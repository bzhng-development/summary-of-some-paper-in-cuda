# Rectified Sparse Attention

**ArXiv:** [2506.04108](https://arxiv.org/abs/2506.04108)

## 🎯 Pitch

This paper introduces **Rectified Sparse Attention (ReSA)**, a method for efficient long-sequence generation that combines group block-sparse attention with periodic dense rectification (refreshing the KV cache at fixed intervals using a dense forward pass) to bound approximation error accumulation during sparse decoding.

---

## 1. Executive Summary

This paper introduces **Rectified Sparse Attention (ReSA)**, a method for efficient long-sequence generation that combines group block-sparse attention with periodic dense rectification (refreshing the KV cache at fixed intervals using a dense forward pass) to bound approximation error accumulation during sparse decoding. Evaluated on math reasoning benchmarks (Minerva Math, Gaokao 2023 En, OlympiadBench, AIME24, AMC23), language modeling, and the RULER retrieval benchmark using Qwen2.5 and DeepSeek-R1-Qwen-Distill models, ReSA achieves near-lossless generation quality relative to dense attention while delivering up to 2.42× end-to-end speedup at 256K sequence length under INT4 decoding. The method establishes that periodic rectification can close the quality gap between sparse and dense decoding, but only when the rectification frequency is chosen to balance overhead against error accumulation—with the paper showing f = 32 strikes this balance, maintaining accuracy within a narrow margin of the dense baseline across all evaluated tasks.

## 2. Context and Motivation

### The Core Problem: Sparse Decoding Degrades Over Long Sequences

The fundamental challenge this paper tackles is deceptively simple: **when you use sparse attention to speed up long-sequence generation, the accumulated approximation errors in the KV cache cause generation quality to deteriorate more and more the longer you decode.** This is not a hypothetical concern — it's a measurable, compounding failure mode that becomes worse the longer the model generates (Figure 1).

Standard autoregressive decoding with dense attention requires each new token to attend to the full KV cache — every key and value from every previous token. This creates an O(n²) memory access pattern where n is the sequence length. For long contexts (hundreds of thousands of tokens), this memory access dominates latency, turning the attention mechanism into the primary throughput bottleneck rather than the feedforward layers or other components. This is a well-known problem, but prior work has treated it primarily as a *static* efficiency problem — how do we avoid accessing the full KV cache per step? The critical gap this paper identifies is that *dynamic error accumulation* during sparse decoding is the real culprit behind quality degradation, not just the per-step approximation error of a single sparse attention computation.

The paper's insight is that sparse decoding introduces a form of **training-inference misalignment**: during pretraining, tokens were generated with full dense attention, so the values stored in the KV cache reflected dense attention computations. During sparse decoding, the model selectively attends to only a subset of previous tokens, producing slightly different attention outputs. These slight differences get written into the KV cache. On the *next* decoding step, those already-imprecise KV entries influence the current token's computation, adding a new layer of error on top. Over hundreds or thousands of decoding steps, these errors compound, and the KV cache drifts further and further from what dense attention would have produced. The model was trained to predict tokens given dense-attention KV caches, but it's now operating on progressively corrupted KV caches. The result: performance that degrades monotonically with decoding length, as shown empirically in Figure 1, where top-3 accuracy drops from approximately 0.795 at short lengths to below 0.78 as the decoding sequence extends.

This gap is significant for several practical reasons:

- **Test-time scaling amplifies the problem.** As the paper notes (Section 1), test-time scaling — where models generate very long reasoning chains to improve accuracy — has become a dominant paradigm with models like DeepSeek-R1 and OpenAI o1 generating thousands of reasoning tokens. The paper's experiments on math reasoning tasks show average decoding lengths of 4,000–12,000 tokens (Table 1). If sparse decoding degrades on these timescales, models that are supposedly being helped by additional test-time compute are actually being *harmed* by the very efficiency method deployed to make that compute affordable.
- **Real-world long-context deployment is bottlenecked by latency.** Systems processing documents, codebases, or long conversations need to generate responses while attending to very long contexts (up to millions of tokens, as the paper cites with Gemini 1.5 and Qwen2.5-1M). The IO pressure of dense attention makes this infrastructure-intensive and expensive. Sparse methods could make this practical — but only if they don't sacrifice quality.
- **The error accumulation problem is a fundamental limitation, not an implementation detail.** It doesn't matter how clever your sparse pattern is on a per-step basis — if each step's approximation error persists in the KV cache, you're facing compounding error that becomes worse at longer lengths.

### The Contradiction Between Static and Dynamic Sparsity Performance

The paper is motivated by a genuine tension observable in prior sparse decoding work. **Static evaluations** (where you measure attention accuracy on a single forward pass with a given KV cache) often show that sparse attention closely matches dense attention using only a small fraction of the context. Quest (Tang et al., 2024) and ClusterKV (Liu et al., 2024) both demonstrate that query-aware block-sparse attention can identify the most relevant KV blocks with high accuracy, achieving near-dense performance with 10–20% of memory accesses. By these metrics, sparse decoding works.

But **dynamic evaluation** (where you measure end-to-end generation quality after many decoding steps) reveals the gap. As the paper shows in Figure 1 and Table 1, block-sparse attention consistently underperforms dense attention on math reasoning tasks (e.g., 57.72% vs. 60.72% average accuracy on the 7B model), and language modeling accuracy drops with increasing length specifically under sparse decoding. The static approximation is good; the dynamic error accumulation is the problem. This is a classic compounding-error problem: each step's error is small, but over enough steps, the integration of those errors becomes large.

This explains why prior work could simultaneously claim that sparse attention works well (measured on single-step accuracy or short generations) while practitioners observe quality degradation on long generations. The two observations are not contradictory — they're measuring different things. The paper's central motivation is to **address the dynamic accumulation problem directly** rather than treating sparse decoding as a static approximation problem.

### Where Prior Approaches Fall Short

The paper identifies specific limitations in existing work along several axes:

**Training-free sparse attention methods don't bound error accumulation.** Methods like Quest (Tang et al., 2024), InfLLM (Xiao et al., 2024), MagicPig (Chen et al., 2024), and ClusterKV (Liu et al., 2024) all improve per-step efficiency by selectively attending to a subset of the context — either through query-aware block selection, locality-sensitive hashing, or semantic clustering. But they do nothing to prevent the KV cache from accumulating approximation errors over time. Once a key or value is written with a slightly incorrect value (due to sparse attention rather than dense attention), that error stays in the cache forever and influences all future tokens. These methods have no mechanism to detect or correct such drift, so their performance degrades with sequence length even though their per-step approximation remains good. The paper explicitly demonstrates this in Section 3.2: "Sparse Decoding alone consistently underperforms" (Table 1), and in Section 3.3: "sparse decoding performance becomes worse with increasing decoding length due to error accumulation of KV cache" (Figure 1 caption).

**Training-aware sparse methods require costly retraining.** Architectures like NSA (Yuan et al., 2025) and MoBA (Lu et al., 2025) integrate sparsity into the model's pretraining, so the model learns to operate with sparse attention patterns that are hardware-aligned. This avoids the training-inference mismatch by making sparse attention the training-time regime. But the cost is high: full pretraining from scratch is computationally expensive and may not be feasible for organizations using pre-existing foundation models. The paper positions its method as complementary to these approaches — it works on top of standard pretrained Transformers without requiring any model weight modification.

**Speculative decoding addresses a different bottleneck.** Speculative decoding (Leviathan et al., 2023) and its variants (Medusa by Cai et al., 2024; EAGLE by Li et al., 2024; TriForce by Sun et al., 2024; MagicDec by Sadhukhan et al., 2024) accelerate generation by drafting multiple tokens cheaply and then verifying them with the full model. Sparse KV-based self-speculation (TriForce, MagicDec) uses a sparse KV cache for fast drafting and a dense cache for verification. The paper's comparison with self-speculation (Appendix B, Table 3) reveals a key distinction: at matched accuracy levels, ReSA achieves approximately **2× higher throughput** than self-speculation. Why? Because speculative decoding's verification step must make **per-token accept/reject decisions**, which requires running dense attention for each verification. Even if 8 out of 16 drafted tokens are accepted on average (the paper's finding), the verification cost plus the drafting cost creates overhead. ReSA avoids this entirely — it never makes per-token accept/reject choices, instead rectifying the KV cache in batch every f steps. The paper's core insight here is that **when sparse attention is already highly accurate, strict per-token verification is overkill** — the marginal accuracy gain doesn't justify the latency cost.

**No prior work treats error accumulation as a bounded-control problem.** The paper's key conceptual move is framing sparse decoding quality degradation not as an irreducible limitation of sparsity, but as an **error accumulation problem that can be bounded through periodic correction**. This perspective is novel. Previous work either accepted the degradation as the cost of efficiency (training-free methods) or eliminated it entirely through retraining (training-aware methods). The paper proposes a middle ground: let sparse decoding introduce errors, but refresh the KV cache periodically so errors never compound beyond a fixed window size. This is conceptually analogous to checkpointing in numerical integration — you don't need perfect approximation at every step; you need the error to remain bounded across the integration interval.

### How This Paper Positions Itself

The paper frames ReSA as a lightweight, composable solution that addresses the error accumulation problem without the drawbacks of prior approaches. Several design choices reflect this positioning:

**Training-free, operates on standard pretrained models.** Unlike NSA or MoBA, ReSA requires no model retraining or architecture changes. It applies directly to off-the-shelf Transformers (the paper uses Qwen2.5 and DeepSeek-R1-Qwen-Distill, standard pretrained models). The block-sparse attention pattern is computed using purely statistical block descriptors (min/max pooling over key blocks, Section 2.1), with no learned parameters. This means it can be deployed on existing models immediately.

**Builds on proven block-sparse designs but adds error control.** ReSA adopts the block-sparse attention mechanism from Quest (block partitioning, query-aware block selection via min-max descriptors, top-n selection with sparsity ratio p). This is a strong, well-tested foundation. The paper's innovation is not in the sparse pattern itself but in the **rectification mechanism** layered on top: after every f tokens of sparse decoding, batch-recompute those f tokens' KV entries using dense attention (Algorithm 1). This bounds the accumulated error to at most f steps of sparse decoding. It's a control-theoretic framing applied to attention computation: treat sparse decoding as an open-loop approximation and add periodic feedback correction.

**Positioned between sparse decoding and self-speculation in the design space.** The paper explicitly contrasts ReSA with sparse KV-based self-speculation (Appendix B). Both methods perform a fast sparse pass and a slower dense pass. But they differ in *what* they verify: self-speculation verifies whether output tokens match the draft model's predictions, enforcing token-level exactness to dense decoding. ReSA verifies and corrects the KV cache itself, accepting whatever tokens were generated by the sparse path. This philosophical difference — verifying the memory versus verifying the output — means ReSA doesn't need to run dense forward passes for every batch of drafted tokens, which is slower. Instead, it rectifies the *memory state* in batch, which the paper shows achieves similar generation quality with less overhead.

**The efficiency-quality tradeoff is parameterized by a single tunable frequency f.** The rectification frequency f is the primary knob controlling the balance between quality (lower f = more frequent rectification = less error accumulation) and speed (higher f = less rectification overhead = faster generation). The paper's ablation studies (Figure 9) systematically characterize this tradeoff: f = 32 achieves near-dense accuracy across all benchmarks while keeping rectification overhead manageable; f = 16 provides marginal accuracy gains but at twice the rectification cost; f = 64 or 128 still provides substantial improvement over pure sparse decoding, showing the rectification mechanism is robust even with infrequent updates. This single-parameter design makes ReSA simple to tune for different deployment scenarios: latency-sensitive applications can increase f, quality-sensitive ones can decrease it.

**Sparsity ratio p as a secondary knob.** Beyond rectification frequency, the sparsity ratio p (the fraction of memory blocks attended to during sparse decoding) controls the cost of each sparse step. The paper defaults to p = 0.9 (attending to 10% of blocks) but explores down to p = 0.05 (attending to only 5% of blocks) in language modeling (Figure 5), showing that even extreme sparsity remains viable when coupled with rectification (though with some quality degradation). The paper notes that p interacts with the block selection strategy's quality — better block selection (e.g., via learned descriptors like SeerAttention) could enable higher sparsity at the same quality level.

**Practical compatibility with existing serving infrastructure.** The paper emphasizes that rectification is naturally compatible with continuous batching and chunked prefill (Section 2.2). Since rectification is just a batched dense forward pass every f steps, it fits into the same scheduling frameworks that modern serving systems use to interleave prefill and decode workloads. There are no special synchronization barriers, no blocking operations — the system can dynamically group rectification steps from multiple requests, just as it groups prefill steps. This makes ReSA deployable in production serving stacks without custom scheduling logic.

In sum, the paper positions ReSA as filling a specific gap in the sparse decoding landscape: it provides **bounded error accumulation without retraining, without per-token verification overhead, and without special infrastructure requirements**, achieving the quality of dense decoding at a fraction of the memory access cost.

## 3. Technical Approach

This is a **systems paper** whose core idea is that sparse decoding's quality degradation over long sequences is fundamentally an error accumulation problem, not a per-step approximation problem, and that periodically refreshing the KV cache with a dense forward pass bounds this error to a constant window size, enabling near-dense quality with sparse-attention efficiency.

### 3.1 Reader Orientation

ReSA is a **decoding algorithm** — not a model architecture — that you can apply to any pretrained Transformer to speed up long-sequence generation. It alternates between two operating modes: fast autoregressive decoding using highly sparsified attention (attending to only ~10% of previous context) for most steps, and occasional full dense attention passes that correct any accumulated approximation errors in the KV cache. The problem it solves is that sparse attention, while efficient per-step, writes slightly incorrect values into the KV cache at each step — and these errors compound over thousands of decoding steps until the model is operating on KV caches that are substantially different from what it was trained to expect. The "shape" of ReSA's solution is a **bounded-control** approach: let sparse decoding introduce bounded local errors, then apply periodic global corrections so those errors never compound beyond a fixed window.

### 3.2 Big-Picture Architecture (Diagram in Words)

ReSA has four major components organized in a repeating two-phase cycle:

1. **Group Block Sparse Attention (GBSA)** — the fast decoding engine. Each new token attends to only a dynamically selected subset of previous context, organized into contiguous memory blocks. Query heads share sparse patterns within GQA groups for additional efficiency. This produces most tokens.

2. **Block Key Cache** — a compact, training-free summary of the full KV cache, maintained incrementally during decoding. Each block of consecutive tokens is represented by its element-wise min and max key values, enabling rapid approximate relevance scoring without scanning individual tokens.

3. **Dense Rectification** — the periodic correction mechanism. After every f tokens of sparse decoding, those f tokens are batch-fed through a single dense forward pass to recompute their KV entries exactly. The corrected entries overwrite the approximate ones in the KV cache, and the block key statistics are refreshed correspondingly.

4. **The Alternating Scheduler** — the control logic (Algorithm 1) that interleaves sparse decoding and dense rectification. It maintains a counter of steps since the last rectification; when that counter reaches f, it triggers a rectification step before resuming sparse decoding.

Information flows as follows: a prompt enters → standard dense prefill encodes it into the KV cache and initializes block key statistics → sparse decoding generates tokens, each time (a) computing block-level query-to-key similarity scores using the block key cache, (b) selecting the top-n blocks plus a local window, and (c) attending only to those selected blocks → every f tokens, the rectification step (d) batches those f tokens, (e) runs dense attention over the full KV cache to produce corrected KV entries, (f) overwrites the sparse-produced entries with the dense ones, and (g) refreshes the block key statistics for those refreshed blocks → sparse decoding resumes → cycle repeats until generation completes.

### 3.3 Roadmap for the Deep Dive

- **First**, the Group Block Sparse Attention mechanism — how blocks are formed, scored, and selected, and why query-dependent sparsity avoids the static-pattern limitations of fixed attention windows.
- **Second**, the block representation and selection mathematics — the min-max block descriptors, the similarity scoring function (Equation 4), and the dynamic top-n strategy with sparsity ratio p — since this determines *what* gets attended to and drives efficiency.
- **Third**, the dense rectification procedure — how it bounds error accumulation, its amortized cost model (Equation 6), and why it avoids the per-token verification overhead of speculative decoding.
- **Fourth**, the custom kernel implementation — how the workload is partitioned across streaming multiprocessors and how intra-GQA key sharing is exploited — since this is what delivers the measured speedups.
- **Fifth**, the decoding procedure (Algorithm 1) — the complete control flow that ties sparse generation and rectification into an alternating cycle, including the initialization from dense prefill and the block cache update rules.

### 3.4 Detailed, Sentence-Based Technical Breakdown

#### Group Block Sparse Attention (GBSA) — The Fast Decoding Engine

The first major component is the attention mechanism used during sparse decoding steps. GBSA modifies the standard attention computation so that each query token attends to only a dynamically selected subset of previous tokens, organized into contiguous blocks of size b.

**Why blocks?** Individual token-level sparsity (e.g., only attending to the top-k individual tokens) would be memory-inefficient because GPUs fetch memory in contiguous chunks. By organizing the KV cache into blocks of b consecutive tokens and selecting entire blocks (rather than individual tokens), the method ensures that every memory access retrieves a contiguous region of memory, maximizing the bytes-transferred-per-access ratio. The paper sets b = 16 by default (Section 3.1), striking a balance between retrieval granularity (smaller blocks = finer selection) and memory efficiency (larger blocks = fewer but larger contiguous reads).

**The attention computation with block sparsity.** Standard group-query attention (GQA), as formalized in Equation 1, computes:

$$Attention(Q, K, V)_{ij} = softmax\left(\frac{Q_{ij}K_i^T}{\sqrt{d}}\right)V_i$$

where Q ∈ ℝ^{h×g×n×d} is the query tensor (h KV heads, g query heads per KV head, n sequence positions, d head dimension), K, V ∈ ℝ^{h×n×d} are the key and value tensors, and softmax is applied row-wise. The pairwise QK^T computation requires O(n²d) operations, meaning each new token must compute a dot product with every previous token's key.

GBSA modifies this by introducing a block sparse mask M ∈ {0, 1}^{h×n×n/b}, where n/b is the number of blocks and each entry M_{ijk} = 1 means query i in head j attends to block k. The computation becomes:

$$GBSA(Q, K, V, M)_{ij} = softmax\left(\frac{Q_{ij}K_i^T \cdot M_i}{\sqrt{d}}\right)V_i, \quad M_{ijk} = M_{ij\lfloor k/b \rfloor}$$

where M_{ijk} is 1 only for block indices ⌊k/b⌋ that are selected by the sparsity pattern for that query and head, and 0 otherwise (attending to masked-out positions with score −∞ in practice). M_i is expanded along the token dimension so that all tokens within a selected block are attended, and all tokens within an unselected block are masked out.

**What it computes:** For each query vector (one per head per sequence position), the standard attention score QK^T is computed first — but then element-wise multiplied by the expanded mask M_i. Positions where M_i is 0 get their attention score set to −∞, which the subsequent softmax maps to zero probability. Positions where M_i is 1 retain their computed score. This means softmax normalization is only over the selected subset of tokens. The output V_i multiplication then aggregates values from only the selected tokens.

**Why this form:** The mask M is query-dependent — different queries can attend to different blocks. This is critical because static sparse patterns (e.g., sliding window + global tokens) impose the same attention structure on every query regardless of content. A query asking "what is the author's main argument?" needs different context than one asking "what is the publication date?" — query-dependent sparsity enables the model to route attention to the most relevant context for each specific query. The block granularity (rather than token granularity) makes this practical: selecting at the block level means M has only n/b entries per query, not n, and the selected blocks can be fetched contiguously from memory.

**Shared grouping within GQA groups.** The paper notes (Section 2.1): "we further accelerate decoding by maintaining a shared sparse pattern within each GQA group." In standard GQA, multiple query heads share a single set of key-value heads. The paper takes advantage of this by having all query heads in the same GQA group select the same blocks. This means the block selection computation (pooling queries, computing block scores) happens once per GQA group rather than once per query head, reducing the selection overhead by a factor of g (the number of query heads per KV head). The pooling step averages the query vectors across all heads in the group to produce a single representative query for block scoring:

$$q_{pooled} = \frac{1}{g}\sum_{i=1}^{g} q_i$$

where q_i ∈ ℝ^d is the query vector for the i-th head in the group. This pooled query is then used for block selection, and the resulting block indices are applied identically to all heads in the group. This is a pragmatic choice: different heads within a group typically attend to correlated regions of context (they share the same KV head), so sharing the sparse pattern costs little in accuracy but saves substantial memory access during selection.

#### Block Representation: Training-Free Min-Max Descriptors

To select which blocks to attend to, GBSA needs a way to score the relevance of each block to the current query — without computing full query-key dot products for every token in every block (which would defeat the purpose of sparsity). The paper adopts a training-free block representation using min-max pooling, following Quest (Tang et al., 2024).

**Block partitioning.** Given the key matrix k ∈ ℝ^{n×d} for one KV head (n tokens, d dimensions), the sequence is partitioned into non-overlapping blocks of size b. The i-th block contains tokens indexed from i·b to (i+1)·b − 1. For each block, two summary vectors are computed:

$$k_{block\_min,i} = \min(k_{ib:(i+1)b}), \quad k_{block\_max,i} = \max(k_{ib:(i+1)b})$$

where min(·) and max(·) are applied element-wise across the b tokens in the block. So k_{block_min,i} ∈ ℝ^d is a vector where the j-th entry is the minimum value of the j-th key dimension across all b tokens in the block. Similarly, k_{block_max,i} is the element-wise maximum.

**What this represents:** Each block is summarized by an axis-aligned bounding box in the d-dimensional key space — a hyper-rectangle whose lower corner is k_{block_min,i} and upper corner is k_{block_max,i}. If a query vector points into this hyper-rectangle (i.e., each query dimension falls between the block's min and max for that dimension), then at least one key in the block could have high dot-product similarity. If the query falls entirely outside the hyper-rectangle, no key in the block can have high similarity (under certain monotonicity assumptions about the dot product). The min-max descriptors thus provide an approximate necessary condition for relevance: if the query and the block's hyper-rectangle are far apart across many dimensions, the block is unlikely to contain relevant keys and can be safely skipped.

**Why training-free?** The paper explicitly notes: "the block representation is entirely training-free, relying solely on statistical descriptors." This means no parameters need to be learned or fine-tuned — the block descriptors are computed purely from the data at hand. This makes ReSA immediately applicable to any pretrained model without any weight modification. The tradeoff is that learned block descriptors (as in SeerAttention; Gao et al., 2024) could potentially achieve more accurate retrieval by adapting to the model's specific attention patterns. The paper positions this as a compatible extension: "Our method remains compatible with more advanced block representation strategies, such as SeerAttention, where block keys are fine-tuned jointly with the model to achieve higher retrieval precision if needed."

**Incremental updates.** A practical advantage of min-max descriptors is that they support incremental updates. When a new token is generated and its key vector is appended to the KV cache, it falls into the currently-active block (if that block has fewer than b tokens) or starts a new block. In either case, the block's min and max vectors can be updated by element-wise comparison with the new key vector — there's no need to recompute from scratch over all b tokens. The paper notes this in Section 2.1: "newly generated keys can be incrementally incorporated by updating the block key statistics, enabling an online update mechanism without recomputing from scratch."

#### Block Selection: Scoring, Top-n Selection, and Sparsity Control

Given a pooled query q ∈ ℝ^d for a GQA group and a set of M block summaries {(k_{block_min,i}, k_{block_max,i})}_{i=1}^{M}, the block selection step computes a relevance score for each block and then selects the top-n blocks for attention. This is the core of the query-dependent sparsity.

**Similarity scoring.** The score between query q and block i follows Equation 4:

$$score_i = \sum_{j=1}^{d} \max(q_j \times (k_{block\_max,i})_j, \quad q_j \times (k_{block\_min,i})_j)$$

where q_j is the j-th dimension of the pooled query, and (k_{block_min,i})_j, (k_{block_max,i})_j are the j-th dimensions of the block's min and max vectors respectively.

**What it computes:** For each dimension j separately, the function computes q_j multiplied by whichever of the block's two extremes (min or max) gives the larger product. If q_j is positive, multiplying by the maximum gives the larger product; if q_j is negative, multiplying by the minimum gives the larger product. The max operation thus selects the "best-case" product for that dimension under the constraint that the actual key values must lie within the block's bounding box. Summing across all d dimensions gives a total score representing the maximum possible dot product between the query and any key that could exist inside the block. This is an upper bound on the actual dot product between q and any token-level key vector in the block.

**Why this form:** This is a conservative (optimistic) relevance estimate — it assumes that for each dimension, the actual key value that maximizes the dot product with the query is present in the block. If this upper bound is low, then no key in the block could have a high dot product with the query, so the block can be safely skipped. The max-per-dimension structure is crucial because it decouples the dimensions: the true maximum dot product requires finding a single combined key vector that maximizes the sum across all dimensions simultaneously, which is a harder optimization problem. The per-dimension max provides a looser but computationally trivial upper bound — it's equivalent to assuming the ideal key exists independently for each dimension, which overestimates relevance but guarantees no false negatives (no truly relevant block gets incorrectly skipped).

**Dynamic top-n with enforced components.** The paper uses a three-part selection strategy (Section 2.1) rather than a fixed number of blocks:

1. **Local window (n_local):** A fixed number of the most recent blocks (the default is n_local = 1 block, containing the most recent tokens) are always selected by setting their scores to +∞. This ensures local coherence — the newest tokens are always attended, preserving the model's ability to maintain short-range dependencies (grammar, local topic continuity) that might not be captured by relevance scoring alone.

2. **Minimum block count (n_min):** A floor of n_min = 16 blocks is enforced to prevent degenerate behavior on very short sequences where the sparsity ratio would select too few blocks. Without this floor, the sparsity ratio p might select only 1–2 blocks on sequences under a few hundred tokens, which could cause severe quality degradation. The minimum ensures a baseline of at least 16 blocks (256 tokens at b = 16) are always attended.

3. **Sparsity ratio (p):** Beyond the enforced minimum, the number of selected blocks n is proportional to the total number of available memory blocks M:

$$n = \max(n_{min}, \lceil M \times p \rceil)$$

where ⌈·⌉ is the ceiling function (round up to nearest integer). The default sparsity ratio is p = 0.9, meaning attention is restricted to approximately 10% of available blocks (1 − p = 0.1 fraction attended). Note a naming subtlety: in this paper, p is the *sparsity ratio* — the fraction of blocks that are *skipped*, not attended. So p = 0.9 means 90% of blocks are skipped, 10% are attended. This is the inverse of how some other papers report it. The dynamic formulation means that as the sequence grows (M increases), n grows proportionally, so the absolute number of attended blocks increases but the fraction remains roughly constant.

**Putting it together:** For each decoding step, the system (a) computes the pooled query per GQA group, (b) computes score_i for all blocks i = 1...M using Equation 4, (c) sets the scores of the n_local most recent blocks to +∞, (d) sorts blocks by score and selects the top n according to Equation 5, and (e) constructs the mask M to allow attention only to tokens within selected blocks. This mask then feeds into the GBSA computation (Equation 2).

#### Dense Rectification — Bounding Error Accumulation

The second major component is the rectification mechanism that periodically refreshes the KV cache. This is ReSA's core intellectual contribution: sparse decoding alone causes error accumulation; rectification bounds that error.

**The error accumulation problem, precisely.** During a sparse decoding step, the model computes attention over a subset of the KV cache — not the full cache. This means the resulting attention output differs slightly from what dense attention would have produced. Since in autoregressive Transformers, each token's key and value vectors are functions of the attention output from preceding layers (via the residual stream), the new KV entries appended to the cache carry this approximation error. On the *next* step, those error-containing KV entries influence the attention computation for the next token, which in turn produces new KV entries with potentially larger errors. This is a classic integration of errors over time: even if per-step error is small, the accumulated error after T steps can be O(T) (if errors are systematic) or O(√T) (if errors are independent zero-mean). The result is that the KV cache drifts away from what dense attention would have produced, and the model — trained on dense-attention KV caches — performs worse.

**The rectification solution.** The paper's insight is that this accumulation can be bounded by periodically "resetting" the KV cache to its dense-attention values. The rectification procedure is straightforward (Section 2.2):

After every f tokens of sparse decoding:
1. **Batch the last f tokens:** Collect the f most recently generated tokens (the ones generated since the last rectification).
2. **Run one dense forward pass:** Feed these f tokens through the model with full dense attention over the entire accumulated KV cache (all tokens generated so far). This recomputes the key and value vectors for these f tokens using the *exact* attention computation rather than the approximate sparse version.
3. **Overwrite the KV cache entries:** The newly-computed dense KV entries replace the sparse-produced entries for these f positions in the KV cache. Note that earlier tokens' KV entries (from before the last rectification, which were themselves dense-produced) remain unchanged — rectification only corrects the most recent f tokens.
4. **Refresh block key statistics:** Since the KV values for these f tokens have changed, the block key cache (min-max descriptors) must be updated to reflect the new values. This ensures subsequent sparse decoding steps use accurate block statistics for selection.

**Why it bounds error:** After rectification, the KV cache is *exactly* what dense attention would have produced for all tokens up to the current point. Any approximation errors that accumulated during the preceding f sparse decoding steps are erased — the cache is reset to dense-equivalent state. From this clean state, the next f sparse decoding steps will again accumulate errors, but those errors can only build up over at most f steps before the next rectification. The maximum accumulated error at any point is thus bounded by the error that can accumulate over f consecutive sparse decoding steps, which is O(f) rather than O(T). For T ≫ f, this changes the scaling from linear growth to constant-bounded.

**Rectification frequency f as the control parameter.** The paper's default is f = 32 (Section 3.1). This was chosen empirically (Section 3.6, Figure 9): f = 32 achieves accuracy very close to dense decoding across all evaluated benchmarks while keeping rectification overhead manageable. Lower f (e.g., 16) provides marginally better quality but at twice the rectification cost. Higher f (e.g., 64, 128) still provides substantial improvement over pure sparse decoding, demonstrating that even infrequent rectification captures most of the benefit.

**Rectification is done in parallel, not sequentially.** A critical implementation detail: the f rectification tokens are processed in a single batch forward pass, not one at a time. This is what makes rectification efficient — rather than running dense attention for each of the f tokens individually (which would defeat the purpose and be slower than just doing dense decoding), the model processes all f tokens simultaneously using the standard batched attention computation. The computational cost is thus one dense forward pass over f tokens, not f separate dense forward passes. This amortization is crucial: the cost per rectification token is approximately 1/f of a dense forward pass, which for f = 32 means rectification adds roughly 3% overhead in total attention computation.

**Compatibility with serving infrastructure.** The paper explicitly notes (Section 2.2): "Dense Rectification is naturally compatible with modern LLM serving optimizations such as continuous batching and chunked prefill." In continuous batching systems, the scheduler dynamically groups decoding steps with prefill steps to maximize GPU utilization. A rectification step is computationally identical to a chunked prefill — it's a batch of tokens that need to be processed with attention over a full KV cache. The scheduler can treat rectification requests exactly like small prefill requests, batching them together with other rectification or prefill operations across different sequences. There are no synchronization barriers or special handling required — the rectification step fits seamlessly into the standard prefill/decoding scheduling paradigm.

#### Memory Access Analysis and the Amortized Cost Model

The paper provides a cost model (Equation 6 in Section 2.3) that decomposes the average memory access per decoding step into three components:

$$Avg(mem) = mem(KV\_cache) \times \left(\frac{1}{b} + p + \frac{1}{f}\right)$$

where mem(KV_cache) is the total memory footprint of the key-value cache, b is the block size (default 16), p is the sparsity ratio — the fraction of blocks attended to — not skipped, so p = 1 − sparsity_level. With the paper's default sparsity of 0.9 skipped, p = 0.1 (10% of blocks attended), and f is the rectification frequency (default 32).

**What each term represents:**

- **1/b:** The cost of reading the block key cache for relevance scoring during sparse estimation. The block key cache stores two d-dimensional vectors (min and max) per block of b tokens. So the memory footprint of the block cache is mem(KV_cache) × 2/b. Adding the query access (~negligible), the total sparse estimation memory access is approximately mem(KV_cache)/b. For b = 16, this is 6.25% of full KV cache per step.

- **p:** The cost of reading the selected blocks' keys and values during the sparse attention computation itself. Since attention is restricted to a fraction p of all blocks, the KV cache reads are p × mem(KV_cache). For the default p = 0.1 (attending to 10% of blocks), this is 10% of full KV cache per step.

- **1/f:** The amortized cost of rectification per decoding step. Every f steps, the rectification performs one dense forward pass over the full KV cache, costing mem(KV_cache) in total. Amortized over f steps, the per-step cost is mem(KV_cache)/f. For f = 32, this adds approximately 3.1% of full KV cache per step.

**Total memory access reduction.** The sum of these three terms gives the fraction of the full KV cache that must be accessed per decoding step on average. For the default hyperparameters (b = 16, p = 0.1, f = 32):

$$\frac{1}{16} + 0.1 + \frac{1}{32} = 0.0625 + 0.1 + 0.03125 = 0.19375$$

This means ReSA accesses approximately **19.4%** of the KV cache per step on average — a reduction factor of about 5.16× compared to dense attention's 100% access. The paper's empirical speedup measurements (up to 2.42× end-to-end) are lower than this theoretical factor because attention is only one component of total inference latency — the feedforward layers, embedding lookup, and other operations don't benefit from attention sparsity and contribute a fixed cost per token.

**The tradeoff space.** The three parameters (b, p, f) define a design space for trading accuracy against speed:

- **Block size b:** Smaller b enables finer-grained selection (potentially better accuracy at the same p) but increases the block key cache size (1/b term grows). Larger b reduces the selection overhead but coarsens the selection granularity. The paper fixes b = 16 as a standard choice and doesn't ablate it.

- **Sparsity p (fraction attended):** Lower p means sparser attention (faster) but potentially lower accuracy. The paper explores p = 0.02, 0.05, 0.1, 0.2 (equivalent to 98%, 95%, 90%, 80% sparsity) in Figure 5 and Figure 9, finding that p = 0.1 offers the best tradeoff, with p = 0.2 showing somewhat better accuracy but reduced speedup.

- **Rectification frequency f:** Lower f means more frequent correction (better accuracy, higher overhead from the 1/f term). The paper shows f = 32 as the sweet spot, with f = 16 providing marginal accuracy gains at doubled cost, and f = 64 or 128 still providing most of the benefit.

#### Kernel Implementation

The paper implements ReSA using a custom CUDA kernel (Section 2.4, Appendix A) that follows a split-execution strategy similar to Flash Decoding (Dao et al., 2023). The key design principles are:

**Per-SM GQA group isolation.** Each streaming multiprocessor (SM) on the GPU is assigned to process one specific GQA group (one KV head and its associated query heads). This eliminates inter-SM communication for attention computation within a group — everything an SM needs (the queries for that group, the block indices, and the KV cache entries for the selected blocks) is fetched independently. The number of groups processed in parallel equals the number of SMs, and if there are more groups than SMs, multiple waves are executed.

**Workload splitting across SMs by block index.** The decoding workload is batch_size × num_kv_heads. Given that a batch of queries typically activates k memory blocks (k = n from Equation 5, the number of selected blocks), these k blocks are partitioned evenly across the available SMs assigned to that group's computation. Each SM is responsible for computing attention over approximately k/split blocks. This means each SM fetches only its assigned blocks' KV entries from global memory, computes sparse attention locally, and produces partial outputs (attention-weighted value sums and log-sum-exp normalization factors).

**Splitting, combining, and the Flash Decoding pattern.** The kernel follows the Flash Decoding algorithm structure (Algorithm 2 in Appendix A). Each SM:
1. Loads its assigned query vectors for the GQA group.
2. Determines which block indices from the global selected-block list fall under its responsibility (based on its rank among the splits).
3. Iterates over its assigned blocks, for each loading the keys and values from global memory, computing scaled dot-product scores, masking invalid positions (padding within blocks), and maintaining running statistics: running max m_i for numerical stability and running sum ℓ_i (exponential sum) for softmax normalization.
4. Writes its partial attention output and partial log-sum-exp values to global memory.
5. A final combine step (across splits) applies the Flash Decoding reduction formula to merge the partial results from different splits, producing the final attention output for each query.

**Intra-GQA key sharing.** Because all query heads in a GQA group share the same sparse pattern (the same selected blocks), the key-value fetches from global memory are performed once per group and shared across all query heads. This is the implementation-level realization of the design choice described in Section 2.1. The kernel loads keys and values once into shared memory or registers, then all query heads in the group use those shared KV entries for their respective attention computations. This reduces memory bandwidth consumption by a factor equal to the number of query heads per KV head (g), since without sharing, each head would independently fetch the same KV entries.

**Why split-execution?** The splitting strategy ensures that no single SM becomes a bottleneck by being assigned too many blocks while others sit idle. Since the active blocks are query-dependent (different queries select different blocks), the distribution of work across blocks could otherwise be highly uneven. By splitting the k active blocks across SMs, the approach load-balances the attention computation dynamically — each SM gets approximately the same number of blocks to process, regardless of which specific blocks those are. This is the same load-balancing principle that makes Flash Decoding efficient for long-context dense attention.

**Integration with quantized matmul.** For the INT4 experiments (Figure 8), the paper uses the Marlin kernel (Frantar et al., 2024) for the feedforward layer computations. The attention kernel itself operates in FP16 (the KV cache and attention computation remain in FP16), while the weight matrices for the MLP and projection layers are quantized to INT4. The speedup from ReSA stacks multiplicatively with the speedup from weight quantization — the attention bottleneck is addressed by ReSA, while the computation bottleneck (matmuls) is addressed by INT4 quantization.

#### The Complete Decoding Procedure (Algorithm 1)

The paper formalizes the alternating sparse-rectify cycle in Algorithm 1. Here is the step-by-step procedural logic:

**Step 1: Prefill (dense).** The initial prompt tokens P are processed using standard dense attention. This produces a complete, exact KV cache K for all prompt tokens. The block key cache B is initialized by computing the min and max descriptors (Equation 3) for each block of the prompt's keys. The output sequence G is initialized as empty.

**Step 2: Sparse decoding loop.** For each decoding step t = 1 to T:

- **2a. Generate one token:** The sparse forward pass (SparseForward) takes the most recently generated token G[t−1] as input, along with the current KV cache K and block key cache B. It computes GBSA (Equation 2) using the block selection procedure (Equation 4, Equation 5). The model outputs logits, from which the next token is sampled or greedily selected. The token t is appended to G.

- **2b. Update caches:** The new token's key and value vectors (computed during the sparse forward pass) are appended to the KV cache K. The block key cache B is updated: if the current block has fewer than b tokens, the new key's values are incorporated by element-wise comparison with the existing min and max; if the current block is full (b tokens), a new block descriptor is initialized.

- **2c. Check rectification condition:** If t is a multiple of f (i mod f = 0), trigger rectification.

**Step 3: Rectification (when triggered).** When the step counter reaches a multiple of f:

- **3a. Batch and re-encode:** The f most recently generated tokens G[t−f : t] are collected and passed through a dense forward pass (DenseForward) over the current full KV cache K. This is a single batched forward pass — all f tokens are processed simultaneously with dense attention.

- **3b. Overwrite cache entries:** The newly computed dense key and value vectors for these f tokens replace their existing (sparse-produced) entries in the KV cache K. The structure and tensor shapes of K don't change — only the numerical values for the last f positions are updated.

- **3c. Refresh block cache:** The block key cache B is updated for the blocks containing these f tokens, since their KV values have changed. If a block contains a mix of rectified and unrectified tokens (which happens at block boundaries), the min and max are recomputed over all tokens in that block. For blocks fully contained within the last f tokens, the min-max can be recomputed directly from the new KV values.

**Step 4: Continue.** Return to Step 2, with the now-rectified KV cache K and block cache B. The cycle of sparse-then-rectify continues until a stop condition (maximum length T reached or end-of-sequence token generated).

**A subtle correctness property.** The rectification step processes f tokens simultaneously with dense attention, but these f tokens were originally generated *sequentially* via sparse decoding. This means the rectification forward pass sees a different computational graph than what produced the tokens — the queries, keys, and values are recomputed under dense attention, which could in principle produce different attention outputs and thus different residual stream activations. However, because the output tokens themselves are not regenerated (the token identities are frozen), the rectification only affects the KV cache entries *for those token positions*. The sequence of output tokens remains unchanged. This is the key difference from speculative decoding: ReSA accepts whatever tokens the sparse path produced and only corrects the KV cache state. If the sparse path produced a suboptimal token, that token stays in the output sequence — rectification won't fix incorrect tokens, only incorrect KV cache values for correct-enough tokens.

**Why this ordering ensures bounded error.** The invariant is: immediately after a rectification step, the KV cache for all tokens generated so far — both the original prompt tokens (dense-prefilled) and all generated tokens (rectified) — is exactly what would have been produced by fully dense decoding. During the subsequent f sparse decoding steps, errors are introduced into the KV entries for the newly generated tokens only. After at most f steps, rectification corrects those f entries. The maximum age of any erroneous KV entry is f steps. This is the bounded-control property: error never accumulates beyond a fixed window.

#### Design Rationale: Why Rectification Beats Per-Token Verification

A natural question is: why not verify every token against dense attention, as speculative decoding does, rather than waiting f steps? The paper addresses this through the comparison in Appendix B and Table 3.

Speculative decoding with a sparse KV draft model works as follows: (1) draft k tokens using sparse attention; (2) run one dense forward pass to compute the target model's logits for those k positions; (3) for each position, compare the drafted token against the target model's predicted distribution — if the drafted token's probability under the target model is higher than under the draft model, accept it; otherwise, reject with some probability, sample from the target model, and discard subsequent tokens. This guarantees output that is statistically identical to dense decoding but at lower latency (because k tokens can be drafted in one step). However, the verification step requires running the target model (dense attention) for each batch of k drafted tokens, and only a fraction (on average, the paper reports about 8 out of 16) are accepted.

ReSA's alternative is philosophically different. It operates under the premise that the sparse path's token choices are already good enough — Table 1 shows ReSA achieving 60.52% vs. 60.72% for dense on math reasoning, a gap of only 0.2 percentage points. If the tokens themselves are correct at near-dense rates, there's little value in per-token verification. The problem is not token-level mistakes but cumulative KV cache drift that causes progressively worse token choices over time. Rectification addresses this KV cache drift directly at the memory level, without the overhead of computing and comparing per-token output distributions. The result (Table 3) is approximately 2× higher throughput than self-speculation.

**Why this design choice is justified:** The paper's experimental results validate the premise. On math reasoning (Table 1), ReSA's accuracy is within 0.2 points of dense; on language modeling (Figure 4), ReSA's top-3 accuracy nearly matches the dense upper bound; on retrieval (Table 2), ReSA matches or exceeds dense performance at p = 0.9 sparsity. The sparse attention's token-level accuracy is high enough that per-token verification provides negligible quality benefit for substantial latency cost. The paper's ablations (Figure 9) confirm that even f = 128 (rectifying only every 128 steps) provides most of the quality benefit, indicating that KV cache drift is the dominant error mode, not token-level mistakes.

#### Sparsity Ratio and Rectification Frequency: The Dual-Knob Tradeoff Space

The paper's ablation studies (Section 3.6, Figure 9) characterize how the two main hyperparameters interact:

**Sparsity ratio p (the fraction of blocks skipped — higher p = more sparsification):** Reducing the attended fraction from p = 0.1 (90% sparsity) to p = 0.02 (98% sparsity) makes each sparse step faster but less accurate. Figure 9 shows that at p = 0.9 (10% attended), ReSA with f = 32 achieves accuracy nearly identical to the dense baseline across all five math benchmarks. At p = 0.95 (5% attended), there's a noticeable drop (e.g., AIME24 drops from ~50% to ~46% at f = 32; AMC23 drops from ~86% to ~82%). At p = 0.98 (2% attended), the drop is more severe. This illustrates that block-sparse attention can tolerate surprisingly high sparsity (90%) with minimal accuracy loss when coupled with rectification, but extreme sparsity (98%) exceeds what even rectification can compensate for.

**Rectification frequency f:** At fixed sparsity p = 0.9, Figure 9 shows that f = 32 and f = 64 perform very similarly (curves overlap substantially), f = 16 provides marginal additional gains (1-2 percentage points on some benchmarks), and f = 128 maintains most of the benefit but shows slightly lower accuracy on some tasks. This robustness to f is important — it means the method isn't brittle to the exact choice of rectification frequency, and a wide range of f values (from 16 to 128) provide substantial benefits over pure sparse decoding.

**The interaction:** The paper doesn't extensively explore the joint (p, f) space — most experiments vary one at a time — but the pattern is clear: higher p (more sparsity) requires lower f (more frequent rectification) to maintain quality, and vice versa. The default (p = 0.9, f = 32) represents a empirically-validated sweet spot where sparse steps are fast (10% attention), rectification overhead is low (~3% amortized cost), and accuracy is near-dense. Deployments prioritizing maximum speed could increase p and f together (e.g., p = 0.95, f = 64), accepting some quality degradation. Deployments prioritizing quality could decrease both (e.g., p = 0.8, f = 16), trading speed for accuracy.

## 4. Key Insights and Innovations

### Innovation 1: Reframing Sparse Decoding Degradation as an Error Accumulation Problem Rather Than a Static Approximation Problem

The paper's most fundamental intellectual move is the diagnostic reframing of *why* sparse decoding underperforms dense attention on long sequences. Prior work on sparse attention (Quest by Tang et al., 2024; InfLLM by Xiao et al., 2024; MagicPig by Chen et al., 2024; ClusterKV by Liu et al., 2024) had treated the challenge as a **static approximation problem**: the goal was to select the most relevant subset of context for each query, with quality measured by how well the sparse attention output matched dense attention output on a single forward pass. Under this framing, the natural optimization target is improving the block selection mechanism — better block representations, smarter scoring, more accurate top-k retrieval. Progress is measured by the fidelity of a single sparse attention computation to its dense counterpart.

ReSA's key insight is that this framing is **categorically incomplete**. The paper demonstrates empirically (Figure 1, Table 1) that even when the per-step sparse approximation is quite good, quality degrades monotonically with decoding length — a phenomenon that a static approximation framework cannot explain or address. The paper's reframing identifies the true culprit as **dynamic error accumulation in the KV cache**: sparse attention writes slightly incorrect key and value vectors into the cache, these corrupted entries influence the next step's attention computation, which produces further-corrupted entries, and the errors compound over time. This is a fundamentally different problem class — it's not about per-step approximation quality but about the integration of errors over a dynamical system.

This reframing matters because it changes **what kind of solution is needed**. If the problem is static approximation, the solution is better selection mechanisms (learned block descriptors, more sophisticated scoring). If the problem is dynamic accumulation, the solution is **error control** — mechanisms that prevent errors from compounding, regardless of how they're introduced. This is a conceptual shift comparable to moving from open-loop control (design a better controller) to closed-loop control (add feedback to correct drift). The paper makes this shift explicit: rectification is a feedback mechanism applied to the KV cache state, periodically measuring and correcting the deviation from the dense-attention ground truth.

The significance of this reframing extends beyond ReSA itself. It provides a unifying explanation for why prior sparse decoding methods show good short-sequence performance but degrade on long generations — a pattern visible in the literature but not previously explained as an accumulation phenomenon. It also suggests that future work on sparse attention should evaluate methods by their **dynamic** performance (accuracy as a function of decoding length) rather than only static per-step approximation quality, since the two can diverge substantially.

The evidence for this reframing is the paper's central empirical result: pure sparse decoding (without rectification) shows declining performance with sequence length (Figure 1, Table 1), while ReSA — which uses the *same* sparse attention mechanism but adds periodic rectification — maintains near-constant quality. The sparse attention per-step approximation is identical in both conditions; only the error accumulation behavior differs. This clean experimental dissociation between per-step approximation quality and end-to-end generation quality validates the reframing as more than a theoretical posture.

---

### Innovation 2: Periodic KV Cache Rectification as a Bounded-Control Solution to Error Accumulation

Given the reframing of the problem as error accumulation, the paper's second innovation is the specific **bounded-control strategy** it proposes: periodically refresh the KV cache with a dense forward pass so that approximation errors never compound beyond a fixed window of f steps. This is conceptually simple but represents a genuinely novel approach within the sparse decoding literature.

**What makes this novel relative to prior work:** Training-free sparse decoding methods (Quest, InfLLM, ClusterKV, MagicPig) have no error-correction mechanism whatsoever — they apply sparse attention at every step and accept whatever drift accumulates. Training-aware methods (NSA by Yuan et al., 2025; MoBA by Lu et al., 2025) eliminate the training-inference mismatch by baking sparsity into pretraining, but at the cost of requiring full model retraining — a fundamentally different solution class that is infeasible for deployed models. Speculative decoding (Leviathan et al., 2023) and its sparse-KV variants (TriForce by Sun et al., 2024; MagicDec by Sadhukhan et al., 2024) do combine sparse and dense passes, but they verify **output tokens** against a dense model, making per-token accept/reject decisions. ReSA is the first method to perform **KV cache state correction** rather than output verification — it fixes the memory representation itself rather than checking whether individual token predictions match.

This distinction — state correction vs. output verification — is subtle but consequential. Output verification (speculative decoding) guarantees that the generated sequence is statistically identical to what dense decoding would produce, but it requires computing the dense model's output distribution for every batch of drafted tokens and comparing it token-by-token to the sparse model's predictions. This overhead grows with the verification frequency. State correction (ReSA) makes no guarantees about individual token correctness — incorrect tokens from the sparse path are accepted — but fixes the underlying KV cache so that future tokens are generated from a clean state. The paper's empirical finding (Appendix B, Table 3) that ReSA achieves ~2× higher throughput than sparse-KV self-speculation at matched accuracy validates that state correction is more efficient than output verification when the sparse path's token accuracy is already high. This is a **design principle** with implications beyond ReSA: when the approximation is good enough that most individual decisions are correct, fixing the accumulated state may be more efficient than verifying every decision.

**The bounded-error property is the key theoretical contribution.** The paper explicitly analyzes the memory access cost of rectification (Equation 6) and shows that the amortized cost per step is only 1/f of a dense forward pass. This means the error accumulation window can be made arbitrarily small (by decreasing f) at a predictable cost, or made larger to save computation at a predictable quality cost. The paper characterizes this tradeoff empirically (Figure 9, Figure 4, Figure 5), showing that f = 32 achieves near-dense quality while keeping rectification overhead at ~3% of total attention memory access. This parametric relationship — error bounded by O(f), cost scales as O(1/f) — gives practitioners a **single tunable knob** to navigate the accuracy-efficiency tradeoff without retraining or architecture changes. No prior training-free sparse method offers this kind of predictable, tunable error control.

The evidence is Figure 4: at f = 32, ReSA's top-3 accuracy nearly matches the "Decode Only" upper bound (where all KV cache entries were produced by dense attention and only the final decoding step uses sparse attention). Larger f values (64, 128) show graceful degradation rather than catastrophic failure. Figure 9 confirms this pattern across five math reasoning benchmarks, with f = 32 and f = 64 both achieving accuracy very close to dense, while f = 128 retains most of the benefit. This robustness to f is itself a non-trivial finding — it means the system doesn't need precise tuning to work well.

---

### Innovation 3: Demonstrating That Near-Dense Quality Is Achievable with Extreme Sparsity (90%+) When Error Accumulation Is Bounded

The paper's third contribution is the empirical demonstration of **how much sparsity becomes viable when error accumulation is controlled**. Prior sparse decoding methods typically operate at moderate sparsity levels (attending to 20–50% of context) to maintain acceptable quality, with the implicit assumption that higher sparsity necessarily means proportionally worse quality. ReSA's results challenge this assumption.

At the default sparsity ratio p = 0.9 (meaning 90% of context blocks are skipped, attending to only 10%), ReSA achieves accuracy within 0.2 percentage points of dense attention on math reasoning tasks (Table 1: 60.52% vs. 60.72% average across five benchmarks for the 7B model) and actually **exceeds** dense performance on the RULER retrieval benchmark at intermediate sparsity (Table 2: 0.559 vs. 0.549 for dense at p = 0.9). The language modeling results (Figure 5) show that even at p = 0.95 (5% attended, 95% sparsity), ReSA with f = 32 maintains accuracy substantially above the pure sparse baseline. At p = 0.98 (2% attended), degradation is visible but still far less severe than sparse decoding without rectification.

**What makes this a genuine insight rather than just a strong result:** It demonstrates that the **limiting factor for sparsity is not per-step approximation quality but cumulative error**. When error accumulation is bounded by rectification, the model tolerates far higher per-step sparsity than previously thought possible. This is a conceptual advance because it separates two confounded variables in prior work: the sparsity ratio (how much context is skipped per step) and the error accumulation budget (how many steps of errors are allowed to compound). Prior methods conflated these — increasing sparsity inevitably increased accumulated error, so the observed quality-sparsity tradeoff was actually a quality-accumulation tradeoff. ReSA disentangles them by introducing a separate accumulation-control parameter f. This means the design space for sparse decoding is actually two-dimensional: you can independently tune sparsity p and accumulation window f, rather than being forced along a single p-quality curve.

The practical implication is significant: if 90% sparsity with bounded accumulation achieves near-dense quality, the attention memory access can be reduced by roughly 10× compared to dense attention (the theoretical factor is higher due to block selection overhead, but still substantial). This opens the door to deploying long-context models on hardware that would otherwise be memory-bandwidth-bound. The paper's measured speedups (up to 2.42× end-to-end, Figures 7 and 8) are lower than the theoretical attention reduction because non-attention components (feedforward layers, embeddings) don't benefit from sparsity — but as sequence length grows, attention becomes the dominant cost, and the gap between theoretical and realized speedup narrows. The trend in Figures 7 and 8 shows speedup increasing from 1.02–1.03× at 4K to 2.18–2.44× at 256K, confirming that the benefit scales with sequence length as attention dominates.

The RULER results (Table 2) are particularly instructive: at p = 0.9, ReSA matches or slightly exceeds dense attention on average (0.559 vs. 0.549). The slight improvement is likely noise or a benign effect of attention regularization (sparse attention may act as a form of dropout, preventing overfitting to irrelevant context), but the key finding is that **sparsity does not inherently hurt retrieval accuracy** when error accumulation is controlled. This challenges the assumption in prior work that sparse attention must trade accuracy for speed.

---

### Innovation 4: The "Verify the Memory, Not the Output" Design Principle and Its Efficiency Implications

The paper's fourth contribution is a **design principle** that emerges from the comparison with speculative decoding (Appendix B, Table 3): when the approximate attention path is sufficiently accurate, **verifying and correcting the KV cache state is more efficient than verifying individual output tokens**. This principle is not stated abstractly in the paper but is implicit in the architecture choice and the experimental comparison.

**The distinction matters.** Speculative decoding with sparse KV caches (TriForce, MagicDec) operates on a "trust but verify" model for outputs: use sparse attention to quickly draft candidate tokens, then run dense attention to check whether each drafted token matches what the full model would have produced. This guarantees output identical to dense decoding but at the cost of verifying every batch of drafted tokens, and discarding rejected tokens. The verification cost is high because it requires computing the dense model's full output distribution and comparing per-token.

ReSA operates on a "correct the memory" model: accept whatever tokens the sparse path produces, but periodically fix the KV cache to prevent drift. This means no tokens are ever discarded — every sparse-generated token is kept — and no per-token output distribution comparison is performed. The cost is a single batched dense forward pass every f steps to recompute KV entries.

**Why this principle emerges from the empirical evidence:** Table 3 shows approximately 2× speedup for ReSA over sparse-KV self-speculation at matched accuracy. The paper attributes this to the fact that speculative decoding's verification step only accepts about 8 out of 16 drafted tokens on average, effectively halving the generation rate. ReSA, by accepting all tokens and only correcting the cache, avoids this throughput penalty. The key enabling condition is that the sparse path's token accuracy is already near-dense — Table 1 shows ReSA's accuracy gap from dense is only 0.2 points on average. If the sparse path were substantially less accurate, the "verify the output" approach would be necessary to maintain quality. But when the sparse path is already good, per-token verification becomes a costly redundancy — the marginal quality gain doesn't justify the latency cost.

This is a **pragmatic insight** with implications for system design beyond ReSA. In any system that uses approximate computation for efficiency, there are two correction philosophies: verify each output to ensure correctness, or periodically correct the internal state to bound drift. The choice depends on whether the dominant error mode is **individual decision mistakes** (which output verification catches) or **accumulated state corruption** (which state correction addresses). The paper demonstrates empirically that for sparse attention in long-sequence generation, the dominant error mode is the latter — which is not obvious a priori and requires the experimental characterization that the paper provides.

The design principle also has practical consequences for deployment. Output verification (speculative decoding) requires maintaining two separate forward-pass implementations (sparse draft and dense verify) and complex accept/reject logic that can interact poorly with batching and scheduling systems. State correction (ReSA) requires only that the system support occasional batched dense forward passes — which modern serving systems already do for prefill — making it easier to integrate with existing infrastructure. The paper explicitly notes this compatibility advantage in Section 2.2.

This innovation is **incremental in mechanism but fundamental in principle**: the ReSA architecture itself is a straightforward alternation of sparse and dense passes, but the *reasoning about why this specific alternation beats other alternations* (speculative decoding) advances understanding of when and how to combine approximate and exact computation in autoregressive systems.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The paper evaluates on three distinct task categories. For math reasoning (Section 3.2): Minerva Math (Lewkowycz et al., 2022), Gaokao 2023 En (Liao et al., 2024), OlympiadBench (He et al., 2024), AIME24, and AMC23 — five benchmarks selected because they produce average inference lengths well above 512 tokens, making them suitable for evaluating long-context generation quality (the paper explicitly excludes GSM8K and MATH because their average inference lengths fall below this threshold). For language modeling (Section 3.3): long-sequence book data, with each sequence truncated from the left to ensure identical prediction tokens across settings. For retrieval (Section 3.4): the RULER benchmark, a standard long-context retrieval evaluation suite.

- **Base model(s).** Two model families are used. For math reasoning: DeepSeek-R1-Qwen-Distill at both 1.5B and 7B scales (Guo et al., 2025), chosen because test-time scaling produces very long reasoning chains (average lengths of 4,000–12,000 tokens, Table 1) that stress sparse decoding's error accumulation behavior. The 7B variant has 28 attention heads with 4 KV heads, 3584 hidden dimension, and 28 layers. For language modeling, retrieval, and efficiency measurements: Qwen2.5 7B (Yang et al., 2024), a standard pretrained Transformer representative of widely-deployed architectures.

- **Metrics.** For math reasoning: task-specific accuracy (%) on each benchmark, graded against ground-truth answers. For language modeling: top-3 next-token prediction accuracy computed over the final 32 tokens of each sequence, focusing on the later decoding stages where error accumulation is most pronounced. For retrieval: accuracy on the RULER benchmark's subtasks (single-key retrieval, multi-key, multi-query, multi-value, etc., plus an average across all subtasks). For efficiency: kernel-level CUDA execution time in milliseconds (latency) and end-to-end throughput in tokens per second, both excluding CPU-side scheduling overhead to isolate GPU performance.

- **Baselines.** The paper compares against: **(1) Dense attention** — full dense attention using FlashAttention as the highly-optimized implementation, serving as the quality upper bound and the efficiency baseline. **(2) Sparse decoding alone** — the same group block sparse attention mechanism (Section 2.1) applied at every decoding step without any rectification, directly demonstrating the error accumulation problem. **(3) Sparse with dense first two layers** (labeled "Sparsedense2" in Table 1) — a variant where the first two transformer layers use dense attention and the remaining layers use sparse attention, following the pattern from Quest (Tang et al., 2024), tested as an ablation to assess whether early-layer densification helps. **(4) Sparse KV-based self-speculation** (Appendix B, Table 3) — speculative decoding using the sparse KV cache for drafting and dense cache for verification, with speculation length set to 16, serving as a throughput comparison point. For efficiency measurements, the primary baseline is FlashAttention running dense attention at the same sequence lengths and batch sizes.

- **Generation budget / compute accounting.** For quality experiments, the primary comparison is between methods operating at the same sparsity ratio p (fraction of blocks skipped) and rectification frequency f (when applicable). Since ReSA and sparse decoding use the same per-step attention mechanism, the comparison is naturally budget-matched in terms of attention memory access. For efficiency measurements (Section 3.5), the paper reports CUDA kernel execution time at fixed sequence lengths (16K, 64K, 256K) and batch size 8, using a shared KV cache strategy across layers to prevent memory overflow. End-to-end throughput is measured in both FP16 and INT4 precision, with INT4 using the Marlin kernel (Frantar et al., 2024) for quantized matmul with group size 128.

- **Cross-validation / statistical protocol.** The paper does not employ cross-validation or statistical significance testing. Results are reported as single-run measurements across fixed test sets. For language modeling experiments (Section 3.3), the paper uses identical data for each target sequence length, truncating from the left to ensure prediction tokens are "perfectly aligned across all settings" — this is a careful experimental control to eliminate data-sampling variance, but does not constitute cross-validation. The ablation studies (Section 3.6) sweep across hyperparameter values and report per-benchmark results, but without error bars or confidence intervals.

### Main Quantitative Results

#### Math Reasoning: Test-Time Scaling Performance

**Headline result:** ReSA achieves near-dense accuracy on long-sequence math reasoning while pure sparse decoding consistently underperforms. For the 7B model (Table 1, bottom panel), ReSA averages 60.52% accuracy across five benchmarks compared to 60.72% for dense attention — a gap of only 0.20 percentage points. In contrast, sparse decoding alone averages 57.72%, a gap of 3.00 points from dense. The 1.5B model (Table 1, top panel) shows a similar pattern: ReSA averages 45.56% versus 46.82% for dense (gap of 1.26 points), while sparse decoding averages 43.50% (gap of 3.32 points).

**Per-benchmark breakdown.** Looking at individual benchmarks for the 7B model (Table 1):

- **Minerva:** Dense 40.4%, Sparse 38.1%, ReSA 39.7%. ReSA recovers most of the 2.3-point gap, closing to within 0.7 points of dense.
- **Gaokao2023En:** Dense 73.8%, Sparse 72.9%, ReSA 73.5%. A relatively small gap on this task, with ReSA nearly matching dense.
- **OlympiadBench:** Dense 52.3%, Sparse 48.4%, ReSA 52.3%. ReSA **exactly matches** dense performance, fully closing the 3.9-point gap from sparse decoding.
- **AIME24:** Dense 48.1%, Sparse 46.1%, ReSA 51.1%. ReSA **exceeds** dense performance by 3.0 points — the only benchmark where ReSA meaningfully outperforms dense. The paper does not discuss this anomalous result; possible explanations include sparse attention acting as a beneficial regularizer or statistical noise given the small AIME24 test set.
- **AMC23:** Dense 89.0%, Sparse 83.1%, ReSA 86.0%. ReSA recovers about half of the 5.9-point gap from sparse decoding, leaving a 3.0-point gap from dense.

**Average sequence lengths.** For the 7B model, average decoding lengths range from 2,890 tokens (Gaokao2023En) to 10,475 tokens (AIME24), with an overall average of 6,127 tokens (Table 1). The 1.5B model produces longer sequences on average (8,058 tokens overall), likely because the smaller model requires more reasoning steps to reach answers. This confirms the test-time scaling setting: models generate thousands of tokens in reasoning chains, making sparse decoding's error accumulation a genuine practical concern.

**The Sparsedense2 ablation.** Adding dense attention to the first two layers (following Quest's design) provides no meaningful improvement over pure sparse decoding for the 7B model: Sparsedense2 averages 57.38% versus Sparse's 57.72% (Table 1). This is notable because Quest found early-layer densification helpful. The paper's brief mention — "manually enforcing dense layers for the first two layers does not result in a significant improvement in math-reasoning tasks" — suggests that error accumulation in deeper layers dominates, or that DeepSeek-R1-Distill's attention patterns differ from the models tested in Quest.

**Sparsity ratio effect on math reasoning (Figure 9).** Sweeping p across {0.9, 0.95, 0.98} (attending to 10%, 5%, and 2% of blocks respectively) at various rectification frequencies:

- At p = 0.9 (10% attended, the default): ReSA with f = 32 or f = 64 achieves accuracy very close to the dense baseline across all five benchmarks. The curves for f = 32 and f = 64 substantially overlap.
- At p = 0.95 (5% attended): A noticeable but modest gap from dense appears. For example, AIME24 with f = 32 drops from approximately 50% (dense level) at p = 0.9 to roughly 46% at p = 0.95. AMC23 drops from roughly 86% to roughly 82%. The pure sparse baseline at p = 0.95 is significantly worse than ReSA at any f.
- At p = 0.98 (2% attended): Degradation is more pronounced, but ReSA still outperforms pure sparse decoding at the same sparsity. For instance, Gaokao2023En at p = 0.98 with f = 32 achieves roughly 72% versus dense at 74%, while pure sparse drops below 70%.

The consistent pattern across all benchmarks: ReSA outperforms sparse decoding at every sparsity level, and the benefit is largest at the most extreme sparsity (p = 0.98), where pure sparse decoding suffers severely from error accumulation while rectification partially compensates.

#### Language Modeling: Long-Sequence Next-Token Prediction

**Headline result (Figure 4):** ReSA with rectification frequency f = 32 (equivalent to x = 32 in the prefix-suffix simulation, where x tokens are encoded with sparse attention before a rectification-triggering boundary) nearly matches the "Decode Only" upper bound — the setting where the entire KV cache was generated by dense attention and only the final decoding step uses sparse attention. This upper bound isolates the effect of KV cache quality from per-step sparse attention approximation: since decoding always uses sparse attention, the only difference between settings is how the KV cache entries were produced (dense vs. sparse).

**Sequence length scaling.** Figure 4 (left, x = f) plots top-3 accuracy for four configurations as sequence length increases from 8K to 64K:

- **Dense (full dense attention):** Accuracy decreases modestly from roughly 0.795 at 8K to approximately 0.79 at 64K — a natural degradation as longer sequences present harder prediction tasks.
- **Decode Only (dense KV cache, sparse attention at decode):** Accuracy tracks dense very closely, approximately 0.01–0.015 lower at all lengths. This is the performance ceiling for ReSA: even with a perfect KV cache, sparse attention approximation at the decode step introduces a small error.
- **ReSA (f = 32):** Accuracy at 8K starts near 0.79, tracks downward slightly, and reaches roughly 0.78 at 64K — staying within approximately 0.01 of the Decode Only upper bound. This demonstrates that rectification every 32 steps bounds the KV cache quality sufficiently that the dominant remaining error source is per-step sparse approximation, not cache drift.
- **Sparse (no rectification):** Accuracy starts near 0.78 at 8K but drops more steeply, reaching roughly 0.765 at 64K. The gap from ReSA widens with sequence length — approximately 0.01 at 8K, growing to roughly 0.015 at 64K — directly visualizing the cumulative error effect that rectification prevents.

**Key insight from the Decode Only reference:** The fact that ReSA nearly matches the Decode Only upper bound means rectification at f = 32 is effectively producing KV caches of near-dense quality. The residual gap between ReSA and the upper bound (~0.01 in top-3 accuracy) represents the maximum accumulated error over 32 sparse decoding steps — which is small and bounded, confirming the bounded-control design works as intended.

**Sparsity sweep at fixed rectification (Figure 5, right panel, varying p).** At a fixed rectification frequency of f = 32 (x = 32 in the simulation), varying the sparsity ratio p ∈ {0.05, 0.1, 0.2} (attending to 5%, 10%, 20% of blocks):

- p = 0.2 (20% attended): Accuracy runs roughly 0.005–0.01 below the dense reference across all lengths, the closest match of any sparsity level.
- p = 0.1 (10% attended): Accuracy approximately 0.01–0.015 below dense across lengths. The paper adopts this as the default due to its "better trade-off between performance and efficiency" — the accuracy loss from p = 0.2 to p = 0.1 is small, but the speedup is substantial (2× fewer attention memory accesses).
- p = 0.05 (5% attended): Accuracy roughly 0.02–0.03 below dense, with the gap widening slightly at longer lengths. The paper notes that this extreme sparsity remains viable: top-3 accuracy drops from roughly 0.79 at 8K to roughly 0.775 at 64K, versus dense's 0.79 at 64K — a gap of only about 0.015 despite attending to only 5% of context.

The paper explicitly notes: "there is a noticeable performance gap between the p = 0.98 and p = 0.95" (referring to sparsity levels of 2% and 5% attended, respectively, using the paper's p-as-sparsity-ratio convention). This suggests a threshold effect: at moderate sparsity (5–20% attended), the block selection mechanism is accurate enough that attending to more blocks provides diminishing returns, but below ~5% attended, too many relevant blocks are missed even by the scoring mechanism.

#### Long-Sequence Retrieval: RULER Benchmark

**Headline result (Table 2):** ReSA at moderate sparsity achieves retrieval accuracy comparable to or slightly exceeding dense attention. The average across all RULER subtasks is 0.549 for dense, 0.559 for ReSA at p = 0.9 (10% attended), 0.552 at p = 0.8 (20% attended), and 0.531 at p = 0.95 (5% attended). ReSA at p = 0.9 actually **outperforms** dense on average by 0.01, though this is likely within noise given the single-run reporting.

**Per-subtask breakdown (Table 2):**

- **Single-key retrieval:** The only task where ReSA at p = 0.9 (0.625) substantially **exceeds** dense (0.563). This is a striking result: for the simplest retrieval task (finding a single key in a long context), the sparsification actually helps, perhaps by filtering out distractor context.
- **Multi-query:** ReSA at p = 0.9 (0.203) slightly trails dense (0.211), but is notably better than p = 0.95 (0.180).
- **Multi-key:** ReSA at p = 0.9 (0.750) exceeds dense (0.688) by 0.062 — another case where sparsification helps.
- **Multi-value:** ReSA at all sparsity levels (0.234–0.246) matches or slightly trails dense (0.246).
- **Frequent word extraction (FWE):** ReSA at p = 0.9 (0.760) trails dense (0.833) noticeably.
- **Variable tracking (VT):** All methods identical at 0.719.
- **Context word extraction (CWE):** ReSA at p = 0.9 (0.178) exceeds dense (0.134) by 0.044 — sparsification substantially improves performance on this subtask.

The pattern is heterogeneous: ReSA helps on some retrieval subtasks (single-key, multi-key, CWE) and hurts on others (FWE). The paper does not discuss this per-subtask variation, but a plausible interpretation is that sparsification acts as a form of attention regularization — filtering out irrelevant context helps when the relevant information is localized (single-key, multi-key) but hurts when the task requires scanning the full context for word frequencies (FWE).

**Sparsity trend:** Moving from p = 0.95 (5% attended) to p = 0.9 (10% attended) improves average accuracy from 0.531 to 0.559 — a substantial 0.028 gain. Further increasing to p = 0.8 (20% attended) yields 0.552 — marginally lower than p = 0.9, again suggesting that 10% attention captures most relevant information and additional blocks may add noise rather than signal. The paper concludes that p = 0.9 "represents a better trade-off between performance and efficiency on the RULER benchmark."

**Why rectification matters less for RULER:** As the paper notes in Section 3.4, "the RULER benchmark focuses on relatively short output sequences." With short generation lengths, sparse decoding's error accumulation has less time to compound, so the final accuracy is primarily determined by per-step sparse approximation quality rather than KV cache drift. This is consistent with ReSA's design: when generation is short, the rectification benefit is marginal, and the key determinant of quality is the block selection mechanism and sparsity ratio. This explains why the RULER experiments focus on varying p rather than f.

#### Inference Efficiency: Kernel-Level and End-to-End

**Headline result (Figures 6, 7, 8):** ReSA delivers up to 2.18× end-to-end speedup in FP16 and 2.44× in INT4 at 256K context length, with the speedup increasing monotonically with sequence length. At shorter contexts, the speedup is modest: approximately 1.02–1.03× at 4K and 1.11–1.18× at 16K, reflecting that attention is not the dominant cost at these lengths.

**Kernel-level latency breakdown (Figure 6):** At each of three sequence lengths (16K, 64K, 256K), latency is decomposed into three components: sparse estimation (computing block scores and selecting top-n blocks), attention computation (the actual sparse attention over selected blocks), and rectification (the amortized dense forward pass). Key observations:

- **At 16K:** Dense attention latency is approximately 10 ms. ReSA total is roughly 5 ms — about 2× faster — with sparse estimation and attention each consuming roughly 2 ms and rectification negligible at this length.
- **At 64K:** Dense attention grows to roughly 28 ms. ReSA total is roughly 13 ms — about 2.15× faster. Sparse estimation (~5 ms) and attention (~5 ms) are roughly equal, rectification adds approximately 3 ms (28.9% of total attention latency per the paper).
- **At 256K:** Dense attention reaches roughly 65 ms. ReSA total is roughly 30 ms — about 2.17× faster. Sparse estimation (~12 ms) and attention (~12 ms) remain roughly balanced, and rectification adds approximately 10 ms (32.7% of total attention latency per the paper).

**The estimation-attention balance:** The paper notes that "sparse estimation and attention computation consume comparable amounts of time" because their memory access patterns scale similarly: estimation accesses mem(KV_cache)/b and attention accesses mem(KV_cache) × p. With b = 16 and p = 0.1 (attending to 10% of blocks), both operate on roughly 6–10% of the full KV cache — so they consume similar fractions of total attention memory bandwidth. This implies that further increasing the sparsity ratio (higher p, attending to fewer blocks) would yield diminishing speedup returns because the sparse estimation cost (fixed at ~6.25% of KV cache for b = 16) would become the bottleneck. The paper explicitly confirms: "under fixed block size, further increasing the sparsity ratio can not bring significant speed-up."

**Rectification overhead analysis.** The paper reports that rectification accounts for 28.9% of attention-related latency at 64K and 32.7% at 256K. The paper notes that "when the sequence length is scaling, the latency ratio will converge to the memory access ratio 1/f" = 1/32 = 3.125%. The observed ratios (28.9%, 32.7%) are higher than this asymptotic limit because at these sequence lengths, the sparse estimation and attention costs are not yet fully dominated by KV cache size — there are fixed overheads per kernel launch, per SM scheduling, etc. As sequence length grows very large, the rectification fraction should approach 3.125% of attention cost, making it negligible.

**End-to-end throughput scaling (Figures 7 and 8):** The end-to-end speedup factors:

| Context Length | FP16 Speedup | INT4 Speedup |
|---|---|---|
| 4K | 1.02× | 1.03× |
| 16K | 1.11× | 1.18× |
| 64K | 1.47× | 1.70× |
| 256K | 2.18× | 2.44× |

The speedup grows roughly quadratically with sequence length, consistent with ReSA addressing the O(n²) attention bottleneck while non-attention components (feedforward layers, embeddings) scale as O(n). At 4K, attention is a small fraction of total latency, so reducing attention cost yields minimal end-to-end gain. By 256K, attention dominates, and the 5× theoretical attention speedup translates to roughly 2.2–2.4× end-to-end.

**INT4 vs. FP16 comparison.** INT4 consistently shows higher speedup factors than FP16 at the same sequence length (e.g., 1.70× vs. 1.47× at 64K; 2.44× vs. 2.18× at 256K). This is because INT4 quantization reduces the matmul cost of feedforward layers (making them faster), which makes attention an even larger fraction of total latency — so the attention speedup from ReSA has proportionally more impact on end-to-end throughput. The paper uses the Marlin kernel for INT4 matmul with group size 128, while the attention computations (both sparse and dense) remain in FP16.

**Practical significance.** The 256K context length is the regime where dense attention becomes severely IO-bound on A100 GPUs (80GB HBM2e bandwidth of ~2 TB/s). ReSA reduces the KV cache memory access by approximately 5× (from 100% to ~19.4% per step on average), directly alleviating this bandwidth bottleneck. The 2.42× INT4 speedup at this length means a model that would take 10 seconds per token with dense attention takes roughly 4.1 seconds — still not interactive, but substantially more practical for batch processing.

### Ablation Studies and Robustness Checks

**Rectification frequency f (Figure 9):** Sweeping f ∈ {16, 32, 64, 128} at three sparsity levels (p ∈ {0.9, 0.95, 0.98}) across five math reasoning benchmarks reveals a consistent pattern: f = 32 and f = 64 achieve very similar accuracy, with curves largely overlapping. f = 16 provides marginal additional gains (1–2 percentage points on some benchmarks at the highest sparsity) but at double the rectification cost. f = 128 retains most of the benefit over pure sparse decoding but shows slightly lower accuracy, particularly at p = 0.95 and p = 0.98 on harder benchmarks (e.g., AIME24 at p = 0.95 with f = 128 drops roughly 2 points below f = 32). The robustness to f is a key practical finding: the method is not sensitive to precise tuning of rectification frequency, and a wide range from 16 to 128 provides substantial quality improvement over sparse decoding. The paper defaults to f = 32 as the sweet spot balancing quality and overhead.

**Sparsity ratio p (Figures 5, 9; Table 2):** At fixed f = 32, varying the fraction of attended blocks from 20% (p = 0.8) to 2% (p = 0.98):
- In language modeling (Figure 5): p = 0.2 and p = 0.1 perform nearly identically, both tracking close to dense. p = 0.05 shows modest degradation (0.01–0.015 in top-3 accuracy). The paper selects p = 0.9 (10% attended) as default, noting it offers "better trade-off between performance and efficiency" than p = 0.8 (which provides minimal accuracy gain at double the attention cost).
- In math reasoning (Figure 9): The gap between p = 0.9 and p = 0.95 is more noticeable than in language modeling, particularly on AIME24 and AMC23. p = 0.98 shows clear degradation, though ReSA at any f still outperforms pure sparse decoding at the same sparsity.
- In retrieval (Table 2): p = 0.9 achieves the best average accuracy (0.559), slightly outperforming both p = 0.8 (0.552) and p = 0.95 (0.531).

**Sparse vs. Sparsedense2 (Table 1):** Restricting sparse attention to all layers (the paper's default) versus using dense attention for the first two layers (following Quest's design) shows minimal difference: 57.72% vs. 57.38% average accuracy for Sparse and Sparsedense2 respectively on the 7B model. The paper interprets this as evidence that error accumulation in deeper layers dominates any benefit from early-layer densification, at least for math reasoning with DeepSeek-R1-Distill.

**Rectification frequency in language modeling (Figure 4, varying x = f):** The simulation framework varies the suffix length x (which controls how many tokens are encoded with sparse attention before a dense rectification equivalent). At shorter x (x = 16, 32), accuracy nearly matches the Decode Only upper bound. At x = 128 and x = 256 (not shown in the paper but implied by the trend), accuracy degrades toward the pure sparse baseline. This ablation directly visualizes the bounded-error property: smaller x means tighter error bounds and better quality, converging to the Decode Only upper bound as x → 1 (every token rectified, equivalent to dense decoding). The paper focuses on x = 32 as the default, which is sufficiently tight to achieve near-ceiling quality.

**Self-speculation comparison (Appendix B, Table 3):** ReSA achieves approximately 1.92× average speedup over sparse KV-based self-speculative decoding at matched accuracy on math reasoning tasks (individual task speedups range from 1.86× on AMC23 to 1.98× on OlympiadBench). The paper attributes this to self-speculation's per-token verification overhead: with speculation length 16, only about 8 tokens are typically accepted per verification step, effectively halving the generation rate compared to ReSA's batch-rectification approach.

**Block size b and minimum blocks n_min:** These hyperparameters are not ablated. The paper fixes b = 16 and n_min = 16, citing standard practice from Quest and noting that these values "avoid performance degradation in short context." The robustness to these choices is untested in this paper but presumably follows from Quest's ablations.

**Negative result — ReST^EM equivalent not applicable:** Unlike the example paper which tested an RL-fine-tuned revision model that degraded performance, ReSA does not involve model fine-tuning, so this class of negative result doesn't apply. The closest negative finding is that Sparsedense2 (dense first two layers) provides no benefit in the math reasoning setting — a result that contradicts expectations from prior work (Quest) and suggests architectural or task-dependent sensitivity.

### Critical Assessment

The experiments largely support the paper's central claims, but several important caveats limit the strength and generality of the conclusions.

**Claim: ReSA achieves near-lossless generation quality relative to dense attention.** The evidence is strong for math reasoning (Section 3.2) and language modeling (Section 3.3), where ReSA with default settings (f = 32, p = 0.9) closes most or all of the gap between sparse and dense decoding. Table 1 shows ReSA averaging 60.52% versus dense's 60.72% — a gap of 0.2 percentage points, which qualifies as "near-lossless" in practical terms. However, three factors complicate this claim:

First, the "lossless" claim should be benchmark-specific. On AMC23, ReSA trails dense by 3.0 points (86.0% vs. 89.0%) — not near-lossless but a meaningful degradation. On AIME24, ReSA exceeds dense by 3.0 points — which, if not noise, suggests the sparse approximation is changing model behavior in ways that can improve or degrade performance depending on the task. "Near-lossless on average" would be more precise than "near-lossless" without qualification.

Second, all quality experiments use a single model family at two scales (DeepSeek-R1-Qwen-Distill 1.5B and 7B for reasoning; Qwen2.5 7B for language modeling). These are both Qwen-derived architectures with GQA. Whether ReSA's rectification frequency generalizes to models with different attention patterns (standard MHA with more heads, different KV head ratios, models from other families like Llama or Gemma) is untested. The paper's claim that the method works on "standard pretrained Transformers" is supported only for Qwen architectures.

Third, the language modeling experiments (Section 3.3) use a **simulated** sparse decoding pattern rather than true autoregressive generation: the prefix is encoded with dense attention, the suffix with sparse, and the boundary between them acts as an implicit rectification. This simulation captures KV cache quality effects but does not replicate the full dynamics of ReSA's alternating sparse-rectify cycle over thousands of steps. In particular, it cannot capture whether errors from sparse decoding in the suffix would affect the token identities generated during the suffix (since the simulation uses ground-truth tokens from the book data, not model-generated tokens). True autoregressive evaluation — generating long sequences with ReSA and measuring perplexity or accuracy — would be a stronger validation. The paper's math reasoning experiments are genuine autoregressive generation, so the core claim has real-generation support, but the language modeling results should be interpreted as an upper bound on expected ReSA performance, not a direct measurement.

**Claim: ReSA delivers up to 2.42× end-to-end speedup.** The efficiency measurements (Figures 7, 8) convincingly demonstrate this at 256K context, with speedup growing quasi-quadratically with sequence length. The kernel-level measurements (Figure 6) provide a clean latency decomposition showing that the sparse estimation and sparse attention components are well-balanced and rectification overhead is manageable. However:

The speedup is measured at batch size 8 with a shared KV cache across layers. The shared KV cache is a memory-saving strategy that the paper adopts to prevent overflow on the 80GB A100, but it means the KV cache is compressed compared to a standard per-layer cache. This could affect the relative cost of attention versus other operations in ways that make the speedup numbers optimistic or pessimistic compared to standard deployment configurations. The paper does not ablate batch size or KV cache strategy.

At shorter context lengths where many production deployments operate (4K–16K), the speedup is modest (1.02–1.18×). ReSA is primarily valuable for very long contexts (>64K), and the paper's efficiency claims should be contextualized by this length dependence. The paper is explicit about this (the speedup numbers are reported per-length in Figures 7 and 8), but the headline "up to 2.42×" could be misread as typical rather than peak.

The comparison with speculative decoding (Appendix B, Table 3) reports 1.92× speedup on math reasoning tasks, but this comparison uses a specific self-speculation configuration (speculation length 16) without sweeping this hyperparameter. Self-speculation's acceptance rate and thus throughput depend on speculation length, target model, and task — the paper's single configuration may not represent the best possible self-speculation throughput. The claim that "ReSA achieves nearly 2× speedup over self-speculation" is supported under the tested configuration but may not generalize to optimally-tuned self-speculation settings.

**Claim: The dominant error mode in sparse decoding is accumulated KV cache drift, not per-step approximation error.** The paper provides indirect but compelling evidence for this reframing: pure sparse decoding degrades with sequence length (Figure 1, Figure 4), while ReSA — using the same per-step approximation but with periodic cache correction — maintains near-constant quality relative to dense. This is a clean experimental dissociation: same per-step method, different accumulation behavior, different outcomes. The language modeling results (Figure 4) are particularly clear: the "Decode Only" upper bound (dense KV cache, sparse attention) nearly matches dense accuracy, showing that per-step sparse approximation alone introduces minimal error; the gap between "Decode Only" and pure sparse decoding represents the accumulation effect that rectification addresses.

However, the paper does not directly **measure** the KV cache drift — it infers it from downstream accuracy. A more direct validation would compute the cosine similarity or L2 distance between sparse-produced KV entries and their dense-attention equivalents as a function of decoding step, quantifying the drift and showing that rectification resets it. Without this, the claim that "error accumulation in the KV cache" is the causal mechanism remains an inference from output quality, not a directly observed phenomenon.

**Missing experiments and baselines:**

- **No comparison with other training-free sparse attention methods** (Quest, InfLLM, ClusterKV, MagicPig) at matched sparsity levels. The paper builds on Quest's block selection mechanism but does not compare ReSA against Quest's full system (which includes early-layer densification and other optimizations) to isolate the contribution of rectification. A comparison showing ReSA outperforms Quest at the same overall sparsity would strengthen the claim that rectification is the key missing ingredient.

- **No sweep of block size b.** The paper fixes b = 16 based on Quest's defaults but provides no evidence that this is optimal for ReSA. Smaller blocks (b = 8) would enable finer-grained selection but increase the 1/b sparse estimation cost and potentially change the sparsity-quality tradeoff. Larger blocks (b = 32) would reduce estimation overhead but coarsen selection. Given that the 1/b term contributes 6.25% to the total KV cache access (Equation 6), the choice of b has a material impact on efficiency.

- **No measurement of generation quality at scale.** The quality experiments on math reasoning use 500 test questions (MATH's split) and individual benchmarks of unspecified size. The language modeling experiments use unspecified book data. The paper does not report dataset sizes, making it difficult to assess statistical reliability. Results are reported without error bars, confidence intervals, or standard deviations.

- **No ablation of the local window n_local or minimum blocks n_min.** These parameters are set to 1 and 16 respectively with no justification beyond "avoiding performance degradation in short context." The sensitivity to these choices is unknown.

- **No evaluation of combined sparse-rectify dynamics in autoregressive language modeling.** As noted above, the Section 3.3 experiments are simulated, not generated. True autoregressive evaluation on a standard benchmark (e.g., PG19, BookCorpus perplexity) with ReSA would provide a more realistic quality measurement.

- **No comparison with learned block selection strategies** (e.g., SeerAttention, which the paper mentions as compatible). The paper uses training-free min-max descriptors; it's unknown whether learned descriptors would enable higher sparsity at the same quality or reduce the need for rectification.

**Where the claims hold conditionally:**

- The near-lossless quality claim holds when f ≤ 64 and p ≤ 0.9. At f = 128 or p = 0.95–0.98, quality degrades measurably (Figures 5, 9).
- The speedup claims hold at very long contexts (64K–256K) on A100-80G hardware with the tested batch size and KV cache strategy. At shorter contexts (4K–16K), the speedup is modest (1.02–1.18×).
- The advantage over self-speculation holds under the tested speculation length (16) and acceptance rates; optimal self-speculation tuning could change this.
- All results are specific to Qwen-derived model architectures (Qwen2.5 and DeepSeek-R1-Qwen-Distill) and may not transfer to substantially different architectures (different attention mechanisms, different head counts, different layer norms).

**Strengths of the experimental design:**

- The three-task evaluation (reasoning, language modeling, retrieval) covers complementary aspects: long generation with error accumulation (reasoning), KV cache quality independent of generation dynamics (language modeling simulation), and short-generation retrieval where sparse approximation dominates.
- The Decode Only upper bound in language modeling (Figure 4) is a clever control — it isolates KV cache quality from sparse attention approximation, directly quantifying the maximum benefit rectification can provide.
- The kernel latency decomposition (Figure 6) provides transparency into where time is spent, enabling informed optimization.
- The ablation of rectification frequency f across a range from 16 to 128 at three sparsity levels (Figure 9) thoroughly characterizes the dual-knob tradeoff and demonstrates robustness to f.
- The self-speculation comparison (Table 3) addresses a natural alternative design (why not verify outputs rather than correct state?) and provides empirical justification for the design choice.

## 6. Limitations and Trade-offs

### Accuracy Improvement Requires Non-Trivial Rectification Frequency — Sparsity Alone Cannot Be Driven Arbitrarily High

The paper demonstrates that ReSA achieves near-dense quality at p = 0.9 (attending to 10% of blocks) with rectification frequency f = 32. However, the ablation studies (Figure 9) reveal a hard constraint: when the sparsity ratio is pushed to more extreme levels (p = 0.95 or p = 0.98, attending to only 5% or 2% of blocks), ReSA's accuracy degrades measurably even with frequent rectification. For instance, at p = 0.98 with f = 32, AIME24 accuracy drops from approximately 50% (dense-level, at p = 0.9) to roughly 44% — a 6-point gap that rectification at any frequency cannot fully close (Figure 9, third column). On AMC23, the drop from p = 0.9 to p = 0.98 is roughly 7–8 points at f = 32 (from ~86% to ~78%).

The consequence is that ReSA does not eliminate the accuracy-sparsity tradeoff — it shifts where the tradeoff becomes binding. The paper's default configuration (p = 0.9, f = 32) achieves near-dense quality, but the attention memory access is still approximately 19.4% of the full KV cache per step on average (Equation 6: 1/16 for block estimation + 0.1 for attention + 1/32 for rectification). This is a ~5× reduction from dense attention's 100% access, not a 10× or 50× reduction. Pushing sparsity further (p = 0.95, attending to 5%) would achieve ~14% memory access but with a measurable quality gap that rectification cannot eliminate because the per-step sparse approximation itself — not just error accumulation — becomes the bottleneck. The paper's kernel latency analysis (Section 3.5.1) explicitly acknowledges this saturation: "under fixed block size, further increasing the sparsity ratio can not bring significant speed-up" because the sparse estimation cost (mem(KV_cache)/b) becomes the dominant remaining term.

**What evidence exists:** Figure 9 provides the key evidence across five math reasoning benchmarks. The gap between p = 0.9 and p = 0.95 is visible but modest (1–4 points across benchmarks); the gap between p = 0.95 and p = 0.98 is larger and more consistent. Figure 5 (language modeling) confirms a similar pattern: p = 0.05 (5% attended) shows a gap of 0.01–0.015 in top-3 accuracy from dense, versus 0.005–0.01 for p = 0.1 (10% attended). The paper explicitly notes: "there is a noticeable performance gap between the p = 0.98 and p = 0.95."

**Mitigation status:** The paper is transparent about this tradeoff, adopting p = 0.9 as the default specifically because it "offers better trade-off between performance and efficiency" (Section 3.3). It suggests that "more advanced block selection strategies such as SeerAttention" could enable higher sparsity at the same quality, but this is speculative — no experiments with learned block descriptors are provided. Without improved block selection mechanisms, the practical sparsity ceiling with near-dense quality appears to be approximately 90% (p = 0.9), corresponding to roughly 5× attention memory reduction.

### The Difficulty Estimation Cost Is Unaccounted for in Practical Deployment

This is not a limitation the paper itself identifies — it is a gap in the deployment story. ReSA requires no explicit difficulty estimation (unlike the compute-optimal test-time scaling paper that generated 2048 samples per question), but it does require choosing the **rectification frequency f and sparsity ratio p** for each deployment scenario. The paper's ablation studies (Figure 9) characterize the (p, f) tradeoff space, but they do so using **ground-truth accuracy on held-out benchmarks** — that is, the "best" configuration is selected by evaluating multiple hyperparameter combinations on the same benchmarks used for reporting results, and choosing the one that achieves the best accuracy-efficiency tradeoff.

The consequence is that a practitioner deploying ReSA on a new model or task domain has no principled way to select p and f without running a comparable set of ablation experiments on their own target data. The paper's recommended defaults (p = 0.9, f = 32) are validated on math reasoning, language modeling, and RULER retrieval with Qwen-derived models, but may not be optimal — or even near-optimal — for different model families, different task types (code generation, translation, dialogue), or different sequence length regimes. The dual-knob design (p and f) is a strength in principle (tunable to different deployment priorities) but a practical burden because there is no automated procedure for setting these knobs. A production deployment would need offline benchmarking across (p, f) combinations on representative workloads, which requires access to evaluation data and significant compute time — costs not reflected in the paper's efficiency measurements.

**What evidence exists:** The paper's own results demonstrate task-dependent sensitivity. On RULER retrieval (Table 2), p = 0.9 outperforms p = 0.8 (0.559 vs. 0.552 average), while in language modeling (Figure 5), p = 0.2 (20% attended) provides slightly higher accuracy than p = 0.1 — the optimal sparsity is task-dependent. On math reasoning (Figure 9), the optimal f varies by benchmark: f = 32 and f = 64 are nearly identical on Minerva and Gaokao2023En, but f = 32 is noticeably better than f = 64 on AIME24 at p = 0.95. These variations confirm that no single (p, f) pair is universally optimal, but the paper provides no automated or principled method for per-task tuning.

**Mitigation status:** The paper does not address this gap. It does not propose a method for online or automated hyperparameter selection — e.g., monitoring the PRM score distribution or attention entropy during decoding to dynamically adjust p or f. The default values (p = 0.9, f = 32) are offered as recommendations based on the paper's evaluation suite, but their transferability to new settings is assumed, not demonstrated. This is an actionable area for future work: developing automated difficulty- or domain-aware scheduling policies that select (p, f) per-request without requiring offline benchmarking.

### All Results Are on a Single GPU Architecture with a Single Model Family

All efficiency measurements use NVIDIA A100-80G GPUs (Section 3.5). All quality and efficiency experiments use Qwen-derived model architectures: Qwen2.5 7B for language modeling, retrieval, and efficiency; DeepSeek-R1-Qwen-Distill 1.5B and 7B for math reasoning (Section 3.1). The paper explicitly selects these as "a widely-used standard Transformer" (Qwen2.5) and a representative reasoning model (DeepSeek-R1-Distill), but does not test on other major model families (Llama, Gemma, Mistral, Phi) or other hardware (H100, consumer GPUs).

The consequence is twofold. First, the speedup numbers (Figures 7, 8) are hardware-specific. The A100's HBM2e bandwidth (~2 TB/s) and SM count (108) determine the absolute latencies and the crossover point where attention becomes memory-bandwidth-bound. On an H100 with HBM3 (~3.35 TB/s), the dense attention baseline may be faster relative to compute, potentially changing the speedup factor. On a consumer GPU with lower memory bandwidth (e.g., RTX 4090 at ~1 TB/s), the attention bottleneck may be even more severe, and ReSA's relative benefit could be larger — or the block selection and rectification overhead could become proportionally more expensive. Neither scenario is evaluated.

Second, the quality results may not transfer across model families. Different models have different attention patterns — some may concentrate attention more sharply on a small number of relevant tokens (making sparse attention more accurate), others may distribute attention more evenly (making block selection harder). The Qwen2.5 and DeepSeek-R1-Distill models both use GQA with 4 KV heads and 28 query heads (7B models), which provides a specific level of head sharing that ReSA's group-pooling mechanism exploits. Models with different GQA configurations (e.g., Llama 3 8B with 8 KV heads) or standard MHA would have different block selection dynamics — the pooled query from more query heads per KV head might produce better or worse block relevance estimates. The paper's claim that the method works on "standard pretrained Transformers" (Section 3.1) is qualitatively supported for Qwen architectures but quantitatively unvalidated for others.

**What evidence exists:** All experiments in Sections 3.2–3.5 use Qwen-based models. The paper provides specifications for the 7B model (28 attention heads, 4 KV heads, 3584 hidden size, 28 layers) but does not compare against models with different attention configurations. All efficiency measurements are on A100-80G.

**Mitigation status:** The paper does not discuss hardware or model family generalization. This is a common limitation in systems papers (it is infeasible to test every model on every GPU), but the complete absence of even a second GPU architecture or a second model family means the generalization claims are extrapolations. The method itself is architecture-agnostic (it only requires standard GQA and the ability to perform block-sparse attention) and should transfer to other models and GPUs in principle, but the quantitative speedup and quality numbers reported are specific to the tested configuration. Practitioners should expect to re-benchmark on their target hardware and model.

### The Language Modeling Evaluation Uses Simulated, Not Autoregressive, Decoding

The paper's language modeling experiments (Section 3.3) evaluate ReSA using a simulation framework rather than true autoregressive generation. The method: take a ground-truth sequence of length L, split it into a prefix of length L − x and a suffix of length x, encode the prefix with dense attention and the suffix with sparse attention, and measure top-3 accuracy on the final 32 tokens. The parameter x acts as a proxy for the rectification frequency: larger x means more tokens are encoded with sparse attention before a "rectification boundary" (which in this simulation is a hard boundary at x tokens, not periodic rectification every f steps). The paper uses this simulation to vary x and measure its effect on KV cache quality.

The consequence is that this simulation does not capture the full dynamics of ReSA's actual autoregressive operation. In true autoregressive generation with ReSA:

1. **Tokens are model-generated, not gold.** During sparse decoding, the model produces tokens based on its own (potentially drift-affected) KV cache. These tokens may be suboptimal due to accumulated error, and subsequent tokens are conditioned on these suboptimal choices — a compounding effect beyond just KV cache drift. The simulation uses ground-truth book tokens, so the token identities are always correct regardless of how much the KV cache has drifted. This means the simulation measures only the *direct effect* of KV cache quality on prediction accuracy (does a degraded cache make it harder to predict the next gold token?), not the *compounding effect* of prediction errors on generation quality (does a degraded cache cause the model to generate wrong tokens, which then further degrade the cache?).

2. **The rectification pattern is a single boundary, not periodic intervals.** In ReSA, rectification happens every f steps throughout generation, creating a sawtooth pattern of error accumulation: error builds up over f steps, gets reset by rectification, builds up again, etc. The simulation has one sparse-attention region (the suffix) whose length is x, with no periodic resetting inside that region. For x = 32, the simulation approximates one rectification cycle of ReSA, but for x = 64 or 128, it approximates sparse decoding with long accumulation windows rather than ReSA's periodic correction.

3. **There is no feedback from model outputs to KV cache state.** In the simulation, the KV cache entries for the suffix tokens are produced by sparse-attention encoding of ground-truth tokens. In real ReSA, the KV cache entries for generated tokens are produced by sparse attention over prior KV cache entries, which themselves may be approximate — this recursive dependence is absent in the simulation.

**What evidence exists:** The paper is explicit about the simulation methodology: "we divide each input sequence into two parts... The prefix is processed using dense attention, while the suffix uses sparse attention." It does not claim these are autoregressive generation results. The math reasoning experiments (Section 3.2) are genuine autoregressive generation, so the core quality claims have authentic-generation support. But the detailed characterization of KV cache quality as a function of f (Figure 4) and the sparsity sweep (Figure 5) rely entirely on the simulation.

**Mitigation status:** The paper does not acknowledge the gap between simulated and autoregressive evaluation. Standard practice in efficient-attention papers often includes perplexity evaluation under true autoregressive generation (e.g., on PG19 or BookCorpus), which would capture the compounding error dynamics. The lack of such evaluation means the language modeling results should be interpreted as an **upper bound** on ReSA's performance under real generation conditions — the simulation likely overestimates quality because it uses gold tokens and has no error feedback loop. A practitioner deploying ReSA for long-form text generation should expect some additional quality degradation beyond what Figures 4 and 5 suggest.

### Hard Problems Where the Model's Attention Is Widely Distributed Remain Unsolved

ReSA's block-sparse attention relies on the assumption that for each query, the most relevant context can be captured by a small number of blocks — specifically, the top-n blocks according to the min-max scoring function (Equation 4) plus a local window. The paper's results on reasoning and retrieval show this assumption holds well: 10% attention (p = 0.9) achieves near-dense quality. However, this implicitly assumes that the model's true attention distribution is **sufficiently concentrated** — that the information needed for accurate prediction lives in a small fraction of the context and can be identified by the block scoring mechanism.

The consequence is that ReSA's quality guarantees break down when the model's true attention is widely distributed — for instance, tasks requiring aggregation over the entire context (computing document-level statistics, tracking entities across very long narratives, answering questions that require synthesizing information from many scattered passages). The paper's RULER results provide suggestive evidence: on the Frequent Word Extraction (FWE) subtask (Table 2), ReSA at p = 0.9 achieves 0.760 versus dense's 0.833 — a substantial 0.073 gap, the largest of any subtask. FWE requires counting word frequencies across the entire context, which inherently demands broad attention distribution. The block-sparse mechanism, by attending to only 10% of blocks, misses relevant occurrences and degrades accuracy.

More broadly, this limitation means ReSA's accuracy promises are conditional on the task's **attention concentration properties**. The paper characterizes performance on reasoning (where attention is often focused on the most recent reasoning steps and key problem statements), language modeling (where local context dominates), and retrieval (where relevant information is localized by design in RULER's needle-in-a-haystack construction). Tasks or domains where attention is inherently diffuse — multi-document summarization, multi-hop question answering across many documents, long-form text coherence evaluation — are untested and may show larger quality gaps.

**What evidence exists:** The RULER FWE result (Table 2) is the clearest signal: a task requiring broadly-distributed attention shows the largest gap from dense. The paper does not explicitly analyze attention distribution or characterize which tasks are vulnerable to this failure mode. The math reasoning results (Table 1) show variability across benchmarks (AMC23 has a 3-point gap from dense even with ReSA, while OlympiadBench shows no gap), which may partially reflect differences in attention concentration, but this is not investigated.

**Mitigation status:** The paper does not discuss this limitation or propose mechanisms to detect or handle diffuse-attention tasks. The local window (n_local = 1 block) and minimum block count (n_min = 16) provide some protection against missing critical context, but they are fixed heuristics, not adaptive to attention distribution. A potential mitigation — dynamically increasing the attention fraction p when the model's attention entropy is high — is not explored. The paper's suggestion that learned block descriptors (SeerAttention) could improve retrieval accuracy is relevant but does not address the fundamental issue: if the task genuinely requires attending to most of the context, no block selection mechanism can achieve high sparsity without quality loss.

### The Speedup Numbers Assume Batch Size 8 and Shared KV Cache — Practical Throughput Under Production Loads Is Uncharacterized

The paper's efficiency measurements (Section 3.5, Figures 7 and 8) are conducted at a fixed batch size of 8 with a shared KV cache across all layers — a configuration the paper adopts "to prevent memory overflow issues caused by excessively large KV caches during long-sequence evaluation" (Section 3.5). This is a practical necessity for the A100's 80GB memory at 256K context length, but it means the measured speedups correspond to a specific (and potentially non-standard) operating point.

The consequence is that the speedup factors may not generalize to deployment scenarios with different batch sizes or memory configurations. Several dynamics are at play:

**Batch size effects.** At batch size 1 (interactive inference), latency is dominated by memory bandwidth to stream the KV cache. ReSA's attention speedup would be close to the theoretical memory access reduction (~5× for attention specifically), but the end-to-end speedup may be higher or lower than the batch-8 measurements depending on how well the GPU's memory bandwidth is saturated. At very large batch sizes (e.g., 64 or 128 for throughput-optimized serving), the GPU's SMs may become compute-bound on the non-attention components (feedforward matmuls), making the attention speedup less impactful on end-to-end throughput. The paper does not sweep batch size, so the scaling behavior is unknown.

**Shared KV cache strategy.** The paper shares KV caches across layers to save memory, meaning all layers use the same key-value representations. This is not standard in Transformer inference (each layer typically has its own KV cache) and changes the memory access pattern: with per-layer KV caches, each layer's attention reads from its own dedicated cache, potentially increasing total memory traffic but also enabling better cache locality. How the shared-cache strategy affects ReSA's relative speedup versus dense attention is unclear — it could artificially compress the attention bottleneck (making ReSA's benefit seem smaller) or amplify it (making ReSA's benefit seem larger), depending on the GPU's cache hierarchy behavior.

**No continuous batching or multi-request dynamics.** The paper's efficiency measurements use a single batch of 8 sequences. Production serving systems interleave requests with different sequence lengths, priorities, and rectification schedules. The paper claims (Section 2.2) that rectification is "naturally compatible with modern LLM serving optimizations such as continuous batching and chunked prefill," but provides no empirical validation. In practice, rectification steps from different requests would need to be batched together for efficiency, which requires the scheduler to align rectification intervals across requests or to dynamically group rectification work as it arrives. Neither the overhead of this scheduling nor the achievable rectification batch utilization is measured.

**What evidence exists:** Figures 7 and 8 explicitly state "batch size is fixed at 8 by default throughout all experiments." The shared KV cache strategy is mentioned in the same paragraph. No ablation of batch size or KV cache configuration is provided.

**Mitigation status:** The paper does not claim the speedup numbers are batch-size-independent, but it also does not discuss how batch size or memory configuration affect the results. This is a deployment-relevant gap: a practitioner planning to serve ReSA at batch size 32 on H100s with per-layer KV caches cannot directly use the paper's 2.42× speedup figure for capacity planning. The method's architectural compatibility with continuous batching is argued qualitatively (Section 2.2) but not demonstrated empirically. Characterizing throughput under production serving conditions — dynamic batching, mixed sequence lengths, multiple concurrent requests, per-layer KV caches — would substantially strengthen the practical deployment case.
