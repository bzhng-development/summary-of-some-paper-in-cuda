# MULTI-HEAD LOW-RANK ATTENTION

**ArXiv:** [2603.02188](https://arxiv.org/abs/2603.02188)

## Pitch

Multi-Head Latent Attention (MLA) offers efficient KV cache compression but suffers from a critical tensor parallelism (TP) bottleneck, as its single latent head cannot be sharded across GPUs. This paper proposes Multi-Head Low-Rank Attention (MLRA), which decomposes the latent head into multiple independent branches to enable native 4-way TP support during decoding. MLRA achieves state-of-the-art perplexity while delivering a 2.8× speedup over MLA, effectively resolving the tension between memory efficiency and distributed inference scalability.

---

## 1. Executive Summary

This paper proposes **Multi-Head Low-Rank Attention (MLRA)**, a novel attention mechanism that enables partitionable latent states for efficient 4-way tensor parallelism (TP) during distributed decoding — addressing MLA's fundamental limitation that its single latent head cannot be sharded across devices, forcing redundant KV cache loading. Experiments at the 2.9B-parameter scale on FineWeb-Edu-100B and seven common-sense reasoning benchmarks demonstrate that MLRA-4 achieves state-of-the-art perplexity (13.672 vs. 13.727 for MLA) and zero-shot accuracy (58.84% vs. 58.75% for MLA), while delivering a 2.8× decoding speedup over MLA and 1.05–1.26× over GQA for long-context sequences up to 2M tokens, establishing that multi-branch low-rank decomposition can simultaneously improve model quality and inference efficiency — but only when the branch outputs are summed at the attention level rather than the KV-computation level, creating the shardable latent structure that MLA lacks.

## 2. Context and Motivation

### The Core Problem: KV Cache Loading Is the Bottleneck in Long-Context Decoding, and MLA Doesn't Help Distributed Systems

The paper addresses a specific, concrete bottleneck in large language model inference: **during the decoding (token-generation) phase, the Key–Value (KV) cache must be repeatedly transferred from off-chip High-Bandwidth Memory (HBM) to on-chip Static Random-Access Memory (SRAM) for every single token generated**. This data movement, not the actual computation, dominates latency when context lengths are long.

To understand why this matters, you need to understand the two-phase structure of transformer inference. During *prefilling*, the model processes the entire input prompt in parallel — the KV cache is written once. During *decoding*, the model generates tokens one at a time, and for each new token, it must compute attention against *all* previous tokens' keys and values. That means the entire KV cache — which grows linearly with sequence length — must be read from memory at every step. The arithmetic intensity (FLOPs per byte of memory access) is so low that the GPU's compute units sit idle waiting for data. This is the "memory wall" problem that the paper references through Gholami et al. (2024) and Ivanov et al. (2021).

The scale of this problem in modern deployments is enormous. The paper cites retrieval-augmented generation (RAG) and long chain-of-thought (CoT) reasoning as two driving forces behind increasingly long contexts (Section 1). When a model must maintain a 128K or 1M token context during generation, the KV cache for a model like Qwen3-32B (64 query heads, 8 KV heads, $d_h = 128$) grows to hundreds of megabytes. Reading that from HBM for every token generated is the dominant cost.

### Why MLA Alone Doesn't Solve This: The Tensor Parallelism Blind Spot

Multi-Head Latent Attention (MLA), introduced in DeepSeek-V2 (DeepSeek et al., 2024c), was a significant advance. Its core insight is elegant: instead of storing full-dimensional keys and values for every head, **MLA compresses the KV cache into a single low-dimensional latent vector** ($d_c = 4d_h$ dimensions, yielding 4.5$d_h$ total when including the RoPE key). During decoding, the weight matrices that would normally up-project this latent vector into full keys and values are instead *absorbed into the query* — using the associativity of matrix multiplication to avoid ever materializing the large KV tensors. This reduces the KV cache loading per token from $2hd_h$ (for standard MHA) to just $d_c + d_h^R = 4.5d_h$, independent of the number of heads. The paper's Section 2.1 walks through this absorption process in detail (Steps 1–3), but the key outcome is that decoding becomes an MQA-style operation where the shared latent representations serve as the keys and values for all heads simultaneously.

This is a genuine efficiency win for single-GPU inference. However, the paper identifies a **critical failure mode for distributed inference**: MLA's single latent head **cannot be partitioned across devices under tensor parallelism (TP)**.

Here's why this matters in practice. In tensor parallelism, you distribute the model's weight matrices and computation across multiple GPUs. For attention, a natural partitioning strategy is to split along the head dimension — GPU 0 handles heads 0–15, GPU 1 handles heads 16–31, etc. This reduces each device's memory footprint and compute load proportionally to the number of TP devices. But MLA's architecture defeats this: because all heads share a single latent representation $C^{KV}$, every device must possess the complete latent state to compute its assigned heads' keys and values. The paper quantifies this in Table 1: under MLA, the per-device KV cache loading remains a constant $4.5d_h$ **regardless of whether you use 1, 2, 4, or 8 GPUs**. The up-projection matrices can be sharded by head across devices, but the cached data must be redundantly loaded by every device, consuming precious HBM bandwidth with no benefit from parallelism.

This is not a minor implementation detail — it fundamentally limits the throughput scaling of MLA-based models in production serving systems where multiple GPUs are standard. The paper explicitly calls this out in the introduction:

> "MLA is unfriendly to tensor parallelism (TP) because its single latent head cannot be sharded."

### Where Prior Attention Mechanisms Fall Short

The paper situates MLRA within a landscape of attention variants, each making different tradeoffs between expressiveness, KV cache size, and TP-friendliness. Understanding these tradeoffs is essential to appreciating why MLRA's design choices matter.

**Standard Attention (MHA, MQA, GQA).** Multi-Head Attention (MHA) stores full-dimensional keys and values for all $h$ heads, requiring $2hd_h$ of KV cache loading per token. This gives full expressiveness — every head has independent key/value projections — but the memory cost is prohibitive for long contexts. Multi-Query Attention (MQA) reduces this to $2d_h$ by sharing a single KV head across all query heads, at the cost of reduced model quality. Grouped-Query Attention (GQA) interpolates: $g$ KV heads shared across $h$ query heads, requiring $2gd_h$ loading. GQA supports TP by sharding KV heads — with 4 KV heads on 4 GPUs, each GPU loads only 1 KV head — but the loading scales as $2gd_h/\phi$ where $\phi$ is the number of TP devices. For Qwen3-32B with $g=8$, reaching the $1.5d_h$ loading that MLRA achieves at 4-way TP would require 8-way TP (Table 1), which is communication-expensive and often impractical.

**GLA-2 (Grouped Latent Attention).** GLA-2 (Zadouri et al., 2025) was the closest predecessor to MLRA and represents the first attempt to make MLA TP-friendly. It partitions the single latent head into two smaller latent heads, each serving half the attention heads. This enables 2-way TP — each of two GPUs handles one latent group — reducing per-device loading from $4.5d_h$ to $2.5d_h$. However, GLA-2 hits a sharding ceiling at 2 GPUs: beyond that, the KV cache loading plateaus at $2.5d_h$ (Table 1) because each latent group already serves the minimum set of heads it can without further partitioning. The paper's Section 2.2 formalizes GLA-2's group-mapping function and block decomposition, which MLRA directly generalizes.

**Other variants (TPA, GTA, MFA).** The paper also benchmarks against TPA (Zhang et al., 2025), which represents keys and values as low-rank mixtures of shared component vectors — supporting partial TP but with complex coefficient sharding that leaves the shared components redundantly loaded (showing $4d_h + 2d_h/\phi$ loading in Table 1). GTA (Zadouri et al., 2025) takes a different approach by tying NoPE keys to values and using grouped value heads, reaching $1.5d_h$ at 8-way TP. MFA (Hu et al., 2024) uses a single KV head with higher-dimensional projections and low-rank query factorization, but like MLA it cannot benefit from TP at all (constant $4d_h$ loading). The paper's Table 1 comprehensively compares all these variants, showing that **no existing mechanism achieves TP-scalable KV cache loading below $2.5d_h$ with fewer than 8 GPUs**.

### The Two Approaches to Partitioning Latent Attention: KV-Level vs. Attention-Level Summation

This is the most conceptually important part of the motivation, and the paper builds up to it carefully. To understand what MLRA does differently, you need to see how MLA's computation can be decomposed — and why the obvious decomposition doesn't work for TP.

**The block decomposition of MLA (Section 2.1, Eq. 2).** The paper shows that MLA's up-projection matrices $W^{UK}$ and $W^{UV}$ (each $\in \mathbb{R}^{d_c \times hd_h}$) can be partitioned into four row-blocks, each $\in \mathbb{R}^{d_h \times hd_h}$. This partitions the KV latent state $C^{KV}$ into four channel blocks $C^{KV}_{:,(b)}$ for $b \in \{0,1,2,3\}$, each $\in \mathbb{R}^{n \times d_h}$. The NoPE key for head $i$ can then be expressed as a sum of four block-wise products:

$$K^{\text{NoPE}}_{:,(i),:} = \sum_{b=0}^{3} C^{KV}_{:,(b)} W^{UK}_{(b),(i)}$$

and similarly for the value. This is exact — it's just a rearrangement of the same computation, leveraging the structure of the up-projection matrices.

**GLA-2's partial solution.** GLA-2 groups heads into two sets and each group's key is expressed as a sum of two block products (Section 2.2, Eq. 4). This reduces the summation depth from 4 to 2 per group, and crucially, each group's computation depends only on two of the four latent blocks. This is what makes GLA-2 amenable to 2-way TP: split the four blocks into two groups of two, assign each group to a different device. The summation is still done at the KV-computation level — keys are fully materialized before attention.

**Why KV-level summation blocks further TP scaling.** To go beyond 2-way TP, you would need GLA-4: four latent heads, each using only one block. But here's the problem the paper implicitly identifies: if you keep doing the summation at the KV level, each latent head constructs only a *partial* key and value (a single block's contribution), and the attention computation that follows is only between partial queries and partial keys/values. The sum-of-partial-attentions is not equivalent to the attention-of-the-sum unless you make a specific architectural choice — which is exactly MLRA's insight.

**MLRA's key move: attention-level summation.** The paper's central architectural innovation (Section 3.1, Eq. 5) is to **move the summation from the KV computation stage to the attention output stage**:

$$\begin{aligned}
O_{:,i,:} &= \sum_{b=0}^{3} \text{Softmax}\Big(\tau Q^{\text{NoPE}}_{:,i,:} \big(C^{KV}_{:,(b)} W^{UK}_{(b),(i)}\big)^\top \\ 
&\quad + \tau Q^{\text{RoPE}}_{:,i,:} (K^{\text{RoPE}})^\top\Big) \big(C^{KV}_{:,(b)} W^{UV}_{(b),(i)}\big)
\end{aligned}$$

Each of the four blocks now forms an **independent attention branch** that computes its own softmax and output, and the results are summed. This is not mathematically equivalent to MLA's Eq. (2) — the softmax of sums is not the sum of softmaxes — but the paper's empirical results show this approximation works well and confers the crucial property that **each branch is an independent computation that only needs its own latent block**. Table 1 shows the consequence: MLRA achieves $1.5d_h$ per-device KV cache loading with only 4-way TP, matching GTA at 8-way TP and outperforming all other mechanisms at practical parallelism degrees.

### Variance Instability as a Second-Order Motivation

The paper identifies a subtle numerical issue that affects MLA and its variants, which MLRA must also address. Section 3.3 formalizes this as Assumption 1 and derives the variance of different attention components. The key finding: **the RoPE key $K^{\text{RoPE}}$ has variance $\approx d\sigma_w^2$, while the NoPE key $K^{\text{NoPE}}$ has variance $\approx d_c\sigma_w^2$**. Since MLA typically uses $d_c = 4d_h$ which is much smaller than the model dimension $d$ (e.g., $d=3072$ vs. $d_c=512$ in the paper's main experiments), there is a significant variance mismatch. The RoPE key dominates the softmax computation, effectively drowning out the NoPE components that carry most of the learned information.

The paper fixes this by rescaling: applying $\alpha_q = \sqrt{d/d'_c}$ to query latent states and $\alpha_{kv} = \sqrt{d/d_c}$ to KV latent states (Eq. 9). For MLRA's multi-branch architecture, the summation of branch outputs also requires rescaling (Eq. 10): dividing by $\sqrt{2}$ for MLRA-2 and by $2$ for MLRA-4, reflecting the assumption that branch outputs are mutually uncorrelated.

This variance analysis connects to the work of LongCat et al. (2025), who first observed the mismatch. The paper's ablation (Figure 2, Table 39) shows that scaling improves MLA and GLA-2 substantially but MLRA-2 only marginally — suggesting that the multi-branch architecture's explicit rescaling of outputs already mitigates some of the variance issue.

### How the Paper Positions Itself in the Literature

The paper frames MLRA as a **unifying advance** that simultaneously addresses three desiderata that prior attention mechanisms only partially satisfied:

1. **Low KV cache loading per token** (matching MLA's $4.5d_h$ for single-device, but scalable down to $1.5d_h$ with TP).
2. **Tensor-parallelism support** (the primary motivation, with MLRA achieving at 4 TP what GTA needs 8 TP for, and what MLA/GLA-2 cannot achieve at all beyond 2 TP).
3. **High arithmetic intensity during decoding** (Table 2 shows MLRA-4 achieves $2h$, double that of MLA/GLA-2/MHA, meaning it shifts the workload further from memory-bound toward compute-bound).

The paper is careful not to claim superiority along all dimensions simultaneously — the gated attention results in Section 4.4 provide a nuanced picture where gated MLRA-4 leads on average perplexity but gated MLA matches or slightly edges out gated MLRA-2. Instead, the contribution is positioned as filling a specific gap: **making low-rank attention mechanisms compatible with efficient multi-GPU distributed inference**, without sacrificing model quality.

The related work section (Appendix I) situates MLRA within three broader research threads: (1) KV cache compression techniques that retrofit existing models (quantization, token eviction), which are orthogonal and potentially complementary; (2) low-rank approximation methods for parameter reduction, where MLA and MLRA share the philosophy of compressing to low-dimensional latents and up-projecting; and (3) efficient attention kernels (FlashAttention family, FlashMLA), which MLRA builds upon by using FlashAttention-3 as the computational backend for its branch-wise attention operations.

### Summary of the Gap

The paper addresses a clearly specified problem: **existing low-rank attention mechanisms (MLA, GLA-2) achieve impressive KV cache compression for single-GPU inference but fail to scale their memory loading benefits to multi-GPU tensor-parallel deployments**. This matters because production LLM serving at scale invariably uses multiple GPUs, making single-device efficiency an incomplete metric. The paper's solution — decomposing the latent head into independently computable attention branches whose outputs are summed — is motivated by showing that the component structure exists in MLA's block decomposition (Section 2.1) and GLA-2's group-wise decomposition (Section 2.2), and that the failure point is where the summation happens (KV-level vs. attention-level). This is a clean, well-motivated architectural intervention with clear practical consequences, validated in Table 1 and the decoding efficiency experiments of Section 4.5.

## 3. Technical Approach

### 3.1 Reader Orientation

The paper proposes a new attention mechanism called Multi-Head Low-Rank Attention (MLRA) that can be dropped into any transformer architecture as a replacement for standard attention. It solves the problem that Multi-Head Latent Attention (MLA) — currently the most efficient attention mechanism for long-context decoding on a single GPU — cannot distribute its compressed KV cache across multiple GPUs during tensor-parallel inference, forcing every device to redundantly load the complete cache and eliminating the memory-saving benefits of parallelism. MLRA's solution is conceptually simple: **take MLA's single compressed latent representation, split it into four independent latent heads, run attention separately on each, and sum the results** — a decomposition that makes each latent head independently shardable across up to four GPUs while preserving the low KV-cache footprint and model quality of MLA.

### 3.2 Big-Picture Architecture

MLRA operates within a standard decoder-only transformer block (the paper uses the Llama-3 architecture, described in Appendix D). The attention computation has five major stages:

1. **Latent State Compression (Down-Projection):** The input hidden states `$H \in \mathbb{R}^{n \times d}$` for `$n$` tokens are projected down to a low-dimensional latent space via a learned matrix `$W^{DKV} \in \mathbb{R}^{d \times d_c}$`, producing the compressed KV latent state `$C^{KV} \in \mathbb{R}^{n \times d_c}$`. This is the same compression step as MLA — it's what reduces the KV cache size from `$2hd_h$` to `$d_c + d_h^R$` per token.

2. **Latent Channel Partitioning:** The single `$C^{KV}$` latent matrix is conceptually partitioned into four channel blocks `$C^{KV}_{:,(b)}$` for `$b \in \{0,1,2,3\}$`, each of dimension `$d_c/4$`. In MLRA-4, these four blocks become four independent latent heads. In MLRA-2, they are grouped into two pairs serving head groups.

3. **Branch-wise Up-Projection and Attention:** Each latent block `$C^{KV}_{:,(b)}$` is independently up-projected through its own learned weight matrices `$W^{UK}_{(b),(i)}$` and `$W^{UV}_{(b),(i)}$` (blocks of the full up-projection matrices) to form per-head keys and values. A full softmax attention computation — including RoPE positional encoding — is performed separately for each branch, producing an attention output `$O_{(b),(i),:}$` for each branch and each head.

4. **Attention Output Summation:** The branch-wise attention outputs are summed across branches: `$O_{:,i,:} = \sum_{b=0}^{3} O_{(b),(i),:}$` for MLRA-4 (two branches for MLRA-2). This is the key architectural difference from MLA — MLA sums *before* the softmax (at the KV-computation level), MLRA sums *after* (at the attention-output level).

5. **Output Projection and Residual:** The summed attention output is projected back to the model dimension `$d$` via `$W^{O,attn}$` and added as a residual connection, followed by the standard FFN block.

The information flow during decoding is: `$H$` → RMSNorm → `$W^{DKV}$` down-projection → latent `$C^{KV}$` → partition into 4 blocks → each block independently: up-project to KV, compute attention with query → sum the 4 attention outputs → `$W^{O,attn}$` → add residual → RMSNorm → FFN → add residual → next layer.

### 3.3 Roadmap for the Deep Dive

- **First, the mathematical derivation from MLA to MLRA** — how the block decomposition of MLA's up-projection matrices (Section 2.1, Eq. 2) reveals the natural four-branch structure, and why moving the summation outside the softmax (Eq. 5) creates independently computable attention branches suitable for tensor parallelism.
- **Second, the MLRA-2 variant** — how the same principle applies to grouped latent attention, yielding a two-branch architecture that is the direct generalization of GLA-2.
- **Third, the variance analysis and rescaling strategy** — why the RoPE key variance dwarfs the NoPE key variance in MLA-like architectures (Section 3.3, Assumption 1), how rescaling the latent states and attention outputs fixes this, and what the concrete scaling factors are for MLRA-2 and MLRA-4.
- **Fourth, the quantitative analysis of KV cache loading and arithmetic intensity** — how the per-device KV cache loading scales with tensor-parallel degree across all attention mechanisms (Table 1), and why MLRA achieves higher arithmetic intensity than MLA or GLA-2 (Table 2), shifting decoding from memory-bound toward compute-bound.
- **Fifth, the gating mechanism** — an orthogonal architectural addition (Appendix E) that multiplies attention outputs elementwise with a learned sigmoid gate, which is evaluated in Section 4.4 and provides complementary improvements.

### 3.4 Detailed, Sentence-Based Technical Breakdown

This is primarily an **architectural design paper** whose core idea is that decomposing a low-rank attention mechanism into independently computable branches — where summation happens at the attention-output level rather than at the KV-computation level — produces a model that is simultaneously parameter-efficient (low KV cache), shardable under tensor parallelism, and competitive or superior in perplexity and downstream accuracy compared to the best existing attention mechanisms.

#### From MLA's Block Decomposition to MLRA's Attention-Level Summation

The starting point is the observation — established in Section 2.1 — that MLA's up-projection matrices `$W^{UK}$` and `$W^{UV}$`, which expand the compressed latent state `$C^{KV}$` into full-dimensional keys and values, can be partitioned into row-blocks. This is not an approximation but an exact algebraic identity. For any head `$i$`, the up-projection matrix `$W^{UK}_{:,(i)} \in \mathbb{R}^{d_c \times d_h}$` (the slice that produces head `$i$`'s NoPE key) can be vertically partitioned into four blocks, each in `$\mathbb{R}^{d_h \times d_h}$`:

$$W^{UK}_{:,(i)} = \begin{bmatrix} W^{UK}_{(0),(i)} \\ W^{UK}_{(1),(i)} \\ W^{UK}_{(2),(i)} \\ W^{UK}_{(3),(i)} \end{bmatrix}$$

where `$W^{UK}_{(b),(i)} = W^{UK}[bd_h : (b+1)d_h, id_h : (i+1)d_h]$` is the `$b$`-th row-block of the `$i$`-th head's up-projection slice, `$b \in \{0,1,2,3\}$` indexes the four equal-sized partitions along the input dimension, and `$i \in \{0,\ldots,h-1\}$` indexes the attention head.

**What this partitioning does:** it divides the `$d_c$`-dimensional latent space (which equals `$4d_h$` in the paper's configuration) into four subspaces of dimension `$d_h$` each. Correspondingly, the latent state matrix `$C^{KV} \in \mathbb{R}^{n \times d_c}$` is partitioned horizontally into channel blocks `$C^{KV}_{:,(b)} = C^{KV}[:, bd_h : (b+1)d_h] \in \mathbb{R}^{n \times d_h}$` for each block `$b$`.

**Why four blocks specifically:** because `$d_c = 4d_h$` is the standard MLA configuration (following DeepSeek-V3; DeepSeek et al., 2024b), and partitioning into `$d_h$`-sized blocks means each block has the same dimension as a single attention head. This is the natural granularity for subsequent per-head computation. The decomposition is exact for any block size, but `$d_h \times d_h$` blocks align with the head dimension and produce the clean 4-branch structure that enables 4-way TP.

Substituting this block decomposition into the NoPE key computation (Eq. 2 of Section 2.1) gives the key identity that MLRA exploits:

$$K^{\text{NoPE}}_{:,(i),:} = \sum_{b=0}^{3} C^{KV}_{:,(b)} W^{UK}_{(b),(i)}$$

**What this equation states:** the NoPE key for head `$i$` is exactly the sum of four independent matrix products, where each product involves one latent block `$C^{KV}_{:,(b)}$` (shape `$n \times d_h$`) and its corresponding weight block `$W^{UK}_{(b),(i)}$` (shape `$d_h \times d_h$`). The same decomposition holds identically for the value:

$$V_{:,(i),:} = \sum_{b=0}^{3} C^{KV}_{:,(b)} W^{UV}_{(b),(i)}$$

Now, in standard MLA, these sums are computed *before* the attention softmax. The full attention output for head `$i$` (using the identity from Eq. 2 and the standard attention formula) would be:

$$O_{:,i,:} = \text{Softmax}\left(\tau Q^{\text{NoPE}}_{:,i,:} \left(\sum_{b=0}^{3} C^{KV}_{:,(b)} W^{UK}_{(b),(i)}\right)^\top + \tau Q^{\text{RoPE}}_{:,i,:} (K^{\text{RoPE}})^\top\right) \left(\sum_{b=0}^{3} C^{KV}_{:,(b)} W^{UV}_{(b),(i)}\right)$$

where `$\tau = 1/\sqrt{d_h + d_h^R}$` is the standard softmax temperature, `$Q^{\text{NoPE}}_{:,i,:} \in \mathbb{R}^{n \times d_h}$` is the NoPE query for head `$i$`, `$Q^{\text{RoPE}}_{:,i,:} \in \mathbb{R}^{n \times d_h^R}$` is the RoPE query, and `$K^{\text{RoPE}} \in \mathbb{R}^{n \times d_h^R}$` is the shared RoPE key cached during inference.

**What this equation computes:** the standard dot-product attention mechanism, where the keys are the sum of four block contributions, and the values are the sum of the same four blocks' value projections. The softmax is applied to the full summed attention logits. The output `$O_{:,i,:} \in \mathbb{R}^{n \times d_h}$` is the attention-weighted aggregate of the summed values.

**Why this form cannot be sharded under TP:** because the softmax non-linearity couples all four blocks together. To compute the softmax, you need the complete sum — every device needs access to all four latent blocks `$C^{KV}_{:,(b)}$` to form the full key. This is the mathematical reason MLA cannot split its KV cache across devices: the non-linear operation (softmax) operates on the summed logits, making the computation of each branch *dependent* on the others.

**MLRA's innovation — moving the summation outside the softmax.** The paper proposes to approximate the full attention output by summing *independent attention computations* for each branch:

$$O_{:,i,:} = \sum_{b=0}^{3} \text{Softmax}\left(\tau Q^{\text{NoPE}}_{:,i,:} \left(C^{KV}_{:,(b)} W^{UK}_{(b),(i)}\right)^\top + \tau Q^{\text{RoPE}}_{:,i,:} (K^{\text{RoPE}})^\top\right) \left(C^{KV}_{:,(b)} W^{UV}_{(b),(i)}\right)$$

This is Eq. (5) from Section 3.1.

**What this equation computes:** for each branch `$b$`, it independently computes (a) the branch-specific key as `$C^{KV}_{:,(b)} W^{UK}_{(b),(i)}$`, (b) the attention logits against the query (with the RoPE component added identically to every branch), (c) the softmax-normalized attention weights, and (d) the branch-specific value as `$C^{KV}_{:,(b)} W^{UV}_{(b),(i)}$`. The four resulting attention outputs are then summed elementwise.

**Why this form enables tensor parallelism — the central mechanism:** each branch `$b$` requires *only* the latent block `$C^{KV}_{:,(b)}$` to compute its contribution. The branches are completely independent during computation — there is no cross-branch dependence before the final summation. Therefore, you can assign branch 0 to GPU 0, branch 1 to GPU 1, branch 2 to GPU 2, and branch 3 to GPU 3. Each GPU only needs to load and cache its own latent block `$C^{KV}_{:,(b)}$` (size `$d_h$` per token) plus the shared RoPE key `$K^{\text{RoPE}}$` (size `$d_h^R = d_h/2$` per token), for a total of `$1.5d_h$` per device — versus `$4.5d_h$` per device for MLA regardless of TP degree.

**Why this is an approximation, not an identity — and why that's acceptable:** the softmax of a sum is not equal to the sum of softmaxes. The standard identity (using MLA's KV-level summation) computes a single softmax over the complete logit matrix, producing normalized attention weights that reflect competition among all tokens using the full key representation. MLRA computes four separate softmaxes, each normalized independently over only the branch-specific logits. The summed output does not equal the original output.

However, the paper's position (validated empirically in Section 4.3) is that this is a **beneficial inductive bias**. Training the model with attention-level summation forces each branch to learn to contribute meaningfully *independently* — it cannot rely on cross-branch interactions within the softmax to produce good representations. This is analogous to multi-head attention itself: each head computes its own softmax independently, and the outputs are concatenated (which is a form of summation after projection). The paper shows this yields *better*, not worse, perplexity and downstream accuracy (Table 3: MLRA-4 at 13.672 vs. MLA at 13.727; Table 4: MLRA-4 at 58.84% vs. MLA at 58.75%).

#### MLRA-2: The Two-Branch Variant

Section 3.2 applies the same attention-level summation principle to a grouped architecture, producing MLRA-2. This variant is the direct generalization of GLA-2 (Section 2.2), with the crucial difference that the summation again moves from the KV-computation level to the attention-output level.

GLA-2 partitions the `$h$` attention heads into two groups, each served by a latent head composed of two channel blocks. The head-to-group mapping is defined by the function `$\gamma(i)$` (Eq. 3):

$$\gamma(i) = \begin{cases} 0, & i < h/2 \\ 1, & i \geq h/2 \end{cases}$$

where `$\gamma(i) \in \{0,1\}$` maps head index `$i$` to its latent group, and `$\bar{i} = i - \gamma(i) \cdot h/2 \in \{0,\ldots,h/2-1\}$` re-indexes `$i$` within its group.

In GLA-2 (Eq. 4), the NoPE key for head `$i$` is the sum of two block contributions from its assigned group:

$$K^{\text{NoPE}}_{:,(i),:} = C^{KV}_{:,(2\gamma(i))} W^{(\gamma(i)),UK}_{(0),(i)} + C^{KV}_{:,(2\gamma(i)+1)} W^{(\gamma(i)),UK}_{(1),(i)}$$

where `$W^{(\gamma(i)),UK}_{(b),(i)} \in \mathbb{R}^{d_h \times d_h}$` are the `$b$`-th row-blocks of the up-projection slice for group `$\gamma(i)$` and head `$\bar{i}$`.

**MLRA-2's modification:** instead of summing the two block contributions before the softmax (as GLA-2 does), MLRA-2 computes two independent attention operations and sums their outputs. Eq. (6) states:

$$O_{:,i,:} = \text{Softmax}\left(\tau Q^{\text{NoPE}}_{:,i,:} \left(C^{KV}_{:,(2\gamma(i))} W^{(\gamma(i)),UK}_{(0),(i)}\right)^\top + \tau Q^{\text{RoPE}}_{:,i,:} (K^{\text{RoPE}})^\top\right) \left(C^{KV}_{:,(2\gamma(i))} W^{(\gamma(i)),UV}_{(0),(i)}\right) \\ + \text{Softmax}\left(\tau Q^{\text{NoPE}}_{:,i,:} \left(C^{KV}_{:,(2\gamma(i)+1)} W^{(\gamma(i)),UK}_{(1),(i)}\right)^\top + \tau Q^{\text{RoPE}}_{:,i,:} (K^{\text{RoPE}})^\top\right) \left(C^{KV}_{:,(2\gamma(i)+1)} W^{(\gamma(i)),UV}_{(1),(i)}\right)$$

**What this computes:** for each head `$i$`, two independent attention computations are performed — one using latent block `$C^{KV}_{:,(2\gamma(i))}$` and weight block `$W^{(\gamma(i)),UK}_{(0),(i)}$`, the other using latent block `$C^{KV}_{:,(2\gamma(i)+1)}$` and weight block `$W^{(\gamma(i)),UK}_{(1),(i)}$`. Both use the same query and the shared RoPE key. The two attention outputs are summed to produce the final head output.

**Structural difference from MLRA-4:** MLRA-2 uses two branches per head, each serving only `$h/2$` heads (those in the assigned group). The block-products are organized by group: the first two latent blocks serve group 0 (heads 0 through `$h/2-1$`), the last two serve group 1 (heads `$h/2$` through `$h-1$`). MLRA-4 uses four branches per head, each serving *all* `$h$` heads — every head sees all four latent blocks, each through its own branch. The paper's Table 17 shows this increases the up-projection parameter count: MLRA-4 has `$W^{UK}, W^{UV} \in \mathbb{R}^{d_c \times hd_h}$` (same as MLA, since all heads use all blocks), while MLRA-2 has per-group up-projections `$W^{j,UK}, W^{j,UV} \in \mathbb{R}^{d_c/2 \times hd_h/2}$` for each group `$j$`, totaling the same parameter count.

**Consequences for sharding:** MLRA-2 only enables 2-way TP (each GPU gets one latent block from each group — e.g., GPU 0 gets blocks 0 and 2, GPU 1 gets blocks 1 and 3). Beyond 2 GPUs, the per-device loading plateaus at `$2.5d_h$` (Table 1), the same plateau as GLA-2. MLRA-4 achieves `$1.5d_h$` with 4-way TP because all four latent blocks are independent and can be distributed one per GPU.

#### Variance Calibration: Latent State and Attention Output Rescaling

Section 3.3 addresses a numerical stability issue that affects MLA and its derivatives. The problem arises because MLA applies RMSNorm to the latent states *before* up-projection, but the RoPE key is generated directly from the input hidden states without going through the latent bottleneck. This creates a variance mismatch.

The paper formalizes this through Assumption 1:

> "We assume that all elements of the weight matrices `$W^{DQ}, W^{DKV}, W^{UQ}, W^{QR}, W^{UK}, W^{KR}, W^{UV}$` are independent and identically distributed (i.i.d.) random variables with zero mean and variance `$\sigma_w^2$`."

Under this assumption, the paper derives the variance of each attention component:

**RoPE key variance (Eq. 7):** `$K^{\text{RoPE}} = \text{RoPE}(HW^{KR})$`. Since `$H$` is RMS-normalized, each element `$H_{t,m}$` has expected square approximately 1. The weight matrix `$W^{KR} \in \mathbb{R}^{d \times d_h^R}$` has i.i.d. entries with variance `$\sigma_w^2$`. The product yields:

$$\text{Var}(K^{\text{RoPE}}) \approx d \sigma_w^2$$

**What this says:** the variance of the RoPE key scales with the full model dimension `$d$` (3072 in the paper's main experiments). RoPE is an orthogonal transformation, so it preserves this variance — the rotation doesn't change the magnitude.

**NoPE key variance (Eq. 8):** `$K^{\text{NoPE}} = C^{KV}W^{UK}$`. The latent KV state `$C^{KV}$` is RMS-normalized, so its elements also have expected square approximately 1. The weight matrix `$W^{UK}$` has entries with variance `$\sigma_w^2$` in its initialisation, applied across `$d_c$` latent dimensions:

$$\text{Var}(K^{\text{NoPE}}) \approx d_c \sigma_w^2$$

**What this says:** the variance of the NoPE key scales with the latent dimension `$d_c$` (512 in the paper's configuration), not the model dimension `$d$`.

**The mismatch:** the ratio `$\text{Var}(K^{\text{RoPE}}) / \text{Var}(K^{\text{NoPE}}) \approx d/d_c$`. With `$d=3072$` and `$d_c=512$`, this ratio is 6. The RoPE key is approximately **six times larger in magnitude** than the NoPE key. Since the attention softmax computes `$\exp(\tau QK^\top)$`, components with larger variance dominate the logits — the RoPE positional signal drowns out the learned content-based NoPE signal.

**The same mismatch affects queries:** `$\text{Var}(Q^{\text{NoPE}}) \approx d'_c\sigma_w^2$` and `$\text{Var}(Q^{\text{RoPE}}) \approx d'_c\sigma_w^2$`, both smaller than the RoPE key variance by a factor of `$d/d'_c$` (where `$d'_c = 1024$` in MLRA's main configuration, giving a factor of 3).

**The rescaling solution (Eq. 9):** the paper applies multiplicative rescaling factors to the latent states *before* up-projection, following the approach of LongCat et al. (2025):

$$C^Q \leftarrow \sqrt{\frac{d}{d'_c}} C^Q, \quad C^{KV} \leftarrow \sqrt{\frac{4d}{d_c}} C^{KV}$$

where `$\alpha_q = \sqrt{d/d'_c}$` rescales the query latent state and `$\alpha_{kv} = \sqrt{4d/d_c}$` rescales the KV latent state.

**What these factors do:** after up-projection, `$\alpha_q$` multiplies the query components, bringing their variance to approximately `$d\sigma_w^2$` — matching the RoPE key. The factor `$\alpha_{kv}$` includes an extra `$\sqrt{4}$` because `$d_c = 4d_h$`, so `$\sqrt{4d/d_c} = \sqrt{d/d_h}$`, which brings the NoPE key variance to `$d\sigma_w^2$` as well. After rescaling, all query and key components — RoPE and NoPE alike — have approximately equal variance, preventing any single component from dominating the attention logits.

**Why `$\sqrt{4d/d_c}$` rather than `$\sqrt{d/d_c}$`:** because the NoPE key up-projection `$W^{UK}$` operates across `$d_c$` dimensions, and to match the `$d$`-dimensional RoPE key variance, you need to scale by `$\sqrt{d/d_c}$`. The factor of 4 inside the square root reflects that `$d_c = 4d_h$` (this is the standard MLA latent dimension). If `$d_c$` were defined differently, the scaling would adjust accordingly. The paper's main experiments use `$d=3072$`, `$d_c=512$`, `$d'_c=1024$`, yielding `$\alpha_q = \sqrt{3072/1024} = \sqrt{3}$` and `$\alpha_{kv} = \sqrt{4 \cdot 3072 / 512} = \sqrt{24}$`, matching the values in Tables 16 and 17.

**Attention output rescaling for MLRA (Eq. 10):** because MLRA sums multiple independent attention outputs, the variance of the sum is larger than each individual branch. Under the additional assumption that the branch outputs `$O_{(b),(i),:}$` are mutually uncorrelated (`$\text{Cov}(O_{(a),(i),:}, O_{(b),(i),:}) \approx 0$` for `$a \neq b$`), the variance of the sum is the sum of the variances:

$$O_{:,i,:} \leftarrow \frac{1}{\sqrt{2}} O_{:,i,:} \quad \text{for MLRA-2}$$

$$O_{:,i,:} \leftarrow \frac{1}{2} O_{:,i,:} \quad \text{for MLRA-4}$$

**What these factors do:** for MLRA-2 with two branches, dividing by `$\sqrt{2}$` preserves the variance (since `$\text{Var}(X + Y) = 2\text{Var}(X)$` under uncorrelated equal-variance assumptions, and dividing by `$\sqrt{2}$` returns it to the original scale). For MLRA-4 with four branches, dividing by 2 (which equals `$1/\sqrt{4}$`) achieves the same.

**Grounded caveat (Remark 1):** the paper explicitly acknowledges that these assumptions — zero-mean i.i.d. weights and uncorrelated branch outputs — "may not strictly hold in practice" during training, because weights evolve away from their initialization distribution. The effectiveness of the rescaling is therefore validated empirically in the ablation study of Section 4.2.2 (Figure 2, Table 39), which shows that scaling improves MLA and GLA-2 substantially but MLRA-2 only marginally — suggesting the multi-branch rescaling already provides some variance stabilization.

#### Quantitative Analysis: KV Cache Loading and Arithmetic Intensity

Section 3.4 provides the analytical justification for MLRA's efficiency claims through two key metrics: per-device KV cache loading under tensor parallelism (Table 1), and arithmetic intensity during decoding (Table 2).

**KV Cache Loading Analysis (Table 1).** The paper evaluates per-device KV cache loading using Qwen3-32B (GQA with `$h=64$` query heads, `$g=8$` KV heads, `$d_h=128$`) and Kimi-K2 (MLA with `$h=64$`, `$d_h=128$`, `$d_h^R=64$`) as architectural references. For each attention mechanism, the table reports the total bytes of KV cache data that must be loaded per token per GPU, as a function of the number of tensor-parallel devices (1, 2, 4, or 8 GPUs).

The key pattern is:

- **MLA:** loading is constant at `$4.5d_h$` regardless of TP degree. The single latent head (`$d_c = 4d_h$`) cannot be partitioned, so every GPU must load the complete `$4d_h$` latent state plus the `$0.5d_h$` RoPE key. The up-projection weights can be sharded by head, but the data they operate on must be fully replicated.

- **GLA-2:** loading drops from `$4.5d_h$` (1 GPU) to `$2.5d_h$` (2 GPUs) because the two latent groups (each `$2d_h$`) can be assigned to different GPUs. However, it plateaus at `$2.5d_h$` for 4 and 8 GPUs — the two groups cannot be further partitioned, so the benefit of additional parallelism saturates. The `$2.5d_h$` figure represents `$2d_h$` (one group's latent state) plus the `$0.5d_h$` RoPE key.

- **GTA:** loading scales with the number of KV heads (`$g=8$`), reaching `$1.5d_h$` at 8-way TP (one KV head per GPU plus the shared RoPE key). At 4-way TP, it's `$2.5d_h$` (two KV heads per GPU).

- **GQA:** with 8 KV heads, it reaches `$2d_h$` at 8-way TP (`$g=8$`, so 1 KV head per GPU, `$2d_h$` per head for key + value, but Table 1 shows `$2g d_h = 16 d_h$` total loading divided by 8 = `$2 d_h$`). At 4-way TP, it's `$4d_h$`.

- **MLRA-2 and MLRA-4:** both achieve `$1.5d_h$` at 4-way TP — a figure that GTA requires 8-way TP to match, and that GQA and GLA-2 cannot reach at any TP degree. MLRA-4 reaches this because its four latent blocks (each `$d_h$`) can be distributed one per GPU, plus the replicated `$0.5d_h$` RoPE key. MLRA-2 reaches this at 4-way TP because even though it only has two groups, each group's latent state (`$2d_h$`) can be further partitioned into its constituent `$d_h$` blocks; however, the up-projection matrix sharding pattern in MLRA-2 (where blocks within a group serve different head sub-groups) means that at 4-way TP, each GPU loads only one `$d_h$` block that serves its assigned subset of heads.

**What Table 1 demonstrates — the central efficiency claim:** MLRA with 4-way TP achieves the per-device KV cache loading that would require 8-way TP for GTA or GQA, and that is fundamentally unachievable for MLA (stuck at `$4.5d_h$`) or GLA-2 (stuck at `$2.5d_h$`). This directly translates to lower HBM bandwidth consumption and higher throughput, as validated in the decoding speed benchmarks (Section 4.5, Figures 5 and 6).

**Arithmetic Intensity Analysis (Table 2).** Arithmetic intensity (AI) is defined as the ratio of floating-point operations (FLOPs) to bytes of memory access (FLOPs/byte), a standard metric from the roofline model (Williams et al., 2009) for determining whether a workload is compute-bound or memory-bound. Higher AI means more computation per byte of data loaded, pushing the workload toward the compute-bound regime where GPU cores are fully utilized.

The paper derives AI formulas for each attention mechanism during decoding, assuming the context length `$n$` is the dominant factor. For MHA and MQA: AI `$\approx 1$` (since each query token performs `$O(hd_h n)$` FLOPs but loads `$O(hd_h n)$` bytes — the constants cancel, leaving a very low intensity that makes these strongly memory-bound). For MLA: AI `$\approx 2h$` (because the latent space computation increases FLOPs — absorbing the up-projection into the query adds `$O(hd_c)$` FLOPs per token — while the data loaded is only `$O(d_c + d_h^R)$` per token).

For MLRA-4, the paper derives:

$$\text{AI} \approx \frac{4n h d_c/4 + 2nh d_h^R}{2n(d_c/4 + d_h^R)} \approx 2h$$

**What this computes:** the numerator counts FLOPs: `$4nh \cdot d_c/4$` is the NoPE attention computation across four branches (each operating on `$d_c/4 = d_h$` dimensions per head), and `$2nh d_h^R$` accounts for the RoPE attention logits that are computed once and added to each branch. The denominator counts bytes loaded: `$2n(d_c/4 + d_h^R)$` for a single branch's KV cache (factor of `$d_c/4 + d_h^R$` dimensions, 2 bytes per FP16 value). The ratio simplifies to approximately `$2h$` — double that of MLA or MHA.

**Why higher AI matters:** with 64 heads and `$h=64$`, MLRA-4's AI is `$\approx 128$`, versus MLA's `$\approx 64$` and MHA's `$\approx 1$`. This means MLRA-4 performs 128 FLOPs per byte loaded, dramatically reducing the memory-boundedness of the decoding step. The practical consequence is that long-context decoding can better utilize the GPU's compute units rather than stalling on HBM latency — which is exactly what Figures 5 and 6 demonstrate in the speed benchmarks.

#### Decoding Implementation: How Absorption and Fusion Work in MLRA

Section 2.1 describes MLA's efficient decoding algorithm in three steps: (1) absorb the key up-projection weights into the query via Einstein summation, producing `$\tilde{Q}^{\text{NoPE}}_{n-1,:,:} \in \mathbb{R}^{h \times d_c}$`; (2) perform MQA-style attention on the latent KV cache `$\tilde{K} \in \mathbb{R}^{n \times 1 \times (d_c + d_h^R)}$` and `$\tilde{V} \in \mathbb{R}^{n \times 1 \times d_c}$` using FlashAttention-3 or FlashMLA kernels; (3) apply the value up-projection to map back to per-head outputs.

For MLRA, this same absorption approach applies within each branch. In MLRA-4, the four branches operate on latent KV caches of dimension `$d_c/4 = d_h$` each (plus the shared `$d_h^R = d_h/2$` RoPE key). The absorption step for branch `$b$` produces `$\tilde{Q}^{\text{NoPE}, (b)}_{n-1,i,:} = Q^{\text{NoPE}}_{n-1,i,:} (W^{UK}_{(b),(i)})^\top \in \mathbb{R}^{d_h}$` for each head `$i$`. The attention step then computes:

$$Z^{(b)}_{n-1,i,:} = \text{Softmax}\left(\tau \tilde{Q}^{\text{NoPE}, (b)}_{n-1,i,:} (C^{KV}_{:,(b)})^\top + \tau Q^{\text{RoPE}}_{n-1,i,:} (K^{\text{RoPE}})^\top\right) C^{KV}_{:,(b)} W^{UV}_{(b),(i)}$$

**What happens computationally:** for each branch `$b$`, the head-specific absorbed query `$\tilde{Q}^{\text{NoPE},(b)}_{n-1,i,:}$` (already in the `$d_h$`-dimensional latent space) is dotted with the cached latent block `$C^{KV}_{:,(b)}$` (also `$d_h$`-dimensional). The RoPE contribution is added identically. The resulting attention weights are used to aggregate the values, which are computed as `$C^{KV}_{:,(b)} W^{UV}_{(b),(i)}$`. The four branch outputs are then summed and rescaled by the attention output factor (1/2 for MLRA-4).

The paper's MLRA kernel (Section 4.5) implements this using FlashAttention-3 (Shah et al., 2024) as the computational backend. Each branch's attention computation is a separate FlashAttention-3 call, but because each branch operates on only `$d_h = 128$` dimensions (vs. `$d_c = 512$` for MLA), the per-call memory footprint is smaller. The four calls can potentially be overlapped or fused, though the paper does not detail specific kernel-level optimizations beyond noting that the implementation is "based on FlashAttention-3."

#### Gating Mechanism (Appendix E)

The paper also evaluates an orthogonal architectural enhancement: applying a learned sigmoid gate to the attention output before the output projection. The gated attention formulation (Appendix E) is:

$$G = \varsigma(H W^G), \quad O^{\text{attn}} = \text{Attention}(H') \odot G$$

where `$W^G \in \mathbb{R}^{d \times hd_h}$` is a learned gate projection matrix, `$\varsigma(\cdot)$` is the sigmoid function, and `$\odot$` denotes elementwise (Hadamard) product. `$H' = \text{RMSNorm}(H)$` is the normalized input.

**What this does:** the gate `$G \in \mathbb{R}^{n \times hd_h}$` acts as a learned, token-wise and channel-wise mask on the attention output. Values close to 1 let the attention output through unchanged; values close to 0 suppress it. This provides the model with a mechanism to dynamically modulate how much attention information flows into the residual stream at each token position.

**Parameter budget adjustment:** adding the gate projection `$W^G$` (which has `$d \times hd_h$` parameters — exactly the same as a standard attention output projection) increases the model's parameter count. To maintain the total parameter budget matched across all models (all at approximately 2.9B parameters), the paper proportionally *reduces* the FFN intermediate dimension `$d_f$` when gating is added. The architectural hyperparameters in Appendix F.5 show this adjustment: MLRA-4 goes from `$d_f = 9880$` (no gating, Table 17) to `$d_f = 8856$` (with gating, Table 37), a reduction of approximately 10.4%.

**Empirical validation:** Section 4.4 (Figure 4, Table 5) shows that gating consistently improves convergence and final perplexity across all five tested attention mechanisms (GQA, MLA, GLA-2, MLRA-2, MLRA-4), confirming that it provides an orthogonal benefit not specific to any particular attention variant. Gated MLRA-4 achieves the best average perplexity (13.621), with gated MLA second (13.642) and gated MLRA-2 third (13.651).

#### Concrete Architectural Configurations

The paper specifies all hyperparameters in detail (Appendix F.1, Tables 7–17). The core model is 2.9B parameters with 24 transformer layers, model dimension `$d = 3072$`, 24 attention heads (`$h=24$`), head dimension `$d_h = 128$`, partial RoPE dimension `$d_h^R = 64$`, latent query dimension `$d'_c = 1024$` (for MLA-based variants, this is 1536 for MLA itself), and latent KV dimension `$d_c = 512 = 4d_h$`. The FFN intermediate dimension `$d_f$` is adjusted per variant to keep the total parameter count approximately matched at 2872M–2873M (range less than 0.05%).

**MLRA-4 specific (Table 17):** `$d'_c = 1024$`, `$d_c = 512$`, scaling factors `$\alpha_q = \sqrt{3}$`, `$\alpha_{kv} = \sqrt{24}$`, `$\alpha_{attn} = 1/2$`, FFN `$d_f = 9880$`. The up-projection matrices are `$W^{UK}, W^{UV} \in \mathbb{R}^{512 \times 3072}$` (since `$d_c = 512$` and `$hd_h = 24 \times 128 = 3072$`), then partitioned into four `$128 \times 3072$` row-blocks, one per branch.

**MLRA-2 specific (Table 16):** identical to MLRA-4 except `$\alpha_{attn} = 1/\sqrt{2}$` and `$d_f = 10048$` (higher because MLRA-2's grouped up-projections use fewer parameters, leaving more budget for the FFN). The up-projection matrices are per-group: each group `$j \in \{0,1\}$` has `$W^{j,UK}, W^{j,UV} \in \mathbb{R}^{256 \times 1536}$` (since `$d_c/2 = 256$` and `$hd_h/2 = 1536$`), further partitioned into two `$128 \times 1536$` row-blocks per group.

**Parameter parity mechanism:** the FFN intermediate dimension `$d_f$` is the tuning knob that absorbs parameter count differences between attention mechanisms. Attention variants that use fewer attention parameters (e.g., MQA with one KV head) get a larger FFN; variants that use more (e.g., MLA with its up-projection matrices) get a smaller FFN. This ensures that all comparisons are FLOPs-matched and parameter-matched, isolating the effect of the attention mechanism itself rather than total model capacity.

## 4. Key Insights and Innovations

### Innovation 1: The Summation Locus as the Core Architectural Degree of Freedom

The paper's most conceptually distinctive contribution is not the idea of multiple latent heads per se — GLA-2 (Zadouri et al., 2025) already split MLA's single latent head into two. Rather, it is the **diagnosis that *where* the summation happens in a low-rank attention architecture — before or after the softmax non-linearity — determines whether the mechanism can support tensor parallelism**. This is a framing that transforms what appears to be a minor algebraic rearrangement into a first-class architectural degree of freedom.

Prior to this work, the field implicitly treated the summation as something that naturally belongs at the KV-computation level. MLA sums block contributions to form complete keys and values, then applies attention. GLA-2 does the same, just with fewer blocks per group. The natural generalization to enable 4-way TP would be GLA-4 — four groups, each with a single latent block — but this runs into a mathematical wall: each group's key would be only a *partial* key (one block's contribution), and the attention over partial keys is not equivalent to the attention over the complete key unless the summation is explicitly moved. The paper's Section 3.1 makes this explicit: GLA's Eq. (4) sums at the KV level, while MLRA's Eq. (5) sums at the attention-output level.

What's intellectually distinctive here is that the paper reframes the approximation — moving the summation outside the softmax — not as a necessary evil to enable TP, but as a **beneficial inductive bias**. The evidence in Tables 3 and 4 shows that MLRA-4 *improves* perplexity and accuracy over MLA (13.672 vs. 13.727 perplexity; 58.84% vs. 58.75% zero-shot accuracy), at matched parameter counts. The multi-branch attention with independent softmaxes per branch acts similarly to multi-head attention itself: each branch learns to contribute meaningfully on its own, without relying on cross-branch coupling within the softmax to form good representations. This is a fundamental insight — it suggests that the non-linear coupling of latent blocks within the softmax, which MLA preserves but MLRA sacrifices, is not actually critical for model quality, and the independence may even help.

The significance extends beyond the specific architecture. The paper establishes that **summation locality is a design parameter** in low-rank attention, not a fixed procedural detail. Future work can explore other positions for the summation — partial coupling, learned routing between branches, dynamic branch selection — all building on the framing that MLRA introduces. This is a conceptual contribution that generalizes beyond the specific MLRA-4 and MLRA-2 instantiations.

### Innovation 2: Tensor-Parallel Shardability as a First-Class Attention Design Objective

The paper makes a significant move by elevating **tensor-parallelism compatibility from a deployment afterthought to a primary attention design objective**. Prior work on efficient attention mechanisms — MQA (Shazeer, 2019), GQA (Ainslie et al., 2023), MLA (DeepSeek et al., 2024c), MFA (Hu et al., 2024), TPA (Zhang et al., 2025) — optimized for single-device KV cache size, arithmetic intensity, or training efficiency. TP compatibility, if considered, was a secondary property. This is understandable historically: attention mechanisms were designed when single-GPU serving was the common case, and the primary concern was reducing memory to fit longer contexts on one device.

MLRA flips this priority. The paper's introduction frames the problem not as "how do we reduce KV cache size" (MLA already does that well) but as "how do we make KV cache reduction *scale with the number of GPUs*." Table 1 is the key piece of evidence for why this matters: MLA's per-device loading stays flat at $4.5d_h$ regardless of whether you use 1 or 8 GPUs, making the KV cache a bottleneck that no amount of parallelism can alleviate. GLA-2 partially fixes this but plateaus at $2.5d_h$. MLRA is designed from the ground up to achieve $1.5d_h$ at exactly 4-way TP — the parallelism degree that the paper argues is the practical sweet spot (more GPUs increase communication overhead without proportional benefit; Table 1 shows GTA needs 8-way TP to match MLRA's 4-way TP figure).

This is a reframing with practical consequences. In production LLM serving systems, multi-GPU deployments are the norm — not the exception — for large models. By making TP-scalable KV cache loading an explicit design objective, the paper changes the evaluation criteria for attention mechanisms: the relevant metric is not just total KV cache size per token, but **per-device KV cache loading as a function of the parallelism degree**. This creates a new axis on which future attention mechanisms will be compared, and it's an axis that MLA, for all its elegance, fundamentally fails on.

The FLOPs-matched comparison across attention mechanisms (Tables 3 and 4) validates that this new objective does not come at the cost of model quality — MLRA-4 achieves state-of-the-art results on both perplexity and downstream accuracy while being the most TP-scalable mechanism in the comparison. This is significant because it refutes the implicit assumption that there must be a tradeoff between shardability and expressiveness in low-rank attention.

### Innovation 3: Variance Diagnosis and Calibration as a Principled Correction to Low-Rank Attention Instability

The paper provides a clean, formal analysis of a numerical pathology that affects MLA and its variants: the **variance mismatch between RoPE-derived and NoPE components of the attention logits** (Section 3.3). While the observation that this mismatch exists is not entirely novel — the paper credits LongCat et al. (2025) — the paper's contribution is to formalize it as an architectural design consideration within the specific context of low-rank attention, derive the exact scaling factors needed to correct it under i.i.d. weight assumptions, and show empirically that these corrections are necessary for convergence (Figure 2, Table 39).

What's intellectually distinctive is how the paper ties this variance analysis to MLRA's multi-branch structure. The derivation shows that the RoPE key variance scales with the model dimension $d$, while the NoPE key variance scales with the latent dimension $d_c$. With typical MLA configurations ($d=3072$, $d_c=512$), the ratio is 6:1 — the positional signal drowns out the content signal. The scaling correction ($C^{KV} \leftarrow \sqrt{4d/d_c} C^{KV}$) is derived directly from this ratio.

For MLRA specifically, the multi-branch summation introduces an additional variance consideration: summing uncorrelated branch outputs increases the total variance, requiring a compensating rescaling of the output ($1/2$ for MLRA-4, $1/\sqrt{2}$ for MLRA-2). The paper explicitly states the assumption of uncorrelated branches (Assumption 1) and acknowledges it may not strictly hold after training (Remark 1), but validates empirically that the correction is beneficial (Figure 2).

This is a second-order but conceptually important contribution because it establishes that **low-rank attention mechanisms have inherent variance dynamics that differ from standard attention**, and these dynamics must be accounted for in the architecture design — not just treated as a training-time hyperparameter to tune. The ablation in Figure 2 shows that MLA and GLA-2 benefit substantially from scaling, while MLRA-2 shows only a marginal gain — suggesting that the output rescaling inherent in MLRA's design already partially addresses the variance issue, which is an emergent property of the architecture that the paper did not explicitly design for.

### Innovation 4: A Unified Framework for the Pareto Frontier of Attention Efficiency vs. TP-Scalability

The paper's comprehensive comparison in Table 1 and Table 2 does more than benchmark MLRA — it constructs what amounts to a **two-dimensional Pareto frontier analysis** of attention mechanism efficiency. One axis is single-device KV cache loading (how compact is the cache when there's no TP?), and the other axis is TP-scalability (how well does loading scale with additional GPUs?). Prior work evaluated attention mechanisms on at most one of these axes; by jointly analyzing both, the paper reveals that mechanisms that appear competitive on one axis can be fundamentally non-competitive on the other.

For example, MLA looks excellent on the single-device axis ($4.5d_h$, the minimum achievable) but is at the worst possible point on the TP-scalability axis (flat at $4.5d_h$ for any number of GPUs). GQA looks mediocre on single-device ($16d_h$ at $g=8$) but scales well with TP (down to $2d_h$ at 8 GPUs). MLRA-4 is at or near the Pareto frontier on both axes: $4.5d_h$ single-device (matching MLA), scaling to $1.5d_h$ at 4 GPUs (matching what GTA achieves only at 8 GPUs). Table 2 adds a third dimension — arithmetic intensity during decoding — where MLRA-4 achieves ~$2h$, double MLA's ~$h$, meaning it's simultaneously more memory-efficient and more compute-capable.

This multi-dimensional framing is significant because it moves the field beyond unidimensional comparisons ("mechanism X has smaller KV cache than mechanism Y") toward a richer understanding of the tradeoffs. It establishes that the relevant question is not "which attention mechanism is best" but "which attention mechanism occupies the most favorable point in the TP-scalability vs. single-device-efficiency space for a given deployment scenario." This is a diagnostic tool that future attention mechanism proposals can be evaluated against.

The framework is empirically grounded — the 2.9B-scale pretraining experiments on FineWeb-Edu-100B and the decoding speed benchmarks on H100 GPUs (Figures 5 and 6) provide the data points — but its conceptual value extends beyond the specific numbers. It provides a template for how to evaluate attention mechanism efficiency that accounts for the reality of distributed inference.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The primary pretraining corpus is FineWeb-Edu-100B (Penedo et al., 2024), a filtered educational subset of the FineWeb dataset. All models are pretrained from scratch on 98.3B tokens of this data, with an additional 0.1B tokens held out for validation. For perplexity evaluation, the paper uses seven held-out datasets: Wikipedia, C4 (Raffel et al., 2020), the Pile (Gao et al., 2020), RefinedWeb (Penedo et al., 2023), Cosmopedia (Ben Allal et al., 2024), FineWeb (Penedo et al., 2024), and the FineWeb-Edu validation split — each evaluated on 0.1B tokens. For zero-shot downstream evaluation, the paper uses seven common-sense reasoning benchmarks: ARC-Easy, ARC-Challenge (Yadav et al., 2019), OpenBookQA (Mihaylov et al., 2018), BoolQ (Clark et al., 2019), HellaSwag (Zellers et al., 2019), Winogrande (Sakaguchi et al., 2021), and PIQA (Bisk et al., 2020), all evaluated through the lm-evaluation-harness package (Gao et al., 2024).

- **Base model(s).** All experiments use a Llama-3 (Llama et al., 2024) architecture modified to 24 transformer layers, model dimension `d = 3072`, 24 attention heads, head dimension `dh = 128`, and approximately 2.9B total parameters. The MHA baseline is initialized from the Llama3.2-3B configuration and serves as the parameter-count reference; for every other attention variant (MQA, GQA, MLA, MFA, TPA, GLA-2, GLA-4, GTA, MLRA-2, MLRA-4), the FFN intermediate dimension is adjusted to match this total parameter count, ensuring all comparisons are FLOPs-matched and parameter-matched. The 2.9B scale was chosen as a balance between computational feasibility (pretraining 11 variants from scratch on 100B tokens using 8× NVIDIA H100 80GB GPUs) and representativeness of modern LLM architectures.

- **Metrics.** The primary metric is **validation perplexity** (lower is better), computed as the exponential of the cross-entropy loss on each held-out dataset, with the average across all seven datasets reported as the summary statistic. For downstream evaluation, **normalized accuracy** is reported for ARC-Easy, ARC-Challenge, OpenBookQA, HellaSwag, and PIQA, while **standard accuracy** is reported for BoolQ and Winogrande; the average across all seven tasks is the summary zero-shot reasoning metric. For decoding efficiency, **latency** (µs per token, measured at batch=1 across sequence lengths from 131K to 2M tokens) and **throughput** (tokens per millisecond, measured at batch=128 on 8 GPUs) are the key metrics, with all timing conducted on NVIDIA H100 80GB GPUs.

- **Baselines.** The paper compares against ten alternative attention mechanisms, all evaluated under identical pretraining conditions at the 2.9B scale: **MHA** (standard multi-head attention; Vaswani et al., 2017), **MQA** (multi-query attention with 1 KV head; Shazeer, 2019), **GQA** (grouped-query attention with `g = h/4 = 6` KV heads; Ainslie et al., 2023), **MLA** (multi-head latent attention with `d'_c = 1536`, `d_c = 4d_h = 512`, `d_h^R = 0.5d_h = 64`; DeepSeek et al., 2024c), **MFA** (multi-matrix factorization attention with a single KV head and `d'_c = 2048`; Hu et al., 2024), **TPA** (tensor product attention with ranks `β_q = 6`, `β_kv = 2`; Zhang et al., 2025), **GLA-2** (grouped latent attention with 2 latent groups; Zadouri et al., 2025), **GLA-4** (an extension of GLA-2 to 4 latent groups, introduced in this paper), and **GTA** (grouped-tied attention with `g = 6`; Zadouri et al., 2025). For the decoding speed benchmarks (Section 4.5), MLA uses the official FlashMLA kernel (Jiashi Li, 2025), GQA and GLA-2 use FlashAttention-3 kernels (Shah et al., 2024), and MLRA-4 uses a custom kernel built on FlashAttention-3.

- **Generation budget / compute accounting.** All pretraining comparisons are compute-matched: each model is trained on exactly 98.3B tokens with a global batch size of 480 sequences (983,040 tokens per step, approximately 1M tokens) for 100,000 steps, using context length 2048. Parameter counts are matched by adjusting the FFN intermediate dimension `d_f` per variant (Appendix F.1, Tables 7–17), with all models falling within 2872.0M–2873.2M parameters (range < 0.05%). For decoding benchmarks, all models use 64 attention heads with `dh = 128` and `d_h^R = 64` for MLA-based variants, with the comparison conducted across identical sequence lengths on the same H100 80GB hardware. Tensor-parallel configurations are specified per mechanism: MLA uses data parallelism only (DP=8), GLA-2 uses TP=2/DP=4, MLRA-4 uses TP=4/DP=2, and GQA uses TP=8, following the principle of "aim to eliminate redundant KV cache loading" (Section 4.5, citing SGLang; Zheng et al., 2024).

- **Cross-validation / statistical protocol.** The paper does not employ cross-validation in the traditional sense — all models are pretrained once from scratch, and evaluation is performed on fixed held-out datasets. For the initialization ablation (Section 4.2.1), scaling ablation (Section 4.2.2), double-heads ablation (Section 4.2.3), and gating ablation (Section 4.4), each configuration is trained as a separate full pretraining run, and results are compared via training loss curves over the 100B tokens and final validation perplexity on the seven held-out datasets. The paper does not report confidence intervals, standard deviations across random seeds, or statistical significance tests — the comparisons rely on the consistency of patterns across multiple datasets (e.g., MLRA-4 achieves best perplexity on 6 of 7 individual datasets in Table 3, not just the average).

### Main Quantitative Results

#### Perplexity on Held-Out Language Modeling Data

Table 3 presents the central perplexity comparison across all eleven attention mechanisms on seven held-out datasets. **MLRA-4 achieves the best average perplexity of 13.672, outperforming all other mechanisms including MLA (13.727) and GLA-2 (13.779).** The pattern of results is:

- **MLRA-4 vs. MLA:** MLRA-4 achieves lower perplexity on 6 of 7 datasets, with the largest gaps on Wikipedia (14.407 vs. 14.567, a reduction of 0.160), C4 (16.286 vs. 16.345, -0.059), and FineWeb-Edu (9.193 vs. 9.284, -0.091). MLA beats MLRA-4 only on Cosmopedia (8.966 vs. 8.937). The average improvement is 0.055 perplexity points, representing a 0.4% relative reduction.

- **MLRA-4 vs. GLA-2:** The improvement is larger: average perplexity of 13.672 vs. 13.779, a gap of 0.107. MLRA-4 outperforms GLA-2 on 5 of 7 datasets, with especially notable margins on FineWeb-Edu (9.193 vs. 9.249) and Pile (13.124 vs. 13.225).

- **MLRA-2 performance:** At 13.804 average perplexity, MLRA-2 underperforms MLRA-4 by 0.132 points, MLA by 0.077 points, and GLA-2 by 0.025 points. This establishes that the four-branch architecture (MLRA-4) provides consistent advantages over the two-branch variant (MLRA-2), despite both having identical KV cache loading per device under 4-way TP.

- **Comparison with non-latent baselines:** All latent attention variants (MLA, GLA-2, GLA-4, MLRA-2, MLRA-4) outperform the standard attention baselines. MHA achieves 13.860, GQA achieves 14.139, MQA achieves 14.306, MFA achieves 14.315, GTA achieves 13.972, and TPA achieves 13.985. This confirms the broader finding that low-rank latent attention provides both efficiency and quality benefits over traditional KV-cache designs.

- **GLA-4 vs. GLA-2 vs. MLRA-4:** GLA-4 (13.815) underperforms GLA-2 (13.779) by 0.036 points and MLRA-4 (13.672) by 0.143 points. This is a particularly informative comparison: GLA-4 uses four latent heads with summation at the KV level (like MLA and GLA-2), while MLRA-4 uses four latent heads with summation at the attention-output level. The inferior performance of GLA-4 suggests that simply increasing the number of latent groups while preserving KV-level summation does not improve quality — the attention-level summation in MLRA is the operative factor.

The consistency across datasets is noteworthy: MLRA-4 is either best or second-best on every individual dataset, with no dataset where it performs poorly. This pattern holds across diverse text distributions — Wikipedia articles, web text (RefinedWeb, FineWeb), code and technical content (the Pile, Cosmopedia), and curated educational text (FineWeb-Edu) — suggesting the benefit is not dataset-specific.

#### Zero-Shot Common-Sense Reasoning

Table 4 presents accuracy on seven downstream reasoning tasks. **MLRA-4 achieves the highest average accuracy of 58.84%, narrowly outperforming MLA (58.75%) and more substantially outperforming all other mechanisms.** The detailed task-level breakdown reveals:

- **MLRA-4's strengths:** It achieves best or second-best performance on HellaSwag (62.16%, best overall), Winogrande (61.48%, best overall by 1.42 percentage points over MLA at 60.06%), and OpenBookQA (43.00%, tied with TPA's value heads and MLA at 42.60% for best). On ARC-Challenge, it scores 41.38%, behind MLRA-2 (42.24%) and GLA-4 (41.04%) but ahead of MLA (39.16%).

- **MLRA-4's relative weakness:** On ARC-Easy, it scores 67.63%, below TPA (69.44%), MHA (69.11%), MFA (69.02%), GLA-4 (68.77%), and MLA (68.22%). On PIQA, it scores 74.48%, below MLA (75.68%), MLRA-2 (75.52%), and GLA-2 (75.41%). On BoolQ, it scores 61.74%, below MLA (64.10%), GLA-2 (63.94%), and GQA (63.39%).

- **MLRA-2 performance:** At 58.68% average, MLRA-2 is competitive with MLRA-4 (difference of 0.16 percentage points, within the range of task-level variation). MLRA-2 leads on ARC-Challenge (42.24%, best overall by 1.20 points over GLA-4) and PIQA (75.52%), but trails on HellaSwag (61.49% vs. 62.16%) and Winogrande (59.98% vs. 61.48%).

- **Comparison with baselines:** MLA at 58.75% is the closest competitor, with MFA at 58.53% and GLA-2 at 58.30%. The non-latent baselines cluster lower: MHA at 57.81%, GQA at 57.89%, TPA at 57.87%, GTA at 57.80%, and MQA at 57.55%. The advantage of latent attention over standard attention on downstream reasoning is consistent but modest — the range from best (MLRA-4 at 58.84%) to worst (MQA at 57.55%) is only 1.29 percentage points, suggesting that attention architecture has a limited but non-negligible impact on zero-shot reasoning at this model scale.

- **Cross-task patterns:** No single mechanism dominates all tasks. TPA wins ARC-Easy (69.44%); MLRA-2 wins ARC-Challenge (42.24%); MLRA-4 and TPA tie on OpenBookQA (43.00%); MLA wins BoolQ (64.10%); MLRA-4 wins HellaSwag (62.16%) and Winogrande (61.48%); MLA wins PIQA (75.68%). This heterogeneous pattern suggests that different attention mechanisms may encode different inductive biases that benefit different types of reasoning, and that MLRA-4's advantage comes from being consistently strong across tasks rather than exceptionally strong on any single one.

#### Decoding Efficiency: Latency and Throughput

Section 4.5 reports two sets of timing experiments on NVIDIA H100 80GB GPUs, comparing GQA, MLA, GLA-2, and MLRA-4 under the tensor-parallel configurations that maximize their respective efficiencies.

**Decoding Latency (Figure 5).** Measured at batch=1 across sequence lengths from 131,072 to 2,097,152 tokens (128K to 2M):

- **MLRA-4 (TP=4) achieves the lowest latency at every sequence length**, with the absolute gap growing as context lengthens. At 128K tokens, MLRA-4 latency is approximately 150 µs vs. roughly 175 µs for MLA (DP=8) — a gap of roughly 25 µs. At 2M tokens, MLRA-4 latency is approximately 690 µs vs. MLA at roughly 870 µs — a gap of roughly 180 µs. The speedup over MLA is described as "steady at about 2.8×" (Section 4.5), though the absolute numbers on the figure suggest cumulative improvement rather than a constant multiplicative factor per token.

- **MLRA-4 vs. GQA (TP=8):** MLRA-4 yields speedups of 1.05×–1.26× over GQA, with the gap widening with context length. GQA latency at 128K is roughly 190 µs (MLRA-4 at ~150 µs, ~1.27× speedup) and at 2M is roughly 870 µs (MLRA-4 at ~690 µs, ~1.26× speedup). The widening gap against GQA is particularly significant because GQA is the most widely deployed efficient attention mechanism in production models (Llama-3, Qwen3-32B, etc.).

- **MLRA-4 vs. GLA-2 (TP=2):** The gap also widens with sequence length. At 128K, GLA-2 latency is approximately 220 µs vs. MLRA-4 at ~150 µs. At 2M, GLA-2 is approximately 810 µs vs. MLRA-4 at ~690 µs. The gap is larger than the MLRA-4 vs. MLA gap, consistent with the theoretical analysis in Table 1 showing that GLA-2's per-device loading (2.5dh at 2-way TP) is higher than MLRA-4's (1.5dh at 4-way TP).

**Decoding Throughput (Figure 6).** Measured at batch=128 on 8 GPUs across sequence lengths from 1,024 to 16,384 tokens, with end-to-end measurements including pre-attention and attention computation:

- **MLRA-4 (TP=4/DP=2) achieves the highest throughput across all sequence lengths.** At 1K tokens, MLRA-4 throughput is approximately 860 tokens/ms vs. GQA (TP=8) at roughly 830 tokens/ms and MLA (DP=8) at approximately 680 tokens/ms. At 16K tokens, MLRA-4 throughput is approximately 180 tokens/ms vs. GQA at roughly 150 tokens/ms and MLA at roughly 100 tokens/ms.

- **Short-sequence behavior:** At 1K–2K tokens, GQA outperforms MLA and GLA-2, which the paper attributes to pre-attention overhead dominating at short context lengths (Section 4.5: "For short sequences, GQA outperforms MLA and GLA-2 because pre-attention dominates latency"). However, MLRA-4 remains competitive with GQA even at these short lengths, which the paper attributes to MLRA-4 having "even fewer query, key, and value parameters, as shown in Appendix F.1" — meaning the pre-attention projection and absorption steps are cheaper.

- **Long-sequence behavior:** As sequence length increases (4K–16K), the gap between MLRA-4 and all baselines widens substantially. At 16K, MLRA-4 throughput is roughly 1.8× MLA's throughput (100 tokens/ms) and roughly 1.2× GQA's throughput (150 tokens/ms). This confirms that the higher arithmetic intensity derived in Table 2 (MLRA-4: ~2h vs. MLA: ~h vs. GQA: ~h/g) translates to real throughput gains when the attention computation dominates runtime.

- **MLA's throughput limitation:** MLA with DP=8 shows the lowest throughput across all sequence lengths, despite having the smallest single-device KV cache (4.5dh per token). The paper attributes this to the DP=8 configuration meaning "attention parameters are replicated across devices and the load can become imbalanced due to varying sequence lengths" (Section 4.5). This is the empirical evidence for MLA's TP-unfriendliness: using pure data parallelism to avoid redundant KV cache loading creates parameter replication and load imbalance that hurts throughput.

#### Gated Attention Results

Section 4.4 and Table 5 present perplexity for five attention mechanisms (GQA, MLA, GLA-2, MLRA-2, MLRA-4) with a sigmoid gating mechanism applied to the attention output (Appendix E). To maintain parameter parity, the FFN intermediate dimension is reduced proportionally (Appendix F.5, Tables 33–37).

**Gated MLRA-4 achieves the best average perplexity of 13.621**, with gated MLA second at 13.642 and gated MLRA-2 third at 13.651. The detailed patterns:

- **Gating consistently improves all models:** Figure 4 shows that all five models exhibit lower training loss when gating is applied, with the loss curves separating early in training (within the first 20B tokens) and the gap persisting through 100B tokens. The improvement is not specific to MLRA — GQA improves from 14.139 (Table 3) to 13.806 (Table 5, a reduction of 0.333), MLA improves from 13.727 to 13.642 (reduction of 0.085), GLA-2 improves from 13.779 to 13.701 (reduction of 0.078), MLRA-2 improves from 13.804 to 13.651 (reduction of 0.153), and MLRA-4 improves from 13.672 to 13.621 (reduction of 0.051).

- **MLRA-4's improvement from gating is the smallest:** The 0.051 reduction for MLRA-4 is notably smaller than GQA's 0.333 or MLRA-2's 0.153. This suggests that MLRA-4's multi-branch attention with independent softmaxes already provides some of the dynamic modulation that the gating mechanism adds — there may be a partial functional overlap.

- **Gated MLRA-2 closes the gap with gated MLA:** Gated MLRA-2 at 13.651 is only 0.009 worse than gated MLA at 13.642, compared to the non-gated comparison where MLRA-2 (13.804) trails MLA (13.727) by 0.077. Gating disproportionately benefits MLRA-2, making it competitive with MLA in the gated regime.

- **Dataset-level consistency for gated MLRA-4:** It achieves best or second-best perplexity on 6 of 7 datasets, with the CleanWeb dataset being the exception (GLA-2 achieves 8.874 on Cosmopedia vs. MLRA-4's 8.874 — a tie — and MLRA-4 leads on FineWeb with 15.266 vs. GLA-2's 15.369).

### Ablation Studies and Robustness Checks

**Initialization strategy (Section 4.2.1, Figure 1, Table 38):** Zero initialization of attention and FFN output projection weights outperforms the standard GPT initialization (N(0, σ=0.02)) across all nine tested attention mechanisms. The loss difference curves in Figure 1 (computed as loss with N(0, 0.02) minus loss with zero init) show positive values for all models throughout training — meaning zero init consistently achieves lower loss. The gap is largest for TPA (roughly 0.09 loss difference at 100B tokens), substantial for GLA-4 and GTA (roughly 0.04–0.05), moderate for GLA-2, MLA, MQA, and MFA (roughly 0.02–0.03), and smallest for MHA and GQA (roughly 0.01–0.02). Table 38 confirms that average perplexity improves with zero init for 8 of 9 models, with MQA being the sole exception (14.306 with zero init vs. 14.283 with N(0, 0.02), a degradation of 0.023). Unless otherwise specified, all models in the main experiments use zero initialization.

**Latent state and attention output scaling (Section 4.2.2, Figure 2, Table 39):** Applying the variance-calibrating scaling factors (Eqs. 9–10) improves convergence for MLA, GLA-2, and MLRA-2, but with different magnitudes. Figure 2 shows that MLA benefits most substantially (loss difference of roughly 0.009 at 100B tokens when scaling is applied), GLA-2 benefits moderately (roughly 0.005), and MLRA-2 benefits marginally (roughly 0.001–0.002). Table 39 confirms this pattern: scaling improves MLA's average perplexity from 13.779 to 13.727 (reduction of 0.052), GLA-2's from 13.827 to 13.779 (reduction of 0.048), and MLRA-2's from 13.808 to 13.804 (reduction of only 0.004). The paper interprets this as evidence that MLRA-2's attention output rescaling (dividing the summed branch outputs by √2) already addresses some of the variance mismatch, reducing the marginal benefit of additional latent state scaling. This is an important robustness check: it shows that the scaling factors are not merely cosmetic but necessary for MLA-style architectures to converge properly, while MLRA's multi-branch structure provides some inherent numerical stability.

**Doubling attention heads while keeping KV cache size fixed (Section 4.2.3, Figure 3, Table 40):** Increasing the number of attention heads from 24 to 48 for GQA, MLA, and GLA-2 — while keeping the KV cache size fixed by adjusting FFN dimensions to maintain parameter parity — uniformly degrades performance. Figure 3 shows positive loss differences for all three models (loss without doubled heads minus loss with doubled heads — a positive value means doubled heads are worse). Table 40 confirms: doubled-head GQA achieves 14.213 average perplexity vs. 14.139 for standard GQA (degradation of 0.074), doubled-head MLA achieves 13.836 vs. 13.727 (degradation of 0.109), and doubled-head GLA-2 achieves 13.851 vs. 13.779 (degradation of 0.072). This result validates that MLRA's performance advantage over MLA and GLA-2 is **not** attributable to MLRA having more independent attention computations (4 branches × 24 heads vs. 24 heads for MLA), since naively increasing head count while keeping the same KV cache structure is harmful, not helpful. The mechanism matters — attention-level summation across independent branches is beneficial, while simply adding more heads with shared KV representations is detrimental.

**GLA-4 as a natural ablation of summation locus:** The paper includes GLA-4 as a baseline (Tables 3, 4, 13–14), which implements four latent groups with KV-level summation (like GLA-2, but with four groups instead of two). If simply having more latent heads with shared KV structure were sufficient, GLA-4 should outperform GLA-2. Instead, GLA-4 achieves 13.815 average perplexity — worse than GLA-2 (13.779) and substantially worse than MLRA-4 (13.672). This is a clean ablation isolating the effect of summation locus: GLA-4 and MLRA-4 both have four latent blocks, but GLA-4 sums at the KV level (each group's key is the sum of one block's contribution) while MLRA-4 sums at the attention-output level (each block is an independent attention branch). The 0.143 perplexity gap between them (13.815 vs. 13.672) can be attributed to this architectural difference, since parameter counts are nearly identical (2873.22M for both; Tables 14 and 17). This is the strongest piece of evidence in the paper that the summation locus matters independently of the number of latent partitions.

**Gating as an orthogonal enhancement (Section 4.4, Figure 4, Table 5):** Adding a sigmoid gate to the attention output consistently improves all tested models, but the magnitude varies. GQA benefits the most (0.333 perplexity reduction), MLRA-2 benefits substantially (0.153 reduction), and MLRA-4 benefits the least (0.051 reduction). The ordering of models with gating is: MLRA-4 (13.621) > MLA (13.642) > MLRA-2 (13.651) > GLA-2 (13.701) > GQA (13.806). This both validates gating as a broadly useful architectural addition and confirms that MLRA-4's advantage is not dependent on gating — it leads with or without it.

### Critical Assessment

The experiments generally support the paper's central claims, but several important caveats and gaps should be noted.

**On the claim that MLRA-4 achieves state-of-the-art perplexity and downstream accuracy:** This is directly supported by Tables 3 and 4, but the margins are small. MLRA-4's average perplexity of 13.672 beats MLA's 13.727 by only 0.055 points (0.4% relative). On downstream accuracy, the margin is 0.09 percentage points (58.84% vs. 58.75%). These differences are consistent across datasets — MLRA-4 leads on 6 of 7 perplexity datasets — but the paper does not report any measure of statistical reliability (no standard errors, no confidence intervals, no multi-seed evaluations). At a 500-question test set per downstream task and 0.1B tokens per perplexity dataset, the effective sample sizes are large enough that the average gaps may be statistically significant, but this cannot be confirmed from the reported data. A reader should interpret "state-of-the-art" here as "slightly ahead of the closest competitor on these specific benchmarks at this specific scale."

**On the claim that MLRA delivers 2.8× decoding speedup over MLA:** Figure 5 supports a substantial latency reduction, and the paper's description states "the speedup over MLA remains steady at about 2.8×" (Section 4.5). However, this comparison is between MLRA-4 with TP=4 and MLA with DP=8 — different parallelism strategies. MLA is forced into pure data parallelism because its single latent head cannot be sharded, which the paper argues is an inherent limitation of MLA's architecture. But it also means the 2.8× figure reflects the benefit of tensor parallelism (distributing the KV cache) plus any inherent efficiency of MLRA's attention computation, not a pure algorithmic speedup at the same parallelism configuration. A comparison of MLRA-4 and MLA both under DP=8 would isolate the algorithmic speedup, but this is not reported. The 2.8× figure is therefore best understood as **the end-to-end deployment advantage of choosing an MLRA-based model over an MLA-based model in a multi-GPU setting**, not as a per-FLOP algorithmic advantage.

**On the claim that MLRA achieves 1.05–1.26× speedup over GQA:** This is supported by Figure 5. However, GQA is configured with TP=8 (vs. MLRA-4's TP=4). An 8-way tensor-parallel configuration is communication-heavy and may not be practical for all deployments. If GQA were run with TP=4 (matching MLRA-4's configuration), its per-device KV cache loading would be 4dh (Table 1) vs. MLRA-4's 1.5dh, which would substantially increase the speedup over GQA beyond the reported 1.05–1.26×. The paper's choice to give GQA its optimal TP=8 configuration makes the comparison *more conservative* for MLRA-4, which strengthens the claim — but it also means the reported speedup underestimates MLRA-4's advantage in configurations where high-degree TP is infeasible (e.g., smaller GPU clusters).

**Missing experiment: direct comparison of MLRA-4 vs. MLA at matched TP degree.** The paper's Table 1 shows MLA cannot benefit from TP, but what about a comparison where both use DP=8? MLRA-4 with DP=8 would have each GPU load the full 4.5dh KV cache (redundantly, like MLA), but would the multi-branch attention computation itself be faster or slower than MLA's single-branch absorption approach? This experiment is not reported. The 2.8× speedup conflates the TP benefit with any inherent computational efficiency difference.

**Single scale, single model family, single training dataset:** All experiments are at the 2.9B parameter scale, using the Llama-3 architecture, trained on FineWeb-Edu-100B. The paper does not demonstrate that the results hold at different scales (e.g., 1B, 7B, 13B), with different architecture families (e.g., non-Llama MLP designs, mixture-of-experts), or on different pretraining data distributions. The 2.9B scale is large enough to be non-trivial — pretraining 11 variants from scratch on 100B tokens represents a substantial computational investment — but scaling behavior of attention mechanisms can be non-linear. MLA's advantage over MHA, for example, may increase or decrease with model size. Whether MLRA-4 maintains its edge over MLA at 7B or 70B parameters is unknown.

**KV cache loading analysis (Table 1) uses architectural references from other model families:** The table uses Qwen3-32B (GQA) and Kimi-K2 (MLA) as base architectures for the loading calculations, not the Llama-3 2.9B models actually trained in the paper. The absolute numbers (e.g., 128dh for MHA) depend on the specific head counts and dimensions of these reference architectures. While the relationships between methods (MLA cannot shard, MLRA-4 reaches 1.5dh at 4-way TP) should hold regardless of the base architecture, the paper does not validate that the per-device loading figures in Table 1 correspond to the actual memory traffic measured during the decoding benchmarks in Figures 5 and 6. This is a theoretical analysis, not an empirical measurement of HBM traffic.

**Arithmetic intensity analysis (Table 2) is approximate and assumes large n:** The AI formulas simplify by assuming sequence length n dominates other terms. For the short-sequence benchmarks in Figure 6 (1K–16K tokens), constant factors from pre-attention computation and kernel launch overhead may significantly affect the realized intensity. The paper notes this implicitly by explaining GQA's advantage at short sequences as pre-attention overhead dominating, but does not provide a rigorous short-sequence FLOP/byte analysis.

**Missing ablation: varying d_c (latent KV dimension).** MLA uses d_c = 4dh, which produces the 4-block structure that MLRA-4 exploits. What if d_c = 2dh (producing 2 blocks) or d_c = 8dh (producing 8 blocks)? Would MLRA-8 with 8-way TP provide further benefits, or does the branching overhead outweigh the sharding benefits? This ablation would help characterize the scaling behavior of the summation-locus idea beyond the specific 4-branch instantiation.

**Missing ablation: attention-level summation with learned branch weights.** MLRA sums branch outputs with uniform weights (implicitly 1, then rescaled by 1/2 or 1/√2 for variance). Would learned, head-specific, or input-dependent branch mixing coefficients improve quality? This is a natural extension that the paper does not explore, but it would help determine whether uniform summation is optimal or merely sufficient.

**Downstream evaluation is limited to common-sense reasoning.** The paper evaluates on ARC, OpenBookQA, BoolQ, HellaSwag, Winogrande, and PIQA — all relatively short-context tasks that do not stress the long-context decoding efficiency that is MLRA's primary motivation. There is no evaluation on long-context reasoning tasks (e.g., needle-in-a-haystack, long-document QA, summarization) that would directly validate the claim that MLRA's decoding efficiency benefits translate to better long-context task performance at a given latency budget. This is a significant gap: the paper's primary motivation is long-context efficiency, but the quality evaluation does not include a single long-context benchmark.

**GLA-4 is introduced as a baseline but not motivated as a natural ablation:** The paper introduces GLA-4 (4 latent groups with KV-level summation) as a baseline without explicitly discussing why it's included. From the results, it serves as a crucial ablation — same number of latent partitions as MLRA-4, same parameter count, but summation at the KV level instead of the attention level — and its inferior performance (13.815 vs. 13.672) is the cleanest evidence that the summation locus matters. The paper could have highlighted this comparison more prominently as the key mechanistic validation.

**Training curves (Figure 7) show convergence but not final-ranking stability:** The training loss curves in Figure 7 show that all models are still improving at 100B tokens, with no obvious saturation. The relative ordering of models at 50B tokens may differ from the ordering at 100B tokens. The paper reports only final perplexity (at 100B tokens) and does not discuss whether the performance gaps are stable, widening, or narrowing toward the end of training. If MLRA-4's advantage over MLA is narrow and the curves are converging, the gap might disappear with additional training. Conversely, if the gap is widening, MLRA-4's advantage might be understated.

**The double-heads ablation uses a different mechanism than MLRA's multi-branch attention:** Section 4.2.3 doubles the number of attention heads from 24 to 48 for GQA, MLA, and GLA-2 while keeping KV cache size fixed. This is intended to test whether MLRA's performance benefit comes simply from having more attention computations. However, doubling attention heads in these architectures changes the query/key/value projection dimensions and the per-head dimension allocations in ways that don't perfectly mirror MLRA's branch structure. In MLRA, each of the 24 heads processes 4 independent branches with separate softmaxes, but the per-head dimension dh = 128 remains constant. In the doubled-head variants, each of 48 heads has the same dh = 128, but the total attention parameter count increases (requiring FFN reduction). The comparison is informative but not a perfect isolation of the "number of attention computations" variable.

In summary, the experimental evidence supports the paper's claims at the tested scale and configuration, with the strongest support being for (1) MLRA-4's slight quality advantage over MLA and other attention mechanisms at matched parameters, (2) the substantial decoding latency and throughput benefits when tensor parallelism is employed, and (3) the importance of attention-level vs. KV-level summation as demonstrated by the GLA-4 vs. MLRA-4 comparison. The primary weaknesses are the lack of statistical reliability reporting, the single-scale evaluation, the absence of long-context downstream benchmarks, and the conflation of algorithmic and parallelism-related speedup factors in the 2.8× MLA comparison.

## 6. Limitations and Trade-offs

### 6.1 All Experiments Are at a Single Scale (2.9B Parameters), with No Evidence the Gains Transfer to Larger Models

**The assumption or constraint.** The paper evaluates MLRA exclusively at the 2.9B-parameter scale, pretrained on 98.3B tokens of FineWeb-Edu-100B. Section 4.1 describes this as the sole experimental configuration. While 2.9B is a non-trivial scale — pretraining 11 variants from scratch on 100B tokens represents a substantial computational investment — the paper does not demonstrate that the findings hold at scales typical of production LLM deployment (7B, 13B, 70B, or larger). All claims about state-of-the-art perplexity, downstream accuracy, and decoding efficiency are conditional on this single scale.

**The consequence.** The relative performance of attention mechanisms can shift with model scale. MLA's compression ratio (`d_c = 4d_h`) may be more or less optimal at different model sizes — what works at `h = 24` heads may not work at `h = 64` or `h = 128`. Similarly, the variance mismatch that Section 3.3 addresses scales with the ratio `d/d_c`, which changes with model dimension. At larger scales, the tradeoffs between attention parameter count and FFN parameter count (which the paper controls by adjusting `d_f` to match total parameters) may shift in ways that favor or disfavor MLRA relative to MLA or GQA. A practitioner considering MLRA for a production 70B model cannot infer from this paper whether the 0.4% perplexity improvement over MLA (Table 3) would scale, shrink, or reverse at that size. The decoding efficiency gains (2.8× over MLA, Figure 5) are measured at a single configuration (64 heads, `d_h = 128`, matching the DeepSeek-V3 architecture; Section 4.5) — these speedups depend on the ratio of computation to memory access, which changes with model architecture and GPU characteristics at different scales.

**What evidence exists in the paper.** None. All 11 attention variants are trained and evaluated exactly once at 2.9B parameters. The paper includes no scaling law experiments, no smaller-scale validation runs (e.g., 1B or 500M), and no extrapolation analysis. The decoding benchmarks (Section 4.5) use `h = 64` and `d = 7168` (matching DeepSeek-V3) rather than the 2.9B model's `h = 24` and `d = 3072`, creating a further mismatch between the quality experiments and the efficiency experiments.

**Mitigation status.** The paper does not acknowledge this as a limitation. There is no discussion of how results might change at larger scales, nor any suggestion that future work should validate at production-relevant model sizes. A reader must treat all quantitative claims (13.672 perplexity, 58.84% accuracy, 2.8× speedup) as point estimates at a specific, relatively small scale, with unknown generalizability.

---

### 6.2 Difficulty Estimation Cost for KV-Cache Distribution Is Not Accounted for in the Efficiency Analysis

**The assumption or constraint.** The decoding efficiency analysis (Section 4.5, Figures 5 and 6, Table 1) assumes that the four latent blocks `C^{KV}_{:,(b)}` for `b ∈ {0,1,2,3}` can be cleanly assigned to four GPUs under 4-way tensor parallelism, with each GPU loading only its assigned `d_h`-dimensional block plus the shared `d_h^R`-dimensional RoPE key (total `1.5d_h` per device). This is the core mechanism enabling the claimed speedups over MLA and GQA. However, the paper does not describe how the latent blocks are *produced and distributed* during generation. In MLA, the down-projection `C^{KV} = α_{kv} RMSNorm(H W^{DKV})` produces a single `d_c`-dimensional vector per token — this operation happens on one device or requires an all-reduce across devices. To achieve the `1.5d_h` per-device loading in Table 1, each GPU must receive only its assigned `d_h`-dimensional slice of `C^{KV}`. The communication cost of distributing these slices — whether via an all-to-all scatter, a broadcast followed by local slicing, or some other pattern — is not included in the latency or throughput measurements.

**The consequence.** The actual per-device data movement for MLRA under 4-way TP includes: (1) the KV cache loading (`1.5d_h` per token, as claimed), PLUS (2) the communication cost of distributing the freshly computed latent state `C^{KV}` across GPUs at each generation step. For standard MHA under tensor parallelism, the analogous cost is the all-reduce of attention outputs after each head computes its portion — a well-understood and optimized communication pattern. For MLRA, the equivalent cost depends on where `W^{DKV}` resides (is it replicated? sharded?) and how the latent state is partitioned. If `W^{DKV}` is replicated, each GPU computes the full `C^{KV}` and then discards three-quarters of it — this wastes computation but not communication. If `W^{DKV}` is sharded, an all-reduce is needed to form the complete `C^{KV}` before partitioning, which adds communication latency proportional to `d_c = 4d_h` at every step. Neither cost is modeled in Table 1, Table 2, or the benchmarks in Figures 5 and 6. The headline `1.5d_h` per-device figure is therefore a lower bound on actual per-device memory traffic.

**What evidence exists in the paper.** None. The paper reports end-to-end throughput (Figure 6) including "the pre-attention stage that prepares inputs for the attention kernel and the attention computation itself" (Section 4.5), so *some* of this cost may be captured in the throughput measurements. However, the paper does not break down what fraction of the runtime is attention computation vs. pre-attention projection vs. communication, making it impossible to verify that the `1.5d_h` loading analysis in Table 1 corresponds to measured memory traffic. The 2.8× speedup over MLA is an empirical measurement, not a theoretical derivation, so it does include whatever communication overhead exists — but the paper does not characterize how that overhead scales with sequence length or TP degree, leaving practitioners uncertain about whether the speedup would persist in different deployment configurations.

**Mitigation status.** Not addressed. The paper does not discuss the communication cost of distributing latent states under tensor parallelism, the placement of `W^{DKV}`, or the pre-attention computation pattern in a multi-GPU setting. This is a significant gap because the entire motivation for MLRA is distributed inference efficiency, yet the analysis of that efficiency omits a necessary cost.

### 6.3 MLRA Decouples Latent Blocks at the Softmax Level — an Approximation Whose Failure Modes Are Not Characterized

**The assumption or constraint.** MLRA's fundamental architectural move — summing attention outputs rather than summing keys and values before the softmax — is an approximation to the full MLA computation. Section 3.1 (Eq. 5) makes this explicit: the softmax of sums is not equal to the sum of softmaxes. The paper treats this as a beneficial inductive bias and validates it with perplexity and accuracy results (Tables 3 and 4), but it does not analyze *when* this approximation might be harmful versus helpful. The RoPE key `K^{\text{RoPE}}` is added identically to every branch's attention logits — this means the positional signal is replicated four times in the overall attention computation, while the content signal from `C^{KV}_{:,(b)}` is partitioned across branches. The interaction between these replicated and partitioned signals is not analyzed.

**The consequence.** There are at least two potential failure modes that the paper does not investigate. First, **repeated RoPE contributions**: since each branch independently adds `τ Q^{\text{RoPE}}_{:,i,:} (K^{\text{RoPE}})^\top` to its logits, the positional component of the attention score is effectively counted four times (once per branch, then implicitly averaged when outputs are summed and rescaled by 1/2). If the RoPE signal is noisy or dominant for certain head/token combinations, this replication could amplify positional bias at the expense of content-based attention. Second, **branch collapse**: if the four branches learn redundant representations (e.g., all branches learn to attend to similar token patterns), the effective capacity of the multi-branch architecture is wasted, and the model is effectively paying the computational cost of four branches for the representational benefit of one. The paper's assumption that branch outputs are mutually uncorrelated (Assumption 1, Section 3.3) is used to derive the output rescaling factor of 1/2 (since `Var(Σ O_b) = Σ Var(O_b)` under zero correlation), but the paper acknowledges in Remark 1 that this "may not strictly hold in practice" during training. If branch outputs become correlated, the rescaling factor of 1/2 is too aggressive and the summed output is artificially attenuated. Conversely, if they are anti-correlated, the rescaling is insufficient.

**What evidence exists in the paper.** The only indirect evidence is the performance comparison between MLRA-4 (attention-level summation) and GLA-4 (KV-level summation), which shows MLRA-4 achieving 13.672 vs. 13.815 perplexity (Table 3). This demonstrates that attention-level summation is better *on average* at this scale, but does not characterize *on which inputs* it is better or worse. The paper does not report per-dataset variance or per-example analysis. There is no measurement of branch output correlation during or after training, no analysis of whether individual branches specialize to different attention patterns, and no visualization of branch attention distributions. The failure modes described above remain hypothetical — the paper provides no evidence for or against their occurrence.

**Mitigation status.** Not addressed. The paper presents the approximation as validated by aggregate performance metrics but does not investigate its qualitative behavior or failure conditions. Remark 1 acknowledges the uncorrelated-branches assumption may not hold in practice, but this is treated as a caveat about the variance analysis, not as a prompt to investigate branch behavior empirically.

### 6.4 The Downstream Evaluation Contains No Long-Context Benchmarks — the Very Regime MLRA Is Designed to Accelerate

**The assumption or constraint.** The paper's primary motivation is long-context decoding efficiency. Section 1 states that "sequential token generation under Multi-Head Attention requires reloading the KV cache from high-bandwidth memory every step, so data movement, not computation, dominates latency for long-context inference." MLRA is proposed as a solution to this bottleneck, and the decoding speed benchmarks (Section 4.5, Figures 5 and 6) demonstrate reduced latency and improved throughput at sequence lengths up to 2M tokens. However, the quality evaluation — perplexity and downstream accuracy — uses only standard, short-context benchmarks. Pretraining uses a context length of 2048 tokens (Section 4.1). The downstream evaluation (Table 4) uses ARC-Easy, ARC-Challenge, OpenBookQA, BoolQ, HellaSwag, Winogrande, and PIQA — none of which require long-context reasoning. The perplexity evaluation (Table 3) uses 0.1B-token slices from standard corpora, evaluated at the same 2048-token context length used during training.

**The consequence.** MLRA's multi-branch attention with independent softmaxes per branch is a different computational primitive than standard attention. Its behavior on very long sequences — where the softmax operates over tens or hundreds of thousands of tokens per branch — may differ qualitatively from its behavior on 2048-token sequences. Specifically, MLRA's four-branch partitioning means that each branch's key dimension is only `d_h = 128` (versus `d_c = 512` for MLA's full latent attention). The attention logit for a query-key pair in each MLRA branch is the dot product of two vectors in a 128-dimensional space (plus the 64-dimensional RoPE contribution). In standard MLA, the equivalent attention logit comes from a 512-dimensional space (plus RoPE). For very long sequences, the softmax temperature τ and the dimensional scaling of dot products interact in ways that depend on the dimension — higher-dimensional dot products have larger variance, which affects the effective temperature of the softmax. MLRA's per-branch attention operates in a lower-dimensional space, which may change how attention weights distribute over long contexts (potentially making them more or less concentrated). The paper provides no evidence about whether MLRA maintains its quality advantage — or even its basic functionality — at the 128K+ sequence lengths that motivate its design. A practitioner deploying MLRA for long-context RAG or chain-of-thought applications does not know whether the perplexity gains in Table 3 (measured at context length 2048) hold for documents of 100K tokens.

**What evidence exists in the paper.** None. Every quality evaluation uses the 2048-token context length. The decoding speed benchmarks (Figures 5 and 6) measure *latency and throughput*, not *output quality* — they show that MLRA generates tokens faster, not that the tokens it generates are correct or coherent. There is no needle-in-a-haystack evaluation, no long-document summarization, no multi-hop reasoning over long contexts, and no long-context perplexity measurement (which would require evaluating on sequences longer than 2048 tokens, requiring positional encoding extrapolation or training with longer contexts).

**Mitigation status.** The paper does not acknowledge this gap. The quality experiments and efficiency experiments are presented in different sections (4.3 and 4.5, respectively) with no discussion of their relationship. A reader might reasonably conclude from the abstract and introduction that MLRA's quality advantages have been demonstrated in long-context settings — but this is not the case.

### 6.5 The 2.8× Speedup over MLA Compounds TP-Friendliness with Architecture-Specific Efficiency, and the Comparison Does Not Isolate Either Factor

**The assumption or constraint.** The paper's most prominent efficiency claim is that "MLRA-4 with TP=4 substantially reduces long-context decoding latency" and "the speedup over MLA remains steady at about 2.8×" (Section 4.5). This comparison is between MLRA-4 using 4-way tensor parallelism (TP=4, with data parallelism DP=2 for throughput) and MLA using pure data parallelism (DP=8). The justification, stated in Section 4.5, is that "with DP, we assign different requests to different devices, so attention parameters are replicated across devices and the load can become imbalanced due to varying sequence lengths. With TP, the up-projection parameters are sharded by head, but the KV cache loading is repeated across devices. Following SGLang, we aim to eliminate redundant KV cache loading."

**The consequence.** The 2.8× speedup figure conflates two distinct effects: (1) the benefit of using tensor parallelism to distribute the KV cache across devices (reducing per-device HBM traffic from `4.5d_h` to `1.5d_h`), and (2) any inherent computational efficiency difference between MLRA's four-branch attention and MLA's single-branch absorbed attention. A practitioner cannot determine how much of the 2.8× comes from better parallelism (which is MLRA's core contribution and the point of the paper) versus how much comes from MLRA's attention computation being intrinsically faster (e.g., because the per-branch attention operates on smaller matrices that better utilize GPU tensor cores). If the speedup is primarily from TP-friendliness, then the paper's central claim is validated — MLRA enables efficient multi-GPU decoding that MLA cannot. If a significant portion comes from intrinsic computational differences, then the claim is partially about MLRA being a faster attention kernel regardless of parallelism, which the paper has not established through a controlled comparison (e.g., MLRA-4 vs. MLA both at DP=8).

**What evidence exists in the paper.** The only evidence is Figure 5, which reports latency for the specific (and asymmetric) configurations. There is no ablation comparing MLRA and MLA at identical parallelism configurations. The paper does not report a latency breakdown separating attention computation from KV cache loading from communication. The arithmetic intensity analysis in Table 2 suggests MLRA-4 has ~2h AI vs. MLA's ~h, implying MLRA does have an intrinsic computational advantage — but this is a theoretical FLOP/byte ratio, not a measured speedup. The paper also does not report MLRA-4 latency under DP=8, nor MLA latency under TP=4 (if implemented with the redundant loading that the paper criticizes). Without these comparisons, the 2.8× figure is best interpreted as "the end-to-end speedup you get by choosing MLRA-4 over MLA in a multi-GPU deployment, using each mechanism's best parallelism strategy" — a practically meaningful but analytically confounded result.

**Mitigation status.** The paper partially mitigates this by reporting throughput with GQA at TP=8 (Figure 6), making the comparison more comprehensive. However, the specific MLA-vs-MLRA comparison at the center of the paper's claims remains confounded. The paper does not discuss this confound or suggest a decomposition of the speedup into TP-friendliness and intrinsic efficiency components. For a paper whose primary contribution is enabling efficient tensor parallelism, this omission is significant — readers cannot assess whether the 2.8× figure represents the true benefit of the architectural innovation or an artifact of comparing optimal-vs-suboptimal parallelism strategies.

## 7. Implications and Future Directions

### Establishing Partitionable Low-Rank Attention as a Design Space

The most significant conceptual contribution is establishing that **latent compression and tensor parallelism are not mutually exclusive** for attention mechanisms. Prior to this work, the field had:

1. **Compressed but non-parallelizable**: MLA, with excellent KV efficiency but no TP support.
2. **Parallelizable but less compressed**: GQA, with full TP support but requiring 8-way TP to match MLRA-4's 4-way efficiency.
3. **Partial solutions**: GLA-2, enabling 2-way TP but plateauing beyond that.

MLRA opens a new region in this design space: **partitionable low-rank attention** where the latent representation is explicitly structured to support sharding. This suggests a research agenda:

- **Arbitrary TP degrees**: Can MLRA be generalized to $N$-branch variants (MLRA-$N$) for any TP degree? The mathematical structure suggests yes—partition into $N$ blocks instead of 4—but the variance calibration and output scaling would need rederivation.
- **Optimal branching factor**: Is 4 branches optimal? What tradeoffs exist between branch count, quality, and parallelism? The paper shows MLRA-4 outperforms MLRA-2 (13.672 vs. 13.804), suggesting more branches help, but the upper bound is not explored.
- **Hybrid partitioning**: Could different attention layers use different branching factors? Early layers (where position encoding matters more) might benefit from fewer branches, while later layers might use more.

### Practical Implications for LLM Deployment

**For inference serving systems (vLLM, SGLang, TensorRT-LLM)**:
MLRA-4 provides a blueprint for attention kernels that achieve both KV cache efficiency and tensor parallelism. The paper's custom kernel implementation (based on FlashAttention-3) demonstrates feasibility, but production integration would require:
- Paged attention support for variable-length batching
- Integration with continuous batching schedulers
- Communication optimization for the branch output summation across TP devices

**For hardware designers**:
MLRA-4's arithmetic intensity of $2h$ (vs. $h$ for MLA) shifts decoding toward compute-bound operation. This has implications for:
- HBM bandwidth requirements: Lower bandwidth suffices, potentially enabling smaller/cheaper memory subsystems.
- Compute unit utilization: Higher arithmetic intensity means better GPU SM utilization during decoding.
- Inter-device communication: The all-reduce for branch output summation becomes a new bottleneck at high TP degrees.

**For model architects**:
The variance calibration strategy (Section 3.3) is broadly applicable to any attention mechanism using latent compression with separate RoPE components. This addresses a stability issue noted in LongCat (2025) but not systematically resolved. The zero initialization for output projections (Section 4.2.1) is another broadly applicable finding.

### Follow-Up Research Directions

**1. Scaling to larger models and longer contexts**

The 2.9B experiments are promising but insufficient for understanding MLRA's behavior at production scales. Key questions:
- Does MLRA-4 maintain perplexity advantages at 70B scale?
- How does MLRA-4 handle context lengths beyond 2M tokens? The latency benchmarks go to 2M, but quality evaluation at extreme context lengths is not provided.
- Does MLRA-4 affect context utilization patterns? For example, the multi-branch structure might affect how information is retrieved from distant tokens.

**2. Retrofitting pretrained models**

Practical adoption requires either training new models from scratch (expensive) or fine-tuning existing models. Research needed:
- Can GQA/MHA models be converted to MLRA via continued pretraining with architecture modification?
- What is the quality gap between MLRA-trained-from-scratch vs. MLRA-fine-tuned?
- Is there a "MLRA-aware" training approach that produces models more amenable to later MLRA conversion?

**3. Combining MLRA with other efficiency techniques**

MLRA addresses KV cache efficiency and TP, but other bottlenecks remain:
- **Speculative decoding**: MLRA's multi-branch structure might interfere with draft model alignment.
- **KV cache quantization**: Can MLRA's latent partitions be quantized separately for additional compression?
- **Sparse attention**: Could branches learn to attend to different token subsets, enabling implicit sparsity?

**4. Beyond 4-way TP: Hierarchical or adaptive partitioning**

The 4-branch structure limits MLRA to 4-way TP. Alternatives:
- **Hierarchical partitioning**: Further partition each branch for recursive TP (e.g., 4 branches × 2 sub-branches = 8-way TP).
- **Adaptive partitioning**: Dynamically adjust branch assignment based on available devices, enabling flexible deployment.

**5. Theoretical analysis of multi-branch attention**

The paper empirically shows MLRA-4 improves over MLA, but why? Possible explanations:
- **Ensemble effect**: Independent branches reduce variance.
- **Specialization**: Different branches learn different attention patterns.
- **Optimization dynamics**: More gradient pathways improve training.

Formal analysis connecting branch structure to representational capacity and optimization landscape would strengthen the theoretical foundation.

### When to Prefer MLRA Over Alternatives

**Choose MLRA-4 when:**
- Deploying with 4 GPUs and tensor parallelism is required.
- Long-context inference (128K+ tokens) is the primary workload.
- Training from scratch is acceptable.
- Perplexity and downstream quality are prioritized.

**Choose GQA when:**
- Deploying with 8+ GPUs and full weight sharding is needed.
- Fine-tuning an existing GQA-pretrained model.
- Short-context workloads dominate (pre-attention overhead is concern).

**Choose MLA when:**
- Single-GPU deployment (no TP needed).
- Latent KV cache efficiency is critical but parallelism is not.
- Compatibility with DeepSeek ecosystem (FlashMLA kernels).

**Choose GLA-2 when:**
- Exactly 2-way TP is needed.
- Simpler architecture preferred over MLRA-4's multi-branch complexity.

### Integration Guidance

For practitioners implementing MLRA:

1. **Variance calibration is essential**: Use scaling factors $\alpha_q = \sqrt{d/d_c'}$ and $\alpha_{kv} = \sqrt{4d/d_c}$ for query and KV latents, plus output scaling ($\alpha_{attn} = 1/2$ for MLRA-4). The ablation (Table 39) shows instability without these.

2. **Zero initialization for output projections**: Initialize $W_{O,attn}$ and $W_{O,mlp}$ to zero, following Section 4.2.1.

3. **Gating provides marginal benefit**: Table 5 shows gating improves MLRA-4 from 13.672 to 13.621, a 0.051 reduction. Consider whether this justifies additional parameters.

4. **Kernel implementation**: Build on FlashAttention-3 as the paper does. The "MQA-style decoding on latent KV cache" formulation (Section 2.1, Step 2) requires custom kernels that absorb up-projections into queries.

5. **Communication pattern**: For TP=4, each device computes one branch's attention output, then an all-reduce sums outputs across devices. This differs from standard TP where each device handles different heads independently.
