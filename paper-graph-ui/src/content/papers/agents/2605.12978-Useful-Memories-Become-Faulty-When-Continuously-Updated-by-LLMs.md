# Useful Memories Become Faulty When Continuously Updated by LLMs

**ArXiv:** [2605.12978](https://arxiv.org/abs/2605.12978)

## 🎯 Pitch

Even when distilling ground-truth solutions into memory, GPT-5.4 ends up flunking over half the tasks it originally aced—a stunning collapse traced not to bad experience but to the consolidation step itself, which steadily corrupts useful abstractions with each successive update. The culprit is mandatory rewriting after every interaction, which strips conditions, mixes up episodes, and progressively drives performance below a no-memory baseline.

---

## 1. Executive Summary

This paper systematically examines what happens when LLM agents continuously consolidate past trajectories into abstracted textual memory, studying representative agentic-memory methods—CLIN, Agent Workflow Memory, Dynamic Cheatsheet, and ACE—across ALFWorld, ScienceWorld, WebShop, AppWorld, and a controlled ARC-AGI Stream testbed using GPT-5.4 and Qwen3.5 model families. The central finding is that consolidated memory produced by today's LLMs is **faulty even when derived from useful experiences**: as consolidation proceeds, memory utility first rises, then degrades, and can fall below the no-memory baseline—in the cleanest case, GPT-5.4 fails on 54% of ARC-AGI problems it had previously solved at 100% accuracy without memory after consolidating from ground-truth solutions to those very problems. The failure is traced to the consolidation step itself rather than the underlying experience, driven by three mechanisms: misgrouping episodes before abstraction, stripping applicability conditions from lessons so they interfere with neighboring tasks, and overfitting to narrow input streams. The paper establishes that raw episodic trajectories should be treated as first-class evidence rather than disposable material to be compressed away—an episodic-only control matches or beats consolidators across benchmarks, and agents that preserve raw episodes by default double the accuracy of their forced-consolidation counterparts on ARC-AGI Stream—while showing that mandatory rewriting at every step, rather than abstraction itself, is the decisive failure mode.

## 2. Context and Motivation

### The Core Problem: Consolidated Agent Memory Degrades With Use

The fundamental question this paper tackles is counterintuitive: **when LLM agents compress past experiences into reusable textual abstractions—the dominant paradigm in agentic-memory systems—does more experience actually produce better memory?** The answer, supported across five benchmarks and multiple model families, is that it often does not. Consolidated memory initially improves, then degrades, and can fall below having no memory at all. This is not a problem of noisy or unhelpful input trajectories—the paper deliberately studies settings where experiences are demonstrably useful (either drawn from problems the agent solved without memory, or supplied with ground-truth solutions). The failure lies in the consolidation mechanism itself.

This matters for three practical reasons the paper surfaces throughout:

- **Self-evolving agent pipelines assume consolidation is at worst neutral.** Systems like CLIN (Majumder et al., 2023), Agent Workflow Memory (Wang et al., 2024), Dynamic Cheatsheet (Suzgun et al., 2026), and ACE (Zhang et al., 2025) all adopt update-after-every-interaction designs that treat each consolidation step as either beneficial or harmless. The paper's central empirical finding contradicts this assumption directly: each consolidation step is a lossy rewrite where useful details are dropped, spurious rules are introduced, and once-helpful abstractions drift away from the underlying task structure. If consolidation can make agents *worse* on problems they previously solved, then the default design pattern in agentic memory—rewrite on every experience—is actively harmful.

- **Memory is meant to enable long-horizon deployment, but actually degrades with horizon length.** The promise of persistent memory is that agents improve over time as they accumulate experience. The paper shows the opposite: on ScienceWorld, utility peaks around step 20 and declines through step 100 for every memory size (Figure 1a); on WebShop, Agent Workflow Memory produces a 0.64 success rate at 8 examples that collapses to 0.20 at 128 examples—identical to the no-memory baseline (Figure 1b). The very mechanism designed to make agents scale with experience instead causes them to erode.

- **The pretraining-inference paradigm analogy is incomplete.** The field has invested heavily in making pretraining produce better base models, with relatively less attention to whether the inference-time mechanisms that build on those models are reliable. This paper establishes that the memory consolidation step—analogous to the cognitive process by which humans extract reusable schemas from experience (McClelland et al., 1995; Squire et al., 2015)—is currently unreliable in LLM agents. Just as scaling laws guided pretraining investment, evidence about consolidation failure modes should guide memory architecture investment.

### Conflicting Implicit Assumptions in Prior Work

The paper is motivated by a tension embedded in how different research communities approach memory. On one side, **cognitive science** has long understood that memory consolidation is a dual process: a fast episodic system stores individual experiences, while a slow consolidation process extracts compact schemas that integrate with prior knowledge (McClelland et al., 1995; Squire et al., 2015; Dudai et al., 2015; Moscovitch et al., 2016). Critically, cognitive theories also recognize that consolidation is *harmful when non-selective*: it causes interference and loss of specificity (McClelland et al., 1995; Sun et al., 2023), and whether it helps depends on metacognitive control—deciding which experiences belong together, how abstractly to rewrite them, and when to preserve distinctions rather than collapse them (Flavell, 1979; Nelson and Narens, 1990; Koriat, 1997).

On the other side, **contemporary agentic-memory systems** have implicitly collapsed this dual architecture into a single rewrite loop. They task the same LLM with both generating memory and monitoring its own abstraction quality, without metacognitive gating mechanisms that decide *when* to consolidate versus *when* to retain. The paper explicitly connects these two threads:

> "Agent-memory systems implement an explicit analogue, abstracting 'lessons' that are reused on later tasks while putting the same model in charge of both generating the memory and monitoring its own abstraction; the failure modes we observe (§6) are consistent with this control loop being unreliable in practice." (Section 2)

This is not merely a theoretical concern. Human metacognition is itself imperfect (Flavell, 1979; Nelson and Narens, 1990; Koriat, 1997), and in adjacent LLM settings, chain-of-thought explanations have been shown to diverge from the underlying computation (Turpin et al., 2023). Whether LLMs reliably monitor their self-generated abstractions is an open question—and the paper's empirical results suggest the answer is negative.

### Where Existing Approaches Fall Short

The paper identifies specific limitations in prior work along multiple axes:

**The episodic-trajectory baseline is missing from evaluation.** Prior work on agentic memory typically compares consolidated-memory agents against a no-memory baseline, but not against an episodic-only baseline that retains the same raw trajectories without abstracting them. This matters because, as the paper demonstrates, schema-like behavior can emerge from in-context learning on preserved instances comparably to a separately stored abstraction—an idea with deep roots in cognitive psychology (Hintzman, 1986; Brooks, 1978; Medin and Schaffer, 1978; Logan, 1988). In Table 2, the episodic-only control is competitive with ACE, AWM, and Dynamic Cheatsheet across AppWorld, ALFWorld, and WebShop. A memory method whose value depends on distillation should, the paper argues, be tested against the unabstracted rollouts it distills—and most prior work omitted this diagnostic.

**Update-after-every-interaction designs assume consolidation is neutral.** The paper identifies a common architectural pattern across CLIN, Agent Workflow Memory, Dynamic Cheatsheet, and ACE: each new experience triggers a consolidation step that rewrites some or all of the memory store. These designs treat each consolidation as at worst harmless. The paper's finding that memory utility is *non-monotonic* in updates (Figure 1a, Figure 1b, Figure 3) contradicts this assumption directly. Early abstractions can anchor later rewrites, and small errors in segmentation or abstraction compound into progressively distorted memories—a dynamic the field had not systematically studied.

**No controlled testbed for isolating abstraction failures from input noise.** Existing agent benchmarks (ALFWorld, ScienceWorld, WebShop) make it difficult to trace *why* a memory update hurt performance: was the input trajectory noisy, did the abstraction misgroup experiences, or did overgeneralization cause interference? The paper identifies this as a gap and addresses it with ARC-AGI Stream, a controlled testbed with three properties absent from prior benchmarks: (i) a fully specified latent task taxonomy enabling family-by-family tracing of memory actions and results, (ii) programmatic ground-truth solutions ensuring all input trajectories are correct by construction, and (iii) an exposed vocabulary of memory operations (Retain, Delete, Consolidate) that can be audited per step. These controls make abstraction errors attributable—if a model receives correct episodes from known families but later merges families, the failure lies in memory abstraction rather than in trajectory quality.

**The Complementary Learning Systems prescription is ignored in current architectures.** Cognitive theory prescribes that a fast episodic store and a slow schema-forming store be kept architecturally distinct so that fast learning does not overwrite the slow one (McClelland et al., 1995; Kumaran et al., 2016; Tse et al., 2007; Sun et al., 2023). Current agentic-memory systems collapse this separation into a single rewrite loop, recreating the interference conditions the dual-system design was meant to prevent (McCloskey and Cohen, 1989; French, 1999). The paper explicitly positions its ARC-AGI Stream experiments as a test of this gating prediction: by comparing Force (mandatory consolidation every round), Auto (agent chooses whether to retain raw or abstract), and Episodic Management Only (abstraction disabled entirely), the paper can measure whether the dual-store separation matters.

### How This Paper Positions Itself

The paper positions itself not as proposing a new consolidation method, but as **diagnosing a systematic failure mode in an entire paradigm**. This is explicitly stated in the Broader Impacts section:

> "Our findings are diagnostic: they identify a failure mode in a widely adopted paradigm for agent memory and suggest more conservative default designs that preserve raw evidence and gate abstraction."

Within this framing, the paper's contributions are empirical and conceptual rather than algorithmic:

**Empirically**, it provides the first systematic evidence that consolidated memory degrades with continued updates across multiple benchmarks, model families, and memory frameworks. The evidence is designed to isolate the consolidation step: by holding trajectories fixed while varying the consolidation schedule (Section 4.1: "The consolidation procedure itself shapes the rate of decline") and by comparing episodic-only controls against consolidators (Table 2), the paper traces the failure to the rewrite loop itself rather than to input quality.

**Conceptually**, it connects the observed failure modes to cognitive theories of memory consolidation, providing a vocabulary for understanding *why* LLM consolidation fails: misgrouping before abstraction (§6.1), interference from overgeneralized lessons (§6.2), and overfitting to narrow streams (§6.3). Each failure mode weakens the boundary between what should be generalized, what should remain task-specific, and what should be preserved as raw episodic evidence—boundaries that cognitive theories have long identified as requiring metacognitive control (Sun et al., 2023; Bartlett, 1932; Brainerd and Reyna, 2002).

**Architecturally**, it provides evidence for an alternative default: retain raw episodes as first-class evidence, gate abstraction explicitly rather than firing it after every interaction, and keep the episodic and abstraction-forming roles distinct rather than collapsing both into a single rewrite loop. This is not presented as a final solution—the paper explicitly notes that "episodic accumulation cannot be the long-term answer: as deployment continues, raw histories grow unboundedly and resist compositional reuse—compression and transfer ultimately require abstraction" (Section 1)—but as a more robust starting point that avoids the active harm caused by mandatory rewriting.

The paper also positions itself relative to a specific cognitive tradition. The Complementary Learning Systems framework (McClelland et al., 1995; Kumaran et al., 2016) provides the theoretical vocabulary: a fast episodic system (hippocampus-like) and a slow schema-forming system (neocortex-like) must be architecturally distinct, and consolidation should be gated by schema fit rather than triggered on every event. The paper's Force regime "collapses this separation into a mandatory rewrite loop, recreating the interference conditions the dual-system design was meant to prevent" (Section 5). This framing allows the paper to interpret its empirical results not merely as "LLMs make mistakes during consolidation" but as evidence that current architectures violate principles that cognitive science has identified as necessary for reliable memory formation.

## 3. Technical Approach

### 3.1 Reader Orientation

This is primarily an **empirical analysis paper** that systematically studies what happens when LLM agents repeatedly compress past trajectories into abstracted textual memory. The paper does not propose a new consolidation algorithm—instead, it builds a controlled experimental apparatus to measure, isolate, and diagnose failures in the dominant paradigm of continuously updated agentic memory. The core idea is that **current LLMs are not reliable memory consolidators**: each abstraction step is a lossy rewrite where useful details are dropped, spurious rules are introduced, and once-helpful abstractions drift away from the underlying task structure, and by holding trajectories fixed while varying the consolidation schedule and comparing against episodic-only baselines, the paper traces these failures to the consolidation step itself rather than to noisy input experiences.

### 3.2 Big-Picture Architecture (Diagram in Words)

The experimental apparatus has five major components, arranged as a pipeline that takes agent experiences as input and produces memory-conditioned task performance as output:

1. **Experience Collection** — produces raw trajectories (action–observation sequences) from agent interactions with environments. In most experiments, these are deliberately useful (ground-truth solutions, or trajectories from problems the agent solved without memory) to eliminate "garbage in, garbage out" as an explanation for memory failure.

2. **Trajectory Abstraction (Optional, Method-Dependent)** — converts raw trajectories into structured memory items. For ALFWorld/WebShop/AppWorld, this uses method-specific abstraction pipelines (CLIN's relation-phrase rules, AWM's workflow templates, Dynamic Cheatsheet's living document, ACE's bullet lists). For ARC-AGI Stream, the abstraction step is exposed as an explicit `Consolidate` action that the agent may choose to invoke or skip.

3. **Memory Management Regime** — governs how and when abstraction happens. Three regimes differ only in how trajectories are presented to the memory manager: **Static-All** abstracts from the entire trajectory pool in one pass (simulating offline batch construction); **Static-Group** abstracts each task type separately and concatenates (controls for grouping effects); **Stream** updates memory in batches as new experiences arrive (simulating continual learning). Stream further varies batch size, within-batch task composition (homogeneous vs. heterogeneous), and memory capacity (bounded vs. unbounded).

4. **Controlled Testbed: ARC-AGI Stream** — a synthetic environment built on ARCGEN (Moffitt, 2025) that combines three properties absent from existing benchmarks: (i) a fully specified latent task taxonomy with six families and seven skills, enabling family-by-family tracing of memory actions; (ii) programmatic ground-truth solutions so all input trajectories are correct by construction; (iii) an exposed, structured vocabulary of memory operations (`Retain`, `Delete`, `Consolidate`) whose use can be audited per step. The testbed maintains two stores following the Complementary Learning Systems prescription: an **Episodic buffer** of problem–solution pairs and an **Abstract store** of consolidated lessons.

5. **Evaluation Harness** — conditions a solver LLM on the current memory state (plus the task specification) and measures task success. For ARC-AGI Stream, the solver prompt bundles task examples, the current strategy memory, callable tool helpers, and the recent history buffer. For ALFWorld/ScienceWorld/WebShop, evaluation follows each method's standard protocol. The key diagnostic is comparing memory-conditioned performance against the no-memory baseline and against an episodic-only control that retains raw trajectories without abstracting them.

Information flows as follows: experiences are collected (1) → optionally abstracted into memory items (2) → the memory management regime determines when and how consolidation occurs (3) → the resulting memory store conditions the solver at evaluation time (5). The ARC-AGI Stream testbed (4) is the controlled environment where the abstraction process itself—rather than just its downstream accuracy—can be introspected, by exposing memory-management actions and tracing them against known task families.

### 3.3 Roadmap for the Deep Dive

- **First**, the experimental regimes (Static-All, Static-Group, Stream) and the memory management conditions (Force, Auto, Episodic Management Only), since how trajectories are presented to the consolidator is the independent variable whose effects the entire paper measures.
- **Second**, the ARC-AGI Stream testbed in full detail—its latent task taxonomy, its two-store architecture, its exposed memory operations, and its solver/consolidator prompt structure—since this is the primary diagnostic instrument that makes abstraction failures attributable and auditable.
- **Third**, the specific agentic-memory methods studied (CLIN, AWM, Dynamic Cheatsheet, ACE) and how their consolidation pipelines are instantiated for each benchmark, since the paper's claims are about a paradigm, not a single algorithm.
- **Fourth**, the trajectory-abstraction pipeline shared across ALFWorld/WebShop/AppWorld experiments (the SkillRL abstraction step that converts raw rollouts into structured memory items), since this is the shared substrate that different consolidation methods operate on.
- **Fifth**, the evaluation methodology—how memory-conditioned solvers are prompted, what metrics are used, and how episodic-only baselines are constructed—since the paper's central empirical claim is that consolidated memory underperforms unabstracted trajectories.

### 3.4 Detailed, Sentence-Based Technical Breakdown

This is primarily an **empirical analysis paper** whose core idea is that each consolidation pass is a lossy rewrite that compounds over updates, and that raw episodic trajectories should be treated as first-class evidence rather than disposable material to be compressed away.

---

#### The Experimental Regimes: How Trajectories Are Presented to the Consolidator

The paper studies three memory construction conditions that differ only in how trajectories are presented to the memory manager. These conditions are the primary independent variable: holding the trajectory pool fixed, the paper varies the consolidation schedule to isolate the effect of the rewrite process itself.

**Static-All.** The entire pool of trajectories is presented to the consolidator in a single call. The consolidator produces one memory store from all available evidence at once. This simulates offline, batch memory construction—the regime in which consolidation should perform best, since it has access to all evidence simultaneously and can avoid the anchoring effects of early partial abstractions. Static-All serves as an upper bound on what consolidation can achieve when unconstrained by streaming order.

**Static-Group.** Trajectories are first partitioned by task type (e.g., all `pick_and_place` trajectories together, all `pick_clean_then_place_in_recep` together), each partition is consolidated separately, and the resulting per-type memories are concatenated. This simulates a scenario where the agent correctly segments experiences by task family before abstracting—it controls for the misgrouping failure mode (§6.1) by providing ground-truth grouping. Static-Group serves as a diagnostic: if Static-Group outperforms Static-All, then cross-family interference during consolidation is a significant failure mode. For ALFWorld and ScienceWorld, the task types are the environment's built-in categories; for ARC-AGI Stream, task types are the six families in the latent taxonomy.

**Stream.** Trajectories arrive in batches over time, simulating an agent that encounters new experiences sequentially and updates its memory after each batch. The consolidator sees only the current batch plus the existing memory store; it cannot look ahead to future batches, and its earlier abstractions become the context for later rewrites. The paper varies three parameters within Stream:

- **Batch size** (`|B|`): the number of trajectories presented in each update. Larger batches give the consolidator more evidence per decision but fewer opportunities to refine. Table 4 reports batch sizes of 1 and 8 for ARC-AGI Stream; Figure 4 compares batch sizes 6 and 32 for ALFWorld.

- **Within-batch task composition:** **Homogeneous** batches contain trajectories from a single task type; **heterogeneous** batches mix trajectories from multiple task types. Heterogeneous batches are hypothesized to accelerate decline because the consolidator must segment experiences before abstracting, and mixed-type batches invite misgrouping (§6.1).

- **Memory capacity** (`|M|`): the maximum number of entries the memory store can hold. When the store is full, a FIFO (first-in-first-out) eviction policy removes the oldest entries. Figure 1a sweeps `|M|` = 16, 50, ∞ for ScienceWorld. Bounded capacity is the realistic setting for long-horizon deployment, since raw histories grow unboundedly.

**Why these three regimes.** Together they isolate the effect of consolidation order from the effect of consolidation content. Static-All and Static-Group use the identical trajectory pool and identical consolidator; any performance difference between them must be due to grouping (cross-family vs. within-family consolidation). Static-Group and Stream (with homogeneous batches) also use task-separated evidence; any performance difference must be due to the streaming order (one-shot vs. incremental). Stream with homogeneous vs. heterogeneous batches uses the same streaming order but varies batch composition; any performance difference must be due to within-batch task mixing. This nested design allows the paper to attribute performance variance to specific aspects of the consolidation schedule.

**Memory management conditions within ARC-AGI Stream (Force, Auto, Episodic Management Only).** These are the control loops that govern whether and when consolidation occurs, implemented on top of the Stream regime:

- **Force:** Consolidation is required at every round. After each batch of new trajectories, the agent must compress the current episodic buffer into the abstract store. No episodic entries persist between rounds—all evidence is distilled into abstracted memory, and the episodic buffer is cleared. This condition replicates the "update-after-every-interaction" design of CLIN, AWM, Dynamic Cheatsheet, and ACE, where each new experience triggers a rewrite that absorbs prior state.

- **Auto:** The agent chooses at each step among three actions—`Retain` a raw episode in the episodic buffer, `Delete` an existing entry from either store, or `Consolidate` buffered episodes into the abstract store. The episodic buffer persists across rounds, and the abstract store accumulates only when the agent elects to compress. This condition instantiates the gated-consolidation prescription from Complementary Learning Systems theory: abstraction is opt-in and triggered by the agent's assessment of whether episodes share structure, rather than forced on every trajectory.

- **Episodic Management Only:** Only `Retain` and `Delete` are available; `Consolidate` is disabled entirely. The agent maintains only an episodic buffer of raw problem–solution pairs, with no abstract store at all. This condition tests whether abstraction provides any benefit beyond what in-context learning from raw episodes can achieve. It serves as both a diagnostic (if Episodic Management Only matches or beats Auto, then the abstract store is not carrying the gain) and as a proposed conservative default (retention rather than compression).

The two trajectory regimes complete the design: **GT** (ground-truth trajectories are streamed, simulating training on demonstrations) and **Running** (the agent learns from its own solve attempts, successes and failures alike).

#### The ARC-AGI Stream Testbed: A Controlled Instrument for Memory Introspection

ARC-AGI Stream is the paper's primary diagnostic instrument. It is designed to make consolidation failures *visible and attributable*: given a known task taxonomy and programmatically correct input trajectories, any failure in the resulting memory can be traced to the abstraction process itself rather than to noisy inputs or unknown task structure.

**Latent task taxonomy.** The testbed's task generator decomposes each ARC-style problem along two orthogonal axes:

- **Family:** a rule that selects which subset of connected non-background objects in the input grid participates in the task's transformation. The six families are:
  - `detect_color_property`: selects objects of a target color (inferred from the examples) — an intrinsic per-object attribute.
  - `detect_largest_objects_select`: selects the largest object(s) by cell count (ties all selected) — intrinsic size extremum.
  - `detect_key_marker_rule`: an all-or-none global selection gated by the upper-left cell's color — a conditional cue.
  - `group_by_shape_then_select`: selects objects in the shape-frequency mode group — a cross-object relation.
  - `detect_inside_frame_relation`: selects objects strictly inside a hollow frame — a spatial containment relation.
  - `compose_horizontal`: selects the left or right sub-scene of a two-panel input — a cross-grid structural property.

- **Skill:** a fixed transformation applied uniformly to every object selected by the family. The seven skills are: `keep` (retain selected, erase rest), `border` (draw one-cell border), `recolor` (repaint in single new color), `translate` (shift by fixed offset), `flip_horizontal` (mirror within bounding box), `mark_center` (mark centroid cell), and `hollow` (erase interior, keep border).

The two axes are orthogonal: the same family can be paired with different skills, and the same skill can be paired with different families. This orthogonality means that the testbed can generate held-out tasks that test whether a memory entry captures the family's *selection rule* (transferring to a new skill) or the skill's *transformation* (transferring to a new family), enabling fine-grained diagnosis of what an abstracted memory entry has actually learned.

**Why this taxonomy matters.** In ALFWorld, ScienceWorld, and WebShop, there is no ground-truth mapping from task instances to underlying task families. If a consolidated memory performs poorly on an evaluation task, the experimenter cannot determine whether the failure is due to misgrouping (the consolidator merged episodes from different task types), overgeneralization (the consolidator stripped preconditions so a lesson fires on the wrong task), or input noise (the training trajectory was itself incorrect). ARC-AGI Stream eliminates input noise entirely (ground-truth solutions), provides a known task taxonomy for tracing grouping decisions, and generates held-out tasks that systematically vary family and skill to test for overgeneralization.

**The two-store architecture.** Following the Complementary Learning Systems framing (McClelland et al., 1995; Sun et al., 2023; Tse et al., 2007), the testbed maintains:

- An **Episodic buffer**: a bounded FIFO queue (`|Episodic|` = 50 or 100 in experiments) storing raw problem–solution pairs. Each entry contains one task's input–output example pair and the Python `solve` function that passed all evaluation examples for that task. The buffer does not abstract; it preserves exactly the evidence that was observed.

- An **Abstract store**: an unbounded list of consolidated strategy entries. Each entry is a natural-language description with two fields: `when_to_use` (visual/task patterns that should trigger this memory) and `solve_strategy` (step-by-step reusable procedure). The abstract store is the product of the `Consolidate` action: the consolidator reads selected entries from the episodic buffer, plus any existing abstract entries, and produces a replacement strategy memory.

Both stores are available to condition the solver at evaluation time. The key experimental manipulation is *which* store(s) the solver sees: `Auto + Episodic` uses both, `Episodic Only` uses only the buffer, `Abstract Only` uses only the consolidated store, and `No Memory` uses neither. By comparing these conditions, the paper can isolate whether performance gains come from raw episodes, from abstracted lessons, or from their combination (Appendix K.1, Figure 17).

**Exposed memory operations.** At each step, the agent (the same LLM that serves as solver) issues one of three meta-level actions on the current memory state:

- **Retain:** Append the current task's raw trajectory (input–output pair + solver code) to the episodic buffer. If the buffer is at capacity, the oldest entry is evicted.

- **Delete:** Remove one or more entries from the episodic buffer or abstract store by index. This allows the agent to prune entries it judges to be outdated, redundant, or harmful.

- **Consolidate:** Select a subset of entries from the episodic buffer (by 1-based index) and distill them into one or more abstract strategy entries. The selected episodic entries are *consumed*—their information moves into the abstract store, and they are removed from the buffer. The consolidator receives the current strategy buffer (existing abstract entries) and the selected episodic entries, and returns a **full replacement strategy buffer** as a JSON list. Existing abstract entries not referenced in the output are dropped.

The exposed action vocabulary is critical for the paper's diagnostic goals. By logging every `Consolidate` action and its selected episodic indices, the experimenter can trace which task families the consolidator chose to compress together—and, by comparing against the known task taxonomy, can measure **misclassification count**: the number of `Consolidate` actions that combine episodes from two or more distinct problem families (Figure 7a). Similarly, by logging the abstract store after each step and comparing its entries against the task taxonomy, the experimenter can measure **family coverage**: how many of the six families are represented in the abstract store at each step (Table 4).

**The consolidator decision prompt (Appendix B.3).** After the solver's response is graded as passing, the consolidator decision prompt is issued. It presents:

1. The current history buffer (up to capacity, with carryover entries from previous steps and the new entry from the current step). Each history entry contains one task's input–output example pair and the Python solve code that passed.
2. The current strategy memory (abstract store), with each entry's `when_to_use` and `solve_strategy` fields.
3. The action space: `Keep` (leave both stores unchanged), `Remove` (drop specified history entries by index), or `Strategy extraction` (consolidate specified history entries into abstract memory; selected entries are consumed).

The model returns a JSON object with `action`, `reason`, and (for `Remove` or `Strategy extraction`) `fn_indices` listing which history entries to operate on. The model must select at least 2 indices for `Strategy extraction` when entries share a plan, enforcing that consolidation only fires when the agent judges that episodes have common structure.

**The consolidator extraction prompt (Appendix B.4).** When the decision is `Strategy extraction`, a second prompt is issued to actually produce the replacement strategy buffer. This prompt receives:

1. The current strategy buffer (existing abstract entries, with 1-based indices).
2. The selected episodic entries (the `fn_indices` from the decision step), each with its input–output example and solve code.
3. Instructions to produce a **full replacement strategy buffer** as a JSON list, where each entry is one of three kinds:
   - `Retain`: reference existing entries by index (`"from_existing": [i, j, ...]`). Each referenced index becomes its own kept-as-is entry. Multiple indices in one `Retain` entry mean "keep all of them as separate entries."
   - `New`: distill from selected episodic entries (`"from_functions": [k1, k2, ...]`). Must have both `when_to_use` and `solve_strategy` text fields.
   - `Merge`: combine existing entries (`"from_existing"`) with new episodic evidence (`"from_functions"`) into a single cleaner entry. Must have both text fields and at least one non-empty index array.

Existing indices not referenced anywhere in the output are **dropped** from the new buffer. This forces the consolidator to explicitly decide which prior abstractions to preserve: abstaining from referencing an index is equivalent to deleting it. The model may output an empty list to drop everything.

**Content rules for new and merged entries.** The extraction prompt specifies several constraints that operationalize the paper's concern with abstraction quality:

- The `when_to_use` field must describe "observable cues: output size, object movement, color changes, cropping, symmetry, counting, markers, repeated patterns" — forcing the consolidator to ground the trigger in test-time-verifiable features.
- The `solve_strategy` field must be "detailed enough that another model could apply it to a new ARC task" — preventing vacuous abstractions (§D.1).
- Task-specific colors must be replaced with semantic roles ("background color, target color, marker color, object color, fill color") — preventing the concrete-vocabulary erosion failure mode (§D.2).
- Task-specific coordinates are forbidden unless they express a reusable relation ("top-left, center, border, same row") — preventing overspecification to instance-level details.
- Multiple input tasks may collapse into one entry "when they share an algorithmic plan" — this is the grouping operation whose correctness is measured by the misclassification count.
- The output must contain at most N entries (the number of existing abstract entries plus the number of selected episodic entries), and the model should "merge near-duplicates rather than listing them separately" — preventing the paraphrase-cluster erosion mode (§G.1).

**The solver prompt (Appendix B.1).** At each step, the solver receives:

1. The current task's input–output examples (typically 2–10 grid pairs in the standard ARC format).
2. The current strategy memory (abstract store entries, each with `when_to_use` and `solve_strategy`).
3. A **Tool Buffer** of eight callable Python helpers (`extract_objects`, `apply_recolor`, `apply_translate`, `apply_flip_horizontal`, `apply_border`, `apply_hollow`, `apply_mark_center`, `apply_op_per_object`). The solver may call these helpers but must not redefine them. The helpers are drawn directly from the ground-truth implementation of the seven skills, ensuring the solver has access to the primitives needed to express any correct solution in the taxonomy.
4. A **History Buffer** of previous task trajectories (input–output pairs + solve code), serving as in-context demonstrations. This is the episodic-store contribution: when the episodic buffer persists (Auto and Episodic Management Only modes), the history buffer carries forward raw evidence from earlier tasks.

The solver is instructed: "Reason briefly from the examples, then write the simplest correct `solve`. Do not output long chain-of-thought or extra prose." The response is parsed for the first Markdown-fenced Python block, which is executed against the evaluation examples. A task passes only if the solver's code produces the correct output for all provided examples.

**Failure recording (Appendix B.5).** In some experimental conditions, failed solve attempts are also recorded in the history buffer. Failed entries carry a Python-comment banner that prepends the solve code with one input/output triple from the failure: the input on which the candidate failed, the expected output, and what the candidate produced. Because the banner is comment-only, it is valid Python inside the same code fence the solver prompt's history block already uses. This mechanism enables the experiment in §D.4, where exposing the consolidator to failure traces caused it to distill recurring patterns from *failed* code into new abstract entries ("phantom strategies from failed attempts").

**Strategy selection variant (Appendix B.7).** An alternative solver invocation decomposes the call into a selection step followed by a synthesis step. The selection prompt provides the task examples (half of the full set), the current strategy memory, and the tool buffer, and asks the model to pick one existing strategy by index. The selected strategy text is then injected into the synthesis prompt's memory block in place of the full memory listing. This variant tests whether retrieval—picking the right abstract entry for the current task—is itself a point of failure, separate from the quality of the stored entries.

#### Agentic-Memory Methods Studied

The paper studies four representative methods that share the paradigm of distilling procedural knowledge from past trajectories into textual memory. For each, the paper follows the original method's design as closely as possible while adapting it to the paper's experimental framework.

**CLIN (Majumder et al., 2023).** CLIN abstracts individual trajectories into natural-language rules using a constrained format: each memory entry is a unified rule using one of a small set of relation phrases: `MAY BE NECCESSARY to`, `SHOULD BE NECCESSARY to`, `MAY BE CONTRIBUTE to`, and `DOES NOT CONTRIBUTE to`. Each rollout is presented together with an evaluation report indicating success or failure.

The paper introduces several modifications to the original CLIN update procedure to enable the long-horizon consolidation experiments on ScienceWorld:

- **Bounded memory bank with explicit capacity instruction:** The LLM is informed of the maximum memory bank size and the FIFO replacement policy. This is necessary for studying whether memory degradation occurs within a bounded store—without a cap, the store could grow unboundedly, masking erosion in per-entry quality with growth in entry count.

- **Extended memory-bank operations:** Beyond the original CLIN's add-only behavior, the paper allows `delete` (remove entries by ID), `replace` (remove specified entries and insert new ones), `add` (insert new entries without removing existing ones), and `retain` (keep a buffered rollout as a concrete case record in memory rather than abstracting it). The `retain` operation is the paper's key addition: it allows the agent to preserve raw evidence rather than forcing it through abstraction, directly testing whether the episodic-vs-abstract distinction matters.

- **Mini-batch consolidation:** Instead of feeding rollouts one at a time, the LLM processes a mini-batch of `k` rollouts together (configured batch size `k = pool_batch_size`). The prompt instructs: "Compare the rollout summaries jointly before editing the MEMORY BANK. If several rollouts support the same general lesson, prefer a single compact memory that captures the shared pattern rather than duplicating near-identical memories. If the rollouts disagree, preserve only the parts that are clearly supported by the evidence." This forces the model to perform the segmentation step (deciding which episodes belong together) explicitly rather than implicitly across separate update calls.

- **Multi-round evaluation:** After each full pass over all rollouts for a given number of consolidation rounds, the current memory bank is evaluated on a fixed ScienceWorld test set (44 cases sampled from the same 15 tasks, with 2–4 cases per task depending on available variants). This produces the utility-vs-updates curves in Figures 1a and 10.

The ScienceWorld experiments use 15 medium-difficulty tasks (Table 9), each with an average optimal action sequence length between 20 and 100, totaling 485 rollout cases. Tasks include boiling, freezing, melting, paint-mixing, plant-growth, conductivity-testing, and life-stage identification.

**Agent Workflow Memory (AWM; Wang et al., 2024).** AWM abstracts trajectories into workflow templates, each pairing a thought rationale with an action sequence. The WebShop experiments (Section H.1.2, Appendix I.1) use 128 golden trajectories (all reward 1.0) sampled from the AgentGym AgentTraj-L corpus, consolidated by `gpt-5.4-mini` with batch size 16 over 3 epochs. Each workflow template uses placeholder variables (`<headline_category>`, `<required_color>`, `<candidate_item_id>`, etc.) meant to be bound at execution time.

The paper's AWM experiments on WebShop are configured to expose a specific failure mode: the consolidated workflow file at epoch 1 contains 8 workflows (W1–W8), one of which (W8) prescribes a page-turning loop (`click[Next >]`) with no stop criterion and no concrete candidate selection step (the `<candidate_item_id>` placeholder is never bound to a real product). The memory surgery ablation (Appendix I.1) removes W8 and shows that doing so improves the win rate (from 7/50 to 14/50 for `gpt-5.4-mini`), reduces page-turn actions by a factor of 2.3, and increases the count of episodes that issue `click[Buy Now]`. This isolates one workflow's causal contribution to overall agent failure.

**Dynamic Cheatsheet (DC; Suzgun et al., 2026).** DC maintains a single living document that is rewritten after every trajectory. Each entry is a `<memory_item>` with a `<description>`, `<example>` (action template with placeholders), and a `Count` field tracking how many trajectories contributed to the rule. The WebShop experiments (Appendix H.1.1) show a healthy mid-run snapshot at stage 100, organized under an `Action patterns and interaction sequences` heading with concrete templates for apparel, color, and size verification.

**ACE (Zhang et al., 2025).** ACE maintains a flat list of bullet items grouped into named sections (e.g., "Common mistakes to avoid," "Problem-solving heuristics"). The consolidation pipeline involves three roles: a *reflector* emits bullet candidates from each trajectory, a *curator* decides which are added or modified in the running memory, and an *analyzer* merges any pair of items whose embedding similarity exceeds a deduplication threshold (0.75 in the paper's experiments). The AppWorld, WebShop, and ALFWorld experiments use ACE with `gpt-5.4-mini` as both reflector and curator.

**The SkillRL abstraction pipeline (shared across methods).** For ALFWorld, WebShop, and AppWorld, raw trajectories are first converted into structured memory items via a shared abstraction step before being fed to the method-specific consolidator. This pipeline uses `gpt-5.4` (for ALFWorld) or `gpt-5.4-mini` (for WebShop and AppWorld) as the abstraction model, making 3 LLM calls per trajectory to produce one item with three fields: `contextual_description`, `refined_trajectory`, and `strategic_guidelines`. The abstraction step is method-agnostic—it produces a uniform structured representation that CLIN, AWM, DC, or ACE can then further consolidate according to their respective update rules.

#### Trajectory Data Sources and Composition

The paper deliberately constructs trajectory pools that are *demonstrably useful* to isolate consolidation failures from input-quality failures.

**ALFWorld (Appendix F.1).** Three trajectory variants are used:

- `n=64 golden`: 64 success-only trajectories per task type (384 total), generated by `gpt-4.1`, filtered to reward = 1.0.
- `n=128 golden`: 128 success-only trajectories per task type (768 total), generated by `gpt-4.1`, reward = 1.0 only.
- `n=64 with_failures`: 64 mixed-success trajectories per task type (384 total), generated by `gpt-5-nano`, no filtering—contains both successes and failures. Used for probes that test consolidation behavior under imperfect inputs.

After collection, every trajectory is abstracted via the SkillRL pipeline (3 `gpt-5.4` calls per trajectory) into `{contextual_description, refined_trajectory, strategic_guidelines}`. The six task types are: `pick_and_place`, `pick_clean_then_place_in_recep`, `pick_two_obj_and_place`, `look_at_obj_in_light`, `pick_cool_then_place_in_recep`, `pick_heat_then_place_in_recep`.

The two-task-type probe set (for the interference experiment in §6.2, Figure 8c) pairs `pick_and_place` (focal) with `pick_clean_then_place_in_recep` (probe). The base memory is a single-type consolidation fixing the per-stage task type to `pick_and_place`, sampling 32 abstracts per stage from the `n=64` pool, with snapshots taken at consolidation stage S ∈ {1, 20, 50, 100}. From each snapshot, one additional consolidation iteration with 32 abstracts from the probe task type is run, and the performance drop is measured.

**WebShop (Appendix F.2).** Two trajectory variants are used:

- `golden 128`: 128 trajectories (seed 42) from the AgentGym AgentTraj-L corpus, filtered to score = 1.0 (perfect-reward demonstrations only). Session IDs span 72–6772 (sparse, 128 distinct IDs). This is the training set for the AWM workflow ablation (Appendix I.1).

- `non-golden 128`: 128 trajectories generated by `gpt-5.4-mini` directly, with no reward filtering. Session IDs span 1500–1627 (contiguous, disjoint from the test pool [0, 500)). Only 20/128 trajectories have score = 1.0. This set tests how memory consolidation behaves when training trajectories are imperfect (mixed success/failure), contrasting with the golden set where all inputs are expert demonstrations.

Raw trajectories are replayed through the paper's WebShop environment instance (`num_products=1000`) to obtain matching observation–action sequences, then abstracted via the same SkillRL pipeline as ALFWorld.

**ScienceWorld (Appendix F.3).** Trajectories are collected from the 15 medium-difficulty tasks listed in Table 9 (485 total rollout cases). Each rollout is presented with an evaluation report (success/failure feedback). The CLIN-style constrained memory format is used: each memory entry is a unified natural-language rule using the relation phrases `MAY BE NECESSARY to`, `SHOULD BE NECESSARY to`, `MAY BE CONTRIBUTE to`, and `DOES NOT CONTRIBUTE to`.

**AppWorld (Appendix F.4).** Combined training set of 140 trajectories: 90 from AppWorld's official train split (generated by `gpt-4o-2024-05-13` via the ReAct baseline) and 50 from the dev split (generated by `Qwen3.5-27B` on a stratified-by-difficulty sample). Mean Task Goal Completion (TGC) over the combined set is 61.4% (86/140). For methods requiring gold-quality input, a parallel set of 140 ground-truth trajectories is collected by replaying AppWorld's released ground-truth solutions through the environment API. Each training datapoint consists of a task identifier, a final pass/fail outcome, and a `Qwen3.5-27B`–generated prose summary of the full ReAct trajectory (thoughts, actions, and observations of all steps), used in place of the raw token-level trajectory to keep per-entry length tractable for prompt-time concatenation.

**ARC-AGI Stream (Section 3, Appendix A).** Tasks are generated programmatically from the 6-family × 7-skill taxonomy, with ground-truth Python solver code produced by composing family-selection logic with skill-transformation primitives. The GT trajectory regime streams ground-truth solutions to simulate training on demonstrations; the Running regime has the agent learn from its own solve attempts. The number of tasks, the family–skill distribution, and the evaluation protocol vary by experiment (e.g., the 19-problem slice in Figure 2 is a fixed pool of 19 tasks spanning all 6 families; the 250-task stream in Example 2 of §D.5 spans all families with one-at-a-time presentation; the 400-step Running experiment in Figure 5 evaluates cumulative success over 400 training steps).

#### The Episodic-Only Baseline: Design and Rationale

A central methodological contribution of the paper is the **episodic-only baseline**: a memory condition that retains raw trajectory logs without abstracting them, and conditions the solver on these raw episodes as in-context demonstrations. This baseline is constructed differently across benchmarks but follows a consistent principle.

**In WebShop, ALFWorld, and AppWorld (Table 2).** The episodic-only baseline stores the same experience that ACE, AWM, and Dynamic Cheatsheet are asked to compress. All memory entries—whether raw trajectories or consolidated abstractions—are placed in context at evaluation time. The trajectory baseline has several variants:

- **All:** the full pool of raw trajectories is appended to the solver's context.
- **FS=N:** a fixed-size subset of N trajectories is randomly sampled (FS=64, 32, 16). This controls for context-length effects: if consolidated memory outperforms raw trajectories only when the raw trajectories are truncated, then the advantage is due to compression saving context space, not to abstraction adding value.
- **Incr. Keep:** the LLM itself curates which trajectories to retain vs. delete, in a streaming fashion (the model sees trajectories sequentially and decides which to keep in a bounded buffer). This is analogous to the Auto mode in ARC-AGI Stream: the agent exercises metacognitive control over which raw episodes to preserve, without abstracting them.
- **One-Pass Keep:** the LLM curates the full pool in a single pass, selecting which to retain. This is the Static-All analogue for episodic-only memory.

**In ARC-AGI Stream.** The episodic-only baseline is the `Episodic Management Only` condition: the agent may `Retain` or `Delete` raw episodes but may never `Consolidate`. The solver is conditioned on the episodic buffer's contents. The `Episodic Only` ablation (Appendix K.1, Figure 17) restricts the solver to reading *only* the episodic buffer, excluding the abstract store entirely, to measure the episodic store's standalone contribution.

**Why this baseline is diagnostically essential.** If a memory method whose value depends on distillation cannot outperform unabstracted rollouts, then the abstraction step is not adding value—it is at best neutral and at worst harmful. The paper demonstrates that, across multiple benchmarks and model backbones, abstracted memory often cannot significantly outperform direct in-context learning from trajectory logs (Table 2, Table 3). In AppWorld, the `All` trajectory baseline achieves TGC of 73% (Qwen3.5-27B), while ACE achieves 65% and AWM achieves 68%—neither beats the unabstracted baseline. In ALFWorld, the `All` baseline reaches 90% task success (GPT-5.4-Mini), while ACE achieves 79%, AWM 65%, and DC 58%—all below the episodic-only store. These results suggest that "the evidence available before abstraction already contains task-relevant signal that the solver can exploit directly" (Section 4.2), and that schema-like behavior can emerge from in-context learning on preserved instances comparably to a separately stored abstraction.

#### The Memory Erosion Curve: Definition and Measurement

The paper's central empirical finding is a specific shape: abstracted memory utility is **non-monotonic** in the number of consolidation updates. The paper defines and measures this curve in two settings.

**ScienceWorld with CLIN (Figure 1a).** The x-axis is the number of consolidation steps (`#Steps`), where each step processes a mini-batch of 4 trajectories. The y-axis is utility (operationalized as test score on the fixed 44-case evaluation set). Three curves are shown for different memory capacities (`|M|` = 16, 50, ∞). The qualitative pattern is consistent across capacities: utility rises early (as initial abstractions capture useful patterns) and then declines through step 100. At `|M|` = 16, the decline brings utility below the no-memory baseline; at `|M|` = ∞, the unbounded store allows the agent to accumulate entries without eviction, but the curve still declines, demonstrating that per-entry *quality* degrades even when per-entry *quantity* grows.

**WebShop with AWM (Figure 1b).** The x-axis is the number of training examples (`# Examples`, in powers of 2 from 8 to 128). The y-axis is success rate on the 50-session held-out evaluation split. AWM goes from a success rate of approximately 0.64 at 8 examples to approximately 0.20 at 128 examples, while the no-memory baseline sits at approximately 0.20 and the raw-trajectory baseline rises steadily. The parenthesized value next to each marker is the mean reward (a separate WebShop metric): the same decline is visible. The "Raw − AWM gap" annotation measures the vertical distance between the raw-trajectory curve and the AWM curve—it widens with scale, showing that more training data makes the consolidated memory *relatively worse* compared to simply retaining the raw trajectories.

**What the erosion curve measures.** The erosion curve is not a learning curve in the standard sense. The model is not being trained (no parameter updates occur). The erosion curve measures the **cumulative effect of lossy rewrites**: each consolidation step takes the existing memory store plus a batch of new trajectories and produces a rewritten store. Small errors in segmentation (merging episodes from different task types), abstraction (stripping preconditions), or overfitting (encoding surface patterns from the batch) accumulate, and because the rewritten store becomes the input to the next rewrite, these errors compound. The curve rises early because the initial abstractions capture genuinely useful patterns that outweigh the errors; it declines later because the accumulated errors degrade the store faster than new evidence can repair it.

#### Summary of Design Choices and Their Justifications

- **Ground-truth or self-solved trajectories as input, rather than arbitrary rollouts:** eliminates "garbage in, garbage out" as an explanation for memory failure. If the agent regresses on tasks it previously solved without memory after consolidating from ground-truth solutions (Figure 2), the failure must be in the consolidation step.

- **Three consolidation regimes (Static-All, Static-Group, Stream) varying only presentation order, holding trajectory pool fixed:** isolates the effect of consolidation schedule from consolidation content. Any performance difference between Static-Group and Stream with homogeneous batches must be due to one-shot vs. incremental presentation.

- **Two-store architecture with exposed memory operations (ARC-AGI Stream):** makes abstraction failures attributable and auditable. Misclassification count, family coverage, and buffer composition (Figure 6, Figure 7a) can be measured directly from action logs, rather than inferred from downstream accuracy.

- **Episodic-only control consuming the same trajectories as the consolidator:** a diagnostic baseline that the paper argues should be standard for any memory method whose value depends on distillation. If unabstracted rollouts are competitive, abstraction is not adding value.

- **Force vs. Auto vs. Episodic Management Only control loops:** directly test the Complementary Learning Systems prediction that gated consolidation outperforms mandatory rewriting. The Force regime collapses episodic and abstract stores into a single rewrite loop; the Auto regime keeps them architecturally distinct.

- **Multiple model backbones (GPT-5.4 family, Qwen3.5 family, Claude-Haiku-4.5) and multiple consolidation methods (CLIN, AWM, DC, ACE) across five benchmarks:** ensures findings are not specific to one model–method–environment combination. The consistency of the erosion pattern across these axes is the paper's central empirical claim.

- **Memory surgery ablation (Appendix I.1):** isolates the causal contribution of individual memory items by removing one entry and re-evaluating. The W8 ablation demonstrates that a single workflow can measurably degrade agent performance, providing a concrete mechanism for the aggregate erosion curves.

- **Offline trajectory abstraction (SkillRL pipeline) before method-specific consolidation:** standardizes the input representation across ACE, AWM, DC, and CLIN, ensuring fair comparison—all methods operate on the same structured memory items, and performance differences are due to consolidation strategy rather than input format.

## 4. Key Insights and Innovations

### Innovation 1: Consolidation Is Not Neutral — The Foundational Assumption of Agentic Memory Is Wrong

The paper's most fundamental contribution is not any single failure mode but the **empirical refutation of a premise that underlies an entire research paradigm**: the assumption that consolidating experiences into textual abstractions is at worst harmless. Prior agentic-memory systems—CLIN (Majumder et al., 2023), Agent Workflow Memory (Wang et al., 2024), Dynamic Cheatsheet (Suzgun et al., 2026), ACE (Zhang et al., 2025)—all adopt update-after-every-interaction designs that treat each consolidation step as either beneficial or neutral. The paper demonstrates that this premise is false: each consolidation is a lossy rewrite where useful details are dropped, spurious rules are introduced, and once-helpful abstractions drift away from the underlying task structure. This is not a matter of insufficiently sophisticated consolidation algorithms—it happens even when the input trajectories are ground-truth solutions.

What makes this insight intellectually distinctive rather than merely empirical is its **attributional clarity**. The paper constructs conditions where the only variable is the consolidation schedule: the trajectory pool is held fixed across Static-All, Static-Group, and Stream regimes (Section 4.1). The fact that consolidation order and grouping produce qualitatively different end states from identical evidence (Figure 3: Static-Group beats Static-All by 17–38 percentage points across model sizes; Stream underperforms Static-All substantially) demonstrates that the *process of consolidation itself*—not input quality—determines memory quality. The cleanest demonstration is Figure 2: GPT-5.4 solves a 19-problem ARC-AGI slice at 100% accuracy without memory; after consolidating from *ground-truth solutions to those very problems* in streaming order, it fails on 46% of them. The trajectories are correct by construction, yet the memory produced from them is harmful. This isolates the consolidation mechanism as the failure point with an unusual degree of rigor.

Prior work had no reason to suspect this. The dominant framing was that memory consolidation succeeds or fails based on experience quality: if the agent explores poorly or receives noisy rewards, the learned abstractions will be poor. The paper eliminates this explanation by construction—golden trajectories, ground-truth solutions, problems the agent already solved—and still observes degradation. This shifts the burden of proof: the default assumption going forward should be that consolidation is potentially harmful, and architectures must include mechanisms (episodic gating, abstention from rewriting, dual-store separation) that prevent active degradation rather than merely improving abstraction quality.

This is a **fundamental reframing**, not an incremental refinement. The paper changes the question from "how do we extract better abstractions from experience?" to "should we be abstracting at all right now, and if so, under what conditions?" It is analogous to the shift in RLHF when reward hacking was recognized not as a training bug to be fixed with better algorithms but as a fundamental property of optimizing against learned reward models. Here, consolidation-induced regression is recognized not as an implementation detail to be improved with better prompts but as a property of lossy rewriting by current LLMs.

---

### Innovation 2: The Episodic Baseline as a Diagnostic Instrument

A second conceptual contribution is the introduction of a **diagnostic baseline that the field had systematically omitted**: comparing consolidated memory against the raw, unabstracted trajectories it was built from. Prior agentic-memory work compared consolidated-memory agents against a no-memory baseline (showing that memory helps) but typically did not compare against simply retaining the raw trajectories and using them as in-context demonstrations. The paper demonstrates that this omitted baseline is often competitive—and sometimes strictly better—than consolidated memory (Table 2, Table 3).

What makes this more than a methodological suggestion is its **theoretical grounding**. The paper connects the episodic-only baseline to a long tradition in cognitive psychology: instance-based theories of categorization and skill acquisition (Hintzman, 1986; Brooks, 1978; Medin and Schaffer, 1978; Logan, 1988) predict that schema-like behavior can emerge from in-context learning on preserved instances without requiring explicit abstraction. The paper provides empirical evidence that this prediction holds for LLM agents: across AppWorld, ALFWorld, and WebShop, raw trajectory logs at evaluation time often match or exceed the abstractions they were distilled into. In AppWorld with Qwen3.5-27B, the `All` trajectory baseline achieves 73% TGC versus 65% for ACE and 68% for AWM. In ALFWorld with GPT-5.4-Mini, trajectory logs reach 90% task success versus 79% for ACE, 65% for AWM, and 58% for DC. The red `(–)` marks in Table 2 flag every consolidated method that is beaten by at least one trajectory-log variant—and there are many red entries.

The diagnostic value of this baseline is that it **reverses the burden of proof**. A memory method whose claimed value depends on distillation should be tested against the unabstracted rollouts it distills. If it cannot outperform them, consolidation is at best neutral and at worst harmful. The paper's recommendation (Section 4.2) that "a memory method whose value depends on distillation should be tested against the unabstracted rollouts it distills" has implications for how the field evaluates future memory systems. It is not enough to beat the no-memory baseline; you must beat the raw-experience baseline.

This is a **methodological innovation** with conceptual weight. It is not merely "add another baseline to your evaluation suite"—it is the empirical instantiation of a theoretical claim: that the LLM-as-solver already performs an implicit form of abstraction through in-context learning, and that explicit textual abstraction may be redundant with (or worse than) this implicit process. If this finding generalizes, it suggests that the entire "distill into lessons" paradigm may be solving a problem that in-context learning already addresses, while introducing new failure modes (misgrouping, overgeneralization, overfitting) that in-context learning avoids by preserving raw evidence.

---

### Innovation 3: The Complementary Learning Systems (CLS) Diagnosis — Not Just That Consolidation Fails, But Why It Must

The paper's third distinctive contribution is the **theoretical diagnosis** that connects the observed failure modes to a specific architectural principle from cognitive science: the Complementary Learning Systems framework (McClelland et al., 1995; Kumaran et al., 2016; Sun et al., 2023). This is not merely a citation of prior theory—it is an active reinterpretation of why current architectures fail.

The CLS framework prescribes that a fast episodic system (hippocampus-like) and a slow schema-forming system (neocortex-like) must be **architecturally distinct** so that fast learning does not overwrite the slow one, and consolidation should be gated by schema fit rather than triggered on every event (Tse et al., 2007). The paper's diagnosis is that current agentic-memory systems violate both principles: they collapse the two stores into a single rewrite loop, and they trigger consolidation on every interaction without gating. The paper's Force regime "collapses this separation into a mandatory rewrite loop, recreating the interference conditions the dual-system design was meant to prevent" (Section 5), directly citing McCloskey and Cohen (1989) and French (1999) on catastrophic interference.

What makes this more than post-hoc theorizing is that the paper's ARC-AGI Stream experiments **instantiate the CLS prescription as testable conditions** and show that it matters. The three control loops—Force (mandatory consolidation, no episodic persistence), Auto (gated consolidation, episodic persistence), and Episodic Management Only (no consolidation at all)—directly test whether architectural separation and consolidation gating improve outcomes. The results confirm the CLS prediction: Auto and Episodic Management Only consistently match or beat Force (Figure 5, Figure 9a). On the GT-400 stream, Auto with a 100-entry episodic buffer achieves 62% cumulative success versus 54% for Force (Figure 9b). The component ablation (Appendix K.1, Figure 17) further shows that the episodic store carries nearly all the gain: restricting the solver to the abstract store alone reduces performance to the no-memory baseline, while restricting to the episodic store alone recovers most of the Auto-mode benefit.

The significance of this diagnosis extends beyond the paper's empirical results. It provides a **principled vocabulary for designing memory architectures**: what cognitive science identifies as necessary for reliable consolidation (separate stores, gated abstraction, preserved evidence) is precisely what current systems lack. It also predicts that the failure modes will persist as long as the architectural violation persists—improving the consolidation prompt or the base LLM may shift the erosion curve but will not eliminate it, because the fundamental problem is the collapsed-loop design, not the quality of any individual abstraction. This is a **conceptual advance** that reframes the problem space: the question is not how to build a better consolidator but how to build an architecture where consolidation is optional, reversible, and grounded in recoverable evidence.

---

### Innovation 4: The Failure-Mode Taxonomy as a Diagnostic Language

The paper's fourth contribution is the **articulation of a taxonomy of consolidation failure modes** that provides a shared vocabulary for diagnosing and comparing memory systems. The taxonomy—misgrouping before abstraction (§6.1), interference from overgeneralized lessons (§6.2), and overfitting to narrow streams (§6.3)—is not merely a list of things that can go wrong but a **structural decomposition** of the consolidation process into separable sub-problems, each of which can be measured and addressed independently.

**Misgrouping** is the failure to correctly segment experiences before abstracting them: the consolidator pools episodes that do not share underlying structure and then produces a "lesson" that merges incompatible procedures. On ARC-AGI Stream, Figure 7a quantifies this directly as the *misclassification count*—the number of Consolidate actions that combine episodes from two or more distinct problem families. Under Force (batch size 8), the model misclassifies 74 times over 400 steps. The qualitative case studies in §D.3 (foreign-family injection) and §D.5 (single-strategy collapse on multi-family compression) show what the resulting memories look like: an inside-frame strategy entry that includes a cross-frame shape-signature lookup from an unrelated family, or a memory that collapses all six families into a single inside-frame-plus-hollow playbook.

**Interference** is the failure to preserve applicability conditions during abstraction: lessons that were correct in their original context are stripped of preconditions and fire in contexts where they are harmful. Figure 8b demonstrates switch-induced forgetting: a single task switch overwrites 40% (GPT-5-mini) of previously learned accuracy. Figure 8c shows that more distillations on one task increasingly interfere with performance on a related-but-different task: after 100 distillations, conjugate-task accuracy drops by 48.2 points for Qwen3.5-27B. The Fresh-vs-Cumulative comparison in Figure 10 provides the cleanest demonstration: consolidating jointly over tasks 1…t (Cumulative) ends 203 points behind consolidating only on task t (Fresh), and Cumulative accumulates overgeneralized memories at roughly 5× and garbage memories at roughly 20× the rate of Fresh (Appendix K.2, Figure 18).

**Overfitting** is the failure to abstract at the right level: when the input stream is narrow, the consolidator encodes surface regularities of the observed instances rather than the underlying strategy. Figure 11 shows that after repeated consolidation on a single strategy family, performance remains stable on exact repetitions (in-distribution) but collapses on simple variations within the same family (out-of-distribution). The concrete-vocabulary erosion example (§D.2) traces a memory entry through 50 rewrites: it goes from "identify and extract structured elements from input → compute a global metric (e.g., max size)" to "Find the maximum value of a derived per-object numeric attribute"—the concrete feature that the task actually selects on (size) has been abstracted away entirely.

What makes this taxonomy a contribution rather than a description is its **diagnostic decomposability**. Each failure mode has a measurable signature: misgrouping can be quantified by counting cross-family merges given a known task taxonomy; interference can be measured by task-switch performance drop; overfitting can be detected by the ID/OOD gap. The taxonomy thus provides a **test suite for future memory systems**: a proposed consolidation method can be evaluated not just on aggregate accuracy but on whether it reduces each class of failure. This is a **conceptual infrastructure contribution**—it gives the field a shared language for discussing what consolidation failures look like and how to measure them, analogous to how the taxonomy of reward hacking behaviors (reward model overoptimization, distributional shift, goal misgeneralization) structured the RLHF research agenda.

The taxonomy also unifies phenomena that might otherwise appear as unrelated bugs. The phantom-strategy case (§D.4), where exposing the consolidator to failed trajectories causes it to distill recurring patterns from *incorrect* code into new abstract entries, is not a separate problem from overgeneralization—it is overgeneralization applied to a different input distribution (failure traces rather than success traces). The single-strategy collapse (§D.5) is not a separate problem from misgrouping—it is the endpoint of a process that fails to segment by family at every step, progressively merging more and more families until only one survives. The taxonomy thus provides explanatory unification, which is what makes it more than a list.

## 5. Experimental Analysis

### Evaluation Methodology

**Dataset.** The paper evaluates across five environments: ALFWorld (48-episode balanced test split across 6 task types), ScienceWorld (44-case test set sampled from 15 medium-difficulty tasks, with 2–4 cases per task), WebShop (50-session test subset drawn from indices [0, 500) with training-session overlap removed), AppWorld (100-task subset stratified across test_normal and test_challenge splits), and ARC-AGI Stream (programmatically generated tasks from a 6-family × 7-skill taxonomy, with held-out tasks that vary family–skill combinations to test generalization). The ARC-AGI Stream testbed additionally provides a fully specified latent task taxonomy for tracing memory-management actions family-by-family.

**Base model(s).** The paper uses models from the GPT-5.4 family (GPT-5.4, GPT-5.4-mini, GPT-5-mini, GPT-5-nano) and the Qwen3.5 family (Qwen3.5-27B, Qwen3.5-9B, Qwen3.5-4B), with Claude-Haiku-4.5 appearing in some baselines. Models serve in multiple roles: as solvers (producing task solutions conditioned on memory), as consolidators (producing abstracted memory entries from trajectories), and as memory managers (deciding what to retain, delete, or compress). The paper deliberately uses multiple model families to test whether findings are model-specific.

**Metrics.** ALFWorld reports binary task success (wins/48, success rate in [0, 1]). ScienceWorld reports average test score across 44 evaluation cases (the scoring function varies by task—some involve partial credit, producing scores that range above and below zero). WebShop reports wins/50 (episodes with reward = 1.0) and mean reward (arithmetic mean of per-episode rewards in [0, 1]; an episode where the agent never issues `click[Buy Now]` yields reward 0). AppWorld reports Task Goal Completion (TGC%), the percentage of evaluation tasks where all unit tests pass. ARC-AGI Stream reports task accuracy (%)—the fraction of held-out test inputs for which the solver's Python code produces the correct output grid. The paper also reports diagnostic metrics specific to ARC-AGI Stream: misclassification count (number of Consolidate actions combining episodes from ≥2 distinct families), family coverage (how many of 6 families appear in the buffer), buffer composition (share of episodic vs. abstract entries over time), and action-share distribution across Retain/Delete/Consolidate.

**Baselines.** The paper compares against several baselines for each benchmark:
- **No memory**: the solver receives the task specification without any memory entries or trajectory demonstrations. This establishes the floor.
- **Episodic-only / Trajectory Logs (Summarized)**: raw trajectories are retained as context without cross-trajectory abstraction. Multiple variants exist—`All` (full pool in context), `FS=N` (random N-shot subset to control for context length; N = 64, 32, 16), `Incr. Keep` (LLM-curated streaming retain/delete), and `One-Pass Keep` (LLM-curated single-pass retention). For ARC-AGI Stream, this baseline is the `Episodic Management Only` condition.
- **ACE** (Zhang et al., 2025): the original method's consolidation pipeline (reflector → curator → analyzer with dedup threshold 0.75). A variant `ACEGT` uses ground-truth labels for the reflector step.
- **Agent Workflow Memory (AWM)** (Wang et al., 2024): workflow templates abstracted from trajectories, consolidated over multiple epochs.
- **Dynamic Cheatsheet (DC)** (Suzgun et al., 2026): a single continuously rewritten document with `<memory_item>` blocks.
- **CLIN** (Majumder et al., 2023): relation-phrase memory rules (`MAY BE NECESSARY to`, etc.) with the paper's extensions (bounded memory, extended operations including retain, mini-batch consolidation).
- For ARC-AGI Stream: **Force** (mandatory consolidation every round, no episodic persistence), **Auto** (agent chooses Retain/Delete/Consolidate), and **Episodic Management Only** (only Retain/Delete, no Consolidate).

**Generation budget / compute accounting.** The paper does not measure FLOPs or wall-clock time. The relevant budget is measured in number of training trajectories processed, number of consolidation rounds, or memory capacity. For ScienceWorld, the x-axis is consolidation steps (each step processes a mini-batch of 4 trajectories); memory capacities of 16, 50, and ∞ are compared. For WebShop, the x-axis is number of training examples (powers of 2 from 8 to 128). For ALFWorld, consolidation stages range from 0 to 200, with snapshots evaluated every 20 stages. For ARC-AGI Stream, budget is measured in training steps (up to 400), episodic buffer capacity (50 or 100 entries), and batch size (1 or 8). Latency and wall-clock time are not accounted for—a point the paper flags as a limitation in Section 8.

**Cross-validation / statistical protocol.** The paper does not employ formal cross-validation or statistical significance testing. Due to API-cost constraints, results are typically reported as point estimates from a small number of repeats per question (often single runs). The paper acknowledges this limitation explicitly in Section 8: "we report point estimates from a small number of repeats per question rather than formal error bars; we mitigate this by checking that conclusions hold across multiple models, benchmarks, and memory frameworks, but per-figure variance should be interpreted with this in mind." For ARC-AGI Stream, evaluation averages two repeats per question unless noted otherwise. The multi-model, multi-benchmark replication strategy serves as a robustness check in lieu of formal error bars—conclusions that hold across GPT-5.4, GPT-5-mini, Qwen3.5-27B, and Claude-Haiku-4.5, and across ALFWorld, ScienceWorld, WebShop, AppWorld, and ARC-AGI Stream, are less likely to be artifacts of a single configuration.

### Main Quantitative Results

#### Consolidated Memory Utility Is Non-Monotonic in Updates

The paper's headline finding is that consolidated memory initially improves, then degrades, and can fall below the no-memory baseline as updates accumulate (Figure 1a, Figure 1b). This pattern is demonstrated across two environments with different memory frameworks.

**ScienceWorld with CLIN (Figure 1a).** Starting from an empty memory store, utility rises early—reaching its peak near consolidation step 20—and then declines through step 100. The pattern holds for all three memory capacities tested: `|M|` = 16, 50, and ∞. At `|M|` = 16, the decline pushes utility below the no-memory baseline. Critically, the unbounded store (`|M|` = ∞) also declines, separating the erosion in per-entry *quality* from the effect of eviction: even when the agent can accumulate entries without discarding old ones, the content of those entries degrades as consolidation rewrites them. The curve is labeled with three phases in the figure: "Utility Increase" (early steps), followed by "Memory Erosion" (the long decline).

**WebShop with AWM (Figure 1b).** Consolidated memory utility degrades with scale: AWM achieves a success rate of approximately 0.64 at 8 examples, falling to approximately 0.20 at 128 examples—identical to the no-memory baseline. The parenthesized values next to each marker report mean reward (a separate WebShop metric), and the same decline is visible. Meanwhile, the raw trajectory baseline (labeled "Raw Traj.") remains robust as scale increases, reaching a success rate of approximately 0.85 at 128 examples. The figure annotates the "Raw − AWM gap," which widens monotonically with scale: more training data makes consolidated memory *relatively worse* compared to simply retaining raw trajectories.

Both curves share the same qualitative shape—early improvement followed by degradation—but differ in their baselines. On ScienceWorld, the erosion brings utility below the no-memory baseline; on WebShop, AWM collapses to the no-memory baseline but not below it. The difference may reflect environment-specific dynamics (WebShop's action space is simpler than ScienceWorld's, so the no-memory baseline is proportionally higher), but both demonstrate that the benefit of consolidation is non-monotonic and can be fully erased by continued updates.

#### Good Starting Memory Degrades Under Continued Consolidation

Even when consolidation begins from a high-quality memory rather than an empty store, continued updates cause decline (Figure 4). The paper first consolidates ALFWorld trajectories with GPT-5.4 (the strongest model tested) following the Static-Group setting, then continues updating that store in batches with GPT-5-nano on the same trajectory pool. The resulting memory is evaluated under three Qwen3.5 solver sizes (27B, 9B, 4B) to test whether the decline is an artifact of a particular solver.

All three solver sizes show declining utility. The magnitude of the decline is substantial: drops are visible between consecutive evaluation steps (every 20 stages), and in some steps the drop is drastic. The Qwen3.5-27B solver, which achieves the highest absolute accuracy with the memory, also shows the largest absolute decline over stages—consistent with the interpretation that stronger solvers extract more from the memory and therefore lose more when it degrades. Memory size stays bounded at 38–50 items throughout (the cap is 50), so the erosion is in content quality, not entry count.

The detailed case study in Appendix G.1 traces the erosion qualitatively: at stage 20 (peak), the memory contains 42 items each covering a distinct decision-relevant insight—task-type recognition, systematic search strategies, cooling-vs-heating asymmetry, shuttle defaults for two-object tasks. By stage 200 (eroded), the memory has collapsed to 38 items dominated by overlapping paraphrase clusters: 22 mention the desklamp, 28 mention multi-object handling, 33 mention systematic search. Two items are byte-identical duplicates. Concrete meta-strategies present at stage 20 (the cooling-vs-heating asymmetry, the recognize-task-type-early principle) are absent from every item at stage 200—evicted to make room for paraphrases of the desklamp template.

#### The Cleanest Case: Agents Regress on Previously Solved Tasks

Figure 2 presents what the paper terms "the clearest case"—one that isolates the consolidation step from any input-side excuse. A 19-problem slice of ARC-AGI Stream is selected such that GPT-5.4 solves all 19 at 100% accuracy without memory (the dashed ceiling in the figure). The same problems are then streamed through the consolidation loop with ground-truth solutions available at every step, and the model's accuracy on those same problems is re-evaluated.

Under the **Static** condition (consolidate the full pool in one pass), accuracy remains at 100% after both R = 10 refresh rounds (94.7%) and R = 50 refresh rounds (94.7%)—essentially at the ceiling. Under the **Stream** condition (update memory after each problem), accuracy drops to 73.7% at R = 1 and 52.6% at R = 10. The labels on the figure annotate the drops as "−26" and "−47" percentage points respectively.

The comparison between Static and Stream is the critical diagnostic: both conditions receive identical problem sets and identical ground-truth solutions. The only difference is presentation order—all at once vs. one at a time. The fact that Static preserves near-ceiling accuracy while Stream collapses demonstrates that the failure is in the streaming consolidation process, not in the trajectory content. The annotation in the figure text reinforces this: "Since ground-truth solutions are available at every consolidation step, all input trajectories are useful by construction."

#### The Consolidation Schedule Itself Shapes Memory Quality

Holding the trajectory pool fixed, how trajectories are presented to the consolidator produces qualitatively different end states (Figures 3 and 4).

**Grouping by task family helps (Figure 3).** On ALFWorld evaluated under four model sizes (GPT-5 Nano, Qwen3.5-27B, Qwen3.5-9B, Qwen3.5-4B), consolidating each task type separately ("Summary") consistently outperforms consolidating across types jointly ("Ungrp."). The gap is substantial: for Qwen3.5-27B, Grouped achieves 85.4% accuracy vs. Ungrouped at 55.4%—a 30-percentage-point difference. For GPT-5 Nano, the gap is 17.2 points; for Qwen3.5-4B, 26.0 points. This demonstrates that correct segmentation—identifying which episodes belong together before abstraction—is a major determinant of memory quality, and that LLMs struggle with segmentation when heterogeneous tasks are pooled into a single abstraction step.

**One-shot consolidation beats streaming (Figure 3).** Holding the trajectory pool fixed, streaming updates ("Stream" in the figure) underperform a single whole-pool pass ("Static"). Across the four model sizes, Stream loses 17–38 percentage points relative to Static. The gap is annotated on the figure: −17.2 for GPT-5 Nano, −18.6 for Qwen3.5-27B, −38.5 for Qwen3.5-9B, and −26.0 for Qwen3.5-4B. This finding suggests that early abstractions anchor later rewrites—once the consolidator has formed an abstraction from an early subset of trajectories, it interprets later trajectories through that lens rather than revisiting the earlier decision.

**Heterogeneous batches accelerate decline within streaming (Figure 4).** Even when updates must be streamed, batch composition matters. Batches that mix tasks from different types ("Heterogeneous") produce worse memory than batches drawn from one task type at a time ("Homogeneous"). Figure 4 shows this across three batch-size conditions (`|B|` = 6 with unbounded memory, `|B|` = 6 with `|M|` = 50, `|B|` = 32 with `|M|` = 50) and three solver sizes. In each panel, the homogeneous batch curve lies above the heterogeneous batch curve across most of the consolidation trajectory. The figure annotates the "Max Drop" from the starting memory quality to the worst observed point—heterogeneous batches consistently show larger maximum drops than homogeneous batches, supporting the hypothesis that mixing tasks within a batch invites the model to merge incompatible lessons in a single update.

#### The Episodic-Only Store Is Competitive With Consolidators

Table 2 reports consolidated memory performance against the raw trajectories they were built from, across three benchmarks (AppWorld, ALFWorld, WebShop) and multiple model backbones. A red `(–)` marks any non-trajectory-log approach that is beaten by at least one trajectory-log baseline in the same row. The best result per row is bolded.

**AppWorld (TGC%).** For Qwen3.5-27B, the `All` trajectory baseline achieves 73%, while ACE achieves 65% and AWM achieves 68%. For GPT-5.4-Mini, `All` achieves 59%, while ACE achieves 57% and AWM achieves 52%. For Claude-Haiku-4.5, `All` achieves 66%, ACE achieves 60%, AWM achieves 74 (best in row), and DC achieves 64%. Notably, ACE and AWM are beaten by at least one trajectory-log baseline in most conditions—the red `(–)` marks appear frequently.

**ALFWorld (Task Success %).** For GPT-5.4-Mini, `All` achieves 90%, while ACE achieves 79%, AWM 65%, and DC 58%—all substantially below the raw-trajectory baseline. For GPT-5-Mini, `All` achieves 81%, versus ACE at 56%, AWM at 60%, DC at 50%. For Claude-Haiku-4.5, `All` achieves 92%, ACE at 73%, AWM at 81%, DC at 81%. The trajectory-log baselines claim the best result in every row.

**WebShop (Table 3).** For GPT-5.4-Mini, the best trajectory-log result is FS=16 at 51 (mean reward ×100), versus ACE at 23 and AWM at 3. For GPT-5-Mini, FS=32 achieves 63, versus AWM at 59. For Claude-Haiku-4.5, FS=64 achieves 63, versus AWM at 32. ACE and DC experiments were not completed for all backbones (marked `—`), and some ACE results were near zero (marked `00*`), leading the authors to stop further ACE/DC experiments on WebShop.

These results are consistent across environments: in the majority of conditions, at least one trajectory-log variant matches or beats every consolidated method tested. The paper interprets this as evidence that "the evidence available before abstraction already contains task-relevant signal that the solver can exploit directly" (Section 4.2).

#### Forced Abstraction Underperforms Retained Episodes (ARC-AGI Stream)

The ARC-AGI Stream experiments directly test the Complementary Learning Systems prediction that gated consolidation should outperform mandatory rewriting. The results (Figures 5, 9a, 9b) consistently support this prediction.

**Training-time cumulative success (Figure 5).** Over 400 training steps, Auto (which keeps episodes by default and uses abstraction sparingly) generally outperforms Force (which consolidates at every round) on both GPT-5.4 and Claude-Haiku backbones. On GPT-5.4, Auto with `|Episodic|` = 100 achieves 43.2% cumulative success, versus 37.8% for Force and 22.0% for no memory. On Claude-Haiku, Auto with `|Episodic|` = 100 achieves 35.5%, versus 26.0% for Force and 23.8% for no memory. Auto with a smaller episodic buffer (`|Episodic|` = 50) achieves intermediate results on both backbones.

**Ablation by memory source (Figure 9a).** When the solver is restricted to different memory sources, the episodic store carries most of the gain. Using only the episodes the agent retained ("Auto (Episodic)") achieves 68% success, similar to the full Auto condition ("Auto + Episodic") at 62%. Using only the abstract store ("Auto (Abstract Only)") achieves 32%—at or below the no-memory baseline of 38%. Episodic Management Only (retention/deletion of raw episodes with abstraction disabled) achieves 54%, matching or beating Auto + Episodic at 62%. The figure caption summarizes: "In Auto, using the episodes it retained alone shows strong performance, and it synergizes with the abstract store. Meanwhile, managing episodic memory alone beats or matches the performance."

**Training-time success across memory configurations (Figure 9b).** Across four checkpoints (50, 200, 300, 400 steps), Episodic Only and Auto consistently lie above Abstract Only, which remains near the zero-shot baseline. Two in-context reference conditions—raw code demonstrations ("In Context (Code)," 86%) and natural-language descriptions ("In Context (NL)," 66%)—provide upper bounds, showing what performance would be if all problems of the same family were available as demonstrations. The memory-based conditions fall below these upper bounds but above zero-shot (38%), with the episodic-based conditions closer to the upper bounds than the abstract-only condition.

**The agent's own management decisions (Figure 7b, 7c).** Given the choice, the agent saturates the episodic buffer quickly: at both `|Episodic|` = 50 and `|Episodic|` = 100, the buffer fills to near capacity early and stays there. The abstract store remains sparse (2–3 entries at most checkpoints). The action-share distribution (Figure 7c) shows that the agent chooses `Keep` ~60.8% of the time and `Compress` ~18.5% when `|Episodic|` = 100; at `|Episodic|` = 50, `Compress` rises to 32.5% and `Keep` drops to 58.5%, but `Keep` remains the dominant action. The figure caption summarizes: "Bigger buffer halves Compress, grows Keep." This is the episodic-first policy that the agent chooses when the architecture permits it.

#### Memory Erosion Case Studies: Qualitative Evidence

The paper supplements quantitative results with detailed case studies tracing memory content across consolidation steps.

**Erosion from good to degraded (Appendix G.1).** On ALFWorld, a 200-stage iterative consolidation run (GPT-5-nano manager, Qwen3.5 solvers) shows the memory's content transformation. At stage 20 (peak, 42 items, 35/48 wins for Qwen3.5-4B and 9B solvers), the items cover diverse, decision-relevant insights: task-type recognition, cooling-vs-heating asymmetry ("Cooling and cleaning are usually simpler than heating"), shuttle defaults for two-object tasks, desklamp co-location protocols. At stage 200 (eroded, 38 items, 15/48 wins for 4B, 16/48 for 9B), the memory has collapsed to overlapping paraphrase clusters: 22 of 38 items mention the desklamp, two items are byte-identical duplicates, and the cooling-vs-heating asymmetry is absent from every item. The 50-item cap evicted useful entries to make room for near-verbatim restatements of the desklamp directive.

**Single-stage collapse from 50 items to 1 (Appendix G.2).** One consolidation step (stage 168 → 169) merges a 50-item, 48,506-character memory into a single 1,960-character "unified loop" that tries to cover all six ALFWorld task types in one numbered procedure. The rollout-level effect of this single-stage transition is reported in Table 11: Qwen3.5-4B drops from 35/48 to 29/48 (∆ = −6), Qwen3.5-9B from 36/48 to 26/48 (∆ = −10), and Qwen3.5-27B from 37/48 to 24/48 (∆ = −13). The magnitude scales with solver strength—stronger solvers lose more when the structured 50-item memory collapses into one entry.

**Workflow 8 ablation on WebShop (Appendix I.1).** A single workflow in an AWM consolidated memory file (W8: "Search across pages when the first results do not match") is shown to measurably degrade agent behavior. Removing W8 improves wins/50 from 7 to 14 for GPT-5.4-mini and from 18 to 23 for GPT-5-mini, reduces page-turn actions by a factor of 2.3 in both rollouts (Table 13), and increases the number of episodes that issue `click[Buy Now]` from 14 to 21 (GPT-5.4-mini) and from 28 to 33 (GPT-5-mini). The W8 workflow prescribes clicking `[Next >]` with no stop criterion and no concrete candidate selection step—a failure mode traced to a single entry that biases the agent toward dead-end page-turning loops instead of product-page interactions that lead to purchase.

#### Failure Mode: Misgrouping Before Abstraction (ARC-AGI Stream, Figure 7a)

Quantitative evidence for misgrouping comes from the ARC-AGI Stream testbed, where each Consolidate action's selected episodic indices can be checked against the known task taxonomy. Figure 7a reports the misclassification count—the number of consolidation actions that combine episodes from two or more distinct families—under different conditions.

Under Force with batch size 8, the model misclassifies 74 times over 400 steps. Under Auto (`|Episodic|` = 50), misclassifications drop to 36; under Auto (`|Episodic|` = 100), to 10. The "Compress" bar shows the total number of consolidation actions in each condition: 145 for Force, with 74 misclassifications (51% of consolidation actions are misclassified); 36 for Auto-50; 10 for Auto-100. The reduction in misclassifications under Auto conditions is consistent with the interpretation that gating consolidation (allowing the agent to choose when to compress, rather than forcing it at every step) reduces cross-family merging.

Table 4 reports additional diagnostics: average number of families covered in the episodic buffer and abstract store, average number of fused entries per consolidation action, and buffer size. Under Force with batch size 8, average families covered is 5.00 and buffer size is 50.00, but this is achieved at the cost of 74 misclassifications, as Figure 7a shows.

The paper also provides qualitative case studies of specific misgrouping failures. In §D.3 ("Foreign-family injection"), a consolidated memory entry for an inside-frame task includes a cross-frame shape-signature lookup that belongs to the group-by-shape family and a marker-style color write that belongs to the key-marker family—neither of which is part of the inside-frame source task. In §D.5 ("Single-strategy collapse"), after 190 consolidation steps over 19 tasks spanning six families, the memory contains a single entry prescribing an inside-frame-plus-hollow playbook, and the solver applies this entry verbatim to held-out tasks from other families, failing where the same model without memory succeeds.

#### Failure Mode: Interference from Overgeneralized Lessons

The paper provides quantitative evidence for interference across several experiments.

**Switch-induced forgetting (Figure 8b).** A single task switch in ARC-AGI overwrites a non-trivial fraction of previously learned accuracy. The figure shows old-task accuracy before and after a switch, annotated with the forgetting percentage and the retained percentage. For GPT-5-mini, forgetting is 40% (retained: 60%). For GPT-5.4, forgetting is 40% at batch size 1 and 10% at batch size 50. For Qwen3.5-27B, forgetting is 40% at batch size 25 and 5% at batch size 50. Larger batch sizes tend to produce less forgetting—consistent with the finding in Figure 4 that heterogeneous batches accelerate decline, since if a larger batch contains more evidence for the original task, it may provide counter-pressure against the new task's overwriting.

**Cross-task interference under repeated consolidation (Figure 8c).** More distillations on one task (Pick&Place) increasingly interfere with performance on a related but different task (Pick-Clean-Place). After 1 distillation, conjugate task accuracy is 70.4% for Qwen3.5-27B and 22.2% for GPT-5-Nano. After 100 distillations, it drops to 37.0% (Qwen3.5-27B, a 48.2-point drop) and 11.1% (GPT-5-Nano, a 25.9-point drop—but note the starting accuracy was already much lower, at 22.2%, so the relative drop is comparable). The figure annotates the drop from 1 to 100 distillations: the memory that was once helpful for the conjugate task becomes increasingly misaligned as it is repeatedly rewritten with evidence from the focal task.

**Fresh vs. Cumulative consolidation under task switching (Figure 10).** On the 15-task ScienceWorld switch sequence, consolidating only on the current task (Fresh) ends 203 points ahead of consolidating jointly over all tasks seen so far (Cumulative). The figure plots per-task cumulative score advantage: the gap widens monotonically as more tasks are added, reaching +203 by task 15. Appendix K.2, Figure 18, provides a mechanistic account: Cumulative accumulates overgeneralized memories at roughly 5× Fresh's rate and garbage memories at roughly 20× Fresh's rate. By task 15, Cumulative has 94 overgeneralized entries vs. 18 for Fresh, and 217 garbage entries vs. 11 for Fresh. Both gaps widen monotonically across the 15-task sequence.

#### Failure Mode: Overfitting to Narrow Streams

Figure 11 demonstrates overfitting on ARC-AGI: after repeated consolidation on a single strategy family, performance on exact repetitions of those problems (in-distribution, ID) remains high, but performance on simple variations within the same strategy family (out-of-distribution, OOD) collapses. The ID/OOD gap is annotated for each model: GPT-5.4 shows ID accuracy of 0.65 and OOD of 0.05 (gap: 0.60), GPT-5-mini shows ID 0.50 and OOD 0.00 (gap: 0.50), and Qwen3.5-27B shows ID 0.45 and OOD 0.05 (gap: 0.40). Additional reference conditions—raw code ("Code") and summarized code ("Code Summ.")—show OOD performance of 0.80 and 0.55 respectively, demonstrating that the base model can generalize within the family when not forced through repeated consolidation.

The concrete-vocabulary erosion case study (§D.2) traces the overfitting mechanism qualitatively: a memory entry goes through 50 rewrites and loses the concrete feature it was meant to abstract. At round 1, the entry reads "identify and extract structured elements from input → compute a global metric (e.g., max size) → iterate elements and selectively apply targeted edits." By round 50, it reads "Find the maximum value of a derived per-object numeric attribute and apply a uniform transformation to every object whose attribute equals that maximum." The parenthetical "(e.g., max size)"—the only concrete property the task actually selects on—has been abstracted away entirely, replaced by the vacuous "derived per-object numeric attribute."

### Ablation Studies and Robustness Checks

**Memory capacity:** The non-monotonic curve in Figure 1a holds across three memory capacities (`|M|` = 16, 50, ∞). The unbounded capacity shows the same erosion shape as bounded capacities, confirming that degradation is in per-entry quality rather than entry count. However, bounded capacity (`|M|` = 16) produces the deepest decline—utility falls below the no-memory baseline—suggesting that eviction compounds the erosion by removing useful entries before they have a chance to be refined.

**Batch composition (homogeneous vs. heterogeneous):** Figure 4 demonstrates that heterogeneous batches accelerate memory erosion compared to homogeneous batches across three batch-size conditions and three solver sizes. The maximum drop from starting quality to worst observed point is consistently larger for heterogeneous batches.

**Batch size within streaming:** Figure 4 compares `|B|` = 6 and `|B|` = 32. Larger batches show different erosion dynamics—with `|B|` = 32 and homogeneous composition, the maximum drop is smaller than with `|B|` = 6, consistent with the interpretation that having more within-task evidence per decision step reduces the chance of forming an early erroneous abstraction that anchors later rewrites.

**Consolidation schedule (Static-All vs. Static-Group vs. Stream):** Figure 3 compares these three regimes holding the trajectory pool and consolidator fixed. Static-Group (consolidating each task type separately) outperforms Static-All (cross-family consolidation) by 17–38 percentage points across model sizes. Stream underperforms Static-All substantially. These differences are measured on identical trajectory content, isolating the effect of presentation order. The gap between Static-Group and Static-All directly quantifies the cost of cross-family consolidation.

**One-shot vs. iterative consolidation quality:** Table 2 includes both `One-Pass Keep` (LLM curates the full pool in a single pass) and `Incr. Keep` (LLM curates in streaming fashion). On ALFWorld with GPT-5.4-Mini, Incr. Keep achieves 85% vs. One-Pass Keep at 81%—streaming curation slightly outperforms single-pass curation, but both trail the `All` baseline (90%). On AppWorld with Qwen3.5-27B, One-Pass Keep achieves 69% vs. Incr. Keep at 69%—identical performance.

**Trajectory subset sizes:** Table 2 compares `All` (full pool) against fixed-size subsets (FS=64, 32, 16) to control for context-length effects. On ALFWorld with GPT-5.4-Mini, FS=64 achieves 92% vs. `All` at 90%—the subset slightly outperforms the full pool, suggesting that beyond some point, additional raw trajectories may add noise rather than signal, but the effect is small. On WebShop (Table 3), FS=32 achieves the best result for GPT-5-Mini (63) and FS=16 achieves the best for GPT-5.4-Mini (51), both outperforming the full `All` baseline.

**Solver model scale:** Figure 4 evaluates consolidation quality under three Qwen3.5 sizes (4B, 9B, 27B) for each batch-size/memory-capacity condition. The erosion pattern is consistent across solver sizes, but the absolute magnitude of the decline scales with solver strength—larger models achieve higher peak utility and show larger absolute drops when the memory degrades (Table 11: the drop from stage 168 to 169 is −6 for 4B, −10 for 9B, −13 for 27B).

**Multiple memory frameworks simultaneously:** The erosion pattern is observed across CLIN (ScienceWorld, Figure 1a), AWM (WebShop, Figure 1b), ACE (Tables 2 and 3), and Dynamic Cheatsheet (Tables 2 and 3). No single framework is immune, supporting the paper's claim that the failure is paradigmatic rather than method-specific.

**Multiple model families:** The episodic-only baseline outperforms consolidated memory across GPT-5.4 family models, Qwen3.5 family models, and Claude-Haiku-4.5 (Table 2). The erosion curve (Figure 1a) is demonstrated with GPT-5.4-mini on ScienceWorld. The ARC-AGI Stream experiments use GPT-5.4 and Claude-Haiku as solvers (Figure 5). Conclusions hold across model families, reducing the likelihood that findings are artifacts of a particular model's idiosyncrasies.

**Ground-truth vs. self-generated trajectories:** On ARC-AGI Stream, the GT trajectory regime (ground-truth solutions) and Running regime (self-generated solutions) are compared indirectly across experiments. The collapse in Figure 2 uses ground-truth trajectories—the strongest possible input—and still shows degradation. The phantom-strategy failure mode (§D.4) demonstrates that exposing the consolidator to *failed* trajectories (the Running regime) causes it to distill recurring patterns from incorrect code into new abstract entries. This is a negative result: including failure information does not help the consolidator prune bad entries; instead, it extracts "phantom strategies" that encode fictional rules.

**Autonomy over consolidation (Force vs. Auto vs. Episodic Management Only):** Figure 5 shows that Auto outperforms Force on both GPT-5.4 and Claude-Haiku backbones across 400 training steps. Figure 9a shows that Episodic Management Only matches or beats Auto + Episodic. The component ablation in Appendix K.1 (Figure 17) shows that restricting the solver to the episodic store alone recovers nearly all of Auto's gain, while restricting to the abstract store alone reduces performance to the no-memory baseline. Together, these results demonstrate that the episodic store—not the abstract store—carries the performance benefit, and that forced consolidation actively degrades performance relative to retention-only policies.

**Memory surgery—single-workflow ablation (Appendix I.1):** Removing one workflow (W8) from an 8-workflow consolidated memory file on WebShop measurably improves agent behavior. This is the most granular causality test in the paper: changing a single entry in the memory store alters downstream action distributions and success rates, providing direct evidence that specific memory content—not just aggregate memory quality—causally affects agent performance. The ablation further strengthens the case that the consolidation process, rather than some external factor, is the source of performance degradation.

**Memory composition under task switching (Appendix K.2, Figure 18):** The LLM-judge labeling of memory entries as normal, overgeneralized, overspecific, or garbage quantifies the mechanistic difference between Fresh and Cumulative consolidation. Cumulative accumulates overgeneralized entries at ~5× Fresh's rate (94 vs. 18 by task 15) and garbage entries at ~20× Fresh's rate (217 vs. 11 by task 15). These quantitative content-level measurements provide a direct explanation for the +203-point performance gap between Fresh and Cumulative in Figure 10.

**Failed trajectory exposure (Appendix B.5):** The paper tests whether exposing the consolidator to failed attempts (each failure paired with the wrong output it produced) helps prune bad entries. The result is negative: the consolidator instead distills recurring patterns from the failed code into new entries, creating "phantom strategies" that encode fictional rules (verbatim example in §D.4). This is a particularly informative negative result—it suggests that simply providing failure information does not give the consolidator the metacognitive ability to distinguish useful patterns from spurious ones.

**Strategy selection vs. synthesis (Appendix B.7):** The alternative solver invocation—first selecting an existing strategy by index, then synthesizing code from that strategy—tests whether retrieval is a point of failure separate from entry quality. The case studies in §D.5 demonstrate that retrieval can apply a correct-for-its-own-family strategy to the wrong task (Example 1: the inside-frame strategy applied to a color-removal task; Example 2: the group-by-shape strategy applied to a keep-largest task). In both cases, the same model without memory solves the task correctly, indicating that the error is in retrieval/application of memory, not in the model's underlying capability.

### Critical Assessment

#### Does the paper demonstrate that "consolidated memory produced by today's LLMs is often faulty even when derived from useful experiences"?

**Yes, with strong evidence for the streaming regime, weaker evidence for batch regimes.** The cleanest demonstration is Figure 2: GPT-5.4 solves 19 ARC-AGI problems at 100% accuracy without memory, then fails on 46% of them after streaming consolidation from ground-truth solutions. Since the inputs are correct by construction and the model previously solved the tasks, the only variable is the consolidation process. This is about as clean a causal attribution as is possible in this domain.

The Figure 1a and 1b curves also support the claim, showing non-monotonic utility that can fall below the no-memory baseline. The case studies in Appendices G and H provide qualitative evidence that the content of memory becomes less useful—concrete strategies are replaced by paraphrases, byte-identical duplicates, and vacuous abstractions.

**However**, the strength of the evidence depends on the consolidation regime. The Static condition in Figure 2 preserves near-ceiling accuracy—consolidation is not *inherently* faulty; it is faulty under streaming (incremental, batch-by-batch) conditions. This is an important scope condition: the paper's central finding is about *continuously updated* memory, not about consolidation in general. The batch (Static-All) condition in Figure 3 also shows much better performance than Stream. So the claim should be understood as "consolidation under streaming update is faulty," not "all forms of consolidation are faulty."

The episodic-only baseline (Table 2) demonstrates that consolidated memory often fails to beat unabstracted trajectories, but this is evidence that consolidation is *unnecessary* rather than that it is *harmful*—it does not directly demonstrate faultiness, only redundancy. The case where consolidation falls *below* no-memory (Figure 1a, bounded capacity curve) and the case where it causes regression on previously solved tasks (Figure 2) are the only conditions where harmful consolidation is demonstrated.

#### Does the paper demonstrate that "the failure is traced to the consolidation step itself rather than the underlying experience"?

**Yes, with multiple lines of converging evidence.** Holding the trajectory pool fixed while varying the consolidation schedule (Figure 3: Static-All vs. Static-Group vs. Stream; Figure 2: Static vs. Stream) directly isolates the consolidation process from trajectory content. The episodic-only control (Table 2) consumes the same trajectories without abstracting them and remains competitive—if the trajectories were the problem, the episodic-only control should also degrade. The Fresh vs. Cumulative comparison (Figure 10) uses identical trajectories; the only difference is whether consolidation happens within-task or across-task. The memory surgery ablation (Appendix I.1) removes a single workflow from a consolidated memory and shows causal impact on downstream performance.

Collectively, these experiments make a strong case that consolidation introduces errors not present in the input trajectories. The paper would have been even stronger if it had included a condition where the *same* trajectories were consolidated by a different, non-LLM abstraction method (e.g., simple template extraction) as a control—this would distinguish LLM-specific abstraction failures from failures inherent to any compression process. Without this, we know that LLM-driven consolidation is faulty, but we do not know whether *any* automated textual consolidation would show the same pattern or whether this is specific to how current LLMs perform abstraction.

#### Does the paper demonstrate that "raw episodic trajectories should be treated as first-class evidence rather than disposable material to be compressed away"?

**Yes, strongly.** The episodic-only baseline outperforms consolidated memory in the majority of conditions (Table 2, Table 3). The ARC-AGI Stream experiments show that Auto (which keeps episodes) outperforms Force (which discards episodes after each round's consolidation), and that Episodic Management Only (which never consolidates) matches or beats Auto (Figure 9a). The component ablation (Appendix K.1, Figure 17) demonstrates that restricting to the abstract store alone collapses performance to the no-memory baseline, while restricting to the episodic store alone recovers nearly all the gain—the abstract store adds little value beyond raw episodes, while the episodic store carries the value.

**However**, the paper does not demonstrate that raw trajectories *scale* as a long-term memory solution. The episodic buffers in ARC-AGI Stream are capped at 50–100 entries, and the evaluation tasks are drawn from the same distribution as the training tasks. In a truly long-horizon deployment with thousands of episodes and distribution shift, an unbounded episodic store would face context-length limits, retrieval challenges, and potential interference effects that the paper does not study. The paper acknowledges this limitation explicitly ("episodic accumulation cannot be the long-term answer: as deployment continues, raw histories grow unboundedly and resist compositional reuse—compression and transfer ultimately require abstraction") but does not test the boundary at which episodic-only fails. This is not a weakness of the evidence for the *current* claim, but it limits the practical upshot: we know episodes are better than faulty abstractions, but we do not know at what scale they break down.

#### Does the paper demonstrate that "mandatory rewriting at every step, rather than abstraction itself, is the decisive failure mode"?

**Yes, for the ARC-AGI Stream setting.** Figure 9a shows that Episodic Management Only (no abstraction at all) matches or beats Auto + Episodic (gated abstraction), and both substantially beat Force (mandatory abstraction). Figure 5 shows the same ordering across 400 training steps. If abstraction itself were the problem, Episodic Management Only should outperform Auto—but it does not consistently; the two are competitive. This suggests that *gated* abstraction is not harmful, while mandatory abstraction is. The agent's own behavior (choosing Keep ~60% of the time and Compress ~18.5%) supports the interpretation that the problem is frequency and timing, not the act of abstraction per se.

**However**, this conclusion is specific to ARC-AGI Stream, where consolidation actions are exposed and the two-store architecture is explicit. In the other benchmarks (ALFWorld, ScienceWorld, WebShop, AppWorld), the paper does not directly compare mandatory rewriting against gated rewriting—the Force and Auto conditions are not implemented. The ScienceWorld CLIN experiments use repeated consolidation rounds, which is analogous to Force, but there is no Auto comparison. The WebShop AWM experiments consolidate over epochs, which is also Force-like. So the claim that "mandatory rewriting, not abstraction itself, is the decisive failure mode" is well-supported for ARC-AGI Stream but is extrapolated to other benchmarks rather than directly tested there.

The case studies in Appendices G and H do show specific instances where abstraction *content* is faulty (phantom strategies, vacuous abstractions, foreign-family injection), even in non-streaming conditions. This suggests that abstraction quality is also a problem, not just the mandatory rewriting schedule. If abstraction content were always correct, mandatory rewriting might still be acceptable. The paper's own evidence shows that both scheduling and content quality matter.

#### Does the paper demonstrate that misgrouping, overgeneralization, and overfitting are the mechanisms behind faulty memory?

**Partially.** The misgrouping evidence is strong for ARC-AGI Stream (Figure 7a: misclassification counts, with the known task taxonomy providing ground truth). The qualitative case studies in §D.3 and §D.5 provide vivid examples of cross-family merging. The Static-Group vs. Static-All comparison (Figure 3) provides indirect evidence across benchmarks—the gap between within-family and cross-family consolidation suggests misgrouping, though without a known task taxonomy in ALFWorld, this is inference rather than measurement.

The overgeneralization evidence is strong across multiple experiments. Figure 8b (switch-induced forgetting), Figure 8c (cross-task interference under repeated consolidation), and Figure 10 (Fresh vs. Cumulative) all demonstrate that consolidated lessons from one task interfere with performance on related-but-different tasks. The LLM-judge labeling (Appendix K.2, Figure 18) provides quantitative evidence that overgeneralized entries accumulate over time. The case studies in §G.3 ("Overgeneralized" items) show verbatim examples of memory entries whose recommendations apply to any state.

The overfitting evidence is based primarily on Figure 11 and the qualitative case study in §D.2. While Figure 11 clearly shows an ID/OOD gap after repeated consolidation on a narrow stream, the gap is shown for only one strategy family, and the number of consolidation iterations is not specified in the figure caption—making it difficult to assess whether the magnitude of overfitting warrants the emphasis it receives in the taxonomy. The concrete-vocabulary erosion example (§D.2) is compelling but is a single qualitative trace; more quantitative characterization of overfitting would strengthen this part of the diagnosis.

**A missing diagnostic:** The paper does not measure the relative contribution of each failure mode to overall performance degradation. We know all three modes occur, but we do not know whether, say, misgrouping is responsible for 60% of the degradation and overgeneralization for 20%, or vice versa. Without this decomposition, the taxonomy's practical utility for guiding architectural improvements is limited—should future work invest more in episode segmentation, applicability-condition preservation, or diversity of training streams?

#### Additional weaknesses and missing experiments

**Test set sizes are small.** ALFWorld evaluation uses 48 episodes, ScienceWorld uses 44 cases, WebShop uses 50 sessions, and the ARC-AGI 19-problem regression test (Figure 2) uses only 19 problems. Small test sets limit statistical reliability, and the absence of formal confidence intervals makes it difficult to assess whether some of the smaller gaps (e.g., Auto vs. Episodic Management Only in Figure 9a: 62% vs. 54%) are reliably different. The paper's mitigation strategy—replication across models and benchmarks—is reasonable but does not substitute for larger test sets on individual benchmarks.

**No formal statistical testing.** The paper reports point estimates from single runs (or few repeats) with no error bars, confidence intervals, or significance tests. This is explicitly acknowledged as a limitation due to API-cost constraints, but it means that differences of a few percentage points cannot be distinguished from noise. The broad replication across models and benchmarks provides qualitative robustness, but quantitative claims about specific magnitudes should be interpreted cautiously.

**Difficulty estimation or task complexity control is absent.** For ALFWorld, ScienceWorld, WebShop, and AppWorld, there is no task-difficulty annotation analogous to what was done in the MATH benchmark analysis of the reference example paper. We do not know whether consolidation is more harmful on easy tasks, hard tasks, or uniformly across difficulty. This is a significant gap because the reference paper found that test-time compute effects are strongly difficulty-dependent. The paper's own ARC-AGI experiments do use a known task taxonomy (families and skills), but do not explicitly break down results by task difficulty within families. Including a difficulty-conditioned analysis would have provided more actionable guidance—perhaps consolidation is safe for easy tasks but harmful for hard ones, or vice versa.

**Limited exploration of consolidation gating criteria.** The Auto mode lets the agent decide when to consolidate based on its own judgment, but the paper does not analyze what features of the current state predict the agent's consolidation decisions. Do agents consolidate when the episodic buffer is nearly full? When they encounter a task of a familiar type? When performance on recent tasks drops? Understanding the triggers would inform the design of programmatic gating heuristics that do not require an LLM call at every step.

**No exploration of retrieval mechanisms.** All memory entries are placed in context at evaluation—there is no retrieval step that selects a subset of relevant entries for the current task. In a long-horizon deployment with a large abstract store, retrieval quality would be critical, and retrieval errors could compound abstraction errors. The paper's finding that abstract memory provides little benefit over episodic memory could be partially driven by the fact that all entries are in context, making it easier for the solver to ignore irrelevant ones. With retrieval, a single faulty abstract entry might be selected and lead the solver astray, making abstraction failures even more impactful.

**The consolidation prompt engineering space is unexplored.** The paper uses specific prompt templates (documented in appendices) for each consolidation method, but does not ablate over prompt design choices. Could different instructions—for instance, requiring the consolidator to list preconditions explicitly, or to provide counterexamples where a strategy should not apply—reduce overgeneralization? This is a significant gap because the prompt is the primary interface through which the LLM performs consolidation, and the paper's core claim is about LLM consolidation capability. Without prompt ablation, we cannot distinguish "current LLMs cannot consolidate reliably regardless of prompt" from "the specific prompts used happen to produce unreliable consolidation."

**No comparison to non-LLM consolidation methods.** The paper compares consolidated memory against episodic-only and no-memory baselines, but not against simpler, non-LLM abstraction methods. For example, in WebShop, a simple template-based extraction (search → open → select variant → buy) might capture the most common workflow pattern without suffering from LLM-specific overgeneralization or phantom-strategy errors. Such a comparison would distinguish whether the failure is specific to how LLMs perform abstraction (overfitting to surface patterns, losing preconditions) or whether any text-based abstraction would face similar challenges.

**The ablation on batch size is limited.** Figure 4 compares `|B|` = 6 and `|B|` = 32, but does not explore the full range from `|B|` = 1 to `|B|` = N (Static-All). The finding that larger homogeneous batches show smaller drops suggests a monotonic relationship—bigger batches are better—but the paper does not characterize where diminishing returns set in or whether very large batches (approaching Static-All) avoid erosion entirely, which would inform the design of batched consolidation schedules. Similarly, the interaction between batch size and memory capacity is not fully characterized: at `|M|` = ∞, batches of size 6 (Figure 4, left column) show one erosion shape, but we do not know how batch size 32 would look with unbounded capacity.

**The episodic buffer management strategy is not compared against random or FIFO baselines.** In ARC-AGI Stream, the Auto mode lets the LLM decide which episodes to retain and which to delete. If a random retention policy or a simple FIFO policy achieved similar performance, it would suggest that the LLM's metacognitive decisions over what to keep are not adding value beyond what a simple capacity-management heuristic provides. The paper does not include this ablation, making it unclear whether the Auto mode's success is due to intelligent retention decisions or simply due to *having* an episodic buffer (regardless of what it contains).

**The phantom-strategy failure from failed trajectories (Appendix B.5, §D.4) is described but not quantified.** We see one verbatim example of a "glyph-like" fictional strategy extracted from failure code, but we do not know how frequently such phantom strategies appear, how many memory entries they occupy, or what fraction of downstream failures they cause. Quantifying this effect would strengthen the paper's recommendation that consolidators should not be exposed to failed trajectories.

**The relationship between consolidation model strength and failure rate is not systematically explored.** The paper uses GPT-5.4 as a consolidator in some experiments and GPT-5-nano in others (Figure 4 uses GPT-5-nano for management; Figure 3 uses GPT-5.4 for initial consolidation). If consolidation quality improves monotonically with model scale, then the paper's findings might not generalize to future, more capable models. The SLEDGE hammer comparison in Figure 4 (starting from a GPT-5.4 consolidated memory and continuing with GPT-5-nano) shows that a strong starting memory degrades under a weaker consolidating model, but does not test whether a strong model continuing consolidation on its own output also degrades, or at what rate. A scaling experiment—comparing consolidation quality across model sizes—would address this directly.

## 6. Limitations and Trade-offs

### The Cost of Difficulty Estimation Is Not Accounted For in the Headline Gains

**Assumption or constraint.** The paper's central policy prescription—gate consolidation, retain raw episodes by default, and compress only selectively—implicitly requires the agent to know *when* episodes share structure and *when* abstraction is safe. The paper provides no cheap mechanism for making this judgment. In ARC-AGI Stream, the Auto mode delegates the decision to the same LLM that performs consolidation, requiring an additional LLM call (the consolidator decision prompt, Appendix B.3) at every step. This cost is not factored into any efficiency comparison.

For the benchmarks other than ARC-AGI Stream (ALFWorld, ScienceWorld, WebShop, AppWorld), the paper does not implement gated consolidation at all—the experiments that demonstrate erosion use mandatory rewriting (the Force analogue), and the experiments that demonstrate episodic-only competitiveness use append-only raw trajectories with no gating decisions. The paper does not measure what fraction of consolidation actions in Auto mode are correct (i.e., applied to episodes that genuinely share underlying structure), nor does it measure the cost of incorrect gating decisions (failing to consolidate when it would help, or consolidating when it would hurt).

**Consequence.** The practical upshot of the paper—"retain raw episodes and gate abstraction"—is an architectural prescription without an operational mechanism. A practitioner implementing this advice would face an immediate design question: **what rule or model decides when to consolidate?** The paper provides evidence that LLMs can make this decision when prompted (Auto mode outperforms Force), but:

- The decision prompt itself costs compute (one LLM call per step, plus a second LLM call for the actual extraction if consolidation is chosen).
- The decision quality is imperfect—even in Auto mode, misclassifications occur (Figure 7a: Auto with `|Episodic|` = 50 produces 36 misclassifications over 400 steps), and the paper does not measure whether some of these misclassifications cause downstream harm comparable to the forced-consolidation failures.
- In domains without the kind of structured task taxonomy that ARC-AGI Stream provides, it is unclear what features the LLM uses to decide whether episodes share structure, or whether the decision would transfer.

The paper acknowledges this gap indirectly in the discussion of the Complementary Learning Systems framework: "consolidation is gated by schema fit rather than triggered on every event" (Section 5), but it does not operationalize "schema fit" as a measurable signal. The metacognitive control that cognitive theories identify as necessary (Nelson and Narens, 1990; Koriat, 1997) is outsourced to an LLM call whose reliability is itself untested outside the ARC-AGI Stream setting.

**Evidence in the paper.** Figure 7a reports misclassification counts under Force (74), Auto-50 (36), and Auto-100 (10), showing that the decision quality improves with a larger episodic buffer (since the model consolidates less often when it can retain more raw episodes). The action-share distribution (Figure 7c) shows that `Keep` is the dominant action (60.8% at `|Episodic|` = 100). However, the paper does not evaluate the decision quality against an oracle gating policy, does not measure the false-negative rate (failing to consolidate when episodes genuinely share structure), and does not compute the net benefit of gating after accounting for the cost of the decision prompts themselves.

**Mitigation status.** Not addressed. The paper identifies the gating problem as central—"abstraction should be selective, delayed, and grounded in recoverable trajectories" (Section 7)—but provides no mechanism for implementing selective abstraction beyond using the LLM itself. The suggestion that "future work could develop programmatic gating heuristics" is implied but not stated as an explicit research direction. This is the single largest gap between the paper's diagnosis and its prescription.

---

### All Results Are on a Single Evaluation Regime: In-Context Memory Without Retrieval

**Assumption or constraint.** In every experiment across all five benchmarks, all memory entries—whether consolidated abstractions or raw episodic trajectories—are placed in context at evaluation time. There is no retrieval step that selects a subset of relevant entries for the current task. The paper states this explicitly: "at evaluation we provide all memory entries in context" (Section 3). For the episodic-only baseline, this means the solver sees the full trajectory log (or a fixed-size random subset, in the FS=N conditions). For consolidated memory, the solver sees the entire abstract store.

This is an unrealistic deployment condition for any long-horizon agent. As the number of stored episodes or abstracted lessons grows, the context window will eventually overflow. At that point, the agent must either truncate (discarding potentially relevant entries) or retrieve (selecting a subset based on relevance to the current task). The paper's central finding—that raw episodes outperform consolidated abstractions—was measured in a regime where all raw episodes fit in context. It is unknown whether this advantage persists when retrieval is necessary.

**Consequence.** The paper cannot distinguish between two interpretations of why consolidated memory underperforms raw trajectories:

1. **Abstraction destroys useful information**: consolidated entries omit details that the solver needs, and the solver would perform better with raw episodes even if it could only see a retrieved subset.
2. **Raw episodes benefit from full-context access**: the solver performs well with raw trajectories because it can see *all* of them and pick out relevant patterns through in-context attention. If retrieval were applied to raw episodes (e.g., embedding-based similarity search selecting the top-K most relevant past trajectories), performance might degrade to match or fall below consolidated memory.

If interpretation (2) is correct, then the paper's prescription—"retain raw episodes"—is only viable at small scale, and the long-term need for abstraction remains. If interpretation (1) is correct, then even with retrieval, raw episodes would outperform consolidated abstractions, and the prescription is robust to scale. The paper provides no evidence to distinguish these.

A secondary consequence: several of the paper's specific findings may be artifacts of the full-context regime. The desklamp paraphrase cluster in Appendix G.1 (22 of 38 entries at stage 200 restating the desklamp directive) matters because those 22 entries consume context space that could have held other useful information. With retrieval, the solver might never see the desklamp entries unless the current task involves a desklamp—in which case, the repetition might be harmless. The overgeneralized memory items in §G.3 ("Prioritize actions that directly advance the current subgoal") might never be retrieved for any specific task, since they match everything and therefore rank low in relevance. The full-context regime makes memory clutter directly harmful; a retrieval regime might make it merely wasteful.

**Evidence in the paper.** The paper does include one condition that partially addresses this: the FS=N trajectory-log variants (Table 2, Table 3) downsample the full pool to a fixed number of shots (64, 32, 16) at random. On ALFWorld, FS=64 achieves 92% vs. All at 90%—the subset slightly outperforms the full pool, suggesting that random subsampling does not degrade performance and may even help. On WebShop, FS=32 achieves the best result for GPT-5-Mini (63) and FS=16 achieves the best for GPT-5.4-Mini (51), both outperforming the full All baseline. This suggests that at least some of the benefit of raw trajectories can be preserved under subsampling.

However, random subsampling is not retrieval—it does not select for relevance to the current task. The Incr. Keep and One-Pass Keep conditions (Table 2) allow the LLM to curate which trajectories to retain, which is a form of gated retention, but the retained trajectories are still all placed in context at evaluation, not selectively retrieved per task.

**Mitigation status.** Minimally addressed. The FS=N conditions demonstrate that the episodic-only advantage is not purely an artifact of having more context tokens, since smaller subsets can outperform larger ones. But the paper does not implement or evaluate a retrieval mechanism, does not vary context-budget constraints (e.g., limiting the solver to seeing at most 10 memory entries regardless of store size), and does not discuss how retrieval quality might interact with consolidation quality. The paper's own acknowledgment that "episodic accumulation cannot be the long-term answer: as deployment continues, raw histories grow unboundedly" (Section 1) directly identifies this gap but does not fill it. The question of whether retrieval from raw episodes outperforms retrieval from consolidated abstractions—the comparison that would matter in a scaled deployment—is left entirely open.

---

### No Comparison Against Non-LLM Abstraction Methods

**Assumption or constraint.** The paper's entire empirical apparatus is designed to test whether LLMs are reliable memory consolidators. The finding is that they are not. However, the paper does not test whether the observed failure modes are specific to *LLM-driven* consolidation or whether they would appear in any automated text-based abstraction process. The consolidator is always an LLM (GPT-5.4, GPT-5.4-mini, GPT-5-nano, or Qwen3.5 variants), and no non-LLM consolidation method is evaluated.

This matters for attributing the source of failure. The paper identifies three mechanisms—misgrouping, overgeneralization, overfitting—and attributes them to LLM limitations in metacognitive monitoring. But template-based or rule-based consolidation might exhibit similar patterns. For instance, a simple extractive summarizer that keeps the most frequent action sequences across episodes might also overfit to narrow streams and underrepresent rare but important patterns. A clustering-based grouper that merges episodes by surface lexical similarity might misgroup episodes just as the LLM does, since surface similarity and task-structural similarity are not the same.

**Consequence.** The paper's strongest claim—that "current LLMs are not reliable memory consolidators" (Section 1, Section 7)—conflates two claims that the evidence does not separate: (1) LLM-driven consolidation is unreliable, and (2) textual consolidation in general is unreliable. If non-LLM consolidation methods are equally unreliable, then the fault is in the paradigm (distilling trajectories into text), not in the specific tool (LLMs). If non-LLM consolidation is more reliable, then the prescription should be to replace LLM consolidators with simpler methods, not to abandon consolidation.

The paper's episodic-only baseline provides a partial answer: raw trajectories do outperform LLM-consolidated memory, but we do not know whether a simpler consolidator (e.g., extracting templates by counting frequent action sequences, grouping episodes by environment-returned task type labels, or applying off-the-shelf text clustering) would close the gap or even beat raw trajectories. If template extraction achieved 85% of the episodic-only performance on ALFWorld while using 10% of the context tokens, that would be a positive result for consolidation that the current experiments cannot reveal.

**Evidence in the paper.** None. The paper does not implement or reference any non-LLM consolidation baseline. The closest the paper comes is the Static-Group condition (Figure 3), which uses ground-truth task-type labels to group episodes before consolidation—but the consolidation itself is still performed by an LLM. A non-LLM baseline would use the ground-truth task-type labels for grouping and then apply a simple extraction rule within each group (e.g., "for pick_and_place tasks, the most common action sequence is: find object → pick up → go to destination → place"), bypassing the LLM entirely for the abstraction step.

**Mitigation status.** Not addressed. The paper does not discuss non-LLM consolidation methods as a comparison point or as a direction for future work. This is a significant omission because the paper's framing—diagnosing a failure mode in "the dominant paradigm of continuously updated textual memory"—implicitly encompasses all textual consolidation, not just LLM-driven variants. Distinguishing whether the paradigm or the tool is at fault would substantially sharpen the paper's recommendations.

### Test Set Sizes Are Small, and No Formal Statistical Testing Is Performed

**Assumption or constraint.** The paper explicitly acknowledges this limitation in Section 8:

> "due to API-cost constraints we report point estimates from a small number of repeats per question rather than formal error bars; we mitigate this by checking that conclusions hold across multiple models, benchmarks, and memory frameworks, but per-figure variance should be interpreted with this in mind."

The test set sizes are: 48 episodes for ALFWorld, 44 cases for ScienceWorld, 50 sessions for WebShop, 100 tasks for AppWorld, and varying sizes for ARC-AGI Stream (19 problems in the regression test of Figure 2, 400-step runs for Figures 5 and 9b). The number of repeats per question is typically one or two. There are no confidence intervals, error bars, or significance tests reported anywhere in the paper.

**Consequence.** Several of the paper's quantitative claims involve differences that may not be statistically reliable:

- The single-stage collapse in Table 11 shows drops of −6, −10, and −13 wins out of 48 (for Qwen3.5-4B, 9B, and 27B respectively). On a 48-episode test set, a 6-win difference corresponds to 12.5 percentage points. Without error bars, we cannot determine whether this drop is larger than the run-to-run variance of the consolidation process itself—would repeating the same 200-stage consolidation run from a different random seed produce the same collapse at stage 169, or was this a stochastic fluke?

- The Auto vs. Force comparison in Figure 5 shows a gap of roughly 5.4 percentage points at step 400 for GPT-5.4 (43.2% vs. 37.8%) and 9.5 points for Claude-Haiku (35.5% vs. 26.0%). These are cumulative success rates over 400 steps, meaning each data point aggregates many individual task outcomes. However, the curves are from single training runs—if the Auto agent happened to encounter an easier sequence of tasks than the Force agent, the gap could reflect task sampling variance rather than policy quality.

- The episodic-only vs. Auto + Episodic comparison in Figure 9a shows 54% vs. 62% (an 8-percentage-point gap) and 68% for "Auto (Episodic)" vs. 62% for "Auto + Episodic" (a 6-point gap in the opposite direction). With unknown variance and a test set of unspecified size for these specific bars, we cannot determine whether either gap is reliable.

The cross-model, cross-benchmark replication strategy that the paper uses as mitigation is reasonable for establishing the *qualitative* pattern (utility degrades, episodes outperform abstractions, gated beats forced), but it does not validate the *quantitative* claims about specific magnitudes. A practitioner trying to decide between episodic-only and gated-abstraction policies needs to know whether the 8-percentage-point difference in Figure 9a is real or noise—the paper provides no basis for that judgment.

**Evidence in the paper.** The paper's own acknowledgment (Section 8) is candid. The mitigation strategy is visible in the experimental design: key claims are tested across GPT-5.4, GPT-5.4-mini, GPT-5-mini, GPT-5-nano, Qwen3.5-27B, Qwen3.5-9B, Qwen3.5-4B, and Claude-Haiku-4.5; across ALFWorld, ScienceWorld, WebShop, AppWorld, and ARC-AGI Stream; and across CLIN, AWM, ACE, and Dynamic Cheatsheet. The qualitative consistency of the erosion pattern across this many axes is the paper's best evidence that the findings are not flukes. However, qualitative consistency is not the same as quantitative reliability, and several of the paper's specific numerical claims (the 4× overgeneralization rate in Fresh vs. Cumulative, the 2.3× page-turn ratio in the W8 ablation, the 203-point Fresh-vs-Cumulative gap) are cited as precise figures without associated uncertainty.

**Mitigation status.** Partially addressed through replication across models, benchmarks, and memory frameworks. The paper acknowledges the limitation explicitly. However, the paper does not report even simple measures of variance (e.g., standard deviation across the two repeats per question on ARC-AGI Stream), which would be feasible within the API-cost constraints since the data was already collected. The absence of any quantitative uncertainty reporting weakens the paper's specific numerical claims, even while the broad qualitative pattern is well-supported by the multi-axis replication.

---

### The Effect of Consolidator Model Scale on Failure Rate Is Not Systematically Explored

**Assumption or constraint.** The paper uses multiple models as consolidators—GPT-5.4, GPT-5.4-mini, GPT-5-mini, GPT-5-nano, Qwen3.5-27B—but does not systematically vary consolidator capability while holding other factors constant. The clearest case where consolidator scale matters is Figure 4: a GPT-5.4–produced starting memory is subsequently updated by GPT-5-nano, and the memory degrades. But the paper does not compare a GPT-5.4-produced memory updated by GPT-5.4 against the same memory updated by GPT-5-nano, which would isolate the effect of consolidator capability on erosion rate. Similarly, the paper does not test whether the Auto mode's gating decisions become more accurate with a stronger consolidator model, or whether the episodic-only advantage over consolidated memory shrinks as consolidator capability increases.

This matters because the paper's central claim—"current LLMs are not reliable memory consolidators"—is time-bound. If consolidation reliability scales with model capability, then a future, more capable model might consolidate reliably, and the paper's architectural prescriptions (separate stores, gated abstraction) might become unnecessary. If consolidation reliability does *not* scale with capability—if the failure modes are inherent to the textual abstraction paradigm rather than to model quality—then the prescriptions are durable.

**Consequence.** A practitioner deciding whether to invest in the paper's recommendations (episodic-first architecture, gated consolidation) versus waiting for better models needs to know whether the failure modes are model-quality-limited or paradigm-limited. The paper provides suggestive but inconclusive evidence:

- GPT-5.4 (the strongest model tested) produces a high-quality static memory (Figure 2: Static condition preserves ceiling accuracy) but a degrading streaming memory (Figure 2: Stream condition collapses by −47 points at R=10). This suggests that even the strongest model cannot consolidate reliably under streaming—supporting the paradigm-limited interpretation.

- GPT-5-nano (the weakest model tested) degrades a GPT-5.4–produced memory (Figure 4), but we do not know whether GPT-5.4 would preserve its own memory better than GPT-5-nano does. If GPT-5.4 erodes its own memory at the same rate as GPT-5-nano, that would strongly support the paradigm-limited interpretation. If GPT-5.4 erodes its own memory more slowly, that would support the model-quality-limited interpretation.

- The episodic-only baseline beats consolidated memory across multiple consolidator models (Table 2 includes GPT-5.4-Mini, GPT-5-Mini, and Claude-Haiku-4.5 as consolidators), but the gap is not compared across consolidator scale within a fixed benchmark and trajectory pool.

**Evidence in the paper.** Figure 4 provides the closest thing to a scaling comparison: the starting memory is GPT-5.4–produced, and the updating model is GPT-5-nano. The erosion is clear, but this confounds consolidator quality (GPT-5.4 vs. GPT-5-nano) with consolidation regime (static batch vs. streaming). The ALFWorld case study in Appendix G.1 uses GPT-5.4 for the initial seed memory and GPT-5-nano for streaming updates. The ARC-AGI Stream experiments in Figure 5 use GPT-5.4 and Claude-Haiku as solvers *and* memory managers (the model making consolidation decisions), but the figure compares Auto vs. Force within each backbone, not across backbones. We see that GPT-5.4 Auto achieves 43.2% vs. Claude-Haiku Auto at 35.5%, but this could reflect solver quality, consolidator quality, gating-decision quality, or all three.

**Mitigation status.** Not addressed. The paper does not discuss consolidator scale as a variable, does not compare erosion rates across consolidator models within a fixed experimental setup, and does not frame its findings with respect to model scaling trends. The paper's conclusion that "we see faulty memory as a central open problem in agentic memory" (Section 7) implicitly assumes the problem will persist, but this assumption is not tested. A simple experiment—running the same streaming consolidation procedure from Figure 2 using GPT-5.4, GPT-5.4-mini, and GPT-5-mini as consolidators and measuring the R=10 accuracy drop—would directly inform whether the problem is model-quality-limited.

### Memory Erosion Dynamics Are Not Characterized Over Truly Long Horizons

**Assumption or constraint.** The longest consolidation runs in the paper are 200 stages (ALFWorld, Appendix G.1; ScienceWorld, Figure 1a with 100 steps and 20 consolidation rounds) and 400 steps (ARC-AGI Stream, Figure 5). These are non-trivial horizons relative to prior work—most agentic-memory evaluations use fewer than 10 updates—but they are far short of the "long-horizon deployment" that the paper's motivation invokes. A production agent operating for weeks or months would accumulate thousands or millions of episodes, and the paper provides no evidence about whether the erosion curve plateaus, accelerates, or changes character at larger scales.

This matters for two reasons. First, the episodic-only prescription relies on bounded episodic buffers (50–100 entries in ARC-AGI Stream). Over very long horizons, a 100-entry buffer represents a tiny fraction of total experience, and a FIFO eviction policy would discard all but the most recent episodes. Whether the early episodes that happened to contain rare but valuable strategies are retained is a function of the agent's retention decisions in Auto mode, and the paper does not characterize retention quality over horizons where the buffer has turned over many times. Second, the abstract store in Auto mode is unbounded and the paper does not report its size over time—if it grows slowly but steadily, the retrieval problem (all entries in context at evaluation) eventually becomes prohibitive.

**Consequence.** The paper's findings are best understood as characterizing the *transient dynamics* of memory consolidation—what happens in the first few hundred updates—rather than the steady-state behavior of a long-running memory system. It is possible that:

- The erosion curve eventually plateaus: after enough updates, the memory reaches a stable state (perhaps a mixture of a few robust abstractions and a full episodic buffer of recent diverse episodes) and does not degrade further. In this case, the initial erosion is a transient cost that a long-running agent eventually recovers from or stabilizes at, making the paper's warnings less dire than they appear.

- The erosion accelerates: the paraphrasing and deduplication failures documented in Appendix G.1 get worse as the store contains more near-duplicate content, leading to accelerating collapse. In this case, the paper's 200-stage runs actually *understate* the severity of the problem.

- The episodic buffer saturates and becomes stale: if the agent retains the earliest diverse episodes and then fills the buffer, new episodes are evicted before being consolidated, and the memory stops learning. This would make episodic-only a good short-term strategy but a dead end for continual improvement.

Without longer-horizon experiments, we cannot distinguish these scenarios. The paper's acknowledgment that "episodic accumulation cannot be the long-term answer" (Section 1) recognizes this gap but does not quantify where the boundary lies.

**Evidence in the paper.** The ScienceWorld curve (Figure 1a) extends to 100 consolidation steps. For `|M|` = 16, the utility has dropped below the no-memory baseline and appears to still be declining at step 100—no plateau is visible. For `|M|` = 50 and `|M|` = ∞, the decline is decelerating but not clearly flattened. The ALFWorld curve (Figure 4) extends to 200 stages and shows continuing decline in most conditions, particularly with heterogeneous batches. The ARC-AGI Stream experiments (Figures 5, 9b) extend to 400 steps; the episodic-only and Auto curves are still rising, suggesting that the episodic store has not yet saturated in value, but the 400-step horizon is still modest relative to deployment scales.

**Mitigation status.** Not addressed. The paper does not extrapolate beyond its experimental horizons, does not fit functional forms to the erosion curves (e.g., logarithmic decay vs. linear decline), and does not discuss the computational requirements for running longer-horizon experiments. Given API-cost constraints, this is understandable as a scope limitation rather than an oversight, but it means the paper's prescriptions are validated for the transient regime (up to a few hundred updates) and their applicability to steady-state deployment is an extrapolation.

## 7. Implications and Future Directions

### How This Work Changes the Landscape

This paper shifts the conversation around agentic memory from one of *method construction* to one of *diagnostic skepticism*. Before this work, the dominant question was "how do we extract better abstractions from experience?" — with CLIN, AWM, Dynamic Cheatsheet, and ACE each proposing more sophisticated consolidation architectures while sharing the same underlying assumption: that consolidating trajectories into textual lessons is at worst neutral and at best the path to continual self-improvement. The paper demolishes this premise with evidence that is unusually difficult to dismiss, because it deliberately removes every input-side excuse. The trajectories are ground-truth solutions; the problems are ones the agent previously solved; the consolidator is GPT-5.4, the strongest model tested. Yet streaming consolidation causes regression on 46% of previously solved tasks (Figure 2). The fault is in the rewrite loop itself.

This is not an incremental finding that consolidation sometimes produces suboptimal lessons. It is a **paradigm-level reframing**: the question changes from "how do we consolidate better?" to "should we be consolidating at all right now, and if so, under what gating conditions?" This is analogous to the shift in reinforcement learning from human feedback when reward overoptimization was recognized not as a training bug to be fixed with better algorithms but as a fundamental property of optimizing against learned reward models. Here, consolidation-induced regression is recognized not as an implementation detail to be improved with better prompts, but as a property of lossy rewriting by LLMs that cannot be eliminated by making individual abstractions better — it must be *architected around*.

The paper resolves a tension that had been latent in the cognitive-science grounding of agentic memory. Prior work routinely cited Complementary Learning Systems theory (McClelland et al., 1995) as inspiration for extracting schemas from episodes, but conveniently omitted the theory's other half: that consolidation is harmful when non-selective, that episodic and schema-forming stores must be architecturally distinct so fast learning does not overwrite the slow one, and that consolidation should be gated by schema fit rather than triggered on every event (Tse et al., 2007; Sun et al., 2023). The paper demonstrates empirically what the theory predicts: collapsing both stores into a single rewrite loop and firing consolidation on every interaction recreates the interference conditions the dual-system architecture was meant to prevent. This does not invalidate the CLS framing — it validates it, by showing what happens when its architectural prescriptions are violated. The paper thus provides the first empirical evidence that CLS is not just a useful metaphor for agent memory but a design constraint: architectures that ignore it pay a measurable cost.

The paper redirects research attention along several axes:

- **Away from consolidation sophistication and toward consolidation gating.** The finding that the Auto regimen (which consolidates sparingly) matches or beats Force (which consolidates constantly) on ARC-AGI Stream, and that Episodic Management Only (no consolidation at all) is competitive with gated consolidation (Figure 9a), suggests that improving *when* consolidation happens is more important than improving *how* it happens. The paper's central architectural prescription — keep the episodic and abstract stores distinct, gate abstraction explicitly — does not require better prompts or stronger models; it requires a different system design.

- **Away from the no-memory baseline and toward the episodic-only baseline.** Table 2 demonstrates that raw trajectories often match or beat consolidated memory, yet prior work routinely omitted this comparison. The paper makes a compelling case that "a memory method whose value depends on distillation should be tested against the unabstracted rollouts it distills" (Section 4.2). This changes the evaluation standard for the field: beating the no-memory baseline is no longer sufficient; you must beat raw experience.

- **Toward failure-mode diagnosis as a first-class evaluation dimension.** The taxonomy of misgrouping, overgeneralization, and overfitting (§6) provides a diagnostic language that future memory systems can be evaluated against. A proposed consolidation method should be measured not just on aggregate accuracy but on whether it reduces each class of failure — a shift analogous to how the RLHF community moved from "does RL improve task performance?" to "does RL cause reward hacking, distributional shift, or goal misgeneralization?"

- **Toward controlled testbeds with known task structure.** ARC-AGI Stream demonstrates the value of a benchmark where the experimenter knows the ground-truth task taxonomy and can trace memory-management actions family-by-family. This enables measurements — misclassification count, family coverage, buffer composition — that are impossible on ALFWorld or ScienceWorld because those environments lack an explicit task ontology. The paper makes a strong implicit case that the field needs more benchmarks with this property, not fewer.

Perhaps the paper's most lasting contribution is making the **diagnostic burden** explicit. Before this work, a researcher proposing a new consolidation method could demonstrate improvement over no-memory and call it success. After this work, a researcher must also demonstrate that consolidation does not actively harm performance on previously solved tasks, that it outperforms simply retaining raw trajectories, and that its benefits are not limited to a narrow difficulty regime or a specific consolidation schedule. This raises the bar for the entire subfield in a way that is likely to be durable, because the diagnostic framework is independent of any particular model or consolidation algorithm.

### Follow-Up Research This Work Enables

**Systematic scaling of consolidator capability to test whether the failure modes are model-quality-limited or paradigm-limited.** The paper uses multiple consolidator models (GPT-5.4, GPT-5.4-mini, GPT-5-nano) but does not systematically vary consolidator scale while holding the experimental setup fixed. A direct experiment would replicate the Figure 2 streaming-consolidation protocol (19-problem ARC-AGI slice solved at 100% without memory) using a range of consolidator models — from GPT-5-nano through GPT-5.4 and potentially beyond (GPT-6, Claude-4, Gemini) — and measure the R=10 accuracy drop as a function of consolidator capability. If the drop shrinks monotonically with model scale (e.g., −47 points for GPT-5-nano, −30 for GPT-5.4, −15 for a hypothetical stronger model), the failure modes are model-quality-limited and the paper's architectural prescriptions are a temporary patch. If the drop plateaus at some non-zero floor regardless of scale, the failure modes are paradigm-limited — inherent to lossy textual rewriting — and the paper's architectural prescriptions are permanent design requirements. This experiment would also characterize *which* failure modes scale with capability (does misgrouping improve faster than overgeneralization? does overfitting get worse as models become better at pattern extraction?) and thus guide investment in architectural vs. capability improvements.

**Retrieval-aware consolidation evaluation to test whether the episodic advantage survives at scale.** The paper's finding that raw episodes outperform consolidated abstractions was measured in a regime where all memory entries fit in context. A direct follow-up would implement a retrieval mechanism (embedding-based similarity search selecting the top-K most relevant entries for the current task) and compare episodic retrieval against abstract retrieval under a fixed context budget. The ARC-AGI Stream testbed is well-suited for this: the known task taxonomy allows constructing evaluation sets that systematically vary the similarity between training and test tasks (same family, different skill; different family, same skill; unrelated), and retrieval quality can be measured as precision/recall against the ground-truth relevant family. A strong experiment would measure four conditions — (episodic + retrieval), (abstract + retrieval), (episodic + full context), (abstract + full context) — at increasing store sizes to characterize the crossover point where retrieval becomes necessary and whether the episodic advantage persists under retrieval. If episodic retrieval degrades faster than abstract retrieval as the store grows (because raw episodes are less semantically searchable than structured abstractions), the paper's prescription must be qualified: retain episodes at small scale, consolidate at large scale, with retrieval quality determining the transition point.

**Gating-policy learning: train a lightweight classifier to predict whether a batch of episodes should be consolidated, using the LLM's own Auto-mode decisions as supervision.** The paper shows that Auto mode outperforms Force (Figure 5, Figure 9a), but the gating decision itself requires an LLM call at every step — too expensive for practical deployment. A natural follow-up would use the action logs from Auto-mode runs (the decision JSON at each step, including the `reason` field) as training data for a lightweight classifier that takes as input features of the current episodic buffer (family diversity, buffer occupancy, average task success rate, embedding similarity between buffered episodes) and predicts whether consolidation is warranted. The classifier could be evaluated against the LLM's decisions (does it replicate the consolidation gating pattern?) and against downstream task performance (does gating by the classifier produce the same accuracy as gating by the LLM, at a fraction of the cost?). ARC-AGI Stream's exposed action vocabulary and known task taxonomy make this feasible: the family labels provide ground truth for whether episodes in a proposed consolidation batch genuinely share structure, enabling both supervised training (predict whether a batch is single-family) and evaluation (measure the classifier's false-positive and false-negative rates against the oracle family labels).

**Failure-mode-specific interventions to test whether misgrouping, overgeneralization, and overfitting can be independently reduced.** The paper identifies three failure modes but does not test targeted countermeasures. Follow-up experiments could isolate each: (1) To reduce misgrouping, provide the consolidator with ground-truth task-type labels and force within-family consolidation only (Static-Group serves as the upper bound; the question is whether providing labels to the LLM during consolidation achieves Static-Group performance without manual partitioning). (2) To reduce overgeneralization, require the consolidator to include explicit applicability preconditions and counterexample conditions in every abstracted entry (e.g., add a `do_not_use_when` field to the strategy memory format) and measure whether this reduces switch-induced forgetting (Figure 8b) or cross-task interference (Figure 8c). (3) To reduce overfitting, enforce a diversity constraint on the episodic buffer before consolidation is permitted (e.g., the buffer must contain episodes from at least 3 distinct families, or the embedding variance across buffered episodes must exceed a threshold), and measure whether this reduces the ID/OOD gap (Figure 11). Each intervention targets a specific mechanism; if one intervention reduces its target failure mode without affecting others, it provides causal evidence for the taxonomy's decomposability. If multiple interventions are needed, the failure modes are more entangled than the taxonomy implies.

**Cross-domain replication with a standardized episodic-only baseline to test the generality of the episodic advantage.** The paper demonstrates the episodic-only baseline's competitiveness across ALFWorld, ScienceWorld, WebShop, AppWorld, and ARC-AGI Stream, but all are text-based agent environments with procedural task structures. A direct extension would replicate the core comparison — consolidated memory (using the best available method per domain) vs. episodic-only vs. no-memory — on domains with different characteristics: (a) multi-modal environments where trajectories include visual observations (embodied AI benchmarks like Habitat, ALFRED, or robotics manipulation tasks), testing whether abstraction becomes more valuable when episodes are high-dimensional and in-context learning from raw pixels is less efficient; (b) knowledge-intensive QA where the relevant "experience" is retrieved documents rather than agent trajectories, testing whether the episodic advantage extends to factual recall; (c) social dialogue or negotiation tasks where task structure is less crisply defined, testing whether abstraction is more harmful when "task families" are fuzzy and the misgrouping risk is higher. Each domain should use a standardized episodic baseline — retain all raw interactions, place them in context (or use retrieval if context limits apply), compare against the domain's state-of-the-art consolidation method. A consistent result (episodic beats consolidated across diverse domains) would strengthen the paper's paradigm-level claims; a domain-dependent result (episodic wins on procedural tasks but loses on knowledge-intensive tasks) would sharpen the boundary conditions and inform when consolidation is genuinely necessary.

**Long-horizon consolidation dynamics to characterize whether erosion plateaus, accelerates, or reaches a steady state.** The paper's longest runs (200 ALFWorld stages, 100 ScienceWorld steps, 400 ARC-AGI Stream steps) show ongoing decline in most conditions but do not extend far enough to determine the asymptotic behavior. A follow-up would extend the ScienceWorld CLIN protocol (Figure 1a) or the ALFWorld iterative consolidation protocol (Appendix G.1) to 500–1000 steps, measuring utility at finer granularity and fitting functional forms (exponential decay, power law, logistic plateau) to the erosion curve. The key measurement is whether utility eventually stabilizes above the no-memory baseline — if it does, the initial erosion is a transient cost and the paper's warnings, while valid for short-to-medium horizons, overstate the long-term risk. If it stabilizes *below* the no-memory baseline, consolidation is actively harmful in steady state and should be avoided entirely (episodic-only with bounded retention becomes the only viable strategy). If it continues declining without bound, memory systems require periodic resets or re-initialization from raw episodes — a "reboot" mechanism that the paper does not discuss. The experiment would also track the LLM-judge labels (normal, overgeneralized, overspecific, garbage) from Appendix K.2 at each step to determine whether the composition of failure modes shifts over time (e.g., early erosion dominated by misgrouping, late erosion dominated by paraphrase duplication).

### Practical Applications and Downstream Use Cases

**Long-horizon agent deployments with bounded memory budgets.** For any organization deploying an LLM agent that accumulates experience over days or weeks — customer support bots that learn from resolved tickets, coding assistants that build a library of past solutions, research assistants that collect and synthesize findings — the paper's findings provide a direct architectural recommendation: maintain a bounded episodic buffer of raw successful trajectories (input–output pairs, action sequences, or code solutions), use them as in-context demonstrations at evaluation time, and disable automatic consolidation after every interaction. The paper's evidence that an episodic-only store with 50–100 entries matches or beats consolidated memory (Table 2, Figure 9a) translates to a concrete implementation: a FIFO buffer of the most recent N successful episodes, with an LLM-based retention/deletion policy if budget allows (Incr. Keep in Table 2), and no separate abstract store unless ablation shows it adds value beyond raw episodes. On ALFWorld, the episodic baseline reaches 90% task success (GPT-5.4-Mini) while ACE reaches 79% and AWM reaches 65% — the simpler architecture wins by a large margin. The cost savings are direct: no consolidation LLM calls at every step, no prompt space consumed by abstracted entries that may be paraphrases or overgeneralizations, and a memory store whose contents are auditable (raw trajectories are easier to inspect for correctness than abstracted "lessons").

**Self-improving agent pipelines where training data is generated by the agent itself.** In paradigms like STaR, ReST$^{EM}$, or rejection-sampling fine-tuning, an agent generates solutions to training problems, and correct solutions are used to improve the agent. The paper's finding that streaming consolidation from ground-truth solutions causes regression on previously solved tasks (Figure 2: 100% → 54% on the same problems) has direct implications for how the generated solutions should be stored and reused. If the agent consolidates its self-generated solutions into an abstracted memory between fine-tuning rounds, it risks degrading the very knowledge it acquired. The safer pipeline — and the one the paper's results support — is to retain the raw solutions as an episodic store, use them as in-context demonstrations during the next round of data generation (improving generation quality through example-based prompting rather than through abstracted memory), and fine-tune directly on the raw solutions without an intermediate consolidation step. The paper's phantom-strategy finding (§D.4) provides additional caution: if the pipeline exposes the consolidator to failed solutions (which is standard in STaR-like approaches, where both successes and failures inform the next iteration), the consolidator may distill recurring patterns from incorrect code into new "strategies" that are actively harmful.

**Evaluation suites for agentic-memory systems.** The paper's diagnostic framework — episodic-only baseline, misclassification count, family coverage, ID/OOD gap, Fresh-vs-Cumulative comparison — can be adopted immediately by teams developing or evaluating memory architectures. A minimal evaluation protocol would include: (1) an episodic-only baseline retaining the same trajectories the consolidator receives, with both full-context and fixed-shot (FS=N) variants; (2) a regression test where the agent is evaluated on tasks it previously solved without memory, after consolidating from those tasks' solutions, to measure consolidation-induced forgetting (analogous to Figure 2); (3) if the domain has identifiable task types, a misgrouping metric that counts how often consolidation merges episodes from different types; (4) a Fresh-vs-Cumulative comparison (consolidate only on the current task vs. consolidate jointly over all tasks seen so far) to measure cross-task interference. These diagnostics are independent of any specific consolidation method and can be layered onto existing benchmarks without requiring new environments. The paper's ARC-AGI Stream provides a reference implementation for the two-store architecture and exposed memory operations that makes these diagnostics straightforward to compute — a team could adapt its consolidator to the ARC-AGI Stream interface and obtain misclassification counts, family coverage, and buffer composition automatically from the action logs.

**Cost-efficient data curation for in-context learning at scale.** For applications where an LLM must solve many instances of structurally similar tasks (e.g., processing thousands of legal documents with the same extraction schema, generating SQL queries for a fixed database, answering customer queries about a specific product), the paper's episodic-only finding suggests a lightweight alternative to prompt engineering or fine-tuning: retain a diverse set of raw solved instances as a demonstration pool, and at inference time, populate the context with the most relevant past instances (by embedding similarity or keyword match). The paper's FS=N results (Table 2: FS=64 achieves 92% on ALFWorld vs. All at 90%) suggest that a curated subset can outperform the full pool, meaning the curation step (whether random, similarity-based, or LLM-driven) is itself a lightweight form of "memory management" that does not require textual abstraction. The cost profile is attractive: retaining raw instances costs only storage, similarity-based retrieval is computationally cheap compared to consolidation LLM calls, and the absence of an abstract store means there is no ongoing risk of consolidation-induced erosion as the pool grows. When the problem distribution shifts, old instances can be evicted by simple staleness heuristics rather than requiring the consolidator to unlearn and rewrite abstracted lessons — avoiding the switch-induced forgetting that Figure 8b demonstrates with a single task change.
