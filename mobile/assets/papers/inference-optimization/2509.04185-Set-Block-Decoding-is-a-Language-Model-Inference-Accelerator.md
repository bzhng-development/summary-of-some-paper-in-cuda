# Set Block Decoding is a Language Model Inference Accelerator

**ArXiv:** [2509.04185](https://arxiv.org/abs/2509.04185)

## 🎯 Pitch

Fine-tuning standard LLMs to generate multiple non-consecutive tokens in parallel—like unmasking a set rather than extending a sequence—can slash the number of forward passes by 3–5× with zero accuracy loss, but the real surprise is that these savings translate to actual wall-clock speedups only because modern GPU decoding is hopelessly memory-bandwidth-bound, not compute-bound.

---

## 1. Executive Summary

This paper introduces **Set Block Decoding (SBD)**, a paradigm for accelerating LLM inference that integrates standard next-token prediction with masked token prediction in a single architecture, enabling parallel decoding of multiple non-consecutive future tokens via advanced discrete-diffusion solvers like the Entropy Bounded Sampler (unmasking tokens with low predicted entropy). By fine-tuning Llama-3.1 8B and Qwen-3 8B on 70B tokens, SBD achieves a 3–5× reduction in the number of forward passes required for generation while matching NTP baselines on reasoning and code benchmarks (e.g., 3.4× speedup on LiveCodeBench v6 with no accuracy loss). The paper's roofline analysis establishes that these forward-pass savings translate to equivalent wall-clock speedups on modern GPUs, but only when block sizes remain moderate and batch sizes are small.

## 2. Context and Motivation

### The Core Problem: LLM Decoding Is Computationally Expensive, Not Because of Flops but Because of Memory

The fundamental problem this paper addresses is a subtle but critical bottleneck in LLM deployment: **the decoding stage is dominated by memory bandwidth, not computation**. Understanding this distinction is essential to grasping why SBD's approach works and why prior acceleration methods have been only partially successful.

When a transformer generates text, it processes one token at a time via next-token prediction (NTP). Each forward pass to generate a single new token must read the entire model weights from GPU memory (e.g., tens of gigabytes for an 8B-parameter model), along with the complete key-value (KV) cache that stores the attention states for all preceding tokens. The actual floating-point operations per generated token are minimal — just a few matrix multiplications through the network layers. This makes the decoding stage **memory-bandwidth-bound**, not compute-bound. The GPU's tensor cores sit mostly idle while the memory subsystem struggles to feed them data.

The paper quantifies this explicitly in Section 4 using a roofline model on an H100 GPU. For a standard 8B transformer generating single tokens (block size = 1), the computation is firmly in the memory-bound regime — the model weights and KV cache must be read from memory for every single token produced. This means that generating $L$ tokens requires $L$ complete memory reads of the model parameters, even though each read only produces one token of output. The practical consequence is that **latency scales linearly with sequence length** in a regime where the GPU's computational capacity is severely underutilized.

This problem matters enormously for real-world deployment. As the paper notes in Section 1, applications requiring low latency (interactive assistants, real-time code completion, conversational AI) and high throughput (batch inference pipelines, API serving) are directly bottlenecked by this per-token memory access cost. The sequential nature of NTP decoding — each token depends on all previous tokens — means this cost cannot be parallelized in the standard paradigm. Even though the transformer architecture itself is highly parallelizable during training, inference suffers from an inherent serial dependency that leaves hardware underutilized.

### Why Existing Solutions Fall Short: The Three-Category Landscape

The paper frames prior approaches to inference acceleration in three categories (Section 1), each with fundamental limitations that SBD is designed to overcome. Understanding these limitations is crucial to appreciating what makes SBD different.

**Model Compression (Quantization, Pruning, Distillation).** These techniques reduce the model size to reduce memory bandwidth pressure. While effective up to a point, they inherently trade off model quality for speed. Quantization to lower precision (e.g., FP8, INT4) reduces the bytes that must be read per parameter but introduces approximation error that compounds across layers. Pruning removes weights or attention heads but risks removing capabilities that were learned during pretraining. Distillation trains a smaller student model to mimic a larger teacher, but the student fundamentally has lower capacity. None of these approaches address the core serial dependency — they make each forward pass cheaper, but you still need $L$ forward passes.

**System-Level Optimization (Kernel Fusion, KV-Cache Management, Batching).** These approaches improve hardware utilization without changing the model. FlashAttention (Dao et al., 2022) fuses attention operations to reduce memory reads — the paper explicitly references and assumes this in its roofline analysis (Section 4.1). Continuous batching increases throughput by processing multiple requests simultaneously, but at the cost of increased latency for any individual request. Prefix caching avoids recomputation for shared prompt prefixes. These are important engineering improvements, but they don't change the fundamental fact that the model generates one token per forward pass. They optimize *how* the $L$ passes are executed, not the fact that there are $L$ of them.

**Algorithmic / Modeling Innovations.** This is where SBD lives, and where the prior work is most directly related. The paper identifies two sub-strategies:

*Speculative Decoding* (Leviathan et al., 2023; Chen et al., 2023) uses a fast draft model to propose multiple candidate future tokens, which are then verified by the larger target model in a single forward pass. The target model checks all draft tokens simultaneously using its causal attention, accepting a prefix of consecutive correct tokens. This reduces the number of target model forward passes. However, speculative decoding introduces system complexity (maintaining and synchronizing two models) and the draft model introduces a quality-speed tradeoff — if the draft model is too small, its proposals are often rejected, and if it's too large, the draft cost eats into the savings. Variants like Medusa (Cai et al., 2024) and Eagle (Li et al., 2024b) attach additional prediction heads to the target model itself to generate draft tokens, eliminating the separate draft model but adding architectural complexity that must be carefully designed and trained.

Critically, **all these speculative approaches are restricted to accepting a consecutive prefix of draft tokens**. The target model's verification step uses standard causal attention and can only validate tokens that form a coherent left-to-right sequence. This constraint fundamentally limits how many tokens can be accepted per target-model forward pass.

*Parallel Block Decoding* (Stern et al., 2018) attempts to predict $k$ future tokens simultaneously in a single forward pass by learning only the marginal distributions $p(x_i | x_{<t})$ for each future position independently. The joint distribution over the $k$ tokens is factorized as independent marginals:

$$p(x_I | x_{<t}) = \prod_{i \in I} p(x_i | x_{<t})$$

where $I = \{t, t+1, \ldots, t+k-1\}$. The paper is explicit about why this is problematic:

> "Since modeling the joint probability of more than a single token is intractable with today's vocabulary sizes $|V|$, e.g., the joint probability mass function of two tokens requires $|V|^2$ values in general"

This independence assumption is a crude approximation. Tokens in natural language are highly interdependent — the choice of word at position $t$ strongly affects what should appear at $t+1$. Generating them independently leads to incoherent outputs that violate syntactic and semantic constraints. This is why parallel block decoding still requires a verification step with the standard NTP model, and why only consecutive correct prefixes are accepted — the same limitation as speculative decoding.

### The Gap: Parallel Decoding Without Independence Assumptions

What should now be clear is a fundamental tension in prior work: **to parallelize decoding, you need to predict multiple tokens simultaneously, but modeling their joint distribution exactly is intractable**. The independence factorization used by parallel block decoding is the only tractable option but produces poor-quality outputs that need sequential verification. This verification step re-introduces the serial bottleneck that parallelization was meant to solve.

This is exactly the gap SBD fills. Instead of assuming independence among future tokens, SBD models **conditional distributions where some future tokens are observed and others are masked**:

$$p(x_i | x_{<t}, x_J) \quad \text{for } i \in M, \; J \subset I, \; M = I \setminus J$$

By iteratively revealing tokens — first decoding the ones the model is most confident about, then conditioning on those to decode the remaining ones — SBD builds the joint distribution of the $k$ future tokens as a product of conditional distributions:

$$p(x_I | x_{<t}) = \prod_{j=1}^{\ell} \prod_{i \in D_j} p(x_i | x_{<t}, x_{I_{j-1}})$$

This is **exact** when the tokens in each decoding step $D_j$ are conditionally independent given the already-revealed tokens (Section 2.2, Equation 7). In practice, conditional independence is not guaranteed, but the Entropy Bounded Sampler (Ben-Hamu et al., 2025) provides a principled way to choose which tokens to decode together based on an upper bound on their mutual information. Tokens with low entropy (the model is confident about them individually) and low mutual information (they don't strongly depend on each other) can be safely decoded in parallel with minimal error.

### How SBD Positions Itself Relative to Prior Work

The paper distinguishes SBD from prior approaches along four dimensions that collectively make it a practical and effective solution:

**1. Against Speculative Decoding: Single Model, No Draft.** SBD eliminates the two-model complexity of speculative decoding. There is no draft model to train, maintain, or synchronize. There are no additional prediction heads (Medusa, Eagle) to architect and tune. The model is a single transformer with the same architecture as the base NTP model — the only difference is the training objective and the attention mask. The paper emphasizes this simplicity as a key advantage:

> "Simplicity: Single language model, no architectural changes and additions; no added hyper-parameters during training"

**2. Against Independent Parallel Decoding: Conditional, Not Marginal.** Where Stern et al. (2018) and similar approaches predict marginals independently, SBD predicts conditionals where the model sees an arbitrary subset of already-decoded future tokens. This is a fundamentally different — and more powerful — modeling assumption. The paper frames this as moving from independent parallel decoding (Equation 3) to set/mask parallel decoding (Equation 5), drawing on work by Ghazvininejad et al. (2019), Lou et al. (2023), Gat et al. (2024), and others. The key insight is that conditioning on some future tokens makes the predictions for the remaining tokens more accurate, enabling higher-quality parallel decoding.

**3. Against Pure Diffusion Models: Preserves NTP Performance with KV-Caching.** Recent masked diffusion language models (LLaDa, Dream, Mercury, DiffuCoder, Gemini Diffusion) have shown competitive quality with autoregressive models but face efficiency challenges. The paper identifies a specific limitation: these models use bidirectional attention on the full sequence, which makes **exact KV-caching impossible**. The attention states for all tokens depend on all other tokens, so when new tokens are generated, the entire attention computation must be redone. Prior work has introduced approximate KV-caching heuristics (Ma et al., 2025; Liu et al., 2025b) that exploit the empirical observation that mask token representations change slowly, but these are approximations that trade some quality for speed.

SBD solves this by combining causal attention for past tokens with bidirectional attention only within the current block of future tokens (Figure 3). Past tokens — including previously completed blocks — use standard causal attention with exact KV-caching. Only the current block's tokens attend bidirectionally to each other. This architecture means:

- All past blocks can be exactly KV-cached with zero approximation error.
- The bidirectional attention within the current block enables the model to condition future tokens on each other, enabling the set parallel decoding mechanism.
- The model can generate text of arbitrary length by iterating block by block, with each completed block being cached and treated as causal past for subsequent blocks.

**4. Against Hybrid Models (BD3-LM, CtrlDiff): Fine-Tuning from Existing NTP Models.** Block diffusion models like BD3-LM (Arriola et al., 2025) and its extensions (CtrlDiff, Fathi et al., 2025, Esoteric Language Models) share a similar goal — combining autoregressive and parallel generation — but the paper argues they focus on different aspects. BD3-LM proposes a semi-autoregressive block structure with block-causal attention but uses diffusion-based unmasking within blocks. CtrlDiff adds adaptive block sizing. Fathi et al. explore hybrid noising processes for improved quality at the cost of longer inference. Sahoo et al. (2025) propose a hybrid attention scheme to improve KV-caching.

SBD's key differentiation is its **pragmatic fine-tuning approach**: 

> "While these methods focus on a similar goal, fusing NTP with MATP models, our work introduces an efficient method to fine-tune an existing NTP model, taking advantage of the efficient NTP training, while providing it with the ability for fast block decoding"

This is not a minor detail — it's a practical enabler. Training a hybrid model from scratch requires massive computational resources and discards the investment already made in pretrained NTP models. SBD's fine-tuning recipe (Algorithm 1) requires only a continuation of training with a modified loss function and attention mask, using the same data and optimizer. The paper shows this with two widely-used model families (Llama-3.1 8B and Qwen-3 8B), demonstrating that existing pretrained models can be converted to SBD models without architectural changes. The key experimental finding that makes this work is the necessity of retaining the NTP loss term (Section 3.2, Figure 4): training only the masked prediction loss causes the model to forget its autoregressive capabilities, which are essential for both quality and for the KV-caching mechanism.

### The Broader Significance: Changing Inference from Serial to Block-Parallel

Stepping back, the paper is best understood as proposing a **paradigm shift in how we think about LLM inference**: from generating one token at a time to generating blocks of tokens with adaptive parallelization. This shift is enabled by three converging ingredients: (1) a training procedure that preserves NTP quality while adding masked prediction capability, (2) an attention architecture (causal past + bidirectional block) that enables exact KV-caching, and (3) a principled sampling algorithm (EB-Sampler) that adaptively decides how many tokens to generate in parallel based on model confidence.

The practical question the paper must answer — and does answer through its benchmark results (Table 1) and roofline analysis (Section 4) — is whether the reduction in model forward passes (3–5× fewer) actually translates to wall-clock speedups when each forward pass now processes a block of multiple tokens (which is more expensive). The roofline analysis demonstrates that for the block sizes and batch sizes used in the experiments, each block forward is only marginally more expensive than a single-token forward because the computation remains memory-bandwidth-bound — the dominant cost is still reading the model weights from memory, regardless of whether the forward produces one token or sixteen. This is the paper's central efficiency argument, and it's what makes SBD practically viable where previous parallel decoding methods weren't: **you get multiple tokens for the memory-bandwidth cost of approximately one**.

## 3. Technical Approach

### 3.1 Reader Orientation

Set Block Decoding is a **drop-in training procedure and inference strategy** that converts a standard autoregressive language model into one that can generate multiple future tokens in parallel per forward pass, without changing the model architecture. It solves the problem of inference latency by replacing the serial "one token per forward pass" bottleneck with a block-parallel scheme where each forward pass produces multiple tokens, while preserving exact KV-caching and matching the quality of standard next-token prediction.

### 3.2 Big-Picture Architecture (Diagram in Words)

The SBD system has four major components that operate at different phases:

1. **The SBD Transformer** — a single model with the same parameters as the original autoregressive LM but a modified attention mask that supports both causal attention (over past tokens) and bidirectional attention (within the current block of future tokens). It accepts a sequence where some tokens in the prediction block are real words and others are the special `[MASK]` token. This is the only model in the system — there is no separate draft, verifier, or additional prediction head.

2. **The SBD Training Procedure** — a fine-tuning recipe that adds a masked token prediction loss term alongside the standard next-token prediction loss. The key mechanism is dual-sequence construction: the input is split into a causal prefix (processing all tokens autoregressively) followed by a masked block (where some fraction of tokens are replaced with `[MASK]`). The model predicts both the next causal token and the masked tokens simultaneously in one forward pass, with the appropriate attention pattern per region.

3. **The Entropy Bounded (EB) Sampler** — the inference-time algorithm that decides, at each step, which masked tokens to reveal in parallel. Given the model's predicted probability distribution over each masked position, it computes the entropy (uncertainty) of each prediction, sorts masks from lowest to highest entropy, and reveals as many as possible while keeping the sum of entropies below a user-specified threshold `$\gamma$`. Low `$\gamma$` values produce fewer tokens per step (higher accuracy, lower speedup); high `$\gamma$` values reveal more tokens per step (lower accuracy, higher speedup).

4. **The Block-Wise Generation Loop** — the outer orchestration that processes the full sequence in chunks. The prompt is first processed ("prefilled") with all tokens attended to causally. Then, for each block of `$k$` future positions, the system initializes them all as `[MASK]`, iteratively applies the EB-Sampler to reveal tokens within the block, and once the block is fully decoded, it is KV-cached as past context for subsequent blocks. This loop repeats until the full generation length `$L$` is reached.

Information flows as follows: The prompt enters → the transformer pre-fills and caches all prompt tokens → the prediction block is initialized as all masks → the EB-Sampler iteratively calls the model, each time receiving probability distributions over the remaining masked positions, and selectively reveals low-entropy tokens → once the block is fully decoded, it becomes part of the KV-cached past → the next block is initialized and the process repeats → the full generated sequence is assembled from all completed blocks.

### 3.3 Roadmap for the Deep Dive

- **First**, the attention mask architecture (Equation 9, Figure 3), because it is the only structural change from standard transformers and defines the model's dual capability: causal processing of the past and bidirectional processing of the future block.
- **Second**, the training procedure (Algorithm 1, Equation 14), including how input sequences are constructed, how the dual loss combines NTP and masked prediction, and why the NTP term is essential.
- **Third**, the inference algorithm (Algorithm 2 and 3), covering the block-wise generation loop, how KV-caching is updated block-by-block, and how the EB-Sampler selects which tokens to unmask at each step.
- **Fourth**, the Entropy Bounded Sampler in detail (Equation 8), explaining why entropy is used as the error proxy, how the threshold `$\gamma$` controls the accuracy-speedup tradeoff, and the theoretical justification from the discrete diffusion literature.
- **Fifth**, the roofline analysis (Section 4, Equations 15–17), which is not a separate system component but is essential for understanding why the reduction in model forwards translates to wall-clock speedups — explaining the memory-bandwidth-bound nature of the computation and why block forwards are only marginally more expensive than single-token forwards.

### 3.4 Detailed, Sentence-Based Technical Breakdown

This is a **methods and systems paper** whose core idea is that a transformer can be trained to simultaneously perform next-token prediction (for past tokens, with causal attention) and masked token prediction (for future tokens within a block, with bidirectional attention) using the same parameters and attention mechanism with only a modified attention mask. This dual training enables inference-time parallelization via iterative unmasking: instead of decoding tokens one-by-one left-to-right, the model decodes a block of `$k$` tokens by repeatedly predicting the remaining masked positions and revealing the most confident ones.

---

#### The SBD Attention Mask: Causal Past + Bidirectional Block

The only architectural difference between an SBD transformer and a standard autoregressive transformer is the attention mask. The forward pass computes two types of outputs depending on whether the query token is in the causal region or the prediction block, defined by Equation 9:

$$z_t = f_\theta(x_1, \ldots, x_{t-1}; \text{ })$$
$$(\hat{z}_t, \ldots, \hat{z}_{t+k-1}) = f_\theta(x_1, \ldots, x_{t-1}; \hat{x}_t, \ldots, \hat{x}_{t+k-1})$$

where `$x_1, \ldots, x_{t-1}$` are the past tokens (before the semicolon), `$\hat{x}_t, \ldots, \hat{x}_{t+k-1}$` are the `$k$` tokens in the prediction block (after the semicolon), `$z_t \in \mathbb{R}^V$` is the logits vector for predicting the next token at position `$t$` using only causal attention, and `$\hat{z}_t, \ldots, \hat{z}_{t+k-1}$` are the logits vectors for predicting the tokens in the prediction block using bidirectional attention among themselves plus causal attention to the past. The semicolon is notational: it separates the causal inputs (before `;`) from the bidirectional inputs (after `;`). The paper explicitly states that all tokens before the semicolon use causal attention, while tokens after the semicolon use bidirectional attention.

**What this computes:** The forward pass simultaneously produces two sets of outputs. `$z_t$` is the standard next-token prediction logits for position `$t$`, computed by attending causally to all past tokens `$x_1, \ldots, x_{t-1}$`. The block logits `$\hat{z}_t, \ldots, \hat{z}_{t+k-1}$` are computed by having the block tokens attend causally to the entire past AND bidirectionally to each other — each token in the block sees every other token in the block, regardless of position. This means that when some block tokens are real words (already decoded) and others are masks (still to be decoded), the mask positions can attend to the already-decoded words in the same block, incorporating that information into their predictions.

**Why this form:** This hybrid attention pattern is the architectural foundation that enables SBD's dual capability. The causal attention on the past preserves the autoregressive property needed for exact KV-caching — the key insight is that tokens in the past are never affected by tokens in the future, so their attention keys and values can be computed once and cached permanently. The bidirectional attention within the block enables the model to condition future token predictions on other future tokens that have already been decoded, which is what makes set parallel decoding possible. Pure diffusion models use bidirectional attention everywhere, which breaks KV-caching because every token's representation depends on every other token. Pure autoregressive models use causal attention everywhere, which prevents conditioning on future tokens within the same block. The semicolon-based split — shown visually in Figure 3 as an attention mask where the lower-right quadrant (block tokens attending to block tokens) is fully filled while the lower-left quadrant (block tokens attending to past tokens) shows block-causal structure — gives both properties simultaneously.

The attention mask is implemented concretely via FlexAttention (Dong et al., 2024), with two variants: one for training and one for inference.

**Training attention mask (Algorithm in Figure 9):** The training sequence is constructed as a concatenation of the original sequence and its masked version (see training section below), creating a `$2 \times \text{seq\_len}$` matrix conceptually divided into four quadrants:

- **Top-left quadrant (past tokens attending to past tokens):** Standard causal attention — token at query position `$q$` can attend to key positions `$kv \leq q$` only if both are in the first half of the concatenated sequence.
- **Bottom-right quadrant (block tokens attending to block tokens):** Block-structured attention — token at query position `$q$` can attend to key position `$kv$` only if both are in the second half and belong to the same block. Blocks are determined by dividing the position within the second half by `block_len` (a randomly sampled integer from `[2, max_block_size]` at each training step).
- **Bottom-left quadrant (block tokens attending to past tokens):** Block-causal attention — a query token in the second half (block) at block index `$q\_block$` can attend to any key token in the first half (past) whose block index `$kv\_block$` is strictly less than `$q\_block$`. This means a block only sees past blocks that are fully before it, not tokens in the current or future blocks of the past.
- **Top-right quadrant:** No attention is allowed — past tokens cannot see future block tokens.

**Inference attention mask (Algorithm in Figure 10):** The inference mask is simpler because the sequence structure is different — there is no concatenation of original and masked copies. Instead, the inference mask depends on a single parameter: `causal_point`, the index of the first token in the prediction block. The rule is: a query at position `$q$` can attend to a key at position `$kv$` if either `$kv \leq q$` (standard causal attention) OR `$q \geq \text{causal\_point}$` (all tokens from the prediction block onward can attend to all other tokens). This means:

- All tokens before `causal_point` use standard causal attention (they see themselves and all preceding tokens).
- All tokens from `causal_point` onward can attend to EVERY token in the sequence — they see the full past plus each other with full bidirectional attention.

The transition at `causal_point` reflects that once we begin decoding a block, all tokens in that block need to see each other, and also need to see the full past (which is now KV-cached from previous blocks).

#### The SBD Training Procedure: Dual-Sequence Dual-Loss

SBD training follows Algorithm 1 and is designed to teach the model to predict both the next token autoregressively AND masked tokens within a block simultaneously. The key design choice is that **training uses a single forward pass** that processes a concatenated input containing both tasks, with the loss computed over different regions of the output.

**Step 1: Construct the masked sequence.** Given an input sequence `$x = (x_1, \ldots, x_L)$` of length `$L$`, the procedure creates a copy `$\hat{x} = (\hat{x}_1, \ldots, \hat{x}_L)$` where each token is independently replaced by the mask token with probability `$\eta$`, and kept unchanged with probability `$1 - \eta$`. The noising probability `$\eta$` is randomized uniformly in `$(0, 1)$` for each training example:

$$\hat{x}_i = \begin{cases} \text{[MASK]} & \text{with prob } \eta \\ x_i & \text{with prob } 1 - \eta \end{cases}$$

where `$\eta \sim \text{Uniform}(0, 1)$` is sampled once per training sequence.

**What this computes:** For each token in the original sequence, we flip a biased coin to decide whether to hide it (replace with `[MASK]`) or reveal it (keep the original token). The masking probability `$\eta$` is itself random, meaning that in some training examples nearly all tokens are masked while in others very few are masked. This is critical: the model learns to predict tokens given arbitrary subsets of revealed tokens, which is exactly what it needs to do during inference when different numbers of tokens have been revealed at different steps of the EB-Sampler.

**Why this form:** The uniform randomization of `$\eta$` over the full interval `$(0, 1)$` ensures the model sees the full spectrum of masking ratios during training — from nearly all tokens revealed (similar to standard NTP) to nearly all tokens masked (similar to pure masked prediction from scratch). This is different from typical masked language model training (like BERT) which uses a fixed masking probability (e.g., 15%). The paper does not explicitly justify the uniform distribution over a fixed single value, but the rationale follows from the EB-Sampler's behavior: during inference, the number of masked tokens in the block changes at each iteration — starting with all `$k$` tokens masked and progressively decreasing. Training with random `$\eta$` exposes the model to all these regimes without needing to simulate the multi-step sampling process during training.

**Step 2: Form the training input and labels.** The training input is a concatenation of the original sequence (as the causal context) and the masked sequence (as the prediction target):

- **Input:** `$\text{input\_ids} = \text{concat}(x_{1:L-1}, \hat{x}_{1:L})$` — the original sequence up to position `$L-1$` followed by the full masked sequence of length `$L$`.
- **Labels:** `$\text{label\_ids} = \text{concat}(x_{2:L}, \text{parallel\_labels}_{1:L})$` — the next-token targets for the first half (original sequence shifted by one) and the masked prediction targets for the second half. For the parallel labels, positions where the input is NOT masked (i.e., `$\hat{x}_i = x_i$`) are set to `-100` (the ignore index in PyTorch's cross-entropy, meaning no loss is computed for that position). Only positions where `$\hat{x}_i$` is actually `[MASK]` contribute to the masked prediction loss.

Additionally, **positional embeddings are duplicated:** the same positional encoding is used for position `$i$` in the original sequence and position `$i$` in the masked sequence (Figure 7, line 25–26). This is essential: the model needs to know that `$x_i$` and `$\hat{x}_i$` occupy the same temporal position in the sequence, so the positional signal must be identical. Without this duplication, the concatenated sequence would assign different position IDs to the same logical position, confusing the model about word order.

**Step 3: Compute the SBD loss (Equation 14).** The loss function combines two terms:

$$\mathcal{L}(x, \hat{x}; \theta) = -\sum_{t=2}^{L} \log p_\theta(x_t | x_{<t}; \text{ }) - \sum_{t \in \mathcal{T}} \sum_{i=0}^{k-1} \mathbb{1}_{\hat{x}_{t+i} = \text{[MASK]}} \log p_\theta(x_{t+i} | x_{<t}; \hat{x}_t, \ldots, \hat{x}_{t+k-1})$$

where `$\mathcal{T} = \{1 + \ell k \mid \ell = 0, 1, 2, \ldots, \lfloor \frac{L}{k} \rfloor - 1\}$` is the set of starting indices for blocks of size `$k$` in the masked sequence.

**What each term is:**

- **First summation (NTP loss):** The standard autoregressive next-token prediction loss. For each position `$t$` from 2 to `$L$` (all positions with a valid previous token to condition on), we compute the negative log probability of the true token `$x_t$` given all previous tokens `$x_{<t}$` using the causal attention path (the output `$z_t$` from Equation 9a). This is computed over the first half of the concatenated input (the original sequence). The sum runs over all `$L-1$` positions.

- **Second summation (masked token prediction loss):** The masked prediction loss computed only over the prediction blocks. For each block starting position `$t \in \mathcal{T}$` (spaced `$k$` apart), and for each position `$i$` within that block (from 0 to `$k-1$`), if the token at `$\hat{x}_{t+i}$` is a mask token, we compute the negative log probability of the true token `$x_{t+i}$` given the past context `$x_{<t}$` AND the noisy block `$\hat{x}_t, \ldots, \hat{x}_{t+k-1}$` (which contains both real tokens and masks), using the bidirectional attention path (the output `$\hat{z}_{t+i}$` from Equation 9b). The indicator `$\mathbb{1}_{\hat{x}_{t+i} = \text{[MASK]}}$` ensures loss is only computed for positions that were actually masked — positions where the true token was revealed in the input contribute zero to this term.

The two loss terms are simply added together (no weighting coefficient is mentioned or needed — the implicit weighting comes from the proportion of masked vs. unmasked tokens, which varies with `$\eta$`).

**Why this form — two simultaneous tasks in one forward pass:** This dual-loss design is the paper's key training innovation. Instead of training the model separately for NTP and masked prediction (which would require two forward passes or alternating training), the concatenated input structure allows both losses to be computed from a single forward pass. The model processes the original sequence causally to maintain its autoregressive capability, and simultaneously processes the masked block with bidirectional attention to learn the masked prediction capability. The attention mask (Figure 9) ensures that the two computations don't interfere: the NTP outputs (top half) are computed purely causally without seeing the masked future, while the MATP outputs (bottom half) can see the original sequence plus bidirectionally attend among themselves.

**Why require the NTP loss term:** This is empirically critical, as demonstrated in Section 3.2 (Figure 4 and Table 2). When training SBD without the NTP loss term (only the masked prediction term), the model's autoregressive performance degrades significantly — the NTP loss increases and likelihood benchmark scores drop by 5–12 percentage points (Table 2). The NTP term serves as a regularizer that preserves the model's sequential generation capability. During inference, the model must still generate tokens left-to-right within each block (just not one-at-a-time) and must maintain coherent autoregressive generation across blocks. Without the NTP loss, the model "forgets" how to do this. The paper explicitly states:

> "without the NTP loss term, SBD training will not maintain the AR capabilities of the base model, while training SBD with the full loss only results in a slightly higher NTP loss."

The "slightly higher NTP loss" — visible in Figure 4 as a small gap between the gray (pure NTP) and orange (SBD) curves — represents the trade-off: the model's autoregressive quality degrades marginally in exchange for gaining the masked prediction capability that enables 3–5× inference speedup.

**Training hyperparameters (from Section 3.1 experiments, not separate ablation):** For the 8B model fine-tuning experiments, the paper uses AdamW optimizer with learning rate `$3 \times 10^{-4}$`, warmup of 200 iterations, and cosine annealing schedule. Batch size is 2M tokens with 34k total iterations. The block size during training is **randomly sampled uniformly from `[2, 16]`** at each training step — the paper calls this "variable block size." This is important: the model never sees a fixed block size during training, so it learns to predict masks given arbitrary block sizes up to 16, which provides flexibility at inference time (though the paper's main experiments use fixed block sizes at inference).

The training data consists of 70B tokens, mixing reasoning data (mitigated versions of OpenCodeReasoning and OpenMathReasoning) and instruction data (a publicly available mix similar to the one used for Llama-3.1 Instruct).

#### The SBD Inference Loop: Block-Wise Generation with Iterative Unmasking

Inference with SBD follows Algorithm 2 (the outer loop) and Algorithm 3 (the `sample_block` subroutine). The process is:

**Outer loop (Algorithm 2):**

1. **Pre-filling:** The prompt `$x_{<0}$` (all tokens before the first generated token) is processed with a standard forward pass using causal attention. All keys and values from this prefill step are cached. The paper does not detail the block structure during prefill — the prefill handles the entire prompt at once, which is standard for transformer inference.

2. **Block iteration:** For each subsequent block of size `$k$` (indexed by `$t = 0, k, 2k, \ldots, L-k$`), call `sample_block(x_{<t})` to generate the next `$k$` tokens. After the block is returned, it is appended to the sequence.

3. **Termination:** Continue until `$L$` total tokens (beyond the prompt) have been generated.

**The `sample_block` subroutine (Algorithm 3):**

This is where the EB-Sampler operates within a single block of `$k$` future tokens:

1. **Initialization:** All `$k$` positions in the block are set to `[MASK]`: `$\hat{x}_{t:t+k-1} = (m, m, \ldots, m)$`.

2. **Iterative unmasking loop (while masks remain):** At each iteration:

   - **Forward pass:** Compute the logits `$\hat{z}_{t:t+k-1}$` for all `$k$` block positions using the model. There are two variants depending on context:
     - **KV-cached path (first iteration and `$t \geq k$`):** If this is the first iteration of unmasking AND the current block is not the first block (`$t \geq k$`), use the KV-cached past: the input is the last `$k$` tokens of the previous block (serving as causal context) plus the current masked block: `$f_\theta(x_{t-k:t-1}, \text{KV-cache}; \hat{x}_{t:t+k-1})$`. The KV-cache contains all tokens before `$x_{t-k}$`, which have already been cached from previous blocks. This is what enables the model to scale to arbitrary generation lengths without recomputing attention over the entire history.
     - **Full-computation path (otherwise):** If it's a subsequent iteration within the same block OR the first block of generation, compute the full forward pass: `$f_\theta(x_{<t}; \hat{x}_{t:t+k-1})$`. Note that for subsequent iterations within a block, the `$\hat{x}$` have changed (some masks have been replaced with predicted tokens from the previous iteration), but the past `$x_{<t}$` is unchanged — only the prediction block inputs change between iterations.

   - **Compute probabilities and select which masks to reveal:** Convert the logits `$\hat{z}_{t:t+k-1}$` to probability distributions via softmax for each position. Apply the EB-Sampler criterion (Equation 8, described in the next subsection) to determine which subset of the currently-masked positions should be revealed. For each selected position, sample a token from its predicted distribution (at temperature 0, this is argmax/greedy) and replace the `[MASK]` with the sampled token.

   - **Repeat** until no masks remain in the block.

3. **Return the fully decoded block** appended to the input sequence.

**The KV-caching distinction (lines 3–7 of Algorithm 3):** This is a subtle but important optimization. On the VERY FIRST unmasking iteration of a block, if there is at least one full previous block (`$t \geq k$`), the model can use the KV-cache from all tokens before `$x_{t-k}$` and only needs to process the last `$k$` tokens (`$x_{t-k:t-1}$`) plus the masked block. This is because the attention mask for block tokens allows them to see all past tokens with block-causal attention (Figure 3, lower-left quadrant), and since previous blocks are fixed and never change, their keys and values can be cached. On SUBSEQUENT unmasking iterations within the same block, however, the block tokens themselves have changed (some masks were replaced with predicted tokens), so their self-attention values within the bidirectional block quadrant must be recomputed. The algorithm handles this by falling through to the non-cached path.

**The block-causal boundary condition:** The paper notes that the block tokens attend to past tokens in chunks: a block at index `$q\_block$` sees past blocks with indices strictly less than `$q\_block$`. This means the most recent past block (at index `$q\_block - 1$`) IS visible to the current block — the condition is `$q\_block\_idx\_bl > kv\_block\_idx\_bl$` in Figure 9, not `$\geq$`. This design ensures that the current block has full context of the immediately preceding block, which is necessary for coherent generation, while still enabling KV-caching of all past blocks that will never change.

#### The Entropy Bounded (EB) Sampler: Adaptive Token Unmasking

The EB-Sampler (Ben-Hamu et al., 2025) is the inference-time algorithm that decides which subset of currently-masked tokens to reveal at each iteration. It operates within a single block of `$k$` tokens, where some have already been decoded (the set `$J$`) and the remaining are still masked (the set `$M = I \setminus J$`). The core idea is to decode in parallel only those tokens whose predictions are both confident AND conditionally independent of each other.

**Step 1: Compute predicted distributions and entropies.** For each masked position `$i \in M$`, the model provides a probability distribution over the vocabulary: `$p(x_i | x_{<t}, x_J)$`. The entropy of this distribution is:

$$H(p(x_i | x_{<t}, x_J)) = -\sum_{v \in \mathcal{V}} p(x_i = v | x_{<t}, x_J) \log p(x_i = v | x_{<t}, x_J)$$

where `$\mathcal{V}$` is the vocabulary of size `$V$`.

**What entropy measures here:** Entropy quantifies the model's uncertainty about token `$i$`. If the model is highly confident (e.g., 99% probability on one token), entropy is near zero. If the model is uncertain (e.g., uniform distribution over many tokens), entropy is high (maximum `$\log V$`). Low entropy means the model "knows" what this token should be; high entropy means it's still unsure.

**Step 2: Sort masked positions by entropy.** Sort all masked indices `$i \in M$` in ascending order of entropy to obtain `$i_1, i_2, \ldots, i_{|M|}$`, where `$i_1$` has the lowest entropy (most confident) and `$i_{|M|}$` has the highest (least confident).

**Step 3: Determine how many to reveal (Equation 8).** Find the largest integer `$s \geq 1$` such that:

$$\sum_{j=1}^{s-1} H(p(x_{i_j} | x_{<t}, x_J)) \leq \gamma$$

where `$\gamma > 0$` is a user-prescribed threshold. At least one token is always revealed (when `$s=1$`, the sum over `$j=1$` to `$0$` is empty, i.e., zero, which is always `$\leq \gamma$`).

**What this computes in operational terms:** Starting from the most confident prediction, accumulate the entropies of the predicted distributions. Keep including tokens as long as the cumulative entropy of the already-included tokens (EXCLUDING the `$s$`-th token itself) stays below the threshold `$\gamma$`. The `$s$`-th token is the first one that would push the cumulative sum above `$\gamma$`, so we decode tokens `$i_1, \ldots, i_s$` — all tokens up to but not including the one that breaks the budget. The "-1" in the summation bound is the critical detail: the summation bound is `$s-1$`, meaning the entropy of the `$s$`-th token (the boundary token) is NOT included in the constraint. This ensures that at least the most confident token is always decoded (when `$s=1$`, the sum is empty), and the constraint bounds the entropy of all PREVIOUSLY decoded tokens, not the one currently being added.

**Step 4: Decode the selected tokens in parallel.** For each `$i \in \{i_1, \ldots, i_s\}$`, sample a token from `$p(x_i | x_{<t}, x_J)$`. At temperature 0 (greedy decoding, which the paper uses for all benchmarks), this is argmax. These tokens are added to the revealed set `$J$`, and the masks `$M$` are correspondingly reduced. The process repeats from Step 1 with the updated `$J$` and `$M$`.

**Why entropy as the error proxy:** The EB-Sampler is theoretically motivated by bounding the approximation error of decoding tokens independently when they are not truly conditionally independent. The paper's Section 2.2 explains this:

> "The EB-Sampler finds at each step a subset of tokens to decode in parallel, `$D_j$`, by identifying the masked tokens with low mutual information, which quantifies the degree of dependence among these tokens. Since the mutual information cannot be computed without the full joint probability, an upper bound is used instead utilizing the entropy of the marginals"

The mutual information between two tokens `$x_a$` and `$x_b$` given context is bounded above by the minimum of their individual entropies: `$I(x_a; x_b | \text{context}) \leq \min(H(x_a), H(x_b))$`. So tokens with low individual entropy have low maximum possible mutual information — they are unlikely to be strongly dependent on other tokens. Decoding multiple low-entropy tokens in parallel is therefore a safe approximation: even if they are not perfectly independent, the error introduced by treating them as independent is bounded by their individual uncertainties. The cumulative sum of entropies in Equation 8 approximates the total error from parallel decoding.

**Why the threshold `$\gamma$` and its effect:** `$\gamma$` is the single inference-time hyperparameter that controls the speed-accuracy tradeoff:

- **`$\gamma$` small (e.g., 0.1 as used for `$\gamma_{\text{low}}$` on reasoning tasks):** Only very confident predictions qualify — the cumulative entropy bound is tight. Few tokens are revealed per iteration, requiring more iterations to complete the block, but each revealed token is likely correct. This preserves quality at lower speedup.
- **`$\gamma$` large (e.g., 0.35 for `$\gamma_{\text{high}}$` on reasoning, 0.6 on chat tasks):** More tokens can be revealed per iteration because the entropy budget is looser. The block is decoded in fewer iterations (higher speedup) but more errors are introduced because tokens with higher uncertainty are being decoded independently.
- **`$\gamma = 0$`:** The cumulative sum constraint becomes `$0 \leq 0$`, which is satisfied only when `$s-1 = 0$` (empty sum), so exactly 1 token — the most confident one — is revealed per iteration. This reduces to essentially autoregressive decoding within the block.
- **`$\gamma \to \infty$`:** The constraint is always satisfied, so ALL remaining masked tokens are decoded in one iteration regardless of confidence. This reduces to independent parallel decoding (Section 2.1), which is fast but low-quality.

The paper's benchmark results (Table 1) use two specific `$\gamma$` settings chosen per task type: for reasoning tasks (MATH500, AIME25, LiveCodeBench), `$\gamma_{\text{low}} = 0.1$` and `$\gamma_{\text{high}} = 0.35$`; for chat benchmarks (GSM8K, HumanEval+, MBPP), `$\gamma_{\text{low}} = 0.35$` and `$\gamma_{\text{high}} = 0.6$`. The higher thresholds for chat tasks likely reflect that these benchmarks have shorter outputs and the errors from parallel decoding are less consequential.

#### The Roofline Analysis: Why Block Forwards Are Not Proportionally More Expensive

The roofline analysis in Section 4 is not part of the SBD algorithm per se but is essential for understanding why SBD's reduction in model forward passes translates to wall-clock speedup. The analysis answers the question: if each SBD forward pass processes `$k$` tokens instead of 1, isn't each forward pass `$k$` times more expensive? The answer — crucial for SBD's viability — is no, because inference is memory-bandwidth-bound, not compute-bound.

**The roofline model (Equation 15):**

$$\text{theoretical\_time} = \max\left(\frac{\text{total\_flops}}{\text{PEAK\_FLOPS}}, \frac{\text{total\_memory}}{\text{MEMORY\_BANDWIDTH}}\right)$$

where `$\text{total\_flops}$` is the number of floating-point operations needed for the forward pass, `$\text{PEAK\_FLOPS} = 1978 \times 10^{12}$` FLOPS (FP8 on H100), `$\text{total\_memory}$` is the total bytes that must be transferred between GPU memory and compute units, and `$\text{MEMORY\_BANDWIDTH} = 3.35 \times 1024^4$` bytes/second (H100 bandwidth). The max determines the bottleneck: if memory transfers take longer than the actual computation, the operation is **memory-bound** and the GPU's compute units sit idle while waiting for data.

**What this model reveals for small block sizes:** For block sizes typical in SBD experiments (1–16) and small batch sizes (1–4), the memory term dominates — the time to read model weights (several GB for an 8B model) plus KV cache far exceeds the time for the actual matrix multiplications. This means that going from block size 1 (NTP) to block size 16 (SBD) adds only marginal computational cost because the computation is free relative to the memory access cost. The model weights must be read from memory regardless of whether they produce 1 token or 16 tokens — the major cost is already paid.

This is quantified in Table 3, which shows the "slowdown factor" of a block forward versus a single-token forward. For block size 8 with batch size 1, the slowdown is at most 1.015× across all KV cache lengths up to 4 million tokens — meaning a block-8 forward is only 1.5% slower than a block-1 forward. For block size 16, it's at most 1.004× — essentially identical cost. For block size 32, the slowdown reaches 1.015–1.029× depending on cache length, still negligible. Only when block sizes reach 64 or batch sizes reach 8–16 does the slowdown become significant (1.0–3.8×, with colored cells in the table indicating non-trivial overhead).

**Why larger blocks/batches become compute-bound:** As `$k$` or batch size increases, the matrix multiplications in the linear layers (FFN up/down projections, attention Q/K/V/O projections) scale with `$O(k^2)$` for attention and `$O(k)$` for linear layers, while the memory transfer of weights stays constant. Eventually, the total FLOPS term in Equation 15 overtakes the memory term — the computation becomes compute-bound. The roofline analysis in Appendix A.2 (Figure 11) explicitly calculates these times by summing the roofline-predicted times for the attention operation (Equation in `calculate_fused_attention_roofline`) and all linear layers (Equation in `calculate_linear_layers_roofline`) for each block and batch size.

**The wall-clock speedup formula (Equation 16):**

$$\text{speedup}(l, k) = \frac{k \cdot \text{time}(1)}{\text{time}(2k) + (l - 1) \cdot \text{time}(k)}$$

where `$l$` is the number of model forward passes used by SBD to decode a block of `$k$` tokens, `$\text{time}(1)$` is the forward time for a single token (NTP), `$\text{time}(2k)$` is the time for the first unmasking iteration (which processes `$2k$` tokens: `$k$` past context + `$k$` block tokens), and `$\text{time}(k)$` is the time for subsequent iterations within the block.

**What this computes:** The numerator is the total time for standard NTP to generate `$k$` tokens sequentially (each taking `$\text{time}(1)$`). The denominator is the total time for SBD to generate the same `$k$` tokens: the first iteration processes `$k$` past context tokens plus the `$k$`-token masked block (total `$2k$` tokens), and each of the remaining `$l-1$` iterations processes only the `$k$`-token block (the past is cached). The speedup is the ratio of these total times.

**Why `$\text{time}(2k)$` for the first iteration:** The first SBD iteration within a block needs to see the immediately preceding `$k$` tokens as causal context — this is `$x_{t-k:t-1}$` in Algorithm 3, line 4. These `$k$` tokens, plus the `$k$` masked block tokens, give a forward pass of `$2k$` tokens. Subsequent iterations only need to re-evaluate the `$k$` block tokens because the past context hasn't changed (it's cached). This asymmetry means the per-block overhead is slightly higher than `$l \cdot \text{time}(k)$`, and the formula accounts for it.

**Practical translation: NFEs to wall-clock (Equation 17 and Table 4):**

$$\text{NFE\_speedup} = \frac{k}{l}$$

The NFE speedup is the ratio of tokens generated to model forwards used — if you generate 16 tokens in 4 model forwards, the NFE speedup is 4×. Table 4 shows the theoretical wall-clock speedup `$\text{speedup}(l, k)$` for different combinations of NFE speedup, block size, batch size, and KV cache length. The key finding is in the uncolored cells: for block sizes 8–16, batch sizes 1–4, and NFE speedups of 2–4×, the wall-clock speedup closely matches the NFE speedup. For example, at batch size 1, block size 16, and NFE speedup = 4×, the theoretical wall-clock speedup is 3.982× (Table 4, middle batch_size=1 subtable, column "16", row "NFE_speedup=4") — essentially identical to the 4× forward-pass reduction. This validates the paper's central claim that the 3–5× NFE reduction in Table 1 "are expected to translate to almost identical factors of wall-clock savings in practice" (Section 4.1).

**Where the translation breaks down (colored cells):** When block sizes or batch sizes become large, the wall-clock speedup falls below the NFE speedup. For batch size 8, block size 64, NFE speedup = 4×, the wall-clock speedup drops to 1.978× — less than half the NFE reduction. This is because at these scales, the computation has become compute-bound: each forward pass is genuinely more expensive, and the savings from fewer forwards are partially offset by the higher per-forward cost. The paper's recommended operating regime — moderate block sizes (8–16) and small batch sizes — stays in the memory-bound zone where the translation is near-perfect.

## 4. Key Insights and Innovations

### Innovation 1: Inference Acceleration Through Memory Utilization, Not Computation Reduction

The dominant mental model for LLM inference acceleration has long been "reduce the amount of computation." Whether through quantization (fewer bits per operation), pruning (fewer weights to compute), or speculative decoding (use a cheaper draft model for most tokens), the implicit assumption is that the bottleneck is the GPU's arithmetic throughput — that generating tokens faster requires doing less math per token.

SBD's roofline analysis in Section 4 reveals a fundamentally different diagnosis. The decoding stage of standard autoregressive generation is not compute-bound but **memory-bandwidth-bound**. The GPU's tensor cores sit mostly idle while the memory subsystem struggles to feed them model weights and KV-cache entries. Each NTP forward pass to generate a single token requires reading the entire model (tens of gigabytes for an 8B model) from HBM. Those reads dominate the latency. The actual matrix multiplications to produce one additional token are trivial by comparison.

This diagnosis reframes the acceleration problem entirely. Instead of asking "how can we do less computation per token?" — which leads to quality-degrading approximations like quantization or draft-model mismatch — SBD asks **"how can we extract more tokens per memory read?"** If the model weights must be read from memory regardless of whether they produce one token or sixteen, the optimal strategy is to amortize that memory access cost over multiple simultaneously-generated tokens.

This is not an incremental engineering insight. It changes the design space for inference optimization from *reducing operations* to *increasing output density per memory transaction*. The paper quantifies this precisely: Table 3 shows that for block sizes up to 16 with batch size 1, a block forward is at most 1.015× slower than a single-token forward. The memory bandwidth cost of reading the model weights dominates so completely that adding 15 additional tokens of computation is essentially free. This explains why previous parallel decoding methods failed to deliver wall-clock speedups: they didn't achieve sufficient NFE reduction to overcome their per-forward overhead, because the overhead was conceptualized as compute rather than memory. SBD succeeds because it targets the actual bottleneck.

The broader implication is that future inference acceleration research for memory-bound models should prioritize techniques that increase "tokens per weight-read" rather than techniques that reduce FLOPs per token — a design principle that the field had not articulated in these terms before.

### Innovation 2: The NTP Loss Term as a Capability Preservation Mechanism, Not a Secondary Objective

When training hybrid models that combine autoregressive and parallel generation capabilities, the natural assumption — visible in prior masked diffusion models like LLaDa and Dream that train exclusively on masked prediction — is that the parallel generation objective is sufficient. After all, if the model learns to predict arbitrary subsets of tokens given arbitrary context, then predicting tokens left-to-right is just a special case.

SBD empirically disproves this assumption and, in doing so, establishes a **diagnostic principle**: the NTP loss term is not merely one of two equally-weighted training objectives but a **capability anchor** that prevents the model's autoregressive skills from degrading. Figure 4 shows that training with only the masked prediction loss causes the NTP loss to drift upward; Table 2 quantifies the downstream damage with likelihood benchmark drops of 5–12 percentage points across MMLU, Hellaswag, and ARC when the NTP loss term is removed.

What makes this a conceptual contribution rather than a mundane ablation is what it reveals about the relationship between the two prediction modes. The NTP and MATP tasks are not independent skills that can be learned separately and combined. They share the same model parameters, and the bidirectional attention used for MATP — where each block token attends to all other block tokens — creates a different representational geometry than the strictly causal attention used for NTP. Training exclusively on MATP with bidirectional attention causes the model to optimize its representations for a regime where future context is always available, which undermines the causal conditioning needed for autoregressive generation. The NTP loss term serves as a regularizer that preserves the ability to generate without peeking into the future, even as the model simultaneously learns to exploit bidirectional context when it is available.

This finding has direct practical implications beyond SBD: any approach that retrofits parallel generation capabilities onto a pretrained autoregressive model must retain the autoregressive training signal as an explicit objective, not assume that masked prediction training will implicitly preserve it. The paper's demonstration that this can be done with a simple sum of losses — no weighting coefficient, no curriculum, no architectural changes — makes this insight actionable for practitioners.

### Innovation 3: The Semicolon Architecture as a Unified Attention Framework

The field has long treated causal and bidirectional attention as architectural alternatives — you choose one based on whether you're building an autoregressive or a masked language model. Prior hybrid approaches like BD3-LM (Arriola et al., 2025) and Esoteric Language Models (Sahoo et al., 2025) attempted to combine them but required novel attention mechanisms (block-causal, hybrid bidirectional-over-clean/tokens-causal-over-masked) that depart from standard transformer implementations.

SBD's key conceptual move is to recognize that **causal and bidirectional attention can coexist in the same forward pass simply by splitting the input sequence at a "semicolon" boundary**, with causal attention to the left and bidirectional attention to the right. The attention mask in Figure 3 — where the lower-right quadrant is fully filled and the rest follows causal or block-causal patterns — is a standard block-sparse attention pattern that can be implemented with existing FlexAttention kernels. There is no new attention mechanism, no modified transformer layer, no additional parameters.

This is not merely an implementation convenience. It's a **unification of the two attention paradigms** in a framework that:
- Preserves exact KV-caching for all tokens left of the semicolon (unlike pure diffusion models, which require approximate caching heuristics because bidirectional attention couples all tokens).
- Enables full bidirectional context within the prediction block (unlike speculative decoding, which can only verify consecutive left-to-right prefixes).
- Allows the model to be trained with a single forward pass that computes both NTP and MATP outputs simultaneously (unlike BD3-LM, which requires separate autoregressive and diffusion steps).

The semicolon is notational but the attention boundary it represents is fundamental. It creates a clean separation between "tokens that are fixed and can be cached" (the past) and "tokens that are being actively predicted and need to interact with each other" (the block). This boundary moves forward block-by-block during inference, with each completed block crossing from the bidirectional side to the cached-causal side — a mechanism that the paper implements trivially by shifting the `causal_point` parameter in the inference attention mask (Figure 10).

### Innovation 4: Difficulty-Adaptive Decoding via Entropy Thresholds Without Difficulty Estimation

The paper's main results in Section 3.2 demonstrate a critical practical property: the EB-Sampler's entropy threshold `γ` provides **automatic, per-token adaptation of the speed-accuracy tradeoff without requiring explicit difficulty estimation**. This is a distinctive capability compared to approaches that require pretraining a difficulty classifier or generating thousands of samples to bin problems by hardness.

The mechanism is self-calibrating: on tokens where the model is confident (low entropy predictions), the EB-Sampler automatically reveals many tokens in parallel, producing high speedup. On tokens where the model is uncertain (high entropy), the cumulative entropy constraint forces serial, essentially autoregressive decoding — high accuracy at low speedup. The model's own uncertainty serves as a local difficulty signal that modulates the degree of parallelization.

This is significant because it means SBD does not need the expensive difficulty-estimation overhead that characterized prior adaptive decoding methods. The paper references Liu et al. (2024) adapted block size selection for diffusion models, which typically requires explicit heuristics or learned controllers. SBD's approach is simpler: the threshold `γ` sets a global budget for tolerable approximation error, and the model's local uncertainty distributes that budget across tokens, spending more (decoding fewer tokens per step) where it's needed and less where it isn't.

The evidence for this behavior is visible in the spread of NFE reduction across benchmarks in Table 1. Reasoning tasks with long, complex outputs (MATH500, AIME25, LiveCodeBench) achieve 3.2–5.4× speedup at `γ_high` because the model is confident about many tokens (structural code patterns, mathematical notation) and can reveal them in parallel. Chat benchmarks with shorter, more open-ended outputs achieve lower speedups (2.2–3.0×) because the higher entropy on those tasks naturally constrains parallelization. The fact that a single `γ` value works across all problems in a benchmark — without per-problem tuning — demonstrates the self-calibrating property. This contrasts with methods requiring per-problem strategy selection, where the overhead of difficulty estimation can negate the inference savings.

### Innovation 5: Fine-Tuning as the Bridge Between Pretrained NTP and Parallel Decoding

The paper's practical contribution — demonstrating that SBD can be obtained by fine-tuning existing pretrained 8B models rather than training from scratch — may seem like an implementation detail, but it represents a **strategic framing** with significant implications for adoption. Prior hybrid and diffusion language models (LLaDa, Dream, Mercury, BD3-LM) required training from scratch or from early-stage checkpoints, discarding the enormous investment already made in pretrained autoregressive models like Llama and Qwen.

SBD's approach of continuing training from a pretrained checkpoint with a modified loss function and attention mask, using the same data pipeline and optimizer, means that the acceleration capability comes at the marginal cost of fine-tuning (70B tokens, which is roughly 0.5% of a typical 15T-token pretraining run). This turns the question from "should we train a new hybrid model?" to "should we spend a small fraction of our training budget to add 3–5× inference speedup to our existing model?"

The evidence that this works without architectural changes is the paper's most practically important result. Table 1 shows that SBD models match or exceed NTP baselines on nearly all benchmarks when using greedy NTP decoding (the SBD NTP row vs. the baseline NTP row), confirming that fine-tuning did not degrade the model's original capabilities. The speedup rows then show that the gained parallel decoding capability translates to real NFE reduction. The fact that this works on two distinct model families (Llama-3.1 and Qwen-3) suggests the approach is not architecture-specific.

The negative result in Appendix K — where ReST^EM-style on-policy optimization of the revision model caused performance degradation — is also instructive. It suggests that the simplicity of SBD's fine-tuning recipe (fixed data distribution, straightforward dual loss, no RL components) is not a limitation but a feature. More complex training procedures that seemed promising actually hurt performance, reinforcing that the core innovations — the dual-loss training and the semicolon attention mask — are sufficient.

This positions SBD not as a new class of model but as a **post-training augmentation** that can be applied to any pretrained autoregressive LM, analogous to how instruction tuning or RLHF are applied to base models. The parallel decoding capability becomes an additional capability that can be "switched on" during fine-tuning, rather than requiring a fundamentally different training paradigm.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The paper evaluates on a suite of reasoning, coding, and mathematics benchmarks. Reasoning benchmarks are AIME25, LiveCodeBench v6 (Jain et al., 2024), and Math500 (Lightman et al., 2023). Chat benchmarks are GSM8K (Cobbe et al., 2021), HumanEval+ (Liu et al., 2023), and MBPP (Austin et al., 2021). These span competition math, competitive programming, grade-school math, function synthesis, and basic programming tasks, providing coverage across problem types.

- **Base model(s).** Two 8B-parameter models are fine-tuned: Llama-3.1 8B base (Meta, 2024) and Qwen-3 8B base (Yang et al., 2025a). For ablation studies in Section 3.2, a smaller 3B transformer (28 layers, hidden dimension 3072) is trained from scratch and fine-tuned. The 8B models are chosen as "representative of the capabilities of many contemporary LLMs" and sit in a regime where NTP performance is non-trivial but the inference cost is substantial enough that 3–5× speedup is practically meaningful.

- **Metrics.** The primary metric is **benchmark accuracy/pass@1 (%)** — the fraction of problems for which the model's generated output is correct. For reasoning benchmarks, the model generates with thinking tokens and up to 32k output tokens; for chat benchmarks, it generates 1024 tokens (HumanEval+, GSM8K) or 256 tokens (MBPP) without thinking. **NFE speedup** is measured as the ratio of model forward passes used by NTP (baseline, counted as 1×) versus SBD, computed only "until the end of the problem's solution" — the paper calls this the "generate until" logic from Ben-Hamu et al. (2025), meaning speedup measurement stops when the solution is complete, not at a fixed token count.

- **Baselines.** Three categories of baselines appear:
  - **NTP baseline for each base model**: The same Llama-3.1 8B or Qwen-3 8B base model fine-tuned on the exact same 70B tokens of data with the same training hyperparameters, but using only the standard next-token prediction loss (no masked prediction). This isolates the effect of the training data from the SBD method.
  - **External baselines in Table 1**: Gemini diffusion (Deepmind, 2025), Mercury (Labs et al., 2025), Diffucoder (Gong et al., 2025), Llada 1.5 (presumably LLaDa 1.5; You et al., 2025; Liu et al., 2025a), and Dream-coder (Xie et al., 2025). These are included for reference but are not directly comparable to SBD since they use different training data, model architectures, and training paradigms.
  - **Ablation baselines**: "SBD w/o NTP loss" (Section 3.2) — training the masked prediction loss without the autoregressive term. "Factor" sampler (Wu et al., 2025a) as an alternative to EB-Sampler (Appendix B.1).
  - For the SBD model itself, three sampling configurations serve as its own baselines: **SBD (NTP)** — standard autoregressive greedy decoding using the NTP path (`p_θ(x_t | x_{<t}; )` in Equation 10), demonstrating that fine-tuning preserves original capabilities; **SBD (SBD, γ_high)** — higher speedup, lower accuracy setting; **SBD (SBD, γ_low)** — lower speedup, higher accuracy setting.

- **Generation budget / compute accounting.** The unit of test-time compute is **number of model forward passes (NFEs)**. For NTP, generating `L` tokens requires `L` NFEs. For SBD, generating `L` tokens using blocks of size `k` requires approximately `l` NFEs per block, where `l` is the number of EB-Sampler iterations to decode `k` tokens. The NFE speedup is `k/l`. All speedup numbers in Table 1 are NFE speedups, measured on the benchmark problems themselves, not theoretical estimates. The paper does NOT account for the computational cost of the EB-Sampler's entropy computation and sorting within each iteration (which runs on the CPU or GPU outside the model forward pass and is negligible relative to the forward pass cost). The roofline analysis in Section 4 separately validates that NFE speedup translates to wall-clock speedup.

- **Cross-validation / statistical protocol.** There is no cross-validation, statistical significance testing, or multiple-seed reporting. All benchmark results are single-run evaluations. The ablation studies in Section 3.2 use training iteration counts (8.5k, 17k, 34k) and show performance trajectories across these checkpoints, providing some indication of training stability, but no error bars or confidence intervals are reported. For the two 8B models (Table 1), the results represent a single fine-tuning run per model with a single evaluation. The absence of statistical rigor is a notable weakness for a paper claiming to match NTP baseline performance — "matching" could be within noise for the sample sizes involved.

### Main Quantitative Results

#### SBD Matches NTP Performance While Enabling 3–5× Forward-Pass Reduction

The headline results appear in Table 1. Across all six benchmarks and both base models, SBD with NTP decoding (the SBD model sampled autoregressively with greedy decoding) matches or exceeds the NTP baseline trained on the same data:

| Benchmark | Llama-3.1 NTP | Llama-3.1 SBD (NTP) | Qwen-3 NTP | Qwen-3 SBD (NTP) |
|-----------|---------------|---------------------|------------|-------------------|
| MATH500 | 80.2 | 81.6 | 86.6 | 86.6 |
| AIME25 | 33.3 | 30.0 | 33.3 | 33.3 |
| LiveCodeBench v6 | 31.5 | 31.3 | 36.6 | 37.4 |
| GSM8K | 85.3 | 85.6 | 90.1 | 90.4 |
| HumanEval+ | 56.7 | 57.9 | 69.5 | 66.5 |
| MBPP | 70.4 | 70.9 | 78.0 | 77.7 |

The maximum deviation is Llama-3.1 on AIME25 (33.3 → 30.0, a 3.3 percentage point drop) and Qwen-3 on HumanEval+ (69.5 → 66.5, a 3.0 point drop). All other differences are ≤1.9 points. This confirms that **SBD fine-tuning does not degrade the model's original autoregressive capabilities on these benchmarks**.

When sampled with the EB-Sampler (γ_low), the models achieve 3.0–3.9× NFE speedup (average across benchmarks: ~3.2× for Llama-3.1, ~3.4× for Qwen-3) while maintaining accuracy within ~1–2 points of the NTP baseline on most benchmarks. Specific numbers (Table 1):

- **Llama-3.1 SBD (γ_low, 3.0× avg speedup):** MATH500 81.0 (vs. 80.2 NTP baseline, +0.8), AIME25 30.0 (vs. 33.3, −3.3), LiveCodeBench 31.7 (vs. 31.5, +0.2), GSM8K 84.2 (vs. 85.3, −1.1), HumanEval+ 57.9 (vs. 56.7, +1.2), MBPP 69.5 (vs. 70.4, −0.9).
- **Qwen-3 SBD (γ_low, 3.2× avg speedup):** MATH500 85.0 (vs. 86.6, −1.6), AIME25 33.3 (vs. 33.3, 0.0), LiveCodeBench 37.2 (vs. 36.6, +0.6), GSM8K 90.1 (vs. 90.1, 0.0), HumanEval+ 66.5 (vs. 69.5, −3.0), MBPP 77.5 (vs. 78.0, −0.5).

At the higher-speedup setting (γ_high), average speedup increases to 3.4× (Llama-3.1) and 3.8× (Qwen-3), with larger accuracy drops:

- **Llama-3.1 SBD (γ_high, 3.4× avg):** MATH500 80.4 (−0.8 from NTP baseline, but actual NFE speedup on MATH500 is 3.23× as noted in the table), AIME25 23.3 (−10.0, with 4.50× speedup), LiveCodeBench 29.9 (−1.6, with 4.59× speedup).
- **Qwen-3 SBD (γ_high, 3.8× avg):** AIME25 drops to 26.6 (−6.7) while achieving 5.06× speedup; LiveCodeBench achieves 5.36× speedup with accuracy 33.3 (−3.3).

A critical detail: the speedup factors in parentheses in Table 1 are NOT the average speedup across all benchmarks but **per-benchmark speedups**. For example, Llama-3.1 SBD (γ_high) achieves 3.23× on MATH500, 4.50× on AIME25, 4.59× on LiveCodeBench, 2.34× on GSM8K, 2.95× on HumanEval+, and 2.66× on MBPP. The "3.4×" listed next to the sampling method name appears to be an approximate average or selected representative value. The chat benchmarks consistently show lower speedups (~2.2–3.0×) than reasoning benchmarks (~3.2–5.4×), consistent with the EB-Sampler revealing fewer tokens per step on tasks where the model is less confident.

Figure 1 (the LiveCodeBench-V6 bar chart) visualizes this tradeoff: NTP baselines sit at 1× speedup with accuracies ~31.5% (Llama-3.1) and ~36.6% (Qwen-3); SBD with increasing γ moves rightward (higher speedup) while accuracy stays flat or declines gradually, reaching 3.6–4.7× speedup with minimal accuracy loss.

#### SBD Fine-Tuning Requires the NTP Loss Term to Preserve Autoregressive Capability

Section 3.2 (Figure 4 and Table 2) contains the paper's most important ablation. When training SBD **without the NTP loss term** (only the masked prediction objective in Equation 14's second summation), the model rapidly loses autoregressive performance:

- **Figure 4:** During 3B model pretraining, the NTP loss curve for "SBD w/o NTP" (blue) diverges upward from both the pure NTP baseline (gray) and full SBD (orange), indicating that masked prediction training alone degrades the model's causal prediction accuracy. The full SBD training (orange) shows only a small gap above the NTP baseline — the model maintains near-original NTP capability.

- **Table 2** quantifies this on likelihood benchmarks after 1T tokens of training (SBD models start from a 900B checkpoint and train the last 100B tokens with the SBD objectives). SBD w/o NTP loss shows catastrophic degradation: MMLU drops from 50.9 (NTP baseline) to 43.2 (−7.7 percentage points), Hellaswag drops from 76.4 to 71.1 (−5.2 points), ARC-E drops from 71.2 to 58.8 (−12.4 points), ARC-C drops from 51.4 to 43.2 (−8.2 points). Full SBD training shows much smaller deviations: MMLU −1.0%, ARC-C −2.8%, with GPQA actually improving +3.6% and Winogrande +0.7%.

The paper interprets this as evidence that "without the NTP loss term, SBD training will not maintain the AR capabilities of the base model" (Section 3.2, under Figure 4). The NTP loss term serves as an essential regularizer that anchors the model's representations to the causal prediction task.

#### SBD Requires More SFT Steps Than NTP to Reach Performance Parity

Section 3.2 (Figure 5) shows the training dynamics during supervised fine-tuning of a 3B model. At 8.5k iterations, SBD with EB-Sampler substantially underperforms NTP training across HumanEval, MBPP, and GSM8K — the accuracy gap is roughly 5–10 points. By 17k iterations, the gap narrows but persists. At 34k iterations, SBD (EB with low γ values like 0.01–0.2) matches or nearly matches the NTP baseline. Figure 5 also shows the γ sweep: as γ increases, mean NFE decreases (faster generation) but accuracy drops — the Pareto frontier shifts upward with more training, indicating that longer fine-tuning improves both the model's prediction quality AND the efficiency-quality tradeoff.

This finding is practically significant: **SBD fine-tuning is not a drop-in replacement for SFT with zero overhead**. It requires roughly 2× the SFT iterations compared to NTP to reach the same accuracy, though the paper does not explicitly state this 2× factor. The authors note "SBD requires more steps to reach on-par performance as NTP training but closes the performance gap after roughly 34k training iterations."

#### EB-Sampler Outperforms Factor Sampling on Code Benchmarks

Appendix B.1 (Figures 12 and 13) compares the EB-Sampler with entropy error proxy against the Factor parallel decoding method (Wu et al., 2025a). On HumanEval at all three training checkpoints (8.5k, 17k, 34k iterations), EB-Sampler achieves higher accuracy at comparable or lower NFE than Factor — the EB curve sits consistently above the Factor curve in the accuracy-vs-NFE Pareto plots. On MBPP and GSM8K, the two samplers perform similarly once the model is sufficiently trained (34k iterations), with overlapping curves.

Figure 13 additionally shows that EB-Sampler with confidence error proxy (the variant using confidence-based sorting with the entropy bound from Ben-Hamu et al., 2025) closely tracks the Factor method, which also uses confidence-based sorting. The entropy error proxy (Figure 12) generally shows a more favorable accuracy-efficiency tradeoff than the confidence-based variants. This validates the paper's choice of entropy-based EB-Sampler as the default inference algorithm.

#### Roofline Analysis Confirms NFE Savings Translate to Wall-Clock Speedup for Typical Operating Regimes

Section 4's theoretical analysis quantifies when NFE reduction translates to actual wall-clock savings. Table 3 presents the **slowdown factor of a single block forward versus a single-token forward** for an H100 GPU and standard 8B transformer configuration:

- **Block sizes 1–32, batch sizes 1–4, all KV cache lengths:** Slowdown ≤ 1.062× — block forwards are at most 6.2% more expensive than single-token forwards. For block size 16 (likely the paper's default), slowdown ≤ 1.004× — essentially identical cost.
- **Block size 64, batch size 1–4:** Slowdown grows to 1.015–1.111× depending on cache length — still marginal.
- **Batch size 8, block size 64:** Slowdown jumps to 1.903× (short cache) to 3.799× (batch size 16, block size 64) — computation becomes compute-bound.

The paper marks these compute-bound regimes with colored cells in Table 3, warning that the wall-clock translation degrades.

Table 4 then combines these slowdowns with Equation 16 to compute **actual wall-clock speedup for different NFE speedups**:

- **NFE speedup = 2×, block size 16, batch size 1:** Wall-clock = 1.992× (near-perfect translation).
- **NFE speedup = 4×, block size 16, batch size 1:** Wall-clock = 3.982× (near-perfect).
- **NFE speedup = 8×, block size 16, batch size 1:** Wall-clock = 7.955× (slight degradation from 8× ideal).
- **NFE speedup = 4×, block size 64, batch size 8:** Wall-clock = 1.978× — NFE savings are cut in half due to compute-bound forward passes.

The uncolored cells in Table 4 span block sizes 8–16 and batch sizes 1–4 across all NFE speedups (2×, 4×, 8×) and most KV cache lengths, showing wall-clock speedups within ~2% of the NFE speedup. This is the paper's evidence that the 3–5× NFE reductions in Table 1 will translate to near-equivalent wall-clock savings in practice, at least for single-request or small-batch inference.

### Ablation Studies and Robustness Checks

**NTP loss term (Figure 4, Table 2):** As detailed above, removing the NTP loss term during SBD training causes NTP loss drift and 5–12 percentage point accuracy drops on likelihood benchmarks. This confirms the NTP term is essential for preserving autoregressive capability.

**Number of SFT training iterations (Figure 5):** SBD fine-tuning requires roughly 34k iterations to match NTP performance at the same data quantity, compared to NTP which achieves near-peak performance earlier (likely at 17k or earlier, though the paper does not show the NTP training curve across iterations). The gap closes with more training, suggesting SBD is data-inefficient relative to pure NTP fine-tuning.

**Block size during training (Section 3.1 description):** The paper samples block size uniformly from [2, 16] during training but does NOT ablate this choice — there is no comparison to training with a fixed block size. This is a missing ablation: the inference block size used for the benchmark results is not explicitly stated (the paper only says block size during training is variable), making it unclear whether the model's performance depends on matching the training distribution's block size range.

**EB-Sampler vs. Factor vs. EB-Sampler (confidence proxy) (Figures 12 and 13):** EB-Sampler with entropy error proxy outperforms Factor sampling on HumanEval across all training budgets and performs similarly on MBPP and GSM8K at 34k iterations. EB-Sampler with confidence error proxy closely tracks Factor, supporting the interpretation that the entropy-based selection criterion (rather than confidence-based) provides the quality advantage.

**γ threshold sensitivity (Table 1, Figures 5, 6):** The paper sweeps γ values in Figure 5: {0, 0.01, 0.1, 0.2, 0.4, 0.8, 1.5} for the 3B models. The accuracy-vs-NFE curves show a smooth tradeoff — lower γ values achieve higher accuracy with more NFEs, higher γ values achieve faster generation with lower accuracy. The two γ settings used for benchmarks (γ_low = 0.1 reasoning / 0.35 chat; γ_high = 0.35 reasoning / 0.6 chat) are chosen without formal justification — the paper does not explain how these specific values were selected or whether they were tuned on the test benchmarks. This is a potential overfitting concern.

**Training data composition:** All experiments use the same 70B token mix (reasoning + instruction data) without ablating data composition. It is unknown whether SBD fine-tuning would be equally effective on pure code, pure math, or general web text data.

### Critical Assessment

**Do the experiments support the claim that SBD "achieves a 3–5× reduction in forward passes while matching NTP performance"?**

Yes, for the benchmarks tested, with qualifications. Table 1 shows that at γ_low, the Llama-3.1 SBD model achieves average speedups of 3.0× with accuracy differences from the NTP baseline ranging from −3.3 (AIME25) to +1.2 (HumanEval+). The Qwen-3 SBD model at γ_low achieves 3.2× average speedup with accuracy differences from −3.0 (HumanEval+) to +0.6 (LiveCodeBench). The claim of "matching performance" holds for most benchmarks — differences of 1–2 points are likely within the variance of single-run evaluation — but the AIME25 drop for Llama-3.1 (−3.3 points, from 33.3 to 30.0) and HumanEval+ drop for Qwen-3 (−3.0 points, from 69.5 to 66.5) suggest non-trivial degradation on some tasks even at γ_low.

A genuine concern: the paper does not report error bars, multiple random seeds, or statistical significance. With test sets of 500 questions (Math500), 30 questions (AIME25), 164 questions (HumanEval+), etc., some of these point-estimate differences could be sampling noise. AIME25 has only 30 problems — a 3.3-point drop represents exactly one additional incorrectly answered problem, which could easily be noise. The paper's claim of "matching performance" would be considerably strengthened by reporting confidence intervals or at minimum clarifying that some differences are within expected variance.

The "3–5×" range is benchmark-dependent and method-dependent. The per-benchmark speedups in Table 1 (in parentheses) range from 2.20× (Llama-3.1 γ_low on GSM8K) to 5.36× (Qwen-3 γ_high on LiveCodeBench). The paper's headline "3–5×" is a reasonable summary but glosses over the substantial variation across tasks — chat benchmarks consistently achieve lower speedups (~2.2–3.0×) than reasoning benchmarks (~3.2–5.4×). This task-dependence is expected from the EB-Sampler's entropy-based mechanism but would benefit from explicit discussion.

**Do the experiments support that the forward-pass reduction translates to wall-clock speedup?**

The roofline analysis (Section 4) provides theoretical justification but no empirical wall-clock measurements. The paper never reports actual wall-clock speedup from a GPU implementation — all speedups in Table 1 are NFE speedups. Table 4 shows that theoretical wall-clock speedup closely matches NFE speedup for block sizes 8–16 and batch size 1, but this assumes:
- The model architecture exactly matches the roofline assumptions (8B, hidden_dim 4096, FFN_dim 4× hidden_dim, etc.).
- The attention kernel achieves the theoretical roofline performance (the paper assumes FlashAttention-like fused kernels).
- Memory bandwidth and FLOPS are fully utilized with no overhead from the EB-Sampler logic (entropy computation, sorting, token selection).

These are idealized conditions. In practice, the EB-Sampler requires additional operations (computing softmax and entropy over the vocabulary for each masked position, sorting tensors on GPU) that are not accounted for in the roofline model. For small batch sizes, these overheads could be non-negligible. An actual wall-clock measurement — even on a single benchmark with a reference implementation — would substantially strengthen the paper's central efficiency claim. The absence of any empirical timing measurement is the paper's most significant weakness.

**Do the experiments demonstrate that SBD is simpler than prior approaches?**

The paper claims "simplicity" as an advantage: "Single language model, no architectural changes and additions; no added hyper-parameters during training." This claim is partially supported:
- SBD does not require a draft model (unlike speculative decoding), additional prediction heads (unlike Medusa, Eagle), or modified transformer layers.
- Training does not introduce new hyperparameters — the loss is a sum of two cross-entropy terms with implicit weighting.
- However, inference introduces the γ hyperparameter, which must be tuned per task type (the paper uses different γ values for reasoning vs. chat). This is a non-trivial practical consideration — deploying SBD requires selecting γ, and the paper provides only heuristic values without a principled selection method.

The simplicity claim would benefit from a comparison of engineering complexity: lines of code changed relative to a standard training/inference loop, additional GPU memory required (none, since no additional model parameters), and additional inference-time CPU overhead.

**Missing experiments that would strengthen the paper:**

1. **Wall-clock timing benchmarks.** A measured speedup on an actual H100 or A100 using a production inference framework (vLLM, TensorRT-LLM) for at least one model on one benchmark. The gap between theoretical and measured speedup is often substantial due to kernel launch overhead, memory fragmentation, and the EB-Sampler's extra-logistic overhead.

2. **Scaling experiments across model sizes.** All speedup results are for 8B models. Does the speedup hold for 1B, 3B, 70B models? The roofline analysis suggests memory-bandwidth-bound behavior is universal across model sizes (the model weights are always large), but the block-size-to-speedup relationship may differ.

3. **Longer-form generation evaluation.** The paper evaluates on benchmarks with relatively short outputs (MATH500 solutions, code completions). For tasks requiring thousands of tokens of generation (long-form writing, multi-turn dialogue), the block-wise generation with fixed block size `k` may interact differently with the EB-Sampler.

4. **Varying block size at inference.** The paper trains with variable block size [2,16] but uses a fixed block size `k` at inference. What is the optimal inference block size? How does performance vary with `k`? This is not ablated.

5. **Direct comparison to speculative decoding at equal accuracy.** The paper argues SBD is simpler than speculative decoding but never compares speedup or accuracy against a properly tuned speculative decoding baseline (e.g., Llama-3.1 8B with a 1B draft model). A head-to-head comparison would validate the "simpler alternative" claim.

6. **Statistical significance and variance.** All results are single-run point estimates on benchmarks with finite test sets. Standard errors or at minimum a statement about test-retest variance would contextualize the small accuracy differences.

7. **SBD from earlier pretraining checkpoints.** The fine-tuning experiments start from fully pretrained models. How much pretraining can be saved by switching to SBD training earlier? The paper suggests future work on "scaling SBD to even larger models" but doesn't explore whether SBD training from scratch (or from an earlier checkpoint) would be more efficient than fine-tuning a fully pretrained model.

**Conditional validity of the claims:**

- **"3–5× reduction in forward passes":** Conditionally true. Holds for the tested benchmarks with the specific γ values chosen, but speedup varies from 2.2× to 5.4× per benchmark. Not tested beyond 8B scale or for very long generations.
- **"No performance reductions":** True for the aggregate pattern but not universally — AIME25 drops 3.3 points for Llama-3.1 at γ_low; HumanEval+ drops 3.0 points for Qwen-3 at γ_low. Whether these are statistically significant is unknown.
- **"Almost identical factors of wall-clock savings":** Supported by theoretical analysis but not empirically validated. The claim is conditional on the model architecture matching roofline assumptions, the attention implementation being near-optimal, and the EB-Sampler overhead being negligible.
- **"Simple and flexible":** Supported for architectural simplicity (no new parameters) but nuanced for practical deployment (γ must be chosen per task, fine-tuning requires 2× SFT iterations to match NTP).

The paper's most robust finding — that SBD training preserves NTP quality while enabling parallel decoding — is well-supported by the NTP-decoding row in Table 1 and the NTP loss curves in Figure 4. The speedup claims are supported on the tested benchmarks but limited by the absence of empirical timing measurements. The contribution is strongest as a **modeling innovation** (how to train a single model for dual prediction modes) and weakest as an **end-to-end deployment solution** (where actual wall-clock measurements and real-system overheads remain unmeasured).

## 6. Limitations and Trade-offs

### Limitation 1: No Empirical Wall-Clock Speedup Measurements — All Speedups Are Theoretical or Forward-Pass-Counts

**The assumption or constraint:** The paper's central efficiency claim — that SBD achieves a 3–5× reduction in generation time — rests entirely on two proxies: (1) the number of model forward passes (NFEs) reduced, measured per benchmark (Table 1), and (2) a theoretical roofline model (Section 4) that predicts near-perfect translation from NFE reduction to wall-clock speedup under idealized GPU conditions. The paper never reports a measured wall-clock time on real hardware. The authors acknowledge this implicitly in Section 6:

> "developing hardware-aware inference implementations to match the theoretical roofline analysis... could further unlock the potential of SBD to maximize wall-clock speedups"

This phrasing concedes that the theoretical analysis has not yet been matched by an implementation.

**The consequence:** The gap between theoretical roofline predictions and actual GPU performance can be substantial, particularly for inference pipelines that add overhead beyond the transformer forward pass. The EB-Sampler requires computing softmax distributions over the full vocabulary (`V = 128k+` for Llama-3.1) for each masked position, computing entropies, sorting tensors by entropy, and updating the attention mask — all of which occur between model forwards and consume GPU cycles not captured by the roofline model (which only accounts for attention and linear layer compute/memory). For the small batch sizes where SBD is most effective (batch size 1–4, per the roofline analysis), kernel launch overhead and CPU-GPU synchronization for the EB-Sampler logic could be non-negligible fractions of the total iteration time. Without measured wall-clock numbers, a practitioner cannot estimate whether they will see 2×, 3×, or 5× actual speedup in their deployment — or whether the per-iteration overhead might erode the gains enough to make SBD no faster than well-optimized NTP inference (which benefits from years of kernel-level optimization in frameworks like vLLM, TensorRT-LLM, and FlashAttention).

**What evidence exists in the paper:** None. The paper contains zero empirical timing measurements. All speedup numbers in Table 1 are NFE counts. Section 4's analysis is purely theoretical, based on a Python implementation of a roofline model (Figure 11) that sums idealized times for attention and linear layers. Table 4 reports "theoretical wall-clock speedups" — the word "theoretical" is the authors' own qualification. The roofline model further assumes the attention implementation achieves the theoretical peak (which the paper flags by noting it "assume[s] a single fused kernel like in Dao et al. (2022)"), but even state-of-the-art FlashAttention implementations fall below the roofline for irregular attention patterns like the SBD mask.

**Mitigation status:** The paper frames hardware-aware implementation as future work (Section 6) and does not attempt to mitigate this limitation. The roofline analysis provides an upper bound on achievable speedup, not a realistic estimate. A single benchmark measured end-to-end on an H100 or A100 — even with an unoptimized implementation — would substantially clarify the gap between theory and practice. The absence of any such measurement is the paper's most significant weakness for practitioners evaluating adoption.

---

### Limitation 2: Inference Requires Tuning the γ Hyperparameter Per Task, with No Principled Selection Method

**The assumption or constraint:** The EB-Sampler's entropy threshold γ is the sole inference-time hyperparameter controlling the accuracy-speedup tradeoff (Equation 8). The paper uses different γ values for different task categories: `γ_low = 0.1, γ_high = 0.35` for reasoning benchmarks (MATH500, AIME25, LiveCodeBench) and `γ_low = 0.35, γ_high = 0.6` for chat benchmarks (GSM8K, HumanEval+, MBPP). The paper does not explain how these values were selected — whether through grid search on a validation set, through heuristics, or through tuning on the test benchmarks themselves. Section 2.2 describes γ as a "user prescribed threshold" but provides no guidance for choosing it beyond the qualitative principle that lower γ preserves more accuracy.

**The consequence:** This is a practical deployment barrier. A practitioner deploying SBD on a new task or data distribution has no principled method to select γ. If they tune γ on their validation set, they incur additional computational cost (multiple evaluation runs) that is not accounted for in the paper's speedup numbers. If they use the paper's reported values (0.1 or 0.35), there is no guarantee these transfer across model families, data distributions, or generation tasks — the optimal γ depends on the model's calibration (how well entropy correlates with prediction correctness) and the task's tolerance for approximation error. For safety-critical or high-stakes applications, overestimating γ (too much parallelization) could introduce unacceptable error rates. For throughput-oriented applications, underestimating γ would leave speedup on the table.

Furthermore, the paper's use of different γ values for "reasoning" vs. "chat" suggests a sharp boundary that does not exist in practice. Is a code-generation task with thinking tokens "reasoning" or "chat"? What about multi-turn dialogue that involves mathematical problem-solving? The binary categorization masks what is likely a continuous relationship between task characteristics and optimal γ, and the paper provides no analysis of which task properties (output length, entropy distribution, structuredness of the domain) drive the optimal threshold.

**What evidence exists in the paper:** Figure 5 (3B model SFT) shows accuracy-vs-NFE curves for a sweep of γ values in {0, 0.01, 0.1, 0.2, 0.4, 0.8, 1.5}, demonstrating the tradeoff is smooth and that higher γ values degrade accuracy while reducing NFE. Table 1 shows that the specific γ values used produce different per-benchmark speedups (ranging from 2.20× to 5.36×), indicating strong task-dependence. However, the paper does not report how the chosen values were determined, whether they were tuned on test data, or how sensitive results are to small perturbations in γ. The ablation in Appendix B.1 compares EB-Sampler variants (entropy vs. confidence error proxy) but does not ablate the γ selection methodology itself.

**Mitigation status:** Not addressed. The paper treats γ as a user-tunable knob without providing a tuning protocol, cost model for tuning, or analysis of transferability. This is a significant gap for a method whose headline advantage is simplicity and ease of adoption.

---

### Limitation 3: The Fine-Tuning Cost (70B Tokens, ~2× SFT Iterations) Is Omitted from the Efficiency Calculation

**The assumption or constraint:** The paper presents SBD as a "quickly fine-tuned" method (Section 1) that can be applied to existing pretrained NTP models. However, the fine-tuning cost — 70B tokens for the 8B experiments, 34k iterations at batch size 2M tokens with the same optimizer and data pipeline — is treated as a one-time upfront cost separate from the inference savings. The headline "3–5× speedup" measures inference savings without amortizing the training cost over the total deployed inference volume. The paper acknowledges the training overhead in Section 3.2 (Figure 5): SBD requires roughly 2× the SFT iterations of NTP fine-tuning to reach performance parity ("SBD requires more steps to reach on-par performance as NTP training but closes the performance gap after roughly 34k training iterations").

**The consequence:** For a deployment with finite total inference volume, the training cost matters. A 70B-token fine-tuning run on 8B models is substantial — roughly equivalent to generating 70B tokens of inference output. If a deployed model serves only a few billion tokens of inference over its lifetime, the training cost could dominate or even exceed the inference savings. The paper's efficiency claim is valid only in the **high-inference-volume regime** (`R = D_inference / D_pretrain >> 1` in the language of the referenced training-inference tradeoff literature), where the 70B-token fine-tuning cost amortizes to negligible per-token overhead. The paper does not characterize this regime, does not compute the break-even inference volume, and does not discuss what deployment scenarios justify the upfront training investment.

Additionally, the fine-tuning requires the same high-quality data mix (reasoning + instruction) that would be used for standard SFT. If a team was already planning to fine-tune their base model on this data, the marginal cost of SBD over NTP fine-tuning is only the extra SFT iterations (roughly 2×) — a more modest overhead. But if they were not planning to fine-tune at all (using the base model directly), SBD imposes the full 70B-token cost, which could be a significant fraction of the original pretraining budget.

**What evidence exists in the paper:** Figure 5 documents the training dynamics: SBD at 8.5k iterations (25% of the full 34k budget) substantially underperforms NTP; at 17k (50%), the gap narrows; at 34k, parity is achieved. Table 1 shows the end result. The paper does not report the compute cost of fine-tuning in GPU-hours or FLOPs, making it difficult to compute the break-even inference volume. The 70B tokens of training data equals roughly 0.5% of the ~15T tokens used to pretrain Llama-3.1 (based on the Llama-3 paper; not stated in this paper), which is modest in relative terms but absolute cost depends on scale.

**Mitigation status:** The paper does not address the amortization question. Section 6 suggests "scaling SBD to even larger models" as future work but does not discuss the training-inference cost tradeoff. A break-even analysis — at what inference volume does SBD fine-tuning pay for itself — would be practical guidance for deployment decisions.

### Limitation 4: No Results on Long-Form or Open-Ended Generation — Only Short, Closed-Form Benchmarks

**The assumption or constraint:** All evaluations use benchmarks with relatively short, structured outputs: math problems with definitive answers (MATH500, AIME25, GSM8K), code generation with unit-testable correctness (HumanEval+, MBPP, LiveCodeBench), and multiple-choice knowledge questions (MMLU, ARC, Hellaswag). The longest generation settings are 32k tokens for reasoning benchmarks (with "thinking" tokens), but these are structured chains-of-thought leading to a final answer — not open-ended creative text. The paper does not evaluate on tasks requiring coherent long-form generation (story writing, multi-turn dialogue, document summarization) where the block-wise generation with fixed block size `k` and iterative unmasking may interact differently with discourse-level coherence constraints.

**The consequence:** The EB-Sampler's parallelization mechanism relies on conditional independence assumptions that may be weaker for open-ended text. In mathematical reasoning and code, many tokens are structurally determined (e.g., closing brackets, mathematical operators, standard variable names) and have low entropy — the model is confident, so the EB-Sampler reveals many tokens in parallel with minimal error. In creative writing, word choice is inherently higher-entropy (many plausible continuations), which would force the EB-Sampler into a more serial, autoregressive-like decoding regime — reducing NFE speedup. Worse, the block structure (fixed-size blocks with bidirectional attention within each block) may produce subtle coherence breaks at block boundaries, where the model treats the block start as a "reset" with only causal access to the preceding block. These boundary effects would be invisible on structured tasks but could degrade fluency in long-form generation.

Additionally, the paper's "generate until" logic for measuring speedup — which stops counting NFE when the solution is complete, not at a fixed token count — may be favorable to SBD on tasks with variable-length outputs. If SBD with high γ sometimes generates incorrect but shorter solutions (fewer tokens generated before stopping), the per-token speedup could be overstated because fewer total tokens were generated. The paper does not report average output lengths for SBD vs. NTP, making this impossible to verify.

**What evidence exists in the paper:** None for long-form generation. All benchmarks have well-defined correctness criteria. The chat benchmarks (GSM8K, HumanEval+, MBPP) are structured tasks masquerading as "chat" — GSM8K is grade-school math word problems, HumanEval+ is function synthesis from docstrings, MBPP is basic programming tasks. The paper does not evaluate on any benchmark where output quality is measured by human preference, fluency, or coherence rather than exact-match accuracy.

**Mitigation status:** Not addressed. The paper does not claim applicability to open-ended generation and does not discuss this as a limitation. Given the strong results on structured reasoning tasks, the natural extension to long-form generation would be a valuable evaluation — but the current evidence cannot support claims about SBD's effectiveness in that regime.

### Limitation 5: The Roofline Analysis Predicts Diminishing Returns at Scale — SBD Is Fundamentally a Small-Batch, Moderate-Block-Size Method

**The assumption or constraint:** The roofline analysis in Section 4 reveals that SBD's near-perfect NFE-to-wall-clock translation holds only in the memory-bandwidth-bound regime: block sizes ≤ 16, batch sizes ≤ 4. Table 3 and Table 4 systematically quantify the degradation: at batch size 16 with block size 64, an NFE speedup of 4× translates to only 1.978× wall-clock speedup; at NFE speedup of 8×, it drops to 3.736× — roughly half of the theoretical gain. The paper marks these degraded regimes with colored cells in both tables but does not discuss them in the main text. The implication is that SBD provides diminishing returns — or even net slowdown — when deployed in high-throughput batch inference settings.

**The consequence:** This creates a sharp deployment tradeoff between **latency-sensitive single-request inference** and **throughput-oriented batch inference**. For interactive applications (chatbots, code assistants, real-time translation) where batch size is inherently 1, SBD's speedup should be near-ideal. For batch inference pipelines (evaluating thousands of problems, generating training data, API serving with high concurrency) where batch sizes of 8–64 are standard, SBD may provide substantially less benefit — or even increase total compute time if the block forward cost grows faster than the NFE reduction. The paper positions SBD as an inference accelerator suitable for "practical deployment" (Section 1) but does not distinguish these deployment modes or guide practitioners on when SBD is appropriate.

Furthermore, the batch-size dependence interacts with the γ threshold: at high batch sizes where block forwards become compute-bound, the per-iteration cost of the EB-Sampler (entropy computation, sorting) also increases because more tokens are being processed simultaneously. This overhead is not captured by the roofline analysis and could further degrade wall-clock performance in batch settings.

**What evidence exists in the paper:** Tables 3 and 4 provide the evidence, but the paper does not discuss it as a limitation. The uncolored-vs-colored cell distinction in both tables clearly demarcates the "good" regime (block size 8–16, batch size 1–4) from the "degraded" regime. The paper's benchmark results (Table 1) presumably use batch size 1 (since they are single-problem evaluations), which explains why the roofline predicts near-perfect translation. But the paper never states the batch size used, and never evaluates SBD at higher batch sizes to validate the theoretical degradation.

**Mitigation status:** The paper acknowledges diminishing returns only implicitly through the colored cells, without discussion. Section 4.1 notes that "as batch sizes and/or block size increase the roofline analysis indicates diminishing returns due to increased computational costs," but this appears at the end of a technical exposition, not as a deployment consideration. There is no guidance on choosing block size or batch size for different deployment scenarios. The future work section (Section 6) mentions "developing hardware-aware inference implementations" but does not address the batch-size sensitivity as a fundamental property of the method.

### Limitation 6: Single Evaluation Per Benchmark Without Statistical Significance — Weak Support for "Matching Performance" Claims

**The assumption or constraint:** All benchmark results in Table 1 are single-run point estimates. The paper reports no error bars, confidence intervals, standard deviations across random seeds, or statistical tests for any comparison. Test set sizes vary from 30 problems (AIME25) to 500 (MATH500), 164 (HumanEval+), and unspecified (LiveCodeBench v6, GSM8K, MBPP). The claim that SBD "matches" or "preserves" NTP performance — which the paper makes repeatedly (Section 1, Section 3.1, Section 6) — is based on differences as small as +0.2 points (Llama-3.1 LiveCodeBench V6: 31.3 vs. 31.5) and as large as −3.3 points (Llama-3.1 AIME25: 30.0 vs. 33.3). For small test sets, these point-estimate differences may not be statistically distinguishable from zero.

**The consequence:** A practitioner reading that SBD "matches NTP performance" at 3–5× speedup might reasonably assume this means the accuracy difference is negligible with high confidence. In reality, the evidence quality varies substantially by benchmark:
- On MATH500 (500 problems), the differences of −0.2 to +1.4 points are plausible as noise.
- On AIME25 (30 problems), a 3.3-point drop represents exactly one additional incorrect answer — which could easily be a single unlucky sample. Conversely, the fact that Qwen-3 SBD (γ_low) achieves identical 33.3% on AIME25 might be slightly lucky — a 0-point difference in 30 problems is fragile.
- On LiveCodeBench and GSM8K (test set sizes unstated), the reliability of the comparisons cannot be assessed without knowing the test set size.

Without statistical characterization, the paper's central claim — "SBD enables a 3-5x reduction in the number of forward passes required for generation while achieving same performance as equivalent NTP training" (abstract) — is partially supported but not rigorously demonstrated. The qualification "equivalent NTP training" refers to NTP baseline models trained on the same data, which is a strong comparison, but the confidence in that equivalence is unevaluated.

**What evidence exists in the paper:** Table 1 reports point estimates. The paper does not discuss statistical methodology anywhere. Figure 5 provides three data points per benchmark across training iterations (8.5k, 17k, 34k), giving some indication of training stability, but no information about evaluation variance. The ablation in Figure 4 (NTP loss during pretraining) shows smooth curves, suggesting reliable measurement, but this is pretraining loss (computed over massive amounts of data), not benchmark accuracy on small test sets.

**Mitigation status:** Not addressed. This is common in LLM benchmarking papers — many report single-run accuracies without statistical tests due to the computational cost of multiple evaluations — but the fine-grained nature of the "matching performance" claim (differences of 1–3 points) demands higher evidentiary standards. The paper could strengthen this claim by: (1) reporting test set sizes for all benchmarks, (2) noting that some differences fall within expected binomial variance, or (3) running multiple evaluations with different random seeds on the smallest benchmarks (AIME25) where point estimates are least reliable.

## 7. Implications and Future Directions

### How This Work Changes the Landscape

SBD does not propose a fundamentally new architecture or training paradigm. It does not introduce a novel attention mechanism, a new loss function, or a theoretical breakthrough in parallel decoding. What it does — and why it matters — is **reframe the inference acceleration problem around memory-bandwidth utilization rather than compute reduction**, and demonstrate that this reframing leads to a practical, simple method that can be retrofitted onto existing pretrained models at modest cost.

This is a **reframing with practical consequences**, not a paradigm shift. The field has long understood that LLM decoding is memory-bandwidth-bound — the roofline model itself dates to Williams et al. (2008) — but prior acceleration work largely treated this as a constraint to engineer around (through quantization, kernel fusion, KV-cache compression) rather than an opportunity to exploit. SBD's key conceptual move is to ask: if the memory system must read the full model weights for every token regardless, why not produce multiple tokens per read? This question seems obvious in retrospect, but answering it required the convergence of three ingredients that the paper assembles: (1) a training procedure that preserves autoregressive quality while adding masked prediction capability, (2) an attention pattern (causal past + bidirectional block) that enables exact KV-caching without the approximation errors of pure diffusion models, and (3) the EB-Sampler, an adaptive unmasking algorithm from the discrete diffusion literature that decides which tokens to decode in parallel based on model confidence.

The diagnostic contribution is as important as the method. The paper's roofline analysis (Section 4) systematically characterizes *when* parallel decoding translates to wall-clock speedup (small batch, moderate block size) and *when* it doesn't (large batch, large block), providing a quantitative framework that applies beyond SBD to any block-parallel inference scheme. Table 4's colored-cell demarcation of the "good" vs. "degraded" regime is a practical tool for practitioners evaluating whether block-parallel methods are appropriate for their deployment scenario. The paper does not explicitly call this out as a diagnostic contribution, but it functions as one: it tells the field that **block-parallel decoding is a small-batch, latency-sensitive technology, not a throughput technology for high-concurrency serving**. This distinction is valuable because it prevents the method from being misapplied in settings where it would underperform, and it focuses future research on the regime where block-parallel methods have the most leverage.

The paper also contributes a **reconciliation of why prior parallel decoding methods failed to deliver practical speedups**. Stern et al. (2018) proposed independent parallel decoding but saw limited adoption because (a) the independence assumption produced poor-quality outputs requiring serial verification, and (b) the forward-pass savings were insufficient to overcome the per-block overhead. BD3-LM (Arriola et al., 2025) and its extensions achieved better quality through block-level diffusion but lost exact KV-caching, relying on approximate heuristics that traded quality for speed. Pure masked diffusion models (LLaDa, Dream) achieved competitive quality but required training from scratch and lacked efficient sampling. SBD resolves these tensions by showing that the right combination — conditional rather than independent parallel decoding, causal rather than fully bidirectional attention on the past, and fine-tuning rather than training from scratch — makes block-parallel decoding work at practical scales with existing models. This doesn't make prior work "wrong" but instead clarifies which design choices were the bottlenecks.

A subtle but important reframing: the paper treats **the NTP loss term as a capability preservation mechanism, not merely one of two training objectives**. The ablation in Section 3.2 (Figure 4, Table 2) demonstrates that masked prediction training alone degrades autoregressive quality by 5–12 percentage points on likelihood benchmarks. This finding implies that future hybrid models mixing autoregressive and parallel generation cannot simply train on the parallel objective and assume the autoregressive capability is a special case — the autoregressive ability must be explicitly maintained during training. This is a design principle that the paper establishes empirically, and it will likely influence how future work designs training objectives for hybrid models.

The research directions that become **more attractive** after SBD:

- **Hardware-aware implementations of block-parallel decoding**. The paper's theoretical roofline analysis shows near-perfect translation is possible; the next step is to achieve it in practice with optimized kernels for the semicolon attention pattern.
- **Adaptive block sizing and dynamic γ selection**. The EB-Sampler's entropy threshold is currently set per task category by the user; learning it from data or adapting it per-token could improve the speed-accuracy Pareto frontier.
- **Applying SBD-style fine-tuning to other model families and modalities**. The paper shows results on two 8B text models; the approach should transfer to vision-language models, code-specific models, and models at different scales, but this remains empirically untested.
- **Speculative decoding with SBD as the draft model**. Since SBD can generate multiple tokens per forward pass, it could serve as an efficient draft model for an even larger target model, potentially combining the strengths of both approaches.

The research directions that become **less attractive** after SBD:

- **Pure diffusion language models that sacrifice exact KV-caching**. SBD demonstrates that you can have both bidirectional attention within blocks AND exact KV-caching across blocks. Diffusion models that use fully bidirectional attention everywhere and rely on approximate caching heuristics now look like a dominated design choice unless they offer quality advantages that SBD cannot match.
- **Independent parallel decoding with serial verification**. The paper shows that conditional parallel decoding (where revealed tokens inform remaining masked tokens) substantially outperforms independent parallel decoding. The extra complexity of the draft-then-verify speculative decoding pipeline may be unnecessary when a single model can perform the parallel decoding with built-in quality control via the EB-Sampler's entropy threshold.
- **Training hybrid models from scratch**. SBD's fine-tuning approach — converting a pretrained NTP model in ~0.5% of pretraining tokens — makes training hybrid models from scratch (like BD3-LM or LLaDa) look unnecessarily expensive unless the from-scratch models demonstrate quality advantages that cannot be recovered through fine-tuning.

### Follow-Up Research This Work Enables

**Measuring actual wall-clock speedup on production GPU hardware with an optimized inference kernel.** The paper's central efficiency claim — that 3–5× NFE reduction translates to 3–5× wall-clock speedup — is supported only by theoretical roofline analysis (Tables 3 and 4). A concrete experiment would implement the SBD inference loop (Algorithm 3 plus EB-Sampler) using a production-grade inference framework (vLLM with custom attention kernel, or TensorRT-LLM with a FlexAttention-like mechanism) on an H100 or A100, measure end-to-end latency for Llama-3.1 8B SBD vs. standard NTP on LiveCodeBench v6 (where the paper reports 3.72–4.59× NFE speedup), and report both median and tail latency (p95, p99). The experiment should separately profile the cost of the EB-Sampler's entropy computation and sorting per iteration, which is not captured by the roofline model. A finding that measured speedup is within 20% of the roofline prediction would validate the paper's theoretical analysis and provide practitioners with reliable deployment estimates. A finding that measured speedup is substantially lower (e.g., 2× instead of 4×) would identify the EB-Sampler overhead or kernel inefficiency as the primary bottleneck for future engineering work.

**Direct comparison to speculative decoding at matched accuracy and model scale.** The paper claims SBD is "simpler" than speculative decoding (Section 1, Section 5) but never benchmarks against it. A controlled experiment would compare Llama-3.1 8B SBD (γ tuned to match NTP accuracy on HumanEval+ at 57.9%) against standard speculative decoding with Llama-3.1 8B as the target model and a 1B-parameter draft model (e.g., Llama-3.2 1B or a distilled variant), measuring both NFE reduction and wall-clock latency at equal accuracy. If SBD achieves comparable or better speedup, the "simpler alternative" claim gains empirical support and positions SBD as a drop-in replacement for speculative decoding without the two-model complexity. If speculative decoding outperforms SBD significantly, the claim needs qualification — SBD may be simpler but not faster, which changes the deployment tradeoff (simplicity vs. maximum speedup). This experiment also tests whether SBD's advantage over speculative decoding grows or shrinks with task difficulty, since speculative decoding's acceptance rate depends on draft quality while SBD's depends on model confidence.

**Training SBD from earlier pretraining checkpoints to reduce the total training budget.** The paper fine-tunes fully pretrained 8B models (Llama-3.1, Qwen-3) on 70B tokens of SBD training data. How much of the original pretraining can be saved by switching to SBD training earlier? A scaling experiment would take intermediate checkpoints of a model being pretrained from scratch (e.g., at 100B, 300B, 600B, 900B, 1.2T tokens of a 1T-token pretraining run), fine-tune each with the SBD objective for the remaining tokens to reach a fixed total budget (e.g., 1T tokens total), and measure both final NTP quality (to check whether the NTP loss term preserves capability) and SBD speedup on a held-out benchmark. If SBD fine-tuning from the 600B checkpoint matches the quality of NTP pretraining to 1T tokens while adding inference speedup, the SBD training recipe could reduce total pretraining cost by enabling earlier stopping — the model doesn't need to reach full autoregressive quality before adding parallel capability. This would make SBD compelling not just as a post-training add-on but as an integral part of the pretraining pipeline.

**Evaluating SBD on long-form open-ended generation with human evaluation.** All benchmarks in Table 1 are closed-form tasks with automatic evaluation (exact match, unit tests). A stress-test experiment would evaluate Llama-3.1 8B SBD on a long-form generation benchmark — such as summarization (CNN/DailyMail, XSum), story generation (WritingPrompts with automated metrics plus human preference), or multi-turn dialogue (MT-Bench with LLM-as-judge evaluation) — comparing SBD with γ_low and γ_high against the NTP baseline. The key measurements are: (1) does the block-wise generation with fixed block size `k` produce coherence breaks or repetition at block boundaries? (2) does the EB-Sampler's entropy-based parallelization degrade output quality in high-entropy creative writing contexts where nearly all tokens have high entropy, forcing serial-like decoding with no speedup? (3) does the per-token speedup degrade compared to structured tasks, and if so, by how much? A negative result — substantial quality degradation on open-ended tasks — would clarify SBD's applicability domain and prevent overclaiming. A positive result would substantially broaden SBD's claimed scope.

**Adaptive γ selection via lightweight calibration on a few examples.** The paper's γ values are pre-selected per task category (0.1/0.35 for reasoning, 0.35/0.6 for chat) without a principled selection method. A follow-up could train a small predictor (e.g., a linear probe on top of the base model's hidden states or a lightweight neural network taking the prompt embedding as input) to predict the γ that achieves a target speedup or accuracy level. The training data would be generated by running SBD with a sweep of γ values on a small calibration set of 100–500 examples and recording per-example accuracy and NFE. The predictor would learn to map prompt characteristics (difficulty, domain, expected output length) to an appropriate γ. If a predictor trained on one benchmark generalizes to others within the same task category, this would eliminate the per-task γ tuning burden and make SBD deployable without manual hyperparameter selection. This is a natural extension of the paper's difficulty-adaptive theme — the EB-Sampler already adapts per-token within a problem; a γ predictor would adapt per-problem across a benchmark.

**Combining SBD with speculative decoding for multiplicative speedup.** Since SBD generates multiple tokens per forward pass and speculative decoding uses a fast draft to propose tokens for a slow verifier, the two methods address different bottlenecks and could compound. A concrete experiment: use SBD as the draft model in a speculative decoding pipeline where the target is a larger model (e.g., Llama-3.1 70B) and the draft is an SBD fine-tuned version of a smaller model (e.g., Llama-3.1 8B SBD). The SBD draft would propose not individual tokens one at a time but blocks of tokens generated via the EB-Sampler, which the larger target model would verify in a single forward pass. The speedup would be the product of SBD's per-forward token increase (3–5×) and speculative decoding's acceptance rate advantage (typically 2–3×) — potentially 6–15× total speedup. The experiment would need to characterize how block-level proposals interact with the verification step (can the target verify an entire block with bidirectional attention, or must it verify tokens left-to-right?) and whether the SBD draft's quality remains high enough for reasonable acceptance rates when used speculatively.

### Practical Applications and Downstream Use Cases

**Latency-sensitive interactive coding assistants.** In real-time code completion (e.g., IDE copilots), the model must respond within a few hundred milliseconds to feel instantaneous to the user, and batch size is inherently 1 (each user's request is independent). The paper's benchmark results on HumanEval+ (57.9% at 2.61× NFE speedup for Llama-3.1 γ_low) and MBPP (69.5% at 2.49×) are directly relevant: these are function synthesis tasks representative of what a coding assistant does. The roofline analysis (Table 4, batch_size=1, block size 8–16) predicts near-perfect translation from NFE to wall-clock, meaning a 2.5× NFE reduction should cut response latency by roughly 60%. For a coding assistant serving millions of requests daily, this latency reduction directly improves user experience without degrading suggestion quality. The SBD model can be obtained by fine-tuning an existing code-focused LLM (like CodeLlama or DeepSeek-Coder) on SBD-formatted code data, making this application immediately actionable with the paper's published training recipe.

**Single-request mathematical reasoning in educational tools.** Math tutoring systems that generate step-by-step solutions to student-submitted problems (e.g., MATH500-style questions) need both high accuracy and low latency to maintain an interactive tutoring experience. Qwen-3 SBD (γ_low) achieves 85.0% on MATH500 at 3.41× NFE speedup and 33.3% on AIME25 at 3.85× — preserving the base model's mathematical reasoning quality while generating solutions roughly 3.5× faster. For a tutoring platform processing student queries in real-time, this means either (a) serving 3.5× more students with the same GPU capacity, or (b) reducing per-student latency from ~10 seconds to ~3 seconds for a complex AIME-level solution, making the interaction feel more conversational. The γ_low setting is appropriate here because accuracy is paramount for educational applications — small errors in mathematical reasoning can mislead students. The "generate until" logic (measuring speedup only until the solution is complete) is particularly relevant since math solutions have natural stopping points.

**On-device or edge deployment with SBD-fine-tuned smaller models.** The paper's experimental focus on 8B models demonstrates the approach at a scale where inference cost is already a concern. A natural extension is applying SBD fine-tuning to smaller models (1B–3B parameters) intended for on-device deployment (smartphones, laptops, embedded systems). The roofline analysis shows that SBD's speedup is most reliable in the memory-bandwidth-bound regime, which is the *only* regime for on-device inference (GPU memory bandwidth on mobile GPUs is even more constrained relative to compute than on data-center H100s). A 3B SBD model achieving 3× NFE speedup on GSM8K (as suggested by Figure 5 at 34k iterations) would generate grade-school math solutions on-device in roughly one-third the time, making on-device reasoning assistants more practical. The fine-tuning cost (70B tokens for the paper's 8B experiments, likely less for smaller models) is amortized once during model preparation and does not affect per-user inference cost, making this a one-time investment for a persistent deployment advantage. This application is speculative because the paper doesn't evaluate on-device hardware, but the roofline methodology directly supports it — memory bandwidth is the bottleneck universally, so the "amortize the weight read over multiple tokens" strategy should transfer.

### When to Prefer This Method

The paper does not provide an explicit head-to-head comparison or decision framework against named alternatives (speculative decoding, Medusa, Eagle, pure diffusion models). The "simpler alternative" claim in Section 1 and the architectural comparisons in Section 5 position SBD favorably but do not articulate a clear decision rule with conditions. The paper leaves practitioners to infer tradeoffs from the roofline analysis (batch size sensitivity, block size limits) and the benchmark results (task-dependent speedup). A forced decision matrix based on extrapolation from the paper's results would overstate what the paper actually establishes. The most one can say based on the paper's evidence is that SBD is likely preferable when (a) batch size is small (≤4), (b) the base model has already been pretrained and fine-tuning cost is acceptable, (c) the deployment scenario values architectural simplicity (single model, no draft, no additional heads), and (d) the generation task produces structured outputs where the model exhibits high confidence on many tokens. These conditions are empirically grounded in the paper's results but the paper never frames them as a formal decision rule, and stating one would impose a structure the authors did not provide.
