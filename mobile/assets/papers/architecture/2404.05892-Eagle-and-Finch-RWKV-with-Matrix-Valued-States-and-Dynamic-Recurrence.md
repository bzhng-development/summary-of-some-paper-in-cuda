# Eagle and Finch: RWKV with Matrix-Valued States and Dynamic Recurrence

**ArXiv:** [2404.05892](https://arxiv.org/abs/2404.05892)

## 🎯 Pitch

Eagle and Finch achieve near-perfect multi-query associative recall—outperforming all prior non-Transformer architectures—by upgrading the recurrent state from a vector to a matrix, massively boosting expressivity. Finch’s data-dependent decay then pushes a 3B RNN to surpass Llama-2-7B’s multilingual accuracy, all while maintaining constant O(1) inference time and memory per token.

---

## 1. Executive Summary

This paper introduces two successive RNN architectures — Eagle (RWKV-5) and Finch (RWKV-6) — that advance the RWKV lineage by replacing vector-valued states with **multi-headed matrix-valued states** (expanding the recurrent state from 5DL to 66DL, geometrically decaying a $K^T V$ matrix per head) and, in Finch, introducing a **dynamic recurrence mechanism** (data-dependent token-shift and time-decay via LoRA-augmented linear interpolations, allowing each channel's decay rate to vary per-timestep based on input content). Trained on the new 1.12-trillion-token multilingual RWKV World v2 dataset, Eagle and Finch models achieve competitive performance against similarly-sized Transformers and Mamba across LM Evaluation Harness benchmarks, with Finch-3B reaching 57.1% average multilingual accuracy (versus 54.3% for Llama-2-7B) while maintaining O(1) inference time and memory per token and demonstrating a 4.2× training speed advantage over Flash Attention at 16k sequence length. The architectures also achieve near-perfect multi-query associative recall — substantially outperforming all prior non-Transformer architectures — establishing that RNN-based models can match or exceed Transformer quality **only when** the recurrent state is both sufficiently expressive (matrix-valued) and contextually adaptive (data-dependent decay).

## 2. Context and Motivation

### The Core Problem: The Inference-Training Parallelism Tradeoff

The fundamental tension this paper addresses is architectural: **how do you build a sequence model that trains as efficiently as a Transformer but runs inference as cheaply as an RNN?** This is not a new question, but it is one that has resisted satisfactory resolution for years.

Transformers dominate language modeling because they are **massively parallelizable during training**. The self-attention mechanism computes interactions between all pairs of tokens simultaneously, making it possible to train on thousands of tokens in parallel across GPU cores. This is the architectural property that enabled the scaling revolution — without it, training on trillion-token corpora would be impractically slow regardless of hardware budgets.

However, this same mechanism imposes a **quadratic inference cost**. At each generation step, a Transformer must attend to every previous token in the context. For a sequence of length $N$, this costs $O(N)$ time and $O(N)$ memory per token. In practical terms: serving a long-context Transformer model at scale is expensive, and the cost grows linearly with sequence length. This is why deployed systems rely on techniques like KV-caching (which reduces computation but increases memory linearly with sequence length) or impose context window limits that fundamentally constrain the model's ability to reason over long documents, conversations, or codebases.

RNNs invert this tradeoff. Classic recurrent architectures process one token at a time, maintaining a fixed-size hidden state $h_t$. This means inference costs $O(1)$ time and $O(1)$ memory per token — the state size doesn't grow with sequence length, so you can theoretically process sequences of unbounded length at constant cost per step. But this same property makes RNNs **inherently sequential**: computing $h_t$ requires $h_{t-1}$, which prevents parallelization across the time dimension during training. For decades, this was an absolute constraint — you either got parallel training or constant-time inference, never both.

The paper identifies a specific gap that opened around 2020–2023: **it became possible to have both**, but the architectures that achieved this either sacrificed too much model quality or introduced new limitations. Understanding why requires examining the three architectural families that preceded Eagle and Finch.

### Where Prior Architectures Fall Short

**Linear attention** was the earliest attempt to square this circle. The key insight (Katharopoulos et al., 2020) was to replace the softmax normalization in standard attention — which forces computing all pairwise interactions — with a separable kernel: $\text{softmax}(QK^T)V$ becomes $\phi(Q)(\phi(K)^T V)$. This reordering exploits the associativity of matrix multiplication: instead of computing $QK^T$ first (which produces an $N \times N$ matrix, the source of quadratic cost), you compute $\phi(K)^T V$ first, yielding a $d \times d$ matrix where $d$ is the feature dimension. This matrix can be updated recurrently: at each timestep, you add $\phi(k_t)^T v_t$ to the running state and compute $\phi(q_t)$ times the accumulated state.

This elegantly gives you $O(1)$ inference and parallel training. The problem? **Naïve linear attention underperforms standard attention substantially.** The paper notes this explicitly in Section 2: "naive linear attention suffers from significantly reduced performance compared to MHA-based transformers." The softmax normalization that was removed turns out to be important for model quality — it provides implicit sparsity (extreme values are suppressed), stabilizes gradients, and creates a sharper distinction between attended and ignored tokens.

**RWKV-4** (Peng et al., 2023) was the first architecture to close much of this quality gap while maintaining the efficiency properties. It reformulated the Attention Free Transformer (AFT) equation by replacing AFT's learned pairwise positional biases with a **channel-wise learned decay vector** $w$, where each feature channel decays at its own learned rate. The core operation in RWKV-4 is:

$$wkv_t = \frac{\sum_{i=1}^{t-1} e^{-(t-1-i)w + k_i} \odot v_i + e^{u + k_t} \odot v_t}{\sum_{i=1}^{t-1} e^{-(t-1-i)w + k_i} + e^{u + k_t}}$$

where $w \in \mathbb{R}^d$ controls per-channel decay rates and $u$ is a learned "bonus" that gives the current token special treatment. This is essentially a weighted average over past values, where the weights decay exponentially at different rates per channel. It can be computed recurrently in $O(1)$ per step and trained in parallel.

RWKV-4 became the first RNN to approximately match similarly-sized Transformers on language modeling benchmarks. But it had concrete limitations that this paper explicitly seeks to address:

- **Vector-valued states restrict memory capacity.** In RWKV-4, the recurrent state per head is a single vector of dimension $d$, storing a weighted sum of past $k \odot v$ pairs. This is a rank-1 representation per head — the model can only store information along a single direction per channel. Complex associations that require distinguishing between multiple key-value pairs within the same channel get collapsed into a single weighted sum.

- **The denominator in the WKV computation introduces numerical instability.** The normalization term (the denominator in the equation above) divides the accumulated weighted sum by the sum of weights. This is mathematically elegant — it keeps the output bounded — but it prevents a clean factorization into matrix-valued states, and the division operation is expensive and numerically delicate in low-precision training.

- **The decay schedule is static.** Once trained, each channel's decay rate $w$ is a fixed scalar. It doesn't change based on whether the current input contains important information or irrelevant noise. A model can't "decide" that a particular token deserves to persist longer in memory based on what it contains.

- **Token-shift is purely learned, not contextual.** RWKV-4's token-shift mechanism linearly interpolates between the current and previous token using a learned scalar per channel. This provides basic temporal mixing — the model learns how much attention to give to new vs. old information — but the mixing ratio is the same regardless of what the tokens actually contain. Important information that should override the past gets blended in at the same fixed rate as routine tokens.

**State Space Models (SSMs)**, particularly Mamba (Gu & Dao, 2023), addressed some but not all of these limitations through a different architectural philosophy. SSMs model sequences by maintaining a hidden state of basis function coefficients, updated via discretized differential equations. The key advance in Mamba was making the $A$ (state transition) and $B$ (input projection) matrices **data-dependent** — they change based on the input token, allowing the model to selectively retain or forget information.

Mamba achieved strong results and the paper uses it as a primary comparison point. But Mamba approaches the problem through a continuous-state differential equation framework, while RWKV approaches it through an attention-inspired decay-based weighted average. These are different inductive biases, and the paper's associative recall experiments (Figure 4) suggest that the decay-based formulation may be better suited to certain memory-intensive tasks — a point we return to when discussing the technical approach.

### The Specific Gap This Paper Fills

The paper positions itself in the lineage of architectures that have progressively closed the quality gap with Transformers while maintaining O(1) inference: Linear Attention → AFT → RWKV-4 → Eagle → Finch. Each step addresses specific limitations of the prior architecture.

The key innovations that distinguish this work are:

1. **From vector to matrix states:** The paper identifies that RWKV-4's vector-valued state is fundamentally limited for multi-query associative recall — a task that tests whether a model can remember and retrieve multiple key-value associations presented in context. This is directly relevant to in-context learning ability (Section 8.2). Expanding the state to a matrix ($K^T V$ per head, dimension $64 \times 64$) gives each head the capacity to represent multiple independent associations without destructive interference. The paper quantifies this: the state size jumps from $5DL$ in RWKV-4 to $66DL$ in Eagle/Finch — a >10× expansion that directly addresses the representational bottleneck.

2. **From static to data-dependent decay:** In Eagle, the decay rate $w$ remains a learned vector shared across the sequence (though it is now applied to matrix-valued states). In Finch, $w_t$ becomes **time-varying and input-dependent**, generated through LoRA-augmented linear interpolations that take both the current and previous token as input. This means the model can decide, token-by-token and channel-by-channel, whether to retain or overwrite information. If a token contains critical information, the decay can be slowed (setting $w_t$ close to 1 for relevant channels), effectively "locking" that information into the state. If a token is irrelevant, decay can proceed at the normal rate.

3. **Data-dependent token-shift:** Finch extends the token-shift mechanism in the same way — the interpolation ratio between current and past token becomes a function of the tokens themselves, not just a learned static parameter. This builds on the intuition that the model should be able to "flag" important information for inclusion in the state, effectively pre-filtering before information even enters the recurrence.

### Why This Matters Now

The paper is motivated by converging practical and research trends:

**On the deployment side:** As LLMs are integrated into production systems, inference costs dominate. Training happens once; inference happens millions or billions of times. The quadratic memory cost of Transformer attention means that supporting long contexts (16k, 32k, 128k tokens) requires proportional increases in GPU memory, directly translating to higher hardware costs. An architecture with O(1) memory per token fundamentally changes this calculus — the 66DL state might be large in absolute terms (865M parameters for Eagle-7B's state), but it's fixed regardless of whether the context is 4k or 128k tokens.

**On the capability side:** Long-context reasoning is increasingly important for applications like code understanding (entire repositories), document analysis (legal contracts, scientific papers with appendices), and multi-turn conversation. The paper's experiments on PG19 (Figure 5) and Bamboo (Table 5) directly address whether RNN architectures can actually use long contexts effectively, not just handle them efficiently.

**On the research side:** The paper was written at a moment when multiple research groups were simultaneously discovering that adding data-dependence to recurrent states dramatically improves quality (Mamba, GateLoop, GLA all appeared around the same time). Eagle and Finch represent the application of this principle specifically within the RWKV decay-based framework, and the paper's systematic ablations (Appendix J, K) help disentangle which architectural choices matter and why.

### How This Paper Differs from Prior RWKV Work

The paper is explicit that it builds directly on RWKV-4, and the architectural evolution is presented as incremental but cumulative: each change addresses a specific limitation, and the combined effect is substantial. The paper's own ablation (Table 18) shows that training an identical-sized model (170M parameters) on identical data (the Pile) with the RWKV-6 architecture improves average benchmark accuracy from 47.7% (RWKV-4) to 50.7%, matching or exceeding Mamba (50.1%) and substantially outperforming Pythia (47.9%).

The paper also contributes **engineering infrastructure** — a new tokenizer, a new dataset, public code and weights — that makes this architecture practically usable. This is acknowledged explicitly: "A completely open training pipeline to enable interpretability and reproducibility of alternative-architecture LLMs" (Table 2 shows that for 7B+ models, Eagle is among the only architectures with fully open weights, training code, inference code, and training data).

### The Unifying Thesis

If there is a single idea that ties together all the architectural changes from RWKV-4 → Eagle → Finch, it is this: **recurrent states need to be both high-dimensional (to store complex associations without interference) and contextually adaptive (to selectively retain important information).** Vector-valued states limit the former; static decay schedules limit the latter. Eagle addresses the first; Finch addresses both. The experiments are designed to test whether each of these improvements actually matters and whether the resulting architecture can genuinely compete with Transformers — not just on efficiency, but on quality.

## 3. Technical Approach

### 3.1 Reader Orientation

**What the system is:** Eagle and Finch are recurrent neural network architectures for language modeling that process text one token at a time while maintaining a fixed-size internal memory called a *state*, which summarizes all previously seen information.

**What problem it solves and the shape of the solution:** The problem is the tradeoff between training efficiency (where Transformers excel through parallel computation across all tokens simultaneously) and inference efficiency (where RNNs excel through constant-time, constant-memory per-token processing). Eagle and Finch solve this by redesigning the internal state to be both *high-dimensional* (storing rich associations in a matrix rather than a vector) and, in Finch's case, *contextually adaptive* (letting the model decide, token by token, what to remember and what to forget based on what it reads). This means the model trains in parallel like a Transformer but runs inference like an RNN — with O(1) cost per token regardless of sequence length — while achieving competitive quality.

### 3.2 Big-Picture Architecture (Diagram in Words)

The Eagle/Finch architecture is a stack of identical residual blocks, each containing two sub-layers (following the Transformer convention):

1. **Input Embedding Layer:** Converts discrete tokens (integers representing words or subwords) into continuous vectors of dimension $D$. The output is a sequence of vectors $X \in \mathbb{R}^{L \times D}$, where $L$ is the sequence length.

2. **Stacked Residual Blocks (×L layers):** Each block processes the output of the previous layer through two sequential sub-components:

   - **Time-Mixing sub-layer** (analogous to Transformer attention): This is where the recurrent computation happens. It takes the current token and the previous token as input, uses a *token-shift* mechanism to blend new and old information, projects them into *receptance* (r), *key* (k), *value* (v), and *gate* (g) vectors, updates a matrix-valued recurrent state $s \in \mathbb{R}^{(D/h) \times (D/h)}$ per head (storing a weighted sum of $k^T v$ pairs with exponential decay), and produces an output that combines the current query (receptance) with the accumulated memory. In Finch, the amount of old-vs-new blending and the decay rates are themselves functions of the input tokens, making the recurrence *data-dependent*.

   - **Channel-Mixing sub-layer** (analogous to Transformer feed-forward): This is a position-wise MLP that processes each token independently, with its own token-shift mechanism. It takes the current and previous token, applies linear projections and a squared ReLU activation, and gates the output through a sigmoid. This is where most of the model's capacity for non-linear transformation resides.

3. **Output LayerNorm and Projection:** After all $L$ blocks, a final LayerNorm normalizes the hidden representation, and a linear projection maps back to vocabulary size $V$ to produce logits for next-token prediction.

The critical design principle: **the only temporal interaction occurs in the Time-Mixing sub-layer through the recurrent state.** Everything else — the Channel-Mixing, the LayerNorms, the input and output embeddings — operates independently at each position. This means that during training, once the recurrent state computation is parallelized (using techniques like associative scan or custom CUDA kernels), the entire model can process all tokens simultaneously. During inference, only the recurrent state needs to be carried forward, and its size is fixed regardless of context length.

### 3.3 Roadmap for the Deep Dive

We will build understanding from the ground up, explaining each mechanism before introducing the refinements that depend on it:

- **First, the Token-Shift mechanism (Eagle version):** This is the simplest temporal operation — how the model blends information from the current and previous token. Understanding this is essential because token-shift feeds into every other computation and because Finch's primary innovation is making token-shift data-dependent.

- **Second, the Eagle Time-Mixing computation:** The core recurrent operation — how key, value, and receptance interact with a decaying matrix-valued state to produce outputs. This establishes the *matrix state* concept and the *static decay* baseline.

- **Third, the Channel-Mixing module:** The position-wise feed-forward component, which is unchanged between Eagle and Finch but is structurally important and parameter-count-significant.

- **Fourth, Finch's data-dependent innovations:** Building squarely on Eagle, Finch makes two things data-dependent — the token-shift interpolation weights (via DDLerp) and the time-decay rates (via LoRA-augmented decay). We explain these as *modifications* to the Eagle baseline, showing exactly what changes and why.

- **Fifth, the recurrent formulation and parallelization:** How these equations can be written as an RNN cell (for inference) and how they are parallelized across the time dimension (for training). This connects the mathematics to the practical efficiency claims.

This order ensures that each new concept has its prerequisites established. You cannot understand data-dependent decay without first understanding what static decay does; you cannot understand the matrix state without seeing why the vector state in RWKV-4 was limiting.

### 3.4 Detailed, Sentence-Based Technical Breakdown

This is primarily an **architectural design paper** whose core idea is that recurrent language models can match Transformer quality if their recurrent states are both *high-dimensional enough to avoid representational bottlenecks* (matrix-valued, not vector-valued) and *contextually adaptive enough to selectively retain important information* (data-dependent decay and token-shift).

#### Token-Shift in Eagle: Blending Past and Present

Token-shift is the mechanism by which RWKV architectures incorporate information from the immediately preceding token without requiring a full attention computation over the entire history. It is the minimal temporal interaction — a learned per-channel linear interpolation between the current token's embedding and the previous token's embedding.

The operation is defined through a helper function, the **linear interpolation (lerp)**:

$$ \text{lerp}_\square(a, b) = a + (b - a) \odot \mu_\square $$

where $a$ and $b$ are vectors of dimension $D$ (typically $a$ is the previous token's representation and $b$ is the current token's representation), $\mu_\square \in \mathbb{R}^D$ is a learnable vector of interpolation coefficients (one per channel), and $\odot$ denotes element-wise (Hadamard) multiplication. The subscript $\square$ indicates that different learned $\mu$ vectors are used for different projections (receptance, key, value, gate).

**What it computes:** For each channel (feature dimension) independently, lerp computes a weighted blend between $a$ and $b$. When $\mu_i = 0$ for channel $i$, the output is purely $a$ (the previous information). When $\mu_i = 1$, the output is purely $b$ (the new information). When $\mu_i = 0.5$, the output is the exact average. The vector $\mu$ is learned during training, so the model decides per-channel how much of the past versus present to retain.

**Why this form:** This is equivalent to a 1D causal convolution with kernel size 2, but with a crucial computational property: instead of learning two independent weight matrices (one for the current token, one for the previous), the lerp formulation enforces a *linear relationship* between them. The weight on the previous token is $\mu$ and the weight on the current token is $1 - \mu$. This parameter sharing drastically reduces the number of parameters needed for temporal mixing and provides an inductive bias that the job of each channel is to decide *how much* to mix rather than learning completely independent filters. It also means that the token-shift operation is trivially reversible during parallel training — you can compute it for all positions simultaneously by shifting the sequence and applying the lerp.

**What token-shift enables:** The paper argues that token-shift makes it possible to form induction heads within a single layer. An induction head — the mechanism believed to underlie in-context learning — needs to: (1) attend to a previous occurrence of the current token, and (2) predict that the token that followed it previously will follow again. With token-shift, a single head can have access to both the current token's embedding (to form a query) and the previous token's embedding (to accumulate into the state), in different learned proportions for different subspaces (receptance vs. key vs. value). This means the circuitry for matching patterns across time can exist within a single layer rather than requiring cross-layer coordination.

#### Eagle Time-Mixing: Matrix-Valued States with Static Decay

The Time-Mixing module is the heart of the architecture — where the recurrent state lives and where computation across time happens. Eagle's version introduces two major changes from RWKV-4: the state becomes a matrix (specifically, a $K^T V$ outer product per head) rather than a vector, and the normalization denominator from RWKV-4 is eliminated.

**Step 1: Token-shift and projection.** For each of four roles — receptance (r), key (k), value (v), gate (g) — the model first applies token-shift to blend the current and previous token, then projects through a learned weight matrix:

$$ \square_t = \text{lerp}_\square(x_t, x_{t-1}) W_\square, \quad \square \in \{r, k, v, g\} $$

where $x_t \in \mathbb{R}^D$ is the input to the Time-Mixing module at position $t$ (the output of the previous layer's Channel-Mixing or the embedding), $W_\square \in \mathbb{R}^{D \times (D/h)}$ are learned projection matrices, and $h$ is the number of heads (with $D/h = 64$ by design — the head dimension is always 64 regardless of model size). The lerp uses different learned $\mu_r$, $\mu_k$, $\mu_v$, $\mu_g$ vectors for each role.

**What happens here:** The model looks at both the current token and the previous token (via token-shift), decides how much of each to use per channel for each role, and projects them into a lower-dimensional per-head space. The receptance $r_t$ will act like a query — "what should I look for in memory?" The key $k_t$ will act like an address — "where should current information be stored?" The value $v_t$ is the content to be stored. The gate $g_t$ will control how much of the retrieved information flows to the output.

**Step 2: Static decay rate computation.** The per-channel decay rate $w$ is not directly learned — instead, a raw parameter $\omega \in \mathbb{R}^{D/h}$ is learned, and the actual decay is computed as:

$$ w = \exp(-\exp(\omega)) $$

**What this computes:** The double exponential ensures that $w$ is strictly in the interval $(0, 1)$. The outer $\exp$ takes the negative of $\exp(\omega)$, which is always positive, producing a value between 0 (when $\exp(\omega)$ is large) and 1 (when $\exp(\omega)$ is very negative). Specifically, if $\omega_i$ is large and positive, $\exp(\omega_i)$ is large, $\exp(-\exp(\omega_i))$ approaches 0, meaning channel $i$ decays quickly (forgets fast). If $\omega_i$ is very negative, $\exp(\omega_i)$ approaches 0, $\exp(-0) = 1$, meaning channel $i$ retains information indefinitely.

**Why this form:** This parameterization has two desirable properties. First, it guarantees that $\text{diag}(w)$ is a contraction mapping in the recurrent update — each application of the decay multiplies the state by a factor less than 1, ensuring the state doesn't explode over long sequences. Second, it maps the unconstrained learned parameter $\omega \in \mathbb{R}$ to a valid decay rate in $(0, 1)$ smoothly, which is better for gradient-based optimization than, say, a sigmoid (which would saturate at the extremes).

In Eagle, $w$ is a fixed learned vector — it is the same for every position in every sequence. This is the "static decay" that Finch will later make data-dependent.

**Step 3: The WKV computation (matrix-valued recurrent state).** This is the core operation. The recurrent state at position $t$ for a given head is a matrix $s_t \in \mathbb{R}^{(D/h) \times (D/h)}$, computed as:

$$ wkv_t = \text{diag}(u) \cdot k_t^T \cdot v_t + \sum_{i=1}^{t-1} \text{diag}(w)^{t-1-i} \cdot k_i^T \cdot v_i $$

where $\text{diag}(u)$ and $\text{diag}(w)$ are diagonal matrices with the vectors $u$ and $w$ on their diagonals, respectively. The vector $u \in \mathbb{R}^{D/h}$ is a learned "bonus" parameter that gives special treatment to the current token. The product $k_t^T \cdot v_t$ is an outer product: if $k_t$ and $v_t$ are row vectors of dimension $D/h$, then $k_t^T$ is a column vector of dimension $D/h \times 1$ and $v_t$ is a row vector of dimension $1 \times D/h$, so their product is a matrix of dimension $(D/h) \times (D/h)$.

**What this computes:** At each timestep, the model adds the current token's information (as $k_t^T v_t$) to a running sum that decays over time. The decay is per-channel: each row of the state matrix (corresponding to one dimension of the key) decays independently at the rate $w_i$. At position $t$, information from position $i < t$ has been multiplied by $w^{t-1-i}$ — if the decay rate is 0.9, information from 10 steps ago contributes $0.9^{10} \approx 0.35$ of its original strength; information from 100 steps ago contributes $0.9^{100} \approx 0.000027$, effectively zero.

The current token gets special treatment through $u$: rather than being multiplied by 1 (as it would be if we just set $u = \mathbf{1}$), the model learns a per-channel boost. If $u_i > 1$ for some channel, the current token's contribution to that row of the state is amplified relative to the accumulated history, making the model more "recency-biased" along that dimension. If $u_i < 1$, the current token is attenuated, making the model rely more on history.

**Why the matrix state matters:** The outer product $k^T v$ has rank 1 by construction (it's the product of a column vector and a row vector). However, the *sum* of many such rank-1 matrices can have rank up to $\min(t, D/h)$. This means the state can represent up to $D/h$ independent associations (key-value pairs) simultaneously. In RWKV-4, the state was a vector $k \odot v$ — a rank-1 object that collapses all information along a single direction. Two different key-value pairs in the same channel would destructively interfere: if you add $(k_1, v_1)$ and then $(k_2, v_2)$ along the same channel, you get a single blended vector that cannot distinguish the two associations. With a matrix state, different keys put information in different *rows* of the matrix, allowing multiple associations to coexist without interference — as long as the key vectors are approximately orthogonal.

The paper quantifies this: for a head dimension of 64, the state matrix is $64 \times 64$, meaning it can theoretically store up to 64 linearly independent key-value associations per head. This is the fundamental representational advance over RWKV-4.

**Recurrent formulation (equivalent, used for inference):**

$$ wkv' = s + \text{diag}(u) \cdot k^T \cdot v $$
$$ s' = \text{diag}(w) \cdot s + k^T \cdot v $$

Here, $s \in \mathbb{R}^{(D/h) \times (D/h)}$ is the recurrent state carried forward from the previous timestep. At each new token, the state is: (1) decayed by multiplying each row by the corresponding $w_i$, (2) the current token's $k^T v$ is added, and (3) the output is this updated state plus a bonus term that gives the current token special weight via $u$.

**Step 4: Output computation with gating.** The WKV state is queried using the receptance, normalized, gated, and projected:

$$ o_t = \text{concat}\left(\text{SiLU}(g_t) \odot \text{LayerNorm}(r_t \cdot wkv_t)\right) W_o $$

Let me unpack this step by step:

- $r_t \cdot wkv_t$: The receptance vector $r_t$ (dimension $D/h$) right-multiplies the WKV matrix (dimension $(D/h) \times (D/h)$), producing a vector of dimension $D/h$. This is the "read" operation: $r_t$ acts as a query that extracts a weighted combination of the rows of the WKV matrix. If the WKV matrix stores key-value associations, then $r_t$ retrieves the values associated with keys that are similar to $r_t$.

- $\text{LayerNorm}(r_t \cdot wkv_t)$: This output is normalized using LayerNorm applied independently to each of the $h$ heads (equivalent to GroupNorm with $h$ groups). This stabilizes the scale of the WKV output, which can vary dramatically depending on how much information has accumulated in the state.

- $\text{SiLU}(g_t)$: The gate vector $g_t$ is passed through a SiLU (Sigmoid Linear Unit) activation — $x \cdot \sigma(x)$ — which acts as a soft gating mechanism. Unlike a sigmoid (which can only attenuate, producing values in $(0, 1)$), SiLU can also amplify (producing values > 1 for positive inputs) and is smooth, non-monotonic, and unbounded above.

- $\text{SiLU}(g_t) \odot \text{LayerNorm}(r_t \cdot wkv_t)$: The gated gate multiplies the normalized WKV output element-wise. This allows the model to selectively amplify or suppress the information retrieved from the recurrent state based on the current token's content. If the retrieved memory is irrelevant to the current context, the gate can suppress it; if it's highly relevant, the gate can amplify it.

- The concatenated outputs from all heads are projected back to dimension $D$ via $W_o \in \mathbb{R}^{D \times D}$.

**Why remove the denominator?** In RWKV-4, the WKV computation had a normalizing denominator: $wkv_t = \frac{\text{numerator}}{\text{denominator}}$, where the denominator was the sum of the same decay weights used in the numerator. This normalization kept the output bounded but had two drawbacks: (1) it prevented the clean matrix-valued formulation because dividing a matrix by a vector channel-by-channel is not a standard linear algebra operation, and (2) the division introduces numerical instability in low-precision training (bfloat16). By removing the denominator and relying on LayerNorm for stabilization, Eagle gains the ability to use matrix-valued states while maintaining training stability.

**Why SiLU gating on the output rather than sigmoid on receptance?** In RWKV-4, the receptance itself was passed through a sigmoid: $\sigma(r_t)$ was multiplied with the WKV output. This meant the receptance played a dual role — it was both the query (determining *what* to retrieve) and a gate (determining *how much* of the output to use). In Eagle, these roles are separated: receptance is purely a query (no activation function, it interacts with the WKV matrix directly), and a separate gate vector $g_t$ controls the output magnitude. This separation gives the model more flexibility — the same receptance vector can be used to retrieve information while the gate independently decides whether to use it.

#### Channel-Mixing: Position-Wise Feed-Forward with Token-Shift

The Channel-Mixing module is the second sub-layer of each residual block, analogous to the Feed-Forward Network in a Transformer. It processes each position independently (no cross-position interaction except via token-shift) and is where most of the model's non-linear computation happens.

The computations are:

$$ r'_t = \text{lerp}_{r'}(x'_t, x'_{t-1}) W_{r'} \in \mathbb{R}^D $$
$$ k'_t = \text{lerp}_{k'}(x'_t, x'_{t-1}) W_{k'} \in \mathbb{R}^{3.5D} $$
$$ v'_t = \text{ReLU}(k'_t)^2 W_{v'} \in \mathbb{R}^D $$
$$ o'_t = \sigma(r'_t) \odot v'_t \in \mathbb{R}^D $$

where $x'_t$ is the output of the Time-Mixing sub-layer at position $t$, $W_{r'} \in \mathbb{R}^{D \times D}$, $W_{k'} \in \mathbb{R}^{D \times 3.5D}$, and $W_{v'} \in \mathbb{R}^{3.5D \times D}$ are learned weight matrices.

**What this computes, step by step:**

1. The *receptance* $r'_t$ is produced by token-shifting (blending the current and previous Time-Mixing outputs), then projecting through $W_{r'}$. It will act as a gate.

2. The *key* $k'_t$ is produced similarly but projected to a higher dimension ($3.5D$ rather than $D$). This expansion gives the non-linearity more room to operate.

3. The *value* $v'_t$ applies a squared ReLU to the key: first set all negative values to zero, then square what remains. This is a specific non-linear activation — $\text{ReLU}(x)^2$ — that is smooth (unlike ReLU), non-negative, and grows quadratically for positive inputs. Then project back to dimension $D$.

4. The output $o'_t$ gates the value with the receptance: $\sigma(r'_t)$ produces values in $(0, 1)$ (sigmoid), and these are multiplied element-wise with $v'_t$. This is a standard gating mechanism — the model learns which channels of the value to pass through and which to suppress.

**Why $3.5D$ hidden dimension?** In RWKV-4, the Channel-Mixing hidden dimension was $4D$. Eagle reduces this to $3.5D$ to compensate for the additional parameters introduced by the new SiLU gating in the Time-Mixing module. The goal is to maintain approximately the same total parameter count as RWKV-4 at equal model dimension and layer count, enabling fair comparison. The parameter count formula (Equation 23) confirms this: $\#(\text{Params})_E = 13D^2L + 14DL + 4D + 2DV$, which includes both the Time-Mixing and Channel-Mixing parameters.

**Why squared ReLU?** The paper doesn't explicitly justify this choice, but squared ReLU ($\text{ReLU}(x)^2$) has properties that make it suitable for language modeling: it's non-negative (the value representation is naturally non-negative, acting like a magnitude), it's smooth at zero (unlike ReLU, which has a discontinuity in its derivative), and it grows faster than linearly for large inputs (allowing strong activations to dominate). The gating via sigmoid receptance then selectively scales each channel.

#### Finch Token-Shift: Data-Dependent Linear Interpolation (DDLerp)

Finch's primary innovation is making the token-shift mechanism *data-dependent* — the interpolation ratio between old and new information is no longer a fixed learned parameter but a function of the input tokens themselves. This means the model can decide, for each token and each channel, how much to blend based on *what* the tokens contain.

The mechanism uses two new components: **LoRA-augmented parameters** and a **two-stage interpolation**.

**LoRA augmentation (the building block):**

$$ \text{lora}_\square(x) = \lambda_\square + \tanh(x A_\square) B_\square $$

where $x \in \mathbb{R}^D$ is an input vector, $\lambda_\square \in \mathbb{R}^D$ is a learned base value, $A_\square \in \mathbb{R}^{D \times 32}$ and $B_\square \in \mathbb{R}^{32 \times D}$ are learned low-rank weight matrices, and $\tanh$ is applied element-wise. The output is a vector of dimension $D$.

**What this computes:** This is an adaptation of Low-Rank Adaptation (LoRA, Hu et al., 2022) applied to *vectors* rather than weight matrices. The input $x$ is first compressed to a 32-dimensional bottleneck via $A_\square$, passed through $\tanh$ (which squashes to $(-1, 1)$), and then expanded back to $D$ dimensions via $B_\square$. The result is added to a learned base value $\lambda_\square$. Crucially, the $\tanh$ ensures the correction term is **bounded** — it can shift the base value by at most the row norms of $B_\square$, preventing the data-dependent component from producing extreme values.

**Why LoRA?** Directly learning a $D \times D$ matrix to transform the input into an interpolation coefficient would cost $D^2$ parameters per use — prohibitively expensive at scale. The low-rank bottleneck ($D \times 32$ then $32 \times D$) reduces this to $2 \times 32D = 64D$ parameters, which is a minor addition. The intuition is that the data-dependent adjustment to the interpolation coefficient is a low-complexity function — 32 dimensions suffice to capture the relevant variation.

**DDLerp (the full data-dependent interpolation):**

$$ \text{ddlerp}_\square(a, b) = a + (b - a) \odot \text{lora}_\square(a + (b - a) \odot \mu_x) $$

where $a$ and $b$ are the previous and current token representations (as in the standard lerp), $\mu_x \in \mathbb{R}^D$ is a learned base interpolation vector (like the original Eagle token-shift), and $\text{lora}_\square$ is applied to a *pre-blended* input.

**What this computes:** This is a two-stage process:

1. **First stage (inside the lora input):** $a + (b - a) \odot \mu_x$ computes an initial blend of old and new information using the *fixed* learned vector $\mu_x$. This is exactly the standard Eagle token-shift, producing a vector that represents "the input as the model would normally see it."

2. **Second stage (the lora output):** The lora function takes this pre-blended vector and produces a *correction* to a base interpolation coefficient. The output $\text{lora}_\square(\cdot)$ is a vector in $\mathbb{R}^D$ representing per-channel interpolation weights.

3. **Final blend:** $a + (b - a) \odot \text{lora}_\square(\cdot)$ uses these data-dependent weights to blend $a$ and $b$. For channel $i$, if $\text{lora}_\square(\cdot)_i = 0$, the output is purely $a_i$ (the previous token). If $\text{lora}_\square(\cdot)_i = 1$, the output is purely $b_i$ (the current token). Values can also fall outside $[0, 1]$ because the lora output is $\lambda_\square$ plus a bounded correction — this allows extrapolation, meaning the model can *amplify* the difference rather than just interpolating.

**Why two stages?** The first stage ($\mu_x$ blend) provides a sensible default interpolation — a learned baseline that works well on average. The lora correction then adjusts this baseline based on the content of the (pre-blended) token. If the current token contains critical information, the lora can increase the interpolation weight (closer to 1) for relevant channels, ensuring that information enters the state with less attenuation from the past. If the current token is routine, the weight stays near the baseline.

**Parameter count and scaling:** For each of the five uses of ddlerp in Finch (receptance $r$, key $k$, value $v$, gate $g$, and the decay input $d$), separate $\lambda_\square$, $A_\square$, and $B_\square$ parameters are learned. Additionally, $A_\omega$ and $B_\omega$ for the time-decay $w$ are double-sized: $A_\omega \in \mathbb{R}^{D \times 64}$, $B_\omega \in \mathbb{R}^{64 \times D}$. The paper notes that "future 7B and larger Finch models are expected to further increase the size of these weight matrices by double or more," suggesting that the 32/64 bottleneck dimensions are a preliminary choice that may scale with model size.

#### Finch Time-Mixing: Data-Dependent Decay

The core change in Finch Time-Mixing is that the decay rate $w$ — which was a static learned vector in Eagle — becomes *time-varying and input-dependent*. This means that at each timestep, the model can decide, for each channel, whether to retain or forget information based on what it's currently reading.

**Step 1: Data-dependent token-shift for projections.** Same structure as Eagle, but with ddlerp replacing lerp:

$$ \square_t = \text{ddlerp}_\square(x_t, x_{t-1}) W_\square, \quad \square \in \{r, k, v, g\} $$

Each of the four roles gets its own ddlerp parameters ($\lambda_\square$, $A_\square$, $B_\square$), allowing the interpolation ratio to be role-specific and context-dependent.

**Step 2: Data-dependent decay computation.** This is the key innovation:

$$ d_t = \text{lora}_d(\text{ddlerp}_d(x_t, x_{t-1})) $$
$$ w_t = \exp(-\exp(d_t)) $$

**What this computes:** First, $\text{ddlerp}_d(x_t, x_{t-1})$ produces a data-dependent blend of the current and previous token (using the ddlerp mechanism with its own learned parameters). This blended vector is then passed through $\text{lora}_d$ — another LoRA-augmented function that produces the raw decay parameters $d_t \in \mathbb{R}^{D/h}$. Finally, $w_t = \exp(-\exp(d_t))$ maps these to valid decay rates in $(0, 1)$, just as in Eagle.

The critical difference: in Eagle, $d$ was a fixed learned vector $\omega$ — the same for all positions. In Finch, $d_t$ depends on both $x_t$ and $x_{t-1}$ through the ddlerp mechanism, making it *time-varying*. Each channel's decay rate at position $t$ can be different from its decay rate at position $t+1$, determined by what the model reads.

**Why this matters:** This enables *selective retention*. If the model encounters a token containing a name or key fact that will be referenced later, it can set $w_t$ close to 1 for relevant channels, ensuring that this information persists in the state rather than being decayed away. Conversely, if the current token is filler or noise, the decay can proceed at its normal rate, overwriting old information. This is analogous to the "forget gate" in an LSTM, but it's applied to a matrix-valued state and driven by the content of the current and previous tokens.

The paper describes this as "a second-order variant of Token-Shifting" — intuitively, the decay rate at time $t$ is determined by a blend of the current and prior token ($x_t$ and $x_{t-1}$), where the blend itself is determined by aspects of both tokens (through the lora mechanism). This is "second-order" because it's using past information to decide how much to weight the present, and then using that decision to control how the state evolves.

**Step 3: Time-varying WKV computation.** The recurrence now uses position-dependent $w_t$:

$$ wkv_t = \text{diag}(u) \cdot k_t^T \cdot v_t + \sum_{i=1}^{t-1} \text{diag}\left(\prod_{j=i+1}^{t-1} w_j\right) \cdot k_i^T \cdot v_i $$

where the product $\prod_{j=i+1}^{t-1} w_j$ is element-wise over the sequence of decay vectors from position $i+1$ to $t-1$. For each channel, this product represents the cumulative decay between when information was stored (position $i$) and the current position ($t$).

**What this computes:** Information from position $i$ is decayed by the product of all subsequent $w_j$ vectors. If at some position $j$ between $i$ and $t$, the model set $w_j$ to a very small value (near 0) for some channel, information from before $j$ is essentially erased along that channel — subsequent multiplications by $w_{j+1}, w_{j+2}, \ldots$ cannot recover it. This gives the model the ability to "reset" parts of its state when a topic shift occurs or when old information becomes irrelevant.

**Recurrent formulation:**

$$ wkv' = s + \text{diag}(u) \cdot k^T \cdot v $$
$$ s' = \text{diag}(w) \cdot s + k^T \cdot v $$

The recurrent update is identical in form to Eagle, but $w$ is now $w_t$ (computed fresh at each step) rather than a fixed vector. This means the state evolution is fully described by the recurrence, with the caveat that $w_t$ must be computed from the inputs before the state update.

**Step 4: Output computation.** Identical to Eagle:

$$ o_t = \text{concat}\left(\text{SiLU}(g_t) \odot \text{LayerNorm}(r_t \cdot wkv_t)\right) W_o $$

The output mechanism doesn't change — it's the *content* of the WKV state and the *decay dynamics* that differ.

**Why the loRA chain for $d_t$?** The computation $d_t = \text{lora}_d(\text{ddlerp}_d(x_t, x_{t-1}))$ applies two levels of data-dependence: first ddlerp produces a context-dependent blend of the two tokens, then lora applies another data-dependent transformation to produce the final decay parameters. This two-stage design means the model can first decide *what* information to consider (via ddlerp's content-dependent interpolation) and then decide *how much to decay* based on that information (via lora). The paper's ablation in Appendix K confirms that removing the data-dependence from token-shift while keeping it on decay hurts less than removing it entirely, but the full ddlerp provides the best results (Table 19: Finch validation loss 2.91, DDLerp only on decay 2.923, no DDLerp 2.926).

#### Recurrent Formulation and Parallelization

The equations presented above for both Eagle and Finch can be written as an RNN cell — a function that takes the current input $x_t$, the previous state $s_{t-1}$, and the previous token representations (for token-shift) and produces the current output $o_t$ and updated state $s_t$. The PyTorch implementation in Appendix B shows this compactly:

```python
def rwkv_5_or_6_recurrent(r, k, v, w, u, wkv_state):
    kv = k.mT @ v      # outer product: (D/h) x (D/h)
    out = r @ (wkv_state + u.mT * kv)
    wkv_state = w.mT * wkv_state + kv
    return out, wkv_state
```

Here, `k.mT` is the transpose of `k` (converting a row vector to a column vector), `@` is matrix multiplication, and `*` is element-wise multiplication after broadcasting. The state `wkv_state` is updated in-place: each head's state matrix is decayed by the corresponding $w$ values and then augmented with the current $k^T v$.

**For inference**, this recurrent formulation gives exactly O(1) time and O(1) memory per token. The state size is $h \times (D/h) \times (D/h) = D^2/h = 64D$ per layer (since $h = D/64$). Across $L$ layers, plus the token-shift context (storing $x_{t-1}$ for both Time-Mixing and Channel-Mixing, $2D$ per layer), the total state size is $66DL$ (Equation 30). For Eagle-7B ($D = 4096$, $L = 32$), this is $66 \times 4096 \times 32 = 8,650,752$ floating-point numbers, or about 35 MB in bfloat16.

**For training**, the challenge is parallelizing across the time dimension. The paper takes a specific approach: rather than using associative scan (which Mamba uses) or other time-parallel algorithms, they **parallelize over non-time dimensions only** while using a custom CUDA kernel that keeps the state operations in fast SRAM. The justification is that the repeated memory transfers between SRAM and HBM in fully time-parallel approaches (like associative scan) prove "inefficient" — the cost of moving the state matrix on and off chip dominates. By keeping the recurrence sequential in time but parallelized across batch and head dimensions, they achieve high GPU utilization without the memory bandwidth bottlenecks of time-parallel methods.

The paper also provides a pure PyTorch implementation that does parallelize over time using an algorithmic approach similar to GLA (Yang et al., 2023), for environments where the custom CUDA kernel isn't available.

**Why this parallelization strategy?** The state matrix is $(D/h) \times (D/h) = 64 \times 64$ for all model sizes. This is small enough to fit entirely in on-chip SRAM, meaning the recurrence can be computed without accessing HBM for the state. Time-parallel methods like associative scan require materializing intermediate results across the time dimension, which forces HBM access. The paper's benchmarks (Figures 6 and 7) show that this design choice pays off: Finch training time scales linearly with sequence length and is approximately 4.2× faster than Flash Attention at 16k sequence length.

#### Parameter Count and FLOPs Accounting

The paper provides exact formulas for parameter counts and FLOPs (Equations 23–29), which are important for understanding the cost implications of the architectural choices.

**Eagle parameter count:**
$$ \#(\text{Params})_E = 13D^2L + 14DL + 4D + 2DV $$

where $D$ is model dimension, $L$ is number of layers, and $V = 65536$ is vocabulary size. The dominant term is $13D^2L$ — the $13$ coefficient reflects the combined weight matrices in both Time-Mixing and Channel-Mixing sub-layers. This is directly comparable to a Transformer's $\approx 12D^2L$ — the architectures have similar parameter efficiency.

**Finch parameter count:**
$$ \#(\text{Params})_F = 13D^2L + 464DL + 4D + 2DV $$

The difference from Eagle is in the $DL$ term: $464DL$ vs. $14DL$. This $450DL$ difference comes from the LoRA parameters added for the data-dependent mechanisms. For Finch-3B ($D = 2560$, $L = 32$), this adds $450 \times 2560 \times 32 \approx 37$ million parameters — a modest increase of about 1.2% over Eagle-3B's 3.06B parameters.

**Inference FLOPs per token (Eagle):**
$$ \#(\text{InferFLOPs})_E = 26D^2L + 28DL + 8D + 4DV + 6D^2L/h $$

The first five terms are twice the parameter count (one multiply and one add per parameter), representing the cost of all linear transformations. The final term $6D^2L/h$ accounts for the WKV state operations: three matrix multiplications per head (computing $k^T v$, $r \cdot s$, and $u \cdot k^T v$ in the recurrent formulation), each costing approximately $2(D/h)^3$ FLOPs, summed over $hL$ heads.

**Training FLOPs per token (Eagle):**
$$ \#(\text{TrainFLOPs})_E = 78D^2L + 84DL + 16D + 12DV + 18D^2L/h $$

Training FLOPs are approximately 3× inference FLOPs (to account for the forward pass, backward pass with respect to activations, and backward pass with respect to weights), plus the WKV operations (which must be differentiated through in both the weight and activation backward passes, hence the increase from $6$ to $18$ in the coefficient).

For Eagle-7B, inference costs approximately 15.1 billion FLOPs per token, and training costs approximately 45.3 billion FLOPs per token. The total training budget for 1.12 trillion tokens is approximately $1.12 \times 10^{12} \times 4.53 \times 10^{10} \approx 5.1 \times 10^{22}$ FLOPs — a substantial but not extraordinary training cost for a 7B-parameter model.

**Why provide these formulas?** The paper's goal is transparency and reproducibility. By giving exact FLOP counts rather than approximate scaling laws, the paper enables direct comparison with other architectures on an equal footing — you can compute the training cost of a Transformer with the same parameter count and see whether Eagle/Finch actually uses fewer FLOPs per token (they don't — the advantage is in inference, not training cost per token).

#### Design Philosophy: Separating What from How

A subtle but important design principle emerges across both Eagle and Finch: **the separation of computational roles into distinct vectors.** In the Time-Mixing module, the receptance $r$ acts as a *query* (determining what information to retrieve), the key $k$ acts as an *address* (determining where to store information), the value $v$ is the *content* to be stored, and the gate $g$ controls *how much* of the retrieved information to use. In RWKV-4, some of these roles were conflated (receptance was both query and gate through the sigmoid). The separation in Eagle/Finch gives the model more degrees of freedom — it can, for example, retrieve a piece of information (via receptance) and then independently decide to suppress it (via gate) if it's not useful for the current context.

Similarly, in Channel-Mixing, the key $k'$ determines the non-linear transformation, and the receptance $r'$ gates how much of that transformation reaches the output. The squared ReLU on $k'$ ensures non-negative values (magnitudes), and the sigmoid on $r'$ provides a soft on/off switch per channel.

This design pattern — separate projections for separate computational roles, combined through gating — is a hallmark of the gated linear unit (GLU) family of architectures and appears in many successful models (LLaMA, Mistral, etc.). Eagle and Finch apply it systematically to both the temporal and channel dimensions.

#### Initialization Scheme

The paper provides an unusually detailed initialization scheme (Appendix I) that is critical for training stability. The scheme uses layer-dependent scaling, with parameters $r_0 = l/(L-1)$ and $r_1 = 1 - l/(L-1)$ that interpolate between early and late layers.

For Eagle Time-Mixing:

- **Token-shift coefficients:** $\mu_r$ and $\mu_g$ are initialized to $1 - (i/D)^{r_1/2}$, $\mu_k$ to $1 - (i/D)^{r_1}$, and $\mu_v$ to $1 - (i/D)^{r_1} - 0.3r_0$. This creates a systematic variation across channels (via $i/D$) and layers (via $r_0$, $r_1$): early layers ($r_0 \approx 0$, $r_1 \approx 1$) emphasize current information more; later layers ($r_0 \approx 1$, $r_1 \approx 0$) blend more evenly.

- **Time decay $w$:** Initialized to $-6 + 5(i/(D-1))^{0.7+1.3r_0}$. This produces decay rates that vary across channels and layers — from fast decay (small $w$) in early layers to slower decay (larger $w$) in later layers, with the steepness controlled by the exponent.

- **Time-first $u$:** Initialized to $r_0(1 - i/(D-1)) + 0.1((i+1) \bmod 3)$. The $(i+1) \bmod 3$ term adds a periodic component, creating structured variation across channels.

- **Output matrix and value/receptance matrices in Channel-Mixing:** Initialized to **zero**. This means that at initialization, the Time-Mixing output contribution is zero, and the Channel-Mixing output contribution is zero — the model starts as essentially a residual stream with only the embedding passing through. This "zero-init" technique prevents the model from making large random predictions at the start of training, which can destabilize the optimizer.

- **Embedding:** Initialized with uniform distribution $U(-\text{maxLR}, \text{maxLR})$, which is tiny (maxLR is at most $4 \times 10^{-4}$). This produces near-zero token embeddings initially, which interact well with the zero-initialized outputs — the model starts by predicting roughly uniformly over the vocabulary and gradually sharpens its predictions.

**Why this complexity matters:** Training deep RNNs is notoriously difficult due to vanishing and exploding gradients. The careful initialization scheme — particularly the zero-init for output projections and the layer- and channel-dependent scaling for temporal parameters — is likely essential for making the 32-layer, 4096-dimensional models train successfully. Without it, the recurrent state could either saturate (if decay rates are too extreme) or oscillate (if they're poorly balanced), preventing the model from learning long-range dependencies.

The Finch initialization builds on Eagle's scheme, with the additional LoRA weight matrices $A$ and $B$ initialized to uniform $U(-10^{-4}, 10^{-4})$ — effectively zero. This means that at initialization, Finch behaves identically to Eagle (the data-dependent corrections start at zero and are learned gradually), providing a stable starting point from which the model can learn to make its decay and token-shift context-dependent.

## 4. Key Insights and Innovations

### Innovation 1: Matrix-Valued States as a Representational Bottleneck Diagnosis — and Its Resolution

The paper's most intellectually distinctive contribution is not the matrix-valued state itself, but the **diagnosis that makes it necessary**. Prior work on efficient architectures — RWKV-4, Mamba, H3, RetNet — had incrementally improved recurrent and state-space models, but no one had explicitly framed the fundamental limitation of vector-valued states: they impose a **rank-1 bottleneck on associative memory**.

This is a conceptual move, not a mechanistic one. The insight is that storing information as a sum of vectors ($\sum k_i \odot v_i$ in RWKV-4) forces all key-value pairs assigned to the same channel to collapse into a single blended direction. Two different $k \odot v$ pairs in the same channel destructively interfere — the state cannot simultaneously represent "the capital of France is Paris" and "the currency of France is the Euro" along the same channel dimension without confusing them. The model could theoretically avoid this by using different channels for different facts, but this requires knowing at storage time which facts might need to be distinguished later — a circular requirement.

The paper **quantifies** this insight: the jump from vector-valued states ($5DL$ parameters in RWKV-4's state) to matrix-valued states ($66DL$ in Eagle/Finch) isn't just "more parameters" — it's a change in the **algebraic structure** of what the state can represent. A $64 \times 64$ matrix per head can store up to 64 linearly independent key-value associations simultaneously (assuming the key vectors are approximately orthogonal), whereas a vector can store exactly one direction per channel. This is why the associative recall experiments (Figure 4) show such a dramatic improvement — multi-query associative recall is the task that directly tests whether a model can store and retrieve multiple independent associations without interference.

**Prior work comparison:** Mamba (Gu & Dao, 2023) also uses a matrix-valued state in its SSM formulation, but through a different mechanism — the state is the SSM hidden state projected through the $B$ and $C$ matrices, not an accumulated $K^T V$ outer product. The paper's achievement is showing that within the decay-based attention framework (RWKV lineage), the matrix formulation is the *correct* generalization of the vector formulation, and that this single change — keeping everything else about the architecture the same — accounts for a substantial fraction of the performance gap between RWKV-4 and Transformers. This is demonstrated in the ablation (Table 18): Eagle's improvements over RWKV-4 on a controlled 170M-parameter comparison (same data, same tokenizer) isolate the effect of the matrix state and associated changes.

The significance of this insight extends beyond the paper: it suggests that future RNN architectures should think of the recurrent state not as a "memory vector" but as a **learned associative memory matrix** with explicit rank considerations. This reframes the design problem from "how do we compress the past into a fixed-size vector?" to "how do we structure the state so that independent pieces of information occupy approximately orthogonal subspaces?"

---

### Innovation 2: Data-Dependent Decay as a General Principle for Selective Memory in RNNs

The paper's second major conceptual contribution is demonstrating that **making the forgetting rate data-dependent** — rather than a fixed learned parameter — is the key to closing the remaining quality gap with Transformers. This was emerging as a theme in the 2023 architecture landscape (Mamba, GateLoop, GLA all introduced data-dependent state transitions around the same time), but the paper's contribution is to **instantiate this principle specifically within the decay-based framework** and to **show via controlled ablation exactly how much it matters**.

The conceptual insight is deceptively simple: a fixed decay rate means that every token is treated the same way by the memory system, regardless of its informational content. A token containing a proper noun that will be referenced later is forgotten at the same rate as a token containing a filler word. By making the decay rate a *function of the input*, the model can decide — token by token, channel by channel — whether to lock information into the state ($w_t \approx 1$) or let it decay normally ($w_t \ll 1$). This is the architectural equivalent of giving the model a "save" button for its working memory.

What distinguishes this paper's treatment from concurrent work:

**First**, the mechanism is conceptually layered. Finch's decay computation ($d_t = \text{lora}_d(\text{ddlerp}_d(x_t, x_{t-1}))$) applies data-dependence at two levels: first through the token-shift (deciding *which* information from past and present to consider when computing the decay), then through the LoRA transformation (deciding *how much* to decay based on that information). This "second-order" design — using past information to decide how much to weight the present, then using that to control state evolution — is a more nuanced version of data-dependence than simply making $w_t$ a learned linear function of $x_t$.

**Second**, the paper provides a clean ablation (Appendix K, Table 19) that isolates the contribution of data-dependent decay from data-dependent token-shift. Removing DDLerp from token-shift while keeping it on decay hurts validation loss (2.91 → 2.923); removing it entirely hurts more (2.91 → 2.926). This decomposes the contribution and shows it's *not* monotonic — the combination matters, not just the presence of data-dependence somewhere in the architecture.

**Third**, the paper ties this innovation directly to a measurable capability: the near-perfect MQAR performance of Finch (Figure 4). Associative recall requires the model to store associations and retrieve them later despite intervening distractor tokens. Data-dependent decay allows the model to "protect" stored associations by setting decay rates near zero for relevant channels during the distractor period, preventing the distractors from overwriting the stored information. This is a mechanistic explanation for *why* the architectural change improves a specific capability, not just an observed correlation.

The paper positions this as an incremental refinement of Eagle (Finch is presented as Eagle + data-dependent mechanisms), but the contribution is fundamental: it establishes that **static decay is a ceiling on RNN quality** and that data-dependent gating of memory is essential for matching Transformer-level in-context learning. This is a conceptual finding that applies beyond the RWKV lineage — it suggests that any recurrent architecture aiming for Transformer-quality performance needs a mechanism for content-based selective retention.

---

### Innovation 3: A Unified Framework for Understanding Why Matrix States + Data-Dependence Are Complementary

While the previous two innovations address individual mechanisms, the paper's most subtle intellectual contribution is the **implicit framework** it provides for understanding why matrix-valued states and data-dependent decay are *complementary* rather than alternative solutions to the same problem.

Prior to this work, one might have reasonably asked: "If data-dependent decay already lets the model selectively retain information, why do we need the expensive matrix state? Couldn't we just make the vector-valued RWKV-4 state data-dependent and get similar benefits?" The paper's answer, demonstrated across multiple experiments, is no — and the *reason* is itself the insight.

**Matrix-valued states provide capacity** — the ability to store many independent associations without interference. **Data-dependent decay provides selectivity** — the ability to decide *which* associations to keep and which to overwrite. These are orthogonal architectural properties. Without capacity, even perfect selectivity is useless — you can't protect what you can't store. Without selectivity, even large capacity is wasted — everything decays at the same rate regardless of importance.

The paper demonstrates this complementarity empirically:

- **Eagle (matrix state, static decay)** dramatically improves over RWKV-4 on associative recall (Figure 4) and MQAR tasks, showing that capacity alone addresses the rank-1 bottleneck. But on long-context language modeling (Figure 5, PG19), Eagle still shows loss increasing with sequence position — it can store more, but it can't selectively protect important information from being overwritten.

- **Finch (matrix state, data-dependent decay)** improves further on both MQAR (near-perfect accuracy) and long-context modeling (Figure 5, loss continues to drop further into the sequence). The data-dependent decay allows the model to lock in critical information (like character names, plot points) while letting routine details decay.

- **The gap between Eagle and Mamba on MQAR** (Figure 4) is particularly instructive. Mamba has both data-dependent state transitions and matrix-valued states (through its SSM formulation), yet Finch substantially outperforms it on MQAR. This suggests that *how* you implement these properties matters — the decay-based formulation in Finch may be better suited to associative recall than the continuous-state ODE formulation in Mamba. This is a finding about inductive bias, not just capacity.

This framework is never explicitly stated as a theorem or principle, but it pervades the paper's experimental design and argumentation. It represents a genuine conceptual advance: before this work, the field was exploring individual mechanisms in isolation; after it, we understand that **capacity and selectivity are separate axes of improvement for recurrent architectures**, and maximizing both is necessary for competitive performance.

**Significance beyond performance:** This framework provides a vocabulary for reasoning about future architectures. A researcher designing a new RNN can ask: "Does my state have sufficient rank to store the associations this task requires? Does my state update rule allow selective retention based on content?" These are diagnostic questions that the experimental evidence in this paper makes answerable. The associative recall experiments (Figure 4) and the PG19 loss-over-position curves (Figure 5) become not just benchmarks but **analytical tools** — if a new architecture underperforms on MQAR, the bottleneck is likely capacity; if it underperforms on long-context, the bottleneck is likely selectivity.

### Innovation 4: Demonstrating That Architecture Alone Can Close the Transformer Quality Gap — With Full Openness

The paper makes a contribution that is less about algorithmic novelty and more about **evidentiary standards and community infrastructure**, but it is genuinely innovative in the context of how LLM research is typically done. The claim is: **an RNN architecture, trained on openly available data with fully open code and weights, can match similarly-sized Transformers on a broad range of benchmarks.** This is a claim about what is *possible*, and the paper backs it with exhaustive transparency.

Why is this a conceptual contribution rather than just engineering? Because prior to this work, the default assumption in the field — reflected in Table 2 of the paper — was that competitive LLM performance required either Transformer attention, closed-source training pipelines, or both. The open-source models that existed (Pythia, early RWKV, open Mamba implementations) consistently lagged behind their closed-source or Transformer counterparts. The paper's comparison table (Table 2) shows that for 7B+ parameter models, Eagle is among the only architectures with fully open weights, training code, inference code, *and* training data. This is not just a release — it's a **proof of existence** that changes the Overton window for what RNN architectures can achieve.

The evidence is systematic:

- **Controlled ablation** (Table 18): 170M parameters, identical data, identical tokenizer. RWKV-6 (Finch) achieves an average benchmark accuracy of 50.7%, compared to 47.7% for RWKV-4, 50.1% for Mamba, and 47.9% for Pythia (a standard Transformer). This isolates the architectural contribution from data and scale effects.

- **Multilingual benchmarks** (Table 3): Finch-3B (3.1B parameters) achieves 57.1% average accuracy, exceeding Llama-2-7B (54.3%) and Mistral-7B (55.5%). This demonstrates that the efficiency advantages of RNNs don't come at the cost of multilingual capability — in fact, the RWKV World Tokenizer's explicit non-English vocabulary curation gives these models an advantage on underrepresented languages.

- **Long-context reasoning** (Table 5, Bamboo): Eagle-7B outperforms LLaMA2-Chat-7B on 5 of 9 tasks despite being a base model (not instruction-tuned) and despite being trained on only 1.1T tokens versus LLaMA2's 2T.

- **Associative recall** (Figure 4): Finch achieves near-perfect MQAR accuracy even at sequence lengths of 256, matching the Transformer baseline and substantially exceeding all prior non-Transformer architectures.

This is not a single breakthrough result — it's a **pattern of evidence** that cumulatively makes the case that RNN architectures have closed the quality gap. The paper's explicit framing in the Introduction — that Eagle and Finch are "competitive to transformers when trained using enough FLOPs to make meaningful scaling conclusions" — is deliberately modest, but the evidence actually supports a stronger claim: on several important dimensions (multilingual capability, associative recall, inference efficiency), RNNs may now be *preferable* to Transformers.

**Significance for the field:** This innovation is about lowering barriers and raising standards. By releasing everything openly, the paper enables the kind of controlled comparisons (Table 18) that are impossible with closed-source models. It also makes a statement about how LLM research should be done — if you're claiming architectural superiority, show it with controlled experiments, not just headline benchmarks. This is a methodological contribution as much as a technical one.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The primary language modeling evaluations use standard benchmarks from the `lm_evaluation_harness` (Gao et al., 2023), including multilingual benchmarks (LAMBADA Multilingual, XCOPA, XNLI, PAWS-X, XStoryCloze, xWinogrande) and English-focused benchmarks (LAMBADA, HellaSwag, PIQA, AI2 ARC Easy/Challenge, GLUE, WinoGrande, SciQ, COPA). Long-context evaluation uses the PG19 test set (Rae et al., 2019) and the Bamboo benchmark (Dong et al., 2023), which comprises 10 tasks across question answering, hallucination detection, text sorting, language modeling, and code completion with a maximum context window of 4k tokens. Synthetic associative recall experiments use the multi-query associative recall (MQAR) task as benchmarked by Arora et al. (2023). The models were trained on the newly introduced RWKV World v2 dataset, a 1.12-trillion-token multilingual corpus described in Appendix D and Table 9.

- **Base model(s).** The paper reports results for four Eagle models (0.4B, 1.5B, 3B, 7B parameters) and two Finch models (1.6B, 3B parameters). All models were trained on the 1.12-trillion-token RWKV World v2 multilingual corpus with a context length of 4096 tokens. The 7B-scale models are positioned for comparison against similarly-sized open Transformers (Llama-2-7B, Mistral-7B, Falcon-7B, MPT-7B) and the prior RWKV-4-7B. The smaller scales (1.5B, 3B) allow comparison against Pythia, Mamba, and RWKV-4 at matched parameter counts. An additional ablation model of 170M parameters was trained on the Pile dataset using the GPT-NeoX-20B tokenizer for controlled architectural comparison.

- **Metrics.** For language modeling benchmarks, the primary metric is accuracy (acc) or normalized accuracy (acc_n) as defined by `lm_evaluation_harness`, with average accuracy computed across task groups. For the LAMBADA datasets, perplexity (ppl) is also reported. For the Bamboo benchmark, tasks use either accuracy or F1 score as specified by the benchmark. For PG19 long-context evaluation, bits-per-byte loss is plotted as a function of sequence position. For MQAR, accuracy is reported as a function of sequence length. For music modeling, bits-per-byte loss is averaged across the validation set and Gaussian-smoothed over position.

- **Baselines.** The paper compares against Transformer-based models (Pythia 1.4B/2.8B/6.9B, MPT-7B, Llama-2-7B, Falcon-7B, Mistral-7B-v0.1), the prior RWKV-4 generation (1.5B, 3B, 7B), and the Mamba state-space model (1.4B, 2.8B). In the controlled 170M ablation (Table 18), the baselines are RWKV-4-Pile, Pythia, and Mamba trained on identical data with identical tokenizer. For long-context Bamboo evaluation, additional baselines include Mamba-2.8B-Hermes (instruction-tuned), LLaMA2-Chat-7B, and Mistral-Instruct-7B. For multimodal experiments, baselines include BLIP-2, InstructBLIP, IDEFICS-9B/80B, and TinyGPT-V. For audio, baselines include DeepRes, PANNs, and HTS-AT.

- **Generation budget / compute accounting.** Training FLOPs are computed analytically using the formulas in Equations 24–29, which account for both linear layer operations and WKV state operations. The exact FLOP counts per model are reported in Table 11. For evaluation, the primary metric is task accuracy at fixed model scale — there is no "generation budget" sweep as in inference-time scaling papers; models are evaluated with standard decoding (the paper does not explicitly specify temperature or sampling parameters for benchmark evaluations, though the chat examples in Appendices L and M use temperature 1.0). The speed and memory benchmarks (Figures 6 and 7) use a batch size of 8, model dimension of 4096, head size of 64 for Finch and Flash Attention, and state dimension 16 with model dimension 8192 for Mamba (reflecting Mamba's expansion factor of 2).

- **Cross-validation / statistical protocol.** The paper does not employ cross-validation for benchmark evaluation; models are evaluated once on the standard test sets. For the MQAR experiments, the paper states that models were trained "using identical criteria with various model dimensions and sequence lengths" (Section 8.2) but does not report variance across training runs. For the Bamboo benchmark, since all models failed on the code completion task, it was excluded from the average — a principled but post-hoc exclusion.

### Main Quantitative Results

#### Language Modeling Benchmarks: Multilingual Performance

The headline result from Table 3 is that Finch-3B achieves an average multilingual accuracy of 57.1%, exceeding Llama-2-7B (54.3%) by 2.8 percentage points despite having less than half the parameters. Eagle-7B reaches 58.2% average accuracy, the highest among non-Mistral models. The pattern holds across scales: Eagle-1.5B (54.3%) substantially outperforms Pythia-1.4B (49.7%), RWKV-4-1.5B (51.8%), and Mamba-1.4B (51.8%). Finch-1.6B further improves to 55.0%.

Breaking down individual benchmarks reveals the architecture's particular strengths. On LAMBADA Multilingual perplexity, the progression from RWKV-4 to Eagle to Finch is dramatic: at the 3B scale, perplexity drops from 48.1 (RWKV-4) to 30.8 (Eagle) to 28.1 (Finch). This is a 42% reduction in perplexity within the same parameter count. On XStoryCloze, Eagle-7B achieves 63.3% accuracy versus RWKV-4-7B's 60.9% and Llama-2-7B's 57.5%. On xWinogrande, Finch-3B reaches 77.8%, exceeding Mistral-7B's 81.2% but substantially outperforming Pythia-2.8B (71.5%) and Mamba-2.8B (75.6%).

A notable pattern: the Eagle and Finch models show especially strong performance on LAMBADA Multilingual and XStoryCloze — both tasks require maintaining cross-sentence context and resolving entity references, which aligns with the architectural motivation of matrix-valued states improving associative recall. The gap is smaller on PAWS-X (paraphrase identification) and XNLI (natural language inference), tasks that rely more on local syntactic and semantic understanding than long-range memory.

#### Language Modeling Benchmarks: English Performance

Table 4 reports English-focused benchmarks. Eagle-7B achieves 71.5% average accuracy, competitive with Llama-2-7B (71.1%) and Falcon-7B (71.2%) but trailing Mistral-7B (75.8%). Finch-3B at 67.5% exceeds Mamba-2.8B (66.2%) and Eagle-3B (66.0%).

The English results show a more modest improvement over RWKV-4 than the multilingual results. Eagle-7B (71.5%) improves over RWKV-4-7B (67.3%) by 4.2 percentage points, but the gap to Mistral-7B remains large (4.3 points). On HellaSwag, Eagle-7B scores 70.9% versus Mistral-7B's 81.0% — a 10-point gap that suggests the architecture may struggle with certain types of commonsense reasoning. On ARC Challenge, Eagle-7B (39.5%) substantially lags both Llama-2-7B (43.1%) and Mistral-7B (50.1%).

A curious result: Finch-3B outperforms Eagle-3B on LAMBADA (70.8% vs. 68.7%) and WinoGrande (63.6% vs. 62.0%) but Eagle-3B wins on ARC Easy (68.6% vs. 66.5%) and SciQ (92.6% vs. 92.5%). The differences are small and likely within noise, but they suggest that data-dependent decay (Finch) may not uniformly improve all task types at the 3B scale — the benefits may be task-specific or only clearly manifest at larger scales.

#### Training FLOPs Efficiency: Pareto Frontier Analysis

Figures 2 and 3 plot accuracy versus training FLOPs for multilingual and English benchmarks respectively, showing where each architecture lies relative to the Pareto frontier. For multilingual benchmarks (Figure 2), Eagle and Finch represent "a substantial improvement to the Pareto frontier, achieving far higher scores than other models trained for a similar number of FLOPs." The Eagle-7B point sits clearly above the trend line defined by Pythia, MPT, Falcon, and Llama-2 — meaning it achieves higher multilingual accuracy per training FLOP than any of those architectures at comparable scale.

For English benchmarks (Figure 3), the advantage is less dramatic. Eagle and Finch lie near the trend line but do not clearly redefine the frontier — Mistral-7B, despite using fewer training FLOPs (the exact number is not disclosed in the paper since Mistral's training data size is not public), achieves substantially higher accuracy. This is the paper's own data showing that the architecture's advantage is more pronounced in multilingual settings.

#### MQAR: Associative Recall Results

Figure 4 presents the MQAR results, which the paper presents as a key differentiator. The finding is that Finch achieves "extremely high accuracy" and "outperforms all well-known non-transformer architectures previously used to train large language models." Specifically, at sequence length 256, Finch maintains near-perfect accuracy while Mamba's accuracy drops substantially (exact numbers are not given in the text — the results are presented visually in Figure 4). Eagle shows improved MQAR over RWKV-4 but still falls below Finch, consistent with the incremental benefit of data-dependent decay for memory-intensive tasks.

The paper notes a "performance disparity between Mamba and Finch, despite their shared architectural features such as matrix-valued state and data-dependent memory modification, suggesting different combinations of these elements result in superior performance." This is a qualitative observation from Figure 4 but is not quantified with a table — the reader must infer exact accuracy values from the plot.

#### Long Context: PG19 Loss Over Sequence Position

Figure 5 plots loss against sequence position for 3B RWKV-4, Eagle, and Finch models on the PG19 test set, starting from token 2048 onward. All models were trained with context length 4096, so positions beyond 2048 represent extrapolation. The key findings:

- RWKV-4 World shows loss that initially decreases slightly then begins rising, with visible instability at longer positions.
- Eagle "improves dramatically over RWKV-4 on this long sequence task" — the loss curve is lower overall and continues to decrease further into the sequence.
- Finch "further improves on this test beyond Eagle, with loss continuing to drop further into the sequence" — the loss curve is the lowest of the three and shows the most consistent downward trend even at positions approaching 8000 tokens.

This is direct evidence for the paper's claims about data-dependent decay improving long-range retention: if the model can selectively retain important information (Finch) rather than having all information decay at fixed rates (Eagle), loss at distant positions should be lower, which is exactly what Figure 5 shows.

#### Bamboo Long-Context Benchmark

Table 5 presents results on 9 of 10 Bamboo tasks (code completion excluded since all models failed). At the 1.5B scale, Eagle-1.5B (9.2% average) and Finch-1.6B (8.9%) dramatically outperform Pythia-1.4B (2.1%) and Mamba-1.4B (2.1%). At the 3B scale, Finch-3B (11.3%) and Eagle-3B (9.9%) substantially exceed Pythia-2.8B (2.2%) and Mamba-2.8B (2.4%), though Mamba-2.8B-Hermes (instruction-tuned) reaches 11.9%.

At the 7B scale, Eagle-7B-Hermes (16.8%) outperforms Pythia-6.9B (3.3%) by an enormous margin but trails LLaMA2-Chat-7B (24.1%) — though note that Eagle-7B-Hermes is a fine-tuned variant while the base Eagle-7B was not tested. The comparison is instructive: on specific tasks like MeetingQA, Eagle-7B-Hermes (31.0%) substantially exceeds LLaMA2-Chat-7B (6.0%). But on ALTQA, both score 0.0% while LLaMA2-Chat-7B achieves 46.0% — a striking discrepancy suggesting that the RWKV architecture may have specific weaknesses on certain types of long-context tasks that the paper does not analyze further.

A notable pattern: Pythia models at all scales perform near floor on Bamboo (2.1–3.3% average), suggesting that standard Transformers trained on similar data volumes (Pythia-6.9B was trained on 300B tokens, far less than Eagle's 1.1T) struggle with long-context tasks unless specifically designed or instruction-tuned for them. Eagle and Finch, despite similar or less training, dramatically outperform Pythia — this is evidence that the RNN inductive bias provides inherent advantages for long-range reasoning beyond just efficiency.

#### Speed and Memory Benchmarks

Figures 6 and 7 present training speed and memory benchmarks on A100 80GB GPUs. The key claims:

- **Memory (Figure 6):** Finch uses less memory than both Flash Attention and Mamba across all sequence lengths from 512 to 16,384. At 16k sequence length, Finch uses approximately 27.7 GB versus roughly 33 GB for Mamba and roughly 46 GB for Flash Attention v2 — "40% and 17% less memory usage than Flash Attention and Mamba respectively." The memory curves are linear for all three methods.

- **Speed (Figure 7):** All three methods show linear scaling with sequence length, but with different slopes. Finch and Mamba scale similarly; Finch is "significantly faster than Flash Attention for sequence lengths beyond 4k, being around 4.2× faster for a sequence length of 16k." The 4.2× figure is based on reading from the plot — at 16k, Finch takes approximately 200ms while Flash Attention v2 takes approximately 840ms.

The paper notes that "further optimization of our Finch CUDA implementation, including algorithmic improvements, are possible, and could lead to speed increases and greater parallelization" — this is an honest admission that the current kernel is not necessarily optimal and that these benchmarks represent a lower bound on achievable performance.

### Ablation Studies and Robustness Checks

**Controlled architectural ablation (170M parameters, identical data):** Table 18 trains four architectures (RWKV-4, Pythia, Mamba, RWKV-6/Finch) on exactly the same Pile dataset with the GPT-NeoX-20B tokenizer at 170M parameters. RWKV-6-Pile achieves 50.7% average accuracy, versus 50.1% for Mamba, 47.9% for Pythia, and 47.7% for RWKV-4-Pile. This is the cleanest evidence that the architectural changes from RWKV-4 to Finch improve quality independently of data and tokenizer effects. The 3-percentage-point gap between RWKV-6 and RWKV-4 represents the cumulative benefit of matrix-valued states, SiLU gating, and data-dependent mechanisms. The fact that RWKV-6 surpasses Mamba by a small margin (0.6 points) is notable: both have matrix-valued states and data-dependence, but implemented differently, and the decay-based formulation shows a slight edge in this controlled setting.

**DDLerp ablation (Appendix K, Table 19):** Training a small Finch model (6 layers, dimension 768) on the 1.6B-token minipile, removing data-dependent token-shift while keeping data-dependent decay increases validation loss from 2.91 to 2.923; removing DDLerp entirely increases loss to 2.926. The differences are small (0.013 and 0.016 respectively) but consistent, confirming that both components contribute independently and that the full DDLerp mechanism is beneficial. The small magnitude of the differences is expected given the tiny model scale and training budget — this ablation would be more informative at larger scales.

**Tokenizer efficiency (Appendix F, Table 12):** The RWKV World Tokenizer is compared against cl50k_base, cl100k_base, and Llama2 tokenizers on five languages and code. For Chinese, the RWKV tokenizer produces 998M tokens from 1.06B characters (average 1.06 chars/token), substantially more efficient than Llama2's 1.52B tokens (0.69 chars/token) and even outperforming cl100k_base (1.24B tokens, 0.85 chars/token). For Arabic, the advantage is similar: 1.13B tokens (1.56 chars/token) versus Llama2's 1.57B tokens (1.12 chars/token). For English and Spanish, all tokenizers perform comparably. This directly supports the claim that the manually curated vocabulary produces more efficient tokenization for underrepresented languages.

**Tokenizer speed (Appendix F, Table 13):** The Rust implementation of the RWKV tokenizer achieves 90.32 MB/s, 9.6× faster than Tiktoken's 9.34 MB/s and dramatically faster than Python implementations of Mistral (2.41 MB/s) and Llama2 (2.40 MB/s). This is relevant for training on trillion-token corpora where tokenization speed can be a bottleneck.

**Alignment benchmark (Appendix G, Table 14):** On AlignBench, a Chinese alignment benchmark with 683 queries, Eagle-7B achieves a total score of 3.89, versus RWKV-4-7B's 3.45. Finch-3B scores 3.53, exceeding Eagle-3B's 3.34. The improvements are consistent across all eight categories (professional knowledge, Chinese understanding, basic tasks, math, writing, QA, role play, logical reasoning), with particularly large gains in professional knowledge (Eagle-7B: 5.15 vs. RWKV-4-7B: 4.91) and writing (5.69 vs. 5.16).

**Self-learning capability (Appendix G, Table 15):** Evaluated using the SLC Score metric from Ferdinan et al. (2024), Eagle-7B (partially instruct-trained) achieves SLC scores of 0.37 (open generation), 0.70 (oracle-selected), 0.57 (induced generation), and 0.65 (external prompt). These are competitive with Mistral-7B-Instruct-v0.2 (0.35, 0.65, 0.25, 0.84) and neural-chat-7b-v3-3 (0.57, 0.75, 0.59, 0.74), suggesting the architecture does not fundamentally limit self-learning capability.

**Music modeling (Section 10.1, Figure 8):** A 24-layer, 512-dimension Eagle model trained on ABC music notation achieves approximately 2% lower loss than RWKV-4-Music, with the improvement concentrated in the musical score portion of the sequences (bytes 100+) rather than the header. This demonstrates that the architectural improvements transfer to a completely different modality (symbolic music) with a much smaller model size.

**Visual-language tasks (Section 10.2, Table 6):** VisualRWKV (Eagle-1.5B with CLIP-L vision encoder) achieves 48.5% on GQA, comparable to InstructBLIP with Vicuna-7B (49.2%) and exceeding BLIP-2 with Vicuna-13B (41.0%). On Text-VQA, VisualRWKV with Eagle-3B scores 46.4%, approaching InstructBLIP with Vicuna-7B (50.1%). The architecture generalizes to multimodal settings without architectural modification — only a projection layer is added between the vision encoder and the language model.

**Audio classification (Section 11, Table 7):** AudioRWKV-T (8.7M parameters) achieves 0.435 mAP on AudioSet, approaching HTS-AT's 0.437 at 28.8M parameters. AudioRWKV-S (28.4M) achieves 0.452, exceeding all baselines. The quad-directional shift (Q-Shift) mechanism adapts the temporal token-shift concept to 2D spectrograms, demonstrating architectural flexibility.

### Critical Assessment

**Claim 1: Eagle and Finch "significantly improve over RWKV-4 on benchmarks for LLMs."** This claim is well-supported but its strength varies by domain. The improvements are largest on multilingual benchmarks (Tables 3, Figure 2) where RWKV-4-7B to Eagle-7B jumps from 47.4% to 53.7% on LAMBADA Multilingual accuracy and from 56.4% to 58.2% average — genuinely significant gains. On English benchmarks (Table 4), the improvement is more modest: Eagle-7B (71.5%) over RWKV-4-7B (67.3%) is a 4.2-point gain, but this could partly reflect the larger and more diverse training data (RWKV World v2 at 1.12T tokens) rather than pure architectural improvement. The controlled ablation (Table 18) partially addresses this by showing that even on identical data, RWKV-6 outperforms RWKV-4 (50.7% vs. 47.7%), but this uses a tiny 170M scale — the magnitude of the architectural contribution at 7B scale cannot be precisely separated from data effects. The paper does not train an Eagle model on RWKV-4's original training data, which would be the definitive controlled comparison.

A genuine weakness: on HellaSwag, Eagle-7B scores 70.9% versus Mistral-7B's 81.0% and Falcon-7B's 76.4%. This is not just below Mistral — it's substantially below another open 7B model (Falcon) by 5.5 points. The paper does not analyze why HellaSwag specifically shows this gap. HellaSwag tests grounded commonsense reasoning about everyday scenarios; the gap might indicate that matrix-valued states with static decay are poorly suited to tasks requiring fine-grained temporal reasoning about physical sequences, but the paper doesn't investigate this.

**Claim 2: The RWKV World Tokenizer improves efficiency for underrepresented languages.** This claim is directly supported by Table 12: for Chinese, the tokenizer achieves 1.06 characters/token versus 0.69 (Llama2) and 0.85 (cl100k_base). For Arabic, 1.56 vs. 1.12 and 1.44. The efficiency ratios (roughly 1.5× fewer tokens for Chinese, 1.3× for Arabic) are substantial and consequential for deployment cost. However, the claim is only tested on 5 languages plus code — it's unclear how it performs on the full range of languages it was designed for. The manual selection process ("manually select tokens from multiple vocabulary files") is necessarily subjective and may have baked in the biases of the curators. The paper acknowledges that the tokenizer construction process involves manual selection but doesn't describe the criteria or who made the choices, which limits reproducibility.

**Claim 3: Finch achieves "extremely high accuracy in MQAR" and "outperforms all well-known non-transformer architectures."** This claim is supported by Figure 4, but the evidence is presented only visually — no table of exact accuracies is provided. The reader must estimate values from a plot. At sequence length 256, Transformer (presumably a standard attention model) and Finch appear to achieve near 100% accuracy, while Mamba drops visibly but not to zero (perhaps 60–80%). The paper doesn't state the model sizes used for the MQAR experiments, the training data, or the number of trials, making it impossible to assess statistical reliability. This is the strongest architectural evidence in the paper — the task most directly tied to the matrix-state innovation — yet it receives the least rigorous quantitative treatment. A table with exact accuracies, standard deviations, and model configurations would substantially strengthen this claim.

**Claim 4: Eagle and Finch are "competitive to transformers when trained using enough FLOPs to make meaningful scaling conclusions."** The evidence for this claim is mixed and depends heavily on which baseline you choose. Against Pythia (Table 4: Eagle-7B 71.5% vs. Pythia-6.9B 63.8%), the win is enormous — but Pythia was trained on only 300B tokens, making it a weak baseline. Against Llama-2-7B (71.1% vs. 71.5%), Eagle is marginally ahead but Llama-2 was trained on 2T tokens — nearly double Eagle's 1.1T. Against Mistral-7B (75.8% vs. 71.5%), Eagle trails by 4.3 points, a non-trivial gap. The fairest comparison might be MPT-7B (70.9% vs. 71.5%), where Eagle slightly edges ahead.

The paper's own Figure 3 tells the story clearly: for English benchmarks, Eagle-7B lies on or slightly below the trend line defined by Transformer models. It is competitive in the sense of "in the same ballpark," not "equal or better." For multilingual benchmarks (Figure 2), Eagle-7B is clearly above the trend line — this is where "competitive" becomes "superior." But the claim in the paper does not make this distinction; it presents the results as generally competitive, which is true only with careful choice of comparison points.

A missing experiment: the paper never compares Eagle/Finch against a Transformer trained on exactly the same RWKV World v2 data. The controlled ablation (Table 18) uses The Pile, not World v2. Without this comparison, it's impossible to say whether the strong multilingual results come from the architecture (better modeling of multilingual sequences) or the data (better multilingual representation in World v2) or the tokenizer (more efficient encoding of non-English text). This is the single most important missing experiment in the paper.

**Claim 5: Finch is "4.2× faster than Flash Attention for a sequence length of 16k" during training.** This claim from the speed benchmarks (Figure 7) is supported by the plot but needs qualification. The 4.2× figure compares a custom CUDA kernel for Finch against a PyTorch implementation of Flash Attention v2 (not Triton or CUDA-optimized Flash Attention). The paper notes this explicitly: "We use the PyTorch Implementation of Flash Attention v2." The Flash Attention comparison is thus against a suboptimal baseline — a properly optimized Flash Attention kernel would likely reduce the gap. Mamba, which also uses a custom CUDA kernel, scales similarly to Finch in the plot — the advantage is primarily over the PyTorch Flash Attention implementation, not over all possible Transformer training approaches. The memory advantage (Figure 6) is more robust since memory usage is determined by the algorithmic requirement to store the full attention matrix, which Flash Attention mitigates but doesn't eliminate. At 16k, Flash Attention uses approximately 46 GB to Finch's 28 GB — this 40% reduction is inherent to the architecture, not the implementation.

**Additional weaknesses not addressed by the paper:**

- **No scale above 7B parameters.** The largest model is Eagle-7B; Finch stops at 3B. Scaling behavior is a critical question for architectures: does the advantage grow, shrink, or stay constant with scale? Transformer scaling laws are well-characterized; RNN scaling laws are not. The paper promises "future work" on 7B and 14B Finch but provides no evidence about whether the trends observed at 3B will persist. The gap between Finch-3B and Eagle-7B on some tasks (Finch-3B: 67.5% English average; Eagle-7B: 71.5%) suggests that model size still matters substantially, but whether Finch-7B would reach or exceed Eagle-7B is unknown.

- **No training stability analysis at scale.** The initialization scheme (Appendix I) is elaborate and layer-dependent, suggesting that training these models is non-trivial. The paper doesn't report training loss curves, gradient statistics, or any evidence of training stability for the 7B model. This matters because a claimed advantage of the architecture — parallel training with O(N) complexity — is only relevant if the models can actually be trained to convergence without numerical issues.

- **No comparison against modern Transformer variants with efficient attention.** The Transformer baselines (Pythia, Llama-2, Falcon, Mistral) all use standard or grouped-query attention. The paper doesn't compare against Transformer variants with sliding window attention (Mistral already uses this, but the paper doesn't analyze this aspect), linear attention, or hybrid approaches (like Griffin, which mixes recurrence with local attention). This makes the "competitive with Transformers" claim narrower than it appears — it's competitive with specific Transformer implementations but not with the broader family of attention variants.

- **The Bamboo results (Table 5) include instruction-tuned variants but not consistently.** Eagle-7B-Hermes is compared against LLaMA2-Chat-7B (both fine-tuned), but at smaller scales, only base Mamba and base Eagle/Finch are compared. The presence of Mamba-2.8B-Hermes but not Eagle-3B-Hermes makes the comparison uneven.

- **MQAR hyperparameters unspecified.** The model dimensions and sequence lengths used for MQAR experiments are stated to use "identical criteria" but the exact criteria are not given. Without knowing the model size, it's unclear whether Finch's near-perfect MQAR reflects a fundamental architectural advantage or simply that Finch was tested at a scale where the task is easy.

**The strongest evidence in the paper:** The multilingual Pareto frontier (Figure 2), where Eagle-7B defines a new best-in-class for training efficiency; the controlled 170M ablation (Table 18), which cleanly isolates the architectural contribution; and the PG19 long-context curves (Figure 5), which show monotonic improvement from RWKV-4 to Eagle to Finch and demonstrate a capability (improving loss at very long context) that directly tests the architectural innovations. These three results together make a compelling case that the matrix-state and data-dependent decay innovations are genuine improvements over prior work.

**The weakest evidence:** The speed/memory benchmarks are provisional (unoptimized PyTorch baseline, room for Finch kernel improvement); the Bamboo results are incomplete (missing baselines, inconsistent fine-tuning); and the MQAR results are inadequately reported (no tables, no configuration details). The HellaSwag gap (70.9% vs. 81.0% for Mistral-7B) is never addressed and might indicate a fundamental limitation for certain reasoning types that the paper should have investigated.

**Overall:** The experiments support the paper's core architectural thesis — that matrix-valued states and data-dependent decay improve over RWKV-4 — but the claim that these architectures are "competitive" with Transformers at scale is only partially demonstrated. They are competitive in multilingual settings and long-context tasks, roughly on par in English benchmarks, and notably behind on specific reasoning tasks like HellaSwag. The paper would be strengthened by a controlled data-matched comparison against a strong Transformer baseline, MQAR results in table form, and analysis of the HellaSwag gap.

## 6. Limitations and Trade-offs

### 6.1 No Controlled Comparison Against a Transformer Trained on Identical Data

**The assumption or constraint:** The central claim of the paper — that Eagle and Finch are "competitive to transformers when trained using enough FLOPs to make meaningful scaling conclusions" (Section 1) — rests on comparisons against publicly available Transformer models (Llama-2, Mistral, Falcon, Pythia) that were trained on different data mixtures, with different tokenizers, and with different training budgets. The paper's own controlled ablation (Table 18) uses The Pile dataset and the GPT-NeoX-20B tokenizer for a 170M-parameter comparison, but this is **not the configuration used for the main 1.5B–7B models** reported in Tables 3 and 4. The RWKV World v2 dataset (1.12T tokens) was purpose-built for this work and has no Transformer counterpart trained on it.

**The consequence:** It is impossible to determine how much of Eagle and Finch's performance — particularly their strong multilingual results — comes from the architecture versus the data curation (70% English, 15% multilingual, 15% code with explicit non-English vocabulary support in the tokenizer) versus the tokenizer's efficiency advantage for non-European languages. The paper shows that the RWKV World Tokenizer alone produces 1.5× fewer tokens for Chinese than Llama2's tokenizer (Table 12) — this means that at an equivalent token budget, Eagle models effectively process more linguistic content per training step for those languages. A Transformer trained on RWKV World v2 with the RWKV World Tokenizer might close a substantial portion of the multilingual gap, undermining the architectural attribution.

**What evidence exists in the paper:** The 170M ablation (Table 18) partially addresses this, but it uses only The Pile (English-heavy) and standard tokenizer — it cannot speak to the multilingual advantage that is the paper's strongest result. The multilingual Pareto frontier (Figure 2) compares Eagle against Transformer models trained on different data, making the "frontier" a convolution of architectural and data effects. The paper does not train even a single Transformer baseline on RWKV World v2 at any scale.

**Mitigation status:** The paper does not acknowledge this as a limitation. The "Limitations" section (Section 12) discusses weak embedding performance, synthetic training data artifacts, and the need for larger training corpora, but never addresses the absence of a data-matched Transformer baseline. This is the single most important missing experiment for establishing the paper's headline claim.

---

### 6.2 No Scale Above 7B Parameters for Eagle and 3B for Finch

**The assumption or constraint:** The paper studies architectures at parameter counts from 0.4B to 7.5B (Eagle) and 1.6B to 3.1B (Finch). No model larger than 7B is reported, and Finch — the more sophisticated architecture with data-dependent decay — has no model above 3.1B. The paper states in the "Future Work" section: "We also plan to train and release larger versions of Finch such as 7B and 14B parameters" (Section 12), implicitly acknowledging this as incomplete.

**The consequence:** Scaling behavior is a first-order question for any architecture intended to replace Transformers. Transformer scaling laws (Hoffmann et al., 2022) show that architecture quality at small scale does not reliably predict quality at large scale — some architectures scale better than others. Without a Finch model at 7B or beyond, the paper cannot answer whether the data-dependent mechanisms continue to provide benefits at scale, whether the LoRA bottleneck dimensions (32 for token-shift, 64 for decay) remain adequate, or whether the added complexity introduces training instability that only manifests at depth or width.

The Finch-3B results provide suggestive evidence of superior scaling: Finch-3B (3.1B params, 67.5% English average) already matches or exceeds Eagle-3B (66.0%) and approaches Eagle-7B (71.5%) on some tasks. This implies favorable scaling — but whether this trend holds to 7B and beyond, and whether Finch-7B would surpass Eagle-7B, is speculation without evidence. The paper's assertion that "future 7B and larger Finch models are expected to further increase the size of these weight matrices by double or more" (Section 4.2.1) indicates ongoing uncertainty about the correct hyperparameter scaling for the LoRA components.

**What evidence exists in the paper:** The scaling plots (Figures 2 and 3) show Eagle and Finch points at 0.4–7B, but these are cross-sectional — different models at different sizes trained with varying hyperparameters — not a systematic scaling law study. The gap between Eagle-7B and Mistral-7B on English benchmarks (71.5% vs. 75.8%, Table 4) could widen, narrow, or reverse at 14B — all are consistent with the current data.

**Mitigation status:** The paper explicitly lists larger Finch models as future work, and the "Future Work" section acknowledges the limitation. This is a practical constraint (compute budget) rather than a methodological oversight, but it means the paper's strongest claims about Finch (the architecture most directly aimed at closing the Transformer gap) are based on models that are 2–4× smaller than the strongest Transformer comparisons.

---

### 6.3 Unexplained Performance Gap on Commonsense Reasoning (HellaSwag)

**The assumption or constraint:** The paper presents results across diverse benchmarks (Tables 3 and 4) and argues for general competitiveness with Transformers. However, a specific and large performance gap on HellaSwag — a benchmark testing grounded commonsense reasoning about everyday scenarios — goes unexamined. Eagle-7B achieves 70.9% accuracy versus Mistral-7B's 81.0%, Falcon-7B's 76.4%, and Llama-2-7B's 76.0%. This 5–10 point gap is the single largest relative weakness among the English benchmarks.

**The consequence:** HellaSwag requires understanding physical causality, temporal ordering, and typical human activity — capabilities that are central to many real-world applications (robotics planning, procedural reasoning, safety-critical decision-making). If the gap reflects a fundamental limitation of the recurrent architecture — for instance, that matrix-valued decay-based states struggle to represent fine-grained temporal sequences or counterfactual reasoning about physical scenarios — it would limit the architecture's applicability in domains where this type of reasoning is important. Alternatively, if the gap is purely a data effect, it could be closed without architectural changes, but the paper provides no evidence either way.

**What evidence exists in the paper:** The HellaSwag result appears in Table 4 but is never discussed in the text. The gap is consistent across scales: Eagle-1.5B (55.0%) vs. Mamba-1.4B (59.0%), Eagle-3B (62.6%) vs. Mamba-2.8B (65.9%). This suggests it is not merely a 7B artifact — even at smaller scales, the RWKV architectures trail Mamba on HellaSwag. The Finch-1.6B result (57.3%) closes some of the gap relative to Mamba-1.4B (59.0%) but Finch-3B (64.8%) still trails Mamba-2.8B (65.9%). This pattern — consistent underperformance on HellaSwag across model sizes and generations — warrants analysis that the paper does not provide.

**Mitigation status:** Not addressed. The paper treats HellaSwag as one benchmark among many, averaging it into the English score without comment. No ablation investigates whether specific architectural choices (static vs. data-dependent decay, matrix state dimensionality, gating mechanisms) affect HellaSwag performance differently from other tasks.

---

### 6.4 Training Parallelization Strategy Is Non-Standard and May Limit Adoption

**The assumption or constraint:** Section 4 and Appendix B describe the training parallelization approach: rather than fully parallelizing across the time dimension using associative scan (as Mamba does), the paper "parallelizes over non-time dimensions only while using a custom CUDA implementation that carefully keeps state operations in fast SRAM" (Appendix B). The paper argues that time-parallel methods incur expensive memory transfers between SRAM and HBM that "prove inefficient."

**The consequence:** This design choice has practical implications for adoption. A custom CUDA kernel tied to the specifics of the RWKV recurrence is a maintenance burden — it requires engineering effort to port to new hardware generations (H100, future GPUs), new precision formats, or new software stacks. It also means the architecture cannot benefit from generic time-parallel primitives (like FlashAttention's optimized kernels or Triton-based implementations) that are being aggressively optimized by the broader community. If the kernel is not ported to a user's hardware, they either use the pure PyTorch implementation (which the paper provides but doesn't benchmark for speed) or they cannot train the model efficiently.

The paper's speed benchmarks (Figures 6 and 7) compare Finch's custom CUDA kernel against a "PyTorch Implementation of Flash Attention v2" — explicitly not the optimized Triton or CUDA Flash Attention that practitioners actually use. This makes the 4.2× speedup claim at 16k sequence length a comparison against a suboptimal baseline rather than against the best available Transformer training infrastructure. The memory advantage (Figure 6) is more inherent to the architecture, but the speed advantage may shrink substantially against properly optimized attention kernels.

Furthermore, the custom kernel approach means the architecture is less amenable to emerging compilation-based approaches (torch.compile, OpenAI Triton) that automatically generate efficient kernels from high-level code — the kernel must be hand-written and hand-optimized for each target.

**What evidence exists in the paper:** The paper acknowledges that "further optimization of our Finch CUDA implementation, including algorithmic improvements, are possible" (Section 9). The pure PyTorch time-parallel implementation is described as providing "similar full-model speed characteristics" but is never benchmarked against the CUDA kernel — the reader cannot assess the performance penalty of using the portable implementation. The paper provides no data on training throughput (tokens/second) for end-to-end model training, only per-kernel timing, making it hard to assess whether the kernel advantage translates to wall-clock training speed improvements.

**Mitigation status:** The paper provides the pure PyTorch implementation for portability and notes that kernel optimization is "left for future work." But this is not framed as a limitation — it's presented as an implementation detail. The choice to not use associative scan (unlike Mamba) is justified on efficiency grounds, but the counterargument (portability, maintainability, community standardization) is never considered.

---

### 6.5 Near-Zero Performance on Hard Long-Context Tasks Suggests Fundamental Capability Boundaries

**The assumption or constraint:** The Bamboo benchmark (Table 5) reveals a stark pattern: on certain long-context tasks, Eagle and Finch models — and indeed all models tested except the instruction-tuned Mistral — score at or near floor. On ALTaQA, Eagle-7B-Hermes scores 0.0% (versus LLaMA2-Chat-7B's 46.0%). On ReportsumSort and ShowsSort, all models at 1.5B and 3B score 0.0%. On MeetingPred and ShowsPred, performance is near zero across nearly all models. The paper excludes the Code Completion task entirely "since all tested models failed to generate correct code completions for this task" (Section 8.4).

**The consequence:** This pattern suggests that for certain types of long-context reasoning — specifically, tasks requiring structured information extraction, sorting, or integration across a long document — the recurrent architecture may hit a harder capability ceiling than Transformers. It is possible that the 66DL state, though large, is still insufficient to maintain the structured representations needed for these tasks, or that the decay-based memory mechanism loses critical ordering information that attention's explicit pairwise comparisons preserve.

The ALTQA result is especially concerning: Eagle-7B-Hermes — an instruction-tuned model — scores 0.0% while LLaMA2-Chat-7B achieves 46.0%. This is not a small gap; it suggests a qualitative difference in what the architectures can represent. If these tasks reflect real-world use cases (e.g., answering questions about a long contract, sorting claims in a legal document), the architecture may be fundamentally unsuitable regardless of scale.

**What evidence exists in the paper:** Table 5 reports these results but the paper does not analyze the pattern. The text states that "the latest Finch and Eagle models outperform the vanilla Mamba by at least a 7% average score" — true, but this average is driven almost entirely by the hallucination detection tasks (SenHallu, AbsHallu) where Eagle and Finch score non-trivially while Pythia and base Mamba score zero. On the five tasks involving structuring, sorting, or prediction, Eagle and Finch score near zero at all scales. The average masks a bimodal distribution: the architecture works on some long-context tasks (hallucination detection, question answering on meetings/papers) and completely fails on others (sorting, prediction, alternative QA).

**Mitigation status:** Not addressed. The paper treats Bamboo as validation of long-context capability ("superior capacity of the proposed Finch and Eagle models on a vast range of long-context tasks"), which is true only if "vast range" excludes the five tasks where they score zero. The paper does not investigate whether the architecture can be improved on these tasks (e.g., through larger state dimension, modified decay mechanisms, or hybrid attention-recurrence approaches) or whether the failures are inherent.

### 6.6 No Accounting for Inference Latency in Sequential Recurrence

**The assumption or constraint:** The paper emphasizes O(1) inference time and memory per token as a key advantage over Transformers: "RWKV's recurrence mechanism does not examine tokens more than one time-step old. This allows us to train on and provide inference for unbounded sequence lengths without requiring increased computing power or memory" (Appendix B). The speed benchmarks (Figures 6 and 7) measure training throughput, not inference latency.

**The consequence:** The O(1) per-token complexity means that the computation *per token* is constant — but the tokens must still be processed **sequentially**. During autoregressive generation, each new token requires the full recurrent update (computing $w_t$, updating the $K^T V$ state, computing the output) before the next token can be generated. This is fundamentally sequential: you cannot parallelize across generated tokens the way you can with a Transformer's KV cache (which allows computing attention for the new token against all previous tokens in parallel, since the KV cache stores pre-computed keys and values).

For latency-sensitive applications (interactive chat, real-time translation), this sequential bottleneck may dominate. A Transformer with a KV cache might generate tokens faster in wall-clock time despite higher theoretical FLOPs, because the attention computation for the new token against the full context can be parallelized across the context dimension on GPU. The RWKV recurrence for the new token is a series of matrix multiplications through $L$ layers that cannot be parallelized across layers — each layer depends on the previous layer's output.

The paper's "4.2× faster than Flash Attention" claim is about **training throughput with full sequence parallelism**, not token-by-token inference latency for autoregressive generation. These are different regimes with different bottlenecks, but the paper does not distinguish them clearly. A practitioner reading the paper might reasonably but incorrectly conclude that Finch generates text 4× faster than a Transformer.

**What evidence exists in the paper:** The training speed benchmarks (Figures 6 and 7) are for forward passes over full sequences during training. The paper provides no inference latency benchmarks — no measurements of time-per-token during autoregressive generation, no comparisons against Transformer inference with KV caching, no analysis of how batch size affects inference throughput. The recurrent formulation (Appendix B, PyTorch code) is presented as compact and efficient, but this is pseudocode, not a latency benchmark.

**Mitigation status:** Not addressed. The paper consistently discusses efficiency in terms of "O(1) time and memory per token" without distinguishing training throughput from inference latency. The O(1) bound describes asymptotic scaling with sequence length — it says nothing about the constant factor, which is what matters for interactive applications. The paper mentions that RWKV "provides efficient inference" (Section 1) but never measures or defines what "efficient" means in latency terms.

## 7. Implications and Future Directions

### How This Work Changes the Landscape

This paper shifts the conceptual framing around efficient sequence modeling from a **single-axis "efficiency vs. quality" tradeoff** to a **multi-dimensional design space defined by state capacity and selectivity**. Before Eagle and Finch, the conversation around non-Transformer architectures was dominated by the question: "Can we match Transformer quality without quadratic attention?" The paper's answer is not just "yes, approximately" — it's that answering this question requires decomposing it into two separate structural requirements that prior architectures addressed only partially or not at all.

The reframing is this: **recurrent architectures need both high-rank representational capacity (to store multiple independent associations without interference) and content-based selective memory (to retain important information while forgetting irrelevant details).** Neither property alone suffices. RWKV-4 had neither (vector-valued state, static decay) and substantially underperformed Transformers. Eagle added the first (matrix-valued state) and improved dramatically on associative recall and multilingual benchmarks but still showed loss increase on long sequences, indicating that capacity without selectivity hits a ceiling. Finch added the second (data-dependent decay and token-shift) and achieved near-perfect MQAR, consistently decreasing long-context loss, and the best multilingual results among all non-Transformer architectures at comparable scale.

This is not a paradigm shift in the sense of introducing a completely new mechanism — linear attention, gated recurrence, and exponential decay were all known before. It is, rather, a **diagnostic contribution**: the paper provides the vocabulary and evidence to separate "can this architecture store multiple associations?" from "can this architecture selectively protect stored information?" These are now testable, separable hypotheses rather than vague claims about "memory capacity." The MQAR task (Figure 4) directly tests the first; the PG19 loss-over-position curve (Figure 5) directly tests the second. A researcher designing a new recurrent architecture can now run both experiments and identify which bottleneck is binding.

The paper also **reconciles conflicting signals about architectural competitiveness**. Prior to this work, one could reasonably look at RWKV-4 and Mamba and conclude that RNNs were catching up but still trailing; or look at the HellaSwag gap for Eagle-7B (70.9% vs. Mistral-7B's 81.0%) and conclude they were fundamentally limited. The paper's multi-metric evaluation — showing strong results on multilingual associative recall and long-context modeling alongside weaknesses on grounded commonsense reasoning — reframes the question from "are RNNs as good?" to "**for which cognitive capabilities are RNNs better or worse suited, and why?**" The answer appears to be: exceptionally strong at maintaining and retrieving discrete associations across long contexts (multilingual benchmarks, MQAR, Bamboo hallucination detection), competitive on general language understanding, and potentially weaker on tasks requiring fine-grained physical or temporal reasoning (HellaSwag, Bamboo sorting/prediction tasks). This specificity is more useful than a single yes/no answer — it tells practitioners which applications will benefit most from the architecture.

A key shift in research priorities emerges implicitly from the evidence: **improving recurrent architectures is now primarily a problem of inductive bias engineering, not fundamental capability.** The near-perfect MQAR and strong long-context results demonstrate that recurrence *can* capture the necessary information. The remaining gaps on tasks like HellaSwag suggest that *how* information is represented and retrieved matters — the decay-based mechanism may not provide the right inductive bias for all reasoning types. This means the most productive research direction is understanding and expanding the range of computations that recurrent states can efficiently represent, rather than pursuing ever-larger models in hopes that scale will solve all problems.

The paper also makes a **methodological contribution regarding openness**. Table 2's documentation of which 7B+ models have open weights, inference code, training code, and training data is itself an argument — by making Eagle/Finch fully open, the paper enables the kind of controlled ablations (Table 18) that are impossible with closed-source models. This raises the evidentiary bar for future architectural claims: if you're claiming superiority, show it with controlled experiments, not just headline numbers on different data distributions. The paper demonstrates that this standard is achievable, and future work that fails to meet it will be judged accordingly.

### Follow-Up Research This Work Enables

**Training a Transformer baseline on RWKV World v2 with the RWKV World Tokenizer.** The single most informative experiment the paper does not run. Train a standard Transformer (e.g., Llama-2 architecture) on the exact same 1.12T-token dataset with the same tokenizer at 1.5B and 7B scales. This would cleanly decompose the multilingual benchmark advantage (Figure 2, Tables 3–4) into architectural versus data/tokenizer contributions. Hypothesis: a substantial fraction of the multilingual gap closes, but Eagle/Finch retain an advantage on tasks requiring long-range cross-sentence context (LAMBADA Multilingual, XStoryCloze, xWinogrande) due to the matrix state's associative memory properties. A null result — the Transformer matches or exceeds Eagle/Finch on all benchmarks — would substantially weaken the paper's architectural claims and redirect attention to data engineering. This experiment costs approximately one additional training run at each scale and is directly enabled by the paper's release of the full data pipeline.

**Investigating the HellaSwag gap: a head-by-head analysis of what the matrix state learns to represent.** Eagle-7B trails Mistral-7B by 10.1 points on HellaSwag (Table 4), and this gap persists across scales (Eagle models consistently trail Mamba on HellaSwag at 1.5B and 3B). Mechanistic interpretability techniques — analyzing which heads fire on which types of temporal or causal relationships, probing the WKV state for representations of physical sequences, comparing against a Transformer's attention patterns on the same examples — could reveal whether the gap is due to insufficient state capacity, wrong inductive bias (decay-based memory may not capture the discrete step-by-step structure of physical narratives), or something else entirely. The finding would guide the next architectural iteration: if the gap is capacity-driven, larger matrix dimensions may help; if it's inductive bias, a hybrid mechanism (local attention for fine-grained temporal reasoning, recurrence for long-range reference) may be needed. This paper's open weights and architecture make such analysis feasible; a strong follow-up would identify specific HellaSwag subcategories where the gap is largest and trace the information flow through the recurrent state to identify the failure point.

**Scaling Finch to 7B and 14B to test whether data-dependent decay benefits compound with scale.** The paper only reports Finch up to 3.1B parameters (Table 11). Finch-3B already achieves 67.5% average English accuracy (Table 4) versus Eagle-3B's 66.0% and Mamba-2.8B's 66.2%, and 57.1% multilingual accuracy (Table 3) versus Eagle-3B's 56.5% and Llama-2-7B's 54.3%. These are encouraging trends, but the scaling slope is unknown. Does Finch-7B surpass Eagle-7B? Does Finch-14B close the HellaSwag gap with Mistral-7B? Does the 32-dimension LoRA bottleneck remain adequate, or does it become a limiting factor at scale (requiring the "double or more" increase the paper speculates about in Section 4.2.1)? Training Finch-7B on the existing RWKV World v2 data and comparing against Eagle-7B would answer whether data-dependent mechanisms show increasing, constant, or diminishing returns with model size. Training Finch-14B would test whether the architecture can reach the quality frontier currently defined by models like Mistral and Llama-2 at the 7B scale.

**Probing the Bamboo task-level failure modes to diagnose architectural ceilings.** Eagle and Finch score near zero on five Bamboo tasks: MeetingPred, ShowsPred, ReportsumSort, ShowsSort, and ALTQA (Table 5), while scoring non-trivially on hallucination detection and meeting/paper QA. This bimodal pattern is not random — the failing tasks share a requirement to maintain and manipulate structured representations across long contexts (sorting items, predicting future events from past patterns, answering questions that require cross-document temporal reasoning). A controlled experiment: train Eagle and Transformer models at identical scale on synthetic tasks that isolate these sub-skills (e.g., sorting lists of varying length, predicting next element in patterned sequences, answering questions about temporally ordered events). If Eagle fails at specific sequence lengths or pattern complexities where Transformers succeed, this identifies a fundamental representational limitation. The finding would inform whether the architecture needs larger state dimensions, explicit positional encoding, or hybrid attention mechanisms for structured reasoning. The Bamboo benchmark provides the diagnostic tasks; the paper's open code enables controlled synthetic experiments to isolate the failure cause.

**Combining Finch with local sliding-window attention for fine-grained temporal reasoning.** The HellaSwag gap (Section 8.1) and Bamboo structured-task failures (Table 5) both suggest difficulty with ordered, step-by-step reasoning. This is precisely what local attention mechanisms excel at — attending to the previous few tokens with high precision. A hybrid architecture: use Finch's recurrent state for long-range associative memory and cross-document reference, but add a small sliding-window attention layer (kernel size 4–8) at each block for fine-grained local pattern matching. This follows the pattern of Griffin (De et al., 2024), which mixes recurrent layers with local attention. The experiment: train a hybrid Finch-Attention model at 1.5B scale on RWKV World v2, evaluate on HellaSwag and Bamboo structured tasks. Hypothesis: local attention closes the HellaSwag gap and enables non-zero performance on sorting/prediction tasks, while the recurrent state maintains the long-context and multilingual advantages. If the hybrid underperforms pure Finch on associative recall, this reveals a tradeoff between local precision and long-range memory that would inform architecture design for specific applications. The paper's modular block design (Figure 1) makes such hybridization architecturally straightforward — the Time-Mixing sub-layer could be replaced with a local attention module in alternating blocks.

**Using the matrix-valued state as a pre-trained context representation for downstream tasks.** The paper notes in its Limitations that "we experimented with using Eagle as an embedding model... but were not able to get strong embedding performance. We believe that its state is a very high-quality embedding of the context but an appropriate method is required to aggregate the information content" (Section 12). This is a specific, testable hypothesis: the $K^T V$ state matrix per head contains rich associative information about the context that is lost when reduced to a single embedding vector. A follow-up would develop aggregation methods that preserve the matrix structure — e.g., flattening the state matrices from all heads and layers into a structured embedding, using the state matrices directly for retrieval-augmented generation (where the query interacts with the matrix-valued state similarly to how receptance queries the WKV state during generation), or fine-tuning a linear probe on top of the concatenated state matrices for classification tasks. Evaluate on MTEB (Muennighoff et al., 2023), which the paper mentions as a target but could not achieve strong results on. Success would open a new use case: pre-trained Eagle/Finch models as context encoders that preserve fine-grained associative structure, useful for retrieval, clustering, and semantic search applications where traditional vector embeddings lose information.

### Practical Applications and Downstream Use Cases

**Multilingual document processing and retrieval at scale.** The combination of the RWKV World Tokenizer's efficiency for non-European languages (1.5× fewer tokens for Chinese, 1.3× for Arabic vs. Llama2, Table 12) and Eagle/Finch's strong multilingual benchmark performance (Finch-3B: 57.1% average, exceeding Llama-2-7B's 54.3%, Table 3) makes these architectures immediately deployable for organizations processing large volumes of multilingual text. A legal discovery platform handling contracts in Chinese, Arabic, and English could use Finch for document understanding and cross-lingual retrieval with lower tokenization overhead (directly reducing API or compute costs for non-English text) and O(1) inference memory (supporting long documents without memory pressure). The 40% memory reduction versus Flash Attention at 16k sequence length (Figure 6: 28 GB vs. 46 GB) means higher throughput on fixed GPU hardware — more documents processed per dollar. The specific efficiency numbers: for a 10M-document Chinese corpus, the tokenizer advantage alone saves roughly 3.3 billion tokens of processing compared to a Llama2-tokenized pipeline, translating to reduced inference cost proportional to token count for any downstream model.

**On-device long-context assistants with fixed memory budgets.** The O(1) inference memory per token — the recurrent state is fixed at 66DL parameters regardless of context length (Equation 30) — means that Eagle/Finch models can process arbitrarily long conversations or documents without growing memory requirements. For Eagle-1.5B, the state size is approximately 3.2M parameters per layer × 24 layers ≈ 77M floating-point numbers, or roughly 154 MB in bfloat16. This is a hard ceiling — unlike a Transformer with a KV cache that grows linearly with context length (requiring progressively more memory as a conversation continues), the RWKV state size is constant from the first token to the millionth. This enables deployment scenarios currently impractical: a mobile app that maintains a persistent, indefinitely long conversation history without memory pressure; an e-reader that processes an entire book chapter-by-chapter while retaining context from the preface; a code assistant that keeps an entire repository in its recurrent state while the developer navigates between files. The Bamboo results (Table 5) show that this constant-memory context retention actually works for certain long-context tasks (hallucination detection, meeting QA) — the architecture doesn't just claim O(1) memory, it demonstrably uses the state to answer questions about long documents.

**Cost-efficient training data generation with architecture-aware allocation.** The paper's finding that Eagle and Finch excel on multilingual associative recall and long-context tasks but lag on specific reasoning types (HellaSwag, structured sorting) suggests a practical deployment strategy: use Eagle/Finch as the primary model for tasks matching its strengths, and route challenging cases to a (more expensive) Transformer. For an organization generating synthetic training data (e.g., for fine-tuning a smaller model), the architecture choice affects cost and quality differently across task types. Use Finch for: generating multilingual question-answer pairs from long source documents (strength: cross-lingual reference resolution, long-context memory), detecting hallucinations in model outputs (strength: Bamboo hallucination tasks where Eagle/Fitch score well), and maintaining consistency across multi-turn dialogue (strength: MQAR, LAMBADA). Route to a Transformer for: generating grounded physical reasoning examples (weakness: HellaSwag), structured sorting or temporal prediction tasks (weakness: Bamboo structured tasks). The speed benchmarks (Figure 7) show that for document-length sequences, Finch processes tokens faster than Flash Attention, meaning this hybrid pipeline could be both higher-quality (using the right architecture per task) and faster (using Finch for the bulk of long-context generation) than a Transformer-only approach.

**Base architecture for multimodal models with long temporal dependencies.** The paper demonstrates that Eagle adapts to vision-language (VisualRWKV, Section 10.2, Table 6: Eagle-3B with CLIP-L achieves 49.7% on GQA, competitive with InstructBLIP+Vicuna-7B at 49.2%), symbolic music (Section 10.1, Figure 8: 2% lower loss than RWKV-4), and audio classification (Section 11, Table 7: AudioRWKV-S with 28.4M parameters achieves 0.452 mAP, exceeding all baselines). These are not just existence proofs — they demonstrate that the recurrent state can effectively integrate information across modalities and long temporal sequences without the quadratic cost that would make long-video or long-audio Transformer processing prohibitive. A practical application: video understanding models that process minutes or hours of footage by feeding frame embeddings into a pre-trained Eagle/Finch backbone, using the recurrent state to maintain object identities, scene context, and narrative structure across thousands of frames. The O(1) per-frame cost means the computational budget scales linearly with video length rather than quadratically — a 2-hour video costs 120× more than a 1-minute clip, not 14,400× more. The VisualRWKV results provide the architectural template (projection layer from vision encoder to RWKV backbone, two-stage instruction tuning); the audio results with Q-Shift demonstrate that the token-shift mechanism generalizes to 2D spectrogram neighborhoods — suggesting video adaptations (3D or spatial-temporal token-shift) are architecturally natural extensions.

### When to Prefer This Method

The paper positions Eagle and Finch primarily against standard Transformer architectures (Tables 3–4, Figures 2–3) and secondarily against Mamba (Figures 4, 6, 7; Table 18). Based on the experimental evidence, the decision rules are:

- **Prefer Eagle/Finch when:** (1) Inference memory is the binding constraint and context lengths are long or unpredictable (O(1) state size of 66DL per layer vs. O(N) KV cache — at 16k tokens, Finch uses 40% less memory than Flash Attention, Figure 6). (2) The problem involves maintaining and cross-referencing multiple discrete facts across long contexts (associative recall: MQAR Figure 4; multilingual entity tracking: LAMBADA Multilingual, Table 3). (3) Multilingual processing efficiency matters and the language mix includes non-European languages (tokenizer advantage: 1.5× fewer tokens for Chinese vs. Llama2, Table 12; strong xWinogrande and XStoryCloze results, Table 3). (4) Training throughput at long sequence lengths dominates cost considerations (4.2× faster than the tested PyTorch Flash Attention implementation at 16k, Figure 7, though note the baseline caveat — this is against a non-optimized Flash Attention implementation). (5) Full training pipeline openness is required for reproducibility or customization (Table 2: Eagle is among the only 7B+ models with fully open weights, training code, inference code, and training data).

- **Prefer standard Transformers (or hybrid architectures) when:** (1) The task requires fine-grained physical, temporal, or procedural reasoning where structured step-by-step attention to recent tokens is critical (HellaSwag gap: Eagle-7B at 70.9% vs. Mistral-7B at 81.0%, Table 4; Bamboo sorting/prediction floor effects, Table 5). (2) Inference latency for single-token generation is the binding constraint — the recurrent state update is inherently sequential layer-by-layer, while Transformer KV-cache inference parallelizes attention across context for each new token (the paper provides no inference latency benchmarks, so the comparison is theoretical). (3) The deployment already uses heavily optimized Transformer inference infrastructure (Flash Attention 3, vLLM, TensorRT-LLM) and the engineering cost of porting Finch's custom CUDA kernel outweighs the efficiency gains. (4) The model scale needed exceeds 7B parameters — the paper provides no evidence about Finch scaling beyond 3B or Eagle beyond 7B, and architectural scaling behavior at 14B+ is unknown.

- **Consider Mamba over Eagle/Finch when:** HellaSwag performance specifically matters (Mamba-2.8B: 65.9% vs. Eagle-3B: 62.6% at comparable scale, Table 4) and the deployment environment already supports Mamba's associative-scan training infrastructure. However, if multilingual associative recall or long-context hallucination detection are priorities, Finch substantially outperforms Mamba on MQAR (Figure 4) and Eagle-3B/Finch-3B dramatically outperform Mamba-2.8B on Bamboo (Table 5: 9.9%/11.3% vs. 2.4%).

These tradeoffs are grounded in the paper's data but acknowledge its gaps — the lack of inference latency benchmarks, the absence of a data-matched Transformer baseline, and the unknown scaling behavior of Finch beyond 3B parameters mean that several of these preferences are provisional and should be validated on task-specific benchmarks before deployment decisions.
