# Lightning Attention-2: A Free Lunch for Handling Unlimited Sequence Lengths in Large Language Models

**ArXiv:** [2401.04658](https://arxiv.org/abs/2401.04658)

## 🎯 Pitch

This paper introduces **Lightning Attention-2**, the first linear attention implementation that realizes the theoretical computational benefits of linear attention in causal settings, where prior algorithms were bottlenecked by cumulative summation operations.

---

## 1. Executive Summary

This paper introduces **Lightning Attention-2**, the first linear attention implementation that realizes the theoretical computational benefits of linear attention in causal settings, where prior algorithms were bottlenecked by cumulative summation operations. The authors integrate their method into TransNormerLLM and benchmark against LLaMA with FlashAttention-2 on a GPU cluster using 128 A100 80G GPUs, evaluating across model sizes from 400M to 3B parameters and sequence lengths from 1K to 92K tokens. The core mechanism is a tiling strategy that separates computation into intra-block and inter-block components — conventional left-product attention within blocks and linear attention kernel tricks across blocks — implemented as an IO-aware Triton kernel that leverages GPU SRAM and HBM bandwidth asymmetries. Lightning Attention-2 maintains a constant training speed regardless of sequence length (approximately 38,500 tokens per GPU per second at 400M parameters from 1K to 92K contexts), while FlashAttention-2 degrades roughly 9× over the same range (from ~36,000 to ~4,000 TGS), establishing that linear attention can deliver its theoretical O(n) scaling on real hardware but only when cumulative summation is addressed through intra-inter block decomposition rather than naive tiling or parallel block computation.

## 2. Context and Motivation

### The Core Problem: Linear Attention's Theoretical Promise Doesn't Materialize on Hardware

The fundamental problem this paper addresses is deceptively simple: **linear attention promises $O(n)$ computational complexity for sequence modeling, but in practice, it fails to deliver this speedup in the one setting that matters most — causal (autoregressive) language modeling.** This gap between theoretical complexity and real-world wall-clock performance is not a minor implementation detail; it represents a fundamental barrier preventing linear attention from competing with highly optimized softmax attention implementations like FlashAttention-2, which have been refined through years of hardware-aware engineering.

To understand why this gap exists, we need to step back and examine what linear attention actually does. Standard softmax attention computes $\text{softmax}(QK^\top)V$, which requires explicitly forming the $n \times n$ attention matrix — an $O(n^2)$ operation that dominates computation at long sequence lengths. Linear attention replaces the softmax with a kernel function $\phi$, allowing the computation to be rewritten as $\phi(Q)(\phi(K)^\top V)$. By the associativity of matrix multiplication, you can compute $\phi(K)^\top V$ first (an $n \times d \times d$ operation, $O(nd^2)$) and then multiply by $\phi(Q)$, avoiding the $n \times n$ matrix entirely. In theory, this is $O(n)$ when $d$ is treated as constant — a dramatic improvement.

However, this reordering breaks in the causal setting. The reason is subtle but critical: when generating tokens autoregressively, token $t$ can only attend to tokens $1, 2, \ldots, t$, not to future tokens. With softmax attention, this is handled by applying a causal mask to the $n \times n$ attention matrix. With linear attention's right-product formulation, causality requires that each output $o_t = \sum_{s \leq t} \phi(q_t)(\phi(k_s)^\top v_s)$ is computed separately — or equivalently, that we maintain a running sum $\text{KV}_t = \text{KV}_{t-1} + \phi(k_t)^\top v_t$ and compute $o_t = \phi(q_t)(\text{KV}_t)$. This **cumulative summation (cumsum)** operation is inherently sequential: you cannot compute $\text{KV}_t$ until you've computed $\text{KV}_{t-1}$, because each step depends on the accumulated state from all previous tokens.

This is the crux of the problem. The theoretical $O(n)$ complexity assumes you can compute the right product in one shot, but the cumsum dependency forces sequential processing that prevents the kind of massively parallel computation GPUs excel at. As the authors note in Section 3.1:

> "when dealing with causal prediction tasks, the effectiveness of the right product is compromised, leading to the requirement for the computation of cumsum... This impediment hinders the potential for highly efficient parallel computation."

This is not a minor performance regression — it's a fundamental algorithmic bottleneck. Without solving cumsum, linear attention implementations end up either (a) falling back to left-product computation with $O(n^2)$ complexity in practice, defeating the purpose, or (b) accepting poor hardware utilization due to sequential dependencies. Either way, the theoretical advantage evaporates on real hardware.

This gap matters enormously because it determines whether linear attention can serve as a genuine replacement for softmax attention in production LLM training and inference. If the community cannot solve the cumsum problem, then all the theoretical elegance of linear attention — the constant inference cost regardless of sequence length, the fixed memory footprint — remains locked behind a hardware efficiency barrier that makes it practically slower than heavily optimized quadratic attention despite having better asymptotic complexity.

### Why This Problem Is Important

The stakes extend well beyond an academic comparison of attention mechanisms. The inability to efficiently handle long sequences is one of the most significant practical bottlenecks in modern LLM deployment, and it manifests across multiple dimensions:

**Training economics.** Training LLMs on long-context data (documents, books, multi-turn conversations, code repositories) requires the attention mechanism to scale with sequence length. With quadratic attention, doubling the sequence length quadruples the attention computation, rapidly dominating the total training cost. The paper's Figure 1 makes this concrete: at 400M parameters, LLaMA with FlashAttention-2 drops from approximately 36,000 tokens per GPU per second (TGS) at 1K context to roughly 4,000 TGS at 92K context — a 9× slowdown. For a 3B model, FlashAttention-2 runs out of memory entirely at 32K context on an 80GB A100. These numbers mean that training a model with genuinely long-range reasoning capabilities is either prohibitively expensive or outright infeasible under the current paradigm.

**Inference at scale.** For deployed LLMs handling long conversations, document analysis, or multi-modal inputs (where visual tokens can easily number in the thousands), per-query latency and cost scale with sequence length under quadratic attention. A chatbot that maintains conversation history over thousands of turns, or a code assistant that reads entire repositories, incurs attention costs that grow quadratically with the total context. Linear attention's theoretical property — constant per-token inference cost regardless of context length — would eliminate this scaling problem, but only if it actually runs fast in practice.

**Scientific and industrial applications.** The paper explicitly mentions "extended conversations in various professional domains and handling a vast number of tokens in multimodal modeling tasks" (Section 1). More broadly, applications like genomic sequence modeling (where inputs can be millions of base pairs), legal document analysis, long-form video understanding, and scientific literature synthesis all push against the context-length ceiling imposed by quadratic attention. Breaking through this ceiling would unlock qualitatively new capabilities, not just quantitative improvements in existing ones.

**The hardware-software gap.** This paper touches on a deeper issue in ML systems: the gap between algorithmic complexity theory and actual hardware performance. Linear attention is $O(n)$ on paper but has been consistently slower than well-implemented $O(n^2)$ attention in practice for causal modeling. This is not unique to attention — many theoretically efficient algorithms perform poorly on GPUs due to memory access patterns, parallelism constraints, or underutilization of specialized hardware units. Solving this gap for linear attention demonstrates that careful co-design of algorithms and hardware-aware implementations can bridge theory and practice, which has implications beyond this specific mechanism.

### Prior Approaches and Their Shortcomings

The paper identifies three categories of prior work that attempted to address attention efficiency, each with specific limitations that Lightning Attention-2 is designed to overcome.

#### Linear Attention Variants (The Algorithm Family)

The core idea behind linear attention — replacing softmax with a kernel function to enable right-product computation — was introduced independently by multiple groups. Katharopoulos et al. (2020a) used the $1 + \text{elu}$ activation function as the kernel; Choromanski et al. (2020) developed random Fourier feature approximations (Performers); Qin et al. (2022b) proposed cosine-based kernels (cosFormer); and Ke et al. (2021) and Zheng et al. (2022; 2023) explored sampling-based strategies. All of these share the same mathematical structure: $\text{Attention}(Q, K, V) \approx \phi(Q)(\phi(K)^\top V)$, with variations in how $\phi$ is defined.

The critical limitation across all these methods is that **the theoretical $O(nd^2)$ complexity does not translate to causal settings**. The authors are explicit about this in Section 2.1:

> "Despite having a theoretical complexity of $O(nd^2)$, the practical computational efficiency of linear attention diminishes notably in causal attention scenarios, primarily due to the necessity for cumsum operations."

This is the key insight that motivates the entire paper: it's not that prior linear attention methods made poor choices of kernel functions or approximations — the issue is deeper. The cumsum requirement creates a sequential dependency that prevents efficient parallelization regardless of which kernel function you choose. Improving $\phi$ does nothing to address the underlying hardware utilization problem.

#### IO-Aware Attention (FlashAttention and Lightning Attention-1)

The FlashAttention series (Dao et al., 2022; Dao, 2023) represents the state of the art in efficient softmax attention implementation. The key innovation is **IO-awareness**: recognizing that the bottleneck in attention computation is not FLOPs but memory bandwidth — specifically, the time spent reading and writing attention matrices between GPU High Bandwidth Memory (HBM) and on-chip SRAM. FlashAttention uses tiling to compute attention in blocks that fit entirely in SRAM, avoiding expensive HBM reads/writes of the full attention matrix.

Lightning Attention-1 (Qin et al., 2023b) applied this same IO-aware tiling philosophy to linear attention. However, the authors identify a fundamental limitation of this approach (Section 2.2):

> "Although this method is much more efficient than the PyTorch implementation, it does not take advantage of the computational characteristics inherent to Linear Attention, and the theoretical complexity remains $O(n^2d)$."

In other words, Lightning Attention-1 solved the IO problem (memory bandwidth) but not the computational complexity problem. By using the left-product formulation within each block (to avoid cumsum), it maintained $O(n^2)$ scaling despite being linear attention in name. It was faster than naive implementations but still exhibited quadratic growth in practice, as visible in Figure 3 (upper row), where Lightning Attention-1's runtime still curves upward with sequence length, albeit more slowly than FlashAttention-2.

The deeper issue is that **tiling alone doesn't solve cumsum**. If you simply break the sequence into blocks and compute attention block-by-block, you still need to handle dependencies between blocks. Without a principled way to separate intra-block and inter-block computation, you're forced to either (a) compute everything with left products (quadratic within blocks), (b) compute everything with right products (sequential cumsum between blocks), or (c) some ad-hoc combination that doesn't fully exploit linear attention's properties.

#### Length Extrapolation Techniques (The Alternative Approach)

A different line of work attempts to handle long sequences not by changing the attention mechanism's complexity, but by improving how models extrapolate to lengths beyond their training context. The paper surveys several approaches in Section 2.3:

- **Positional encoding methods**: ALiBi (Press et al., 2022) uses linear decay biases to suppress attention to distant tokens. RoPE (Su et al., 2021) encodes relative position through rotation. Kerple (Chi et al., 2022) generalizes ALiBi through kernel-based positional biases.

- **Context window extension**: Position Interpolation (Chen et al., 2023) extends RoPE-based models to 32K contexts through minimal fine-tuning. StreamingLLM (Xiao et al., 2023) exploits the "attention sink" phenomenon, preserving initial tokens' keys and values to maintain performance with sliding window attention.

The authors identify a fundamental limitation of all these approaches:

> "These methods can only extend sequence length in fine-tuning or testing phases, while our method allows training models in long sequence lengths from scratch with no additional cost."

This distinction is crucial. Length extrapolation techniques are post-hoc patches — they let a model trained at, say, 2K context handle 8K or 32K at inference time by modifying attention patterns, but they don't reduce the $O(n^2)$ cost of self-attention during training. You still can't afford to train on 100K-length sequences; you can only hope the model generalizes to them. For applications where long-range dependencies must be learned from data (not just extrapolated), these methods offer no solution.

#### GLA and RetNet (Concurrent Work with Partial Solutions)

The paper briefly discusses two closely related approaches in the Discussion at the end of Section 3.2.2. Gated Linear Attention (GLA) (Yang et al., 2023) uses data-dependent decay in linear attention and employs a chunk-wise Block-Parallel Algorithm that also uses tiling and IO-awareness. However, the authors note a key difference:

> "Unlike Lightning Attention-2, it uses parallel computations for each block, which leads to higher memory usage."

Retentive Network (RetNet) (Sun et al., 2023b) uses a chunk-wise retention algorithm structurally similar to TransNormerLLM's attention. The forward pass of RetNet's algorithm is comparable to Lightning Attention-2's forward pass, but:

> "does not consider IO-aware or the backward pass."

This is a critical omission — the backward pass is where much of the memory pressure and computational complexity in training comes from. An algorithm that only optimizes the forward pass leaves substantial efficiency on the table.

### How This Paper Positions Itself

The paper positions Lightning Attention-2 not as a new attention mechanism or a new kernel function, but as **the first implementation that bridges the gap between linear attention's theoretical complexity and real hardware performance in the causal setting**. The authors make this positioning explicit in their abstract:

> "Lightning Attention-2, the first linear attention implementation that enables linear attention to realize its theoretical computational benefits."

This is a systems contribution, not an algorithmic one. The core mathematical formulation — $\text{Norm}(Q(K^\top V))$ — is unchanged from prior linear attention work (specifically TransNormer). What's new is the **decomposition strategy** that makes this formulation run fast on GPUs despite the cumsum constraint.

The key insight is the **intra-inter block separation** (Section 3.2, Figure 2). Within a block of $B$ tokens (where $B$ is chosen to fit in SRAM), the algorithm uses conventional left-product attention — $[(Q_i K_i^\top) \odot M]V_i$ — because the $B \times B$ attention matrix fits entirely on-chip and doesn't incur HBM bandwidth penalties. This intra-block computation is $O(B^2 d)$ per block, but since $B$ is small and constant, it's effectively $O(1)$ per token.

Between blocks, the algorithm uses the linear attention kernel trick — $\Lambda Q_i(\text{KV})$ — where $\text{KV}$ is the accumulated key-value state from all previous blocks. This inter-block computation is $O(B d^2)$ per block, which is $O(d^2)$ per token — linear in sequence length, with no quadratic dependency. The critical innovation is that this inter-block state can be updated and propagated efficiently because the blocks are processed sequentially, with $\text{KV}$ maintained in SRAM.

The paper explicitly frames this as a "divide and conquer" strategy (Section 1, Section 3.2). By splitting the computation along block boundaries and using different algorithms for local (within-block) and global (across-block) attention, Lightning Attention-2 avoids both the quadratic scaling of pure left-product attention and the sequential bottleneck of pure cumsum. Each block's computation is largely independent — you need the $\text{KV}$ state from previous blocks, but once you have it, all $B$ tokens in the block can be processed in parallel. The inter-block dependency is $O(1)$ state transfers per block, not $O(B)$ sequential steps.

This is a fundamentally different approach from Lightning Attention-1, which used tiling for IO efficiency but kept the $O(n^2)$ left-product formulation throughout. Lightning Attention-2's innovation is recognizing that **you can use both formulations within the same attention operation**, switching between them based on whether you're computing within a block (where left product is efficient because $B$ is small) or across blocks (where right product is efficient because it avoids the quadratic dependency on total sequence length).

The paper also positions itself at the intersection of two research traditions: linear attention algorithms (Section 2.1) and hardware-aware kernel design (Section 2.2). By combining the mathematical insights of linear attention with the engineering techniques of IO-aware tiling (from FlashAttention) and custom GPU kernels (implemented in Triton), Lightning Attention-2 represents a **full-stack solution** — it's efficient at both the algorithmic level ($O(n)$ complexity) and the hardware level (minimizing HBM-SRAM transfers).

Finally, the paper draws an implicit contrast with GLA and RetNet by emphasizing that Lightning Attention-2 handles both the forward and backward pass with IO-awareness, and that its memory usage scales better than parallel-block approaches. The backward pass algorithms (Algorithm 2, Equations 15–20) are a significant part of the contribution — they show how the intra-inter decomposition extends to gradient computation with the same tiling structure, maintaining efficiency in both directions.

## 3. Technical Approach

### 3.1 Reader Orientation

This paper presents a **GPU kernel implementation** — not a new attention mechanism or model architecture — that makes an existing linear attention formulation actually run fast on hardware in the causal (autoregressive) setting. The system being built is a drop-in replacement for the attention computation in TransNormerLLM, implemented as a Triton kernel that can be called like any other PyTorch operation during training and inference.

The problem it solves has two parts. First, linear attention has theoretical $O(n)$ complexity but the cumulative summation required for causal masking forces sequential computation that prevents GPU parallelism. Second, naive tiling (as in Lightning Attention-1) circumvents cumsum by using the $O(n^2)$ left-product within each tile, defeating the purpose. The shape of the solution is a **block-level decomposition** that uses two different attention formulations within the same operation: the conventional left product within each small block (where $O(B^2)$ is acceptable because $B$ is constant and the block fits in SRAM) and the linear-attention right product across blocks (where $O(d^2)$ per block gives linear scaling in total sequence length). The key architectural decision is maintaining a running $\text{KV}$ state in SRAM that accumulates key-value information from all previous blocks, enabling each block to attend to the entire prefix without recomputing history.

### 3.2 Big-Picture Architecture (Diagram in Words)

The Lightning Attention-2 system operates as follows, with five conceptual components:

1. **Input segmentation**: The full $Q$, $K$, $V \in \mathbb{R}^{n \times d}$ matrices are divided into $T = n / B$ blocks of size $B \times d$ each, where $B$ is chosen to fit the block computation entirely within GPU SRAM. $X_t$ denotes the $t$-th block of matrix $X$.

2. **Forward intra-block computation**: For each block, compute the conventional causal left-product attention $[(Q_t K_t^\top) \odot M] V_t$ where $M$ is a fixed $B \times B$ causal mask with exponential decay. This captures fine-grained local attention structure within the current block and runs entirely on-chip in SRAM.

3. **Forward inter-block computation**: For each block, compute $\Lambda Q_t (\text{KV})$ where $\text{KV}$ is a $d \times d$ matrix maintained in SRAM that accumulates the right-product key-value state from all blocks processed so far, and $\Lambda$ is a diagonal matrix encoding exponential temporal decay. This captures global attention without forming $n \times n$ matrices.

4. **KV state update**: After processing block $t$, update $\text{KV} \leftarrow \lambda^B \text{KV} + (\lambda^B \Lambda^{-1} K_t)^\top V_t$, applying decay to old information and incorporating the new block. The updated $\text{KV}$ stays in SRAM for the next block.

5. **Backward pass (reverse sweep)**: During backpropagation, an analogous decomposition is applied in reverse order. A $d\text{KV}$ state (maintained in SRAM) propagates gradient information from later blocks to earlier ones, enabling the gradients $\partial \mathcal{L}/\partial Q$, $\partial \mathcal{L}/\partial K$, and $\partial \mathcal{L}/\partial V$ to be computed as intra-block and inter-block components with the same tiling structure.

Information flows forward block-by-block: HBM → SRAM (load $Q_t, K_t, V_t$), on-chip intra + inter computation, KV state update, SRAM → HBM (write $O_t$). The backward pass reverses direction, loading blocks from $t = T$ down to $1$, computing gradients with the same decomposition, and propagating $d\text{KV}$ backward through the sequence.

### 3.3 Roadmap for the Deep Dive

- **First, the mathematical formulation of linear attention** (Equations 1–2 in the paper, Section 3.1) — the NormAttention mechanism from TransNormer and the recursive KV state that creates the cumsum bottleneck. This establishes what is being computed and WHY naive implementations fail.

- **Second, the forward pass decomposition** (Equations 3–10, Algorithm 1) — how the intra-block and inter-block separation is derived mathematically, what each term represents physically, and how the KV state is propagated across blocks. This is the core algorithmic contribution.

- **Third, the backward pass decomposition** (Equations 11–20, Algorithm 2) — how gradients flow through the tiled structure, particularly the $d\text{KV}$ state that propagates gradient information backward across blocks. The backward pass is equally important because training throughput depends on both forward and backward efficiency.

- **Fourth, the hardware mapping and implementation details** — how the algorithm maps to GPU memory hierarchy (HBM vs. SRAM), why certain operations stay on-chip, how the Triton implementation achieves IO-awareness, and the specific design choices around block size, masking, and decay matrices. This connects the mathematics to the actual speedup.

- **Fifth, the relationship to prior and concurrent work** — how Lightning Attention-2 differs from Lightning Attention-1 (which used left-product tiling throughout, maintaining $O(n^2)$), from GLA (which uses parallel block computation with higher memory usage), and from RetNet (which handles the forward pass similarly but doesn't address IO-awareness or the backward pass).

### 3.4 Detailed, Sentence-Based Technical Breakdown

This is primarily a **systems implementation paper** whose core idea is that linear attention's theoretical $O(n)$ complexity can be realized on GPU hardware by decomposing the attention computation into intra-block (left-product, $O(B^2)$ per block) and inter-block (right-product, $O(d^2)$ per block) components, with the inter-block computation leveraging a running KV state maintained in SRAM to avoid both the $O(n^2)$ scaling of left-product attention and the sequential bottleneck of naive cumsum.

#### Mathematical Formulation of Linear Attention (NormAttention and Recursive KV State)

The paper builds on the NormAttention mechanism from TransNormer (Qin et al., 2022a). The starting point is the attention formulation:

$$O = \text{Norm}((Q K^\top) V)$$

where $Q \in \mathbb{R}^{n \times d}$ is the query matrix, $K \in \mathbb{R}^{n \times d}$ is the key matrix, and $V \in \mathbb{R}^{n \times d}$ is the value matrix, with $n$ denoting sequence length and $d$ representing the feature (head) dimension. $\text{Norm}(\cdot)$ is a normalization operation — the paper notes it is ignored in the derivations for simplicity, since it doesn't affect the computational structure being optimized.

**What it computes:** the standard attention operation (without softmax) — each query token computes a weighted combination of all value vectors, where the weights come from query-key similarity. The $QK^\top$ product produces an $n \times n$ matrix of pairwise similarities, which is multiplied by $V$ to produce the $n \times d$ output.

**Why this form:** TransNormer dispenses with the softmax operation that makes standard attention expensive. Without softmax, the matrix multiplication is associative, enabling the mathematical equivalence:

$$O = \text{Norm}(Q (K^\top V))$$

This reordering is the foundation of linear attention. Instead of computing $QK^\top$ (an $O(n^2 d)$ operation) then multiplying by $V$, you compute $K^\top V$ first (an $O(n d^2)$ operation) then multiply by $Q$. When $d \ll n$ (as is typical in transformers, where $d$ might be 64–128 while $n$ can be 100K+), $O(n d^2)$ is dramatically cheaper than $O(n^2 d)$.

However, this reordering breaks in the **causal setting**. The problem is that for autoregressive generation, each token $t$ can only attend to tokens $s \leq t$ (itself and the past). In the left-product formulation, this is enforced by applying a causal mask to the $n \times n$ matrix. In the right-product formulation, the $K^\top V$ product must be computed differently for each position $t$, because it should only include information from tokens $\leq t$. The paper introduces the recursive formulation that captures this constraint:

$$o_t = q_t \sum_{s \leq t} \lambda^{t-s} k_s^\top v_s$$

where $o_t \in \mathbb{R}^{1 \times d}$ is the output for the $t$-th token, $q_t \in \mathbb{R}^{1 \times d}$ is the $t$-th query vector, $k_s \in \mathbb{R}^{1 \times d}$ is the $s$-th key vector, $v_s \in \mathbb{R}^{1 \times d}$ is the $s$-th value vector, and $\lambda \in \mathbb{R}^+$ is a decay rate constant (a hyperparameter that controls how quickly the influence of past tokens diminishes).

**What it computes:** for each position $t$, it computes a weighted sum of all past (and current) value vectors, where the weight for position $s$ is the dot product $q_t k_s^\top$ scaled by an exponential decay factor $\lambda^{t-s}$ that reduces the influence of distant tokens.

**Why this form:** the exponential decay $\lambda^{t-s}$ serves as the causal masking mechanism — it doesn't zero out future tokens (they're excluded from the sum entirely) but it does reduce the weight of distant past tokens, serving a similar function to the position-dependent scaling that different positional encoding schemes provide. This decay is what makes the recursive formulation possible.

The recursive form that causes the cumsum bottleneck is:

$$\text{kv}_0 = 0 \in \mathbb{R}^{d \times d}$$

$$\text{kv}_t = \lambda \text{kv}_{t-1} + k_t^\top v_t$$

$$o_t = q_t(\text{kv}_t)$$

where $\text{kv}_t \in \mathbb{R}^{d \times d}$ is the accumulated key-value state at position $t$.

**What it computes:** at each step $t$, you take the previous KV state $\text{kv}_{t-1}$, decay it by $\lambda$ (reducing the influence of all past information), and add the outer product $k_t^\top v_t$ (a $d \times d$ matrix representing the information from the current token). The output $o_t$ is simply the query $q_t$ multiplied by this accumulated state.

**Why this form is the bottleneck:** this recurrence is inherently sequential — you cannot compute $\text{kv}_t$ until $\text{kv}_{t-1}$ is available. On a GPU, which achieves its throughput through massive parallelism (thousands of threads operating simultaneously), a sequential dependency of length $n$ means you can only use a tiny fraction of the available compute at any given time. The $k_t^\top v_t$ outer product is a rank-1 update to a $d \times d$ matrix, which uses very few GPU cores. You're essentially running the GPU like a sequential processor, losing 2–3 orders of magnitude of potential throughput. This is why the authors note that "the effectiveness of the right product is compromised, leading to the requirement for the computation of cumsum" (Section 3.1) — the theoretical $O(n d^2)$ complexity is correct in FLOP-counting terms, but the hardware utilization is so poor that the actual wall-clock time is much worse than the FLOP count would suggest.

#### Forward Pass: Intra-Inter Block Decomposition

The core algorithmic insight of Lightning Attention-2 is to break the sequence into blocks of size $B$, and compute attention differently within blocks versus across blocks. The derivation proceeds by partitioning the sequence into $T = n/B$ blocks, where $X_t$ denotes the $t$-th block of matrix $X$ (for $X \in \{Q, K, V, O, dO\}$). The block output for block $t+1$ at position $tB + r$ (where $1 \leq r \leq B$) is derived by splitting the sum over past tokens into two parts: tokens in the current block and tokens in all previous blocks:

$$o_{tB+r} = q_{tB+r}\left(\sum_{s=tB+1}^{tB+r} \lambda^{tB+r-s} k_s^\top v_s + \lambda^r \sum_{s \leq tB} \lambda^{tB-s} k_s^\top v_s\right)$$

where the first term sums over tokens within the current block (positions $tB+1$ through $tB+r$) and the second term captures all tokens from previous blocks (through position $tB$), with an additional $\lambda^r$ factor to account for the temporal distance.

**What it computes:** for each token in block $t+1$, the output is the sum of (a) attention to other tokens within the same block and (b) attention to all tokens in all previous blocks, decayed by the appropriate temporal distance.

**Why this split:** this is the mathematical justification for the intra-inter decomposition. The first term involves only tokens within the current block — all indices are within a range of size $B$. The second term involves a sum over all previous blocks that can be pre-computed and reused for every token in the current block. The key observation is that $\sum_{s \leq tB} \lambda^{tB-s} k_s^\top v_s$ is exactly the KV state accumulated from all tokens up through block $tB$, which can be maintained as a running $d \times d$ matrix that is updated once per block rather than once per token.

Rewriting this in matrix form for the entire $(t+1)$-th block gives the central equation of the forward pass:

$$O_{t+1} = \underbrace{[(Q_{t+1} K_{t+1}^\top) \odot M] V_{t+1}}_{\text{Intra Block}} + \underbrace{\Lambda Q_{t+1}(\text{KV}_t)}_{\text{Inter Block}}$$

where each term is defined as follows:

- $Q_{t+1}, K_{t+1}, V_{t+1} \in \mathbb{R}^{B \times d}$ are the query, key, and value matrices for the $(t+1)$-th block (containing $B$ tokens each).
- $M \in \mathbb{R}^{B \times B}$ is a fixed causal mask with entries $M_{ij} = \lambda^{i-j}$ if $i \geq j$ and $0$ otherwise. This mask is pre-initialized once and reused for every block — it encodes the exponential decay pattern within a block.
- $\odot$ denotes element-wise (Hadamard) multiplication. The product $(Q_{t+1} K_{t+1}^\top) \odot M$ computes a $B \times B$ attention matrix for tokens within the block, with causal masking and exponential decay applied simultaneously.
- $\Lambda = \text{diag}\{\lambda^1, \lambda^2, \ldots, \lambda^B\} \in \mathbb{R}^{B \times B}$ is a diagonal matrix that applies temporal decay to the inter-block attention based on each token's position within the block. The $i$-th diagonal entry is $\lambda^i$, meaning the $i$-th token in the block receives inter-block information decayed by $\lambda^i$.
- $\text{KV}_t \in \mathbb{R}^{d \times d}$ is the accumulated key-value state from all blocks up through block $t$, defined as $\text{KV}_t = \sum_{s \leq tB} \lambda^{tB-s} k_s^\top v_s$.

**What it computes:** the output of block $t+1$ is the sum of two contributions. The intra-block term $[(Q_{t+1} K_{t+1}^\top) \odot M] V_{t+1}$ computes local attention within the current $B$ tokens — each of the $B$ tokens attends to all tokens in the block that precede it (including itself), with exponential decay weights. This is exactly the conventional (quadratic) attention computation, but applied to a block of constant size $B$, so its cost is $O(B^2 d)$ per block, which is $O(B d)$ per token — constant with respect to total sequence length $n$. The inter-block term $\Lambda Q_{t+1}(\text{KV}_t)$ computes global attention to all previous blocks. $\text{KV}_t$ is a $d \times d$ matrix encoding all past information, $Q_{t+1}(\text{KV}_t)$ projects each of the $B$ queries against this accumulated state (cost: $O(B d^2)$), and $\Lambda$ applies position-dependent decay. The cost is $O(B d^2)$ per block, or $O(d^2)$ per token — linear in sequence length, with no quadratic dependency.

**Why this form works:** the critical property is that the intra-block computation costs $O(B^2 d)$ per block but $B$ is chosen to be small enough that the $B \times B$ attention matrix fits entirely in SRAM, avoiding expensive HBM writes. The inter-block computation costs $O(B d^2)$ per block and depends on the entire prefix only through the compact $\text{KV}_t$ state (a fixed-size $d \times d$ matrix regardless of how many tokens are in the prefix). By using the left product for intra-block operations (where $B$ is small and the quadratic cost is acceptable) and the right product for inter-block operations (where $n$ is large and linear scaling is essential), the algorithm achieves the best of both worlds. A pure left-product approach would cost $O(n^2 d)$ total. A pure right-product approach would require per-token sequential updates to $\text{KV}$ (the cumsum problem), preventing parallelism. This hybrid approach costs $O(n B d + n d^2 / B)$ total — the first term from intra-block computation (linear in $n$ because $B$ is constant) and the second term from inter-block computation (also linear in $n$). Neither term has quadratic dependence on $n$.

The KV state update between blocks is derived by extending the summation:

$$\text{KV}_{t+1} = \sum_{s \leq (t+1)B} \lambda^{(t+1)B-s} k_s^\top v_s$$

$$= \lambda^B \sum_{s \leq tB} \lambda^{tB-s} k_s^\top v_s + \sum_{s=tB+1}^{(t+1)B} \lambda^{(t+1)B-s} k_s^\top v_s$$

$$= \lambda^B \text{KV}_t + (\lambda^B \Lambda^{-1} K_{t+1})^\top V_{t+1}$$

where $\Lambda^{-1} = \text{diag}\{\lambda^{-1}, \lambda^{-2}, \ldots, \lambda^{-B}\}$ is the inverse of the decay matrix, used to "undo" the decay that will be applied in the next block's inter-block computation.

**What it computes:** to prepare the KV state for the next block, the algorithm (a) decays the existing state by $\lambda^B$ (accounting for the $B$ time steps between blocks), and (b) adds the contribution from the current block's tokens. The term $(\lambda^B \Lambda^{-1} K_{t+1})$ represents the keys with their decay factors adjusted so that when the next block applies $\Lambda$ to its queries, the temporal alignment is correct.

**Why this update rule:** the mathematical derivation follows directly from the definition of $\text{KV}_t$ as a summation. The $\lambda^B$ factor on the old state accounts for the fact that all tokens in $\text{KV}_t$ are now $B$ time steps further in the past relative to the next block. The $\Lambda^{-1}$ factor on $K_{t+1}$ is a subtle detail: each row $i$ of $K_{t+1}$ corresponds to a token at position $tB + i$, and its contribution to $\text{KV}$ must be properly aligned so that when a query at position $(t+1)B + j$ (in the next block) multiplies against $\text{KV}$, the decay exponent is $\lambda^{(t+1)B + j - (tB + i)} = \lambda^{B + j - i}$, which is exactly what $\lambda^B \Lambda^{-1}$ encodes when combined with the $\Lambda$ factor that will be applied to the query.

The complete forward pass is detailed in Algorithm 1 of the paper, reproduced here conceptually:

1. **Initialize** $\text{KV} = 0 \in \mathbb{R}^{d \times d}$ and the mask $M$ and decay matrix $\Lambda$.
2. **For each block** $i = 1, 2, \ldots, T$:
   - Load $Q_i, K_i, V_i \in \mathbb{R}^{B \times d}$ from HBM to SRAM.
   - Compute $\text{O}_{\text{intra}} = [(Q_i K_i^\top) \odot M] V_i$ entirely in SRAM.
   - Compute $\text{O}_{\text{inter}} = \Lambda Q_i (\text{KV})$ entirely in SRAM.
   - Compute $\text{KV} = \lambda^B \text{KV} + (\lambda^B \Lambda^{-1} K_i)^\top V_i$ entirely in SRAM.
   - Write $O_i = \text{O}_{\text{intra}} + \text{O}_{\text{inter}}$ from SRAM to HBM.
3. **Return** the concatenation of all $O_i$ blocks.

The critical hardware-aware design choice is that **all block-level computation stays in SRAM** — the $Q_i, K_i, V_i$ blocks are loaded once, the intra and inter outputs are computed using only SRAM-resident data (including the running $\text{KV}$ state), and only the final output block is written back to HBM. This minimizes the number of HBM-SRAM transfers, which are the dominant cost in attention computation on modern GPUs (as FlashAttention established). The $B \times B$ intra-block attention matrix $(Q_i K_i^\top) \odot M$ is never written to HBM — it exists only as an intermediate value in SRAM, consumed immediately by the multiplication with $V_i$.

#### Backward Pass: Gradient Propagation Through the Tiled Structure

The backward pass is equally critical for training throughput, and the paper provides a full derivation showing that the same intra-inter decomposition applies to gradient computation. The backward pass must compute three gradients: $\partial \mathcal{L} / \partial Q$, $\partial \mathcal{L} / \partial K$, and $\partial \mathcal{L} / \partial V$, given the upstream gradient $dO = \partial \mathcal{L} / \partial O \in \mathbb{R}^{n \times d}$. The derivation starts from the element-wise gradients for a single token:

$$dq_t = do_t(\text{kv}_t)^\top \in \mathbb{R}^{1 \times d}$$

$$dk_t = v_t(d\text{kv}_t)^\top \in \mathbb{R}^{1 \times d}$$

$$dv_t = k_t(d\text{kv}_t) \in \mathbb{R}^{1 \times d}$$

where $do_t \in \mathbb{R}^{1 \times d}$ is the gradient with respect to the output at position $t$, and $d\text{kv}_t \in \mathbb{R}^{d \times d}$ is defined as:

$$d\text{kv}_t = \sum_{s \geq t} \lambda^{s-t} q_s^\top do_s \in \mathbb{R}^{d \times d}$$

with the recursive form:

$$d\text{kv}_{n+1} = 0 \in \mathbb{R}^{d \times d}$$

$$d\text{kv}_{t-1} = \lambda d\text{kv}_t + q_{t-1}^\top do_{t-1}$$

**What it computes:** $d\text{kv}_t$ is the gradient of the loss with respect to the KV state at position $t$. It accumulates gradient contributions from all future positions (since the KV state at time $t$ affects all outputs $o_s$ for $s \geq t$), with exponential decay applied backward in time. The recursive form shows that $d\text{kv}_t$ can be computed by moving from the end of the sequence backward: each step takes the previous $d\text{kv}_{t+1}$, decays it by $\lambda$, and adds the contribution from the current position's query and output gradient.

**Why this backward recurrence matters:** this is the dual of the forward cumsum problem. In the forward pass, $\text{kv}_t$ must be computed sequentially from left to right. In the backward pass, $d\text{kv}_t$ must be computed sequentially from right to left. Both create sequential dependencies that prevent parallelization. The tiling strategy must handle both directions.

For the block-level decomposition, the paper defines a block-level $d\text{KV}$ state analogous to the forward $\text{KV}$:

$$d\text{KV}_{T+1} = 0 \in \mathbb{R}^{d \times d}$$

$$d\text{KV}_t = \sum_{s > tB} \lambda^{s-tB} q_s^\top do_s$$

**What it computes:** $d\text{KV}_t$ is the gradient with respect to the block-level KV state at block boundary $tB$. It accumulates gradient contributions from all tokens in blocks after block $t$.

The gradient for queries in block $t+1$ follows the same intra-inter decomposition as the forward pass:

$$dQ_{t+1} = \underbrace{[(dO_{t+1} V_{t+1}^\top) \odot M] K_{t+1}}_{\text{Intra Block}} + \underbrace{\Lambda dO_{t+1}(\text{KV}_t)^\top}_{\text{Inter Block}}$$

**What it computes:** the gradient with respect to queries in block $t+1$ has two sources. The intra-block term captures how changes in $Q_{t+1}$ affect the output through local attention within the block — the structure $[(dO_{t+1} V_{t+1}^\top) \odot M] K_{t+1}$ is the derivative of the intra-block forward computation. The inter-block term captures how changes in $Q_{t+1}$ affect the output through global attention to the accumulated KV state — this uses the forward $\text{KV}_t$ (computed during the forward pass and stored).

The gradients for keys and values require the backward-propagating $d\text{KV}$ state. For block $t-1$:

$$dK_{t-1} = \underbrace{[(dO_{t-1} V_{t-1}^\top) \odot M]^\top Q_{t-1}}_{\text{Intra Block}} + \underbrace{\lambda^B \Lambda^{-1} V_{t-1} (d\text{KV}_t^\top)}_{\text{Inter Block}}$$

$$dV_{t-1} = \underbrace{[(Q_{t-1} K_{t-1}^\top) \odot M]^\top dO_{t-1}}_{\text{Intra Block}} + \underbrace{\lambda^B \Lambda^{-1} K_{t-1} (d\text{KV}_t)}_{\text{Inter Block}}$$

**What these compute:** the gradients for keys and values in block $t-1$ have intra-block components (local effects within the block) and inter-block components that depend on $d\text{KV}_t$ — the gradient information flowing backward from all later blocks. The factors $\lambda^B$ and $\Lambda^{-1}$ ensure the temporal alignment is correct (matching the forward pass structure).

The update rule for $d\text{KV}$ propagating backward is:

$$d\text{KV}_t = \lambda^B d\text{KV}_{t+1} + (\Lambda Q_t)^\top dO_t$$

**What it computes:** moving from block $t+1$ to block $t$, the algorithm decays the existing $d\text{KV}$ by $\lambda^B$ (since we're moving one block backward in time) and adds the contribution from the current block's queries and output gradients. This is structurally identical to the forward KV update, but operating in reverse on gradient information rather than forward on key-value pairs.

The complete backward pass (Algorithm 2) proceeds in two sweeps:

1. **Forward-order sweep** (for $dQ$): process blocks $i = 1, \ldots, T$ in forward order. For each block, load $K_i, V_i, O_i, dO_i$ and the running $\text{KV}$ state, compute $dQ_i^{\text{intra}}$ and $dQ_i^{\text{inter}}$ (which uses $\text{KV}$ from the forward pass), update $\text{KV}$ (replicating the forward pass computation to maintain the state), and write $dQ_i$. This works in forward order because $dQ_t$ only depends on $\text{KV}_{t-1}$ (computed from tokens before $t$), which is available from the forward pass.

2. **Reverse-order sweep** (for $dK$ and $dV$): process blocks $i = T, \ldots, 1$ in reverse order. For each block, load $Q_i, K_i, V_i, O_i, dO_i$ and the running $d\text{KV}$ state, compute $dK_i^{\text{intra}}, dK_i^{\text{inter}}, dV_i^{\text{intra}}, dV_i^{\text{inter}}$, update $d\text{KV}$ using $(\Lambda Q_i)^\top dO_i$, and write $dK_i, dV_i$. This works in reverse order because $dK_t$ and $dV_t$ depend on $d\text{KV}_{t+1}$ (gradient information from tokens after $t$), which must be accumulated from right to left.

**Why two sweeps are necessary:** the forward pass produces two types of intermediate states that gradients depend on. The $\text{KV}$ state (accumulated left to right) is needed for $dQ$, so $dQ$ can be computed in the same forward sweep. The $d\text{KV}$ state (accumulated right to left) is needed for $dK$ and $dV$, requiring a separate backward sweep. This is not an inefficiency — it's a direct consequence of the causal structure. The key optimization is that both sweeps use the same tiling, the same block size $B$, and the same SRAM-resident state maintenance pattern, so the backward pass achieves the same $O(n)$ scaling as the forward pass.

#### Hardware Mapping and IO-Aware Implementation

The algorithm's theoretical efficiency depends on a careful mapping to GPU memory hierarchy. Modern GPUs (like the A100) have two memory tiers with dramatically different characteristics:

- **HBM (High Bandwidth Memory):** 80 GB capacity, ~2 TB/s bandwidth, shared across all streaming multiprocessors. Reading/writing HBM is the dominant cost in most GPU kernels — it's approximately 10–20× slower than SRAM access per byte.
- **SRAM (Static Random-Access Memory):** ~192 KB per streaming multiprocessor (on A100), ~19 TB/s bandwidth (aggregate across all SMs). SRAM is on-chip, physically close to the compute units, and can sustain the full computational throughput of tensor cores.

The key design principle of Lightning Attention-2 is that **all $B \times B$ matrices (intra-block attention) and all $d \times d$ matrices ($\text{KV}$ and $d\text{KV}$ states) fit in SRAM**, and are never written to HBM. The specific memory layout and sizes are:

- **Block size $B$:** chosen so that $B \times d$ matrices for $Q_i, K_i, V_i, O_i$ plus the $B \times B$ intra-block attention matrix plus the $d \times d$ KV state all fit within the SRAM budget of a single streaming multiprocessor. While the paper does not explicitly state the numerical value of $B$, the constraint is: $4Bd + B^2 + d^2 + 2d^2 \leq \text{SRAM\_size}$ (accounting for Q, K, V, O matrices, the attention matrix, KV, dKV, and workspace). For typical values like $d = 128$ and $B = 128$, the memory requirement would be approximately $4 \times 128 \times 128 \times 2 + 128^2 \times 2 + 2 \times 128^2 \times 2$ bytes (assuming FP16) ≈ 256 KB, which is feasible within A100's 192 KB per SM with careful management (possibly using multiple SMs cooperatively or a smaller block size).

- **KV state ($d \times d$):** maintained persistently in SRAM across block iterations. This is the key state that enables $O(1)$ memory for inter-block attention — regardless of how many blocks have been processed, the prefix is summarized in a fixed-size $d \times d$ matrix. The $d\text{KV}$ state (for the backward pass) is similarly maintained.

- **Mask $M$ and decay matrix $\Lambda$:** pre-computed once (size $B \times B$ and $B \times B$ respectively) and stored in SRAM or constant memory. Since these are the same for every block and every attention head, they can be loaded once and reused.

The IO pattern for the forward pass (per block) is:
1. **HBM → SRAM:** read $Q_i, K_i, V_i$ (3 reads of $B \times d$ elements each).
2. **SRAM computation:** intra-block attention ($B \times B$ multiply, masked, times $V$), inter-block attention ($\Lambda Q_i$ times $\text{KV}$), KV update.
3. **SRAM → HBM:** write $O_i$ (1 write of $B \times d$ elements).

The total IO volume per block is $4Bd$ reads/writes. Across all $T = n/B$ blocks, the total IO is $4nd$ elements — linear in sequence length. This contrasts with naive attention implementations that would read/write the $n \times n$ attention matrix ($n^2$ IO) or Lightning Attention-1 that, while tiled, still computes $O(n^2)$ operations per block internally.

**Why Triton:** the paper implements Lightning Attention-2 in Triton (Tillet et al., 2019), a Python-embedded DSL for writing GPU kernels. Triton provides two key advantages for this type of algorithm: (1) it automatically handles low-level details like thread block scheduling, shared memory allocation, and coalesced memory access patterns — the programmer specifies the computation at the block level and Triton compiles it to efficient GPU code; (2) it enables rapid experimentation with different block sizes, tiling strategies, and memory layouts without writing CUDA C++. The IO-awareness comes from explicitly controlling which tensors are loaded into SRAM (via Triton's `tl.load` and `tl.store` operations) and ensuring that intermediate results (the $B \times B$ attention matrix) are kept in registers or shared memory rather than being written to global memory.

**The decay rate $\lambda$:** this is a hyperparameter of the attention mechanism (not the implementation). The paper inherits it from TransNormerLLM and does not specify its exact value, but it acts as a temporal decay factor: $\lambda < 1$ means distant tokens are progressively down-weighted, while $\lambda = 1$ would give equal weight to all past tokens (no decay). The exponential form $\lambda^{t-s}$ means the influence of a token $s$ on token $t$ decays by a factor of $\lambda$ for each time step of separation. The choice of $\lambda$ affects the model's inductive bias toward local versus global attention, and is typically tuned as part of model design rather than the kernel implementation.

#### Relationship to Prior and Concurrent Work

The paper explicitly distinguishes Lightning Attention-2 from three related approaches in the Discussion (end of Section 3.2.2).

**Lightning Attention-1 (Qin et al., 2023b):** the predecessor used tiling for IO efficiency but computed attention within each block using the left-product formulation exclusively — $[(Q_i K_i^\top) \odot M] V_i$ for each block, without any inter-block right-product component. This means the computational complexity per block is $O(B^2 d)$, and across all blocks it's $O(n B d)$. However, because there's no mechanism for blocks to share information through a KV state, each block can only attend to tokens within itself. To handle cross-block attention, Lightning Attention-1 would need to process blocks differently (perhaps with overlapping blocks or a separate cross-block mechanism), which the authors note leads to "theoretical complexity remains $O(n^2 d)$" (Section 2.2). In practice, Lightning Attention-1's runtime curves upward with sequence length (Figure 3, upper row), indicating that it does not achieve constant per-token cost. Lightning Attention-2's key improvement is the addition of the inter-block term $\Lambda Q_i(\text{KV})$ with the running KV state, which enables cross-block attention at $O(d^2)$ per block rather than $O(B^2)$ or worse.

**Gated Linear Attention (GLA) (Yang et al., 2023):** GLA uses data-dependent decay (the decay rate varies per token and per head, rather than being a fixed $\lambda$) and employs a chunk-wise Block-Parallel Algorithm. The critical difference the authors highlight is that GLA "uses parallel computations for each block, which leads to higher memory usage." In GLA's approach, all blocks are processed in parallel (or at least independently), which requires storing intermediate states for each block simultaneously. For a sequence of length $n$ with block size $B$, this means storing $n/B$ separate KV states (each $d \times d$), leading to memory usage that scales as $O(n d^2 / B)$ — linear in sequence length. Lightning Attention-2's sequential block processing stores only one KV state at a time, giving $O(d^2)$ memory regardless of sequence length. For very long sequences, this memory difference becomes critical: at $n = 100K$, $d = 128$, $B = 128$, GLA's approach would store roughly $100K/128 \approx 780$ KV states, requiring about $780 \times 128^2 \times 2$ bytes ≈ 25 MB for the KV states alone (in FP16), while Lightning Attention-2 stores exactly one ($128^2 \times 2$ bytes ≈ 32 KB). The sequential processing may seem like a disadvantage for parallelism, but within each block, the $B$ tokens are processed in parallel — the sequential dependency is only between blocks, and there are far fewer blocks than tokens ($T \ll n$ for typical $B$).

**RetNet (Sun et al., 2023b):** RetNet's chunk-wise retention algorithm is structurally similar to Lightning Attention-2's forward pass — it also splits computation into intra-chunk and inter-chunk components with a running state. However, the authors note two limitations: (1) RetNet "does not consider IO-aware" — its implementation does not explicitly manage the HBM-SRAM data movement, meaning intermediate results may be unnecessarily written to and read from HBM, incurring bandwidth costs; (2) RetNet's algorithm only addresses the forward pass, leaving the backward pass to automatic differentiation, which would not apply the same tiling and state-maintenance optimizations and would likely be much slower. Lightning Attention-2 provides IO-aware implementations of both forward and backward passes (Algorithms 1 and 2), with the backward pass explicitly designed to maintain $O(n)$ complexity and minimize HBM-SRAM transfers.

The paper also implicitly contrasts with FlashAttention-2 (Dao, 2023), though not in the Discussion. FlashAttention-2 achieves excellent performance for softmax attention through IO-aware tiling, but its computational complexity remains $O(n^2 d)$ — it reduces the constant factor (by minimizing HBM transfers) but not the asymptotic scaling. This is why FlashAttention-2's throughput degrades with sequence length (Figure 1, Figure 3) while Lightning Attention-2's remains constant. The key structural difference is that FlashAttention-2 must eventually compute the softmax over the full attention row for each query, which requires materializing (if only in SRAM) portions of the $n \times n$ attention matrix, while Lightning Attention-2's right-product formulation never materializes any attention matrix larger than $B \times B$.

#### Summary of Design Choices and Their Justifications

- **Intra-block left product, inter-block right product:** using the left product within blocks exploits the fact that $B$ is small and the $B \times B$ attention matrix fits in SRAM — the quadratic cost is acceptable because $B$ is constant. Using the right product across blocks avoids the $O(n^2)$ dependency on total sequence length — the $d \times d$ KV state compactly summarizes the entire prefix.

- **Sequential block processing with SRAM-resident KV state:** processing blocks sequentially (rather than in parallel) means only one KV state needs to be maintained, keeping memory usage constant in sequence length ($O(d^2)$ rather than $O(n d^2 / B)$). The sequential dependency is only $T = n/B$ steps, not $n$ steps (since each block processes $B$ tokens in parallel internally), so the parallelism loss is minimal for reasonable $B$ (e.g., $B = 128$, $n = 131072$, $T = 1024$ blocks — 1024 sequential steps versus 131072 for token-level recurrence).

- **Triton implementation:** provides IO-awareness (explicit control over HBM-SRAM transfers) without the development complexity of hand-written CUDA. Critically, Triton's block-level programming model maps naturally to the algorithm's block-level decomposition — each Triton program instance processes one block of $Q, K, V$, exactly matching the algorithm's structure.

- **Two-sweep backward pass:** computing $dQ$ in forward order (using the stored $\text{KV}$ from the forward pass) and $dK, dV$ in reverse order (using the backward-propagating $d\text{KV}$ state) is a direct consequence of the causal structure — gradients for queries depend only on the past, gradients for keys and values depend only on the future. The two-sweep design ensures both passes maintain the same $O(n)$ scaling and IO efficiency as the forward pass.

- **Causal mask $M$ with integrated decay:** the mask simultaneously enforces causality ($M_{ij} = 0$ for $i < j$) and exponential decay ($M_{ij} = \lambda^{i-j}$ for $i \geq j$). Combining these into a pre-computed mask avoids computing $\lambda^{i-j}$ dynamically for each attention weight and enables the Hadamard product $(QK^\top) \odot M$ to be computed as a single fused operation (multiply then mask) in the kernel.

- **Decay matrix $\Lambda$ and its inverse for KV alignment:** the $\Lambda$ factor on inter-block queries and the $\Lambda^{-1}$ factor on keys during KV updates ensure that the exponential decay exponents are correctly aligned across block boundaries. This is a bookkeeping detail that would be handled implicitly in a token-level recurrence, but becomes explicit in the block formulation. Getting this alignment right is essential for mathematical correctness — a naive implementation that omits $\Lambda^{-1}$ would apply incorrect decay exponents to inter-block attention.

## 4. Key Insights and Innovations

### Innovation 1: The Intra-Inter Block Decomposition as a Solution to the Cumsum Bottleneck, Not Just a Tiling Optimization

The dominant assumption in the linear attention literature — from the original Linear Transformer (Katharopoulos et al., 2020a) through Performer (Choromanski et al., 2020), cosFormer (Qin et al., 2022b), and Lightning Attention-1 (Qin et al., 2023b) — was that the cumulative summation required for causal masking was an implementation nuisance: something that could be worked around with better engineering (tiling, IO-awareness, fused kernels) but not something that required rethinking the computational decomposition itself. Lightning Attention-1 represented the apex of this assumption — it applied state-of-the-art IO-aware tiling (following FlashAttention's philosophy) to linear attention, yet the authors acknowledge it "does not take advantage of the computational characteristics inherent to Linear Attention, and the theoretical complexity remains O(n²d)" (Section 2.2).

Lightning Attention-2's conceptual breakthrough is recognizing that the cumsum problem is not an engineering annoyance to be tiled around — it is a **structural feature of the computation that demands a qualitatively different decomposition**. The key insight is that the left-product formulation (QK^TV, conventional attention) and the right-product formulation (Q(K^TV), linear attention) are not mutually exclusive choices for the entire sequence. They are **complementary operations that are each optimal at different scales of the attention computation**. Within a block of B tokens (where B is small and the B×B attention matrix fits in SRAM), the left product is efficient because the quadratic cost O(B²) is bounded by the constant block size. Across blocks (where the total sequence length n can be arbitrarily large), the right product is essential because it collapses the entire prefix into a fixed-size d×d state, achieving O(d²) per block rather than O(n²).

This is a fundamentally different intellectual move than prior tiling-based approaches. FlashAttention and Lightning Attention-1 both apply tiling to decompose a large computation into smaller pieces that fit in SRAM — but they compute the **same mathematical operation** within each tile as they would on the full sequence (softmax attention for FlashAttention, left-product linear attention for Lightning Attention-1). The tiling is purely an IO optimization; the mathematics is unchanged. Lightning Attention-2, by contrast, uses the block boundaries to **switch the mathematical formulation of attention itself** — from left product (within blocks) to right product (across blocks). The blocks are not just a memory management strategy; they delineate where each formulation applies.

The significance of this insight extends beyond the specific implementation. It reframes the cumsum problem from a hardware limitation ("we can't parallelize the recurrence") to an algorithmic design question ("where should we use the left product vs. the right product to maximize both parallelism and asymptotic efficiency?"). This reframing opens the door to hybrid attention mechanisms that dynamically choose their computational formulation based on sequence structure, rather than committing to one attention type for the entire model. The paper doesn't explore this generalization, but the conceptual framework — that attention formulations can be mixed within a single forward pass, with block boundaries as the switching points — is the intellectual contribution that makes such exploration possible.

Evidence for the effectiveness of this decomposition is stark in Figure 3 (upper row): Lightning Attention-2's forward and backward pass runtime grows linearly with sequence length (visually appearing nearly flat on the plot), while Lightning Attention-1 (which uses tiling but only left-product computation) still exhibits visibly upward-curving runtime. At 131K sequence length, the forward pass gap between Lightning Attention-1 and Lightning Attention-2 is approximately 4× (roughly 800ms vs. 200ms by visual estimate from Figure 3). This gap is not attributable to better IO optimization — Lightning Attention-1 was already IO-aware — but to the fundamental algorithmic difference: Lightning Attention-1 pays O(nBd) for intra-block computation across all blocks, which grows linearly in n, while Lightning Attention-2 pays O(nBd + nd²/B) with the second term (inter-block) being the dominant cost at large n. The constant throughput in Figure 1 (38,500 TGS from 1K to 92K contexts for the 400M model) is the empirical signature of true linear scaling — it demonstrates that the intra-inter decomposition eliminates the hidden quadratic dependency that survived in Lightning Attention-1's left-product-only tiling.

This is a fundamental shift rather than an incremental refinement. Prior work asked "how do we make linear attention's right product run fast on GPUs?" and answered with better engineering (IO-awareness, custom kernels). Lightning Attention-2 asks "when should we use the right product vs. the left product?" and answers with a hybrid decomposition that uses each where it's optimal. The distinction matters because it suggests that the future of efficient attention is not about picking one formulation over another, but about designing mechanisms that fluidly switch between them.

---

### Innovation 2: Maintaining a Single SRAM-Resident KV State Across Sequential Blocks as an O(1)-Memory Cross-Block Attention Mechanism

The standard approach to handling cross-block dependencies in tiled attention — used by FlashAttention and inherited by Lightning Attention-1 — is to recompute or reload information when processing each block. FlashAttention, for instance, must recompute softmax statistics across blocks because the softmax normalization couples all attention weights for a given query. This recomputation is IO-efficient (it avoids writing intermediate attention matrices to HBM) but it does not reduce the computational dependency on sequence length: each query's softmax still requires scanning all keys, even if that scanning is done incrementally.

Lightning Attention-2 introduces a fundamentally different approach to cross-block information flow: instead of recomputing or scanning, it maintains a **persistent, incrementally updated KV state** — a single d×d matrix stored in SRAM — that accumulates information from all previously processed blocks. When the algorithm moves to block i+1, it doesn't need to re-examine blocks 1 through i; it only needs the KV state, which compactly represents everything those blocks contributed. The inter-block computation for block i+1 is simply ΛQ_{i+1}(KV), a matrix multiplication between a B×d query block and a d×d state — O(Bd²) computation with no dependence on how many blocks came before.

This is conceptually distinct from the standard tiling paradigm in a way that's easy to miss. Standard tiling in attention (FlashAttention, Lightning Attention-1) is about **partitioning the computation to fit in memory** — you break a large matrix multiply into smaller pieces, compute each piece, and aggregate results. The algorithm's dependence on the full sequence length is unchanged; it just processes the sequence in manageable chunks. Lightning Attention-2's KV state is about **compressing the prefix into a fixed-size representation** — you process each block once, update a compact summary, and then never revisit that block's raw key-value pairs. The dependence on prefix length is eliminated entirely from the per-block computation; it's replaced by a dependence on the state dimension d (which is typically 64–128, constant with respect to sequence length).

The intellectual significance is that this makes cross-block attention an **O(1)-memory operation** with respect to sequence length. In FlashAttention, the memory required to compute attention includes space for the softmax statistics that must be maintained per query — this scales with sequence length (though FlashAttention's tiling keeps it in SRAM, the number of blocks processed grows with n). In GLA (Yang et al., 2023), the parallel block processing requires storing separate KV states for each block, giving memory usage of O(nd²/B) — linear in n. Lightning Attention-2 stores exactly one d×d KV state regardless of whether the sequence has 1,000 tokens or 1,000,000 tokens. At n = 131K, d = 128, this is the difference between ~32 KB (Lightning Attention-2) and tens of megabytes (GLA-style parallel states) for the cross-block attention state.

The authors explicitly flag this as a key differentiator from GLA (Section 3.2.2 Discussion): "[GLA] uses parallel computations for each block, which leads to higher memory usage." The significance is practical for very long sequences: constant memory means you can process arbitrarily long inputs without hitting a memory wall from the attention mechanism itself. The sequence length limit becomes purely a function of storing the Q, K, V, O activations (which are O(nd) regardless of attention mechanism) rather than attention-specific state.

This is an incremental refinement of the linear attention paradigm (the recursive KV formulation was already known — Equation 5 shows it), but a fundamental advance in how that paradigm is mapped to hardware. Prior linear attention implementations either (a) used the recurrence token-by-token (pure sequential, losing parallelism), (b) computed the right product in one shot for the full sequence (breaking causality), or (c) used left-product tiling (losing the asymptotic advantage). Lightning Attention-2 is the first to show that block-level sequential processing with a single persistent KV state achieves both causality (because blocks are processed left-to-right), parallelism (because all B tokens within a block are processed simultaneously), and constant memory (because only one KV state exists at a time). The evidence is Figure 3 (lower row): memory footprint grows linearly with sequence length for all methods (since Q, K, V must be stored), but Lightning Attention-2's backward memory is consistently lower than both FlashAttention-2 and Lightning Attention-1 — approximately 10 GB vs. 15 GB at 131K sequence length by visual estimate — reflecting the elimination of per-block cross-attention state.

### Innovation 3: The Backward Pass as a First-Class Citizen in Linear Attention Kernel Design, with a Symmetric Reverse-Sweep Algorithm

The attention mechanism literature — including FlashAttention-2, Lightning Attention-1, RetNet, and GLA — has focused disproportionately on optimizing the forward pass, with the backward pass either handled by automatic differentiation (relying on saved intermediates from the forward pass) or left as an engineering detail. RetNet's chunk-wise algorithm, for example, addresses only the forward pass (as the authors note: "does not consider... the backward pass"), implicitly assuming that standard autograd will handle gradient computation — which would not apply the same tiling, state maintenance, or IO optimizations.

Lightning Attention-2 treats the backward pass as a **co-designed component** with its own algorithmic structure, not merely a derivative of the forward pass to be computed by autograd. The backward algorithm (Algorithm 2) mirrors the forward pass's intra-inter decomposition but introduces a **symmetric reverse-sweep mechanism** driven by a dKV state that propagates gradient information from later blocks to earlier ones. This dKV state is the dual of the forward KV state: KV accumulates key-value pairs left-to-right for attention computation; dKV accumulates query-output-gradient pairs right-to-left for gradient computation.

The intellectual move here is recognizing that the backward pass through causal linear attention has the same structural properties as the forward pass, but in reverse. Forward: KV state accumulates past information for future queries (left-to-right dependency). Backward: dKV state accumulates future gradient information for past keys and values (right-to-left dependency). The same intra-inter decomposition applies: within a block, gradients are computed using the conventional formulation (derivatives of the B×B attention matrix); across blocks, they use the dKV state to summarize gradient information from all subsequent blocks.

What makes this significant beyond being a thorough implementation is that it **closes a gap between algorithmic complexity theory and training throughput**. In theoretical terms, linear attention has always been O(n) for both forward and backward passes — but this has never been realized in practice for the backward pass because standard implementations relied on autograd, which would materialize intermediate states that break the asymptotic scaling. The authors don't provide an ablation comparing their custom backward pass to autograd (which limits the strength of this claim), but the performance evidence indirectly supports it: Figure 3 (upper right) shows that Lightning Attention-2's backward pass maintains linear scaling (near-constant runtime visually), while Lightning Attention-1's backward pass runtime curves upward with sequence length. Since both use Triton kernels, the difference is not just implementation quality but algorithmic structure.

The two-sweep design of the backward pass — forward-order for dQ (using the stored forward KV), reverse-order for dK and dV (using the backward-propagating dKV) — is also conceptually novel. It demonstrates that the causality constraint, which creates the cumsum problem in the forward pass, creates a symmetric anti-causal dependency in the backward pass (gradients for early tokens depend on later tokens' output gradients). By handling these two dependencies with separate sweeps, each using the appropriate state (KV for forward-order, dKV for reverse-order), the algorithm achieves full parallelism within each sweep while maintaining the correct mathematical dependencies across sweeps.

This is an incremental contribution in the context of the paper (the primary innovation is the forward pass decomposition), but it addresses a real gap in the linear attention ecosystem. Prior work that claimed "linear attention is O(n)" was making a statement about forward pass FLOPs; Lightning Attention-2 makes that statement true for end-to-end training throughput, which is what practitioners actually care about. The distinction matters because training is typically 2–3× more expensive than inference (due to backward pass computation and optimizer steps), so an O(n) forward pass paired with an O(n²) backward pass would still be bottlenecked at scale.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The training corpus consists of a "uniquely assembled corpus" with 300B tokens and a separate 30B subset for benchmarking, drawn from an unspecified source. The authors do not cite a standard public dataset — they reference "our corpus" throughout Section 4, indicating a proprietary collection. For downstream evaluation (Section 4.3), they use standard benchmarks: BoolQ, PIQA, SIQA (referenced as SIQA in the text, not SocialIQA directly), HellaSwag, WinoGrande, ARC-Easy, ARC-Challenge, OpenBookQA, MMLU, and C-Eval, all evaluated through the lm-evaluation-harness framework (Gao et al., 2023). The absence of details about the training corpus composition (languages, domains, filtering criteria) limits reproducibility.

- **Base model(s).** The experiments use **TransNormerLLM** (Qin et al., 2023b), a linear-attention-based architecture, at three scales: 400M, 1B, and 3B parameters (Section 4.1, Table 1), plus a 15B-parameter variant (Section 4.3). The models integrate Lightning Attention-2 as a drop-in replacement for the attention mechanism. The paper does not specify architectural details like layer count, head count, or hidden dimensions for the 400M–3B models (these are provided only for the 15B variant: 42 layers, 40 attention heads, 5120 embedding dimension). For accuracy benchmarking on downstream tasks, a 15B-parameter TransNormerLLM with Lightning Attention-2 (TNL-LA2) is compared against Pythia-12B (Biderman et al., 2023) — not against LLaMA or other softmax-attention models at comparable scale, which is a notable omission given that the speed comparisons are all against LLaMA.

- **Metrics.** Two categories of metrics are reported, corresponding to two distinct evaluation goals:

  - **Training efficiency metrics:** Tokens per GPU per Second (TGS) measures throughput during training — how many tokens the model can process per second on a single GPU. This is the primary metric for the paper's central claim of constant-speed scaling. It is reported across sequence lengths from 1K to 92K tokens (Table 1) and for both forward and backward passes separately in the attention module evaluation (Figure 3, runtime in milliseconds).

  - **Model quality metrics:** Training loss (reported in Table 2 and Figure 4) measures next-token prediction performance on the training corpus. Downstream accuracy (reported in Table 3) measures performance on commonsense reasoning and multiple-choice benchmarks using standard evaluation protocols (accuracy, accuracy normalized, and their averages). The 15B model is evaluated at two intermediate checkpoints (50B and 100B tokens processed) rather than after full training, which is acknowledged as training-in-progress.

- **Baselines.** The paper uses three primary baselines:

  - **LLaMA with FlashAttention-2** (LLaMA-FA2): the standard softmax-attention Transformer architecture using FlashAttention-2 (Dao, 2023) as the attention kernel. This is the main speed comparison baseline. LLaMA uses Rotary Position Embedding (RoPE) and standard causal softmax attention.

  - **TransNormerLLM with Lightning Attention-1** (TNL-LA1): the predecessor linear attention implementation using tiling but with left-product-only computation within blocks, maintaining O(n²d) complexity in practice (Qin et al., 2023b).

  - For accuracy benchmarking (Section 4.3), **Pythia-12B** (Biderman et al., 2023) serves as the comparison point for the 15B TransNormerLLM variant. This is a softmax-attention model trained on the Pile dataset.

  - Additional models appear in Figure 4 loss curves: **HGRN** (Qin et al., 2023d) and **TNN** (Qin et al., 2023a), both efficient sequence modeling architectures from the same research group, used to contextualize training loss convergence.

- **Generation budget / compute accounting.** Compute is measured in terms of **throughput (TGS)** at specific model sizes, sequence lengths, and hardware configurations, not in FLOP counts. For the attention module microbenchmarks (Figure 3), runtime is measured in milliseconds for forward and backward passes in isolation on a single A100 80G GPU. For the full-model training speed benchmarks (Table 1, Figure 1), TGS is measured using 2×A100 80G GPUs at 400M and 1B scales, and at 3B scale though the specific GPU count for that configuration is not explicitly stated in the table (context from Figure 1 caption indicates larger models use more GPUs). Memory footprint is reported in gigabytes during forward and backward passes (Figure 3, lower panels). The paper does not provide a formal FLOP-counting methodology or normalize for differences in model architecture between TransNormerLLM and LLaMA (different attention mechanisms may have different FLOP-per-token costs even at the same parameter count), which complicates direct efficiency comparisons.

- **Cross-validation / statistical protocol.** The paper does not employ cross-validation or report statistical significance for any result. The 15B model evaluation (Table 3) reports results from a single training run at two intermediate checkpoints (50B and 100B tokens). The 400M model loss comparison in Table 2 reports a single number (2.228 vs. 2.229) from one training run of 100K iterations, with no variance estimate. For the loss curves in Figure 4, only a single training trajectory is shown per model with no error bars or multiple seeds. The authors note the corpus uses an "initial seed" (Section 4.2: "using the sampled corpus from our corpus with 300B tokens and initial seed") but do not specify whether multiple random seeds were evaluated. This is a significant methodological limitation — the performance differences reported (e.g., 0.001 loss difference in Table 2, 1–3% accuracy gaps in Table 3) cannot be distinguished from noise without replication.

### Main Quantitative Results

#### Training Speed: Lightning Attention-2 Achieves Constant Throughput with Increasing Sequence Length

The paper's headline result appears in Table 1 and Figure 1. For the 400M parameter TransNormerLLM with Lightning Attention-2 (TNL-LA2), the training throughput is **38,615 TGS at 1K context and 38,596 TGS at 92K context** — effectively flat, varying by less than 0.05% across a 92× increase in sequence length. This is the empirical signature of true linear scaling: the per-token computational cost is independent of total sequence length. In contrast, LLaMA with FlashAttention-2 degrades from 35,931 TGS at 1K to 4,078 TGS at 92K (an 8.8× slowdown), and TransNormerLLM with Lightning Attention-1 degrades from 41,789 TGS at 1K to 6,012 TGS at 92K (a 6.9× slowdown).

The constant-throughput property holds across model sizes, though with important qualifications. At 1B parameters, TNL-LA2 maintains approximately 20,000 TGS from 1K through 92K (20,052 at 1K, 20,186 at 92K), while LLaMA-FA2 drops from 14,897 to 3,167 and TNL-LA1 drops from 21,195 to 4,625. At 3B parameters, TNL-LA2 maintains approximately 7,550 TGS from 1K through 32K (ranging from 7,524 to 7,599), while LLaMA-FA2 drops from 7,117 to 2,558 and TNL-LA1 drops from 8,001 to 3,512. All three models run out of memory at 65K context length for the 3B scale — the constant-throughput property is constrained by GPU memory capacity for storing Q, K, V, O activations, which scale as O(nd) regardless of the attention mechanism.

A subtle but important pattern in Table 1: **Lightning Attention-2 is not always the fastest at short sequence lengths**. At 1K context, TNL-LA1 achieves higher TGS than TNL-LA2 across all three model sizes (41,789 vs. 38,615 at 400M; 21,195 vs. 20,052 at 1B; 8,001 vs. 7,524 at 3B). The crossover point where Lightning Attention-2 becomes faster is approximately 2K–4K context length. This reflects the overhead of maintaining the KV state and computing the inter-block term — at very short sequences, the intra-block computation dominates and the simpler left-product-only tiling of Lightning Attention-1 has lower overhead. Lightning Attention-2's advantage emerges as sequence length grows and Lightning Attention-1's hidden quadratic dependency begins to dominate.

#### Attention Module Microbenchmarks: Forward and Backward Pass Scaling

Figure 3 provides fine-grained runtime and memory measurements for the attention module in isolation (not the full model). The upper panels show forward and backward pass runtime in milliseconds across sequence lengths from 1K to 131K on a single A100 80G GPU.

For the forward pass: FlashAttention-2 grows from approximately 50ms at 1K to approximately 1,800ms at 131K — roughly 36× slower. Lightning Attention-1 grows from approximately 40ms to approximately 750ms — roughly 19× slower. Lightning Attention-2 grows from approximately 40ms to approximately 200ms — roughly 5× slower, but critically, the growth appears nearly linear and very shallow, with most of the increase occurring between 1K and 8K and the curve flattening thereafter. At 131K, Lightning Attention-2 is approximately 9× faster than FlashAttention-2 and approximately 3.8× faster than Lightning Attention-1.

For the backward pass: the pattern is qualitatively similar but the gaps are larger. FlashAttention-2 grows from approximately 60ms at 1K to approximately 1,900ms at 131K (32×). Lightning Attention-1 grows from approximately 50ms to approximately 1,100ms (22×). Lightning Attention-2 grows from approximately 50ms to approximately 250ms (5×). At 131K, Lightning Attention-2 is approximately 7.6× faster than FlashAttention-2 and approximately 4.4× faster than Lightning Attention-1 in the backward pass.

The backward pass advantage being larger than the forward pass advantage is noteworthy — it suggests that Lightning Attention-2's custom backward kernel (Algorithm 2) provides disproportionate benefits over autograd-based approaches, consistent with the paper's claim that prior work neglected backward pass optimization.

Memory footprint (Figure 3, lower panels): during the forward pass, Lightning Attention-2 uses approximately 8 GB at 131K vs. approximately 12 GB for FlashAttention-2 and approximately 14 GB for Lightning Attention-1. During the backward pass, the gap widens: approximately 10 GB for Lightning Attention-2 vs. approximately 18 GB for FlashAttention-2 and approximately 40 GB for Lightning Attention-1 at 131K. The backward memory advantage over Lightning Attention-1 is particularly striking (approximately 4× less memory at maximum sequence length) and reflects the elimination of per-block intermediate states that Lightning Attention-1's left-product tiling requires.

#### Model Quality: Lightning Attention-2 Matches Lightning Attention-1 in Training Loss

Table 2 reports that after 100K training iterations on a 2K-context, 300B-token corpus, a 400M-parameter TransNormerLLM with Lightning Attention-1 achieves a loss of 2.229, while the same model with Lightning Attention-2 achieves 2.228 — a difference of 0.001 in favor of Lightning Attention-2. This is reported as a "marginal performance difference" with Lightning Attention-2 showing a "performance decrement of 0.001 compared to its counterpart with Lightning Attention-1." The direction is actually a marginal improvement, not a decrement, but the magnitude is so small (0.04% relative) that it should be interpreted as identical performance — the two attention implementations produce effectively equivalent model quality.

Figure 4 extends this comparison to 1B and 3B parameter scales, showing training loss curves over 30B tokens. At 1B parameters, TNL-LA2 achieves marginally lower loss than LLaMA-FA2, HGRN, and TNN throughout training, with the gap widening slightly at later tokens (approximately 2.97 vs. 3.02 at 30B tokens by visual estimate). At 3B parameters, the pattern is similar — TNL-LA2 maintains a small but consistent advantage over the other architectures. The differences are modest (roughly 0.05–0.10 in loss at 30B tokens) and come from single training runs with no error bars, so they should be interpreted cautiously.

The key conclusion from the quality experiments is that Lightning Attention-2 is **not trading off accuracy for speed** — it achieves training loss comparable to or marginally better than both Lightning Attention-1 and FlashAttention-2-based Transformers, while providing dramatically better throughput scaling. This is essential for the "free lunch" framing: the speed gains do not come at the cost of model quality degradation.

#### Downstream Benchmarking at 15B Scale: Competitive but Not State-of-the-Art

Table 3 reports downstream task performance for TransNormerLLM-15B with Lightning Attention-2 (TNL-LA2) compared to Pythia-12B at two training stages: approximately 50B tokens and approximately 100B tokens processed. At the 100B-token checkpoint, TNL-LA2 outperforms Pythia-12B on commonsense reasoning benchmarks by approximately 2 percentage points on average (56.76 vs. 54.58), with the largest gaps on HellaSwag (61.09 vs. 58.83, a 2.26-point advantage) and ARC-Challenge (34.64 vs. 31.91, a 2.73-point advantage). On aggregated benchmarks (MMLU, C-Eval), TNL-LA2 exceeds the 25% random baseline for 4-choice questions, scoring approximately 26.5% on average across 5-shot settings, vs. Pythia-12B at approximately 24.4%.

Several important caveats attend these results. First, the comparison is between a 15B-parameter model (TNL-LA2) and a 12B-parameter model (Pythia-12B) — a 25% parameter count advantage for TNL-LA2 that confounds the architectural comparison. Second, both models are evaluated at intermediate checkpoints (50B and 100B tokens), not after full training convergence. Pythia was trained on 300B tokens total; the 100B checkpoint represents one-third of its full training budget. Third, the 15B model is trained with a sequence length of 6,144 tokens while Pythia-12B was trained with 2,048-token contexts (based on the Pythia paper), which may advantage TNL-LA2 on tasks benefiting from longer context. Fourth, the authors note "fluctuations in the 5-shot MCQ tasks, with an average MCQ score of around 26.5%," which is only marginally above the 25% random baseline and suggests the model has not yet reliably acquired the knowledge tested by MMLU and C-Eval at this training stage.

The most significant absence from Table 3 is any comparison against **LLaMA or LLaMA-2 at comparable scale** — the models that Lightning Attention-2 is benchmarked against for speed (Table 1, Figure 1) are not evaluated for accuracy. This is a conspicuous gap: the paper demonstrates that TNL-LA2 is faster than LLaMA-FA2 but does not demonstrate that it is as accurate. Without this comparison, the "free lunch" claim — that Lightning Attention-2 provides speed without accuracy loss — is only partially supported (against Lightning Attention-1 and Pythia, but not against the primary speed comparison target).

### Ablation Studies and Robustness Checks

The paper does not report formal ablation studies in the conventional sense — there is no systematic variation of block size B, decay rate λ, or architectural parameters with corresponding performance measurements. The experiments that come closest to ablation are:

- **Lightning Attention-1 vs. Lightning Attention-2 (same architecture, different attention kernel):** This is the central comparison throughout the paper and serves as an implicit ablation of the intra-inter decomposition strategy. At the attention module level (Figure 3), Lightning Attention-2 achieves approximately 3.8× faster forward pass and 4.4× faster backward pass than Lightning Attention-1 at 131K sequence length, with approximately 4× less backward memory footprint. At the full-model level (Table 1), the gap is similarly large at long sequences: at 92K context and 400M parameters, TNL-LA2 achieves 38,596 TGS vs. TNL-LA1's 6,012 TGS — a 6.4× advantage. The loss comparison (Table 2) shows equivalent quality, confirming that the speedup does not come from degraded model performance. However, this is an ablation of the implementation strategy, not of the underlying linear attention formulation — both use the same NormAttention mechanism; the difference is entirely in how it's computed on hardware.

- **Model scale ablation (400M, 1B, 3B):** Table 1 and Figure 1 demonstrate that the constant-throughput property holds across three model sizes spanning a 7.5× range in parameter count. At each scale, Lightning Attention-2 throughput is essentially flat with sequence length, while both baselines exhibit significant degradation. This suggests the intra-inter decomposition is robust to model size, though the absolute throughput naturally decreases with larger models (38,500 TGS at 400M vs. 7,550 at 3B). The upper limit on sequence length is determined by GPU memory capacity for the Q, K, V, O activations — at 3B, all methods run out of memory at approximately 65K context on the 80GB A100 GPUs used.

- **Sequence length sweep (1K to 92K):** The extensive sweep across sequence lengths in Table 1 provides empirical evidence that Lightning Attention-2's throughput is genuinely constant, not just less-degrading. At 400M, the maximum deviation from the mean TGS across all sequence lengths is approximately ±0.5%, which is within measurement noise. This is the strongest evidence for the paper's central claim — no prior linear attention implementation has demonstrated this flatness over a nearly 100× range of sequence lengths.

- **Attention module vs. full-model measurement:** Figure 3 isolates the attention module, while Table 1 measures the full model (including feed-forward layers, layer norm, embedding, etc.). The constant-throughput property appears in both, confirming that the attention mechanism — not other model components — is the bottleneck that Lightning Attention-2 addresses. In the full-model measurements, the attention module's overhead is partially masked by other operations (which scale linearly with sequence length regardless of attention mechanism), so the relative advantage over baselines is smaller than in the isolated attention benchmarks but still substantial.

- **Downstream task evaluation at 15B scale (Table 3):** This serves as an existence proof that Lightning Attention-2 can scale to production-relevant model sizes (15B parameters) while maintaining competitive downstream performance. The 1,620 TGS reported for this model at 6,144 context length provides a reference point for practitioners, though no comparative throughput numbers are given for equivalent softmax-attention models at this scale, making it impossible to assess the efficiency advantage at 15B.

**Negative result (implicit):** Lightning Attention-2 is not universally faster — at very short sequence lengths (1K–2K), Lightning Attention-1 modestly outperforms it (approximately 8% higher TGS at 400M, Table 1). This suggests the intra-inter decomposition introduces a constant-factor overhead (the inter-block computation and KV state maintenance) that only pays off when sequence length is sufficient for the asymptotic advantage to overcome the constant overhead. The paper does not discuss this crossover behavior or analyze how the crossover point scales with model size and block size B.

**Missing ablations (notable absences):**

- **Block size B:** No experiments vary the block size to show how it affects throughput and memory. The optimal B depends on SRAM capacity (which varies across GPU generations) and the tradeoff between intra-block parallelism (favors larger B) and inter-block state update frequency (favors smaller B). This is a critical hyperparameter for practitioners adopting the method.

- **Decay rate λ:** No sensitivity analysis for the exponential decay rate, which controls the inductive bias toward local vs. global attention. Different λ values may affect both model quality and the computational efficiency (extreme λ values could lead to near-zero entries that create sparsity opportunities).

- **Multiple random seeds:** The loss comparisons (Table 2, Figure 4) use single training runs, so the reported differences of 0.001 in loss cannot be distinguished from training noise.

- **Long-context downstream tasks:** Despite the paper's emphasis on "unlimited sequence length," all downstream evaluations (Table 3) use standard benchmarks that do not require long-context reasoning. There are no experiments on long-document QA, multi-turn conversation modeling, or other tasks where the ability to train on 92K-length sequences would plausibly improve performance.

### Critical Assessment

#### Central Claim: Lightning Attention-2 realizes linear attention's theoretical computational benefits, maintaining constant training speed regardless of input sequence length

**The evidence for throughput constancy is strong and well-measured.** Table 1 shows TGS varying by less than 1% from 1K to 92K context at 400M parameters (38,615 to 38,596 TGS), and similarly flat curves at 1B and 3B scales. Figure 3's attention module microbenchmarks confirm that the constant-throughput property holds for both forward and backward passes in isolation, extending to 131K sequence length where the full model measurements are memory-constrained. The contrast with FlashAttention-2 (8.8× slowdown over the same range) and Lightning Attention-1 (6.9× slowdown) is unambiguous. This is the first demonstration in the literature of genuinely constant per-token training cost for a linear attention mechanism across nearly two orders of magnitude of sequence length, and it represents the paper's primary contribution.

However, there are important boundary conditions on this claim that the paper acknowledges but does not quantify. The constant-throughput property holds only while the sequence fits in GPU memory — at 3B parameters on 80GB A100s, all methods run out of memory at approximately 65K context (Table 1, "OOM" entries). The memory constraint comes from storing the Q, K, V, O activations (which are O(nd) and identical across attention mechanisms), not from the attention computation itself. Lightning Attention-2's memory advantage (approximately 2× less than FlashAttention-2 during backward pass at 131K in Figure 3) pushes the OOM boundary to slightly longer sequences but does not eliminate it. The "unlimited sequence length" in the title and abstract is therefore qualified by hardware memory constraints, which the paper notes in a footnote: "the sequence length may still be limited by hardware constraints, such as the GPU memory." This is an important qualifier that tempers the universal-sounding claim in the title.

Additionally, the constant-throughput property is demonstrated only for training on TransNormerLLM with the specific NormAttention formulation. The paper does not evaluate whether the Lightning Attention-2 kernel generalizes to other linear attention variants (Performer, cosFormer, Linear Transformer) or to softmax attention with linearized approximations. The claim is about "linear attention" broadly but the evidence is for one specific linear attention architecture.

The comparison with FlashAttention-2, while favorable, has an apples-to-oranges dimension: LLaMA with FlashAttention-2 computes full softmax attention, which has different expressive properties than linear attention. The paper does not control for the attention mechanism when comparing speed — it compares a linear-attention model with an optimized linear-attention kernel against a softmax-attention model with an optimized softmax-attention kernel. This conflates two differences (attention type and kernel quality). A tighter comparison would benchmark Lightning Attention-2 against the same TransNormerLLM model using FlashAttention-style tiling of the left-product formulation (i.e., Lightning Attention-1) — which the paper does — and also against an implementation of linear attention using the right-product formulation with naive cumsum. This latter baseline is absent and would directly quantify how much of the improvement comes from the decomposition strategy vs. from IO-awareness alone.

#### Claim: Lightning Attention-2 is a "free lunch" — it provides speed without sacrificing accuracy

**The evidence for equivalent quality against Lightning Attention-1 is convincing but minimal.** Table 2 shows a 0.001 loss difference (2.228 vs. 2.229) at 400M scale after 100K iterations, which is within training noise for a single run. Figure 4 shows that TNL-LA2 achieves marginally lower loss than LLaMA-FA2, HGRN, and TNN at 1B and 3B scales, suggesting that the linear attention architecture itself (not just the kernel) can be competitive with softmax attention in terms of training loss. However, training loss on the pretraining corpus is an imperfect proxy for downstream capability — models with similar perplexities can differ substantially on reasoning benchmarks.

**The evidence for competitive downstream accuracy is weak and incomplete.** Table 3 compares a 15B-parameter TransNormerLLM with Lightning Attention-2 against a 12B-parameter Pythia model at intermediate checkpoints (50B and 100B tokens). The 25% parameter count advantage for TNL-LA2, combined with different training data (proprietary corpus vs. the Pile), different context lengths (6,144 vs. 2,048), and intermediate (not final) checkpoints, makes this comparison insufficient to establish competitive quality. The most consequential absence is **any accuracy comparison against LLaMA or LLaMA-2 at matched parameter counts** — the models that Lightning Attention-2 is shown to dramatically outperform in training speed (Table 1). Without demonstrating that TNL-LA2 matches LLaMA's accuracy, the speed comparison is of limited practical value: faster training is only useful if the resulting model is equally capable. The paper implicitly acknowledges this limitation by not including LLaMA in Table 3 and by noting that the 15B model's MMLU/C-Eval performance hovers near random baseline levels.

The "free lunch" framing — suggesting that Lightning Attention-2 provides speed benefits without any tradeoffs — is therefore not fully established. The paper demonstrates a **throughput free lunch** (faster training without loss degradation compared to Lightning Attention-1), but the **capability free lunch** (faster training without downstream accuracy degradation compared to softmax attention) remains unsubstantiated. This is the most significant gap in the experimental evaluation.

#### Claim: Lightning Attention-2 enables training on unlimited sequence lengths with no additional cost

This claim contains two separable assertions. The first — that Lightning Attention-2 maintains constant per-token cost — is supported by Table 1 and Figure 3. The second — that this enables training on sequences longer than what softmax attention can handle — is partially supported by the throughput data but not by any demonstration of improved model quality from longer-context training.

The paper does not train any model on sequences longer than 92K tokens or show that models trained with longer contexts on Lightning Attention-2 outperform models trained with shorter contexts. All accuracy evaluations (Table 3) use the standard benchmarks, none of which require or benefit from the 6,144-token context length used for the 15B model. The paper's framing emphasizes the potential for "extended conversations in various professional domains and handling a vast number of tokens in multimodal modeling tasks" (Section 1), but provides no evidence that Lightning Attention-2 enables better performance on such tasks.

This is a missed opportunity. A natural experiment would be to train two TransNormerLLM models — one with Lightning Attention-2 at a long context length (e.g., 32K or 64K), one with FlashAttention-2 at a shorter context length that achieves comparable training throughput — and compare them on a long-context benchmark (e.g., long-document QA, needle-in-haystack retrieval). This would directly test whether Lightning Attention-2's constant throughput translates to improved long-context capabilities within a fixed training budget. The paper's failure to include such an experiment limits the strength of its practical claims.

#### Missing Baselines and Comparisons

Several baselines that would clarify the contribution are absent:

- **Pure right-product linear attention with naive cumsum:** This would quantify the overhead that the intra-inter decomposition eliminates. Without it, the improvement over Lightning Attention-1 cannot be decomposed into "better IO-awareness" vs. "better algorithmic structure."

- **LLaMA accuracy at matched parameter count:** Essential for the "free lunch" claim. The paper compares speed against LLaMA but accuracy only against Pythia, which has a different architecture and training recipe.

- **RetNet and GLA:** These are discussed as related work (Section 3.2.2) but never benchmarked against. Comparisons would contextualize Lightning Attention-2 within the broader landscape of efficient attention mechanisms.

- **Multiple training seeds:** All training results are from single runs. The 0.001 loss difference in Table 2 and the modest gaps in Figure 4 cannot be interpreted as reliable without variance estimates.

- **Standard deviation or confidence intervals:** None of the throughput or accuracy measurements include error bars. The TGS numbers in Table 1 are reported to five significant figures (e.g., 38,615), implying a precision that is unlikely to be reproducible without variance characterization.

#### Generalizability Concerns

All experiments use TransNormerLLM, a specific linear attention architecture with the NormAttention formulation and exponential decay. The paper does not demonstrate that Lightning Attention-2 works with other linear attention variants (e.g., Performer's random features, cosFormer's cosine-based kernel, or gated variants like GLA). The tiling strategy and KV-state maintenance are formulated in terms of the specific decay structure (λ^{t-s}), and it's not obvious that they generalize to linear attention mechanisms without exponential decay or with data-dependent gating.

The implementation is in Triton and tested exclusively on A100 80G GPUs. Performance characteristics may differ on other hardware (H100 with larger SRAM, consumer GPUs with different memory hierarchies, TPUs with entirely different parallelism models). The block size B is implicitly tuned for A100 SRAM capacity; the paper provides no guidance for adapting it to other hardware.

#### Summary Assessment

The paper makes a genuine systems contribution — the first demonstration of linear attention achieving constant per-token training throughput across a wide range of sequence lengths — and the engineering behind the intra-inter decomposition is clever and well-executed. The throughput results in Table 1 and Figure 3 are unambiguous and represent a meaningful advance over Lightning Attention-1.

However, the experimental evaluation has significant gaps that qualify the paper's broader claims. The "free lunch" assertion requires demonstrating both speed equivalence and accuracy equivalence against softmax attention models, and the paper only establishes the former (speed vs. LLaMA) and the latter only weakly (accuracy vs. Pythia at different scales and intermediate checkpoints). The absence of long-context downstream task evaluation means the practical benefit of training on longer sequences — the ostensible motivation for the entire approach — is asserted rather than demonstrated. The single-seed, single-corpus, single-architecture nature of all experiments limits confidence in generalizability.

The paper is best understood as a **systems demonstration** that linear attention's theoretical advantages can be realized on GPU hardware through careful algorithm-hardware co-design, not as evidence that Lightning Attention-2-equipped models are ready to replace softmax-attention Transformers in production. The "unlimited sequence length" framing should be tempered to "constant-throughput training for sequence lengths that fit in GPU memory," which is a substantial advancement but not the capability breakthrough the title suggests.

## 6. Limitations and Trade-offs

### 6.1 Downstream Accuracy Against Softmax-Attention Transformers Is Not Established

**The assumption or constraint:** The paper demonstrates that TransNormerLLM with Lightning Attention-2 (TNL-LA2) trains substantially faster than LLaMA with FlashAttention-2 across sequence lengths — the core speed claim — but never evaluates whether TNL-LA2 achieves competitive downstream accuracy against LLaMA at matched parameter counts. The only accuracy comparison in Table 3 is against Pythia-12B, a model with 25% fewer parameters (15B vs. 12B), trained on different data (proprietary corpus vs. the Pile), at different context lengths (6,144 vs. 2,048), and evaluated at intermediate checkpoints (50B and 100B tokens) rather than after full training. The paper does not acknowledge this as a limitation — it presents the Pythia comparison as sufficient evidence of competitive quality without commenting on the absence of LLaMA comparisons in Table 3.

**The consequence:** The "free lunch" framing collapses if TNL-LA2 does not match LLaMA's accuracy. The paper's central practical value proposition is: use linear attention with Lightning Attention-2 instead of softmax attention with FlashAttention-2, and you get dramatically better throughput scaling without sacrificing model quality. The speed half of this proposition is well-established (Table 1, Figure 1, Figure 3). The quality half is unsubstantiated against the primary speed comparison target. A practitioner choosing between training a LLaMA-style model with FlashAttention-2 and a TransNormerLLM with Lightning Attention-2 has no basis in this paper for estimating the accuracy tradeoff. It is entirely possible that the linear attention formulation in TransNormerLLM — which dispenses with softmax and uses exponential decay — underperforms softmax attention on certain reasoning tasks, knowledge-intensive benchmarks, or long-context evaluations. The paper provides no evidence either way.

**What evidence exists in the paper:** The accuracy evidence that does exist is thin and confounded. Table 2 shows a 0.001 loss difference between Lightning Attention-1 and Lightning Attention-2 at 400M scale — this establishes kernel equivalence (the two implementations produce near-identical models) but says nothing about the attention mechanism's quality relative to softmax. Figure 4 shows TNL-LA2 achieving marginally lower training loss than LLaMA-FA2 at 1B and 3B scales — but training loss on a proprietary corpus is a weak proxy for downstream capability, and the identical-training-loss regime at 30B tokens is far from convergence for models of this scale (LLaMA-1B was trained on 1T+ tokens). The 15B model in Table 3 achieves only ~26.5% average on MMLU/C-Eval 5-shot — barely above the 25% random baseline for 4-choice tasks, suggesting the model at 100B tokens has not yet reliably acquired the knowledge these benchmarks test.

**Mitigation status:** Not addressed at all. The paper does not acknowledge the absence of LLaMA accuracy comparisons, does not explain why Pythia was chosen instead, and does not state plans to evaluate against LLaMA in future work. The 15B model is described as still training ("the comprehensive pre-training phase is scheduled to span three months"), so final accuracy numbers may emerge later, but the current paper makes strong practical claims without corresponding accuracy evidence.

### 6.2 Constant Throughput Is Memory-Bound at Long Sequence Lengths — "Unlimited" Requires Hardware That Does Not Yet Exist

**The assumption or constraint:** The paper's title claims "Handling Unlimited Sequence Lengths," and the abstract states the method "can train LLMs with unlimited sequence length without extra cost." However, the constant-throughput property holds only while the Q, K, V, O activation matrices — which scale as O(nd) regardless of attention mechanism — fit in GPU memory. The paper acknowledges this in a footnote: "the sequence length may still be limited by hardware constraints, such as the GPU memory." At 3B parameters on 80GB A100 GPUs, all methods (including TNL-LA2) run out of memory at approximately 65K context (Table 1, OOM entries). Even with Lightning Attention-2's memory advantage (approximately 2× less than FlashAttention-2 during backward pass at 131K, Figure 3 lower right), the activation memory grows linearly with sequence length and will eventually exceed any fixed GPU memory budget.

**The consequence:** The "unlimited" framing is misleading in practice. For a 3B model on current high-end hardware (80GB A100), the practical sequence length ceiling is ~65K tokens — roughly 4× longer than FlashAttention-2's ceiling at the same model size (~32K before OOM), but far from "unlimited." The ceiling becomes more restrictive for larger models (the 15B variant is trained at only 6,144 context, not the 92K lengths demonstrated at 400M scale) and for practitioners with less GPU memory (consumer GPUs, older datacenter GPUs). Multi-GPU tensor parallelism or sequence parallelism could extend this, but the paper does not implement or evaluate such strategies — it mentions "sequence parallelism" as future work (Section 5 Conclusion) but provides no measurements.

**What evidence exists in the paper:** Table 1 directly shows the memory ceiling: at 3B parameters, all three model variants hit OOM between 32K and 65K context on 2×A100 80G. The 400M and 1B models reach 92K without OOM, demonstrating that the ceiling scales inversely with model size. Figure 3 (lower panels) quantifies memory footprint: Lightning Attention-2 forward pass uses ~8 GB at 131K, backward pass ~10 GB. Extrapolating linearly: at 262K context, forward pass would need ~16 GB, backward ~20 GB, plus parameter storage — likely exceeding 80GB for a 1B+ model.

**Mitigation status:** Partially acknowledged (footnote about hardware constraints, future work on sequence parallelism) but not solved. The paper's rhetoric ("unlimited sequence length") dramatically overstates what the current implementation actually delivers. A more accurate characterization would be "constant-throughput training up to the GPU memory ceiling, which is substantially higher than FlashAttention-2's ceiling at the same model size." The sequence parallelism suggestion in the conclusion is a direction, not a solution — it would distribute activations across GPUs, trading communication overhead for increased capacity, but the paper provides no implementation or analysis of this tradeoff.

### 6.3 No Evidence That Longer-Context Training Improves Model Capabilities

**The assumption or constraint:** The entire motivation for Lightning Attention-2 is that it enables training on much longer sequences than softmax attention, which should unlock capabilities requiring long-range reasoning. The paper explicitly cites "extended conversations in various professional domains and handling a vast number of tokens in multimodal modeling tasks" (Section 1) as motivating applications. However, no experiment in the paper tests whether training with longer contexts actually improves any model capability. The 15B model is trained at 6,144 context — only 3× longer than the 2K contexts used for the loss comparisons in Table 2 and Figure 4 — and all downstream evaluations (Table 3) use standard benchmarks (BoolQ, PIQA, HellaSwag, MMLU, etc.) that do not require or benefit from long-context reasoning.

**The consequence:** The paper demonstrates that Lightning Attention-2 makes long-context training **feasible** (by maintaining constant throughput) but provides no evidence that long-context training is **useful** (by improving model quality on tasks that require it). A skeptical practitioner could conclude: "I can train on 92K contexts at the same per-token speed as 1K contexts, but you haven't shown me that doing so produces a better model — maybe the model can't effectively use 92K tokens of context anyway." This gap is especially consequential because prior work on linear attention models has shown that they sometimes struggle with long-range dependency learning compared to softmax attention, and the exponential decay mechanism in TransNormerLLM (controlled by λ) may inherently limit very-long-range information retention regardless of context length.

**What evidence exists in the paper:** None. There are zero experiments on long-context benchmarks (e.g., LongBench, SCROLLS, needle-in-haystack retrieval, long-document QA). The only evaluation of downstream quality (Table 3) uses standard-length tasks. The training loss curves in Figure 4 are at 2K context length.

**Mitigation status:** Not addressed or acknowledged. The paper treats the ability to train on long sequences as an end in itself, not as a means to improve model capabilities. This is a significant omission for a paper whose title emphasizes "handling unlimited sequence lengths." The authors do not suggest future work on long-context evaluation.

### 6.4 Single Architecture, Single Attention Formulation — Generalizability to Other Linear Attention Variants Is Unproven

**The assumption or constraint:** All experiments use TransNormerLLM with the specific NormAttention formulation (Equation 1–2): linear attention with exponential decay λ^{t-s} and a normalization operator. The lightning Attention-2 kernel is derived specifically for this formulation — the intra-block mask M encodes exponential decay, the inter-block Λ and Λ^{-1} matrices are defined in terms of λ, and the KV state propagation uses λ^B decay. The paper frames its contribution as enabling "linear attention" broadly (abstract, Section 1) and surveys multiple linear attention variants (Section 2.1: Performer, cosFormer, Linear Transformer, sampling-based approaches), but never demonstrates that the tiling strategy works for any formulation other than NormAttention.

**The consequence:** The paper's claims about "linear attention" writ large may not hold for other variants. Many linear attention mechanisms use different kernel functions or gating mechanisms that do not factor neatly into the intra-inter decomposition. For example, Performer's random Fourier features produce positive kernel values that don't have a natural exponential decay structure; GLA uses data-dependent gating that varies per token, which would require recomputing the Λ mask dynamically rather than using a pre-computed static M; cosFormer uses cosine-based re-weighting without an explicit decay parameter. Adapting Lightning Attention-2 to these variants would require re-deriving the intra-block mask, inter-block alignment factors, and KV state update rule — it is not a drop-in replacement. A practitioner using a different linear attention architecture cannot assume they will see the same constant-throughput scaling.

**What evidence exists in the paper:** None — all experiments are with TransNormerLLM's NormAttention. The paper discusses GLA and RetNet in the Discussion (Section 3.2.2) but only to contrast design choices (parallel vs. sequential blocks, IO-awareness, backward pass handling), not to demonstrate compatibility or benchmark performance. The kernel is implemented for one specific attention formulation.

**Mitigation status:** Not addressed. The paper does not discuss how to adapt the kernel to other linear attention variants, does not provide an abstraction or interface that would make such adaptation straightforward, and does not test even one alternative formulation. The broad framing ("the first linear attention implementation that enables linear attention to realize its theoretical computational benefits") implies generality that is not empirically supported.

### 6.5 No Statistical Replication — All Results Are from Single Runs Without Variance Estimates

**The assumption or constraint:** Every quantitative result in the paper comes from a single experimental run. The 400M loss comparison (Table 2) reports 2.228 vs. 2.229 from one training run of 100K iterations. The loss curves in Figure 4 show single trajectories per model with no error bars or confidence bands. The downstream evaluations in Table 3 report point estimates from one training run at two checkpoints. The throughput numbers in Table 1 are reported to five significant figures (e.g., 38,615 TGS) with no indication of run-to-run variance. The paper provides no information about whether experiments were repeated, whether different random seeds produce consistent results, or whether the reported numbers are averages across runs.

**The consequence:** The paper's key performance comparisons cannot be distinguished from noise. The 0.001 training loss difference between Lightning Attention-1 and Lightning Attention-2 (Table 2) — presented as evidence that the two kernels produce equivalent models — could easily be reversed in a replicate run. The loss curve gaps between TNL-LA2 and LLaMA-FA2 in Figure 4 (~0.05 loss at 30B tokens) may or may not be reliable without variance characterization. The downstream accuracy gaps in Table 3 (e.g., 56.76 vs. 54.58 average commonsense reasoning at 100B tokens) have unknown stability. For a systems paper making strong efficiency claims, the absence of any statistical rigor is a notable methodological weakness, especially since the paper is effectively arguing for the adoption of a new attention kernel in production training pipelines, where reliability and reproducibility matter.

**What evidence exists in the paper:** The raw numbers in Tables 1–3 and Figures 1, 3–4 are all presented without variance estimates. The authors mention using an "initial seed" for the training corpus sampling (Section 4.2) but do not indicate whether multiple seeds were evaluated. There is no discussion of measurement methodology for TGS (how many steps were averaged, whether warmup was excluded, whether measurements were taken from a single run or multiple runs).

**Mitigation status:** Not addressed or acknowledged. The paper provides no error analysis, no discussion of reproducibility, and no information about how many runs underlie the reported numbers. In fairness, this level of replication is common in systems papers where training large models multiple times is computationally prohibitive, but the paper should at minimum acknowledge this limitation and characterize measurement noise for the throughput benchmarks (which are cheap to repeat).

### 6.6 Latency vs. Throughput Tradeoff Is Not Discussed — Sequential Block Processing May Increase Wall-Clock Time for Inference

**The assumption or constraint:** Lightning Attention-2's forward pass processes blocks sequentially — block 1, then block 2, then block 3, etc. — with each block depending on the KV state from the previous block. Within each block, the B tokens are processed in parallel, but there are T = n/B sequential block steps. During training, this sequential dependency is usually hidden by the fact that the GPU is processing multiple sequences in a batch simultaneously, so the block-level sequential steps for different batch elements can overlap or be pipelined. At inference time with batch size 1 (the typical deployment scenario for autoregressive generation), the block-level sequential dependency becomes a hard latency constraint: generating the (t+1)-th block's output requires waiting for the t-th block's KV state update to complete. The paper reports throughput (TGS) throughout but never measures or discusses latency — the wall-clock time to process a single sequence end-to-end.

**The consequence:** For inference workloads — interactive chatbots, real-time translation, code completion — latency matters at least as much as throughput. A method that achieves excellent throughput by processing large batches but has poor per-sequence latency may be unsuitable for interactive deployment. FlashAttention-2, by contrast, can process attention in parallel across sequence positions (within the constraints of causal masking), potentially offering lower latency at short-to-medium sequence lengths despite worse throughput scaling. The paper provides no information about whether Lightning Attention-2's block-sequential design introduces latency penalties relative to FlashAttention-2 for individual sequences, particularly at sequence lengths where FlashAttention-2's quadratic scaling has not yet made it prohibitively slow (e.g., 1K–8K contexts, which cover most current production deployments).

**What evidence exists in the paper:** None. All measurements are throughput (TGS), which is appropriate for training but insufficient for characterizing inference performance. The attention module runtimes in Figure 3 are measured for full forward/backward passes (not per-token latency), and they use the full sequence length — these are training-style measurements, not autoregressive generation measurements. The paper does not benchmark inference latency for generating a single token given a prefix, nor does it measure time-to-first-token or per-token generation latency for autoregressive decoding.

**Mitigation status:** Not addressed at all. The paper focuses exclusively on training throughput and does not discuss inference latency, the batch-size-1 regime, or the tradeoff between parallel processing within blocks and sequential dependency across blocks. This is a significant gap given the paper's emphasis on "unlimited sequence length" applications, many of which (conversational AI, document analysis) are inference-dominated. The claimed advantage for inference — "constant computation complexity of O(d²) irrespective of sequence length, thereby enabling inference over unlimited long sequences" (Section 3.1) — is stated as a theoretical property but never measured or demonstrated on hardware.
