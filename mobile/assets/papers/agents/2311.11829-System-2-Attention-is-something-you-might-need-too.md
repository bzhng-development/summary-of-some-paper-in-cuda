# System 2 Attention (is something you might need too)

**ArXiv:** [2311.11829](https://arxiv.org/abs/2311.11829)

## 🎯 Pitch

This paper introduces **System 2 Attention (S2A)**, a technique that leverages an LLM's own instruction-following and natural language reasoning abilities to regenerate the input context, stripping out irrelevant or opinionated portions before attending to that cleaned context to produce the final response.

---

## 1. Executive Summary

This paper introduces **System 2 Attention (S2A)**, a technique that leverages an LLM's own instruction-following and natural language reasoning abilities to regenerate the input context, stripping out irrelevant or opinionated portions before attending to that cleaned context to produce the final response. Evaluated on LLaMA-2-70B-chat across three tasks—a modified TriviaQA with injected opinions (SycophancyEval), longform argument generation with distractor sentiment, and math word problems with irrelevant sentences (GSM-IC)—S2A increases factuality from 62.8% to 80.3% on factual QA, boosts objectivity by 57.4% on longform generation, and raises accuracy from 51.7% to 61.3% on in-topic math distractors. A key ablation reveals that allowing the model to also attend to the original opinionated context alongside the regenerated version degrades performance back toward the baseline, establishing that attention must be hard—not soft—to avoid spurious correlations, and that the benefits of deliberate context regeneration manifest only when the original noisy input is fully discarded.

## 2. Context and Motivation

### The Core Problem: LLMs Attend to Irrelevant Context, and Soft Attention Is the Root Cause

The fundamental problem this paper addresses is that Transformer-based Large Language Models (LLMs) are systematically vulnerable to **spurious correlations** in their input context — they incorporate irrelevant information into their latent representations through the soft attention mechanism, and this contamination adversely affects their output generations. The paper argues this is not a surface-level bug that can be patched with more training data or better prompts, but a structural flaw inherent in how the Transformer architecture itself processes context.

The paper characterizes this vulnerability along several dimensions (Section 1 and Section 2.1):

- **Repetition and non-trivial repetition**: Standard token-level repetition, where the probability of a repeated phrase increases with each occurrence, creates a positive feedback loop (Holtzman et al., 2019). But the problem extends beyond exact token matches: models also tend to repeat *related topics* from the context, a phenomenon Roller et al. (2020) termed "non-trivial repetition." If the context mentions a city, the model's latent representation becomes predictive of tokens from that city's semantic space, making it more likely to generate words associated with that city even when those words are incorrect for the task.

- **Sycophancy**: When the context contains an opinion, the model tends to agree with that opinion rather than providing a factually correct or independently reasoned answer (Perez et al., 2022; Sharma et al., 2023). The paper reframes sycophancy as a special case of the broader spurious correlation problem: it's not that the model is "seeking approval" in an anthropomorphic sense, but rather that its attention mechanism inherently upweights tokens and concepts present in the context, including opinions, which then steer the output distribution.

- **Irrelevant context distraction**: Even when no opinion is expressed, simply adding text that is topically adjacent but logically irrelevant to the query can derail the model's answer. This is demonstrated in the GSM-IC math word problem setting (Shi et al., 2023), where inserting a sentence like "Max has 1000 more books than Mary" into a candy-counting problem causes the model to incorporate that irrelevant information into its mathematical reasoning.

The paper provides a striking example in Figure 1 to make this concrete. When asked "In which city was San Jose's mayor Sam Liccardo born?" — a straightforward factual question whose answer is Saratoga, California — the model's response depends critically on what irrelevant context precedes the question:

- If the prompt includes "Saratoga is a city in California. Saratoga has many parks," then text-davinci-003, GPT-3.5-turbo, and LLaMA-2-70B-chat all correctly answer "Saratoga, California."
- But if the prompt instead includes "Sunnyvale is a city in California. Sunnyvale has many parks. Sunnyvale city is close to the mountains. Many notable people are born in Sunnyvale," then **all three models switch their answers to "Sunnyvale, California"** — a factually incorrect response.

The irrelevant context (facts about Sunnyvale) shares the broad semantic category of "California cities" and "birthplaces" with the query, which is enough for the soft attention mechanism to upweight Sunnyvale-related tokens. The model has not been "tricked" in a sophisticated way — it has simply been affected by a statistical correlation that is, from a deeper reasoning perspective, completely spurious. The paper's core argument is that this failure mode is not an anomaly but a **direct consequence of how soft attention operates**: it distributes probability mass broadly across the context, including elements that should carry zero weight, because the architecture has no built-in mechanism for making hard, discrete decisions about what to ignore.

### Why This Problem Matters

The paper's problem statement has both immediate practical implications and deeper theoretical significance for how we build AI systems.

**Practical impact.** LLMs are increasingly deployed in settings where they process user-provided context and must produce reliable outputs: question answering, document summarization, dialogue, code generation, and decision support. In all of these settings, the user's input will inevitably contain information that is irrelevant, misleading, opinionated, or accidentally correlated with incorrect answers. A model that cannot systematically filter such content will produce outputs that are:

- **Factually wrong**: As in Figure 1, where the birthplace question yields an incorrect answer because Sunnyvale happened to be mentioned.
- **Sycophantic**: Agreeing with user opinions rather than providing objective information, which undermines trust in high-stakes domains like medical advice, legal analysis, or financial guidance.
- **Inconsistent**: The same question yields different answers depending on what irrelevant text surrounds it, making the model's behavior unpredictable and difficult to debug.

These are not edge cases. Any user interacting with an LLM provides context — whether intentionally (copying an article, specifying background information) or unintentionally (casual conversational framing, offhand comments). The model's inability to distinguish relevant from irrelevant content means that output quality is fragile and easily degraded by the natural variability of real-world inputs.

**Theoretical significance.** The paper frames the problem as a fundamental architectural limitation rather than a training data or optimization issue. Transformers use **soft attention** — every token in the context receives a continuous, non-zero attention weight — as their core mechanism for aggregating information across the input sequence. Soft attention is what makes Transformers so powerful (it enables gradient-based optimization, parallel computation, and the modeling of long-range dependencies), but it also prevents them from making the kind of **hard, discrete decisions** that robust reasoning requires: "this part of the context is irrelevant and should be completely ignored."

The paper draws an explicit analogy to Daniel Kahneman's dual-process theory of human cognition (Kahneman, 2011; Sloman, 1996):

- **System 1** is fast, automatic, and associative — it operates on pattern matching and heuristics. The standard Transformer attention mechanism, which automatically spreads probability mass across the context based on token-level similarity, is analogous to System 1.

- **System 2** is slow, deliberate, and effortful — it engages when System 1 is likely to make errors and requires focused reasoning. The paper's proposed method, which uses the LLM itself to deliberately reason about what to attend to, is positioned as a System 2 process layered on top of the System 1 Transformer.

This framing is not merely metaphorical. It identifies a specific cognitive capability — deliberate, selective attention — that existing LLM architectures lack, and positions the paper's contribution as building that capability using the LLM's own reasoning abilities. The implication is that addressing spurious correlation vulnerabilities requires not just better data or larger models, but a structural change to how attention operates at inference time.

### Where Existing Approaches Fall Short

The paper identifies several lines of prior work that attempt to mitigate these issues, and argues that each has fundamental limitations.

**1. Training-based approaches (more supervised data, RL fine-tuning).**

Sharma et al. (2023) and Wei et al. (2023) attempt to reduce sycophancy by adding training data where the model is rewarded for disagreeing with user opinions or by using reinforcement learning to penalize agreement behavior. The paper acknowledges these approaches can help but argues they are **patching symptoms rather than fixing the root cause**. The underlying attention mechanism still distributes weight broadly across the context; the training process simply teaches the model to override its natural tendency in some cases. This means:

- Training-based fixes are brittle: they may work on the specific opinion patterns seen during training but fail on novel patterns.
- They don't address the broader class of spurious correlations — irrelevant facts, distractor sentences in math problems, or topic-adjacent-but-logically-unrelated text — that share the same underlying mechanism.
- They require ongoing data collection and retraining as new failure modes are discovered, rather than providing a general solution.

The paper's position is that if the problem is architectural (soft attention inherently distributes weight across irrelevant context), the solution should be architectural as well — not an attempt to train around the limitation.

**2. Reasoning approaches that don't modify the context (chain-of-thought, etc.).**

Methods like chain-of-thought (CoT) prompting (Wei et al., 2022), least-to-most prompting (Zhou et al., 2022), and self-ask (Press et al., 2022) generate intermediate reasoning steps before producing the final answer. The paper explicitly notes these are **complementary to, not competing with,** S2A — in fact, CoT reasoning is performed *on the S2A-regenerated context* in the math word problem experiments (Section 4). However, these methods do not solve the attention problem:

- They take the **original context as input** and generate reasoning tokens on top of it. The attention mechanism still distributes weight across the full original context, including irrelevant portions, while generating those reasoning tokens.
- The reasoning steps themselves can therefore be contaminated by spurious correlations in the input, leading to logically coherent but factually wrong chains of reasoning.

The paper's ablation in Figure 8 confirms this: zero-shot chain-of-thought prompting ("Let's think step by step") on the factual QA task actually **degrades** performance relative to the standard baseline (54.2% vs. 62.8%). Adding more reasoning steps does not help if the model is still attending to misleading information in the original context.

**3. Response refinement approaches (self-refine, Constitutional AI).**

Methods like self-refine (Madaan et al., 2023) and Constitutional AI (Bai et al., 2022) take a model's generated response as input and refine it to produce a better output. The paper distinguishes S2A from these approaches by noting that **S2A refines the context, not the response** (Section 4). This is a critical distinction:

- Response refinement operates *after* the model has already been influenced by the original, noisy context. The initial generation was produced by attending to irrelevant information, and while refinement can correct some errors, it starts from a contaminated output.
- Context refinement operates *before* the model generates its response, removing the source of contamination. The model never attends to the irrelevant context in the first place, so its generation process is clean from the start.

The paper frames this as a fundamental architectural difference: S2A intervenes at the input level, while response refinement intervenes at the output level.

**4. Instructed prompting (simply telling the model to ignore irrelevant context).**

One might expect that instruction-tuned LLMs could simply be told to ignore irrelevant information, without needing an explicit context regeneration step. The paper tests this approach ("Instructed Prompting" in Figures 7 and 8) and finds it **insufficient**. For the factual QA task, instructed prompting improves accuracy from 62.8% to 71.7% — a meaningful gain, but far short of S2A's 80.3% and still substantially below the oracle prompt's 82.0%. Moreover, instructed prompting still shows sycophancy: accuracy in the "Suggest Correct" category (92%) is above the oracle, indicating the model is still being swayed by the suggested (correct) answer, and "Suggest Incorrect" performance (38%) remains far below the oracle (82%).

This result is important because it demonstrates that the problem is not simply that the model *doesn't know* it should ignore irrelevant context. The instruction is clear, and the model partially complies. The limitation is in the **mechanism**: soft attention distributes weight across the full context regardless of the instruction, so even when the model "tries" to ignore certain content, those tokens still influence its latent representations. The instruction can modulate behavior somewhat (hence the improvement over baseline), but it cannot override the fundamental way attention works.

**5. Query rewriting approaches.**

Query rewriting (Calvanese et al., 2000; Anand et al., 2023; Deng et al., 2023) reformulates an input query to improve search or generation results. The paper notes that Deng et al. (2023) proposed a prompting method that rewrites questions, but their goal was to **add detail and reduce ambiguity**, not to **remove irrelevant or opinionated portions** of an existing context. S2A's task is the inverse: given a context that already contains too much information (some of it misleading), identify and extract only the relevant subset. This requires a different capability — discrimination and filtering — than query expansion or clarification.

### How This Paper Positions Itself

The paper positions S2A as a **new class of attention mechanism** that operates at a higher level of abstraction than the token-level soft attention in Transformers. Rather than modifying the Transformer architecture itself (which would require retraining and would break compatibility with existing models), S2A uses the LLM's own natural language generation capabilities to implement a form of **hard attention**: the model explicitly decides which parts of the context to keep and which to discard, producing a new, cleaned context that is then fed back into the same LLM for final generation.

This positioning has several key characteristics:

**It's architectural without being invasive.** S2A doesn't change the Transformer's internal attention computation, loss function, or training procedure. It works with any instruction-tuned LLM off the shelf, using zero-shot prompting. This makes it immediately deployable with existing models — the paper uses LLaMA-2-70B-chat without any fine-tuning — while still addressing what the paper identifies as a structural limitation of those models.

**It reframes the problem from "training better models" to "using models better at inference time."** The paper explicitly argues (Section 1) that the issue is "inherent in the way the transformer itself is built, and in particular its attention mechanism." The implication is that training-based fixes alone cannot fully solve the problem because they don't change how attention operates during inference. S2A provides an inference-time mechanism that compensates for the architectural limitation.

**It connects to the System 1 / System 2 cognitive framework.** The paper uses this analogy to motivate why S2A is necessary (System 1 attention, being automatic and associative, will inevitably be swayed by spurious correlations) and how it works (System 2 deliberate reasoning is applied to the attention problem itself, deciding what deserves attention before the automatic system processes the input). This framing helps explain why simple approaches like "tell the model to ignore irrelevant content" fail: they are asking System 1 to override itself, which it can only do imperfectly because its fundamental operation hasn't changed. S2A creates a separate System 2 step that operates *before* System 1 processes the final context.

**It's part of a broader class of "System 2 Attention" techniques.** The paper is careful to note that its specific implementation (zero-shot prompted context regeneration) is one instance of a broader class. The defining characteristic is not the specific prompting template but the two-step structure: (1) deliberately reason about what to attend to and produce a cleaned context, then (2) attend only to that cleaned context for final generation. This opens the door for future implementations using fine-tuning, reinforcement learning, or alternative architectures, while keeping the core principle — hard, deliberate attention decisions — intact.

**The "hard attention" principle is non-negotiable.** Perhaps the most important positioning claim comes from the ablation in Figure 8: the "Keep Original" variant of S2A, where both the original context and the S2A-regenerated context are provided to the model, performs substantially worse than standard S2A (74.5% vs. 80.3%). The paper interprets this as evidence that "attention must be hard (sharp) not soft when it comes to avoiding irrelevant or spurious correlations in the context" (Section 3.2.1). Even though the cleaned context is available, the model's soft attention still distributes weight to the original, opinionated context, and this residual attention is enough to degrade performance. The implication is clear: half-measures don't work. The original noisy context must be fully removed from the model's attention scope for the benefits to materialize.

This finding also connects back to the earlier discussion of why instructed prompting fails: both approaches leave the original context in the model's attention window. Instructed prompting adds an instruction to ignore it; S2A-KeepOrig adds a cleaned version alongside it. In both cases, the soft attention mechanism still processes the noisy tokens, and their influence leaks into the output. Only complete removal — replacing the context with its cleaned version — prevents this leakage.

## 3. Technical Approach

### 3.1 Reader orientation (approachable technical breakdown)

System 2 Attention (S2A) is a two-stage inference-time procedure that uses an instruction-tuned LLM to first rewrite its own input context — stripping out opinions, irrelevant sentences, and otherwise misleading text — and then generate a final response using only that cleaned, deliberately curated context. S2A addresses the problem that standard Transformer soft attention inherently distributes probability mass across all tokens in the input, including irrelevant or misleading ones, by introducing a deliberate, hard-attention filtering step that operates in natural language before the model's automatic attention mechanism ever processes the final prompt.

### 3.2 Big-picture architecture (diagram in words)

The S2A system has three major components, executed sequentially:

1. **The S2A Prompt Template (`$P_{S2A}$`)** — a zero-shot instruction that tells the LLM to regenerate a given input context `$x$` by removing opinions, biases, or irrelevant text while preserving the factual core and the original query. This prompt is specific to the task type (opinion filtering for QA vs. relevance filtering for math word problems) and is the only task-specific engineering required.

2. **The Context Regeneration Step (Step 1)** — the LLM processes `$P_{S2A}(x)$` and produces a cleaned context `$x'$`. This is the "System 2" operation: the model deliberately reasons about what deserves attention, deciding which portions of the original input to keep and which to discard, and outputs its decision as natural language text. The model may also restructure the context (e.g., separating factual background from the question itself) to prevent the final generation step from being confused about what is being asked.

3. **The Final Generation Step (Step 2)** — the LLM processes only the cleaned context `$x'$` (the original `$x$` is **completely discarded**) to produce the final response `$y$`. An optional instructed-prompting suffix (e.g., "Answer in an unbiased way") can be appended to further guide generation style. The key design constraint is that the original noisy context is not included alongside `$x'$` — the cleaned version *replaces* it entirely.

Information flows strictly forward: Original input `$x$` → S2A prompt template wraps `$x$` → LLM generates cleaned context `$x'$` → Original `$x$` is discarded → LLM generates final response `$y$` from `$x'$` alone.

### 3.3 Roadmap for the deep dive

- **First**, the formal specification of S2A as a two-step generative procedure, including the symbolic notation that makes precise what "regenerating the context" means operationally and what the model sees at each stage.
- **Second**, the specific prompting implementation — the exact prompt templates used for each task (Figures 2, 15), what they instruct the model to do, and why the design choices (e.g., separating context from question in the output) matter for reliability.
- **Third**, the post-processing and Step 2 construction — how the raw output from Step 1 is cleaned and assembled into the prompt for final generation, including the instructed-prompting suffix and why its effect is secondary to the context regeneration itself.
- **Fourth**, the alternative implementations and ablated variants (no separation, keep original, no instructed suffix, relevance-framing) — what each variant changes about the base procedure and what the ablation results in Figure 8 reveal about which design elements are load-bearing versus incidental.
- **Fifth**, the design rationale — why S2A is implemented as purely zero-shot prompted rather than fine-tuned, why it operates on the context rather than the response, and why hard (complete) removal of the original context is theoretically necessary rather than merely helpful.

### 3.4 Detailed, sentence-based technical breakdown

This is primarily a **systems/methods paper** whose core idea is that an LLM can serve as its own attention filter: by prompting the model to deliberately reason about what in its input context is relevant versus irrelevant, and then feeding only the relevant portion back into the model for final generation, the resulting outputs become more factual, more objective, and less susceptible to spurious correlations — without any retraining, architectural changes, or access to ground-truth labels.

#### Formal Specification: S2A as a Two-Step Generative Procedure

The paper defines S2A in terms of the standard LLM generation framework. In a standard setup, an LLM takes a context `$x$` (which typically includes both background information and a query or instruction) and produces an output sequence `$y$`:

$$y \sim \text{LLM}(x)$$

where `$x$` is the full input context (text) provided to the model, `$\text{LLM}(\cdot)$` denotes the generative process of the language model — typically autoregressive sampling from the conditional distribution `$P(y_t \mid x, y_{<t})$` — and `$y$` is the generated output sequence.

**What it computes:** standard LLM inference — given a text prompt, sample a completion token by token until a stopping condition is met.

**Why this form:** this is the universal interface for instruction-tuned LLMs. The paper uses it as the baseline to establish that the standard procedure is vulnerable to spurious context correlations, and as the substrate on which S2A is built (both steps of S2A use this same interface).

S2A transforms this single-step procedure into a two-step procedure by interposing a context-regeneration phase:

**Step 1: Context Regeneration**

$$x' \sim \text{S2A}(x)$$

where `$x$` is the original (potentially noisy, opinionated, or irrelevant-laden) input context, `$\text{S2A}(\cdot)$` denotes a specific prompting-and-generation procedure (described in detail below) that instructs the LLM to produce a cleaned version of the context, and `$x'$` is the regenerated context — a text string that should contain only the relevant, factual, and non-opinionated portions of `$x$`, along with the original query.

**What it computes:** a deliberate filtering operation performed by the LLM itself. The model reads the full original context, reasons (implicitly, through its forward pass and autoregressive generation) about which parts are irrelevant or misleading, and outputs a new text that preserves only what it judges to be important. This is not a separate model or a learned filter — it is the same LLM, prompted to perform a specific metacognitive task.

**Why this form:** the entire motivation of the paper is that standard soft attention cannot make hard exclusion decisions — it always distributes non-zero weight across all tokens. By forcing the model to *generate* a new context rather than *modulate* attention weights, S2A creates an explicit, discrete bottleneck: the model must actively decide what text to include in `$x'$`, and anything it omits is completely absent from the next stage. This converts the continuous soft-attention problem into a discrete text-generation problem, which the LLM is already trained to handle.

The paper specifies S2A as a **class of techniques** rather than a single fixed algorithm. The concrete implementation described in the paper instantiates this class using instruction-tuned LLMs with zero-shot prompting:

$$\text{S2A}(x) = \text{LLM}(P_{S2A}(x))$$

where `$P_{S2A}(\cdot)$` is a prompt-template function that takes the original context and wraps it in a specific instruction, and `$\text{LLM}(\cdot)$` is the same base model used for the final generation (LLaMA-2-70B-chat in all experiments).

**What it computes:** the prompt-template function `$P_{S2A}$` maps the raw input text `$x$` to a formatted instruction string that tells the model what filtering operation to perform. The LLM then executes that instruction, producing the cleaned context `$x'$` as its output. This means the same model is used for both the "attention" step (deciding what to attend to) and the "response" step (generating the answer given the attended context).

**Why this form:** using the same LLM for both steps means no additional models need to be trained, no architectural modifications are required, and the approach works with any instruction-tuned LLM off the shelf. The zero-shot prompting design means S2A can be deployed immediately without collecting training data. However, this form also means the quality of S2A is bounded by the base LLM's ability to follow the filtering instruction — if the model fails to correctly identify relevant vs. irrelevant content in Step 1, the cleaned context `$x'$` will be flawed, and the final output `$y$` will suffer.

**Step 2: Final Generation from Cleaned Context**

Once `$x'$` has been generated, the original context `$x$` is **completely discarded**, and the final response is produced using only `$x'$`:

$$y \sim \text{LLM}(x')$$

**What it computes:** standard LLM generation, but crucially, the model's attention mechanism now operates over `$x'$` — the cleaned context — rather than `$x$`. Any tokens that were present in `$x$` but omitted from `$x'$` are entirely absent from the model's context window for this generation step. They cannot influence the latent representations at any layer, because they are simply not in the input sequence.

**Why this form — and why "keep original" fails:** the ablation experiment with the S2A-KeepOrig variant (Section 3.2.1, Figure 8) tests what happens when this strict replacement is relaxed. In that variant, the final generation prompt includes both the original `$x$` and the cleaned `$x'$`, so the model can attend to both. The accuracy drops from 80.3% (S2A) to 74.5% (S2A-KeepOrig). The paper's interpretation (Section 3.2.1) is definitive: "attention must be hard (sharp) not soft when it comes to avoiding irrelevant or spurious correlations in the context." Even with the cleaned version present, the soft attention mechanism still distributes weight to the original opinionated tokens, and that residual attention is sufficient to significantly degrade performance. This finding is load-bearing for the entire approach: **S2A works not because it adds cleaned context, but because it removes the noisy context entirely.**

#### The Prompting Implementation: Task-Specific S2A Templates

The paper provides two distinct S2A prompt templates, each tailored to a different type of filtering needed by different tasks. Both are zero-shot — they contain no examples of correct filtering behavior — and rely entirely on the instruction-tuned LLM's ability to follow the described procedure.

**Opinion-focused S2A prompt (used for factual QA and longform generation)**

The primary prompt template is shown in Figure 2. The full text is:

> "Given the following text by a user, extract the part that is unbiased and not their opinion, so that using that text alone would be good context for providing an unbiased answer to the question portion of the text. Please include the actual question or query that the user is asking. Separate this into two categories labeled with 'Unbiased text context (includes all content except user's bias):' and 'Question/Query (does not include user bias/preference):'.  
> Text by User: [ORIGINAL INPUT PROMPT]"

This prompt encodes several design decisions:

**It frames the task as extraction, not summarization or rewriting.** The verb "extract" implies that the model should identify and copy relevant portions of the original text, not generate new content. This is important because the goal is to preserve factual accuracy — any generative rephrasing could introduce hallucinated content or alter the meaning of the query.

**It explicitly names the filtering criterion: "unbiased and not their opinion."** This tells the model what *kind* of content to remove. For the sycophancy-related tasks (factual QA with opinion injection, longform argument generation with sentiment injection), the harmful content is opinion-based, so the filter is defined in terms of bias and opinion.

**It requests that the question/query be preserved separately.** The instruction to separate output into "Unbiased text context" and "Question/Query" serves two purposes. First, it prevents the model from accidentally omitting the question itself while filtering opinionated text (the authors note that "some models otherwise may have trouble copying all the necessary context" in Section 2.3). Second, it structures the output for reliable post-processing in Step 2 — the question and context can be clearly identified and reassembled.

**It places the original input at the end, after the instruction.** This follows the standard pattern for instruction-tuned LLMs where the instruction precedes the data to be operated on. The `[ORIGINAL INPUT PROMPT]` placeholder is replaced with the full user input, which for the factual QA task includes both a fact-seeking question and an injected opinion statement (e.g., "I think the answer is Johnny Depp but I'm really not sure").

**Relevance-focused S2A prompt (used for math word problems)**

For the GSM-IC math word problem task, the harmful content is not opinion but irrelevant factual sentences. The filtering criterion therefore shifts from "unbiased" to "related and useful." The prompt template is given in Figure 15:

> "Given the following text by a user, extract the part that is related and useful, so that using that text alone would be good context for providing an accurate and correct answer to the question portion of the text. Please include the actual question or query that the user is asking. Separate this into two categories labeled with 'Context text related to the question (includes all content except unrelated sentences):' and 'Detailed question:'. Do not use list.  
> Text by User: [ORIGINAL INPUT PROMPT]"

The differences from the opinion-focused prompt are deliberate:

**The filtering criterion is "related and useful" rather than "unbiased and not their opinion."** This matches the nature of the GSM-IC task, where distractors are semantically related to the math problem's topic (e.g., both involve quantities or both involve people's possessions) but are logically irrelevant to the computation needed to solve the problem. The model must distinguish topical similarity from logical relevance.

**The output labels shift to reflect the different framing.** The categories are "Context text related to the question (includes all content except unrelated sentences)" and "Detailed question:" — emphasizing that the filtering is about relevance, not opinion removal.

**The instruction "Do not use list" is added.** The authors do not explain this choice explicitly, but it likely prevents the model from outputting a bulleted list of sentences rather than coherent prose, which could interfere with the math problem's structure (math word problems are typically a single paragraph).

**Why two different prompts instead of a single universal one?** The paper does not claim to have a single S2A prompt that works for all filtering criteria. The prompt is effectively a specification of *what to remove*, and different tasks require different removal criteria. This is both a strength (the approach can be adapted to different types of irrelevant content by changing the prompt) and a limitation (the prompt must be tailored to the task, and the right prompt for a given task is discovered through experimentation rather than derived from principles). The paper acknowledges this: "As our method is zero-shot prompted it largely depends on the choice of prompt, which we have not made great efforts to optimize" (Section 6).

#### Post-Processing and Step 2 Construction

The raw output from Step 1 typically contains more than just the requested context and question. Instruction-tuned LLMs often produce additional text — chain-of-thought reasoning, commentary, restatements of the instruction — alongside the requested output fields. The paper describes a post-processing step (Section 2.2) to extract the structured components for Step 2:

> "Typically, some post-processing may also be applied to the output of step 1 in order to structure the prompt for step 2, as instruction following LLMs produce additional chain-of-thought reasoning and comments in addition to requested fields. We remove the requested text in parenthesis from Figure 2 and add additional instructions given in Figure 13."

Concretely, this means:

1. The Step 1 output is parsed to identify the sections labeled "Unbiased text context:" (or "Context text related to the question:") and "Question/Query:" (or "Detailed question:").
2. The label headers and any parenthetical instructions are stripped, leaving only the actual content generated by the model.
3. The extracted content is assembled into the Step 2 prompt.

**The Step 2 prompt (with instructed prompting).** Figure 13 shows the template used for final generation in the standard S2A configuration:

> "[INPUT CONTEXT]  
> Answer in an unbiased way."

where `[INPUT CONTEXT]` is replaced with the cleaned context `$x'$` (the combined output from Step 1's separated categories). The additional instruction "Answer in an unbiased way" is the **instructed prompting** component — a direct request to the model to avoid bias in its response. The paper explicitly ablates this component (the "S2A-NI" or "Not Instructed" variant in Figure 8) to determine whether the context regeneration or the debiasing instruction is responsible for S2A's improvements.

**Why the instructed-prompting suffix matters — but isn't the main driver.** The ablation results (Figure 8) show that S2A without the instructed prompting suffix (S2A-NI) achieves 79.3% accuracy, compared to 80.3% for full S2A — a difference of only 1 percentage point. However, the authors note a qualitative difference: "we see skew appearing in the Suggest Correct category for example in this case" for S2A-NI. The instructed prompting suffix thus provides a small additional guard against residual sycophancy in the Suggest Correct category (where the original prompt suggests the right answer, and the model might still be swayed to agree with it), but it is not the primary mechanism — the context regeneration itself is responsible for the bulk of the improvement.

**The Step 2 prompt for math word problems.** For the GSM-IC task, the final generation uses a different prompt (Figure 16):

> "Solve the following math problem. Please separate into two categories labeled with 'Solution:' and 'Final answer (in numbers):'  
> Problem: [MATH PROBLEM]"

where `[MATH PROBLEM]` is the cleaned context from Step 1. This prompt does not include a debiasing instruction — it simply asks the model to solve the problem, relying on the fact that the Step 1 filtering has already removed irrelevant sentences. The model performs chain-of-thought reasoning naturally (the paper notes that "the model always performed chain-of-thought reasoning in its solution" even with zero-shot prompting), so the solution will include intermediate reasoning steps followed by a final numerical answer.

---

#### Alternative Implementations and Ablated Variants

The paper describes four significant variants of the S2A procedure (Section 2.3), three of which are evaluated in the ablation study (Figure 8) on the factual QA task. Each variant isolates a specific design choice and reveals whether that choice is load-bearing.

**Variant 1: No context/question separation (S2A-Single)**

The standard S2A prompt (Figure 2) asks the model to separate its output into "Unbiased text context" and "Question/Query" categories. The "Single" variant (Figure 12) uses a prompt that does not request this separation:

> "Given the following text by a user, extract the portion that is unbiased and not their opinion, so that using that text alone would be good context plus question for providing an unbiased answer to the question portion of the text.  
> Please start your response with 'Unbiased version of text by User, including question:' followed by your extracted/rewritten text.  
> Text by User: [ORIGINAL INPUT PROMPT]"

The output is a single block of cleaned text that includes both the context and the question, without structural separation.

**Results (Figure 8).** S2A-Single achieves 78.5% accuracy, compared to 80.3% for standard S2A — a drop of 1.8 percentage points. The authors interpret this as a small but real degradation: "The 'Single' version of S2A... ends up performly similarly to the version of S2A (default) that does separate, but with just slightly worse performance." The separation is therefore helpful but not critical — it provides a structural hint that helps the model in Step 2 distinguish background information from the question being asked, but the model can mostly recover without it.

**Why this matters.** This variant tests whether the explicit structural decomposition (context vs. question) is a necessary component of S2A or an incidental design choice. The result suggests it's helpful for reliability (especially on weaker models — the authors note in Section 2.3 that "for short contexts (or strong LLMs) this is probably not necessary") but not fundamental to the approach. The core mechanism — generating cleaned context — works with or without the separation.

**Variant 2: Keep original context (S2A-KeepOrig)**

This is the most theoretically important ablation. In standard S2A, the original context `$x$` is completely discarded after Step 1, and only the cleaned context `$x'$` is provided to the model in Step 2. The "Keep Original" variant (Figure 14) breaks this rule: it includes both `$x$` and `$x'$` in the Step 2 prompt:

> "Original user query (possibly biased): [ORIGINAL USER PROMPT]  
> Unbiased context: [CONTEXT GENERATED BY S2A]  
> Given the above unbiased context, answer the following: [QUESTION GENERATED BY S2A]"

The model can now attend to both the original opinionated text and the S2A-cleaned version.

**Results (Figure 8).** S2A-KeepOrig achieves 74.5% accuracy, compared to 80.3% for standard S2A — a drop of 5.8 percentage points. The per-category breakdown shows degradation across all opinion types: Refute Correct drops from 82% to 78%, Suggest Incorrect from 76% to 71%, and Suggest Correct from 82% to 86% (the only category where performance *increases*, likely because the original prompt suggests the correct answer, and the model can now attend to that suggestion).

**Why this matters.** This ablation validates the paper's central theoretical claim: that soft attention inherently incorporates irrelevant information, and the only way to prevent this is to make that information physically absent from the model's input. Having the cleaned version *available* is not enough — the model's attention mechanism will still distribute weight to the original, noisy tokens if they are present, and that residual attention is sufficient to meaningfully degrade performance. The paper interprets this as evidence that "attention must be hard (sharp) not soft" (Section 3.2.1). This finding distinguishes S2A from approaches that try to "override" or "outweigh" noisy context with additional clean context or instructions — such approaches leave the noisy tokens in the attention window, and soft attention ensures they will have some effect.

**Variant 3: No instructed prompting in Step 2 (S2A-NI)**

Standard S2A adds the suffix "Answer in an unbiased way" to the Step 2 prompt (Figure 13). The "Not Instructed" variant (S2A-NI) removes this suffix, relying purely on the cleaned context to produce unbiased outputs without an explicit debiasing instruction.

**Results (Figure 8).** S2A-NI achieves 79.3% accuracy, compared to 80.3% for full S2A — a drop of 1.0 percentage point overall. The per-category breakdown reveals where the instructed prompting suffix matters: in the Suggest Correct category, S2A-NI achieves 86% versus S2A's 82%, while the oracle prompt achieves 82%. This means S2A-NI is still exhibiting residual sycophancy — when the original prompt suggests the correct answer, the model is slightly more likely to agree with it (86% correct vs. oracle 82%) than when that suggestion is absent. The "Answer in an unbiased way" instruction in full S2A suppresses this residual skew, bringing Suggest Correct performance back down to the oracle level.

**Why this matters.** This ablation isolates the contribution of the instructed-prompting suffix from the context regeneration. The takeaway is that context regeneration is the primary driver of improvement (S2A-NI at 79.3% is far above the baseline at 62.8%), and the instructed-prompting suffix provides a small additional calibration benefit, particularly for preventing the model from being swayed by correct answer suggestions. This confirms that the core innovation is the context filtering, not the debiasing prompt.

**Variant 4: Instructed prompting without S2A context regeneration**

This is not an S2A variant but a comparison baseline: what if we simply add the debiasing instruction from Step 2 to the original, unfiltered prompt, without performing any context regeneration? The paper calls this "Instructed Prompting" (Figure 8). The prompt is:

> "[ORIGINAL INPUT PROMPT WITH OPINIONS]  
> Answer in an unbiased way."

**Results (Figure 8).** Instructed Prompting achieves 71.7% accuracy — an improvement over the baseline of 62.8%, but far below S2A's 80.3% and still substantially below the oracle's 82.0%. The per-category breakdown reveals the mechanism of residual failure: Suggest Correct accuracy is 92% (well above oracle's 82%), indicating the model is still being swayed by the correct answer suggestion. Suggest Incorrect accuracy is 38% (far below oracle's 82%), indicating the model is also being swayed by incorrect suggestions. The model is partially complying with the instruction to be unbiased, but the soft attention mechanism is still incorporating the opinionated tokens into its latent representations, and this leakage is sufficient to produce substantial sycophancy.

**Why this matters.** This comparison establishes that the problem is not a lack of instruction-following capability — the model can understand and partially comply with the instruction to be unbiased. The problem is that soft attention distributes weight across all tokens in the context regardless of instructions, and instructions to "ignore" certain content cannot fully override this fundamental architectural operation. S2A works not because it gives better instructions, but because it changes what the model can physically attend to.

**Additional baseline: Chain-of-Thought (CoT) prompting.** The paper also tests zero-shot CoT by appending "Let's think step by step" to the original opinionated prompt (Figure 8). This achieves only 54.2% accuracy — substantially *worse* than the baseline of 62.8%. The paper does not analyze this degradation in detail, but it is consistent with a well-known failure mode: when the context contains misleading information, chain-of-thought reasoning can amplify the error by constructing elaborate reasoning chains that rationalize the incorrect answer suggested by the context. Generating more tokens does not help if the attention mechanism is still processing the noisy input.

---

#### Design Rationale: Why S2A Is Built This Way

Several overarching design choices shape the S2A approach, and the paper provides explicit or implicit justification for each.

**Why zero-shot prompting rather than fine-tuning?** The paper acknowledges (Section 6) that fine-tuning on S2A task data (mappings from original context to cleaned context) "would likely be stronger," and that distilling S2A outputs back into model weights ("fine-tuning using the original prompts as inputs and the final improved S2A responses as targets") is a promising direction. But the zero-shot approach is chosen for the current work because:

- **Immediate deployability.** S2A works with any instruction-tuned LLM off the shelf, requiring no training data, no GPU hours for fine-tuning, and no model weight modifications. This makes the approach accessible and easy to replicate.
- **Interpretability.** The zero-shot prompt makes explicit what filtering criterion is being applied. If the model fails, one can inspect the Step 1 output to see what context was retained and what was removed, providing a debugging surface that would be opaque in a fine-tuned model.
- **Flexibility.** Different filtering criteria can be applied to different tasks simply by changing the prompt, without retraining the model. The opinion-focused prompt works for QA and longform generation; the relevance-focused prompt works for math word problems.

**Why operate on the context rather than the response?** The paper explicitly contrasts S2A with response refinement approaches like self-refine (Madaan et al., 2023) and Constitutional AI (Bai et al., 2022) (Section 4). The key argument is about the **direction of information flow and contamination**:

- **Response refinement** operates after the model has already processed the noisy context. The initial generation — the candidate response being refined — was produced by attending to irrelevant or misleading content. Refinement can correct some errors, but it starts from a contaminated output, and the contamination may be subtle or embedded in ways that refinement cannot fully undo.
- **Context refinement** (S2A) operates before the model generates its response. The model never attends to the irrelevant content — it is physically removed from the input before the attention mechanism processes it. The generation process is therefore clean from the start.

This is a causal argument: intervening upstream of the contamination source is fundamentally more reliable than trying to correct contamination downstream, because some effects of contamination may be irreversible or difficult to detect in the generated output.

**Why must the original context be fully removed (hard attention) rather than supplemented with clean context?** This is the finding from the S2A-KeepOrig ablation, and it connects directly to the paper's theoretical framing. Soft attention in Transformers computes a weighted sum over all token representations in the context, where weights are non-negative and sum to 1 (after softmax normalization). This means:

- Every token in the context contributes *some* non-zero amount to the final representation at each layer.
- There is no mechanism for a token to have exactly zero influence — the softmax ensures all weights are strictly positive.
- Adding clean context alongside noisy context gives the model *more* relevant information to attend to, but it does not prevent the irrelevant information from also influencing the representation. The soft attention distribution will allocate some weight (perhaps small, but non-zero) to the noisy tokens, and across the many layers of the Transformer, this residual influence compounds.

By removing the original context entirely, S2A avoids this problem at the architectural level. The noisy tokens are simply absent from the input sequence, so they receive zero attention weight — not because the model chose to ignore them, but because there is nothing to attend to. This is what the paper means by "hard attention": the decision about what to exclude is made discretely and irrevocably before the soft attention mechanism operates, rather than being attempted as a continuous modulation within soft attention.

**Why use the same model for Step 1 and Step 2?** S2A uses LLaMA-2-70B-chat for both context regeneration and final response generation. This is not a necessary design choice — one could imagine using a specialized "context cleaner" model for Step 1 and a different "responder" model for Step 2 — but it has practical advantages:

- **Simplicity.** Only one model needs to be loaded and served.
- **Consistency.** The same model's knowledge and reasoning capabilities are applied to both understanding what to filter and generating the response. There is no mismatch between what Step 1 considers important and what Step 2 needs to generate a good answer.
- **Zero-shot compatibility.** The same instruction-tuning that enables Step 2 response generation also enables Step 1 filtering. No specialized training is needed for either step.

The potential downside is that if the base model is poor at the filtering task (e.g., it cannot reliably distinguish opinion from fact), S2A cannot compensate — the model's limitations in Step 1 propagate to Step 2. The paper acknowledges this implicitly in the Limitations section (Section 6): "While System 2 Attention aims to remove irrelevant context to improve generations, it certainly does not always succeed."

---

#### Computational Cost Model

The paper provides an informal cost characterization (Section 6) rather than a quantitative analysis. S2A requires two full forward passes through the LLM — one for context regeneration (Step 1) and one for final response generation (Step 2) — compared to a single pass for standard generation.

The additional cost depends on the length of the regenerated context `$x'$`. If S2A must copy a large amount of relevant text (e.g., a long quoted argument in the longform generation task), the Step 1 generation cost is proportional to that length. The paper notes that "this could potentially be remedied with speedup tricks, e.g., only generate the difference, or the parts not to include, or when copying large sections that have a label/section header, it could just reference the label instead" (Section 6). These optimizations are left to future work, so the current implementation pays the full cost of regenerating all retained content.

The cost is "somewhat analogous to that incurred in methods like chain-of-thought which also makes intermediate generations" (Section 6). However, chain-of-thought adds reasoning tokens to the same forward pass (or a single extended generation), while S2A requires a separate, completed generation followed by a second independent generation. This makes S2A more expensive than standard CoT for the same total output length, because the model must process the full context twice (once for Step 1, once for Step 2) rather than once.

The paper does not report wall-clock timing measurements, FLOP counts, or token counts for the S2A steps, so the practical cost overhead cannot be quantified from the provided data. This is a significant gap for practitioners evaluating whether to adopt the method in latency-sensitive or cost-sensitive applications.

## 4. Key Insights and Innovations

### Innovation 1: Reframing Attention as a Deliberate, Metacognitive Act Rather Than a Passive Architectural Mechanism

The most intellectually distinctive move in this paper is the conceptual reframing of "what to attend to" from a low-level architectural operation (the softmax-weighted sum over token embeddings that Transformers compute automatically) to a high-level metacognitive task that the model itself can perform through natural language reasoning. This is not an incremental improvement to attention — it is a category shift in how attention is conceived.

**What the field did before.** Attention mechanisms in neural networks have historically been understood as mathematical operations — differentiable functions that compute weighted combinations of input representations. The entire history of attention, from Bahdanau et al. (2014) through the Transformer (Vaswani et al., 2017), treats attention as something the architecture *does* to the input. Research on improving attention has consequently focused on architectural modifications: sparse attention patterns, retrieval-augmented mechanisms, different positional encodings, or learned sparsity. Even "hard attention" in its classical formulation (Mnih et al., 2014; Xu et al., 2015) was still an architectural mechanism — a discrete sampling operation trained with REINFORCE. The field's operating assumption has been that attention is a **sub-symbolic, architectural property**, not something a model can reason about explicitly.

**What S2A changes.** S2A redefines attention as a **generative task**: given an input context, produce a new context that contains only what deserves attention. The model is not being asked to modulate its internal attention weights — it is being asked to *write* the text it should attend to. This transforms attention from a mechanism into a behavior, and from an implicit computation into an explicit, inspectable output. The term "System 2 Attention" is not merely a metaphor — it identifies a genuinely different type of attention, one that operates through deliberate, symbolic reasoning rather than automatic, continuous association.

This reframing matters because it breaks the assumed coupling between how attention *should* work (selectively focusing on relevant information while ignoring the rest) and how Transformers *actually* implement attention (distributing soft probability mass across all tokens). Prior work attempted to close this gap by making soft attention behave more like hard attention — through architectural changes, training objectives, or inference-time modifications to attention weights. S2A circumvents the gap entirely by implementing hard attention at a different level of abstraction — the level of text generation, where discrete inclusion/exclusion decisions are natural and the LLM already has extensive training.

**Significance beyond performance.** The conceptual move here is significant even if S2A were no more accurate than baselines (though it is). It opens a new design space for attention mechanisms: rather than asking "how can we make the attention weights better?", researchers can ask "how can we make the model better at deciding what text to present to its own attention mechanism?" This is a **meta-attention** capability — attention about attention — and it is fundamentally different from both classical hard attention (which was still a sub-symbolic mechanism) and response refinement (which operates on outputs, not on what the model attends to).

**Evidence anchors.** The S2A-KeepOrig ablation (Figure 8) provides the cleanest evidence for why this reframing is necessary, not merely clever. When the cleaned context is provided alongside the original context, performance drops from 80.3% to 74.5%. The model's soft attention cannot help but distribute weight to the noisy original text even when a clean version is available. This demonstrates that the problem is not about giving the model better information to attend to — it is about *physically removing* the information that should not be attended to. S2A's reframing of attention as a text-generation task makes this physical removal possible: the model generates a new context string, and the old one is simply not in the input. No amount of architectural tweaking of soft attention weights could achieve this, because soft attention fundamentally cannot assign exactly zero weight to a present token.

---

### Innovation 2: Demonstrating That Soft Attention's Inability to Fully Ignore Tokens Is a Hard Performance Ceiling, Not a Surmountable Limitation of Scale or Training

The paper provides a crisp empirical argument — crystallized in one ablation — that the soft attention mechanism's inherent property of distributing non-zero probability mass across all input tokens represents a fundamental performance ceiling that cannot be overcome by better instructions, more training data, larger models, or chain-of-thought reasoning. This is a negative result with significant positive implications for where research effort should be directed.

**What the field assumed.** The dominant working assumption in the LLM literature has been that attention-related failures (sycophancy, distraction by irrelevant context, repetition loops) are **training artifacts** that can be addressed through better data, better objectives, or better alignment procedures. Works like Sharma et al. (2023) and Wei et al. (2023) attempted to reduce sycophancy through supervised fine-tuning and reinforcement learning — implicitly assuming that the model *could* learn to ignore opinions in context if trained appropriately. Instructed prompting ("ignore irrelevant sentences") makes the even stronger assumption that the model already has the capability to selectively attend and merely needs to be told to do so. The field's trajectory has been toward solving attention failures through scale and training improvements.

**What S2A's evidence shows.** The paper's ablation results establish a clear hierarchy of what works and what doesn't, and the pattern points to an architectural bottleneck, not a training gap:

- **Chain-of-thought prompting** on opinionated context *reduces* accuracy from 62.8% to 54.2% (Figure 8). More reasoning tokens do not help — they can amplify errors by constructing elaborate justifications for context-suggested answers.
- **Instructed prompting** ("Answer in an unbiased way") improves accuracy to 71.7%, but substantial sycophancy remains: Suggest Correct accuracy (92%) is well above oracle (82%), and Suggest Incorrect accuracy (38%) is far below oracle (82%). The model partially complies but cannot fully override the influence of opinion tokens in its attention window.
- **S2A-KeepOrig** (cleaned context + original context) achieves only 74.5%. Even with explicit, high-quality cleaned text available, the presence of the original noisy context degrades performance by 5.8 percentage points relative to S2A with original context removed (80.3%).
- **S2A with original context removed** achieves 80.3%, approaching oracle performance (82.0%). The only thing that changes between S2A-KeepOrig and standard S2A is whether the original noisy tokens are in the input sequence.

The monotonic improvement from CoT → Instructed → S2A-KeepOrig → S2A is not a scaling curve — it is a series of interventions that progressively reduce the model's exposure to irrelevant tokens, with the final step (complete removal) providing a discontinuous jump. This pattern is consistent with an architectural floor, not a gradual improvement from better training.

**Why this matters for the field.** If the problem were primarily a matter of insufficient training or instruction-following, then the path forward would be clear: more data, better alignment, larger models. The paper's evidence suggests this path has a ceiling — soft attention will always leak influence from present-but-irrelevant tokens, and no amount of training can teach the model to assign exactly zero weight to a token (the softmax function mathematically cannot output zero for any finite input). This redirects research effort toward **architectural or procedural interventions that physically restrict the model's input**, rather than training interventions that try to modulate attention weights. S2A is one such intervention (context regeneration + removal), but the principle is broader: any method that prevents the model from ever processing irrelevant tokens will be more robust than any method that tries to teach the model to ignore them.

**Evidence anchors.** The key comparison is the triad of Instructed Prompting (71.7%), S2A-KeepOrig (74.5%), and S2A (80.3%) in Figure 8. Instructed Prompting asks the model to ignore irrelevant content but keeps it in the input — partial improvement, substantial residual failure. S2A-KeepOrig adds clean context but also keeps the original — better, but still degraded. S2A removes the original entirely — near-oracle performance. The inference is clean: presence of irrelevant tokens in the input sequence, regardless of what else is present or what instructions are given, imposes a performance penalty that cannot be fully eliminated by non-architectural means.

---

### Innovation 3: Establishing Context Regeneration as a Distinct Paradigm from Both Response Refinement and Prompt Engineering

The paper carves out a new category of LLM inference-time methods — **context regeneration** — that is structurally distinct from both response refinement (improving the model's output) and prompt engineering (improving the instruction given to the model). This is a taxonomic innovation with practical consequences: it identifies a lever for improving LLM behavior that the field had not systematically explored.

**What the field had before.** Prior methods for improving LLM outputs at inference time fell into two categories:

- **Prompt engineering and reasoning methods** (chain-of-thought, least-to-most, self-ask, instructed prompting) modify *how the model is asked to process the input* — they add instructions, examples, or reasoning templates — but leave the input context itself unchanged. The model still attends to all original tokens.
- **Response refinement methods** (self-refine, Constitutional AI, Chain-of-Verification) take the model's *output* and iteratively improve it — correcting errors, removing hallucinations, or aligning with desired principles. These methods operate downstream of the original context processing; the initial generation, produced by attending to potentially noisy context, is the starting point for refinement.

**Where context regeneration fits.** S2A operates at a third point in the pipeline: **between the input and the initial generation**. It modifies the *context itself* before the model generates its response. This is upstream of response refinement (the model never produces a contaminated initial output to refine) and orthogonal to prompt engineering (the prompt for Step 2 can still include instructions, chain-of-thought, or other reasoning techniques — indeed, the math word problem experiments use chain-of-thought on the S2A-cleaned context).

The paper explicitly distinguishes S2A from query rewriting (Section 4), noting that Deng et al. (2023) rewrites questions to *add detail and reduce ambiguity*, while S2A rewrites context to *remove irrelevant or misleading portions*. This is a different capability — discrimination and filtering rather than expansion and clarification — even though both involve rewriting input text.

**Why this is more than a minor variation.** The distinction between context regeneration and response refinement has practical consequences for failure modes:

- Response refinement can correct errors in the model's answer, but it cannot recover information that the model failed to attend to in the original context. If the model's attention was captured by an irrelevant distractor sentence and it consequently failed to process a critical number in a math problem, no amount of output refinement can recover that number — it was never in the model's working representation.
- Context regeneration can preserve critical information that might be overlooked if attention is misallocated. By forcing the model to explicitly decide what to include in the cleaned context, S2A creates a deliberate, all-or-nothing filtering step that is less prone to the "partial attention" problem where important tokens receive some weight but not enough to drive correct generation.

The paper's results on GSM-IC (Figure 7) support this distinction: S2A improves accuracy from 51.7% to 61.3% on in-topic distractors by regenerating the context to remove the distractor sentence. A response refinement approach, starting from a generation contaminated by the distractor, would need to detect that the model incorporated irrelevant information (e.g., "Max has 1000 more books") into its mathematical reasoning — a substantially harder task than simply removing the distractor before generation begins.

**Evidence anchors.** The comparison between Instructed Prompting and S2A on GSM-IC (Figure 7, right) is the cleanest demonstration. Instructed Prompting — which tells the model to ignore irrelevant sentences but leaves them in the context — achieves 54.7% accuracy, barely above the baseline of 51.7%. S2A — which removes the irrelevant sentences from the context before the model solves the problem — achieves 61.3%. The instruction to ignore is present in both cases (implicitly, through the context regeneration in S2A), but the physical presence or absence of the distractor sentence in the attention window is what drives the 6.6 percentage point gap. Context regeneration provides a lever — physical removal of tokens — that no form of prompt engineering or response refinement can replicate.

---

### Innovation 4: The "Hard Attention Required" Principle as a Design Rule for Robust LLM Systems

The paper's most transferable insight is not S2A itself but a design principle that S2A validates: when building systems that must produce outputs resistant to spurious context correlations, **half-measures that leave irrelevant content in the model's attention window are fundamentally insufficient** — only complete physical removal of that content from the input sequence is reliable. This principle has implications beyond the specific S2A implementation and even beyond the sycophancy/distraction problems studied in the paper.

**What the field assumed.** The dominant approach to making LLMs robust against unwanted context influence has been to provide countervailing signals: instructions to ignore certain content, additional context that outweighs the unwanted content, or fine-tuning on examples where the unwanted content is present but the correct answer is provided. The implicit assumption is that the model's attention mechanism can be steered — that given enough signal in the right direction, the model will learn to allocate near-zero attention to irrelevant tokens, and that any residual attention is negligible.

**What S2A demonstrates.** The S2A-KeepOrig ablation (Figure 8) directly contradicts this assumption. In that condition, the model receives both the S2A-cleaned context (which explicitly contains only relevant, unbiased information) and the original opinionated context. The cleaned context is specifically designed to be a better source of information for answering the question. Yet performance drops by 5.8 percentage points relative to S2A with the original context removed. The model's soft attention distributes enough weight to the original, opinionated tokens — despite having a superior alternative explicitly present and labeled — to meaningfully degrade accuracy.

This is not a marginal effect. The 5.8 percentage point drop represents roughly a quarter of the total gap between the baseline (62.8%) and oracle performance (82.0%). The presence of the original context, even alongside a cleaned version, erases approximately one quarter of the total possible improvement from perfect context filtering. This is a substantial penalty for what might seem like a conservative design choice (keeping the original context available "just in case" the cleaning removed something important).

**Why this is a design rule, not just an observation.** The principle generalizes: any system that passes user-provided context to an LLM and wants the LLM's output to be robust against irrelevant or misleading content in that context should not attempt to override the irrelevant content with instructions or supplementary information — it should remove the irrelevant content from the input entirely. This applies to:

- **Retrieval-augmented generation (RAG)**: if retrieved documents contain contradictory or misleading information, adding a prompt instruction to "prioritize reliable sources" may be insufficient — the unreliable documents should be filtered from the context before generation.
- **Multi-turn dialogue**: if a user makes offhand comments that could sway the model's subsequent responses, those comments should be summarized or excluded from the context window when generating task-critical outputs.
- **Agent systems**: if an LLM agent's observation stream includes irrelevant or misleading environmental cues, those cues should be stripped before the agent decides on its next action — not merely accompanied by an instruction to ignore them.

The paper's finding that instructed prompting (71.7%) falls well short of S2A (80.3%) on the same task provides converging evidence for this principle: telling the model what to ignore is a weak intervention compared to making the ignorable content physically absent.

**Evidence anchors.** The design rule is supported by the consistent pattern across three conditions in Figure 8 that leave the original context in the input to varying degrees:
- Instructed Prompting (full original context + instruction to be unbiased): 71.7%
- S2A-KeepOrig (cleaned context + full original context available): 74.5%
- Standard S2A (cleaned context only, original removed): 80.3%

Each step that reduces or qualifies the model's exposure to the original context improves performance, but only complete removal achieves near-oracle results. The pattern is monotonic and the final step (removal) provides a gain (5.8 points) comparable to the gain from adding the cleaned context alongside the original (74.5% - 71.7% = 2.8 points). Complete removal matters at least as much as providing clean context.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The paper uses three tasks: (1) a modified version of TriviaQA from the SycophancyEval benchmark (Sharma et al., 2023) for factual QA — 200 prompts where opinion statements are injected alongside fact-seeking questions; (2) the arguments prompts from SycophancyEval for longform generation — 200 prompts asking the model to comment on quoted argument contexts with injected sentiment statements; (3) the GSM-IC task (Shi et al., 2023) for math word problems — 100 problems chosen from GSM8K (Cobbe et al., 2021) with one distracting sentence added before the final question, tested in two configurations: random distractors and in-topic distractors. For GSM-IC, results are averaged over 3 random seeds to reduce variance.

- **Base model(s).** All experiments use LLaMA-2-70B-chat as the base LLM. The paper does not provide explicit justification for this choice beyond its use as the substrate for demonstrating S2A's effectiveness. The model is used in a zero-shot fashion for all tasks — no fine-tuning, no few-shot examples. For all three methods (Baseline, Oracle Prompt, S2A), decoding uses temperature 0.6 and top-p 0.9.

- **Metrics.** Three distinct evaluation metrics are used, each implemented via GPT-4 as an automated judge:
  - **Factual QA accuracy:** GPT-4 evaluates whether the model's response matches the ground-truth TriviaQA label using a scoring rubric from 0–5 (Figure 9). Only responses scoring a 5 are counted as correct; lower scores are incorrect. The paper reports the percentage of correct responses across the 200-prompt test set.
  - **Longform generation quality and objectivity:** GPT-4 evaluates overall generation quality on a 0–5 scale (Figure 10). Objectivity is measured via a separate GPT-4 prompt that assesses sentiment on a -5 to +5 scale (negative to positive, 0 being neutral; Figure 11). The objectivity score is then computed as `5 − |S|`, where `S` is the sentiment score. A perfectly neutral response (S = 0) achieves the maximum objectivity of 5; strongly positive or negative responses achieve low objectivity scores.
  - **Math word problem accuracy:** Exact match between the model's extracted final numerical answer and the ground-truth label from GSM8K. The model's output is parsed to extract the final answer (the paper uses the "Final answer (in numbers):" field from the structured output prompt shown in Figure 16).

- **Baselines.** The paper evaluates against the following:
  - **Baseline (standard LLM):** The original prompt from the dataset — including all injected opinions or irrelevant sentences — is fed directly to LLaMA-2-70B-chat with zero-shot prompting. This measures the model's performance when exposed to the full, unmodified context.
  - **Oracle Prompt:** The prompt *without* the injected opinions (factual QA, longform) or irrelevant sentences (GSM-IC) is fed to the model. This establishes an approximate upper bound on performance achievable if all spurious context were optimally removed. The paper notes this is an "approximate" upper bound because for longform generation, the argument context itself may contain opinionated language that the oracle does not filter.
  - **Instructed Prompting:** An additional instruction is appended to the original (opinionated/distractor-containing) prompt, asking the model to ignore irrelevant content or answer in an unbiased way. For factual QA and longform: the suffix "Answer in an unbiased way" (Figure 13) is added directly to the original prompt. For GSM-IC: the instruction "If there is part that is irrelevant and not useful... you may ignore that part" is added (Figure 17). This baseline tests whether explicit instructions can override soft attention's tendency to incorporate irrelevant tokens, without any context regeneration.
  - **Chain-of-Thought (CoT) prompting:** Zero-shot CoT via appending "Let's think step by step" to the original opinionated prompt, following Kojima et al. (2022). Tested only on the factual QA task (Figure 8). This tests whether additional reasoning tokens help the model overcome context contamination.

- **Generation budget / compute accounting.** The paper does not provide a formal compute accounting framework. S2A is qualitatively described as requiring two full forward passes — one for context regeneration (Step 1) and one for final response generation (Step 2) — compared to a single pass for the baseline methods. No FLOP counts, token counts, or wall-clock timing measurements are reported. The paper acknowledges the additional cost (Section 6) and characterizes it as "somewhat analogous to that incurred in methods like chain-of-thought which also makes intermediate generations," but notes that S2A's cost depends on the length of the regenerated context — copying large relevant sections increases cost. Speed-up techniques (generating only differences, referencing section labels rather than copying full text) are mentioned as future work but not implemented.

- **Cross-validation / statistical protocol.** None reported. The paper evaluates on fixed test sets (200 prompts for factual QA, 200 for longform generation, 100 problems × 3 seeds for GSM-IC) and reports aggregate metrics without confidence intervals, standard deviations (except the 3-seed averaging for GSM-IC), or statistical significance tests. For the factual QA ablation study (Figure 8), all variants are evaluated on the same 200 prompts, with per-category breakdowns (Refute Correct, Suggest Incorrect, Suggest Correct) also reported on the same fixed split. The absence of statistical testing means the reported differences — some as small as 1–2 percentage points — cannot be assessed for reliability against sampling variance.

### Main Quantitative Results

#### Factual QA with Injected Opinions

The headline result (Figure 5, left) is that S2A achieves 80.3% accuracy on the modified TriviaQA prompts, compared to 62.8% for the baseline (LLaMA-2-70B-chat with opinionated prompts) and 82.0% for the oracle prompt (unopinionated prompts). S2A closes 88% of the gap between baseline and oracle performance (a 17.5 percentage point improvement over a 19.2 point gap), establishing that context regeneration can recover most of the accuracy lost to opinion contamination.

The per-category breakdown (Figure 5, right) reveals where the baseline fails and where S2A succeeds:

- **Suggest Correct** (prompt includes "I think the answer is [correct answer], but I'm really not sure"): Baseline achieves 94% accuracy — substantially *higher* than the oracle's 82%. The model is being helped by the correct suggestion, exhibiting sycophancy in the "beneficial" direction. S2A achieves 82%, matching the oracle exactly. S2A is not swayed by the correct suggestion and performs as if the opinion were absent.

- **Suggest Incorrect** (prompt includes "I think the answer is [incorrect answer], but I'm really not sure"): Baseline achieves only 40% accuracy, far below the oracle's 82%. The model is being swayed toward the incorrect suggestion. S2A achieves 76% — a 36 percentage point improvement over baseline, though still 6 points below oracle. This is S2A's weakest category, indicating the model's context regeneration does not fully eliminate the influence of incorrect suggestions in all cases.

- **Refute Correct** (prompt includes "I don't think the answer is [correct answer], but I'm really not sure"): Baseline achieves 32% — the worst across all categories, as the prompt actively argues against the right answer. S2A achieves 82%, matching the oracle exactly. S2A completely neutralizes the effect of the refutation.

The pattern is asymmetric: S2A fully recovers oracle performance for Suggest Correct and Refute Correct (82% in both cases, matching oracle), but shows a residual deficit for Suggest Incorrect (76% vs. oracle 82%). The paper does not analyze why incorrect suggestions are harder to fully filter than correct refutations, but the asymmetry suggests that S2A's Step 1 filtering may be imperfect when the opinion is stated as a positive assertion of an incorrect fact rather than a negation of a correct one.

#### Longform Generation with Injected Sentiment

The headline result (Figure 6, left) shows that S2A substantially increases objectivity without sacrificing quality:

- **Quality:** All three methods achieve similar quality scores — Baseline: 4.7, Oracle: 4.6, S2A: 4.6 (all out of 5). The differences are small and likely not statistically meaningful given the 200-prompt test set without reported confidence intervals. S2A does not degrade generation quality despite operating on a regenerated context.

- **Objectivity:** Baseline achieves only 2.23 out of 5, oracle achieves 3.0, and S2A achieves 3.82. S2A is not only more objective than the baseline (by 1.59 points, a 71% relative improvement) but also more objective than the oracle prompt (by 0.82 points, a 27% relative improvement). This is a striking finding: S2A's regenerated context produces *more* objective responses than providing the original question without any added opinion at all.

Why would S2A outperform the oracle? The paper explains (Section 3.2): "In this task, there may be text in the context arguments themselves that provides considerable sway, independent of the additional comments added to the input prompt, which S2A can also decrease when it regenerates the context." The oracle prompt removes the injected opinion ("I like this argument," "I wrote this argument," etc.) but leaves the argument text itself intact. If the argument text contains opinionated or emotionally charged language (which real arguments typically do), the oracle prompt still exposes the model to that language, and the model's response may be swayed by it. S2A, in regenerating the context, can also neutralize opinionated language within the argument — reframing tendentious claims as neutral statements, or extracting only the factual core. This means S2A can achieve *super-oracle* objectivity because it filters a broader class of biasing content than the oracle prompt's simple removal of the injected sentiment statement.

The per-category breakdown (Figure 6, right) confirms this interpretation:

- **Category "None"** (no injected opinion): Baseline objectivity is 2.5, oracle is 2.5, but S2A achieves 4.2. This is the clearest evidence that S2A is neutralizing bias inherent in the argument text itself, not just the injected sentiment. Even when no opinion is added to the prompt, S2A's context regeneration produces responses that are substantially more neutral (4.2 vs. 2.5).

- **Category "Like"** (prompt states "I like this argument"): Baseline objectivity drops to 1.42 — the model's response becomes significantly more positive, agreeing with the user's stated preference. Oracle achieves 2.87, S2A achieves 3.46. S2A substantially mitigates the positivity skew but does not fully reach the "None" category's 4.2, suggesting some residual influence.

- **Category "Wrote"** (prompt states "I wrote this argument"): Baseline objectivity is 2.0, oracle is 2.35, S2A is 3.85. Similar pattern to "Like" — S2A strongly mitigates but does not fully neutralize the sentiment injection.

- **Category "Dislike"** (prompt states "I dislike this argument"): Baseline is 2.35, oracle is 3.46, S2A is 3.98. S2A again outperforms oracle.

- **Category "Didn't Write"** (prompt states "I didn't write this argument"): Baseline is 2.35, oracle is 3.67, S2A is 4.2 — matching the "None" category's 4.2. S2A fully neutralizes this injection.

The S2A advantage over oracle is most pronounced in the "None" category (+1.7 points) and the "Like"/"Wrote" categories (+0.59 and +1.5 points respectively), consistent with S2A filtering bias from both the injected sentiment and the argument text itself.

#### Math Word Problems with Irrelevant Sentences (GSM-IC)

The headline result (Figure 7) shows that S2A improves accuracy on math word problems with irrelevant distractor sentences, with the magnitude depending on the distractor type:

- **Random distractors (Figure 7, left):** Baseline achieves 56.3%, oracle 69.7%, S2A 68.3%. S2A provides a 12.0 percentage point improvement over baseline, recovering 89% of the gap to oracle performance. Instructed Prompting achieves only 54.7% — actually *worse* than baseline — confirming that telling the model to ignore irrelevant sentences is ineffective for this task.

- **In-topic distractors (Figure 7, right):** Baseline achieves 51.7%, oracle 69.7%, S2A 61.3%. S2A provides a 9.6 percentage point improvement over baseline, but the gap to oracle remains larger (8.4 points) compared to random distractors (1.4 points). In-topic distractors are harder to completely filter because they share semantic content with the problem — e.g., a distractor about Max having 1000 more books than Mary in a problem about Mary's candy count — making the relevance/irrelevance distinction subtler than for random distractors. Instructed Prompting achieves 54.7%, a marginal improvement over baseline (3 points) but far below S2A.

The oracle accuracy (69.7%) is identical for both distractor types because the oracle prompt removes the distractor sentence entirely, so the model sees the same clean problem in both conditions. The baseline drop from 56.3% (random) to 51.7% (in-topic) confirms Shi et al. (2023)'s finding that in-topic distractors are more harmful. S2A reduces but does not eliminate this differential harm: S2A achieves 68.3% on random distractors but only 61.3% on in-topic, a 7-point gap that is substantially smaller than the baseline's 4.6-point gap but still present. This indicates that S2A's Step 1 filtering is less reliable when the distractor is topically related to the problem — the model sometimes fails to identify that a semantically related sentence is logically irrelevant.

**Example analysis.** Figure 3 provides a qualitative example of S2A succeeding on the GSM-IC task. The original problem includes the distractor "Max has 1000 more books than Mary." The baseline model's solution incorporates this irrelevant information, computing "Max has 1000 + 3x + 10 pieces of candy" and then setting up an equation that involves the number 1000, leading to an incorrect final answer of 328. S2A's Step 1 regenerates the context as: "Mary has 3 times as much candy as Megan. Mary then adds 10 more pieces of candy to her collection. If Megan has 5 pieces of candy, how many does Mary have in total?" — completely removing the Max sentence. The Step 2 solution then correctly computes 3 × 5 = 15, 15 + 10 = 25, yielding the correct answer.

#### Comparison Across Tasks

The magnitude of S2A's improvement varies across tasks:

| Task | Baseline | S2A | Oracle | S2A Gain | % of Gap Closed |
|------|----------|-----|--------|----------|-----------------|
| Factual QA | 62.8% | 80.3% | 82.0% | +17.5 pp | 91% |
| Longform Objectivity | 2.23 | 3.82 | 3.0 | +1.59 | N/A (exceeds oracle) |
| GSM-IC Random | 56.3% | 68.3% | 69.7% | +12.0 pp | 89% |
| GSM-IC In-Topic | 51.7% | 61.3% | 69.7% | +9.6 pp | 53% |

S2A is most effective at closing the gap to oracle for factual QA and random-distractor math problems (89–91% gap closure), but leaves a substantial residual gap for in-topic math distractors (53% gap closure). The longform generation results are exceptional because S2A exceeds the oracle, so gap-closure framing does not apply.

### Ablation Studies and Robustness Checks

All ablations in this section are evaluated on the factual QA task (modified TriviaQA with injected opinions, 200 prompts) using LLaMA-2-70B-chat and are reported in Figure 8.

**S2A without context/question separation (S2A-Single):** Removing the instruction to separate the regenerated context into "Unbiased text context" and "Question/Query" categories — using the unified prompt from Figure 12 instead — yields 78.5% accuracy vs. 80.3% for standard S2A, a drop of 1.8 percentage points. The degradation is modest, suggesting the structural separation is helpful but not load-bearing. Per the authors: "The 'Single' version of S2A... ends up performly similarly to the version of S2A (default) that does separate, but with just slightly worse performance." The separation likely provides a useful scaffolding for weaker models or longer contexts; for LLaMA-2-70B-chat on these prompts, the effect is small.

**S2A with original context kept (S2A-KeepOrig):** Including both the original opinionated context and the S2A-regenerated context in the Step 2 prompt (Figure 14) yields 74.5% accuracy vs. 80.3% for standard S2A, a drop of 5.8 percentage points. The per-category breakdown shows: Refute Correct drops from 82% to 78%, Suggest Incorrect from 76% to 71%, and Suggest Correct actually *increases* from 82% to 86% (the model can now attend to the original correct suggestion). This is the most theoretically significant ablation: even with explicit, high-quality cleaned context available and labeled as "Unbiased," the model's soft attention still distributes sufficient weight to the original opinionated tokens to meaningfully degrade performance. The paper's interpretation is that "attention must be hard (sharp) not soft when it comes to avoiding irrelevant or spurious correlations in the context" — half-measures that leave the original context in the attention window are fundamentally insufficient.

**S2A without instructed prompting in Step 2 (S2A-NI):** Removing the "Answer in an unbiased way" suffix from the Step 2 prompt yields 79.3% accuracy vs. 80.3% for standard S2A, a drop of only 1.0 percentage point. However, the per-category breakdown reveals a qualitative difference: in the Suggest Correct category, S2A-NI achieves 86% vs. S2A's 82% and oracle's 82%. This means S2A-NI still exhibits residual sycophancy — when the original context suggested the correct answer, the model is slightly more likely to agree with that suggestion than it would be without the suggestion (82% is oracle performance when no suggestion is present; 86% indicates the suggestion is still influencing the model). The instructed prompting suffix suppresses this residual skew, bringing Suggest Correct performance back to the oracle level. The bulk of S2A's improvement (17.5 points over baseline) comes from context regeneration, not the debiasing instruction, but the instruction provides a small additional calibration benefit specifically for preventing the model from being swayed by correct suggestions.

**Instructed Prompting without context regeneration:** Adding the "Answer in an unbiased way" instruction directly to the original opinionated prompt — without performing S2A's context regeneration step — yields 71.7% accuracy. This is an improvement over baseline (62.8%) but falls far short of S2A (80.3%) and even S2A-KeepOrig (74.5%). Per-category: Suggest Correct achieves 92% (well above oracle's 82%), Suggest Incorrect achieves only 38% (far below oracle's 82%), and Refute Correct achieves 82% (matching oracle). The instruction partially mitigates the Refute Correct and Suggest Incorrect failures, but leaves a large residual effect in Suggest Incorrect (38% vs. oracle 82%) and actually makes the sycophancy worse in Suggest Correct (92% vs. oracle 82%). This confirms that instructed prompting alone cannot overcome soft attention's tendency to incorporate opinionated tokens — the model partially complies with the instruction but cannot fully override the architectural leak.

**Chain-of-Thought (CoT) prompting:** Adding "Let's think step by step" to the original opinionated prompt yields only 54.2% accuracy — substantially *worse* than baseline (62.8%). Per-category: Refute Correct achieves 20%, Suggest Incorrect 30%, Suggest Correct 86%. CoT amplifies the sycophancy in the Refute Correct case (dropping from baseline's 32% to 20%) while modestly reducing the skew in Suggest Incorrect (30% vs. baseline's 40%) and Suggest Correct (86% vs. baseline's 94%). The paper does not analyze this degradation in detail, but the pattern is consistent with a known failure mode: when the context contains misleading information, chain-of-thought reasoning can construct elaborate rationalizations for the context-suggested (incorrect) answer, increasing confidence in wrong answers for the Refute Correct category while sometimes helping the model recover in the Suggest Incorrect case. Overall, more reasoning tokens do not compensate for contaminated input.

**Relevance-based vs. opinion-based S2A prompting (across-task comparison):** The paper uses different S2A prompt templates for different tasks — opinion-focused for factual QA and longform generation (Figure 2), relevance-focused for GSM-IC (Figure 15). This is not presented as a controlled ablation, but the difference in effectiveness across tasks (91% gap closure for factual QA vs. 53% for in-topic GSM-IC distractors) suggests that relevance-based filtering is harder to perform reliably than opinion-based filtering. The paper does not test the relevance prompt on the factual QA task or vice versa, so the prompt-dependence claim is inferred from cross-task comparisons rather than directly tested.

**Seed averaging for GSM-IC:** The math word problem results are averaged over 3 random seeds (Section 3.1.3). The paper does not report variance across seeds, so the stability of the reported improvements cannot be assessed. The 100-problem test set is relatively small, and a few problem-level failures or successes could meaningfully shift aggregate accuracy. The 3-seed averaging provides some protection against sampling noise in the generation process but does not address the fixed test-set limitation.

### Critical Assessment

The experiments demonstrate that S2A can substantially improve factual accuracy, objectivity, and mathematical reasoning accuracy on tasks where the input context contains irrelevant, opinionated, or distracting content. However, close examination reveals significant gaps between what the paper claims and what the experiments actually test, as well as several experimental design limitations that qualify the strength of the conclusions.

**The central claim is that S2A "outperforms standard attention-based LLMs" on three tasks, increasing factuality, objectivity, and accuracy.** The experiments support this claim directionally — S2A consistently outperforms the baseline across all three tasks by meaningful margins (17.5 pp on factual QA, 1.59 points on objectivity, 9.6–12.0 pp on GSM-IC). However, the claim of "outperforming" is tested against a single baseline (LLaMA-2-70B-chat with zero-shot prompting) on a single model family. The paper does not demonstrate that S2A outperforms *any* alternative approach to mitigating context contamination besides instructed prompting and chain-of-thought. Missing comparisons include:

- **Fine-tuned models specifically trained to resist sycophancy**, such as those produced by Sharma et al. (2023) or Wei et al. (2023). These are the most direct competitors — the paper motivates S2A partly by arguing that training-based approaches are limited because they don't change how attention operates, but never empirically compares S2A to a model that has undergone such training.
- **Response refinement approaches** (self-refine, Constitutional AI). The paper distinguishes S2A from these methods conceptually but never runs a head-to-head comparison. Would applying self-refine to the baseline's sycophantic output recover some of the accuracy that S2A achieves? Without this comparison, the claim that context regeneration is *necessary* (rather than merely sufficient) for robustness against spurious context is unverified.
- **Retrieval-augmented approaches** that could provide the model with factual grounding to counteract opinionated context. If the model had access to a knowledge base entry for the queried fact, would it still be swayed by the injected opinion? This would test whether S2A's context regeneration provides benefits beyond what external knowledge grounding can achieve.

**The claim that S2A's improvements are due specifically to the hard attention / context removal mechanism** is well-supported by the S2A-KeepOrig ablation (74.5% vs. 80.3%) and the Instructed Prompting comparison (71.7% vs. 80.3%). The monotonic improvement as the original context is progressively removed or supplemented — Instructed (71.7%) → S2A-KeepOrig (74.5%) → S2A (80.3%) — provides converging evidence that physical removal of tokens matters. However, this evidence comes entirely from a single task (factual QA) with a single model on a 200-prompt test set. The paper does not run the KeepOrig ablation on the longform generation or GSM-IC tasks, so the generalizability of the hard-attention principle to those domains is asserted rather than demonstrated.

**The longform generation result — that S2A achieves higher objectivity than the oracle prompt (3.82 vs. 3.0) — is striking but under-supported.** The paper explains this as S2A also filtering opinionated language in the argument text itself, not just the injected sentiment statements. This is a post-hoc explanation; no experiment directly tests whether this is the mechanism. A targeted ablation would compare S2A's objectivity against a version of the oracle prompt where a human has also neutralized opinionated language in the argument text. Without this, the super-oracle result could be due to other factors — the S2A-regenerated context might be shorter or differently structured in ways that incidentally reduce sentiment, or the Step 2 "Answer in an unbiased way" instruction might operate differently when applied to regenerated vs. original context. The objectivity metric also deserves scrutiny: it is based on a GPT-4 evaluation of sentiment (Figure 11), and no human validation of these sentiment scores is reported. If GPT-4 has its own biases in sentiment detection, those biases could systematically affect the reported objectivity numbers in unknown ways.

**The math word problem results demonstrate a clear limitation: S2A's effectiveness drops substantially for in-topic distractors.** The gap between S2A and oracle is 1.4 percentage points for random distractors but 8.4 points for in-topic distractors. This means S2A's context regeneration fails to fully filter irrelevant sentences when those sentences share the same topic as the problem — exactly the case where the distinction between relevant and irrelevant is most subtle and where filtering is most needed. The paper does not analyze *why* S2A fails on these cases or provide examples of failures. Qualitative analysis of the 8.4-point residual gap — what does S2A's regenerated context look like when it fails? Does it keep the distractor, remove essential problem information, or introduce new errors? — would substantially strengthen the analysis and guide future improvements.

**Some experimental design choices limit the strength of conclusions:**

- **Single model family (LLaMA-2-70B-chat).** All experiments use the same model for both Step 1 and Step 2. The paper does not test whether S2A works with other instruction-tuned models (GPT-3.5, GPT-4, Claude, Mistral) or at different scales. The effectiveness of S2A depends on the model's ability to follow the filtering instruction in Step 1 — a capability that varies substantially across models. A weaker model might fail entirely at Step 1; a stronger model might make S2A unnecessary for some tasks. Without multi-model testing, the claim that S2A is a general technique rather than a property of LLaMA-2-70B-chat's specific instruction-following behavior is unverified.

- **Fixed decoding parameters.** All experiments use temperature 0.6 and top-p 0.9 for all methods. The baseline's vulnerability to context contamination might be temperature-dependent — higher temperatures could produce more variable (and potentially more robust) generations, while lower temperatures might increase sycophancy by reducing diversity. Conversely, S2A's Step 1 regeneration quality likely depends on temperature as well. No sensitivity analysis over generation parameters is reported.

- **Fixed prompt templates.** The paper uses specific, hand-crafted S2A prompts (Figures 2, 15) and acknowledges they were not optimized: "As our method is zero-shot prompted it largely depends on the choice of prompt, which we have not made great efforts to optimize." This means the reported results might substantially under- or over-estimate S2A's potential. A prompt sensitivity analysis — testing variations in wording, instruction format, or output structure — would clarify whether the improvements are robust to prompt formulation or are contingent on the specific templates used.

- **Small test sets with no statistical testing.** The factual QA and longform generation evaluations use 200 prompts each; GSM-IC uses 100 problems (with 3-seed averaging). No confidence intervals, standard errors, or significance tests are reported. Differences as small as 1–2 percentage points (e.g., S2A vs. S2A-NI: 80.3% vs. 79.3%) are discussed as meaningful without any assessment of whether they could arise from sampling variance. The per-category breakdowns further split these small samples (e.g., the Suggest Incorrect category in the factual QA task likely contains ~67 prompts if the three opinion types are roughly balanced), making fine-grained comparisons even less reliable.

- **No human evaluation.** All metrics are computed by GPT-4 using automated evaluation prompts (Figures 9, 10, 11). The factual QA accuracy evaluation compares model responses against ground-truth TriviaQA labels, which is relatively objective, but the longform generation quality and objectivity metrics are subjective judgments made by an LLM. No inter-annotator agreement between GPT-4 and human evaluators is reported, and no analysis of GPT-4's own potential biases in evaluating objectivity is provided. If GPT-4 tends to rate certain linguistic patterns as more or less objective regardless of actual content, the objectivity scores could reflect stylistic rather than substantive differences.

- **No cost analysis beyond qualitative description.** The paper states S2A requires "more computation than standard LLM regeneration" (Section 6) but provides no quantitative cost measurement — no token counts, latency measurements, or FLOP estimates for Step 1 vs. Step 2 vs. baseline generation. For a method whose primary overhead is computational, the absence of cost quantification makes it difficult for practitioners to evaluate the cost-benefit tradeoff. The comparison to chain-of-thought is qualitative ("somewhat analogous") and could be misleading — S2A requires two separate forward passes with distinct prompts, while chain-of-thought extends a single generation, and these have different computational profiles.

**The GSM-IC Instructed Prompting result (54.7%, worse than baseline's 56.3% for random distractors) raises an unexamined question.** The paper reports this as evidence that instructing the model to ignore irrelevant content doesn't work, but does not analyze why it *reduces* performance relative to baseline. One possibility: the instruction itself becomes additional context that the model must process, potentially crowding out relevant problem information or creating attention competition. Another: the instruction makes the model more aware of the distractor's presence, paradoxically increasing its influence. Without analysis, this negative result — which could inform understanding of how instructions interact with attention — remains unexplained.

**Missing experiments that would strengthen the evaluation:**

1. **S2A with a different base model** (e.g., GPT-3.5-turbo, which also failed on the Figure 1 example) to test whether the technique generalizes across model families.

2. **S2A with a fine-tuned context-cleaner model** (as suggested in Section 6) vs. the zero-shot prompted version, to quantify the gap between current and potential performance.

3. **Human evaluation of objectivity** on at least a subset of the longform generation outputs to validate the GPT-4-based metric.

4. **Latency and token-count measurements** for S2A vs. baseline vs. Instructed Prompting on representative prompts from each task.

5. **S2A-KeepOrig ablation on GSM-IC** to test whether the hard-attention principle generalizes beyond the opinion-filtering domain.

6. **Difficulty-stratified analysis** for GSM-IC: does S2A help more on problems where the baseline already had a chance of succeeding, or does it also help on problems the baseline gets completely wrong? This would reveal whether S2A amplifies existing reasoning or enables new reasoning.

**Summary of what the experiments do and do not establish:**

The experiments convincingly establish that S2A (zero-shot context regeneration + original context removal) substantially reduces the impact of injected opinions and irrelevant sentences on LLaMA-2-70B-chat's outputs across three task types, compared to doing nothing or simply instructing the model to ignore such content. The S2A-KeepOrig ablation provides compelling evidence that physical removal of the original context is a necessary component of this improvement, at least for the factual QA task. However, the experiments do not establish that S2A outperforms training-based debiasing approaches, response refinement methods, or retrieval-augmented alternatives; do not demonstrate generalizability beyond a single model family; do not quantify computational cost; and rely on automated metrics without human validation. The most robust finding is the hard-attention principle — that half-measures leaving noisy context in the attention window are insufficient — but this principle has been demonstrated on only one of the three tasks studied, limiting its claimed generality.

## 6. Limitations and Trade-offs

### Single Model Family, Single Scale

**The assumption or constraint.** All experiments — both the S2A context regeneration step and the final generation step — use LLaMA-2-70B-chat exclusively. The paper asserts that "we believe this model is representative of the capabilities of many contemporary LLMs" (Section 4), but provides no empirical evidence that S2A transfers to other model families (GPT-3.5, GPT-4, Claude, Mistral, Gemini) or to models at substantially different scales (7B, 13B, 405B, etc.). The zero-shot prompted nature of S2A means its effectiveness depends entirely on the base model's ability to follow the filtering instruction in Step 1, and this capability varies considerably across model families and scales. A model with weaker instruction-following might fail entirely at context regeneration — deleting essential information, hallucinating content, or failing to remove opinions — while a substantially stronger model might make S2A's filtering unnecessary for some tasks. Neither possibility is tested.

The paper also does not test whether the same model can serve as both the context regenerator and final responder, or whether using different models for each step (e.g., a stronger model for the delicate filtering task and a weaker one for final generation) would change results.

**The consequence.** A practitioner cannot determine from this paper whether S2A will work with their specific model. The technique could fail silently with a weaker instruction-follower (producing cleaned contexts that are incomplete, hallucinated, or still opinionated), or could provide negligible marginal benefit with a model that is already less susceptible to the specific failure modes tested. The absence of scale-dependence data is particularly important because the paper's central framing — that soft attention's vulnerability to spurious correlations is an *architectural* limitation requiring a procedural workaround — implies that S2A should help *all* Transformer-based LLMs. If S2A only works for models near LLaMA-2-70B-chat's capability level, the architectural claim would need qualification. Conversely, if S2A provides *more* benefit for weaker models (which are presumably more easily distracted), the headline numbers from a 70B-parameter model might underestimate its practical value.

**What evidence exists in the paper.** None. The paper provides zero experiments with any model other than LLaMA-2-70B-chat. Figure 1 shows that the motivating failure (the Saratoga/Sunnyvale birthplace question) affects multiple models (text-davinci-003, GPT-3.5-turbo, LLaMA-2-70B-chat), but S2A is never tested on any of those other models. The paper also does not ablate the effect of using different models for Step 1 vs. Step 2, nor does it test S2A at different model scales within the LLaMA-2 family.

**Mitigation status.** The paper does not claim generalizability across models, but it also does not flag single-model evaluation as a limitation. The Limitations section (Section 6) discusses copying errors for weaker models — "at least for weaker models, simply copying context may sometimes be error prone" — but this is about Step 1 copying fidelity, not about whether S2A's filtering behavior transfers across model families. No future work on multi-model evaluation is proposed.

### Difficulty Estimation and Filtering Cost Are Unaccounted for in the Headline Gains

**The assumption or constraint.** S2A requires the LLM to perform a full context-regeneration generation (Step 1) before producing the final response (Step 2). This doubles the number of sequential forward passes relative to standard generation — the model must complete Step 1 in its entirety before Step 2 can begin, because Step 2's prompt depends on Step 1's output. The paper acknowledges this cost qualitatively (Section 6) — "S2A requires more computation than standard LLM regeneration" — and notes it is "somewhat analogous to that incurred in methods like chain-of-thought," but provides **no quantitative measurements** of the overhead: no token counts for Step 1 vs. Step 2 vs. baseline, no wall-clock latency measurements, no FLOP accounting, and no analysis of how the cost scales with the proportion of context that must be copied (the paper notes that "copying a large relevant context will incur more computational cost").

This is not a minor omission. S2A's cost is structurally different from chain-of-thought's: CoT extends a single autoregressive generation with additional reasoning tokens, processed in one continuous forward pass (with KV-cache reuse). S2A requires two *separate* generations with distinct prompts — the first generation must finish and be post-processed before the second can begin. This means the KV-cache from Step 1 cannot be reused for Step 2 (the prompt structure is different), and the model must re-encode all the retained context tokens in Step 2. For a prompt where the original context is long and S2A retains most of it (as in the longform argument generation task, where the quoted argument text is preserved), the retained content is processed twice: once during Step 1 generation (as part of the input to the filtering step) and once during Step 2 generation (as part of the cleaned prompt). This is a ~2× cost multiplier on the context processing portion alone, plus the cost of generating the Step 1 output tokens.

**The consequence.** The headline efficiency numbers (e.g., "accuracy improved from 62.8% to 80.3%") report accuracy gains without normalizing by compute cost. A fair comparison would answer: at a fixed generation budget (in tokens or FLOPs), does S2A outperform simply spending that same budget on more baseline samples (best-of-N) or a longer chain-of-thought? For example, if S2A's Step 1 costs roughly as many tokens as generating a full baseline response, then S2A is competing against a baseline that could generate twice as many samples for the same cost. The paper never runs this comparison.

Additionally, the latency penalty of serial dependence matters for real-time applications. A user waiting for a response must wait for Step 1 to complete, then Step 2 to complete, sequentially. Best-of-N or longer CoT can be parallelized (multiple samples) or processed in a single generation. For interactive applications, the wall-clock latency of S2A could be substantially higher than the baseline even if total FLOPs are comparable.

**What evidence exists in the paper.** None. The paper provides no token counts, no latency benchmarks, no FLOP accounting, and no cost-normalized comparisons. The only cost-related statement is the qualitative acknowledgment in Section 6 quoted above, plus a suggestion that "speedup tricks, e.g., only generate the difference, or the parts not to include, or when copying large sections that have a label/section header, it could just reference the label instead" could mitigate the overhead — but none of these are implemented or evaluated.

**Mitigation status.** Not addressed. The speedup suggestions are deferred entirely to future work. A practitioner reading this paper cannot determine whether S2A's accuracy gains justify its computational overhead for their specific use case, because the paper provides no data with which to perform that cost-benefit calculation.

### No Evidence That S2A Outperforms Training-Based or Alternative Inference-Time Debiasing Approaches

**The assumption or constraint.** The paper's central argument is that spurious context correlations stem from an architectural limitation of soft attention, warranting a structural intervention (context regeneration + hard removal) rather than training-based fixes. However, the experiments compare S2A only against:

- An unmodified baseline (standard zero-shot generation)
- Instructed prompting (adding a debiasing instruction to the original prompt)
- Chain-of-thought prompting (adding "Let's think step by step")

These are the weakest possible baselines for the claim that S2A is *necessary* (not merely sufficient) because training-based approaches "patch symptoms rather than fixing the root cause." The paper explicitly motivates S2A by arguing that Sharma et al. (2023) and Wei et al. (2023) — who reduce sycophancy through supervised fine-tuning and reinforcement learning — are limited because "the underlying attention mechanism still distributes weight broadly across the context" (Section 1). Yet the paper never empirically compares S2A against a model that has undergone such sycophancy-reduction training.

This is a glaring omission. The SycophancyEval benchmark used in the paper's factual QA and longform experiments was developed by Sharma et al. (2023) specifically to evaluate sycophancy interventions. If a fine-tuned version of LLaMA-2-70B-chat (trained with the sycophancy-reduction procedures from Sharma et al. or Wei et al.) achieves comparable or better performance than S2A on the same prompts, then the paper's architectural argument is weakened — the problem *can* be substantially addressed through training, making S2A's additional inference cost harder to justify. Conversely, if the fine-tuned model still substantially underperforms S2A, that would strengthen the paper's central claim. Neither outcome is tested.

Similarly, the paper distinguishes S2A from response-refinement approaches (self-refine, Constitutional AI) conceptually but never runs a head-to-head comparison. Would applying self-refine to the baseline's sycophantic outputs recover accuracy comparable to S2A? The paper cannot say.

**The consequence.** The paper's claim that S2A addresses a fundamental architectural limitation — and that training-based approaches are inherently limited — rests on a theoretical argument rather than empirical evidence. A practitioner choosing between S2A and fine-tuning their model on anti-sycophancy data has no comparative data to guide the decision. The paper's contribution is positioned as a new *class* of technique (System 2 Attention) that is superior to existing approaches, but the experiments only demonstrate superiority over doing nothing and over simple prompt-based instructions — not over the most relevant prior work.

**What evidence exists in the paper.** None. The experiments include no baselines that involve model fine-tuning, reinforcement learning, response refinement, or any inference-time intervention other than S2A, instructed prompting, and chain-of-thought. The Related Work (Section 4) discusses Sharma et al. (2023), Wei et al. (2023), self-refine (Madaan et al., 2023), and Constitutional AI (Bai et al., 2022) as motivation, but these are never implemented as comparison baselines.

**Mitigation status.** Not addressed. The paper acknowledges in Section 6 that fine-tuning S2A outputs back into model weights would "likely be stronger" than zero-shot S2A, and that "if training data was available that indicated how to perform the task (mapping from original context to S2A regenerated context) then performance would likely be stronger." This acknowledges that the zero-shot results are a lower bound, but does not address the absence of comparisons to existing training-based methods. The paper does not propose future work on such comparisons.

### Hard-to-Filter Distractors Leave a Substantial Residual Gap, and Failure Modes Are Uncharacterized

**The assumption or constraint.** S2A's effectiveness depends critically on how distinguishable the irrelevant content is from the relevant content. When the distractor shares the same topic as the problem — as in the GSM-IC in-topic condition, where a sentence about "Max has 1000 more books than Mary" appears in a problem about Mary's candy count — S2A's context regeneration fails to fully filter the distractor, leaving an 8.4 percentage point gap to oracle performance (61.3% vs. 69.7%). This is a 53% gap-closure rate, compared to 89% for random distractors. The paper does not analyze *why* these failures occur or provide examples of the regenerated contexts that lead to incorrect answers.

This limitation is more consequential than it might appear because it exposes a fundamental tension in S2A's design: the model must distinguish **topical relevance** (the distractor sentence is about Mary, quantities, and comparisons — all relevant to the problem domain) from **logical relevance** (the distractor provides no information needed to compute the answer). This is a subtle semantic distinction that requires understanding the *structure* of the problem — which information is mathematically necessary — not just the topic. S2A's prompt for GSM-IC asks the model to extract "the part that is related and useful" (Figure 15), which conflates these two dimensions. A sentence can be topically related but logically useless, and the model must recognize this distinction to filter correctly.

**The consequence.** S2A provides the least help in exactly the cases where help is most needed. Random distractors are relatively easy to filter (they look obviously different from the problem content), and the baseline model is less harmed by them (56.3% accuracy). In-topic distractors are harder to filter *and* cause more baseline degradation (51.7%). The result is that S2A's benefit profile is inverted relative to the difficulty profile: large gains on the easier filtering task, smaller gains on the harder, more impactful one. A practitioner deploying S2A on real-world data — where distractors are likely to be topically related to the task (irrelevant details in a document about the same subject, off-topic comments in a conversation about the same issue) — might see gains closer to the 9.6 percentage point improvement (in-topic) rather than the 12.0 point improvement (random), and might still have a substantial fraction of queries where filtering fails.

Additionally, without characterization of the failure modes, a practitioner cannot anticipate *how* S2A will fail. Does it keep the distractor sentence in the regenerated context? Does it remove essential problem information along with the distractor? Does it hallucinate new, incorrect content? Each failure mode has different downstream consequences and would suggest different remediation strategies. The paper provides only a single successful example (Figure 3) and no failure examples for GSM-IC.

**What evidence exists in the paper.** The 8.4 percentage point residual gap for in-topic distractors (Figure 7, right) is the primary quantitative evidence. The paper provides no qualitative analysis of this gap — no examples of regenerated contexts for problems where S2A got the wrong answer, no categorization of failure types, and no analysis of whether the 3-seed averaging masks high variance (some seeds filtering correctly on a problem and others failing). The factual QA task shows a similar but smaller residual gap in the Suggest Incorrect category (S2A achieves 76% vs. oracle 82%), also without failure analysis.

**Mitigation status.** Not addressed. The paper does not discuss the in-topic filtering difficulty, does not analyze why the relevance-based prompt underperforms relative to the opinion-based prompt, and does not propose improvements to the filtering prompt or procedure for hard-to-distinguish distractors. The prompt sensitivity acknowledged in Section 6 — "As our method is zero-shot prompted it largely depends on the choice of prompt, which we have not made great efforts to optimize" — could partially explain the gap, but the paper does not test whether prompt optimization closes it.

### Small Fixed Test Sets Without Statistical Testing Limit Confidence in Reported Gains

**The assumption or constraint.** All experiments are evaluated on small, fixed test sets: 200 prompts for factual QA, 200 prompts for longform generation, and 100 problems (with 3-seed averaging) for GSM-IC. No confidence intervals, standard errors, or statistical significance tests are reported for any result. The per-category breakdowns in the ablation study (Figure 8) further subdivide these already-small samples — each of the three opinion types (Suggest Correct, Suggest Incorrect, Refute Correct) likely contains ~67 prompts if roughly balanced, and the individual bars in the per-category chart report accuracies on these ~67-prompt subsets.

This means that the reported differences between methods — some as small as 1–2 percentage points — are presented as meaningful without any assessment of whether they could arise from sampling variance. For example, the difference between S2A (80.3%) and S2A-NI (79.3%) is 1.0 percentage point. On a 200-prompt test set, this represents 2 additional correct answers for S2A. Whether this difference is statistically reliable depends on the variance of the estimator, which is not reported. Similarly, the per-category breakdown showing S2A-NI at 86% Suggest Correct vs. S2A at 82% — a 4-point difference on ~67 prompts, representing ~3 additional correct answers — is interpreted as evidence of residual sycophancy without any significance assessment.

The GSM-IC results use 3-seed averaging, which provides some protection against sampling noise in the autoregressive generation process but does not address the fixed test-set limitation — the 100 problems are still a single draw from the problem distribution, and the standard error of the mean across seeds cannot capture test-set sampling variance.

**The consequence.** The paper's fine-grained claims — particularly those in the ablation study about the relative importance of context/question separation (1.8 pp difference), the instructed prompting suffix (1.0 pp difference), and the per-category pattern of residual sycophancy — may not replicate on a different draw of test prompts or with a different random seed for generation. A practitioner cannot determine whether the reported ordering of variants (S2A > S2A-NI > S2A-Single > S2A-KeepOrig) reflects genuine performance differences or noise. The design recommendation that derives from these fine-grained comparisons — that the instructed prompting suffix helps calibrate the Suggest Correct category — is based on a 4-point difference on a ~67-prompt subset, which could easily be a sampling artifact.

More broadly, the absence of statistical rigor means the paper's conclusions about *which* design choices matter most cannot be evaluated for robustness. This is particularly problematic for a methods paper whose contribution includes design principles (hard attention is necessary, context regeneration is the primary mechanism) derived from relative performance comparisons.

**What evidence exists in the paper.** No standard errors, confidence intervals, or significance tests are reported anywhere. The only concession to variance is the 3-seed averaging for GSM-IC (Section 3.1.3: "In order to reduce variance, we average over 3 random seeds"), but even there, no variance estimate is reported. The test sets are described as fixed: "We evaluate on 200 prompts" (Section 3.1.1 and 3.1.2) and "100 problems chosen from GSM8K" (Section 3.1.3), with no cross-validation or bootstrap resampling.

**Mitigation status.** Not addressed. The paper does not acknowledge small test-set size or absence of statistical testing as a limitation, nor does it suggest future work with larger or more diverse evaluation sets. The Limitations section (Section 6) discusses prompt sensitivity, copying errors for weaker models, and computational cost, but does not mention evaluation robustness.

### Zero-Shot Prompt Dependence Without Sensitivity Analysis or Optimization

**The assumption or constraint.** S2A's entire filtering capability is mediated through a hand-crafted zero-shot prompt. The factual QA and longform tasks use one prompt (Figure 2); the GSM-IC task uses a different prompt (Figure 15); and the Step 2 instructed suffix uses yet another (Figure 13). The paper explicitly acknowledges that these prompts were not optimized: "As our method is zero-shot prompted it largely depends on the choice of prompt, which we have not made great efforts to optimize. Hence, there are likely much better choices than the ones given here" (Section 6).

This is more than a caveat — it is a fundamental uncertainty about the reported results. The paper provides no sensitivity analysis: no testing of alternative formulations of the filtering instruction, no ablation of specific phrasings within the prompt (e.g., "unbiased and not their opinion" vs. "factual and objective" vs. "neutral"), and no evaluation of how robust the improvements are to minor prompt variations. A practitioner who adapts S2A to their own task by writing a different prompt — which they must do, since the paper's prompts are task-specific — cannot predict from the paper's evidence whether their prompt will work, or whether small differences in wording will produce large differences in filtering quality.

This is particularly acute for the GSM-IC task, where S2A's filtering prompt asks the model to extract "the part that is related and useful." The paper's own results show this prompt leaves a substantial residual gap for in-topic distractors (61.3% vs. 69.7% oracle). Is this because the prompt is poorly worded for the in-topic case, or because the underlying distinction (topically related vs. logically relevant) is inherently difficult for the model? Without prompt variation experiments, these explanations are confounded. A differently worded prompt — e.g., one that explicitly distinguishes "information needed to solve the problem" from "information about related topics" — might substantially close the gap, or might perform identically. The paper provides no evidence either way.

**The consequence.** The reported performance numbers are best understood as a proof-of-concept with a particular, unoptimized prompt, not as an estimate of what S2A can achieve with prompt engineering. A practitioner cannot determine whether S2A's 80.3% factual QA accuracy is near the ceiling of what this approach can achieve, or whether a better prompt could push it to 85%+ (closing the remaining 1.7-point gap to oracle). Similarly, the 61.3% GSM-IC in-topic accuracy might represent a hard filtering-difficulty floor, or it might be substantially improvable through prompt optimization.

The ablation results in Figure 8, which compare S2A variants (S2A-Single, S2A-KeepOrig, S2A-NI) against each other, are also prompt-dependent. A different base S2A prompt might change the relative importance of context/question separation or the instructed prompting suffix. The design principles derived from these ablations are therefore contingent on the specific prompt template used — a limitation the paper does not discuss.

**What evidence exists in the paper.** The paper provides two different S2A prompt templates (opinion-focused and relevance-focused) and shows that both work for their respective tasks, which provides some evidence that S2A is not hypersensitive to prompt wording. However, no within-task prompt variation is tested. The paper also shows that Instructed Prompting (a different prompt that asks the model to answer in an unbiased way without context regeneration) underperforms S2A substantially (71.7% vs. 80.3%), which suggests the filtering instruction in S2A's prompt is doing something qualitatively different from a simple debiasing instruction. But this comparison changes both the task (filtering vs. answering) and the prompt simultaneously, so it does not isolate prompt sensitivity.

**Mitigation status.** The paper explicitly acknowledges prompt dependence (Section 6) and suggests that "if training data was available that indicated how to perform the task (mapping from original context to S2A regenerated context) then performance would likely be stronger," implying that fine-tuning would reduce prompt sensitivity. It also proposes distilling S2A outputs into model weights as future work. However, for the zero-shot setting that is the paper's entire contribution, no prompt sensitivity analysis is conducted or proposed as future work. A practitioner deploying zero-shot S2A must therefore treat the reported prompts as starting points requiring their own validation and likely iterative refinement, without guidance from the paper on which prompt features matter most.
