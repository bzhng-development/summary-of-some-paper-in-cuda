# TransNormerLLM: A Faster and Better Large Language Model with Improved TransNormer

**ArXiv:** [2307.14995](https://arxiv.org/abs/2307.14995)

## 🎯 Pitch

## 1. Executive Summary

This paper introduces **TransNormerLLM**, the first linear attention-based Large Language Model that surpasses conventional softmax attention-based models in both accuracy and efficiency, evolving the prior TransNormer architecture through a suite of targeted modifications. The model is validated on a self-collected 6TB pretraining corpus (over 2 trillion tokens) at scales of 385M, 1B, and 7B parameters, with scaling demonstrated up to 175B. The key mechanisms include **LRPE-d** (Linearized Relative Positional Encoding with exponential decay, which replaces DiagAttention to restore global token interactions while preventing attention dilution), **Lightning Attention** (an IO-aware block-level computation technique that accelerates linear attention by more than 2× in runtime and reduces memory usage by 4×), **Simple Gated Linear Units** (a gating mechanism that removes the activation function from GLU with no performance loss, yielding a 20% speedup), and **SimpleRMSNorm** (a simplified tensor normalization that matches standard normalization accuracy while being faster at large dimensions). Benchmark results on Commonsense Reasoning, MMLU, CMMLU, and C-Eval demonstrate that TransNormerLLM matches the performance of state-of-the-art Transformer-based LLMs at comparable sizes — for instance, the 7B model achieves 43.10% on MMLU and 47.99% on CMMLU — while maintaining constant inference time and memory footprint regardless of sequence length, establishing that linear attention can be a viable replacement for softmax attention in large-scale language modeling only when accompanied by carefully engineered positional encoding, gating, normalization, and IO-aware training optimizations.

## 2. Context and Motivation

### The Core Problem: Quadratic Complexity Makes Transformers Expensive at Scale

The fundamental problem this paper addresses is the **quadratic time and memory complexity** of the standard softmax attention mechanism with respect to sequence length. In a conventional Transformer, the attention computation for a sequence of length $n$ requires computing an $n \times n$ attention matrix — every token attends to every other token. The computational cost of this operation scales as $O(n^2 d)$, where $d$ is the representation dimension, and the memory required to store the attention matrix during training scales as $O(n^2)$. This quadratic scaling has profound consequences as language models grow:

- **Training becomes prohibitively expensive for long contexts.** A sequence of 8K tokens requires an attention matrix with 64 million entries. At 32K tokens, that jumps to over 1 billion entries. Training a 175B parameter model on long sequences strains even large clusters, as the paper documents in Table 14 (Section E.2): a Transformer-175B can only train with a context length of 10K tokens on 64 A100 80GB GPUs before hitting the memory ceiling.

- **Inference latency and memory grow with sequence length.** In autoregressive generation, each new token must attend to all previous tokens, making generation progressively slower as the output lengthens. For applications like document summarization, code generation, or multi-turn dialogue — where outputs routinely reach thousands of tokens — this growth becomes a deployment bottleneck.

- **The cost-per-token at inference depends on context length**, not just on the number of new tokens generated. This means that Transformer-based LLMs are most expensive precisely when they need to process the most information, creating a tension between capability (longer context for more complex tasks) and cost.

This problem is not merely academic. The widespread deployment of LLMs in latency-sensitive applications (chatbots, code assistants, real-time translation) and cost-sensitive batch processing (document analysis, data labeling) means that inference efficiency directly impacts economic viability. A model that maintains constant inference time and memory regardless of sequence length — as TransNormerLLM demonstrates in Figure 4 — fundamentally changes the cost structure of deploying large language models.

### The Gap: Linear Attention Has Been Promising in Theory but Disappointing in Practice

The research community has long recognized the quadratic complexity problem and has proposed numerous **efficient attention variants** that reduce the theoretical complexity to linear — $O(n d^2)$ rather than $O(n^2 d)$. The paper identifies four main families of alternatives in its Related Work (Section 2.2):

**Linear Transformers** decompose the softmax attention into an inner product of hidden representations, enabling the "right product trick": instead of computing $QK^\top$ (an $n \times n$ matrix) and then multiplying by $V$, they compute $K^\top V$ first (a $d \times d$ matrix) and then multiply by $Q$. Since the sequence length $n$ typically far exceeds the feature dimension $d$ in LLMs, this transforms an $O(n^2 d)$ operation into an $O(n d^2)$ operation — a substantial theoretical savings. Early linear attention methods include using $1+\text{elu}$ as an activation function (Katharopoulos et al., 2020) or cosine-based approximations of softmax (Qin et al., 2022b, the cosFormer).

The paper identifies two critical failures that have prevented linear attention from being adopted in production LLMs (Section 1, paragraph on efficient sequence modeling):

> "there are two reasons that prohibit them to be applied to LLMs: 1) their performance in language modeling is often unsatisfactory; 2) they do not demonstrate speed advantages in real-world scenarios."

Let us unpack both failures in detail.

**Failure 1: Unsatisfactory language modeling performance.** Linear attention removes the softmax normalization, which plays several critical roles in standard Transformers. The softmax acts as a competition mechanism — it forces attention weights to sum to 1, creating a relative importance distribution across tokens rather than absolute magnitudes. It also provides a form of automatic scaling: the division by $\sqrt{d}$ inside the softmax prevents the dot products from growing too large as the dimension increases. When you remove softmax, you lose both properties.

The practical consequence is what the paper calls **attention dilution**: in linear attention, the cumulative nature of the $K^\top V$ product (which sums over all previous tokens) means that early tokens' contributions get diluted as more tokens are added. A token at position 1000 contributes the same absolute magnitude to the attention sum as a token at position 1, but the cumulative sum is 1000× larger, effectively washing out recent, contextually relevant tokens. This is why the original TransNormer (Qin et al., 2022a) resorted to **DiagAttention** at lower layers — a restricted form of attention that limits each token to attending only to a local window, sacrificing global interactions to avoid dilution. But this local-only attention fundamentally limits the model's ability to capture long-range dependencies, which is the entire point of the Transformer architecture.

Additionally, most linear attention methods have struggled to match the representational quality of softmax attention. The paper's own baseline comparison (Table 1) shows that when comparing a standard Transformer to an unoptimized linear attention variant at 1B parameters, the Transformer achieves a lower loss — but the paper will show that this gap is not inherent to linear attention itself, but rather stems from missing components (positional encoding, gating, normalization) that the softmax provides implicitly.

**Failure 2: No real-world speed advantages.** This is the subtler and more damning critique. While linear attention has $O(n d^2)$ theoretical complexity versus $O(n^2 d)$ for softmax attention, theoretical complexity does not directly translate to wall-clock speed. The paper identifies three practical bottlenecks that have plagued prior linear attention implementations:

- **The cumsum problem in causal attention.** During training with causal masking, linear attention cannot simply do one matrix multiplication. To correctly enforce causality (token $t$ can only attend to tokens $1 \ldots t$), the computation requires a cumulative sum over the sequence dimension — computing $[K^\top V]_t = \sum_{i=1}^{t} k_i v_i^\top$ for each position $t$. A naive cumulative sum is inherently sequential and cannot be parallelized efficiently on GPUs, negating much of the theoretical speed advantage.

- **Poor IO utilization.** Modern GPU programming is not limited by raw FLOPs but by memory bandwidth — the time spent moving data between High Bandwidth Memory (HBM, the large but slow GPU memory) and on-chip SRAM (the small but fast compute memory). The paper identifies (Section 3.2.1) that standard implementations of linear attention, even when parallelized, make inefficient use of memory bandwidth because they repeatedly read and write large intermediate tensors to slow HBM. This is precisely the insight that motivated FlashAttention (Dao et al., 2022a) for softmax attention — and the paper applies the same IO-awareness principle to linear attention through its Lightning Attention algorithm.

- **Hidden constant factors.** The $O(n d^2)$ complexity has a constant factor that depends on implementation quality. For moderate sequence lengths where $n$ and $d$ are comparable (e.g., $n = 2048$, $d = 2048$), the theoretical advantage of $O(n d^2)$ over $O(n^2 d)$ is minimal or nonexistent because $n \approx d$. The advantage only becomes decisive when $n \gg d$, which requires both very long sequences and highly optimized implementations to realize.

These two failures — poor accuracy and illusory speed — have created a situation where, despite years of research into efficient attention mechanisms, essentially all production LLMs (GPT-3, GPT-4, LLaMA, PaLM, Falcon) continue to use standard softmax attention or minor variants of it (e.g., multi-query attention for inference optimization). As the paper notes in Section 2.1, even among large models, "only GPT-3 adopted" sparse attention, and that was a limited optimization. The field has lacked a linear attention variant that works *in practice* at LLM scale.

### TransNormerLLM's Position: Fix the Missing Pieces, Not Replace the Core Idea

The paper positions TransNormerLLM not as a radical new architecture but as an **evolutionary improvement** that fixes the specific shortcomings that prevented prior linear attention models from scaling. It builds on the TransNormer architecture (Qin et al., 2022a) as its starting point, but the improvements are not incremental tweaks — each addresses a specific failure mode identified in prior work:

**From DiagAttention to LRPE-d (Section 3.1.1).** The original TransNormer used DiagAttention at lower layers to avoid dilution, sacrificing global interactions. TransNormerLLM instead introduces LRPE-d — Linearized Relative Positional Encoding with exponential decay. The key insight is that rather than *restricting* attention locally, you can *bias* it toward recent tokens using an exponentially decaying weight $\lambda^{s-t}$ (where $s$ is the query position and $t$ is the key position, with $s \ge t$ in causal attention). This decay naturally prevents dilution because recent tokens contribute more strongly to the attention sum, while still allowing long-range interactions (the weight never reaches zero). The LRPE component adds a rotary position encoding that is itself linearizable — it can be decomposed into terms depending only on $s$ or only on $t$, preserving the right-product trick.

Critically, the decay rate $\lambda$ is not uniform across the model. Equation 2 defines:

$$\lambda = \exp\left(-\frac{8h}{H} \times \left(1 - \frac{l}{L}\right)\right)$$

where $h$ is the head index, $H$ is the total number of heads, $l$ is the layer index, and $L$ is the total number of layers. This means: (1) within a layer, different heads have different decay rates (controlled by $h/H$), creating a multi-scale temporal representation — some heads focus on very recent tokens, others retain longer history; and (2) lower layers have faster decay (smaller $\lambda$, more local focus) while higher layers have slower decay (larger $\lambda$, approaching 1.0 at the final layer, allowing global attention). This design directly addresses the "lack of global interactions" criticism of the original TransNormer while maintaining the anti-dilution benefits of position-based biasing.

**From ad-hoc implementations to IO-aware Lightning Attention (Section 3.2.1).** The paper recognizes that the cumsum bottleneck in causal linear attention training is fundamentally an IO problem, not a compute problem. Lightning Attention applies the tiling strategy pioneered by FlashAttention: split the $Q$, $K$, $V$ matrices into blocks, load each block pair into fast SRAM, compute the local attention contribution, and accumulate results. The key difference from FlashAttention is that Lightning Attention computes $O = (QK^\top \odot M)V$ (where $M$ is the causal mask incorporating positional encoding) using block-level tiling that avoids materializing the full $n \times n$ attention matrix. The forward pass (Algorithm 3 in Appendix B) divides $Q$ into $T_r = n/B_r$ row blocks and $K$, $V$ into $T_c = n/B_c$ column blocks, then iterates over block pairs, keeping intermediate accumulation in SRAM. The backward pass (Algorithm 4) follows a similar tiled strategy for gradient computation.

This yields the concrete speed and memory improvements shown in Figure 3: at sequence length 8192, Lightning Attention runs more than 2× faster than the baseline PyTorch linear attention implementation, and uses 4× less memory. These are not theoretical complexity improvements — they are measured wall-clock and memory improvements that directly translate to throughput gains during training.

**From bare linear attention to Gated Linear Attention (Section 3.1.2).** The paper introduces a gating mechanism drawn from Flash (Hua et al., 2022), where the token mixing output is modulated by an input-dependent gate:

$$\text{TokenMixer}: O = \text{Norm}(QK^\top V) \odot U$$

where $U = XW_u$ is a learned gating signal. This provides a mechanism for the model to learn *when* to use the attention output and when to suppress it — analogous to how the output gate in an LSTM controls the flow of information. The gating is particularly important for training stability: Table 5 shows that adding the gate reduces loss from 2.263 to 2.248, a small but meaningful improvement, but the qualitative benefit is smoother training dynamics that prevent the loss spikes and NaN issues that have plagued prior linear attention models.

**From RMSNorm to SimpleRMSNorm (Section 3.1.3).** Normalization is a critical but often overlooked component of Transformer training. The original TransNormer used NormAttention — normalizing the attention output by its L2 norm — to replace the softmax's implicit normalization. TransNormerLLM simplifies the normalizer from RMSNorm to SimpleRMSNorm:

$$\text{SRMSNorm}(x) = \frac{x}{\|x\|_2 / \sqrt{d}}$$

This removes the learned scaling and shifting parameters present in RMSNorm, using only the raw normalized values. Table 8 shows this simplification causes no performance degradation (PPL of 4.770 for SRMSNorm vs. 4.766 for RMSNorm), and Figure 2 demonstrates that SRMSNorm implemented in Triton is significantly faster than the equivalent PyTorch RMSNorm at large feature dimensions — contributing a 20% overall speedup to the model.

**The SGLU simplification in channel mixing.** The paper observes that the gating mechanism in GLU — multiplying the output of a linear transformation by the output of another linear transformation passed through an activation function — already introduces non-linearity through the multiplicative gate. Therefore, the activation function on the gating branch is redundant. TransNormerLLM's SGLU removes it:

$$\text{SGLU}: O = [V \odot U]W_o, \quad V = XW_v, \quad U = XW_u$$

Table 7 confirms no performance loss from removing the activation (PPL 4.770 without vs. 4.788 with Swish), while saving computation.

### How This Paper Differs from Prior Work

The paper's contribution is best understood by contrasting it with three lines of prior work:

**Against prior linear attention models** (e.g., Linear Transformer by Katharopoulos et al., cosFormer by Qin et al., Performer by Choromanski et al.): These models demonstrated the theoretical feasibility of linear attention but were evaluated on relatively small-scale tasks with moderate sequence lengths. They did not address the engineering challenges (IO-aware computation, distributed training, inference stability) required to scale to billions of parameters and trillions of training tokens. TransNormerLLM is, by the paper's claim, "the first linear attention-based Large Language Model (LLM) that outperforms conventional softmax attention-based models in terms of both accuracy and efficiency" (abstract). Whether the benchmark results fully support "outperforms" is debatable — the model matches rather than clearly exceeds the best Transformer-based models — but the key distinction is that TransNormerLLM is demonstrated at true LLM scale (up to 175B parameters) with competitive performance on standard benchmarks.

**Against state space models** (e.g., S4, H3, Mamba): State space models also achieve linear or near-linear complexity and have shown strong performance on long-range sequence modeling. However, they are based on a fundamentally different mathematical framework (state space equations with special initializations) that makes them less directly compatible with the Transformer ecosystem (layer designs, parallelism strategies, training recipes). TransNormerLLM retains the Transformer's basic block structure (attention-like token mixing + MLP-like channel mixing) with linearized attention, making it a drop-in replacement that benefits from the extensive engineering investment in Transformer training infrastructure.

**Against linear RNNs** (specifically RWKV, Peng et al., 2023b): RWKV is the closest competitor — a linear RNN-based LLM that has shown competitive performance against similarly scaled Transformers. The paper acknowledges RWKV as a notable example in Section 2.2 and includes it in the benchmark comparisons (Table 9). TransNormerLLM differs from RWKV in its attention formulation: RWKV uses a time-mixing mechanism that resembles an RNN update, while TransNormerLLM maintains the explicit query-key-value attention structure but linearizes it. The paper does not claim superiority over RWKV — in fact, the benchmarks show comparable performance — but rather positions TransNormerLLM as an alternative point in the design space of efficient LLM architectures, with its own set of trade-offs.

### The Practical Stakes: Why "Linear Attention That Actually Works" Matters Now

The timing of this paper is not accidental. Several converging trends make efficient attention architectures urgent:

- **Context length demands are exploding.** Models like GPT-4 and Claude now offer 100K+ token context windows. Training and serving these models with quadratic attention is becoming economically prohibitive. A linear attention model that truly maintains constant inference time with sequence length (Figure 4) becomes increasingly attractive as context windows grow.

- **The open-source LLM ecosystem needs diversity.** As the paper's benchmark table (Table 9) illustrates, the open-source LLM landscape is dominated by Transformer-based models (LLaMA, Falcon, MPT, Baichuan, ChatGLM). Having a competitive non-Transformer architecture provides architectural diversity, which is valuable for ensemble methods, for deployment scenarios where Transformer inference is bottlenecked, and for research exploring the space of possible architectures.

- **Inference efficiency determines deployment feasibility.** As LLMs move from research demos to production services, inference costs dominate total cost of ownership. A model that is 1.35× faster at training (Table 14, 175B model) and has constant inference time regardless of context is directly more economical to serve at scale. The paper's stress tests (Appendix E.2) showing TransNormerLLM achieving 12K context length vs. 10K for Transformer at 175B scale, with 1.35× higher throughput, translate directly to serving more users with the same hardware.

The paper thus addresses a gap that is simultaneously theoretical (can linear attention match softmax attention in representational quality?), engineering (can linear attention be made fast on real hardware, not just in asymptotic analysis?), and practical (can a linear attention LLM compete with Transformer-based LLMs on standard benchmarks?). Its answer to all three is a qualified yes: the representational gap can be closed through careful design of position encoding and gating, the engineering gap through IO-aware computation and simplified components, and the practical gap through demonstration at scale on standard benchmarks — while acknowledging that the hardest cases (the largest models, the longest sequences, the most demanding benchmarks) remain an open frontier.

## 3. Technical Approach

This section is the longest and most detailed in the analysis. We will systematically unpack every component of TransNormerLLM — what it does, how it works, why each design choice was made, and what the alternatives were. The goal is for the reader to fully understand the architecture, training optimizations, and inference procedure without needing to consult the original paper.

### 3.1 Reader Orientation

TransNormerLLM is a large language model architecture that **replaces the standard quadratic-complexity softmax attention** of Transformers with a **linear-complexity attention mechanism** while matching or exceeding Transformer performance through a carefully designed suite of complementary improvements. The core problem it solves is the $O(n^2)$ computational and memory cost of standard attention, which makes Transformers expensive to train on long sequences and costly to serve at scale. The shape of the solution is not a single algorithmic breakthrough but rather **five coordinated modifications** — positional encoding, gating, normalization, IO-aware computation, and numerically stable inference — each addressing a specific failure mode that prevented prior linear attention models from working at LLM scale.

### 3.2 Big-Picture Architecture (Diagram in Words)

The TransNormerLLM architecture processes a sequence of token embeddings through a stack of identical transformer-like blocks. Each block has two sub-layers connected by residual connections and pre-normalization:

1. **Input tokens** (a sequence of $n$ vectors, each of dimension $d$) enter the block.

2. **First sub-layer (Token Mixing):** The input passes through **SimpleRMSNorm** (a simplified normalization), then enters **Gated Linear Attention (GLA)** . Inside GLA, the normalized input is projected into four matrices — Query ($Q$), Key ($K$), Value ($V$), and a gating signal ($U$) — using learned weight matrices. The linear attention computes $\text{Norm}(QK^\top V)$ using the "right product trick" ($K^\top V$ first, costing $O(n d^2)$ instead of $O(n^2 d)$), then element-wise multiplies this output by the gate $U$. The result is added back to the input via a residual connection.

3. **Second sub-layer (Channel Mixing):** The output of the first sub-layer passes through **SimpleRMSNorm** again, then enters **Simple Gated Linear Unit (SGLU)** . SGLU projects the input into two matrices ($V$ and $U$), element-wise multiplies them, and projects the result back to dimension $d$. This is added back via a residual connection.

4. **Positional information** is injected through **LRPE-d** (Linearized Relative Positional Encoding with exponential decay), which is applied at the first layer (with learned rotary components and a decay factor $\lambda^{s-t}$) while subsequent layers use only the exponential decay. The decay rate varies across heads and layers according to a structured formula.

5. **During training**, the attention computation uses **Lightning Attention** — an IO-aware tiled algorithm that splits $Q$, $K$, $V$ into blocks, processes them in fast on-chip SRAM, and avoids materializing the full $n \times n$ attention matrix. This achieves >2× speedup and 4× memory reduction over standard linear attention implementations.

6. **During inference**, the model operates as a **recurrent neural network**: the $K^\top V$ matrix is updated incrementally as each new token arrives, requiring only $O(d^2)$ work per token regardless of sequence length. A **robust inference algorithm** prevents numerical instability from the exponential decay factors.

The model is trained using **Fully Sharded Data Parallelism (FSDP)** and **model parallelism** adapted specifically for linear attention, enabling scaling to 175B parameters across large GPU clusters.

#### The Linear Attention Mechanism: Core Computation

The paper's attention mechanism builds on the NormAttention introduced in the original TransNormer (Qin et al., 2022a). In a standard Transformer, the attention operation for a single head is:

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d}}\right)V$$

where $Q, K, V \in \mathbb{R}^{n \times d}$ are the query, key, and value matrices (each row is a token's representation), and $n$ is the sequence length. The softmax is applied row-wise to the $n \times n$ matrix $QK^\top/\sqrt{d}$, producing attention weights that sum to 1 for each query position.

The computation requires:
- Computing $QK^\top$: an $n \times n$ matrix multiplication costing $O(n^2 d)$ operations
- Applying softmax: $O(n^2)$ operations
- Multiplying by $V$: $O(n^2 d)$ operations
- Storing the attention matrix: $O(n^2)$ memory

The key bottleneck is the $n \times n$ intermediate matrix. For a sequence of 8,192 tokens with $d = 2048$, this matrix has over 67 million entries. For 32,768 tokens, over 1 billion entries.

**NormAttention** removes the softmax entirely and applies L2 normalization instead:

$$O = \text{Norm}((QK^\top)V)$$

where $\text{Norm}$ applies some normalization (discussed in the normalization section below). Without softmax, the computation becomes a simple sequence of matrix multiplications.

**The right-product trick.** The critical insight of linear attention is the associative property of matrix multiplication: $(QK^\top)V = Q(K^\top V)$. The left-hand side computes $QK^\top$ first (an $n \times n$ matrix, costing $O(n^2 d)$). The right-hand side computes $K^\top V$ first (a $d \times d$ matrix, costing $O(n d^2)$), then multiplies by $Q$ (another $O(n d^2)$). The total cost is $O(n d^2)$ rather than $O(n^2 d)$. Since $d$ is typically 1024–4096 in LLMs while $n$ can be 8K–100K+, the savings are substantial when $n \gg d$.

The paper writes the token-mixing equation as:

$$O = \text{Norm}(QK^\top V)$$

and notes (Section 3.1.3):

> "This linear form allows for recurrent prediction with a complexity of $O(n d^2)$, making it efficient during inference. Specifically, we only update $K^\top V$ in a recurrent manner without computing the full attention matrix."

**What this means operationally:** During autoregressive generation, when a new token arrives at position $t$, we compute its query $q_t$, key $k_t$, and value $v_t$ (each vectors of dimension $d$). We update the running $d \times d$ matrix $[KV]_t = [KV]_{t-1} + k_t v_t^\top$, then compute the output as $o_t = q_t [KV]_t$. Each step costs $O(d^2)$, independent of $t$. This is fundamentally different from softmax attention, where each new token must attend to all previous tokens, costing $O(t d)$ per step and growing linearly with sequence length.

**Incorporating causal masking and positional encoding.** In practice, the attention computation during training must enforce causality (token $t$ can only attend to positions $\leq t$) and incorporate positional information. The paper writes the full training-time attention as:

$$O = (QK^\top \odot M)V$$

where $M \in \mathbb{R}^{n \times n}$ is a mask matrix that combines the lower-triangular causal mask (entries above the diagonal are 0, entries on or below are 1 or incorporate positional decay) with positional encoding. The $\odot$ denotes element-wise multiplication. This is the form that Lightning Attention optimizes (discussed later).

#### LRPE-d: Linearized Relative Positional Encoding with Exponential Decay

**The problem being solved.** In the original TransNormer, DiagAttention was used at lower layers — each token attended only to a local window of neighboring tokens — to avoid **attention dilution**: in linear attention without softmax, as the sequence grows longer, the cumulative $K^\top V$ matrix sums over more tokens, and the contribution of any individual token (especially recent, contextually relevant ones) gets washed out. The mathematical issue is that $\|K^\top V\|$ grows approximately linearly with sequence length (since it is a sum of $n$ outer products), while the query vector $q_t$ has roughly constant norm. The output $q_t(K^\top V)$ therefore becomes dominated by the accumulated magnitude rather than the semantic content of the $q_t, k_i$ dot products.

DiagAttention solves this by restricting attention locally, but at the cost of losing global interactions — the model cannot relate distant tokens, which is the entire motivation for attention mechanisms over recurrent models.

**The LRPE-d solution.** Instead of restricting attention spatially, LRPE-d biases attention toward recent tokens using **exponentially decaying weights**, while still allowing long-range attention. The attention score between query at position $s$ and key at position $t$ (with $s \ge t$ in causal attention) is:

$$a_{st} = q_s^\top k_t \lambda^{s-t} \exp(i\theta(s-t))$$

where:
- $q_s, k_t \in \mathbb{R}^d$ are the query and key vectors at positions $s$ and $t$
- $\lambda \in (0, 1]$ is the exponential decay factor — smaller $\lambda$ means faster decay, making the model more locally focused
- $\theta$ is a learned rotary position encoding parameter
- $\exp(i\theta(s-t))$ is the complex-valued rotation that encodes relative position (standard RoPE-style encoding)
- The product $q_s^\top k_t$ is the standard dot-product attention score (content-based)
- $\lambda^{s-t}$ multiplicatively downweights tokens that are farther in the past (larger $s-t$)

**What this computes operationally.** For a query at position $s$ attending to a key at position $t$, the attention score is the content-based similarity $q_s^\top k_t$ multiplied by a decay factor $\lambda^{s-t}$ and rotated by the relative position $\theta(s-t)$. Tokens that are close in sequence (small $s-t$) contribute with weight near 1; tokens far in the past (large $s-t$) contribute with weight near 0 (if $\lambda < 1$) but never exactly 0 — long-range interactions are always possible, just attenuated.

**The critical property: decomposability for the right-product trick.** The key insight that makes LRPE-d compatible with linear attention is that the exponential decay and rotary encoding can be factored into terms depending only on $s$ or only on $t$:

$$a_{st} = (q_s \lambda^s \exp(i\theta s))^\top (k_t \lambda^{-t} \exp(-i\theta t))$$

This means we can absorb the position-dependent factors into the query and key vectors before computing attention: define $\tilde{q}_s = q_s \lambda^s \exp(i\theta s)$ and $\tilde{k}_t = k_t \lambda^{-t} \exp(-i\theta t)$. Then $a_{st} = \tilde{q}_s^\top \tilde{k}_t$, and the standard linear attention computation works with $\tilde{Q}$ and $\tilde{K}$ replacing $Q$ and $K$.

The paper notes:

> "this position encoding is fully compatible with Linear Attention, as it can be decomposed with respect to $s$ and $t$ separately" (Section 3.1.1)

**The structured decay schedule across heads and layers.** Instead of using a single $\lambda$ for all attention heads, the paper defines a structured schedule (Equation 2):

$$\lambda = \exp\left(-\frac{8h}{H} \times \left(1 - \frac{l}{L}\right)\right)$$

where:
- $h \in \{1, \ldots, H\}$ is the head index within a layer
- $H$ is the total number of attention heads
- $l \in \{1, \ldots, L\}$ is the layer index
- $L$ is the total number of layers

This formula produces a systematic variation:
- **Within a layer**, the factor $8h/H$ means heads with larger indices $h$ have larger $8h/H$, hence smaller $\lambda$ (faster decay, more local focus). Head 1 has $8/H$ (very slow decay, near-global), head $H$ has $8$ (very fast decay, highly local). This creates a multi-scale representation where different heads specialize to different temporal ranges — some capture very recent context, others retain longer history.

- **Across layers**, the factor $(1 - l/L)$ means lower layers (small $l$) have smaller $\lambda$ (more local focus), and higher layers (large $l$) have larger $\lambda$ approaching 1.0. At the top layer ($l = L$), $(1 - L/L) = 0$, so the exponent is 0 regardless of $h$, meaning $\lambda = 1$ — **all heads in the final layer attend globally without decay**. This aligns with the original TransNormer's design principle that lower layers should have smaller Theoretical Receptive Fields (TRF) while higher layers integrate information globally.

The constant 8 in the numerator controls the overall dynamic range of decay rates. The paper states that $\lambda$ is **non-learnable** because:

> "we empirically found that gradients become unstable when $\lambda$ is learnable, leading to NaN values" (Section 3.1.1)

This is an important practical finding: while learnable positional encodings are common (e.g., learned absolute position embeddings in BERT), making the decay rate learnable introduces training instability in linear attention, likely because the gradient of $\lambda$ interacts with the cumulative $K^\top V$ product in ways that amplify small changes into exploding values.

**The Mix positional encoding: LRPE-d at first layer, pure exponential decay elsewhere.** The paper empirically finds that applying the full LRPE-d (with the complex rotation $\exp(i\theta(s-t))$) to every layer is unnecessary and computationally expensive. Instead, they propose a "Mix" strategy:

> "applying it to the first layer and keeping other layers with exponential decay can speed up training by approximately 15-20% but only with a subtle effect on the performance" (Section 3.1.1)

The full LRPE-d adds computational overhead because the complex rotation requires computing trigonometric functions and performing complex-valued multiplications (or their real-valued equivalents) for every query-key pair. By restricting the learned rotary component to the first layer, where it provides the most benefit (establishing initial positional representations), and using only the scalar exponential decay in subsequent layers, the model recovers most of the accuracy benefit while substantially reducing computation. Table 3 quantifies this: "Mix" achieves PPL 4.770 (essentially tied with pure LRPE-d at 4.728) while being 15-20% faster.

**Why exponential decay prevents dilution.** The dilution problem in linear attention arises because the $K^\top V$ sum grows unboundedly with sequence length. With exponential decay, the effective contribution of past tokens is bounded: $\sum_{i=1}^{\infty} \lambda^i = \lambda/(1-\lambda)$ is finite for $\lambda < 1$. This means the cumulative sum does not grow without bound — it reaches a steady state where new tokens are added and very old tokens are effectively forgotten. The model thus maintains a "running summary" of recent context with controllable length, parameterized by $\lambda$.

**Ablation on the temperature term.** The $(1 - l/L)$ factor is called the "decay temperature" in the paper. An ablation (Table 4) shows that removing this term (making $\lambda$ uniform across layers) increases PPL from 4.770 to 4.804 — a small but consistent degradation, confirming that the layer-dependent decay schedule is beneficial.

#### Gating Mechanisms: Gated Linear Attention and Simple GLU

**Why gating matters for linear attention.** Standard softmax attention includes an implicit gating mechanism through the softmax normalization: attention weights are forced to sum to 1, so the model must decide how to *distribute* a fixed amount of attention across tokens. If one token receives high attention, others get lower attention — this is a form of competition that acts as a soft selection mechanism. Linear attention removes this constraint: the unnormalized attention scores can be arbitrarily large or small, and there is no mechanism forcing the model to be selective about which information to pass through.

Gating provides an alternative selectivity mechanism. Instead of competing for a fixed attention budget, the gate learns to *modulate* the attention output — amplifying useful information and suppressing irrelevant or noisy contributions.

**Gated Linear Attention (GLA).** The token mixing output is computed as:

$$O = \text{Norm}(QK^\top V) \odot U$$

where:
- $Q = \phi(XW_q)$, $K = \phi(XW_k)$, $V = XW_v$, $U = XW_u$
- $X \in \mathbb{R}^{n \times d}$ is the input to the attention block
- $W_q, W_k, W_v, W_u \in \mathbb{R}^{d \times d}$ are learned projection matrices
- $\phi$ is an activation function (chosen to be Swish)
- $\text{Norm}$ is the normalization function (SRMSNorm or equivalent)
- $\odot$ is element-wise (Hadamard) multiplication

**What this computes operationally.** The input $X$ is first normalized, then projected four ways. $Q$ and $K$ pass through the Swish activation function before computing attention (because linear attention without activation can produce unbounded values, and the activation constrains the range). $V$ and $U$ do not use activation — $V$ contains the values to be aggregated, and $U$ provides the gating signal. The attention $QK^\top V$ aggregates information across tokens, and the gate $U$ element-wise modulates this aggregated output — each dimension of the output can be independently amplified or suppressed based on the current input. The gating is input-dependent: different tokens at different positions produce different gating signals, allowing context-conditional information routing.

**Why this form and not others.** The GLA structure is adopted from Flash (Hua et al., 2022), which demonstrated that gating improves the performance of linear attention models. The key advantage over ungated linear attention is training stability and representational capacity. Table 5 quantifies the benefit: adding the gate reduces loss from 2.263 to 2.248 (PPL improvement from 4.820 to 4.770). While the absolute improvement seems small, the qualitative effect on training dynamics is significant — gating helps prevent the loss spikes and NaN issues that have historically plagued linear attention models at scale.

The choice of Swish ($\phi(x) = x \cdot \sigma(x)$, where $\sigma$ is the sigmoid function) as the activation for $Q$ and $K$ is empirical. Table 6 shows that Swish (PPL 4.770) and 1+elu (PPL 4.767) perform similarly, while removing the activation entirely degrades to PPL 4.882. The paper notes that:

> "using 1+elu in our 7B model may encounter a NaN problem, so we use Swish in our model" (Section on GLA Activation Functions)

This is an important practical observation: 1+elu has a minimum value of approximately -0.632 (since elu(x) → -1 as x → -∞, plus 1 gives a minimum near 0 for very negative inputs but actually the minimum of $1+\text{elu}(x)$ is approximately 0 when $x$ is very negative because $\text{elu}(x) = \alpha(\exp(x)-1)$ for $x < 0$ with $\alpha=1$ gives $\text{elu}(x) \to -1$ as $x \to -\infty$, so $1+\text{elu}(x) \to 0$), which may cause gradient issues in the cumulative $K^\top V$ product. Swish is bounded below by approximately -0.278 (its minimum occurs at $x \approx -1.3$) and grows approximately linearly for positive inputs, providing a better balance of non-linearity and gradient flow.

**Simple Gated Linear Unit (SGLU) for channel mixing.** The channel mixing (feed-forward) component in standard Transformers typically uses a two-layer MLP with an activation function. GLU (Gated Linear Unit) variants improve on this by using a gating mechanism:

$$\text{Standard GLU: } O = [\phi(XW_v) \odot (XW_u)]W_o$$

where $\phi$ is an activation function (typically SiLU/Swish). The paper's key observation is that the element-wise multiplication $\odot$ itself introduces non-linearity — the product of two linear transformations is quadratic in the input. Therefore, the activation function on the gating branch is redundant:

$$\text{SGLU: } O = [V \odot U]W_o, \quad V = XW_v, \quad U = XW_u$$

where no activation function is applied to either $V$ or $U$.

**What this computes operationally.** The input $X$ is projected into two matrices $V$ and $U$ of the same shape. These are multiplied element-wise — each entry of $V$ scales the corresponding entry of $U$ (or vice versa). The result is projected back to dimension $d$ via $W_o$. The element-wise multiplication means that if either $V_{ij}$ or $U_{ij}$ is near zero, the output at that position is near zero — this is a multiplicative gate, whereas an activation function is an additive non-linearity.

**Why removing the activation works.** Table 7 confirms that SGLU (no activation, PPL 4.770) performs identically to GLU with Swish (PPL 4.788), and slightly better in this experiment. The intuition is that the multiplicative interaction between $V$ and $U$ already provides sufficient non-linearity: the function $f(v, u) = v \cdot u$ is not linear in the input $X$ because both $v$ and $u$ are linear functions of $X$, making $v \cdot u$ a quadratic form. Removing the activation saves computation — one fewer activation function evaluation per token — which contributes to the overall speedup.

#### SimpleRMSNorm: Simplified Tensor Normalization

**The role of normalization in linear attention.** In standard softmax attention, the division by $\sqrt{d}$ and the softmax operation provide implicit normalization: attention weights sum to 1, and the output magnitude is roughly controlled. In linear attention without softmax, there is no such automatic normalization, and the magnitude of $(QK^\top)V$ can grow with sequence length, feature dimension, and the norms of the learned projections. Uncontrolled magnitude growth leads to training instability and poor gradient flow.

The original TransNormer introduced NormAttention:

$$O = \text{Norm}((QK^\top)V)$$

where Norm applies normalization along the feature dimension for each token independently. The paper does not fully specify the original NormAttention normalization, but the context suggests it used RMSNorm (Root Mean Square Normalization), which normalizes by the root mean square of the features:

$$\text{RMSNorm}(x) = \frac{x}{\text{RMS}(x)} \cdot \gamma, \quad \text{RMS}(x) = \sqrt{\frac{1}{d}\sum_{i=1}^d x_i^2}$$

where $\gamma$ is a learnable scale parameter.

**SimpleRMSNorm (SRMSNorm)** removes the learnable scale parameter:

$$\text{SRMSNorm}(x) = \frac{x}{\|x\|_2 / \sqrt{d}}$$

where $\|x\|_2 = \sqrt{\sum_{i=1}^d x_i^2}$ is the L2 norm.

**What this computes operationally.** For a vector $x \in \mathbb{R}^d$, SRMSNorm divides each element by the L2 norm divided by $\sqrt{d}$. Equivalently, it divides by the root mean square (since $\text{RMS}(x) = \|x\|_2 / \sqrt{d}$). The result is a vector with RMS = 1, meaning the average squared value is 1. Unlike RMSNorm, there is no learned scaling — the normalized values are used directly.

**Why the simplified version works equally well.** Table 8 shows that SRMSNorm (PPL 4.770), RMSNorm (PPL 4.766), and LayerNorm (PPL 4.765) produce essentially identical results. This suggests that, in the context of linear attention with the other normalization mechanisms already present (the Norm in NormAttention, the residual connections), the learnable scale parameter in RMSNorm is not providing meaningful additional capacity. Removing it simplifies the computation and, crucially, enables a more efficient Triton kernel implementation.

**The Triton implementation and speedup.** Figure 2 demonstrates that a custom Triton implementation of SRMSNorm is substantially faster than the PyTorch implementation, especially at large feature dimensions. At dimension 16,384, the Triton implementation is approximately 2× faster in both forward and backward passes. The speedup comes from two factors: (1) fused operations — the Triton kernel combines the normalization and the element-wise division in a single pass over the data, avoiding intermediate allocations; and (2) the simpler computation (no learned parameters means no gradient computation for $\gamma$, and no need to load/store $\gamma$).

The paper reports that this normalization improvement contributes to an "impressive acceleration of over 20%" for the overall model. This 20% figure is the cumulative effect of both the simplified normalization and the Mix positional encoding (which by itself provides 15-20% speedup, as noted earlier).

#### Lightning Attention: IO-Aware Training Algorithm

**The fundamental challenge.** The theoretical $O(n d^2)$ complexity of linear attention assumes we can efficiently compute $Q(K^\top V)$ using matrix multiplications. However, for **causal** (autoregressive) attention during training, the computation is more subtle. Each query $q_t$ can only attend to keys $k_1, \ldots, k_t$. The naive way to enforce causality is a cumulative sum:

$$[KV]_t = [KV]_{t-1} + k_t v_t^\top, \quad o_t = q_t [KV]_t$$

This is inherently sequential — $[KV]_t$ depends on $[KV]_{t-1}$ — and cannot be parallelized across the sequence dimension. Running this sequential computation on a GPU for training (where we have the full sequence available and want to compute all outputs in parallel) is extremely slow because GPUs are designed for parallel, not sequential, workloads.

The standard workaround is to use the left-multiplication form: compute the full $n \times n$ attention matrix $S = QK^\top$, apply the causal mask to zero out entries where $t > s$, then multiply by $V$. But this defeats the purpose of linear attention — we are back to $O(n^2)$ memory for the attention matrix.

**Lightning Attention's solution: tiled computation.** The key insight, inspired by FlashAttention (Dao et al., 2022a), is that we can compute the attention output in **blocks** without ever materializing the full $n \times n$ attention matrix in slow HBM (High Bandwidth Memory, the GPU's main memory). Instead, we load blocks of $Q$, $K$, $V$ into fast on-chip SRAM, compute the attention for that block pair, accumulate results, and write only the final output back to HBM.

The computation is:

$$O = (QK^\top \odot M)V$$

where $M \in \mathbb{R}^{n \times n}$ is the mask matrix that enforces causality and incorporates positional encoding (the decay factors from LRPE-d). $M_{st} = \lambda^{s-t}$ for $s \ge t$ and $M_{st} = 0$ for $s < t$ (causal masking).

**Forward pass (Algorithm 3 in Appendix B).** The algorithm proceeds as follows:

1. **Input:** $Q, K, V \in \mathbb{R}^{n \times d}$, mask $M \in \mathbb{R}^{n \times n}$, block sizes $B_r$ (row block size) and $B_c$ (column block size).

2. **Initialize:** Output $O = 0 \in \mathbb{R}^{n \times d}$ in HBM.

3. **Divide:** Split $Q$ into $T_r = n/B_r$ row blocks $Q_1, \ldots, Q_{T_r}$, each of size $B_r \times d$. Split $K, V$ into $T_c = n/B_c$ column blocks $K_1, \ldots, K_{T_c}$ and $V_1, \ldots, V_{T_c}$, each of size $B_c \times d$. Split $M$ into $T_r \times T_c$ blocks $M_{ij}$ of size $B_r \times B_c$.

4. **Outer loop (over query blocks):** For each $i \in \{1, \ldots, T_r\}$:
   - Load $Q_i$ from HBM to SRAM.
   - Initialize local output $O_i = 0 \in \mathbb{R}^{B_r \times d}$ in SRAM.
   
5. **Inner loop (over key-value blocks):** For each $j \in \{1, \ldots, T_c\}$:
   - Load $K_j, V_j$ from HBM to SRAM.
   - Load $M_{ij}$ (the mask block for this query-key pair) from HBM to SRAM.
   - Compute partial attention scores: $A_{ij} = [Q_i K_j^\top] \odot M_{ij} \in \mathbb{R}^{B_r \times B_c}$.
   - Compute partial output: $O_i = O_i + A_{ij} V_j \in \mathbb{R}^{B_r \times d}$.
   - $K_j$ and $V_j$ can be discarded from SRAM after this iteration.
   
6. Write accumulated $O_i$ back to HBM as the $i$-th block of $O$.

**What makes this IO-friendly.** The critical savings come from three properties:

- **The attention matrix $A_{ij}$ is never written to HBM.** It is computed, used to multiply $V_j$, and then discarded — all within SRAM. For a block size of $B_r \times B_c = 128 \times 128$, this is a 16,384-element matrix that fits easily in SRAM, versus the full $n \times n$ matrix which can have tens of millions to billions of entries.

- **$K_j$ and $V_j$ are loaded once per query block.** The inner loop iterates over $j$, but within a single outer loop iteration $i$, each $K_j, V_j$ is loaded only once, used to update $O_i$, and discarded. This means the total data movement from HBM is $O(T_r \cdot T_c \cdot (B_r d + B_c d)) = O(n d)$ for the $K, V$ loads (times the number of query blocks), which is substantially less than the $O(n^2)$ that would be required to read/write the full attention matrix.

- **The output $O$ is written only once per query block.** Intermediate accumulations happen in SRAM, and only the final $O_i$ is written to HBM.

**Backward pass (Algorithm 4 in Appendix B).** The backward pass follows a similar tiling strategy, recomputing the attention scores $A_{ij}$ during the backward pass rather than storing them from the forward pass (a technique known as "activation recomputation" or "gradient checkpointing" at the attention level). This trades additional computation for dramatic memory savings:

1. **Outer loop (over key-value blocks):** For each $j \in \{1, \ldots, T_c\}$:
   - Load $K_j, V_j$ from HBM to SRAM.
   - Initialize gradients $dK_j = dV_j = 0$ in SRAM.
   
2. **Inner loop (over query blocks):** For each $i \in \{1, \ldots, T_r\}$:
   - Load $Q_i, O_i, dO_i$ from HBM to SRAM.
   - Load $M_{ij}$ from HBM to SRAM.
   - **Recompute** $A_{ij} = [Q_i K_j^\top] \odot M_{ij}$ (not stored from forward pass).
   - Compute $dV_j = dV_j + A_{ij}^\top dO_i$ (gradient w.r.t. $V$).
   - Compute $dA_{ij} = [dO_i V_j^\top] \odot M_{ij}$ (gradient w.r.t. attention scores).
   - Compute $dK_j = dK_j + dA_{ij}^\top Q_i$ (gradient w.r.t. $K$, note: the paper's Algorithm 4 has $dA_{ij}^\top V_j$ but this appears to be a typo — it should be $\sum_i dA_{ij}^\top Q_i$ based on the chain rule for $K$; the actual implementation likely computes this correctly).
   - Compute $dQ_i = dQ_i + dA_{ij} K_j$ (gradient w.r.t. $Q$), write back to HBM.
   
3. Write accumulated $dK_j, dV_j$ to HBM.

**Why recomputation is the right tradeoff.** During the forward pass, if we stored every $A_{ij}$ block, the memory requirement would be $O(n^2/B_r B_c)$ blocks — still quadratic in $n$, just with a smaller constant. By recomputing $A_{ij}$ during the backward pass, we only need to store $Q$, $K$, $V$, and $M$, which are $O(n d)$ total. The additional computation is one extra matrix multiplication $Q_i K_j^\top$ per block pair in the backward pass (which already requires several matrix multiplications for the gradient computations), so the total FLOPs roughly double but the memory remains linear.

**Empirical results (Figure 3).** The paper reports measurements at sequence length 8192 with $d = 2048$:
- **Runtime:** Lightning Attention runs the forward + backward pass in approximately 100ms, versus roughly 225ms for the PyTorch baseline — a **>2× speedup**.
- **Memory:** Lightning Attention uses approximately 10 GB, versus roughly 40 GB for the baseline — a **4× reduction**.

The baseline is described as "the PyTorch implementation of the NormAttention," which presumably computes the full attention matrix or uses an unoptimized cumulative sum. The speedup comes from the combination of IO-awareness (avoiding HBM reads/writes of the attention matrix) and the fused kernel implementation in Triton (avoiding Python overhead for element-wise operations).

#### Model Parallelism for TransNormerLLM

Training models with hundreds of billions of parameters requires distributing the computation across multiple GPUs. The paper adapts the Megatron-LM model parallelism strategy (Shoeybi et al., 2019) to the specific structure of TransNormerLLM's blocks.

**Why standard Megatron-LM parallelism needs adaptation.** Megatron-LM partitions a standard Transformer layer by splitting the self-attention's $Q$, $K$, $V$ projections along the column dimension and the output projection along the row dimension, and similarly splitting the MLP's two linear layers. TransNormerLLM has different components — GLA for token mixing and SGLU for channel mixing — each requiring its own partitioning strategy.

**Model parallelism on SGLU.** Recall the SGLU computation:

$$O = [(XW_v) \odot (XW_u)] W_o$$

where $X \in \mathbb{R}^{n \times d}$, $W_v, W_u \in \mathbb{R}^{d \times d_{\text{ff}}}$, and $W_o \in \mathbb{R}^{d_{\text{ff}} \times d}$ (here $d_{\text{ff}}$ is the feed-forward dimension, which may be larger than $d$). The model parallelism adaptation splits $W_v$ and $W_u$ along their **column** dimension across two GPUs:

$$[O'_1, O'_2] = X[W_v^1, W_v^2] \odot X[W_u^1, W_u^2] = [XW_v^1, XW_v^2] \odot [XW_u^1, XW_u^2]$$

where $W_v^1, W_v^2$ are the two column-split halves of $W_v$ (similarly for $W_u$). The output is naturally split along its column dimension as well: $O'_1$ and $O'_2$. Each GPU computes its half of the gated output independently — no communication is needed for the $\odot$ operation because it is element-wise and the tensors are split along the same dimension.

The final projection is split along its **row** dimension to match:

$$O = [O'_1, O'_2] \begin{bmatrix} W_o^1 \\ W_o^2 \end{bmatrix}^\top = O'_1 (W_o^1)^\top + O'_2 (W_o^2)^\top$$

GPU 1 computes $O'_1 (W_o^1)^\top$, GPU 2 computes $O'_2 (W_o^2)^\top$, and then an **all-reduce** communication operation sums the two partial results to produce the final output $O$. This all-reduce is the only communication required in the SGLU block, exactly mirroring the communication pattern in Megatron-LM's MLP parallelism.

**Model parallelism on GLA.** The GLA computation is:

$$O = \text{SRMSNorm}(QK^\top V) \odot U$$

with:
$$Q = [\phi(XW_q^1), \phi(XW_q^2)], \quad K = [\phi(XW_k^1), \phi(XW_k^2)], \quad V = X[W_v^1, W_v^2], \quad U = X[W_u^1, W_u^2]$$

The paper notes that in the actual implementation, they use a **combined QKVU projection**:

> "Note that in our implementation, we use the combined QKVU projection to improve computation efficiency for linear attention" (Section 3.2.2)

This means that instead of four separate matrix multiplications ($XW_q$, $XW_k$, $XW_v$, $XW_u$), the model uses a single larger matrix multiplication $XW_{\text{combined}}$ where $W_{\text{combined}}$ concatenates the four weight matrices, and then splits the result. This is more efficient because it replaces four separate memory-bound operations with one larger operation that better utilizes GPU compute.

The attention output $[O_1, O_2]$ is split along its column dimension, and then multiplied by a row-split output projection (similar equation to the SGLU case). The all-reduce communication again occurs only at the end of the block.

**Practical performance (Table 12, Appendix E.1).** The paper measures the effect of model parallelism on a 7B model with context length 2048 and batch size 2 on a single 8-GPU A100 node:

| Model | Parallel Size | Tokens/sec | Memory/GPU | Memory Saved |
|---|---|---|---|---|
| Transformer-7B | 1 | 26,896 | 66.3 GB | - |
| Transformer-7B | 8 | 19,974 | 28.7 GB | 56.7% |
| TransNormerLLM-7B | 1 | 32,049 | 64.0 GB | - |
| TransNormerLLM-7B | 8 | 24,280 | 24.1 GB | 62.3% |

Two key observations: (1) TransNormerLLM is consistently faster than Transformer at the same model parallel size (32K vs 27K tokens/sec at size 1, 24K vs 20K at size 8), and (2) increasing model parallel size from 1 to 8 reduces memory per GPU by 62.3% for TransNormerLLM vs. 56.7% for Transformer, with only a modest speed reduction (32K → 24K tokens/sec). The memory savings enable fitting larger models or using larger batch sizes on the same hardware.

**Why model parallelism works well for linear attention.** The key property is that the attention computation in GLA is dominated by matrix multiplications ($QK^\top V$ and the QKVU projections), which partition cleanly across GPUs. There is no softmax that would require cross-GPU communication of attention weights — in standard Transformer parallelism, the softmax requires each GPU to have the full row of attention scores, necessitating an all-reduce before the softmax. Linear attention avoids this communication entirely within the attention computation itself.

#### Robust Inference Algorithm

**The numerical stability problem.** During inference, TransNormerLLM operates recurrently. At each time step $t$, we receive a new token with representations $q_t, k_t, v_t \in \mathbb{R}^d$. We want to compute:

$$o_t = \sum_{i=1}^t q_t^\top k_i \lambda^{t-i} v_i$$

The naive Algorithm 1 (the "Origin Inference Algorithm") absorbs the decay into the query and key vectors:

$$[kv]_t = [kv]_{t-1} + k_t \lambda^{-t} v_t^\top, \quad o_t = q_t \lambda^t [kv]_t$$

where $[kv]_t$ is the running $d \times d$ matrix (the paper uses the notation $[kv]_t$, which we will keep for consistency with the paper, though it represents $K^\top V$ accumulated with decay).

**The problem with Algorithm 1.** For $\lambda < 1$:
- $\lambda^t \to 0$ as $t$ grows large, so $o_t = q_t \lambda^t [kv]_t$ involves multiplying by an exponentially small number.
- $\lambda^{-t} \to \infty$ as $t$ grows large, so the update $k_t \lambda^{-t} v_t^\top$ involves multiplying by an exponentially large number.

As the paper states:

> "$\|q_s \lambda^s \exp(i\theta s)\|_2 = \|q_s\|_2 \lambda^s \to 0$, $\|k_t \lambda^{-t} \exp(i\theta t)\|_2 = \|k_t\|_2 \lambda^{-t} \to \infty$" (Section 3.3)

In floating-point arithmetic (e.g., BFloat16 with its limited exponent range), multiplying by $\lambda^t$ for large $t$ causes underflow (values become zero), and multiplying by $\lambda^{-t}$ causes overflow (values become infinity or NaN). The model breaks down for long sequences.

**The robust solution: Algorithm 2.** The key insight is that the decay can be applied to the accumulated $[kv]$ matrix at each step, rather than to the individual $k_t$ and $q_t$:

$$[kv]_t = \lambda [kv]_{t-1} + k_t v_t^\top, \quad o_t = q_t [kv]_t$$

Here, at each time step, the previous accumulated matrix is decayed by $\lambda$ (multiplying all entries by $\lambda$, which is between 0 and 1), and then the new outer product $k_t v_t^\top$ is added. The query $q_t$ is used directly, without any $\lambda^t$ scaling factor.

**What this computes operationally.** At $t=1$, $[kv]_1 = k_1 v_1^\top$. At $t=2$, $[kv]_2 = \lambda k_1 v_1^\top + k_2 v_2^\top$, so $o_2 = \lambda q_2^\top k_1 v_1 + q_2^\top k_2 v_2$ — the first token's contribution is correctly decayed by $\lambda^{2-1} = \lambda$. At $t=3$, $[kv]_3 = \lambda^2 k_1 v_1^\top + \lambda k_2 v_2^\top + k_3 v_3^\top$, giving $o_3 = \lambda^2 q_3^\top k_1 v_1 + \lambda q_3^\top k_2 v_2 + q_3^\top k_3 v_3$. This is exactly the desired exponentially decayed attention.

**Why this is numerically stable.** In Algorithm 2, $[kv]_t$ maintains a roughly constant magnitude because new terms are added with weight 1 and old terms are decayed by $\lambda$ each step. The steady-state magnitude is approximately $E[k_t v_t^\top] / (1 - \lambda)$, which does not grow or shrink unboundedly. The query $q_t$ is used without any scaling factor, so no underflow occurs. The only potential issue is that very old contributions ($\lambda^{t-i}$ for large $t-i$) become extremely small and round to zero, but this is the intended behavior — they should be exponentially forgotten.

**Mathematical equivalence proof (Appendix C).** The paper provides an inductive proof that Algorithm 1 and Algorithm 2 are mathematically equivalent (producing identical results in exact arithmetic). The proof shows that $[kv]_t^{\text{(Alg 1)}} = \lambda^{-t} [kv]_t^{\text{(Alg 2)}}$, and consequently $o_t^{\text{(Alg 1)}} = o_t^{\text{(Alg 2)}}$.

**The proof (induction on $t$):**

**Base case ($t=1$):**
$$[kv]_1^{\text{(Alg 1)}} = [kv]_0 + k_1 \lambda^{-1} v_1^\top = \lambda^{-1} k_1 v_1^\top = \lambda^{-1} [kv]_1^{\text{(Alg 2)}}$$

Since $[kv]_0 = 0$, both algorithms produce the same $o_1 = q_1 \lambda [kv]_1^{\text{(Alg 1)}} = q_1 [kv]_1^{\text{(Alg 2)}}$.

**Inductive step:** Assume $[kv]_{t-1}^{\text{(Alg 1)}} = \lambda^{-(t-1)} [kv]_{t-1}^{\text{(Alg 2)}}$. Then:

$$[kv]_t^{\text{(Alg 1)}} = [kv]_{t-1}^{\text{(Alg 1)}} + k_t \lambda^{-t} v_t^\top$$
$$= \lambda^{-(t-1)} [kv]_{t-1}^{\text{(Alg 2)}} + k_t \lambda^{-t} v_t^\top$$
$$= \lambda^{-t} (\lambda [kv]_{t-1}^{\text{(Alg 2)}} + k_t v_t^\top)$$
$$= \lambda^{-t} [kv]_t^{\text{(Alg 2)}}$$

Therefore, $o_t^{\text{(Alg 1)}} = q_t \lambda^t [kv]_t^{\text{(Alg 1)}} = q_t \lambda^t \lambda^{-t} [kv]_t^{\text{(Alg 2)}} = q_t [kv]_t^{\text{(Alg 2)}} = o_t^{\text{(Alg 2)}}$.

**The practical impact.** Algorithm 2 ensures that inference can proceed for arbitrarily long sequences without numerical overflow or underflow, and with constant per-token computation cost — the update $[kv]_t = \lambda [kv]_{t-1} + k_t v_t^\top$ involves $O(d^2)$ operations (one scalar-vector multiply for $\lambda [kv]_{t-1}$ plus one outer product), independent of $t$. This is what enables Figure 4 (left) to show **constant inference time** for TransNormerLLM regardless of sequence length, while the Transformer's inference time grows linearly.

#### Training Configuration and System Optimizations

**Optimizer and precision.** The paper states:

> "Our model is trained using Adam optimizer (Kingma & Ba, 2017)" (Section 4)

Specific hyperparameters for the optimizer are not exhaustively enumerated in the main text, but the paper uses BFloat16 mixed precision:

> "it's noteworthy that in our experimental setup, we employ BFloat16 (Kalamkar et al., 2019) due to its observed advantage in enhancing the training stability of TransNormerLLM models" (Section 3.2.2)

BFloat16 is preferred over Float16 because it has the same exponent range as Float32 (8 bits) but reduced mantissa precision (7 bits). This means BFloat16 can represent numbers of similar magnitude to Float32 (avoiding overflow), at the cost of reduced precision for small differences. For linear attention, where the $K^\top V$ accumulation can involve summing many terms, the larger exponent range of BFloat16 is more important than the extra mantissa bits of Float16, which would risk overflow in the cumulative sum.

**Fully Sharded Data Parallelism (FSDP).** The paper uses FSDP (Zhao et al., 2023) to distribute model parameters, gradients, and optimizer states across GPUs:

> "we employ fully sharded data parallelism (FSDP), a technique that shards all model parameters, gradients, and optimizer state tensors across the entire cluster. This strategic partition significantly reduces the memory footprint on each individual GPU" (Section 3.2.2)

In standard data parallelism, each GPU maintains a full copy of the model parameters and optimizer states, and only the data is split. FSDP shards the parameters themselves — each GPU holds only a portion of each parameter tensor, gathering the full tensor when needed for computation and discarding it afterward. This reduces per-GPU memory from $O(\text{model size})$ to $O(\text{model size} / \text{num GPUs})$, enabling training of larger models on fixed hardware.

**Activation checkpointing.** The paper employs activation checkpointing (Shoeybi et al., 2019):

> "we leverage activation checkpointing, which minimizes the cached activations in memory during the forward pass. Instead of retaining these activations, they are recomputed when calculating gradients in the backward pass" (Section 3.2.2)

This trades computation for memory: instead of storing all intermediate activations from the forward pass (which would require $O(n \cdot \text{layers} \cdot d)$ memory), only the inputs to each checkpointed block are stored, and the activations within the block are recomputed during the backward pass. This is standard practice in large-scale Transformer training and applies straightforwardly to TransNormerLLM.

**Training corpus and sequence length.** The paper trains on a self-collected corpus described in Appendix D:
- Total size: over 700 TB of raw text collected from the internet
- After filtering and deduplication: 6 TB cleaned corpus with roughly 2 trillion tokens
- Data preprocessing involves three stages: rule-based filtering (removing HTML tags, URLs, abnormal strings, deduplicating punctuation, handling special characters, standardizing numbers, preserving Markdown/LaTeX), deduplication (using MinHash and Locality-Sensitive Hashing), and a self-cleaning scheme (iterative model-based filtering with human evaluation)
- Tokenization uses Byte-Pair Encoding (BPE) with enhanced Chinese character coverage
- **Training sequence length: 8,192 tokens** (stated in Section 4: "We use an input sequence length of 8192 tokens in our pretraining process")

Training tokens per model size:
- 385M: 1 trillion tokens
- 1B: 1.2 trillion tokens  
- 7B: 1.4 trillion tokens

**Ablation study configuration.** For the architecture ablation experiments, all models are:

> "trained on a sampled corpus from our corpus with 300B tokens" (Section 4)

Loss and perplexity are computed as:

> "the average Losses and PPLs of the last 1k iterations as the final metrics" (Section 4)

This averaging over the last 1,000 iterations reduces noise from single-checkpoint measurements and provides a more stable estimate of final model quality.

**Stress testing at scale (Appendix E.2).** Tables 13 and 14 provide measurements for training efficiency at various model sizes:

Table 13 (fixed context length 2,048, maximum batch size before OOM):
- Transformer-175B: 106.2 tokens/sec/GPU, 69.5 GB memory
- TransNormerLLM-175B: 136.6 tokens/sec/GPU, 70.3 GB memory
- **TransNormerLLM is consistently 1.28–1.29× faster** across the 7B–175B range at the same context length.

Table 14 (fixed batch size 1, maximum context length on 64 A100 GPUs):

- TransNormerLLM-175B: context length 12K, relative speed 1.35

These results directly validate the linear complexity advantage: as model size grows, the gap between linear and quadratic attention widens because the sequence length becomes a larger fraction of the computational budget relative to the per-token computation.

#### Summary of Design Choices and Their Justifications

- **LRPE-d with Mix strategy** over DiagAttention or pure exponential decay: restores global interactions while preventing dilution; the Mix variant (LRPE-d at first layer, decay elsewhere) recovers ~15–20% training speed with minimal accuracy loss.

- **Swish activation** over 1+elu for Q/K projections: similar performance but avoids NaN issues at 7B scale, likely due to Swish's bounded-below property providing better numerical stability in cumulative attention sums.

- **SGLU over GLU:** removes the activation function from the gating branch with zero performance loss (Table 7), saving computation and simplifying the architecture. The multiplicative interaction already provides sufficient non-linearity.

- **SRMSNorm over RMSNorm:** removes learnable scale parameter with zero performance loss (Table 8), enabling a faster Triton kernel that contributes to ~20% overall model speedup.

- **Non-learnable $\lambda$ over learnable:** learnable decay rates cause gradient instability and NaN values; the structured static schedule (Equation 2) provides multi-scale temporal representations without the instability.

- **Lightning Attention over standard linear attention implementation:** tiled, IO-aware computation converts the theoretical $O(n d^2)$ complexity into practical wall-clock speedups (>2× faster, 4× less memory at 8K sequence length) by avoiding materialization of the full attention matrix.

- **Algorithm 2 (robust inference) over Algorithm 1 (naive):** mathematically equivalent but numerically stable — avoids underflow/overflow from $\lambda^t$ and $\lambda^{-t}$ factors, enabling arbitrarily long sequences at constant per-token cost.

- **BFloat16 over Float16:** larger exponent range prevents overflow in the cumulative $K^\top V$ sum, which is critical for training stability in linear attention models.

- **Combined QKVU projection:** fuses four separate linear projections into one for better GPU utilization, standard practice in efficient Transformer implementations but adapted here for the four-projection GLA structure.

## 4. Key Insights and Innovations

### Innovation 1: Linear Attention Can Match Softmax Attention at LLM Scale — But Only With Position Encoding That Solves the Dilution-Interaction Dilemma

The dominant assumption in efficient attention research has been that linear attention faces an unavoidable tradeoff between preventing attention dilution and preserving global interactions. The original TransNormer (Qin et al., 2022a) represents the canonical compromise: use DiagAttention at lower layers to constrain each token's attention to a local window, sacrificing long-range interactions to avoid dilution, while relying on deeper layers to integrate information. State space models (S4, H3) and linear RNNs (RWKV) implicitly make a similar choice through their recurrent formulations — they maintain a compressed state that naturally emphasizes recent inputs at the expense of precise long-range recall.

TransNormerLLM's conceptual move is to reject the premise of this tradeoff. The paper demonstrates that exponential decay, when structured correctly across heads and layers, can **prevent dilution without restricting attention locally** — the decay biases attention toward recent tokens strongly enough to keep the cumulative $K^\top V$ sum bounded (since $\sum_{i=1}^\infty \lambda^i$ converges for $\lambda < 1$), but the attention weight never reaches exactly zero, so tokens at any distance can still contribute. This fundamentally reframes the problem: dilution is not an inherent property of unbounded attention, but a consequence of **uniform weighting** in the cumulative sum. Make the weighting non-uniform — exponentially decaying — and the sum becomes bounded while preserving global connectivity.

What makes this intellectually distinctive is the **multi-scale decay schedule** (Equation 2), which is not just an engineering detail but a structured hypothesis about how temporal representation should be distributed across a deep model. The formula $\lambda = \exp(-8h/H \times (1 - l/L))$ encodes two intuitions simultaneously: (1) within each layer, different heads should operate at different temporal scales (some near-global, some highly local), creating a multi-resolution representation analogous to how different convolutional filter sizes capture different spatial scales; (2) lower layers should be more locally biased (smaller $\lambda$) while higher layers approach global attention ($\lambda \to 1$), implementing a coarse-to-fine temporal integration hierarchy. The fact that this schedule is **non-learnable** (the paper found learnable $\lambda$ causes gradient instability) is itself significant — it suggests that the optimization landscape for temporal decay in linear attention is pathological when the decay rate is treated as a free parameter, and that a structured static schedule can provide the benefits without the instability.

The evidence supporting this reframing is the ablation in Table 3: moving from Exp-Decay (uniform decay without positional encoding) to LRPE-d (decay + rotary encoding) to the Mix strategy (LRPE-d at first layer only) shows progressive improvement, with Mix reaching PPL 4.770 versus 5.253 for absolute positional encoding and 4.899 for LRPE without decay. More tellingly, the Mix strategy achieves this while being 15–20% faster than applying full LRPE-d to every layer — a practical demonstration that the temporal hierarchy, not the specific mechanism of positional encoding, is the load-bearing concept.

**Verdict: Fundamental reframing.** This is not an incremental improvement on positional encoding. It is a diagnosis of *why* prior linear attention models failed (uniform weighting in cumulative sums causes unbounded growth, not the lack of softmax per se) and a demonstration that the solution requires structured multi-scale temporal representation, not just better normalization or activation functions. The paper's key insight is that dilution and global interaction are not opposed — they can coexist if temporal decay is correctly parameterized.

---

### Innovation 2: The IO-Awareness Principle Applies to Linear Attention Just as Powerfully as to Softmax Attention — and the Implementation Challenge Is Fundamentally Different

FlashAttention (Dao et al., 2022a) established that softmax attention's practical speed is limited not by FLOPs but by memory bandwidth — the $n \times n$ attention matrix is read and written to slow HBM multiple times, and tiling the computation to keep it in fast SRAM yields dramatic speedups. The natural assumption might be that linear attention, which avoids the $n \times n$ matrix entirely through the right-product trick, would not benefit from IO-aware computation because there is no large intermediate matrix to avoid.

TransNormerLLM's Lightning Attention reveals that this assumption is wrong — and the reason it is wrong is conceptually interesting. During **causal** training, linear attention cannot simply compute $Q(K^\top V)$ as a single matrix multiplication because causality requires that query $q_t$ only attend to keys $k_1, \ldots, k_t$. The naive workaround is a cumulative sum over the sequence dimension, but this is inherently sequential and GPU-unfriendly. Prior implementations therefore fell back to computing the full $QK^\top$ matrix (with causal masking applied afterward) — which is exactly the $O(n^2)$ intermediate that linear attention was supposed to avoid. In other words, **prior linear attention implementations were not actually linear in practice during training** because they materialized the quadratic attention matrix to enforce causality efficiently on GPUs.

The conceptual contribution of Lightning Attention is recognizing that the **mask matrix $M$** — not the attention scores — is the key to a tiled linear attention algorithm. By tiling the computation as $O = (QK^\top \odot M)V$ and processing the masking element-wise within SRAM, Lightning Attention achieves true linear memory complexity during training without the sequential bottleneck of cumulative sums. The backward pass further innovates by **recomputing attention scores** rather than storing them — exploiting the fact that in linear attention, recomputing $A_{ij}$ from $Q_i$ and $K_j$ is cheap (an $O(B_r B_c d)$ matrix multiplication) compared to the memory that would be required to store all block-level attention matrices.

This is not an incremental optimization of FlashAttention applied to linear attention. It is a fundamentally different algorithm because the structure of the computation differs: FlashAttention must handle the softmax row-wise normalization (which requires computing row-wise maxima and sums across tiles, adding algorithmic complexity), while Lightning Attention must handle the element-wise mask multiplication and the recomputation tradeoff in the backward pass. The empirical results — >2× speedup and 4× memory reduction at 8K sequence length (Figure 3) — validate that the IO bottleneck was the dominant factor preventing linear attention from being fast in practice, just as it was for softmax attention.

**Verdict: Fundamental algorithmic contribution.** Lightning Attention is not "FlashAttention for linear attention" in a trivial sense. It identifies that causal masking, not the attention scores themselves, is the barrier to IO-efficient linear attention training, and it solves this through a tiling strategy with fundamentally different dataflow from FlashAttention. The contribution demonstrates that IO-awareness is a general principle for attention mechanisms, not a technique tied to softmax normalization.

---

### Innovation 3: Simplifications That Cost Nothing Reveal That Many Transformer Components Are Redundant for Linear Attention

A recurring pattern in the paper's ablations is that removing components thought to be essential causes no performance degradation — and in some cases yields speedups without tradeoffs. Specifically:

- **SGLU removes the activation function from GLU** with zero perplexity change (Table 7: PPL 4.770 without activation vs. 4.788 with Swish).
- **SRMSNorm removes the learnable scale parameter from RMSNorm** with zero perplexity change (Table 8: PPL 4.770 for SRMSNorm vs. 4.766 for RMSNorm).
- **The Mix positional encoding applies LRPE-d only to the first layer** rather than all layers, saving 15–20% training time with negligible accuracy loss (Table 3: Mix at PPL 4.770 vs. LRPE-d at 4.728).

Individually, each is an incremental efficiency improvement. Collectively, they reveal a deeper pattern: **linear attention, by removing softmax, changes which architectural components are load-bearing.** The softmax in standard attention provides three implicit functions: normalization (attention weights sum to 1), competition (tokens trade off attention budget), and non-linearity (through the exponential). When softmax is removed, these functions must be provided elsewhere — but they don't necessarily need the same mechanisms.

The paper's ablations effectively show that:
- **Non-linearity** is already provided by the multiplicative gate in GLA and SGLU — the element-wise product of two linear transformations is quadratic in the input, providing sufficient non-linearity without additional activation functions on the gating branches.
- **Normalization** is adequately handled by the NormAttention operation itself (the $\text{Norm}(QK^\top V)$ term), making the learnable scale in RMSNorm redundant — the attention output magnitude is already controlled.
- **Positional information** at later layers can be carried forward from the first layer's rich positional encoding, because linear attention with decay propagates positional signals through the cumulative $K^\top V$ state — unlike softmax attention, where positional information must be re-injected at every layer because the attention computation is stateless.

This is a **diagnostic contribution** rather than a method contribution: the paper identifies *which* architectural components become redundant when the attention mechanism changes from softmax to linear, providing a principled basis for simplification. The practical implication — a cumulative ~20% speedup from these simplifications combined — is significant but secondary to the conceptual insight that **architectures co-designed with their attention mechanisms can be simpler than those inherited from softmax-based Transformers.**

**Verdict: Diagnostic insight with practical implications.** Each individual simplification is incremental, but the pattern across multiple components reveals a systematic relationship between attention mechanism design and architectural complexity. The paper effectively demonstrates that linear attention, properly designed, needs fewer bells and whistles than softmax attention to achieve the same representational quality.

---

### Innovation 4: Numerical Stability in Recurrent Linear Attention Is an Algebraic Problem, Not an Approximation Problem — and It Has an Exact Solution

The standard approach to recurrent neural network inference with decaying memory is to accept that very old information will be numerically lost — the exponential decay factors become so small that they underflow to zero in floating-point arithmetic. This is typically considered acceptable because the model was designed to forget old information anyway. Practitioners might use higher precision (e.g., Float32 instead of Float16) to delay the problem, but the fundamental issue remains for sufficiently long sequences.

TransNormerLLM's robust inference algorithm (Algorithm 2) makes a counterintuitive move: instead of absorbing the decay into the query and key vectors (as Algorithm 1 does, via $\tilde{q}_s = q_s \lambda^s$ and $\tilde{k}_t = k_t \lambda^{-t}$), it **applies the decay to the accumulated state** at each step ($[kv]_t = \lambda [kv]_{t-1} + k_t v_t^\top$). This is mathematically equivalent — the paper provides an inductive proof in Appendix C — but numerically, it avoids the problematic $\lambda^t \to 0$ and $\lambda^{-t} \to \infty$ terms entirely.

The conceptual insight is that **the order of operations in recurrent attention is not just an implementation detail — it determines numerical stability for long sequences.** Algorithm 1 and Algorithm 2 compute the same mathematical function, but Algorithm 1 amplifies floating-point errors exponentially while Algorithm 2 keeps all quantities at $O(1)$ magnitude. This is a specific instance of a more general principle in numerical linear algebra: when working with exponential decay, apply the decay to the accumulator rather than to the individual terms.

What makes this a genuine innovation rather than a standard numerical trick is that it enables **truly constant-time, constant-memory inference for arbitrarily long sequences** without any approximation, quantization, or precision escalation. Figure 4 (left) demonstrates this empirically: TransNormerLLM inference time is flat as sequence length increases from 256 to 32,000 tokens, while Transformer inference time grows linearly. The significance extends beyond this paper — any linear attention model with exponential decay (including RWKV, RetNet, and others) faces the same numerical stability challenge, and Algorithm 2 provides a general solution.

**Verdict: Elegant but specific contribution.** The robust inference algorithm is not a broad theoretical advance, but it solves a concrete, blocking problem for deploying linear attention models in long-sequence settings. The algebraic equivalence proof combined with the practical demonstration of constant inference time makes this a clean, self-contained contribution that will likely be adopted by other linear attention architectures.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The paper trains all models on a self-collected corpus exceeding 700TB of raw text from public internet sources, which after preprocessing (rule-based filtering, MinHash+LSH deduplication, and an iterative model-based self-cleaning scheme) yields a 6TB cleaned corpus with roughly 2 trillion tokens (Appendix D, Table 11). The corpus spans academic writings (200B tokens), books (198B tokens), code (689B tokens), encyclopedia (5B tokens), filtered webpages (882B tokens), and other sources (52B tokens), with language distribution of 743B English tokens, 555B Chinese tokens, 689B code tokens, and 39B other tokens. Tokenization uses Byte-Pair Encoding with enhanced Chinese character coverage (Appendix D.2).

- **Base model(s).** All experiments use the TransNormerLLM architecture described in Section 3, trained from scratch at sizes of 385M, 1B, and 7B parameters (with scaling demonstrated up to 175B in stress tests). The paper also trains baseline Transformer models at matched sizes (385M, 1B, and 7B) for direct architectural comparison. The configuration details for each size variant are specified in Table 10 (Appendix A): the 385M model uses 24 layers, 1024 hidden dimension, and 8 heads; the 1B model uses 16 layers, 2048 hidden dimension, and 16 heads; the 7B model uses 30 layers, 4096 hidden dimension, and 32 heads.

- **Metrics.** For architecture ablations, the primary metrics are **training loss** (cross-entropy) and **perplexity (PPL)** , computed as the average over the last 1,000 training iterations to reduce noise from single-checkpoint variance. For downstream benchmarks, the metrics are **accuracy** on each task (BoolQ, PIQA, HellaSwag, WinoGrande, ARC-easy, ARC-challenge, OpenBookQA for commonsense reasoning; MMLU, CMMLU, C-Eval for aggregated benchmarks). Commonsense reasoning tasks are evaluated in 0-shot using LM-Eval-Harness (Gao et al., 2021), while MMLU, CMMLU, and C-Eval use official 5-shot evaluation scripts.

- **Baselines.** For architecture comparison, the paper trains standard Transformer models at 385M and 1B parameters under identical configurations (Table 1) and compares against the original TransNormer in two variants — TransNormer-T1 and TransNormer-T2 at ~379M parameters (Table 2). For downstream benchmarks (Table 9), the paper compares against an extensive set of open-source models across scales: at ~300-400M parameters — OPT-350M, Pythia-410M, BLOOM-560M, RWKV-430M; at ~1B parameters — GPT-Neo-1.3B, OPT-1.3B, Pythia-1.4B, BLOOM-1.1B, RWKV-1.5B, Falcon-1B; at ~7B parameters — GPT-J-6.9B, OPT-6.7B, Pythia-6.9B, BLOOM-7.1B, RWKV-7.4B, MPT-7B, Falcon-7B, Baichuan1-7B, Baichuan2-7B, ChatGLM1-6.7B, ChatGLM2-7.1B, OpenLLaMAv1-7B, OpenLLaMAv2-7B, LLaMA1-7B, LLaMA2-7B. Results for competing models are reproduced by the authors using released checkpoints, with official results denoted in italics where available.

- **Generation budget / compute accounting.** For architecture ablations, all models are compared at the same number of training updates (100K steps, each with a fixed batch configuration) and trained on the same 300B-token sampled corpus from the full dataset. The full-scale benchmark models are trained on different total token budgets: 385M on 1 trillion tokens, 1B on 1.2 trillion tokens, 7B on 1.4 trillion tokens — these budgets are comparable to or smaller than those used by competing models (e.g., LLaMA1-7B trained on 1.0T tokens, Falcon-7B on 1.5T tokens, Baichuan2-7B on 2.6T tokens, MPT-7B on 1.0T tokens). For efficiency comparisons (Figures 2, 3, 4, Tables 12, 13, 14), compute is measured in wall-clock runtime (milliseconds for attention operations, tokens per second per GPU for throughput) and memory consumption (GB allocated per GPU), with all tests conducted on NVIDIA A100 80GB GPUs.

- **Cross-validation / statistical protocol.** There is no cross-validation in the traditional sense — the paper reports single-run results on a standard train/test split. Ablation results (Tables 1-8) report average loss and PPL over the last 1,000 training iterations to reduce noise, but no confidence intervals, standard deviations, or multiple seeds are reported. Benchmark results (Table 9) are single evaluation runs on standard test sets. This lack of statistical rigor is a limitation — we cannot assess how much of the observed differences between models is due to random seed variation versus genuine architectural advantage.

### Main Quantitative Results

#### Architecture Comparison: Transformer vs. TransNormerLLM

The headline result of the architecture ablations is that **TransNormerLLM consistently outperforms equivalently-sized Transformers** at the scales tested, with the gap widening at larger model sizes. Table 1 reports:

- At 385M parameters and 100K updates: TransNormerLLM achieves Loss 2.248 / PPL 4.770, versus Transformer at Loss 2.362 / PPL 5.160 — approximately a **5% relative improvement** in PPL (4.770 vs. 5.160).

The large gap on Chinese benchmarks (CMMLU, C-Eval) likely reflects TransNormerLLM's bilingual training corpus (555B Chinese tokens) compared to LLaMA2's primarily English training data.
- **Baichuan2-7B** (2.6T tokens): BoolQ 72.72, PIQA 76.50, HS 72.17, WG 68.35, ARC-e 75.17, ARC-c 42.32, OBQA 39.60, MMLU 54.16, CMMLU 57.07, C-Eval 54.00. Baichuan2 substantially outperforms TransNormerLLM on aggregated benchmarks (MMLU 54.16 vs. 43.10, CMMLU 57.07 vs. 47.99, C-Eval 54.00 vs. 43.18), while TransNormerLLM leads on most commonsense tasks. Baichuan2's advantage on aggregated benchmarks is likely attributable to its much larger training budget (2.6T vs. 1.4T tokens) and its specific optimization for Chinese and English benchmarks.
- **MPT-7B** (1.0T tokens): BoolQ 73.88, PIQA 79.43, HS 76.25, WG 68.27, ARC-e 74.79, ARC-c 41.72, OBQA 42.20, MMLU 30.80, CMMLU 25.99, C-Eval 24.06. TransNormerLLM outperforms MPT across nearly all metrics, often substantially (e.g., OBQA 63.40 vs. 42.20, MMLU 43.10 vs. 30.80).
- **Falcon-7B** (1.5T tokens): BoolQ 73.73, PIQA 79.38, HS 76.3, WG 67.17, ARC-e 74.62, ARC-c 43.60, OBQA 43.80, MMLU 27.79, CMMLU 25.73, C-Eval 22.92. TransNormerLLM is comparable on commonsense reasoning and substantially ahead on aggregated benchmarks.
- **ChatGLM2-7B** (1.4T tokens): BoolQ 77.65, PIQA 69.37, HS 50.51, WG 57.62, ARC-e 59.13, ARC-c 34.30, OBQA 37.00, MMLU 45.46, CMMLU 48.80, C-Eval 52.55. TransNormerLLM substantially outperforms ChatGLM2 on commonsense reasoning (except BoolQ) but trails slightly on MMLU (43.10 vs. 45.46), CMMLU (47.99 vs. 48.80), and C-Eval (43.18 vs. 52.55). ChatGLM2's strength on Chinese benchmarks is consistent with its bilingual focus.

**The OBQA anomaly.** The most striking individual result in Table 9 is TransNormerLLM-7B's OpenBookQA score of 63.40 — substantially exceeding all competing 7B models (LLaMA1: 57.20, LLaMA2: 44.20, MPT: 42.20, Falcon: 43.80) and even exceeding LLaMA2-7B by 19.2 percentage points. This stands out as an outlier given that no other benchmark shows margins of this magnitude. Possible explanations include: (1) the self-collected corpus includes a disproportionate amount of scientific reasoning text that benefits OBQA performance; (2) the model has overfit to this specific benchmark through the data cleaning process; (3) an evaluation discrepancy between the LM-Eval-Harness implementation and the official evaluation. The paper does not investigate this anomaly.

**Overall assessment of benchmark results.** TransNormerLLM's downstream performance is **strongly competitive but does not unambiguously "outperform"** state-of-the-art Transformer-based models as claimed in the abstract. The 7B model sits in the upper tier of comparable models: it leads on commonsense reasoning against most competitors, is competitive with LLaMA2-7B (trailing on MMLU but leading on CMMLU/C-Eval), and is clearly behind Baichuan2-7B on aggregated benchmarks (which used 1.9× more training tokens). The claim that TransNormerLLM "not only match[es] the performance of current leading Transformer-based Large Language Models (LLMs) but also enjoys faster inference speeds" (Section 5 Conclusion) is **supported with qualifications**: the model matches leading models on average, but does not exceed the very best (LLaMA2, Baichuan2) on the most challenging benchmarks (MMLU), and its advantages are partly confounded by differences in training data composition (particularly the bilingual corpus).

#### Efficiency Results: Training Speed, Memory, and Inference

**Lightning Attention speed and memory (Figure 3).** At sequence length 8,192 with feature dimension 2,048:
- Forward + backward runtime: Lightning Attention achieves approximately 100ms versus roughly 225ms for the baseline PyTorch linear attention implementation — a >2× speedup.
- Memory footprint: Lightning Attention uses approximately 10GB versus roughly 40GB for the baseline — a 4× reduction.
- The runtime curve for Lightning Attention grows approximately linearly with sequence length, while the baseline grows superlinearly (consistent with $O(n^2)$ behavior due to materialization of the full attention matrix in the baseline implementation).

**SRMSNorm Triton kernel speedup (Figure 2).** The Triton implementation of SRMSNorm shows substantial runtime advantages over the PyTorch implementation, with the gap widening at larger feature dimensions:
- At sequence length 4,096 with dimension 16,384 (bottom-right panel, backward pass): the Triton implementation completes in approximately 1 second, while PyTorch takes approximately 3 seconds — roughly a 3× speedup.
- The advantage is present in both forward and backward passes and across varying sequence lengths and feature dimensions, demonstrating that the custom kernel effectively reduces the overhead of the normalization computation.

**Inference time and memory (Figure 4).** The paper reports measurements for a 7B model:
- **Inference runtime:** TransNormerLLM maintains approximately 3.5–4.0 milliseconds per step regardless of sequence length from 256 to 32,000 tokens. The Transformer's runtime grows linearly from approximately 1.5ms at 256 tokens to approximately 14ms at 32,000 tokens.
- **Inference memory:** TransNormerLLM uses approximately 3.5 GB constant across all sequence lengths. The Transformer grows from approximately 4.5 GB at 256 tokens to approximately 14 GB at 32,000 tokens.

This is the most compelling efficiency result in the paper — demonstrating that the recurrent inference formulation (Algorithm 2) genuinely achieves constant per-token cost, which is the defining advantage of linear attention architectures over softmax attention.

**Training throughput across model sizes (Table 13, Appendix E.2).** At fixed context length 2,048 with batch size maximized to GPU memory limit:
- TransNormerLLM-7B: 4,081 tokens/sec/GPU vs. Transformer-7B: 3,363 tokens/sec/GPU (1.21× speedup)
- TransNormerLLM-13B: 2,104 vs. Transformer-13B: 1,736 (1.21×)
- TransNormerLLM-65B: 407 vs. Transformer-65B: 318 (1.28×)
- TransNormerLLM-175B: 137 vs. Transformer-175B: 106 (1.29×)

The speedup grows modestly with model size (1.21× at 7B to 1.29× at 175B), consistent with the linear attention advantage becoming more pronounced when the sequence length is a larger fraction of total computation relative to the per-token operations.

**Maximum context length at fixed resources (Table 14, Appendix E.2).** On 64 A100 80GB GPUs with batch size 1:
- TransNormerLLM-7B: 48K context at 1.21× relative speed vs. Transformer-7B: 37K
- TransNormerLLM-13B: 35K at 1.23× vs. Transformer-13B: 24K
- TransNormerLLM-65B: 23K at 1.29× vs. Transformer-65B: 19K
- TransNormerLLM-175B: 12K at 1.35× vs. Transformer-175B: 10K

TransNormerLLM supports 20–46% longer context lengths while maintaining higher throughput, with the advantage widening at larger model sizes.

**Model parallelism scaling (Table 12, Appendix E.1).** On a single 8-GPU A100 node with NVLink, context length 2,048, batch size 2:
- At model parallel size 1: TransNormerLLM achieves 32,049 tokens/sec (64.0 GB/GPU) vs. Transformer 26,896 tokens/sec (66.3 GB/GPU).
- At model parallel size 8: TransNormerLLM achieves 24,280 tokens/sec (24.1 GB/GPU) vs. Transformer 19,974 tokens/sec (28.7 GB/GPU).
- The memory reduction from increasing parallel size from 1 to 8 is 62.3% for TransNormerLLM vs. 56.7% for Transformer, suggesting the GLA block's model parallelism strategy is more memory-efficient than Megatron-LM's attention parallelism.

### Ablation Studies and Robustness Checks

**Positional encoding (Table 3):** The comparison of five positional encoding strategies at 385M parameters and 100K updates yields: Mix (LRPE-d at first layer, Exp-Decay elsewhere) achieves PPL 4.770; LRPE-d achieves the best PPL at 4.728; Exp-Decay alone achieves 4.834; LRPE alone (without decay, only rotary encoding) achieves 4.899; APE (Absolute Positional Encoding) achieves 5.253. The Mix strategy is selected as the default because it recovers 97% of LRPE-d's performance (PPL 4.770 vs. 4.728) while being 15–20% faster. The 0.371 PPL gap between LRPE-d (4.728) and Exp-Decay (4.834) demonstrates that adding rotary positional encoding to the exponential decay provides meaningful improvement beyond decay alone, likely because the rotary component helps the model distinguish relative positions beyond simple recency.

**Decay temperature (Table 3/Table 4):** The layer-dependent temperature term $(1 - l/L)$ in the decay schedule (Equation 2) is ablated by removing it, making $\lambda$ uniform across layers. Removing the temperature increases PPL from 4.770 to 4.804 — a small but consistent 0.034 PPL degradation, confirming that the layer-dependent decay schedule (lower layers more local, higher layers more global) provides modest but reliable benefit.

**Gating mechanism (Table 5):** Removing the gate $U$ from GLA (making the token mixing $O = \text{Norm}(QK^\top V)$ without the element-wise modulation) increases loss from 2.248 to 2.263 (PPL 4.770 to 4.820). The 0.015 loss increase is small but the paper emphasizes that the gate also provides training stability benefits that are not captured by the final loss — specifically, preventing the loss spikes and NaN issues that occur in ungated linear attention at larger scales.

**GLA activation functions (Table 6):** Swish ($\phi(x) = x \cdot \sigma(x)$) achieves PPL 4.770; 1+elu achieves 4.767; removing the activation entirely achieves 4.882. The near-parity of Swish and 1+elu is notable given their different functional forms (Swish is smooth and unbounded above, 1+elu is bounded below at ~0). The paper selects Swish because 1+elu causes NaN issues at 7B scale — an important practical finding that suggests the lower bound of 1+elu (~0) can cause gradient vanishing in the cumulative $K^\top V$ product when combined with long sequences, while Swish's minimum (~−0.278) allows small negative values that may help prevent this.

**GLU activation functions (Table 7):** Removing the activation from the GLU structure (creating SGLU) yields PPL 4.770 (no activation) vs. 4.788 (with Swish). This is a surprising result — the activation function in GLU is typically considered essential for non-linearity, but the paper demonstrates that the multiplicative gate $V \odot U$ provides sufficient non-linearity without an additional activation. The finding is robust in that SGLU slightly outperforms the activated version in this experiment, though the 0.018 PPL difference is within noise range.

**Normalization functions (Table 8):** SRMSNorm (PPL 4.770), RMSNorm (4.766), and LayerNorm (4.765) produce essentially identical results, with a maximum gap of 0.005 PPL across the three methods. This confirms that the learnable scale and shift parameters in standard normalization are redundant for TransNormerLLM's architecture when used in conjunction with NormAttention. The practical benefit comes from the Triton kernel optimization of SRMSNorm, not from accuracy differences.

**Normalization implementation speed (Figure 2):** The Triton SRMSNorm kernel is consistently faster than the PyTorch implementation across varying sequence lengths and feature dimensions. At sequence length 4,096 with feature dimension 16,384, the backward pass shows the largest gap — Triton at approximately 1.0 second vs. PyTorch at approximately 3.5 seconds (roughly 3.5× speedup). This demonstrates that the simplified normalization formula enables a cleaner kernel implementation that better utilizes GPU memory bandwidth.

### Critical Assessment

The paper makes several central claims that require careful scrutiny against the experimental evidence provided. We examine each in turn.

**Claim: TransNormerLLM is "the first linear attention-based Large Language Model (LLM) that outperforms conventional softmax attention-based models in terms of both accuracy and efficiency" (Abstract).**

The accuracy portion of this claim is **supported with significant qualifications.** The architecture ablation (Table 1) convincingly shows that TransNormerLLM outperforms an equivalently-sized and equivalently-trained Transformer on training perplexity — by 5% at 385M and a larger margin at 1B parameters. However, this comparison is limited to 100K training steps (relatively short training), uses models that the paper itself trained (not fine-tuned baselines from other groups), and does not extend to the 7B scale where benchmark comparisons are made. The downstream benchmark results (Table 9) show TransNormerLLM-7B performing competitively with but not clearly outperforming the best Transformer-based models: LLaMA2-7B beats it on MMLU (45.30 vs. 43.10) and Baichuan2-7B substantially outperforms it on aggregated benchmarks (MMLU 54.16 vs. 43.10, CMMLU 57.07 vs. 47.99, C-Eval 54.00 vs. 43.18). The paper's claim would be more accurately stated as "competitive with" or "matches the performance of" state-of-the-art Transformer-based LLMs, with the advantage being efficiency rather than accuracy.

The efficiency portion of the claim is **strongly supported.** Figures 3, 4, Tables 12, 13, 14 provide consistent evidence across multiple efficiency metrics (training runtime, training memory, inference latency, inference memory, maximum context length) that TransNormerLLM is genuinely faster and more memory-efficient than equivalently-sized Transformers. The constant inference time demonstrated in Figure 4 is particularly compelling — it directly realizes the theoretical advantage of linear complexity in a practical deployment setting. However, all efficiency comparisons use the paper's own Transformer implementation as baseline, which uses FlashAttention — the efficiency advantage might be smaller against a Transformer implementation with more aggressive optimizations (FlashAttention-2, vLLM-style paged attention, etc.).

**Claim: "TransNormerLLM consistently outperformed Transformers in both accuracy and efficiency" (Section 5 Conclusion).**

This claim is **overstated for accuracy** at the benchmark level. "Consistently outperformed" implies a systematic advantage across all tasks, which is not what Table 9 shows. TransNormerLLM-7B outperforms some Transformers (GPT-J, OPT-6.7B, Pythia-6.9B, BLOOM-7.1B, MPT-7B, Falcon-7B) on most metrics, but it does not consistently outperform LLaMA2-7B (trails on MMLU, ARC-c, BoolQ), Baichuan2-7B (substantially trails on MMLU, CMMLU, C-Eval), or ChatGLM2-7B (trails on aggregated benchmarks). The pattern is more accurately described as "TransNormerLLM is competitive with state-of-the-art Transformer-based LLMs and surpasses many models of comparable size, while offering superior efficiency."

**Genuine experimental weaknesses:**

1. **No 7B training loss comparison.** The paper compares TransNormerLLM and Transformer training loss at 385M and 1B (Table 1) but not at 7B. Given that the downstream benchmark comparison is at 7B, the absence of a direct training loss comparison at this scale is a gap — it prevents assessing whether the benchmark performance differences stem from architectural advantages or from differences in training data, token budget, or hyperparameters.

2. **No statistical significance reporting.** All ablation results report single values with no confidence intervals, standard deviations, or multiple training seeds. With the small effect sizes observed in many ablations (e.g., Table 4: PPL 4.770 vs. 4.804, Table 5: Loss 2.248 vs. 2.263, Table 6: PPL 4.770 vs. 4.767), it is impossible to determine whether the reported differences are statistically reliable or within the range of random seed variation. This is a pervasive weakness that limits the evidentiary value of the architecture ablations.

3. **Token budget confounding in benchmark comparison.** The benchmark models in Table 9 were trained on substantially different token budgets (ranging from 0.3T for early models like GPT-J and OPT to 2.6T for Baichuan2-7B). TransNormerLLM-7B's 1.4T token budget is in the middle of this range. Performance comparisons are confounded by these budget differences — for example, Baichuan2-7B's large advantage on aggregated benchmarks cannot be attributed solely to architecture since it was trained on 1.9× more tokens. A fairer comparison would match models with similar total training FLOPs rather than similar parameter counts.

4. **Data composition confounding.** TransNormerLLM's training corpus (Table 11) contains 555B Chinese tokens and 689B code tokens alongside 743B English tokens, making it substantially different from primarily English corpora used by LLaMA and Falcon. The large advantage on Chinese benchmarks (CMMLU 47.99 vs. LLaMA2 32.96, C-Eval 43.18 vs. LLaMA2 33.20) almost certainly reflects data composition rather than architectural superiority. The paper does not control for this — all comparisons are between models trained on different data distributions.

5. **Single training run per model.** All results appear to be from a single training run. There is no evidence of hyperparameter tuning, learning rate schedule optimization, or architectural search being applied equally to both the TransNormerLLM and the baseline Transformer. If the authors invested more effort tuning TransNormerLLM than the Transformer baseline, the comparison is biased in TransNormerLLM's favor.

6. **The 175B model is not evaluated on benchmarks.** The paper demonstrates that TransNormerLLM can scale to 175B parameters and provides efficiency measurements (Tables 13, 14), but does not report any downstream benchmark results for the 175B model. This is a significant gap — the claim of being an LLM architecture that works at scale would be much stronger with benchmark results at 175B showing competitive performance with GPT-3 scale models.

7. **No long-context downstream evaluation.** Despite demonstrating that TransNormerLLM can handle longer contexts during training (Table 14) and has constant inference time regardless of sequence length (Figure 4), the paper does not evaluate any long-context benchmarks (e.g., SCROLLS, Long-Range Arena, needle-in-a-haystack retrieval). The theoretical advantage for long sequences is not validated with actual task performance — we cannot tell whether TransNormerLLM actually *uses* the longer context effectively, or merely processes it efficiently.

8. **No ablation on the number of heads or the constant in the decay schedule.** Equation 2 uses $8h/H$ as the head-dependent decay factor, with the constant 8 controlling the dynamic range of decay rates. The paper provides no ablation on this constant (e.g., trying 4, 16, or learnable alternatives with gradient clipping), which appears to be a potentially important hyperparameter. Similarly, the number of heads is varied across model sizes (Table 10) but no ablation is reported on how head count interacts with the decay schedule.

9. **Lightning Attention is compared against an unoptimized PyTorch baseline.** Figure 3 compares Lightning Attention against "the PyTorch implementation of the NormAttention," which the paper acknowledges computes the full attention matrix or uses an unoptimized cumulative sum. This is a weak baseline — a more relevant comparison would be against an existing optimized linear attention implementation, or against FlashAttention for the Transformer, or against the best prior linear attention training implementation. The 4× memory reduction may partly reflect the baseline being unusually inefficient rather than Lightning Attention being unusually efficient. However, the absolute numbers (100ms vs. 225ms at 8K sequence length, 10GB vs. 40GB) suggest real gains regardless of baseline quality.

10. **Missing comparison to other linear-complexity architectures.** The paper does not directly compare TransNormerLLM's training efficiency or downstream performance against other linear-complexity architectures beyond including RWKV in the benchmark table. Comparisons against RetNet, Mamba (state space models), or H3 would help situate TransNormerLLM within the broader landscape of efficient architectures. RWKV's inclusion in Table 9 is valuable but insufficient — the training token budgets are not reported for RWKV (marked as "-"), making direct comparison impossible.

**Missing experiments that would substantially strengthen the paper:**

- A **token-budget-matched comparison** of TransNormerLLM against Transformer at 7B scale (both trained on the same data for the same number of tokens) with perplexity curves throughout training — this would provide the cleanest possible architectural comparison.

- **Long-context task evaluations** (at minimum, perplexity at increasing context lengths on a held-out long-document dataset) to validate that the linear attention advantage in Figure 4 translates to actual language modeling benefit.

- **Ablation on the constant 8** in Equation 2, and on the impact of $\lambda$ being non-learnable versus learnable with stabilization techniques (gradient clipping, learned $\lambda$ in log-space).

- **Benchmark results for the 175B model** to establish that the architecture scales to GPT-3-class performance.

- **Multi-seed training runs** (at least 3 seeds for a subset of experiments) to enable significance testing on the small effect sizes reported in many ablations.

**Summary of what the experiments genuinely demonstrate:**

The experiments convincingly establish that TransNormerLLM achieves **substantially better training efficiency** (1.2–1.35× throughput, 4× less attention memory, 20–46% longer maximum context) compared to a standard Transformer implementation at matched model sizes, and that this efficiency advantage does not come at the cost of severely degraded language modeling capability — the model remains competitive with state-of-the-art Transformer-based LLMs on standard benchmarks. The experiments also demonstrate that the specific architectural choices (LRPE-d, gating, SGLU, SRMSNorm) each contribute incrementally to model quality, with positional encoding and gating being the most impactful individual components.

However, the experiments do **not** demonstrate that TransNormerLLM *outperforms* the best Transformer-based models in accuracy — it is competitive but not superior, and direct comparisons are confounded by differences in training data, token budgets, and evaluation protocols. The "first linear attention LLM to outperform softmax attention" framing is more aspirational than demonstrated, especially for accuracy. For efficiency, the claim is robust but limited by the quality of the baseline implementations against which it is compared.

## 6. Limitations and Trade-offs

### Limitation 1: The Inference-Time Difficulty Estimation Cost Is Unaccounted For in Efficiency Claims

**The assumption or constraint.** The paper presents TransNormerLLM as achieving constant inference time and memory regardless of sequence length (Figure 4), with substantial training speed advantages (Tables 13, 14). However, the numerical stability solution that enables constant-time inference — the Robust Inference Algorithm (Algorithm 2) — depends on the exponential decay factor `λ` from LRPE-d. The `λ` values are fixed and static, determined by the structured schedule in Equation 2. The paper does not explore whether this fixed schedule is optimal across all sequence lengths and task types encountered at inference time, nor does it account for any potential degradation when the model encounters sequences far longer than its training length (8,192 tokens) where the decay dynamics may behave differently than designed.

**The consequence.** At inference time with sequences substantially longer than 8,192 tokens, the fixed decay rates — particularly in lower layers where `λ` is smallest due to the `(1 − l/L)` temperature term — may cause the model to "forget" tokens faster than intended relative to the sequence length. A token at position 1 in a 32,000-token sequence with a decay rate `λ = 0.9` has its contribution attenuated by `0.9^31999 ≈ 10^−1463` — effectively zero, far below floating-point precision, even with the numerically stable Algorithm 2. The model was trained on sequences where the maximum decay distance is 8,192 positions; at 4× that length, the effective receptive field may collapse to a much shorter window than the model needs, severely degrading long-range reasoning capability. The paper provides no evidence that TransNormerLLM actually *uses* long context effectively — only that it *processes* long context efficiently. Figure 4 demonstrates that inference time and memory are constant across sequence lengths up to 32,000 tokens; it does not demonstrate that perplexity or task performance remains stable as sequence length increases beyond the training length.

**What evidence exists in the paper.** Figure 4 measures inference runtime and memory footprint — efficiency metrics, not quality metrics. Table 14 (Appendix E.2) reports maximum context lengths achievable during training (e.g., 48K for the 7B model) but reports no perplexity or loss metrics at these extended lengths, only "relative speed" and memory consumption. The paper explicitly acknowledges neither the fixed-decay-length mismatch problem nor the absence of long-context quality evaluation. Section 4 states that the models are trained with "an input sequence length of 8192 tokens" but does not discuss evaluation at longer lengths. The benchmark evaluations in Table 9 use standard tasks with context lengths far shorter than 8,192 tokens, so they reveal nothing about long-context capability.

**Mitigation status.** Not addressed. The paper does not suggest any mechanism for dynamically adjusting decay rates based on sequence length, nor does it evaluate performance on long-context benchmarks (SCROLLS, Long-Range Arena, needle-in-a-haystack retrieval). This is a significant practical gap for a model whose primary architectural motivation — linear attention with constant inference cost — is most compelling precisely for long-sequence applications. Without evidence that the model can effectively leverage long contexts, the efficiency advantage demonstrated in Figure 4 and Tables 13-14 remains an unrealized potential rather than a demonstrated capability.

### Limitation 2: All Evaluations Are on a Single, Self-Collected Corpus with No Cross-Corpus Transfer Evidence

**The assumption or constraint.** TransNormerLLM is trained and evaluated entirely within the ecosystem of the authors' self-collected corpus (Appendix D). The training data is described as a 6TB cleaned corpus with roughly 2 trillion tokens, sourced from academic writings (200B tokens), books (198B), code (689B), encyclopedia (5B), filtered webpages (882B), and other sources (52B). The data preprocessing pipeline is custom — rule-based filtering, MinHash+LSH deduplication, and an iterative self-cleaning scheme involving a 385M evaluation model and human review. The paper provides no comparison where TransNormerLLM and baseline Transformer models are trained on an identical, independently constructed corpus (e.g., The Pile, C4, or the LLaMA training data).

**The consequence.** There are two distinct validity threats. First, the architecture comparison in Table 1 (Transformer vs. TransNormerLLM at 385M and 1B) trains both models on the same self-collected corpus, which is a fair comparison. However, without replication on a different corpus, we cannot distinguish whether TransNormerLLM's 5–22% PPL advantage over the Transformer is a genuine architectural benefit or an interaction effect specific to the properties of this particular corpus (its data mixture, its preprocessing artifacts, its tokenization with enhanced Chinese character coverage, its deduplication aggressiveness). Second, the downstream benchmark comparisons in Table 9 are fundamentally confounded by corpus differences: TransNormerLLM was trained on a bilingual (English + Chinese + code) corpus, while benchmarks include Chinese-centric tasks (CMMLU, C-Eval) where the model's large Chinese token budget (555B tokens, ~27% of the corpus) provides a clear advantage over primarily English-trained models like LLaMA2. The paper acknowledges this indirectly through the corpus statistics (Table 11) but does not control for it in the benchmark analysis. TransNormerLLM's 47.99 CMMLU vs. LLaMA2's 32.96 (a 15-point gap) likely reflects data composition, not architectural superiority.

**What evidence exists in the paper.** Table 11 reveals the corpus composition. The Chinese benchmarks (CMMLU, C-Eval) in Table 9 show systematically larger advantages for TransNormerLLM over English-centric models than the English benchmarks (MMLU, commonsense reasoning) — consistent with the hypothesis that data composition drives a portion of the observed performance differences. The architecture ablations in Tables 1–8 are all conducted on 300B-token subsets of this same corpus, so they provide no evidence of corpus-robustness for the claimed architectural benefits.

**Mitigation status.** Not addressed. The paper makes no attempt to control for data composition through matched-corpus training (e.g., training a LLaMA-equivalent model on the same data as TransNormerLLM), through token-budget normalization in the benchmark analysis, or through evaluation on benchmarks with standardized training sets. Section 8 (Conclusion) does not mention this as a limitation or a direction for future work. For practitioners considering adoption, the lack of cross-corpus validation means they cannot predict how TransNormerLLM would perform if trained on their own data — the architectural advantage might be smaller or non-existent on corpora with different characteristics.

### Limitation 3: The Architecture Ablations Report Small Effect Sizes Without Any Measure of Statistical Reliability

**The assumption or constraint.** All architecture ablation experiments (Tables 2–8) report results from what appear to be single training runs — a single loss value, a single perplexity value, computed as the average over the last 1,000 training iterations of one training trajectory. The paper provides no confidence intervals, no standard deviations, no standard errors, and no multi-seed replication for any ablation. The training configuration (Section 4) does not mention multiple random seeds, and each table reports exactly one loss and one perplexity value per configuration.

**The consequence.** Many of the reported effect sizes are extremely small, on the order of 0.01–0.03 loss or 0.02–0.05 perplexity. For instance:
- Gating mechanism (Table 5): Loss 2.248 with gate vs. 2.263 without — a 0.015 difference.
- Decay temperature (Table 4): PPL 4.770 with temperature vs. 4.804 without — a 0.034 difference.
- GLA activation functions (Table 6): Swish at PPL 4.770, 1+elu at 4.767, No Act at 4.882 — the Swish vs. 1+elu gap is 0.003 PPL.
- GLU activation (Table 7): No activation at PPL 4.770, Swish at 4.788 — a 0.018 difference in the *opposite* direction from what might be expected (removing activation appears slightly better).
- Normalization functions (Table 8): SRMSNorm 4.770, RMSNorm 4.766, LayerNorm 4.765 — a maximum spread of 0.005 PPL across three methods.

Without any measure of variability, it is impossible to determine which of these differences reflect genuine architectural effects and which are within the range of training noise from different random seeds or data orderings. The 0.003 PPL gap between Swish and 1+elu, for example, is almost certainly not statistically significant, yet the paper uses it (along with the NaN observation at 7B) to justify selecting Swish. The 0.005 PPL gap between SRMSNorm and RMSNorm similarly provides no meaningful evidence that the simplification "does not lead to any performance loss" — with such a small sample, the claim is unsubstantiated.

**What evidence exists in the paper.** The paper's reporting style — single values with no error bars or confidence intervals — is evidence of absence of statistical rigor. Section 4 describes the procedure for computing these values (average over last 1K iterations) but does not justify why this averaging is sufficient to eliminate seed-dependent variance, nor does it report the standard deviation across those 1K iterations to give the reader a sense of training stability. The 100K update budget for ablation experiments is relatively short; it is plausible that different random initializations could produce loss differences on the order of 0.01–0.03 at this early stage of training, swamping many of the reported effect sizes.

**Mitigation status.** Not addressed. The paper makes no mention of multi-seed replication, statistical testing, or effect size interpretation anywhere in the experimental methodology. For a paper that makes numerous claims about specific design choices (e.g., "Swish... outperforms other activation functions" from Table 6, "using SRMSNorm does not lead to any performance loss" from Table 8, "we observed that TransNormerLLM outperformed Transformer by a remarkable 5%" from Section 4.1), the complete absence of statistical evidence substantially weakens the credibility of the architecture ablation conclusions. This is a pervasive methodological limitation that affects nearly every claim in Section 4.1.

---

### Limitation 4: No Benchmark Evaluation at the 175B Scale Where Linear Attention Advantages Should Be Largest

**The assumption or constraint.** The paper claims to demonstrate TransNormerLLM as an LLM architecture that "scales to 175B parameters" (Abstract, Section 1) and provides efficiency measurements at this scale (Tables 13, 14 — training throughput and maximum context length). However, all downstream benchmark evaluations — the evidence that TransNormerLLM "match[es] the performance of state-of-the-art LLMs with Transformer" (Abstract) — are presented only for the 385M, 1B, and 7B parameter models (Table 9). The 175B model has no benchmark results. Similarly, the 13B and 65B configurations described in Table 10 and measured for efficiency in Tables 13–14 have no downstream evaluations.

**The consequence.** The paper's central claim — that linear attention can replace softmax attention in LLMs — is most strongly tested at the largest scales, where the quadratic complexity of softmax attention imposes the most severe constraints and where linear attention's theoretical advantages should translate into the largest practical gains. At 7B parameters and 8K context length, the efficiency advantage is 1.21× in training throughput (Table 13) — a meaningful but modest improvement. At 175B, this grows to 1.29×, with TransNormerLLM supporting 12K context vs. 10K for the Transformer. However, without knowing whether the 175B TransNormerLLM maintains competitive benchmark performance with equivalently-sized Transformers (GPT-3 175B, BLOOM 176B), the efficiency measurements are of limited practical value — a faster model that underperforms on downstream tasks is not a viable replacement. The efficiency-accuracy tradeoff at scale is the critical unknown: does the 1.29× speedup at 175B come at the cost of degraded benchmark scores, or does the performance gap narrow, widen, or stay constant with scale?

**What evidence exists in the paper.** Tables 13 and 14 provide efficiency measurements for models from 7B to 175B. The architectural scaling trends are encouraging — the relative speedup grows from 1.21× at 7B to 1.29× at 175B. However, Table 9 stops at 7B parameters. The paper offers no perplexity curves, no validation loss trajectories, and no benchmark evaluations for models larger than 7B. Appendix A (Table 10) lists configurations for 13B, 65B, and 175B models, confirming that these were designed and at least partially trained (the stress tests require trained models to measure throughput and memory), but no quality metrics are reported.

**Mitigation status.** Not addressed. The paper does not explain why benchmark results are absent for the larger models, nor does it frame this as a limitation to be addressed in future work. Given the paper's title ("A Faster and Better Large Language Model with Improved TransNormer") and its claim to be the "first linear attention-based Large Language Model (LLM) that outperforms conventional softmax attention-based models" (Abstract), the absence of large-scale benchmark evidence is a significant gap. The strongest form of the paper's claim requires demonstration at GPT-3 scale (175B) on standard benchmarks; the current evidence supports only a weaker claim about models up to 7B parameters with promising scaling trends at larger sizes.

### Limitation 5: The Constant Inference Time Guarantee (Figure 4) Is Demonstrated Only for a Prefill-Free Generation Scenario on a Single GPU

**The assumption or constraint.** Figure 4 demonstrates that TransNormerLLM inference time and memory are constant across sequence lengths from 256 to 32,000 tokens, while the Transformer's grow linearly. The paper's robust inference algorithm (Algorithm 2) theoretically enables this by updating a fixed-size `[kv]` matrix of dimensions `d × d` at each step. However, the paper does not specify under what conditions Figure 4 was measured. Key unstated details include: whether this measures only the per-token generation step (not the initial prefill, where the full input prompt must be processed); what batch size was used; whether the measurement includes the full model or only the attention component; which GPU hardware was used; and whether the measurement accounts for the cost of computing `Q`, `K`, `V` projections and the SGLU feed-forward layers, which scale with `n × d^2` even if attention itself is constant-time.

**The consequence.** In a realistic autoregressive generation scenario, there are two phases: (1) **prefill**, where the full input prompt (potentially thousands of tokens long) is processed in parallel to populate the KV cache (or, in TransNormerLLM's case, the running `[kv]` matrix), and (2) **generation**, where tokens are produced one at a time, each attending to all previous tokens. The constant-time claim applies only to phase 2, and only to the attention component within phase 2. During prefill, TransNormerLLM must process the entire prompt — the computation scales as `O(n d^2)` for `n` prompt tokens, which is linear (not constant) in prompt length. For a long prompt (e.g., a 32K-token document to be summarized), the prefill cost may dominate the total inference cost, and the constant-time per-token generation advantage becomes marginal. The paper does not specify whether Figure 4 includes prefill cost, measures only per-token generation cost after some fixed-length prompt, or measures a synthetic scenario with no prefill. Additionally, the projections `XW_q`, `XW_k`, `XW_v`, `XW_u` and the SGLU channel mixing each require `O(n d^2)` computation that grows linearly with sequence length — only the attention component is constant-time. If these other components dominate the attention cost at the sequence lengths measured, the overall model inference time would still grow with `n`, just with a smaller slope than the Transformer.

**What evidence exists in the paper.** Figure 4 has axis labels ("Sequence length" vs. "Runtime (ms)" and "Sequence length" vs. "Memory (GB)") but the figure caption provides no methodological detail: "Inference Time and Memory Footprint. Left: inference runtime measured in milliseconds across different sequence lengths. Right: memory consumption during inference for varying sequence lengths." Section 3.3 (Robust Inference) describes Algorithm 2 but does not discuss prefill vs. generation or the contribution of non-attention components to total inference cost. The paper's claim that TransNormerLLM "demonstrates a consistent inference time and memory footprint" (Figure 4 caption) is ambiguous about whether this is per-token generation time, total time for processing a sequence of that length, or attention-only time.

**Mitigation status.** Not addressed. The paper presents Figure 4 as evidence of constant inference time without clarifying the measurement methodology, making it difficult for practitioners to determine whether the observed behavior would translate to their deployment scenario. For applications with long prompts (document QA, summarization, multi-turn dialogue where conversation history grows long), the prefill cost may be substantial, and the constant-time generation advantage may be a smaller fraction of total inference time than Figure 4 suggests.

### Limitation 6: The Structured Decay Schedule (Equation 2) Has No Ablation on Its Key Hyperparameter — the Dynamic Range Constant

**The assumption or constraint.** Equation 2 defines the head-and-layer-dependent decay schedule:

$$\lambda = \exp\left(-\frac{8h}{H} \times \left(1 - \frac{l}{L}\right)\right)$$

where the constant `8` in the numerator controls the dynamic range of decay rates: a larger constant produces a wider spread between the slowest-decaying head (large `λ`, near-global) and the fastest-decaying head (small `λ`, highly local), and also steepens the layer-dependent gradient. The paper states that `λ` is non-learnable because making it learnable causes "gradients [to] become unstable... leading to NaN values" (Section 3.1.1). These two decisions — fixing the dynamic range constant to exactly 8, and making all decay rates static — are presented as empirically motivated but receive no systematic experimental justification.

**The consequence.** The constant 8 is essentially an untuned hyperparameter that governs the model's temporal representation diversity. If 8 is too small, all heads have similar decay rates (low diversity) and the multi-scale temporal representation hypothesis is not realized — every head is either too local or too global. If 8 is too large, the fastest-decaying heads have extremely small `λ` (e.g., `λ = exp(−8) ≈ 0.0003` for head `H` in layer 1), effectively restricting them to attending to only the most recent few tokens — defeating the purpose of linear attention with global connectivity. The paper also does not explore stabilized learning of `λ` — for instance, learning `λ` in log-space, applying gradient clipping specifically to the decay parameters, or using a regularization penalty to prevent `λ` from approaching the unstable regime. The binary framing ("learnable causes NaN, non-learnable works") leaves unexplored a large design space of partially-learnable or constrained-learnable decay schedules that might outperform the static schedule.

Additionally, the paper pairs the non-learnable `λ` with a learnable rotary position encoding `θ` (from LRPE). The interaction between a learnable rotation and a fixed decay is unexplored — it is plausible that making `λ` learnable failed because the combination of learnable `θ` and learnable `λ` creates optimization interference, and that fixing *both* or learning *only* `λ` (with fixed `θ`) might succeed. The single NaN report provides no diagnostic information about *why* the gradients become unstable.

**What evidence exists in the paper.** The paper states: "we empirically found that gradients become unstable when λ is learnable, leading to NaN values" (Section 3.1.1). No experiment, figure, or table is provided to support this claim — it is a statement of empirical observation without documentation. Table 4 ablates the *temperature* term `(1 − l/L)` within the static schedule (showing a 0.034 PPL benefit), but there is no ablation on the dynamic range constant 8, no experiment comparing different static constants (e.g., 4, 8, 12, 16), and no exploration of partially-learnable alternatives. The paper does not discuss the choice of 8 or whether any hyperparameter search was conducted over this value.

**Mitigation status.** Not addressed. The dynamic range constant 8 appears to be an arbitrary choice based on the intuition that the head-dependent term `h/H` should produce a meaningful spread (with `8h/H` ranging from approximately `8/H` to 8, providing head 1 with very slow decay and head H with fast decay). The paper neither justifies this choice through ablations nor acknowledges it as an unexplored design dimension. For practitioners implementing TransNormerLLM, the sensitivity of model quality to this constant is unknown — a different model size, head count, or training corpus might require a different dynamic range, but the paper provides no guidance for selecting it. The complete foreclosure of learned `λ` based on an unreported NaN observation is also a limitation — the instability might be fixable with standard numerical techniques, and learned decay rates could substantially improve the model's ability to adapt its temporal receptive fields to task demands.

## 7. Implications and Future Directions

### How This Work Changes the Landscape

TransNormerLLM does not introduce a fundamentally new mathematical framework for attention — linear attention has existed since at least 2020 (Katharopoulos et al., 2020). Rather, the paper's contribution is **diagnostic and engineering**: it identifies, through systematic ablation, the specific reasons prior linear attention models failed to scale to LLM training regimes, and it demonstrates that a coordinated set of fixes — structured multi-scale exponential decay, gating, simplified normalization, IO-aware training, and numerically stable recurrent inference — closes the gap with softmax attention on standard benchmarks at competitive scales.

This is best understood as a **credibility-restoring result** for linear attention in the LLM era. Before this paper, the dominant narrative in the field was that linear attention, while theoretically appealing, suffered from an irreducible accuracy-efficiency tradeoff that made it unsuitable for large-scale language modeling: models either performed poorly (Katharopoulos et al., 2020; cosFormer, Qin et al., 2022b) or failed to deliver real-world speed advantages (due to the cumsum bottleneck and IO inefficiency, as the paper articulates in Section 2.2). The field's practical response was to pursue alternatives — state space models (S4, Mamba), linear RNNs (RWKV), sparse attention, and long convolutions — while treating linear attention itself as largely abandoned for LLM-scale work.

TransNormerLLM changes that calculus. By showing that a linear attention model can match LLaMA2-7B on many commonsense benchmarks (Table 9: 75.21 vs. 76.02 on HellaSwag, 75.42 vs. 76.30 on ARC-easy) while providing 1.21–1.35× training throughput advantages (Tables 13–14) and constant inference time regardless of sequence length (Figure 4), the paper demonstrates that the failure mode was not inherent to linear attention but rather to incomplete implementations of it. The specific burden of proof that the paper meets is: **linear attention with properly designed positional encoding, gating, normalization, and IO-aware computation can be competitive with softmax attention at LLM scale.** This is not a paradigm shift — the paradigm (linear attention reduces complexity from O(n²d) to O(nd²)) was always clear. It is an **existence proof** that the paradigm can be realized in practice.

The paper also reframes what "efficiency" means for attention mechanisms. Prior work often reported theoretical asymptotic complexity improvements without demonstrating wall-clock speedups on real hardware at real LLM scales. The paper's Lightning Attention (Figure 3) and SRMSNorm Triton kernel (Figure 2) demonstrate that IO-awareness — the principle that GPU memory bandwidth, not FLOPs, is the binding constraint for attention computation — applies to linear attention just as it does to softmax attention (FlashAttention), but requires a fundamentally different tiling strategy because the algorithmic structure differs (element-wise masking vs. softmax row-wise normalization). This establishes that **IO-awareness is a general design principle for attention mechanisms, not a softmax-specific optimization**, and that each attention variant requires its own IO-efficient algorithm rather than a one-size-fits-all approach.

**Reconciling prior contradictions.** The paper does not explicitly reconcile conflicting results from prior linear attention work (since prior linear attention work largely did not claim LLM-scale competitiveness). However, it implicitly reconciles a tension that has existed in the broader efficient architectures literature: the tension between models that achieve strong long-range benchmarks (like S4 on Long-Range Arena) and models that achieve strong language modeling perplexity (like Transformers). TransNormerLLM demonstrates that the two are not opposed — the same architecture can process long sequences efficiently (Figure 4) while matching Transformer perplexity and downstream performance — provided the temporal representation (decay schedule, rotary encoding) and training/inference algorithms (Lightning Attention, robust inference) are properly designed.

**Research directions that become more attractive:**

- **Linear attention as a drop-in replacement for softmax attention in existing Transformer training pipelines.** TransNormerLLM's architecture retains the standard Transformer block structure (token mixing + channel mixing with residual connections and pre-normalization). This means the extensive infrastructure for training Transformers at scale — FSDP, activation checkpointing, mixed precision, Megatron-style model parallelism — transfers directly, with only the attention computation needing replacement. This lowers the barrier for experimentation compared to architectures that require entirely new training recipes (state space models) or fundamentally different parallelism strategies.

- **Verifier and self-improvement pipelines that exploit constant-time inference.** The constant inference time demonstrated in Figure 4 means that generating long reasoning chains — where a model produces thousands of tokens of intermediate computation before arriving at a final answer — becomes economically viable in a way that it is not with softmax attention, where each additional generation step costs progressively more. Self-improvement methods that rely on long model-generated trajectories (STaR, ReST^EM, process reward model training) could benefit disproportionately from TransNormerLLM's inference characteristics.

- **Architecture co-design for linear attention.** The paper's demonstration that simplifications like SGLU (removing the GLU activation) and SRMSNorm (removing the learned scale) cost nothing in performance (Tables 7–8) suggests that the standard Transformer component set was co-designed with softmax attention, and that linear attention admits a simpler, more efficient component set. This opens the door for more aggressive architecture search — what else can be removed or simplified when softmax is absent?

**Research directions that become less attractive:**

- **Further theoretical work on linear attention variants that lack practical implementation.** The paper establishes that implementation quality — IO-awareness, numerical stability, optimized kernels — is the binding constraint on linear attention performance, not the specific choice of kernel function or normalization scheme. Future linear attention proposals that cannot demonstrate wall-clock speedups on real hardware against a strong baseline (Lightning Attention or equivalent) will be less compelling.

- **Pure state space models or long convolutions as alternatives to attention for general language modeling.** The paper demonstrates that a properly implemented linear attention model can achieve competitive LLM performance without the specialized mathematical machinery (HiPPO initialization, FFT convolution) that state space models and long convolutions require. While these alternatives may have domain-specific advantages (e.g., state space models for continuous-time signals), their marginal benefit over well-implemented linear attention for language modeling is now less clear.

### Follow-Up Research This Work Enables

**1. Dynamic decay rate adaptation for length generalization.** The paper's fixed decay schedule (Equation 2), with `λ` determined purely by head index and layer depth, was designed for training sequences of 8,192 tokens. At inference time with substantially longer sequences (e.g., 32K+ tokens), the fixed decay rates cause tokens near the beginning of the sequence to be attenuated below floating-point precision — even with the numerically stable Algorithm 2 — because `λ^(t−i)` becomes zero for large `t−i` when `λ < 1`. A critical follow-up would investigate whether making `λ` **length-dependent** — scaling the effective decay rate so that the half-life of attention is proportional to the total sequence length — enables effective long-range reasoning beyond the training length. Concretely, one could modify Equation 2 to `λ = exp(−8h/(H × (L_seq/L_train)))`, where `L_seq` is the inference-time sequence length. The evaluation would measure perplexity on held-out long documents (e.g., PG-19, Books3) at lengths of 16K, 32K, and 64K tokens, comparing fixed vs. length-scaled decay. More ambitiously, one could evaluate on needle-in-a-haystack retrieval (where a fact is inserted at a random position in a long context and the model must recall it) to directly measure whether length-dependent decay improves information retention at arbitrary distances.

**2. Head-level ablation of the multi-scale decay schedule to identify redundancy.** Equation 2 creates a spread of decay rates across heads through the term `8h/H`, meaning heads 1 through H have progressively faster decay. The paper never ablates whether all H heads are necessary, whether the linear spacing of decay rates is optimal, or whether the model actually learns to use different heads for different temporal ranges. A strong follow-up would **prune heads with intermediate decay rates** and measure the impact on perplexity and downstream benchmarks. The hypothesis is that the multi-scale representation might be highly redundant — perhaps only a few heads (e.g., the slowest-decaying and fastest-decaying, or every k-th head) carry most of the temporal information, and the rest can be removed or merged without loss. The experiment would start with the trained 7B checkpoint from the paper, compute the effective contribution of each head (e.g., by measuring the change in output when that head's attention is zeroed out), and progressively prune the least impactful heads, fine-tuning briefly after each pruning step. A finding that 50% or more of heads can be removed with minimal performance loss would suggest that the fixed decay schedule over-allocates capacity to temporal representation, and that a learned or sparser schedule would be more efficient.

**3. Direct FLOPs-matched comparison of TransNormerLLM and Transformer at 7B scale.** The paper's architecture comparison (Table 1) is limited to 100K training steps at 385M and 1B parameters on 300B tokens, and the downstream benchmark comparison (Table 9) is confounded by different training token budgets, data compositions, and hyperparameter tuning across models from different groups. A definitive architecture comparison would train TransNormerLLM-7B and a standard Transformer-7B (with FlashAttention-2) on the **exact same corpus, same tokenizer, same training hyperparameters, and same total FLOP budget**, recording validation perplexity throughout training and evaluating both models on the full set of downstream benchmarks in Table 9. This experiment would isolate the architectural effect from all confounding variables. The key measurement is not just final benchmark scores but the **entire scaling curve** — does TransNormerLLM learn faster per FLOP, or does it converge to a better optimum, or does it show diminishing returns relative to the Transformer at larger scales? The paper's current evidence suggests the gap widens from 385M to 1B (5% to 22% PPL improvement), but without the 7B data point, the scaling trend is speculative.

**4. Investigation of the OBQA outlier to determine whether it reflects a genuine capability or an artifact.** TransNormerLLM-7B's OpenBookQA score of 63.40 (Table 9) substantially exceeds all competing 7B models (LLaMA2: 44.20, MPT: 42.20, Falcon: 43.80, even LLaMA1: 57.20). This 19-point gap over LLaMA2 — the largest single-benchmark deviation in the entire table — demands investigation. A strong follow-up would systematically evaluate TransNormerLLM and matched Transformers on OpenBookQA under controlled conditions: same training data, same token budget, multiple evaluation protocols (0-shot, 5-shot, chain-of-thought), and with ablation of whether the advantage persists when the model is trained without the scientific/academic writing portion of the corpus (200B tokens of academic writings, Table 11). If the advantage disappears when academic writings are removed, it confirms data contamination or domain specialization rather than architectural benefit. If it persists, it suggests TransNormerLLM's linear attention with exponential decay is particularly well-suited to the multi-hop factual reasoning that OBQA requires — a finding that would merit deeper investigation into the interaction between attention decay and factual recall.

**5. Training a 175B TransNormerLLM and evaluating against GPT-3 and BLOOM on standard benchmarks.** The paper provides efficiency measurements for TransNormerLLM at 175B (Tables 13–14) but no benchmark results. The existence proof that linear attention can match softmax attention at LLM scale is incomplete without demonstrating competitive performance at GPT-3-class scale on MMLU, HellaSwag, and other standard benchmarks. A critical follow-up would complete the training and evaluation of the 175B model (whose configuration is already specified in Table 10: 88 layers, 12,288 hidden dimension, 96 heads) on the same corpus used for the smaller models, and report MMLU, HellaSwag, ARC, and other standard evaluation scores. The comparison should use multiple baselines: GPT-3 175B (if accessible), BLOOM 176B, and ideally an internally-trained Transformer-175B with FlashAttention-2 on the same data. This experiment would also reveal whether the efficiency advantage (1.29× throughput at 175B, 20% longer context) translates into maintained or improved benchmark performance at scale — the central unanswered question from the current paper.

**6. Evaluating the compute-optimal scaling law for linear vs. softmax attention.** The paper establishes that TransNormerLLM has better training efficiency than Transformer at matched parameter counts (Tables 13–14), but does not address the **compute-optimal allocation** question: given a fixed total FLOP budget, should one train a larger TransNormerLLM or a smaller Transformer, or vice versa? This requires training multiple model sizes of each architecture under iso-FLOP constraints and measuring the resulting validation loss and downstream performance, analogous to the Chinchilla scaling law analysis. The experiment would train TransNormerLLM and Transformer at sizes ranging from 100M to 7B parameters, each with a fixed total training FLOP budget (e.g., 10^20, 3×10^20, 10^21), and fit power-law curves to determine the optimal model size for each architecture at each budget. The hypothesis is that TransNormerLLM's linear complexity means the compute-optimal allocation shifts toward larger models (since the per-token training cost grows more slowly with sequence length), making linear attention increasingly advantageous as total compute budgets increase. This experiment would provide the theoretically principled justification for adopting linear attention that the current paper's empirical engineering comparisons approximate but do not rigorously establish.

### Practical Applications and Downstream Use Cases

**Long-context batch processing for document analysis.** For organizations that process large document collections — legal document review, scientific literature mining, financial report analysis — the combination of TransNormerLLM's linear memory scaling during training (Figure 3, right: 4× less memory at 8K sequence length) and constant inference time (Figure 4, left: flat runtime from 256 to 32K tokens) directly reduces infrastructure costs. A document QA system that processes 32K-token documents with a Transformer-7B would see inference latency grow roughly 8× compared to 4K-token documents; with TransNormerLLM, latency stays constant. The 1.21–1.35× training throughput advantage (Table 14) additionally reduces the cost of fine-tuning on domain-specific documents. For a service processing 1 million 16K-token documents per day, the inference memory savings alone (~3.5 GB vs. ~8 GB per GPU at 16K tokens, extrapolating Figure 4, right) could reduce the GPU fleet size by roughly half.

**Chinese-English bilingual enterprise LLM deployment.** TransNormerLLM's training corpus is 27% Chinese (555B tokens, Table 11), and the benchmark results on CMMLU (47.99) and C-Eval (43.18) substantially exceed English-centric models like LLaMA2-7B (32.96 and 33.20 respectively) while remaining competitive on English benchmarks (MMLU 43.10 vs. LLaMA2 45.30). For enterprises serving bilingual (Chinese-English) user bases — common in Asia-Pacific markets — TransNormerLLM provides a single-model solution that avoids the additional cost of maintaining separate English and Chinese models or relying on translation pipelines. The 7B model's memory footprint of ~24 GB per GPU at model parallel size 8 (Table 12) means it can be served on a single A100 or A10 GPU, making on-premises deployment feasible for organizations with data sovereignty requirements that prohibit using cloud-based LLM APIs.

**On-device or edge deployment with long-form generation.** The constant per-token inference cost demonstrated in Figure 4 (left) — approximately 3.5–4.0 ms per token regardless of how many tokens have already been generated — makes TransNormerLLM particularly suitable for applications requiring long, open-ended generation from a local model. Examples include: code autocomplete running locally in an IDE, where the model may need to generate hundreds of tokens of code while attending to thousands of tokens of existing file context; or privacy-sensitive document drafting where user documents never leave the device. With a Transformer, the latency for generating the 500th token of a response to a 4K-token prompt is roughly 2–3× higher than generating the 10th token; with TransNormerLLM, the latency is identical (ignoring the one-time prefill cost of processing the prompt), providing a predictable user experience. The 4× attention memory reduction during training (Figure 3) also means that smaller TransNormerLLM variants (385M, 1B) can be fine-tuned on domain-specific data using consumer GPU hardware (e.g., RTX 4090 24GB) at context lengths that would be infeasible for equivalently-sized Transformers.

**Token-efficient self-improvement pipelines with long reasoning trajectories.** The paper's efficient inference characteristics are well-matched to self-improvement methods like STaR (Zelikman et al., 2022) or ReST^EM (Singh et al., 2024), where a model generates multi-step reasoning chains that are then filtered by correctness and used for fine-tuning. In such pipelines, the generation phase dominates the total computation, and each reasoning chain may be thousands of tokens long (problem statement + step-by-step solution + verification). With TransNormerLLM's constant per-token generation cost, the economic feasibility of generating very long reasoning trajectories — which may be necessary for complex mathematical or scientific reasoning — improves substantially compared to Transformers, where the later steps of a long chain are disproportionately expensive. The 1.21× training throughput advantage additionally reduces the cost of the fine-tuning phase after new training data has been generated. Concretely, a self-improvement loop that generates 100K reasoning chains averaging 4K tokens each would save roughly 20% in generation compute costs and 20% in fine-tuning compute costs compared to an equivalent Transformer pipeline, with the savings compounding over multiple improvement iterations.
