# Layer-Condensed KV Cache for Efficient Inference of Large Language Models

**ArXiv:** [2405.10637](https://arxiv.org/abs/2405.10637)

## 🎯 Pitch

This paper introduces a **Layer-Condensed KV Cache** method that reduces the memory footprint of transformer inference by computing and caching key-value pairs for only a single top layer rather than every layer, pairing queries from all layers with that one set of KVs.

---

## 1. Executive Summary

This paper introduces a **Layer-Condensed KV Cache** method that reduces the memory footprint of transformer inference by computing and caching key-value pairs for only a single top layer rather than every layer, pairing queries from all layers with that one set of KVs. Experiments on Llama models from 1.1B to 30B parameters demonstrate up to 26× higher throughput and up to 32× larger batch sizes compared to standard transformers, while retaining competitive performance on language modeling and commonsense reasoning benchmarks—with a sandwich-style configuration of a few retained standard-attention "warmup layers" (e.g., `w = 10`) recovering essentially all of the gap to baseline accuracy. The approach integrates orthogonally with sequence-length compression techniques like StreamingLLM, establishing that layer-count reduction and sequence-length reduction are independent, composable axes for inference efficiency.

## 2. Context and Motivation

### The Core Problem: The KV Cache Is a Memory Bottleneck That Scales With Both Sequence Length *and* Layer Depth

The fundamental inefficiency this paper targets is deceptively simple to state but mechanically profound: **in a standard transformer decoder, every layer must compute and cache its own key-value pairs for every previously generated token, and the aggregate memory cost grows proportionally to both the sequence length and the total number of layers.** For large language models with tens of layers (e.g., 32 layers in Llama-7B, 60 layers in Llama-30B, and hundreds in frontier models), the KV cache becomes a dominant consumer of GPU memory during autoregressive generation—often exceeding 30% of total GPU memory in deployment (as the authors note, citing Kwon et al., 2023).

This is not merely an academic concern. The memory consumed by the KV cache directly constrains the **maximum batch size** an inference server can handle. Since GPU memory is fixed and shared among model parameters, activations, and the KV cache, every byte spent on caching KVs for previously generated tokens is a byte that cannot be used to process additional requests in parallel. In high-throughput serving scenarios—chat applications, API endpoints, batch processing pipelines—batch size is a primary determinant of tokens-per-second throughput and cost-per-token economics. A 30% reduction in KV cache memory translates almost directly to the ability to serve proportionally more concurrent requests on the same hardware.

The problem intensifies with modern trends: models are getting deeper (more layers means proportionally more KV cache), context windows are expanding to hundreds of thousands or millions of tokens (more cached positions per layer), and applications increasingly demand long-form generation (each generated token adds one more cached entry per layer). These three factors multiply together: a 60-layer model generating 8,192 tokens with a prompt of 8,192 tokens stores approximately $60 \times (8192 + 8192) \times d_{\text{kv}}$ floats, where $d_{\text{kv}}$ is the per-head KV dimension. The authors make explicit that this is "one of the most significant parts" of memory consumption (Section 1), and this framing is backed by the system benchmarking literature they cite (Pope et al., 2023; Zhang et al., 2023; Sheng et al., 2023).

### Why Prior Approaches Focused Only on One Axis (Sequence Length) and Missed the Other (Layer Count)

Every existing method the paper surveys operates by **reducing the number of cached tokens per layer**—that is, compressing along the sequence-length dimension. The authors provide a taxonomy in Section 1 and the Related Work (Section 5):

- **Prompt compression methods** (Jiang et al., 2023a,b; Li et al., 2023; Mu et al., 2023) shorten the effective prompt by removing redundancies, compressing document-level context into shorter representations, or learning "gist tokens" that summarize reusable system prompts. These reduce the number of prompt tokens that enter the KV cache.
- **Token pruning / eviction methods** (Zhang et al., 2023; Liu et al., 2023; Ge et al., 2023) dynamically discard KV entries during generation based on attention scores or importance heuristics, keeping only a subset of previously seen tokens. H2O (Zhang et al., 2023) uses cumulative attention scores to identify and retain "heavy hitter" tokens. Scissorhands (Liu et al., 2023) exploits the persistence of token importance across steps.
- **Attention sink methods** (Xiao et al., 2024; Han et al., 2023) observe that initial tokens act as "attention sinks" that absorb disproportionate attention mass, and that only initial tokens plus recent tokens are essential—allowing intermediate tokens to be discarded. StreamingLLM (Xiao et al., 2024) uses this to enable theoretically infinite-length context with constant cache size.

All of these are fundamentally **one-dimensional**: they ask "which tokens should we keep?" but never ask "how many layers' worth of KVs do we need per token?" A method that compresses the sequence length by a factor of $k$ reduces KV cache from $O(L \times n)$ to $O(L \times n/k)$, where $L$ is the number of layers and $n$ is the sequence length. But the factor $L$—the number of layers—remains untouched. This is a multiplicative blind spot: if you could reduce $L$ to a small constant, you would multiply the benefits of any sequence-length compression on top.

### Where Existing Methods Fall Short

Beyond the one-dimensional reduction, the paper identifies a more structural limitation: all prior methods modify the **content** of the KV cache (which tokens are stored), which necessarily introduces a **quality-efficiency tradeoff**. When you discard tokens from the KV cache, you are discarding information that the attention mechanism might need. The heuristics used to decide what to discard—attention score thresholds, recency biases, fixed patterns—are approximations that can fail. A token deemed unimportant at one generation step might become critical later, and once evicted from the cache, it is permanently lost (unless recomputed at additional cost). The paper's own experiments with StreamingLLM (Section 3.3, Figure 6) show that while the method works, perplexity degrades as the cache size shrinks—the quality-efficiency tradeoff is real.

By contrast, the authors propose to reduce the other multiplicative factor: **the number of layers that produce and store KVs**. This is qualitatively different because it does not discard information about *which tokens* were seen—it changes *which representation* of those tokens is used for attention. The idea is that if the top layer's representation is the most refined (having been processed through the full depth of the network), it might be sufficient for attention computation at all layers, making the per-layer KVs of lower layers redundant.

### The Conceptual Insight: Stacked Layers as Iterative Refinement

The paper draws motivation from an interpretation of transformer depth articulated in prior work (Wu and Tu, 2023): the stacking of transformer layers can be viewed as an **iterative process of improving token representations**, where each layer refines the hidden state produced by the previous one. Under this view, the representation at the top layer is the most informative—it has benefited from the full depth of computation. If that representation is strictly better than intermediate-layer representations, then using it as the sole source of keys and values for attention at all layers might be not just acceptable but optimal.

This interpretation connects to an underexplored parallel: the standard transformer **encoder-decoder** architecture. In a typical encoder-decoder, all decoder layers attend to the output of the **top encoder layer** via cross-attention—they do not attend to intermediate encoder layers. This works because the top encoder layer's representation is considered the most refined encoding of the source sequence. The authors explicitly note this similarity: "We also note the similarity of our idea to the cross-attention mechanism in a standard transformer encoder-decoder, in which all the decoder layers attend to the top encoder layer" (Section 1). But applying this principle *within* a single decoder stack—having each decoder layer attend to the top decoder layer's KVs from previous tokens—had never been attempted before this work.

The key difference that makes the decoder case challenging is the **cyclic dependency**: in a decoder, each token must attend to itself (and to previous tokens), but the top-layer representation of the current token cannot be computed until all lower layers have finished processing it. The encoder-decoder case has no such problem because the encoder is fully computed before the decoder begins. This cyclic dependency is what the paper must solve through its training and inference procedures—and it is likely why the approach was not previously proposed despite the conceptual similarity to encoder-decoder cross-attention.

### Prior Work That Touches Related Ideas (and Why It's Different)

The paper acknowledges the closest prior work: **Feedback Transformers** (Fan et al., 2020), which aggregate hidden representations from all layers and use them as a "token memory" from which KVs are projected for all layers. This shares the high-level idea of using representations from multiple or all layers to produce a shared KV store. However, the authors identify a critical practical difference that explains why Feedback Transformers did not see adoption for large-scale LLM inference: their training process is **fully sequential**, processing one token at a time with no parallelization. As the authors state, "their sequential training process is time-costly and not practical for large models" (Section 5). The Layer-Condensed KV Cache method's primary algorithmic contribution—beyond the model design itself—is the **parallel training approximation** (Section 2.2) that makes the approach computationally feasible at scale. This is the bridge from an interesting theoretical idea to a practically deployable method.

### How This Paper Positions Itself

The paper frames its contribution not as a replacement for sequence-length compression methods, but as an **orthogonal and composable** layer of optimization. This positioning is explicit and strategically important: "our method is orthogonal to existing transformer memory-saving techniques, so it is straightforward to integrate them with our model, achieving further improvement in inference efficiency" (Section 1). The integration experiment with StreamingLLM (Section 3.3, Figures 5–7) is designed to demonstrate exactly this: layer-count reduction and sequence-length reduction are independent multiplicative factors. If StreamingLLM alone reduces KV cache memory to $O(c)$ where $c$ is a constant cache size, and LCKV alone reduces it to $O(1)$ layers' worth, the combination reduces it to $O(c \times 1) = O(c)$—but with the constant improved by the layer-factor reduction that StreamingLLM alone cannot achieve.

The paper also positions itself in the context of a broader engineering trend: the growing recognition that inference efficiency is a first-class design constraint for LLMs, not an afterthought applied post-training. This is reflected in the benchmarks they choose: maximum batch size and tokens-per-second throughput on realistic hardware (RTX 3090 with 24GB, A100 with 80GB), using end-to-end generation with FlashAttention-2 and fused kernels—exactly the setting in which production deployment decisions are made. The comparison of a 1.1B model with LCKV against the standard TinyLlama baseline (Section 3.2) directly addresses whether the efficiency gains come at an unacceptable accuracy cost, and the sandwich warmup layer configuration is positioned as the mechanism to dial the tradeoff to near-zero accuracy degradation.

### The Specific Gaps the Paper Directly Addresses

Synthesizing the above, the paper addresses a set of concrete, previously unaddressed gaps:

1. **The layer-count dimension of KV cache memory is completely unexploited.** Every existing method compresses along the token-count axis; no prior work asks whether all layers need to produce and store their own KVs. This is the foundational gap that motivates the entire paper.

2. **No prior method achieves memory reduction without discarding token-level information.** Sequence-length compression necessarily implies information loss about which tokens were in the context. Reducing layer count avoids this tradeoff entirely—it changes the *quality* of the stored representation (from each layer's own KVs to the top layer's KVs) without discarding any token positions.

3. **The iterative-refinement view of transformer depth has not been operationalized for inference efficiency.** While the interpretation that higher layers produce better representations exists in the analysis literature, it had not been translated into a concrete architectural modification that eliminates per-layer KV computation for lower layers.

4. **The practical training bottleneck that prevented Feedback Transformers from scaling has not been solved.** The cyclic dependency problem (a token's top-layer KV is needed for its own lower-layer attention computation, but the top layer hasn't been computed yet) is the algorithmic barrier that the paper's parallel training method overcomes.

These gaps collectively define a research space that the paper occupies: **structural reduction of KV cache memory through layer sharing, motivated by representation quality arguments from the analysis literature, enabled by a novel parallel training approximation, and designed for composition with existing sequence-length compression techniques.**

## 3. Technical Approach

### 3.1 Reader Orientation

The paper proposes a **structural modification to the transformer decoder architecture** in which queries from every layer attend to key-value pairs computed by only the top (or a small number of top) layers rather than needing each layer to compute and cache its own KVs. This solves the problem of KV cache memory growing linearly with the number of layers by **collapsing the layer dimension of the cache to a small constant**, achieving memory savings that multiply with any sequence-length compression technique applied on top.

### 3.2 Big-Picture Architecture (Diagram in Words)

The system has five major interconnected components that span both model architecture and training procedure:

1. **Layer-Condensed Attention Mechanism** — the core architectural modification: for all non-warmup layers, replace the standard self-attention (where layer `$\ell$` attends to KVs from layer `$\ell$`) with cross-layer attention where queries from layer `$\ell$` attend to KVs from the top layer only. This eliminates KV computation and storage for all layers except the top layer (and any designated warmup layers).

2. **Warmup Layers (Sandwich Configuration)** — a small number of layers (`$w$` total) that retain standard self-attention to preserve the model's ability to capture different types of linguistic information at different depths. These are split equally: `$w/2$` at the bottom of the network and `$w/2$` at the top, forming a "sandwich" around the layer-condensed middle section.

3. **Diagonal Attention Mask** — a modification to the attention pattern that prevents each token from attending to itself, breaking the cyclic dependency where a token would need its own top-layer KV (which hasn't been computed yet) to perform attention at lower layers.

4. **Iterative Parallel Training Procedure** — an algorithm that converts the inherently sequential computation graph (each token depends on the top-layer KV of all previous tokens) into a form that supports parallel training over all tokens in a sequence, using `$n$` iterations of parallel computation followed by gradient stopping and KV convergence approximations to make training tractable.

5. **Prompt Encoding by Iterative Refinement** — the inference-time procedure for processing input prompts, which runs enough iterations (`$m + b = 9$` by default) to allow the shared top-layer KVs to converge before generation begins.

### 3.3 Roadmap for the Deep Dive

- **First, the layer-condensed attention mechanism itself** (Section 2.1), because every other component exists to make this core idea work. We need to understand exactly what changes in the attention computation, which layers produce KVs, and which layers consume them.
- **Second, the diagonal masking and the cyclic dependency problem**, because this is the fundamental algorithmic barrier that the entire training procedure is designed to overcome. Understanding why the naive approach creates a deadlock explains why the training method is non-trivial.
- **Third, the warmup layers and sandwich configuration**, because these are the practical bridge between the extreme memory-saving version (single top layer) and the performance-preserving version (a few standard-attention layers retained).
- **Fourth, the parallel training procedure**, because this is the paper's primary algorithmic contribution beyond the architecture itself. We build up from the sequential computation graph → the equivalent iterative parallel graph → gradient stopping → KV convergence approximation.
- **Fifth, inference with prompts**, which follows naturally from the training procedure and completes the deployment picture.
- **Sixth, the summary of all hyperparameter defaults and their justifications**, since many design choices involve tradeoffs between memory, throughput, and accuracy.

### 3.4 Detailed, Sentence-Based Technical Breakdown

This is primarily a **systems and architecture paper** whose core insight is that the KV cache memory cost can be reduced by eliminating per-layer KV computation for most layers, using the top layer's more refined representations as a shared KV store for all layers' attention queries.

---

#### Layer-Condensed Attention: How Queries From All Layers Attend to One Set of KVs

In a standard transformer decoder with `$L$` layers, the self-attention operation at layer `$\ell$` at position `$i$` computes:

$$\text{Attention}(Q^\ell_i, K^\ell_{1:i}, V^\ell_{1:i})$$

where `$Q^\ell_i$` is the query vector at the current position `$i$` in layer `$\ell$`, `$K^\ell_{1:i}$` and `$V^\ell_{1:i}$` are the key and value vectors from layer `$\ell$` for all positions `$1$` through `$i$` (the current token plus all previous tokens). Each layer `$\ell$` projects its own hidden state through its own learned weight matrices `$W^\ell_K$` and `$W^\ell_V$` to produce these keys and values, and these projections are computed and cached for every layer independently.

The layer-condensed variant replaces this with:

$$\text{Attention}(Q^\ell_i, K^L_{1:i}, V^L_{1:i})$$

for all layers `$\ell$` that are not warmup layers. Here, `$L$` is always the top layer of the network (or the top warmup layer if warmup layers are used at the top). The critical changes are:

- **Only the top layer computes and stores KVs.** Layers other than the top layer and warmup layers do not compute `$K$` or `$V$` projections at all during inference. Their `$W_K$` and `$W_V$` weight matrices can be discarded entirely, reducing both memory and parameter count.
- **Queries from all layers use the same KV store.** Every attention head at every non-warmup layer queries against the identical set of key-value pairs from the top layer. This means there is a single KV cache for the entire model rather than one per layer.
- **The KV cache memory cost drops from `$O(L \times n \times d_{\text{kv}})$` to `$O(w \times n \times d_{\text{kv}})$`**, where `$w$` is the number of warmup layers (typically 2–10) and `$L$` is the total number of layers (22–60 in the models tested). Since `$w \ll L$` in all configurations, this is a substantial multiplicative reduction.

**What this computes:** For every non-warmup layer, the standard self-attention mechanism is executed, but with keys and values sourced from the top layer's KV projections rather than from that layer's own projections. The attention scores are computed as `$\text{softmax}(Q^\ell_i \cdot (K^L_{1:i})^T / \sqrt{d_k})$` and the output is the weighted sum `$\sum_{j} \alpha_{ij} V^L_j$`. This is architecturally identical to standard attention—the only change is *which activations serve as keys and values*.

**Why this form:** The design is motivated by the interpretation of transformer depth as iterative representation refinement. If the top layer produces the most informative token representations (having integrated information across the full depth of the network), then using those representations as attention keys and values should be at least as good as using intermediate-layer representations. The design also mirrors the standard encoder-decoder cross-attention pattern, where all decoder layers attend to the single top encoder layer's output—a pattern that is well-established as effective. The key variation is that in a decoder, the "encoder" (the top layer) is computed on-the-fly as tokens are generated, creating dependencies that require the training procedure innovations described below.

A subtle but important practical consequence: since layers that don't produce KVs also don't need `$W_K$` and `$W_V$` parameters, the model size is slightly smaller. This parameter reduction contributes to the throughput improvements independently of the KV cache memory reduction, since there are fewer weights to load and fewer matrix multiplications to perform during the forward pass.

---

#### The Cyclic Dependency Problem and Diagonal Masking

The layer-condensed attention mechanism creates an immediate problem: **a token at position `$i$` needs its own top-layer KV to attend to itself, but the top-layer representation of token `$i$` cannot be computed until all lower layers have finished processing token `$i$`.** This is a cyclic dependency:

1. To compute layer 1 at token `$i$`, you need `$K^L_i$` and `$V^L_i$` (the top-layer KV for token `$i$`).
2. But `$K^L_i$` and `$V^L_i$` are computed from `$h^L_i$`, the hidden state at the top layer.
3. `$h^L_i$` depends on the output of layer `$L-1$`, which depends on layer `$L-2$`, and so on down to layer 1.
4. Layer 1 depends on `$K^L_i$` — closing the cycle.

The paper's solution is simple and direct: **drop the self-attention of each token to itself** by masking the diagonal of the attention matrix. Mathematically, the attention pattern becomes strictly lower-triangular without the diagonal, meaning position `$i$` attends to positions `$1$` through `$i-1$` only, never to position `$i$` itself.

**What this computes:** For each token position `$i$`, the attention mechanism uses only the top-layer KVs from positions `$1, 2, ..., i-1$`, plus dummy zero vectors for position 1 (which has no previous tokens to attend to). The attention output at each layer is a weighted combination of *previous* token representations only, excluding the current token. The current token's information still propagates through the network via residual connections: the output of each layer is `$\text{LayerNorm}(x + \text{Attention}(x) + \text{FFN}(x + \text{Attention}(x)))$` where `$x$` is the input to the layer, so the token's own embedding and all intermediate representations flow upward through the residual stream even though they are not accessed through self-attention.

**Why this form:** Diagonal masking is the minimal change that breaks the cyclic dependency. It eliminates the only edge in the computation graph that points from a token's own future (top-layer) to its past (lower-layer). The alternative—computing the top layer first and then lower layers—would require knowing the final representation before computing the intermediate representations, which is circular in a different way. The diagonal mask avoids this entirely by ensuring that each token's attention computation depends only on *fully computed* previous tokens. The authors verify empirically that removing self-attention does not degrade performance (Section 2.1: "Empirically, we find that the diagonal mask of the attention matrix does not affect the performance of the model"), which is plausible because residual connections already provide a direct path for a token's own information to flow through the network without going through attention.

---

#### Warmup Layers and the Sandwich Configuration

The extreme version of layer-condensed attention—using only the single top layer's KVs for all attention operations throughout the model—produces a measurable accuracy degradation. The authors attribute this to the observation from prior work (Clark et al., 2019b) that **different layers in a transformer specialize in different types of linguistic information**: lower layers tend to capture syntactic patterns (part-of-speech, dependency relations, local phrase structure) while higher layers capture semantic patterns (entity relationships, discourse coherence, abstract meaning). Forcing all layers to attend to the same top-layer KVs eliminates this depth-dependent specialization.

The solution is to retain standard self-attention for a small number of layers, called **warmup layers**. These layers compute and cache their own KVs exactly as in a standard transformer, while all other layers use the layer-condensed attention pattern. The warmup layers are arranged in a **sandwich configuration**: `$w/2$` at the bottom of the network and `$w/2$` at the top. For example, with `$w = 10$` and `$L = 22$` (TinyLlama configuration), layers 1–5 and 18–22 use standard self-attention, while layers 6–17 use layer-condensed attention attending to the KVs of layer 22.

**What this configuration achieves:** The bottom warmup layers preserve the model's ability to extract and refine syntactic features at lower depths using their own per-layer KV representations. The top warmup layers produce their own KVs that encode the most refined semantic representations, which are then shared with the middle condensed layers. The condensed middle layers benefit from the top-layer KVs without needing their own KV computation. This splits the difference between the two extremes: `$w = 0$` (all condensed, maximum efficiency) and `$w = L$` (all standard, maximum accuracy).

**Why the sandwich specifically:** The authors test three configurations with `$w = 2$` (Table 4): warmup layers at the bottom only ("all-bottom"), at the top only ("all-top"), and split equally ("sandwich"). The sandwich configuration achieves the best perplexity (e.g., 14.069 vs. 14.556 for all-bottom and 221.850 for all-top on a 50M model). The authors hypothesize that "top and bottom layers serve different functionalities (e.g., semantic vs. syntactic) and it makes more sense to warm up both than just one of them." The all-top configuration's catastrophic performance (221.85 perplexity) is particularly informative: it suggests that bottom-layer syntactic processing benefits critically from layer-specific KVs, and that losing this bottom-layer specialization cannot be compensated by attending to top-layer semantics alone.

**Tradeoff controlled by `$w$` (Figure 8):** The number of warmup layers directly controls the memory-throughput-accuracy tradeoff. The authors sweep `$w$` from 0 to 22 on a 1.1B model:
- **`$w = 0$` (no warmup, "red region"):** Significant perplexity degradation relative to baseline (log dev ppl ~2.85 vs. ~2.70 for standard transformer). Maximum throughput because only one layer's KVs are cached.
- **`$w = 2$` to `$w = 6$` ("yellow region"):** Perplexity jumps close to baseline levels while throughput remains substantially higher than standard. The paper's default for high-throughput scenarios (`$w = 2$`).
- **`$w = 8$` to `$w = 16$` ("green region"):** Perplexity actually *beats* the standard transformer in some configurations (e.g., `$w = 10$` in the 1.1B model achieves slightly better dev perplexity and higher average downstream accuracy than TinyLlama), while throughput remains elevated but decreases as more warmup layers are added. The paper's default for quality-preserving scenarios (`$w = 10$`).
- **`$w = 22$` (all warmup):** Identical to standard transformer, no throughput benefit.

The non-monotonic behavior—where intermediate `$w$` values can *outperform* both `$w = 0$` and `$w = L$`—is notable. The authors don't fully explain this phenomenon, but it suggests that the layer-condensed attention pattern may act as a form of regularization or may force the model to learn more transferable representations in the middle layers that benefit from the shared top-layer KV context.

#### The Iterative Parallel Training Procedure: From Sequential to Tractable

Training a standard transformer decoder is naturally parallel over sequence positions: since each position's computation depends only on previous positions' *final* hidden states (through causal masking), all positions can be processed simultaneously in one forward pass. The layer-condensed architecture breaks this because **a position's computation depends on previous positions' *top-layer* KVs**, which are not available until the full depth of computation is complete for those previous positions. This creates sequential dependencies across positions as well as across layers.

The paper develops the training procedure in three conceptual steps, moving from an intractable sequential graph to a practical parallel approximation.

---

##### Step 1: From Sequential to Parallel (Equivalent Transformation)

The naive training computation graph (Figure 2a) is sequential over the `$n$` token positions: process token 1 through all `$L$` layers, producing its top-layer KV; then process token 2 (which uses token 1's top-layer KV) through all layers; then token 3; and so on. This is `$O(n)$` sequential steps, each of depth `$L$`, making training prohibitively slow.

The first key insight (Theorem 1, proven in Appendix A) is that there exists an **equivalent parallel computation graph** (Figure 2b) with the following structure:

1. **Initialize:** Process all `$n$` tokens through all layers in parallel, but pair queries with **dummy zero-vector KVs** for the attention operations. This produces an initial set of top-layer KVs for all positions.
2. **Iterate:** For iteration `$t = 1, 2, ..., n$`: process all `$n$` tokens through all layers in parallel again, but this time pair queries with the top-layer KVs produced in iteration `$t-1$`.
3. **Compute loss:** After `$n$` iterations, use the final hidden states from iteration `$n$` to compute the cross-entropy loss.

The equivalence rests on an inductive argument: in iteration 1, only token 1's computation is correct (it needs no previous KVs except the dummy zero vectors, which are available from the start). Token 2 is incorrect because it attends to token 1's KV from iteration 0 (the dummy), not from the properly computed version. In iteration 2, token 1's KV is now correct (it was computed correctly in iteration 1 using the dummy KVs—the only KVs it needs), and token 2's computation becomes correct because it now attends to token 1's correct KV from iteration 1. By induction, after `$t$` iterations, the first `$t$` tokens have correct computations. After `$n$` iterations, all tokens are correct.

**What this transformation achieves:** It replaces `$n$` sequential steps of depth `$L$` with `$n$` parallel-over-tokens steps of depth `$L$`. The critical point is that **the length of the longest dependency chain stays the same** — `$n$` iterations are still required. This is not yet a speedup; it's a restructuring that makes the computation *amenable* to the approximations that follow. The value is that each iteration can be parallelized across all tokens using standard batched matrix operations on GPUs, unlike the original sequential graph where each token truly must wait for the previous one.

The formal proof (Appendix A) defines `$f_{1,i}$` as the function computing token `$i$`'s final hidden state in the sequential graph, and `$f^{(t)}_{2,i}$` as the function computing it in iteration `$t$` of the parallel graph. The induction shows `$f_{1,i} = f^{(t)}_{2,i}$` for all `$t \geq i$`, regardless of initial KV values. This is because the data dependencies are topologically identical: token `$i$` always depends on KVs from tokens `$1$` through `$i-1$`, and by iteration `$i$`, those KVs have been correctly computed through the iterative refinement process.

---

##### Step 2: Gradient Stopping (Backpropagation Truncation)

Even with the parallel restructuring, training requires `$n$` iterations of forward computation, and—critically—backpropagation through all `$n$` iterations to compute gradients. For typical sequence lengths (`$n = 2048$`), this means backpropagating through `$2048 \times L$` layers of computation, which is far too large to fit in GPU memory.

The solution is **gradient stopping**, a technique borrowed from Transformer-XL (Dai et al., 2019): instead of backpropagating through all `$n$` iterations, backpropagate only through the last `$b$` iterations, treating the KVs from iteration `$n-b$` as fixed constants (no gradient flows through them). This reduces the backpropagation depth from `$n \times L$` to `$b \times L$`, making training memory-tractable.

**Why `$b \geq 2$` is necessary:** If `$b = 1$`, then backpropagation only reaches the computation of the final iteration. The KVs used in the final iteration come from iteration `$n-1$`, but since backpropagation stops at the boundary between iteration `$n-1$` and iteration `$n$`, no gradient flows to the parameters that produced those KVs. The `$W_K$` and `$W_V$` weights of the top layer receive no training signal at all, which the authors find "would result in a large performance degradation." With `$b = 2$`, gradients flow from the loss through the final iteration's computations, into the penultimate iteration's KVs (which were used as input to the final iteration), and from there to the parameters that produced those KVs. This is the minimum setting that allows the top-layer KV projections to be trained.

**The default is `$b = 2$`** across all experiments. The authors test `$b = 3$` and `$b = 4$` (Figure 11, Table 8) and find that larger `$b$` does not monotonically improve perplexity—in fact, for `$b = 4$`, the KVs converge more slowly and training becomes less stable for a 1.1B model (perplexity 10.885 for `$b = 4$` vs. 10.390 for `$b = 2$`). Training time also increases linearly with `$b$`. The instability with larger `$b$` likely arises because the longer backpropagation chain amplifies the approximation error from the KV convergence (step 3 below), causing gradients to become noisier.

---

##### Step 3: KV Convergence Approximation (Forward Propagation Truncation)

Even with gradient stopping, the forward pass still requires `$n$` iterations: `$n-b$` iterations to converge the KVs (no gradient through these) plus `$b$` iterations that receive gradients. For `$n = 2048$`, this is still `$2048$` forward passes, which is prohibitively expensive.

The critical empirical observation that enables practical training is that **KVs converge to their final values very quickly**—far faster than the `$n$` iterations suggested by theory. Figure 3 demonstrates this for a randomly initialized TinyLlama-configuration model with 2048 tokens: the mean squared error between KVs at iteration `$i$` and iteration `$i-1$` drops to near zero after approximately 15–20 iterations with no warmup layers, approximately 8–10 iterations with `$w = 2$`, and approximately 5–7 iterations with `$w = 4$`. More warmup layers accelerate convergence because the standard-attention layers act as anchors that stabilize the iterative process.

The training procedure exploits this by running only `$m$` iterations total instead of `$n$`, where `$m \ll n$`:

- The first `$m - b$` iterations are forward-only (gradients stopped).
- The last `$b$` iterations receive full backpropagation.
- The KVs produced by iteration `$m - b$` serve as the converged approximation of what would be produced after `$n$` iterations.

**The default is `$m = 7$` and `$b = 2$`**, meaning the model runs 7 total iterations: 5 forward-only to converge KVs, followed by 2 with backpropagation. The authors verify this choice empirically (Figure 9, top) by training a 50M model with different values of `$m$`: perplexity stabilizes at `$m \geq 6$` for the `$w = 2$` configuration and at `$m \geq 4$` for `$w = 0$` (no warmup layers converge faster in the trained model, counterintuitively, likely because the model learns to make the shared top-layer KVs especially informative).

**Why KVs converge quickly:** This is not merely an empirical convenience—it has a structural explanation. The iterative process is essentially running a fixed-point iteration: each pass refines the top-layer KVs based on the previous iteration's KVs, and the refinement operator is a deep transformer network. If this operator is contractive (as deep networks trained with residual connections and layer normalization tend to be), the iteration converges geometrically to a fixed point. The convergence rate depends on the spectral properties of the effective "KV transition operator," and warmup layers appear to improve the conditioning by providing stable intermediate representations that anchor the iteration. Figure 10 shows that a trained 1.1B model converges even faster than the random initialization in Figure 3—KVs stabilize after only 3–5 iterations for the trained model—which further supports the `$m = 7$` default as conservative.

---

##### Training Cost Tradeoff

The paper is transparent that the iterative training procedure increases pretraining time: **"pre-training our model costs about 3 times the time of pre-training TinyLlama with the same amount of data due to the iterative training process"** (Section 3.2). Specifically, training the 1.1B model on 100B tokens of SlimPajama takes 14 hours 43 minutes for TinyLlama versus 1 day 16 hours 44 minutes for LCKV with `$w = 2$` (2.77×) and 1 day 15 hours 52 minutes for LCKV with `$w = 10$` (2.71×). The approximately 3× factor comes from running `$m = 7$` iterations instead of 1 forward pass, plus the overhead of the iterative structure.

The authors argue this is acceptable because "in most scenarios, a speedup in inference is worth a slowdown in training which is a one-time process." They also note that initializing from a pretrained standard transformer checkpoint can substantially reduce training time (Appendix C.1): an LCKV model initialized from a TinyLlama checkpoint trained on 2.5T tokens and then fine-tuned on 100B tokens achieves perplexity of 8.514, outperforming both the randomly-initialized LCKV model (9.746) and a TinyLlama checkpoint trained on 500B tokens (9.046). This initialization pathway partially mitigates the training cost penalty.

---

#### Inference With Prompts: Encoding Through Iterative Refinement

At inference time, the model operates in standard autoregressive left-to-right fashion for generation, but handling the input prompt requires special treatment. A standard transformer can encode the entire prompt in parallel in a single forward pass because each prompt token's computation depends only on previous prompt tokens through causal masking—all dependencies are within the same forward pass.

The layer-condensed model cannot do this because each token's attention computation at lower layers requires the top-layer KVs of previous tokens, which aren't available until those previous tokens have been fully processed. The paper's solution is to **apply the same iterative refinement procedure used in training to encode the prompt**: run `$m + b$` iterations of parallel computation over all prompt tokens, starting with dummy zero KVs and refining with each iteration.

**The default is `$m + b = 7 + 2 = 9$` iterations** for prompt encoding. This matches the training configuration and ensures the prompt KVs are converged to the same quality as the KVs used during training. The authors note that "typically, `$m + b$` is far less than the number of tokens to generate, and thus the extra time spent in encoding the prompts is negligible" (Section 2.3). This is true for generation-heavy tasks (chat, story generation, code completion) where the generation length dominates the prompt length, but becomes a concern for prompt-heavy tasks (document summarization, long-context QA). The paper explicitly acknowledges this limitation: "Since our method requires iteratively processing the prompts, the throughput degrades when the prompts are much longer than the generation length" (Limitations section).

The authors also investigate whether fewer iterations can be used during inference (Appendix C.4, Figure 12). Reducing from 9 iterations to 2–4 iterations causes a measurable but moderate perplexity increase, with `$w = 10$` being more robust to iteration reduction than `$w = 2$` (because the warmup layers with standard attention provide stability). Increasing iterations beyond 9 does not noticeably improve performance. This means deployment can trade off prompt encoding speed against quality by adjusting the number of encoding iterations.

**For autoregressive generation** after the prompt is encoded, the model operates normally: one token at a time, left to right. Each new token requires one forward pass through all layers. During generation, the attention pattern uses the converged prompt KVs (from the iterative encoding) plus the KVs of all previously generated tokens. The new token's own KV is added to the shared KV cache (only for the top layer and warmup layers). The generation process does not require additional iterations because each new token only needs to attend to *already-known* KVs—there is no cyclic dependency for tokens that haven't been computed yet.

---

#### Integration With Sequence-Length Compression (StreamingLLM)

The paper demonstrates composability with StreamingLLM (Xiao et al., 2024), which is an attention sink method that retains only the KVs of:
- The first `$k_{\text{sink}}$` tokens (typically 4), which serve as "attention sinks" that absorb large attention weights and prevent the softmax from collapsing.
- The most recent `$k_{\text{recent}}$` tokens.
- All intermediate tokens are discarded from the KV cache.

When LCKV and StreamingLLM are combined:
- **LCKV reduces which *layers* produce KVs** (from `$L$` to `$w$`).
- **StreamingLLM reduces how many *positions* per layer are cached** (from `$n$` to `$k_{\text{sink}} + k_{\text{recent}}$`).
- **The total KV cache size becomes `$w \times (k_{\text{sink}} + k_{\text{recent}}) \times d_{\text{kv}}$`** instead of `$L \times n \times d_{\text{kv}}$` for the standard transformer or `$L \times (k_{\text{sink}} + k_{\text{recent}}) \times d_{\text{kv}}$` for StreamingLLM alone.

The experiments in Section 3.3 (Figures 5–7) verify that the combination works: the integrated model achieves lower latency and memory consumption than StreamingLLM alone at all cache sizes tested (Figure 5); it achieves better perplexity at equivalent cache sizes (Figure 6); and it maintains stable perplexity on 4-million-token inputs (Figure 7), preserving StreamingLLM's infinite-length capability.

---

#### Summary of Hyperparameters, Design Choices, and Their Justifications

**Model architecture choices:**
- **Top-layer KV sharing (not middle-layer or bottom-layer):** Justified by the iterative refinement view—the top layer produces the most informative representations. Using bottom-layer KVs would defeat the purpose since those representations are the least refined.
- **Diagonal attention masking (not cyclic resolution):** Simpler than attempting to resolve the cycle through special initialization or iterative solvers. Empirically verified not to harm performance because residual connections provide an alternative information pathway for self-representation.
- **Sandwich warmup configuration:** Empirically outperforms all-bottom or all-top configurations because it preserves both syntactic (bottom) and semantic (top) layer specialization. The split is symmetric (`$w/2$` at each end) for simplicity; the authors do not explore asymmetric splits.
- **`$w = 2$` for high-throughput, `$w = 10$` for quality-preserving:** These are the two operational points the paper evaluates most thoroughly. The choice depends on the application's accuracy-throughput tradeoff.

**Training procedure choices:**
- **`$m = 7$` iterations:** Empirically determined as the point of diminishing returns for KV convergence (Figure 9). Larger `$m$` does not improve perplexity but linearly increases training time.
- **`$b = 2$` backpropagation iterations:** Minimum that allows gradient flow to KV projection parameters. Larger `$b$` can cause training instability rather than improvement (Table 8, Figure 11).
- **Gradient stopping at `$m - b$` boundary:** Standard technique from Transformer-XL, adapted here to the iterative computation graph. The alternative—full backpropagation through all `$m$` iterations—would be memory-prohibitive.
- **No KV loss (auxiliary MSE on KV convergence):** Tested in Appendix C.3 (Table 9) but found to help only for small models (`$w = 0$`) and small datasets; for large models or large `$w$`, it hurts performance, likely because it forces convergence on immature KVs early in training and interferes with the natural optimization trajectory.

**Inference choices:**
- **`$m + b = 9$` prompt encoding iterations:** Matches training configuration. Fewer iterations may be used to trade quality for encoding speed (Figure 12).
- **Autoregressive generation unchanged:** After prompt encoding, generation proceeds normally with no additional iterations, since dependencies are strictly backward-looking.
- **Pretrained checkpoint initialization (optional):** Substantially reduces training time when available, by starting from converged representations that already produce reasonable top-layer KVs (Appendix C.1).

**Why the training procedure is correct despite the approximations:** The key theoretical guarantee is Theorem 1 (Appendix A), which proves that the parallel iterative graph is *exactly equivalent* to the sequential graph when run for `$n$` iterations. The two approximations—forward truncation (using `$m$` iterations instead of `$n$`) and gradient stopping (backpropagating through only `$b$` iterations)—introduce error, but this error is controlled by the empirical observation of fast KV convergence. If KVs have converged after `$m$` iterations, then running more iterations would not change them, and the truncated computation produces the same KVs as the full computation would. The gradient stopping approximation is justified by the same convergence: since the first `$m-b$` iterations primarily serve to converge KVs (not to compute new information), their contribution to the gradient is dominated by noise rather than signal for the downstream loss.

**What would happen without these approximations:** Training with `$n = 2048$` iterations would be approximately `$2048/7 \approx 290\times$` slower than the `$m = 7$` approximation, making the method completely impractical. The paper's primary algorithmic contribution is not the architecture itself but the demonstration that these aggressive truncations are both *necessary* and *empirically safe*—a finding that could not have been predicted from theory alone and required the convergence experiments in Figures 3, 9, and 10 to establish.

## 4. Key Insights and Innovations

### Innovation 1: Identifying Layer Count as an Independent, Unused Axis for KV Cache Compression

Before this paper, every method for reducing the KV cache memory footprint operated on a single axis: **the sequence length** — which token positions get to keep their KVs in the cache. Prompt compression, token pruning, eviction policies, and attention sink methods all ask variants of the same question: "given `n` tokens across `L` layers, how can we keep fewer than `n` of them?" The total KV cache size was treated as `L × n_reduced × d_kv`, and progress was measured by how small `n_reduced` could be made without unacceptable accuracy loss.

This paper makes a conceptual move that is obvious in retrospect but was entirely absent from the prior literature: **the multiplicative factor `L` — the number of layers that produce KVs — is not a constant of nature. It is a design choice.** By asking "do all `L` layers need to compute and store their own KVs?" rather than "which `n` tokens should we keep?", the authors open a second, completely independent axis for compression. The total KV cache size becomes `w × n_reduced × d_kv` where `w` is the number of layers that still compute standard KVs, and `w` can be as small as 0 or 2.

This is a fundamental reframing, not an incremental improvement. The significance lies in the multiplicative interaction: if sequence-length compression reduces the cache by a factor of `k` and layer-count reduction reduces it by a factor of `L/w`, the combined reduction is `(L/w) × k`, not `k + (L/w)`. The paper's integration experiment with StreamingLLM (Section 3.3, Figures 5–7) directly demonstrates this composability, and the fact that the combination works without interference — lower latency, lower memory, better perplexity than streaming alone at equivalent cache sizes (Figure 6) — validates that these are genuinely orthogonal dimensions. The field's prior implicit assumption that "every layer needs its own KV cache" turns out to have been an architectural default, not a necessity, and challenging that default is the paper's most distinctive conceptual contribution.

---

### Innovation 2: Recasting the Cyclic Dependency as a Convergence Problem, Then Solving It With Empirical Truncation

The layer-condensed attention mechanism creates an immediate algorithmic deadlock: a token's lower-layer attention computation requires its own top-layer KV, but the top-layer KV cannot be computed until lower layers finish. In a standard decoder with causal masking, dependencies flow strictly forward in sequence position and upward in layers — there are no cycles. The layer-condensed variant introduces a backward dependency from lower layers to the (future) top layer of the same token, closing a cycle that naive computation cannot resolve.

Prior work that touched similar ideas — specifically Feedback Transformers (Fan et al., 2020), which aggregate representations from all layers into shared KVs — sidestepped this by embracing full sequential computation over tokens, making training impractically slow for large models. The paper does not attempt to "solve" the cycle analytically (e.g., through fixed-point iteration with theoretical convergence guarantees). Instead, it makes a far more practical move: **recast the cycle as an iterative refinement process that empirically converges very fast, then truncate the iteration aggressively based on measured convergence rates.**

This is a diagnostic innovation as much as a methodological one. The key empirical finding — that top-layer KVs converge to their final values in 3–15 iterations rather than the `n` iterations suggested by the theory (Figures 3, 9, 10) — is the linchpin that makes the entire approach practical. Without it, training would require `n = 2048` iterations, making the method about 290× slower than the `m = 7` default. But the convergence observation itself only becomes actionable because the authors develop the parallel iterative computation graph (Figure 2b) and prove its equivalence to the sequential graph (Theorem 1, Appendix A). This equivalence is what allows them to *measure* convergence: without it, there would be no well-defined "final KV" to converge toward in the parallel setting, and no way to know whether truncation is safe.

The truncation strategy — `m = 7` total iterations with `b = 2` receiving gradients — is an engineering solution, but the conceptual move is deeper: **treating the cyclic dependency not as a correctness barrier to be eliminated, but as a convergence process to be approximated.** This is analogous to how truncated backpropagation through time (TBPTT) made RNN training practical — not by solving the vanishing gradient problem, but by observing that long-term dependencies often don't matter enough to justify full backpropagation. Here, the observation is that KV iteration converges quickly, so full iteration doesn't justify the compute. The fact that `b ≥ 2` is necessary (to allow gradients to flow to the KV projection parameters) but `b > 2` can hurt stability (Table 8, Figure 11) is a non-obvious empirical finding that would be difficult to predict from first principles.

---

### Innovation 3: The Sandwich Configuration as a Mechanism for Preserving Depth-Dependent Representation Specialization

The extreme version of layer-condensed attention (`w = 0`, where every layer attends to the single top layer's KVs) produces a measurable accuracy degradation. The paper's diagnosis, drawing on the interpretability literature (Clark et al., 2019b), is that **different layers of a transformer specialize in different types of information** — lower layers capture syntactic patterns, higher layers capture semantic patterns — and forcing all layers to attend to the same top-layer KVs eliminates this depth-dependent specialization.

The solution — retaining standard self-attention for a small number of layers split equally between the bottom and top of the network (the "sandwich configuration") — seems straightforward, but the paper provides evidence that the **split placement matters fundamentally**. The ablation in Table 4 is striking: with `w = 2` on a 50M model, all-bottom warmup achieves log dev perplexity of 14.556, all-top warmup collapses to 221.850 (essentially random performance), and the sandwich achieves 14.069 — the best of the three and substantially better than the worst. The catastrophic failure of all-top warmup is the diagnostic signal: it suggests that bottom-layer syntactic processing is critically dependent on layer-specific KV representations, and that attending to top-layer KVs at the bottom of the network destroys the model's ability to process local linguistic structure. The fact that all-bottom warmup works reasonably well (14.556 vs. 14.069 for sandwich) suggests that top-layer semantic processing is more robust to using generic KVs, presumably because semantic representations are less position-sensitive and more abstract.

This is more than a hyperparameter tuning result. It provides **architectural evidence for the functional specialization hypothesis** that had previously been supported only by probing and attention-pattern analysis. If layers were interchangeable — if depth was just about iterative refinement without qualitative specialization — then warmup layer placement wouldn't matter, and certainly wouldn't produce a 15× difference between all-top and sandwich configurations. The sandwich configuration works because it preserves each type of specialization where it's most needed: syntactic processing at the bottom, semantic processing at the top, and the middle layers can operate on shared high-level representations without losing critical local information.

The non-monotonic performance trend with `w` (Figure 8) — where intermediate `w` values can outperform both `w = 0` and the full standard transformer — is an additional puzzle. The authors don't explain it mechanistically, but it hints that the layer-condensed attention pattern may act as a regularizer: forcing middle layers to attend to top-layer KVs may prevent them from overfitting to layer-specific features and encourage learning representations that are more transferable or abstract. This is speculative but consistent with the observation that `w = 10` achieves slightly *better* average downstream accuracy (46.84) than TinyLlama (46.65) in Table 2.

---

### Innovation 4: Demonstrating That Inference Efficiency Gains Can Come From Structural Redundancy Removal, Not Just Approximation

Nearly all prior work on efficient transformer inference falls into one of two categories: **approximation methods** that sacrifice some fidelity for speed (quantization, pruning, sparse attention, token dropping) or **systems optimizations** that improve hardware utilization without changing the computation (kernel fusion, memory management, paged attention). Both categories accept the standard transformer architecture as given and work around its inefficiencies.

This paper belongs to a third, rarer category: **structural redundancy removal** — identifying that a component of the standard architecture performs computation whose output is largely redundant with something already computed elsewhere, and eliminating it. The claim is not that per-layer KVs are approximated or compressed; the claim is that they are *unnecessary* because the top layer's KVs — which must be computed anyway — contain sufficiently rich information to serve all layers' attention needs.

The evidence for genuine redundancy (rather than lossy approximation) is the `w = 10` result: a model where 12 out of 22 layers do not compute their own KVs achieves **better** downstream accuracy (46.84 vs. 46.65 averaged across 7 commonsense reasoning tasks, Table 2) and comparable perplexity (9.265 vs. 9.219, Table 3) compared to the standard TinyLlama baseline. If per-layer KVs carried unique, non-redundant information, eliminating them should produce a measurable accuracy cost that cannot be recovered by adding warmup layers — warmup layers preserve standard attention, but they don't replace the missing per-layer KVs in the condensed layers. The fact that the condensed layers function at all — let alone match or exceed baseline performance — is evidence that the information in intermediate-layer KVs is largely redundant with what can be derived from top-layer KVs through the query-key attention mechanism.

This reframes the memory bottleneck as partly a **design inefficiency** rather than an inherent computational requirement. The standard architecture computes `L` separate KV caches because each layer's attention is defined as self-attention, not because each layer's KVs encode information that is genuinely distinct and necessary. The paper demonstrates that most of this computation is wasted from an information-theoretic perspective — a finding with implications beyond this specific method, suggesting that future transformer architectures might be designed from the start with shared KV representations rather than treating them as per-layer by default.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The primary language modeling evaluation uses a 10M-token subset of the **SlimPajama development set** (Soboleva et al., 2023) for perplexity measurement. Downstream task evaluation uses the **lm-eval-harness framework** (Gao et al., 2023) to test zero-shot accuracy on seven commonsense reasoning benchmarks: HellaSwag (Zellers et al., 2019), OpenBookQA (Mihaylov et al., 2018), WinoGrande (Sakaguchi et al., 2021), ARC-Easy and ARC-Challenge (Clark et al., 2018), BoolQ (Clark et al., 2019a), and PIQA (Bisk et al., 2020). The long-context experiment (Section 3.3) uses the **PG19 dataset** (Rae et al., 2020) with inputs up to 4 million tokens. Pre-training uses a 100B-token subset of **SlimPajama**. Analyses in Section 4 use WikiText-103 (Merity et al., 2017) and MiniPile (Kaddour, 2023) for smaller-scale experiments.

- **Base model(s).** The paper tests **Llama-family models** (Touvron et al., 2023) at four scales: 50M parameters (8 layers, hidden size 512), 1.1B parameters (22 layers, hidden size 2048, following the TinyLlama configuration from Zhang et al., 2024), 7B parameters (32 layers, hidden size 4096), and 30B parameters (60 layers, hidden size 6656). The 1.1B and 50M models are pre-trained from scratch; the 7B and 30B models are used for throughput benchmarking only. The models are chosen to span the range from small research-scale models to production-scale LLMs, with the 1.1B TinyLlama serving as the primary accuracy-efficiency comparison point because it represents a well-documented open-source baseline with published training recipes and downstream task performance.

- **Metrics.** Throughput experiments measure **maximum batch size** (the largest number of concurrent sequences that fit in GPU memory without out-of-memory errors) and **tokens per second**, calculated as `(batch_size × generation_length) / total_latency_seconds` in an end-to-end fashion following FlexGen (Sheng et al., 2023). Latency is defined as total wall-clock time for prompt processing plus autoregressive generation of all sequences. Language modeling quality is measured by **perplexity** on held-out text. Downstream task quality is measured by **zero-shot accuracy** using lm-eval-harness. For the iteration-convergence analysis, the paper uses **mean squared error (MSE)** between KV values at consecutive iterations.

- **Baselines.** The throughput experiments compare against **standard Llama/TinyLlama transformers** with identical model configurations (same layer count, hidden size, attention heads) but with standard per-layer KV computation and caching. The accuracy experiments compare against **TinyLlama** (Zhang et al., 2024), a 1.1B-parameter Llama model pre-trained on the same SlimPajama data using the same hyperparameters. For the integration experiment (Section 3.3), the baseline is **StreamingLLM** (Xiao et al., 2024) applied to the standard TinyLlama model, using 4 initial attention sink tokens plus a variable number of recent tokens as the cache. No other KV cache compression methods are quantitatively compared, although the paper discusses several in the related work (H2O, Scissorhands, LM-Infinite, various prompt compression methods).

- **Generation budget / compute accounting.** Throughput experiments use sequence length configurations specified as "prompt_length + generation_length" (e.g., "5+2043" means 5 prompt tokens and 2043 generated tokens). Maximum batch size is determined by binary search: the largest batch that does not trigger an out-of-memory error on the target GPU. All throughput benchmarks use FlashAttention 2 (Dao, 2023), fused RMS norm, fused cross-entropy, and fused SwiGLU kernels for both the baseline and LCKV models, ensuring fair comparison. Training compute is measured in wall-clock time for a fixed data budget (100B tokens of SlimPajama). For accuracy experiments, the inference budget is measured in total forward passes: the LCKV model requires `m + b = 9` iterations for prompt encoding plus one pass per generated token, while the standard transformer requires one pass for prompt encoding plus one pass per generated token.

- **Cross-validation / statistical protocol.** No cross-validation or statistical significance testing is reported. The downstream evaluation uses the standard lm-eval-harness zero-shot protocol, which is deterministic given fixed model weights. Perplexity is computed on a single 10M-token subset of the SlimPajama development set. All throughput numbers are reported as single measurements for a given GPU and sequence length configuration, without error bars or multiple runs. The iteration-convergence MSE curves (Figures 3, 9, 10) are collected on single input sequences (2048 or 1024 randomly selected tokens), not averaged across multiple sequences. This absence of statistical rigor is a limitation, particularly for the downstream task results where accuracy differences between LCKV with `w = 10` (46.84) and TinyLlama (46.65) are small enough (0.19 percentage points average across 7 tasks) that they could plausibly fall within run-to-run variance from different random seeds or data orders.

---

### Main Quantitative Results

#### Throughput and Batch Size Scaling (Section 3.1, Table 1, Figure 4)

The headline result is that **LCKV achieves up to 26× higher throughput and up to 32× larger maximum batch sizes** compared to standard transformers, with the magnitude of improvement depending on model size, GPU type, and sequence length configuration.

**On an RTX 3090 (24GB) with a 1.1B model** (TinyLlama configuration, 22 layers) at prompt length 5 and generation length 2043:
- Standard TinyLlama maximum batch size: 239
- LCKV with `w = 2`: maximum batch size 1,150 (4.8× larger), throughput 10,033 tokens/s vs. 5,143 tokens/s (2.0× higher)
- LCKV with `w = 10`: maximum batch size 289 (1.2× larger), throughput 7,240 tokens/s (1.4× higher)

At the longer prompt-plus-generation configuration (5+8187 tokens), the batch size improvements are even more dramatic: 48 for standard vs. 384 for `w = 2` (8×) and 119 for `w = 10` (2.5×). The throughput improvement also widens: 4,113 vs. 1,425 tokens/s (2.9×) for `w = 2`.

**On an RTX 3090 with a 7B model** (32 layers), the absolute batch sizes are small because the model pushes against the 24GB memory limit, but the relative improvements are larger:
- At 5+8187: 1 for standard vs. 12 for `w = 2` (12×), 151.9 vs. 32.0 tokens/s (4.7×)
- At 2048+2048: 2 for standard vs. 23 for `w = 2` (11.5×), 171.7 vs. 57.0 tokens/s (3.0×)
- At 5+2043: 5 for standard vs. 64 for `w = 2` (12.8×), 534.0 vs. 140.9 tokens/s (3.8×)
- At 512+512: 9 for standard vs. 95 for `w = 2` (10.6×), but throughput only 378.9 vs. 225.3 tokens/s (1.7×) — the batch size increase is large but the throughput gain diminishes because at smaller sequence lengths, the KV cache is less dominant in total memory.

**On an RTX 3090 with a 30B model** using CPU offloading (512 prompt + 1024 generation), the batch size goes from 4 to 83 for `w = 2` (20.8×) and throughput from 0.23 to 5.99 tokens/s (26.0×). The 26× figure is the paper's headline maximum throughput improvement, but it comes in a CPU-offloading scenario where absolute throughput is already very low (5.99 tokens/s is still far below interactive speeds), which somewhat tempers its practical significance.

**On an A100 (80GB) with a 7B model** (2048+2048), the batch size increases from 15 to 128 for `w = 2` (8.5×), and throughput from 141.1 to 421.0 tokens/s (3.0×). For the 30B model on A100 (2048+2048), batch size increases from 1 to 32 (32× — this is the headline maximum batch size improvement), and throughput from 14.1 to 108.3 tokens/s (7.7×).

**A critical nuance about throughput (Figure 4, Appendix C.6):** The increased throughput is **not solely due to increased batch size**. Figure 4 shows that for a 7B model on A100 with 2048+2048 sequences, LCKV achieves higher throughput than the standard transformer even when both are run at the same batch size. For example, at batch size 8, LCKV achieves approximately 250 tokens/s vs. approximately 170 tokens/s for the standard transformer — a ~1.5× improvement at identical batch size. This means the throughput gains come from two sources: (1) the ability to use larger batch sizes because less GPU memory is consumed by the KV cache, and (2) faster per-token computation because fewer KV projections are computed and less memory bandwidth is consumed by cache accesses. Appendix C.6 reports that at the same batch size of 15 for 7B on A100 (2048+2048), the standard Llama takes 217.71 seconds for 15 sequences of 2048+2048 tokens (141.1 tokens/s), while LCKV with `w = 2` takes 89.15 seconds for 16 sequences (367.6 tokens/s) — a 2.6× latency reduction at comparable batch size.

The throughput also exhibits a saturation effect: Figure 4 shows that beyond batch size 32 for the 7B A100 configuration, throughput stops increasing for both the standard and LCKV models, suggesting the computation transitions from memory-bound to compute-bound (Dao et al., 2022). At that point, further batch size increases from additional memory savings would not improve throughput.

| HellaSwag | 44.58 | 42.22 (−2.36) | 44.74 (+0.16) |
| OpenBookQA | 30.20 | 30.60 (+0.40) | 31.00 (+0.80) |
| WinoGrande | 50.99 | 49.64 (−1.35) | 51.70 (+0.71) |
| ARC-Challenge | 25.00 | 24.74 (−0.26) | 24.83 (−0.17) |
| ARC-Easy | 46.38 | 43.10 (−3.28) | 46.38 (±0.00) |
| BoolQ | 60.46 | 61.38 (+0.92) | 61.38 (+0.92) |
| PIQA | 68.93 | 66.49 (−2.44) | 67.90 (−1.03) |
| **Average** | **46.65** | **45.45** (−1.20) | **46.84** (+0.19) |

The `w = 10` model achieves an average accuracy (46.84) that is **slightly higher** than the TinyLlama baseline (46.65), a non-obvious result given that 12 out of 22 layers do not compute their own KVs. The improvement is driven by HellaSwag (+0.16), OpenBookQA (+0.80), WinoGrande (+0.71), and BoolQ (+0.92), partially offset by small degradations on ARC-Challenge (−0.17) and PIQA (−1.03). The `w = 2` model shows larger degradation on HellaSwag (−2.36), ARC-Easy (−3.28), and PIQA (−2.44), with improvements on OpenBookQA (+0.40) and BoolQ (+0.92).

**How to interpret these numbers:** The accuracy differences for `w = 10` are small enough (maximum 1.03 percentage points on PIQA) that they fall within what might be expected from different random seeds or data order during pre-training. The paper's claim that `w = 10` achieves "almost no performance degradation" (Section 2.1) and "competitive performance" (Section 3.2) is supported by these results, though the "competitive" framing understates that `w = 10` actually achieves a marginally *higher* average — a finding the paper does not emphasize or explain mechanistically.

**Pre-training time cost:** Training TinyLlama on 100B tokens takes 14 hours 43 minutes. Training LCKV with `w = 2` takes 1 day 16 hours 44 minutes (2.77× longer), and `w = 10` takes 1 day 15 hours 52 minutes (2.71× longer). The authors note these times are from "before we optimize our codes" and could be further reduced, particularly for `w = 10` where more layers use standard attention.

#### Position-Dependent Perplexity (Appendix C.5, Figure 13)

To verify that the layer-condensed attention pattern does not cause degradation at longer context positions, the paper measures perplexity as a function of token position on the concatenated PG19 test set (context length 2048, the maximum the 1.1B models were trained on).

The results in Figure 13 show that:
- TinyLlama perplexity is approximately flat across positions 0–2000 (log PPL ~3.2–3.4).
- LCKV with `w = 2` shows slightly higher perplexity throughout (~3.4–3.6) but also flat across positions.
- LCKV with `w = 10` shows perplexity nearly identical to TinyLlama (~3.2–3.4) and flat across positions.

Neither LCKV variant exhibits the increasing-perplexity-with-position pattern that would indicate accumulating KV approximation errors over long contexts. This supports the claim that the iterative KV convergence procedure produces stable, position-independent KV quality.

### Integration with StreamingLLM (Section 3.3, Figures 5–7)

#### Latency and Memory Scaling (Figure 5)

The paper tests StreamingLLM applied to TinyLlama (1.1B) and StreamingLLM applied to LCKV with `w = 10`, varying the StreamingLLM cache size (number of recent tokens retained) from 256 to 4096.

**For TinyLlama (1.1B) + StreamingLLM:**
- Per-token latency grows from ~21.95 ms at cache size 256 to ~22.24 ms at cache size 4096 (essentially flat).
- Memory consumption grows from ~2.51 GiB at 256 to ~2.85 GiB at 4096.

**For LCKV (`w = 10`) + StreamingLLM:**
- Per-token latency grows from ~18.93 ms at cache size 256 to ~19.39 ms at cache size 4096 (flat and consistently ~3 ms lower than TinyLlama + StreamingLLM).
- Memory consumption grows from ~2.48 GiB at 256 to ~2.60 GiB at 4096 (consistently ~0.05–0.25 GiB lower).

**For 7B Llama** (same comparison, second row of Figure 5):
- Standard + StreamingLLM: latency 29.8–58.0 ms, memory 13.5–21.4 GiB across cache sizes 256–4096.
- LCKV (`w = 10`) + StreamingLLM: latency 25.3–43.8 ms, memory 11.8–22.9 GiB.

The LCKV integration consistently achieves lower latency and lower memory at all cache sizes, though the memory advantage narrows at large cache sizes (4096) where the KV cache dominates regardless of layer count. At cache size 4096, the 7B LCKV actually uses *more* memory than standard StreamingLLM (22.9 vs. 21.4 GiB), which the authors do not explain — possibly an artifact of different memory fragmentation patterns or implementation details.

#### Perplexity vs. Cache Size Tradeoff (Figure 6)

On the first text sample of PG19 (using 4 initial attention sink tokens):
- StreamingLLM alone: perplexity ranges from ~10.4 at cache size 2048 to ~11.2 at cache size 256.
- LCKV (`w = 10`) + StreamingLLM: perplexity ranges from ~10.4 at cache size 2048 to ~10.7 at cache size 256.

The LCKV-integrated version achieves **better perplexity at equivalent cache sizes**, with the gap widening as the cache size shrinks. At cache size 256, LCKV + StreamingLLM achieves perplexity ~10.7 versus ~11.2 for StreamingLLM alone — a 0.5 perplexity improvement. This is notable because LCKV is already reducing the number of layers that produce KVs, so each cached token position carries less total KV information. The fact that performance *improves* despite this suggests that the top-layer KVs (which StreamingLLM retains) are more informative per-token than the full set of per-layer KVs, possibly because they encode more abstract, semantically rich information that generalizes better when only a sparse subset of token positions is retained.

#### Infinite-Length Context (Figure 7)

The LCKV + StreamingLLM model is tested on 4 million concatenated tokens from the PG19 test set. The log perplexity starts at approximately 1.0 for short contexts, rises to approximately 3.5 by 1M tokens, and remains stable between 3.5–4.0 through 4M tokens. There is no upward drift that would indicate accumulating errors from the iterative approximation or from the streaming cache eviction, confirming that the combination preserves StreamingLLM's ability to handle arbitrarily long inputs.

### Convergence Speed of KVs (Section 4.3, Figures 3, 9, 10)

This analysis is central to justifying the `m = 7` training truncation, so it warrants quantitative detail.

**Randomly initialized 1.1B model (Figure 3):** With 2048 input tokens:
- `w = 0` (no warmup): MSE between consecutive iterations starts at ~3.0, drops to ~0.5 by iteration 10, and continues declining slowly to ~0.1 by iteration 30.
- `w = 2` (sandwich): MSE starts at ~2.5, drops to ~0.2 by iteration 10, and reaches ~0.05 by iteration 30.
- `w = 4` (sandwich): MSE starts at ~1.5, drops below 0.1 by iteration 7, and stays below 0.05 thereafter.

More warmup layers accelerate convergence because the standard-attention layers provide stable anchor KVs that don't change across iterations, reducing the dimensionality of the space that needs to converge.

**Trained 1.1B model with `w = 2` (Figure 10):** Tested with 2048 tokens. The MSE starts at ~0.5 (already much lower than the random model's initial MSE of ~2.5) and drops to ~0.1 by iteration 5 and below 0.05 by iteration 10. The trained model converges substantially faster than the random model — 5 iterations vs. 15–20 for equivalent MSE levels — because the trained model has learned to produce top-layer KVs that serve as effective fixed-point attractors for the iterative process.

**50M model trained with different `m` values (Figure 9, top):** Training with `m = 2, 3, 4, 6, 8, 10` iterations:
- `w = 0`: Log dev perplexity drops from ~4.0 at `m = 2` to ~3.1 at `m = 6`, then plateaus (~3.0–3.1 for `m ≥ 6`).
- `w = 2`: Log dev perplexity drops from ~4.0 at `m = 2` to ~2.9 at `m = 4`, then plateaus (~2.85–2.90 for `m ≥ 4`).

The `w = 2` model converges at lower `m` (4 vs. 6) because the warmup layers provide stable KVs that don't require iteration, reducing the effective dimensionality of convergence. This justifies `m = 7` as a conservative default that works for both configurations.

**50M trained model KV convergence (Figure 9, bottom):** The MSE plot for a trained 50M model with 1024 tokens shows convergence even faster than the 1.1B trained model: MSE drops below 0.1 by iteration 3–4 for the trained model, compared to 15–20 iterations for the random 50M model. This is consistent across model scales: trained models learn to make the iterative process converge rapidly.

### Ablation Studies and Robustness Checks

**Warmup layer placement (Section 4.1, Table 4):** On a 50M model with 8 layers and `w = 2`, the sandwich configuration (bottom 1 + top 1 warmup) achieves log dev perplexity of 14.069 on WikiText-103. The all-bottom configuration (warmup layers at layers 1–2) achieves 14.556. The all-top configuration (warmup layers at layers 7–8) achieves 221.850 — essentially random-level perplexity. On a 1.1B model with 22 layers and `w = 2`, the sandwich achieves 7.381, all-bottom achieves 7.668, and all-top achieves 9.098. The sandwich configuration is consistently optimal and the all-top configuration is consistently worst, with the gap being catastrophic for the smaller model (221.85 vs. 14.07, a 15.8× increase in perplexity) and less severe but still substantial for the larger model (9.098 vs. 7.381, a 23% relative increase). This provides strong evidence that bottom-layer syntactic processing is critically dependent on layer-specific KVs — when the lowest layers are forced to attend to top-layer KVs, the model essentially cannot process language at all at small scales, and is significantly impaired even at 1.1B parameters.

**Number of warmup layers `w` (Section 4.2, Figure 8):** On a 1.1B model (22 layers), `w` is swept from 0 to 22:
- `w = 0`: log dev perplexity ~2.85, the worst among all non-zero configurations.
- `w = 2`: log dev perplexity ~2.76, throughput ~10,000 tokens/s on RTX 3090 (5+2043).
- `w = 6`: log dev perplexity ~2.72, throughput ~8,500 tokens/s.
- `w = 10`: log dev perplexity ~2.70, throughput ~7,200 tokens/s.
- `w = 14`: log dev perplexity ~2.68, throughput ~6,500 tokens/s.
- `w = 16`: log dev perplexity ~2.69, throughput ~6,200 tokens/s.
- `w = 18`: log dev perplexity ~2.71, throughput ~5,800 tokens/s.
- `w = 22` (standard transformer): log dev perplexity ~2.70, throughput ~5,100 tokens/s.

The perplexity curve is non-monotonic: it improves from `w = 0` to `w = 14` (best point), then degrades slightly from `w = 14` to `w = 18`, then returns to baseline at `w = 22`. The throughput curve is monotonically decreasing with `w`. The optimal perplexity-efficiency tradeoff differs depending on the priority: `w = 2` for maximum throughput with acceptable quality loss, `w = 10–14` for near-baseline or better quality with substantial throughput gains. The non-monotonicity — where intermediate `w` values outperform the standard transformer — is not explained mechanistically but is a robust empirical finding.

**Backpropagation iterations `b` (Appendix C.2, Figure 11, Table 8):** On a 50M model with `m + b = 9` fixed:
- `w = 0`: log dev perplexity ~2.71 for `b = 2`, ~2.70 for `b = 3`, ~2.71 for `b = 4` (essentially flat).
- `w = 2`: ~2.70 for `b = 2`, ~2.69 for `b = 3`, ~2.72 for `b = 4` (small increase at `b = 4`).
- `w = 4`: ~2.69 for `b = 2`, ~2.69 for `b = 3`, ~2.74 for `b = 4` (noticeable increase at `b = 4`).

On a 1.1B model (Table 8): dev perplexity 10.390 for `b = 2`, 10.476 for `b = 3`, 10.885 for `b = 4`. Training time increases from 8 hours (`b = 2`) to 13 hours (`b = 4`). Larger `b` requires more GPU memory for backpropagation and leads to less stable training, likely because the longer gradient chain through unconverged KVs amplifies noise. The default `b = 2` is the minimum that still allows gradient flow to the KV projection parameters.

**KV loss auxiliary objective (Appendix C.3, Table 9):** Adding an MSE loss between KVs at consecutive iterations:
- 50M model, `w = 0` on WikiText-103: 15.610 with KV loss vs. 15.965 without — a 0.355 perplexity improvement.
- 50M model, `w = 2`: 15.065 with KV loss vs. 15.004 without — a 0.061 degradation.
- 1.1B model, `w = 2` on 100B SlimPajama: 10.073 with KV loss vs. 9.746 without — a 0.327 degradation.

The KV loss helps only for the smallest model without warmup layers, where KVs converge more slowly and an explicit convergence objective provides useful training signal. For larger models or models with warmup layers, the KV loss hurts performance, presumably because it imposes a convergence pressure that interferes with the natural optimization trajectory — early in training, forcing KVs to converge prematurely may lock in poor representations.

**Prompt encoding iterations (Appendix C.4, Figure 12):** Using the 1.1B models trained with `m = 7, b = 2` and varying the number of prompt encoding iterations from 2 to 12:
- `w = 2`: log dev perplexity ~5.0 at 2 iterations, drops to ~3.5 at 4 iterations, ~3.2 at 6 iterations, and stabilizes at ~3.1 for 8–12 iterations.
- `w = 10`: log dev perplexity ~3.8 at 2 iterations, drops to ~3.2 at 4 iterations, ~3.0 at 6 iterations, and stabilizes at ~2.9 for 8–12 iterations.

The `w = 10` model is more robust to reduced iterations (perplexity only rises ~0.9 from 9 iterations to 2 iterations, vs. ~1.9 for `w = 2`), consistent with the convergence analysis showing warmup layers accelerate KV stabilization. In deployment, one could use fewer iterations to trade prompt encoding speed for generation quality.

**Initialization from pre-trained checkpoints (Appendix C.1, Table 7):**
- TinyLlama baseline (trained on 100B tokens from scratch): dev perplexity 9.219, average downstream accuracy 46.65.
- LCKV `w = 2` (trained on 100B tokens from scratch): 9.746, 45.45.
- TinyLlama checkpoint at 500B tokens: 9.046, 48.28.
- TinyLlama checkpoint at 2.5T tokens: 7.822, 53.97.
- LCKV `w = 2` initialized from the 2.5T TinyLlama checkpoint, then trained on 100B tokens: 8.514, 49.55.

Initializing from a pre-trained standard transformer provides a substantial head start: the initialized LCKV model achieves better perplexity than the randomly-initialized LCKV model (8.514 vs. 9.746) and better downstream accuracy (49.55 vs. 45.45), despite only training for 100B additional tokens. It even outperforms the TinyLlama checkpoint at 500B tokens (8.514 vs. 9.046 perplexity, 49.55 vs. 48.28 accuracy), suggesting that the LCKV architecture can effectively leverage knowledge from standard transformer pre-training without needing to relearn from scratch. This partially mitigates the 3× training time penalty: if a pre-trained checkpoint is available, the additional training cost is only the fine-tuning on the target data budget, not the full pre-training cost.

**Training with larger `b` and KV convergence interaction (Appendix C.2, Figure 11):** The interaction between `b` and convergence is noted but not fully explained. The authors report that "for `b = 4` the KVs do not converge as fast as for `b = 2`." This is a significant observation: increasing the backpropagation depth actually *slows down* KV convergence. The likely mechanism is that with `b = 4`, the training signal for KV parameters comes from four iterations of refinement, creating a more complex optimization landscape where the model can exploit the multi-iteration pathway rather than learning to produce KVs that converge quickly. With `b = 2`, the model is forced to make KVs useful after just one iteration of refinement (since only the penultimate-to-final transition receives gradient), encouraging faster convergence as a byproduct of the training objective.

### Throughput Scaling With Batch Size (Figure 4, Appendix C.6)

For 7B Llama on A100 with 2048+2048 sequences, the throughput vs. batch size curve (Figure 4) shows:
- Standard Llama: 141.1 tokens/s at batch size 15 (max), with throughput increasing roughly linearly from batch sizes 2–15.
- LCKV: 421.0 tokens/s at batch size 32 (max for the range plotted), with the curve still increasing at batch size 32 but at a diminishing rate.
- At equivalent batch sizes, LCKV achieves higher throughput: at batch size 8, LCKV achieves ~250 tokens/s vs. ~100 tokens/s for standard Llama; at batch size 15, ~340 vs. ~140.

At batch size 128 (only achievable by LCKV due to memory savings), the throughput drops below the batch size 32 peak, indicating the computation becomes compute-bound. This means that the full memory savings of LCKV cannot be converted to throughput improvements for large-batch scenarios on this hardware — the compute units saturate before the memory capacity is exhausted. The paper acknowledges this: "when the batch size grows larger than 32, the throughput no longer increases and even decreases with a batch size of 128." This implies that the maximum practical throughput improvement from LCKV alone (without complementary compute optimizations) is the ~3× observed at the optimal batch size for the available compute, not the 8.5× batch size improvement.

### Critical Assessment

#### Does the paper demonstrate that the KV cache is reduced by collapsing the layer dimension? 

Yes, this is directly measured and strongly supported. The maximum batch size improvements in Table 1 are a direct proxy for KV cache memory reduction, since larger batch sizes are possible only because less GPU memory is consumed by the KV cache. The improvements are systematic across model scales (1.1B, 7B, 30B), GPU types (RTX 3090, A100), and sequence length configurations. The 32× maximum batch size increase (30B on A100, 2048+2048, `w = 2`) is the most dramatic demonstration, though this specific configuration starts from a baseline batch size of 1, making the multiplier artificially large.

However, the paper does not report **actual KV cache memory measurements** in bytes or as a fraction of total GPU memory. The batch size metric is an indirect proxy that conflates KV cache savings with other memory effects (parameter reduction from discarded `W_K` and `W_V` weights, potential differences in memory fragmentation). A direct measurement of KV cache memory consumption would have been more convincing and would allow readers to decompose the total memory savings into KV-cache-specific vs. parameter-specific components.

#### Does the paper demonstrate competitive performance on language modeling and downstream tasks?

Supported with important qualifications. The `w = 10` model achieves accuracy that is marginally better than TinyLlama on average (46.84 vs. 46.65 across 7 tasks, Table 2) and perplexity that is nearly identical (9.265 vs. 9.219, Table 3). This supports the claim that the method can recover baseline-level performance. However, the following qualifications are important:

- **The test is on a single training run with a single data budget (100B tokens).** There is no evidence that the results are stable across random seeds, data orders, or training durations. The accuracy differences between `w = 10` and TinyLlama are small enough (0.19 points average) that they could flip sign with different random initializations. The paper would be stronger with multiple training runs or at least a discussion of expected variance.

- **The training budget is modest.** 100B tokens is a small fraction of what state-of-the-art LLMs are trained on (TinyLlama itself is trained on 3T tokens for its final release). It is unknown whether the gap between `w = 10` and the standard transformer would widen, narrow, or remain stable with longer training. The authors partially address this with the initialization experiment (Table 7), showing that an LCKV model initialized from a 2.5T-token TinyLlama checkpoint outperforms a 500B-token TinyLlama, but they don't compare against a 2.5T-token TinyLlama (which would be the fair baseline for that initialization point).

- **The evaluation tasks are all commonsense reasoning.** There is no evaluation on knowledge-intensive tasks, code generation, mathematical reasoning, or long-form generation quality. It is possible that the layer-condensed attention pattern affects factual recall or multi-step reasoning differently than it affects commonsense inference, and these dimensions are unexplored.

- **The `w = 2` model does show a measurable degradation** — 1.20 points average accuracy loss and 0.527 perplexity increase. While this is framed as a tradeoff for higher throughput, the paper does not systematically characterize *which types* of tasks or examples are most affected by the reduced warmup count.

#### Does the paper demonstrate that the method composes orthogonally with sequence-length compression?

Partially supported. The StreamingLLM integration experiment (Section 3.3) demonstrates that the combination works and provides benefits beyond either method alone. Figures 5 and 6 show that LCKV + StreamingLLM achieves lower latency, lower memory, and better perplexity than StreamingLLM alone at equivalent cache sizes. Figure 7 shows that the combination preserves the long-context capability on 4M-token inputs.

However, this is tested with only one sequence-length compression method (StreamingLLM) and one model configuration (`w = 10`, 1.1B and 7B). The paper does not demonstrate integration with token eviction methods (H2O, Scissorhands), prompt compression methods (LLMLingua, Gist tokens), or other attention sink variants (LM-Infinite). The claim of orthogonality is conceptually sound — the two methods operate on independent dimensions of the KV cache — but the empirical evidence is limited to a single integration partner. A more thorough demonstration would show that the benefit of LCKV is multiplicative with the compression ratio of StreamingLLM (i.e., the relative improvement from LCKV is approximately constant regardless of the StreamingLLM cache size), which Figure 6 qualitatively suggests but does not quantify.

#### Does the paper demonstrate that the training method is practical?

With significant caveats. The 3× training time overhead is a genuine cost that the paper acknowledges. However, the following practical concerns are underexplored:

- **The `m = 7` default is justified for 1.1B models trained on 100B tokens, but the convergence analysis in Figure 3 is on a *randomly initialized* model.** The relationship between convergence speed at initialization and convergence speed after partial training is not characterized. If convergence slows mid-training (e.g., as the model's KV representations become more complex), the `m = 7` default might become insufficient, and the model might start underperforming relative to a fully-converged baseline. The paper's Figure 9 (top) partially addresses this for 50M models but not for the 1.1B scale.

- **The pre-training time comparison is against TinyLlama with identical hyperparameters, but LCKV uses a fundamentally different computation graph.** The paper does not explore whether LCKV could use a different learning rate schedule, batch size, or optimizer configuration that might reduce the training overhead. The 3× factor is measured with hyperparameters optimized for standard transformers, not for the iterative training procedure.

- **GPU memory usage during training is not reported.** The parallel iterative training requires storing activations for `m = 7` forward passes (with gradient stopping on 5 of them), which likely consumes more training memory than standard transformer training. If the method requires more GPUs or gradient accumulation to fit the same batch size during training, the effective training cost penalty could be larger than 3× when accounting for hardware requirements.

- **The initialization from pre-trained checkpoints (Appendix C.1) is promising but presented as a single data point.** The 2.5T → 100B transfer shows that LCKV can leverage existing pre-training, but the cost of the 2.5T pre-training is not amortized in the comparison. If a user needs to train a standard model to 2.5T tokens first and then fine-tune to LCKV, the total training cost is 2.5T tokens of standard training plus 100B tokens of LCKV training — far more than training LCKV from scratch on 100B tokens.

#### Does the paper identify the optimal operating point for the accuracy-efficiency tradeoff?

Partially. Figure 8 provides a clear visualization of the tradeoff curve, and the paper identifies two operating points (`w = 2` for high throughput, `w = 10` for quality preservation). However, the analysis is limited to a single model scale (1.1B). It is unknown whether the optimal `w` scales with model size — does a 7B model need proportionally more or fewer warmup layers than a 1.1B model? The throughput experiments in Table 1 test both `w = 2` and `w = 10` at 7B and 30B, but do not sweep `w` at those scales, so the optimal configuration for larger models remains unexplored.

#### Missing experiments that would strengthen the paper:

- **Direct KV cache memory measurement** in bytes, not just batch size as a proxy, to precisely quantify the memory savings.
- **Training curves** showing loss vs. tokens for LCKV vs. standard transformer, rather than just final perplexity, to assess whether LCKV learns at the same rate or requires more data to converge.
- **Scaling the data budget** beyond 100B tokens to see whether the gap between LCKV and standard transformers widens or narrows with more training.
- **Evaluation on non-commonsense tasks** (e.g., MMLU, HumanEval, GSM8K) to assess whether the layer-condensed attention affects factual knowledge, reasoning, or code generation differently than commonsense inference.
- **Multiple random seeds** for the 1.1B training runs to quantify the variance in the downstream accuracy measurements.
- **Ablation on the `m` vs. `b` tradeoff at the 1.1B scale**, not just at 50M, since the optimal truncation parameters may depend on model capacity.
- **Integration with at least one other KV cache compression method** (e.g., H2O) beyond StreamingLLM to substantiate the orthogonality claim.
- **Throughput-per-dollar or throughput-per-FLOP analysis** that accounts for the increased training cost, providing a holistic efficiency metric rather than inference-only throughput.

#### Summary of evidence quality:

The paper's strongest evidence is in the throughput and batch size measurements (Table 1, Figure 4), which are systematic across scales and configurations and demonstrate large, consistent improvements. The accuracy evidence (Tables 2 and 3) is adequate to show that `w = 10` approximately matches baseline performance, but is based on a single training run at modest scale with limited task diversity. The convergence analysis (Figures 3, 9, 10) provides convincing justification for the training truncation parameters at the scales tested. The integration experiment with StreamingLLM (Section 3.3) is a valuable proof-of-concept for composability but is limited in scope. The paper's central architectural claim — that per-layer KVs are largely redundant and can be replaced by top-layer KVs for most layers — is supported by the `w = 10` results but would be strengthened by experiments at larger scales and on more diverse tasks.

## 6. Limitations and Trade-offs

### The 3× Training Time Overhead Is a Genuine Deployment Barrier, Not Fully Offset by Inference Savings

**The assumption or constraint.** The iterative parallel training procedure requires `m = 7` forward passes per training step rather than a standard transformer's single forward pass, and backpropagation through `b = 2` of those iterations. The authors are transparent about the cost:

> "pre-training our model costs about 3 times the time of pre-training TinyLlama with the same amount of data due to the iterative training process" (Section 3.2).

Specifically, training the 1.1B model on 100B tokens of SlimPajama takes 14 hours 43 minutes for TinyLlama vs. 1 day 16 hours 44 minutes for LCKV with `w = 2` (2.77×) and 1 day 15 hours 52 minutes for `w = 10` (2.71×). The authors argue that "in most scenarios, a speedup in inference is worth a slowdown in training which is a one-time process."

**The consequence.** This framing as a "one-time" cost ignores several practical realities. First, the training cost is not merely time — it is GPU-hours, which translate directly to dollars, carbon emissions, and opportunity cost. A practitioner evaluating whether to adopt LCKV must amortize the 3× training cost premium against the inference savings over the model's deployed lifetime. For a model that will serve billions of inference requests, the inference savings dominate and the training premium is negligible. But for a model that will be trained many times (hyperparameter sweeps, architecture search, frequent retraining on updated data, or domain-specific fine-tuning), the 3× multiplier applies on every training run, and the cumulative cost may outweigh inference savings. The paper provides no breakeven analysis — at what inference volume does the training premium become worthwhile?

Second, the training procedure likely requires more GPU memory per training step than standard transformer training because it must store activations for `m = 7` iterations (even though only `b = 2` receive gradients, the forward activations for all 7 must be kept for the gradient-stopped iterations to serve as inputs to later iterations). This is not measured anywhere in the paper. If LCKV training requires more GPUs or more aggressive gradient accumulation to fit the same effective batch size, the hardware cost multiplier could exceed 3×. The training was done on 128 NVIDIA A800 GPUs (Section 3.2), but the paper does not report whether TinyLlama training required the same number of GPUs, leaving open the possibility that LCKV training has a higher hardware footprint.

**What evidence exists in the paper.** The training time measurements (Section 3.2, Appendix B) provide the raw numbers. The initialization-from-pretrained-checkpoint experiment (Appendix C.1, Table 7) partially mitigates the concern by showing that an LCKV model initialized from a 2.5T-token TinyLlama checkpoint and then trained on only 100B additional tokens achieves dev perplexity of 8.514, outperforming a randomly-initialized LCKV model (9.746) and a 500B-token TinyLlama checkpoint (9.046). However, this pathway still requires the pre-existence of a fully pre-trained standard transformer, which itself cost 2.5T tokens of training. The total training investment is the standard model's cost plus the LCKV fine-tuning cost — not cheaper than training LCKV from scratch, just shifted in time.

**Mitigation status.** The paper acknowledges the training cost as its first listed limitation ("Limitations" section) and suggests two mitigations: (1) initialization from pre-trained standard checkpoints, which "is empirically found to speed up the process" but whose total cost is not analyzed; (2) noting that the training times were recorded "before we optimize our codes" and could be reduced. Neither mitigation is quantified. The paper does not explore whether `m` could be reduced during later stages of training (when KVs converge faster, per Figure 10), whether a curriculum could start with smaller `m` and increase it, or whether different optimizer configurations could accelerate LCKV-specific training dynamics. The 3× figure is presented as a fixed cost without sensitivity analysis.

---

### Prompt-Heavy Workloads Incur a Latency Penalty That the Throughput-Centric Evaluation Obscures

**The assumption or constraint.** The method requires `m + b = 9` iterations of parallel computation over all prompt tokens before autoregressive generation can begin. The authors note:

> "typically, `m + b` is far less than the number of tokens to generate, and thus the extra time spent in encoding the prompts is negligible" (Section 2.3).

This assumption holds for generation-heavy tasks (chat, story generation, code completion) where hundreds or thousands of tokens are generated per prompt. It breaks down for prompt-heavy tasks where the prompt dominates the sequence length.

**The consequence.** For tasks like document summarization (long document → short summary), long-context question answering (retrieved passages → short answer), or few-shot prompting with many examples (long prompt → short completion), the 9× prompt encoding overhead becomes a significant fraction of total inference time — or even the dominant cost. If the prompt is 8,192 tokens and the generation is 256 tokens, the encoding cost is approximately `9 × 8192 × L` layer-computations vs. `1 × 256 × L` for generation plus `1 × 8192 × L` for a standard transformer's prompt encoding. This makes LCKV's prompt processing roughly 9× more expensive than the standard transformer's, potentially negating or reversing the throughput advantages claimed in Table 1 (which predominantly use short prompts of 5 or 512 tokens relative to generation lengths of 2043 or 2048 tokens).

The paper's throughput benchmarks in Table 1 all use configurations where prompt length is small relative to generation length: 5+8187, 5+2043, 2048+2048, 512+512, 512+1024. None of these test the regime where prompt length exceeds generation length by a large margin. The 5+8187 configuration has the most extreme generation-to-prompt ratio (1637:1), which is the precisely the regime where the paper's assumption holds best. The lack of benchmarks with prompt lengths of 4096, 8192, or longer relative to short generation lengths means the paper provides no evidence about performance in the prompt-dominated regime it acknowledges as a limitation.

**What evidence exists in the paper.** The paper explicitly flags this in its Limitations section:

> "Since our method requires iteratively processing the prompts, the throughput degrades when the prompts are much longer than the generation length, e.g., in document summarization. Generally, our method is more suitable for tasks with a large generation length, such as translation, dialogue, question answering, CoT problem solving, etc."

This is a candid acknowledgment, but it is qualitative only. No experiment measures the degradation or identifies the crossover point where the iterative encoding cost outweighs the per-token generation savings. Figure 12 (Appendix C.4) shows that prompt encoding iterations can be reduced from 9 to as few as 2–4 with moderate perplexity increase (e.g., for `w = 10`, log dev perplexity rises from ~2.9 at 9 iterations to ~3.0 at 6, ~3.2 at 4, ~3.8 at 2). This provides a partial mitigation pathway — trade encoding quality for speed — but does not characterize the latency-quality tradeoff in end-to-end throughput terms.

**Mitigation status.** The paper suggests reducing the number of iterations as the primary mitigation (Appendix C.4) and notes that the method is "more suitable for tasks with a large generation length." No architectural modifications to reduce prompt encoding cost are proposed (e.g., caching and reusing converged KVs across similar prompts, hybrid encoding where only a subset of prompt tokens are iteratively refined, or using standard attention for prompt encoding and switching to layer-condensed attention only during generation). The limitation is acknowledged but untreated as a research problem.

### Difficulty Estimation Cost Is Unaccounted For, Making the Headline Efficiency Gains an Upper Bound

**The assumption or constraint.** The paper implicitly assumes that the cost of the iterative prompt encoding is the only inference-time overhead beyond standard autoregressive generation. But the 9× prompt encoding overhead (relative to standard transformers' single-pass encoding) is categorically different from the per-generation-token costs and is not amortized in any of the headline throughput numbers.

**The consequence.** The throughput numbers in Table 1 and the 26× improvement claim must be interpreted carefully. For the 5+2043 configuration on RTX 3090 with `w = 2`, the 1.1B model achieves 10,033 tokens/s (2.0× the standard transformer's 5,143 tokens/s). But this configuration has only 5 prompt tokens, so the iterative encoding cost is `9 × 5 × L` vs. `1 × 5 × L` for the standard transformer — a negligible absolute difference. For a configuration like 4096+256 (long document summarization), the prompt encoding cost would be `9 × 4096 × L` vs. `1 × 4096 × L`, and the 8× encoding overhead on the long prompt could easily consume the savings from faster per-token generation on the short output. The 26× headline number comes from the 30B model with 512+1024 under CPU offloading — a configuration where prompt encoding is 33% of the total sequence length and the iterative overhead is moderate. The paper provides no throughput measurements for prompt-dominated configurations, so the headline efficiency claims are only validated in the generation-heavy regime.

The parallel with the reference example's observation about prompt difficulty estimation cost is instructive: just as the compute-optimal scaling paper's $4 \times$ efficiency gain did not account for the 2048 samples used to estimate difficulty, this paper's throughput gains do not account for the iterative prompt encoding cost in prompt-heavy regimes. In both cases, the headline numbers represent an upper bound on realized efficiency that may not be achievable in all deployment scenarios.

**What evidence exists in the paper.** Table 1 provides the raw numbers for specific prompt-generation length configurations. Section 2.3 and the Limitations section qualitatively acknowledge the prompt-length sensitivity. Figure 12 provides perplexity-vs-iterations data that could inform a tradeoff analysis but is not translated into throughput terms. The paper does not provide a parametric model of throughput as a function of prompt length, generation length, number of warmup layers, and number of iterations, which would allow practitioners to compute the crossover point for their specific workload.

**Mitigation status.** The paper offers two partial mitigations: (1) reduce the number of encoding iterations, trading quality for speed (Figure 12), and (2) restrict use to generation-heavy tasks (Limitations section). Neither is a solution; both are workarounds that limit the method's applicability. The method fundamentally pays a multiplicative cost on prompt encoding to achieve savings on generation, and this tradeoff is inherent to the architecture — it cannot be eliminated without a different mechanism for prompt processing (such as the standard transformer's single-pass encoding).

### Evaluation Is Confined to a Single Model Family, a Single Training Budget, and Commonsense Reasoning Tasks — Generalization Across Architectures, Scales, and Task Types Is Unverified

**The assumption or constraint.** All accuracy experiments use Llama-family models (50M, 1.1B) pre-trained on SlimPajama with a single training budget (100B tokens). All throughput experiments use Llama architectures at 1.1B, 7B, and 30B. The downstream evaluation covers seven commonsense reasoning tasks only. The paper does not test on non-Llama architectures (e.g., MPT, Falcon, Gemma), on models with different attention mechanisms (e.g., grouped-query attention, multi-query attention), on knowledge-intensive benchmarks (MMLU, TriviaQA), on reasoning benchmarks (GSM8K, MATH), on code generation (HumanEval, MBPP), or on long-form generation quality.

**The consequence.** Several aspects of the method's design could interact differently with different architectural choices:

- **Grouped-query attention (GQA) and multi-query attention (MQA):** The 1.1B TinyLlama uses 32 attention heads but only 4 KV heads (Table 5), which already reduces the KV cache by sharing KVs across query heads within each layer. LCKV reduces the KV cache further by sharing KVs across layers. The interaction between these two forms of sharing — within-layer head sharing via GQA and cross-layer KV sharing via LCKV — is untested. A model using MQA (1 KV head) might see less relative benefit from LCKV because the per-layer KV cache is already small.

- **Model scale:** The accuracy experiments are at 1.1B parameters, a scale where the 100B-token training budget is a small fraction of Chinchilla-optimal. It is unknown whether LCKV's accuracy parity with standard transformers would hold at 7B, 13B, or 70B parameters with proportionally larger training budgets. The non-monotonic perplexity curve in Figure 8 — where intermediate `w` values outperform the standard transformer — is observed only at 1.1B and may not replicate at larger scales where the baseline model's representations are more robust.

- **Task types:** Commonsense reasoning relies on different capabilities than factual knowledge retrieval or multi-step mathematical reasoning. The layer-condensed attention pattern could affect these differently. For example, factual knowledge might be stored in MLP layers and be relatively unaffected by KV sharing, while multi-step reasoning might depend more heavily on the quality of attention-based information routing across layers. The paper provides no evidence either way.

The paper states that it "believe[s] this model is representative of the capabilities of many contemporary LLMs" (Section 4), but this is an assertion, not an empirical finding. The generalization of the method beyond Llama on SlimPajama at 1.1B/100B-tokens to other architectures, datasets, scales, and task families is entirely unverified.

**What evidence exists in the paper.** The throughput experiments span 1.1B, 7B, and 30B Llama models (Table 1), providing some evidence that the memory savings scale with model depth. The perplexity-vs-position analysis (Figure 13) shows that LCKV does not degrade with context length up to 2048 tokens. The StreamingLLM integration (Section 3.3) works at both 1.1B and 7B. These provide partial evidence of scaling behavior but are all within the Llama family and do not test accuracy scaling. The 50M-scale ablation experiments (Section 4) explore hyperparameters but at a scale too small to draw conclusions about larger models.

**Mitigation status.** The paper does not claim generalization beyond what it tests. The title and abstract refer to "large language models" generically, but the experiments are explicitly on "Llama" models (Section 3). The Limitations section does not mention this scope restriction, which is an omission — a reader encountering the paper's claims in isolation might reasonably assume the method transfers to any transformer LLM, when in fact it has been validated on exactly one architecture family on one data distribution with one task category.

### The Accuracy Evaluation Lacks Statistical Rigor — Single Training Runs With No Variance Estimates Make the Near-Baseline Claims Fragile

**The assumption or constraint.** All accuracy comparisons in Tables 2 and 3 are based on a single training run per configuration. The paper does not report confidence intervals, standard deviations across random seeds, or any other measure of statistical reliability. The average downstream accuracy difference between LCKV with `w = 10` (46.84) and TinyLlama (46.65) is 0.19 percentage points across 7 tasks, with per-task differences ranging from −1.03 (PIQA) to +0.92 (BoolQ).

**The consequence.** In the absence of variance estimates, it is impossible to determine whether the observed differences are statistically meaningful or within the range of run-to-run variation from different random seeds, data orders, or hardware nondeterminism. The paper's central accuracy claim — that `w = 10` achieves "almost no performance degradation" or "competitive performance" — rests on the assumption that a 0.19-point average improvement is evidence of parity. But if the standard deviation across training runs is, say, 0.5 points (not implausible for 1.1B models trained on 100B tokens with different seeds), then the observed difference is well within noise, and the correct conclusion is that the experiment cannot distinguish between the two models — which is a weaker claim than parity, let alone improvement.

The `w = 2` results are more clearly separated from baseline (1.20 points average degradation), but even this gap lacks a variance estimate. Without knowing the run-to-run stability, we cannot assess whether `w = 2` consistently underperforms by ~1.2 points or whether this particular run happened to produce a favorable or unfavorable result. The paper's recommended operating points (`w = 2` for throughput, `w = 10` for quality) are based on point estimates from single runs, and practitioners adopting these recommendations are implicitly assuming the point estimates are reliable.

The situation is analogous to the reference example's criticism of the compute-optimal scaling paper's ~50-question-per-bin strategy selection — small sample sizes and single measurements make it hard to distinguish signal from noise. Here, the sample size is 500 test questions for perplexity (a single 10M-token subset) and 7 tasks for downstream accuracy, each measured once.

**What evidence exists in the paper.** Tables 2 and 3 report single numbers per configuration. The paper does not mention running multiple seeds, does not provide error bars on any accuracy or perplexity figure, and does not discuss expected variance. The training details in Appendix B specify one set of hyperparameters per configuration, implying single runs. The downstream evaluation uses lm-eval-harness with its standard zero-shot protocol, which is deterministic given fixed model weights and prompts, so the only source of variance is the training process itself — which is not measured.

**Mitigation status.** None. The paper does not acknowledge the absence of statistical rigor as a limitation. The near-identical performance of `w = 10` and TinyLlama is presented as evidence of parity without qualification, and the `w = 2` results are presented as evidence of a modest accuracy tradeoff without discussing whether larger training budgets, different seeds, or different data mixtures could change the gap. For a paper whose practical adoption depends on practitioners trusting that `w = 10` really does recover baseline performance, this is a significant evidentiary gap.

### The Memory and Throughput Gains Are Measured Only Indirectly — No KV Cache Memory Breakdown Makes It Difficult to Decompose Savings or Predict Behavior on Different Hardware

**The assumption or constraint.** The paper uses maximum batch size and tokens-per-second throughput as proxies for memory savings, rather than directly measuring the KV cache memory consumption in bytes or as a fraction of total GPU memory. The authors cite Kwon et al. (2023) for the claim that KV cache "takes over 30% of the GPU memory during deployment" (Section 1), but they never measure what fraction of memory LCKV saves relative to that 30% baseline.

**The consequence.** A practitioner evaluating LCKV against alternative KV cache compression methods cannot directly compare memory savings. The maximum batch size metric conflates several effects:
- KV cache memory reduction (the intended mechanism).
- Parameter reduction from discarding `W_K` and `W_V` weights for non-warmup layers (a secondary benefit).
- Potential differences in memory fragmentation, activation memory, or CUDA context overhead between the standard and LCKV implementations.
- The specific GPU's memory capacity and architecture.

Two methods could achieve the same batch size improvement through different combinations of these effects, but the batch size metric alone cannot distinguish them. For example, if LCKV achieves a 4× batch size improvement on a 24GB GPU, does that come from reducing KV cache from 8GB to 2GB (a 6GB saving) or from 12GB to 3GB (a 9GB saving)? The distinction matters for predicting behavior on GPUs with different memory capacities, for combining LCKV with other methods, and for understanding how much headroom remains for further optimization.

The throughput metric has a similar conflation problem. Appendix C.6 and Figure 4 show that LCKV achieves higher throughput than standard transformers even at the same batch size, which the authors attribute to "factors such as the reduced calculation of KVs, the decreased memory consumption enabling faster memory transfer and access, and various implementation details." This honest admission of uncertainty about the mechanism means that a practitioner cannot confidently predict which of these factors will transfer to their specific hardware, model architecture, or implementation framework. If the throughput improvement at equal batch size is primarily due to reduced KV computation (fewer matrix multiplies), it will transfer broadly. If it is primarily due to reduced memory bandwidth pressure (fewer cache reads), it may be hardware-specific and could change with different GPU memory hierarchies.

**What evidence exists in the paper.** Table 1 reports batch sizes and throughput for specific GPU-model-sequence configurations. Figure 4 shows throughput scaling with batch size. Figure 5 shows latency and "Memory (GiB)" for StreamingLLM integration at different cache sizes. The memory numbers in Figure 5 are the closest the paper comes to direct memory measurement, but they are total GPU memory consumption (not KV cache specifically) and are only reported for the StreamingLLM integration experiment, not for the main throughput benchmarks in Table 1. Appendix C.6 reports latency at equivalent batch sizes (Table 10) but does not decompose the latency into computation vs. memory-access components.

**Mitigation status.** The paper does not provide a memory breakdown and does not acknowledge the conflation as a limitation. The authors' speculation in Appendix C.6 about the sources of throughput improvement suggests they recognize the mechanism is not fully understood, but they do not conduct the profiling experiments (e.g., measuring KV cache size directly, profiling memory bandwidth utilization, ablating the effect of parameter reduction vs. KV cache reduction) that would disentangle the effects. For a paper whose primary claimed contribution is memory reduction, the absence of direct memory measurements is a significant gap.
