# Is Preference Alignment Always the Best Option to Enhance LLM-Based Translation? An Empirical Analysis

**ArXiv:** [2409.20059](https://arxiv.org/abs/2409.20059)

## 🎯 Pitch

Optimizing translation models directly against neural quality estimators can silently break lexical metrics: contrastive preference alignment improves COMET scores by up to 2 points but often drops chrF by 1.8 points. Simply using the model’s own sampled candidates for alignment matches multi-system gains while keeping all metrics stable.

---

## 1. Executive Summary

This paper empirically analyzes whether preference-based alignment—specifically **Contrastive Preference Optimization (CPO)**—always improves LLM-based machine translation quality when optimizing model weights against neural metric preferences. The study conducts extensive experiments on the WMT'22 and WMT'23 test sets using ALMA-13B-LoRA as the base model, examining two candidate generation strategies: a multi-system approach (where chosen and rejected translations are drawn from GPT-4, the base model, and gold references) and a mono-system approach (where candidates come exclusively from the base model's own top-p-sampled outputs). The findings reveal that while CPO consistently outperforms Supervised Fine-Tuning on the alignment metric—achieving gains of approximately 1–2 points on xCOMET-QE for out-of-English translations—it introduces **adverse metric effects**, particularly dropping chrF by roughly 1.8 points for en-xx translations in the multi-system setting, and demonstrates high sensitivity to which candidate systems are included, establishing that mono-system alignment achieves performance comparable to multi-system approaches (matching within ~0.3 xCOMET-QE points) while preserving better consistency across neural and lexical evaluation metrics.

## 2. Context and Motivation

### The Core Problem: We Don't Understand How Preference Alignment Affects Translation Quality

The fundamental question this paper tackles is deceptively simple: **when we fine-tune an LLM for machine translation using preference-based alignment techniques, what actually happens to the model's behavior?** The question matters because there is a growing assumption in the field that if a neural metric correlates well with human judgments, then directly optimizing model weights to maximize that metric should unambiguously improve translation quality. This paper challenges that assumption by systematically investigating the downstream effects—including unintended ones.

The paper identifies a specific gap in our understanding (Section 1):

> "While some studies have examined quality-informed decoding techniques and their influence on translation output, there is still a gap in our understanding of how preference-based fine-tuning affects translation quality."

This gap exists precisely because preference-based alignment represents a paradigm shift from prior approaches. Unlike quality-aware decoding strategies that inject quality information at inference time (e.g., N-best reranking, Minimum Bayes Risk decoding), preference-based alignment modifies the model's weights during training to implicitly learn preferences induced by quality metrics. The paper argues that understanding the impact of these approaches is "a relevant problem" because the optimization is indirect—the model learns to prefer certain translations over others according to a metric, but how this preference learning interacts with other dimensions of translation quality (especially dimensions not directly targeted by the alignment metric) remains poorly characterized.

### Why This Problem Matters

**Real-world deployment decisions.** Organizations building LLM-based translation systems face a concrete choice: should they invest in preference-based alignment, supervised fine-tuning on high-quality data, or quality-aware decoding strategies? Each approach has different computational costs, data requirements, and deployment implications. Without understanding how preference alignment affects downstream performance across multiple evaluation dimensions, practitioners cannot make informed decisions about which technique to adopt. The paper provides empirical evidence that the answer is not straightforward—preference alignment can simultaneously improve one metric while degrading another, a tradeoff that has direct practical consequences.

**Metric gaming and evaluation fragility.** The machine translation community has increasingly moved away from lexical metrics like BLEU and chrF toward neural metrics like COMET, BLEURT, and Metric-X because the latter better correlate with human judgments (Mathur et al., 2020; Kocmi et al., 2021; Freitag et al., 2022b; Kocmi et al., 2024). However, this shift creates a new risk: if models are directly optimized against neural metrics, those metrics may become unreliable as evaluation tools—what the paper calls "adverse metric effects." The paper demonstrates exactly this phenomenon: CPO alignment on xCOMET-QE improves xCOMET-QE scores but degrades chrF scores, particularly for out-of-English translations (see Table 1, where en-xx chrF drops from 49.49 for the base model to 47.69 after CPO alignment on xCOMET-QE). This matters because it echoes a broader concern in the metrics literature (Kocmi et al., 2024): using the same metric for optimization and evaluation can lead to inflated or misleading assessments.

**The rise of decoder-only LLMs for translation.** The paper positions itself at the intersection of two trends: the adoption of decoder-only LLMs for translation tasks (Zhu et al., 2023; Jiao et al., 2023; Hendy et al., 2023; Xu et al., 2023) and the availability of high-quality neural metrics (Rei et al., 2020; Juraska et al., 2023). LLM-based translation systems introduce new training dynamics—these models are typically not trained from scratch for translation but rather fine-tuned from general-purpose checkpoints—making the interaction between preference optimization and model capabilities potentially different from what has been observed in encoder-decoder NMT systems. Understanding these dynamics is critical as the field shifts toward LLM-based approaches.

### Prior Approaches and Their Limitations

**Quality-aware decoding strategies.** Before preference-based alignment became viable, the dominant approach for incorporating quality information into translation systems was at inference time. The approach is straightforward: sample multiple candidate translations from the model using diverse decoding (e.g., beam search, top-p sampling), score each candidate with a quality metric, and select the best one. This methodology is exemplified by N-best reranking (for reference-free metrics) and Minimum Bayes Risk (MBR) decoding (for reference-based metrics), as described in work by Fernandes et al. (2022) and Freitag et al. (2022a).

The paper identifies both the strengths and limitations of this approach (Section 2.1). On the positive side, these techniques "consistently yield better results than likelihood-based decoding techniques" (citing Eikema and Aziz, 2020; Koehn and Knowles, 2017; Ott et al., 2018). The problem is that decoding-based methods are computationally expensive at scale: they require generating many samples *per inference call*, multiplying the cost of each translation by the number of candidates. For batch inference or high-throughput production systems, this overhead can be prohibitive. Moreover, decoding strategies don't change the underlying model—each time the model is used, the same expensive sampling and reranking procedure must be repeated.

**Supervised Fine-Tuning on high-quality data.** A complementary approach involves filtering parallel training data based on quality metrics and fine-tuning the model on high-quality translations (Alves et al., 2024; Section 2.2). This is simpler and more direct than preference optimization: identify translations that score well according to a metric and perform standard sequence-level supervised training on those examples. The limitation, as the paper notes, is that SFT only optimizes likelihood on chosen translations—it doesn't leverage information about which translations are *rejected*. If a high-quality translation and a slightly-higher-quality translation are both available, SFT treats the slightly-higher-quality one as the sole target and discards the signal present in the quality gap between them.

**Preference Optimization methods.** The paper focuses specifically on a family of techniques that learn from pairwise preferences between translations. The key idea (Section 2.2) is that rather than simply increasing the probability of good translations, the model should learn to distinguish between better and worse alternatives—it should actively learn to *reject* poor translations, not just produce good ones. The most prominent method in this family is Direct Preference Optimization (DPO), introduced by Rafailov et al. (2024), which maximizes a scaled likelihood gap between a chosen and rejected translation:

$$\mathcal{L}_{\text{DPO}} = -\mathbb{E}_{(x, y_c, y_r) \sim \mathcal{D}} \left[ \log \sigma \left( \beta \log \frac{\pi_\theta(y_c | x)}{\pi_{\text{ref}}(y_c | x)} - \beta \log \frac{\pi_\theta(y_r | x)}{\pi_{\text{ref}}(y_r | x)} \right) \right]$$

where $\pi_\theta$ is the policy being optimized, $\pi_{\text{ref}}$ is a reference policy (typically the base model), and $\beta$ controls the strength of the preference signal.

Contrastive Preference Optimization (CPO) extends this by incorporating an SFT loss term on chosen translations, yielding the objective discussed in the paper (Section 3.2):

$$\mathcal{L}_{\text{CPO}} = -\frac{1}{N} \sum_{i=1}^N \left[ \log \sigma \left( \beta \log \frac{\pi_\theta(y_i^c | x_i)}{\pi_\theta(y_i^r | x_i)} \right) \right] + \mathcal{L}_{\text{SFT}}$$

where $\mathcal{L}_{\text{SFT}} = -\frac{1}{N} \sum_{i=1}^N \log \pi_\theta(y_i^c | x_i)$. The paper notes that CPO removes the reference policy from the objective (unlike DPO), which "improves training efficiency."

However, these methods have been studied almost exclusively in terms of their *alignment effectiveness*—whether they improve the metric they were trained to optimize. The paper identifies a critical gap: **their broader effects on translation quality, particularly on metrics not directly optimized, and their robustness to the choice of candidate systems used to construct preference data, are largely unexplored.**

### Conflicting Signals in the Literature

The paper is motivated by an implicit tension in prior work. On one side, preference-based alignment has shown impressive gains on alignment metrics: Xu et al. (2024a) demonstrated that CPO achieves "very competitive translation performance" and established a seemingly successful recipe involving multi-system candidate generation. On the other side, prior work on quality-aware decoding (Amrhein and Sennrich, 2022) had already suggested that "weaknesses in machine translation metrics" can be exposed when models are optimized against them—metrics that work well for evaluation may not serve well as optimization targets. The paper does not cite conflicting studies directly, but the tension is clear: if preference alignment works, *why* might it not always be the best option? And if there are failure modes, under what conditions do they emerge?

### How This Paper Positions Itself

The paper frames itself as an **empirical diagnosis** rather than a proposal for a new method. The authors take the strongest existing preference alignment approach (CPO with multi-system candidates, following Xu et al., 2024a) and systematically interrogate it:

**First**, they replicate the finding that CPO outperforms SFT on alignment metrics—this establishes that the phenomenon they're studying is real and reproducible.

**Second**, they examine the *interactions* between optimized and non-optimized metrics. This is where the paper's primary contribution lies: the demonstration that CPO can produce significant adverse effects on lexical metrics, and that SFT does not produce such effects (Table 1). This directly challenges the implicit assumption that alignment improvements are monotonic or benign.

**Third**, they test the sensitivity of alignment performance to the composition of candidate systems (Section 4.2). Prior work used a fixed recipe (base model + GPT-4 + gold references) without examining whether this choice was essential or arbitrary. The paper shows that candidate system choice strongly affects both alignment effectiveness and downstream metric consistency, with CPO being substantially more sensitive than SFT.

**Fourth**, they propose and evaluate an alternative: mono-system preference data, where the base model itself generates all candidates (Section 5). This shifts the research question from "which external systems should we use?" to "can a model align effectively using only its own outputs?" The paper shows that mono-system alignment achieves competitive performance while mitigating adverse metric effects, and additionally offers fine-grained control over the quality gap between chosen and rejected options (Section 5.2).

**Conceptually**, the paper is best understood as an **ablation and robustness study** of the CPO alignment pipeline for translation. It does not argue that preference alignment is bad—in fact, it repeatedly shows CPO outperforms SFT—but rather that the benefits come with tradeoffs that the field has not adequately characterized. The paper's title is literal: "Is Preference Alignment Always the Best Option?" The answer, based on their evidence, is "not always, and the conditions under which it is or isn't depend on the candidate systems, the evaluation metric, and the language direction."

The paper also connects to a broader methodological concern in the MT metrics community about "using the same metric for evaluation that was used during training/inference" (citing Kocmi et al., 2024). Their findings provide concrete empirical evidence for why this caution is warranted, extending it from decoding strategies (where it was previously studied by Amrhein and Sennrich, 2022) to preference-based fine-tuning.

### The Specific Gap the Paper Fills

To summarize the gap specifically: prior work on preference alignment for translation (Xu et al., 2024a) demonstrated strong results but did not systematically analyze **when and why** the approach succeeds or fails. Specifically, the literature lacked answers to four questions:

1. Does CPO's improvement over SFT hold across all evaluation metrics, or does it introduce metric-specific effects?
2. How sensitive is CPO to the composition of candidate systems used for preference data generation?
3. Can effective alignment be achieved without external systems (mono-system), and how does this compare to the multi-system approach?
4. What are the optimal properties of preference data (chosen/rejected quality gap) for maximizing alignment performance?

The paper addresses all four questions through extensive controlled experiments, providing the first systematic characterization of preference-based alignment's effects on translation quality across multiple metrics, language directions, and candidate generation strategies. In doing so, it doesn't propose a new algorithm but rather establishes the **boundary conditions and failure modes** of an existing one—a type of contribution that is essential for the field to move from "this works" to understanding *where* and *why* it works.

## 3. Technical Approach

### 3.1 Reader Orientation

This paper builds a systematic evaluation framework for analyzing how preference-based fine-tuning, specifically Contrastive Preference Optimization (CPO), affects machine translation quality when optimizing against neural and lexical quality metrics. The core problem it solves is *diagnostic* rather than algorithmic: given that CPO improves the metric it is aligned against, what happens to other metrics that are not directly optimized, and how robust is this improvement to the choice of candidate systems used to construct preference data? The "shape" of the solution is a controlled experimental design that isolates two variables—the learning objective (SFT vs. CPO) and the candidate generation strategy (multi-system vs. mono-system)—while measuring downstream effects across three evaluation metrics spanning neural and lexical families, two language direction groups, and multiple candidate system configurations.

### 3.2 Big-Picture Architecture (Diagram in Words)

The experimental pipeline has four major components:

1. **Preference Data Construction** — takes a source dataset of translation pairs and produces a dataset of (source, chosen translation, rejected translation) triples, where "chosen" and "rejected" are determined by scoring candidate translations with a target metric. This component has two variants: multi-system (candidates from Base model, GPT-4, and gold references) and mono-system (candidates from the Base model's own top-p-sampled outputs).

2. **Contrastive Preference Optimization (CPO) Training** — takes the preference dataset and fine-tunes the base model (ALMA-13B-LoRA) using the CPO objective, which combines a preference term (maximizing the likelihood gap between chosen and rejected) with a supervised term (maximizing likelihood on chosen translations alone). A parallel SFT baseline is run on chosen translations only.

3. **Inference** — all aligned models are decoded using greedy decoding on the WMT'22 and WMT'23 test sets, producing single-best translations for each source sentence across 10 language directions.

4. **Multi-Metric Evaluation** — each model's outputs are scored with three metrics: xCOMET-QE (neural, reference-free), CometKiwi (neural, reference-free), and chrF (lexical, reference-based). The evaluation measures both absolute performance on each metric and, critically, the *interactions* between metrics—whether improvements on the alignment metric come at the cost of degradation on non-aligned metrics.

Information flows linearly: preference data is constructed → models are trained → translations are generated → metrics are computed → performance differences are statistically tested using paired Student's t-tests at the 5% significance level.

### 3.3 Roadmap for the Deep Dive

- **First**, the preference data construction pipeline: how candidate translations are generated, scored, and paired into chosen/rejected triples for both multi-system and mono-system settings. This is the foundation everything else depends on, because the quality and composition of preference data directly determine what the model learns.

- **Second**, the CPO learning objective and its relationship to SFT: why CPO adds a reject term to the standard SFT loss, how the β parameter controls the preference signal strength, and what removing the reference policy (vs. DPO) means for training dynamics. Understanding this objective is essential to interpreting the experimental results.

- **Third**, the training configuration: base model choice (ALMA-13B-LoRA), LoRA hyperparameters, optimization schedule, and the specific β value used. These are the engineering details that enable replication.

- **Fourth**, the inference and evaluation setup: why greedy decoding is used, which test datasets are evaluated, and how statistical significance is assessed. This connects the training outcomes to the reported results.

- **Fifth**, the candidate system ablation methodology (for Section 4): how systems are removed from the candidate pool, how the chosen system is fixed, and what each ablation is designed to test. This explains the experimental logic before the results are presented.

- **Finally**, the mono-system preference data optimization methodology (for Section 5): how nine preference datasets with varying chosen/rejected quality levels are constructed from the base model's own outputs, and how the optimal quality gap is identified. This completes the technical picture by showing how mono-system alignment can be tuned beyond simply replicating multi-system properties.

### 3.4 Detailed, Sentence-Based Technical Breakdown

This is primarily an **empirical analysis paper** whose core idea is that preference-based alignment with CPO improves the alignment metric but can introduce adverse effects on non-aligned metrics, and that these effects are mediated by the choice of candidate systems used to construct preference data.

#### Preference Data Construction

**Multi-System Candidate Pool**

The multi-system approach follows the exact recipe established by Xu et al. (2024a). For each source sentence in the training corpus, three candidate translations are drawn from three distinct systems:

- **Base**: The output of ALMA-13B-LoRA (the model to be aligned), which the paper refers to as "the base model we aim to align" (Section 3.1).
- **GPT-4**: Translations generated by OpenAI's GPT-4 (OpenAI, 2023).
- **Ref**: The human-written gold reference translation from the parallel corpus.

Formally, for each data sample indexed by $i$, the candidate set is:

$$Y_i^{\text{multi}} = \left\{y_i^{\text{Ref}}, \; y_i^{\text{Base}}, \; y_i^{\text{GPT-4}}\right\}$$

where $y_i^{\text{Ref}}$ denotes the gold reference, $y_i^{\text{Base}}$ denotes the base model's translation, and $y_i^{\text{GPT-4}}$ denotes GPT-4's translation.

**What it means:** for every source sentence, the system has exactly three candidate translations available, each produced by a fundamentally different generation process—one from the model being aligned, one from a much larger and more capable closed-source model, and one written by a human translator. These three translations differ not just in quality but in their *distributional properties*: GPT-4's outputs may have different lexical patterns, syntactic structures, or error types than the base model's outputs, and human references have their own distinctive properties (e.g., perfect lexical overlap with the reference by definition when scored with chrF).

**Why this composition:** the multi-system approach is designed to provide a diverse pool of candidates with a wide quality range. GPT-4 typically produces the highest-quality translations, the base model produces intermediate-quality translations, and the reference serves as an anchor. This diversity is intended to ensure that the preference signal is both strong (large quality gaps between chosen and rejected) and informative (different translation styles and error patterns are represented).

**Pair Selection**

Once candidates are generated, they are scored with a target metric $m$, and a preference pair is formed by selecting the highest-scoring translation as the chosen hypothesis and the lowest-scoring translation as the rejected hypothesis:

$$y_i^c = \arg\max_{y \in Y_i^{\text{multi}}} m(y) \quad \land \quad y_i^r = \arg\min_{y \in Y_i^{\text{multi}}} m(y)$$

**What it means:** for each source sentence, the system picks the "best" and "worst" translation according to metric $m$ from the pool of three candidates. The chosen $y_i^c$ is the one the model should learn to emulate; the rejected $y_i^r$ is the one the model should learn to avoid. The metric $m$ determines what "best" and "worst" mean—if $m$ is a neural metric like xCOMET-QE, the preference reflects semantic adequacy and fluency; if $m$ is a lexical metric like chrF, the preference reflects character n-gram overlap with the reference.

**Why this selection method:** selecting the extremes (max and min) from the candidate pool maximizes the quality gap between chosen and rejected, which should provide the strongest possible training signal for CPO. However, this method also means that if the metric $m$ is imperfect or biased, those imperfections will be amplified in the preference pairs—the "best" translation by a flawed metric may not be the genuinely best translation.

**Mono-System Candidate Pool**

In the mono-system setting, all candidates come exclusively from the base model itself. For each source sentence, $K = 50$ candidate translations are generated using top-p sampling with $p = 0.6$ and temperature $\tau = 0.9$. These are the default sampling parameters from the ALMA paper (Xu et al., 2023, 2024a).

The candidates are then scored with metric $m$ and sorted in increasing quality order:

$$Y_i^{\text{mono}} = \left\{y_i^1, \ldots, y_i^K\right\}$$

where $y_i^1 \preceq \cdots \preceq y_i^K$ and $\preceq$ denotes "is scored lower than or equal to by metric $m$."

**What it means:** instead of drawing candidates from multiple external systems, the model generates 50 diverse translations of the same source sentence by sampling from its own output distribution at elevated temperature. These 50 candidates span a range of quality—some will be good (fluent, adequate), some will be mediocre, and some will be poor—but they all come from the same underlying distribution (the base model's learned translation behavior). This ensures that the preference pairs reflect *intra-model* quality variation rather than *inter-system* differences.

**Why 50 candidates:** the number 50 is not explicitly justified in the paper, but it provides a sufficient sample size to reliably estimate the base model's quality distribution per source sentence and to construct preference pairs with meaningful quality gaps. With only 3 candidates (as in the multi-system setting), the quality range is limited and may not capture the full span of the model's capabilities; with 50, there is much finer granularity in selecting chosen and rejected translations.

**Mono-System Pair Selection**

The key constraint in mono-system preference pair construction is that the chosen translation must be of higher quality than the base model's greedy-decoded output (denoted $y_i^{\text{Base}}$), and the rejected translation must be of lower quality. This ensures the preference pairs provide a meaningful contrast signal.

Given the sorted candidate list, the greedy-decoded translation's position in the ranking is identified. Let $b_i$ be the index such that $y_i^{b_i} = y_i^{\text{Base}}$ (after re-ranking by metric $m$). Then:

$$y_i^1 \preceq \cdots \preceq y_i^{b_i-1} \preceq y_i^{\text{Base}} \preceq y_i^{b_i} \preceq \cdots \preceq y_i^K$$

The chosen and rejected translations are selected using two offset parameters $o_r, o_c \in \mathbb{N}$:

$$y_i^c = y_i^{\min(K, b_i + o_c)}$$

$$y_i^r = y_i^{\max(1, b_i - o_r)}$$

**What it means:** given the base model's greedy output at position $b_i$ in the quality ranking, the chosen translation is selected $o_c$ steps *above* it (higher quality), and the rejected translation is selected $o_r$ steps *below* it (lower quality). The $\min$ and $\max$ operations prevent index errors when the base model's output is near the top or bottom of the distribution.

**Why this form:** the offset parameters provide explicit control over the quality gap between chosen and rejected translations. By varying $o_c$ and $o_r$, the experimenter can create preference datasets with different properties: small offsets produce narrow quality gaps (the chosen is only slightly better than the rejected), while large offsets produce wide gaps. The additional paper statistics (Table 11 in Appendix B.1) show that the "multi-system replica" mono-system dataset was constructed with parameters designed to match the average chosen and rejected qualities of the multi-system dataset: rejected xCOMET-QE of 87.80 (mono) vs. 87.86 (multi) and chosen xCOMET-QE of 97.29 (mono) vs. 97.24 (multi).

**The multiple-mono-system-datasets design (for Section 5.2):** to study the optimal preference data properties, the paper constructs nine mono-system preference datasets by categorizing chosen and rejected average qualities into three groups (High, Mid, Low) and crossing them. This produces a 3×3 grid of datasets, each with a different combination of chosen quality level and rejected quality level, enabling a systematic exploration of how the quality gap affects post-CPO performance. The specific quality thresholds for High/Mid/Low are not reported numerically in the main text but are documented in Appendix B.1 (Table 11), showing average xCOMET-QE scores ranging from 75.36 to 98.16 for chosen options and from 75.36 to 92.15 for rejected options.

**Source Dataset**

All preference data is built on the FLORES-200-based dataset from Xu et al. (2024a). The corpus includes over 20,000 translation pairs spanning six languages (English, Czech, German, Icelandic, Russian, Chinese) and covering ten language directions: five into-English (cs-en, de-en, is-en, ru-en, zh-en) and five out-of-English (en-cs, en-de, en-is, en-ru, en-zh). The language statistics (Appendix B.2, Figure 2) show that English is the most common source language (51.2% of samples) and the most common target language (48.8% of samples), reflecting the centrality of English in the translation directions studied. Individual language pairs have roughly balanced sample sizes (ranging from 9.8% to 11.1% each). The use of a multilingual dataset spanning typologically diverse languages (Germanic, Slavic, Sino-Tibetan) is important because it tests whether the observed alignment effects generalize across language families or are specific to particular translation directions.

**Alignment Metrics**

Three metrics are used to induce preferences, chosen to represent different metric families:

- **xCOMET-QE-XXL** (abbreviated xCOMET-QE): a reference-free neural metric that scores translations based on the source sentence and the translation alone, without access to a gold reference. It is trained to predict human quality judgments and has been shown to correlate strongly with human preferences (Guerreiro et al., 2023).

- **CometKiwi-XXL** (abbreviated CometKiwi): another reference-free neural metric, specifically the WMT'23 version (Rei et al., 2023). It uses a similar architecture to xCOMET-QE but is trained on different data, meaning the two metrics may capture slightly different aspects of translation quality despite both being neural and reference-free.

- **chrF**: a reference-based lexical metric that computes character n-gram F-score between the translation and the gold reference (Popovi´c, 2015). Unlike neural metrics, chrF measures surface-form overlap—how many character n-gram sequences the translation shares with the reference—making it sensitive to lexical choice and word order but insensitive to semantic adequacy (a translation can score high on chrF while being semantically wrong if the lexical patterns match by coincidence).

**Why these three metrics:** they span two fundamentally different evaluation paradigms. Neural metrics (xCOMET-QE, CometKiwi) learn to predict human judgments from annotated training data and can assess translation quality without a reference. Lexical metrics (chrF) compute overlap statistics with a reference and make no attempt to model semantics or human preferences. By aligning on one type and evaluating on the other type, the paper can detect whether improvements on neural metrics come at the cost of lexical degradation, or vice versa. This cross-metric analysis is central to the paper's contribution.

#### The CPO Learning Objective

**Background: Why CPO Over DPO or Pure SFT**

Contrastive Preference Optimization (CPO) is introduced by Xu et al. (2024a) as an improvement over Direct Preference Optimization (DPO) for machine translation. The key innovation is merging a preference-learning term with a standard supervised likelihood term, while removing the reference model that DPO requires.

The paper's framing (Section 2.2 and Section 3.2) positions CPO as combining the strengths of two approaches: DPO learns to distinguish between better and worse translations (the "contrastive" signal), while SFT directly increases the probability of high-quality translations (the "likelihood" signal). By combining both in a single objective, CPO should theoretically learn both *what to produce* (from SFT on chosen translations) and *what to avoid* (from the preference gap between chosen and rejected).

**The CPO Loss Function**

The empirical CPO loss is:

$$\mathcal{L}_{\text{CPO}} = -\frac{1}{N} \sum_{i=1}^N \left[ \log \sigma \left( \beta \log \frac{\pi_\theta(y_i^c | x_i)}{\pi_\theta(y_i^r | x_i)} \right) \right] + \mathcal{L}_{\text{SFT}}$$

where:

$$\mathcal{L}_{\text{SFT}} = -\frac{1}{N} \sum_{i=1}^N \log \pi_\theta(y_i^c | x_i)$$

and where:
- $N$ is the number of training samples (preference pairs),
- $x_i$ is the $i$-th source sentence,
- $y_i^c$ is the chosen translation for source $x_i$,
- $y_i^r$ is the rejected translation for source $x_i$,
- $\pi_\theta(y | x)$ is the probability the model with parameters $\theta$ assigns to generating translation $y$ given source $x$ (the model's likelihood of the sequence),
- $\sigma(z) = 1 / (1 + e^{-z})$ is the sigmoid function (mapping real values to the range $[0, 1]$),
- $\beta = 0.1$ is a hyperparameter controlling the strength of the preference signal,
- $\log \sigma(\cdot)$ is the log-sigmoid of the scaled log-ratio of chosen vs. rejected probabilities.

**What it computes (first term, preference component):** for each preference pair, the model computes the log-ratio $\log(\pi_\theta(y_i^c | x_i) / \pi_\theta(y_i^r | x_i))$, which is positive when the model assigns higher probability to the chosen translation than to the rejected one, and negative when the reverse is true. This log-ratio is scaled by $\beta = 0.1$ and passed through the sigmoid function $\sigma(\cdot)$, which maps it to a value between 0 and 1 (close to 1 when the log-ratio is large and positive, close to 0 when it is large and negative). Taking the log and negating produces a loss term: when the chosen translation has much higher probability than the rejected, the term is small (good); when the rejected has higher probability, the term is large (bad). The sum over all $N$ pairs averages this preference loss across the dataset.

**What it computes (second term, SFT component):** the cross-entropy loss between the model's predicted distribution and the chosen translation $y_i^c$. This is the standard supervised learning objective: the model is penalised for assigning low probability to the tokens of $y_i^c$ given $x_i$. This term alone would train the model to simply produce translations similar to the chosen ones, without any contrastive signal.

**What the full objective does operationally:** the model receives two simultaneous training signals for each source sentence. The SFT term pulls the model's probability distribution toward the chosen translation—"produce translations like this." The preference term pushes the model's probability distribution away from the rejected translation relative to the chosen one—"when in doubt between these two options, prefer the chosen one by at least this margin." The combined effect is that the model learns to not just output high-scoring translations in general, but specifically to rank translations in the same order as the alignment metric $m$.

**Why this form over alternatives:**

- **Compared to DPO**, CPO removes the reference policy $\pi_{\text{ref}}$ that appears in the DPO objective. In DPO, the preference term involves $\log(\pi_\theta(y^c|x)/\pi_{\text{ref}}(y^c|x)) - \log(\pi_\theta(y^r|x)/\pi_{\text{ref}}(y^r|x))$, which requires forward passes through both the trained model and the frozen reference model. CPO replaces this with a single log-ratio $\log(\pi_\theta(y^c|x)/\pi_\theta(y^r|x))$ that depends only on the current model. The paper states this "improves training efficiency" because it halves the number of forward passes needed per training step (no reference model computation). It also removes a hyperparameter—the choice of reference model—which can affect DPO's behavior.

- **Compared to pure SFT**, CPO adds the preference term. Pure SFT on chosen translations would ignore the rejected translations entirely, missing the opportunity to learn from negative examples. CPO's preference term explicitly penalizes the model when it assigns high probability to rejected translations, which should reduce the model's tendency to produce translations with properties that the alignment metric disfavors.

- **Compared to a margin-based ranking loss** (e.g., max-margin), the sigmoid-based log-ratio provides a smooth, differentiable preference signal. The sigmoid saturates when the log-ratio is very large (the chosen is already much more probable than the rejected), preventing the model from over-optimizing on pairs where the preference is already well-learned. This saturation property is important for stability.

**The β parameter role:** with $\beta = 0.1$, the log-ratio $\log(\pi_\theta(y^c|x)/\pi_\theta(y^r|x))$ is scaled down before entering the sigmoid. This has the effect of making the preference signal "softer"—the sigmoid is less saturated for typical log-ratio values, providing more graded feedback. If $\beta$ were large (e.g., $\beta = 1.0$), the sigmoid would quickly saturate, making the loss almost binary (0 or 1) and potentially causing the model to focus only on the hardest preference pairs while ignoring moderate ones. The value $\beta = 0.1$ is taken from the original DPO paper (Rafailov et al., 2024) and is not tuned in this work.

**The equivalent SFT baseline:** in all experiments, CPO is compared to standard SFT on the chosen translations alone, using the identical training configuration (same optimizer, learning rate, number of epochs, batch size). The SFT loss is simply:

$$\mathcal{L}_{\text{SFT-only}} = -\frac{1}{N} \sum_{i=1}^N \log \pi_\theta(y_i^c | x_i)$$

This identical configuration ensures that any difference between CPO and SFT performance can be attributed to the preference term, not to differences in training recipe.

#### Training Configuration

**Base Model**

All experiments use ALMA-13B-LoRA (Xu et al., 2023) as the base model for alignment. ALMA (Advanced Language Model-based trAnslator) is a fine-tuned version of LLaMA-2-13B that has been optimized for machine translation through a two-stage process: first, continued pretraining on monolingual data, then supervised fine-tuning on parallel translation data using LoRA (Low-Rank Adaptation). The model uses LoRA with rank 16, meaning that only a small fraction of the total parameters are trainable—two low-rank matrices per attention layer that approximate full weight updates. This makes fine-tuning computationally efficient while preserving the base model's general language capabilities.

**Why ALMA-13B-LoRA:** this model represents the state-of-the-art for open-source LLM-based translation at the time of the experiments, and it is the same base model used in the CPO paper (Xu et al., 2024a) that this work studies. Using the identical base model ensures direct comparability of results.

**LoRA Fine-Tuning Hyperparameters**

The training configuration exactly replicates Xu et al. (2024a):

- **LoRA rank**: 16 (the dimension of the low-rank decomposition matrices)
- **Training epochs**: 1 (a single pass over the preference data)
- **Initial learning rate**: $10^{-4}$
- **Learning rate schedule**: inverse square root decay (the learning rate decreases proportionally to $1 / \sqrt{t}$ where $t$ is the number of steps)
- **Batch size**: 128 (preference pairs per gradient update)
- **CPO β parameter**: 0.1 (the preference signal strength, as described above)

**What these choices mean:** training for only 1 epoch means the model sees each preference pair exactly once during fine-tuning. This is a relatively light fine-tuning regime compared to full model training (which might involve multiple epochs or full-weight updates). The high initial learning rate ($10^{-4}$) with inverse square root decay means the model makes large updates early in training (when it encounters the first preference pairs) and progressively smaller updates later, settling into a stable configuration. The batch size of 128 is standard for LLM fine-tuning and provides a stable gradient estimate.

**Why these hyperparameters:** they are taken directly from prior work and are not independently tuned in this paper. The paper's experimental contribution is not in finding better hyperparameters but in characterizing the *behavior* of these established settings. By replicating the exact configuration from Xu et al. (2024a), the paper ensures that any differences observed between SFT and CPO, or between multi-system and mono-system alignment, are due to the learning objective and data composition, not to changes in optimization procedure.

**Implementation**

All models are trained using the code implementation provided by Xu et al. (2024a), which is publicly available. This ensures that the training pipeline—including data loading, batching, LoRA adapter management, and loss computation—is identical to the original CPO work, eliminating implementation differences as a confounding factor. Training compute is provided by the Jean Zay supercomputer and the Adastra supercomputer (acknowledged in the paper).

#### Inference and Evaluation Setup

**Decoding Strategy**

All generations at inference time use **greedy decoding**, as explicitly stated in Section 3.3:

> "Following other works on LLM-based translation (Alves et al., 2024; Briakou et al., 2024), all generations at inference time are produced using greedy decoding, as it provides maximum computational efficiency while preserving high output quality."

**What greedy decoding means:** at each step of generation, the model selects the single token with the highest predicted probability, given the source sentence and all previously generated tokens. There is no sampling, no beam search, and no reranking. The output is deterministic—for a given model and input, the same translation is always produced.

**Why greedy decoding:** the paper's focus is on how fine-tuning affects the model's weights and, consequently, its single-best translation output. Using deterministic decoding eliminates variance from sampling, making the evaluation clean and reproducible. Practically, greedy decoding is also the most computationally efficient decoding strategy—it generates exactly one token per step with no additional forward passes—making it suitable for large-scale evaluation across multiple models, test sets, and language pairs. The paper contrasts this with quality-aware decoding approaches (like MBR) that generate multiple candidates and rerank them: those approaches achieve higher quality at higher computational cost, while fine-tuning aims to improve the model's greedy output directly, amortizing the quality improvement into the weights rather than paying for it at inference time.

**Inference Implementation**

Decoding is performed using the vLLM library (Kwon et al., 2023), which is an efficient inference engine for LLMs that uses PagedAttention to manage GPU memory. The use of vLLM is a practical engineering choice to enable fast generation across thousands of test sentences without memory bottlenecks.

**Evaluation Datasets**

Models are evaluated on two test sets:

- **WMT'22 test data**: 17,471 source-reference pairs covering the same ten language pairs as the preference data (five into-English and five out-of-English). This is the primary evaluation dataset discussed in the main text.

- **WMT'23 test data**: an additional test set used for validation that the observed effects generalize across different test distributions. The paper reports WMT'23 results in Appendix A and notes they "support the observations discussed in the main text."

The language statistics for these test sets (Appendix B.2, Figure 3) show that English is the predominant source/target language in both WMT'22 and WMT'23, with into-English pairs making up approximately 48% of WMT'22 and 39% of WMT'23.

**Evaluation Metrics**

All models are evaluated using the same three metrics used to create preference datasets:

- **xCOMET-QE-XXL**: neural, reference-free. Scores range approximately from 0–100, with higher values indicating better quality as predicted by a model trained on human judgments.

- **CometKiwi-XXL** (WMT'23 version): neural, reference-free. Similar score range to xCOMET-QE.

- **chrF**: lexical, reference-based. Character n-gram F-score ranging from 0 to 100, where 100 indicates perfect character n-gram overlap with the reference. The paper uses the standard chrF implementation (Popović, 2015).

Additional metrics are reported in Appendix A (Tables 9 and 10): Metric-X-Large (a reference-based neural metric) and BLEU (a reference-based lexical metric), providing a wider picture of metric behavior.

**Why three metrics:** using two neural metrics and one lexical metric enables the paper to detect two types of metric interactions: (a) whether aligning on one neural metric improves or degrades the other neural metric (testing generalization within the neural metric family), and (b) whether neural alignment degrades lexical performance (testing cross-family compatibility). The additional metrics in Appendix A (Metric-X, BLEU) provide further validation.

**Statistical Testing**

All comparisons between models are tested for statistical significance using **one-tailed paired Student's t-tests at the 5% significance level**. In the result tables, values in italic font denote statistically significant differences.

**What one-tailed paired t-test means:** for each test sentence, the difference in metric scores between two models (e.g., CPO minus SFT) is computed. The t-test evaluates whether the mean of these per-sentence differences is significantly greater than zero (one-tailed, testing for improvement) or significantly less than zero (one-tailed, testing for degradation). The paired nature of the test accounts for the fact that the same sentences are being evaluated across models—sentence-level difficulty is controlled for. The 5% significance level ($p < 0.05$) means that if the null hypothesis (no difference between models) were true, the observed difference would occur by chance less than 5% of the time.

**Why this test:** paired t-tests are standard in MT evaluation and are appropriate when comparing two systems on the same test set because they control for per-sentence variance. The one-tailed variant is used because the paper's hypotheses are directional (e.g., "CPO outperforms SFT" or "removing a candidate system reduces performance"), not simply testing for any difference.

**Metrics Reporting**

Results are reported separately for into-English (xx-en) and out-of-English (en-xx) translations, aggregating across the five language directions in each group. This split is motivated by the observation that translation behavior often differs substantially between translating into versus out of English, particularly for LLM-based systems. The paper finds that adverse metric effects are primarily observed in the out-of-English direction, making this disaggregation essential for interpreting results.

**Color Coding in Result Tables**

The paper uses a consistent color scheme across all result tables: green shades indicate metric improvements over the base model (higher scores after alignment), and red shades indicate metric decreases over the base model. A filled circle (•) marks scenarios where the evaluation metric matches the preference metric used for alignment—this draws the reader's attention to alignment-vs.-evaluation metric relationships.

#### Candidate System Ablation Methodology (for Section 4)

**System Removal Experiments**

To test the sensitivity of alignment performance to candidate system composition, the paper systematically removes individual systems from the multi-system candidate pool and evaluates the effect on downstream metrics. Starting from the full candidate pool $\{y_i^{\text{Ref}}, y_i^{\text{Base}}, y_i^{\text{GPT-4}}\}$, three ablated pools are created:

- **No Base**: $\{y_i^{\text{Ref}}, y_i^{\text{GPT-4}}\}$ — the base model's own translations are excluded, leaving only the gold reference and GPT-4 as candidates.
- **No Ref**: $\{y_i^{\text{Base}}, y_i^{\text{GPT-4}}\}$ — the gold reference is excluded, leaving the base model and GPT-4.
- **No GPT-4**: $\{y_i^{\text{Ref}}, y_i^{\text{Base}}\}$ — GPT-4 is excluded, leaving only the gold reference and the base model.

For each ablated pool, new preference datasets are constructed using the same method (score all candidates with metric $m$, select highest as chosen, lowest as rejected), and both SFT and CPO models are trained on these datasets. The results are compared to the "All systems" baseline.

**What this tests:** if removing a system causes a significant drop in alignment performance, that system was contributing important information to the preference pairs. If removing a system causes an *improvement*, that system was introducing noise or harmful biases. This ablation design isolates the contribution of each candidate system.

**Why this is necessary:** prior work (Xu et al., 2024a) used all three systems without justification for why each was needed. This ablation tests whether the choice is incidental or essential—could alignment work equally well with just two systems, or with a different combination?

**Chosen System Fixation Experiments**

A complementary analysis fixes the chosen system to a single source while allowing the rejected system to vary among the remaining candidates (when a lower-scoring candidate exists). Three fixed-chosen datasets are created:

- **Chosen = Base**: all chosen translations are forced to be the base model's output. The rejected translation is selected from $\{y_i^{\text{Ref}}, y_i^{\text{GPT-4}}\}$ as the one with the lower xCOMET-QE score (samples where no remaining candidate has a lower score than the base output are discarded).

- **Chosen = Ref**: all chosen translations are the gold reference. Rejected is the lower-scoring of the base model or GPT-4 output.

- **Chosen = GPT-4**: all chosen translations are GPT-4's output. Rejected is the lower-scoring of the reference or base model output.

**What this tests:** by fixing the chosen system, the experiment controls what the model is being aligned *toward*. If CPO performs well when GPT-4 is the chosen system but poorly when the base model is the chosen system, that reveals that CPO's benefit comes primarily from learning to emulate high-quality external translations, not from learning to distinguish within its own quality range. If SFT is more robust than CPO under chosen system variation, that reveals a fundamental stability difference between the two objectives.

**Why this matters:** in practical scenarios, high-quality external translations (like GPT-4 outputs or gold references) may not always be available. Understanding whether alignment works when the chosen system is the model's own output tests the feasibility of self-improvement—can a model bootstrap its own quality by learning preferences among its own translations?

**Statistical Reporting for Ablations**

In Table 2, values in italic font denote statistically significant differences (at the 5% level, one-tailed paired Student's t-test) between the full "All systems" alignment and the ablated version. This tells the reader which candidate systems have a *reliable* effect on performance, as opposed to random variation.

#### Mono-System Preference Data Optimization Methodology (for Section 5.2)

**The Nine-Dataset Grid**

To investigate how the quality of chosen and rejected options affects post-alignment performance, the paper constructs nine distinct mono-system preference datasets by systematically varying the offset parameters $o_c$ and $o_r$ described earlier. The chosen and rejected qualities are categorized into three groups:

- **Low quality**: the chosen (or rejected) translation is selected close to the base model's own quality level—a small offset $o_c$ (or $o_r$) from $b_i$.
- **Mid quality**: the translation is selected at an intermediate quality distance from the base model.
- **High quality**: the translation is selected far from the base model's quality level—a large offset.

Crossing these three levels for chosen and three levels for rejected produces nine datasets, denoted by the nine points A through I in Figure 1.

**What the nine datasets represent:** each point corresponds to a different *preference data configuration*, defined by the average quality of chosen translations and the average quality of rejected translations in that dataset. For example, point C has "rejected quality: Mid, chosen quality: High," meaning the rejected translations are of intermediate quality (neither very bad nor close to the base model's level) and the chosen translations are of very high quality. The full quality statistics for all nine datasets are provided in Table 11 (Appendix B.1).

**Why a 3×3 grid:** this design enables the paper to test three hypotheses simultaneously: (i) whether higher chosen quality always improves performance (tested by comparing columns of the grid), (ii) whether lower rejected quality always improves performance (tested by comparing rows), and (iii) whether there is an interaction between chosen and rejected quality—i.e., whether the optimal chosen quality depends on the rejected quality level. The grid structure makes these comparisons systematic and interpretable.

**Training and Evaluation on the Nine Datasets**

For each of the nine datasets, a CPO model is trained using the standard configuration ($\beta = 0.1$, rank-16 LoRA, 1 epoch, etc.). Each model is then evaluated on the WMT'22 test set using xCOMET-QE as the evaluation metric. The resulting performance scores are interpolated to produce the contour plot in Figure 1.

**What Figure 1 shows:** the x-axis (A → I points) represents increasing chosen quality (from left to right, across the three columns) and increasing rejected quality (from bottom to top within each column, across the three rows). The bracketed numbers next to each point are the average xCOMET-QE scores on WMT'22 test data for the model trained on that preference configuration. The contour coloring indicates performance levels, with the optimal region highlighted.

**Key findings from the grid (as methodological insights):** the paper identifies three properties of preference data that negatively impact CPO performance:
- Chosen quality that is too low (the model doesn't learn to produce translations much better than its current capability)
- Rejected quality that is extremely low or extremely high (the preference signal is either trivially easy or provides no meaningful contrast)
- Too wide a gap between chosen and rejected qualities (the preference loss term may dominate the SFT term, causing the model to focus on easy distinctions at the expense of learning high-quality generation)

**The optimal configuration:** the paper finds that optimal test performance is obtained with rejected options averaging around 90% of the base model's quality (i.e., $\Delta = -10\%$ below $y_i^{\text{Base}}$) and chosen options averaging around 105% of the base model's quality ($\Delta = +5\%$ above $y_i^{\text{Base}}$). This configuration is denoted "Mono-system (opt.)" in Table 4.

**What this analysis enables:** by mapping the relationship between preference data properties and downstream performance, the paper provides practical guidance for constructing mono-system preference datasets. Rather than simply matching multi-system properties (as in the "multi-system replica" dataset), practitioners can tune the offset parameters to achieve optimal alignment performance for their specific model and metric. The paper does not claim these exact percentages generalize to all settings, but the analytical method—varying chosen and rejected quality systematically—provides a template that can be applied to other models, metrics, and language pairs.

**Connection to the main comparison (Table 4):** the optimized mono-system model achieves xCOMET-QE scores within approximately 0.3 points of the multi-system model while nearly eliminating the adverse chrF effects observed in the multi-system setting (en-xx chrF: 49.11 for optimized mono vs. 47.69 for multi-system CPO). This demonstrates that careful tuning of mono-system preference data can match multi-system performance while providing better metric consistency—the core practical contribution of the mono-system analysis.

#### Design Choice Summary

The paper's technical approach can be understood as systematically varying three factors while holding everything else constant:

1. **Learning objective**: SFT vs. CPO (within each experiment, varying only the loss function)
2. **Candidate system composition**: full multi-system, ablated multi-system, fixed-chosen multi-system, or mono-system (varying the data construction pipeline)
3. **Preference data properties**: quality levels of chosen and rejected options (varying the offset parameters in mono-system construction)

By controlling all other factors—base model (ALMA-13B-LoRA), training hyperparameters (learning rate, epochs, batch size, β), decoding strategy (greedy), evaluation datasets (WMT'22, WMT'23), and evaluation metrics (xCOMET-QE, CometKiwi, chrF)—the paper isolates the effect of each factor on downstream translation quality and metric consistency. The use of statistical significance testing ensures that observed differences are reliable rather than artifacts of sampling noise.

**Why this experimental design over alternatives:** a less controlled design—for example, comparing CPO to MBR decoding or to different base models—would conflate multiple factors and make it impossible to attribute performance differences to the alignment method itself. By constraining all training factors to be identical except the ones under study, the paper achieves high internal validity: differences between SFT and CPO must be due to the preference term, and differences between multi-system and mono-system alignment must be due to the candidate distributions, not to optimization artifacts. This makes the paper's diagnostic conclusions—that CPO introduces adverse metric effects not seen with SFT, and that candidate system choice strongly affects CPO robustness—credible and actionable.

## 4. Key Insights and Innovations

### Innovation 1: The Adverse Metric Effect as a Discovered Phenomenon in Preference-Based Fine-Tuning

The paper's most conceptually significant contribution is the empirical identification and characterization of what we might call the **adverse metric effect**: the finding that CPO-based alignment on a neural metric systematically degrades performance on lexical metrics, even while improving the alignment metric itself. This is not merely a "regression on one metric while improving another" tradeoff—it is an *induced negative interaction* between metric families that does not appear under SFT on the same chosen translations.

What makes this a genuine discovery rather than an expected tradeoff is the **asymmetry** with SFT. Table 1 shows that when xCOMET-QE is the alignment metric, SFT on chosen translations improves en-xx chrF from 49.49 (base) to 50.28 (+0.79), while CPO degrades it to 47.69 (−1.80). Both methods see the same chosen translations during training—the only difference is the addition of a rejected translation in CPO's preference term. The fact that adding a *negative signal* (learning to avoid rejected translations) causes lexical degradation where positive-only learning does not is non-obvious and challenges the implicit assumption that preference optimization is a strict improvement over likelihood-based training.

Prior work in the MT metrics literature had warned about the risks of optimizing against the same metric used for evaluation (Kocmi et al., 2024) and had documented cases where quality-aware decoding strategies like MBR could surface metric weaknesses (Amrhein and Sennrich, 2022). But these observations were in the context of inference-time selection—picking the best candidate from a fixed set according to a metric. The paper extends this concern to *weight-space optimization*: when the model's parameters are updated to maximize a neural metric, the resulting distributional shift can produce translations that score well on neural metrics (which capture semantic adequacy and fluency) but poorly on lexical metrics (which capture surface-form overlap with a reference). This is a more fundamental problem because, unlike decoding strategies, fine-tuning changes the model permanently for all future uses.

The significance of this finding lies in its implications for how the field should evaluate preference-based alignment. It demonstrates that **single-metric evaluation is insufficient**: a paper reporting improved xCOMET-QE after CPO alignment is telling an incomplete story if it doesn't also report lexical metrics. The paper's diagnostic framework—always reporting the alignment metric alongside metrics from different families—should become standard practice. Without it, the community risks optimizing translation models into metric-specific local maxima that look good on the optimized metric but have degraded performance on dimensions that matter to users (like lexical precision, which chrF partially captures).

This insight is **fundamental rather than incremental** because it changes what we mean by "alignment works." Before this paper, success was defined as improvement on the alignment metric. After this paper, success must also account for cross-metric consistency. The adverse metric effect is not a small second-order concern—Table 1 shows it can be larger than the SFT improvement itself (the −1.80 chrF drop under CPO is larger in magnitude than the +0.79 gain under SFT, representing a net swing of −2.59 points relative to what SFT achieves). Dismissing this as "lexical metrics don't matter because neural metrics correlate better with humans" misses the point: the degradation itself reveals something about how CPO shifts the model's generation distribution, and understanding that shift is essential for building robust alignment methods.

---

### Innovation 2: Preference Alignment Sensitivity to Candidate System Composition as a Robustness Diagnostic

The paper's second major intellectual move is reframing candidate system choice—previously treated as an incidental implementation detail in the CPO recipe—as a **first-class experimental variable that reveals fundamental properties of preference optimization**. Through systematic ablation (Tables 2 and 3), the paper demonstrates that CPO is substantially more sensitive to which systems contribute candidates than SFT is, and that this sensitivity is not merely a matter of data quality but reflects a deeper instability in how CPO processes preference signals from heterogeneous sources.

The key evidence for this differential sensitivity is in Table 3. When the chosen system is forced to be the base model itself, CPO fails to outperform SFT (en-xx xCOMET-QE: 91.75 for CPO vs. 91.94 for SFT, both barely above the 91.91 base), meaning CPO's advantage over SFT in the full multi-system setting depends entirely on having access to higher-quality chosen translations from external systems. When the chosen system is forced to be the gold reference, CPO catastrophically underperforms the base model across all metrics—including the alignment metric xCOMET-QE (88.81 → 81.95 for xx-en, a −6.86 drop; 92.75 → 86.97 for en-xx, a −5.78 drop). SFT on the same reference-chosen data shows no such collapse. This is not a gradual degradation but a **qualitative failure mode**: CPO with reference-as-chosen learns something actively harmful to translation quality.

Prior work on preference optimization (Rafailov et al., 2024; Xu et al., 2024a) treated preference data construction as a solved step—collect high-quality chosen translations, collect lower-quality rejected translations, train with CPO/DPO. The multi-system recipe (Base + GPT-4 + Reference) was presented as a working configuration without investigating whether any component was essential or potentially harmful. This paper shows that the recipe is brittle in specific ways: removing GPT-4 causes the largest performance drop (Table 2), and including the reference can be actively harmful when combined with CPO (Table 2, "No Ref" vs. "All systems" for CPO on en-xx chrF: 50.67 vs. 47.69, a +2.98 recovery by removing references). The reference, which has perfect chrF by definition (100.0 in Table 11) but lower neural metric scores than GPT-4, appears to introduce a conflicting signal that CPO handles poorly.

The conceptual significance here is that it **recasts preference alignment from an optimization problem to a data composition problem**. The paper's title—"Is Preference Alignment Always the Best Option?"—is answered partly by showing that the answer depends on *which* candidate systems are available and *how* they are used. The field's default assumption that "more diverse candidate systems produce better preference data" is overturned by the finding that the reference system, despite being the gold standard for translation evaluation, is detrimental in certain CPO configurations.

This insight is **incremental in its specific empirical claims** (it documents sensitivity for one model, one metric family, one CPO variant) but **potentially fundamental in its methodological implications**. If CPO's behavior depends strongly on the distributional properties of candidate translations, then future work on preference alignment must characterize and control these properties, not just maximize the chosen-rejected quality gap. The paper provides a template for this characterization through its ablation and chosen-fixation experiments, establishing a methodology that can and should be applied to other alignment methods, model families, and tasks.

---

### Innovation 3: Mono-System Preference Alignment as a Controlled Alternative with Comparable Performance

The paper's third distinctive contribution is demonstrating that **preference alignment can be effective using only the base model's own outputs**, achieving performance competitive with multi-system approaches while offering two advantages: better metric consistency and fine-grained control over preference data properties. This is not merely "another way to build preference data" but a conceptual reframing of what preference alignment requires.

The standard assumption in prior work (Xu et al., 2024a) was that effective preference alignment needs high-quality external translations to serve as chosen examples—the model cannot bootstrap improvements from its own outputs because its own best translations are still limited by its current capability. The mono-system results in Table 4 directly challenge this: CPO on mono-system data achieves 89.35 xx-en xCOMET-QE vs. 89.95 for multi-system, a gap of only 0.60 points, while nearly eliminating the adverse chrF effect (49.02 vs. 47.69, a recovery of 1.33 points). The optimized mono-system variant narrows the xCOMET-QE gap further to 0.37 points (89.58 vs. 89.95) while maintaining lexical consistency.

What makes this intellectually distinctive is not the performance parity itself but the **control it enables over the alignment process**. Multi-system alignment is fundamentally constrained by whatever external systems happen to be available—the quality gap between chosen and rejected is whatever the candidate pool provides. Mono-system alignment, by contrast, allows explicit tuning of the chosen and rejected quality levels through the offset parameters $o_c$ and $o_r$ (Section 5.2, Figure 1). The paper's nine-dataset grid analysis reveals that the optimal preference data configuration has a specific relationship: rejected quality around 90% of base quality and chosen quality around 105% of base quality. This is a finding about the *structure of useful preference signals*—the model benefits most from learning to distinguish translations that are moderately better and moderately worse than its current output, not from extreme contrasts.

This connects to a broader principle in machine learning: the most informative training examples are often those near the decision boundary, not the easiest or hardest cases. In preference alignment, extremely low-quality rejected translations (chosen/rejected gap too wide) may provide little useful signal because the distinction is trivially easy—the model already strongly prefers the chosen over the rejected. Extremely high-quality chosen translations (from GPT-4) may be hard to learn from because they represent a distribution the base model cannot easily produce. The mono-system framework makes these effects visible and tunable in a way that multi-system approaches, with their fixed candidate pools, cannot.

The significance of this innovation is that it **democratizes preference alignment**. Multi-system alignment requires access to high-quality external translation systems (like GPT-4) or gold references, which may not be available for low-resource languages, specialized domains, or proprietary deployments. Mono-system alignment uses only the model's own sampling capabilities, making it applicable anywhere the base model can generate diverse candidates. The paper's finding that it works almost as well as multi-system alignment (and better on metric consistency) opens preference alignment to a much wider range of practical scenarios.

This is a **fundamental conceptual shift** in how we think about preference data. Prior work implicitly treated preference pairs as needing to come from a "better" source (larger model, human translator) to provide a meaningful training signal. This paper shows that intra-model quality variation—the difference between a model's best and worst samples on the same input—carries sufficient signal for effective alignment, and that this signal can be tuned to avoid the metric-specific degradation that multi-system alignment introduces.

---

### Innovation 4: CPO vs. SFT as a Diagnostic Lens on Preference Learning Dynamics

Throughout the paper, the systematic comparison between CPO and SFT serves as more than a baseline—it functions as a **diagnostic instrument for understanding what the preference term in CPO actually contributes** to model behavior. Every experiment runs both objectives on the same data, and the consistent pattern of results reveals something non-obvious about preference optimization: CPO's preference term does not simply amplify the benefits of SFT but can induce qualitatively different (and sometimes harmful) learning dynamics.

The cleanest evidence for this is in the lexical alignment experiments (Tables 1 and 2). When aligning on chrF, SFT on chosen translations shows roughly stagnant performance (xx-en chrF: 56.97 vs. 58.53 base, a slight −1.56 drop; en-xx chrF: 50.30 vs. 49.49 base, a slight +0.81 gain). This makes sense: the chosen translation in chrF-based preference data is almost always the reference (since the reference has perfect chrF by definition), so SFT on references is essentially standard supervised training on gold data, which doesn't improve chrF because the model was already trained on similar data. CPO on chrF, however, causes catastrophic degradation: xx-en chrF drops to 45.32 (−13.21 from base) and en-xx chrF to 42.50 (−6.99). The model learned to *avoid* something from the rejected translations that caused it to produce worse translations even by the very metric it was aligned to optimize.

This is a **counterintuitive negative result** that reveals something fundamental about CPO: the preference term can backfire when the metric used for ranking is not well-aligned with the model's generation distribution. chrF measures character n-gram overlap with a reference—a surface-form property. When the candidate pool includes GPT-4 translations (which have high chrF but different lexical patterns than the base model) and the base model's own translations (lower chrF), the preference pairs may teach the model to emulate GPT-4's lexical choices at the expense of its own native translation patterns, resulting in translations that score worse on chrF than the original model. SFT on references alone doesn't cause this because it provides no negative signal about what to avoid.

The diagnostic power of the CPO-vs-SFT comparison extends to the chosen-fixation experiments (Table 3). When the chosen system is GPT-4, both SFT and CPO improve over the base model on neural metrics, but CPO degrades more on lexical metrics (en-xx chrF: 50.22 for CPO vs. 50.73 for SFT). When the chosen system is the reference, both methods hold roughly steady under SFT but CPO collapses. This pattern—CPO consistently showing higher variance in outcomes than SFT when the data composition changes—suggests that CPO amplifies whatever properties are present in the preference pairs, for better or worse. When the pairs capture a genuine quality improvement signal (GPT-4 as chosen, base as rejected), CPO amplifies it. When the pairs capture a misleading or harmful signal (reference as chosen with CPO on neural metrics), CPO amplifies that too.

This insight is **methodologically fundamental** for the preference alignment literature. It suggests that evaluating a new preference optimization method should always include an SFT-on-chosen baseline, because differences between CPO and SFT on the same data isolate the contribution of the preference term. A method that outperforms SFT on the alignment metric but underperforms on other metrics is not strictly better—it's making a different tradeoff that may or may not be desirable depending on the deployment context. The paper doesn't resolve this tradeoff but provides the diagnostic framework for identifying and measuring it.

### Innovation 5: Difficulty-Agnostic Metric Interactions as a Complement to Difficulty-Conditioned Compute Allocation

While this paper operates in a different domain (translation quality) than the test-time compute scaling literature, it makes an analogous conceptual move: **identifying that a technique's effectiveness is not uniform across evaluation dimensions, and that ignoring this heterogeneity leads to misleading conclusions.** Where the test-time compute scaling paper showed that beam search helps on medium-difficulty problems but hurts on easy problems (a difficulty-conditioned effect), this paper shows that CPO helps on neural metrics but can hurt on lexical metrics (a metric-family-conditioned effect). Both papers argue that the field's default assumption—"more of this technique is better"—is wrong in predictable, measurable ways.

The connection is not superficial. Both papers identify that the problematic effects (PRM over-optimization in one case, adverse metric effects in the other) share a common mechanism: **optimizing against a proxy that is imperfectly correlated with the true objective**. The PRM is a stand-in for ground-truth correctness; neural metrics like xCOMET-QE are stand-ins for human translation quality judgments. In both cases, aggressive optimization against the proxy can improve proxy-measured performance while degrading performance on dimensions the proxy doesn't capture. The PRM paper's solution was difficulty-conditioned allocation (use less aggressive search where the proxy is unreliable). This paper's solution is structurally similar: use mono-system alignment (which constrains the optimization to stay closer to the base model's distribution) when metric consistency matters.

This places the paper's contribution in a broader intellectual current: the growing recognition that **optimization against learned proxies requires explicit management of proxy failure modes**, whether in test-time compute, RLHF, or metric-based fine-tuning for translation. The paper's specific empirical contribution—documenting exactly which metrics degrade under which CPO configurations—provides a concrete case study of this general principle in the translation domain.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** All experiments use the FLORES-200-based preference dataset from Xu et al. (2024a) for training, containing over 20,000 translation pairs across six languages (English, Czech, German, Icelandic, Russian, Chinese) and ten language directions (five into-English: cs-en, de-en, is-en, ru-en, zh-en; five out-of-English: en-cs, en-de, en-is, en-ru, en-zh). Evaluation is performed on the WMT'22 test set (17,471 source-reference pairs) with additional validation on WMT'23 test data reported in Appendix A. The language statistics in Appendix B.2 (Figures 2 and 3) show English dominates as both source (~51% for preference data, ~52% for WMT'22) and target (~49% for preference data, ~48% for WMT'22) language, with individual language pairs roughly balanced at 5–11% of total samples each.

- **Base model(s).** The base model is ALMA-13B-LoRA (Xu et al., 2023), a fine-tuned LLaMA-2-13B decoder-only LLM optimized for machine translation via continued pretraining on monolingual data followed by supervised fine-tuning on parallel data using LoRA with rank 16. The model is chosen because it represents the state of the art for open-source LLM-based translation and is the identical base model used in the CPO paper (Xu et al., 2024a) that this work systematically analyzes, ensuring direct comparability of results.

- **Metrics.** Three evaluation metrics span two fundamentally different paradigms: xCOMET-QE-XXL (Guerreiro et al., 2023) and CometKiwi-XXL (WMT'23 version, Rei et al., 2023) are reference-free neural metrics trained to predict human quality judgments; chrF (Popović, 2015) is a reference-based lexical metric computing character n-gram F-score overlap with the gold reference. Additionally, Appendix A reports Metric-X-Large (reference-based neural) and BLEU (reference-based lexical). Metrics are reported separately for xx-en and en-xx language direction groups, with green shading indicating improvement over the base model, red indicating degradation, and filled circles (•) marking scenarios where the evaluation metric matches the alignment metric.

- **Baselines.** The primary baseline is Supervised Fine-Tuning (SFT) on chosen translations alone, using the identical training configuration as CPO (same optimizer, learning rate, epochs, batch size) to isolate the effect of the preference term. All aligned models are compared against the unmodified base model (ALMA-13B-LoRA with greedy decoding). The paper does not benchmark against quality-aware decoding strategies (N-best reranking, MBR decoding) or other preference optimization methods (standard DPO), focusing instead on the SFT-vs-CPO comparison as a diagnostic instrument.

- **Generation budget / compute accounting.** At inference time, all models use greedy decoding via the vLLM library for maximum computational efficiency and deterministic output. There is no generation budget to account for because inference produces exactly one translation per source sentence—the paper explicitly contrasts this with quality-aware decoding approaches that generate multiple candidates per input. At training time, all models are fine-tuned for exactly one epoch with batch size 128, making training cost identical across SFT and CPO variants. Training compute is provided by the Jean Zay and Adastra supercomputers (acknowledged).

- **Cross-validation / statistical protocol.** The paper does not use cross-validation for model selection—all models are trained on the full preference dataset and evaluated on held-out WMT test sets. Statistical significance testing uses one-tailed paired Student's t-tests at the 5% significance level, comparing per-sentence metric score differences between model pairs (e.g., CPO vs. SFT, or ablated vs. full candidate pool). In all result tables, values in italic font denote statistically significant differences at this threshold. The paired nature of the test controls for per-sentence difficulty, and the one-tailed variant reflects directional hypotheses (e.g., "CPO outperforms SFT" or "removing a system reduces performance").

### Main Quantitative Results

#### Multi-System Preference Fine-Tuning: CPO vs. SFT Across Alignment Metrics

The headline finding from Table 1 is that CPO consistently outperforms SFT on the alignment metric when optimizing against neural metrics, but introduces adverse effects on non-aligned metrics—particularly lexical metrics in the out-of-English direction—that SFT does not produce.

**Neural alignment improves downstream performance for both methods.** When aligning on xCOMET-QE, SFT improves xx-en xCOMET-QE from 87.80 (base) to 89.13 (+1.33) and en-xx from 91.91 to 92.38 (+0.47). CPO improves these further to 89.95 (+2.15 over base, +0.82 over SFT) for xx-en and 92.75 (+0.84 over base, +0.37 over SFT) for en-xx. The CPO-vs-SFT gaps are statistically significant (italicized in Table 1). For CometKiwi alignment, the same pattern holds: CPO achieves 89.82 xx-en CometKiwi vs. 89.26 for SFT, and 83.64 en-xx vs. 81.93 for SFT. Both methods also improve the *other* neural metric when aligning on one of them—xCOMET-QE alignment boosts CometKiwi scores and vice versa—which the paper hypothesizes "may be the result of high correlation between different neural metrics, as they are typically trained on similar data."

**CPO introduces adverse metric effects not seen with SFT.** The critical finding appears in the en-xx chrF column of Table 1. Under xCOMET-QE alignment, SFT improves en-xx chrF from 49.49 (base) to 50.28 (+0.79), while CPO *degrades* it to 47.69 (−1.80 from base, −2.59 relative to what SFT achieves). Under CometKiwi alignment, the pattern replicates: SFT reaches 50.49 (+1.00), CPO drops to 48.11 (−1.38 from base, −2.38 from SFT). The xx-en direction shows no such adverse effect—chrF remains approximately stable or slightly improved under both methods. This directional asymmetry (adverse effects only in en-xx) is a non-obvious finding that the paper does not fully explain, but which recurs throughout the experiments.

**Lexical alignment fails catastrophically under CPO.** When chrF is the alignment metric (Table 1, bottom rows), SFT on chosen translations shows roughly stagnant performance: xx-en chrF drops slightly from 58.53 to 56.97 (−1.56), en-xx chrF improves marginally from 49.49 to 50.30 (+0.81). These small changes make sense because the chosen translation for chrF-based preferences is almost always the gold reference (which has perfect chrF by definition), so SFT on references is essentially retraining on gold data that the model already learned from. CPO on chrF, however, produces catastrophic degradation: xx-en chrF drops to 45.32 (−13.21 from base), en-xx chrF to 42.50 (−6.99 from base), and neural metrics also collapse (xx-en xCOMET-QE: 78.51 vs. 87.80 base; en-xx: 88.89 vs. 91.91 base). The CPO preference term, when paired with chrF-based rankings, learns actively harmful patterns that degrade performance across all evaluation dimensions.

**Why this matters:** These results directly motivate the paper's central question. If CPO always outperformed SFT across all metrics, the answer to "Is preference alignment always the best option?" would be an unambiguous "yes." Instead, Table 1 shows the answer depends on (a) which metric you care about, (b) which metric you align on, and (c) which translation direction you're evaluating. For a practitioner who values both neural adequacy and lexical precision in out-of-English translation, SFT on neural-preferred translations may be preferable to CPO—it captures most of the neural improvement without the lexical degradation.

#### Sensitivity to Candidate System Composition

Table 2 reports the results of systematically removing individual systems from the multi-system candidate pool, with xCOMET-QE as the alignment metric. The key findings reveal that CPO is more sensitive to candidate system composition than SFT, and that specific systems play different roles depending on the learning objective.

**Removing GPT-4 causes the largest performance drops.** Under SFT, removing GPT-4 ("No GPT-4" in Table 2) reduces en-xx xCOMET-QE from 92.38 (all systems) to 92.33—a negligible change that is not statistically significant. Under CPO, the same removal causes a drop from 92.75 to 92.22 (−0.53), which is statistically significant at the 5% level. This asymmetry—CPO suffering more when the highest-quality system is removed—is consistent across both xx-en and en-xx. GPT-4 provides the strongest chosen translations (see Table 11: average xCOMET-QE of 94.58 for GPT-4 vs. 93.09 for base and 91.84 for reference), and CPO's preference term appears to rely more heavily on this quality signal than SFT does.

**Removing the reference eliminates adverse chrF effects under CPO.** The most striking result in Table 2 concerns the "No Ref" ablation for CPO with xCOMET-QE alignment. In the full "All systems" configuration, CPO degrades en-xx chrF to 47.69 from 49.49 (base). When references are removed from the candidate pool, en-xx chrF recovers to 50.67 (+2.98 from All systems, and now *above* the base model's 49.49). The neural metrics remain essentially unchanged: en-xx xCOMET-QE is 92.44 (No Ref) vs. 92.75 (All systems), a drop of only 0.31 that is not statistically significant. This is a clean dissociation: the reference system is the primary driver of CPO's adverse lexical effects, and removing it nearly eliminates those effects without compromising neural alignment performance.

**Removing the base model has minimal impact.** Under both SFT and CPO, removing the base model's own translations ("No Base") produces results that are statistically indistinguishable from the All-systems configuration for most metrics. This suggests the base model's translations are the least informative component of the preference pairs—the system can learn effectively from the contrast between GPT-4 and the reference alone, without seeing its own outputs.

**The chrF alignment failure is also driven by references.** The bottom rows of Table 2 show that when aligning on chrF, removing references ("No Ref") from the CPO training data eliminates the catastrophic degradation observed in Table 1. Under chrF alignment with CPO, the All-systems configuration produces xx-en chrF of 45.32 and en-xx chrF of 42.50 (Table 1), but the No Ref configuration (Table 2) achieves 60.63 xx-en chrF (+15.31 recovery) and 51.11 en-xx chrF (+8.61 recovery). The neural metrics also recover: xx-en xCOMET-QE goes from 78.51 to 89.26. This confirms that the reference, when used as the chosen system in CPO preference pairs, is the source of the learning failure—the model learns to emulate reference-like translations in ways that CPO's objective amplifies into pathological behavior.

#### Chosen System Fixation Experiments

Table 3 reports performance when the chosen system is forced to a single source (Base, Ref, or GPT-4), with xCOMET-QE as the alignment metric. These experiments reveal that CPO is not robust to which system serves as the alignment target.

**CPO fails to outperform SFT when the base model is the chosen system.** When chosen = Base, SFT achieves 88.17 xx-en xCOMET-QE and 91.94 en-xx—essentially identical to the base model (87.80 and 91.91), as expected when fine-tuning on a model's own greedy outputs. CPO achieves 87.94 xx-en (−0.23 vs. SFT) and 91.75 en-xx (−0.19 vs. SFT). The italic font in Table 3 indicates these CPO-vs-SFT differences are statistically significant in the *negative* direction for three of the six metric-by-direction combinations (xx-en CometKiwi, xx-en chrF, en-xx chrF). CPO not only fails to improve over SFT but slightly degrades performance, demonstrating that CPO's advantage in the full multi-system setting (Table 1) depends entirely on having higher-quality chosen translations from external systems.

**CPO collapses when the reference is the chosen system.** When chosen = Ref, SFT performs normally: 88.04 xx-en xCOMET-QE and 92.35 en-xx, with modest chrF changes. CPO, however, suffers catastrophic degradation: xx-en xCOMET-QE drops to 81.95 (−6.09 from SFT, −5.85 from base), en-xx to 86.97 (−5.38 from SFT, −4.94 from base). Every metric in both directions shows statistically significant degradation (all six CPO entries in the Ref-chosen rows are italicized). This is not a small performance regression but a qualitative failure—CPO with reference-as-chosen learns to produce translations that are worse than the unaligned base model across all evaluation dimensions, including the very metric (xCOMET-QE) that was used to construct the preferences.

**GPT-4 as chosen works well for both methods, but CPO still shows lexical degradation.** When chosen = GPT-4, SFT achieves the highest neural scores in the table (89.81 xx-en xCOMET-QE, 91.96 en-xx) with lexical improvements (60.53 xx-en chrF, 50.73 en-xx chrF). CPO achieves comparable neural scores (89.69 xx-en, 90.50 en-xx) but degrades chrF relative to SFT, particularly in en-xx (50.22 vs. 50.73). The gap is smaller than in the full multi-system setting, suggesting that the adverse lexical effects in Table 1 arise partly from the interaction between multiple candidate systems rather than from GPT-4-chosen pairs alone.

**Broader implication:** These results demonstrate that CPO is not robust to the preference setting in a way that SFT is. SFT on chosen translations behaves predictably across all three fixation conditions—it improves when the chosen translations are high-quality (GPT-4) and stays flat when they match the base model's current quality (Base, Ref). CPO amplifies whatever signal is present: when that signal is genuinely better translations (GPT-4), it amplifies improvement on the alignment metric (but with lexical side effects); when the signal is misleading (Ref with CPO's objective dynamics), it amplifies degradation catastrophically.

#### Mono-System Preference Fine-Tuning: Comparison with Multi-System

Table 4 presents the head-to-head comparison between multi-system and mono-system alignment, with xCOMET-QE as the alignment metric. The mono-system dataset is constructed to approximately replicate the average chosen/rejected quality properties of the multi-system data (rejected xCOMET-QE: 87.80 vs. 87.86; chosen: 97.29 vs. 97.24; see Table 11).

**Mono-system alignment improves over the base model across all neural metrics.** For SFT, mono-system achieves 88.51 xx-en xCOMET-QE (+0.71 over base) and 92.17 en-xx (+0.26 over base). For CPO, mono-system reaches 89.35 xx-en (+1.55 over base) and 92.69 en-xx (+0.78 over base). Both methods produce statistically significant improvements, establishing that effective alignment does not require external systems—the base model's own output distribution contains sufficient quality variation for preference learning.

**CPO consistently outperforms SFT on neural metrics in the mono-system setting.** The mono-system CPO-vs-SFT gaps (89.35 vs. 88.51 for xx-en, 92.69 vs. 92.17 for en-xx) are smaller than in the multi-system setting (89.95 vs. 89.13, 92.75 vs. 92.38) but consistently positive and statistically significant for the alignment metric in both directions. This reinforces the pattern from Table 1: CPO's preference term provides genuine benefit over pure likelihood training, and this benefit persists even when candidate translations come from a single system distribution.

**Mono-system alignment slightly underperforms multi-system on neural metrics, but the gap is small.** The xx-en xCOMET-QE difference is 89.35 (mono CPO) vs. 89.95 (multi CPO), a gap of 0.60 points. For en-xx, it is 92.69 vs. 92.75, a gap of only 0.06 points. The en-xx gap is not statistically significant (not italicized), and the xx-en gap, while significant, is substantially smaller than the improvement over the base model. The paper notes that "having translations from different distributions, particularly from GPT-4, appears to add value for achieving optimized alignment effectiveness," but the value added is modest compared to the gain from alignment itself.

**Mono-system alignment nearly eliminates adverse chrF effects.** This is the most practically significant finding in Table 4. Multi-system CPO degrades en-xx chrF from 49.49 (base) to 47.69 (−1.80). Mono-system CPO achieves 49.02 (−0.47 from base), a recovery of 1.33 points. While still slightly below the base model, this degradation is dramatically smaller than in the multi-system case. The mono-system CPO result (49.02) is not statistically significantly different from the base model at the 5% level (not italicized for chrF in the mono-system rows). For xx-en chrF, mono-system CPO reaches 59.52 vs. 59.83 for multi-system CPO and 58.53 for base—all three values are within a narrow range, with no adverse effect in this direction.

**The optimized mono-system variant matches multi-system performance while preserving metric consistency.** The "Mono-system (opt.)" row in Table 4 shows performance when preference data is constructed with the optimal quality configuration identified in Section 5.2 (Figure 1): rejected quality around 90% of base, chosen quality around 105% of base. This configuration achieves 89.58 xx-en xCOMET-QE (vs. 89.95 multi, gap of 0.37) and 92.87 en-xx (vs. 92.75 multi, actually slightly higher), with en-xx chrF at 49.11 (vs. 47.69 multi, a recovery of 1.42 points). The xx-en xCOMET-QE difference between optimized mono and multi-system is not statistically significant (not italicized), meaning the two approaches are statistically indistinguishable on the alignment metric for into-English translation, while the mono-system approach provides significantly better lexical consistency for out-of-English translation.

#### Mono-System Preference Data Optimization

Figure 1 presents the results of training CPO models on nine preference datasets with systematically varied chosen and rejected quality levels, evaluated on WMT'22 using xCOMET-QE. The figure uses a 3×3 grid of data points (A through I), with the x-axis representing increasing chosen quality and the y-axis (within each column) representing increasing rejected quality.

**The optimal configuration is not at the extremes.** The highest test performance (91.3 xCOMET-QE, point E) is achieved with rejected options at the "Mid" level (around 84.5 average xCOMET-QE, per Table 11) and chosen options at the "Mid" level (around 95.8 average xCOMET-QE). The worst performance in the grid (90.4, point H) occurs with rejected quality at "High" (92.15 average) and chosen quality at "Mid"—a configuration where the quality gap between chosen and rejected is narrow, providing weak preference signal. The paper identifies three specific properties of preference data that negatively impact CPO performance: "(i) a chosen option of too low quality, (ii) an extremely low or high quality of the rejected option, and (iii) too wide a gap between the qualities of the rejected and chosen options."

**Extremely low rejected quality does not help.** Points A, D, and G all have rejected quality at the "Low" level (75.36 average xCOMET-QE, per Table 11). Their test scores (90.9, 90.8, 91.1 respectively) are below the optimal point E (91.3) despite having the widest chosen-rejected gaps. This is non-obvious: one might expect that very low-quality rejected translations would provide the strongest contrastive signal, but the paper finds that "a rejected option of too low quality" is actually detrimental. A possible explanation (not elaborated in the paper) is that extremely poor translations are so obviously flawed that the model learns nothing useful from distinguishing them—the preference loss term saturates quickly because the chosen translation is already vastly more probable than the rejected one.

**Extremely high rejected quality also does not help.** Points C, F, and I have rejected quality at "High" (92.15 average). Their test scores (90.9, 90.7, 90.8) are the lowest in their respective columns, and point H (chosen: Mid, rejected: High) achieves the worst score in the entire grid at 90.4. When the rejected translation is only slightly worse than the base model's output, the preference signal is weak and noisy—the model may struggle to learn a reliable distinction between chosen and rejected translations.

**The optimal quality gap is moderate.** The paper quantifies this as: "rejected options average around 90% (∆ = −10%) of the base model's quality, and chosen options averaging around 105% (∆ = +5%)." This corresponds roughly to point E in Figure 1, which achieves 91.3 test xCOMET-QE. The optimized mono-system model in Table 4 is trained on this configuration and achieves performance statistically indistinguishable from multi-system CPO while maintaining chrF consistency.

**Why this matters beyond the specific numbers:** The 3×3 grid analysis demonstrates that mono-system alignment offers a degree of control over the alignment process that multi-system approaches cannot match. With multi-system data, the quality gap is whatever the external systems happen to provide. With mono-system data, the practitioner can explicitly tune the gap to maximize desired properties—in this case, balancing neural improvement against lexical preservation. The paper does not claim that the exact 90%/105% thresholds generalize to other models or metrics, but the methodology of constructing multiple preference datasets with varying quality parameters and evaluating them on held-out data provides a template for adapting the approach to new settings.

### Ablation Studies and Robustness Checks

**WMT'23 test set replication (Appendix A, Tables 5–8):** All major findings from WMT'22 are replicated on WMT'23 test data. The CPO-vs-SFT advantage on alignment metrics (Table 5), the adverse chrF effects under multi-system CPO (en-xx chrF: 44.29 for CPO vs. 48.38 for SFT), the sensitivity to candidate system removal (Table 6; removing GPT-4 causes the largest neural metric drops, removing references eliminates chrF degradation), the CPO collapse with reference-as-chosen (Table 7; xx-en xCOMET-QE drops to 84.06 from 88.00 base, en-xx to 81.01 from 86.19 base), and the mono-system vs. multi-system comparison (Table 8; optimized mono system achieves 89.36 xx-en xCOMET-QE vs. 89.77 multi, with en-xx chrF at 46.48 vs. 44.29 multi) all replicate the directional patterns. The consistency across two independent test sets substantially strengthens confidence that the observed effects are not artifacts of the specific WMT'22 evaluation data.

**Per-language-pair and additional metric reporting (Appendix A, Tables 9–10):** The paper provides comprehensive per-language-pair breakdowns for WMT'22 (Table 9) and WMT'23 (Table 10), reporting xCOMET-QE, CometKiwi, Metric-X, chrF, and BLEU for all models and configurations. This level of detail is valuable for identifying whether effects are driven by specific language pairs. The tables reveal substantial variation across language pairs—for example, under multi-system xCOMET-QE CPO, en-de chrF drops from 56.95 (base) to 55.95 (−1.00), while en-is drops from 53.31 to 51.70 (−1.61) and en-zh drops from 33.62 to 31.67 (−1.95). The adverse chrF effect appears across all out-of-English pairs, but its magnitude varies, with en-zh and en-is showing larger degradations than en-de or en-cs. This per-language-pair detail is not discussed in the main text but provides evidence that the effect is not an artifact of averaging across heterogeneous directions.

**Preference dataset quality statistics (Appendix B.1, Table 11):** The paper documents the average quality properties for all preference datasets used, including multi-system candidate statistics (GPT-4: 94.58 xCOMET-QE, Base: 93.09, Reference: 91.84; chosen: 97.24, rejected: 87.86 for the vanilla multi-system dataset with xCOMET-QE alignment) and mono-system dataset statistics (from rejected/chosen at 75.36/93.60 for "Low/Low" to 92.15/98.16 for "High/High"). This table is essential for interpreting the optimization results in Figure 1—without it, the exact quality levels corresponding to "Low," "Mid," and "High" would be unknown.

**Neural vs. lexical metric consistency under SFT:** An important negative result that emerges across all tables is that SFT on chosen translations—regardless of which metric induces the preferences—never produces the catastrophic degradations seen with CPO. Even when aligning on chrF (Table 1, SFT rows), where SFT on references produces essentially flat performance, it does not collapse like CPO does. This is a robustness check on CPO itself: the instability is specific to the preference term, not to the data or the training configuration. The paper does not highlight this as a separate ablation, but the consistent SFT behavior across all experiments serves as a implicit control demonstrating that CPO's sensitivity to data composition is a property of the learning objective, not an artifact of the experimental setup.

**Reference system removal as a robustness intervention:** The "No Ref" ablation (Tables 2 and 6) functions as both an analysis tool and a demonstration of a practical fix for CPO's adverse effects. Removing references from the candidate pool restores chrF performance to baseline levels or better (en-xx chrF: 50.67 under xCOMET-QE CPO with No Ref vs. 47.69 with All systems) while preserving neural metric improvements. This ablation shows that the adverse effects are not inherent to CPO but arise from a specific interaction between CPO's objective and the reference's distributional properties (perfect chrF, lower neural metric scores than GPT-4). It also provides a practical recommendation: if lexical consistency matters, exclude gold references from CPO preference data and use only system-generated translations.

**GPT-4 as a necessary but not sufficient component:** The "No GPT-4" ablation (Tables 2 and 6) shows the largest neural metric drops across both SFT and CPO, confirming that GPT-4's high-quality translations are the primary driver of neural alignment improvements. However, GPT-4 alone (with Base, without Ref) does not achieve the full multi-system performance—the All-systems configuration slightly outperforms No Ref on neural metrics, suggesting that even the reference, despite its adverse lexical effects, contributes marginally to neural alignment. This is a nuanced finding: the reference is simultaneously helpful (for neural alignment) and harmful (for lexical preservation), and its net effect depends on which evaluation dimension is prioritized.

**CometKiwi alignment produces similar patterns to xCOMET-QE alignment:** Throughout the experiments, alignment on CometKiwi (Tables 1, 5, and per-metric rows in other tables) yields results qualitatively identical to alignment on xCOMET-QE: CPO outperforms SFT on the alignment metric, adverse chrF effects appear in en-xx under CPO, and the mono-system approach mitigates these effects. The two neural metrics are sufficiently correlated (both trained to predict human judgments) that alignment on one generalizes to the other, suggesting that the paper's findings are not specific to xCOMET-QE but apply to reference-free neural metrics more broadly.

**chrF alignment under CPO with references removed:** When references are excluded from chrF-aligned preference data (Table 2, "Preferences induced with chrF, No Ref"), CPO performance recovers dramatically: xx-en chrF reaches 60.63 (vs. 45.32 with All systems) and en-xx chrF reaches 51.11 (vs. 42.50 with All systems). Neural metrics also recover: xx-en xCOMET-QE is 89.26 (vs. 78.51 with All systems). This ablation confirms that the CPO-with-chrF failure mode is specifically caused by the inclusion of references (which have perfect chrF and become the chosen translation by definition). When chrF-based preferences are constructed from system outputs only (Base and GPT-4), CPO works effectively and even improves neural metrics—a non-obvious finding that challenges the simple narrative that "CPO doesn't work with lexical metrics."

### Critical Assessment

#### Does the paper demonstrate that CPO outperforms SFT on the alignment metric?

Yes, but with an important scope limitation. The advantage holds for neural metrics (xCOMET-QE, CometKiwi) in both xx-en and en-xx directions, with CPO achieving statistically significant improvements of roughly 0.4–0.8 points over SFT on the alignment metric in the multi-system setting (Table 1). The advantage persists in the mono-system setting (Table 4), though the gap narrows. However, this advantage is demonstrated only for ALMA-13B-LoRA with LoRA fine-tuning at rank 16 for one epoch with β = 0.1. The paper does not test whether CPO's advantage over SFT varies with training duration (more epochs), model scale (7B vs. 13B vs. larger), LoRA rank, or β values. An experiment varying β across, say, {0.05, 0.1, 0.5, 1.0} would reveal whether CPO's advantage is robust to this hyperparameter or specific to the DPO-default value. Additionally, the paper does not test whether the CPO-vs-SFT gap widens or narrows when training for multiple epochs—the single-epoch design, while practical, leaves open the possibility that SFT would catch up with CPO given more training.

#### Does the paper demonstrate that CPO introduces adverse metric effects?

Yes, and this is the most robustly supported claim in the paper. The adverse chrF effects in en-xx under multi-system CPO with neural alignment appear in Table 1 (en-xx chrF: 47.69 for xCOMET-QE CPO vs. 50.28 for SFT), replicate in the WMT'23 data (Table 5: 44.29 vs. 48.38), and hold across CometKiwi alignment (Tables 1 and 5). The effect is directional—appearing in en-xx but not xx-en—which the paper documents but does not attempt to explain mechanistically. A missing analysis that would strengthen this claim is a qualitative examination of *how* the translations change: do CPO-aligned models produce shorter translations (reducing chrF by reducing n-gram overlap opportunities), or do they use different lexical choices (different vocabulary distribution), or do they restructure sentences syntactically? Without such analysis, we know that chrF drops but not why—and understanding the "why" is essential for designing fixes. Additionally, the paper does not assess whether the chrF degradation corresponds to genuine quality degradation or to a shift toward translations that are semantically adequate but lexically divergent from the reference—a distinction that would require human evaluation.

#### Does the paper demonstrate that candidate system choice affects alignment performance?

Yes, with strong evidence from the ablation experiments. Removing GPT-4 causes the largest neural metric drops (Table 2, en-xx xCOMET-QE CPO: 92.22 No GPT-4 vs. 92.75 All systems, significant at 5% level). Removing references eliminates adverse chrF effects (en-xx chrF CPO: 50.67 No Ref vs. 47.69 All systems, a recovery of +2.98). The chosen-fixation experiments (Table 3) provide even stronger evidence: CPO with reference-as-chosen causes catastrophic collapse across all metrics, while SFT on the same data does not. However, the paper tests only one multi-system composition (Base + GPT-4 + Ref). A more thorough analysis would vary the external system—for example, replacing GPT-4 with Claude, or using a different open-source model, or testing with two different LLMs of varying quality levels. This would reveal whether the sensitivity is to GPT-4 specifically, to "a model much stronger than the base model" generally, or to the diversity of system origins. The current design demonstrates sensitivity to *this specific* candidate pool but cannot distinguish between these hypotheses.

#### Does the paper demonstrate that mono-system alignment achieves performance comparable to multi-system alignment?

The paper demonstrates that mono-system CPO achieves performance statistically indistinguishable from multi-system CPO on the alignment metric for en-xx (92.69 vs. 92.75, Table 4), and that the gap for xx-en, while statistically significant, is small (89.35 vs. 89.95, a difference of 0.60 points). The optimized mono-system variant narrows the xx-en gap further to 0.37 points (89.58 vs. 89.95), which is not statistically significant. This is a convincing demonstration, but it is limited to the specific base model (ALMA-13B-LoRA), specific sampling parameters (top-p = 0.6, temperature = 0.9, K = 50 candidates), and specific alignment metric (xCOMET-QE). The paper does not test whether mono-system alignment would remain competitive with multi-system alignment for a weaker base model (where the quality range of self-generated candidates might be narrower) or for a stronger base model (where external systems might provide less marginal benefit). The K = 50 setting is also not ablated—would 25 candidates suffice? Would 100 candidates enable mono-system to match or exceed multi-system? These missing experiments limit the generalizability of the "comparable performance" claim.

#### Does the paper demonstrate that mono-system alignment offers better metric consistency?

The evidence is clear for the specific metrics tested. Multi-system CPO degrades en-xx chrF by 1.80 points (Table 4, 47.69 vs. 49.49 base), while mono-system CPO degrades it by only 0.47 points (49.02 vs. 49.49 base), a 74% reduction in the adverse effect. The optimized mono-system variant further reduces the degradation to 0.38 points (49.11 vs. 49.49). However, the paper evaluates metric consistency only through aggregate chrF scores. A more rigorous consistency analysis would examine per-sentence metric correlations—do sentences that improve on xCOMET-QE systematically degrade on chrF under CPO, and is this correlation weaker under mono-system alignment? Without per-sentence analysis, aggregate scores can mask compensating effects (some sentences improving, others degrading) that might have different practical implications than uniform small degradation. Additionally, the paper tests consistency only between neural metrics and chrF; consistency with other lexical metrics (BLEU, METEOR), with other neural metrics (BLEURT, Metric-X in reference-based mode), and with human judgments is not assessed.

#### What experiments would have strengthened the paper?

**Human evaluation.** The paper relies entirely on automatic metrics to assess translation quality. This is standard practice in MT research, but given the paper's central claim that CPO's metric improvements may not reflect genuine quality improvements across all dimensions, human evaluation of a sample of translations (particularly those showing large metric divergences between SFT and CPO) would substantially strengthen the argument. If human raters confirm that CPO-aligned translations are genuinely better on adequacy/fluency but worse on lexical precision, the adverse metric effects become a genuine quality tradeoff rather than a potential metric artifact.

**Training budget ablations.** The paper trains all models for exactly one epoch. Varying the number of epochs (e.g., 0.5, 1, 2, 4) would reveal whether the CPO-vs-SFT gap and the adverse chrF effects are stable over training or emerge only after a certain amount of optimization. If the adverse effects worsen with more training (as the model increasingly exploits the preference signal), that would strengthen the argument that CPO's preference term is the causal mechanism. If they appear immediately and stabilize, that would suggest a different dynamic.

**β parameter sensitivity.** CPO uses β = 0.1 from the DPO paper without tuning. Testing β values across a range (e.g., 0.01, 0.05, 0.1, 0.5, 1.0) would reveal whether the adverse effects are specific to this β choice. A larger β (stronger preference signal) might amplify both the alignment improvement and the adverse effects, while a smaller β might reduce both, essentially interpolating between CPO and SFT. Such analysis would provide practical guidance for practitioners balancing alignment effectiveness against metric consistency.

**Multiple base models.** All experiments use ALMA-13B-LoRA. Testing with ALMA-7B, Tower-13B (Alves et al., 2024), or other LLM-based translation models would test whether the observed effects are model-specific or general properties of CPO alignment for translation. Given that ALMA-13B-LoRA is fine-tuned from LLaMA-2-13B, which itself has specific pretraining properties, the findings might not transfer to models with different architectures or pretraining data.

**Direct comparison to quality-aware decoding.** The paper positions itself relative to decoding-based quality injection methods (MBR, N-best reranking) but never directly compares CPO-aligned models to base models augmented with decoding strategies. A FLOPs-matched or latency-matched comparison—for example, CPO with greedy decoding vs. base model with best-of-8 MBR decoding—would contextualize the practical value of preference alignment relative to inference-time alternatives. The paper states (Section 2.2) that fine-tuning "shifts the objective from selecting the best candidate translation according to a metric at inference time to directly updating model weights," but does not evaluate whether this shift is net-beneficial in realistic deployment scenarios with compute constraints.

**Qualitative analysis of adverse effects.** The paper provides per-language-pair metric breakdowns (Appendix A) but no examples of translations that improve on neural metrics while degrading on lexical metrics. A qualitative analysis showing, for instance, that CPO-aligned en-de translations use different German compounds that preserve meaning but reduce character n-gram overlap with the reference would make the adverse effect concrete and interpretable. Without examples, the reader cannot assess whether the chrF degradation corresponds to genuine lexical deterioration or a benign distributional shift.

#### What claims hold conditionally, and what are the precise conditions?

**CPO outperforms SFT on the alignment metric** holds for neural metrics (xCOMET-QE, CometKiwi) with ALMA-13B-LoRA at β = 0.1, one training epoch, and the multi-system or mono-system candidate pools tested. It does not hold for lexical metrics (chrF), where CPO underperforms SFT and degrades below the base model. It may not hold for different β values, more training epochs, or different base models, which were not tested.

**CPO introduces adverse lexical effects** holds for en-xx translation directions under multi-system neural alignment with references in the candidate pool. It does not hold for xx-en directions (where chrF is stable or improved) or when references are removed from the candidate pool (No Ref ablation). It may not hold for other lexical metrics beyond chrF, though the per-language-pair BLEU scores in Appendix A suggest similar patterns.

**Candidate system choice affects alignment performance** holds for the specific systems tested (Base, GPT-4, Ref) with xCOMET-QE and chrF alignment. The finding that removing GPT-4 causes the largest neural metric drops is specific to GPT-4 being the highest-quality system in the pool—if a different system were highest-quality, the pattern would presumably shift to that system. The finding that references cause adverse effects under CPO is specific to references having properties (perfect chrF, lower neural metric scores than GPT-4) that create conflicting signals for CPO's preference term.

**Mono-system alignment achieves comparable performance to multi-system** holds for ALMA-13B-LoRA with K = 50 top-p-sampled candidates, evaluated on the alignment metric xCOMET-QE. The "comparable" claim is strongest for en-xx (where differences are not statistically significant) and slightly weaker for xx-en (where the 0.60-point gap is significant but small). It holds for the optimized mono-system configuration in both directions (no significant difference from multi-system). It may not hold for weaker base models (whose self-generated candidate quality range might be narrower) or for substantially different sampling parameters.

**Mono-system alignment offers better metric consistency** holds for the en-xx chrF metric under xCOMET-QE alignment, where mono-system CPO reduces chrF degradation by approximately 74% compared to multi-system CPO. It has not been tested for other lexical metrics, other language directions, or other neural alignment metrics beyond xCOMET-QE (though CometKiwi alignment patterns in Appendix A are consistent).

## 6. Limitations and Trade-offs

### The Difficulty Estimation Cost Is Unaccounted for in the Efficiency Claims

**The assumption or constraint.** The paper frames mono-system alignment as providing "better metric consistency" and "comparable performance" to multi-system alignment while requiring only the base model's own outputs. However, the mono-system approach incurs a substantial upfront computational cost that is nowhere included in any efficiency accounting. For each of the 20,000+ training samples, the paper generates `K = 50` candidate translations using top-p sampling with `p = 0.6` and temperature `τ = 0.9`, then scores all 50 candidates with the alignment metric (xCOMET-QE) to determine quality rankings before constructing preference pairs. This means that **building the mono-system preference dataset requires 50× more inference calls and neural metric evaluations than the multi-system approach** (which uses only 3 candidates per sample). The paper never quantifies this cost, nor does it include it in any comparison with multi-system alignment. The cost is acknowledged only implicitly, through the description of the procedure in Section 3.1.

**The consequence.** In a realistic deployment scenario, the total computational cost of mono-system alignment is: (cost of generating 50 candidates per source sentence) + (cost of scoring all candidates with a neural metric) + (cost of CPO training). For the multi-system approach, the cost is: (cost of obtaining GPT-4 translations, which may involve API fees) + (cost of base model inferences, typically 1 per sample) + (cost of scoring 3 candidates) + (cost of CPO training). The paper's finding that mono-system alignment "achieves performance comparable to using multiple external systems" (Section 5.1) is evaluated purely on downstream metric quality, not on total resource expenditure. A practitioner deciding between the two approaches would need to weigh the one-time cost of generating 50 samples × 20,000 sentences (= 1,000,000 inference calls, plus 1,000,000 neural metric evaluations) against the alternative cost of accessing external systems like GPT-4. For a model like ALMA-13B-LoRA running on academic GPU clusters, generating 1M translations at 50 candidates each is non-trivial; for a production deployment with larger models, it may be prohibitive.

Furthermore, the optimized mono-system variant (Section 5.2) requires constructing and evaluating **nine separate preference datasets** to find the optimal chosen/rejected quality configuration. This multiplies the already-high data construction cost by a factor of up to 9×, depending on whether the nine datasets share candidate generation (they likely do, since the same 50 candidates per sentence can be re-paired with different offsets). Even with sharing, the grid search over offset parameters is an expensive hyperparameter optimization procedure that the paper's headline results do not account for.

**What evidence exists in the paper.** The paper provides the statistics for the nine mono-system datasets in Appendix B.1 (Table 11), confirming the 50-candidate generation procedure and the grid search methodology. However, no FLOPs count, GPU-hour estimate, or wall-clock time measurement is reported anywhere. The paper states that "Training compute was provided by the Jean Zay supercomputer" and the Adastra supercomputer, but does not break down how much was used for data construction versus model training. The efficiency comparison in Table 4 reports only downstream metric scores, not total resource expenditure.

**Mitigation status.** The paper does not address this limitation at all. It does not recommend reducing `K` (e.g., testing whether 10 or 25 candidates suffice), does not propose amortizing the candidate generation cost across multiple alignment metrics or multiple training runs, and does not compare total FLOPs or wall-clock time between mono-system and multi-system pipelines. A practitioner reading the paper would need to estimate these costs independently before adopting the mono-system approach. The paper also does not discuss whether the 50 candidates generated during preference data construction could be reused for other purposes (e.g., as additional SFT training data, or for ensembling), which might partially offset the cost.

---

### All Results Are on a Single Model Family and a Single Model Scale

**The assumption or constraint.** Every experiment in the paper uses **ALMA-13B-LoRA** as the base model—a fine-tuned version of LLaMA-2-13B that was optimized for translation via continued pretraining and supervised fine-tuning with LoRA (Xu et al., 2023). The paper states (Section 3.1) that this model was chosen because it is "the base model we aim to align" and is the identical model used in the CPO paper (Xu et al., 2024a). No other model architectures, model scales, or pretraining paradigms are tested. The paper does not evaluate with ALMA-7B, Tower-13B (Alves et al., 2024), LLaMA-3-based translation models, or any encoder-decoder NMT system for comparison.

**The consequence.** Several of the paper's central findings could be specific to ALMA-13B-LoRA's particular properties. First, **the adverse chrF effect under CPO** may depend on the base model's output distribution—ALMA-13B-LoRA was fine-tuned on parallel data, which likely biases its translations toward reference-like lexical patterns. CPO alignment on neural metrics pushes the model away from this distribution, causing the observed chrF drop. A model with different pretraining (e.g., a base LLM fine-tuned with less emphasis on parallel data) might show different sensitivity to the CPO preference term, potentially larger or smaller adverse effects. Second, **the optimal mono-system quality configuration** (rejected at ~90% of base quality, chosen at ~105%) is almost certainly model-specific—a weaker model might have a narrower self-generated quality range, making it harder to construct preference pairs with a meaningful quality gap, while a stronger model might saturate with less benefit from alignment. Third, **the CPO-vs-SFT gap** may vary with model scale—larger models might benefit more from the preference term (because they have more capacity to learn the distinction) or less (because their SFT baseline is already stronger). Fourth, **the sensitivity to candidate system composition** (Tables 2 and 3) depends on the quality gap between the base model and the external systems (GPT-4, references). If the base model were stronger (e.g., GPT-4-level translation quality), external systems would provide less marginal benefit, and mono-system alignment might match or exceed multi-system alignment without optimization. If the base model were weaker, external systems might be essential because the model's own outputs lack sufficient high-quality examples.

**What evidence exists in the paper.** The paper provides no evidence across model families or scales. The Acknowledgments section mentions compute grants from Jean Zay and Adastra supercomputers, suggesting that experiments were resource-constrained, but the paper does not discuss model scale as a limitation. The choice of ALMA-13B-LoRA is well-justified for comparability with prior work, but the paper does not acknowledge that this choice bounds the generality of its conclusions.

**Mitigation status.** The paper does not address this limitation. The Limitations section (at the end of the paper) acknowledges that "Future experiments could benefit from validating our findings using different model families," but this is framed as a future direction rather than a constraint on the current claims. The paper consistently presents its findings as general statements about CPO alignment (e.g., "preference-based alignment, specifically using CPO, globally outperforms SFT on high-quality data in terms of improving neural evaluation metrics" in the Conclusion), without qualifying that this has been demonstrated only for a single 13B-parameter model with a specific fine-tuning history. A more cautious formulation would specify that the findings are demonstrated for ALMA-13B-LoRA and may or may not transfer to other models.

---

### The Mono-System vs. Multi-System Comparison Is Not Compute-Matched

**The assumption or constraint.** The paper compares multi-system and mono-system alignment using the same CPO training configuration (one epoch, batch size 128, identical optimizer and learning rate) and evaluates both on downstream metrics. However, the two approaches differ fundamentally in the **amount and diversity of information** provided to the model during training, and no attempt is made to equalize total computational cost, training data volume, or information content. The multi-system approach provides the model with translations from three distinct distributions (base model, GPT-4, human references) with a wide quality range and diverse translation strategies. The mono-system approach provides translations from a single distribution (the base model's own outputs) with a narrower quality range. These are not matched on any dimension except the number of preference pairs seen during training. A fairer comparison might give the mono-system approach more training epochs, a larger batch size, or additional synthetic data to compensate for its narrower information source.

**The consequence.** The paper's headline finding—that mono-system alignment "achieves performance comparable to using multiple external systems" (Section 5.1)—is based on a comparison where the multi-system approach has an **information advantage** (access to GPT-4's high-quality translations and human references) but does not fully exploit it, while the mono-system approach has an **unaccounted cost advantage** (no need for external APIs or reference translations). The comparison confounds two factors: the alignment method and the data source. If the multi-system approach were given equivalent total compute (e.g., by generating more preference pairs from the same three-system pool, or by augmenting with additional base model samples), the performance gap might widen. Conversely, if the mono-system approach were restricted to the same number of candidate translations as the multi-system approach (3 candidates instead of 50), the performance gap might widen in the opposite direction.

The paper does not establish whether the mono-system approach's performance is due to the larger number of candidates (50 vs. 3) providing a better estimate of the quality distribution, or due to the single-distribution property reducing metric conflicts, or both. This makes it impossible to determine whether the mono-system approach would remain competitive under a more stringent compute-matched comparison.

**What evidence exists in the paper.** Table 4 reports the direct comparison, but the only control for data volume is that both approaches train for one epoch with batch size 128—the same number of gradient updates, but on different data. Table 11 (Appendix B.1) shows that the mono-system "multi-system replica" dataset was explicitly constructed to match the average chosen/rejected qualities of the multi-system data (rejected xCOMET-QE: 87.80 mono vs. 87.86 multi; chosen: 97.29 vs. 97.24), confirming that the paper attempted to control for *quality gap* but not for *total information content*. The paper does not report the number of valid preference pairs in each dataset (some multi-system samples may be discarded when the chosen system fixation experiments leave no valid rejected candidate), making it impossible to compare exact training data volumes.

**Mitigation status.** The paper does not address the compute-matching issue. The Limitations section (at the end of the paper) suggests that "Future experiments could benefit from validating our findings using different model families, a broader range of alignment and evaluation metrics, and additional translation datasets," but does not mention the need for compute-matched or information-matched comparisons. The paper's framing of mono-system alignment as a practical alternative implicitly assumes that external system access is the primary cost, but it does not analyze the total cost structure or propose a fair comparison methodology.

---

### No Human Evaluation of Translation Quality, Despite Central Claims About Metric Tradeoffs

**The assumption or constraint.** All evaluation in the paper is conducted using automatic metrics: xCOMET-QE, CometKiwi, chrF, Metric-X, and BLEU. The paper's central claim—that CPO introduces "adverse metric effects" and that mono-system alignment offers "better metric consistency"—is entirely grounded in automatic metric scores. At no point does the paper validate whether the observed metric degradations correspond to genuine quality degradations as perceived by human evaluators, or whether the metric improvements correspond to genuine quality improvements.

**The consequence.** The interpretation of the "adverse metric effect" depends critically on what chrF measures and whether it matters to end users. If CPO-aligned translations are semantically adequate, fluent, and preferred by human raters, but happen to use different lexical choices that reduce character n-gram overlap with the reference, then the chrF drop is a **benign measurement artifact**—the metric is penalizing valid translations that diverge from the reference's surface form. In this scenario, the paper's warning about adverse effects would be misleading; mono-system alignment's "better metric consistency" would be preserving a metric that does not reflect genuine quality. Conversely, if the chrF drop reflects genuine degradation (e.g., the model produces shorter, less precise, or lexically inappropriate translations), then the adverse effect is a real quality tradeoff that practitioners need to manage.

The paper provides no evidence to distinguish these two scenarios. The neural metrics (xCOMET-QE, CometKiwi) are trained to predict human judgments, so their improvement under CPO suggests that CPO-aligned translations are likely better by human standards. But neural metrics are imperfect proxies—they have their own biases and failure modes—and the paper's own finding that aligning on neural metrics can degrade chrF demonstrates that metrics can move in opposite directions. Without human evaluation, we cannot determine which metric's movement better reflects true translation quality.

This gap is particularly significant for the paper's practical recommendations. If the chrF drop is benign, practitioners should prefer CPO with multi-system alignment (highest neural metric scores) and ignore the lexical metric degradation. If the chrF drop reflects genuine quality loss, practitioners face a real tradeoff and might prefer mono-system alignment or SFT. The paper's framing implies the latter (that metric consistency is valuable), but this implication is unvalidated.

**What evidence exists in the paper.** The paper provides extensive automatic metric results (Tables 1–10, Figures 1) but no human evaluation data. The Conclusion states that "careful consideration must be given to the choice of candidate translations, the learning objective, and the potential trade-offs regarding downstream metric consistency," which assumes the tradeoffs are real. The Ethics Statement mentions that "future work could benefit from additional human evaluation," acknowledging this gap. The paper does not report inter-metric correlations (e.g., Kendall's τ between chrF changes and xCOMET-QE changes at the sentence level), which would provide some insight into whether the metrics are moving together or diverging systematically.

**Mitigation status.** The paper explicitly acknowledges this limitation in the Limitations section: "our evaluation relied on automatic metrics, both lexical and neural, with the latter closely approximating human judgments but still being unable to fully replace them. Given their imperfect correlation with human preferences, future work could benefit from additional human evaluation of outputs obtained via the approaches we studied to get an even deeper understanding of post-alignment downstream performance dynamics." However, this acknowledgment comes at the end of the paper and does not affect how the main results are presented or interpreted. The paper's conclusions treat automatic metric scores as proxies for translation quality without caveating that the relationship between metric scores and human judgments may itself shift when models are optimized against those metrics (a form of Goodhart's law).

---

### The Adversarial ChrF Effect Appears Only in Out-of-English Translation and Is Unexplained Mechanistically

**The assumption or constraint.** The paper documents that the "adverse metric effect"—CPO on neural metrics degrading chrF—appears **primarily or exclusively in the out-of-English (en-xx) direction**. In Table 1, xx-en chrF under xCOMET-QE CPO is 59.83, essentially unchanged from the base model's 58.53 and comparable to SFT's 59.82. In en-xx, chrF drops from 49.49 (base) to 47.69 (CPO), a statistically significant degradation of −1.80 points. This directional asymmetry persists across CometKiwi alignment (xx-en chrF: 60.22 for CPO vs. 60.01 for SFT, essentially flat; en-xx chrF: 48.11 for CPO vs. 50.49 for SFT, a clear degradation) and across the candidate system ablations (Table 2). The paper reports this asymmetry but provides **no mechanistic explanation** for why CPO affects translation into English differently from translation out of English.

**The consequence.** Without understanding the mechanism, practitioners cannot predict whether the adverse effect will appear in their specific use case. If the mechanism is related to the base model's asymmetric translation capabilities (LLaMA-2 was pretrained primarily on English data, potentially making it better at generating English than other languages), then the effect might be specific to English-centric models and would not appear in models with different language distributions. If the mechanism is related to chrF's sensitivity to target-language morphology (character n-gram overlap may be a stricter constraint for morphologically rich target languages like Czech, German, or Russian than for English), then the effect might be metric-specific rather than quality-specific. If the mechanism is related to the preference data composition (the multi-system candidate pool may contain higher-quality English translations from GPT-4 than non-English translations), then the effect might be an artifact of the specific candidate systems used.

The asymmetry also complicates the paper's practical recommendations. A practitioner translating into English (xx-en) might reasonably conclude from Table 1 that CPO with multi-system neural alignment is strictly beneficial—it improves neural metrics without damaging chrF. A practitioner translating out of English (en-xx) faces the tradeoff the paper highlights. The paper's conclusion that "preference-based alignment techniques hold promise for improving MT quality" but require "careful consideration" is direction-agnostic, yet the evidence suggests the considerations are direction-specific.

**What evidence exists in the paper.** The directional asymmetry is visible in every table that disaggregates xx-en and en-xx results (Tables 1–10). The per-language-pair breakdowns in Appendix A (Tables 9–10) confirm that the en-xx chrF degradation appears across all five out-of-English directions (en-cs, en-de, en-is, en-ru, en-zh), though with varying magnitude. The paper notes the asymmetry in Section 4.1: "aligning with CPO also introduces adverse effects between neural and lexical metrics for out-of-English translations." But it offers only an implicit explanation through the candidate system ablation—removing references from the candidate pool (No Ref, Table 2) restores en-xx chrF, suggesting references are involved in the mechanism. However, why references specifically harm en-xx but not xx-en remains unexplained.

**Mitigation status.** The paper does not attempt to explain the directional asymmetry beyond documenting it and showing that removing references mitigates it. The Limitations section does not mention this as an open question. A deeper investigation—for example, comparing the distribution of reference quality across language directions, analyzing whether CPO changes translation length differently in en-xx vs. xx-en, or measuring whether the base model's confidence differs by direction—would be needed to diagnose the mechanism. The paper's practical recommendation (use mono-system alignment to preserve chrF) works empirically for en-xx but does not address the underlying question of whether the chrF degradation is a genuine quality issue or a benign metric artifact, which the directional asymmetry makes more pressing (why would genuine quality degradation only happen in one direction?).

---

### The Reference System's Dual Role (Helpful for Neural Alignment, Harmful for Lexical Preservation) Is Not Resolved

**The assumption or constraint.** The paper's ablation experiments reveal that the gold reference plays a **contradictory role** in CPO alignment: removing references from the multi-system candidate pool eliminates the adverse chrF effect (Table 2, en-xx chrF: 50.67 No Ref vs. 47.69 All systems, a recovery of +2.98) while preserving most of the neural metric improvement (en-xx xCOMET-QE: 92.44 No Ref vs. 92.75 All systems, a drop of only 0.31, not statistically significant). At the same time, the All-systems configuration (which includes references) achieves the highest neural metric scores in most settings—the reference appears to contribute marginally to neural alignment even though it is the primary driver of lexical degradation. The paper documents this dual role but provides **no framework for deciding whether to include references** in a given deployment scenario.

**The consequence.** The reference's dual role creates an unresolved tradeoff for practitioners constructing CPO preference data. Including references provides a small boost to neural metric alignment (approximately 0.3 xCOMET-QE points in en-xx, Table 2) at the cost of a substantial chrF degradation (approximately 3 chrF points in en-xx). Whether this tradeoff is worthwhile depends on the application: if the translation system is evaluated primarily on neural metrics (increasingly common in MT research and shared tasks), the reference's marginal neural benefit might justify its inclusion. If the system is deployed where lexical precision matters (e.g., technical translation, terminology-constrained domains), the chrF degradation might be unacceptable. The paper does not provide guidance for making this decision, nor does it explore whether there exists a middle ground—for instance, including references only for a subset of training samples, or downweighting reference-derived preference pairs during CPO training.

The deeper issue is that the paper identifies the reference as a **confounding variable** in CPO alignment but does not explain *why* it is confounded. The reference has two relevant properties: (1) it has perfect chrF by definition (100.0, per Table 11), making it the chosen translation under chrF-based preferences and a strong chrF signal under neural-based preferences; (2) it has lower neural metric scores than GPT-4 (91.84 xCOMET-QE vs. 94.58 for GPT-4, per Table 11), making it more likely to be the rejected translation under neural-based preferences when GPT-4 is present. These properties interact with CPO's objective in complex ways—when the reference is chosen (because no higher-neural-scoring candidate exists for that sample), the model is forced to emulate reference-like translations, which may improve chrF but potentially at odds with the neural preference signal. When the reference is rejected (because GPT-4 scores higher), the model is taught to *avoid* reference-like properties, which may improve neural scores but degrade chrF. The paper's aggregate results reflect the net effect of these sample-level dynamics, but without per-sample analysis, the mechanism remains opaque.

**What evidence exists in the paper.** The No Ref ablation (Tables 2 and 6) provides the cleanest evidence for the reference's dual role. The chosen-fixation experiments (Tables 3 and 7) provide corroborating evidence: when the reference is forced as the chosen system, CPO collapses across all metrics (xx-en xCOMET-QE drops from 87.80 base to 81.95 under CPO, Table 3), confirming that the reference as an alignment target is harmful. When the reference is absent from the candidate pool, this harmful dynamic is removed. However, the paper does not analyze the *frequency* with which the reference serves as chosen vs. rejected in the All-systems configuration, which would quantify how often each dynamic occurs.

**Mitigation status.** The paper does not resolve this tradeoff. It demonstrates empirically that removing references mitigates the adverse chrF effect, but it does not recommend doing so unconditionally—the Conclusion does not mention reference removal as a practical guideline. Instead, the paper frames mono-system alignment as the primary solution to metric consistency issues, which sidesteps the reference question entirely (mono-system data has no references by construction). For practitioners who have access to references and want to use multi-system alignment, the paper provides evidence that references are problematic but no decision framework for whether to keep or discard them. A more complete treatment would analyze the reference's contribution at the per-sample level, identify the conditions under which it helps vs. harms, and propose a filtering strategy (e.g., include references only when their neural metric score is above some threshold relative to other candidates).

## 7. Implications and Future Directions

### How This Work Changes the Landscape

This paper does not propose a new algorithm, but it makes a **methodological intervention** that shifts how the field should evaluate preference-based alignment for machine translation. Before this work, the CPO recipe from Xu et al. (2024a)—multi-system candidate generation, CPO training, evaluation on the alignment metric—represented a seemingly solved pipeline: follow the recipe, report improved xCOMET-QE or CometKiwi scores, and conclude that preference alignment works. This paper demonstrates that this evaluation protocol is **incomplete in a specific, measurable way** and that the recipe itself is **brittle in ways that were invisible under single-metric evaluation**.

The magnitude of this intervention is **diagnostic rather than paradigmatic**. The paper does not overturn the finding that CPO improves alignment metrics—it consistently replicates it. What it overturns is the *interpretation* of that improvement as an unqualified good. The adverse metric effect in Table 1—where CPO on xCOMET-QE improves xCOMET-QE by ~2.2 points (xx-en) while degrading en-xx chrF by ~1.8 points, a degradation not seen under SFT on the same chosen translations—is a concrete falsification of the implicit assumption that preference optimization is a Pareto improvement over likelihood-based training. The fact that SFT on the identical chosen translations *improves* chrF (+0.79 in en-xx for xCOMET-QE alignment, Table 1) while CPO degrades it (−1.80) isolates the preference term as the causal mechanism. This is not a tradeoff where more alignment gain means more lexical loss—SFT achieves most of the alignment gain with no lexical loss. The CPO-specific degradation is a **previously unknown failure mode** of preference optimization in translation.

This finding reconciles a latent tension in the literature. Prior work on quality-aware decoding (Amrhein and Sennrich, 2022) had shown that optimizing against neural metrics at inference time could surface metric weaknesses. But that work studied decoding strategies, not weight-space optimization, and it was unclear whether weight-space optimization would exhibit the same vulnerability. This paper closes that gap: yes, it does, and the vulnerability is *worse* under CPO than under SFT because CPO actively learns to avoid translations that the metric disfavors, amplifying whatever biases or blind spots the metric has. The paper also provides a concrete explanation for why prior CPO results (Xu et al., 2024a) did not surface this issue: those evaluations focused on the alignment metric itself and did not systematically report cross-family metrics or disaggregate by translation direction. The adverse chrF effect is concentrated in out-of-English translation (en-xx), so an evaluation that aggregates all directions or only reports neural metrics would miss it entirely.

The paper also **reframes candidate system composition as a first-class experimental variable**. Before this work, the choice of candidate systems for preference data was treated as an engineering detail—use whatever high-quality systems are available. The chosen-fixation experiments (Table 3) demonstrate that this choice is not incidental but can determine whether CPO improves over the base model or catastrophically underperforms it. When the reference is forced as the chosen system, CPO collapses below the unaligned base model by ~5.9 xCOMET-QE points (xx-en: 81.95 vs. 87.80). When the base model is forced as the chosen system, CPO fails to outperform SFT. CPO's advantage over SFT in the standard multi-system configuration depends entirely on having external systems (specifically GPT-4) as high-quality chosen translations. This finding implies that preference alignment is not a property of the learning objective alone but of the interaction between the objective and the data distribution—a conceptual shift from "CPO works" to "CPO works under specific data conditions that must be explicitly verified."

**Research directions that become more attractive:**

- **Multi-metric evaluation as a standard requirement.** After this paper, any study reporting improvements from preference-based alignment should report at minimum one neural metric and one lexical metric, disaggregated by translation direction. Single-metric evaluation is no longer credible because the paper demonstrates that metric-specific degradation can be large (1.8 chrF points) while the alignment metric improves. This raises the bar for future alignment papers and makes cross-metric consistency a legitimate evaluation criterion alongside raw metric scores.

- **Understanding the mechanism of CPO-induced degradation.** The paper identifies *that* CPO degrades chrF in en-xx but not *why*. This opens a direct research question: does CPO change the model's vocabulary distribution, sentence length, syntactic patterns, or something else? Answering this would connect the observed metric effects to linguistic properties of the generated translations, making the findings interpretable and actionable.

- **Data composition as an optimization problem.** The mono-system grid analysis (Figure 1) shows that the quality gap between chosen and rejected options can be tuned to optimize downstream performance, with the optimum at a moderate gap (rejected ~90% of base quality, chosen ~105%). This suggests that preference data construction is not just about maximizing the chosen-rejected quality difference but about finding the *informative* range for a given model. This frames data composition as a hyperparameter optimization problem that could be automated.

**Research directions that become less attractive:**

- **Developing ever-more-aggressive preference optimization objectives.** The paper's finding that CPO (which amplifies the preference signal) introduces adverse effects not seen under SFT (which uses only the positive signal) suggests that stronger preference optimization—larger β, harder negative mining, more extreme chosen-rejected gaps—may exacerbate metric-specific degradation. The field should be cautious about methods that promise larger alignment gains without evaluating cross-metric effects.

- **Assuming that reference-based evaluation metrics are neutral evaluation tools after alignment.** The paper shows that aligning on neural metrics can degrade reference-based metrics (chrF), and that including references in CPO preference data can catastrophically degrade neural metrics (Table 3, reference-as-chosen). This bidirectional fragility means that reference-based and reference-free metrics cannot be treated as independent evaluation dimensions after preference alignment—they interact through the training process in ways that undermine their reliability as evaluation tools. The metrics community's recommendation to avoid using the same metric for training and evaluation (Kocmi et al., 2024) needs to be extended: after preference alignment, even *different* metrics may not provide independent assessments.

### Follow-Up Research This Work Enables

**Diagnosing the mechanism of the en-xx chrF degradation through controlled linguistic analysis.** The paper documents that CPO on neural metrics degrades en-xx chrF by ~1.8 points while leaving xx-en chrF essentially unchanged. A strong follow-up would sample 200–500 en-xx sentence pairs where CPO and SFT translations differ substantially in chrF, then annotate the differences along specific linguistic dimensions: translation length (do CPO translations get shorter?), lexical diversity (does CPO use a narrower vocabulary?), syntactic divergence from the reference (does CPO restructure sentences?), and morphological accuracy (does CPO make more inflection errors in morphologically rich target languages?). The per-language-pair breakdowns in Tables 9–10 already show that en-is and en-zh suffer larger chrF drops than en-de or en-cs; a follow-up could test whether this correlates with morphological complexity (Icelandic has complex inflectional morphology) or script differences (Chinese uses characters rather than alphabetic n-grams, which may interact differently with chrF). This analysis would transform the opaque "chrF dropped" finding into an interpretable description of *how* CPO changes translation output, enabling practitioners to decide whether the change is acceptable for their use case.

**Stress-testing the mono-system optimal quality configuration across model scales and capabilities.** The paper identifies an optimal mono-system configuration (rejected at ~90% of base quality, chosen at ~105%) for ALMA-13B-LoRA. A natural extension would test whether this ratio generalizes across model scales. Specifically, take ALMA-7B, ALMA-13B, and (if available) larger models like Tower-13B or LLaMA-3-based translation models, construct mono-system preference datasets with the same 3×3 quality grid (varying offsets $o_r$ and $o_c$ to produce Low/Mid/High chosen and rejected qualities), and measure whether the optimal ratio shifts. The hypothesis: weaker models may benefit from a narrower gap (their best self-generated translations are less informative, so extreme chosen quality provides a distribution shift that is harder to learn from), while stronger models may benefit from a wider gap (their best self-generated translations are already quite good, so the marginal value of extreme chosen quality is lower). If the optimal configuration is model-specific, this would motivate automated methods for tuning the offset parameters per model rather than using fixed heuristics. If the 90%/105% ratio is stable across scales, it becomes a broadly applicable guideline.

**Human evaluation to determine whether the chrF degradation corresponds to genuine quality loss or benign metric divergence.** The paper's central tradeoff—improved neural metrics vs. degraded lexical metrics—is measured entirely through automatic metrics. A critical follow-up would conduct a controlled human evaluation on a stratified sample of translations selected to maximize the metric divergence. Specifically, identify sentence pairs where CPO (multi-system, xCOMET-QE alignment) and SFT (same chosen translations) produce translations with a large xCOMET-QE improvement but a large chrF degradation (the "adverse effect" sentences), and pairs where both metrics improve (the "aligned" sentences). Have professional translators rate both outputs for adequacy, fluency, and lexical appropriateness on a 5-point scale, without knowing which system produced which translation. If human raters prefer CPO outputs on the adverse-effect sentences despite the chrF drop, the "adverse metric effect" is a measurement artifact and practitioners should ignore chrF when evaluating preference-aligned models. If human raters confirm that CPO outputs are lexically worse, the tradeoff is real and the paper's cautionary message is validated. This experiment is essential because all of the paper's practical implications depend on whether the chrF degradation reflects genuine quality loss.

**Testing whether CPO's adverse effects are specific to the reference-free neural metric family or generalize to reference-based neural metrics.** The paper aligns on xCOMET-QE and CometKiwi (both reference-free) and evaluates chrF (reference-based lexical). It does not test alignment on a reference-based neural metric like Metric-X or BLEURT. A follow-up would construct preference datasets using Metric-X (reference-based neural) as the alignment metric, train CPO and SFT models, and evaluate on xCOMET-QE, CometKiwi, chrF, and BLEU. The question: does aligning on a reference-based neural metric also cause lexical degradation, or does the inclusion of the reference in the metric's input provide a regularizing effect that preserves lexical properties? If reference-based neural alignment avoids the chrF degradation, this would provide a practical recommendation (prefer reference-based metrics for alignment when possible) and a mechanistic clue (the degradation may stem from reference-free metrics being insensitive to lexical precision, a known limitation). If reference-based neural alignment also degrades chrF, the mechanism is deeper—any metric that prioritizes semantic adequacy over surface overlap will cause this effect when optimized via CPO.

**Extending the mono-system approach to other preference optimization methods (DPO, ORPO, SimPO) and measuring whether the benefits are CPO-specific.** The paper focuses exclusively on CPO, noting that it "combines a preference term with a likelihood term" and removes the reference policy from DPO. A systematic comparison would take the identical mono-system preference datasets (including the nine quality configurations from Section 5.2) and train models using standard DPO (with the base model as reference policy), ORPO (which combines SFT and preference alignment in a single objective without a reference model), and SimPO (which uses length-normalized likelihood as the preference signal). For each method, measure both the alignment metric improvement and the cross-metric consistency (chrF preservation). The hypothesis: methods that include an explicit SFT term (CPO, ORPO) may show better metric consistency than pure preference methods (DPO) because the SFT term anchors the model to producing high-quality translations, not just distinguishing between them. Methods that use a reference policy (DPO) may show different sensitivity to candidate system composition because the reference policy provides an additional regularization signal. If CPO's adverse chrF effect also appears under DPO, the problem is fundamental to preference optimization. If it is CPO-specific, the field can adopt alternative objectives that preserve the alignment benefit without the lexical side effect.

**Investigating whether the reference system's harmful effect under CPO can be mitigated by filtering or weighting preference pairs.** The paper shows that removing references from the candidate pool eliminates the adverse chrF effect while preserving most neural improvement (Table 2, No Ref en-xx chrF: 50.67 vs. 47.69 All systems). A finer-grained follow-up would, instead of binary removal, filter or weight reference-containing preference pairs based on the reference's neural metric score. For example, include the reference in the candidate pool only when its xCOMET-QE score exceeds some threshold (e.g., only when the reference is not the lowest-scoring candidate), or weight CPO training examples inversely by the quality gap between the reference and the other candidates. The goal: recover the marginal neural improvement from including references (~0.3 xCOMET-QE points, per Table 2) without paying the full chrF cost. If a threshold or weighting scheme can achieve this, it provides a practical compromise for practitioners who have access to references and want to maximize neural alignment. If no scheme works, the paper's implicit recommendation (exclude references from CPO preference data) is robust.

**Evaluating whether the adverse metric effects accumulate or saturate over multiple rounds of alignment in a self-improvement loop.** The paper studies a single round of preference alignment. A natural extension is iterative self-improvement: take the CPO-aligned model (mono-system, optimized configuration), use it to generate new candidate translations, construct new preference pairs from those candidates, and train another round of CPO. Measure both the alignment metric and cross-family metrics after each round. The hypothesis: if the adverse chrF effect is caused by distribution shift (the model moves away from its pretrained lexical patterns), each round of alignment may compound this shift, leading to progressive chrF degradation even under the mono-system approach. Conversely, if the first round of alignment stabilizes the model in a new distribution that subsequent rounds don't further shift, the chrF degradation may saturate after one round. The mono-system setting makes this experiment practical because it requires no external systems at any round—the model bootstraps from its own outputs. This would directly test the paper's implicit claim (in the Conclusion) that mono-system alignment provides "more control over preference-based fine-tuning" and would characterize the limits of iterative self-alignment for translation.

### Practical Applications and Downstream Use Cases

**Cost-efficient fine-tuning for translation service providers with limited access to high-quality external systems.** The paper's mono-system alignment results (Table 4) demonstrate that a translation model can achieve statistically indistinguishable neural metric performance compared to multi-system alignment (within ~0.4 xCOMET-QE points for en-xx) using only its own sampled outputs, without requiring GPT-4 API access or gold reference translations. For a translation service provider operating in a specialized domain (legal, medical, financial) where GPT-4 may not be available, affordable, or permitted for data processing, this finding is directly actionable: (1) take the in-domain base model, (2) generate 50 diverse candidate translations per source sentence using top-p sampling (p = 0.6, τ = 0.9), (3) score candidates with a neural metric (xCOMET-QE or CometKiwi), (4) construct preference pairs with moderate quality gaps (rejected at ~90% of base quality, chosen at ~105%), (5) train CPO for one epoch. The result is a model that achieves roughly 90–95% of the alignment gain that including GPT-4 translations would provide, without the API costs, data privacy concerns, or dependency on external model availability. The upfront cost of generating 50 candidates per training sample (~1M inferences for a 20K-sample dataset) is a one-time investment amortized over all subsequent uses of the fine-tuned model, making it economical for high-volume production deployments.

**Multi-metric quality assurance for production translation systems.** The paper's finding that CPO on xCOMET-QE degrades en-xx chrF by ~1.8 points while SFT on the same chosen translations improves it by ~0.8 points (Table 1) provides a concrete decision criterion for production teams. If the deployment context requires lexical precision—for instance, translating technical documentation where terminology consistency with reference materials matters, or translating legal contracts where specific wording carries legal weight—the team should prefer SFT on neural-preferred translations over CPO, or use mono-system CPO (which reduces the chrF degradation by ~74%, to only −0.5 points, Table 4). If the deployment context prioritizes fluency and semantic adequacy (e.g., translating news articles or social media content where surface-form overlap with a reference is irrelevant), multi-system CPO provides the best neural metric scores. The paper's evaluation framework—always reporting the alignment metric plus at least one cross-family metric, disaggregated by language direction—provides a template for making this decision quantitatively on the team's own data rather than relying on published results from different domains. The team would: (1) construct preference data from their own domain corpus, (2) train SFT and CPO variants, (3) evaluate on held-out domain data across neural and lexical metrics, (4) select the method that optimizes their specific quality criteria.

**Bootstrapping translation quality for low-resource languages where external systems and references are scarce.** The mono-system approach requires no external translation systems, no gold references (for preference construction—it uses the neural metric as a quality oracle), and no parallel data beyond what was used to train the neural metric. For a low-resource language where GPT-4 performs poorly or is unavailable, and where high-quality reference translations are limited, the multi-system recipe (Base + GPT-4 + Reference) is infeasible. The mono-system recipe, by contrast, requires only: (1) a base model that can translate the language (even if imperfectly), (2) a neural metric that can score translations in that language (which may require some human judgment data for metric training, but far less than full parallel corpora), and (3) the compute to generate 50 candidates per source sentence during preference data construction. The paper's finding that the optimal mono-system configuration uses a *moderate* quality gap (chosen at ~105% of base quality) rather than an extreme gap is particularly relevant for low-resource settings: the base model's best self-generated translations may be of modest absolute quality, but the *relative* improvement over its typical output still provides a useful training signal. A deployment team could apply this recipe to iteratively improve a low-resource translation model without any external dependencies beyond the initial neural metric.

**Preference data quality auditing for research groups releasing aligned translation models.** The paper's sensitivity analysis (Tables 2 and 3) reveals that CPO performance is highly dependent on candidate system composition, with the reference system capable of causing catastrophic degradation when forced as the chosen system (−5.9 xCOMET-QE points in xx-en, Table 3). For research groups releasing preference-aligned translation models, the paper provides an auditing protocol: before releasing a model, test sensitivity to candidate system composition by training ablated variants (remove each candidate system in turn, fix the chosen system to each candidate) and report whether performance is stable across these variations. If model performance collapses when the reference is removed (suggesting the model learned to exploit reference-specific lexical patterns) or when GPT-4 is removed (suggesting the model's quality gains depend entirely on a single external system), the release should include a prominent caveat. The paper's Table 2 provides a concrete example of what such an audit table looks like, and the statistical testing methodology (one-tailed paired t-tests at 5% significance) provides a replicable standard for determining whether sensitivity is significant. This auditing practice would increase the reliability and reproducibility of published aligned models, addressing a gap the paper identifies: prior CPO work did not report these diagnostics, making it impossible to assess whether reported gains were robust to data composition choices.
