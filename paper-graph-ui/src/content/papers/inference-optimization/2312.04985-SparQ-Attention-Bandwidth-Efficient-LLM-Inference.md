# SparQ Attention: Bandwidth-Efficient LLM Inference

**ArXiv:** [2312.04985](https://arxiv.org/abs/2312.04985)

## 🎯 Pitch

This paper introduces **SparQ Attention**, a technique for accelerating LLM inference by reducing data transfers within attention layers through selective fetching of the cached key-value history, targeting the memory bandwidth bottleneck that dominates batched long-sequence generation.

---

## 1. Executive Summary

This paper introduces **SparQ Attention**, a technique for accelerating LLM inference by reducing data transfers within attention layers through selective fetching of the cached key-value history, targeting the memory bandwidth bottleneck that dominates batched long-sequence generation. The method operates through two approximation mechanisms—query sparsity (selecting the top-r magnitude components of the query vector to compute approximate attention scores) and attention score sparsity (fetching only the top-k keys and values indicated by those approximate scores), combined with a mean value reallocation correction that interpolates between the sparse attention output and a running mean of all values. Evaluated on Llama 2, Llama 3, Mistral, Gemma, and Pythia models across question answering, summarization, perplexity, and text repetition tasks, SparQ Attention achieves up to 8× compression in attention data transfers without substantial accuracy loss, maintaining dense-model performance on SQuAD at 1/4 compression as sequence length scales to 128k tokens—establishing that bandwidth-efficient attention is achievable by exploiting natural sparsity in both query vectors and attention scores, without requiring any pretraining modifications or additional fine-tuning.

## 2. Context and Motivation

### The Core Problem: Memory Bandwidth as the Hidden Bottleneck in LLM Inference

When we think about what makes large language models slow, our intuition often points to computation—the massive number of floating-point operations required by the transformer's matrix multiplications. This paper argues that intuition is wrong for most practical inference scenarios. The real bottleneck is not compute but **data transfer**: the sheer volume of information that must be moved between memory and the processing unit for every single token generated.

To understand why, we need to examine what happens during autoregressive generation. When an LLM produces a sequence of tokens one by one, each new token requires the model to attend to every previous token in the sequence. The standard optimization for this is **KV caching** (Pope et al., 2023): store the key and value vectors for all previously processed tokens in memory so they don't need to be recomputed. This cache eliminates redundant computation, but creates a new problem. For each token generated, the **entire** KV cache—spanning all previous positions across all attention heads—must be fetched from memory before attention scores can be computed.

The size of this fetch grows linearly with sequence length and batch size. For a Llama 2 7B model with batch size 1 and sequence length 4096, this is manageable. But the applications driving LLM adoption—chat histories spanning thousands of words, documents injected as context for retrieval-augmented generation, multi-turn conversations—routinely push sequence lengths into the tens of thousands of tokens. When processing these in batches (as services like ChatGPT must, to serve millions of users cost-effectively), the data transfer volume explodes.

The paper formalizes this through the concept of **arithmetic intensity**: the ratio of arithmetic operations (A) to data transfers (M) required by a workload. A compute unit capable of $r_A$ operations per second connected to memory with $r_M$ transfers per second is compute-bound when $A/M$ exceeds $r_A/r_M$, and memory-bandwidth-bound when it doesn't. The authors derive (Section 2, Appendix C) that for a standard transformer layer:

$$\frac{A}{M} = \frac{6 + \rho g}{6/B + \rho}$$

where $\rho = S/(g d_m)$ is a derived variable capturing the relationship between sequence length $S$, the number of grouped-query heads per key-value head $g$, and the model dimension $d_m$. The critical observation: even for multi-head attention ($g=1$), when $S$ equals $d_m$ (4096 for Llama 2 7B), the limiting arithmetic intensity is just 7. For grouped-query attention ($g=8$), it reaches only 104 when $S \ll d_m$. Modern ML hardware provides $r_A/r_M$ ratios of 200–300 (the paper cites H100 at 295 and Bow IPU at 32 for comparison). This means **inference is almost always bandwidth-bound, not compute-bound**, as visualized in Figure 2.

The proportion of data transfers attributable to attention specifically (as opposed to model parameters) is derived in Equation (1):

$$\frac{M_{\text{attn}}}{M_{\text{attn}} + M_{\text{params}}} = \frac{\rho}{\rho + 6/B}$$

When $\rho \gg 6/B$ (large sequence length or batch size), attention transfers dominate completely. Figure 3 validates this empirically using llama.cpp benchmarks: at 50,000 token sequence lengths on GPU, approximately 80% of inference time is spent in attention layers. On CPU, this reaches roughly 65%.

### The Practical Stakes: Why This Matters for Real-World Deployment

The bandwidth bottleneck has concrete consequences that cascade through the LLM ecosystem:

**Latency is the primary usability constraint for interactive applications.** Users expect chat responses in under a second. When attention data transfers slow generation to a crawl on long contexts, the model becomes effectively unusable regardless of its output quality. The paper notes (Section 1) that "the speed at which tokens can be generated [is] a key usability metric for LLMs."

**Throughput determines cost-per-query for API services.** LLM inference providers are economically constrained by how many queries they can serve per GPU-hour. When generation is bandwidth-limited, adding more computational capacity doesn't help—the memory interface is saturated. The only path to higher throughput is reducing data movement.

**Long-context capabilities are undermined by inference speed.** In-context learning (Wei et al., 2022) enables LLMs to incorporate arbitrary textual information—documents, examples, conversation history—at inference time without fine-tuning. This capability has been a primary driver of LLM utility, spawning applications from retrieval-augmented generation to few-shot prompting. But the paper identifies a tension: "to leverage the benefits of in-context learning, there has been demand for LLMs to support increasingly long input sequences. However, the standard inference optimization used to support in-context learning, key-value (KV) caching, is constrained by the need to fetch a large amount of data from memory when processing batches of long sequences."

**Batched inference amplifies the problem.** Individual users experience latency, but service providers experience both latency and throughput constraints. The KV cache size scales with batch size × sequence length, meaning that the economics of serving many users simultaneously with long-context models are fundamentally bottlenecked by memory bandwidth.

**The trend toward longer sequences is accelerating.** Models are being deployed with context windows of 32k, 128k, and even 1M tokens. Without corresponding improvements in attention efficiency, the bandwidth problem grows proportionally. The paper's roofline analysis (Figure 2) shows that for batch size 1 with sequence length 23,000, Llama 2 7B is already bandwidth-bound; for batch size 20 with sequence length 1,000, the same model is deep in the bandwidth-bound regime.

### Prior Approaches and Their Fundamental Limitations

The paper organizes existing work into several categories, each with distinct shortcomings that motivate the SparQ Attention approach.

#### 1. Architectural Modifications During Pretraining

A large body of work has redesigned attention mechanisms to be more efficient, but these must be baked into the model during pretraining. This includes **Sparse Transformers** (Child et al., 2019), which use fixed sparsity patterns; **Longformer** (Beltagy et al., 2020) and **BigBird** (Zaheer et al., 2020), which combine local windows with global tokens; **Reformer** (Kitaev et al., 2020), which uses locality-sensitive hashing; and **Multi-Query Attention** (Shazeer, 2019) and **Grouped-Query Attention** (Ainslie et al., 2023), which share key-value heads across multiple query heads.

The limitation (Section 7): "These methods form part of the architecture: they must be implemented during pre-training, carry varying task performance trade-offs, and may affect model quality and stability." For practitioners working with off-the-shelf models—which is the vast majority of LLM usage—these approaches are irrelevant. You cannot retrofit MQA into a pretrained Llama model.

#### 2. Inference-Only Cache Eviction Methods

More relevant to this paper are techniques that modify only the inference procedure of pretrained models. The simplest approach, part of **FlexGen** (Sheng et al., 2023), calculates exact attention scores using the full key cache but only fetches the values corresponding to the top-k scores. This provides at most a 50% reduction in transfers because the full K cache must still be read to compute scores. The paper notes (Section 7): "This process uses the full key cache to produce attention scores, limiting the asymptotic reduction of the memory transfers to only 50%."

**LM-Infinite** (Han et al., 2023) and **StreamingLLM** (Xiao et al., 2023) employ fixed sparsity patterns: preserve the most recent tokens and a few initial tokens, discarding everything in between. These approaches "are not selective in their cache lookup" (Section 7)—they apply the same pattern regardless of what the query is actually looking for. If the information needed to answer a question lies in the discarded middle portion of the context, it is permanently lost.

**Eviction schemes** like **H2O** (Zhang et al., 2023), **Scissorhands** (Liu et al., 2023a), and **FastGen** (Ge et al., 2024) maintain only a subset of the KV cache in memory by deleting tokens deemed uninformative. H2O uses a greedy policy based on "Heavy Hitter" attention scores; Scissorhands identifies "pivotal tokens" that exceed an importance threshold; FastGen uses heuristics like preserving special tokens and punctuation.

These approaches share a fundamental flaw (Section 8): "they also lead to permanent loss of information from the context window, which can lead to mistakes for queries seeking less-attended parts of the sequence." The paper's experiments bear this out starkly. In Table 2, on the SQuAD task at 1/8 compression, H2O drops from 80.8% to 63.0% on Llama 2 13B, while LM-Infinite collapses to 30.1%. The text repetition task is even more dramatic: H2O falls from 229-character match length to 26 at 1/8 compression, and LM-Infinite reaches only 29. These degradations occur because the eviction policies permanently delete information that later queries may need.

#### 3. Approximate Nearest Neighbor and Other Domains

**IceFormer** (Mao et al., 2023) applies approximate nearest neighbor search to attention on CPUs but focuses on the prefill stage rather than token generation. **Scatterbrain** (Chen et al., 2021) combines sparse and low-rank attention but targets computer vision. Neither addresses the autoregressive generation bottleneck that this paper targets.

#### 4. Orthogonal Approaches

Weight sparsity methods like **Deja Vu** (Liu et al., 2023c) and activation sparsity techniques (Kurtz et al., 2020; Mirzadeh et al., 2024) target the parameter-transfer bottleneck that dominates in small-batch, short-sequence regimes. KV cache quantization to 4-bit formats (Liu et al., 2023b; Sheng et al., 2023) reduces the bytes-per-element but does not reduce the number of elements transferred—it is complementary to, but not a substitute for, selective fetching.

### How SparQ Attention Positions Itself

The paper frames SparQ Attention as occupying a specific and previously unfilled position in the design space (Section 1): **maintain the full KV cache in memory but selectively fetch from it at each generation step.** This is distinct from eviction schemes that delete from the cache (permanently losing information) and from the FlexGen approach that uses full keys to compute scores (limited to 2× compression).

The key insight that enables this positioning comes from three empirical observations about pretrained LLMs, analyzed in Section 3 and Figure 4:

1. **Attention score sparsity is natural and severe.** Figure 4a shows that across 40 SQuAD queries, the sum of the top-32 attention scores (out of thousands of positions) frequently exceeds 0.8 on a 0–1 scale. Most of the attention mass concentrates on a small fraction of tokens. Figure 4b shows this pattern holds per-head across all layers, though some heads are more diffuse than others. This means—in principle—only a small subset of values needs to be fetched, since contributions from low-scoring positions are negligible.

2. **Query vectors are heavy-tailed, not Gaussian.** Figures 4c and 4d show that the components of query vectors exhibit high Fisher kurtosis across most attention heads. Compared to a unit Gaussian, the combined mass of elements with absolute z-score exceeding 3.0 is up to 20× higher. This means a small number of query dimensions carry most of the magnitude, and these likely dominate the dot-product attention scores. If this is true, approximate attention scores can be computed using only these top-r components of the query—and consequently only those components of the key cache need to be fetched.

3. **Value vectors are highly auto-correlated along the sequence axis.** Table 1 shows an excess correlation ratio along the sequence dimension of 0.14–0.26 for Llama 2 7B, while correlation along layer, head, and hidden dimensions is approximately zero. This means that the values at different sequence positions are not independent—a running mean captures substantial information about the values that were not fetched, enabling a correction term.

These three observations motivate the three-step structure of SparQ Attention (Section 4): (1) use query sparsity to cheaply approximate attention scores, (2) use score sparsity to selectively fetch full keys and values, (3) use value auto-correlation to correct for the missing mass via a mean value vector.

The paper explicitly positions this as an **inference-only, plug-and-play technique**—no pretraining modifications, no fine-tuning, no permanent information loss. Section 1 states: "Our proposed technique can be applied directly to off-the-shelf LLMs during inference, without requiring any modification to the pre-training setup or additional fine-tuning." This is a crucial practical differentiator: any existing deployed model can immediately benefit from SparQ Attention by swapping the attention implementation.

### The Contradiction That Motivates Sparse Attention

There is a deep tension in transformer inference that the paper exploits. Attention was designed to let each token "look at" every other token—the quadratic all-to-all connection is what gives transformers their expressive power for in-context learning and long-range dependencies. Yet empirically, at any given generation step, most tokens do not need to look at most other tokens. The paper cites Vig (2019) and Yun et al. (2020) showing that "tokens generally only attend to a small part of the sequence at a time."

The standard dense attention implementation is therefore highly wasteful: it fetches the entire KV cache (millions of elements) to compute attention scores, then multiplies those scores against all value vectors, when only a small fraction of those data movements actually matter for the output. The challenge—and the gap this paper fills—is **predicting which tokens will have high attention scores without first fetching the full key cache to compute them.** If this prediction can be done accurately and cheaply, the bandwidth bottleneck can be dramatically reduced.

SparQ Attention's contribution is showing that this prediction is possible using only the query vector's own statistics—no per-head learned predictors, no auxiliary model, no cached metadata beyond what already exists. The query itself, through its largest-magnitude components, contains sufficient information to identify the important keys, because these large-magnitude components are not noise but rather the dimensions where meaning is being encoded (the heavy-tailed distribution of Figure 4c).

### Why This Paper's Evaluation Setup Matters

The paper constructs evaluation tasks specifically designed to stress-test sparse attention methods (Section 5.1). This is important because the weakness of existing approaches is not in easy cases but in challenging ones where relevant information is scattered throughout a long context and not trivially locatable.

The **SQuAD** setup is particularly revealing: each example contains the relevant context plus seven additional "confusion contexts" from unrelated questions. This forces the model to distinguish the relevant paragraph from distractors—exactly the scenario where a fixed sparsity pattern (LM-Infinite) or an eviction policy (H2O) might discard the needed information. The **text repetition** task is similarly adversarial: the model must reproduce a verbatim substring from its context, requiring precise retrieval of information that could reside anywhere in the sequence. The **needle in a haystack** evaluation pushes this even further by inserting a single sentence at a controlled depth and testing whether the model can find it.

The paper's choice to report results on models spanning five families (Llama 2, Llama 3, Mistral, Gemma, Pythia) and sizes up to 13B parameters is also notable. SparQ Attention makes no architecture-specific assumptions beyond the standard attention mechanism, and demonstrating robustness across multi-head attention (g=1) and grouped-query attention (g=4, 8) variants, different normalization schemes, and different activation functions validates the technique's generality.

## 3. Technical Approach

### 3.1 Reader Orientation

This is an **inference-optimization technique paper** whose core idea is that you can dramatically reduce the data transferred during transformer attention by using the query vector itself—specifically, its largest-magnitude components—as a cheap proxy to predict which keys will receive high attention scores, then fetching only those keys and values in full, without ever reading the complete key cache from memory. What's being built is a drop-in replacement for the standard attention operation that reduces memory bandwidth consumption by 4–8× while maintaining output quality, by exploiting the natural sparsity of both attention scores (most tokens contribute negligibly to the output) and query vectors (a few dimensions carry most of the magnitude), combined with a correction term using the running mean of value vectors to compensate for the unattended mass.

### 3.2 Big-Picture Architecture (Diagram in Words)

The system has **four major components** that process a single attention head's forward pass:

1. **Query Analyzer** — examines the incoming query vector `q`, identifies its `r` largest-magnitude components, and uses only those components to compute approximate attention scores against the key cache. Responsible for producing a cheap, bandwidth-efficient estimate of which sequence positions matter.

2. **Key Cache (Stored Twice)** — the full key matrix `K` is stored in two memory layouts: once in sequence-major order (contiguous along the hidden dimension) for Step 1's columnar access, and once in hidden-dimension-major order (contiguous along the sequence dimension) for Step 2's row-wise access. This 50% memory overhead enables efficient gather operations in both steps.

3. **Sparse Attention Executor** — takes the approximate attention scores from Step 1, identifies the top-`k` positions, fetches the full key and value vectors at those positions, and computes exact attention using only the retrieved subset. Responsible for producing the core attention output from the most relevant tokens.

4. **Mean Value Corrector** — maintains a running mean of all value vectors in the sequence and interpolates between the sparse attention output and this mean, weighted by the estimated total attention mass captured by the top-`k` positions. Responsible for compensating for the contribution of the values that were not fetched.

Information flows sequentially: query `q` enters → Query Analyzer computes approximate scores `\hat{s}` using only `r` key dimensions → Sparse Attention Executor selects top-`k` positions from `\hat{s}`, fetches full `K[:, i2]` and `V[:, i2]`, and computes exact attention output `y_` → Mean Value Corrector estimates captured mass `\alpha` from `\hat{s}` and produces final output `y = \alpha y_ + (1-\alpha) \bar{v}`.

### 3.4 Detailed, Sentence-Based Technical Breakdown

#### The Dense Attention Operation and Its Memory Cost

Consider a single attention query head with head dimension `d_h` processing an input sequence of length `S`. During autoregressive generation, the output of the attention head is calculated by the standard scaled dot-product attention formula given in Equation (2):

$$y = \text{softmax}\left(\frac{q \cdot K^\top}{\sqrt{d_h}}\right) \cdot V$$

where `q \in \mathbb{R}^{d_h}` is the query vector for the current token, `K \in \mathbb{R}^{S \times d_h}` is the key cache containing key vectors for all `S` previous tokens, and `V \in \mathbb{R}^{S \times d_h}` is the value cache containing value vectors for all `S` previous tokens.

**What it computes:** the query `q` is dotted with every row of `K` (each row is one previous token's key vector) to produce a raw score per position. These scores are divided by `\sqrt{d_h}` for variance scaling (preventing dot products from growing too large with dimensionality) and passed through softmax to produce a probability distribution `s \in (0, 1)^S` over sequence positions. This distribution is then used as a weighted sum over the value vectors, producing the output `y \in \mathbb{R}^{d_h}`.

**Why this form:** the `\sqrt{d_h}` scaling originates from the original Transformer paper (Vaswani et al., 2017) and compensates for the fact that the dot product of two vectors grows in variance with dimensionality. Without this scaling, the softmax would saturate toward one-hot distributions as `d_h` increases, preventing meaningful attention patterns.

The memory transfer cost per forward pass for a single attention head is given in Equation (3):

$$M_{\text{dense}} = 2 S d_h + 2 d_h$$

where the first term `2 S d_h` accounts for reading the full `K` and `V` matrices (each of size `S \times d_h`), and the second term `2 d_h` accounts for writing the current token's new `k` and `v` vectors to memory, appending them to the cache for future tokens.

**What it computes:** the total number of scalar elements that must move between memory and the compute unit for one attention head to process one new token. The factor of 2 in the first term reflects that both `K` and `V` must be read; the second term reflects that the new key and value vectors (each of size `d_h`) must be written to the growing cache.

**Why this form matters:** the dominant term is `2 S d_h`, which grows linearly with sequence length `S`. For Llama 2 7B with `d_h = 128` and `S = 4096`, this is approximately 1 million elements per head per token, multiplied by 32 heads and 32 layers—producing the bandwidth bottleneck that Section 2 analyzes. When using Grouped Query Attention (GQA) where `g` query heads share each KV head, `K` and `V` are transferred `g` times fewer, but the scaling with `S` remains identical.

#### Attention Score Sparsity: Why We Can Skip Most Values

The attention scores `s \in (0, 1)^S` produced by the softmax are empirically sparse—most of the probability mass concentrates on a small number of positions. The paper demonstrates this in Figure 4a by summing the softmax output allocated to the 32 highest-scoring positions across many examples: the distribution is heavily concentrated near 1.0, meaning nearly all attention mass is captured by just 32 tokens regardless of total sequence length. Figure 4b shows this pattern holds across all layers and heads, though some heads are more diffuse than others.

This sparsity motivates the first approximation, expressed in Equation (5):

$$y_1 = (s \circ m_s) \cdot V \approx s \cdot V$$

where `s \in (0, 1)^S` is the exact attention score distribution, `m_s \in \{0, 1\}^S` is a boolean mask selecting the top-`k` positions in `s` (with `k \ll S`), and `\circ` denotes element-wise multiplication. The masked softmax distribution `s \circ m_s` is renormalized implicitly by the fact that the removed elements have negligible mass.

**What it computes:** instead of computing the full weighted sum over all `S` value vectors, we compute it over only the `k` positions with the highest attention scores and approximate the result as equivalent. The mask `m_s` selects exactly those `k` positions and zeroes out the rest.

**Why this helps:** if we could know which `k` positions have the highest scores without reading the full `K` matrix, we would only need to fetch `k` value vectors instead of `S`. However, computing `s` itself requires reading all of `K`—the dot product `q \cdot K^\top` must be evaluated at every position before we can identify the top-scoring ones. This means the naive approach saves at most 50% of data transfers (reading all of K but only k rows of V), as used by FlexGen's top-k attention.

#### Mean Value Reallocation: Compensating for Missing Values

The value vectors `v_i` at different sequence positions are not independent. Table 1 reports an excess correlation ratio (a normalized measure of statistical dependence) along the sequence axis of 0.14–0.26 for Llama 2 7B, compared to approximately 0.0 along the layer, head, and hidden dimension axes. This means that tokens at different positions in the same sequence have statistically similar value vectors—they encode semantically related information.

This auto-correlation enables an improved approximation given in Equation (6):

$$y_2 = (s \circ m_s) \cdot V + (1 - s \cdot m_s) \bar{v}$$

where `\bar{v} = \frac{1}{S} \sum_{i=1}^{S} v_i` is the running mean of all value vectors in the sequence, and `s \cdot m_s` is the total attention mass captured by the top-`k` positions (a scalar between 0 and 1, typically close to 1).

**What it computes:** the attention output is split into two parts: the contribution from the `k` selected positions, computed exactly, and the contribution from all other positions, approximated by their mean value vector `\bar{v}` weighted by the remaining attention mass `1 - s \cdot m_s`. If the top-`k` positions capture 90% of the attention mass and the mean value vector reasonably represents the aggregate of the remaining 10%, the approximation error is small.

**Why this form rather than just using `y_1`:** without the correction term, the approximation in Equation (5) simply drops the contribution of low-attention positions entirely, assuming it to be zero. The correction replaces that zero with the mean value vector, which is a much better estimate of the average contribution of the dropped positions—free, in terms of the number of dropped positions being estimated (the error is only in how well `\bar{v}` approximates the weighted average of the low-scoring values). The overhead is minimal: `\bar{v}` must be maintained as a running mean (updated each time a new token is added) and fetched once per attention head per generation step, adding only `2 d_h` elements to the transfer cost (one read of the previous `\bar{v}`, one write of the updated `\bar{v}`).

A critical detail: `\bar{v}` is updated sequentially as new tokens are generated. When token `S+1` is appended, the new mean is `\bar{v}_{\text{new}} = (S \cdot \bar{v}_{\text{old}} + v_{S+1}) / (S+1)`. This requires reading the old mean and writing the updated mean, accounting for the `4 d_h` term that appears in the full SparQ Attention transfer cost (Equation 11).

#### Query Sparsity: Approximating Attention Scores Without Full Keys

The key insight that enables SparQ Attention to break through the 50% compression limit is that **approximate attention scores `\hat{s}` can be computed without reading the full key matrix `K`**, by exploiting the heavy-tailed distribution of query vector components.

Figure 4c shows a kernel density estimate of the components of `q` in layer 16 of Llama 2 7B, compared to a unit Gaussian. The empirical distribution has much heavier tails—large-magnitude components occur far more frequently than a normal distribution would predict. Figure 4d quantifies this per-head using Fisher kurtosis: most heads have kurtosis substantially exceeding the Gaussian baseline of 0, confirming that `q` is leptokurtic (heavy-tailed). The paper reports that "the combined mass of the elements with absolute z-score exceeding 3.0 is up to 20× higher" than a Gaussian.

This means a small number of query dimensions carry most of the vector's magnitude, and—crucially—these large-magnitude components are not noise; they are the dimensions where the query's information is most concentrated. Consequently, **the dot product `q \cdot k_i` for each key `k_i` is dominated by the dimensions where `|q|` is largest.** This allows us to approximate attention scores using only the top-`r` components of `q` (and the corresponding components of each key), as formalized in Equation (7):

$$\hat{s} = \text{softmax}\left(\frac{(q \circ m_q) \cdot K^\top}{\tau}\right)$$

where `m_q \in \{0, 1\}^{d_h}` is a per-query boolean mask selecting the top-`r` components of `|q|` (element-wise absolute value of the query), `\circ` denotes element-wise multiplication (zeroing out all components not in the top-`r`), and `\tau` is the softmax temperature (discussed below).

**What it computes:** instead of the full dot product `q \cdot K^\top` over all `d_h` dimensions, the approximate scores use only `r` dimensions—those where the query has the largest magnitude. For each key vector, the dot product `(q \circ m_q) \cdot k_i` sums over only the `r` selected coordinates. The result `\hat{s}` is a vector of length `S` providing approximate attention scores for all positions.

**Why this enables bandwidth savings:** because only `r` components of each key need to be fetched. Specifically, we need the submatrix `K_{[:, i_1]}` where `i_1` is the set of `r` indices selected from `q`. This costs `S \cdot r` elements to read instead of `S \cdot d_h`. For typical configurations (`r = 32`, `d_h = 128`), this is a 4× reduction in the cost of computing attention scores. The memory transfer for this step is `S r` (reading `r` components of `K` for all `S` positions), which is the first term in Equation (11).

A crucial implementation detail: the paper stores `K` in sequence-contiguous layout (also called S-major) for this step. In this layout, all `d_h` components for position 0 are contiguous, followed by all components for position 1, and so on. This means accessing column `j` of `K` (the `j`-th component for all `S` positions) requires strided memory access, which is inefficient on standard hardware if done naively. The dual-layout storage (described below) addresses this.

#### The Softmax Temperature Correction

When computing approximate attention scores using only `r` out of `d_h` dimensions, the variance of the dot products changes, which affects softmax behavior. The softmax temperature `\tau` must be chosen carefully to maintain calibration—so that the approximate scores `\hat{s}` accurately reflect which positions would have high scores in the full-dimensional computation.

If the `r` dimensions were chosen uniformly at random from the `d_h` available, the appropriate temperature would be `\tau = \sqrt{r}` because the dot product over `r` dimensions has expected variance proportional to `r`. If the top-`r` components captured all the magnitude (and the remaining `d_h - r` were exactly zero), the appropriate temperature would be `\tau = \sqrt{d_h}` because the full dot product magnitude is preserved. Reality lies between these extremes, so the paper proposes Equation (9):

$$\tau = \sqrt{d_h \cdot \frac{\|q \circ m_q\|_1}{\|q\|_1}}$$

where `\|q \circ m_q\|_1` is the L1 norm (sum of absolute values) of the query restricted to the top-`r` components, and `\|q\|_1` is the L1 norm of the full query vector. The ratio `\|q \circ m_q\|_1 / \|q\|_1` is the **L1 coverage**—the fraction of the query's total magnitude captured by the top-`r` components.

**What it computes:** the temperature is scaled between the two extremes. When the top-`r` components capture nearly all the query's magnitude (ratio close to 1), `\tau \approx \sqrt{d_h}`—the full temperature, appropriate because the approximation loses little information. When the top-`r` components capture little magnitude (ratio small, because `r` is very small or the query is diffuse), `\tau` shrinks toward `\sqrt{r \cdot d_h / S}`—a smaller temperature that compensates for the reduced dot-product magnitude by making the softmax sharper.

**Why this form:** the L1 norm is used rather than L2 because it provides a more robust measure of how much "signal" is captured. The L2 norm would be dominated by the largest components (which are already selected), making the ratio artificially close to 1. The L1 norm gives partial credit to smaller components that still contribute meaningful information. Figure 4f validates this choice by measuring "agreement between the coverage `\alpha` based on estimated scores versus the true mass of the top-128 scores, for different softmax temperatures"—the proposed temperature achieves the best agreement compared to alternatives (`\sqrt{d_h}`, `\sqrt{r}`, and `\tau \to 0`).

The paper also compares these alternatives directly in Figure 7b, showing that the proposed L1-coverage-weighted temperature outperforms `\sqrt{d_h}` and `\sqrt{r}` on SQuAD accuracy for two hyperparameter configurations (`r=32`, `r=64`, both with `k=128`). The `\tau \to 0` case corresponds to `\alpha = 1` (no mean value reallocation, since a zero temperature makes the softmax a one-hot at the argmax position), which performs substantially worse—confirming that the mean value correction is essential.

#### Computing Sparse Attention with Approximate Scores

Once the approximate attention scores `\hat{s}` are computed from the reduced-dimension keys, the top-`k` positions are identified. However, there is an important subtlety: the tail of the sequence (the most recent `l` positions) is always included regardless of approximate scores, via a mask `m \in \{0, 1\}^S` where `m_i = 1` for `i > S - l`. The paper sets `l = k/4` throughout the experiments (Table G1). This ensures that the most recent tokens—which are typically important for local coherence in autoregressive generation—are never missed due to approximation error in `\hat{s}`. The indices are selected as:

$$i_2 = \text{argtopk}(\hat{s} + m, k)$$

where adding the boolean mask ensures that any token in the last `l` positions is effectively forced into the top-`k` (the mask values of 1 boost those positions' scores above any possible softmax value from `\hat{s}`, which is at most 1).

The exact attention computation then proceeds using the full `d_h`-dimensional keys and values at the selected positions, as given in Equation (8):

$$y_3 = \text{softmax}\left(\frac{q \cdot K_{[:, i_2]}^\top}{\sqrt{d_h}} + \log(m_{\hat{s}} + \epsilon)\right) \cdot V_{[:, i_2]}$$

where `m_{\hat{s}} \in \{-\infty, 0\}^k` is a mask that is `0` for the selected positions and `-\infty` (before the log) for all other positions, ensuring the softmax is computed only over the `k` selected positions, and `\epsilon \to 0` is a small constant to prevent `\log(0)`. In practice, this is implemented as standard attention using gathered key/value matrices: `K_{[:, i_2]}` and `V_{[:, i_2]}` each of size `k \times d_h`.

**What it computes:** exact attention is computed, but only over the `k` selected positions. The dot products use the full `d_h` dimensions (not the `r`-dimensional approximation), so the attention scores at the selected positions are exact. The output `y_3` is the attention-weighted sum of the `k` value vectors.

**Why this two-stage approach:** the approximate scores `\hat{s}` are used only for **ranking** positions (identifying which `k` are most important), not for computing the actual attention output. The final multiplication uses exact scores because the cost of computing exact scores for `k` positions is small (requiring `k \cdot d_h` operations for the dot products) and eliminates any approximation error in the attention weights for the selected positions. The approximation error manifests only if an important position was missed in the top-`k` selection.

The memory transfer for this step is `2 k d_h`—reading `k` full key vectors and `k` full value vectors—which is the second term in Equation (11).

#### The Full SparQ Attention Algorithm

Algorithm 1 (Figure 5) combines the query sparsity, attention score sparsity, and mean value reallocation into a complete procedure. The final output is calculated as a weighted interpolation:

$$y = \alpha \cdot y_3 + (1 - \alpha) \cdot \bar{v}$$

where `\alpha = \sum_{j \in i_2} \hat{s}_j` is the total approximate attention mass assigned to the selected top-`k` positions, computed by summing the approximate scores `\hat{s}` at the indices `i_2`.

**What it computes:** the final attention output blends the exact sparse attention result `y_3` with the mean value vector `\bar{v}`. The blending weight `\alpha` estimates what fraction of the true attention mass was captured by the `k` selected positions. If `\alpha \approx 1` (the top-`k` captured nearly all mass), the output is mostly `y_3`—the sparse computation was sufficient. If `\alpha \ll 1` (the top-`k` missed significant mass, perhaps because the query is diffuse or `k` is small), the output incorporates more of `\bar{v}`, which acts as a generic "background" value vector.

**Why this weighting scheme:** `\alpha` is estimated from the approximate scores `\hat{s}`, not the exact scores `s`, because computing exact scores would require reading the full key cache—defeating the purpose. Since `\hat{s}` is an approximation, `\alpha` is also approximate, but Figures 4f and 7b show that the approximation is well-calibrated at the proposed temperature. The interpolation with `\bar{v}` provides a graceful degradation: when the sparse approximation becomes less reliable (small `r`, small `k`, diffuse queries), the output smoothly transitions toward the mean value vector, which is correct on average, rather than producing arbitrarily wrong outputs from incorrect sparse attention.

The complete memory transfer cost for SparQ Attention on a single attention head is given in Equation (11):

$$M_{\text{SparQ}} = S r + 2 k d_h + 4 d_h$$

where the first term `S r` corresponds to reading `r` components of `K` for all `S` positions (Step 1—approximate attention scores), the second term `2 k d_h` corresponds to reading the full `K` and `V` vectors at the `k` selected positions (Step 2—exact sparse attention), and the third term `4 d_h` corresponds to the overhead of writing the current token's `k` and `v` vectors to the cache plus reading and writing the running mean `\bar{v}`.

**What it computes:** the per-head per-token memory transfer in scalar elements. For comparison against the dense baseline `M_{\text{dense}} = 2 S d_h + 2 d_h`, the compression ratio is `M_{\text{SparQ}} / M_{\text{dense}}`.

**Why these terms:** the `S r` term is the key innovation—replacing `S d_h` (reading all dimensions of all keys) with `S r` (reading only `r` dimensions of all keys), which for `r = 32` and `d_h = 128` is a 4× reduction. The `2 k d_h` term replaces `S d_h` (reading all values) with `2 k d_h` (reading `k` keys and `k` values), which for `k = 128` and `S = 4096` is a 32× reduction. The `4 d_h` overhead is negligible for large `S`. The trade-off is governed by `r` and `k`: making `r` smaller reduces the `S r` term but degrades `\hat{s}` quality; making `k` smaller reduces the `2 k d_h` term but increases the risk of missing important positions.

#### Grouped Query Attention (GQA) Modifications

For models using Grouped Query Attention (Ainslie et al., 2023), where `g` query heads share each key-value head, SparQ Attention modifies Steps 1 and 2 to aggregate information across the grouped queries. In Step 1, instead of selecting the top-`r` components of `|q|` for each query head independently, the algorithm sums `|q|` across all `g` query heads within a group before selecting the top-`r` components. This ensures the selected key dimensions are relevant to all queries in the group. The paper describes this as: "we modify Step 1 to sum `|q|` within each group before selecting top-`r` components."

In Step 2, the approximate attention scores `\hat{s}` are computed per query head as before, but then summed across the `g` query heads within a group before selecting the top-`k` positions. This produces a single set of `k` key-value positions shared by all `g` query heads. Each query head then computes its exact attention output `y_3` independently over the same `k` positions.

The paper makes a model-specific adjustment: "Although Step 3 can be implemented exactly as before, we found that GQA models obtained better performance without it, so we omitted this step for Llama 3 and Mistral." This means for these models, `\alpha` is effectively set to 1 (no mean value reallocation), and the final output is simply `y = y_3`. The authors do not provide a detailed ablation explaining why this helps, but it likely relates to the fact that GQA already averages information across query heads, potentially making the mean value correction redundant or even harmful due to the shared key-value access pattern.

#### Storing Key Cache Twice: The Dual-Layout Optimization

A practical implementation challenge arises from accessing `K` along two different axes in the two steps of SparQ Attention. In Step 1, we need the submatrix `K_{[:, i_1]}`—all `S` rows but only `r` columns (the columns corresponding to the top-`r` query dimensions). This is a columnar access pattern: for each of the `r` selected dimensions, we need that component for all `S` positions. In Step 2, we need the submatrix `K_{[:, i_2]}`—the full `d_h` columns but only `k` rows (the rows corresponding to the top-`k` positions). This is a row-wise access pattern: for each of the `k` selected positions, we need the full key vector.

If `K` were stored in a single layout, one of these access patterns would be non-contiguous—requiring strided memory access that is inefficient on GPUs and other vector processors. The paper's solution: "store K twice, in both dh-contiguous and S-contiguous layouts." The **dh-contiguous layout** stores each key vector contiguously (ideal for Step 2's row-wise access), while the **S-contiguous layout** stores each component dimension contiguously across positions (ideal for Step 1's columnar access). This increases KV cache memory usage by 50% (since K is stored twice, but V and the running mean are stored once), but "uses only a small amount of extra bandwidth to write k twice. This extra write is non-contiguous, but small, so should not form a bottleneck."

The alternative, labeled "SparQ (Triton, 1×K)" in the microbenchmarks, avoids the 50% memory overhead by storing K only once in dh-contiguous layout and accepting the cost of strided access in Step 1. This is a memory-accuracy trade-off that practitioners can choose based on their memory constraints.

#### Design Choices and Their Justifications

**Fixed `k = 128` across experiments.** The paper states: "Based on these results, we propose a simple recipe of setting `k = 128` and tuning `r` to maintain a good trade-off between data transfer and task performance for a range of models and tasks." Figure 7c (ablation) shows that `k = 128` captures most of the benefit on both SQuAD accuracy and repetition match length across a range of `r` values. Making `k` a hyperparameter to tune per-task would add complexity without commensurate gain.

**Local window of `l = k/4`.** The paper always includes the most recent 25% of the selected positions as a safety mechanism for autoregressive coherence. This is comparable to H2O's local window (also set to `k/4` in the paper's implementation) and reflects the empirical observation that recent tokens are disproportionately important in language generation, regardless of their approximate attention scores.

**L1 norm for temperature scaling.** Discussed above—chosen over L2 because it provides better calibration of the captured mass fraction, as validated in Figure 4f.

**Top-r by absolute value, not signed value.** The mask `m_q` selects the `r` largest components of `|q|` (absolute value), not `q` itself. This is because the magnitude of the dot product contribution depends on `|q_j \cdot k_{i,j}|`, not the signed product. A large negative `q_j` is just as informative as a large positive one for predicting which keys will have high attention scores. Selecting by signed value would risk missing query components that are large in magnitude but negative.

**No auxiliary model or learned predictor.** SparQ Attention uses only the query vector's own statistics to determine which positions to fetch. This is a deliberate design choice that makes the method immediately applicable to any pretrained transformer without calibration data, adaptation time, or additional parameters. The cost is that the approximation may be suboptimal compared to a learned predictor, but the paper's results suggest the natural sparsity is sufficient for up to 8× compression.

## 4. Key Insights and Innovations

### Innovation 1: The "Full Cache, Selective Fetch" Paradigm as a Third Way Between Dense Transfer and Permanent Eviction

The dominant conceptual framing for reducing attention's memory cost has been a binary choice: either transfer everything (standard dense attention) or permanently delete from the cache (eviction schemes like H2O, Scissorhands, FastGen). This framing treats the KV cache as a storage problem—if the cache is too large, throw things away. SparQ Attention introduces a fundamentally different paradigm: **keep everything, but fetch selectively per query**. The entire KV cache remains resident in memory; what changes is which subset moves across the memory bus at each generation step.

This is not an incremental optimization of eviction. It is a category shift with distinct failure modes and guarantees. Eviction schemes make an irreversible decision: once a token is deleted, no future query can ever attend to it, regardless of what information it contains. The paper's experiments expose the cost of this irreversibility starkly. On the text repetition task (Table 2), where the model must reproduce a verbatim substring from anywhere in its context, H2O drops from 229-character match length to 26 at 1/8 compression, and LM-Infinite reaches only 29. SparQ Attention achieves 190. The degradation occurs because the needed text happened to reside in a portion of the sequence that the eviction heuristic deemed unimportant at deletion time—a failure that is impossible under SparQ Attention, since the information was never deleted, only not fetched for queries that didn't need it.

The conceptual weight of this distinction becomes clearer when considering deployment diversity. An LLM serving millions of heterogeneous queries cannot predict at cache-insertion time which tokens future queries will need. An eviction policy is a bet placed without knowledge of the questions to come. SparQ Attention defers the decision to query time, when the question is known and the query vector itself encodes what information is relevant—a strictly more informed choice. This is not architecturally obvious: it requires believing that the query vector contains sufficient signal to identify relevant keys without scanning the full key cache, which is the claim the paper empirically validates.

The "selective fetch" paradigm also changes the economics of memory. Eviction schemes save both memory capacity and memory bandwidth, which seems strictly better. But the paper's analysis (Appendix F, dual-layout storage) shows that the capacity savings of eviction come at the cost of information loss, while SparQ Attention's 50% memory overhead (storing K twice) enables bandwidth savings without information loss—a trade-off that favors bandwidth-constrained but capacity-sufficient deployments, which the roofline analysis (Figure 2) suggests describes most GPU inference scenarios.

### Innovation 2: The Query Vector Itself as a Learned Index into the Key Cache

Prior work on predicting which tokens will receive high attention scores has taken two approaches: fixed structural patterns (local windows, initial tokens in LM-Infinite and StreamingLLM) or offline-learned heuristics (H2O's heavy-hitter scores accumulated during generation, FastGen's per-head strategies). Both approaches impose a model of attention sparsity that is external to the query—the sparsity pattern is either predetermined or learned from aggregate statistics, not derived from what the current query is actually looking for.

SparQ Attention makes a distinctive conceptual move: **the query vector is not just the "question" side of attention—it is also a compact, precomputed index into the key cache.** The heavy-tailed distribution of query components (Figure 4c, 4d) means that a small number of dimensions carry most of the magnitude, and the dot-product attention mechanism means these large-magnitude components dominate the similarity computation. Therefore, the indices of the top-`r` query components, together with those components of the key cache, form a learned hash function: similar keys will tend to have similar values in those high-magnitude dimensions, so the approximate dot product over `r` dimensions preserves the ranking of the full dot product.

This reframes what the query vector "is" in a way that has practical consequences. Under the standard view, the query is an intermediate activation used exclusively for computing attention scores—its internal structure (which components are large) is architecturally meaningless. Under SparQ Attention's view, the sparsity structure of the query is functionally significant: it encodes which dimensions of the key space are discriminative for this particular retrieval, and this structure can be exploited for bandwidth efficiency without any auxiliary model or separate index structure.

The significance of this reframing extends beyond the immediate bandwidth savings. It suggests that pretrained transformers have implicitly learned to organize their query representations such that a small subset of dimensions suffices for approximate key retrieval—not because they were trained to do so, but because the attention mechanism naturally encourages concentrating discriminative information in high-magnitude components when operating under the softmax's competition dynamics. This is an empirical claim about emergent structure in pretrained representations, and Figure 4e provides the validating evidence: top-`k` agreement between approximate and true scores using only the top-`r` query components reaches 0.8–1.0 for a wide range of `k` and `r` values, substantially outperforming a random low-rank projection baseline (Figure 7a).

The comparison to learned-index literature is instructive but implicit: just as learned index structures (Kraska et al., 2018) use the data distribution itself to build efficient lookup structures, SparQ Attention uses the query distribution (within a single vector) as the index. No separate training, no auxiliary data structure—the index is already there, latent in the pretrained weights and activations.

### Innovation 3: Value Auto-Correlation as a Closure Term for Sparse Approximation

When attention scores are sparse, the standard approach is to compute a weighted sum over only the high-scoring values and accept the error from dropping the rest. This is a truncation error—Equation (5) in Section 3—that becomes problematic when sparsity is aggressive (small `k`) or when the attention distribution is diffuse (the top-`k` capture only a modest fraction of total mass).

The paper's mean value reallocation correction (Equation 6, Equation 10) is more than an engineering trick. It represents a conceptual insight: **the value vectors at different sequence positions are statistically redundant enough that their mean serves as a good estimator for the aggregate of any subset.** This is not obvious a priori. Value vectors encode the information that each token contributes to the output—one might expect them to be highly diverse, since different tokens convey different meaning. Table 1 shows the opposite: the excess correlation ratio along the sequence axis is 0.14–0.26, while correlation along the layer, head, and hidden dimension axes is approximately zero. Tokens at different positions within the same sequence carry systematically similar value vectors.

Why would this be? The paper does not speculate deeply, but the finding connects to the functional role of value vectors in attention. The value projection is what the attention mechanism reads from when composing the output. If many tokens in a sequence are part of the same discourse context, describing the same entities and relationships, their value vectors will encode overlapping information. The mean value vector `\bar{v}` captures this shared background, and the attention-weighted sum over specific positions adds the token-specific deviations.

This insight transforms the sparse attention problem from one of "which values can we afford to drop" to one of "how much of the remaining mass can we approximate with a shared statistic." The interpolation weight `\alpha` estimated from approximate scores (Equation 10) becomes the critical calibration parameter: it determines how much to trust the sparse computation versus the mean-field approximation. When `\alpha \approx 1` (most mass captured by top-`k`), the output is essentially exact sparse attention. When `\alpha` is lower, the output smoothly interpolates toward the mean, which is the optimal constant prediction in the absence of position-specific information.

This is a fundamentally different error mode from truncation. Truncation produces systematic bias: the output is missing whatever information was carried by the dropped values, and that missing information could be anything. The mean reallocation correction replaces missing information with the average information, which is correct in expectation and has bounded worst-case error when value vectors are sufficiently correlated. The empirical validation comes in Figure 7b, where setting `\alpha = 0` (equivalent to `\tau \to 0`, i.e., no mean value correction) performs consistently and substantially worse than the proposed `\alpha`-interpolated version across two hyperparameter configurations.

### Innovation 4: A High-Fidelity Diagnostic That Exposes Where and Why Prior Methods Fail

The paper's evaluation setup—particularly the SQuAD with confusion contexts and the text repetition task—functions as more than a benchmark suite. It is a **diagnostic instrument** that reveals the distinct failure signatures of different sparse attention strategies. This is an underappreciated contribution: the paper doesn't just show that SparQ Attention outperforms baselines; it reveals *why* those baselines fail and provides a language for discussing those failures.

Consider the pattern across tasks in Table 2. On TriviaQA and WikiText-103, H2O performs respectably at 1/8 compression (Llama 2 13B: 78.4% accuracy and 0.64 BPC, versus SparQ Attention's 78.2% and 0.70). On SQuAD and text repetition, H2O collapses. The difference is not task difficulty per se—it is **the spatial distribution of relevant information in the context.** TriviaQA provides a single factual passage; the relevant information is concentrated. WikiText-103 requires predicting the next token given the preceding text; local context dominates. But SQuAD with confusion contexts scatters relevant information among distractors, requiring the model to distinguish signal from noise scattered throughout the sequence. Text repetition requires retrieving a specific substring that could reside anywhere.

H2O's "Heavy Hitter" eviction policy maintains tokens that historically received high attention scores. In SQuAD with distractors, tokens in the distractor paragraphs may receive modest attention simply because they are syntactically similar to the relevant context, diluting the heavy-hitter signal. The policy may retain distractor tokens while evicting tokens from the relevant context that happened to receive lower scores during the prefill phase—and once evicted, those tokens can never be recovered. SparQ Attention's per-query selection avoids this: even if distractor tokens are fetched, the exact attention computation (Step 2) using full-dimension dot products can distinguish them from genuinely relevant tokens.

The needle-in-a-haystack results (Table 3, Figure A4) provide the purest diagnostic. At compression 1/4, LM-Infinite achieves only 23.5% accuracy averaged over depths and sequence lengths—because the needle is often in the "middle" portion that its fixed window discards. H2O achieves 5.9–10.3%—because its heavy-hitter policy was not designed to preserve a single needle sentence that receives minimal attention during prefill. SparQ Attention achieves 90.4–100%—because when the query asks about the needle, the query vector's structure directs the approximate scoring to fetch the needle's keys and values, regardless of where they reside in the sequence.

This diagnostic function reframes the problem of sparse attention from a one-dimensional compression-accuracy trade-off to a multi-dimensional design space where **the statistical assumptions of the sparsity policy must match the access patterns of the downstream task.** Fixed structural patterns assume recency dominates. Eviction policies assume historical attention scores predict future relevance. SparQ Attention assumes the query vector contains sufficient signal to locate relevant keys. Each assumption breaks under different conditions, and the paper's task suite identifies which conditions matter.

This is more than an empirical contribution—it is a **conceptual framework for reasoning about sparse attention mechanisms.** Rather than asking "does method X compress well," a practitioner should ask "what access pattern does my application require, and which sparsity mechanism's assumptions align with that pattern?" The paper's results provide the evidence to ground such reasoning.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The paper constructs five task variants from existing datasets, each designed to stress-test sparse attention by requiring information retrieval and reasoning over long input sequences (Section 5.1). For question answering, **SQuAD v1.1** (Rajpurkar et al., 2016) is augmented with seven additional "confusion contexts" from unrelated questions—forcing the model to distinguish the relevant paragraph from distractors scattered throughout a 1k–2k token sequence. **TriviaQA** (Joshi et al., 2017) is used in the open-book setting. Summarization is evaluated on **CNN/DailyMail** (See et al., 2017). Language modeling uses **WikiText-103** (Merity et al., 2016) with bits-per-character (BPC) as the metric, chosen to account for vocabulary differences across models. An artificial **Text Repetition** task constructs examples from Tiny-Shakespeare (Karpathy, 2015) where the model must reproduce a verbatim substring from its context, testing precise retrieval of information that could reside anywhere in the sequence. Sequence lengths for all tasks are between 4,000 and 8,000 characters (roughly 1k–2k tokens). For the needle-in-a-haystack evaluation, the paper additionally uses essays by Paul Graham following the implementation of Dhinakaran (2024), inserting a single sentence at controlled depths across sequence lengths from 1k to 32k.

- **Base models.** Experiments span eight distinct models across five families: **Llama 2** at 7B and 13B parameters (Touvron et al., 2023), **Llama 3** at 8B (Meta AI, 2024), **Mistral** at 7B (Jiang et al., 2023), **Gemma** at 7B (Mesnard et al., 2024), and **Pythia** at 1.4B, 2.8B, and 6.9B (Biderman et al., 2023). This selection is deliberate: all are decoder-only transformers pretrained on causal language modeling with shared architectural components (rotary positional embeddings) but differing in attention mechanisms (multi-head attention with g=1 for Llama 2, Gemma, and Pythia; grouped-query attention with g=4 for Llama 3 and Mistral), normalization implementations, activation functions, and whether modules execute in parallel. The paper states (Section 5.1): "They share similar architectural components such as rotary positional embedding, while also having some notable differences such as different attention mechanisms... layer normalisation implementations, activation functions and execution of modules in parallel." Testing across both MHA and GQA variants is essential because the GQA modification to SparQ Attention differs substantially (omitting Step 3 for Llama 3 and Mistral).

- **Metrics.** Five task-specific metrics are reported (Table 2). For question answering, **exact string match accuracy** (percentage, ↑) measures whether the generated answer matches the ground truth exactly. For summarization, **ROUGE-L F-score** (Lin, 2004) quantifies the quality of generated summaries against references (↑). For language modeling, **bits per character (BPC)** (↓) is used rather than perplexity to account for vocabulary size differences across models—the authors note "We quote performance for sub-word language modelling in BPC, to account for any differences in vocabulary across models" (Section 5.1). For text repetition, **exact character length match** with the continuation from the context (↑) measures how far the model can reproduce verbatim text before diverging. No metric is aggregated into a single composite score—each task stands independently. The primary independent variable across all experiments is **attention data transfers per token**, measured in megabytes and computed from the number of scalar elements transferred multiplied by the bit-width of the representation (typically 16-bit for the KV cache).

- **Baselines.** Three methods from prior work are compared, each representing a distinct approach to attention efficiency. **H2O** (Zhang et al., 2023) is a cache eviction technique that maintains a fixed-size cache by keeping the `k - l` tokens with the highest accumulated attention scores ("heavy hitters") plus the most recent `l` tokens. The paper uses its own implementation with `l = k/4`, noting a validation study showing close agreement with the original authors' implementation on a small-scale test (Appendix G: 60/200 vs. 57/200 correct on Pythia-1.4B SQuAD, with 41/79 shared error patterns). **LM-Infinite** (Han et al., 2023) employs a fixed sparsity pattern: always include the first 16 tokens plus the most recent `k - 16` tokens, discarding everything in between. **FlexGen** (Sheng et al., 2023) uses exact attention scores computed from the full key cache but retrieves only the values corresponding to the top-k positions—limiting compression to at most 50% since K must still be fully read. FlexGen results are excluded from the main Tables 2 and 3 because its minimum compression ratio is 1/2, but appear in the full trade-off curves in Appendix A (Figures A1–A3). All baselines use the same fixed cache size `k` as SparQ Attention's top-k, enabling direct comparison at equivalent transfer budgets using the compression ratio formulas in Appendix G.

- **Generation budget / compute accounting.** The paper measures cost not in FLOPs or wall-clock time but in **attention data transfers per token**—the number of scalar elements moved between memory and the compute unit during attention, as defined by the transfer models in Equations (3) and (11). This abstraction intentionally decouples the method from specific hardware and numerical formats (Section 5.2): "The results above use a theoretical cost model of total memory transfers (the number of scalar elements transferred to and from memory per token), allowing us to evaluate SparQ Attention independently of the specific hardware setup and number formats used." The compression ratio is defined as `M_technique / M_dense` where the per-technique transfer formulas are derived in Appendix G. For SparQ Attention specifically, `M_SparQ = S r + 2 k d_h + 4 d_h` (Equation 11); for H2O, `M_H2O = 2 k d_h + 2 d_h + 2 S` (the `2 S` term accounts for writing new tokens to the full cache); for LM-Infinite, `M_LM∞ = 2 k d_h + 2 d_h`; and for FlexGen, `M_FlexGen = S d_h + k d_h + 2 d_h`. The paper sweeps `k` values across {192, 256, 384, 512, 768} for baselines and `r` across {8, 16, 32, 64} for SparQ Attention, with `k = 128` fixed for SparQ Attention (Table G1). These sweeps produce compression ratios ranging from approximately 1/2 to 1/8 versus dense, shown as vertical dotted lines in Figures A1–A3.

- **Cross-validation / statistical protocol.** The paper does not use cross-validation for strategy selection (unlike the compute-optimal paper in the reference example). Instead, results are reported as point estimates with **standard errors** computed across test examples. The paper states (Table 2 caption): "Median standard errors across all models and sparsity settings are: SQuAD 0.8, TriviaQA 0.8, CNN/DailyMail 0.4, WikiText 0.01, Repetition 2." These are plotted as shaded regions in Figures A1–A3. Figure 1 additionally shows "± one standard error over 4000 examples (the uncertainty from a finite test set)." For the needle-in-a-haystack evaluation, Table 3 reports averages over "all depths and sequence lengths S within the specified range," with full heatmaps in Figure A4 showing per-position accuracy as a binary correct/incorrect grid. The specific sample sizes: SQuAD uses 4,000 examples, TriviaQA 2,992, CNN/DailyMail 500, WikiText-103 500, Repetition 1,000 (Table G1). No statistical significance tests (t-tests, confidence intervals for differences) are reported—only standard errors and visual overlap in the compression-accuracy curves.

### Main Quantitative Results

#### Aggregate Performance Across All Tasks and Models (Table 2)

The paper's headline results appear in Table 2, which reports performance for the largest model of each family at three compression levels: 1 (dense), 1/2, and 1/8. The values presented are "those closest to the target compression ratio for each technique, where bold represents the best score for each setting."

**Overall pattern.** SparQ Attention is the only method that maintains near-dense performance across all five tasks at 1/8 compression. On SQuAD with Llama 2 13B at 1/8 compression, SparQ Attention achieves 74.9% accuracy versus 63.0% for H2O and 30.1% for LM-Infinite (dense: 80.8%). On the same model for text repetition at 1/8 compression, SparQ Attention maintains 190 characters of exact match versus 26 for H2O and 29 for LM-Infinite (dense: 229). The gap is not uniform across tasks: on TriviaQA at 1/8 compression with Llama 2 13B, SparQ Attention achieves 78.2% versus H2O's 78.4%—essentially tied, with H2O nominally ahead. On WikiText-103, H2O achieves 0.64 BPC at 1/8 compression on Llama 2 13B, notably better than SparQ Attention's 0.70 (dense: 0.61). This task-dependent variation is a key finding rather than noise—it reveals that eviction policies work well when local or concentrated information dominates (TriviaQA, WikiText-103) but fail when information is scattered (SQuAD) or requires precise retrieval from arbitrary positions (text repetition).

**Model family variation.** SparQ Attention's robustness is consistent across model families despite architectural differences. On Pythia 6.9B—a smaller, less capable model (dense SQuAD accuracy only 57.8% versus Llama 2 13B's 80.8%)—SparQ Attention at 1/8 compression achieves 57.1% accuracy, essentially maintaining the dense performance while H2O drops to 45.5% and LM-Infinite to 17.0%. This is significant because it demonstrates the method does not depend on the model having high absolute capability; it works as long as the query vectors exhibit the heavy-tailed statistics the method exploits. On Llama 3 8B (GQA, g=4), SparQ Attention at 1/8 compression achieves 78.3% SQuAD accuracy versus 61.7% for H2O, 51.8% for LM-Infinite, and the dense 81.2%. On Mistral 7B (also GQA), SparQ Attention achieves 77.5% versus 56.9% for H2O and 29.0% for LM-Infinite at 1/8. The GQA models omit SparQ Attention's Step 3 (mean value reallocation), yet still substantially outperform baselines, confirming that the query-sparsity approximation (Steps 1–2) alone provides the dominant benefit.

**Compression-accuracy trade-off curves (Figures A1–A3).** The per-model, per-task curves in Figures A1–A3 provide finer granularity than Table 2's three discrete compression levels. The x-axis is attention transfers per token in megabytes, with vertical dotted lines at 1/2×, 1/4×, and 1/8× compression versus dense. The consistent pattern: SparQ Attention's curves (blue) remain nearly flat as compression increases, often overlapping the dense baseline performance (black dotted line) down to approximately 1/8 compression, after which accuracy begins to decline. H2O's curves (orange) show earlier and steeper degradation on SQuAD and text repetition, though they track SparQ Attention more closely on TriviaQA and WikiText-103. LM-Infinite (green) shows substantial degradation across all tasks at any meaningful compression, confirming these tasks require access to non-local, non-initial information. FlexGen (red, 16-bit, appearing only in these figures) shows intermediate performance—better than LM-Infinite but generally below H2O and SparQ Attention—limited by its 50% maximum compression ratio.

The Llama 2 7B SQuAD panel is illustrative: at 128 MB/transfer (approximately dense), all methods cluster around 0.75 accuracy. At 64 MB (1/2 compression), SparQ Attention maintains roughly 0.74, H2O drops to roughly 0.68, LM-Infinite to roughly 0.52, FlexGen to roughly 0.60. At 32 MB (1/4 compression), SparQ Attention is at roughly 0.72, H2O at roughly 0.62, LM-Infinite at roughly 0.48. At 16 MB (1/8 compression), SparQ Attention is at roughly 0.65, H2O at roughly 0.52, and LM-Infinite has collapsed to roughly 0.44. The shaded standard error bands show that SparQ Attention's higher mean performance is consistently outside the uncertainty ranges of the baselines at moderate-to-high compression.

#### Sequence Length Scaling (Section 5.3)

The main experiments use sequences of 1k–2k tokens, but practical LLM deployments involve much longer contexts. Two additional evaluations test behavior at extended lengths.

**SQuAD with increasing confusion contexts (Figure 6).** Using Vicuna 1.5 7B (a Llama 2 descendant fine-tuned for 16k context), the SQuAD task is modified to include 7 to 63 confusion contexts, producing sequence lengths from roughly 2,000 to over 12,000 tokens. Both SparQ Attention and H2O are configured at a fixed 1/4 compression ratio (SparQ Attention: `r = 32`, `k` adjusted to maintain compression; H2O: `l = k/4`). The dense baseline's SQuAD accuracy declines from roughly 0.65 at 2,000 tokens to roughly 0.55 at 12,000 tokens—attributed by the authors to "an artefact of the RoPE scaling and fine-tuning procedure used to extend the context window of the Vicuna model." SparQ Attention tracks the dense baseline almost perfectly across the full range, maintaining performance within the standard error envelope. H2O, in contrast, shows a steeper decline: at roughly 6,000 tokens, H2O drops to approximately 0.45 versus SparQ Attention and dense at roughly 0.58; at 12,000 tokens, H2O reaches approximately 0.35 versus roughly 0.55. The paper notes: "SparQ Attention is scalable to large sequences, as it can maintain performance up to 128k sequence length." (The figure actually shows up to ~12k tokens; the 128k claim appears to reference the needle-in-a-haystack evaluation or a model-specific maximum, though the plotted range in Figure 6 extends only to ~12,000.)

**Needle in a haystack (Table 3, Figure A4).** Using the `togethercomputer/LLaMA-2-7B-32K` model, a single sentence ("The best thing to do in San Francisco is eat a sandwich and sit in Dolores Park on a sunny day") is inserted at various depths (0% to 100% of sequence length) within essays by Paul Graham, across sequence lengths from 1k to 32k tokens. The model is asked what the best thing to do in San Francisco is, and the answer is scored as correct (blue) or incorrect (red) in Figure A4 heatmaps. Table 3 aggregates these results by reporting average accuracy across all depths for three sequence-length ranges.

At compression 1 (dense), accuracy is 100% for sequences up to 24k and 90.4% for 24k–32k—the model nearly always finds the needle. At compression 1/4, LM-Infinite achieves only 23.5% across all three sequence-length ranges, H2O achieves 5.9%–10.3%, and SparQ Attention achieves 100% for 8k–24k and 90.4% for 24k–32k—essentially identical to dense. At compression 1/8, SparQ Attention achieves 79.4% for 8k–16k and 100% for 16k–24k, 87.5% for 24k–32k, while H2O drops to 2.9%–5.9% and LM-Infinite to 11.8%. The heatmaps (Figure A4) reveal the spatial pattern of failures: H2O fails across essentially all depths—its eviction policy simply does not preserve the needle. LM-Infinite succeeds only when the needle is near the beginning or end of the sequence (the "initial tokens" and "recent tokens" windows), failing entirely in the middle 60–80% of depths. SparQ Attention's sparse failures at 1/8 compression cluster at intermediate depths and long sequences, suggesting the approximation degrades when the needle's position requires distinguishing it from a large volume of similar text.

These results directly validate the paper's central diagnostic claim: SparQ Attention's per-query selection mechanism preserves information that fixed-structural-pattern (LM-Infinite) and eviction-based (H2O) methods permanently lose.

#### FLOPs-Matched / Speedup Benchmarks (Section 6)

While the main results use a theoretical transfer model, Section 6 validates that the transfer savings translate to actual wall-clock speedups.

**Microbenchmarks (Table 4, Figure 8).** On GPU using Llama 2 7B shape parameters (`d_h = 128`, 32 heads, batch size 64, `r = 32`, `k = 128`), the dense baseline (using the faster of PyTorch or built-in scaled dot product attention) achieves 49 µs/query on A100 (40GB). SparQ Attention with Triton kernels and dual K storage ("SparQ (Triton)") achieves 16 µs/query for a 3.02× speedup on A100 and 31 µs/query (4.17× speedup) on A10G at `S = 4096`. The theoretical speedup for this configuration is 6.4×, indicating implementation overhead. As sequence length increases (Figure 8, A100), the dense baseline scales roughly linearly from 8 µs at `S = 2048` to 256 µs at `S = 16384`, while SparQ Attention (Triton) scales from roughly 5 µs to roughly 80 µs—the gap widens with sequence length because the transfer savings compound. The single-copy variant ("SparQ (Triton, 1×K)") without dual-layout storage achieves 38 µs (1.28× speedup) on A100 at `S = 4096`, substantially slower than the dual-layout version, confirming that non-contiguous memory access in Step 1 imposes a significant penalty if not mitigated by the second layout. On IPU (Bow Pod16, batch size 1, `S = 16384`), the dense baseline achieves 40.4 ms/query while SparQ Attention (`r = 32`, `k = 128`) achieves 5.28 ms/query—a 7.41× speedup, nearly matching the theoretical 7.53×. The paper explains: "This near-perfect speedup is achieved because attention is strongly memory bound when using remote memory" on IPU, whereas GPU's high-bandwidth memory (HBM) makes the bandwidth bottleneck less severe at small scales.

**End-to-end benchmarks (Figures 9, 10).** On CPU (AMD EPYC, batch size 1, 1/8 compression), SparQ Attention implemented in llama.cpp achieves speedups that grow with sequence length: from near 1× at `S = 2^{12} \approx 4096` to approximately 2.5× at `S = 2^{17} \approx 131,072`. The theoretical `M_dense / M_SparQ` line (dashed) shows the upper bound—the gap between achieved and theoretical widens with sequence length, reflecting implementation overhead and non-attention computation. On GPU (H100 PCIe, batch size 1, 1/8 compression), the pattern is similar but with smaller absolute speedups: roughly 1.1× at `S = 4096`, rising to roughly 2.2× at `S = 2^{15} \approx 32,768`. The theoretical line (again dashed) exceeds the achieved speedups, indicating that GPU inference at batch size 1 is less severely bandwidth-bound than the roofline model predicts—likely because HBM bandwidth is high enough that compute and data transfer overlap partially, or because the implementation is not fully optimized for single-sample inference.

These benchmarks are important because they validate the paper's central cost model: measuring compression in scalar elements transferred is a reasonable proxy for wall-clock time, but the conversion factor depends on hardware (near-perfect on bandwidth-starved IPU, less than theoretical on GPU) and on batch size (Figure F1 shows that speedups are available across batch sizes 1–64 and sequence lengths 1,024–65,536, with the most significant speedups at large `batch_size × sequence_length` products).

### Ablation Studies and Robustness Checks

**Key cache compression mechanism (Figure 7a):** To isolate the contribution of the query-sparsity approximation (Step 1) from the overall SparQ Attention pipeline, the paper compares three variants on Llama 2 7B SQuAD: (a) an **oracle** that provides the exact top-k keys without any data transfer to compute the top-k—this is the theoretical upper bound for any selective-fetching scheme; (b) SparQ Attention; and (c) a **random low-rank projection** where `K` is projected using a random matrix rather than the top-r query components. The oracle achieves roughly 0.78 accuracy at 32 MB/transfer, SparQ Attention achieves roughly 0.75—a gap of only ~0.03—while the random projection achieves roughly 0.62. At 64 MB/transfer, SparQ Attention (roughly 0.78) is nearly indistinguishable from the oracle (roughly 0.79), and the random projection is at roughly 0.70. This ablation directly tests the paper's claim that the top-r query components carry discriminative information for key retrieval: if the specific choice of `r` components didn't matter, the random projection would perform comparably. The substantial gap between SparQ Attention and the random projection validates that the heavy-tailed query structure is functionally meaningful for approximate attention scoring, not merely a statistical curiosity. The narrow gap to the oracle indicates that further improvements to Step 1 (better query-based approximations) would yield only marginal gains—most of the remaining error comes from the sparsity of attention scores themselves (k = 128 being insufficient for some heads/queries), not from misidentification of which positions should be in the top-k.

**Softmax temperature for approximate scores (Figure 7b):** Five temperature settings are compared on Llama 2 7B SQuAD at two hyperparameter configurations (`k = 128, r = 32` and `k = 128, r = 64`): (a) the proposed L1-coverage-weighted temperature `\tau = \sqrt{d_h \cdot \|q \circ m_q\|_1 / \|q\|_1}`, (b) `\tau = \sqrt{d_h}` (full-dimension temperature), (c) `\tau = \sqrt{r}` (reduced-dimension temperature), (d) `\tau \to 0` (limiting case, corresponding to `\alpha = 1`, i.e., no mean value reallocation), and (e) `\lim_{x \to 0} x` (described in the figure; likely a very small fixed temperature). For the `r = 32` configuration, the proposed temperature achieves roughly 0.745 accuracy, `\sqrt{d_h}` achieves roughly 0.735, `\sqrt{r}` achieves roughly 0.725, and the `\tau \to 0` variant achieves roughly 0.710. For `r = 64`, the proposed temperature achieves roughly 0.755, `\sqrt{d_h}` achieves roughly 0.745, `\sqrt{r}` achieves roughly 0.740, and `\tau \to 0` achieves roughly 0.720. The consistent ordering—proposed > `\sqrt{d_h}` > `\sqrt{r}` > `\tau \to 0`—confirms that (1) the L1-coverage interpolation between the two extreme temperatures provides a genuine improvement, (2) using the full `\sqrt{d_h}` temperature is too conservative (scores are too diffuse, reducing discrimination), (3) using `\sqrt{r}` is too aggressive (scores are too sharp, amplifying noise in the approximate dot products), and (4) omitting the mean value correction (`\tau \to 0`, `\alpha = 1`) is consistently the worst option. The gap is modest—roughly 0.03–0.04 accuracy between best and worst—but consistent and statistically meaningful given the standard error of 0.8 on this task.

**Hyperparameter interaction of `r` and `k` (Figure 7c):** On Llama 2 7B, both SQuAD accuracy and text repetition match length are evaluated across `k` values {32, 64, 128, 256} and `r` values {16, 32, 64}, plotted against attention transfers per token (MB) to show the compression-accuracy frontier. On SQuAD, the envelope of points shows that at a given transfer budget (e.g., 64 MB), larger `k` with smaller `r` outperforms smaller `k` with larger `r`: `(k=256, r=16)` achieves roughly 0.75 accuracy while `(k=64, r=64)` achieves roughly 0.72. On text repetition, the same pattern holds but with a stronger dependence on `k`: at 64 MB, `k=128` achieves roughly 175-character match, `k=256` achieves roughly 190, and `k=64` drops to roughly 140. The paper's recommendation—"a simple recipe of setting `k = 128` and tuning `r` to maintain a good trade-off between data transfer and task performance"—is based on these curves: `k = 128` captures most of the benefit (diminishing returns to `k = 256` are small) while allowing `r` to be tuned downward for compression or upward for accuracy. The `r = 16` and `r = 32` configurations at `k = 128` provide good operating points across all transfer budgets.

**GQA model variant (Step 3 omission):** The paper reports (Section 4) that for Llama 3 and Mistral (both GQA models), "we found that GQA models obtained better performance without [Step 3], so we omitted this step." No ablation figure is provided specifically isolating this effect. However, the performance of these models in Table 2 provides indirect evidence: Mistral 7B with SparQ Attention at 1/8 compression achieves 77.5% on SQuAD, 79.0% on TriviaQA, and 23.0% ROUGE-L on CNN/DailyMail—all very close to dense. If omitting Step 3 were harmful, these results would show degradation. The fact that they do not suggests that for GQA architectures, the query-aggregation in Steps 1–2 is sufficient for accurate sparse attention, and the mean value reallocation may introduce a source of error (due to query-head-specific value expectations that the shared mean cannot satisfy). This is a notable **negative result** about the interaction between SparQ Attention's correction mechanism and GQA's head-sharing architecture, but the lack of a dedicated ablation limits detailed understanding.

**Sequence-length scaling with fixed compression (Figure 6):** This serves as an ablation on the interaction between compression ratio and sequence length. By fixing `r = 32` and adjusting `k` to maintain a constant 1/4 compression as `S` increases, the experiment tests whether SparQ Attention's approximation quality degrades with sequence length independent of compression ratio. The result—performance tracks dense closely from 2k to 12k tokens—indicates that SparQ Attention's per-query selection scales well: longer sequences provide more distractors but the query-sparsity mechanism (top-r components) remains discriminative, and the top-k selection (with fixed compression ratio, meaning `k` grows proportionally to `S`) captures a sufficient number of positions. This is not a foregone conclusion: one could imagine that as sequence length increases, the approximate scores become less reliable (more positions to rank, more opportunity for noise in the approximate dot products to mis-rank), requiring larger `r` or `k` to maintain accuracy. The empirical result suggests this is not a problem up to at least 12k tokens and 1/4 compression.

**Effect of the local window:** The paper includes a local window of `l = k/4` positions (always including the most recent tokens regardless of approximate scores) but does not provide a dedicated ablation on the effect of this window. The choice is justified by analogy to H2O and LM-Infinite (which also include local windows) and the known importance of recency for autoregressive coherence, but the size (`k/4`) appears to be selected heuristically. In the needle-in-a-haystack evaluation, the local window could not help locate the needle (since the needle is not necessarily recent), so SparQ Attention's strong performance there is attributable entirely to the query-sparsity mechanism, not the window. In the main tasks (e.g., SQuAD with confusion contexts, repetition), the local window may contribute to stability—preventing the model from "losing its place" in the local discourse—but its quantitative contribution is not isolated.

**Dual-layout K storage (Table 4, Figure F1):** The microbenchmark results include a variant "SparQ (Triton, 1×K)" that stores K only in dh-contiguous layout, trading memory overhead for slower Step 1. On A100 at `S = 4096`, batch size 64, this variant achieves 38 µs/query (1.28× speedup over dense) compared to 16 µs/query (3.02×) for dual-layout storage. On A10G, 1×K achieves 79 µs (1.63×) versus 31 µs (4.17×) for dual-layout. The gap—roughly 2.4×—demonstrates that strided memory access in Step 1 (gathering `r` components across all `S` positions from a dh-contiguous layout) is severely penalized on GPU hardware with its cache-line-based memory system. This ablation quantifies the cost of not using dual-layout storage: the 50% memory overhead buys a 2–3× speedup in the attention operation itself.

### Critical Assessment

#### Claim 1: "SparQ Attention brings up to 8× savings in attention data transfers without substantial drops in accuracy" (Abstract)

**What the experiments actually demonstrate:** Table 2 and Figures A1–A3 show that at 1/8 compression, SparQ Attention maintains accuracy within a few percentage points of dense on most tasks and models. However, the claim of "without substantial drops" requires careful qualification.

On **SQuAD**, the evidence is strong for most models: Llama 2 13B drops from 80.8% to 74.9% at 1/8 (Δ = -5.9pp), Llama 3 8B drops from 81.2% to 78.3% (Δ = -2.9pp), Gemma 7B drops from 80.4% to 80.3% (essentially flat), Pythia 6.9B drops from 57.8% to 57.1% (Δ = -0.7pp). These are genuinely small degradations. However, Mistral 7B drops from 81.0% to 77.5% (Δ = -3.5pp) and Llama 2 7B in Figure A1 drops from roughly 0.75 to roughly 0.65 at 1/8 compression (Δ ≈ 10pp, visually estimated from the transfer curves). The 7B Llama 2 result, in particular, suggests that model size interacts with compression tolerance—smaller models may be more sensitive to approximation error because their attention patterns are less sharply concentrated or their query vectors less heavy-tailed. The paper does not analyze this interaction.

On **TriviaQA**, the evidence is more mixed: Llama 2 13B at 1/8 compression achieves 78.2% versus dense 78.7% (Δ = -0.5pp)—excellent. But H2O achieves 78.4% at the same compression—nominally better. On Gemma 7B, SparQ Attention achieves 82.7% at 1/8 versus dense 82.8% (Δ = -0.1pp), while H2O achieves 82.5%. On this task, the performance ordering between SparQ Attention and H2O is not consistently in SparQ Attention's favor. The paper's claim that SparQ Attention is superior is task-dependent: on tasks requiring precise retrieval from arbitrary positions (SQuAD, repetition), the advantage is clear; on tasks where information is concentrated or local (TriviaQA, WikiText-103), H2O is competitive or better.

On **Text Repetition**, the advantage is dramatic and unambiguous: at 1/8 compression on Llama 2 13B, SparQ Attention achieves 190 characters of exact match versus 26 for H2O and 29 for LM-Infinite (dense: 229). This is the strongest evidence for the paper's central argument—that eviction policies permanently lose information needed by later queries, while selective fetching preserves it. However, even SparQ Attention shows a non-trivial drop from 229 to 190 (Δ = -39 characters, 17% relative), so "without substantial drops" is debatable for this task.

**Missing evaluation:** The paper does not report the specific hyperparameters (`r`, `k`) used to achieve the 1/8 compression points in Table 2. Given that `k = 128` is fixed across experiments, `r` must be set to achieve the target compression. For Llama 2 13B with `d_h = 128` and `S ≈ 2000`, achieving 1/8 compression requires `r ≈ 16` (solving `(2000×r + 2×128×128 + 4×128) / (2×2000×128) ≈ 1/8`). But Figure 7c shows that `r = 16` with `k = 128` produces noticeably lower SQuAD accuracy than `r = 32` or `r = 64`—the 1/8 compression points in Table 2 may be using configurations at the edge of SparQ Attention's reliable operating range. The paper does not report whether other hyperparameter configurations could achieve similar compression with better accuracy (e.g., smaller `k` with larger `r`).

**What the "8×" claim means:** The compression ratio is defined relative to attention data transfers only (Equation 11 vs. Equation 3), not end-to-end inference time. The end-to-end speedups (Figures 9, 10) are more modest: approximately 2.5× on CPU at long sequence lengths, approximately 2.2× on GPU. This is because non-attention computation and transfer (parameter fetching, MLP layers, layer norms) are not compressed by SparQ Attention. The 8× figure is a theoretical upper bound on attention compression; the realized end-to-end speedup depends on the fraction of time spent in attention (Figure 3), which varies with hardware and sequence length. This is not a weakness of the method—it accurately reflects that SparQ Attention targets the dominant bottleneck—but the abstract's "up to 8× savings in attention data transfers" may be misinterpreted as end-to-end speedup by readers who don't distinguish the two.

#### Claim 2: SparQ Attention requires "no modification to the pre-training setup or additional fine-tuning" (Abstract, Section 1)

**What the experiments actually demonstrate:** All results use off-the-shelf pretrained models with SparQ Attention applied as a drop-in replacement for standard attention at inference time. No fine-tuning, no architecture modification, no calibration data. This is correctly and fully supported by the experimental design.

**Nuance the claim misses:** While no model modification is required, the implementation does require **dual-layout storage of the key cache** (S-major and dh-major) to achieve efficient memory access in both Step 1 (columnar gather) and Step 2 (row-wise gather). This increases KV cache memory usage by 50% (since K is stored twice). The paper acknowledges this explicitly (Section 6.1) and provides a single-copy variant ("SparQ (Triton, 1×K)") that avoids the memory overhead but delivers only 1.28× speedup on A100 versus 3.02× for dual-layout. In memory-constrained deployments—which is precisely the regime where KV cache size is a problem—this 50% overhead may be prohibitive, effectively trading memory capacity for memory bandwidth in a way that isn't captured by the "no modification" framing. The paper does not report memory usage numbers; a practitioner would need to evaluate whether their deployment can absorb the overhead.

Additionally, for GQA models (Llama 3, Mistral), the method omits Step 3 (mean value reallocation), which constitutes a model-specific modification to the algorithm. This is a minor point—the algorithm adapts to the model architecture—but "applied directly to off-the-shelf LLMs" might suggest a single universal implementation, whereas practitioners need to know whether their model uses MHA or GQA.

#### Claim 3: SparQ Attention is "robust across numerous tasks and models" (Section 8)

**What the experiments actually demonstrate:** Five model families (eight specific model variants) and five task types are evaluated. This is substantially broader than many papers in this area (which often evaluate on a single model family), and the consistency of SparQ Attention's advantage over baselines across Llama 2, Llama 3, Mistral, Gemma, and Pythia is genuine evidence of robustness.

**Genuine weaknesses:**

1. **No models beyond 13B parameters.** All evaluations use models from 1.4B to 13B parameters. The paper does not test Llama 2 70B, Llama 3 70B, or any model at the scale of current frontier deployments. Larger models may exhibit different attention sparsity patterns (e.g., more specialized heads, more diffuse attention for some head types), and it is unknown whether SparQ Attention's hyperparameters (`k = 128`, `r = 32`) would transfer. The paper's claim of robustness across "model sizes up to 13 billion parameters" (Section 5.1) is accurate as stated but bounds the claim.

2. **No non-English evaluation.** All tasks are in English. Query vector sparsity patterns (heavy-tailedness) might differ for languages with different morphological or syntactic properties, potentially affecting the top-r approximation. This is not tested.

3. **No code generation or mathematical reasoning tasks.** The evaluation suite covers question answering, summarization, language modeling, and text repetition—all natural language tasks. Code generation, which often requires attending to specific variable definitions or function signatures scattered throughout long files, would be a natural stress test for sparse attention. Mathematical reasoning, where attention to specific numbers or equations matters, is also absent. The paper acknowledges none of these gaps.

4. **The hyperparameter recommendation (`k = 128`, tune `r`) is derived from Llama 2 7B ablations (Figure 7c) but applied to all models.** The paper does not show whether this recommendation is optimal or even good for other model families. The Gemma 7B model has `d_h = 256` (Table G1) rather than the `d_h = 128` used in Llama 2 ablations, meaning the fraction of key dimensions read by `r = 32` is half as large (32/256 = 12.5% versus 32/128 = 25%). This could affect approximation quality, yet no per-model hyperparameter sensitivity analysis is reported for non-Llama models.

5. **Standard errors are reported but no formal statistical comparisons.** The median standard errors (Table 2 caption) are: SQuAD 0.8, TriviaQA 0.8, CNN/DailyMail 0.4, WikiText 0.01, Repetition 2. These are small relative to the gaps between SparQ Attention and baselines on SQuAD and repetition, but on TriviaQA (where the gaps are small, e.g., Llama 2 13B at 1/8 compression: SparQ 78.2% vs. H2O 78.4%), the difference is within one standard error. The paper does not claim significance where unsupported, but the visual presentation (bold in Table 2 for the "best" score) can overstate the reliability of small differences.

#### Claim 4: SparQ Attention "maintains the full KV cache in memory" unlike eviction schemes (Section 8)

**What the experiments actually demonstrate:** The paper's strongest results—SQuAD with confusion contexts, needle in a haystack—directly test the consequences of this design choice. In both cases, SparQ Attention dramatically outperforms eviction-based H2O and structural-sparsity-based LM-Infinite. The needle-in-a-haystack heatmaps (Figure A4) provide particularly clean evidence: SparQ Attention's failures at 1/8 compression cluster at specific (depth, length) combinations and recover at 1/4 compression, while H2O and LM-Infinite show systematic failures across nearly all depths and fail to recover even at 1/4 compression. This is exactly the pattern predicted by the "full cache, selective fetch" paradigm: SparQ Attention can attend to any position when the query demands it (accuracy recovers when compression is relaxed), while eviction schemes cannot (accuracy remains low regardless of compression because the information was deleted).

**Nuance:** However, the paper does not directly measure whether SparQ Attention's failures are due to mis-ranking in Step 1 (wrong keys identified as top-k) or insufficient `k` (the right keys were identified but there were more than `k` of them, so some were truncated). The ablation in Figure 7a (oracle top-k) partially addresses this: the gap between SparQ Attention and the oracle is small, suggesting mis-ranking is not the dominant error source. But this ablation is only for Llama 2 7B on SQuAD at specific hyperparameters—it does not characterize the error decomposition across tasks, models, and compression levels.

#### What Experiments Would Have Strengthened the Paper

- **A direct measurement of top-k recall**: what fraction of the true top-k positions (by exact attention scores) are correctly identified by the approximate scores `\hat{s}`? This would provide a task-independent diagnostic of Step 1's quality, decoupled from downstream task performance. The paper presents top-k agreement in Figure 4e, but only for 40 SQuAD queries on Llama 2 7B—not as a systematic evaluation across models, layers, and tasks.

- **Per-layer or per-head analysis of SparQ Attention's approximation quality**: Figure 4b shows that attention sparsity varies across heads—some heads are diffuse, some are concentrated. Does SparQ Attention perform uniformly across all heads, or do sparse heads compensate for diffuse ones? Per-head analysis would reveal whether head-specific hyperparameters (`r` and `k` varying by head) could improve the compression-accuracy frontier, or whether the current uniform setting leaves performance on the table for diffuse heads.

- **Comparison to a learned top-k predictor**: SparQ Attention uses a fixed rule (top-r query components by magnitude) to predict which keys are relevant. A natural baseline would be a lightweight learned predictor—perhaps a small MLP or even a linear projection—trained to predict top-k membership from the query vector alone. This would calibrate how much room for improvement exists beyond SparQ Attention's hand-designed approximation.

- **Prefill-stage behavior**: All experiments and benchmarks evaluate autoregressive generation (token-by-token decoding). The prefill stage (processing the input prompt) involves different computational patterns—all queries attend to all previous keys in parallel rather than sequentially. The paper does not discuss whether SparQ Attention applies during prefill or only during generation, how it would be adapted (the mean value vector `\bar{v}` would not exist before the sequence is processed), or what the bandwidth implications are.

- **Interaction with KV cache quantization**: The paper mentions (Section 7) that "4-bit compression is complementary to techniques that reduce the number of transferred elements," but does not test the combination. Quantized 4-bit KV caches plus SparQ Attention's selective fetching could compound bandwidth savings; alternatively, quantization noise might degrade the approximate scoring in Step 1 more than expected. This interaction is an open question.

- **Batch size sensitivity of end-to-end speedups**: The GPU microbenchmarks use batch size 64, and Figure F1 shows speedups across batch sizes 1–64, but the end-to-end benchmarks (Figures 9, 10) use batch size 1. Since SparQ Attention's transfer savings scale with batch size (the `S r` term is multiplied by batch size), larger batches should show larger absolute speedups. Characterizing this relationship for realistic deployment batch sizes (1–32) would strengthen the practical case.

#### Summary Assessment

The experiments provide **strong evidence for the paper's central mechanism**: query-sparsity-based approximate scoring can identify relevant keys accurately enough to enable substantial bandwidth savings without permanent information loss, outperforming eviction-based and structural-sparsity baselines on tasks requiring flexible access to scattered information. The evidence is **weaker for the universality of the "8× compression without substantial drops" claim**: some models (Llama 2 7B) and some tasks (text repetition) show non-trivial degradation at 1/8 compression, and the end-to-end speedups are more modest (2–2.5×) than the attention-only compression ratio suggests. The evaluation across five model families is a genuine strength, but the absence of models larger than 13B, non-English tasks, code generation, and formal statistical comparisons limits the scope of the robustness claim. The needle-in-a-haystack evaluation is particularly persuasive as a diagnostic of the method's information-preservation properties, but the paper would benefit from a more systematic decomposition of where and why SparQ Attention's approximation fails (mis-ranking vs. insufficient `k`, per-head variation, sequence-length scaling of approximation quality beyond 12k tokens).

## 6. Limitations and Trade-offs

### The 50% Memory Overhead for Dual-Layout Key Storage

**The assumption or constraint.** SparQ Attention requires storing the key cache in two layouts—one contiguously along the sequence dimension (S-major) and one contiguously along the hidden dimension (dh-major)—to enable efficient gather operations in both Step 1 (columnar access) and Step 2 (row-wise access). The paper acknowledges this explicitly in Section 6: "This increases KV cache memory usage by 50%, but uses only a small amount of extra bandwidth to write k twice." The single-copy variant ("SparQ (Triton, 1×K)") is presented as an alternative, but its achieved speedup in Table 4—only 1.28× on A100 and 1.63× on A10G versus 3.02× and 4.17× for dual-layout—reveals how severely the design depends on this overhead to deliver meaningful gains.

**The consequence.** The 50% KV cache memory increase directly competes with the very problem SparQ Attention purports to solve. The paper's motivation (Section 2) frames memory bandwidth as the bottleneck, but in practice, memory capacity and bandwidth are coupled: the reason long-sequence batched inference is bandwidth-bound is precisely because the KV cache has grown large enough to stress both. Adding 50% to the key cache footprint may push deployments that are already memory-capacity-constrained—for instance, serving multiple users with long contexts on a single GPU with limited HBM—over the edge into out-of-memory failures or forced reduction in batch size, which itself reduces throughput and increases per-query cost. The trade-off is not just memory-for-speed; it is memory-for-speed with a risk of memory-for-availability. For a practitioner evaluating whether to deploy SparQ Attention, the question is not "does it reduce data transfer" but "can my hardware absorb a 50% KV cache increase while maintaining the batch size that makes the bandwidth bottleneck binding in the first place?"

**What evidence exists in the paper.** Table 4 and Figure F1 provide the direct comparison between dual-layout and single-copy implementations. On A100 at `S = 4096`, batch size 64, the single-copy variant's 1.28× speedup versus 3.02× demonstrates that the memory overhead is not an optional optimization—it is essential for competitive performance. The IPU microbenchmarks (Section 6.1) are reported only in the dual-layout configuration (7.41× speedup), meaning the paper's most dramatic result does not generalize to the memory-saving variant. The paper does not report peak memory usage for any end-to-end benchmark, does not measure the maximum batch size or sequence length achievable with and without dual-layout storage, and provides no guidance on when the overhead is acceptable versus prohibitive. Figure F1 aggregates speedup across batch sizes and sequence lengths for different `r` values, but does not break out whether certain configurations of `(batch size, sequence length)` run out of memory with dual-layout storage where single-copy would fit.

**Mitigation status.** The paper acknowledges the overhead and provides the single-copy variant as a fallback, but does not quantify the memory-capacity trade-off in concrete deployment terms. There is no exploration of alternative layouts (e.g., storing K once in a blocked or tiled format that partially mitigates strided access without full duplication), no measurement of whether the overhead can be reduced by only duplicating a subset of layers or heads, and no analysis of whether the overhead interacts with other memory-saving techniques like KV cache quantization. The statement that the extra write "is non-contiguous, but small, so should not form a bottleneck" (Appendix F) addresses a secondary concern (write bandwidth) without engaging the primary one (capacity).

### No Direct Measurement of Top-K Recall—The Core Mechanism's Accuracy Is Inferred from Downstream Tasks

**The assumption or constraint.** SparQ Attention's central claim is that the top-r query components, combined with the corresponding key cache dimensions, produce approximate attention scores `\hat{s}` that correctly identify which positions would have the highest true attention scores. The correctness of the entire method depends on this ranking: if `\hat{s}` frequently misses genuinely important positions, the sparse attention computation in Step 2 operates on the wrong subset of keys and values, and no amount of mean value reallocation can compensate. The paper validates this assumption indirectly through downstream task performance (accuracy, ROUGE-L, BPC, repetition length) and through Figure 4e, which reports "top-k agreement between approximate and true scores" for 40 SQuAD queries on a single model (Llama 2 7B). It does not report top-k recall—the fraction of the true top-k positions that are correctly included in the approximate top-k—as a systematic metric across models, layers, heads, tasks, or compression levels.

**The consequence.** Without a direct measurement of top-k recall, the paper cannot diagnose *why* SparQ Attention fails when it does. Consider the text repetition task at 1/8 compression on Llama 2 13B: SparQ Attention drops from 229 to 190 characters of exact match (Table 2). Is this because (a) Step 1 mis-identified which positions contained the relevant continuation, due to the query lacking sufficient signal in its top-r components? Or (b) Step 1 correctly identified the relevant positions, but there were more than `k = 128` of them (the continuation spans many tokens, each of which may attend to multiple preceding positions), and the truncation to `k` omitted some needed keys? Or (c) the approximate attention scores correctly ranked the keys, but the mean value reallocation in Step 3 introduced error by blending the sparse attention output with `\bar{v}` using a poorly-calibrated `\alpha`? These error sources suggest different remedies—larger `r` (if query sparsity is too aggressive), larger `k` (if score sparsity is too aggressive), or omitting Step 3 (if the mean value correction is harmful for this task), and the ablation in Figure 7c explores some of these trade-offs but not in a way that isolates the failure mechanism.

For a practitioner, this diagnostic gap has practical implications. If the dominant error source is query sparsity (type a), switching to a GQA model (which aggregates query information before selecting top-r components) might help. If it is score sparsity (type b), increasing `k` is the fix, but at the cost of lower compression. If it is mean value reallocation (type c), the GQA models' approach of omitting Step 3 might be preferable. The paper provides no guidance on distinguishing these cases from observable behavior.

**What evidence exists in the paper.** Figure 4e reports top-k agreement for Llama 2 7B across various `(r, k)` pairs, showing values between roughly 0.6 and 0.95 depending on configuration—but this is a single data point averaged over 40 queries without per-layer or per-head breakdown. The oracle ablation in Figure 7a compares SparQ Attention to an oracle that provides the exact top-k positions without data transfer cost. The gap between SparQ Attention (~0.75 accuracy) and the oracle (~0.78) at 32 MB/transfer is modest—roughly 0.03—suggesting that mis-ranking is not the dominant error source at this operating point. However, this is one model (Llama 2 7B), one task (SQuAD), and a specific compression ratio. It does not characterize how the gap changes with sequence length (longer sequences mean more positions to mis-rank), with model size (larger models may have more discriminative query representations, reducing mis-ranking), or with task type (text repetition may require more precise retrieval than SQuAD).

**Mitigation status.** The oracle ablation in Figure 7a partially addresses this gap by providing an upper bound on performance if ranking were perfect, but it does not decompose the error further. The paper does not suggest future work on diagnostic metrics for sparse attention mechanisms, nor does it provide per-head or per-layer analysis of approximation quality that might reveal which architectural features predict ranking accuracy.

### No Evaluation on Code Generation, Mathematical Reasoning, or Non-English Tasks

**The assumption or constraint.** All five evaluation tasks—SQuAD, TriviaQA, CNN/DailyMail, WikiText-103, and Text Repetition—are English natural language tasks. The paper does not test on code generation (e.g., HumanEval, MBPP), mathematical reasoning (e.g., GSM8K, MATH), multi-lingual benchmarks, or tasks where attention patterns might differ fundamentally from the English prose setting. The authors do not explicitly acknowledge this as a limitation, though the scope is stated clearly in Section 5.1: "our evaluation setup consists of various tasks requiring information retrieval and reasoning over long input sequences."

**The consequence.** The generalizability of SparQ Attention's core mechanism—query sparsity enabling cheap approximate key retrieval—depends on the statistical properties of query vectors, key vectors, and attention patterns in the pretrained model. Different task domains may produce systematically different statistics. In code generation, attention often involves precise lookups to specific variable definitions, function signatures, or import statements scattered throughout a file. These lookups may require attending to tokens with specific syntactic roles (identifiers) that do not necessarily correspond to high query-vector magnitude in a pretrained model's representation, because magnitude may encode semantic rather than syntactic salience. If the top-r query components capture semantic dimensions (what the code is about) rather than syntactic dimensions (which variable name matches), the approximate scoring in Step 1 might systematically miss the keys needed for correct code generation. Similarly, mathematical reasoning often requires attending to specific numbers, operators, and equals signs with exact precision—attention patterns that may be more diffuse across the sequence or more dependent on specific low-magnitude query dimensions that would be discarded by the top-r selection. In multi-lingual settings, the heavy-tailed distribution of query components observed for English (Figure 4c, 4d) may not hold for languages with different morphological structures, different tokenization properties, or different pretraining data distributions—and the paper provides no evidence either way.

**What evidence exists in the paper.** None. The paper reports no experiments on code, math, or non-English data. This is a scope limitation, not a claimed capability, but the abstract and conclusion use general language ("a wide range of downstream tasks," "robust across numerous tasks and models") that could lead a practitioner to assume coverage includes domains beyond the five tested natural-language tasks.

**Mitigation status.** Not addressed. The paper does not mention these domain gaps as limitations, does not suggest future work on domain generalization, and does not qualify its robustness claims with domain caveats. A practitioner deploying SparQ Attention for a code assistant or a mathematical reasoning system must extrapolate from natural-language results with no evidence that the extrapolation is valid.

### End-to-End Speedups Are Substantially Lower Than the Headline Compression Ratio

**The assumption or constraint.** The paper's primary metric—attention data transfers per token—measures only the attention portion of the inference workload. Equation (1) and Figure 3 establish that attention dominates data transfers at long sequence lengths and large batch sizes, but they do not eliminate non-attention transfers entirely. The end-to-end benchmarks (Section 6.2) measure actual wall-clock speedups that reflect both the attention speedup and the constant-cost non-attention computation. The paper does not state this as a limitation, but the discrepancy between the headline "8× savings" and the measured end-to-end speedups is a transparency issue that affects deployability assessments.

**The consequence.** A practitioner reading the abstract ("up to 8× savings in attention data transfers") and skimming the end-to-end results might reasonably conclude that SparQ Attention provides near-8× end-to-end inference speedup under favorable conditions. The data do not support this. On CPU with Llama 2 7B at batch size 1 and 1/8 compression (Figure 9), the maximum end-to-end speedup is approximately 2.5× at `S ≈ 131,072` tokens, falling to near 1× at `S ≈ 4096`. On GPU (H100, Figure 10), the maximum is approximately 2.2× at `S ≈ 32,768`, again near 1× at `S = 4096`. The gap between theoretical `M_dense / M_SparQ` (which would be 8× for 1/8 compression if attention were 100% of the workload) and the achieved speedup is large and grows with sequence length—exactly the regime where attention should dominate according to Figure 3.

This gap has a concrete origin that the paper does not quantify: SparQ Attention reduces attention *data transfers* but not necessarily attention *latency* by the same factor, because the remaining non-attention computation (MLP layers, layer norms, residual additions, the softmax and weighting operations within SparQ Attention itself) does not compress. At batch size 1 on GPU, the arithmetic intensity may be high enough that compute and data transfer partially overlap, meaning reducing transfers does not linearly reduce wall-clock time—the compute becomes the bottleneck once transfers are sufficiently reduced. This is visible in the GPU microbenchmark (Table 4): the theoretical speedup is 6.4×, but the achieved speedup is 3.02× even for the attention operation in isolation (batch size 64, which should be more bandwidth-bound than batch size 1). The remaining gap reflects kernel launch overhead, non-fused memory operations, and the computational cost of the approximate scoring and top-k selection steps, which are small relative to dense attention but non-zero.

For a practitioner deciding whether to adopt SparQ Attention, the question is not "what is the attention compression ratio" but "what is the end-to-end speedup on my hardware, batch size, and sequence length?" The paper provides partial answers for CPU (AMD EPYC, batch 1, llama.cpp) and GPU (H100, batch 1, gpt-fast), but these are single configurations. The microbenchmarks (Figure F1) show substantial variation across devices (M2000, A10G, A100) and batch sizes, and the end-to-end results do not cover this space.

**What evidence exists in the paper.** Figures 9 and 10 plot end-to-end speedups alongside the theoretical `M_dense / M_SparQ` line, making the gap explicit. The paper states that "SparQ Attention attains speedups at all sequence lengths evaluated" (Section 6.2), which is technically true (speedup > 1×) but elides the magnitude relative to the 8× claim. Table 4 reports a theoretical speedup of 6.4× versus achieved speedups of 3.02× (A100) and 4.17× (A10G) for the attention microbenchmark, indicating that even in isolation, implementation overhead prevents the full theoretical gain. The IPU result (7.41× achieved versus 7.53× theoretical) shows near-perfect realization, but this is on specialized hardware with a different memory hierarchy where "attention is strongly memory bound when using remote memory"—a condition that does not hold for standard GPU deployments with HBM.

**Mitigation status.** The paper transparently reports both theoretical compression ratios and measured speedups, which is more than many systems papers provide. However, it does not analyze why the end-to-end speedups fall short (no breakdown of time spent in attention versus other layers in the SparQ Attention implementation), does not explore whether implementation improvements could close the gap, and does not characterize the speedup as a function of batch size in the end-to-end setting—only in microbenchmarks (Figure F1). The abstract and introduction emphasize the 8× figure; the conclusion (Section 8) does not mention the end-to-end speedup at all, reinforcing the risk that readers overestimate the practical benefit.

### The Method Has No Mechanism for Recovering from Total Query Sparsity Failure

**The assumption or constraint.** SparQ Attention assumes that the top-r components of the query vector contain sufficient information to discriminate among keys—that the large-magnitude dimensions correspond to the semantically discriminative dimensions for the current attention head. This assumption is validated empirically (Figure 4c, 4d, 4e) but not guaranteed. For some queries, on some heads, the query vector may be relatively flat (all components similar magnitude), or the large-magnitude components may encode information that is irrelevant to the specific retrieval task of that head. In such cases, the approximate scores `\hat{s}` become essentially random with respect to the true attention scores, and the top-k selection in Step 2 fetches an arbitrary subset of the sequence. The paper provides no fallback mechanism—no detection of when the approximation is unreliable, no adaptive increase of `r` or fallback to dense attention.

**The consequence.** When query sparsity fails on a particular head for a particular token, SparQ Attention silently produces an incorrect attention output. The mean value reallocation in Step 3 can partially compensate if the problem is *diffuse attention* (genuinely many positions matter) by blending toward `\bar{v}`, but it cannot compensate if the problem is *mis-directed attention* (the wrong positions were selected). In the latter case, the output `y_3` is computed from irrelevant value vectors, and blending with `\bar{v}` using `\alpha` simply mixes an incorrect signal with a generic background—there is no guarantee this is better than either alone. The downstream effect depends on how many heads in how many layers experience this failure, and how the residuals propagate through the transformer. The paper's aggregate accuracy metrics (Table 2) cannot distinguish between "most heads are working correctly and a few are failing silently" and "all heads are working moderately well"—both could produce similar accuracy, but the failure mode has different implications for robustness, especially on out-of-distribution or adversarial inputs.

This vulnerability is particularly concerning for the needle-in-a-haystack task, which the paper presents as a key strength. If a query like "What is the best thing to do in San Francisco?" happens to have a flat query vector on a head responsible for attending to proper nouns, the needle may be missed not because SparQ Attention's hyperparameters are too aggressive, but because the query's representational structure does not support sparse approximation on that head. The paper's strong needle-in-a-haystack results suggest this is rare in practice, but do not bound its frequency or severity.

**What evidence exists in the paper.** Figure 4c and 4d show that most query components are heavy-tailed, but they also show that the degree of heavy-tailedness varies by head: Figure 4d is a heatmap with substantial variation in kurtosis across heads and layers. Some heads have kurtosis near 0 (Gaussian), meaning their query components are not heavy-tailed—for these heads, the top-r selection has no basis in the signal structure and the approximation is inherently unreliable. The paper does not report what fraction of heads fall into this category, whether these Gaussian-query heads are concentrated in specific layers, or whether they correspond to heads with diffuse attention patterns (which would be visible in Figure 4b but is not cross-referenced). Figure 4e shows top-k agreement varying from roughly 0.5 to 0.95 depending on `r` and `k`—meaning even under favorable conditions, some head-query pairs achieve only 50% overlap between approximate and true top-k. The paper does not analyze whether these low-agreement cases cluster on specific heads, specific input types, or specific layers.

**Mitigation status.** The paper does not acknowledge this as a failure mode, does not propose a detection mechanism (e.g., monitoring the L1 coverage `\|q \circ m_q\|_1 / \|q\|_1` as a signal of approximation quality and falling back to larger `r` or dense attention when coverage is low), and does not analyze per-head failure patterns. The `\alpha`-weighted interpolation with `\bar{v}` provides a soft fallback for diffuse attention (where many positions genuinely matter and `\alpha` is low) but not for mis-directed attention (where `\alpha` is high but the selected positions are wrong). The kurtosis heatmap in Figure 4d implicitly flags this vulnerability—some heads have kurtosis near zero, meaning query sparsity is unsupported—but the paper does not connect this observation to any mitigation or limitation discussion.

### No Systematic Analysis of Prefill-Stage Applicability or Cost

**The assumption or constraint.** All experiments, benchmarks, and the formal cost model (Equations 3 and 11) describe the autoregressive generation phase—producing one token at a time, where the query vector `q` corresponds to the latest token and the KV cache contains all prior tokens. The paper does not discuss whether SparQ Attention applies during the prefill (or prompt-processing) stage, where the entire input sequence is processed in parallel: all queries attend to all preceding keys simultaneously, the KV cache is being populated rather than read from, and the computational pattern differs fundamentally from token-by-token generation. The paper mentions the prefill stage only once, in the related work discussion of IceFormer (Section 7: "focusing on speeding-up the prefill stage, rather than generation"), implicitly positioning SparQ Attention as a generation-phase technique. But the scope of this limitation is never stated explicitly.

**The consequence.** For many practical deployments, prefill latency is a first-order concern. When a user submits a long document or conversation history, the model must process the entire prompt before generating the first response token—this prefill step involves computing attention for every token against every previous token, and for long prompts (tens of thousands of tokens), it can dominate the end-to-end response time. SparQ Attention's selective-fetch mechanism does not obviously translate to the prefill setting. During prefill, all queries are available simultaneously, and the attention computation is typically implemented as batched matrix multiplications (Q·K^T) that are compute-bound rather than bandwidth-bound at typical batch sizes. The mean value vector `\bar{v}` does not exist until after the sequence is processed, so Step 3 would need modification or omission. The dual-layout storage strategy would need to be populated during prefill, potentially adding overhead to the initial processing. If SparQ Attention provides no benefit during prefill, the end-to-end speedup for interactive applications (where prefill and generation alternate) is diluted: a hypothetical 3× generation speedup may translate to only a 1.5× end-to-end speedup if prefill constitutes half the total time.

**What evidence exists in the paper.** Essentially none. The paper's microbenchmarks (Section 6.1, Figure 8) measure "time per query" in what appears to be a generation setting (single query against a pre-populated KV cache). The end-to-end benchmarks (Figures 9, 10) measure "the time it took to generate a single token, given an existing sequence length S"—explicitly a generation-phase measurement. The CPU benchmarking methodology (Appendix D) describes prefilling the KV cache with a prompt of length S, then measuring the time to generate one additional token. The prefill cost itself is not measured, reported, or discussed.

**Mitigation status.** The paper does not acknowledge this limitation, does not discuss whether SparQ Attention can be adapted for prefill, and does not analyze the prefill-generation time split for its evaluation tasks. Given that the paper's motivation emphasizes "applications to support long input sequences" (Section 1), the silence on prefill is a significant gap—long input sequences are precisely where prefill cost is highest. A practitioner cannot determine from the paper whether SparQ Attention accelerates the full inference pipeline or only the token-generation tail.

### Hyperparameter Transfer Across Models Is Assumed, Not Validated

**The assumption or constraint.** The paper proposes a "simple recipe of setting `k = 128` and tuning `r` to maintain a good trade-off between data transfer and task performance" (Section 5.4), based on ablations on Llama 2 7B (Figure 7c). The experiments in Table 2 and Figures A1–A3 apply this recipe across five model families without reporting per-model hyperparameter optimization. The implicit assumption is that the relationship between `r`, `k`, compression, and accuracy observed for Llama 2 7B transfers to Llama 2 13B, Llama 3 8B, Mistral 7B, Gemma 7B, and Pythia 1.4B–6.9B—models with different head dimensions (`d_h` ranging from 80 for Pythia 2.8B to 256 for Gemma 7B), different numbers of layers and heads, different GQA configurations, and different pretraining objectives and data.

**The consequence.** The transfer assumption fails in at least one identifiable way: Gemma 7B has `d_h = 256` (Table G1), meaning `r = 32` reads only 12.5% of the key dimensions versus 25% for Llama 2's `d_h = 128`. The approximation quality of Step 1 depends on the fraction of dimensions retained, not just the absolute number—`r = 32` on `d_h = 256` discards more information than `r = 32` on `d_h = 128`. Yet Table 2 reports Gemma 7B at 1/8 compression achieving 80.3% SQuAD accuracy (essentially flat from 80.4% dense), which seems too good to be true if the approximation were substantially degraded. This suggests either (a) Gemma's query vectors are more heavy-tailed, so the top-32 components carry proportionally more information than Llama 2's, or (b) the sparse attention is over-provisioned and `r` could be even smaller, or (c) the SQuAD task does not stress the approximation at 1/8 compression for Gemma. The paper provides no analysis to distinguish these possibilities, so a practitioner cannot determine whether `r = 32` is universally safe, universally conservative, or model-dependent.

The Pythia 2.8B model has `d_h = 80` (Table G1)—smaller than Llama 2's 128—meaning `r = 32` retains 40% of the key dimensions, potentially making the approximation more reliable. The Pythia 1.4B and 6.9B models have `d_h = 128`. The paper does not report whether `r` was adjusted per model to maintain a consistent fraction of retained dimensions, or whether the fixed `r = 32` yields systematically different approximation quality across models. The compression ratio depends on `r` through the `S r` term (Equation 11), so holding `r` fixed while `d_h` varies changes not only the approximation quality but also the achieved compression for a given sequence length—a confound that the paper does not disentangle.

**What evidence exists in the paper.** Figure 7c provides the only hyperparameter sensitivity data, and only for Llama 2 7B on two tasks (SQuAD, Repetition). The paper states: "Based on these results, we propose a simple recipe of setting `k = 128` and tuning `r` to maintain a good trade-off between data transfer and task performance for a range of models and tasks." The phrase "tuning `r`" implies per-model, per-task adjustment, but the experimental setup (Table G1) sweeps `r` across `{8, 16, 32, 64}` and reports results at fixed compression ratios—the tuning was apparently done to select which `r` values correspond to which compression ratios for reporting, not to optimize accuracy per model. The paper does not report whether the optimal `r` for a given compression ratio differs across models, or whether `k = 128` is optimal (or even good) for `d_h = 80` or `d_h = 256`.

**Mitigation status.** The paper does not acknowledge this as a limitation. The recipe is presented as empirically supported rather than as a heuristic awaiting validation on diverse architectures. The model diversity in Table 2 (five families, varying `d_h`, varying GQA) is a strength, but the failure to analyze whether hyperparameter transfer held—or whether per-model tuning would have improved results—leaves the practitioner uncertain about how to configure SparQ Attention for a new, unseen model.
