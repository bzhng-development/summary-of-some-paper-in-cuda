# GoldFinch: High Performance RWKV/Transformer Hybrid with Linear Pre-Fill and Extreme KV-Cache Compression

**ArXiv:** [2407.12077](https://arxiv.org/abs/2407.12077)

## 🎯 Pitch

This paper introduces **GoldFinch**, a hybrid Linear Attention/Transformer sequence model that combines an enhanced Finch (RWKV-6) architecture with a novel transformer variant called GOLD to achieve dramatic KV-cache compression — reducing cache size by 756–2550× relative to traditional transformers — while maintaining greater-than-Llama modeling performance.

---

## 1. Executive Summary

This paper introduces **GoldFinch**, a hybrid Linear Attention/Transformer sequence model that combines an enhanced Finch (RWKV-6) architecture with a novel transformer variant called GOLD to achieve dramatic KV-cache compression — reducing cache size by 756–2550× relative to traditional transformers — while maintaining greater-than-Llama modeling performance. GoldFinch stacks Finch-C2 layers (a parameter-efficient Finch modification removing the gate, swapping GroupNorm for LayerNorm, and replacing the bonus term with a second data-dependent value) for the first two-thirds of the model, compresses their output via a novel **TokenCat** mechanism (concatenating a 16×-compressed key cache with original token embeddings) into a single global key cache shared across all subsequent layers, and processes this cache through GOLD attention layers that generate keys and values from the compressed cache and embedding table rather than storing them. On 1.5B parameter models trained on minipile, GoldFinch achieves a final loss of 2.2762 versus 2.3905 for Llama and 2.3856 for Finch while using over 100 million fewer parameters than its Finch counterpart, and on common benchmarks improves average accuracy by 1.2–1.4 percentage points over both baselines. The architecture enables O(1) per-token pre-fill computation via its RNN-based initial layers and perfect multi-query associative recall via its attention-based final layers, establishing that extreme KV-cache compression need not sacrifice modeling quality when the compressed cache is generated by a recurrent architecture that implicitly encodes positional information and consumed by attention layers that reconstitute keys and values on-demand.

## 2. Context and Motivation

### The Core Problem: The KV-Cache Is Making Long-Context Inference Impractical

The fundamental challenge this paper addresses is straightforward to state but has resisted satisfactory solution: **as language models scale to longer context lengths, the memory required to store the key-value cache during autoregressive generation becomes prohibitively expensive.** This is not a minor implementation detail — it is the primary bottleneck determining whether extremely long-context models can be deployed on real hardware.

To understand why this matters, consider what happens during standard transformer inference. When a transformer generates tokens autoregressively, each new token needs to attend to every previous token. Naively recomputing the key and value projections for all prior tokens at each generation step would be catastrophically expensive — $O(N^2)$ per step for a sequence of length $N$. The standard solution, now universal in production systems, is the **KV-Cache** (Pope et al., 2022): store the computed keys and values for all previous tokens in memory so they can be retrieved rather than recomputed. This reduces the per-step computational complexity to $O(N)$ but introduces a memory cost that grows linearly with sequence length.

The paper provides a concrete example that makes the scale of the problem visceral (Section 1):

> "a 1 million token cache for an 80 layer traditional transformer model of hidden dimension 8192 would take up over 2.5 terabytes at bfloat16 precision"

The arithmetic behind this: each token at each layer requires storing a key vector and a value vector, each of dimension $d_{model}$. For an 80-layer model with hidden dimension 8192, the per-token KV-cache size is $2 \times 80 \times 8192 = 1,310,720$ elements. In bfloat16 precision (2 bytes per element), that is approximately 2.6 MB per token. For a 1 million token context, this balloons to roughly 2.6 TB. This is not a theoretical concern — models like Gemini Pro (Gemini Team et al., 2024) already offer million-token context windows, and the memory demands of their KV-caches at scale represent a genuine infrastructure challenge.

### Why the Problem Matters: Three Practical Tensions

The paper's motivation is grounded in three intersecting practical concerns that make KV-cache compression urgent rather than merely interesting:

**First, there is an architectural tension between capability and efficiency in long-context models.** The advantage of transformers — their ability to attend directly to any previous token — is also the source of their memory inefficiency. Linear attention models (Katharopoulos et al., 2020) and state-space models address this by using a fixed-size recurrent state that is updated at each timestep, achieving $O(1)$ per-step computation and memory. As the paper notes, "Instead of inspecting the entire context length to generate each new token, recurrent linear attention uses a fixed-size hidden state that is updated at each time-step, functioning as its memory of the past." However, this efficiency comes at a cost: the fixed-size state has limited memory capacity, and linear attention models consistently underperform transformers on tasks requiring precise associative recall — the ability to retrieve specific information seen earlier in the context (Arora et al., 2023). The field thus faces a tradeoff: transformers give you recall but cost you memory, while recurrent models give you efficiency but sacrifice memory capacity.

**Second, there is a glaring asymmetry in many real-world LLM use cases that the paper explicitly identifies.** Consider the common scenario of asking questions about a long document: the input context (the document) may be hundreds of thousands of tokens, but the generated response may be only a few hundred tokens. In a standard transformer, you pay the full $O(N^2)$ attention cost during pre-fill (processing the input context) and then $O(N)$ per generated token during decoding, all while maintaining the full KV-cache for the entire input. The pre-fill cost is a one-time payment per query, but the cache persists throughout generation and consumes memory regardless of how short the output is. The paper highlights this as a motivating inefficiency:

> "Because our compressed key cache is generated by an RNN with an operating time and space complexity of O(1) per token with regard to sequence length, we are able to generate the cache in these cases extremely inexpensively and apply the O(N) per token cost GOLD transformer portion of our calculations only to new token generation, for which relatively few iterations are often required."

In other words, large parts of the model's computation should depend on the length of the *output*, not the input, but existing architectures don't cleanly enable this separation.

**Third, there is an economic and deployment tension.** Large KV-caches consume expensive Video Random-Access Memory (VRAM). Consumer GPUs — which the paper's experiments explicitly target, noting they ran on "a single node containing 8 RTX 4090 cards" — have limited VRAM (the RTX 4090 has 24 GB). A 2.5 TB cache for a million-token context is literally two orders of magnitude beyond what consumer hardware can support. Even on datacenter GPUs, the memory cost translates directly into dollar cost: more memory per query means fewer concurrent queries per GPU, higher infrastructure costs, and worse latency due to memory bandwidth constraints. Solutions that reduce KV-cache size are therefore not merely algorithmic curiosities — they directly enable deployment of long-context models on cheaper hardware and at higher throughput.

### Prior Approaches and Where They Fall Short

The paper positions itself against a landscape of existing approaches for KV-cache reduction, each of which addresses part of the problem but leaves significant gaps:

**Grouped-Query Attention (GQA) (Ainslie et al., 2023)** reduces the KV-cache by sharing key and value heads across groups of query heads. With $n_g$ groups and $n_h$ heads, GQA reduces the cache size by a factor of $n_g / n_h$ — typically about 8× for common configurations. This is a genuine improvement, and the paper acknowledges it as "helpful, especially on consumer grade hardware." However, the paper identifies two specific limitations: GQA "leads to a reduction in downstream performance" (the sharing of key-value heads constrains the model's representational capacity), and more fundamentally, even an 8× reduction is insufficient for very long contexts — a 1 million token cache at 256 GB (after 8× reduction) is still far beyond consumer hardware budgets. GQA is a constant-factor improvement, not an asymptotic solution.

**Multi-head Latent Attention (MLA) from DeepSeek-V2 (DeepSeek-AI et al., 2024)** uses low-rank joint key-value compression to reduce the KV-cache from $2 n_h d_h l$ to $\frac{9}{2} d_h l$, which the paper notes is "equivalent to the KV-Cache size required for GQA with only 2.25 groups." MLA achieves this through learned low-rank projections rather than head sharing, giving it better per-parameter performance than standard MHA because the low-rank compression requires fewer parameters than full-rank key and value matrices. However, MLA still produces a per-layer cache that grows linearly with the number of layers, and the compression factor — while better than GQA — is still a constant factor relative to the full cache. The paper cites MLA as an inspiration for its own compression-based parameter reduction but aims for much more aggressive compression.

**YOCO (You Only Cache Once) (Sun et al., 2024)** is the most direct predecessor to GoldFinch and the approach the paper most explicitly builds upon. YOCO introduces a **global KV-Cache** rather than per-layer caches: the first half of the model's layers use RetNet-G, a linear attention architecture, and their output serves as a single shared cache for all subsequent standard attention layers. This reduces the cache size by a factor equal to the number of layers — a substantial improvement over per-layer caching — and also makes pre-fill $O(N)$ instead of $O(N^2)$ by using the recurrent RetNet-G layers for the initial pass. The paper reports that YOCO achieves this "without a reported performance reduction," making it the state-of-the-art baseline for global caching approaches. However, YOCO's cache is still the full hidden dimension per token (compressed only by removing the per-layer duplication, not by compressing the representations themselves). The paper's Table 1 makes this concrete: for a 256k context, 32 layers, 4096 hidden-dimension model, YOCO requires 4 GB for its KV-cache, while GoldFinch requires only 0.068 GB — roughly 59× smaller than YOCO.

**H3 (Hungry Hungry Hippos) (Fu et al., 2023)** demonstrated that a hybrid SSM-transformer model with just two layers of attention could outperform pure transformers on language modeling. As the paper puts it, H3 "served as a warning shot that SSM(or linear attention)-transformer hybrids have the potential to step in as higher performance replacements for transformers alone." This established the viability of hybrid architectures — but H3 did not address the KV-cache problem directly, nor did it achieve the extreme compression that GoldFinch targets.

**Other concurrent hybrid models (Zamba, Jamba, Samba)** each explored variations on interleaving state-space model blocks with attention blocks. The paper notes specific architectural similarities — Zamba's concatenation of original embeddings with residual outputs "bears similarity to our new 'TokenCat' technique," and Jamba's finding that explicit positional encoding may be unnecessary for hybrid architectures mirrors GoldFinch's reliance on RWKV's implicit positional encoding within the trained context length. However, these models all maintain per-layer caches for their attention components (even if shared across layers), and none achieve the extreme compression ratios that GoldFinch targets. Samba uses sliding-window attention to cap per-token attention cost, but this sacrifices the ability to attend to distant tokens rather than compressing the cache.

**Ring Attention (Liu et al., 2023)** takes an orthogonal approach: rather than compressing the cache, it distributes it across multiple processors that don't share VRAM. Each processor stores only a fraction of the total KV-cache, linearly amortizing the memory cost across devices. The paper acknowledges this in Appendix B as enabling "unbounded scaling of attention given enough hardware," but identifies two key limitations: it "does not address the cost of $O(N^2)$ compute" during pre-fill, and it "still imposes total memory costs that scale with the sequence length" — the memory is spread across devices but still exists. Ring attention is a scaling solution, not an efficiency solution; it requires proportionally more hardware for longer contexts.

### The Unmet Need: Deep Compression Without Quality Degradation

Synthesizing these prior efforts reveals the specific gap that the paper aims to fill. Existing approaches fall along a spectrum:

- **Head-sharing approaches (GQA, MLA)** reduce the cache by a constant factor (8–16×) but leave the per-layer structure intact and sacrifice some modeling capacity.
- **Global-cache approaches (YOCO)** remove the per-layer duplication but don't compress the cache entries themselves.
- **Hybrid architectures (H3, Zamba, Jamba, Samba)** improve efficiency through interleaving but either maintain per-layer caches or limit attention range (sliding window).
- **Distribution approaches (Ring Attention)** spread the memory cost across hardware but don't reduce total memory or compute.

What was missing — and what the paper explicitly sets out to provide — is a method that achieves **extreme compression ratios (hundreds to thousands of times smaller than traditional caches) while maintaining or improving modeling performance relative to strong transformer baselines.** The paper's stated ambition is not merely to reduce cache size by a factor of 2 or 8, but to reduce it by two to three orders of magnitude — from $2 d_{model} n_{layer}$ per token to approximately $1 + \frac{d_{model}}{16}$ per token, plus the original token indices (typically 2 bytes per token, adding negligible overhead). This compression, summarized in Table 1, changes the qualitative nature of the problem: at these ratios, a million-token context for an 80-layer 8192-dimension model would require approximately 0.5 GB rather than 2.5 TB, fitting comfortably on consumer hardware.

The paper also identifies a specific secondary gap: the tension between **pre-fill efficiency and attention quality.** YOCO demonstrated that recurrent layers can handle pre-fill in $O(N)$ time and produce a cache usable by attention layers, but GoldFinch pushes this further by making the cache both smaller (through compression) and more expressive (through the TokenCat mechanism that concatenates compressed keys with original embeddings). The goal is to achieve $O(1)$ pre-fill — meaning the cost per token to process the input context is constant with respect to sequence length — while retaining the full power of quadratic attention for generation, where it matters most.

### How This Paper Positions Itself

The paper positions GoldFinch as a synthesis and extension of two research threads: **linear attention/RNN architectures** (specifically Finch/RWKV-6) and **global caching strategies** (YOCO). The explicit framing is:

> "Goldfinch takes a related approach [to YOCO], and processes the output differently, creating an effective but much smaller cache via our TokenCat mechanism"

The key differentiators that the paper claims:

1. **Compression depth vs. YOCO:** While YOCO stores the full hidden dimension as its global cache, GoldFinch compresses it 16× before storage and reconstitutes richer representations through TokenCat (concatenating compressed cache with original embeddings).

2. **Key-only caching:** GoldFinch eliminates the value cache entirely. Instead of storing values, it stores the original token indices (a negligible cost) and generates values on-demand from the embedding table with data-dependent transformations. This nearly halves the cache size before any compression is applied.

3. **Improved constituent architectures:** The paper doesn't just combine existing components — it improves both the linear attention backbone (Finch-C2 removing the gate, improving normalization, adding a second data-dependent value) and the transformer component (GPTAlpha incorporating RWKV channel mixers and token shifts). Both improvements are validated through standalone ablations showing they outperform their predecessors.

4. **Unified compression pipeline:** Unlike approaches that treat cache compression as an afterthought (post-hoc quantization), GoldFinch integrates compression into the architecture's training objective from the start. The compression matrix $W_{KD}$ is learned end-to-end as part of the model, not applied as a separate post-processing step.

5. **Proposal-cum-verification that extreme compression can coexist with superior performance:** The paper's most provocative claim is not just that GoldFinch compresses the cache, but that the compressed architecture *outperforms* uncompressed baselines (Llama and Finch) on both perplexity and downstream benchmarks. If true, this inverts the conventional wisdom that efficiency must come at a quality cost.

The paper also explicitly aligns itself with the emerging consensus that hybrid architectures — combining recurrent or SSM layers for efficiency with attention layers for precision — represent the most promising direction for long-context language modeling. It cites H3's demonstration that even two attention layers in an otherwise recurrent model can exceed pure transformer performance, and extends this insight by showing that when the recurrent layers are specifically optimized to produce a good compressed cache (via Finch-C2 improvements and the TokenCat mechanism), the attention layers can operate effectively on dramatically less stored information.

## 3. Technical Approach

### 3.1 Reader Orientation

GoldFinch is a hybrid language model architecture that combines a recurrent neural network (specifically, an improved version of Finch/RWKV-6 called Finch-C2) for the first two-thirds of its layers with a novel attention-based transformer (called GOLD) for the remaining layers, where the recurrent portion compresses its output into a single, extremely small key-value cache that is shared across all subsequent attention layers rather than each layer maintaining its own separate cache. The core problem it solves is the prohibitive memory cost of the traditional transformer KV-cache during long-context inference: rather than storing full key and value vectors for every token at every layer — which requires $2 \times d_{model} \times n_{layer}$ elements per token — GoldFinch stores only a 16×-compressed key representation plus the original token indices, reducing cache size by 756–2550× while maintaining or exceeding the modeling performance of equivalently-sized Llama and Finch models.

### 3.2 Big-Picture Architecture (Diagram in Words)

GoldFinch processes a sequence of tokens through five major components in order:

1. **Embedding Layer**: Converts input token indices into dense vectors of dimension $D$ (the model dimension). The paper uses the RWKV World tokenizer and a standard learned embedding table. The raw token indices are preserved throughout as $x^0$, the original embeddings, which serve as a persistent source of token identity information for later stages.

2. **Finch-C2 Layers (first 2/3 of total layers)**: Each layer contains a Finch-C2 time-mixing sub-layer (a recurrent linear attention mechanism that updates a fixed-size hidden state) followed by a Finch channel-mixing sub-layer (a gated feed-forward network with squared ReLU activation). These layers process the sequence recurrently, requiring only $O(1)$ time and memory per token. Their output flows in two directions simultaneously: (a) upward through the normal residual stream to the next layer, and (b) into the key compression module.

3. **Key Compression Module**: A single learned matrix $W_{KD} \in \mathbb{R}^{D \times (D/16)}$ (shared across all positions, not per-layer) projects the Finch-C2 output at each position from dimension $D$ down to dimension $D/16$. This compressed representation, denoted $c_t$ for position $t$, is stored in a single global key cache — one entry per token for the entire model, regardless of how many GOLD layers exist above.

4. **GOLD Attention Layers (last 1/3 of total layers)**: Each GOLD layer performs standard multi-head scaled dot-product attention, but critically, it does not have its own learned key and value projection matrices. Instead, it reconstitutes its keys from the compressed key cache through the TokenCat decompression mechanism (concatenating the compressed key $c_t$ with the original embedding $x^0_t$, then projecting to dimension $D$), and reconstitutes its values from the original token embeddings $x^0_t$ with data-dependent transformations. Queries are computed normally from the current hidden state. The GOLD layers thus consume the global cache rather than maintaining per-layer caches.

5. **Output Head**: A standard language modeling head that projects the final hidden state to vocabulary logits for next-token prediction.

The information flow during pre-fill (processing the input context prior to generation) is: token indices → embeddings → Finch-C2 layers (recurrently, $O(1)$ per token) → key compression → storage in global cache, with the final $2G-1$ tokens (where $G$ is the number of GOLD layers) also passed through the full GOLD layers to initialize their token-shift hidden states. During autoregressive generation, only the new token is passed through the full model (Finch-C2 + GOLD), and the GOLD layers decompress cache entries on-the-fly for attention computation.

### 3.3 Roadmap for the Deep Dive

- **First, the Finch-C2 time-mixing mechanism**, since it is the recurrent engine that processes all input tokens efficiently and produces the representations that will be compressed into the global cache. Understanding its innovations (removing the gate, changing normalization, adding the second value) is essential because these changes affect both the quality of the cached representations and the model's parameter efficiency.

- **Second, the key compression and decompression (TokenCat) pipeline**, since this is the central mechanism enabling the extreme cache reduction. We'll trace exactly how a $D$-dimensional vector becomes $D/16$-dimensional for storage and then becomes $D$-dimensional again for attention, and why concatenation with original embeddings is critical rather than optional.

- **Third, the GOLD attention mechanism**, since this is what consumes the compressed cache. We need to understand how keys and values are generated without learned per-layer projection matrices, why data-dependent token shifts are applied to them, and how the architecture maintains strong attention quality despite operating on compressed and reconstituted representations.

- **Fourth, the Finch channel mixing sub-layer**, since it is used identically in both Finch-C2 and GOLD layers as the feed-forward network component, replacing the standard transformer FFN. Understanding its gating mechanism and squared ReLU activation explains part of the performance improvement over Llama.

- **Fifth, the GPTAlpha standalone variant**, since this shows how the GOLD innovations can be used independently of the compression pipeline, providing evidence that the attention improvements are genuine and not artifacts of the hybrid architecture.

- **Sixth, the pre-fill and inference procedures**, since the architecture's theoretical efficiency depends on specific implementation details — which parts run recurrently, which tokens must pass through the full model, and how the cache is accessed during generation.

### 3.4 Detailed, Sentence-Based Technical Breakdown

This is primarily an **architectural innovation paper** whose core idea is that a recurrent neural network can generate a highly compressed, reusable global key cache that enables standard quadratic attention layers to operate effectively without per-layer KV-caches, achieving extreme memory reduction while maintaining or improving modeling quality.

---

#### Finch-C2 Time Mixing: The Recurrent Engine

The Finch-C2 time-mixing mechanism is a modification of the Finch (RWKV-6) architecture's time-mixer — the recurrent linear attention component that processes each token and updates a fixed-size hidden state representing the model's memory of past tokens. The paper makes four specific changes to the original Finch formulation, each motivated by a combination of parameter efficiency and empirical performance.

**Background: What Finch's time mixer does.** The original Finch time mixer (Peng et al., 2024) computes, for each head, a recurrent update to a matrix-valued hidden state (the "kv-state") that accumulates outer products of keys and values, weighted by data-dependent exponential decays. Specifically, it maintains a state $wkv_t \in \mathbb{R}^{H \times H}$ (per head, where $H$ is the head dimension) that is updated as:

$$wkv_t = w_t \cdot wkv_{t-1} + k_t^\top \cdot v_t$$

where $k_t$ and $v_t$ are key and value vectors derived from the current input, and $w_t \in (0, 1)$ is a per-channel data-dependent decay factor that controls how much of the past state is retained. The output is then computed as $r_t \cdot wkv_t$ (plus a "bonus" term $u \cdot v_t$ in the original Finch), where $r_t$ is a "receptance" gate that controls how much of the accumulated memory is passed forward. This is a form of linear attention because the state update is $O(H^2)$ per token rather than $O(N)$ — the state size does not grow with sequence length.

**Change 1: Removing the gate.** In the original Finch, the time-mixer includes a separate gate vector $g_t$ that multiplicatively modulates the output before the final projection. The paper removes this gate entirely:

> "We customize the Finch time-mixing sub-layers by removing the gate"

The gate in Finch is computed as $g_t = \text{ddlerp}_g(x_t, x_{t-1}) W_G$ and applied as an element-wise multiplication on the time-mixer output before the $W_O$ projection. Removing it saves the parameters of $W_G$ and the associated data-dependent token shift parameters, while the paper claims (through the ablation study in Table 4) that performance is maintained or improved when combined with the other changes. The intuition is that the receptance $r_t$ already provides a learned gating function (it multiplies the $wkv_t$ state), and the second value term (Change 4 below) compensates for any lost expressivity.

**Change 2: Swapping GroupNorm for LayerNorm across all heads.** The original Finch applies GroupNorm (Wu & He, 2018) separately within each head before the final output projection. The paper replaces this with LayerNorm applied across the concatenated outputs of all heads:

> "swapping out GroupNorm for a LayerNorm across all heads"

In the original Finch, after computing $r_t \cdot wkv_t + u \cdot v_t$ for each head independently, GroupNorm normalizes each head's output separately, treating the head dimension as the group. In Finch-C2, the per-head outputs are first concatenated, then LayerNorm is applied across the full $D$-dimensional vector before the $W_O$ projection. The paper cites HGRN2 (Qin et al., 2024) as precedent: "HGRN2 replaces the per-head GroupNorm with a full-width LayerNorm, and we do the same in our Finch-C2 architecture." The likely benefit is that full-width normalization allows the model to learn cross-head interactions in the normalization statistics, and it simplifies the implementation. The paper's ablation (Table 4) shows Finch-C2 outperforms standard Finch (2.7082 vs. 2.7191 loss), though this change is conflated with the others.

**Change 3: Multiplying the key by one minus the decay.** In the original Finch, the key $k_t$ is computed directly from the input via a data-dependent token shift and linear projection. In Finch-C2, the key is additionally multiplied by $(1 - w_t)$:

$$k_t = \text{ddlerp}_k(x_t, x_{t-1}) W_K \cdot (1 - w_t)$$

The paper explains this as: "doing a new multiplication of the key by one minus the decay." The reason is related to state normalization. In the original Finch update $wkv_t = w_t \cdot wkv_{t-1} + k_t^\top v_t$, if the decay $w_t$ is close to 1 (meaning the model wants to retain most of the past), the new key-value pair contributes only a small fraction of the new state, which is correct. But if the decay is close to 0 (meaning the model wants to forget the past), the new pair should dominate. By multiplying $k_t$ by $(1 - w_t)$, the contribution of the new pair is scaled down when retention is high and up when retention is low, providing a form of automatic normalization that keeps the kv-state rows approximately normalized. The paper explicitly states: "to keep the kv-state rows normalized." The HGRN2 connection is noted: "HGRN2 sets their key to be equal to one minus the decay, and we do something related but slightly different, multiplying our key by one minus the decay" — in HGRN2 the key *is* $(1 - w_t)$ (replacing the learned key entirely), while in Finch-C2 the learned key is *modulated* by $(1 - w_t)$, preserving more expressivity.

**Change 4: Replacing the bonus term with a second data-dependent value.** The original Finch includes a "bonus" term $u \cdot v_t$ in the output computation, where $u$ is a static learned per-head vector (not data-dependent). This term allows the current token's value to contribute directly to the output without going through the kv-state accumulation — effectively a skip connection in the time domain. The paper replaces this with a new data-dependent value:

> "we replace Finch's u ('bonus') term with a new data-dependent separately token-shifted second Value, computed using the same weights as the base Value, with an additional LoRA added to the result"

The new term $u'_t$ is computed as:

$$u_t = \text{ddlerp}_u(x_t, x_{t-1})$$

$$u'_t = u_t W_V + \tanh(u_t W_{UD}) W_{UU}$$

where $W_V$ is the same weight matrix used to compute the base value $v_t$ (an intentional parameter savings), and $W_{UD} \in \mathbb{R}^{H \times r}$, $W_{UU} \in \mathbb{R}^{r \times H}$ define a LoRA (low-rank adaptation) that adds a data-dependent correction. The $\tanh$ nonlinearity bounds the LoRA input to $[-1, 1]$, stabilizing training.

This second value provides a data-dependent "current token" contribution to the output that is separate from the accumulated kv-state. Unlike the original static $u$, this term can vary based on the token content, allowing the model to decide per-token how much direct contribution (vs. history-derived contribution) is appropriate. The LoRA structure ($W_{UD}$ and $W_{UU}$ with a small rank $r$) keeps the parameter cost low while providing sufficient expressivity for the correction. The paper's ablation (Table 4) shows that removing the second value increases loss from 2.7082 to 2.7105 (for the L12 D768 models), confirming a small but positive contribution.

**The full Finch-C2 computation.** With these changes, the Finch-C2 time-mixing sub-layer proceeds as follows (per head, $H$ dimensional):

First, compute data-dependent decays and derived quantities using the `ddlerp` (data-dependent lerp) operator:

$$d_t = \text{lora}_d(\text{ddlerp}_d(x_t, x_{t-1}))$$

$$w_t = \exp(-\exp(d_t))$$

$$r_t = \text{ddlerp}_r(x_t, x_{t-1}) W_R$$

$$k_t = \text{ddlerp}_k(x_t, x_{t-1}) W_K \cdot (1 - w_t)$$

$$v_t = \text{ddlerp}_v(x_t, x_{t-1}) W_V$$

$$u_t = \text{ddlerp}_u(x_t, x_{t-1})$$

$$u'_t = u_t W_V + \tanh(u_t W_{UD}) W_{UU}$$

where `$x_t \in \mathbb{R}^D$` is the current input to the sub-layer and `$x_{t-1}$` is the previous timestep's input.

The `ddlerp` (data-dependent data linear interpolation) operator is defined as:

$$\text{ddlerp}_\square(a, b) = a + (b - a) \odot \text{lora}_\square(a + (b - a) \odot \mu_x)$$

where `$\mu_x$` is a learned per-channel vector that provides a static interpolation preference, and `$\text{lora}_\square$` is a low-rank adapter that makes the interpolation data-dependent:

$$\text{lora}_\square(x) = \lambda_\square + \tanh(x A_\square) B_\square$$

where `$A_\square \in \mathbb{R}^{H \times r}$` and `$B_\square \in \mathbb{R}^{r \times H}$` (with $r$ small) are learned, and `$\lambda_\square$` is a learned scalar bias. The $\tanh$ ensures the LoRA output is bounded.

**What ddlerp computes, operationally:** It produces an interpolation between the current input $a$ and the previous input $b$, where the interpolation ratio varies per channel based on a learned static preference $\mu_x$ and a data-dependent adjustment from the LoRA. When the LoRA output is 0 (after adding $\lambda_\square$), the interpolation is $a + (b - a) \odot \sigma(\mu_x)$ — a standard learned constant token shift. When the LoRA output is non-zero, the effective interpolation ratio shifts based on the content of $(a + (b - a) \odot \mu_x)$ — the input after being partly shifted toward the previous timestep. This allows the model to decide, on a per-channel basis and conditioned on the current token's content, whether to use more of the current or previous timestep's information.

**Why ddlerp instead of a standard 1D convolution:** A standard 1D convolution with kernel size 2 would use a fixed, data-independent interpolation weight. ddlerp makes this weight data-dependent at very low parameter cost (just the LoRA matrices, which are low-rank). This is the key innovation that originated in the RWKV architecture — it provides the benefits of dynamic temporal mixing (the model can decide per-channel and per-token how much to blend past and present) without the parameter explosion of full attention.

The exponential decay $w_t$ is computed as:

$$d_t = \text{lora}_d(\text{ddlerp}_d(x_t, x_{t-1}))$$

$$w_t = \exp(-\exp(d_t))$$

**Why double-exponential:** The inner $\exp(d_t)$ ensures positivity (so the decay is between 0 and 1), and the outer $\exp(-\cdot)$ maps the positive value to $(0, 1]$, with larger $d_t$ producing smaller $w_t$ (faster forgetting) and smaller $d_t$ producing $w_t$ close to 1 (stronger retention). The double-exponential provides a log-log relationship between the learned parameter $d_t$ and the effective decay, which the RWKV authors have found empirically beneficial for learning appropriate decay rates.

The kv-state is then updated:

$$wkv_t = w_t \cdot wkv_{t-1} + k_t^\top \cdot v_t$$

This is a matrix-valued recurrence: `$wkv_t \in \mathbb{R}^{H \times H}$` is the recurrent state (per head). The decay $w_t$ is applied element-wise to each row of $wkv_{t-1}$ (since $w_t$ is a vector of $H$ elements, one per channel). The outer product $k_t^\top v_t$ produces an $H \times H$ matrix, which is added to the decayed previous state.

**What this updates computes, operationally:** For each channel (row of $wkv_t$), we take the previous state for that channel, decay it by the channel-specific factor $w_t$, and add the new key-value outer product. The result is an accumulated summary of all past key-value pairs, weighted by a cumulative product of decays — distant past contributions are exponentially downweighted. This is exactly analogous to a linear attention mechanism where the "attention weight" of a past token decays exponentially with its age, modulated by data-dependent per-token decay rates.

Finally, the output is:

$$o_t = \text{LayerNorm}(\text{concat}(r_t \cdot wkv_t + u'_t)) W_O$$

The per-head outputs are concatenated across all $N$ heads (producing a $D$-dimensional vector, since $N \times H = D$), LayerNorm is applied across this full vector, and the result is projected with $W_O \in \mathbb{R}^{D \times D}$.

**Why LayerNorm at this position:** The layer normalization ensures the time-mixer output is properly scaled before being added to the residual stream and before entering the channel mixer. Without it, the magnitudes of $r_t \cdot wkv_t$ and $u'_t$ could drift over long sequences (since $wkv_t$ is an accumulation that can grow), leading to training instability. LayerNorm provides a learned affine rescaling that prevents this drift.

**Summary of Finch-C2 innovations relative to Finch:**
- **Removed gate**: Saves parameters; receptance $r_t$ already provides multiplicative gating of the kv-state output.
- **LayerNorm across heads**: Enables cross-head normalization interactions; simplified implementation.
- **Key multiplied by $(1 - w_t)$**: Keeps kv-state rows normalized by scaling the new contribution inversely with retention, preventing state magnitude drift.
- **Second data-dependent value replacing static bonus**: Provides content-dependent direct-path contribution through the current token, with LoRA-based correction for parameter efficiency and reuse of $W_V$ to save parameters.

These changes collectively reduce parameter count (Table 2 shows GoldFinch at 1.45B parameters vs. Finch at 1.60B, despite having additional GOLD layers), while the ablation (Table 4, first row vs. fourth row: 2.7293 without $k \cdot (1-w)$ vs. 2.7082 with it) and the overall GoldFinch performance confirm that the changes improve rather than degrade modeling quality.

#### Key Compression and Decompression (TokenCat Pipeline)

The key compression pipeline is the central mechanism that enables GoldFinch's extreme cache reduction. It transforms the $D$-dimensional output of the final Finch-C2 layer into a $D/16$-dimensional compressed representation for storage, and then reconstitutes a full $D$-dimensional key representation for use by the GOLD attention layers.

**Why compression is necessary:** Without compression, even a global cache (shared across all layers) would still require $D$ elements per token — for a model with $D = 2048$ and a 256k context, this is approximately 1 GB in bfloat16, which is manageable but still substantial. The paper targets two to three orders of magnitude reduction relative to traditional per-layer KV-caches, which requires compressing the cache entries themselves, not just sharing them.

**Step 1: Compression.** The output of the final Finch-C2 layer at position $t$, denoted $x_t \in \mathbb{R}^D$, is projected down to dimension $D/16$ using a single learned matrix shared across all positions:

$$c_t = x_t W_{KD} \in \mathbb{R}^{D/16}$$

where `$W_{KD} \in \mathbb{R}^{D \times (D/16)}$` is a global (not per-layer) weight matrix.

**What this computes:** For each token position $t$, we take the $D$-dimensional hidden state exiting the last Finch-C2 layer and multiply it by a learned projection matrix to produce a compressed vector of dimension $D/16$ (e.g., for $D = 2048$, this is 128 dimensions). This projection is a bottleneck — the model must learn to encode information useful for future attention into this compact representation. Since $W_{KD}$ is learned during training, the compression is optimized end-to-end for the downstream task (language modeling).

**Why $D/16$ specifically:** The paper states a "16:1 hidden-dimension compression ratio" and verifies in Table 2 that GoldFinch with 1:1 compression (no compression, just global caching) achieves identical final loss (2.2762) to the 16:1 version. This is a critical empirical finding: the compression bottleneck does not hurt performance. The paper does not provide a detailed ablation of other compression ratios, but the 16× factor appears to be a sweet spot — aggressive enough to dramatically reduce cache size, but not so aggressive that the compressed representation loses essential information. The mechanism by which information is preserved is the TokenCat decompression (Step 3 below), which supplements the compressed representation with the original token embeddings.

**Step 2: Storage.** The compressed vectors $c_t$ for all positions $t \in [1, L]$ (where $L$ is the sequence length) are stored in a single global key cache. Additionally, the original input token indices are stored (typically 2 bytes per token). The total cache size per token is therefore:

$$\text{size\_per\_token} = \frac{D}{16} \times \text{bytes\_per\_element} + 2 \text{ bytes for index}$$

For bfloat16 (2 bytes per element) and $D = 2048$, this is $128 \times 2 + 2 = 258$ bytes per token. Compare to a traditional transformer's KV-cache for $n_{layer} = 24$ and $D = 2048$: $2 \times 24 \times 2048 \times 2 = 196,608$ bytes per token. The compression ratio is approximately $196,608 / 258 \approx 762\times$, and this ratio grows linearly with the number of layers (more layers means the traditional cache grows but GoldFinch's does not). The paper claims "756-2550 times smaller" depending on layer count, which is consistent with this arithmetic.

**Why store token indices:** The original token embeddings $x^0_t$ are needed during decompression (Step 3). Rather than storing the full $D$-dimensional embedding vectors (which would defeat the purpose of compression), we store only the integer token indices and recompute the embeddings by looking them up in the embedding table when needed. This is a standard space-time tradeoff: the embedding table lookup costs a small amount of compute but saves $D \times \text{bytes\_per\_element}$ bytes per token in storage.

**Step 3: Decompression (TokenCat).** To reconstitute keys for attention, the compressed cache entries are decompressed by concatenating them with the original token embeddings and projecting:

$$k^D_t = \text{RMSNorm}(\text{concat}(x^0_t, c_t) W_{KU})$$

where `$x^0_t \in \mathbb{R}^D$` is the original token embedding at position $t$ (retrieved from the embedding table using the stored token index), `$c_t \in \mathbb{R}^{D/16}$` is the compressed key from the cache, `$\text{concat}(x^0_t, c_t) \in \mathbb{R}^{D + D/16}$` is their concatenation, `$W_{KU} \in \mathbb{R}^{(D + D/16) \times D}$` is a global learned projection matrix, and RMSNorm normalizes the result.

**What this computes, operationally:** For each position, we take two sources of information — the original token identity (from $x^0_t$, which tells us *which* token is at this position) and the compressed Finch-C2 context (from $c_t$, which encodes the token's role and relationships within the sequence) — and combine them through a learned linear projection to produce a full $D$-dimensional key representation. The concatenation ensures that both sources of information are available to the projection without forcing them to interact through a fixed combination (e.g., addition). The RMSNorm stabilizes the output magnitudes.

**Why "TokenCat" (Token conCatenation):** The name emphasizes that the key innovation is the concatenation of compressed cache with original embeddings, rather than using either source alone. If we used only the compressed cache $c_t$, we would have only $D/16$ dimensions of information, which would severely limit the attention mechanism's ability to discriminate between positions. If we used only the original embeddings $x^0_t$, we would lose all the contextual information accumulated by the Finch-C2 layers (e.g., syntactic role, semantic relationships, co-reference). The concatenation gives the decompression step access to both the token identity (high-resolution but decontextualized) and the compressed context (low-resolution but contextualized), and the learned projection $W_{KU}$ learns how to optimally blend them.

**The Zamba connection:** The paper notes that Zamba (Glorioso et al., 2024) independently uses a similar technique: "Zamba concatenates the original embeddings generated before layer zero onto this residual output, and use the double-width combination as the input to attention." The paper cites this as a concurrent validation of the idea, though Zamba applies it differently (for attention input, not for key decompression from a compressed cache).

**Step 4: Key consumption by GOLD layers.** The decompressed proto-keys $k^D_t$ are not used directly as attention keys. Instead, each GOLD layer applies further transformations to produce its own unique keys:

$$k_t = \text{LayerNorm}(\text{loradapt}_k(\text{lerp}(k^D_t, k^D_{t-1}, \text{lora}_k(a_t))))$$

This step (detailed in the GOLD Attention section below) applies a data-dependent token shift to the decompressed keys, making them time-aware, and passes them through a LoRA-based adaptation (loradapt) that allows each layer to learn to extract different information from the shared key representations. The LoRA adaptation is parameter-efficient: it adds only a small number of additional parameters per layer, preserving the overall parameter savings.

**The complete pipeline (from token to attention key):**

1. Token enters model → embedding lookup → $x^0_t$ (stored as 2-byte index)
2. $x^0_t$ passes through Finch-C2 layers → $x_t$ (final Finch-C2 output at this position)
3. $x_t W_{KD} \rightarrow c_t$ (compressed, stored in global cache, $D/16$ dimensions)
4. At GOLD layer $l$, for position $t$: retrieve $x^0_t$ (from embedding table via stored index) and $c_t$ (from cache)
5. $\text{concat}(x^0_t, c_t) W_{KU} \rightarrow k^D_t$ (decompressed proto-key, $D$ dimensions)
6. Data-dependent token shift + LoRA adaptation → $k_t$ (layer-specific attention key, $D$ dimensions)

The critical property is that steps 1–3 only need to be done once per token (during pre-fill for input tokens, as each new token is generated for output tokens), and steps 4–6 are repeated for each GOLD layer at generation time, but the only per-layer storage is the LoRA parameters (which are small), not the keys themselves.

#### GOLD Attention Time Mixing: The Attention Consumer

The GOLD (GPTAlpha Over Linear transformer Decoder) attention mechanism is what consumes the compressed key cache to perform standard multi-head scaled dot-product attention. The key innovation is that GOLD layers do not have learned key and value projection matrices ($W_K$ and $W_V$) of their own — instead, they derive keys from the decompressed proto-keys and values from the original token embeddings, both with data-dependent transformations.

**Why eliminate $W_K$ and $W_V$:** In a standard transformer layer, the key and value projections $x_t W_K$ and $x_t W_V$ are learned per layer. Together with the output projection $W_O$, they constitute a significant fraction of the layer's parameters. By eliminating them (or rather, replacing them with much smaller LoRA-based adaptations of shared representations), GOLD saves parameters and — more importantly — eliminates the need to store separate keys and values per layer. The keys are generated on-the-fly from the shared $k^D_t$, and the values are generated on-the-fly from $x^0_t$.

**Query computation (standard, but with Finch-style token shift).** Queries are computed from the current hidden state with a data-dependent token shift, similar to Finch's receptance mechanism:

$$q_t = \text{LayerNorm}(\text{ddlerp}_q(x_t, x_{t-1}) W_Q)$$

where `$x_t$` is the input to this GOLD sub-layer (from the residual stream), `$x_{t-1}$` is the previous timestep's input, `$\text{ddlerp}_q$` performs a data-dependent interpolation between current and previous inputs, `$W_Q \in \mathbb{R}^{D \times D}$` is the query projection, and LayerNorm normalizes the result. The query is the only component that is computed entirely from the current hidden state with its own full-rank weight matrix — it is the "question" that attention asks of the key-value memory.

**Attention data for keys and values.** Both keys and values are conditioned on a shared attention data vector $a_t$, which provides contextual information about the token shift:

$$a_t = \text{lerp}(x^0_t, x^0_{t-1}, \mu_x)$$

where `$\text{lerp}(a, b, t) = a + (b - a) \odot t$` is the standard linear interpolation, `$x^0_t$` and `$x^0_{t-1}$` are the original token embeddings at the current and previous positions, and `$\mu_x$` is a learned per-channel static interpolation weight.

**What $a_t$ represents, and why use $x^0$ rather than the hidden state:** The vector $a_t$ is a simple interpolation between the current and previous token embeddings, providing a lightweight signal about the transition between consecutive tokens. The paper explicitly justifies using $x^0$ for this purpose rather than the hidden state: "Note that the token shift cannot be dependent on the hidden-state, as that would make recurrent calculation impossible for older keys and values, and would require a full KV-Cache to be stored. Instead, we use the original input token embeddings as the data upon which the key and value token-shifts depend." This is a critical design constraint: if keys depended on the hidden state at their position, then during autoregressive generation we would need to re-run the entire model for all past positions to recompute their keys whenever the hidden state evolved — defeating the purpose of caching. By making the token shifts for keys and values depend only on $x^0$ (which is static and stored), the keys and values for past positions remain valid without recomputation.

**Key computation (from decompressed proto-keys).** Each GOLD layer produces its own keys by applying a data-dependent token shift and a LoRA-based adaptation to the shared decompressed proto-keys:

$$k_t = \text{LayerNorm}(\text{loradapt}_k(\text{lerp}(k^D_t, k^D_{t-1}, \text{lora}_k(a_t))))$$

Breaking this down from inside out:
- `$\text{lora}_k(a_t)$`: A low-rank adapter takes the attention data $a_t$ (the token-embedding-derived transition signal) and produces per-channel interpolation weights for the key token shift. This makes the interpolation data-dependent — the model can decide, based on the token transition, how much to blend the current and previous proto-keys.
- `$\text{lerp}(k^D_t, k^D_{t-1}, \text{lora}_k(a_t))$`: Linear interpolation between the current and previous decompressed proto-keys, using the data-dependent weights. This provides a simple form of local temporal context to the keys.
- `$\text{loradapt}_k(\cdot)$`: A LoRA-based adaptation defined as:

$$\text{loradapt}_\square(x) = x + \tanh(x C_\square) D_\square$$

where `$C_\square \in \mathbb{R}^{D \times r}$` and `$D_\square \in \mathbb{R}^{r \times D}$` are learned low-rank matrices (per layer, per component). The $\tanh$ bounds the input to the second projection, and the result is added to the original $x$ — this is a residual LoRA, meaning the adaptation is a correction to the identity mapping rather than a full transformation.

- `$\text{LayerNorm}(\cdot)$`: Normalizes the adapted keys.

**What this produces:** A per-layer, per-position key vector that combines (a) the compressed contextual information from Finch-C2 ($k^D_t$), (b) local temporal context from the token shift (blending $k^D_{t-1}$ with $k^D_t$), and (c) layer-specific adaptation via the LoRA residual. Different GOLD layers can learn different LoRA parameters $C_k$ and $D_k$, allowing them to extract different features from the same shared proto-keys — one layer might focus on syntactic relationships while another focuses on semantic content.

**Value computation (from original token embeddings).** Values are computed similarly, but from the original token embeddings rather than from decompressed keys:

$$v_t = \text{LayerNorm}(\text{loradapt}_v(\text{lerp}(x^0_t, x^0_{t-1}, \text{lora}_v(a_t))))$$

The structure is identical to the key computation, but uses $x^0_t$ (the embedding) as the base representation instead of $k^D_t$ (the decompressed proto-key). This is how GoldFinch eliminates the value cache: values are generated on-demand from the stored token indices (which give us $x^0_t$) rather than stored. The LoRA adaptation allows each layer to derive different value representations from the same embeddings, and the token shift provides local temporal context.

**Why separate key and value sources:** Keys need to encode information useful for matching — determining which past positions are relevant to the current query. The decompressed proto-keys $k^D_t$, which are derived from the Finch-C2 output, encode rich contextual information (syntax, semantics, co-reference) that is useful for this matching task. Values need to encode the information that should be aggregated once relevant positions are identified — the actual content to attend to. The original token embeddings $x^0_t$ encode fine-grained token identity and are well-suited as a base for value construction. By using different sources for keys and values, the architecture separates the "lookup" and "content" functions of attention, allowing each to be optimized independently.

**Attention computation.** With queries, keys, and values produced, standard scaled dot-product attention is applied:

$$o_t = \text{LayerNorm}(\text{concat}(\text{attention}(q_t, k, v)) W_O)$$

where attention is the standard multi-head formulation (each head computes $\text{softmax}(q_h k_h^\top / \sqrt{H}) v_h$), the per-head outputs are concatenated, LayerNorm is applied, and $W_O \in \mathbb{R}^{D \times D}$ projects to the output dimension.

**The explicit positional encoding situation.** The paper makes a nuanced claim about positional encoding in GoldFinch (Section 1, benefit 5):

> "By using Finch-C2 blocks at the start of the model, the key cache automatically encodes the underlying implicit positional representation, thereby removing the need for positional encoding within our transformer layers for trained context lengths."

The Finch-C2 layers, being recurrent, process tokens in order and their hidden states naturally encode position through the recurrent dynamics — the state at position $t$ is a function of all previous positions, with implicit positional information in the decay structure. This positional information is compressed into $c_t$ and thus available to the GOLD layers through the decompressed keys. For context lengths up to the trained maximum (1024 or 2048 in the paper's experiments), this implicit positional encoding is sufficient.

However, for extrapolation beyond trained context lengths, the paper acknowledges: "We do still require an additional positional encoding method for extrapolation to new context lengths unseen during training." The long-context experiments (Section 4.4) confirm this: "The GoldFinch model trained with RoPE on its GOLD attention sub-layers performs better, but loss still increases somewhat as the sequence progresses. However, by applying interpolated RoPE values we are able to obtain low loss throughout the extended context length." So the practical recommendation is: if extrapolation is needed, train GOLD layers with Rotary Position Embedding (RoPE) and use position interpolation at inference time.

**Why the Finch-C2 implicit positional encoding works for trained lengths:** Each Finch-C2 layer's $wkv_t$ state accumulates information with exponentially decaying weights that depend on position within the sequence (tokens further in the past are more decayed). When this state is used to produce $x_t$ (the layer output), the resulting representation implicitly encodes how far back various pieces of information occurred. This positional signal propagates through the residual stream and into the compressed cache $c_t$. The GOLD attention layers, by attending over these position-tagged keys, can learn to use this implicit signal for within-trained-length positioning without explicit position encodings.

#### Finch Channel Mixing (The Feed-Forward Network)

The channel mixing sub-layer serves as the feed-forward network (FFN) in both Finch-C2 and GOLD layers. Unlike a standard transformer FFN (two linear projections with a GeLU or ReLU activation in between), the Finch channel mixer uses a gated architecture with squared ReLU activation. The paper uses this identically in both the recurrent and attention portions of the model, replacing the Llama-style FFN that would normally accompany transformer attention layers.

$$r_t = \text{lerp}_r(x_t, x_{t-1}, \mu_r) W_R \in \mathbb{R}^D$$

$$k_t = \text{lerp}_k(x_t, x_{t-1}, \mu_k) W_K \in \mathbb{R}^{3.5D}$$

$$v_t = \text{ReLU}(k_t)^2 W_V \in \mathbb{R}^D$$

$$o_t = \sigma(r_t) \odot v_t \in \mathbb{R}^D$$

where `$x_t$` and `$x_{t-1}$` are the current and previous inputs to this sub-layer, `$\mu_r$` and `$\mu_k$` are learned static interpolation vectors (standard token shift, not data-dependent ddlerp), `$W_R \in \mathbb{R}^{D \times D}$`, `$W_K \in \mathbb{R}^{D \times 3.5D}$`, `$W_V \in \mathbb{R}^{3.5D \times D}$` are learned weight matrices, `$\sigma$` is the sigmoid function, and `$\odot` is element-wise multiplication.

**Step-by-step operational description:**

1. **Receptance gate:** $r_t$ is computed by applying a static token shift (lerp between current and previous inputs with learned weight $\mu_r$) followed by a linear projection $W_R$. The sigmoid $\sigma(r_t)$ produces values in $(0, 1)$, which will gate the output.

2. **Key (expanded representation):** $k_t$ is computed similarly with a different static token shift ($\mu_k$) and projected to $3.5D$ dimensions via $W_K$. This expansion gives the network a higher-dimensional space in which to compute nonlinear transformations, similar to the expansion factor in standard transformer FFNs (typically 4×). The $3.5\times$ factor is a specific design choice from the RWKV lineage.

3. **Value (nonlinear transformation):** $v_t$ is computed by applying ReLU to $k_t$ (zeroing out negative values), squaring the result (making all values non-negative and creating a smooth nonlinearity), and projecting back to $D$ dimensions with $W_V$. The ReLU-squared activation is notable: it is smooth (unlike ReLU at zero) and produces strictly non-negative outputs, which may interact favorably with the sigmoid gating.

4. **Gated output:** The final output is the element-wise product of the gate $\sigma(r_t)$ and the transformed value $v_t$. This allows the network to selectively suppress or amplify different channels of the value representation based on the receptance gate, which is conditioned on the token-shifted input.

**Why squared ReLU:** Standard transformer FFNs use GeLU or ReLU activations. Squared ReLU ($\text{ReLU}(x)^2$) has the property that it is zero for negative inputs and grows quadratically for positive inputs. This provides a different nonlinear profile than GeLU (which has a smooth transition around zero) and may be beneficial for certain types of feature interactions. The paper inherits this choice from the RWKV/Finch lineage without extensive ablation against alternatives.

**Why a channel mixer rather than a standard FFN in GOLD layers:** The paper integrates this channel mixer into the GPTAlpha architecture (which underlies GOLD) as a replacement for the standard transformer FFN. In the ablation study (Table 4), GPTAlpha (which uses this channel mixer) achieves 2.6684 loss compared to Llama's 2.7125, suggesting the channel mixer contributes to the performance improvement. The paper does not provide a direct ablation comparing channel mixer vs. standard FFN within the same GPTAlpha architecture, so the specific contribution of the channel mixer is confounded with other GPTAlpha changes (token shifts, extra LayerNorms).

**Parameter count implications:** The channel mixer uses an expansion factor of 3.5× rather than the standard 4× used in many transformers, which provides a small parameter savings. Combined with the Finch-C2 parameter reductions (removed gate, shared $W_V$), this contributes to GoldFinch's overall parameter efficiency relative to Finch (1.45B vs. 1.60B for the L24 D2048 models).

#### GPTAlpha: The Standalone Transformer Variant

The paper introduces GPTAlpha as an improved transformer architecture that can be used independently of the GoldFinch compression pipeline. It serves two purposes in the paper: (1) as a standalone baseline showing that the architectural improvements (channel mixer, token shifts, extra LayerNorms) genuinely improve transformer performance, and (2) as the foundation for GOLD, which removes GPTAlpha's $W_K$ and $W_V$ in favor of the compression-based key/value generation.

**GPTAlpha time mixing (standalone, without TokenCat compression):**

$$q_t = \text{LayerNorm}(\text{ddlerp}_q(x_t, x_{t-1}) W_Q)$$

$$k_t = \text{LayerNorm}(\text{ddlerp}_k(x_t, x_{t-1}) W_K)$$

$$v_t = \text{LayerNorm}(\text{ddlerp}_v(x_t, x_{t-1}) W_V)$$

$$o_t = \text{LayerNorm}(\text{concat}(\text{attention}(q_t, k, v)) W_O)$$

**Differences from standard Llama attention:**

1. **Data-dependent token shifts (ddlerp)** on queries, keys, and values. Llama uses no token shift — the input $x_t$ is projected directly. The ddlerp provides a data-dependent interpolation with the previous timestep's input, giving the attention mechanism local temporal context. This is the same ddlerp mechanism used in Finch-C2, ported to the transformer context.

2. **LayerNorm after every projection.** Llama typically applies LayerNorm only to the input of the attention sub-layer (pre-norm), not to the individual Q, K, V projections. GPTAlpha applies LayerNorm after each of $W_Q$, $W_K$, and $W_V$, and after the concatenated attention output (before $W_O$). This is a total of four additional LayerNorms per attention sub-layer. The paper includes "adding RWKV style token shifts and extra LayerNorms to attention layers" as the key modifications to obtain GPTAlpha from Llama.

3. **Finch channel mixer replacing the standard FFN.** Instead of the Llama FFN (two linear layers with SiLU activation in between), GPTAlpha uses the Finch channel mixer described above with its squared ReLU activation and gating mechanism.

**Why these changes help:** The paper does not provide a detailed theoretical justification, but the empirical evidence is in Table 4: GPTAlpha achieves 2.6684 loss vs. Llama's 2.7125 (L12 D768 models), a substantial improvement. Possible mechanisms:
- The token shifts provide explicit local temporal context that the attention mechanism would otherwise need to learn to extract from the positionally-encoded inputs, reducing the learning burden.
- The extra LayerNorms may stabilize training dynamics, especially in deeper models, by preventing internal covariate shift within the attention computation.
- The channel mixer's gating mechanism ($\sigma(r_t) \odot v_t$) may be more expressive than the standard FFN's additive structure, providing better feature selection.

**Ablation evidence:** Table 4 shows GPTAlpha with RoPE at 2.6684 loss. When combined with Finch-C2 layers in a hybrid (last 1/3 layers GPTAlpha, first 2/3 Finch-C2) but without compression, the loss is 2.6586 — very close to GoldFinch's 2.6582 with the same architecture and 1/3 GOLD fraction. This indicates that the compression pipeline costs essentially nothing in terms of modeling quality — the 16:1 compression is effectively lossless for language modeling on this dataset.

#### Pre-Fill and Inference Procedures

The architectural innovations described above translate into specific computational procedures during inference that realize the theoretical efficiency gains.

**Pre-fill (processing the input context).** When a user submits a prompt of $L$ tokens, the model must compute the compressed key cache entries for all $L$ positions before autoregressive generation can begin. The paper claims $O(1)$ time per token for pre-fill:

> "pre-fill computation of the entire initial cache state for a submitted context costs only O(1) time per token due to the use of a recurrent neural network (RNN) to generate this cache"

The procedure:

1. For positions $t = 1, 2, ..., L$: pass token $t$ through the embedding layer and through all Finch-C2 layers recurrently. Each Finch-C2 layer requires only the current input and its own previous hidden state ($wkv_{t-1}$), which was updated at the previous position. The cost per layer per token is dominated by the matrix multiplications for the ddlerp operations, which are $O(D^2)$ (fixed with respect to sequence length), and the $wkv$ update, which is $O(H^2 \cdot N_{\text{heads}})$ (also fixed). So the per-token cost is $O(1)$ with respect to $L$, and the total pre-fill cost is $O(L)$.

2. At each position $t$, compute the compressed key $c_t = x_t W_{KD}$ (where $x_t$ is the output of the final Finch-C2 layer) and store $c_t$ in the global key cache. Also store the token index (2 bytes).

3. **The last $2G-1$ tokens require special handling.** The paper identifies a subtle issue: "token shift requires the prior layer hidden-state output from the previous time-step. At first glance this appears problematic, as the GOLD layers require full quadratic attention, which is what we were trying to avoid during pre-fill." The GOLD layers' ddlerp and channel mixer lerp operations require $x_{t-1}$ (the previous timestep's input) for each sub-layer. These hidden states are from within the GOLD layers themselves, and computing them requires running the full model (including GOLD attention). The solution:

> "given $G$ GOLD layers in the model, there must be $2G - 1$ sub-layers that require such a previous time-step hidden state but are directly or indirectly reliant on the outputs of quadratic attention. Therefore, the last $2G - 1$ tokens of pre-fill must be run through the full model (not just the Finch-C2 layers) to generate these hidden-states."

In other words, to initialize the token-shift hidden states for all GOLD sub-layers, the final $2G-1$ positions of the input need to pass through the full model (including quadratic attention). The paper notes this can be done efficiently: "These $2G - 1$ computations can be done in a single call to the full model to leverage the same kinds of parallelism used during training" — meaning you can batch the $2G-1$ tokens through the full model in a single forward pass with causal masking, which is $O((2G-1)^2)$ attention but with a very small constant since $2G-1$ is small (e.g., for a 24-layer model with 8 GOLD layers, $2G-1 = 15$).

The key point is that the $O(N^2)$ attention cost during pre-fill applies only to this small window of $2G-1$ tokens, not to the entire input. All preceding tokens are processed only through the $O(1)$-per-token Finch-C2 layers. For long inputs (thousands of tokens with $G$ typically 4–12), the pre-fill cost is dominated by the linear Finch-C2 processing, making it effectively $O(L)$ rather than $O(L^2)$.

**Autoregressive generation (decoding).** When generating the next token at position $L+1$:

1. The new token passes through the embedding layer and all Finch-C2 layers (recurrently updating the $wkv$ states), producing a new $x_{L+1}$ at the final Finch-C2 layer output.

2. Compute the compressed key $c_{L+1} = x_{L+1} W_{KD}$ and append it to the global key cache.

3. Pass $x_{L+1}$ through the GOLD layers, which perform full quadratic attention over all $L+1$ positions. The keys and values for positions $1$ through $L$ are recomputed on-the-fly from the global cache and embedding table using the decompression and adaptation steps described above. This recomputation is $O(L)$ per GOLD layer, making per-token generation cost $O(L)$ overall — the same asymptotic complexity as standard transformer generation, but with dramatically lower memory usage because only the compressed cache (not full per-layer KV-caches) is stored.

**Memory-efficient incremental attention.** The paper describes an implementation optimization for extremely low VRAM usage:

> "Because decompression and token shift can be done on contiguous regions of key value pairs instead of all of them at once, extremely low VRAM usage can be achieved during inference by calculating attention incrementally across the sequence for each layer and decompressing as you go."

This means that rather than decompressing all $L$ cache entries at once (which would require $O(L \cdot D)$ memory for the decompressed keys), the implementation can process the sequence in chunks: decompress a block of keys, compute attention for that block, accumulate the attention output, and discard the decompressed keys. The peak memory usage is then determined by the chunk size rather than the full sequence length, enabling inference on sequences that would otherwise exceed VRAM even with the compressed cache. This is analogous to block-wise attention or FlashAttention-style tiling, applied to the decompression step.

**Checkpoint upgrade training (Section 4.5).** The paper describes attempts to convert pre-trained Finch models into GoldFinch models through fine-tuning rather than training from scratch. Two methods were explored:

1. **Append GOLD layers:** Add 4 new GOLD layers on top of a pre-trained 1.6B Finch checkpoint (originally 24 layers), freeze the original 24 layers at their final learning rate (1e-5), and train the new layers with a cosine-annealed learning rate from 3e-4 to 1e-5 for 100 million tokens. The result: "performance of this model was in line with the original model, it was unclear if the resultant model from this method really learned anything of value in its GOLD layers."

2. **Replace upper layers:** Freeze the embedding and lower Finch layers, replace the final 1/3 of the channel mixer sub-layers with newly initialized GOLD attention sub-layers (keeping the same total layer count), and train for 7.5 billion tokens. The result: "obtained a similar validation loss on minipile to the base model, despite being trained on a completely different dataset and the base model having been already trained for over 2.25 trillion tokens. However, the new model's LAMBADA scores were worse." The paper attributes the degradation to "the 'brain surgery' required to keep the layer count the same, in which we effectively erased the Finch time-mix parameters in the upper 1/3rd of the model."

The paper frames these as ongoing work and does not claim success, but the attempts suggest that warm-starting GoldFinch from pre-trained Finch models is non-trivial — the architectural changes (removing gates, adding GOLD layers, training the compression matrix $W_{KD}$ from scratch) are significant enough that direct fine-tuning may not recover the performance of training from scratch, at least with the limited upgrade training budgets attempted.

#### Summary of Key Design Decisions and Tradeoffs

**Design Decision 1: Compression ratio of 16:1.** The paper empirically verifies that 1:1 compression (no compression) achieves identical loss to 16:1 compression (Table 2), but does not explore intermediate ratios (e.g., 4:1, 8:1) to find the point where compression starts to hurt. The choice of 16:1 appears to be aggressive-but-safe — it's validated as lossless on minipile, but whether this holds for more complex datasets or larger models is untested.

**Design Decision 2: TokenCat specifically, not just concatenation.** The concatenation of compressed cache with original embeddings is essential because the compressed cache alone ($D/16$ dimensions) is too information-poor to support effective attention. The original embeddings provide the high-resolution token identity that the compressed cache lacks. An alternative would be to use a less aggressive compression ratio (e.g., $D/4$) and skip the concatenation, but this would increase cache size by 4×.

**Design Decision 3: Shared $W_V$ between the base value and the second value in Finch-C2.** The paper notes this is "an intentional parameter count savings" — the second value computation $u'_t = u_t W_V + \tanh(u_t W_{UD}) W_{UU}$ reuses the same $W_V$ that produces the base value $v_t$. This means the second value is not a completely independent value pathway but rather a data-dependent modulation of the same value projection. The LoRA ($W_{UD}$ and $W_{UU}$) provides the differentiation, keeping the parameter cost low.

**Design Decision 4: Using $x^0$ (original embeddings) as the conditioning signal for key and value token shifts in GOLD layers.** This is a crucial choice motivated by the caching constraint: if token shifts depended on the hidden state, the keys and values for past tokens would become invalid whenever the model's hidden representations evolved (which they do during generation, as new context is added). By conditioning only on $x^0$ (which is static), the past keys and values remain valid regardless of future context, enabling the single global cache approach.

**Design Decision 5: Finch channel mixer used universally.** Rather than developing separate FFN components for the recurrent and attention portions, the paper uses the same Finch channel mixer throughout. This simplifies the architecture and likely contributes to the parameter efficiency, but it means GoldFinch inherits whatever limitations the Finch channel mixer has relative to other FFN designs (e.g., SwiGLU). The paper does not ablate the channel mixer against alternatives in the GOLD layers.

**Design Decision 6: Implicit positional encoding from Finch-C2 for trained lengths, explicit RoPE for extrapolation.** The architecture relies on the recurrent layers to encode positional information, which works for lengths seen during training. For extrapolation, RoPE with interpolation is needed. This is a pragmatic compromise — the recurrent positional encoding is "free" (no additional parameters or computation) for in-distribution lengths, and RoPE is added only when extrapolation is required. The paper does not explore whether training with RoPE from the start (even for in-distribution lengths) would improve or degrade performance.

## 4. Key Insights and Innovations

### Innovation 1: KV-Cache Reduction Is Framed as an Information Transmission Problem, Not a Compression Problem

The dominant paradigm for reducing KV-cache size in transformers has been to treat it as a *compression* problem: take the full cache and make it smaller. GQA (Ainslie et al., 2023) compresses by sharing heads. MLA (DeepSeek-AI et al., 2024) compresses by low-rank projection of the key-value pairs. Quantization schemes compress by reducing numerical precision. All of these operate on the cache *after* it has been produced by the standard attention mechanism — they are post-hoc reductions of information that was already computed at full fidelity.

GoldFinch makes a fundamentally different move: it treats the KV-cache not as something to be compressed, but as an **information transmission channel** between two architectural components — a recurrent encoder (Finch-C2) and an attention decoder (GOLD). The question becomes: what is the *minimum information* that must be transmitted from the recurrent portion to the attention portion to enable effective attention? This reframes the problem from "how do we squeeze down the cache" to "what does the attention mechanism actually need to know about each token."

The evidence for why this reframing matters is in Table 2: GoldFinch with 16:1 compression achieves identical loss to GoldFinch with 1:1 compression (both 2.2762). If compression were inherently lossy, we would expect the compressed version to underperform. The fact that it doesn't — that a 16× reduction in the information transmitted through the cache produces no degradation — suggests that the standard KV-cache transmits substantial *redundant* information. The recurrent layers have already encoded the relevant contextual information into representations that can survive aggressive dimensionality reduction, and the TokenCat mechanism (concatenating compressed representations with original embeddings) provides the attention layers with exactly what they need: high-resolution token identity (from embeddings) plus low-resolution but contextualized relational information (from the compressed cache).

This is not an incremental improvement on compression techniques — it's a **conceptual reframing** that changes what we optimize. Instead of asking "how do we make the cache smaller without hurting performance," we ask "what is the information-theoretic bottleneck between the recurrent and attention components, and can we train the encoder to produce representations that saturate that bottleneck?" The paper does not use information-theoretic language, but the architecture embodies this logic: $c_t = x_t W_{KD}$ is a learned projection to a $D/16$-dimensional bottleneck, trained end-to-end with the language modeling objective. The model learns to encode the attention-relevant information into those 128 dimensions (for $D=2048$) because that's all the channel capacity it's given. The finding that 1:1 compression doesn't help (Table 2) is actually the most important result in the paper — it proves the bottleneck is not binding, meaning the relevant information fits in far fewer bits than the standard cache provides.

---

### Innovation 2: Separating "What Token Is There" from "What Role Does It Play" Enables Extreme Compression

A standard transformer KV-cache entry for a token encodes two things simultaneously and opaquely: the token's identity (which word it is) and its contextual role (how it relates to other tokens, what syntactic/semantic function it serves, what co-references it participates in). These are entangled in the $D$-dimensional key and value vectors — you cannot separate "this is the word 'cat'" from "this is the subject of the sentence that was modified by the adjective three tokens back."

GoldFinch's TokenCat mechanism makes this separation **architecturally explicit**. The original token embedding $x^0_t$ encodes identity (and is stored essentially for free, as a 2-byte integer index). The compressed cache $c_t$ encodes contextual role (and is stored in $D/16$ dimensions). These are transmitted through separate channels and combined only at the point of use via concatenation and projection:

$$k^D_t = \text{RMSNorm}(\text{concat}(x^0_t, c_t) W_{KU})$$

This decomposition matters because identity information is both high-dimensional (distinguishing among tens of thousands of vocabulary items) and slowly-changing (the embedding for "cat" is the same wherever it appears). Contextual role information is lower-dimensional (the space of possible syntactic/semantic relationships is smaller than the vocabulary) but highly position-dependent. Standard KV-caches use the same high-dimensional representation for both, which is wasteful: you're using a $D$-dimensional vector to convey information that might be capturable in far fewer dimensions once separated from identity.

The connection to Zamba (Glorioso et al., 2024) is instructive here. Zamba independently discovered that concatenating original embeddings with residual outputs improves attention quality, but it does this at full dimensionality and does not compress either stream. GoldFinch takes the additional step of recognizing that the two streams have different information content and can therefore be transmitted at different bandwidths. The identity stream needs full resolution; the context stream can be heavily compressed. This is not an obvious move — it requires the empirical verification that 16:1 compression of the context stream is lossless (Table 2) — but it has the flavor of a **diagnostic insight**: the field has been storing identity and context together not because they need the same representational capacity, but because standard attention architectures entangle them.

The significance extends beyond the specific 16:1 ratio. The conceptual separation suggests a research direction: what other information categories can be disentangled and transmitted at different rates? Positional information (already partially separated in some architectures via explicit position encodings), document-level metadata, task instructions — all might benefit from explicit separation rather than opaque entanglement in the hidden state.

---

### Innovation 3: The Hybrid Architecture Is Not Just an Efficiency Hack — It's a Better Model, Period

The conventional narrative around hybrid RNN-transformer architectures has been: you sacrifice some modeling quality to gain efficiency. YOCO (Sun et al., 2024) established that a hybrid could match transformer performance while reducing cache size, which was already a strong result — equal quality at lower cost. H3 (Fu et al., 2023) showed that even two attention layers in an otherwise SSM model could beat pure transformers, hinting that hybrids might be more than just a compromise.

GoldFinch pushes this further: **the hybrid architecture is not merely competitive with transformers — it outperforms them.** Table 2 shows GoldFinch at 2.2762 final loss versus 2.3905 for Llama (a gap of over 0.1, which is substantial at this scale) and 2.3856 for Finch. Table 3 shows GoldFinch beating both baselines on 7 of 8 downstream benchmarks, with an average accuracy advantage of roughly 1.2–1.4 percentage points. This is not "efficiency with a small quality penalty" — it's efficiency *and* quality improvement simultaneously.

What makes this intellectually significant is that it challenges the **implicit assumption that attention is the optimal computation to apply at every layer.** The standard transformer applies the same operation — full quadratic attention — uniformly across depth. GoldFinch suggests this is suboptimal: recurrent computation in early layers followed by attention in later layers produces better results than attention everywhere. The mechanism likely involves a division of labor: early layers can use the recurrent state to build up a compressed representation of the sequence (exploiting the fact that early-layer features are more local and benefit from the inductive bias of recurrence), while later layers use attention to access specific information from anywhere in the compressed representation (exploiting attention's strength at precise retrieval).

The ablation in Table 4 provides further evidence for this division-of-labor interpretation. The pure Finch-C2 model (all recurrent) achieves 2.7082 loss. The pure GPTAlpha model (all attention) achieves 2.6684. But the hybrid with 1/3 GOLD layers achieves 2.6582 — better than either pure architecture. The hybrid is not averaging the strengths of both; it's producing something *better than the better of the two*. This is a genuinely non-obvious result: if attention is strictly more powerful than recurrence, you'd expect all-attention to win. If recurrence is strictly better, you'd expect all-recurrence to win. The fact that a mix wins suggests there are complementary computational properties — recurrence is better at some aspects of sequence processing and attention at others — and that stacking them in the right order extracts the benefits of both.

The YOCO comparison sharpens this point. YOCO demonstrated that a hybrid could *match* transformer performance with a smaller cache. GoldFinch demonstrates that a hybrid can *beat* transformer performance with a much smaller cache. The difference is not just quantitative (0.1 loss improvement vs. 0.0 loss penalty) but qualitative: it transforms the hybrid architecture from a pragmatic compromise into a positive design choice.

---

### Innovation 4: Data-Dependent Token Shifts Are a General-Purpose Mechanism That Works Across Architectural Boundaries

Token shifting — interpolating between the current and previous timestep's representations — originated in the RWKV lineage as a core component of the recurrent time-mixer. It provides local temporal context at very low parameter cost (just a few learned interpolation weights, or slightly more for the data-dependent ddlerp variant). The natural assumption would be that token shifting is specifically useful for recurrent architectures, where the state update inherently depends on the previous timestep.

GoldFinch demonstrates that token shifting generalizes successfully to attention layers. The GOLD attention mechanism applies ddlerp to queries, and applies a simpler lerp + LoRA combination to keys and values. GPTAlpha (the standalone transformer) applies ddlerp to all of Q, K, and V. The ablation evidence (Table 4) shows GPTAlpha with these token shifts achieving 2.6684 loss versus Llama's 2.7125 — a substantial improvement coming from a transformer that differs from Llama primarily in the addition of token shifts, extra LayerNorms, and the channel mixer.

This is an **architectural insight**: local temporal context is useful regardless of whether the computation is recurrent or attention-based. The standard transformer provides temporal information only through positional encodings (which are static and data-independent) and through the attention mechanism itself (which is global, not local). Token shifts provide a complementary signal: a data-dependent, channel-specific interpolation with the immediate past that operates before and independently of attention. They are effectively a learned local filter — a form of dynamic convolution with kernel size 2 — that the attention mechanism can then build upon.

The GOLD key/value token shift design (Section 3.4) takes this insight further by recognizing a **caching constraint** that is easy to miss. If key and value token shifts depended on the hidden state (as they do in Finch-C2), then past keys and values would need recomputation whenever the hidden state changed (which happens at every generation step, as new context is added). By conditioning key and value token shifts on $x^0$ (the original embeddings, which are static) rather than on the hidden state, the shifted keys and values for past tokens remain valid forever. The architecture thus achieves data-dependent temporal smoothing for attention keys and values *without* sacrificing cacheability — a non-trivial design constraint that the paper handles cleanly.

This is not a massive performance leap, but it's a genuine **architectural contribution**: the demonstration that a mechanism developed for recurrent architectures ports naturally to attention architectures and produces consistent improvements. It suggests that token shifting may be a broadly applicable technique that future architectures (hybrid or otherwise) can adopt as a standard component, much like LayerNorm or residual connections.

---

### Innovation 5: Perfect Associative Recall Is Achieved Without Storing Full Attention State

Multi-query associative recall (MQAR) — the ability to retrieve specific previously-seen key-value pairs from a sequence — has been a persistent weakness of linear attention and state-space models. Arora et al. (2023) extensively benchmarked this and found a performance gap between linear transformers and standard softmax attention on MQAR tasks. The explanation is intuitive: linear attention models compress the entire history into a fixed-size state, which fundamentally limits their ability to recall arbitrary specific items — the state simply doesn't have enough capacity to store every key-value pair exactly. This has been understood as a fundamental tradeoff: you can have efficient recurrence or precise recall, but not both.

GoldFinch achieves **perfect MQAR scores** (Figures 3 and 4) while maintaining $O(1)$ pre-fill and dramatically compressed caching. How? The GOLD attention layers can attend over the entire compressed cache with standard quadratic attention. The recurrent Finch-C2 layers handle the efficient pre-fill, but the attention layers handle the precise retrieval. This is not "solving" the linear attention recall problem — it's acknowledging that the problem is inherent to purely recurrent architectures and sidestepping it by using attention where recall matters.

The intellectual contribution here is making explicit what was implicit in earlier hybrid work (H3, YOCO): **recall and efficiency are separable concerns that can be handled by different architectural components.** The Finch-C2 layers are optimized for efficient, lossy compression of the sequence into a state and a cache. The GOLD layers are optimized for precise, lossless retrieval from that cache. Neither component needs to solve both problems. This division of labor is what enables the architecture to claim both benefits — perfect MQAR (from attention) and $O(1)$ pre-fill (from recurrence) — without the standard tradeoff.

The significance goes beyond the specific architecture. It suggests a general design principle for sequence models: rather than searching for a single mechanism that is simultaneously efficient and precise (which may be impossible, per the MQAR results), design architectures where different components specialize in different aspects of the problem and communicate through a compressed interface. The compressed cache is not just a memory-saving device — it's the **interface specification** between the two components, defining what information the recurrent encoder must provide and what the attention decoder can expect. The paper's empirical finding that this interface can be extremely narrow (16:1 compression) while supporting perfect recall is genuinely surprising and suggests the recurrent encoder is learning to produce representations optimized specifically for attention-based retrieval.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** All primary experiments use **minipile** (Kaddour, 2023), a 1.5 trillion token subset of The Pile designed for data-efficient language modeling research. The paper does not explicitly state the train/validation split sizes, but the loss curves in Figure 2 show both training and validation loss, implying a standard held-out validation set was used. For long-context evaluation, the **PG19** dataset (Rae et al., 2019) of older books is used to test loss at context lengths up to 65,536 tokens (Section 4.4). For MQAR experiments, synthetic key-value retrieval tasks are used following the protocol of Arora et al. (2023) (Section 4.3).

- **Base model(s).** Three model families are trained from scratch at the 1.5B parameter class for direct comparison: **Llama** (Touvron et al., 2023) using standard transformer architecture with the RWKV small init embeddings optimization but no Grouped-Query Attention (to give it "the most favorable conditions"), **Finch** (RWKV-6, Peng et al., 2024) using the standard Finch architecture, and **GoldFinch** using the proposed hybrid architecture. All models use 24 layers, 2048 hidden dimension, and 2048 context length, with the RWKV World tokenizer. For ablations, smaller L12 D768 ctx1024 models are trained (Section 4.2). The paper also uses a pre-trained 1.6B Finch checkpoint trained on 2.5 trillion tokens for the checkpoint upgrade experiments (Section 4.5).

- **Metrics.** The primary metric is **training and validation loss** (cross-entropy) on minipile (Table 2, Figure 2). For downstream evaluation, the paper reports **zero-shot accuracy** on LAMBADA (lmbd), PIQA (piqa), HellaSwag (hella), WinoGrande (winog), ARC-Challenge (arc_c), ARC-Easy (arc_e), and SCIQ (sciq), plus **perplexity** (ppl) on a held-out set (Table 3). For MQAR experiments, **exact match accuracy** on key-value retrieval is reported (Figures 3, 4). For long-context experiments, **perplexity/loss on PG19** at varying context lengths is reported (Section 4.4).

- **Baselines.** The paper compares against:
  - **Llama** (Touvron et al., 2023): Standard transformer with pre-norm, RoPE, and SwiGLU FFN, modified with RWKV small init embeddings optimization and trained without GQA for fair comparison.
  - **Finch** (Peng et al., 2024): Standard RWKV-6 architecture with matrix-valued states and dynamic recurrence.
  - **Finch-C2**: The paper's own improved variant removing the gate, swapping GroupNorm for LayerNorm, multiplying key by (1 − decay), and replacing the bonus term with a second data-dependent value.
  - **GPTAlpha**: The paper's own improved standalone transformer with ddlerp token shifts, extra LayerNorms, and Finch channel mixer replacing the standard FFN.
  - **GoldFinch variants**: With 1:1 compression (no dimensionality reduction, only global cache sharing) and with 16:1 compression at different GOLD layer fractions (1/2, 1/3, 1/6 of total layers).

- **Generation budget / compute accounting.** Compute is measured in terms of **total training FLOPs** rather than inference budget (this is an architecture comparison paper, not an inference scaling paper). All models within a size class are trained on identical data (minipile) with identical hyperparameters: the 1.5B class models train on 4 GPUs with per-GPU per-step batch size 8, two steps of gradient accumulation, 10-step learning rate warmup followed by cosine decay from 3e-5 to 1e-5, Adam betas of 0.9 and 0.99, epsilon 1e-8, and weight decay 0.001 (Section 4.1). The smaller ablation models (L12 D768) train on single GPUs with per-step batch size 32, two gradient accumulation steps, warmup from 6e-5 to 2e-5, and otherwise identical hyperparameters (Section 4.2). FLOPs are not explicitly counted, but equal step counts and batch sizes make the comparison fair in terms of training compute. Weight decay is applied only to matrix parameters that are not part of LoRAs or the GoldFinch key compression/expansion steps, which gives GoldFinch a slight regularization advantage over standard weight decay.

- **Cross-validation / statistical protocol.** No cross-validation is reported. The paper trains a single run of each architecture at each scale and reports the final loss values (Table 2, Table 4) and benchmark scores (Table 3). Loss curves showing training dynamics are provided (Figure 2), which serve as a basic robustness check (ensuring no architecture collapses or diverges during training), but no error bars, standard deviations, or multiple seeds are reported. For the downstream benchmarks, the paper reports single-run zero-shot accuracy numbers without confidence intervals (Table 3). This is a limitation: we cannot assess whether the 0.1 difference in final loss or the 1–2 percentage point differences in benchmark accuracy are statistically significant or within the range of training noise.

### Main Quantitative Results

#### Architecture Comparison at 1.5B Scale

The headline result from Section 4.1 is that **GoldFinch achieves substantially lower final loss than both Llama and Finch** on minipile while using fewer parameters than Finch. Table 2 reports:

|---|---|---|
| Llama | 1.47B | 2.3905 |
| Finch | 1.60B | 2.3856 |
| GoldFinch (16:1 compression) | 1.45B | 2.2762 |
| GoldFinch (1:1 compression) | 1.45B | 2.2762 |

The gap between GoldFinch and Llama is 0.1143 in loss, which is substantial at this model scale. The gap between GoldFinch and Finch is 0.1094, also substantial. Critically, the 16:1 compressed version achieves **identical final loss** to the 1:1 uncompressed version (both 2.2762), directly demonstrating that the compression bottleneck imposes no measurable degradation on language modeling quality. GoldFinch achieves this while using 1.45B parameters — fewer than Finch (1.60B) and comparable to Llama (1.47B) — confirming the paper's claim of parameter efficiency from the Finch-C2 improvements (removed gate, shared $W_V$).

The training loss curves in Figure 2 show that GoldFinch (red and brown lines) separates from both Llama (blue) and Finch (orange) early in training and maintains a widening gap throughout. The curves do not show signs of convergence — GoldFinch is still improving relative to the baselines at the end of training — suggesting the advantage might grow further with additional training tokens.

**Key patterns across these ablations:**

The **$k \cdot (1-w)$ multiplication in Finch-C2** provides a measurable benefit: removing it increases loss from 2.7082 to 2.7293 (a 0.0211 degradation), which is the largest single-modification gap in the Finch-C2 ablation sequence.

The **second value** (replacing Finch's static $u$ bonus term) provides a smaller but positive contribution: removing it increases loss from 2.7082 to 2.7105 (0.0023 degradation). This is the "smallest positive impact of anything measured" per the paper's own assessment.

**Finch-C2 (2.7082) outperforms standard Finch (2.7191)** by 0.0109, confirming the aggregate of the four changes (gate removal, LayerNorm, $k \cdot (1-w)$, second value) is net positive despite the gate removal eliminating parameters.

**GPTAlpha with RoPE (2.6684) outperforms Llama (2.7125)** by 0.0441, a substantial margin confirming that the combination of data-dependent token shifts, extra LayerNorms, and Finch channel mixer genuinely improves transformer performance over the standard Llama recipe.

- Finch-C2 + last 1/3 GPTAlpha (no compression): 2.6586
- GoldFinch, last 1/3 GOLD: 2.6582
- GoldFinch, last 1/6 GOLD: 2.6578
- GoldFinch, last 1/2 GOLD: 2.6637

The difference between the best (1/6 GOLD at 2.6578) and the worst (1/2 GOLD at 2.6637) is only 0.0059 — these are nearly indistinguishable at this scale. The Finch-C2 + GPTAlpha hybrid (no compression, 2.6586) is only 0.0004 worse than GoldFinch with compression (2.6582), directly demonstrating that the compression pipeline and value cache elimination cost essentially nothing. The RoPE-on-GOLD variant (2.6590) is trivially worse than the no-RoPE variant (2.6582) by 0.0008 — within training noise, suggesting RoPE neither helps nor hurts for in-distribution context lengths, consistent with the paper's claim that Finch-C2 layers already provide implicit positional encoding within the trained context length.

**Note:** The paper states GoldFinch "performed very slightly better than even the Finch-C2/GPTAlpha hybrid with no KV compression at all," which is technically true (2.6582 vs. 2.6586) but the difference is negligible (0.0004) and should be interpreted as "equivalent performance" rather than "better performance" given the lack of multiple seeds or confidence intervals.

The 1/6 GOLD variant achieving the lowest loss (2.6578) is notable: it suggests that very few GOLD attention layers (2 out of 12 total layers for the L12 D768 model) are sufficient to capture the benefits of quadratic attention, and that the marginal benefit of additional GOLD layers beyond the first few is near zero or slightly negative at this scale. This is consistent with the H3 finding (Fu et al., 2023) that even two attention layers can outperform pure transformers.

#### Associative Recall

The paper tests models on multi-query associative recall (MQAR) using the protocol from Arora et al. (2023). Figure 3 shows that GoldFinch achieves **100% accuracy across all sequence lengths tested** (up to 256 tokens), while the standard Finch model degrades significantly as sequence length increases — consistent with the known weakness of purely recurrent architectures on precise retrieval tasks.

Figure 4 extends this to longer sequences (up to 1024 tokens, matching the training context length) and shows GoldFinch maintaining perfect accuracy while Finch's performance continues to decline. The paper explicitly states: "GoldFinch achieves perfect MQAR scores, outperforming traditional attention-free language models." This directly validates the architectural division of labor — the GOLD attention layers can perform exact retrieval from the compressed cache, solving the MQAR task that linear attention models fundamentally struggle with.

The comparison to Arora et al. (2023)'s findings is implicit but clear: the paper positions GoldFinch as resolving the "performance gap between different linear transformer architectures and the traditional transformer with attention" that Arora et al. identified for MQAR tasks. GoldFinch performs identically to a standard transformer on MQAR (perfect accuracy) while maintaining the efficiency advantages of the linear attention backbone.

#### Long Context Extrapolation

Section 4.4 reports experiments testing how models trained at 1024 context length perform when evaluated at extended lengths (up to 65,536 tokens) on the PG19 dataset.

**Key findings:**

- **Finch (purely recurrent) maintains fairly low loss** throughout the 65,536 context length despite being trained only at 1024. This is an expected property of recurrent architectures — they process tokens sequentially with a fixed-size state and do not have an explicit context length limit, though the state's memory capacity limits the quality of very long-range dependencies. The paper states: "The Finch model is able to maintain a fairly low loss throughout the 65536 context length."

- **GoldFinch without RoPE suffers substantially at extended lengths.** The paper reports: "The base GoldFinch model trained with no positional encoding goes up in loss significantly starting at around double the trained context length, then plateauing at a high loss." This is the direct consequence of the GOLD attention layers lacking explicit positional encoding — the attention mechanism's implicit position signals from the Finch-C2 cache break down when the positions are far outside the training distribution.

- **GoldFinch with RoPE performs better but still degrades.** "The GoldFinch model trained with RoPE on its GOLD attention sub-layers performs better, but loss still increases somewhat as the sequence progresses." RoPE provides explicit position information to the attention mechanism, which helps, but the model was trained at 1024 context length and the RoPE frequencies were optimized for that range. At 64× the training context length, the position encodings are outside their training distribution, causing degradation.

- **RoPE interpolation resolves the degradation.** "By applying interpolated RoPE values we are able to obtain low loss throughout the extended context length." This is the standard position interpolation technique: the RoPE frequencies are rescaled so that the extended position indices map back into the range seen during training. The paper reports this works successfully.

- **Fine-tuning only the GOLD layers at longer context lengths succeeds.** The paper fine-tuned the RoPE and non-RoPE models on 165 million tokens of minipile at longer context lengths, freezing the entire Finch-C2 portion and only updating the GOLD layers and output head. The RoPE model "exhibited significantly lower losses against PG19 up through those lengths and even beyond." The non-RoPE model "was somewhat successful within the fine-tuned context length, while still failing at extrapolation." This is an important practical result: adapting GoldFinch to new context lengths requires fine-tuning only the attention layers (a small fraction of total parameters), which is much cheaper than full model fine-tuning. The paper reports this uses "roughly 3x fewer FLOPS per token."

The finding that the non-RoPE model showed some improvement within the fine-tuned context length (despite no explicit positional encoding in the GOLD layers) is described as "unexpected" and the paper speculates "token-shift may supply some minimal positional information to the model." The same fine-tuning method did not generalize beyond the fine-tuned length for the non-RoPE model, consistent with token-shift providing only very local positional signals insufficient for true extrapolation.

### Ablation Studies and Robustness Checks

**Compression ratio (16:1 vs. 1:1):** The 1:1 compression variant (global cache without dimensionality reduction) achieves identical loss to the 16:1 variant at both model scales tested (Table 2 for L24 D2048: both 2.2762; implicitly tested but not separately reported for L12 D768 since the 1:1 variant is not listed in Table 4). This is the single most important ablation because it validates the paper's central claim that extreme compression is lossless. However, only these two compression ratios are tested — intermediate ratios (2:1, 4:1, 8:1) are not explored, so we don't know where the degradation threshold actually lies.

**GOLD layer fraction (1/2, 1/3, 1/6 of total layers):** Table 4 shows that all three fractions perform nearly identically: 2.6637 (1/2), 2.6582 (1/3), and 2.6578 (1/6). The 1/6 fraction achieves the numerically lowest loss, suggesting that 2 GOLD layers out of 12 total may be sufficient for the benefits of quadratic attention at this scale. The paper does not test 1/12 (single GOLD layer), 0 GOLD layers (pure Finch-C2, which achieves 2.7082 and is substantially worse), or fractions between 1/6 and 1/3. The finding that the fraction is insensitive over a 3× range (1/6 to 1/2) suggests robustness but also raises a question: if even 1/6 is sufficient, why use 1/3 for the main experiments? The paper doesn't explain the choice.

**RoPE on GOLD layers:** GoldFinch with RoPE (2.6590) vs. without RoPE (2.6582) at L12 D768 scale (Table 4) shows a trivial 0.0008 difference, well within likely training noise. This validates the claim that Finch-C2 provides sufficient implicit positional encoding for in-distribution context lengths. The paper acknowledges RoPE is needed for extrapolation (Section 4.4), so the practical tradeoff is: train without RoPE for in-distribution efficiency, with RoPE if extrapolation is expected.

**Finch-C2 vs. Finch (Table 4):** Finch-C2 (2.7082) outperforms standard Finch (2.7191), confirming the aggregate of the four modifications is positive. However, the ablations are not fully factorized — we see Finch-C2 with all four changes (2.7082), without $k \cdot (1-w)$ (2.7293), and without the second value (2.7105), but we don't see ablations removing the gate removal in isolation or swapping LayerNorm back to GroupNorm in isolation. The contribution of each change is partially confounded.

**GPTAlpha vs. Llama (Table 4):** GPTAlpha (2.6684) substantially outperforms Llama (2.7125), but the GPTAlpha-Llama comparison is confounded by three simultaneous changes: token shifts (ddlerp), extra LayerNorms, and the Finch channel mixer replacing the standard FFN. The paper does not ablate these separately, so we cannot attribute the gain to any specific component. A reader evaluating whether to adopt the full GPTAlpha package vs. selectively porting individual improvements would not know which changes matter most.

**Checkpoint upgrade training (Section 4.5, negative result):** Attempts to convert a pre-trained 1.6B Finch model to GoldFinch via fine-tuning rather than training from scratch were unsuccessful. Method 1 (appending 4 GOLD layers, training for 100M tokens): "unclear if the resultant model from this method really learned anything of value in its GOLD layers." Method 2 (replacing upper 1/3 with GOLD layers, training for 7.5B tokens): "obtained a similar validation loss on minipile to the base model" but "LAMBADA scores were worse." This is an important negative result: GoldFinch's performance benefits require training from scratch (or at least a more sophisticated upgrade procedure than was attempted). The paper frames this as ongoing work.

**Second value contribution (Table 4):** Removing the second value from Finch-C2 increases loss from 2.7082 to 2.7105, a difference of 0.0023. The paper describes this as "the smallest positive impact of anything measured," which accurately characterizes the result. The second value is a minor contributor — removing it does not fundamentally break the architecture, and a practitioner could consider omitting it for simplicity with minimal performance cost.

### Critical Assessment

**Claim 1: GoldFinch dramatically reduces KV-cache size (756–2550× smaller than traditional transformers).** This claim is **analytically supported** by the architecture specification in Table 1 and is a direct consequence of the design (global cache + 16:1 compression + key-only caching + token index storage), not an empirical result. The paper correctly computes the cache sizes: for the specific configuration of a 256k context, 32 layers, 4096 hidden dimension, GoldFinch requires 0.068 GB vs. 128 GB for Llama2 (a ~1882× reduction). However, the range "756–2550×" depends on model layer count because the traditional cache scales linearly with layers while GoldFinch's does not. The 756× figure would apply to a very shallow model (~10 layers), while 2550× applies to a very deep model (~100 layers). For the 24-layer models actually trained in this paper, the reduction is approximately 750× ((2 × 24 × 2048 × 2) / (258) ≈ 762 — per the calculation in Section 3.4's analysis). The claim is valid as an architectural property, but it is important to recognize that the paper only validates this cache scheme at 1.5B parameter scale with 2048–4096 context lengths during training — actual deployment of a million-token context with this architecture would require demonstrating that the compressed cache remains sufficient for attention quality at those extreme lengths, which the long-context experiments only partially address (up to 65k tokens, a 64× extrapolation from 1024 training context, not a million-token context).

**Claim 2: GoldFinch achieves greater-than-Llama performance (Section 1, Table 2, Table 3).** This claim is **supported at the specific scale tested** (1.5B parameters, minipile dataset) with the specific architectures compared. The loss gap of 0.1143 (Llama 2.3905 vs. GoldFinch 2.2762) is substantial. However, several qualifiers limit the strength of this claim:

- **The Llama baseline is not the strongest possible Llama configuration.** The paper uses Llama without Grouped-Query Attention to give it "the most favorable conditions" for modeling quality, which is reasonable for isolating architecture quality from efficiency tradeoffs. But GQA is standard in production Llama models, and a comparison against a Llama variant with GQA (which typically reduces performance slightly) is missing.
- **The Llama baseline uses the RWKV small init embeddings optimization**, which is not standard in the Llama recipe. While the paper frames this as favorable to Llama, it means the baseline is not a canonical Llama configuration — it's a modified Llama with a technique from the RWKV lineage. A reader evaluating whether GoldFinch beats "Llama" as commonly understood would need to know whether this modification helps or hurts.
- **All models use the RWKV World tokenizer**, not a Llama-standard tokenizer. Tokenizer choice can affect perplexity and downstream performance, and this choice may favor architectures from the RWKV family.
- **Only one training run per architecture is reported.** No error bars, confidence intervals, or multiple seeds. The loss differences in Table 4 are small enough (e.g., 2.6582 vs. 2.6586 vs. 2.6590) that we cannot distinguish true differences from training noise.
- **The downstream benchmark improvements** (Table 3) show a consistent but small advantage — roughly 1–1.2 percentage points average absolute accuracy. On individual benchmarks, GoldFinch loses to Llama on ARC-Challenge (18.3% vs. 19.3%) and essentially ties on WinoGrande and ARC-Easy. The aggregate advantage is real but modest, and the evaluation is zero-shot on a single model seed — we cannot assess statistical reliability.

**Claim 3: Pre-fill computation is O(1) per token (Section 1, benefit 6, Section 3 inference procedure).** This claim is **architecturally accurate but comes with a nuance the paper acknowledges.** The Finch-C2 layers process tokens in O(1) time per token (fixed-size matrix multiplications, no attention over the past). However, the paper correctly identifies that the final 2G−1 tokens of pre-fill must pass through the full model (including GOLD attention) to initialize token-shift hidden states. This is O((2G−1)²) = O(G²) attention cost, which is constant with respect to sequence length L but non-trivial — for G = 8 (a 24-layer model with 1/3 GOLD layers), that's 15 tokens of quadratic attention. For very long pre-fill contexts (hundreds of thousands of tokens), the cost of processing those 15 tokens through full attention is negligible relative to the linear-cost Finch-C2 processing of the rest. The O(1) per token claim is therefore **valid asymptotically** but with a small constant overhead that could matter for very short contexts. The paper does not provide wall-clock pre-fill measurements to validate the practical speedup, only the asymptotic analysis.

**Claim 4: GoldFinch achieves perfect MQAR recall (Section 4.3, Figures 3, 4).** This claim is **fully supported by the experimental evidence.** The figures show 100% accuracy for GoldFinch across all tested sequence lengths (up to 1024), while Finch degrades. This directly demonstrates the architectural division of labor works as intended. The limitation is scope: MQAR is a synthetic diagnostic task, and perfect performance on MQAR does not guarantee perfect retrieval of arbitrary information in natural language contexts. The paper does not test retrieval quality on naturalistic long-context tasks (e.g., needle-in-a-haystack, long-document QA), which would provide stronger evidence.

**Claim 5: The 16:1 compression ratio is lossless (Table 2).** This claim is **supported** by the identical loss values for 16:1 and 1:1 compression GoldFinch variants at L24 D2048 scale (both 2.2762). The near-identical loss for the Finch-C2+GPTAlpha hybrid without compression (2.6586) vs. GoldFinch with compression (2.6582) at L12 D768 scale provides additional evidence. However, the paper tests only minipile as the training corpus and only model sizes up to 1.5B parameters. Whether the 16:1 ratio remains lossless on more complex datasets (e.g., code, mathematics, multi-lingual text), at larger model scales, or at much longer context lengths is untested. The finding that compression is lossless is empirical, not theoretical — it depends on the information content of minipile being capturable in the reduced dimensionality. On more information-dense data, the optimal compression ratio might be different.

**Missing experiments that would strengthen the paper:**

1. **Wall-clock pre-fill and generation speed benchmarks.** The paper claims O(1) pre-fill and dramatically reduced memory, but provides no throughput or latency measurements. Table 1 gives theoretical memory numbers, but real-world performance depends on implementation details (kernel fusion, memory bandwidth utilization, chunked attention overhead). A comparison of tokens-per-second during pre-fill and tokens-per-second during generation for GoldFinch vs. Llama at various context lengths would substantially strengthen the practical efficiency claims.

2. **Scaling to larger model sizes.** All experiments are at 1.5B parameters or smaller. The paper hypothesizes that the benefits scale to larger models (Section 5 mentions hopes to "demonstrate GoldFinch's performance on larger models with significantly more tokens") but provides no evidence. Key questions: does the 16:1 compression remain lossless at 7B, 13B, 70B scales? Do the Finch-C2 improvements over standard Finch hold at larger scales? Do the GOLD attention layers with their reduced parameter count (no $W_K$, $W_V$) scale as well as standard attention layers?

3. **Needle-in-a-haystack or long-document QA evaluations.** The paper demonstrates MQAR (synthetic retrieval) and PG19 perplexity (language modeling), but does not test actual information retrieval from long natural language contexts. A needle-in-haystack test would directly validate whether the compressed cache preserves specific factual information that the GOLD layers can retrieve.

4. **Comparison to GQA and MLA baselines.** Table 1 compares cache sizes theoretically, but the paper does not train GQA or MLA variants of its Llama baseline to compare actual downstream performance at equal cache sizes. A fair comparison would be: GoldFinch at cache size X vs. Llama with GQA at the same cache size X, to determine whether GoldFinch wins on quality or just on cache compression.

5. **Ablation of individual Finch-C2 changes.** The paper ablates the $k \cdot (1-w)$ multiplication and the second value separately, but does not ablate the gate removal or the GroupNorm→LayerNorm change in isolation. The contributions of these changes to the overall improvement over standard Finch are unknown.

6. **Ablation of individual GPTAlpha changes.** GPTAlpha differs from Llama in three ways: token shifts, extra LayerNorms, and channel mixer. The paper does not ablate these independently, so we cannot determine which change(s) drive the 0.0441 loss improvement.

7. **Compression ratio sensitivity analysis.** Only two compression ratios (1:1 and 16:1) are tested. A sweep across ratios (2:1, 4:1, 8:1, 16:1, 32:1, 64:1) would identify the point at which compression starts to degrade performance, which is directly actionable for practitioners deciding how aggressively to compress.

8. **Long-context fine-tuning effectiveness on downstream tasks.** The Section 4.4 long-context experiments report only PG19 loss. The claim that fine-tuning only GOLD layers for longer contexts is effective would be stronger with a downstream retrieval or QA task showing that the fine-tuned model can actually use the extended context, not just achieve low language modeling loss.

**Conditional nature of the claims:** The paper's central claims hold most strongly under these conditions:

- **Training data:** minipile (1.5T tokens of English web text). Performance on code, mathematics, non-English languages, or multi-modal data is unknown.
- **Model scale:** ≤1.5B parameters. Extrapolation to >7B is plausible but unvalidated.
- **Context length:** trained at 1024–2048 tokens, tested up to 65k tokens with fine-tuning. Extreme long-context deployment (100k+ tokens) is supported by the architectural analysis but not empirically demonstrated.
- **No GQA for the Llama baseline.** Against production Llama with GQA, the performance gap would likely be smaller (GQA typically reduces performance), and the cache size advantage would also be smaller (GQA already provides ~8× reduction).

**The most robust finding** in the paper is that a hybrid recurrent-attention architecture with a compressed global cache can match or exceed the performance of both pure recurrent and pure transformer architectures at the 1.5B scale on minipile, while providing dramatic cache size reduction. The most important open question is whether this finding scales to the model sizes and datasets where KV-cache memory is actually a binding constraint in practice.

## 6. Limitations and Trade-offs

### Scale of Empirical Validation Is Insufficient to Guarantee Real-World Deployment Viability

**The assumption or constraint.** All architectural comparisons are conducted at the 1.5B parameter class or smaller (L12 D768 for ablations), trained on minipile (1.5T tokens of English web text), with trained context lengths of only 1024 or 2048 tokens. The paper acknowledges this explicitly in Section 5 (Further Work):

> "Most of the experiments done for this pre-print were performed over a short period of time on a single node containing 8 RTX 4090 cards. In the future we hope to demonstrate GoldFinch's performance on larger models with significantly more tokens."

**The consequence.** The headline claims — extreme cache compression with greater-than-Llama performance — are validated only in a regime where KV-cache memory is not actually a binding constraint. At 1.5B parameters and 2048 context length, a standard Llama KV-cache is approximately 196 MB (2 × 24 layers × 2048 dim × 2048 tokens × 2 bytes), which fits comfortably in the VRAM of the RTX 4090 GPUs used for the experiments (24 GB). The dramatic cache reduction (756–2550×) matters most at large model scales (70B+ parameters) and long context lengths (100k+ tokens) — precisely the regimes where GoldFinch has not been validated. It is unknown whether the 16:1 compression remains lossless at 7B, 13B, or 70B parameter scales, whether the Finch-C2 improvements over standard Finch persist, or whether the GOLD attention layers with eliminated key/value weight matrices scale competitively with standard attention at large model sizes. The paper also does not test on code, mathematics, or non-English text — domains where the information density may be higher and the optimal compression ratio may differ.

**What evidence exists in the paper.** Only two model scales are tested: L24 D2048 (1.45–1.60B parameters, Section 4.1) and L12 D768 (Section 4.2). The training corpus is exclusively minipile. Context lengths are 1024 or 2048 during training, with extrapolation experiments (Section 4.4) on PG19 up to 65,536 tokens — a 64× extrapolation, but only measuring language modeling loss, not retrieval or downstream task performance. No experiments on code, mathematics, multi-lingual, or multi-modal data.

**Mitigation status.** The paper explicitly flags this as "further work" (Section 5) and expresses intent to scale up, but no mitigation is provided in the current manuscript. The authors note that "GoldFinch will likely benefit from any future improvements to the RWKV and transformer architectures" (Section 5) and suggest that other linear attention backbones (e.g., Mamba) could substitute for Finch-C2, but none of this is validated.

---

### Difficulty Estimation Cost Is Unaccounted for in the Headline Efficiency Numbers

**The assumption or constraint.** The 16:1 compression ratio is validated as lossless by comparing GoldFinch with compression (16:1) against GoldFinch without compression (1:1), showing identical final loss (Table 2: both 2.2762). This comparison treats the compressed and uncompressed variants as architecturally equivalent except for the compression bottleneck. However, the 1:1 variant still uses the global cache sharing (no per-layer caches) and key-only caching — it only skips the 16× dimensionality reduction of the cache entries. The true baseline for measuring the cost of the GoldFinch compression pipeline would be an architecture with standard per-layer KV-caches (like the Llama baseline), or at minimum a YOCO-style global cache without dimensionality reduction. The paper does not report what fraction of the total cache reduction comes from each of the three mechanisms (global cache sharing, value cache elimination, 16:1 compression) versus what the performance cost of each mechanism is individually.

**The consequence.** A practitioner deciding whether to adopt GoldFinch cannot determine which of the three compression strategies is most essential. If most of the cache savings come from global cache sharing (which YOCO already demonstrated is lossless) and value cache elimination (which the paper does not ablate independently), then the 16:1 compression might be an unnecessarily aggressive choice that could fail at larger scales or on more complex data. Conversely, if the 16:1 compression is critical but begins to hurt at larger model sizes, the practitioner has no guidance on what compression ratio to use instead. The paper's finding that 1:1 compression achieves identical loss to 16:1 (Table 2) actually weakens the case for aggressive compression — it shows the bottleneck is sufficient but does not demonstrate it is necessary for the architecture to work. The value cache elimination (generating values from stored token indices rather than caching them) is a completely separate mechanism whose individual contribution is never measured.

**What evidence exists in the paper.** Table 2 shows 16:1 and 1:1 compression achieve identical loss (2.2762), but this comparison conflates the effect of compression with the effect of global cache sharing and value cache elimination, since the 1:1 variant still uses both. Table 4 compares Finch-C2+GPTAlpha hybrid (no compression pipeline at all, standard per-layer caches for the GPTAlpha attention layers) against GoldFinch with compression: the difference is 2.6586 vs. 2.6582 — trivially small at 0.0004. Neither table isolates the individual contributions of global cache sharing, value elimination, and dimensionality compression. No experiment measures the performance of a GoldFinch variant that stores a full uncompressed per-token cache but shares it globally, nor one that caches values but compresses keys, nor one that compresses only values but not keys.

**Mitigation status.** The paper does not acknowledge this as a limitation. The individual mechanisms are presented as a unified package (Section 1, benefits 1–3: global cache, value elimination, and 16:1 compression are listed as separate innovations) but their independent contributions are not measured. A reader interested in selectively adopting parts of the approach has no empirical basis for doing so.

---

### The Revision Model (Finch-C2) Cannot Be Warm-Started from Pre-Trained Finch Checkpoints

**The assumption or constraint.** The paper assumes that GoldFinch models are trained from scratch. Section 4.5 reports attempts to convert pre-trained Finch models into GoldFinch through fine-tuning ("checkpoint upgrade training"), and all attempts are described as unsuccessful. Method 1 (append 4 GOLD layers to a pre-trained 1.6B Finch model, train for 100M tokens): "unclear if the resultant model from this method really learned anything of value in its GOLD layers." Method 2 (replace the final 1/3 of Finch time-mix layers with GOLD attention layers, train for 7.5B tokens): "obtained a similar validation loss on minipile to the base model" but "the new model's LAMBADA scores were worse." The paper attributes this to "'brain surgery' required to keep the layer count the same, in which we effectively erased the Finch time-mix parameters in the upper 1/3rd of the model."

**The consequence.** This is a significant practical limitation: the vast majority of LLM development in production settings starts from pre-trained models rather than training from scratch. If GoldFinch cannot be obtained by fine-tuning an existing Finch (or RWKV) checkpoint, then organizations with substantial investment in pre-trained models cannot adopt the architecture without discarding that investment and training from scratch. The cost of training a 1.5B model from scratch on 1.5 trillion tokens is substantial (the paper used 4 GPUs, and while the total GPU-hours are not stated, it is a non-trivial expense). For larger models (7B, 14B, 70B), the cost of training from scratch would be prohibitive for many potential adopters. The paper's inability to successfully upgrade even a 1.6B Finch model after 2.5 trillion tokens of pre-training suggests the architectural modifications (removing the gate, adding GOLD layers, training the compression matrix W_KD, the Finch-C2 changes) are sufficiently deep that they cannot be retrofitted onto existing models through affordable fine-tuning budgets.

**What evidence exists in the paper.** Section 4.5 reports two upgrade methods, both unsuccessful. The first method (appending 4 GOLD layers to a 24-layer pre-trained Finch, 100M token fine-tuning) produced ambiguous results — "performance of this model was in line with the original model, it was unclear if the resultant model from this method really learned anything of value in its GOLD layers." The second method (replacing 1/3 of layers, 7.5B token fine-tuning) explicitly degraded performance: LAMBADA scores were worse. The paper is transparent about these failures and frames them as ongoing work: "We are still doing further experimentation on these upgrade methods to see just how well they can be made to perform."

**Mitigation status.** The paper does not claim to have solved the checkpoint upgrade problem and explicitly states these are ongoing experiments (Section 4.5, Section 5: "We anticipate updating this pre-print with further studies as results become available, including checkpoint upgrade results"). However, no specific path to a solution is proposed, and the fundamental challenge — that GoldFinch architectural changes are not merely additive but modify existing layer computations — remains unaddressed.

---

### No Wall-Clock Latency or Throughput Measurements Are Reported

**The assumption or constraint.** The paper claims O(1) per-token pre-fill complexity and dramatically reduced memory usage, but provides only theoretical asymptotic analysis and static memory calculations (Table 1). No wall-clock timing experiments are reported. The paper relies on a conceptual argument: Finch-C2 layers process tokens recurrently in fixed time regardless of sequence length, and the final 2G−1 tokens require full attention but this is a small constant overhead (Section 3, pre-fill procedure). Similarly, the paper claims that "extremely low VRAM usage can be achieved during inference by calculating attention incrementally across the sequence for each layer and decompressing as you go" (Section 3.4), but never demonstrates this in practice.

**The consequence.** Real-world inference performance depends on factors beyond asymptotic complexity: kernel launch overhead, memory bandwidth utilization, the cost of decompressing cache entries on-the-fly, the efficiency of chunked attention implementations, and the throughput impact of the decompression-recomputation tradeoff. The GOLD layers recompute keys and values from the compressed cache and embedding table at every generation step for all previous positions — this is O(N) per token per layer, the same asymptotic cost as standard attention, but the constant factors may differ substantially. If decompression (concatenating x^0_t with c_t, projecting with W_KU, applying token shift and LoRA adaptation) is more expensive than a simple cache lookup, the per-token generation cost could be *higher* than a standard transformer despite the memory savings. Conversely, the memory savings could enable larger batch sizes that increase throughput — but without measurements, the net practical effect is unknown. The paper also does not measure pre-fill throughput: the claim that pre-fill is O(1) per token is an asymptotic statement, but on actual hardware with actual sequence lengths, the constant factor of the Finch-C2 processing (which involves matrix multiplications, ddlerp computations, and wkvt state updates) relative to optimized FlashAttention implementations could mean pre-fill is not actually faster in practice for the sequence lengths where KV-cache memory is currently binding (tens to hundreds of thousands of tokens).

**What evidence exists in the paper.** Table 1 provides theoretical cache memory sizes for various architectures at a specific configuration (256k context, 32 layers, 4096 hidden dim). No wall-clock timing experiments appear anywhere in the paper. No throughput (tokens per second) measurements for pre-fill or generation. No latency measurements. No comparison of peak memory usage during actual inference runs. The long-context experiments (Section 4.4) measure only loss on PG19, not inference speed or memory consumption at those extended context lengths.

**Mitigation status.** The paper does not acknowledge the absence of timing measurements as a limitation. The claims about pre-fill efficiency and memory reduction are presented as architectural properties without empirical validation of their practical impact. A practitioner cannot determine from the paper whether GoldFinch is actually faster, slower, or comparable to a standard transformer at the sequence lengths where KV-cache memory is a real problem.

---

### Long-Context Extrapolation Requires RoPE and Interpolation Despite the Implicit Positional Encoding Claim

**The assumption or constraint.** The paper claims that "By using Finch-C2 blocks at the start of the model, the key cache automatically encodes the underlying implicit positional representation, thereby removing the need for positional encoding within our transformer layers for trained context lengths" (Section 1, benefit 5). This claim is supported by the finding that GoldFinch without RoPE achieves essentially identical training loss to GoldFinch with RoPE at in-distribution context lengths (Table 4: 2.6582 vs. 2.6590). However, the paper also acknowledges: "We do still require an additional positional encoding method for extrapolation to new context lengths unseen during training."

**The consequence.** The implicit positional encoding from Finch-C2 layers is insufficient for extrapolation beyond the trained context length. The long-context experiments (Section 4.4) demonstrate this clearly: "The base GoldFinch model trained with no positional encoding goes up in loss significantly starting at around double the trained context length, then plateauing at a high loss." Even the RoPE-trained model "performs better, but loss still increases somewhat as the sequence progresses" without interpolation. The practical consequence is that deploying GoldFinch at context lengths longer than those seen during training requires two additional measures: training the GOLD layers with RoPE (which slightly increases parameter count and compute) AND applying position interpolation at inference time (which requires selecting an interpolation factor, typically through hyperparameter search). This undercuts the elegance of the implicit-positional-encoding claim — in the regime where positional encoding matters most (long-context extrapolation), GoldFinch requires the same explicit encoding and interpolation techniques as standard transformers. The implicit encoding from Finch-C2 is sufficient only for in-distribution lengths, which is the easy case.

**What evidence exists in the paper.** Section 4.4 provides direct evidence: the non-RoPE GoldFinch model fails to extrapolate beyond 2× training context length, with loss "going up significantly." The RoPE model without interpolation also degrades. Only RoPE with interpolation achieves low loss throughout the extended context. The fine-tuning experiment (freezing Finch-C2 layers, training only GOLD layers at longer contexts) showed RoPE models improved at the fine-tuned lengths, but non-RoPE models only improved within the fine-tuned length and "still failing at extrapolation."

**Mitigation status.** The paper is transparent about this limitation (Section 1, benefit 5 explicitly states the extrapolation caveat; Section 4.4 demonstrates the issue empirically). The recommended mitigation — training with RoPE and using position interpolation — is standard practice for transformer long-context extrapolation and is shown to work. However, this means GoldFinch does not fundamentally solve the positional encoding extrapolation problem; it inherits the same solution (RoPE + interpolation) as standard transformers, with the same limitations (interpolation hyperparameter must be chosen, performance degrades with extreme extrapolation ratios). The paper does not explore whether the Finch-C2 implicit encoding could be made extrapolatable through architectural modifications, which would be a more fundamental solution.

### The Baseline Comparisons Overstate the Performance Advantage by Modifying the Baselines Favorably

**The assumption or constraint.** The paper makes several design choices in the baseline comparisons that favor GoldFinch, and the magnitude of these effects is not measured. Specifically:

1. The Llama baseline uses the "RWKV small init embeddings optimization (LayerNorm after embeddings with small initialized values)" (Section 4.1), which is a technique from the RWKV lineage, not standard in the Llama recipe. The paper frames this as "giving it the most favorable conditions," but a technique developed for recurrent architectures may not benefit (or may even harm) transformer architectures, and its impact is not ablated.

2. The Llama baseline does not use Grouped-Query Attention (GQA), which the paper justifies as "giving it the most favorable conditions" for modeling quality since GQA typically reduces performance. However, GQA is standard in production Llama models precisely because it provides a favorable quality-efficiency tradeoff, and excluding it means the baseline does not represent a practical Llama deployment.

3. All models use the RWKV World tokenizer, which was developed for RWKV models. Tokenizer choice can affect perplexity comparisons, and a tokenizer optimized for RWKV-family architectures may not fairly represent Llama performance. A Llama model with its native tokenizer (e.g., SentencePiece BPE) might achieve different loss values.

4. Weight decay is applied only to matrix parameters that are not part of LoRAs or the GoldFinch key compression/expansion steps (Section 4.1). This gives GoldFinch an implicit regularization advantage — some of its parameters (LoRA matrices, compression matrices) are exempt from weight decay, while all Llama parameters are subject to it. The impact of this differential regularization is not ablated.

**The consequence.** The reported performance gap between GoldFinch and Llama (0.1143 in loss, Table 2; ~1.2 percentage points average benchmark accuracy, Table 3) may partially reflect these favorable-to-GoldFinch experimental design choices rather than purely architectural superiority. The absence of standard Llama features (GQA, native tokenizer, uniform weight decay) means the comparison is not against a canonical Llama configuration that a practitioner would recognize or deploy. A practitioner evaluating GoldFinch would need to compare against their actual production Llama model, which likely uses GQA, a different tokenizer, and uniform weight decay — and the performance gap may be smaller than reported. The paper does not provide the necessary ablations to estimate the contribution of each design choice to the measured gap.

**What evidence exists in the paper.** Section 4.1 explicitly states these baseline modifications but does not ablate them. No comparison is provided against Llama with GQA, Llama without the RWKV small init embeddings optimization, Llama with its native tokenizer, or any variant with uniform weight decay. The justification for excluding GQA — "giving it the most favorable conditions" — addresses the direction of the bias (if anything, including GQA would make Llama look worse, not better) but does not address the practical relevance of the comparison: the claim that GoldFinch "significantly outperforms Llama" is made relative to a modified Llama that a practitioner would not actually deploy.

**Mitigation status.** The paper does not treat these baseline modifications as limitations. The framing presents the modifications as generosity toward the baselines — "in the interest of fairly comparing performance for Llama by giving it the most favorable conditions" (Section 4.1). However, the baseline modifications are not standard practice, and their individual effects are unmeasured. A more convincing comparison would include a canonical Llama configuration (with GQA, standard tokenizer, standard weight decay) alongside the modified version, allowing readers to assess how much the modifications matter.
