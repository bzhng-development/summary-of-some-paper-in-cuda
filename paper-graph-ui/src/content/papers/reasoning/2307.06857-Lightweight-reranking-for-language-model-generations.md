# Lightweight reranking for language model generations

**ArXiv:** [2307.06857](https://arxiv.org/abs/2307.06857)

## 🎯 Pitch

This paper proposes a lightweight reranking method for selecting the best generation from a set of language model outputs, relying on easy-to-compute pairwise statistics between generations rather than auxiliary models or additional inferences.

---

## 1. Executive Summary

This paper proposes a lightweight reranking method for selecting the best generation from a set of language model outputs, relying on easy-to-compute pairwise statistics between generations rather than auxiliary models or additional inferences. The core contribution is the **generalized self-consistency score (GSC)**, which formalizes reranking as selecting the generation with the highest average pairwise similarity to all other generations — operationalized concretely via a **Unigram Consistency Score (UCS)** that measures token overlap between generation pairs without requiring token probabilities. Evaluated on code generation tasks (HumanEval, MBPP, MBPP-S) using Codex and Llama models, UCS improves pass@1 accuracy substantially over random selection (e.g., from 0.435 to 0.539 on HumanEval with Codex002) and proves competitive with much heavier baselines like Coder-Reviewer Reranker, while its probability-weighted variants (WUCS, Consensus-WUCS) deliver consistent though smaller gains on autoformalization, summarization, and translation tasks — establishing that minimal-overhead, black-box reranking is highly effective for open-ended generation only when the similarity function captures semantically meaningful overlap, with the unigram signal proving far more discriminative for code than for natural language tasks.

## 2. Context and Motivation

### The Core Problem: Reranking Open-Ended Generations Is Either Expensive or Impossible

The practical problem driving this paper is straightforward but operationally critical: when a language model generates multiple candidate outputs for the same input, there is substantial variation in quality, and selecting the best one — rather than just taking the first sample — can yield significant performance improvements. The issue is that **doing this selection well has historically required either significant additional computation or task-specific infrastructure that is often unavailable**.

The paper identifies a specific gap in the reranking toolbox (Section 1). Most extant reranking methods fall into one of three categories, each with practical limitations:

- **Training an auxiliary reranker model**, which requires curating training data (often with human feedback or automated metrics like BLEU/ROUGE), training a separate model, and maintaining it alongside the generator. This is the approach taken by SummaReranker (Ravaut et al., 2022) and PairReranker (Jiang et al., 2022b), among others. The cost is not just computational — it involves a full model training pipeline.

- **Doubling inference cost via query likelihood methods**, such as the Coder-Reviewer Reranker (Zhang et al., 2022), which computes both the probability of the generation given the prompt and the probability of the prompt given the generation. Both directions require forward passes through the same or another LLM, effectively doubling the inference budget and adding latency overhead that is significant in production settings.

- **Execution-based methods for code**, which run generated code on unit tests and cluster programs by behavioral equivalence. This is used in MBR-Exec (Shi et al., 2022) and AlphaCode (Li et al., 2022), and it works well when unit tests exist. But the paper points out a crucial practical limitation (Section 1): "it becomes much less feasible as you move past the contest coding setting due to the complexity of setting up the build environment for arbitrary code as well as sandboxing it appropriately." In other words, for general-purpose code generation in the wild — where the user's prompt might require libraries with complex dependencies, system-specific configurations, or execution environments that cannot be safely or easily containerized — execution-based verification is often impractical.

What is needed, and what the paper sets out to provide, is a reranking method that works with **black-box access only** — just the raw text of the generations, no token probabilities, no execution, no auxiliary models — and adds **minimal compute overhead** to the generation process.

### Why This Matters: The Gap Between Self-Consistency and Open-Ended Tasks

The paper is motivated by a specific technical puzzle. Self-consistency (Wang et al., 2022) is remarkably effective for tasks with a small, fixed answer space: multiple-choice questions, math word problems where the answer is a single number or expression. The method works by sampling multiple chain-of-thought reasoning paths, extracting the final answer from each, and taking a majority vote over the answers. The underlying principle — "marginalize over multiple different reasoning paths and rank the answers based on their marginal probability rather than their probability conditioned on a single reasoning path" (Section 1) — is elegant and well-justified.

But open-ended generation tasks — code generation, summarization, translation, autoformalization — break this model in two fundamental ways that the paper explicitly identifies (Section 1):

**Observation 1: Near-equivalence without exact match.** "We can have semantically equivalent or near-equivalent generations that are nevertheless not exact matches." Two summaries might convey the same information in different words. Two programs might implement the same algorithm with different syntax (a list comprehension vs. a for-loop with an accumulator). Majority voting fails because it relies on exact string matching to identify agreement. You cannot simply count votes when every semantically equivalent pair produces a different string.

**Observation 2: Composite quality across multiple elements.** "For open-ended tasks, a generation can encompass multiple elements. For summarization, there might be multiple relevant facts in the text that a good summary should mention. For code, there might be multiple branch conditions that need to be present to generate a correct implementation." A generation set might contain fragments of the correct solution spread across different outputs: generation A handles edge case 1 correctly but misses edge case 2, generation B handles edge case 2 but misses edge case 1, and only generation C handles both. Simple majority voting over outputs cannot reconstruct C from A and B, because there is no semantically equivalent pair to create a majority. The optimal generation is a singleton with respect to any exact-match criterion.

These two observations mean that self-consistency — the dominant lightweight approach to improving generation quality — does not transfer to open-ended tasks. The problem is not that self-consistency is a bad idea; it is that its implementation (exact-match voting) is brittle and only works when the answer space is trivially discretized.

### Prior Approaches and Their Specific Failures

The paper positions itself against a landscape of heavier reranking methods, each of which it argues is unnecessarily expensive for what can often be accomplished with minimal computation.

**Auxiliary model training (Section 5.1).** SummaReranker uses a mixture-of-experts architecture trained to optimize multiple evaluation metrics simultaneously. PairReranker trains a discriminative classifier to select the better summary from a pair. Both approaches require curated training data and a separate model training, deployment, and maintenance pipeline. For a practitioner who simply wants to improve the output of an existing LLM, this is substantial infrastructure overhead. The cost is not just in FLOPs but in the engineering complexity of managing multiple models.

**Query-likelihood methods (Section 5.2).** The Coder-Reviewer Reranker computes a mutual information–style score: `log p(x|y) + log p(y|x)`, where `x` is the prompt and `y` is the generation. Computing `log p(x|y)` — the probability of the prompt given the generation — requires a separate forward pass through the model where the generation serves as context for predicting the prompt tokens. This effectively **doubles the inference cost** for every candidate generation being scored. Moreover, the method still requires full token probability access, which is not always exposed by API providers or available in black-box deployment scenarios.

**Execution-based methods for code (Section 5.2).** MBR-Exec and AlphaCode execute generated programs on provided unit tests and cluster them by behavioral equivalence — two programs are in the same cluster if they produce identical outputs on all test cases. The method then selects from the largest cluster. This is conceptually elegant but has an obvious dependency: you need executable unit tests. The Codex HumanEval and MBPP benchmarks provide these, which is why execution-based methods perform well on them. But as the paper notes, this assumption breaks in real-world settings where:
- The coding problem might involve I/O, network calls, or system interactions that cannot be safely sandboxed.
- The required runtime environment (libraries, language versions, OS dependencies) might not be available or safe to instantiate.
- The correctness criterion might be fuzzy — what does it mean for a generated bash script to "pass" a test? — rather than a discrete pass/fail on provided test cases.

CodeT (Chen et al., 2022) attempts to circumvent the need for human-written tests by using the LLM itself to generate candidate unit tests, but this adds yet another layer of inference cost and quality dependency (the generated tests must themselves be correct and comprehensive).

### How This Paper Positions Itself

The paper's framing is that **reranking should not require more than you already have**: the raw text of the generations. The key intellectual move is to show that pairwise agreement between generations — computed via a trivially simple unigram overlap metric — can approximate the ideal of "agreement on semantically meaningful predicates" without ever knowing what those predicates are.

The formalization in Section 2 is the paper's conceptual backbone. It recasts self-consistency in terms of latent predicates: imagine there exists a set of binary properties that a correct generation should satisfy (e.g., "the return type is a string," "all characters in the forbidden set are skipped"). If we could evaluate these predicates on each generation, we could select the generation that satisfies the most predicates. If we further assume the self-consistency property — that for each predicate, the majority value across generations is the correct value — then we can recover the optimal generation by selecting the one that agrees most with the majority on each predicate.

The critical insight is that this does not require evaluating predicates at all. Computing **pairwise agreement between generations** (on what fraction of predicates do they agree?) and selecting the generation with the highest average pairwise agreement with all others is equivalent to selecting the generation closest to the latent majority — under the assumption that agreement on predicates is reflected in surface-form similarity. The paper then operationalizes this with unigram overlap as a cheap, effective proxy for predicate agreement.

This positions the method in a specific niche in the cost-capability tradeoff space (which the results section validates empirically):
- **Much cheaper than** training auxiliary models, executing code, or running additional inference passes.
- **More effective than** random selection, mean log probability ranking, or naive majority voting for open-ended tasks.
- **Applicable to** any generation task, with code seeing the strongest gains because unigram overlap is more discriminative for code than for natural language (Section 4.3.1).

The theoretical results (Theorems 2.1–2.3) provide partial guarantees: if there is only one predicate, the method always recovers the optimum; if an optimal generation exists in the candidate set, it is always selected; and under a Bernoulli model for predicate values, the expected fraction of satisfied predicates has an upper bound that characterizes the method's statistical behavior. These are not tight guarantees — the paper acknowledges the bounds are loose — but they establish that the selection criterion is principled rather than ad hoc.

### The Simplicity Claim Is Both a Strength and a Bet

The paper's core bet is that **token-level surface overlap captures semantically meaningful agreement** well enough for reranking purposes. This is not an obvious claim. Two program implementations could be semantically equivalent but share very few tokens (e.g., a recursive solution vs. an iterative solution). Two summaries could convey the same facts with entirely different vocabulary. The paper provides evidence that this bet pays off for code (where unigram overlap is highly discriminative — Table 6 shows that the ratio of overlap between top and bottom generations is 1.95 for HumanEval vs. ~1.07–1.08 for translation tasks), and that it yields smaller but still consistent gains for natural language tasks.

The fact that the method sometimes outperforms methods requiring token probabilities (UCS beats mean-logp on HumanEval for Codex002: 0.539 vs. 0.539, and on MBPP for Llama-30B: 0.276 vs. 0.273) is surprising and suggests that raw overlap statistics capture something about generation quality that sequence-level probability does not — possibly diversity, or resistance to the degenerate-repetition problem that mean-logp ranking is known to suffer from (Holtzman et al., 2019; Section G in the Supplement shows mean-logp performance declining sharply as the number of samples increases, while UCS variants maintain accuracy).

## 3. Technical Approach

### 3.1 Reader Orientation

This paper presents a **lightweight post-hoc reranking system** that selects the highest-quality generation from a set of candidate outputs produced by any black-box language model. The problem it solves is: given `$M$` sampled generations for the same input prompt, how do you pick the best one without access to unit tests, token probabilities, auxiliary models, or any additional inference — using only the raw text strings that have already been generated? The solution shape is a **pairwise similarity matrix** computed over the generation set using cheap token-overlap statistics, followed by selecting the generation with the highest average similarity to all others — a procedure formalized as an extension of self-consistency from discrete answer spaces to open-ended text generation.

### 3.2 Big-Picture Architecture (Diagram in Words)

The system has four major components arranged in a simple pipeline:

1. **Generation Sampler** — the black-box LLM (e.g., Codex, Llama) that takes a prompt and produces `$M$` candidate output strings. This is the only point of interaction with the model; everything downstream operates on static text.

2. **Text Vectorizer** — a function that maps each generation string to a sparse binary (or weighted) vector representing the presence/absence of unigrams (individual tokens) in that generation. This is the core representational choice: no embeddings, no parsing, just token occurrence.

3. **Pairwise Similarity Computer** — computes an `$M \times M$` similarity matrix where entry `$(i, j)$` is the inner product (or weighted variant) between the vector representations of generations `$i$` and `$j$`. For `$K=1$` unigrams, this reduces to counting how many tokens two generations share, scaled by the vocabulary size.

4. **Generalized Self-Consistency (GSC) Scorer and Selector** — for each generation `$i$`, averages its similarity scores against all other `$M-1$` generations. The generation with the highest GSC score is selected as the top-ranked output. An extension (GSC-ranked) modifies this for selecting top-k diverse generations by penalizing similarity to already-selected candidates.

Information flows linearly: prompt → LLM generates `$M$` candidates → each candidate is vectorized → an `$M \times M$` similarity matrix is computed → GSC scores are derived → the argmax generation is returned. The entire post-generation pipeline involves only token counting and dot products, with no model calls.

### 3.4 Detailed Sentence-Based Technical Breakdown

This is primarily a **method paper with theoretical motivation** whose core idea is that selecting the generation that is on average most similar to all other generations approximates selecting the generation closest to the latent correct answer, under the assumption that surface token overlap correlates with agreement on unobserved semantic predicates.

#### The Predicate-Based Framework and the GSC Criterion

Before introducing any similarity function, the paper constructs a formal model of what an "ideal" reranker would do, then shows how to approximate it without access to the ideal information. This theoretical scaffolding is in Section 2 of the paper and is essential for understanding why the GSC criterion is not ad hoc — it emerges naturally from a set of assumptions about the relationship between generations and correctness.

**The predicate model of generation quality.** Imagine that for any given prompt, there exists a set of `$k$` latent predicates — boolean properties that a correct generation should satisfy. For a coding problem, these might be "the return type is a string," "all characters in the forbidden set are skipped," "the function handles empty input." For summarization, they might be "mentions fact A," "mentions fact B," "does not hallucinate." Each predicate captures an atomic semantic requirement.

Let `$v = [v_1, v_2, \ldots, v_k]$` be a vector of the *correct* values for these `$k$` predicates — the ground-truth specification of what properties an ideal generation should exhibit. For binary predicates, `$v_t \in \{0, 1\}$`; more generally, each predicate can take on `$m_t$` possible values. The paper does not assume binary values only, though the theorems are proved for the binary case.

Each generation `$i$` (out of `$n$` total sampled generations) can be evaluated against these predicates, producing a vector `$u_i = [u_i^1, u_i^2, \ldots, u_i^k]$` where `$u_i^t$` is the value of predicate `$t$` for generation `$i$`. If we had access to both the predicates and their values, the optimal selection rule would be trivial: pick the generation `$i$` whose `$u_i$` achieves the highest agreement with `$v$`, i.e., the one that satisfies the most predicates correctly.

**The self-consistency assumption (majority is correct per predicate).** The key bridge from this idealized setup to a practical method is the following assumption, borrowed and generalized from Wang et al. (2022):

> "for each individual predicate, the most frequent response is assumed to be correct"

Formally, if predicate `$t$` can take on values `$1, 2, \ldots, m_t$`, and without loss of generality the correct value is `$v_t = 1$`, then:

$$1 = \arg\max_j \sum_{i=1}^n \mathbb{1}(u_i^t = j)$$

where `$\mathbb{1}$` is the indicator function, `$u_i^t$` is the value of predicate `$t$` for generation `$i$`, and `$n$` is the number of generations.

**What this equation computes:** for each predicate independently, we count how many generations take on each possible value, and the value with the highest count (the plurality) is assumed to be the ground-truth correct value `$v_t$`. This is a per-predicate majority vote over the `$n$` generations.

**Why this form:** this is a natural generalization of self-consistency. For multiple-choice QA or math word problems, there is exactly one predicate ("what is the answer?") with a small discrete set of possible values, and self-consistency selects the majority answer. Here, the assumption is that the same property holds *for each semantic predicate individually* — the model is more likely to get each sub-property right than wrong, across the population of sampled generations. This is the core inductive bias that makes the framework work.

**From predicates to pairwise agreement.** The critical step — and the paper's key insight — is that **we do not need to know what the predicates are or evaluate them explicitly**. We only need to know how much pairs of generations agree *on the predicates*, and we can approximate that through surface-form similarity.

Define the pairwise fractional agreement between two generations `$i$` and `$j$` as:

$$a(u_i, u_j) = \frac{1}{k} \sum_{t=1}^{k} \mathbb{1}(u_i^t = u_j^t)$$

where `$k$` is the total number of predicates, `$u_i^t$` and `$u_j^t$` are the values of predicate `$t$` for generations `$i$` and `$j$` respectively, and `$\mathbb{1}$` is 1 if the two values match and 0 otherwise.

**What this computes:** the fraction of all `$k$` predicates on which generations `$i$` and `$j$` produce the same value. This is a number between 0 (complete disagreement on all predicates) and 1 (complete agreement on all predicates).

**Why this form:** if we can compute this for all pairs `$(i, j)$`, then the generation `$b$` with the highest average `$a(u_b, u_j)$` across all `$j \neq b$` is — under the self-consistency assumption — the one whose predicate values are closest to the latent majority values, and therefore closest to the ground-truth `$v$`. This transforms the problem from "identify and evaluate semantic predicates" to "estimate pairwise agreement on those predicates," which is a strictly easier task because it only requires a similarity signal between generations, not an absolute evaluation against ground truth.

**The GSC criterion.** This leads directly to the Generalized Self-Consistency score for generation `$i$`:

$$\text{GSC}_{\text{Sim}}(i) = \frac{1}{M-1} \sum_{j=1, j \neq i}^{M} \text{Sim}(i, j)$$

where `$M$` is the number of generations, `$\text{Sim}(i, j)$` is a pairwise similarity function between generations `$i$` and `$j$`, and the sum excludes the self-similarity term `$j = i$`.

**What it computes:** the average similarity of generation `$i$` to all other `$M-1$` generations in the candidate set. This is a scalar score per generation. The generation with the highest GSC score is selected as the output: `$\arg\max_i \text{GSC}_{\text{Sim}}(i)$`.

**Why this form:** this directly instantiates the predicate-agreement framework if `$\text{Sim}(i, j)$` approximates `$a(u_i, u_j)$`. Under the self-consistency assumption, the generation whose predicate values agree most with the majority per-predicate will also have the highest average agreement with all other generations, because the majority value is by definition the most common value, and a generation that matches the majority on many predicates will match many other generations on those predicates. The normalization by `$M-1$` makes the score comparable across sets of different sizes but is irrelevant for ranking within a fixed set.

**Connection to existing methods.** The paper explicitly shows how two prior reranking methods fit this same template (Section 3):

- **Self-consistency (exact match):** if `$\text{Sim}(i, j) = \mathbb{1}(\text{Answer}_i = \text{Answer}_j)$` — i.e., similarity is 1 only if generations `$i$` and `$j$` produce an exact string match on the extracted final answer — then GSC reduces exactly to majority voting. The average pairwise similarity for generation `$i$` is simply the fraction of other generations sharing its answer, and the generation with the highest score is the majority-vote answer.

- **MBR-Exec and AlphaCode (execution-based):** if `$\text{Sim}(i, j) = \mathbb{1}(\text{Program}_i \text{ and } \text{Program}_j \text{ agree on all unit tests})$`, then GSC selects the program from the largest behavioral equivalence cluster, which is exactly what both MBR-Exec and AlphaCode do.

This unification is not merely taxonomic. It shows that the GSC framework captures a broad class of reranking methods, with the similarity function being the *only* point of variation. The paper's contribution is a new similarity function (UCS) that is far cheaper to compute than execution-based or model-based alternatives while still capturing enough semantic agreement to be useful.

**Theoretical guarantees (Theorems 2.1–2.3).** The paper provides three theorems that characterize the behavior of the GSC criterion under the predicate model. All proofs are in the Supplement (Appendix A).

**Theorem 2.1 (single predicate is easy, multiple predicates are not guaranteed).** For `$k = 1$` (a single predicate), the GSC criterion always selects the generation whose predicate value matches the ground-truth `$v$`. For `$k > 1$`, there is no such guarantee.

The intuitive reason: with one predicate, the majority value *is* `$v$` by the self-consistency assumption, and the generation with the highest average agreement with others is simply the one that takes the majority value — which is correct. With multiple predicates, a generation could agree with the majority on many low-weight predicates but disagree on the one predicate that matters most, and the GSC score would not distinguish this from a generation that gets the important predicate right but differs on minor ones. The paper gives a concrete counterexample: if predicate 1 has `$p_1 = 0.34$` (only 34% of generations get it right), a generation `$g$` that gets it right might still lose to a generation `$g'$` that gets predicate 2 right (which 32% of generations get right) but misses predicate 1, because `$g'$`'s GSC score benefits more from aligning with the 32% that get predicate 2 right on that predicate.

**Theorem 2.2 (optimal generation is always selected if it exists).** If there exists a generation `$b$` such that `$u_b = v$` — i.e., a generation that perfectly satisfies all predicates with the correct values — then `$b = \arg\max_i \frac{1}{n-1} \sum_{j \neq i} a(u_i, u_j)$`.

The proof (Appendix A.2) is by induction on the number of predicates. The intuition: if `$u_b = v$`, then on every predicate, `$b$` takes the majority value (by the self-consistency assumption, the majority value *is* `$v_t$`). Therefore, for any other generation `$j$`, the agreement `$a(u_b, u_j)$` is at least as high as the agreement between any other pair of generations on each predicate individually. Summing across predicates, `$b$` has the highest total agreement. This is an encouraging guarantee: if the model *did* happen to produce a perfect generation, the method will find it.

**Theorem 2.3 (expected quality bound under Bernoulli model).** Assume that `$u_i^t \sim \text{Bernoulli}(p_t)$` iid across generations and predicates, where `$p_t$` is the probability that a generation gets predicate `$t$` right (takes the correct value, which by the self-consistency assumption is also the majority value). Let `$b$` be the generation selected by the GSC criterion. Then:

$$\mathbb{E}\left[\sum_{j=1}^k u_b^j\right] \leq \sum_{i=1}^k p_i + \sqrt{\frac{k \log n}{2}}$$

where `$u_b^j$` is the `$j$`-th predicate value for the selected generation `$b$`, `$p_i$` is the probability that a random generation gets predicate `$i$` right, `$k$` is the number of predicates, and `$n$` is the number of generations.

**What this computes:** an upper bound on the expected number of predicates that the GSC-selected generation `$b$` satisfies (the left-hand side is the expected sum of predicate values, which for binary `$\{0, 1\}$` predicates is the expected count of satisfied predicates). The right-hand side is the expected number of satisfied predicates for a random generation (`$\sum p_i$`) plus a penalty term that grows with `$\sqrt{k \log n}$`.

**Why this form:** the bound uses sub-Gaussian concentration (Wainwright, 2019, cited in the Supplement). The random variable `$q_i = \sum_{j=1}^k u_i^j$` (total number of predicates satisfied by generation `$i$`) is a sum of independent bounded random variables and is therefore sub-Gaussian with parameter `$\sqrt{k}/2$`. The maximum of `$n$` such sub-Gaussian random variables concentrates around the mean plus a term scaling as `$\sqrt{\log n}$`. The bound is not tight — the paper acknowledges this — but it shows that the penalty for selecting the maximum-agreement generation (rather than the true best generation) grows sublinearly in `$\sqrt{k}$` and only logarithmically in `$n$`, meaning the method does not catastrophically degrade as the number of generations or predicates increases. The bound is loose primarily because it uses a generic sub-Gaussian inequality that does not exploit the specific structure of the agreement-maximization problem; the simulation results in the Supplement show much better empirical performance than the bound suggests.

**Simulation validation.** Because the theoretical bounds are loose and only cover binary predicates, the paper conducts extensive simulations (Supplement, Appendix B) to validate the GSC criterion empirically. The setup:

- Fix the number of predicates `$d$`, the number of generations `$n$`, and the number of categories per predicate `$l$`.
- For each predicate, sample a categorical distribution uniformly at random (this determines how "easy" the predicate is — how concentrated the distribution is around the correct value).
- Sample `$n$` generation vectors `$u_i$` from these distributions.
- Apply the GSC criterion (select the generation with highest average fractional agreement with all others) and measure: (1) the fraction of times the best generation (the one with highest true agreement with `$v$`) is selected; (2) the ratio of the selected generation's agreement with `$v$` to the best possible agreement.

The results (Figures 4 and 5 in the Supplement, with `$d$` and `$l$` varied from 2 to 50, and `$n$` from 25 to 250) show:

- **Best-generation recovery is high for small `$l$`** (few categories per predicate). When `$l < 5$`, the best generation is recovered a very high fraction of the time even as `$d$` grows large. For larger `$l$`, recovery rate drops but remains substantially above random.
- **Recovery rate is stable with `$n$`**: going from 25 to 250 generations does not significantly degrade the recovery rate, which is consistent with the `$\sqrt{\log n}$` dependence in Theorem 2.3.
- **Average agreement with the best generation is very high**: even when the best generation is not selected, the selected generation achieves close to 100% of the best possible agreement for small `$l$`, and substantially better than random selection even for large `$l$`.

These simulations bridge the gap between the theoretical guarantees (which are weak) and the empirical results (which are strong), showing that the GSC criterion works well in practice under the predicate model even when the formal guarantees do not ensure optimality.

#### The Unigram Consistency Score (UCS) — Minimal Black-Box Similarity

The predicate framework requires pairwise fractional agreement `$a(u_i, u_j)$`, which depends on knowing predicate values. The paper's operational contribution is replacing this with a **surface-form similarity function** that can be computed from raw text alone. The simplest and most important variant is the Unigram Consistency Score (UCS), which uses `$K=1$` n-grams (individual tokens) as proxies for predicates.

**Vectorization: from text to binary token-presence vectors.** For each generation `$i$`, construct a vector `$v_i$` of length `$|V|$`, where `$V$` is the vocabulary — the set of all unique tokens that appear in *any* generation in the candidate set for the current prompt. The `$j$`-th element of this vector is:

$$v_i^j = \mathbb{1}(t_j \in g_i)$$

where `$t_j$` is the `$j$`-th token in the vocabulary `$V$`, `$g_i$` is the text of generation `$i$`, and `$\mathbb{1}$` is the indicator function returning 1 if token `$t_j$` appears anywhere in `$g_i$` and 0 otherwise.

**What this computes:** a binary bag-of-words representation. Each generation becomes a sparse vector (most tokens appear in only a few generations) where a 1 at position `$j$` means "this generation uses token `$t_j$` at least once." The vocabulary `$V$` is constructed dynamically per prompt from the union of all tokens in all `$M$` candidate generations, so the vector length adapts to the specific generation set.

**Why this form:** the binary presence/absence encoding treats every token as a potential predicate — "does this generation use token X?" If two generations agree on using a token, they are judged similar; if one uses a token and the other does not, they are judged dissimilar on that dimension. This is the minimal representation that captures lexical overlap without any modeling of token order, frequency, or semantics. The binary encoding (rather than term frequency) prevents a generation that repeats a common token many times from dominating the similarity score — what matters is *which* tokens appear, not *how often*.

**Similarity function: unnormalized dot product.** The UCS similarity between two generations `$i$` and `$j$` is:

$$\text{UCS}(i, j) = \frac{1}{|V|} v_i \cdot v_j = \frac{1}{|V|} \sum_{t=1}^{|V|} v_i^t \cdot v_j^t = \frac{1}{|V|} \sum_{t=1}^{|V|} \mathbb{1}(t_t \in g_i) \cdot \mathbb{1}(t_t \in g_j)$$

where `$|V|$` is the vocabulary size, `$v_i$` and `$v_j$` are the binary token-presence vectors for generations `$i$` and `$j$`, and `$\cdot$` is the dot product.

**What this computes:** the fraction of the total vocabulary that appears in *both* generations. If generations `$i$` and `$j$` share 50 tokens out of a vocabulary of 500, UCS = 0.1. This is a number between 0 (no token overlap) and `$|g_i \cap g_j| / |V|$` (bounded by the size of the smaller generation's unique token set relative to the total vocabulary).

**Why this form:** the dot product directly counts shared tokens — each token `$t$` that appears in both generations contributes `$1 \times 1 = 1$` to the sum. Dividing by `$|V|$` normalizes for vocabulary size, making scores comparable across prompts with different generation lengths and token diversity. This is deliberately *not* a cosine similarity or Jaccard index. The paper makes an explicit design choice to **not normalize by the vector norms** (Section 3, paragraph on unnormalized inner product, and Supplement I). The reasoning: neural generation models are prone to producing degenerate, repetitive sequences (Holtzman et al., 2019; Welleck et al., 2019). Normalizing by `$\|v_i\| \cdot \|v_j\|$` would remove the contribution of having more unique tokens — a longer, more diverse generation would receive the same normalized similarity score as a short, repetitive one if they share the same proportion of their token sets. By using the raw dot product (scaled only by `$|V|$`), longer generations with more unique tokens *automatically* get higher similarity scores with other diverse generations, because they have more opportunities for token overlap. This creates an implicit preference for diverse outputs, which aligns with the known issue that high-quality generations in open-ended tasks tend to be more lexically diverse than degenerate ones.

The ablation in Table 5 (Supplement) confirms this design choice: normalizing the inner product degrades performance. For Codex002 on HumanEval, WUCS-normalized achieves 0.462 vs. 0.558 for unnormalized WUCS. Ranking by the longest sequence alone (0.441) or by most diverse sequence alone (0.510) does not match UCS performance, showing that the similarity-based selection is doing more than just picking the longest or most diverse output.

**The GSC-UCS selection rule.** Plugging UCS into the GSC formula:

$$\text{GSC}_{\text{UCS}}(i) = \frac{1}{M-1} \sum_{j=1, j \neq i}^{M} \text{UCS}(i, j) = \frac{1}{M-1} \sum_{j \neq i} \frac{1}{|V|} v_i \cdot v_j$$

and the selected generation is `$\arg\max_i \text{GSC}_{\text{UCS}}(i)$`. This requires **zero model calls** beyond the initial generation step. The computational cost is `$O(M^2 \cdot |V|)$` for computing all pairwise dot products, but since `$|V|$` is the number of unique tokens across all generations (typically hundreds to low thousands) and `$M$` is typically 25–125, this is negligible compared to the cost of generating the candidates.

**Why this works for code especially well.** The paper provides a diagnostic in Section 4.3.1 (and Table 6 in the Supplement). They take the top-3 and bottom-3 generations (by quality) for coding and non-coding tasks, compute the unigram overlap within each set, and compute the ratio. For HumanEval (coding), the ratio of overlap in top generations to bottom generations is **1.95**. For translation tasks, it is ~1.07–1.08. For summarization (Xsum), it is ~1.21. This means that for code, correct generations share substantially more unigrams with each other than incorrect generations do — the token-level signal is highly discriminative. For natural language, the signal is weaker because correct and incorrect generations share more vocabulary, so unigram overlap is less informative about quality. This explains the empirical pattern: UCS gives strong gains on code (~10 percentage points improvement on HumanEval for Codex002: 0.435 → 0.539) and smaller but consistent gains on translation and summarization (~1–2 BLEU/ROUGE points).

**Design choice: vocabulary defined per prompt, not globally.** The vocabulary `$V$` is constructed from the `$M$` generations for the specific prompt being reranked, not from a global fixed vocabulary. This means:
- The vector dimension adapts naturally to generation length and diversity — a prompt yielding very long generations will have a larger vocabulary.
- Common tokens that appear in every generation (e.g., language keywords like "def", "return", "if") appear in the vocabulary but contribute the same amount to every pairwise similarity score, so they do not affect relative rankings — they effectively add a constant offset to all GSC scores.
- Rare tokens that appear in only one generation contribute zero to all pairwise similarities involving that generation, again acting as a constant shift. What matters for discrimination is the overlap pattern on tokens that appear in *some but not all* generations — these are the ones that create variance in the similarity matrix.

**N-gram generalization (NCS).** The paper defines a more general N-gram Consistency Score (NCS) where the vocabulary `$V$` contains all n-grams for `$n = 1$` to `$n = K$` (Section 3). For `$K=1$`, this is UCS; for `$K=4$`, the vocabulary includes unigrams, bigrams, trigrams, and 4-grams. The experimental sweep (Figure 7 in Supplement) shows that increasing `$K$` from 1 to 4 provides a slight accuracy improvement on MBPP, but gains flatten after `$K=4$`. The paper notes that 4-grams are also what is conventionally used in BLEU score computation, and speculates this is an interesting coincidence. For simplicity and minimal overhead, the paper primarily uses `$K=1$` (UCS) throughout the main experiments.

#### Weighted Variants (WUCS and Consensus-WUCS) — Incorporating Token Probabilities

When the LLM API or serving infrastructure provides per-token log probabilities (which is common but not universal — some APIs expose this, others do not), the paper introduces two extensions that weight the token overlap by the model's confidence in each token. The intuition (Section 3, paragraph on weighted variants) is: "if a generation has a low token probability for the generated token, then finding a match for that token should count for less." A token that the model was uncertain about is a weaker signal of agreement than a token the model generated with high confidence.

**Weighted Unigram Consistency Score (WUCS).** The binary presence/absence vector `$v_i$` is replaced with a real-valued vector where each token's contribution is weighted by its average generation probability:

$$v_i^j = \begin{cases} \frac{1}{c_i^j} \sum_{k=1}^{c_i^j} p(t_i^{j,k}) & \text{if } t_j \in g_i \\ 0 & \text{otherwise} \end{cases}$$

where `$c_i^j$` is the number of times token `$t_j$` appears in generation `$i$`, and `$p(t_i^{j,k})$` is the token-level probability that the model assigned to the `$k$`-th occurrence of token `$t_j$` in generation `$i$` (the probability under the model's output distribution at the position where that token was generated).

**What this computes:** for each token `$t_j$` that appears in generation `$i$`, we compute the average probability the model assigned to that token across all its occurrences in the generation. If a token appears 3 times with probabilities 0.9, 0.8, and 0.7, its entry is `$(0.9 + 0.8 + 0.7) / 3 = 0.8$`. Tokens not in the generation contribute 0. This produces a vector where each entry is in `$[0, 1]$`, with higher values for tokens the model was more confident about.

**Why this form:** the averaging across occurrences `$\frac{1}{c_i^j}$` prevents a frequently repeated token from dominating — a token that appears 10 times with probability 0.9 contributes 0.9, the same as a token that appears once with probability 0.9. The paper does not explore alternative aggregations (max, min, sum), but averaging is the natural choice for a "typical confidence" measure. The WUCS similarity is then the same unnormalized dot product as UCS, but with these real-valued vectors:

$$\text{WUCS}(i, j) = \frac{1}{|V|} v_i \cdot v_j$$

**Consensus-WUCS.** This variant combines WUCS with the mean log probability of the generation — a standard reranking baseline — by multiplying them:

$$\text{Consensus-WUCS}(i) = \text{WUCS} \cdot \exp\left(\frac{1}{|g_i|} \cdot p(g_i)\right)$$

where `$|g_i|$` is the number of tokens in generation `$i$`, and `$p(g_i)$` is the log-probability of the generation (the sum of log-probabilities of all tokens in the sequence, under the model). Equivalently, the exponentiated term is the per-token geometric mean probability — `$\exp(\frac{1}{|g_i|} \sum \log p(\text{token}))$` — which is the standard "mean log probability" metric normalized by length.

**What this computes:** the GSC-WUCS score for a generation is multiplied by a factor that is high when the model assigns high average probability to the generation's tokens (confident generation) and low when the model was uncertain. This is a product of two signals: (1) the consensus signal from WUCS (how much does this generation agree with others, weighted by token confidence) and (2) the intrinsic quality signal from mean log probability (how confident was the model in this generation overall).

**Why this form:** multiplication (rather than a weighted sum) means that both signals must be high for the final score to be high — a generation with high consensus but low model confidence is penalized, and vice versa. This combines two complementary sources of information: consensus captures agreement with other samples (which is about *correctness* relative to the generation set), while mean log probability captures the model's own assessment of quality (which is about *fluency and typicality*). The exponentiation ensures the mean-log-prob factor is positive and can be interpreted as a multiplicative weight.

**Empirical behavior.** The results tables (Table 1 in the main paper, Table 2 in Supplement for mean reciprocal rank) show:
- WUCS consistently outperforms mean-log-probability ranking alone. On HumanEval Codex002, WUCS achieves 0.558 vs. 0.539 for mean-logp. This is notable because both methods use the same token probability information, but WUCS uses it to weight a consensus signal rather than to directly score individual generations.
- Consensus-WUCS almost always outperforms WUCS, adding 1–2 percentage points across most model-dataset combinations (e.g., HumanEval Codex002: 0.568 vs. 0.558). The multiplicative combination with mean log probability provides a small but consistent boost.
- UCS (no token probabilities) often outperforms mean-logp ranking despite having strictly less information (HumanEval Codex002: 0.539 vs. 0.539; MBPP Llama-30B: 0.276 vs. 0.273), which the paper attributes to mean-logp's known tendency to favor degenerate, repetitive sequences (Holtzman et al., 2019) — a problem that UCS avoids by selecting for similarity to a diverse set of peers rather than for high individual probability.

**Weighting for n-gram variants.** When `$K > 1$` (using bigrams, trigrams, etc.), the paper modifies the weighting to account for the fact that longer n-grams appear fewer times in a generation. Specifically, for an n-gram of length `$n$` tokens appearing `$k$` times in generation `$i$` of length `$|g_i|$` tokens, the weight is multiplied by `$\frac{|g_i|}{|g_i| - |t_i^{j,k}| + 1}$` where `$|t_i^{j,k}|$` is the length of the n-gram in tokens. This corrects for the reduced frequency of longer n-grams — a 4-gram that appears once in a 100-token generation gets a higher weight than a unigram that appears once, because the 4-gram's presence is more informative (there are ~97 possible 4-gram positions vs. 100 possible unigram positions).

#### GSC-Ranked: Extending to Top-k Selection

Standard pass@k evaluation for code generation asks: if you select `$k$` generations from the candidate set, does at least one of them pass all unit tests? The GSC criterion naturally selects the single best generation, but for `$k > 1$`, simply taking the top `$k$` by GSC score would select generations that are all very similar to each other (all near the consensus), which is suboptimal for diversity — if the first generation is wrong, the second (being nearly identical) is likely wrong for the same reason.

**The ranked selection criterion.** The paper proposes GSC-ranked (Section 3.1), which iteratively selects generations while penalizing similarity to already-selected candidates. Let `$S_{k'}$` be the set of `$k'$` generations already selected (with `$k' < k$`). The score for selecting the `$(k'+1)$`-th generation `$i$` (where `$i \notin S_{k'}$`) is:

$$\text{GSC}_{\text{Sim}}^{\text{ranked}}(i) = \frac{1}{n-1} \left( \sum_{j \notin S_{k'}} \text{Sim}(i, j) - \sum_{j \in S_{k'}} \text{Sim}(i, j) \right)$$

where `$n$` is the total number of generations, `$S_{k'}$` is the set of already-selected generations, the first sum is over all generations not yet selected, and the second sum is over the already-selected generations.

**What this computes:** for a candidate generation `$i$`, we compute its average similarity to all *unselected* generations (rewarding consensus with the remaining pool) and subtract its average similarity to *already-selected* generations (penalizing redundancy with what has already been chosen). The generation with the highest GSC-ranked score is added to `$S_{k'+1}$`, and the process repeats until `$k$` generations are selected.

**Why this form:** this is an explicit diversity mechanism. If generation `$i$` is very similar to already-selected generation `$j \in S_{k'}$`, the penalty term `$\text{Sim}(i, j)$` reduces its score. This encourages selecting generations that represent different "clusters" in the similarity space — different high-level approaches to the problem. For `$k=1$`, the second sum is empty, so GSC-ranked reduces to standard GSC.

**Empirical results for GSC-ranked (Figure 3 in Supplement).** The paper compares GSC (top-k by raw GSC score) vs. GSC-ranked for pass@k with `$k$` from 1 to 10 on HumanEval, MBPP, and MBPP-S. The results show:
- Raw GSC performance for top-k declines as `$k$` increases — taking the top-k by raw GSC score adds little beyond the first selection because later selections are nearly identical to the first.
- GSC-ranked maintains substantially better performance at higher `$k$`, with the gap widening as `$k$` grows.
- The improvement is consistent across all three code generation benchmarks.

This is a practically significant extension because many code generation deployments use pass@k (e.g., showing the user the top-3 generated programs and letting them choose or test). The GSC-ranked method provides a principled way to produce a diverse top-k list from a single similarity-based framework, without requiring separate diversity-promoting mechanisms.

#### Key Configurations and Hyperparameters

The paper sweeps or fixes several practical settings that affect performance:

**Number of generations `$M$`.** The paper samples 125 generations per prompt for code generation tasks and 50 for MiniF2F and Xsum (Section 4). The reranking is then performed on subsets of size 25 via bootstrap sampling (50 bootstrap iterations, sampling 25 generations without replacement from the 125), following Shi et al. (2022) and Zhang et al. (2022). This bootstrap procedure provides error bars and ensures the results are not sensitive to the particular generation set. The sensitivity analysis in Figure 8 (Supplement) varies the number of generations from 5 to 100 and shows that UCS variants maintain stable accuracy while mean-logp ranking degrades sharply as the number of samples increases (because mean-logp increasingly selects degenerate sequences when given more candidates).

**Maximum n-gram length `$K$`.** The default is `$K=1$` (unigrams only) for all main experiments. Figure 7 (Supplement) sweeps `$K$` from 1 to 10 and shows slight improvement up to `$K=4$` with flattening thereafter. The computational cost of higher `$K$` grows because the vocabulary size `$|V|$` expands to include all n-grams up to length `$K$`, but the similarity computation remains `$O(M^2 \cdot |V|)$`.

**Inner product normalization.** Not normalized — as discussed in the UCS section and ablated in Table 5 (Supplement), normalizing the dot product by vector norms consistently degrades performance, confirming that the unnormalized form's implicit preference for diverse sequences is beneficial.

**Vocabulary construction.** Vocabulary `$V$` is the set of all unique tokens (or n-grams) appearing in any of the `$M$` generations for the current prompt. No global fixed vocabulary, no token filtering, no stop word removal. This is the simplest possible approach and avoids introducing additional design choices or data dependencies.

**Token probability weighting (WUCS).** Token probabilities are averaged across multiple occurrences of the same token within a generation. No alternative aggregation (max, sum, min) is explored. The weighting is applied at the vector construction stage (before pairwise similarity computation), not as a post-hoc adjustment.

**Consensus-WUCS combination.** WUCS score is multiplied by `$\exp(\text{mean\_log\_prob})$`. No weighting coefficient or mixing parameter is tuned — this is a fixed multiplicative combination.

**Bootstrap evaluation protocol.** 50 bootstrap iterations, sampling 25 generations without replacement from 125 (or 50 for non-code tasks). All reported numbers are averages over these 50 bootstrap samples. This protocol matches prior work and provides statistical robustness — the variance across bootstrap samples captures the sensitivity to which particular generations happen to be in the candidate set.

**Temperature sweep.** Figure 6 (Supplement) evaluates UCS variants on MBPP with decoding temperatures from 0.2 to 1.0. Consensus-WUCS dominates at lower temperatures (0.2–0.6), which is also where absolute performance is highest. At temperature 1.0, all methods converge to similar performance as generation quality degrades. This suggests the method is robust to the typical operating range of generation temperatures but relies on the model producing relatively high-quality candidates (at very high temperatures where outputs are essentially random, no reranking method helps).

#### Summary of Design Choices and Their Justifications

- **Binary token-presence vectors over TF-IDF or embeddings**: minimal computation, no external data dependencies, no separate model. The binary encoding prevents token frequency from dominating (a token repeated 50 times counts the same as a token used once). TF-IDF would require corpus statistics; embeddings would require an embedding model and inference cost.

- **Unnormalized dot product over cosine/Jaccard**: creates implicit preference for longer, more diverse generations, which counters the known degenerate-repetition problem in neural text generation. The ablation confirms this choice.

- **Per-prompt vocabulary over global vocabulary**: adapts naturally to generation length and content. Global vocabulary would require prior knowledge of the token distribution and would be either too large (wasteful) or too small (missing rare but discriminative tokens).

- **Average probability weighting over max or sum**: prevents a single high-confidence token from dominating while still upweighting tokens the model is consistently confident about. The design choice is not empirically ablated against alternatives, but it is the natural aggregation for a "typical confidence" signal.

- **Multiplicative combination of WUCS and mean-logp**: ensures both signals (consensus + model confidence) must be high, rather than allowing one to compensate for the other. No mixing weight is tuned, keeping the method parameter-free.

- **GSC-ranked penalty for pass@k**: uses the same similarity matrix already computed for GSC, adding no computational overhead beyond a modified scoring step. The penalty-subtraction form naturally produces diversity by downweighting candidates similar to already-selected ones.

## 4. Key Insights and Innovations

### Innovation 1: Self-Consistency Generalizes Through Latent Predicates, Not Answer Extraction

The paper's most fundamental conceptual move is redefining what self-consistency *operates over*. Prior work (Wang et al., 2022) applied self-consistency by extracting a discrete final answer from each chain-of-thought generation and voting over those answers — a procedure that works only when the answer space is small and answers can be identified via exact string matching. This assumes that the unit of agreement is the *entire output*, treated as an atomic label.

This paper replaces that assumption with a strictly more general one: that the unit of agreement is a set of *latent semantic predicates* — atomic properties that a correct generation should satisfy — and that these predicates are never directly observed. The key insight is that **you do not need to extract answers to do self-consistency; you need to estimate, for each generation, how well it agrees with the latent majority on whatever the relevant predicates happen to be.** This transforms self-consistency from a voting procedure over extracted answers into a pairwise-agreement maximization problem over raw generation text, with the similarity function serving as the bridge between surface form and latent predicate agreement.

This is not an incremental extension of self-consistency — it is a **fundamental reframing of what the method is doing**. The original self-consistency paper motivated majority voting as marginalizing over reasoning paths to the same answer. This paper shows that the same mathematical structure (maximizing average agreement with peers) applies to any generation task, provided you can define a similarity function that correlates with predicate-level agreement. The theoretical framework in Section 2 — the predicate model, the self-consistency assumption applied per-predicate, the reduction to pairwise fractional agreement — gives this reframing formal grounding. Theorems 2.1–2.3 then characterize when and how well the agreement-maximization criterion recovers the optimal generation, establishing boundary conditions (single predicate: always optimal; multiple predicates: not guaranteed but bounded in expectation) that were absent from prior self-consistency work.

The significance extends beyond the particular similarity functions tested in this paper. The GSC framework provides a **unified lens** for understanding reranking methods: self-consistency (exact answer match), MBR-Exec (test-case agreement), and AlphaCode (behavioral clustering) all emerge as instances of the same template with different similarity functions (Section 3). This unification is diagnostic — it tells you that *any* future reranking method for open-ended tasks should be evaluated by whether its similarity function captures agreement on the predicates that matter for the task. The paper's empirical contribution is showing that even a trivial unigram-overlap similarity function captures enough predicate agreement to be useful, but the conceptual contribution is the framework itself, which is independent of any specific similarity function.

The simulation results (Supplement B, Figures 4–5) strengthen this conceptual claim by validating the predicate model in isolation — when predicate values are known, the GSC criterion reliably recovers near-optimal generations across a wide range of conditions (varying numbers of predicates, categories per predicate, and generations). This decouples the validity of the agreement-maximization principle from the quality of any particular similarity function, showing that the framework is sound even if better similarity functions remain to be developed.

### Innovation 2: Lexical Overlap as a Surprisingly Effective Proxy for Semantic Agreement — For Code

The paper makes a counterintuitive empirical discovery: **unigram overlap between code generations — a representation that discards syntax, structure, dataflow, and semantics — is strongly discriminative for correctness.** This is not an obvious result. Two correct programs that implement the same algorithm in different styles (list comprehension vs. imperative loop, recursion vs. iteration) can share very few tokens. Two incorrect programs might share many tokens (both use the same wrong approach with slight variations). The prior expectation, grounded in natural language processing work on semantic textual similarity, would be that surface-level token overlap is a weak signal for semantic equivalence.

The diagnostic in Table 6 (Supplement) is the paper's key empirical insight on this point. The unigram overlap ratio between top-quality and bottom-quality generations is 1.95 for HumanEval and only ~1.07–1.08 for translation tasks, with summarization at ~1.21. This means that **for code, correct generations cluster in token space while incorrect ones scatter**, but for natural language, both correct and incorrect generations share similar amounts of vocabulary. The paper does not fully explain *why* this is the case — it is an empirical observation, not a derived property — but the implication is significant: the nature of code as a formal language with constrained vocabulary (keywords, standard library function names, variable naming conventions) means that correctness leaves a stronger lexical signature than it does in natural language, where paraphrastic variation is larger and correctness is more about factual accuracy than lexical choice.

This finding has direct practical implications for when and why lightweight reranking works. It explains the otherwise puzzling pattern in the results: UCS gives 10+ percentage point improvements on code generation (HumanEval Codex002: 0.435 → 0.539) but only 1–2 point improvements on translation and summarization. The method is not universally strong — it is **task-specifically strong in proportion to how much correctness information is carried by token overlap**. This is a more nuanced and useful claim than "our method improves performance," because it tells practitioners *when* to expect the method to help (code, structured generation tasks with constrained vocabulary) and when not to (open-ended natural language where paraphrase is common).

The paper also provides evidence that this lexical-overlap signal is more robust than sequence-level probability. Figure 8 (Supplement) shows that as the number of candidate generations increases from 5 to 100, mean-log-probability ranking degrades sharply — likely because it increasingly selects degenerate, repetitive sequences (a known failure mode documented in Holtzman et al., 2019) — while UCS variants maintain or improve their accuracy. This suggests that **consensus-based selection acts as an implicit regularizer against the degeneracy problem**, because a repetitive generation will share tokens with itself but not with diverse, high-quality peers. This is an insight about the interaction between reranking and the known pathologies of neural text generation: reranking by similarity to a diverse peer set provides a "wisdom of the crowd" effect that individual sequence probabilities cannot capture.

### Innovation 3: Reranking Cost Can Be Decoupled From Model Inference Cost Without Sacrificing Quality

The paper demonstrates that **a reranking method requiring zero additional model calls, zero training, and zero execution can match or exceed methods that double inference cost or require separate trained models.** This is not a marginal efficiency gain — it is a qualitative change in the deployment profile of reranking systems.

Consider the comparison with Coder-Reviewer Reranker (Zhang et al., 2022) in Table 3 (Supplement). The Normalized Reviewer (NR) variant requires computing log p(x|y) — the probability of the prompt given the generation — which means a second forward pass through the LLM for every candidate generation. For M = 25 generations, this is 25 additional inference calls, effectively doubling the total inference budget. The Normalized Coder-Reviewer (NCR) variant combines this with the standard log p(y|x), still requiring the extra forward pass. Despite this cost, Consensus-WUCS **outperforms NR in 13/15 model-dataset combinations** and is competitive with NCR (outperforming it in 6/15 combinations, ranking second in 8/15). UCS, which requires no token probabilities at all, outperforms NR in several settings as well.

This is significant because it challenges the implicit assumption in the reranking literature that better reranking requires more computation or more model access. The coder-reviewer approach is conceptually sophisticated — it frames reranking as a mutual information problem — but its practical gains over simple unigram overlap are marginal and inconsistent, while its cost is substantially higher. The paper does not frame this as "UCS is better than coder-reviewer" but rather as evidence that **the dominant source of reranking signal for code generation is captured by cheap lexical statistics**, and that investing additional computation (via auxiliary models, query likelihood, or execution) yields diminishing returns relative to simply generating more candidates and computing their unigram overlap.

The practical implication is a reframing of the cost-quality tradeoff for reranking. Rather than the prevailing model of "spend inference compute on a sophisticated reranker," the results suggest "spend inference compute on generating more diverse candidates, then use a nearly-free consensus method to select among them." This is especially relevant for API-based deployments where inference calls are metered and costly — UCS requires no API calls beyond the initial generation, making it effectively free to operate once the candidates exist.

The robustness to generation count (Figure 8, Supplement) reinforces this point. As the number of generations increases from 5 to 100, the cost of UCS grows quadratically in the number of generations (M² pairwise comparisons) but this is negligible compared to the linear cost of generating those generations (each of which requires a full forward pass through a large model). The reranking cost remains dominated by generation cost even at large M, meaning the method scales gracefully with the number of candidates.

### Innovation 4: Diversity-Promoting Reranking Through Similarity Penalization

The GSC-ranked extension (Section 3.1) introduces a simple but conceptually important modification: for pass@k with k > 1, penalizing similarity to already-selected generations when choosing the next one. This transforms the reranker from a pure quality-maximizer (pick the k generations closest to the consensus) into a quality-diversity optimizer (pick k generations that are each close to the consensus *of the remaining pool* but far from each other).

The conceptual move is recognizing that **the similarity matrix already computed for GSC contains all the information needed for diversity-promoting selection**. There is no need for a separate clustering step, no need to define distance thresholds, and no need for a distinct diversity objective. The penalty term `- Σ_{j∈S_k'} Sim(i, j)` directly encodes an anti-redundancy preference using the same similarity function that captures quality. This is an elegant unification: the same signal that tells you *which* generations are good also tells you *how to avoid picking redundant good generations*.

The empirical results (Figure 3, Supplement) show this matters substantially. Raw GSC for pass@k sees quickly diminishing returns as k increases — because the top k generations by raw GSC score are all near the consensus and therefore nearly identical. GSC-ranked maintains meaningfully higher pass@k accuracy at larger k, with the gap widening from k=2 to k=10. This is not a small tweak; it is the difference between a pass@k reranker that effectively provides only one genuinely distinct candidate and one that provides k meaningfully different candidates.

This innovation has implications beyond the paper's specific method. It demonstrates that **pairwise similarity matrices — which are cheap to compute once — can serve double duty for quality estimation and diversity optimization**, eliminating the need for separate diversity-promoting mechanisms (such as the Maximal Marginal Relevance approach or clustering-based selection used in prior work). The penalty term is parameter-free (no weight to tune) and adds negligible computation to the already-computed similarity matrix.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The paper evaluates on six datasets spanning four task types: (1) **HumanEval** (Chen et al., 2021) — 164 hand-written Python programming problems with unit tests; (2) **MBPP** (Austin et al., 2021) — approximately 974 entry-level Python programming problems; (3) **MBPP-sanitized** (MBPP-S) — a cleaned version of MBPP with 427 problems; (4) **MiniF2F** (Jiang et al., 2022a) — a dataset for autoformalizing mathematical statements from natural language to Isabelle, using the split provided by Jiang et al.; (5) **Xsum** (Narayan et al., 2018) — an extreme summarization dataset of BBC news articles with single-sentence summaries; (6) **WMT14** French-to-English and German-to-English (Bojar et al., 2014) — machine translation benchmark. The paper samples 125 generations per prompt for code generation datasets and 50 generations for MiniF2F and Xsum.

- **Base model(s).** Experiments use the **Codex** family (Codex-davinci-001, Codex-davinci-002, Codex-Cushman) via the OpenAI API, the **Llama** family (Llama-13B, Llama-30B), and **GPT-J** for Xsum, MiniF2F, and WMT14. The choice spans both API-based closed models (Codex) and open-weight models (Llama, GPT-J), with model scales from ~6B (GPT-J) to ~175B (Codex-davinci). The paper notes that due to the "unexpected shutdown of the OpenAI API," results for Codex-001 and Codex-Cushman could not be obtained on Xsum, MiniF2F, and WMT14 (Section 4).

- **Metrics.** The primary metric is **pass@1 accuracy** for code generation — the fraction of prompts for which the top-ranked generation (after reranking) passes all provided unit tests. For MiniF2F autoformalization, **BLEU score** is used, following Wu et al. (2022). For Xsum summarization, **ROUGE-2** and **ROUGE-L** scores (reported divided by 100). For WMT14 translation, **BLEU score**. All results are reported as the average over bootstrap samples with 50 iterations, following the protocol in Shi et al. (2022) and Zhang et al. (2022). For each bootstrap iteration, 25 generations are sampled without replacement from the larger pool (125 or 50), reranking is applied, and the top generation is evaluated.

- **Baselines.** The paper compares against five baselines: (1) **Random selection** — uniformly random choice from the candidate set; (2) **Mean log probability ranking** — selecting the generation with the highest average per-token log probability; (3) **Medoid ranking** — selecting the generation with the lowest mean distance to all other generations in the confidence-weighted unigram space used by WUCS (this essentially picks the geometric center of the candidate set under the WUCS vector representation); (4) **Coder-Reviewer Reranker** (Zhang et al., 2022) — in two variants: Normalized Reviewer (NR), which ranks by mean per-token log p(x|y) where x is the prompt and y is the generation, and Normalized Coder-Reviewer (NCR), which combines NR with mean log p(y|x); (5) **Majority voting** is implicitly referenced in Section 3 as the self-consistency baseline when using exact-match similarity, though it is not separately tabulated for open-ended tasks since exact-match voting is inapplicable.

- **Generation budget / compute accounting.** The paper measures compute in terms of **inference passes**: generating M candidate outputs from the LLM constitutes the dominant cost. The reranking methods themselves require zero additional model calls (UCS, WUCS), one additional forward pass per candidate (NR, NCR), or no additional passes beyond generation (all methods). The paper does not compute FLOPs or wall-clock time, but the cost argument is made qualitatively: UCS requires only token counting and dot products over M² pairs with vocabulary size |V|, while coder-reviewer requires M additional forward passes through the LLM. The number of generations M is 25 for bootstrap evaluation (from pools of 125 or 50), with sensitivity analysis sweeping M from 5 to 100 (Figure 8, Supplement).

- **Cross-validation / statistical protocol.** The primary statistical protocol is **bootstrap resampling with 50 iterations**, following prior work (Shi et al., 2022; Zhang et al., 2022). For each bootstrap sample, 25 generations are drawn without replacement from the full pool (125 or 50), reranking is applied, and the selected generation is evaluated. Results are reported as averages over these 50 bootstrap iterations. This protocol captures variance due to which specific generations happen to be in the candidate set, providing error bars implicitly through the bootstrap distribution. There is no cross-validation over prompts or model checkpoints — the method has no learned parameters to fit — and no separate validation set is used.

### Main Quantitative Results

#### Code Generation: UCS Provides Large Gains, WUCS and Consensus-WUCS Are Strongest Overall

The headline result for code generation is that **UCS — which requires no token probabilities — improves pass@1 accuracy substantially over random selection across all models and datasets**, while **Consensus-WUCS achieves the best or near-best performance in almost every setting**, frequently matching or exceeding the much more expensive Coder-Reviewer Reranker.

**HumanEval results (Tables 1 and 7, main paper and Supplement).** For Codex002, random selection achieves 0.435 accuracy. UCS raises this to 0.539 — a 10.4 percentage point improvement. WUCS (0.558) and Consensus-WUCS (0.568) further improve by incorporating token probability information, with Consensus-WUCS outperforming mean-logp ranking (0.539) by 2.9 points. For Codex001, UCS achieves 0.402 vs. 0.345 (Random), with Consensus-WUCS reaching 0.445. For Code-Cushman, UCS: 0.353 vs. 0.311 (Random). For Llama models, the gains are smaller in absolute terms but proportionally substantial: Llama-13B improves from 0.142 (Random) to 0.177 (UCS) to 0.192 (Consensus-WUCS); Llama-30B from 0.207 to 0.257 to 0.267.

**MBPP-S results (Table 1).** Codex002: Random 0.55 → UCS 0.572 → Consensus-WUCS 0.589. Codex001: 0.494 → 0.523 → 0.546. Llama-30B: 0.325 → 0.253 → 0.373. Note that for Llama-30B on MBPP-S, UCS underperforms Random (0.253 vs. 0.325) — one of the few negative results — though WUCS (0.363) and Consensus-WUCS (0.373) recover and exceed Random. This is not discussed in the paper; it may indicate that when token overlap is an especially weak signal (lower-quality base model, smaller candidate pool), the unweighted version can be misleading.

**MBPP results (Table 1).** Codex002: Random 0.536 → UCS 0.58 → Consensus-WUCS 0.594. The gain from UCS over Random (4.4 points) is smaller than on HumanEval but still meaningful. Code-Cushman shows a particularly large improvement from UCS: 0.305 → 0.386 (8.1 points), with Consensus-WUCS reaching 0.42. This suggests the method is especially helpful for weaker base models where the gap between average and best generation is larger.

**Comparison with log-probability baselines.** A consistent finding across all code datasets: **WUCS outperforms mean-logp ranking in every model-dataset combination.** For example, HumanEval Codex002: WUCS 0.558 vs. mean-logp 0.539; MBPP Codex002: WUCS 0.587 vs. mean-logp 0.512; MBPP-S Codex002: WUCS 0.580 vs. mean-logp 0.570. This is a non-trivial result — both methods have access to the same token probability information, but WUCS uses it to weight a consensus signal while mean-logp uses it as a direct quality score. The superiority of WUCS suggests that **consensus-weighted probability is a better quality indicator than raw probability**, likely because it mitigates the tendency of mean-logp to favor degenerate, repetitive sequences that score highly under the model but are semantically poor.

**Comparison with Medoid baseline.** Consensus-WUCS outperforms Medoid in 13/15 model-dataset combinations for code (Table 7 in Supplement reports mean reciprocal rank, where the pattern is similar). Medoid performs competitively on some settings (e.g., Codex002 on MBPP-S: Medoid 0.583 vs. Consensus-WUCS 0.589) but is consistently weaker on HumanEval (Codex002: 0.437 vs. 0.568). The Medoid approach — selecting the generation with minimum average distance to all others — is conceptually similar to GSC but uses the WUCS vector space directly rather than unnormalized dot products, and the gap between them validates the paper's specific similarity function design.

**Comparison with Coder-Reviewer Reranker (Table 3, Supplement).** This is the key cost-quality comparison. Consensus-WUCS outperforms the Normalized Reviewer (NR) baseline in 13 of 15 model-dataset combinations. For instance, HumanEval Codex002: Consensus-WUCS 0.568 vs. NR 0.524; MBPP Codex002: 0.594 vs. 0.631 (one of the two losses); MBPP-S Codex002: 0.589 vs. 0.559. Against the stronger Normalized Coder-Reviewer (NCR), Consensus-WUCS outperforms in 6/15 combinations and ranks second in 8/15. This is the paper's strongest empirical claim about efficiency: a method requiring zero additional inference passes is competitive with or superior to a method requiring a full second forward pass per candidate. The few cases where NCR wins (e.g., HumanEval Codex002: NCR 0.576 vs. Consensus-WUCS 0.568) show that query-likelihood information does provide some signal not captured by token overlap, but the margin is small relative to the cost difference.

**Mean Reciprocal Rank results (Table 2, Supplement).** The paper also reports MRR, which captures how highly the correct answer is ranked even if it is not the top selection. The trends mirror pass@1: Consensus-WUCS achieves the best MRR in 9/15 code settings, with WUCS best in most remaining cases. This confirms that the method does not merely find a correct generation sometimes but consistently ranks correct generations near the top.

**Ranked pass@k results (Figure 3, Supplement).** For k > 1, GSC-ranked (which penalizes similarity to already-selected generations) substantially outperforms raw GSC. On HumanEval, raw GSC pass@k accuracy falls from ~0.68 at k=1 to ~0.72 at k=10, while GSC-ranked rises from ~0.68 to ~0.78 over the same range. On MBPP, the gap is similar: raw GSC increases only modestly with k while GSC-ranked continues to climb. This confirms that the diversity penalty is working as intended — raw GSC selects redundant near-consensus generations while GSC-ranked diversifies into different solution clusters.

#### Non-Code Tasks: Consistent but Smaller Gains Across Autoformalization, Summarization, and Translation

For all non-code tasks, the pattern is: **UCS variants consistently outperform Random and mean-logp ranking, but the margins are smaller than for code generation**, typically 1–3 points on the relevant metrics rather than 5–10 points.

**MiniF2F autoformalization (Table 1, BLEU scores).** For Codex002, the best method is Medoid at 58.2, followed by Consensus-WUCS at 56.2, both above Random at 55.8. The differences are small — all methods cluster within ~2.4 BLEU points. For Llama-13B, UCS (24.6), WUCS (24.7), and Consensus-WUCS (24.8) all marginally exceed Random (24.3). For GPT-J, the top methods (Medoid, Consensus-WUCS, WUCS) tie at 24.8 vs. Random at 24.2. These are statistically fragile differences given the bootstrap variance, but the consistency across models (all UCS variants beat Random for all models) suggests a real but weak signal. Notably, Medoid is the best method on MiniF2F for 3 of 4 models — this is the only task where Medoid outperforms the UCS variants, possibly because the WUCS vector space captures something about autoformalization quality that selecting the central point in that space is better than selecting the point with highest average agreement.

**Xsum summarization (Table 1).** For Rouge-2 on Codex002, Consensus-WUCS achieves 21.9 vs. Random 19.7 — a 2.2 point gain. UCS alone (21.0) outperforms both Random and mean-logp (21.4 for Codex002 on Rouge-2? Wait — actually Table 1 shows mean-logp at 21.4 vs. UCS at 21.0 for Codex002, so UCS loses to mean-logp in this specific cell, though Consensus-WUCS wins at 21.9). For Llama-13B, UCS (10.4) and WUCS/Consensus-WUCS (10.6) outperform Random (9.2) by 1.2–1.4 points. For Rouge-L on Codex002, UCS (34.8) and Consensus-WUCS (35.6) beat Random (33.9) but the best method is Medoid (36.3). The pattern across models is: UCS variants almost always beat Random and mean-logp (with a few exceptions), and Consensus-WUCS is best in 6 of the 10 Xsum evaluations (Rouge-2 and Rouge-L combined). Medoid wins some comparisons (notably Codex002 Rouge-L).

**WMT14 translation (Table 1).** For French-to-English on Codex002, Consensus-WUCS achieves 37.0 BLEU vs. Random 34.7 — a 2.3 point gain. UCS (36.2) outperforms both Random and Medoid (35.9). For the smaller models (Llama-13B, Llama-30B, GPT-J), BLEU scores are very low (3–5 range) because these models were not instruction-tuned for translation, and the gains from UCS are correspondingly tiny: e.g., Llama-13B Fr→En: Random 4.3 → UCS 4.4 → Consensus-WUCS 4.6. For German-to-English, the same pattern holds: Codex002 sees meaningful gains (Random 30.7 → UCS 31.6 → Consensus-WUCS 34.0), while smaller models see marginal improvements (GPT-J: 3.1 → 3.3).

**Aggregate summary.** Across all 20 non-code evaluations (4 models × 5 task-metrics: MiniF2F BLEU, Xsum Rouge-2, Xsum Rouge-L, WMT14 Fr→En BLEU, WMT14 De→En BLEU), Consensus-WUCS achieves the top spot in 12/20, WUCS in 7/20, UCS in 3/20, and Medoid in 5/20 (primarily from MiniF2F). This is evidence that the method transfers across tasks and modalities, but with substantially attenuated effect sizes compared to code.

#### Diagnostic: Why Gains Are Smaller for Non-Code Tasks

The paper provides a direct empirical explanation in Section 4.3.1 and Table 6 (Supplement). For each dataset, the authors compute the unigram overlap within the top-3 and bottom-3 generations (by quality), and report the ratio. The ratios are:
- HumanEval (code): 1.95
- MBPP (code): 1.34
- Xsum (summarization): 1.21
- MiniF2F (autoformalization): 1.08
- WMT14 French-to-English (translation): 1.07
- WMT14 German-to-English (translation): 1.08

This means that **for code, correct generations share substantially more unigrams with each other than incorrect generations do** — the lexical signal is highly discriminative. For translation, the ratio is nearly 1.0, meaning correct and incorrect generations share similar levels of vocabulary, so unigram overlap provides almost no information about quality. This directly explains the performance gradient: UCS gives large gains where the ratio is high (code), small gains where the ratio is moderate (summarization at 1.21), and minimal gains where the ratio is near 1.0 (translation, autoformalization).

The paper does not provide this analysis for the WUCS and Consensus-WUCS variants — it is possible that weighting by token probabilities partially compensates for the weaker lexical signal in natural language tasks, which would explain why the gap between UCS and Random is smaller for non-code but the gap between Consensus-WUCS and Random remains meaningful (e.g., Xsum Codex002 Rouge-2: Random 19.7 vs. UCS 21.0 vs. Consensus-WUCS 21.9). The probability weighting may capture quality-relevant information that raw token overlap misses in natural language settings.

#### GSC Score Ratios for Correct vs. Incorrect Generations

Table 8 (Supplement) provides a sanity check: the ratio of the average GSC score for correct generations to the average GSC score for incorrect generations. For Codex001 on HumanEval, this ratio is +2.8% (i.e., correct generations have higher GSC scores). However, the values vary by dataset and model: for AQuA, MultiArith, and StrategyQA (reasoning benchmarks evaluated with Codex and LaMDA), the ratios range from +1.9% to +7.1%. The UL2-20B model shows slightly negative ratios on StrategyQA (-0.1%) and MultiArith (-0.1%), indicating that for this model, the GSC score does not reliably distinguish correct from incorrect generations — a concerning negative result. The paper includes this table without extensive discussion, but it suggests the method's effectiveness is model-dependent: if a model does not consistently assign higher GSC scores to correct outputs, the reranking cannot work.

### Ablation Studies and Robustness Checks

**Maximum n-gram length (Figure 7, Supplement):** Increasing K from 1 (unigrams only) to 4 provides a small accuracy improvement on MBPP (approximately 0.58 → 0.60 for WUCS), but gains flatten after K=4. The paper notes that 4-grams are also the conventional setting for BLEU score computation and describes this convergence as "interesting." The computational cost grows with K because the vocabulary expands to include all n-grams up to length K, but the similarity computation remains O(M² · |V|). The flatness after K=4 suggests that multi-token patterns beyond 4-grams add negligible discriminative power for code generation — likely because code semantics are largely captured by keyword presence and short idiomatic phrases.

**Normalization of inner product (Table 5, Supplement):** Normalizing the dot product by vector norms (`WUCS-normalized`) degrades performance across all tested settings. For HumanEval Codex002, WUCS-normalized achieves 0.462 vs. 0.558 for unnormalized WUCS — a drop of nearly 10 points. For MBPP Codex002: 0.576 vs. 0.587. Ranking by the longest sequence alone (0.441 on HumanEval) or by the most diverse sequence (0.51 on HumanEval) both underperform WUCS, confirming that the similarity metric provides signal beyond simple length or diversity preferences. This is the most important ablation: it validates the paper's deliberate choice to leave the inner product unnormalized and demonstrates that the gains are not simply an artifact of selecting longer or more lexically diverse outputs.

**Decoding temperature (Figure 6, Supplement):** For MBPP with Codex002, evaluated across temperatures from 0.2 to 1.0: Consensus-WUCS dominates at lower temperatures (0.2–0.6), where absolute accuracy is also highest (~0.50 at temperature 0.2–0.4). At temperature 1.0, all methods converge to similar accuracy (~0.30). UCS alone is competitive with mean-logp at temperatures ≤ 0.4 but falls behind at higher temperatures. This suggests that the method is most effective in the operating regime where models are typically deployed (moderate temperatures producing largely coherent outputs) and that very high-temperature sampling — where outputs become essentially random — provides no useful signal for any reranking method.

**Number of generations (Figure 8, Supplement):** As the number of candidate generations increases from 5 to 100 on MBPP, UCS and WUCS variants maintain or improve accuracy (UCS: ~0.55 → ~0.60; Consensus-WUCS: ~0.56 → ~0.62), while mean-logp ranking **declines sharply** from ~0.52 to ~0.38 — falling below random selection (~0.43 at 100 generations). On Xsum Rouge-L, UCS variants remain roughly flat (~0.355–0.370) as generations increase from 20 to 100, while mean-logp again declines. The paper attributes this to the known tendency of mean-logp to favor degenerate, repetitive sequences (Holtzman et al., 2019) — as the candidate pool grows, the probability of encountering a degenerate sequence that scores highly under mean-logp but is semantically poor increases, and mean-logp ranking increasingly selects these. UCS variants avoid this because a degenerate generation shares tokens only with itself and thus receives low average similarity to a diverse peer set. This is a robustness result with practical significance: **UCS-based methods scale gracefully with generation count, while the standard log-probability baseline degrades.**

**OpenAI Ada embedding similarity (Table 4, Supplement):** Using cosine similarity between OpenAI `text-ada-embedding-002` embeddings as the GSC similarity function (instead of UCS) yields: HumanEval: 0.487 (vs. Consensus-WUCS 0.568, Random 0.437); MBPP: 0.579 (vs. 0.594); MiniF2F: 0.584 (vs. 0.562). Ada-based similarity outperforms Random and mean-logp for code tasks, validating the GSC framework with a completely different similarity function. However, it underperforms UCS for code generation, and the paper notes this is a "more heavyweight" approach requiring a separate embedding model. This ablation demonstrates that the GSC criterion (pick the generation with highest average similarity) is robust to the choice of similarity function — the framework is sound even if UCS is not uniquely optimal.

**GSC score ratios across models and tasks (Table 8, Supplement):** For reasoning benchmarks (AQuA, MultiArith, StrategyQA) evaluated with Codex001, Codex002, LaMDA-137, and UL2-20B, the ratio of average GSC score for correct generations to incorrect generations ranges from -1% to +7.1%. UL2-20B shows slightly negative ratios on AQuA (-1%), MultiArith (-0.1%), and StrategyQA (-0.1%), indicating that for this model, the GSC score does not discriminate correct from incorrect — a failure case that the paper acknowledges in the main text (Section 4.1: "The ratios are consistently > 1 for all models except for the UL2-20B model for which they still remain very close to 1"). This is important because it shows the method is not universally applicable; it depends on the model exhibiting the self-consistency property (correct generations being more similar to each other than to incorrect ones), which may not hold for all architectures or training procedures.

**Comparison with execution-based methods (implicit ablation):** The paper does not directly compare against MBR-Exec or AlphaCode, which use unit test execution for clustering — a comparison that would require the same execution infrastructure. However, the paper's framing (Section 3) positions UCS as an alternative for settings where execution is infeasible. The lack of a head-to-head comparison with execution-based methods on benchmarks where execution is possible (HumanEval, MBPP have unit tests) is a notable omission that a critical reviewer would flag. It is likely that execution-based clustering would outperform UCS on these benchmarks, since execution provides a ground-truth behavioral equivalence signal, but the paper's contribution is precisely for settings where that signal is unavailable.

### Critical Assessment

#### Claim 1: UCS provides substantial improvements over random selection for code generation, competitive with much heavier methods.

**What was tested:** The paper evaluates UCS, WUCS, and Consensus-WUCS against Random, mean-logp, Medoid, and Coder-Reviewer Reranker on HumanEval, MBPP, and MBPP-S across 5 models (Codex002, Codex001, Code-Cushman, Llama-13B, Llama-30B).

**What the experiments demonstrate:** UCS consistently and substantially outperforms Random on code generation. The gains are large in absolute terms for Codex models (8–10 points on HumanEval) and proportional for Llama models (2–5 points from a lower base). Consensus-WUCS outperforms the Normalized Reviewer baseline in 13/15 code evaluations and is competitive with Normalized Coder-Reviewer (6 wins, 8 second places out of 15). These results are robust across bootstrap samples and models.

**What was NOT tested:** The paper does not compare against execution-based clustering methods (MBR-Exec, AlphaCode) on benchmarks where unit tests are available. Since these methods use ground-truth behavioral equivalence signals, they would likely outperform UCS on HumanEval and MBPP — the claim is about competitiveness with *inference-based* rerankers, not all possible reranking approaches. The paper also does not evaluate on code generation benchmarks without unit tests (where execution is impossible), which would be the most natural setting for demonstrating UCS's unique value proposition. A study evaluating UCS on, say, code documentation generation or commit message generation — where "correctness" is fuzzy and execution is irrelevant — would strengthen the claim that UCS is useful precisely when execution-based methods are inapplicable.

**Limitation:** The evaluation uses 25-generation subsets via bootstrap from pools of 125, following prior work. This is a standard protocol but may overestimate pass@1 relative to a deployment setting where the number of generations is fixed at 25 — the bootstrap averages over many different 25-generation subsets, effectively giving the method multiple chances. The paper's sensitivity analysis (Figure 8) partially addresses this by showing the trend across generation counts from 5 to 100.

#### Claim 2: The method transfers to non-code tasks with consistent though smaller gains.

**What was tested:** MiniF2F (autoformalization), Xsum (summarization), and WMT14 (translation) across Codex002, Llama-13B, Llama-30B, and GPT-J.

**What the experiments demonstrate:** UCS variants consistently outperform Random across all non-code tasks, but the margins are small: typically 1–3 BLEU/ROUGE points. Consensus-WUCS achieves the top spot in 12/20 non-code evaluations. The diagnostic in Table 6 explains why: unigram overlap is substantially less discriminative for natural language tasks (ratio ~1.07–1.21) than for code (ratio ~1.34–1.95).

**What was NOT tested:** The paper does not evaluate on other open-ended generation tasks where lexical overlap might be more discriminative — for instance, structured data-to-text generation, SQL query generation, or formal specification writing. It also does not test whether adjusting the similarity function for natural language (e.g., using sentence embeddings, using synonym-aware token matching, or using n-gram TF-IDF weights) would close the gap with code performance. The claim of "transfer" is supported in the sense that UCS always beats Random, but the practical significance of 1–2 point gains on metrics like Rouge-L is debatable — these are often within the range of statistical noise for small test sets.

**Limitation:** The MiniF2F and Xsum evaluations use only 50 candidate generations per prompt (vs. 125 for code), and the bootstrap samples 25 from 50. This smaller pool may limit the method's ability to find high-quality consensus generations. The paper does not ablate the effect of pool size on non-code tasks.

#### Claim 3: The GSC-ranked extension improves pass@k for k > 1 by promoting diversity.

**What was tested:** GSC vs. GSC-ranked for pass@k with k = 1 to 10 on HumanEval, MBPP, and MBPP-S (Figure 3, Supplement).

**What the experiments demonstrate:** GSC-ranked substantially outperforms raw GSC at larger k, with the gap widening as k increases. This is a clean, well-designed ablation: the only difference is the penalty term for similarity to already-selected generations, which uses the same similarity matrix and adds negligible computation.

**What was NOT tested:** The paper does not compare GSC-ranked against other diversity-promoting selection methods (e.g., clustering-based selection, Maximal Marginal Relevance, or simply taking the top-k by raw GSC and then deduplicating by edit distance). Without such baselines, it is unclear whether the specific penalty-based formulation is better than simpler alternatives. The paper also does not evaluate whether the diversity mechanism sometimes selects lower-quality but diverse generations that collectively hurt pass@k — the pass@k metric only cares whether *any* of the k generations passes, which biases toward diversity. A user-facing metric (e.g., average quality of the top-k, or user preference studies) might reveal different tradeoffs.

#### Claim 4: The method requires minimal compute overhead compared to alternatives.

**What was tested:** Implicitly, through the comparison with Coder-Reviewer Reranker (which doubles inference cost) and through the description of UCS's computational requirements (token counting + dot products).

**What the experiments demonstrate:** UCS achieves competitive performance with a method that costs 2× inference compute. The paper does not report actual wall-clock times or FLOP counts.

**What was NOT tested:** The paper does not measure actual latency or compute cost in absolute terms. For M=25 generations, computing the M² similarity matrix is trivial, but for deployment scenarios with M in the thousands, the O(M² · |V|) cost could become non-trivial — though still likely dominated by the O(M) generation cost. The paper also does not compare against other lightweight reranking methods that might be similarly cheap (e.g., length-normalized best-of-N with a verifier, or simple heuristics like selecting the generation with the median length). The claim of "minimal overhead" is qualitatively accurate but quantitatively unsubstantiated.

#### Overall Strengths of the Evaluation

- **Multi-model, multi-dataset coverage** for code generation: the consistent improvement across Codex and Llama models of different scales suggests the method is not model-specific.
- **The bootstrap protocol** provides meaningful variance estimates and follows community standards.
- **The diagnostic in Table 6** (unigram overlap ratio between good and bad generations) provides a mechanistic explanation for *why* performance varies across tasks, which is more informative than simply reporting numbers.
- **The negative results** (UCS underperforming Random on Llama-30B MBPP-S, UL2-20B showing negative GSC score ratios, mean-logp degrading with more generations) are reported and add credibility.
- **The normalized inner product ablation** directly validates the paper's key design choice and would be the first thing a skeptical reader would question.

#### Overall Weaknesses of the Evaluation

- **No execution-based baseline comparison** on code benchmarks where execution is the natural competitor, leaving unclear how much performance is left on the table.
- **Small absolute gains on non-code tasks** that may not be practically significant — the paper acknowledges this but does not explore whether better similarity functions could close the gap.
- **No confidence intervals or statistical significance tests** — the bootstrap provides point estimates but the paper does not report standard deviations or test whether differences between methods are statistically significant. Given that some margins are small (e.g., Consensus-WUCS vs. Medoid on MiniF2F: 56.2 vs. 58.2), the ranking of methods may be within noise.
- **The GSC score ratio check (Table 8)** includes models and datasets not used in the main experiments (AQuA, MultiArith, StrategyQA, LaMDA, UL2-20B), suggesting the authors had additional data that was not fully reported.
- **Temperature ablation (Figure 6)** uses only MBPP and does not explore the interaction with task type — it is plausible that natural language tasks benefit from different temperature regimes, but this is not tested.
- **The Ada embedding experiment (Table 4)** is presented almost as an afterthought ("we chose not to explore it further") despite being conceptually important — it validates the GSC framework with a completely different similarity function, which is stronger evidence for the framework's generality than the UCS results alone. The decision to not develop this further is a missed opportunity to demonstrate that the unified framework is the contribution, not just the specific UCS metric.

## 6. Limitations and Trade-offs

### Unigram Overlap Is Fundamentally Weak for Natural Language Tasks

**The assumption or constraint.** The paper's entire approach depends on the assumption that surface-level token overlap between generations correlates with agreement on latent semantic predicates — that is, two correct generations will share more unigrams than a correct and an incorrect one. The paper explicitly measures the strength of this signal across tasks in Section 4.3.1 and Table 6:

> "The ratio of the overlap for coding tasks was a lot higher than that for non-coding tasks giving a hint as to why we see a much stronger improvement for coding tasks. This means that if a unigram is not shared between two generations, that gives a lot more information about whether two generations are semantically far apart for coding tasks versus non-coding tasks."

**The consequence.** For tasks where paraphrastic variation is high — translation, summarization, autoformalization — the unigram signal becomes weakly discriminative or nearly non-discriminative. On WMT14 translation tasks, the unigram overlap ratio between top and bottom generations approaches 1.0 (1.07–1.08), meaning correct and incorrect generations share essentially the same amount of vocabulary. The consequence is that UCS provides only marginal improvements (1–3 BLEU/ROUGE points) that may fall within statistical noise for small test sets. A practitioner deploying this method on a natural language generation task — document summarization in a production setting, for instance — would see performance gains that are real but too small to justify modifying an existing pipeline. The method is not broken for these tasks, but it is not practically transformative either.

**What evidence exists in the paper.** Table 6 directly quantifies the overlap ratio across all evaluated tasks, showing the steep drop from code (HumanEval: 1.95) to natural language (WMT14: 1.07–1.08). Table 1 shows the corresponding performance: on Xsum Rouge-2 with Codex002, Consensus-WUCS achieves 21.9 vs. Random 19.7 — a 2.2 point gain; on WMT14 French-to-English with Llama-13B, the gain is 4.3 → 4.6 BLEU. These are the smallest effect sizes in the paper. The authors are transparent about this in Section 4.3.1 but do not explore whether alternative similarity functions (embedding-based, synonym-aware, or n-gram TF-IDF) could recover stronger signals for natural language.

**Mitigation status.** Partially addressed. The WUCS and Consensus-WUCS variants incorporate token probability information, which provides a complementary quality signal and yields slightly larger gains than UCS alone for natural language tasks (e.g., Xsum Rouge-2 Codex002: UCS 21.0 → Consensus-WUCS 21.9). But this does not address the root cause — the underlying lexical overlap signal is weak — and the gains remain small. The Ada embedding experiment (Table 4) is presented as an alternative similarity function that could potentially work better for natural language, but the paper "chose not to explore it further," leaving the natural language limitation unresolved.

---

### The Method Depends on the Model Exhibiting Self-Consistency — And Some Models Don't

**The assumption or constraint.** The entire GSC framework rests on the self-consistency assumption formalized in Section 2: for each latent predicate, the most frequent value across generations is assumed to be correct. The paper states this as a foundational assumption — not an empirical finding — and all theoretical guarantees (Theorems 2.1–2.3) condition on it. For the method to work, the model must generate correct predicate values more often than incorrect ones, so that consensus converges toward correctness.

**The consequence.** If a model does not satisfy the self-consistency property — if its errors are systematic rather than random, or if incorrect outputs consistently outnumber correct ones on certain predicate dimensions — the GSC criterion will select generations that agree with the *incorrect* majority. The method actively harms performance in this regime: it confidently selects wrong answers because they are more similar to each other than the rare correct ones are. This is not a hypothetical failure mode. The paper's own data shows that the UL2-20B model exhibits GSC score ratios very close to or below 1.0 on multiple reasoning benchmarks (Table 8): AQuA: −1%, MultiArith: −0.1%, StrategyQA: −0.1%. A ratio below 1.0 means incorrect generations have *higher* GSC scores than correct ones — the method would actively select against correctness.

**What evidence exists in the paper.** Table 8 (Supplement) reports GSC score ratios for four models on reasoning benchmarks. UL2-20B is the clear negative case. The paper acknowledges this in Section 4.1 with the understated observation that "The ratios are consistently > 1 for all models except for the UL2-20B model for which they still remain very close to 1" — but "very close to 1" understates the problem when the ratio dips below 1.0. Additionally, the Llama-30B result on MBPP-S where UCS underperforms Random (0.253 vs. 0.325, Table 1) may be a manifestation of weak self-consistency for that model-task combination. The paper does not diagnose this failure or characterize which model properties predict self-consistency.

**Mitigation status.** Not addressed. The paper does not propose a diagnostic for detecting when self-consistency fails, does not provide guidance on which models or tasks exhibit the property, and does not suggest fallback strategies for when the assumption is violated. A practitioner cannot know, without running the full experiment, whether their model-task combination will benefit from UCS or be harmed by it. The theoretical analysis (Theorem 2.2) guarantees optimal selection *if* a perfect generation exists and *if* self-consistency holds — but provides no recourse when these conditions are absent.

---

### Cost of Generating the Candidate Pool Is Unaccounted for in the "Minimal Overhead" Claim

**The assumption or constraint.** The paper claims that UCS provides "minimal compute overhead" (Section 1, Abstract) and emphasizes that the reranking step requires "zero model calls" beyond the initial generation. However, the method's effectiveness depends on having a sufficiently large and diverse candidate pool to establish a reliable consensus signal. The paper uses 125 generations per prompt for code and 50 for text tasks, with bootstrap evaluation on subsets of 25.

**The consequence.** The headline "minimal overhead" claim is technically true for the reranking step in isolation — computing unigram overlaps over M=25 candidates is indeed negligible. But it obscures the fact that the method requires generating 5–25× more tokens than a single greedy decode. For a production system where each generation incurs API costs or GPU inference time, generating 125 candidates to select one represents a 125× increase in inference compute compared to taking the first sample. This is the standard best-of-N cost structure, and the paper's contribution is not reducing it but rather improving the selection step *given* that cost. A practitioner comparing UCS against execution-based reranking or coder-reviewer reranking needs to account for the fact that all three approaches share the same candidate-generation cost — the differences are in the selection overhead. The paper's framing sometimes conflates "no additional model calls for reranking" with "low total cost," but the dominant cost factor is the candidate generation itself, which is large and shared across methods.

**What evidence exists in the paper.** The paper does not provide FLOP counts, wall-clock times, or cost estimates for candidate generation vs. reranking. The sensitivity analysis in Figure 8 (Supplement) shows performance as the number of generations varies from 5 to 100, but this is framed as a robustness check rather than a cost analysis. The comparison with Coder-Reviewer Reranker (Table 3) correctly identifies that NR/NCR require doubling inference cost for the scorer, while UCS/WUCS do not — this is a legitimate 2× cost advantage in the selection phase. But the paper does not contextualize this relative to the base cost of generating M=125 candidates, which dominates both approaches.

**Mitigation status.** Partially addressed by implication. The paper shows that UCS performance is relatively stable as the number of generations decreases (Figure 8), suggesting that smaller candidate pools (and thus lower total cost) may suffice. But there is no systematic analysis of the minimum viable generation budget, no comparison of cost-normalized performance (e.g., accuracy per inference FLOP), and no guidance on how to choose M in practice. The paper leaves the practitioner to determine their own cost-quality tradeoff.

---

### The Method Has No Mechanism for Recognizing When It Fails — It Always Returns an Answer

**The assumption or constraint.** The GSC criterion is a forced-choice selector: given any set of M generations, it will always return the one with the highest average similarity to the others, regardless of whether any generation in the set is actually good. There is no confidence score, no abstention mechanism, and no quality threshold — the method is purely relative within the candidate set.

**The consequence.** If all M generations are poor (e.g., the model lacks capability for the task, or the sampling temperature is too high), the GSC-selected generation will still be poor — it will simply be the one that is most similar to the other poor generations. The method can actively mislead by presenting a confidently selected wrong answer. This is a structural limitation shared by all relative reranking methods that operate without absolute quality signals, but it is particularly acute for UCS because the similarity function is purely lexical: on a problem where the model consistently produces the same wrong approach with minor variations (e.g., all generations incorrectly use a for-loop instead of a while-loop), UCS will select the generation that uses the most common incorrect tokens — the "most consensus wrong answer." This is a failure mode that execution-based methods avoid (if all generations fail unit tests, no generation is selected as correct) and that probability-based methods partially mitigate (a confidently wrong generation gets a low probability score if the model is well-calibrated).

**What evidence exists in the paper.** The difficulty-bin results in the paper's problem framing suggest this is a real concern: for the hardest problems in the MATH benchmark (difficulty bin 5), the base model's pass@1 is near zero, and no test-time compute strategy helps — the proposal distribution contains no correct answers to find. Applied to UCS, this implies that on problems where the model has near-zero capability, the candidate set will contain only incorrect generations, and UCS will select the "best" wrong answer. The paper does not evaluate UCS on out-of-distribution or adversarial prompts, and does not report the quality of the GSC-selected generation conditional on no correct generation being present in the candidate set. The GSC score ratio close to 1.0 for UL2-20B (Table 8) hints that for some models, the GSC score provides essentially no discrimination between correct and incorrect — in such cases, the method is no better than random selection but still returns a confident answer.

**Mitigation status.** Not addressed. The paper does not propose a confidence score, a threshold on GSC values below which the selection should be treated as unreliable, or a fallback to a different method. The GSC framework, as presented, has no notion of uncertainty. This is a practical gap for any deployment where some fraction of prompts are outside the model's capability range — the method will silently fail on those prompts rather than flagging them for human review or escalation to a stronger model.

---

### No Comparison Against Execution-Based Methods on the Benchmarks Where Execution Is Possible

**The assumption or constraint.** The paper's motivation emphasizes settings where execution-based verification is infeasible — "as you move past the contest coding setting due to the complexity of setting up the build environment for arbitrary code as well as sandboxing it appropriately" (Section 1). However, all of the paper's code generation evaluations are on HumanEval, MBPP, and MBPP-S — benchmarks that explicitly provide unit tests specifically designed for execution-based evaluation. These are precisely the "contest coding" settings where execution *is* feasible and where MBR-Exec and AlphaCode have demonstrated strong performance.

**The consequence.** The paper compares UCS only against other inference-based reranking methods (Coder-Reviewer, mean-logp, Medoid, Random) — never against execution-based clustering on the same benchmarks. This leaves unanswered the central question a practitioner would ask: on benchmarks where I *can* execute code, how much performance do I sacrifice by using UCS instead of MBR-Exec or AlphaCode? The paper's value proposition hinges on settings where execution is impossible, but it never evaluates on such a setting. The claim that UCS is useful "when execution is infeasible" is supported by the diagnostic showing UCS works on code (Tables 1, 2) but not by a direct demonstration that UCS fills a gap that execution-based methods cannot. A skeptic would note that all the benchmarks used *do* support execution, and that the paper's failure to include an execution-based baseline on those benchmarks may reflect that execution would outperform UCS — a comparison that would weaken the paper's claim.

**What evidence exists in the paper.** Table 3 compares UCS variants against Coder-Reviewer Reranker (NR, NCR) — an inference-based method — but not against MBR-Exec or AlphaCode. The paper does not report execution-based clustering results on any of its evaluated datasets, nor does it justify why such a comparison is omitted. Section 5.2 describes MBR-Exec and AlphaCode conceptually but provides no empirical comparison. The ablation in Table 4 using Ada embeddings as a similarity function comes closest to testing an alternative to UCS, but this is an embedding-based method, not execution-based.

**Mitigation status.** Not addressed. The paper acknowledges execution-based methods in the related work (Section 5.2) and in the conceptual framework (Section 3) but provides no experimental comparison. The omission is notable because HumanEval and MBPP are the canonical benchmarks for code generation evaluation, and execution-based clustering is the dominant reranking approach on them. A fair evaluation would include an execution-based baseline and would also evaluate on one or more code generation tasks where execution is genuinely infeasible (e.g., generating code documentation, commit messages, or configuration files) to demonstrate UCS's unique value. The paper's framing of UCS as a solution for "when execution is infeasible" is not matched by its experimental design.

### The GSC Framework Provides Loose Theoretical Guarantees That Do Not Constrain Real-World Behavior

**The assumption or constraint.** Section 2 and Appendix A present three theorems that attempt to characterize when and how well the GSC criterion recovers the optimal generation. These theorems rely on strong assumptions: predicates are binary and independent (Theorem 2.3), the self-consistency property holds exactly (all theorems), and the optimal generation is present in the candidate set (Theorem 2.2). The paper acknowledges that Theorem 2.3's bound is not tight: "the bounds in Theorem 2.3 are still not very tight" (Section 2, immediately following the theorem statement). The bound grows as `√(k log n)`, where k is the number of predicates — but in the actual method, k is never observed (it is the number of latent predicates, not the vocabulary size), so the bound cannot be computed or used in practice.

**The consequence.** The theoretical analysis provides qualitative reassurance — "the penalty for selecting the maximum-agreement generation grows sublinearly in the number of predicates and generations" — but gives a practitioner no actionable guidance. The bound cannot be evaluated because k is unknown. The condition for Theorem 2.2 (a perfect generation exists in the candidate set) cannot be verified at inference time. Theorem 2.1's guarantee for k=1 (single predicate) is trivially satisfied for multiple-choice QA but irrelevant to the open-ended tasks that are the paper's focus. The gap between the theoretical framework (latent predicates with known values) and the operational method (unigram overlap as a proxy for unknown predicates) is never bridged formally — there is no theorem relating the error in the similarity proxy to the error in generation selection. The simulation results (Appendix B, Figures 4–5) partially fill this gap by showing that the GSC criterion works well when predicate values are known, but they do not simulate the effect of approximating predicate agreement with unigram overlap. The paper's empirical results are the real validation; the theory provides motivation and intuition but not guarantees.

**What evidence exists in the paper.** The theorems are stated in Section 2 with proofs in Appendix A. The simulations in Appendix B validate the GSC criterion under the predicate model with known predicate values, showing strong recovery rates for small numbers of categories per predicate (l < 5) and continued reasonable performance for larger l. However, these simulations do not model the proxy step — they assume access to true predicate agreement, not unigram overlap — so they validate the *criterion* but not the *operationalization*. The empirical results in Tables 1–3 provide the operational validation, but there is no formal connection between the two.

**Mitigation status.** The paper is transparent about the looseness of the bounds and uses simulations to supplement the theory. The statement that "the bounds in Theorem 2.3 are still not very tight" (Section 2) is an honest acknowledgment. However, the paper does not attempt to derive tighter bounds, does not characterize the conditions under which unigram overlap approximates predicate agreement, and does not provide a formal error analysis for the proxy step. The theoretical framework serves as motivation and intuition-building rather than as a source of operational guarantees — which is acceptable for an empirical methods paper, but a limitation nonetheless for practitioners seeking formal reliability assurances.

## 7. Implications and Future Directions

### How This Work Changes the Landscape

This paper does not propose a new model architecture, training paradigm, or decoding algorithm. Its contribution is more subtle and, in some ways, more broadly applicable: it provides a **conceptual reframing of reranking as a unified agreement-maximization problem** and demonstrates that this reframing, operationalized through trivially cheap lexical statistics, yields competitive or superior results compared to methods requiring substantially more computation or infrastructure.

The landscape shift is not a paradigm overthrow — the paper does not claim that UCS is better than execution-based clustering when execution is possible, or that it obsoletes auxiliary reranker models. Rather, the shift is in **lowering the barrier to effective reranking** and in **providing a diagnostic framework for understanding when and why different reranking methods work**. Prior to this work, practitioners faced an implicit choice: either accept the first model output (cheap but low-quality), invest in training a specialized reranker (expensive to build and maintain), double inference costs via query-likelihood methods (expensive per query), or set up execution infrastructure for code (powerful but fragile and task-specific). The paper shows that a fourth option — **consensus-based selection using only raw generation text** — is viable and often surprisingly competitive, particularly for code generation where token overlap is highly discriminative.

The paper's unification of existing reranking methods under the Generalized Self-Consistency (GSC) framework — where self-consistency voting, MBR-Exec, AlphaCode, and UCS are all instances of the same template with different similarity functions — is the kind of conceptual contribution that changes how researchers think about a problem. It converts a collection of seemingly disparate methods into a single design space parameterized by the similarity function. This means that **future reranking research can focus on designing better similarity functions rather than inventing entirely new selection mechanisms**, and any new similarity function can be evaluated in the GSC framework with minimal infrastructure. The paper validates this claim with the Ada embedding experiment (Table 4), which uses cosine similarity between embeddings as the similarity function and still outperforms random selection — demonstrating that the framework generalizes beyond the paper's specific UCS implementation.

The paper also resolves a specific tension in the self-consistency literature. Wang et al. (2022) showed that majority voting over extracted answers works well for tasks with small answer spaces, but the method was understood as fundamentally tied to answer extraction — you need a discrete final answer to vote on. This paper shows that **answer extraction is a sufficient but not necessary condition for self-consistency to work**. By recasting self-consistency as operating over latent semantic predicates rather than extracted answers, the paper removes the requirement for a small, extractable answer space and opens self-consistency to open-ended generation. This reframing is not an incremental tweak — it is a generalization that subsumes the original method as a special case (when the similarity function is exact answer match) while extending applicability to tasks where the original method is inapplicable.

More practically, the paper changes the cost-quality calculus for reranking in two ways. First, it demonstrates that **generating more candidates and using cheap consensus is often more effective than spending the same compute on a sophisticated reranker**. The comparison with Coder-Reviewer Reranker (Table 3) is the key evidence: Consensus-WUCS matches or exceeds a method that doubles inference cost in 13/15 code evaluations, despite requiring zero additional model calls. This suggests that the marginal return on compute invested in sophisticated reranking (query likelihood, auxiliary models) is low relative to simply generating more candidates and applying UCS — the dominant reranking signal is already captured by cheap lexical consensus. Second, it shows that **log-probability ranking, the standard lightweight baseline, is actively harmful at scale**: Figure 8 demonstrates that mean-logp ranking degrades as the number of candidates increases, falling below random selection at large M, while UCS variants maintain or improve accuracy. This is a practically important warning: the "obvious" cheap baseline does not scale, and UCS provides a drop-in replacement that does.

The paper also serves as a **diagnostic tool for understanding model behavior**. The GSC framework provides a way to measure whether a model exhibits the self-consistency property for a given task — by computing the ratio of GSC scores for correct vs. incorrect generations (Table 8). A ratio substantially above 1.0 indicates that correct generations are more similar to each other than incorrect ones are, which is a prerequisite for consensus-based methods to work. A ratio near or below 1.0 (as seen for UL2-20B) signals that the model's errors are systematic or that its correct outputs are not lexically coherent as a group. This diagnostic could guide deployment decisions: if the GSC score ratio is low for a model-task pair, consensus-based reranking is unlikely to help, and alternative approaches (execution, human review, or a different model) should be preferred.

The main limitation of the landscape impact is that **the effect sizes are strongly task-dependent**, and the paper's own analysis (Table 6) shows that the underlying signal — lexical overlap between correct generations — weakens dramatically for natural language tasks compared to code. This means the landscape shift is not uniform: for code generation, UCS provides a genuinely competitive alternative to heavier methods; for summarization and translation, the gains are real but small enough that a practitioner might reasonably decide they do not justify modifying an existing pipeline. The paper does not claim otherwise, but the disparity means that **UCS is best understood as a code-generation-first method that also provides small but consistent gains on text tasks**, rather than as a universally strong reranker for all generation tasks.

### Follow-Up Research This Work Enables

**Characterizing when GSC fails and developing fallback diagnostics.** The paper shows that UL2-20B exhibits GSC score ratios near or below 1.0 (Table 8), meaning the consensus criterion does not discriminate correct from incorrect — and may actively select against correctness. But the paper provides no systematic characterization of *which* models, tasks, or generation settings exhibit this failure mode, and no diagnostic that can be computed at inference time (without ground-truth labels) to detect it. A strong follow-up would: (1) compute GSC score ratios across a broad set of models (scaling from ~1B to ~100B+ parameters) on code and text tasks to map the landscape of self-consistency; (2) develop an unsupervised proxy for the GSC score ratio (e.g., the variance of GSC scores across the candidate set, or the similarity between the top-ranked generation and the centroid of the candidate set) that correlates with debiased accuracy improvement; (3) evaluate whether models that fail self-consistency can be "rescued" by generating candidates at higher temperature (to increase diversity and break systematic error patterns) or by using a different similarity function (e.g., embedding-based rather than lexical). A negative result — finding that self-consistency failure is common in smaller models or certain architectures — would be as valuable as a positive one, because it would define the boundary conditions for the entire GSC approach.

**Embedding-based similarity functions for natural language tasks.** The paper's Ada embedding experiment (Table 4) is a brief, tantalizing glimpse of an alternative similarity function: cosine similarity between OpenAI `text-ada-embedding-002` embeddings outperforms random selection and mean-logp on code tasks, though it underperforms UCS. The paper "chose not to explore it further" but the GSC framework makes this exploration straightforward — any similarity function can be plugged into the same selection criterion. A strong follow-up would systematically compare similarity functions across the task spectrum: (1) lexical overlap (UCS, with varying n-gram lengths and TF-IDF weighting), (2) static embeddings (Ada, Sentence-BERT, or lightweight models like all-MiniLM-L6-v2 that can run locally without API calls), (3) task-specific fine-tuned embeddings (e.g., CodeBERT embeddings for code, or a contrastively trained model for summarization), and (4) execution-based similarity (MBR-Exec) as an oracle upper bound. The key question is whether embedding-based similarity can close the gap between UCS and execution-based methods on code, and — more importantly — whether it can substantially improve upon UCS's weak performance on natural language tasks where lexical overlap is nondiscriminative (Table 6: WMT14 ratio ~1.07). If a lightweight embedding model (running on CPU, adding minimal latency) could raise UCS-scale gains on summarization and translation from 1–3 points to 5–8 points, the method would become practically compelling for text tasks as well. The paper's own diagnostic (Table 6) suggests where to look: tasks with low unigram overlap ratios between good and bad generations are the ones where better similarity functions should provide the largest relative gains.

**Combining UCS with execution-based methods for hybrid reranking.** The paper's motivation emphasizes settings where execution is infeasible, but a more practical framing for many real-world code generation systems is that **execution is partially feasible**: some generated programs can be executed (those using standard libraries in sandboxable environments), while others cannot (those requiring network access, GPU dependencies, or system-level operations). A natural extension is a hybrid reranker that uses UCS (or GSC with a better similarity function) to rank all candidates initially, then applies execution-based clustering to the subset that can be executed, and combines the two signals. The experiment would involve: (1) constructing a code generation benchmark where only a fraction of problems have executable unit tests (e.g., by subsampling unit tests from HumanEval or by using a dataset like CodeContests where test infrastructure is complex), (2) evaluating UCS-only, execution-only, and a combined method (e.g., using UCS scores as a prior for execution-based clustering, or using execution results to calibrate UCS confidence), and (3) measuring whether the combined method outperforms either alone in the partial-execution regime. The key hypothesis is that UCS captures lexical signals about code quality that execution misses (e.g., code style, readability, algorithmic efficiency) and that execution provides ground-truth signals about functional correctness that UCS cannot capture — and that combining them yields a better ranking than either alone. This directly addresses the paper's stated motivation ("past the contest coding setting") but on a benchmark that actually reflects that setting.

**Abstention and confidence estimation for GSC-based reranking.** The paper identifies a structural limitation — GSC always returns an answer, even when all candidates are poor — but does not propose a mitigation. For any production deployment where some queries are outside the model's capability, this is a critical gap. A follow-up should develop a confidence score derived from the GSC framework that predicts whether the selected generation is actually correct, enabling abstention or escalation to a stronger model. Candidate signals include: (1) the absolute GSC score of the top-ranked generation (a generation with low average similarity to peers may be an outlier rather than a consensus choice), (2) the margin between the top-ranked and second-ranked GSC scores (a close contest suggests uncertainty), (3) the entropy of the GSC score distribution across candidates, (4) the ratio of the top generation's GSC score to the average GSC score (if the top generation is only marginally more consensus-aligned than average, the selection may be unreliable). The experiment would require evaluating these confidence signals on a dataset that includes both in-distribution prompts (where the model produces correct generations) and out-of-distribution or adversarial prompts (where it does not), measuring the correlation between confidence and actual correctness, and setting thresholds that achieve a target precision-recall tradeoff. A strong result would be a confidence metric that identifies, with high recall, the subset of queries for which GSC selection is no better than random — enabling a system that falls back to a stronger model or requests human review on those queries while using GSC for the majority where it works.

**Scaling laws for consensus-based reranking.** The paper shows (Figure 8) that UCS accuracy improves or remains stable as the number of candidate generations M increases from 5 to 100, while mean-logp ranking degrades. But M is only swept up to 100 for technical reasons (generation cost). A natural question, analogous to scaling laws for model size and data, is: **how does reranking accuracy scale with M for different similarity functions and task types?** Does consensus-based reranking exhibit a power-law improvement in pass@1 as M increases, or does it saturate? At what M do diminishing returns set in? How does the scaling behavior differ between code (where the unigram signal is strong) and natural language (where it is weak)? An experiment would generate very large candidate pools (M up to 1000 or more, depending on compute budget) for a fixed set of prompts, evaluate pass@1 as a function of M for UCS, WUCS, Consensus-WUCS, and execution-based oracles, and fit scaling curves. This would provide practical guidance for deployment (how many generations to budget) and theoretical insight into the nature of the consensus signal. The paper's existing data (Figure 8) is suggestive but insufficient for fitting scaling laws — M only goes to 100 and the curves are noisy. A more systematic study with larger M and rigorous curve-fitting would either validate that consensus-based methods scale gracefully (encouraging investment in generating more candidates) or reveal saturation points (encouraging investment in better similarity functions rather than larger M).

**Adversarial robustness of GSC-based selection.** The paper evaluates UCS on standard benchmarks with natural model outputs but does not assess robustness to adversarial manipulation. A generation set could be adversarially constructed to exploit the UCS selection criterion — for example, by injecting many near-duplicate incorrect generations that share high unigram overlap with each other, creating a spurious consensus for a wrong answer. This is not a purely academic concern: in any setting where generations might be influenced by prompt injection, data poisoning, or coordinated attacks, a consensus-based reranker could be exploited. A follow-up stress test would: (1) construct adversarial generation sets where a fraction of candidates are designed to maximize UCS score for an incorrect answer (e.g., by generating many slight variants of a wrong solution with high token overlap), (2) measure how many adversarial generations are needed to flip the GSC selection from correct to incorrect, and (3) test whether weighted variants (WUCS, where low-probability tokens contribute less) provide any robustness against this attack. A negative result — showing that even a small fraction of adversarial generations can hijack UCS selection — would be important for practitioners deploying the method in adversarial settings and would motivate research into robust aggregation functions or outlier-resistant similarity metrics.

### Practical Applications and Downstream Use Cases

**Cost-efficient code generation in API-based deployments.** Consider a software development tool that uses the OpenAI API to generate code completions or function implementations for developer prompts. At current API pricing, generating 25 candidate completions per query and selecting the best via UCS costs 25× the generation cost of a single greedy decode — but the reranking itself adds zero additional API calls. The paper's results suggest that on HumanEval, UCS improves pass@1 from 0.435 (random selection from the 25 candidates) to 0.539 for Codex002 (Table 1). This is approximately a 24% relative improvement in the probability that the selected generation is correct. For a developer tool where correctness directly translates to user trust and reduced editing time, this improvement may justify the 25× generation cost — especially if the tool caches generations or uses speculative decoding to reduce per-token latency. The GSC-ranked extension (Section 3.1, Figure 3 in Supplement) further enables showing the user a diverse top-3 list rather than a single suggestion, increasing the chance that at least one suggestion is useful with only marginal additional reranking cost (since the similarity matrix is already computed). The key practical advantage over alternative reranking methods is that UCS works with black-box API access — no need for token probabilities (which some API tiers do not expose), no need to execute generated code, and no need to train or host an auxiliary model. The entire reranking pipeline is a few lines of Python using string operations on the API responses.

**Batch data generation for self-improvement and distillation pipelines.** When using LLMs to generate training data for fine-tuning smaller models (knowledge distillation) or for self-improvement loops (STaR, ReST), the quality of the generated outputs directly determines the quality of the resulting model. A common approach is rejection sampling: generate N candidates per training example, keep the ones that pass some quality filter, and fine-tune on the kept examples. UCS provides a quality filter that works on raw text without requiring execution, human evaluation, or auxiliary scoring models. For code generation distillation, this is particularly valuable: a large teacher model (e.g., GPT-4) generates many candidate solutions for each training prompt; UCS selects the highest-consensus generation as the pseudo-ground-truth; the student model is fine-tuned on these selected solutions. The paper's results suggest that UCS-selected generations are substantially more likely to be correct than random selections (e.g., HumanEval Codex002: 0.539 vs. 0.435), translating directly to higher-quality training data. The GSC-ranked variant could also be used to generate multiple diverse high-quality training examples per prompt, increasing dataset diversity. The key advantage over execution-based filtering is that UCS works for any generation task, not just code with unit tests — enabling the same pipeline to be applied to summarization, translation, or instruction-following data generation where automated quality checking is harder. The paper's non-code results (Table 1) show smaller but consistent gains, so the improvement in downstream model quality would need to be empirically validated, but the infrastructure cost is negligible compared to the generation cost.

**Best-of-N decoding for open-ended tasks in resource-constrained settings.** Many deployment scenarios involve edge devices, on-premise servers, or applications where model inference is the dominant cost and latency constraint. In these settings, deploying a dedicated reranker model is infeasible (additional GPU memory, inference latency) and execution-based verification is often impossible (no sandbox, no unit tests). UCS provides a reranking method that can run on CPU with negligible memory and latency, making it deployable alongside the generation model with minimal overhead. The specific benefit: for a given inference budget, a system can generate N candidate outputs (consuming the budget) and apply UCS to select the best, rather than generating a single output with greedy or temperature-1 decoding. The paper's results (Figure 8) show that UCS accuracy improves as N increases from 5 to 100 on code tasks, while mean-logp ranking degrades — meaning UCS enables the system to exploit additional generation budget productively, whereas the standard cheap baseline (mean-logp) becomes counterproductive. This is particularly relevant for on-device models (like quantized Llama variants or small code generation models) where the candidate generation cost is low enough that N = 25 or 50 is feasible, and the improvement from UCS directly translates to better user-facing output quality without requiring cloud offloading or additional model hosting.
