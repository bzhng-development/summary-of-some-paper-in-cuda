# BitNet v2: Native 4-bit Activations with Hadamard Transformation for 1-bit LLMs

**ArXiv:** [2504.18415](https://arxiv.org/abs/2504.18415)

## 🎯 Pitch

BitNet v2 introduces **H-BitLinear**, a module that applies an online Hadamard transformation before activation quantization to enable native 4-bit activations in 1-bit LLMs — a capability previously blocked by outlier-prone intermediate activation distributions (in the attention output projection Wo and FFN down projection Wdown).

---

## 1. Executive Summary

BitNet v2 introduces **H-BitLinear**, a module that applies an online Hadamard transformation before activation quantization to enable native 4-bit activations in 1-bit LLMs — a capability previously blocked by outlier-prone intermediate activation distributions (in the attention output projection Wo and FFN down projection Wdown). Training from scratch on 100B tokens from RedPajama, BitNet v2 with 8-bit activations matches BitNet b1.58 performance across model sizes from 400M to 7B (e.g., +0.16% to +0.61% average zero-shot accuracy on 1.3B–7B models), and when continue-trained with 4-bit activations for only 5B additional tokens, it achieves perplexity comparable to the hybrid 4-bit/8-bit BitNet a4.8 while outperforming post-training quantization baselines like SpinQuant and QuaRot by large margins (11.33 vs. 13.52 perplexity at 1.3B). The framework establishes that native dense 4-bit computation is viable for 1.58-bit LLMs, but only when the activation distribution is first reshaped into a Gaussian-like form — without the Hadamard transformation, models diverge entirely.

## 2. Context and Motivation

### The Core Problem: Activation Quantization in 1-Bit LLMs Hits a Wall

BitNet v2 addresses a specific and precisely characterized bottleneck: **while 1.58-bit weight quantization has been solved (via BitNet b1.58), quantizing activations below 8 bits within the same models remains fundamentally blocked by outlier-prone intermediate activation distributions**. This is not a minor optimization detail — it represents the primary remaining obstacle to fully leveraging emerging 4-bit-capable hardware in the context of extremely weight-efficient LLMs.

To understand why this matters, we need to be precise about what "1-bit LLM" means in this line of work. The BitNet family (BitNet, BitNet b1.58, BitNet a4.8, and now BitNet v2) uses **ternary weights**: each weight parameter is constrained to one of three values {−1, 0, +1}, which requires approximately 1.58 bits to represent (hence "1.58-bit"). This is a form of extreme quantization-aware training (QAT): the model is trained from scratch with weights quantized to ternary values, using the straight-through estimator to propagate gradients through the non-differentiable quantization function. The payoff is enormous: weight storage drops by roughly 10× compared to FP16, memory bandwidth bottlenecks are dramatically alleviated, and specialized hardware can perform inference using primarily integer addition operations rather than floating-point multiplications.

However, weight quantization is only half the story. During inference, the model must also quantize its **activations** — the intermediate tensors flowing between layers — to avoid expensive dequantization operations and to fully exploit low-precision compute units. BitNet b1.58 quantized activations to 8-bit integers (INT8). While this is better than full precision, it leaves substantial efficiency on the table: next-generation GPUs like the NVIDIA GB200 offer native 4-bit compute capability, and an 8-bit activation pipeline cannot exploit these 4-bit instructions fully. The paper states this directly:

> "This reliance on 8-bit precision prevents these models from fully leveraging the 4-bit computational capabilities of emerging hardware, shifting the efficiency bottleneck towards computation itself."

### Why This Bottleneck Is Structurally Important

The distinction between weight quantization benefits and activation quantization benefits maps directly to the two classic bottlenecks in transformer inference:

**Memory bandwidth bottleneck (weight-bound operations).** When generating tokens autoregressively one-at-a-time, the dominant cost is shuttling model weights from memory to compute units — the matrix multiplications involve a weight matrix (large, loaded from memory) multiplied by a single token's activation vector (small). Quantizing weights to 1.58 bits directly attacks this bottleneck, reducing weight memory footprint by ~10×. BitNet b1.58 already solves this problem.

**Compute throughput bottleneck (activation-bound operations).** In **batched inference** or during the prefill phase (processing a long prompt in parallel), the dominant cost shifts: now the activation matrices are large (many tokens × hidden dimension), and the compute units themselves become the limiting resource. Quantizing activations to 4 bits would double the theoretical throughput versus 8-bit on hardware with native 4-bit support, since twice as many operations can be packed into the same compute cycles. BitNet b1.58's INT8 activations leave this second bottleneck largely unaddressed.

This is why the paper frames the problem specifically around **batched inference efficiency** (Section 1 and throughout). For single-query, latency-bound deployments, 1.58-bit weights with 8-bit activations may already be close to optimal — weight bandwidth dominates. But for high-throughput serving (many queries processed simultaneously) or long-context prefill (where the prompt is processed in one forward pass with many tokens), the compute throughput of activation-heavy operations becomes the binding constraint, and 4-bit activations provide a direct path to doubling throughput.

### The Fundamental Obstacle: Outlier Channels in Intermediate Activations

The paper does not simply observe that quantizing activations to 4 bits causes degradation — it identifies the **precise mechanism** causing the failure, which is essential for understanding why prior approaches were inadequate and why the proposed solution works.

The transformer architecture produces two qualitatively different types of activation distributions (Section 2.1, Figure 2):

**Gaussian-like activations (easy to quantize).** The inputs to the attention projections (queries, keys, values — Wqkv) and the up/gate projections in the FFN (Wup,gate) exhibit distributions that are approximately Gaussian. Their values are relatively well-distributed around zero with moderate variance. These distributions are amenable to low-bit quantization because standard quantizers (absmax, absmean) can capture their range without catastrophic clipping or excessive quantization error.

**Outlier-prone activations (hard to quantize).** The **intermediate states** — specifically, the outputs of the attention mechanism before final projection (the activation feeding into Wo) and the outputs of the gating mechanism before the down projection (the activation feeding into Wdown) — exhibit a very different distribution. These tensors contain **outlier channels**: specific feature dimensions whose magnitudes are consistently much larger than the rest of the distribution. The paper's visualizations (Figure 1, bottom row; Figure 2(b,d); Figure 3) make this vivid: the activation maps for Wo and Wdown in BitNet b1.58 show bright vertical streaks corresponding to outlier channels, with most entries clustered near zero but a few channels exhibiting values 10–100× larger.

Why do these outliers appear specifically in intermediate states and not in inputs? The paper does not theorize extensively, but the pattern is well-documented in the broader quantization literature (which the paper cites: Wang et al. 2024; Liu et al. 2024). The attention mechanism's softmax and the FFN's gating (SwishGLU) produce sparse activations where certain feature dimensions are consistently activated with high magnitude — potentially because these dimensions encode features that are important across many tokens (e.g., positional information, register-like features). The projection matrices learn to amplify these dimensions, creating channels that consistently dominate the distribution.

**Why outliers break low-bit quantization.** When quantizing to 4 bits, you have only 16 representable values (integers −8 to 7, in the paper's INT4 scheme). The quantizer must choose a scaling factor that maps the floating-point range to these 16 levels. If the distribution contains a few channels with magnitude 100 and the rest with magnitude ~1, the scaling factor is forced to accommodate the outliers:

- If you set the scaling factor to cover the full range (including outliers), the quantization step size becomes large, and most values in the ~1 range collapse to 0 or ±1 — massive information loss for the bulk of the signal.
- If you set the scaling factor to capture the bulk of the distribution, the outliers get clipped to ±8, losing potentially critical information from those channels.

This is the fundamental tension: **a single global scaling factor cannot simultaneously preserve both the outliers and the signal in the dense mass of the distribution** when the dynamic range spans more than ~2–3 orders of magnitude. At 8 bits (256 levels), this is manageable — the extra resolution provides enough distinct values to represent both the body and the tails. At 4 bits (16 levels), it is catastrophic.

### Prior Approaches and Where They Fall Short

The paper positions itself against three families of prior work, each of which attempts to address activation quantization but leaves specific gaps.

**1. Uniform quantization with outlier handling (BitNet a4.8).** The most directly relevant predecessor is BitNet a4.8 (Wang, Ma, and Wei, 2024), which attempted exactly the same goal — pushing activations below 8 bits in 1.58-bit LLMs. BitNet a4.8's approach was **selective**: use 4-bit quantization for the well-behaved input activations (Wqkv, Wup,gate) but fall back to an 8-bit sparsification scheme for the problematic intermediate states (Wo, Wdown). This hybrid approach achieved minimal performance loss compared to the INT8 baseline, demonstrating that the input activations could indeed be quantized to 4 bits without issue.

However, BitNet a4.8's reliance on sparsification for the intermediate states introduces a deployment-side problem that the BitNet v2 paper highlights explicitly:

> "sparsification is less suited for maximizing throughput in batched inference, where dense computations are often preferred for hardware efficiency"

This is a crucial practical distinction. Sparsification means that not all activation values are computed — the top-K largest activations are kept, and the rest are set to zero. While this reduces the number of multiply-accumulate operations, it introduces irregular memory access patterns and load imbalance. Modern GPU tensor cores are optimized for **dense** matrix multiplication, where all values in a tile are processed uniformly. Sparse computation requires either specialized hardware support (sparse tensor cores, which have limitations on sparsity patterns) or incurs overhead from gather/scatter operations and workload imbalance between threads. For high-throughput batched inference where the goal is to saturate the GPU's compute capacity, dense 4-bit computation is preferable to sparse 8-bit computation — even if the theoretical operation count is similar.

BitNet v2 therefore targets a specific capability gap left by BitNet a4.8: **native dense 4-bit computation across all linear layers**, including the problematic intermediate states. This requires solving the outlier problem directly rather than sidestepping it with sparsification.

**2. Post-training quantization with rotations (QuaRot, SpinQuant).** A parallel line of work addresses activation quantization in full-precision models using **post-training quantization (PTQ)** — quantizing a pre-trained model without retraining. Two representative methods, QuaRot (Ashkboos et al., 2024) and SpinQuant (Liu et al., 2024), both observe the same outlier phenomenon and propose a similar solution: apply a rotation matrix (randomized Hadamard in QuaRot, learned rotation in SpinQuant) to the activation space before quantization. The intuition is that by rotating the coordinate system, outlier magnitudes get "smeared" across dimensions, reducing the dynamic range per channel and making the distribution more Gaussian-like.

This is conceptually similar to BitNet v2's approach, but the paper identifies a critical gap when these methods are applied to **1.58-bit models** as opposed to full-precision models. The results in Table 4 are stark:

- Applying QuaRot or SpinQuant to BitNet b1.58 (1.58-bit weights, PTQ to 4-bit activations) yields perplexities of 19.80–20.83, compared to 11.33 for BitNet v2 (a4) trained from scratch. That is a catastrophic degradation.
- Even with the removal of rotary matrix fusion into the weight quantization (which the paper shows is necessary for reasonable PTQ performance in ternary models, reducing SpinQuant perplexity from 19.80 to 13.52), the PTQ baselines still lag far behind BitNet v2's 11.33.

The paper attributes this sensitivity to a specific interaction between ternary weights and rotation-based quantization:

> "ternary models are more sensitive to the fusion of rotary matrix and latent weights"

When PTQ methods fuse the rotation matrix into the weight matrix (computing Q_w(W R^T) in one shot rather than Q_w(W) R^T), the ternary quantization step interacts poorly with the rotated weight distribution, presumably because the ternary constraint {−1, 0, 1} is applied post-rotation, which distorts the intended rotational effect. Without fusion, the weights operate in full precision (W16A4), which defeats the purpose of 1-bit LLMs — you lose the weight memory savings. This reveals that **PTQ approaches designed for full-precision models do not transfer straightforwardly to the ternary weight regime**, and training-aware approaches (like BitNet v2) are necessary.

**3. The broader activation quantization literature.** The paper cites work by Liu et al. (2024) on training-free activation sparsity and the general observation that LLM activations contain outlier features. This body of work establishes that activation outliers are a universal phenomenon in transformer LLMs — they appear in models from different families, at different scales, and with different training recipes. The problem is not specific to 1-bit models; it is a fundamental property of the transformer architecture itself. However, the consequences are more severe for 1-bit models because:

- The weights are already at the theoretical minimum precision. All remaining precision loss comes from the activations.
- The models are explicitly designed for deployment efficiency, so leaving activation quantization at 8 bits when hardware supports 4-bit operations leaves a large fraction of potential speedup unrealized.
- The combination of extreme weight quantization and aggressive activation quantization creates compound effects that don't appear when either is done in isolation.

### How BitNet v2 Positions Itself

The paper's positioning can be understood along three dimensions:

**Methodological dimension: training-aware vs. post-training.** BitNet v2 is firmly in the training-aware camp. The Hadamard transformation is integrated into the forward pass during training (not applied after training as a one-time rotation), and the 4-bit variant is produced through **continue-training** — start from the 8-bit trained model and fine-tune with 4-bit activations for a small number of additional tokens (5B out of the 100B total). This "8-bit → 4-bit continue-training" strategy is explicitly presented as a practical advantage: it reuses optimizer states and requires only a small fraction of the total training budget. The paper does not claim that 4-bit training from scratch is impossible, but rather that the two-stage approach is efficient.

**Architectural dimension: targeted, not universal.** The Hadamard transformation is applied **only where needed** — in the output projection Wo and the down projection Wdown — not universally across all linear layers. This is a deliberately minimalist design choice, justified by the observation (Figure 2) that the input activations (Wqkv, Wup,gate) are already Gaussian-like and don't need transformation. Adding unnecessary rotations would increase computational overhead without benefit.

**Hardware dimension: batched inference as the target regime.** The paper's efficiency arguments are specifically scoped to **batched inference**, where dense 4-bit computation can be fully utilized. This is a pragmatic scope: in single-query inference, weight bandwidth dominates and 8-bit activations may already be sufficient. By focusing on batched inference, the paper addresses the regime where activation quantization actually translates to throughput improvements on real hardware.

This positioning is communicated concisely in the abstract and introduction, but it carries significant implications. It says: "We are not claiming that 4-bit activations help in all scenarios. We are claiming that in the specific (and increasingly important) scenario of high-throughput batched inference, 4-bit activations are the bottleneck, and BitNet v2 removes that bottleneck without degrading model quality." This is a more modest but also more credible claim than "4-bit is always better."

### The Stakes: Why This Matters Beyond the BitNet Family

While BitNet v2 is evaluated exclusively on ternary-weight models in the BitNet lineage, the significance extends further. The transformer activation outlier phenomenon is universal, and the Hadamard transformation as a pre-quantization smoothing operation is potentially applicable to any model where activations need to be quantized to low precision. The paper's key empirical finding — that without Hadamard transformation, 4-bit activation training **diverges** entirely ("No rotation: diverged" in Tables 5, 6, 7) — establishes that distribution reshaping is not a minor optimization but a **necessary condition** for low-bit activation quantization in this architecture.

Furthermore, as the hardware ecosystem moves toward native 4-bit support (the paper specifically cites the NVIDIA GB200), the distinction between "models that can exploit 4-bit compute" and "models that cannot" becomes a real deployment differentiator. A model that achieves the same quality with 4-bit activations versus 8-bit activations effectively delivers ~2× higher throughput on the same hardware in batched scenarios. This is a direct cost and latency advantage that compounds with scale — for large-scale LLM serving, it could mean the difference between needing 8 GPUs versus 4 GPUs to meet a throughput target. The paper's contribution is making that advantage achievable without the quality degradation that naive 4-bit quantization would cause.

## 3. Technical Approach

### 3.1 Reader Orientation

BitNet v2 is a transformer architecture that replaces two specific linear layers in each transformer block with **H-BitLinear**, a module that applies an online Hadamard transformation before activation quantization, enabling the model to be trained end-to-end with weights quantized to ternary values {−1, 0, 1} and **activations quantized natively to 4-bit integers** across all linear layers—something that was previously impossible because outlier channels in intermediate activations would cause catastrophic information loss under 4-bit quantization. The solution is not a new quantization formula but a **pre-processing step**: rotate the activation space so that outlier magnitudes get smeared across dimensions, transforming the distribution from sharp-and-sparse to approximately Gaussian, after which standard per-token quantization functions work without special-case handling for outliers.

### 3.2 Big-Picture Architecture (Diagram in Words)

BitNet v2 inherits the LLaMA-like backbone from prior BitNet variants (RMS normalization, SwishGLU activations, rotary position embeddings, no bias terms) and modifies exactly two types of linear layer in each of the L stacked transformer blocks:

1. **Standard BitLinear layers** (unchanged from BitNet b1.58)—used for the attention input projections Wqkv (queries, keys, values) and the FFN up/gate projections Wup,gate. These layers quantize weights to ternary {−1, 0, 1} using absmean per-tensor quantization, and quantize activations to INT8 or INT4 using per-token absmax (8-bit) or absmean (4-bit) functions.

2. **H-BitLinear layers** (the novel component)—used for the attention output projection Wo and the FFN down projection Wdown. These layers quantize weights identically to BitLinear (ternary via absmean), but **prepend a Hadamard transformation and a layer normalization before activation quantization**. The flow is: input activations → LayerNorm → online Hadamard transform (fast Walsh-Hadamard) → per-token quantization to INT8 or INT4 → matrix multiply with ternary weight matrix.

The Hadamard transformation is applied **only to activations** (not weights) in the final design, based on ablation experiments showing that weight-side rotation provides marginally faster convergence but not better final performance.

**Training pipeline.** All BitNet v2 models follow a two-stage protocol. Stage 1: train from scratch for 95B tokens with INT8 activations and 1.58-bit weights. Stage 2: continue-train (fine-tune) for an additional 5B tokens with INT4 activations, reusing optimizer states from Stage 1. This "8-bit → 4-bit continue-training" approach means only ~5% of the total training budget is spent at the lower precision, which is substantially cheaper than training 4-bit from scratch while achieving comparable results.

### 3.3 Roadmap for the Deep Dive

- **First, the weight quantization scheme**—the ternary {−1, 0, 1} quantization used across all linear layers (both BitLinear and H-BitLinear), because it is a shared foundation that must be understood before we can discuss what is different about H-BitLinear.

- **Second, the activation quantization functions**—per-token absmax (8-bit) and per-token absmean (4-bit), the losses they minimize, and crucially, **why they fail on intermediate activations without transformation**. This diagnosis motivates the entire paper.

- **Third, the Hadamard transformation**—what it is mathematically, how it is computed efficiently using the fast Walsh-Hadamard transform, where it is applied (and where it is not), and **why it reshapes activation distributions into Gaussian-like forms**. This is the core technical contribution.

- **Fourth, H-BitLinear end-to-end**—the complete forward pass through an H-BitLinear layer, including the ordering of LayerNorm → Hadamard → quantize → multiply, and the backward pass (how gradients flow through each component).

- **Fifth, the two-stage training protocol**—why 4-bit training from scratch is possible but the 8-bit → 4-bit continue-training approach is preferred, what "reusing optimizer states" means concretely, and the hyperparameters governing both stages.

- **Sixth, QKV quantization**—how the model handles quantization of attention query, key, and value states (post-RoPE), including the special treatment of the beginning-of-sequence token's KV cache.

This is primarily an **architectural innovation paper** whose core idea is that an online Hadamard transformation applied before activation quantization can reshape outlier-prone intermediate activation distributions into Gaussian-like forms, enabling native 4-bit activations in ternary-weight LLMs without the hybrid quantization/sparsification workarounds required by prior approaches.

#### Ternary Weight Quantization (Shared Across All Linear Layers)

All linear layers in BitNet v2—including both standard BitLinear and H-BitLinear—use the same ternary weight quantization scheme inherited from BitNet and BitNet b1.58. The weights of each weight matrix are constrained to the set {−1, 0, 1}, which requires approximately 1.58 bits per parameter (since log₂(3) ≈ 1.585).

The quantization function for a weight matrix `$W$` is:

$$Q_w(W) = \alpha \cdot \text{RoundClip}\left(\frac{W}{\alpha + \epsilon},\ -1,\ 1\right)$$

where:
- `$\alpha = \text{mean}(|W|)$` is a per-tensor scaling factor (a single scalar computed as the average absolute value of all weights in that matrix),
- `$\epsilon$` is a small constant added for numerical stability (preventing division by zero when all weights are exactly zero),
- `$\text{RoundClip}(X, a, b) = \min(\max(\text{round}(X), a), b)$` rounds each element to the nearest integer and then clamps to the range `$[a, b]$`.

**What it computes, operationally:** For a weight matrix `$W$` of any shape, the function first computes `$\alpha$` as the mean of the absolute values of all entries. It then divides every element of `$W$` by `$\alpha$`, rounds to the nearest integer (−1, 0, or 1), clips values outside [−1, 1] (which shouldn't happen after division by `$\alpha$`, but provides a safety guarantee), and multiplies the resulting ternary matrix by `$\alpha$`. The output `$Q_w(W)$` is a matrix of the same shape as `$W$` containing only the values {−α, 0, +α}. In the forward pass, this ternary matrix is used directly for the matrix multiplication with quantized activations.

**Why this form:** The absmean scaling (`$\alpha = \text{mean}(|W|)$`) is a per-tensor, not per-channel or per-token, quantization. This is deliberately simple: it produces a single scaling factor per weight matrix, which means the ternary values are uniform across the entire matrix, simplifying hardware implementation (no per-channel scaling lookup during inference). Alternative per-channel scaling (computing a separate `$\alpha$` for each row or column) would produce more fine-grained ternary values but would require storing and applying per-channel scale factors during inference, partially defeating the memory savings of ternary weights. The absmean function specifically—rather than absmax—is chosen because it is less sensitive to individual outlier weights: a single unusually large weight does not inflate the scaling factor and suppress all other weights toward zero.

**Gradient handling (straight-through estimator).** The quantization function `$Q_w$` is non-differentiable because of the `$\text{round}$` and `$\text{clip}$` operations. During backpropagation, BitNet v2 uses the straight-through estimator (STE): the gradient is passed through `$Q_w$` as if it were the identity function. That is, `$\frac{\partial L}{\partial W} \approx \frac{\partial L}{\partial Q_w(W)}$`. This means the full-precision "latent" weight (maintained in floating-point throughout training, separate from the quantized weight used in the forward pass) receives gradient updates as if no quantization had occurred, allowing it to be optimized with standard optimizers (AdamW). The latent weight is updated in full precision, and the quantized weight is recomputed from it on every forward pass.

#### Input Activation Quantization: Gaussian-Like Distributions (Wqkv, Wup,gate)

The standard BitLinear layers—used for the attention input projections (Wqkv) and FFN up/gate projections (Wup,gate)—quantize their input activations directly, without any pre-transformation. The paper observes (Figures 2a, 2c, 2e, 2g) that these activations naturally exhibit approximately Gaussian distributions: values are symmetrically distributed around zero with moderate variance and no extreme outlier channels.

For **8-bit activations**, the per-token absmax quantization is:

$$Q_{\text{INT8}}(X) = \frac{\gamma}{127} \cdot \text{RoundClip}\left(\frac{127}{\gamma + \epsilon} X,\ -128,\ 127\right)$$

where:
- `$X$` is the activation tensor (shape: tokens × hidden_dim),
- `$\gamma = \max(|X|)$` is a per-token scalar: for each token (row of `$X$`), `$\gamma$` is the maximum absolute value among that token's hidden dimensions,
- the constants 127 and −128 define the representable integer range of signed INT8.

**What it computes:** For each token independently, find the maximum absolute activation value across all hidden dimensions. Scale the entire token's activation vector so that this maximum value maps to 127 (or −127 for negative), then round to integers and clip to [−128, 127]. The multiplication by `$\gamma/127$` after rounding restores the approximate scale of the original values. The result is an INT8 representation of each activation value with a per-token scaling factor.

For **4-bit activations**, the per-token absmean quantization is:

$$Q_{\text{INT4}}(X) = \frac{\beta}{\sqrt{7}} \cdot \text{RoundClip}\left(\frac{\sqrt{7}}{\beta + \epsilon} X,\ -8,\ 7\right)$$

where:
- `$X$` is the activation tensor,
- `$\beta = \text{mean}(|X|)$` is a per-token scalar: for each token, the average absolute value across hidden dimensions,
- the constants 7 and −8 define the representable integer range of signed INT4.

**Why the switch from absmax to absmean at 4-bit:** The paper does not explicitly justify this choice, but the reasoning follows from quantization theory. At 4 bits (16 representable values), the quantization step size is large relative to the signal range. Using absmax (`$\gamma = \max(|X|)$`) at 4 bits would mean that a single outlier value in a token's activation vector would set the scaling factor and cause most non-outlier values to collapse to zero or ±1 after rounding, losing nearly all information. Absmean (`$\beta = \text{mean}(|X|)$`) is more robust: it sets the scaling factor based on the average magnitude, which is dominated by the bulk of the distribution. Outlier values larger than `$\beta \cdot 8/\sqrt{7}$` get clipped to ±8, but the majority of non-outlier values get preserved with reasonable resolution. This is a fundamental tradeoff: absmax preserves the range (including outliers) at the expense of precision in the bulk; absmean preserves precision in the bulk at the expense of clipping outliers. At 4 bits, preserving the bulk is more important than preserving the tails, because the tails can at most carry information for a small fraction of hidden dimensions.

**Why these quantization schemes work for input activations but fail for intermediate activations.** The input activations (Wqkv, Wup,gate) have approximately Gaussian distributions: the per-channel means and variances are similar, there are no extreme outlier channels, and the dynamic range per token is moderate. For these distributions, per-token quantization—whether absmax at 8-bit or absmean at 4-bit—can represent the full distribution with acceptable error. But intermediate activations (Wo, Wdown) have the opposite property: specific channels consistently produce values 10–100× larger than the median channel, creating a distribution that is simultaneously very sparse (most values near zero) and very heavy-tailed (a few values far from zero). A single per-token scaling factor cannot simultaneously represent both regimes—this is the core problem that H-BitLinear solves.

#### The Hadamard Transformation: Reshaping Activation Distributions

The central technical innovation of BitNet v2 is the application of an **online Hadamard transformation** to activations before quantization, specifically in the layers where outliers are known to occur (Wo and Wdown). The transformation is a linear operation that rotates the activation vector in its hidden dimension, with the effect of "smearing" outlier magnitudes across all dimensions so that the resulting distribution is approximately Gaussian.

**Mathematical definition.** For an activation vector `$X \in \mathbb{R}^n$` where `$n = 2^m$` is a power of two (the hidden dimension is chosen to satisfy this constraint), the Hadamard transformation is:

$$\text{Hadamard}(X) = H_m X$$

where `$H_m$` is the `$2^m \times 2^m$` Hadamard matrix defined recursively:

$$H_m = \frac{1}{\sqrt{2}} \begin{pmatrix} H_{m-1} & H_{m-1} \\ H_{m-1} & -H_{m-1} \end{pmatrix}, \quad H_0 = (1)$$

**What it computes, operationally:** The matrix `$H_m$` is an orthogonal matrix (up to the scaling factor `$1/\sqrt{2^m}$`) whose entries are all `$\pm 1/\sqrt{2^m}$`. The transformation `$H_m X$` computes, for each output dimension, a signed sum of all input dimensions with alternating sign patterns determined by the recursive structure. Because the matrix entries are uniform in magnitude (`$1/\sqrt{2^m}$`), every output dimension is an equally weighted combination of all input dimensions. The consequence is that any single input dimension with an unusually large magnitude contributes only `$1/\sqrt{2^m}$` of its value to each output dimension—its outlier energy is smeared uniformly across the entire transformed vector. Conversely, every output dimension receives equal-magnitude contributions from all input dimensions, so no output dimension can be an outlier unless the entire input vector had extreme energy, which doesn't happen for per-token normalized activations.

**Why this works to remove outliers.** Consider a token's activation vector where channel `$i$` has value 100 and all other `$n-1$` channels have values near 0. After the Hadamard transformation, channel `$i$`'s contribution to output channel `$j$` is `$H_{j,i} \cdot 100 = \pm 100/\sqrt{n}$`. For `$n = 4096$` (a typical hidden dimension), this is approximately `$\pm 1.56$`. The rest of the approximately-zero channels contribute negligible amounts. So every output channel has magnitude roughly `$1.56$` rather than one channel having magnitude 100 and the rest having magnitude 0. The dynamic range of the transformed vector is dramatically compressed, eliminating the quantization challenge.

The scaling factor `$1/\sqrt{2}$` in the recursive definition ensures that `$H_m$` is an orthogonal matrix (specifically, `$H_m^T H_m = I$`), making the transformation norm-preserving: `$\|H_m X\| = \|X\|$`. This is critical because it means the transformation does not change the information content or energy of the activations—it only redistributes that energy across dimensions to make the distribution more uniform.

**The online Hadamard transform and the power-of-two constraint.** The paper uses the "online" qualifier to indicate that the Hadamard transformation is applied during every forward pass (it is part of the model's computation graph, not a one-time pre-processing of weights). The transformation itself has `$O(n \log n)$` computational complexity using the fast Walsh-Hadamard transform (FWHT) algorithm referenced in the paper (the `fast-hadamard-transform` library from Dao-AILab). The `$n \log n$` complexity means the overhead scales sub-quadratically with hidden dimension, making it acceptable as an online operation even at scale.

The constraint that the hidden dimension must be a power of two (`$n = 2^m$`) is inherent to the Hadamard matrix construction. The paper does not discuss what happens if the hidden dimension is not a power of two—presumably the architecture is designed to use hidden dimensions that satisfy this constraint (the paper's model configurations in Table 8 show hidden sizes 1024, 2048, 4096, all powers of two).

**Layer normalization before Hadamard.** In H-BitLinear, the Hadamard transformation is preceded by a Layer Normalization:

$$X_r = \text{Hadamard}(\text{LN}(X))$$

The LN step normalizes each token's activation vector to have zero mean and unit variance (or approximately so, depending on the LN variant—the paper uses RMSNorm). This normalization is important because the Hadamard transformation, while norm-preserving, does not change the total energy of the vector. If the input already has extreme energy (which can happen without normalization), then after Hadamard the energy is uniformly distributed but still large, and the quantization will still have to accommodate a wide dynamic range. LN ensures that the vector entering the Hadamard transformation has controlled scale, so the transformed vector also has controlled scale before quantization.

**Where the Hadamard transformation is applied (and where it is not).** H-BitLinear replaces the standard BitLinear **only** for the attention output projection Wo and the FFN down projection Wdown. These are precisely the layers whose input activations (the intermediate states) exhibit the outlier problem (Figures 2b, 2d, 3a, 3c). The attention input projections (Wqkv) and FFN up/gate projections (Wup,gate) continue to use standard BitLinear without Hadamard transformation, because their input activations are already approximately Gaussian (Figures 2a, 2c).

This is a deliberately minimal design choice. If the Hadamard transformation were applied universally, it would add unnecessary computation to layers that don't need it. The paper's ablation study (Table 5, "Activation rotation" vs. "Weight & activation rotation") further shows that applying the rotation to weights as well as activations does not improve final performance—it may speed up convergence but is not necessary.

---

#### H-BitLinear: The Complete Layer

Putting the pieces together, the forward pass through an H-BitLinear layer for a weight matrix `$W$` and input activations `$X$` is:

$$Y = Q_w(W) \cdot Q_{\text{INT8/4}}(X_r), \quad X_r = \text{Hadamard}(\text{LN}(X))$$

where:
- `$X$` is the input activation tensor (shape: tokens × `$d_{\text{in}}$`),
- `$\text{LN}$` is layer normalization (RMSNorm in BitNet v2),
- `$\text{Hadamard}$` is the fast Walsh-Hadamard transform applied along the hidden dimension,
- `$X_r$` is the rotated activation tensor,
- `$Q_{\text{INT8/4}}$` is per-token absmax (8-bit) or absmean (4-bit) quantization,
- `$Q_w(W)$` is the ternary weight quantization (Equation 1),
- `$Y$` is the output tensor.

**Operational sequence, step by step:**

1. **Receive activations** `$X$` from the previous sublayer (for Wo: from the attention head outputs; for Wdown: from the SwishGLU gating output).

2. **Apply RMSNorm:** Normalize each token's activation vector to control its scale before the Hadamard rotation. This is a per-token operation: for each token's vector, compute the root-mean-square, divide the vector by it, and multiply by a learned scale parameter.

3. **Apply Hadamard transformation:** For each token in the batch, compute `$\text{Hadamard}(X_{\text{normed}})$` using the fast Walsh-Hadamard transform. This smears outlier energy across dimensions. The output `$X_r$` has the same shape as the input but with an approximately Gaussian distribution.

4. **Quantize rotated activations:** Apply per-token absmax (INT8) or absmean (INT4) to `$X_r$`. Because `$X_r$` is now Gaussian-like, per-token quantization works without the outlier-induced information loss that would occur without step 3. The output is an integer tensor with a per-token scale factor.

5. **Quantize weights:** Compute `$Q_w(W)$`, the ternary weight matrix, using per-tensor absmean.

6. **Matrix multiply:** Compute `$Y = Q_w(W) \cdot Q_a(X_r)$`. Because both operands are quantized (weights to {−α, 0, +α}, activations to INT8 or INT4), this multiplication can be implemented using integer arithmetic on hardware that supports it—no floating-point operations are needed in the forward pass (except the scaling factors, which can be applied separately).

**Backward pass.** The backward pass must propagate gradients through three non-differentiable operations: activation quantization, Hadamard transformation (which is differentiable, but the gradient needs to flow correctly), and weight quantization.

For activation quantization (`$Q_a$`): the straight-through estimator is used, treating `$\frac{\partial L}{\partial X_r} \approx \frac{\partial L}{\partial Q_a(X_r)}$`.

For the Hadamard transformation: since `$H_m$` is an orthogonal matrix (`$H_m^T = H_m^{-1}$`), the gradient with respect to the input is:

$$\frac{\partial L}{\partial X} = \text{Hadamard}\left(\frac{\partial L}{\partial \text{Hadamard}(X)}\right)$$

That is, the gradient is simply the Hadamard transformation applied to the incoming gradient—the transformation is its own inverse (up to scaling). This means the backward pass through the Hadamard transformation has the same `$O(n \log n)$` cost as the forward pass.

For weight quantization: the straight-through estimator passes the gradient directly to the latent full-precision weight.

**Why H-BitLinear, not just "quantize after Hadamard anywhere."** The Hadamard transformation is integrated specifically into the linear layer rather than being applied as a separate preprocessing step for several reasons. First, it is an online operation, meaning the transformation changes as the activations change during training—it is not a fixed rotation learned offline. Second, by placing the Hadamard transformation inside the layer and after LayerNorm, the normalization ensures consistent input statistics to the Hadamard, which prevents the transformation from having to adapt to shifting activation scales during training. Third, the backward pass through the Hadamard (Equation 8) is efficiently computable using the same FWHT algorithm, keeping the training overhead manageable.

#### The Two-Stage Training Protocol: 8-Bit → 4-Bit Continue-Training

BitNet v2 is not trained with 4-bit activations from scratch. Instead, the paper uses a two-stage protocol:

**Stage 1 (95B tokens):** Train BitNet v2 with 1.58-bit weights and **INT8 activations** from scratch on 100B total tokens (but the first 95B use INT8). All H-BitLinear layers use `$Q_{\text{INT8}}$` for activation quantization. The optimizer (AdamW) accumulates full-precision latent weights and standard momentum/variance states.

**Stage 2 (5B tokens):** Continue training with **INT4 activations** for the final 5B tokens. All H-BitLinear layers switch to `$Q_{\text{INT4}}$`. Critically, the optimizer states from Stage 1 are **reused** rather than reset—the momentum and variance buffers continue from their Stage 1 values rather than starting fresh.

**Why this two-stage approach instead of 4-bit from scratch.** The paper states (Section 2.2):

> "Similar to BitNet a4.8, BitNet v2 with 4-bit activations can be continue-trained from its 8-bit activation counterpart using a small number of training tokens, while incurring negligible performance loss."

The rationale is practical: training with 4-bit activations from scratch is possible (the model does not diverge if the Hadamard transformation is present), but it converges more slowly and may settle at a slightly worse optimum. Starting from an 8-bit trained model provides a good initialization that is already near a good solution; the 5B tokens of 4-bit fine-tuning adapt the model to the noisier quantization regime. Because only 5B out of 100B tokens (5%) use 4-bit training, the total training cost is only marginally higher than training an 8-bit model alone.

**What "reusing optimizer states" means concretely.** The AdamW optimizer maintains, for each parameter, a first-moment estimate `$m$` (exponential moving average of gradients) and a second-moment estimate `$v$` (exponential moving average of squared gradients). These states encode information about the recent gradient history. When switching from 8-bit to 4-bit activations, the loss surface changes (4-bit quantization introduces different noise patterns), but the parameter values are close to a good solution. Resetting the optimizer states would discard the gradient history that got the model there, potentially causing instability as the optimizer adapts to the new loss surface from scratch. By keeping `$m$` and `$v$`, the optimizer retains its "momentum" and continues smoothly, adapting to the new quantization noise without the large initial transients that a fresh optimizer would cause.

**Hyperparameters (Table 9).** All model sizes use the same training hyperparameter family with size-dependent learning rates:

| Model Size | Learning Rate Scheme | Weight Decay | Warmup Steps | Adam β |
|---|---|---|---|---|
| 400M | 1.8 × 10⁻³ → 1.2 × 10⁻³ | 0.1 → 0 | 375 | (0.9, 0.95) |
| 1.3B | 1.2 × 10⁻³ → 8 × 10⁻⁴ | 0.1 → 0 | 375 | (0.9, 0.95) |
| 3B | 1.2 × 10⁻³ → 6.4 × 10⁻⁴ | 0.1 → 0 | 375 | (0.9, 0.95) |
| 7B | 1 × 10⁻³ → 6 × 10⁻⁴ | 0.1 → 0 | 375 | (0.9, 0.95) |

The learning rate follows a two-stage schedule: a higher initial learning rate that decays to a lower final learning rate (the `→` notation in the table). Weight decay follows the same two-stage pattern: start at 0.1 and decay to 0. This is the "two-stage weight decay and learning rate scheduling" inherited from BitNet b1.58. All models use batch size 1M tokens (Table 8), sequence length 2048, and are trained for 100B total tokens from the RedPajama dataset.

#### QKV Quantization for Low-Bit Attention

Beyond the linear layers, BitNet v2 also quantizes the **query, key, and value states** in attention to reduce the memory footprint of the KV cache during inference. The paper reports results with several configurations (Tables 2 and 3): 4-bit KV cache, 4-bit QKV, and 4-bit Q with 3-bit KV.

**Quantization method.** QKV states are quantized **post-RoPE** (after rotary position embedding is applied) using per-token absmax (the absmax function maps to unsigned integers—the paper does not provide the exact formula, but the standard approach maps to [0, 2ᵇ − 1] for unsigned b-bit integers). The paper states:

> "We adopt post-RoPE quantization for QKV states. The QKV heads were directly quantized to unsigned integers using the absmax function, without the need of any calibration dataset."

The post-RoPE placement is important: the rotary position embedding applies a rotation to the query and key vectors that encodes positional information. If quantization were applied before RoPE, the rotation would destroy any structure the quantizer was exploiting. By quantizing after RoPE, the quantization operates on the position-aware representations directly.

**Special treatment of the BOS token.** The paper notes a specific implementation detail:

> "We retain the KV heads of [BOS] token as 8-bit precision."

The beginning-of-sequence (BOS) token's key and value vectors are kept at higher precision (8-bit rather than 4-bit or 3-bit). The rationale is not explicitly stated, but this is a common practice in KV cache quantization: the first token often serves as an "attention sink"—it accumulates a disproportionate amount of attention weight across all subsequent tokens, and quantization errors in its representation can propagate through the entire sequence. Keeping it at higher precision is a low-cost way to prevent this error propagation (one token out of potentially thousands, so the additional memory cost is negligible).

**Results.** Tables 2 and 3 show that 4-bit KV cache quantization causes minimal accuracy degradation: for the 7B BitNet v2 (a8) model, 4-bit KV drops average accuracy from 58.73% to 58.71% (a 0.02 percentage point difference). Even the most aggressive configuration—4-bit Q, 3-bit KV—maintains 58.13% for the 7B a8 model, a loss of only 0.60 percentage points. This demonstrates that the Hadamard-smoothed activation distributions are amenable to aggressive quantization even in the attention mechanism, though the attention QKV states are not themselves processed through H-BitLinear—the outlier suppression in the preceding feed-forward and attention output layers may indirectly normalize the statistics flowing into the next layer's attention inputs.

#### Ablation: Where to Apply the Hadamard Transformation

The paper's ablation study (Tables 5, 6, 7) evaluates three configurations of the Hadamard transformation:

1. **No rotation** — standard BitLinear everywhere. Labeled "No rotation."
2. **Weight and activation rotation** — apply Hadamard to both the weight matrix and the activations. Labeled "Weight & activation rotation."
3. **Activation rotation only** — apply Hadamard only to the activations. Labeled "Activation rotation." This is the final H-BitLinear design.

The results are decisive. With no rotation, all models **diverge** when trained with 4-bit activations (Table 5, "No rotation" + "W1.58A4": "diverged"). This is the key finding that motivates the entire paper: without the Hadamard transformation, 4-bit activation training is not just suboptimal—it is impossible. The outlier channels cause such severe quantization error that the training signal is destroyed.

With weight and activation rotation, the model trains stably and achieves performance close to the activation-only rotation. For the 1.3B model with INT8 activations (Table 6): weight+activation rotation achieves 50.47% average accuracy vs. 51.17% for activation-only rotation. For the 3B model at INT4 (Table 7): 54.98% vs. 55.43%. The paper notes that weight+activation rotation shows "faster convergence" but "achieves similar performance to applying it only to the activations as training progresses." The final choice—applying Hadamard only to activations—is justified by simplicity: it achieves equivalent final performance with fewer operations, since the weight-side rotation would require either fusing the rotation into the weight quantization (which is problematic for ternary models, as Section 3.2 demonstrates) or applying it online during every forward pass (adding unnecessary computation).

## 4. Key Insights and Innovations

### Innovation 1: Activation Outlier Removal via Runtime Distribution Reshaping, Not Selective Precision

The dominant approach to handling activation outliers in low-bit LLMs has been **selective precision**: identify the problematic layers or channels and treat them differently from the well-behaved ones. BitNet a4.8 exemplifies this strategy—it uses 4-bit quantization for "easy" input activations but falls back to 8-bit sparsification for the outlier-heavy intermediate states. QuaRot and SpinQuant, while using rotations, apply them as a one-time post-training transformation to make the entire model amenable to uniform quantization.

BitNet v2 makes a fundamentally different conceptual move: **don't special-case the outliers—eliminate them**. Rather than accepting that some activations are inherently harder to quantize and routing them to higher-precision paths, H-BitLinear changes the distribution itself so that *all* activations become easy to quantize. The Hadamard transformation smears outlier energy uniformly across all dimensions, converting the problematic sharp-and-sparse distribution into an approximately Gaussian one—at which point the *same* per-token quantization functions that work for input activations also work for the intermediate states.

This is a diagnostic reframing, not just an architectural improvement. Prior work implicitly treated activation outliers as a *property of specific layers* that must be accommodated. BitNet v2 treats them as a *property of the coordinate system* that can be rotated away. The distinction matters because it suggests a different design philosophy: instead of building heterogeneous quantization pipelines with different rules for different layers (complexity that propagates into hardware kernels and compiler passes), build a homogeneous pipeline where every linear layer uses the same quantization primitives, and add targeted rotations only where the coordinate system needs fixing.

The evidence that this conceptual move is necessary, not merely helpful, comes from the ablation in Table 5: without any rotation, 4-bit training **diverges entirely**. This is not a case where the model trains suboptimally—it fails catastrophically. The Hadamard transformation is therefore established as a **necessary condition** for native 4-bit activations in ternary-weight LLMs, not an optional optimization.

Compared to QuaRot and SpinQuant—which also use rotations to address outliers—BitNet v2's approach differs in an important way: the rotation is **online** (part of every forward pass) and **training-aware** (integrated into the training dynamics from scratch), rather than a post-training fix applied to a frozen model. The paper demonstrates (Table 4) that post-training rotation approaches fall apart when applied to ternary-weight models (perplexity degrades from ~11 to ~20), establishing that the training-aware integration is essential in the 1-bit regime even though post-training rotation works acceptably for full-precision models. This finding clarifies a boundary condition: rotation-based outlier suppression transfers across precision regimes, but *how* the rotation is integrated (training-aware vs. post-hoc) matters critically when weights are already in extreme low-bit formats.

---

### Innovation 2: Establishing That the Intermediate State Outlier Problem in 1-Bit LLMs Is Solvable Without Sparsity

Prior to BitNet v2, the state of the art for sub-8-bit activation quantization in 1.58-bit LLMs was BitNet a4.8, which achieved 4-bit activations only through a **hybrid scheme**: 4-bit for input projections, but 8-bit sparsification (top-K, with squared ReLU) for the intermediate states. This hybrid approach was effective—performance loss was minimal—but it left an open question: **is dense 4-bit activation computation fundamentally incompatible with the outlier structure of intermediate states, or was the hybrid approach just the first viable solution found?**

BitNet v2 answers this question definitively. By showing that dense 4-bit activations across *all* linear layers achieve comparable performance to the hybrid BitNet a4.8 (Table 1: 3B BitNet v2 a4 at 55.43% average vs. 55.19% for BitNet a4.8; 7B at 58.30% vs. 57.91%), the paper establishes that **sparsity is not required**. The bottleneck was never intrinsic to the information content of the activations—it was an artifact of the coordinate representation. Change the representation, and dense quantization becomes viable.

This is significant as a **negative result about hybrid approaches** rather than a positive result about BitNet v2 specifically. The paper argues (Section 1) that sparsification is "less suited for maximizing throughput in batched inference, where dense computations are often preferred for hardware efficiency." This is not a theoretical claim—it reflects the reality of GPU tensor core design, where sparse computation requires either hardware support for specific sparsity patterns (e.g., NVIDIA's 2:4 structured sparsity) or incurs overhead from irregular memory access. Dense 4-bit matrix multiplication maps cleanly onto existing and upcoming hardware primitives; sparse 8-bit does not. By solving the outlier problem directly, BitNet v2 enables a deployment path (dense 4-bit) that BitNet a4.8's hybrid approach could not offer, even though both achieve similar model quality.

This innovation should be understood as **changing the problem statement**. Before BitNet v2, the question was "how do we work around the intermediate state outlier problem?" (answer: hybrid precision/sparsity). After BitNet v2, the question becomes "how do we remove the outlier structure so the problem doesn't arise?" (answer: coordinate rotation). The second framing is more powerful because it generalizes: any layer with outlier channels can potentially be fixed with a rotation rather than requiring a custom quantization scheme. The paper only demonstrates this for Wo and Wdown, but the principle is broader.

---

### Innovation 3: The "8-Bit → 4-Bit Continue-Training" Protocol as a Practical Efficiency Insight

At first glance, training a model with 8-bit activations for 95B tokens and then continue-training with 4-bit activations for only 5B tokens appears to be an implementation detail. It is not—it represents a **practical insight about quantization-aware training dynamics** that could influence how low-bit models are developed more broadly.

The standard assumption in quantization-aware training is that the target bit-width should be used throughout training so the model learns to be robust to quantization noise from the beginning. BitNet v2 challenges this assumption by showing that the model only needs a small fraction of its total training budget (5%) at the target 4-bit precision to adapt, provided it has been well-initialized from the 8-bit model. This is not just a training cost savings (though that matters—5% of 100B tokens is 5B tokens saved versus training 4-bit from scratch for the full 100B). It is a statement about **the relationship between precision and optimization**: the optimization landscape at 8-bit appears to be a good proxy for the landscape at 4-bit once outliers are handled, such that the model can find a good region in the higher-precision space and then fine-tune locally in the lower-precision space.

The "reusing optimizer states" detail reinforces this interpretation. If the 4-bit loss surface were fundamentally different from the 8-bit surface, the momentum and variance estimates from 8-bit training would be misleading—they encode gradient history from a different optimization problem. That reusing them works well (the paper reports "negligible performance loss") suggests that the two loss surfaces are sufficiently similar that the optimizer's accumulated knowledge transfers. This has implications beyond BitNet: it suggests that for any quantization-aware training pipeline, a "train at higher precision, fine-tune at target precision" strategy may be generally efficient, provided outlier structures are addressed.

The comparison to BitNet a4.8, which used the same continue-training protocol, shows that this insight is not unique to the Hadamard approach—it works with hybrid quantization too. But BitNet v2 validates the principle in the more challenging regime of *dense* 4-bit activations, where the quantization noise is more severe (no sparsification safety net for intermediate states). That the continue-training approach still works under these harsher conditions strengthens the generality of the insight.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** All models are trained on 100B tokens from the RedPajama dataset (Together Computer, 2023) using sequence length 2048 and batch size 1M tokens (Table 8). Evaluation uses the C4 validation set (Raffel et al., 2019) for perplexity and a suite of six zero-shot language understanding benchmarks via the `lm-evaluation-harness` toolkit (Gao et al., 2024): ARC-Easy, ARC-Challenge (Yadav et al., 2019), HellaSwag (Zellers et al., 2019), PIQA (Bisk et al., 2019), Winogrande (Sakaguchi et al., 2020), and LAMBADA (Paperno et al., 2016).

- **Base models.** All experiments use the BitNet family of ternary-weight transformers (Wang et al., 2023; Ma et al., 2024) with LLaMA-like components: RMSNorm (Zhang and Sennrich, 2019), SwishGLU (Shazeer, 2020), rotary position embeddings, and no bias terms. Four model sizes are evaluated: 400M, 1.3B, 3B, and 7B parameters (Table 8). Models are trained from scratch with 1.58-bit weights (ternary quantization using per-tensor absmean) and INT8 activations for the first 95B tokens, then continue-trained with INT4 activations for the final 5B tokens.

- **Metrics.** Two classes of metric are reported. **Perplexity (PPL)** is computed on the C4 validation set—lower is better. **Zero-shot accuracy** is computed separately for each of the six benchmark tasks, with an "Avg" column reporting the arithmetic mean across all six tasks (each task equally weighted). For the QKV quantization experiments (Tables 2–3), the same zero-shot accuracy suite is used, and the average across tasks is reported identically.

- **Baselines.** Three primary baselines are compared throughout:
  - **BitNet b1.58** (Ma et al., 2024): Ternary weights with fully INT8 activations across all linear layers. This is the "upper bound" for what BitNet v2 should match at 8-bit precision.
  - **BitNet a4.8** (Wang, Ma, and Wei, 2024): Ternary weights with hybrid activation quantization—4-bit for input activations (Wqkv, Wup,gate) and 8-bit sparsification for intermediate states (Wo, Wdown). This is the prior state-of-the-art for sub-8-bit activations.
  - **Post-training quantization baselines** (Section 3.2, Table 4 only): QuaRot (Ashkboos et al., 2024) and SpinQuant (Liu et al., 2024), both using rotation-based outlier suppression followed by GPTQ weight quantization and per-token absmax activation quantization to 4-bit, applied to BitNet b1.58 models as a post-training step.

- **Generation budget / compute accounting.** All models are trained with matched training budgets: 100B total tokens from RedPajama with identical batch size (1M tokens) and sequence length (2048) across all model sizes and variants (Tables 8–9). For the continue-training phase (BitNet v2 a4 and BitNet a4.8), the total remains 100B tokens—95B at INT8, 5B at INT4. This is a compute-matched, not token-matched, comparison since the INT4 forward pass is computationally cheaper than INT8; the paper does not normalize for this and instead treats the 100B token budget as the controlled variable across all runs.

- **Cross-validation / statistical protocol.** The paper does not report any cross-validation or statistical significance testing. All results in Tables 1–7 are single-run evaluations on the standard test sets for each benchmark (using `lm-evaluation-harness` defaults). The spin-quant baseline tuning (Section 3.2) uses 800 calibration samples from WikiText-2, but this is calibration data for the rotation, not cross-validation of final metrics.

### Main Quantitative Results

#### 8-Bit Activation Results: Matching BitNet b1.58 with H-BitLinear

The paper first establishes that introducing the Hadamard transformation does not degrade model quality when activations remain at 8-bit precision—in fact, it slightly improves performance. Table 1 reports the headline comparison:

**At the 1.3B scale:** BitNet v2 (a8) achieves 51.17% average zero-shot accuracy compared to 51.01% for BitNet b1.58 (+0.16 percentage points) and 50.90% for BitNet a4.8. Perplexity is 11.14 for both BitNet v2 (a8) and BitNet b1.58 (11.14 vs. 11.02—a negligible difference).

**At the 3B scale:** BitNet v2 (a8) achieves 55.71% average accuracy, outperforming BitNet b1.58 at 55.22% (+0.49 points) and BitNet a4.8 at 55.19% (+0.52 points). Perplexity is 9.72 vs. 9.71 for BitNet b1.58.

**At the 7B scale:** BitNet v2 (a8) achieves 58.73% average accuracy, compared to 58.12% for BitNet b1.58 (+0.61 points) and 57.91% for BitNet a4.8 (+0.82 points). Perplexity is 9.14 vs. 9.09 for BitNet b1.58.

The pattern across scales is consistent: H-BitLinear with 8-bit activations performs at parity or slightly better than standard BitLinear. The per-task breakdown (Table 1 columns ARCc through LBA) shows no systematic weakness—BitNet v2 (a8) outperforms BitNet b1.58 on most tasks at most scales, with ARCe, ARCc, and LAMBADA showing particularly consistent gains (e.g., 3B: ARCc 30.55 vs. 28.84; 7B: LAMBADA 64.22 vs. 61.63). This is a critical result because it establishes that the Hadamard transformation imposes no quality penalty even when operating at the same bit-width. The activation distribution reshaping (Figures 2–3) costs nothing in terms of model expressivity.

#### 4-Bit Activation Results: Dense 4-Bit Matches Hybrid Sparsification

The central claim of the paper is that native 4-bit activations can match the prior hybrid approach. Table 1 confirms this:

**At the 3B scale:** BitNet v2 (a4) achieves 55.43% average accuracy with perplexity 9.85, compared to 55.19% for BitNet a4.8 (+0.24 points) and 55.71% for the 8-bit version (−0.28 points from the a8 model). The degradation from 8-bit to 4-bit is only 0.28 average accuracy points and 0.13 perplexity points.

**At the 7B scale:** BitNet v2 (a4) achieves 58.30% average accuracy with perplexity 9.24, compared to 57.91% for BitNet a4.8 (+0.39 points) and 58.73% for the 8-bit version (−0.43 points). Again, the 4-bit degradation is modest.

**At the 1.3B scale:** BitNet v2 (a4) achieves 50.41% average accuracy with perplexity 11.33, compared to 50.90% for BitNet a4.8 (−0.49 points). This is the only scale where BitNet v2 (a4) slightly underperforms BitNet a4.8, though the difference is under half a percentage point on average accuracy.

The per-task pattern is informative. At the 3B scale, BitNet v2 (a4) outperforms BitNet a4.8 on 4 of 6 tasks (ARCe: 55.01 vs. 55.01—tied; HS: 56.59 vs. 55.92; WGe: 59.67 vs. 59.59; LBA: 60.74 vs. 59.85) while slightly underperforming on ARCc (28.92 vs. 29.01) and PQ (71.65 vs. 71.76). At the 7B scale, BitNet v2 (a4) leads on 3 of 6 tasks and trails on 3, with the largest gaps being ARCc (32.42 vs. 31.91 for a4.8) and WGe (60.85 vs. 59.67). There is no task where BitNet v2 (a4) catastrophically underperforms BitNet a4.8, confirming that the dense 4-bit approach does not have systematic weaknesses on any particular reasoning or language understanding category.

Comparing 4-bit to 8-bit within BitNet v2 shows a clear but small degradation. At 3B, the drop is noticeable on HellaSwag (57.19 → 56.59, −0.60) and LAMBADA (60.90 → 60.74, −0.16); at 7B, the largest drops are on ARCc (32.94 → 32.42, −0.52) and ARCe (58.54 → 58.00, −0.54). No task loses more than 1 point of accuracy when dropping from 8-bit to 4-bit activations, and some tasks show essentially no degradation (7B PQ: 74.10 → 74.27, +0.17; 7B HS: 61.08 → 60.71, −0.37). This demonstrates that the Hadamard transformation effectively preserves the information needed for downstream task performance under aggressive 4-bit quantization.

#### Comparison with Post-Training Quantization (Table 4)

Table 4 presents the most dramatic evidence for the advantage of training-aware quantization over post-training methods in the ternary weight regime. All models compared are 1.3B with 1.58-bit weights and 4-bit activations.

**BitNet v2 (a4) achieves perplexity 11.33** on the C4 validation set and 50.41% average accuracy.

**QuaRot applied to BitNet b1.58:** With fusion of the rotary matrix into the weight matrix (the standard QuaRot approach), perplexity is **20.83** and average accuracy drops to 42.53%. Removing rotary matrix fusion (so weights operate at full precision, W16A4) improves perplexity to **13.52** and accuracy to 46.55%, but this is still far behind BitNet v2 (a4)—a 2.19 perplexity gap and 3.86 accuracy point gap. Furthermore, as the paper notes, removing fusion "forces these projections to revert to full precision (W16A4), thus sacrificing inference efficiency"—the weight memory savings of ternary quantization are lost, and only activations remain quantized.

**SpinQuant applied to BitNet b1.58:** The pattern is identical. With rotary fusion, perplexity is **19.80** and accuracy is 43.29%. Without fusion, perplexity improves to **13.52** and accuracy to 46.79%, but still substantially underperforms BitNet v2 (a4). The SpinQuant configuration was tuned with 800 WikiText-2 calibration samples, representing the best-case post-training rotation.

The convergence of these baselines at perplexity 13.52 (both QuaRot and SpinQuant without fusion) suggests there is a floor on what post-training rotation can achieve on ternary-weight models—approximately 2.2 perplexity points worse than the training-aware approach. This floor likely arises because the weight-rotation interaction (fusing rotation into ternary weights) is fundamentally problematic, and decoupling them sacrifices the weight efficiency that motivates 1-bit models in the first place. Either way, post-training methods fail to achieve competitive results, confirming that the Hadamard transformation must be integrated during training.

#### QKV Cache Quantization (Tables 2–3)

Tables 2 and 3 explore how aggressively the attention mechanism's internal states can be quantized once the model already uses H-BitLinear. These experiments take the already-trained BitNet v2 (a8) and BitNet v2 (a4) models and further quantize the query, key, and value states post-RoPE using unsigned integer absmax quantization, with no additional training or calibration.

**For the 8-bit activation model (Table 2):**
- **3B:** 4-bit KV cache yields 55.37% average accuracy vs. 55.71% baseline (−0.34 points). Adding 4-bit Q as well yields 55.60% (−0.11 points). The most aggressive configuration (4-bit Q, 3-bit KV) yields 54.88% (−0.83 points).
- **7B:** 4-bit KV yields 58.71% vs. 58.73% baseline (−0.02 points). 4-bit QKV yields 58.51% (−0.22 points). 4-bit Q, 3-bit KV yields 58.13% (−0.60 points).

**For the 4-bit activation model (Table 3):**
- **3B:** 4-bit KV yields 55.02% vs. 55.43% baseline (−0.41 points). 4-bit QKV yields 55.02% (−0.41). 4-bit Q, 3-bit KV yields 55.02% (−0.41)—all three configurations land at identical average accuracy.
- **7B:** 4-bit KV yields 58.38% vs. 58.30% baseline (+0.08 points, slightly better). 4-bit QKV yields 58.33% (+0.03). 4-bit Q, 3-bit KV yields 57.69% (−0.61).

The remarkable finding is how little degradation occurs. The 7B model with 8-bit activations loses only 0.02 points of average accuracy when KV cache is quantized to 4 bits—essentially within measurement noise. Even the most aggressive 4-bit Q/3-bit KV configuration at 7B loses only 0.60 points from the 8-bit activation baseline, and only 0.61 points from the 4-bit activation baseline. At 3B, the maximum loss is 0.83 points from the 8-bit baseline. These are exceptionally small penalties for memory savings that reduce KV cache size by 50–67%.

The paper notes a specific implementation detail that likely contributes to this robustness: the KV heads of the [BOS] token are retained at 8-bit precision regardless of the quantization scheme. Since early tokens in the sequence can accumulate disproportionately large attention weights (acting as "attention sinks"), preserving their representation at higher precision prevents a single badly-quantized token from degrading the entire sequence's attention computation.

### Ablation Studies and Robustness Checks

**Hadamard transformation placement (Tables 5, 6, 7):** The ablation tests three configurations: no rotation, rotation of both weights and activations, and rotation of activations only (the final H-BitLinear design). The finding is stark:
- With **no rotation** at all, 4-bit activation training **diverges entirely** (Table 5, "No rotation" + "W1.58A4": "diverged" for both 1.3B and 3B). This is not a case of suboptimal convergence but complete training failure, establishing the Hadamard transformation as a necessary condition.
- **Weight & activation rotation** achieves performance close to activation-only rotation: at 1.3B/INT8 (Table 6), 50.47% vs. 51.17% accuracy; at 3B/INT8, 55.54% vs. 55.71%; at 3B/INT4 (Table 7), 54.98% vs. 55.43%. Weight+activation rotation shows slightly faster convergence but equivalent final performance, so the simpler activation-only scheme is chosen.

**Model scale sensitivity (Table 1, across columns):** The benefit of BitNet v2 over BitNet b1.58 grows monotonically with scale for 8-bit activations: +0.16% at 1.3B, +0.49% at 3B, +0.61% at 7B. This suggests the Hadamard transformation's benefit is not just a small-model phenomenon—it scales favorably, possibly because outlier channels become more pronounced in larger models and the smoothing effect becomes more valuable. For 4-bit activations, the pattern relative to BitNet a4.8 is less smooth (+0.24 at 3B, +0.39 at 7B) but still positive at the two largest scales.

**Task-level consistency (Table 1, per-task columns):** No individual task drives the average accuracy improvements. BitNet v2 (a8) outperforms BitNet b1.58 on:
- 1.3B: 4 of 6 tasks (ARCc: 23.29 vs. 24.32—actually slightly worse; ARCe, PQ, WGe, LBA better; HS slightly worse)
- 3B: 5 of 6 tasks (all except PQ: 71.33 vs. 71.44)
- 7B: 4 of 6 tasks (ARCc, PQ, WGe, LBA better; ARCe 59.51 → 58.54; HS 61.49 → 61.08)

The tasks where BitNet v2 sometimes lags (ARC-Challenge, HellaSwag) do not form a coherent category, suggesting minor run-to-run variation rather than a systematic weakness.

**Scaling behavior of the 4-bit degradation (Table 1):** The gap between BitNet v2 (a8) and (a4) shrinks as models grow: -0.38 points at 400M (44.33 → 43.95), -0.76 at 1.3B, -0.28 at 3B, -0.43 at 7B. There is no consistent trend toward better or worse 4-bit tolerance with scale—the 1.3B model shows the largest gap, but this may be an artifact of that particular run given the adjacent scales show smaller degradation.

### Critical Assessment

#### Does the evidence support the claim that BitNet v2 with 8-bit activations matches BitNet b1.58 performance?

Yes—and in fact the evidence shows slight but consistent improvement rather than mere parity. At 1.3B, 3B, and 7B scales (Table 1), BitNet v2 (a8) achieves equal or lower perplexity (11.14 vs. 11.02 at 1.3B is essentially identical; the difference is within 0.03 across all scales) and 0.16–0.61 percentage point higher average accuracy. The improvement appears across three out of four model sizes (400M is the exception: 44.33 vs. 44.87, slightly worse). The paper is actually underclaiming here—"matches BitNet b1.58" understates the consistent small advantage. However, the improvement is small enough that it could plausibly be within the variance of single-run training, and without multiple seeds or statistical testing, the claim that these differences are meaningful (rather than noise) is unsupported. The safer interpretation is "BitNet v2 with 8-bit activations achieves parity with BitNet b1.58," which the data clearly support.

#### Does the evidence support the claim that BitNet v2 achieves minimal performance degradation when trained with native 4-bit activations?

Yes, but with an important qualification about what "minimal" means. At 3B, the degradation from 8-bit to 4-bit is 0.28 average accuracy points and 0.13 perplexity points (Table 1). At 7B, it is 0.43 points and 0.10 perplexity points. These are indeed small—they compare favorably to the 8-bit vs. 4-bit gaps seen in prior work, and they are small enough that the throughput gains from 4-bit compute would almost certainly dominate in a cost-benefit analysis.

However, the 1.3B model shows a larger gap (0.76 points, from 51.17 to 50.41) and the 400M model shows a 0.38 point gap (44.33 to 43.95). These are still modest in absolute terms but represent a meaningful fraction of the total accuracy at these smaller scales. The paper does not discuss what "minimal" means in context or establish a quantitative threshold. A skeptical reader could note that a 0.76 point drop at 1.3B represents roughly 1.5% relative accuracy degradation—whether this is "minimal" depends on the deployment requirements.

More importantly, **the paper cannot claim that BitNet v2 (a4) achieves minimal degradation relative to the optimal 4-bit performance achievable, only relative to the 8-bit version of itself.** There is no experiment showing that training 4-bit from scratch for the full 100B tokens would not yield better performance. The 5B-token continue-training protocol may leave performance on the table that full 4-bit training could recover. The claim is about efficiency of the training protocol, not about the ceiling of 4-bit performance.

#### Does the evidence support the claim that BitNet v2 (a4) offers superior computational efficiency to BitNet a4.8 for batched inference?

This claim is the central practical motivation for the paper, and **the evidence supporting it is qualitative and architectural, not quantitative.** The paper compares model quality (Table 1) and shows that BitNet v2 (a4) matches or exceeds BitNet a4.8 on accuracy and perplexity. It then argues that dense 4-bit computation is inherently more efficient than the sparsified 8-bit computation used by BitNet a4.8 for intermediate states.

However, the paper reports **zero throughput, latency, or memory measurements** for either model on any hardware. The efficiency advantage is argued entirely from architectural principles:
- Dense 4-bit matrix multiplication maps efficiently onto GPU tensor cores (including upcoming hardware like GB200 with native 4-bit support).
- Sparse computation requires irregular memory access or rigid sparsity patterns (e.g., 2:4 structured sparsity) that may not match BitNet a4.8's top-K sparsification pattern.
- The paper notes that "sparsification is less suited for maximizing throughput in batched inference" (Section 1) but provides no data.

This is a significant gap. The frequency with which theoretical efficiency advantages fail to materialize in practice (due to kernel launch overhead, memory layout issues, compiler limitations, or unexpected bottlenecks) is high enough that architectural arguments alone are insufficient. A minimal validation would be wall-clock throughput measurements for BitNet v2 (a4) vs. BitNet a4.8 (or vs. BitNet b1.58) on a representative GPU with a representative batch size. Without such measurements, the claim of "superior computational efficiency" is unvalidated—it could be true in principle but false in practice on current hardware due to immature 4-bit kernel support or inefficient Hadamard transform implementations.

A related measurement gap: the paper does not report the overhead of the online Hadamard transformation itself. While the FWHT has O(n log n) complexity, the constant factors and GPU implementation efficiency matter. If the Hadamard transform adds 10% overhead to each H-BitLinear layer's compute time, then the net speedup from 4-bit activations would need to exceed 10% to yield a wall-clock benefit. This number is never measured or estimated.

#### Does the evidence support the claim that post-training quantization fails for ternary-weight models?

Yes, and this is one of the paper's strongest contributions. Table 4 shows that QuaRot and SpinQuant—two leading post-training quantization methods—achieve perplexities of 19.80–20.83 when applied to BitNet b1.58 with fused rotary matrices, compared to 11.33 for BitNet v2 (a4). Even with the rotary fusion removed (sacrificing weight efficiency), perplexity only improves to 13.52, still 2.19 points worse than BitNet v2 (a4).

Several observations strengthen this finding:
- Both QuaRot and SpinQuant fail similarly, suggesting the problem is not method-specific but fundamental to the post-training-rotation + ternary-weight combination.
- The 800-sample calibration used for SpinQuant represents the best-case tuning scenario; real deployment might use fewer calibration samples and perform worse.
- The bit-width configuration is matched (W1.58A4 for all models in the comparison), so the difference is in the quantization method, not in precision.

However, the natural follow-up experiment—applying the same post-training quantization to **BitNet v2 (a8)** rather than BitNet b1.58—is not reported. Since BitNet v2 already incorporates Hadamard transformations during training, one might hypothesize that post-training quantization would work better on it (the activation distributions are already Gaussian-like). This experiment would distinguish whether the failure is due to "post-training methods don't work on ternary models" (which the paper implies) or "post-training methods don't work without in-training distribution reshaping." This missing ablation leaves a gap in the causal story.

#### What is not tested?

- **Training 4-bit from scratch for the full 100B tokens.** The paper presents the continue-training approach as efficient, but does not establish whether full-training would yield better or worse results. If full-training produced substantially better 4-bit performance, the 5B-token protocol would be a tradeoff (efficiency vs. quality) rather than a pure advantage.

- **Comparisons at larger scales (>7B).** The largest model is 7B parameters. Modern LLMs routinely exceed 70B or 100B+ parameters. Whether the Hadamard transformation remains effective at those scales—where both the outlier problem and the representational demands are different—is unknown. The favorable scaling pattern (improvement grows from 1.3B to 7B) is encouraging but does not justify extrapolation to 70B+.

- **Comparisons on non-English or code data.** All training uses RedPajama (English web text) and evaluation uses English benchmarks. Whether outlier channel patterns differ for code, multilingual text, or domain-specific corpora is unknown.

- **Direct throughput/latency measurements on hardware.** Discussed above—the efficiency claims are theoretical only.

- **Training with 4-bit from different initializations or with different 8→4 transition points.** The paper uses 95B/5B token split. Whether 90B/10B, 99B/1B, or 50B/50B would improve or degrade results is unexplored.

- **Sensitivity to the Hadamard being online vs. one-time.** The paper's H-BitLinear applies the Hadamard transformation during every forward pass. The ablation only tests weight+activation vs. activation-only rotation; it does not test whether a one-time fixed rotation applied post-training to a standard BitNet b1.58 model would perform similarly (this is what QuaRot attempts, but with the fusion problem confounding the result). A clean experiment applying the same Hadamard matrix as a one-time pre-processing step to the activations of an 8-bit trained model (without fusion into weights) would isolate the online vs. one-time rotation effect.

#### Summary of Evidence Strength

The paper's strongest claims—that BitNet v2 (a8) matches BitNet b1.58 and that 4-bit training diverges without the Hadamard transformation—are well-supported by Tables 1 and 5. The claim that BitNet v2 (a4) matches BitNet a4.8's quality is well-supported by Table 1, though the 1.3B model slightly underperforms. The claim that post-training quantization fails for ternary models is well-supported by Table 4. The claim of superior batched inference efficiency is logically coherent but empirically unvalidated—no throughput or latency measurements are reported. The scaling trend (improvement with model size) is observed but limited to the 400M–7B range, and extrapolation to larger models is speculative.

## 6. Limitations and Trade-offs

### Activation-Only Rotation Leaves a Fractional Dimension Constraint on Architecture Design

**The assumption or constraint.** H-BitLinear applies the Hadamard transformation only to activations (not weights, per the ablation in Section 3.3 and Tables 5–7), and the Hadamard matrix `$H_m$` is defined only for dimensions that are exact powers of two (`$n = 2^m$`, Equation 4). Since the transformation operates along the hidden dimension of the activation vectors feeding into Wo and Wdown, the hidden dimension of the model **must be a power of two** for these layers. The paper does not acknowledge or discuss this constraint explicitly, but it is implicit in the mathematical definition and visible in the model configurations (Table 8), where all hidden sizes are powers of two: 1024, 2048, 4096.

**The consequence.** This constraint is architectural, not merely implementational. Any model using H-BitLinear must choose its hidden dimension from the set {512, 1024, 2048, 4096, 8192, ...}, which restricts the granularity of model scaling. A practitioner who wants a model with hidden dimension 3072 or 5120—common sizes in other transformer families—cannot directly use H-BitLinear without either padding to the next power of two (wasting parameters and compute) or using a non-Hadamard rotation matrix that may not share the same outlier-suppression properties. The paper also applies the Hadamard transformation only to activations, not weights (Section 3.3), which means the weight matrices Wo and Wdown can have arbitrary output dimensions—only the input (hidden) dimension is constrained. But for the FFN down projection Wdown, the input dimension is the GLU intermediate size (Table 8: 4096, 8192, 8192, 16384 for the four model sizes), which must also be a power of two. This constrains both the hidden dimension and the FFN expansion factor to be powers of two.

**What evidence exists in the paper.** The model configurations in Table 8 show all hidden sizes and GLU sizes as powers of two. However, the paper does not discuss whether non-power-of-two dimensions were tested or whether the Hadamard transformation can be adapted (e.g., via padding or truncation). The fast Hadamard transform library cited (Dao-AILab's `fast-hadamard-transform`) requires power-of-two inputs, confirming the constraint is real and not merely a design choice. The ablation in Section 3.3 compares activation-only rotation to weight+activation rotation but does not explore alternative transformations (e.g., random orthogonal matrices, learned rotations as in SpinQuant) that might not require power-of-two dimensions.

**Mitigation status.** Not addressed. The paper neither acknowledges the power-of-two constraint nor discusses its practical implications for model design. Future work could explore alternative orthogonal transformations with more flexible dimension requirements, or investigate whether padding to the next power of two introduces negligible overhead at scale.

### Efficiency Gains Are Argued Architecturally but Never Measured on Hardware

**The assumption or constraint.** The paper's central practical motivation is that native 4-bit activations improve computational efficiency over BitNet a4.8's hybrid sparsification, specifically "for batched inference" (Section 1). BitNet a4.8 "is less suited for maximizing throughput in batched inference, where dense computations are often preferred for hardware efficiency." The entire contribution is framed around enabling dense 4-bit computation on hardware with native 4-bit support, cited as next-generation GPUs like the GB200.

**The consequence.** Without throughput, latency, or memory measurements, it is **impossible to assess whether the architectural advantage translates to real-world performance gains**, or to quantify the magnitude of any such gains. Several factors could reduce or eliminate the theoretical advantage:

- The **online Hadamard transformation** itself consumes compute. The FWHT has O(n log n) complexity, which for hidden dimension 4096 is roughly 4096 × 12 ≈ 49K operations per token per H-BitLinear layer. While this is small relative to the matrix multiplication (4096 × 4096 ≈ 16.8M operations), the constant factors on GPU implementations of FWHT versus highly-optimized matrix multiply kernels could shift the balance.
- **Immature 4-bit kernel support** on current hardware may mean that 8-bit kernels with mature engineering outperform 4-bit kernels with early-stage implementations, even if the theoretical FLOP count is halved. The paper invokes future hardware (GB200) without qualifying that current hardware may not realize the gains.
- **The 8→4 bit precision transition is only for activations.** Weights remain ternary, and the weight-activation matrix multiply is the dominant cost in most linear layers. Halving activation precision does not halve total layer compute because the weight representation (ternary) and the scaling factor multiplications are unchanged.
- **Memory bandwidth for activations** is typically not the bottleneck in batched inference; the bottleneck is compute throughput. Reducing activation precision from 8 to 4 bits halves the activation memory footprint, but if activations were not the memory bottleneck to begin with, this saving does not translate to wall-clock speedup.

**What evidence exists in the paper.** **None.** The paper reports zero throughput, latency, memory bandwidth, or FLOP utilization measurements for any model on any hardware. There is no comparison of BitNet v2 (a4) inference speed to BitNet a4.8 or BitNet b1.58. The only efficiency-related numbers are bit-width assignments (which layers use 4-bit vs. 8-bit) and model sizes (parameter counts). The claim that dense computation is preferred over sparse for batched inference is stated as a general principle (Section 1) without citation or empirical validation.

**Mitigation status.** Not addressed. The paper's efficiency claims remain entirely theoretical. A minimal validation—e.g., wall-clock time per token for a batched forward pass on a representative GPU (A100, H100) comparing BitNet v2 (a4), BitNet a4.8, and BitNet b1.58—would substantially strengthen the practical contribution. The authors do not flag this as future work.

### The Continue-Training Protocol Obscures the True Cost of Reaching 4-Bit Performance

**The assumption or constraint.** The paper's training pipeline (Section 2.2) trains BitNet v2 with 8-bit activations for 95B tokens from scratch, then continue-trains with 4-bit activations for only 5B tokens, reusing optimizer states. The paper frames this as efficient: "BitNet v2 with 4-bit activations can be continue-trained from its 8-bit activation counterpart using a small number of training tokens, while incurring negligible performance loss." The headline result (Table 1) compares BitNet v2 (a4) to BitNet a4.8, which uses the same continue-training protocol.

**The consequence.** The reported performance of BitNet v2 (a4) is **contingent on first training a full 8-bit model**. The total cost to produce a 4-bit model is 100B tokens of training (95B at 8-bit + 5B at 4-bit), which is essentially the same as training an 8-bit model from scratch. This creates an accounting problem:

- The paper's framing implies that BitNet v2 (a4) is a 4-bit model that is cheap to obtain. In reality, **the 8-bit model must be trained first**, and the 4-bit variant is an incremental additional cost. If a practitioner only needs a 4-bit model, they must still pay for 95B tokens of 8-bit training, which dominates the total cost.
- The paper does not report results for **training 4-bit from scratch for the full 100B tokens**. This is the relevant baseline for understanding whether the 8-bit pre-training is necessary or merely convenient. If 4-bit from scratch achieves similar or better performance, the 8-bit stage is wasted compute. If 4-bit from scratch underperforms or diverges, then the 8-bit stage is essential but expensive—the "small number of additional tokens" framing understates the true cost of reaching 4-bit performance.
- The "reusing optimizer states" claim (Section 2.2) is presented as an advantage, but it also means the 4-bit training is **not independent**—it inherits the optimization trajectory from the 8-bit run. This makes the protocol fragile: if the 8-bit training is suboptimal (e.g., wrong learning rate schedule, poor initialization), the 4-bit fine-tuning cannot recover.

**What evidence exists in the paper.** Table 1 compares BitNet v2 (a8) and BitNet v2 (a4) and shows the performance gap is small (e.g., 0.28 points at 3B, 0.43 points at 7B). Table 5 shows that 4-bit training without Hadamard diverges entirely ("No rotation: diverged"), but this is for models **without** the Hadamard transformation—it does not test whether BitNet v2 trained with 4-bit activations from scratch for 100B tokens (with Hadamard) would converge and what performance it would achieve. The ablation in Table 5 compares only with and without rotation, not 8-bit pre-trained vs. from-scratch 4-bit.

**Mitigation status.** Not addressed. The paper does not discuss this accounting issue or report 4-bit-from-scratch baselines. The continue-training protocol is presented as an unqualified advantage without cost analysis. A fair accounting would report: (1) total FLOPs to produce BitNet v2 (a4), (2) performance of BitNet v2 trained with 4-bit activations from scratch for 100B tokens, and (3) whether a shorter 8-bit pre-training phase (e.g., 50B tokens) followed by longer 4-bit fine-tuning could achieve the same performance at lower total cost. The authors do not flag this as future work.

### Scaling Behavior Beyond 7B Parameters Is Completely Unknown

**The assumption or constraint.** All experiments are conducted at model sizes from 400M to 7B parameters (Table 8). While this covers a meaningful range for edge deployment and small-server scenarios, it is far below the scale of frontier LLMs (70B–405B+). The paper observes that BitNet v2's advantage over BitNet b1.58 grows with scale (+0.16% at 1.3B, +0.49% at 3B, +0.61% at 7B for 8-bit activations, Table 1) and presents this as an encouraging trend. But the trend is based on only three data points beyond the 400M scale, and the improvement from 3B to 7B (+0.12 percentage points) is much smaller than from 1.3B to 3B (+0.33 points), which could indicate a saturating or even reversing trend.

**The consequence.** The paper's claims cannot be extrapolated to larger models without additional evidence. Several mechanisms could cause the approach to degrade or behave differently at scale:

- **Outlier channel severity may increase with model size.** If larger models develop stronger outlier channels (as suggested by the quantization literature the paper cites), the Hadamard transformation's effectiveness at smoothing these distributions may change. The transformation "smears" outlier energy uniformly—if outliers become more extreme at scale, the smeared energy per dimension increases, potentially recreating the dynamic range problem the transformation was designed to solve.
- **The Hadamard transformation itself may interact differently with learned representations at scale.** The orthogonality of the transformation guarantees norm preservation, but it also means that features which were disentangled in the original coordinate system become mixed in the transformed space. At small scales, the model can learn to use features in the rotated space; at larger scales, the representational capacity exists to learn more structured feature spaces, and forcibly rotating them may impose a stronger inductive bias cost.
- **The 4-bit activation degradation may not remain "minimal" at scale.** The paper shows the 8→4 bit gap is 0.28 points at 3B, 0.43 points at 7B—increasing, not decreasing. If this trend continues, larger models could see larger absolute degradation, undermining the practical case for 4-bit activations.

**What evidence exists in the paper.** The scaling data points are limited to 400M, 1.3B, 3B, and 7B (Table 1). The paper does not train models at 13B, 30B, or 70B scale. There is no theoretical analysis or extrapolation of how the outlier distribution or the Hadamard transformation's effectiveness scales with model size. The QKV quantization experiments (Tables 2–3) are also limited to 3B and 7B.

**Mitigation status.** Not addressed. The paper draws conclusions about "BitNet v2" as a general framework without qualifying that the evidence is limited to sub-10B models. The introduction and abstract make claims without scope limitations. Given that the practical relevance of 4-bit inference is arguably largest at the scales where serving costs dominate (10B+ parameters), this is a significant evidence gap.

### The Single-Dataset, Single-Model-Family Evaluation Leaves Domain Generalization Uncharacterized

**The assumption or constraint.** All models are trained exclusively on RedPajama, an English web-text corpus, and evaluated on English-language benchmarks (C4 perplexity, ARC, HellaSwag, PIQA, Winogrande, LAMBADA). The entire experimental validation is thus scoped to **English natural language understanding** with a specific data distribution. The paper does not evaluate on code generation, mathematical reasoning, multilingual text, or any domain outside standard English LM benchmarks.

**The consequence.** It is unknown whether the Hadamard transformation and 4-bit activation training generalize to other domains where activation distributions may differ:

- **Code generation** often involves highly structured, repetitive patterns with different activation statistics than natural language. Outlier channels might behave differently when the input is code rather than prose.
- **Mathematical reasoning** requires precise numerical computation through the model's activations; quantization errors that are negligible for language modeling perplexity might compound across multi-step reasoning chains.
- **Multilingual text** introduces different token distributions and potentially different activation patterns, especially for scripts that are underrepresented in the English-dominated RedPajama training data.
- **Instruction-tuned or chat models** undergo additional training (SFT, RLHF) that may alter activation distributions relative to the base pretrained models evaluated in the paper.

Furthermore, the baseline comparison against BitNet b1.58 and BitNet a4.8 is only conducted on these same English benchmarks. If the Hadamard transformation introduces subtle degradations that only appear on other task types, the current evaluation would miss them entirely.

**What evidence exists in the paper.** The evaluation suite (Section 3) consists of six zero-shot English language tasks plus C4 perplexity. The paper does not discuss domain generalization, nor does it claim that results should generalize. The benchmarks chosen are standard for the LLM pretraining literature and allow direct comparison with BitNet b1.58 and BitNet a4.8, but they represent a narrow slice of potential deployment scenarios.

**Mitigation status.** Not addressed. The paper does not flag domain generalization as a limitation or suggest evaluation on code, math, or multilingual benchmarks as future work. This is a common limitation in LLM pretraining papers (especially at smaller scales where training multiple domain-specific variants is expensive), but it is particularly relevant here because the core technical contribution (the Hadamard transformation) is motivated by properties of the activation distribution that could be domain-dependent.
