# Sequence-Level PPO for Long-Horizon Reasoning Tasks

**ArXiv:** [2604.08865](https://arxiv.org/abs/2604.08865)

## 🎯 Pitch

A scalar prompt-solvability critic that predicts whether a problem will be solved—without watching the individual reasoning steps—eliminates the credit-assignment instability that makes standard token-level PPO *worse than doing nothing* on math tasks, while matching the accuracy of multi-sample methods like GRPO at 5.9× the speed.

---

## 1. Executive Summary

This paper introduces **Sequence-Level PPO (SPPO)**, a reinforcement learning algorithm for aligning LLMs on long-horizon reasoning tasks with verifiable rewards. Evaluating on mathematical benchmarks (AIME24/25, AMC23, MATH500, Minerva) with DeepSeek-R1-Distill-Qwen models at 1.5B and 7B scales, SPPO reformulates reasoning as a **Sequence-Level Contextual Bandit** problem—treating the entire response as an atomic action and deriving a scalar advantage signal A = R − V(sₚ) from a learned value function that predicts prompt solvability—rather than decomposing credit across thousands of tokens via GAE (which induces the "Tail Effect" where the token-level critic only discriminates correctness at the final few tokens). SPPO matches GRPO's peak performance with 5.9× training speedup and enables single-sample updates (N = 1) instead of requiring expensive multi-sampling (N = 8) for baseline estimation, while a decoupled lightweight 1.5B critic aligning a 7B policy cuts memory usage by 12.8%, establishing that a scalar sequence-level baseline is structurally robust for sparse-reward alignment only when the critic captures prompt solvability rather than attempting step-by-step credit assignment.

## 2. Context and Motivation

### The Core Problem: PPO Breaks Down on Long Reasoning Trajectories

The fundamental problem this paper addresses is that **standard Proximal Policy Optimization (PPO), when applied to long Chain-of-Thought reasoning tasks with sparse rewards, suffers from a structural instability that makes it unreliable—and sometimes outright harmful—for alignment.** This matters enormously because PPO has been the workhorse algorithm for aligning LLMs since the original RLHF pipeline, and reasoning tasks (mathematical problem-solving, code generation, logical deduction) represent one of the most important capability frontiers for contemporary LLMs.

The instability is not a minor implementation detail. In the paper's experiments (Table 1), standard PPO on the 1.5B model achieves an average score of **44.06**, which is actually *below* the base model's 44.96—meaning the RL fine-tuning degraded performance rather than improving it. On every single individual benchmark for the 1.5B model, PPO scores equal or lower than the base model. This is a catastrophic failure mode for an algorithm whose entire purpose is to improve the model.

To understand *why* PPO fails, we need to examine the mechanism at the heart of the algorithm: **credit assignment**.

### The Credit Assignment Challenge in Sparse-Reward Settings

In reinforcement learning, credit assignment refers to the problem of determining which actions in a sequence contributed to the eventual outcome. When a model produces a 2,000-token reasoning chain that arrives at a correct (or incorrect) final answer, how do we decide which token-level decisions were responsible?

Standard PPO addresses this through a **token-level Markov Decision Process (MDP)** decomposition. The environment is modeled as a sequence of states $s_t$ (the prompt + tokens generated so far), actions $a_t$ (the next token), and a learned **Critic** $V(s_t)$ that attempts to predict the expected future return from each intermediate state. The advantage signal $\hat{A}_t$ that drives policy updates is computed via **Generalized Advantage Estimation (GAE)**:

$$\hat{A}^{\text{GAE}}_t = \sum_{l=0}^{T-t-1} (\gamma\lambda)^l \delta_{t+l}$$

where the temporal difference (TD) error at each step is:

$$\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)$$

In sparse-reward reasoning tasks, the standard configuration sets $\gamma = \lambda = 1$ to propagate the terminal reward all the way back to the beginning. Under this setting, GAE collapses to a deceptively simple form:

$$\hat{A}^{\text{GAE}}_t = G_t - V(s_t)$$

where $G_t$ is the Monte Carlo return (the binary outcome reward, since intermediate rewards are zero). In words: the advantage at token $t$ is simply the difference between "what actually happened" and "what the Critic expected would happen from this point."

This formulation has an appealing symmetry: if the model ultimately succeeds but the Critic predicted failure ($V(s_t)$ is low), every token gets a strong positive advantage. If the model fails but the Critic was optimistic ($V(s_t)$ is high), every token gets penalized. The Critic's role is to establish a token-dependent baseline that isolates which decisions were genuinely good or bad *relative to expectations*.

### Why GAE Fails: The Tail Effect

In theory, token-level credit assignment via GAE should work. In practice, on long reasoning chains, it fails systematically. The paper identifies and visualizes the failure mode through what they call the **"Tail Effect"** (Section 1, Figure 1).

The insight is this: a token-level Critic trained on thousands of reasoning trajectories inevitably learns to predict success based on **position rather than semantic content**. As the generation approaches the final answer tokens, the Critic's value estimate $V(s_t)$ for correct trajectories rises to converge with the terminal reward, while for incorrect trajectories it diverges. The consequence is that the advantage signal $\hat{A}_t = G_t - V(s_t)$ **vanishes** precisely when it matters most:

- **On correct trajectories:** The Critic correctly predicts success by the final steps, so $V(s_t) \approx 1$ and $\hat{A}_t \approx 0$. The policy receives essentially no positive reinforcement for the tokens that actually led to the correct answer—the Critic has already "priced in" the success.
- **On incorrect trajectories:** The Critic similarly predicts failure by the final steps, so $V(s_t) \approx 0$ and again $\hat{A}_t \approx 0$. The policy receives no negative signal for the tokens that caused the failure.

Figure 1 visualizes this with concrete value curves. Blue lines (correct trajectories) show $V(s_t)$ rising late in the sequence, while red lines (incorrect trajectories) stay low. The separation occurs almost entirely at the tail. The extended visualization in Appendix B (Figure 9, with 10 randomly sampled problems) confirms this is not cherry-picked—the value curves for correct and incorrect trajectories remain entangled throughout the intermediate reasoning process and only diverge at the final few tokens.

The paper's diagnosis is precise (Section 1):

> "This 'tail effect' bases credit on position rather than contribution, undermining optimization."

The Critic isn't learning to evaluate reasoning quality—it's learning to recognize when the model has arrived at (or departed from) the answer format. This is a form of **overfitting to semantic cues at the sequence tail**, and it means the advantage signal that drives policy improvement is essentially noise for the vast majority of tokens in the chain.

### The Memory Cost Problem

Beyond the instability issue, standard PPO has a second critical bottleneck: **memory**. The token-level Critic $V(s_t)$ is typically the same size as the policy model (e.g., a 7B Critic for a 7B Actor). This effectively doubles the GPU memory footprint of the training pipeline. For long-context reasoning tasks where both prompt and response can span thousands of tokens, the combined memory requirements can exceed available hardware even on high-end GPUs.

The paper quantifies this in Figure 6: standard PPO with a 7B+7B actor-critic configuration peaks at **89.8% GPU memory utilization**, while methods that eliminate the Critic entirely (GRPO) peak at 85.7%. The Critic isn't just unstable—it's expensive. Together, these two problems (unstable credit assignment and prohibitive memory cost) motivated the development of critic-free alternatives.

### The GRPO Response: Eliminate the Critic, but at What Cost?

Group Relative Policy Optimization (GRPO, Shao et al., 2024) emerged as the leading response to PPO's instability in reasoning tasks. Its core innovation is radical: **eliminate the learned Critic entirely.** Instead of training a value function to estimate expected returns, GRPO samples $N$ complete responses per prompt, computes the mean and standard deviation of their empirical rewards, and uses the standardized score as the advantage:

$$\text{Adv}(s_p, a) = \frac{R - \mu_g}{\sigma_g}$$

where $\mu_g$ and $\sigma_g$ are the sample mean and standard deviation across the $N$ responses for the same prompt.

This approach works. GRPO has driven several high-profile reasoning model releases (DeepSeek-R1, among others), and in the paper's experiments (Table 1), GRPO with $N = 8$ achieves 47.08 average on the 1.5B model and 57.44 on the 7B model—substantially above both the base model and standard PPO. Its success can be understood through two complementary lenses:

**1. Implicit sequence-level modeling.** The paper's key insight (Section 2.2) is that GRPO's advantage formulation implicitly **reformulates the reasoning task as a Contextual Bandit rather than a multi-step MDP.** To see this, model the $N$ sampled responses for a prompt $s_p$ as independent Bernoulli trials with success probability $\hat{p}(s_p)$ (the empirical pass rate). Under this model, the sample mean $\mu_g = \hat{p}$ and the sample standard deviation $\sigma_g \approx \sqrt{\hat{p}(1-\hat{p})}$. Substituting into the advantage formula yields:

$$\text{Adv}(s_p, R) \approx 
\begin{cases} 
\sqrt{\frac{1-\hat{p}}{\hat{p}}} & \text{if } R = 1 \text{ (Success)} \\
-\sqrt{\frac{\hat{p}}{1-\hat{p}}} & \text{if } R = 0 \text{ (Failure)}
\end{cases}$$

This reveals the mechanism (visualized in Figure 2): GRPO dynamically scales the reward based on the prompt's estimated difficulty $\hat{p}(s_p)$. For easy prompts (high $\hat{p}$), a success receives a small positive advantage (the model was expected to succeed) while a failure receives a large negative penalty (it's surprising to fail). For hard prompts (low $\hat{p}$), a success is heavily rewarded (surprising) while a failure is only mildly penalized (expected). The entire response is evaluated as an **atomic unit** against a prompt-dependent baseline, completely sidestepping the token-level credit assignment problem.

**2. Variance through group normalization.** By normalizing against the group mean, GRPO ensures that the advantage signal adapts to the difficulty of each prompt individually, preventing easy prompts from dominating the gradient and hard prompts from being ignored.

### The Bias-Variance Tradeoff that GRPO Introduces

GRPO's success comes with a fundamental tradeoff that the paper identifies as the central tension in current reasoning alignment methods (Section 1, 2.2):

> "While [GRPO] removes the high bias inherent in token-level value estimation, the reliance on Monte Carlo outcomes introduces high variance in the gradient signal."

This is a **Bias-Variance Trade-off** in the statistical sense. Standard PPO's token-level Critic introduces **high bias** (the Tail Effect: the value estimates are systematically wrong for most tokens) but **low variance** (the Critic is a deterministic function; with $N=1$ sample, you get one clean advantage signal). GRPO eliminates that bias by not attempting token-level credit assignment at all, but replaces it with **high variance** from Monte Carlo estimation: with finite $N$, the sample mean $\mu_g$ is a noisy estimate of the true prompt difficulty, and this noise propagates directly into the advantage.

To mitigate this variance and achieve stable training, GRPO requires **multiple samples per prompt** ($N > 1$). The paper uses $N = 8$, which is standard in the literature. This means that for every prompt in a training batch, the model must generate 8 complete reasoning chains, compute their rewards, and then normalize—a process that is computationally 8× more expensive in the generation phase than a method requiring only $N = 1$ sample per prompt.

The computational cost is the bottleneck (Section 5.1). In the paper's 7B experiments (Figure 5), GRPO requires over **120 hours** of wall-clock time to converge, while SPPO reaches peak performance in approximately **22 hours**—a 5.9× speedup. This is not because SPPO's per-step computation is lighter; it's because GRPO's multi-sampling requirement means that each policy update cycle generates 8× more tokens, consuming substantially more GPU time and memory bandwidth.

### Conflicting Results in the Literature

The paper is situated within a broader landscape of conflicting findings about what works for RL-based reasoning alignment:

- **Standard PPO with token-level Critic:** Results are inconsistent. Some implementations report reasonable performance (Guo et al., 2025), while others observe severe degradation (Kazemnejad et al., 2025; Yuan et al., 2025). The paper's experiments firmly place standard PPO in the "degradation" category—it underperforms the base model on the 1.5B scale, and while it shows improvement on the 7B scale (56.44 vs. 52.49 base), it still lags behind all sequence-level alternatives.

- **Critic-free group-based methods (GRPO, and variants like DAPO, Dr.GRPO):** These consistently outperform standard PPO but at a steep computational cost. Recent work (Liu et al., 2025; Luo et al., 2025) has proposed refinements to GRPO's gradient dynamics and sampling strategies, but all remain bound to the multi-sampling paradigm.

- **Alternative critic-free sequence-level methods (ReMax, RLOO):** These eliminate the Critic without requiring multi-sampling, instead using baselines like the reward of a greedy-decoded response (ReMax) or leave-one-out estimation across a small set of samples (RLOO). In the paper's experiments, both outperform standard PPO but fall short of GRPO: ReMax achieves 46.74/57.09 (1.5B/7B) and RLOO achieves 46.15/57.02, compared to GRPO's 47.08/57.44.

- **Sequence-level optimization with PPO-style clipping (GSPO, GMPO):** These methods argue that PPO's token-level design is incongruent with sequence-level rewards, but they position their contribution primarily as addressing routing instability in Mixture-of-Experts architectures, so the paper excludes them from direct comparison.

The field thus faces a dilemma: **the best-performing methods (GRPO) are the most computationally expensive**, while the cheaper methods (standard PPO, ReMax, RLOO) leave performance on the table. There is no existing approach that simultaneously achieves GRPO-level performance and single-sample efficiency.

### The Key Misconception the Paper Identifies

The paper's central conceptual move is to argue that the field has drawn the wrong lesson from GRPO's success. The common interpretation is: "GRPO works because it eliminates the learned Critic." The paper argues this is a **misconception** (Section 1, 2.2). The correct interpretation, in their view, is:

> "GRPO's success stems from implicitly remodeling reasoning as a Sequence-Level Contextual Bandit problem—treating the entire response as an atomic action to bypass token-level noise—rather than a multi-step Markov Decision Process (MDP)."

This distinction matters because it opens up a design space that GRPO does not explore: **if the key is the sequence-level formulation, not the absence of a Critic, then we can explicitly adopt that formulation while keeping a Critic—but redesigning the Critic to operate at the sequence level rather than the token level.**

This is what separates SPPO from both standard PPO (which uses a token-level Critic) and GRPO (which uses no Critic). SPPO keeps the architectural efficiency of having a learned value function (enabling $N = 1$ updates) but redesigns it to predict a single scalar $V(s_p)$—the probability of success given the prompt—rather than a per-token value $V(s_t)$. This scalar Critic serves the same role as GRPO's $\hat{p}(s_p)$ (estimated prompt difficulty), but it's learned rather than estimated via expensive multi-sampling.

The paper explicitly frames this as a resolution of the Bias-Variance Trade-off:

- **Standard PPO:** High bias (token-level Critic overfits to the tail) + Low variance ($N = 1$ updates).
- **GRPO:** Low bias (no token-level Critic) + High variance (Monte Carlo baseline with $N > 1$).
- **SPPO:** Low bias (sequence-level contextual bandit formulation eliminates token-level credit assignment) + Low variance (learned scalar Critic provides a stable baseline with $N = 1$).

### How This Paper Positions Itself

The paper's positioning is explicit and three-fold:

**1. As a conceptual reframing.** The primary contribution is not a new loss function or training trick, but rather the argument that the reasoning alignment problem should be viewed as a **Sequence-Level Contextual Bandit** (SL-CB) rather than a token-level MDP. Section 3.1 formalizes this: the context $S$ is the static prompt $s_p$, the action $A$ is the entire response sequence treated as an atomic unit, and the reward $r(s_p, a_{\text{seq}})$ evaluates holistic correctness. By collapsing the time horizon ($H = 1$), the credit assignment problem simply disappears—there are no intermediate steps to assign credit to, only a single action whose outcome directly determines the advantage.

**2. As a practical algorithm that harmonizes competing objectives.** SPPO is presented as the algorithm that operationalizes this reframing within the PPO framework. It preserves PPO's clipped surrogate objective and single-sample efficiency, but replaces GAE's token-level advantage with a sequence-level advantage $A(s_p, a) = R - V_\phi(s_p)$ that is broadcast uniformly to all constituent tokens. The value model $V_\phi(s_p)$ is trained with a simple Binary Cross-Entropy loss against the binary outcome reward, explicitly optimizing it to predict prompt solvability.

**3. As an efficiency breakthrough.** The paper emphasizes that SPPO does not just match GRPO's performance—it does so with dramatically lower computational cost (5.9× training speedup, single-sample updates, lower memory footprint via critic decoupling). This is positioned not as an incidental benefit but as a core design goal: the algorithm should be both stable and resource-efficient, enabling alignment of large reasoning models under constrained hardware budgets.

The paper also draws an explicit contrast with prior sequence-level methods (Section 6.2). RLOO (Ahmadian et al., 2024) uses REINFORCE-style updates with a leave-one-out baseline, but recent work (Wang et al., 2025b) has shown that PPO's clipping mechanism plays a crucial role in learning stability through token masking—so RLOO's abandonment of clipping may be a step backward. ReMax uses the reward of a greedy-decoded response as a baseline, but this provides no adaptive difficulty calibration. SPPO retains both the clipping mechanism (for stability) and the learned baseline (for difficulty calibration), while upgrading the baseline from token-level to sequence-level.

### The Practical Stakes

The paper's problem framing has direct practical implications that go beyond algorithmic elegance:

- **Training throughput is a bottleneck for iterative RL.** In the emerging paradigm of self-improving reasoning models (where models generate training data, are fine-tuned on it, and repeat), the speed of each RL iteration directly determines how many cycles can be completed within a fixed compute budget. A 5.9× speedup means potentially 5.9× more improvement cycles—or the same number of cycles at a fraction of the cost.

- **Hardware accessibility constrains who can participate.** Standard RLHF with symmetric actor-critic architectures requires loading two full-size models simultaneously. For a 70B model, this demands roughly 280 GB of GPU memory just for the model weights (assuming FP16), before accounting for activations, optimizer states, and the batch data. The decoupled critic approach (1.5B critic for a 7B policy) reduces the critic memory footprint proportionally—a 7B policy with a 7B critic requires double the weight memory, while with a 1.5B critic the overhead is only ~20%. This pattern scales: a 70B policy could potentially be aligned with a 7B critic, making the pipeline viable on hardware configurations that couldn't support a symmetric setup.

- **Single-sample efficiency enables online learning.** Methods requiring $N > 1$ samples per prompt must generate and store all $N$ responses before computing advantages and performing updates. This introduces latency and memory overhead that complicate online or streaming learning scenarios. Single-sample methods can update the policy after each generation, enabling more rapid iteration.

The paper thus addresses a problem that is simultaneously theoretical (how should we think about credit assignment in long-horizon reasoning?), algorithmic (how do we design an RL algorithm that is both stable and efficient under sparse rewards?), and practical (how do we align reasoning models without requiring prohibitive computational resources?).

## 3. Technical Approach

This is primarily an **algorithm design paper** whose core idea is that the instability of token-level PPO in long-horizon reasoning tasks stems not from the intractability of value estimation itself, but from the **token-level MDP decomposition** that forces a Critic to assign credit to individual tokens in a sequence where only the final outcome matters. By explicitly reformulating reasoning as a Sequence-Level Contextual Bandit and redesigning the Critic to operate at the sequence level, SPPO achieves both the stability of sequence-level modeling and the sample efficiency of single-sample PPO-style updates.

---

### 3.1 Reader Orientation (Approachable Technical Breakdown)

**What is being built:** SPPO is an RL fine-tuning algorithm that takes a pretrained LLM and improves its reasoning ability using only binary feedback (correct/incorrect final answer), without needing intermediate step-level supervision.

**What problem it solves and the shape of the solution:** The algorithm resolves the tension between standard PPO (which is sample-efficient but unstable on long reasoning chains due to flawed token-level credit assignment) and GRPO (which is stable but computationally expensive due to requiring multiple samples per prompt). SPPO achieves this by **redesigning the value function** to predict a single scalar—the probability that the model will solve the prompt correctly—rather than attempting to predict per-token future returns, and then broadcasting this sequence-level advantage uniformly to all tokens in the response during the policy update.

---

### 3.2 Big-Picture Architecture (Diagram in Words)

The SPPO training pipeline has four major components that interact in a standard actor-critic RL loop:

1. **The Policy (Actor) $\pi_\theta$** — the LLM being fine-tuned. It generates a complete reasoning chain $a_{\text{seq}} = (y_1, \ldots, y_T)$ conditioned on the prompt $s_p$, using standard autoregressive sampling. This is the same as the policy in standard PPO.

2. **The Reward Function $\mathcal{R}$** — an external, deterministic verifier that inspects the final answer and returns a binary reward $R \in \{0, 1\}$ (1 for correct, 0 for incorrect). No intermediate rewards are provided; the reward signal is purely outcome-based.

3. **The Value Model (Critic) $V_\phi$** — a learned scalar function that takes only the prompt $s_p$ (not the generated tokens) and predicts the probability that the current policy $\pi_\theta$ will produce a correct answer. This is the key architectural departure from standard PPO. The Critic is trained via binary cross-entropy against the actual binary reward, treating prompt solvability as a Bernoulli parameter to be estimated.

4. **The Advantage Estimator** — a computation that subtracts the Critic's predicted solvability $V_\phi(s_p)$ from the observed binary reward $R$ to produce a single scalar advantage $A(s_p, a) = R - V_\phi(s_p)$. This scalar is then **broadcast uniformly** to every token in the generated sequence, replacing the per-token GAE advantages used in standard PPO.

**Information flow during one training step:**

- **Step 1 (Generation):** The Actor $\pi_\theta$ samples one complete response $a_{\text{seq}}$ for each prompt $s_p$ in the batch. Critically, only $N = 1$ sample per prompt is needed, unlike GRPO which requires $N > 1$.

- **Step 2 (Reward computation):** The verifier evaluates each complete response and produces a binary reward $R \in \{0, 1\}$.

- **Step 3 (Value prediction):** The Critic $V_\phi$ processes each prompt $s_p$ (without seeing the generated response) and outputs a scalar $\hat{p} = V_\phi(s_p) \in [0, 1]$, its estimate of the probability that the current policy would solve this prompt correctly.

- **Step 4 (Advantage computation):** The sequence-level advantage is computed as $A = R - V_\phi(s_p)$. If the model succeeded ($R = 1$) but the Critic was pessimistic ($V_\phi(s_p)$ is low), the advantage is strongly positive. If the model failed ($R = 0$) but the Critic was optimistic ($V_\phi(s_p)$ is high), the advantage is strongly negative. If the Critic's prediction matches the outcome, the advantage is near zero.

- **Step 5 (Policy update):** The Actor is updated using PPO's clipped surrogate objective, but with the sequence-level advantage $A$ applied uniformly to every token in the response. Each token $t$ in the sequence receives the identical advantage signal, reinforcing or penalizing the entire reasoning chain as an atomic unit.

- **Step 6 (Critic update):** The Critic $V_\phi$ is updated using binary cross-entropy loss against the observed reward $R$, training it to better predict prompt solvability for future iterations.

This loop repeats for the specified number of training steps, with the Critic and Actor improving in tandem: the Critic learns to estimate difficulty more accurately, enabling more precise advantage signals, while the Actor learns to produce reasoning chains that consistently yield correct answers.

### 3.4 Detailed, Sentence-Based Technical Breakdown

#### 3.4.1 The Sequence-Level Contextual Bandit Formulation

The foundational conceptual move of SPPO is to **redefine the environment in which reinforcement learning operates.** Standard PPO models the reasoning process as a token-level Markov Decision Process (MDP) with the tuple $(\mathcal{S}, \mathcal{A}, \mathcal{T}, r, \gamma)$, where:

- $\mathcal{S}$ is the state space (the prompt plus all tokens generated so far).
- $\mathcal{A}$ is the action space (the vocabulary — choosing the next token).
- $\mathcal{T}$ is the transition dynamics (deterministic: appending the chosen token to the sequence).
- $r$ is the reward function (zero for all intermediate steps, binary at the terminal step).
- $\gamma$ is the discount factor (typically set to 1.0 for sparse-reward reasoning).

Under this MDP, the policy $\pi_\theta(a_t | s_t)$ generates tokens one at a time, each token is treated as a distinct action, and the Critic $V(s_t)$ must estimate the expected future return from each intermediate state. This is the root cause of the Tail Effect: the Critic is asked to solve an ill-posed problem (predicting final correctness from partial reasoning chains where the answer hasn't yet been formulated).

SPPO replaces this with a **Sequence-Level Contextual Bandit (SL-CB)** formulation defined by the tuple $(\mathcal{S}, \mathcal{A}, r)$, where:

$$\text{SL-CB} = (\mathcal{S}, \mathcal{A}, r)$$

where $\mathcal{S}$ is the context space restricted to the static prompt $s_p$ only (no intermediate states), $\mathcal{A}$ is the action space where each action $a_{\text{seq}}$ is an entire response sequence $(y_1, \ldots, y_T)$ treated as an atomic unit, and $r(s_p, a_{\text{seq}})$ is the binary reward evaluating the holistic correctness of the complete chain.

**What this formulation computes:** It conceptually collapses the time horizon from $T$ steps to $H = 1$ step. The "state" is only the prompt (a static context), the "action" is the entire generation (one atomic decision), and the reward is the outcome of that generation. There is no sequential decision-making to optimize over — only a mapping from prompts to response distributions, evaluated by expected outcome reward.

**Why this form:** This formulation directly targets the structural mismatch between standard PPO's MDP assumption and the reality of sparse-reward reasoning. In mathematical problem-solving with verifiable outcomes, the intermediate reasoning steps have no intrinsic reward — they are valuable only instrumentally, to the extent that they lead to a correct final answer. There is no notion of "partial correctness" that can be meaningfully scored at intermediate steps (unlike, say, a game of chess where material advantage is a valid intermediate signal). By formalizing this insight — that the task is fundamentally a contextual bandit, not an MDP — SPPO eliminates the credit assignment problem at its source: there are no intermediate steps to assign credit to, only a single holistic action whose outcome directly determines the advantage.

This is not just a philosophical reframing. It has concrete algorithmic consequences explored in the next sections: the value function only needs to condition on the prompt (not the partial sequence), the advantage is a single scalar (not a per-token vector), and the policy update reinforces or penalizes the entire sequence uniformly rather than attempting to differentially weight individual tokens based on their estimated contribution.

The paper notes that this reframing is inspired by the observation that GRPO's advantage formulation (Equation 6 in Appendix A) implicitly treats the task as a contextual bandit — GRPO's advantage depends only on the prompt difficulty $\hat{p}(s_p)$ and the outcome $R$, not on any per-token signal. SPPO makes this implicit modeling choice explicit and builds an algorithm around it.

---

#### 3.4.2 The Scalar Value Function: Design and Training

The Critic in SPPO is fundamentally redesigned compared to standard PPO. Instead of a token-level value function $V(s_t)$ that maps from arbitrary intermediate states to expected returns, SPPO trains a **scalar value function $V_\phi(s_p)$** that maps directly from the prompt to a single probability:

$$V_\phi(s_p) \in [0, 1]$$

where $V_\phi(s_p)$ estimates the probability that the current policy $\pi_\theta$ will produce a correct answer when given prompt $s_p$.

**Architecture and implementation.** The value model $V_\phi$ is implemented as a separate neural network — in the paper's experiments, another instance of the same base model architecture (DeepSeek-R1-Distill-Qwen) — that takes the prompt $s_p$ as input and outputs a scalar between 0 and 1. The model processes the prompt tokens through its transformer layers and extracts a pooled representation (typically from the final token position or a dedicated classification head) that is mapped to a probability via a sigmoid activation.

The paper explores two configurations for the Critic's scale relative to the policy:
- **Symmetric critic:** The Critic uses the same model size as the policy (e.g., 7B Critic for 7B Actor). This is the standard configuration tested in the main SPPO results.
- **Decoupled/Small critic:** The Critic uses a smaller model (e.g., 1.5B Critic for 7B Actor). This configuration is tested as the "w/ Small Critic" variant.

**Training objective.** The Critic is trained using the **Binary Cross-Entropy (BCE) loss** against the observed binary reward $R$:

$$\mathcal{L}_V(\phi) = -\mathbb{E}\left[ R \log V_\phi(s_p) + (1 - R) \log(1 - V_\phi(s_p)) \right]$$

where $R \in \{0, 1\}$ is the binary outcome reward (1 for correct, 0 for incorrect) and $V_\phi(s_p)$ is the Critic's predicted probability of success.

**What this objective computes:** The BCE loss measures the discrepancy between the Critic's predicted success probability and the actual observed outcome. When $R = 1$ (the model succeeded), the loss reduces to $-\log V_\phi(s_p)$, which heavily penalizes the Critic for predicting a low probability of success — it should have been confident the model would succeed. When $R = 0$ (the model failed), the loss reduces to $-\log(1 - V_\phi(s_p))$, which heavily penalizes the Critic for predicting a high probability of success — it should have recognized this was a difficult prompt.

**Why this form:** Binary cross-entropy is the maximum-likelihood objective for a Bernoulli random variable, which is the correct statistical model for binary outcomes. The Critic's prediction $V_\phi(s_p)$ is being trained as a calibrated probability, and BCE is the proper scoring rule for probability calibration. An alternative like Mean Squared Error (MSE) between $V_\phi(s_p)$ and $R$ would also encourage the Critic to match the observed frequency, but BCE has the additional property that its gradient is steeper for predictions far from the true label, providing stronger learning signals when the Critic is badly miscalibrated — which is exactly when accurate difficulty estimation matters most for advantage computation.

**Training hyperparameters.** From the execution commands in Appendix E (Figures 10-12), the Critic is trained with:
- Learning rate: `5e-6` for the 1.5B Critic, `1e-5` for the 7B Critic
- The Critic uses FSDP (Fully Sharded Data Parallelism) with `param_offload=False` and `optimizer_offload=False`
- Gradient checkpointing is enabled (`enable_gradient_checkpointing=True`)
- The Critic uses a mini-batch size of 128 (1.5B) or 32 (7B) for updates
- The Critic does not use dynamic batch sizing (`use_dynamic_bsz=False`)
- No warmup period is used for the Critic (`trainer.critic_warmup=0`), meaning the Critic is trained from the first step alongside the policy

**What makes this value function different from standard PPO's Critic.** In standard PPO, the Critic $V(s_t)$ must answer the question: "Given that we've generated tokens $y_1, \ldots, y_t$ so far, what is the expected final reward?" This requires the Critic to implicitly model the policy's future behavior from any intermediate state, which is a complex distributional modeling problem. The Tail Effect demonstrates that what the Critic actually learns is a much simpler heuristic: "We're near the end of the sequence and the format looks like an answer" or "We're still in the middle of reasoning so the answer could go either way."

In SPPO, the Critic $V_\phi(s_p)$ answers a fundamentally simpler question: "What is the probability that the current policy solves this prompt?" This only requires the Critic to assess the difficulty of the prompt relative to the policy's current capabilities — it doesn't need to model the generation process at all. The paper argues this is a more tractable learning problem, and the empirical evidence supports this: the Critic learns meaningful difficulty estimates (Section 5.2, Figure 7, Pearson $r = 0.642$) without exhibiting the pathological position-based overfitting seen in token-level critics.

#### 3.4.3 The Sequence-Level Advantage and Policy Update

With the scalar value function established, SPPO computes the advantage signal for policy optimization. The advantage for a prompt-response pair $(s_p, a_{\text{seq}})$ is:

$$A(s_p, a_{\text{seq}}) = R - V_\phi(s_p)$$

where $R \in \{0, 1\}$ is the binary outcome reward and $V_\phi(s_p) \in [0, 1]$ is the Critic's predicted probability of success for prompt $s_p$.

**What this computes:** The advantage is the difference between what actually happened (the binary reward) and what the Critic expected to happen (the predicted success probability). This difference can range from -1 to +1:
- If $R = 1$ and $V_\phi(s_p) = 0.3$: the advantage is $+0.7$ — the model succeeded on a prompt the Critic thought was difficult, so this is a strong positive signal.
- If $R = 1$ and $V_\phi(s_p) = 0.9$: the advantage is $+0.1$ — the model succeeded on an easy prompt as expected, so this is a weak positive signal.
- If $R = 0$ and $V_\phi(s_p) = 0.7$: the advantage is $-0.7$ — the model failed on a prompt the Critic thought was easy, so this is a strong negative signal.
- If $R = 0$ and $V_\phi(s_p) = 0.1$: the advantage is $-0.1$ — the model failed on a hard prompt as expected, so this is a weak negative signal.

**Why this form:** This is a standard baseline-subtraction advantage in reinforcement learning, but with the crucial distinction that the baseline $V_\phi(s_p)$ conditions only on the prompt, not on the partial sequence. This means the advantage naturally scales with the surprise of the outcome given the prompt's difficulty — easy prompts that are failed receive large penalties, hard prompts that are solved receive large rewards. This is exactly the adaptive difficulty scaling that GRPO achieves through group normalization (as shown in Equation 6 of Appendix A), but SPPO achieves it through a learned Critic rather than empirical multi-sampling.

The paper notes (Section 3.2) that this formulation "naturally amplifies the signal when the model is confident but wrong, and suppresses noise when the model is uncertain ($V \approx 0.5$)." When $V_\phi(s_p) \approx 0.5$, the Critic is maximally uncertain, and the advantage for either outcome is approximately $\pm 0.5$ — a moderate signal that doesn't dominate the gradient. But when the Critic is confident ($V_\phi(s_p)$ near 0 or 1) and wrong, the advantage is near $\pm 1$, providing a strong corrective signal.

**Policy update via clipped surrogate objective.** SPPO adapts the standard PPO clipped surrogate objective to use the sequence-level advantage. The objective is:

$$J_{\text{SPPO}}(\theta) = \mathbb{E}_{s_p \sim \mathcal{D}, a \sim \pi_{\theta_k}, t \in a} \left[ \min\left( r_t(\theta) A(s_p, a), \text{clip}(r_t(\theta), 1 - \epsilon, 1 + \epsilon) A(s_p, a) \right) \right]$$

where:
- $\theta$ are the current policy parameters being optimized
- $\theta_k$ are the behavior policy parameters (the policy that generated the data, frozen during this update)
- $s_p \sim \mathcal{D}$ is a prompt sampled from the training dataset
- $a \sim \pi_{\theta_k}$ is a response generated by the behavior policy
- $t \in a$ iterates over all token positions in the generated response
- $r_t(\theta) = \frac{\pi_\theta(a_t | s_p, a_{<t})}{\pi_{\theta_k}(a_t | s_p, a_{<t})}$ is the probability ratio for token $t$
- $A(s_p, a)$ is the sequence-level advantage (identical for all tokens in the sequence)
- $\epsilon$ is the clipping hyperparameter (standard value: 0.2)
- $\min(\cdot, \cdot)$ selects the more conservative of the unclipped and clipped objectives
- $\text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)$ constrains the probability ratio to prevent destructively large updates

**What this objective computes:** For each token $t$ in the generated response, the algorithm computes the ratio between the current policy's probability of that token and the behavior policy's probability. If the sequence-level advantage $A(s_p, a)$ is positive, the objective encourages increasing the probability of each token, but clips the increase to at most a factor of $1 + \epsilon$ to prevent the policy from changing too radically. If the advantage is negative, the objective encourages decreasing the probability, similarly clipped. The $\min$ operation ensures conservatism: when the advantage is positive, we take the minimum of the unclipped and clipped ratios (preventing over-optimistic updates); when the advantage is negative, we take the maximum (preventing over-pessimistic updates, since both terms are negative and we want the less negative one).

**The critical difference from standard PPO.** In standard PPO, each token $t$ receives a unique advantage $\hat{A}_t$ computed via GAE, which theoretically reflects the token's individual contribution to the outcome. In SPPO, every token in the sequence receives the **identical** sequence-level advantage $A(s_p, a)$. This is the operationalization of the contextual bandit insight: since the entire response is treated as an atomic action, every constituent token shares equally in the credit or blame for the outcome.

This uniform broadcasting has a subtle but important consequence: the policy gradient for each token is scaled by the same factor, regardless of where the token appears in the sequence. This means the algorithm does not attempt to distinguish between "critical reasoning steps" and "formatting tokens" — but it also means it doesn't erroneously assign zero advantage to the reasoning tokens while only rewarding the answer format tokens (which is what the Tail Effect does in standard PPO). The paper's empirical results suggest that uniform broadcasting is preferable to erroneous differential weighting — it's better to treat all tokens equally than to systematically misattribute credit.

**Hyperparameters for the policy update.** From the execution commands in Appendix E:
- Clipping parameter $\epsilon$: The standard value of 0.2 is used (implicitly, since it's the default in the `verl` library and not overridden in the commands)
- Actor learning rate: `1e-6` for both 1.5B and 7B models
- KL penalty coefficient $\beta_{\text{KL}}$: Set to `0` explicitly (`algorithm.use_kl_in_reward=False` or `actor_rollout_ref.actor.use_kl_loss=False`). The paper states this is "to encourage exploration" (Section 4.1).
- Weight decay: 0.01 for 1.5B, 0.1 for 7B
- Learning rate warmup: Set to constant with `lr_warmup_steps_ratio=0` (no warmup)
- Optimizer: AdamW (implicit in the `verl` library defaults)
- PPO mini-batch size: 128 for 1.5B, 32 for 7B
- PPO micro-batch size per GPU: 2 for 1.5B, 1 for 7B
- Total training steps: 1000 for 1.5B, 200 for 7B

**Generation hyperparameters.** During rollout, the policy generates responses with:
- Temperature: `0.6` for both training and validation
- Maximum prompt length: 1024 tokens (1.5B) or 2048 tokens (7B)
- Maximum response length: 8192 tokens for both model sizes
- The vLLM inference engine is used for efficient generation (`actor_rollout_ref.rollout.name=vllm`)
- GPU memory utilization for vLLM: `0.8` (80% of available GPU memory)

**Batch configuration:**
- Global training batch size: 256 for 1.5B, 512 for 7B
- These batch sizes represent the number of prompts per training step. Since SPPO uses $N = 1$ sample per prompt, each training step involves generating 256 (or 512) complete responses, computing their rewards, evaluating the Critic, computing advantages, and performing one policy update.

#### 3.4.4 The Decoupled Critic Architecture

A key design choice in SPPO is the **decoupling of Critic size from Policy size.** The paper hypothesizes that estimating prompt solvability (a scalar prediction problem) is fundamentally simpler than generating reasoning chains (a sequence generation problem), and therefore the Critic can be substantially smaller than the policy without sacrificing the quality of the advantage signal.

**Experimental validation.** To test this hypothesis, the paper trains a 7B policy using a 1.5B Critic (both initialized from DeepSeek-R1-Distill-Qwen variants). The "w/ Small Critic" configuration in Table 1 achieves an **average score of 58.56** across the five benchmarks, which is the highest overall score in the 7B experiments — slightly above the symmetric SPPO (58.11) and above all baselines including GRPO (57.44). This provides strong empirical evidence that the Critic's model capacity is not the bottleneck for advantage estimation quality.

**Memory efficiency implications.** Figure 6 quantifies the memory savings. Standard RLHF with symmetric actor-critic architectures (7B policy + 7B Critic) requires loading two full-size models simultaneously. The paper reports that in the 7B experiments:
- SPPO with symmetric critic: peak GPU memory utilization of **91.5%**
- SPPO with decoupled small critic (7B + 1.5B): peak GPU memory utilization of **78.7%**
- GRPO (no Critic): peak GPU memory utilization of **85.7%**
- Standard PPO (7B + 7B): peak GPU memory utilization of **89.8%**
- RLOO: peak GPU memory utilization of **98.6%**
- ReMax: peak GPU memory utilization of **98.7%**

The decoupled critic configuration reduces peak memory by approximately **12.8 percentage points** compared to the symmetric SPPO, and by approximately 11 percentage points compared to standard PPO. The paper explicitly notes this reduction, stating that "This validates that a lightweight critic can effectively align a large policy, significantly reducing the memory footprint of RLVR training."

**Why this works: complexity analysis.** The paper's hypothesis, stated in Section 3.2, is that "scalar solvability estimation is significantly simpler than generative reasoning." To estimate whether a prompt is solvable, the Critic only needs to:
1. Understand the problem statement (requires reading comprehension of the prompt).
2. Assess its difficulty relative to the policy's capabilities (requires implicit knowledge of what kinds of problems the policy tends to solve or fail on).

Both of these capabilities are present to some degree even in smaller language models. The Critic doesn't need to generate reasoning steps, maintain coherent multi-step logical chains, or produce formally correct mathematical notation — it only needs to produce a single calibrated probability. This is a discriminative task (classify difficulty) rather than a generative task (produce reasoning), and discriminative tasks typically require less model capacity.

**Implementation detail.** The decoupled critic uses the same training procedure as the symmetric critic — BCE loss against observed rewards, AdamW optimizer, same learning rate (1e-5 for the 1.5B critic aligning the 7B policy). The only difference is the model path specified in the Critic configuration:
- Symmetric: `critic.model.path=deepseek-ai/DeepSeek-R1-Distill-Qwen-7B`
- Decoupled: `critic.model.path=deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B`

The paper also notes that the system-level memory optimizations in the `verl` library (Sheng et al., 2025) — specifically, "advanced memory management and sharding techniques" — contribute to the memory efficiency by "minimizing redundant memory allocation" (Section 5.1).

#### 3.4.5 The Ablation Experiment: Isolating the Source of Gains

To establish **causal evidence** that SPPO's performance comes from the sequence-level contextual bandit formulation rather than from incidental implementation details (specifically, the BCE loss function used to train the Critic), the paper conducts a controlled ablation study (Section 4.3, Figure 4).

**The control condition: PPO + BCE.** In this experiment, the authors take the standard token-level PPO framework and replace the typical Critic training loss (usually MSE against Monte Carlo returns) with the BCE loss used in SPPO, while keeping everything else — the token-level MDP formulation, GAE advantage estimation, per-token varying advantage signals — unchanged. The Critic still predicts per-token values $V(s_t)$, but it is trained with BCE instead of MSE:

$$\mathcal{L}_{\text{PPO+BCE}} = -\mathbb{E}\left[ R \log V(s_t) + (1 - R) \log(1 - V(s_t)) \right]$$

**What this controls for:** If SPPO's gains were simply due to BCE being a better loss function for Critic training (perhaps because it naturally handles the binary nature of the outcome better than MSE), then PPO + BCE should show similar improvements. If SPPO's gains come from the sequence-level formulation (the collapsing of the time horizon and the uniform advantage broadcasting), then PPO + BCE should fail to reproduce SPPO's performance.

**Results (Figure 4).** The ablation produces a clear result: PPO + BCE fails to reproduce SPPO's success. As shown in Figure 4, the PPO + BCE curve closely tracks standard PPO, exhibiting the same instability. Both PPO-based runs (standard and + BCE) were **terminated early at 500 steps** "due to observed performance collapse and degrading scores" — meaning the training became so unstable that continuing would have been counterproductive. In contrast, SPPO continues improving throughout the full training run (1000 steps for 1.5B).

**Interpretation.** The paper states this interpretation explicitly (Section 4.3):

> "This empirical evidence validates that SPPO's efficacy derives fundamentally from its Sequence-Level Contextual Bandit formulation—specifically the propagation of a unified advantage signal $A = R - V(s_p)$—rather than the adoption of the BCE loss in isolation."

This is a crucial result for the paper's central claim. It demonstrates that the BCE loss is not a "free lunch" that improves any Critic — it only helps when combined with the sequence-level formulation that makes the Critic's prediction task well-posed. When the Critic is still asked to predict per-token values $V(s_t)$ from arbitrary intermediate states, changing the loss function from MSE to BCE doesn't fix the fundamental problem that $V(s_t)$ is an ill-defined quantity for most intermediate reasoning steps.

**Why the BCE loss alone doesn't fix token-level PPO.** The Tail Effect is a problem of what the Critic is asked to predict, not how it's trained. A token-level Critic, regardless of loss function, must estimate $V(s_t)$ — the expected return from an intermediate state. For the first 90% of a reasoning chain, this expected return is essentially the policy's overall success rate on that prompt, because the answer hasn't been determined yet. But the Critic observes the partial reasoning chain and can pick up on spurious correlations (e.g., length, formatting, keywords) that happen to correlate with success in the training data. Changing from MSE to BCE doesn't change what features the Critic can overfit to — it only changes the precise form of the overfitting. The sequence-level formulation solves this by eliminating the intermediate states entirely: the Critic only sees the prompt, so it can only learn prompt-level difficulty, which is exactly what we want it to learn.

#### 3.4.6 Design Choice Summary: Why Each Component Is Necessary

The SPPO algorithm can be understood as the result of three interdependent design decisions, each addressing a specific failure mode:

**Design Decision 1: Sequence-Level Contextual Bandit formulation instead of token-level MDP.**
- **What it does:** Collapses the time horizon so the policy action is the entire response, not individual tokens.
- **Why necessary:** This eliminates the credit assignment problem at its root. If there are no intermediate actions, there's no need to assign credit to intermediate steps. The Tail Effect (Figure 1, Figure 9) demonstrates that token-level credit assignment via GAE systematically fails on long reasoning chains — the Critic overfits to position-based cues at the sequence tail.
- **Alternative considered and rejected:** Standard PPO's MDP formulation with GAE. The paper shows this leads to performance degradation (1.5B PPO scores below base model) or instability requiring early termination (Figure 4).

**Design Decision 2: Learned scalar value function $V_\phi(s_p)$ instead of empirical group baseline.**
- **What it does:** Trains a Critic to predict prompt solvability, providing a stable baseline for advantage estimation with single-sample efficiency ($N = 1$).
- **Why necessary:** This achieves low-variance advantage estimation without the computational cost of multi-sampling. GRPO's empirical baseline $\mu_g$ has variance that scales as $1/\sqrt{N}$, requiring $N = 8$ (or more) to be stable enough for training. SPPO's learned baseline provides a deterministic estimate with no sampling variance (conditioned on the learned parameters), enabling $N = 1$ updates and the 5.9× training speedup.
- **Alternative considered and rejected:** GRPO's group-based empirical baseline. The paper acknowledges GRPO's effectiveness (47.08/57.44 on 1.5B/7B) but identifies the multi-sampling requirement as a computational bottleneck.

**Design Decision 3: Uniform advantage broadcasting instead of per-token varying advantages.**
- **What it does:** Applies the identical sequence-level advantage $A = R - V_\phi(s_p)$ to every token in the response during the policy update.
- **Why necessary:** This operationalizes the contextual bandit insight in the policy gradient. If the entire response is an atomic action, every constituent token shares equally in the credit or blame. Attempting to differentially weight tokens (as GAE does) introduces bias when the differential weighting is based on an unreliable Critic.
- **Why not just use REINFORCE with a sequence-level baseline (like RLOO):** The paper retains PPO's clipped surrogate objective because prior work (Wang et al., 2025b) has shown that the clipping mechanism provides crucial stability through implicit token masking — preventing individual tokens from receiving destructively large updates. RLOO, being based on REINFORCE without clipping, lacks this stabilization mechanism. The paper's empirical results support this: RLOO scores 46.15/57.02 (1.5B/7B), below SPPO's 48.06/58.11.

**Design Decision 4: Decoupled Critic size.**
- **What it does:** Uses a smaller model (e.g., 1.5B) for the value function while keeping a larger model (e.g., 7B) for the policy.
- **Why necessary:** The value prediction task (estimating prompt solvability) is discriminative and requires less capacity than the policy task (generating coherent reasoning chains). Decoupling reduces memory footprint by 12.8 percentage points (Figure 6) without sacrificing performance — indeed, the decoupled configuration achieves the highest average score (58.56).
- **Why not always use the smallest possible critic:** The paper only tests 1.5B critic for 7B policy. The lower bound on useful critic size is not explored — it's possible that even smaller critics (e.g., 0.5B) would suffice, or that the critic size should scale with policy size according to some ratio. This remains an open question.

**Training hyperparameter choices and their justifications:**
- **$\beta_{\text{KL}} = 0$:** The KL penalty is explicitly disabled "to encourage exploration" (Section 4.1). In standard RLHF, a KL penalty prevents the policy from diverging too far from the reference model, but for reasoning tasks where the base model already has some capability and the goal is to improve it, constraining the policy to stay near its initial distribution may limit the gains from RL. The paper's empirical results suggest this choice is appropriate — the policy improves substantially without KL regularization.
- **$\gamma = 1, \lambda = 1$ for standard PPO baseline:** These are set to propagate sparse terminal rewards through GAE. This is standard practice for sparse-reward tasks, but it means GAE provides no temporal discounting or bias-variance tradeoff — it purely computes $G_t - V(s_t)$.
- **Temperature = 0.6 for both training and validation:** This provides a moderate level of stochasticity in generation, balancing exploration (needed to discover new correct reasoning patterns) with exploitation (needed to consistently produce correct answers for advantage estimation).
- **Learning rate ratio (Actor 1e-6 vs. Critic 5e-6 or 1e-5):** The Critic uses a 5–10× higher learning rate than the Actor. This is a standard practice in actor-critic methods: the Critic needs to adapt quickly to the changing policy to provide accurate baselines, while the policy should change more slowly to maintain stable learning.

## 4. Key Insights and Innovations

### Innovation 1: The Source of PPO's Instability Is the Token-Level MDP Decomposition, Not the Learned Critic Per Se

The paper's most conceptually significant move is to diagnose *why* standard PPO fails on long-horizon reasoning, and the diagnosis itself constitutes a genuine insight that reframes the problem. Prior work had observed the symptoms — Kazemnejad et al. (2025) noted instability, Yuan et al. (2025) documented "PPO's collapse in long-CoT" — but the dominant interpretation treated the learned Critic itself as the root cause. This interpretation motivated the turn toward critic-free methods (GRPO, RLOO, ReMax), which eliminate the Critic entirely and rely on statistical or heuristic baselines instead.

SPPO's diagnostic move is to show that the Critic is not intrinsically the problem — rather, **the problem is asking the Critic to solve an ill-posed estimation task.** The token-level MDP decomposition forces the Critic to predict expected returns $V(s_t)$ from arbitrary intermediate states, which for long reasoning chains means predicting final correctness from partial reasoning where the answer hasn't been formulated yet. The Tail Effect (Figure 1, extended in Appendix B Figure 9) reveals what the Critic actually learns: it overfits to position-based semantic cues at the sequence tail, discriminating correct from incorrect trajectories only in the final few tokens. The Critic isn't broken — it's answering the wrong question.

This diagnosis reframes the field's options. The prior framing was: "Token-level Critics are unstable → eliminate them." The paper's framing is: "Token-level value estimation is an ill-posed problem in sparse-reward reasoning → redesign the estimation target." The latter opens up a design space — sequence-level value estimation — that retains the Critic's benefits (low-variance baselines, single-sample efficiency) while avoiding its pathology.

The evidence for this diagnosis being correct rather than merely asserted comes from the ablation experiment (Section 4.3, Figure 4). If the BCE loss function were the key ingredient (as might be hypothesized if one believed the Critic's problem was merely poor calibration), then PPO + BCE should improve over standard PPO. It doesn't — both standard PPO and PPO + BCE collapse at 500 steps and are terminated early. The problem isn't *how* the Critic is trained (MSE vs. BCE); it's *what* the Critic is asked to predict (per-token returns vs. scalar solvability). This is a causal demonstration, not a correlation, and it constitutes the paper's strongest piece of evidence for its central conceptual claim.

This is a **fundamental diagnostic reframing**, not an incremental improvement. It changes the question from "How do we replace the Critic?" to "What should the Critic estimate?" — a shift that reopens the possibility of learned value functions in reasoning alignment, a direction that the field had largely abandoned after GRPO's success.

---

### Innovation 2: Explicit Reformulation of Reasoning as a Contextual Bandit, Operationalized Within PPO

The paper's second distinctive contribution is making explicit what GRPO does implicitly, and then building an algorithm that extracts the benefits without GRPO's computational costs. This is a two-part insight, and both parts matter.

**Part 1: Identifying that GRPO implicitly models reasoning as a Contextual Bandit.** The derivation in Appendix A (and the visualization in Figure 2) shows that GRPO's group-normalized advantage — when the sampling process is modeled as Bernoulli trials — reduces to a function that depends only on the prompt's empirical success rate $\hat{p}(s_p)$ and the binary outcome $R$, with the entire response treated as an atomic unit. GRPO never explicitly declares itself a contextual bandit algorithm, but its advantage formulation is mathematically equivalent to one. The paper's contribution is to name this implicit modeling choice, argue that it is the *source* of GRPO's stability (not the absence of a Critic), and frame it as a general design principle.

This is an insight about *why GRPO works*, not just *that* it works. Prior work had attributed GRPO's success to eliminating the biased token-level Critic. The paper argues this attribution is a misconception: the real mechanism is the implicit shift from token-level sequential credit assignment to sequence-level holistic evaluation. This distinction is not semantic — it has practical consequences for algorithm design, because it suggests that a sequence-level Critic (which GRPO lacks) could provide the same structural stability with better sample efficiency.

**Part 2: Operationalizing this insight within the PPO framework rather than abandoning it.** Several prior works (GSPO, GMPO, RLOO) have argued that PPO's token-level design is fundamentally incompatible with sequence-level rewards and have proposed abandoning PPO-style clipping in favor of REINFORCE-based updates or alternative policy gradient formulations. SPPO takes a different path: it retains PPO's clipped surrogate objective and its single-sample update structure, but replaces the token-level advantage estimation (GAE) with a sequence-level advantage that is broadcast uniformly to all tokens.

This is a non-obvious design choice. The uniform broadcasting of a scalar advantage to all tokens might seem crude — surely the first token of a reasoning chain contributes differently to the outcome than the final answer token. But the paper's empirical results suggest that uniform broadcasting is *better* than erroneous differential weighting. The Tail Effect shows that GAE's per-token advantages are systematically wrong: they vanish for most tokens on correct trajectories (providing no learning signal where it's needed) and fail to penalize early reasoning mistakes on incorrect trajectories (providing no corrective signal). Uniform broadcasting — treating all tokens equally — is a form of "noisy but unbiased" credit assignment compared to GAE's "precise but systematically biased" assignment. In the bias-variance tradeoff that structures the paper's argument, SPPO opts for zero bias (no differential credit assignment at all) with zero variance from credit assignment (since the advantage is identical for all tokens), accepting that some granularity in the learning signal is lost.

This is a **fundamental algorithmic reframing** rather than an incremental tweak. It resolves the tension between two competing camps in reasoning alignment — the PPO camp (sample-efficient but unstable) and the GRPO camp (stable but sample-inefficient) — by showing that the stability comes from the sequence-level formulation, not from critic elimination, and that the sample efficiency comes from the learned Critic, not from token-level credit assignment. By combining both within a single algorithm, SPPO demonstrates that this tradeoff was always a false dichotomy driven by conflating two independent design axes.

---

### Innovation 3: The Decoupled Critic as Evidence That Solvability Estimation Is a Fundamentally Simpler Task Than Generation

The paper's finding that a 1.5B Critic can effectively align a 7B policy — and indeed achieves the highest overall average score (58.56, Table 1, "w/ Small Critic") — is more than a practical optimization. It's empirical evidence for a substantive claim about the nature of the tasks involved: **predicting whether a prompt is solvable is a discriminative reasoning task that requires substantially less model capacity than generating the solution itself.**

This matters because it challenges an implicit assumption in standard RLHF pipelines. The standard practice of using a symmetric Critic (same size as the policy) assumes that value estimation is roughly as complex as policy execution — that to judge whether a partial generation is good, you need approximately the same reasoning capacity as generating it. In game-playing domains where this assumption originated (Atari, Go, continuous control), it's often true: estimating the value of a board position is comparably difficult to choosing the next move. But for language model reasoning with sparse outcome rewards, the Critic in SPPO's formulation only needs to answer: "Given this problem statement, how likely is the current policy to solve it?" This is closer to difficulty classification than to reasoning evaluation, and the paper's results suggest it can be done effectively by a model with ~20% of the policy's parameters.

The memory implications (Figure 6: 78.7% peak utilization for decoupled vs. 91.5% for symmetric, a 12.8 percentage point reduction) are the practical payoff, but the conceptual payoff is the reframing of the Critic's role. In standard PPO, the Critic is a co-equal partner to the Actor — both must reason about the problem. In SPPO, the Critic is more like a **difficulty oracle** that calibrates the policy's learning rate on a per-prompt basis. This is a fundamentally different role, and it's one that can be fulfilled by a much smaller model.

The paper does not explore the lower bound — could a 0.5B critic work? A 300M critic? This remains an open question, but the existence proof (1.5B works for 7B) already constitutes a significant finding. It suggests that for reasoning alignment, the field can decouple the scaling of policy capacity from the scaling of value estimation capacity, with the latter potentially scaling much more slowly. This is a **fundamental finding about task complexity**, not just an efficiency trick, and it has implications for how future RL pipelines allocate their model capacity budgets.

---

### Innovation 4: The Bias-Variance Tradeoff as a Unifying Framework for Reasoning Alignment Algorithms

While bias-variance tradeoffs are standard in statistical learning theory, the paper's contribution is to apply this lens systematically to the landscape of RL algorithms for LLM reasoning, providing a unified framework that explains the relative strengths and weaknesses of all major approaches. This is a **conceptual synthesis** rather than a new algorithm, but it's one that clarifies the design space and motivates SPPO's specific architectural choices.

The taxonomy the paper establishes (Section 1, 2.2) is:
- **Standard PPO (token-level Critic + GAE):** High bias (the Tail Effect systematically misattributes credit) + Low variance (deterministic Critic, $N=1$ updates). Result: unstable, often degrades performance.
- **GRPO (no Critic, group empirical baseline):** Low bias (no token-level credit assignment) + High variance (Monte Carlo baseline, variance scales as $1/\sqrt{N}$). Result: stable but computationally expensive ($N=8$ required).
- **ReMax / RLOO (no learned Critic, alternative baselines):** Low bias + Moderate variance (greedy baseline or leave-one-out estimator). Result: more stable than PPO but below GRPO performance (46.74/46.15 vs. 47.08 on 1.5B).
- **SPPO (sequence-level learned Critic):** Low bias (contextual bandit formulation eliminates token-level assignment) + Low variance (learned deterministic Critic, $N=1$ updates). Result: matches GRPO performance with 5.9× training speedup.

This framework is valuable because it explains *why* each method behaves as it does, and more importantly, it shows that the bias-variance tradeoff is not a fundamental law that forces a choice between stability and efficiency. SPPO achieves low bias and low variance simultaneously by redesigning the estimation target (eliminating bias at its source) and using a learned baseline (eliminating Monte Carlo variance). The framework predicts that future improvements could come from further reducing either term — a better Critic architecture that reduces variance further, or a more refined bandit formulation that captures some sequential structure without reintroducing bias.

The significance of this innovation extends beyond SPPO itself. By providing a common vocabulary for discussing algorithm tradeoffs, the paper enables more principled comparison between methods and suggests productive directions for future work. It reframes the question from "Which algorithm is best?" to "How do we simultaneously minimize bias and variance in the advantage estimation for this specific task structure?" — a more precise and productive framing. This is a **conceptual advance** in how the field understands the problem, not just an empirical finding about algorithm performance.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The paper uses two training datasets at different model scales. For the 1.5B model, training uses the **DeepScaleR-Preview** dataset (Luo et al., 2025; MIT license). For the 7B model, training uses the **DAPO-17K** dataset (Yu et al., 2025), described as "a curated subset of high-quality mathematical reasoning problems" (Section 4.1, Section 5.1). Both datasets consist of mathematical reasoning problems with verifiable ground-truth answers. Complete dataset links and licenses are provided in Appendix D, Table 2.

- **Base model(s).** Experiments use two model scales from the same family: **DeepSeek-R1-Distill-Qwen-1.5B** and **DeepSeek-R1-Distill-Qwen-7B** (both MIT license). These are distilled reasoning models that have already undergone some reasoning-oriented training, providing a non-trivial but imperfect starting point for RL fine-tuning — the base 1.5B model achieves 44.96 average across five benchmarks and the base 7B achieves 52.49 (Table 1). The paper does not explicitly justify why these specific models were chosen, but they represent a standard scale comparison within a widely-used open-source reasoning model family.

- **Metrics.** The primary metric is **Average@16 accuracy** (Section 4.1), which for each benchmark computes the model's accuracy when sampling 16 responses per prompt and checking whether any are correct (pass@16). The paper also reports **Average@8** for the training efficiency analysis (Figure 5). Individual benchmark scores (AIME24, AIME25, AMC23, MATH500, Minerva Math) and their average across the five benchmarks are reported in Table 1. Rewards during training are strictly binary: **+1 for correct boxed answers, 0 for incorrect answers** (Section 4.1). The reward function is implemented via the `Reasoning360` library (Cheng et al., 2025) for consistency between training and evaluation.

- **Benchmarks.** Five held-out evaluation benchmarks are used (Section 4.1): **AIME24, AIME25** (Art of Problem Solving, 2025a), **AMC23** (Art of Problem Solving, 2025b), **MATH500** (Hendrycks et al., 2021), and **Minerva Math** (Lewkowycz et al., 2022). No benchmark-specific preprocessing or adaptation is described; the models are evaluated on the standard problem sets.

- **Baselines.** The paper compares SPPO against five baselines (Section 4.1, Table 1):
  1. **Base Model** — The pretrained DeepSeek-R1-Distill-Qwen model without any RL fine-tuning.
  2. **Standard PPO** — Token-level PPO with a learned Critic $V(s_t)$, GAE advantage estimation with $\gamma = 1, \lambda = 1$ (Schulman et al., 2017; Guo et al., 2025).
  3. **ReMax** — A critic-free method using the reward of a greedy-decoded response as the baseline (referenced but no original citation provided; as used in the verl library).
  4. **RLOO** — REINFORCE Leave-One-Out, a critic-free method using leave-one-out baseline estimation across multiple samples (Ahmadian et al., 2024). In these experiments, RLOO uses $N = 5$ samples (`actor_rollout_ref.rollout.n=5` in Appendix E, Figures 17-18).
  5. **GRPO** — Group Relative Policy Optimization with $N = 8$ samples per prompt for group-based baseline estimation (Shao et al., 2024).
  
  All algorithms are implemented via the **verl** library (Sheng et al., 2025). The paper states that hyperparameters "generally follow the official recommended examples provided by the verl library" (Section 4.1). Exact execution commands with all hyperparameter settings are provided in Appendix E (Figures 10-20).

- **Generation budget / compute accounting.** The paper measures computational cost along three axes:
  1. **Sample count ($N$):** SPPO and standard PPO use $N = 1$ sample per prompt per update. GRPO uses $N = 8$. RLOO uses $N = 5$.
  2. **Wall-clock time:** Training efficiency comparisons in Figure 5 plot validation performance against training time in hours, directly comparing the throughput of different algorithms.
  3. **GPU memory:** Peak VRAM utilization is measured and compared across methods (Figure 6), capturing the memory footprint of each algorithm's actor-critic architecture.
  
  These three measures capture different aspects of computational cost: sample efficiency (how many generations needed per update), throughput (how fast the system converges in wall-clock time), and hardware accessibility (how much GPU memory is required).

- **Cross-validation / statistical protocol.** The paper does not employ formal cross-validation. Performance is evaluated on the standard held-out benchmark test sets (AIME24, AIME25, AMC23, MATH500, Minerva). The paper does not report confidence intervals, standard deviations, or statistical significance tests for any of the reported numbers. The training efficiency curves (Figures 4, 5) appear to show raw (smoothed) validation performance over training steps/time, without error bars. The correlation analysis in Figure 7 reports Pearson and Spearman coefficients with $N = 200$ prompts.

- **Hardware and implementation details.** 1.5B experiments run on **4 × A100 GPUs**; 7B experiments run on **4 × H100 GPUs** (Section 4.1). Key hyperparameters include: $\beta_{\text{KL}} = 0$ (no KL penalty, "to encourage exploration"), Actor learning rate `1e-6`, Critic learning rate `5e-6` (1.5B) or `1e-5` (7B), temperature `0.6` for both training and validation generation, and training steps of 1000 (1.5B) or 200 (7B). Global batch sizes are 256 for 1.5B and 512 for 7B. The vLLM inference engine handles generation with GPU memory utilization set to 0.8.

### Main Quantitative Results

#### Overall Performance Comparison (Table 1)

The headline result across both model scales is that SPPO achieves the highest or near-highest average performance while operating with single-sample efficiency ($N = 1$), compared to GRPO which requires $N = 8$ samples per prompt.

**1.5B scale (trained on DeepScaleR-Preview):**

SPPO achieves an average score of **48.06** across the five benchmarks, compared to:
- Base Model: 44.96 (SPPO improves by **+3.10**)
- Standard PPO: 44.06 (SPPO improves by **+4.00**, and notably standard PPO scores *below* the base model)
- ReMax: 46.74 (SPPO improves by **+1.32**)
- RLOO: 46.15 (SPPO improves by **+1.91**)
- GRPO ($N = 8$): 47.08 (SPPO improves by **+0.98**)

On individual benchmarks, SPPO achieves the highest score on **4 out of 5**: AIME24 (34.17 vs. GRPO's 30.00, a **+4.17** margin), AIME25 (25.83; ReMax scores 25.42, GRPO scores 26.25), AMC23 (74.38 vs. GRPO's 73.13), and matches GRPO on Minerva (22.15). On MATH500, SPPO (83.78) is slightly below ReMax (84.38) and base model (83.73), but above GRPO (83.88 — note: 83.88 is higher than 83.78, so this is actually below GRPO; the difference is marginal at 0.10).

A notable result: standard PPO degrades the base model on every single benchmark for the 1.5B model — AIME24 stays flat at 27.50, but AIME25 drops from 21.67 to 20.83, AMC23 drops from 71.56 to 70.63, MATH500 drops from 83.73 to 81.38, and Minerva drops from 20.35 to 19.89. This confirms the paper's framing of standard PPO as fundamentally unstable at this scale.

**7B scale (trained on DAPO-17K):**

SPPO achieves an average score of **58.11** (symmetric critic), compared to:
- Base Model: 52.49 (SPPO improves by **+5.62**)
- Standard PPO: 56.44 (SPPO improves by **+1.67**)
- ReMax: 57.09 (SPPO improves by **+1.02**)
- RLOO: 57.02 (SPPO improves by **+1.09**)
- GRPO ($N = 8$): 57.44 (SPPO improves by **+0.67**)

The **"w/ Small Critic"** variant (1.5B Critic aligning 7B policy) achieves the **highest overall average of 58.56**, improving over symmetric SPPO by +0.45 and over GRPO by +1.12.

On individual benchmarks, SPPO (symmetric) achieves top scores on AIME24 (**50.83**, vs. ReMax's 49.38 and GRPO's 47.08), and ties for top on AIME25 (35.00, tied with GRPO) and AMC23 (86.25, tied with GRPO). The small critic variant achieves the top score on AIME24 (**52.29**), AMC23 (**87.19**), and Minerva (**28.86**), while scoring 34.58 on AIME25 (slightly below the symmetric SPPO and GRPO at 35.00) and 89.88 on MATH500 (slightly below RLOO's 90.35).

Standard PPO at the 7B scale shows improvement over the base model (56.44 vs. 52.49, +3.95), unlike the 1.5B scale where it degraded performance. However, it still lags behind all sequence-level methods.

#### Training Efficiency: Wall-Clock Time Analysis (Figure 5)

Figure 5 plots average validation performance (Avg@8 across the five benchmarks) against wall-clock training time in hours for the 7B model on the DAPO-17K dataset. This is the paper's central evidence for SPPO's computational efficiency advantage.

**Headline finding:** SPPO reaches peak performance (mean score ≈58) in approximately **22 hours**, while GRPO requires over **120 hours** to converge — a speedup of approximately **5.9×**. Baselines reach lower peak scores even at extended training times:
- SPPO (symmetric, solid red): Reaches ~58 at ~22 hours, plateaus.
- SPPO (small critic, dashed pink): Tracks closely with symmetric SPPO, reaching ~57-58 in similar time.
- GRPO (green): Converges slowly, reaching ~57.5 only after ~120 hours.
- Standard PPO (red): Reaches ~56.5 at ~30 hours but plateaus and does not improve further.
- RLOO (orange): Reaches ~57 at ~90 hours.
- ReMax (blue): Reaches ~57 at ~120 hours.

The speed differential is most dramatic in the early-to-mid training phase. At approximately 20 hours, SPPO has already reached ~57-58, while GRPO is at approximately ~55 with significant variance (the GRPO curve appears noisier, consistent with higher variance from Monte Carlo baseline estimation). The paper attributes this speedup to single-sample efficiency: "SPPO, which operates with single-sample efficiency ($N = 1$), updates the policy more frequently within the same time window" (Section 5.1).

A crucial caveat: the y-axis in Figure 5 is labeled "Average Performance (Mean Score)" and the caption clarifies it uses **Avg@8** (average of 8 samples per prompt at evaluation time), not the Avg@16 used in Table 1. This means the absolute numbers in Figure 5 are not directly comparable to Table 1. The paper uses Avg@8 for the efficiency analysis presumably because evaluating with 8 samples per prompt is faster, enabling more frequent evaluation during the training run.

#### GPU Memory Efficiency (Figure 6)

Figure 6 visualizes normalized peak VRAM usage during 7B policy training across all methods. The key numbers:

- **SPPO (symmetric, 7B + 7B):** Peak **91.5%** memory utilization
- **SPPO (small critic, 7B + 1.5B):** Peak **78.7%** — a reduction of **12.8 percentage points** from symmetric
- **GRPO (no Critic):** Peak **85.7%**
- **Standard PPO (7B + 7B):** Peak **89.8%**
- **RLOO:** Peak **98.6%**
- **ReMax:** Peak **98.7%**

The decoupled critic configuration (7B policy + 1.5B critic) achieves the lowest peak memory utilization among all methods — even lower than GRPO, which eliminates the Critic entirely. The paper attributes this to the combination of the smaller critic model and "the advanced memory management and sharding techniques provided by the verl library" which "minimizes redundant memory allocation" (Section 5.1).

This is a practically significant result: it means that aligning a 7B reasoning model is feasible on hardware that would be at or near capacity for symmetric actor-critic setups. RLOO and ReMax, which require loading only the policy model (no separate Critic), paradoxically show the highest memory utilization (98.6-98.7%). The paper does not explain this counterintuitive result, but it likely reflects implementation-level differences in how the verl library handles rollout generation, reference model loading, or batch processing for these algorithms — some of which require storing multiple samples simultaneously (RLOO with $N = 5$) or additional reference model passes (ReMax for greedy baseline computation).

The time axis in Figure 6 shows that memory utilization fluctuates over the course of training, with periodic spikes likely corresponding to evaluation phases, checkpointing, or rollout generation. The reported peak values represent the maximum observed across the entire training run.

#### Value Model Calibration and Correlation Analysis (Figure 7, Section 5.2)

To validate that the sequence-level Critic $V_\phi(s_p)$ learns meaningful difficulty estimates rather than arbitrary values, the paper conducts a correlation analysis on a held-out validation set.

**Setup:** The authors randomly sample $N = 200$ prompts and execute the policy multiple times for each prompt to compute the empirical pass rate (Avg@k, where $k = 64$ — though the figure says $k = 64$, this detail appears only in the caption). The empirical pass rate serves as the "ground truth" difficulty label. The Critic's predicted probability $V_\phi(s_p)$ is compared against this empirical rate.

**Correlation results:** The analysis reveals:
- **Pearson correlation coefficient: $r = 0.642$** — indicating a moderate-to-strong positive linear relationship between the Critic's predictions and empirical difficulty.
- **Spearman rank correlation: $\rho = 0.664$** — confirming the monotonic relationship is robust to the specific distribution shapes.

These correlations are statistically meaningful: the Critic is not merely guessing. It has learned to distinguish between prompts that the policy tends to solve and prompts that it tends to fail on, using only the prompt text as input. The paper interprets this as "strong statistical evidence that the Value Model has successfully learned to capture the relative difficulty of prompts, effectively cutting through the inherent stochasticity of LLM generation" (Section 5.2).

**Distribution shape analysis (marginal histograms in Figure 7):** Beyond the correlation coefficients, the histograms reveal an informative discrepancy between the Critic's predictions and empirical difficulty:
- **Empirical difficulty (top histogram):** Follows a **bimodal distribution** — tasks are typically either completely unsolvable (mass near 0.0) or consistently solvable (mass near 1.0). This is expected for mathematical reasoning problems, which tend to be either clearly within or clearly outside the model's capability.
- **Critic predictions (right histogram):** Exhibit a **unimodal, quasi-normal distribution centered around 0.6-0.7**. The Critic is more conservative, avoiding extreme predictions (near 0 or 1) and instead clustering around intermediate probabilities.

**Interpretation of the distributional discrepancy:** The paper diagnoses this as the Critic adopting a "conservative prediction strategy, aggregating uncertainty rather than overfitting to the binary extremes of the empirical data" (Section 5.2). This "regression to the mean" behavior means the Critic is **calibrated conservatively** — it rarely predicts certainty even for prompts the policy consistently solves or consistently fails.

**Implications for advantage estimation:** Despite the distributional discrepancy, the Critic serves as a valid baseline because:
- For hard prompts (empirical Avg@k ≈ 0), the Critic predicts lower values (≈ 0.5), so a rare success ($R = 1$) yields a strong positive advantage ($A \approx 1 - 0.5 = +0.5$).
- For easy prompts (empirical Avg@k ≈ 1), the Critic predicts higher values (≈ 0.8), so a failure ($R = 0$) yields a significant negative penalty ($A \approx 0 - 0.8 = -0.8$).
- The key property is the **monotonic relationship** (captured by the positive correlation), not exact calibration. Even a conservatively-biased Critic preserves the relative ordering of prompt difficulties, which is sufficient for variance-reducing advantage estimation.

The paper does not explore whether improved Critic calibration (e.g., through temperature scaling, ensemble methods, or longer training) would further improve SPPO's performance, nor does it quantify how much of the remaining advantage variance is attributable to Critic miscalibration versus inherent stochasticity in policy generation.

#### Controlled RLVR Benchmark Analysis (Figure 8, Section 5.3)

To rigorously validate SPPO in a setting that isolates algorithmic properties from the complexities of LLM training (distributed systems, tokenization, large-scale optimization), the paper designs a controlled experiment using five classic control tasks reformulated as sparse-reward RLVR problems.

**Task design:** Each environment is modified to match the structure of LLM reasoning alignment:
- **Long time horizons:** CartPole ($H = 200$), MountainCar ($H = 1000$), Hopper ($H = 1000$), LunarLander ($H = 1000$), Pendulum ($H = 1000$).
- **Sparse binary rewards:** Agents receive $r_t = 0$ for all $t < H$ and a binary terminal reward $r_H \in \{0, 1\}$ at the final step, with no intermediate feedback. Discount factor $\gamma = 1.0$.
- **Three-stage training pipeline mimicking LLM alignment:** (1) Expert Synthesis using dense shaped rewards, (2) Supervised Fine-Tuning via behavior cloning on successful trajectories, (3) RL Fine-tuning with the sparse binary reward.

This design controls for several LLM-specific confounding variables: deterministic transitions (no stochastic environment dynamics), continuous control (different action space from discrete token generation), and low-dimensional state spaces (no language understanding required). If SPPO's advantage comes from the sequence-level bandit formulation rather than implementation details of the verl framework, it should demonstrate advantages in these minimal settings.

**Results across environments (Figure 8):**

- **Pendulum ($H = 1000$):** SPPO (blue solid) and Standard PPO (red dashed) both converge to near-perfect success rate (~1.0), with SPPO showing slightly faster early convergence. The environment appears learnable by both methods.

- **CartPole ($H = 200$, Precision variant requiring $|\theta| \leq 0.5^\circ$):** SPPO achieves faster convergence, reaching ~0.9 success rate at ~20,000 episodes compared to Standard PPO's ~0.7 at the same point. SPPO reaches near-perfect success (~1.0) by ~30,000 episodes, while Standard PPO asymptotes around ~0.85 at 40,000 episodes. The paper interprets this as SPPO's superiority in "precision alignment" — distinguishing between "good" and "perfect" trajectories under binary feedback, which mirrors the challenge of improving reasoning quality when the base model already has non-zero success rate.

- **MountainCar ($H = 1000$):** Standard PPO flatlines at near-zero success rate for the entire 10,000-episode training run. SPPO begins improving around episode 5,000 and reaches ~0.7 success rate by 10,000 episodes, still ascending. This is a strong signal: the token-level critic in Standard PPO completely fails to propagate the sparse reward signal across the 1000-step horizon, while SPPO's sequence-level critic successfully learns to estimate the initial state's solvability.

- **LunarLander ($H = 1000$):** Standard PPO shows unstable learning — success rate fluctuates between ~0.4 and ~0.7 with no clear upward trend, exhibiting the kind of instability the paper attributes to biased credit assignment. SPPO maintains monotonic improvement, reaching ~0.7 success rate by ~30,000 episodes and continuing to improve. The gap is particularly pronounced in the mid-training phase (15,000-25,000 episodes) where Standard PPO's success rate dips while SPPO's steadily climbs.

- **Hopper ($H = 1000$, success = survival + forward progress $x > 1.0$ m):** Standard PPO flatlines at ~0.0-0.1 success rate for the entire 20,000-episode run — a complete failure. SPPO begins improving around episode 10,000 and reaches ~0.6 success rate by 20,000 episodes, with the curve still rising. This is the starkest difference across all environments. The SFT initialization provides a "weak prior" (the agent can sometimes survive but not consistently), and Standard PPO's token-level value function fails to learn from these sparse successes. SPPO's sequence-level critic successfully learns to distinguish initial states that lead to survival from those that don't.

**What these results demonstrate:** The controlled benchmark provides evidence that SPPO's advantages are not artifacts of LLM-specific implementation details. The algorithm outperforms standard PPO across environments that share the core structural features of reasoning alignment (long horizons, sparse binary rewards, imperfect initialization) but use entirely different architectures (MLP policies, continuous action spaces). The failures of standard PPO on MountainCar and Hopper — where it cannot learn at all — mirror its degradation on the 1.5B LLM experiments, suggesting a common underlying mechanism (the Tail Effect in credit assignment) rather than a problem specific to language.

**Three-stage pipeline detail (establishing the RLVR connection):** The Expert Synthesis phase uses dense rewards (velocity bonuses, upright incentives) to train policies that can occasionally succeed. The SFT phase filters successful trajectories and applies behavior cloning, producing a policy with "non-zero but imperfect solvability." The RL phase strips away all intermediate rewards, leaving only the sparse binary outcome. This pipeline explicitly mirrors the LLM alignment lifecycle: pretraining (Expert Synthesis), supervised fine-tuning (SFT), and RL fine-tuning with verifiable rewards (RL). The paper uses this structural parallel to argue that SPPO's performance in these control tasks is informative about its likely performance in LLM reasoning.

### Ablation Studies and Robustness Checks

**Impact of BCE loss function on token-level PPO (PPO + BCE ablation, Figure 4):** To isolate whether SPPO's gains come from the BCE loss function or the sequence-level formulation, the paper trains a variant of standard PPO where the token-level Critic uses BCE loss instead of MSE. The result: PPO + BCE fails to reproduce SPPO's performance, exhibiting the same instability as standard PPO. Both PPO and PPO + BCE were terminated early at 500 steps "due to observed performance collapse and degrading scores." SPPO continues improving through the full 1000-step run. This constitutes the paper's central causal evidence: the sequence-level bandit formulation (uniform advantage broadcasting) — not the loss function — is the active ingredient.

**Small critic decoupling (Table 1, Figure 6):** Using a 1.5B Critic to align a 7B policy (rather than a matched 7B Critic) produces the highest overall average score (58.56 vs. 58.11 for symmetric SPPO, Table 1), while reducing peak GPU memory from 91.5% to 78.7% (Figure 6). This ablation validates two claims simultaneously: (1) that scalar solvability estimation requires less model capacity than reasoning generation, and (2) that the decoupled architecture is a practical path to more efficient RL alignment. The paper does not ablate critic sizes below 1.5B, so the lower bound on useful critic capacity remains unknown.

**Standard PPO as a negative control (Table 1, across both scales):** At the 1.5B scale, standard PPO degrades base model performance on every benchmark, achieving 44.06 average vs. 44.96 base. At the 7B scale, standard PPO improves over the base model (56.44 vs. 52.49) but underperforms all sequence-level methods by margins ranging from +0.58 (vs. RLOO) to +1.67 (vs. SPPO). This across-scale pattern is informative: the token-level Critic's tail effect may be less severe at larger model sizes (presumably because the larger Critic has more capacity to learn spurious but less harmful position-based heuristics), but it still imposes a performance penalty relative to sequence-level baselines.

**ReMax and RLOO as critic-free single-sample baselines (Table 1):** These methods eliminate the Critic without requiring the $N > 1$ multi-sampling of GRPO, making them the most directly comparable baselines for SPPO's claim of efficient single-sample updates. SPPO outperforms both at both model scales: at 1.5B, SPPO (48.06) vs. ReMax (46.74) and RLOO (46.15); at 7B, SPPO (58.11) vs. ReMax (57.09) and RLOO (57.02). The margins are moderate (0.3-1.9 points) but consistent, suggesting that the learned sequence-level Critic provides a better baseline than the heuristic alternatives (greedy reward for ReMax, leave-one-out for RLOO).

**GRPO with $N = 8$ as the performance ceiling baseline (Table 1):** SPPO marginally outperforms GRPO at both scales: 48.06 vs. 47.08 (1.5B) and 58.11 vs. 57.44 (7B). The margins are small (+0.98 and +0.67 respectively), which means the performance claim is less about SPPO achieving *better* final accuracy than GRPO and more about achieving *equivalent* final accuracy with dramatically lower computational cost (5.9× speedup, Figure 5). The small critic variant widens the gap to +1.12 over GRPO at the 7B scale.

**No KL penalty ($\beta_{\text{KL}} = 0$) as an exploration choice (all SPPO runs, Section 4.1):** The paper explicitly disables the KL penalty between the current policy and the reference model, stating this is "to encourage exploration." This is not ablated — the paper does not compare SPPO with vs. without KL penalty — but it is a conscious design choice that departs from standard RLHF practice. The positive results suggest that for reasoning tasks where the base model already has some capability, constraining the policy to stay near its initial distribution may not be necessary and may in fact limit the gains from RL.

**PPO early termination at 500 steps (Figure 4, Section 4.3):** The fact that both standard PPO and PPO + BCE required early termination at 500 steps (out of a planned 1000) is itself an informative negative result. It indicates not just underperformance but actual training collapse — the policy worsens with continued training, a failure mode that SPPO's design explicitly aims to prevent through stable advantage estimation.

### Critical Assessment

#### Does the paper demonstrate that SPPO matches GRPO's performance with substantially lower computational cost?

**Yes, with qualifications.** Table 1 shows SPPO achieving 48.06 vs. GRPO's 47.08 (1.5B) and 58.11 vs. 57.44 (7B). The margins are small (+0.98 and +0.67), and the paper does not report confidence intervals, so we cannot assess whether these differences are statistically significant or within the noise floor of the evaluation. However, Figure 5 provides the more persuasive evidence: SPPO reaches its peak performance approximately 5.9× faster than GRPO in wall-clock time. Even if the final performance difference is negligible, the speed difference is substantial.

**The qualification:** The paper compares SPPO at $N = 1$ against GRPO at $N = 8$. This is the standard configuration for GRPO in the literature, but it represents a particular point on GRPO's sample-efficiency curve. The paper does not ablate GRPO with smaller $N$ (e.g., $N = 4$ or $N = 2$) to determine whether a lower-sample variant of GRPO could achieve comparable performance to SPPO with less computational overhead. Recent work (Liu et al., 2025; Li et al., 2025) has explored adaptive or token-efficient variants of GRPO that may close this gap. Without this ablation, the $N = 8$ baseline, while standard, may overstate the efficiency advantage for GRPO as a family of methods.

Additionally, the 5.9× speedup figure is derived from a single training run (the 7B model on DAPO-17K). Training dynamics can vary substantially across runs, datasets, and model initializations. The paper doesn't report multiple seeds or variance in convergence time, so the speedup figure should be understood as indicative rather than precisely quantified.

#### Does the paper demonstrate that the sequence-level bandit formulation is the causal source of SPPO's advantages, rather than the BCE loss?

**Yes, with the PPO + BCE ablation as the strongest piece of evidence.** Figure 4 shows that adding BCE loss to token-level PPO does not rescue it from collapse — both standard PPO and PPO + BCE fail by 500 steps and require early termination. This is a clean ablation: it isolates the loss function while keeping everything else (token-level MDP, GAE, per-token varying advantages) constant. The failure of PPO + BCE and the success of SPPO together imply that the sequence-level formulation (uniform advantage broadcasting) is the active ingredient.

**However, this is a single comparison, and the causal claim rests on one experiment.** The paper does not ablate in the other direction: what if we take SPPO's sequence-level framework but replace the BCE-trained scalar Critic with a GRPO-style group empirical baseline (estimating prompt solvability via multi-sampling rather than learning)? This would test whether the learned Critic contributes beyond the sequence-level formulation. Such an ablation would strengthen the paper's claim that *both* the sequence-level formulation *and* the learned Critic are necessary, or reveal that the sequence-level formulation alone (even with a group baseline) would suffice.

A related missing ablation: SPPO with $N > 1$, combining the learned scalar Critic with multiple samples per prompt (averaging or taking the maximum advantage across samples). This could potentially further reduce variance at additional cost, pushing the bias-variance frontier even further toward low variance. The paper doesn't explore whether there are diminishing returns to the learned Critic when combined with multi-sampling.

#### Does the paper demonstrate that the decoupled critic (smaller critic for larger policy) is genuinely effective?

**Yes, but only at one size pairing (1.5B critic for 7B policy).** The result is striking: the small critic variant achieves the highest overall score (58.56, Table 1) while reducing memory by 12.8 percentage points (Figure 6). This is not merely "no performance loss" but actually a slight performance gain, suggesting that the smaller critic may be learning a more robust or better-generalizing difficulty estimate by virtue of its reduced capacity (acting as a regularizer).

**The missing evidence:** The paper tests exactly one decoupled configuration (1.5B → 7B, a ratio of approximately 1:4.7). It does not test other pairings (e.g., 3B → 7B, 0.5B → 7B, or 7B → 14B) to establish whether there's a systematic relationship between critic size, policy size, and alignment quality. It also doesn't test the reverse: could a 7B critic align a 1.5B policy, and would the larger critic overfit? The single data point is suggestive but doesn't establish a general principle — the claim that "scalar solvability estimation is significantly simpler than generative reasoning" is supported by this one pairing but would be considerably strengthened by a scaling sweep.

Furthermore, the 58.56 score for the small critic vs. 58.11 for the symmetric critic is a difference of +0.45. Without confidence intervals, we cannot assess whether this is a real effect or noise. The paper doesn't discuss whether the small critic and symmetric critic were trained with identical hyperparameters (learning rates, batch sizes, etc.), which matters because the optimal hyperparameters might differ by critic size.

#### Does the paper convincingly demonstrate that the sequence-level Critic avoids the "Tail Effect"?

**Indirectly, through the performance results and the correlation analysis, but not through direct visualization parallel to Figure 1.** The paper shows (Figure 1, Appendix B Figure 9) that standard PPO's token-level Critic exhibits the Tail Effect: value curves for correct and incorrect trajectories only diverge at the sequence tail. For SPPO, by design, there is no per-token value curve to visualize — the Critic produces a single scalar per prompt. The correlation analysis (Figure 7) shows that this scalar Critic learns meaningful difficulty estimates (Pearson $r = 0.642$), which is evidence that it's *not* simply overfitting to position-based cues (since there are no positions to overfit to).

**What's missing:** A direct comparison showing what SPPO's advantage signals look like for individual tokens compared to standard PPO's GAE advantages — for instance, by training both algorithms and comparing the distribution of per-token advantage values on the same set of prompts. The paper argues conceptually that the Tail Effect is eliminated (because there are no per-token state values to collapse toward the terminal reward), but doesn't provide empirical evidence that the resulting per-token advantages are actually more informative for learning. The performance results are consistent with this claim but don't directly validate the mechanism.

Additionally, the controlled RLVR benchmark (Figure 8) provides mechanistic evidence that is easier to interpret. In Hopper and MountainCar, where standard PPO's token-level value function completely fails (flatlines near zero), SPPO learns successfully. In these minimal environments, there are no confounding factors (no language, no tokenization, no large-scale distributed training), so the performance gap can be more confidently attributed to the credit assignment mechanism. This is valuable corroborating evidence, though the environments are simple enough that the mapping to LLM reasoning is analogical rather than direct.

#### Does the paper adequately characterize the limitations of its experimental evaluation?

**Partially.** The paper acknowledges some limitations explicitly in the dedicated "Limitations" section (not reproduced here, but referenced): the method is designed for verifiable outcome tasks and doesn't trivially extend to open-ended generation, and the experiments are conducted on mathematical reasoning benchmarks only. These are important scope limitations that the paper is transparent about.

**Limitations not explicitly discussed include:**

1. **Single model family.** All experiments use DeepSeek-R1-Distill-Qwen models. The paper does not test whether SPPO's advantages generalize to other model families (e.g., LLaMA-based models, Qwen-based models without reasoning distillation, or models at scales substantially different from 1.5B and 7B). The specific distillation process used to create DeepSeek-R1-Distill-Qwen models may interact with SPPO's learning dynamics in ways that wouldn't generalize.

2. **No statistical reporting.** The paper reports single numbers without confidence intervals, standard deviations, or multiple random seeds. For the main results table (Table 1) with 5 benchmarks × 7 methods × 2 model scales = 70 reported numbers, the absence of variance estimates makes it impossible to distinguish meaningful differences from noise, particularly for the small margins between top methods (SPPO vs. GRPO: +0.98 at 1.5B, +0.67 at 7B).

3. **Benchmark size not reported.** The paper does not state how many problems are in each benchmark test set (AIME24, AIME25, AMC23, MATH500, Minerva). MATH500 is presumably 500 problems; the AIME and AMC competitions typically have 15-30 problems each. Small test sets amplify variance in accuracy estimates, making the lack of confidence intervals more consequential.

4. **No baseline that combines GRPO's group baseline with PPO's clipping.** The paper contrasts SPPO (sequence-level scalar Critic + PPO clipping) with GRPO (group empirical baseline without clipping, as GRPO uses its own objective). A natural intermediate baseline would be: use GRPO-style multi-sampling to estimate $\hat{p}(s_p)$ empirically, then compute $A = R - \hat{p}(s_p)$ and apply PPO's clipped surrogate. This would isolate the effect of the learned Critic vs. the empirical baseline while keeping everything else (clipping, uniform broadcasting) constant. Without this baseline, the paper can't distinguish the contribution of the learned Critic from that of PPO's clipping mechanism.

5. **The difficulty estimation cost is not accounted for.** The Critic $V_\phi(s_p)$ must be trained alongside the policy, consuming additional compute and memory beyond the policy alone. While the decoupled critic reduces this overhead, it doesn't eliminate it. The paper's comparison with GRPO in Figure 5 accounts for the Critic's training time (since SPPO's training includes Critic updates), but doesn't break down what fraction of SPPO's training time is spent on Critic updates vs. policy updates. For very large models where even a decoupled critic is substantial (e.g., a 7B critic for a 70B policy), this overhead could be non-trivial.

6. **The Avg@16 evaluation metric conflates model capability with test-time compute.** All methods are evaluated at Avg@16 (generate 16 samples, check if any are correct). This means the reported numbers mix the effect of RL training with the effect of test-time sampling. A method that improves the policy's average correctness but reduces its diversity could look worse under pass@16 than under pass@1, and vice versa. The paper does not report pass@1 or analyze the diversity-correctness tradeoff.

7. **Training dataset contamination with evaluation benchmarks.** The paper uses DeepScaleR-Preview (1.5B) and DAPO-17K (7B) for training and evaluates on AIME, AMC, MATH500, and Minerva. It does not discuss whether these training datasets contain problems from or similar to the evaluation benchmarks, which could inflate apparent performance through memorization rather than genuine reasoning improvement.

8. **No exploration of the scalar Critic's architecture.** The paper uses a standard language model (DeepSeek-R1-Distill-Qwen) as the Critic, processing the prompt tokens and outputting a scalar. It does not explore whether a simpler architecture (e.g., a smaller transformer, a pooled embedding + MLP head, or even a non-neural difficulty estimator) would suffice. The claim that solvability estimation is "significantly simpler" than reasoning generation would be strengthened by showing that a Critic much smaller than 1.5B — or a non-LLM Critic — can still provide useful baselines.

9. **The controlled benchmark (Figure 8) uses environments that are structurally analogous but trivial compared to LLM reasoning.** The longest horizon is 1000 steps (Hopper, MountainCar, LunarLander, Pendulum), while LLM reasoning chains can be thousands of tokens with far more complex dynamics. The state spaces are low-dimensional (typically <20 dimensions), while LLM state spaces are the full token embedding space. The policy architectures are MLPs, while LLM policies are transformers. These differences limit the strength of the analogy between the controlled benchmark results and LLM reasoning performance.

10. **No analysis of failure modes or qualitative examples of SPPO's behavior.** The paper does not provide examples of reasoning chains generated by SPPO-trained models, nor does it analyze what kinds of errors SPPO is correcting vs. introducing. For understanding the mechanism and practical limitations, qualitative analysis would complement the quantitative results.

#### Summary assessment

The experiments provide reasonably strong evidence for the paper's central efficiency claim: SPPO achieves training speedups (5.9×) and memory savings (12.8% peak reduction) over GRPO while matching or slightly exceeding its performance on mathematical reasoning benchmarks, using DeepSeek-R1-Distill-Qwen models at 1.5B and 7B scales. The evidence for the conceptual claim — that the sequence-level bandit formulation resolves the credit assignment problem — rests primarily on one ablation (PPO + BCE, Figure 4) and the consistent underperformance of standard PPO (Table 1), supplemented by the controlled benchmark (Figure 8). While suggestive, this evidence base is narrower than the paper's framing implies. Missing experiments (GRPO at different $N$, a sequence-level empirical baseline with PPO clipping, multiple model families, variance estimates, qualitative analysis) would substantially strengthen confidence in the paper's conclusions. The practical engineering contributions (training speedup, memory efficiency, single-sample updates) are more robustly supported than the theoretical/conceptual claims about credit assignment mechanisms.

## 6. Limitations and Trade-offs

### Single Model Family and Training Paradigm

**The assumption or constraint.** All experiments across all sections—main results (Table 1), efficiency analysis (Figure 5), memory profiling (Figure 6), and the controlled RLVR benchmark (Figure 8)—use the DeepSeek-R1-Distill-Qwen model family at exactly two scales (1.5B and 7B). The base models are not raw pretrained LMs but have already undergone reasoning-oriented distillation from a larger teacher, which means they start from a non-trivial reasoning capability baseline (44.96 and 52.49 average, Table 1). The paper does not test SPPO on models from other families (e.g., LLaMA, Qwen2.5, Gemma), on non-distilled base models, on models that begin RL fine-tuning from a much lower success rate, or at scales substantially beyond 7B.

**The consequence.** A practitioner considering SPPO cannot determine whether the algorithm's demonstrated advantages generalize across model families or pretraining recipes. Two failure modes are particularly concerning:

First, the distillation process that created DeepSeek-R1-Distill-Qwen trains the student model on reasoning trajectories, which may produce a policy distribution that is more amenable to sequence-level RL than a non-distilled model. The SFT initialization in the controlled benchmark (Section 5.3) is explicitly designed to provide "non-zero but imperfect solvability," which mirrors the distilled model's starting state—but a model without this prior might have pass@1 near zero on many prompts, and it's unclear whether SPPO's scalar Critic can learn meaningful difficulty estimates when the policy succeeds so rarely that positive reward signals are extremely sparse.

Second, the paper's finding that standard PPO degrades performance at 1.5B but improves at 7B (Table 1: -0.90 vs. +3.95 over base) suggests that credit assignment failures may be scale-dependent. SPPO outperforms standard PPO at both scales, but the performance gap narrows at 7B (SPPO: +5.62 vs. PPO: +3.95 = 1.67 gap) compared to 1.5B (SPPO: +3.10 vs. PPO: -0.90 = 4.00 gap). If this trend continues at larger scales—where standard PPO's token-level Critic may become increasingly less pathological simply through greater model capacity—SPPO's relative advantage may diminish. The paper provides no evidence about whether and where the curves cross.

**What evidence exists in the paper.** The model family constraint is visible in every reported table and figure. The paper acknowledges the limitation implicitly through its experimental scope but does not discuss it as a limitation. The potential scale-dependence of the standard PPO baseline is visible in Table 1 but not commented on.

**Mitigation status.** Not addressed. The paper does not suggest future work on cross-model-family validation or discuss whether the results are expected to generalize. The distilled nature of the base models is not flagged as a potential confound for the algorithm's applicability.

---

### Difficulty Estimation Without Verifiable Rewards

**The assumption or constraint.** SPPO's scalar Critic $V_\phi(s_p)$ is trained via binary cross-entropy against the binary outcome reward $R \in \{0, 1\}$ (Equation 2, Section 3.2). This requires a verifiable correctness signal—in the paper's case, checking whether a boxed mathematical answer matches the ground truth. The paper explicitly acknowledges this scope limitation:

> "our approach is explicitly tailored for tasks with verifiable outcomes to estimate prompt solvability. As a result, extending this sequence-level bandit formulation to open-ended generation tasks, which lack objective ground-truth verifiers, remains a direction for future research."

**The consequence.** This is not a minor scope constraint—it gates applicability to a specific class of tasks. For any task where correctness is ambiguous, multi-dimensional, subjective, or expensive to verify (dialogue quality, summarization faithfulness, creative writing, code that requires execution to test, multi-step planning in open environments), SPPO's Critic training pipeline breaks because there is no binary $R$ to compute the BCE loss against. A practitioner cannot straightforwardly use SPPO for general RLHF alignment where rewards come from a learned reward model rather than a deterministic verifier.

Moreover, even within the verifiable reward paradigm, the paper uses a strict binary reward (+1 for correct, 0 for incorrect) implemented through the `Reasoning360` library's precise reward function (Section 4.1). This means partial credit—which is common in mathematical grading rubrics (e.g., a partially correct chain-of-thought with an arithmetic error at the last step)—is collapsed to zero. The Critic learns to predict the binary outcome, but in problems where "almost correct" reasoning is common and distinguishable from "completely wrong" reasoning, a finer-grained reward signal might provide a stronger learning signal. The paper does not investigate whether SPPO's performance would improve with partial-credit rewards, which would require the Critic to predict expected reward rather than success probability—or whether the binary formulation is actually essential to the algorithm's stability.

**What evidence exists in the paper.** The limitation is explicitly stated in the dedicated Limitations section. No experiments address partial-credit rewards, non-binary outcome signals, or learned reward models. All five evaluation benchmarks (AIME24, AIME25, AMC23, MATH500, Minerva) involve problems with objectively verifiable answers, as do the training datasets (DeepScaleR-Preview, DAPO-17K).

**Mitigation status.** Not addressed beyond the explicit acknowledgment as future work. The paper correctly identifies that extending the sequence-level bandit formulation to tasks without verifiable rewards is non-trivial—it requires either a learned reward model that provides binary (or scalar) outcome signals with sufficient accuracy to train the Critic, or a fundamentally different Critic training objective that doesn't depend on binary rewards. Neither approach is explored.

---

### Unaccounted Cost of Critic Training and Memory

**The assumption or constraint.** SPPO requires training and loading a separate Critic model $V_\phi(s_p)$ alongside the policy. While the decoupled critic architecture (1.5B critic for 7B policy) reduces this overhead compared to a symmetric setup, it does not eliminate it. The headline 5.9× training speedup over GRPO (Figure 5) accounts for the Critic's training time because SPPO's training loop includes both policy and Critic updates—but the paper does not decompose training time to show what fraction is spent on Critic updates versus policy updates versus generation.

**The consequence.** For very large policy models (e.g., 70B, 405B), even a decoupled critic will represent a substantial memory and compute cost. The paper demonstrates a 1.5B critic for a 7B policy (a ratio of ~1:4.7), but a practitioner scaling to 70B might need a critic in the 10-20B range—which, while still substantially smaller than the policy, is itself a large model requiring significant GPU memory, training time, and engineering effort to maintain alongside the policy. The paper's Figure 6 memory analysis reports peak utilization percentages but not absolute memory consumption in GB, making it difficult for practitioners to estimate hardware requirements at other scales.

Furthermore, the Critic is trained from scratch (no warmup period: `trainer.critic_warmup=0`, Appendix E), meaning it must learn the prompt difficulty estimation task entirely during the RL fine-tuning process. In early training steps, the Critic's predictions will be essentially random, producing noisy advantage signals that could slow initial policy improvement. The paper does not investigate whether pre-training the Critic (e.g., on base model pass@1 data collected before RL begins) would accelerate the early phase of training or improve final performance.

Finally, the paper's speedup claim ($5.9\times$ over GRPO, Figure 5) depends on the generation bottleneck dominating training time. In a hypothetical deployment where generation is cheap (e.g., small prompts, fast inference engine) but Critic training is expensive (e.g., very large critic, limited GPU memory requiring frequent offloading), the speedup could shrink substantially. The paper's cost model does not separate these components, making it hard to predict performance in different hardware regimes.

**What evidence exists in the paper.** Figure 6 quantifies memory utilization reduction (78.7% for decoupled vs. 85.7% for GRPO and 91.5% for symmetric SPPO), but GRPO eliminates the Critic entirely while SPPO (even decoupled) does not. The 5.9× speedup in Figure 5 implicitly accounts for Critic training time within SPPO's wall-clock time. The paper does not break down where the training time is spent or test a version of SPPO where the Critic is pre-trained or frozen after an initial warmup period.

**Mitigation status.** The decoupled critic is explicitly presented as a mitigation—reducing memory and potentially compute cost by shrinking the critic relative to the policy. The paper tests exactly one decoupled configuration (1.5B → 7B) and does not explore thinner critics or pre-training strategies. The paper frames the decoupled critic as a successful demonstration of a principle ("scalar solvability estimation is significantly simpler than generative reasoning," Section 5.1) rather than a fully optimized solution.

---

### Average@K Evaluation Obscures Per-Sample Accuracy

**The assumption or constraint.** All reported performance numbers use Average@16 (Table 1) or Average@8 (Figure 5) as the primary metric—generating $K$ samples per prompt and checking whether any are correct. This evaluates the policy's capability at a specific level of test-time compute rather than its single-sample (pass@1) accuracy. The paper does not report pass@1 numbers for any method at any scale.

**The consequence.** Average@K conflates two distinct dimensions of policy quality: (1) the average correctness per sample, and (2) the diversity or coverage of the generation distribution. A method that increases a model's pass@1 from 0.3 to 0.4 while collapsing its output distribution to a single deterministic style might increase pass@1 but decrease pass@16 (because the 16 samples are now highly correlated and offer little diversity benefit). Conversely, a method that doesn't change pass@1 at all but substantially increases diversity (e.g., by encouraging exploration over a wider range of reasoning strategies) could improve pass@16 without improving average quality.

This matters for deployment decisions. If a practitioner is deploying the model with greedy decoding or single-sample generation, pass@1 is the relevant metric, and Average@16 results may overstate the effective improvement. The paper presents Average@16 as the primary metric (Section 4.1), which makes the improvements look larger and more uniform than they might be under a pass@1 evaluation.

Furthermore, the paper sets $\beta_{\text{KL}} = 0$ to "encourage exploration" (Section 4.1), which likely increases output diversity. If SPPO's gains are partly attributable to increased diversity rather than improved per-sample quality, this design choice interacts with the evaluation metric in a way that advantages SPPO over baselines that use KL regularization (RLOO and ReMax: `algorithm.kl_ctrl.kl_coef=0.001`, Appendix E)—not because SPPO produces better individual responses, but because its responses are more diverse and therefore benefit more from pass@K aggregation. The paper does not control for this interaction.

**What evidence exists in the paper.** The metric choice is stated in Section 4.1. No pass@1 results are reported anywhere. The KL penalty difference between SPPO ($\beta = 0$) and RLOO/ReMax ($\beta = 0.001$) is visible in the execution commands (Appendix E) but not discussed in the main text.

**Mitigation status.** Not addressed. The paper neither reports pass@1 nor discusses the pass@K vs. pass@1 distinction. The interaction between $\beta_{\text{KL}} = 0$ and the Average@K metric is not acknowledged.

---

### GRPO Baseline Fixed at N=8 and Missing Intermediate Baselines

**The assumption or constraint.** The paper's central efficiency claim—that SPPO matches GRPO's performance with substantially lower computational cost—relies on comparing SPPO at $N = 1$ against GRPO at $N = 8$ (Table 1, Figure 5). While $N = 8$ is standard in the GRPO literature, it represents an arbitrary point on GRPO's sample-efficiency curve. The paper does not ablate GRPO with smaller $N$ (e.g., $N = 2, 4$) to determine whether GRPO's performance would remain competitive at lower sample counts—and therefore whether the efficiency advantage over GRPO is fundamental or an artifact of comparing against GRPO's most expensive standard configuration.

**The consequence.** A practitioner aware that $N = 8$ is expensive could reasonably ask: "What happens if I run GRPO with $N = 4$?" The paper provides no evidence to answer this question. If GRPO at $N = 4$ achieves 95% of GRPO at $N = 8$'s performance at half the generation cost, then the effective speedup of SPPO over GRPO-at-$N = 4$ would be closer to $2.5-3\times$ rather than $5.9\times$—still substantial but less dramatic.

More importantly, the paper's conceptual framing (Section 2.2) argues that the key insight is the sequence-level bandit formulation, and that the learned Critic provides a more efficient way to estimate prompt solvability than GRPO's empirical group baseline. To fully validate this, the paper should test a hybrid baseline that uses GRPO-style multi-sampling to estimate $\hat{p}(s_p)$ empirically and then computes the advantage as $A = R - \hat{p}(s_p)$ with PPO-style uniform broadcasting and clipping—the same policy update as SPPO but with the Critic replaced by empirical difficulty estimation. This would isolate the contribution of the learned Critic specifically, keeping everything else (clipping, broadcasting, single-sample or multi-sample policy updates) constant. Without it, the attribution of SPPO's success to the learned Critic (as opposed to the combination of PPO clipping + sequence-level formulation) remains somewhat speculative.

**What evidence exists in the paper.** The GRPO $N = 8$ configuration is used consistently and is noted in Section 4.1 and Table 1. No ablation over $N$ is performed. The PPO+BCE ablation (Figure 4) isolates the BCE loss function but does not test a sequence-level empirical baseline. The RLOO baseline uses $N = 5$ samples (Appendix E, Figures 17-18) but uses a different advantage formulation (leave-one-out) rather than PPO-style clipping.

**Mitigation status.** Not addressed. The paper does not discuss the possibility that GRPO with smaller $N$ might close the efficiency gap, nor does it include a sequence-level empirical baseline as an ablation. Recent work on adaptive and token-efficient GRPO variants (Li et al., 2025; Lin et al., 2025) is cited in the related work (Section 6.1) but not tested as baselines.

---

### No Statistical Uncertainty Quantification

**The assumption or constraint.** Every quantitative result in the paper—Table 1 (70 accuracy numbers across benchmarks, methods, and model scales), Figure 4 (training curves), Figure 5 (efficiency curves), Figure 6 (memory profiles), Figure 7 (correlation analysis), and Figure 8 (controlled benchmark)—is reported as a point estimate without confidence intervals, standard deviations, error bars, or any other measure of statistical uncertainty. The paper does not report multiple training runs with different random seeds, nor does it discuss run-to-run variance. For the correlation analysis (Figure 7), the paper reports Pearson and Spearman coefficients on $N = 200$ prompts but provides no confidence intervals or p-values for these correlations.

**The consequence.** For the paper's headline comparisons—particularly SPPO vs. GRPO, where the performance margins are small (+0.98 at 1.5B, +0.67 at 7B in Table 1)—the absence of uncertainty quantification makes it impossible to determine whether the reported differences reflect genuine algorithmic improvements or are within the noise floor of training stochasticity and evaluation variance. This is especially acute given that several of the evaluation benchmarks (AIME24, AIME25, AMC23) likely contain only 15-30 problems each (the paper does not specify benchmark sizes), meaning that small absolute differences in the number of correctly solved problems produce large swings in reported accuracy percentages.

The training efficiency comparison (Figure 5) shows a single training run for each method on the 7B model. RL training is notoriously sensitive to random seeds—different initializations, data orderings, and generation stochasticity can produce substantially different convergence curves. Without multiple seeds, the reported 5.9× speedup could reflect a particularly favorable SPPO run or a particularly unfavorable GRPO run. The paper provides no evidence that the result is reproducible.

The memory utilization analysis (Figure 6) reports peak percentages for single runs. Memory usage can fluctuate based on GPU state, other processes, and implementation-level details of memory management, making single-run peak measurements potentially unreliable for precise comparisons—especially at the margins (GRPO at 85.7% vs. SPPO symmetric at 91.5%).

**What evidence exists in the paper.** The absence of uncertainty quantification is pervasive. No error bars appear on any figure. The execution commands in Appendix E contain no seed-setting flags, suggesting that the default initialization (likely random) is used without control.

**Mitigation status.** Not addressed at all. The paper does not acknowledge the lack of statistical reporting as a limitation, nor does it provide any of the standard mitigations (multiple seeds, confidence intervals, effect sizes, significance tests). This is a significant omission for a paper making empirical performance claims, particularly given the small margins between top methods.

## 7. Implications and Future Directions

### How This Work Changes the Landscape

This paper introduces a **diagnostic reframing** rather than a paradigm shift — it changes how the field understands *why* existing methods succeed or fail, which in turn opens a design space that had been prematurely foreclosed. The magnitude is significant but bounded: it does not introduce a new learning paradigm (like the shift from supervised to RL fine-tuning), but it does resolve a tension that had produced contradictory results and conflicting design philosophies.

**The core reframing: the source of PPO's instability.** Prior to this work, the dominant interpretation of the empirical evidence was that learned Critics are fundamentally incompatible with long-horizon sparse-reward reasoning. The evidence seemed clear: standard PPO degrades performance (the paper's 1.5B result: 44.06 vs. 44.96 base, Table 1), eliminating the Critic entirely (GRPO, RLOO, ReMax) restores stability, and therefore the Critic is the problem. This interpretation motivated a research program focused on critic-free alternatives — group-based empirical baselines, leave-one-out estimators, greedy-decoding anchors — and the field largely abandoned the investigation of learned value functions for reasoning alignment.

SPPO challenges this consensus by identifying a more precise locus of failure: **not the Critic itself, but the token-level MDP decomposition that forces the Critic to estimate an ill-posed quantity $V(s_t)$ from arbitrary intermediate states.** The Tail Effect (Figure 1, Appendix B Figure 9) shows that token-level Critics learn to predict success based on position rather than semantic content — not because neural networks are incapable of value estimation, but because the estimation target $V(s_t)$ is poorly defined for partial reasoning chains where the answer hasn't been formulated. The PPO + BCE ablation (Figure 4) provides causal evidence: simply changing the Critic's loss function from MSE to BCE — which might improve calibration — does nothing to rescue token-level PPO from collapse. The problem is *what* the Critic is asked to predict, not *how* it's trained.

This reframing reopens the design space of learned value functions for reasoning alignment. If the token-level MDP decomposition is the root cause of instability, then a Critic that operates at a different granularity — the sequence level, predicting prompt solvability $V(s_p)$ rather than per-token returns $V(s_t)$ — should be both stable and sample-efficient. SPPO's results (matching or exceeding GRPO's performance with 5.9× training speedup, Table 1, Figure 5) validate this prediction and demonstrate that the field's turn toward critic-free methods, while empirically productive, was based on an incomplete diagnosis.

**Reconciling prior contradictions.** The paper resolves the apparent contradiction between the success of GRPO (stable, effective, but expensive) and the failure of standard PPO (unstable, sample-efficient, but often harmful) by showing that the two axes — stability from sequence-level modeling, efficiency from learned baselines — are orthogonal and can be combined. The false dichotomy ("you must choose between stability and efficiency") arose because the field conflated two design decisions that GRPO happened to bundle together: (1) the elimination of token-level credit assignment (which GRPO achieves by normalizing against group means) and (2) the elimination of the learned Critic (which GRPO achieves by using the empirical mean as the baseline). SPPO disentangles these: it adopts the sequence-level formulation (achieving stability) while retaining a learned Critic (achieving sample efficiency). The result demonstrates that the stability of critic-free methods was never about the absence of a Critic — it was about the absence of token-level credit assignment.

This reconciliation also explains the mixed results in the literature on standard PPO for reasoning. Studies that found PPO to be effective (Guo et al., 2025) may have used shorter reasoning chains, less sparse reward structures, or larger models where the Tail Effect is less severe (the paper's 7B PPO baseline does improve over the base model: 56.44 vs. 52.49, Table 1). Studies that found PPO to be harmful (Kazemnejad et al., 2025; Yuan et al., 2025) may have operated in regimes — smaller models, longer chains, purely sparse rewards — where the Tail Effect dominates. The paper's diagnostic framework (the Tail Effect as a function of the token-level MDP decomposition) predicts these divergences and provides a unified explanation.

**Which research directions become more attractive.** The paper's reframing makes several directions newly tractable or more promising:

1. **Learned value functions for reasoning are back on the table.** Prior to SPPO, a researcher proposing a new Critic-based method for reasoning alignment would face the immediate objection that Critics are known to fail in this setting. SPPO provides a counterexample and a design principle: operate at the sequence level. This opens the door to a wide range of Critic architectures and training objectives that were previously dismissed.

2. **Scaling properties of value functions vs. policies.** The decoupled critic result (1.5B critic effectively aligning a 7B policy, achieving the highest overall score of 58.56, Table 1) suggests a systematic relationship between the capacity needed for value estimation and the capacity needed for policy execution. Investigating this relationship — empirically and theoretically — becomes a productive direction that the field had no reason to pursue when Critics were believed to be fundamentally broken.

3. **Adaptive credit assignment granularity.** The paper's framing suggests a spectrum between pure token-level credit assignment (standard PPO) and pure sequence-level assignment (SPPO). Intermediate granularities — segment-level, step-level, or difficulty-conditioned assignment — could potentially capture some of the sequential structure without reintroducing the Tail Effect. This design space was invisible under the prior framing of "Critics work or they don't."

4. **Verifier-guided exploration with learned baselines.** The paper's scalar Critic learns to estimate prompt solvability, which is essentially a difficulty model. This difficulty estimate could be used not just for advantage computation but also to allocate exploration budgets — spending more samples on prompts where the Critic is uncertain, or using the Critic's prediction to decide between exploration strategies. This connects SPPO to the broader literature on uncertainty-guided exploration and active learning.

**Which directions become less attractive.** The paper's results suggest that certain previously-promising directions may be less productive:

1. **Purely critic-free methods as an end state.** While GRPO and its variants are empirically successful, the paper demonstrates that their computational overhead is not an inevitable cost of stability — a well-designed Critic can provide equivalent stability at lower cost. Pushing critic-free methods to ever-lower variance (through larger $N$, Kalman filtering as in Wang et al., 2025a, or dynamic sampling as in DAPO) addresses the symptom (high variance) rather than the structural cause (the need for multi-sampling to estimate difficulty). SPPO suggests that investing in better Critics may be more efficient than investing in more sophisticated group-baseline estimators.

2. **Token-level credit assignment for sparse-reward reasoning.** The paper's diagnostic — that the Tail Effect is a systematic consequence of the token-level MDP decomposition, not a training artifact — implies that efforts to fix token-level PPO through better Critic architectures, loss functions, or training protocols are likely to hit a fundamental ceiling. The PPO + BCE ablation (Figure 4) shows that changing the loss function does nothing. While the paper doesn't prove that *no* token-level approach can work, it shifts the burden of proof: a token-level method would need to demonstrate that it has solved the Tail Effect, not just that it improves over a weak baseline.

3. **Symmetric actor-critic architectures as a default.** The decoupled critic result — a 1.5B critic matching or exceeding a 7B critic in alignment quality — challenges the assumption that value estimation requires comparable capacity to policy execution. For reasoning tasks, symmetric architectures may represent significant wasted capacity, particularly at large policy scales. This finding pushes the field toward investigating the scaling laws of critic size relative to policy size, rather than assuming 1:1 as the default.

**What the paper does not change.** It's important to be precise about the magnitude of the shift. The paper does not demonstrate that SPPO achieves capabilities beyond what GRPO can achieve — the final performance numbers are very close (48.06 vs. 47.08 at 1.5B, 58.11 vs. 57.44 at 7B, Table 1) and the margins are small enough that they may not be statistically significant. The contribution is **efficiency**, not **capability**. A team with unlimited compute could use GRPO to achieve essentially the same results; SPPO's value proposition is that it achieves them faster, cheaper, and with lower memory requirements. For research groups or industrial deployments where compute is a binding constraint, this efficiency gain is practically transformative; for groups where compute is abundant, the conceptual reframing is the primary contribution.

Similarly, the paper does not resolve the fundamental limitation that all RL-based reasoning alignment methods share: **the method only works on tasks with verifiable outcomes.** SPPO's Critic training depends on binary reward signals, and extending it to tasks where rewards come from learned reward models or human preferences is non-trivial and unexplored. The paper's reframing doesn't address this boundary condition.

### Follow-Up Research This Work Enables

**Scaling laws for decoupled critic size relative to policy size.** The paper demonstrates one data point: a 1.5B critic effectively aligns a 7B policy, achieving the highest overall score (58.56, Table 1). But this is a single pairing. A systematic scaling study would train critics at sizes of 0.5B, 1.5B, 3B, 7B to align a 7B policy (and analogous sweeps at other policy scales: 14B, 32B, 70B), measuring both final alignment quality and the correlation between critic predictions and empirical pass rates (as in Figure 7). The key questions are: Is there a minimum critic size below which solvability estimation breaks down entirely? Does the optimal critic-to-policy ratio change with policy scale? The paper hypothesizes that solvability estimation is "significantly simpler" than reasoning generation, but what is the quantitative complexity ratio? A strong result would be a power-law relationship between critic size, policy size, and alignment quality that could guide capacity allocation in future RL pipelines — analogous to how Chinchilla scaling laws (Hoffmann et al., 2022) guide pretraining compute allocation.

**SPPO with learned reward models for open-ended tasks.** The paper explicitly limits scope to tasks with verifiable binary rewards, where the Critic's BCE training target $R$ is available from a deterministic verifier. A direct extension would test SPPO with learned reward models on tasks where ground-truth verification is unavailable: summarization (evaluated by FactPegasus, AlignScore, or GPT-as-judge), dialogue (evaluated by human preference models), or code generation where correctness requires execution (using pass@1 on test cases as the binary reward). The key change: the Critic is trained via BCE against the *reward model's score* (thresholded to binary or used as a continuous target) rather than against a ground-truth verifier. The critical ablation is: does the Critic overfit to reward model biases in the same way token-level Critics overfit to position cues? If the reward model has systematic errors (e.g., preferring verbose outputs), the Critic learning to predict "rewardability" rather than "correctness" could amplify rather than correct those errors. A negative result here — SPPO fails or degrades with learned rewards — would precisely delineate the boundary where the sequence-level bandit formulation is valid.

**Combining SPPO with outcome-level test-time compute strategies.** The paper evaluates SPPO at training time (using $N = 1$ samples per update) but evaluates all methods using Average@16 (generating 16 samples at inference time and checking if any are correct). This evaluation protocol opens a natural question: does SPPO-trained policy benefit differently from test-time compute than GRPO-trained or standard PPO-trained policies? Specifically, does the uniform sequence-level advantage broadcasting affect output diversity (and thus pass@K scaling) compared to methods that differentially weight tokens? A study would compare the pass@K curves (for $K = 1, 2, 4, 8, 16, 32, 64$) of policies trained with SPPO vs. GRPO vs. standard PPO, matched for final pass@1 accuracy (to control for absolute capability differences). If SPPO-trained policies are less diverse (because uniform broadcasting encourages a single "winning" reasoning style rather than diverse approaches), the pass@K improvement with SPPO might be smaller than with GRPO, even if pass@1 is equivalent, which would have implications for deployment strategies that rely on best-of-N sampling.

**Segment-level advantage estimation as an intermediate granularity.** SPPO broadcasts a single scalar advantage to all tokens uniformly; standard PPO attempts per-token advantages via GAE. Between these extremes lies a spectrum: what if the advantage were computed at the granularity of reasoning steps (e.g., by splitting chains at natural delimiters like newlines, numbered steps, or "therefore" markers) and broadcast within each step but varied across steps? This would capture some sequential structure — early reasoning steps that are logically necessary but not sufficient for correctness could receive different weight than final answer steps — while avoiding the full pathology of token-level credit assignment (since steps are fewer and more semantically coherent than tokens). A natural experiment: train a version of SPPO where the Critic $V_\phi$ conditions on both the prompt and a step index (or step embedding), predicting $V_\phi(s_p, \text{step}_k)$, and the advantage for tokens in step $k$ is computed as $A_k = R - V_\phi(s_p, \text{step}_k)$. Compare this against pure SPPO (all tokens equal) and segment-level PPO methods like Segment Policy Optimization (Guo et al., 2025, cited in the paper's references). The key metric is whether the step-conditional Critic avoids the Tail Effect while providing more granular learning signals — measured both by final accuracy and by the correlation between Critic predictions and empirical pass rates at each step granularity.

**Difficulty-conditioned sample allocation at training time.** SPPO's Critic $V_\phi(s_p)$ learns to estimate prompt solvability during training, but the paper always uses $N = 1$ sample per prompt regardless of difficulty. An adaptive extension: use the Critic's prediction to allocate more samples to prompts where the advantage signal is expected to be most informative. Specifically, the advantage magnitude $|A| = |R - V_\phi(s_p)|$ is largest when the Critic is confident but wrong, and smallest when the Critic is uncertain ($V_\phi \approx 0.5$) or correct. A strategy that allocates more samples per update to prompts where $V_\phi(s_p)$ is near 0 or near 1 (where the Critic is confident and could be wrong, producing strong learning signals) and fewer to prompts where $V_\phi \approx 0.5$ could increase the per-update information content without increasing total generation cost. The experiment: compare SPPO with fixed $N = 1$ against SPPO with adaptive $N$ (e.g., $N = 2$ for prompts with $V_\phi \notin [0.3, 0.7]$ and $N = 1$ otherwise) at matched total generation budgets. The metric is final policy accuracy — does difficulty-conditioned allocation improve sample efficiency beyond what the scalar Critic already provides?

**SPPO on non-reasoning RLHF tasks with dense or shaped rewards.** The paper's sequence-level bandit formulation is motivated specifically by sparse-reward reasoning tasks where token-level credit assignment is ill-posed. But what happens when SPPO is applied to tasks where intermediate rewards *are* available and meaningful — for instance, RLHF for helpfulness where a reward model provides per-token or per-span scores, or dialogue tasks where user engagement signals arrive at multiple turns? The prediction from the paper's framework: SPPO's uniform advantage broadcasting should *underperform* standard PPO in dense-reward settings because it throws away useful per-token signal. Testing this prediction is important for establishing the boundary conditions of the method. A strong negative result — SPPO significantly underperforms standard PPO on dense-reward RLHF tasks — would actually strengthen the paper's conceptual contribution by demonstrating that the sequence-level formulation is specifically suited to sparse-reward settings, not a universally better approach. The experimental setup would mirror standard RLHF benchmarks (e.g., Anthropic's helpfulness/harmlessness data, training with a learned preference model) and compare SPPO, standard PPO, and GRPO.

### Practical Applications and Downstream Use Cases

**Cost-efficient RL fine-tuning for open-source reasoning models on consumer hardware.** The paper's most directly actionable finding is the combination of single-sample efficiency ($N = 1$), 5.9× training speedup (Figure 5), and the decoupled critic reducing peak GPU memory by 12.8 percentage points to 78.7% (Figure 6). For a practitioner with a single 4× H100 or 4× A100 node — or even 4× consumer GPUs — aligning a 7B reasoning model on a domain-specific mathematical or logical reasoning dataset becomes feasible within hours rather than days. The paper's exact execution commands (Appendix E) provide a turnkey recipe. A concrete deployment scenario: a team fine-tuning an open-source reasoning model on a proprietary dataset of financial or legal reasoning problems, where the ground-truth correctness can be verified (e.g., the correct numerical answer or legal conclusion), can use SPPO with a decoupled 1.5B critic to achieve similar alignment quality to GRPO at a fraction of the time and memory cost, enabling faster iteration cycles and lower cloud GPU expenditure.

**Budget-constrained academic and startup research on RL alignment.** The paper's memory efficiency result — SPPO with decoupled critic at 78.7% peak VRAM vs. 98.6-98.7% for RLOO and ReMax (Figure 6) — lowers the hardware barrier for doing RL-based reasoning alignment research. Groups that previously could not run standard RLHF pipelines (which require loading a symmetric critic) or GRPO (which requires storing $N = 8$ samples simultaneously) can now experiment with alignment algorithms using smaller GPU clusters or even high-memory consumer GPUs. The concrete threshold: the paper demonstrates that aligning a 7B model is possible on 4 GPUs with 80GB each (4× H100) using the decoupled critic. For a 7B model in FP16 (~14GB weights), plus a 1.5B critic (~3GB), plus optimizer states, activations, and the KV cache for generation, the total memory fits within 80GB per GPU with sharding — a configuration accessible to many academic labs that have a few A100 or H100 GPUs but not large clusters.

**Training data generation pipelines with learned difficulty filtering.** The scalar Critic $V_\phi(s_p)$ that SPPO trains as a byproduct of alignment provides a difficulty estimate for every prompt in the training set — essentially a model-specific measure of which problems the current policy can and cannot solve. In a self-improvement pipeline where the policy generates training data for its own next iteration, this difficulty estimate can be used to filter or prioritize prompts. Concretely: for a dataset of 100,000 math problems, after one round of SPPO training, the Critic scores each problem with $V_\phi(s_p)$, and the next round of training focuses on problems where $0.3 < V_\phi(s_p) < 0.7$ — problems the policy solves with intermediate probability, which are most likely to produce informative learning signals. This is directly analogous to curriculum learning strategies that prioritize examples of "medium" difficulty, but the Critic provides a policy-specific difficulty estimate without requiring multi-sampling to compute empirical pass rates. The correlation analysis (Figure 7, Pearson $r = 0.642$) suggests the Critic's estimates are meaningfully correlated with empirical difficulty, though the conservative calibration (predictions clustered around 0.6-0.7 rather than at extremes) means that filtering by exact probability thresholds may require calibration improvement. Even the raw Critic scores, however, can rank prompts by approximate difficulty more cheaply than computing pass@K for every prompt.

**On-device or edge deployment with small alignment Critics.** For applications where a reasoning model is deployed on-device (e.g., a 1.5B or 3B model on a laptop or phone), continuing to fine-tune or personalize the model using user-specific data raises memory constraints that make symmetric actor-critic architectures infeasible. The decoupled critic result suggests that even a very small critic (e.g., 300M parameters) might suffice to align a 1.5B policy, making on-device RL personalization feasible. A concrete scenario: a math tutoring app that adapts its underlying reasoning model to a student's specific error patterns. The app collects examples where the student's answer is verified as correct or incorrect (providing the binary reward), and uses SPPO with a tiny critic to fine-tune the base model in the background. The paper's finding that solvability estimation requires substantially less capacity than generation makes this scenario more plausible than it would be under a symmetric-critic assumption.

### When to Prefer This Method

The paper explicitly positions SPPO against named alternatives — standard PPO (Section 2.1) and GRPO (Section 2.2, Section 5.1) — and articulates a clear tradeoff in terms of bias, variance, and computational cost. From this positioning, a decision rule can be extracted:

- **Prefer SPPO over standard PPO when:** (1) The task involves long reasoning chains (hundreds to thousands of tokens) with sparse, outcome-only binary rewards — the Tail Effect (Figure 1, Appendix B Figure 9) makes standard PPO's token-level GAE advantages systematically unreliable. (2) Training stability is a priority — the paper shows standard PPO degrading base model performance at 1.5B (44.06 vs. 44.96, Table 1) and requiring early termination due to collapse (Figure 4). (3) The base model has non-zero pass@1 on a meaningful fraction of prompts, giving the scalar Critic a learnable signal for solvability estimation (the Critic cannot learn difficulty if the policy never succeeds).

- **Prefer SPPO over GRPO when:** (1) Training throughput or computational cost is a binding constraint — SPPO's 5.9× wall-clock speedup (Figure 5) and single-sample updates ($N = 1$ vs. $N = 8$) make it preferable when GPU hours are limited. (2) GPU memory is constrained — the decoupled critic reduces peak memory to 78.7% vs. 85.7% for GRPO (Figure 6), enabling training on smaller GPU configurations. (3) The desired final performance is within the range where SPPO and GRPO are comparable (Table 1: SPPO matches or slightly exceeds GRPO on mathematical reasoning with DeepSeek-R1-Distill-Qwen models at 1.5B and 7B scales). (4) A learned difficulty estimate $V_\phi(s_p)$ is independently useful (e.g., for curriculum learning or exploration allocation), since SPPO produces this as a byproduct.

- **Prefer GRPO over SPPO when:** (1) The model family or task has not been validated with SPPO and the practitioner is risk-averse — GRPO has a broader track record across multiple model families and reasoning benchmarks, while SPPO is demonstrated only on DeepSeek-R1-Distill-Qwen with mathematical reasoning. (2) The task lacks any possibility of training a useful Critic — for instance, if the model's pass@1 is so low that positive rewards are extremely rare and the Critic cannot learn meaningful solvability estimates, GRPO's group-based empirical baseline requires no additional model to train. (3) Deployment already requires generating multiple samples per prompt for other reasons (e.g., for ensembling or verification), in which case GRPO's multi-sampling cost is already being paid and its advantage is that it doesn't add a Critic training cost on top.

- **Prefer standard PPO over SPPO when:** (1) The task provides dense, informative intermediate rewards (not just sparse outcomes) — for instance, step-level process rewards from a trained PRM, or turn-level engagement signals in dialogue — where the token-level credit assignment is well-posed and SPPO's uniform broadcasting would discard useful signal. (2) The reasoning chains are short enough that the Tail Effect does not manifest — the paper doesn't establish the horizon threshold but the failure only becomes severe in long-horizon settings. (3) Memory for a symmetric critic is not a constraint (e.g., training small models on large GPU clusters) and the practitioner prefers the more extensively studied and debugged algorithm.

These tradeoffs are grounded in the paper's explicit findings and framing but come with the caveats identified in the experimental analysis: the SPPO vs. GRPO performance margins are small and not statistically validated, the model family tested is narrow, and the practical performance of SPPO on tasks outside mathematical reasoning is unknown.
