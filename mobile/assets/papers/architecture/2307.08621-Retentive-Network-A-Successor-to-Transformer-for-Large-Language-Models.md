# Retentive Network: A Successor to Transformer for Large Language Models

**ArXiv:** [2307.08621](https://arxiv.org/abs/2307.08621)

## 🎯 Pitch

RetNet breaks the 'impossible triangle' by matching Transformer performance while delivering 8.4× faster decoding and constant-cost O(1) inference—no key-value cache needed. This is made possible by a retention mechanism that unifies parallel training, recurrent decoding, and chunkwise processing in a single architecture.

---

## 1. Executive Summary

This paper proposes **Retentive Network (RetNet)** as a foundation architecture for large language models that simultaneously achieves training parallelism, low-cost inference, and competitive performance — breaking through the “impossible triangle” that prior architectures could not resolve. The core contribution is the **retention mechanism**, which supports three computation paradigms — parallel representation (enables GPU-efficient training like Transformers), recurrent representation (enables O(1) inference by eliminating the growing key-value cache), and chunkwise recurrent representation (enables linear-complexity long-sequence modeling by encoding chunks in parallel while passing cross-chunk information recurrently). On language modeling with models up to 6.7B parameters trained on 100B tokens, RetNet matches Transformer perplexity and downstream task performance while delivering 8.4× faster decoding, 70% memory reduction, and length-invariant throughput at 8k sequence length, establishing that a single architecture can unify training parallelism with constant-cost inference only when the sequence modeling mechanism has a dual parallel-recurrent form rather than relying on softmax attention.

## 2. Context and Motivation

### The Core Problem: Transformer Inference Is Fundamentally Expensive

The paper addresses a structural tension at the heart of modern large language model deployment. Transformers achieve training parallelism by computing attention scores across all pairs of tokens simultaneously, enabling GPUs to be fully utilized during training. But this design creates a severe bottleneck at inference time: each new token generated during autoregressive decoding must attend to all previously generated tokens, making the per-step computational cost scale as **O(N)** where N is the sequence length. Worse, Transformers must store a growing **key-value cache** — the key and value vectors for every previously generated token — which produces an O(N) memory footprint that balloons with sequence length and batch size.

This is not a minor implementation inconvenience. For a 7B parameter model processing 8k-length sequences, the KV cache can consume more GPU memory than the model weights themselves. The paper's Figure 6a shows that at 8k sequence length, Transformer memory consumption reaches roughly 45GB on an A100-80GB GPU, with KV caches accounting for a substantial fraction. This directly constrains deployment: it limits the maximum batch size (reducing throughput), increases latency (Figure 6c shows latency growing with both sequence length and batch size), and makes Transformers "unfriendly to deployment" as the authors state.

The problem compounds with scale. As LLMs are deployed in increasingly long-context scenarios — document summarization, multi-turn dialogue with history, retrieval-augmented generation with dozens of retrieved passages — the O(N) per-step cost of attention becomes the dominant factor in inference cost. The paper's framing is precise: "training parallelism of Transformers is at the cost of inefficient inference."

### Why This Matters: The "Impossible Triangle"

The paper organizes the challenge around what it calls the "impossible triangle" (Figure 2): three desirable properties that no architecture before RetNet had successfully unified:

1. **Training parallelism**: The ability to process all tokens in a sequence simultaneously during training, utilizing GPU parallelism efficiently. This is what made Transformers dominant — recurrent models like LSTMs process tokens sequentially, creating a training bottleneck.

2. **Good performance**: Competitive language modeling perplexity and downstream task accuracy. Any architecture that sacrifices too much modeling quality for efficiency will not be adopted, regardless of its speed advantages.

3. **Low-cost inference**: O(1) per-step computational and memory cost that does not grow with sequence length. This is what Transformers lack, and what recurrent models historically provided.

The triangle is "impossible" because prior architectures consistently achieved at most two of these three properties. The paper's Table 1 catalogs this systematically: Transformer gets training parallelism and good performance but fails on inference cost (O(N)). Linear Transformers get training parallelism and O(1) inference but sacrifice performance — the paper notes they "struggle to effectively encode position information, rendering the models less performant." Recurrent neural networks get O(1) inference and good performance in principle but sacrifice training parallelism entirely, making them impractical to train at scale. Recent approaches like RWKV sacrifice training parallelism by running recurrently during training, while state-space models like H3 and S4 achieve training parallelism and O(1) inference but at the cost of O(N log N) long-sequence memory complexity and performance that has not been convincingly demonstrated at the multi-billion-parameter scale.

The practical significance of resolving this triangle is enormous. It means a single model architecture can be trained efficiently on massive GPU clusters, deployed with constant memory and latency regardless of context length, and still match or exceed Transformer quality — no tradeoffs required. This would change the economics of LLM deployment, particularly for latency-sensitive applications (chatbots, code completion) and memory-constrained environments (edge devices, consumer GPUs).

### Prior Approaches and Where They Fall Short

The paper identifies three main strands of prior research, each of which achieves at most two vertices of the triangle:

**Linearized Attention (Strand 1)**. Methods like Linear Transformer replace the softmax attention scores $\text{softmax}(QK^T)$ with kernel approximations $\phi(Q)\phi(K)^T$, which allows the attention computation to be rewritten in a recurrent form. The mathematical motivation is elegant: if attention scores factor as inner products of feature maps, then the autoregressive inference can be computed as a recurrence, achieving O(1) per-step cost. However, the paper identifies a critical shortcoming: "the modeling capability and performance are worse than Transformers, which hinders the method's popularity." The issue is that linear attention struggles to encode position information effectively. Position is crucial for language — knowing that "not" appeared immediately before "good" matters for sentiment, and this positional sensitivity gets lost in the kernel approximation. The performance gap has prevented linear attention from seeing widespread adoption despite its theoretical efficiency advantages.

**Return to Recurrent Models (Strand 2)**. This line of work goes back to recurrent architectures (LSTMs, GRUs, or modern RNN variants) that have O(1) inference inherently, but then attempts to recover training parallelism through various tricks. The paper specifically references RWKV, which uses element-wise operators for acceleration — essentially replacing the quadratic attention matrix multiplication with cheaper per-element operations. The tradeoff is explicit: "representation capacity and performance are harmed." Element-wise operations are faster than matrix multiplications, but they provide less expressive interactions between tokens. The paper also notes that these approaches typically sacrifice training parallelism entirely, running the model recurrently during training as well as inference, which makes scaling to billions of parameters on modern GPU clusters far less efficient than Transformers' fully parallel training.

**Alternative Sequence Modeling Mechanisms (Strand 3)**. This strand replaces attention entirely with different computational primitives. S4 (Structured State Space) models use a continuous-time state-space formulation that can be computed as a convolution during training (giving parallelism) and as a recurrence during inference (giving O(1) cost). Variants like H3 (Hungry Hungry Hippos) and Hyena build on this approach, with Hyena using long convolutions parameterized by implicit neural representations. However, the paper identifies two limitations. First, the long-sequence memory complexity is O(N log N) rather than O(N) for S4/H3 (due to FFT-based convolution), and O(N) per inference step for Hyena (the same as Transformers — it loses the O(1) inference property). Second, and more critically, "none of the previous work can break through the impossible triangle, resulting in no clear winner compared with Transformers." The performance at scale — particularly at the multi-billion-parameter regime where LLMs operate — has not been convincingly demonstrated to match Transformers.

### How This Paper Positions Itself: A Theoretical Unification

What distinguishes RetNet from all prior work is not an incremental improvement along one axis but a **fundamentally different approach to the problem**: deriving a sequence modeling mechanism that has both a parallel form and a recurrent form as exact mathematical equivalents, not approximations.

The paper's Section 2.1 does something that none of the prior approaches attempt: it starts from a recurrent formulation (Equation 1) and derives a parallel representation as an algebraic identity, rather than starting from attention and approximating it with a recurrence. Specifically, the retention mechanism begins with a linear recurrence $s_n = A s_{n-1} + K_n^T v_n$, where $s_n$ is a state vector that accumulates information across time. The output $o_n = Q_n s_n$ then reads from this state. The matrix $A$ is diagonalized as $A = \Lambda(\gamma e^{i\theta}) \Lambda^{-1}$, and by absorbing $\Lambda$ into the learned projections, the recurrence expands into a form where the output at position $n$ is a sum over all previous positions $m$ of a term that decays exponentially with distance ($\gamma^{n-m}$) and uses complex exponentials ($e^{in\theta}$) for relative position encoding (Equation 4).

This algebraic manipulation produces a parallel formulation (Equation 5) that computes retention for all positions simultaneously — exactly what GPUs need for training — while being mathematically identical to the recurrent form (Equation 6) that processes tokens one at a time with a fixed-size state. There is no approximation, no kernel function, no element-wise simplification. The parallel and recurrent forms are the same computation expressed two ways.

This theoretical unification is what enables RetNet to achieve all three vertices of the impossible triangle simultaneously:
- **Training parallelism**: The parallel representation (Equation 5) is a matrix multiplication $(QK^T \odot D)V$ that runs efficiently on GPUs, just like Transformer attention but without the softmax.
- **Low-cost inference**: The recurrent representation (Equation 6) maintains a fixed-size state $S_n$ that is updated at each step with $O(1)$ cost, completely eliminating the growing KV cache.
- **Good performance**: Because the two forms are mathematically equivalent, there is no approximation gap — the model that is trained is exactly the model that is deployed, unlike linear attention where the kernel approximation creates a train-test mismatch.

The paper also positions retention as a more principled approach to capturing sequence structure than prior methods. The $\gamma$ decay term ($0 < \gamma < 1$) gives the model an inductive bias toward recency — nearby tokens contribute more to the state than distant ones, with the influence decaying exponentially. This is a natural prior for language (nearby context is usually more relevant), but unlike hard windowing approaches, it still allows long-range information to be retained (it just contributes less to the current state). The complex rotation $e^{in\theta}$ encodes relative position in a way that the paper explicitly connects to xPos and RoPE, two successful position encoding schemes for Transformers. By baking these inductive biases into the mathematical structure of the mechanism rather than adding them as auxiliary features, RetNet achieves strong performance without the computational overhead of softmax attention.

The paper's position can be summarized as: **the impossible triangle is only impossible if you start from attention and try to make it recurrent. If you start from recurrence and make it parallel, all three properties emerge naturally.** The key insight is that the dual form must be an exact equivalence, not an approximation, because any approximation gap will manifest as either a training-inference discrepancy (hurting performance) or a computational inefficiency (hurting speed).

## 3. Technical Approach

### 3.1 Reader Orientation

The system being built is a **stack of neural network blocks** that processes sequences of text — like sentences or documents — to produce contextualized representations useful for language modeling. The core problem it solves is that existing architectures force a choice: you can either have fast training (Transformers) or cheap inference (recurrent networks), but not both simultaneously with good performance. The "shape" of the solution is a single mathematical mechanism — the **retention** operation — that has two exact algebraic forms: one that processes all tokens in parallel (for training) and one that processes tokens one at a time with a fixed-size memory (for inference), with no approximation gap between them.

### 3.2 Big-Picture Architecture (Diagram in Words)

RetNet is an L-layer stack where each layer contains two modules connected by residual connections with pre-LayerNorm, following the same organizational pattern as a standard Transformer. The components are:

1. **Input embedding**: Converts the sequence of discrete tokens $\{x_i\}_{i=1}^{|x|}$ into a matrix $X^0 \in \mathbb{R}^{|x| \times d_{\text{model}}}$ of continuous vectors, where $|x|$ is the sequence length and $d_{\text{model}}$ is the hidden dimension (e.g., 2048, 2560, or 4096 depending on model size).

2. **Multi-Scale Retention (MSR) module**: The paper's replacement for multi-head self-attention. It takes the layer input $X^l$, projects it into queries, keys, and values, applies the retention mechanism using multiple decay rates (one per head), applies a gating non-linearity, and normalizes the per-head outputs via GroupNorm. The output is added back to the input via a residual connection. This module exists in three computational forms that are mathematically identical: parallel (for training), recurrent (for inference), and chunkwise recurrent (for long-sequence training).

3. **Feed-Forward Network (FFN) module**: A two-layer MLP with GELU activation: $\text{FFN}(X) = \text{gelu}(X W_1) W_2$. In Transformers, the intermediate dimension is typically $4d$, but RetNet uses $2d$ to keep total parameter count matched since MSR uses more parameters than standard attention. Output is added via residual connection.

4. **Output layer**: After $L$ layers, $X^L$ is projected to vocabulary logits for language modeling (standard softmax over token predictions).

Information flows as follows: discrete tokens → embedding lookup → $X^0$ → [MSR → residual add → LayerNorm → FFN → residual add] × L layers → $X^L$ → output projection → token probabilities. The critical architectural innovation is entirely within the MSR module — the FFN and overall layout are standard — where the retention mechanism provides the dual parallel-recurrent form.

### 3.3 Roadmap for the Deep Dive

- **First**, the core retention recurrence and its algebraic diagonalization (Equations 1–4), because this derivation is the mathematical engine that enables all three computation paradigms.
- **Second**, the three computation paradigms — parallel, recurrent, and chunkwise recurrent — because these are the concrete forms that training and inference systems actually execute, and understanding the exact matrices and state vectors involved clarifies why each paradigm achieves its computational properties.
- **Third**, the multi-scale retention (MSR) module and its components (multiple decay rates, swish gate, GroupNorm, retention score normalization), because these are the architectural choices that turn the raw retention operation into a competitive sequence model.
- **Fourth**, the overall network architecture (stacked layers, FFN, parameter allocation), because this shows how RetNet fits into the familiar Transformer blueprint and where the parameter counts are rebalanced.
- **Fifth**, the design choices and their justifications — why specific decisions (complex-valued positions, fixed $\gamma$ across layers, widened value dimension, Sub-LayerNorm via GroupNorm) were made relative to the alternatives.
- **Sixth**, training and inference procedures (which paradigm is used when, chunk size choices, hyperparameters), because the practical deployment strategy is inseparable from the architectural innovation.

### 3.4 Detailed, Sentence-Based Technical Breakdown

This is primarily a **novel architecture paper** whose core idea is that a sequence modeling mechanism can be derived from a linear recurrence that is algebraically equivalent to a parallel form, enabling a single model to be trained with full GPU parallelism and deployed with O(1) per-step inference cost — without any approximation gap.

#### The Retention Mechanism: From Recurrence to Parallelism

The retention mechanism is the mathematical heart of RetNet. It is derived by starting from a recurrence, diagonalizing the state transition matrix, and recognizing that the resulting expression factors into a form that can be computed either sequentially (one token at a time) or in parallel (all tokens simultaneously). This section walks through the derivation because understanding how the dual form emerges from the math is essential to understanding why the architecture works without approximation.

**Step 1: Define a linear recurrence with state.**

The authors begin by considering a sequence modeling problem: map an input sequence $v(1), v(2), \ldots, v(n)$ to an output sequence $o(1), o(2), \ldots, o(n)$ through a state vector $s_n$ that accumulates information over time. The state evolves via a linear recurrence:

$$s_n = A s_{n-1} + K_n^\top v_n$$

$$o_n = Q_n s_n = \sum_{m=1}^n Q_n A^{n-m} K_m^\top v_m$$

where $s_n \in \mathbb{R}^{d \times d}$ is the state matrix at timestep $n$, $A \in \mathbb{R}^{d \times d}$ is a state transition matrix governing how past information decays, $K_n \in \mathbb{R}^{1 \times d}$ is a row vector that projects the scalar input $v_n$ (derived from the current token's value vector) into the state, $v_n \in \mathbb{R}$ is a scalar (one dimension of the value projection), $Q_n \in \mathbb{R}^{1 \times d}$ is a row vector that reads from the state to produce the scalar output $o_n$, and $A^{n-m}$ is the state transition matrix raised to the power of the time difference between positions $n$ and $m$.

> **What it computes:** The state $s_n$ is a running summary of all past inputs $v_1, \ldots, v_n$, each weighted by how the transition matrix $A$ has evolved it over the intervening time steps. The output $o_n$ is a linear readout from this state — it computes a weighted sum over all past inputs $v_m$, where the weight for position $m$ is the scalar $Q_n A^{n-m} K_m^\top$. The key conceptual move is that the recurrent state $s_n$ is a **fixed-size matrix** (it does not grow with sequence length), so the per-step computation to update it from $s_{n-1}$ to $s_n$ is O(1).

> **Why this form:** The linear recurrence with a matrix state is more expressive than a scalar or vector state — it can maintain $d \times d$ degrees of freedom to track different aspects of the sequence history. This is a deliberate choice over element-wise recurrences (like RWKV) that operate on vectors: matrix states provide higher-dimensional memory, which the paper argues "contributes to expressive ability and better performance." The form is also chosen because a linear recurrence with a diagonalizable $A$ can be unrolled into an exact parallel form, which is the step that follows.

**Step 2: Make projections content-aware.**

The scalars $v_n$ and the vectors $Q_n, K_n$ are not fixed — they depend on the actual content of the input at position $n$. Specifically, each input vector $X_n \in \mathbb{R}^{d_{\text{model}}}$ is projected:

$$Q = X W_Q, \quad K = X W_K$$

where $X \in \mathbb{R}^{|x| \times d_{\text{model}}}$ is the input matrix of all token embeddings, $W_Q, W_K \in \mathbb{R}^{d_{\text{model}} \times d}$ are learnable projection matrices, $Q, K \in \mathbb{R}^{|x| \times d}$ are the resulting query and key matrices, and $d$ is the per-head dimension. This makes the recurrence content-aware — what information is written into the state and how it is read out depends on the token identities, not just their positions.

**Step 3: Diagonalize the transition matrix.**

The critical algebraic manipulation that enables the dual form is diagonalizing $A$. The authors assume $A$ can be decomposed as:

$$A = \Lambda (\gamma e^{i\theta}) \Lambda^{-1}$$

where $\Lambda \in \mathbb{C}^{d \times d}$ is an invertible matrix of eigenvectors, $\gamma \in (0, 1)$ is a positive real scalar controlling the decay rate (how quickly past information is forgotten), $\theta \in \mathbb{R}^d$ is a vector of rotation angles (one per state dimension), $e^{i\theta} = [e^{i\theta_1}, \ldots, e^{i\theta_d}]$ is a diagonal matrix of complex exponentials representing rotations in the complex plane, and $i$ is the imaginary unit.

> **What this decomposition means:** The state transition $A$ is factored into three parts: a change of basis ($\Lambda^{-1}$ maps the state into eigen coordinates), a diagonal operation ($\gamma e^{i\theta}$ applies per-dimension decay and rotation in the eigenbasis), and a change back to the original basis ($\Lambda$). The diagonal form is what makes the unrolling possible because $( \gamma e^{i\theta} )^{n-m}$ can be computed for any gap size by element-wise exponentiation along the diagonal.

> **Why this specific form:** The combination of exponential decay ($\gamma$) and rotation ($e^{i\theta}$) gives the mechanism two complementary inductive biases. The decay captures recency — information from $k$ steps ago is weighted by $\gamma^k$, which shrinks exponentially, making nearby context more influential (a natural prior for language). The rotation encodes relative position — the angle between query at position $n$ and key at position $m$ depends on $n - m$ through $e^{i(n-m)\theta}$, which is exactly the mechanism behind Rotary Position Embedding (RoPE) and xPos. Using complex numbers rather than real-valued rotation matrices is a computational convenience: complex exponentials factor neatly in the algebra.

Substituting the diagonalized form and absorbing $\Lambda$ into the learned projections (since $W_Q$ and $W_K$ can learn to undo any fixed linear transformation), the output becomes:

$$o_n = \sum_{m=1}^n Q_n (\gamma e^{i\theta})^{n-m} K_m^\top v_m = \sum_{m=1}^n (Q_n (\gamma e^{i\theta})^n) (K_m (\gamma e^{i\theta})^{-m})^\top v_m$$

> **What this computes:** The output at position $n$ is a sum over all previous positions $m$, where each past contribution is weighted by three factors: (1) a content-based query-key similarity $Q_n \cdot K_m^\top$, (2) an exponential recency decay $\gamma^{n-m}$, and (3) a relative position rotation $e^{i(n-m)\theta}$. The factorization in the second line separates the position-dependent parts: $Q_n (\gamma e^{i\theta})^n$ depends only on the current position $n$, and $K_m (\gamma e^{i\theta})^{-m}$ depends only on the past position $m$, which is the structure that enables parallel computation (all $Q, K$ at all positions can be pre-multiplied by their position factors independently).

**Step 4: Simplify $\gamma$ to a scalar.**

The final simplification treats $\gamma$ as a scalar rather than a per-dimension vector:

$$o_n = \sum_{m=1}^n \gamma^{n-m} (Q_n e^{i n \theta}) (K_m e^{i m \theta})^\dagger v_m$$

where $^\dagger$ denotes the conjugate transpose (complex conjugate of the transpose), and $e^{i n \theta}$ means each dimension of $Q_n$ is multiplied by $e^{i n \theta_j}$ for its corresponding $\theta_j$.

> **Why scalar $\gamma$:** Making $\gamma$ a scalar (shared across all $d$ dimensions of the state) is a simplification that reduces parameters and has been found sufficient in practice. The multi-scale property — having different decay rates — is instead achieved by using different $\gamma$ values across different attention heads, not across dimensions within a head. This keeps the per-head computation simple while still providing diversity of temporal scales across heads.

#### Three Computation Paradigms

From the same algebraic expression (Equation 4), three different computational implementations emerge depending on how the summation is organized.

**Parallel Representation (for training):**

The parallel form computes all outputs simultaneously by treating the sequence as a matrix operation:

$$Q = (X W_Q) \odot \Theta, \quad K = (X W_K) \odot \overline{\Theta}, \quad V = X W_V$$

$$\Theta_n = e^{i n \theta}, \quad D_{nm} = \begin{cases} \gamma^{n-m}, & n \geq m \\ 0, & n < m \end{cases}$$

$$\text{Retention}(X) = (Q K^\top \odot D) V$$

where $X \in \mathbb{R}^{|x| \times d_{\text{model}}}$ is the sequence input, $W_Q, W_K \in \mathbb{R}^{d_{\text{model}} \times d}$ and $W_V \in \mathbb{R}^{d_{\text{model}} \times 2d}$ are learned projections (note: $V$ dimension is $2d$, double that of $Q$ and $K$), $\Theta \in \mathbb{C}^{|x| \times d}$ is the complex rotation matrix that applies position-dependent phases to queries, $\overline{\Theta}$ is its complex conjugate applied to keys, $\odot$ is element-wise multiplication, $D \in \mathbb{R}^{|x| \times |x|}$ is the causal decay mask combining the lower-triangular causal constraint ($n \geq m$) with exponential decay along relative distance, and $\text{Retention}(X)$ is the output of shape $\mathbb{R}^{|x| \times 2d}$.

> **What it computes:** First, the query and key matrices are rotated by complex exponentials encoding absolute position — $Q_n$ gets multiplied by $e^{i n \theta}$ and $K_m$ gets multiplied by $e^{-i m \theta}$ (via conjugation), so their dot product $Q_n K_m^\top$ automatically encodes relative position $e^{i(n-m)\theta}$. Then the raw attention scores $Q K^\top \in \mathbb{C}^{|x| \times |x|}$ are element-wise multiplied by the causal decay mask $D$, which zeros out future positions and applies exponential decay for past positions. Finally, this masked score matrix is multiplied by $V$ to produce the output. The entire operation is a sequence of matrix multiplications, which GPUs execute efficiently — training throughput benefits from the same parallelism that makes Transformer training fast.

> **Why this form:** Compared to standard attention, retention replaces $\text{softmax}(Q K^\top / \sqrt{d})$ with $Q K^\top \odot D$. The softmax is what prevents Transformers from having a recurrent form — the normalization over all keys makes the computation inherently non-factorable across positions. By removing softmax and using fixed exponential decay instead, the computation becomes a linear operation that can be reorganized into a recurrence. The decay matrix $D$ is precomputed and fixed (not learned), so there is no additional parameter cost. The causal mask ensures autoregressive correctness during training.

**Recurrent Representation (for inference):**

The recurrent form computes outputs one token at a time using a fixed-size state:

$$S_n = \gamma S_{n-1} + K_n^\top V_n$$

$$\text{Retention}(X_n) = Q_n S_n, \quad n = 1, \ldots, |x|$$

where $S_n \in \mathbb{C}^{d \times 2d}$ is the complex-valued state matrix at timestep $n$, $K_n \in \mathbb{C}^{1 \times d}$ is the conjugated key vector for the current token, $V_n \in \mathbb{R}^{1 \times 2d}$ is the value vector for the current token, $K_n^\top V_n \in \mathbb{C}^{d \times 2d}$ is the outer product that adds the current token's information to the state, $\gamma \in (0, 1)$ is the decay factor that shrinks all previous state content, and $Q_n \in \mathbb{C}^{1 \times d}$ is the current query vector.

> **What it computes:** At each new token $n$, the state $S_{n-1}$ is decayed by $\gamma$ (reducing the influence of all past tokens uniformly) and then the current token's key-value outer product $K_n^\top V_n$ is added. The output for token $n$ is simply the query vector $Q_n$ multiplied by the current state matrix — a matrix-vector product costing O($d \times 2d$) operations. The state $S_n$ has fixed dimensions regardless of sequence length, so both the memory and per-step computation are O(1). For a 6.7B model with $d = 256$ and $2d = 512$ for values, the state per head is $256 \times 512 = 131,072$ complex numbers, which is negligible compared to storing a full KV cache of attention keys and values for thousands of tokens.

> **Why this form:** The recurrent representation is mathematically identical to the parallel form — it computes the exact same output sequence, not an approximation. This is the key property that makes RetNet deployment practical: the model trained with the parallel form can be switched to the recurrent form for inference with zero performance degradation. No distillation, no fine-tuning, no adaptation period. The recurrent form eliminates the KV cache entirely; the state $S_n$ serves as a **compressed summary** of all past keys and values. For Transformers, the KV cache grows linearly with sequence length because every past key and value vector must be stored individually to compute softmax attention. For RetNet, the state $S_n$ is a fixed-size matrix that accumulates information via outer products, so only this single matrix needs to be stored and updated.

**Chunkwise Recurrent Representation (for long-sequence training):**

The chunkwise form is a hybrid that processes fixed-length blocks in parallel while passing information between blocks recurrently:

$$Q_{[i]} = Q_{B i : B(i+1)}, \quad K_{[i]} = K_{B i : B(i+1)}, \quad V_{[i]} = V_{B i : B(i+1)}$$

$$R_i = K_{[i]}^\top (V_{[i]} \odot \zeta) + \gamma^B R_{i-1}, \quad \zeta_{ij} = \gamma^{B - i - 1}$$

$$\text{Retention}(X_{[i]}) = \underbrace{(Q_{[i]} K_{[i]}^\top \odot D) V_{[i]}}_{\text{Inner-Chunk}} + \underbrace{(Q_{[i]} R_{i-1}) \odot \xi}_{\text{Cross-Chunk}}, \quad \xi_{ij} = \gamma^{i+1}$$

where $B$ is the chunk size (set to 512 in experiments), $[i]$ denotes the $i$-th chunk (positions $B i$ through $B(i+1)-1$), $Q_{[i]}, K_{[i]}, V_{[i]} \in \mathbb{R}^{B \times d}$ are the query, key, and value matrices for the chunk, $D \in \mathbb{R}^{B \times B}$ is the causal decay mask within the chunk (same as in the parallel representation but of size $B \times B$), $R_i \in \mathbb{C}^{d \times 2d}$ is a recurrent state summarizing all chunks up to $i-1$, $\zeta \in \mathbb{R}^B$ is a vector of decay factors that weight each token within the chunk according to its position before being written to $R_i$, $\gamma^B$ decays the previous chunk's state by the chunk length, and $\xi \in \mathbb{R}^B$ is a vector of decay factors for the cross-chunk contribution (how much the past chunk state should influence each position in the current chunk).

> **What it computes in two parts:**
> 1. **Inner-chunk computation:** Within a chunk of $B$ tokens, use the parallel representation (Equation 5) — $Q_{[i]} K_{[i]}^\top \odot D$ is a $B \times B$ matrix multiplication that runs efficiently on GPU tensor cores. This captures fine-grained interactions between tokens that fall within the same chunk.
> 2. **Cross-chunk computation:** The effect of all previous chunks is compressed into the state $R_{i-1}$, which is a fixed-size matrix summarizing positions 0 through $B(i-1)-1$. For each position $j$ in the current chunk, the cross-chunk contribution is $(Q_{[i], j} \cdot R_{i-1}) \times \gamma^{j+1}$ — the query reads from the past state, scaled by a position-dependent decay that reflects how far into the current chunk position $j$ is. This captures long-range dependencies that span chunk boundaries.
>
> After computing the chunk output, the state is updated: $R_i$ takes the previous state $R_{i-1}$, decays it by $\gamma^B$ (the total decay across $B$ tokens), and adds a weighted sum of the current chunk's key-value outer products. The weighting vector $\zeta$ ensures that tokens later in the chunk are decayed less when added to the state (since they're "fresher" relative to the next chunk).

> **Why this form:** The chunkwise representation solves the memory problem of training on very long sequences. The parallel form requires $O(|x|^2)$ memory for the $Q K^\top$ matrix, which becomes prohibitive for sequences of 8k, 16k, or longer. The chunkwise form reduces the peak memory to $O(B^2)$ for the inner-chunk attention plus $O(|x| \cdot d)$ for storing the per-chunk states $R_i$. The total complexity is $O(|x| \cdot B \cdot d)$, which is linear in sequence length when $B$ is fixed. The chunk size $B = 512$ is chosen as a sweet spot: large enough to get good GPU utilization from the inner-chunk matrix multiplications, small enough that $B^2 = 262,144$ fits comfortably in SRAM. The paper notes this is especially useful for long-sequence training, where it is "efficient in terms of both FLOPs and memory consumption."

---

#### Multi-Scale Retention (MSR) Module

The raw retention operation is extended into a multi-head module with several architectural enhancements:

**Multiple heads with different decay rates.**

The retention computation is split into $h = d_{\text{model}} / d$ heads, where $d$ is the per-head dimension (256 for queries and keys, 512 for values, giving a default $d_{\text{model}} / d$ heads). Each head has its own learned projections $W_Q, W_K, W_V \in \mathbb{R}^{d_{\text{model}} \times d}$ (with $W_V$ outputting $2d$ dimensions). Critically, each head is assigned a **different decay rate** $\gamma$, generated by:

$$\gamma = 1 - 2^{-5 - \text{arange}(0, h)} \in \mathbb{R}^h$$

where $\text{arange}(0, h)$ produces the sequence $[0, 1, 2, \ldots, h-1]$. This yields $\gamma$ values ranging from approximately $1 - 2^{-5} = 0.96875$ for head 0 (slow decay — retains long history) to $1 - 2^{-5-(h-1)}$ for head $h-1$ (fast decay — mostly recent context). The paper also uses a scaled variant for the parametric comparison: $\gamma = 1 - e^{\text{linspace}(\log 1/32, \log 1/512, h)}$, which varies from $31/32 = 0.96875$ to $511/512 = 0.99805$ — very slow decays that retain information for hundreds of tokens.

> **What multiple decay rates achieve:** Different heads specialize in different temporal scales. Heads with $\gamma$ close to 1 retain information for many steps (long-range dependencies), while heads with smaller $\gamma$ focus primarily on very recent tokens (local syntax, adjacent word relationships). This is analogous to having convolution kernels of different widths, or attention heads with different effective receptive fields, but implemented through the exponential decay parameter. The paper's ablations (Table 6, "−multi-scale decay") confirm that using a single $\gamma$ for all heads hurts performance, validating the multi-scale design.

> **Why $\gamma$ is fixed, not learned:** The $\gamma$ values are set analytically and kept fixed across all layers. This is a deliberate design choice — learned decay rates would add parameters and potentially lead to instability (a learned $\gamma$ could drift outside $(0,1)$). The geometric spacing ensures coverage of temporal scales from "very local" to "very long-range" without requiring gradient-based optimization. The paper notes this choice: "for simplicity, we set $\gamma$ identical among different layers and keep them fixed."

**Swish gate for non-linearity.**

The retention output of each head is gated by a swish-activated projection of the input:

$$\text{MSR}(X) = (\text{swish}(X W_G) \odot Y) W_O$$

$$Y = \text{GroupNorm}_h(\text{Concat}(\text{head}_1, \ldots, \text{head}_h))$$

where $W_G \in \mathbb{R}^{d_{\text{model}} \times d_{\text{model}}}$ is a learned gate projection, $\text{swish}(x) = x \cdot \sigma(x)$ is the swish activation function (a smooth, self-gated non-linearity), $\text{head}_i = \text{Retention}(X, \gamma_i)$ is the output of the $i$-th retention head with decay rate $\gamma_i$, $\text{Concat}$ concatenates all head outputs along the feature dimension, $\text{GroupNorm}_h$ applies Group Normalization separately to each head's output (dividing the concatenated tensor into $h$ groups, one per head), $\odot$ is element-wise multiplication (gating), and $W_O \in \mathbb{R}^{d_{\text{model}} \times d_{\text{model}}}$ is the output projection.

> **What it computes:** Each head independently applies retention with its own decay rate, producing an output of shape $\mathbb{R}^{|x| \times 2d}$ (since $V$ has $2d$ dimensions, the retention output inherits this dimension). The head outputs are concatenated into a tensor of shape $\mathbb{R}^{|x| \times 2d \cdot h} = \mathbb{R}^{|x| \times 2 d_{\text{model}}}$, normalized per-head by GroupNorm, and then multiplied by $W_O \in \mathbb{R}^{2 d_{\text{model}} \times d_{\text{model}}}$ to project back to $d_{\text{model}}$. In parallel, the input $X$ is projected through $W_G$ (shape $d_{\text{model}} \times d_{\text{model}}$) and passed through swish to produce a gate of shape $\mathbb{R}^{|x| \times d_{\text{model}}}$. The gate is element-wise multiplied with the projected retention output, and the result is the MSR output.

> **Why gating:** The retention mechanism itself is a linear operation (the state update is linear, the readout is linear). Without non-linearity, stacking multiple retention layers would be equivalent to a single linear transformation. The swish gate introduces input-dependent non-linearity: the gate values determine how much of each retention output dimension passes through. The paper's ablation (Table 6, "−swish gate") shows that removing the gate degrades perplexity from 26.05 to 27.84, confirming that "the gating module is essential for enhancing non-linearity and improving model capability."

> **Why GroupNorm:** Because different heads use different $\gamma$ values, they produce outputs with different variance statistics. A head with $\gamma \approx 0.97$ accumulates information over many tokens, producing larger-magnitude outputs than a head with $\gamma \approx 0.5$ that mostly captures recent context. GroupNorm normalizes each head independently, preventing heads with larger $\gamma$ from dominating the concatenated output. The paper's ablation (Table 6, "−GroupNorm") shows perplexity increases from 26.05 to 27.54 without it, confirming that "group normalization in retention balances the variances of multi-head outputs, which improves training stability and language modeling results."

**Retention score normalization.**

Three numerical stabilization tricks are applied to the retention computation (Equation 5), all exploiting the scale-invariant property of GroupNorm — multiplying a head's output by a scalar does not change the normalized result:

1. **Query-key normalization:** The raw scores are scaled as $Q K^\top / \sqrt{d}$, following the standard attention scaling practice to prevent dot products from growing with dimension.

2. **Decay mask normalization:** The decay mask $D$ is replaced with $\tilde{D}_{nm} = D_{nm} / \sqrt{\sum_{i=1}^n D_{ni}}$. This normalizes each row of the decay mask so that the sum of squared entries is 1, preventing the accumulated decay from producing vanishingly small scores for early tokens in long sequences.

3. **Score normalization:** Let $R = Q K^\top \odot D$ be the retention scores. Each row is normalized as $\tilde{R}_{nm} = R_{nm} / \max(|\sum_{i=1}^n R_{ni}|, 1)$, preventing any single row from having unbounded magnitude.

The retention output then becomes $\text{Retention}(X) = \tilde{R} V$. The paper states these tricks "do not affect the final results while stabilizing the numerical flow of both forward and backward passes, because of the scale-invariant property" of GroupNorm. This is a practical implementation detail that prevents training instability — without it, the combination of complex exponentials, exponential decay, and deep stacking could produce gradients that explode or vanish.

---

#### Overall Network Architecture

The RetNet architecture follows the standard Transformer blueprint with pre-LayerNorm and residual connections, but with modified parameter allocation:

**Layer structure.** For an $L$-layer network, layer $l$ computes:

$$Y^l = \text{MSR}(\text{LN}(X^l)) + X^l$$

$$X^{l+1} = \text{FFN}(\text{LN}(Y^l)) + Y^l$$

where $\text{LN}(\cdot)$ is LayerNorm applied before each sublayer (pre-norm), $\text{MSR}(\cdot)$ is the multi-scale retention module described above, $\text{FFN}(X) = \text{gelu}(X W_1) W_2$ is a two-layer feed-forward network with GELU activation, and $W_1 \in \mathbb{R}^{d_{\text{model}} \times d_{\text{ffn}}}$, $W_2 \in \mathbb{R}^{d_{\text{ffn}} \times d_{\text{model}}}$ are learned FFN weights.

**Parameter reallocation.** A critical design decision is how parameters are distributed between the retention and FFN modules to keep total parameters matched to Transformer baselines. Let $d = d_{\text{model}}$ for simplicity:

- **Transformer:** Self-attention uses approximately $4d^2$ parameters ($W_Q, W_K, W_V, W_O \in \mathbb{R}^{d \times d}$ each). FFN with intermediate dimension $4d$ uses $d \cdot 4d + 4d \cdot d = 8d^2$ parameters ($W_1 \in \mathbb{R}^{d \times 4d}, W_2 \in \mathbb{R}^{4d \times d}$). Total per layer: $\approx 12d^2$.

- **RetNet:** Retention uses $8d^2$ parameters — $W_Q, W_K \in \mathbb{R}^{d \times d}$ ($2d^2$ total), $W_G \in \mathbb{R}^{d \times d}$ ($d^2$), $W_V \in \mathbb{R}^{d \times 2d}$ ($2d^2$), $W_O \in \mathbb{R}^{2d \times d}$ ($2d^2$), plus an additional $d^2$ from other components. The doubled value dimension ($2d$ instead of $d$) increases MSR's parameter count relative to standard attention. To compensate, the FFN intermediate dimension is reduced from $4d$ to $2d$, using $d \cdot 2d + 2d \cdot d = 4d^2$ parameters. Total per layer: $\approx 12d^2$, matching Transformer.

> **Why widen values:** The value vector $V$ has dimension $2d$ while $Q$ and $K$ have dimension $d$. This means the state $S_n \in \mathbb{C}^{d \times 2d}$ has twice as many columns as it would if $V$ had dimension $d$. The paper argues this increases the "memory capacity of hidden states" — the state can store more information about past tokens because each key dimension maps to two value dimensions. The ablation on head dimension (Table 6, "Reduce head dimension") supports this: reducing the head dimension from 256 to 64 (while keeping $d_{\text{model}}$ fixed by increasing the number of heads) degrades performance, suggesting that larger per-head state capacity is beneficial.

**Model configurations.** The paper evaluates three model sizes (Table 2 and Appendix A, Table 7):
- **1.3B:** 24 layers, $d_{\text{model}} = 2048$, FFN size $= 4096$ ($2d$), 8 heads, $d = 256$
- **2.7B:** 32 layers, $d_{\text{model}} = 2560$, FFN size $= 5120$, 10 heads, $d = 256$
- **6.7B:** 32 layers, $d_{\text{model}} = 4096$, FFN size $= 8192$, 16 heads, $d = 256$

The head dimension $d = 256$ is kept constant across model sizes (so $d_{\text{model}} = h \cdot 256$). This means larger models get more heads rather than wider heads, which the paper's ablation suggests is the better tradeoff (wider heads = larger state capacity per head = better performance).

#### Training and Inference Procedures

**Training.** During training, the parallel representation (Equation 5) is used for efficiency on standard-length sequences, and the chunkwise recurrent representation (Equation 7) is used for long sequences. The paper reports using chunk size $B = 512$ for long-sequence training. Training hyperparameters (Appendix A, Table 7):
- **Optimizer:** AdamW with $\beta_1 = 0.9$, $\beta_2 = 0.98$, weight decay $= 0.01$
- **Learning rate:** $6 \times 10^{-4}$ (1.3B), $3 \times 10^{-4}$ (2.7B and 6.7B), with polynomial decay
- **Warmup:** 375 steps with linear LR warmup
- **Batch size:** 4M tokens per batch (2048 tokens × ~1953 sequences)
- **Training tokens:** 100B total (25,000 steps)
- **Sequence length:** 2048 maximal length during training
- **Dropout:** 0.1
- **Gradient clipping:** 2.0
- **Initialization:** DeepNet initialization to "guarantee training stability"
- **Implementation:** TorchScale framework, trained on 512 AMD MI200 GPUs

**Inference.** During autoregressive decoding, the recurrent representation (Equation 6) is used exclusively. The state $S_n$ is initialized to zero and updated at each step. Since $S_n$ has fixed dimensions, GPU memory consumption is constant regardless of sequence length. The paper reports inference metrics on an A100-80GB GPU for the 6.7B model.

#### Design Choices and Their Justifications

The paper makes several specific design decisions that warrant explicit discussion:

**Complex-valued positions via $e^{i n \theta}$ rather than real-valued RoPE.** The paper connects retention to xPos and RoPE — both use complex exponentials or their real-valued equivalents (rotation matrices) to encode position. Retention uses the complex form directly because the algebra of diagonalization naturally produces complex eigenvalues. This is computationally convenient: complex multiplications in the parallel form are trivially parallelizable, and in the recurrent form, the complex-valued state $S_n$ maintains phase information that enables relative position encoding without storing position vectors explicitly. The paper notes that if $Q_n$ and $K_n$ were content-unaware (fixed), the formulation would degenerate to S4, which uses a similar state-space structure but without content-dependent projections — highlighting that the content-awareness is what distinguishes retention from pure state-space models.

**Causal masking integrated into $D$.** The decay matrix $D$ serves double duty: it enforces causality ($D_{nm} = 0$ for $n < m$) and applies exponential decay ($\gamma^{n-m}$ for $n \geq m$). This is more elegant than having separate causal mask and position bias matrices — the decay naturally provides the causal constraint because future positions have zero weight. During the recurrent formulation, causality is automatic: the state $S_{n-1}$ only contains information from positions $1$ through $n-1$.

**Why not learn $\gamma$?** The paper treats $\gamma$ as a fixed hyperparameter rather than a learned parameter. Learned decay rates would require gradient-based optimization, risking values outside $(0,1)$ that could cause the state to explode (if $\gamma > 1$) or lose all information immediately (if $\gamma \approx 0$). Fixed geometric spacing provides interpretable temporal scales and removes one source of training instability. The paper found that a single $\gamma = 127/128$ for all heads performs worse than multi-scale fixed $\gamma$ (Table 6), confirming the benefit of diversity, but does not experiment with learned $\gamma$.

**Why GroupNorm instead of LayerNorm in MSR?** Standard Transformer sub-layers use LayerNorm over the full hidden dimension. RetNet uses GroupNorm with groups equal to heads because the multi-scale $\gamma$ values cause heads to produce outputs with different variances. Normalizing each head independently prevents high-$\gamma$ heads (which accumulate more information) from dominating the signal. The paper explicitly states: "the heads use multiple $\gamma$ scales, which results in different variance statistics. So we normalize the head outputs separately."

**Why the FFN intermediate dimension is $2d$ instead of $4d$.** This is purely a parameter-count matching decision. Since MSR uses $8d^2$ parameters (vs. $4d^2$ for standard attention), the FFN is reduced from $8d^2$ to $4d^2$ parameters to keep total per-layer parameters constant at $\approx 12d^2$. This means RetNet allocates more parameters to the sequence-mixing operation (retention) and fewer to the per-token processing (FFN) compared to Transformers. The paper does not ablate this allocation — it is chosen for fair comparison, not because it is necessarily optimal.

**Why no softmax or normalization over keys?** The defining difference between retention and attention is the removal of softmax. In attention, $\text{softmax}(Q K^\top / \sqrt{d})$ normalizes the attention weights for each query to sum to 1, which prevents unbounded outputs but also makes the computation inherently non-factorable — the normalization couples all keys together. Retention replaces this with fixed exponential decay $\gamma^{n-m}$, which is precomputed and independent of the actual key/query values. This is what enables the dual form: because the decay is data-independent, the summation $\sum_{m=1}^n \gamma^{n-m} K_m^\top V_m$ can be accumulated in a fixed-size state. The price is that retention cannot dynamically reweight attention based on content (e.g., attending strongly to a single relevant token while ignoring others) in the same way softmax can — it must rely on the content-based query-key dot product multiplied by a fixed positional decay.

**Why the complex conjugate on keys?** In Equation (5), keys are multiplied by $\overline{\Theta}$ (the complex conjugate of $\Theta$), so that the dot product $Q_n K_m^\top$ encodes the relative phase $e^{i (n-m) \theta}$. If keys used $\Theta$ instead of $\overline{\Theta}$, the dot product would encode absolute position $e^{i (n+m) \theta}$, which is not translation-invariant — the same relative offset would produce different phase differences depending on absolute position. Using the conjugate ensures the dot product depends only on $n-m$, making the position encoding relative.

**Why the chunkwise form uses $\gamma^B$ for cross-chunk decay (Equation 7)?** When updating the recurrent state from chunk $i-1$ to chunk $i$, the previous state $R_{i-1}$ is multiplied by $\gamma^B$. This accounts for the fact that $B$ tokens have been processed between the end of chunk $i-1$ and the start of chunk $i$. Without this, the state would treat tokens from previous chunks as if they were immediate neighbors, inflating their influence. The $\gamma^B$ factor correctly applies the cumulative decay that those tokens would have experienced if processed sequentially.

## 4. Key Insights and Innovations

### Innovation 1: The Dual Form as an Exact Algebraic Identity, Not an Approximation

The fundamental conceptual move in RetNet is deriving a sequence modeling mechanism where the parallel and recurrent computations are **mathematically identical**, not approximate. This distinguishes retention from every prior attempt to unify training parallelism with O(1) inference, all of which introduced some form of approximation gap that either hurt performance or limited practical utility.

Prior work approached the problem from one of two directions. Linearized attention methods start with the Transformer's softmax attention and replace it with a kernel approximation $\phi(q)\phi(k)$, which enables a recurrent rewrite but introduces a representational mismatch — the model is trained with the kernel approximation but would ideally use exact softmax, creating a permanent performance ceiling. The paper explicitly notes this: linear attention "struggles to effectively encode position information, rendering the models less performant." State-space models like S4 start from a continuous-time differential equation and discretize it, achieving a dual convolutional-recurrent form, but the content-aware projections that make attention powerful are retrofitted rather than built into the core mechanism. RWKV uses exponential decay and element-wise operations that trade representation capacity for speed, achieving O(1) inference but at the cost of training parallelism (it runs recurrently during training as well).

RetNet inverts this logic entirely. Instead of starting from attention and trying to make it recurrent, **it starts from a recurrence and derives its parallel form algebraically**. The key is in Section 2.1: the authors define a linear recurrence with a matrix state $s_n = A s_{n-1} + K_n^\top v_n$, diagonalize $A = \Lambda(\gamma e^{i\theta})\Lambda^{-1}$, absorb $\Lambda$ into the learned projections, and recognize that the resulting sum over past positions factors into a matrix multiplication $(Q K^\top \odot D) V$. This is the same computation, expressed two ways — no kernel trick, no discretization error, no element-wise simplification. The parallel form is what the model actually computes during training; the recurrent form is what it actually computes during inference; and they produce identical outputs.

Why this matters beyond implementation convenience: **any approximation gap creates a train-test mismatch**. If the inference model is even slightly different from the trained model, the guarantees of empirical risk minimization break down — you are deploying a model you haven't evaluated. Prior methods essentially trained one model (with the kernel or discretization) and deployed a slightly different one (the recurrent form), hoping the gap was small enough. RetNet eliminates this gap entirely, which means perplexity measured during training is exactly what you'll get at inference, scaling curve improvements are real rather than artifacts of the approximation, and there is no need for post-hoc calibration or distillation to align the two forms.

This is a theoretical contribution as much as a practical one: the paper demonstrates that **the "impossible triangle" is only impossible if you insist on softmax as the core operation**. Once you relax that constraint and work backward from the desired dual form, a solution exists. The conceptual reframing — from "how do we make attention recurrent?" to "what recurrence has an exact parallel form?" — changes the search space for future architectures.

**Evidence:** The equivalence is baked into the math (Equations 1–4 derive the parallel form from the recurrence; Equations 5–6 show the two operational forms). The empirical validation is indirect but essential: RetNet matches Transformer perplexity at 6.7B parameters (Figure 5) and outperforms on downstream tasks (Table 3), which would be impossible if the recurrent form introduced significant degradation relative to the parallel form used during training.

### Innovation 2: Making the Inference-State Capacity a First-Class Architectural Parameter

The paper makes a subtle but important conceptual contribution by treating the **dimensionality of the recurrent state** as a primary design variable rather than an incidental consequence of other choices. The retention state $S_n \in \mathbb{C}^{d \times 2d}$ has $d \times 2d$ complex degrees of freedom, where $d$ is the per-head dimension (256) and the value dimension is deliberately doubled to $2d$. This means each head maintains a state matrix with $256 \times 512 = 131,072$ complex numbers — substantial representational capacity that can encode rich information about sequence history.

The contrast with prior approaches is instructive. Linear attention methods like the Linear Transformer have a recurrent state that is a key-value outer product sum, but the state dimension is inherited from the attention head size without explicit consideration of whether it provides sufficient memory. Element-wise recurrent models like RWKV operate on vectors rather than matrices, giving them fundamentally lower state capacity per token processed. S4 and its variants have state dimensions determined by the order of the underlying differential equation rather than by a direct choice about how much history the model should remember. The paper's ablation on head dimension (Table 6, "Reduce head dimension") provides direct evidence: shrinking the head from 256 to 64 degrades perplexity from 26.05 to 27.68, supporting the claim that "the larger head dimension achieves better performance" through increased state capacity.

What makes this a genuine innovation rather than just a hyperparameter choice: the paper **connects state capacity to the removal of the KV cache**. In Transformers, all past key and value vectors are stored explicitly — if you want the model to have access to more past information, you simply don't evict the cache. The KV cache is a literal memory of everything. Retention replaces this with a fixed-size state that must summarise the entire history. The question of "how big should this state be?" becomes critical because it determines how much information survives the summarization bottleneck. By widening the value dimension to $2d$ (vs. $d$ for queries and keys), the paper explicitly allocates more parameters to the "memory write" pathway ($K_n^\top V_n$ outer product) than to the "memory read" pathway ($Q_n S_n$ dot product), reflecting an architectural intuition that writing rich information into the state is more important than having a high-dimensional query to read it out.

This is a **diagnostic contribution**: the paper identifies that state capacity is something architectures should explicitly optimize, not inherit. Future work on recurrent LLM architectures can now ask "what is the right state dimension for a given model size?" as a first-class question, rather than treating it as a fixed consequence of the attention head dimension.

**Evidence:** The ablation in Table 6 showing head dimension matters significantly. The parametric comparison in Section 3.1 explicitly notes that $V$ dimension is $2d$ while $Q, K$ are $d$, and the FFN intermediate dimension is reduced to $2d$ (from Transformer's $4d$) to compensate — a zero-sum parameter reallocation that prioritizes state capacity over per-token FFN processing.

### Innovation 3: Multi-Scale Decay as a Structured Inductive Bias for Temporal Abstraction

The paper's use of **multiple fixed, geometrically-spaced decay rates across attention heads** is a conceptually elegant solution to a problem that Transformers solve very differently. In standard attention, each head can learn to attend over different timescales by learning different query-key patterns — a head might learn to attend broadly to all tokens (global context) or sharply to recent tokens (local context). This temporal specialization is entirely emergent from the data and the softmax mechanism.

RetNet cannot rely on softmax for this because there is no softmax — the decay is fixed and position-based, not content-based. The paper's response is to provide explicit temporal structure: each head gets a different $\gamma$ value, geometrically spaced from approximately 0.97 (slow decay, retains information for hundreds of tokens) to near 0.998 (extremely slow decay, near-lossless memory). This imposes a **structured temporal hierarchy** where different heads are forced to operate at different timescales, regardless of what they learn about content.

Why this is clever rather than just convenient: **it converts a potential weakness of the architecture (rigid exponential decay rather than flexible softmax attention) into a form of inductive bias**. The geometric spacing ensures that the model has heads covering the full range from "mostly local" to "mostly global," preventing the degenerate case where all heads learn similar temporal profiles and long-range dependencies get lost. The paper's ablation (Table 6, "−multi-scale decay") confirms that using a single $\gamma = 127/128$ for all heads hurts perplexity (27.02 vs. 26.05), validating that the diversity of timescales matters.

This connects to a broader principle in deep learning: when you remove a learned mechanism (content-based attention weighting), you need to replace it with a structured prior (multi-scale fixed decay) that provides the same functional diversity. The paper's design suggests a general template: **fixed structures can substitute for learned flexibility if they provide sufficient coverage of the relevant degrees of freedom**. The geometric spacing is chosen analytically to span the range of temporal scales present in natural language (from adjacent-word syntax to paragraph-level coherence), making it a domain-informed inductive bias rather than an arbitrary hyperparameter sweep.

This is an incremental rather than fundamental contribution — it builds on ideas from multi-scale architectures in computer vision and signal processing — but the specific application to sequence model decay rates and the empirical validation at LLM scale make it practically significant.

**Evidence:** Table 6 ablation results. The specific formula $\gamma = 1 - 2^{-5 - \text{arange}(0,h)}$ (or the parametric variant) provides explicit geometric spacing, and the paper's language modeling results across multiple model sizes (Figure 5) and out-of-domain corpora (Table 5) demonstrate that this temporal structure transfers across data distributions.

### Innovation 4: Diagnostic Evidence That the Architecture Bottleneck Is Verifier-Free — Scaling Curves Without Over-Optimization

While this is primarily a data point rather than a theoretical advance, the paper's **scaling results at 1.3B, 2.7B, and 6.7B parameters** (Figure 5) provide an important existence proof: an architecture without softmax attention can match Transformer perplexity scaling at meaningful model sizes. This matters because prior efficient architectures (Linear Transformer, S4, H3, Hyena, RWKV) had either not been demonstrated at multi-billion-parameter scale or had shown scaling curves that diverged from Transformers as model size increased.

The specific observation that "RetNet starts to outperform Transformer when the model size is larger than 2B" (Section 3.2) is suggestive: the architectural advantages (structured temporal bias, larger state capacity per head) may become more beneficial as model capacity increases, while the Transformer's softmax advantage may saturate. The paper doesn't claim this as a law — it's a single observation from three model sizes — but it raises the hypothesis that **recurrent architectures with sufficient state capacity may have better scaling properties than attention-based ones at large scale**, which would invert the conventional wisdom that attention's flexibility makes it inherently more scalable.

The significance goes beyond "RetNet works." The paper demonstrates that an architecture designed for inference efficiency does not necessarily trade off training performance — the "impossible triangle" can be genuinely resolved, not just cheated by accepting worse perplexity in exchange for faster decoding. This changes the default assumption for architecture design: efficiency and performance are not a zero-sum game if the mathematical structure is right.

**Evidence:** Figure 5 shows nearly overlapping perplexity curves for Transformer and RetNet at 1.3B, 2.7B, and 6.7B parameters on 100B training tokens. Table 3 shows RetNet matching or exceeding Transformer on 7 zero-shot and few-shot benchmarks at 6.7B scale (average 69.51 vs. 66.07 zero-shot). Tables 4 and Figure 6 provide the efficiency counterpart: 25-50% training memory savings over standard Transformer, 8.4× decoding speedup at 8k sequence length, and 70% GPU memory reduction.

### Innovation 5: The Chunkwise Representation as a General-Purpose Long-Sequence Training Strategy

The chunkwise recurrent representation (Equation 7, Figure 4) is a **general computational pattern** that extends beyond RetNet: it shows how to train a recurrent model on long sequences by splitting the sequence into blocks, processing each block in parallel (exploiting GPU tensor cores), and passing summary states between blocks recurrently (avoiding O(N²) memory). The complexity analysis is revealing: inner-chunk attention costs O(B²) per chunk (where B = 512), cross-chunk recurrence costs O(B ⋅ d) per chunk, and total complexity is O(N ⋅ B ⋅ d) for sequence length N — linear in N when B and d are fixed. This is strictly better than the O(N²) of standard attention training and the O(N log N) of FFT-based convolution approaches like H3/S4.

What makes this an innovation rather than just a chunking trick: the paper explicitly connects it to the dual form of retention. The chunkwise representation is not a separate mechanism — it's the natural consequence of combining parallel processing within chunks (using Equation 5) and recurrent processing across chunks (using Equation 6). The same mathematical identity that enables the parallel-recurrent dual form also enables the chunkwise form. This means the model can seamlessly switch between all three representations depending on the computational context: fully parallel for moderate-length training, chunkwise for long-sequence training, fully recurrent for inference.

The broader significance: this suggests a design principle for future architectures. Any sequence model with an exact parallel-recurrent dual form will automatically admit a chunkwise form, enabling efficient long-sequence training without additional mechanisms. This is not true for attention (which has no recurrent form) or pure RNNs (which have no parallel form). The chunkwise representation is thus **diagnostic of the architecture class** — if you can do chunkwise training exactly (not approximately), you have a true dual-form architecture.

**Evidence:** Table 4 shows that RetNet with chunkwise training on 8k sequences outperforms both standard Transformer and FlashAttention-optimized Transformer in memory (34.5 GB vs. 74.8 GB vs. 38.8 GB for 1.3B) and throughput (73,344 wps vs. 10,832 wps vs. 63,965 wps). The chunk size B = 512 is specified in Section 3.3 as the operational setting. The chunkwise pseudocode in Figure 4 is concise but general — the pattern of inner-chunk parallel computation plus cross-chunk state passing applies to any dual-form architecture, not just RetNet.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The primary training corpus is a curated compilation of The Pile, C4, and The Stack — three large-scale text corpora spanning web text, cleaned web crawls, and permissively licensed source code. Language modeling validation perplexity is reported on a held-out set from this mixture. For out-of-domain evaluation (Table 5), the paper uses Project Gutenberg 2019-2022 (PG22; books), QMSum (meeting summarization), GovReport (government documents), and SummScreen (screenplay summarization). Downstream task evaluation (Table 3) uses HellaSwag, BoolQ, COPA, PIQA, Winograd, Winogrande, and StoryCloze — standard zero-shot and few-shot benchmarks.

- **Base model(s).** All experiments use RetNet models with sizes of 1.3B, 2.7B, and 6.7B parameters, trained from scratch on 100B tokens. The comparison baselines include equivalently-sized standard Transformers trained under identical conditions, plus a set of 200M-parameter models (16 layers, hidden dimension 1024) for comparisons against efficient Transformer variants (Linear Transformer, RWKV, H3, Hyena). The paper also uses FlashAttention-optimized Transformers as an additional training efficiency baseline. The primary inference comparisons use the 6.7B model on an A100-80GB GPU.

- **Metrics.** For language modeling, the paper reports **validation perplexity** — the exponential of the average negative log-likelihood per token on held-out data. For downstream tasks, it reports **accuracy** (percentage of correct predictions) in zero-shot and 4-shot settings. For inference efficiency, three metrics are tracked: **GPU memory consumption** (GB), **throughput** (words per second; wps), and **latency** (milliseconds). Memory is measured as total GPU memory used during decoding; throughput measures how many tokens can be generated per second; latency measures wall-clock time per decoding step.

- **Baselines.** The paper compares against several categories of baselines:
  - **Standard Transformer** (Vaswani et al., 2017) with multi-head self-attention and KV cache during inference, matched for total parameters.
  - **Transformer with FlashAttention** (Dao et al., 2022), using the IO-aware exact attention kernel for improved memory and speed during training.
  - **Linear Transformer** (Katharopoulos et al., 2020), which replaces softmax attention with kernel-based linearized attention.
  - **RWKV** (Peng et al., 2023), a modern RNN variant using element-wise token mixing with exponential decay, trained recurrently.
  - **H3** (Dao et al., 2022), a state-space model using S4-style structured state spaces.
  - **Hyena** (Poli et al., 2023), using long convolutions parameterized by implicit neural representations.
  
  For fair comparison, all 200M-parameter variants keep FFN layers consistent, with RWKV replacing only the self-attention sub-layer with its TimeMix module.

- **Generation budget / compute accounting.** During training, compute is measured via **training throughput** (words per second) and **GPU memory consumption** at a fixed sequence length of 8192 tokens. The unit of comparison is effectively FLOPs per second, since throughput on identical hardware with identical batch sizes reflects computational efficiency. For inference, the budget is implicitly the **sequence length** being decoded — the paper compares how memory, throughput, and latency scale as the sequence length grows from 2048 to 8192 tokens at a fixed batch size. The key metric is the asymptotic scaling: Transformer costs grow as O(N), RetNet remains O(1). For the 200M-parameter comparisons, training FLOPs are controlled by training all models for the same number of steps (10k) with the same batch size (0.5M tokens) on the same data.

- **Cross-validation / statistical protocol.** The paper does not employ cross-validation or multiple training runs with error bars. Results are reported as single-run perplexity, accuracy, throughput, and latency numbers. The scaling curves (Figure 5) use three model sizes as the primary form of validation — consistent trends across 1.3B, 2.7B, and 6.7B serve as evidence that results are not artifacts of a single configuration. The out-of-domain evaluations (Table 5) provide a separate form of robustness check by testing on corpora not seen during training.

### Main Quantitative Results

#### Language Modeling Scaling: RetNet Matches Transformer Perplexity and Shows Favorable Scaling

The headline result from Figure 5 is that RetNet achieves **comparable validation perplexity** to Transformer across three model sizes trained on 100B tokens:

- **1.3B:** Both architectures cluster around 14.0–15.0 perplexity (exact values not enumerated in the figure; the y-axis spans ~12.5 to 15.0).
- **2.7B:** Both architectures show reduced perplexity, with points around 13.0–13.5.
- **6.7B:** Further reduction to approximately 12.0–12.5 range for both.

The paper makes a specific empirical observation: "RetNet tends to outperform Transformer when the model size is larger than 2B." At 6.7B parameters, RetNet's perplexity is visibly lower than Transformer's in Figure 5 — the RetNet point sits below the Transformer point on the scaling curve. Since exact perplexity values are not provided in the figure or text (the paper states "we empirically observe" without specific numbers), the claim is qualitative and visual. However, the trend across three model sizes is consistent: the gap between RetNet and Transformer narrows or reverses as scale increases.

Table 8 (Appendix B) provides a complementary view by varying context length at a fixed model size. RetNet outperforms Transformer across all context lengths tested (512, 1024, 2048 tokens):
- At 512 context: RetNet 13.09 vs. Transformer 13.55
- At 1024 context: RetNet 12.14 vs. Transformer 12.56
- At 2048 context: RetNet 11.98 vs. Transformer 12.35

The consistent gap (approximately 0.37–0.46 perplexity points) across context lengths suggests that RetNet's advantage is not dependent on sequence length — it holds at short, medium, and standard training-length contexts. Notably, "RetNet can utilize longer context for better results" — perplexity drops from 13.09 to 11.98 as context increases from 512 to 2048, while Transformer drops from 13.55 to 12.35.

**Assessment:** The scaling curve evidence supports performance parity between RetNet and Transformer at the 1.3B–6.7B scale. The visual suggestion that RetNet pulls ahead at larger scales is intriguing but rests on three data points and a single training run each — not a statistical claim that can be rigorously evaluated without error bars or multiple seeds. This is the paper's most critical empirical result because it addresses the "good performance" vertex of the impossible triangle (Figure 2). Without competitive perplexity, the efficiency advantages of retention would be irrelevant. The evidence is adequate to establish parity but insufficient to confidently claim superiority at scale.

|---|---|---|---|---|
| HellaSwag | 55.9 | 60.7 | 55.8 | 60.5 |
| BoolQ | 62.0 | 62.2 | 58.7 | 60.1 |
| COPA | 69.0 | 77.0 | 71.0 | 78.0 |

The pattern is consistent: RetNet outperforms Transformer on every benchmark in both zero-shot and few-shot settings except BoolQ zero-shot (tied within 0.2 points). The largest gaps are on COPA (+8.0 zero-shot, +7.0 few-shot) and Winograd (+7.7 zero-shot, +6.0 few-shot) — both tasks testing causal reasoning and commonsense inference. The few-shot results show a small additional gap in RetNet's favor (+0.25 average improvement from zero-shot to few-shot, vs. +0.37 for Transformer), suggesting both architectures benefit modestly from in-context examples.

**Assessment:** These results strengthen the performance parity claim by demonstrating that language modeling perplexity improvements translate to downstream task accuracy. The consistent advantage across diverse benchmarks (commonsense reasoning, natural language inference, story understanding, question answering) suggests the gains are not an artifact of a particular task type. However, the paper does not report these results for the 1.3B and 2.7B models, so it is unclear whether the downstream advantage is present at smaller scales or emerges only at 6.7B, paralleling the scaling curve observation in Figure 5.

#### Training Cost: RetNet Reduces Memory by 25–50% and Increases Throughput Over Standard Transformer

Table 4 reports training memory and throughput for Transformer, Transformer with FlashAttention, and RetNet at four model sizes with 8k sequence length on 8× A100-80GB GPUs:

| Model Size | Memory (GB) — Trm | Memory — Trm+FlashAttn | Memory — RetNet | Throughput (wps) — Trm | Throughput — Trm+FlashAttn | Throughput — RetNet |
|---|---|---|---|---|---|---|
| 1.3B | 74.8 | 38.8 | 34.5 | 10,832 | 63,965 | 73,345 |
| 2.7B | 69.6 | 42.1 | 42.0 | 5,186 | 34,990 | 38,921 |
| 6.7B | 69.0 | 51.4 | 48.0 | 2,754 | 16,230 | 17,459 |
| 13B | 61.4 | 46.3 | 45.9 | 1,209 | 7,945 | 8,642 |

The memory advantage is dramatic over standard Transformer: RetNet uses 54% less memory at 1.3B (34.5 vs. 74.8 GB), 40% less at 2.7B, and 30% less at 6.7B. Compared to FlashAttention — which is already highly optimized — RetNet still provides a smaller but consistent advantage: 11% less at 1.3B, roughly tied at 2.7B (42.0 vs. 42.1), 7% less at 6.7B, and roughly tied at 13B.

Throughput shows a similar pattern. RetNet achieves 6.8× higher throughput than standard Transformer at 1.3B (73,345 vs. 10,832 wps), 7.5× at 2.7B, and 6.3× at 6.7B. Against FlashAttention, RetNet maintains an advantage: 15% faster at 1.3B, 11% at 2.7B, 8% at 6.7B, and 9% at 13B.

A notable detail: the paper uses vanilla PyTorch implementation for RetNet training while FlashAttention uses custom CUDA kernels. The authors explicitly note they "leave kernel fusion or FlashAttention-like acceleration for future work," suggesting the current RetNet numbers are a lower bound on what optimized implementations could achieve.

**Assessment:** These results support the claim that RetNet achieves training parallelism competitive with or better than Transformer. The comparison against FlashAttention is particularly important because FlashAttention represents the state-of-the-art in efficient Transformer training — RetNet matching or exceeding it without custom kernels suggests the architecture itself, not implementation tricks, is the source of the efficiency. The absence of similar optimizations for RetNet makes the comparison slightly unfair in RetNet's favor (FlashAttention is optimized but RetNet is not, yet RetNet wins), which actually strengthens the conclusion: further optimization of RetNet's implementation would likely widen the gap.

#### Inference Cost: RetNet Achieves Length-Invariant Memory, 8.4× Faster Decoding, and Insensitivity to Batch Size

Figure 6 presents the inference cost comparison for the 6.7B model on an A100-80GB GPU across sequence lengths from 2048 to 8192:

**Memory (Figure 6a):** Transformer memory grows linearly from approximately 25 GB at 2048 tokens to roughly 42 GB at 8192 tokens, driven by the expanding KV cache. RetNet memory is flat at approximately 15–16 GB regardless of sequence length — the model weights occupy 97% of memory, with the recurrent state accounting for only 3%. At 8192 tokens, RetNet uses roughly 35–40% less GPU memory than Transformer. The paper's claim of "70% of memory" savings (Section 1, Figure 1 caption) appears to refer to the KV cache portion specifically — RetNet eliminates the cache entirely, and the 3% state overhead represents a 70% reduction relative to what Transformer's cache would consume plus model weights.

**Throughput (Figure 6b):** Transformer throughput declines from approximately 275 wps at 2048 tokens to roughly 190 wps at 8192 tokens — a 31% drop as sequence length increases. RetNet throughput is flat at approximately 275–280 wps across all sequence lengths. At 8192 tokens, RetNet achieves approximately 1.45× higher throughput than Transformer (280 vs. 190 wps). The paper's headline claim of "8.4× faster" decoding (Figure 1) is not explained in the text — it may refer to a specific comparison point (potentially at longer sequence lengths or with larger batch sizes) not directly visible in Figure 6b. The consistent throughput of RetNet is the key finding: inference speed does not degrade as context grows.

**Latency (Figure 6c):** Transformer latency grows with both batch size and sequence length. At batch size 1, latency is approximately 50 ms for 1024-length, rising to roughly 75 ms for 8192-length. At batch size 8, latency balloons: roughly 175 ms for 1024-length to approximately 320 ms for 8192-length. RetNet latency is approximately 50 ms and nearly flat across all batch sizes (1 through 8) at 8192 sequence length — the line is essentially horizontal. This means RetNet can serve 8× the batch size at the same latency, directly enabling higher total throughput in production.

The batch size insensitivity is perhaps the most practically significant result in Figure 6c. In Transformer deployments, latency constraints force small batch sizes (to keep per-request latency acceptable), which limits total system throughput. RetNet's flat latency curve means batch size can be scaled up to hardware limits without latency penalties, potentially enabling order-of-magnitude throughput improvements in serving scenarios.

**Assessment:** The inference results are the strongest empirical contribution in the paper. They directly validate the architectural claim that the recurrent representation eliminates the KV cache bottleneck, and the measured improvements (constant memory, length-invariant throughput, batch-size-insensitive latency) are exactly what the theory predicts. The quantitative claims require careful reading: the "8.4× faster" and "70% memory" figures from Figure 1 are high-level summaries that need cross-referencing with the detailed plots in Figure 6 to understand the specific comparison conditions. The paper would benefit from a table explicitly stating the comparison points (sequence length, batch size) for each headline number.

Table 5 reports perplexity for 200M-parameter models trained on 10k steps with 0.5M token batch size:

| Method | In-Domain | PG22 | QMSum | GovReport | SummScreen |
|---|---|---|---|---|---|
| RetNet | 26.05 | 45.27 | 21.33 | 16.52 | 22.48 |
| H3 | 29.97 | 49.17 | 24.29 | 19.19 | 25.11 |
| RWKV | 30.92 | 51.41 | 28.17 | 19.80 | 25.78 |

RetNet achieves the lowest perplexity on every dataset, with particularly large gaps on in-domain evaluation (26.05 vs. 29.97 for H3, the next best) and PG22 (45.27 vs. 49.17). Linear Transformer performs worst by a substantial margin (40.24 in-domain vs. 26.05 for RetNet), consistent with the paper's claim that linear attention "struggles to effectively encode position information." H3 is the strongest competitor, consistently second-best across all corpora, suggesting state-space models are the closest architectural relative to retention in terms of modeling capability at this scale.

The out-of-domain results are important because they test whether the architectural advantages (multi-scale decay, larger state capacity) overfit to the training distribution. RetNet's consistent advantage on PG22 (books — different genre), QMSum (meeting transcripts — different domain), GovReport (government documents — different style), and SummScreen (screenplays — different format) suggests the benefits transfer across data distributions.

**Assessment:** The 200M-scale comparison provides the cleanest evidence that retention has better modeling capacity than prior efficient architectures. However, 200M parameters and 10k training steps is a limited setting — the results may not reflect behavior at the 1B+ scale where these architectures are deployed. The paper does not train the competing architectures at larger scales, leaving open the possibility that H3, Hyena, or RWKV might close the gap with more parameters or more training. This is an understandable limitation (training multiple architectures at 6.7B would be extremely expensive), but it means the strongest evidence for RetNet's superiority over efficient Transformers is only at small scale.

### Ablation Studies and Robustness Checks

All ablations use the 200M-parameter configuration (16 layers, hidden dimension 1024) trained for 10k steps with 0.5M token batch size, evaluated on the same in-domain and out-of-domain corpora as Table 5.

**Swish gate removal:** Removing the swish gate from the MSR module (Equation 8) degrades in-domain perplexity from 26.05 to 27.84 (+1.79, or 6.9% relative increase). Out-of-domain degradation is consistent: PG22 increases from 45.27 to 49.44 (+4.17), QMSum from 21.33 to 22.52, GovReport from 16.52 to 17.45, and SummScreen from 22.48 to 23.72. The gate is "essential for enhancing non-linearity and improving model capability," as the paper states — without it, stacking multiple retention layers provides limited representational benefit because the retention operation itself is linear.

**GroupNorm removal:** Removing GroupNorm and using standard LayerNorm instead (or no per-head normalization) increases in-domain perplexity from 26.05 to 27.54 (+1.49). Out-of-domain: PG22 45.27 → 46.95, QMSum 21.33 → 22.61, GovReport 16.52 → 17.59, SummScreen 22.48 → 23.73. The paper attributes this to GroupNorm "balancing the variances of multi-head outputs" — without it, heads with larger decay rates (accumulating more information) produce higher-variance outputs that dominate the concatenated representation.

**Gamma decay removal (γ = 1):** Setting γ = 1 for all heads (no exponential decay, equivalent to uniform averaging over all past tokens) increases in-domain perplexity from 26.05 to 27.86 (+1.81), the largest degradation among the ablations. Out-of-domain: PG22 45.27 → 47.85, QMSum 21.33 → 21.99, GovReport 16.52 → 17.49, SummScreen 22.48 → 23.70. This is the most theoretically significant ablation because it tests whether exponential decay is necessary or whether the model can learn to ignore distant information without it. The result confirms that the recency bias provided by γ < 1 is crucial — without decay, the model's fixed-size state becomes a simple average over all history, losing the ability to distinguish recent from distant context.

**Multi-scale decay removal (single γ):** Using a single decay rate γ = 127/128 for all heads (instead of geometrically-spaced rates) increases in-domain perplexity from 26.05 to 27.02 (+0.97). Out-of-domain: PG22 45.27 → 47.18, QMSum 21.33 → 22.08, GovReport 16.52 → 17.17, SummScreen 22.48 → 23.38. The degradation is smaller than removing decay entirely (27.02 vs. 27.86), confirming that having any decay helps, but having diverse decay rates across heads provides additional benefit. This supports the multi-scale temporal abstraction argument — different heads specialize at different timescales.

**Head dimension reduction:** Reducing the head dimension from 256 to 64 (while increasing number of heads to keep $d_{\text{model}}$ constant at 1024) increases in-domain perplexity from 26.05 to 27.68 (+1.63). Out-of-domain: PG22 45.27 → 47.72, QMSum 21.33 → 23.09, GovReport 16.52 → 17.46, SummScreen 22.48 → 23.41. This is the second-largest degradation and directly tests the paper's claim about state capacity: larger head dimension means larger recurrent state matrix ($d \times 2d$), which can store more information about sequence history. The paper's interpretation that "the larger head dimension achieves better performance" through increased memory capacity is consistent with the result, though alternative explanations (wider heads provide more expressive query-key interactions) cannot be ruled out.

**Non-obvious finding:** The relative importance ordering of ablations is revealing: γ decay removal (+1.81) > head dimension reduction (+1.63) > swish gate removal (+1.79) ≈ GroupNorm removal (+1.49) > multi-scale decay removal (+0.97). The decay mechanism — the core architectural distinction between retention and alternatives — has the largest impact, followed by state capacity (head dimension). Non-linearity (swish gate) and normalization (GroupNorm) are important but secondary. This ordering validates the paper's architectural priorities: the mathematical structure (decay, state dimension) matters more than auxiliary components (gating, normalization).

**What is NOT ablated:** Several important design choices are not tested:
- **The value dimension being 2d vs. d:** The paper states this increases memory capacity, but never trains a model with $d$-dimensional values to quantify the benefit.
- **Complex vs. real-valued positions:** The retention derivation uses complex exponentials $e^{i n \theta}$; whether a real-valued rotation (like standard RoPE) would work as well is not tested.
- **Fixed vs. learned γ:** The paper fixes γ analytically; testing learned decay rates (with appropriate constraints to keep values in (0,1)) would clarify whether the geometric spacing is optimal.
- **Layer-dependent γ:** All layers use the same γ values; varying decay rates across layers (earlier layers more local, later layers more global) is a common hierarchical design not explored.
- **The FFN dimension tradeoff:** The paper reduces FFN from 4d to 2d to compensate for MSR's higher parameter count. Whether this specific allocation is optimal or whether a different balance would improve performance is not tested.

### Critical Assessment

#### Claim: "RetNet achieves favorable scaling results" and "RetNet is consistently competitive in terms of scaling curves" (Abstract, Section 3.2)

**What was tested:** Validation perplexity for three model sizes (1.3B, 2.7B, 6.7B) on 100B training tokens, compared to identically-sized Transformers trained on the same data with the same hyperparameters. Figure 5 shows the scaling curves, and Table 3 provides downstream task results at 6.7B.

**What the evidence shows:** RetNet matches Transformer perplexity at 1.3B and 2.7B, and visually appears to pull slightly ahead at 6.7B. The 6.7B downstream results consistently favor RetNet (average +3.44 in zero-shot, +3.32 in few-shot). The context-length analysis (Table 8) shows RetNet outperforming Transformer at all lengths tested, with the gap widening slightly at 2048 tokens.

**What the evidence does NOT show:** This is NOT a scaling laws study in the tradition of Kaplan et al. or Hoffmann et al. There are only three model sizes and a single training budget (100B tokens). The claim that RetNet "starts to outperform Transformer when the model size is larger than 2B" is based on visual inspection of Figure 5 without reported confidence intervals, error bars, or multiple training runs. The gap at 6.7B appears modest — perhaps 0.2–0.3 perplexity points based on the figure's scale. Whether this gap widens, narrows, or reverses at 13B, 30B, or 70B parameters is completely unknown. The paper's title declares RetNet "a successor to Transformer for large language models," but the experimental scale is well below what the field considers "large" in 2023 (GPT-3 at 175B was released in 2020). The evidence supports "RetNet is competitive with Transformer at 1–7B parameters on 100B training tokens" — a much narrower claim.

**Missing experiments:** Training runs at 13B+ parameters; training runs with more tokens (100B tokens for a 6.7B model is well below compute-optimal; Chinchilla scaling would suggest ~130B+ tokens); multiple random seeds to quantify variance; other data mixtures (all experiments use the same Pile/C4/Stack compilation); other domains beyond English text (code, math, multilingual).

#### Claim: "Low-cost inference: RetNet decodes 8.4× faster and saves 70% of memory than Transformers with key-value caches" (Section 1, Figure 1)

**What was tested:** Inference memory, throughput, and latency for the 6.7B model on A100-80GB GPU at sequence lengths 2048–8192 (Figure 6). The recurrent representation is used for RetNet; KV-cached attention for Transformer.

**What the evidence shows:** The 8.4× and 70% figures are headline numbers that require careful decomposition. Figure 6a shows RetNet memory is flat at ~15–16 GB while Transformer memory grows from ~25 GB (2048) to ~42 GB (8192). At 8192 tokens, the memory ratio is approximately 42/16 ≈ 2.6× — RetNet uses about 38% of Transformer's memory, not 30% as "70% savings" would imply (unless measured differently, perhaps as KV cache savings specifically). Figure 6b shows throughput of ~280 wps (RetNet) vs. ~190 wps (Transformer) at 8192, a ratio of roughly 1.5×, not 8.4×. The 8.4× figure likely comes from a specific comparison point — perhaps at longer sequences, different batch sizes, or counting total tokens processed including prompt — but **the paper does not specify the conditions under which 8.4× was measured**. Figure 1 states "inference cost" with 8k input length, but the individual subplots (memory, throughput, latency) do not show an 8.4× ratio at that length.

**What the evidence does NOT show:** Exact measurement conditions for the headline numbers. The 8.4× throughput claim and 70% memory claim are stated in the introduction and Figure 1 but cannot be directly verified from Figure 6 without additional information. The latency result (Figure 6c) is compelling — RetNet latency is flat while Transformer latency grows with both batch size and sequence length — but the absolute latency values (~50 ms per step for RetNet) are not compared to Transformer at the same operating point in a way that yields a simple multiplier.

**Missing information:** What batch size, sequence length, and prompt-to-generation ratio produce the 8.4× and 70% figures; whether these represent peak, average, or best-case improvements; whether the comparison includes the prompt encoding phase or only autoregressive decoding; whether the Transformer baseline uses any KV cache optimizations (e.g., multi-query attention, grouped-query attention, paged attention) that are standard in production deployments.

#### Claim: RetNet achieves "training parallelism" competitively with Transformer (Table 4)

**What was tested:** Training memory and throughput for four model sizes (1.3B–13B) at 8k sequence length on 8× A100 GPUs, comparing RetNet to standard Transformer and FlashAttention-optimized Transformer.

**What the evidence shows:** RetNet consistently outperforms standard Transformer (1.5–7.5× throughput, 30–54% less memory) and matches or slightly exceeds FlashAttention (8–15% throughput, 0–11% less memory). The chunkwise recurrent representation with chunk size 512 is used for RetNet; FlashAttention-specific kernels for the optimized baseline.

**What the evidence does NOT show:** This is a single-hardware, single-sequence-length comparison. Training throughput depends heavily on sequence length (shorter sequences favor different parallelism strategies), hardware configuration (GPU model, interconnect, number of GPUs), and implementation quality. The RetNet implementation uses vanilla PyTorch while FlashAttention uses custom CUDA kernels — the paper acknowledges this and frames it as a conservative comparison (RetNet would likely improve further with kernel fusion). However, this also means the comparison is not purely architectural: FlashAttention represents years of engineering optimization for Transformers, while RetNet benefits from a simpler computation that is inherently more efficient on current hardware.

**Missing experiments:** Training throughput at different sequence lengths (the 512, 1024, 2048 used in the main experiments, not just 8192); training on non-NVIDIA hardware (the paper mentions AMD MI200 training but provides no comparative numbers); scaling to more GPUs (the 8-GPU setup is modest by LLM training standards); the impact of chunk size on training throughput (only B=512 is reported).

#### Claim: RetNet is "a strong successor to Transformer for large language models" (title and throughout)

**What was tested:** Perplexity scaling at 1.3–6.7B, downstream accuracy at 6.7B, training efficiency, inference efficiency, and 200M-scale comparisons against efficient variants.

**What the evidence shows:** RetNet achieves the three vertices of the impossible triangle simultaneously at the tested scales — it trains in parallel (Table 4), infers with O(1) cost (Figure 6), and matches or exceeds Transformer performance (Figure 5, Table 3). The unification is genuine: the same model, trained once, switches between parallel and recurrent forms without fine-tuning or performance degradation.

**What the evidence does NOT show:** "Successor" implies widespread adoption would follow, which requires evidence beyond what the paper provides:
- **Scale:** 6.7B parameters and 100B tokens is not "large" by 2023 standards. GPT-3 (175B), PaLM (540B), and LLaMA (65B) are substantially larger. The paper trains no model in the regime where LLMs are most impactful.
- **Generality:** All experiments are on English text language modeling. There is no evidence about code generation, mathematical reasoning, multimodal understanding, or instruction following — all critical capabilities for modern LLMs.
- **Production readiness:** The paper does not compare against production-optimized Transformer deployments using techniques like multi-query attention, grouped-query attention, paged attention (vLLM), continuous batching, or quantization. These techniques substantially reduce Transformer inference cost in practice.
- **KV cache alternatives:** The paper frames KV cache elimination as the primary inference advantage, but does not compare against Transformers with multi-query attention (which reduces KV cache size by sharing keys/values across heads) or grouped-query attention (used in LLaMA 2 and GPT-4). These reduce, though do not eliminate, the cache bottleneck.
- **Long-context performance:** While inference cost is length-invariant, the paper does not evaluate whether RetNet's modeling quality degrades on very long sequences (16k, 32k, 64k tokens) relative to Transformers. Constant-cost inference is valuable only if the model actually uses long context effectively.
- **Training stability at scale:** The paper mentions using DeepNet initialization for stability. Whether RetNet exhibits different failure modes (loss spikes, state explosion) compared to Transformers at larger scales is unknown.

**The "impossible triangle" claim is supported with qualifications:** At the tested scales (1.3–6.7B parameters, up to 8k sequence length), RetNet simultaneously achieves training parallelism, Transformer-competitive performance, and O(1) inference. This is a genuine breakthrough over prior architectures (Table 1: all others fail at least one vertex). However, the claim that this makes RetNet "a strong successor to Transformer" requires evidence at the scales and in the domains where Transformers are actually deployed, which the paper does not provide. The contribution is better characterized as: **RetNet demonstrates that the impossible triangle can be resolved in principle, and provides an existence proof at moderate scale, opening a promising direction for LLM architecture design that should be validated at larger scales and in more diverse settings.**

#### Strengths of the Experimental Design

- **Fair parametric comparisons:** Parameter counts are carefully matched between RetNet and Transformer (Section 3.1 describes the reallocation of parameters between MSR and FFN). The comparison against FlashAttention acknowledges the state-of-the-art for Transformer training.
- **Multiple efficiency metrics:** The paper measures memory, throughput, and latency separately, capturing different dimensions of deployment cost that matter in different scenarios (batch processing favors throughput; interactive applications favor latency).
- **Out-of-domain evaluation for 200M models:** Testing on PG22, QMSum, GovReport, and SummScreen provides evidence that retention's advantages are not overfitting to the training distribution.
- **Ablation structure:** Each architectural component (decay, multi-scale decay, head dimension, gate, GroupNorm) is ablated separately, providing a clear picture of what matters and why.

#### Weaknesses of the Experimental Design

- **Single training run per configuration:** No error bars, no multiple seeds, no statistical testing. The scaling curves in Figure 5 could shift non-trivially with different random initialization.
- **Small scale for the central claim:** 6.7B parameters and 100B tokens is below the threshold where LLM capabilities (in-context learning, reasoning, instruction following) become practically useful. The 200M-parameter comparisons (Table 5) are more thorough but at trivially small scale.
- **No training tokens scaling:** The paper varies model size but not training tokens. A compute-optimal scaling analysis (varying both parameters and tokens) would reveal whether RetNet's efficiency advantage persists under optimal training budgets.
- **Limited baseline comparison at scale:** Only standard Transformer is compared at 1.3B+, not RWKV, H3, or Hyena. The claim of superiority over these architectures rests entirely on the 200M-scale results.
- **Unspecified headline metrics:** The 8.4× throughput and 70% memory claims cannot be independently verified from the provided figures. This undermines the paper's most impactful quantitative claims.

## 6. Limitations and Trade-offs

### The Empirical Scale Does Not Match the "Successor" Claim

**The assumption or constraint.** The paper positions RetNet as "a strong successor to Transformer for large language models" (title, Abstract) and demonstrates that it "starts to outperform Transformer when the model size is larger than 2B" (Section 3.2). All evidence is gathered at 1.3B, 2.7B, and 6.7B parameters trained on 100B tokens — a scale the authors themselves do not claim is "large" by the standards of production LLMs in 2023.

**The consequence.** The paper cannot answer whether RetNet's favorable scaling trend continues at GPT-3 scale (175B) or PaLM scale (540B). Three data points on a log-scale perplexity curve (Figure 5) are insufficient to establish a scaling law, and the visual inference that RetNet "tends to outperform Transformer when the model size is larger than 2B" could reverse, plateau, or diverge at 13B, 30B, or 70B. Since Transformers exhibit emergent capabilities at large scale (in-context learning, reasoning, instruction following) that are absent at 6.7B, there is no evidence that RetNet would replicate these capabilities. The training budget of 100B tokens for a 6.7B model is also well below compute-optimal — Chinchilla scaling laws suggest roughly 130B+ tokens for a model of this size — meaning the models are undertrained relative to how production LLMs are produced. Whether RetNet's architectural advantages persist or diminish under optimal training budgets is unmeasured. A practitioner deciding whether to invest in RetNet over Transformer for a production LLM deployment has no evidence at the scale that matters.

**What evidence exists in the paper.** Figure 5 shows three model sizes on 100B tokens; Figure 1 shows a scaling curve with axes labeled 1, 3, 7 on the model size axis. No experiments at 13B+ or with additional training tokens are reported. The paper's own conclusions are qualified — "we empirically observe" rather than "we demonstrate" — but the framing language ("successor") implies a level of validation the experiments do not provide.

**Mitigation status.** Not addressed. The paper does not explicitly flag this as a limitation. Section 4 acknowledges future work to "scale up RetNet in terms of model size and training steps," implicitly conceding that current scale is insufficient, but does not characterize the risk that scaling trends may not hold.

### Inference Efficiency Headline Numbers Are Not Reproducible From the Reported Evidence

**The assumption or constraint.** The paper makes specific, quantitative efficiency claims in Section 1 and Figure 1: RetNet "decodes 8.4× faster and saves 70% of memory than Transformers with key-value caches" for a 7B model at 8k input length. These claims are intended as the paper's primary practical contribution — the justification for adopting RetNet over Transformer in deployment. However, the detailed inference results in Figure 6 do not reproduce these ratios, and the measurement conditions are never specified.

**The consequence.** A practitioner cannot determine whether the 8.4× throughput improvement applies to their deployment scenario. Figure 6b shows RetNet throughput at roughly 280 wps and Transformer throughput at roughly 190 wps at 8192 sequence length — a ratio of approximately 1.5×, not 8.4×. Figure 6a shows RetNet memory at roughly 16 GB and Transformer at roughly 42 GB — a ratio of approximately 2.6× (RetNet uses ~38% of Transformer's memory), not 3.3× as "70% savings" would imply. The 8.4× figure may arise from a specific combination of batch size, sequence length, prompt-to-generation ratio, or total tokens processed — but since the paper does not disclose these conditions, the claim cannot be verified, reproduced, or applied to make deployment decisions. This undermines the paper's most impactful quantitative contribution: the claim that RetNet dramatically reduces inference cost is the primary reason to adopt it over Transformer, but the evidence for the specific magnitude of the improvement is incomplete.

**What evidence exists in the paper.** Figure 6 reports memory, throughput, and latency for the 6.7B model at sequence lengths 2048–8192 on an A100-80GB. Figure 1 and the introduction paragraph state the 8.4×, 15.6× (latency), and 3.4× (throughput on the bar chart) figures as headline results. The text does not enumerate the measurement conditions (batch size, prompt length, generation length, caching strategy) under which these multipliers were obtained. The 15.6× latency figure in Figure 1 does not correspond to any ratio visible in Figure 6c. The bar chart in Figure 1 (GPU Memory, Throughput, Latency) plots bars labeled "RetNet" and "Transformer" with ratios annotated, but the underlying data cannot be cross-referenced with the detailed plots in Figure 6.

**Mitigation status.** Partially addressed by the existence of Figure 6, which provides detailed measurements under specified conditions and shows substantial (though smaller) improvements. A careful reader can extract 1.5× throughput improvement, ~2.6× memory improvement, and significant latency improvements from Figure 6. But the paper does not reconcile these with the headline figures, explain the discrepancy, or specify the conditions under which the larger multipliers were measured. The limitation is in the presentation and reproducibility of the central quantitative claim, not in the absence of efficiency improvements (which are real and substantial).

### No Comparison Against Production-Ready Transformer Inference Optimizations

**The assumption or constraint.** The paper's inference comparison (Figure 6) uses a standard Transformer with a full key-value cache — every attention head stores its own keys and values. This is the simplest Transformer inference setup, but it is not representative of production deployments. Modern LLM inference stacks employ several orthogonal optimizations that substantially reduce KV cache memory: **multi-query attention** (MQA; Shazeer, 2019) shares keys and values across all heads, reducing cache size by the number of heads (typically 8–16×); **grouped-query attention** (GQA; used in LLaMA 2, Llama 3) shares keys and values across groups of heads, providing a tunable tradeoff; **paged attention** (vLLM; Kwon et al., 2023) manages KV cache memory more efficiently via virtual memory paging; and **continuous batching** dynamically packs requests to maximize throughput. The paper does not compare RetNet's inference efficiency against a Transformer equipped with any of these techniques.

**The consequence.** The claimed memory and throughput advantages of RetNet over Transformer may be substantially smaller — or disappear entirely — when compared against a production-optimized Transformer. For example, a Transformer using multi-query attention with 16 heads would have a KV cache that is 16× smaller per token than the standard multi-head baseline used in Figure 6. This would dramatically reduce the memory growth with sequence length, partially closing the gap with RetNet's constant memory. Similarly, paged attention and continuous batching improve Transformer throughput in ways not captured by the single-sequence, fixed-batch-size measurements in Figure 6b. The paper's core argument — that eliminating the KV cache is a decisive architectural advantage — depends on showing that even the best available KV cache optimizations cannot close the gap. Without this comparison, the advantage is established only against a straw-man Transformer baseline.

**What evidence exists in the paper.** Section 3.4 and Figure 6 compare RetNet against a standard Transformer with KV cache. The paper mentions that "the implementation is greatly simplified without key-value cache tricks" (Section 1), implicitly acknowledging that KV cache optimizations exist but not benchmarking against them. The Transformer variant comparison (Table 1, Table 5) evaluates RWKV, H3, Hyena, and Linear Transformer — but these are alternative architectures, not optimized Transformer deployments. The training comparison (Table 4) benchmarks against FlashAttention, which is an attention computation optimization (not a KV cache optimization) and represents good practice for training fairness. No inference-time KV cache optimization is tested.

**Mitigation status.** Not addressed. The paper does not acknowledge this as a limitation or discuss how MQA/GQA/paged attention would affect the comparison. Future work on "kernel fusion or FlashAttention-like acceleration" (Section 3.3) is mentioned for training, but inference optimizations for Transformers are not discussed.

### No Evidence on Long-Context Modeling Quality — Only Inference Cost

**The assumption or constraint.** The paper demonstrates that RetNet's **inference cost** is length-invariant — GPU memory, throughput, and latency remain constant as sequence length grows (Figure 6). This is a computational property of the recurrent representation and is convincingly established. However, the paper does not evaluate whether RetNet's **modeling quality** on long sequences matches or degrades relative to Transformers. Constant-cost inference is only valuable if the model can actually use long context effectively.

**The consequence.** A practitioner choosing RetNet for long-context applications (document QA, summarization of long texts, multi-turn dialogue with extensive history) cannot determine whether the model will maintain accuracy as context grows. The exponential decay mechanism ($\gamma^{n-m}$) is a strong recency bias — information from 512 tokens ago is weighted by approximately $\gamma^{512}$. For the slowest decay rate used in the parametric models ($\gamma = 511/512 \approx 0.998$), this factor is $0.998^{512} \approx 0.36$, meaning information 512 tokens back contributes at most 36% of its original weight to the current state. For faster decay heads ($\gamma = 31/32 \approx 0.969$), the factor is $0.969^{512} \approx 1.6 \times 10^{-7}$ — effectively zero. Whether the fixed-size state $S_n \in \mathbb{C}^{d \times 2d}$ can preserve long-range dependencies through this aggressive decay, or whether critical information gets "forgotten" before it can be used, is not empirically tested. Transformers, by contrast, can attend directly to any previous token with equal maximum weight (via softmax), giving them theoretically unbounded effective context — the limitation is computational cost, not architectural information loss.

**What evidence exists in the paper.** Table 8 shows perplexity for context lengths 512, 1024, and 2048, with RetNet perplexity improving from 13.09 to 11.98 as context grows — suggesting the model benefits from longer context at these modest lengths. But 2048 is the maximum training context length; no evaluation at 4096, 8192, or beyond is reported. The chunkwise training (Section 3.3) uses sequence length 8192 but only for training efficiency measurements (Table 4), not for language modeling quality evaluation. The out-of-domain evaluations (Table 5) do not vary sequence length.

**Mitigation status.** Not addressed as a limitation. The paper focuses entirely on computational cost as the long-sequence bottleneck but does not evaluate whether the architecture imposes a modeling bottleneck at long ranges. The multi-scale decay design (multiple $\gamma$ values) is specifically intended to address this — slow-decay heads are meant to preserve long-range information — but whether they succeed in practice at lengths beyond 2k tokens is an open question that the paper does not investigate.

### Difficulty Estimation and Dynamic Strategy Allocation Are Completely Absent

**The assumption or constraint.** RetNet provides a single sequence modeling mechanism with three computational paradigms, but it does **not** include any mechanism for estimating the difficulty of an input or dynamically selecting which paradigm to use based on input characteristics. The parallel form is used for training, the recurrent form for inference, and the chunkwise form for long-sequence training — this is a fixed schedule determined by the deployment phase (train vs. infer) and sequence length, not an adaptive policy that could, for example, use more computation on difficult tokens or allocate different decay rates based on content.

**The consequence.** In Transformers, each token's attention distribution is **content-dependent** — the model can decide to attend strongly to a single relevant token (e.g., a named entity mentioned 500 tokens ago) while mostly ignoring others. This content-based selectivity is the key mechanism by which Transformers handle variable difficulty: a token that requires long-range information can "reach back" through softmax attention with high weight, while a token that only needs local context can have a narrow attention distribution. Retention replaces this content-dependent attention weighting with a **fixed positional decay** $\gamma^{n-m}$ multiplied by a content-based dot product $Q_n K_m^\top$. The model cannot increase the attention weight on a distant but highly relevant token beyond what the exponential decay allows — the positional factor $\gamma^{n-m}$ applies regardless of content. This means that for tasks requiring precise long-range retrieval (e.g., answering a question about a fact stated early in a long document), RetNet has a fundamental architectural disadvantage: the decay function may have already "forgotten" the relevant information before the query token is processed. The paper does not measure whether this limitation manifests in practice as degraded long-context accuracy or task-specific failures.

**What evidence exists in the paper.** The ablation "−γ decay" (Table 6), which sets $\gamma = 1$ for all heads, shows the largest perplexity degradation among all ablations (+1.81), confirming that exponential decay is essential and that uniform averaging over history performs worse. This suggests the recency bias is beneficial on average — which is expected, since nearby context is usually more relevant in language — but it does not test whether the model suffers on tasks that specifically require retrieval of distant information. Table 8 shows perplexity improves with longer context, but this measures average token prediction quality, not targeted long-range retrieval. No synthetic tasks (e.g., copy tasks, associative recall, passkey retrieval) that specifically test long-range information access are evaluated.

**Mitigation status.** Not addressed. The paper does not discuss the tradeoff between content-based attention selectivity (Transformer's strength) and fixed positional decay (Retention's design), does not evaluate tasks that isolate long-range retrieval capability, and does not propose mechanisms to dynamically modulate the effective context window (e.g., content-dependent $\gamma$, learned gating of the decay, or hybrid attention-retention mechanisms). This is a fundamental architectural tradeoff — RetNet gains O(1) inference by giving up content-dependent attention weighting — and the paper neither quantifies the performance cost of this tradeoff nor proposes mitigations.

### Single-Domain, Single-Modality, English-Only Evaluation

**The assumption or constraint.** All language modeling experiments use a training corpus compiled from The Pile, C4, and The Stack — English-language text corpora. All downstream evaluations (Table 3, Table 5) use English-language benchmarks. The paper positions RetNet as a "foundation architecture for large language models" (Abstract) and mentions future work on "multimodal large language models" (Section 4), but provides no evidence about RetNet's behavior on code, mathematics, multilingual text, or multimodal inputs.

**The consequence.** Architecture design choices that work for English text may not transfer to other domains. The multi-scale decay mechanism assumes that exponential recency is a good prior for sequence structure — this is reasonable for natural language (local syntax, paragraph-level coherence) but may be less appropriate for code (where a function definition at the top of a file is as relevant as the immediately preceding line) or mathematics (where a lemma stated early in a proof is referenced much later with undiminished importance). The complex-valued position encoding $e^{i n \theta}$ encodes sequential position but not the hierarchical or tree-structured relationships present in code syntax or mathematical derivations. The fixed $\gamma$ schedule was designed with English text temporal scales in mind and may not align with the characteristic dependency lengths in other domains. Without evaluation beyond English text, the claim that RetNet is a "foundation architecture" and "successor to Transformer" is based on a narrow slice of LLM capabilities.

**What evidence exists in the paper.** The training corpus includes The Stack (source code), so the models are exposed to code during pretraining. However, no code-specific evaluations (HumanEval, MBPP) are reported, so it is unknown whether RetNet learns to generate or understand code effectively. The downstream benchmarks (HellaSwag, BoolQ, COPA, PIQA, Winograd, Winogrande, StoryCloze) are all English commonsense reasoning and natural language understanding tasks. The out-of-domain evaluations (PG22, QMSum, GovReport, SummScreen) vary genre and domain but remain English text.

**Mitigation status.** Acknowledged as future work. Section 4 states: "We will also use RetNet as the backbone architecture to train multimodal large language models." The paper does not present this as a limitation — it frames it as a natural extension — but the absence of non-English, code, and math evaluation means the current evidence supports "RetNet is competitive with Transformer for English language modeling" rather than "RetNet is a successor to Transformer for large language models" in general.

## 7. Implications and Future Directions

### How This Work Changes the Landscape

This paper introduces a **fundamentally different design philosophy for sequence modeling architectures**: rather than starting from the desired computation (content-based attention) and trying to make it efficient, start from the desired computational properties (parallel training, O(1) inference, linear memory) and derive the mathematical structure that satisfies them. This inverts the direction of architecture research that has dominated since the Transformer's introduction in 2017.

The magnitude of this shift is **conceptual reframing rather than paradigm shift at present**, but with paradigm-shift potential if results replicate at scale. The paper does not introduce a new training objective, a new scaling law, or a new capability — it demonstrates that an alternative mathematical mechanism can achieve the same empirical outcomes as softmax attention while providing deployment properties that attention fundamentally cannot. The shift is from "how do we make Transformers cheaper?" (the motivating question behind linear attention, FlashAttention, KV cache compression, sparse attention, and mixture-of-experts) to "what sequence mixing operation has the computational properties we need, and can we prove it works?" This changes the search space for architecture design from patching attention's inefficiencies to deriving mechanisms from first principles.

The paper resolves a **specific contradiction in the efficient architecture literature** that has been accumulating since 2020. Linear attention methods (Linear Transformer, Performer, Linformer) promised O(1) inference via kernel approximations but consistently underperformed Transformers in practice, leading to a widespread belief that softmax attention was necessary for quality. State-space models (S4, H3, Hyena) showed promising results on synthetic long-range tasks but had not been convincingly validated at LLM scale or matched Transformer perplexity on standard language modeling. RWKV demonstrated that RNN-style architectures could be competitive but sacrificed training parallelism entirely. The field was fragmenting into architectures that each achieved two vertices of the impossible triangle at the cost of the third. RetNet's core contribution is demonstrating that **this fragmentation was unnecessary** — a single mechanism can achieve all three properties simultaneously, and the key is exact mathematical equivalence between parallel and recurrent forms, not approximation or hybridization.

The paper also **reframes the role of the key-value cache in architecture design**. Prior work treated the KV cache as an implementation detail to be optimized — FlashAttention makes it faster, multi-query attention makes it smaller, paged attention makes it more memory-efficient. RetNet eliminates it entirely at the architectural level, replacing explicit key-value storage with a fixed-size recurrent state. This shifts the conversation from "how do we manage the growing cache?" to "why do we need a cache at all?" If the recurrent state can be made sufficiently expressive — and the paper's ablation on head dimension (Table 6) suggests capacity matters — then the KV cache is revealed as an architectural choice, not a necessity, for high-quality sequence modeling.

Research directions that become **more attractive** after this work:

- **Architecture-first scaling research.** The paper suggests that the choice of sequence mixing mechanism may have as much impact on scaling behavior as model size or training data, opening a new axis for scaling laws research: how do different mixing mechanisms scale with compute? This was previously a fixed choice (attention); now it is a variable to be optimized.

- **State capacity as a first-class design parameter.** The paper's head dimension ablation and widened value dimension connect recurrent state size directly to model quality, making state capacity something to be explicitly tuned rather than inherited from attention head dimensions.

- **Multi-scale temporal modeling via fixed decay.** The geometric $\gamma$ spacing provides a template for imposing temporal structure without learned parameters, which could generalize to other sequence domains (video, audio, time series) where characteristic timescales are known a priori.

Research directions that become **less attractive**:

- **Linear attention via kernel approximation.** If exact dual forms exist that match Transformer quality, the approximation approach (which permanently accepts a performance ceiling) becomes less defensible unless it offers compensating advantages that RetNet lacks.

- **Pure RNN training with element-wise operators.** RWKV-style architectures sacrifice training parallelism for inference efficiency. RetNet shows this tradeoff is unnecessary — you can have both, so architectures that accept the training parallelism cost are at a structural disadvantage at scale.

- **KV cache compression heuristics.** If the KV cache can be eliminated architecturally while maintaining quality, research on pruning, evicting, or quantizing cached keys and values addresses a problem that may not exist in future architectures.

### Follow-Up Research This Work Enables

**Scaling RetNet to 70B+ parameters with compute-optimal training budgets.** The paper's most critical gap is the absence of evidence at production LLM scale. A direct follow-up would train RetNet at 13B, 30B, and 70B parameters using Chinchilla-optimal token budgets (e.g., ~260B tokens for 13B, ~600B for 30B, ~1.4T for 70B) and compare against equivalently-trained Transformers on the full suite of LLM evaluation benchmarks (MMLU, BIG-Bench, HumanEval, GSM8K, etc.). The key measurement is whether the apparent scaling trend in Figure 5 — RetNet pulling ahead after 2B — continues, flattens, or reverses. A negative result (RetNet plateauing or diverging from Transformer) would establish the boundary conditions for the architecture. A positive result (RetNet maintaining or widening its advantage) would make the "successor" claim substantially more credible and trigger serious investment in RetNet-based LLMs. This is newly tractable because the paper provides a complete training recipe (hyperparameters in Appendix A, initialization from DeepNet, chunkwise training for long sequences) and demonstrates training stability at 6.7B, removing the uncertainty about whether RetNet can be trained at all.

**Systematic evaluation of long-range retrieval capability under exponential decay.** The paper establishes that inference cost is length-invariant but does not measure whether modeling quality degrades on tasks requiring precise access to distant information. A follow-up would evaluate RetNet on synthetic long-range benchmarks: the **passkey retrieval task** (retrieve a randomly placed numeric key from a long document), **associative recall** (remember token pairs presented at the start of a sequence and retrieve the partner when cued), and the **Long Range Arena** benchmark suite. The experiment would compare RetNet against Transformers (with and without sparse attention) at sequence lengths from 2k to 64k tokens, measuring both accuracy and the effective retrieval horizon — the distance at which information becomes effectively inaccessible due to decay. The multi-scale $\gamma$ design predicts that slow-decay heads ($\gamma \approx 0.998$) should preserve information for thousands of tokens, but whether $d \times 2d$ state capacity is sufficient in practice is an open empirical question. This would establish whether the exponential decay is a practical limitation or a benign inductive bias that the multi-scale design successfully mitigates.

**Combining retention with content-dependent gating for dynamic context windows.** The paper identifies — implicitly — a fundamental tension: fixed exponential decay provides computational efficiency but removes content-based control over how much attention distant tokens receive. A natural extension would introduce a **learned gating mechanism** that modulates the effective decay based on content: for example, the state update $S_n = \gamma S_{n-1} + K_n^\top V_n$ could become $S_n = g(X_n) \cdot \gamma S_{n-1} + (1 - g(X_n)) \cdot K_n^\top V_n$, where $g(X_n) \in (0,1)$ is a learned function of the current input that decides how much to retain versus overwrite. When an important entity is introduced, the gate could preserve existing state; when a topic shift occurs, the gate could allow faster forgetting. This preserves O(1) inference (the gate is a scalar per head, adding negligible computation) while addressing the architecture's inability to dynamically reweight attention — a capability that softmax provides and retention currently lacks. The experiment would compare gated vs. ungated retention on tasks requiring selective long-range memory, using the same training setup as the paper.

**Benchmarking RetNet against production Transformer inference stacks with MQA/GQA.** The paper's inference comparison uses a standard multi-head Transformer with full KV cache, which no production LLM deployment uses. A rigorous follow-up would implement RetNet inference in a production framework (e.g., vLLM, TensorRT-LLM) and benchmark against equivalently-sized Transformers using multi-query attention (keys and values shared across all heads), grouped-query attention (e.g., 8 query heads sharing 1 key-value head, as in LLaMA 2 70B), and paged attention memory management. The measurement would cover realistic serving scenarios: variable-length prompts, continuous batching with multiple concurrent requests, and total throughput (requests/second) under a latency constraint (e.g., time-to-first-token < 100ms). The key question is whether RetNet's O(1) state still provides a decisive advantage when the Transformer baseline uses an 8–16× smaller KV cache via MQA/GQA. This experiment determines whether the architectural argument (eliminate the cache) translates to practical deployment advantages or whether production optimizations have already made the cache bottleneck manageable for Transformers.

**Training a RetNet-based instruction-following model with RLHF.** The paper evaluates only base language model perplexity and zero-shot/few-shot accuracy — not instruction following, dialogue, or alignment, which are the capabilities that make LLMs useful products. A follow-up would fine-tune the 6.7B RetNet (or a scaled-up version) with supervised instruction tuning and RLHF (or DPO) on standard alignment datasets, then evaluate on benchmarks like AlpacaEval, MT-Bench, and Chatbot Arena. This tests a practical concern: architectures with strong recency bias (exponential decay) might struggle with multi-turn dialogue where instructions from early turns must be remembered precisely. If RetNet instruction-tuned models match Transformer instruction-tuned models, it validates the architecture for the most commercially important LLM use case. If they underperform, it identifies a specific failure mode that future architecture iterations must address.

**Ablation of the value dimension ratio to quantify state capacity requirements.** The paper doubles the value dimension ($2d$) relative to queries and keys ($d$), arguing this increases "memory capacity of hidden states," but never ablates this specific choice. A follow-up would train 200M-parameter RetNet variants with value dimensions of $d$, $2d$, $3d$, and $4d$ (adjusting FFN size to keep total parameters constant) and measure both perplexity and the effective context length (via synthetic retrieval tasks). This would produce a **state capacity scaling curve** — how much does increasing the state size improve long-range modeling, and where does it saturate? The result informs a central design question for recurrent architectures: what is the right ratio of "memory write" bandwidth (value dimension) to "memory read" bandwidth (query dimension)? The paper's existing ablation (reducing head dimension from 256 to 64, Table 6) conflates state capacity with query-key expressiveness; isolating value dimension would provide cleaner evidence.

### Practical Applications and Downstream Use Cases

**Latency-sensitive interactive applications (chatbots, code completion, real-time translation).** The paper's Figure 6c shows RetNet latency is essentially flat at ~50 ms per decoding step across batch sizes 1–8, while Transformer latency grows from ~50 ms (batch 1, 1024 context) to ~320 ms (batch 8, 8192 context). For interactive applications where users expect sub-100ms response times, this means RetNet can serve 8× more concurrent users at the same latency, or maintain responsiveness at much longer context lengths (e.g., a chatbot with 32k tokens of conversation history). A code completion service using RetNet could maintain context over an entire codebase without latency degradation, while a Transformer would require context window truncation or suffer increasing delay. The batch size insensitivity is the killer feature here — it directly translates to higher throughput per GPU in latency-constrained serving, reducing cloud compute costs for real-time LLM products.

**On-device deployment with long context.** The paper reports that for the 6.7B model at 8k sequence length, RetNet's total GPU memory is ~16 GB with only 3% attributed to the recurrent state (the rest to model weights). This means the inference memory footprint is dominated by the model itself, not the context. For on-device scenarios (mobile phones, laptops, edge accelerators) where memory is severely constrained (e.g., 4–8 GB total), this property is enabling: a quantized RetNet could process arbitrarily long documents or maintain indefinite conversation history with fixed memory overhead, while a quantized Transformer would hit a hard context limit when the KV cache exhausts available memory. The 70% memory reduction claim (Section 1) applies to the KV cache specifically — for edge deployment, this could mean the difference between fitting the model at all versus running out of memory after a few hundred tokens.

**Batch inference for document processing pipelines.** For organizations running large-scale batch inference — evaluating thousands of documents for classification, summarization, or information extraction — Figure 6b shows RetNet throughput is length-invariant at ~280 wps while Transformer throughput drops from ~275 wps (2k tokens) to ~190 wps (8k tokens). For a pipeline processing 100,000 documents averaging 8k tokens each, RetNet would complete the batch in approximately 100,000 × 8192 / 280 ≈ 2.9 million seconds (~34 days on a single A100). A Transformer at 8k would require approximately 100,000 × 8192 / 190 ≈ 4.3 million seconds (~50 days) — roughly 50% longer. The throughput advantage compounds with document length: the longer the documents, the larger the gap. This directly reduces cloud compute costs for batch NLP workloads, particularly those involving long texts (legal documents, scientific papers, financial reports).

### When to Prefer This Method

The paper explicitly positions RetNet against Transformer based on inference efficiency, training parallelism, and performance — the "impossible triangle." The decision criteria follow directly from the empirical results:

- **Prefer RetNet when** inference latency or memory is the binding constraint (interactive applications, on-device deployment, long-context serving) AND the model scale is moderate (1.3B–6.7B, extrapolating from the paper's evidence) AND the task is primarily English text language modeling or commonsense reasoning. The length-invariant throughput (Figure 6b), flat latency curve (Figure 6c), and elimination of the KV cache provide unambiguous advantages in these settings, and the paper demonstrates performance parity with Transformer at tested scales (Figure 5, Table 3).

- **Prefer RetNet when** training long sequences (8k+ tokens) with limited GPU memory. Table 4 shows RetNet uses 34.5 GB vs. 74.8 GB for standard Transformer at 1.3B on 8k sequences — nearly 2.2× less memory — and still outperforms FlashAttention (38.8 GB). The chunkwise recurrent representation makes long-sequence training feasible on hardware that would be insufficient for standard Transformer attention.

- **Prefer Transformer when** model scale exceeds the validated range (beyond 6.7B) AND the deployment environment has sufficient GPU memory and batch sizes for KV-cached inference, OR when the task requires precise long-range retrieval that may stress the exponential decay mechanism. The paper provides no evidence for RetNet at GPT-3 scale or beyond, and the architectural assumption that exponential decay does not lose critical long-range information is untested on retrieval-specific tasks.

- **Prefer Transformer when** the deployment stack already includes production KV cache optimizations (multi-query attention, grouped-query attention, paged attention) AND the measured Transformer inference cost is acceptable for the target application. The paper's inference comparison is against a basic multi-head Transformer; whether RetNet still provides decisive advantages over MQA/GQA-equipped Transformers is an open question not addressed in this work.
