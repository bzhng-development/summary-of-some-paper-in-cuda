# What Matters in Transformers? Not All Attention is Needed

**ArXiv:** [2406.15786](https://arxiv.org/abs/2406.15786)

## 🎯 Pitch

Attention layers, the very mechanism that defines Transformer architectures, turn out to be massively redundant—dropping half of them from a 70B-parameter model costs almost no performance while delivering a 48% speedup. This surprising finding reveals that the standard symmetric stacking of attention modules, long taken for granted, is a major bottleneck we can immediately exploit for faster, leaner models.

---

## 1. Executive Summary

This paper systematically analyzes structural redundancy across three levels of Transformer architecture—Blocks, MLP layers, and Attention layers—in Llama-2, Mistral, and Llama-3 models using a similarity-based importance metric (cosine similarity between layer inputs and outputs, aggregated via residual connections). The central discovery is that Attention layers, despite being the defining component of Transformers, exhibit extreme redundancy: removing half the Attention layers from Llama-2-70B yields only a 2.4% performance drop while achieving a 48.4% inference speedup. The authors formalize this into a training-free pruning strategy called **Attention Drop** (selectively dropping layers with the lowest importance scores) and a complementary **Joint Layer Drop** (combining importance scores from both MLP and Attention layers to drop the least important modules of either type, enabling more aggressive pruning—e.g., dropping 31 total layers from Llama-2-13B while retaining 90% of MMLU performance). The paper further demonstrates that attention layer redundancy is inherent and persistent throughout training, establishing that deeper layers exhibit consistently higher redundancy across all stages but that this redundancy pattern in attention layers is a bottleneck built into the architecture itself, not an artifact of undertraining.

## 2. Context and Motivation

### The Core Problem: LLMs Are Over-Parameterized, But We Don't Know Where

The fundamental question this paper tackles is: **if we want to make a Transformer-based LLM smaller and faster, which parts should we remove?** This matters because the current paradigm of Transformer design treats all architectural components as equally essential by default. Every decoder layer contains exactly one Attention sublayer and one MLP sublayer, stacked $L$ times. This symmetric stacking is an architectural convention inherited from Vaswani (2017), not a finding grounded in empirical necessity. As LLMs scale to 70B+ parameters with up to 80 layers, this unexamined symmetry becomes extremely costly — Llama-2-70B at FP16 precision exceeds the memory capacity of a single A100 GPU.

The gap the paper identifies is specific and important: **prior compression work treats redundancy uniformly, without distinguishing between Attention and MLP layers.** Quantization methods (Frantar et al., 2023; Lin et al., 2024) reduce the precision of all parameters equally. Unstructured pruning (Sun et al., 2023; Frantar & Alistarh, 2023) removes individual weights across the entire network without regard to layer type. Even structured pruning approaches that remove entire layers or blocks (Gromov et al., 2024; Men et al., 2024; Kim et al., 2024) treat all layers as interchangeable units, applying the same pruning logic regardless of whether a layer is an Attention or MLP module.

The authors argue this is a critical oversight because Attention and MLP layers **perform fundamentally different functions** in the Transformer architecture:

- **Attention layers** compute contextual relationships between tokens using quadratic-complexity operations. They are responsible for information flow across the sequence — determining which tokens attend to which other tokens. They also impose the memory bottleneck of the KV-cache, which stores intermediate key and value representations for all previously generated tokens.

- **MLP layers** transform each token independently through up-projection and down-projection matrices. They contribute the majority of the model's parameter count and perform position-wise feature extraction unaided by cross-token interaction.

Given these divergent roles, there is no a priori reason to believe both layer types exhibit the same degree of redundancy. Yet prior work had never systematically compared them.

### Why This Matters: Practical and Theoretical Stakes

The practical stakes are substantial. The paper cites concrete deployment constraints that make structural pruning urgently relevant:

**Memory costs dominate deployment.** The KV-cache for storing attention states grows linearly with both sequence length and number of attention layers. For Llama-2-13B (which lacks grouped-query attention), the KV-cache alone consumes 52GB of memory at a batch size of 32 with 2048-token sequences. Removing redundant attention layers directly shrinks this cache — in the extreme case, halving the attention layers (and thus the KV-cache entries) reduces memory from 52GB to 26GB. For deployments on resource-constrained hardware or high-throughput serving environments where memory bandwidth is the bottleneck, these savings directly translate to larger possible batch sizes, longer context windows, or reduced hardware requirements.

**Inference latency scales with depth.** Each layer adds sequential computation that cannot be parallelized across layers. Reducing depth — whether by removing blocks, MLP layers, or Attention layers — directly improves inference throughput. The paper quantifies this through the Speedup Degradation Ratio ($\gamma$), which measures the percentage of performance lost per percentage of speedup gained. A method with low $\gamma$ is practically valuable because it extracts efficiency with minimal capability damage. The paper's headline result — a 48.4% speedup with only 2.4% average performance degradation on Llama-2-70B — represents a $\gamma$ of approximately 0.05, meaning each 1% of speedup costs only 0.05% of performance.

**Training budgets are squandered on unnecessary parameters.** If attention layers are inherently redundant — a finding the paper establishes by tracing redundancy across training checkpoints — then the computational resources spent training those layers are wasted. Understanding which components are redundant *during training* (not just post-training) could inform more efficient architecture design from the outset, potentially enabling models that achieve the same performance with substantially fewer parameters and less pretraining compute.

Beyond these practical concerns, there is a deeper theoretical motivation. The paper is interested in whether attention — widely considered the key innovation distinguishing Transformers from alternative architectures like RWKV (Peng et al., 2023) or Mamba (Gu & Dao, 2024) — is **as indispensable as the literature assumes**. Finding that half the attention layers can be removed with negligible consequence challenges the implicit assumption that every attention layer contributes uniquely and essentially to the model's reasoning capability. It raises the provocative question: if so many attention layers are redundant, what are they actually doing, and could future architectures allocate them differently?

### Where Prior Approaches Fall Short

The paper identifies several limitations in existing compression and redundancy-analysis work:

**Quantization changes precision but not structure.** Approaches like GPTQ (Frantar et al., 2023) and AWQ (Lin et al., 2024) reduce the bit-width of model weights but leave the architecture intact. A 4-bit quantized Llama-2-70B still has 80 blocks, 80 attention layers, and 80 MLP layers — all the redundant components remain, just at lower precision. The paper explicitly notes that quantization and layer dropping are orthogonal (Appendix C, Table 11), meaning they can be combined. But quantization alone does nothing to address the structural over-provisioning that the paper argues is the deeper inefficiency.

**Unstructured pruning produces hardware-unfriendly sparsity.** Methods like Wanda (Sun et al., 2023) and SparseGPT (Frantar & Alistarh, 2023) remove individual weights, creating sparse matrices that maintain performance but cannot be efficiently executed on standard hardware. The resulting models require custom kernels or sparsity-aware accelerators to realize speedups, limiting their practical deployment. The paper directly compares against Wanda (Appendix B, Table 9) and shows that Attention Drop — which removes entire structured modules — achieves similar or better performance while providing actual speedups that Wanda's unstructured sparsity cannot deliver.

**Block-level pruning is too coarse.** Recent work by Gromov et al. (2024) and Men et al. (2024) (ShortGPT) observed that deeper Transformer layers are more redundant than shallower ones and proposed removing entire blocks. This approach is similar in spirit to the paper's "Block Drop" baseline but suffers from what the authors identify as insufficient granularity: removing a block eliminates *both* the attention and MLP sublayers together. The paper shows (Table 1, Figure 5) that Block Drop causes severe performance degradation even at modest pruning ratios — dropping only 4 blocks from Llama-2-13B reduces average performance from 68.2% to 65.8% (a 2.4% absolute drop), and dropping 8 blocks causes a 7.5% absolute drop. This is because blocks inevitably contain some essential layers (particularly MLP layers) that get removed alongside redundant ones. The block-level approach cannot discriminate.

**ShortGPT (Men et al., 2024) and Shortened LLaMA (Kim et al., 2024) identify layer redundancy but don't differentiate by type.** ShortGPT's Block Influence metric measures how much each layer's output deviates from its input, effectively a similar idea to the similarity-based metric in this paper. However, ShortGPT applies this metric to entire layers without decomposing them into Attention and MLP subcomponents. The authors explicitly build on this line of work but take the crucial next step: breaking the block into its constituent sublayers and measuring their redundancy independently. This finer granularity is what reveals the asymmetric redundancy pattern — Attention layers being far more redundant than MLP layers — that the block-level analyses missed entirely.

**Training-based pruning requires expensive retraining.** Shortened LLaMA (Kim et al., 2024) uses post-compression retraining to recover performance after depth pruning (e.g., using PPL-based or Taylor-based importance estimation). While this can improve results, it adds significant computational cost that undermines the efficiency motivation. The paper's Attention Drop is explicitly **training-free** — importance scores are computed once on a small calibration set (256 samples from C4), and layers are removed in a single step. The ablation in Appendix B (Figure 9) confirms that iterative, one-at-a-time dropping provides no meaningful benefit over the simpler one-shot approach, validating the cost-efficient design choice. The comparison with Shortened LLaMA (Table 8) shows that Joint Layer Drop, despite being training-free, outperforms Shortened LLaMA with retraining in average accuracy while achieving higher speedup (1.45× vs. 1.23×).

### The Overlooked Insight: Attention vs. MLP Redundancy

Figure 3 in the paper is the pivotal observation that no prior work had made: when importance scores are computed separately for Attention and MLP layers across multiple calibration datasets (C4, LIMA, CodeAlpaca, MathInstruct), **Attention layers consistently exhibit lower importance scores than MLP layers.** The importance score, defined as:

$$S = 1 - \text{CosineSim}(X, Y)$$

is a measure of how much a layer *transforms* its input. A score near zero means the layer's output is nearly identical to its input — the layer is essentially computing an identity function, contributing nothing novel. The paper finds that many attention layers, particularly in deeper positions, have importance scores near 0.1 or below, while MLP importance scores are substantially higher across the same positions. This means many attention layers are barely modifying the representations passing through them, while MLP layers continue to perform meaningful transformations even at depth.

This observation fundamentally reframes the question. Prior work asked: "Which layers are redundant?" This paper asks: "Which *types* of layers are redundant, and why?" The answer — that attention layers are far more redundant than MLP layers — could not have been discovered by methods that treat all layers as interchangeable.

### How This Paper Positions Itself

The paper frames its contribution not as proposing an entirely new compression technique but as **revealing an architectural property of Transformers that was previously undocumented**. The methodology — cosine similarity between input and output with residual connections properly accounted for — is adapted from Gromov et al. (2024) and Men et al. (2024) but applied at a new level of granularity. The novelty is in *what* this analysis reveals, not the metric itself.

The authors explicitly position their work as providing "valuable insights for future network architecture design" (Section 1) and "insights for scaling down models to achieve more efficient architectures" (Section 8). This is a forward-looking framing: the paper is not just about compressing existing models but about rethinking how Transformers should be designed in the first place. The finding that attention layer redundancy is **inherent and consistent across training stages** (Figure 7, tracking MAP-Neo-7B checkpoints) — not something that emerges only after full training — implies that future models could be built with fewer attention layers from the outset without sacrificing capability.

Two specific architectural implications are highlighted:

1. **The parity between attention and MLP layers is unnecessary.** Current Transformers allocate one attention layer for every MLP layer. The paper's results suggest that a model with fewer attention layers (perhaps only the shallow ones, which show higher importance) but the same number of MLP layers could achieve comparable performance with greater efficiency.

2. **Attention layer redundancy may represent a training bottleneck.** The fact that attention layers remain highly redundant throughout training, while MLP importance scores increase over time, suggests that attention mechanisms may be under-utilized during learning. The paper speculates that future training techniques could be designed to better leverage attention capacity, or that alternative mechanisms could replace redundant attention layers entirely.

The paper also implicitly positions itself in contrast to two common narratives in the field: (a) that attention is the essential, irreplaceable component of Transformers, and (b) that deeper layers are uniformly more important because they handle higher-level semantics. It shows that neither narrative holds uniformly — deeper attention layers are specifically redundant, while deeper MLP layers retain importance, and attention can be pruned far more aggressively than the architecture's design symmetry would suggest.

## 3. Technical Approach

### 3.1 Reader Orientation

This paper builds a **training-free structural pruning system** that identifies and removes redundant layers from pre-trained Transformer-based LLMs by measuring how much each layer's output differs from its input. It solves the problem of *where* to prune: rather than treating all layers as equally important or pruning entire blocks indiscriminately, it separately evaluates Attention sublayers, MLP sublayers, and entire Blocks, revealing that Attention layers are far more redundant than MLP layers and can be aggressively removed with minimal performance loss. The "shape" of the solution is a two-part analysis-and-action pipeline: first, a similarity-based metric computes an importance score for every target module using a small calibration dataset, then a one-shot pruning step removes the modules with the lowest scores according to a user-specified budget.

### 3.2 Big-Picture Architecture (Diagram in Words)

The system consists of five major components:

1. **Calibration Dataset** — a small set of text sequences (256 samples from C4 validation, each truncated to 2048 tokens) that provides representative inputs to probe layer behavior. It is NOT used for training; it is only used for forward passes to compute importance scores.

2. **Importance Score Calculator** — for each target module (Block, MLP+LayerNorm unit, or Attention+LayerNorm unit), captures the module's input hidden states `$X$` and output hidden states `$Y$`, then computes `$S = 1 - \text{CosineSim}(X, Y)$`. Low `$S$` means the module barely transforms its input and is therefore redundant.

3. **Module Selector** — given a dropping ratio or a fixed number of modules to remove, sorts all modules of the target type by their importance scores and selects the lowest-scoring ones for removal. For Joint Layer Drop, this operates over the combined list of Attention and MLP scores.

4. **Model Rewriter** — modifies the model configuration (e.g., HuggingFace `config.json`) to reflect the removed layers, enabling the pruned model to be loaded with standard libraries with only minor configuration changes.

5. **Pruned Model** — the output artifact: a structurally shallower Transformer that can be loaded and run with existing inference frameworks, with corresponding reductions in KV-cache memory and per-step compute.

**Information flow:** Calibration data → forward pass through the full pre-trained model → capture input/output hidden states at every target module → compute cosine similarity per module → aggregate importance scores across calibration samples → sort modules by score → select lowest-scoring modules for removal → rewrite model configuration → output pruned model. Everything is one-shot: no iterative pruning, no retraining, no gradient computation.

### 3.3 Roadmap for the Deep Dive

- **First**, the **similarity-based importance metric** (Equation 1), because it is the foundation for all pruning decisions. We'll define it, explain what it computationally measures, and justify why cosine similarity is chosen over alternative metrics.

- **Second**, **Block Drop** as the baseline approach. This serves as the simplest strawman — removing entire Transformer blocks — and motivates why finer granularity is needed by showing the severe performance degradation it causes.

- **Third**, **MLP Drop** and **Attention Drop** as separate, fine-grained strategies. We'll explain how residual connections are accounted for, why the LayerNorm is included in the measured unit, and how the importance scores for these two layer types reveal the asymmetric redundancy that is the paper's central finding.

- **Fourth**, the **one-shot pruning protocol and model loading** mechanism, including the practical implementation details that make this training-free approach deployable.

- **Fifth**, **Joint Layer Drop**, which combines the two granular strategies by pooling importance scores across both layer types and selecting the globally least-important modules. This builds naturally on the separate analyses and shows how complementary redundancy can be exploited for more aggressive pruning.

### 3.4 Detailed, Sentence-Based Technical Breakdown

This is primarily an **empirical analysis paper** whose core idea is that structurally pruning Transformers by layer type — rather than by whole blocks — reveals a previously undocumented asymmetry: Attention layers are far more redundant than MLP layers, enabling aggressive, training-free pruning with minimal performance degradation.

---

#### The Similarity-Based Importance Metric

The foundation of all pruning decisions in this paper is a single scalar score computed per module, measuring how much a module transforms its input. The underlying hypothesis is straightforward and explicitly stated:

> "redundant modules produce outputs that are similar to their inputs, implying minimal transformation. In contrast, important modules are expected to significantly alter their inputs and thus should be preserved."

The importance score `$S$` for a module is computed as:

$$S = 1 - \text{CosineSim}(X, Y)$$

where `$X$` is the input hidden state tensor to the module and `$Y$` is the output hidden state tensor from the module.

**What this computes:** Cosine similarity measures the angular alignment between two vectors (or, for batched tensor comparisons, it is computed over the hidden dimension and averaged appropriately). It ranges from `$-1$` (perfectly anti-aligned) to `$+1$` (perfectly aligned, i.e., identical up to scaling). Subtracting from 1 inverts this: a module that produces output identical to its input (cosine similarity = 1) gets `$S = 0$`, indicating maximum redundancy. A module that substantially transforms its input (cosine similarity ≪ 1) gets a larger positive `$S$`, indicating importance. The score is therefore a **dissimilarity measure** bounded approximately between 0 and 2 in practice (since hidden states from Transformer layers are almost never perfectly anti-aligned).

**Why this form:** Several alternative metrics could measure redundancy, and the paper explicitly compares against them in Appendix B (Table 7):

- **Random dropping:** selects layers arbitrarily. Achieves average accuracy of only 39.4% when dropping 12 attention layers from Mistral-7B, compared to 64.8% for cosine similarity. This baseline simply demonstrates that not all layers are equally important — some selection logic is better than none.

- **Reverse Order:** drops layers from deepest to shallowest (the order identified by Men et al., 2024 as correlated with redundancy). Achieves 61.5% at 12 dropped layers. This is substantially better than random but significantly worse than cosine similarity, because it imposes a fixed ordering that ignores per-layer variability in importance.

- **Relative Magnitude (from ShortGPT):** measures the L2 norm of the difference between input and output relative to the input norm. Achieves 62.3% at 12 dropped layers. This is closer to cosine similarity but still underperforms, likely because magnitude-based metrics are sensitive to the scale of the residual stream, which can vary across layers for reasons unrelated to functional importance.

The cosine similarity metric has three desirable properties that make it the best choice:

1. **Scale invariance (within the hidden dimension).** Two hidden states that differ only by a constant scaling factor will have cosine similarity 1, correctly indicating that the direction of the representation hasn't changed. This matters because LayerNorm operations can rescale activations without altering their semantic content, and a magnitude-sensitive metric would incorrectly flag such rescaling as "important transformation."

2. **Bounded range.** Cosine similarity is always in `$[-1, 1]$`, making `$S$` naturally interpretable: scores near 0 mean near-identity behavior, scores near 1 mean substantial transformation. This makes threshold selection and cross-model comparison straightforward.

3. **Computationally cheap.** Cosine similarity requires only a dot product and two norm computations per module, with no gradient computation, no parameter updates, and no iterative refinement. For a 70B model, the entire importance-scoring pass over 256 calibration samples completes in minutes on a single GPU.

**Calibration and aggregation.** The importance score is computed per calibration sample and then averaged across all 256 samples. The paper shows (Figure 10) that importance scores stabilize rapidly with sample count — patterns are nearly identical whether using 4, 16, 64, 256, or 1024 samples. This robustness is critical: it means the calibration set can be small (256 samples, the default used throughout experiments) without risking unstable or sample-dependent importance rankings.

**Calibration dataset choice.** The paper defaults to the C4 validation set (Raffel et al., 2019) with sequence length 2048, following the setup of Sun et al. (2023). However, Figure 2 and Figure 3 demonstrate that the importance score patterns are **consistent across diverse calibration datasets**: C4 (web text), LIMA (instruction-following data), CodeAlpaca (code generation), and MathInstruct (mathematical reasoning) all produce qualitatively similar importance score curves. This cross-dataset robustness is important because it means the pruning decisions are not artifacts of the calibration data distribution — they reflect genuine architectural properties of the model, not overfitting to a particular text domain.

#### Block Drop: The Baseline

The simplest structural pruning approach is to remove entire Transformer blocks, where each block consists of one Attention sublayer and one MLP sublayer. The paper treats this as a baseline to motivate finer-grained approaches.

**Definition of a block's importance.** For the `$l$`-th block, the importance score is:

$$S^l_B = 1 - \text{CosineSim}(X^l_B, Y^l_B)$$

where `$X^l_B$` is the input hidden state to the `$l$`-th block (specifically, the input to the first LayerNorm within that block) and `$Y^l_B$` is the output hidden state from the `$l$`-th block (the output after the residual addition following the MLP sublayer).

**What this computes:** the overall transformation performed by the entire block, aggregating both the attention and MLP sublayers and their residual connections. A block with `$S^l_B \approx 0$` is essentially an identity function — it takes in representations and passes them through unchanged, meaning both its attention and MLP components are contributing nothing.

**Pruning procedure.** Blocks are ranked by `$S^l_B$` (ascending: lowest score = most redundant), and the `$k$` lowest-scoring blocks are removed. The model is then rewritten to have `$L - k$` blocks, where `$L$` is the original number of layers. The output of block `$l-1$` now feeds directly into block `$l+1$`, skipping the removed block entirely.

**Why Block Drop fails.** The paper's results (Table 1, Figure 5a) show that Block Drop causes rapid performance degradation:

- Removing 4 blocks from Llama-2-13B drops average accuracy from 68.2% to 65.8% (a 2.4-point absolute decline), with a speedup of only 1.11× and a speedup-degradation ratio `$\gamma = 0.22$` (each 1% of speedup costs 0.22% of performance).

- Removing 8 blocks drops accuracy to 60.7% (a 7.5-point decline), with speedup of 1.24× and `$\gamma = 0.31$`.

- On Mistral-7B, removing 8 blocks drops accuracy from 70.3% to 58.6% (an 11.7-point collapse), with `$\gamma = 0.37$`.

The problem is **granularity**: each block contains one MLP layer and one Attention layer. The paper's subsequent analysis (Figure 3) shows that MLP layers have consistently higher importance scores than Attention layers at the same depth. Removing an entire block therefore discards a relatively important MLP layer along with a redundant Attention layer. The MLP loss drags performance down, while the block-level aggregation prevents the method from selectively preserving the valuable component (MLP) while discarding the redundant one (Attention).

**Visualization of dropping patterns.** Figure 6a shows the dropping order for Block Drop on Mistral-7B and Llama-2-13B. The pattern is consistent: deeper blocks (indices near the maximum layer count) are dropped first, then progressively shallower blocks as the dropping ratio increases. The last one or two blocks (closest to the output) are often preserved even at high dropping ratios, suggesting they perform critical output-proximate transformations. This deepest-first pattern aligns with findings from Men et al. (2024) and Gromov et al. (2024).

#### MLP Drop: Fine-Grained Pruning of MLP Layers

The paper decomposes each Transformer block into its two constituent sublayers — MLP and Attention — and evaluates their redundancy independently. We begin with MLP Drop because its mechanics are slightly simpler, then address Attention Drop, which yields the paper's most surprising finding.

**Why residual connections must be accounted for.** Each MLP sublayer in a standard Transformer is wrapped in a residual connection. The forward computation within a block at layer `$l$` is:

$$Y^l_M = X^l_M + \text{MLP}(\text{LayerNorm}(X^l_M))$$

where `$X^l_M$` is the input to the LayerNorm that precedes the MLP at layer `$l$`, and `$Y^l_M$` is the output after the residual addition.

If we measured similarity between the MLP's *internal* input and output (i.e., between `$\text{LayerNorm}(X^l_M)$` and `$\text{MLP}(\text{LayerNorm}(X^l_M))$`), we would ignore the residual pathway. A module could have the MLP compute a near-zero output, but the residual connection would still pass `$X^l_M$` through, making the overall block output essentially identical to its input. This would make the module appear redundant (because the MLP contributes nothing) but we would incorrectly attribute the redundancy to the MLP's internal computation rather than recognizing the residual as the source of identity-like behavior.

Conversely, measuring similarity between `$X^l_M$` and `$Y^l_M$` (the input and output of the entire MLP+residual unit) correctly captures whether the *overall sublayer* is performing a meaningful transformation. If the MLP is important, `$Y^l_M$` will differ substantially from `$X^l_M$`. If the MLP is redundant, `$Y^l_M \approx X^l_M$`, indicating the MLP is essentially computing a zero or near-zero function and the residual is preserving the input.

**The MLP importance score.** To properly capture this, the paper treats the **MLP layer and its associated LayerNorm as a single unit**. The importance score is:

$$S^l_M = 1 - \text{CosineSim}(X^l_M, Y^l_M)$$

where `$X^l_M$` is the hidden state entering the LayerNorm before the MLP at layer `$l$`, and `$Y^l_M$` is the hidden state after the residual addition following the MLP.

**What this computes:** the dissimilarity between what enters the MLP sublayer unit and what exits it, including the residual pathway. A score near 0 means the MLP sublayer is approximately an identity function — the input passes through essentially unchanged. A larger score means the MLP is performing meaningful transformation.

**Why the LayerNorm is included:** When an MLP layer is dropped, its associated LayerNorm must also be removed because the LayerNorm's output scale and bias are calibrated for the original MLP's input distribution. If the MLP were removed but the LayerNorm kept, the residual connection would add the LayerNorm-modified input to the previous block's output, producing an incorrect transformation. Removing both as a unit preserves the residual pathway in its simplest form — the input `$X^l_M$` passes directly to the next sublayer without any modification. The paper validates this design choice in Appendix B (Table 6), confirming that "the involvement of the residual connection is essential for Layer Drop": dropping without considering the residual (measuring only internal MLP/Attention input vs. output) produces substantially worse results.

**Pruning procedure for MLP Drop.** The `$k$` MLP sublayer units with the lowest `$S^l_M$` scores are removed. The model configuration is rewritten so that, at the positions of removed MLP sublayers, the output of the preceding Attention sublayer (or block input) feeds directly into the next Attention sublayer's LayerNorm, skipping the MLP entirely.

**Results of MLP Drop.** Table 1 and Figure 5b show that MLP Drop is significantly less forgiving than Attention Drop:

- Dropping 4 MLP layers from Llama-2-13B reduces accuracy from 68.2% to 66.9% (a 1.3-point drop), with `$\gamma = 0.32$`.
- Dropping 8 MLP layers reduces accuracy to 61.9% (a 6.3-point drop), with `$\gamma = 0.79$`.
- On Mistral-7B, dropping 8 MLP layers causes catastrophic degradation: accuracy falls from 70.3% to 53.4% (a 16.9-point collapse), with `$\gamma = 2.82$`.

The `$\gamma$` values for MLP Drop are substantially higher than for Attention Drop, indicating a much worse speed-accuracy trade-off. MLP layers, particularly the shallow ones, perform transformations that the model depends on. The paper attributes this to the role of MLPs in position-wise feature extraction — each token's representation is independently transformed, and this transformation contributes to the model's knowledge and reasoning capacity in a way that cannot be easily bypassed.

**Importance score patterns for MLP layers.** Figure 3a shows MLP importance scores across layer indices for multiple calibration datasets. The pattern shares some similarity with Blocks: deeper layers tend to have lower scores (more redundancy), and the very last layer often shows elevated importance. However, the absolute values of MLP importance scores are consistently higher than Attention scores at the same depth — MLP scores rarely fall below 0.1, while many Attention scores hover near 0.05 or lower. This quantitative difference is the paper's key empirical finding.

#### Attention Drop: The Central Contribution

The procedure for Attention Drop mirrors MLP Drop structurally but operates on a different sublayer and produces dramatically different results.

**The Attention sublayer unit.** Like MLPs, Attention sublayers operate within a residual connection:

$$Y^l_A = X^l_A + \text{Attention}(\text{LayerNorm}(X^l_A))$$

where `$X^l_A$` is the input to the LayerNorm preceding the Attention sublayer at layer `$l$`, and `$Y^l_A$` is the output after residual addition.

The importance score is defined analogously:

$$S^l_A = 1 - \text{CosineSim}(X^l_A, Y^l_A)$$

**What this computes:** the dissimilarity between the input and output of the entire Attention sublayer unit (LayerNorm + Attention + residual). A score near 0 means the Attention sublayer is essentially computing an identity function — the multi-head attention mechanism is producing near-zero outputs or outputs that cancel out in the residual addition, leaving the input representation effectively unchanged.

**Why this is the paper's central finding.** Figure 3b shows the importance scores for Attention layers across the same four calibration datasets. The striking observation is that Attention importance scores are **consistently and substantially lower** than MLP importance scores at corresponding depths. Many attention layers, especially in the deeper half of the model, have `$S^l_A < 0.1$`, indicating that 90%+ of the angular alignment between input and output is preserved — the attention mechanism is barely changing the representations.

This cannot be attributed to dataset-specific artifacts: the pattern holds across C4, LIMA, CodeAlpaca, and MathInstruct. It cannot be attributed to model size or architecture: it holds for Llama-2-7B/13B/70B, Mistral-7B, Llama-3-8B/70B, and MAP-Neo-7B. It cannot be attributed to training stage: Figure 7 shows that attention layer redundancy persists from early checkpoints (500B trained tokens) through to the end of training (4500B+ tokens) in MAP-Neo-7B.

**Results of Attention Drop.** This is where the paper's headline numbers come from (Tables 1, 2, 3; Figure 5c):

- **Llama-2-13B:** Dropping 8 attention layers maintains average accuracy of 68.1% vs. 68.2% baseline (a 0.1-point drop), with speedup of 1.13× and `$\gamma = 0.01$`. Dropping 20 attention layers (half the model's 40 attention sublayers) still achieves 64.9% accuracy (a 3.3-point drop), with speedup of 1.40× and `$\gamma = 0.08$`.

- **Mistral-7B:** Dropping 8 attention layers maintains 69.8% vs. 70.3% baseline (a 0.5-point drop), with speedup of 1.23× and `$\gamma = 0.02$`. Dropping 12 attention layers retains 67.3% accuracy, with speedup of 1.40× and `$\gamma = 0.08$`.

- **Llama-2-70B:** This is the most dramatic case. Dropping 32 attention layers (out of 80) maintains 73.8% accuracy — identical to the baseline. Dropping 40 layers (half) maintains 71.5% accuracy (a 2.4-point drop), with speedup of 1.48× and `$\gamma = 0.05$`. Even dropping 48 attention layers (60% of them) retains 66.9% accuracy, with speedup of 1.62× and `$\gamma = 0.11$`.

- **Llama-3-70B:** Dropping 32 attention layers maintains 75.2% accuracy (baseline is 75.1% — performance actually slightly *improves*, likely due to noise). Dropping 40 layers retains 73.3% accuracy, with speedup of 1.43× and `$\gamma = 0.00$` (the speedup-degradation ratio rounds to zero because accuracy barely budges).

The `$\gamma$` values for Attention Drop are typically in the range 0.00–0.08, meaning **each 1% of speedup costs well under 0.1% of performance**. This is an order of magnitude better than the trade-off for MLP Drop (`$\gamma$` often >0.3) or Block Drop (`$\gamma$` often >0.2).

**Why Attention Drop outperforms other structured compression methods.** The paper includes two direct comparisons:

1. **Against Wanda (unstructured pruning, Sun et al., 2023):** Under the same parameter budget (Table 9), Attention Drop achieves equal or better accuracy than Wanda while providing actual speedups (1.05×–1.20×). Wanda, being unstructured, cannot provide speedups on standard hardware despite having theoretically fewer non-zero parameters. This demonstrates that the structured nature of Attention Drop translates its parameter reduction into genuine inference efficiency.

2. **Against Shortened LLaMA (depth pruning with retraining, Kim et al., 2024):** Joint Layer Drop (which includes Attention Drop as its primary mechanism) achieves 60.7% average accuracy with 1.45× speedup, compared to Shortened LLaMA-PPL at 60.3% accuracy with 1.23× speedup and Shortened LLaMA-Taylor at 60.6% accuracy with 1.22× speedup (Table 8). The training-free method outperforms methods that require post-compression retraining, both in accuracy and speedup.

**The role of grouped-query attention (GQA).** An important detail when interpreting speedup numbers: Llama-2-13B does NOT use grouped-query attention (it uses standard multi-head attention), while Mistral-7B, Llama-2-70B, Llama-3-8B, and Llama-3-70B all use GQA. Models with GQA have smaller per-token KV-cache entries because key and value heads are shared across query heads. This means that for Llama-2-13B, the KV-cache per attention layer is substantially larger (Table 4: 52GB for 40 layers at batch size 32, sequence length 2048), and dropping attention layers yields proportionally larger memory savings. For GQA models, the KV-cache savings per dropped layer are smaller but still significant.

**Difficulty-dependent behavior.** Figure 12 explores what happens when Attention Drop is applied to math-fine-tuned models. MetaMath-Mistral-7B (fine-tuned on mathematical reasoning data from Mistral-7B) retains strong GSM8K performance when dropping up to 8 attention layers. However, MetaMath-7B-V1.0 (fine-tuned from Llama-2-7B) experiences rapid degradation. The authors hypothesize that Llama-2-7B's base mathematical capability is poor, and the fine-tuned math ability is "superficial" — dependent on specific attention patterns that are fragile to pruning. In contrast, Mistral-7B's stronger base capabilities make its acquired math skills more robust to attention removal. This is a subtle finding hinting that redundancy patterns interact with the depth of a model's learned capabilities.

**Long-context behavior.** Table 12 evaluates Llama-2-7B-32K (a context-extended variant) on BANKING77, a long-context intent detection task. With up to 14K-token contexts, Attention Drop maintains substantially better performance than MLP Drop at equivalent pruning levels. Dropping 4 attention layers maintains 61.4% average accuracy across context lengths (vs. 65.6% baseline), while dropping 4 MLP layers yields only 54.6%. This indicates that the redundancy of attention layers is not specific to short-context processing — it persists in long-context regimes where attention's role in aggregating information across distant tokens would seem most critical.

**Dropping order visualization.** Figure 6c shows which attention layers are dropped at different pruning ratios. The pattern mirrors Block Drop: deeper attention layers (indices near the maximum) are dropped first, with only the last 1-2 layers preserved at high dropping ratios. On Llama-2-13B (40 layers), dropping 4 attention layers removes indices near 30-39; dropping 12 removes layers spanning roughly indices 20-39; dropping 20 removes layers from roughly index 10 upward. The pattern is remarkably consistent across models (compare Mistral-7B and Llama-2-13B in Figure 6c), reinforcing that this is a deep architectural property, not model-specific.

#### One-Shot Pruning Protocol and Model Loading

The paper explicitly designs its pruning procedure to be one-shot (compute scores once, remove all targeted layers simultaneously) rather than iterative (remove one layer, recompute scores, repeat).

**Rationale for one-shot.** The ablation in Figure 9 (Appendix B) compares iterative dropping (layers removed one by one, scores recomputed at each step) against one-shot dropping (all layers identified in a single pass). For Mistral-7B with 4 dropped attention layers, iterative achieves 66.5% average accuracy vs. 67.0% for one-shot. With 8 dropped layers, iterative achieves 62.1% vs. 66.9% for one-shot. The one-shot approach is not only computationally cheaper (one forward pass vs. `$k$` forward passes for `$k$` removed layers) but actually performs slightly better or equivalently. The authors attribute this to the fact that iterative removal can compound small estimation errors — removing one layer changes the residual stream for all subsequent layers, making the original importance scores stale, but recomputing them introduces new estimation noise on a now-modified model. One-shot removal avoids this compounding effect.

**The calibration process in detail.** The calibration procedure follows these precise steps:

1. **Load the full pre-trained model** in evaluation mode (no dropout, no gradient tracking).
2. **Feed 256 calibration samples** (each 2048 tokens from C4 validation) through the model one at a time (or in batches, though the paper's description suggests sample-by-sample processing for memory efficiency).
3. **For each target module** (Block, MLP unit, or Attention unit, depending on the analysis being performed), capture the input hidden state `$X$` (before the LayerNorm) and the output hidden state `$Y$` (after the residual addition). For a full model with `$L$` layers, this produces `$L$` block scores, `$L$` MLP scores, and `$L$` attention scores.
4. **Compute cosine similarity per sample** between `$X$` and `$Y$` along the hidden dimension, then compute `$S = 1 - \text{CosineSim}(X, Y)$` for that sample.
5. **Average the scores** across all 256 samples to get the final importance score for each module.
6. **Sort modules by average score** (ascending) and select the `$k$` lowest for removal.

**Implementation details for loading the pruned model.** The paper notes that loading the pruned model requires only "minor adjustments to the model configuration" when using HuggingFace Transformers. The specific adjustment involves modifying the model's `config.json` to reflect the new architecture:

- For Block Drop: the `num_hidden_layers` parameter is reduced from `$L$` to `$L - k$`, and the model definition skips the removed block indices.
- For Attention Drop: the model configuration is modified to indicate which Attention+LayerNorm units are omitted. The remaining layers maintain their original indexing for weight loading purposes, but the removed layers' weights are simply not loaded.
- For MLP Drop: analogous to Attention Drop, but targeting MLP+LayerNorm units.

The key advantage is that no custom kernels, sparse matrix formats, or specialized inference engines are needed. The pruned model is a valid, dense Transformer with fewer layers, executable by any framework that supports the base architecture. This is what makes the approach "hardware-friendly" — in contrast to unstructured pruning, where the theoretical parameter reduction doesn't translate to wall-clock speedup without specialized sparse computation support.

**Memory offloading during calibration.** The paper mentions that "since the similarity scores are computed locally, we can offload irrelevant modules to save memory." This means that when computing scores for a specific block or layer, other parts of the model can be moved off the GPU (e.g., to CPU memory). For very large models (70B), this enables the calibration process to run on hardware that couldn't hold the full model in GPU memory simultaneously. This is a practical engineering detail that makes the method applicable to the largest open-source models.

#### Layer Importance Patterns Across Depth

The paper's analysis of *where* redundant layers are located provides important architectural insights.

**Deep layers are consistently more redundant.** Across all three module types (Block, MLP, Attention) and all tested models (Llama-2-7B/13B/70B, Mistral-7B, Llama-3-8B/70B), the importance scores show a clear depth-dependent pattern: deeper layers (indices closer to `$L-1$`, excluding the very last 1-2 layers) have lower importance scores, indicating higher redundancy. The shallow layers (indices 0-5 or so) consistently show the highest importance. This is visible in Figure 2 (Blocks), Figure 3 (MLP and Attention), and Figure 11 (larger models).

**The very last layers are an exception.** The final 1-2 layers before the LM head consistently show elevated importance scores compared to their immediate predecessors. This is especially visible in Figure 3 for Llama-2-13B: layer index 39 shows a sharp uptick in importance relative to indices 30-38. This suggests that the layers closest to the output perform critical transformations that prepare the hidden states for the final prediction — compressing or reformatting representations into the vocabulary space. These "output-proximate" layers are almost never among the first dropped.

**Consistency across training stages (Figure 7).** By examining MAP-Neo-7B checkpoints at intervals of 500B trained tokens (from 500B to 4500B+), the paper shows that:

- **Attention layer importance scores remain low throughout training.** The heatmap in Figure 7a shows light-colored regions (low importance, high redundancy) dominating the deeper attention layers at every checkpoint. The attention redundancy is not a late-training phenomenon that emerges as the model converges — it is present from the earliest available checkpoint.

- **MLP importance scores increase over training.** Figure 7b shows that MLP importance scores gradually rise (darker colors) as training progresses, especially in the shallow-to-middle layers. This suggests MLP layers are learning increasingly complex transformations that become progressively more essential to the model's function.

- **Block importance scores follow the MLP pattern more than the Attention pattern.** Figure 7c shows a gradual darkening (increasing importance) during training, driven by the MLP contribution.

This temporal analysis is significant because it rules out a plausible alternative explanation: that attention layers only appear redundant *after* training because the model has converged to a solution that happens not to use them, but that they were important during the learning process itself. The evidence instead suggests that the optimization process never finds productive uses for many attention layers — they remain near-identity functions from the start.

**Implications for training efficiency.** If attention layers are redundant throughout training, the computational resources spent on forward and backward passes through those layers are wasted. The paper's observation suggests a potential architectural improvement: training a model with fewer attention layers from the outset, allocating that compute budget to additional MLP layers or to training more tokens with the remaining parameters. This is the "insight for future network architecture design" that the paper emphasizes.

#### Joint Layer Drop: Combining Redundancy Across Layer Types

The separate analyses of MLP Drop and Attention Drop reveal that while attention layers are far more redundant on average, some MLP layers (particularly deeper ones) also have low importance scores. Joint Layer Drop leverages this by pooling importance scores from both layer types and selecting the globally least-important modules, regardless of type.

**The joint importance pool.** For a model with `$L$` attention layers and `$L$` MLP layers, the joint importance score array is:

$$\mathbf{S} = [S^0_A, S^1_A, \ldots, S^{L-1}_A, S^0_M, S^1_M, \ldots, S^{L-1}_M]$$

The lowest `$k$` scores from this combined list of `$2L$` items determine which `$k$` modules are removed, irrespective of whether they are attention or MLP layers.

**What this enables.** At low dropping ratios, Joint Layer Drop behaves identically to Attention Drop because attention layers dominate the low-scoring tail of the distribution — their importance scores are so much lower than MLP scores that the first `$k$` lowest scores will all be from attention layers. This is visible in Figure 8: the Joint Drop curves overlap exactly with the Attention Drop curves for the first ~14 dropped modules in Mistral-7B and ~18 in Llama-2-13B.

However, as the dropping ratio increases past the point where the most redundant attention layers have been removed, the next-lowest importance scores start coming from MLP layers. At this stage, Joint Layer Drop begins removing MLP layers as well. The specific points where MLP layers start being dropped are marked with stars (⋆) in Figure 8, and the points where attention layers are dropped are marked with squares (■). The transition occurs where the joint approach's curve diverges from the pure Attention Drop curve.

**Why Joint Layer Drop outperforms pure Attention or MLP Drop at high sparsity.** After the most redundant attention layers are exhausted, continuing to drop attention layers (as pure Attention Drop would) would start removing relatively *more important* attention layers — those with moderate importance scores that the model depends on. At this point, dropping a low-importance MLP layer instead causes less performance degradation than dropping a medium-importance attention layer. Joint Layer Drop captures this adaptive logic automatically through the pooled ranking.

The quantitative benefit is visible in Figure 8:

- On Llama-2-13B, when dropping 31 total modules (the rightmost point), Joint Drop achieves approximately 49-50% MMLU accuracy, compared to roughly 47% for pure Attention Drop and roughly 30% for pure MLP Drop. Joint Drop retains about 90% of the original MMLU performance (55.1%) even after removing more than a third of all sublayers.

- On Mistral-7B, dropping 27 total modules sees Joint Drop achieve approximately 34% MMLU, compared to roughly 28% for Attention Drop and roughly 25% for MLP Drop.

**The speedup-degradation trade-off.** Joint Layer Drop achieves the best `$\gamma$` values at high dropping ratios because it extracts efficiency from both layer types before degrading the higher-importance attention layers. This makes it the preferred strategy when aggressive compression is needed and some performance degradation is acceptable.

**Why not always use Joint Layer Drop?** At low-to-moderate dropping ratios, Joint Layer Drop is equivalent to Attention Drop (because only attention layers are selected anyway). The additional complexity of Joint Layer Drop — computing scores for both layer types and managing the pooled ranking — provides no benefit until the dropping ratio exceeds the natural attention redundancy threshold (roughly 35-40% of attention layers in the tested models). For applications targeting modest speedups (1.2×–1.4×), pure Attention Drop is simpler and equally effective. For aggressive compression (1.5×+ speedups), Joint Layer Drop becomes the superior choice.

#### The Speedup Degradation Ratio (SDR) as an Evaluation Metric

The paper introduces a new metric, the Speedup Degradation Ratio `$\gamma$`, to quantify the efficiency-accuracy trade-off of different pruning strategies:

$$\gamma = \frac{\Delta \text{Avg.}}{\Delta \text{Speedup}}$$

where `$\Delta \text{Avg.}$` is the absolute percentage-point change in average accuracy across evaluated tasks (no negative sign — degradation is implicitly understood as a decrease), and `$\Delta \text{Speedup}$` is the percentage increase in inference speed relative to the baseline (e.g., a speedup of 1.13× corresponds to `$\Delta \text{Speedup} = 13$`).

**What this computes:** the average performance degradation incurred per 1% increase in speedup. A `$\gamma$` of 0.05 means that each 1% of speedup improvement costs 0.05 percentage points of accuracy on average. Lower `$\gamma$` is better — it indicates an efficient trade-off where speed comes cheaply in terms of performance.

**Why this metric?** Without a unified metric, comparing pruning methods across different speedup ratios is ambiguous. Method A might achieve 1.2× speedup with 1% accuracy loss (`$\gamma = 0.05$`), while Method B achieves 1.5× speedup with 5% accuracy loss (`$\gamma = 0.10$`). Which is better? The `$\gamma$` metric normalizes the trade-off into a single ratio, enabling direct comparison. However, it assumes a linear relationship between speedup and degradation, which holds approximately in the low-to-moderate pruning regime but may break down at extreme pruning ratios where performance collapses nonlinearly.

**Practical interpretation of `$\gamma$` values from the paper:**
- `$\gamma < 0.05$`: Excellent trade-off (e.g., Attention Drop on Llama-2-70B)
- `$\gamma \approx 0.1$`: Good trade-off (e.g., Attention Drop at aggressive ratios)
- `$\gamma \approx 0.2$–$0.3$`: Mediocre trade-off (e.g., Block Drop)
- `$\gamma > 0.5$`: Poor trade-off (e.g., MLP Drop at moderate ratios)
- `$\gamma > 1.0$`: The method costs more performance than it gains in speed (e.g., MLP Drop on Mistral-7B at 8 layers: `$\gamma = 2.82$`)

**Important caveat not discussed in the paper:** `$\gamma$` treats all percentage points of accuracy as equally valuable, which may not hold in practice. A drop from 90% to 89% on HellaSwag might matter less than a drop from 55% to 54% on MMLU if MMLU is the primary target metric. The averaging across tasks also assumes uniform importance weighting, which may not match deployment priorities.

#### Summary of Design Choices and Their Justifications

- **Cosine similarity over L2 distance or Relative Magnitude:** scale-invariant, bounded, and empirically superior in ablation (Table 7). Scale invariance matters because LayerNorm can rescale activations without changing semantic content; cosine similarity correctly ignores such rescaling while magnitude-based metrics would penalize it.

- **Residual-inclusive measurement** (measuring similarity between input to LayerNorm and output after residual addition) over internal-only measurement: captures the true functional contribution of the sublayer as a unit, validated by ablation showing that residual-exclusive measurement fails completely (Table 6).

- **LayerNorm included in the pruned unit:** when a sublayer is removed, its LayerNorm must also be removed to avoid mismatched normalization statistics. Treating the LayerNorm+sublayer as a single unit simplifies the pruning logic and prevents configuration errors.

- **One-shot over iterative pruning:** faster (one forward pass vs. `$k$` passes for `$k$` removed modules) and empirically equal or better in accuracy (Figure 9). Iterative recomputation introduces estimation noise on a progressively modified model without providing benefit.

- **256 calibration samples:** sufficient for stable importance estimates (Figure 10 shows convergence well before 256 samples), balancing statistical reliability against calibration cost.

- **C4 validation set as default calibration data:** following prior work (Sun et al., 2023), but the paper validates that importance patterns are consistent across diverse datasets (Figures 2, 3), establishing that calibration set choice is not a sensitive hyperparameter.

- **Attention Drop as the primary contribution rather than Joint Layer Drop:** because the paper's central insight is the *discovery* of asymmetric redundancy, not the *optimization* of pruning strategies. Joint Layer Drop is a natural extension that validates the insight — if attention layers weren't systematically more redundant, jointly dropping both types would not outperform pure Attention Drop at any sparsity level.

## 4. Key Insights and Innovations

### Innovation 1: Layer-Type Asymmetry as a Diagnostic — Not All Redundancy Is Created Equal

The paper's deepest conceptual move is not the discovery of redundancy in Transformers (which prior work had already established) but the demonstration that **redundancy is not uniformly distributed across architectural components**. This reframes the question from *"how much redundancy exists?"* to *"where does redundancy live, and why is it concentrated where it is?"*

**What the field assumed before this work.** Prior depth-pruning research (Gromov et al., 2024; Men et al., 2024; Kim et al., 2024) treated Transformer layers as atomic, interchangeable units. The implicit assumption was that if a layer is redundant, it's redundant as a whole — the Attention sublayer and MLP sublayer within a block are either both useful or both expendable. This assumption was never explicitly justified; it was inherited from the architectural symmetry of Transformers, where every block contains exactly one of each sublayer type. ShortGPT (Men et al., 2024) measured Block Influence — how much each layer's output deviates from its input — and used this to identify redundant layers, but it never decomposed the measurement into sublayer contributions. Shortened LLaMA (Kim et al., 2024) applied pruning to entire layers and then used retraining to recover performance, again without distinguishing sublayer types.

**What this paper reveals that changes the picture.** By decomposing the block-level importance score into separate Attention and MLP scores (Figure 3), the paper uncovers a sharp qualitative asymmetry: Attention layers are systematically far more redundant than MLP layers at corresponding depths. Many attention layers, particularly in the deeper half of models, have importance scores below 0.1 — meaning their outputs are 90%+ aligned with their inputs — while MLP importance scores at the same depths rarely fall below 0.1 and often exceed 0.2. This asymmetry is not subtle: it is large enough that block-level analyses missed it entirely because the relatively important MLP signal masked the redundant attention signal when the two were aggregated.

This is not merely an empirical observation; it is a **diagnostic insight** that reinterprets prior negative results. Block Drop performs poorly (Table 1, Figure 5a) not because entire blocks are essential but because each block contains a relatively important MLP layer that gets removed alongside a redundant attention layer. The failure mode of block-level pruning was misattributed — the problem was granularity, not depth reduction per se. Attention Drop succeeds (Figure 5c) precisely because it exploits the granular insight that MLP layers matter more than attention layers at corresponding depths.

**Why this is fundamental, not incremental.** The layer-type asymmetry finding shifts the burden of proof for future Transformer architecture design. The convention of 1:1 attention-to-MLP parity — one attention sublayer for every MLP sublayer — was never empirically justified; it was a design choice inherited from Vaswani (2017) and preserved through scaling. This paper provides the first systematic evidence that this parity is wasteful: at least in the tested open-weight models, far fewer attention layers would likely suffice. The finding implies that future architectures could be designed with asymmetric layer counts — perhaps two MLP layers for every attention layer in deeper regions, or attention layers only in the shallower portion of the network — without sacrificing capability. This is not a compression trick applied post-hoc to an existing model but a forward-looking architectural principle that could reduce pretraining costs from the outset.

The finding also carries explanatory power for why alternative architectures like Mamba (Gu & Dao, 2024) and RWKV (Peng et al., 2023), which dispense with attention entirely in favor of state-space models or linear recurrent formulations, can be competitive with Transformers at certain scales: if many attention layers in Transformers are near-identity functions anyway, removing them entirely (as Mamba does) may not lose as much signal as the architectural differences would suggest.

---

### Innovation 2: Redundancy Is Inherent and Training-Stable — Not a Convergence Artifact

The paper's second major conceptual contribution is the empirical demonstration that attention-layer redundancy is not something that emerges after training as the model converges to a solution that happens to under-utilize attention. It is **present from the earliest available training checkpoints and persists throughout the entire training process**, with minimal change.

**What the field assumed (or at least, what a plausible alternative hypothesis would predict).** A natural counter-explanation for post-training redundancy is that the model *learns* to make some layers redundant during training — early in optimization, all layers might contribute meaningfully, but as the loss landscape flattens and the model converges, some layers atrophy because the model finds a solution that routes information through a subset of pathways. In this narrative, redundancy is an *outcome* of optimization dynamics, not an *architectural property*. If true, this would mean that the observed redundancy could potentially be reduced by different training recipes (longer training, different learning rate schedules, architectural modifications that encourage distributed representation) and that pruning strategies that work on converged models might not generalize to models at different training stages or trained with different objectives.

**What the paper shows that rejects this hypothesis.** By examining MAP-Neo-7B checkpoints at 500B-token intervals throughout training (Figure 7), the paper establishes three facts that collectively rule out the "convergence artifact" narrative:

1. **Attention importance scores are low from the start.** At the earliest available checkpoint (500B tokens), the importance score heatmap for attention layers (Figure 7a) already shows light-colored (low-importance, high-redundancy) regions dominating the deeper layers. There is no evidence of an early-training phase where all attention layers show uniformly high importance that later decays.

2. **Attention importance scores remain stable throughout training.** The pattern at 500B tokens looks qualitatively similar to the pattern at 4500B+ tokens. While MLP importance scores *increase* over training (Figure 7b, showing progressive darkening), attention scores show minimal change. This differential trajectory — MLP layers becoming more important while attention layers stay flat — suggests that optimization is *actively using* MLP capacity while leaving attention capacity idle, not that both are equally utilized early and then pruning differentially.

3. **MLP importance grows while attention importance stagnates.** The divergence between MLP and attention trajectories during training (compare Figures 7a and 7b) is particularly informative. It means that as the model learns, it allocates representational work disproportionately to MLP layers. The optimization process *could* in principle distribute transformations across both sublayer types, but it doesn't — it concentrates them in MLPs. This is not a property of the data distribution (the same pattern holds across diverse calibration datasets, as shown in Figures 2 and 3) but a property of how gradient-based optimization interacts with the Transformer architecture.

**Why this matters beyond the specific experimental result.** The training-stability finding transforms the paper's message from "here is a useful post-training compression technique" to "here is a fundamental property of current Transformer architectures that should inform how we design them." If attention redundancy were a convergence artifact, the implication would be that with better training, models might learn to use all their attention layers productively — in which case the correct response would be to improve training, not to reduce attention layers. But if attention redundancy is inherent and training-stable, the implication is that **attention layers are over-provisioned by architectural design**, and future models should be built with fewer of them.

This finding also connects to broader questions about inductive biases in deep learning architectures. The fact that optimization consistently under-utilizes attention relative to MLP suggests that the Transformer's architectural structure — specifically, the residual connections that allow gradient flow to bypass entire sublayers — may create an optimization landscape where attention layers are "optional" in a way that MLP layers are not. The paper doesn't fully explain *why* this happens (it flags this as future work), but the empirical evidence that it *does* happen, consistently and from early in training, is itself a significant contribution because it identifies a previously undocumented architectural bottleneck.

---

### Innovation 3: Attention Drop as a Training-Free Compression Strategy That Exposes Overprovisioning

While Attention Drop is a method (described in Section 3), its status as an innovation lies not in the mechanism itself — which is a straightforward application of the similarity metric at finer granularity — but in **what the method's success reveals about the models it prunes**. The paper's headline result (48.4% speedup on Llama-2-70B with 2.4% performance loss, Table 3) is impressive as an efficiency achievement, but its deeper significance is as **diagnostic evidence for severe architectural overprovisioning**.

**How to interpret the result.** If removing half the attention layers from a 70B-parameter model causes negligible accuracy degradation (73.9% → 71.5% average, as in Table 3 for Attn-40), the strong implication is that those 40 removed layers were contributing almost nothing to the model's output quality. They were performing near-identity transformations, consuming compute and memory without meaningfully improving predictions. The fact that this holds across diverse evaluation tasks — BoolQ, HellaSwag, MMLU, WinoGrande, and others — indicates that the redundancy is not task-specific but pervasive.

**Prior work did not predict this magnitude of redundancy.** While Gromov et al. (2024) observed that deeper layers could be pruned with modest degradation, their analysis treated entire blocks and found significant performance drops at comparable pruning ratios (e.g., Block Drop in Table 1 reduces accuracy by 7.5 points at 8 blocks removed, vs. Attention Drop at 8 layers removed reducing accuracy by only 0.1 points). The key difference is not the pruning technique but the *target*: by isolating attention layers, the paper's method removes only the low-importance subcomponents while preserving the high-importance MLP sublayers, revealing the true extent of attention-specific overprovisioning that block-level analyses had underestimated.

**The comparison against Wanda (Table 9) sharpens the point.** Wanda (Sun et al., 2023) is an unstructured pruning method that removes individual weights across the entire network, achieving sparsity without structural bias toward any layer type. Under matched parameter budgets, Attention Drop achieves equal or better accuracy while providing actual speedups (Wanda, being unstructured, cannot). This means that structured, layer-type-aware pruning — despite being coarser than unstructured pruning — is *more effective* at preserving capability than fine-grained weight removal, precisely because it targets the right *kind* of computation (attention) rather than distributing the pruning budget uniformly. This is an inversion of the usual structured-vs-unstructured trade-off (structured pruning usually preserves less accuracy at matched sparsity because it's coarser) and is only possible because the attention-specific redundancy is so extreme.

**What this tells us about model scaling.** The paper tests Attention Drop across model sizes ranging from 7B to 70B (Tables 1, 2, 3) and finds a consistent, perhaps even strengthening, pattern: larger models appear at least as tolerant of attention removal as smaller ones. Llama-2-70B can drop 40 of 80 attention layers with negligible impact; Llama-3-70B can drop 40 layers with a `$\gamma$` of 0.00 (Table 2). This suggests that as models scale, the attention overprovisioning problem *grows*, not shrinks — the ratio of useful attention layers to total attention layers may actually decrease with model size. This has direct implications for the economics of large-scale training: if a 70B model's attention layers are half-redundant, then roughly 35B parameters' worth of attention weights were trained unnecessarily. At current pretraining costs, this represents a substantial fraction of total compute expenditure.

**The Speedup Degradation Ratio formalizes the insight.** The paper introduces `$\gamma$` (Equation 7) as a way to compare pruning strategies across different speedup ratios, but the metric's deeper role is to **quantify the concept of "useful computation per layer."** A `$\gamma$` near 0 (as achieved by Attention Drop on Llama-2-70B and Llama-3-70B) means that removing layers extracts nearly free speedup — those layers were doing essentially nothing. A `$\gamma$` above 0.3 (as with MLP Drop) means that each removed layer was contributing meaningfully and the speedup comes at real cost. The `$\gamma$` metric thus operationalizes the core diagnostic question: "how much of this model's computation is actually productive?"

### Innovation 4: Joint Layer Drop as a Principle of Cross-Type Redundancy Pooling

While Joint Layer Drop might appear to be a straightforward combination of Attention Drop and MLP Drop, its conceptual contribution is distinct: it demonstrates that **redundancy is a global property of the model, not a per-layer-type property**, and that optimal pruning should pool importance scores across architectural boundaries rather than treating layer types as separate pruning domains.

**The naive approach and why it's suboptimal.** A natural strategy given the paper's findings would be to set separate pruning budgets for attention and MLP layers — for example, drop 30% of attention layers and 10% of MLP layers based on their respective importance scores. This "separate budgets" approach assumes that the optimal pruning distribution follows the layer-type boundaries: attention layers should be pruned more aggressively because they're more redundant, but the pruning decisions within each type are independent.

Joint Layer Drop rejects this independence. By pooling all importance scores into a single ranked list and selecting the globally lowest-scoring modules regardless of type, it allows the optimization to adapt to the specific shape of redundancy in each model. If the 31st least-important module is an attention layer, it removes an attention layer; if it's an MLP layer, it removes an MLP layer. The transition point where attention removal ends and MLP removal begins (marked with ⋆ and ■ in Figure 8) is not predetermined — it emerges from the data.

**Why this is a principled insight, not just a trick.** The success of Joint Layer Drop (Figure 8) validates a more general claim: **importance scores from different module types are commensurable**. The cosine similarity metric, when applied to Attention and MLP sublayers with residual connections properly accounted for, produces scores that can be directly compared despite the modules performing fundamentally different computations. An attention layer with `$S = 0.08$` and an MLP layer with `$S = 0.08$` are approximately equally redundant — removing either will have similar impact on model output. This commensurability is non-obvious: one might expect that attention and MLP layers operate in different representational regimes where the same numeric score means different things, but the empirical evidence suggests otherwise.

**The practical implication for future architecture design.** Joint Layer Drop's behavior at high sparsity — where it begins removing MLP layers after exhausting the most redundant attention layers — reveals that there exists a **natural redundancy ordering** across architectural components. In the models tested, the ordering is: deepest attention layers < middle attention layers < deepest MLP layers < shallow attention layers < shallow MLP layers. This ordering is not something the method imposes; it's something the method *discovers* from the pooled importance scores. The existence of such an ordering suggests that future architecture design could explicitly allocate capacity along this spectrum — placing more MLP capacity where it matters most (shallow-to-middle layers) and less attention capacity overall, rather than maintaining the rigid 1:1 parity that forces equal allocation regardless of the natural redundancy gradient.

**Connection to model compression theory.** Joint Layer Drop can be seen as an application of a broader principle: **when redundancy is heterogeneous across component types, optimal compression is type-agnostic**. This principle applies beyond Transformers — any modular architecture with functionally distinct components (CNNs with convolution and normalization layers, mixture-of-experts models with experts and routers, multimodal models with modality-specific encoders) could potentially benefit from pooled importance scoring that ignores architectural boundaries. The paper provides a clear template for how to test such hypotheses: measure component-wise importance with a unified metric, pool the scores, and compare type-agnostic pruning against type-separate baselines at matched budgets.

The comparison with Shortened LLaMA (Table 8) validates this principle concretely: Joint Layer Drop (training-free, type-agnostic) outperforms Shortened LLaMA (retraining-based, type-blind because it prunes entire blocks) in both accuracy (60.7% vs. 60.3-60.6%) and speedup (1.45× vs. 1.22-1.23×). The fact that a training-free method with type awareness beats a retraining-based method without it suggests that **knowing which component types are redundant is more valuable than retraining to recover from blunt pruning**.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The paper uses two categories of data. For **calibration** (computing importance scores), it uses the validation set of C4 (Raffel et al., 2019), with 256 samples truncated to 2048 tokens each, following the setup of Sun et al. (2023). For **evaluation**, it reports results on eight standard benchmarks: BoolQ (Clark et al., 2019), OpenBookQA (OBQA; Mihaylov et al., 2018), PIQA (Bisk et al., 2019), RTE (Wang et al., 2019), ARC-Challenge (ARC-C; Clark et al., 2018), HellaSwag (Zellers et al., 2019), MMLU (Hendrycks et al., 2021), and WinoGrande (2019). GSM8K (Cobbe et al., 2021) is used for a focused math-reasoning evaluation in Appendix C. Evaluation is conducted using the EleutherAI LM Evaluation Harness (Gao et al., 2023). Table 5 specifies the number of few-shot examples and normalization settings per task.

- **Base model(s).** The paper experiments primarily with the Llama-2 family (Touvron et al., 2023) at 7B, 13B, and 70B scales, Mistral-7B (Jiang et al., 2023), and Llama-3 (AI@Meta, 2024) at 8B and 70B scales. These are chosen for their "competitive performance and wide usage," providing coverage across model families (Llama, Mistral), scales (7B to 70B), and generations (Llama-2 vs. Llama-3). Additionally, MAP-Neo-7B (Zhang et al., 2024) is used for the training-stage analysis because it released continuous intermediate checkpoints. For the long-context evaluation, `togethercomputer/LLaMA-2-7B-32K` is used, which extends Llama-2-7B's context window to 32K tokens via position interpolation.

- **Metrics.** The primary evaluation metric is **average accuracy** across the eight benchmark tasks listed above, reported as a simple unweighted mean of per-task accuracies. The paper introduces a derived metric, the **Speedup Degradation Ratio (SDR)** — denoted `$\gamma$` — defined as `$\gamma = \Delta\text{Avg.} / \Delta\text{Speedup}$`, where `$\Delta\text{Avg.}$` is the absolute percentage-point change in average accuracy relative to the unpruned baseline, and `$\Delta\text{Speedup}$` is the percentage increase in inference speed (e.g., a 1.13× speedup corresponds to `$\Delta\text{Speedup} = 13$`). Lower `$\gamma$` indicates a more favorable trade-off (more speedup per unit of accuracy lost).

- **Baselines.** The paper compares against several internal and external baselines:
  - **Block Drop**: the paper's own implementation of removing entire Transformer blocks using the same similarity metric applied to block-level input/output pairs. This serves as the coarse-grained strawman that motivates finer-grained approaches.
  - **Random dropping**: attention layers removed at random (Appendix B, Table 7). Establishes a lower bound on pruning efficacy by showing that some structured selection is necessary.
  - **Reverse Order dropping**: removing layers from deepest to shallowest, following the pattern identified by Men et al. (2024). Tests whether the simple depth-based heuristic suffices.
  - **Relative Magnitude (ShortGPT)**: the Block Influence metric from Men et al. (2024), measuring the L2 norm of the difference between input and output relative to input norm (Appendix B, Table 7).
  - **Wanda** (Sun et al., 2023): unstructured weight pruning. Compared under matched parameter budgets in Appendix B (Table 9) to assess whether structured Attention Drop outperforms fine-grained sparsity at equivalent compression ratios.
  - **Shortened LLaMA** (Kim et al., 2024): depth pruning with post-compression retraining (both PPL-based and Taylor-based variants). Compared in Appendix B (Table 8) under matched parameter budgets.
  - **MLP Drop**: the paper's own implementation of removing only MLP+LayerNorm units, serving as the contrast case to highlight attention-specific redundancy.
  - The full, unpruned model serves as the primary reference point for all accuracy and speedup comparisons.

- **Generation budget / compute accounting.** This paper is about structural pruning of pre-trained models, not about test-time generation. There is no "generation budget" in the sense of sampling multiple outputs. Instead, the relevant compute budget is measured in two ways: (1) **inference speedup**, measured end-to-end on a single NVIDIA RTX A6000 Ada GPU, covering both the prefill (processing the input prompt) and generation (token-by-token decoding) stages with 2048 input tokens and 2048 generated tokens, using batch sizes that maximize GPU utilization (Section 5); (2) **KV-cache memory reduction**, reported as the absolute memory footprint of the key-value cache at 16-bit precision for a given batch size and sequence length, both before and after pruning (Table 4). For the 70B models, 4-bit quantization (AWQ; Lin et al., 2024) is employed to fit the model on a single GPU for speed measurement, with the paper noting that Attention Drop is orthogonal to quantization (validated in Appendix C, Table 11). The calibration cost — 256 forward passes through the full model — is not included in the reported speedups, which is a limitation when considering the total computational budget for the method.

- **Cross-validation / statistical protocol.** There is no cross-validation or statistical significance testing reported in this paper. The evaluation uses standard benchmark test sets with fixed few-shot settings (Table 5). For the random dropping baseline in Table 7, performance is averaged over five different random seeds to account for variance. For all other methods, importance scores are computed once on the 256-sample C4 calibration set and pruning is applied deterministically based on the resulting ranking. The paper does not report confidence intervals, error bars, or significance tests for any of its main results.

### Main Quantitative Results

#### Block Drop vs. Layer Drop: Granularity Matters Decisively

The paper's first set of experiments (Table 1, Figure 5) establishes the core comparative finding: pruning at block granularity causes severe performance degradation, pruning MLP layers alone causes moderate-to-severe degradation, and pruning Attention layers alone causes minimal degradation even at aggressive ratios.

**Block Drop (Table 1, Figure 5a).** Removing entire blocks produces rapid accuracy collapse. On Llama-2-13B, dropping 4 blocks reduces average accuracy from 68.2% to 65.8% (a 2.4-point absolute decline) with a speedup of only 1.11×, yielding `$\gamma = 0.22$`. Dropping 8 blocks drops accuracy to 60.7% (7.5 points lost) with 1.24× speedup and `$\gamma = 0.31$`. On Mistral-7B, dropping 8 blocks causes a catastrophic decline from 70.3% to 58.6% (11.7 points lost), with 1.32× speedup and `$\gamma = 0.37$`. Figure 5a shows that the accuracy curves across individual tasks (HellaSwag, MMLU, OBQA, WinoGrande) decline monotonically and often steeply as more blocks are removed, with some tasks (MMLU, HellaSwag on Mistral-7B) dropping below 30% accuracy at high pruning ratios.

**MLP Drop (Table 1, Figure 5b).** Pruning only MLP+LayerNorm units is somewhat less destructive than Block Drop but still problematic. On Llama-2-13B, dropping 4 MLP layers reduces accuracy from 68.2% to 66.9% (`$\gamma = 0.32$`); dropping 8 reduces it to 61.9% (`$\gamma = 0.79$`). On Mistral-7B, MLP Drop is particularly damaging: dropping 4 layers drops accuracy from 70.3% to 66.9% (`$\gamma = 1.13$`, meaning each 1% of speedup costs more than 1 percentage point of accuracy), and dropping 8 layers causes a near-total collapse to 53.4% (`$\gamma = 2.82$`). Figure 5b confirms this pattern visually: HellaSwag and MMLU curves decline sharply as MLP layers are removed.

**Attention Drop (Table 1, Figure 5c).** This is where the paper's central empirical result lives. On Llama-2-13B, dropping 8 attention layers maintains average accuracy of 68.1% (baseline: 68.2%) — essentially unchanged — with 1.13× speedup and `$\gamma = 0.01$`. Even dropping 20 attention layers (half of the model's 40 attention sublayers) preserves 64.9% accuracy with 1.40× speedup and `$\gamma = 0.08$`. On Mistral-7B, dropping 8 attention layers yields 69.8% vs. 70.3% baseline (1.23× speedup, `$\gamma = 0.02$`); dropping 12 preserves 67.3% (1.40× speedup, `$\gamma = 0.08$`). Figure 5c shows that accuracy curves for individual tasks remain remarkably flat until dropping ratios exceed roughly 30-40% of total attention layers, at which point gentle degradation begins.

The key structural observation is that `$\gamma$` for Attention Drop (0.01–0.08) is an order of magnitude lower than for MLP Drop (0.32–2.82) or Block Drop (0.22–0.44) at comparable pruning ratios. This difference is what the paper interprets as evidence for asymmetric redundancy.

#### Scaling Behavior: Larger Models Tolerate More Aggressive Attention Removal

Tables 2 and 3 extend the analysis to larger models (Llama-3-8B, Llama-2-70B, Llama-3-70B) and reveal a striking pattern: **the tolerance for attention removal increases with model scale.**

**Llama-2-70B (Table 3).** Dropping 32 of 80 attention layers maintains 73.8% average accuracy — exactly equal to the 73.9% baseline within rounding — with 1.35× speedup and `$\gamma = 0.00$`. Dropping 40 layers (half) yields 71.5% accuracy (only 2.4 points below baseline) with 1.48× speedup and `$\gamma = 0.05$`. Even at 48 dropped layers (60% of attention sublayers), the model retains 66.9% accuracy with 1.62× speedup and `$\gamma = 0.11$`. Table 3 also shows that Block Drop and MLP Drop on this model remain destructive: dropping 16 blocks reduces accuracy from 73.9% to 54.4% (19.5 points lost, `$\gamma = 0.65$`), and dropping 16 MLP layers drops accuracy to 65.9% (`$\gamma = 1.00$`).

**Llama-3-70B (Table 2).** The pattern is even more extreme. Dropping 32 attention layers (out of 80) maintains 75.2% accuracy — slightly above the 75.1% baseline (attributable to noise) — with 1.35× speedup and `$\gamma = 0.00$`. Dropping 40 layers yields 73.3% with 1.43× speedup and `$\gamma = 0.00$`. Only at 48 dropped layers does a meaningful decline appear: 71.0% accuracy with 1.55× speedup and `$\gamma = 0.07$`.

**Llama-3-8B (Table 2).** This smaller Llama-3 model shows somewhat less tolerance than the 70B version but still substantially more than the Llama-2 and Mistral models. Dropping 8 attention layers maintains 67.4% accuracy (baseline: 67.6%) with 1.16× speedup and `$\gamma = 0.01$`. However, dropping 16 layers causes a sharper decline to 55.4% (`$\gamma = 0.32$`), and dropping 20 layers collapses to 38.6% (`$\gamma = 0.56$`). This suggests that while Llama-3-8B's attention layers are still substantially redundant, the redundancy is not as extreme as in the 70B model — perhaps because the smaller model has less total capacity and thus each layer contributes proportionally more.

The cross-scale comparison across these models reveals a consistent trend: larger models (70B) can drop proportionally more attention layers (40–50%) with near-zero `$\gamma$`, while smaller models (7B–13B) show gentle but real degradation at 20–30% removal. This is not a rigorously tested scaling law claim but an empirical observation across the specific models tested.

#### Efficiency Gains: KV-Cache Memory and Wall-Clock Speedup

The paper validates that Attention Drop translates into genuine deployment efficiency gains through two concrete measurements.

**KV-cache memory reduction (Table 4).** For a sequence length of 2048 tokens at 16-bit precision, the KV-cache memory footprint is measured before and after pruning. The results are dramatic for models without grouped-query attention (GQA). Llama-2-13B (which uses standard multi-head attention, not GQA) sees its KV-cache drop from 52GB to 26GB when halving attention layers (from 40 to 20) at a batch size of 32 — a 50% reduction. For GQA-equipped models (Mistral-7B, Llama-2-70B, Llama-3-8B, Llama-3-70B), the per-layer KV-cache is smaller because key and value heads are shared, but the proportional reduction still holds: Mistral-7B drops from 16GB to 10GB when reducing from 32 to 20 attention layers at batch size 64. Llama-2-70B drops from 20GB to 10GB when reducing from 80 to 40 layers at batch size 32. The paper notes that these measurements are in resource-constrained scenarios; in resource-sufficient cases with larger batch sizes and longer sequences, the absolute memory savings would be even more significant.

**Inference speedup (Tables 1, 2, 3).** Speedup is measured on a single NVIDIA RTX A6000 Ada GPU with batch sizes chosen to maximize utilization for each model. The procedure covers the full generation pipeline: 2048 input tokens processed (prefill) followed by 2048 tokens autoregressively generated. For Llama-2-70B (Table 3), dropping 40 attention layers yields a 1.48× speedup with only 2.4 percentage points of performance degradation (`$\gamma = 0.05$`). For Llama-2-13B (Table 1), dropping 20 attention layers yields 1.40× speedup with 3.3 points lost (`$\gamma = 0.08$`). For Llama-3-70B (Table 2), dropping 40 layers yields 1.43× speedup with essentially no degradation (`$\gamma = 0.00$`). These speedup numbers are the basis for the paper's claim of "up to 48.4% speedup" (which corresponds to the 1.48× figure for Llama-2-70B Attn-40 or the 1.52× figure for Llama-3-8B Attn-20).

#### Joint Layer Drop: Exploiting Complementary Redundancy at High Sparsity

Figure 8 presents the accuracy curves for Joint Layer Drop compared against pure Attention Drop, pure MLP Drop, and Block Drop on Llama-2-13B (panel a) and Mistral-7B (panel b), across four tasks (HellaSwag, MMLU, OBQA, WinoGrande).

**Behavior at low-to-moderate dropping ratios.** For both models, the Joint Drop curve (solid line) overlaps exactly with the Attention Drop curve for roughly the first 14–18 dropped modules on Llama-2-13B and ~14 on Mistral-7B. This overlap occurs because all of the lowest importance scores in the pooled ranking belong to attention layers — no MLP layers are selected until the most redundant attention layers are exhausted. This is direct evidence that the attention redundancy is systematically deeper than the MLP redundancy.

**Transition to MLP removal.** The Joint Drop curves diverge upward from the Attention Drop curves at the point where MLP layers begin entering the pool of lowest-scoring modules (marked with ⋆ for MLP drops and ■ for attention drops in Figure 8). At this transition, Joint Drop begins removing low-importance MLP layers rather than continuing to remove medium-importance attention layers, resulting in better performance than pure Attention Drop at the same total dropped count.

**Quantitative advantage at high sparsity.** On Llama-2-13B at 31 total dropped modules, Joint Drop achieves approximately 49–50% on MMLU (Figure 8a, second subplot from left), compared to roughly 47% for pure Attention Drop and roughly 30% for MLP Drop. For OBQA, Joint Drop achieves approximately 41% vs. roughly 38% for Attention Drop and 32% for MLP Drop. On Mistral-7B at 27 total dropped modules, Joint Drop achieves approximately 34% on MMLU vs. roughly 28% for Attention Drop and 24% for MLP Drop. The gap between Joint Drop and the single-type alternatives widens monotonically with the number of dropped modules past the transition point.

**Comparison with Shortened LLaMA (Table 8).** Under matched parameter budgets, Joint Layer Drop applied to Vicuna-13B-v1.3 achieves 60.7% average accuracy (across HellaSwag, MMLU, OBQA, WinoGrande) with 1.45× speedup, compared to Shortened LLaMA-PPL at 60.3% with 1.23× speedup and Shortened LLaMA-Taylor at 60.6% with 1.22× speedup. The Joint Layer Drop approach is training-free, while Shortened LLaMA involves post-compression retraining. This result demonstrates that type-aware dropout can outperform retraining-based depth pruning when the pruning target is chosen correctly.

#### Attention Drop Across Specialized Settings

The paper extends the evaluation to two specialized regimes: math-fine-tuned models and long-context processing.

**Math reasoning (Figure 12, Table 10).** Using GSM8K, the paper evaluates Attention Drop on Mistral-7B and Llama-2-7B both in their base configurations and after instruction fine-tuning for math (MetaMath-Mistral-7B and MetaMath-7B-V1.0; Yu et al., 2023). The key finding is a divergence in robustness: MetaMath-Mistral-7B shows minimal GSM8K degradation when dropping up to 8 attention layers (accuracy dropping roughly from ~68% to ~65%), while MetaMath-7B-V1.0 suffers rapid collapse (dropping from ~39% to below 10% after only 6 dropped layers). The authors hypothesize that this is because Llama-2-7B's base mathematical capability is poor, and the fine-tuned math ability is "superficial" — dependent on fragile attention patterns that are disrupted by pruning. In contrast, Mistral-7B's stronger base math capability (visible in its higher unpruned accuracy) makes its acquired skills robust to attention removal. Table 10 provides a qualitative example showing that MetaMath-Mistral-7B still produces correct answers (with proper reasoning) after dropping 8 attention layers, begins showing format issues at 10 dropped layers (correct answer but missing the "####" delimiter), and produces a wrong answer at 12 dropped layers.

**Long-context processing (Table 12).** Evaluating Llama-2-7B-32K (context-extended to 32K tokens) on BANKING77, a long-context intent detection task, the paper tests context lengths from 2K to 14K tokens. Attention Drop maintains substantially better performance than MLP Drop at equivalent pruning levels. Dropping 4 attention layers yields 61.4% average accuracy across context lengths vs. 65.6% baseline (a 4.2-point decline), while dropping 4 MLP layers yields only 54.6% (an 11-point decline). Dropping 8 attention layers still achieves 48.0% vs. 39.0% for 8 MLP layers dropped. The degradation from attention removal becomes more pronounced as context length grows — at 14K tokens, the gap between Attention Drop (64%) and baseline (81%) is larger than at 2K tokens (15% vs. 26%) — but remains substantially better than MLP Drop at all tested lengths.

#### Training-Stage Analysis: Redundancy Is Inherent

Figure 7 presents importance score heatmaps for MAP-Neo-7B across training checkpoints spaced at 500B-token intervals (from 500B to 4500B+). Three patterns are visible:

1. **Attention importance scores (Figure 7a) are consistently low throughout training.** The heatmap is dominated by light-colored (low-importance) regions in deeper layers at every checkpoint, with only shallow layers (indices 0–5) showing darker (higher importance) colors. There is no visible trend toward increasing attention importance as training progresses — the pattern at 500B tokens looks qualitatively similar to the pattern at 4500B+ tokens.

2. **MLP importance scores (Figure 7b) increase progressively during training.** The heatmap shows a gradual darkening (increasing importance scores) from left (early checkpoints) to right (late checkpoints), especially in shallow-to-middle layers. This suggests that optimization is actively allocating representational capacity to MLP layers as training proceeds.

3. **Block importance scores (Figure 7c) follow the MLP pattern more than the attention pattern**, with progressive darkening over training. This is expected because block-level scores aggregate both sublayer types, and the increasing MLP signal dominates the flat attention signal.

The paper interprets this temporal stability of attention redundancy as evidence that it is "an inherent property" of Transformer architectures, not a convergence artifact. If attention layers were important early in training and only became redundant as the model converged, the heatmaps would show dark (high-importance) regions early that progressively lighten — but they don't. Instead, attention layers are light (redundant) from the start and stay that way.

### Ablation Studies and Robustness Checks

- **One-shot vs. iterative dropping (Figure 9, Appendix B):** On Mistral-7B, one-shot dropping achieves 67.0% average accuracy vs. 66.5% for iterative at 4 dropped attention layers, and 66.9% vs. 62.1% at 8 dropped layers. The one-shot approach is not only computationally cheaper but empirically performs at least as well, likely because iterative recomputation compounds estimation errors on a progressively modified model.

- **Residual connection involvement (Table 6, Appendix B):** When importance scores are computed without accounting for the residual connection — measuring similarity between the internal input and output of the Attention or MLP module only, rather than between the overall sublayer input and post-residual output — performance collapses. For Mistral-7B Attention Drop at 8 removed layers, the "w/o residual" variant achieves only 37.7% average accuracy, compared to 65.3% with residual-inclusive measurement. For 20 dropped attention layers, the gap is 32.0% vs. 62.9%. This validates that the residual pathway is essential for correctly assessing whether a sublayer is functioning as an identity transformation.

- **Choice of importance metric (Table 7, Appendix B):** On Mistral-7B with Attention Drop at 12 removed layers, cosine similarity achieves 64.8% average accuracy, compared to 62.3% for Relative Magnitude (ShortGPT), 61.5% for Reverse Order, and 39.4% for Random dropping. At 8 removed layers, cosine similarity achieves 66.9%, vs. 66.8% for Relative Magnitude and 66.9% for Reverse Order (the latter two are competitive at moderate sparsity but fall behind as sparsity increases).

- **Calibration sample count (Figure 10, Appendix B):** Importance score patterns for Block, MLP, and Attention modules stabilize rapidly. The curves for 4, 16, 64, 256, and 1024 calibration samples are visually nearly identical in all three panels. This justifies the paper's choice of 256 samples — it sits comfortably past the convergence point — and confirms that the importance ranking is not sample-dependent.

- **Calibration dataset choice (Figures 2, 3):** Importance score curves for Blocks, MLP layers, and Attention layers are plotted across four diverse calibration datasets: C4, LIMA, CodeAlpaca, and MathInstruct. The overall shape of the curves — deeper layers showing lower importance, shallow layers showing higher importance — is consistent across all datasets for all module types. This suggests the redundancy patterns are properties of the model architecture, not artifacts of calibrating on a particular text distribution.

- **Integration with quantization (Table 11, Appendix C):** When Attention Drop is combined with 4-bit AWQ quantization (Lin et al., 2024) on Llama-2-13B and Mistral-7B, the quantized pruned models maintain performance within less than 1% of the unquantized pruned models. For Llama-2-13B Attn-8, the unquantized version achieves 66.2% average accuracy vs. 65.9% with quantization. For Mistral-7B Attn-8, the figures are 66.4% vs. 65.9%. This validates the paper's claim that Attention Drop is orthogonal to quantization and that the two techniques can be combined for multiplicative efficiency gains.

- **Dropping order visualization (Figures 6, 11):** The heatmap-style visualizations confirm that deeper layers are consistently dropped first across all module types and all tested models. For Llama-2-13B Attention Drop (Figure 6c), the first 4 dropped layers are all in the index range ~30–39; the first 12 span roughly indices 20–39; the first 20 span indices ~10–39. The last 1–2 layers (closest to the output) are preserved even at high dropping ratios. Larger models (Llama-2-70B, Llama-3-70B, Figure 11) show qualitatively similar patterns, though with some variation in exact ordering across model generations (the authors attribute differences between Llama-2-70B and Llama-3-70B block dropping order to "different training techniques, e.g., different numbers of training tokens").

### Critical Assessment

This section examines whether the experimental evidence genuinely supports the paper's major claims, identifies weaknesses in experimental design, and highlights experiments that would strengthen the findings.

The paper's central claim is that **Attention layers in Transformer LLMs exhibit substantially greater redundancy than MLP layers, and this redundancy is an inherent architectural property that can be exploited for training-free structural pruning with minimal performance loss.** The evidence for this claim is multi-faceted: (1) the systematic comparison of Block Drop, MLP Drop, and Attention Drop across multiple models and tasks (Tables 1–3, Figure 5); (2) the per-module importance score distributions (Figure 3); (3) the training-stage analysis showing persistent attention redundancy (Figure 7); (4) the Joint Layer Drop results confirming that attention layers dominate the low-importance tail (Figure 8).

**What the experiments demonstrate.** The experiments convincingly show that, for the tested open-weight models (Llama-2-7B/13B/70B, Mistral-7B, Llama-3-8B/70B), removing attention layers using the similarity-based metric preserves dramatically more accuracy than removing MLP layers or entire blocks at matched pruning ratios. The `$\gamma$` metric quantifies this: Attention Drop achieves `$\gamma$` values of 0.00–0.08 across models, compared to 0.22–0.44 for Block Drop and 0.18–2.82 for MLP Drop. The cross-model consistency is strong — the pattern holds across three model families, two training paradigms (Llama-2 vs. Llama-3), and scales from 7B to 70B. The training-stage analysis on MAP-Neo-7B provides evidence that attention redundancy is not a late-training convergence artifact, though it is based on a single model.

**What the experiments do not demonstrate.** Several important gaps remain between what the experiments show and what the paper's framing implies:

**1. The "inherent architectural property" claim rests on one model's training trajectory.** The training-stage analysis (Figure 7) uses only MAP-Neo-7B — a single model from a single training run. While the result is suggestive, it falls short of establishing that attention redundancy is "an inherent property of Transformer architectures" (the paper's phrasing in Section 1). To support this claim, one would need: (a) training trajectories from multiple model families showing the same pattern; (b) evidence that the pattern persists under different training hyperparameters (learning rate schedules, data mixtures, model sizes); and (c) ideally, evidence that architectural variants (different attention-to-MLP ratios, different residual connection structures, different normalization placements) produce different redundancy patterns, establishing that the observed pattern is specific to the standard Transformer architecture rather than an inevitable consequence of deep residual networks. The paper provides none of these.

**2. The causal mechanism underlying attention redundancy is not established.** The paper documents *that* attention layers are redundant but does not investigate *why*. Several plausible mechanisms could explain the observed pattern: (a) attention layers might be fundamentally harder to optimize due to the softmax normalization or the quadratic interaction structure, causing gradient-based optimization to under-utilize them; (b) the residual connections might allow information to route around attention layers, making them "optional" in a way that MLP layers (which perform position-wise transformations that the residual cannot replicate) are not; (c) the specific pretraining objectives (next-token prediction on web text) might not require the full attention capacity, and different training objectives (e.g., retrieval-augmented generation, multi-turn dialogue, structured reasoning) might produce different redundancy patterns. The paper acknowledges this gap only implicitly, by suggesting future work on "why attention layers are so redundant" in Section 8. Without this mechanistic understanding, it is unclear whether the finding generalizes to models trained differently.

**3. The evaluation benchmarks skew toward knowledge and surface-level reasoning.** The eight evaluation tasks (BoolQ, OBQA, PIQA, RTE, ARC-C, HellaSwag, MMLU, WinoGrande) are mostly multiple-choice knowledge and commonsense reasoning benchmarks. They do not test open-ended generation quality, multi-step reasoning coherence, factual accuracy in long-form text, instruction-following in complex scenarios, or code generation. The paper adds GSM8K (math reasoning) in Appendix C (Figure 12) and BANKING77 (long-context classification) in Appendix C (Table 12), which partially address this gap. However, the GSM8K results (Figure 12) actually reveal an important limitation: MetaMath-7B-V1.0, a math-fine-tuned Llama-2-7B, collapses rapidly under Attention Drop, losing most of its math accuracy after only 6 dropped layers. The authors attribute this to "superficial" math ability in the base model, but this explanation is post-hoc — it wasn't tested systematically. A more rigorous approach would evaluate Attention Drop across a diverse set of reasoning-intensive tasks (multi-step logical deduction, code generation, mathematical theorem proving, long-form summarization) on models with varying base capabilities to determine whether attention redundancy is genuinely a property of the architecture or an artifact of evaluating on tasks that don't stress attention's core function (contextual information aggregation across tokens).

**4. The paper does not compare against a simple parameter-count-matched shallower baseline.** The speedup and memory savings from Attention Drop are compared against the full model, but not against a model that was originally designed to have fewer attention layers. Concretely: if Llama-2-13B with 20 attention layers dropped achieves 1.40× speedup and 64.9% average accuracy, how does this compare to a hypothetical model with the same total parameter count but with 20 attention layers and proportionally more MLP capacity from the start? The paper cannot answer this because such models were not trained. However, this comparison is the relevant baseline for the paper's prescriptive claim that "future network architecture design" should reduce attention layer counts. The current results show that removing attention layers from a pre-trained model is less damaging than removing MLP layers, but they do not demonstrate that training with fewer attention layers from scratch would yield better performance than the default 1:1 parity design. It is possible that attention layers, even if redundant in the final converged model, serve an important role during training (e.g., enabling gradient flow, providing inductive bias for learning long-range dependencies) that would be missed if they were absent from the start. The training-stage analysis partially addresses this by showing that attention redundancy is present early in training, but it does not test the counterfactual.

**5. The difficulty estimation and task-specific sensitivity are not explored.** The paper reports only aggregate accuracy numbers across benchmarks. It does not analyze whether attention redundancy varies by task difficulty — for example, whether harder MMLU subsets (e.g., college mathematics, physics) show different degradation patterns than easier subsets, or whether questions requiring cross-sentence inference degrade more than questions answerable from a single sentence. This is relevant because attention's role in aggregating information across tokens might be more critical for certain types of reasoning than others. The long-context experiment (Table 12) provides a partial view, showing that Attention Drop degrades more at longer contexts (14K tokens: 64% vs. 81% baseline, a 17-point gap) than at shorter contexts (2K tokens: 15% vs. 26% baseline, an 11-point gap). This hints that attention's role becomes more important as the information to be aggregated becomes more distributed, but the analysis is limited to a single classification task.

**6. The single-GPU speedup measurements may not reflect distributed serving scenarios.** Speedup is measured on a single NVIDIA RTX A6000 Ada GPU with batch sizes chosen to maximize utilization. In production serving environments, models are often sharded across multiple GPUs using tensor parallelism or pipeline parallelism. The relationship between layer count and inference speed in these settings may differ from the single-GPU case — for example, pipeline-parallel deployments might see different speedup characteristics if attention layers are on a critical path. The paper does not discuss this, and its speedup claims should be understood as applying to single-GPU inference.

**7. The calibration dataset sensitivity is tested only for dataset type, not for domain shift.** The paper shows that importance score patterns are consistent across C4, LIMA, CodeAlpaca, and MathInstruct (Figures 2, 3). This validates robustness to calibration dataset type. However, all four datasets are English-language text. The paper does not test whether calibration on English text produces appropriate pruning decisions for non-English evaluation, or whether domain-specific calibration (e.g., using medical text when deploying the pruned model for medical applications) would yield different and potentially better pruning choices. This is an important practical consideration that the paper does not address.

**8. The paper does not explore the interaction between Attention Drop and fine-tuning.** All experiments use pre-trained (or instruction-fine-tuned) models without further training after pruning. The paper does not investigate whether fine-tuning the pruned model on downstream tasks could recover some of the degraded performance, which is a standard practice in the pruning literature (as in Shortened LLaMA, which the paper compares against). While the paper's training-free approach is appealing for its simplicity, the comparison against retraining-based methods (Table 8) would be more informative if it included a variant where Joint Layer Drop was followed by light fine-tuning — this would separate the benefit of type-aware pruning from the benefit (or cost) of post-pruning adaptation.

**Summary of evidential strength.** The paper's core empirical finding — that attention layers in the tested Transformer LLMs can be pruned far more aggressively than MLP layers with minimal accuracy loss — is well-supported by the experiments. The `$\gamma$` metric, the cross-model replication, and the ablation studies collectively provide strong evidence for this descriptive claim. The paper's prescriptive and explanatory claims — that attention redundancy is an inherent architectural property, that future architectures should reduce attention layer counts, and that this finding reveals a fundamental inefficiency in Transformer design — are less well-supported. They rely on a single training trajectory, a limited set of evaluation tasks, and no causal or mechanistic analysis. These claims are plausible hypotheses motivated by the data, but the experimental evidence does not yet establish them as findings.

## 6. Limitations and Trade-offs

### The Difficulty Estimation Cost Is Not Accounted For — and It Dominates the Pruning Budget

**The assumption or constraint.** The paper's importance-scoring procedure requires a calibration pass: 256 forward passes through the full, unpruned model (each processing a 2048-token sequence from C4) to compute the cosine similarity scores that determine which layers to drop. The authors explicitly acknowledge in Section 3.1 that "since the similarity scores are computed locally, we can offload irrelevant modules to save memory," but they never quantify the compute cost of this calibration phase or include it in the reported speedup figures. The speedup measurements in Tables 1–3 cover only inference throughput *after* pruning, not the total cost of *achieving* the pruned model.

**The consequence.** For a one-time pruning of a model that will be deployed for millions of inference queries, the calibration cost is amortized and negligible. But the paper's framing — "a simple yet effective algorithm for efficiently removing redundant Attention layers in a training-free manner" (Section 1) — implies practical deployability in resource-constrained settings. In those settings, running 256 forward passes through a 70B model may itself require hardware (sufficient GPU memory for the full model) and time (minutes to hours on consumer hardware) that the end user does not have. The headline claim of "48.4% speedup" is accurate per-inference-query *after* pruning, but a complete cost accounting would include the calibration overhead.

**What evidence exists in the paper.** Figure 10 (Appendix B) shows that importance scores stabilize with as few as 4–16 samples, which suggests the calibration cost could be dramatically reduced without sacrificing pruning quality. However, all experiments in the main text use 256 samples, and the paper does not report speedup-or-accuracy results for a 4-sample or 16-sample calibration budget. Table 4 and the speedup measurements in Tables 1–3 do not include calibration FLOPs in the speedup denominator.

**Mitigation status.** The paper provides partial mitigation through Figure 10, which demonstrates that the importance scores are stable at far smaller sample counts — implying that a practitioner could use 16 or even 4 calibration samples and likely achieve similar pruning decisions at a fraction of the cost. However, the paper does not validate that the downstream accuracy of pruned models is preserved when using fewer calibration samples (it only shows that the importance *scores* are stable, not that the resulting pruning *decisions* and *model performance* are unchanged). This is an easy experiment that the paper does not conduct. The authors do not explicitly flag this as a limitation or propose calibration-cost reduction as future work.

---

### Attention Drop's Viability Depends on Task Type — and the Evaluation Suite Underrepresents Reasoning-Heavy Tasks

**The assumption or constraint.** The paper evaluates pruned models on eight benchmarks: BoolQ, OBQA, PIQA, RTE, ARC-C, HellaSwag, MMLU, and WinoGrande. These are predominantly multiple-choice knowledge and commonsense reasoning tasks. The authors acknowledge this scope implicitly by adding GSM8K (mathematical reasoning) and BANKING77 (long-context classification) in Appendix C, but the main results — including the headline `\gamma` scores and the claim that attention layers can be dropped with "minimal performance loss" — are based on the eight-task benchmark suite.

**The consequence.** The paper's own GSM8K results (Figure 12) reveal a failure mode that the main benchmark suite masks: **math-fine-tuned models can collapse under Attention Drop even at moderate pruning ratios.** MetaMath-7B-V1.0 (math-fine-tuned from Llama-2-7B) drops from ~39% GSM8K accuracy to well below 10% after removing only 6 attention layers. The authors attribute this to Llama-2-7B's weak base math capability, arguing that fine-tuned math skills are "superficial" and fragile to attention removal. But this explanation is post-hoc and was not systematically tested: MetaMath-Mistral-7B (fine-tuned from Mistral-7B) shows better robustness, dropping from ~68% to ~65% after 8 dropped attention layers, but still exhibits declining accuracy with each removed layer.

The implication for practitioners is clear: **the redundancy of attention layers is not uniform across task types.** Attention layers may be genuinely important for multi-step reasoning, mathematical derivation, or any task requiring the model to maintain and manipulate intermediate representations across token positions. The eight-task benchmark suite, which skews toward surface-level comprehension and commonsense judgment, systematically underestimates attention's contribution to the capabilities that practitioners most value in LLMs (reasoning, code generation, long-form coherent text). A practitioner deploying Attention Drop for a code generation application or a mathematical tutoring system cannot rely on the paper's `\gamma = 0.01` figures as indicative of what they will experience.

**What evidence exists in the paper.** Figure 12 (Appendix C) shows the GSM8K accuracy curves. Table 10 provides a qualitative output example where the model's reasoning degrades at 10–12 dropped layers: at 10 dropped, the model still produces the correct numerical answer but breaks the output format (missing "####" delimiter), and at 12 dropped, it produces a wrong answer with flawed reasoning. The long-context experiment in Table 12 also shows that attention removal hurts more at longer context lengths — at 14K tokens, dropping 4 attention layers reduces accuracy from 81% to 64% (a 17-point gap), compared to a much smaller gap at 2K tokens (26% → 15%, an 11-point gap). This suggests attention's role grows with the amount of contextual information that must be aggregated.

**Mitigation status.** The paper adds GSM8K and BANKING77 as supplementary experiments, which partially addresses the benchmark diversity limitation. However, there is no evaluation on code generation (HumanEval, MBPP), open-ended generation quality, multi-step logical reasoning (e.g., LogiQA, FOLIO), or tasks requiring factual consistency in long-form outputs. The paper does not discuss what task properties predict robustness to attention removal, nor does it provide guidance to practitioners on when Attention Drop is safe vs. risky. The section falls back on the general statement that "future work is testing the applicability of these techniques across a broader range of models, such as vision transformers and vision-language models" (Section 8), which expands model scope but not task-type scope within language models.

---

### The Method Discovers *That* Attention Layers Are Redundant, but Not *Why* — Making Prescriptive Architectural Claims Premature

**The assumption or constraint.** The paper's core prescriptive message is that "future works could reduce the number of attention layers without sacrificing performance, rather than maintaining parity with MLP layers" (Section 8). This claim assumes that the discovered redundancy is a **persistent architectural property** that would hold in models trained from scratch with fewer attention layers — not merely an artifact of how gradient-based optimization distributes representational work in standard Transformer architectures under standard training recipes.

**The consequence.** There is a critical distinction between (a) removing attention layers from a converged model and observing minimal accuracy loss, and (b) training a model with fewer attention layers from the start and achieving equivalent performance. The paper demonstrates (a) but claims (b) by implication. The gap between these two scenarios is large because **attention layers, even if redundant in the final model, may serve crucial roles during training** — enabling gradient flow across long distances, providing optimization shortcuts, or acting as "scaffolding" that helps the model learn representations that later become concentrated in MLP layers.

Concretely: if attention layers are important early in training and only become redundant late (a "scaffolding" hypothesis), then training without them from the start would hurt final performance, even though a converged model can tolerate their removal. The paper's training-stage analysis (Figure 7) partially addresses this by showing that attention redundancy is present from the earliest available checkpoint (500B tokens into training for MAP-Neo-7B). However, 500B tokens is already late in training — many representational properties are established much earlier (e.g., the first 10-100B tokens). The earliest checkpoint available (500B) may still be past the critical window where attention layers, if present, shaped the model's learning trajectory.

A second possibility is that attention layers are redundant *because* there are many of them — the presence of 40–80 attention layers may create optimization dynamics where gradient-based learning finds it easier to concentrate representational work in MLPs and shallow attention layers, leaving deep attention layers idle. If a model were trained with only 10 attention layers, optimization might be forced to use them more efficiently, potentially achieving similar performance with dramatically fewer attention parameters. Or it might not — the attention layers might genuinely have limited capacity to contribute beyond a certain point, regardless of count.

The paper cannot distinguish between these scenarios because it only manipulates pre-trained models, not training trajectories. The claim that future architectures should reduce attention layer counts is a **hypothesis motivated by the data**, not a **finding established by the data**.

**What evidence exists in the paper.** The training-stage analysis in Figure 7 uses MAP-Neo-7B checkpoints at 500B-token intervals from 500B to 4500B+. Attention importance scores are low and stable throughout this range, while MLP importance scores increase. However, (a) this is a single model from a single training run, (b) the earliest checkpoint (500B tokens) is already well into training (MAP-Neo-7B was trained on ~4.5T tokens total, so 500B is ~11% of the way through), and (c) there is no comparison against a model trained from scratch with a reduced attention layer count to test the prescriptive claim directly.

**Mitigation status.** The paper does not directly address this gap. Section 8 frames it as future work: "future research could explore replacing attention layers with alternative mechanisms or develop new training techniques that capitalize on this redundancy." This is a responsible flagging of the limitation, but the prescriptive language throughout the paper ("insights for scaling down," "future works could reduce the number of attention layers") overstates what the experiments can support. A more precise claim would be: "attention layers in standard pre-trained Transformers can be substantially pruned post-hoc without retraining, suggesting that their marginal contribution in the converged model is small — but whether this redundancy reflects a training inefficiency or a fundamental architectural overprovisioning requires further study."

---

### The Calibration Procedure Assumes Importance Scores Are Stable Under Distribution Shift — and This Is Not Tested for Deployment-Specific Domains

**The assumption or constraint.** The entire pruning decision hinges on importance scores computed from 256 samples of the C4 validation set — a dataset of general web text. The paper demonstrates (Figure 2, Figure 3) that importance score patterns are qualitatively similar when calibration is performed on C4, LIMA, CodeAlpaca, or MathInstruct, and uses this cross-dataset consistency to argue that "the redundancy patterns are properties of the model architecture, not artifacts of calibrating on a particular text distribution."

**The consequence.** The cross-dataset consistency shown in Figures 2 and 3 is reassuring but insufficient for a practitioner deploying a pruned model in a specific domain. The figures show that the *overall shape* of importance curves (deeper layers less important, shallow layers more important) is preserved across datasets. But the precise *ranking* of individual layers — which determines exactly which layers get dropped at a given pruning ratio — may vary across calibration datasets. If calibration on domain-specific text (e.g., biomedical literature, legal contracts, low-resource languages) produces a different ranking than C4, pruning based on C4-derived scores could drop layers that are important for the target domain while retaining layers that are redundant in that domain.

The paper provides no test of this: there is no experiment where calibration is performed on one dataset and evaluation on another dataset from a different domain, measuring whether the pruning decisions transfer. The GSM8K experiment (Figure 12) evaluates on math after calibrating on C4, but GSM8K is a downstream evaluation, not a calibration dataset — the question of whether calibrating on math-specific data would produce different (and better) pruning decisions for math tasks is not tested. The long-context experiment (Table 12) similarly evaluates on BANKING77 after calibration on C4, with no comparison against calibrating on in-domain banking text.

For a practitioner, this means: **the paper's pruning recipe may be suboptimal — and potentially harmful — for domain-specific deployments, and there is no guidance on when C4-calibrated pruning is safe vs. when domain-specific calibration is needed.**

**What evidence exists in the paper.** Figures 2 and 3 show importance score curves for four datasets, establishing cross-dataset shape consistency. However, these figures aggregate across all layers into line plots, which can mask rank-swapping between individual layers. Two layers with similar importance scores might swap positions in the ranking across datasets without visibly changing the curve shape. The paper does not report rank correlation (e.g., Spearman's `\rho`) between importance orderings produced by different calibration datasets, which would be the relevant statistic for evaluating pruning decision transfer.

**Mitigation status.** None. The paper does not discuss domain shift as a limitation of the calibration procedure or propose domain-adaptive calibration strategies. This is a practical gap that is particularly relevant given the paper's framing of Attention Drop as a deployment-time efficiency technique. A simple experiment — calibrate on C4, prune, evaluate on domain-specific tasks from BioASQ, CaseHOLD, or similar benchmarks — would substantially strengthen the practical case.

---

### The Speedup Measurements Are Single-GPU, Single-Batch-Size, and Do Not Reflect Distributed or Variable-Load Serving

**The assumption or constraint.** All speedup measurements in the paper are conducted on a single NVIDIA RTX A6000 Ada GPU, with a fixed input sequence length of 2048 tokens and 2048 generated tokens, using batch sizes chosen to "maximize GPU utilization for each model" (Section 5). For 70B models, 4-bit quantization is employed to fit the model on a single GPU, with the paper noting that "Attention Drop is orthogonal to quantization" (Appendix C, Table 11).

**The consequence.** Production LLM serving rarely occurs on a single GPU at maximum utilization. Real-world deployment scenarios include: (a) **multi-GPU tensor parallelism**, where attention computation may be sharded differently than MLP computation and the relationship between layer count and communication overhead is complex; (b) **pipeline parallelism**, where layer removal can shift the critical path and produce non-linear speedup effects; (c) **variable batch sizes** in online serving, where the speedup from removing layers may be masked by request queuing, memory bandwidth bottlenecks, or KV-cache management overhead; (d) **continuous batching** frameworks (e.g., vLLM, TensorRT-LLM) that optimize GPU memory allocation differently than the static-batch setting measured in the paper.

The paper's single-GPU measurement methodology is reasonable for establishing the *existence* of speedup from Attention Drop, but the specific numerical speedup claims (1.48× for Llama-2-70B Attn-40, 1.43× for Llama-3-70B Attn-40) should not be interpreted as predictions of what a practitioner will observe in their specific deployment environment. The speedup depends on the ratio of attention computation to MLP computation, which varies with batch size, sequence length, and model architecture (particularly the presence or absence of grouped-query attention). A deployment with very long sequences (where attention's quadratic complexity dominates) would likely see *larger* speedups from attention removal than the paper reports, while a deployment with very short sequences (where attention's constant-factor overhead is small relative to MLP) might see smaller speedups.

**What evidence exists in the paper.** Section 5 describes the measurement setup in moderate detail. Table 4 reports KV-cache memory savings, which is a complementary metric that is less sensitive to the specific serving configuration. The speedup numbers in Tables 1–3 are reported alongside `\gamma` values that normalize for the speedup-accuracy trade-off, which is a design choice that implicitly acknowledges the machine-specificity of absolute speedup figures.

**Mitigation status.** The paper does not discuss how speedup might vary across deployment configurations. It does not measure speedup at multiple batch sizes, sequence lengths, or GPU configurations. The orthogonal integration with quantization (Table 11) provides one dimension of deployment flexibility, but the speedup of quantized-plus-pruned models is not separately measured. For a practitioner, the paper's speedup numbers are best treated as **feasibility demonstrations** (showing that Attention Drop yields meaningful wall-clock improvements) rather than as **performance predictions** for a specific serving setup.

---

### The Method Is Entirely Post-Hoc and Offers No Mechanism for Recovering Performance Lost During Pruning

**The assumption or constraint.** Attention Drop and Joint Layer Drop are explicitly "training-free" — importance scores are computed once, layers are removed in a single step, and the model is deployed as-is. The paper positions this as a strength (simplicity, no GPU-hours spent on fine-tuning), and the ablation in Figure 9 confirms that iterative pruning provides no benefit over one-shot removal.

**The consequence.** Training-free pruning imposes a hard ceiling on achievable compression: once layers are removed, the performance that was lost cannot be recovered. This is in contrast to methods like Shortened LLaMA (Kim et al., 2024), which use post-compression retraining to regain some of the accuracy sacrificed by depth reduction. The paper's comparison with Shortened LLaMA (Table 8) shows that Joint Layer Drop (training-free) slightly outperforms the retrained Shortened LLaMA variants (60.7% vs. 60.3-60.6% average accuracy), but this comparison is at matched parameter budgets — it shows that type-aware pruning is *better* than type-blind pruning even when the latter uses retraining, not that training-free is strictly superior to retraining-based approaches.

The more relevant comparison would be: **Joint Layer Drop + fine-tuning vs. Joint Layer Drop alone**, which would quantify how much additional performance could be recovered through post-pruning adaptation. This experiment is not conducted. As a result, the paper's accuracy numbers (e.g., 71.5% for Llama-2-70B Attn-40 in Table 3) represent a **lower bound** on what type-aware pruning could achieve — it is plausible that light fine-tuning after pruning would close much of the remaining gap to the baseline (73.9%), making even more aggressive pruning ratios viable.

The ReST$^{EM}$ -style self-improvement loops are not explored here — the paper focuses exclusively on one-shot removal.

**What evidence exists in the paper.** The comparison with Shortened LLaMA (Table 8) provides indirect evidence: Joint Layer Drop without retraining achieves 60.7% accuracy with 1.45× speedup, vs. Shortened LLaMA with retraining at 60.3-60.6% with 1.22-1.23× speedup. This demonstrates that type-aware target selection can substitute for retraining when the pruning budget is allocated correctly. However, it does not test whether retraining *on top of* type-aware pruning would unlock further gains. The paper also does not evaluate whether fine-tuning the pruned model on the calibration dataset (or on task-specific data) recovers accuracy.

**Mitigation status.** The paper acknowledges this limitation in Section 8: "our methods focus on post-training dropping without involving retraining, which could potentially recover or even improve performance after pruning. Retraining these models could unlock even greater efficiency in more compact architectures." This is an honest flag, but it leaves the practical question unanswered: for a practitioner with a modest fine-tuning budget, what is the optimal combination of pruning ratio and post-pruning adaptation?

## 7. Implications and Future Directions

### How This Work Changes the Landscape

This paper shifts the conversation around Transformer architecture design from a **symmetry-by-default** paradigm toward a **heterogeneity-aware** paradigm. The current convention — every decoder block contains exactly one Attention sublayer and one MLP sublayer, stacked L times — is an unexamined inheritance from Vaswani (2017) that has survived through every generation of LLM scaling. Prior to this work, there was no systematic evidence testing whether this 1:1 parity is justified by the functional contributions of the two sublayer types. The paper's central empirical demonstration — that Attention layers are substantially more redundant than MLP layers across model families, scales, and training stages — provides the first concrete evidence that **the symmetric block design over-allocates capacity to attention** relative to its marginal contribution in converged models.

This is not a paradigm shift in the Kuhnian sense — the paper does not propose a new architecture, a new training objective, or a new theoretical framework for understanding Transformers. It is better characterized as a **diagnostic reframing** with significant practical consequences. The reframing has two components:

**First, the paper changes the unit of analysis for Transformer redundancy from blocks to sublayers.** Prior work (Gromov et al., 2024; Men et al., 2024; Kim et al., 2024) analyzed redundancy at the block level, treating each Transformer layer as an atomic unit. This paper demonstrates that block-level analysis systematically underestimates the extent of redundancy because it conflates the relatively important MLP signal with the highly redundant attention signal. By decomposing the importance measurement into separate Attention and MLP scores (Figure 3), the paper reveals a qualitative asymmetry that block-level methods could not detect. This is a methodological contribution — future redundancy analyses in any modular architecture should consider whether functionally distinct subcomponents within a module exhibit different redundancy patterns — but its impact comes from what the decomposition reveals, not the decomposition technique itself.

**Second, the paper reframes attention from a defining, indispensable mechanism to an over-provisioned architectural component.** The Transformer's identity is built on attention — "Attention Is All You Need" is the literal title of the originating paper. Subsequent architectures that remove attention (Mamba, RWKV, state-space models) are framed as departures from the Transformer paradigm, with attention positioned as the key ingredient being sacrificed for efficiency. This paper complicates that narrative by showing that, in large pre-trained Transformers, many attention layers contribute near-zero transformation to the representations passing through them (`$S^l_A < 0.1$` for many deep layers in Figure 3b). The finding does not diminish the importance of the attention layers that *do* contribute (shallow layers show consistently high importance scores), but it severs the implicit link between "attention is the defining mechanism of Transformers" and "every attention layer is essential." If half the attention layers can be removed with a `$\gamma$` of 0.05, those layers were not essential; they were architectural ballast.

**Prior contradictions this work helps resolve.** The paper reconciles an apparent tension in the efficiency literature. On one side, depth pruning methods (ShortGPT, Shortened LLaMA) demonstrated that deeper Transformer layers could be removed with modest degradation, suggesting substantial overall redundancy. On the other side, those same methods showed rapid performance collapse when pruning exceeded modest ratios — dropping 8 blocks from Llama-2-13B caused a 7.5-point accuracy decline. The paper resolves this by showing that the collapse is primarily attributable to MLP removal within pruned blocks, not to depth reduction per se. Attention Drop at equivalent or greater pruning ratios (8 attention layers removed) produces near-zero degradation. The prior negative results on depth pruning were not evidence that models need most of their layers; they were evidence that **models need most of their MLP layers**, and block-level pruning inadvertently removed those alongside redundant attention layers.

**Research directions that become more attractive.** Several lines of inquiry gain momentum from this work:

- **Asymmetric architecture design** — training models from scratch with non-1:1 attention-to-MLP ratios — becomes a high-priority empirical question. If attention redundancy is inherent (as Figure 7 suggests), models with fewer attention layers and the same MLP capacity may match or exceed the performance of symmetric designs while requiring less pretraining compute.

- **Verifier and importance metrics for structured pruning** become more important. The paper's cosine similarity metric works well for the tested models, but developing importance estimators that are robust to domain shift, calibration dataset choice, and model architecture variations is a clear next step, since the entire pruning decision depends on the quality of these scores.

- **Understanding *why* attention layers are redundant** becomes a foundational mechanistic interpretability question. Is it an optimization failure (gradient-based learning struggles to assign useful computations to attention)? An architectural property (residual connections allow information to bypass attention)? A data-driven phenomenon (next-token prediction on web text under-utilizes attention's capacity for long-range dependency modeling)? Distinguishing between these hypotheses would inform whether the solution is better training, better architectures, or both.

**Research directions that become less attractive.** The paper's results suggest that:

- **Developing more sophisticated block-level pruning criteria** (e.g., better importance metrics for entire blocks) is unlikely to yield large gains over existing methods, because the fundamental limitation of block-level pruning is not the quality of the importance metric but the granularity — even perfect block-level importance ranking would still remove MLP layers alongside attention layers. Attention Drop achieves better results with a simple metric at finer granularity than sophisticated metrics at coarse granularity.

- **Iterative pruning protocols** for Transformer depth reduction may be unnecessary complexity. The paper's one-shot vs. iterative ablation (Figure 9) shows that iterative removal provides no benefit and may slightly harm performance, consistent with the finding that importance scores are stable and the redundancy pattern is a structural property of the converged model, not something that shifts as layers are removed.

- **Unstructured pruning of attention weights specifically** may be a less promising direction than structured attention removal. The comparison with Wanda (Table 9) shows that structured Attention Drop achieves equal or better accuracy than unstructured pruning at matched parameter budgets, while providing actual hardware speedups. This suggests that attention redundancy is a structural property best addressed structurally — removing entire attention sublayers — rather than through fine-grained weight removal that preserves the layer count and the associated computational overhead.

---

### Follow-Up Research This Work Enables

**Training transformers from scratch with asymmetric attention-to-MLP ratios.** The paper's core prescriptive claim — that future architectures should reduce attention layer counts — cannot be validated by post-hoc pruning alone, because attention layers may serve important roles during training even if they are redundant in the converged model. A strong follow-up would train a series of Llama-scale models (e.g., 1B, 7B, 13B parameters) on the same data budget with varying attention-to-MLP ratios: the standard 1:1 baseline, a 1:2 configuration (one attention layer for every two MLP layers, with total depth held constant by stacking MLP layers), a 1:3 configuration, and a configuration where attention layers are concentrated in the shallow half of the network and the deep half contains only MLP layers. The key measurement is whether asymmetric models match the pretraining loss curve and downstream benchmark performance of the symmetric baseline at matched total FLOPs. A positive result would directly validate the paper's architectural prescription; a negative result (asymmetric models underperform despite post-hoc redundancy in the symmetric baseline) would demonstrate that attention layers serve a training-time role that post-hoc pruning analysis cannot detect, sharply constraining the paper's prescriptive claims.

**Mechanistic analysis of why attention layers become redundant during training.** The paper documents *that* attention redundancy exists and persists through training, but provides no causal explanation. A mechanistic study could probe this by analyzing gradient flow through attention vs. MLP sublayers during training: do attention layers receive smaller gradients relative to MLP layers? Do the residual connections create "shortcuts" that allow the model to route information primarily through MLP pathways? Does the softmax normalization in attention create optimization challenges (vanishing gradients in saturated attention patterns) that discourage the optimizer from using attention capacity? A specific experiment: track the per-layer gradient norms and the effective rank of attention output matrices throughout training for models of varying sizes, testing whether attention under-utilization is a gradient signal problem (which could be addressed through architectural modifications like scaled attention or different normalization schemes) or a capacity allocation problem (the model simply doesn't need that much attention to solve the pretraining objective).

**Task-conditioned redundancy profiling: when does attention matter?** The paper's GSM8K results (Figure 12) hint that attention redundancy is not uniform across task types — math-fine-tuned models degrade more under Attention Drop than base models, and the MetaMath-7B-V1.0 collapse suggests that attention may be important for multi-step reasoning even when it appears redundant on knowledge-intensive benchmarks. A systematic study would profile the impact of Attention Drop across a diverse task taxonomy: multi-step mathematical reasoning (GSM8K, MATH), code generation (HumanEval, MBPP), factual knowledge retrieval (MMLU subsets organized by domain), long-range dependency tasks (narrative QA, multi-document summarization), and open-ended generation (AlpacaEval, MT-Bench). For each task type, measure the degradation curve as attention layers are progressively removed, and identify the task properties that predict sensitivity to attention pruning. The hypothesis is that tasks requiring the model to aggregate information across many token positions — multi-hop reasoning, long-context QA, code generation with long-range dependencies — will show earlier and steeper degradation than tasks answerable from local context. This would produce a practical decision rule for practitioners: "Attention Drop is safe up to ratio X for task type Y, but should be avoided entirely for task type Z."

**Domain-adaptive calibration and the transferability of importance scores.** The paper calibrates importance scores on C4 (general web text) and demonstrates cross-dataset shape consistency, but does not test whether calibration domain affects downstream performance of the pruned model in domain-specific applications. A critical follow-up would measure the rank correlation (Spearman's `$\rho$`) between importance orderings produced by calibration on C4 vs. domain-specific corpora (biomedical PubMed abstracts, legal contracts from CaseHOLD, multilingual text from FLORES-200, code from The Stack). Then, for models pruned to a fixed sparsity ratio (e.g., 30% attention layers removed), compare the downstream accuracy of C4-calibrated pruning vs. domain-calibrated pruning on domain-specific evaluation benchmarks. The finding that C4 calibration generalizes well (high rank correlation, small accuracy gap vs. domain calibration) would validate the paper's claim that redundancy patterns are architectural rather than data-dependent. The finding that domain calibration matters (low rank correlation, significant accuracy gap) would imply that the paper's current pruning recipe is a general-purpose default that practitioners should override for specialized deployments, and would motivate research into lightweight domain-adaptive calibration procedures (e.g., using a handful of in-domain documents rather than 256 C4 samples).

**Combining Attention Drop with post-pruning fine-tuning to recover and extend capability.** The paper's training-free approach establishes a lower bound on what type-aware pruning can achieve. An obvious extension is to measure how much additional performance can be recovered — and how much further pruning can be pushed — when the pruned model undergoes light continued pretraining or instruction fine-tuning. Specific experiments: (1) After applying Attention Drop at a range of sparsity levels (20%–50% of attention layers removed), fine-tune the pruned model on the same pretraining corpus for a small number of steps (e.g., 1B tokens) and measure accuracy recovery on the eight-task benchmark suite. (2) Compare the accuracy of a 50%-attention-pruned model after 10B tokens of continued training against an unpruned model given the same additional training budget — this tests whether the pruned model can "catch up" or whether the lost attention capacity creates an unrecoverable deficit. (3) Test whether post-pruning fine-tuning can push the viable pruning ratio beyond the point where training-free Attention Drop begins to degrade (e.g., can continued training make a model with 60% attention layers removed competitive with an unpruned baseline?). The results would establish an efficiency envelope — how much pretraining compute can be saved by starting from a pruned model vs. training from scratch — and would bridge the gap between the paper's training-free methodology and the retraining-based approaches it compares against.

**Attention Drop in multimodal and encoder-decoder architectures.** The paper restricts evaluation to decoder-only language models. Extending the analysis to vision Transformers (ViT), vision-language models (LLaVA, BLIP-2), and encoder-decoder models (T5, BART) would test whether attention redundancy is a general property of the Transformer architecture or specific to autoregressive language modeling. The hypothesis is that encoder attention layers — which process the full input sequence bidirectionally — may exhibit different redundancy patterns than decoder attention layers, which operate causally. In vision Transformers, attention's role in spatial feature aggregation might make it more essential than in text, where local statistics are often sufficient. A strong study would replicate the paper's core analysis (cosine similarity importance scoring, separate Attention and MLP scores, per-module dropping at graded sparsity levels) across at least one model from each of these architectural families, reporting both the importance score distributions and the downstream accuracy degradation curves.

### Practical Applications and Downstream Use Cases

**Reducing KV-cache memory for long-context serving deployments.** The paper's KV-cache measurements (Table 4) have immediate implications for practitioners serving models with long context windows. Llama-2-13B at 2048 tokens and batch size 32 consumes 52GB of KV-cache memory at 16-bit precision. Halving the attention layers reduces this to 26GB — a 50% savings that can translate directly to larger possible batch sizes (improving throughput), longer supported context lengths (enabling new applications like document QA over full-length papers), or reduced hardware requirements (serving on a single GPU that previously required two). For models without grouped-query attention (where the per-layer KV-cache is largest), the savings are proportionally greater. The paper demonstrates that this 50% attention reduction costs only 2.4 percentage points of average accuracy on Llama-2-70B (Table 3, Attn-40), making the trade-off compelling for applications where context capacity is the binding constraint. A concrete deployment scenario: a customer-support chatbot using a 13B-parameter model to answer queries about long product documentation could double its context window by halving attention layers, allowing it to ingest entire manuals rather than truncated excerpts, while degrading benchmark accuracy from 68.2% to 64.9% — a 3.3-point trade-off that may be acceptable for the specific domain if the expanded context enables qualitatively better answers.

**Cost-efficient batch inference for knowledge-intensive evaluations.** Organizations running large-scale batch evaluations (e.g., evaluating thousands of questions across multiple benchmarks, generating training data, or scoring candidate responses) are sensitive to total inference time. The paper's speedup figures — 1.48× on Llama-2-70B with 2.4% accuracy loss (Table 3, Attn-40), 1.43× on Llama-3-70B with essentially no accuracy loss (Table 2, Attn-40) — directly translate to reduced GPU-hours and lower cloud compute bills. The training-free nature of Attention Drop makes it particularly suitable for this use case: a team can calibrate importance scores once on their specific model, prune to the desired speedup ratio, and then run their entire batch pipeline on the pruned model with confidence that accuracy on knowledge-intensive benchmarks (MMLU, HellaSwag, WinoGrande) will remain near baseline. The integration with quantization (Table 11) means the team can compound the benefits — a 4-bit quantized Llama-2-13B with 20 attention layers dropped would consume less than half the GPU memory of the original 16-bit model while delivering approximately 1.4× inference throughput, with total accuracy degradation in the range of 3-5 points. For high-volume evaluation pipelines, this compound efficiency justifies the one-time calibration cost within the first few hours of inference.

**Enabling single-GPU deployment of 70B-scale models for low-throughput applications.** The paper's speed measurements use a single NVIDIA RTX A6000 Ada GPU. Without pruning, running Llama-2-70B at FP16 is not feasible on this hardware — model weights alone exceed GPU memory, and the KV-cache adds further pressure. The paper addresses this by using 4-bit quantization for the 70B speed measurement, but separately demonstrates that Attention Drop reduces KV-cache memory by 50% (Table 4: 20GB to 10GB for 40 layers). A practitioner with a single high-memory consumer GPU (e.g., RTX 4090 with 24GB, or workstation A6000 with 48GB) could deploy a quantized, attention-pruned 70B model locally — something that would be impossible at full attention depth due to KV-cache overflow. The use case is low-throughput applications where latency is not critical but model capability matters: personalized research assistants running on a local workstation, offline document analysis tools, or privacy-sensitive processing that cannot be sent to cloud APIs. The paper's results suggest that a 50% attention-pruned, 4-bit quantized Llama-2-70B would fit within 48GB of GPU memory (model weights ~35GB in 4-bit, KV-cache 10GB after pruning, leaving headroom for activations) while retaining approximately 96.7% of the original model's benchmark performance (73.9% → 71.5% average accuracy).

**Accelerating iterative model development and experimentation.** Machine learning researchers and engineers frequently run evaluation sweeps across model checkpoints, hyperparameter configurations, or fine-tuning variants. Each evaluation run incurs inference costs proportional to model depth. Attention Drop provides a fast approximate evaluation mode: prune the model to 60-70% of its original attention layers (achieving 1.2-1.4× speedup with negligible accuracy degradation per Tables 1-3), run exploratory sweeps on the pruned version, and reserve full-model evaluation for the most promising configurations. The paper's calibration procedure requires only 256 forward passes — a fixed cost that is amortized across all subsequent inference — and the one-shot nature means no iterative refinement is needed. This is particularly valuable for teams without access to large GPU clusters: a single workstation can evaluate more configurations in a fixed time budget, accelerating the experimentation cycle. The caveat from the paper's GSM8K results (Figure 12) is important here: this approximate evaluation mode is most reliable for knowledge and commonsense benchmarks, and may be misleading for math reasoning or other attention-sensitive tasks. Practitioners should validate that their specific evaluation suite is robust to attention pruning before adopting this workflow.

### When to Prefer This Method

The paper itself positions Attention Drop against several specific alternatives, and the experimental results provide clear guidance on when each is preferable:

- **Prefer Attention Drop over Block Drop when** you want to preserve MLP layer functionality while eliminating redundant computation. Block Drop removes both sublayers within each block, destroying relatively important MLP computations alongside redundant attention ones. The `$\gamma$` comparison is decisive: Attention Drop achieves `$\gamma = 0.00-0.08$` across models, while Block Drop yields `$\gamma = 0.22-0.65$` (Tables 1, 3). The single scenario where Block Drop might be preferred is when maximum architectural simplicity is required and moderate performance degradation is acceptable — removing entire blocks produces a shallower model with no internal structural modifications, which may be easier to integrate into inference frameworks that expect standard Transformer blocks.

- **Prefer Attention Drop over MLP Drop when** you are targeting moderate to high speedup ratios (1.1×–1.5×) and need to preserve model accuracy. MLP Drop causes steep accuracy declines even at low pruning ratios (`$\gamma = 0.32-2.82$` across models), reflecting the genuine importance of MLP layers for knowledge representation. Attention Drop consistently achieves far lower `$\gamma$` values at equivalent or greater speedup. The one exception: at very low pruning ratios (1-2 layers removed from a large model), the `$\gamma$` difference matters less and the choice may be driven by other factors (e.g., KV-cache reduction favors Attention Drop, while parameter-count reduction favors MLP Drop since MLP layers contain more weights).

- **Prefer Joint Layer Drop over pure Attention Drop when** you are targeting aggressive compression (dropping more than ~35-40% of attention layers) and want to maximize accuracy at a given sparsity ratio. Joint Drop's advantage emerges only after the most redundant attention layers are exhausted and low-importance MLP layers become the next-best pruning targets (Figure 8). Below this transition point, Joint Drop is equivalent to Attention Drop and the added complexity of pooling scores across layer types provides no benefit. A practitioner can determine the transition point for their specific model by examining the importance score distribution: when the next-lowest attention score approaches the lowest MLP score, Joint Drop will begin to diverge from Attention Drop.

- **Prefer training-free Attention Drop over retraining-based depth pruning (e.g., Shortened LLaMA) when** you lack the computational resources for post-compression fine-tuning, or when you need to deploy the pruned model immediately. The comparison in Table 8 shows that training-free Joint Layer Drop matches or slightly exceeds the accuracy of retraining-based Shortened LLaMA at a higher speedup (1.45× vs. 1.22-1.23×), suggesting that retraining offers limited benefit when the pruning target is chosen correctly. However, this comparison is at matched parameter budgets — it does not address whether retraining on top of type-aware pruning would yield further gains. For practitioners with a fine-tuning budget, the optimal strategy may be Attention Drop followed by light continued training to recover any residual accuracy loss, a combination the paper does not evaluate.

- **Prefer Attention Drop over unstructured pruning (Wanda, SparseGPT) when** you need actual hardware speedup rather than theoretical parameter reduction. Unstructured pruning produces sparse weight matrices that require custom kernels or specialized hardware to accelerate; on standard GPUs, they run at baseline speed. Attention Drop removes entire structured sublayers, producing a valid dense Transformer that any inference framework can execute with genuine wall-clock speedup. The Table 9 comparison shows that Attention Drop matches or exceeds Wanda's accuracy at equivalent parameter budgets, while providing speedup that Wanda cannot deliver on standard hardware. The one scenario where unstructured pruning may be preferred is when downstream fine-tuning will densify the sparse model anyway (using pruning as a temporary compression for storage or transmission), or when the deployment hardware has native sparse matrix acceleration.
