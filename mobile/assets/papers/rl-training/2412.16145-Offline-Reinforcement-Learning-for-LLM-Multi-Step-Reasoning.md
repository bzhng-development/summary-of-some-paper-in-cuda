## 1. Executive Summary

This paper introduces **OREO** (Offline REasoning Optimization), an offline reinforcement learning method that jointly trains a policy model and an explicit value function by enforcing the soft Bellman Equation, targeting the multi-step reasoning limitations of Direct Preference Optimization—namely its reliance on paired preference data and its uniform treatment of all tokens, which prevents effective credit assignment in tasks with sparse rewards (e.g., a math problem where correctness hinges on a single subtraction step). Evaluated on GSM8K, MATH, and ALFWorld using Qwen2.5-Math-1.5B, DeepSeekMath-7B, and MiniCPM-2B models, OREO outperforms rejection sampling, DPO, and KTO baselines—achieving a 10.5% relative improvement over SFT on MATH with the 1.5B model and a 17.9% relative improvement from value-guided beam search over greedy decoding—while the learned value function enables test-time tree search at no additional training cost, establishing that explicit value function learning from unpaired offline data improves multi-step reasoning substantially and that pretraining remains the only viable path only when the base model's capability on a problem is near zero.

## 2. Context and Motivation

### The Core Problem: Offline Reinforcement Learning for Multi-Step Reasoning Is Broken

The paper addresses a specific, practical bottleneck: **we do not have effective offline reinforcement learning methods for improving large language models on multi-step reasoning tasks**. This matters because multi-step reasoning—mathematical problem solving, embodied agent control, web navigation—represents a large and growing fraction of LLM applications where correctness depends on getting a chain of interdependent decisions right. In these tasks, a single wrong token early in the reasoning chain can cascade into a completely wrong final answer, yet the environment only provides a binary success/failure signal at the end (sparse reward). The question is: given an offline dataset of trajectories with only this sparse terminal reward, how do we update the model to produce correct reasoning chains more often?

This is not a hypothetical problem. The dominant approach for post-training LLMs has been RLHF (Reinforcement Learning from Human Feedback), which relies on online data collection—generating responses, getting human or environment feedback, and updating the model in a tight loop. But online RLHF is **prohibitively expensive for most users**. As the authors note in Section 1:

> "tuning LLMs with Proximal Policy Optimization (PPO, Schulman et al., 2017) is often prohibitively expensive for most users, which limits practical applications"

This creates a gap: practitioners who want to improve their models on multi-step reasoning tasks need methods that work with pre-existing offline datasets—collections of trajectories generated by some prior policy—without requiring live interaction, environment access, or expensive human annotation. The paper's central claim is that existing offline methods either fail to work well on reasoning tasks (DPO) or fail to extract all the available signal from the data (rejection sampling), and that this gap can be closed with a principled approach borrowed from maximum-entropy reinforcement learning.

### Why This Problem Matters

The significance operates on three levels.

**Practical accessibility.** If the only way to improve LLM reasoning with RL is to run online PPO—requiring a reward model, a value model, a reference model, and the infrastructure to coordinate model generation with environment interaction—then only well-resourced organizations can participate. Offline methods democratize this: you collect a dataset once (or use an existing one), run training offline, and deploy. The paper's experiments use models in the 1.5B–7B parameter range—hardware that individual researchers and small teams can work with. This is not a paper about scaling to frontier models; it is about making RL-based reasoning improvement accessible.

**Data efficiency.** Multi-step reasoning datasets have a natural structure that simpler offline methods ignore. In a dataset of math problem solutions, roughly half the trajectories lead to correct answers and half do not. Rejection sampling—take only the correct trajectories, fine-tune on them—throws away the failed trajectories entirely. But those failures contain information: the model can learn *what not to do*, which tokens or reasoning steps are correlated with downstream errors, and how to recover from common mistake patterns. The paper argues (citing Kumar et al., 2022) that offline RL should be able to "learn from failure experience and enhance model robustness" in ways that supervised fine-tuning on only successes cannot. This is not merely a philosophical point—it translates to measurable performance differences, particularly on harder problems where successes are rare in the training data.

**Credit assignment at the token or step level.** This is the paper's most technically specific motivation. In a math problem where the model writes a 200-token solution and gets the answer wrong because of a single arithmetic error on token 47, any method that treats all tokens uniformly—assigning the same loss magnitude to every token based on the final binary outcome—is fundamentally inefficient. The error token should receive a strong negative learning signal; the surrounding correct reasoning tokens should not be penalized. This is the **credit assignment problem**, and it is especially acute in multi-step reasoning where correctness is path-dependent. The paper positions this as DPO's critical failure mode: "it treats all tokens uniformly, making it ineffective for credit assignment in multi-step reasoning tasks, which often come with sparse reward" (Section 1). A method that learns an explicit value function—which estimates the expected future reward from any intermediate state—can in principle assign credit at finer granularity, because the value function tells you *where in the trajectory* things went wrong.

### Prior Approaches and Where They Fall Short

The paper identifies three families of prior work and explains why each is insufficient for offline multi-step reasoning improvement.

#### Rejection Sampling / STaR (Self-Taught Reasoner)

The simplest approach: generate many candidate solutions from the base model, filter for those that lead to correct answers, and fine-tune on the correct ones. This has been called STaR (Zelikman et al., 2022), RAFT (Dong et al., 2023), ReST (Gulcehre et al., 2023), and ReST$^{EM}$ (Singh et al., 2023), and is essentially supervised fine-tuning on model-generated correct solutions.

**What it does well:** It is simple, stable, and often effective, particularly when the base model already produces some correct solutions on the target distribution (which provides training signal). The paper's own experiments (Table 1) confirm that rejection sampling outperforms DPO and KTO on several settings, and in the iterative setting (Figure 2) it provides consistent gains in the first few rounds.

**Where it falls short:** It learns nothing from failures. If the base model's success rate on a problem type is, say, 5%, rejection sampling discards 95% of the generated data. Those 95% of trajectories contain information about common error patterns, about *near-misses* (solutions that are almost right but fail at a specific step), and about the distribution of the model's outputs. Throwing them away leaves potential learning signal unused. The paper frames this as a fundamental limitation: rejection sampling "fails to fully exploit the offline dataset's potential—particularly the opportunity to learn from failure experience and enhance model robustness" (Section 1). This limitation manifests empirically in the iterative setting (Figure 2): rejection sampling shows saturation by iteration 3, while OREO continues to improve, "likely due to its ability to effectively learn from failed trajectories" (Section 5.2).

#### Direct Preference Optimization (DPO)

DPO (Rafailov et al., 2024b) reparameterizes the RLHF objective to optimize the policy directly from pairwise preference data without needing to train a separate reward model. It has become widely used for aligning LLMs with human preferences in dialogue and instruction-following settings.

**What it does well:** For general preference alignment, DPO is simpler than PPO (no reward model training, no online sampling) and achieves comparable results. It uses offline preference data efficiently.

**Where it falls short for multi-step reasoning:** The paper identifies two specific failure modes, both derived analytically in Section 3.3:

1.  **Unnecessary pairwise data construction.** DPO requires paired preference data: for each prompt, you need a "winning" response and a "losing" response, with the assumption that the probability of preferring one over the other follows the Bradley-Terry model (Equation 5). In multi-step reasoning tasks, however, the reward signal is objective and scalar—the answer is either correct or incorrect. There is no inherent need to construct pairwise preferences; you can directly observe whether a trajectory succeeded or failed. To apply DPO to reasoning tasks, prior work has had to *artificially* construct preference pairs (e.g., pairing a correct solution with an incorrect one for the same query), which the paper calls "an inefficient usage of offline data" (Section 3.3). This is not just a philosophical objection—constructing pairs from independent trajectories means you lose information about *which* incorrect trajectories are informative (e.g., a near-miss vs. a completely nonsensical answer), since both are treated identically as "losing" members of pairs.

2.  **No credit assignment.** This is the deeper technical problem, and the paper derives it formally. DPO's optimization telescopes the soft Bellman Equation across the entire trajectory (Equation 4), meaning the learning signal for each token in a response is proportional only to the difference in aggregate log-ratio between the winning and losing responses, not to that token's individual contribution to the outcome. All tokens are treated identically in the loss—there is no mechanism to penalize the specific token where an error occurred more than the preceding correct tokens. In multi-step reasoning, where a single wrong token can invalidate an otherwise correct reasoning chain, this granularity loss is critical. The paper states it bluntly: "Relaxing the soft Bellman Equation from every time step to the entire trajectory loses the granularity of credit assignment, which is especially critical in multi-step reasoning tasks where correctness often depends on a few key tokens" (Section 3.3).

#### KTO (Kahneman-Tversky Optimization)

KTO (Ethayarajh et al., 2024) is a more recent variant of DPO that can work with unpaired data—it labels each example as "desirable" or "undesirable" rather than requiring pairwise comparisons. This removes DPO's first limitation (the need for paired data).

**Where it falls short:** KTO still suffers from the credit assignment problem, because it operates at the response level rather than the token or step level. The paper's empirical results bear this out: KTO underperforms rejection sampling on GSM8K and MATH (Table 1), achieving 73.4% vs. 74.9% for rejection sampling on GSM8K with the 1.5B model, and 48.3% vs. 50.3% on MATH. On the 7B model, KTO actually performs *worse* than the SFT baseline on MATH (46.9% vs. 46.8%). This suggests that removing the pairwise requirement alone is insufficient; the credit assignment issue remains.

#### Online RL Methods (PPO, REINFORCE)

The paper acknowledges that online RL methods like PPO (used extensively in RLHF pipelines for models like GPT-4 and Gemini) can in principle address credit assignment by learning a value function through online interaction. However, the practical barrier is cost:

> "tuning LLMs with Proximal Policy Optimization (PPO) is often prohibitively expensive for most users" (Section 1)

Online RL requires generating responses on-the-fly during training, evaluating them against a reward model or environment, and updating the policy—all of which demands significant computational infrastructure and engineering complexity. For multi-step reasoning tasks, this is compounded by the length of trajectories (a MATH solution can be hundreds of tokens) and the need for the environment or reward model to evaluate intermediate states. The paper's contribution is to show that value function learning—and its benefits for credit assignment—can be achieved *offline*, without any of this online infrastructure.

#### Process Reward Models (PRMs)

A parallel line of work (Lightman et al., 2023; Wang et al., 2024a; Luo et al., 2024) trains separate Process Reward Models that score individual reasoning steps, typically using Monte Carlo rollouts: for each intermediate step in a solution, sample many completions and estimate the probability of eventual correctness. These PRMs can then be used to guide search at test time or to provide step-level reward signals for reinforcement learning.

**Where this connects to OREO:** The paper explicitly notes (Section 2.2) that Monte Carlo rollout-based PRM training "is a special case of the value function learned through our method." The value function $V_\phi(s_t)$ learned by OREO estimates the expected future reward from state $s_t$—exactly the quantity that Monte Carlo rollouts approximate. The difference is that OREO learns this value function jointly with the policy through a principled optimization objective (the soft Bellman Equation), rather than through a separate, heuristically designed training procedure. The paper argues this "removes the need for the extensive heuristic designs commonly required in prior works" (Section 4.4).

**Where prior PRM work falls short:** It typically requires substantial data engineering—deciding how to segment solutions into steps, defining what constitutes a "step," running many rollouts per step—and does not directly improve the policy model (PRMs are used for search at inference time or as reward signals for separate RL training, not for joint policy-value optimization). OREO produces both an improved policy and a value function from a single training procedure.

### How This Paper Positions Itself

The paper positions OREO as filling a specific gap in the existing landscape. It is not proposing online RL (too expensive), not proposing rejection sampling (too wasteful of failure data), and not proposing DPO/KTO (insufficient credit assignment for multi-step reasoning). Instead, it proposes an **offline maximum-entropy RL method** that:

1.  **Works with unpaired data** (unlike DPO), removing the need for artificial preference pair construction. Each trajectory in the offline dataset is used independently with its sparse terminal reward.

2.  **Learns from both successes and failures** (unlike rejection sampling), by training a value function that estimates expected future reward from any state, regardless of whether the trajectory ultimately succeeded.

3.  **Enables credit assignment at the token or step level** (unlike DPO, KTO, and response-level methods), by enforcing the soft Bellman Equation at every timestep—the consistency between the current state's value, the next state's value, and the action taken must hold locally, not just for the full trajectory.

4.  **Provides a value function for free** (unlike standalone PRM training), which can be used at test time for beam search or best-of-K action selection without additional training.

The paper anchors its approach in the established theory of maximum-entropy RL, specifically building on Path Consistency Learning (Nachum et al., 2017). The key theoretical move is elegantly simple: extend the soft Bellman Equation from standard maximum-entropy RL to the KL-regularized RLHF objective (Section 3.2), show that satisfying this equation at every timestep characterizes the optimal policy and value function (Theorems 1 and 2), and then design a loss function that jointly trains a policy and value model to minimize the violation of this equation on offline data (Section 4.1). The derivation in Section 3.3 further shows that DPO emerges as a special case when the equation is telescoped across the full trajectory and combined with a Bradley-Terry preference model, making explicit *why* DPO loses the credit assignment granularity that OREO preserves.

In summary, the paper is not arguing that prior methods are useless—rejection sampling works surprisingly well, and DPO works for preference alignment. Rather, it is arguing that multi-step reasoning with sparse rewards is a regime where these methods' limitations become bottlenecks, and that a theoretically grounded approach from the maximum-entropy RL literature directly addresses those bottlenecks with minimal additional complexity: train a value function alongside the policy.

## 3. Technical Approach

### 3.1 Reader Orientation

OREO is an offline reinforcement learning system that jointly trains a large language model (the policy) and a separate neural network (the value function) to improve the LLM's multi-step reasoning ability using only a pre-collected dataset of reasoning trajectories labeled with success or failure. The core problem is that existing offline methods either discard failed trajectories entirely (rejection sampling) or treat every token in a trajectory as equally responsible for the final outcome (DPO, KTO), but multi-step reasoning tasks have sparse rewards—only the final answer is checked—meaning that a single error token early in a solution should receive a different learning signal than the correct tokens surrounding it. OREO solves this by enforcing the soft Bellman Equation, a mathematical consistency condition from maximum-entropy reinforcement learning, at every timestep of every trajectory, which forces the learned value function to assign different future-reward estimates to different states and thereby provides the policy with token-level credit assignment signals.

### 3.2 Big-Picture Architecture

The system has four major components, all trained from the same offline dataset of reasoning trajectories:

- **The policy model** (`$\pi_\theta$`): an LLM (e.g., Qwen2.5-Math-1.5B) that generates reasoning token by token. It is initialized from a supervised fine-tuned checkpoint and updated to produce higher-expected-reward outputs while staying close to a reference policy.

- **The value model** (`$V_\phi$`): a separate neural network (typically a LoRA adapter on the same base LLM) that takes a partial reasoning state—a prompt plus a prefix of generated tokens—and outputs a scalar estimate of the expected future KL-regularized reward from that state. This is the credit-assignment mechanism.

- **The reference policy** (`$\pi_{\text{ref}}$`): a frozen copy of the initial policy (post-SFT), used only to compute KL-divergence penalties that prevent the updated policy from drifting too far from its starting point.

- **The offline dataset**: a collection of complete reasoning trajectories, each labeled with a sparse terminal reward—1 if the final answer is correct, 0 otherwise. No pairwise preferences, no step-level annotations, no environment interaction is needed.

Information flows through training as follows. A trajectory is sampled from the offline dataset. The policy model reads through the trajectory token by token, and at each token position, the value model reads the prefix up to that token and predicts a scalar `$V_\phi(s_t)$`. The soft Bellman Equation (Equation 7) says that this predicted value at state `$s_t$` should equal the actual future KL-regularized reward from `$s_t$` onward, which can be computed from the known terminal reward and the policy's own log-probabilities. The difference between the value model's prediction and the actual future return becomes the value loss (Equation 8). The policy is updated to minimize the inconsistency between consecutive states' values and the action taken (Equation 9), which effectively pushes the policy to take actions that lead to higher-valued states. Both models are updated simultaneously from the same trajectories, with gradients flowing through the policy's log-probabilities and through the value model's predictions.

At inference time, the policy generates solutions autoregressively (optionally guided by the value model through beam search). The value model is not needed for generation but can be used as a free process reward model for test-time search.

### 3.3 Roadmap for the Deep Dive

- **First**, the formal MDP formulation for LLM reasoning (Section 3.1 in the paper), which defines states, actions, transitions, and rewards in token-generation terms—this provides the mathematical vocabulary for everything that follows.
- **Second**, the soft Bellman Equation and the optimality theorems (Section 3.2), which establish *what* property the optimal policy and value function must satisfy and *why* enforcing this property is sufficient to recover the optimal policy.
- **Third**, the connection to DPO (Section 3.3), which shows analytically how DPO emerges as a special case when the soft Bellman Equation is telescoped across the full trajectory—making explicit exactly which properties DPO sacrifices that OREO preserves, thereby motivating the design.
- **Fourth**, the OREO training objectives (Section 4.1), which translate the optimality condition into concrete loss functions for jointly training the policy and value models on offline data.
- **Fifth**, the loss variants—step-level and response-level OREO (Section 4.2)—which help isolate *why* the token-level credit assignment matters and connect the method to existing approaches.
- **Sixth**, the iterative extension (Section 4.3) and the test-time search procedure (Section 4.4), which show how the learned components can be reused beyond single-round training.

This is primarily a **method paper** that derives a training algorithm from a theoretical optimality condition and then validates it empirically. The core idea is that multi-step reasoning with sparse rewards requires credit assignment at the token or step level, and that jointly training an explicit value function alongside the policy through the soft Bellman Equation provides this credit assignment while remaining fully offline.

#### Markov Decision Process Formulation for LLM Reasoning

OREO frames LLM generation as a Markov Decision Process (MDP), which is a standard formalism for sequential decision-making under uncertainty. This formulation is necessary because reinforcement learning algorithms operate on MDPs, and casting token generation as an MDP lets us apply well-understood RL theory to language model training.

**States.** At timestep `$t$`, the state `$s_t$` is the entire token sequence seen so far: the input prompt `$(x_0, \dots, x_L)$` concatenated with all previously generated tokens `$(y_0, \dots, y_{t-1})$`. For tasks that do not involve external environment interaction (like math reasoning), this is the complete context the model uses to decide what token to generate next.

**Actions.** An action `$a_t$` is a single generated token. The policy `$\pi(a_t \mid s_t)$` is the probability the language model assigns to token `$a_t$` given the current state `$s_t$`—this is exactly the standard next-token probability distribution that language models produce.

**Transitions.** For non-interactive tasks, the transition function `$f$` is deterministic:

$$s_{t+1} = f(s_t, a_t) = s_t \mid a_t$$

where `$\mid$` denotes string concatenation. The next state is simply the current state with the chosen token appended.

For interactive tasks (like embodied agent control in ALFWorld), the transition has an additional step: if `$a_t$` is the final token of the agent's complete response (e.g., "go to desk 1"), then the environment produces an observation, and the next state becomes `$s_t \mid a_t \mid \text{next observation}$`. This captures the feedback loop between the agent's actions and the environment's responses.

**Rewards.** The reward function `$r(s_t, a_t)$` is defined for every state-action pair but is non-zero only at the terminal step `$t = T$`. For math reasoning, the terminal reward is 1 if the final answer matches the ground truth and 0 otherwise. For embodied tasks, it is 1 if the task is completed successfully and 0 otherwise. This sparse reward structure is the fundamental challenge: the model receives only a single binary signal at the end of a potentially long trajectory, with no intermediate feedback about which specific tokens or reasoning steps were correct.

**Why this formulation matters.** By modeling token generation as an MDP, OREO can import concepts from reinforcement learning—value functions, optimality equations, credit assignment—that were developed for sequential decision-making. A value function `$V(s_t)$` represents the expected future reward from state `$s_t$`, which in the token-generation context means "how likely is it that continuing from this partial solution will lead to the correct answer?" This is exactly the quantity needed for credit assignment: if the value drops sharply after generating a particular token, that token likely introduced an error.

**The KL-regularized objective.** The overall optimization goal for the policy is:

$$\pi^* = \arg\max_\pi \; \mathbb{E}_{(s_0,\dots,s_T) \sim \rho_\pi} \sum_{t=0}^T \left[ r(s_t, a_t) - \beta \log \frac{\pi(a_t \mid s_t)}{\pi_{\text{ref}}(a_t \mid s_t)} \right]$$

where `$\rho_\pi$` is the distribution over trajectories induced by following policy `$\pi$`, `$\pi_{\text{ref}}$` is a frozen reference policy (typically the SFT checkpoint used for initialization), and `$\beta$` is a hyperparameter controlling the strength of the KL regularization. The first term `$r(s_t, a_t)$` encourages the policy to achieve high reward. The second term `$-\beta \log \frac{\pi(a_t \mid s_t)}{\pi_{\text{ref}}(a_t \mid s_t)}$` penalizes the policy for deviating from the reference policy—this is the standard KL penalty from RLHF that prevents the policy from collapsing to degenerate outputs that exploit the reward signal.

**What it computes:** the expected sum, over a full trajectory generated by following the policy, of immediate rewards minus a KL penalty at each step. The expectation is over the randomness in the policy's own token sampling, meaning the optimization considers not just the most likely trajectory but the entire distribution of possible trajectories.

**Why this form:** the KL penalty is essential in offline settings because the training data covers only a limited region of the state space. Without it, the policy might learn to output tokens that achieve high value under the learned value function but that were never observed in training—and for which the value function's estimates are unreliable. The penalty keeps the policy in regions where both the policy and value function are well-estimated. This is inherited directly from the RLHF literature (Ouyang et al., 2022) and is standard practice.

#### The Soft Bellman Equation and Optimality Theorems

The theoretical foundation of OREO is the soft Bellman Equation, which characterizes the relationship between an optimal policy and its value function under entropy-regularized (or KL-regularized) reinforcement learning.

**Defining the KL-regularized value function.** For any policy `$\pi$`, the value `$V^\pi(s_t)$` of being in state `$s_t$` is the expected sum of future KL-regularized rewards:

$$V^\pi(s_t) = \mathbb{E}_{(a_t, s_{t+1}, \dots) \sim \rho_\pi} \sum_{l=0}^{T-t} \left[ r(s_{t+l}, a_{t+l}) - \beta \log \frac{\pi(a_{t+l} \mid s_{t+l})}{\pi_{\text{ref}}(a_{t+l} \mid s_{t+l})} \right]$$

where the expectation is over trajectories starting from `$s_t$` and following `$\pi$` thereafter. This is the standard definition of a value function, augmented with the KL penalty term.

**What it computes:** starting from a partial solution `$s_t$`, if we follow policy `$\pi$` for all remaining tokens, what total KL-regularized reward do we expect to accumulate? This is a forward-looking estimate: it depends on the future tokens the policy will generate, not on past tokens. For a math problem, `$V^\pi(s_t)$` at an early reasoning step might be 0.7, meaning the policy expects a 70% chance of reaching the correct answer (accounting for the KL penalty); if the policy then generates an erroneous step, `$V^\pi(s_{t+1})$` might drop to 0.3.

**Why define it this way:** the value function decomposes the trajectory-level optimization into a per-state quantity. If we can accurately estimate `$V^\pi(s_t)$` for every state, we can judge the quality of individual actions by comparing the value before and after the action—which is exactly credit assignment.

**Theorem 1 (Soft Bellman Equation).** The paper proves (with proof sketch in Appendix B) that the optimal policy `$\pi^*$` and its value function `$V^*$` satisfy the following consistency condition at every timestep:

$$V^*(s_t) - V^*(s_{t+1}) = r(s_t, a_t) - \beta \log \frac{\pi^*(a_t \mid s_t)}{\pi_{\text{ref}}(a_t \mid s_t)}$$

where `$s_{t+1} = f(s_t, a_t)$`.

**What this equation says in operational terms:** the difference in optimal value between the current state `$s_t$` and the next state `$s_{t+1}$` (the left-hand side) should exactly equal the immediate KL-regularized reward obtained at this step (the right-hand side). In other words, the value function is *consistent* across time: the drop or gain in expected future return from taking action `$a_t$` equals the immediate reward minus the policy's KL penalty for that action.

**Why this form matters:** this is a local, per-step condition. It must hold for every `$(s_t, a_t, s_{t+1})$` triple individually, not just on average over trajectories. This is what enables credit assignment: if the left-hand side is large but the right-hand side is small, there is inconsistency, and the policy and value function are not optimal. By minimizing this inconsistency across all observed steps in the offline data, we can push the policy and value function toward optimality.

**Connecting to standard RL.** When `$\beta = 0$` (no KL regularization), the soft Bellman Equation reduces to the standard Bellman equation: `$V^*(s_t) - V^*(s_{t+1}) = r(s_t, a_t)$`. The KL term `$-\beta \log \frac{\pi^*}{\pi_{\text{ref}}}$` acts as an additional reward-like signal that encourages the policy to stay close to the reference.

**Theorem 2 (Sufficiency of Consistency).** If a policy `$\pi$` and value function `$V$` satisfy the soft Bellman Equation (Equation 3 in the paper) for *all* states `$s$` and actions `$a$`, then `$\pi = \pi^*$` and `$V = V^*$`.

**What this means for algorithm design:** Theorem 2 is the key justification for OREO's training approach. It says that if we can find a policy `$\pi_\theta$` and value function `$V_\phi$` that minimize violation of the soft Bellman Equation on our data, then we are guaranteed to recover the optimal policy and value function—no additional optimization is needed. This converts the problem of "find the policy that maximizes expected reward" into the problem of "find a policy and value function that are self-consistent according to Equation 3." The latter is a supervised-style regression problem on observed transitions, which is much more amenable to offline training.

**Derivation sketch (from Appendix B).** The proof proceeds by recognizing that the KL-regularized objective can be rewritten as a standard maximum-entropy RL objective with a modified reward `$r'(s_t, a_t) = r(s_t, a_t) + \beta \log \pi_{\text{ref}}(a_t \mid s_t)$`. Maximum-entropy RL theory (Haarnoja et al., 2017) then establishes that the optimal policy satisfies `$\beta \log \pi^*(a_t \mid s_t) = Q^*(s_t, a_t) - V^*(s_t)$`, where the optimal Q-function satisfies `$Q^*(s_t, a_t) = r'(s_t, a_t) + \mathbb{E}[V^*(s_{t+1})]$`. Substituting the modified reward and the Q-function expression yields the soft Bellman Equation. This derivation is lightweight because it reuses existing maximum-entropy RL results rather than proving them from scratch.

#### Connection to DPO: Where the Credit Assignment Is Lost

The paper derives DPO from the same soft Bellman Equation framework to show precisely *which* assumptions cause DPO to lose credit assignment. This derivation (Section 3.3) serves double duty: it validates the framework by showing it can recover a known method as a special case, and it makes the limitations of that method analytically transparent.

**Step 1: Telescoping the soft Bellman Equation.** Summing Equation 3 from `$t = 0$` to `$t = T-1$` causes intermediate state values to cancel:

$$\sum_{t=0}^{T-1} r(s_t, a_t) = V^*(s_0) + \sum_{t=0}^{T-1} \beta \log \frac{\pi^*(a_t \mid s_t)}{\pi_{\text{ref}}(a_t \mid s_t)}$$

where we use the fact that `$V^*(s_T) = 0$` at the terminal state (no future reward). This is Equation 4 in the paper.

**What this telescoping does:** it aggregates the per-step consistency conditions into a single trajectory-level constraint. The intermediate values `$V^*(s_1), V^*(s_2), \dots, V^*(s_{T-1})$` vanish from the equation—only the initial state value `$V^*(s_0)$` and the sum of per-token log-ratios remain. This is mathematically valid (it follows directly from Equation 3) but operationally consequential: we have lost the ability to distinguish which tokens contributed how much to the trajectory's outcome. The sum of log-ratios is a single scalar per trajectory, not a per-token breakdown.

**Step 2: Introducing the Bradley-Terry preference model.** DPO further assumes that human preferences (or, in reasoning tasks, the ground-truth reward) follow the Bradley-Terry model:

$$p^*(\tau^w \succ \tau^l) = \frac{\exp(r(s^w_T, a^w_T))}{\exp(r(s^w_T, a^w_T)) + \exp(r(s^l_T, a^l_T))}$$

where `$\tau^w$` is a "winning" trajectory and `$\tau^l$` is a "losing" trajectory. This assumes that the probability of preferring one trajectory over another depends only on their terminal rewards, and that those rewards are scalar values that can be compared through a softmax.

**What this assumption does:** it forces the preference to be determined entirely by the terminal state's reward, ignoring the trajectory's internal structure. For multi-step reasoning with a binary terminal reward (correct = 1, incorrect = 0), this means all correct trajectories are treated as equally preferable to all incorrect trajectories, regardless of *how* correct or incorrect they are. A correct solution with a flawed intermediate step that happened to cancel out is treated identically to a flawless solution; an incorrect solution that fails only at the last token is treated identically to one that is nonsensical from the start. There is no mechanism for graded preference.

**Step 3: Deriving the DPO loss.** Substituting the telescoped Equation 4 for the terminal reward in the Bradley-Terry model and maximizing log-likelihood over preference pairs `$(\tau^w, \tau^l)$` yields the DPO loss:

$$\mathcal{L}_{\text{DPO}} = -\mathbb{E}_{(\tau^w, \tau^l) \sim \mathcal{D}} \left[ \log \sigma \left( \sum_{t=0}^{T-1} \beta \log \frac{\pi^*(a^w_t \mid s^w_t)}{\pi_{\text{ref}}(a^w_t \mid s^w_t)} - \sum_{t=0}^{T-1} \beta \log \frac{\pi^*(a^l_t \mid s^l_t)}{\pi_{\text{ref}}(a^l_t \mid s^l_t)} \right) \right]$$

where `$\sigma$` is the logistic sigmoid function.

**What this loss computes:** for each pair of trajectories, it increases the aggregate log-ratio (summed over all tokens) for the winning trajectory and decreases it for the losing trajectory. The gradient flows uniformly to all tokens in each trajectory—there is no per-token distinction in the learning signal. A token in the winning trajectory receives a positive gradient regardless of whether it was genuinely helpful or merely present; a token in the losing trajectory receives a negative gradient regardless of whether it caused the failure or was actually correct.

**The two concrete problems.** The derivation makes explicit what Section 1 claims:

1. **Unnecessary pairwise data:** Equation 6 requires paired winning and losing trajectories per prompt. But in reasoning tasks, the reward is scalar and objective—we don't need to *infer* preferences, we can *compute* correctness directly. Constructing artificial pairs from independent correct and incorrect trajectories discards the absolute reward signal and treats all failures identically regardless of their proximity to success.

2. **No credit assignment:** The telescoping step aggregates all per-token log-ratios into a single sum. The DPO loss sees this sum, not its constituent terms. It cannot assign more credit or blame to tokens that were causally responsible for the outcome because all tokens contribute equally to the sum.

**What OREO does differently:** OREO does not telescope—it enforces the soft Bellman Equation at every timestep individually (Equation 7 below). OREO does not use the Bradley-Terry model—it uses the raw sparse terminal reward directly. And OREO trains an explicit value function `$V_\phi$` that predicts expected future reward from each state, which by design captures per-state credit assignment because the value difference `$V_\phi(s_t) - V_\phi(s_{t+1})$` isolates the contribution of the specific action `$a_t$`.

#### OREO Training Objectives

OREO jointly trains a policy model `$\pi_\theta$` and a value model `$V_\phi$` to minimize violation of the soft Bellman Equation on offline data. The training procedure has two loss functions—one for the value model and one for the policy—that are computed from the same trajectory data.

**Telescoped consistency for sparse rewards.** Since the reward is non-zero only at the terminal step, the soft Bellman Equation can be telescoped from an arbitrary intermediate state `$s_t$` to the end of the trajectory:

$$V^*(s_t) = R_t - \beta \sum_{i \geq t} \log \frac{\pi^*(a_i \mid s_i)}{\pi_{\text{ref}}(a_i \mid s_i)}$$

where `$R_t = \sum_{i \geq t} r(s_i, a_i)$` is the sum of future rewards from step `$t$` onward—which for sparse reward is simply 1 if the trajectory eventually succeeds and 0 if it fails, regardless of `$t$`. This is Equation 7.

**What this says:** the optimal value at state `$s_t$` should equal the actual future outcome `$R_t$` (which is 0 or 1, determined by whether the trajectory ultimately succeeds) minus the cumulative KL penalty that the optimal policy would incur from `$t$` onward. The right-hand side is fully computable from the offline trajectory: we know `$R_t$` (it's the terminal reward), and we can compute the log-ratios from the current policy `$\pi_\theta$` and the frozen reference `$\pi_{\text{ref}}$`.

**Why telescope here but not in DPO?** This is a *partial* telescope—we sum from `$t$` to `$T$` rather than from `$0$` to `$T$`. Crucially, we keep `$t$` as a free variable: we will enforce this consistency condition for *every* timestep `$t$` in the trajectory, not just for `$t = 0$`. This means the value function must be accurate at every intermediate state, which is what enables credit assignment. DPO only uses the `$t=0$` version, which discards all intermediate-state information.

**Value function loss.** The value model `$V_\phi$` is trained with a mean squared error (MSE) loss to match the right-hand side of Equation 7:

$$\mathcal{L}_V(\phi) = \frac{1}{T} \sum_{t=0}^{T-1} \left( V_\phi(s_t) - R_t + \beta \sum_{i \geq t} \log \frac{\pi_\theta(a_i \mid s_i)}{\pi_{\text{ref}}(a_i \mid s_i)} \right)^2$$

where the sum runs over all timesteps in the trajectory.

**What it computes:** for each prefix of the trajectory `$s_t$`, we compute the target value—the actual outcome `$R_t$` (0 or 1) minus the cumulative KL penalty from the current policy from `$t$` to the end—and penalize the squared difference between `$V_\phi(s_t)$` and this target. The target is computed using the current policy `$\pi_\theta$`, not the optimal policy, so the value model learns to predict the expected return under the *current* policy rather than the optimal one. As the policy improves, the target changes, and the value model tracks it. At convergence, `$\pi_\theta = \pi^*$` and `$V_\phi = V^*$`.

**Why MSE?** The target is a scalar (continuous between approximately 0 and 1 after accounting for KL penalties), and MSE is the standard regression loss for continuous targets. Binary cross-entropy would be appropriate if the target were a probability, but here the target includes the KL penalty which can push it outside `$[0,1]$` and gives it a different interpretation (expected KL-regularized return rather than pure success probability).

**Policy loss.** The policy is trained to minimize the squared inconsistency of the soft Bellman Equation at each step, with the value model providing the per-state estimates:

$$\mathcal{L}_\pi(\theta) = \frac{1}{T} \sum_{t=0}^{T-1} \left( V_\phi(s_t) - R_t + \beta \log \frac{\pi_\theta(a_t \mid s_t)}{\pi_{\text{ref}}(a_t \mid s_t)} + \text{sg}\left[ \beta \sum_{i > t} \log \frac{\pi_\theta(a_i \mid s_i)}{\pi_{\text{ref}}(a_i \mid s_i)} \right] \right)^2 + \alpha \mathcal{L}_{\text{reg}}$$

where `$\text{sg}[\cdot]$` is the stop-gradient operator and `$\mathcal{L}_{\text{reg}} = \frac{1}{T} \sum_{t=0}^{T-1} \text{KL}[\pi_\theta(\cdot \mid s_t) \parallel \pi_{\text{ref}}(\cdot \mid s_t)]$` is an additional KL regularization term scaled by hyperparameter `$\alpha$`.

**What it computes, term by term:**

- `$V_\phi(s_t)$`: the value model's estimate of expected future return from the current state. This is the "should-be" value.
- `$R_t$`: the actual future outcome (0 or 1). For a successful trajectory, `$R_t = 1$` for all `$t$`; for a failed trajectory, `$R_t = 0$` for all `$t$`.
- `$\beta \log \frac{\pi_\theta(a_t \mid s_t)}{\pi_{\text{ref}}(a_t \mid s_t)}$`: the KL penalty for the specific action taken at step `$t$`. This is the policy's *current* contribution to the soft Bellman Equation.
- `$\text{sg}[\beta \sum_{i > t} \log \frac{\pi_\theta(a_i \mid s_i)}{\pi_{\text{ref}}(a_i \mid s_i)}]$`: the KL penalty for future actions, with gradients stopped. This term provides the correct target value but does not receive gradients—the policy at step `$t$` is updated based on its own action's contribution, not on actions taken at future steps.

The squared difference between the first three terms and `$R_t - \text{sg}[\cdot]$` (rearranged) is minimized. The regularization term `$\alpha \mathcal{L}_{\text{reg}}$` provides an additional, direct KL penalty averaged over all timesteps.

**What this accomplishes operationally:** at each step `$t$`, the policy is encouraged to adjust `$\log \pi_\theta(a_t \mid s_t)$` so that the predicted value at `$s_t$` (the current state) equals the predicted value at `$s_{t+1}$` (captured implicitly through the future terms) plus the immediate KL penalty. If the trajectory is successful (`$R_t = 1$`) but the value model predicts low value at `$s_t$`, the policy is pushed to increase `$\pi_\theta(a_t \mid s_t)$`—because a larger log-probability reduces the penalty term and helps satisfy the equation. Conversely, if the trajectory fails (`$R_t = 0$`) but the value model predicts high value at `$s_t$`, the policy is pushed to decrease `$\pi_\theta(a_t \mid s_t)$`—the action likely contributed to the failure. This is credit assignment: the signal depends on the relationship between the value at the current state, the value at the next state, and the action taken, not on a uniform per-token weight.

**Why the stop-gradient?** Without it, the gradient for `$\log \pi_\theta(a_t \mid s_t)$` would include contributions from all future log-probabilities in the sum, effectively making the per-step gradient identical to the response-level gradient (all tokens get the same signal). The stop-gradient isolates the gradient to the immediate action's log-probability, ensuring that each step's update depends only on its own contribution to the soft Bellman consistency. The future terms still affect the target value—so the magnitude of the update is correct—but they do not dilute the per-step credit assignment.

**Why the additional regularization term** `$\alpha \mathcal{L}_{\text{reg}}$`**?** The soft Bellman Equation itself contains an implicit KL penalty, but only for the actions actually taken in the trajectory. The explicit regularization term penalizes the KL divergence between `$\pi_\theta$` and `$\pi_{\text{ref}}$` over the *entire* token distribution at each state—not just the observed action—which prevents the policy from collapsing probability mass onto observed actions while ignoring other valid alternatives. It also helps stabilize training by bounding how far the policy can move from initialization per update.

**Joint training dynamics.** Both losses are computed from the same batch of trajectories. The value model is updated to better predict future returns under the current policy; the policy is updated to take actions that are more consistent with the value model's estimates. This is a cooperative rather than adversarial training process—both models work toward satisfying the same consistency condition—and it contrasts with actor-critic methods where the critic provides a target for the actor but the actor does not directly influence the critic's target beyond generating the data.

**Hyperparameters (from Appendix A.3).** For OREO, the learning rate is `$5 \times 10^{-6}$`, `$\beta = 0.03$` (the KL penalty coefficient in the soft Bellman Equation), `$\alpha = 0.01$` (the weight of the additional regularization term), and the batch size is 128. For 1.5B models, training runs for 1 epoch; for 7B models, 2 epochs (such that total samples match). For 7B models, LoRA is used for the value model (rank 64, alpha 64) with a learning rate of `$10^{-4}$` for the critic, to save computation.

#### Loss Variants: Step-Level and Response-Level OREO

The paper introduces two variants of the OREO objective to isolate the contribution of token-level credit assignment and to connect the method to existing approaches.

**Step-level OREO.** Instead of treating each token as a separate action, step-level OREO treats an entire reasoning step (e.g., "In May, Natalia sold 48 / 2 = 24 clips.") as a single action. The probability of a step `$a = (t_1 t_2 \cdots t_k)$` is the product of token-level probabilities conditioned on the prefix: `$\pi(a \mid s) = \prod_{i=1}^k p(t_i \mid s, t_1, \dots, t_{i-1})$`. The loss functions are modified accordingly—sums over tokens become sums over steps, and the value function predicts at step boundaries rather than token boundaries.

**Segmentation.** For GSM8K, reasoning steps are delimited by line breaks already present in the dataset. For MATH, both line breaks and periods indicate step boundaries (Appendix A.2). This segmentation is heuristic but works because math solutions tend to have natural step structure.

**What this variant tests:** it provides an intermediate granularity between token-level (finest) and response-level (coarsest) credit assignment. If step-level OREO performs comparably to token-level OREO, it suggests that the key benefit is distinguishing between reasoning steps rather than between individual tokens within a step. If it underperforms, it suggests that finer granularity matters—individual tokens within a step can be the source of errors.

**Empirical finding** (Table 5): step-level OREO performs comparably to token-level OREO and slightly outperforms it on GSM8K (the paper attributes this to potential noise reduction, since the value function may be more accurate at step boundaries where more context is available). The paper adopts token-level OREO as the standard due to simpler implementation (no step segmentation needed), but notes that step-level policy optimization "remains an intriguing avenue for future exploration."

**Response-level OREO.** This variant enforces the soft Bellman Equation only at the initial state `$s_0$` of the trajectory:

$$\mathcal{L}^{\text{resp}}_\pi(\theta) = \left( V_\phi(s_0) - R_0 + \beta \sum_{i \geq 0} \log \frac{\pi_\theta(a_i \mid s_i)}{\pi_{\text{ref}}(a_i \mid s_i)} \right)^2 + \alpha \mathcal{L}_{\text{reg}}$$

**What this does:** it collapses all per-token consistency conditions into a single trajectory-level constraint. Every token in the trajectory receives the same gradient signal (modulated only by the log-probability derivative), because the loss depends on the sum of all log-ratios. This is essentially DPO-like credit assignment but with a continuous target (the squared error to the value at `$s_0$`) rather than a binary preference comparison.

**What this variant tests:** it provides a direct ablation of token-level credit assignment. If response-level OREO underperforms token-level OREO, it demonstrates that the per-step enforcement of the soft Bellman Equation—not just the joint policy-value training or the use of unpaired data—is responsible for the performance gains.

**Empirical finding** (Table 5): response-level OREO underperforms token-level OREO, confirming that "treating all actions in the trajectories uniformly, making it challenging to properly assign the sparse reward to individual tokens" (Section 5.1) is indeed a performance bottleneck. The paper explicitly connects this to DPO's limitations: "This limitation also sheds light on the suboptimal performance of DPO, as it struggles with credit assignment."

**Design justification for the variants.** The paper includes these variants not as alternative recommendations but as analytical tools: they isolate *which* component of OREO matters. Token-level granularity matters, joint policy-value training matters (creating an explicit value function separate from the policy), and the combination of both is what drives the performance improvements over DPO and rejection sampling.

#### Iterative OREO

When additional computational resources are available, OREO can be extended into an iterative framework (Section 4.3 and Figure 2). The process is:

1. **Initial training:** Train OREO on the offline dataset (trajectories generated by the base or SFT model).
2. **Data collection:** Use the updated policy model to generate new trajectories—either by solving math problems or interacting with the environment—and label them with terminal rewards.
3. **Dataset update:** Add these new trajectories to the training dataset (or replace old trajectories).
4. **Re-training:** Train OREO again on the expanded dataset, initializing from the previous iteration's checkpoint.
5. **Repeat** for multiple iterations.

**Why this helps:** the initial offline dataset is generated by a relatively weak policy (the base model), so the trajectories it contains—particularly the failed ones—represent error patterns that a weaker policy makes. After one round of OREO training, the policy improves and may make different kinds of errors. Collecting new trajectories from the improved policy exposes the value function and policy to these new error patterns, enabling further learning. The iterative process expands the diversity of states and outcomes in the training data.

**Empirical behavior** (Figure 2): OREO shows steady improvement across three iterations on both GSM8K and MATH. Rejection sampling also improves initially but shows saturation by iteration 3, while OREO continues to improve. The paper hypothesizes that "the updated policy model in each new iteration may be able to explore novel failure patterns, and incorporate these insights into the learning process" (Section 5.2). OREO's ability to learn from failures means that each iteration's new failure modes provide fresh training signal; rejection sampling, which discards failures, sees diminishing returns as the policy's success rate increases and fewer training examples are available.

**Implementation note:** the paper does not provide separate hyperparameters for the iterative setting. The same OREO configuration is used at each iteration.

#### Test-Time Search with the Learned Value Function

A key practical benefit of OREO is that the value model `$V_\phi$`, which is trained as a byproduct of the policy optimization, can be directly used at inference time for search-based decoding without any additional training (Section 4.4).

**For math reasoning (step-level beam search).** The value model functions as a Process Reward Model (PRM): given a partial solution (prompt + reasoning prefix), `$V_\phi(s)$` estimates the expected future KL-regularized reward—effectively, how likely it is that continuing from this prefix will lead to the correct answer. The beam search procedure is:

1. Maintain a set of `$B$` candidate partial trajectories (beams). Initialize with a single empty beam (just the prompt).
2. At each reasoning step, for each of the `$B$` beams, generate `$B$` possible next reasoning steps by sampling from the policy model.
3. This produces `$B^2$` candidate extended trajectories. Score each with the value model `$V_\phi$` at the new state.
4. Keep the `$B$` candidates with the highest value scores.
5. Repeat until all beams reach a terminal state or a maximum step count, then select the beam with the highest final value or extract the final answers and use majority voting.

**What makes this possible:** the value model `$V_\phi$` was trained to satisfy `$V_\phi(s_t) \approx \mathbb{E}[\text{future KL-regularized return} \mid s_t]$`. This is precisely the quantity needed to rank partial solutions: a higher value means a higher expected chance of eventual success. Unlike dedicated PRMs that require separate training pipelines with Monte Carlo rollouts and heuristic step segmentation, OREO's value model is trained jointly with the policy and inherits its step segmentation implicitly from the data.

**Why this is "for free":** no additional data collection, annotation, or training is required. The value model exists because OREO's training procedure required it. Using it at test time is a pure inference-time addition.

**For embodied agent tasks (best-of-K action selection).** In interactive environments where the transition dynamics are unknown and full beam search is not possible (the environment only reveals the next observation after an action is taken), the value model can still be used for test-time improvement. At each step, sample `$K$` candidate actions from the policy, score each resulting partial trajectory with `$V_\phi$`, and select the action that leads to the highest-valued state.

**Empirical results** (Section 5.4, Figures 3 and 4):
- On MATH (500-question subset), beam search with `$B = 7$` provides an 11.4% relative improvement on GSM8K and a 17.9% relative improvement on MATH over greedy decoding.
- On ALFWorld, best-of-K action selection with `$K = 5$` significantly improves success rates in both seen and unseen environments.
- Performance improves with compute budget: larger `$B$` (or `$K$`) yields higher accuracy/success rate, with diminishing returns.

**Connection to PRM works.** The paper explicitly notes that prior PRM methods (Wang et al., 2024a; Luo et al., 2024) train their models using Monte Carlo rollouts for each step, which is "essentially similar to the objective used for training the value function in our approach (Eq. 8)." The difference is that OREO provides this value function as an integrated component of policy training rather than as a separate, heuristically designed pipeline. The paper claims this "removes the need for the extensive heuristic designs commonly required in prior works" (Section 4.4)—no separate step segmentation for PRM training, no rollout budget allocation, no independent PRM architecture design.

**The implicit vs. explicit value function comparison** (Section 5.3, Figure 1). The paper also compares OREO's explicit value model `$V_\phi$` with the implicit value function that can be extracted from the DPO-trained policy `$\pi_\theta$` (as proposed by Rafailov et al., 2024a). The implicit value at state `$s_t$` is defined as:

$$V_\theta(s_t) = V(s_0) + \sum_{t'=0}^t \beta \log \frac{\pi_\theta(a_{t'} \mid s_{t'})}{\pi_{\text{ref}}(a_{t'} \mid s_{t'})}$$

and the implicit advantage of a reasoning step (tokens `$i$` to `$j$`) is:

$$A_\theta = \sum_{t=i}^{j-1} \beta \log \frac{\pi_\theta(a_t \mid s_t)}{\pi_{\text{ref}}(a_t \mid s_t)}$$

The explicit advantage from OREO's value model is:

$$A_\phi = V_\phi(s_j) - V_\phi(s_i)$$

**Qualitative finding** (Figure 1): the explicit value function produces larger-magnitude advantage estimates that better distinguish correct from incorrect reasoning steps. In an example where a step is incorrect ("Betty now has $50 + $30 = $80"), the explicit value drops from 0.816 to 0.385 (advantage = -0.431), while the implicit advantage is "much more conservative." In a more challenging MATH example, the explicit advantage correctly identifies the correct step while the implicit advantage fails. The paper hypothesizes this gap is due to the "softmax bottleneck" (Yang et al., 2017): the policy model's log-probability predictions for all tokens at a given state are generated from the same final hidden state, differing only by a linear head and softmax, while the value model processes the entire text sequence through the full transformer, enabling a richer representation of the state.

## 4. Key Insights and Innovations

### Innovation 1: Explicit Value Function Learning as the Solution to Credit Assignment in Sparse-Reward Reasoning

The paper's most distinctive intellectual contribution is not the specific loss functions—those follow naturally from the soft Bellman Equation—but the **diagnosis that the central failure mode of existing offline methods for multi-step reasoning is the absence of an explicitly learned, separate value function**. This is a conceptual reframing of what the field should be optimizing, not merely a new algorithm.

Before OREO, the dominant offline approaches to improving LLM reasoning fell into two camps, both of which implicitly or explicitly avoided learning a value function. DPO and its variants (Rafailov et al., 2024b; Ethayarajh et al., 2024) collapsed the entire trajectory into a single preference comparison, effectively treating the policy model itself as an implicit value function but never training it to perform that role. Rejection sampling (Zelikman et al., 2022; Dong et al., 2023) avoided value estimation entirely by discarding all trajectories that did not succeed, sidestepping the credit assignment problem through data filtering rather than algorithmic design. Process Reward Models (Lightman et al., 2023; Wang et al., 2024a) *did* learn value-like functions, but as a separate, heuristically designed pipeline disconnected from policy optimization—a two-phase approach where the PRM was trained first and then used to guide search or provide rewards, rather than being learned jointly with the policy in a principled optimization framework.

OREO's insight is that **the value function is not an optional add-on for multi-step reasoning with sparse rewards—it is the essential mechanism for credit assignment**, and it should be learned jointly with the policy from the same data through a single, theoretically grounded objective. The value function `$V_\phi(s_t)$` answers the question "what is the expected future return from this intermediate state?" This quantity is what allows the system to distinguish between a token that occurs early in a successful trajectory (high value before and after: the token was fine, the eventual success is attributed to later steps) and a token that immediately precedes a value drop (the token likely introduced an error). No amount of clever reweighting of a trajectory-level loss can recover this information without estimating state-specific expected returns.

The significance of this move extends beyond raw performance numbers. It establishes that **credit assignment in reasoning is fundamentally a representation-learning problem**: you need a model that can read a partial solution and predict its eventual correctness, and that model needs to be rich enough to capture the semantic content of the reasoning state, not merely the policy's own log-probability distribution. The paper's comparison between explicit and implicit value functions (Section 5.3, Figure 1) provides direct evidence: the policy-derived implicit value function produces conservative advantage estimates that fail to distinguish correct from incorrect steps in harder problems, while the explicit value model—which processes the full reasoning prefix through a transformer—produces sharper, more accurate advantage estimates. The authors attribute this to the "softmax bottleneck" (Yang et al., 2017): the policy model's log-probability predictions at a given state are generated from a single hidden state through a linear head and softmax, constraining their expressiveness, while the value model encodes the entire state sequence through the full transformer stack.

This is a fundamental conceptual shift, not an incremental refinement. It changes the question from "how do we weight tokens in a trajectory-level loss?" to "how do we learn a state-value function that enables per-step credit assignment?"—and provides a principled answer via the soft Bellman Equation.

**Evidence:** The explicit vs. implicit value function comparison in Figure 1 shows the explicit value function detecting errors that the implicit function misses. The ablation in Table 5 shows that response-level OREO (which collapses to trajectory-level consistency, similar to DPO's telescoping) underperforms token-level OREO, confirming that per-state value estimation drives the gains. The test-time search results (Figures 3 and 4) show the explicit value model successfully guiding beam search and action selection, achieving up to 17.9% relative improvement over greedy decoding—a capability that the implicit value function lacks.

---

### Innovation 2: The Soft Bellman Equation as a Unifying Framework That Reveals DPO's Limitations

The paper makes a second conceptual contribution by **deriving DPO from the soft Bellman Equation and using the derivation to identify precisely which assumptions cause DPO to fail on multi-step reasoning**. This is not merely a theoretical exercise—it transforms a set of empirical observations ("DPO doesn't work well on math reasoning") into an analytically understood limitation with clear boundary conditions.

The derivation in Section 3.3 shows that DPO emerges from the same maximum-entropy RL framework as OREO, but with two additional steps: (1) telescoping the soft Bellman Equation across the entire trajectory, which sums all per-step consistency conditions into a single trajectory-level constraint and eliminates all intermediate state values from the equation, and (2) introducing the Bradley-Terry preference model, which assumes that the relative preference between two trajectories is determined by a softmax over their terminal rewards. These two steps together explain both of DPO's failure modes on reasoning tasks: the telescoping step removes credit assignment granularity (all tokens contribute equally to the sum), and the Bradley-Terry step forces the use of pairwise data even when scalar ground-truth rewards are available.

What makes this framing intellectually distinctive is that **it converts a "method A vs. method B" comparison into a spectrum defined by which terms of the soft Bellman Equation are enforced**. DPO enforces the equation only at `$t = 0$` (trajectory-level). Response-level OREO (the ablation in Section 4.2) enforces it at `$t = 0$` with a squared-error target rather than a Bradley-Terry comparison—removing the pairwise data requirement but keeping the credit assignment limitation. Token-level OREO enforces it at every timestep, enabling full credit assignment. The empirical results track this spectrum: response-level OREO underperforms token-level OREO (Table 5), demonstrating that the per-timestep enforcement—not just the removal of pairwise data—is necessary for the gains. KTO, which removes the pairwise requirement but keeps trajectory-level credit assignment, also underperforms (Table 1).

This reframing matters because it gives future work a clear diagnostic tool. Rather than asking "does method X work for reasoning?", researchers can ask "at what granularity does method X enforce the soft Bellman Equation, and does that granularity match the credit assignment needs of the task?" It also explains the conflicting results in the DPO-for-reasoning literature: DPO can sometimes improve reasoning (Chen et al., 2024a; Song et al., 2024) when the credit assignment problem is mild—e.g., when errors are distributed roughly uniformly across tokens rather than concentrated at specific steps—and can fail (Yuan et al., 2024; Chen et al., 2024b) when credit assignment is critical. The framework predicts *when* DPO will work, not just that it sometimes doesn't.

**Evidence:** The derivation in Section 3.3 and the loss variant ablation in Table 5, which shows the performance gradient from response-level to step-level to token-level OREO. DPO's underperformance relative to rejection sampling on MATH (Table 1) is consistent with the framework: on harder problems, credit assignment is more critical, and DPO's trajectory-level signal is insufficient.

### Innovation 3: Test-Time Search as a Free Byproduct of Joint Policy-Value Training

OREO's third distinctive contribution is the **realization that the value function trained for credit assignment during policy optimization doubles as a process reward model for test-time search, with no additional training, data collection, or heuristic design required**. This is not a new search algorithm—beam search and best-of-K are standard—but rather a novel argument about *where* the value function for search should come from and *how* it should be trained.

Prior work on process reward models (Lightman et al., 2023; Wang et al., 2024a; Luo et al., 2024) treats PRM training as an independent pipeline: collect or generate solution trajectories, segment them into steps, run Monte Carlo rollouts from each step to estimate success probabilities, and train a separate model to predict those probabilities. This involves substantial engineering—step segmentation heuristics, rollout budget allocation, data filtering—and produces a PRM that is disconnected from the policy optimization process. The PRM can guide search at inference time, but it does not directly improve the policy that generates the candidates being searched over.

OREO collapses this separation. The value model `$V_\phi$` is trained on the exact same objective that a Monte Carlo PRM approximates—estimating expected future return from a state—but does so jointly with the policy and without requiring explicit step segmentation or a separate rollout budget. The training signal comes from the same offline trajectories used for policy optimization: for each prefix `$s_t$` of a trajectory, the target is the actual outcome `$R_t$` minus the cumulative KL penalty. This is a natural byproduct of enforcing the soft Bellman Equation, not a separate training goal.

What makes this intellectually significant beyond the engineering convenience is that **it aligns the value function's training distribution with the policy's output distribution**. In standard PRM training, the PRM is trained on trajectories generated by some (possibly different) policy, creating a distribution shift when the PRM is later used to score outputs from an improved policy. OREO's value model is trained on the same trajectories as the policy and is updated at each training step alongside the policy, meaning it tracks the policy's evolving output distribution. This is a form of implicit on-policy value estimation without requiring online data collection.

The "for free" framing also changes the cost-benefit calculus for adopting RL-based reasoning improvement. In the standard two-phase approach, the cost of training a PRM is an additional investment that must be justified by the downstream benefits of test-time search. In OREO, the value model is a necessary component of the training algorithm itself—it cannot be omitted without losing the credit assignment mechanism. The test-time search capability is genuinely a free byproduct: you get it whether you plan to use it or not, and the marginal cost of using it at inference time is just the additional computation of running beam search.

**Evidence:** Figures 3 and 4 show the value model successfully guiding beam search and best-of-K action selection, with performance scaling with compute budget—the hallmark of a well-calibrated value function. The comparison in Section 5.3 shows the explicit value function producing sharper advantage estimates than the policy-derived implicit value, confirming that the joint training produces a value model that is informative beyond what the policy alone captures. The paper explicitly connects this to prior PRM work by noting that Monte Carlo rollout supervision "is a special case of the value function learned through our method" (Section 2.2).

---

### Innovation 4: Learning from Failures as the Mechanism for Avoiding Saturation in Iterative Training

The fourth insight is more empirical than theoretical, but it has important implications for how iterative self-improvement pipelines should be designed. The paper demonstrates that **the ability to learn from failed trajectories—not just successful ones—is what enables continued improvement across multiple iterations of training, while rejection sampling saturates**.

In the iterative setting (Section 5.2, Figure 2), rejection sampling shows the classic pattern of a method that only learns from successes: it improves in the first iteration (more training data from a better policy), improves less in the second, and plateaus by the third. This is because each iteration increases the policy's success rate, which reduces the number of failures—but those failures contain the information about where the policy still makes mistakes. As the failure rate drops, rejection sampling has fewer training examples and sees diminishing returns.

OREO does not saturate because **failures are not discarded—they are training data for the value function**. Even when the policy's success rate is high (say, 70%), the remaining 30% of trajectories are failures that the value function can learn from: it observes which states lead to eventual failure and adjusts its predictions accordingly, which in turn provides credit assignment signals to the policy. Each iteration produces new failure patterns (the policy makes different mistakes as it improves), and OREO can learn from all of them.

This finding reframes the role of negative data in iterative self-improvement. Prior work on self-training for reasoning (Zelikman et al., 2022; Singh et al., 2023) focused on generating high-quality positive examples—correct solutions that could be used for supervised fine-tuning. OREO's results suggest that **negative examples are equally valuable, but only if the training algorithm can extract per-state credit assignment signals from them**. A trajectory-level method (DPO, KTO) can use negative examples but cannot localize the error; a positive-only method (rejection sampling) cannot use negative examples at all. OREO's value function provides the mechanism to extract useful signal from failure trajectories by identifying *where* the failure occurred.

This is not merely an incremental improvement over rejection sampling—it represents a different philosophy about what constitutes useful training data. In the rejection sampling paradigm, a trajectory is useful if and only if it succeeds. In the OREO paradigm, every trajectory—success or failure—provides signal, because every prefix `$s_t$` has a known outcome `$R_t$` that can be used to train the value function and, through the soft Bellman consistency, the policy. This is a fundamental shift from "filter then train" to "train on everything with credit assignment."

**Evidence:** Figure 2 shows OREO continuing to improve across three iterations while rejection sampling plateaus. Table 1 shows OREO outperforming rejection sampling in single-round training, and the paper attributes the iterative gains to "its ability to effectively learn from failed trajectories" (Section 5.2). The ALFWorld results in Table 2 provide additional evidence: in unseen environments where the policy's initial success rate is low and failures are abundant, OREO achieves a 17.7% relative improvement over SFT, while rejection sampling shows only marginal gains—consistent with OREO extracting value from the many failure trajectories that rejection sampling cannot use.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The paper uses three datasets across two task types. For mathematical reasoning: GSM8K (Cobbe et al., 2021) with 7,473 training and 1,319 test problems, and MATH (Hendrycks et al., 2021) with 7,500 training and 5,000 test problems, both labeled with step-by-step ground-truth solutions. For embodied agent control: ALFWorld (Shridhar et al., 2020), using 3,119 training trajectories with rationales annotated by Song et al. (2024) and evaluation on 140 seen-environment tasks and 134 unseen-environment tasks. For test-time search experiments, a subset of MATH containing 500 queries (MATH500) is used, following Lightman et al. (2023).

- **Base model(s).** For math reasoning: Qwen2.5-Math-1.5B (Yang et al., 2024) and DeepSeekMath-7B-Instruct (Shao et al., 2024). For embodied agent tasks: MiniCPM-2B-dpo-bf16 (Hu et al., 2024). The Qwen2.5-Math-1.5B is chosen to demonstrate effectiveness at a small, accessible scale; DeepSeekMath-7B-Instruct represents a stronger, instruction-tuned baseline that has already been heavily optimized (776K SFT samples); MiniCPM-2B provides a small model for agent tasks.

- **Metrics.** For GSM8K and MATH: accuracy, measured as the percentage of test problems where the extracted final answer matches the ground truth using the evaluation script from DeepSeekMath. For ALFWorld: success rate, measured as the percentage of tasks completed within 40 steps. For MATH500 test-time search: accuracy on the 500-question subset.

- **Baselines.** Five baselines are compared:
  - **SFT**: supervised fine-tuning on the training datasets (for Qwen2.5-Math-1.5B, trained on GSM8K and MATH for 3 epochs; for DeepSeekMath-7B-Instruct, the model is already instruction-tuned so no additional SFT is performed; for MiniCPM-2B, trained on the annotated ALFWorld data for 2 epochs).
  - **Rejection Sampling** (also known as STaR/RFT/ReST/ReST$^{EM}$; Zelikman et al., 2022; Dong et al., 2023; Gulcehre et al., 2023; Singh et al., 2023): fine-tune the SFT model on only the successful trajectories from the offline dataset.
  - **DPO** (Rafailov et al., 2024b): trained on pairwise preference data constructed from correct and incorrect trajectories for the same query.
  - **KTO** (Ethayarajh et al., 2024): a DPO variant that works with unpaired data, labeling examples as desirable or undesirable.
  - **DQO** (Liu et al., 2024a): a concurrent work using a similar maximum-entropy RL approach; compared in Appendix C, Table 3.

- **Generation budget / compute accounting.** The paper does not measure test-time compute in FLOPs or generations as a budget—this is a *training method* paper, not a test-time scaling paper. The main results compare methods at equal training data (same offline datasets, same number of epochs or total samples). For the test-time search experiments (Section 5.4), compute is measured by beam width `$B$` (number of beams maintained) or `$K$` (number of actions sampled per step), with accuracy reported as a function of this budget.

- **Cross-validation / statistical protocol.** No cross-validation or statistical significance testing is reported. All main results (Tables 1–3) are single-run evaluations on the standard test sets. The iterative training experiment (Figure 2) reports per-iteration test accuracy without error bars. The absence of uncertainty quantification is a genuine limitation—with MATH having 5,000 test questions, a 1–2% accuracy difference may or may not be statistically significant, and the paper does not provide the information needed to assess this.

- **Dataset construction for offline RL.** For 1.5B model experiments: 10 responses are sampled per query for GSM8K and MATH; only trajectories with correct answers receive reward 1. For DPO, up to 6 correct-incorrect pairs are sampled without replacement per query. For 7B models: 16 responses are sampled per query, with at most 4 positive and 4 negative instances selected (enforcing that positives do not exceed negatives, with at least 1 positive if any exist); for DPO, up to 10 pairs are sampled. For ALFWorld: 5 rollouts per training task, with up to 5 preference pairs for DPO.

- **Hyperparameter overview.** All experiments use batch size 128. SFT uses learning rate `$2 \times 10^{-5}$` and 2–3 epochs. Rejection sampling uses learning rate `$5 \times 10^{-6}$` (math) or `$2 \times 10^{-5}$` (ALFWorld), 1 epoch. DPO uses learning rate `$5 \times 10^{-7}$`, `$\beta = 0.1$`, 1 epoch. KTO uses learning rates of `$5 \times 10^{-8}$` (1.5B, 1 epoch) and `$10^{-7}$` (7B, 2 epochs). OREO uses learning rate `$5 \times 10^{-6}$`, `$\beta = 0.03$`, `$\alpha = 0.01$`, 1–3 epochs depending on model size. For 7B models, LoRA (rank 64, alpha 64) is applied to the value model with critic learning rate `$10^{-4}$`. Full details in Appendix A.3.

### Main Quantitative Results

#### Mathematical Reasoning: Offline Training (Table 1)

The central result compares OREO against four baselines on GSM8K and MATH across two model families. On Qwen2.5-Math-1.5B: OREO achieves 77.3% on GSM8K (vs. 73.5% SFT, a 5.2% relative improvement) and 52.5% on MATH (vs. 47.5% SFT, a 10.5% relative improvement). Rejection sampling reaches 74.9% and 50.3% respectively; DPO reaches 74.4% and 49.2%; KTO reaches 73.4% and 48.3%. OREO's margin over the strongest baseline (rejection sampling) is 2.4 points on GSM8K and 2.2 points on MATH.

On DeepSeekMath-7B-Instruct—a model already heavily instruction-tuned on 776K samples (Shao et al., 2024)—the baseline SFT accuracy is 82.9% on GSM8K and 46.8% on MATH. OREO reaches 85.9% on GSM8K (a 3.6% relative improvement) and 49.2% on MATH (a 5.1% relative improvement). Rejection sampling achieves 83.6% and 47.2%; DPO achieves 82.4% and 47.2%; KTO achieves 82.5% and 46.9%.

Two patterns stand out. First, DPO underperforms rejection sampling on GSM8K (74.4% vs. 74.9% for 1.5B; 82.4% vs. 83.6% for 7B) and is roughly tied on MATH. This is consistent with prior findings that DPO is not reliably better than rejection sampling for reasoning tasks (Yuan et al., 2024; Chen et al., 2024b). Second, KTO performs slightly *worse* than SFT on the 7B model for MATH (46.9% vs. 46.8%—essentially tied), and underperforms SFT on GSM8K for the 1.5B model (73.4% vs. 73.5%—also tied). Removing the pairwise requirement (KTO vs. DPO) provides no consistent improvement, suggesting the credit assignment problem, not data format, is the binding constraint.

#### Embodied Agent Control: ALFWorld (Table 2)

On ALFWorld, OREO achieves 79.1% success rate in unseen environments and 80.7% in seen environments. The SFT baseline achieves 67.2% and 62.9% respectively. Rejection sampling achieves 68.7% and 79.3%—performing well in seen environments (close to OREO's 80.7%) but poorly in unseen environments (68.7%, a 10.4-point gap to OREO). DPO achieves 69.4% and 64.3%.

The key finding is the differential performance in unseen environments. Rejection sampling improves only marginally over SFT (68.7% vs. 67.2%, a 2.2% relative improvement), consistent with the hypothesis that it cannot generalize beyond the success patterns seen in training. OREO achieves a 17.7% relative improvement over SFT (79.1% vs. 67.2%), which the paper attributes to learning from failed trajectories: "OREO effectively leverages the failed trajectories, which results in more generalizable capabilities" (Section 5.1). This is the strongest evidence that failure-trajectory learning provides benefits beyond what rejection sampling can achieve, particularly in settings where the training and test distributions differ.

#### Loss Variants: Token-Level vs. Step-Level vs. Response-Level (Table 5, Section 5.1)

The paper ablates the granularity of the soft Bellman Equation enforcement by training OREO variants on Qwen2.5-Math-1.5B. The token-level variant (standard OREO) is the baseline. Step-level OREO (actions are entire reasoning steps, delimited by line breaks and periods) performs comparably—slightly better on GSM8K and slightly worse on MATH—which the paper suggests may be due to "the value function's limited accuracy at each step, which introduces noise into policy learning" (Section 5.1). Response-level OREO (enforcing consistency only at `$s_0$`, analogous to DPO's telescoping) performs worse than both, confirming that per-step or per-token enforcement is necessary for the observed gains.

This ablation directly isolates the credit assignment mechanism. Response-level OREO still benefits from joint policy-value training and from using unpaired data—it is strictly more capable than DPO in terms of data format—but loses the per-state credit assignment. Its underperformance demonstrates that the credit assignment granularity, not just the removal of pairwise data or the addition of a value function, is responsible for OREO's advantage.

#### Iterative Training (Figure 2)

On both GSM8K and MATH with the 1.5B model, OREO shows consistent improvement across three iterations, with accuracy increasing at each round. Rejection sampling also improves in the first iteration and more modestly in the second, but shows clear saturation by the third—the curve flattens. The gap between OREO and rejection sampling widens with each iteration.

The paper's explanation is that OREO "continues to improve, likely due to its ability to effectively learn from failed trajectories" and that "the updated policy model in each new iteration may be able to explore novel failure patterns, and incorporate these insights into the learning process" (Section 5.2). Rejection sampling, by contrast, only learns from successes—as the policy improves and the success rate rises, fewer failure trajectories exist, but those that remain represent the hardest cases that rejection sampling cannot learn from.

The key limitation of this experiment is that all iterative training uses the 1.5B model only. It is unclear whether the iterative advantage persists at larger scales or whether rejection sampling's saturation point shifts with model size. Additionally, the paper does not report the computational cost of each iteration (data collection, retraining), making it difficult to assess whether iterative OREO is more compute-efficient than, say, a single round of OREO with more data or a larger model.

#### Test-Time Search with the Value Function (Figures 3 and 4)

For math reasoning (Figure 3): on GSM8K and MATH500 with the 1.5B model, step-level beam search guided by OREO's value function `$V_\phi$` shows monotonically increasing accuracy with beam width `$B$`. On GSM8K, accuracy improves from the greedy decoding baseline (beam width 1) to `$B = 7$`, achieving an 11.4% relative improvement. On MATH500, the relative improvement is 17.9%. The improvement curve shows diminishing returns—the gain from `$B=1$` to `$B=3$` is larger than from `$B=3$` to `$B=5$`, and further to `$B=7$`.

Rejection sampling ("Rej." in Figure 3) is also shown with beam search for comparison, but the paper does not report whether rejection sampling uses the same value model or a different one—this is ambiguous in the figure and text. If rejection sampling uses the same `$V_\phi$`, the accuracy difference reflects the policy quality (OREO's policy produces better candidates for the value model to select among). If rejection sampling uses no value model or a different one, the comparison is confounded.

For embodied agent tasks (Figure 4): best-of-K action selection using the value function shows rapid improvement on ALFWorld success rates as `$K$` increases from 1 to 5, with stabilization around `$K = 5$`. This is a simpler test-time intervention than beam search—at each step, sample K actions, pick the one with highest `$V_\phi$`—and demonstrates the value function's utility even without full tree search.

The paper emphasizes that these search capabilities come "for free"—the value model is trained during OREO optimization and requires no additional data or training for test-time use. The value model is a necessary component of OREO's credit assignment mechanism; its test-time utility is a byproduct.

#### Explicit vs. Implicit Value Functions (Figure 1, Section 5.3)

The paper presents qualitative case studies comparing the explicit value function `$V_\phi$` (OREO's value model) with the implicit value function derivable from the policy model `$\pi_\theta$` (following Rafailov et al., 2024a). The implicit advantage of a reasoning step (tokens `$i$` through `$j$`) is computed as the sum of per-token log-ratios: `$A_\theta = \sum_{t=i}^{j-1} \beta \log \frac{\pi_\theta(a_t|s_t)}{\pi_{\text{ref}}(a_t|s_t)}$`. The explicit advantage is `$A_\phi = V_\phi(s_j) - V_\phi(s_i)$`.

Two examples are shown. In a GSM8K problem involving money calculation, an incorrect step ("Betty now has $50 + $30 = $80") causes the explicit value to drop from 0.816 to 0.385 (advantage = -0.431), correctly flagging the error. The implicit advantage is "much more conservative" and produces a weaker signal. In a more challenging MATH problem, `$A_\phi$` successfully identifies the correct reasoning step, while `$A_\theta$` fails—both advantages correctly favor the correct step in the GSM8K example, but only the explicit advantage generalizes to the harder case.

The paper hypothesizes this gap arises from the softmax bottleneck (Yang et al., 2017): the policy's log-probability predictions for all tokens at a given state share the same final hidden state, differing only by a linear head and softmax, constraining their capacity to represent state-specific value. The value model processes the full reasoning prefix through the transformer stack, enabling richer representations.

This comparison is qualitative (two cherry-picked examples) and lacks quantitative metrics (e.g., accuracy of error detection across many steps, correlation between advantage and actual correctness). The claim that the explicit value function "successfully identifies the correct reasoning step" while the implicit one fails is based on visual inspection of the examples, not on a systematic evaluation. This is not a weakness per se—the paper presents these as illustrative case studies, not as a formal evaluation—but the generality of the finding is unquantified.

#### Comparison to DQO (Appendix C, Table 3)

The paper reproduces DQO (Liu et al., 2024a), a concurrent maximum-entropy RL method, on the same 1.5B model and training data. OREO achieves 77.3% on GSM8K vs. DQO's 75.1%, and 52.5% on MATH vs. DQO's 49.4%. The paper notes that DQO is "not yet open-sourced" and that the reproduction uses the same training data—these results should be treated as approximate rather than definitive, but they suggest OREO's specific design choices (KL regularization term, stop-gradient, the PCL-based derivation rather than SAC-based) provide measurable benefits.

### Ablation Studies and Robustness Checks

- **Loss granularity (token vs. step vs. response)**: Response-level OREO underperforms token-level OREO, confirming that per-state enforcement of the soft Bellman Equation is necessary for the performance gains (Table 5, Section 5.1). Step-level OREO performs comparably to token-level, suggesting the critical granularity is at the reasoning-step level or finer; token-level is adopted as the standard for implementation simplicity.

- **KL regularization coefficient** `$\alpha$`: The paper sweeps `$\alpha \in \{0.01, 0.1, 0.3\}$` for the step-level and response-level variants and selects the best-performing value per variant (`$\alpha = 0.1$` for step-level, `$\alpha = 0.3$` for response-level; Appendix A.3). For token-level OREO, `$\alpha = 0.01$` is used. The sensitivity of performance to `$\alpha$` is not reported—we do not know whether small changes in this hyperparameter significantly affect results.

- **Value model representation capacity (1.5B full model vs. 7B LoRA)**: For 1.5B models, the value model is a full separate model (presumably the same architecture as the policy). For 7B models, LoRA with rank 64 is applied to save computation (Appendix A.3). The paper does not ablate whether the value model's capacity matters—would a full 7B value model outperform the LoRA version? This is an open question, and the LoRA approximation could limit the value function's accuracy at larger scales.

- **Number of training epochs**: For 1.5B models, OREO trains for 1 epoch; for 7B models, 2 epochs (to match total samples). The paper does not ablate epoch count to check for overfitting or undertraining. This is not a major concern since performance is measured on held-out test sets, but it means the reported results may not represent the optimal training duration.

- **DPO pair sampling strategy**: For 1.5B models, up to 6 pairs per query are sampled from 10 generated responses. For 7B models, up to 10 pairs from 16 responses. The paper does not evaluate whether DPO performance is sensitive to the number of pairs or the pairing strategy (random pairs vs. hardest-negative pairs vs. all pairs). This matters because DPO's underperformance could be partly attributable to suboptimal pair construction rather than to the inherent limitations of the algorithm.

- **Value function initialization**: The paper does not specify whether the value model `$V_\phi$` is initialized from the SFT checkpoint, from the base model, or randomly. For 7B models with LoRA, the base model for the value function is presumably the same as the policy base, but this is not explicitly stated. Initialization could affect training dynamics and final value function quality.

- **Robustness across model families**: The method is tested on Qwen2.5-Math-1.5B, DeepSeekMath-7B-Instruct, and MiniCPM-2B—three different model families—and shows consistent improvement across all three (Tables 1 and 2). This provides some evidence of generality, though all models are in the 1.5B–7B range and from Chinese LLM families (Qwen, DeepSeek, MiniCPM). Testing on Western model families (Llama, Mistral, Gemma) would strengthen the generality claim.

### Critical Assessment

The experiments support the paper's central claims with a few important caveats.

**Claim 1: OREO outperforms existing offline learning methods on multi-step reasoning.** This is supported by Tables 1 and 2: OREO achieves higher accuracy/success rate than SFT, rejection sampling, DPO, and KTO across GSM8K, MATH, and ALFWorld on three model families. The margins are consistent (2–10 percentage points over the next-best baseline) and appear across both math and embodied agent tasks. The comparison to DQO in Appendix C (Table 3) suggests OREO outperforms the closest concurrent method. However, the absolute improvements are relatively modest—on the 7B model, OREO improves MATH from 46.8% to 49.2% (a 5.1% relative gain, or 2.4 absolute points). Whether this improvement justifies the additional complexity of training a value model, tuning two extra hyperparameters (`$\beta$`, `$\alpha$`), and running joint optimization depends on the practitioner's cost-benefit calculus. For some applications, the simpler rejection sampling baseline (47.2% on MATH with the 7B model, only 2 points below OREO) may be preferable.

**Claim 2: The value function provides effective credit assignment that DPO lacks.** The loss variant ablation (Table 5) is the primary evidence: response-level OREO (which uses the same joint policy-value training but enforces the Bellman equation only at `$s_0$`) underperforms token-level OREO. This isolates the effect of per-state enforcement—removing it degrades performance, confirming that token- or step-level credit assignment matters. However, the ablation does not directly compare OREO against a hypothetical "DPO with value function"—it compares OREO variants against each other and against standard DPO. The claim that DPO's failure is specifically due to credit assignment (rather than, say, the Bradley-Terry assumption, the pairwise data format, or optimization difficulties) is supported by the analytical derivation (Section 3.3) and by the response-level OREO result, but a direct experiment modifying DPO to incorporate a value function while keeping other aspects fixed would be more conclusive.

**Claim 3: OREO can learn from failed trajectories, unlike rejection sampling.** The strongest evidence is the ALFWorld result (Table 2): in unseen environments, rejection sampling improves only marginally over SFT (68.7% vs. 67.2%), while OREO achieves 79.1%—a large gap that is consistent with learning from failure trajectories providing generalization benefits. The iterative training results (Figure 2) provide supporting evidence: rejection sampling saturates while OREO continues to improve, again consistent with failure-trajectory learning. However, the paper does not provide a direct ablation that isolates failure-trajectory learning—for example, training OREO only on successful trajectories (as an ablation, to verify that the performance drops to rejection-sampling levels). Such an ablation would definitively establish that failures, not some other aspect of OREO's training, drive the gains.

**Claim 4: Test-time search with the learned value function provides substantial improvements at no additional training cost.** Figures 3 and 4 support this: beam search with `$B=7$` provides 11.4% (GSM8K) and 17.9% (MATH) relative improvements over greedy decoding. However, these results are only reported for the 1.5B model on MATH500 (a 500-question subset, not the full 5,000-question MATH test set). The full MATH results for the 1.5B and 7B models with beam search are not reported. This is a significant omission—the test-time search is presented as a key contribution, but its evaluation is limited to a small model on a small test subset. Whether the value function from a 7B OREO-trained model provides similar or better beam search improvements is unknown. Additionally, the paper does not compare the value-guided beam search against alternative test-time strategies (majority voting, best-of-N with an outcome reward model, or PRM-guided search from prior work), so the claim that the value function is "highly effective" is relative to greedy decoding only.

**Claim 5: Iterative OREO continues to improve while baselines saturate.** Figure 2 supports this for the 1.5B model over 3 iterations. The evidence is clear but limited: one model size, three iterations, two datasets. The computational cost of iterative training is not reported—each iteration requires generating new trajectories, labeling them, and retraining—so the efficiency of iterative OREO relative to, say, training OREO once with more data or for more epochs is unclear. The saturation of rejection sampling also depends on how much data is collected per iteration; with more aggressive data collection, rejection sampling might continue improving. The paper does not explore this dimension.

**Genuine weaknesses and missing experiments:**

- **Single-run evaluations without uncertainty quantification:** All main results are reported as point estimates without confidence intervals, standard deviations, or significance tests. With MATH's 5,000-question test set, a 1–2% absolute difference may or may not be statistically reliable. The iterative training results (Figure 2), which involve multiple rounds of data collection and retraining, are especially vulnerable to run-to-run variance. Reporting means and standard deviations over multiple training seeds would substantially strengthen the evidence.

- **MATH500 for test-time search is a 500-question subset, not the full test set:** The 17.9% relative improvement on MATH with beam search is computed on this subset, not on the full 5,000-question MATH test set. The 1.5B model achieves 52.5% on the full MATH set (Table 1), but the beam search result is on MATH500—these numbers are not directly comparable. The paper also does not clarify whether MATH500 is a random subset or a specific subset; if it is a specific benchmark split, it may have different difficulty characteristics than the full MATH set.

- **No baseline for test-time search:** The beam search results (Figure 3) compare against greedy decoding only. Missing comparisons include: majority voting at the same compute budget, best-of-N sampling with the same policy, and PRM-guided search using a separately trained process reward model. Without these, we cannot assess whether the value function is a *good* search heuristic or merely a *non-zero* one. The fact that accuracy improves with beam width is expected for any non-random scoring function; the relevant question is whether OREO's value function is better than alternatives, and this is not tested.

- **No combination with PRM-style search algorithms:** The paper frames the value function as an alternative to PRM training but does not evaluate whether combining the value function with more sophisticated search algorithms (MCTS, weighted best-of-N) outperforms simple beam search. The test-time search results are a proof of concept, not a thorough evaluation of the value function's search capabilities.

- **Limited scale:** All iterative and test-time search experiments use the 1.5B model. The main results include a 7B model, but only for single-round training on math reasoning. ALFWorld uses a 2B model. The paper does not test whether OREO's advantages scale to larger models (13B, 70B) or whether the value function quality degrades or improves with scale.

- **No hyperparameter sensitivity analysis:** The values of `$\beta$`, `$\alpha$`, and the learning rates are reported but not ablated (except for `$\alpha$` across variants). We do not know whether OREO's performance is robust to these choices or whether extensive tuning was required to achieve the reported results. Given that OREO introduces two new hyperparameters beyond standard SFT (`$\beta$` and `$\alpha$`), this is a practical concern for adoption.

- **Data construction details matter but are not ablated:** The number of samples per query (10 for 1.5B, 16 for 7B), the pair sampling strategy for DPO, and the train/test splits are fixed. The paper does not explore whether OREO's advantage over baselines is sensitive to data quantity or construction. If OREO requires more data per query than rejection sampling (which is plausible, since it uses both positive and negative trajectories), the comparison at equal data *quantity* may not reflect equal data *collection cost*.

- **The explicit vs. implicit value function comparison is qualitative and anecdotal:** Figure 1 shows two examples where the explicit value function works better than the implicit one. This is an existence proof, not a systematic comparison. A quantitative evaluation—e.g., using value function predictions to classify correct vs. incorrect reasoning steps across many trajectories, and comparing accuracy/F1 of explicit vs. implicit—would be more informative. The softmax bottleneck hypothesis is plausible but untested.

In summary, the experimental evidence supports the paper's core claims—OREO outperforms existing offline methods, the per-state credit assignment matters, the value function enables test-time search—but the support for each claim has specific limitations. The main results on offline training (Tables 1 and 2) are the strongest and most complete. The iterative training and test-time search results are limited to a single model scale and lack important baselines. The credit assignment evidence relies on loss variant ablations and qualitative case studies rather than direct measurement of credit assignment quality. None of these limitations invalidate the claims, but they bound their generality and practical applicability more tightly than the paper's framing might suggest.

## 6. Limitations and Trade-offs

### The Difficulty Estimation Cost Is Unaccounted for and Potentially Dominates the Inference Budget

**The assumption or constraint.** OREO trains a value function `$V_\phi$` to estimate expected future reward from any intermediate reasoning state, which provides the credit assignment signal that the paper argues is essential for multi-step reasoning. However, this value function's accuracy is not guaranteed out-of-distribution—it is trained on states encountered in the offline dataset, which are generated by a specific policy (the initial SFT model or the policy from the previous iteration). As the policy is updated during training, it may visit states that were rare or absent in the training data, and the value function's predictions on those states may be unreliable.

The paper does not directly address this distribution shift problem in its main analysis. The offline RL literature has long recognized that value function overestimation on out-of-distribution states is a central failure mode of offline actor-critic methods (Kumar et al., 2022; Levine et al., 2020). OREO relies on KL regularization to keep the policy close to the reference `$\pi_{\text{ref}}$`, which should limit distribution shift, but does not explicitly measure or bound the shift.

**The consequence.** If the value function overestimates the expected return from a novel state—predicting high value for a partial solution that the policy would not actually be able to complete correctly—the policy will be encouraged to take actions leading to that state, which may degrade performance. Conversely, if the value function underestimates, valid reasoning paths may be incorrectly penalized. This is the classic "deadly triad" of RL (bootstrapping, function approximation, off-policy learning), made more acute by the large state space of natural language and the limited coverage of offline data.

The soft Bellman consistency objective (Equation 9) includes a stop-gradient on future terms, which means the policy update at step `$t$` treats the value at `$s_{t+1}$` as fixed. If `$V_\phi(s_{t+1})$` is inaccurate, the policy's gradient for `$\log \pi_\theta(a_t | s_t)$` will push it in the wrong direction. The value model and policy are trained jointly, so errors can compound: an inaccurate value model leads to a degraded policy, which generates trajectories that are further from the training distribution, making the value model even less accurate on the next training batch.

**What evidence exists in the paper.** The paper does not measure distribution shift or value function calibration on held-out states. There is no evaluation of the value function's prediction error as a function of state novelty (e.g., measured by how many times a similar state appeared in the training data). The ablation of step-level vs. token-level OREO (Table 5, Section 5.1) notes that step-level "may be due to the value function's limited accuracy at each step, which introduces noise into policy learning," suggesting the value function is not perfectly reliable even in-distribution. The test-time search results (Figure 3) provide indirect evidence: the value function successfully guides beam search, producing monotonic accuracy gains with beam width, which suggests it is at least somewhat accurate. But this is on the same test distribution as the training problems—it does not test generalization to harder or different problems.

The iterative training results (Figure 2) provide the strongest implicit evidence that distribution shift is managed: OREO improves across three iterations, which requires that the value function remain informative about the updated policy's outputs. However, the KL penalty `$\beta = 0.03$` and the additional regularization `$\alpha = 0.01$` are fixed hyperparameters, and their sufficiency for preventing value function degradation is not ablated across a range of shift magnitudes.

**Mitigation status.** The paper partially addresses this through the KL regularization terms, following standard practice in RLHF (Ouyang et al., 2022) and maximum-entropy RL (Haarnoja et al., 2018). The KL penalty discourages the policy from moving to states where the value function's estimates are unreliable, and the explicit `$\mathcal{L}_{\text{reg}}$` term in Equation 9 provides additional regularization. The iterative training procedure provides some natural mitigation: each iteration collects new trajectories from the current policy, expanding the training data to cover states that the policy actually visits.

However, these are indirect and untested mitigations. The paper does not compare the value function's predictions against Monte Carlo rollout estimates to measure accuracy, does not ablate the KL coefficient `$\beta$` to check sensitivity, and does not evaluate whether value function errors correlate with performance degradation. The slogan that the explicit value function "enables better credit assignment" (Section 5.3) is supported only by two qualitative examples (Figure 1) showing the value function correctly identifies errors—but we do not know its false positive rate (flagging correct steps as errors) or how it performs on harder problems where the policy is less capable.

A practitioner would want to know: does the value function's accuracy degrade significantly after several rounds of OREO training, and if so, does this limit the achievable performance improvement? The paper provides no systematic answer, leaving this as a significant open risk for deployment.

### All Iterative and Test-Time Search Results Are Limited to 1.5B Models, with No Evidence of Scaling Behavior

**The assumption or constraint.** The paper evaluates the iterative training framework (Section 5.2, Figure 2) and the test-time search with the learned value function (Section 5.4, Figures 3 and 4) exclusively on the Qwen2.5-Math-1.5B model. The main offline training results (Tables 1 and 2) include a 7B model (DeepSeekMath-7B-Instruct) and a 2B model (MiniCPM-2B) for single-round training, but the iterative and search results—which are presented as key contributions in the abstract, introduction, and Section 4—are never tested beyond the 1.5B scale. The paper acknowledges this directly in its limitations section:

> "Due to limited computation resources, some of our experiments, including ablation studies, iterative OREO, and test-times search, use 1.5B models. We plan to run experiments on larger scales in the future." (Section 7)

**The consequence.** This is a critical gap because two of the paper's three headline claims depend on these experiments. The iterative training claim—that OREO "continues to improve, likely due to its ability to effectively learn from failed trajectories" while rejection sampling saturates (Section 5.2)—is demonstrated only at 1.5B. The test-time search claim—that "our value function can be used in test-time search to improve the model performance" with up to a 17.9% relative improvement (Abstract, Section 5.4)—is also 1.5B-only.

There are reasons to expect scaling behavior might differ. Larger models have different base accuracy profiles (e.g., DeepSeekMath-7B achieves 82.9% on GSM8K vs. 73.5% for the 1.5B), which affects the distribution of correct vs. incorrect trajectories in the training data—the higher the base accuracy, the fewer failure trajectories exist to learn from. The value function's quality may also depend on model capacity: for 7B models, the paper uses LoRA with rank 64 for the value model to save computation (Appendix A.3), which constrains its representational capacity relative to a full 7B value model. Whether the value function learned through a LoRA adapter retains sufficient accuracy to guide beam search effectively at larger scales is unmeasured.

If the iterative gains or test-time search improvements do not scale to larger models, the practical significance of OREO is substantially reduced. The offline training gains on 7B models are positive but modest—49.2% vs. 47.2% for rejection sampling on MATH (Table 1), a 2.0-point absolute improvement. The bulk of OREO's claimed advantage comes from these unscaled experiments. A practitioner deciding whether to adopt OREO for a production 7B or larger model would not know whether the iterative or search benefits materialize.

**What evidence exists in the paper.** The single-round offline training results at 7B (Table 1) provide the only evidence beyond 1.5B, showing OREO outperforms baselines by 1.4--2.0 points on MATH and 2.3--3.5 points on GSM8K. These are consistent with the 1.5B results' direction but smaller in relative terms. The 7B model was not tested iteratively, and no beam search results are reported for 7B. The ALFWorld experiments use a 2B model for single-round training only—no iterative or search results are reported.

The paper does not report any experiments that would directly test scaling behavior: no 7B iterative training, no 7B test-time search, no comparison of value function accuracy (e.g., prediction vs. Monte Carlo rollout) across model sizes.

**Mitigation status.** None within the paper—the authors flag it as a limitation and defer to future work. The open-sourced code may enable the community to run these experiments, but the paper provides no guidance on whether the same hyperparameters (`$\beta = 0.03$`, `$\alpha = 0.01$`, learning rates) transfer to larger scales or whether the LoRA rank of 64 is sufficient for the value model at 7B+. A practitioner attempting to scale OREO would need to re-tune these hyperparameters without guidance from the paper.

### OREO Introduces Two Additional Hyperparameters (`$\beta$`, `$\alpha$`) and Joint Training Dynamics That Are Not Robustness-Tested

**The assumption or constraint.** OREO's training objective (Equations 8 and 9) introduces two hyperparameters beyond what standard SFT or rejection sampling requires: `$\beta$`, which controls the strength of the KL penalty in the soft Bellman Equation, and `$\alpha$`, which weights an additional explicit KL regularization term. The paper sets `$\beta = 0.03$` and `$\alpha = 0.01$` for the standard token-level OREO, with different values for the step-level (`$\alpha = 0.1$`) and response-level (`$\alpha = 0.3$`) variants (Appendix A.3).

Additionally, the value model introduces a separate optimizer with its own learning rate (`$10^{-4}$` for the 7B LoRA critic, vs. `$5 \times 10^{-6}$` for the policy), and the training dynamics involve two interacting models being optimized simultaneously from the same data—a regime where stability can depend on relative learning rates, batch composition, and initialization.

**The consequence.** The paper presents OREO's results as point estimates from what appears to be a single hyperparameter configuration per model size and task. There is no hyperparameter sensitivity analysis—no sweep over `$\beta$` or `$\alpha$` values, no report of how performance varies as these parameters change. A practitioner trying to apply OREO to a new model, dataset, or task would need to re-tune these parameters without guidance on reasonable ranges, sensitivity, or tuning strategy.

This matters because `$\beta$` and `$\alpha$` control the fundamental tradeoff in OREO between reward optimization and staying close to the reference policy. If `$\beta$` is too small, the KL penalty is weak, and the policy may drift into regions where the value function is poorly estimated (exacerbating the distribution shift problem discussed above). If `$\beta$` is too large, the policy barely moves from the reference, and OREO reduces to SFT with extra computation. If `$\alpha$` is too small, the explicit regularization in Equation 9 provides insufficient stabilization. If it is too large, it may dominate the consistency loss and prevent the policy from learning.

The joint training of policy and value model adds further fragility. The value model's target (Equation 8) depends on the current policy's log-probabilities; the policy's target (Equation 9) depends on the value model's predictions. This is a moving-target problem where poor initialization or imbalance in learning rates can lead to divergence or collapse. The paper mentions that the regularization term `$\alpha \mathcal{L}_{\text{reg}}$` "helps stabilize training" (Section 4.1), but does not quantify how necessary it is or what happens without it.

**What evidence exists in the paper.** The only evidence of hyperparameter variation is for `$\alpha$` across the loss variants (Appendix A.3): the authors sweep `$\alpha \in \{0.01, 0.1, 0.3\}$` for step-level and response-level OREO and choose the best value per variant. For the main token-level OREO, `$\alpha = 0.01$` is used—the smallest value in the sweep range. There is no reported sweep for `$\beta$`, for the policy learning rate, for the critic learning rate, or for the interaction between these parameters.

The different optimal `$\alpha$` values across variants (0.01 for token-level, 0.1 for step-level, 0.3 for response-level) strongly suggest that `$\alpha$` is sensitive to the loss formulation. Since the step-level and response-level losses have different scales (the response-level sums over the entire trajectory, producing larger-magnitude loss values), this sensitivity is expected. But it means a practitioner applying token-level OREO to a new setting—with different trajectory lengths, different reward scales, or a different base model—cannot simply adopt `$\alpha = 0.01$` and expect optimal performance.

**Mitigation status.** None within the paper. The existence of these hyperparameters is acknowledged, and their values are reported (which is good practice for reproducibility), but there is no analysis of robustness, no guidance on tuning, and no ablation demonstrating that the reported gains are not contingent on specific hyperparameter values. The comparison to DQO in Appendix C (Table 3) shows OREO outperforming a similar method, which provides some reassurance that the specific design choices (including hyperparameters) matter positively, but does not address sensitivity.

### The Paper Does Not Evaluate Whether the Learned Value Function Is Actually Performing Credit Assignment, as Opposed to Providing Other Benefits

**The assumption or constraint.** The paper's central argument is that OREO outperforms DPO and rejection sampling because it "enables better credit assignment" (Section 5.3) and "enables finer-grained credit assignment" (Section 1) through per-step enforcement of the soft Bellman Equation. The value function `$V_\phi$` is posited to identify which tokens or steps in a trajectory contributed to success or failure, allowing the policy to be updated more intelligently than with a uniform trajectory-level signal.

**The consequence.** Despite this being the paper's core conceptual claim, there is no direct measurement of credit assignment quality. The paper provides:

1.  **Indirect evidence from loss variant ablations** (Table 5): response-level OREO (which collapses to trajectory-level consistency) underperforms token-level OREO. This shows that per-step enforcement matters, but it does not demonstrate *why*—the performance difference could arise from optimization dynamics, regularization effects, or other factors unrelated to credit assignment per se.

2.  **Qualitative case studies** (Figure 1, Section 5.3): two examples where the explicit value function's advantage estimates better distinguish correct from incorrect reasoning steps than the implicit (policy-derived) advantage function. This is an existence proof, not a systematic evaluation. We do not know the false positive rate (value function flags correct steps as errors), the false negative rate (value function misses actual errors), or how these rates compare to alternatives across the full test set.

3.  **Test-time search improvements** (Figures 3 and 4): the value function successfully guides beam search, selecting better partial trajectories than greedy decoding. This shows the value function contains useful signal, but does not isolate whether that signal specifically reflects *credit assignment* (distinguishing which past tokens caused success/failure) versus *state evaluation* (predicting final outcome from the current state, regardless of how the state was reached).

The distinction matters. A value function can predict final outcome accurately—"this partial solution looks like it's on the right track"—without providing differential credit to individual past actions. The policy improvement from OREO could come primarily from learning a good state evaluation (which helps the policy by providing better targets in the consistency loss) rather than from fine-grained per-token credit assignment. If this alternative mechanism drives the gains, the paper's theoretical framing around credit assignment would be partially misaligned with the empirical mechanism.

**What evidence exists in the paper.** The loss variant ablation (Table 5) and the qualitative case studies (Figure 1). Both are suggestive but insufficient to establish the credit assignment mechanism conclusively.

To directly measure credit assignment, one would need experiments like: (a) take trajectories where a single step is corrupted to be incorrect, and measure whether the value function's predictions at surrounding states correctly localize the error; (b) compare the policy's per-token gradient magnitudes in OREO vs. response-level OREO vs. DPO, and verify that OREO assigns larger gradients to error tokens specifically; or (c) train OREO with the value model's credit assignment signals replaced by uniform weights and measure the performance drop. None of these are attempted.

**Mitigation status.** The paper does not explicitly claim to have *measured* credit assignment, only that the method *enables* it. The evidence presented is consistent with the credit assignment hypothesis but does not rule out alternative explanations. The authors do not acknowledge this as a limitation or propose methods for directly evaluating credit assignment quality. This is a gap between the theoretical motivation and the empirical validation that weakens the paper's explanatory power, even if the performance results stand on their own.

### The Benchmarks Are Narrow (Math Reasoning and Simulated Household Tasks Only), with No Testing on Code, Open-Ended Reasoning, or Interactive Domains

**The assumption or constraint.** The paper evaluates OREO on three datasets: GSM8K (grade-school math), MATH (competition math), and ALFWorld (text-based household agent simulation). The authors acknowledge this limitation:

> "Our method has primarily been evaluated on mathematical reasoning and embodied agent tasks. As future work, we aim to extend OREO to a wider variety of tasks, such as coding and web browsing, to explore its effectiveness in domains with different structures and requirements." (Section 7)

**The consequence.** All three benchmarks share structural properties that may favor OREO in ways that do not generalize. Math reasoning tasks (GSM8K, MATH) have deterministic ground-truth answers, well-defined reasoning steps with clear logical dependencies, and sparse binary rewards that are perfectly correlated with correctness—no ambiguity, no partial credit. ALFWorld tasks have clear success/failure criteria, relatively short trajectories (max 40 steps), and a constrained action space.

Several important reasoning domains lack these properties. Code generation tasks often have multiple valid solutions, partial credit is common (a program that compiles but fails some test cases is not fully wrong), and the reward signal may be multi-dimensional (correctness, efficiency, style). Open-ended reasoning tasks (essay writing, analysis, debate) have no ground-truth answers, making the sparse binary reward structure inapplicable. Web navigation tasks (Mind2Web, WebArena) have much longer trajectories, partial observability, and complex state spaces where the value function's credit assignment may be substantially harder.

The paper's framework assumes a sparse terminal reward that is known and objective. This assumption holds for the evaluated tasks but fails for a large class of practically important reasoning problems. Extending OREO to tasks with learned reward models (RLHF-style), with dense intermediate rewards, or with multiple reward components would require modifications to the training objective that are not explored.

**What evidence exists in the paper.** The consistent improvement across GSM8K, MATH, and ALFWorld (Tables 1 and 2) provides some evidence of generality *within these task families*, but all three are structurally similar in the ways described above. The paper's strongest result on ALFWorld unseen environments (79.1% vs. 67.2% SFT) demonstrates generalization to novel environment configurations, but within the same task structure and reward type.

The paper does not test on any code generation benchmark (HumanEval, MBPP, APPS), any scientific or logical reasoning benchmark (ARC, FOLIO, LogiQA), or any open-ended generation task. The absence of code evaluation is particularly notable because code generation is one of the most important applications of LLM reasoning and has natural sparse reward structure (unit tests), making it a direct candidate for OREO.

**Mitigation status.** The authors explicitly identify this as future work in Section 7 and give specific examples (coding, web browsing). This is appropriate transparency—the paper does not claim generality beyond the tested tasks. However, the abstract and introduction frame OREO broadly as a method for "enhancing LLM multi-step reasoning" without qualification, which could lead readers to assume broader applicability than has been demonstrated. A practitioner working on code generation or dialogue systems would need to verify independently whether OREO's mechanisms transfer to their domain.

### The Learned Value Function Is Compared Only Against Greedy Decoding for Test-Time Search, Not Against Standard Test-Time Scaling Baselines

**The assumption or constraint.** The test-time search experiments (Section 5.4, Figures 3 and 4) compare OREO's value-guided beam search against greedy decoding (beam width `$B=1$`) only. The paper claims that "this results in up to a 17.9% relative improvement over greedy decoding on the MATH dataset" (Abstract) and that "the explicit value function is more effective than the policy in distinguishing between correct and incorrect reasoning steps" (Section 5.4).

**The consequence.** The comparison against greedy decoding establishes only that the value function provides *some* useful signal—not that it is a *good* search heuristic relative to available alternatives. Several baselines are conspicuously absent:

- **Majority voting at the same generation budget.** Instead of beam search with `$B=7$` beams (which generates up to `$B^2 = 49$` candidate next steps per step), one could generate `$N$` complete solutions independently and take a majority vote on the final answer. This is the simplest test-time scaling baseline and requires no value function at all. If majority voting at comparable compute matches or exceeds the beam search improvement, the value function's contribution is redundant.

- **Best-of-N with an outcome reward model (ORM).** A separately trained ORM that scores complete solutions, used for best-of-N selection, is a standard test-time scaling method. The paper could compare beam search with `$V_\phi$` against best-of-N with the same policy and a comparable generation budget.

- **Best-of-N with the value function itself.** Instead of beam search, use `$V_\phi$` on the final state of each complete solution as an outcome scorer, then select the best solution. This would isolate whether the *search* aspect (building partial solutions incrementally) or the *value function* aspect (having a good scoring function) drives the improvement. If best-of-N with `$V_\phi$` performs similarly to beam search with `$V_\phi$`, then the beam search structure is unnecessary and the value function is merely a good outcome scorer.

- **Standard PRM-guided search.** Prior work (Lightman et al., 2023; Wang et al., 2024a) trains dedicated process reward models and uses them for search. Comparing OREO's value function against a separately trained PRM on the same policy would test whether joint training produces a better or worse value function than dedicated PRM training.

The paper's claim about the value function being "highly effective in guiding beam search" (Abstract) has no comparative anchor—we know it is better than random/greedy, but not whether it is better than simpler, cheaper, or standard alternatives.

**What evidence exists in the paper.** Figure 3 shows accuracy as a function of beam width for OREO and for rejection sampling ("Rej."). The meanings of the "Rej." curves are ambiguous—the paper does not clearly state whether rejection sampling uses the same `$V_\phi$` value model, a different value model, or no value model at all. If rejection sampling is using the same value function for beam search, the accuracy difference reflects policy quality (OREO's policy produces better candidates), not value function quality. If rejection sampling is using a different search mechanism or no search, the comparison is confounded. The paper's text says only that rejection sampling is shown "for comparison" (Figure 3 caption) without specifying what aspect is being compared.

Figure 4 (ALFWorld best-of-K) is compared only against the `$K=1$` baseline (greedy action selection). There is no comparison against alternative action selection strategies—e.g., sampling K actions and using the policy's own probabilities to select, or using a separately trained action-value model.

**Mitigation status.** None. The test-time search experiments are presented as strong evidence for the value function's utility, but the evidence supports only a minimal claim (the value function provides non-zero signal) rather than the stronger claim the paper makes (it is a "highly effective" search heuristic). This is the most significant missing evaluation in the paper, because it affects the practical takeaway for the test-time search contribution. A practitioner reading the paper might assume that using OREO's value function for beam search is a recommended best practice; in reality, they would need to compare it against simpler and cheaper baselines that the paper does not evaluate.
