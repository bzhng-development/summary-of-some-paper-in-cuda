# Sigma: Differential Rescaling of Query, Key and Value for Efficient Language Models

**ArXiv:** [2501.13629](https://arxiv.org/abs/2501.13629)

## 🎯 Pitch

This paper introduces **SIGMA**, an efficient large language model specialized for the system domain, built around a novel attention mechanism called **DiffQKV attention** that differentially rescales Query, Key, and Value components rather than treating them uniformly.

---

## 1. Executive Summary

This paper introduces **SIGMA**, an efficient large language model specialized for the system domain, built around a novel attention mechanism called **DiffQKV attention** that differentially rescales Query, Key, and Value components rather than treating them uniformly. The core design consists of two complementary strategies: **differentially compressed KV**—aggressively compressing Key heads and dimensions while lightly compressing Value heads, grounded in the empirical finding that model performance is far more sensitive to V compression than K compression—and **augmented Q**—expanding the Query head dimension to boost representational capacity with minimal inference cost since Q vectors are not cached. Through implementation of a custom FlexHeadFA kernel that decouples Key and Value head counts in FlashAttention, SIGMA achieves up to a **33.36% improvement in inference speed over conventional grouped-query attention (GQA)** in long-context scenarios, establishing that the benefits of differential KV treatment manifest primarily when prefix and output lengths are large—the efficiency crossover point shifts earlier as sequence length grows, with SIGMA outperforming GQA even without a prefix when generating 64k tokens.

## 2. Context and Motivation

### The Core Problem: The KV Cache Is the Primary Bottleneck for LLM Inference

The fundamental problem this paper tackles is deceptively simple: **the Key-Value (KV) cache in transformer-based large language models has become the dominant bottleneck for inference efficiency**, yet existing approaches treat the compression of Key and Value vectors uniformly despite their distinct functional roles in the attention mechanism.

To understand why this matters, we need to step back and understand what the KV cache is and why it creates such a severe bottleneck. In decoder-only transformer architectures (which include virtually all modern LLMs—GPT, LLaMA, Mistral, etc.), every decoding step requires attending to all previously generated tokens. Rather than recomputing the Key and Value projections for all past tokens at each step (which would be quadratically expensive), the standard practice is to **cache** these vectors in GPU memory once they are computed. At each new decoding step, only the newest token's K and V are computed, while all previous K and V vectors are simply loaded from memory and reused.

This caching strategy eliminates redundant computation but creates a different problem: **the KV cache grows linearly with sequence length**. For a model with $L$ layers, $H$ attention heads, head dimension $d_h$, and sequence length $s$, the KV cache consumes $2 \times L \times H \times d_h \times s$ floating-point numbers. In practical terms, Pope et al. (2023) showed that for long sequences, the KV cache can consume **more GPU memory than the model parameters themselves**. This isn't just a storage problem—it becomes a **memory bandwidth problem**. As Shazeer (2019) and Ribar et al. (2024) established, repeatedly loading these growing KV caches from memory to compute units places enormous demands on memory bandwidth, which is the true bottleneck for LLM inference speed.

The paper frames this clearly in Section 1:

> "KV cache is a common technique in the decoder-only Transformer architecture, which stores Key and Value vectors for future reuse in decoding. It can consume considerable GPU memory and place substantial demands on memory bandwidth."

This bandwidth bottleneck is particularly acute because modern GPUs have compute capabilities far exceeding their memory bandwidth—they can perform computations much faster than they can move data in and out of memory. This means inference is often **memory-bound, not compute-bound**. Any reduction in the size of data that must be loaded from memory translates directly to faster inference.

### Prior Approaches and Their Critical Limitation: Uniform KV Treatment

The research community has recognized the KV cache bottleneck and developed several categories of solutions. The paper situates itself relative to three broad approaches (detailed in Appendix A):

**Architectural compression (pre-training stage).** The most influential methods in this category are Multi-Query Attention (MQA) from Shazeer (2019) and Grouped-Query Attention (GQA) from Ainslie et al. (2023). MQA takes the extreme approach: all Query heads share a single Key head and a single Value head ($n_k = n_v = 1$). This reduces the KV cache size by a factor of $n_q$ (the number of Query heads), but it removes the model's ability to attend to different representational subspaces through different Key projections. GQA provides a middle ground: Query heads are organized into groups, with each group sharing one Key-Value head pair. For example, with 32 Query heads and 4 Key-Value heads, every 8 Query heads share one KV head, reducing the cache size by a factor of 4 while retaining some multi-head diversity.

Both MQA and GQA are widely adopted—GQA in particular is used in LLaMA 2, LLaMA 3, Mistral, and many other production models. But the paper identifies a specific, underexplored limitation:

> "most prior studies tend to treat the compression of K and V vectors uniformly, both in terms of the optimization methodology and the compression ratio."

In GQA and related methods, the number of Key heads always equals the number of Value heads ($n_k = n_v$). The compression is applied identically to both. This is the critical assumption the paper challenges: **what if K and V should be compressed differently?**

**Post-training KV cache eviction.** A second category of approaches leaves the pretrained model unchanged and instead selectively discards KV cache entries at inference time. Methods like H2O (Zhang et al., 2024b), StreamingLLM (Xiao et al., 2023), and Scissorhands (Liu et al., 2024a) identify and retain only "important" tokens' KV entries based on attention scores, while evicting the rest. These approaches can dynamically reduce cache size, but they still treat K and V uniformly—when a token is evicted, both its K and V vectors are discarded together. The paper notes this limitation explicitly in Appendix A:

> "The same applies to methods based on KV cache eviction, which carefully select a fixed number of tokens and cache both their K and V vectors."

**System-level optimizations.** Methods like vLLM (Kwon et al., 2023) with PagedAttention address memory fragmentation and enable more efficient KV cache management through the operating system, but they don't change what is stored—they just manage it better. These are complementary to architectural changes.

**Prompt compression.** Techniques like Gisting (Mu et al., 2024) and LongLLMLingua (Jiang et al., 2023b) compress prompts into fewer tokens, reducing the number of KV cache entries from the start. But again, K and V are compressed together.

The unifying gap across all these approaches is that **none of them exploit the functional asymmetry between K and V in the attention mechanism**. Key vectors are used to compute attention weights—they determine *where* the model attends. Value vectors are what the model actually retrieves and aggregates—they determine *what* information the model extracts. The paper argues that these different roles suggest different sensitivities to compression, a hypothesis that prior work had not systematically investigated.

### Why This Gap Matters: The Distinct Roles of K and V

The paper's motivation becomes clearer when we examine what K and V actually do in the attention computation. For a given Query vector $\mathbf{q}$ at position $t$, the attention output is:

$$\text{Attention}(\mathbf{q}, \mathbf{K}, \mathbf{V}) = \text{softmax}\left(\frac{\mathbf{q}\mathbf{K}^T}{\sqrt{d_k}}\right)\mathbf{V}$$

Key vectors participate in the dot product with the Query to produce attention scores—a set of scalar weights summing to 1. These scores are known to be **highly sparse** during inference: Zhang et al. (2024b) demonstrated that attention score distributions typically have sparsity exceeding 95%, meaning only a small fraction of past tokens receive non-trivial attention weights. This sparsity has a direct implication: even with compressed Key representations, the attention score computation can still produce a good approximation of the true attention distribution. A rough Key can still tell you *where* to attend.

Value vectors, by contrast, are the actual information carriers. The attention output is a weighted sum of Value vectors, and this sum directly feeds into the subsequent layer computations. Compressing Value vectors means losing information that flows through the entire network. The paper's hypothesis—which they systematically verify—is that **V compression should be more harmful than K compression**, and therefore K can be compressed more aggressively.

This asymmetry is not just theoretical. It has practical implications for cache design: if K can be cheaply compressed but V cannot, then a differentially compressed architecture could achieve significant cache reductions—and therefore speed improvements—while preserving more model quality than uniformly compressed alternatives. This is the intellectual foundation for the entire DiffQKV design.

### The Neglected Optimization of Query

Beyond the K-V asymmetry, the paper identifies a second underexplored opportunity: **Query vectors are never cached**. In autoregressive decoding, each token's Query is used only at the moment that token is generated. After that, the Query is discarded. Only K and V persist in the cache.

This has an important consequence for model design: adding parameters to Q (expanding its dimension, increasing its representational capacity) incurs **no additional memory cost at inference time**. The computation for projecting a single new token's Query is a small constant cost per step. By contrast, adding parameters to K or V increases the cache size for every token in the sequence, multiplying the memory and bandwidth cost.

The paper observes that existing architectures don't exploit this asymmetry either—in MHA, MQA, and GQA, the Query head dimension equals the Key and Value head dimensions ($d_q = d_k = d_v$). The paper asks: **if we're going to add parameters somewhere to boost model capacity, shouldn't we put them in Q rather than in K, V, or the FFN, since Q parameters are "free" from a caching perspective?**

### The System Domain: A Neglected Application Area

Beyond the architectural contribution, the paper addresses a second gap: the lack of specialized LLMs and benchmarks for the **system domain**. The authors define this domain (Section 1) as:

> "automated optimization of AI infrastructure... leveraging AI models to autonomously validate, evaluate, diagnose, and optimize the key components of AI infrastructure (e.g., hardware, configurations, cloud services, databases, and workloads)."

This is a genuinely important and under-served area. Modern AI infrastructure—GPU clusters, network topologies, cloud service configurations, monitoring pipelines—is enormously complex, and the experts who can diagnose and optimize these systems are scarce. An LLM that could autonomously generate correct GPU monitoring commands, retrieve relevant benchmark results, optimize network topologies for all-gather operations, or convert natural language queries into infrastructure query languages would have substantial practical value.

Yet the paper notes:

> "despite its promise, however, this important area of research has yet to receive commensurate attention."

Existing general-purpose LLMs (GPT-4, LLaMA, Qwen, DeepSeek-Coder) are not trained on system-domain data and, as the paper's experiments show (Table 6), perform poorly on system-domain tasks—particularly on command generation and topology optimization. This is not surprising: these models' training data skews heavily toward natural language, general code, and math, with minimal exposure to the specialized vocabulary, tools, and reasoning patterns of system administration.

The paper positions SIGMA as addressing both gaps simultaneously: an **architecturally efficient model** (via DiffQKV) that is **domain-specialized** (via curated system-domain pretraining data). The two contributions are complementary: the efficiency gains from DiffQKV make it practical to deploy SIGMA for system-domain tasks that may involve long-context reasoning (analyzing long log files, reasoning about complex infrastructure configurations), while the domain specialization ensures the model has the knowledge needed for these tasks.

### How This Paper Positions Itself

The paper positions DiffQKV as a **generalization** of existing attention mechanisms rather than a replacement for them. As Section 2 states:

> "Our research explores a more generalized form of attention mechanism, termed DiffQKV attention, where QKV can possess distinct numbers of heads as well as different dimensions per head."

MHA, MQA, and GQA are all special cases of DiffQKV: MHA has $n_q = n_k = n_v$ and $d_q = d_k = d_v$; MQA has $n_q > n_k = n_v = 1$; GQA has $n_q > n_k = n_v$ with some intermediate number of shared heads. DiffQKV removes the constraint that $n_k = n_v$ and $d_k = d_v$, opening up a larger design space that the paper then empirically explores.

The contribution is therefore **not a new attention mechanism per se**, but rather:
1. The **empirical demonstration** that K and V have different sensitivities to compression, which invalidates the uniform-treatment assumption underlying prior work.
2. The **design principle** that K can (and should) be compressed more aggressively than V.
3. The **architectural prescription** that Q should be augmented to compensate for the capacity lost through KV compression.
4. A **working implementation** (FlexHeadFA) that makes this differential treatment practical within the constraints of modern GPU kernels and LLM serving frameworks.

The paper's relationship to prior work is thus not adversarial but **absorptive and extending**. It doesn't claim that GQA or KV cache eviction are wrong—it claims they are **incomplete**, missing an optimization dimension that the paper's experiments show is significant. The paper takes the standard GQA architecture as its baseline and shows that decoupling K and V compression yields measurable efficiency gains with minimal or no performance degradation.

### The Efficiency Promise in Context

The paper's claim of "up to 33.36% inference speed improvement" (Section 3.3) deserves contextualization. This improvement is not uniform—it manifests primarily in **long-context scenarios**. As Figure 2 shows, at short sequence lengths (2k output, short prefix), SIGMA is actually slightly *slower* than the standard GQA baseline. The efficiency crossover occurs at longer sequences—roughly 16k prefix length for 2k outputs, or immediately (no prefix) for 64k outputs.

Why does the benefit scale with sequence length? Because the KV cache cost grows linearly with sequence length, while the cost of SIGMA's extra computations (the feed-forward layer to align K and V dimensions, the augmented Q projection) is constant per step. At short sequences, the constant overhead dominates. At long sequences, the cache savings—a 37.5% reduction in K cache size from reducing $n_k$ from 16 to 4—dominate. The 33.36% figure represents the total cost reduction at (64k output, 64k prefix), where the KV cache is so large that reducing K heads yields proportional speed improvements.

This is practically significant because **long-context inference is increasingly important**. As LLMs are deployed for document analysis, codebase understanding, multi-turn conversations, and autonomous agent workflows, sequence lengths are growing. The paper's approach directly targets this trend, making it timely even though the short-context overhead exists.

The paper also flags an important implementation detail that tempers the practical impact: **existing frameworks like FlashAttention and vLLM assume $n_k = n_v$**. The authors had to implement a custom kernel (FlexHeadFA) to support differential head counts, and they explicitly note that "broader DiffQKV support" is needed (Section 3.2). Until this support is integrated into standard frameworks, the efficiency gains require custom engineering effort—a practical barrier to adoption that the paper acknowledges but does not solve.

## 3. Technical Approach

### 3.1 Reader Orientation

This paper presents a pre-trained language model architecture—not a post-hoc compression method or an inference-time optimization trick—where the attention mechanism is fundamentally redesigned to treat Query, Key, and Value components as independent, differentially-configurable modules rather than forcing them to share head counts and dimensions. The problem it solves is that the Key-Value (KV) cache dominates inference memory and bandwidth costs, yet existing architectures compress K and V uniformly despite their distinct functional roles, and they miss the opportunity to add parameters to Query (which is never cached) to compensate for capacity lost through compression. The solution is a **surgical reallocation of parameters across Q, K, and V**: aggressively shrink K (fewer heads, optionally smaller dimensions), lightly compress or preserve V, and expand Q—all within a single unified attention formulation that MHA, MQA, and GQA fall out as special cases.

### 3.2 Big-Picture Architecture (Diagram in Words)

The DiffQKV attention system has five major components that interact at each decoder layer:

1. **Independent Q/K/V Projections** — Three separate linear transformations map the input hidden states to Query, Key, and Value tensors, each with its own number of heads and per-head dimension. Unlike standard attention where $n_q = n_k = n_v$ and $d_q = d_k = d_v$, here $n_k$ can be much smaller than $n_v$, and $d_q$ can be larger than $d_k$ and $d_v$.

2. **GroupSharing Operation** — When the number of Query heads exceeds the number of Key or Value heads, a GroupSharing function maps multiple Q heads to each K/V head by replicating or indexing the smaller K/V tensors to match the Q head count for attention computation. This is the generalization of GQA's grouping logic to asymmetric K and V head counts.

3. **Dimensional Alignment Module** — When K head dimension differs from V head dimension, a trainable feed-forward layer transforms K to match V's dimension before the attention score computation, enabling dot products between tensors of different shapes.

4. **Augmented Q Module** — An optional expansion of the Query projection with higher intermediate dimension, implemented as a gated linear unit (SwiGLU-style: `q_gate_proj`, `q_up_proj`, `q_down_proj`) that projects Q to a larger representational space and then back down, adding parameters that are never cached.

5. **FlexHeadFA Kernel** — A modified FlashAttention2 implementation that replaces the assumption $n_k = n_v$ with address probing based on head index mapping, enabling efficient GPU execution of attention computation with unequal K and V head counts.

Information flows through these components in a fixed order at each layer and each decoding step: input hidden states → independent Q, K, V projections → Augmented Q expansion (for Q only) → KV cache store (for K and V) → KV cache load (previous tokens) → GroupSharing to align head counts → dimensional alignment for K if needed → attention score computation (Q·K^T) → softmax → attention-weighted V aggregation → output projection.

The overall model (SIGMA) wraps this DiffQKV attention in a standard decoder-only transformer architecture with SwiGLU feed-forward layers, rotary position embeddings, and RMS layer normalization, available at 1.5B and 10B parameter scales.

### 3.3 Roadmap for the Deep Dive

- **First**, the **formulation of DiffQKV attention** as a formal generalization of standard attention, with explicit notation for head counts and dimensions, because all subsequent design choices—compression ratios, augmentation factors, implementation decisions—are parameterized by these degrees of freedom.
- **Second**, the **empirical observations** that justify the specific design choices: the differential sensitivity of K vs. V to compression, the negligible impact of halving K dimension, the capacity gains from augmenting Q, and the comparison between Q-augmentation and FFN expansion. These observations are the empirical foundation for everything that follows and must be understood before the architectural decisions make sense.
- **Third**, the **final architectural configuration** of SIGMA-1.5B and SIGMA-10B—the concrete parameter values and model dimensions—since these represent the "optimal" configuration derived from the observations and scoping experiments.
- **Fourth**, the **FlexHeadFA kernel implementation**—the practical engineering that makes DiffQKV run efficiently on GPUs despite existing frameworks assuming equal K and V head counts—because the theoretical efficiency gains are only realizable through this implementation.
- **Fifth**, the **KV Group Sharing workaround** for frameworks that cannot support differential head counts natively, which is a practical compatibility layer that trades some efficiency for deployment flexibility.

### 3.4 Detailed, Sentence-Based Technical Breakdown

This is primarily an **empirical architecture design paper** whose core idea is that the attention mechanism has unexploited degrees of freedom—independent Q, K, V head counts and dimensions—and that systematically exploring and exploiting these degrees of freedom yields a more efficient architecture than the constrained designs (MHA, MQA, GQA) that dominate practice.

#### Formulation of DiffQKV Attention

The paper begins Section 2 by defining DiffQKV as a formal generalization of multi-head attention. The key insight is that the standard formulation imposes two unnecessary constraints: (1) the number of Key heads equals the number of Value heads ($n_k = n_v$), and (2) the per-head dimensions of Q, K, and V are equal ($d_q = d_k = d_v$). DiffQKV removes both constraints, treating the number of heads and per-head dimension as independent hyperparameters for Q, K, and V.

**Step 1: Independent projections.** Given an input hidden state $h_t$ at position $t$, the model computes three independent linear projections:

$$q_t = h_t \cdot W_Q, \quad k_t = h_t \cdot W_K, \quad v_t = h_t \cdot W_V$$

where $h_t \in \mathbb{R}^{d_m}$ is the model's hidden state (dimension $d_m$, also called the residual stream dimension), $W_Q \in \mathbb{R}^{d_m \times (n_q \cdot d_q)}$ is the Query projection weight matrix, $W_K \in \mathbb{R}^{d_m \times (n_k \cdot d_k)}$ is the Key projection weight matrix, and $W_V \in \mathbb{R}^{d_m \times (n_v \cdot d_v)}$ is the Value projection weight matrix. The outputs $q_t$, $k_t$, $v_t$ have shapes $[n_q, d_q]$, $[n_k, d_k]$, and $[n_v, d_v]$ respectively—each is a set of vectors, one per head, with potentially different numbers of heads and different per-head dimensionalities.

**What this computes:** three separate linear transformations of the same input, each projecting into a differently-shaped output space. The total parameter count for these projections is $d_m \times (n_q d_q + n_k d_k + n_v d_v)$, which generalizes the standard formula $d_m \times 3 \cdot (n_h \cdot d_h)$ where all three share the same head count and dimension.

**Why this form:** decoupling the projections lets the architect allocate parameter budget asymmetrically. If the model can tolerate aggressive Key compression (fewer heads, smaller dimension), those saved parameters can be redistributed to Query (which costs nothing in cache) or Value (which carries the actual information). The standard form forces all three to have the same capacity, which is wasteful if they have different sensitivities to compression.

**Step 2: KV cache concatenation.** At each decoding step, the newly computed Key and Value vectors are appended to the cache of all previous Keys and Values:

$$K_t = [K_{t-1}; k_t], \quad V_t = [V_{t-1}; v_t]$$

where $K_t \in \mathbb{R}^{t \times n_k \times d_k}$ is the full Key tensor for all positions up to $t$, and $V_t \in \mathbb{R}^{t \times n_v \times d_v}$ is the full Value tensor. The semicolon denotes concatenation along the sequence-length dimension.

**Step 3: GroupSharing to align head counts.** This is the critical operation that enables attention computation when $n_q \neq n_k$ or $n_q \neq n_v$. The paper describes it as follows:

$$[K_{(t,1)}; K_{(t,2)}; \ldots; K_{(t,n_q)}] = \text{GroupSharing}(K_t, n_q, n_k)$$
$$[q_{(t,1)}; q_{(t,2)}; \ldots; q_{(t,n_q)}] = q_t$$

The GroupSharing operation maps the $n_k$ Key heads (or $n_v$ Value heads) to $n_q$ heads for compatibility with the Query. If $n_k < n_q$, multiple Query heads share each Key head—specifically, Query head $i$ accesses Key head $\lfloor i \cdot n_k / n_q \rfloor$ (integer division). The same operation is applied to Value:

$$[V_{(t,1)}; V_{(t,2)}; \ldots; V_{(t,n_q)}] = \text{GroupSharing}(V_t, n_q, n_v)$$

**What this computes:** a replication or indexing pattern that expands the smaller K/V head count to match the larger Q head count. If $n_q = 32$ and $n_k = 4$, then every 8 consecutive Q heads share the same K head. If $n_k > n_q$, some K heads would be unused (though this configuration is not explored in the paper). The output is a set of $n_q$ Key tensors $K_{(t,i)} \in \mathbb{R}^{t \times d_k}$ and $n_q$ Value tensors $V_{(t,i)} \in \mathbb{R}^{t \times d_v}$, one per Query head.

**Why this form:** this is a direct generalization of GQA's sharing pattern. In GQA, $n_k = n_v$ and Query heads are partitioned into equal-sized groups. Here, the sharing pattern for K and V can be different because $n_k$ and $n_v$ can differ—for example, $n_k = 4$ and $n_v = 16$ in SIGMA-1.5B, meaning K is shared across 8 Query heads each while V is shared across only 2 Query heads each. This allows differential compression: K heads are aggressively reduced (saving cache) while V heads are more lightly reduced (preserving information).

**Step 4: Attention score computation with potential dimensional alignment.** The paper notes that when $d_k \neq d_v$, the standard dot-product attention formulation breaks down because Q and K must have the same dimension for the dot product $q^T k$ to be defined. The paper's solution:

> "we implement this part by transforming the dimension of K to the same as V through another feed-forward layer"

So when $d_k < d_v$ (the K-dimension-compressed case), an additional learned linear transformation maps each K head from dimension $d_k$ to $d_v$ before the attention computation. Let $\tilde{K}_{(t,i)} = K_{(t,i)} \cdot W_{\text{align}}$ where $W_{\text{align}} \in \mathbb{R}^{d_k \times d_v}$. The attention scores are then:

$$\alpha_{(t,i)} = \text{Softmax}\left(\frac{q_{(t,i)}^T \tilde{K}_{(t,i)}}{\sqrt{d_k}}\right)$$

where $\alpha_{(t,i)} \in \mathbb{R}^t$ is the attention weight vector for Query head $i$ over all $t$ positions.

**What this computes:** standard scaled dot-product attention, but with K optionally projected to a different dimension first. The scaling factor $\sqrt{d_k}$ uses the original K dimension (not the transformed dimension) following the standard convention where the scaling depends on the Key's native dimensionality.

**Why this form:** the feed-forward alignment layer adds a small computational cost (a matrix multiplication of size $d_k \times d_v$ per head per position), but as the paper argues in Observation 2, this is a favorable trade-off because "the primary bottleneck for LLM inference speed lies in memory consumption rather than computation." The saved KV cache size ($d_v - d_k$ elements per K head per position) dominates the added compute, especially for long sequences where the cache is loaded many times.

**Step 5: Output aggregation.** The attention output for each Query head is the weighted sum of (potentially dimension-aligned) Value vectors:

$$o_{(t,i)} = \sum_{j=1}^{t} \alpha_{(j,i)} V_{(j,i)}$$

where $o_{(t,i)} \in \mathbb{R}^{d_v}$. These per-head outputs are concatenated and projected back to the model dimension:

$$x_t = W_O [o_{(t,1)}; o_{(t,2)}; \ldots; o_{(t,n_q)}]$$

where $W_O \in \mathbb{R}^{(n_q \cdot d_v) \times d_m}$ is the output projection matrix.

**What this computes:** the standard multi-head attention output—a weighted mixture of Value vectors aggregated across all positions, with different Query heads attending to different aspects of the context, then concatenated and linearly projected back to the residual stream.

**Key difference from standard attention:** the Value head count $n_v$ determines the number of distinct Value vectors stored in cache, but the Query head count $n_q$ determines the number of distinct attention patterns computed. The GroupSharing on V means that some Query heads receive identical Value vectors (just weighted by different attention scores), but the attention patterns themselves can differ because each Query head has its own learned projection $W_Q$. This is identical to how GQA works for V, but the novelty is that K compression can proceed independently of V compression.

**The differential V cache loading option.** The paper briefly mentions another optimization in Appendix B.2: Selective V Cache Fetching. Because attention scores are highly sparse (>95% of weights are near zero), the system can optionally load only the V vectors corresponding to the highest attention scores, skipping the transfer of V vectors that will be multiplied by near-zero weights. The paper shows (Table 8) that loading only the top-100 V vectors (out of potentially thousands) preserves model performance within 0.3 points of the full-loading baseline. This is an optional, composable optimization on top of the architectural compression.

**Relationship to MHA, MQA, and GQA.** The paper makes explicit that standard attention mechanisms are special cases:

- **MHA:** $n_q = n_k = n_v$ and $d_q = d_k = d_v$ — all heads counts equal, all dimensions equal.
- **MQA:** $n_q > n_k = n_v = 1$ and $d_q = d_k = d_v$ — single shared K and V head.
- **GQA:** $n_q > n_k = n_v$ and $d_q = d_k = d_v$ — intermediate number of shared K and V heads, equal counts.
- **DiffQKV:** no constraints — $n_k$ and $n_v$ can differ, $d_q$, $d_k$, $d_v$ can differ.

This means DiffQKV is not a new attention mechanism in the algorithmic sense—the operations (projections, dot products, softmax, weighted sum) are identical to standard attention. It is a **generalization of the configuration space**: by removing the constraints that prior work implicitly or explicitly imposed, it enables architectures that would be impossible to express in the MHA/MQA/GQA framework, such as one with 4 Key heads, 16 Value heads, and 32 Query heads with expanded dimension.

---

#### Empirical Foundation: The Four Observations That Drive the Design

The paper does not derive the optimal DiffQKV configuration from first principles or theoretical analysis. Instead, it conducts a systematic set of **small-scale training experiments** (1B parameters, 100B tokens from FineWeb-Edu) to measure how model performance responds to different compression and augmentation choices. The results are distilled into four observations that directly prescribe the final SIGMA architecture. These experiments are evaluated on a suite of 9 benchmarks: HellaSwag, OpenBookQA, WinoGrande, ARC Challenge, PIQA, SciQ, BoolQ, LogiQA, and LAMBADA.

---

##### Observation 1: Model Performance Is More Sensitive to V Head Reduction Than K Head Reduction

This is the foundational empirical result that justifies the entire "differentially compressed KV" strategy. The paper compares what happens when you reduce the number of Key heads versus the number of Value heads by the same amount, starting from a baseline with equal KV head counts.

**Experiment design.** The paper starts with three baselines: MHA ($n_k = n_v = 32$), GQA with $n_k = n_v = 16$, and GQA with $n_k = n_v = 4$. For each baseline, they create two variants: one where only V heads are reduced (e.g., $n_v$ goes from 16 to 4, a 75% reduction) and one where only K heads are reduced by the same factor ($n_k$ goes from 16 to 4). The number of Q heads is fixed at $n_q = 32$ throughout. Performance is measured as the average score across the 9 benchmarks.

**Results (Table 1 and Table 9):**

- **Starting from MHA ($n_k = n_v = 32$, baseline 52.40):** Reducing V heads by 50% ($n_v = 16$) causes a 0.66-point drop to 51.74. Reducing K heads by 50% ($n_k = 16$) actually *improves* performance by 0.43 points to 52.83.
- **Starting from GQA with $n_k = n_v = 16$ (baseline 52.14):** Reducing V heads by 75% ($n_v = 4$) causes a 0.38-point drop to 51.76. Reducing K heads by 75% ($n_k = 4$) causes only a 0.17-point drop to 51.97.
- **Starting from GQA with $n_k = n_v = 4$ (baseline 51.66):** Reducing V heads by 75% ($n_v = 1$, effectively MQA for V only) causes a 0.63-point drop to 51.03. Reducing K heads by 75% ($n_k = 1$) causes essentially no change (51.67, a 0.01-point *increase*).

The pattern is consistent: **V head reduction always hurts more than K head reduction**, often substantially so. In the most extreme case (going from 16 to 1 heads), V compression costs 0.63 points while K compression costs nothing.

**What this means mechanistically:** the model can tolerate having fewer distinct Key projection subspaces because the attention score computation is inherently approximate—the softmax normalizes the scores anyway, and the scores are known to be sparse (only a few positions receive significant weight). A coarse-grained Key projection can still produce approximately the same attention distribution as a fine-grained one. But Value vectors directly contribute to the output representation; reducing the number of Value heads means each head must represent a coarser mixture of information, and this information loss propagates through all subsequent layers.

**Why this motivates differential compression:** if K can be compressed with minimal performance penalty while V cannot, then a differentially compressed architecture ($n_k < n_v$) can achieve most of the cache savings of uniform compression while preserving most of the performance of the uncompressed baseline. For example, reducing $n_k$ from 16 to 4 saves 75% of K cache with only a 0.17-point performance cost, while making the same reduction to V would cost 0.38 points—more than twice as much.

##### Observation 2: Halving K Head Dimension Is Nearly Free

While Observation 1 addresses head *count* compression, Observation 2 addresses head *dimension* compression—making each K head narrower. This is an orthogonal compression axis: reducing $n_k$ reduces the number of heads, while reducing $d_k$ reduces the per-head dimension.

**Experiment design.** For three baseline architectures (MHA with $n_k = 32$, GQA with $n_k = 16$, and GQA with $n_k = 4$), the paper creates variants where $d_k = d_v / 2$ (half the K head dimension). To make attention computation possible with different K and V dimensions, a trainable feed-forward layer maps the compressed K to V's dimension before the dot product. The Q head count is fixed at 32, and all models are trained on the same 100B tokens.

**Results (Table 2 and Table 10):**

- MHA baseline (52.40) → with half K dim (52.56): **+0.16 points**
- GQA with $n_k = 16$ baseline (52.14) → with half K dim (52.06): **−0.08 points**
- GQA with $n_k = 4$ baseline (51.66) → with half K dim (51.92): **+0.26 points**

In all three cases, the performance change is negligible—well within the noise of small-scale training runs. In two of three cases, the compressed variant slightly *outperforms* the baseline. The feed-forward alignment layer apparently learns to recover whatever information is lost through dimensionality reduction.

**Cost-benefit analysis.** Halving $d_k$ reduces the K cache size by 50% per head. The cost is the added feed-forward layer, which requires $d_k \times d_v$ parameters per K head and a matrix multiplication per attention computation. The paper argues this is a favorable trade-off because the primary inference bottleneck is memory bandwidth for loading KV cache, not computation. Modern GPUs can perform the extra matrix multiplication much faster than they can load the saved cache bytes from memory.

**Why this matters for the architecture:** this observation, combined with Observation 1, suggests that K can be compressed along *both* axes—fewer heads AND smaller dimension—with minimal performance impact. However, the final SIGMA architecture (Appendix B.5) **opts not to reduce K head dimension**, applying compression only to the head count. The paper states:

> "For the sake of balancing the model performance and the cost of the KV cache, during the training of SIGMA-1.5B and SIGMA-10B, no dimension compression is applied to the K heads. Only the number of K heads was decreased."

This is a practical choice: the implementation complexity of supporting different K and V dimensions (the feed-forward alignment layer, potential kernel modifications) may not justify the additional cache savings given that head count reduction already provides substantial benefits. The observation is included in the paper to demonstrate that dimension compression is a viable option for future architectures even if not exercised in the current models.

**A nuance the paper doesn't fully explore:** the three baselines have different starting performance (52.40, 52.14, 51.66), and the effect of halving K dim is slightly different in each. With MHA (many heads, $n_k = 32$), halving K dim actually helps (+0.16). With GQA $n_k = 16$, it slightly hurts (−0.08). With GQA $n_k = 4$ (more aggressive head compression), it helps again (+0.26). There's no monotonic pattern, which suggests the interaction between head count compression and dimension compression is complex and may depend on the specific capacity-pressure point of the architecture.

##### Observation 3: Augmenting Query Consistently Boosts Performance

This observation establishes the second pillar of DiffQKV: adding parameters to Query to compensate for the representational capacity lost through KV compression, exploiting the fact that Query vectors are never cached.

**What "augmented Q" means.** The standard Query projection is a single linear transformation: $q_t = h_t \cdot W_Q$ where $W_Q \in \mathbb{R}^{d_m \times (n_q \cdot d_q)}$. The augmented Q replaces this with a gated linear unit (similar to the SwiGLU activation used in the FFN layers), which expands the Query to a higher intermediate dimension and then projects back down:

$$q_t = W_{\text{down}}(\sigma(W_{\text{gate}} h_t) \odot W_{\text{up}} h_t)$$

where $W_{\text{gate}}, W_{\text{up}} \in \mathbb{R}^{d_m \times d_q^{\text{aug}}}$ project the input to a higher dimension $d_q^{\text{aug}} > d_m$, $\sigma$ is an activation function (SwiGLU uses SiLU), $\odot$ is element-wise multiplication (the "gating"), and $W_{\text{down}} \in \mathbb{R}^{d_q^{\text{aug}} \times (n_q \cdot d_q)}$ projects back to the original Query shape. This is confirmed by the code in Appendix E:

```python
query_states = self.q_down_proj(self.act_fn(self.q_gate_proj(query_states)) * self.q_up_proj(query_states))
```

**Parameter cost.** The augmented Q adds $2 \cdot d_m \cdot d_q^{\text{aug}} + d_q^{\text{aug}} \cdot (n_q \cdot d_q)$ parameters per layer. The key point is that **none of these parameters affect the KV cache size**—they only affect Query computation, which happens once per new token and is not stored. At inference time, the cost is the additional FLOPs for the three projections and the element-wise multiplication, which is compute-bound (not memory-bound) and therefore relatively cheap on modern GPUs.

**Experiment design.** The paper tests augmented Q on three baselines: MHA ($n_k = n_v = 32$), GQA with $n_k = n_v = 16$, and GQA with $n_k = n_v = 4$. For the GQA baselines, they sweep multiple augmentation sizes: $d_q^{\text{aug}} = 3072$ (1.5× the hidden dimension of 2048), $d_q^{\text{aug}} = 4096$ (2×), and $d_q^{\text{aug}} = 5632$ (2.75×). The Q head count is fixed at 32.

**Results (Table 3 and Table 11):**

- MHA baseline (52.40) + AugQ $d_q = 5632$: 53.03 (**+0.63**)
- GQA $n_k = 16$ baseline (52.14) + AugQ $d_q = 3072$: 53.38 (**+1.24**)
- GQA $n_k = 16$ + AugQ $d_q = 4096$: 52.93 (**+0.79**)
- GQA $n_k = 16$ + AugQ $d_q = 5632$: 53.07 (**+0.93**)
- GQA $n_k = 4$ baseline (51.66) + AugQ $d_q = 5632$: 53.13 (**+1.47**)

Three patterns emerge: (1) augmenting Q always helps, across all baselines and all augmentation sizes; (2) the benefit is *larger* when KV compression is more aggressive—the gain on GQA with $n_k = 4$ (1.47 points) exceeds the gain on MHA (0.63 points); (3) a scaling factor of 1.5× ($d_q^{\text{aug}} = 3072$ on a 2048-dim model) appears optimal—further increases to 2× or 2.75× actually reduce the gain (compare 1.24 vs. 0.79 vs. 0.93 for GQA $n_k = 16$).

**Why the benefit is larger with more KV compression:** when KV is aggressively compressed (fewer heads, less capacity), the attention mechanism has less representational power to work with. Augmenting Q gives the Query side more capacity to extract information from the compressed KV representations—it can learn more sophisticated attention patterns that compensate for the coarser Key and Value projections. This is the paper's "compensation" narrative: augmented Q partially counteracts the performance decline from KV compression.

**Why 1.5× seems optimal:** the paper doesn't deeply analyze the non-monotonicity, but it likely reflects overfitting at small scale. With only 100B training tokens, a 1B model with 2× or 2.75× Q augmentation may have too many parameters relative to the data, causing the training to underfit or the model to overfit the training distribution. At larger scales (more data, bigger models), the optimal augmentation factor might shift.

**Important detail for the final architecture:** SIGMA-1.5B uses $d_q^{\text{aug}} = 3072$ (1.5× hidden dimension), and SIGMA-10B uses $d_q^{\text{aug}} = 6144$ (also 1.5× hidden dimension, which is 4096). This consistent 1.5× factor is the paper's recommended default.

##### Observation 4: Augmenting Q Beats Augmenting FFN at Equal Parameter Count

This observation addresses a natural counterargument: if you're going to add parameters to improve performance, why add them to Query specifically rather than to the feed-forward network (FFN), which is the conventional place to scale up? The paper's answer is that **Q-augmentation is more parameter-efficient than FFN augmentation for improving model quality**, and the two can be combined for additive gains.

**Experiment design (Table 4 and Table 12).** The baseline is GQA with $n_k = n_v = 16$ and FFN dimension 5632 (the standard FFN hidden dimension for this 1B-scale architecture). The paper defines a "unit" of parameter increase $\delta = 3072$ and compares:

- **AugF($\delta$):** Expand the FFN intermediate dimension by $\delta$ (from 5632 to 8704). This adds approximately $\delta \cdot d_m \cdot 3$ parameters (for the three FFN weight matrices: gate, up, down).
- **AugQ($\delta$):** Set $d_q^{\text{aug}} = \delta = 3072$. This adds parameters for the three Q projection matrices.
- **AugF($\delta$) + AugQ($\delta$):** Both augmentations simultaneously.

The paper also tests larger FFN expansions: AugF($2\delta$), AugF($3\delta$), AugF($5\delta$), and combinations with AugQ.

**Results (Table 4):**

- Baseline GQA: 52.14
- AugF($\delta$): 53.26 (+1.12)
- AugQ($\delta$): 53.38 (+1.24)
- AugF($2\delta$): 53.16 (+1.02)
- AugF($\delta$) + AugQ($\delta$): 54.55 (+2.41)
- AugF($3\delta$): 54.50 (+2.36)
- AugF($2\delta$) + AugQ($\delta$): 54.67 (+2.53)
- AugF($5\delta$): 55.08 (+2.94)
- AugF($3\delta$) + AugQ($\delta$): 55.09 (+2.95)

The key comparisons:

1. **At equal added parameters** (both add $\delta$): AugQ ($+1.24$) beats AugF ($+1.12$).
2. **AugF needs ~2× more parameters to match AugQ:** AugF($2\delta$) gives +1.02, which is *worse* than AugQ($\delta$) at +1.24, despite having twice the parameter increase. Even AugF($3\delta$) at +2.36 is roughly comparable to AugQ($\delta$) + AugF($\delta$) combined (+2.41), meaning the Q augmentation is providing roughly the same benefit as 3× more FFN parameters.
3. **The gains are approximately additive:** AugQ($\delta$) alone gives +1.24. AugF($\delta$) alone gives +1.12. Together they give +2.41, which is close to the sum (2.36) but slightly more—suggesting a small positive interaction. This pattern holds across other comparisons: AugF($2\delta$) + AugQ($\delta$) gives +2.53 vs. AugF($2\delta$) alone at +1.02 and AugQ($\delta$) alone at +1.24 (sum = 2.26, actual = 2.53, so the interaction adds ~0.27 points).
4. **The highest performance** (55.09) comes from AugF($3\delta$) + AugQ($\delta$), just barely above AugF($5\delta$) alone at 55.08—essentially tied. But AugF($5\delta$) uses far more parameters in the FFN, which are expensive in memory and compute compared to Q parameters.

**What this means mechanistically:** there's something special about adding capacity to the attention mechanism's Query projection that makes it more impactful per parameter than adding capacity to the FFN. The paper's interpretation is that augmenting Q directly enhances the model's ability to form better attention patterns—it can query the context more effectively, extract more relevant information, and route information more precisely. FFN augmentation adds general processing capacity but doesn't specifically target the attention bottleneck. Since the attention mechanism is what allows the model to access long-range context and integrate information across positions, improving it has outsized effects.

**Why this matters for architectural design:** if you have a fixed parameter budget to spend on improving a model, the paper's results suggest you should allocate some of it to augmented Q *before* expanding the FFN. The SIGMA architecture reflects this: it includes augmented Q (1.5× expansion) as a core component, and the FFN dimensions (6144 for 1.5B, 14336 for 10B) are presumably tuned to work well with this Q augmentation rather than being maximally expanded.

#### The Final SIGMA Architecture

The four observations above prescribe a specific DiffQKV configuration, which the paper crystallizes into two models: SIGMA-1.5B and SIGMA-10B. Table 14 provides the complete hyperparameter specification.

**SIGMA-1.5B configuration:**

- **Layers:** 26 transformer blocks
- **Hidden dimension ($d_m$):** 2048
- **FFN intermediate dimension:** 6144 (3× hidden dimension, standard for SwiGLU)
- **Augmented Q dimension ($d_q^{\text{aug}}$):** 3072 (1.5× hidden dimension)
- **Attention heads ($n_q$):** 32
- **Key heads ($n_k$):** 4 (87.5% reduction from 32, 75% reduction from $n_v = 16$)
- **Value heads ($n_v$):** 16 (50% of Query heads, same as GQA with group size 2)
- **Peak learning rate:** $4 \times 10^{-4}$
- **Activation function:** SwiGLU
- **Vocabulary size:** 128,256 (same tokenizer as LLaMA 3)
- **Positional embeddings:** Rotary Position Embeddings (RoPE) with base frequency $\theta = 50,000$

**SIGMA-10B configuration:**

- **Layers:** 32
- **Hidden dimension ($d_m$):** 4096
- **FFN intermediate dimension:** 14,336
- **Augmented Q dimension:** 6144 (1.5× hidden dimension)
- **Attention heads ($n_q$):** 32
- **Key heads ($n_k$):** 4 (same absolute number as 1.5B!)
- **Value heads ($n_v$):** 16 (same as 1.5B)
- **Peak learning rate:** $1.5 \times 10^{-4}$
- **Activation function:** SwiGLU
- **Vocabulary size:** 128,256
- **Positional embeddings:** RoPE with base frequency $\theta = 500,000$ (10× larger than 1.5B, extending the context length capacity)

**Key architectural decisions and their justifications:**

1. **$n_k = 4$ for both model sizes.** This is an interesting choice: the absolute number of Key heads stays constant even as the model scales from 1.5B to 10B. This means the compression ratio increases with scale: from 32:4 (8:1 sharing) in the 1.5B model to 32:4 (still 8:1) in the 10B model since $n_q$ stays at 32. The paper doesn't explain why $n_q$ doesn't increase at the larger scale (many models scale head count with width), but maintaining $n_k = 4$ suggests the authors believe 4 Key heads are sufficient even for a 10B model—consistent with Observation 1's finding that K head compression is nearly free.

2. **$n_v = 16$ for both model sizes.** Value gets 4× more heads than Key (16 vs. 4), reflecting Observation 1's finding that V is more sensitive to compression. The ratio $n_q : n_v = 32 : 16 = 2:1$ means each Value head is shared by exactly 2 Query heads, which is mild compression compared to the 8:1 sharing for Key.

3. **No K dimension compression.** Despite Observation 2 showing dimension compression is viable, the final architecture compresses K only via head count. The paper cites "balancing the model performance and the cost of the KV cache" as the reason—dimension compression adds implementation complexity (the feed-forward alignment layer, potential kernel issues) for incremental cache savings on top of the substantial savings already achieved through head count reduction.

4. **Augmented Q at 1.5× scaling.** Both models use 1.5× hidden dimension for the Q intermediate dimension, following Observation 3's finding that this scaling factor is optimal. The augmented Q parameters are never cached, making this a "free lunch" in terms of memory.

5. **RoPE base frequency scaling.** The 10B model uses $\theta = 500,000$ vs. 50,000 for the 1.5B model. This is a standard technique for extending the effective context length: a higher base frequency means the rotary embeddings rotate more slowly with position, allowing the model to distinguish positions at longer distances. This is not directly related to DiffQKV but reflects the expectation that larger models will be used for longer-context tasks.

**How DiffQKV affects parameter count and cache size:**

For a single layer with hidden dimension $d_m$, the parameter counts (ignoring biases and normalization) are:

- **Standard GQA ($n_q = 32, n_k = n_v = 16, d_q = d_k = d_v = 64$):**
  - Q projection: $d_m \times (32 \times 64) = d_m \times 2048$
  - K projection: $d_m \times (16 \times 64) = d_m \times 1024$
  - V projection: $d_m \times (16 \times 64) = d_m \times 1024$
  - Output projection: $(32 \times 64) \times d_m = 2048 \times d_m$
  - Total attention parameters: $d_m \times (2048 + 1024 + 1024 + 2048) = d_m \times 6144$

- **SIGMA ($n_q = 32, n_k = 4, n_v = 16, d_q^{\text{aug}} = 1.5 d_m$):**
  - Augmented Q: $2 \cdot d_m \cdot 1.5 d_m + 1.5 d_m \cdot (32 \times 64) = 3 d_m^2 + 3072 d_m$
  - K projection: $d_m \times (4 \times 64) = d_m \times 256$
  - V projection: $d_m \times (16 \times 64) = d_m \times 1024$
  - Output projection: $(32 \times 64) \times d_m = 2048 \times d_m$
  - Total attention parameters: roughly $3 d_m^2 + d_m \times (3072 + 256 + 1024 + 2048) = 3 d_m^2 + 6400 d_m$

For $d_m = 2048$ (SIGMA-1.5B), the augmented Q adds about $3 \times 2048^2 \approx 12.6$M parameters per layer in the Q projection alone, which is significant. However, the K projection savings ($1024 d_m$ vs. $256 d_m$ at $d_m = 2048$) save about $768 \times 2048 \approx 1.6$M parameters. The net effect is more total parameters (due to augmented Q) but a much smaller K cache (4 heads × 64 dim vs. 16 heads × 64 dim = 256 vs. 1024 elements per position per layer—a 75% reduction in K cache size).

#### FlexHeadFA Kernel: Making DiffQKV Run Efficiently

The theoretical efficiency of DiffQKV depends on actually being able to execute attention computation with $n_k \neq n_v$ on GPU hardware. The paper confronts a practical obstacle: FlashAttention2, the standard fast attention kernel, only supports attention when $n_k = n_v$ and $n_q$ is an integer multiple of $n_k$ and $n_v$. This is because FlashAttention2's internal indexing assumes symmetric Key and Value head counts—it can handle GQA's $n_k = n_v < n_q$ but not SIGMA's $n_k = 4, n_v = 16, n_q = 32$.

**The address probing solution.** The paper introduces FlexHeadFA, a modified FlashAttention2 that replaces the hard-coded assumption $n_k = n_v$ with computed head indices based on the Query head index. The core logic is encapsulated in a single formula:

$$\text{idx}_i = \text{idx}_q \cdot \frac{n_i}{n_q}, \quad i \in \{k, v\}$$

where $\text{idx}_q$ is the Query head index (running from 0 to $n_q - 1$), and $\text{idx}_k$ and $\text{idx}_v$ are the corresponding Key and Value head indices to access. Integer division ensures the mapping: for $n_q = 32, n_k = 4$, Query heads 0–7 map to Key head 0, heads 8–15 map to Key head 1, etc. For $n_q = 32, n_v = 16$, Query heads 0–1 map to Value head 0, heads 2–3 map to Value head 1, etc.

**What this formula computes:** a deterministic GroupSharing mapping from Query head space to Key/Value head space, expressed as a simple integer division. Instead of storing replicated K and V tensors (which would negate the cache savings), the kernel uses this index mapping to **probe** the correct Key and Value head addresses in GPU memory during the attention computation. This is "address probing"—the kernel computes where each K and V head lives in memory based on the Query head index, rather than assuming a 1:1 or fixed-ratio correspondence.

**Two-kernel architecture.** FlexHeadFA follows FlashAttention2's design of splitting the attention computation into two GPU kernel operations:

1. **`flash_fwd_splitkv_kernel` (split kernel):** This kernel handles the primary attention computation—the matrix multiplications between Query and Key, the softmax, and the multiplication by Value. It divides the Key and Value matrices into chunks that fit in GPU shared memory (SRAM), processes each chunk, and writes partial outputs. In FlexHeadFA, this kernel uses the index mapping formula to determine which Key and Value heads to load for each Query head, rather than assuming 1:1 correspondence.

2. **`flash_fwd_splitkv_combine_kernel` (combine kernel):** This kernel assembles the partial output chunks from the split kernel into the final attention output matrix. It is unaffected by head count changes because it operates on the output dimension, not the K/V dimensions.

**How FlexHeadFA achieves the speedup.** The split kernel directly benefits from reduced Key heads because it loads fewer Key tensors from GPU global memory (HBM) into shared memory (SRAM). With $n_k = 4$ instead of $n_k = 16$, the Key tensor is 4× smaller, reducing both the memory load time and the SRAM footprint, which allows processing larger chunks. The combine kernel, which only assembles outputs, sees essentially no change (its cost is independent of K and V head counts). This aligns with the KET results in Figure 1: the split kernel shows 25–27% improvement at moderate-to-long prefix lengths, while the combine kernel shows near-zero improvement.

**Remaining overhead.** FlexHeadFA still loads all Value heads because $n_v = 16$ is not reduced from the baseline. The speedup comes entirely from the K cache reduction. The theoretical maximum speedup for a 75% K head reduction is not 75% because: (1) V cache and V attention computation are unchanged, (2) Q computation is unchanged (or increased, with augmented Q), (3) there are fixed overheads (combine kernel, softmax, etc.). The paper's theoretical analysis (Section 3.1) computes the expected convergence rate as 37.5% for the KV cache module alone, and the empirical results approach but don't quite reach this for total attention cost.

**Practical challenge: framework support.** The paper explicitly acknowledges that FlexHeadFA is a custom modification needed because "the official FlashAttention supports attention computations only when $n_k$ equals $n_v$." This means that adopting DiffQKV currently requires maintaining a custom kernel, which is a barrier to adoption. The authors "emphasize the need for broader DiffQKV support" in mainstream frameworks—a call for the community to integrate this capability into standard FlashAttention, vLLM, and TensorRT-LLM.

#### KV Group Sharing: A Compatibility Workaround

For deployment scenarios where custom kernels are not feasible (e.g., using standard HuggingFace Transformers with FlashAttention2 without code modifications), the paper provides a fallback mechanism called KV Group Sharing. This is explicitly described as a workaround, not a recommended approach:

> "this approach is highly discouraged, as it negates the efficiency improvements entirely by degrading to GQA."

**How it works (Appendix E).** The workaround replicates the smaller K tensor to match the size of the larger V tensor before passing both to standard FlashAttention. The Python implementation (reproduced in the paper) checks if `num_key_heads > num_value_heads` or vice versa, and expands the smaller one by repeating it along the head dimension:

```python
if self.num_key_heads > self.num_value_heads:
    n_rep = int(self.num_key_heads / self.num_value_heads)
    value_states = value_states[:, :, None, :, :].expand(batch, self.num_value_heads, n_rep, slen, head_dim)
    return key_states, value_states.reshape(batch, self.num_value_heads * n_rep, slen, head_dim)
else:
    n_rep = int(self.num_value_heads / self.num_key_heads)
    key_states = key_states[:, :, None, :, :].expand(batch, self.num_key_heads, n_rep, slen, head_dim)
    return key_states.reshape(batch, self.num_key_heads * n_rep, slen, head_dim), value_states
```

For SIGMA ($n_k = 4, n_v = 16$), this means the 4 Key heads are replicated 4 times each to create 16 Key heads, matching the 16 Value heads. The resulting K tensor has the same memory footprint as a standard GQA model with $n_k = 16$, completely negating the K cache savings. The attention computation also processes this replicated 16-head K tensor, wasting compute.

**Why it exists.** The workaround enables SIGMA to run on standard infrastructure without kernel modifications—important for reproducibility, testing, and deployment in environments where custom CUDA kernels are not practical. But for production use where efficiency matters, FlexHeadFA is essential.

#### Efficiency Analysis: Theoretical and Empirical

The paper provides both a theoretical framework for understanding where the speedup comes from and empirical measurements confirming the theory.

**Theoretical KV Cache cost model.** The paper models the cost of KV cache operations as proportional to the total number of elements stored and loaded:

$$L = \alpha \cdot [b \cdot s \cdot (n_k \cdot d_k + n_v \cdot d_v)] + \beta$$

where $\alpha$ is the proportional cost per cache element (covering memory load/store time), $b$ is batch size, $s$ is sequence length, $n_k$ and $n_v$ are head counts, $d_k$ and $d_v$ are head dimensions, and $\beta$ is a fixed overhead term independent of cache size.

**What this computes:** the total time spent on KV cache memory operations (loading past K and V from GPU global memory to compute units, storing new K and V to the cache) as a linear function of cache size. The $\alpha$ term scales with the total number of floating-point values in the cache (batches × positions × K heads × K dim + batches × positions × V heads × V dim), while $\beta$ captures fixed costs like kernel launch overhead.

**Why this linear form:** memory load/store time is proportional to the number of bytes transferred, assuming the memory bandwidth is the bottleneck and the transfers can be coalesced. This is a reasonable first-order approximation for bandwidth-bound operations on GPUs.

**Theoretical reduction rate.** For SIGMA-1.5B with $n_k = 4, d_k = 64$ and $n_v = 16, d_v = 64$, compared to a GQA baseline with $n_k = n_v = 16, d_k = d_v = 64$, the total number of cache elements per position per layer changes from $16 \times 64 + 16 \times 64 = 2048$ to $4 \times 64 + 16 \times 64 = 1280$. As sequence length $s \to \infty$, the fixed overhead $\beta$ becomes negligible, and the relative reduction converges to:

$$r = \lim_{s \to \infty} \frac{L_{\text{GQA}} - L_{\text{SIGMA}}}{L_{\text{GQA}}} = \frac{2048 - 1280}{2048} = \frac{768}{2048} = 37.5\%$$

**What this 37.5% means:** in the limit of very long sequences, the KV cache operations (loading and storing) for SIGMA should take 37.5% less time than for the equivalent GQA model. This is the theoretical ceiling for KV cache speedup from reducing $n_k$ from 16 to 4.

**Why attention computation will differ.** The paper notes that while KV cache operations are "primarily I/O-intensive" (memory-bound), "attention computation is significantly more computation-intensive." The attention computation involves matrix multiplications (Q·K^T, attention·V) that are compute-bound, meaning the speedup from reduced K heads will be less than 37.5% for the attention computation module specifically. The combine kernel, which assembles outputs, is entirely unaffected. The overall speedup will be a weighted average of the large KV cache speedup and the smaller attention computation speedup.

**Empirical validation via KET (Kernel Execution Time).** Table 15 and Figure 1 provide precise GPU kernel timing measurements using NVIDIA Nsight Systems (`nsys`). At prefix length 32k with output length 10 (a long-context, short-generation scenario):

- Split kernel: STD (GQA baseline) takes 27.5M ns, SIGMA takes 20.0M ns → **27.21% improvement**
- Combine kernel: STD takes 1.99M ns, SIGMA takes 2.01M ns → **−0.93%** (essentially unchanged)
- Total: STD takes 29.5M ns, SIGMA takes 22.1M ns → **25.31% improvement**

The split kernel improvement (27.21%) approaches but doesn't reach the theoretical 37.5% because: (1) the split kernel also processes Value tensors, which are unchanged, (2) there's computational work (softmax, reductions) that doesn't scale with K head count, (3) prefix length 32k is long but not infinite—fixed overheads still matter. The combine kernel is unaffected (near-zero change), confirming the paper's expectation that it "is responsible solely for combining output chunks" and "is unaffected by changes in the key matrix."

**KET scaling with prefix length.** From Table 15, the relative improvement for the split kernel grows with prefix length: 1.17% at 2k → 25.33% at 4k → 26.30% at 16k → 27.21% at 32k. This asymptotic approach toward the theoretical bound is exactly what the model predicts.

**Empirical validation via CEET (Cuda Event Elapsed Time).** Figure 2 provides end-to-end timing for the total cost of attention layers (KV Cache + Attention Computation + Augmented Q), sweeping both output length and prefix length in a grid. Key findings:

- At 2k output length (Figure 2a): SIGMA is **slower** than STD for prefixes below ~16k tokens (the gray dashed crossover line). The augmented Q overhead and the less-than-perfect K cache savings don't offset the costs until sequences are long enough.
- At 4k output length (Figure 2b): the crossover shifts earlier—SIGMA becomes faster at ~4k prefix length.
- At 8k output length (Figure 2c): SIGMA is faster at all prefix lengths ≥ 2k.
- At 16–64k output length (Figures 2d–2g): SIGMA is consistently faster, with the absolute improvement growing with output length.
- At 64k output and 64k prefix (Figure 2g): SIGMA achieves **33.36% total cost reduction**—the headline number from the abstract.

The 33.36% is measured at the most extreme tested length (64k output + 64k prefix). This is the scenario where KV cache dominates total cost most strongly, and therefore where K head reduction has the largest proportional impact. The improvement is slightly less than the 37.5% theoretical KV cache ceiling because: (1) the Augmented Q adds some compute cost not present in the baseline, (2) attention computation improvement is less than KV cache improvement, and (3) at 64k, the $\beta$ term is not quite zero.

**The "slightly less efficient at short context" trade-off.** The paper is transparent that SIGMA is not universally faster—at short sequences (e.g., 2k output with no prefix), SIGMA incurs ~1–3% overhead from augmented Q. The practical significance is that for applications dominated by short prompts and short responses (many chatbot interactions, simple QA), SIGMA may not provide efficiency benefits. For applications with long contexts (document analysis, codebase tasks, multi-turn conversations with accumulated history, system log analysis), the benefits are substantial and growing. This aligns with the paper's positioning of SIGMA for the system domain, where analyzing long configuration files, log outputs, and infrastructure states involves long contexts.

**Memory consumption benefit.** Beyond speed, the reduced K cache size enables larger batch sizes. The paper notes:

> "the reduction of $n_k$ also decreases KV cache's memory consumption. SIGMA hence allows for larger batch sizes, enhancing inference efficiency naturally."

This is a secondary benefit not measured directly in the paper: if each sequence's KV cache is 37.5% smaller for K (and V is unchanged, so total cache is perhaps 20% smaller overall), the same GPU memory can hold more simultaneous sequences, increasing throughput for batched inference.

#### Summary of Design Choices and Their Justifications

- **Independent Q, K, V head counts ($n_q \neq n_k \neq n_v$):** Observation 1 shows K can be compressed much more aggressively than V. Removing the $n_k = n_v$ constraint enables asymmetric compression that maximizes cache savings while minimizing performance loss.
- **$n_k = 4$ specifically:** The 75% reduction from 16 to 4 Key heads costs only 0.17 points in the scoping experiments (Table 1)—a negligible performance penalty for a 75% K cache reduction.
- **$n_v = 16$ (not compressed further):** Reducing V heads to 4 costs 0.38 points (Table 1)—more than double the K compression cost. The paper accepts $n_v$ at 16 to preserve Value-side representational capacity.
- **$n_q = 32$ (not increased with scale):** This is a standard head count for models of this size. The paper doesn't explore varying $n_q$; it's preserved from the baseline.
- **Augmented Q at 1.5× hidden dimension:** Observation 3 finds this is the optimal scaling factor at 1B scale. Observation 4 shows Q augmentation is more parameter-efficient than FFN expansion. The consistent 1.5× factor is the paper's recommended default.
- **No K dimension compression in final models:** Despite Observation 2 showing it's viable, the implementation complexity and incremental benefit didn't justify it for the production models. The head count reduction alone provides substantial savings.
- **FlexHeadFA custom kernel over KV Group Sharing:** FlexHeadFA realizes the efficiency gains; KV Group Sharing is a compatibility fallback that intentionally sacrifices efficiency for deployment convenience.
- **RoPE base frequency scaling for 10B ($\theta = 500,000$ vs. 50,000):** Standard context-length extension technique, not directly related to DiffQKV but important for the long-context scenarios where DiffQKV's benefits are most pronounced.

## 4. Key Insights and Innovations

### Innovation 1: Treating K and V Compression Asymmetrically Is a New Design Axis for Efficient Attention

The paper's most conceptually distinctive contribution is the **empirical demonstration that Key and Value vectors respond to compression with fundamentally different sensitivities**, and that this asymmetry constitutes a new, previously unexploited degree of freedom for designing efficient attention architectures. This is not merely a new compression technique—it is a **diagnostic finding that invalidates the uniform-treatment assumption** underlying virtually all prior KV cache optimization work.

**What the field assumed before this paper.** Every major architectural approach to KV cache reduction—Multi-Query Attention (Shazeer, 2019), Grouped-Query Attention (Ainslie et al., 2023), Cross-Layer Attention (Brandon et al., 2024), and the YOCO decoder-decoder architecture (Sun et al., 2024)—imposes the constraint $n_k = n_v$. The same head count is applied to both K and V, even when that count is reduced. Similarly, KV cache eviction methods (H2O from Zhang et al., 2024b; StreamingLLM from Xiao et al., 2023; Scissorhands from Liu et al., 2024a) discard both K and V vectors for evicted tokens together. The assumption—implicit in every one of these works—is that K and V are roughly equally important to preserve, or at least that there is no systematic difference worth exploiting.

**What this paper discovered.** The scoping experiments in Tables 1 and 9 reveal that this assumption is quantitatively false. Starting from a GQA baseline with $n_k = n_v = 16$ and reducing K heads by 75% ($n_k = 4$) causes a 0.17-point performance drop, while the same reduction applied to V heads ($n_v = 4$) causes a 0.38-point drop—more than double. In the most extreme comparison (from GQA with $n_k = n_v = 4$ to single-head MQA-style compression), reducing K heads to 1 costs essentially nothing (0.01-point *increase*), while reducing V heads to 1 costs 0.63 points. The magnitude and consistency of this asymmetry is the finding.

**Why this is a conceptual advance rather than just an empirical observation.** The paper does not simply report "K compression hurts less" and move on. It provides a **functional explanation grounded in the mechanics of attention**: Key vectors determine *where* the model attends (attention score computation), and these scores are known from prior work to be highly sparse (>95% of weights near zero). A coarser Key representation can still produce a reasonable approximation of the attention distribution because the softmax normalizes the scores and most positions receive negligible weight. Value vectors, by contrast, are *what* the model retrieves—the actual information carriers that get aggregated into the output. Lossy compression of Values directly degrades the signal flowing through the network everywhere downstream. This is not a new mathematical insight per se—the distinction between scoring and retrieval in attention has been understood since Vaswani et al. (2017)—but **no prior work had connected this functional asymmetry to a systematic, exploitable difference in compression tolerance**. The paper converts a known mechanistic fact into an actionable architectural design principle.

**How this changes the design space.** Before this paper, the question for an architect designing efficient attention was: "How many KV heads should I use?"—with the implicit constraint that K and V share the same answer. After this paper, the question splits into two: "How many K heads do I actually need?" and "How many V heads do I actually need?"—with the strong prior that the answer for K will be smaller. This expands the architectural search space from one dimension (the KV head count ratio relative to Q) to at least three ($n_k$, $n_v$, and their relationship to $n_q$). The paper's Observation 2 further adds K head dimension as an independent variable. This is a **fundamental expansion of the design space**, not an incremental refinement within an existing space.

**The connection to dimension compression generalizes the finding.** Observation 2 (Table 2) shows that the same asymmetry holds for per-head dimension: halving $d_k$ costs essentially nothing across all tested configurations (ranging from a 0.16-point *gain* to a 0.08-point loss), while the paper doesn't even test halving $d_v$—the prior from Observation 1 would predict it's substantially more harmful. This suggests the asymmetry is a **property of the functional roles of K and V**, not an artifact of a particular compression method or head count.

**Anchor.** Tables 1, 2, and 9–10, and the explanatory framing in Section 2 (Observation 1 and 2 discussion).

### Innovation 2: Augmented Query as a "Free Parameter" Allocation Strategy for Attention

The paper's second conceptual contribution is the recognition and empirical validation that **Query vectors occupy a privileged position in the parameter-efficiency landscape because they are never cached**, making them the optimal destination for extra parameters in a memory-constrained architecture. This is not a novel mathematical operation—gated linear units with expansion factors are standard in transformer FFNs—but the **strategic insight** that this expansion should be preferentially applied to Query rather than to K, V, or the FFN is new and non-obvious.

**Why this is counterintuitive.** The conventional wisdom in scaling transformers, following the original architecture design and reinforced by scaling laws work (Kaplan et al., 2020), is that if you have extra parameters to spend, you expand the feed-forward network—the FFN intermediate dimension is the primary knob for trading parameters against performance. This makes intuitive sense: the FFN contains the majority of the model's parameters and is where most of the "computation" happens. Expanding it should increase representational capacity proportionally. The paper's Observation 4 (Table 4) directly challenges this: at equal added parameter count, augmenting Q ($+1.24$ points) **outperforms** augmenting the FFN ($+1.12$ points). And to match the benefit of a relatively modest Q augmentation (1.5× expansion), the FFN needs roughly 2–3× more added parameters.

**What makes this a conceptual advance.** The paper doesn't just report numbers—it provides a **resource-theoretic framing** that makes the result generalizable. The key insight is that parameters in different components of the transformer have different **inference-time costs**. Parameters added to K or V directly increase the KV cache size, multiplying the memory and bandwidth cost across every token in the sequence. Parameters added to the FFN increase per-step compute but not memory. Parameters added to Query increase per-step compute in the same way as FFN parameters—but Observation 4 shows they provide more performance benefit per parameter. So the architectural design problem becomes: **how do you allocate a fixed parameter budget across Q, K, V, and FFN to maximize performance while respecting inference-time memory and bandwidth constraints?** Before this paper, this question wasn't asked because the standard architectures (MHA, GQA) didn't expose these as independent allocation decisions. DiffQKV makes them independent, and the paper's experiments begin to answer the allocation question.

**Why Q specifically benefits from expansion.** The paper speculates, but doesn't prove, a mechanistic explanation: augmenting Query enhances the model's capacity to form precise, context-aware attention patterns. A richer Query representation can extract more nuanced information from the same K and V tensors—it can ask "better questions" of the context. If attention is the mechanism by which the model routes information from past tokens to the current computation, then improving the Query is like improving the routing logic: the same stored information (K, V) becomes more useful because it's accessed more intelligently. This interpretation is consistent with Observation 3's finding that Q augmentation provides more benefit when KV is more aggressively compressed—when the stored information is coarser, better routing matters more.

**The practical implication.** The paper establishes a design principle: **when building efficient models, prefer Q augmentation over FFN expansion for a given parameter budget, up to a factor of roughly 1.5× the hidden dimension.** The fact that this principle is stated explicitly and supported by direct comparison (Table 4, Table 12) makes it actionable for other architecture designers, not just a property of SIGMA specifically.

**How this relates to prior work.** Prior efficient architecture designs (MobileLLM from Liu et al., 2024b; OpenELM from Mehta et al., 2024; SmolLM from Allal et al., 2024) explored different layer-wise parameter allocations and FFN-to-attention ratios, but none of them investigated asymmetric Q augmentation as a targeted strategy. The paper's finding that Q augmentation beats FFN expansion at equal parameter count is, to my knowledge, a novel empirical contribution to the efficient architecture design literature.

**Anchor.** Tables 3, 4, 11, and 12, and the Observations 3–4 discussion in Section 2.

### Innovation 3: DiffQKV as a Unifying Generalization of Attention Mechanisms

The paper's third conceptual contribution is **reframing MHA, MQA, and GQA not as distinct attention mechanisms but as special cases of a more general family** parameterized by independent Q, K, V head counts and dimensions. This is a taxonomic insight that has both intellectual and practical value.

**Why this reframing matters.** The standard narrative in the efficient attention literature treats MHA → MQA → GQA as a progression of increasingly parameter-efficient architectures, each with its own name, its own paper, and its own community understanding. MQA (Shazeer, 2019) is understood as "all Q heads share one KV head." GQA (Ainslie et al., 2023) is understood as "Q heads are partitioned into groups, each group sharing one KV head." These are described in terms of sharing patterns, which makes it non-obvious how to generalize them further—once you've shared KV heads across Q groups, what's the next step?

**What DiffQKV does differently.** By expressing the architecture in terms of independent head counts ($n_q$, $n_k$, $n_v$) and dimensions ($d_q$, $d_k$, $d_v$), the paper shows that MHA, MQA, and GQA are simply points in a continuous (discretized) design space:
- MHA: $n_k = n_v = n_q$, $d_k = d_v = d_q$
- GQA: $n_k = n_v < n_q$, $d_k = d_v = d_q$
- MQA: $n_k = n_v = 1$, $d_k = d_v = d_q$
- DiffQKV: no constraints on any of these

This reframing immediately suggests generalizations that the sharing-pattern narrative obscures: what if $n_k < n_v < n_q$? What if $n_k < n_q$ but $n_v = n_q$ (Value is uncompressed)? What if $d_k < d_v$? These are not arbitrary configurations—they are motivated by the functional asymmetry between K and V that the paper empirically establishes.

**The practical value of this unification.** By showing that the three dominant attention mechanisms are special cases of a single parameterized formulation, the paper makes it possible to **transfer implementation effort** across architectures. A single FlexHeadFA kernel that implements the general DiffQKV formulation can execute MHA, MQA, GQA, and any asymmetric variant by simply setting the head count and dimension parameters appropriately. This is more than a notational convenience—it means that if the community adopts DiffQKV-aware kernels (as the paper advocates), all existing architectures benefit from the optimized implementation path.

**How this compares to prior unification attempts.** The progression from MHA to MQA to GQA was previously understood as a spectrum of KV head sharing, but no prior work had proposed a **parameterized family** that includes all three as instances. The paper's GroupSharing operation is the key generalization: rather than hard-coding a fixed sharing ratio between Q and KV (as in GQA) or between Q and a single KV head (as in MQA), GroupSharing takes $n_q$ and $n_i$ (for $i \in \{k, v\}$) as arguments and computes the sharing pattern dynamically. The index mapping $\text{idx}_i = \text{idx}_q \cdot n_i / n_q$ in FlexHeadFA is the implementation-level expression of this conceptual unification.

**Caveat.** This is primarily a **conceptual and engineering contribution**, not a theoretical advance in attention mechanisms. The mathematical operations (dot product, softmax, weighted sum) are unchanged. The novelty is in recognizing that the constraints $n_k = n_v$ and $d_k = d_v$ are **artifacts of the original MHA design choices, not requirements of the attention operation**, and that removing them opens up a productive design space.

**Anchor.** Figure 3 (the comparison diagram showing MHA, MQA, GQA, and DiffQKV side-by-side), Section 2 formulation, and Appendix B.1.

### Innovation 4: Verifying That Asymmetric Compression Efficiency Gains Are Realizable in Practice Through Kernel Engineering

The paper makes a distinctive **engineering validation contribution**: it demonstrates that the theoretical efficiency gains from differential K-V compression can actually be realized on modern GPU hardware, but only by modifying the assumptions baked into standard attention kernels. This is a contribution of a different kind—it's about bridging the gap between architectural ideas and deployable systems.

**Why this is a genuine contribution.** In the space of efficient transformer research, it's common to propose architectural changes that look good on paper but cannot be efficiently implemented because the underlying kernels (FlashAttention, cuDNN, etc.) make assumptions that the new architecture violates. For example, many sparse attention patterns are theoretically more efficient than dense attention, but implementing them with competitive wall-clock speed requires custom kernels that are difficult to write, maintain, and integrate with serving frameworks. A paper that stops at "we propose an architecture with $n_k \neq n_v$" without addressing the kernel problem would leave the efficiency gains as purely theoretical.

**What the paper actually did.** The authors identified a specific hard-coded constraint in FlashAttention2—the assumption that $n_k = n_v$ and that $n_q$ is an integer multiple of both—and replaced it with a flexible address-probing scheme (FlexHeadFA) that computes K and V head indices from the Q head index at runtime. They then validated this kernel's performance using both Kernel Execution Time (KET, measured via NVIDIA Nsight Systems) and Cuda Event Elapsed Time (CEET), confirming that the split kernel benefits from reduced K head count (27.21% improvement at 32k prefix length) while the combine kernel is unaffected (near-zero change), exactly as the theoretical analysis predicts.

**The significance beyond this paper.** By releasing the FlexHeadFA implementation and explicitly calling for "broader DiffQKV support" in vLLM, TensorRT-LLM, and FlashAttention, the paper is doing the engineering groundwork that could enable an ecosystem of differentially-compressed attention architectures. The KV Group Sharing compatibility workaround (Appendix E) shows the authors thought carefully about the deployment pipeline: they provide a drop-in solution for standard frameworks (even though it negates the speedup) and a high-performance solution for custom deployments. This dual-track approach is rare in architecture papers and reflects a pragmatic understanding that new architectural ideas only matter if they can be deployed.

**What makes this more than "just engineering."** The paper's efficiency analysis (Section 3) provides a **quantitative model** of where the speedup comes from—the theoretical 37.5% KV cache reduction, the asymptotic convergence, the divergence between KV cache and attention computation—and then validates this model against empirical measurements. The fact that the KET-measured split kernel improvement approaches but doesn't quite reach the theoretical bound, that the combine kernel shows no improvement, and that the crossover point (where SIGMA becomes faster than GQA) shifts earlier as output length increases—all of these are *predictions* of the model that the measurements confirm. This transforms the paper from "we built a faster kernel" to "we characterized *why* it's faster and *when* the speedup materializes," which is more scientifically valuable and more useful for practitioners deciding whether to adopt the architecture.

**The limitation.** The paper acknowledges that custom kernel requirements are a barrier to adoption. FlexHeadFA is not upstreamed into FlashAttention mainline (at least at the time of writing), and the authors "emphasize the need for broader DiffQKV support." The efficiency gains are real but currently gated on engineering effort from the community or the FlashAttention maintainers.

**Anchor.** Section 3.2–3.3, Figures 1–2, Table 15, FlexHeadFA detail in Section 3.2, Appendix E for KV Group Sharing, Appendices F–G for detailed efficiency results.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The architecture design experiments (Observations 1–4 in Section 2) use 100B tokens sampled from FineWeb-Edu (Penedo et al., 2024) for pre-training the 1B-scale testbed models. The downstream evaluation for these scoping experiments uses 9 commonsense reasoning and text understanding benchmarks: HellaSwag, OpenBookQA, WinoGrande, ARC Challenge, PIQA, SciQ, BoolQ, LogiQA, and LAMBADA. The full SIGMA models are pre-trained on 6T tokens combining general-domain data (DCLM and FineWeb-EDU, deduplicated and quality-filtered), math data (proof-pile-2 plus filtered general-domain math), code data (filtered following StarcoderV2's method), and 1T tokens of synthesized/rewritten data. System-domain evaluation uses the custom AIMICIUS benchmark across four tasks: CMDGen (2,838 training / 395 test), Infrawise (422 training / 911 test), Optiflow (8,000 training / 1,258 test), and NL2KQL (5,166 training / 43 test). General-domain evaluation uses the same 9 benchmarks as the scoping experiments plus MMLU, MMLU-Pro, BBH, HumanEval, MBPP, MATH, and GSM8K.

- **Base model(s).** The scoping experiments (Section 2) use a 1B-parameter model with 22 transformer layers and a hidden dimension of 2048, trained from scratch for each architectural variant. The production models are SIGMA-1.5B (26 layers, hidden dimension 2048, FFN dimension 6144, augmented Q dimension 3072, $n_q = 32$, $n_k = 4$, $n_v = 16$) and SIGMA-10B (32 layers, hidden dimension 4096, FFN dimension 14336, augmented Q dimension 6144, same head configuration). For the system-domain evaluation, SIGMA-10B is further fine-tuned with full-parameter supervised fine-tuning on per-task datasets. The efficiency comparison uses a "standard model" (STD) matching SIGMA-1.5B's architecture but with conventional GQA ($n_k = n_v = 16$) and no augmented Q, enabling isolated measurement of DiffQKV's efficiency impact.

- **Metrics.** For the architecture scoping experiments, the primary metric is the average accuracy across the 9 benchmarks. For the AIMICIUS system-domain benchmark, each task has custom metrics: CMDGen uses CMD Score (cosine similarity of command embeddings via all-MiniLM-L6-v2), Output Score (cosine similarity of execution results), Calibration Score (thresholded combination), Exact Match, Success Ratio, and Accuracy (the primary metric: Exact Match OR Success Ratio); Infrawise uses per-component accuracy (Target, Baseline, Criterion, Workload) plus DCW correctness, Benchmark Result Recall, and Benchmark Result Accuracy (the primary: all relevant results retrieved, no irrelevant results); Optiflow uses Code Detected, Code Executable, Plan Valid, and Plan Improved (the primary: latency reduction from initial to improved plan); NL2KQL uses Syntax Accuracy, Jaccard Similarity, and per-component scores (Cluster, Database, Table, Column). For general-domain evaluation, standard task-specific accuracy metrics are used. For efficiency analysis, two latency metrics are employed: Cuda Event Elapsed Time (CEET), which places checkpoints in code for end-to-end module timing, and Kernel Execution Time (KET), measured via NVIDIA Nsight Systems (nsys) for precise GPU kernel timing.

- **Baselines.** For the architecture scoping experiments, the baselines are standard MHA ($n_k = n_v = 32$), GQA with $n_k = n_v = 16$, and GQA with $n_k = n_v = 4$, all with $n_q = 32$ and equal head dimensions. For system-domain evaluation, baselines are GPT-4 (Bubeck et al., 2023), DeepSeek-Coder-7b-Instruct-v1.5 (Xin et al., 2024), Qwen2.5-Coder-7B-Instruct (Yang et al., 2024), and LLaMA3-8B-Instruct (Dubey et al., 2024). For general-domain evaluation at the 1.5B scale, baselines include Pythia-1.0B/1.4B (Biderman et al., 2023), TinyLlama-1.1B (Zhang et al., 2024a), Bloom-1.1B (Muennighoff et al., 2022), OLMo-1.2B (Groeneveld et al., 2024), OPT-1.3B (Zhang et al., 2022), CerebrasGPT-1.3B (Dey et al., 2023), Phi1-1.3B (Gunasekar et al., 2023), DCLM-1.4B (Li et al., 2024), StableLM2-1.6B (Bellagente et al., 2024), SmolLM-1.7B (Allal et al., 2024), and Gemma-2B (Team et al., 2024). For efficiency analysis, the primary baseline is the standard model (STD)—a hypothetical GQA model with $n_k = n_v = 16$ and no augmented Q, identical in all other respects to SIGMA-1.5B.

- **Generation budget / compute accounting.** The architecture experiments use a fixed training budget of 100B tokens for all variants, with models scaled to approximately 1B parameters. For efficiency experiments, both SIGMA-1.5B and STD are evaluated with output lengths and prefix lengths independently swept in a grid of [2k, 4k, 8k, 16k, 32k, 64k] for CEET, and prefix lengths [2k, 4k, 16k, 32k] with output length fixed at 10 for KET. All efficiency experiments run on a single NVIDIA H100 80G HBM3 GPU. The theoretical analysis models KV cache cost as proportional to the total number of elements: $L = \alpha \cdot [b \cdot s \cdot (n_k \cdot d_k + n_v \cdot d_v)] + \beta$, with the asymptotic reduction rate $r$ computed as the relative difference in cache element count between GQA and SIGMA as $s \to \infty$.

- **Cross-validation / statistical protocol.** The architecture scoping experiments train each variant once from scratch on 100B tokens—no multiple seeds or cross-validation is reported. For the system-domain evaluation, models are fine-tuned on task-specific SFT datasets and evaluated on held-out test sets; no cross-validation is mentioned. For efficiency experiments, CEET and KET are measured as raw hardware timings without statistical aggregation across multiple runs (though the paper notes CEET "may be unstable at small absolute time scales"). A t-test is performed on the relative improvement ratio of the Augmented Q module to verify its expectation is zero (computed T-value = −0.214, P-value = 0.832), confirming the module's cost is independent of prefix and output length. For the general-domain benchmark comparison, all baselines are re-evaluated under a unified setup to ensure fair comparison, with differences from original reports explicitly noted in Table 7.

### Main Quantitative Results

#### Architecture Scoping Experiments: Differential Sensitivity of K vs. V Compression

The foundational result is the asymmetric impact of head count compression on K versus V, shown in Table 1 (and detailed in Table 9). Starting from MHA with $n_k = n_v = 32$ (baseline average 52.40 across 9 benchmarks), reducing V heads by 50% ($n_v = 16$) drops performance by 0.66 points to 51.74, while the identical reduction applied to K heads ($n_k = 16$) actually *improves* performance by 0.43 points to 52.83. The asymmetry persists and widens at higher compression ratios. Starting from GQA with $n_k = n_v = 16$ (baseline 52.14), a 75% reduction in V heads ($n_v = 4$) costs 0.38 points (to 51.76), while a 75% reduction in K heads ($n_k = 4$) costs only 0.17 points (to 51.97)—less than half the degradation. At the extreme, starting from GQA with $n_k = n_v = 4$ (baseline 51.66), reducing V heads to 1 (MQA-style) costs 0.63 points (to 51.03), while reducing K heads to 1 costs essentially nothing (51.67, a 0.01-point increase).

The dimension compression results in Table 2 (detailed in Table 10) establish a second, independent axis of asymmetry. Halving K head dimension ($d_k = d_v / 2$) with a trainable feed-forward alignment layer produces negligible performance change across three baselines: MHA with half K dim yields 52.56 vs. 52.40 baseline (+0.16), GQA $n_k = 16$ yields 52.06 vs. 52.14 (−0.08), and GQA $n_k = 4$ yields 51.92 vs. 51.66 (+0.26). In no case does the performance change exceed 0.3 points.

The augmented Q experiments in Table 3 (detailed in Table 11) demonstrate consistent improvement from adding parameters to Query, with the gain proportional to KV compression severity. On MHA (no KV compression), AugQ at $d_q^{\text{aug}} = 5632$ adds 0.63 points (52.40 → 53.03). On GQA $n_k = n_v = 16$ (moderate compression), AugQ at $d_q^{\text{aug}} = 3072$ adds 1.24 points (52.14 → 53.38), with diminishing returns at higher augmentation factors ($d_q^{\text{aug}} = 4096$: +0.79; $d_q^{\text{aug}} = 5632$: +0.93). On GQA $n_k = n_v = 4$ (aggressive compression), AugQ at $d_q^{\text{aug}} = 5632$ adds 1.47 points (51.66 → 53.13)—the largest gain observed.

The AugQ vs. AugF comparison in Table 4 (detailed in Table 12) confirms Q augmentation's parameter efficiency advantage. At equal added parameters (both adding $\delta = 3072$ to a baseline of 52.14), AugQ achieves 53.38 (+1.24) while AugF achieves 53.26 (+1.12). Doubling the FFN expansion to AugF($2\delta$) yields only 53.16 (+1.02)—worse than AugQ($\delta$) despite twice the parameter increase. The gains are roughly additive: AugF($\delta$) + AugQ($\delta$) achieves 54.55 (+2.41), close to the sum of individual improvements (1.12 + 1.24 = 2.36). The highest recorded performance, 55.09 (+2.95), comes from AugF($3\delta$) + AugQ($\delta$), essentially tied with AugF($5\delta$) alone at 55.08 (+2.94).

The combined strategy experiment in Table 13 shows that integrating all three optimizations—AugQ ($d_q^{\text{aug}} = 3072$), 75% K head reduction ($n_k = 4$), and K dimension halving ($d_k = d_v / 2$)—yields 52.61, which outperforms the original GQA baseline (52.14) by 0.47 points while substantially reducing K cache.

#### Efficiency Analysis: Kernel and End-to-End Timing

The KET results in Table 15 and Figure 1 provide precise GPU kernel timing. At prefix length 32k with output length 10, the split kernel (primary attention computation) shows 27.21% relative improvement (STD: 27.5M ns → SIGMA: 20.0M ns), while the combine kernel (output assembly) shows essentially no change (−0.93%, from 1.99M ns to 2.01M ns). The total KET improvement is 25.31% (29.5M ns → 22.1M ns). The split kernel improvement scales with prefix length: 1.17% at 2k → 25.33% at 4k → 26.30% at 16k → 27.21% at 32k, asymptotically approaching the theoretical 37.5% bound.

The CEET results in Figure 2 show total attention layer cost (KV Cache + Attention Computation + Augmented Q) across a grid of output and prefix lengths. At 2k output (Figure 2a), SIGMA is slower than STD for prefix lengths below ~16k—the gray dotted crossover line appears around 16k prefix. At 4k output (Figure 2b), the crossover shifts to ~4k prefix. At 8k output (Figure 2c), SIGMA is faster at all tested prefix lengths ≥2k. At 16–64k output (Figures 2d–2g), SIGMA is consistently faster, with the absolute time gap widening. The maximum measured improvement occurs at 64k output + 64k prefix (Figure 2g): SIGMA reduces total cost by 33.36%—the headline efficiency number.

The Augmented Q module's CEET cost (Figure 4) is verified to be invariant to prefix and output length, with the relative improvement ratio consistently near zero across all tested configurations. The t-test (T = −0.214, P = 0.832) fails to reject the null hypothesis that the ratio has expectation zero.

The KV Cache module's CEET analysis (Figure 5) shows the strongest alignment with theory. At 64k prefix and 64k output, SIGMA achieves a 36.57% reduction in KV cache operations—close to the theoretical 37.5%. The Attention Computation module's CEET (Figure 6) shows more modest but still substantial improvement, reaching up to 15.4% reduction at long contexts, with the deviation from theory attributed to operations not directly influenced by K head count (combine kernel, softmax, context switching overhead).

On the CMDGen NVIDIA subtask, SIGMA-SYSTEM-10B achieves 87.5 CMD Score and 74.5 Accuracy, compared to GPT-4 at 84.0 and 25.0 respectively—an absolute improvement of 49.5 percentage points on Accuracy. ### Ablation Studies and Robustness Checks

**K head reduction vs. V head reduction at multiple baseline compression levels**: The paper tests 50% reduction from MHA (32 → 16 heads) and 75% reduction from two GQA baselines (16 → 4 and 4 → 1) in Table 1 and Table 9. The consistent pattern—K reduction costs less than V reduction in every comparison, often substantially so—rules out the possibility that the result is an artifact of a particular baseline compression ratio. The effect is present at both moderate (50%) and aggressive (75%) reduction levels, and for both MHA (no sharing) and GQA (existing sharing). The one anomalous result is the 50% K reduction from MHA actually improving performance (+0.43 in Table 1), which may reflect regularization from the reduced parameter count at small scale.

**K dimension halving across architectures**: Table 2 and Table 10 test three different baseline architectures (MHA, GQA $n_k = 16$, GQA $n_k = 4$), showing the effect of halving $d_k$ is consistently negligible (−0.08 to +0.26). This suggests the K dimension compression tolerance is not an interaction effect with the head count compression—it holds independently across all tested configurations.

**Augmented Q scaling factor sweep**: Table 3 and Table 11 test three augmentation sizes for the GQA $n_k = 16$ baseline: $d_q^{\text{aug}} = 3072$ (×1.5 hidden dim, +1.24), $d_q^{\text{aug}} = 4096$ (×2.0, +0.79), and $d_q^{\text{aug}} = 5632$ (×2.75, +0.93). The non-monotonic relationship—with ×1.5 outperforming larger expansions—indicates overfitting at small scale (100B tokens, 1B parameters). This is a genuine negative result: blindly increasing Q capacity beyond a moderate factor does not yield proportional benefits and can actually reduce gains. This directly informs the final architecture's choice of 1.5× for both SIGMA-1.5B and SIGMA-10B.

**AugQ vs. AugF at multiple expansion levels**: Table 4 and Table 12 systematically compare Q augmentation against FFN expansion at four FFN sizes (AugF with $\Delta d_F \in \{\delta, 2\delta, 3\delta, 5\delta\}$ where $\delta = 3072$). At every comparable parameter count, AugQ provides more benefit per parameter. The additive nature of the gains (AugQ + AugF combinations consistently outperform either alone) rules out the possibility that they are capturing the same variance—they contribute independently.

**Combined strategies**: Table 13 tests all 8 combinations of three binary choices (AugQ: yes/no, 75% K head reduction: yes/no, K dim halving: yes/no). The combination with all three optimizations (52.61) outperforms the original GQA baseline (52.14), confirming the strategies are compatible. Interestingly, the combination of K dimension compression + 75% K head reduction without AugQ (51.74) performs slightly below baseline (52.14), while with AugQ it recovers and exceeds baseline (52.61)—suggesting that AugQ partly compensates for the capacity lost through aggressive compression.

**Selective V cache fetching**: Table 8 tests loading only the top-100 V vectors (by attention score) for attention output computation across three baselines. The performance impact is negligible: MHA drops 0.30 points (52.40 → 52.10), GQA $n_k = n_v = 16$ drops 0.06 points (52.14 → 52.08), and GQA $n_k = n_v = 4$ actually improves 0.01 points (51.66 → 51.67). This confirms that attention score sparsity (>95%) can be exploited for V-side memory savings without architectural changes, and validates this as an optional composable optimization on top of DiffQKV.

**System domain continued pre-training**: Table 16 shows that adding the 19.5B system-domain pre-training data before fine-tuning improves CMDGen NVIDIA Accuracy by +1.5 points for Mistral-7B (30.7 → 32.2) and +6.4 points for LLaMA3-8B (50.7 → 57.1). This ablation demonstrates that the domain data value is not solely captured through fine-tuning—the pre-training exposure provides complementary benefits.

**Augmented Q cost invariance**: Figure 4 demonstrates through CEET measurements that the Augmented Q module's cost is constant regardless of prefix length and output length, and the relative improvement ratio between STD and SIGMA for this module is statistically indistinguishable from zero (t-test T = −0.214, P = 0.832). This validates the paper's claim that Q augmentation's inference cost is independent of sequence length and therefore does not diminish the long-context efficiency gains.

**KET vs. CEET consistency**: The KET-measured improvement for the split kernel (27.21% at 32k prefix, Table 15) is higher than the CEET-measured attention computation improvement (up to 15.4%, Figure 6h). The paper explicitly attributes this to CEET capturing end-to-end overhead (context switching, CPU operations) that KET excludes, providing methodological transparency about what each metric measures.

**KV cache CEET approaching theoretical bound**: Figure 5h shows the relative CEET improvement for KV cache operations reaching 36.57% at 64k prefix + 64k output, very close to the theoretical 37.5%. The convergence toward this asymptotic bound as sequence length increases validates the linear cost model $L = \alpha \cdot [b \cdot s \cdot (n_k \cdot d_k + n_v \cdot d_v)] + \beta$ and confirms that the measured improvement is genuinely attributable to the reduced K cache size rather than other architectural differences.

### Critical Assessment

The experiments genuinely support the paper's central architectural claim—that K compression is substantially less harmful than V compression—with a consistent pattern across multiple baselines, compression ratios, and both head count and dimension axes. All comparisons in Tables 1, 2, 9, and 10 point in the same direction. The claim that augmented Q boosts performance is equally well-supported across architectures and augmentation scales (Tables 3, 11). The claim that Q augmentation is more parameter-efficient than FFN expansion (Table 4, 12) is clear and substantiated. These are the empirical pillars on which the DiffQKV design rests, and the evidence for them is internally consistent and methodical.

The claim of "up to 33.36% inference speed improvement" is **supported but narrowly scoped**. This figure is measured only at the maximum tested sequence lengths (64k output + 64k prefix) in Figure 2g, and only for the SIGMA-1.5B vs. STD comparison. At short sequences, SIGMA is slower (Figure 2a: crossover at ~16k prefix for 2k outputs). The 33.36% number is a ceiling, not a typical improvement. The paper is transparent about this limitation in Figure 2, but the abstract's unqualified "up to 33.36% improvement" may overstate the practical benefit for users who primarily work with shorter contexts.

Several significant weaknesses in the experimental design temper the strength of the conclusions:

**Single training scale for architecture experiments.** All Observations 1–4 are derived from 1B-parameter models trained on 100B tokens. The paper does not demonstrate that the differential sensitivity of K vs. V to compression, the optimal 1.5× Q augmentation factor, or the parameter efficiency advantage of AugQ over AugF hold at larger scales (e.g., 7B, 13B, 70B). Architecture design insights from small-scale experiments do not always transfer—phenomena like attention head redundancy, the value of added capacity, and overfitting dynamics are scale-dependent. The final 1.5B and 10B models adopt the configurations derived from 1B experiments without validation that the 1B-scale findings generalize. This is a necessary practical compromise (full-scale architecture sweeps are prohibitively expensive), but it means the architectural decisions for SIGMA-10B are extrapolations, not directly validated choices.

**Single training data distribution for architecture experiments.** All Observations 1–4 use 100B tokens from FineWeb-Edu, a web-text dataset. The differential importance of K vs. V might depend on the nature of the training data—for example, code (with its long-range syntactic dependencies) or math (with its logical structure) might place different demands on K and V representations. The full SIGMA models are trained on a mixture of general, math, code, and synthetic data, but the architecture was optimized for web-text. This mismatch is not explored.

**No multi-seed training for architecture experiments.** Each architectural variant in Tables 1–4, 8–13 is trained exactly once. Without error bars, we cannot distinguish a genuine architectural improvement from training noise, especially for the small differences involved (e.g., 0.08–0.66 point changes on average across 9 benchmarks). The 1B scale models likely have high run-to-run variance. The AugQ non-monotonicity ($d_q^{\text{aug}} = 4096$ being worse than $3072$) could be noise rather than a genuine overfitting signal.

**Efficiency baselines are idealized.** The STD model used for efficiency comparison is not a real deployed model—it's a hypothetical GQA variant constructed to be identical to SIGMA except for the attention configuration. This isolates the DiffQKV effect cleanly, but it means the comparison doesn't account for real-world factors that might affect the relative efficiency: kernel launch overhead differences, memory access pattern effects, or interaction with other system-level optimizations (paged attention, continuous batching, prefix caching). A comparison against a production-optimized GQA model like LLaMA-3.2-1B or a similarly-sized Mistral variant would be more informative about practical deployment benefits.

**The system-domain baseline comparisons conflate architecture and training data.** SIGMA-SYSTEM-10B outperforms GPT-4, DeepSeek-Coder, Qwen, and LLaMA3 on AIMICIUS (Table 6), but this comparison conflates three differences: (1) SIGMA's DiffQKV architecture, (2) its domain-specific pre-training on 19.5B system-domain tokens, and (3) its domain-specific fine-tuning. The continued pre-training ablation in Table 16 begins to disentangle the training data effect (showing +1.5 to +6.4 Accuracy improvement from domain pre-training on top of fine-tuning alone), but it doesn't isolate the architecture contribution. There's no experiment comparing SIGMA-SYSTEM against an identically-trained model with standard GQA architecture. The paper's strong system-domain results primarily demonstrate the value of domain-specific data curation and fine-tuning—a contribution in its own right, but one that is independent of the DiffQKV innovation. The claim "SIGMA demonstrates performance on par with the latest state-of-the-art models across general domains" (Table 7, average 61.6) similarly cannot isolate DiffQKV's contribution from SIGMA's training data recipe and training procedure.

**Limited scale range for general-domain evaluation.** SIGMA-1.5B is compared against models from 1.0B to 2.0B parameters, and placing 4th–5th out of 12 in average performance (Table 7) is respectable. But this doesn't directly validate that DiffQKV's efficiency gains come "for free" in terms of model quality—the best-performing models in the comparison (DCLM-1.4B at 62.8, Gemma-2B at 62.2) use different architectures and different training data. Without an ablation that trains two identically-sized models on identical data with GQA vs. DiffQKV attention at the 1.5B scale and full 6T token budget, we cannot conclude that DiffQKV matches GQA's performance while being more efficient—the signal is swamped by data and training differences.

**Missing ablation: DiffQKV vs. GQA with matched parameter count at production scale.** The architecture scoping experiments (1B, 100B tokens) show that differential KV compression with AugQ can match or exceed GQA performance. The 1.5B model's general-domain results are competitive but not dominant. A direct, controlled comparison at the 1.5B scale—DiffQKV vs. GQA, same data, same training recipe, matched or comparable total parameters—is the critical missing experiment for validating that DiffQKV's efficiency benefits do not come at a performance cost. The paper never runs this ablation, relying instead on the scoping experiments at smaller scale and the competitive-but-not-definitive comparison against heterogeneous external baselines.

**Augmented Q's contribution to total parameters and training cost is not analyzed.** The Augmented Q module adds substantial parameters—roughly $3d_m^2$ per layer for the gated linear unit projections. At the 1.5B scale with $d_m = 2048$, this is approximately $3 \times 4.2\text{M} \approx 12.6\text{M}$ parameters per layer × 26 layers ≈ 327M parameters just for the Q augmentation. The paper never reports what fraction of the total 1.5B parameters comes from AugQ, nor does it compare a DiffQKV model with an equally-sized GQA model that invests those parameters elsewhere (e.g., wider FFN, more layers). This is the missing counterfactual: is DiffQKV's performance advantage over GQA at equal total parameters, or does it rely on having more total parameters thanks to the "free" Q augmentation? The AugQ vs. AugF comparison in Table 4 addresses this at 1B scale (showing AugQ beats AugF at equal added parameters), but this is at the scoping scale with 100B tokens, not at production scale. A 1.5B GQA model with a proportionally wider FFN (to match total parameter count) could be a stronger baseline than the comparisons in Table 7, where model sizes vary from 1.0B to 2.0B.

**AIMICIUS test set sizes are very small for some subtasks.** NL2KQL has only 43 test cases (Table 5, Section 4). Infrawise has 911 test cases, but these are presumably structured—DCW generation metrics and benchmark retrieval metrics may be highly correlated across test cases sharing the same underlying database. The CMDGen test set (395 cases) is larger but still modest for evaluating generalizable command generation capability. Optiflow has 1,258 test cases, but Plan Improved depends on comparing two code generations, which may have high variance. The 52.5% "absolute improvement" over GPT-4 and the near-zero baselines on Plan Improved (GPT-4: 0.5%, DeepSeek: 0%, Qwen: 0%, LLaMA: 1.1%) suggest these tasks are extremely difficult for general models—a finding that is stark but should be contextualized by the small, domain-specific test sets.

**Efficiency measurements don't include batching effects or multi-user serving scenarios.** All efficiency experiments use a single sequence (no batching, though the theoretical model includes batch size $b$). In production serving with continuous batching, the relationship between K cache reduction and throughput improvement may differ from the single-sequence measurements because memory bandwidth contention and scheduling dynamics change. The paper notes SIGMA enables larger batch sizes due to reduced memory consumption, but this benefit is not empirically measured.

**The KV Group Sharing workaround's performance cost is not quantified.** The paper states it "negates the efficiency improvements entirely by degrading to GQA" (Section 3.2), but provides no timing measurements for this fallback path. Users who cannot deploy FlexHeadFA (the majority of current practitioners) would experience no efficiency gain, and the paper doesn't quantify how much slower KV Group Sharing is versus native FlexHeadFA.

## 6. Limitations and Trade-offs

### The Architecture Design Space Was Explored at Only One Scale, and the Optimal Configuration May Not Transfer

**The assumption.** The four observations that prescribe the DiffQKV configuration—differential K vs. V compression sensitivity, the near-zero cost of halving K dimension, the optimal 1.5× Q augmentation factor, the parameter-efficiency advantage of AugQ over AugF—are all derived from a single experimental setup: 1B-parameter models with 22 layers and hidden dimension 2048, trained on 100B tokens of FineWeb-Edu. The paper does not conduct any architecture sweeps at larger scales. The final SIGMA-1.5B and SIGMA-10B models inherit these 1B-scale findings directly: both use the same 1.5× AugQ factor, the same 4 Key heads, the same 16 Value heads, and the same decision to compress K only via head count (not dimension), as stated in Appendix B.5:

> "For the sake of balancing the model performance and the cost of the KV cache, during the training of SIGMA-1.5B and SIGMA-10B, no dimension compression is applied to the K heads. Only the number of K heads was decreased."

**The consequence.** Architecture design insights from small-scale experiments do not reliably transfer to larger scales. Several phenomena that shape the observations could shift with model size: (1) The differential sensitivity of K vs. V to compression might narrow or widen—larger models have more redundant representational capacity, potentially making both K and V compression less harmful, or the increased depth might amplify the effect of V degradation as it propagates through more layers. (2) The optimal AugQ scaling factor might change—a 1B model's capacity is constrained differently than a 10B model's, and the non-monotonicity observed at 1B scale ($d_q^{\text{aug}}$ = 3072 outperforming 4096 and 5632 in Table 3) might reflect 1B-scale-specific overfitting rather than a universal sweet spot. (3) The parameter-efficiency comparison between AugQ and AugF might shift at scale, since FFN expansion benefits are known to exhibit different scaling behavior than attention-side capacity increases. If the 1B-scale optimal configuration is suboptimal at 10B, the production SIGMA models would leave performance on the table—or worse, might have made the wrong tradeoff (e.g., compressing K too aggressively for the model's capacity).

**What evidence exists in the paper.** The paper provides no cross-scale validation. There is no experiment showing that reducing K heads from 16 to 4 has the same negligible effect at 1.5B or 10B as it does at 1B. There is no sweep of AugQ factors at larger scales. The 1.5B and 10B models are evaluated only in their final configuration, so we cannot tell whether alternative choices (e.g., $n_k = 8$ instead of 4, AugQ at 2× instead of 1.5×, or applying K dimension compression) would have produced better or worse results at production scale. The paper acknowledges this gap only indirectly in the Future Work section (Appendix I): "Key areas for investigation include the trade-off between Augmented Q and Feed-Forward Network parameters, varied key-value compression across layers, and appropriate hyper-parameters for scale up."

**Mitigation status.** Not addressed. The paper treats the 1B-scale observations as sufficient justification for the production architecture decisions. The only partial mitigation is that the final 1.5B and 10B models' competitive benchmark performance (Tables 7 and 17) provides weak validation that the chosen configuration is at least reasonable—but not that it is optimal or near-optimal among the DiffQKV design space. A practitioner cannot know whether a differently-configured DiffQKV model would have performed better, and cannot confidently apply the 1.5× AugQ / 4 K-head prescription to their own model at a different scale without independent validation.

---

### The Efficiency Gains Require a Custom Attention Kernel Not Available in Standard Frameworks, and the Compatibility Workaround Negates Them Entirely

**The assumption.** The paper's headline efficiency improvements depend on FlexHeadFA, a modified FlashAttention2 kernel that replaces the hard-coded assumption $n_k = n_v$ with address probing based on Query head index mapping. Section 3.2 states the problem explicitly:

> "the official FlashAttention supports attention computations only when $n_k$ equals $n_v$, and $n_q$ is an integer multiple of $n_k$ and $n_v$, which could not be directly applied to SIGMA."

The paper provides FlexHeadFA as the solution, but also provides a fallback—KV Group Sharing (Appendix E)—that replicates the smaller K tensor to match the V tensor's head count, making the model compatible with unmodified FlashAttention2. However, the paper is explicit about the cost:

> "this approach is highly discouraged, as it negates the efficiency improvements entirely by degrading to GQA."

**The consequence.** The practical efficiency benefit of DiffQKV is gated on non-standard software infrastructure. As of this writing, FlexHeadFA is not upstreamed into FlashAttention mainline, vLLM, TensorRT-LLM, or any other major inference framework. A practitioner who wants to deploy SIGMA with its claimed efficiency benefits must either: (1) maintain a custom fork of FlashAttention2 with the FlexHeadFA modifications, accepting the engineering burden of tracking upstream changes, debugging, and ensuring correctness across GPU architectures and CUDA versions; (2) use the KV Group Sharing fallback and accept that they get no efficiency improvement at all—the model runs at GQA-equivalent speed while carrying the augmented Q overhead, making it actually *less* efficient than a standard GQA model; or (3) wait for the community to adopt DiffQKV-aware kernels, with no timeline. This dramatically reduces the practical impact of the paper's main contribution. The headline "33.36% improvement" is real in the paper's controlled experiments but currently unrealizable for any practitioner using standard tooling. The paper explicitly calls for ecosystem support: "we propose our current solutions and emphasize the need for broader DiffQKV support," but provides no roadmap for upstreaming.

**What evidence exists in the paper.** The paper provides extensive efficiency measurements with FlexHeadFA (Section 3.3, Figures 1–2, Table 15) and thoroughly characterizes when the benefits materialize (long contexts) versus when they do not (short contexts). But the paper provides no timing measurements for the KV Group Sharing fallback—it states that it "negates the efficiency improvements" without quantifying the overhead. A practitioner cannot tell from the paper whether KV Group Sharing runs at the same speed as the STD baseline, slightly slower (due to the replication operation), or noticeably slower. More critically, the paper provides no benchmark numbers or even an estimate of the engineering effort required to integrate FlexHeadFA into a production serving stack.

**Mitigation status.** Partially addressed through the provision of both paths (FlexHeadFA and KV Group Sharing), but not resolved. The paper treats the kernel integration problem as a community challenge rather than something it solves. The availability of FlexHeadFA as a reference implementation reduces but does not eliminate the practical barrier—someone still needs to maintain it, verify it, and integrate it with the rest of the inference stack (paged attention, continuous batching, quantization, tensor parallelism). A practitioner evaluating whether to adopt DiffQKV must weigh the uncertain timeline of ecosystem support against the efficiency gains, and the paper provides no guidance for this decision.

---

### The System-Domain Results Cannot Isolate the Architecture's Contribution from the Training Data's Contribution

**The assumption.** The paper presents SIGMA-SYSTEM-10B's performance on AIMICIUS (Table 6) as evidence of the model's capability, with dramatic improvements over GPT-4 (up to 52.5% absolute improvement). However, SIGMA-SYSTEM differs from these baselines along multiple axes simultaneously: (1) the DiffQKV architecture, (2) pre-training on 19.5B tokens of carefully curated system-domain data (Table 5: arXiv papers, StackOverflow, technical blogs, Azure documentation), (3) domain-specific supervised fine-tuning on per-task datasets (e.g., 2,838 examples for CMDGen NVIDIA), and (4) a general pre-training recipe (6T tokens with specific math, code, and synthetic data phases) that may differ from the baselines' training. The paper does not disentangle these factors.

**The consequence.** The strong AIMICIUS results primarily demonstrate the value of domain-specific data curation and fine-tuning—a contribution with independent merit, but one that provides no evidence about DiffQKV's role. A standard GQA model subjected to the same domain pre-training and fine-tuning pipeline might achieve similar or identical results. The continued pre-training ablation in Table 16 shows that adding the 19.5B domain pre-training data before fine-tuning improves CMDGen NVIDIA Accuracy by +1.5 points for Mistral-7B and +6.4 points for LLaMA3-8B—a substantial effect from the data alone, without any architectural change. This suggests the data contribution may dominate. Without a controlled experiment comparing SIGMA-SYSTEM against an identically-trained GQA model (same data, same recipe, same scale), the paper cannot claim that DiffQKV enables or enhances the system-domain capability. The architecture and the domain specialization are presented as a unified contribution, but they are logically independent and empirically confounded.

**What evidence exists in the paper.** Table 6 provides the system-domain results with architectural baselines (GPT-4, DeepSeek-Coder, Qwen, LLaMA3), but these baselines differ in architecture, pre-training data, pre-training scale, and fine-tuning—making attribution impossible. Table 16 provides the only controlled ablation (domain pre-training on vs. off for Mistral and LLaMA), but this isolates the data effect within standard architectures, not the architecture effect within the domain setting. There is no experiment that trains a GQA model at 10B scale on the exact same data pipeline as SIGMA-SYSTEM-10B and compares them on AIMICIUS.

**Mitigation status.** Not addressed. The paper treats the system-domain specialization and the DiffQKV architecture as two pillars of a single contribution (Sections 1 and 4 describe both as essential to SIGMA), but provides no evidence that the architecture pillar matters for the domain results. The closest the paper comes is the general-domain evaluation (Tables 7 and 17), which shows SIGMA-1.5B is competitive with similarly-sized models on standard benchmarks—but this demonstrates that DiffQKV does not *harm* general capability, not that it *helps* system-domain capability specifically. A reader interested in building a system-domain LLM cannot tell from this paper whether they need DiffQKV or just need the data curation and fine-tuning pipeline.

---

### The Difficulty Estimation Required for Optimal Allocation Is Not Addressed, and the Gains Depend on Sequence-Length-Aware Deployment Decisions

**The assumption.** The paper demonstrates that DiffQKV's efficiency benefits are not uniform—they depend critically on sequence length. Section 3.3 shows that at 2k output length, SIGMA is slower than the GQA baseline for prefixes below ~16k tokens (Figure 2a). The crossover point shifts with output length: at 4k outputs, SIGMA is faster above ~4k prefix (Figure 2b); at 64k outputs, SIGMA is faster even with no prefix (Figure 2g). The maximum benefit (33.36%) materializes only at the longest tested lengths (64k output + 64k prefix). The paper frames this as acceptable:

> "while SIGMA is slightly less efficient than the standard model in short-context scenarios, it shows significant advantages in long-context scenarios, which are common and critical in practical applications."

**The consequence.** Deploying SIGMA is not a simple drop-in replacement for a GQA model. A practitioner must determine, for their specific workload, whether the typical sequence lengths are long enough to put them on the beneficial side of the crossover. If the workload mix skews toward short contexts (many chatbot interactions, simple QA, short code completions), SIGMA will be *less* efficient than GQA—the augmented Q overhead dominates, and the K cache savings are too small to compensate. If the workload includes long contexts (document analysis, multi-turn conversations with accumulated history, system log analysis), the benefits can be substantial. The paper provides crossover curves (Figure 2) for one specific hardware configuration (NVIDIA H100 80G), but these curves likely shift with GPU architecture, memory bandwidth, batch size, and serving framework. There is no guidance for how to predict the crossover point in a different deployment setting, and no model for estimating whether a given workload distribution will benefit on net. The "up to 33.36%" headline number is a point estimate at an extreme operating point, not an expected benefit for typical use.

**What evidence exists in the paper.** Figure 2 provides a comprehensive grid of crossover behavior for SIGMA-1.5B vs. STD on a single H100 GPU, with output lengths [2k, 4k, 8k, 16k, 32k, 64k] and prefix lengths [0, 2k, 4k, 16k, 32k, 64k]. This characterization is thorough for the tested hardware and model scale. However, there is no sensitivity analysis across batch sizes, no measurement on different GPU architectures (A100, H200, consumer GPUs), and no characterization of the 10B model's efficiency behavior at all—all efficiency experiments use the 1.5B model. The paper's theoretical model ($L = \alpha \cdot [b \cdot s \cdot (n_k d_k + n_v d_v)] + \beta$) provides a framework for extrapolation, but the coefficients $\alpha$ and $\beta$ are hardware-specific and not estimated.

**Mitigation status.** Partially addressed through the detailed Figure 2, which at least lets a practitioner assess whether their expected sequence lengths fall in the beneficial regime for H100 hardware at batch size 1. The paper does not provide tools or guidance for predicting the crossover in other settings. The finding that "the cost crossover point shifts earlier as output length increases" is a qualitative insight that may generalize, but its quantitative expression (e.g., crossover at 16k prefix for 2k output vs. 4k prefix for 4k output) is likely hardware-dependent. A practitioner deploying on A100 or with higher batch sizes would need to re-benchmark.

### The FLOPs and Memory Accounting Does Not Include Augmented Q's Training Cost or the Difficulty of Hardware-Aware Deployment

**The assumption.** The paper's efficiency analysis (Section 3) focuses exclusively on inference-time speed and memory, comparing SIGMA against a GQA baseline at equal inference batch configurations. The augmented Q module is presented as "free" from a caching perspective—since Q vectors are never stored, adding parameters to Q does not increase the KV cache footprint. The paper states:

> "adding extra parameters to Q components is more cost-effective than doing so for KV components. ... Q vectors in self-attention do not need to be cached during inference, their impact on memory usage and data transfer duration is minimal."

**The consequence.** This framing elides two significant costs. First, **training cost**: the augmented Q module adds substantial parameters—for SIGMA-1.5B, approximately $3 d_m^2 \approx 12.6\text{M}$ parameters per layer × 26 layers ≈ 327M parameters just for the Q gating projections, out of the total 1.5B. These parameters require gradient computation, optimizer states, and communication during distributed training. The paper never reports the training FLOP or time overhead of AugQ versus a same-total-parameter GQA baseline (where the equivalent parameters might be in the FFN, requiring different training dynamics). A practitioner comparing architectures at equal training budget should account for this. Second, **deployment complexity**: the efficiency crossover behavior (Figure 2) means that realizing the benefits requires hardware-aware batching and scheduling decisions—routing short-context requests to a different model or accepting the overhead—which adds operational complexity not reflected in the per-query timing numbers.

**What evidence exists in the paper.** The paper provides no training cost comparison between DiffQKV and GQA at matched total parameters. The CEET analysis in Figure 4 confirms that AugQ's inference cost is constant with respect to sequence length and statistically indistinguishable between STD (with AugQ attached for measurement) and SIGMA, but this only addresses inference FLOPs, not training. The paper does not report total training time, GPU-hours, or FLOPs for the 1.5B or 10B models, nor does it compare these to what a GQA model of equal total parameters would cost to train.

**Mitigation status.** Not addressed. The paper treats AugQ's parameter count as a pure benefit (more capacity with no inference memory cost) without accounting for the training-side implications. The AugQ vs. AugF comparison in Table 4 addresses *performance* per added parameter but not *training cost* per added parameter—these are different metrics. A model with 327M AugQ parameters might train slower or require different hyperparameters than one with those parameters in the FFN, but the paper provides no evidence either way. The paper also does not discuss whether AugQ affects training stability, convergence speed, or sensitivity to learning rate and batch size—all of which matter for practitioners training models at scale.

### The Hardest System-Domain Benchmarks Show That SIGMA's Capabilities Are Still Far from Production-Ready, and No Amount of Inference Efficiency Can Compensate

**The assumption.** The paper presents SIGMA-SYSTEM's AIMICIUS results as demonstrating "remarkable performance across all tasks, significantly outperforming GPT-4 with an absolute improvement up to 52.5%." This framing emphasizes the relative improvement over baselines, but the absolute performance on several critical metrics reveals fundamental capability gaps that the efficiency improvements do not address. The paper acknowledges this in passing:

> "it is crucial to recognize that its absolute performance in specific tasks, such as Infrawise and NL2KQL, is still subpar."

**The consequence.** On Infrawise, the most critical end-to-end metric—Benchmark Result Accuracy—is only 28.3% for SIGMA-SYSTEM (Table 6). This means that in more than 70% of test cases, SIGMA fails to retrieve the correct benchmark results without including irrelevant ones. The DCW generation component metrics are strong (Target: 95.2, Baseline: 92.9, Criterion: 75.1), but these are intermediate steps—the final retrieval task, which requires reasoning across multiple retrieved candidates and selecting the correct subset, remains largely unsolved. On NL2KQL, the Database Score is 40.7 and the Table Score is 17.4—meaning SIGMA fails to identify the correct database in ~60% of cases and the correct table in ~83% of cases. The Jaccard Similarity of 34.9 is comparable to baselines and indicates that even the best model is producing queries that differ substantially from the ground truth. On Optiflow, the Plan Improved rate of 66.7% means one-third of optimization attempts fail to reduce latency. These are not marginal failures—they represent fundamental task components that the model cannot reliably perform. The efficiency gains from DiffQKV (33.36% faster inference) are irrelevant if the model's answers are wrong 40–83% of the time on critical task components.

**What evidence exists in the paper.** Table 6 provides the per-metric breakdown that reveals these gaps, and Section 5 (Performance Evaluations) includes the acknowledgment of subpar absolute performance. The paper is transparent about the numbers. The limitation is not that the paper hides the low absolute scores, but that it frames them as "room for further improvement" without addressing the possibility that the underlying capability ceiling is architectural or data-limited in ways that efficiency improvements cannot solve. The system-domain task failures (especially benchmark retrieval and NL2KQL) appear to be complex reasoning problems where the model lacks the necessary knowledge or reasoning patterns, not problems solvable by faster inference or longer context.

**Mitigation status.** Acknowledged but not addressed. The paper states: "As part of our future work, we plan to enrich the training dataset and refine the data generation policy to better capture the complexity and variability of these tasks." This is a data-centric mitigation strategy that assumes the failures are due to insufficient training data rather than fundamental model capability limits. It does not address whether a 10B model—regardless of training data—can achieve the multi-step reasoning and precise retrieval required for these tasks, or whether larger scale or architectural innovations beyond DiffQKV would be needed. For a practitioner evaluating SIGMA for system-domain deployment, the paper provides no lower bound on expected performance for the hardest subtasks and no evidence that the efficiency improvements translate to better outcomes on these tasks specifically.
