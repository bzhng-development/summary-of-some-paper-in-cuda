# InfLLM-V2: Dense-Sparse Switchable Attention for Seamless Short-to-Long Adaptation

**ArXiv:** [2509.24663](https://arxiv.org/abs/2509.24663)

## 🎯 Pitch

InfLLM-V2 achieves 4x faster inference than dense attention on 32k+ sequences while retaining over 98% of the performance, without introducing any extra parameters. It does this by reusing the standard dense attention parameters in a unified sparse attention design, enabling seamless adaptation from short-sequence pretraining to long-sequence finetuning—unlike NSA which requires three separate key-value projections and disrupts the standard training workflow.

---

## 1. Executive Summary

This paper introduces **dense-sparse switchable attention** (InfLLM-V2), a trainable sparse attention framework that enables LLMs to seamlessly adapt from short-sequence pretraining to long-sequence finetuning without introducing extra parameters—unlike prior approaches such as NSA, which require three separate KV projection sets and a gating module. Evaluated on an 8B-parameter model pretrained on 4k-length sequences, InfLLM-V2 achieves 4× faster inference than dense FlashAttention-2 while retaining 98.1% of the full-attention baseline's performance on long-context understanding (RULER, 32k length) and 99.7% on chain-of-thought reasoning tasks (MATH-500, AIME, LiveCodeBench), establishing that parameter-free architectural alignment with standard GQA—through shared KV projections and a unified sparse attention that fuses selected and sliding attention into a single output—enables effective short-to-long adaptation only when the model can dynamically switch between dense attention for short sequences and sparse attention for long ones.

## 2. Context and Motivation

### The Core Problem: Long Sequences Break Self-Attention

The fundamental challenge this paper addresses is architectural: **the standard self-attention mechanism in Transformers becomes computationally and memory prohibitive as sequence length grows**. This is not a minor implementation inconvenience—it's a structural bottleneck that determines what LLMs can and cannot do in practice.

Self-attention computes pairwise interactions between every token and every other token in a sequence. For a sequence of length $n$, this requires $O(n^2)$ computation and $O(n^2)$ memory to store the attention score matrix. When sequences are short ($n$ in the thousands), this is manageable. But modern LLM applications—deep research tools that ingest entire codebases or academic papers, chatbots that maintain long conversational histories, autonomous agents that accumulate multi-step trajectories, and reasoning models that produce multi-thousand-token chains of thought—routinely push sequence lengths into tens or hundreds of thousands of tokens. At $n = 32\text{k}$, the attention matrix alone requires storing $~10^9$ floating-point values. At $n = 128\text{k}$, it's $~1.6 \times 10^{10}$. The quadratic scaling means even modest increases in context window produce dramatic increases in compute cost.

This matters for two distinct but equally important reasons:

**Real-world deployment cost.** When a model processes a 32k-length prompt on a single A100 GPU, the attention computation alone can consume tens of milliseconds for prefill and add similar overhead per decoding step. Multiply this across millions of queries in production, and the cost difference between linear and quadratic scaling translates directly to infrastructure budgets, latency guarantees, and hardware requirements. The paper's end-to-end measurement in Figure 7 shows that on a 128k sequence with an 8B model at W4A16 quantization, dense attention takes over 40 seconds just to produce the first token on an RTX 4090—a consumer-grade GPU that would otherwise be capable of running an 8B model comfortably for short sequences.

**Capability ceiling.** Compute cost ultimately limits what models can be trained and deployed on. If attention is quadratic, then training on 128k sequences costs $1024\times$ more attention FLOPs than training on 4k sequences (assuming everything else is equal). This creates a harsh economic disincentive against pushing context windows further, which in turn limits the model's ability to learn long-range dependencies, process document-length inputs, or generate extended reasoning traces. The paper operates in exactly this regime: pretraining on 8T tokens at 4k length, then finetuning on 5B tokens at up to 32k length. Without sparse attention, the long-context finetuning would be prohibitively expensive.

### Sparse Attention: The Obvious Solution and Its Two Branches

Sparse attention is the natural response: instead of computing attention between every pair of tokens, restrict each query token to attend to only a carefully chosen subset of key tokens. If each token attends to $k \ll n$ keys, the complexity drops from $O(n^2)$ to $O(nk)$. The central design question is **how to choose which $k$ tokens each query should attend to**—and this is where the field has split into two approaches with fundamentally different tradeoffs.

#### Training-Free Sparse Attention: Exploit the Sparsity That Already Exists

Training-free methods (InfLLM, MInference, Quest, SpargeAttention, and many others) take a model trained with dense attention and, at inference time, selectively compute only a subset of the attention scores. The intuition is that attention matrices in trained Transformers are naturally sparse—most query tokens attend strongly to only a small number of key tokens, with the remaining scores being negligible. If you can identify which keys matter for each query *before* computing the full attention, you can skip the computation for the rest.

The paper surveys two strategies for doing this identification:

- **Predefined sparse patterns** use fixed heuristics: sliding windows (each token attends to its local neighborhood), attention sinks (all tokens attend to the first few tokens), or segment separators. These patterns are derived from human observation of attention behavior—for instance, Xiao et al. (2024b) observed that initial tokens consistently receive high attention scores regardless of the query, suggesting they serve as generic "sinks" that can be included by default.

- **Dynamic sparse patterns** compute cheap similarity scores between queries and candidate key blocks at inference time, then select the top-scoring blocks for each query. This is more flexible than predefined patterns because it adapts to the specific content of each query. Methods like InfLLM (Xiao et al., 2024a) and MInference (Jiang et al., 2024) fall into this category: they partition the key sequence into blocks, compute a lightweight relevance score for each block-query pair (e.g., by averaging query and key representations within blocks), and retain only the top-scoring blocks.

The appeal of training-free methods is obvious: they require no additional training, no architectural changes, and can be applied to any existing dense-attention model. However, the paper identifies a fundamental limitation that has become increasingly clear across the literature:

> "the training-free setting introduces a fundamental trade-off between sparsity and model performance. To avoid significant performance degradation, the degree of sparsity that can be applied is often limited, which in turn restricts the potential efficiency gains."

This is the key tension. When you take a model trained with dense attention and force it to use sparse attention at inference time, you're creating a **distribution mismatch**: the model learned to produce outputs assuming it could attend to all tokens, and now you're restricting its access to only a subset. The more aggressive the sparsity (i.e., the smaller the number of tokens $k$ that each query can attend to), the larger the mismatch, and the more performance degrades.

The paper's own experimental results in Tables 1 and 2 make this concrete. InfLLM (the training-free predecessor to InfLLM-V2) achieves only 27.94% average accuracy on RULER at 32k length, compared to 84.26% for full attention. MInference does better at 73.22%, but still loses over 11 percentage points. On LongBench, InfLLM drops from 42.30 to 32.30; MInference drops to 41.55. On LongPPL (long-sequence perplexity), InfLLM's perplexity balloons from 2.06 to 12.01. These are not marginal degradations—they represent substantial capability losses that would be unacceptable in most production settings.

The root cause is that training-free sparsity relies on **heuristic relevance estimates** (block-averaged attention scores, or predefined sliding window boundaries) that approximate but do not perfectly match the true attention distribution learned during training. When the heuristic selects the wrong blocks for a query, that query loses access to information it needs, and the error compounds through subsequent layers. The only way to mitigate this is to be less aggressive with sparsity—retain more tokens—which directly eats into the efficiency gains that motivated sparse attention in the first place.

#### Trainable Sparse Attention: Teach the Model to Be Sparse from the Start

Trainable methods take the opposite approach: incorporate sparsity into the training process itself so the model learns to produce good outputs given restricted attention patterns. The key advantage is that the model can adapt its representations and its token-to-token routing behavior to compensate for the sparsity, rather than being forced into a sparse regime it was never trained for.

The paper discusses three representative trainable sparse attention approaches:

**SeerAttention (Gao et al., 2024)** trains a router module that selects relevant key blocks for each query block. The training uses self-distillation: the sparse model is trained to mimic the attention distribution of a dense teacher. This has the flavor of knowledge distillation applied to attention patterns rather than output logits. However, because it partitions query tokens into blocks, it only accelerates the prefill phase (where many query tokens are processed simultaneously)—during autoregressive decoding, each new token is a singleton query that doesn't benefit from block-wise query partitioning.

**MoBA (Lu et al., 2025)** similarly uses block-sparse attention with learned routers during the short-to-long adaptation phase. Like SeerAttention, it partitions query tokens into blocks and can only accelerate prefilling, since decoding processes one query token at a time and can't amortize router computation across query blocks.

**NSA (Yuan et al., 2025)** is the most ambitious and the most directly relevant baseline. NSA designs three complementary attention modules to cover different aspects of the attention pattern:

1. **Compressed Attention**: Instead of computing attention against the full-resolution key sequence, NSA first compresses the keys into a coarser representation (via an MLP-based compression module with learned parameters) and computes attention against this compressed representation. This provides a global but low-resolution view of the sequence.

2. **Selected Attention**: Using the attention scores from the compressed attention as importance indicators, NSA identifies the most relevant key blocks and computes high-resolution attention only against those selected blocks. This is the dynamic sparsity mechanism—it uses the cheap compressed attention to decide where to spend the expensive full-resolution attention.

3. **Sliding Attention**: A local window of neighboring tokens that each query always attends to, capturing fine-grained local patterns that might be missed by the coarser block selection.

These three modules produce three separate outputs, which are combined via a learned gating mechanism: $\text{Output} = g_{\text{cmp}} O_{\text{cmp}} + g_{\text{slc}} O_{\text{slc}} + g_{\text{win}} O_{\text{win}}$, where the gate scores $g_{\text{cmp}}, g_{\text{slc}}, g_{\text{win}}$ are produced by an MLP with sigmoid activation applied to the input features.

Critically, each of the three attention modules has its own set of KV projection matrices: $W^{\text{cmp}}_K, W^{\text{cmp}}_V, W^{\text{slc}}_K, W^{\text{slc}}_V, W^{\text{win}}_K, W^{\text{win}}_V$. This means NSA introduces **three times the KV parameter count** of standard GQA, plus the additional MLP for key compression and the gating MLP. For an 8B model with a hidden size of 4096, this represents a substantial parameter overhead.

NSA also develops custom CUDA kernels to make the three-module computation efficient, targeting Grouped-Query Attention (GQA) with a group size of 16—a configuration where multiple query heads share the same KV head, allowing the block selection pattern to be shared across the group and reducing the overhead of computing separate selection patterns per head.

### Where NSA Falls Short: The Pretrain-on-Short, Finetune-on-Long Mismatch

The paper's central critique of NSA—and the primary motivation for InfLLM-V2—is not about NSA's absolute performance but about its **suitability for the dominant LLM development workflow**. The standard practice for building long-context LLMs is:

1. **Pretrain on short sequences** (e.g., 4k tokens). This is where the vast majority of compute is spent—trillions of tokens at costs measured in millions of dollars. Short sequences are used because they're abundant in web-crawled data, because pretraining on long sequences is prohibitively expensive, and because most of the fundamental language understanding and reasoning capabilities can be learned from short contexts.

2. **Finetune on long sequences** (e.g., 32k tokens). This is a much shorter phase—typically billions rather than trillions of tokens—that teaches the model to extend its capabilities to longer contexts without relearning everything from scratch.

When you try to apply NSA in this workflow, you encounter a fundamental architectural mismatch. The pretrained model uses standard dense GQA attention with a single set of KV projections and a single attention output. NSA requires three sets of KV projections, three attention modules, and a gating mechanism. When you switch from the pretrained dense architecture to the NSA sparse architecture for long-context finetuning, you are asking the model to:

- **Absorb a sudden influx of new parameters**: The three KV projection sets must be initialized somehow. The paper initializes them by replicating the original dense KV parameters, but this means the model now has three independent copies of parameters that were previously shared, each of which will diverge during finetuning.

- **Handle a structural output mismatch**: Dense attention produces a single attention output that flows into the output projection and residual connection. NSA produces three outputs that are combined via a learned gate. The model must learn not only *what* to attend to in long sequences but also *how to combine* three structurally different attention outputs—a problem it never encountered during pretraining.

- **Overcome disrupted representations**: The parameters that were trained to work in a single-output, full-attention regime are now forced into a multi-output, sparse-attention regime. The representations that the model learned during pretraining—which encode syntactic patterns, semantic relationships, and reasoning shortcuts—were optimized for a specific computational structure. Changing that structure mid-training means the model must unlearn and relearn aspects of its representations.

The paper provides direct evidence for this disruption in Figure 5, which shows the training loss during long-context finetuning for three models: full attention (baseline), NSA, and InfLLM-V2. The NSA loss curve shows a clear **spike** at the beginning of long-context finetuning—the loss jumps upward before gradually decreasing—indicating that the architectural switch has disrupted what the model previously learned. In contrast, InfLLM-V2's loss curve is smooth and tracks closely with the full-attention baseline, suggesting minimal disruption.

The quantitative results in Tables 1 and 2 confirm that this disruption translates to real performance penalties. NSA achieves only 59.92% on RULER (vs. 84.26% for full attention) and 37.10 on LongBench (vs. 42.30). Its LongPPL of 4.24 is over double the full attention baseline of 2.06, confirming that "NSA has not adequately learned long-range dependencies" (Section 4.2). NSA's performance on general short-sequence tasks (Table 4) also degrades—dropping from 67.73 (SHORT pretrained) to 60.63 on average across MMLU, CEval, MATH-500, HumanEval, MBPP, and BBH—indicating that the architectural disruption during long-context finetuning has partially erased capabilities the model had after pretraining.

There is an important nuance here: the original NSA paper (Yuan et al., 2025) reported results competitive with full attention when **training from scratch on long sequences**. The mismatch problem specifically manifests in the pretrain-on-short, finetune-on-long workflow. This explains why NSA's authors didn't identify it as a limitation—they were evaluating a different deployment scenario. But the short-to-long adaptation workflow is far more common in practice because pretraining from scratch on long sequences is cost-prohibitive for most organizations. The paper's contribution is thus not to say "NSA is bad" but rather "NSA is misaligned with how long-context models are actually built."

### The Short-Sequence Efficiency Problem

Beyond the training disruption, the paper identifies a second limitation of NSA that has substantial practical impact: **computational overhead on short sequences**. Because NSA always routes through all three attention modules and the gating mechanism, it incurs significant extra computation even when processing short inputs where dense attention would be perfectly fast and sparse patterns are unnecessary.

This might seem like a minor concern—after all, the whole point of sparse attention is to handle long sequences—but in practice, deployed models receive a mixture of short and long inputs. A chatbot might receive "hello" (a few tokens) in one request and a 50-page document in the next. If the model is locked into NSA's multi-module attention architecture, every short query pays the overhead of running compressed attention, selected attention, sliding attention, and gating—computations that are completely wasted when the sequence is short enough that dense attention would be faster. The paper's motivation here is that **a practical sparse attention mechanism should be efficient across the entire range of sequence lengths a model encounters in deployment**, not just at the long end.

This is what motivates the "dense-sparse switchable" property that gives the paper its title: the ideal architecture would use dense attention for short inputs (where it's both accurate and fast) and smoothly transition to sparse attention for long inputs (where dense attention becomes expensive). NSA can't do this because its architecture is fundamentally incompatible with standard dense attention—it has three KV projections, not one, and three outputs, not one.

### How InfLLM-V2 Positions Itself

The paper positions InfLLM-V2 as addressing all three of these limitations simultaneously through a single design principle: **architectural alignment between dense and sparse attention modes**. Rather than designing a new sparse attention mechanism from scratch, InfLLM-V2 takes the existing dense GQA attention as its foundation and constructs sparse attention as a *restricted subset* of the same computation.

The name "InfLLM-V2" references the training-free InfLLM (Xiao et al., 2024a), which also used block-sparse attention with dynamic block selection. But the deep conceptual connection is to the pretrain-on-short, finetune-on-long workflow itself: the architecture is designed so that switching between dense and sparse attention is a seamless, parameter-preserving operation. When the sequence is short, the model uses dense attention with its standard parameters; when the sequence is long, the model uses sparse attention with the *same* parameters, applying them to a restricted set of key-value blocks.

This positioning leads to three specific technical claims that differentiate InfLLM-V2 from prior work:

1. **Zero extra parameters.** By reusing the dense attention KV projections and eliminating the compressed attention output (keeping only its attention scores for block selection), InfLLM-V2 requires no additional learned parameters beyond what's already in the pretrained model. This directly contrasts with NSA's three KV projection sets, compression MLP, and gating MLP.

2. **Unified single output.** By fusing the selected attention and sliding attention into a single sparse attention module (rather than computing them separately and gating the results), InfLLM-V2's output structure matches dense attention one-to-one: one set of attention scores produces one attention output. This makes the training dynamics during the dense-to-sparse transition much more stable.

3. **Dynamic dense-sparse switching.** Because the architecture is the same in both modes (just with different key-value blocks made visible to each query), the model can switch between dense and sparse attention based on sequence length at inference time. Short sequences get dense attention with its full accuracy and simple implementation; long sequences get sparse attention with its $O(nk)$ complexity and hardware-optimized kernels.

The paper's experimental narrative then aims to demonstrate that these design choices translate to: (a) stable training without loss disruption (Figure 5), (b) competitive performance with full attention on both long-context understanding and long reasoning tasks (Tables 1–3), (c) preserved performance on general short-text benchmarks after long-context finetuning (Table 4), and (d) substantial speedups over both dense attention and NSA at equivalent sparsity levels (Figure 6).

There is also an implicit positioning relative to the broader efficient-attention literature. While the paper acknowledges the existence of linear attention, kernel-based approximations, and state-space models as alternative approaches to the long-sequence problem, it focuses exclusively on sparse attention—the dominant approach in current production systems. The implicit argument is that sparse attention, when done right (i.e., with architectural alignment to the pretraining workflow), can achieve both strong performance and practical speedups without requiring a fundamental rethinking of the Transformer architecture.

## 3. Technical Approach

### 3.1 Reader Orientation

The paper develops **InfLLM-V2**, a trainable sparse attention mechanism that can be substituted directly for standard dense self-attention in a Transformer without adding any new parameters. The system solves the problem of adapting a large language model from short-sequence pretraining to long-sequence inference by constructing sparse attention as a mathematically valid subset of dense attention—the same weights, the same projections, just restricted to a carefully chosen subset of key-value tokens per query—so that the model can switch between dense and sparse modes at inference time based on sequence length with no architectural mismatch.

### 3.2 Big-Picture Architecture (Diagram in Words)

The core architecture has four major components, each of which modifies or extends standard Grouped-Query Attention (GQA):

1. **Shared Key-Value Projection ($W_K, W_V$)** — a single set of projection matrices inherited from the pretrained dense attention model, used identically in both dense and sparse modes. This is the "no extra parameters" guarantee.

2. **Block Compression Pipeline** — a three-stage, parameter-free pooling mechanism that produces coarse-grained attention scores used to select which key-value blocks each query should attend to. Takes the full-resolution key sequence as input and outputs block-level importance scores $S^{\text{cmp}}$ via mean pooling, then head-group summation (exploiting GQA structure), then max pooling.

3. **Unified Sparse Attention Module** — the actual attention computation, which restricts each query to attending only to a predetermined pattern of key-value blocks (initial blocks + local blocks + top-k selected blocks) rather than the full sequence. This module produces a single attention output, structurally identical to dense attention's output, using the shared KV projections.

4. **Length-Based Mode Switch** — a simple conditional at inference time: if the input sequence length is below a threshold, route through standard dense FlashAttention; if above, route through the sparse attention path with block selection. No parameters, no gating, no structural change.

Information flows as follows: the input hidden states are projected to queries, keys, and values using the standard (shared) projection matrices → if the sequence is short, FlashAttention computes the full attention output and returns it → if the sequence is long, the keys enter the block compression pipeline to produce block-level importance scores → these scores determine which key-value blocks are "visible" to each query → sparse attention is computed only over the visible blocks → the output (identical in shape and semantics to dense attention's output) is passed to the output projection and residual connection.

### 3.3 Roadmap for the Deep Dive

- **First**, the mathematical foundation: standard Grouped-Query Attention (GQA), since every design choice in InfLLM-V2 inherits from and respects GQA's structure.
- **Second**, the shared KV projection and why it matters—what NSA did with three separate projections and why that causes the pretrain-to-finetune disruption.
- **Third**, the block compression pipeline (three-stage pooling) in full detail, because this is what determines *which* tokens the model attends to and must be both accurate and cheap.
- **Fourth**, the unified sparse attention mask—how the selected, sliding, and initial blocks are combined into a single attention pattern without gating or multiple outputs.
- **Fifth**, the efficient implementation (Fused Head Group Summation and LSE Approximation), because the block selection stage can easily become a new bottleneck that erases the gains from sparse attention.
- **Sixth**, the full training and inference procedure, including hyperparameters and the pretrain-on-short, finetune-on-long schedule.

### 3.4 Detailed, Sentence-Based Technical Breakdown

This is primarily a **systems and architecture paper** whose core idea is that sparse attention can be defined as a parameter-free restriction of dense attention, and that this design—by eliminating all extra parameters and maintaining identical output structure—makes the pretrain-on-short, finetune-on-long workflow seamless where prior approaches cause disruptive distribution shifts.

#### Grouped-Query Attention (GQA): The Foundation

InfLLM-V2 inherits the mathematical structure of Grouped-Query Attention (Ainslie et al., 2023), and every design decision in the paper is constrained by this structure. Understanding GQA is necessary to understand why the paper's choices about block selection, head grouping, and KV sharing work the way they do.

In standard multi-head attention, there are $h_q$ query heads, $h_{kv}$ key heads, and $h_{kv}$ value heads, with $h_q = h_{kv}$ — each query head has its own dedicated key-value head. GQA relaxes this by setting $h_{kv} < h_q$, so multiple query heads share the same key-value head. The group size is $G = h_q / h_{kv}$.

Given an input sequence of hidden states $X \in \mathbb{R}^{n \times d}$ (length $n$, hidden dimension $d$), the projections are:

$$Q = X W_Q, \quad K = X W_K, \quad V = X W_V$$

where the projection matrices have shapes $W_Q \in \mathbb{R}^{d \times (h_q d_h)}$ (projecting to all query heads jointly), $W_K \in \mathbb{R}^{d \times (h_{kv} d_h)}$, and $W_V \in \mathbb{R}^{d \times (h_{kv} d_h)}$, with head dimension $d_h$.

**What this means physically:** the input at each position is a vector of $d$ numbers. The three projection matrices map this vector to three different spaces: queries (what this position is "looking for"), keys (what this position "offers" to other positions), and values (what this position "communicates" if attended to). The key and value projections produce fewer heads ($h_{kv}$) than queries ($h_q$), so multiple query heads must share.

The tensors are reshaped to form individual heads: $\{Q_i\}_{i=1}^{h_q}$ for queries, each of shape $n \times d_h$, and $\{K_j, V_j\}_{j=1}^{h_{kv}}$ for keys and values. For the $i$-th query head, its corresponding KV head index is:

$$j = \left\lfloor\frac{i - 1}{G}\right\rfloor + 1$$

For the paper's 8B model configuration: $d = 4096$, $h_q = 32$, $h_{kv} = 2$, $d_h = 128$, and $G = 16$. This means 16 query heads share each KV head, and each head operates on 128-dimensional slices of the hidden state.

The attention computation for head $i$ is:

$$S_i = \text{Softmax}\left(\frac{Q_i K_j^\top}{\sqrt{d_h}}\right), \quad O_i = S_i V_j$$

$$S_i \in \mathbb{R}^{n \times n}, \quad O_i \in \mathbb{R}^{n \times d_h}$$

**What this computes:** for every pair of positions (query position $p$, key position $q$), the dot product $Q_i[p] \cdot K_j[q]$ measures compatibility — how relevant the key at position $q$ is to the query at position $p$. Scaling by $1/\sqrt{d_h}$ prevents the dot products from growing too large (which would push the softmax into a near-one-hot regime and kill gradients). The softmax converts these compatibility scores into a probability distribution over key positions for each query position. The attention output at position $p$ is the weighted average of all value vectors, with weights given by the softmax probabilities.

The final output concatenates all query head outputs and projects back to dimension $d$:

$$\text{Attention}(X) = \text{Concat}(O_1, \ldots, O_{h_q}) W_O$$

with $W_O \in \mathbb{R}^{(h_q d_h) \times d}$. The concatenated output has dimension $h_q d_h = 32 \times 128 = 4096$, matching the input dimension.

**Why GQA matters for InfLLM-V2:** the fact that $G = 16$ query heads share each KV head means that block selection decisions can be shared across an entire group. If head 1 and head 17 both attend to KV head 1, they can use the same sparse mask pattern—you don't need to compute separate block selections for each of the 32 query heads, only for the 2 KV head groups. This reduces the overhead of the block selection stage by a factor of $G$, which is critical for making sparse attention faster than dense attention. The paper follows NSA in setting $G = 16$ specifically because "a configuration well-suited for block sparse attention" (Section 3.4).

#### Shared Key-Value Projection: Eliminating NSA's Parameter Overhead

The paper's first major design choice is to reuse the pretrained dense attention's KV projection matrices directly, rather than introducing separate projections for different sparse attention components.

In NSA, there are three distinct attention modules (compressed, selected, sliding), each with its own KV projections:

- $W_K^{\text{cmp}}, W_V^{\text{cmp}}$ for compressed attention
- $W_K^{\text{slc}}, W_V^{\text{slc}}$ for selected (block-sparse) attention
- $W_K^{\text{win}}, W_V^{\text{win}}$ for sliding window attention

The NSA output is gated: $\text{Output} = g_{\text{cmp}} O_{\text{cmp}} + g_{\text{slc}} O_{\text{slc}} + g_{\text{win}} O_{\text{win}}$, where the gate scores come from an MLP applied to the input features.

**What InfLLM-V2 does instead:** there is exactly one set of KV projections, $W_K$ and $W_V$, identical to what the model used during dense pretraining. These are the same matrices, loaded from the pretrained checkpoint, and they are the only KV projections that exist—no copies, no new initializations, no separate modules.

During the long-context finetuning phase, these $W_K$ and $W_V$ are updated through gradient descent on the long-sequence data. But the key architectural invariant is that they are the *same* matrices regardless of whether the model is operating in dense or sparse mode. When the model switches to sparse attention at inference time, it simply restricts which key-value tokens each query attends to—it never changes which parameters produce the keys and values.

**Why this matters for the pretrain-on-short, finetune-on-long workflow:** when you initialize the long-context finetuning phase with the pretrained dense model, every parameter has a learned value that was optimized on short sequences. With InfLLM-V2, the model's attention computation at the start of long-context finetuning is mathematically identical to what the pretrained model would produce if you restricted its attention to a subset of tokens. The parameters are the same; only the mask pattern changes. The model doesn't need to learn from scratch how to use three independent KV representations—it just needs to adapt its existing representations to work with a restricted attention field.

Contrast this with NSA: at the start of long-context finetuning, the three KV projection sets are initialized by replicating the original $W_K, W_V$, which means each attention module initially receives the same keys and values. But as soon as finetuning begins, these three sets diverge—the compressed attention learns to produce keys that work well for coarse-grained global attention, the selected attention learns to produce keys that work well for block-sparse attention, and the sliding attention learns to produce keys for local patterns. The model has to simultaneously learn (a) what each attention mode is good for, (b) how to route information through three parallel pathways rather than one, and (c) how to interpret three different attention outputs that get combined through a gate. This is a substantially harder learning problem than simply adapting to seeing fewer tokens.

The paper's experimental evidence for this comes from Figure 5: NSA's training loss spikes when long-context finetuning begins, while InfLLM-V2's loss continues smoothly from where short pretraining left off. The loss spike is the direct manifestation of the disruption: the model's representations were optimized for a single-output, full-attention computation, and the sudden introduction of three parallel attention pathways forces a partial relearning of those representations.

#### Block Compression Pipeline: Three-Stage Parameter-Free Pooling

The central computational problem in sparse attention is **block selection**: before computing the expensive high-resolution attention, you need to decide which key-value blocks are relevant to each query. This decision must be both *accurate* (select the blocks that actually contain useful information) and *cheap* (the selection cost must be much less than the attention cost you're saving).

InfLLM-V2's block selection uses a three-stage compression process that produces a coarse attention score matrix $S^{\text{cmp}} \in \mathbb{R}^{h_{kv} \times T_q \times T_k}$ (for $T_q$ query blocks and $T_k$ key blocks, per KV head group), with no learned parameters at any stage. The progression is: token-level keys → block-level mean-pooled keys → head-group summed scores → block-level max-pooled scores.

**Stage 1: Coarse-grained key compression via mean pooling**

The full-resolution key sequence $K$ has shape $n \times d_h$ per KV head (all query heads in the group share this $K$). The first stage compresses this into a shorter sequence $K^{C1}$ by applying mean pooling with a block size $l_{C1}$ and stride $s_{C1}$:

$$K^{C1}_i = \text{Mean}(K_{i \cdot s_{C1} : i \cdot s_{C1} + l_{C1}})$$

where $K^{C1}_i \in \mathbb{R}^{d_h}$ is the $i$-th compressed key vector, computed as the element-wise mean of $l_{C1}$ consecutive key vectors starting at position $i \cdot s_{C1}$.

**What this computes:** each compressed key vector summarizes a window of $l_{C1}$ tokens by averaging their key representations. The stride $s_{C1}$ controls overlap between windows. With $l_{C1} = 32$ and $s_{C1} = 16$ (the paper's configuration), adjacent compressed vectors overlap by 16 tokens—each token of the original sequence contributes to two compressed vectors, creating a smoother, less lossy compression than non-overlapping blocks.

The length of the compressed sequence is approximately $n / s_{C1}$ (specifically, $\lceil n / s_{C1} \rceil$ vectors, assuming appropriate padding). For a 32k sequence, this produces approximately 2048 compressed key vectors—a 16× reduction from the original 32k tokens.

**Why mean pooling rather than an MLP (as in NSA):** NSA uses a learned MLP for key compression, which requires additional parameters and training. InfLLM-V2 uses mean pooling because it's parameter-free and because the compression module no longer needs to produce a representation suitable for attention *output* (since InfLLM-V2 eliminates the compressed attention output). Mean pooling only needs to produce keys that are good enough for coarse relevance scoring. The paper argues that this is sufficient because the scores from this stage are only used for block selection, not for producing the final attention output—the full-resolution attention is then computed over the selected blocks, recovering any fine-grained information lost in compression.

Standard attention scores between queries and compressed keys are then computed:

$$S^{C1} = \text{Softmax}\left(Q (K^{C1})^\top\right)$$

with $S^{C1} \in \mathbb{R}^{h_q \times n \times (n/s_{C1})}$ (all query heads, all query positions, all compressed key positions).

**What this computes:** for every query token and every compressed key block, a standard scaled dot-product attention score, then normalized by softmax across all compressed key blocks. The resulting score $S^{C1}[q, i]$ represents how strongly query token $q$ attends to the $i$-th compressed key block. This is computed over all $h_q$ query heads independently at this stage—the head-group merging happens next.

**Critical computational cost note:** this is a $O(n \times n/s_{C1})$ operation, which is still quadratic but with a constant factor $1/s_{C1} = 1/16$ smaller than full attention. For a 32k sequence, this is $32\text{k} \times 2\text{k} \approx 64$ million attention scores per query head—substantial but manageable. However, *storing* $S^{C1}$ in GPU HBM would require writing $h_q \times n \times n/s_{C1}$ floating-point values, which for 32 query heads, 32k tokens, and 2k compressed keys is approximately 2 billion floats ≈ 8 GB. This I/O is the bottleneck the paper addresses in Section 3.4.

**Stage 2: Head-group summation (exploiting GQA structure)**

Because GQA groups of $G$ query heads share the same KV head, they can share the same sparse attention mask. The paper enforces this by summing the first-stage attention scores across all heads within each KV group:

$$S^{\text{shared}} = \sum_{h=1}^{G} S^{C1(h)}$$

where $S^{C1(h)}$ is the attention score matrix for the $h$-th query head within the current group, and $S^{\text{shared}} \in \mathbb{R}^{n \times (n/s_{C1})}$ is the per-group aggregated importance score.

**What this computes:** for each KV head group (2 groups in the paper's configuration, since $h_{kv} = 2$), it sums the attention scores from all 16 query heads that share that group's KV head. If a compressed key block is important to any of the 16 query heads, its aggregated score will be high—the summation ensures no head's preferences are ignored.

**Why summation rather than max or mean:** the paper doesn't explicitly justify summation over alternatives, but the logic follows from the goal of block selection. If you use max, a single query head with a strong preference for a block could dominate, potentially causing the model to ignore blocks that are moderately important to many heads. If you use mean, diffuse attention across many heads to a block could produce a moderate score that doesn't reflect any individual head's strong preference. Summation balances these: it gives weight both to blocks that are important to many heads (each contributing a moderate score that adds up) and to blocks that are important to a few heads (each contributing a large score that isn't diluted by averaging).

**Stage 3: Block-level max pooling**

The first two stages produce token-level scores: $S^{\text{shared}}[q, i]$ is the importance of the $i$-th compressed key block (which covers $l_{C1}$ original tokens) for query token $q$. The third stage further aggregates these into block-level scores suitable for block-sparse attention with block size $B$:

$$S^{\text{cmp}}_i = \text{Max}(S^{\text{shared}}_{i \cdot s : i \cdot s + l})$$

where $l = 5$ and $s = 4$ are the pooling window length and stride.

**What this computes:** each block in the final score $S^{\text{cmp}}$ covers multiple compressed key blocks, and the max operation takes the highest score within the window. This produces scores at the granularity needed for block selection: one score per block of $B$ original tokens.

**The relationship between parameters:** the paper sets $l_{C1} = B/2 = 32$, $s_{C1} = B/4 = 16$, $l = 5$, $s = 4$, and $B = 64$. The total compression from original $B = 64$ tokens to a single $S^{\text{cmp}}$ block score can be verified: the original 64 tokens are covered by $64/s_{C1} = 4$ compressed key vectors (each covering $l_{C1} = 32$ tokens, with stride 16), each producing one score in $S^{\text{shared}}$. The stage-3 max pooling with $l = 5$ and $s = 4$ aggregates across approximately 5 compressed key blocks (spanning $5 \times 16 = 80$ original tokens, but overlapping). The paper states this achieves "the same compression ratio as 1-stage compression of block size $B$" — meaning the final score $S^{\text{cmp}}_i$ summarizes the relevance of a block of size $B = 64$ tokens.

**Why three stages rather than one:** the paper explicitly addresses this in Section 3.3: "Simply compressing a long sequence with a large block size $B$ in 1-stage can lead to a significant loss of granular information." The three-stage design with overlapping windows provides a more nuanced relevance estimate: the first stage uses small windows (32 tokens) with 50% overlap; the third stage uses a sliding max that can capture the most salient sub-block within a larger block. This matters because a block of 64 tokens might contain both highly relevant and completely irrelevant content—if you mean-pool the entire block, the irrelevant content dilutes the relevant content, and the block appears less important than it should.

**Design choice summary:** the entire compression pipeline is parameter-free (no learned weights, no MLP, no trainable projections), uses only simple pooling operations (mean and max) and a softmax (which has no parameters), and exploits GQA structure to reduce the number of independent scores by a factor of $G = 16$. This is in deliberate contrast to NSA, which uses a learned MLP for compression and computes separate attention scores per query head.

#### Unified Sparse Attention Mask: Fusing Selected, Sliding, and Initial Blocks

Once the block-level importance scores $S^{\text{cmp}}$ are computed, the system constructs a binary mask determining which key-value blocks each query token can attend to. The paper's key innovation here is combining what in NSA were three separate attention patterns (selected, sliding, initial) into a single unified mask — no gating, no multiple outputs, just a single set of visible blocks per query.

For a query token at absolute position $i$ (1-indexed), let $b_i = \lfloor (i-1)/B \rfloor + 1$ be the block containing the query. Three categories of key-value blocks are always included:

**Initial blocks** (a fixed set):
$$I_{\text{init}} = \{1, 2, \ldots, N_{\text{init}}\}$$

The paper sets $N_{\text{init}} = 1$, meaning every query token always attends to the first block of the sequence (tokens 1 through $B$). This is motivated by the "attention sink" phenomenon observed in prior work (Xiao et al., 2024b): the first few tokens of a sequence consistently receive high attention scores regardless of the query content, probably because they serve as a generic "null" or "summary" position that the model uses to dump attention when no other token is strongly relevant. Forcing all queries to attend to the initial block costs very little (only $B = 64$ extra tokens per query) and prevents the model from losing this capability.

**Local blocks** (a window around the query):
$$I_{\text{local}}(i) = \{b_i - N_{\text{local}} + 1, \ldots, b_i - 1, b_i\}$$

The paper sets $N_{\text{local}} = 32$, meaning each query attends to its own block and the 31 preceding blocks — covering $32 \times 64 = 2048$ tokens of local context. This covers a sliding window of recent tokens.

**Top-k selected blocks** (the dynamic component):
$$I_{\text{topk}}(i) = \text{TopK}(S^{\text{cmp}}, k)$$

where the top-k blocks are selected from the set of blocks **not already covered** by $I_{\text{init}}$ and $I_{\text{local}}$. The paper sets the total number of selected blocks $|I| = 96$ (including all three categories), so $|I_{\text{topk}}| = 96 - 1 - 32 = 63$ blocks. With block size $B = 64$, the total number of visible tokens per query is $96 \times 64 = 6144$ tokens — roughly 6k tokens, regardless of the full sequence length.

The complete set of attended block indices is the union:

$$I(i) = I_{\text{init}} \cup I_{\text{local}}(i) \cup I_{\text{topk}}(i)$$

and the set of visible token indices for query $i$ is the union of the tokens in these blocks: $\bigcup_{j \in I(i)} T_j$, where $T_j = \{jB + 1, \ldots, (j+1)B\}$ are the tokens in the $j$-th block.

**The fusion of sliding and selected attention.** In NSA, sliding attention and selected attention are computed as separate modules with separate KV projections and separate outputs, then combined via a learned gate. The sliding attention module gives each token access to a contiguous window of $w$ previous tokens; the selected attention gives access to top-k blocks identified by compressed attention scores.

InfLLM-V2 observes that these two patterns *overlap*: the local blocks in selected attention naturally cover a region similar to what sliding attention would cover. Rather than maintaining two separate patterns and gating their outputs, InfLLM-V2 expands the local block count $N_{\text{local}}$ to strictly cover the region that sliding attention would cover. Specifically, to replace a sliding window of size $w$ (in tokens), the local blocks need to cover at least $w$ tokens: $N_{\text{local}} \geq \lceil w / B \rceil + 1$ (the "+1" ensures the query's own block is included).

Figure 3 in the paper illustrates this concretely. With parameters $\text{init}=1, \text{topk}=2, \text{local}=1$, NSA's selected attention produces one mask pattern; with $w=6$, NSA's sliding attention produces a diagonal band. The InfLLM-V2 mask with $\text{init}=1, \text{topk}=2, \text{local}=3$ covers the union of both patterns — the local blocks ($N_{\text{local}}=3$) plus one block reserved for the query itself produces a band that encompasses the entire sliding window region plus some buffer.

**Why this fusion matters for training stability:** in NSA, the three attention outputs are combined as $g_{\text{cmp}} O_{\text{cmp}} + g_{\text{slc}} O_{\text{slc}} + g_{\text{win}} O_{\text{win}}$. The model must learn appropriate gate values $g$ for every input, effectively learning to route information through three parallel computational pathways. This is a non-trivial learning problem that doesn't exist during dense pretraining, where there's only one attention pathway. The fused approach eliminates the need for gating entirely—there's one attention mask, one attention computation, one output. The model only needs to learn to produce good representations given a restricted attention field, which is a strictly easier learning problem.

The paper also eliminates the compressed attention output ($O_{\text{cmp}}$) entirely, retaining only its attention scores for block selection. This is a crucial simplification: compressed attention in NSA served two purposes — block selection AND contributing to the output. In InfLLM-V2, it serves only block selection, which means the compressed representation doesn't need to be high-quality enough to produce output tokens, only high-quality enough to rank blocks correctly.

**Dynamic dense-sparse switching.** Because the sparse attention mask is defined purely in terms of which blocks to include (a set of indices), and the attention computation itself uses the same $W_K, W_V, W_Q, W_O$ as dense attention, the switch is trivial: if $\text{seqlen} \leq$ threshold (typically 4k, matching the pretraining length), set $I(i)$ to all blocks (dense); if $\text{seqlen} >$ threshold, use the sparse mask defined above. No parameter changes, no architectural modification, just a different set of indices to iterate over in the attention kernel.

#### Efficient Implementation: Fused Head Group Summation and LSE Approximation

The block selection pipeline described above is conceptually clean but computationally dangerous. The paper identifies through profiling that computing the first-stage attention scores $S^{C1}$ and writing them to GPU HBM (high-bandwidth memory, i.e., the main GPU DRAM) is the dominant bottleneck—not the attention computation itself, but the **I/O** of storing intermediate results.

**The I/O problem.** For a 32k sequence with $h_q = 32$ query heads and compression stride $s_{C1} = 16$, the score matrix $S^{C1}$ has dimensions $h_q \times n \times (n/s_{C1}) = 32 \times 32768 \times 2048 \approx 2.15$ billion elements. At 2 bytes per element (FP16/BF16), this is approximately 4.3 GB — just to store the intermediate attention scores for one layer, before they're summed and reduced. Multiply by the number of layers (typically 32 for an 8B model) and the I/O cost of writing and reading these scores dominates the computation time.

The solution has two components: **Fused Head Group Summation** and **LSE Approximation**, both inspired by FlashAttention's (Dao, 2024) strategy of keeping intermediate results in fast on-chip SRAM and minimizing HBM writes.

**Fused Head Group Summation (Algorithm 1).** The core idea is to perform the head-group summation (stage 2 of the compression pipeline) inside the SRAM computation loop, so that only the *reduced* scores $S^{\text{shared}}$ (with $G = 16$ times fewer elements) are written to HBM.

The challenge is that the head-group summation (over the head dimension) and the softmax normalization (over the sequence dimension) are not commutative:

$$\text{Softmax}(X) \text{ along dim } D \text{ then Sum along dim } H \neq \text{Sum along dim } H \text{ then Softmax along dim } D$$

Specifically, you can't first compute softmax-normalized scores per head, then sum them, and get a valid score — because each head's softmax normalizes independently, the summed scores don't have a clean interpretation. Conversely, you can't sum the raw logits across heads before softmax and then softmax, because the softmax's nonlinearity means $\text{Softmax}(\sum_h X_h) \neq \sum_h \text{Softmax}(X_h)$.

The paper's solution is a **two-pass** approach:

**First pass (coarse-grained, for LSE computation):** Instead of computing the full-resolution $S^{C1}$ to get the log-sum-exp (LSE) normalization term, the paper computes it using a coarser compression $K^{C2}$ with larger block size:

$$K^{C2}_i = \text{Mean}(K_{i \cdot s_{C2} : i \cdot s_{C2} + l_{C2}})$$
$$S^{C2} = \text{Softmax}(Q (K^{C2})^\top)$$

with $l_{C2} = 4 \cdot l_{C1} = 128$ and $s_{C2} = 4 \cdot s_{C1} = 64$. This is a significantly cheaper computation: the compressed sequence length is $n/s_{C2} = 32768/64 = 512$ (versus $2048$ for $K^{C1}$), making the attention score matrix $4 \times$ smaller in the key dimension. The log-sum-exp values from this coarse softmax are stored and used to approximate the true LSE for the fine-grained computation.

**Second pass (fine-grained, with fusion):** Now the full-resolution $S^{C1}$ is computed block by block. For each block of queries and each block of $K^{C1}$, the raw attention scores are computed on-chip, normalized using the approximate LSE from the first pass, summed over the head group dimension while still in SRAM, and only the reduced scores $S^{\text{shared}}_{ij}$ (of shape $B_q \times B_k$, representing $G$ times fewer elements than the full per-head scores) are written to HBM.

Algorithm 1 in the paper formalizes this. The outer loop iterates over query blocks $i = 1, \ldots, T_q$ in parallel (each block loaded to SRAM once). The LSE is first computed via a coarse pass over $K^{C2}$ blocks, then a fine-grained pass over $K^{C1}$ blocks computes the attention scores, normalizes them with the stored LSE, sums over the head group, and writes the reduced block to HBM.

**LSE Approximation.** The key efficiency insight is that the LSE (log-sum-exp) values needed for softmax normalization don't need to be exact — they only need to be good enough to produce reasonable normalized scores for the purpose of ranking blocks. Using the coarser $K^{C2}$ to approximate the LSE reduces the first-pass computational cost by a factor of 4 (since $K^{C2}$ has $1/4$ the length of $K^{C1}$). The total overhead relative to a single-pass approach goes from $2\times$ (if you did both passes at full resolution) to $1 + 1/4 = 1.25\times$.

Table 5 demonstrates the effectiveness: on A100 at 128k sequence length, the LSE Approximation reduces block selection time from 75.36 ms to 56.59 ms (a 25% reduction). On RTX 4090 at 128k, the reduction is from 83.26 ms to 59.04 ms (a 29% reduction).

**Why this two-pass approach is correct enough:** the LSE is used only to normalize the attention scores for block selection. The selected blocks then undergo full-resolution attention, which recomputes exact attention scores (with correct LSE) against the actual (non-compressed) keys. So any error introduced by the LSE approximation only affects *which blocks are selected*, not the final attention output. If the approximation occasionally causes a borderline block to be selected or deselected incorrectly, the impact is limited — the block was borderline anyway, and the full-resolution attention will compute correct scores for whatever blocks were selected.

**What about computing the actual softmax $S^{\text{cmp}}$ used for top-k?** After head-group summation, $S^{\text{shared}}$ is stored in HBM. The stage-3 max pooling and top-k selection are relatively cheap operations (no matrix multiplications, just element-wise max and sorting), so they are performed as separate kernels without further fusion. The paper notes that "the max-pooling and top-k operations related to $S^{\text{cmp}}$ could also be fused into the kernel; however, we leave this implementation for future work."

**Sparse Attention Kernel (Algorithm 2).** The actual sparse attention computation follows the FlashAttention-2 pattern but with a restricted inner loop. Standard FlashAttention (Algorithm 3 in the appendix) iterates over all key-value blocks $j = 1, \ldots, T_k$. The sparse version (Algorithm 2) only iterates over blocks $j$ that are in the visible set $I(i)$ for the current query position $i$. The FlashAttention tiling structure is modified so that: (1) the key-value block size $B_k$ must divide the sparse attention block size $B$ (so that $B/B_k$ key-value blocks fit within one selected sparse block), and (2) the query block contains all $G$ heads of a single token (rather than multiple tokens of a single head, as in standard FlashAttention), so that all heads within the group share the same sparse mask.

The appendix provides the full pseudocode for both the sparse attention kernel (Algorithm 2) and the dense FlashAttention kernel (Algorithm 3) for reference, showing that the only structural difference is the conditional `if Kj in visible tokens` check in the inner loop.

**Block sizes for the attention kernel.** For the paper's GQA configuration with $G = 16$, each query "block" in the FlashAttention sense contains one token across all 16 heads in the group (a $G \times d_h = 16 \times 128$ slice of the query tensor). This is loaded to SRAM once and used to compute attention against each visible key-value block, which has size $B_k \times d_h$ (the paper doesn't specify $B_k$ explicitly, but it must divide $B = 64$, so typical values would be 64, 32, or 16 depending on SRAM size constraints).

#### Training and Inference Procedure

**Pretraining (Short Sequences).** The model is trained from scratch using standard dense GQA attention on 4k-length sequences for 8 trillion tokens. The architecture is an 8B-parameter Transformer with $d = 4096$, $h_q = 32$, $h_{kv} = 2$, $d_h = 128$, and $G = 16$. Pretraining data consists primarily of FineWeb-Edu (Penedo et al., 2024) and Stack-v2 (Lozhkov et al., 2024). Training uses 8M tokens per batch, a WSD (warmup-stable-decay) learning rate scheduler (Hu et al., 2024) with 2000 warmup steps to an initial learning rate of $7.5 \times 10^{-3}$, and 27000 decay steps to a final learning rate of $3 \times 10^{-4}$. This phase produces the SHORT model.

**Long-Context Finetuning (Sparse Adaptation).** The pretrained model is then finetuned for 5 billion tokens with sequences up to 32k length. The attention mechanism is switched from dense to InfLLM-V2 sparse attention at this point. The training batches contain sequences from four length intervals: 0–4k, 4k–12k, 12k–24k, and 24k–32k tokens, with token counts in a 1:1:1:1 ratio — meaning each interval contributes an equal number of total tokens to each batch, so shorter sequences appear more frequently (more individual examples) than longer ones.

Key hyperparameters for long-context finetuning: initial learning rate $3 \times 10^{-4}$ with linear decay to $2.75 \times 10^{-4}$. No warmup is mentioned for this phase, suggesting the learning rate starts at the decayed value from pretraining (the paper doesn't specify the exact transition, but the WSD scheduler produces a low final learning rate, so the finetuning likely either restarts at a higher rate or continues from the final pretraining rate — the text says "an initial learning rate of 3e-4," implying a restart).

The block selection parameters are set following NSA: compression block size $l_{C1} = 32$, stride $s_{C1} = 16$, attention block size $B = 64$. For the efficient implementation, LSE approximation uses $l_{C2} = 128$, $s_{C2} = 64$. The selected block count is fixed at $|I| = 96$, composed of $|I_{\text{init}}| = 1$ initial block, $|I_{\text{topk}}| = 63$ dynamically selected blocks, and $|I_{\text{local}}| = 32$ local blocks, giving a total of $96 \times 64 = 6144$ visible tokens per query.

**Baseline training.** The FULLATTN baseline is finetuned with the exact same training configuration, but with standard dense attention (no sparsity) and proportionally higher computational cost. The NSA baseline is constructed by taking the same pretrained model and converting it to NSA architecture for long-context finetuning: the three sets of KV parameters ($W_K^{\text{cmp}}, W_V^{\text{cmp}}, W_K^{\text{slc}}, W_V^{\text{slc}}, W_K^{\text{win}}, W_V^{\text{win}}$) are initialized by replicating the original $W_K, W_V$ from the pretrained model. The additional MLP modules (compression MLP and gating MLP) are trained from scratch (the paper doesn't specify their initialization, but random initialization is standard). The NSA implementation uses an open-source Triton implementation rather than the original NSA code, since "NSA does not publish their code."

**Inference.** At inference time, InfLLM-V2 supports two modes:
- **DENSE mode:** standard FlashAttention-2, used for short sequences (the paper demonstrates this by showing DENSE results separately in tables, confirming that the model can switch back without degradation).
- **SPARSE mode:** the InfLLM-V2 sparse attention with block selection, used for long sequences.

The switch is determined by sequence length—though the paper doesn't specify an exact threshold, the natural choice would be 4k (the pretraining length), since sequences shorter than this can be handled efficiently by dense attention with no sparsity overhead.

The paper also demonstrates **W4A16 quantization** for the end-to-end inference benchmarks (Figure 7), using the Marlin kernel (Frantar et al., 2025) for efficient 4-bit weight, 16-bit activation inference. This is not part of the attention mechanism per se but demonstrates that InfLLM-V2's speedups compound with standard quantization techniques for the FFN layers (which InfLLM-V2 does not accelerate).

**Why the 1:1:1:1 length ratio in finetuning:** the combination of short and long sequences during finetuning is important because it prevents catastrophic forgetting of short-sequence capabilities. If the model only saw 32k sequences during finetuning, its representations would adapt exclusively to the sparse attention regime with long-range dependencies, potentially degrading its performance on short inputs. By continuing to include 0–4k sequences (which use dense-like attention patterns — the local blocks plus a few top-k blocks effectively cover most of a 4k sequence), the model maintains its short-context competence while learning to handle sparse attention on longer inputs.

The total visible token budget of 6k per query during both training and inference means that the model never sees more than 6k tokens of context per attention layer, even when the input is 32k tokens long. This is the fundamental efficiency-for-capability tradeoff: the model gets ~5× fewer tokens per layer but must learn to route information through the bottleneck of block selection. The experimental results in Section 4 demonstrate that with appropriate training, this bottleneck is sufficient to maintain near-full-attention performance.

## 4. Key Insights and Innovations

### Innovation 1: Sparse Attention as a Strict Subset of Dense Attention, Not a Parallel Architecture

The paper's most fundamental conceptual move is redefining what it means for a model to "switch" from dense to sparse attention. Prior trainable approaches—most prominently NSA (Yuan et al., 2025)—treated sparse attention as an *architectural addition*: you take a dense model, bolt on new attention modules with their own parameters (compressed, selected, sliding), and train a gating mechanism to combine their outputs. The implicit assumption was that sparse attention requires a different computational structure than dense attention, and therefore needs different parameters and different pathways.

InfLLM-V2 rejects this assumption entirely. Its core insight is that sparse attention can be defined as **the exact same computation as dense attention, applied to a restricted subset of key-value tokens**. Every operation—query projection, key projection, value projection, scaled dot-product, softmax, weighted sum, output projection—is mathematically identical between the two modes. The only difference is which indices appear in the inner loop of the attention kernel. This means the entire parameter set of the model ($W_Q$, $W_K$, $W_V$, $W_O$, and all FFN weights) is invariant to whether the model is running dense or sparse attention at any given moment.

This is not an incremental refinement of NSA's approach—it's a fundamentally different design philosophy. NSA asks: "What new components do we need to add to make sparse attention work?" InfLLM-V2 asks: "How can we make sparse attention emerge as a natural sub-case of the computation the model already knows how to do?" The answer—shared KV projections, single output, no gating, no learned compression—is what enables the seamless pretrain-on-short, finetune-on-long workflow that the paper demonstrates.

The significance of this reframing extends beyond the specific method. It establishes a design principle for efficient attention mechanisms: **architectural alignment with the dense pretraining computation is a first-class objective, not an afterthought**. Prior work evaluated sparse attention mechanisms primarily on their standalone performance after training from scratch (as NSA did). InfLLM-V2 argues—and demonstrates empirically—that the *transition cost* from dense to sparse is equally important, because the dominant development workflow in practice is short-pretrain then long-finetune. A method that performs well when trained from scratch but disrupts pretrained representations during finetuning (as NSA's loss spike in Figure 5 shows) is less useful than one that performs slightly worse but preserves existing capabilities.

This idea has a significant implication that the paper doesn't fully articulate but that follows directly from the design: because dense and sparse attention share all parameters, **any improvement to the dense model (better pretraining data, longer pretraining, architectural improvements to the FFN or normalization) automatically transfers to the sparse model without modification**. You don't need to retrain or re-architect the sparse attention components when you upgrade the base model—you just load the new weights. This makes InfLLM-V2 a drop-in replacement for dense attention that scales with the base model's capabilities, which is not true of NSA (where improved pretrained weights would need to be replicated across three sets of KV projections and the gating mechanism would need to be retrained to work with the new representations).

The evidence for this innovation is primarily architectural (the design described in Section 3) and behavioral (the smooth training loss in Figure 5 versus NSA's disruption, the preserved general-task performance in Table 4 where InfLLM-V2 Dense scores 66.76 vs. NSA's 60.63). The conceptual weight of the contribution is higher than the raw performance numbers might suggest, because it changes how subsequent researchers will think about the design space for efficient attention.

### Innovation 2: The Pretrain-on-Short, Finetune-on-Long Mismatch as a Diagnostic Framework

The paper doesn't just propose a new method—it identifies and names a specific failure mode that prior work had overlooked. The failure mode is: **architectural discontinuity between the pretraining attention mechanism and the finetuning attention mechanism causes disruption of learned representations, even if the finetuning attention mechanism is well-designed in isolation**.

This is a diagnostic contribution, not just an empirical observation. Before this paper, the dominant evaluation framework for trainable sparse attention was: train a model from scratch with the sparse mechanism, and compare its performance to a dense baseline at equivalent compute. By that metric, NSA succeeds—the original NSA paper reported competitive performance with full attention. But this evaluation assumes a training-from-scratch scenario that is rarely practical. The paper reframes the evaluation to ask: given that the vast majority of long-context models are built by pretraining on short sequences and finetuning on long ones, how well does each sparse attention mechanism handle the *transition*?

This reframing surfaces a problem that was invisible under the old evaluation paradigm. NSA's disruption doesn't manifest during from-scratch training because there's no pretrained knowledge to disrupt—the model starts random and learns everything under the NSA architecture from the beginning. But in the short-to-long adaptation setting, NSA's three KV projection sets and multi-output gating create a sudden distribution shift that the model must recover from. Figure 5 makes this visible: NSA's loss spikes at the beginning of long-context finetuning, indicating that the architectural switch has partially invalidated what the model learned during pretraining. InfLLM-V2, by contrast, shows a smooth loss curve that continues without disruption from the pretraining trajectory.

The diagnostic value of this insight is that it provides a **criterion for evaluating future sparse attention mechanisms** beyond just their asymptotic performance: does the mechanism preserve pretrained representations when activated? Could a model trained with this mechanism switch back to dense attention for short sequences without degradation? The paper's Tables 1, 2, and 4 can be read as providing quantitative answers to these questions for InfLLM-V2 (yes, Dense mode scores 88.32 on RULER vs. 84.26 for FullAttn; yes, 66.76 on general tasks vs. 67.73 for SHORT), and negative answers for NSA (59.92 on RULER; 60.63 on general tasks).

This diagnostic framework also explains a pattern that might otherwise seem contradictory: why does InfLLM-V2 in Dense mode sometimes *outperform* the FullAttn baseline (e.g., 88.32 vs. 84.26 on RULER)? The interpretation is that long-context finetuning with sparse attention forces the model to develop more robust representations—it must learn to extract information from a restricted 6k-token window per layer, which encourages the model to compress and route information more efficiently. When dense attention is then re-enabled at inference time, these more robust representations yield better performance than a model that was finetuned with dense attention throughout. This is not a claim the paper makes explicitly, but it's a natural interpretation of the Dense mode results and points to an interesting direction: sparse attention during training as a form of *regularization* that produces better general-purpose representations.

The limitation of this diagnostic contribution is that it's demonstrated on a single model scale (8B), a single architecture family (GQA-based Transformers), and a single pretraining configuration. Whether the short-to-long mismatch is equally severe for larger models (where pretrained representations might be more robust to perturbation) or for different attention variants (multi-head, multi-query) is an open question. But the framework itself—test the transition, not just the endpoint—is likely to influence how subsequent papers evaluate their methods.

### Innovation 3: The Block Selection Bottleneck as an I/O Problem, Not a Compute Problem

A recurring theme in efficient attention research is that the overhead of deciding *which* tokens to attend to can consume the efficiency gains from attending to fewer tokens. The paper's profiling-driven insight is that this overhead is primarily an **I/O bottleneck** (moving data between GPU HBM and SRAM), not a **compute bottleneck** (running FLOPs). This diagnosis leads to a specific optimization strategy—fuse reductions into the SRAM-resident computation to minimize HBM writes—that is conceptually borrowed from FlashAttention but applied to a different stage of the pipeline.

The specific technical contribution is the two-pass Fused Head Group Summation with LSE Approximation (Algorithm 1). But the intellectual contribution is broader: the paper demonstrates that the **block selection stage of sparse attention can be treated as an attention-like computation with its own tiling, fusion, and approximation opportunities**, not as a separate pre-processing step that must be optimized independently. By recognizing that the head-group summation and the softmax normalization share the same memory access patterns as standard attention (loading query blocks, iterating over key blocks, computing dot products), the paper applies the FlashAttention fusion recipe—keep intermediates in SRAM, write only reduced results to HBM—to a stage that prior work had treated as a black-box pre-processing cost.

The numerical evidence for this insight is in Figure 6 and Table 5. Figure 6 breaks down the attention kernel execution time into "Block Selection" and "Sparse Attention" components. At 128k sequence length on A100 with 16 selected blocks (the most aggressive sparsity setting), the total InfLLM-V2 kernel time is dominated by computation, not selection—the Block Selection bar is a small fraction of the total. For NSA at the same setting, the speedup over FlashAttention is only 2.4×, while InfLLM-V2 achieves 7.4×. Table 5 quantifies the LSE Approximation's contribution: on A100 at 128k, it reduces block selection time from 75.36 ms to 56.59 ms—a 25% reduction that directly translates to end-to-end speedup.

This insight has implications beyond InfLLM-V2. Any sparse attention mechanism that uses a learned or heuristic scoring function to select tokens or blocks faces the same I/O problem: the score matrix is $O(n \times n/s)$ in size, and materializing it in HBM can be the dominant cost. The paper's fusion strategy—compute coarse LSE in a first pass, then fuse the fine-grained scoring and the reduction into a single SRAM-resident second pass—is a general template that could be applied to other scoring functions (learned routers, similarity-based selection, hash-based partitioning) provided the scoring can be expressed as a matrix multiplication amenable to tiling.

A subtle point that the paper notes but doesn't fully explore: the LSE Approximation introduces *error* into the block selection scores, which means some blocks may be incorrectly selected or deselected. The fact that this has no measurable impact on downstream task performance (Table 1, with vs. without LSE Approx: 82.62 vs. 82.09 on RULER) is itself an interesting finding. It suggests that block selection is robust to moderate approximation error—you don't need exact softmax normalization to identify the most relevant blocks, just a reasonable ranking. This robustness could enable even more aggressive approximations (lower-precision arithmetic, sparser key representations, randomized LSE estimates) that push the block selection cost even lower.

### Innovation 4: Eliminating the Compressed Attention Output as a Form of Structural Regularization

One of the paper's subtler design choices—eliminating the compressed attention output and retaining only its attention scores for block selection—is easy to miss as a mere simplification, but it represents a substantive insight about the relationship between compression and attention quality. In NSA, compressed attention serves two roles: it provides the scores for block selection, AND it contributes directly to the final attention output via the gating mechanism ($g_{\text{cmp}} O_{\text{cmp}}$). The implicit assumption is that compressed attention captures global, low-resolution information that complements the high-resolution selected and sliding attention.

InfLLM-V2 rejects this dual role. The compressed keys are used exclusively for ranking blocks; they never contribute to the attention output. The full-resolution attention over selected blocks is the only source of attended information. This means the compression module (now parameter-free mean pooling) only needs to be good enough to produce a correct ranking of blocks, not good enough to produce output tokens.

Why is this a conceptual innovation rather than just an engineering simplification? Because it separates two concerns that were previously tangled: **representation quality** (how well does the compressed vector capture the information content of a block for the purpose of producing output tokens?) and **discriminative quality** (how well does the compressed vector distinguish relevant from irrelevant blocks?). These are different objectives that may require different compression strategies. Mean pooling might be suboptimal for representation—it loses positional information within the block, can't capture nonlinear interactions between tokens, and treats all tokens equally—but it's surprisingly effective for discrimination, because the average key vector of a block correlates well with whether queries will attend to tokens within that block.

The evidence that this separation works comes from the experimental results: InfLLM-V2 matches or exceeds full attention performance (RULER: 82.62 vs. 84.26; LongBench: 42.54 vs. 42.30; MATH-500: 87.80 vs. 86.00) despite never producing an attention output from the compressed representation. This implies that the information the compressed attention would have contributed to the output is either (a) redundant with what the selected blocks already provide, or (b) of sufficiently low quality that including it would add noise rather than signal. NSA's gating mechanism would have to learn to downweight $g_{\text{cmp}}$ in these cases, but that requires training the gate correctly, which adds another potential failure mode.

There's a connection here to the broader literature on attention approximation. Many "efficient attention" methods—Linformer, Performer, Linear Transformers—replace the full attention matrix with a low-rank or kernelized approximation and use that approximation as the attention output. InfLLM-V2 suggests an alternative philosophy: use the cheap approximation *only for routing* (deciding where to spend the expensive full-resolution computation), and compute the actual output from the full-resolution attention. This is analogous to the distinction in information retrieval between using a cheap scoring function for document retrieval and an expensive one for reranking, applied at the level of individual attention heads. Whether this philosophy generalizes to other efficient attention mechanisms—e.g., using a Performer-style kernel approximation for block selection but full attention for the output—is an open and potentially fruitful direction.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The paper evaluates on five categories of benchmarks:
  - **RULER** (Hsieh et al., 2024): a synthetic long-context understanding benchmark with configurable average length. Evaluated at 32k sequence length across 13 subtasks spanning retrieval (Single NIAH: SG1–SG3, Multi-key NIAH: MK1–MK3, Multi-value NIAH: MV, Multi-query NIAH: MQ), variable tracking (VT), common/frequent word extraction (CWE, FWE), and question answering (QA1, QA2).
  - **LongBench** (Bai et al., 2024): a bilingual benchmark for long-context understanding built from real-world datasets, covering single-document QA, multi-document QA, summarization, few-shot learning, synthetic tasks, and code. Average length varies by subcategory.
  - **LongPPL** (Fang et al., 2025): a perplexity evaluation benchmark for long sequences, measuring language modeling quality on long contexts.
  - **Long Reasoning Tasks**: MATH-500 (Hendrycks et al., 2021b), AIME 24 and AIME 25 (MAA competition problems), and LiveCodeBench v5 and v6 (Jain et al., 2025) — all measuring the model's ability to produce long chain-of-thought reasoning traces.
  - **General (Short-Context) Tasks**: MMLU (Hendrycks et al., 2021a), MMLU-Redux (Gema et al., 2025), CEval (Huang et al., 2023), MATH-500, HumanEval (Chen et al., 2021), MBPP (Austin et al., 2021), and BBH (Suzgun et al., 2023) — evaluating whether long-context finetuning degrades short-sequence capabilities.

- **Base model(s).** An 8B-parameter Transformer using standard Grouped-Query Attention (GQA) with hidden size $d = 4096$, $h_q = 32$ query heads, $h_{kv} = 2$ key-value heads, head dimension $d_h = 128$, and group size $G = 16$. The model is pretrained from scratch on 8 trillion tokens of 4k-length sequences (primarily FineWeb-Edu and Stack-v2) using a WSD learning rate scheduler (2000 warmup steps to $7.5 \times 10^{-3}$, 27000 decay steps to $3 \times 10^{-4}$). This model is chosen to be "representative of the capabilities of many contemporary LLMs" at a scale where long-context finetuning is computationally tractable for controlled experiments.

- **Metrics.** For RULER, accuracy (%) is reported per subtask and averaged across all 13 subtasks. For LongBench, accuracy/F1 is reported per subtask and macro-averaged across six task categories to produce an "Overall" score. For LongPPL, perplexity is reported (lower is better). For reasoning tasks, accuracy (exact match or equivalent grading) is reported. For general tasks, standard metrics per benchmark are used (accuracy for MMLU, CEval, BBH; pass@1 for HumanEval and MBPP; exact match for MATH-500), then macro-averaged. For efficiency, kernel execution time (ms) is measured on NVIDIA A100 and RTX 4090 GPUs, with end-to-end inference speed measured via time-to-first-token (TTFT) for prefilling and time-per-output-token (TPOT) for decoding.

- **Baselines.**
  - **FULLATTN**: the same pretrained model finetuned on 5B tokens of long-sequence data (up to 32k) using standard dense GQA attention, with identical training hyperparameters to InfLLM-V2. This is the upper-bound reference.
  - **SHORT + YaRN** (Peng et al., 2023): the pretrained model without long-context finetuning, using YaRN position embedding interpolation to extend the context window to 32k. Tests whether position interpolation alone suffices.
  - **InfLLM** (Xiao et al., 2024a): training-free block-sparse attention applied directly to the FULLATTN model. Represents the dynamic-sparse, no-training baseline.
  - **MInference** (Jiang et al., 2024): another training-free sparse attention method applied to the FULLATTN model. Represents an alternative dynamic-sparse, no-training approach.
  - **NSA** (Yuan et al., 2025): the primary trainable sparse attention baseline. The pretrained model is converted to NSA architecture (three KV projection sets initialized by replicating original $W_K, W_V$; new MLP modules trained from scratch) and finetuned on the same 5B tokens of long-sequence data. This is the key head-to-head comparison.
  - **InfLLM-V2 (SPARSE)**: the proposed method in sparse attention mode during inference.
  - **InfLLM-V2 (DENSE)**: the proposed method switched back to dense FlashAttention-2 at inference time. Tests whether the model retains dense-attention capability after sparse finetuning.
  
  All sparse attention baselines are evaluated at the same sparsity level: $|I| = 96$ selected blocks of size $B = 64$, for a total of 6144 visible tokens per query.

- **Generation budget / compute accounting.** For the attention efficiency benchmarks (Figure 6), the number of visible blocks $|I|$ is swept from 16 to 96, and kernel execution time is compared at fixed block counts across methods. For end-to-end inference (Figure 7), the configuration uses $|I| = 96$ blocks (6k visible tokens) with W4A16 weight quantization (Frantar et al., 2025), measuring wall-clock time including both attention and FFN computation. For task performance, sparsity is fixed at $|I| = 96$ (6k visible tokens) regardless of sequence length, so the compute budget scales linearly with sequence length rather than quadratically. No difficulty-based or adaptive budget allocation is used—the sparsity is uniform across all inputs.

- **Cross-validation / statistical protocol.** The paper does not report cross-validation or statistical significance testing. The 8B model is a single training run; no error bars, confidence intervals, or multiple seeds are reported. The 500-question MATH-500 is one of the smaller test sets, at 500 examples. RULER subtasks vary in size but are synthetic with controlled difficulty. The absence of statistical testing means small numerical differences (e.g., 42.54 vs. 42.49 on LongBench Overall between InfLLM-V2 Sparse and Dense) cannot be reliably interpreted as meaningful.

### Main Quantitative Results

#### Long-Context Understanding (RULER, LongBench, LongPPL)

**RULER at 32k (Table 1).** InfLLM-V2 (SPARSE) achieves 82.62% average accuracy across 13 RULER subtasks, compared to 84.26% for FULLATTN—retaining **98.1%** of the full-attention baseline's performance. This is the headline number for long-context understanding efficiency.

Breaking down by method at equivalent sparsity ($|I| = 96$ blocks):

| Method | RULER Avg. (%) | Retention vs. FULLATTN |
|---|---|---|
| FULLATTN | 84.26 | 100% (reference) |
| InfLLM-V2 (SPARSE) | 82.62 | 98.1% |
| InfLLM-V2 (DENSE) | 88.32 | 104.8% |
| MInference | 73.22 | 86.9% |
| NSA | 59.92 | 71.1% |
| SHORT + YaRN | 40.63 | 48.2% |
| InfLLM (training-free) | 27.94 | 33.2% |

The gap between InfLLM-V2 and NSA is 22.7 percentage points—a massive difference given that both are trainable sparse attention methods finetuned on the same data with the same sparsity level. This directly supports the paper's central claim that architectural alignment (shared KV, single output, no gating) is critical for the pretrain-on-short, finetune-on-long workflow.

An unexpected result: InfLLM-V2 (DENSE) outperforms FULLATTN by 4.06 points (88.32 vs. 84.26). The model finetuned with sparse attention, when switched back to dense attention at inference, surpasses the model that was finetuned with dense attention throughout. This is not a central claim of the paper but suggests that sparse attention during training may act as a regularizer that produces more robust representations.

**Subtask-level RULER analysis.** The performance patterns reveal where each method struggles:

- **Easy subtasks (SG1–SG3, MV, VT):** Both InfLLM-V2 and MInference match FULLATTN near-perfectly. NSA performs competitively on SG1 (100.00) but degrades on SG2 (88.00) and SG3 (82.00), suggesting difficulty with tasks requiring attention to specific non-initial positions. InfLLM (training-free) catastrophically fails on SG2 (6.00) and SG3 (4.00), confirming the fundamental limitation of training-free sparsity.

- **Multi-key NIAH (MK1–MK3):** This is where all sparse methods degrade relative to FULLATTN. FULLATTN scores 96.00, 94.00, 92.00 on MK1–MK3. InfLLM-V2 scores 94.00, 82.00, 62.00—holding up well on single-key retrieval but degrading as the number of keys increases. NSA scores 54.00, 38.00, 30.00, a much steeper drop. MInference scores 76.00, 36.00, 46.00. The multi-key retrieval task is the clearest stress test of the block selection mechanism's accuracy, and InfLLM-V2's advantage here suggests its three-stage compression pipeline is more effective at identifying multiple relevant blocks than NSA's compressed attention.

- **Variable Tracking (VT):** InfLLM-V2 achieves 98.50 vs. FULLATTN's 82.00. This is an unusual result where the sparse model substantially *outperforms* the dense baseline—the sparse attention may be forcing the model to track state more carefully rather than relying on global attention patterns that could be noisy.

- **Common Word Extraction (CWE):** FULLATTN scores only 44.40, suggesting this is a genuinely hard task for the 8B scale. InfLLM-V2 scores 50.40, outperforming FULLATTN. NSA scores 34.40.

- **Question Answering (QA1, QA2):** InfLLM-V2 scores 72.00 and 40.00 vs. FULLATTN's 48.00 and 56.00—an inversion where InfLLM-V2 wins on QA1 but loses substantially on QA2. The paper doesn't analyze this subtask-level pattern, but it suggests the sparse attention mechanism may have task-specific strengths and weaknesses not captured by the aggregate metric.

**LSE Approximation impact (Table 1, bottom rows).** The variant without LSE Approximation achieves 82.09% vs. 82.62% with LSE Approximation. This 0.53-point difference is negligible and confirms that the approximate LSE computation does not harm block selection quality meaningfully.

**LongBench (Table 2).** On real-world long-context tasks, the pattern largely replicates:

| Method | LongBench Overall ↑ | LongPPL ↓ |
|---|---|---|
| FULLATTN | 42.30 | 2.06 |
| InfLLM-V2 (SPARSE) | 42.54 | 2.12 |
| InfLLM-V2 (DENSE) | 42.49 | 2.00 |
| MInference | 41.55 | 2.62 |
| NSA | 37.10 | 4.24 |
| SHORT + YaRN | 37.86 | 5.28 |
| InfLLM | 32.30 | 12.01 |

InfLLM-V2 (SPARSE) actually slightly exceeds FULLATTN on LongBench (42.54 vs. 42.30)—a 0.24-point advantage that is likely within noise but confirms no meaningful degradation. NSA's 37.10 is 5.2 points behind, a statistically meaningful gap. The LongPPL results are particularly informative: NSA's 4.24 is over double FULLATTN's 2.06, confirming the paper's claim that "NSA has not adequately learned long-range dependencies." InfLLM-V2's 2.12 is nearly identical to the dense baseline.

**LongBench subcategory breakdown (Table 6 in Appendix B).** The detailed results show:
- **Multi-Document QA** shows the largest variability: on HotpotQA, InfLLM-V2 SPARSE achieves 54.11 vs. FULLATTN's 50.13 (a 3.98-point gain). On MuSiQue, it achieves 21.74 vs. 24.68 (a 2.94-point loss).
- **Few-shot Learning** shows a notable weakness: InfLLM-V2 SPARSE scores 22.50 on TREC vs. FULLATTN's 45.00 and 22.01 on LSHT vs. 37.75. This suggests that the sparse attention mechanism may be suboptimal for tasks requiring the model to locate and leverage specific few-shot examples within a long context.
- **Code** tasks (LCC, RepoBench-P) show InfLLM-V2 SPARSE outperforming FULLATTN (44.73 vs. 35.72 on LCC; 44.62 vs. 35.00 on RepoBench-P), which the paper doesn't analyze but which is consistent with the regularization hypothesis.

#### Long Reasoning Tasks (Table 3)

**Headline.** InfLLM-V2 (SPARSE) achieves 42.66% average across MATH-500, AIME 24, AIME 25, LCB v5, and LCB v6, compared to FULLATTN's 42.79%—retaining **99.7%** of the full-attention baseline's performance on long chain-of-thought reasoning.

|---|---|---|---|---|
| MATH-500 | 86.00 | 83.80 | 87.80 | 86.40 |
| AIME 24 | 37.50 | 28.75 | 38.33 | 36.67 |
| AIME 25 | 30.63 | 23.54 | 29.38 | 23.33 |

The key observations: (1) InfLLM-V2 SPARSE is within 0.13 points of FULLATTN on average—effectively identical performance. (2) NSA trails by 5.51 points on average, a substantial gap that is most pronounced on the hardest benchmarks (AIME 24: 28.75 vs. 37.50; AIME 25: 23.54 vs. 30.63). (3) InfLLM-V2 DENSE shows a notable drop on AIME 25 (23.33 vs. 30.63), a pattern the paper doesn't explain, though the DENSE average of 40.53 is still 3.25 points ahead of NSA.

The long reasoning results are particularly significant because chain-of-thought generation is an *autoregressive* task where the model must maintain coherent reasoning over thousands of generated tokens. The sparse attention mask during decoding covers 6k visible tokens—enough to include the full reasoning trace for problems up to that length, but potentially truncating context for very long solutions. The fact that performance is nearly identical to full attention suggests that 6k tokens of context per layer is sufficient for the model to carry forward all relevant reasoning state.

#### General (Short-Context) Tasks (Table 4)

**Headline.** InfLLM-V2 (DENSE) achieves 66.76% average across seven general benchmarks, compared to 67.73% for the SHORT (pretrained) model and 67.41% for FULLATTN. This confirms that long-context finetuning with InfLLM-V2 does not catastrophically degrade short-context performance.

The critical comparison is between NSA and InfLLM-V2 on short-context retention. NSA drops 7.1 points from the SHORT baseline (67.73 → 60.63), losing substantial ground on MATH-500 (54.40 → 44.40, a 10-point drop), HumanEval (70.73 → 62.20), MBPP (75.49 → 65.00), and BBH (51.90 → 43.81). InfLLM-V2 drops only 0.97 points (67.73 → 66.76), with no single benchmark showing a catastrophic decline. This directly supports the paper's claim that architectural alignment prevents the long-context finetuning phase from disrupting pretrained short-context capabilities. NSA's disruption is likely due to the three separate KV projection sets diverging during finetuning, such that when the model is evaluated with dense attention on short sequences, the single set of KV projections it uses (the original $W_K, W_V$ from pretraining) are no longer well-matched to the representations the model learned during finetuning.

The BBH results show a notable decline for ALL models after long-context finetuning (SHORT: 51.90 → FULLATTN: 49.13 → InfLLM-V2 DENSE: 47.09). InfLLM-V2 DENSE's 47.09 is within 2 points of FULLATTN's 49.13, confirming it's not a sparse-attention-specific degradation.

#### Efficiency Results (Figures 6 and 7)

**Kernel-level speed (Figure 6).** On A100 at 128k sequence length with $|I| = 16$ selected blocks:
- InfLLM-V2 achieves 7.4× speedup over FlashAttention-2
- NSA achieves 3.5× speedup over FlashAttention-2
- InfLLM-V2's advantage over NSA is 2.1× at the same sparsity level

The speedup scales with sequence length: at 32k, InfLLM-V2 achieves 3.0× vs. NSA's 1.5×; at 64k, 5.2× vs. 2.2×; at 96k, 6.4× vs. 2.6×; at 128k, 7.4× vs. 2.9×. The gap widens at longer sequences because NSA's compression and multi-module overhead becomes more significant relative to the sparse attention computation.

At $|I| = 96$ (the configuration used for task evaluation), the speedup is more modest: at 128k on A100, InfLLM-V2 achieves approximately 1.4× over FlashAttention-2 (read from the figure; the top-right bar at $|I|=96$ is approximately 1.4×). This is the real-world throughput improvement at the configuration that preserves 98.1% of full-attention accuracy.

On RTX 4090 (a consumer GPU with less memory bandwidth), the speedups are higher: at 128k with $|I|=16$, InfLLM-V2 achieves 9.3× vs. NSA's 3.5×. With $|I|=96$, the speedup is approximately 2.1×. The larger speedups on consumer hardware reflect that sparse attention's reduced memory I/O has proportionally greater impact on bandwidth-constrained devices.

**Block selection overhead (Figure 6 breakdown).** The stacked bars in Figure 6 show execution time split into "Block Selection" (the compression and top-k computation) and "Sparse Attention" (the actual sparse FlashAttention kernel). For InfLLM-V2, the Block Selection component is a small fraction of the total across all lengths and block counts—the optimization in Section 3.4 is effective. For NSA, the figure doesn't show this breakdown explicitly, but the total NSA time is substantially higher at equivalent block counts, and the paper attributes this to NSA's more expensive compression and multi-module structure.

**End-to-end inference (Figure 7).** With $|I| = 96$ blocks and W4A16 quantization:
- On A100 at 128k: prefilling speedup 1.99×, decoding speedup 1.82×
- On RTX 4090 at 128k: prefilling speedup 2.13×, decoding speedup 2.32×

These are end-to-end measurements including FFN layers (which InfLLM-V2 does not accelerate), so the speedups are necessarily lower than the attention-only kernel speedups. The paper notes that "a higher speedup ratio can be achieved by incorporating FFN-specific acceleration techniques in future work." At shorter sequence lengths, the speedup diminishes: at 32k on A100, prefilling is only 1.09× faster, reflecting that at short lengths the attention cost is a smaller fraction of total inference time (FFN dominates).

A notable detail: the decoding speedup (1.82–2.32×) is comparable to the prefilling speedup (1.99–2.13×) despite decoding having very different computational characteristics (one query token per step, KV cache access dominates). This confirms that InfLLM-V2 accelerates both phases effectively, unlike some block-sparse methods (SeerAttention, MoBA) that only accelerate prefilling. The decoding speedup comes from two sources: (1) only 6k KV cache entries need to be loaded per decoding step rather than the full 128k, and (2) the sparse attention kernel is optimized for the single-query, many-keys access pattern via Algorithm 2.

### Ablation Studies and Robustness Checks

- **LSE Approximation (Tables 1 and 5).** Removing the LSE Approximation degrades RULER performance negligibly: 82.09% vs. 82.62% with LSE Approximation (Table 1, bottom). This confirms that the approximate softmax normalization introduces no meaningful ranking errors for block selection. On the efficiency side (Table 5), LSE Approximation reduces block selection time by 19–29% depending on sequence length and GPU. On A100 at 128k: 56.59 ms with LSE Approx vs. 75.36 ms without. On RTX 4090 at 128k: 59.04 ms vs. 83.26 ms. The speedup is larger on the consumer GPU, consistent with the I/O-bound nature of the bottleneck (consumer GPUs have lower memory bandwidth).

- **Dense vs. Sparse inference mode (Tables 1–3, INFLLM-V2 DENSE vs. SPARSE rows).** Across all benchmarks, the model retains the ability to use dense attention after sparse finetuning. On RULER, DENSE mode achieves 88.32 vs. SPARSE's 82.62—a 5.7-point advantage for dense mode, suggesting that for maximum accuracy on long-context tasks, the model can optionally use dense attention (at higher computational cost). On LongBench, DENSE and SPARSE are nearly identical (42.49 vs. 42.54). On reasoning tasks, DENSE achieves 40.53 vs. SPARSE's 42.66—here SPARSE actually outperforms DENSE on average, with the gap driven primarily by AIME 25 (23.33 vs. 29.38). This is a robustness check confirming the switchable design works bidirectionally: the model trained with sparse attention can successfully use either mode at inference.

- **LSE Approximation variants (Table 1, with vs. without).** The near-identical RULER performance (82.62 vs. 82.09) confirms that the two-pass LSE approximation with coarse $K^{C2}$ (block size 128, stride 64) is sufficient for accurate block ranking. The paper does not ablate different $l_{C2}, s_{C2}$ settings, so the sensitivity to these hyperparameters is unknown. Given that $l_{C2} = 4 \cdot l_{C1}$ is a 4× coarsening, the robustness is surprising and suggests even more aggressive compression might be viable.

- **Block count $|I|$ sweep (Figure 6, x-axis).** The number of visible blocks is swept from 16 to 96. At $|I| = 16$ (the most aggressive sparsity, 1024 visible tokens per query), the speedup is highest (7.4× on A100 at 128k) but the paper does not report task performance at this setting. The task evaluation uses only $|I| = 96$ (6144 tokens). The paper does not provide an accuracy-vs-speedup tradeoff curve that would be necessary to determine the "pareto-optimal" operating point. This is a missing experiment: what is the minimum $|I|$ at which InfLLM-V2 matches full-attention performance on each benchmark?

- **Training length and data mixture.** The paper finetunes for exactly 5B tokens with a 1:1:1:1 ratio across four length intervals (0–4k, 4–12k, 12–24k, 24–32k). No ablation of finetuning duration or length mixture is reported. It's unknown whether 5B tokens is the minimum needed, or whether the 1:1:1:1 ratio is optimal. An ablation reducing the finetuning budget or changing the length distribution would clarify how data-efficient the adaptation is.

- **GQA group size $G = 16$.** This is inherited from NSA and not ablated. The paper notes that $G = 16$ is "well-suited for block sparse attention" because it allows 16 query heads to share a block selection pattern, but no experiments test smaller or larger group sizes. Larger $G$ would reduce block selection overhead further (fewer independent score matrices to compute) but might hurt attention quality. Smaller $G$ would increase overhead but might improve block selection accuracy per head.

- **Comparison with NSA at equivalent training.** Both InfLLM-V2 and NSA are finetuned on the same 5B tokens from the same pretrained checkpoint, making the comparison fair in terms of data. However, NSA has more parameters (3× KV projections, compression MLP, gating MLP), so it is being trained with more capacity on the same data. The fact that NSA underperforms despite this capacity advantage strengthens the paper's claim that *architecture*, not just capacity, matters.

### Critical Assessment

**Claim: InfLLM-V2 retains 98.1% of full-attention performance on long-context understanding while being 4× faster.**

*What was tested:* The 98.1% figure comes from RULER at 32k length (82.62% vs. 84.26%). The 4× speedup comes from the kernel-level benchmark at $|I| = 16$ blocks on A100 at 128k (7.4× over FlashAttention). These are mismatched conditions: the 98.1% is at 96 blocks (6k visible tokens, ~1.8× end-to-end speedup), while the 4× is at 16 blocks (1k visible tokens, unknown accuracy). The paper does not report RULER accuracy at $|I| = 16$, so the reader cannot verify whether the configuration that achieves 4× speedup also retains 98.1% accuracy. This is the most significant weakness in the experimental presentation: the headline numbers come from different operating points. Based on the end-to-end results in Figure 7, the realistic speedup at the accuracy-preserving configuration ($|I| = 96$) is approximately 1.8–2.3×, not 4×.

The LongBench and LongPPL results partially address this by showing that InfLLM-V2 SPARSE matches or exceeds FULLATTN at the $|I| = 96$ configuration, but the speedup at this configuration is modest.

*What would strengthen this claim:* A figure plotting accuracy on RULER or LongBench against $|I|$ (number of selected blocks) for InfLLM-V2, showing the accuracy-speedup Pareto frontier. This would let the reader determine the minimum $|I|$ at which accuracy is within, say, 1% of full attention, and the corresponding speedup.

**Claim: InfLLM-V2 achieves seamless short-to-long adaptation without the training disruption NSA causes.**

*What was tested:* Figure 5 shows training loss curves during long-context finetuning. NSA's loss spikes upward at the transition; InfLLM-V2's does not. Table 4 shows that NSA's short-context performance degrades substantially after long-context finetuning (67.73 → 60.63 on the general benchmark average) while InfLLM-V2's does not (67.73 → 66.76). This claim is well-supported by the evidence, with the caveat that the training loss is shown for only a few hundred steps (Figure 5's x-axis goes to ~40 for the short pretraining phase and ~600 for long finetuning). The long finetuning curve for NSA eventually decreases, approaching InfLLM-V2's loss, but it doesn't reach it within the shown steps, and the final task performance gap (Table 1) confirms the disruption has lasting consequences.

A missing detail: the NSA implementation uses an open-source Triton reimplementation, not the original NSA code. If the open-source implementation has differences from the original (e.g., in the gating mechanism, compression MLP architecture, or training recipe), the comparison may not fully represent NSA's potential. The paper acknowledges this but doesn't discuss potential discrepancies.

**Claim: InfLLM-V2 can dynamically switch between dense and sparse attention, providing efficiency on short sequences and capability on long ones.**

*What was tested:* Tables 1–4 include DENSE and SPARSE rows for InfLLM-V2, showing both modes work. DENSE mode sometimes outperforms SPARSE (RULER: 88.32 vs. 82.62) and sometimes underperforms (reasoning average: 40.53 vs. 42.66). The efficiency of the switch itself is not measured—no benchmark shows the overhead of switching modes between requests of different lengths. The paper demonstrates the *capability* to switch but not the *practicality* of switching in a serving system with mixed-length requests.

*What would strengthen this claim:* A benchmark showing throughput for a batch of mixed-length sequences (e.g., 50% 2k-length, 50% 32k-length) comparing InfLLM-V2 to both dense-only and NSA-only deployments. This would demonstrate the real-world benefit of the switchable design.

**Claim: InfLLM-V2's efficient block selection implementation removes the overhead bottleneck.**

*What was tested:* Figure 6's stacked bars show Block Selection time as a fraction of total kernel time. Table 5 compares block selection time with and without LSE Approximation. The evidence is strong that the paper's fused implementation is effective: block selection overhead is a small fraction of total time, and LSE Approximation provides a meaningful additional reduction. The paper notes that further optimization is possible (fusing max-pooling and top-k into the kernel).

**Additional weaknesses not addressed by the paper's claims:**

1. **Single model scale.** All experiments use an 8B model. Scaling behavior is entirely unknown. Will the same architectural alignment principles work at 1B? 70B? 405B? The GQA group size of 16 may not be appropriate at all scales—very large models may use different GQA configurations, and the block selection efficiency depends critically on $G$.

2. **Single pretraining configuration.** The 8T tokens at 4k length is one data point. The disruption NSA causes might be less severe for a model pretrained on more data (stronger pretrained representations might be more robust to architectural changes) or longer sequences (the model might already have some sparse-attention-compatible representations).

3. **The 4× speedup figure is misleading in context.** The abstract and conclusion emphasize "4× faster than dense attention," but this is at $|I| = 16$ blocks (1k visible tokens per query). No task performance is reported at this configuration. The configuration that preserves accuracy ($|I| = 96$, 6k tokens) achieves approximately 1.8–2.3× end-to-end speedup. The reader must dig into Figure 6's fine print to discover this discrepancy.

4. **No ablation of $B$ (block size).** The paper fixes $B = 64$ throughout, inherited from NSA. Block size is a critical hyperparameter: larger blocks reduce the number of selection decisions but risk including irrelevant tokens within selected blocks; smaller blocks increase selection overhead but allow finer-grained attention. The sensitivity of performance and efficiency to $B$ is unknown.

5. **No evaluation on truly extreme lengths.** The paper evaluates up to 128k for efficiency but only 32k for task performance. Modern long-context models claim support for 128k, 256k, or 1M tokens. Whether InfLLM-V2's 6k visible token budget is sufficient for much longer sequences is not tested.

6. **The LongBench few-shot learning degradation (Table 6).** InfLLM-V2 SPARSE scores 22.50 on TREC vs. FULLATTN's 45.00, and 22.01 on LSHT vs. 37.75. These are large drops that the aggregate LongBench score masks (because TREC and LSHT are averaged with other subcategories where InfLLM-V2 performs well). The paper does not discuss this failure mode. It suggests that tasks requiring the model to locate and attend to specific few-shot examples scattered across a long context are challenging for the block selection mechanism. This is a practically important limitation: if a user provides several examples in a long prompt, the model may fail to attend to them effectively.

7. **No comparison with alternative efficient attention paradigms.** The paper compares only with sparse attention methods (NSA, InfLLM, MInference) and full attention. There is no comparison with linear attention, state-space models (Mamba, etc.), or hybrid approaches. This is a reasonable scope limitation but means the paper doesn't establish where InfLLM-V2 sits in the broader landscape of efficient attention methods.

8. **Training data leakage risk.** The general benchmarks (MMLU, CEval, etc.) may have been included in the pretraining data, making the short-context retention numbers potentially overoptimistic if the model memorized answers. This is a standard concern in LLM evaluation which the paper doesn't address.

## 6. Limitations and Trade-offs

### The 4× Speedup Claim and the Accuracy-Preserving Configuration Are Evaluated at Different Sparsity Levels

**The constraint.** The paper's abstract and conclusion prominently claim "4× faster than dense attention while retaining 98.1% and 99.7% of the performance" on long-context understanding and reasoning, respectively. However, these two numbers come from different operating points. The 4× speedup (and the 7.4× figure cited in Section 4.3) is measured at $|I| = 16$ selected blocks — meaning only 1024 visible tokens per query — as shown in Figure 6, where the largest speedup numbers are at the leftmost point on the x-axis. Meanwhile, the 98.1% and 99.7% retention figures come from Tables 1 and 3, which are evaluated at $|I| = 96$ blocks (6144 visible tokens). The paper never reports task performance at $|I| = 16$, so the reader cannot determine what accuracy the model achieves at the configuration that actually delivers 4× speedup.

**The consequence.** A practitioner reading the abstract would reasonably conclude that the method is 4× faster while losing only 1.9% of accuracy on long-context understanding and 0.3% on reasoning. This is not what the experiments demonstrate. Figure 6 shows that at $|I| = 96$ (the accuracy-preserving configuration), the attention-only kernel speedup is approximately 1.4×, and Figure 7 shows the end-to-end speedup at this configuration is approximately 1.8–2.3× depending on GPU and phase (prefilling vs. decoding). The real tradeoff — at the configuration where accuracy is competitive — is roughly a 2× speedup, not 4×. The 4× figure is therefore misleading without a companion measurement of accuracy at that sparsity level. Since the method uses a fixed visible token budget, pushing sparsity from 96 blocks to 16 blocks means the model has access to 6.2× fewer tokens of context — a dramatic reduction that the training-free InfLLM results (which collapse to 27.94% on RULER at a comparable sparsity) suggest is likely to cause substantial performance degradation.

**What evidence exists in the paper.** The paper itself contains all the pieces to notice this mismatch: the 98.1% number is in Table 1 (RULER at $|I| = 96$, Section 4.2), the 4× speedup claim is in the abstract and the kernel benchmarks (Figure 6, $|I| = 16$), and the end-to-end speedup at $|I| = 96$ is in Figure 7 (1.99× on A100, 2.13× on 4090). The paper does not connect these dots for the reader — it does not state the speedup at the accuracy-matched operating point, nor the accuracy at the speed-matched operating point.

**Mitigation status.** The paper does not acknowledge this as a limitation. No accuracy-vs-blocks tradeoff curve is provided that would let readers determine the Pareto-optimal sparsity level. The abstract and conclusion present the speedup and accuracy numbers as if they apply to the same configuration, which the body of the paper shows they do not. This is a presentation issue with real consequences for how the method is understood and whether it would be adopted.

---

### No Accuracy-vs-Sparsity Tradeoff Characterization

**The constraint.** The paper uses a single fixed sparsity configuration — $|I| = 96$ blocks, yielding 6144 visible tokens per query — for all task evaluation (Tables 1–3). The efficiency benchmarks in Figure 6 sweep the number of selected blocks from 16 to 96, showing how kernel speedup varies with sparsity, but the paper never reports how *accuracy* varies with sparsity. There is no experiment measuring what happens to RULER, LongBench, or reasoning task performance at $|I| = 64$, $|I| = 32$, or $|I| = 16$. The training-free methods evaluated at the same $|I| = 96$ show that aggressive sparsity with a fixed budget can be catastrophic: InfLLM scores 27.94% on RULER (vs. 84.26% full attention) and MInference scores 73.22%, while the paper's own method scores 82.62%. These baselines demonstrate that *which* blocks are selected matters enormously — but they don't tell us how InfLLM-V2's *learned* block selection degrades as the budget is tightened.

**The consequence.** Without an accuracy-vs-blocks curve, practitioners cannot determine how to trade off speed and accuracy for their application. Is $|I| = 96$ the minimum needed? Could $|I| = 64$ preserve 95% of full-attention accuracy while delivering a larger speedup? Could $|I| = 128$ deliver better-than-full-attention accuracy at a smaller speedup? The paper provides no guidance. This also means the headline "4× faster" number is floating without context — the reader knows 4× speedup is achievable at $|I| = 16$ but has no idea whether the model produces coherent output at that sparsity. The training curve (Figure 5) shows that InfLLM-V2 was finetuned at $|I| = 96$, so at $|I| = 16$ during inference there would be a train-test sparsity mismatch — the model was never trained to operate with that few visible tokens, and it's unclear whether its representations would generalize.

**What evidence exists in the paper.** Figure 6 provides the speedup side of the tradeoff curve. The accuracy side is entirely missing. The training-free baselines (InfLLM at 27.94%, MInference at 73.22% on RULER) demonstrate that sparsity *at the same block count* can produce wildly different results depending on the selection mechanism, but they are at $|I| = 96$, not $|I| = 16$. The paper's own InfLLM-V2 results are a single point on what should be a curve.

**Mitigation status.** The paper does not discuss this as a limitation and does not propose experiments to characterize the tradeoff. Given that the method's core value proposition is an *efficiency-accuracy* tradeoff (faster inference with minimal accuracy loss), the absence of a characterized tradeoff curve is a significant gap. The paper does note in Section 4.3 that "all the above sparse attention methods, we maintain the same sparsity level to ensure a fair comparison" — but this is about fair comparison between methods, not about finding the optimal operating point for InfLLM-V2 itself.

---

### The LongBench Few-Shot Learning Degradation Is Not Discussed

**The constraint.** The LongBench subcategory results in Appendix B (Table 6) reveal a substantial degradation on few-shot learning tasks that the paper's aggregate metrics conceal. On TREC (a question classification task where models must leverage in-context examples), InfLLM-V2 SPARSE scores 22.50 vs. FULLATTN's 45.00 — a 22.5-point drop, meaning the sparse model achieves only 50% of the dense baseline's performance. On LSHT (a similarly structured few-shot task), InfLLM-V2 SPARSE scores 22.01 vs. FULLATTN's 37.75 — a 15.74-point drop. These degradations are large enough to be practically disqualifying for applications that depend on in-context learning from long prompts. However, the LongBench "Overall" macro-average across six categories (Table 2) shows InfLLM-V2 at 42.54 vs. FULLATTN at 42.30 — a slight *improvement* — because these few-shot subtasks are averaged with other categories where InfLLM-V2 performs well (e.g., Code, Multi-Document QA), effectively hiding the failure mode.

**The consequence.** A practitioner deploying InfLLM-V2 for a long-context application that involves providing multiple examples in the prompt (a common pattern for few-shot prompting, retrieval-augmented generation with exemplars, or instructional prompts with detailed demonstrations) would encounter a severe and unexpected performance regression. The block selection mechanism likely struggles to identify and attend to the specific few-shot examples scattered across the context — the examples may not score highly in the compressed attention scores if they don't match the query's surface-level features, even though they are critical for the task format. This limitation is not surfaced in any of the paper's headline metrics (98.1% retention on RULER, 99.7% on long reasoning), because RULER is a synthetic retrieval benchmark that doesn't test in-context learning, and the reasoning benchmarks (MATH, AIME, LiveCodeBench) evaluate the model's own generated reasoning rather than its ability to leverage provided examples.

**What evidence exists in the paper.** Table 6 in Appendix B provides the per-subtask breakdown. The few-shot learning category includes TREC (InfLLM-V2 SPARSE: 22.50 vs. FULLATTN: 45.00; NSA: 23.50), TriviaQA (84.22 vs. 84.35; near-identical), SAMSum (40.69 vs. 40.26; near-identical), and LSHT (22.01 vs. 37.75; large gap). The degradation is specific to TREC and LSHT — tasks where the model must find and apply specific format and content patterns from a small number of examples embedded in a long context. TriviaQA and SAMSum, despite being categorized as few-shot, may rely more on the model's pretrained knowledge than on the specific in-context examples.

**Mitigation status.** The paper does not discuss this degradation or even note it. The LongBench analysis in Section 4.2 mentions only the aggregate score (42.54 vs. 42.30, "highly competitive"), with no discussion of the per-category breakdown. The few-shot learning failure mode suggests that the block selection mechanism has a systematic weakness for certain attention patterns — likely those requiring precise retrieval of sparse, semantically specific tokens (like classification labels in TREC) — that could inform future work but is left unexamined.

### The 6k Visible Token Budget Is Not Validated for Sequences Beyond 32k

**The constraint.** All task performance evaluations (RULER, LongBench, LongPPL, reasoning tasks) are conducted at a maximum sequence length of 32k tokens. The model is finetuned on sequences up to 32k (with a 1:1:1:1 ratio across 0–4k, 4–12k, 12–24k, and 24–32k intervals). The visible token budget is fixed at 6144 tokens per query (96 blocks × 64 tokens/block). This means that at 32k sequence length, each attention layer sees approximately 19% of the available context (6k out of 32k). The efficiency benchmarks in Figure 6 and Figure 7 test up to 128k sequence length, but the paper never reports whether the model's *task performance* holds up at 64k, 96k, or 128k — despite claiming in the abstract that the method enables "seamless short-to-long adaptation."

**The consequence.** As sequence length grows, the fraction of context visible to each attention layer shrinks: at 64k, each layer sees only 9.6% of tokens; at 128k, only 4.8%. The paper provides no evidence that the model's block selection mechanism can maintain accuracy as this fraction drops. This is a critical gap because: (1) The block selection was trained only on sequences up to 32k, so the compressed attention scores $S^{\text{cmp}}$ may not generalize to the different attention patterns required at much longer lengths. (2) The fixed 6k token budget was calibrated at 32k finetuning — there's no reason to assume the same budget is appropriate at 128k, where the model might need access to a larger absolute number of tokens to maintain coherence. (3) The efficiency benchmarks at 128k use $|I| = 16$ and $|I| = 96$ configurations — but if task performance at $|I| = 96$ degrades at 128k, the model would need a *larger* block count, eating into the speedup. The paper's claim that InfLLM-V2 is a solution for "long-sequence processing" beyond 32k is essentially unvalidated for task quality.

**What evidence exists in the paper.** The LongPPL benchmark (Table 2) may evaluate at longer lengths, but the paper doesn't specify the sequence length used for LongPPL evaluation, and perplexity on long sequences is a weak proxy for downstream task performance — as Fang et al. (2025), the creators of LongPPL, have argued. The RULER evaluation is specifically at 32k (noted in Section 4.2). The efficiency figures (6 and 7) confirm the kernels work at 128k but don't measure output quality.

**Mitigation status.** The paper does not acknowledge this scope limitation. It claims "long-context understanding" based on 32k evaluations, which is at the low end of what current long-context models support. The introduction references applications requiring "tens or hundreds of thousands of tokens" but evaluates only at 32k. The conclusion's statement that "InfLLM-V2 offers a practical and powerful solution for advancing the capabilities of large language models in the long-context era" is supported only up to 32k for task quality.

---

### Single Model Scale and Single Pretraining Configuration: Scaling Behavior Is Unknown

**The constraint.** All experiments use a single model: an 8B-parameter Transformer trained from scratch on 8T tokens of 4k-length data, with a specific GQA configuration ($h_q = 32$, $h_{kv} = 2$, $G = 16$, $d = 4096$). The paper does not evaluate InfLLM-V2 at any other model scale (e.g., 1B, 70B, 405B), with any other pretraining data volume or sequence length, or with any other attention variant (standard multi-head attention, multi-query attention). The GQA group size $G = 16$ is a critical hyperparameter — it determines the block selection overhead (since $G$ heads share a mask, reducing score computation by $G\times$) and may interact with model scale in non-obvious ways.

**The consequence.** Several key claims may not generalize:

- **Architectural alignment benefit at larger scales.** Larger models have more capacity and may be more robust to architectural disruption — the advantage of InfLLM-V2's parameter-free design over NSA might shrink at 70B or 405B, where the model has enough capacity to absorb the extra NSA parameters without catastrophic forgetting. Conversely, larger models might be more sensitive because their pretrained representations are more finely tuned.

- **Visible token budget scaling.** The 6k visible token budget was determined for an 8B model. At larger scales, models might need more context per layer to maintain performance, or they might be able to work with less because individual token representations are richer. The optimal $|I|$ almost certainly depends on model capacity, but the paper provides no guidance.

- **Pretraining data volume.** The 8T token pretraining budget is substantial but not at the frontier for 8B models (the Chinchilla-optimal for 8B is approximately 160B tokens, so 8T is far into the "overtrained" regime). A model pretrained on fewer tokens might have weaker representations that benefit more from dense attention during finetuning; a model pretrained on more tokens might have stronger representations that survive sparsity better. The paper cannot distinguish these regimes.

- **The GQA group size of 16.** The paper inherits this from NSA and states it is "well-suited for block sparse attention" (Section 3.4), but no ablation tests whether $G = 8$ or $G = 4$ would produce better accuracy at the cost of higher selection overhead. At different model scales, the standard GQA configuration varies — many production models use $h_{kv} = 8$ or $h_{kv} = h_q$ (no grouping). InfLLM-V2's block selection efficiency depends on $G$ being large enough to amortize the compression cost; at $G = 1$ (standard multi-head attention), the Fused Head Group Summation optimization provides no benefit because there is no group to sum over.

**What evidence exists in the paper.** None — this is purely a scope limitation. The paper evaluates one model at one scale with one pretraining configuration. The abstract and conclusion do not qualify their claims with model scale.

**Mitigation status.** The paper does not discuss this limitation or propose scaling experiments. It does not claim the results generalize to other scales, but it also doesn't warn readers that they might not. The open-source release of the 8B model (MiniCPM4.1) enables community replication at this scale but not at others.

### The Block Selection Cost During Training Is Not Accounted For

**The constraint.** The paper's efficiency analysis (Figures 6 and 7, Tables 5) focuses exclusively on *inference* speed. However, InfLLM-V2's block selection mechanism — computing compressed attention scores $S^{\text{cmp}}$ via the three-stage pooling pipeline and performing top-k selection — is also executed during the long-context finetuning phase. The paper reports that long-context finetuning used 5B tokens with sequences up to 32k, but does not measure how much slower each training step is compared to dense attention training, nor how much total training time is added by the block selection overhead. Since the block selection must be done in the forward pass (to determine which blocks are visible for the sparse attention) and the top-k operation is non-differentiable (so gradients flow only through the selected blocks, not the selection mechanism itself), the selection computation is pure overhead during training.

**The consequence.** The paper's narrative positions InfLLM-V2 as enabling efficient long-context finetuning — "the pretrain-on-short, finetune-on-long workflow" is the central use case. But if the training-time block selection overhead significantly increases the cost of the finetuning phase, then the total compute picture is less favorable than the inference-only speedups suggest. Specifically: (1) The block selection computation during training is not accelerated by the fact that fewer blocks are attended to — you still have to compute $S^{C1}$, $S^{\text{shared}}$, and $S^{\text{cmp}}$ for the entire sequence to decide which blocks to select. (2) The LSE Approximation optimizations (Algorithm 1) apply to the inference kernel, but whether they were applied during training is not specified — if training used a less optimized block selection path, the training overhead could be substantially higher than the inference overhead. (3) The paper finetunes for 5B tokens — for comparison, the pretraining used 8T tokens. If the block selection makes each finetuning step, say, 30% slower, that adds a meaningful absolute cost to the workflow, even though finetuning is a small fraction of total compute.

**What evidence exists in the paper.** The paper reports no training throughput or training time measurements. The training loss curves (Figure 5) show steps on the x-axis, not wall-clock time. The efficiency section (4.3) is exclusively about inference kernels and end-to-end inference speed. The paper does not disclose how long the 5B-token finetuning took in GPU-hours, making it impossible to compute the total cost of the short-to-long adaptation.

**Mitigation status.** The paper does not acknowledge this as a gap. The efficiency claims ("4× faster than dense attention") are presented as if they apply uniformly, without distinguishing training from inference. In practice, the training-time overhead of block selection is unavoidable — the top-k operation is inherently sequential (you can't know which blocks are top-k until you've scored them) and doesn't benefit from the same FLOPs reduction as the attention computation itself. A complete efficiency analysis of the pretrain-on-short, finetune-on-long workflow would need to account for both training and inference costs.

## 7. Implications and Future Directions

### How This Work Changes the Landscape

This paper introduces a **design criterion** rather than a new algorithm: the quality of a trainable sparse attention mechanism should be judged not only by its asymptotic performance when trained from scratch, but by how cleanly it integrates into the dominant pretrain-on-short, finetune-on-long workflow. This is a **reframing of the evaluation framework** for efficient attention, not a paradigm shift in attention mechanisms themselves. The core technical ideas — block-sparse attention, compressed key representations for routing, FlashAttention-style kernel fusion — all have clear precedents. What is new is the argument that **architectural continuity between dense pretraining and sparse finetuning is a first-class objective**, and that satisfying this objective (via shared KV projections, single-output attention, no gating) enables a model to retain >98% of dense-attention accuracy while finetuning for only 5B tokens on long sequences, whereas a method that violates it (NSA) loses 10–25 percentage points on the same benchmarks despite using the same data budget.

Concretely, this reframing changes the landscape in several ways:

**It explains the gap between NSA's original results and the short-to-long adaptation results.** The original NSA paper reported competitive performance with full attention when training from scratch on long sequences. Section 4.2 of this paper shows NSA achieving only 59.92% on RULER (vs. 84.26% full attention) and 37.10 on LongBench (vs. 42.30) when finetuned from a short-sequence pretrained checkpoint. The architectural mismatch — three KV projection sets, multi-output gating, learned compression MLP — causes a training loss spike (Figure 5) and lasting performance degradation that is invisible when training NSA from random initialization. This suggests that prior work evaluating trainable sparse attention under from-scratch training may have systematically overestimated real-world performance, since the dominant deployment pattern is short-pretrain then long-finetune.

**It redirects the efficient-attention research agenda from "design a better sparse pattern" to "design sparse attention as a sub-case of dense attention."** Before this paper, the implicit design philosophy behind NSA and similar methods was: dense attention is one computation, sparse attention is a different computation, so build a separate architecture for each mode and train them to work together. InfLLM-V2 demonstrates that you can instead define sparse attention as **the exact same computation applied to a restricted index set**, which eliminates the need for separate parameters, separate outputs, and learned gating. This is a simpler design principle that produces quantitatively better results (82.62% vs. 59.92% on RULER) with zero additional parameters. Future work on trainable sparse attention will face a higher bar: it's no longer sufficient to demonstrate that a new sparse mechanism works well from scratch; authors must also demonstrate that it can be cleanly substituted into a pretrained dense model without disrupting existing capabilities.

**It strengthens the case for block-sparse attention with dynamic selection as a practical inference accelerator.** Training-free sparse attention methods (InfLLM, MInference) have shown that attention matrices are naturally sparse, but their performance degrades unacceptably at aggressive sparsity levels (InfLLM: 27.94% on RULER; MInference: 73.22%). NSA attempted to solve this through training but introduced architectural disruption that erased pretrained capabilities. InfLLM-V2 shows that a trainable block-sparse mechanism with parameter-free compression, GQA-aware block selection, and kernel fusion can preserve near-full-attention accuracy at 2× end-to-end speedup (Figure 7) while avoiding both the training-free degradation and the architectural disruption. This establishes block-sparse attention as a viable acceleration strategy for *deployed models*, not just a research curiosity. The paper's open-source release of the full 8B model trained under this framework provides a reproducible baseline that subsequent work can build on or compare against.

**It surfaces a previously hidden tension: the accuracy-speedup Pareto frontier may have different shapes for different task categories.** The LongBench subcategory results (Table 6 in Appendix B) reveal that InfLLM-V2 performs comparably to full attention on most task types but degrades sharply on few-shot learning tasks requiring precise retrieval of sparse exemplars (TREC: 22.50 vs. 45.00; LSHT: 22.01 vs. 37.75). This suggests that the block selection mechanism's 6k-token visible budget is adequate for tasks requiring *aggregate* context understanding (summarization, multi-document QA) but inadequate for tasks requiring *precise* token-level retrieval from scattered positions. This task-dependence of sparse attention quality has not been systematically characterized in prior work and opens a new axis for evaluation: beyond average accuracy, what types of attention patterns does each sparse mechanism preserve, and which does it distort?

**It makes training-free sparse attention less attractive as a standalone solution.** The dramatic gap between InfLLM-V2 (82.62%) and the best training-free method MInference (73.22%) at the same sparsity level — nearly 10 percentage points on RULER — demonstrates that even sophisticated dynamic selection heuristics (computing query-key similarity at inference time) cannot match what a modest amount of finetuning (5B tokens) can achieve. Training-free methods retain the advantage of zero additional training cost and immediate applicability to any model, but for deployment scenarios where accuracy is paramount, the paper tilts the cost-benefit calculation firmly toward trainable methods. This does not make training-free methods obsolete — they remain the only option for models where finetuning is infeasible — but it establishes a clear accuracy ceiling that training can break through.

**One result the paper does not fully interpret but which may prove influential:** InfLLM-V2 in Dense mode (switching back to full attention at inference time after sparse finetuning) *outperforms* the full-attention baseline on RULER (88.32 vs. 84.26) and matches or exceeds it on LongBench (42.49 vs. 42.30). This suggests that sparse attention during training acts as a **regularizer** — forcing the model to learn more robust, compressible representations that generalize better even when the sparsity constraint is removed at inference. This is reminiscent of dropout (which also constrains information flow during training but is removed at inference), but applied at the level of attention patterns rather than individual neurons. If this regularization effect is real and general, it implies that sparse attention during finetuning could be beneficial *even when you plan to deploy with dense attention* — you train sparse to build better representations, then run dense to exploit them fully. The paper doesn't develop this hypothesis, but it's a natural interpretation of the Dense-mode results and a direction that could change how long-context finetuning is done.

### Follow-Up Research This Work Enables

**Characterizing the accuracy-vs-blocks Pareto frontier for InfLLM-V2.** The paper's most pressing gap is the absence of task performance measurements at sparsity levels other than $|I| = 96$ blocks. A direct follow-up would evaluate RULER, LongBench, and the reasoning benchmarks at a sweep of block counts — say, $|I| \in \{16, 24, 32, 48, 64, 96, 128, 192\}$ — and plot accuracy against kernel speedup (from Figure 6) and end-to-end speedup (from Figure 7). This would produce a Pareto frontier showing the minimum visible token budget needed to achieve, say, 95%, 98%, or 99% of full-attention accuracy on each benchmark category. The experiment would answer: does the model catastrophically collapse below some critical block count (consistent with the training-free InfLLM results), or does it degrade gracefully? Is the optimal operating point task-dependent (e.g., 48 blocks for summarization but 96 for multi-key retrieval)? This characterization is essential for practitioners deciding how to deploy InfLLM-V2 and would also inform whether the fixed $|I| = 96$ used throughout the paper is near-optimal or substantially over-provisioned for some tasks.

**Scaling InfLLM-V2 to larger models and testing whether architectural alignment matters more or less at scale.** The paper's core claim — that eliminating architectural disruption during short-to-long adaptation preserves pretrained capabilities — is demonstrated only at 8B parameters. A natural extension would replicate the InfLLM-V2 vs. NSA comparison at multiple model scales: 1B, 8B, 30B, and 70B parameters (or the largest feasible given compute constraints). The key question is whether the *gap* between InfLLM-V2 and NSA narrows or widens with scale. If larger models are more robust to architectural disruption (because they have more capacity to relearn disrupted representations during the 5B-token finetuning phase), NSA's disadvantage might shrink at 70B — larger models could absorb the three KV projection sets without catastrophic forgetting. Conversely, if larger models' pretrained representations are more finely tuned and harder to recover once disrupted, the gap might widen. Either outcome is informative: a shrinking gap would suggest InfLLM-V2's advantage is most relevant for smaller, resource-constrained models; a widening gap would suggest architectural alignment becomes *more* important as capabilities increase. The experiment would also test whether the optimal visible token budget $|I|$, block size $B$, and compression parameters scale with model size.

**Testing whether sparse training acts as a regularizer that improves dense-attention performance (the Dense-mode-boost hypothesis).** The paper's unexpected result — InfLLM-V2 Dense outperforming FULLATTN on RULER (88.32 vs. 84.26) and matching it on LongBench — deserves direct experimental investigation. A controlled study would compare three training protocols, all starting from the same pretrained checkpoint and finetuning on the same 5B tokens: (a) dense attention throughout (FULLATTN), (b) InfLLM-V2 sparse attention throughout, evaluated in both Sparse and Dense mode, and (c) a "mixed" schedule where sparsity is gradually reduced during finetuning (e.g., increasing $|I|$ from 48 to 96 to 192) to test whether the regularization benefit can be captured without committing to a fixed sparsity level. The hypothesis is that sparse attention forces each layer to compress information into a subset of token representations that are maximally informative for downstream layers, and this compression pressure produces representations that generalize better even when the full context is available at inference. If confirmed, this would have implications beyond efficient inference: it would suggest that sparse attention during training is a generally useful regularizer for Transformer models, similar to how dropout is applied during training but removed at inference. The key measurement would be whether Dense-mode performance after sparse finetuning exceeds Dense-mode performance after dense finetuning, across multiple benchmarks and model scales. The paper already has suggestive evidence on RULER and LongBench; replicating this on reasoning tasks, general knowledge benchmarks, and out-of-distribution evaluations would establish whether the effect is robust.

**Diagnosing and repairing the few-shot learning degradation on LongBench.** The LongBench subcategory results (Table 6) reveal a specific failure mode: InfLLM-V2 SPARSE scores 22.50 on TREC vs. FULLATTN's 45.00, and 22.01 on LSHT vs. 37.75. A focused follow-up would systematically characterize what types of few-shot prompts cause the degradation. Possible hypotheses: (a) the block selection mechanism fails to score few-shot examples highly because the examples' surface-level similarity to the query is low (the query asks a question; the examples demonstrate the answer format — they're semantically related but lexically distinct); (b) the 6k visible token budget is insufficient when few-shot examples are interleaved with long stretches of distractor text; (c) the sliding window/local blocks dominate attention, causing the model to rely on nearby tokens rather than retrieving distant exemplars. Experiments would include: constructing synthetic few-shot prompts where the number and position of exemplars is controlled; measuring whether the compressed attention scores $S^{\text{cmp}}$ actually assign high values to the blocks containing exemplars; testing whether increasing $|I_{\text{topk}}|$ (more dynamically selected blocks) or adding task-specific bias terms to the block selection scores recovers the lost accuracy; and evaluating whether the degradation persists in Dense mode (if Dense mode also struggles on TREC/LSHT, the issue is in the finetuning data or procedure rather than the block selection). This line of work would both fix a practical limitation and deepen our understanding of what information the block selection mechanism systematically misses.

**Extending the block selection mechanism to support trainable or head-specific routing.** The paper's block selection uses a purely parameter-free compression pipeline (mean pooling, head-group summation, max pooling) with fixed initial and local block counts. This is elegant but may be suboptimal. A natural extension would introduce a small number of learnable parameters into the routing mechanism — for example, a lightweight linear projection applied to the compressed keys before computing attention scores, or head-specific biases that allow different query heads to prioritize different types of blocks (one head specializes in long-range retrieval, another in local syntax). The tension to manage is that adding parameters risks reintroducing the architectural disruption the paper carefully avoided — but a small routing-specific projection (say, a single linear layer producing scalar block scores) that is initialized to approximate the current mean-pooling behavior and then gently finetuned might improve block selection accuracy without causing the NSA-style loss spike. The experiment would compare: (a) pure parameter-free compression (current InfLLM-V2), (b) a learned linear router added on top of the pooled keys and trained during long-context finetuning, and (c) the learned router with a KL regularization toward the parameter-free scores to prevent drastic deviation. The key measurement is whether learned routing improves performance on the few-shot learning subtasks (TREC, LSHT) and multi-key retrieval (MK2, MK3) where the current mechanism shows weakness, without degrading general performance or disrupting training stability.

**Combining InfLLM-V2 with FFN acceleration to push end-to-end speedups beyond 2–3×.** Figure 7 shows that at $|I| = 96$, InfLLM-V2's end-to-end speedup is limited to ~2× because the FFN layers (which the method does not accelerate) consume a significant fraction of inference time. A systems-focused follow-up would integrate InfLLM-V2 with complementary FFN acceleration techniques — such as activation sparsity (exploiting the fact that FFN activations are often >90% zero after ReLU/GeLU, as in DejaVu or PowerInfer), structured FFN pruning, or mixture-of-experts routing — and measure the compound speedup. The paper itself notes this direction: "a higher speedup ratio can be achieved by incorporating FFN-specific acceleration techniques in future work" (Section 4.3). The concrete experiment would profile the full model with InfLLM-V2 attention, identify the new bottleneck (likely FFN dominated), apply an off-the-shelf FFN acceleration method, and measure whether the speedups compose multiplicatively. If attention is 2× faster and FFN becomes 2× faster through sparsity, does the end-to-end speedup approach 4×? Or do memory bandwidth and kernel launch overhead impose diminishing returns? The outcome would determine whether InfLLM-V2 alone is sufficient for practical deployments or whether it should be treated as one component in a broader inference acceleration stack.

**Evaluating InfLLM-V2 on tasks beyond 32k to test whether the 6k visible token budget is sufficient for much longer contexts.** The paper evaluates task performance only up to 32k but benchmarks kernel speed up to 128k. A direct extension would measure RULER accuracy at 64k, 96k, and 128k sequence lengths with the same $|I| = 96$ configuration (and possibly larger $|I|$ values) to determine whether the model's block selection mechanism maintains accuracy as the fraction of context visible to each layer shrinks from 19% (at 32k) to 9.6% (at 64k) to 4.8% (at 128k). The hypothesis to test is that the model's representations, trained to operate with 6k visible tokens, may be sufficient for any sequence length as long as the block selection correctly identifies the *relevant* 6k tokens — but this requires the block selection quality to not degrade as the candidate pool grows. A negative result (accuracy falling substantially at 64k+) would reveal a fundamental limit of fixed-budget sparse attention for ultra-long contexts and would motivate adaptive budget strategies where $|I|$ grows sublinearly with sequence length rather than staying constant. A positive result would extend InfLLM-V2's practical applicability to the full range of modern long-context deployments.

### Practical Applications and Downstream Use Cases

**Cost-efficient finetuning of long-context models from existing short-context checkpoints.** The most immediate application is the one the paper directly demonstrates: taking a pretrained short-context model and adapting it to long contexts with minimal additional training. The paper's recipe — 5B tokens of long-context finetuning with InfLLM-V2 sparse attention, using a 1:1:1:1 ratio of sequence lengths from 0–4k to 24–32k — recovers 98.1% of full-attention accuracy on RULER at 32k (82.62% vs. 84.26%). For an organization that has already invested in pretraining a model on short sequences (the dominant case), this means long-context capability can be added for the cost of finetuning 5B tokens — a tiny fraction of the pretraining budget (0.06% of the 8T-token pretraining). Without InfLLM-V2, the options are: (a) finetune with dense attention, which is slower and more memory-intensive (though the paper shows it produces slightly higher accuracy at 84.26%); (b) use NSA, which the paper shows degrades performance to 59.92% on RULER; or (c) use training-free sparsity, which collapses to 27.94%. InfLLM-V2 thus occupies a uniquely attractive position in the cost-accuracy tradeoff space for short-to-long adaptation: substantially cheaper than dense finetuning, substantially more accurate than training-free sparsity or NSA under the same budget.

**Deploying long-context LLMs on consumer-grade hardware.** The RTX 4090 results in Figures 6 and 7 are particularly relevant for the growing ecosystem of local and edge-deployed LLMs. On an RTX 4090 at 128k sequence length, InfLLM-V2's end-to-end time-to-first-token is 2.13× faster than dense attention, and time-per-output-token is 2.32× faster (Figure 7, with W4A16 quantization). These speedups translate directly to user experience: a 128k-context prompt that would take 40+ seconds to produce its first token with dense attention takes under 20 seconds with InfLLM-V2. For applications like local document analysis (ingesting a 200-page PDF), codebase understanding (loading an entire repository as context), or personal AI assistants with long-term memory, this speedup makes long-context inference practical on hardware that users actually own, rather than requiring cloud GPU instances. The paper's open-source release of the full 8B model (MiniCPM4.1) means practitioners can deploy this immediately without reimplementing the attention kernels or retraining.

**Long chain-of-thought reasoning with bounded inference cost.** The long reasoning results in Table 3 demonstrate that InfLLM-V2 preserves 99.7% of full-attention accuracy on MATH-500, AIME, and LiveCodeBench while generating multi-thousand-token reasoning traces. For reasoning-focused deployments — automated theorem proving, competitive programming, scientific problem-solving — the key bottleneck is often the cost of generating long chains of thought, where each additional reasoning step adds quadratic attention cost in the total sequence length. InfLLM-V2's linear scaling of attention cost with sequence length (since each new token attends to a fixed 6k-token window rather than the full history) means that reasoning traces can grow arbitrarily long without the per-token cost increasing — the model always attends to 6k tokens per layer, regardless of whether the total sequence is 4k or 128k tokens. Combined with the 2.32× decoding speedup on RTX 4090 (Figure 7), this makes long-form reasoning substantially more economical. A deployment generating 16k-token reasoning traces would see attention costs that are linear rather than quadratic in the output length, with direct implications for API pricing and throughput.

**Training data generation for self-improvement pipelines with long contexts.** When using LLMs to generate training data for themselves (as in STaR, ReST, or rejection sampling), the cost of generating long outputs can dominate the total pipeline budget. InfLLM-V2's decoding speedup directly reduces this cost. More interestingly, the paper's Dense-mode result — where sparse finetuning produces a model that *outperforms* dense finetuning when run in dense mode — suggests a training strategy: finetune a model with InfLLM-V2 sparse attention to build robust long-context representations, then generate high-quality training data using the model in dense mode, which achieves higher accuracy than the purely dense-finetuned model. The generated data could then be used to further finetune or distill the model. The paper doesn't explore this loop, but the pieces are in place: the InfLLM-V2 finetuned model in Dense mode scores 88.32 on RULER (vs. 84.26 for the dense-finetuned model), making it a strictly better data generator for long-context tasks at the cost of running dense attention during generation (which is acceptable for offline data generation where throughput, not latency, matters).
