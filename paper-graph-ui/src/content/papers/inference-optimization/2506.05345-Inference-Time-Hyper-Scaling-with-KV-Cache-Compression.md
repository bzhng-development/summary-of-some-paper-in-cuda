# Inference-Time Hyper-Scaling with KV Cache Compression

**ArXiv:** [2506.05345](https://arxiv.org/abs/2506.05345)

## 🎯 Pitch

Scaling inference-time compute in Transformers is bottlenecked not by generating more tokens, but by reading the bloated key–value cache from memory. By compressing the KV cache 8×, the proposed Dynamic Memory Sparsification (DMS) lets models explore more reasoning chains for the same latency, boosting Qwen-R1 32B’s score on AIME 24 by a staggering 12 points—without degrading reasoning quality.

---

## 1. Executive Summary

This paper proposes **inference-time hyper-scaling**, a strategy that compresses the key–value (KV) cache of Transformer LLMs to expand the effective token budget—generating longer reasoning chains or more parallel chains—for the same compute budget (in latency or memory), thereby improving downstream reasoning accuracy. The authors evaluate this approach on MATH-500, AIME 2024, GPQA Diamond, and LiveCodeBench using Qwen-R1 distilled models (1.5B, 7B, 32B), and introduce **Dynamic Memory Sparsification (DMS)**, a trainable KV cache sparsification method that delays token eviction decisions via a sliding window (implicitly merging representations rather than prematurely discarding them), achieving 8× compression with only 1K training steps while outperforming training-free sparse attention baselines. DMS boosts Qwen-R1 32B by 12.0 points on AIME 24, 8.6 on GPQA, and 9.7 on LiveCodeBench at equivalent memory reads, establishing that KV cache compression enables substantial inference-time scaling gains only when compression methods preserve accuracy at high ratios—a condition that training-free heuristics fail to meet.

## 2. Context and Motivation

### The Core Problem: Inference-Time Scaling's Hidden Bottleneck

When we talk about "letting a model think longer" at inference time, the natural mental model is that each additional token of reasoning costs a fixed, incremental amount of compute. This paper reveals that this mental model is fundamentally wrong for Transformer LLMs. The real cost driver during auto-regressive generation is not the computation of new tokens themselves, but rather the retrieval of the **key–value (KV) cache** from memory at each generation step.

The KV cache is the mechanism by which Transformers avoid recomputing representations for all previous tokens when generating each new one. At each time step $t$, the model must read the stored keys and values for all prior tokens ($1, \ldots, t-1$) from GPU memory to compute attention. As the sequence grows—whether through longer reasoning chains (sequential scaling) or through multiple parallel chains (parallel scaling)—this cache grows linearly, and the memory bandwidth required to read it eventually **dominates the inference latency**. As the authors put it in Section 2.1:

> "The larger the token budget, the more retrieving the KV cache through high-bandwidth memory access dominates latency during generation. As a consequence, the KV cache constitutes a bottleneck for inference-time scaling."

This bottleneck has two concrete manifestations:

1. **Memory load**: The KV cache must reside in VRAM on the GPU. For long sequences or multiple parallel chains, it can exhaust the accelerator's memory, preventing deployment on constrained hardware or forcing smaller batch sizes that reduce serving throughput.

2. **Latency**: Even when the cache fits in memory, the attention operation is **memory-bound**: its cost is dominated by the time needed to transfer the cache from high-bandwidth memory to the compute units, not by the actual arithmetic. This is verified analytically in Appendix I, where the authors show that for models like Llama 3.1 8B, KV cache reads contribute increasing fractions of total inference latency as sequence length and batch size grow—from negligible at 2K context to dominant (>80%) at 128K context.

The paper's central question follows directly from this observation (Section 2.1):

> "By making the KV cache leaner, could we scale the length and number of reasoning threads and enhance the accuracy of existing LLMs for an equivalent compute budget?"

This is the essence of **inference-time hyper-scaling**: trade off the quality loss from KV cache compression against the quality gain from being able to generate more (or longer) reasoning chains within the same memory and latency budget. If compression degrades accuracy less than additional reasoning improves it, the net effect is positive—and the model achieves better answers for the same wall-clock time and hardware constraints.

### Why This Problem Matters

The significance of this problem stems from the convergence of two trends in the LLM landscape:

**The rise of inference-time scaling as a dominant paradigm.** The success of models like OpenAI's o1 (OpenAI et al., 2024) and DeepSeek's R1 (Guo et al., 2025) has established that investing extra computation during inference—through longer reasoning chains ("sequential scaling") or multiple sampled solutions ("parallel scaling," also known as majority voting or best-of-N)—is one of the most effective ways to improve reasoning accuracy without modifying the underlying model. The practical importance of this paradigm shift cannot be overstated: it means that deployment decisions around inference budget allocation can have as much impact on downstream performance as pretraining decisions. However, this paradigm creates enormous pressure on inference infrastructure, because the token budgets required for competitive reasoning (e.g., 32K tokens per chain, 8 parallel chains) multiply the traditional KV cache burden.

**The memory-bound nature of attention at scale.** The paper's latency analysis in Appendix I quantifies a phenomenon that is widely known but rarely formalized: even on top-tier hardware (NVIDIA H100 SXM with 3.35 TB/s memory bandwidth), reading the KV cache from memory is significantly slower than computing attention scores. The authors derive that for Llama 3.1 8B, the KV cache component of memory reads scales as $1.31 \times 10^5 \cdot B \cdot L$ bytes (where $B$ is batch size and $L$ is sequence length), while the compute scales as $5.24 \times 10^5 \cdot B \cdot L$ FLOPs. Since memory bandwidth is the bottleneck (989.5 TFLOPS of compute vs. 3.35 TB/s of memory bandwidth), the KV cache read time eventually dominates. At batch size 128 and sequence length 128K, KV cache reads constitute **100% of the estimated latency** for Llama 3.1 8B. This means that for high-throughput, long-context inference scenarios—exactly the regime that inference-time scaling operates in—the entire system is bottlenecked by the sheer volume of KV cache data that must be shuttled from memory to compute units at every single generation step.

**Practical deployment constraints.** Outside of research settings, LLMs are deployed under strict latency and memory budgets. Edge devices, consumer GPUs, and shared cloud instances all impose limits on VRAM and acceptable per-token latency. Even in datacenter deployments, the economic pressure to maximize throughput (queries per second per dollar) means that any technique that reduces KV cache size directly translates to higher batch sizes, lower costs, or both. The paper demonstrates this concretely in Figure 3 (bottom) and Figure 8: DMS-compressed models achieve higher throughput at equivalent accuracy compared to vanilla models, with Qwen3-8B DMS enabling up to $5\times$ higher throughput.

**Theoretical significance: disentangling tokens from compute.** Prior work on inference-time scaling (Snell et al., 2024; Brown et al., 2024; Muennighoff et al., 2025) has implicitly equated "compute budget" with "number of generated tokens." This paper is the first to argue that these are distinct variables—that the effective compute cost (in latency and memory) is determined by the KV cache read volume, not the raw token count. By demonstrating that a compressed model can generate more tokens within the same effective compute budget, the paper opens a new axis of optimization that prior scaling analyses missed. This reframes the inference-time scaling problem from "how do we allocate a token budget?" to "how do we allocate a KV cache read budget?"—a subtle but practically important distinction.

### Where Prior Approaches Fall Short

The paper identifies three families of existing techniques for reducing KV cache overhead, each with critical limitations that motivate DMS:

#### Training-Free KV Cache Eviction (Section 2.2)

Methods like **TOVA** (Oren et al., 2024) and **H2O** (Zhang et al., 2023a) use heuristic rules to decide which tokens to evict from the cache during inference. TOVA evicts the token with the lowest attention weight at each step; H2O uses cumulative attention scores and keeps a sliding window of recent tokens. **Quest** (Tang et al., 2024) takes a different approach: it retains the full KV cache in memory but selectively retrieves only the most relevant pages (fixed-size blocks) during attention computation, using a heuristic based on the highest-magnitude dimensions of each page's KV items.

These methods are appealing because they require **zero training** and add minimal computational overhead. However, they suffer from a fundamental limitation:

> "training-free KV cache eviction methods often incur performance degradation at high eviction rates" (Section 2.3)

This degradation is not just an incremental accuracy loss—it can be catastrophic, especially under the **Grouped Query Attention (GQA)** architecture used by all modern LLMs (including the Qwen and Llama families tested in this paper). In GQA, multiple query heads share a single set of KV heads, meaning that a token eviction decision based on one attention pattern may destroy information needed by other queries sharing the same KV cache. The paper explicitly notes:

> "all the LLMs included in the experiments use Grouped Query Attention (GQA; Ainslie et al., 2023), hence KV tokens are shared among multiple query heads. This exacerbates the destructive effects of training-free token eviction." (Section 4)

Evidence of this degradation is stark: in Table 1, H2O at 4× compression on GSM8K drops from 47.0 (vanilla) to 14.7 accuracy—a collapse of over 32 points. TOVA at the same ratio drops to 20.2. Even Quest, which the paper treats as the strongest training-free baseline because it doesn't permanently discard tokens, shows significant degradation on long-context tasks: Variable Tracking drops from 55.8 (vanilla) to 49.6 at 4× compression.

The root cause is that **heuristic eviction lacks awareness of what information will be needed later**. A token with low current attention weight might be critical for future reasoning steps, but TOVA/H2O have no mechanism to predict this. The heuristics are reactive, not anticipatory.

#### Learned KV Cache Compression—DMC (Section 2.3)

**Dynamic Memory Compression** (DMC; Nawrot et al., 2024) addresses the quality problem by **training** the model to make compression decisions. At each time step and for each attention head independently, DMC decides whether to **append** a new key–value pair normally or **merge** it into the most recent cache entry via weighted averaging. This is learned through continued training (retrofitting) with a compression rate target, using stochastic reparameterization to make the discrete append/merge decision differentiable during training.

DMC's key advantage is that it preserves accuracy much better than training-free methods, even at high compression ratios. The model learns which tokens contain redundant information that can be safely merged and which contain critical information that must be preserved. Additionally, because decisions are per-head, different attention heads can adopt different compression ratios—some aggressively compressing while others preserve full detail.

However, DMC has a critical practical drawback:

> "Applying DMC requires continued training of existing LLMs... the computational cost is still significant" (Section 2.3)

The original DMC paper reported requiring **~44K training steps** to reach 8× compression, with performance substantially degrading when the training data is halved. This cost—while a fraction of full pretraining—is prohibitive for many practitioners and makes rapid experimentation difficult. The paper frames this tradeoff explicitly:

> "DMC offers robust compression at the cost of expensive continued training" (Section 3)

Moreover, DMC's token **merging** operation (weighted averaging of successive KV pairs) is more complex than simple eviction. It requires modifying the stored KV entry rather than just marking it for deletion, which has implications for implementation efficiency in systems like PagedAttention (Kwon et al., 2023) that assume KV entries are immutable once written.

#### The Fundamental Tension

The paper identifies a **missing sweet spot** in the design space (Section 3):

> "To scale inference-time efficiency even further, it is therefore essential to develop a KV cache compression method that is inexpensive, easy to integrate, and maintains accuracy at high compression ratios."

Training-free methods are inexpensive and easy but fail at high compression. DMC maintains accuracy but is expensive. The paper hypothesizes that **sparsification (eviction) rather than merging can be sufficient** if the model is trained to make intelligent decisions about *when* to evict—specifically, by delaying eviction to give the model time to extract information from tokens before they are discarded. This hypothesis motivates DMS, which we will examine in detail in Section 3.

### Quantization and Decomposition: Orthogonal Approaches

The paper also briefly acknowledges two other families of KV cache reduction (Appendix B): **quantization** (KIVI, KVQuant), which reduces the per-token storage cost by using fewer bits per key/value, and **decomposition** (LoRC, Eigen Attention), which reduces the effective dimensionality via SVD. These methods are orthogonal to sparsification—they can theoretically be combined—but the paper argues they are less expressive because they impose uniform compression rather than the adaptive, per-head, input-dependent compression that DMS enables.

### How This Paper Positions Itself

The paper's positioning can be understood along three axes:

**First, it introduces a new framing—inference-time hyper-scaling—that redefines what "scaling inference compute" means.** Prior work treated generated tokens and compute as interchangeable. This paper argues they are decoupled by the KV cache bottleneck, and that compression can expand the token budget *within* a fixed compute budget. This is not an incremental improvement to existing scaling strategies; it is a **qualitatively different axis** of optimization that has been overlooked. The paper claims to be "the first to fully disentangle generated tokens from the effective compute (latency and peak memory load) when reasoning in the discrete language space" (Section 5.4).

**Second, it proposes DMS as the enabler of hyper-scaling—bridging the gap between cheap-but-brittle training-free methods and expensive-but-robust DMC.** DMS is positioned as combining "the best of both worlds" (Section 3):

- **Like training-free eviction**: it uses sparsification (token removal) rather than merging, making it simple to implement and compatible with existing memory management systems like PagedAttention.
- **Like DMC**: it trains the model to make input-dependent, per-head compression decisions, preserving accuracy even at 8× compression.
- **Unlike both**: it introduces **delayed eviction**—a sliding window during which the model can attend to tokens before they are removed—which the paper argues is the key innovation that makes sparsification work at high compression ratios. The ablation in Figure 5 (left) demonstrates this dramatically: immediate eviction causes rapid accuracy degradation, while a sliding window of just 16 tokens preserves reasoning capabilities up to 4× compression.

**Third, it establishes empirical boundaries for when hyper-scaling works.** The paper does not claim universal superiority. The results show that gains are largest on difficult reasoning tasks (AIME 24, LiveCodeBench) and at larger model scales (32B), where the additional token budget from compression translates most directly to improved reasoning. On saturated benchmarks like MATH-500, gains are smaller because models already achieve high accuracy with limited budgets. This nuance is important: it tells practitioners *where* to invest in compression versus where to leave the model unchanged.

**A crucial prerequisite the paper identifies** is that hyper-scaling only works if compression preserves accuracy:

> "this hinges upon the crucial assumption that efficient attention does not degrade the model's reasoning abilities, which unfortunately is often the side effect of training-free sparsification methods" (Section 1)

This explains why the paper devotes substantial effort to developing DMS: the compression method *is* the enabling technology. Without a method that maintains accuracy at high compression ratios, the entire hyper-scaling paradigm collapses—you can generate more tokens, but they're lower quality, and the net effect is negative. The paper demonstrates this empirically: training-free methods like H2O and TOVA fail to improve the Pareto frontier over vanilla models, while DMS consistently pushes it outward (Figure 3, Figure 7).

### Summary of the Motivation Arc

The logical chain that motivates this paper is:

1. **Inference-time scaling works**—generating more/longer reasoning chains improves accuracy.
2. **But it's bottlenecked by the KV cache**—more tokens means more memory reads, dominating latency and exhausting VRAM.
3. **KV cache compression could alleviate this**—allowing more tokens within the same compute budget (hyper-scaling).
4. **Existing compression methods can't deliver**—training-free methods collapse at high compression; learned methods (DMC) are too expensive.
5. **Therefore, we need a new compression method** (DMS) that is cheap to train yet accurate at high compression ratios, making hyper-scaling practical.

This motivation is not merely about improving inference efficiency—it's about enabling a new regime of inference-time scaling that was previously inaccessible due to hardware constraints. As the authors put it, DMS provides "an inexpensive strategy for converting LLMs into more effective reasoners, pushing inference-time scaling to new frontiers" (Section 6).

## 3. Technical Approach

### 3.1 Reader Orientation

This is primarily a **systems-and-methods paper** that introduces a new technique for making Transformer LLMs more efficient at reasoning by compressing their internal memory (the KV cache), and then uses this technique to enable a new scaling paradigm called inference-time hyper-scaling. The core idea is that by training a model to intelligently decide which past tokens to keep and which to discard—using a simple binary "evict or keep" decision per token, but with a crucial delay before the eviction actually happens—we can compress the KV cache by up to 8× with minimal accuracy loss, which frees up memory and memory bandwidth to generate more (or longer) reasoning chains within the same hardware constraints, ultimately producing better answers.

### 3.2 Big-Picture Architecture (Diagram in Words)

The system has four major components that operate at different phases of the model lifecycle:

1. **The Base LLM (a pretrained Transformer)** — this is the starting point: a standard model like Qwen-R1 7B or Llama 3.2 1B with Grouped Query Attention (GQA) and a standard KV cache that stores every token unconditionally. It serves as both the "teacher" (providing distillation targets) during retrofitting and the baseline for comparison during inference.

2. **The DMS Decision Mechanism** — a tiny learned predictor (literally repurposing one neuron from the first query head in each attention group) that, at each generation step and for each attention head independently, outputs a scalar `$\alpha_t \in [0, 1]$` representing whether the current token's key–value pair should eventually be evicted. This mechanism is trained via stochastic reparameterization with a Gumbel-sigmoid distribution, and its binary decision (after thresholding at 0.5 during inference) controls which tokens survive in the cache.

3. **The Delayed Eviction Sliding Window** — a buffer of size `$w$` (typically 256 tokens) that holds tokens *after* they've been flagged for eviction. Instead of removing a token immediately upon the eviction decision, DMS waits `$w$` steps, allowing the model to attend to and potentially extract information from the token before it disappears. This is implemented via the attention mask: positions within the sliding window are forced to `$0$` in the additive mask `$M_\alpha$`, ensuring full visibility, while positions that have fallen outside the window are multiplied by `$\log(1 - \alpha_t)$`, progressively masking them.

4. **The Retrofitting Training Pipeline** — a lightweight continued-training procedure that retrofits the base LLM to make intelligent eviction decisions. It uses logit distillation (the base model as teacher, the DMS-equipped model as student), an auxiliary compression loss that pushes the average `$\alpha$` toward a target ratio, and a linear annealing schedule that gradually increases the target compression ratio during training. Critically, a single retrofitting run produces a family of models at different compression ratios (because the target `$\alpha^\star$` is continuously increased), enabling experiments across multiple CR values without separate training runs.

Information flows as follows during inference: a prompt enters → the model generates tokens autoregressively → at each step `$t$`, the DMS predictor outputs `$\alpha_t$` → if `$\alpha_t \geq 0.5$`, the token is flagged for future eviction → the token remains fully visible for `$w$` more steps (inside the sliding window) → after `$w$` steps, the token is permanently evicted and its slot can be overwritten → the reduced KV cache enables longer sequences or more parallel chains within the same memory and bandwidth budget → a verifier-free strategy (majority voting or best-of-N weighted selection) aggregates final answers from the generated reasoning chains.

### 3.3 Roadmap for the Deep Dive

- **First**, the formal definition of the eviction decision variable `$\alpha_t$` and how it is produced (the Gumbel-sigmoid parameterization and the attention mask construction), because this is the fundamental mechanism that everything else builds on.
- **Second**, the delayed eviction sliding window—why immediate eviction fails, how the window is implemented in the attention mask, and what size works—because this is the key design innovation that distinguishes DMS from training-free eviction methods and makes sparsification viable at high compression ratios.
- **Third**, the retrofitting training procedure, including the loss function (logit distillation + auxiliary compression loss), the annealing schedule, and the initialization choices, because the training recipe determines data efficiency and final accuracy.
- **Fourth**, the inference-time operation, including binarization of decisions, memory management via PagedAttention, and how sparsity is leveraged during prefilling, because the practical deployment characteristics determine whether the method delivers real-world gains.

### 3.4 Detailed, Sentence-Based Technical Breakdown

This paper introduces **Dynamic Memory Sparsification (DMS)**, a method for retrofitting pre-trained Transformer LLMs with a learned, input-dependent KV cache eviction policy that achieves high compression ratios (up to 8×) with minimal training cost (~1K steps) and minimal accuracy degradation, and then deploys these compressed models to enable inference-time hyper-scaling—generating more or longer reasoning chains within fixed latency and memory budgets.

#### The Eviction Decision Variable `$\alpha_t$` and How It Is Produced

The central mechanism of DMS is a **per-token, per-attention-head binary decision**: at each time step `$t$`, for each attention head, should the key–value pair `$(k_t, v_t)$` of the current token be retained indefinitely or eventually evicted? This decision is represented by a scalar `$\alpha_t$`.

**How `$\alpha_t$` is computed:**

For a single attention head, given the input hidden vector to the attention layer at time step `$t$` (call it `$h_t \in \mathbb{R}^d$`), DMS computes:

$$\alpha_t = \text{sigmoid}(h_t w^\top + b)$$

where `$w \in \mathbb{R}^d$` is a trainable weight vector and `$b \in \mathbb{R}$` is a trainable bias scalar.

**What it computes:** This is a linear classifier operating on the hidden state at a single time step. The hidden vector `$h_t$` encodes the model's current understanding of the token in context (after self-attention and feed-forward processing from earlier layers). The weight vector `$w$` projects this high-dimensional representation onto a single dimension, and the bias `$b$` shifts the decision threshold. The sigmoid squashes the result to `$[0, 1]$`, where values near 1 indicate "eventually evict this token" and values near 0 indicate "keep this token." During inference, this value is binarized to `$\alpha_t^{\text{bin}} = \lfloor \text{sigmoid}(h_t w^\top + b) \rceil \in \{0, 1\}$`.

**Why this form:** This is the simplest possible mechanism for making an input-dependent binary decision—a single logistic regression on the hidden state. The paper's key insight is that this simplicity is *sufficient* for high-quality compression decisions, and that the heavy lifting is done by the transformer's already-learned hidden representations (which encode rich contextual information) and by the careful training procedure (which teaches the model to use those representations for predicting future token importance). Using a separate neural network or multiple hidden layers would increase parameter count and training cost without necessarily improving decisions, because the hidden state already contains high-quality features. The choice of projecting from `$h_t$` (rather than, say, the key vector `$k_t$` or the query vector `$q_t$`) is deliberate: `$h_t$` is the input to the attention layer, meaning the eviction decision can be made before computing attention for the current step, and it captures information from all previous layers' processing of this token position.

**Parameter efficiency:** A critical design choice is *how* the weight vector `$w$` is implemented. The paper does not add a new parameter vector to each attention head. Instead, it borrows (repurposes) one neuron from the first query head in each query group. Specifically, for each GQA group, the first dimension of the first query head's weight matrix becomes the eviction predictor:

> "we 'borrow' the first neuron from the first query head in each query group and use it to extract `$\alpha_t$`, eliminating the need for additional parameters while minimizing the impact on attention computation" (Appendix C)

After extracting `$\alpha_t$`, that neuron's contribution to the actual attention computation is set to zero (`$q_{t,\text{first}}[0] = 0$`), so it doesn't affect the attention output. This requires a short transition period (2000 steps) during retrofitting where the neuron's weight is gradually zeroed out:

$$q_{t,\text{first}}[0] \leftarrow q_{t,\text{first}}[0] \times \left(1 - \frac{t}{n_t}\right)$$

where `$t$` is the current training step and `$n_t = 2000$`. After this warm-up, the first query head in each group has one neuron repurposed as the eviction predictor, and all other query heads in the group are unaffected. The alternative—adding a separate zero-initialized trainable projection—is noted as also viable but would slightly increase parameter count.

**Initialization:** The bias `$b$` is set to `$-5$` and the weight vector `$w$` is initialized to all zeros. With `$b = -5$`, the initial sigmoid output is approximately `$\sigma(-5) \approx 0.0067$`, meaning that at the start of training, the model predicts "do not evict" for essentially all tokens. This is crucial:

> "This configuration prevents initial loss spikes, which might cause catastrophic forgetting" (Section 3.1)

If the model started randomly evicting tokens, it would lose access to context it was pretrained to rely on, causing a sudden jump in the language modeling loss that could destabilize training and overwrite pretrained knowledge. By initializing to "keep everything," the model starts from the standard Transformer behavior and gradually learns to be selective.

#### Training-Time Relaxation: The Gumbel-Sigmoid Stochastic Reparameterization

During training, the binary eviction decision must be made differentiable so that gradients can flow back through it. Discrete `$\{0, 1\}$` decisions have zero gradient almost everywhere, so the paper uses **stochastic reparameterization** with a **Gumbel-sigmoid** distribution.

**The training-time `$\alpha_t$`:**

$$\alpha_t \sim \text{Gumbel-sigmoid}(h_t w^\top + b, \tau)$$

where `$\tau$` is a temperature parameter controlling the sharpness of the distribution, and the Gumbel-sigmoid is defined as:

$$\text{Gumbel-sigmoid}(x, \tau) = \text{sigmoid}\left(\frac{x + g_1 - g_2}{\tau}\right)$$

with `$g_1, g_2 \sim \text{Gumbel}(0, 1)$` being independent samples from the standard Gumbel distribution.

**What it computes:** This produces a continuous sample `$\alpha_t \in [0, 1]$` that is a differentiable relaxation of the discrete Bernoulli variable. When `$\tau \to 0$`, the distribution approaches a Bernoulli with probability `$\text{sigmoid}(h_t w^\top + b)$`. When `$\tau$` is larger, samples are softer (less concentrated at 0 and 1). The Gumbel noise adds stochasticity that encourages exploration during training—the model might occasionally keep a token it "wanted" to evict, or vice versa, which prevents the policy from collapsing to a deterministic but suboptimal solution.

**Why Gumbel-sigmoid rather than straight-through estimator (STE) or REINFORCE:** The Gumbel reparameterization (Louizos et al., 2018) provides lower-variance gradient estimates than score-function estimators like REINFORCE because the noise source is externalized and separated from the parameterization. Unlike STE—which uses a hard threshold in the forward pass but pretends the gradient passes through the threshold—Gumbel-sigmoid with low `$\tau$` produces genuinely continuous samples that are close to binary, and the reparameterization trick allows exact gradients with respect to the parameters `$w$` and `$b$`. The paper sets `$\tau$` to a low value to encourage near-binary decisions while maintaining differentiability.

#### The Attention Mask `$M_\alpha$`: How Eviction Decisions Affect Visibility

The eviction decisions `$\alpha_{1:T}$` for all time steps (for a single attention head) are compiled into an **additive attention mask** `$M_\alpha \in (-\infty, 0]^{T \times T}$` that is added to the unnormalized attention scores `$QK^\top$` before softmax. This mask selectively controls which past tokens the current query can attend to.

**Construction of `$M_\alpha$` without delayed eviction (for understanding):**

In a standard causal attention mask, element `$M_{i,j}$` (where `$i$` is the query position and `$j$` is the key position) is `$0$` if `$j \leq i$` (visible) and `$-\infty$` if `$j > i$` (future, invisible). In DMS, the mask elements are set to `$\log(1 - \alpha_j)$` for positions `$j \leq i$` (visible positions), and `$-\infty$` for `$j > i$`:

$$M_\alpha[i, j] = \begin{cases} \log(1 - \alpha_j) & \text{if } j \leq i \\ -\infty & \text{if } j > i \end{cases}$$

**What this means:** When `$\alpha_j = 0$` (keep token `$j$`), `$\log(1 - 0) = \log(1) = 0$`, so the token is fully visible—no penalty is applied to attention scores from that position. When `$\alpha_j = 1$` (evict token `$j$`), `$\log(1 - 1) = \log(0) = -\infty$`, so the attention score becomes `$-\infty$` regardless of the actual dot-product similarity—the token is completely invisible to all future queries. When `$0 < \alpha_j < 1$` (partial eviction during training), the token is partially visible—the attention score is reduced by `$-\log(1-\alpha_j)$`, which is positive (a penalty) but finite.

**Why additive `$\log(1 - \alpha)$` rather than multiplicative `$(1 - \alpha)$`:** The additive formulation in log-space is equivalent to multiplying the attention weights (pre-softmax) by `$(1 - \alpha_j)$`. This means that after softmax normalization, a token with `$\alpha_j$` near 1 gets exponentially suppressed compared to tokens with `$\alpha_j$` near 0. The log-space formulation is standard in attention implementations because it avoids numerical instability from multiplying by very small numbers, and it integrates naturally with the existing causal mask (which also operates in log-space via `$-\infty$`).

**Computational overhead:** The paper notes that "the overhead of DMS on the attention mechanism comes solely from constructing and applying the additive attention mask, which never needs to be materialized" (Section 3.1). For each attention head, the eviction decisions can be passed as a compact vector `$\alpha_{1:T}$` of length `$T$`, which is applied element-wise to the attention scores. This is implementable with existing efficient attention frameworks like FlexAttention (Dong et al., 2024) and FlashMask (Wang et al., 2025a).

#### Delayed Eviction via Sliding Window

The paper's **central design innovation** is the observation that immediate token eviction is harmful. When a token is flagged for eviction at time `$t$` and immediately masked out, the model loses access to that token's information before it might have had a chance to fully integrate it into its evolving representation. The solution is **delayed eviction**: the decision to evict is made at time `$t$`, but the actual removal from visibility occurs at time `$t + w$`, where `$w$` is the sliding window size.

**Implementation in the attention mask:**

Instead of applying `$\log(1 - \alpha_j)$` to all past positions `$j \leq i$`, the mask keeps positions within a window of size `$w$` fully visible:

$$M_\alpha[i, j] = \begin{cases} 0 & \text{if } i - j < w \text{ (within the sliding window)} \\ \log(1 - \alpha_j) & \text{if } i - j \geq w \text{ and } j \leq i \text{ (outside window, past)} \\ -\infty & \text{if } j > i \text{ (future)} \end{cases}$$

**What this means operationally:** When the model generates token `$t$`, it decides `$\alpha_t$` (evict=1 or keep=0). This token then remains **fully visible** (mask contribution 0) for the next `$w$` generation steps—regardless of its `$\alpha_t$` value. Only after the token falls outside the sliding window (when the current time step minus the token's time step exceeds `$w$`) does the `$\alpha_t$` decision take effect: if `$\alpha_t = 1$`, the token becomes fully masked; if `$\alpha_t = 0$`, it remains visible. In the sliding window, the model can attend to the token and potentially extract critical information before it is discarded.

**Why this matters—the intuition:** The paper argues that "decoder-only models heavily attend to recent tokens" (Section 3.1, citing Xiao et al., 2024; Jiang et al., 2024). This means that immediately after a token is generated, the model is likely attending to it heavily (it's the most recent context). If you evict it immediately, you destroy information the model is actively using. By waiting `$w$` steps, the model's attention naturally shifts to more recent tokens, and the token to be evicted becomes less relevant—at which point removing it is less harmful. This delay effectively gives the model time to *implicitly merge* the token's information into the representations of subsequent tokens (through the normal operation of self-attention), creating a form of lossy compression that preserves the essential content without the explicit weighted-averaging operation of DMC.

**Empirical validation of delayed eviction:**

Figure 5 (left) provides the crucial ablation. The authors train DMS variants on Llama 3.2 1B Instruct with different sliding window sizes and evaluate on GSM8K:

- **Immediate eviction (`$w = 0$`):** At compression ratio 2×, GSM8K score drops from 47.0 (vanilla) to ~20. At 4×, it drops to near 0. Training is unstable and accuracy collapses rapidly.
- **Delayed eviction with `$w = 16$`:** At CR 2×, score remains at ~47 (essentially unchanged from vanilla). At CR 4×, score is ~41. The model retains substantial reasoning ability.
- **Delayed eviction with `$w = 64$` or `$w = 256$`:** Even better preservation, with CR 4× maintaining scores close to vanilla.

The paper explicitly states: "Remarkably, DMS retains reasoning capabilities with a window of only 16 tokens up to a compression ratio of 4×" (Section 5.3). A window of 256 tokens (the default) provides even stronger protection and is used for all main experiments unless otherwise noted.

**Why 256 tokens:** This is chosen as a balance between providing enough time for information integration and not being so large that the compression ratio target cannot be met (the cache never actually shrinks if the window is larger than the total sequence length). For reasoning tasks generating sequences up to 32K tokens, a 256-token window means each token is visible for less than 1% of the total sequence before potential eviction, which is sufficient for the model to extract key information while still achieving the target CR.

**The analogy to DMC's merging:** The paper frames delayed eviction as an implicit form of the merging operation that DMC performs explicitly. In DMC, when a token is merged into the previous one, a weighted average is computed, directly combining their representations. In DMS, the sliding window allows the model to *attend to* the to-be-evicted token before it disappears, and through subsequent self-attention operations, the information from that token can propagate forward into later tokens' hidden states. The net effect is similar—information is preserved across compression—but DMS achieves this without the explicit merging logic, making it simpler to implement and more compatible with standard KV cache memory management.

#### Training Objective: Logit Distillation + Compression Auxiliary Loss

The retrofitting process optimizes two objectives simultaneously: preserving the original model's output quality (via **logit distillation**) and achieving the target compression ratio (via an **auxiliary `$\ell_1$` loss**).

**Logit distillation loss `$L_D$`:**

$$L_D = \text{KL}\left(p_{\text{teacher}}(y \mid x) \;\|\; p_{\text{student}}(y \mid x)\right)$$

where `$p_{\text{teacher}}$` is the output distribution of the original (uncompressed) LLM for input sequence `$x$`, and `$p_{\text{student}}$` is the output distribution of the DMS-retrofitted model. This is the standard Kullback-Leibler divergence between teacher and student probability distributions over the vocabulary at each token position.

**What it computes:** For each token position in the training sequence, the student model (with DMS enabled, so some past tokens are partially or fully masked) produces a probability distribution over the vocabulary. The teacher model (the original LLM with full, uncompressed KV cache) produces its own distribution for the same position. The KL divergence measures how different these two distributions are. The student is penalized for deviating from the teacher's predictions.

**Why logit distillation rather than standard language modeling loss:** The standard language modeling loss (`$-\log p_{\text{student}}(y_{\text{true}} \mid x)$`) only penalizes the student for assigning low probability to the single ground-truth next token. Logit distillation, by matching the full distribution, provides a richer training signal—it tells the student not just what the correct answer is, but also what answers are "close" (which the teacher assigns some probability to) and which are completely wrong. This is important for the compression task because: (1) the teacher's distribution encodes nuanced information about token relationships that helps the student learn to preserve critical context even when it's partially masked; (2) it provides more robustness to shifts in the training data distribution, since we're only asking the student to match the teacher's outputs, not necessarily to reproduce the exact training data. The paper notes:

> "logit distillation provides greater robustness to shifts in training data, since the original data mixtures are rarely public, and is especially beneficial for fragile LLMs with lower parameter counts" (Section 4)

**Auxiliary compression loss `$L_{\text{aux}}$`:**

$$L_{\text{aux}} = \max\left(\alpha^\star \cdot L \cdot H \cdot T - \sum_{l \in L} \sum_{h \in H} \sum_{t \in T} \alpha_{lht}, 0\right)$$

where `$L$` is the number of layers, `$H$` is the number of KV attention heads per layer, `$T$` is the sequence length, `$\alpha_{lht}$` is the eviction decision for layer `$l$`, head `$h$`, and time step `$t$`, and `$\alpha^\star \in [0, 1]$` is the **target average eviction rate**.

**What it computes:** This is a one-sided `$\ell_1$` penalty: it is zero when the total sum of all `$\alpha$` values across all layers, heads, and time steps is at least `$\alpha^\star \cdot L \cdot H \cdot T$` (i.e., when the average eviction rate meets or exceeds the target), and it is positive (penalizing) when the average eviction rate is below the target. The penalty is linear: each unit of "missing" eviction (below the target) adds one unit to the loss.

**Why one-sided and why `$\ell_1$`:** The one-sided form means the model is only penalized for compressing *too little*, not for compressing *too much*. This allows individual heads and layers to compress more aggressively than the target if that's beneficial for accuracy—the model can discover that some heads are more compressible than others. The `$\ell_1$` (absolute value) form, rather than `$\ell_2$` (squared), provides a constant gradient magnitude regardless of how far below the target the model is, which prevents the compression loss from dominating early in training when the average `$\alpha$` is near zero. If `$\ell_2$` were used, the gradient would be proportional to the deficit, meaning early training steps (with large deficits) would have enormous compression gradients drowning out the distillation signal.

**Why per-head, per-layer, per-token aggregation:** By summing over all positions and only comparing the *total* to the target, the model has flexibility in *where* to compress. Some layers might compress more than others; some heads within a layer might compress more than others; some tokens might be evicted more aggressively than others. All that matters is that the *average* over the entire model meets the target. This is a crucial advantage over training-free methods that impose uniform compression: DMS can allocate its "compression budget" adaptively, heavily compressing redundant information while preserving critical content.

**Combined objective:**

$$L = L_D + L_{\text{aux}}$$

The two losses are simply summed without any weighting coefficient. The distillation loss ensures output quality; the auxiliary loss ensures compression. The paper found no need for a balancing hyperparameter, likely because the initialization (`$\alpha \approx 0$`) means the auxiliary loss starts at zero and grows gradually as the target `$\alpha^\star$` is annealed.

#### Annealing Schedule: Producing a Family of Models from One Run

The target average eviction rate `$\alpha^\star$` is not fixed during training. Instead, it is **linearly annealed** from 0 (no compression) to the final target value.

**The schedule for the target compression ratio CR:**

$$\text{CR}(t) = \frac{t}{100} + 1$$

where `$t$` is the training step. This means:
- At step 0: CR = 1× (no compression, `$\alpha^\star = 0$`)
- At step 100: CR = 2× (target: evict 50% of tokens, `$\alpha^\star = 0.5$`)
- At step 300: CR = 4× (target: evict 75% of tokens, `$\alpha^\star = 0.75$`)
- At step 700: CR = 8× (target: evict 87.5% of tokens, `$\alpha^\star = 0.875$`)

The relationship between compression ratio and target average `$\alpha$` is:

$$\alpha^\star = 1 - \frac{1}{\text{CR}}$$

because if we evict fraction `$\alpha^\star$` of tokens, the fraction retained is `$1 - \alpha^\star$`, and the compression ratio (original size divided by compressed size) is `$\frac{1}{1 - \alpha^\star}$`.

**What this enables:** Because the target CR increases continuously during training, any intermediate checkpoint corresponds to a model trained at a specific compression ratio. This means a single retrofitting run—starting from CR 1× and ending at, say, CR 8×—produces a family of models at CR 2×, 3×, 4×, ..., 8×, all from one training process. The paper leverages this to evaluate DMS at multiple CR levels without separate training runs for each. This is a substantial practical advantage: the cost to get models at CR 2×, 4×, and 8× from one run is essentially the same as the cost to get just CR 8×.

**Comparison to DMC's training cost:** The paper emphasizes this data efficiency. DMC required ~44K training steps to reach CR 8×. DMS reaches CR 4× in 300 steps and CR 8× in 700 steps—a **~60× reduction** in required steps. This is the "inexpensive" part of DMS's value proposition:

> "DMS achieves higher scores than DMC while using 8× fewer training tokens" (Section 5.3, referring to Figure 5 right)

For the Qwen-R1 models, the actual computational cost per CR increment is documented in Table 3: retrofitting Qwen-R1 7B from CR `$i$` to CR `$i+1$` (100 training steps) requires 75 GPU-hours on NVIDIA H100 GPUs. The full run to CR 8× (700 steps) would require approximately 525 GPU-hours for the 7B model.

**Training configuration details from the paper (Section 4, Appendix C):**

- **Optimizer:** AdamW
- **Learning rate:** `$1 \times 10^{-5}$` for Llama 3.2 1B and Qwen-R1 1.5B; `$3 \times 10^{-5}$` for Qwen-R1 7B and 32B, and Qwen3-8B
- **Batch size:** 1024 for most models (following the original Llama recipe; Touvron et al., 2023); 256 for Qwen3-8B
- **Context length during training:** 4096 tokens for Llama 3.2 1B Instruct; 8192 tokens for Qwen-R1 models (to accommodate the longer sequences required by reasoning benchmarks); 32768 tokens for Qwen3-8B
- **Precision:** bfloat16 for model weights and activations; FP32 for optimizer states
- **Framework:** Megatron-LM (NVIDIA, 2024)
- **GPU:** NVIDIA H100
- **Sliding window size `$w$`:** 256 tokens (default); 16 for the Llama 3.2 1B ablation experiments in Table 1 and Figure 5

**No third fine-tuning phase:** Unlike DMC, which includes a third phase of training with a fixed compression ratio after the annealing phase, the paper found that "it provided negligible benefits for DMS" (Appendix C) and omits it.

#### Inference-Time Operation

During inference, DMS operates with hard binary decisions and leverages the sparsity for both memory reduction and computational savings.

**Binarization of decisions:** The training-time `$\alpha_t \in [0, 1]$` is converted to a binary decision:

$$\alpha_t^{\text{bin}} = \lfloor \text{sigmoid}(h_t w^\top + b) \rceil \in \{0, 1\}$$

**What this means:** The `$\lfloor \cdot \rceil$` notation denotes rounding to the nearest integer, which for values in `$[0, 1]$` is equivalent to thresholding at 0.5: if `$\text{sigmoid}(h_t w^\top + b) \geq 0.5$`, then `$\alpha_t^{\text{bin}} = 1$` (evict); otherwise `$\alpha_t^{\text{bin}} = 0$` (keep). After binarization, the attention mask uses `$\log(1 - \alpha_t^{\text{bin}})$`, which is exactly 0 for kept tokens and exactly `$-\infty$` for evicted tokens (outside the sliding window).

**KV cache management with delayed eviction:** Figure 2a illustrates the process. At time step `$t$`:
1. The incoming key–value pair `$(k_t, v_t)$` is generated and stored in the cache.
2. The model computes `$\alpha_t^{\text{bin}}$`.
3. If `$\alpha_t^{\text{bin}} = 1$`, the token is *scheduled* for eviction at time `$t + w$`.
4. For the next `$w$` steps (while the token is within the sliding window), it remains fully visible to attention.
5. At time `$t + w$`, the token falls out of the sliding window and is evicted—its slot in the KV cache becomes available for overwriting by a future token.

**Memory management via PagedAttention:** The paper explicitly addresses how evicted tokens interact with memory management:

> "Performance-wise, DMS does not introduce any new read/write operations on the KV cache, since the evicted tokens could be simply overwritten by incoming ones, under the assumption that the keys are stored in the KV cache with positional information. PagedAttention (Kwon et al., 2023) facilitates storing the sparsified KV cache in memory, where pages are allocated to individual attention heads." (Section 3.2)

**What this means practically:** In PagedAttention, the KV cache is divided into fixed-size blocks (pages). When a token is evicted, its page can be released or reused. Because DMS decisions are per-head, different heads may have different numbers of surviving tokens, requiring head-specific page allocation—a pattern that PagedAttention already supports. The evicted token's memory slot is simply marked as free; no explicit deletion operation is needed. This is simpler than DMC's merging, which would require modifying stored KV entries in-place (or creating new merged entries and freeing old ones), which is less natural under the PagedAttention abstraction where pages are intended to be immutable.

**Sparse prefilling:** The paper notes that DMS sparsity can also be leveraged during the prefilling phase (the initial forward pass that processes the input prompt):

> "The sparsity introduced by DMS is also leveraged during the prefilling phase to eliminate unnecessary computation" (Section 3.2)

Since DMS produces eviction decisions for every token (including prompt tokens), during prefilling the model can potentially skip attention computation over tokens that will be evicted anyway, reducing the quadratic cost of full attention. This is enabled by sparse attention implementations like FlashMask (Wang et al., 2025a).

**No extra parameters at inference:** Because the weight vector `$w$` was borrowed from an existing neuron, DMS introduces exactly zero additional parameters compared to the original model. The only overhead is the computation of `$\alpha_t^{\text{bin}}$` (a single linear projection + sigmoid per attention group per time step), which is negligible compared to the cost of full attention.

#### How DMS Integrates with Inference-Time Hyper-Scaling

The compressed models are deployed using standard **verifier-free inference-time scaling strategies**: majority voting and best-of-N weighted selection (Section 2.1, following the findings of Wang et al., 2025b that simpler methods remain most competitive). The key is that compression enables configurations that would be infeasible for the uncompressed model.

**Configurations explored:** The paper systematically varies three parameters (Section 5.1):
- **Width (W):** the number of parallel reasoning chains (e.g., 1, 2, 4, 8)
- **Length (L):** the maximum sequence length per chain (e.g., 8K, 16K, 32K tokens)
- **Compression ratio (CR):** the KV cache compression factor (1× for vanilla, 4×, 8× for DMS)

Each experimental point is denoted as a tuple `W-L-CR`, such as "8-16K-CR4" (8 parallel chains of up to 16K tokens each, with 4× compression).

**Metrics for comparison:** The paper evaluates these configurations on three implementation-agnostic efficiency metrics (Section 5.1):

1. **KV cache memory reads:** The total number of items in the KV cache attended to at each generation step, summed across all steps and all parallel chains. This is a proxy for latency because reading the KV cache from memory is the dominant cost. For vanilla models (CR 1×), this is proportional to the number of generated tokens. For compressed models, it's reduced proportionally to the compression ratio.

2. **Peak tokens in memory:** The maximum size of the KV cache at any point during generation, across all parallel chains combined. This reflects memory load and determines whether the configuration fits in VRAM.

3. **Throughput at maximum batch size:** The number of examples processed per minute when using the largest batch size that fits in GPU memory for each configuration. This measures real-world serving efficiency.

**Pareto frontier analysis:** For each method (DMS, Quest, TOVA, vanilla), the paper identifies the **Pareto frontier**—the set of `(efficiency, accuracy)` points that are not strictly dominated by any other point from the same method. The frontier shows the best achievable accuracy for each efficiency level. A method that pushes the frontier up and to the right (higher accuracy at lower cost) is superior.

**Why this evaluation framework matters for understanding DMS:** The critical test is not whether DMS preserves accuracy at the same token count (the "iso-token" comparison), but whether it preserves accuracy at the same **KV cache read count** while generating **more tokens** (the "iso-budget" comparison). If DMS at CR 4× can generate 32K tokens with the same KV cache reads as vanilla at 8K tokens, and if the additional reasoning from those 32K tokens improves accuracy more than the compression degrades it, the net effect is positive. This is the hyper-scaling hypothesis, and the Pareto frontier analysis is the framework for testing it.

The paper finds that DMS configurations consistently lie on the Pareto frontier, with specific configurations like "moderate parallel width + long sequences + high compression" dominating alternatives. We will examine these results in detail in the experimental analysis, but the technical approach—the combination of learned, delayed eviction with systematic exploration of the W-L-CR space—is what makes the evaluation possible.

#### Summary of Design Choices and Their Justifications

- **Binary eviction decisions rather than merging (like DMC):** Simpler to implement, compatible with PagedAttention's immutable page abstraction, and—when combined with delayed eviction—achieves comparable accuracy preservation. The paper's key finding is that sparsification is *sufficient*; the complexity of merging is not necessary.
- **Delayed eviction via sliding window rather than immediate eviction:** The central ablation (Figure 5 left) shows immediate eviction catastrophically degrades reasoning even at modest compression. A window of just 16 tokens preserves performance up to 4× compression. Larger windows (256 tokens) provide even stronger protection. This is the insight that makes sparsification viable where training-free methods fail.
- **Logit distillation rather than standard LM loss:** Provides richer training signal (matching full output distributions rather than just the correct token), robustness to shifts in training data distribution, and better stability for small models. This is borrowed from the model compression literature (Sreenivas et al., 2024; Minixhofer et al., 2025).
- **One-sided `$\ell_1$` auxiliary loss rather than symmetric or `$\ell_2$`:** Allows heads/layers to compress more than the target if beneficial, and provides constant gradient magnitude regardless of deficit size, preventing the compression loss from overwhelming the distillation loss early in training.
- **Linear CR annealing over 100 steps per CR unit rather than fixed target:** Produces a family of models from one training run, enabling systematic exploration of compression ratios without separate training. The specific schedule (CR increases by 1 every 100 steps) was found empirically to provide stable training.
- **Repurposing a query neuron rather than adding parameters:** Zero parameter overhead at inference, no architectural modification needed beyond the attention mask. This makes DMS a drop-in modification that can be applied to any Transformer with GQA.
- **Per-head, per-layer independent decisions rather than uniform compression:** Allows the model to discover which heads are compressible and which are critical. Figure 6 (right) confirms that learned compression ratios vary substantially across layers and heads, with early layers compressed less than later layers—the model learns to preserve information where it matters most.

## 4. Key Insights and Innovations

### Innovation 1: Reframing Inference-Time Scaling from "Token Budget" to "KV Cache Read Budget"

The paper's most fundamental conceptual move is to **disentangle generated tokens from effective compute cost**. Prior to this work, the inference-time scaling literature—from Snell et al. (2024) on compute-optimal test-time scaling to Brown et al. (2024) on repeated sampling to Muennighoff et al. (2025) on simple test-time scaling—universally equated "more inference compute" with "more generated tokens." The implicit assumption was that each additional token incurs a roughly constant incremental cost, so scaling the token budget linearly scales the compute budget.

This paper identifies that assumption as incorrect for Transformer LLMs under realistic hardware constraints. The dominant cost during auto-regressive generation is not token computation (the FLOPs to produce new keys, queries, and values) but **token retrieval**—reading the growing KV cache from high-bandwidth memory at every single generation step. The analytical model in Appendix I quantifies this: for Llama 3.1 8B on an H100 GPU, the KV cache read contribution to per-step latency grows from negligible at 2K context to over 80% at 128K context, and at large batch sizes effectively becomes **the entire latency**. Generated tokens and compute cost are therefore not interchangeable—they are coupled through a KV cache bottleneck that grows quadratically with sequence length (each token generation step must read all previous tokens' keys and values).

The reframing this enables is subtle but profound. Instead of asking "how do we allocate a fixed token budget between sequential and parallel scaling?", the paper asks "how do we maximize reasoning accuracy for a fixed **KV cache read budget**, which is the true compute bottleneck?" The difference is that the KV cache read budget can be expanded *without* increasing memory transfers if the cache itself is compressed. This transforms the problem structure: the optimization variable is no longer just the width (W) and length (L) of reasoning chains, but also the compression ratio (CR), creating a three-dimensional design space (W, L, CR) where points with equal KV cache read volume are directly comparable in terms of real-world latency and memory load.

This is a fundamental conceptual advance, not an incremental refinement. It changes what "compute-optimal" means for inference-time scaling: prior work optimized hyperparameters (beam width, revision depth, parallel samples) within a fixed token budget; this paper argues that the token budget itself is the wrong constraint, and that the KV cache read budget is the correct one. The implication is that any future work on inference-time scaling should report results against this metric, not against raw token counts, because the metric directly corresponds to the hardware bottleneck that determines real-world performance.

The empirical vindication of this reframing is that **configurations with more generated tokens but fewer KV cache reads can outperform configurations with fewer generated tokens but more KV cache reads**. For example, in Figure 3 (top), a DMS CR 8× configuration generating 32K tokens can match or exceed the accuracy of a vanilla CR 1× configuration generating 8K tokens, despite the compressed model generating 4× more raw tokens, because the KV cache read volume is comparable. Without the conceptual reframing, this comparison would be invisible—you would simply say "the 8K model is cheaper because it generates fewer tokens," missing the fact that the two configurations have equivalent latency.

### Innovation 2: Delayed Eviction as Implicit Token Merging—Making Sparsification Sufficient

The paper makes a diagnostic discovery that challenges the prevailing wisdom about what makes learned KV cache compression work. The prior state of the art, DMC (Nawrot et al., 2024), assumed that **explicit token merging** (weighted-averaging successive KV pairs) was necessary to preserve accuracy at high compression ratios. The intuition was that discarding tokens entirely (sparsification/eviction) inevitably loses information, and that merging provides a way to preserve the "gist" of multiple tokens in a single compressed representation. The training-free eviction literature (TOVA, H2O) seemed to confirm this: heuristic eviction degrades rapidly at high compression, suggesting that sparsification is inherently too lossy.

DMS challenges both halves of this assumption. It shows that **sparsification alone, when the model is trained to make intelligent timing decisions about when to evict, achieves comparable accuracy to explicit merging at a fraction of the training cost**. The mechanism—delayed eviction via a sliding window—is not, at surface level, fundamentally different from what training-free methods do (they also use sliding windows of recent tokens). What makes it work is the **learned timing**: the model decides, based on the evolving hidden state representation, exactly when a token's information has been sufficiently integrated into subsequent representations that it can be safely discarded. This is what the paper means by "implicitly merging": the token to be evicted remains visible for some number of steps, during which normal self-attention operations propagate its information forward; after that window, the token is removed, but its informational content has been (approximately) preserved in the hidden states of later tokens.

The ablations in Figure 5 (left) are the definitive evidence for this insight. The comparison between delayed eviction (window = 16) and immediate eviction (window = 0) on GSM8K is stark: immediate eviction causes accuracy to collapse from 47.0 (vanilla) to near zero at 4× compression, while delayed eviction preserves accuracy at ~41 (a drop of only 6 points). The fact that a window of only **16 tokens**—less than one sentence in typical text—makes the difference between catastrophic failure and near-vanilla performance tells us something deep: the model doesn't need tokens to stick around forever; it just needs them to stick around long enough for their information to be consumed by the attention mechanism. The training-free methods fail not because eviction is inherently lossy, but because they evict tokens **before the model has had a chance to read them**.

This is a fundamental insight (not incremental) because it changes how we think about the KV cache problem. The dominant framing in the efficient attention literature has been "which tokens should we keep?" (a selection problem). DMS reframes it as "when is it safe to delete a token?" (a scheduling problem). The difference is that selection assumes information is static and localized in individual tokens; scheduling recognizes that information propagates through the transformer via attention, and that a token can be safely deleted once its information has been distributed to successor tokens. This connects to a broader principle in sequence modeling: what matters is not the retention of individual tokens but the retention of the **information state** they carry, and the transformer architecture itself provides a mechanism (self-attention) for transferring that state forward.

The practical payoff is the dramatic reduction in training cost compared to DMC: ~700 steps for DMS to reach CR 8× vs. ~44K steps for DMC, a ~60× reduction. This is not just an implementation efficiency—it's a consequence of the simpler learning problem. DMC must learn both *what* to merge (which tokens contain redundant information) and *how* to merge (the weighted-averaging coefficients). DMS only needs to learn *when* to delete, because the "how to merge" is handled for free by the pretrained attention mechanism operating within the sliding window. The training signal is therefore cleaner and converges faster.

### Innovation 3: The Compression Budget as a Learnable, Per-Component Allocation Problem

Training-free KV cache compression methods (TOVA, H2O, Quest) impose **uniform compression**: every attention head, every layer, and every sequence position is compressed at the same ratio. This assumption—that all components of the model are equally compressible—is mathematically convenient but almost certainly false. Different attention heads specialize in different linguistic phenomena (some track long-range syntactic dependencies, others attend to local collocations); different layers process different levels of abstraction (early layers capture surface patterns, late layers capture semantic content); different token positions carry different amounts of information (the beginning of a reasoning chain defining the problem is more critical than the middle of a repetitive computation).

DMS converts the compression allocation problem into something the model **learns**. The auxiliary loss (Section 3) penalizes only the *global average* eviction rate across all layers, heads, and positions: `$L_{\text{aux}} = \max(\alpha^\star \cdot L \cdot H \cdot T - \sum \alpha_{lht}, 0)$`. This means the model can allocate its total eviction budget non-uniformly—heavily compressing heads that process redundant information while leaving critical heads nearly uncompressed. The only constraint is that the average meets the target.

Figure 6 (right) empirically confirms that the model exploits this flexibility: early layers are compressed less than later layers (they retain ~80% of tokens vs. ~20–40% for later layers at CR 8×), and there is substantial variation across heads within layers. The model has discovered that early-layer representations, which encode lower-level features needed as inputs to all subsequent processing, are less compressible than late-layer representations, where much of the information has already been abstracted into higher-level features carried by a subset of tokens. This mirrors findings from the pruning and sparsity literature (where early layers are typically sparsified less aggressively) but emerges here purely from the end-to-end compression objective without any architectural prior.

This is an incremental but significant innovation because it resolves a tension in the KV cache compression literature. Training-free methods are forced to impose uniform compression because they lack a training signal to learn otherwise; DMC and DMS can learn non-uniform compression because they optimize a global objective. The key advance in DMS compared to DMC is that the same non-uniform allocation is achieved with a simpler mechanism (binary eviction vs. weighted merging) and dramatically less training. The paper shows that the complexity of merging is not what enables non-uniform compression—simple eviction with learned allocation does just as well.

The broader significance is that this establishes a principle: when compressing a transformer's memory, the **allocation** of the compression budget across components matters as much as the **mechanism** of compression. Future work on KV cache reduction should report not just global compression ratios but the distribution of compression across layers and heads, because the distribution reveals whether the method is making intelligent trade-offs or simply discarding information uniformly. The paper implicitly criticizes the training-free literature for lacking this analysis—TOVA and H2O papers don't ask "where is compression happening?" because the answer is predetermined by the heuristic.

### Innovation 4: Negative Evidence That More Complex Training Objectives Can Backfire—The Sufficiency of Distillation + Simple Auxiliary Loss

This innovation is methodological rather than conceptual, but has significant practical implications for the field. The paper makes a deliberate, empirically-grounded choice to use **logit distillation** rather than the standard language modeling loss for retrofitting. On its surface, this might seem like an implementation detail. But the paper presents evidence that this choice is not merely convenient—it is **necessary for stable training**, especially for smaller models, and that more complex training procedures can actively harm compression performance.

Two pieces of evidence support this. First, the paper explicitly notes (Section 4) that "logit distillation provides greater robustness to shifts in training data, since the original data mixtures are rarely public, and is especially beneficial for fragile LLMs with lower parameter counts." The practical reality of retrofitting pretrained models is that you rarely have access to the original training data. Using next-token prediction loss on out-of-distribution text can cause catastrophic forgetting—the model unlearns pretrained behaviors in favor of fitting the surrogate data. Distillation sidesteps this because the training signal is "match the teacher's output distribution" rather than "predict this specific token," which is a softer constraint that preserves more of the pretrained behavior.

Second, the negative result from the DMC comparison is revealing. DMC uses standard language modeling loss and requires three training phases (warm-up, CR annealing, fixed-CR fine-tuning). DMS with distillation achieves better accuracy (Figure 5, right) while using a single annealing phase and 8× fewer training tokens. The paper doesn't over-interpret this—it simply presents the evidence—but the implication is that **distillation provides a richer, more stable learning signal for the compression task** than next-token prediction. This makes intuitive sense: the compression task requires the model to produce the same outputs as the teacher *despite having less context*, which is exactly what distillation trains for (matching output distributions under different input conditions).

The paper also documents a **negative result with ReST^EM**-style iterative training (Appendix K of the prior paper, referenced in the prior paper's Section 8—note: this paper does not include this experiment; it's from the related DMC work context). Attempting to further optimize a revision model with RL-style training caused performance to degrade, suggesting that the simple distillation approach is a sweet spot—complex enough to preserve knowledge but not so complex that it introduces unstable training dynamics.

This is an incremental but practically significant insight. The takeaway for practitioners is: when retrofitting models for compression, start with distillation. It is more robust, requires less hyperparameter tuning, and avoids the need for access to the original training data. The conceptual contribution is the recognition that compression training is fundamentally a **knowledge preservation** problem (keep everything the teacher knows while reducing memory) rather than a **data fitting** problem (learn to predict tokens on new data), and distillation aligns more naturally with this objective.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The primary experiments for inference-time hyper-scaling use four reasoning benchmarks: **AIME 24** and **MATH-500** (Hendrycks et al., 2021a) for mathematical reasoning, **GPQA Diamond** (Rein et al., 2024) for graduate-level physics, chemistry, and biology, and **LiveCodeBench** (Jain et al., 2025) for coding tasks. Additional general-purpose evaluations include GSM8K (Cobbe et al., 2021) for grade-school math, MMLU (Hendrycks et al., 2021a) for factuality, HellaSwag (Zellers et al., 2019) for common-sense reasoning, and Needle in a Haystack (NIAH; Kamradt, 2023) and Variable Tracking (VT; Hsieh et al., 2024) for long-context processing. For MATH-500 and AIME 24, outputs are parsed into a unified math representation and scored via exact match using MathVerify (Kydlíček and Gandenberger, 2025). For GPQA Diamond, the model must select one of four choices. For LiveCodeBench (covering tasks from 2024-08-01 to 2025-01-31), the metric is pass@all—a success is counted if any generated sequence passes the provided tests.

- **Base model(s).** The primary testbed consists of **Qwen 2.5 models distilled from DeepSeek R1** (Guo et al., 2025) at three scales: 1.5B, 7B, and 32B parameters. These are reasoning models specifically trained for chain-of-thought generation, making them natural targets for inference-time scaling experiments. Additionally, **Qwen3-8B** (distilled from Qwen3-235B-A22B; Yang et al., 2025) is used for broader task evaluation including throughput measurements. For ablations and method development, **Llama 3.2 1B Instruct** (Grattafiori et al., 2024) serves as a smaller, non-reasoning testbed. A key architectural note: all these models use **Grouped Query Attention (GQA)** (Ainslie et al., 2023), meaning multiple query heads share a single set of KV heads, which the paper argues "exacerbates the destructive effects of training-free token eviction" (Section 4) because eviction decisions based on one query's attention pattern may destroy information needed by other queries in the same group.

- **Metrics.** The paper uses three implementation-agnostic efficiency metrics to compare configurations on equal footing: **(i) KV-cache memory reads**—the total number of KV cache items attended to at each generation step, summed across all steps and parallel chains, serving as a proxy for latency (since reading the KV cache from high-bandwidth memory dominates generation time); **(ii) peak tokens in memory**—the maximum KV cache size at any point during generation across all chains, reflecting memory load on GPU VRAM; and **(iii) throughput at maximum batch size**—examples processed per minute when using the largest batch size that fits in GPU memory for each configuration, measured on an NVIDIA H100 SXM GPU in 16-bit precision using a Hugging Face Transformers implementation with FlashAttention (Dao, 2024). Accuracy is measured as exact match (MATH-500, AIME 24), multiple-choice accuracy (GPQA Diamond), or pass@all (LiveCodeBench). All metrics are reported across varying **W-L-CR** configurations, where W is the number of parallel reasoning chains (width), L is the maximum sequence length, and CR is the compression ratio (1× for vanilla).

- **Baselines.** The paper compares DMS against three categories of baselines: **(i) Vanilla Transformer**—the original uncompressed LLM at CR 1×, using standard dense attention with a full KV cache; **(ii) Training-free KV cache sparsification methods**—TOVA (Oren et al., 2024), which evicts the token with the lowest attention weight at each step; H2O (Zhang et al., 2023a), which evicts tokens with the lowest cumulative attention scores while keeping a sliding window of recent tokens; and Quest (Tang et al., 2024), which retains the full KV cache in memory but selectively retrieves only the most relevant pages using a heuristic based on highest-magnitude KV dimensions; **(iii) Learned KV cache compression**—DMC (Nawrot et al., 2024), which dynamically decides whether to append or merge tokens via weighted averaging, trained through continued retrofitting with a compression rate target. For the main inference-time scaling experiments, only the strongest training-free baselines are shown: Quest for accuracy–latency comparisons and TOVA for accuracy–memory load comparisons. All baseline implementations "closely follow the publicly available reference implementations" (Section 4, footnote 2). For H2O and TOVA, the KV budget is computed by summing input length and maximum generation length, then dividing by the compression ratio; for TOVA specifically, the budget is evenly split between the recent cache and the heavy-hitter cache. Quest is permitted to perform prefilling using full dense attention (unlike the memory-reducing methods), with block size set to max(16, 2 × CR), and uses separate top-k for each query head—a configuration that the authors note "provides Quest with an advantage over the other methods" (Appendix H.1).

- **Generation budget / compute accounting.** The fundamental unit of comparison is not generated tokens but **KV-cache token reads**. For a given W-L-CR configuration, the KV cache memory reads are computed as the total number of KV entries attended to across all generation steps and all parallel chains, accounting for the compression ratio. This is what makes configurations with different W, L, and CR directly comparable: a DMS CR 8× configuration generating 32K tokens requires roughly the same KV cache read volume as a vanilla CR 1× configuration generating ~4K tokens per chain (because 32K / 8 = 4K effective reads per step). The peak tokens in memory metric accounts for all parallel chains simultaneously resident in VRAM. Throughput measurements use the maximum batch size that fits in memory for each configuration, with batch size reflecting both the number of parallel reasoning threads per query and the number of distinct queries being served (Figure 4 bottom illustrates how batch size interacts with context length to determine when inference becomes memory-bound).

- **Cross-validation / statistical protocol.** For the long-context tasks (NIAH, VT), the paper uses the evaluation implementation from RULER (Hsieh et al., 2024) with the context length matching the retrofitting procedure. For GSM8K, MMLU, ARC-Challenge, and HellaSwag, the Language Model Evaluation Harness (Gao et al., 2024) version 0.4.3 is used. For AIME 24 results with Qwen3-8B, scores are averaged over 10 runs with different seeds; MATH-500 results use 3 runs. Standard errors are reported for Llama 3.2 1B Instruct experiments in Table 6 (Appendix G). The Pareto frontier analysis (Tables 8 and 9) identifies the largest common budget interval shared by each pair of methods and computes average improvement via numerical integration of the accuracy difference, using linear interpolation for budget values not explicitly measured.

### Main Quantitative Results

#### Inference-Time Hyper-Scaling: Accuracy vs. KV Cache Memory Reads

The headline result appears in Figure 3 (top) and Figure 7 (top): **DMS consistently achieves Pareto-optimal trade-offs between accuracy and KV cache memory reads across all model scales and all four reasoning benchmarks**, dominating both vanilla models and training-free compression baselines.

**AIME 24 results (Figure 3, top-left three panels):** On AIME 24, the most challenging math benchmark, DMS delivers the largest gains. For Qwen-R1 1.5B, DMS configurations at CR 4× and CR 8× push the accuracy–efficiency frontier substantially rightward: configurations like 4-16K and 1-32K with DMS CR 8× achieve ~30% accuracy at KV cache read volumes where vanilla CR 1× configurations with similar reads achieve ~20–22%. The 7B model shows even more dramatic improvement: DMS configurations reach 50–53.3% accuracy across a wide range of budgets, while vanilla models at comparable read volumes achieve 40–47%. For the 32B model, DMS pushes accuracy from the vanilla frontier of roughly 70–73.3% up to 73.3–80% at equivalent read volumes. The Pareto improvement is quantified in Table 8: DMS improves the average accuracy along the frontier over vanilla by **10.6 points (1.5B), 15.0 points (7B), and 12.0 points (32B)**. Quest, the best training-free baseline, achieves only 2.0–3.1 points of improvement over vanilla at 1.5B and 7B, and underperforms vanilla at 1.5B (delivering a negative −6.8 point average improvement).

**LiveCodeBench results (Figure 3, top-right three panels):** For coding tasks, DMS similarly dominates. At 1.5B scale, DMS configurations achieve 17–25% pass@all across a wide budget range, compared to 15–17% for vanilla at equivalent reads (Table 8: +7.3 point improvement). For the 7B model, DMS pushes the frontier from approximately 35.9% (vanilla at 16K, width=1) to 40–50% across expanded budgets (Table 8: +7.9 points). At 32B, the gains are largest: DMS reaches 60–70% compared to vanilla's 57% at similar read volumes (Table 8: +9.7 points). DMS vs. Quest improvements average 3.4–5.6 points across scales. Notably, the W-L-CR configurations on the DMS Pareto frontier for LiveCodeBench tend to combine moderate parallel width with long sequences and high compression ratios (e.g., 8-32K-CR8, 7-32K-CR8 for the 7B model).

**MATH-500 results (Figure 7, top-three panels):** Gains on MATH-500 are more modest but still positive, reflecting the benchmark's lower difficulty ceiling. At 1.5B, DMS adds 4.2 points of average frontier improvement over vanilla (Table 8), with configurations achieving 85–90% accuracy at read volumes that would limit vanilla to 82–85%. At 7B and 32B, gains shrink to 1.0 and 1.6 points respectively, as vanilla models already reach 92–96% accuracy even at modest budgets. Quest provides no improvement on MATH-500 at 1.5B and 7B (negative average improvements over vanilla in Table 8), while DMS delivers consistent (if small) positive gains. This saturation effect is expected and acknowledged by the authors: "Variability across datasets primarily reflects their saturation levels; for instance, models achieve very high performance on MATH-500 even with limited budgets" (Section 5.1).

**GPQA Diamond results (Figure 7, top-three panels):** For graduate-level science questions, DMS improvements are substantial and scale with model size. At 1.5B, DMS adds 4.8 points over vanilla (Table 8), with configurations reaching 35–40% accuracy versus 30–37% for vanilla. At 7B, the gain is 4.1 points (DMS reaches ~50–55% vs. vanilla's ~45–51.5%). At 32B, the gain is largest: 8.6 points, with DMS configurations achieving 60–70% versus vanilla's 60–65%. Quest shows no improvement on GPQA Diamond at any scale—the paper notes "NA" in Table 8 for Quest vs. Vanilla, indicating disjoint Pareto frontier projections on the budget axis, meaning Quest's frontier doesn't overlap with vanilla's in the regions where comparisons can be made.

**Configurations on the Pareto frontier:** The paper notes (Section 5.1) that "for most tasks, these consist of a combination of sequential and parallel scaling, hinting at the necessity of using both for inference-time scaling." Moreover, "most DMS points (for CRs of 4× and 8×) lie on the Pareto frontier, indicating that even higher compression retains sufficient quality to afford superior trade-offs." This is a crucial empirical finding: hyper-scaling is not about choosing between compression ratios—it's about deploying high compression to enable configurations (longer sequences, more parallel chains) that would be infeasible without compression, and the quality retention of DMS at CR 8× is sufficient to make these configurations net-positive.

**The horizontal black reference lines** in Figure 3 mark the accuracy reported by Guo et al. (2025) for the 1-32K vanilla configurations. DMS configurations consistently meet or exceed these reference accuracies at lower or equivalent KV cache read volumes.

#### Inference-Time Hyper-Scaling: Accuracy vs. Peak Memory

Figure 3 (middle) and Figure 7 (middle) compare methods on accuracy versus peak tokens in memory—the primary constraint for hardware with limited VRAM. The pattern mirrors the memory reads results: **DMS dominates TOVA (the best training-free baseline for memory reduction) across all model sizes and tasks.**

**Quantified improvements (Table 9):** On AIME 24, DMS improves average frontier accuracy over vanilla by 17.3 (1.5B), 15.7 (7B), and 14.6 (32B) points—substantially larger than TOVA's improvements of 5.3, −0.2, and 2.6 points respectively. DMS vs. TOVA gaps are 9.6, 15.6, and 8.1 points. On LiveCodeBench, DMS adds 7.4 (1.5B), 8.5 (7B), and 16.7 (32B) points over vanilla, versus TOVA's 3.8, 3.3, and 4.9 points. On GPQA Diamond, DMS delivers 4.9–8.0 points across scales while TOVA ranges from −2.1 to +2.1 points—TOVA actually underperforms vanilla at 1.5B and 7B in terms of memory–accuracy trade-off.

The key practical implication is that DMS enables configurations that fit in memory-constrained environments while maintaining accuracy. For example, a DMS CR 8× configuration at 32K sequence length requires roughly the same peak memory as a vanilla configuration at 4K, but generates substantially longer reasoning chains that improve accuracy.

#### Iso-Token Comparison: DMS vs. Vanilla at the Same Sequence Length

While the hyper-scaling results compare at iso-budget (same KV cache reads), the paper also provides iso-token comparisons—DMS and vanilla evaluated at the same sequence length and width—to isolate the direct accuracy cost of compression (Tables 10–12, Appendix G).

**At CR 4× (Table 10, compared against Quest CR 4× at equivalent reads, and Table 11 compared against TOVA CR 4× at equivalent memory):** For the 32B model on AIME 24 at 32K length and width=1, DMS CR 4× achieves 73.3% versus vanilla's 70.0%—actually **outperforming** the uncompressed model. This seemingly paradoxical result likely reflects the regularizing effect of sparsification or the fact that the same budget allows more parallel samples at the compressed setting in the wider experiments. At 7B, DMS matches vanilla at 53.3%. On LiveCodeBench at 16K and width=1 (32B), DMS CR 4× scores 54.8% versus vanilla's 57.0%—a drop of only 2.2 points for 4× memory savings. On MATH-500 (32B, 32K), DMS CR 4× scores 94.6% versus vanilla's 94.8%—essentially identical. TOVA CR 4× (Table 11) shows larger degradation: on AIME 24 (7B), it drops to 46.7% from vanilla's 53.3%; on LiveCodeBench (7B), it drops to 30.7% from 35.9%.

**At CR 8× (Table 12, width=1):** The degradation becomes more noticeable but remains manageable. On AIME 24 (32B, 32K), DMS CR 8× scores 73.3% versus vanilla's 70.0%—again outperforming (though this may reflect variance or the regularization effect noted above). At 7B, it drops to 50.0% from 53.3%. On LiveCodeBench (32B, 16K), DMS CR 8× achieves 51.7% versus vanilla's 57.0%, a drop of 5.3 points for 8× compression. On MATH-500, the drop at 1.5B is from 84.8% to 80.0%; at 7B from 94.0% to 93.0%; at 32B from 94.8% to 94.6%. The compression cost is modest and—crucially—the iso-token comparison understates DMS's value, since the hyper-scaling results show that the compressed model can generate more tokens within the same read budget, recovering or exceeding the small iso-token loss.

#### Throughput Measurements: Real-World Speedups

Figure 3 (bottom) and Figure 7 (bottom) translate the implementation-agnostic metrics into measured throughput on NVIDIA H100 SXM hardware. **DMS configurations achieve higher throughput at equivalent or better accuracy compared to vanilla models.**

On AIME 24 with Qwen-R1 1.5B, the DMS Pareto frontier reaches ~30% accuracy at approximately 4–6 examples/minute, while vanilla requires ~1–2 examples/minute for similar accuracy. For the 7B model, DMS achieves 40–60% accuracy at 2–4 examples/minute, substantially above vanilla at equivalent throughput. At 32B, the DMS frontier enables ~65–80% accuracy at throughput levels where vanilla cannot reach comparable accuracy at any throughput.

Figure 8 (for Qwen3-8B on LiveCodeBench) explicitly quantifies the throughput multiplier: **DMS enables matching vanilla accuracy with up to 5× higher throughput**. The configurations span CR 4×, 8×, and 12×, with the higher compression ratios enabling larger batch sizes that saturate GPU compute more effectively.

Figure 4 provides the mechanistic explanation: latency per generation step initially stays flat as context length grows (the compute-bound regime), but at some critical context length—which depends on batch size and model scale—it begins to rise linearly due to the KV cache memory read bottleneck. For Qwen3-8B at batch size 128, vanilla runs out of memory entirely at ~16K context length, while DMS CR 4× and CR 8× continue operating. Even at batch size 32, the vanilla 32B model shows rising latency starting around 4K context, while DMS maintains lower absolute latency and flatter scaling.

**Quantified Pareto improvements for throughput (Table 7):** DMS over vanilla averages 5.0 (1.5B), 2.2 (7B), and 3.3 (32B) points on MATH-500; 5.6, 6.0, and 8.4 points on GPQA Diamond; and 8.1, 7.3, and 13.2 points on LiveCodeBench. The negative value for AIME 24 1.5B (−1.5) is the only case where DMS does not improve the throughput–accuracy frontier over vanilla, likely reflecting the limited headroom for the smallest model on the hardest benchmark.

#### DMS for General-Purpose LLMs

Table 1 (Section 5.2) evaluates Llama 3.2 1B Instruct on a broad set of tasks at compression ratios 2×, 3×, and 4×, comparing DMS (with a modest 16-token sliding window) against H2O, TOVA, Quest, and DMC.

**Key findings at CR 4×:** On GSM8K, DMS scores 42.3 versus vanilla's 47.0—a drop of 4.7 points, compared to H2O's catastrophic 14.7 (−32.3 points) and TOVA's 20.2 (−26.8 points). Quest achieves 39.9 and DMC only 3.6. On MMLU, DMS scores 40.3 versus vanilla's 47.9; H2O collapses to 25.6. On HellaSwag, DMS matches vanilla exactly (43.4 vs. 43.4), while all baselines degrade. On NIAH, DMS scores 96.8 versus vanilla's 96.4—**outperforming** the uncompressed model—while H2O drops to 13.4 and DMC collapses to 0.0. On Variable Tracking, DMS achieves 67.6 versus vanilla's 55.8—a **+11.8 point gain** over vanilla—while H2O scores 12.6 and DMC 4.0.

**The DMC collapse phenomenon:** DMC catastrophically fails on long-context extrapolation. At CR 4× on NIAH (4K context), DMC scores 0.0 versus DMS's 96.8. The paper attributes this to DMC's training objective being more brittle and its difficulty extrapolating beyond the retrofitting context length (4K tokens) during inference, whereas DMS with delayed eviction generalizes more gracefully (Appendix F, Table 4).

Table 2 (Section 5.2) evaluates DMS 8× on Qwen3-8B with a sliding window of 512 tokens across a comprehensive set of tasks including math, science, coding, conversation, and instruction following. **DMS 8× is within close range of vanilla across all benchmarks**: GPQA Diamond 57.6 vs. 58.8 (−1.2), MMLU-Pro 73.5 vs. 74.2 (−0.7), AIME 2024 73.0 vs. 75.0 (−2.0), MATH-500 95.5 vs. 95.1 (+0.4), HumanEval 89.6 vs. 87.8 (+1.8), IFEval 88.8 vs. 90.3 (−1.5), ArenaHard v0.1 89.7 vs. 88.4 (+1.3). The average absolute deviation is approximately 1.3 points, with some benchmarks showing DMS slightly **above** vanilla and others slightly below—consistent with variance rather than systematic degradation.

#### Learned Compression Patterns

Figure 6 (left) shows how the measured compression ratio varies with context length for Qwen-R1 7B trained with DMS CR 4× while processing AIME 24, MATH-500, and GPQA Diamond instances. **The model sparsifies less than the target CR in early parts of sequences but more aggressively than specified beyond ~10K tokens.** This pattern "closely matches that reported in Nawrot et al. (2024)" and stems from two factors: the one-sided auxiliary loss formulation (which only penalizes under-compression, not over-compression) and the decreasing conditional entropy rate of text as context grows—the model finds it easier to compress redundant later tokens.

Figure 6 (right) reveals the per-head compression distribution for Qwen-R1 7B at CR 8×. **Early layers retain a higher fraction of tokens (~80% at layer 1, declining to ~20–40% by layers 20–28), and there is substantial variation across KV heads within each layer.** This confirms that the model learns to allocate the compression budget non-uniformly—preserving information in early layers where representations encode lower-level features needed by all subsequent processing, while aggressively compressing later layers where information has been abstracted.

### Ablation Studies and Robustness Checks

**Delayed eviction (sliding window) vs. immediate eviction:** Figure 5 (left) provides the critical ablation. On Llama 3.2 1B Instruct evaluated on GSM8K 0-shot, immediate eviction (window=0) causes rapid accuracy degradation: at CR 2×, GSM8K score drops from 47.0 (vanilla) to approximately 20; at CR 4×, it collapses to near zero. Delayed eviction with a window of just 16 tokens preserves reasoning: at CR 2×, score remains ~47 (identical to vanilla); at CR 4×, score is ~41. Larger windows (64, 256) provide even stronger protection. The paper states: "Remarkably, DMS retains reasoning capabilities with a window of only 16 tokens up to a compression ratio of 4×" (Section 5.3). This ablation is the central empirical justification for the delayed eviction mechanism—it demonstrates that the quality gap between DMS and training-free eviction methods is not primarily about the decision heuristic (learned vs. rule-based) but about the **timing** of eviction (delayed vs. immediate).

**Data efficiency: DMS vs. DMC:** Figure 5 (right) compares DMS and DMC retrained on Llama 3.2 1B with varying training token budgets, evaluated on GSM8K. DMS achieves higher scores than DMC while using **8× fewer training tokens**. DMC requires ~44K steps to reach CR 8× in the original paper; DMS reaches CR 8× in 700 steps. The paper notes that the Qwen-R1 models were trained with "60× less training data" than DMC would require, achieving CR 4× within 300 steps and CR 8× within 700 steps (Section 5.3). This ablation validates DMS's claim to being "inexpensive" compared to existing learned compression methods.

**Sliding window size:** Figure 5 (left) implicitly ablates this by comparing window sizes of 0, 16, 64, and 256. Larger windows monotonically improve accuracy, though diminishing returns appear: the jump from window=0 to window=16 is dramatic (saving accuracy from collapse), while the jump from 64 to 256 provides more modest gains. The default window of 256 is chosen as a practical compromise between providing sufficient integration time and maintaining effective compression at realistic sequence lengths.

**Compression ratio annealing schedule:** The paper uses a linear schedule of 100 steps per CR unit (Section 4, Appendix C). No explicit ablation of different schedules is reported (e.g., exponential, step-function, or varying the steps-per-CR parameter). This is a gap—the sensitivity of final accuracy to the annealing rate is not characterized, though the paper's ability to reach CR 8× in 700 steps with good accuracy suggests the current schedule is at least sufficient.

**Logit distillation vs. standard LM loss:** The paper states that logit distillation was chosen because it "provides greater robustness to shifts in training data" and "is especially beneficial for fragile LLMs with lower parameter counts" (Section 4), but **no direct ablation comparing distillation to standard next-token prediction loss is presented** for DMS. The evidence is indirect: DMC (which uses LM loss) performs worse and requires more data in the Figure 5 (right) comparison. However, since DMC also differs in its compression mechanism (merging vs. sparsification), the comparison confounds the loss function with the compression architecture. A controlled experiment—DMS trained with LM loss vs. DMS trained with distillation, holding all else equal—would have strengthened this claim but is absent.

**One-sided vs. symmetric auxiliary loss:** The choice of a one-sided ℓ1 auxiliary loss (penalizing only under-compression) is discussed but not ablated. The paper argues that the one-sided form allows heads to compress more aggressively than the target if beneficial, but no experiment compares one-sided against symmetric or ℓ2 variants. This is a design choice justified by intuition rather than direct empirical comparison.

**Per-head vs. uniform compression (implied ablation):** While not presented as a formal ablation, the comparison between DMS (which learns per-head compression) and training-free methods (which impose uniform compression) implicitly demonstrates the value of non-uniform allocation. Figure 6 (right) confirms that the learned allocation is highly non-uniform, and Tables 8–9 show DMS substantially outperforms uniform-compressing baselines. However, the specific contribution of non-uniformity is confounded with the contribution of learned decision-making—a DMS variant forced to use uniform per-head compression would isolate this effect but is not reported.

**Sparse prefilling:** The paper mentions that "the sparsity introduced by DMS is also leveraged during the prefilling phase to eliminate unnecessary computation" (Section 3.2) and that this does not affect performance in short generation settings (Table 1 shows DMS matching vanilla on MMLU and HellaSwag, which have short generation lengths). However, no explicit ablation comparing DMS with and without sparse prefilling is presented, and the accuracy impact of prefilling sparsification is not separately measured.

**Negative result: immediate eviction is fundamentally inadequate:** The Figure 5 ablation is a strong negative result showing that the natural baseline—learned eviction without delay—fails completely. This is important because it demonstrates that the "intelligence" in DMS comes not from the learned decision itself but from the **combination** of learned decision and delayed execution. A naive extension of training-free methods that simply learns the eviction score (without delay) would not work.

**Negative result: DMC fails to extrapolate context length:** Table 4 (Appendix F) shows that DMC at CR 4× on NIAH scores 0.0 at 4K and 8K context lengths, despite being retrofitted at 4K, while DMS at window=16 scores 97.8 and 99.4. This is a practically significant finding: it means DMC's training procedure is brittle to length extrapolation, whereas DMS's sliding window mechanism provides inherent robustness. The paper attributes this to DMC's "more challenging training objective amplified by the limited 1B model capacity" (Appendix F), but the failure mode is striking enough to warrant caution for practitioners considering DMC for long-context applications.

**Quest's advantage does not translate to superior Pareto frontiers:** Despite the paper giving Quest the advantage of full dense prefilling and per-query-head top-k (Appendix H.1), DMS still achieves better accuracy–latency trade-offs (Table 8). This strengthens the claim that DMS's quality retention, not just its compression mechanism, drives the hyper-scaling gains.

### Critical Assessment

#### Does the paper demonstrate that KV cache compression enables inference-time hyper-scaling (its central claim)?

**Yes, with important scope boundaries.** The evidence in Figure 3 and Figure 7 convincingly shows that DMS-compressed models achieve higher accuracy than vanilla models at equivalent KV cache memory reads across AIME 24, LiveCodeBench, GPQA Diamond, and MATH-500. The Pareto frontier analysis (Tables 8–9) quantifies these gains, which are large on difficult benchmarks (10–15 points on AIME 24 at 7B and 32B scales) and positive but modest on saturated benchmarks (1–4 points on MATH-500). The key mechanism—compression enables longer sequences or more parallel chains within the same read budget, and the additional reasoning improves accuracy more than compression degrades it—is directly visible in the W-L-CR configurations: the Pareto-optimal DMS points tend to use high CR values with expanded L or W relative to vanilla.

However, the demonstration is limited to a specific regime: **(i)** reasoning models from the Qwen-R1 family, **(ii)** compression ratios of 4× and 8×, **(iii)** sequences up to 32K tokens, and **(iv)** verifier-free majority voting / best-of-N scaling strategies. The paper does not test whether hyper-scaling works with non-reasoning base models (the Llama 3.2 1B experiments evaluate DMS quality but do not perform the W-L-CR hyper-scaling sweep), with PRM-guided search strategies, with models using different attention architectures (e.g., Multi-head Latent Attention in DeepSeek-V2), or at extreme compression ratios beyond 8×. The claim that hyper-scaling "push[es] inference-time scaling to new frontiers" (Section 6) is therefore supported specifically for the R1-style reasoning model family using majority voting, and generalizability to other settings remains an open question.

#### Does the paper demonstrate that DMS is "inexpensive, easy to integrate, and maintains accuracy at high compression ratios"?

**Partially.** The "inexpensive" claim is well-supported: DMS reaches CR 8× in 700 training steps versus ~44K for DMC, a ~60× reduction (Section 5.3, Figure 5 right). Table 3 provides concrete GPU-hour costs (75 GPU-hours to train Qwen-R1 7B from CR $i$ to CR $i+1$). The "maintains accuracy" claim is supported by the iso-token comparisons (Tables 10–12): at CR 4×, DMS is within 0–3 points of vanilla across most tasks; at CR 8×, within 3–7 points; on some configurations, DMS even slightly outperforms vanilla (possibly reflecting variance or regularization). The general-purpose evaluation (Tables 1–2) confirms DMS's robustness across diverse task types. The "easy to integrate" claim is supported by the zero-parameter-overhead design (neuron borrowing) and PagedAttention compatibility (Section 3.2), but no implementation-level ablation (e.g., measured integration effort in lines of code, compatibility testing with popular serving frameworks like vLLM) is provided—the claim rests on architectural reasoning rather than empirical integration evidence.

**A significant unaccounted cost** is the difficulty estimation analog from the Snell et al. (2024) paper: DMS requires retrofitting, which means for each new base model, a retraining run is needed. The paper argues this is cheap (~1K steps), but it's still a barrier to adoption compared to training-free methods like Quest that require zero model modification. The paper does not discuss whether a single DMS checkpoint transfers across related models (e.g., can the Qwen-R1 7B DMS weights be used to initialize Qwen-R1 32B DMS training?), which would further reduce the practical cost.

#### Are the baseline comparisons fair?

**Generally yes, with one notable asymmetry.** The paper gives Quest—the strongest training-free baseline for latency—the advantage of full dense prefilling and per-query-head top-k (Appendix H.1), which actually increases Quest's memory reads compared to a more constrained implementation. Despite this advantage, DMS still dominates Quest on the Pareto frontier (Table 8). This strengthens the DMS result.

However, the comparison between DMS and DMC is confounded in the data efficiency ablation (Figure 5 right): DMS uses logit distillation while DMC uses standard LM loss, so the 8× data efficiency gain may partially reflect the superiority of distillation rather than the architectural choice of sparsification over merging. A controlled experiment with DMC trained via distillation (or DMS trained via LM loss) would isolate the architectural contribution to data efficiency.

Additionally, **the vanilla baseline uses only a limited set of W-L configurations** (primarily the diagonal of the W-L space): the paper does not explore whether vanilla models with more aggressive parallel scaling (very large W at short L) or more aggressive sequential scaling (very long L at W=1) could partially recover the DMS advantage. The hyper-scaling claim is that compression enables configurations that are *infeasible* for vanilla (they would exceed memory), but the paper could strengthen this by explicitly marking which vanilla configurations hit out-of-memory and are therefore missing from the Pareto frontier.

#### What experiments would have strengthened the paper but are absent?

**1. Hyper-scaling with non-reasoning models:** The paper establishes DMS quality on Llama 3.2 1B Instruct (Table 1) but never performs the W-L-CR hyper-scaling sweep on this model. This would test whether hyper-scaling requires reasoning-specialized models or generalizes to any LLM.

**2. Combination with PRM-guided search:** The paper explicitly notes in Section 5.4 that "hyper-scaling can be extended to PRM strategies" and that the PRM "would need to be accelerated by prefilling-time sparse attention methods, such as MInference," but leaves this to future work. This is a significant gap because PRM-guided search (beam search, lookahead search) is a major inference-time scaling paradigm, and it's unclear whether hyper-scaling's benefits are specific to verifier-free strategies.

**3. DMS trained with LM loss vs. distillation:** A controlled ablation isolating the loss function's contribution to data efficiency would clarify whether the DMS architecture or the distillation training is primarily responsible for the improvement over DMC.

**4. Sliding window size sweep at larger scales:** The window size ablation (Figure 5 left) is only on the 1B model. The paper defaults to window=256 for all models, but doesn't verify that this is optimal (or even sufficient) for the 32B model on 32K sequences. A 256-token window is less than 1% of a 32K sequence—does this remain sufficient for preserving long-range reasoning dependencies?

**5. Difficulty-stratified analysis:** The Snell et al. (2024) paper demonstrated that the optimal inference-time strategy depends on problem difficulty. This paper does not break down hyper-scaling results by difficulty bin (though MATH-500's ~95% accuracy for larger models is a de facto "easy" bin where gains are small). Understanding whether hyper-scaling primarily helps on hard problems (where extra reasoning is valuable) or on easy problems (where compression's quality cost is minimal) would inform deployment decisions.

**6. Statistical significance for Pareto frontiers:** The paper reports average Pareto improvements (Tables 8–9) but does not provide confidence intervals for these quantities. The AIME 24 benchmark in particular has only 30 problems, and the W-L-CR configuration space has many points—the risk of overfitting the frontier to a small test set is non-trivial. Bootstrap confidence intervals on the average frontier improvement would quantify reliability.

**7. DMS sensitivity to annealing rate and target CR schedule:** No ablation varies the 100-steps-per-CR rate or tests alternative schedules. If the method is sensitive to this hyperparameter, the reported 700-step training cost may not generalize to other model families without schedule tuning.

#### Do the latency measurements (Figure 4, throughput) reflect production systems?

The latency measurements use "a simple implementation based on the Hugging Face Transformers library and FlashAttention" (Section 5.1). While this is a reasonable academic baseline, production serving systems use sophisticated batching (continuous batching, dynamic batching), prefix caching, and optimized memory management that could change the relative importance of KV cache reads. The paper acknowledges that the implementation is "simple" but does not discuss whether the throughput gains would persist in a vLLM or TensorRT-LLM deployment. The FlashMask integration (Wang et al., 2025a) mentioned in Section 3.2 suggests a path toward production optimization, but this integration is not demonstrated in the paper itself.

#### A note on the "outperforms vanilla" results

Several iso-token comparisons show DMS slightly outperforming vanilla (e.g., DMS CR 8× on AIME 24 32B at 73.3% vs. vanilla's 70.0% in Table 12; DMS CR 4× on NIAH at 97.8 vs. vanilla's 96.4 in Table 1). While these are directionally favorable, they are not explained mechanistically. The paper does not hypothesize why sparsification might sometimes improve accuracy (possible explanations: stochastic regularization, forcing the model to rely on more robust features, or simply test-set variance given small benchmarks like AIME 24's 30 questions). Without error bars on these specific configurations, it's unclear whether these represent genuine improvements or noise.

#### Summary evaluation

The experimental analysis convincingly demonstrates the **existence and magnitude** of the hyper-scaling effect for Qwen-R1 reasoning models on four challenging benchmarks. The Pareto frontier methodology is appropriate and well-executed. The ablation on delayed eviction (Figure 5 left) is the strongest single piece of evidence—it cleanly isolates the mechanism that makes DMS work and explains why training-free methods fail. The main weaknesses are: (1) the single model family limits generalizability claims; (2) the absence of PRM-guided search integration leaves an important inference-time scaling paradigm unexplored; (3) the lack of difficulty-stratified analysis prevents understanding of *where* hyper-scaling helps; and (4) the controlled DMS vs. DMC comparison is confounded by the loss function difference. These gaps do not undermine the paper's core contributions but define the boundaries of what has been demonstrated versus what is claimed by extension.

## 6. Limitations and Trade-offs

### The Difficulty Estimation Cost Is Unmeasured and Potentially Dominant

The paper's central contribution—inference-time hyper-scaling—requires compressing the KV cache to expand the effective token budget. However, the DMS retrofitting procedure that enables this compression is not free: each new base model requires a separate training run. While the paper convincingly demonstrates that this training is dramatically cheaper than prior learned compression methods (700 steps vs. ~44K for DMC, a ~60× reduction; Section 5.3), **the absolute cost and its amortization across deployment are never analyzed**. The paper reports GPU-hour costs per CR increment in Table 3 (e.g., 75 GPU-hours for Qwen-R1 7B to advance one CR unit), but never computes the total retrofitting cost to reach the CR levels used in the main experiments (CR 4× or CR 8×), nor discusses how many inference queries would need to be served before the one-time training cost is recovered through per-query savings in KV cache reads and memory.

The consequence is that the headline efficiency gains—the Pareto frontier improvements in Tables 8–9 and the throughput multipliers in Figure 8—represent a **gross rather than net efficiency improvement**. The true net improvement would subtract the amortized retrofitting cost from the per-query savings, and this amortization depends on the deployment scale. For a laboratory setting evaluating 500 test questions with a single model, the retrofitting cost dominates: training Qwen-R1 32B from CR 1× to CR 8× requires approximately 7 × 345 = 2,415 GPU-hours (Table 3), which is orders of magnitude more compute than the inference savings on 500 questions. For a production setting serving millions of queries, the upfront cost amortizes to near zero per query, and the net savings approach the gross savings reported in the paper. The absence of this analysis means a practitioner cannot determine their break-even deployment scale from the paper's data—they would need to estimate it independently.

This is a direct analog of the difficulty estimation cost problem identified in the Snell et al. (2024) compute-optimal scaling paper: generating 2048 samples to estimate prompt difficulty consumes more compute than the test-time budget itself. Here, retrofitting the model to enable compression consumes training compute whose amortization is deployment-dependent. The paper acknowledges that DMS requires continued training (Section 3) but never frames this as a cost that must be amortized against inference savings. The authors are transparent about the absolute GPU-hour requirements (Table 3) but do not provide the analysis that would let a practitioner decide whether retrofitting is economically justified for their use case.

**Mitigation status:** Not addressed. The paper does not discuss amortization, break-even points, or the scale of deployment at which retrofitting becomes net-beneficial. This is a gap in the practical deployment picture that the paper otherwise paints in detail (throughput, latency, memory).

---

### Generalization Is Untested Beyond the Qwen-R1 Reasoning Model Family

All inference-time hyper-scaling experiments (Figures 3, 7, 8; Tables 7–9) are conducted exclusively on **Qwen 2.5 models distilled from DeepSeek R1**, a specific family of reasoning-specialized LLMs trained through reinforcement learning for chain-of-thought generation. The paper additionally evaluates DMS's *quality retention* on Llama 3.2 1B Instruct (Table 1) and Qwen3-8B (Table 2), but **never performs the full hyper-scaling W-L-CR sweep on any non-R1 model**. The central claim—that KV cache compression enables superior accuracy–efficiency trade-offs through expanded token budgets—is therefore demonstrated for only one architectural family and one training paradigm (reasoning distillation).

The consequence is that a practitioner using a different model family—Llama, Mistral, Gemma, command-series, or any non-reasoning-tuned model—cannot assume from this paper that hyper-scaling will help. Reasoning models like R1 are unusual in several respects that may interact with the hyper-scaling mechanism: (1) they generate very long chain-of-thought sequences (often 10K–30K tokens), making them natural beneficiaries of compression that enables even longer reasoning; (2) their outputs are structured (step-by-step reasoning) with clear informational redundancy that a learned eviction policy might exploit; (3) their accuracy scales monotonically with inference compute in ways that general-purpose models may not exhibit. A standard instruction-tuned model asked to answer a factual question in 100 tokens has nowhere to "spend" the extra token budget that compression enables—the gains from hyper-scaling may be zero or negative.

The paper is partially transparent about this: it states that the models are "representative of the capabilities of many contemporary LLMs" (Section 1, referenced implicitly) but does not claim representativeness of the R1 family specifically. The general-purpose evaluations (Tables 1–2) demonstrate that DMS itself works across model families, but the hyper-scaling claim—which is the paper's main contribution, not just compression quality—is untested outside R1. The Llama 3.2 1B Instruct experiments in Table 1 show that DMS preserves accuracy on short-context tasks (GSM8K, MMLU, HellaSwag) and even improves on long-context tasks (NIAH, VT), but these are iso-token comparisons, not hyper-scaling comparisons. We do not know whether Llama 3.2 1B with DMS CR 8× generating 4× more tokens would outperform vanilla Llama 3.2 1B generating standard-length responses—this is the critical missing experiment.

**Mitigation status:** Not addressed. The paper acknowledges in Appendix A that "exploring even larger models, longer contexts, and higher compression ratios remains an exciting avenue for future research," but does not frame the missing model-family generalization as a limitation. The recommended next step—replicating the full hyper-scaling sweep on at least one non-R1 model (e.g., Llama 3.1 8B Instruct or Qwen3-8B without reasoning traces)—would establish whether hyper-scaling is a general phenomenon or specific to reasoning-specialized architectures.

---

### The Paper Does Not Demonstrate Hyper-Scaling with PRM-Guided Search, Covering Only Verifier-Free Strategies

All inference-time scaling experiments in this paper use **verifier-free strategies**: majority voting across parallel chains and best-of-N weighted selection (Section 2.1). This choice is explicitly justified by citing Wang et al. (2025b), which found that "simpler PRM-free strategies such as majority voting remain the most competitive." However, process reward model (PRM) guided search—including beam search, lookahead search, and tree-of-thought variants—remains a major paradigm in the inference-time scaling literature (Snell et al., 2024; Lightman et al., 2024; Feng et al., 2023), and several state-of-the-art reasoning systems (OpenAI's o1, DeepSeek-R1's training pipeline) incorporate verifier-based selection. The paper's Section 5.4 acknowledges this gap:

> "hyper-scaling can be extended to PRM strategies, too. In particular, the verifier's complexity is quadratic in the sequence length; to complement the benefits of KV cache compression of the LLM, the PRM would need to be accelerated by prefilling-time sparse attention methods, such as MInference (Jiang et al., 2024). We leave this possible direction to future work."

The consequence is that **we cannot determine whether hyper-scaling's benefits generalize to the PRM-guided regime or are specific to verifier-free majority voting**. This matters because PRM-guided search and KV cache compression may interact in non-obvious ways. For example: (1) PRM search relies on step-level scoring, which requires the verifier to attend to the full reasoning trace—if DMS aggressively compresses the LLM's KV cache but the PRM must still process uncompressed sequences, the verifier becomes the bottleneck and compression of the base model achieves no net speedup. (2) The PRM's own KV cache may be compressible with DMS, but training a separate DMS-retrofitted PRM would multiply the retrofitting cost. (3) Search algorithms like beam search generate multiple partial sequences that diverge at different points—the optimal DMS eviction policy for a branching search tree is fundamentally different from the policy for a linear chain, and the training pipeline described in this paper (which assumes linear auto-regressive generation with a single sequence) may not produce policies that transfer well to tree-structured generation.

Additionally, the Snell et al. (2024) paper demonstrated that the optimal inference-time strategy depends on problem difficulty, and that PRM-guided beam search outperforms best-of-N on medium-difficulty problems while underperforming on easy problems (due to verifier over-optimization). This paper does not replicate that analysis in the hyper-scaling context. We do not know whether hyper-scaling with compressed KV caches changes the difficulty thresholds at which different strategies become optimal, or whether the verifier over-optimization phenomenon is exacerbated or mitigated by attention sparsification.

**Mitigation status:** Acknowledged as future work in Section 5.4, but not addressed experimentally. This is a significant gap because it leaves open the possibility that the paper's headline gains (+12.0 points on AIME 24 for Qwen-R1 32B) would not materialize—or would be substantially different—in deployments that use PRM-guided selection, which is common in production reasoning systems. A minimal experiment—applying DMS compression to the base model while using a standard (uncompressed) PRM for selection, and measuring whether the net accuracy–latency trade-off improves—would partially close this gap.

### DMS Training Does Not Guarantee Retention of Long-Range Reasoning Dependencies

The delayed eviction sliding window—the central mechanism that makes DMS work—operates at a fixed length of 256 tokens (default, used for all main experiments). The ablation in Figure 5 (left) demonstrates that this window preserves accuracy at up to 4× compression on GSM8K (a grade-school math task with typical reasoning traces of 100–500 tokens) and that even a 16-token window prevents the catastrophic collapse seen with immediate eviction. However, **no experiment measures whether the 256-token window preserves long-range dependencies in sequences of 16K–32K tokens**, which are the regime where hyper-scaling's benefits are claimed.

The mechanism of information propagation through the sliding window is as follows: when a token is flagged for eviction, it remains visible for 256 more steps before being permanently removed. During those 256 steps, the model can attend to the token via self-attention; the token's information can be copied into the hidden states of subsequent tokens, which may themselves be kept or evicted. This creates an **information relay**: critical early information must propagate forward through a chain of intermediate tokens, each of which must be kept (or have its information further relayed before eviction). For a 32K-token reasoning trace, an early premise might need to survive ~125 relay hops (32K / 256) to influence the final answer. The paper provides no evidence that this relay mechanism actually preserves reasoning-relevant information over such distances—the GSM8K and long-context evaluations (NIAH, VT) operate at shorter effective relay chains.

The consequence is that **hyper-scaling gains on tasks requiring long-range dependency tracking may be substantially smaller than reported**, or negative. The AIME 24 and MATH-500 benchmarks involve multi-step algebraic derivations where an early algebraic manipulation determines the validity of all subsequent steps. If DMS's 256-token window drops critical early steps before their consequences have been fully propagated, the model may produce fluent but logically disconnected reasoning traces that arrive at wrong answers. The paper does not analyze error modes—are DMS failures on hard problems due to the base model's capability limits or due to information loss from aggressive compression? The NIAH benchmark (Table 1, 4) partially tests long-range retention but uses a synthetic retrieval task (find the needle) rather than reasoning over dependent mathematical steps.

The per-head compression pattern in Figure 6 (right) is suggestive: early layers retain more tokens (less aggressive compression), which could help preserve critical information before it reaches later layers. However, this is an *average* over many sequences and doesn't guarantee that the specific token carrying the critical algebraic step survives the full ~125-hop relay. The fixed 256-token window size is applied uniformly regardless of sequence length—a 32K sequence gets the same window as a 4K sequence—which means the relay chain length scales linearly with total sequence length, and the probability of information loss may compound over many hops.

**Mitigation status:** Not directly addressed. The paper demonstrates DMS accuracy on long-context retrieval (NIAH scores of 96.8 at CR 4× in Table 1, even outperforming vanilla's 96.4) and state tracking (VT scores of 67.6 at CR 4× vs. vanilla's 55.8), which provides some evidence that information propagates effectively over context lengths where the relay operates. However, NIAH and VT test whether a *single* piece of information (the needle or the variable binding) survives—they do not test the survival of a *chain* of interdependent pieces of information, where losing any single link breaks the reasoning. A more diagnostic evaluation would be a synthetic task where the correct answer depends on information introduced at controlled distances from the end of the sequence, measuring accuracy as a function of that distance under DMS compression. This is not presented.

### Hyper-Scaling's Benefit Is Concentrated on Unsaturated Benchmarks and Diminishes with Model Scale—But the Scaling Trend Is Not Characterized

The paper's own results contain a pattern that is noted but not systematically analyzed: **the gains from hyper-scaling vary dramatically across benchmarks and model scales, and the direction of this variation is not straightforward**. Table 8 reveals that on MATH-500, DMS's average Pareto improvement over vanilla *decreases* with model scale: 4.2 points (1.5B) → 1.0 points (7B) → 1.6 points (32B). On GPQA Diamond, the pattern is reversed: 4.8 → 4.1 → 8.6 points—gains *increase* with scale. On AIME 24, gains are large at all scales but peak at 7B (10.6 → 15.0 → 12.0). On LiveCodeBench, gains increase monotonically: 7.3 → 7.9 → 9.7 points.

The paper attributes the MATH-500 pattern to saturation: "models achieve very high performance on MATH-500 even with limited budgets" (Section 5.1). This is a partial explanation—if vanilla already achieves 92–96%, there is little headroom for improvement—but it doesn't explain why the 1.5B model, which is *not* saturated (84.8% at 32K length, width=1), shows the largest gain. More importantly, the paper does not characterize **whether hyper-scaling's benefit follows a predictable scaling law with respect to model size and benchmark difficulty**, which would be essential for a practitioner deciding whether to invest in DMS retrofitting for a specific model–task combination.

The consequence is that a practitioner reading this paper cannot reliably extrapolate: if they have a 70B parameter reasoning model and want to deploy it on a medical diagnosis benchmark (similar difficulty to GPQA Diamond), should they expect large gains (following the GPQA trend where gains increase with scale) or diminishing returns (following the MATH-500 trend)? The paper provides no theoretical or empirical framework for making this prediction. The three model sizes tested (1.5B, 7B, 32B) are insufficient to distinguish between competing hypotheses about the scaling trend—e.g., whether gains asymptote, grow logarithmically, or follow an inverted-U pattern.

This limitation is compounded by the small test sets. AIME 24 has only 30 problems, meaning a single additional correct answer changes accuracy by 3.3 percentage points. The 12.0-point average Pareto improvement for the 32B model on AIME 24 could reflect as few as ~4 additional correct answers when comparing DMS configurations to vanilla configurations at equivalent budgets. With 30 total problems and extensive hyperparameter search over W, L, and CR, the risk that some of the reported improvement is due to configuration overfitting rather than genuine capability improvement is non-trivial. The paper reports error bars for Llama 3.2 1B (Table 6) but not for the R1 models on AIME 24.

**Mitigation status:** Partially acknowledged through the discussion of saturation effects (Section 5.1). The paper does not claim to have established scaling laws or to predict hyper-scaling benefits for unseen model sizes or tasks. However, the absence of any systematic scaling analysis beyond "gains vary by benchmark and scale" leaves the practitioner with point estimates that do not support generalization. A minimal extension—fitting a simple parametric model relating benchmark difficulty (as measured by vanilla accuracy), model scale, and hyper-scaling gain—would substantially improve the paper's practical utility.

---

### The DMS Training Recipe Has an Unablated Sensitivity to the Sliding Window Size Hyperparameter

The sliding window size `$w$` is the critical hyperparameter that distinguishes DMS from training-free eviction and makes sparsification viable at high compression ratios. The paper uses a default of `$w = 256$` for all main experiments (Section 4) and presents a single ablation varying window size on the 1B model for GSM8K (Figure 5, left). This ablation shows that larger windows monotonically improve accuracy, with the jump from `$w = 0$` (immediate eviction, catastrophic failure) to `$w = 16$` (near-vanilla accuracy at CR 4×) being the largest effect, and diminishing returns beyond `$w = 64$`.

However, **no ablation of window size is performed on the models used for the main hyper-scaling experiments** (Qwen-R1 1.5B, 7B, 32B), on the longer sequences (16K–32K tokens) that characterize the hyper-scaling regime, or on the reasoning benchmarks (AIME 24, GPQA Diamond, LiveCodeBench) where hyper-scaling gains are measured. The 1B model on GSM8K (typical reasoning traces of 100–500 tokens) is a substantially different regime from the 32B model on AIME 24 (traces of 8K–32K tokens). The optimal window size may depend on model scale (larger models may integrate information faster or slower), on sequence length (longer sequences require longer relay chains, potentially needing larger windows to prevent information loss at each hop), and on task type (mathematical derivations may require longer integration windows than factual retrieval).

The consequence is that the reported hyper-scaling gains may be **sensitive to the specific window size chosen**. If `$w = 256$` is suboptimal for the 32B model on 32K sequences—either too small (causing information loss in long relay chains) or too large (wasting compression budget on tokens that could be evicted sooner)—then the Pareto frontiers in Figure 3 represent a lower bound on achievable performance, and a different window size could push the frontier further. Conversely, if `$w = 256$` happens to be near-optimal for these specific models and benchmarks, the method's practical adoption would require practitioners to perform their own window size tuning when deploying on different model–task combinations, which adds cost and complexity not reflected in the paper's "inexpensive" framing.

The paper does not discuss how to choose `$w$` or whether the choice is robust. The fixed window size also means that the compression ratio target `$\alpha^\star$` interacts with window size: for a given CR, a larger window leaves fewer tokens outside the window that can actually be evicted, limiting the achievable compression early in the sequence. This interaction is visible in Figure 6 (left): the measured CR is below target for the first ~2K tokens because many tokens are still within the 256-token window and cannot yet be evicted. For sequences shorter than `$w$`, the effective compression ratio is 1× regardless of the target. This means hyper-scaling's benefits are diminished or absent for short-generation tasks—a regime where the paper does not claim benefits but which many practical applications occupy.

**Mitigation status:** The GSM8K ablation (Figure 5, left) demonstrates that DMS works across window sizes `$w \in \{0, 16, 64, 256\}$` for a specific (small) model and task, establishing that the mechanism is not brittle to this choice. However, the absence of scaling this ablation to the regime of interest (32B model, 32K sequences, AIME 24) means the window size was selected without empirical guidance for the main experiments. A single additional data point—evaluating the 7B model at CR 4× on AIME 24 with `$w \in \{128, 256, 512\}$`—would substantially strengthen confidence that the default is reasonable. Alternatively, making window size adaptive (learned per-head, similar to how eviction decisions are learned) would eliminate the hyperparameter entirely, which the paper does not explore.

## 7. Implications and Future Directions

### How This Work Changes the Landscape

This paper introduces a **conceptual reframing** of the inference-time scaling problem that is likely to be more consequential than the specific compression method it proposes. Prior work—from Snell et al. (2024) on compute-optimal scaling to Brown et al. (2024) on repeated sampling to Muennighoff et al. (2025) on simple test-time scaling—implicitly equated "inference compute budget" with "number of generated tokens." Each additional reasoning step was assumed to cost a roughly constant increment of compute, so scaling analysis focused on how to allocate a fixed token budget between sequential and parallel dimensions.

This paper demonstrates that this equivalence is **fundamentally incorrect** for Transformer LLMs under realistic hardware constraints. The dominant cost during autoregressive generation is not the FLOPs to produce new tokens but the memory bandwidth to retrieve the growing KV cache from high-bandwidth memory at every generation step. When the cache is compressed, the model can generate substantially more tokens—longer chains, more parallel chains, or both—within the same memory-read budget. Generated tokens and effective compute are decoupled.

The magnitude of this shift should not be overstated: it is a **reframing of the optimization objective**, not a discovery of a new scaling law. The underlying mechanisms—KV cache compression, inference-time scaling via majority voting—were individually known. What is new is the synthesis: the recognition that compression and scaling are not separate problems but complementary levers that interact through the KV cache bottleneck. The paper's key empirical finding is that this interaction is **net-positive**: the accuracy gain from generating more tokens at a given compression ratio typically exceeds the accuracy loss from compressing the KV cache to achieve that ratio. This converts KV cache compression from a pure efficiency technique (do the same work with less memory) into a **capability amplifier** (do better work within the same hardware constraints).

The paper also resolves a latent tension in the efficient attention literature. Training-free eviction methods (TOVA, H2O) offered simplicity but collapsed at high compression ratios; learned methods (DMC) preserved accuracy but required expensive retraining. The field operated under the implicit assumption that these were points on a continuous Pareto frontier—that you couldn't have both cheap retraining and high-quality compression. DMS breaks this tradeoff by identifying that **the timing of eviction, not the mechanism of eviction, is the critical variable**. Delayed eviction via a sliding window—a technique that costs nothing in parameters and minimal complexity in implementation—enables simple binary sparsification to achieve accuracy comparable to DMC's explicit token merging while requiring ~60× fewer training steps. This finding redirects research attention from developing more sophisticated compression operations (merging, interpolation, learned deletion functions) toward understanding **when** information can be safely discarded—a scheduling problem rather than a selection or transformation problem.

The practical consequence is that KV cache compression moves from the periphery of the inference-time scaling conversation to its center. Prior papers on test-time compute scaling (Snell et al., 2024; Brown et al., 2024) did not consider compression as a relevant variable; they assumed a fixed, uncompressed model and optimized hyperparameters within that constraint. After this work, any serious analysis of inference-time compute allocation must account for the possibility that compressing the KV cache and reallocating the saved memory bandwidth to additional reasoning may outperform any configuration that leaves the cache uncompressed. This doesn't mean compression always helps—the paper shows it doesn't help on saturated benchmarks like MATH-500 where accuracy is already near ceiling—but it means compression is now a **first-class optimization variable** alongside width, length, and selection strategy.

A secondary but important shift is methodological. The paper introduces **KV cache memory reads** as the correct efficiency metric for comparing inference-time scaling configurations, rather than raw token counts or FLOPs estimates. This metric directly captures the hardware bottleneck that dominates real-world latency, and it enables fair comparison between compressed and uncompressed models that would be invisible under token-count-based accounting. The paper's analytical derivation in Appendix I—showing that KV cache reads contribute >80% of per-step latency at long contexts and large batch sizes—provides a quantitative justification for this choice. Future work in the inference-time scaling literature should adopt this metric (or a close proxy like HBM transfer volume) if it aims to make claims about real-world efficiency.

The paper does **not** resolve the question of how hyper-scaling interacts with verifier-guided search strategies (PRM beam search, lookahead search, tree-of-thought). Section 5.4 explicitly defers this to future work. This is a significant open frontier: PRM-guided search is the dominant paradigm in state-of-the-art reasoning systems, and the paper's results on verifier-free majority voting may not transfer directly. The PRM itself has a KV cache bottleneck (quadratic in sequence length for the verifier's attention over the reasoning trace), and compressing only the LLM's cache while leaving the PRM's cache uncompressed creates a new bottleneck that could negate hyper-scaling's benefits. This is not a weakness of the paper—it is a clearly-scoped boundary—but it means the landscape shift is currently confined to the verifier-free scaling regime.

### Follow-Up Research This Work Enables

**Hyper-scaling with process reward model (PRM) guided search.** The paper's Section 5.4 explicitly identifies this direction: PRM-guided tree search and beam search are major inference-time scaling paradigms, but the PRM's own attention over reasoning traces is quadratic in sequence length, creating a second KV cache bottleneck. A natural experiment would apply DMS compression to both the LLM and the PRM, then evaluate compute-optimal hyper-scaling (in the Snell et al., 2024 framework) with compressed models, measuring whether the difficulty-dependent strategy selection (best-of-N for easy problems, beam search for medium problems) changes when the KV cache budget is expanded through compression. The experiment would replicate the compute-optimal scaling analysis on MATH-500 and AIME 24 using DMS-compressed Qwen-R1 models with a separately retrofitted PRM, comparing Pareto frontiers against uncompressed PRM-guided search on identical KV-cache-read budgets. The key question is whether PRM over-optimization (documented in Snell et al., 2024: beam search degrades on easy problems because the verifier is exploited) is exacerbated or mitigated when the verifier's own KV cache is compressed.

**Difficulty-stratified analysis of hyper-scaling benefits.** The paper reports aggregate Pareto improvements across all test questions but does not break down gains by problem difficulty—a central variable in Snell et al. (2024)'s analysis. A follow-up would stratify AIME 24 and MATH-500 questions into difficulty quintiles (following Snell et al.'s protocol: sample 2048 solutions from the base model, compute pass@1, bin by quintile), then evaluate whether DMS hyper-scaling gains are concentrated on hard problems (where additional reasoning tokens are most valuable), easy problems (where compression's accuracy cost is minimal), or medium problems (where both effects are active). The experiment would test a specific hypothesis: hyper-scaling should help most on medium-difficulty problems, because easy problems are already solved by vanilla models and hard problems are outside the base model's capability regardless of token budget. This would establish whether hyper-scaling is a capability amplifier (improving medium problems) or merely an efficiency technique (preserving accuracy on easy problems while reducing cost). The paper's MATH-500 results—where larger models show minimal gains due to saturation—hint at the former, but a direct difficulty-stratified comparison is absent.

**Generalization of hyper-scaling to non-reasoning model families.** The paper demonstrates hyper-scaling exclusively on Qwen-R1 distilled reasoning models. A critical stress-test is whether the phenomenon generalizes to standard instruction-tuned models (Llama 3.1 Instruct, Qwen3, Mistral) that were not specifically trained for chain-of-thought reasoning. The experiment would retrofit a Llama 3.1 8B Instruct model with DMS, then run the full W-L-CR hyper-scaling sweep on reasoning benchmarks (GSM8K as a minimum, AIME 24 if the base accuracy is non-zero), comparing against vanilla Llama 3.1 8B on identical KV-cache-read budgets. The null hypothesis is that hyper-scaling provides zero or negative benefit for non-reasoning models because their outputs are shorter and less structured, leaving no room for the extra token budget to improve accuracy. A negative result here would sharply bound the paper's claims: hyper-scaling is a technique for reasoning models, not general-purpose LLMs. A positive result would substantially expand the claimed impact.

**Adaptive, per-example sliding window sizing.** The paper uses a fixed sliding window of `w = 256` tokens for all models and tasks, with a single ablation on the 1B model (Figure 5, left) showing that larger windows monotonically improve accuracy. A follow-up would make the window size itself a learned function of the input, analogous to how DMS learns per-head eviction decisions: each attention head could output a window size `w_h` (discretized to a small set of options for efficient implementation) based on the hidden state, trained with an auxiliary loss that penalizes total KV cache size. The experiment would compare adaptive-window DMS against fixed-window DMS on AIME 24 with the 7B model, measuring whether adaptivity enables higher effective compression ratios (because short windows are used when safe, reserving budget for long windows when needed) or better accuracy at the same ratio. This would test whether the fixed window size is a convenient simplification or a fundamental limitation—if adaptivity provides no benefit, it suggests that 256 tokens is simply the time needed for information integration regardless of context, which would be an interesting empirical regularity.

**Combined compression via sparsification + quantization.** The paper notes that quantization (KIVI, KVQuant) and decomposition (LoRC, Eigen Attention) are orthogonal to DMS's sparsification approach (Appendix B). A synthesis experiment would apply 4-bit KV cache quantization on top of DMS CR 4× sparsification, targeting effective CR 16× (4× from sparsification × 4× from quantization). The key question is whether these techniques are additive or subadditive in their compression effects—does sparsification remove the high-precision tokens that quantization most needs, or does quantization introduce noise that makes the sparsified model's eviction decisions less reliable? The experiment would measure accuracy on GSM8K, MMLU, and NIAH for the Llama 3.2 1B Instruct model at various combinations of DMS CR and quantization bit-width, fitting a response surface that predicts accuracy as a function of total effective CR. This would establish the practical ceiling for KV cache compression and determine whether the 8× limit in the current paper is fundamental or merely a consequence of using sparsification alone.

**Hyper-scaling with retrieval-augmented generation (RAG).** The paper evaluates hyper-scaling in a closed-context setting where the entire input fits in the KV cache. In RAG deployments, the KV cache must hold both the retrieved documents and the generated reasoning chain, making the memory bottleneck even more acute. A follow-up experiment would evaluate DMS-compressed models on a RAG-based reasoning task (e.g., multi-hop QA over retrieved passages, or tool-use reasoning where API call outputs populate the context) and measure whether hyper-scaling enables including more retrieved documents or longer reasoning chains within a fixed KV cache budget. The specific prediction is that DMS should provide larger relative gains in RAG settings than in closed-book settings because the retrieved context contains substantial redundancy (multiple documents covering similar information) that the learned eviction policy can exploit.

### Practical Applications and Downstream Use Cases

**Cost-efficient batch inference for reasoning workloads.** Organizations running large-scale evaluation of reasoning models—for example, generating training data for self-improvement pipelines, evaluating candidate models on math or coding benchmarks, or processing user-submitted problems in educational platforms—can deploy DMS-retrofitted models to serve substantially more queries per GPU-hour at equivalent accuracy. Figure 8 demonstrates that DMS CR 8× on Qwen3-8B achieves the same LiveCodeBench accuracy as vanilla with up to 5× higher throughput, measured at the maximum batch size that fits in memory. For a batch inference pipeline processing millions of coding problems, this directly translates to ~5× reduction in GPU-hours and associated cloud costs, or equivalently ~5× faster turnaround at the same cost. The retrofitting cost (270 GPU-hours per CR increment for Qwen3-8B; Table 3) amortizes to negligible per-query cost at this scale. The key caveat is that the throughput multiplier depends on the task: on saturated benchmarks where hyper-scaling provides minimal accuracy gain, the compressed model can still serve at higher throughput for the same accuracy, but the accuracy ceiling is unchanged.

**On-device or edge deployment of reasoning-capable models.** DMS CR 8× reduces peak KV cache memory by roughly 8× (since the cache is the dominant memory consumer at long context lengths). For edge devices with limited VRAM—consumer GPUs, mobile processors with unified memory, or embedded systems—this reduction can make the difference between a model fitting in memory or not. A Qwen-R1 7B model generating 32K token reasoning traces with an uncompressed KV cache requires approximately 7B × 2 bytes (weights, FP16) + 32K × 32 layers × 1024 KV dim × 2 heads (simplified GQA) bytes ≈ 14 GB + 2 GB ≈ 16 GB minimum, which exceeds many consumer GPUs. With DMS CR 8×, the KV cache component shrinks to ~0.25 GB, bringing the total within a 12 GB envelope. The paper quantifies this in Figure 4: vanilla Qwen-R1 32B at batch size 32 runs out of memory beyond ~8K context, while DMS CR 8× continues operating. The accuracy cost for CR 8× in iso-token comparisons is modest (Tables 10, 12: Qwen-R1 7B drops from 53.3% to 50.0% on AIME 24 at 32K length for CR 8×; Qwen-R1 32B drops from 57.0% to 51.7% on LiveCodeBench), and the hyper-scaling results show that this loss can be partially or fully recovered by generating longer sequences within the same memory budget.

**Latency-sensitive interactive reasoning applications.** For applications where users expect real-time responses (interactive tutoring, coding assistants, conversational agents that reason step-by-step), the per-token latency is dominated by KV cache reads at long context lengths. Figure 4 shows that for Qwen-R1 7B at batch size 32, vanilla latency begins rising sharply beyond ~8K context, while DMS CR 8× maintains near-constant latency out to ~16K. For a coding assistant that generates long traces (thousands of tokens of reasoning + code), DMS compression directly reduces the wall-clock time users wait for responses, or enables the assistant to reason more thoroughly within acceptable latency bounds. The paper's analytical model in Appendix I quantifies this: at 16K context with batch size 32, KV cache reads account for ~70% of per-step latency for Llama 3.1 8B at CR 1×, dropping to ~30% at CR 8×. This is a substantial improvement in user-perceived responsiveness that doesn't require model distillation or hardware upgrades.

**Long-context processing without specialized architectures.** The paper's evaluation on NIAH and Variable Tracking (Table 1) demonstrates that DMS not only preserves but sometimes improves long-context accuracy over vanilla models: at CR 4× on NIAH, DMS scores 96.8 vs. vanilla's 96.4; on VT, DMS scores 67.6 vs. vanilla's 55.8. This suggests that DMS can serve as a general-purpose replacement for standard dense attention in long-context applications, not just a technique for inference-time scaling. For applications that process long documents (legal contract analysis, scientific literature review, long-form summarization), a DMS-retrofitted model could process documents that are 4–8× longer than the vanilla model can handle at the same memory budget, without the catastrophic degradation exhibited by training-free methods (H2O drops to 13.4 on NIAH at CR 4×; DMC collapses to 0.0). This is a deployment-ready application of the current results, requiring no methodological innovation beyond what the paper already demonstrates.
