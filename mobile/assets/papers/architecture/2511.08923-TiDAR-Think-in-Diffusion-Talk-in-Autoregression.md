# TiDAR: Think in Diffusion, Talk in Autoregression

**ArXiv:** [2511.08923](https://arxiv.org/abs/2511.08923)

## 🎯 Pitch

Autoregressive decoding wastes massive GPU compute because generating one token at a time is memory-bound; TiDAR breaks this bottleneck by drafting blocks of tokens in parallel via diffusion and autoregressively verifying them inside a single forward pass. Remarkably, this hybrid design closes the quality gap with standard AR models while delivering up to 5.9× more tokens per second—a result previous diffusion LLMs and speculative decoding methods have failed to achieve.

---

## 1. Executive Summary

This paper introduces **TiDAR**, a sequence-level hybrid architecture that combines parallel token drafting via diffusion ("thinking") with autoregressive rejection sampling ("talking") in a single forward pass using specially designed structured attention masks — for example, the model pre-drafts a block of candidate tokens from marginal distributions (diffusion mode) while simultaneously verifying previously drafted tokens against the chain-factorized joint distribution (AR mode). Evaluated across coding, math, and reasoning benchmarks at 1.5B and 8B scales using Qwen2.5 and Qwen3 backbones, TiDAR achieves 4.71× to 5.91× relative throughput speedup over standard autoregressive decoding while maintaining competitive generation quality, establishing that diffusion-AR hybridization can recover AR-level fidelity only when the drafting and verification processes execute in parallel within a single model forward rather than sequentially across separate drafter and base models as in speculative decoding.

## 2. Context and Motivation

### The Core Problem: GPUs Are Wasted During Autoregressive Decoding

Large Language Models (LLMs) overwhelmingly use autoregressive (AR) decoding, where tokens are generated one at a time, with each new token conditioned on all previous tokens. While this causal structure aligns naturally with language modeling and produces high-quality text, it creates a fundamental hardware utilization problem at inference time. The paper articulates this clearly in Section 1: AR decoding is **memory-bound** during generation, meaning the dominant latency comes not from the actual computation (matrix multiplications in attention and MLP layers) but from loading model weights and the ever-growing Key-Value (KV) cache from GPU memory.

This is a well-documented phenomenon in LLM serving systems. When you generate tokens one by one with a batch size of 1 (the most latency-sensitive setting, as in interactive chat), each forward pass uses only a tiny fraction of the GPU's computational capacity. The GPU spends most of its time waiting for data to arrive from memory rather than actually computing. This is the insight behind "speculative decoding" techniques that try to generate multiple tokens per forward pass: if you can pack more tokens into a single model invocation, those additional tokens effectively share the weight-loading cost of the single forward, increasing **compute density** — the amount of useful computation per unit of memory bandwidth consumed.

The paper formalizes this with the concept of **"free token slots"** in Figure 1. The idea is that as long as the total number of tokens in a forward pass remains within the memory-bound regime (before transitioning to the compute-bound regime), adding extra tokens incurs minimal to zero additional latency. Their profiling of Qwen3-32B on an NVIDIA H100 shows that at prefix lengths of 1024, 2048, and 4096, the latency curve is essentially flat for a range of additional tokens — the extra computation fits into what would otherwise be idle compute cycles. This is the hardware-level opportunity that TiDAR exploits: if you can generate multiple tokens in a single forward while staying in this flat region, you effectively get those tokens "for free" in terms of wall-clock time.

This problem matters enormously for real-world deployment. As LLMs are integrated into latency-sensitive applications — chatbots, code assistants, real-time translation — the per-token latency directly determines user experience. The prevailing approaches either accept this inefficiency (standard AR), try to work around it with separate draft models (speculative decoding), or embrace parallel generation at the cost of quality (diffusion language models). None fully exploit the hardware's capability to do useful work during otherwise-idle cycles.

### The Diffusion Dilemma: Speed vs. Quality

Diffusion language models (dLMs) offer an intuitive solution to the memory-bound problem: instead of generating one token at a time, corrupt the sequence with mask tokens and denoise multiple tokens in parallel at each step. In principle, this should dramatically increase throughput by making each forward pass produce many tokens simultaneously, moving the workload from memory-bound to compute-bound.

However, a well-known and deeply frustrating tension exists that the paper names directly in Section 1: **the best quality from masked diffusion models is often achieved when decoding strictly one token per denoising step**, which defeats the purpose of parallel generation. The paper identifies the mathematical source of this tension. In autoregressive models, the joint distribution over a sequence factorizes as:

$$p_{\text{AR}}(\cdot; \theta) = \prod_i p^i_{\theta}(x_i | x_{<i}; \theta)$$

Each token is conditioned on all previously generated tokens, preserving full sequential dependencies. Diffusion models, however, sample from:

$$p_{\text{Diff}}(\cdot; \theta) = \mathbb{E}_{\tilde{\mathbf{x}} \sim q(\cdot|\mathbf{x})} \prod_i p^i_{\theta}(x_i | \tilde{\mathbf{x}})$$

When decoding multiple tokens $\{x_j\}_{j \in K}$ in one step, this further factorizes as a product of marginals:

$$p_{\text{Diff\_Independent\_K}}(\cdot; \theta) = \mathbb{E}_{\substack{\tilde{\mathbf{x}} \sim q(\cdot|\mathbf{x}) \\ \text{s.t. } \tilde{\mathbf{x}}_{i \in K}=[m]}} \prod_{i \in K} p^i_{\theta}(x_i^t | \tilde{\mathbf{x}})$$

This **intra-step token independence assumption** is the culprit. When you generate multiple tokens simultaneously, each is predicted independently from the same noisy context, without conditioning on the other tokens being generated in the same step. For natural language, where token choices are highly interdependent (a noun's number constrains the verb form; a function name constrains its arguments), this independence assumption degrades sequence-level coherence and correctness.

The paper quantifies this degradation by citing APD (Adaptive Parallel Decoding): on GSM8K, Dream-7B's accuracy drops by **10 percentage points** when increasing from 1 to 2 tokens per step with the entropy-based sampling strategy. This is catastrophic degradation — parallel generation isn't just slightly worse; it fundamentally breaks the model's reasoning ability.

Prior open-source diffusion LLMs like Llada (Nie et al., 2025) and Dream (Ye et al., 2025) have therefore failed to match the combined speed-quality profile of strong AR models. They represent two points on an unsatisfactory trade-off curve: either decode one token per step (losing the parallelism advantage) or decode multiple tokens per step (losing reasoning quality). Neither is acceptable for production deployment.

### Prior Approaches and Their Specific Shortcomings

The paper positions its contribution against three main categories of prior work, each with identifiable limitations:

#### 1. Traditional Speculative Decoding

Classic speculative decoding (Leviathan et al., 2023; Chen et al., 2023) uses a faster but weaker **draft model** (often a smaller version of the base model) to generate candidate token sequences, which are then verified in parallel by the base model using a modified rejection sampling scheme that mathematically guarantees identical output distribution. The insight is that verifying $K$ tokens in parallel takes roughly the same time as generating one token autoregressively, so if the draft model's acceptance rate is high enough, you get $K$ tokens for the price of one verification forward pass plus the draft model's cost.

The fundamental limitation, as summarized in Table 1, is the **drafting capacity gap**. The draft model is inherently weaker than the base model, so many of its proposals get rejected, limiting the effective speedup. To address this, later methods share some of the base model's computation with the drafter:

- **Medusa** (Cai et al., 2024) adds multiple linear prediction heads on top of the base model's intermediate hidden states, predicting multiple future tokens in parallel with tree-structured verification.
- **EAGLE series** (Li et al., 2024, 2024; 2025) and **DeepSeek-V3 MTP** (Liu et al., 2024) use additional autoregressive layers on the base model's hidden states to predict future tokens.

However, even these improved methods have two critical weaknesses. First, the drafting process is **still autoregressive** — the draft tokens are generated one at a time, sequentially, even if they share the base model's hidden representation. This means the drafting process itself does not exploit the "free token slots" for parallelism; it still suffers from the memory-bound problem, just in a smaller model. Second, drafting is **sequential to verification** — you must first run the draft model to completion, then run the base model for verification. This sequential dependency means you cannot overlap drafting and verification computation, leaving GPU cycles idle during the drafting phase.

Apple's MTP (Samragh et al., 2025) partially addresses the parallelism issue by pre-drafting tokens for the next step conditioned on all possible verification outcomes, but it still uses autoregressive drafting (Table 1, bottom row). TiDAR replaces this autoregressive draft with parallel diffusion.

#### 2. Diffusion Language Models and Their Caching Problem

Beyond the quality-parallelism tension, diffusion LLMs face a second practical challenge: **lack of efficient KV caching**. In standard AR models, once you compute the key-value pairs for past tokens during prefilling (prompt processing), you store them and only compute attention for the new token against this cached context. This is what makes long-context generation tractable. But diffusion models typically use bidirectional attention, which breaks this caching property — if you denoise tokens within a block, those tokens attend to each other bidirectionally, and the attention pattern changes at each denoising step, making incremental caching impossible or lossy.

Recent work has attempted partial solutions:

- **Fast-dLLM** (Wu et al., 2025) proposes block-parallel decoding where the prefix and optionally the suffix are cached, but this is a heuristic approximation, not exact caching.
- **d-KV cache** (Ma et al., 2025) selectively caches certain tokens in a delayed fashion to minimize quality degradation, but again this is lossy relative to true AR caching.
- **Block Diffusion** (Arriola et al., 2025) introduces an inter-block causal and intra-block bidirectional attention pattern, which enables **exact KV caching** for the prefix blocks. This is a genuine advance — tokens in prefix blocks only attend causally to previous tokens, so their KV entries can be cached permanently. However, Block Diffusion was designed to improve the diffusion component's quality and caching, not to support dual-mode AR-diffusion operation. The paper's key insight is that Block Diffusion's architecture can be **repurposed** to enable the hybrid thinking-talking paradigm.

#### 3. The Training Data Inefficiency of Pure Diffusion

A subtle but important limitation of prior diffusion models is their training signal density. When using standard masked diffusion training, only a subset of tokens are randomly masked at each training step, and the loss is computed only on those masked positions. This means: (a) the training signal is sparse — many tokens contribute nothing to the gradient on a given sample, (b) the number of loss terms varies across samples depending on the stochastic masking pattern, making it difficult to balance with any auxiliary losses (e.g., next-token prediction), and (c) there's a train-test discrepancy — during inference, the model may encounter different patterns of masked and unmasked tokens than it saw during training, particularly if doing one-step generation.

Block Diffusion and Set Block Decoding (SBD) (Gat et al., 2025) double the sequence length by appending corrupted tokens to the input, enabling both bidirectional diffusion on the appended tokens and causal attention on the prefix. However, they still apply random masking to the corrupted tokens, inheriting the sparse-signal and train-test mismatch issues.

### How TiDAR Positions Itself

TiDAR's positioning is best understood as addressing the tension between three competing objectives — quality, parallelism, and caching — that no prior architecture simultaneously satisfies:

- **AR models** have quality and caching but no parallelism (memory-bound, one token per forward).
- **Diffusion models** have parallelism but degraded quality (due to independence assumption) and poor caching (bidirectional attention).
- **Block Diffusion** has parallelism and caching but no AR-quality verification (it's diffusion-only, no dual-mode sampling).
- **Speculative decoding with EAGLE/MTP** has quality (via rejection sampling) and caching but limited parallelism (auto-regressive draft, sequential to verification).

TiDAR claims to achieve all three by introducing a **sequence-level hybrid attention mask** that partitions each forward pass into three regions with different attention patterns:

1. **Prefix tokens**: causal attention (like AR) → exact KV caching, supports likelihood evaluation, enables autoregressive loss computation.
2. **Tokens proposed in the previous step**: causal attention → enables autoregressive rejection sampling against the chain-factorized joint distribution for quality guarantee.
3. **Tokens pre-drafted for the next step**: bidirectional attention within block, causal over prefix → enables parallel one-step diffusion drafting that exploits "free token slots" for efficiency.

The crucial innovation is that **the diffusion and autoregressive operations happen simultaneously in a single forward pass**, not sequentially. The model computes the AR distribution over previously proposed tokens (for verification) AND the marginal distributions over future mask tokens (for pre-drafting) in the same attention computation. This eliminates the sequential drafting-verification bottleneck of speculative decoding — there is no separate draft model, no sequential dependency, no idle GPU cycles.

This fusion is only possible because of the paper's training strategy: by **fully masking** all tokens in the diffusion section (rather than using random masking), the model learns to predict every diffusion token simultaneously in one forward pass during training, which directly transfers to one-step diffusion drafting during inference. The training objective becomes a clean weighted sum of:

$$\mathcal{L}_{\text{TiDAR}}(\theta) = \frac{1}{1 + \alpha} \left( \sum_{i=1}^{S-1} \frac{\alpha}{S-1} \cdot \mathcal{L}_{\text{AR}}(x_i, x_{i+1}; \theta) + \sum_{i=1}^{S-1} \frac{1}{S-1} \cdot \mathcal{L}_{\text{Diff}}([\text{mask}], x_i; \theta) \right)$$

where $\alpha$ balances the two objectives and both loss terms are computed over the same number of tokens ($S-1$), eliminating the normalization difficulties that plague random-masking approaches.

The paper explicitly positions TiDAR as achieving what no prior work has: closing the quality gap with AR models while delivering multi-fold throughput improvements, and doing so **without requiring any hyperparameter tuning during inference** — a sharp contrast with diffusion models that require careful entropy thresholds, confidence calibration, or number-of-steps selection.

## 3. Technical Approach

### 3.1 Reader Orientation

**What is being built (plain English):** TiDAR is a single neural network that, at each generation step, simultaneously verifies previously drafted tokens using high-quality autoregressive logic AND drafts new candidate tokens using fast parallel diffusion logic — all in one forward pass — making text generation both accurate (autoregressive quality) and fast (diffusion parallelism). **What problem it solves and the "shape" of the solution:** The core problem is that autoregressive models generate high-quality text but waste GPU compute by producing only one token per forward pass (memory-bound), while diffusion models use GPU compute efficiently by generating multiple tokens in parallel but sacrifice quality due to an intra-step token independence assumption; TiDAR solves this by running both modes in a single forward pass with a structured attention mask that partitions the sequence into three regions — prefix (causal, for caching and AR loss), verification (causal, for rejection sampling against the chain-factorized joint distribution), and pre-drafting (bidirectional within block, for parallel one-step diffusion) — so that the expensive model weight loading is amortized across both operations simultaneously.

### 3.2 Big-Picture Architecture (Diagram in Words)

TiDAR's generation loop has four major components operating within a single model and a single forward pass per step:

1. **The Shared Transformer Backbone (TiDAR Model):** A standard decoder-only transformer initialized from a pretrained AR model (e.g., Qwen2.5 or Qwen3), but trained with a hybrid attention mask that enables two distinct attention patterns within a single forward pass. It produces both AR logits (for verification) and diffusion logits (for drafting) from the same hidden states.

2. **The Structured Attention Mask (Training & Inference):** Not a separate component but the architectural mechanism that partitions the input sequence into three regions with different attention rules: (a) prefix tokens attend causally to all previous tokens, (b) tokens from the previous step's draft attend causally to the prefix and to earlier proposed tokens, and (c) mask tokens for next-step pre-drafting attend bidirectionally within their block and causally to the prefix. This mask is pre-computed once and sliced per step.

3. **The Draft-and-Verify Generation Loop (Inference Only):** At each step, the model receives: the clean prefix (all accepted tokens so far), the tokens drafted in the previous step (to be verified now), and a block of mask tokens (to be pre-drafted for the next step). The AR logits at the drafted positions are used for rejection sampling (verification); the diffusion logits at mask positions are used to propose candidate tokens for the next step. The system selects which proposal to use based on how many drafted tokens are accepted.

4. **The Training Objective (Dual-Mode Learning):** A weighted sum of next-token prediction (NTP) loss on the causal prefix and cross-entropy loss on fully-masked diffusion tokens. Both losses are computed over the same number of tokens (sequence length minus one), enabling simple balancing via a single scalar $\alpha$.

**Information flow per generation step:** The prompt is encoded causally and cached → In the first decoding step, the model pre-drafts a block of tokens from mask positions → At each subsequent step, the model receives (prefix, N proposed tokens from last step, K mask tokens) in one forward pass → AR logits at the N proposed positions are used for rejection sampling against the drafted tokens; accepted tokens are appended to the prefix and their KV cache is kept; rejected tokens' KV cache is evicted → Diffusion logits at the K mask positions produce K new draft tokens → One proposal (corresponding to the number of accepted tokens) is selected as the draft for the next step → Repeat.

### 3.3 Roadmap for the Deep Dive

- **First**, the training attention mask and the dual-mode objective (§3.4.1), because the model's ability to compute both AR and diffusion distributions in one forward pass is the foundation that makes everything else possible — we need to understand HOW the model learns these two modes before seeing how they're used.
- **Second**, the one-step full-mask diffusion strategy and loss balancing (§3.4.2), which explains the critical training design choice (fully masking all diffusion tokens rather than random masking) and why it matters for inference consistency, signal density, and loss normalization.
- **Third**, the parallel self-speculative generation loop (§3.4.3), which ties the dual-mode capability into the actual decoding algorithm — how verification and pre-drafting are interleaved, how proposals are selected, and how KV cache management works without waste.
- **Fourth**, the inference attention mask and KV cache mechanics (§3.4.4), which explains the engineering details of how the structured mask is implemented efficiently (pre-computation, slicing, reordering) and why TiDAR supports exact caching while pure diffusion models don't.
- **Fifth**, the AR vs. diffusion output mixing for verification (§3.4.5), which addresses a subtle ambiguity: since AR and diffusion predict the same token position in certain cases, how does the system decide which distribution to trust during rejection sampling?

### 3.4 Detailed, Sentence-Based Technical Breakdown

This is primarily a **systems-architecture paper** whose core idea is that a single transformer model, trained with a sequence-level hybrid causal-bidirectional attention mask, can simultaneously perform autoregressive verification (for quality) and parallel one-step diffusion drafting (for speed) in one forward pass, exploiting the "free token slots" in the GPU's memory-bound regime without requiring a separate draft model or sequential dependency between drafting and verification.

#### 3.4.1 Training the Dual-Mode Backbone: The Hybrid Attention Mask

The fundamental training challenge is teaching a single transformer to compute two different conditional distributions over tokens within the same forward pass: the **chain-factorized joint distribution** (AR mode, where each token depends on all previous tokens in a left-to-right chain) and the **marginal distribution** (diffusion mode, where each token is predicted independently given a noisy context containing mask tokens). The solution is a **sequence-level causal-bidirectional attention hybridization** — the attention mask varies depending on which position in the (doubled) sequence you're attending from and to.

**Why sequence doubling is necessary:** The model processes the input twice in one forward pass: once as clean tokens (for AR computation) and once as corrupted tokens (for diffusion computation). Concretely, given an input sequence $\{x_i\}_{i=1}^S$ of length $S$, the model receives a concatenated sequence of length $2S$: the first $S$ positions contain the clean input tokens (for the AR section), and positions $S+1$ to $2S$ contain the corrupted tokens (for the diffusion section). This doubling technique is inherited from Block Diffusion and Set Block Decoding.

**The attention mask structure (Figure 3, Left):** The mask defines three distinct attention regimes based on token position and role:

- **Clean prefix tokens (causal attention):** Tokens at positions 0 through $S-1$ (the original input) attend causally to themselves and all preceding clean tokens — the standard left-to-right causal mask of autoregressive transformers. This means the hidden state at position $i$ in the clean section is computed from exactly the tokens $\{x_0, x_1, ..., x_i\}$. This enables computing the autoregressive next-token prediction distribution $p(x_{i+1} | x_{\leq i})$ at each position, which forms the basis of both the AR training loss and the verification distribution during inference.

- **Mask/diffusion tokens (block-causal attention):** Tokens at positions $S$ through $2S-1$ (the corrupted section, which are all mask tokens in TiDAR's training) attend with a **block-causal** pattern: within each block of size $B$ (the training block length), tokens attend bidirectionally to each other; across blocks, tokens attend causally to tokens in earlier blocks and to the entire clean prefix. Formally, if the mask tokens are divided into blocks of size $B$ (e.g., blocks $[S, S+B-1]$, $[S+B, S+2B-1]$, etc.), then a mask token at position $j$ in block $b$ can attend to: (1) all clean prefix tokens (positions $0$ through $S-1$), (2) all mask tokens in earlier blocks (blocks $1$ through $b-1$), and (3) all mask tokens in the current block $b$ (bidirectionally). It **cannot** attend to tokens in future blocks. This is the Block Diffusion attention pattern, but critically, TiDAR uses it only for the **last block** (the decoding block) during inference, preserving the rest of the prefix as purely causal.

- **Cross-attention between sections:** Clean tokens do NOT attend to mask tokens (they can't see the future or the corrupted version), but mask tokens DO attend to clean tokens (the diffusion predictions are conditioned on the clean prefix). This asymmetry is essential: it means the clean section's computation is a pure AR forward pass (isolated from diffusion), while the diffusion section benefits from the full prefix context.

**Position IDs and label alignment:** For the clean (AR) section, the target labels are shifted by one position — token $x_i$ at input position $i$ has label $x_{i+1}$ — matching the standard next-token prediction objective. For the diffusion section, the labels remain aligned with their input positions — the model predicts each mask token's true identity at the same position index. This dual label scheme is necessary because the AR loss trains the model to predict "what comes next" given a clean context, while the diffusion loss trains it to predict "what token was masked" given the full (clean + noisy) context.

**What this mask enables computationally:** In a single forward pass through the transformer, the model computes:
- Hidden states for all clean prefix tokens under causal attention → these produce AR logits for next-token prediction at each position.
- Hidden states for all mask tokens under block-causal attention → these produce diffusion logits for predicting each masked token's identity.
Both sets of logits emerge from the same model weights and the same forward pass, but from different attention masks applied to different parts of the sequence.

**Why this specific hybrid design (not full bidirectional, not pure causal):**
- **Full bidirectional** (like standard diffusion models) would enable parallel generation but destroy the ability to compute the chain-factorized joint distribution needed for AR verification and exact likelihood evaluation — the clean tokens would attend to future tokens, leaking information and making the AR distribution invalid.
- **Pure causal** (like standard AR) would enable quality verification but give no parallelism benefit — the mask tokens would only see the prefix, not each other, making parallel within-block prediction impossible.
- **Block-causal** represents the minimal deviation from causal that still enables block-level parallelism: within a block, tokens can coordinate via bidirectional attention (useful for coherent multi-token generation), but across blocks, the causal constraint preserves the ability to compute valid AR distributions on the prefix and exact KV caching.

**Design choice — why only the last block is bidirectional during inference:** During training, multiple blocks of mask tokens are used for dense diffusion loss. During inference (as described in Figure 2 and Figure 3, Right), only the **current decoding block** (the tokens being pre-drafted for the next step) uses bidirectional attention; all previously accepted tokens (the prefix) use causal attention exclusively. This means the prefix-token hidden states are computed under pure causality, so their KV entries are valid for all future steps (exact caching), while the draft tokens benefit from within-block coordination.

#### 3.4.2 One-Step Full-Mask Diffusion and Loss Balancing

Traditional diffusion language models corrupt a random subset of tokens with mask tokens at each training step, and the loss is computed only on those masked positions. TiDAR makes a radical simplification: **all tokens in the diffusion section are set to mask tokens during training**, and the loss is computed at every diffusion position.

**The training objective:**

$$\mathcal{L}_{\text{TiDAR}}(\theta) = \frac{1}{1 + \alpha} \left( \sum_{i=1}^{S-1} \frac{\alpha}{S-1} \cdot \mathcal{L}_{\text{AR}}(x_i, x_{i+1}; \theta) + \sum_{i=1}^{S-1} \frac{1}{S-1} \cdot \mathcal{L}_{\text{Diff}}([\text{mask}], x_i; \theta) \right)$$

where $\alpha \in [0, 1]$ is the loss balancing factor controlling the relative weight of AR vs. diffusion objectives, $\{x_i\}^S$ is the input sequence of length $S$, and $\mathcal{L}_{\text{AR}}$ and $\mathcal{L}_{\text{Diff}}$ are both standard cross-entropy losses computed from the logits at clean and mask positions respectively, using their respective attention patterns.

**What this computes:** For each token position $i$ from 1 to $S-1$:
- The **AR loss term** `$\mathcal{L}_{\text{AR}}(x_i, x_{i+1}; \theta)$` computes the cross-entropy between the model's predicted distribution over the vocabulary at the output of clean position $i$ (under causal attention) and the true next token $x_{i+1}$. This is the standard language modeling objective, training the model to predict the next token given all previous tokens in sequence.
- The **diffusion loss term** `$\mathcal{L}_{\text{Diff}}([\text{mask}], x_i; \theta)$` computes the cross-entropy between the model's predicted distribution at the output of mask position $S + i$ (under block-causal bidirectional attention, given all mask tokens are `[MASK]`) and the true token $x_i$. This trains the model to denoise a fully masked sequence given the clean prefix as context.

Both sums run over $S-1$ terms (the last clean token has no next-token label, and similarly for the diffusion section), so the per-term normalization is consistent. The outer factor `$1/(1+\alpha)$` ensures the total loss is a convex combination: when $\alpha = 1$, both objectives contribute equally after normalization; when $\alpha \to 0$, the loss reduces to pure diffusion.

**Why this form — the full-mask strategy matters:**

**(1) Train-test consistency:** During inference, TiDAR uses **one-step diffusion drafting** — all draft tokens are generated in a single forward pass from a fully masked block. If the model were trained with random masking (some tokens visible, some masked), it would learn to rely on partially-available clean information within the block during training, but at inference time that information isn't available (all tokens are masked), creating a distribution shift. By training with all mask tokens, the model learns exactly the inference-time task: predict all tokens simultaneously from a fully masked block conditioned only on the clean prefix. This eliminates the train-test discrepancy.

**(2) Denser diffusion loss signal:** With random masking, only a fraction of diffusion positions (those randomly selected for masking) contribute to the gradient. With full masking, every position contributes — the diffusion loss has $S-1$ terms per sample instead of (on average) a fraction thereof. This is particularly important because TiDAR is continually pretrained from AR checkpoints with limited data (50B tokens for 1.5B, 150B tokens for 8B), so signal efficiency matters.

**(3) Consistent loss normalization for balancing:** In traditional random-masking diffusion, the number of masked (and thus loss-contributing) tokens varies per sample depending on the stochastic masking pattern, while the AR loss is always computed over $S-1$ fixed positions. This varying scale makes balancing via a fixed $\alpha$ problematic — the effective diffusion gradient magnitude fluctuates. With full masking, both loss components are calculated over exactly $S-1$ terms every time, with equal variance in the loss scale. The user simply sets $\alpha$ (the paper uses $\alpha = 1$ for most cases, meaning equal weight), and the balancing is clean.

**Connection to inference flexibility:** The full-mask training also explains why TiDAR can flexibly choose whether to use AR or diffusion logits for verification (§3.4.5). Because the model learns to predict the same token from two different contexts (causally from the clean prefix vs. bidirectionally from a masked block), and both are trained to convergence on the same objective (predicting the true token), the two distributions should agree when the model is well-trained. The full-mask strategy strengthens the diffusion signal enough to make this agreement tight.

**How this differs from Block Diffusion and SBD:** Both prior methods double the sequence length and apply random masking to the corrupted tokens (following the standard diffusion corruption process with a noise schedule). They do NOT use full masking. As a result, they face the variable-scale loss balancing problem, they have less dense diffusion gradients, and they have a train-test mismatch if one-step generation is used at inference.

#### 3.4.3 The Parallel Self-Speculative Generation Loop

The inference algorithm is the centerpiece that connects the dual-mode training to actual speedup. It operates as a recurrent loop where each step simultaneously verifies the previous step's drafts and pre-drafts tokens for the next step.

**Step 0 — Prefilling (prompt processing):** The full prompt is encoded causally with the standard AR prefill. The model also pre-drafts the first block of tokens for step 1. To do this, the input sequence is: (clean prefix = prompt tokens, all attending causally) + (mask tokens of block size $B$, attending bidirectionally within block and causally to the prefix). The diffusion logits at the mask positions produce the initial draft tokens $\hat{x}_{P+1}, \hat{x}_{P+2}, ..., \hat{x}_{P+B}$ where $P$ is the prompt length. The KV cache for all prompt tokens is stored. This initial draft is generated without verification because there's nothing to verify yet.

**Step t ≥ 1 — The core loop:** At the start of step $t$, the system has:
- A clean prefix of length $L_{t-1}$ (all tokens accepted in previous steps).
- A draft block of $B$ tokens from step $t-1$: $d_1^t, d_2^t, ..., d_B^t$ (these were pre-drafted in the previous step and need to be verified now).

The forward pass input is constructed as:
`[clean prefix of length L_{t-1}] + [d_1^t, d_2^t, ..., d_B^t] + [MASK_1, MASK_2, ..., MASK_B]`

The attention mask for this forward pass (Figure 3, Right) is:
- **Clean prefix:** causal attention within the prefix (standard AR).
- **Draft tokens from last step ($d_1^t$ through $d_B^t$):** causal attention — each draft token $d_i^t$ attends to the entire clean prefix and to earlier draft tokens $d_1^t, ..., d_{i-1}^t$ (left-to-right causal). They do NOT attend to the mask tokens (those are for the next step, unknown at this point).
- **Mask tokens for next step (MASK_1 through MASK_B):** block-causal bidirectional attention — each mask token attends to the entire clean prefix, all $B$ draft tokens, and all other mask tokens in the same block. They attend bidirectionally within the mask block to coordinate predictions.

**Verification via autoregressive rejection sampling:** The AR logits computed at positions $d_1^t$ through $d_B^t$ (from the causal attention computation) give the chain-factorized conditional distributions:

$$p_{\text{AR}}(x | \text{prefix}, d_1^t, ..., d_{i-1}^t)$$

For $i = 1$ to $B$:
- The model's AR distribution at the position corresponding to $d_i^t$ is compared against the drafted token $d_i^t$ using the standard speculative decoding rejection sampling procedure (Leviathan et al., 2023): if the drafted token's probability under the AR distribution is higher than its probability under the draft distribution, it's accepted; otherwise, it's accepted with probability proportional to the AR probability divided by the draft probability.
- If a token is accepted, it becomes part of the clean prefix. If rejected, a new token is sampled from a modified distribution (the residual of the AR distribution after subtracting the draft distribution, renormalized), and all subsequent draft tokens ($d_{i+1}^t, ..., d_B^t$) are discarded (standard speculative rejection).
- The KV cache entries for accepted draft tokens are retained (they were computed under causal attention, so they're valid AR entries). The KV entries for rejected and discarded tokens are evicted.

**Parallel pre-drafting for the next step:** Simultaneously with verification, the diffusion logits at the MASK_1 through MASK_B positions produce predictions for the NEXT step's draft tokens. Because the model was trained to predict true tokens from fully masked positions given a clean prefix, these logits represent:

$$p_{\text{Diff}}(x_j^t | \text{prefix, all draft tokens from this step, all other mask tokens in block})$$

for each mask position $j$. The key insight — borrowed from Apple's MTP — is that the model pre-drafts **multiple proposals**, one for each possible number of accepted tokens from the current verification step. If the verification step accepts $k$ out of $B$ draft tokens ($0 \leq k \leq B$), the clean prefix for the next step will be of length $L_{t-1} + k$. The model's mask-token predictions were conditioned on all $B$ draft tokens (both accepted and rejected) and on each other, but only the prediction corresponding to the **first mask token after the $k$ accepted positions** is usable as a coherent continuation. Therefore:

- The model outputs $B$ draft-token proposals (one per mask position), each conditioned on the full current context including all $B$ draft tokens.
- After verification determines the acceptance count $k$, the system selects the $(k+1)$-th through $(k+B)$-th predicted tokens as the draft for the next step. Specifically, the selected proposal is the block of $B$ mask-token predictions that corresponds to the positions immediately following the $k$ accepted tokens.

This selection mechanism is what the paper means by "conditioned on all possible outcomes of the rejection sampling" — the model generates all $B$ possible continuations in parallel, and the correct one is selected post-hoc based on the verification result, without any additional forward passes.

**KV cache management:** All tokens computed under **causal attention** (the clean prefix and any accepted draft tokens) have their KV entries stored in the cache for future steps, exactly like standard AR caching. Tokens computed under **bidirectional attention** (the mask tokens) have their KV entries discarded after the step — they were conditioned on the current context only and are invalid for future steps where the prefix has grown. Crucially, even for rejected draft tokens, their KV entries were computed under causal attention (since the draft positions attend causally to the prefix), so they could technically be cached — but since they're not part of the final sequence, they're evicted to save memory. This is the "exact KV cache" property that pure diffusion models lack: at no point does TiDAR need to recompute or approximate attention for any prefix token.

**Warm-up: handling the first decoding step without prior drafts.** In the first decoding step (after prefill), there are no draft tokens from a "previous step" to verify. The input is: `[clean prefix = full prompt] + [MASK_1, ..., MASK_B]`. All mask tokens attend bidirectionally to each other and causally to the prefix. The model generates the first $B$ draft tokens from the mask positions. These are used directly (no verification) as the draft for step 1. Starting from step 1, the full verify-and-predraft loop operates as described above.

**Why this is "self-speculative":**
- In traditional speculative decoding, the draft model is a separate (usually smaller) model. Drafting capacity is limited, and errors from the weak drafter cause frequent rejections.
- In TiDAR, the "draft model" IS the base model itself — the diffusion mode uses the same transformer weights as the AR mode, just with different attention masking. This means the drafting capacity equals the base model's capacity.
- Because the diffusion predictions are generated in parallel (one forward pass, all mask tokens predicted simultaneously) while the AR verification is also computed in the same forward pass, there is zero additional latency for drafting beyond what the verification already costs. The drafting effectively happens "for free" in the mask-token slots.

**Why the acceptance rate is high:** The draft tokens come from the same model weights as the verification distribution, and the training objective forces the AR and diffusion predictions to agree (both predict the same true token at overlapping positions). In a well-trained model, the diffusion marginal predictions closely approximate the AR conditional predictions, so the rejection rate is low. The paper reports average tokens per NFE of 7.45 (1.5B) and 8.25 (8B), which is the effective block size after accounting for rejections — close to the draft block sizes of 4, 8, and 16 used in experiments.

#### 3.4.4 Inference Attention Mask Engineering: Reordering, Pre-Computation, and Slicing

The inference loop described above requires a different attention mask at each step because the prefix length grows. Recomputing the mask from scratch at each step would be wasteful. TiDAR uses a clever engineering trick to amortize this cost.

**The core observation:** Every forward pass during inference has the same structure: a clean prefix (of variable length), $B$ draft tokens from the previous step, and $B$ mask tokens for pre-drafting. The total input length at step $t$ is $L_{t-1} + 2B$ (where $L_{t-1}$ is the current accepted prefix length). The attention pattern is always:
- Prefix: causal to itself.
- Draft tokens: causal to prefix and earlier drafts.
- Mask tokens: block-causal to prefix, all drafts, and within-block.

**Pre-computing one large mask:** At model initialization, the system creates a single attention mask tensor of size `(max_sequence_length + B, max_sequence_length + B)` that encodes the full block-causal pattern for the maximum possible generation length. This mask is computed once and stored.

**Reordering for slicing efficiency (Figure 3, Right):** To reuse this pre-computed mask, the input tokens are **reordered** before the forward pass. Instead of the natural order (prefix, drafts, masks), the tokens are arranged by attention role:
- First, the $B$ draft tokens and $B$ mask tokens from the "sampling-draft" part (these have block-causal attention within themselves).
- Then, the clean prefix tokens (purely causal).
The mask is then **sliced** based on the current prefix length to extract exactly the sub-mask needed for the current step. Because the pre-computed mask has the block-causal pattern built in for the sampling-draft region, the slice at any prefix length naturally inherits the correct attention pattern for that configuration.

**Why this works:** The reordering doesn't change the attention computation — it's just a permutation of input positions that is undone when extracting logits. The benefit is that the slicing operation is O(1) (just indexing into a pre-computed tensor) rather than O(L²) (reconstructing the mask).

**Prefill mask (Figure 7, Appendix B):** For the initial prefill step, a separate pre-computed mask handles the special case: the full prompt (no prior drafts) + $B$ draft mask tokens. This mask is also pre-computed at initialization with size `(max_sequence_length + B, max_sequence_length + B)` and sliced according to the actual prompt length.

**Exact KV caching detail:** The paper emphasizes that TiDAR supports exact KV caching, which means:
- When a draft token is accepted during verification, its KV entry (computed under causal attention from the prefix and earlier accepted drafts) is permanently stored — it never needs to be recomputed.
- When a draft token is rejected, its KV entry is **evicted** (deleted from the cache), and subsequent tokens (which were drafted based on the rejected token) are also discarded.
- The mask tokens' KV entries are always discarded after the step — they served their purpose for within-step bidirectional coordination and are invalid for future steps (where the prefix has grown).
- **No recomputation ever occurs** — unlike Fast-dLLM (which may recompute parts of the prefix with updated masking) or d-KV cache (which selectively re-evaluates cached tokens), TiDAR's KV cache behaves exactly like a standard AR cache for all prefix tokens.

**Comparison with prior caching approaches:**
- **Standard AR:** Perfect caching, but one token per forward.
- **Block Diffusion:** Exact caching for prefix blocks (inter-block causal), exact caching within the current block is impossible (intra-block bidirectional changes per step).
- **Fast-dLLM:** Approximate caching — caches prefix and optionally suffix, but the within-block attention pattern shifts during multi-step denoising, so cached values can become stale.
- **d-KV cache:** Delayed, selective caching — some tokens are cached, but the selection introduces quality degradation.
- **TiDAR:** Exact caching for all prefix tokens (they're computed under pure causality), no caching for mask tokens (they're regenerated each step anyway, and they don't need caching because they only exist for one step). This is strictly better than all diffusion caching schemes and equal to AR caching for prefix tokens.

#### 3.4.5 Handling the AR vs. Diffusion Prediction Ambiguity

A subtle issue arises from TiDAR's no-label-shift design for the diffusion section. In standard AR language models, the input token at position $i$ has label $x_{i+1}$ — the model predicts the NEXT token. But in TiDAR's diffusion section, there is no label shift: the mask token at position $i$ has label $x_i$ — the model predicts the SAME-position token that was masked. This design is necessary for the pre-drafting to work without waiting for AR verification results (the first mask token predicts the first new token, not waiting to know the last verified token), but it creates an overlap at the boundary between the draft tokens and the mask tokens.

**The overlap explained:** Looking at Figure 2, when the verification step has $B=3$ draft tokens `[E, F, G]` and $B=3$ mask tokens `[M, M, M]`:
- The AR output at position `E` predicts token `F` (next-token prediction on clean input).
- The diffusion output at the first mask position also predicts token `F` (same-position prediction on masked input, since the mask token at position 4 is aligned with the true token at position 4 which is `F`).

Both the AR logits (from the draft token `E`'s output) and the diffusion logits (from the first mask token's output) are predicting the same target token `F`. When the model is perfectly trained, these two predictions should be identical (same distribution over the vocabulary). In practice, they may differ slightly due to the different conditioning contexts (causal vs. bidirectional) and training dynamics.

**This overlap exists at EVERY position within the draft block:** For draft token $d_i^t$, the AR prediction is for the token that SHOULD follow $d_{i-1}^t$, while the corresponding mask token prediction is for the token at that same sequential position. These predictions converge to the same target during training but are computed from different attention patterns.

**The mixing solution:** During verification, the system has a choice: use the AR logits only, the diffusion logits only, or a mixture. The paper introduces an aggregate function parameterized by $\beta \in [0, 1]$:

$$\text{logits}_{\text{verify}} = \beta \cdot \text{logits}_{\text{AR}} + (1 - \beta) \cdot \text{logits}_{\text{Diff}}$$

where $\text{logits}_{\text{AR}}$ are the logits from the causal computation at the draft token position, and $\text{logits}_{\text{Diff}}$ are the logits from the bidirectional computation at the corresponding mask position. The token is sampled from the softmax of this mixed logit vector, and then compared against the drafted token in the standard rejection sampling procedure.

**What $\beta$ controls:** $\beta$ represents the degree of "trust" in the AR mode's predictions versus the diffusion mode's predictions. $\beta = 1$ means trust AR completely (standard speculative decoding behavior, verify using only the target model's distribution). $\beta = 0$ means trust diffusion completely (effectively, accept the draft token if it's consistent with the diffusion prediction). Intermediate values blend the two.

**Empirical finding (Figure 6):** The paper shows that performance is remarkably **insensitive** to $\beta$ across a wide range (0 to 1), both for different values of $\beta$ and for different training loss balancing factors $\alpha$. This flatness is a positive signal: it means the model is well-trained enough that the AR and diffusion predictions agree closely, so tuning $\beta$ is unnecessary. The paper treats this as evidence that "the autoregressive rejection sampling... guarantees the quality-speedup trade-offs rather than the AR knowledge" — i.e., the verification mechanism itself provides the quality guarantee, regardless of which mode's logits are used for the comparison.

**The two "trust" modes in evaluation:** Despite the insensitivity, the paper reports two evaluation configurations in Table 2: "Trust AR" and "Trust Diffusion," corresponding to $\beta = 1$ and $\beta = 0$ respectively. For the 8B model, "Trust Diffusion" slightly outperforms "Trust AR" on most tasks (e.g., HumanEval 57.93% vs. 55.49%, GSM8K 80.44% vs. 79.83%), suggesting that for larger models, the diffusion predictions benefit from the bidirectional attention coordination within the block and produce slightly better-aligned distributions. For the 1.5B model, the single "TiDAR" entry combines both modes via the aggregate function with an unspecified $\beta$ (likely $\beta = 0.5$ or a per-task selection).

**Why no label shift matters for parallelism:** If the diffusion section used label shifting (like the AR section), the first mask token would predict the token AFTER the last draft token, which depends on the drafted token's identity. But the drafted token's identity isn't known at pre-drafting time — it's being verified simultaneously. No label shifting breaks this dependency: each mask token predicts its own position's token, which is independent of the verification outcome for the draft tokens at the corresponding positions. This independence is what enables the pre-drafting to be fully parallel with verification — the mask predictions don't need to wait for AR results.

#### 3.4.6 Training Recipe and Hyperparameters

The paper provides specific training configurations that are critical for reproducibility:

**Continual pretraining from AR checkpoints:** TiDAR is initialized from pretrained AR models (Qwen2.5 1.5B, Qwen3 4B, Qwen3 8B) rather than trained from scratch. This is important because: (a) the AR capability is largely preserved in the causal section of the model, (b) the diffusion capability is added via the new attention mask and loss on the appended mask tokens, and (c) the total training data requirement is relatively modest (50B–150B tokens) compared to pretraining from scratch (trillions of tokens).

**Data scale:** "For TiDAR 1.5B model, we continually pretrain with 50B tokens on Nvidia H100s with a global batch size of 2M tokens (DDP) under block sizes of 4, 8, and 16. For the 8B model, we use 150B tokens instead, with a block size of 16, keeping the rest of the settings the same."

**Optimization:** "We adopt the cosine scheduling with max_lr = 1e-5, min_lr = 3e-6 and a warm-up step fraction of 1%. The max sequence length is set to 4096 with distributed Adam optimizer and we turn on gradient checkpointing for the 8B model."

**Precision and framework:** "Both training and inference are conducted in the standard BFloat 16 precision. The overall training framework is a modified Megatron-LM with Torchtitan support."

**Loss balancing:** "We choose to set $\alpha = 1$ for most cases" — meaning equal weight to AR and diffusion losses. The ablation in Figure 6 shows results for three settings: $\alpha$ corresponding to weight ratios (AR×0.8 + Diff×1.0)/1.8, (AR×1.0 + Diff×1.0)/2.0, and (AR×1.2 + Diff×1.0)/2.2, with very similar performance.

**Block sizes:** TiDAR 1.5B is trained with block sizes of 4, 8, and 16 (three separate model variants). TiDAR 8B is trained with block size 16 only. The block size determines the draft length during inference — block size 4 means the model attempts to draft and verify 4 tokens per step. Larger block sizes give higher theoretical speedup (more tokens per NFE) but potentially lower acceptance rates (harder to draft many tokens correctly from marginal distributions). Figure 5 shows the Pareto frontier across block sizes, with block size 16 achieving the highest T/NFE (6.97 average) but slightly lower quality than block size 4 on some tasks.

**Why block sizes 4, 8, 16:** These powers of 2 map naturally to the "free token slots" region in Figure 1 — at typical prefix lengths (1024–4096), adding 4–16 tokens to a forward pass remains in the flat latency region, meaning near-zero additional wall-clock time per step for these draft tokens. Larger blocks would eventually push into the compute-bound regime where additional tokens DO cost proportionally more latency, eroding the speedup advantage. The paper doesn't test block sizes beyond 16, but the principle is clear: stay within the memory-bound regime.

## 4. Key Insights and Innovations

### Innovation 1: The "Free Token Slots" Concept as a Quantifiable Hardware Opportunity, Not Just an Intuition

The paper's most foundational conceptual move is to formalize the GPU memory-bound regime not as a limitation to work around, but as an **unclaimed budget of computation** that can be systematically exploited through architectural design. This is a reframing of how to think about inference efficiency: rather than asking "how can we make each token cheaper?" (the standard optimization framing), TiDAR asks "how many useful tokens can we generate within the latency envelope we're already paying for?"

This is not the same as saying "we can do more with the same FLOPs" — that's a FLOPs-efficiency argument that applies to compute-bound regimes. The "free token slots" concept is specifically about the **structural underutilization of GPUs during memory-bound autoregressive decoding**. In the memory-bound regime — which is where single-batch autoregressive decoding lives for all practical model sizes — the GPU's compute units spend most of their time idle while waiting for model weights and KV cache entries to stream from HBM. A forward pass with 1024 prefix tokens and one new token takes roughly the same wall-clock time as a forward pass with 1024 prefix tokens and 8 new tokens, because the compute for those extra 7 tokens fits into cycles that would otherwise be idle. Figure 1 makes this concrete with real profiling data on an H100 at different prefix lengths, showing the latency curve is essentially flat for a significant range of additional token slots.

Prior work has implicitly exploited this property — speculative decoding verifies multiple drafted tokens in parallel, and diffusion models decode multiple tokens per step — but none have explicitly named it as the central design target. Speculative decoding treats the parallelism as a verification batching benefit; diffusion models treat it as a generation parallelism benefit. TiDAR's insight is that **both verification and generation computations can coexist in these free slots simultaneously**, because the "cost" is measured in total tokens-per-forward, and as long as that total stays in the flat region, it doesn't matter whether those tokens are doing AR work, diffusion work, or both.

This is a **fundamental shift** in how to reason about hybrid architectures: the question isn't "can we make diffusion fast enough?" or "can we make drafting good enough?" but rather "given a fixed latency budget defined by the memory-bound ceiling, how do we optimally allocate the free token slots between verification and drafting work?" TiDAR's answer — use causal attention slots for AR verification and bidirectional attention slots for parallel one-step diffusion drafting — is one specific allocation strategy, but the framing opens a design space: could we allocate some slots to retrieval, to multiple candidate paths, to self-consistency voting? The "free token slots" concept provides a language and a measurement methodology for reasoning about this space.

The significance extends beyond this paper's results. It suggests that inference-time efficiency should be benchmarked in terms of **latency-normalized useful computation**, not just tokens-per-second or FLOPs-per-token. A model that generates 8 tokens in 30ms is not "8× faster" than one that generates 1 token in 30ms if the single token is of much higher quality — but if the 8-token model maintains comparable quality, the speedup is genuine. Figure 4's throughput-quality plots are an attempt at this latency-normalized benchmarking, plotting task score against relative decoding throughput (tokens per second, not per NFE).

### Innovation 2: Dual-Mode Sampling as a Within-Model Speculative Framework, Not a Sequential Draft-Verify Pipeline

The paper reframes speculative decoding from a **two-model sequential pipeline** (draft with a weak model, verify with the strong model, with sequential dependency between the two stages) to a **single-model parallel operation** where drafting and verification share the same model weights, the same forward pass, and the same attention computation. This is not an incremental improvement to speculative decoding — it removes the fundamental architectural assumption that the drafter and verifier must be separate models with different capacities, executing in sequence.

Table 1 makes this structural difference explicit. In classic speculative decoding, the draft model is a separate (usually smaller) model whose capacity is inherently lower than the base model's — this is the "drafting capacity gap" that limits speedup. In EAGLE-3 and DeepSeek-V3 MTP, the draft model shares the base model's hidden states but adds autoregressive layers that execute sequentially, so drafting still has serial dependency and reduced capacity. In TiDAR, there is **no separate draft model at all** — the base model itself generates draft tokens through its diffusion computation path, using the same transformer layers and parameters, just with a different attention mask applied to the mask-token section of the input. The "drafting capacity gap" is closed entirely because the drafter IS the base model.

This is a **fundamental architectural innovation**, not an incremental refinement. The mechanism that enables it — the hybrid attention mask that partitions a single forward pass into causal and bidirectional regions — is the technical contribution described in Section 3. But the conceptual move is recognizing that **within-model self-speculation** is possible if the model is trained to compute two different conditional distributions (chain-factorized for verification, marginal for drafting) from the same hidden states.

This reframing also changes how we think about the acceptance rate in speculative decoding. In traditional speculative decoding, acceptance rate is a measure of how well the draft model approximates the target model's distribution — it's inherently limited by the draft model's capacity. In TiDAR, acceptance rate is a measure of how well the **diffusion marginal distribution approximates the AR chain-factorized distribution**, which are two outputs of the same model at the same time. When the model is well-trained, these two distributions should agree tightly because both are predicting the same true token from (slightly different) contexts, trained on the same objective. The reported 7.45–8.25 tokens per NFE (Table 2 parentheticals) — which is the effective acceptance rate times block size — supports that this agreement is strong in practice.

A subtle implication: this architecture **decouples the quality guarantee from the drafting mechanism**. In standard speculative decoding, if the draft model degrades, the output quality is preserved (rejection sampling falls back to the base model's distribution) but speedup is lost. In TiDAR, if the diffusion predictions degrade, quality is similarly preserved (rejection sampling using AR logits is the verification step), but speedup is lost. The quality floor is therefore exactly the base AR model's quality, regardless of how well the diffusion mode performs. This is verified by Figure 6: even when sweeping $\beta$ (the AR-diffusion mixing weight for verification) from 0 to 1, quality is essentially flat, confirming that the rejection sampling mechanism, not the specific logits used, provides the quality guarantee.

### Innovation 3: Full-Mask Training as a Train-Test Consistency Principle, Not Just a Masking Strategy

At first glance, the decision to set all tokens in the diffusion section to mask tokens during training ("full-mask strategy") might appear to be a minor implementation detail — a simpler alternative to the random masking schedules used in prior diffusion language models. But the paper reveals it as a **principled design choice** that addresses a fundamental train-test distribution shift that prior work either ignored or accepted as inherent to diffusion LMs.

Prior diffusion language models (Llada, Dream, MDLM, Block Diffusion) follow the standard diffusion paradigm: during training, a noise schedule determines which random subset of tokens get corrupted to mask tokens at each step, and the loss is computed only on the corrupted positions. This means the model learns to denoise partially-corrupted sequences — some tokens are clean, some are masked — but at inference time, depending on the generation strategy, the model may encounter fully-masked blocks (one-step generation) or different corruption patterns. The sparser the training mask, the larger the discrepancy.

TiDAR's inference uses **one-step diffusion drafting** — all draft tokens are generated simultaneously from a fully-masked block. If the model were trained with random masking, it would have learned to rely on the partially-visible clean tokens within the drafting block for context, but those clean tokens don't exist at inference time (they're all masked, since they haven't been generated yet). The full-mask training eliminates this mismatch: what the model sees during training (a block of all mask tokens, conditioned on a clean prefix) is exactly what it sees during inference.

This is a **diagnostic insight**, not just a method. It explains why prior diffusion models that use one-step generation often underperform their multi-step counterparts: the multi-step process gradually reveals clean tokens within the block, approximating the training distribution's partial-corruption pattern, while one-step generation faces a pure all-mask condition the model wasn't trained for. By training with full masks, TiDAR makes one-step generation the natural inference mode.

The innovation has cascading benefits that the paper identifies: (1) **Denser diffusion loss signal** — every diffusion position contributes to the gradient, rather than only a random subset. This is critical for data-efficient continual pretraining (50B–150B tokens). (2) **Consistent loss normalization** — both AR and diffusion losses are computed over exactly $S-1$ terms per sample, making the balancing weight $\alpha$ scale-consistent across samples. In random-masking approaches, the number of masked positions varies, causing the effective diffusion gradient magnitude to fluctuate relative to the AR gradient. (3) **Elimination of noise schedule design** — there's no need to tune a masking schedule, corruption ratio, or number of denoising steps, which are hyperparameters that significantly affect diffusion LM quality.

The ablation in Table 5 confirms this is not minor: switching from random to full masking improves average task score from 45.45% to 48.42% at block size 4 (on the 1.5B model), while also increasing tokens per NFE from 3.42 to 3.47. The gap widens at block size 8 (45.68% → 48.94%). This is a substantial gain from what might appear to be a simple masking choice, supporting the claim that train-test consistency is a first-order effect in diffusion LM design, not a second-order detail.

### Innovation 4: Exact KV Caching from a Hybrid Causal-Bidirectional Model — a New Point on the Design Spectrum

The paper demonstrates that a model with bidirectional attention within generation blocks can simultaneously support **exact KV caching** for all prefix tokens, a property that pure diffusion models have struggled to achieve and that prior hybrid approaches (Block Diffusion) only partially realized. This is a **novel point on the architectural design spectrum** that combines the caching benefits of causal models with the parallelism benefits of bidirectional models, without the quality degradation of approximate caching schemes.

To appreciate this, consider the landscape:
- **Pure AR models** have perfect KV caching (every prefix token is computed causally and cached) but no parallelism (one token per forward).
- **Pure diffusion models** (Llada, Dream) have parallelism but fundamentally cannot cache prefix KV entries because bidirectional attention within the entire sequence means the attention pattern changes at each denoising step — cached values from a previous step are computed under a different attention mask than the current step requires.
- **Fast-dLLM** and **d-KV cache** approximate caching by heuristically keeping some KV entries and recomputing or approximating others, trading quality for speed.
- **Block Diffusion** has exact caching for prefix blocks (inter-block causal attention) but loses exactness within the current decoding block (intra-block bidirectional attention requires recomputation or approximation within that block).

TiDAR achieves exact caching by a clean separation: **all tokens that persist across generation steps (the prefix) are computed under pure causal attention**, and **all tokens that use bidirectional attention (the mask tokens) exist only within a single step and their KV entries are discarded**. There is no approximation, no staleness, no recomputation. The causal-attention constraint on prefix tokens is not a compromise — it's exactly what enables the AR verification and quality guarantee, so it serves double duty.

This is significant beyond performance because it **resolves a structural tension** that previously seemed intrinsic: the idea that parallelism requires bidirectional attention, and bidirectional attention precludes exact caching. TiDAR shows these are only in conflict if you insist on making the entire generated sequence use the same attention pattern. By partitioning the sequence temporally — tokens are causal when they're being committed to the prefix, bidirectional when they're being drafted — you get both properties without approximation.

The engineering consequence is that TiDAR's caching behavior is **strictly compatible with existing AR serving infrastructure**. KV cache management (paged attention, prefix sharing, eviction) works identically to standard AR models for the prefix portion. The mask tokens require no caching at all. This is a practical advantage that speculative decoding shares (both EAGLE and standard speculative decoding use AR models with standard caching) but that no prior diffusion architecture can claim. It means TiDAR can be deployed with minimal modification to existing serving stacks, which is a significant barrier-to-entry reduction compared to diffusion models that require custom caching infrastructure.

---

### Innovation 5: The Diffusion-AR Quality Parity at Scale as an Empirical Discovery, Not an Assumption

A distinctive contribution is the empirical finding that **a single model trained with dual AR-diffusion objectives can achieve near-parity between its AR and diffusion predictions**, enabling the self-speculative loop to operate with high acceptance rates without a quality penalty. This is not an obvious result — there are reasons to expect the two distributions to diverge, since they condition on different information (causal left-context only vs. bidirectional context including future mask positions that coordinate predictions). Figure 6 is the key evidence: performance is essentially flat across the full range of $\beta$ (AR-diffusion mixing weight) from 0 to 1, across multiple values of the training loss balancing factor $\alpha$. This flatness means the AR and diffusion predictions are so closely aligned that it doesn't matter which one you use for verification — the rejection sampling outcome is effectively the same.

This is a **surprising empirical result** with important implications. It suggests that when a transformer is trained with both causal and bidirectional losses on the same data, the bidirectional predictions don't just capture the marginal distribution — they implicitly learn to approximate the chain-factorized distribution well enough that the gap is negligible for the purpose of speculative verification. This may be because the full-mask training forces the model to learn strong token-level identity representations that transfer across attention patterns, or because the shared transformer layers develop representations that are sufficiently context-invariant.

The practical consequence is that TiDAR is effectively hyperparameter-free at inference time — unlike diffusion models that require tuning entropy thresholds, confidence cutoffs, or number of denoising steps, TiDAR just runs the self-speculative loop with a fixed block size and the acceptance rate emerges naturally from the model's training quality. This is a significant usability advantage in deployment, and it distinguishes TiDAR from both pure diffusion models (which typically require inference-time tuning) and speculative decoding (which requires choosing and potentially fine-tuning a draft model).

The finding also opens a research question: is this parity a consequence of TiDAR's specific training recipe (full masking, equal loss weighting, continual pretraining from AR checkpoints), or is it a general property of dual-mode training that would hold across architectures? If it's general, then the self-speculative paradigm could be applied to other model families without TiDAR's specific attention mask, using any mechanism that produces both AR and diffusion-style predictions from the same hidden states. If it's recipe-specific, then the full-mask and loss-balancing choices are load-bearing for the quality-speedup trade-off, which would make the training methodology a core contribution in its own right rather than just enabling the architecture.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The paper evaluates on a diverse set of downstream tasks: coding benchmarks (HumanEval, HumanEval+, MBPP, MBPP+) with pass@1 using greedy decoding, math benchmarks (GSM8K with 8-shot chain-of-thought and strict matching, Minerva Math with 4-shot exact matching), factual knowledge (MMLU with 5-shot), and commonsense reasoning (ARC-Easy, ARC-Challenge, HellaSwag, PIQA, Winogrande). All evaluations use `lm_eval_harness` version 0.4.8. Full task configurations (number of few-shot examples, generation length, metric type) are detailed in Appendix A, Table 6. The paper focuses primarily on coding and math tasks for generative evaluation because "their metrics are much more robust" (Section 4.2.1).

- **Base model(s).** TiDAR is initialized via continual pretraining from three AR model families: Qwen2.5 1.5B, Qwen3 4B, and Qwen3 8B (Section 4.1). The paper chooses these because they represent "representative of the capabilities of many contemporary LLMs" (quoting the earlier rationale) and span a useful range of scales for demonstrating the speed-quality trade-off. The 1.5B model is used for extensive ablations; the 8B model demonstrates scaling behavior. For the 4B model, only Block Diffusion comparison results are reported in Table 2. All TiDAR results refer to base models unless explicitly noted as "Instruct" (the EAGLE-3 comparison in Figure 4 uses Qwen3 8B Instruct because EAGLE-3 weights for the base model were unavailable).

- **Metrics.** For generative tasks, the primary quality metric is task-specific accuracy: `pass@1` for coding tasks (with standard post-processing for HumanEval), `strict-match` for GSM8K (8-shot CoT), and `exact-match` for Minerva Math (4-shot). For likelihood tasks (MMLU, ARC, HellaSwag, PIQA, Winogrande), the metric is accuracy or accuracy-normalized as specified in Table 6. For efficiency, the paper reports two metrics: (1) **tokens per NFE** (Network Function Evaluation, i.e., per model forward pass), which measures the average number of valid (accepted) tokens generated per forward pass — this captures the acceptance rate of the self-speculative loop; and (2) **relative decoding throughput** measured in tokens per wall-clock second, normalized against the baseline AR model's throughput in the same size group. The throughput measurements are conducted on a single NVIDIA H100 GPU with batch size 1 using native PyTorch with Flex Attention, with prompts drawn from the downstream generative tasks.

- **Baselines.** The paper compares against several categories: **(a) AR models**: Llama3.2 1B, SmolLM2 1.7B, Qwen2.5 0.5B and 1.5B, Qwen3 1.7B, 4B, and 8B (all base models unless noted). **(b) Diffusion language models**: Dream 7B (Ye et al., 2025), Llada 8B (Nie et al., 2025), and Block Diffusion (Arriola et al., 2025) — the latter is trained by the authors under the same recipe as TiDAR for fair comparison. **(c) Speculative decoding**: EAGLE-3 (Li et al., 2025) using publicly available weights from AngelSlim and Tengyunw, both built on Qwen3 8B Instruct (the only EAGLE-3 weights available for this model family). **(d) A fine-tuned AR baseline** (Figure 5 only): the base Qwen2.5 1.5B model fine-tuned on the same 50B tokens used for TiDAR training, to isolate the effect of additional training from the architectural change.

- **Generation budget / compute accounting.** The universal unit of efficiency comparison is **tokens per second (wall-clock)**, measured under identical hardware conditions (single H100, batch size 1, BFloat16, native PyTorch). For the quality-efficiency benchmarking in Figure 4, the x-axis is "relative AR throughput speedup" — the ratio of TiDAR's tokens-per-second to the AR baseline's tokens-per-second within the same model size group. The paper explicitly notes that this measures **decoding throughput only** (not total throughput including prefill) and that "all of these methods can significantly benefit from further system optimizations such as custom kernels, more efficient KV cache management, and request scheduling" — the benchmarking goal is to provide "a first-hand idea of their performance in native PyTorch" (Section 4.3). For Block Diffusion baselines, the paper tests multiple decoding thresholds (max, 0.8) representing different points on the quality-efficiency trade-off curve, since Block Diffusion requires threshold tuning. TiDAR, by contrast, requires no hyperparameter tuning during inference and naturally produces a single point per block-size configuration. The paper also reports average tokens per NFE (parenthetical values in Table 2, and as annotations on Figure 4 data points) as a hardware-independent efficiency metric capturing the acceptance rate of the self-speculative loop.

- **Cross-validation / statistical protocol.** There is no formal cross-validation or statistical significance testing reported. The paper evaluates on the standard test sets of each benchmark (e.g., HumanEval's 164 problems, MBPP's 500 test problems, GSM8K's 1,319 test problems) and reports single-point accuracy estimates. Throughput measurements are presumably from single runs (no variance reported). The ablations in Figure 5 demonstrate consistency across multiple coding and math tasks, but no confidence intervals or error bars are provided for any result. The small size of some test sets (e.g., HumanEval at 164 problems) means that differences of a few percentage points may fall within sampling noise, but the paper does not discuss this.

### Main Quantitative Results

#### Generative Quality and Efficiency (Table 2, Figure 4)

**Headline finding for 1.5B scale:** TiDAR 1.5B achieves an average of **7.45 tokens per NFE** across coding and math tasks while maintaining or exceeding the quality of comparable-scale AR models on most benchmarks. On the coding-math average, TiDAR 1.5B scores **44.03%** compared to Qwen2.5 1.5B at 41.64% and the block diffusion baseline at 38.41% — meaning TiDAR simultaneously improves quality by ~2.4 percentage points while generating 7.45× more tokens per forward pass.

Breaking this down by task (Table 2):
- **HumanEval**: TiDAR 1.5B reaches **43.29%** vs. Qwen2.5 1.5B at 35.98% and Block Diffusion at 39.02%. The Qwen3 1.7B (a newer, stronger AR model) achieves 48.17%, showing that TiDAR's continual pretraining from the older Qwen2.5 checkpoint doesn't fully close the gap to the latest generation.
- **HumanEval+**: TiDAR achieves **39.02%** vs. Qwen2.5 1.5B at 29.88% — a substantial +9 percentage point improvement over its initialization checkpoint.
- **MBPP**: TiDAR scores **41.40%** vs. Qwen2.5 1.5B at 43.60% — a slight regression, though TiDAR achieves this with **9.25 tokens per NFE**.
- **MBPP+**: TiDAR scores **61.11%** vs. Qwen2.5 1.5B at 59.23% and Block Diffusion at 48.15%.
- **GSM8K**: TiDAR scores **53.90%** vs. Qwen2.5 1.5B at 54.74% — essentially tied, with TiDAR generating **5.07 tokens per NFE**.
- **Minerva Math**: TiDAR scores **25.48%** vs. Qwen2.5 1.5B at 26.40% — a small regression, with **7.92 tokens per NFE**.

The pattern here is noteworthy: TiDAR matches or slightly exceeds Qwen2.5 1.5B on coding tasks (HumanEval, HumanEval+, MBPP+) while roughly matching it on math tasks (GSM8K, Minerva Math), all while generating 5–9 tokens per forward pass. Compared to Block Diffusion under the same training recipe, TiDAR outperforms on every task: +4.27 points on HumanEval, +7.4 points on MBPP, +12.96 points on MBPP+, and +0.91 points on GSM8K (though -3.92 on Minerva Math). This demonstrates that the dual-mode self-speculative mechanism provides quality benefits beyond what block-causal diffusion alone achieves.

**Headline finding for 8B scale:** TiDAR 8B achieves an average of **8.23–8.25 tokens per NFE** with minimal quality loss compared to Qwen3 8B. Under the "Trust Diffusion" configuration, TiDAR 8B scores **65.31%** on the coding-math average vs. Qwen3 8B at 68.09% — a gap of only 2.78 percentage points, while delivering 8.25× more tokens per forward pass. Under "Trust AR," the gap is slightly larger (63.90%, a 4.19-point gap).

By task (Table 2, TiDAR 8B "Trust Diffusion"):
- **HumanEval**: **57.93%** vs. Qwen3 8B at 64.63% (gap: -6.7 points) but superior to Dream 7B at 54.88% and LLaDA 8B at 32.32%.
- **HumanEval+**: **55.49%** vs. Qwen3 8B at 56.71% (gap: -1.22 points).
- **MBPP**: **65.40%** vs. Qwen3 8B at 69.40% (gap: -4.0 points).
- **MBPP+**: **80.95%** vs. Qwen3 8B at 83.07% (gap: -2.12 points).
- **GSM8K**: **80.44%** vs. Qwen3 8B at 81.80% (gap: -1.36 points).
- **Minerva Math**: **51.64%** vs. Qwen3 8B at 52.94% (gap: -1.30 points).

The quality gaps on math tasks (GSM8K, Minerva Math) are notably smaller than on coding tasks (HumanEval, MBPP), with the gap narrowing to ~1–2 percentage points. This is consistent with the observation that "for larger models, trusting the predictions from diffusion predictions is beneficial in most cases, especially for math tasks" (Section 4.2.1).

Crucially, TiDAR 8B substantially outperforms all diffusion baselines at comparable scale: Dream 7B (58.74% average) by ~6.6 points, LLaDA 8B (41.78%) by ~23.5 points, and the authors' own Block Diffusion 4B (60.27%) by ~5 points — despite the Block Diffusion baseline using more parameters (4B starting from Qwen3 4B vs. TiDAR's 8B starting from Qwen3 8B).

**The "Trust AR" vs. "Trust Diffusion" divergence by scale:** For the 1.5B model, the paper reports only a single TiDAR entry (presumably using mixed logits or selecting the better configuration per task). For the 8B model, "Trust Diffusion" outperforms "Trust AR" on every task: +2.44 points on HumanEval, +3.06 on HumanEval+, +0.0 on MBPP (tied), +1.32 on MBPP+, +0.61 on GSM8K, +1.06 on Minerva Math. This is a non-trivial and non-obvious finding: at larger scales, the diffusion predictions (which benefit from bidirectional coordination within the draft block) become more reliable than the purely causal AR predictions for verification purposes. The paper attributes this to the full-mask training producing strong diffusion representations at scale, but does not investigate why the effect is more pronounced at 8B than 1.5B.

#### Throughput Benchmarking: Wall-Clock Speedup (Figure 4)

**Headline finding:** TiDAR 1.5B achieves an average of **4.71× relative throughput speedup** over Qwen2.5 1.5B AR decoding, and TiDAR 8B achieves an average of **5.91× relative throughput speedup** over Qwen3 8B AR decoding, measured in tokens per wall-clock second on an H100 with batch size 1.

Figure 4 plots task score (y-axis) against relative AR throughput speedup (x-axis) for each evaluated task. The key comparisons:

**1.5B scale (Figure 4, left group of six subplots):**
- TiDAR (three block sizes: 4, 8, 16) occupies the upper-right region of all subplots, achieving both higher scores and higher throughput than Block Diffusion with thresholds max and 0.8.
- On HumanEval, TiDAR block size 4 achieves ~38.4% at 3.47× speedup; block size 8 achieves ~39.9% at 5.51×; block size 16 achieves ~41.2% at 6.50×. The Pareto frontier clearly shows TiDAR dominating Block Diffusion: at any given throughput, TiDAR achieves higher accuracy; at any given accuracy, TiDAR achieves higher throughput.
- On GSM8K, TiDAR block size 4 achieves ~55.9% at 3.23× speedup; block size 8 achieves ~54.7% at 4.61×; block size 16 achieves ~53.9% at 5.07× — a slight quality decline with larger block sizes (visible as the points sloping downward from left to right).
- The average subplot (bottom-left of the 1.5B group) shows TiDAR block size 16 at 6.50× speedup with 44.03% average score vs. Qwen2.5 1.5B base at 1.0× speedup with 41.64% — simultaneously faster AND better.

**8B scale (Figure 4, right group):**
- TiDAR 8B block size 16 (only configuration tested at this scale) achieves 7.30–10.13× relative speedup depending on the task, with average speedup of 8.25× (matching the average T/NFE in Table 2).
- Comparing against EAGLE-3 (two public weight variants: AngelSlim and Tengyunw, both on Qwen3 8B Instruct):
  - On HumanEval, TiDAR scores ~57.9% at 7.30× speedup vs. EAGLE-3 AngelSlim at ~3.6× and Tengyunw at ~4.5×. TiDAR simultaneously achieves higher accuracy (the Qwen3 8B Instruct baseline is ~60.5% vs. TiDAR's 57.9%) AND higher throughput than both EAGLE-3 variants.
  - On MBPP, TiDAR scores ~65.4% at 10.0× speedup vs. EAGLE-3 AngelSlim at ~3.5× and Tengyunw at ~4.3×.
  - On GSM8K, TiDAR scores ~80.4% at 7.1× speedup vs. EAGLE-3 AngelSlim at ~3.3× and Tengyunw at ~4.2×.
- The critical observation is that EAGLE-3's throughput is lower despite being the state-of-the-art speculative decoding method, because (as the paper argues) its drafting process is autoregressive and sequential to verification, meaning it cannot exploit the "free token slots" as effectively. TiDAR's parallel drafting and single-forward verification eliminate this sequential bottleneck.
- The paper explicitly notes that TiDAR's raw acceptance rate (T/NFE) is higher than EAGLE-3's: "our raw acceptance rate (T/NFE) is higher than those of EAGLE-3 open weights, and more importantly, our conversion rate (from T/NFE to T/s) is higher, thanks to the parallel drafting and sampling with a single model forward" (Section 4.3). The "conversion rate" refers to how efficiently tokens-per-NFE translates to tokens-per-second — a higher conversion rate means less overhead per forward pass.

**Block Diffusion comparison detail:** Block Diffusion is tested with two threshold settings (max and 0.8) that trade off quality and efficiency. The "max" threshold is more conservative (fewer tokens per NFE, higher quality); 0.8 is more aggressive. Even the conservative setting (leftmost Block Diffusion point in each subplot of Figure 4) is dominated by TiDAR — TiDAR achieves higher accuracy at equivalent or higher throughput. This is strong evidence that the dual-mode self-speculation provides benefits beyond what block-parallel diffusion decoding alone can achieve.

#### Likelihood Evaluation Results (Table 3)

**Headline finding:** TiDAR supports efficient AR-style likelihood evaluation (single NFE, no Monte Carlo sampling) that is competitive with or superior to same-scale AR models, while diffusion models like LLaDA and Dream require expensive Monte Carlo estimation (128 steps) and still underperform.

On the knowledge and reasoning average (MMLU + ARC-Easy + ARC-Challenge + HellaSwag + PIQA + Winogrande):
- **TiDAR 1.5B: 64.43%** vs. Qwen2.5 1.5B at 65.16% (gap: -0.73 points) vs. Block Diffusion 1.5B at 61.05%. TiDAR essentially matches its AR initialization checkpoint in likelihood evaluation quality, despite being trained with a hybrid objective that dedicates half the loss weight to diffusion.
- **TiDAR 8B: 75.40%** vs. Qwen3 8B at 74.25% (TiDAR is +1.15 points HIGHER). This is notable: TiDAR slightly surpasses the base Qwen3 8B on likelihood tasks, suggesting the additional 150B tokens of continual pretraining (even with the diffusion objective mixed in) provides a net benefit on knowledge-intensive benchmarks.

By task category:
- **Factual knowledge (MMLU):** TiDAR 8B scores **76.57%** vs. Qwen3 8B at 76.93% — essentially identical. TiDAR 1.5B scores **58.99%** vs. Qwen2.5 1.5B at 60.96% — a slight regression. Block Diffusion 1.5B scores 57.94%, showing both hybrid models lose ~2–3 points on MMLU relative to the AR initialization.
- **Commonsense reasoning:** TiDAR 8B outperforms Qwen3 8B on ARC-Easy (84.18% vs. 81.90%), HellaSwag (76.36% vs. 78.59%), PIQA (80.25% vs. 79.22%), and Winogrande (76.48% vs. 75.69%), yielding a higher average in this category. TiDAR 1.5B shows mixed results: better on ARC-Easy (77.78% vs. 75.17%) and PIQA (75.52% vs. 76.12%), worse on HellaSwag (65.26% vs. 67.90%) and Winogrande (63.61% vs. 65.75%).

**Comparison with diffusion model likelihood evaluation:** LLaDA 8B (68.06% average using MC with 128 steps) and Dream 7B (71.86%) both underperform TiDAR 8B (75.40%) despite being evaluated with expensive Monte Carlo procedures. Block Diffusion 4B scores 70.00%, also below TiDAR 8B. This is important because it demonstrates that TiDAR's hybrid architecture provides a practical advantage for likelihood-based tasks: single- forward AR-mode evaluation is both more efficient and, in this case, more accurate than diffusion-style MC estimation.

The paper emphasizes that likelihood evaluation for diffusion models "has been very challenging due to various ways of computing the likelihood" and that "directly comparing models using this metric still remains a subject of debate" (Section 4.2.2). TiDAR's ability to use standard AR likelihood computation eliminates this ambiguity.

### Ablation Studies and Robustness Checks

**Pareto frontier under the same training recipe (Figure 5):** All models are trained from Qwen2.5 1.5B with 50B tokens under identical optimization settings. TiDAR variants (block sizes 4, 8, 16, all with full masking) form a clear Pareto frontier that dominates Block Diffusion under multiple decoding thresholds and the baseline AR model. Across all six tasks (HumanEval, HumanEval+, MBPP, MBPP+, GSM8K, average), the TiDAR points lie strictly above and to the right of the Block Diffusion points — meaning at any given T/NFE, TiDAR achieves higher accuracy, and at any given accuracy, TiDAR achieves higher T/NFE. Block size 16 achieves the highest T/NFE (6.97 average) with competitive quality, while block size 4 achieves the highest quality (e.g., ~48.4% average) with moderate T/NFE (3.47). The "AR FT" (fine-tuned AR) point achieves the highest quality overall (~50% average) but at 1.0 T/NFE — establishing an upper bound on quality that TiDAR is approaching with 7× higher throughput. One random-mask TiDAR variant (labeled "Ours Random Mask") is included and consistently underperforms the full-mask variants at similar T/NFE, confirming the full-mask advantage.

**Comparing TiDAR with other decoding strategies (Table 4):** This ablation evaluates alternative decoding approaches applied to the full-mask TiDAR model, comparing them against TiDAR's native self-speculative procedure. The tested alternatives are: (a) **Confidence-based decoding** with thresholds from max (most conservative, T/NFE=1.0) down to 0.6 (most aggressive, T/NFE=3.81) — this is the standard diffusion decoding paradigm where tokens are accepted if the model's confidence exceeds a threshold. (b) **Left-to-right AR decoding** within the diffusion block (generating one token at a time from the bidirectional context). The results show that TiDAR's self-speculative procedure (4, 8, or 16 drafts) dominates all alternatives. At block size 4, TiDAR achieves 38.42% HumanEval average, 50.96% MBPP average, and 55.87% GSM8K with 3.47 T/NFE — compared to confidence-based decoding at 3.42 T/NFE (threshold > 0.7) which achieves only 27.74% HumanEval average, 33.90% MBPP average, and 43.44% GSM8K. The quality gap is enormous at similar T/NFE: +10.68 points on HumanEval, +17.06 points on MBPP, +12.43 points on GSM8K. This demonstrates that the autoregressive rejection sampling in TiDAR's self-speculative loop — not just the parallel generation capability — is the essential quality-preserving mechanism. Confidence-based decoding, which accepts draft tokens based solely on the model's own confidence without any verification against a causal distribution, degrades severely at higher T/NFE. Similarly, left-to-right AR decoding within the block maintains quality at 1.0 T/NFE but degrades sharply at 2.0 T/NFE (HumanEval drops from 36.28% to 21.95%), because the bidirectional context provides weaker sequential dependencies than full causal conditioning.

**Trusting AR vs. diffusion outputs for sampling (Figure 6):** The paper sweeps the mixing weight β (0 to 1, where 0 = trust diffusion completely, 1 = trust AR completely) across three different training loss balancing factors α (corresponding to AR:Diff weight ratios of 0.8:1.0, 1.0:1.0, and 1.2:1.0). The average score across all tasks is essentially flat across the full β range for all three α values, varying by less than ~2 percentage points total. This demonstrates that **(a)** the model's AR and diffusion predictions are sufficiently aligned that the choice of which to use for verification doesn't matter — the rejection sampling outcome is robust; **(b)** the training loss balancing is also robust across a range of α values; and **(c)** the quality guarantee comes from the rejection sampling mechanism itself, not from a particular logit source. This is a strongly positive result: it means TiDAR requires no tuning of β or α at inference time, and the training recipe is forgiving of the exact loss weighting.

**Full-mask vs. random-mask training (Table 5):** The full-mask strategy is compared against random-mask training at block sizes 4 and 8 on the 1.5B model. At block size 4: full masking achieves 38.42% HumanEval average, 50.96% MBPP average, 55.87% GSM8K, and 48.42% overall average with 3.47 T/NFE. Random masking achieves 32.62%, 48.63%, 55.11%, and 45.45% respectively with 3.42 T/NFE. The full-mask improvement is +5.8 points on HumanEval average, +2.33 on MBPP, +0.76 on GSM8K, and +2.97 on the overall average — all with slightly higher T/NFE (3.47 vs. 3.42). At block size 8, the gap widens: full masking achieves 39.94% HumanEval average, 52.13% MBPP average, 54.74% GSM8K, 48.94% overall with 5.49 T/NFE, vs. random masking at 33.85%, 48.77%, 54.43%, 45.68% with 5.22 T/NFE. The full-mask advantage is +6.09 on HumanEval, +3.36 on MBPP, +0.31 on GSM8K, and +3.26 overall — AND it achieves slightly higher T/NFE. This confirms that train-test consistency and denser diffusion signals are first-order effects, particularly for coding tasks where token interdependence is high. The fact that GSM8K shows the smallest improvement (+0.31–0.76 points) may reflect that math reasoning benefits less from within-block bidirectional coordination than code generation does.

### Critical Assessment

**Claim 1: "TiDAR can achieve lossless quality compared to its AR counterpart while generating with 4.71× relative throughput speedup" (1.5B) and "5.91× relative throughput speedup with minimal loss" (8B).**

This claim requires careful parsing. For the 1.5B model, the paper compares TiDAR against Qwen2.5 1.5B and shows that TiDAR achieves higher scores on some tasks (HumanEval: 43.29% vs. 35.98%; HumanEval+: 39.02% vs. 29.88%) while slightly lower on others (MBPP: 41.40% vs. 43.60%; GSM8K: 53.90% vs. 54.74%). The coding-math average is 44.03% vs. 41.64%, so TiDAR is indeed slightly better on average. However, "lossless" is a strong claim — it implies that no task shows degradation beyond noise, but MBPP and Minerva Math do show small regressions (though they may be within sampling error given the test set sizes). More importantly, the comparison is against Qwen2.5 1.5B, not against the contemporaneous Qwen3 1.7B (which scores 52.22% average, roughly +8 points above TiDAR), nor against a version of Qwen2.5 1.5B that received the same 50B tokens of additional training in pure AR mode (the "AR FT" point in Figure 5, which scores ~50% average at 1.0 T/NFE). The fairer comparison for assessing whether the hybrid architecture is "lossless" relative to AR would be: given the same training budget, does TiDAR match a fine-tuned AR model's quality? Figure 5 shows that TiDAR block size 4 reaches ~48.4% average at 3.47 T/NFE, while AR FT reaches ~50% at 1.0 T/NFE — a quality gap of ~1.6 points remains, with TiDAR making different speed-quality trade-offs depending on block size. So "lossless" is true when comparing against the base (non-fine-tuned) AR checkpoint, but not when comparing against an AR model given the same additional training compute.

For the 8B model, the claim is explicitly qualified as "with minimal loss." The coding-math average gap is 2.78 percentage points under Trust Diffusion (65.31% vs. 68.09%) and 4.19 points under Trust AR (63.90% vs. 68.09%). The math gap is small (1.3–1.4 points on GSM8K, Minerva Math), but the coding gap is larger (6.7 points on HumanEval, 4.0 points on MBPP). Whether this qualifies as "minimal" depends on the application — for production code generation, a 6.7-point drop on HumanEval may be unacceptable regardless of throughput. The paper does not report whether these gaps shrink with more training data, leaving open the possibility that TiDAR requires more tokens than 150B to fully close the AR quality gap at scale.

**Claim 2: "TiDAR outperforms speculative decoding in measured throughput."**

This claim is supported by Figure 4, but with important caveats. First, the comparison is against EAGLE-3 on Qwen3 8B Instruct, while TiDAR 8B is a base model. The paper acknowledges this is because EAGLE-3 weights for the base model were unavailable. An instruct model has different output characteristics than a base model, which could affect both quality scores and acceptance rates. Second, the quality scores being compared are between TiDAR base and EAGLE-3 on an instruct model — these aren't the same evaluation target, so the throughput-quality comparison mixes architectural differences with model version differences. A fairer comparison would train EAGLE-3 on the same base model or train TiDAR as an instruct variant. Third, EAGLE-3 is a method applied to an existing model without modifying its weights (beyond the draft heads), while TiDAR requires continual pretraining of the entire base model — these have different deployment constraints. Organizations with an existing deployed AR model may prefer EAGLE-3's plug-and-play nature even if TiDAR's throughput is higher.

That said, the throughput advantage is substantial and well-measured: TiDAR's 7.3–10.1× speedup range (task-dependent) vs. EAGLE-3's 3.3–4.5× range represents a ~2× throughput improvement over the state-of-the-art speculative decoding method. The paper correctly identifies the mechanism: TiDAR's parallel diffusion drafting eliminates the sequential AR draft bottleneck that limits EAGLE-3. This is a genuine architectural advantage, not an artifact of benchmarking choices.

**Claim 3: "TiDAR is the first architecture to close the quality gap with AR models while delivering 4.71× to 5.91× more tokens per second."**

This is the paper's headline claim and requires the most scrutiny. The evidence supports that TiDAR narrows the AR quality gap substantially compared to prior diffusion models — Dream and LLaDA trail TiDAR significantly on both quality and throughput. But "close the quality gap" implies near-parity, and the data shows a residual gap at 8B scale (1.3–6.7 points depending on task), and a comparison against a weaker AR baseline at 1.5B scale (Qwen2.5 rather than Qwen3 or fine-tuned). The claim would be stronger with: (a) a fine-tuned AR baseline given the same training data budget; (b) explicit reporting of whether additional training data reduces the quality gap (the paper uses 50B/150B tokens — would 300B close the coding gap at 8B?); and (c) evaluation on a broader set of tasks beyond coding and math (the likelihood tasks in Table 3 show TiDAR 8B slightly surpassing Qwen3 8B, but these are evaluated differently — TiDAR uses AR mode, diffusion models use MC — making direct comparison to pre-existing diffusion baselines difficult).

**Weaknesses in the experimental design:**

- **No confidence intervals or variance estimates.** All reported scores are point estimates. The test sets vary in size (HumanEval: 164 problems, MBPP: 500, GSM8K: 1,319), meaning a difference of a few percentage points on HumanEval could be within sampling noise. The throughput measurements presumably are from single runs with no reported variance. This makes it impossible to assess whether the small quality regressions (e.g., TiDAR 8B vs. Qwen3 8B on MBPP: 65.40% vs. 69.40%) are statistically significant.

- **Missing AR fine-tuning baseline in the main comparison tables.** Table 2 compares TiDAR against vanilla AR models but not against AR models fine-tuned on the same 50B/150B token budget. The AR FT baseline appears only in the Pareto frontier figure (Figure 5) at 1.5B scale. At 8B scale, there is no AR FT comparison at all. This makes it impossible to determine whether TiDAR's quality comes from the hybrid architecture or simply from the additional training data.

- **EAGLE-3 comparison uses different model variants.** TiDAR 8B is a base model; EAGLE-3 uses Qwen3 8B Instruct. The instruct model may have different output distributions, calibration, and generation characteristics that affect both quality scores and acceptance rates of speculative decoding.

- **Single GPU, single batch size.** All throughput benchmarking is on a single H100 with batch size 1. This is the most favorable setting for TiDAR's "free token slots" argument (the memory-bound regime is widest at batch size 1). At higher batch sizes, the memory-bound regime shrinks, and the advantage of additional token slots may diminish. The paper acknowledges this limitation (Section 5) but does not provide measurements at larger batch sizes to quantify the degradation.

- **No long-context evaluation.** All evaluations use standard context lengths appropriate to each benchmark (max 512 generation tokens per Table 6). TiDAR's sequence-doubling during training (clean sequence + appended mask sequence) means the effective context window is halved relative to the model's native max sequence length of 4096. The paper acknowledges this limitation (Section 5) and defers long-context extension to future work. For applications requiring long context (document QA, multi-turn conversation), this is a significant practical constraint that is not evaluated.

- **Training data composition not specified.** The paper states "continually pretrain with 50B tokens" and "150B tokens" but does not describe the data mixture. If the training data overlaps with evaluation benchmarks, the quality improvements could be partially attributable to data memorization rather than architectural benefits. The use of standard benchmarks and `lm_eval_harness` mitigates this concern somewhat, but the lack of data documentation is a reproducibility gap.

- **No human evaluation or qualitative analysis of outputs.** All quality metrics are automated (pass@1, strict-match, accuracy). There is no qualitative analysis of TiDAR-generated text to assess whether the hybrid architecture introduces subtle coherence issues, repetitiveness, or other artifacts that automated metrics might miss. The paper acknowledges that "the metrics are much more robust" for coding and math tasks, implicitly recognizing that automated metrics for open-ended generation might reveal quality differences that coding/math benchmarks don't capture.

**Experiments that would have strengthened the paper:**

1. **Scaling the training data.** The paper uses fixed token budgets (50B for 1.5B, 150B for 8B). Training curves showing quality and acceptance rate as a function of data volume would reveal whether TiDAR's quality gap from AR continues shrinking with more data, or plateaus at some level.

2. **Instruct model training.** TiDAR is evaluated as a base model. Training and evaluating an instruct/chat variant would demonstrate whether the dual-mode architecture works in the conversational setting where most production throughput concerns arise.

3. **Batch size > 1 throughput measurements.** Quantifying how the relative speedup changes as batch size increases would help practitioners understand the deployment scenarios where TiDAR's advantages are largest (latency-constrained single queries) versus where they diminish (throughput-constrained batch processing).

4. **Ablation on draft block size at inference time, independent of training block size.** The paper trains with a fixed block size and uses the same block size during inference. It's unclear whether inference-time block size can be varied independently (e.g., train with block size 16, decode with block size 8 or 4) and whether that changes the quality-throughput trade-off. This flexibility would be practically valuable (adjusting speed based on load) and is claimed in Section 5 ("adjust the block (draft) length during decoding in a zero-shot manner") but not demonstrated.

5. **Head-to-head with more speculative decoding variants.** Beyond EAGLE-3, comparing against Medusa (which also uses parallel draft heads but simpler than EAGLE) and against standard draft-model speculative decoding (using a smaller Qwen model as drafter) would provide a more complete picture of where TiDAR stands relative to the speculative decoding design space.

6. **Ablation on the causal-vs-bidirectional split within the draft block.** What happens if the draft tokens also use bidirectional attention (not just the mask tokens)? This would sacrifice exact KV caching for draft tokens but might improve acceptance rates by enabling within-step coordination between the verification and drafting predictions. Understanding this trade-off would illuminate whether the causal constraint on draft positions is load-bearing for quality or primarily for caching convenience.

## 6. Limitations and Trade-offs

### Difficulty Estimation Cost: The Unaccounted Budget

**The assumption or constraint.** TiDAR's self-speculative generation loop requires the model to draft and verify tokens simultaneously in a single forward pass, but it does not require explicit difficulty estimation per-prompt — unlike the adaptive compute-optimal test-time scaling in the reference paper, TiDAR uses a fixed block size for all prompts regardless of difficulty. However, TiDAR inherits a different unaccounted cost: **the training data required to achieve competitive quality**. The paper's headline results (4.71× to 5.91× throughput speedup) compare TiDAR models continually pretrained on 50B–150B tokens against a base AR model that did NOT receive this additional training. The paper acknowledges that the base AR checkpoint is not fine-tuned on the same data budget, and the "AR FT" baseline (fine-tuned AR model on 50B tokens) appears only in Figure 5 for the 1.5B model, not in the main comparison tables. At 8B scale, there is no AR FT baseline at all.

**The consequence.** The throughput advantage is computed relative to a weaker baseline than what practitioners would face. A practitioner deciding whether to adopt TiDAR must compare against the best available AR model within their training budget. If the additional 150B tokens of training were instead spent on pure AR fine-tuning, how much of the quality gap would close? Figure 5 suggests that at 1.5B scale, AR FT achieves ~50% average score at 1.0 T/NFE versus TiDAR block size 4 at ~48.4% average at 3.47 T/NFE — so the "lossless" claim only holds relative to the base (non-fine-tuned) AR checkpoint, not relative to an AR model given the same training compute. The 8B comparison would likely show a similar pattern, but no data exists. This makes it impossible to isolate how much of TiDAR's quality comes from the hybrid architecture versus simply from seeing more training tokens, and whether those tokens would have been better spent on pure AR training if throughput were standardized.

**What evidence exists in the paper.** Figure 5 provides the AR FT baseline for 1.5B, showing a ~1.6 percentage point remaining quality gap. Table 2 compares TiDAR 8B only against the base Qwen3 8B (no fine-tuning baseline). Section 4.1 states the training token budgets (50B for 1.5B, 150B for 8B) but does not compare against equivalently fine-tuned AR models in the main results. Section 5 acknowledges "the remaining quality gap from the fine-tuned AR models, which we believe could be potentially closed with more data due to the fact that TiDAR might require a bit more knowledge due to the initial adaptation phase" — suggesting the architecture itself may require MORE training data than AR to reach the same quality, which would partially offset the throughput advantage when training cost is accounted for.

**Mitigation status.** The paper acknowledges this limitation in the Pareto frontier analysis (Section 4.4.1) but does not include AR FT baselines in the headline comparison tables or at 8B scale. No analysis of how the quality gap scales with additional training data is provided. The suggestion that "more data" could close the gap is speculation without empirical support.

---

### Batch Size 1 as the Only Evaluated Regime

**The assumption or constraint.** All throughput benchmarking in the paper is conducted at **batch size 1** on a single NVIDIA H100 GPU. The central design argument — the "free token slots" concept in Figure 1 — depends on the model operating in the **memory-bound regime**, where latency is dominated by loading model weights and KV cache from HBM rather than by computation. The paper explicitly states this regime is widest at small batch sizes: "Decoding in AR models is memory-bound because the latency is dominated by loading the model weights and KV cache rather than compute." At larger batch sizes, the workload transitions to **compute-bound**, where adding extra tokens to a forward pass incurs proportional latency costs, potentially eroding or eliminating TiDAR's throughput advantage.

**The consequence.** The 4.71× to 5.91× speedup figures are valid only for single-query latency-critical scenarios (e.g., interactive chat with one user per GPU). In high-throughput batch inference settings — where many queries are processed simultaneously to maximize hardware utilization — the speedup may degrade substantially or vanish. This is a critical distinction for practitioners: TiDAR is optimized for **latency-constrained deployment** (where you want the fastest possible response for a single prompt) but its advantage for **throughput-constrained deployment** (where you want to maximize total queries per dollar) is unmeasured and likely smaller. The paper does not provide FLOPs-per-token measurements (which would be batch-size-independent), making it impossible to assess whether TiDAR's architectural overhead is justified when GPU compute, rather than memory bandwidth, is the bottleneck.

**What evidence exists in the paper.** Figure 1 characterizes the memory-bound regime only at batch size 1 for different prefix lengths (1024, 2048, 4096 tokens). Section 5 acknowledges this limitation: "Although we focus on batch size = 1 efficiency benchmarking, it does not mean that TiDAR cannot handle large batch size. Not only can we adjust the block (draft) length during decoding in a zero-shot manner to accommodate different compute profile, but also can achieve competitive performance in terms of FLOPs / token." However, no throughput measurements at larger batch sizes are provided, and the claim of "competitive FLOPs/token" is not empirically supported. The suggestion that block size can be reduced is plausible (shorter drafts = fewer "free tokens" needed = more tolerant of compute-bound conditions) but untested.

**Mitigation status.** Partially acknowledged but not empirically addressed. The paper provides no batch size > 1 results, no FLOPs-per-token analysis, and no demonstration of block-size adjustment in response to compute profile. A practitioner evaluating TiDAR for a high-throughput serving scenario would need to conduct their own benchmarking.

---

### Single Model Family and Single Training Paradigm (Continual Pretraining Only)

**The assumption or constraint.** All TiDAR experiments use the Qwen2.5 and Qwen3 model families, initialized via **continual pretraining** from AR checkpoints. The paper states in Section 4.1: "In this paper, we focus on the setting of continual pretraining from AR models." This means TiDAR's demonstrated performance depends on: (a) initializing from a strong AR model with well-developed causal language modeling capabilities, (b) adding the diffusion capability via a relatively modest amount of additional training (50B–150B tokens), and (c) the specific Qwen architecture (standard decoder-only transformer). The paper does not evaluate TiDAR when trained from scratch, when initialized from a different model family (e.g., Llama, Gemma), or when applied to non-decoder architectures (encoder-decoder, mixture-of-experts).

**The consequence.** It is unclear whether TiDAR's self-speculation works because of the specific properties of Qwen models (their pretraining data distribution, their tokenizer, their architectural choices) or whether it generalizes as a technique. The self-speculative quality guarantee depends on the AR and diffusion predictions being tightly aligned (as demonstrated in Figure 6). If a different model family has different calibration properties, different in-context learning behavior, or different representation geometry, the AR-diffusion agreement might be weaker, leading to lower acceptance rates and reduced throughput. Furthermore, training TiDAR from scratch (without a strong AR initialization) might require substantially more data to achieve the same AR-diffusion alignment, since the model must simultaneously learn causal language modeling AND diffusion denoising from a random initialization. The continual pretraining setup means TiDAR is essentially "piggybacking" on the AR model's pretrained quality — it's adding a new capability to an already-competent model rather than building competence from scratch. This makes the training efficiency claims (50B–150B tokens) misleading in the context of building a TiDAR model from scratch, which would require full pretraining budgets (trillions of tokens).

**What evidence exists in the paper.** No ablation across model families, architectures, or training from scratch. All results in Tables 2 and 3 and Figures 4 and 5 use Qwen2.5 or Qwen3 as the base model, initialized from pretrained checkpoints. The paper does not discuss whether the Qwen architecture has properties (e.g., particular attention head configurations, normalization placements, or activation functions) that make it especially well-suited or poorly-suited for the hybrid attention mask. The block sizes tested (4, 8, 16) are evaluated only for Qwen2.5 1.5B; for Qwen3 8B, only block size 16 is tested.

**Mitigation status.** Not acknowledged as a limitation. The paper claims TiDAR "can be initialized from any standard AR transformer" architecturally (the hybrid attention mask is a sequence-level modification, not a model architecture change), but this claim is not empirically validated.

---

### Context Length Halved by Sequence Doubling

**The assumption or constraint.** TiDAR's training doubles the sequence length: each training sample concatenates the clean input sequence (length $S$) with the fully-masked diffusion sequence (also length $S$), for a total length of $2S$. The paper trains with a max sequence length of 4096 tokens (Section 4.1). This means the **effective context window** for the AR prefix is effectively $4096 / 2 = 2048$ tokens after accounting for the appended mask tokens, since both sections must fit within the model's maximum sequence length. The paper evaluates on benchmarks with short contexts (MMLU: few-shot prompts; coding benchmarks: typically < 1K tokens; math: typically < 512 tokens) where this constraint is invisible, but acknowledges in Section 5: "our current implementation requires doubling the sequence length with appended mask tokens during training, we defer the exploration of efficient long context extension methods for future work."

**The consequence.** TiDAR as currently trained **cannot process long-context prompts** that standard AR models of the same base architecture can handle. A Qwen2.5 1.5B model with 32K native context (typical for this model size) can process prompts up to 32K tokens. TiDAR, trained with sequence doubling, would have its effective context halved to ~16K tokens if the training were extended to that length, but the paper only trains with max sequence length 4096. For applications requiring long documents, multi-turn conversation histories, or retrieval-augmented generation with many retrieved passages, this is a severe practical constraint. The paper does not measure long-context performance (e.g., on Needle-in-a-Haystack, LongBench, or any retrieval task), so it's unknown whether TiDAR's hybrid attention mask degrades long-range dependency modeling even within the available context window.

**What evidence exists in the paper.** Section 4.1 states max sequence length = 4096. All evaluated benchmarks (Appendix A, Table 6) use typical few-shot prompts and generation lengths (max 512 tokens), keeping total context well below 2048 tokens. There is no long-context evaluation. Section 5 explicitly states: "Since our current implementation requires doubling the sequence length with appended mask tokens during training, we defer the exploration of efficient long context extension methods (e.g. context parallelism specifically designed for TiDAR) for future work."

**Mitigation status.** Acknowledged but deferred. The paper suggests context parallelism as a future direction but provides no specifics. A practitioner deploying TiDAR for long-context applications would need to either: (a) train with a longer max sequence length (computationally expensive, since the attention cost scales quadratically and the effective context is half the trained length), (b) apply post-hoc context extension techniques (e.g., RoPE scaling, which may interact with the hybrid attention pattern in unknown ways), or (c) use TiDAR for short-context generation only and fall back to standard AR for long contexts. None of these are evaluated.

### No Explicit Quality Guarantee: Rejection Sampling Correctness Depends on an Unverified Equivalence

**The assumption or constraint.** TiDAR's quality guarantee rests on the standard speculative decoding rejection sampling procedure, which mathematically ensures that the output distribution is identical to sampling directly from the target (verifier) model's distribution — **if** the draft tokens are sampled from the correct draft distribution and the rejection step uses the correct target distribution. However, in TiDAR, neither condition holds exactly: (a) the draft tokens come from the **diffusion marginal distribution** $p_{\text{Diff}}$, not from an autoregressive draft model whose distribution can be analytically compared to the target; and (b) the verification can use a **mixture** of AR and diffusion logits (parameterized by $\beta$), which is neither the pure AR distribution nor the pure diffusion distribution. The paper argues this is fine because the AR and diffusion predictions align tightly (Figure 6), but **alignment is not equivalence**, and the speculative decoding guarantee requires exact distribution matching, not approximate alignment.

**The consequence.** TiDAR does NOT provide the same mathematical output-distribution guarantee as traditional speculative decoding. In standard speculative decoding (Leviathan et al., 2023; Chen et al., 2023), if the draft model produces token $x$ with probability $q(x)$ and the target model produces it with probability $p(x)$, the rejection sampling modifies the acceptance probability to ensure the final output distribution equals $p(x)$ exactly. This guarantee depends on knowing both $q(x)$ and $p(x)$ analytically. In TiDAR, the draft tokens come from the diffusion mode's prediction, which is a product of marginals (Equation 3 in Section 1), not a proper autoregressive sequence distribution. The verification may use blended logits (AR + diffusion). The rejection sampling procedure from speculative decoding assumes a valid pair of distributions $(q, p)$ over sequences — TiDAR's draft and verification distributions don't satisfy this theoretically, so the standard guarantee does not apply. Empirically, the quality is high (Figure 6 shows insensitivity to $\beta$, and Table 2 shows minimal quality loss), but there is **no theoretical worst-case bound** on how far the output distribution can deviate from the AR target distribution. A practitioner relying on the speculative decoding guarantee for safety-critical or distributionally-constrained generation (e.g., avoiding certain token sequences, maintaining calibration) cannot assume TiDAR provides equivalent safety properties.

**What evidence exists in the paper.** Figure 6 demonstrates empirical insensitivity to $\beta$ and $\alpha$ on the average score, which suggests the distributions are well-aligned in practice for the evaluated benchmarks. However, this is an average-case result on specific tasks — it does not guarantee alignment for every prompt, every token position, or every output distribution property (e.g., tail behavior, calibration). The paper does not measure distributional divergence metrics (e.g., KL divergence between TiDAR's output distribution and the AR model's output distribution, perplexity of TiDAR-generated text under the AR model, or sequence-level acceptance rates). The paper does not discuss the theoretical validity of applying rejection sampling to diffusion-generated draft sequences.

**Mitigation status.** Not acknowledged. The paper treats the empirical alignment in Figure 6 as sufficient evidence that the self-speculative procedure works, without addressing the theoretical gap. The fact that the method is called "self-speculative" and uses rejection sampling terminology suggests an analogy to speculative decoding, but the paper does not claim the formal guarantee. A practitioner who needs distributional guarantees would need to either (a) accept the empirical evidence as sufficient for their use case, or (b) conduct their own distributional analysis on their target data distribution.

### No Dynamic Block Size: Fixed Draft Length Independent of Prompt Difficulty

**The assumption or constraint.** TiDAR uses a **fixed draft block size** for all prompts during inference — the block size is set at training time (4, 8, or 16) and applied uniformly to every generation step regardless of the content being generated. This contrasts sharply with both speculative decoding (where draft length can be dynamically adjusted) and diffusion models (where entropy-based or confidence-based strategies select how many tokens to commit per step). The paper states that "TiDAR has no hyperparameters to tune during inference" and presents this as a strength, but it also means there is **no mechanism to allocate drafting effort based on token difficulty**. Some tokens are nearly deterministic given context (e.g., function keywords after a known API prefix); others require complex reasoning (e.g., the first token of a mathematical solution step). TiDAR drafts a fixed-length block for all of them.

**The consequence.** TiDAR leaves efficiency on the table compared to adaptive strategies. When generating predictable content (e.g., boilerplate code, common phrases), TiDAR's fixed block size may under-exploit the available free token slots — it could draft more tokens per step without significant rejection risk. When generating unpredictable content (e.g., the first token after a reasoning gap), TiDAR may over-exploit the block, drafting tokens that are frequently rejected, wasting compute in the mask-token section of the forward pass. The paper reports average tokens per NFE (7.45 for 1.5B, 8.25 for 8B with block sizes of 4–16), but this is an average across all tokens and all prompts. A difficulty-conditioned block size — smaller blocks at high-entropy positions, larger blocks at low-entropy positions — could increase the effective T/NFE without quality degradation, or improve quality at the same T/NFE by avoiding over-aggressive drafting at fragile positions.

The Tables 2 and Figure 5 comparison between block sizes shows the tension: larger block sizes achieve higher T/NFE (6.50 for block 16 vs. 3.47 for block 4 at 1.5B scale) but sometimes lower quality (e.g., GSM8K drops from 55.87% at block 4 to 53.90% at block 16). A dynamic strategy could potentially achieve block-16 T/NFE on predictable tokens and block-4 quality on unpredictable tokens, pushing the Pareto frontier further.

**What evidence exists in the paper.** Table 2 and Figure 5 show the fixed-block-size Pareto frontier across block sizes 4, 8, and 16. The paper does not evaluate any dynamic block sizing strategy. Section 5 mentions the possibility to "adjust the block (draft) length during decoding in a zero-shot manner to accommodate different compute profile" but this refers to changing the block size globally (e.g., reduce from 16 to 4 to save compute under load), not to dynamic per-token adjustment. No entropy or confidence measurements are reported to assess how much token-level variance exists in drafting difficulty for TiDAR.

**Mitigation status.** Not acknowledged as a limitation. The paper presents fixed block sizes as a feature (no hyperparameters), but does not discuss the potential efficiency gains from adaptive drafting. The Pareto frontier between block sizes (Figure 5) implicitly demonstrates the trade-off that dynamic adaptation could exploit, but the paper does not explore this direction.

## 7. Implications and Future Directions

### How This Work Changes the Landscape

TiDAR represents a **genuine conceptual reframing** of the relationship between autoregressive and diffusion language models, not merely an incremental improvement to either paradigm. Prior to this work, the field understood AR and diffusion as competing architectures with a fundamental trade-off: AR offers quality through chain-factorized joint distributions but suffers from memory-bound sequential decoding; diffusion offers parallelism through independent marginal predictions but degrades quality due to intra-step token independence. The implicit assumption was that you must choose one architectural philosophy and accept its characteristic limitation. TiDAR demonstrates that this dichotomy is false — the **two modes can coexist within a single model and a single forward pass**, with AR providing the quality guarantee through rejection sampling and diffusion providing the throughput through parallel drafting.

The shift this causes is best characterized as moving from an **either/or architecture decision** to a **both/and scheduling decision**. Prior work asked "should this model be AR or diffusion?" TiDAR replaces this with "how should this model allocate the free token slots in its forward pass between AR verification work and diffusion drafting work?" This transforms the design problem from model architecture selection to **within-forward-pass resource allocation**, which is a fundamentally different optimization landscape. It's analogous to the shift in computer architecture from "should this processor be in-order or out-of-order?" to modern designs where different execution units operate under different scheduling regimes within the same clock cycle.

The paper's most impactful methodological contribution is the **"free token slots" concept** (Section 1, Figure 1), which provides a measurable, hardware-grounded framing for inference efficiency that transcends any single architecture. Rather than reasoning about generation speed in terms of FLOPs-per-token or tokens-per-NFE in the abstract, the free-token-slots framing ties efficiency directly to the GPU's memory-bandwidth ceiling: as long as the total number of tokens in a forward pass remains in the flat latency region of the memory-bound regime, additional useful tokens cost near-zero wall-clock time. This is a **diagnostic tool** that applies to any architecture — speculative decoding, multi-token prediction, mixture-of-experts routing — and provides a unifying language for why some methods achieve real speedup (they use free slots for useful work) and others don't (their overhead pushes them into the compute-bound regime or introduces sequential dependencies that waste slots).

The work also **resolves a standing empirical tension** in the speculative decoding literature about whether drafter capacity or drafter parallelism is the binding constraint. EAGLE-3 and DeepSeek-V3 MTP argued that sharing the base model's hidden states with the drafter closes the capacity gap; TiDAR shows that even with shared hidden states, the **sequential nature of AR drafting** remains the bottleneck — the drafter still generates tokens one at a time, serially, preventing it from occupying the free token slots during the base model's forward pass. By replacing AR drafting with parallel one-step diffusion drafting, TiDAR demonstrates that **drafting parallelism is equally important as drafting capacity**, and that both must be addressed simultaneously to approach the hardware's theoretical throughput ceiling. Table 1 formalizes this insight across the speculative decoding design space, and Figure 4 provides the empirical evidence: TiDAR achieves ~2× the throughput of EAGLE-3 despite having comparable or higher raw acceptance rates, because its parallel drafting eliminates the sequential drafting bottleneck.

The paper also **redirects attention in the diffusion language model community** away from the quality-parallelism trade-off within the diffusion paradigm and toward **hybrid architectures that use diffusion strategically for drafting rather than for final output**. The strong negative result for confidence-based and left-to-right decoding strategies (Table 4) — where T/NFE of 3.42 achieves only 27.74% HumanEval average vs. TiDAR's 38.42% at T/NFE of 3.47 — demonstrates conclusively that parallel generation alone, without autoregressive verification, cannot match AR quality regardless of threshold tuning. This makes pure diffusion decoding less attractive as a standalone approach for quality-sensitive applications and shifts the research incentive toward hybrid verification-drafting schemes where diffusion provides the proposals but a causal mechanism provides the quality floor.

Finally, TiDAR's empirical finding that **AR and diffusion predictions can achieve near-parity in a well-trained dual-mode model** (Figure 6, showing negligible sensitivity to the mixing weight β from 0 to 1) is a **surprising result with theoretical implications**. It suggests that the gap between marginal and chain-factorized predictions — which is theoretically fundamental in the general case — can be made empirically negligible through sufficient training with an appropriate objective. This does not eliminate the theoretical gap, but it does suggest that for the purpose of speculative verification (where approximate alignment is sufficient), the practical barrier is training quality rather than architectural impossibility. This finding makes the self-speculative paradigm newly credible and invites theoretical investigation into the conditions under which marginal and conditional distributions converge in transformer models.

### Follow-Up Research This Work Enables

**Training TiDAR from scratch without AR initialization, measuring the data efficiency gap.** The paper's experiments all start from pretrained AR checkpoints (Qwen2.5/Qwen3), which means the model already possesses strong causal language modeling capabilities before TiDAR training begins. A critical open question is whether TiDAR's dual-mode alignment can be learned from random initialization, and if so, how much additional data is required compared to training a pure AR model of equivalent quality. A concrete experiment: train TiDAR from scratch with the Qwen2.5 1.5B architecture on a controlled data budget (e.g., 100B, 500B, 1T tokens) and measure both the AR quality (via standard benchmarks) and the AR-diffusion alignment (via the β-insensitivity curve of Figure 6) at each scale. Compare against a pure AR model trained on the same data. This would determine whether TiDAR is fundamentally a post-hoc modification to AR models (the "piggybacking" interpretation) or a viable standalone training paradigm. The result has direct implications for whether TiDAR can be applied to new model families without existing strong AR checkpoints.

**Dynamic block sizing guided by per-token diffusion entropy or AR-diffusion divergence.** The paper demonstrates that different fixed block sizes produce different points on the quality-throughput Pareto frontier (Figure 5, block sizes 4, 8, 16), with larger blocks achieving higher T/NFE but sometimes lower quality (e.g., GSM8K drops from 55.87% to 53.90% as block size increases from 4 to 16 at 1.5B scale). This suggests that some tokens are more amenable to aggressive drafting than others. A natural follow-up is to measure the **per-token entropy of the diffusion predictions** or the **per-token KL divergence between AR and diffusion distributions** during generation, and use these as signals to dynamically adjust the draft block size: at low-entropy/high-agreement positions, expand the block to draft more tokens; at high-entropy/low-agreement positions, contract it to minimize rejections. The key measurement would be whether dynamic sizing pushes the Pareto frontier beyond the envelope of fixed block sizes — achieving T/NFE comparable to block size 16 while maintaining quality comparable to block size 4. TiDAR's architecture already supports this because the diffusion predictions are available for "free" in the mask-token slots before drafting begins; the only missing component is the decision rule mapping prediction statistics to block sizes.

**Combining TiDAR's self-speculation with a separate, smaller draft model for tree-structured candidate expansion.** TiDAR drafts exactly one block of tokens per step and verifies them sequentially. Speculative decoding methods like EAGLE-3 and Medusa use **tree-structured verification** where multiple candidate continuations are drafted and verified in parallel, expanding the search space of possible sequences at each step. A hybrid approach could use TiDAR's diffusion mode to generate a primary draft block (high-quality proposals from the full model) and use a lightweight tree-expansion module (e.g., Medusa-style linear heads or a small AR model) to generate alternative branches from the same hidden states, all within the free token slots of a single forward pass. The experiment would measure whether tree-structured verification increases the effective acceptance rate (tokens per NFE) beyond TiDAR's single-path baseline, and whether the quality benefit of multiple candidate paths offsets the increased rejection complexity. This would directly test whether TiDAR's single-path drafting is optimal or whether multi-path exploration within the same forward-pass budget can push the Pareto frontier further.

**Measuring distributional divergence between TiDAR and the base AR model beyond task accuracy.** Figure 6 shows that the average task score is insensitive to the AR-diffusion mixing weight β, but this is a coarse metric that could mask distribution-level differences. A thorough distributional analysis would measure: (a) the **sequence-level KL divergence** between TiDAR's output distribution and the base AR model's output distribution on open-ended generation tasks (not just multiple-choice accuracy), (b) the **perplexity of TiDAR-generated text under the base AR model** compared to the base model's own generated text (a form of self-consistency check), (c) the **acceptance rate distribution** across different token types (function keywords vs. variable names vs. natural language vs. mathematical operators) to identify where AR-diffusion alignment is weakest, and (d) the **calibration curves** for both models on confidence-requiring tasks. This would address the theoretical gap in Section 6 regarding whether TiDAR's rejection sampling provides genuine distributional guarantees or merely empirical quality preservation on benchmark metrics. If substantial divergence is found in some regimes, it would motivate explicit distribution-matching regularization during training.

**Testing TiDAR on non-decoder architectures, especially encoder-decoder models for multilingual or long-context tasks.** The paper evaluates only on decoder-only transformers (Qwen family). The hybrid attention mask concept is architecture-agnostic in principle — any transformer can apply different attention patterns to different sequence regions — but its interaction with encoder-decoder architectures is unexplored. An encoder-decoder variant would process the input (source) through a full bidirectional encoder and apply the causal-bidirectional hybrid mask only in the decoder, potentially enabling TiDAR-style generation speedup for translation, summarization, and other conditional generation tasks where the encoder already handles bidirectional context. The experiment would measure whether the decoder-side diffusion drafting transfers effectively from the decoder-only setting, and whether the presence of cross-attention to the encoder changes the AR-diffusion alignment properties observed in Figure 6. This would expand TiDAR's applicability beyond the pure language modeling setting to the broader sequence-to-sequence paradigm.

**Verifier over-optimization as a lens on TiDAR's self-speculation: when does the diffusion mode "over-optimize" its predictions relative to AR?** The reference paper on compute-optimal test-time scaling identified verifier over-optimization as the primary bottleneck for PRM-guided search — more aggressive optimization of the verifier signal paradoxically degraded performance on easy problems because the verifier's errors were amplified. A parallel phenomenon may exist in TiDAR: the diffusion mode's bidirectional attention gives it strictly more context than the AR mode's causal attention for within-block predictions, potentially leading to **overconfident predictions** that look good to the diffusion mode (low entropy) but diverge from the AR distribution that will be used for verification, causing increased rejections. Measuring the calibration gap between diffusion and AR predictions as a function of block position (earlier tokens in the block have less left-context from the draft; later tokens have more bidirectional coordination) would reveal whether the alignment degrades at later positions and whether this imposes an effective upper bound on useful block size. This would connect TiDAR's design to the broader literature on reward hacking and verifier robustness, potentially motivating regularization strategies that prevent the diffusion mode from exploiting spurious bidirectional correlations that the AR mode cannot access during verification.

### Practical Applications and Downstream Use Cases

**Latency-critical coding assistants and interactive copilots.** The single most natural deployment scenario for TiDAR is in developer-facing coding tools where sub-second latency is non-negotiable and the model must generate syntactically coherent code completions. TiDAR 1.5B achieves 4.71× the throughput of Qwen2.5 1.5B while maintaining competitive pass@1 on HumanEval (43.29% vs. 35.98% for the base model, Table 2), meaning a user waiting for a code suggestion sees the result in roughly one-quarter the wall-clock time. For on-device or edge deployment of small models (1.5B parameters fitting in consumer GPU memory or even quantized on-device NPUs), TiDAR enables AR-quality code generation at throughputs that make interactive use feasible. The block size flexibility (train with block 4, 8, or 16, or adjust at inference time) provides a natural dial: under light load, use block 16 for maximum responsiveness; under heavier load, drop to block 4 to reduce per-query compute while still outperforming AR in throughput. The 8B model's strong performance on MBPP+ (80.95% at 10.13× throughput relative to Qwen3 8B, Table 2) suggests that even for server-side coding assistants where larger models are deployed, TiDAR can dramatically reduce the per-user GPU-seconds required.

**Real-time conversational AI with strict p50 latency targets.** In production chatbot systems, the p50 time-to-first-token and tokens-per-second for multi-turn responses directly determine user satisfaction. TiDAR's throughput advantage (5.91× for 8B, measured at batch size 1 on H100) translates to generating a typical chatbot response of 100 tokens in the time an AR model would take to generate ~17 tokens, assuming the response fits within the model's context window. For applications like customer support automation, voice assistant backends, or real-time translation, where the model must generate fluent responses with minimal perceived delay, TiDAR's ability to maintain AR-comparable quality (e.g., GSM8K at 80.44% vs. Qwen3 8B at 81.80%, a 1.36-point gap, Table 2) while generating 7+ tokens per NFE makes it a drop-in replacement that reduces GPU allocation per query by roughly the throughput ratio. The exact KV caching support means TiDAR integrates with existing paged-attention serving infrastructure (vLLM, TensorRT-LLM) without requiring custom cache management, lowering the engineering barrier to deployment compared to pure diffusion models.

**Batch generation for synthetic data pipelines and self-improvement loops.** When using LLMs to generate training data — for distillation, rejection sampling fine-tuning, or self-play — the primary metric is total high-quality tokens generated per dollar of GPU time. In this setting, throughput per token matters but batch size can be tuned to maximize hardware utilization. TiDAR's efficiency in the single-query regime at batch size 1 is well-demonstrated, but the "free token slots" advantage shrinks as batch size increases and the workload shifts toward compute-bound. However, even in the compute-bound regime, TiDAR's tokens-per-NFE advantage (7.45–8.25 average, Table 2) reduces the total number of forward passes required to generate a given volume of tokens, which directly reduces the FLOPs per token. A data generation pipeline that previously ran best-of-N sampling with an AR model could instead run TiDAR at the same per-token FLOPs budget and generate more candidate solutions per unit time. For self-improvement loops like STaR or ReSTᴱᴹ, where the model iteratively generates solutions, filters for correctness, and fine-tunes on correct solutions, TiDAR's higher generation throughput accelerates the entire loop, potentially enabling more iterations within a fixed compute budget. The paper does not provide FLOPs-per-token numbers, so the exact advantage in this regime remains to be measured, but the tokens-per-NFE metric (which is hardware-independent) establishes a lower bound.

### When to Prefer This Method

The paper explicitly positions TiDAR against three categories of alternatives — standard AR decoding, diffusion language models (Llada, Dream, Block Diffusion), and speculative decoding (EAGLE-3) — and provides quantitative comparisons for each. The decision rules below are directly grounded in the paper's claims and empirical results, not inferred from general principles.

- **Prefer TiDAR over standard AR decoding when**: (a) latency is the primary constraint and throughput at batch size 1 dominates cost (interactive applications, not batch processing); (b) the model size is 1.5B–8B parameters (the evaluated range) where TiDAR's training recipe is validated; (c) context lengths are within ~2K tokens (the effective context window given training with max sequence length 4096 and sequence doubling); (d) a modest quality gap of 1–7 percentage points on the evaluated benchmarks is acceptable (Table 2, comparing TiDAR 8B "Trust Diffusion" to Qwen3 8B base); and (e) the deployment can support continual pretraining of the full model on 50B–150B tokens rather than using an off-the-shelf checkpoint. The throughput advantage is 4.71× to 5.91× (Section 4.3, Figure 4).

- **Prefer TiDAR over diffusion language models (Dream, Llada, Block Diffusion) when**: (a) quality on reasoning tasks (math, coding) is non-negotiable — TiDAR 8B outperforms Dream 7B by ~6.6 points and LLaDA 8B by ~23.5 points on the coding-math average (Table 2); (b) deployment requires exact KV caching for integration with existing serving infrastructure — TiDAR supports this while pure diffusion models use lossy approximation (Section 3.4.4); (c) you want to avoid inference-time hyperparameter tuning — TiDAR requires no entropy thresholds, confidence cutoffs, or step counts, unlike Dream and Llada which need careful threshold selection (Section 4.4.2, Table 4); and (d) likelihood evaluation is needed alongside generation — TiDAR computes likelihood exactly in one forward pass via AR mode, while diffusion models require expensive Monte Carlo estimation (Table 3, LLaDA and Dream using 128-step MC vs. TiDAR's single NFE).

- **Prefer TiDAR over speculative decoding (EAGLE-3, Medusa) when**: (a) maximum throughput on latency-critical single queries is the goal — TiDAR achieves ~2× the throughput of EAGLE-3 on the evaluated tasks (Figure 4, 7.30–10.13× for TiDAR vs. 3.3–4.5× for EAGLE-3); (b) you are willing to continually pretrain the entire model rather than add lightweight draft heads to an existing checkpoint — TiDAR modifies the full model weights, while EAGLE-3 trains only additional layers on top of a frozen base model; and (c) the application does not require exact output-distribution equivalence to the base model — TiDAR's rejection sampling uses the diffusion-drafted tokens and mixed AR-diffusion logits, which provides empirical quality preservation (Figure 6) but does not carry the formal speculative decoding guarantee of identical output distribution (see Section 6 discussion of the theoretical gap).

- **Prefer EAGLE-3 or standard speculative decoding over TiDAR when**: (a) you must preserve the exact output distribution of an existing deployed model for compliance, safety, or reproducibility reasons — EAGLE-3 guarantees bit-identical outputs to the base model under the standard rejection sampling scheme; (b) you need a plug-and-play acceleration method that doesn't require retraining the base model — EAGLE-3 adds draft heads on top of a frozen checkpoint; and (c) the base model is already deployed and inference-hardened, making full-model retraining impractical. The paper acknowledges this trade-off explicitly: "speculative decoding... is able to guarantee exactly the same output as the base model" (Section 4.3), which TiDAR does not claim.
