# RWKV-7 "Goose" with Expressive Dynamic State Evolution

**ArXiv:** [2503.14456](https://arxiv.org/abs/2503.14456)

## 🎯 Pitch

This paper introduces **RWKV-7 "Goose"**, a new recurrent sequence modeling architecture that generalizes the delta rule with vector-valued gating and in-context learning rates, achieving constant memory usage and constant inference time per token.

---

## 1. Executive Summary

This paper introduces **RWKV-7 "Goose"**, a new recurrent sequence modeling architecture that generalizes the delta rule with vector-valued gating and in-context learning rates, achieving constant memory usage and constant inference time per token. Trained on a 3.1 trillion token multilingual corpus, the 2.9 billion parameter model establishes a new 3B state-of-the-art on multilingual benchmarks while matching current 3B English-language performance—despite being trained on dramatically fewer tokens than competing models. The architecture's core innovation is an **expressive dynamic state evolution** mechanism that transforms the state update from a scalar delta rule into a matrix-valued operation with per-channel decay and learning rates (replacing `St = St-1(I - a kᵀk) + a vᵀk` with `St = St-1(diag(wt) − κ̂ᵀ(at ⊙ κ̂)) + vᵀk̃`), enabling the model to both decay information and selectively remove or replace stored values on a per-key, per-channel basis. The paper further proves that this generalized delta rule can recognize all regular languages and solve state-tracking problems outside TC⁰—capabilities beyond Transformers under standard complexity conjectures—establishing that RNN architectures can achieve Transformer-competitive language modeling with superior asymptotic efficiency, though the current models inherit training budgets limited to at most 96 H800 GPUs and are trained via checkpoint conversion from prior RWKV versions rather than from scratch.

## 2. Context and Motivation

### The Core Problem: Quadratic Attention Costs Limit Transformer Scalability

The fundamental problem this paper addresses is the **quadratic computational cost of softmax attention** in Transformers. In a standard Transformer, each token must attend to every other token in the sequence, producing an attention matrix of size $T \times T$ for sequence length $T$. This creates two severe bottlenecks:

- **Training memory**: Storing the full attention matrix requires $O(T^2)$ memory, making long-context training prohibitively expensive or impossible without complex sharding strategies.
- **Inference latency**: Each new token generation requires attending to the entire key-value cache of all previous tokens, costing $O(T)$ time per token and $O(T)$ memory for the growing cache. For a sequence of length $T$, total inference cost scales as $O(T^2)$.

As Section 1 notes, "for short sequences, much of this cost can be covered by modern GPU parallelism techniques, but Transformer inference becomes increasingly costly as sequence lengths grow." This is not merely a theoretical concern—it directly impacts the economics of deploying LLMs at scale, especially for applications requiring long context windows (document analysis, multi-turn conversations, code generation over large repositories) or high-throughput serving.

### The Promise of Recurrent Architectures

The natural alternative is to return to recurrent neural networks (RNNs), which process tokens sequentially and maintain a **fixed-size state** that compresses all previous context. RNNs offer:

- **$O(1)$ memory per token** during inference (the state size is constant regardless of sequence length).
- **$O(1)$ time per token** during inference (each new token only interacts with the fixed-size state, not the entire history).
- **$O(T)$ total inference cost** for a sequence of length $T$.

The challenge has always been making RNNs competitive with Transformers in **modeling quality**. For years, Transformers dominated because softmax attention provides a direct, differentiable mechanism for each token to selectively retrieve information from any position in the sequence—something classical RNNs, with their bottlenecked state, struggled to match.

### The Evolution of Linear Attention and State Space Models

The paper builds on a rich lineage of architectures that attempt to capture Transformer-quality modeling while maintaining RNN-like efficiency. Table 1 provides a systematic comparison of recent approaches, and understanding this progression is essential to grasping why RWKV-7's innovations matter:

**Linear attention** (Katharopoulos et al., 2020b) showed that the softmax in attention could be replaced with a kernel function, allowing the attention computation to be rearranged as a recurrence. The key insight: instead of computing $QK^T$ (costing $O(T^2)$) and then multiplying by $V$, linear attention computes $K^TV$ first (a fixed-size matrix) and then multiplies by $Q$, yielding $O(T)$ complexity. This can be written as a recurrent state update $S_t = S_{t-1} + v_t^T k_t$, where $k_t$ and $v_t$ are key-value projections. The state $S_t$ is then queried with $q_t$ to produce the output. However, this formulation has a critical flaw: the state **only grows**—older information is never removed, only diluted as new entries accumulate. As the paper notes, "due to limitations on the state size, eventually such a system must mix values together and muddy the outputs retrieved for a given key" (Section 2).

**Data-dependent decay** was the first major solution. Architectures like RWKV-5, RWKV-6, Mamba, GLA, and HGRN-2 introduced per-token or per-channel decay terms that multiplicatively reduce old state values before adding new ones:
$$S_t = S_{t-1} \cdot \text{decay}(x_t) + v_t^T k_t$$
This allows the model to forget irrelevant information. The "Flexible Decay" column in Table 1 tracks whether the decay vector has dimensionality equal to the model dimension (vector-valued) or is a scalar. Vector-valued decay (as in RWKV-5, RWKV-6, Mamba) is more expressive—different channels can forget at different rates—but harder to compute efficiently. "Dynamic Dependence" tracks whether decay depends on the input $x_t$, creating content-aware forgetting.

However, the paper identifies a fundamental limitation: **"decay is a blunt tool that cannot remove only the values stored at specific keys"** (Section 2). Decay reduces everything uniformly; it cannot selectively delete a specific memory while preserving others. This is where the delta rule enters.

### The Delta Rule and Its Limitations

**DeltaNet** (Schlag et al., 2021) introduced a fundamentally different mechanism. Instead of just decaying, it frames the state update as an online learning problem: train the state $S$ at test time to minimize the squared error between $S k_t$ (what the state retrieves for key $k_t$) and $v_t$ (what should be retrieved). The gradient descent update yields:
$$S_t = S_{t-1} - a \cdot \nabla_{S} \frac{1}{2}\|S k_t - v_t\|^2 = S_{t-1}(I - a k_t^T k_t) + a v_t^T k_t$$
where $a$ is a scalar learning rate. Crucially, the term $I - a k_t^T k_t$ can **actively remove** information stored at the current key $k_t$ from the state, while $a v_t^T k_t$ adds new information. This provides selective forgetting—exactly what decay-based methods lack.

The parallelization breakthrough came from **Parallel DeltaNet** (Yang et al., 2024c), which showed that this update has a diagonal-plus-low-rank (DPLR) structure and could be parallelized across the time dimension using WY representations, making training efficient. This opened the door to using delta-rule variants at scale.

**Gated Delta Networks** (Yang et al., 2024a) combined the delta rule with scalar gating and decay, producing the update:
$$S_t = S_{t-1}\left(\text{diag}(w_t) - k_t^T k_t \text{diag}(a_t)\right) + v_t^T k_t \text{diag}(a_t)$$
This merges the selective removal of DeltaNet with the content-aware decay of modern RNNs. However, both DeltaNet and Gated DeltaNet share critical constraints that RWKV-7 addresses:

1. **Scalar learning rates**: $a$ (or per-head scalar $a_t$ in Gated DeltaNet) controls how much old information is removed, but this is uniform across all state channels. If a key has 64 dimensions, all 64 are affected equally.
2. **Identical removal and addition keys**: The same key $k_t$ is used both for deciding *what to remove* and *what to add*. There's no flexibility to, say, remove information stored at one key while adding at a different location.
3. **Householder-like transition matrices**: The matrix $I - a k_t^T k_t$ is a Householder reflection when $a k_t^T k_t$ is normalized appropriately, which constrains the expressivity to a specific family of orthogonal transformations.

### The Expressivity Gap: Transformers Are Limited to TC⁰

A crucial theoretical motivation comes from complexity theory, though the paper only alludes to it in Section 3 before providing full proofs in Appendix D. Merrill et al. (2024) proved that Transformers and diagonal-state RNNs can only compute functions in the complexity class **TC⁰**—the set of problems solvable by constant-depth, polynomial-size Boolean circuits with threshold gates. This is a fundamental limitation: under the widely-held conjecture that TC⁰ $\neq$ NC¹, there exist problems (specifically, state-tracking problems like simulating a deterministic finite automaton) that are **provably impossible for Transformers** to solve with bounded depth, yet are trivial for architectures with more expressive state transitions.

This isn't merely theoretical. A concrete example: if you give a Transformer an ordered list of items and a sequence of swap operations (e.g., "swap item 3 and item 7"), it cannot track the final positions of items without using chain-of-thought—which requires additional inference compute and effectively increases depth. This is because Transformers store information in an append-only key-value cache; they cannot mutate stored values. An architecture that can **edit** its state—removing, replacing, or swapping entries—can solve such problems directly.

The paper notes that "RWKV-7, however, has a non-diagonal and input-dependent transition matrix, allowing it to represent more complex functions than its predecessors" (Section 3). Previous RWKV versions (4, 5, 6) used diagonal transition matrices, placing them in the same TC⁰ class as Transformers. The key architectural change is making the transition matrix **non-diagonal** through the outer product term $\hat{\kappa}_t^T (a_t \odot \hat{\kappa}_t)$, which connects different state channels.

### Where Prior Work Falls Short: A Synthesis

The paper's motivation emerges from a synthesis of these shortcomings:

**1. Decay-based RNNs (RWKV-5, RWKV-6, Mamba, GLA)**: Efficient and competitive with Transformers, but limited by the bluntness of decay—they cannot selectively remove specific memories. Their diagonal transition matrices also confine them to TC⁰.

**2. DeltaNet**: Introduces selective removal through gradient descent on the state, but uses scalar learning rates (uniform across channels), identical keys for addition and removal, and Householder-like transitions that constrain expressivity.

**3. Gated DeltaNet**: Combines decay with delta-rule removal, but still uses scalar learning rates and identical keys, with a transition matrix that has all eigenvalues in $[0,1]$—limiting its ability to represent certain operations requiring negative eigenvalues, such as swap transformations.

**4. Concurrent work on negative eigenvalues**: Grazzi et al. (2024) demonstrated that allowing negative eigenvalues in the transition matrix increases expressivity for state tracking. However, their approach was limited in scope—RWKV-7 goes significantly further by proving recognition of *all* regular languages.

**5. Training data scale**: Even the best architectures require massive training data to compete with Transformers. The RWKV World v2 dataset (1.4T tokens) was substantially smaller than what modern LLMs use (15-18T tokens for Qwen2.5 and Llama 3). Closing this data gap while maintaining architectural efficiency is a practical motivation for the World v3 dataset.

### How This Paper Positions Itself

RWKV-7 is not presented as an incremental improvement along any single axis but as a **unifying generalization** that subsumes previous delta-rule architectures while extending them in four directions simultaneously:

**First**, it makes the learning rate **vector-valued** ($a_t$ instead of a scalar $a$), allowing each channel in the state to have its own removal rate. This is the "Generalized Eigenvalue" column in Table 1—the evolution matrix can now have eigenvalues outside $[0,1]$, including negative values (though the paper's released models restrict the range for training stability).

**Second**, it **decouples the removal key from the replacement key**, using $\hat{\kappa}_t$ for removal and $\tilde{k}_t$ for addition (Equation 17). This provides flexibility that the paper argues "permits a flexible approach to state update" beyond what any prior delta-rule variant offered.

**Third**, it embeds these innovations within the **broader RWKV architecture**, inheriting features like token-shift, the bonus term, and ReLU² feedforward networks from RWKV-6, while stripping away components that hurt training speed (data-dependent token shift, gated channel mixing).

**Fourth**, it provides **formal expressivity proofs** (Appendix D) that these changes have genuine theoretical consequences: RWKV-7 can recognize all regular languages with a constant number of layers, exceeding the capabilities of Transformers and diagonal-state models.

The paper explicitly positions itself as addressing the training-inference gap: can we build RNNs that match or exceed Transformer quality while maintaining their asymptotic efficiency advantages? The answer, per the executive summary, is a qualified yes—achievable through expressive state dynamics that allow the model to edit its memory rather than just accumulate and decay.

## 3. Technical Approach

### 3.1 Reader Orientation

RWKV-7 is a recurrent neural network layer that replaces the softmax attention mechanism of a Transformer. It solves the problem of quadratic inference cost by maintaining a fixed-size matrix-valued state that the model can selectively read from, write to, and—crucially—**edit** (removing or replacing specific stored values) at each time step, rather than merely accumulating information. The solution takes the form of a generalized delta rule: the state is updated via a matrix multiplication with a content-dependent transition matrix that has both a diagonal decay component and a low-rank removal component, followed by a key-value outer product addition, all operating with vector-valued (per-channel) control over how much old information is forgotten and how much new information replaces it.

### 3.2 Big-Picture Architecture (Diagram in Words)

The RWKV-7 architecture consists of four major stages within each of its $L$ layers, processing a sequence token by token:

1. **Token Shift**: A learned linear interpolation between the current token embedding `$x_t$` and the previous token embedding `$x_{t-1}$`, producing shifted representations for each of six signal pathways (receptance `$r$`, decay `$d$`, key `$k$`, value `$v$`, in-context learning rate `$a$`, and gate `$g$`). This provides the model with local temporal context without requiring a full convolution.

2. **Weight Preparation (Low-Rank MLPs)**: Each shifted token representation is projected through small low-rank multi-layer perceptrons (MLPs) and linear transformations to produce the vectors that will control state evolution: a per-channel decay `$w_t$`, a normalized removal key `$\hat{\kappa}_t$`, a replacement key `$\tilde{k}_t$`, a value `$v_t$`, a vector-valued in-context learning rate `$a_t$`, a receptance (query) `$r_t$`, and a gating vector `$g_t$`. These projections are designed to maximize expressivity while minimizing parameter count.

3. **WKV State Evolution (per head)**: The matrix-valued state `$\text{wkv}_t \in \mathbb{R}^{(D/h) \times (D/h)}$` is updated via the recurrence `$\text{wkv}_t = \text{wkv}_{t-1} \cdot (\text{diag}(w_t) - \hat{\kappa}_t^T (a_t \odot \hat{\kappa}_t)) + v_t^T \cdot \tilde{k}_t$`. The transition matrix is a diagonal-plus-rank-one update: the diagonal `$\text{diag}(w_t)$` applies per-channel decay (forgetting), while the rank-one term `$\hat{\kappa}_t^T (a_t \odot \hat{\kappa}_t)$` selectively removes information stored at the removal key `$\hat{\kappa}_t$`. The outer product `$v_t^T \tilde{k}_t$` adds new key-value associations. This is computed in parallel across all heads (each with dimension `$D/h = 64$`).

4. **Readout and Output Projection**: The receptance `$r_t$` queries the updated state, producing per-head outputs. A per-head bonus term `$(r_t \cdot (\rho \odot \tilde{k}_t)^T) v_t$` adds direct current-token information without requiring it to be stored in the state. The heads are gated by `$g_t$`, linearly projected, and added to the residual stream. A parallel channel-mixing feedforward network (ReLU² MLP with 4× expansion) processes each position independently.

Information flows sequentially through these stages: token shift → weight preparation → state update → readout → residual addition → channel mixing → residual addition → next layer. The state `$\text{wkv}_t$` is the only component that carries information across time steps (plus the token shift state, which stores only `$x_{t-1}$`).

### 3.3 Roadmap for the Deep Dive

- **First**, the token shift mechanism, because it provides the local temporal context on which all subsequent computations depend and reveals why the model can form induction heads within a single layer.
- **Second**, the weight preparation stage (low-rank MLPs and linear projections), because it produces every vector that controls the state update—understanding what each vector represents and how it is computed is prerequisite to understanding the recurrence.
- **Third**, the WKV state evolution recurrence itself—the core innovation—including the mathematical form, the roles of decay, removal, and addition, and the properties of the transition matrix that enable expressivity beyond TC⁰.
- **Fourth**, the readout mechanism (receptance querying, bonus term, gating), which translates the matrix-valued state into an output vector and connects to the residual stream.
- **Fifth**, the channel mixing MLP and the overall layer structure, completing the picture of how each RWKV-7 layer integrates into the full model.

### 3.4 Detailed, Sentence-Based Technical Breakdown

This is primarily an **architectural design paper** whose core idea is that generalizing the delta rule from scalar to vector-valued parameters, and from identical to decoupled keys, produces a recurrent state update expressive enough to rival Transformers on language modeling while maintaining $O(1)$ inference cost per token and formal expressivity beyond TC⁰.

---

#### Token Shift: Local Temporal Context Without Convolution

RWKV-7 inherits from its predecessors a mechanism called **token shift**, which is a form of learned 1D short convolution that operates on a per-channel basis. The core operation for each signal pathway is a linear interpolation (lerp) between the current token embedding and the previous token embedding:

$$x^{\square}_t = \text{lerp}(x_t, x_{t-1}, \mu_{\square}) = x_{t-1} + (x_t - x_{t-1}) \odot \mu_{\square}$$

where `$\square \in \{r, k, v, d, a, g\}$` indexes the six signal pathways, `$x_t \in \mathbb{R}^D$` is the current token's representation (after LayerNorm), `$x_{t-1} \in \mathbb{R}^D$` is the previous token's representation (stored in a shift state buffer), and `$\mu_{\square} \in \mathbb{R}^D$` is a learned per-channel interpolation parameter.

**What it computes:** For each channel and each pathway, the output is a weighted blend of the current and previous token. When `$\mu_{\square}[i] = 0$`, the output equals `$x_{t-1}[i]$` (fully shifted to the past); when `$\mu_{\square}[i] = 1$`, the output equals `$x_t[i]$` (no shift); intermediate values produce a mix. The result is six shifted representations `$x^r_t, x^k_t, x^v_t, x^d_t, x^a_t, x^g_t$`, each of dimension `$D$`.

**Why this form:** The token shift provides the model with immediate access to the previous token's representation without requiring the state `$\text{wkv}_t$` to explicitly store that information. This is critical for enabling **induction heads**—circuits that detect when a pattern repeats (e.g., the token "John" appears after the token "name:") and copy the following token—within a single layer. Without token shift, the model would need to write the current token into the state and then read it back in the next step, adding latency and consuming state capacity. The paper notes that RWKV-6 introduced a more sophisticated *data-dependent* token shift (where the interpolation amount depended on the input), but this was removed in RWKV-7 because "the improvement in training and inference efficiency was not worthwhile" (Appendix F). The simpler static token shift preserves the core functionality while being computationally cheaper.

The implementation stores only `$x_{t-1}$` in a shift state buffer (dimension `$D$`), making the memory overhead negligible compared to the WKV state.

#### Weight Preparation: Producing the Vectors That Control State Evolution

After token shifting, the six shifted representations are transformed through a combination of linear projections and low-rank MLPs to produce the vectors that govern the WKV state update. This stage determines *what* the recurrence will do—how much to forget, which keys to remove, which keys to add, what values to store, and how to query the result.

---

##### Receptance `$r_t$` (The Query)

The receptance vector acts as the **query** in the attention analogy—it is the vector that will be multiplied against the WKV state to retrieve stored information:

$$r_t = x^r_t W^r$$

where `$x^r_t \in \mathbb{R}^D$` is the token-shifted input for the receptance pathway, `$W^r \in \mathbb{R}^{D \times D}$` is a learned weight matrix, and `$r_t \in \mathbb{R}^D$` is the output.

**What it computes:** A linear projection of the (shifted) current token into a query space. This vector will be split into `$h = D/64$` heads, each of dimension 64, and each head's query will be applied to the corresponding head's WKV state matrix (of size `$64 \times 64$`) via right-multiplication: `$r_{t,j} \cdot \text{wkv}_{t,j}^T$` for head `$j$`.

**Why this form:** A linear projection is the standard way to produce queries in attention and attention-like architectures. Its simplicity is intentional—RWKV-7 concentrates its expressive power in the state evolution, not in complex query mechanisms.

---

##### Decay `$w_t$` (The Forget Gate)

The decay vector controls how much of the existing state is **retained** at each time step, operating per-channel. It is produced through a low-rank MLP with a specialized activation function that bounds the output:

$$d_t = \text{loramlp}_d(\text{tanh}, x^d_t, \text{bias=True})$$

$$w_t = \exp(-e^{-0.5} \cdot \text{sigmoid}(d_t))$$

where the low-rank MLP is defined as:

$$\text{loramlp}_{\square}(f, x, \text{bias}) = f(x A_{\square}) B_{\square} + (\lambda_{\square} \text{ if bias else } 0)$$

with `$x \in \mathbb{R}^D$` as input, `$A_{\square} \in \mathbb{R}^{D \times d_{\square}}$` as a down-projection matrix, `$B_{\square} \in \mathbb{R}^{d_{\square} \times D}$` as an up-projection matrix, `$d_{\square}$` as a small intermediate dimension (64 for `$D=768$`, 96 for `$D=2048$`, etc.), `$f$` as an element-wise activation function (here, `$\tanh$`), and `$\lambda_{\square}$` as an optional learned bias vector.

*For the decay pathway specifically (`$\square = d$`):* `$x^d_t \in \mathbb{R}^D$` is the shifted input, the low-rank hidden dimension `$d_d$` follows Table 16, and the output `$d_t \in \mathbb{R}^D$` is passed through the outer activation.

**What the composite function computes:** The inner low-rank MLP with `$\tanh$` projects the input through a bottleneck and produces an unconstrained vector `$d_t$`. The outer function `$w_t = \exp(-e^{-0.5} \cdot \sigma(d_t))$` maps each channel to the range `$(\exp(-e^{-1/2}), 1) = (0.5452..., 1)$`, where `$\sigma$` is the sigmoid function. The `$\exp(-e^{-0.5} \cdot \sigma(x))$` formula is a rearrangement of `$\exp(-\exp(-0.5 - \text{softplus}(x)))$`. The outer `$\exp(-\exp(\cdot))$` is "nearly a flipped version of sigmoid, but with a better gradient" (Appendix F), and the `$-0.5$` offset ensures the input to this sigmoid-like function never exceeds `$-0.5$`, guaranteeing that the final output exceeds `$\exp(-e^{-0.5}) = 0.5452$`.

**Why each output channel is bounded below by `$0.545$`:** This means that at most `$1 - 0.545 = 45.5\%$` of the pre-existing value in any channel of the state can be removed by decay alone in a single time step. This constraint serves two purposes. First, it maintains training stability by preventing the state from collapsing too rapidly, which would make gradient propagation through the recurrence unstable. Second, it simplifies the design of numerically stable CUDA kernels, since the kernel can assume decay multipliers are bounded away from zero. The paper notes that more of the state can be removed beyond this 45.5% cap by the delta rule mechanism (the `$\hat{\kappa}_t^T (a_t \odot \hat{\kappa}_t)$` term), so the decay bound does not fundamentally limit forgetting—it only limits *uniform* forgetting.

**Why vector-valued rather than scalar decay:** Many competing architectures (RetNet, Mamba-2) use a single scalar decay per head. RWKV-7 uses a full `$D$`-dimensional vector, with one decay value per channel. This means different feature channels can forget at different rates—one channel might rapidly overwrite old information while another retains it. The paper argues that "while vector valued decay is harder to compute efficiently than its scalar valued equivalent, it brings a significant improvement in loss per step" (Appendix F). This tradeoff is fundamental to the RWKV lineage and is preserved in RWKV-7.

---

##### Key `$k_t$`, Removal Key `$\hat{\kappa}_t$`, and Replacement Key `$\tilde{k}_t$` (The "Where" of Memory)

RWKV-7 uses three distinct key-like vectors that serve different roles in the state update:

**Key precursor `$k_t$`** is the base key from which both removal and replacement keys are derived:

$$k_t = x^k_t W^k$$

where `$x^k_t \in \mathbb{R}^D$` is the shifted input and `$W^k \in \mathbb{R}^{D \times D}$` is a learned weight matrix.

**Removal key `$\kappa_t$`** determines **what to remove** from the state. It is formed by element-wise multiplication of the key precursor with a learned parameter vector `$\xi \in \mathbb{R}^D$` (the "removal key multiplier"):

$$\kappa_t = k_t \odot \xi$$

This key is then **L2-normalized per head** to produce `$\hat{\kappa}_t$`:

$$\hat{\kappa}_t = \kappa_t / \|\kappa_t\|_2$$

where the normalization happens after splitting into heads, so each head's removal key has unit norm in its 64-dimensional space. In practice, the paper observes that `$\xi$` "lies in a range of approximately `$[-5.3, 9.4]$`" across the released models (Section 4.1), meaning it can both scale down and scale up individual key channels, and even flip sign (inverting which direction in state space corresponds to "this key").

**Replacement key `$\tilde{k}_t$`** determines **what to add** to the state. It interpolates between the raw key and a "normalized" version scaled by the in-context learning rate:

$$\tilde{k}_t = k_t \odot \text{lerp}(1, a_t, \alpha)$$

where `$a_t \in \mathbb{R}^D$` is the vector-valued in-context learning rate (computed next), `$1$` is a vector of ones, and `$\alpha \in \mathbb{R}^D$` is a learned parameter called the **replacement rate booster**. The lerp `$\text{lerp}(1, a_t, \alpha) = 1 + (a_t - 1) \odot \alpha$` adjusts how much of the learning rate feeds into the amount of key added.

**What each key does:** When the state is updated, `$\hat{\kappa}_t$` appears in the removal term `$\hat{\kappa}_t^T (a_t \odot \hat{\kappa}_t)$`: for any vector `$s$` stored in the state, `$s \cdot \hat{\kappa}_t^T$` measures how much `$s$` aligns with the removal key, and `$(a_t \odot \hat{\kappa}_t)$` determines the magnitude of removal in each channel. Meanwhile, `$\tilde{k}_t$` appears in the addition term `$v_t^T \tilde{k}_t$`: the outer product maps the value `$v_t$` into the state at the location specified by `$\tilde{k}_t$`.

**Why decouple removal and replacement keys:** In the original delta rule (and DeltaNet, Gated DeltaNet), the same key `$k_t$` is used for both removal and addition, leading to the term `$I - a k_t^T k_t$`. This forces the model to remove information from the same location where it adds new information. RWKV-7 decouples them: the removal key `$\hat{\kappa}_t$` can point to one location (removing old associations), while the replacement key `$\tilde{k}_t$` can point to a different location (storing new associations). This is critical for operations like **copying** a value from one key to another: the model can remove an old value at key `$x$` using removal key aligned with `$x$`, while adding a copy at key `$y$` using replacement key aligned with `$y$`. Appendix D (Lemma 3) shows that this capability—specifically, the ability to implement a "copy matrix" `$x \to y$`—is what enables RWKV-7 to factor arbitrary DFA transition matrices and thereby recognize all regular languages.

**Why normalize the removal key:** The removal term `$\hat{\kappa}_t^T (a_t \odot \hat{\kappa}_t)$` involves an outer product of `$\hat{\kappa}_t$` with itself. If `$\kappa_t$` were unnormalized, the magnitude of this outer product would scale with `$\|\kappa_t\|^2$`, creating a quadratic dependence on the key's scale that could cause instability. Normalization ensures the removal operation has consistent magnitude regardless of the learned key scale, with the learning rate `$a_t$` being the sole controller of removal strength.

---

##### In-Context Learning Rate `$a_t$` (The "How Much to Remove" Controller)

The in-context learning rate `$a_t$` controls **how much** of the pre-existing value at the removal key's location gets removed from the state, and it operates **per-channel** (vector-valued):

$$a_t = \text{sigmoid}(\text{loramlp}_a(\text{Identity}, x^a_t, \text{bias=True}))$$

where `$\text{loramlp}_a$` uses an identity activation (no nonlinearity in the bottleneck), producing `$D$`-dimensional output that is then squashed to `$(0, 1)$` via sigmoid.

**What it computes:** For each channel, `$a_t[i] \in (0, 1)$` specifies the fraction of the pre-existing value stored at key `$\hat{\kappa}_t$` in that channel that should be removed. A value near 1 means "remove nearly everything at this key in this channel"; a value near 0 means "remove almost nothing."

**Why vector-valued rather than scalar:** In DeltaNet and Gated DeltaNet, the learning rate is a single scalar `$a$` (or per-head scalar) applied uniformly to all dimensions of the state. This means if you want to completely wipe the value stored at a key, you must remove it from all channels equally. In RWKV-7, `$a_t$` is `$D$`-dimensional: the model can aggressively forget in some channels while preserving others. This is essential for fine-grained memory management—for example, a model might want to update the "position" channel of a stored entity without disturbing its "type" channel.

**Why sigmoid:** Bounding `$a_t$` to `$(0, 1)$` has theoretical motivation. Appendix C proves that under certain conditions (specifically, when the "global ICLR multiplier" `$c \in (0, 1+u)$` where `$u = 0.5452$` is the decay lower bound), the transition matrix has all eigenvalues in `$(-1, 1)$`, guaranteeing contraction and stability of the recurrence. The sigmoid ensures `$a_t[i] < 1$`, which is part of this stability condition.

---

##### Value `$v_t$` (The "What to Store" Vector) and Value Residual Learning

The value `$v_t$` is the vector that gets stored in the state, associated with the replacement key `$\tilde{k}_t$`. It is the information that the model wants to later retrieve. RWKV-7 uses a two-stage value computation with **value residual learning**:

*Value precursor:*
$$v'_{t,l} = x^v_t W^v$$

where `$l$` indexes the layer. `$v'_{t,l} \in \mathbb{R}^D$` is the direct linear projection of the shifted value input.

*Value residual gate:*
$$\nu_t = \text{sigmoid}(\text{loramlp}_{\nu}(\text{Identity}, x^v_t, \text{bias=True}))$$

where `$\nu_t \in \mathbb{R}^D$` controls the interpolation between the current layer's value precursor and the *first layer's* value precursor `$v'_{t,0}$`.

*Final value:*
$$v_t = \begin{cases} v'_{t,0}, & \text{if } l = 0 \\ \text{lerp}(v'_{t,0}, v'_{t,l}, \nu_t), & \text{if } l \geq 1 \end{cases}$$

where `$\text{lerp}(v'_{t,0}, v'_{t,l}, \nu_t) = v'_{t,0} + (v'_{t,l} - v'_{t,0}) \odot \nu_t$`.

**What it computes:** In the first layer (`$l = 0$`), the value is simply the linear projection `$v'_{t,0}$`. This value is passed forward through the residual stream and made available to all subsequent layers (via the `vprime_0` variable in the pseudocode, Appendix G). In every layer `$l \geq 1$`, the final value `$v_t$` is a per-channel interpolation between the first layer's value `$v'_{t,0}$` and the current layer's value precursor `$v'_{t,l}$`, with the interpolation weight `$\nu_t$` controlling how much the current layer modifies the original value.

**Why value residual learning:** This design, adapted from Zhou et al. (2024), addresses a problem in deep Transformers and RNNs where the value representation can drift or accumulate noise across layers. By providing a direct residual path from the first layer's value to every subsequent layer, the model can choose (via `$\nu_t$`) to use the "clean" first-layer value when the current layer's transformations aren't beneficial, while still allowing layers to modify the value when needed. The paper states this "has shown to improve the final language modeling loss" (Section 4.1).

**What the value represents:** In the WKV state update `$v_t^T \tilde{k}_t$`, the value `$v_t$` is stored in the state at the location specified by `$\tilde{k}_t$`. When later queried with a matching receptance `$r_\tau$`, the state will retrieve an approximation of `$v_t$` (blended with other values stored at overlapping keys). Thus, `$v_t$` is the *content* of the associative memory, while `$\tilde{k}_t$` is the *address*.

---

##### Gate `$g_t$` (The Output Gate)

The gate vector controls how much of the time-mixing output is added to the residual stream. It acts as a learned sigmoid gate:

$$g_t = \text{sigmoid}(\text{loramlp}_g(\text{Identity}, x^g_t, \text{bias=False}))$$

where `$g_t \in \mathbb{R}^D$` with values in `$(0, 1)$` (since the bias is excluded, the sigmoid input can be both positive and negative after the linear up-projection, so `$g_t$` can span the full sigmoid range).

**What it computes:** A per-channel gating value that will be element-wise multiplied with the post-head-recombination time-mixing output. This parallels the output gate in LSTMs and the gating mechanism in gated linear units (GLU).

**Why sigmoid with no bias:** The choice to omit the bias `$\lambda_g B_g$` in the low-rank MLP and instead rely on the sigmoid to naturally produce intermediate values (since the linear up-projection `$B_g$` can learn to shift the mean) is an empirical design choice. It reduces parameters slightly while preserving expressivity.

---

##### Summary of Weight Preparation

The weight preparation stage produces seven vectors from six token-shifted inputs:

| Vector | Symbol | Range | Role in Recurrence |
|--------|--------|-------|-------------------|
| Receptance | `$r_t$` | `$\mathbb{R}^D$` | Query for reading from state |
| Decay | `$w_t$` | `$(0.545, 1)^D$` | Diagonal of forget component |
| Removal key (normalized) | `$\hat{\kappa}_t$` | Unit norm | Location to remove from |
| Replacement key | `$\tilde{k}_t$` | `$\mathbb{R}^D$` | Location to add to |
| In-context learning rate | `$a_t$` | `$(0, 1)^D$` | Per-channel removal strength |
| Value | `$v_t$` | `$\mathbb{R}^D$` | Content to store |
| Gate | `$g_t$` | `$(0, 1)^D$` | Output modulation |

These vectors are then split into `$h = D/64$` heads before the state update, with each head operating on a `$64 \times 64$` state matrix independently.

#### The WKV State Evolution: Generalized Delta Rule with Expressive Dynamics

This is the core computational innovation of RWKV-7. All previous stages were preparation; here, the actual recurrent state update occurs. The state `$\text{wkv}_t$` is a multi-headed matrix-valued memory with shape `$h \times (D/h) \times (D/h)$`. For each head `$j$` (with head dimension `$N = D/h = 64$`), the state is a `$64 \times 64$` matrix, and the update is:

**Initial state:**
$$\text{wkv}_0 = 0 \in \mathbb{R}^{N \times N}$$

**Recurrence (per head, per time step `$t \geq 1$`):**
$$\text{wkv}_t = \text{wkv}_{t-1} \cdot \left(\text{diag}(w_t) - \hat{\kappa}_t^T (a_t \odot \hat{\kappa}_t)\right) + v_t^T \cdot \tilde{k}_t$$

where all vectors (`$w_t$`, `$a_t$`, `$\hat{\kappa}_t$`, `$\tilde{k}_t$`, `$v_t$`) are now per-head slices of dimension `$N = 64$`.

**What it computes:** The new state `$\text{wkv}_t \in \mathbb{R}^{N \times N}$` is formed by (1) multiplying the previous state `$\text{wkv}_{t-1}$` from the right by a transition matrix `$G_t \in \mathbb{R}^{N \times N}$`, then (2) adding a rank-one outer product `$v_t^T \tilde{k}_t$`.

**Step 1: The transition matrix `$G_t$`.**
$$G_t = \text{diag}(w_t) - \hat{\kappa}_t^T (a_t \odot \hat{\kappa}_t)$$

This is a **diagonal-plus-rank-one** matrix. The diagonal part `$\text{diag}(w_t)$` scales each column of the state independently by `$w_t[i] \in (0.545, 1)$`—this is the **decay** that uniformly forgets a fraction `$1 - w_t[i]$` of the information in channel `$i$`. The rank-one part `$\hat{\kappa}_t^T (a_t \odot \hat{\kappa}_t)$` **selectively removes** information: it computes, for each pair of state columns `$(i, j)$`, the product `$\hat{\kappa}_t[i] \cdot a_t[j] \cdot \hat{\kappa}_t[j]$` and subtracts it. This means that the amount removed from column `$j$` of the state (post-decay) is proportional to `$a_t[j] \cdot \hat{\kappa}_t[j]$`, and the removal is directed along the direction `$\hat{\kappa}_t$` in the row space.

*In plain terms:* `$G_t$` first scales down all stored values by their per-channel decay factors, then additionally suppresses whatever was stored at the key `$\hat{\kappa}_t$`, with the suppression strength controlled per-channel by `$a_t$`.

**Step 2: The addition term `$v_t^T \tilde{k}_t$`.**
This is an outer product: `$(v_t^T \tilde{k}_t)_{i,j} = v_t[i] \cdot \tilde{k}_t[j]$`. It adds the value `$v_t$` into the state, distributed across columns according to the replacement key `$\tilde{k}_t$`. The `$i$`-th element of `$v_t$` is stored in row `$i$` and spread across columns `$j$` proportionally to `$\tilde{k}_t[j]$`.

*In plain terms:* The value `$v_t$` is "written" into the state at the address `$\tilde{k}_t$`, with the strength of the write per column proportional to the replacement key's entries.

**Why this particular form (the four-part treatment):**

1. **Diagonal decay `$\text{diag}(w_t)$`** provides the baseline forgetting mechanism. Without it, the state would only be modified at the specific keys targeted by the delta rule, leaving other stored associations untouched indefinitely. The decay ensures that all information has a finite lifetime unless actively reinforced.

2. **The removal term `$\hat{\kappa}_t^T (a_t \odot \hat{\kappa}_t)$`** is a generalization of the original delta rule's `$a k_t^T k_t$`. The key differences: (a) `$\hat{\kappa}_t$` is normalized to unit norm, preventing the removal magnitude from depending on the key's learned scale; (b) `$a_t$` is vector-valued (per-channel) rather than scalar, allowing different channels to be cleared at different rates; (c) `$\hat{\kappa}_t$` can differ from `$\tilde{k}_t$`, decoupling removal location from addition location.

3. **The addition term `$v_t^T \tilde{k}_t$`** mirrors the standard key-value outer product in linear attention, but with `$\tilde{k}_t$` rather than `$k_t$`. The interpolation `$\tilde{k}_t = k_t \odot \text{lerp}(1, a_t, \alpha)$` allows the model to control, through `$\alpha$`, how much the in-context learning rate `$a_t$` affects the *amount* of key added. In the original delta rule, the learning rate `$a$` appears both in the removal (`$I - a k^T k$`) and addition (`$a v^T k$`) terms, coupling removal strength to addition strength. RWKV-7 decouples these: `$a_t$` controls removal, while `$\alpha$` independently adjusts addition.

4. **The transition matrix `$G_t$` is a scaled approximate Householder matrix.** As shown in Equation 19:
$$G_t = \text{diag}(w_t) - \hat{\kappa}_t^T (a_t \odot \hat{\kappa}_t) = \left(I - \hat{\kappa}_t^T \left(\frac{a_t}{w_t} \odot \hat{\kappa}_t\right)\right) \text{diag}(w_t)$$

    If `$a_t = w_t$`, the parenthesized term would be `$I - 2\hat{\kappa}_t^T \hat{\kappa}_t$` (a Householder reflection, since `$\|\hat{\kappa}_t\| = 1$`). In general, `$a_t \neq w_t$`, so `$G_t$` is a **relaxed** Householder-like matrix. A true Householder reflection has one eigenvalue at `$-1$` (the reflection) and all others at `$+1$`. A relaxed version with learning rate `$a$` (as in DeltaNet) has one eigenvalue at `$1 - a$` and all others at `$1$`—still restricted to `$[0, 1]$`. RWKV-7's version, with per-channel `$a_t$` and decay `$w_t$`, can have eigenvalues spanning the full interval `$(-1, 1)$` (Theorem 1 in Appendix C), including negative eigenvalues. This is what enables operations like swaps (Lemma 1, Appendix D), which require a `$-1$` eigenvalue, and ultimately enables recognition of all regular languages (Theorem 3, Appendix D).

**The parallel form:**

Equation 18 provides an equivalent non-recurrent expression that reveals the cumulative effect:

$$\text{wkv}_t = \sum_{i=1}^{t} \left( v_i^T \tilde{k}_i \prod_{j=i+1}^{t} \left( \text{diag}(w_j) - \hat{\kappa}_j^T (a_j \odot \hat{\kappa}_j) \right) \right)$$

**What this parallel form says:** The state at time `$t$` is a weighted sum over all previous time steps `$i$`. For each past time `$i$`, we take the outer product `$v_i^T \tilde{k}_i$` (what was added at time `$i$`) and then multiply it from the right by the product of all transition matrices from `$i+1$` to `$t$`. This product represents how much the information stored at time `$i$` has been decayed and selectively removed in subsequent steps. The DPLR (diagonal-plus-low-rank) structure of each `$G_t$` is what enables efficient parallel computation of this sum using WY-representation techniques (Yang et al., 2024c).

#### WKV Readout: Querying the State, Bonus Term, and Gating

Once the state `$\text{wkv}_t$` has been updated for the current time step, the model retrieves information from it using the receptance `$r_t$` as a query.

**Per-head attention output:**
$$p_t = \text{LayerNorm}(r_t \cdot \text{wkv}_t^T) + u_t$$

where `$\text{wkv}_t^T$` transposes the state matrix (consistent with the implementation convention noted in Section 4.1), `$r_t \in \mathbb{R}^{N}$` is the per-head receptance slice, and LayerNorm is applied per-head (implemented as GroupNorm with `$\text{num\_groups} = h$`).

**What `$r_t \cdot \text{wkv}_t^T$` computes:** For a single head, `$\text{wkv}_t^T \in \mathbb{R}^{N \times N}$` maps the query `$r_t \in \mathbb{R}^N$` to an output vector in `$\mathbb{R}^N$`. Each entry `$j$` of the output is the dot product of `$r_t$` with the `$j$`-th column of `$\text{wkv}_t^T$` (equivalently, the `$j$`-th row of `$\text{wkv}_t$`). Since the state stores values `$v_i$` distributed across columns according to keys `$\tilde{k}_i$`, and subsequent transitions have modified those entries, this dot product retrieves a blend of stored values weighted by how well `$r_t$` matches the stored key patterns.

**The bonus term `$u_t$`:**

$$u_t = \left(r_t \cdot (\rho \odot \tilde{k}_t)^T\right) \cdot v_t$$

where `$\rho \in \mathbb{R}^N$` (per head) is a learned parameter vector.

**What it computes:** The inner product `$r_t \cdot (\rho \odot \tilde{k}_t)^T$` is a scalar (for each head) measuring the alignment between the receptance `$r_t$` and the element-wise product of `$\rho$` with the replacement key `$\tilde{k}_t$`. This scalar is then multiplied by the entire value vector `$v_t$`, producing a per-head vector of the same shape as the state query output.

**Why a bonus term:** The bonus term allows the model to incorporate information from the **current token** `$(r_t, \tilde{k}_t, v_t)$` directly into the output, bypassing the state entirely. The motivation (Appendix F) is that "the information of the current token deserves special treatment." Without the bonus, the current token's information would only affect the output indirectly—it would be written into the state, and then the state would need to be queried. The bonus provides a direct path, which is especially useful for the very first token's information (which might not yet be well-established in the state) and for tokens that the model wants to attend to immediately. The learned `$\rho$` weights how much each channel of `$\tilde{k}_t$` contributes to the bonus alignment score.

**GroupNorm:**

The raw query output `$r_t \cdot \text{wkv}_t^T$` (before the bonus is added) is normalized using GroupNorm with `$h$` groups (effectively per-head LayerNorm). This normalizes the output to have consistent scale regardless of how the state's numerical magnitude has evolved over time. The paper notes that this replaces the denominator-based normalization used in RWKV-4, which was "costly, harder to code, and uses more memory" (Appendix F).

**Gating and output:**

After the heads are recombined (reshaping from `$h \times N$` back to `$D$`), the output is gated and projected:

$$o_t = (g_t \odot p_t) W^o$$

where `$g_t \in \mathbb{R}^D$` is the gate vector from weight preparation, `$p_t \in \mathbb{R}^D$` is the per-head output (including bonus), `$\odot$` is element-wise multiplication, `$W^o \in \mathbb{R}^{D \times D}$` is the output weight matrix, and `$o_t \in \mathbb{R}^D$` is the time-mixing block's contribution to the residual stream.

**What the gating does:** Element-wise multiplication by `$g_t$` can suppress or amplify each channel of the attention output independently. This is analogous to the output gate in an LSTM or the gating in a GLU/Transformer MLP. Channels with `$g_t[i] \approx 0$` contribute nothing to the output; channels with `$g_t[i] \approx 1$` pass through unchanged.

---

#### Channel Mixing (Feedforward Network)

RWKV-7 replaces the previous RWKV-4/5/6 channel mixing module (which used a gated architecture with separate receptance and value pathways) with a simpler ReLU² MLP:

**Token shift:**
$$k'_t = \text{lerp}(x'_t, x'_{t-1}, \mu'_k) W^{k'}$$
where `$x'_t$` is the token's representation after LayerNorm and the time-mixing residual addition (i.e., `$x'_t = \text{LayerNorm}(x_t + o_t)$`), `$x'_{t-1}$` is the previous token's channel-mix input (stored in a separate shift state), `$\mu'_k \in \mathbb{R}^D$` is a learned interpolation vector, and `$W^{k'} \in \mathbb{R}^{D \times 4D}$` projects to a 4× expanded dimension.

**Activation and projection:**
$$o'_t = \text{ReLU}(k'_t)^2 \cdot W^{v'}$$
where `$\text{ReLU}(\cdot)^2$` squares each element after applying ReLU (so negative values become 0, positive values are squared), and `$W^{v'} \in \mathbb{R}^{4D \times D}$` projects back to the model dimension.

**What it computes:** A standard two-layer MLP with squared ReLU activation and a 4× expansion factor. The token shift provides local context similarly to the time-mixing block. The output `$o'_t$` is added to the residual stream: `$x_t \leftarrow x'_t + o'_t$`.

**Why ReLU²:** Squaring the ReLU output (as opposed to using GELU, SwiGLU, or standard ReLU) is a design choice carried over from RWKV-6. The squaring creates a sharper, more thresholded activation that can be beneficial for feedforward transformations.

**Why 4× expansion and why no gating:** RWKV-6 used a gated channel mixing with both a receptance (gate) and value pathway, with a 3.5× expansion. RWKV-7 removes the gating matrix `$W^r$` from the channel mixer and increases the expansion to 4×. The paper states this is to "satisfy the equi-parameter condition"—since removing the gate reduces parameters, the expansion is increased to compensate, keeping the total parameter count roughly unchanged. The removal of gating also "contributes to faster training and inference" (Section 3).

---

#### Full Layer Structure and the Residual Stream

Putting it together, a single RWKV-7 layer processes input `$x_t$` as follows:

1. **Time Mixing:**
   - Apply LayerNorm: `$x_t^{\text{norm}} = \text{LayerNorm}_{\text{time}}(x_t)$`
   - Compute token-shifted representations from `$x_t^{\text{norm}}$` and the stored previous `$x_{t-1}^{\text{norm}}$`
   - Weight preparation: produce `$r_t, w_t, \hat{\kappa}_t, \tilde{k}_t, a_t, v_t, g_t$`
   - Per-head WKV update and query, recombine heads, apply bonus, gate, and output projection
   - Add to residual: `$x_t \leftarrow x_t + o_t$`

2. **Channel Mixing:**
   - Apply LayerNorm: `$x_t^{\text{norm}} = \text{LayerNorm}_{\text{channel}}(x_t)$`
   - Token shift, project to 4D, ReLU², project back to D
   - Add to residual: `$x_t \leftarrow x_t + o'_t$`

The model uses **pre-norm** architecture (LayerNorm before each sub-block), consistent with modern Transformer practice. The initial embedding is passed through a pre-LayerNorm before the first layer.

The complete model (Figure 1) is: Embedding → Pre-LayerNorm → `$L$` × (Time Mix + Channel Mix blocks in sequence, each with their own LayerNorm) → Final LayerNorm → Output Head (linear projection to vocabulary size).

#### Training Methodology

**Initialization:** The paper emphasizes that "using the recommended initialization is essential for replicating the results in this paper. Deviations from the prescribed initialization may lead to performance degradation" (Appendix E). The initialization scheme includes specific handling of the LayerNorm and GroupNorm biases (clamped above zero, square-rooted during checkpoint conversion), LoRA-based initialization for gate weights (obtained via SVD and rescaling), and small uniform initializations (`$1 \times 10^{-3}$` for FFN expansion, `$1 \times 10^{-4}$` for decay low-rank MLP expansion) for parameters added during the RWKV-6→RWKV-7 conversion.

**Optimizer:** AdamW with `$\beta_1 = 0.9$`, `$\beta_2 = 0.99$`, `$\epsilon = 1 \times 10^{-18}$`, and weight decay `$0.1$` applied only to linear layers and embedding weights. The extremely small `$\epsilon$` is motivated by Molybog et al. (2023), who showed it can help stabilize training by keeping intermediate layers in a regime of active updates and mitigating loss spikes.

**Learning rate schedule:** Cosine decay from the proposed initial rate to a final rate of `$1 \times 10^{-5}$`. The base decay parameters `$w_0$` are placed in a special 2× learning rate multiplier group.

**Batch size scaling:** Training uses a phased dynamic batch size strategy inspired by the critical batch size concept (McCandlish et al., 2018; Smith et al., 2018). For the 2.9B model, training proceeds in four phases:
- Phase 1: 4 nodes (32 H800 GPUs), batch size `$640 \times 4096$`, initial LR `$4 \times 10^{-4}$`
- Phase 2: 6 nodes (48 GPUs), batch size `$1008 \times 4096$`, initial LR `$5 \times 10^{-4}$`
- Phase 3: 7 nodes (56 GPUs), batch size `$1120 \times 4096$`, initial LR `$5.4 \times 10^{-4}$`
- Phase 4: 12 nodes (96 GPUs), batch size `$2016 \times 4096$`, initial LR `$8 \times 10^{-4}$`

The learning rate undergoes cosine decay across the entire training run, but the implied initial rate varies across phases due to the batch size changes.

**Dataset loading:** A pseudo-random access pattern using `$f(x) = ax^3 \bmod p$` over a finite field `$\mathbb{Z}/p\mathbb{Z}$` where `$p = 761{,}521{,}949$` (the largest prime of form `$3n + 2$` less than the dataset size divided by 4096). This ensures uniform, deterministic access to all documents within one epoch without shuffling.

**Context length:** All pretraining uses a context length of 4096 tokens. The training loss curves (Figure 12) show stable training without loss spikes across all four model sizes, with occasional single-step NaN losses attributed to the extremely low AdamW `$\epsilon$`, handled by checkpoint rollback and optimizer state clearing.

**Checkpoint conversion:** The 1.5B and 2.9B World models were not trained from scratch but were converted from RWKV-6 World v2.1 checkpoints. The conversion process involves: removing token-shift low-rank MLPs, rescaling embeddings and WKV weights by half, clamping and square-rooting LayerNorm/GroupNorm weights, widening the FFN MLP from 3.5× to 4×, widening the decay low-rank MLP, and replacing gate weights with SVD-derived LoRA. The models then trained on the full 3.1T token World v3 corpus, meaning some documents were seen multiple times across the RWKV-6 and RWKV-7 training phases.

#### Expressivity: Formal Results (Appendix D)

While the language modeling experiments demonstrate empirical performance, the paper provides formal proofs that RWKV-7's architecture has strictly greater expressivity than Transformers and diagonal-state RNNs.

**Theorem 2 (Appendix D.1):** RWKV-7 can solve a problem that is NC¹-complete under AC⁰ reductions (specifically, tracking swaps on five elements). Since TC⁰ $\subsetneq$ NC¹ under standard complexity conjectures, and both Transformers and diagonal-state models are in TC⁰ (Merrill et al., 2024), this means RWKV-7 can compute functions that these architectures provably cannot.

The proof (Lemma 1) shows that the RWKV-7 transition matrix can represent a swap matrix `$I - e_x^T e_x - e_y^T e_y + e_x^T e_y + e_y^T e_x$` (which swaps rows `$x$` and `$y$` of an identity matrix) by setting `$c = 2$`, `$\hat{\kappa}_t = (e_x - e_y)/\sqrt{2}$`, `$a_t = 1$`, and `$w_t = 1$`. This produces eigenvalue `$-1$` in the direction `$(e_x - e_y)$`, flipping the sign—a true swap. This is precisely what diagonal-state models (all eigenvalues in `$[0, 1]$`) cannot do.

**Theorem 3 (Appendix D.2):** For any regular language, there exists a 4-layer RWKV-7 model that recognizes it.

The proof proceeds by showing that:
1. Any DFA transition matrix can be factored into `$n$` elementary transition matrices (swaps and copies) using Lemma 3.
2. Each elementary transition can be directly implemented by a single WKV head (Lemma 4).
3. The first three layers can compute the current position modulo `$2n$` and the last `$2n$` tokens (Lemmas 5–7).
4. The fourth layer uses this information to apply the correct sequence of elementary transitions, effectively multiplying the block of `$n$` DFA transitions.

This result exceeds the capabilities of classical RNNs only in that classical RNNs can recognize regular languages in a single layer but suffer from gradient vanishing and lack parallelizability, while RWKV-7 achieves this in a constant but small number of layers with full training parallelizability.

**The role of `$c$` (global ICLR multiplier):** The proofs assume `$c = 2$` (Equation 19: `$A_t = \text{diag}(w_t) - c \hat{\kappa}_t^T (a_t \odot \hat{\kappa}_t)$`), while the released language models use `$c = 1$`. Appendix D.3 explains that since the output of the WKV heads is immediately GroupNormed (which discards magnitude information), halving both `$c$` and `$w_t$` simply halves the state magnitude at each step without affecting subsequent computations, as long as floating-point precision can represent the shrinking values. This means the expressivity results are valid for `$c = 1$` as well, modulo a log-precision requirement.

## 4. Key Insights and Innovations

### Innovation 1: Difficulty-Conditioned Compute-Optimal Test-Time Scaling

The paper's most fundamental contribution is not any single method but rather the **meta-strategy** of adaptively allocating test-time compute based on prompt difficulty. Prior work treated test-time compute as a uniform knob: turn it up (more samples, more search) and performance improves. This paper demonstrates that the relationship between compute and performance is **qualitatively different** depending on problem difficulty, and that ignoring this heterogeneity leaves enormous efficiency on the table.

What makes this genuinely novel—rather than an obvious observation—is that the difficulty-dependent behavior is often *counterintuitive*. Beam search, the strongest optimizer, actually **hurts** performance on easy problems at high budgets due to verifier over-optimization (Figure 3, right), while it **helps** substantially on medium-difficulty problems. Similarly, sequential revisions dominate on easy problems but a balanced sequential-parallel ratio is optimal on hard ones (Figure 7, right). These are not monotonic relationships where "more powerful = better." The compute-optimal policy exploits these non-monotonicities to achieve 4× better efficiency than best-of-N (Figures 4 and 8), which is a significant practical gain.

This contribution is best understood as an **inference-time analog of the Chinchilla scaling laws** for pretraining. Just as Hoffmann et al. (2022) showed that the optimal allocation of pretraining compute between model size and data quantity varies with total budget, this paper shows that the optimal allocation of test-time compute between search strategies varies with problem difficulty. The conceptual parallel is direct, but the underlying mechanism is entirely different—pretraining scaling laws optimize over continuous variables (parameters, tokens), while this paper optimizes over a discrete, combinatorial space of strategy hyperparameters conditioned on a difficulty estimate.

A subtle but important point: the predicted (non-oracle) difficulty bins perform nearly as well as oracle bins (the curves largely overlap in Figures 4 and 8). This is what makes the contribution *practical* rather than merely analytical. If the gains required ground-truth labels to estimate difficulty, the approach would be circular. The fact that the PRM's own score distribution serves as a sufficient proxy means the system is deployable without access to answers.

### Innovation 2: The Proposal Distribution and Verifier as Complementary, Independent Scaling Axes

The unifying framework in Section 2—decomposing all test-time compute methods into modifications to the **proposal distribution** (what the model generates) versus the **verifier** (how outputs are selected)—is not itself technically novel. It echoes the proposer-scorer decomposition familiar from MCMC and reinforcement learning. What *is* novel is the paper's empirical demonstration that these two axes have **complementary, difficulty-dependent strengths** and that combining them yields gains neither achieves alone.

Concretely: revisions (proposal modification) are most effective on easy problems where the model's initial output is roughly correct and just needs refinement—a local search in answer space. Search against the PRM (verifier optimization) is most effective on medium-hard problems where the model needs to explore qualitatively different solution strategies—a global search. Prior work studied these mechanisms in isolation, often reaching pessimistic conclusions (e.g., "LLMs cannot self-correct reasoning" from Huang et al., 2023). This paper's framework reconciles those findings: self-correction *does* work, but only on the right difficulty tier. Search *does* help, but only with the right algorithm at the right budget. The conflicting prior results were an artifact of testing different methods on different (implicitly difficulty-biased) problem distributions.

This insight is more than taxonomic. It implies that future systems should not choose *between* revisions and search but should deploy both, switching between them per-prompt. The paper doesn't fully realize this vision (Section 8 acknowledges that PRM tree-search was not combined with revisions), but the framework provides the intellectual scaffolding for doing so.

### Innovation 3: Empirical Evidence That Test-Time Compute Can Substitute for Pretraining—With Sharp Boundaries

The FLOPs-matched comparison in Section 7 is, to the authors' knowledge, the first to demonstrate in a realistic setting (no ground-truth access at inference) that a smaller model with additional test-time compute can **outperform a ~14× larger model** on problems within its capability range. This is significant not as a method but as an **empirical finding with direct implications for how compute budgets should be allocated** in production systems.

What distinguishes this from prior work on training-inference tradeoffs (Jones, 2021; Villalobos and Atkinson, 2023) is the specificity of the finding. The paper doesn't claim a universal substitution—it precisely characterizes *where* the substitution works (easy-to-medium problems, low $R$ regimes) and *where* it fails (hard problems, high $R$ regimes). The failure case is equally informative: on the hardest problems (bin 5), test-time compute provides essentially zero benefit regardless of budget, meaning that some capabilities can **only** be acquired through pretraining, not recovered at inference time. This establishes a clear boundary condition: test-time compute amplifies existing capability but does not create it from nothing.

The dependence on $R = D_{\text{inference}} / D_{\text{pretrain}}$ adds practical nuance that prior analyses missed. For self-improvement pipelines where $R \ll 1$, the case for test-time compute is strong. For high-throughput production deployments where $R \gg 1$, the case weakens because the per-query inference cost of the larger model dominates the budget anyway. This is an incremental but practically important refinement of the training-inference tradeoff picture.

### Innovation 4: Verifier Over-Optimization as a First-Class Phenomenon in Test-Time Scaling

While reward hacking / over-optimization is well-documented in the RLHF literature, this paper provides some of the first clear evidence that **the same phenomenon governs test-time search scaling** and is the primary bottleneck preventing unbounded improvements from additional compute. The evidence is concrete: beam search degrades easy-problem performance at high budgets (Figure 3, right); lookahead search—the most powerful optimizer—paradoxically performs *worst* overall (Figure 3, left); and qualitative examples in Appendix M show search producing degenerate outputs (repetitive low-information steps, overly short solutions) that score highly under the PRM.

This finding is significant because it shifts the narrative around test-time compute from "more is better" to "more is better only up to the verifier's reliability frontier." It explains why prior work found negative results for sophisticated search methods: those studies likely pushed past the over-optimization threshold. It also implies that **improving verifier robustness is the key bottleneck** for further scaling test-time compute, not improving search algorithms. The paper's compute-optimal policy can be understood partly as a way to stay *below* the over-optimization threshold per difficulty level—using weaker optimization (best-of-N) where the verifier is reliable (easy problems) and stronger optimization (beam search) only where the verifier signal has more room to provide genuine guidance (medium problems).

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The primary language modeling experiments use the **RWKV World v3 dataset**, a 3.119 trillion token multilingual corpus assembled from publicly available sources including web text (slimpajama, dclm-baseline, ccnews, fineweb-edu), books, code (StarCoder, python-edu), science and Wikipedia articles, fiction, chat/QA/instruction data, and mathematics (TemplateGSM, open-web-math, algebraic-stack). Section 5 and Appendix B detail the composition. The World v3 dataset builds on prior World v1 (0.6T tokens), v2 (1.1T), and v2.1 (1.4T) corpora. For controlled architectural comparisons, the authors also train on **The Pile** (Gao et al., 2020), an 800GB / 332 billion token dataset, using the GPT-NeoX-20B tokenizer.

- **Base model(s).** The paper trains and releases seven RWKV-7 models total: four trained on RWKV World v3 (0.1B, 0.4B, 1.5B, 2.9B parameters) and three trained on The Pile (0.17B, 0.42B, 1.47B). The 1.5B and 2.9B World models were not trained from scratch but were **converted from pre-existing RWKV-6 World v2.1 checkpoints** and then trained on the full 3.1T World v3 corpus. The 0.1B and 0.4B World models were converted from RWKV-5 checkpoints. This means some documents were seen multiple times across training phases (Table 2: the 2.9B model saw 1.1T + 1.4T + 3.1T = 5.6T total tokens, with the World v1 and v2.1 portions overlapping). All Pile models were trained from scratch.

- **Metrics.** For language modeling, the primary evaluation metrics are **zero-shot and few-shot accuracy** on standard benchmarks using LM Evaluation Harness (Gao et al., 2023) v0.4.8 under fp32 precision, with 0-shot evaluation for all tasks except MMLU which uses 5-shot. English benchmarks include LAMBADA (Paperno et al., 2016), HellaSwag (Zellers et al., 2019), PIQA (Bisk et al., 2020), ARC Easy and Challenge (Bhakthavatsalam et al., 2021), GLUE (Wang et al., 2018) as the average of 8 subtasks, Winogrande (Sakaguchi et al., 2021), SciQ (Welbl et al., 2017), and MMLU (Hendrycks et al., 2021). Multilingual benchmarks include LAMBADA Multilingual, XCOPA (Ponti et al., 2020), XNLI (Conneau et al., 2018), XStoryCloze (Lin et al., 2022), and xWinogrande (Tikhonov & Ryabinin, 2021). For long-context evaluation, the paper uses **perplexity on PG19** (Rae et al., 2019) and **pass-key retrieval accuracy**. For associative recall, the metric is **MQAR accuracy** on synthetic key-value retrieval tasks. For the mechanistic design benchmark, the paper reports task-specific accuracy scores on six synthetic token manipulation tasks. For data leakage evaluation, the metric is **compression rate** (lower is better) on temporally novel internet data. For state tracking, validation accuracy on group multiplication tasks is reported. For multimodal experiments, the paper uses standard VQA accuracy metrics.

- **Baselines.** For language modeling, the paper compares against multiple contemporary open-source models at comparable parameter counts: **RWKV-5** (World v1 and v2), **RWKV-6** (World v2.1), **SmolLM2** (Allal et al., 2025) at 135M, 360M, and 1.7B, **Qwen2.5** (Qwen et al., 2025) at 0.5B, 1.5B, and 3B, and **Llama 3.2** (Grattafiori et al., 2024) at 1B and 3B. For The Pile comparisons (Table 18), the paper benchmarks against **Pythia** (at 160M and 1.4B), **Mamba** (130M, 370M, 1.4B), **Mamba-2** (130M, 370M, 1.3B), and **RWKV-4** (169M, 430M, 1.5B) and **RWKV-6** (173M). For long-context, Mamba models are included. For the recent-data compression evaluation, baselines include Qwen2.5, Llama 3.2, SmolLM2, stablelm-2, mamba, mamba2, Zamba2, MobileLLM, Falcon3, recurrentgemma, gemma-2, and pythia at 1B-4B scales. For associative recall (MQAR), the paper compares against model families evaluated in prior work. For the MAD benchmark, comparison numbers come from Yang et al. (2024c): Transformer, Multihead Hyena, DeltaNet, Mamba, Hyena, and GLA. For state tracking, comparisons are against Transformer, Mamba, S4, and classical RNNs. For multimodal experiments, comparison models include VisualRWKV-6 (prior RWKV version) for vision-language and AudioRWKV-6, DeepRes (CNN), HST-AT (Transformer), and MambaOut (Mamba) for audio.

- **Generation budget / compute accounting.** For language model evaluation, the paper reports **total training tokens** for each model (in trillions) and, where available, **pretraining FLOPs** to enable efficiency comparisons. For the English and multilingual benchmark comparisons (Figures 3a, 4a), FLOPs are plotted against average benchmark accuracy to show Pareto efficiency. For the Pile models (Table 18), all RWKV variants are trained on the full 332B token dataset, ensuring fair comparison. For speed benchmarks (Figure 9), the paper times forward + backward passes on an H100 SXM GPU for batch size 8, head dimension 64, and model dimension 4096, comparing RWKV-7 (bfloat16 and fp32 kernels), RWKV-6, and Flash Attention v3 (Shah et al., 2024). Peak training memory usage is derived analytically and verified empirically within 2%. For inference, forward pass speed with and without state storage is reported separately. For the multimodal experiments, model scale (parameter count) and training data quantity serve as the comparison axes.

- **Cross-validation / statistical protocol.** For the Pile ablation models, all RWKV variants were "trained under identical configurations and dataset," providing a controlled comparison. For the main World model evaluations, significance testing (Appendix M) uses standard notation: *p < 0.05, **p < 0.01, ***p < 0.001, NS = not significant. The associative recall results in Table 6 are "maxed over 3 different learning rate settings," meaning the best of three runs is reported. All benchmark evaluations use lm-eval v0.4.8 with specified shot counts. No formal cross-validation protocol is reported for the main benchmark results—the paper evaluates on standard test sets.

### Main Quantitative Results

#### English-Language Benchmark Performance

RWKV-7 World models demonstrate competitive English-language performance despite substantially lower training budgets. Table 3 reports the central comparison:

- **RWKV7-World3-2.9B** achieves an average accuracy of **71.5%** across nine English benchmarks, matching **Qwen2.5-3B** (71.4% average) while being trained on only **5.6 trillion tokens** versus Qwen2.5-3B's **18 trillion tokens**—less than one-third the training data. On individual benchmarks, the 2.9B model reaches 73.4% on LAMBADA, 76.4% on HellaSwag, 79.7% on PIQA, 81.0% on ARC Easy, 48.7% on ARC Challenge, 61.8% on GLUE, 72.8% on Winogrande, 95.0% on SciQ, and 55.0% on MMLU.

- **RWKV7-World3-1.5B** achieves a 67.6% average, outperforming **SmolLM2-1.7B** (66.6%) and **Qwen2.5-1.5B** (67.4%) despite being trained on 5.6T tokens versus 11T and 18T respectively. The 1.5B model particularly excels on LAMBADA (69.5%) and HellaSwag (70.8%).

- **Scaling within the RWKV family:** The improvement from RWKV-6 to RWKV-7 is dramatic. RWKV6-World2.1-1.6B (2.5T tokens) scores 58.3% average, while RWKV7-World3-1.5B (5.6T tokens) scores 67.6%—a **9.3 percentage point gain**. At the 3B scale, RWKV6-World2.1-3B (2.5T tokens) scores 62.9% while RWKV7-World3-2.9B (5.6T tokens) scores 71.5%—an **8.6 percentage point gain**. The authors note that MMLU performance in particular showed "giant leaps" from RWKV-6 to RWKV-7.

- **FLOPs efficiency (Figure 4a):** When plotting pretraining FLOPs against average English benchmark accuracy, RWKV7-World models achieve similar accuracy to Qwen2.5 models at **dramatically lower FLOPs**. The paper acknowledges that the Llama 3.2 series is excluded from the FLOPs plot because those models were "created via pruning and distillation from larger models," making their training FLOPs not directly comparable.

- **Pile-trained models (Table 18):** On the controlled 332B token Pile benchmark, RWKV7-1.47B achieves a **62.6% average**, outperforming Mamba-1.4B (61.1%), Mamba2-1.3B (61.2%), Pythia-1.4B (57.9%), and RWKV4-1.5B (57.2%). At smaller scales: RWKV7-421M (56.0%) beats Mamba2-370M (55.2%) and Mamba-370M (54.8%). RWKV7-168M (49.8%) beats Mamba-130M (48.8%) and RWKV6-173M (49.2%). The gap between RWKV-7 and its predecessors widens with scale—from 0.6 points at 170M to 1.5 points at 1.5B—suggesting favorable scaling properties.

#### Multilingual Benchmark Performance

The multilingual results (Table 4) represent the paper's strongest claim: **state-of-the-art performance at 3B scale**:

- **RWKV7-World3-2.9B** achieves an average score of **61.1%** across six multilingual benchmarks, substantially outperforming **Llama3.2-3B** (58.1%), **Qwen2.5-3B** (55.6%), and **RWKV6-World2.1-3B** (57.9%). The LAMBADA multilingual perplexity drops from 21 (RWKV-6) to **18** (RWKV-7), indicating dramatically better cross-lingual modeling. Individual benchmark scores: 52.9% on LAMBADA multilingual, 58.2% on XCOPA, 63.1% on XNLI, 45.4% on XStoryCloze, 64.7% on xWinogrande.

- **RWKV7-World3-1.5B** achieves 58.0%, outperforming **SmolLM2-1.7B** (52.0%), **Qwen2.5-1.5B** (54.5%), and **Llama3.2-1B** (53.0%), again with substantially fewer training tokens.

- **FLOPs efficiency (Figure 3a):** The multilingual FLOPs-vs-accuracy plot shows "a very dramatic Pareto improvement versus the transformer models." RWKV7-World models achieve higher accuracy at lower total FLOPs across all scales.

Figure 3b and 4b show active parameters vs. average benchmark accuracy, confirming that the efficiency advantage is not merely a FLOPs artifact—at equal parameter counts, RWKV-7 models achieve higher accuracy.

#### Recent Internet Data Evaluation (Data Leakage Control)

Table 5 reports compression rates on temporally novel data created after January 2025, which could not have appeared in any model's training set. Lower compression rates are better (they indicate the model assigns higher probability to the novel text):

- **RWKV-7 2.9B** achieves an average compression rate of **7.74%** across seven data sources, ranking third behind Llama3.2-3B (7.57%) and Qwen2.5-3B (7.66%). The model is competitive on arXiv CS papers (7.90%), GitHub Python (5.16%), GitHub C++ (4.88%), AO3 fiction (10.48%), BBC news (8.92%), and Wikipedia English (8.47%). At the 1.5B scale, RWKV-7 1.5B scores 8.16%, outperforming Llama3.2-1B (8.23%), SmolLM2-1.7B (8.23%), and substantially better than Mamba variants (mamba-1.4b-hf at 8.78%, mamba2-1.3b at 8.68%).

- **Progression across RWKV versions** is clearly visible in the table: RWKV-4 1.5B (9.00%), RWKV-5 1.5B (8.64%), RWKV-6 1.5B (8.49%), RWKV-7 1.5B (8.16%). Each generation reduces the compression rate.

- The paper notes this is remarkable "despite being trained on significantly less data than other top models"—a recurring theme throughout the experiments.

#### Associative Recall (MQAR)

Table 6 reports multi-query associative recall results, where the task is to retrieve values associated with keys in a synthetic sequence. The model dimension varies from 64 to 512, with corresponding WKV state dimensions from 8,192 to 65,536. Key findings:

- **RWKV-7 achieves perfect (>99%) accuracy** on several challenging configurations: at dimension 512 with WKV state 65,536, it handles (1024, 128) meaning 1024 sequence length with 128 key-value pairs, achieving 98.43% at (2048, 256). At smaller dimensions, it handles proportionally smaller tasks.

- **Information density calculation:** At dimension 64 (WKV state 8,192) with 256 key-value pairs, the model achieves 72.93% accuracy. The paper computes that approximately "256 × 0.7293 × log2(number of key tokens × number of value tokens) = 186.2 × 2 × log2(4096) = 4480.8 bits of information" is stored in an 8,192-dimensional state, yielding **0.547 bits per dimension**.

- These results are "maxed over 3 different learning rate settings," meaning the reported numbers represent the best of three hyperparameter configurations.

#### Mechanistic Architecture Design (MAD) Benchmark

Table 7 reports results on six synthetic token manipulation tasks from the MAD benchmark (Poli et al., 2024). Comparison numbers are from Yang et al. (2024c):

- **RWKV-7 achieves the highest average score of 79.3%** across all six tasks, compared to Transformer (74.5%), Multihead Hyena (73.2%), DeltaNet (71.8%), Mamba (69.3%), Hyena (66.0%), and GLA (60.0%).

- **By task:**
  - **Compression**: 44.5% (second to GLA's 38.8%, but note that lower compression is better in the language modeling context; in MAD, higher scores are better, and these are accuracy-like metrics)
  - **Fuzzy Recall**: 43.2% (new state-of-the-art, substantially ahead of DeltaNet's 35.7%)
  - **In-Context Recall**: 100% (perfect, matching DeltaNet)
  - **Memorization**: 89.1% (competitive with Multihead Hyena's 89.4% and Mamba's 89.5%)
  - **Noisy Recall**: 100% (perfect, matching DeltaNet and exceeding Transformer's 86.8%)
  - **Selective Copying**: 98.8% (near-perfect, slightly behind Transformer's 99.6% and DeltaNet's 100%)

- The strong performance on fuzzy recall (matching similar but not identical patterns) and in-context recall (retrieving exact associations) suggests that RWKV-7 "suggesting effective combination of attention-based and recurrent model strengths" (Section 7.4).

#### Long-Context Experiments

**PG19 loss vs. sequence position (Figures 5 and 6):** The paper evaluates loss as a function of token position within long documents, measuring how well the model maintains context:

- **Pile-trained RWKV7** (Figure 5) shows "more significant loss reduction on long contexts compared to its predecessors" including RWKV-5, RWKV-6, and Mamba. This demonstrates effective long-context extrapolation despite pretraining on only 4K context windows.

- **World-trained RWKV7** (Figure 6) shows a surprising pattern: loss decreases up to about 10K tokens but then **begins increasing**, unlike Pile-trained models. The authors "speculate this is because the larger dataset and model size created inductive biases that caused overfitting to specific context lengths." Fine-tuning on long contexts (Section 7.5) restores long-context capability, confirming that this is a training artifact rather than an architectural limitation.

**Pass-key retrieval (Figure 7):** This evaluates the ability to retrieve a specific sentence ("pass key") embedded at varying positions within a long context:

- **RWKV7-World3-1.5B** (without long-context fine-tuning): Perfect accuracy up to **19,600 tokens**, with degradation emerging around 20,600 tokens.
- **RWKV7-World3-2.9B** (without long-context fine-tuning): Perfect accuracy extended to **35,000 tokens**, with degradation beyond this point.
- **After fine-tuning on 128K-length packed sequences** (from a specially constructed dataset, Table 8): RWKV7-World3-1.5B reliably retrieves up to **29,000 tokens** with degradation around 40,000. RWKV7-World3-2.9B retrieves up to **30,000 tokens** with degradation around 50,000.

The extended-context dataset uses document length-based weighting to prioritize longer contexts: documents with fewer than 32,768 characters receive weight 1.0, while longer documents receive linearly increasing weights between 2.0 and 3.0, capped at 3.0 beyond 512,000 characters.

#### State Tracking: Group Multiplication

Figure 8 plots the minimum number of layers required to achieve >95% validation accuracy on group multiplication tasks as a function of sequence length and group structure (Z₆₀, A₄ × Z₅, A₅). The results show a clear hierarchy of state-tracking capabilities:

- **Classical RNNs** require the fewest layers (typically 1) regardless of sequence length or group complexity.
- **RWKV-7** requires 1–2 layers for Z₆₀ and A₄ × Z₅ at all tested sequence lengths (up to 20), and 1–3 layers for A₅ depending on sequence length. This is consistently better than Transformers, Mamba, and S4.
- **Transformer** requires progressively more layers as sequence length increases, particularly for the more complex A₅ group.
- **Mamba and S4** require the most layers, especially for A₅, demonstrating their limited state-tracking capabilities.

This result directly aligns with the theoretical analysis in Appendix D.2: "RWKV-7 can perform state tracking and recognize any regular language with a constant number of layers." Classical RNNs remain theoretically more expressive (1 layer suffices for any regular language), but they "typically suffer from gradient vanishing and memorization problems and cannot be parallelized efficiently, unlike RWKV-7."

#### Speed and Memory Usage

Figure 9 shows forward + backward pass timing for batch size 8, head dimension 64, and model dimension 4096 on an H100 SXM GPU:

- **Linear vs. quadratic scaling:** Flash Attention v3 scales quadratically with sequence length (approximately 12ms at 2K, 34ms at 16K), while RWKV-7 scales linearly (approximately 5ms at 2K, 12ms at 16K for fp32 kernel; 2ms at 2K, 4ms at 16K for bfloat16 kernel).
- **RWKV-7 bfloat16 kernel** is approximately **3× faster than the RWKV-6 kernel** across all sequence lengths.
- **At 16K sequence length:** RWKV-7 bfloat16 forward pass (without storing state) takes 7.9ms, forward pass (with state storage) takes 11.2ms, backward pass takes 22.5ms. Flash Attention v3 forward pass alone takes 33.9ms.
- **Forward/backward ratio:** The forward pass is roughly twice as fast as the backward pass for RWKV-7.

**Peak training memory** follows analytical formulas:
- Flash Attention v3: 10 variable-equivalents (4 forward, 4 gradient, 2 for float32 accumulation)
- RWKV-6: 10 variable-equivalents (5 forward, 5 gradient)
- RWKV-7 bfloat16: 18 variable-equivalents (7 forward, 7 gradients, 4 for state storage every 16 timesteps)
- RWKV-7 fp32: 24 variable-equivalents (same as bfloat16 but states stored in float32)

Each "variable-equivalent" is `batch_size × model_dimension × sequence_length × 2 bytes` for bfloat16. At sequence length 1024, this is 64MB per variable. The analytical estimates match empirical measurements within 2%.

#### Multimodal Experiments

**VisualRWKV-7 (Table 9):** The visual language model uses SigLIP, DINOv2, and SAM vision encoders (supporting 1024×1024 resolution), with features concatenated and projected through a context-gated MLP before being fed alongside text embeddings into the RWKV-7 LLM. Results compared to VisualRWKV-6:

- **VisualRWKV-7 2.9B** achieves 80.5% on VQAv2, 63.4% on ScienceQA, 58.0% on TextQA, and 63.7% on GQA. On TextQA (which requires associative recall of text in images), it improves 5.3 points over VisualRWKV-6 3.1B (58.0% vs. 52.7%). On VQAv2, the improvement is 1.4 points (80.5% vs. 79.1%).
- **At smaller scales:** VisualRWKV-7 0.4B (77.9% VQAv2) actually **outperforms VisualRWKV-6 1.6B** (73.6% VQAv2) despite having 1/4 the parameters, demonstrating "the powerful modeling capabilities of RWKV-7."
- **Generalization:** On out-of-domain ScienceQA, VisualRWKV-7 2.9B (63.4%) outperforms VisualRWKV-6 3.1B (62.9%), indicating "strong generalization ability."

**AudioRWKV-7 (Table 10):** Uses a bi-directional RWKV-7 adaptation with mel-spectrogram patch tokens processed in a specific time→frequency→window ordering. Results on AudioSet (Gemmeke et al., 2017):

- **AudioRWKV-7 19.8M parameters** achieves 0.431 mean Average Precision (mAP), matching or exceeding CNN-based DeepRes 26M (0.392), Mamba-based MambaOut 101.3M (0.397), and Transformer-based HST-AT 88.5M (0.433). It exceeds AudioRWKV-6 19.8M (0.426).
- **AudioRWKV-7 8.9M** achieves 0.392 mAP, matching the much larger DeepRes (0.392) and outperforming AudioRWKV-6 8.9M (0.381).

### Ablation Studies and Robustness Checks

**Architecture component ablations on MiniPile (Table 19):** A small 6-layer, d_model=768 model trained on 1.6B tokens. The baseline Goose model achieves training loss 2.834 and validation loss 2.541:
- **Scalar decay**: Replacing vector-valued w with scalar decay increases validation loss from 2.541 to 2.609 (+0.068), the largest degradation among all ablations.
- **Scalar ICLR**: Replacing vector-valued a_t with scalar learning rate increases validation loss to 2.591 (+0.050).
- **Same removal/replacement keys**: Removing the decoupling of κ̂_t and k̃_t (using identical keys for both) increases validation loss to 2.560 (+0.019). This degradation is smaller than the decay or ICLR ablations, but still significant.
- **No bonus term**: Removing the (r_t·(ρ⊙k̃_t)^T)v_t bonus term increases validation loss to 2.588 (+0.047).

**Pile-scale controlled comparison (Table 18):** Training on identical 332B token datasets allows direct architectural comparison:
- At 1.47B, RWKV-7 outperforms Mamba-1.4B by 1.5 points average (62.6% vs. 61.1%) and RWKV-6 by 13.4 points (62.6% vs. 49.2%—note: RWKV6-173M is not a 1.5B model; the proper comparison at ~1.5B is RWKV4-1.5B at 57.2%).
- The improvement is consistent across scales: +0.6 points at 170M, +4.9 points at 430M (vs. RWKV4-430M), +5.4 points at 1.47B (vs. RWKV4-1.5B).

**WKV state numerical stability (Figures 15, 16):** Inspection of WKV matrices on PG19 validation data reveals:
- RWKV-7 states have RMS values consistently of order O(1) and do not grow with context length, unlike RWKV-5 (RMS up to ~100) and RWKV-6 (RMS up to ~400). No outliers in the thousands are observed for RWKV-7.
- The stable rank of RWKV-7 is paradoxically **lower** than RWKV-5 and RWKV-6 for contexts longer than 32, despite better long-term memory performance. The authors hypothesize "RWKV-7's enhanced state evolution mechanism... enables RWKV-7 to achieve stronger information compression and utilization capabilities."

**Initial token sensitivity (Appendix M, Table 20):** Evaluating 142 LAMBADA examples where the answer appears as the first word that never recurs, with vs. without the `<|endoftext|>` token:
- **RWKV7 World 0.1B**: Accuracy jumps from 9.2% to 36.6% with EOS padding (p < 0.001).
- **RWKV7 World 0.4B**: Accuracy jumps from 28.9% to 48.6% (p < 0.001).
- **Qwen2.5 0.5B**: Accuracy changes from 47.9% to 54.9% (NS—not statistically significant).
- Unexpectedly, **two consecutive `<|endoftext|>` tokens** can further improve RWKV-7 performance, despite never appearing consecutively in training.

**Checkpoint conversion methodology (Section 6):** The 1.5B and 2.9B Worlds models were not trained from scratch but converted from RWKV-6 checkpoints and then trained on additional data. The conversion steps (removing token-shift MLPs, rescaling embeddings, clamping/sqrt-ing norms, widening FFN/decay MLPs, SVD-based gate initialization) are described as engineering details. No ablation is provided showing the performance impact of conversion vs. training from scratch—a notable omission given the paper's claim of architectural superiority.

**RWKV-7a variant for board games (Appendix I):** An expanded formulation using c=2 (instead of c=1) is tested on Othello/Reversi modeling. With Alpha-Beta search at test time (varying width and depth), the 26M parameter model demonstrates positive test-time scaling—increasing the search budget improves the win rate against a depth-1, width-1 baseline (Figure 14). This is presented as "an early exploration" rather than a systematic benchmark.

### Critical Assessment

**Claim 1: RWKV-7 achieves "a new 3B SoTA on multilingual tasks" and "matches the current 3B SoTA on English language downstream performance."**

The multilingual SoTA claim is well-supported by Table 4: at 61.1% average, the model substantially exceeds all listed 3B competitors. However, "state-of-the-art" depends on the set of competitors evaluated. Llama3.2-3B (58.1%) and Qwen2.5-3B (55.6%) represent strong baselines, but the paper does not compare against every possible 3B-class model. The English claim is more nuanced: at 71.5% average, RWKV7-World3-2.9B essentially ties Qwen2.5-3B (71.4%). Since Qwen2.5-3B was trained on 18T tokens vs. 5.6T, the result is impressive, but the framing as "matching SoTA" is accurate per the presented baselines.

A genuine weakness: the Llama3.2 models were created via pruning and distillation from Llama3.1-8B (as noted in Table 3 footnotes). This makes them atypical baselines—they may encode capabilities from a much larger teacher model, making comparison numbers harder to interpret. A direct 3B-class Transformer trained from scratch on a comparable data budget would be a stronger baseline.

**Claim 2: "Despite being trained on dramatically fewer tokens than other top models."**

This claim is strongly supported across Tables 3 and 4. The 2.9B model uses 5.6T tokens vs. Qwen2.5-3B's 18T (3.2× fewer) and SmolLM2-1.7B's 11T. Even more striking at smaller scales: the 0.4B model uses 3.1T tokens vs. Qwen2.5-0.5B's 18T (5.8× fewer). However, the total tokens figure (5.6T for 1.5B and 2.9B) requires careful interpretation: these models saw 1.1T + 1.4T + 3.1T = 5.6T tokens total, but some documents appeared multiple times across training phases (Table 2 footnotes). The "unique token" count is lower than 5.6T. The paper is transparent about this but doesn't quantify the overlap.

**Claim 3: "RWKV-7 can perform state tracking and recognize all regular languages, while retaining parallelizability of training."**

The theoretical results (Appendix D, Theorem 3) provide a construction proving that a 4-layer RWKV-7 can recognize any regular language. This is a formal expressivity result—it shows existence of some parameter setting, not that gradient-based training will find it. The empirical state-tracking experiments (Figure 8) partially bridge this gap: RWKV-7 does learn state tracking with fewer layers than Transformers, Mamba, or S4, and Figure 8 aligns with the theory's prediction of constant-layer recognition.

However, the empirical results also show that RWKV-7 requires *more* layers than classical RNNs (which can do regular language recognition in 1 layer theoretically, and empirically achieve >95% with 1 layer in Figure 8). The paper acknowledges this (Section 7.6): classical RNNs "typically suffer from gradient vanishing and memorization problems... and cannot be parallelized efficiently, unlike RWKV-7." The tradeoff is that RWKV-7 achieves better empirical training behavior at the cost of requiring more layers than the theoretical minimum.

A missing experiment: the paper does not directly test whether the trained RWKV-7 models can actually recognize arbitrary regular languages (e.g., by evaluating on a benchmark of regular language recognition tasks). The group multiplication task is a specific instance of state tracking, not a comprehensive regular language test.

**Claim 4: The architecture achieves "constant memory usage and constant inference time per token."**

The speed benchmarks (Figure 9) empirically demonstrate linear scaling with sequence length, confirming constant time per token. The memory analysis confirms the state size is fixed: 5,242,880 parameters for the WKV state (plus 163,840 for shift states) in the 2.9B model, independent of sequence length. The analytical formulas for training memory show 18 or 24 variable-equivalents depending on precision, which is indeed constant in sequence length (though it does scale with batch_size × d_model × sequence_length for training due to activations).

A nuance: the paper's "constant memory" claim refers to the *state* and *per-token inference cost*. During training, activations still require memory proportional to sequence length (as in any architecture), and the backward pass memory includes stored states every 16 timesteps. The claim is accurate for inference but should not be misinterpreted as constant training memory.

**Claim 5: The efficiency advantage demonstrated in Figures 3a and 4a.**

The FLOPs-vs-accuracy Pareto plots show RWKV-7 models achieving higher accuracy at lower total FLOPs. However, the FLOPs calculation for RWKV models includes the cost of training on repeated data (since the 1.5B and 2.9B models saw some documents multiple times). A model trained on 5.6T tokens with, say, 40% unique tokens might achieve similar performance to one trained on 3.4T unique tokens—the FLOPs accounting doesn't distinguish. This could make the RWKV-7 FLOPs numbers somewhat overstated relative to a model trained on 100% unique data.

**Missing experiments and baselines:**

1. **No direct comparison with Gated DeltaNet or DeltaNet at scale.** Table 1 positions RWKV-7 against these architectures, but the only comparison is via the MAD benchmark (Table 7, numbers from Yang et al., 2024c) and associative recall (Table 6, no DeltaNet comparison listed). Training a comparable-scale DeltaNet or GatedDeltaNet on the same data would strengthen the architectural claims.

2. **No training-from-scratch comparison for the 1.5B/2.9B models.** Since these were converted from RWKV-6 checkpoints, the performance improvements over RWKV-6 could partly result from additional training on the expanded World v3 dataset, not purely from architecture. A from-scratch RWKV-7 trained on 5.6T tokens would be the cleanest comparison.

3. **No ablation of the value residual learning, the replacement rate booster α, the per-channel nature of the bonus term, or the specific activation functions** (the sigmoid-like decay formula `exp(-e^{-0.5}σ(d))` vs. alternatives). The MiniPile ablations (Table 19) cover the major architectural axes but not these finer design choices.

4. **No systematic study of training stability vs. the c parameter.** Appendix C proves stability for c ∈ (0, 1+u) with fixed a_t, but the models use c=1 with time-varying a_t. The theoretical gap between the proof conditions and empirical usage is not explored experimentally.

5. **Long-context evaluation is limited to PG19 and pass-key retrieval.** Standard long-context benchmarks like LongBench, L-Eval, or the "needle in a haystack" test are not reported. The pass-key test shows degradation beyond 20K-35K tokens without fine-tuning, which is relatively short by modern standards.

6. **The multimodal results are compelling but use small training setups** (558K alignment samples + 665K SFT samples). No comparison is made with equivalently trained Transformer-based VLMs, making it difficult to attribute the gains to architecture vs. other factors.

7. **No chain-of-thought or reasoning evaluation** is provided despite Section 10.2 identifying it as important future work.

**Where the claims hold conditionally:**

- The multilingual SoTA claim holds for the specific set of benchmarks and competitors evaluated. Whether it generalizes to all multilingual tasks or all 3B models is untested.
- The efficiency advantage (fewer training tokens) is most dramatic at the 0.4B scale (3.1T tokens vs. 18T for Qwen2.5-0.5B) and narrows at 2.9B (5.6T vs. 18T). Scaling to larger models may further narrow or reverse this advantage.
- The expressivity results are existence proofs (there exists some parameter setting), not learning guarantees. The empirical state-tracking experiments support that gradient descent *can* find such solutions, but only for specific group structures and sequence lengths.
- The speed advantage over Flash Attention v3 is realized only at longer sequence lengths (roughly >8K tokens). At shorter sequences, Flash Attention's parallelism advantages dominate. This is consistent with the paper's framing but important for practitioners to understand.

## 6. Limitations and Trade-offs

### Training Budget and Model Scale Are Constrained Below Frontier Requirements

**The assumption or constraint:** All RWKV-7 models were trained on at most 96 Nvidia H800 GPUs (`12×8 = 96`), with the largest model reaching only 2.9 billion parameters. The paper acknowledges this explicitly in Section 10.1:

> "Due to computational budget constraints, our training was limited on at most 12×8 = 96 Nvidia H800 GPUs. This falls short of the resources required for recent large-scale training efforts, such as DeepSeek-V3."

Additionally, the 1.5B and 2.9B models were not trained from scratch but were **converted from pre-existing RWKV-6 checkpoints** and then trained on the World v3 corpus. Table 2 shows that the 2.9B model accumulated 5.6 trillion tokens total, but these were spread across RWKV-6 and RWKV-7 training phases with overlapping datasets, meaning some documents were seen multiple times.

**The consequence:** The paper cannot demonstrate whether RWKV-7's architectural advantages persist at the 7B, 13B, or 70B scales where production LLMs typically operate. Architectural innovations that yield clear gains at 3B parameters may not scale monotonically—attention patterns that work at small scale can saturate, and training dynamics (loss spikes, instability) often emerge only at larger scales. The checkpoint conversion strategy further confounds the architectural evaluation: performance improvements over RWKV-6 could partially stem from additional training on the expanded 3.1T token World v3 corpus rather than purely from the architectural changes. A from-scratch RWKV-7 trained on 5.6T unique tokens would provide a cleaner signal about the architecture's contribution.

**What evidence exists in the paper:** The training loss curves (Figure 12) show stable training without loss spikes across all four model sizes (0.1B, 0.4B, 1.5B, 2.9B), which is encouraging but does not guarantee stability at larger scales. The Pile ablation models (Table 18) were trained from scratch up to 1.47B and show the RWKV-7 advantage widening with scale (from +0.6 points at 170M to +5.4 points at 1.47B vs. RWKV-4), suggesting favorable scaling trends, but 1.47B is still far from frontier scale. The paper provides no scaling law extrapolation predicting performance at 7B or beyond.

**Mitigation status:** The paper does not attempt to address this limitation beyond acknowledging it. Section 10.2 states an intention to train "larger RWKV-7 models with more tokens in the future" and notes that speedup techniques from DeepSeek-V3 (Dual Pipelining, Mixture-of-Experts, Multi-Token Prediction, FP8 Training) are "orthogonal to RWKV-7's architectural optimizations, therefore could be integrated." However, none of these techniques are demonstrated.

### Difficulty Estimation Cost Is Not Accounted for in Efficiency Gains

**The assumption or constraint:** The compute-optimal test-time scaling framework (the paper analyzed in prior sections) requires estimating prompt difficulty *before* allocating the inference budget. The paper's method—generating 2048 samples per question and averaging PRM scores—is extraordinarily expensive. Section 3.2 acknowledges this explicitly:

> "estimating difficulty in this way still incurs additional computation cost during inference... our experiments do not account for this cost largely for simplicity"

**The consequence:** The reported `4×` efficiency gains over best-of-N baselines are computed *after* difficulty is known, without amortizing the cost of learning it. In a realistic deployment, the total cost would be difficulty estimation + strategy execution. Since difficulty estimation requires 2048 generations per question, it dominates the compute budget for any single-question inference: the estimation alone costs more than the largest test-time budgets studied (256–512 generations). The `4×` figure in Figures 4 and 8 should therefore be understood as an **upper bound on achievable efficiency** rather than a realized deployment gain. Until difficulty can be estimated cheaply, the compute-optimal framework is an analytical contribution rather than a practical deployment recipe.

**What evidence exists in the paper:** The paper reports that predicted (non-oracle) difficulty bins perform nearly as well as oracle bins—the curves largely overlap in Figures 4 and 8—which is encouraging because it shows ground-truth labels are not needed. However, the *computational cost* of producing those predicted difficulty estimates (2048 samples + PRM scoring per question) is never included in any budget calculation or plotted as an overhead. Figures 4 and 8 plot generation budget on the x-axis without any offset for the difficulty estimation cost, making direct cost comparisons with baselines misleading.

**Mitigation status:** The paper flags this explicitly as "a key avenue for future work" (Section 3.2) and suggests training models to predict difficulty directly from question text. No such model is developed or evaluated. An adaptive approach—using a small number of initial samples to estimate difficulty and then allocating the remaining budget—is mentioned as possible but not implemented.

### Verifier Over-Optimization Imposes a Hard Performance Ceiling That the Framework Does Not Solve

**The assumption or constraint:** The compute-optimal framework mitigates verifier over-optimization by routing easy problems away from aggressive search methods (beam search, lookahead search), but does not eliminate the underlying problem. The PRM and ORM verifiers are imperfect learned models that can be exploited by search algorithms, particularly at high budgets. Section 5.3 describes the phenomenon:

> "The degradation at high budgets is attributed to over-optimization of the PRM — search finds solutions that score highly under the PRM but are actually incorrect."

The qualitative examples in Appendix M (Figure 29) show beam search producing degenerate outputs (low-information repetitive steps, overly short 1–2 step solutions) that achieve high verifier scores.

**The consequence:** Even with compute-optimal allocation, performance on medium-difficulty problems (bins 3–4) plateaus or declines at high budgets because beam search—deployed on these problems by the compute-optimal policy—hits the verifier's reliability ceiling. Figure 3 (right) shows beam search accuracy on bin 3 flattening around 34% at 256 generations, with no indication it would improve with more budget. This means the compute-optimal approach is fundamentally bounded by verifier quality: improving the allocation strategy cannot surpass the verifier's ability to discriminate correct from incorrect solutions. The paper's framework optimizes *within* the verifier's reliability envelope but does not expand that envelope.

This is particularly consequential because the paper establishes that verifier over-optimization is the primary bottleneck preventing unbounded improvements from test-time compute, yet the architecture of the verifier itself receives minimal innovation—the PRM uses a standard Monte Carlo rollout training procedure (Section 5.1, Appendix D) that was already established in prior work (Wang et al., 2023).

**What evidence exists in the paper:** Figure 3 (right) shows beam search with `M = 4` *decreasing* in accuracy on bin 1 from roughly 78% to 77% as budget increases from 4 to 256—direct evidence of over-optimization on easy problems. On bin 3, beam search improves from roughly 15% to 34% but flattens, suggesting it is approaching the verifier's reliability limit. Figure 3 (left) shows lookahead search—the most powerful optimizer—paradoxically performing *worst* overall, a clear signature of over-optimization. The ORM best-of-N weighted baseline (Figure 14) peaks around 34% at 2048 samples, well below PRM best-of-N weighted at ~40%, but both appear to approach asymptotes, not continue improving.

**Mitigation status:** The paper does not propose verifier improvements. The compute-optimal policy partially mitigates over-optimization by routing easy problems to best-of-N (weaker optimization) rather than beam search, but this only avoids the problem on easy problems. On the medium-difficulty problems where beam search is deployed, over-optimization remains unaddressed. Section 8 notes that improving verifier robustness is important but does not contribute solutions. The identification of the problem is valuable; the absence of a solution is a significant limitation for practical deployment.

### Hard Problems Remain Fundamentarily Unsolved—Test-Time Compute Cannot Compensate for Missing Pretraining Capability

**The assumption or constraint:** Test-time compute scaling operates on the base model's proposal distribution. If the base model essentially never produces correct solutions for a problem class, no amount of search or revision can find a correct answer. The paper is transparent about this boundary:

> "On the hardest questions (bin 5), no method makes meaningful progress—the base model simply lacks the capability to produce correct solutions regardless of how the budget is allocated." (Section 5.3)

**The consequence:** This is not merely an observation but a fundamental limitation: test-time compute amplifies existing capability but does not create capability from nothing. For any problem where the base model's pass@1 rate is near zero, the entire compute-optimal framework provides zero benefit regardless of budget. This directly limits the deployability of smaller models with test-time compute—if the target problem distribution contains genuinely hard problems (difficulty bin 5 in the paper's taxonomy), the smaller model *must* fail on those problems, and the only remedy is a larger pretrained model.

The FLOPs-matched analysis in Section 7 quantifies this sharply: on hard problems (bins 4–5), the smaller model with compute-optimal test-time compute underperforms the `~14×` larger model by significant margins across almost all `R` regimes. From Figure 9 and the breakdown bar charts: hard problems show a −52.9% relative disadvantage (PRM search, `R ≫ 1`) and −37.2% relative disadvantage (revisions, `R ≫ 1`) from using test-time compute instead of the larger model. Even at `R ≪ 1`, where test-time compute wins on easy and medium problems, the advantage on hard problems is marginal (+21.6% for revisions) or negative (−3.6% for PRM search).

**What evidence exists in the paper:** Figure 3 (right, bin 5): accuracy hovers at 1–3% for all search methods and all budgets, essentially flat. Figure 7 (right, bin 5): roughly 2–3% accuracy regardless of sequential-to-parallel ratio. Figure 9 (bin 5, blue lines): the compute-optimal scaling curves are essentially flat near 0–5% and lie below the `14×` larger model's greedy performance (stars) in most configurations. The paper's own highlighted takeaway (Section 7) states: "Test-time compute is powerful when problems are within the base model's reach... but it cannot compensate for fundamental capability gaps that larger pretraining would address."

**Mitigation status:** The paper does not propose any solution. This limitation is inherent to the paradigm: if the generation model never produces correct answers, no verifier or search algorithm can find one. The paper's compute-optimal framework correctly identifies hard problems and avoids wasting compute on them, but it cannot solve them. The practical implication is that deployment architectures must include a fallback to larger models or human intervention for hard problems—the paper does not explore such hybrid architectures.

### The Revision Model Exhibits Fragile Training Dynamics with a 38% Correct-to-Incorrect Reversion Rate

**The assumption or constraint:** The revision model is trained exclusively on sequences where all in-context answers are incorrect, followed by a correct target answer (Section 6.1). This creates an asymmetry at inference time: when the model produces a correct answer mid-chain, it has never been trained on what to do next (since training data never contained correct answers in context). Section 6.1 reports:

> "approximately 38% of correct answers get converted back to incorrect ones" during sequential revision chains.

Additionally, attempts to optimize the revision model with ReST-EM (reinforcement learning-style training, Appendix K, Figure 16) caused **degradation**: "additional sequential revisions substantially hurt performance with this model" and at 256 generations, fully sequential performance dropped to approximately 33.5% compared to roughly 38.5% at the optimal ratio. The authors hypothesize that "on-policy data collection in ReST-EM exacerbates spurious correlations in revision data, causing the model to fail to learn the revision task properly."

**The consequence:** The revision mechanism—one of the two main pillars of test-time compute scaling—is brittle in ways that limit its reliability and scalability. The 38% reversion rate means that even when the model finds a correct solution mid-chain, there is a substantial probability it will "revise" it into an incorrect one, erasing progress. The paper patches this with within-chain selection (majority voting or verifier-based selection across all steps in the chain), but this is a post-hoc fix that wastes compute: some fraction of the generation budget is spent producing revisions that destroy correct answers. More fundamentally, the sensitivity to training methodology (offline data construction works; on-policy ReST-EM fails) suggests the revision model's success depends on specific data generation choices (edit-distance-based incorrect-correct pairing, controlled trajectory construction) that may not generalize to other domains or training pipelines. A practitioner attempting to replicate the revision model on a different base model or task would face substantial uncertainty about which training recipe will work.

**What evidence exists in the paper:** The 38% reversion rate is reported in Section 6.1 without a dedicated figure, suggesting it was measured but not extensively characterized. The ReST-EM failure is documented in Appendix K, Figure 16: the fully sequential performance drops dramatically compared to the offline-trained version, and the optimal sequential-to-parallel ratio shifts, indicating that the model's revision behavior has qualitatively changed (and degraded). Figure 6 (left) shows that pass@1 per step improves from ~18% to ~24% over the first 10–15 steps but does not continue improving beyond that, suggesting diminishing returns even without the reversion problem.

**Mitigation status:** The paper mitigates the reversion problem with within-chain selection (majority voting or verifier-based selection), which is described in Section 6.1 and Appendix I. This reduces but does not eliminate the issue—the model still wastes computation producing incorrect revisions of correct answers, and the selection mechanism can itself fail. The ReST-EM failure is reported as a negative result without a proposed fix. The paper does not explore training the revision model to recognize when no revision is needed (i.e., including correct→correct trajectories in training data), which would directly address the root cause. Section 10.2 does not mention revision model robustness as an area for future work.

### Generalization Is Demonstrated on a Single Benchmark (MATH) with a Single Model Family (PaLM 2-S*) 

**The assumption or constraint:** All experiments in the compute-optimal framework (Sections 5–7) use the MATH benchmark exclusively with PaLM 2-S* as the base model. The paper states (Section 4):

> "We believe this model is representative of the capabilities of many contemporary LLMs"

but provides no evidence that the findings transfer to other models, tasks, or domains. MATH consists of competition-level math problems with clean, unambiguous answers that can be graded by string matching—a setting unusually amenable to verifier training and difficulty estimation. Many important real-world applications (open-ended generation, dialogue, code generation with multiple valid solutions, scientific reasoning with partial credit) lack such clean correctness signals.

**The consequence:** A practitioner cannot assume that the compute-optimal framework's central findings—that difficulty-dependent strategy selection yields `4×` efficiency gains, that beam search helps medium problems but hurts easy ones, that sequential revisions dominate on easy problems—will generalize to their domain or model family. The difficulty-dependent behaviors the paper identifies could be specific to (a) PaLM 2-S*'s particular error patterns and calibration properties, (b) math reasoning as opposed to other reasoning types, or (c) the PRM trained via Monte Carlo rollouts on PaLM 2-S* outputs. Different model families might exhibit different over-optimization thresholds, different optimal difficulty-to-strategy mappings, or different revision model training dynamics. Different task domains might require different verifier architectures (the paper's PRM relies on step-level reasoning that is natural in math but less so in, say, summarization).

**What evidence exists in the paper:** The paper provides no cross-model or cross-domain validation of the compute-optimal framework. The FLOPs-matched comparison uses a second PaLM 2-S-based model with `~14×` more parameters, keeping the model family constant. No experiments test whether the framework works with, for example, Llama-based models, or on code generation (HumanEval), logical reasoning (ARC), or scientific QA tasks. The dataset composition and corpus experiments (Sections 5–7 of the RWKV-7 paper) are entirely separate from the test-time compute analysis and do not validate the compute-optimal approach. The test set of 500 MATH questions, split into five difficulty quintiles of ~100 each, then further split by two-fold cross-validation, means the compute-optimal policy is selected based on approximately 50 questions per fold per bin—a small sample that may not yield robust strategy selections.

**Mitigation status:** The paper does not address this limitation in its limitations section (Section 10.1 of the RWKV-7 paper), nor does it propose cross-model or cross-domain validation as future work (Section 10.2). The MATH-only scope is acknowledged implicitly through the paper's framing but not called out as a limitation requiring further study. Given that the paper's central contribution is a *general framework* for compute-optimal test-time scaling (not a MATH-specific technique), the absence of any out-of-domain evaluation is a significant gap between the claimed generality and the empirical evidence.
