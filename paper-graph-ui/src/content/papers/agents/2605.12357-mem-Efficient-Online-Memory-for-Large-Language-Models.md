# δ-mem: Efficient Online Memory for Large Language Models

**ArXiv:** [2605.12357](https://arxiv.org/abs/2605.12357)

## 🎯 Pitch

Just an 8×8 matrix, updated on the fly by a delta rule and steered into attention, boosts a frozen LLM’s memory-heavy scores by over 30%—no fine-tuning, no context stretching. This compact online associative memory outperforms far heavier baselines, proving that effective long-term recall can be decoupled from bloated context windows.

---

## 1. Executive Summary

This paper introduces **δ-mem**, a lightweight memory mechanism that augments a frozen Transformer backbone with a compact **online state of associative memory (OSAM)** — a fixed-size matrix updated by delta-rule learning — and uses its readout to generate low-rank corrections to the backbone's attention computation during generation. Evaluated on Qwen3-4B-Instruct, Qwen3-8B, and SmolLM3-3B across memory-heavy benchmarks (MemoryAgentBench, LoCoMo, HotpotQA) and general capability benchmarks (IFEval, GPQA-Diamond), δ-mem improves the average score to 1.10× that of the frozen backbone and 1.15× that of the strongest baseline, with gains concentrated on memory-intensive tasks — 1.31× on MemoryAgentBench and 1.20× on LoCoMo — while preserving general capabilities. These results establish that effective online memory can be realized through an extremely compact state (as small as an 8×8 matrix) directly coupled with attention computation, without full fine-tuning, backbone replacement, or explicit context extension.

## 2. Context and Motivation

### The Core Problem: LLMs Need Memory, Not Just Longer Context Windows

As LLMs transition from handling isolated prompts to powering long-term assistants and autonomous agents, they face a fundamental requirement that single-turn models never encountered: **the need to accumulate, maintain, and reuse historical information across extended interactions**. When a personalized assistant remembers user preferences from conversations weeks ago, or when an agent system tracks task progress across hundreds of steps, the model cannot succeed by processing each input independently — it must carry forward a meaningful representation of what has happened before.

The most straightforward response — simply expanding the context window to hold more interaction history — turns out to be inadequate on two fronts. First, it is **computationally expensive**: standard attention mechanisms incur quadratic cost with respect to context length, making very long contexts prohibitively costly even if the hardware can physically accommodate them. Second, and more subtly, **longer context does not guarantee effective use of that context**. As the paper notes in Section 1, models exhibit "context degradation or context rot when the context becomes very long" (Hong et al., 2025; Du et al., 2025), meaning that even if all historical tokens are technically visible to the model, the model may fail to extract and apply the relevant information from them. The paper explicitly states that "even million-token context windows do not fundamentally solve the memory problem" — a pointed observation given that both OpenAI and Google have announced such capabilities.

This gap is not merely academic. In memory-heavy agent scenarios (MemoryAgentBench), the paper reports that the frozen Qwen3-4B-Instruct backbone achieves only 29.54% accuracy (Table 1), meaning it fails to correctly leverage history on more than 70% of test cases. On the TTL (Test-Time Learning) subtask specifically, performance drops to 26.14%. These are systems that fundamentally cannot do their jobs because they lack an effective memory mechanism — not because they lack reasoning ability in the abstract, but because they cannot retain and access what they need to reason *about*.

### Why This Problem Is Challenging: The Two-Dimensional Memory Design Space

The paper introduces a useful unifying framework (Section 1) that characterizes any memory mechanism along two axes:

- **Memory state**: how historical information is stored — as text, as latent vectors, or as parameter updates.
- **Memory steering**: how stored information influences the backbone's reasoning — through the input context, through external pathways, or through internal computation.

This framework clarifies why the problem is difficult: the two dimensions trade off against each other in non-obvious ways. A method might excel at flexible, expressive storage (rich textual representations) but introduce retrieval noise and context-window pressure on the steering side. Another method might offer clean, aligned steering (direct parameter modification) but be too rigid to adapt as new information arrives. The paper's central claim is that **existing methods each optimize one dimension at the expense of the other**, and that what is needed is a mechanism that maintains a compact, dynamically evolving state *and* steers the backbone through a pathway tightly aligned with its internal computation.

### Where Prior Approaches Fall Short

The paper categorizes existing memory mechanisms into three paradigms, each with characteristic limitations (Section 1, elaborated in Section 6):

#### Textual Memory Mechanisms (TMMs): Flexible Storage, Fragile Steering

TMMs — including retrieval-augmented generation (Lewis et al., 2020), memory compression via summarization (Pan et al., 2024; LLMLingua-2), and structured memory banks (Zhong et al., 2024; MemoryBank) — externalize memory as text and re-inject it into the model's input context. The appeal is clear: text is human-readable, easy to inspect and debug, and requires no architectural modifications to the backbone. The paper acknowledges that early retrieval-augmented systems "demonstrate the effectiveness of scalable textual stores for knowledge-intensive generation" (Section 6).

However, the limitations are structural and inescapable:

- **Context-window pressure**: Every byte of retrieved or compressed memory competes with the current input for the model's finite attention budget. This is the "tokenized form" constraint the paper identifies — memory use is fundamentally limited by the model's effective context utilization capacity.
- **Compression loss and retrieval noise**: Summarizing or compressing history inevitably discards information. Retrieval-augmented approaches introduce noise when the retriever returns irrelevant or misleading passages. The paper's experimental results (Table 1) bear this out: BM25 RAG achieves only 44.56% average score, LLMLingua-2 gets 42.96%, and MemoryBank gets 43.88% — all modest improvements or degradations over the base model's 46.79%. On MemoryAgentBench specifically, these methods show "inconsistent gains" that the authors attribute to retrieval noise and information loss from compression.
- **No true state maintenance**: Textual memory entries are snapshots, not continuously updated states. There is no mechanism for incrementally refining a representation as new information arrives — each retrieval starts fresh from the stored text.

#### Outside-Channel Memory Mechanisms (OMMs): Latent Storage, Decoupled Steering

OMMs (Wu et al., 2022; Memorizing Transformers; Wang et al., 2023; LongMem; Wei et al., 2026; MLP Memory) store memory in latent vector form outside the backbone and interact via separate retrieval or reader pathways. This avoids the tokenization bottleneck — memory is not forced through the input context — and can preserve richer internal representations than textual summaries.

But the paper identifies a different set of weaknesses:

- **Retrieval overhead and fusion complexity**: The memory interacts with the backbone through a separate pathway, requiring explicit retrieval operations (sometimes approximate kNN, as in Memorizing Transformers) and dedicated fusion mechanisms. This introduces computational overhead and engineering complexity.
- **Representation mismatch**: Stored representations (encoded at some past time) may not align well with the current input representation, especially as the backbone's internal state evolves. The paper notes that this creates "possible mismatch between stored and current representations" (Section 6).
- **Limited sequential accumulation**: The MLP Memory baseline in particular (Table 1) performs poorly (22.85% average), which the authors attribute to its inability to "explicitly model long-range dependencies" and the information loss from "approximating instance-level retrieval" rather than maintaining a continuously updated state.

The empirical results confirm these concerns: MLP Memory achieves only 22.85% average score — *substantially worse* than the frozen backbone, suggesting that a poorly aligned external memory can actively degrade performance.

#### Parametric Memory Mechanisms (PMMs): Stable Steering, Static Storage

PMMs (Hu et al., 2022; LoRA; Li and Liang, 2021; Prefix-Tuning; Meng et al., 2022a,b; ROME, MEMIT) encode memory into additional model parameters — trainable adapters, prefixes, or targeted weight edits. Their advantage is a tight integration with the backbone's computation: parameter-level modifications directly influence internal representations with low overhead.

The limitation is equally clear: **static storage**. Once trained, these parameters are fixed. They cannot evolve as new information arrives during a conversation or an agent trajectory. The paper draws a sharp distinction (Section 6):

> "Their write granularity is also less aligned with interaction history, which often unfolds at token-, message-, or segment-level resolution. As a result, parametric memory often acts as a persistent modification to model behavior, rather than a state-conditioned memory mechanism whose influence changes with the current history."

In other words, PMMs can make the model *behave differently in general*, but they cannot make it *remember what just happened in this specific interaction*. The empirical results (Table 1) reflect this: Context2LoRA achieves 44.90% average score — slightly below the frozen backbone — and is described as tending to "generalize less robustly across tasks" because its memory is "statically encoded in parameters and can overfit to training distributions." MemGen performs even worse at 30.66%, with the HotpotQA scores dropping dramatically to 5.36% EM — evidence that the static memory interferes with the model's existing capabilities rather than augmenting them.

### The Unified Failure Mode

Stepping back, the paper's analysis implies a common thread across all three paradigms: **the memory state and the memory steering mechanism are optimized independently, without considering how they interact under the constraints of a frozen backbone**. TMMs have expressive, updatable state (text) but force that state through the bottleneck of tokenized context. PMMs have clean, aligned steering (parameter updates) but cannot update their state online. OMMs attempt to solve both problems but introduce representational misalignment between the external store and the backbone's internal computation.

The paper's diagnosis is that the field needs a mechanism where:
1. The memory state is **compact, dynamically updatable, and maintained online** — it evolves with the interaction, not just retrieved from a static store.
2. The steering pathway is **tightly coupled to the backbone's internal attention computation** — not routed through external modules or appended to the input context, but directly modulating how the backbone attends and represents information.

### How δ-mem Positions Itself

δ-mem's design is a direct response to this diagnosis. Rather than choosing between expressive state and aligned steering, it aims to provide both through a single mechanism:

- **Compact online state**: Historical information is compressed into a fixed-size matrix (the online state of associative memory, or OSAM) that is updated continuously as tokens are processed via delta-rule learning. This avoids the context-window pressure of TMMs and the static nature of PMMs — the state *is* the memory, and it changes with every interaction.

- **Attention-coupled steering**: The state's readout is not retrieved as text or routed through an external module. Instead, it is projected into low-rank corrections to the backbone's query and output vectors in the attention computation itself. This means the memory signal participates directly in the forward pass, at the precise point where the model decides what information to attend to and how to represent its output.

- **Frozen backbone**: The entire mechanism operates alongside a frozen Transformer — no fine-tuning of the backbone parameters, no architectural replacement. This preserves the backbone's pretrained capabilities (important for the general-capability benchmarks) while adding memory functionality as a lightweight augmentation.

The paper draws an explicit contrast with LoRA (Section 6), perhaps the most comparable method structurally:

> "δ-mem is close to LoRA in its low-rank interface, but differs fundamentally in that LoRA's low-rank update is static, whereas δ-mem generates low-rank attention corrections from a compact online state at runtime."

This is the crucial distinction: LoRA's low-rank matrices are fixed after training and produce the same modification regardless of context. δ-mem's low-rank corrections are *generated dynamically* from the current memory state — the same δ-mem parameters produce different steering effects under different histories because the state $S_{t-1}$ encodes different historical information at each point in an interaction.

### What Makes This Work Non-Obvious

Several aspects of δ-mem's approach would not have been obvious from prior work:

**The "8×8 is enough" claim is genuinely surprising.** Prior memory mechanisms operate at vastly larger scales — textual memory stores full paragraphs, parametric memory can involve millions of parameters, and latent memory uses retrieval over large external banks. The finding that an 8×8 matrix (64 floating-point numbers total) can capture useful historical signals and improve performance on memory-heavy benchmarks is counterintuitive and would not have been predicted from existing scaling intuitions. It suggests that the key bottleneck is not storage capacity but *how the stored information interfaces with the backbone's computation* — a thesis that the paper's attention-correction design explicitly embodies.

**The coupling of delta-rule learning with attention correction is novel.** Delta-rule learning (Widrow-Hoff) is a classical associative memory update. Linear attention methods (including recent work on gated retention) have used similar update rules for sequence modeling, but typically as the primary sequence mixing mechanism, not as a *side memory* that augments a separate full-attention backbone. The paper's architecture — where a delta-rule memory reads from and writes to a compressed state, while the backbone continues to use standard quadratic attention over a limited context — represents a hybrid design that combines the complementary strengths of both mechanisms: stable long-range memory from the delta-rule state, and precise local attention from the standard Transformer.

**The difficulty-adaptive approach to writing granularity is a practical insight.** The paper's three writing strategies (token-level, segment-level, and multi-state) are not simply architectural variants; they reflect different assumptions about the temporal structure of memory. Token-level writes preserve fine detail but are sensitive to noise. Segment-level writes smooth out noise but lose precision. Multi-state writes reduce interference by partitioning information across parallel states. The finding that different strategies work better for different model scales (SSW for Qwen3-8B, MSW for SmolLM3-3B, as shown in Table 2) suggests that the optimal memory granularity depends on the backbone's representational capacity — a relationship that would not have been obvious without this empirical investigation.

### The Broader Context: Test-Time Memory as an Understudied Dimension

The paper's positioning implicitly argues that test-time memory has been relatively neglected compared to other aspects of LLM scaling. While the field has invested enormous effort in pretraining compute scaling laws (Hoffmann et al., 2022), context window extension (through architectural innovations like sparse attention or recurrent memory), and post-training adaptation (RLHF, instruction tuning), the specific problem of *online memory during deployment* — maintaining and using a compact state that accumulates over an interaction — has received less systematic attention. The paper's three-paradigm taxonomy (TMMs, OMMs, PMMs) makes this gap visible: each paradigm repurposes techniques originally developed for other problems (retrieval, external knowledge, parameter-efficient fine-tuning) rather than designing a mechanism from first principles for online memory.

δ-mem's contribution, in this light, is not just a new method but a conceptual reframing: **memory can be understood as a compact online state whose primary function is to modulate attention computation**, rather than as text to be retrieved, vectors to be fused, or parameters to be frozen. This reframing opens a design space — explored through the ablations in Section 5 on which attention components to correct, at which layers, and with what writing granularity — that prior work had not systematically investigated.

## 3. Technical Approach

### 3.1 Reader Orientation

δ-mem is a lightweight add-on module that sits alongside a frozen Transformer language model and gives it a **dynamic, compressed memory** of everything it has seen so far in an interaction — like a tiny external notebook that gets updated in real time and can subtly influence what the model pays attention to. The problem it solves is that standard LLMs either lose track of long interaction histories (because the context window is finite or poorly utilized) or require expensive architectural overhauls to maintain memory; δ-mem's solution is to compress the entire history into a **fixed-size matrix** (as small as $8 \times 8$), update it continuously using a classic learning rule as new information arrives, and inject the memory signal directly into the model's attention computation through low-rank corrections — all without modifying the backbone's pretrained parameters.

### 3.2 Big-Picture Architecture (Diagram in Words)

The δ-mem system has four major components that operate in a strict per-token cycle within a frozen Transformer backbone:

1. **Memory Projection (Section 3.1)**: At each token position, the backbone's hidden state $x_t$ is projected into a low-dimensional memory space, producing three vectors — a **query** ($q_t^m$) for reading from memory, a **key** ($k_t^m$) and **value** ($v_t^m$) for writing to memory — plus a **write gate** ($\beta_t$) that controls how strongly new information overwrites old information.

2. **Online State of Associative Memory ($S_{t-1}$)**: A fixed-size $r \times r$ matrix that holds the compressed history. This is the persistent memory — it persists across token positions and across separate interactions, being updated at each step rather than recomputed from scratch. Before writing the current token's information, the state is queried using $q_t^m$ to produce a **read vector** $r_t$ containing memory signals relevant to the current input.

3. **Attention Steering (Section 3.3)**: The read vector $r_t$ is projected through two lightweight linear layers to produce **low-rank corrections** $\Delta q_t$ and $\Delta o_t$ that are added to the backbone's query and output vectors in the attention computation. This is where memory physically influences the model — not by adding text to the context, but by directly modulating what the attention mechanism attends to and what it outputs.

4. **Online State Update (Section 3.4)**: After the backbone's attention computation completes for the current token, the memory state is updated using a **gated delta rule** — the difference between the current token's value $v_t^m$ and what the old state predicted for the current key $k_t^m$ is used to correct the state, with the write gate $\beta_t$ controlling the update magnitude. This closes the loop, ensuring the state evolves to track the sequence.

Information flows strictly forward: Input $x_t$ → Memory projection ($q_t^m$, $k_t^m$, $v_t^m$, $\beta_t$) → Read from old state ($r_t = S_{t-1} q_t^m$) → Generate attention corrections ($\Delta q_t$, $\Delta o_t$) → Run backbone attention with corrected query → Update state ($S_t$) using $k_t^m$, $v_t^m$, $\beta_t$. The three writing strategies (TSW, SSW, MSW) vary **when and how** the state update occurs (every token, every segment, or into parallel sub-states), but the core cycle remains the same.

We will walk through the technical design in the following order, which mirrors the information flow through the system and builds understanding from the most fundamental mechanism outward:

- **First, the delta-rule update as the conceptual foundation** (Section 2 preliminaries): Why δ-mem uses a learning-inspired update rule, how it naturally compresses key-value associations, and what the gated variant adds — this is the "engine" that makes the online state work, and understanding it first clarifies everything downstream.

- **Second, memory projections and gate generation** (Section 3.1): How the backbone's hidden state is transformed into the vectors and scalars that the memory state operates on — the interface between the backbone's internal representations and the memory's compressed space.

- **Fourth, attention steering through low-rank corrections** (Section 3.3): The critical design choice — why memory influences the backbone through query and output corrections rather than through other attention components, and how the same δ-mem parameters produce different effects under different histories.

### 3.4 Detailed, Sentence-Based Technical Breakdown

This is primarily a **systems design paper** whose core idea is that a compact online state, updated via delta-rule learning and coupled to attention computation through low-rank corrections, can serve as an effective memory mechanism for frozen Transformer backbones without requiring context extension, backbone modification, or heavy external retrieval.

#### The Delta-Rule Update as the Conceptual Foundation

Before describing how δ-mem integrates with the Transformer, we must understand the update rule that powers its memory state, since this is the mechanism that determines *what* the state stores and *how* it evolves. The paper presents this in Section 2 (Preliminaries), and it is essential to grasp before any of the architectural details make sense.

The delta rule (also known as the Widrow-Hoff learning rule) is a classic algorithm for learning associations between inputs and outputs through iterative error correction. In δ-mem's context, the "input" is a key vector $k_t$ representing what information the current token can be identified by, and the "output" is a value vector $v_t$ representing the information itself that should be retrieved when the key is matched. The memory state $S_t$ is a matrix that, when multiplied by a key, should produce an approximation of the associated value. This is an **associative memory**: the matrix $S$ stores key-value pairs by learning to map keys to values.

**The prediction (reading) step.** Given a key $k_t \in \mathbb{R}^r$ and the state from the previous time step $S_{t-1} \in \mathbb{R}^{r \times r}$, the state's prediction of the associated value is simply the matrix-vector product:

$$\hat{v}_t = S_{t-1} k_t$$

where $\hat{v}_t \in \mathbb{R}^r$ is the predicted value, $S_{t-1} \in \mathbb{R}^{r \times r}$ is the memory state before processing token $t$, and $k_t \in \mathbb{R}^r$ is the current token's memory key.

**What it computes:** a linear readout from the associative memory — the state matrix multiplies the key to produce a prediction of what value should be associated with that key, given everything the state has learned from previous tokens. This is a single matrix-vector product, so its cost is $O(r^2)$ and independent of how many tokens have been processed.

**Why this form:** linear readout is the simplest associative memory operation that supports superposition — multiple key-value associations can be stored in the same matrix because they occupy different directions in the $r$-dimensional key space. If the keys were orthogonal, the state could store $r$ perfectly independent associations without interference. In practice, keys are not orthogonal, so the state learns a compromise that minimizes prediction error across all seen associations, weighted by how recently and how strongly each was encoded.

**The update (writing) step.** After reading, the state is updated to reduce the prediction error for the current key-value pair. The delta-rule update treats the state as the parameter of a linear model and takes one gradient descent step on the squared prediction error:

$$\mathcal{L}_t(S) = \frac{1}{2} \|S k_t - v_t\|^2$$

$$S_t = S_{t-1} - \beta_t \nabla_{S_{t-1}} \mathcal{L}_t(S_{t-1}) = S_{t-1} + \beta_t (v_t - S_{t-1} k_t) k_t^\top$$

where $\mathcal{L}_t(S)$ is the instantaneous squared error at token $t$, $\beta_t \in \mathbb{R}$ is the learning rate (write strength) at token $t$, $v_t \in \mathbb{R}^r$ is the target value for the current token, and $k_t^\top$ denotes the transpose of the key vector.

**What it computes:** a rank-1 update to the state matrix. The residual term $(v_t - S_{t-1}k_t) \in \mathbb{R}^r$ is the prediction error — how far off the state's prediction is from the target value. This error vector is then outer-producted with the key $k_t$ to form the update direction, and scaled by $\beta_t$. The result is added to the previous state.

**Why this form:** the outer product $(\text{error}) \times (\text{key})^\top$ ensures the update is aligned with the key direction — the state is modified only along the subspace spanned by the current key. If the state already perfectly predicts the value for this key, the error is zero and no update occurs. If the prediction is wrong, the state is adjusted in the direction that reduces error for this specific key, with the risk of slightly increasing error for other (non-orthogonal) keys — this is the classic stability-plasticity tradeoff in online learning. Using a single gradient step (rather than iterating to convergence) is crucial because (a) it makes the update $O(r^2)$ per token, and (b) it biases the state toward more recent information, which is desirable for memory — you want the state to track what happened recently, not what happened in the distant past if the two conflict.

**The gated extension.** The basic delta rule has no explicit forgetting mechanism — old associations persist until they are overwritten by conflicting new ones. The paper introduces a forget gate to directly control this:

$$S_t = \lambda_t S_{t-1} + \beta_t (v_t - S_{t-1} k_t) k_t^\top$$

where $\lambda_t \in \mathbb{R}$ is the retention factor (how much of the old state to keep) and $\beta_t \in \mathbb{R}$ is the write strength. The paper further constrains $\lambda_t = 1 - \beta_t$, tying retention and writing so that dimensions that actively write new information correspondingly forget old information.

**Why this gate matters:** without explicit forgetting, the state can become saturated — filled with outdated associations that interfere with new ones. The forget gate allows the state to "make room" for new information by decaying old contents. The coupling $\lambda_t = 1 - \beta_t$ creates a conservation principle: each dimension's capacity is split between retaining the past and encoding the present, preventing unbounded growth in the state norm and ensuring the state represents a weighted combination of recent history rather than an unweighted accumulation of all history.

**Dimensionality note:** the paper's main experiments use $r = 8$, meaning the state matrix is $8 \times 8$ (64 parameters total), and the key, value, and query vectors are all 8-dimensional. The compactness is a deliberate design choice — the thesis is that even this tiny state can capture useful historical signals, and the paper explicitly tests this claim via the context recovery experiment (Section 5.1) where the state substitutes for the entire explicit context.

#### Memory Projections and Gate Generation

Given a hidden state $x_t \in \mathbb{R}^d$ from the frozen Transformer backbone at position $t$ (where $d$ is the backbone's hidden dimension, e.g., 2560 for Qwen3-4B), δ-mem projects it into a much smaller memory space of dimension $r \ll d$ (with $r = 8$ in the main experiments). This projection serves two purposes: it compresses the information so the state stays small, and it creates a separate representational space where the associative memory dynamics (querying, predicting, updating) operate without directly interfering with the backbone's own representations.

The projection for the memory query, key, and value is:

$$q_t^m = \text{L2 norm}\left(\tanh(W_q^m x_t)\right)$$

$$k_t^m = \text{L2 norm}\left(\tanh(W_k^m x_t)\right)$$

$$v_t^m = W_v^m x_t$$

where $W_q^m, W_k^m \in \mathbb{R}^{r \times d}$ are learnable projection matrices mapping from the backbone's hidden dimension to the memory dimension, $W_v^m \in \mathbb{R}^{r \times d}$ is a learnable projection matrix for the value, $\tanh$ applies element-wise, and $\text{L2 norm}$ normalizes the resulting vector to unit length.

**What these compute:** three $r$-dimensional vectors from the current backbone hidden state. The query $q_t^m$ is what the model uses to "search" its memory — it represents what kind of historical information is relevant to the current input. The key $k_t^m$ is the "address" under which the current information should be stored — future queries will match against keys accumulated in the state. The value $v_t^m$ is the "content" to be stored — the information that should be retrieved when a future query matches this key. The three projections use separate weight matrices, allowing the model to learn distinct representations for reading (query), addressing (key), and content (value) — mirroring the query-key-value decomposition in standard attention but operating in the compressed memory space.

**Why apply $\tanh$ and L2 normalization to query and key?** The $\tanh$ function bounds the vector components to $[-1, 1]$, preventing extreme values from destabilizing the recurrent state updates. The L2 normalization constrains the vectors to lie on the unit sphere, which is critical for long-sequence stability: without normalization, the norms of query and key vectors could drift over thousands of tokens, causing the readout $S_{t-1} q_t^m$ and the update $S_{t-1} k_t^m$ to become numerically unstable. Normalization also makes the associative memory behave more like a cosine-similarity matcher — since keys are unit-norm, the matching between a query and the stored key associations is bounded and well-conditioned.

**Why is the value not normalized?** The value carries content information that can legitimately vary in magnitude — a strong association should produce a large prediction, and a weak one a small prediction. Normalizing the value would discard magnitude information that the attention steering mechanism can use.

**The write gate.** The strength of the memory update is also produced from the current hidden state:

$$\beta_t = \sigma(W_\beta x_t + b)$$

$$\lambda_t = 1 - \beta_t$$

where $W_\beta \in \mathbb{R}^{r \times d}$ is a learnable projection matrix, $b \in \mathbb{R}^r$ is a learnable bias vector, $\sigma$ is the sigmoid function (mapping outputs to $(0, 1)$), $\beta_t \in \mathbb{R}^r$ is the per-dimension write strength, and $\lambda_t \in \mathbb{R}^r$ is the per-dimension retention factor.

**What this computes:** an $r$-dimensional vector of gate values, one per memory dimension, each between 0 and 1. A dimension with $\beta_{t,i} \approx 1$ (and $\lambda_{t,i} \approx 0$) means "completely overwrite this dimension with new information; forget the past." A dimension with $\beta_{t,i} \approx 0$ (and $\lambda_{t,i} \approx 1$) means "preserve this dimension as-is; ignore the current token." Intermediate values produce a partial blend.

**Why dimension-wise gating?** Different dimensions of the memory state may encode different types of information — some dimensions might track stable facts that should persist across many tokens, while others might track local syntactic patterns that change rapidly. A single scalar gate would force all dimensions to update at the same rate, which is suboptimal. Dimension-wise gating lets the model learn to route stable information through some dimensions (with consistently low $\beta_t$) and transient information through others (with higher $\beta_t$). The coupling $\lambda_t = 1 - \beta_t$ (dimension-wise) ensures that each dimension independently maintains a conservation between retention and writing — the state norm in each dimension remains controlled.

**Design choice: generating gates from $x_t$ rather than making them learnable parameters.** If $\beta_t$ were a fixed parameter, the write strength would be the same for every token and every context — the model couldn't decide to write strongly when encountering surprising or important information and weakly when processing predictable filler tokens. By making $\beta_t$ a learned function of $x_t$, the model can contextually decide how much to update memory based on the content of the current input, which is essential for selective memory maintenance.

#### Reading from the Online State of Associative Memory

Before updating the state with the current token's information, δ-mem queries the *previous* state (which contains compressed history up through token $t-1$) using the current token's memory query:

$$r_t = S_{t-1} q_t^m$$

where $S_{t-1} \in \mathbb{R}^{r \times r}$ is the memory state after processing the previous token, $q_t^m \in \mathbb{R}^r$ is the current token's memory query (unit-norm), and $r_t \in \mathbb{R}^r$ is the read vector — the associative memory's response to the query.

**What it computes:** a weighted combination of all values stored in the state, weighted by how well each stored key matches the current query. Since $S_{t-1}$ is built from successive outer-product updates of the form $(\text{error}) \times k^\top$ and $v \times k^\top$ (see the state update equation expansion in Section 3.4), the matrix-vector product $S_{t-1} q_t^m$ effectively computes a sum over all past key-value associations, each weighted by the inner product $\langle k_\tau, q_t^m \rangle$ (the similarity between the past key and the current query). This is analogous to linear attention's key-value retrieval, but with the crucial difference that $S_{t-1}$ is maintained as an explicit state rather than recomputed from a KV cache.

**Why this is complementary to standard attention.** Standard self-attention computes attention weights between the current query and all keys in the explicit context window, producing a weighted sum of values from within that window. δ-mem's readout, by contrast, accesses information that may have been processed thousands of tokens ago and compressed into the state — information that may no longer be in the explicit context at all (as demonstrated in the context recovery experiment of Section 5.1, where historical context is completely removed and δ-mem still retrieves useful signals from the state alone). Standard attention gives precise, token-level retrieval within a limited window; δ-mem's readout gives approximate, compressed retrieval over an effectively unlimited history. The two mechanisms serve different temporal scales of memory.

**Why the read happens BEFORE the write.** This ordering ensures causality: the memory signal used at position $t$ depends only on information up through position $t-1$, never on the current token itself. This prevents the model from "cheating" by reading information it just wrote, and it makes the online state a proper causal hidden state that can be maintained during autoregressive generation without look-ahead.

**Cost independence.** Since $S_{t-1}$ is a fixed $r \times r$ matrix, the read operation costs exactly $r^2 = 64$ multiply-adds per token (for $r = 8$), regardless of whether the history contains 10 tokens or 10,000 tokens. This is the core efficiency advantage over context-window expansion: the computational cost of memory access does not grow with history length.

#### Steering Attention Through Low-Rank Corrections

The read vector $r_t$ is the memory signal — it encodes what the compressed history "thinks" is relevant to the current input. The critical design question is: **where and how should this signal influence the backbone's computation?** The paper's answer is to inject it as low-rank corrections to the backbone's attention mechanism, specifically to the query and output vectors.

**Generating the corrections.** The read vector is projected into correction terms via two lightweight linear mappings:

$$\Delta q_t = W_q^\Delta r_t$$

$$\Delta o_t = W_o^\Delta r_t$$

where $W_q^\Delta \in \mathbb{R}^{d \times r}$ maps from the memory space back to the backbone's hidden dimension for the query-side correction, and $W_o^\Delta \in \mathbb{R}^{d \times r}$ does the same for the output-side correction. Both are learnable parameters that are shared across all token positions and all sequences.

**What this computes:** two $d$-dimensional vectors that are low-rank because they are generated from the $r$-dimensional read vector — the rank of the correction is at most $r = 8$, whereas the full attention query and output have dimension $d$ (e.g., 2560). This is the "low-rank correction" the paper refers to: the correction is not an arbitrary $d$-dimensional vector but is constrained to lie in an 8-dimensional subspace of the full representation space, which prevents overfitting and limits the number of trainable parameters.

**Injecting the query-side correction.** The backbone's standard query computation is modified by adding the correction:

$$q_t^0 = W_Q x_t$$

$$\tilde{q}_t = q_t^0 + \frac{\alpha}{r} \Delta q_t$$

where $W_Q \in \mathbb{R}^{d \times d}$ is the backbone's frozen query projection, $q_t^0$ is the original query the backbone would have produced, $\alpha$ is a scalar hyperparameter (set to 16 in experiments), $r = 8$ is the memory dimension, and $\tilde{q}_t$ is the corrected query used in the actual attention computation.

**What this computes:** the corrected query is the backbone's original query plus a scaled correction derived from the memory readout. The scaling factor $\alpha / r$ is a design choice: without division by $r$, the correction magnitude would grow with the memory dimension, making hyperparameter transfer difficult across different $r$ values. With $\alpha = 16$ and $r = 8$, the effective scaling is $16/8 = 2$, meaning the memory correction can significantly shift the query direction.

**Why correct the query?** In standard attention, the query determines *what the model looks for* in the context — it's the "question" being asked of the keys and values. By adding a memory-derived correction, δ-mem allows the model to ask a *different question* when it has relevant history. For example, if the memory state contains information about a user's previously stated preferences, the corrected query might steer attention toward parts of the current context that are relevant to those preferences — effectively, the memory changes what the model considers important.

**Injecting the output-side correction.** After attention is computed with the corrected query, a second correction is applied to the attention output:

$$a_t = \text{Attn}(\tilde{q}_t, K_{\leq t}, V_{\leq t})$$

$$\tilde{y}_t = a_t + \frac{\alpha}{r} \Delta o_t$$

where $\text{Attn}$ is the backbone's frozen attention mechanism (standard scaled dot-product attention), $K_{\leq t}$ and $V_{\leq t}$ are the key and value matrices for all tokens up through position $t$ (within the explicit context window), $a_t$ is the standard attention output, and $\tilde{y}_t$ is the corrected output that feeds into the subsequent feed-forward network.

**What this computes:** the output-side correction adds a memory-dependent offset to whatever the attention mechanism produced. Even if the corrected query didn't manage to pull the right information from the context, the output correction can directly inject memory signals into the representation that will be processed by later layers.

**Why these two correction points (query and output) rather than all four attention components (query, key, value, output)?** The paper's head ablation study (Table 3) systematically tests all 15 combinations of correction injections across the four attention components (q, k, v, o). The full qkvo configuration achieves the best average score (48.05%), but the qo configuration achieves nearly the same (47.97%) with significantly fewer parameters (since it uses only two projection matrices rather than four). The paper explicitly states: "While qkvo yields the highest average score, its marginal gain over qo does not justify the extra parameter overhead. Thus, we default to qo for an optimal performance-efficiency trade-off." The output-only configuration (o) alone achieves 47.05% — better than any single-branch alternative — suggesting that the output-side correction is the most impactful single injection point. The query-only configuration (q) achieves 44.51%, substantially lower.

**Why are the corrections dynamic rather than static?** This is the key distinction from LoRA-style adapters. The projection matrices $W_q^\Delta$ and $W_o^\Delta$ are fixed after training, but their *input* $r_t$ depends on the memory state $S_{t-1}$, which varies with the sequence history. Therefore, the same trained parameters produce different corrections in different contexts — the correction at position $t$ depends on everything that happened before $t$. In a conversation about cooking, the corrections might steer attention toward recipe-relevant details; in a conversation about coding, the same matrices would produce different corrections because the memory state contains different key-value associations.

#### Writing into the Online State of Associative Memory

After the attention computation for the current position is complete, the memory state is updated to incorporate the current token's information. This is the "write" step that maintains the state as a running compression of the sequence. The update follows the gated delta rule introduced in Section 2, now with dimension-wise gating:

$$S_t = \text{Diag}(\lambda_t) S_{t-1} + \text{Diag}(\beta_t) (v_t^m - S_{t-1} k_t^m) (k_t^m)^\top$$

where $\text{Diag}(\lambda_t) \in \mathbb{R}^{r \times r}$ is a diagonal matrix with the retention factors $\lambda_{t,1}, \ldots, \lambda_{t,r}$ on the diagonal, $\text{Diag}(\beta_t) \in \mathbb{R}^{r \times r}$ is a diagonal matrix with the write strengths on the diagonal, $v_t^m - S_{t-1} k_t^m \in \mathbb{R}^r$ is the prediction error (target value minus predicted value), and $(k_t^m)^\top \in \mathbb{R}^{1 \times r}$ is the transposed key.

**What this computes:** a matrix update where each row of the state is updated independently. The old state is first scaled (each row $i$ multiplied by $\lambda_{t,i}$), and then a rank-1 correction is added (each row $i$ of the error vector is multiplied by $\beta_{t,i}$ and then outer-produced with the key). The result is the new state $S_t$ that reflects everything up through position $t$.

**The three-term expansion.** The paper expands the update to clarify the roles of each component:

$$S_t = \underbrace{\text{Diag}(\lambda_t) S_{t-1}}_{\text{retention}} - \underbrace{\text{Diag}(\beta_t) S_{t-1} k_t^m (k_t^m)^\top}_{\text{removal of old prediction}} + \underbrace{\text{Diag}(\beta_t) v_t^m (k_t^m)^\top}_{\text{write new value}}$$

**Retention term:** $\text{Diag}(\lambda_t) S_{t-1}$ simply carries forward the previous state, scaled per dimension. Dimensions with $\lambda_{t,i} \approx 1$ preserve their old contents; dimensions with $\lambda_{t,i} \approx 0$ discard them.

**Removal term:** $-\text{Diag}(\beta_t) S_{t-1} k_t^m (k_t^m)^\top$ subtracts whatever the old state would have predicted for the current key. This prevents double-counting: if the state has already learned an association for this key direction, the old association is removed before the new one is written. Without this term, writing a new value for an existing key would result in the sum of old and new associations, creating interference.

**Write term:** $+\text{Diag}(\beta_t) v_t^m (k_t^m)^\top$ adds the new key-value association, scaled by the write strength. This is the actual encoding of the current token's information into the state.

Together, the three terms implement **error-correcting memory**: the state is modified only to the extent that its prediction was wrong, and the modification replaces the incorrect prediction with the correct value — the net effect is that the state's mapping from $k_t^m$ to the predicted value shifts toward $v_t^m$ by an amount proportional to $\beta_t$.

**Row-wise view.** The paper provides an alternative formulation that makes the dimension-wise independence explicit. Let $s_t^{(i)} \in \mathbb{R}^{1 \times r}$ denote the $i$-th row of $S_t$:

$$s_t^{(i)} = \lambda_{t,i} s_{t-1}^{(i)} + \beta_{t,i} \left(v_{t,i}^m - s_{t-1}^{(i)} k_t^m\right) (k_t^m)^\top$$

**What this reveals:** each row of the state (corresponding to one dimension of the value) is updated independently with its own retention and write gates. The $i$-th row stores associations between keys and the $i$-th component of the value. A high $\beta_{t,i}$ means this particular value component is being actively rewritten; a low $\beta_{t,i}$ means it is being preserved. This dimensional independence allows the state to simultaneously maintain stable information in some dimensions (e.g., user identity — constant $\beta_t \approx 0$) while rapidly updating others (e.g., current topic — high $\beta_t$).

**Why the write happens AFTER the attention computation rather than before.** The read operation at position $t$ uses $S_{t-1}$, ensuring the memory signal does not include information from the token being processed. If the write happened before the read, the model would get a "peek" at the current token through the memory state, which would break causality (the model could use the current token to answer a question about the current token, rather than relying on history). This ordering also ensures that during autoregressive generation, the memory state at the start of generating token $t$ contains only information from the prefix (context + previously generated tokens), which is exactly the information available to the model at that point.

#### Writing Granularity of the Online State

The delta-rule update described above defines *how* to write, but an equally important design choice is *when* to write — at what temporal granularity the state is updated. The paper explores three strategies, each with different assumptions about the structure of memory-worthy events.

**Token-State Write (TSW).** The most fine-grained approach: update the state at every single token position.

$$S_t = \text{Update}(S_{t-1}, x_t)$$

where the Update function is the gated delta-rule procedure described in Section 3.4, applied to the hidden state $x_t$ at each position.

**What happens:** every token triggers a read-write cycle. For a 1000-token interaction, the state is updated 1000 times. This preserves maximum temporal resolution — even single-token events can be captured (e.g., a name mentioned once, a specific number).

**The tradeoff:** because every token triggers a write, the state is sensitive to noise. Formatting tokens (newlines, separators), repeated words, and other low-information tokens still modify the state, potentially overwriting or diluting important information. The paper notes that TSW is "more easily affected by format symbols, repeated expressions, and short-term noise" (Section 3.5).

**Sequence-State Write (SSW).** Instead of writing at every token, group tokens into semantic segments (messages in a conversation, paragraphs in a document) and write once per segment using the segment's average representation.

Let $M^{(j)}$ denote the set of token indices in the $j$-th message segment. The segment representation is:

$$\bar{x}^{(j)} = \frac{1}{|M^{(j)}|} \sum_{t \in M^{(j)}} x_t$$

$$S^{(j)} = \text{Update}(S^{(j-1)}, \bar{x}^{(j)})$$

where $|M^{(j)}|$ is the number of tokens in the segment, and $\bar{x}^{(j)}$ is the mean hidden state across all tokens in the segment.

**What happens:** a 10-message conversation produces only 10 state updates, regardless of how many tokens each message contains. The averaging smooths out token-level noise — individual formatting tokens or stutters are absorbed into the segment mean and don't produce independent state modifications.

**The tradeoff:** fine-grained details within a segment are lost. If a message says "My phone number is 555-0123, and I prefer email on weekdays," the state receives a single averaged representation that blends the phone number and the preference. The model may be able to separate them because the key and value projections extract different aspects of the averaged representation, but the signal is less precise than if each fact received its own dedicated write.

**Why this matters for deployment:** in conversational and agent settings, the natural unit of interaction is the message or turn, not the token. SSW aligns the memory update granularity with the interaction granularity, which the paper argues leads to "more stable" state evolution.

**Multi-State Write (MSW).** Rather than changing the temporal granularity, MSW changes the organizational structure of memory — instead of one state that must store everything, maintain multiple parallel sub-states that can specialize:

$$S_t = \{S_t^{(1)}, \ldots, S_t^{(N)}\}$$

$$S_t^{(i)} = \text{Update}^{(i)}(S_{t-1}^{(i)}, x_t)$$

$$r_t = \text{Concat}(r_t^{(1)}, \ldots, r_t^{(N)})$$

where $N$ is the number of parallel states (set to 4 in experiments), each $S_t^{(i)} \in \mathbb{R}^{r \times r}$ is an independent sub-state with its own update parameters ($W_q^{m,(i)}$, $W_k^{m,(i)}$, $W_v^{m,(i)}$, $W_\beta^{(i)}$), $r_t^{(i)} = S_{t-1}^{(i)} q_t^{m,(i)}$ is the readout from the $i$-th sub-state, and Concat concatenates the $N$ read vectors into a single $Nr$-dimensional vector that feeds into the attention correction projections.

**What happens:** the model maintains four separate associative memories, each with its own projections and gating. Each sub-state can learn to track different types of information — one might specialize in factual content, another in task progress, another in user preferences, and another in conversational flow. The readouts are concatenated, so the attention corrections receive a combined memory signal that covers multiple aspects of the history.

**Why this reduces interference:** in a single-state design, writing a new fact (e.g., a changed user preference) might partially overwrite an unrelated old fact (e.g., a deadline) if their key representations overlap. With multiple sub-states, the model can route different types of information to different sub-states, so overwriting in one sub-state does not affect others. The paper's results (Table 2) show that MSW provides the largest gains on the smallest backbone (SmolLM3-3B: from 26.08% to 36.96%, a 10.88-point improvement), which is consistent with the hypothesis that smaller models have more difficulty disentangling information in a single compressed state and benefit more from explicit decomposition.

**Parameter cost of MSW:** each sub-state requires its own projection matrices, so MSW with $N=4$ uses approximately $4 \times$ the parameters of TSW or SSW. The paper reports (Appendix C, Figure 4) that TSW and SSW use 4.87M trainable parameters, while MSW uses 19.47M — still only 0.48% of the backbone's parameters, but notably more than the single-state variants.

**How the writing strategies relate to the experimental findings.** Table 2 shows that the optimal strategy depends on the backbone scale: Qwen3-4B-Instruct achieves its best average with TSW (51.66%), Qwen3-8B with SSW (50.86%), and SmolLM3-3B with MSW (36.96%). The pattern suggests that stronger backbones can handle the noise of token-level updates (TSW) because their hidden states are already good at separating signal from noise, while weaker backbones benefit from the explicit decomposition of MSW. The paper interprets the Qwen3-8B preference for SSW as evidence that "for backbones with stronger inherent reasoning, segment-level writing smooths state updates and effectively mitigates token-level noise" — the bigger model doesn't need the fine resolution and instead benefits from the stability of segment-level writes.

#### Training Objective

δ-mem is trained on standard language modeling data, but with a crucial procedural difference from standard fine-tuning: the training examples are structured to teach the model to rely on the memory state rather than on explicit context.

**Training data construction.** The paper uses the shortest 2,219 samples from QASPER (Dasigi et al., 2021), a dataset of information-seeking questions about research papers, with a maximum sequence length of 8,269 tokens. Each training example consists of a context $C$ (the research paper text) and a question-answer pair $(Q, Y)$ where $Y$ is the target response.

**The critical training protocol.** During training, the context $C$ is processed token-by-token through the frozen backbone, and δ-mem writes each token's information into the online state — producing the final context-state $S_C$. Then, for the prediction phase (where the model generates $Y$ given $Q$), **the context is NOT provided as explicit input**. The backbone receives only the query $Q$ and the previously generated response tokens $y_{<j}$, while the memory state $S_C$ (containing compressed context) steers attention through δ-mem's correction mechanism.

This is stated explicitly in the paper (Section 3.6):

> "For each example, the context tokens are first written into the online state, producing $S_C$, while they are not replayed as explicit backbone input during prediction. The frozen backbone only receives the query $Q$ and response $Y$, and the stored state steers attention through δ-mem."

**Why this protocol?** If the context were included as explicit input during prediction, the model could learn to ignore the memory state and rely on the context tokens — δ-mem would become vestigial. By removing the context during prediction and forcing the model to depend on the memory state, the training procedure ensures that δ-mem learns to compress and retain useful information. This is a form of **information bottleneck training**: the model must learn to pass relevant signals through the narrow $r \times r$ bottleneck of the online state, because that's the only source of historical information available at prediction time.

**The loss function.** The training objective is standard autoregressive cross-entropy over the response tokens:

$$\mathcal{L}_{\text{SFT}} = -\sum_{j=1}^{|Y|} \log p_{\phi, \theta}(y_j \mid Q, y_{<j}, S_C)$$

where $\phi$ denotes the **frozen** backbone parameters (not updated during training), $\theta$ denotes the trainable δ-mem parameters (the projection matrices $W_q^m$, $W_k^m$, $W_v^m$, $W_\beta$, $W_q^\Delta$, $W_o^\Delta$, and the bias $b$), $y_j$ is the $j$-th token of the target response, $Q$ is the query, $y_{<j}$ are the previously generated response tokens, and $S_C$ is the memory state after processing the entire context.

**What this computes:** the negative log-likelihood of the target response under the model's autoregressive distribution, summed over all response tokens. The model's probability distribution over the next token depends on the query, the previously generated tokens (provided as explicit input), and the memory state (injected through attention corrections). Only the δ-mem parameters $\theta$ receive gradient updates; $\phi$ is frozen.

**Why standard SFT loss rather than a specialized memory loss?** The delta-rule update is not itself trained — it's a fixed algorithmic procedure (gated gradient descent) during both training and inference. The trainable parameters control *what* gets written (the projections) and *how* the readout is used (the correction projections), but not the update mechanism itself. The SFT loss provides a single, end-to-end training signal: the only way for the model to reduce loss is to learn projections that (a) encode useful information into keys and values, (b) retrieve relevant information via queries, and (c) translate retrieved information into effective attention corrections — all without explicit supervision on any of these intermediate steps. This is end-to-end learning of a memory subsystem through the pressure of a downstream task.

**Training hyperparameters (from Appendix A).** The paper reports: training for one epoch on the 2,219-sample QASPER split, maximum backbone training sequence length of 512 tokens, memory write budget of 8,192 tokens, $r = 8$, $\alpha = 16$, applied to query and output branches only. Training infrastructure: 8 × A800 GPUs, bfloat16 precision, DeepSpeed ZeRO-2, fused AdamW optimizer, peak learning rate of $2 \times 10^{-4}$ with cosine decay, warmup ratio of 0.1, per-device batch size of 1 with 4 gradient accumulation steps (effective global batch size of 32), random seed 42.

**Notable hyperparameter choices.** The learning rate of $2 \times 10^{-4}$ is relatively high for fine-tuning — typical LoRA fine-tuning uses $1 \times 10^{-4}$ to $5 \times 10^{-5}$ — which may reflect the fact that the δ-mem parameters are randomly initialized (not warm-started from pretrained weights) and need larger updates to learn the memory projections from scratch. The memory write budget of 8,192 tokens means the state can compress up to 8K tokens of context during training, even though the prediction-time input is limited to 512 tokens — this asymmetry (large memory state, small explicit context) reinforces the training pressure to rely on memory.

**What is NOT trained.** The frozen backbone parameters $\phi$ receive no updates. The delta-rule update mechanism (the gated SGD step) has no trainable parameters — the gates $\beta_t$ and $\lambda_t$ are generated by a learned function, but the update arithmetic itself is fixed. This separation — learned projections for what to store, algorithmic updates for how to store it — is a deliberate design choice that constrains the memory mechanism to behave in an interpretable, analytically tractable way while still allowing the content of memory to be task-optimized.

#### Summary of Design Choices and Their Justifications

- **Delta-rule update over alternative state update rules:** The delta rule is the simplest update that supports associative memory with error correction and superposition. Alternatives like simple averaging ($S_t = \frac{t-1}{t} S_{t-1} + \frac{1}{t} v_t k_t^\top$) would equally weight all tokens and lose recency sensitivity. A full Kalman filter would require maintaining and inverting a covariance matrix, which is $O(r^3)$ rather than $O(r^2)$. The delta rule occupies a sweet spot: computationally cheap, analytically well-understood, and empirically effective for online learning.

- **Dimension-wise gating over scalar gating:** Allows different memory dimensions to operate at different timescales, enabling the state to simultaneously maintain stable facts (low $\beta$, high $\lambda$) and track transient events (high $\beta$, low $\lambda$) without interference.

- **Query and key normalization via $\tanh$ + L2 norm:** Prevents numerical instability in long sequences by bounding vector magnitudes and constraining the readout to a well-conditioned range. Without normalization, the state's eigenvalues could grow or shrink exponentially over thousands of tokens, leading to exploding or vanishing readouts.

- **Value not normalized:** Preserves magnitude information that carries meaningful signal about association strength.

- **Read-before-write ordering:** Enforces causality and prevents information leakage from the current token into the memory signal.

- **Low-rank attention corrections over full-rank corrections:** Limits the parameter count (two $d \times r$ matrices instead of $d \times d$) and prevents the memory mechanism from learning to simply replace the backbone's attention rather than augmenting it. The low-rank constraint forces the memory signal to operate in a compact subspace, which also regularizes training.

- **Query and output correction points over key and value:** The head ablation (Table 3) empirically justifies this: qo achieves nearly the same performance as qkvo (47.97% vs. 48.05%) with half the parameters. Modifying the query influences what the model attends to; modifying the output influences what the model represents after attention — together, these cover the input and output sides of the attention block.

- **Context-removed training protocol over context-included:** Forces the model to learn to compress useful information into the state rather than relying on explicit context. This is the key training trick that makes the memory state actually useful — without it, the model would learn to ignore the memory signal.

- **Gates generated from $x_t$ rather than learned as fixed parameters:** Makes memory writing context-dependent — the model can decide to write strongly on surprising tokens and weakly on predictable ones. A fixed write strength would be suboptimal because information density varies dramatically across tokens.

- **QASPER training data over other datasets:** QASPER provides long-context, information-seeking questions that require synthesizing evidence from a document — an ideal training signal for teaching a model to maintain and query a compressed memory of extended text.

## 4. Key Insights and Innovations

### Innovation 1: Compact Online State as a Viable Alternative to Context Expansion and External Retrieval

The dominant assumption in the memory-for-LLMs literature has been that effective memory requires scale — either scale in the context window (more tokens, more history) or scale in the retrieval infrastructure (large external stores, sophisticated indexing). This paper's most counterintuitive finding is that an **8 × 8 matrix** — 64 floating-point numbers — can capture enough historical signal to substantially improve performance on memory-heavy benchmarks, including recovering context-relevant information even when explicit history is entirely removed (Section 5.1, Figure 2: HotpotQA EM rises from 0.08% to 6.48% with no context).

This is not an incremental improvement on existing memory mechanisms; it is a **conceptual reframing of the memory capacity question**. The field has implicitly treated memory as a storage problem — how much information can we retain? — and therefore pursued solutions that maximize storage capacity: million-token contexts, trillion-token retrieval corpora, large external memory banks. δ-mem's results suggest the bottleneck may be **not storage capacity but interface quality**: how effectively can stored information modulate the backbone's internal computation? An 8 × 8 state that directly corrects attention queries and outputs (rather than being routed through tokenized context or external fusion modules) outperforms much larger memory systems (Table 1: MLP Memory at 3078M parameters achieves only 22.85% average, while δ-mem at 4.87M achieves 51.66%). The size of the memory matters less than how it connects to the model.

This reframing has significant implications beyond δ-mem itself. If a 64-parameter state can capture useful history, then future memory research should prioritize **tight coupling between memory state and backbone computation** over raw storage capacity. The paper's finding that the same δ-mem parameters produce different corrections under different histories (because the state $S_{t-1}$ varies — Section 3.3's key distinction from static LoRA) demonstrates that dynamic memory can be realized through a compact state plus smart routing, rather than through large-capacity storage. This is a **diagnostic insight** more than a performance gain: it tells the field to stop throwing capacity at the memory problem and start thinking about interface design.

### Innovation 2: Delta-Rule Learning as a Memory Update Mechanism for Frozen Transformers

Prior work on test-time memory for Transformers has used three approaches to state maintenance: (1) **no explicit state** — textual memory approaches retrieve from stored text without maintaining a continuously updated representation; (2) **fixed encoding** — parametric memory approaches encode memory once and keep it static; (3) **heuristic state updates** — outside-channel approaches that use custom reading and writing procedures but without a principled learning objective governing how the state evolves. δ-mem is the first to apply **delta-rule learning** — a classical associative memory algorithm — as the state update mechanism for a frozen Transformer backbone, and the choice is conceptually significant rather than merely expedient.

The delta rule (Widrow-Hoff) treats memory maintenance as **online regression**: the state $S$ is a linear model trying to predict values from keys, and each new token provides a training example that the model uses to correct its predictions via gradient descent. This framing brings three advantages that were absent from prior memory mechanisms:

**First, error-correcting rather than accumulating.** The standard approach in recurrent memory (e.g., simple exponential moving averages or unnormalized outer-product accumulation) is to add new information without explicitly removing old predictions that are now wrong. δ-mem's update explicitly subtracts the old prediction component along the current key direction before writing the new value (the three-term decomposition in Section 3.4). This means the state never accumulates contradictory information — it replaces outdated associations with updated ones, which is essential for memory in evolving contexts (e.g., tracking a changing user preference rather than averaging across all past preferences).

**Second, dimension-wise gating as learned timescale separation.** The paper's gated variant (Equation 10) allows each dimension of the memory state to independently control its write strength $\beta_{t,i}$ and retention $\lambda_{t,i}$, generated as a learned function of the current input. This is a **mechanistic answer to the stability-plasticity dilemma**: how should a memory system balance preserving old information against encoding new information? Prior memory mechanisms either fix this balance globally (e.g., a single decay rate for all textual memory entries) or avoid the dilemma by not maintaining a continuously updated state at all. δ-mem's solution — learnable, dimension-wise, context-dependent gating — lets the model discover through training which dimensions should track stable facts and which should track transient events. The coupling $\lambda_t = 1 - \beta_t$ further enforces a conservation principle that prevents unbounded state growth.

**Third, computational independence from history length.** Because the delta-rule update is $O(r^2)$ per token with $r = 8$ fixed, the cost of maintaining and querying the memory state does not grow with the length of the interaction. This is not a new algorithmic insight (it follows directly from the fixed-size state), but the paper's demonstration that a 64-parameter state trained with this update can meaningfully compress thousands of tokens of history (8,192 tokens of training context, Appendix A) makes the theoretical efficiency concrete.

The conceptual contribution here is the marriage of a **principled learning algorithm** (delta rule) with a **frozen Transformer backbone** — two paradigms that had previously been developed in separate literatures (classical associative memory and modern deep learning) with little cross-pollination for the specific problem of online LLM memory.

### Innovation 3: The Difficulty-Adaptive Writing Granularity as a Diagnostic on Memory Interference

The paper's investigation of three writing strategies — token-level (TSW), segment-level (SSW), and multi-state (MSW) — might appear at first glance to be an engineering ablation. But the pattern of results across backbone scales (Table 2) reveals something more fundamental: **the optimal temporal and organizational structure of memory depends on the backbone's representational capacity**, and this dependence is diagnostic of how interference operates in compressed memory states.

The empirical pattern is: Qwen3-8B (strongest backbone) performs best with SSW (segment-level writes), Qwen3-4B-Instruct with TSW (token-level writes), and SmolLM3-3B (weakest) with MSW (multi-state). The paper interprets this as evidence that stronger backbones can handle the noise of fine-grained updates but benefit from the smoothing of segment-level writes, while weaker backbones suffer from interference within a single state and need explicit decomposition into parallel sub-states.

This is an **insight about memory interference as a function of representational quality**. In a single compressed state ($r \times r$ matrix), different types of information — facts, preferences, task progress, local events — must share the same representational space. The quality of the projections $W_q^m$, $W_k^m$, $W_v^m$ determines how well these information types are disentangled in the key space, which in turn determines how much interference occurs when writing new information. A weaker backbone produces lower-quality hidden states $x_t$, which leads to less disentangled memory projections, which amplifies interference — and MSW mitigates this by explicitly partitioning the state. A stronger backbone produces better-hidden states, better-disentangled memory representations, and therefore less interference — so the additional capacity of MSW is unnecessary, and the noise reduction of SSW becomes the dominant factor.

This is not merely an incremental finding about writing strategies. It is a **diagnostic framework** for understanding when and why compressed memory fails: interference is not a fixed property of the memory mechanism but an interaction between the mechanism and the quality of the representations feeding into it. This explains why prior memory mechanisms showed inconsistent results across different backbone models — a textual memory approach that works well with GPT-4's representations might fail with a smaller model not because the mechanism is different but because the representations are more entangled. δ-mem's multi-strategy design makes this interaction visible and measurable.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The paper evaluates on five benchmarks spanning two categories. For **general reasoning and instruction following**: HotpotQA (Yang et al., 2018) — a multi-hop question answering dataset — evaluated using Exact Match (EM) and F1; GPQA-Diamond (Rein et al., 2023) — a graduate-level QA benchmark — evaluated using accuracy; and IFEval (Zhou et al., 2023) — an instruction-following benchmark — evaluated using prompt-level strict accuracy. For **memory-heavy evaluation**: MemoryAgentBench (Hu et al., 2025) — a benchmark for evaluating memory in LLM agents across extended interaction histories — evaluated using sample-weighted average of task-specific metrics across five categories (Accurate Retrieval, Test-time Learning, Long Range Understanding, Selective Forgetting, and multiple datasets within each; see Appendix A, Table 5 for the full breakdown); and LoCoMo (Maharana et al., 2024) — a very long-term conversational memory benchmark — evaluated using F1, with the adversarial question category excluded following Chhikara et al. (2025). The final average score in summary tables uses HotpotQA EM.

- **Base model(s).** Three backbone models of varying scales are used: Qwen3-4B-Instruct (Yang et al., 2025) — the primary backbone for most experiments; Qwen3-8B (Yang et al., 2025) — a larger variant for testing scalability; and SmolLM3-3B (Bakouch et al., 2025) — a smaller, multilingual long-context model for testing whether δ-mem provides outsized benefits on weaker backbones. All backbones are frozen during δ-mem training; only the δ-mem parameters (projection matrices, gate parameters, and correction matrices) are updated.

- **Metrics.** Task-specific metrics are used for each benchmark as described above. The final "Avg." column in Tables 1 and 2 is computed as the arithmetic mean of the benchmark scores, with HotpotQA counted using EM (not F1). For MemoryAgentBench, the aggregate score is the sample-weighted average across all subtasks (Appendix A, Table 5 details the per-dataset metrics: Accuracy for SH-Doc QA, MH-Doc QA, LongMemEval, EventQA, Detective QA, FactConsolidation-SH, FactConsolidation-MH; Recall@5 for Movie Recommendation; F1-Score for ∞Bench-Sum). For the context recovery experiment (Figure 2), HotpotQA is additionally broken down into Bridge and Comparison subsets, and LoCoMo is broken down into Multi, Temp, Open, and Single question types.

- **Baselines.** The paper compares against representative methods from all three memory paradigms (Section 4.1). For **textual memory**: BM25 RAG (Lewis et al., 2020) — retrieves relevant historical text via BM25 and prepends it to the input context; LLMLingua-2 (Pan et al., 2024) — compresses long histories into shorter textual context; and MemoryBank (Zhong et al., 2024) — maintains continuous interaction history through textual memory entries. For **parametric memory**: Context2LoRA (Hu et al., 2022; Back et al., 2026) — encodes memory into low-rank adapters (rank-8 for parameter-matched comparison; Appendix C, Figure 4 reports trainable parameter counts: Context2LoRA uses 5.90M parameters, or 0.15% of backbone); and MemGen (Zhang et al., 2025a) — weaves generative latent memory for self-evolving agents (46.20M parameters, 1.13% of backbone). For **outside-channel memory**: MLP Memory (Wei et al., 2026) — retrieves information in a separate module and fuses back into the model (3078.00M parameters, 76.40% of backbone). The frozen backbone without any memory augmentation ("Qwen3-4B-Instruct" in Table 1) serves as the primary reference point. All baselines are built on the same Qwen3-4B-Instruct backbone for the main comparison (Table 1).

- **Generation budget / compute accounting.** The paper does not use a "generation budget" in the traditional test-time compute sense — there is no best-of-N sampling or search over multiple completions. Instead, efficiency is measured through **parameter overhead** (trainable parameters as a percentage of backbone parameters, reported in Appendix C, Figure 4) and **inference throughput and memory usage** (tokens per second and GPU memory, reported in Appendix B, Figures 3a and 3b). The memory write budget during training is set to 8,192 tokens (Appendix A), meaning the online state is designed to compress up to 8K tokens of history. The maximum backbone training sequence length is 512 tokens. For inference efficiency measurements, prompt lengths of 4K, 16K, and 32K tokens with decode lengths of 64 and 256 tokens are tested.

- **Cross-validation / statistical protocol.** The paper does not employ cross-validation. The training uses a fixed split: the shortest 2,219 samples from QASPER (Dasigi et al., 2021), trained for a single epoch. The random seed is fixed to 42 for reproducibility. No statistical significance testing or confidence intervals are reported. The paper reports results from single runs rather than averaging over multiple random seeds. This is a notable limitation — for a paper making claims about relative performance across methods and backbones, the absence of variance estimates makes it difficult to assess whether observed differences (e.g., TSW at 51.66% vs. SSW at 51.44% in Table 1) are meaningful or within noise.

### Main Quantitative Results

#### Memory Mechanism Comparison on Qwen3-4B-Instruct (Table 1)

The central comparison establishes δ-mem's position relative to all three memory paradigms. The headline result: **δ-mem (TSW) achieves an average score of 51.66%, improving over the frozen Qwen3-4B-Instruct backbone (46.79%) by +4.87 absolute points and over the strongest non-δ-mem baseline, Context2LoRA (44.90%), by +6.76 points.** SSW (51.44%) and MSW (50.74%) are close behind, with all three δ-mem variants outperforming every baseline. The 1.10× multiplier over the frozen backbone and 1.15× over the strongest baseline reported in the abstract are computed from these numbers: 51.66 / 46.79 ≈ 1.104, and 51.66 / 44.90 ≈ 1.151.

The gains are concentrated on memory-heavy benchmarks. On MemoryAgentBench, δ-mem (MSW) improves from 29.54% (backbone) to 38.85%, a gain of +9.31 points. On LoCoMo, δ-mem (MSW) improves from 40.79% to 49.12%, +8.33 points, with the strongest improvements on the Multi subset (38.39% → 42.57%, +4.18) and Open subset (10.77% → 18.12%, +7.35). On HotpotQA, δ-mem (TSW) improves EM from 42.35% to 49.41% (+7.06) and F1 from 56.00% to 63.66% (+7.66). The GPQA-Diamond score is essentially preserved (39.39% → 40.40% for TSW, a marginal +1.01), and IFEval is slightly improved (81.89% → 82.99% for TSW).

The pattern across baselines reveals characteristic failure modes. Textual memory methods show **modest or negative impact**: BM25 RAG achieves 44.56% average — below the frozen backbone's 46.79%; LLMLingua-2 achieves 42.96% (worse than the backbone); and MemoryBank achieves 43.88%. The paper attributes this to "retrieval noise and information loss" from compressing memory into token space. Parametric memory methods also disappoint: Context2LoRA at 44.90% is below the backbone, and MemGen at 30.66% represents a dramatic degradation — its HotpotQA EM drops to 5.36% (from 42.35%), suggesting catastrophic interference with the backbone's existing capabilities. MLP Memory at 22.85% is the worst performer, which the paper attributes to its inability to "explicitly model long-range dependencies" and information loss from "approximating instance-level retrieval." These negative results for the baselines are as informative as δ-mem's positive results: they suggest that poorly-aligned memory mechanisms can actively harm performance, making δ-mem's consistent improvement (with no benchmark showing degradation vs. the backbone) a significant practical advantage.

**A critical caveat on MemoryBank:** Table 1 shows MemoryBank with partial results — only MemoryAgentBench and LoCoMo scores are reported (the IFEval and HotpotQA entries are marked with "—"). The paper does not explain why these baselines could not be evaluated on all benchmarks, which makes the comparison partially incomplete and raises questions about whether the missing evaluations would show different patterns.

**A critical caveat on BM25 RAG:** BM25 RAG shows no IFEval result (marked "—"), and its MemoryAgentBench and LoCoMo results (24.49% and 36.68% average, respectively) are below the backbone. This is surprising given that retrieval-augmented generation is typically baseline-competitive. The paper does not provide retrieval hyperparameters (top-k, chunk size) or analyze retrieval quality, making it difficult to assess whether this is a fair implementation of RAG or a suboptimal configuration.

#### Cross-Backbone Generalization (Table 2)

δ-mem is tested across three backbone scales to assess whether the benefits are specific to a particular model family or capacity. The headline: **δ-mem improves the average score on all three backbones**, with the magnitude of improvement inversely related to backbone capability.

On Qwen3-4B-Instruct: 46.79% → 51.66% (TSW), +4.87 points. On Qwen3-8B: 47.20% → 50.86% (SSW), +3.66 points. On SmolLM3-3B: 26.08% → 36.96% (MSW), +10.88 points — the largest absolute gain. The smaller backbone benefits disproportionately, consistent with the interpretation that weaker backbones produce more entangled representations and therefore benefit more from explicit memory decomposition (MSW) or from having any memory mechanism at all.

The writing strategy × backbone interaction is notable: Qwen3-8B achieves its best performance with SSW (50.86%), while Qwen3-4B-Instruct prefers TSW (51.66%) and SmolLM3-3B prefers MSW (36.96%). The paper interprets this as evidence that stronger backbones benefit from segment-level smoothing (noise reduction matters more than fine-grained resolution), while weaker backbones need explicit state partitioning to reduce interference. However, the gaps between writing strategies within each backbone are small — on Qwen3-4B-Instruct, TSW (51.66%) vs. SSW (51.44%) is a difference of only 0.22 points — making it unclear whether these preferences would be stable across different random seeds or training runs.

Context2LoRA is included as a reference baseline for each backbone. On Qwen3-4B-Instruct, it achieves 44.90% vs. δ-mem's 51.66% (TSW). On Qwen3-8B, 45.92% vs. δ-mem's 50.86% (SSW). On SmolLM3-3B, 34.94% vs. δ-mem's 36.96% (MSW). The gap narrows on the smallest backbone (only 2.02 points), suggesting that the advantages of dynamic memory over static parametric memory are most pronounced when the backbone has sufficient representational capacity to produce informative memory projections — a weak backbone produces poor projections regardless of whether the memory is static or dynamic, so the architectural advantage matters less.

**A missing comparison:** The paper does not report SmolLM3-3B or Qwen3-8B results for the textual or outside-channel baselines, nor for MemGen or MLP Memory. This limits the cross-backbone analysis to only one baseline (Context2LoRA), making it impossible to assess whether δ-mem's advantages over other paradigms generalize across model scales or are specific to the Qwen3-4B-Instruct setting.

#### Context Recovery (Figure 2, Section 5.1)

This experiment directly tests whether the online state retains useful historical information when explicit context is unavailable — a "pure memory" stress test. The setup: the original historical context is completely removed during evaluation, and only the compressed memory state $S_C$ (produced by writing the context into the online state during a preprocessing phase) is used to steer attention. The baseline is the frozen backbone with no context and no memory (effectively answering from the query alone), which achieves near-zero scores (0.08% EM on HotpotQA overall, verifying that the questions genuinely require historical context).

The headline: **δ-mem recovers non-trivial performance from the memory state alone.** On HotpotQA, overall EM rises from 0.08% (no context) to 6.48% with δ-mem, and overall F1 from 8.27% to 15.20%. On the Bridge subset (multi-hop questions requiring connecting evidence across sentences), EM rises from 0.08% to 3.97% and F1 from 6.25% to 11.05%. On the Comparison subset, gains are more modest: EM from 0.07% to 2.33% (+2.26) and F1 from 8.77% to 9.52% (+0.75). On LoCoMo, the overall average across question types improves from 3.49% to 8.05%. The largest LoCoMo gains are on Multi (1.06% → 9.62%, +8.56) and Single (7.90% → 11.48%, +3.58) questions, with Temporal showing a smaller gain (6.89% → 9.52%, +2.63) and Open showing modest improvement (11.97% → 18.00%, +6.03).

**What this demonstrates:** The 6.48% HotpotQA EM is far below the 49.41% achieved when explicit context is available (Table 1, TSW) — the memory state is not a replacement for context but a partial recovery mechanism. However, the improvement from essentially zero (0.08%) to 6.48% is approximately 80× the baseline, confirming that the $8 \times 8$ state genuinely encodes context-relevant signals that can be decoded and used, even when the original text is unavailable. This is the strongest evidence for the paper's "compact memory can capture useful history" thesis.

**Limitations of this experiment:** The paper does not report how the context recovery performance scales with state size $r$ — it would be informative to see whether a larger state (e.g., $r = 16$ or $r = 32$) recovers more context information, or whether the 6.48% represents a saturation point. Additionally, the experiment uses the same δ-mem that was trained with the context-removed protocol (Section 3.6), so it is specifically optimized for this no-context scenario; a δ-mem trained with context included during prediction might perform differently.

### Ablation Studies and Robustness Checks

**Attention component injection (head ablation, Table 3):** The paper tests all 15 combinations of injecting memory corrections into the query (q), key (k), value (v), and output (o) components of the attention block, evaluated on HotpotQA and LoCoMo with Qwen3-4B-Instruct. The full qkvo configuration achieves the best average score of 48.05% (HotpotQA overall EM: 49.94%, LoCoMo average: 46.15%). However, the qo configuration achieves nearly identical performance at 47.97% (HotpotQA overall EM: 49.41%, LoCoMo: 46.53%) — a difference of only 0.08 points. The paper selects qo as the default based on this marginal gap plus the parameter savings (two correction matrices vs. four). Among single-branch variants, output-only (o) performs best at 47.05%, substantially outperforming query-only (q: 44.51%), key-only (k: 42.19%), and value-only (v: 44.24%). The non-obvious finding is that the output correction alone accounts for most of δ-mem's benefit — adding the query correction on top provides only +0.92 points (from 47.05% to 47.97%), suggesting the primary mechanism is post-attention representational steering rather than attention-weight modulation. Modifying the key and value (kv) performs second-worst among all pairs at 43.85%, corroborating that the input side of attention is not where memory signals are most effectively injected.

**Insertion depth (Table 4):** δ-mem is applied to different contiguous layer ranges of the 36-layer Qwen3-4B-Instruct backbone: front 12 layers, middle 12 layers, back 12 layers, and all 36 layers. All-layer application achieves the best average score of 47.97% (the default configuration used in main experiments). Middle-layer application achieves 46.66% — outperforming front-layer (44.39%) and back-layer (44.06%) by substantial margins. The paper interprets this as evidence that intermediate layers "provide a particularly effective interface for memory injection, balancing semantic abstraction and task-specific computation," while front layers operate on "overly local representations" and back layers "leave insufficient depth for associative memory signals to propagate through subsequent computations." A caveat: the layer ranges are coarse (12-layer blocks in a 36-layer model), and the "middle" region spans layers 13–24 — the optimal insertion point might be narrower than 12 layers, and the specific optimal range might vary by backbone architecture and scale.

**Writing granularity (Tables 1, 2):** The three strategies — TSW, SSW, MSW — are evaluated across all three backbones. No single strategy dominates universally: TSW is best for Qwen3-4B-Instruct (51.66% vs. 51.44% for SSW), SSW is best for Qwen3-8B (50.86% vs. 50.68% for TSW), and MSW is best for SmolLM3-3B (36.96% vs. 36.67% for SSW). However, the gaps within each backbone are small — the maximum intra-backbone range is 2.22 points on SmolLM3-3B (36.96% MSW vs. 34.74% TSW), and on Qwen3-4B-Instruct it is only 0.92 points (51.66% TSW vs. 50.74% MSW). This suggests that the writing strategy is not the primary driver of δ-mem's effectiveness; all three strategies provide substantial gains over the frozen backbone, and the choice among them provides modest additional tuning.

**Parameter overhead (Appendix C, Figure 4):** δ-mem's trainable parameter count is compared against baselines. TSW and SSW use 4.87M parameters each (0.12% of the 4B backbone), MSW uses 19.47M (0.48%). In comparison, Context2LoRA uses 5.90M (0.15%), MemGen uses 46.20M (1.13%), and MLP Memory uses 3078.00M (76.40%). The key takeaway: δ-mem achieves the best performance with among the smallest parameter overheads, demonstrating that effective memory is not primarily a capacity problem.

**Inference efficiency (Appendix B, Figures 3a, 3b):** δ-mem achieves nearly the same GPU memory usage as the vanilla backbone and Context2LoRA across prompt lengths from 4K to 32K and decode lengths from 64 to 256 tokens. MLP Memory and MemGen require substantially more memory. In terms of decoding throughput (tokens per second), δ-mem is slower than the vanilla backbone and Context2LoRA — expected, since each step involves reading from and updating the online state — but "considerably faster and more stable than MemGen across all tested settings" (Appendix B). The paper does not provide exact throughput numbers in the text; they must be read from Figure 3a, which shows approximate values: at 32K prompt length with 256 decode tokens, δ-mem achieves roughly 12–15 tokens/second vs. roughly 18–20 for Vanilla and Context2LoRA, and roughly 3–5 for MemGen.

**State size robustness:** The paper does not ablate the state size $r$. All main experiments use $r = 8$, and no results are reported for $r = 4$, $r = 16$, $r = 32$, or larger. This is a notable omission — the "8×8 is enough" finding would be strengthened by showing the scaling curve: does performance plateau at $r = 8$, or would a larger state continue to provide gains? Does a smaller state ($r = 4$) collapse? Without this ablation, the claim that effective memory does not require large capacity rests on the single $r = 8$ data point.

**Training data robustness:** The paper uses only the QASPER dataset (2,219 shortest samples) for training. No ablation on training data size or domain is reported. Would δ-mem trained on a different dataset (e.g., narrative text, dialogue, code) transfer to the memory-heavy benchmarks? Is the QASPER choice — information-seeking questions about research papers — particularly well-suited to teaching compressed memory, or does the approach generalize? The cross-benchmark evaluation (Table 1) provides some evidence of generalization, but the source of the training signal is not isolated.

**Gate design ablation:** The paper does not ablate the dimension-wise gating against a scalar gate (single $\beta_t$ for all dimensions), the $\lambda_t = 1 - \beta_t$ coupling against independent $\lambda_t$ and $\beta_t$, or the learned gates against fixed gates. These choices are presented as design decisions without empirical justification.

**Negative result — ReST-like training is not explored:** The paper does not attempt iterative self-improvement or RL-based training for δ-mem, unlike some prior memory work. This is not a negative result per se, but the absence of exploration of whether additional training paradigms would improve or degrade the online state's quality is a gap.

### Critical Assessment

#### Claim 1: δ-mem improves average score to 1.10× the frozen backbone and 1.15× the strongest baseline.

The numbers are mathematically supported by Table 1: 51.66% (δ-mem TSW) / 46.79% (frozen backbone) ≈ 1.10, and 51.66% / 44.90% (Context2LoRA) ≈ 1.15. However, this claim is **overly precise relative to the experimental methodology**. The paper reports single-run results with no confidence intervals, no multiple seeds, and a fixed random seed of 42. The difference between TSW (51.66%) and SSW (51.44%) is 0.22 points — a tiny margin that would almost certainly be within noise if multiple seeds were run. The 1.10× and 1.15× figures should therefore be understood as **approximate effect sizes**, not as precise multipliers. The claim that δ-mem outperforms the strongest baseline is robust — the gap is 6.76 points — but the exact multiplier is sensitive to which δ-mem variant and which baseline are chosen (MSW at 50.74% vs. Context2LoRA at 44.90% gives only 1.13×, not 1.15×).

More fundamentally, the "strongest baseline" designation is questionable. Context2LoRA achieves 44.90%, which is **below the frozen backbone's 46.79%**. Calling a baseline that degrades performance relative to no memory at all the "strongest" is technically correct among the baselines tested, but it sets a low bar. The baselines appear to be weakly implemented or poorly tuned — BM25 RAG (44.56%), LLMLingua-2 (42.96%), and MemoryBank (43.88%) all underperform the backbone, which is not the expected behavior for retrieval-augmented methods on knowledge-intensive tasks. A well-tuned RAG baseline with appropriate chunking and retrieval depth might significantly outperform the frozen backbone and provide a more meaningful comparison. The paper's claim of 1.15× over the strongest baseline should be interpreted as "1.15× over the best of a set of baselines that all underperform the backbone" rather than "1.15× over competitive memory methods."

#### Claim 2: δ-mem achieves larger gains on memory-heavy benchmarks, reaching 1.31× on MemoryAgentBench and 1.20× on LoCoMo.

This claim is well-supported directionally but overstated numerically. On MemoryAgentBench, MSW at 38.85% vs. backbone at 29.54% gives 1.315× — the 1.31× figure is accurate. On LoCoMo, MSW at 49.12% vs. backbone at 40.79% gives 1.204× — the 1.20× figure is accurate. The gains on these benchmarks are genuinely large: +9.31 points on MemoryAgentBench and +8.33 on LoCoMo, compared to +1.01 on GPQA-Diamond and +1.10 on IFEval (TSW). The concentration of gains on memory-heavy tasks is the strongest empirical finding in the paper and is consistent across all three δ-mem variants and all three backbones.

However, the "memory-heavy" designation deserves scrutiny. HotpotQA, which the paper categorizes as a general reasoning benchmark (not memory-heavy), shows comparable gains: +7.06 EM points (42.35% → 49.41%), which is proportionally 1.17× — competitive with the LoCoMo gain. HotpotQA is a multi-hop reasoning benchmark that requires synthesizing information across a document; in δ-mem's training protocol (where context is removed during prediction and must be recovered from the state), HotpotQA becomes effectively a memory benchmark. The distinction between "memory-heavy" and "general" benchmarks is blurred by the evaluation protocol, making it difficult to cleanly attribute gains to memory specifically rather than to improved context utilization generally.

#### Claim 3: Effective memory does not require extending explicit context or heavy external retrieval modules.

The strongest evidence for this claim is the context recovery experiment (Figure 2): 6.48% HotpotQA EM from the state alone, compared to 0.08% without context. This demonstrates that the $8 \times 8$ state **does** encode useful historical signals that can be decoded to answer questions — an existence proof that compact, attention-coupled memory can work.

However, the claim is overstated relative to the actual deployment scenario. In the main experiments (Tables 1, 2), the explicit context is **still present** during evaluation — δ-mem adds memory corrections on top of standard attention over the explicit context window. The 49.41% HotpotQA EM (Table 1, TSW) is achieved with both the explicit context AND the memory state working together, not from the memory state alone. The claim "does not require extending explicit context" is true in the sense that δ-mem does not increase the context window, but it is misleading in the sense that δ-mem is not replacing the context — it's augmenting it. The context recovery experiment shows what the state can do alone (6.48%), which is far from competitive with context-included performance (49.41%), demonstrating that the memory state is a complement to, not a replacement for, explicit context.

Additionally, the training cost of building the memory state is not zero. The state is constructed by processing the entire context through the frozen backbone's forward pass (to obtain hidden states $x_t$ for the memory projections), which costs one full forward pass over all context tokens — essentially the same cost as processing the context normally. The efficiency claim is about **not having to reprocess the context during generation** (since the state substitutes for it in the attention corrections), but the initial encoding cost is not eliminated. For a single-turn QA scenario (like HotpotQA), this offers no efficiency advantage — you still process the context once. The advantages would emerge in multi-turn settings where the state persists across turns, but the paper does not include a multi-turn efficiency benchmark.

#### Claim 4: δ-mem preserves general capabilities while adding memory.

This claim is supported: IFEval remains essentially flat (81.89% → 82.99% for TSW, a +1.10 change), and GPQA-Diamond is marginally improved (39.39% → 40.40% for TSW, +1.01). There is no evidence of catastrophic forgetting or capability degradation — unlike MemGen, which drops HotpotQA EM from 42.35% to 5.36% (Table 1) and IFEval from 81.89% to 39.37%, demonstrating that poorly-aligned memory mechanisms can severely damage existing capabilities. δ-mem's preservation of general performance while improving memory performance is a genuine practical advantage.

However, the evaluation of "general capabilities" is narrow. Only IFEval and GPQA-Diamond are tested — instruction following and graduate-level QA. Common general capability benchmarks like MMLU, HellaSwag, ARC, or GSM8K are not evaluated. The claim that general capabilities are "largely preserved" (from the abstract) would be stronger with a broader capability evaluation, particularly including reasoning benchmarks that are sensitive to attention-quality degradation.

#### Weaknesses in the experimental design:

**Single training dataset.** All δ-mem variants are trained on only 2,219 QASPER samples. QASPER is a specific domain (scientific paper QA) with a specific structure (long documents, information-seeking questions). The paper provides no evidence that δ-mem trained on QASPER generalizes because of the memory mechanism rather than because of QASPER-specific heuristics. Training on an alternative dataset (e.g., narrative text, dialogue, or code) and showing comparable cross-benchmark performance would substantially strengthen the generality claim.

**No multiple random seeds.** All results are from a single run with seed 42. Differences of 0.22 points between TSW and SSW (Table 1, Qwen3-4B-Instruct) are almost certainly within run-to-run variance. The paper's conclusions about which writing strategy is optimal for which backbone are drawn from point estimates without evidence that the rankings are stable.

**Unclear baseline tuning.** The textual memory baselines (BM25 RAG, LLMLingua-2, MemoryBank) and outside-channel baseline (MLP Memory) perform worse than the frozen backbone, which is surprising and suggests suboptimal configuration. The paper does not report hyperparameter sweeps, retrieval depth, chunk size, or compression ratios for these baselines. Without evidence that the baselines are fairly tuned, the comparison is biased in favor of δ-mem.

**Missing ablation on state size $r$.** The claim that an $8 \times 8$ state is sufficient is central to the paper's thesis, but no experiments vary $r$ to show where performance saturates or collapses. This is the single most important missing experiment for validating the "compact memory" narrative.

**No multi-turn persistence evaluation.** The paper claims δ-mem enables memory "across extended interactions" (Section 1) and the state is "updated after each interaction" (Section 3), but the main evaluation uses single-turn or single-document setups. MemoryAgentBench and LoCoMo involve multi-turn interactions, but the paper does not isolate the contribution of inter-turn state persistence vs. intra-document state compression. An experiment that varies the number of turns while measuring whether performance degrades would directly test the online memory claim.

**Narrow backbone selection.** All backbones are from the Qwen/SmolLM families. Testing on a fundamentally different architecture (e.g., a Llama-based model, or a non-Transformer architecture) would strengthen the claim that δ-mem is architecture-agnostic.

**No comparison to simple context extension.** The paper motivates δ-mem partly by arguing that expanding the context window is "costly and often fails to ensure effective context utilization" (Section 1), but no experiment directly compares δ-mem on a frozen 512-token backbone against a backbone with context extended to 8,192 tokens (to match δ-mem's memory write budget). This comparison would directly test whether compact memory outperforms explicit context at the same effective history length. The context recovery experiment (Figure 2) partially addresses this by removing context entirely, but the more policy-relevant comparison is δ-mem with limited context vs. backbone with extended context.

#### Experiments that would strengthen the paper:

- **State size sweep:** $r \in \{4, 8, 16, 32, 64\}$ on at least one backbone and one benchmark to characterize the memory capacity scaling curve. This is the most important missing experiment.
- **Multi-seed evaluation:** 3–5 random seeds on the main results to establish variance and test whether the TSW/SSW/MSW rankings are stable.
- **Longer-context backbone baseline:** Compare δ-mem (backbone with 512-token context + 8K-token memory) against the same backbone with 8,192-token context and no memory mechanism, on HotpotQA or LoCoMo.
- **Training data ablation:** Train δ-mem on a non-QASPER dataset (e.g., narrative text) and evaluate on the same benchmarks to test domain transfer.
- **Multi-turn ablation on MemoryAgentBench:** Evaluate δ-mem performance as a function of turn count to isolate whether the state's incremental updating across turns (beyond within-document compression) provides measurable benefit.
- **Gate design ablation:** Compare dimension-wise gating vs. scalar gating, and coupled $\lambda_t = 1 - \beta_t$ vs. independent $\lambda_t$, $\beta_t$, to justify these design choices.
- **Broader capability evaluation:** Add MMLU, GSM8K, or HellaSwag to the general capability suite to more thoroughly test for capability preservation.
- **Well-tuned RAG baseline:** Implement BM25 RAG with hyperparameter tuning (chunk size, top-k) and possibly dense retrieval (e.g., using the backbone's own embeddings) to ensure a fair textual memory comparison.

## 6. Limitations and Trade-offs

### The Difficulty Estimation Cost Is Unaccounted for and Potentially Dominant

**The assumption or constraint.** The paper's memory mechanism depends on first processing the entire historical context through the frozen backbone to build the online state $S_C$ before it can be used to steer attention during generation. This is an explicit part of the training and inference protocol (Section 3.6): "the context tokens are first written into the online state, producing $S_C$, while they are not replayed as explicit backbone input during prediction." The memory write budget during training is set to 8,192 tokens (Appendix A), meaning the state is designed to compress substantial context — but only after that context has been fully processed token-by-token through the backbone's forward pass.

**The consequence.** This initial encoding step incurs a computational cost that is **identical to one full forward pass over the context** — exactly the same cost as simply including the context in the input window. For single-turn scenarios (like HotpotQA, where one document is read and one question is answered), δ-mem provides **no efficiency advantage whatsoever**: the context must still be processed to build the state, and the attention corrections add overhead on top of that. The paper's efficiency claims (Figures 3a, 3b in Appendix B) only measure the generation-phase cost — tokens per second and GPU memory during decoding — after the state has already been built. The upfront cost of state construction is not amortized across any of the reported metrics.

The efficiency advantages would only materialize in two scenarios that the paper does not directly evaluate: (1) **multi-turn interactions** where the state persists across turns, amortizing the initial encoding cost over many queries (only one state build for N turns rather than N × context processing); and (2) **pre-computed states** where contexts are encoded offline and the states are stored for later use. MemoryAgentBench and LoCoMo are multi-turn in structure, but the paper does not report the number of turns, the context length per turn, or break down the compute into state-building vs. generation phases — making it impossible to assess whether the amortization actually occurs in practice.

**What evidence exists in the paper.** Appendix B (Figures 3a, 3b) reports decoding throughput and GPU memory usage during generation only — not total end-to-end latency including state construction. The paper does not report wall-clock time for the full pipeline (context encoding + generation), FLOPs counts, or any metric that would capture the upfront cost. The training protocol's asymmetry (8,192 tokens of memory write budget vs. 512 tokens of backbone input) reinforces that the state must process far more tokens than the generation phase operates on, but this extra computation is never accounted for in the efficiency analysis.

**Mitigation status.** Not addressed. The paper acknowledges in Section 3.5 that the memory write budget is 8,192 tokens (Appendix A), but does not discuss the computational cost of writing 8K tokens into the state, does not measure it, and does not amortize it across any of the reported metrics. The abstract and introduction emphasize the efficiency of the compact state ("With only an 8 × 8 online memory state") without mentioning that building that state requires a full forward pass over all of history. A practitioner deciding whether to deploy δ-mem would need to know: for my use case, how many turns does the state need to persist to break even on compute compared to just including the context in the input? The paper provides no data to answer this question.

---

### The $8 \times 8$ State Size Claim Lacks Scaling Evidence — We Don't Know Where Performance Saturates

**The assumption or constraint.** The paper's central architectural claim is that an extremely compact state — specifically $r = 8$, yielding an $8 \times 8$ matrix with 64 parameters — is sufficient for effective memory. This is stated in the abstract ("With only an 8 × 8 online memory state"), the introduction ("an extremely small memory state, implemented as an 8 × 8 matrix, can retain useful historical signals"), and the conclusion ("even with an extremely small 8 × 8 online state, the model can recover useful historical information"). The dimension $r = 8$ is used in all main experiments (Tables 1, 2, 3, 4) and all ablation studies.

**The consequence.** The paper demonstrates that $r = 8$ **works**, but provides **no evidence about whether it is optimal, near-optimal, or substantially suboptimal** relative to larger or smaller states. This matters for two opposite reasons:

- **If $r = 4$ performs similarly**, then the memory state could be even smaller (16 parameters), and the paper's claims about the sufficiency of tiny states would be even stronger. The absence of a smaller-state evaluation leaves open the possibility that the state size could be reduced further with no performance loss — meaning the paper's design is actually over-parameterized for its own thesis.
- **If $r = 16$ or $r = 32$ provides substantial gains**, then the "8 × 8 is enough" framing is misleading — the state works at that size, but significantly more capacity would help, and the paper's efficiency claims trade off against unexplored performance headroom. A practitioner choosing between δ-mem configurations would need to know where the performance curve flattens to make an informed capacity-vs-cost decision.

Neither question can be answered from the data provided. The context recovery experiment (Figure 2, Section 5.1) demonstrates that an $r = 8$ state recovers information when context is removed, but does not show whether a $4 \times 4$ state would collapse or a $16 \times 16$ state would double the recovery rate. The head-to-head comparison with baselines (Table 1) shows δ-mem outperforming much larger memory systems (MLP Memory at 3078M parameters), but this comparison conflates state size with architectural design — the baselines use fundamentally different memory mechanisms, not larger versions of the same mechanism.

**What evidence exists in the paper.** None. There is no ablation over the state dimension $r$. The paper sweeps insertion layers (Table 4: front/middle/back/all), attention components (Table 3: all 15 combinations of q/k/v/o), and writing strategies (TSW/SSW/MSW), but never varies $r$. The memory write budget (8,192 tokens) and the backbone training sequence length (512 tokens) are fixed as well. This is the single most important missing experiment for validating the paper's central thesis about compactness.

**Mitigation status.** Not addressed. The paper does not acknowledge the absence of this ablation, does not discuss how performance might scale with state size, and does not flag it as future work. The implicit claim — that the results at $r = 8$ demonstrate that effective memory can be realized through a compact state — is true in the existential sense (it works at $r = 8$), but would be substantially strengthened or qualified by a scaling curve. A practitioner cannot determine from the paper whether increasing $r$ to 16 (256 parameters, still trivially small by LLM standards) would yield meaningful further gains on MemoryAgentBench or whether the returns have already saturated.

---

### All Baselines Underperform the Frozen Backbone — δ-mem Is Compared to Weak and Possibly Misconfigured Alternatives

**The assumption or constraint.** The paper's headline claim — that δ-mem "outperforms the strongest non-δ-mem memory baseline by 1.15×" (abstract) — depends on the baseline implementations being competitive. The three memory paradigms are represented by BM25 RAG, LLMLingua-2, MemoryBank (textual), Context2LoRA, MemGen (parametric), and MLP Memory (outside-channel), all evaluated on Qwen3-4B-Instruct (Table 1).

**The consequence.** **Every baseline underperforms the frozen backbone on the average score:** the backbone achieves 46.79%, while BM25 RAG gets 44.56%, LLMLingua-2 gets 42.96%, MemoryBank gets 43.88%, Context2LoRA gets 44.90%, MemGen gets 30.66%, and MLP Memory gets 22.85%. The "strongest baseline" that δ-mem outperforms by 1.15× is Context2LoRA at 44.90% — a method that **degrades performance relative to no memory at all** (-1.89 points). This is a fundamental problem for the paper's comparative claims: δ-mem is being evaluated against memory mechanisms that demonstrably hurt the backbone's performance, making the comparison one of "δ-mem helps vs. alternatives hurt" rather than "δ-mem helps more than alternatives help."

This pattern raises serious concerns about baseline implementation quality, particularly for the textual memory baselines. Retrieval-augmented generation with BM25 is a well-established technique that typically provides non-trivial gains on knowledge-intensive tasks like HotpotQA; the paper's implementation achieves 40.35% EM on HotpotQA versus the backbone's 42.35% — a degradation. LLMLingua-2, a published compression method, drops HotpotQA EM to 36.93%. Both results suggest that the baselines may not have been tuned for the specific backbone, context lengths, or task distributions used in this paper. The paper does not report retrieval hyperparameters (chunk size, top-k, retrieval granularity), compression ratios, or any tuning process for these baselines, making it impossible to assess whether the comparison is fair.

The MemGen result (30.66% average, HotpotQA EM collapsing to 5.36%) is so catastrophic that it suggests a fundamental incompatibility between MemGen's training and the evaluation setup rather than an inherent weakness of parametric memory — a misconfigured baseline rather than a fairly-represented one. If δ-mem were compared only against the frozen backbone (46.79% → 51.66%, +4.87 points), the absolute gain would be positive but modest; the 1.15× multiplier inflates the perceived advantage by anchoring against a degraded baseline.

**What evidence exists in the paper.** Table 1 provides the raw numbers. The paper does not report any tuning process for the baselines, does not show sweeps over hyperparameters, and does not discuss why the baselines underperform. Section 4.1 lists the baselines and provides citations, but no implementation details beyond the method names. Appendix C (Figure 4) compares parameter counts, but parameter count is not the relevant metric for textual or outside-channel baselines whose memory capacity comes from stored text or external representations, not trainable parameters.

**Mitigation status.** Partially acknowledged. The paper notes in Section 4.2 that textual memory methods "show inconsistent gains, likely due to retrieval noise and information loss," that Context2LoRA "tends to generalize less robustly across tasks," and that MLP Memory "lacks sequential state accumulation and cannot explicitly model long-range dependencies." These are post-hoc explanations of the observed failures, not a-priori evidence that the baselines were fairly tuned. The paper does not acknowledge that the baseline underperformance relative to the backbone undermines the comparative framing, and does not discuss what a well-tuned baseline might achieve. The most policy-relevant comparison — δ-mem vs. a well-configured RAG or compression baseline — is absent, and the reported numbers cannot be treated as representative of those paradigms' achievable performance.

---

### Training on 2,219 QASPER Samples Leaves Domain Generalization Unverified

**The assumption or constraint.** All δ-mem variants are trained on "the shortest 2,219-sample split of QASPER" (Appendix A), a dataset of information-seeking questions about research papers. The training is for a single epoch. The paper then evaluates on HotpotQA (multi-hop Wikipedia QA), LoCoMo (long-term conversational memory), MemoryAgentBench (agent memory across diverse tasks), GPQA-Diamond (graduate-level science), and IFEval (instruction following). The implicit claim is that δ-mem transfers across these domains because it learns a general memory mechanism rather than QASPER-specific heuristics.

**The consequence.** The cross-benchmark evaluation provides suggestive but incomplete evidence for domain generalization. QASPER shares structural properties with some of the evaluation benchmarks — it involves answering questions that require synthesizing information from a long document, similar to HotpotQA's multi-hop reasoning — but is fundamentally different from conversational memory (LoCoMo) or agent interaction memory (MemoryAgentBench) in terms of interaction structure, information type, and temporal dynamics. The paper provides no evidence that the learned projections ($W_q^m$, $W_k^m$, $W_v^m$, $W_\beta$) encode domain-general memory operations rather than QASPER-specific features (e.g., learning to track citation spans, section references, or academic terminology in the compressed state).

If the projections are adapting to QASPER's specific structure, then δ-mem's performance on the target benchmarks may reflect **incidental transfer** (QASPER happens to teach some transferable memory behaviors) rather than **robust generalization** (any training data that requires memory would work). A practitioner training δ-mem on their own domain's data would need to know: do I need memory-intensive data like QASPER, or will any long-context corpus work? The paper does not isolate the training data's role, making it impossible to answer.

**What evidence exists in the paper.** Table 1 and Table 2 show cross-benchmark performance, and the gains are positive across all benchmarks — this is evidence that some transfer occurs. However, the paper does not ablate the training data: no alternative training dataset is tested, no data-size sweep is reported (does performance plateau at 2,219 samples, or would 10,000 QASPER samples help?), and no per-benchmark breakdown by training-data similarity is provided. The single-epoch training on a fixed 2,219 samples also raises questions about whether the model is under-trained — the paper does not report whether validation loss had converged or whether additional epochs would help.

**Mitigation status.** Not addressed. The paper does not discuss the choice of QASPER, does not justify why 2,219 samples is sufficient, and does not acknowledge domain transfer as a limitation. The training data is presented as an implementation detail (Appendix A) rather than a design choice with implications for generality. The paper's cross-backbone evaluation (Table 2) provides evidence that δ-mem transfers across model scales, but cross-backbone generalization is orthogonal to cross-domain generalization — the question is not whether δ-mem works with different frozen models, but whether δ-mem trained on QASPER works because of QASPER-specific structure or because of general memory learning.

### General Capability Preservation Is Tested on Only Two Benchmarks — Broader Capability Degradation Cannot Be Ruled Out

**The assumption or constraint.** The paper claims that δ-mem "largely preserves general capabilities" (from the abstract, confirmed in Section 4.2 and 4.3). This claim is supported by results on two benchmarks: IFEval (instruction following) and GPQA-Diamond (graduate-level QA). On Qwen3-4B-Instruct, δ-mem (TSW) achieves 82.99% on IFEval (vs. 81.89% for the backbone) and 40.40% on GPQA-Diamond (vs. 39.39%) — both marginal improvements. There is no degradation on these two benchmarks.

**The consequence.** Two benchmarks do not constitute a comprehensive capability evaluation. The paper's memory mechanism modifies the attention computation in all 36 layers of the backbone (the "All Layers" configuration in Table 4), including corrections to query and output vectors. This is a non-trivial intervention: attention is the backbone's primary information-routing mechanism, and low-rank corrections applied uniformly across all layers could alter behavior on tasks that rely on specific attention patterns — mathematical reasoning requiring precise token-level alignment, factual recall depending on specific key-value associations learned during pretraining, or code generation requiring structured attention to syntax. If δ-mem's attention corrections slightly perturb these patterns, the degradation might not manifest on IFEval (which tests surface-level instruction compliance) or GPQA-Diamond (which tests graduate-level scientific knowledge) but could appear on more fine-grained reasoning or factual benchmarks.

The paper's selection of general capability benchmarks is narrow relative to standard LLM evaluation practice. Common benchmarks like MMLU (broad knowledge across 57 subjects), GSM8K (grade-school math reasoning), HellaSwag (commonsense reasoning), ARC (science reasoning), or HumanEval (code generation) are not evaluated. These benchmarks are sensitive to different aspects of model capability: MMLU tests factual knowledge that could be perturbed by attention corrections, GSM8K tests multi-step symbolic reasoning that depends on precise attention alignment, and HumanEval tests structured generation where attention patterns matter for syntactic correctness. Without evaluation on these dimensions, the claim that capabilities are "largely preserved" rests on thin evidence.

**What evidence exists in the paper.** Table 1 and Table 2 report IFEval and GPQA-Diamond for all configurations and backbones. The scores are stable or slightly improved across δ-mem variants: on Qwen3-4B-Instruct, IFEval ranges from 81.52% (MSW) to 82.99% (TSW), and GPQA-Diamond ranges from 37.37% (MSW) to 41.41% (SSW). There is no catastrophic collapse (unlike MemGen, which drops IFEval to 39.37%), but the evaluation is insufficient to claim general preservation. The paper does not report backbone-only baselines on MMLU, GSM8K, or other standard benchmarks, and does not compare δ-mem-augmented models with the backbone on such tasks.

**Mitigation status.** Partially acknowledged by omission — the paper does not claim comprehensive capability evaluation, and the benchmarks tested are explicitly listed in Section 4.1. However, the abstract's phrasing ("largely preserving general capabilities") is stronger than the evidence supports and would be more accurately stated as "preserving performance on IFEval and GPQA-Diamond." A practitioner deploying δ-mem in a setting where factual accuracy, mathematical reasoning, or code generation are important would need to independently evaluate these capabilities — the paper provides no guidance on whether to expect degradation or preservation.

---

### Single-Run Results Without Variance Estimates Make Relative Comparisons Fragile

**The assumption or constraint.** All experimental results in the paper come from a single training run with a fixed random seed (42, per Appendix A). No multiple-seed evaluation, no confidence intervals, and no statistical significance testing are reported. The paper draws comparative conclusions about which δ-mem variant is "best" (TSW for Qwen3-4B-Instruct, SSW for Qwen3-8B, MSW for SmolLM3-3B — Table 2 and Section 4.3), which attention components to correct (qo vs. qkvo — Table 3 and Section 5.2), and which insertion depth to use (all layers — Table 4 and Section 5.3).

**The consequence.** Many of the reported performance differences are small enough to be within plausible run-to-run variance. On Qwen3-4B-Instruct (Table 1), TSW (51.66%) and SSW (51.44%) differ by only 0.22 absolute points — a gap that could easily reverse with a different random seed or training data shuffle. On Qwen3-8B (Table 2), SSW (50.86%) vs. MSW (50.84%) vs. TSW (50.68%) span only 0.18 points. In the head ablation (Table 3), the qo configuration (47.97%) and qkvo (48.05%) differ by 0.08 points. In the insertion depth ablation (Table 4), "All Layers" (47.97%) and "Middle 12" (46.66%) differ by 1.31 points — larger, but still potentially within variance for a 500-sample test set (HotpotQA) evaluated on a single run.

The paper's qualitative interpretations depend on these fragile rankings. The claim that "for backbones with stronger inherent reasoning, segment-level writing (SSW) smooths state updates and effectively mitigates token-level noise" (Section 4.3) is based on SSW being best for Qwen3-8B by 0.18 points over TSW. The claim that "intermediate layers provide a particularly effective interface for memory injection" (Section 5.3) is based on middle layers outperforming front/back by 2+ points — a more stable margin, but still from a single run. Without variance information, neither the rankings nor the interpretations based on them can be treated as reliable.

This is especially problematic for the writing strategy × backbone interaction (TSW vs. SSW vs. MSW across models), which the paper presents as an empirical finding with implications for deployment. A practitioner choosing a δ-mem configuration for their own use case might follow the paper's recommendation (use MSW for smaller backbones, SSW for larger ones) only to find that the ranking was an artifact of a single seed and that the simpler TSW would have worked equally well with fewer parameters (4.87M vs. 19.47M for MSW).

**What evidence exists in the paper.** The paper reports point estimates throughout, with the seed fixed to 42. There is no discussion of variance, no error bars in figures, and no multi-seed table. The test sets for the benchmarks are not extremely small (HotpotQA has 500 test questions, LoCoMo and MemoryAgentBench are larger), but the combination of small effect sizes and single-run evaluation makes the comparative claims unreliable.

**Mitigation status.** Not addressed. The paper does not acknowledge the single-run limitation, does not discuss variance, and does not qualify its comparative claims with appropriate uncertainty. This is a standard practice in many LLM papers (where full multi-seed evaluation is expensive), but it is particularly consequential here because the paper draws fine-grained architectural conclusions from small performance gaps. At minimum, the paper should acknowledge that the TSW/SSW/MSW rankings and the head/depth ablation optima may not be stable, and that practitioners should validate configuration choices on their own data rather than treating the paper's rankings as definitive.

## 7. Implications and Future Directions

### How This Work Changes the Landscape

This paper shifts the conversation around memory for LLMs from a **storage-centric view to an interface-centric view**. The dominant assumption in the field has been that effective memory requires capacity — more tokens in the context window, more text in retrieval stores, more parameters in adapter modules. δ-mem's central empirical finding — that a 64-parameter matrix can meaningfully improve performance on memory-heavy benchmarks while much larger memory systems (MLP Memory at 3078M parameters) actively degrade performance — reframes the problem. Memory is not primarily about how much information you can hold, but about **how tightly stored information couples to the backbone's internal computation**.

This is a **conceptual reframing with diagnostic implications**, not a paradigm shift. It does not obsolete textual retrieval or parametric memory — those paradigms still have strengths (interpretability for text, stability for parameters) that δ-mem does not replace. Rather, it adds a new design axis to the field's vocabulary: the quality of the memory-backbone interface matters at least as much as the storage capacity, and a mechanism that optimizes for interface quality (by generating attention corrections directly from a compact state) can outperform mechanisms that optimize for capacity but route memory through misaligned pathways.

The paper also provides a **unifying diagnosis** for the inconsistent results across prior memory mechanisms. The findings that textual memory methods show "inconsistent gains" (Table 1), that parametric methods "tend to generalize less robustly across tasks" (Section 4.2), and that outside-channel methods can actively hurt performance (MLP Memory at 22.85% vs. backbone at 46.79%) are not random failures — they are manifestations of a common underlying problem: misalignment between the memory state and the backbone's attention computation. Textual memory forces rich stored information through the bottleneck of tokenized context. Parametric memory provides clean parameter-level steering but cannot update online. Outside-channel memory introduces representational mismatch between stored and current encodings. δ-mem's architecture — where memory is a continuous state that directly modulates attention — subjects all three paradigms to the same test (does the interface work?) and shows that the answer depends on interface design, not storage format.

A specific **research direction that becomes less attractive**: developing ever-larger external memory stores (bigger retrieval corpora, more sophisticated indexing) without addressing the interface problem. The MLP Memory result (3078M parameters, 76.40% of backbone, worst performance) is a cautionary datum — scaling capacity through external modules can backfire if the fusion mechanism introduces noise or misalignment. Research investment should shift toward interface design (how memory signals reach the backbone) over raw storage capacity.

A research direction that becomes **more attractive**: exploring other points of tight memory-backbone coupling beyond attention corrections. The paper's head ablation (Table 3) shows that output-side correction provides most of the benefit, but the design space of where and how to inject memory signals is far from exhausted. Feed-forward network corrections, layer-norm modulation, or gating of entire attention heads based on memory readout are all unexplored in the context of compact online states — these become natural extensions now that δ-mem has demonstrated the viability of the direct-coupling approach.

The paper also **reconciles a contradiction** between two strains of prior work. On one hand, retrieval-augmented generation papers have demonstrated that external knowledge stores improve performance on knowledge-intensive tasks (Lewis et al., 2020; Borgeaud et al., 2022). On the other hand, the current paper's RAG baseline (BM25 RAG) actually underperforms the frozen backbone (44.56% vs. 46.79%, Table 1). The resolution is not that RAG doesn't work — it is that retrieval quality and context-window integration matter enormously, and a poorly-tuned RAG pipeline (the paper does not report tuning) can hurt more than it helps. δ-mem's attention-coupling approach sidesteps the retrieval-quality problem entirely by making memory a continuous state rather than a discrete retrieval operation, but the diagnostic implication is that **retrieval-based methods need to match their interface quality to the backbone**, not just their storage scale.

### Follow-Up Research This Work Enables

**1. State-size scaling curves to determine when capacity saturates.** The paper's central claim — that an 8 × 8 state is sufficient — is supported existentially (it works at r = 8) but not empirically bounded (we don't know if r = 4 would collapse or r = 64 would double performance). A direct follow-up would sweep r ∈ {2, 4, 8, 16, 32, 64} on Qwen3-4B-Instruct across the same benchmark suite, measuring both performance and inference overhead. The key questions: (a) Does HotpotQA EM plateau at r = 8, or does it continue to improve? (b) Does the context recovery experiment (Section 5.1) show monotonic improvement with r, or does it saturate? (c) At what r does inference throughput (Appendix B, Figure 3a) become unacceptable relative to the frozen backbone? The answers would transform "8×8 works" from a striking existence proof into a practical design guideline, and would test whether the paper's interface-centric thesis holds — if performance continues to improve with r, then capacity still matters, just through a better interface rather than a larger external store.

**2. Training data ablation: does δ-mem learn general memory or QASPER-specific heuristics?** All training uses 2,219 QASPER samples, and the cross-benchmark evaluation provides suggestive but incomplete evidence for domain generalization. A critical follow-up would train identical δ-mem architectures on three different corpora — QASPER (scientific paper QA, the original), a narrative text dataset (e.g., BookSum or NarrativeQA, requiring tracking characters and plot across long contexts), and a dialogue dataset (e.g., MultiWOZ or a synthetic multi-turn assistant dataset, requiring tracking user preferences and task state) — and evaluate all three on the same benchmark suite (HotpotQA, LoCoMo, MemoryAgentBench, IFEval, GPQA-Diamond). If performance is comparable across training datasets, δ-mem genuinely learns domain-general memory operations. If QASPER-trained δ-mem significantly outperforms the others (especially on HotpotQA, which shares QASPER's structure of synthesizing evidence from a document), then the current results overstate generality and practitioners would need domain-matched training data. This experiment would also reveal whether LoCoMo (conversational memory) benefits more from dialogue-trained δ-mem — an interaction effect the current paper cannot detect.

**3. Multi-turn state persistence: isolating inter-turn benefits from intra-document compression.** δ-mem's design claims to support memory "across extended interactions," but the current evaluation cannot distinguish between benefits from compressing a single long document (e.g., the HotpotQA context) and benefits from state persisting across multiple interaction turns (e.g., carrying user preferences from turn 1 to turn 10 in LoCoMo). A targeted experiment on LoCoMo would: (a) measure δ-mem performance as a function of conversation turn count (e.g., 1-turn, 5-turn, 10-turn, 20-turn), (b) compare against a "reset-state" baseline where the online state is cleared between turns (forcing δ-mem to rely only on intra-turn compression), and (c) compare against the frozen backbone with full conversation history in the context window (extending the backbone's context to accommodate all turns). If δ-mem with persistent state significantly outperforms the reset-state baseline, the inter-turn memory claim is validated. If extending the backbone's context to include all turns outperforms δ-mem, then the compact-state approach is a compression-efficiency win but not a capability win — an important distinction for practitioners choosing between context extension and δ-mem.

**4. Gate design stress-test: how much does dimension-wise, context-dependent gating matter?** The paper's gating design — dimension-wise β_t generated from x_t, with λ_t = 1 − β_t coupling — is presented without ablation. A systematic follow-up would compare four gating configurations on Qwen3-4B-Instruct across HotpotQA and LoCoMo: (a) scalar learned gate (single β ∈ (0, 1), not a function of x_t), (b) scalar context-dependent gate (β_t = σ(w_β · x_t + b) producing a scalar), (c) dimension-wise context-dependent with independent λ_t and β_t (breaking the coupling), and (d) the paper's default (dimension-wise, coupled λ_t = 1 − β_t). If configuration (d) significantly outperforms (a) and (b), the dimension-wise context-dependent design is justified. If (c) outperforms (d), the coupling constraint is unnecessarily restrictive. If (a) performs comparably to (d), then the gate design is far less important than the paper implies, and practitioners can simplify the architecture substantially. This experiment is cheap (only the gate parameters change) and directly tests the paper's claim that "the state can simultaneously maintain stable facts while encoding new information" through dimension-wise gating.

**5. Attention correction analysis: what does δ-mem actually change about attention patterns?** The paper demonstrates that δ-mem improves performance but provides no mechanistic insight into what the memory corrections are doing to attention weights or representations. A follow-up using attention visualization and probing would: (a) for a set of LoCoMo conversations, compare attention maps with and without δ-mem corrections — does the model attend more strongly to memory-relevant tokens (user preferences mentioned earlier, task instructions from prior turns) when δ-mem is active? (b) Train linear probes on the corrected query vectors Δq_t and output vectors Δo_t to predict what kind of historical information is being retrieved (e.g., "this correction encodes the user's previously stated preference for vegetarian food" vs. "this correction encodes the current task completion status"). (c) Measure the cosine similarity between the corrected query and keys from historical turns (which may not be in the explicit context) — does δ-mem shift the query toward directions associated with relevant-but-absent information? Such analysis would transform δ-mem from a black-box performance improver into an interpretable memory mechanism and would guide architectural improvements (e.g., if corrections are primarily retrieving factual associations, adding a dedicated factual memory sub-state in MSW might help; if corrections are primarily modulating task-tracking, a different correction point might be more effective).

**6. Combination with test-time compute scaling: can compact memory improve verifier-guided search?** This paper focuses on memory for frozen backbones, but the prior analysis of test-time compute (distinct from this work) shows that search and revision mechanisms benefit from difficulty-aware allocation. A natural bridge: use δ-mem's online state to estimate problem or conversation difficulty (e.g., from the state's prediction error or gate activation patterns), and use that estimate to allocate inference compute — more search on difficult memory-dependent queries, less on easy ones. A concrete experiment: on LoCoMo, use δ-mem's state (which tracks conversation history) to produce a difficulty signal for each question, then allocate a best-of-N budget accordingly. The hypothesis: the memory state contains information about how conflicted or ambiguous the history is, which predicts whether the model needs extra inference compute to resolve the question. This would unify the test-time compute scaling framework with the online memory framework — the state serves both as memory for answering and as a meta-cognitive signal for resource allocation.

### Practical Applications and Downstream Use Cases

**1. Long-running agent systems with evolving context.** In agent deployments where an LLM interacts with an environment over dozens or hundreds of steps (e.g., code generation agents iterating on a codebase, web navigation agents tracking state across pages), the context window fills with intermediate observations, tool outputs, and previous reasoning steps. δ-mem offers a deployment pattern where the interaction history is compressed into the 8×8 state (or a modestly larger variant), and the explicit context window is reserved for the current step's observations — the memory state provides historical grounding without consuming context budget. The MemoryAgentBench results (29.54% → 38.85%, +9.31 points) suggest this pattern would help specifically on tasks requiring accurate retrieval of past events and test-time learning of new information. The parameter overhead (4.87M, 0.12% of backbone) makes this feasible even for on-device agent deployments where full fine-tuning is impossible and large external memory modules are too expensive.

**2. Personalized assistants with persistent user memory across sessions.** In long-term assistant settings where the model must remember user preferences, past interactions, and personal facts across days or weeks, δ-mem's state can be serialized and reloaded between sessions — a fixed-size 8×8 matrix is trivial to store (256 bytes at float32) and can be updated incrementally as new interactions occur, without requiring re-encoding of the full interaction history. The LoCoMo results (40.79% → 49.12%, +8.33 points with MSW) demonstrate that the state captures multi-hop and temporal information from extended conversations. The SSW writing strategy, which updates per message rather than per token, aligns naturally with the turn-based structure of assistant interactions. A practical deployment would: (a) initialize the state from the user's interaction history during onboarding (a one-time cost of processing past conversations), (b) update the state after each new conversation turn (a lightweight operation), and (c) pass the state alongside the current query for steering during generation. The context recovery results (Figure 2) suggest that the state would provide partial information recovery even if older conversations are pruned from the context window due to length constraints.

**3. Efficient batch processing of long documents for downstream tasks.** For applications that process many long documents (legal document review, scientific literature mining, customer support ticket analysis), δ-mem enables a two-phase pipeline: (a) offline phase — process each document once through the frozen backbone to build its memory state, storing the 8×8 matrix alongside the document metadata, (b) online phase — when a query arrives, load the relevant document states and use them to steer attention while the explicit context contains only the query and a brief prompt. This amortizes the cost of document processing across many queries — an advantage the current paper's single-turn evaluation does not capture but which is inherent in the state-persistence design. The HotpotQA results (42.35% → 49.41% EM with TSW, Table 1) show that the state-augmented model can answer questions about a document more accurately than the backbone with the document in context, suggesting that the state captures complementary information to explicit context rather than just approximating it. The key cost metric for this use case would be (encoding cost / number of queries) + per-query generation cost — the paper's Appendix B efficiency measurements only cover the per-query generation cost, so practitioners would need to benchmark the full pipeline for their query volume.

**4. Enabling memory on resource-constrained edge devices.** The 4.87M-parameter overhead (0.12% of backbone) and the fixed per-token inference cost (Appendix B, Figure 3a) make δ-mem viable on edge devices where large context windows or external memory modules are infeasible due to memory constraints. The SmolLM3-3B results (26.08% → 36.96%, +10.88 points with MSW, Table 2) are particularly relevant — smaller backbones benefit disproportionally from δ-mem, making it a candidate for deploying capable memory-augmented LLMs on phones, IoT devices, or offline systems. The 8×8 state adds negligible storage (256 bytes), so persisting memory across device reboots is trivial. A concrete deployment: an offline personal assistant on a phone running SmolLM3-3B with δ-mem MSW, maintaining user memory across days without network access, storing only the 4 × (8 × 8) state matrices (1 KB total) plus the 19.47M δ-mem parameters (a ~75MB file at float32) alongside the backbone.

### When to Prefer This Method

The paper does not articulate an explicit tradeoff matrix against named alternatives. The baselines serve to demonstrate δ-mem's relative performance but are not presented as competing deployment options between which a practitioner would choose based on scenario-specific conditions — BM25 RAG, LLMLingua-2, and MLP Memory all underperform the frozen backbone, making them non-viable alternatives rather than points on a tradeoff frontier. Context2LoRA comes closest to a comparable alternative (similar parameter count, similar low-rank interface), but the paper's comparison focuses on performance rather than articulating the conditions under which static parametric memory would be preferred over dynamic online memory. Including a forced decision matrix here would invent tradeoffs the paper does not establish. The practical guidance above (multi-turn agents, persistent assistants, document batch processing, edge deployment) represents the paper's implicit positioning toward scenarios where compact, dynamic, attention-coupled memory provides benefits — scenarios that align with δ-mem's architectural strengths but were not explicitly validated as part of a comparative tradeoff analysis.
