# Samba: Simple Hybrid State Space Models for Efficient Unlimited Context Language Modeling

**ArXiv:** [2406.07522](https://arxiv.org/abs/2406.07522)

## 🎯 Pitch

This paper introduces **SAMBA**, a simple hybrid neural architecture that layer-wise interleaves Mamba—a selective State Space Model (SSM)—with Sliding Window Attention (SWA) and MLP layers to achieve efficient language modeling with unlimited context length extrapolation.

---

## 1. Executive Summary

This paper introduces **SAMBA**, a simple hybrid neural architecture that layer-wise interleaves Mamba—a selective State Space Model (SSM)—with Sliding Window Attention (SWA) and MLP layers to achieve efficient language modeling with unlimited context length extrapolation. Pretrained on sequences of only 4K length, SAMBA extrapolates to 1M tokens in zero-shot with improved perplexity on Proof-Pile (a 256× extrapolation ratio) while maintaining linear decoding complexity, and when instruction-tuned on 4K sequences for only 500 steps, it achieves perfect memory recall on Passkey Retrieval up to 256K context length—a regime where pure SWA models fail entirely—while delivering 3.73× higher prompt-processing throughput and 3.64× faster decoding than Transformers with grouped-query attention at 128K length. The 3.8B-parameter SAMBA model substantially outperforms the state-of-the-art Phi-3-mini Transformer trained under identical recipes and data on both short-context benchmarks (71.9 vs. 68.8 MMLU, 87.6 vs. 82.5 GSM8K, 62.8 vs. 58.5 HumanEval) and long-context summarization, establishing that a hybrid SSM-attention architecture can surpass equivalently-trained dense Transformers on standard capabilities while simultaneously enabling efficient length extrapolation that is inaccessible to pure attention-based models.

## 2. Context and Motivation

### The Fundamental Tension in Sequence Modeling: Efficiency vs. Recall

The central problem this paper addresses is a fundamental architectural trade-off that has defined the landscape of large language model design: **how do you build a model that processes extremely long sequences efficiently while still maintaining the ability to precisely recall specific information from across the entire context?**

This is not a minor engineering concern. It cuts to the heart of what makes language models useful. Real-world applications increasingly demand long-context understanding—legal document analysis requires digesting hundreds of pages, conversational agents need to remember details from the beginning of a long dialogue, and code assistants must reason about entire codebases. The ability to handle arbitrarily long contexts is not a luxury feature; it is a prerequisite for many of the most valuable deployment scenarios.

The problem has resisted easy solution because the two desiderata—computational efficiency and precise memory recall—are in direct tension:

**Quadratic-complexity attention solves recall but doesn't scale.** The standard Transformer self-attention mechanism (Vaswani et al., 2017) gives every token direct access to every other token. This is precisely why Transformers excel at information retrieval: the model can "look back" at any position in the sequence with full fidelity. But this comes at the cost of $O(n^2)$ computation and $O(n)$ memory for the KV cache, where $n$ is the sequence length. Processing a 1M-token document with full attention requires on the order of $10^{12}$ operations *per layer*, making it computationally prohibitive for production deployments. This quadratic scaling is not a flaw in existing implementations—it is inherent to the pairwise comparison that makes attention work.

**Linear-complexity models scale but lose recall precision.** State Space Models (SSMs)—and their modern instantiation in Mamba (Gu & Dao, 2023)—address the efficiency problem by compressing the entire sequence history into a fixed-size recurrent state. Processing each new token costs $O(1)$ regardless of how long the sequence has become. The Mamba variant introduces *selective* state spaces that make the state update dependent on the input content, allowing the model to selectively remember or forget information based on relevance rather than following a fixed decay schedule. This is a genuine advance: input-dependent selection means the model can theoretically hold onto important information indefinitely while discarding irrelevant detail.

But the compression is lossy by nature. The recurrent state has finite capacity—in SAMBA's case, the state dimension $d_s$ is 16—and information from thousands of tokens must be distilled into this fixed representation. As the paper notes in Section 1, SSMs "struggle with memory recall due to their recurrent nature," a finding corroborated by formal analysis (Arora et al., 2023) showing that SSMs have fundamental limitations on state tracking compared to Transformers, and by empirical evaluations (Fu et al., 2023; Wen et al., 2024; Arora et al., 2024) demonstrating that SSMs underperform attention on retrieval-intensive tasks.

The evidence for this recall gap is concrete within the paper itself. In Table 2, the pure Mamba model scores **67.66** on SQuAD—a reading comprehension task that requires locating specific spans in a passage—compared to **74.88** for the Llama-3 Transformer architecture and **77.64** for SAMBA. This is a dramatic gap on a core capability, and it reflects a genuine architectural weakness: a recurrent state simply cannot store every detail of a long passage with the fidelity that direct attention provides.

### The Prior Attempts and Why They Fall Short

The field has not been idle in the face of this tension. Prior work has explored multiple strategies for bridging the efficiency-recall gap, but each approach has significant limitations that SAMBA is designed to address.

**Hybridization with full attention.** Several architectures have attempted to combine SSMs with standard quadratic self-attention—using SSMs for most layers to handle long-range dependencies efficiently, and sprinkling in full attention layers to provide retrieval capability. This includes approaches like H3 (Dao et al., 2022b), Mambaformer (Park et al., 2024), and Jamba (Lieber et al., 2024; Team et al., 2024). The intuition is sound: let the SSM do the heavy lifting for most of the sequence processing, and let attention handle the precision retrieval. But the paper identifies a critical flaw in Table 5: **even a single layer of full attention destroys length extrapolation**. When a full-attention layer is placed at the beginning of an otherwise SSM-based model, extrapolation perplexity explodes at 16K context length (beyond the 4K training length). The quadratic complexity may be amortized when attention is rare, but the model is still fundamentally saddled with an architecture that cannot handle sequences longer than what it was trained on—at least not without dedicated extrapolation techniques. This defeats the purpose of building an architecture capable of *unlimited* context.

**Chunked attention hybrids.** Some architectures use attention within fixed-size chunks rather than across the full sequence. SPADE (Zuo et al., 2022), GSS (Mehta et al., 2023), MEGA (Ma et al., 2023), Block State Transformers (Fathi et al., 2023), and Megalodon (Ma et al., 2024) all explore variations of combining SSMs with chunked attention. These achieve linear complexity in principle but introduce a hard boundary: information can only attend within its local chunk, and cross-chunk communication relies entirely on the recurrent state. This is essentially the same information bottleneck that pure SSMs face, just with slightly larger "chunks" of local precision. The recall capability is strictly bounded by the chunk size.

**Pure Sliding Window Attention.** A simpler approach is to replace full attention with sliding window attention (SWA) entirely, where each token attends only to the preceding $w$ tokens (Beltagy et al., 2020). This achieves linear complexity ($O(n w)$) and naturally extrapolates to any length since the window size is fixed. But SWA has a catastrophic limitation: the model has zero access to information beyond the window boundary. If a document mentions a name on page 1 and refers to it on page 50, a pure SWA model cannot make the connection unless the name happened to be repeated within the last $w$ tokens. As the paper demonstrates in Figure 3, an SWA-based Mistral model fine-tuned on Passkey Retrieval at 4K length fails to retrieve the passkey beyond its training length—even with explicit training, the architecture simply cannot bridge information across gaps larger than the window.

**Intra-layer hybridization.** Infini-Attention (Munkhdalai et al., 2024) proposes combining SWA with linear attention within the same layer, using the delta rule (Schlag et al., 2021) for the recurrent component. This is an elegant design that avoids the layer-allocation question entirely. However, as the paper notes in Appendix A, "its performance in the setting of large-scale pre-training from scratch remains questionable." There is no demonstration that this approach scales competitively against state-of-the-art Transformers.

**Length extrapolation for Transformers.** A parallel line of work attempts to extend the context length of pretrained Transformers through position embedding modifications (Chen et al., 2023a; Ding et al., 2024; Jin et al., 2024) or continual training strategies (Xiong et al., 2023; Tworkowski et al., 2023). These methods can extend effective context length significantly—SelfExtend (Jin et al., 2024) is evaluated in the paper—but they have fundamental limitations. The paper shows in Figure 2 that SE-Llama-3 cannot match SAMBA's perplexity on 1M-token sequences, and it introduces "significant inference latency overhead." More critically, these methods still retain quadratic attention complexity; they are *modifying* the attention pattern, not replacing it. The perplexity eventually explodes when the sequence is sufficiently long, and the inference cost continues to scale quadratically. They are band-aids on the fundamental complexity problem, not solutions to it.

**The Griffin comparison.** The work most similar to SAMBA is Griffin (De et al., 2024), which also interleaves a linear recurrent unit (Real-Gated Linear Recurrent Unit, RG-LRU) with Sliding Window Attention. This represents the closest prior attempt at exactly the architecture family SAMBA explores. But Griffin and its follow-up RecurrentGemma (Botev et al., 2024) show only comparable or worse results than Transformers—they demonstrate that the hybrid approach can *match* attention performance on short contexts while providing efficiency, but not that it can *exceed* it. As the paper states in Appendix A: "we are the first to show that interleaving Mamba with both SWA and MLP can substantially outperform modern Transformers (and Mamba) at a scale up to 3.8B parameters, while achieving comparable training speed and better length extrapolation ability under the perplexity metrics." This is a crucial distinction: prior work established feasibility; SAMBA establishes superiority.

### Why the Gap Matters (and Why It Hasn't Been Solved Before)

The persistent failure of prior approaches to simultaneously achieve Transformer-competitive performance *and* linear-complexity length extrapolation reflects a deeper challenge: the field has lacked a clear understanding of how to *allocate* different computational mechanisms across layers. 

Mamba layers and attention layers serve fundamentally different computational roles. The paper conceptualizes this in Section 2 as:

> "the functionality of Mamba as the capture of recurrent sequence structures, SWA as the precise retrieval of memory, and MLP as the recall of factual knowledge."

This is more than a taxonomy—it is a hypothesis about functional specialization. Mamba's selective state space allows it to compress long-term dependencies into a recurrent state, excelling at modeling the time-dependent semantics of sequences (what patterns repeat, what structures persist). But this compression inherently loses the ability to pinpoint exactly "what was said 10,000 tokens ago." SWA provides exactly that pinpoint capability, but only within a limited window. The MLP layers provide the nonlinear transformation and factual knowledge recall that neither recurrent states nor attention patterns capture well.

The challenge is that these components interact in non-obvious ways. If you put attention too early, the recurrent state doesn't have useful context to work with. If you put it too late, the state has already lost the information that attention would need to retrieve. If you use too many attention layers, you lose efficiency. If you use too few, you lose recall. The design space is combinatorial, and prior work had not systematically explored it at scale.

### How SAMBA Positions Itself

The paper positions SAMBA as a specific architectural answer to this design problem, defined by three key choices:

**1. Sliding Window Attention, not full attention.** This is the decision that enables length extrapolation. SWA has linear complexity with respect to sequence length and is naturally translation-invariant—the window size is fixed regardless of how long the sequence becomes. This means the model can process sequences of arbitrary length without modification, and the computational cost grows only linearly. The choice of window size $w = 2048$ is deliberate: FlashAttention 2 has the same training speed as Mamba's selective parallel scan at exactly this sequence length, meaning neither component becomes a training bottleneck.

**2. Layer-wise interleaving, not intra-layer mixing.** SAMBA places Mamba and SWA in separate, alternating layers rather than combining them within the same computational unit. This allows each layer type to specialize completely to its computational role without interference. The paper explores different interleaving patterns in Figure 1: Samba alternates Mamba-MLP and SWA-MLP blocks; Mamba-SWA-MLP places Mamba and SWA in the same block; Mamba-MLP uses no attention at all. The fact that these produce systematically different downstream performances (Table 2) confirms that the arrangement matters.

**3. Mamba specifically, not just any linear recurrence.** The paper justifies this choice empirically in Section 3.2 and Table 3. Replacing Mamba with Multi-Scale Retention (RetNet) or Gated Linear Attention (GLA) produces hybrid models that are competitive but consistently underperform SAMBA on perplexity, particularly at longer extrapolation lengths. The selective state space mechanism—where the state update is input-dependent—appears to be the key ingredient that makes the hybrid work, likely because it allows the Mamba layers to dynamically adjust their compression strategy based on what the attention layers are handling.

The paper's positioning relative to prior work is precise: it does not claim to invent the idea of hybrid SSM-attention models. It claims to be the first to demonstrate that a *specific, carefully designed* hybrid architecture can simultaneously achieve three things that prior work had only achieved in pairs: (1) superior short-context performance over state-of-the-art Transformers, (2) linear-complexity length extrapolation to extreme lengths under the perplexity metric, and (3) practical efficiency gains in training and inference throughput. The contribution is the demonstration that the efficiency-recall tradeoff is not fundamental—a properly architected hybrid can get the best of both worlds.

### The Scale of the Demonstration

A key contextual point is the scale at which these claims are validated. The paper trains models at 421M, 1.3B, 1.7B, and 3.8B parameters, with the largest model trained on 3.2T tokens of the same textbook-quality data used for Phi-3. This matters because architecture comparisons at small scale (sub-1B parameters, sub-100B tokens) often fail to predict behavior at production scale. Phenomena like attention entropy specialization (Figure 5) and the superiority of specific head-count configurations (Table 6) may not manifest at smaller scales. By scaling to 3.8B parameters—comparable to the smallest production-grade models—the paper provides evidence that the architectural advantages are not artifacts of limited scale.

The comparison methodology is also notable: SAMBA and the Phi-3-mini Transformer baseline are trained on identical data with identical recipes. This controls for the confounding effects of training data quality, optimization hyperparameters, and post-training procedures that often make architecture comparisons difficult to interpret. Any performance gap can be attributed to the architecture itself, not to differences in training.

## 3. Technical Approach

### 3.1 Reader Orientation

SAMBA is a neural network architecture for language modeling—specifically, a recipe for stacking together three different types of computational layers (Mamba state space layers, sliding window attention layers, and MLP layers) in a carefully chosen alternating pattern. The system solves the fundamental tension between processing long sequences efficiently and maintaining the ability to precisely recall specific information from anywhere in the context: Mamba layers compress the entire sequence history into a fixed-size recurrent state with $O(1)$ per-token cost, while sliding window attention layers provide high-fidelity recall of recent context within a 2048-token window, and the layer-wise interleaving allows each component to specialize—Mamba focuses on modeling recurrent sequence structure while attention handles precise memory retrieval.

### 3.2 Big-Picture Architecture (Diagram in Words)

The SAMBA architecture consists of a stack of $N$ layers (where $N = 24, 36, 48,$ or $64$ depending on model scale), with each layer falling into one of two block types that alternate through the stack:

1. **Mamba Block**: A Mamba layer (selective state space model) followed by an MLP (SwiGLU) layer. This block captures time-dependent semantics and compresses the sequence history into a recurrent hidden state. It processes the input sequence one token at a time, updating internal state variables that represent a compressed summary of everything seen so far.

2. **Sliding Window Attention (SWA) Block**: A self-attention layer operating on a fixed window of $w = 2048$ previous tokens, followed by its own dedicated MLP layer. This block provides precise, high-fidelity retrieval of information within the recent context window, compensating for the lossy compression inherent in the Mamba block's recurrent state.

Each block is wrapped with Pre-Norm (RMSNorm applied before the sublayer) and residual skip connections. The embedding layer at the bottom converts input tokens to vectors of dimension $d_m$, and the output projection at the top converts the final hidden states back to vocabulary probabilities. Information flows sequentially through the alternating blocks: input embeddings $\rightarrow$ Mamba Block 1 $\rightarrow$ SWA Block 1 $\rightarrow$ Mamba Block 2 $\rightarrow$ SWA Block 2 $\rightarrow \ldots \rightarrow$ output head.

### 3.3 Roadmap for the Deep Dive

- **First**, the Mamba layer in detail—how it compresses input sequences into recurrent states, the role of the selective state space mechanism, and the exact dimensions and parameterizations used in SAMBA. Understanding Mamba is prerequisite because it is the backbone that enables linear complexity.
- **Second**, the Sliding Window Attention layer—how it operates on a fixed 2048-token window, how RoPE is applied within the window, and why the window size of 2048 is chosen for hardware efficiency. This is the component that fills Mamba's recall gap.
- **Third**, the MLP layers—the SwiGLU activation, dimension choices, and why SAMBA uses separate MLPs for Mamba and SWA outputs rather than shared MLPs. This covers the factual knowledge recall role.
- **Fourth**, the layer-wise interleaving pattern—the specific arrangement of Mamba, SWA, and MLP layers, the three hybridization strategies compared (Samba, Mamba-SWA-MLP, Mamba-MLP), and how the interleaving pattern affects functional specialization as measured by attention entropy.
- **Fifth**, the training pipeline and hyperparameter configurations across the four model scales (421M, 1.3B, 1.7B, 3.8B), including datasets, optimization settings, and generation configurations for downstream evaluation.

### 3.4 Detailed, Sentence-Based Technical Breakdown

This is primarily an **architectural design and empirical scaling paper** whose core idea is that interleaving Mamba layers with Sliding Window Attention layers in a specific alternating pattern, with each layer type followed by a dedicated MLP, produces a model that simultaneously achieves transformer-competitive short-context performance and linear-complexity length extrapolation to extreme context lengths.

#### The Mamba Layer: Input-Selective Recurrent Compression

The Mamba layer is the backbone of SAMBA's efficiency. It processes an input sequence of length $n$ and hidden dimension $d_m$ through a selective state space model (S6) that maintains a fixed-size recurrent state, meaning the per-token computational cost is constant regardless of sequence length. This is in contrast to self-attention, where each new token must compare against all previous tokens.

**Input expansion and short convolution.** Given an input sequence representation $X \in \mathbb{R}^{n \times d_m}$ (where $n$ is the sequence length and $d_m$ is the model hidden size), the Mamba layer first expands the hidden dimension:

$$H = XW_{\text{in}} \in \mathbb{R}^{n \times d_e}$$

where $W_{\text{in}} \in \mathbb{R}^{d_m \times d_e}$ is a learnable projection matrix and $d_e$ is the expanded dimension. In SAMBA, $d_e = 2d_m$, so the internal representation is twice the model width.

A Short Convolution (SC) operator (Poli et al., 2023) is then applied to smooth the input signal:

$$U = \text{SC}(H) = \text{SiLU}(\text{DepthwiseConv}(H, W_{\text{conv}})) \in \mathbb{R}^{n \times d_e}$$

where $W_{\text{conv}} \in \mathbb{R}^{k \times d_e}$ with kernel size $k = 4$, and the depthwise convolution is applied along the sequence dimension. SiLU (Sigmoid Linear Unit, also called Swish) is the activation function $\text{SiLU}(x) = x \cdot \sigma(x)$.

**What it computes:** The short convolution is a lightweight local feature extractor that runs along the sequence dimension. For each position $t$, it computes a weighted combination of the $k$ most recent expanded representations at positions $t-k+1$ through $t$, using separate convolution filters for each of the $d_e$ channels (depthwise means no cross-channel mixing). The SiLU nonlinearity then gates these smoothed features.

**Why this form:** The short convolution provides a local inductive bias that helps the model smooth out noisy token-level representations before they enter the recurrent state update. This is conceptually similar to the role of the convolutional front-end in signal processing—removing high-frequency noise before running a recurrent filter. The kernel size of 4 is chosen for hardware efficiency on GPUs, as larger kernels would increase memory access patterns without proportional benefit. The depthwise formulation keeps the parameter count modest (only $4 \cdot d_e$ parameters, not $4 \cdot d_e \cdot d_e$ for a full convolution).

**Selective gate computation.** The core innovation of Mamba over previous SSMs is that the state transition parameters are *input-dependent*—the model selectively decides how much to update its state based on the content of each token. The selective gate $\Delta$ is computed through a low-rank projection followed by Softplus:

$$\Delta = \text{Softplus}(UW_r W_q + b) \in \mathbb{R}^{n \times d_e}$$

where $W_r \in \mathbb{R}^{d_e \times d_r}$ projects down to a reduced rank $d_r = d_m/16$, $W_q \in \mathbb{R}^{d_r \times d_e}$ projects back up to $d_e$, and $b \in \mathbb{R}^{d_e}$ is a bias vector.

**What it computes:** For each position $t$ and each of the $d_e$ expanded channels, $\Delta_{tj}$ is a positive scalar that controls how much the recurrent state updates in response to the current input. A large $\Delta$ means the state heavily incorporates the new information; a small $\Delta$ means the state mostly retains its previous value.

**Why this form:** The low-rank bottleneck $d_r = d_m/16$ is crucial for efficiency—computing a full-rank projection from $d_e$ to $d_e$ would require $d_e^2$ parameters per projection, whereas the low-rank version requires only $2 \cdot d_e \cdot d_r$. This makes the selective mechanism parameter-efficient while still allowing input-dependent gating. Softplus ensures $\Delta > 0$ (strictly positive), which is necessary for the exponential decay in the state update to be well-defined. The bias $b$ is carefully initialized so that after initialization, $\Delta \in [\Delta_{\text{min}}, \Delta_{\text{max}}] = [0.001, 0.1]$. This initialization range is "not sensitive to language modeling performance under the perplexity metric" per the paper, suggesting the model learns to adjust these values during training.

**State space parameters B and C.** The input dependence extends to the SSM parameters $B$ and $C$:

$$B = UW_b \in \mathbb{R}^{n \times d_s}$$
$$C = UW_c \in \mathbb{R}^{n \times d_s}$$

where $d_s = 16$ is the state dimension and $W_b, W_c \in \mathbb{R}^{d_e \times d_s}$ are learnable projections.

**What this means:** $B_t$ (at position $t$) controls how the current input is "written" into the recurrent state, and $C_t$ controls how the recurrent state is "read out" to produce the output. Both are computed from the (convolved) input $U_t$ at the current position, meaning the read/write operations are content-dependent—the model can choose to write certain information more strongly into the state and to read certain dimensions of the state more prominently based on what it is currently processing.

**Recurrent state update (S6).** For each time step $1 \leq t \leq n$, the recurrent inference proceeds in an expanded state space $Z_t \in \mathbb{R}^{d_e \times d_s}$:

$$Z_t = \exp(-\Delta_t \odot \exp(A)) \odot Z_{t-1} + \Delta_t \odot (B_t \otimes U_t) \in \mathbb{R}^{d_e \times d_s}$$

$$Y_t = Z_t C_t + D \odot U_t \in \mathbb{R}^{d_e}$$

where $Z_0 = 0$ (the state starts at zero), $\odot$ denotes element-wise (Hadamard) product, $\otimes$ denotes outer product, and $\exp$ is the point-wise natural exponential function. $D \in \mathbb{R}^{d_e}$ is a learnable vector initialized as $D_i = 1$ for all $i$, providing a direct skip connection from input to output. $A \in \mathbb{R}^{d_e \times d_s}$ is a learnable matrix initialized following S4D-Real (Gu et al., 2022): $A_{ij} = \log(j)$ for $1 \leq j \leq d_s$, giving each state dimension a different decay rate.

**What it computes, step by step:**

1. **Decay factor:** $\exp(-\Delta_t \odot \exp(A))$ is a matrix of decay rates in $\mathbb{R}^{d_e \times d_s}$. Since $\exp(A_{ij}) = j$ (because $A_{ij} = \log(j)$), the decay rate for channel $i$ and state dimension $j$ is $\exp(-\Delta_{ti} \cdot j)$. Larger state dimensions $j$ have faster decay; smaller $j$ have slower decay. The input-dependent $\Delta_{ti}$ modulates how aggressively each channel forgets at each time step—if $\Delta_{ti}$ is large (the model decides this token is important), the decay is stronger (shorter memory), counter-intuitively; but this is because a larger $\Delta$ also means the *new input* is written more strongly (second term).

2. **State update:** $Z_t = \text{decay} \odot Z_{t-1} + \Delta_t \odot (B_t \otimes U_t)$. The outer product $B_t \otimes U_t \in \mathbb{R}^{d_e \times d_s}$ creates a matrix where entry $(i,j)$ represents how strongly channel $j$ of the state encodes channel $i$ of the current input. $\Delta_t$ gates how much of this new information enters the state per channel. The old state $Z_{t-1}$ is decayed element-wise. The result $Z_t$ is the updated state matrix.

3. **Output computation:** $Y_t = Z_t C_t + D \odot U_t$. The matrix-vector product $Z_t C_t$ reads out the state using the content-dependent read weights $C_t$. The term $D \odot U_t$ provides a direct skip connection from the input, ensuring that even if the state is zero, the layer can still pass information through.

**Why this form:** This is a continuous-time state space model discretized for discrete sequences, where the input-dependent $\Delta_t$ acts as the step size in the discretization. The key property is that $Z_t$ has fixed size $d_e \times d_s$ regardless of $t$—the entire sequence history is compressed into this matrix, and processing each new token costs $O(d_e \cdot d_s)$ regardless of how long the sequence has become. The S4D-Real initialization of $A$ provides a spectrum of decay rates (from slow to fast across the state dimensions $j = 1, \ldots, 16$), allowing the model to represent both long-term and short-term memories simultaneously. The input-dependent gating through $B_t$, $C_t$, and $\Delta_t$ is what distinguishes Mamba from earlier SSMs: the model can *choose* what to remember and what to forget based on content, rather than following a fixed decay schedule. This selective mechanism is what gives Mamba its strong empirical performance compared to fixed-decay SSMs.

In practice, training uses a hardware-aware parallel scan algorithm rather than the sequential recurrence shown above. The parallel scan computes the same recurrence in $O(\log n)$ parallel steps, making training efficient on GPUs. This is an implementation detail that does not change the mathematical operation but is critical for practical training throughput.

**Output gating.** The final output of the Mamba layer is obtained through a gating mechanism similar to Gated Linear Units (Shazeer, 2020):

$$O = Y \odot \text{SiLU}(XW_g) W_{\text{out}} \in \mathbb{R}^{n \times d_m}$$

where $W_g \in \mathbb{R}^{d_m \times d_e}$ and $W_{\text{out}} \in \mathbb{R}^{d_e \times d_m}$ are learnable parameters.

**What it computes:** The input $X$ is projected through $W_g$ and passed through a SiLU nonlinearity to produce a gate signal in $\mathbb{R}^{n \times d_e}$, which is multiplied element-wise with the SSM output $Y$. This is then projected back down to the model dimension $d_m$ via $W_{\text{out}}$.

**Why this form:** The SiLU gate acts as a learned filter—it can suppress or amplify specific dimensions of the SSM output based on the original (pre-Mamba) input. This is identical to the gating mechanism in Gated Linear Units and provides the model with a way to control the flow of information from the recurrent computation. If the SSM produced a poor representation, the gate can attenuate it; if the SSM captured something useful, the gate can amplify it.

#### The Sliding Window Attention Layer: Precise Local Retrieval

The SWA layer addresses the fundamental limitation of the Mamba layer: its recurrent state has finite capacity ($d_e \times d_s = 2d_m \times 16$ entries) and cannot store every detail of the sequence with perfect fidelity. Attention, by contrast, gives each token direct access to previous tokens within a fixed window, enabling precise retrieval without compression loss.

**Operation.** Given the input sequence representation at a particular layer, the SWA layer computes standard multi-head self-attention, but restricts each query token to attending only to the $w = 2048$ immediately preceding tokens (including itself). The computational complexity is $O(n \cdot w)$ rather than $O(n^2)$, making it linear in sequence length with a constant factor $w$.

**Position encoding.** Rotary Position Embedding (RoPE) (Su et al., 2021) is applied within the sliding window with a base frequency of 10,000. RoPE encodes relative position by rotating the query and key vectors by an angle proportional to their position difference, ensuring that the attention score between two tokens depends naturally on their distance. Crucially, because the attention is already restricted to a window of size 2048, RoPE only needs to handle relative positions up to 2048—the model never attends across larger gaps.

**Why sliding window over full attention:** The choice of SWA over full attention is what enables length extrapolation. Since the window size is fixed regardless of total sequence length, a model trained on 4K sequences can process 1M-token sequences at test time without any architectural modification—the attention patterns are identical, just with more windows. Full attention, by contrast, would require attending across positions that were never jointly seen during training, leading to the exploding perplexities observed in Table 5. The paper demonstrates this empirically: "even if a single full attention layer is placed at the beginning of the model, the extrapolation perplexity is exploding at a context length of 16K."

**Why window size 2048:** The window size is chosen for hardware efficiency. FlashAttention 2 (Dao, 2023) has "the same training speed as Mamba's selective parallel scan at the sequence length of 2048" (Section 2.1.2). This means that during training with 4K sequences, neither the Mamba nor the SWA layers bottleneck the pipeline—both run at comparable speeds. If the window were larger, attention would become the bottleneck; if smaller, the recall capability would be unnecessarily limited.

**Key-Value head configuration.** The paper explores grouped-query attention for the SWA layers in Table 6. The default configuration for the 421M scale uses 12 query heads and 12 key-value heads (standard multi-head attention). However, the paper finds that reducing to 6 query heads with 1 key-value head (or 12 query heads with 1 key-value head) actually improves perplexity, particularly for SAMBA. This is interpreted as evidence that "Samba can support a smaller number of attention heads" because the Mamba layers are already handling much of the long-range dependency modeling, so the attention layers can focus on targeted retrieval with fewer, more specialized heads.

#### The MLP Layers: Factual Knowledge Recall and Nonlinear Transformation

The MLP layers use the SwiGLU activation (Shazeer, 2020), which is a gated variant of the standard feedforward network:

$$\text{SwiGLU}(x) = (xW_1 \odot \text{SiLU}(xW_2))W_3$$

where $W_1, W_2 \in \mathbb{R}^{d_m \times d_p}$ and $W_3 \in \mathbb{R}^{d_p \times d_m}$, with $d_p$ being the intermediate hidden size (typically $8/3 \cdot d_m$ for models trained on SlimPajama, and larger for the 3.8B model).

**What it computes:** The input $x$ is projected through two separate weight matrices $W_1$ and $W_2$. The second projection passes through a SiLU gate, which is multiplied element-wise with the first projection. The result is then projected back to the model dimension via $W_3$. This is a gated bilinear transformation—the SiLU gate controls how much of each dimension of the $W_1$ projection passes through.

**Why separate MLPs:** SAMBA uses separate MLPs for the Mamba layers and the SWA layers (each Mamba block has its own MLP, and each SWA block has its own MLP). This is different from architectures that share MLPs across layer types. The justification is functional specialization: the information coming out of a Mamba layer (compressed recurrent state readout) is qualitatively different from the information coming out of an SWA layer (precise but local retrieval). Having dedicated MLPs allows each pathway to learn its own nonlinear transformations and factual knowledge projections tailored to the type of representation it receives.

**Why SwiGLU:** SwiGLU is the standard MLP activation in modern LLMs (used in Llama, Mistral, Phi-3, etc.) because it consistently outperforms alternatives like ReLU or GELU in language modeling. The gating mechanism (the SiLU-controlled multiplicative interaction between the two projections) provides a richer family of nonlinear functions than a simple two-layer MLP with a single activation function.

#### Layer-Wise Interleaving: The Block Pattern

The core architectural design decision in SAMBA is how the Mamba, SWA, and MLP layers are arranged. The paper explores three hybridization strategies on the 1.7B scale (Figure 1):

**SAMBA architecture.** The default configuration alternates blocks: Mamba-MLP, then SWA-MLP, repeating through the stack. With $N = 48$ layers at the 1.7B scale, this gives 24 Mamba layers and 24 SWA layers, each followed by their own MLP.

**Mamba-SWA-MLP architecture.** This places Mamba and SWA in the same block before the MLP: each block processes the input through a Mamba layer, then an SWA layer, then an MLP. With 54 layers at the 1.7B scale (more layers because each block contains two sequence-mixing operations), this gives more direct interaction between Mamba and SWA outputs, since the SWA operates on the Mamba-processed representation within the same residual block.

**Mamba-MLP architecture.** This drops attention entirely, alternating Mamba layers with MLPs (no SWA at all). This is included as a baseline to isolate the contribution of the attention layers.

**What the interleaving accomplishes:** The alternating pattern in SAMBA is designed to create a functional specialization gradient through the network. The paper analyzes this through attention entropy in Figure 5a. When examining the Samba 1.7B model on 100 random samples from GSM8K, the attention entropy shows a characteristic U-shaped pattern across layers: the upper and lower layers have higher entropy (more uniform attention, integrating global information), while the middle layers have lower entropy (more focused attention, performing precise retrieval). In contrast, the Mistral 1.6B model (which uses SWA in every layer) shows a more uniform entropy distribution. This suggests that in SAMBA, the attention layers become specialized—some layers focus on high-precision, low-entropy retrieval while others handle broader information integration. This specialization does not emerge when every layer has the same attention mechanism.

Figure 5b examines the *selection entropy* of the Mamba layers: the entropy of the input-dependent gating probabilities $\Delta'$ (normalized to a simplex). Compared to the Mamba-MLP architecture, SAMBA's Mamba layers show higher selection entropy in the middle layers. The paper interprets this as evidence that "given the memory recalling ability of the attention layers, the Mamba layers can focus more on modeling the recurrent structure rather than performing retrieval with precise input selections." In other words, when attention handles the precise retrieval job, the Mamba layers can relax their gating, using more uniform selection across the sequence rather than trying to pinpoint specific tokens—and this relaxation is beneficial for overall performance.

#### Training Pipeline and Hyperparameter Configurations

The paper trains SAMBA models at four scales using different datasets and configurations. The training infrastructure for SlimPajama experiments uses a modified TinyLlama codebase.

**421M and 1.3B scale (SlimPajama dataset, Table 12):**

- **Dataset:** SlimPajama (Soboleva et al., 2023), a cleaned and deduplicated version of RedPajama.
- **Total training tokens:** 20B (421M), 100B (1.3B).
- **Architecture (421M):** $N = 24$ layers, $d_m = 1536$, $d_p = 4096$, 12 query heads, 12 key-value heads (no grouped-query attention at this scale), vocabulary size 32,000.
- **Architecture (1.3B):** $N = 36$ layers, $d_m = 2304$, $d_p = 6144$, 18 query heads, 18 key-value heads.
- **Training hyperparameters:** Batch size 512, learning rate $4 \times 10^{-4}$, weight decay 0.1, gradient clipping 1.0, sequence length 4096, sliding window size $w = 2048$, AdamW optimizer.

**1.7B scale (Phi-2 dataset, Table 12):**

- **Dataset:** Phi-2 (Li et al., 2023), textbook-quality synthetic data.
- **Total training tokens:** 230B.
- **Architecture:** $N = 48$ layers, $d_m = 2048$, $d_p = 8196$, 32 query heads, 4 key-value heads (grouped-query attention with 8:1 ratio), vocabulary size 50,304.
- **Training hyperparameters:** Batch size 2048, learning rate $6 \times 10^{-4}$, weight decay 0.1, gradient clipping 1.0, sequence length 4096, sliding window size 2048.

**3.8B scale (Phi-3 dataset, Table 12):**

- **Dataset:** Same textbook-quality data used for Phi-3 (Abdin et al., 2024), following the same multiphase pretraining strategy.
- **Total training tokens:** 3.2T.
- **Architecture:** $N = 64$ layers, $d_m = 2816$, $d_p = 9984$, 11 query heads, 1 key-value head (multi-query attention—extreme key-value sharing), vocabulary size 32,064.
- **Training hyperparameters (first phase):** Batch size 2048, learning rate $6 \times 10^{-4}$, weight decay 0.1, gradient clipping 1.0, sequence length 4096, sliding window size 2048.

**Why the KV head configuration changes with scale:** The paper shows that SAMBA benefits from fewer key-value heads than standard Transformers. At 1.7B, 4 KV heads (grouped-query attention with ratio 8:1) outperforms the standard 32 KV heads. At 3.8B, the model uses only 1 KV head (multi-query attention), with 11 query heads. This is consistent with the hypothesis that the Mamba layers reduce the burden on the attention mechanism—since Mamba handles much of the long-range contextual modeling, the attention layers can operate with fewer, more focused KV heads. This also reduces the KV cache size, improving inference efficiency further.

**Baseline model configurations (Table 11):** For fair comparison, the paper trains multiple architectures on the same Phi-2 dataset with 230B tokens, controlling for total parameters and training hyperparameters:

- **Llama-3 1.6B:** 48 layers, 2048 model width, 24 full-attention layers, 32 query heads, 4 KV heads.
- **Mistral 1.6B:** 48 layers, 2048 model width, sliding window attention of size 2048 on all layers, 32 query heads, 4 KV heads.
- **Mamba 1.8B:** 64 layers (more layers needed because Mamba has fewer parameters per layer than attention), 2048 model width, no attention layers.
- **Mamba-SWA-MLP 1.6B:** 54 layers, 2048 model width, 18 Mamba layers and 18 SWA layers.
- **Mamba-MLP 1.9B:** 48 layers, 2048 model width, 24 Mamba layers, no attention.

All baseline models use the same batch size (2048), learning rate ($6 \times 10^{-4}$), weight decay (0.1), gradient clipping (1.0), and sequence length (4096).

**Downstream evaluation configurations (Appendix G):** For generation during evaluation, the paper uses specific decoding strategies depending on the task:

- **GSM8K:** Greedy decoding (temperature 0).
- **HumanEval:** Nucleus sampling (Holtzman et al., 2019) with temperature $\tau = 0.2$ and top-p $= 0.95$.
- **MBPP and SQuAD:** $\tau = 0.01$ and top-p $= 0.95$.
- **Long-context summarization (GovReport, SQuALITY):** Greedy decoding, maximum generation length 450 tokens for GovReport and 600 for SQuALITY.

#### Instruction Tuning for Length Extrapolation

The paper demonstrates that SAMBA's architectural length extrapolation can be activated through minimal instruction tuning.

**Passkey Retrieval fine-tuning (Section 3.4):** The Samba 1.7B model is instruction-tuned on Passkey Retrieval with only 4K training sequence length for 500 steps. The training data is generated on-the-fly: a random 5-digit integer passkey is inserted at a random depth in a document of length 4096, and the model is asked to output the passkey given the full document. Training uses batch size 2048, 250 warm-up steps with peak learning rate $1 \times 10^{-4}$, weight decay 0.1, and AdamW optimizer.

**What happens during training:** Figure 7 shows that both SAMBA and Mistral (SWA-only) achieve near-zero training loss in under 250 steps—both architectures can learn the 4K passkey task. But the critical difference emerges in extrapolation: Figure 8 shows that SAMBA reaches near-perfect retrieval accuracy on 256K documents (64× the training length) by step 150, while Mistral remains stuck at ~30% accuracy throughout training. The SWA model has learned to find the passkey only within its 2048-token window; SAMBA has learned that the Mamba state can carry the passkey information across arbitrary gaps.

**Phonebook fine-tuning (Section 3.4):** The Samba-3.8B base model is instruction-tuned on Phonebook (Jelassi et al., 2024) with only 100 steps at 4K sequence length. The task requires retrieving a random phone number from a phone book containing 20 (length ~400) to 480 (length ~8400) name-number pairs. This creates memory pressure because the model must store an increasing number of arbitrary name-number associations in its fixed-capacity recurrent state.

**What the fine-tuning achieves:** Figure 4 shows that the fine-tuned Samba-3.8B-FT closes most of the gap with a full-attention Llama2 7B model (which has twice the parameters) within the 4K training length, and demonstrates significantly better extrapolation accuracy beyond 4K compared to all other models including Phi-3 (which also uses SWA). This is evidence that instruction tuning can teach the model to use its Mamba layers for structured memorization—actively storing and retrieving specific facts from the recurrent state—even though the base model had not learned this capability during pretraining.

#### Computational Complexity and Efficiency Rationale

The architectural choices in SAMBA are driven by a specific computational efficiency argument.

**Mamba complexity:** $O(d_e \cdot d_s)$ per token, where $d_e = 2d_m = 4096$ (for the 1.7B model) and $d_s = 16$. This is approximately 65K operations per token, independent of sequence length. The recurrent state cache size is $d_e \times d_s$ floating-point numbers per Mamba layer, which for the 3.8B model (32 Mamba layers out of 64 total) means the state cache is manageable even at extreme lengths.

**SWA complexity:** $O(w \cdot d_m)$ per token for the attention computation plus $O(w \cdot d_m)$ for the KV cache storage, where $w = 2048$. This grows linearly with sequence length because the KV cache stores the keys and values for all previous tokens within the window—but since the window is fixed, the per-token cost is constant.

**Overall complexity:** The combination yields $O(n \cdot (w \cdot d_m + d_e \cdot d_s))$ total, which is linear in both sequence length $n$ and model size. This is why SAMBA achieves 3.73× higher prompt processing throughput than Llama-3 at 128K length (Figure 6) and 3.64× faster decoding at 64K generation length (Figure 2b).

**Connection to the sliding window size choice:** The window size $w = 2048$ is not arbitrary. The paper notes that "FlashAttention 2 has the same training speed as Mamba's selective parallel scan at the sequence length of 2048." At training length 4096, this means each SWA layer processes roughly the same number of token pairs as a full-attention layer would at length ~64 (because $2048 \times 4096 / 2$ vs. $4096^2 / 2$), making the SWA layers roughly as fast as the Mamba layers. This balanced design prevents any single layer type from becoming the training bottleneck.

**Why 2× training length relative to window size:** Table 9 shows the ablation on training sequence length for SWA models. With window size fixed at 2048, the optimal training length is 4096 (2× the window size). Training at shorter lengths (2048, where the window covers the full context) produces better perplexity at 2048 but worse extrapolation beyond 2048. Training at longer lengths (8192, 16384, 32768) with proportionally smaller batch sizes produces systematically worse perplexity at all evaluation lengths due to the smaller batch size (a known phenomenon: sequence length and batch size trade off through total tokens per step). The optimal configuration balances within-window training signal with extrapolation capability.

## 4. Key Insights and Innovations

### Innovation 1: The Hybrid Architecture as Functional Specialization, Not Just Capacity Addition

The standard mental model for hybrid architectures has been additive: you take two model components that each have weaknesses, combine them, and hope the strengths of one compensate for the weaknesses of the other. This is the logic behind most prior SSM-attention hybrids — use SSMs for efficient long-range processing and attention for precise retrieval, with the combination being better than either alone. The implicit assumption is that each component continues doing what it would do in isolation, just now with help.

SAMBA challenges this with a fundamentally different idea: **hybridization enables functional specialization that changes what each component *learns to do*, not just what it can access.** The evidence is in the entropy analysis of Figure 5. When Mamba layers exist alongside attention layers, their selection entropy pattern changes — they become *less* focused on precise input selection in the middle layers compared to a pure Mamba-MLP model (Figure 5b). Simultaneously, the attention layers develop a U-shaped entropy profile across depth that does not appear in pure SWA models (Figure 5a), with middle layers showing low-entropy, high-precision attention and outer layers showing high-entropy, integrative attention.

This is not merely "Mamba handles long range, attention handles short range." If that were true, you would expect the attention entropy distribution to mirror what SWA models already do — all layers being similarly precise — and the Mamba selection to mirror what pure Mamba does. Instead, both components change their behavior in each other's presence. The Mamba layers, freed from having to also serve as the primary retrieval mechanism, relax their gating and focus on modeling recurrent structure. The attention layers, knowing that Mamba is handling much of the global context, can afford to specialize — some becoming extremely precise retrieval heads, others becoming broad integration heads. The hybrid does not just add capabilities; it **redistributes the computational roles** across the network.

This is a conceptual contribution with implications beyond SAMBA. It suggests that architecture design should not be approached as "which components do we need to cover all capabilities," but rather as "what combination of components induces the most useful *division of labor*?" The fact that different hybridization patterns (Samba vs. Mamba-SWA-MLP vs. Mamba-MLP) produce non-trivially different downstream performance profiles (Table 2 — Mamba-SWA-MLP excels at GSM8K while Samba leads on language understanding) further supports this: the arrangement matters because it changes what each layer learns, not just because it changes connectivity. The specialization pattern is emergent from the training dynamics, not pre-specified by the architectural constraints.

The significance here is that the paper provides a **diagnostic framework** (entropy-based analysis) for understanding *why* hybrids work, moving beyond the hand-wavy "best of both worlds" narrative that has characterized most prior work on hybrid architectures.

---

### Innovation 2: Length Extrapolation Through Architectural Inductive Bias, Not Position Engineering

The dominant approach to length extrapolation in the attention literature has been to take a model trained on short sequences and apply position embedding modifications at inference time — Rotary Position Interpolation (Chen et al., 2023a), SelfExtend (Jin et al., 2024), LM-Infinite (Han et al., 2023), StreamingLLM (Xiao et al., 2024), and others. These methods share a common structure: the model architecture is fundamentally quadratic, and extrapolation is achieved by manipulating or constraining the attention pattern so that it behaves similarly at long lengths to how it behaved at short lengths. They are *bandages* on the quadratic complexity problem, not solutions to it.

SAMBA proposes a fundamentally different strategy: **make the architecture itself translation-invariant with respect to sequence length, so that extrapolation is a natural property of the architecture rather than something achieved through inference-time intervention**. The key mechanism is the combination of selective state spaces (which process tokens sequentially with constant per-token cost, regardless of total length) with sliding window attention whose window size is fixed independent of sequence length. A model trained on 4K sequences and tested on 1M sequences sees exactly the same computational pattern at each position — attention within a 2048-token window, recurrent state update with input-dependent gating. There is no "out-of-distribution" attention pattern because the pattern is defined locally and dimensionally, not relative to the total sequence length.

What makes this an innovation rather than an obvious consequence of using SWA and SSMs is the empirical demonstration that **prior architectural choices that seem translation-invariant fail to extrapolate in practice**. Table 3 shows that Samba-NoPE (SAMBA without rotary position embeddings, relying purely on the translation-invariant Mamba and SWA operations) has exploding perplexity beyond 4K length, with perplexity jumping from ~10 at 4096 to ~315 at 16384 for the 421M model. This is a striking failure: the architecture *should* be translation-invariant, but removing RoPE breaks extrapolation entirely. The paper identifies that RoPE within the sliding window provides a necessary *local* position signal — the model needs to know relative distances within its window, even if the window itself slides translation-invariantly. This is a subtle interaction: global translation invariance requires local position awareness.

Equally important is the negative result about RetNet in Table 3: Sliding RetNet extrapolates well at 438M (perplexity ~10.38 → 9.87 from 4K to 16K) but begins to degrade at 1.3B (~7.56 → 7.56, with the trend suggesting instability). The input-independent decay in RetNet, which works at small scale, does not reliably extrapolate as model capacity increases — the fixed decay schedule becomes a brittleness rather than a feature. Mamba's input-dependent selection avoids this because the model can adapt its effective decay rates during training to match whatever scale it is operating at.

The practical significance is captured in Figure 2: SAMBA achieves improved perplexity (not just stabilized, but actively improving) from 4K to 1M tokens on Proof-Pile. This is qualitatively different from the "prevent explosion" goal of most extrapolation methods. The model is not just tolerating longer sequences — it is *using* the additional context to make better predictions. This suggests that the recurrent state in Mamba layers genuinely accumulates useful information over extreme lengths, and the SWA layers provide the necessary local precision to complement that accumulated signal.

This is a **fundamental shift** in the approach to length generalization: instead of asking "how do we trick the attention pattern into working at longer lengths," SAMBA asks "how do we design the architecture so that length is not a parameter the network needs to generalize over." The fact that this approach also yields linear complexity and competitive short-context performance makes it not just conceptually cleaner but practically superior.

---

### Innovation 3: The Pretraining-Test-Time-Compute Tradeoff as an Empirical Finding, Not a Speculative Claim

The idea that test-time computation can substitute for model size or pretraining compute has been discussed theoretically (Jones, 2021; Villalobos and Atkinson, 2023) and explored in constrained settings, but no prior hybrid architecture had demonstrated at production scale that a linear-complexity model could **simultaneously outperform equivalently-trained dense Transformers on standard benchmarks *and* provide computational efficiency gains that change the deployment economics.** SAMBA provides this demonstration concretely.

The key evidence is Table 1 and the associated throughput measurements. SAMBA 3.8B, trained on identical data with identical recipes as Phi-3-mini, achieves superior scores on every benchmark: MMLU (71.9 vs. 68.8), GSM8K (87.6 vs. 82.5), HumanEval (62.8 vs. 58.5), and GovReport (18.9 vs. 14.4). These are not marginal improvements — they represent substantial capability gains at the same parameter count and training budget. At the same time, SAMBA processes prompts 3.73× faster and decodes 3.64× faster than a comparable Transformer at 128K length (Figure 6, Figure 2b). The architecture is simultaneously **better at the task and cheaper to run**.

What makes this an innovation beyond the performance numbers is that it resolves an empirical tension that had persisted in the literature. Prior hybrid architectures — H3, MEGA, Block State Transformers, Jamba, Griffin — had shown that it was *possible* to combine SSMs with attention without catastrophic performance loss. But none had demonstrated that the combination could be **strictly better** than the best available Transformer trained under equivalent conditions. Griffin and RecurrentGemma achieved comparable or slightly worse results. Jamba showed strong results but at larger scales and without the controlled-equivalent-training comparison. SAMBA's controlled comparison against Phi-3-mini (same data, same recipes, same post-training) removes the confound of training data quality and establishes that the architectural difference alone accounts for the performance gap.

The FLOPs-matched implications are substantial even though the paper does not frame them in an explicit pretraining-vs-inference tradeoff analysis. A model that is 3.7× more throughput-efficient at 128K context length effectively provides 3.7× more inference compute per dollar at that sequence length. For deployment scenarios where long-context processing dominates the compute budget (document analysis, codebase reasoning, long-form dialogue), this is equivalent to a ~4× reduction in inference costs with **better** output quality. This is not a speculative future benefit — it is a realized empirical result at 3.8B scale with 3.2T training tokens.

The importance is that this shifts the burden of proof in the architecture discussion. Before SAMBA, the default assumption was that dense Transformers represent the upper bound on language modeling capability, and efficient architectures (SSMs, linear attention, hybrids) trade off some capability for efficiency. SAMBA demonstrates that this tradeoff is not fundamental — **a properly designed hybrid can be both more capable and more efficient**. This has direct implications for how organizations allocate research effort: pursuing hybrid architectures is not just about reducing costs at the expense of quality; it is a path to Pareto-dominating current Transformer architectures on both axes simultaneously.

---

### Innovation 4: In-Context Memory Recall as a Learnable Skill That Minimal Fine-Tuning Can Activate

It is widely recognized that SSMs and linear recurrent models struggle with in-context recall tasks compared to Transformers (Arora et al., 2023; Fu et al., 2023; Wen et al., 2024). The natural interpretation of this finding is that the finite-capacity recurrent state simply cannot store enough information to support precise retrieval — a fundamental capacity limitation, not a training limitation. The baseline evidence in the paper supports this view: the pre-trained SAMBA model "has a retrieval accuracy (at step 0) similar to that of Mistral" (Section 3.4), meaning the hybrid architecture does not automatically solve the recall problem during pretraining.

What SAMBA demonstrates is that this limitation is **partially remediable through targeted instruction tuning that is dramatically sample-efficient**. The Passkey Retrieval result (Figure 3, Figure 8) shows that 500 steps of fine-tuning on 4K training sequences teaches SAMBA to retrieve passkeys at 256K context length — 64× beyond the training length. The Mistral architecture trained identically fails to exceed ~30% accuracy. This is not a small difference in sample efficiency; it is a qualitative gap in whether the capability can be learned at all under these constraints.

The significance is not that SAMBA can do passkey retrieval — that is a synthetic task. The significance is what this reveals about the architecture's representational capacity: **the Mamba layers have the capacity to store and retrieve specific factual information over very long distances, but this capacity is not automatically exploited during language modeling pretraining.** The pretraining objective (next-token prediction on internet text) rarely requires the model to store and later retrieve an arbitrary token from thousands of positions earlier. Most long-range dependencies in natural language are semantic and structural (maintaining topic coherence, tracking entities) rather than verbatim recall of specific tokens. The pretrained model learns to use its Mamba state for these semantic dependencies, but does not learn to use it as a precise memory buffer for arbitrary facts.

The instruction tuning on Passkey Retrieval teaches the model a new use for its existing architectural capacity — it learns to *actively encode* specific tokens into the recurrent state and *actively decode* them later, rather than relying on the state to passively capture whatever semantic gist is relevant for next-token prediction. This is supported by the Phonebook results (Figure 4), where 100 steps of instruction tuning teach SAMBA-3.8B to close most of the gap with a twice-as-large full-attention Llama2 model on structured retrieval within the training length, while extrapolating better beyond it.

This finding reframes the recall limitation of SSMs from "they cannot do this" to "they do not learn to do this during standard pretraining, but can learn with minimal targeted training." The distinction matters for deployment: it suggests that a SAMBA model could be pretrained once on general data, then cheaply fine-tuned for specific long-context retrieval tasks without architectural modification. The transfer experiment (Samba 1.7B PK-FT fails on Phonebook in zero-shot, Figure 4) suggests the learned recall skill is currently task-specific rather than general, pointing to future work on whether multi-task retrieval fine-tuning could produce a general recall capability.

This is a **diagnostic finding** that changes how we interpret the gap between SSMs and Transformers on recall tasks — it is not purely a capacity limitation, but at least partially a training objective mismatch — and a **practical finding** that enables long-context applications with minimal fine-tuning cost.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The primary training datasets are SlimPajama (Soboleva et al., 2023) for smaller-scale experiments (421M and 1.3B models), the Phi-2 dataset (Li et al., 2023) for 1.7B-scale architecture comparisons, and the Phi-3 dataset (Abdin et al., 2024) for the largest 3.8B model. SlimPajama is a cleaned and deduplicated 627B-token version of RedPajama. Phi-2 and Phi-3 are textbook-quality synthetic datasets whose exact composition is not detailed in the paper but is described as following the data synthesis approach of the Phi model family. For length extrapolation evaluation, the Proof-Pile test set (Zhangir Azerbayev & Piotrowski, 2022) is used with Position Interpolation preprocessing (Chen et al., 2023a). The validation set of SlimPajama is used for perplexity measurements in the architecture comparison tables. For downstream long-context summarization, GovReport (Huang et al., 2021) and SQuALITY (Wang et al., 2022) from the ZeroSCROLLS benchmark (Shaham et al., 2023) are used, with average tokenized document lengths of 11,533 and 7,974 tokens respectively (Appendix F). Passkey Retrieval (Mohtashami & Jaggi, 2023) and Phonebook (Jelassi et al., 2024) serve as synthetic long-context retrieval evaluations.

- **Base model(s).** The paper trains SAMBA models at four scales: 421M, 1.3B, 1.7B, and 3.8B parameters. The 421M and 1.3B models use SlimPajama for controlled architecture ablations. The 1.7B models are trained on Phi-2 for head-to-head architecture comparisons against baselines. The 3.8B model uses the full Phi-3 training pipeline (3.2T tokens, multiphase pretraining) for comparison against state-of-the-art Transformers. All SAMBA models share the same architectural principles: alternating Mamba-MLP and SWA-MLP blocks with sliding window size $w = 2048$, sequence length 4096 during training, and RoPE with base frequency 10,000. Baseline architectures compared include Llama-3 (MetaAI, 2024; Dubey et al., 2024), Mistral (Jiang et al., 2023), pure Mamba (Gu & Dao, 2023), and various hybrid configurations (Mamba-SWA-MLP, Mamba-MLP). The Phi-3-mini Transformer (Abdin et al., 2024) serves as the primary state-of-the-art baseline for the 3.8B comparison, trained on identical data with identical recipes.

- **Metrics.** For language modeling quality, the paper uses perplexity on validation sets (SlimPajama for architecture ablations, Proof-Pile for length extrapolation). For downstream evaluation, it uses accuracy (MMLU, ARC, PIQA, WinoGrande, SIQA, BoolQ, OpenbookQA, TruthfulQA), character-normalized accuracy (HellaSwag, ARC-Challenge following Gu & Dao, 2023), exact match (SQuAD), pass@1 (HumanEval), maj@1 (GSM8K), and ROUGE-L (GovReport, SQuALITY). For long-context retrieval, Passkey Retrieval accuracy is computed as the fraction of correctly retrieved 5-digit passkeys, stratified by document depth and length. Phonebook accuracy measures the fraction of correctly retrieved phone numbers across varying numbers of name-number pairs. Efficiency is measured as peak training throughput (tokens/second on 8×H100 or 8×A100 GPUs), prompt processing throughput (tokens/second on a single A100 GPU with bfloat16), and decoding throughput (tokens/second with batch size 16).

- **Baselines.** The paper compares against an extensive set of architectures: (1) **Llama-3 1.6B** and **Mistral 1.6B** — standard Transformer architectures with full attention and SWA respectively, trained on Phi-2 with 230B tokens; (2) **Mamba 1.8B** — pure SSM model with 64 layers trained on Phi-2; (3) **Mamba-SWA-MLP 1.6B** and **Mamba-MLP 1.9B** — alternative hybridization strategies trained on Phi-2; (4) **Phi-3-mini-4K-instruct** (Abdin et al., 2024) — a state-of-the-art 3.8B Transformer trained on the same Phi-3 data with the same recipes; (5) **Llama-2 1.3B** (Touvron et al., 2023) and **Llama-2-SWA 1.3B** — for SlimPajama-scale ablations; (6) **Sliding RetNet 1.4B**, **Sliding GLA 1.2B**, **Mega-S6 1.3B**, **MLP2-SWA-MLP 1.3B**, and **SAMBA-NoPE 1.3B** — alternative linear recurrent and hybrid architectures for the component ablation in Table 3; (7) **Llama-2 6.7B/13B**, **Mistral 7.2B**, **Gemma 2.5B/8.5B** (Team, 2024), **R-Gemma 2.7B** (Botev et al., 2024), **Llama-3 8B**, and **TFM++ 3.8B** — for the comprehensive base model comparison in Table 7; (8) **Llama-2 7B** — for the Phonebook full-attention baseline in Figure 4; (9) **SE-Llama-3 1.6B** — Llama-3 with SelfExtend (Jin et al., 2024) applied for zero-shot length extrapolation, using group size 4 and neighborhood window 1024. For the post-trained model comparison (Table 8), baselines include **R-Gemma 9B**, **FalconMamba 7B**, **Jamba-1.5-Mini 12B/52B** (Team et al., 2024), **Llama-3.2-Instruct 3B**, and **Llama-3.1-Instruct 8B**.

- **Generation budget / compute accounting.** For training efficiency, throughput is measured in tokens per second on a specified GPU configuration (8×H100 for the 100B-token SlimPajama experiments, 8×A100 for the 20B-token experiments). For inference, prompt processing throughput is measured with the total processing tokens fixed at 128K per measurement, varying batch size accordingly, on a single A100 GPU with bfloat16 precision, with measurements repeated 10 times and averaged (Section 3.3). Decoding throughput is measured at batch size 16 for sequences of up to 64K generation length. All models in the architecture comparisons are trained with identical sequence length (4096), batch size (2048 for Phi-2, 512 for smaller SlimPajama experiments), and total tokens per step (2M for the SlimPajama batch-size-vs-sequence-length ablation in Table 9) to ensure fair comparison. The key efficiency ratios reported are 3.73× higher prompt processing throughput compared to Llama-3 1.6B at 128K prompt length (Figure 6) and 3.64× faster decoding throughput at 64K generation length (Figure 2b).

- **Cross-validation / statistical protocol.** The paper does not employ formal cross-validation or statistical significance testing. For the Phi-2 architecture comparison (Table 2), all models are trained once on the same 230B tokens with the same hyperparameters, and downstream evaluation uses standard benchmark protocols (0-shot or 5-shot as noted). For the SlimPajama perplexity measurements (Tables 3, 5, 6, 9, 10), the paper notes that "perplexity results have a fluctuation around ±0.3%," providing a rough estimate of measurement noise but not formal confidence intervals. The Passkey Retrieval evaluation (Figure 3) tests at 11 different depth positions and 5 different passkeys per depth for each document length, with the heatmap showing accuracy across these conditions. The Phonebook evaluation (Figure 4) tests on varying numbers of name-number pairs from 20 to 480. For the 3.8B model comparison against Phi-3-mini, the paper states that both models use "the same training recipes and datasets" (Table 1), controlling for training pipeline differences. However, there is no mention of multiple training runs, seed variation, or statistical testing of the reported performance gaps.

### Main Quantitative Results

#### Architecture Comparison at 1.7B Scale on Downstream Benchmarks

The central architecture comparison appears in Table 2, where six models with approximately 1.7B parameters are trained on the same Phi-2 dataset with 230B tokens and evaluated across 15 diverse benchmarks. SAMBA achieves the highest average accuracy at **54.33**, substantially ahead of Llama-3 (51.17), Mistral (51.12), and pure Mamba (52.31). The gap is not uniform across tasks: SAMBA leads on MMLU (**48.01** vs. 43.84 for Llama-3 and 45.28 for Mamba), SQuAD (**77.64** vs. 74.88 for Llama-3 and 67.66 for Mamba), and HumanEval (**39.02** vs. 36.59 for both Llama-3 and Mistral). On BoolQ, SAMBA achieves **75.57** compared to 68.20 for Llama-3. On TruthfulQA, SAMBA scores **27.78** (MC1) and **41.62** (MC2) versus 25.70 and 40.35 for Llama-3.

The pure Mamba model shows a distinctive weakness pattern that SAMBA directly addresses: Mamba scores only 67.66 on SQuAD (the lowest among all architectures by a substantial margin), confirming the retrieval limitation of pure SSMs as noted in Section 1. Mamba-MLP, which replaces half the Mamba layers with MLPs, drops dramatically on GSM8K (**27.52** vs. Mamba's 32.07) and HumanEval (**31.10** vs. Mamba's 35.98), suggesting that removing Mamba layers disproportionately harms complex reasoning capabilities. Mamba-SWA-MLP achieves the best GSM8K score at **44.05** — substantially above SAMBA's 38.97 — indicating that closer collaboration between Mamba and attention layers (placing them in the same block rather than separate blocks) may benefit mathematical reasoning specifically, though this configuration underperforms SAMBA on average across all tasks.

The Llama-3 architecture (full attention) and Mistral architecture (sliding window attention on all layers) show remarkably similar average performance (51.17 vs. 51.12), suggesting that replacing full attention with SWA does not inherently degrade short-context capabilities when all layers use attention — the degradation only becomes apparent at longer contexts.

#### Perplexity and Length Extrapolation Across Architectures

Table 3 provides the most comprehensive architecture comparison, evaluating 11 different model variants at both ~438M and ~1.3B scales on SlimPajama, measuring perplexity at 4096 (training length), 8192 (2×), and 16384 (4×) context lengths.

At the 1.3B scale with 100B training tokens, SAMBA achieves the lowest perplexity at all three context lengths: **7.32** at 4K, **7.11** at 8K, and **6.96** at 16K. The perplexity *improves* as context length increases, indicating that the model effectively uses the additional context for better prediction rather than merely tolerating it. Mamba-SWA-MLP is the closest competitor (**7.37** / 7.16 / 7.00), followed by pure Mamba (**7.47** / 7.26 / 7.15). The Transformer baselines show the expected behavior: Llama-2 with full attention explodes from 7.60 at 4K to 249.64 at 16K; Llama-2-SWA with pure sliding window attention extrapolates stably (7.60 / 7.37 / 7.21) but underperforms SAMBA at all lengths. Sliding GLA (7.58 / 7.35 / 7.19) and Sliding RetNet (7.56 / 7.35 / 7.56) are competitive with SWA-only Transformers but do not match SAMBA. Mega-S6 underperforms substantially (9.01 / 8.81 / 8.68), suggesting that intra-layer SSM-attention hybridization is less effective than the layer-wise interleaving approach.

The **SAMBA-NoPE** ablation is particularly revealing: at the 1.3B scale, removing RoPE causes perplexity to explode from 7.33 at 4K to 326.17 at 16K, nearly matching the full-attention Llama-2 failure mode (249.64). This demonstrates that RoPE within the sliding window is essential for length extrapolation even though SWA itself is translation-invariant — the model needs local position awareness to function properly.

The 438M-scale results (20B tokens) show consistent patterns: SAMBA leads at all context lengths (10.06 / 9.65 / 9.57), SAMBA-NoPE fails beyond 4K (10.11 / 28.97 / 314.78), and the full-attention Llama-2 explodes (11.14 / 47.23 / 249.03). An interesting scale-dependent finding emerges with RetNet: Sliding RetNet extrapolates well at 438M (10.38 / 9.96 / 9.87) but shows degradation at 1.3B (7.56 / 7.35 / 7.56 with the 16K perplexity matching the 4K value rather than improving), suggesting that input-independent decay mechanisms may not scale robustly.

Training throughput measurements in Table 3 show that SAMBA achieves **25.2 × 10^5 tokens/second** at the 1.3B scale, matching Llama-2 and Llama-2-SWA (25.9 and 26.2) and substantially exceeding pure Mamba (17.8). This is because Mamba layers are more I/O-intensive than MLP layers, and pure Mamba requires more total layers (48 vs. 36 for Samba at 1.3B) to reach the same parameter count. The throughput advantage of SAMBA over pure Mamba increases with scale.

#### Downstream Evaluation of SlimPajama-Trained Architectures

Table 4 evaluates the 1.3B-scale SlimPajama-trained models on five commonsense reasoning benchmarks. SAMBA achieves the highest average accuracy at **58.54**, slightly ahead of SAMBA-NoPE (58.52) and Mamba-SWA-MLP (58.19). The Llama-2 baseline scores 56.08. SAMBA's largest advantage appears on LAMBADA (**51.68** vs. 48.52 for Llama-2 and 45.97 for Mamba), a task requiring broad discourse context — precisely where the combination of recurrent compression and local attention should excel. On HellaSwag, Mamba achieves the highest score (54.93) with SAMBA close behind (54.73). The Mega-S6 architecture performs notably poorly across all tasks (average 50.31), reinforcing the finding that intra-layer hybridization is less effective.

#### Length Extrapolation to 1M Tokens

Figure 2a shows perplexity on the Proof-Pile test set for five models evaluated at context lengths from 1K to 1M tokens, with all models trained at 4K sequence length. SAMBA 1.7B shows **improved perplexity throughout the entire range**, declining from approximately 5.5 at 1K to approximately 4.0 at 1M — a pattern of genuine improvement from additional context. Mamba 1.8B shows a "slowly and stably increasing perplexity up to 1M sequence length" (Section 3.3), consistent with the finite capacity of its recurrent state gradually being exceeded but not catastrophically. Llama-3 1.6B (full attention) explodes immediately beyond 4K. Mistral 1.6B (SWA on all layers) extrapolates but with flatter and slightly worse perplexity than SAMBA. SE-Llama-3 1.6B, using the SelfExtend zero-shot extrapolation technique, shows better extrapolation than the base Llama-3 but with perplexity increasing notably by 1M and, as noted in the text, with "significant inference latency overhead."

#### Prompt Processing and Decoding Throughput

Figure 6 and Figure 2b present the efficiency results. At 128K prompt length, SAMBA achieves **3.73× higher throughput** than Llama-3 1.6B (Figure 6), with the processing time remaining linear with respect to sequence length for SAMBA while growing quadratically for full-attention models. At 64K generation length with batch size 16, SAMBA achieves **3.64× faster decoding** than the Llama-3 architecture (Figure 2b). The efficiency advantage grows with sequence length — at shorter lengths, the gap is smaller because the quadratic attention cost is less dominant.

#### Instruction-Tuned Length Extrapolation: Passkey Retrieval

Figure 3 presents the Passkey Retrieval results after 500 steps of instruction tuning on 4K sequences. The heatmaps show that SAMBA 1.7B achieves **near-perfect retrieval across all depths** (0% to 100%) and all context lengths from 4K to 256K, maintaining scores of 0.9–1.0 throughout the grid. Mistral 1.6B, by contrast, shows perfect retrieval only within the 4K training length, with performance dropping sharply beyond 4K — by 32K, retrieval accuracy is near zero except at very shallow depths. The Mistral model's SWA layers simply cannot access the passkey when it falls outside the 2048-token window. Figure 8 shows the training dynamics: SAMBA achieves near-perfect overall accuracy at 256K by step 150, while Mistral fluctuates around 0.3 accuracy for the entire 500-step training run, despite both models reaching near-zero training loss on the 4K training data (Figure 7) in under 250 steps. The base pre-trained SAMBA model (step 0 in Figure 8) has retrieval accuracy similar to Mistral, confirming that the capability is learned during instruction tuning, not present from pretraining.

#### Instruction-Tuned Long-Context Retrieval: Phonebook

Figure 4 shows Phonebook evaluation accuracy for various models as the number of name-number pairs increases from 20 (length ~400) to 480 (length ~8400). The Samba-3.8B-FT model, fine-tuned for only 100 steps on 4K sequences, achieves accuracy comparable to the full-attention Llama2 7B model (which has twice the parameters) within the 4K training length — both near 1.0 accuracy at 20 pairs, declining to approximately 0.5–0.6 at 250 pairs (length ~4400). Beyond the 4K training length, SAMBA-3.8B-FT demonstrates **substantially better extrapolation** than all other models: at 480 pairs (length ~8400), SAMBA-3.8B-FT achieves approximately 0.3 accuracy versus near-zero for Phi3 3.8B, SAMBA 3.8B (base, not fine-tuned), and the Mistral-based models. The Samba 1.7B PK-FT model (fine-tuned on Passkey Retrieval) fails to transfer to Phonebook, achieving accuracy similar to Mistral 1.6B PK-FT — both near zero beyond the window size — indicating that the recall skill learned through fine-tuning is task-specific rather than general.

#### Large-Scale 3.8B Model Results

Table 1 presents the flagship comparison: SAMBA-3.8B-IT vs. Phi-3-mini-4K-instruct, both trained on identical data with identical recipes. SAMBA outperforms on every benchmark: MMLU **71.9** vs. 68.8, GSM8K **87.6** vs. 82.5, HumanEval **62.8** vs. 58.5, GovReport **18.9** vs. 14.4, and SQuALITY **21.2** vs. 21.6 (the only metric where Phi-3-mini is slightly ahead, by 0.4 ROUGE-L). Table 7 provides the broader base model comparison against 7 other architectures. SAMBA 3.8B achieves the highest average score of **64.2**, substantially ahead of TFM++ 3.8B (60.1, the Transformer trained on identical data), Llama-3 8B (55.8), and Mistral 7.2B (53.6). The GSM8K gap is particularly striking: SAMBA scores **69.6** vs. 51.5 for TFM++, an 18.1 percentage point absolute improvement. MMLU shows SAMBA at **71.2** vs. 67.2 for TFM++. On HumanEval, SAMBA achieves **54.9** vs. 51.8.

Table 8 compares post-trained chat models. SAMBA (June) 3.8B achieves an average of **66.1**, ahead of Phi-3 (June) 3.8B at 64.4, Jamba-1.5-Mini at 63.5 (despite Jamba having 12B active and 52B total parameters), Llama-3.1-Instruct 8B at 62.1, and Llama-3.2-Instruct 3B at 58.5. The largest advantage over Phi-3 appears on HumanEval (70.1 vs. 66.5) and MBPP (71.7 vs. 70.0), while MMLU-Pro shows 47.9 vs. 46.5.

#### Training Length vs. Window Size Ablation

Table 9 explores the relationship between training sequence length and SWA performance. With window size fixed at 2048, training Llama-2-SWA at different sequence lengths reveals that the optimal configuration is sequence length 4096 (2× the window size), achieving validation perplexity of **11.87 at 2K, 11.16 at 4K, 10.69 at 8K, and 10.61 at 16K**. Training at 2048 (where the window covers the full context) yields better perplexity at 2048 (11.59 vs. 11.87) but worse extrapolation to 16K (357.32 vs. 10.61). Training at longer lengths (8192, 16384, 32768) with proportionally reduced batch sizes produces systematically worse perplexity at all evaluation lengths (e.g., 32768 training length yields 12.94 at 2K, 12.46 at 4K, 11.96 at 8K, 11.86 at 16K), attributed to the smaller batch size rather than the increased sequence length itself.

### Ablation Studies and Robustness Checks

- **Full attention vs. sliding window attention in hybrid models (Table 5):** Replacing SWA with even a single full-attention layer at any position in a Mamba-MLP architecture causes extrapolation perplexity to explode at 16K. A model with full attention at block index 0 (first block) shows perplexity 10.89 at 4K, 10.55 at 8K, and 10.63 at 16K — technically not exploding but substantially worse than SAMBA's 9.57 at 16K. Full attention at index 11 (last block) yields 10.29 / 10.53 / 13.66 (exploding by 16K). Placing full attention at indices 1 and 5 (middle blocks, following the H3 pattern from Dao et al., 2022b) bridges the gap at training length but still cannot extrapolate: 10.06 / 10.34 / 13.57. SAMBA with SWA at odd indices achieves 10.06 / 9.65 / 9.57 — the only configuration that extrapolates with improving perplexity. The training speed of SAMBA (8.59 × 10^5 tokens/s) also exceeds all full-attention variants (7.78–7.93).

- **Number of query heads and key-value heads in SAMBA vs. SWA-only models (Table 6):** Both Llama-2-SWA and SAMBA at the 430M scale show best perplexity with fewer KV heads than the default multi-head configuration. For Llama-2-SWA, reducing from 12 query heads / 2 KV heads to 12 query heads / 1 KV head improves 16K perplexity from 10.56 to 10.35. For SAMBA, the optimal configuration is 12 query heads / 1 KV head (perplexity 9.58 at 16K) or 6 query heads / 1 KV head (9.51 at 16K), both better than the default 12/2 configuration (9.60). The paper interprets this as evidence that "Samba can support a smaller number of attention heads" because Mamba layers handle much of the dependency modeling. The most aggressive grouping (12 query heads / 4 KV heads, doubling the KV cache size) performs worst in both architectures, suggesting that at small scales, reducing KV heads aids optimization.

- **Alternative linear recurrent layers for hybridization (Table 3):** Replacing Mamba with Multi-Scale Retention (Sliding RetNet), Gated Linear Attention (Sliding GLA), or an intra-layer SSM-attention hybrid (Mega-S6) consistently underperforms SAMBA across both 438M and 1.3B scales. At 1.3B, Sliding GLA achieves 7.58 / 7.35 / 7.19 vs. SAMBA's 7.32 / 7.11 / 6.96. Sliding RetNet shows degradation at scale: 7.56 / 7.35 / 7.56 at 1.3B (16K perplexity equals 4K, suggesting the model is not using the additional context). Mega-S6 underperforms significantly (9.01 / 8.81 / 8.68). At 438M, the gaps are smaller but consistent: SAMBA 10.06 / 9.65 / 9.57 vs. Sliding RetNet 10.38 / 9.96 / 9.87 vs. Sliding GLA 10.43 / 10.00 / 9.92.

- **Replacing Mamba layers with MLP layers (Table 3, "MLP2-SWA-MLP"):** When all Mamba layers in SAMBA are replaced with SwiGLU layers (with 6×d_m^2 parameters to match parameter count), perplexity degrades from SAMBA's 7.32 / 7.11 / 6.96 to 7.81 / 7.58 / 7.42 at 1.3B, and from 10.06 / 9.65 / 9.57 to 10.95 / 10.50 / 10.41 at 438M. Training speed improves (26.6 vs. 25.2 at 1.3B, 5.08 vs. 4.46 at 438M) because MLP layers are less I/O-intensive than Mamba, but the perplexity cost is substantial, confirming the importance of the Mamba layers specifically (not just additional parameters) for the architecture's performance.

- **Removing rotary position embeddings (SAMBA-NoPE, Tables 3 and 4):** SAMBA without RoPE shows perplexity exploding beyond training length: at 1.3B, 7.33 at 4K → 20.40 at 8K → 326.17 at 16K. This is comparable to full-attention Llama-2's failure mode (7.60 → 44.32 → 249.64). On downstream tasks (Table 4), SAMBA-NoPE performs comparably to SAMBA on short-context benchmarks (average 58.52 vs. 58.54) and even leads on some (LAMBADA 51.08 vs. 51.68 for SAMBA, WinoGrande 56.51 vs. 55.72). This dissociation — RoPE is critical for length extrapolation but not for short-context performance — is a non-obvious finding: the architecture needs local position information specifically for handling sequences longer than it was trained on, even though the SWA and Mamba operations are themselves translation-invariant.

- **Short Convolution added to other architectures (Table 10):** Adding the Short Convolution operator from Mamba to Llama-2-SWA improves 16K perplexity from 10.57 to 10.31. Adding SC to Sliding RetNet improves from 9.87 to 9.74. Adding SC to Sliding GLA produces only a marginal gain (9.92 to 9.87). Even with SC enhancement, Sliding RetNet (9.74) and Sliding GLA (9.87) do not match SAMBA (9.57), justifying the choice of Mamba specifically over alternative linear recurrences.

- **Instruction tuning length and sample efficiency (Figures 7, 8):** For Passkey Retrieval, both SAMBA and Mistral converge to near-zero training loss on 4K sequences in under 250 steps (Figure 7). However, SAMBA achieves near-perfect 256K retrieval accuracy by step 150, while Mistral never exceeds ~30% (Figure 8). This demonstrates that the architectural capability for long-range recall can be activated with minimal fine-tuning (150–500 steps), but that this activation is only possible in architectures that have a mechanism for carrying information beyond the local window — SWA-only models fundamentally cannot learn this.

- **Difficulty-based bin analysis (implicit in Figure 3 heatmap):** The Passkey heatmap (Figure 3, left) shows that SAMBA's retrieval is perfect across all depths (0% to 100%) and all lengths (4K to 256K). The Mistral heatmap (Figure 3, right) shows that within the 4K training length, retrieval is also perfect across all depths, but beyond 4K, retrieval only works when the passkey is at very shallow depths (within the 2048-token window from the end). This is a sharp demonstration that the recall limitation is purely about architectural access — Mistral can do the task perfectly when the target is within its window, and fails completely when it is outside, with no gradual degradation.

- **Transfer learning between retrieval tasks (Figure 4):** The Samba 1.7B PK-FT model (fine-tuned on Passkey Retrieval) fails to transfer its recall ability to Phonebook, achieving accuracy near zero beyond the window size, similar to Mistral 1.6B PK-FT. This negative result indicates that the recall skill learned through Passkey fine-tuning is task-specific — the model learns to store and retrieve passkey-like patterns, not a general "store arbitrary facts in the recurrent state" capability.

- **Scale consistency of architectural advantages (Tables 3, 7):** The SAMBA advantage over Transformers and pure Mamba is consistent from 438M to 3.8B parameters. Table 3 shows SAMBA > Mamba-SWA-MLP > Mamba ≈ Sliding GLA > Llama-2-SWA > Llama-2 at both 438M and 1.3B scales for perplexity. Table 7 shows SAMBA 3.8B > TFM++ 3.8B > Llama-3 8B > Mistral 7.2B at the 3.8B scale for downstream benchmarks. The GSM8K advantage is notably scale-dependent: at 1.3B (Table 4), SAMBA's advantage on GSM8K-like reasoning is not directly measured, but at 1.7B (Table 2), SAMBA scores 38.97 vs. Mamba's 32.07, and at 3.8B (Table 7), SAMBA scores 69.6 vs. TFM++'s 51.5 — an 18.1 point gap that is proportionally larger than at the smaller scale.

### Critical Assessment

The experiments collectively support the paper's central architectural claim — that interleaving Mamba with Sliding Window Attention produces a model that outperforms equivalently-trained Transformers on short-context tasks while enabling linear-complexity length extrapolation — but the strength of evidence varies across the specific assertions.

**Claim: SAMBA substantially outperforms state-of-the-art Transformers trained under identical conditions.** The controlled comparison in Table 1 and Table 7 provides strong evidence for this at the 3.8B scale. SAMBA beats Phi-3-mini on 9 of 10 reported metrics, with particularly large margins on GSM8K (+5.1 points over Phi-3-instruct, +18.1 points over TFM++ base) and HumanEval (+4.3 points over Phi-3-instruct). The identical training data and recipe remove the most common confound in architecture comparisons. However, the evidence is from a single training run of each model. Given the well-known variance in large-scale training runs (different random seeds can produce meaningfully different final checkpoints), the reported gaps — especially the smaller ones like SQuALITY (21.2 vs. 21.6, a 0.4 ROUGE-L difference) — may not be statistically reliable. The paper provides no error bars, confidence intervals, or multi-seed results.

**Claim: SAMBA extrapolates to 1M tokens with improved perplexity.** Figure 2a shows SAMBA perplexity declining from ~5.5 to ~4.0 across 1K to 1M context length on Proof-Pile, which is genuinely impressive. However, Proof-Pile is a mathematical text dataset with highly structured, repetitive patterns — the paper does not evaluate perplexity extrapolation on more diverse text (e.g., web text, books, dialogue) where the recurrent state might face more heterogeneous information. The 1M perplexity measurement uses a sliding window of 4096 for evaluation (Section 3.3), meaning the perplexity at position 1M only reflects prediction quality for tokens within 4096 positions of the current token. This is a standard evaluation protocol, but it means the metric captures whether the model can *use* long context for better local prediction, not whether it can *recall* specific information from 1M tokens ago for a targeted query. The Passkey experiment (Figure 3) tests recall up to 256K, confirming some long-range retrieval, but does not reach 1M and uses a synthetic task.

**Claim: Instruction tuning on 4K sequences enables recall at 256K.** The Passkey result (Figure 3, Figure 8) is compelling and well-controlled: same training data, same number of steps, same architecture except for the Mamba layers. The SWA-based Mistral model serves as a direct ablation — it achieves the same training loss but cannot extrapolate, demonstrating that the Mamba layers are the mechanism enabling the extrapolation. The Phonebook result (Figure 4) provides a more challenging test with structured memorization of multiple key-value pairs. However, both tasks are synthetic and involve memorizing numbers (passkeys, phone numbers). Whether this fine-tuning would enable recall of natural language facts (e.g., "What was the patient's blood pressure on page 3?") is not tested. The transfer experiment (PK-FT failing on Phonebook) confirms the task-specificity concern.

**Claim: The optimal number of attention heads is smaller for SAMBA than for SWA-only models.** Table 6 provides evidence at the 430M scale that SAMBA achieves best perplexity with 6 or 12 query heads and 1 KV head, while SWA-only benefits from 12/1. The effect is modest (9.51 vs. 9.60 at 16K), and the paper does not show whether this finding holds at larger scales. The 3.8B model uses 11 query heads / 1 KV head, but there is no ablation at that scale testing alternative configurations. The claim that "Samba can support a smaller number of attention heads" is reasonably supported at small scale but not demonstrated to be a general scaling property.

**Claim: The hybridization induces functional specialization (entropy analysis).** Figure 5 provides suggestive evidence: SAMBA's attention layers show more variance in entropy across depth than Mistral's, and SAMBA's Mamba layers show higher selection entropy than Mamba-MLP's. The sample size (100 random GSM8K examples) is small, and the analysis is correlational — it does not establish causation between specialization patterns and downstream performance. The paper does not show whether architectures that perform *worse* (e.g., Mamba-SWA-MLP) show different entropy patterns, which would strengthen the causal interpretation.

**Missing experiments that would strengthen the paper:**

1. **Multi-seed training runs** to quantify variance in the reported performance gaps, particularly for the 3.8B comparison where the practical significance hinges on gaps of 1–5 percentage points on benchmarks with their own measurement noise.
2. **Perplexity extrapolation on diverse text domains** (web text, code, dialogue) beyond Proof-Pile to test whether the 1M extrapolation is a general property or domain-specific.
3. **Scaling the head-count ablation to 1.7B or 3.8B** to test whether the "fewer attention heads suffice" finding is a general property or a small-scale artifact.
4. **Long-context retrieval beyond synthetic tasks** — e.g., long-document QA (NarrativeQA, Qasper) or multi-turn dialogue — to test whether instruction-tuned recall transfers to naturalistic settings.
5. **Comparison against full-attention models with dedicated length-extrapolation techniques** (e.g., PI, LongRoPE) on retrieval tasks at extreme lengths, to contextualize SAMBA's Passkey result against the best available Transformer-based extrapolation.
6. **Ablation on the number of Mamba layers vs. SWA layers** — the paper experiments with different interleaving patterns (Samba vs. Mamba-SWA-MLP vs. Mamba-MLP) but does not systematically vary the ratio of Mamba to SWA layers within the alternating pattern (e.g., 2 Mamba blocks per 1 SWA block, or vice versa).
7. **Analysis of what the Mamba state actually stores** after Passkey fine-tuning — probing or intervention experiments to understand whether the state encodes the passkey explicitly or whether the recall works through a different mechanism.
8. **Evaluation of the difficulty estimation cost** — while not directly applicable to SAMBA (which doesn't use adaptive test-time strategies), a similar concern about the practical cost of achieving the reported benefits arises: the instruction tuning for Passkey/Phonebook requires generating synthetic training data specific to the retrieval task, which may not be available in deployment scenarios.

**Conditional nature of the claims:** The paper's central empirical claims hold most strongly for the specific configuration tested: Phi-3-quality training data, 4K training length, 2048 sliding window, mathematical and synthetic retrieval evaluation. The superiority over Transformers on *short-context* tasks is demonstrated with the Phi-3 data pipeline specifically — whether SAMBA would outperform Transformers trained on other data distributions (e.g., web-scale data like C4 or The Pile) is untested. The length extrapolation results depend on the combination of Mamba + SWA + RoPE within the window; removing RoPE breaks extrapolation entirely despite the architecture being ostensibly translation-invariant, suggesting that subtle interactions between components are load-bearing in ways the paper does not fully analyze. The instruction-tuned recall capability is demonstrated for synthetic number-memorization tasks; its transfer to naturalistic long-context understanding is tested only through the two summarization benchmarks (GovReport, SQuALITY) in Table 1, where SAMBA's advantage over Phi-3-mini on GovReport (18.9 vs. 14.4) is substantial but its performance on SQuALITY is slightly worse (21.2 vs. 21.6), leaving the practical benefits for realistic long-document tasks somewhat ambiguous.

## 6. Limitations and Trade-offs

### Zero-Shot Retrieval Performance Is Not Better Than Pure SWA Models

**The assumption or constraint.** SAMBA's architecture combines Mamba's recurrent compression with SWA's local attention, which should theoretically enable retrieval of information across arbitrary distances via the recurrent state. However, the paper does not demonstrate that the pretrained SAMBA model can actually perform such retrieval in a zero-shot setting. Section 3.4 acknowledges this directly:

> "we can also notice that the pre-trained base Samba model has a retrieval accuracy (at step 0) similar to that of Mistral, highlighting the need for future work to improve Samba's zero-shot retrieval capabilities."

Figure 8 confirms this: at step 0 of Passkey fine-tuning, SAMBA's 256K retrieval accuracy is indistinguishable from Mistral's — both near zero.

**The consequence.** A practitioner deploying a pretrained SAMBA model for long-context retrieval tasks (document QA, conversational memory, codebase reasoning) cannot expect it to recall specific information from beyond the 2048-token sliding window without task-specific instruction tuning. The architectural mechanism for long-range recall (the Mamba recurrent state) exists but is not spontaneously used for precise retrieval during pretraining. This means SAMBA's length extrapolation benefit, as deployed out-of-the-box, is limited to improved perplexity (better local prediction from accumulated context) rather than improved fact retrieval. The impressive Passkey and Phonebook results require explicit fine-tuning on synthetic retrieval tasks, which may not be feasible for every deployment scenario — particularly when the types of facts to be retrieved are heterogeneous or cannot be easily synthesized into training data.

**What evidence exists in the paper.** Figure 8 (step 0), Section 3.4 acknowledgment quoted above, and the transfer experiment in Figure 4 where Samba 1.7B PK-FT (fine-tuned for Passkey) fails completely on Phonebook, demonstrating that the retrieval capability does not generalize across tasks.

**Mitigation status.** The paper is transparent about this limitation and explicitly flags it as future work in Section 3.4: "it is interesting to investigate if a model instruction-tuned on one task can transfer its ability to the other task in zero-shot." The transfer experiment (PK-FT → Phonebook) provides a negative result that confirms the limitation is real. The paper does not propose a specific mitigation beyond suggesting that multi-task retrieval fine-tuning might produce more general recall capabilities, or that pretraining objectives could be modified to encourage exploiting the Mamba state for retrieval.

### Difficulty Estimation Cost for Obtaining the Reported Gains Is Unaccounted For

**The assumption or constraint.** The paper's headline results on long-context retrieval — perfect Passkey Retrieval at 256K and competitive Phonebook performance at 8K — depend on instruction tuning with task-specific synthetic data generated on-the-fly. The Passkey fine-tuning uses 500 steps of batch size 2048, generating random passkeys and insertion positions for each batch. The Phonebook fine-tuning uses 100 steps. While the paper discusses this training cost (Figures 7, 8), it does not account for the cost of generating this training data or the cost of the fine-tuning itself in any throughput or efficiency comparison. The 3.73× prompt processing throughput and 3.64× decoding speedup (Figure 2b, Figure 6) are measured on the pretrained model — they exclude the cost of instruction tuning.

**The consequence.** A practitioner who needs SAMBA to perform long-context retrieval cannot simply download the pretrained model and expect it to work. They must either (a) accept that the model will not retrieve facts beyond the 2048-token window, or (b) invest additional compute in task-specific fine-tuning. The cost of (b) includes generating synthetic retrieval training data (which requires defining what "facts" need to be retrieved and creating appropriate training examples), running the fine-tuning itself (500 steps at batch size 2048 for Passkey, 100 steps for Phonebook), and potentially doing this separately for each retrieval task or domain since the transfer experiment shows no generalization. This cost is not included in any of the paper's efficiency comparisons, making the throughput advantages somewhat overstated for deployment scenarios that require long-range retrieval — the pretraining efficiency gain is partially offset by the need for post-hoc fine-tuning to activate the desired capability.

**What evidence exists in the paper.** Figures 7 and 8 show the training dynamics of Passkey fine-tuning (500 steps). Figure 4 shows the Phonebook fine-tuning (100 steps) and the transfer failure. The paper does not report the GPU-hours required for these fine-tuning runs, nor does it amortize this cost over the inference efficiency numbers. Section 3.4 describes the fine-tuning procedure but does not frame it as an additional deployment cost.

**Mitigation status.** The paper does not address this as a limitation. It presents the instruction tuning as a feature (the model can be quickly adapted) rather than as a cost. However, the transfer failure (PK-FT → Phonebook) implies that per-task fine-tuning may be necessary, which multiplicatively increases the hidden cost. The paper suggests in Section 4 that "future work to further explore the transferability of long-context capabilities in linear complexity models" is needed, acknowledging the generalization problem but not the cost problem.

### All Length Extrapolation Results Are on Synthetic or Domain-Specific Data

**The assumption or constraint.** The paper's three key demonstrations of length extrapolation use datasets that may not represent the diversity of real-world long-context scenarios:

1. **Perplexity extrapolation to 1M tokens** (Figure 2a) uses Proof-Pile, a dataset of mathematical proofs and formal text. Mathematical text has highly structured, repetitive patterns (notation, proof structures, theorem-reference patterns) that may be particularly amenable to recurrent compression — a model can predict "QED" or the next step in an equation from high-level structural features without retaining verbatim details from 100K tokens earlier.

2. **Passkey Retrieval to 256K** (Figure 3) uses synthetic documents with a single 5-digit number to retrieve. This tests whether the architecture *can* carry a single piece of information across a gap — a binary capability test — but does not measure how much information the state can simultaneously retain or how recall degrades with competing information.

3. **Phonebook Retrieval to 8K** (Figure 4) tests structured memorization of name-number pairs, but the maximum context length (8K) is substantially shorter than the Passkey extrapolation (256K), and the task is still synthetic.

**The consequence.** A practitioner cannot infer from these results how SAMBA would perform on realistic long-context tasks such as multi-document summarization (where dozens of documents must be synthesized), long-form dialogue (tracking entities and commitments across hundreds of conversational turns), or codebase reasoning (maintaining awareness of APIs defined thousands of lines earlier). The Proof-Pile perplexity improvement may not translate to improved generation quality or task performance on more diverse text. The Phonebook result at 8K shows SAMBA's accuracy declining from ~1.0 at 20 pairs to ~0.3 at 480 pairs — even within 8K, the architecture is not achieving perfect recall under memory load. The paper does not characterize how recall degrades as a function of the number of items to be stored, which is the critical practical parameter.

**What evidence exists in the paper.** Figure 2a (Proof-Pile only, no alternative domains), Figure 3 (synthetic Passkey), Figure 4 (synthetic Phonebook, evaluated only to 8K). The two naturalistic long-context evaluations — GovReport and SQuALITY in Table 1 — use documents with average lengths of 11.5K and 8.0K tokens respectively (Appendix F), which are within or near the 4K training length. These do not test extrapolation to the extreme lengths claimed elsewhere. SAMBA outperforms Phi-3-mini on GovReport (18.9 vs. 14.4 ROUGE-L) but slightly underperforms on SQuALITY (21.2 vs. 21.6), providing ambiguous evidence even at moderate lengths.

**Mitigation status.** The paper acknowledges in Appendix H that the base model retrieval is similar to SWA-only models and that "this opens up future direction on further improving Samba's retrieval ability without compromising its efficiency and extrapolation ability." However, it does not acknowledge the domain-specificity of the extrapolation benchmarks as a limitation. The inclusion of GovReport and SQuALITY is a partial step toward naturalistic evaluation, but their document lengths are too short to serve as extrapolation tests.

### The Single Training Run per Architecture Precludes Statistical Reliability Assessment

**The assumption or constraint.** Every architecture comparison in the paper — Table 2 (six architectures at 1.7B), Table 3 (eleven architectures at two scales), Table 1 (SAMBA vs. Phi-3-mini at 3.8B) — uses a single training run per configuration. The paper provides no information about training seed, data order randomization, or any form of repeated measurement. The only uncertainty quantification is a note in Section 3 and Table 3's caption that "perplexity results have a fluctuation around ±0.3%," which is not a formal confidence interval and only applies to perplexity measurements, not downstream task scores.

**The consequence.** The reported performance gaps must be interpreted with caution, particularly for smaller differences. In Table 1, SAMBA's SQuALITY score of 21.2 vs. Phi-3-mini's 21.6 is a 0.4 ROUGE-L difference — almost certainly within run-to-run variance for large model training. In Table 4, SAMBA (58.54) leads SAMBA-NoPE (58.52) by 0.02 average accuracy — a difference that is meaningless without variance estimates. Even the larger gaps in Table 2 (SAMBA 54.33 vs. Llama-3 51.17, a 3.16 point difference) may be partially attributable to training variance. For the 3.8B comparison in Table 7, where SAMBA (64.2) beats TFM++ (60.1) by 4.1 points on average, the practical significance depends on whether this gap exceeds typical run-to-run variation at this scale — which is unknown. For 3.2T-token training runs, the cost of a second training run would likely be prohibitive, but this makes the single-run limitation *more* consequential, not less, since we cannot distinguish architectural advantage from training noise.

**What evidence exists in the paper.** None. The paper does not discuss training variance, report confidence intervals, or run multiple seeds for any experiment. The ±0.3% perplexity fluctuation note is the only nod to measurement reliability.

**Mitigation status.** Not addressed. The paper presents all results as point estimates. This is a common limitation in large-scale architecture comparison papers due to computational cost, but it should be explicitly acknowledged. The consistent pattern of SAMBA outperforming baselines across scales (438M, 1.3B, 1.7B, 3.8B), datasets (SlimPajama, Phi-2, Phi-3), and metric types (perplexity, accuracy, pass@1) provides some robustness through triangulation, but does not substitute for formal statistical assessment at the scale where the claims matter most (3.8B).

### The Revision/Search Capability Is Untested — Only Single-Pass Generation Is Evaluated

**The assumption or constraint.** All of SAMBA's downstream evaluations (short-context benchmarks, long-context summarization) use a single generation pass — the model produces one output given the input, without iterative refinement, self-correction, or search over multiple candidate solutions. The Passkey and Phonebook evaluations test whether the model can output a specific stored value. This is a valid evaluation for assessing base language modeling and retrieval capabilities, but it does not cover a capability regime that is increasingly important for LLM deployment: the ability to use additional test-time computation to improve outputs through self-critique, revision, or search-based selection.

The paper's architecture is a *sequence model*, not a *test-time compute framework*, so this may seem like an unfair limitation to raise. However, the paper makes architectural claims about specialized functional roles — Mamba for recurrent sequence structure, attention for precise retrieval — that have implications for how the architecture would interact with test-time compute strategies. The entropy analysis (Figure 5) shows that attention layers specialize along the depth axis, with middle layers performing low-entropy precise retrieval and outer layers performing high-entropy integration. This specialization pattern could interact with search-based or revision-based test-time compute in unknown ways: for example, beam search against a PRM might over-optimize the low-entropy middle attention layers (analogous to the over-optimization discussed in the reference paper's Section 5.3), or sequential revisions might benefit from Mamba's recurrent state differently than parallel sampling.

**The consequence.** A practitioner considering SAMBA for a deployment that uses test-time compute strategies (best-of-N, beam search, self-consistency voting, sequential revisions, verifier-guided selection) has no evidence about whether the architectural advantages demonstrated for single-pass generation persist, amplify, or reverse when additional inference compute is allocated. The specialization pattern in Figure 5, if interpreted through the lens of verifier over-optimization dynamics (reference paper Section 5.3), raises the possibility that aggressive search could exploit the low-entropy attention layers in SAMBA's middle blocks in ways that pure Transformer or pure SSM architectures would not experience. This is speculative — no evidence exists either way — but the interaction between hybrid architecture dynamics and test-time compute strategies is a genuine unknown for downstream deployment.

**What evidence exists in the paper.** None. All experiments use single-pass generation. This is not framed as a limitation in the paper.

**Mitigation status.** Not addressed. This limitation is included because the reference paper demonstrates that test-time compute strategy interacts strongly with model architecture and problem difficulty — making it a relevant consideration for anyone deploying SAMBA in settings where inference compute is not limited to a single forward pass. The specialization documented in Figure 5 makes this interaction particularly plausible, but the question is entirely unexplored.

### The Optimal Window Size and Interleaving Ratio Are Not Systematically Explored

**The assumption or constraint.** SAMBA uses a fixed sliding window size of w = 2048 and an alternating 1:1 ratio of Mamba blocks to SWA blocks (24 Mamba layers, 24 SWA layers at 1.7B; 32 each at 3.8B). The window size choice is justified by hardware efficiency — "FlashAttention 2 has the same training speed as Mamba's selective parallel scan at the sequence length of 2048" (Section 2.1.2) — but the paper does not systematically vary the window size to assess the performance-efficiency tradeoff. Similarly, the 1:1 interleaving ratio is one of several patterns tested (Figure 1: Samba, Mamba-SWA-MLP, Mamba-MLP) but is not part of a systematic sweep over ratios (e.g., 2 Mamba blocks per 1 SWA block, or 1 Mamba block per 2 SWA blocks, or varying the ratio with depth).

**The consequence.** A practitioner deploying SAMBA with different hardware constraints (where the Mamba vs. FlashAttention throughput crossover point is at a different sequence length) or different task requirements (where more or less retrieval precision is needed) has no guidance on how to adjust the window size or interleaving ratio. The 2048 window size, justified by training-time hardware efficiency on A100/H100 GPUs, may not be optimal for deployment on different hardware (edge devices, TPUs, older GPU generations) where the relative throughput of Mamba's parallel scan vs. FlashAttention differs. More fundamentally, the functional specialization argument (Figure 5) suggests that the optimal ratio of Mamba to SWA layers might depend on the task distribution: reasoning-heavy tasks (GSM8K, where Mamba-SWA-MLP excels) might benefit from more Mamba-SWA interaction per block, while retrieval-heavy tasks might benefit from more SWA layers overall. The paper's empirical observation that Mamba-SWA-MLP outperforms SAMBA on GSM8K (44.05 vs. 38.97 in Table 2) but underperforms on average suggests that the optimal architecture is task-dependent, but the paper provides no systematic characterization of this dependence.

**What evidence exists in the paper.** The comparison of Samba, Mamba-SWA-MLP, and Mamba-MLP in Table 2 provides three points in the interleaving design space. Table 9 shows varying training sequence length for SWA-only models but does not vary the SWA window size for SAMBA. The hardware efficiency justification for w = 2048 appears in Section 2.1.2 but is based on a single measurement from Gu & Dao (2023), not on SAMBA-specific profiling across window sizes.

**Mitigation status.** The paper does not treat this as a limitation. The design choices are presented as fixed architectural parameters rather than hyperparameters to be optimized. The paper's contribution is demonstrating that a *particular* configuration works well, not characterizing the full design space. However, for a practitioner deciding whether to adopt SAMBA, the lack of guidance on how to adapt the architecture to different hardware or task regimes is a significant practical gap.
