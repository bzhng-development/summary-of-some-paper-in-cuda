# ATOM: Low-Bit Quantization for Efficient and Accurate LLM Serving

**ArXiv:** [2310.19102](https://arxiv.org/abs/2310.19102)

## 🎯 Pitch

While modern GPUs pack INT4 tensor cores with 4× the throughput of FP16, prior quantization methods either left this performance on the table or suffered severe accuracy crashes—Atom unlocks a 7.73× end-to-end throughput gain over FP16 by keeping just 128 outlier channels at higher precision and fusing dequantization directly into the GEMM pipeline, all at negligible accuracy loss.

---

## 1. Executive Summary

Atom introduces a low-bit weight-activation quantization method for LLM serving that combines **mixed-precision quantization** (keeping 128 outlier channels in INT8 while quantizing remaining values to INT4), **fine-grained group quantization** (dividing matrices into subgroups of 128 elements with fused dequantization in the GEMM pipeline), and **dynamic activation quantization** (computing quantization parameters per-input at runtime) with KV-cache quantization to achieve high throughput with negligible accuracy loss. Evaluated on Llama models (7B–65B) across WikiText2, PTB, C4, and six zero-shot benchmarks, Atom delivers up to 7.73× end-to-end throughput improvement over FP16 and 2.53× over INT8 weight-activation quantization while maintaining the same latency target, with only a 1.4% average zero-shot accuracy drop and 0.3 WikiText2 perplexity increase on Llama-65B. The paper establishes that low-bit weight-activation quantization can substantially outperform both FP16 and weight-only quantization in throughput-oriented serving scenarios, but only when outlier channels are preserved at higher precision and group quantization overheads are mitigated through kernel fusion—without these techniques, prior 4-bit methods suffer 9.6–23.8% accuracy degradation on the same models.

## 2. Context and Motivation

### The Core Problem: LLM Serving Is Expensive, and Current Quantization Leaves Performance on the Table

The paper addresses a fundamental tension in deploying large language models for production serving: **the gap between what modern GPU hardware can do and what current quantization schemes actually deliver.** LLM inference at scale—where providers serve millions of users with models ranging from 7B to 65B+ parameters—is dominated by two resource bottlenecks: compute throughput on dense layers (the MLP and projection operations within each transformer block) and memory bandwidth on self-attention layers (where the KV-cache for each request must be loaded from memory). The paper's roofline analysis (Figure 4) makes this explicit: at the large batch sizes used in production serving, the dense layers become compute-bound, while self-attention remains stubbornly memory-bound due to per-request KV-cache access patterns that cannot be batched across users.

The critical insight driving the paper is that **modern GPUs have INT4 tensor core throughput of 1248 TOPS—4× higher than FP16's 312 TFLOPS and 2× higher than INT8's 624 TOPS** (Section 1). This hardware capability exists on widely deployed architectures like the NVIDIA A100, yet no production quantization scheme at the time of writing could actually exploit it for LLM serving without unacceptable accuracy degradation. The paper frames this as a *hardware-software gap*: the silicon is capable of dramatically higher throughput, but the algorithmic and systems techniques to use it accurately did not exist.

This gap is not merely academic. The paper cites operational costs for LLM service providers approaching $1 million daily (Section 1), driven by both the computational expense of serving and the memory requirements of storing model weights and KV-caches for large batches of concurrent requests. Every request in an LLM serving system goes through two phases: a prefill phase that processes the entire input prompt in parallel and an autoregressive decode phase that generates tokens one at a time. The decode phase is particularly problematic because generating each individual token requires loading the entire model weight matrix while performing only a small number of floating-point operations—a classic memory-bound pattern where GPU compute units sit idle waiting for data. Batching requests together amortizes this cost by sharing weight loads across multiple queries, transforming what would be a memory-bound matrix-vector multiplication (GEMV) into a compute-bound matrix-matrix multiplication (GEMM). But batching alone cannot overcome the fundamental throughput limits of FP16 arithmetic; it simply shifts the bottleneck from memory bandwidth to compute capacity.

### Why Low-Bit Weight-Activation Quantization Matters (and Why It's Hard)

The paper's motivation can be distilled to a simple physical argument: **the fastest operation in a GPU is the one that moves the fewest bits.** If you can represent both model weights and intermediate activations in 4-bit integers instead of 16-bit floating point, you reduce memory movement by 4× and—crucially—you can use the GPU's INT4 tensor cores, which process 4× more operations per cycle than FP16 units. The throughput gains are multiplicative: less data to move, faster operations on the data that does move.

However, the paper is careful to distinguish between **weight-only quantization** (e.g., GPTQ, AWQ) and **weight-activation quantization** (e.g., SmoothQuant, OmniQuant). This distinction is central to understanding the paper's positioning and motivation.

Weight-only quantization keeps weights in low-bit format (e.g., INT4 or INT3) but performs all computation in FP16, dequantizing weights on-the-fly before multiplying them with FP16 activations. As the roofline analysis in Figure 4(b) demonstrates, this approach reduces memory consumption—which helps for the memory-bound decode phase at small batch sizes—but provides *no compute throughput benefit* for the dense layers because the actual matrix multiplications still happen in FP16. Once batching pushes the dense layers into the compute-bound regime (which is exactly what production serving systems aim for), weight-only quantization leaves the dominant compute bottleneck untouched. Moreover, weight-only quantization does nothing for the self-attention bottleneck because the KV-cache (which stores per-token key and value vectors for all previous tokens in each request's context) remains in FP16, so the large memory movement required for attention computation is unchanged.

Weight-activation quantization, by contrast, quantizes *both* weights and intermediate activations to low-bit representations, enabling the use of low-bit tensor cores for the actual matrix multiplications. This addresses both bottlenecks: dense layers get 4× higher compute throughput from INT4 tensor cores, and self-attention benefits from reduced KV-cache memory movement (if the KV-cache is also quantized). The paper's contribution is not merely pointing out this advantage—it's providing the first practical system that achieves INT4 weight-activation quantization on LLMs without catastrophic accuracy loss.

### Where Prior Approaches Fall Short

The paper identifies three categories of prior work and explains why each fails to solve the low-bit weight-activation quantization problem for LLM serving:

**INT8 weight-activation quantization (e.g., LLM.INT8(), SmoothQuant)** solved the accuracy problem for 8-bit quantization but stopped short of what modern hardware can do. LLM.INT8() (Dettmers et al., 2022) introduced the key insight that LLM activations contain "emergent features" in a small number of outlier channels with magnitudes 10–100× larger than typical values, and that isolating these outliers in higher precision (FP16) enables accurate 8-bit quantization of the remaining values. SmoothQuant (Xiao et al., 2023) used mathematical transformations to shift the quantization difficulty from activations to weights, achieving INT8 weight-activation quantization with near-zero accuracy loss. However, both approaches left performance on the table: INT8 tensor cores are only half as fast as INT4, and the 8-bit representation still requires 2× more memory than 4-bit for KV-cache and weight storage. More fundamentally, neither approach demonstrated that their techniques could extend to 4-bit precision, where the limited dynamic range (only 16 distinct values) makes the outlier problem dramatically more severe.

**Recent 4-bit weight-activation methods (OmniQuant, QLLM)** attempted to push into INT4 territory but suffered significant accuracy degradation. As Figure 2 shows, OmniQuant (Shao et al., 2023) and QLLM (Liu et al., 2023a) both produce noticeable perplexity increases on WikiText2 across all Llama model sizes when compared to the FP16 baseline. The accuracy gap is not subtle: Table 1 shows OmniQuant losing 11.4 percentage points of average zero-shot accuracy on Llama-7B (64.04→52.65) and QLLM losing 12.2 points (64.04→51.84) under W4A4. For production serving, these accuracy losses are unacceptable—a 12-point drop on common sense reasoning tasks represents a qualitatively different capability level. The paper does not dismiss these prior works; rather, it uses them to establish that **the accuracy-efficiency frontier for LLM quantization was stuck at INT8**, and pushing to INT4 required fundamentally better techniques for handling the interplay between outlier channels and the extremely limited representation capacity of 4-bit integers.

**Efficiency-focused quantization work (Olive, SysMol)** explored hardware-friendly implementations of mixed-precision quantization but did not directly address LLM serving or achieve the combination of accuracy and throughput that the paper targets. The paper positions itself as filling the gap between these three threads: taking the mixed-precision insight from LLM.INT8(), extending it to 4-bit with the accuracy-preserving techniques described in Section 4, and implementing it efficiently with custom CUDA kernels that are practical for real serving deployments.

### The Underlying Challenge: Quantization Error Physics

To understand why 4-bit quantization is qualitatively harder than 8-bit, and why prior approaches fail, it's worth examining the math that the paper only hints at. Quantization error is fundamentally about dynamic range: how well a small set of discrete values can approximate a continuous distribution of real numbers.

For a symmetric uniform quantizer (which the paper adopts for efficiency, as discussed in Section 2), the quantization step size is:

$$s = \frac{2 \cdot \max(|X|)}{2^{n} - 1} \cdot c$$

where $n$ is the bit width and $c$ is a clipping factor. For INT8 ($n=8$), the denominator is 255, giving 256 distinct values. For INT4 ($n=4$), the denominator is 15, giving only 16 distinct values. The crucial implication: **when you reduce precision from 8-bit to 4-bit, you don't just halve the number of bits—you reduce the number of representable values by 16×** (from 256 to 16).

Now consider what happens when an activation matrix contains outlier channels. If a single channel has values that are 100× larger than the typical range, then the quantization scale $s$ must accommodate that maximum value, meaning that the 16 available integer levels are spread across a range that is 100× wider than necessary for 95% of the channels. The normal channels end up quantized to the same few integer values, losing essentially all their information. This is why Table 3 shows the simple round-to-nearest (RTN) W4A4 baseline achieving a catastrophic WikiText2 perplexity of 2315.52 compared to 5.68 for FP16—the model has been destroyed by quantization errors on the normal channels.

The paper's core insight is that **the outlier problem and the low-bit representation problem are two sides of the same coin**. At 8 bits, there's enough dynamic range that you can partly absorb outlier channels within the quantizer (the 256 levels provide some headroom), which is why SmoothQuant's mathematical transformations sufficed. At 4 bits, there's no margin—you *must* separate outliers from normal values, because 16 levels cannot simultaneously cover a 100× dynamic range and retain meaningful precision on the bulk of the distribution. This motivates the paper's mixed-precision approach, which is not just an optimization but a necessity for INT4 weight-activation quantization.

### How This Paper Positions Itself

Atom is presented not as an incremental improvement over prior quantization schemes but as a **co-designed algorithm-and-system that achieves practical INT4 weight-activation quantization for LLM serving for the first time**. The paper's positioning has several dimensions worth unpacking:

**Accuracy-positioning:** Against OmniQuant and QLLM, Atom claims to cross the accuracy threshold that makes INT4 deployment viable. The paper quantifies this as "negligible accuracy loss"—1.4% average zero-shot accuracy drop and 0.3 WikiText2 perplexity increase on Llama-65B (Section 5.2). These numbers matter because they're small enough that a production LLM service could adopt Atom without retraining or fine-tuning. The paper implicitly draws a line: prior 4-bit methods are in the regime of "unacceptable accuracy loss for deployment," while Atom crosses into the regime of "acceptable trade-off for the throughput gains."

**Performance-positioning:** Against FP16 and INT8 baselines, Atom claims substantial throughput improvements—7.73× over FP16 and 2.53× over INT8—while maintaining comparable latency. The latency comparison is important because LLM serving has a human-perceptible latency constraint (the paper cites Trauzettel-Klosinski et al., 2012, showing ~100ms as the effective human reading speed). Throughput gains that violate latency targets are practically useless; Atom achieves its throughput improvements within the latency envelope of existing approaches.

**Systems-positioning:** The paper integrates Atom into an actual serving framework (Punica, built on continuous batching from Orca and PageAttention from vLLM) and reports end-to-end numbers, not just kernel-level benchmarks. This distinguishes Atom from quantization papers that only report perplexity or accuracy without demonstrating that the scheme actually improves real serving throughput. The kernel fusion techniques (Section 4.2, Figure 8) and the attention integration with FlashInfer (Section 4.5, Figure 6) are not afterthoughts—they are central to the paper's claim that Atom is a practical system, not just an algorithmic idea.

**Conceptual-positioning:** The paper frames the problem as specific to **LLM serving scenarios**, not generic LLM inference. This matters because the optimal quantization strategy depends on the operational regime. For single-query, latency-bound inference (batch size 1), weight-only quantization might be sufficient since the dense layers are memory-bound and the compute throughput of INT4 tensor cores goes unused. For throughput-oriented serving with large batches, the dense layers shift to compute-bound, making weight-activation quantization's tensor core benefits decisive. The paper's roofline analysis in Figure 4 makes this framing precise, showing exactly why weight-only quantization's benefits diminish as batch sizes increase while weight-activation quantization's benefits grow.

### The Serving-Specific Challenges That Motivate Atom's Design

Beyond the fundamental quantization accuracy challenge, the paper is motivated by several practical hurdles that arise specifically when deploying quantized models in production serving systems. These are not the challenges that a pure quantization research paper would address, but they are critical for Atom's claimed practical impact:

**Mixed-precision causes irregular memory access.** Keeping some channels in high precision and others in low precision breaks the regular striding patterns that GPU tensor cores expect. The paper cites Guo et al. (2023) showing that naive mixed-precision implementations can actually be *slower* than uniform quantization due to memory access overhead. Atom's channel reordering technique (Figure 7) is not an accuracy optimization—it's an efficiency optimization that makes mixed-precision implementable without irregular gathers and scatters.

**Group quantization breaks the standard GEMM pipeline.** In a standard matrix multiplication, all elements share the same scale factor, which means the accumulated result can be rescaled once at the end. With group quantization, each subgroup has its own scale, requiring per-group dequantization *within* the accumulation loop. This cannot be done efficiently as a post-processing step—it must be fused into the GEMM kernel itself, interleaving tensor core operations (Step 1 in Figure 8) with CUDA core dequantization (Step 2) and accumulation (Step 3). The paper implements this as a custom fused GEMM operator, which is a substantial engineering contribution that prior quantization work did not address.

**Dynamic quantization adds per-inference overhead.** Computing quantization parameters (scale and zero-point) for each activation matrix on-the-fly requires scanning the entire activation tensor to find min/max values, which is an $O(n)$ operation with low arithmetic intensity. If done naively as a separate kernel launch, this overhead could eliminate the throughput benefits of quantization. Atom fuses these quantization operations into prior operators (e.g., the layer normalization that precedes each FFN block), hiding their cost in the shadow of compute-intensive operations.

**KV-cache quantization requires attention kernel modification.** The KV-cache for each request grows linearly with sequence length and quickly dominates GPU memory for large batch sizes. Quantizing the KV-cache to INT4 reduces memory movement but requires dequantizing it on-the-fly during the attention computation. The paper argues (Section 4.4) that the KV-cache is easier to quantize than activations because: (1) the softmax normalization in attention dampens the effect of quantization errors in the K cache, and (2) the V cache exhibits a less extreme outlier distribution (Figure 9). But taking advantage of this requires modifying the attention kernel—which Atom does by fusing dequantization into FlashInfer.

### The Broader Significance: Why This Paper Matters Beyond the Numbers

Stepping back from the technical details, the paper makes a broader argument about how the field should think about LLM efficiency. The implicit thesis is that **the serving regime is qualitatively different from the training regime**, and techniques optimized for training (where weight-only quantization and INT8 are common) do not automatically transfer.

At training time, the dominant cost is backward-pass computation and optimizer state memory; activations are ephemeral and can be recomputed, and the batch sizes are typically small enough that memory bandwidth rather than compute throughput is the bottleneck. At serving time, the picture inverts: the forward pass dominates (there's no backward pass), activations must be kept for the KV-cache, and batching pushes the dense layers firmly into the compute-bound regime. These differences mean that **the optimal quantization strategy for serving is not the same as the optimal strategy for training**, and the paper's roofline analysis (Figure 4) provides the conceptual framework for understanding exactly why.

The paper's FLOPs-aware approach also connects to a larger trend in ML systems: the idea that algorithm design should be **hardware-aware** from the start rather than treating the hardware as an afterthought. Atom doesn't just propose a quantization algorithm and then see if it works on a GPU; it starts from the GPU's INT4 tensor core capability and works backward to design an algorithm that can exploit it. The channel reordering, kernel fusion, and group quantization decisions all flow from this hardware-first perspective. This is not a new philosophy—it echoes work like FlashAttention (Dao et al., 2022) that similarly starts from hardware constraints—but applying it to the intersection of quantization and LLM serving is novel and practically impactful.

## 3. Technical Approach

### 3.1 Reader orientation (approachable technical breakdown)

Atom is a **quantization system** that converts both the weights and the intermediate activations of a large language model from 16-bit floating-point numbers into 4-bit integers, then runs the quantized model on GPU hardware that can process 4-bit operations at dramatically higher throughput than 16-bit operations. The problem it solves is that modern GPUs have INT4 tensor cores capable of 1248 trillion operations per second (TOPS)—4× higher than FP16—but prior quantization methods either couldn't reach 4-bit precision without catastrophic accuracy loss (OmniQuant, QLLM lose 10–24 percentage points of zero-shot accuracy) or couldn't exploit the tensor cores because they only quantized weights while keeping computations in FP16 (GPTQ, AWQ). Atom's solution has the shape of a **co-designed algorithm-and-kernel system**: three algorithmic techniques preserve accuracy by isolating problematic outlier values and using fine-grained quantization, while custom CUDA kernels make these techniques efficient on real GPU hardware by fusing quantization overhead into existing operations.

### 3.2 Big-picture architecture (diagram in words)

The system has five major components:

1. **Offline weight quantization pipeline** — Before deployment, a calibration process identifies which activation channels contain outliers, reorders weight matrices to align with activation reordering, and applies GPTQ-based quantization to produce INT4 weight matrices. This happens once per model, not at inference time.

2. **Dynamic activation quantization** — At inference time, each activation matrix is scanned to compute per-group scale factors on-the-fly, the outlier channels are separated from normal channels, and the result is quantized to mixed INT4/INT8 format. This is fused into the prior operator (typically layer normalization) to hide overhead.

3. **Mixed-precision GEMM kernel** — The core compute operation multiplies INT4 weights by INT4 activations for normal channels and INT8 weights by INT8 activations for outlier channels, fusing per-group dequantization and accumulation directly into the matrix-multiply pipeline so that no intermediate tensors are written to memory.

4. **KV-cache quantization and attention integration** — The key-value cache for each request is stored in INT4 format and dequantized on-the-fly during the self-attention computation, which is implemented as a fused operator within FlashInfer integrated with PageAttention for efficient memory management.

5. **Serving framework integration** — All quantized operators plug into Punica, an LLM serving system that uses continuous batching (refilling the on-the-fly batch when a request completes) and First-Come-First-Served scheduling, with ShareGPT-derived request distributions for realistic workload modeling.

Information flows through the system as follows: an input prompt arrives and is tokenized → the serving framework batches it with other concurrent requests → for each transformer layer, a fused layer-norm/quantization operator produces quantized activations → the mixed-precision GEMM kernel multiplies quantized weights and activations for the QKV projections and MLP layers → for self-attention, a fused FlashInfer kernel loads quantized KV-cache, dequantizes it, and computes attention → the output proceeds to the next layer → at the final layer, tokens are generated autoregressively, with each new token's KV vectors appended to the quantized KV-cache.

### 3.3 Roadmap for the deep dive

- **First**, the outlier identification and mixed-precision strategy, because the existence of outlier channels in activations is the fundamental physical obstacle that makes 4-bit quantization of LLMs difficult, and how Atom isolates and preserves these outliers determines everything else about the system design.
- **Second**, the channel reordering mechanism, because mixed-precision would cause irregular memory access patterns that negate throughput gains—reordering is the efficiency enabler that makes mixed-precision practical on real GPU tensor cores.
- **Third**, fine-grained group quantization and the fused GEMM kernel, because group quantization provides the second major accuracy gain (after mixed-precision) and the kernel fusion is the primary systems contribution that makes group-dequantization overhead manageable.
- **Fourth**, dynamic activation quantization and the clipping/GPTQ refinements, because these complete the accuracy picture and explain how Atom adapts to per-input variations that static calibration would miss.
- **Fifth**, KV-cache quantization, because it addresses the memory-bound self-attention bottleneck that dense-layer quantization alone cannot solve, and requires different design choices than activation quantization.
- **Sixth**, the end-to-end workflow and kernel fusion strategy, because this ties the components together and shows how Atom achieves practical speedup in a real serving framework rather than just kernel-level benchmarks.

### 3.4 Detailed, sentence-based technical breakdown

This is primarily a **systems-and-algorithms co-design paper** whose core idea is that accurate 4-bit weight-activation quantization for LLM serving requires simultaneously solving three problems: (1) the outlier channel problem that destroys 4-bit accuracy, (2) the quantization granularity problem that determines how much local structure the quantizer can capture, and (3) the hardware efficiency problem that determines whether algorithmic gains translate to actual throughput improvements. Atom's contribution is not any single technique in isolation—mixed-precision and group quantization and dynamic scaling all existed in prior work—but rather the integration of these techniques with bespoke GPU kernel design that makes the combination practical for the first time at the 4-bit precision level.

#### Outlier Identification and Mixed-Precision Quantization

The starting point for Atom's design is the empirical observation, documented in prior work (Dettmers et al., 2022; Lin et al., 2023), that LLM activation matrices consistently contain a small number of **outlier channels**—columns of the activation matrix where the magnitude of values is 10–100× larger than the magnitude of values in typical channels. Figure 5(a) in the paper shows a concrete example from a Llama-7B activation matrix: most channels have mean values clustered around zero, but a handful of channels (marked in the figure) have mean values that are several orders of magnitude larger, creating a dynamic range problem.

The dynamic range problem works as follows. In uniform symmetric quantization, the scale factor for a tensor is determined by the maximum absolute value in that tensor (Equation 1 in the paper, simplified for the symmetric case):

$$s = \frac{2 \cdot \max(|X|)}{2^n - 1} \cdot c$$

where $X$ is the input tensor, $n$ is the quantization bit-width (4 for INT4, giving a denominator of 15), and $c$ is a clipping factor (which can be less than 1 to reduce the influence of extreme outliers, trading off representation range for precision on typical values).

**What it computes:** Given a tensor of floating-point values, this equation produces a single scalar $s$ (the scale factor) that maps the floating-point range $[- \max(|X|) \cdot c, +\max(|X|) \cdot c]$ linearly onto the $2^n$ integer levels available at $n$ bits. Every element in the tensor is then quantized by dividing by $s$ and rounding to the nearest integer: $\bar{X} = \text{clamp}(\lfloor X / s \rceil, -2^{n-1}, 2^{n-1} - 1)$. The scale factor $s$ determines the granularity of the quantized representation: a larger $s$ means each integer level represents a wider range of floating-point values, reducing precision.

**Why this form:** Symmetric quantization (zero-point $z = 0$, mapping centered on zero) is used instead of asymmetric quantization because asymmetric quantization introduces three additional cross-terms during matrix multiplication that must be computed in FP16, defeating the purpose of using low-bit tensor cores. The clipping factor $c$ provides a knob to trade off between clipping range (how many outlier values get saturated) and precision (how finely the quantizer resolves typical values). Without clipping ($c = 1$), a single outlier value of 100 in a tensor where most values are in $[-1, 1]$ would force $s \approx 100/7 \approx 14.3$, meaning the integer levels are spaced 14.3 apart—completely washing out differences between normal values, which all get quantized to the same integer (typically 0 or ±1).

Atom's approach to this problem is **mixed-precision quantization**: separate the outlier channels from the normal channels, quantize the outliers in a higher bit-width (INT8, which has 256 levels and can represent a 100× dynamic range with reasonable precision), and quantize only the normal channels in the aggressive INT4 format.

**Outlier identification procedure.** The paper selects which channels to treat as outliers using calibration data—128 randomly sampled sentences from WikiText2 (Section 5.1). For each linear layer in the model, the calibration data is run through the unquantized model, and the activation values are collected. Then, for each channel (last dimension of the activation matrix), the sum of squared values is computed across all calibration tokens. The 128 channels with the highest squared-sum values are designated as outliers. The paper states: "We select 128 channels with the highest square sum values as outlier channels and keep them in INT8" (Section 5.1).

The choice of 128 outlier channels per activation matrix is a hyperparameter that balances several factors. More outlier channels means more values are preserved at INT8 precision, improving accuracy but reducing the throughput benefit (since INT8 tensor cores are half as fast as INT4). Fewer outlier channels means more of the computation runs at the faster INT4 rate but may miss channels that need higher precision. The paper does not provide an ablation over the number of preserved channels, but the result that INT8 quantization of outliers adds only 0.05 perplexity compared to keeping them in FP16 (Table 3) suggests that 128 channels is sufficient to capture the most problematic outliers.

**Why INT8 for outliers rather than FP16.** Table 3 in the paper shows a key ablation: starting from a baseline W4A4 RTN (round-to-nearest, per-channel/per-token quantization), keeping 128 outlier channels in FP16 reduces WikiText2 perplexity from 2315.52 to 11.34—a dramatic 2304-point improvement. Then, quantizing those same outliers to INT8 (rather than keeping them in FP16) increases perplexity by only 0.05, from 11.34 to 11.39. This is a critical result because INT8 operations are supported by the same tensor cores that handle INT4, whereas FP16 operations require different hardware units and would break the fused kernel pipeline. The paper concludes that INT8 provides sufficient precision for the outlier channels while maintaining hardware compatibility: "INT8 is widely supported by hardware implementations (e.g., NVIDIA Tensor Core), Atom applies INT8 quantization for outliers."

#### Channel Reordering for Regular Memory Access

The mixed-precision strategy creates a hardware efficiency problem: if outlier channels are scattered throughout the activation matrix (as they naturally occur, shown in Figure 5a), then a matrix multiplication kernel must constantly switch between INT4 tensor core operations (for normal channels) and INT8 tensor core operations (for outlier channels), with irregular memory access patterns as the kernel jumps between differently-formatted regions of the weight and activation matrices. The paper cites prior work showing that naive mixed-precision implementations can actually be slower than uniform quantization due to these overheads: "The primary concern with mixed-precision quantization is its irregular memory accesses (Dettmers et al., 2022; Guo et al., 2023), which leads to poor hardware efficiency."

Atom's solution is **channel reordering**: physically permute the columns of the activation matrix (and correspondingly, the rows of the weight matrix) so that all outlier channels are grouped together at the end of the matrix. This transforms the scattered outlier problem into a contiguous block problem that can be handled with two dense matrix multiplications: an INT4 GEMM for the normal channels (the large leading block of the matrix) and an INT8 GEMM for the outlier channels (the small trailing block). This is illustrated in Figure 7 of the paper.

**Static vs. dynamic reordering.** The reordering of weight matrices can be done statically offline because the outlier channels are identified during calibration and fixed for deployment. For each linear layer, the weight matrix W has shape [output_dim, input_dim] (in the standard PyTorch convention where the linear operation is $y = xW^T$). The activation matrix A has shape [batch_size × seq_len, input_dim], where each column corresponds to one channel. If channel index $i$ is identified as an outlier, it needs to be moved to the end of the activation matrix. To maintain mathematical equivalence—ensuring that the output $y = A \cdot W^T$ is unchanged—the corresponding row $i$ of the weight matrix $W$ must be moved to the same position. Since this correspondence is fixed after calibration, the weight reordering is performed once and the reordered weights are stored as the deployment-ready model.

The activation reordering, however, must happen at inference time for each new input because the activation values depend on the input data. This introduces an additional operation: given an activation matrix with channels in their natural order, permute the columns to move the 128 outlier channels to the end. A naive implementation would launch a separate kernel to perform this permutation, adding latency to every transformer layer. Atom's solution is to **fuse the reordering into the preceding operator** (Section 4.1): "Atom fuses the activation matrix reordering operators into prior operators, which significantly reduces the reordering overhead to less than 0.5% of runtime."

Concretely, in the Llama architecture (Figure 6), each decoder layer begins with a layer normalization operation (RMSNorm for Llama). The paper fuses the reordering permutation into this normalization kernel: as the normalization kernel writes its output, it writes the values for normal channels to one contiguous region and the values for outlier channels to another contiguous region, effectively performing the permutation as part of the write stage with no additional memory traffic. The reorder indices—which specify the mapping from original channel positions to reordered positions—are determined offline during calibration and embedded as constants in the fused kernel.

**Why this matters beyond efficiency.** The reordering technique is not just an optimization—it also enables the mixed-precision GEMM to use standard, dense matrix multiplication kernels for both the INT4 and INT8 portions. Without reordering, each kernel launch would need to gather outlier channels from scattered positions, requiring either sparse memory access patterns or expensive scatter/gather operations. With reordering, the outlier portion is a contiguous submatrix that can be multiplied using the same dense GEMM algorithm, just with a different bit-width. This is the key insight that makes the mixed-precision approach practical: by moving the complexity from the GEMM kernel (which is the most performance-critical operation in the entire system) to the normalization kernel (which is memory-bandwidth-bound and has spare compute capacity), the system achieves clean separation of concerns—GEMM does pure dense matrix multiplication, while normalization handles the data layout.

#### Fine-Grained Group Quantization and the Fused GEMM Kernel

Even after removing outliers, the remaining normal channels still span a non-trivial dynamic range, and 4-bit precision with only 16 integer levels cannot capture fine-grained variations across an entire channel (which for Llama models contains 4096 elements). To address this, Atom applies **group quantization**: each channel is divided into subgroups of contiguous elements, and quantization is performed independently within each subgroup, with its own scale factor.

**Why per-channel quantization is insufficient.** In per-channel quantization (used as the baseline in Section 5.4.1), all 4096 elements in a channel share a single scale factor, meaning the scale must accommodate the maximum absolute value anywhere in that channel. If the channel contains internal variation—for example, if some positions have magnitudes of 0.5 while others reach 2.0—the single scale factor is driven by the 2.0 maximum, and the 0.5 values get quantized to coarser levels than necessary. Group quantization solves this by computing separate scale factors for each group of (typically) 128 contiguous elements. Within a group, the dynamic range is smaller, so the 16 INT4 levels can represent the values with higher fidelity.

The paper uses a **group size of 128** for both weights and activations (Section 5.1). This choice represents a trade-off: smaller groups provide better accuracy (finer granularity) but increase the number of scale factors and the overhead of per-group dequantization; larger groups reduce overhead but provide coarser quantization. The paper does not ablate over group size, but 128 is a standard choice in the weight-only quantization literature (e.g., AWQ, GPTQ) and aligns well with GPU warp sizes (32 threads) and tensor core tile dimensions, enabling efficient implementation.

**The fused GEMM kernel.** The core systems challenge is that group quantization in a weight-activation setting requires per-group dequantization *during* the matrix multiplication, not as a separable pre- or post-processing step. To understand why, consider the computation the GEMM kernel must perform.

For a standard matrix multiplication $C = A \times B$ (where A is activations, B is weights), with per-tensor quantization, the computation is:

$$C_{ij} = s_A s_B \sum_k \bar{A}_{ik} \bar{B}_{kj}$$

where $\bar{A}$ and $\bar{B}$ are the integer-quantized matrices and $s_A$, $s_B$ are the per-tensor scale factors. The scale factors can be factored out of the summation: compute the integer dot product first, then multiply by $s_A s_B$ once at the end. This is efficient because the tensor cores do all the work in the low-bit integer domain.

With group quantization on the K dimension (the inner dimension being reduced), the computation becomes:

$$C_{ij} = \sum_{g} s_{A}^{(g)} s_{B}^{(g)} \sum_{k \in \text{group}_g} \bar{A}_{ik} \bar{B}_{kj}$$

where $g$ indexes over groups along the K dimension (groups of 128 contiguous K indices), and $s_A^{(g)}$, $s_B^{(g)}$ are the per-group scale factors for activation group $g$ and weight group $g$ respectively. The scale factors are now *inside* the outer summation over groups—they cannot be factored out because different groups have different scales. This means the kernel must: (1) compute the integer dot product for each group using INT4 tensor cores, (2) multiply the result by the group's scale factors to convert to FP16, and (3) accumulate the FP16 results across groups. Steps 2 and 3 must happen for every group, and if done naively as separate operations after the tensor core computation, they would require writing intermediate results to memory and reading them back, negating the throughput benefit of INT4 tensor cores.

Atom's solution, illustrated in Figure 8, is a **fused GEMM kernel** that interleaves these operations within the MMA (matrix multiply-accumulate) pipeline. The kernel proceeds as follows:

**Step 1 (Tensor Cores):** The INT4 tensor cores compute the integer matrix multiplication for one group of the activation and weight matrices, producing a temporary result in integer format (typically INT32, since the accumulation of INT4 multiplications requires more bits to avoid overflow). This uses the GPU's INT4 tensor core instructions, which are the fastest available compute units.

**Step 2 (CUDA Cores):** Immediately after the tensor cores produce the group's result, CUDA cores dequantize this temporary result by multiplying by the group's scale factors $s_A^{(g)} \cdot s_B^{(g)}$, converting it from INT32 to FP16. Crucially, this dequantization is performed *in-place in registers*, not by writing to memory and reading back.

**Step 3 (CUDA Cores):** The dequantized FP16 result is accumulated into a running FP16 accumulator for the output tile. This accumulation happens using standard FP16 addition.

The paper emphasizes that these three steps are "fused in a single pipeline" and "executed in place without extra memory movement and overlapped with the original MMA instructions" (Section 4.2). In GPU kernel design, "overlapped" refers to the fact that while the tensor cores are computing group $g+1$, the CUDA cores can simultaneously perform the dequantization and accumulation for group $g$, exploiting instruction-level parallelism between different functional units on the GPU. This pipelining is essential for hiding the latency of the dequantization operations.

**Why the fused kernel matters for overall throughput.** The paper reports (Section 5.4.2) that a pure INT4 GEMM kernel without any quantization operations achieves approximately 980 TOPS. Adding mixed-precision support (keeping 128 channels in INT8) reduces this to approximately 900 TOPS—an 8% overhead. Adding group quantization with fused dequantization reduces it further to approximately 770 TOPS—a more significant 21% overhead from the pure INT4 ceiling, but still approximately 18% higher than the theoretical peak INT8 throughput of 624 TOPS. This means that even with the group quantization overhead, Atom's INT4 GEMM kernel is faster than any possible INT8 implementation—and dramatically faster than the FP16 baseline of 312 TFLOPS. The fusion is what makes this possible: without it, the per-group dequantization would require separate kernel launches and memory round-trips that would push the effective throughput below the INT8 ceiling, eliminating the benefit of going to INT4.

#### Dynamic Activation Quantization, Clipping, and GPTQ

**Dynamic vs. static quantization.** The paper adopts **dynamic quantization** for activations, meaning that quantization parameters (scale factors) are computed at inference time for each activation tensor individually, rather than being pre-computed from calibration data and reused for all inputs.

The motivation is that activation distributions vary per input. A sentence about mathematics produces different activation patterns than a sentence about history, and these differences affect the optimal quantization scale. Static quantization would compute a single scale factor from calibration data and apply it to all future inputs, but this can be suboptimal when the runtime input's activation range is narrower or wider than the calibration distribution. A narrower range would be quantized too coarsely (many integer levels unused, reducing effective precision); a wider range would clip values beyond the calibration-determined clipping threshold, introducing error.

Dynamic quantization avoids this by computing the scale factor from the actual activation values at inference time using the symmetric quantization formula with a pre-determined clipping factor:

$$s = \frac{2 \cdot \max(|X|)}{2^4 - 1} \cdot c$$

where the maximum is taken over the actual activation tensor $X$ being quantized. The clipping factor $c$ is determined offline via grid search (Section 5.1: "we use a grid search to find optimal clipping factors 0.9 and 0.85 for activation and weight quantization, respectively") and fixed for deployment. The grid search evaluates multiple values of $c$ on calibration data, selecting the value that minimizes perplexity or maximizes downstream accuracy.

**Fusing quantization into prior operators.** Computing $\max(|X|)$ for each activation tensor requires a reduction over the entire tensor, which is an $O(n)$ operation with low arithmetic intensity—every element is read once but only a single scalar is produced. If implemented as a separate kernel, this reduction would add latency to every transformer layer and potentially become a new bottleneck. Atom fuses the quantization reduction into the preceding operator, following the approach of ZeroQuant (Yao et al., 2022).

In practice, this means that the layer normalization kernel (or the preceding GEMM kernel for activations that are not preceded by normalization) also computes the per-group maximum absolute values needed for quantization. As the kernel writes the activation tensor to memory, it simultaneously updates running maximum values for each group. By the time the tensor is fully written, the scale factors for all groups are available in registers, and the quantization (element-wise division by scale and rounding) can be folded into the same write operation. The paper states that "the additional operator is element-wise (with a reduction and an element-wise division), the run time of the fused operator is still negligible compared to the time-consuming dense and self-attention layers."

**Symmetric vs. asymmetric quantization.** Atom uses **symmetric quantization** (zero-point $z = 0$) for weights and activations, as opposed to asymmetric quantization which includes a non-zero zero-point. The paper explains this choice in Section 2: asymmetric quantization introduces additional cross-terms during matrix multiplication because:

$$W \cdot X = s_W(\bar{W} - z_W) \cdot s_X(\bar{X} - z_X) = s_W s_X (\bar{W}\bar{X} - z_W\bar{X} - z_X\bar{W} + z_W z_X)$$

The three additional terms ($-z_W\bar{X}$, $-z_X\bar{W}$, $+z_W z_X$) must be computed in floating-point arithmetic since they involve the FP16 zero-points, defeating the purpose of using low-bit integer tensor cores for speed. Symmetric quantization with $z_W = z_X = 0$ eliminates these cross-terms, reducing the matrix multiplication to $s_W s_X \cdot (\bar{W}\bar{X})$—a single integer matrix multiplication followed by a single FP16 scale multiplication. The accuracy cost of symmetric quantization (forcing the representation to be symmetric around zero even when the distribution is not perfectly symmetric) is mitigated by the clipping factor $c$, which can effectively shift the effective range.

**Clipping factor optimization.** The clipping factor $c$ in the quantization formula serves to reduce the dynamic range used for quantization. When $c < 1$, values with magnitude greater than $\max(|X|) \cdot c$ are "clipped"—they get quantized to the maximum integer value rather than represented accurately. This reduces the error for the majority of (non-outlier) values because the scale factor $s$ becomes smaller, making each integer level represent a narrower range of floating-point values.

The trade-off is between **clipping error** (the error for values that get saturated) and **quantization error** (the error for values that must be rounded to the nearest integer level). A smaller $c$ increases clipping error (more values get clipped) but decreases quantization error (the remaining values are represented more precisely). The grid search finds the $c$ that balances these two error sources for the specific model and dataset.

The paper reports optimal clipping factors of 0.9 for activations and 0.85 for weights (Section 5.1). The different optimal values reflect the different distribution characteristics: weight distributions tend to be more concentrated near zero with heavier tails (benefitting from more aggressive clipping), while activation distributions vary more per input (benefitting from less clipping to accommodate the variability).

**GPTQ for weight quantization.** For weight matrices, which are quantized offline, Atom incorporates **GPTQ** (Frantar et al., 2023), a post-training quantization algorithm that uses approximate second-order information to minimize the error introduced by weight quantization. GPTQ works by iterating through the rows of the weight matrix, quantizing each row, and adjusting the remaining unquantized rows to compensate for the error introduced by quantization of the current row. This "compensation" uses the inverse Hessian of the calibration data's activations, which captures which weight elements are most sensitive to perturbation.

The paper states (Section 4.3): "We also incorporate GPTQ when quantizing the weight matrix since this is purely an offline process and offers an accuracy boost without sacrificing runtime efficiency." The key point is that GPTQ's computational cost (which involves Hessian computation and iterative updates) is incurred once during offline quantization and does not affect inference latency. Table 3 shows that adding GPTQ after clipping reduces WikiText2 perplexity by an additional 0.09 (from 6.13 to 6.04), confirming that the second-order compensation provides a meaningful accuracy improvement over simple round-to-nearest quantization.

**Ablation study results for accuracy.** Table 3 provides a systematic decomposition of how each quantization technique contributes to Atom's accuracy. Starting from the catastrophic 2315.52 perplexity of simple W4A4 round-to-nearest:

- Adding mixed-precision (keeping 128 outliers in FP16): 2315.52 → 11.34 (a 2304-point improvement, confirming that outliers are the dominant source of error)
- Quantizing outliers to INT8 instead of FP16: 11.34 → 11.39 (only 0.05 increase, justifying the use of INT8 for hardware compatibility)
- Adding group quantization with group size 128: 11.39 → 6.22 (a 5.17-point improvement, the second-largest gain, confirming that per-channel granularity is insufficient)
- Adding clipping optimization: 6.22 → 6.13 (a 0.09 improvement)
- Adding GPTQ: 6.13 → 6.04 (a 0.09 improvement)
- Adding INT4 KV-cache quantization: 6.04 → 6.16 (a 0.12 increase, acceptable given the throughput benefit)

The final result (6.16) is only 0.48 higher than the FP16 baseline of 5.68. The decomposition clearly shows that mixed-precision and group quantization are the two dominant accuracy-preserving mechanisms, with clipping and GPTQ providing smaller but necessary refinements.

#### KV-Cache Quantization Design and Justification

The self-attention layer in transformer models computes attention scores between the current token's query vector Q and all previous tokens' key vectors K, then uses these scores to compute a weighted sum of the value vectors V. In LLM serving, the key and value vectors for all previous tokens in each request's context must be stored in GPU memory—this is the **KV-cache**. For a model with hidden dimension $d$, $L$ layers, and $H$ attention heads, the full KV-cache for a single token requires $2 \times L \times d \times 2$ bytes in FP16 (2 bytes per element, with factor of 2 for both K and V). For a batch of $B$ requests, each with sequence length $S$, the total KV-cache memory is $2 \times B \times S \times L \times d$ bytes (ignoring the head dimension which partitions $d$). This memory grows linearly with batch size and sequence length, quickly becoming the dominant memory consumer at large batch sizes.

Atom applies low-bit quantization to the KV-cache to reduce memory consumption and, consequently, memory movement during the attention computation. The paper makes two key design choices that differentiate KV-cache quantization from activation quantization:

**Asymmetric quantization for KV-cache rather than symmetric.** The paper states (Section 4.4): "Atom uses asymmetric quantization on KV-cache as it can provide accuracy benefits." The rationale is that the self-attention layer is memory-bound—its performance is limited by how fast data can be loaded from memory, not by how fast the arithmetic can be performed—so the additional cross-terms from asymmetric quantization do not become a bottleneck. In a memory-bound operation, the arithmetic units have spare capacity (they're waiting for data), so the extra FLOPs from asymmetric dequantization can be absorbed without increasing latency. Meanwhile, asymmetric quantization can better represent distributions that are not centered around zero, which is common for value vectors (which, after the softmax-weighted sum, tend to be non-negative if the attention weights are non-negative).

**Per-attention-head granularity.** The paper applies quantization "with the granularity of attention head" (Section 4.4), meaning that all K and V vectors within a single attention head share quantization parameters. This is coarser than per-token or per-group quantization but simpler to implement and requires storing fewer scale factors in the KV-cache.

**Why KV-cache is easier to quantize than activations.** The paper provides two arguments for why the KV-cache is more amenable to aggressive quantization (Section 4.4):

**Argument 1: Softmax dampens K-cache quantization error.** During self-attention, the Q vector is multiplied by the K cache, and the result is normalized by a softmax operation before being multiplied by the V cache. The softmax involves an exponential: $\text{softmax}(x)_i = \exp(x_i) / \sum_j \exp(x_j)$. Because the exponential function amplifies differences, small quantization errors in the K cache—which cause small perturbations to the pre-softmax attention scores—get compressed by the softmax normalization. Specifically, if the quantization error in K changes an attention score by ±ε, the softmax output changes by a factor related to $\exp(\pm \epsilon)$, which for small ε is approximately $1 \pm \epsilon$. The subsequent multiplication by V is a linear operation, so the output error is proportional to ε times V. This is in contrast to direct multiplication (as in dense layers), where quantization error in activations propagates linearly without any normalizing nonlinearity to dampen it.

**Argument 2: The V cache exhibits fewer outliers.** Figure 9 in the paper shows a sampled V cache distribution from a single attention head of Llama-7B. Compared to the activation distribution shown in Figure 5(a), the V cache "shows a much less dynamic range with fewer outlier channels." The paper attributes this to the fact that V vectors are the output of attention-weighted sums, which averages values across the sequence and reduces extreme magnitudes. With fewer outliers, uniform low-bit quantization can represent the V cache values more accurately without needing mixed-precision.

**Implementation: Quantized KV-cache with FlashInfer.** At inference time, the KV-cache is stored in INT4 format. During the self-attention computation, Atom loads the quantized K and V vectors from memory and dequantizes them to FP16 before performing the attention computation in FP16. The dequantization is fused into the FlashInfer kernel (Ye et al., 2024), which is a performant library for LLM serving that implements FlashAttention-like optimizations. By fusing dequantization, the kernel loads only the INT4 values and the per-head scale factors from memory, performs on-the-fly conversion to FP16 in registers, and immediately feeds the FP16 values into the attention computation. The memory movement is reduced by approximately 4× compared to loading FP16 KV-cache directly.

The paper also integrates **PageAttention** (Kwon et al., 2023) for efficient memory management of the KV-cache. PageAttention uses virtual memory paging to manage KV-cache blocks, enabling memory sharing across requests and reducing fragmentation. Atom's quantized KV-cache is compatible with PageAttention because the quantization is applied per-block—each page of KV-cache stores INT4 values and associated scale factors, and the FlashInfer kernel handles dequantization transparently regardless of page boundaries.

**Accuracy impact.** Table 3 shows that quantizing the KV-cache to INT4 increases WikiText2 perplexity by 0.12 (from 6.04 to 6.16 on Llama-7B). This relatively small impact supports the paper's argument that the KV-cache is more robust to quantization than activations. The KV-cache quantization is applied on top of all other optimizations, and the cumulative accuracy remains close to FP16 levels.

#### End-to-End Quantization Workflow and Kernel Fusion Strategy

The paper implements Atom as a complete serving pipeline integrated into Punica (Chen et al., 2023), an LLM serving framework. Figure 6 provides a detailed diagram of the per-layer workflow, showing exactly which operators are fused and where quantization/dequantization operations occur.

**Offline preprocessing (one-time per model).** Before deployment, the following steps are performed using calibration data (128 randomly sampled sentences from WikiText2):

1. **Outlier identification:** Run the calibration data through the unquantized FP16 model, collect activation statistics, and identify the 128 channels per linear layer with the highest sum of squared activation values.
2. **Weight reordering:** For each linear layer (Q, K, V, O projections in attention; gate, up, down projections in the MLP), reorder the rows of the weight matrix to align with the activation reordering that will move outliers to the end. The reorder indices are stored for later use in the dynamic activation reordering step.
3. **Weight quantization with GPTQ:** Apply GPTQ to the reordered weight matrices to produce INT4 quantized weights. GPTQ processes the weight matrix row-by-row, quantizing each row to INT4 and adjusting subsequent rows to compensate for the quantization error. The result is a set of INT4 weight matrices (with per-group scale factors for group size 128) and INT8 weight submatrices for the outlier channels.
4. **Clipping factor grid search:** For both activations and weights, evaluate a range of clipping factors on calibration data to find the values that minimize perplexity. The optimal values (0.9 for activations, 0.85 for weights) are stored as deployment constants.

The paper reports that this offline process "takes roughly 4 hours to complete" for Llama-65B on an RTX Ada 6000 GPU, processing the model layer-by-layer (Section 5.1).

**Inference-time per-layer workflow** (Figure 6, described for a single Llama decoder layer):

**Step 1: Layer Normalization + Activation Reordering + Activation Quantization (fused).** The input to each decoder layer first passes through RMSNorm (or standard LayerNorm, depending on the model variant). The fused kernel performs three operations in a single pass: (a) normalize the input activations, (b) reorder the channels to move outlier channels to the end (using the pre-computed reorder indices), and (c) compute per-group scale factors by finding the maximum absolute value in each group of 128 elements and applying the clipping factor 0.9, then quantize to INT4 (or INT8 for the 128 outlier channels). The output of this fused kernel is a quantized activation tensor ready for the subsequent GEMMs.

**Step 2: QKV Projections (fused GEMM).** For the self-attention Q, K, V projections, the quantized activation tensor is multiplied by the respective quantized weight matrices using the fused GEMM kernel described in Section 4.2. Each GEMM uses INT4 tensor cores for the normal channels and INT8 tensor cores for the outlier channels, with per-group dequantization and accumulation fused into the MMA pipeline. The output is dequantized back to FP16 for the subsequent attention computation.

**Step 3: Self-Attention with Quantized KV-Cache.** The FlashInfer kernel computes self-attention using the FP16 Q, K, V from Step 2. For the K and V caches from previous tokens, the kernel loads INT4 values and per-head scale factors from the quantized KV-cache, dequantizes them to FP16 in registers, and performs the standard attention computation. The newly computed K and V vectors for the current token are quantized to INT4 and appended to the KV-cache using PageAttention's memory management.

**Step 4: O Projection (fused GEMM).** The attention output passes through the O projection matrix, another fused GEMM using the quantized weight matrix.

**Step 5: MLP Layers (fused GEMMs).** The Llama MLP uses a gated architecture with three projections: gate_proj, up_proj, and down_proj. The input passes through gate_proj and up_proj in parallel (both fused GEMMs), the gate output passes through a SiLU activation function, element-wise multiplication combines the gate and up outputs, and the result passes through down_proj (another fused GEMM) to produce the MLP output.

**Step 6: Requantization for Next Layer.** The output of the decoder layer needs to be requantized before feeding into the next layer's fused normalization+quantization kernel. The paper shows "Requant" blocks at the boundaries between layers in Figure 6, indicating that activations are maintained in quantized format as they cross layer boundaries when possible, reducing memory traffic.

**Dequantization points.** The paper's Figure 6 uses color coding: blue for FP16 operations and green for low-bit operations. Dequantization operations (converting from low-bit to FP16) are shown at specific points: before the FlashInfer attention kernel (because attention is computed in FP16), and at the output of GEMMs (because subsequent operations like SiLU activation require FP16 precision). The principle is to keep data in low-bit format for as much of the pipeline as possible, dequantizing only when the hardware or the operation's numerical requirements demand it.

#### Serving Framework Integration and Batching Strategy

Atom is integrated into Punica (Chen et al., 2023), which the paper describes as "an LLM serving framework." Punica implements continuous batching, following the approach of Orca (Yu et al., 2022): when a request completes (the model generates an end-of-sequence token or reaches the maximum generation length), the now-empty slot in the batch is immediately filled with a new request from the queue, rather than waiting for all requests in the current batch to finish. This maximizes GPU utilization by ensuring the batch is always full.

The paper models the request distribution using **ShareGPT** (HuggingFace, 2023), which contains real conversation traces from users interacting with LLMs. "We treat multi-round conversations as requests from multiple users. Specifically, we concatenate all previous prompts and responses and use them as the prompt for the new user request" (Section 5.3.2). This means that a single multi-turn conversation in the dataset is split into multiple independent requests, each with the conversation history up to that point as the prompt and the next user utterance as the generation target. This produces a realistic distribution of prefill lengths (from the concatenated history) and decode lengths (from the user response lengths).

The serving system operates in a **First-Come-First-Served (FCFS)** manner: requests are processed in the order they arrive. The paper evaluates batch sizes from 8 to 256, noting that "it is practical to deploy a 180B model with a 256 batch size in the serving scenario" (Section 5.3.2 footnote) when combining quantization, pipeline parallelism, and tensor parallelism to amortize weight loading.

**Memory-constrained evaluation.** The paper's end-to-end experiments are limited by the 24GB memory of the RTX 4090 GPU used for evaluation. At large batch sizes where FP16 models would exceed available memory, the paper uses simulation: "we simulate the performance by reusing the KV-caches from a smaller batch size while preserving the data access pattern and amount of computation" (Section 5.3.2). This simulation accounts for the computational cost of processing a larger batch even when the full batch cannot fit in physical memory, and is used to estimate the throughput that would be achievable on GPUs with sufficient capacity (e.g., A100 80GB or H100). The paper distinguishes solid lines (exact measurements on hardware) from dashed lines (simulated) in Figures 10(a) and 10(b).

**Latency constraint.** The paper uses a target latency of 100ms per token as the acceptable threshold, citing Trauzettel-Klosinski et al. (2012) which found this to be "the effective reading speed of human eyes." Figure 10(b) shows that Atom maintains latency below this threshold across all tested batch sizes (up to 256), while the FP16 baseline exceeds the threshold at batch sizes above approximately 64. This constraint is critical for practical deployment: throughput improvements that violate human-perceptible latency limits are not useful for interactive applications.

#### Hardware-Aware Kernel Design Philosophy

Throughout Sections 4 and 5, the paper demonstrates a consistent design philosophy that can be summarized as **move the complexity to where the hardware has spare capacity**. This philosophy manifests in several specific decisions:

**Fusing quantization into memory-bound operators rather than compute-bound operators.** The layer normalization kernel is memory-bound (it reads a tensor, performs element-wise operations, and writes a tensor—the arithmetic intensity is low), so it has spare compute capacity. By fusing activation reordering and quantization parameter computation into this kernel, the overhead is effectively hidden behind the memory bandwidth that the kernel would be waiting on anyway. Conversely, the GEMM kernel is compute-bound at large batch sizes, so every additional operation in the GEMM pipeline directly reduces throughput. This is why the paper takes care to fuse only the minimum necessary operations (per-group dequantization and accumulation) into the GEMM, moving everything else to prior operators.

**Reordering channels rather than using sparse/scatter operations.** GPUs are architected for dense, regular memory access patterns. The channel reordering technique converts a scattered outlier problem into a dense block problem at the cost of a permutation in the normalization kernel. The permutation is essentially a gather operation on the write path, which is much cheaper than requiring every subsequent kernel to handle irregular memory access.

**Asymmetric quantization for memory-bound operations (KV-cache) but not for compute-bound operations (activations).** The self-attention layer is so memory-bound that the extra arithmetic from asymmetric dequantization can be absorbed (the compute units are idle waiting for data anyway). The dense layers are compute-bound, so the extra arithmetic would directly reduce throughput. This asymmetric choice—different quantization schemes for different operations based on their hardware bottleneck—is the kind of systems-level thinking that distinguishes Atom from pure algorithm papers that would apply the same quantization scheme uniformly.

**Using INT8 for outliers rather than FP16 to maintain tensor core compatibility.** The INT4 and INT8 tensor cores share the same hardware units and instruction pipeline, so a mixed INT4/INT8 GEMM can be implemented as a single fused kernel. FP16, by contrast, uses different execution units (CUDA cores or FP16 tensor cores), and switching between INT4 tensor cores and FP16 units mid-kernel would introduce pipeline stalls and register file spilling. The paper's finding that INT8 quantization of outliers adds only 0.05 perplexity compared to FP16 (Table 3) validates that this hardware-driven design choice does not sacrifice accuracy.

## 4. Key Insights and Innovations

### Innovation 1: Reframing LLM Quantization as a Hardware-Software Co-Design Problem Rather Than an Algorithm-In-Isolation Problem

The dominant framing in prior LLM quantization research treats quantization as a purely algorithmic challenge: design a better quantization scheme (smarter rounding, learned clipping, transformation-based outlier mitigation), measure accuracy on perplexity and zero-shot benchmarks, and declare victory when the accuracy gap to FP16 narrows. The implicit assumption is that if the algorithm produces acceptable accuracy, the throughput will follow naturally from using lower-bit representations. Atom challenges this assumption at a fundamental level.

The paper's distinctive intellectual move is to **start from the hardware capability and work backward to the algorithm**. The opening of Section 1 establishes the GPU arithmetic ceiling as the fixed constraint—INT4 tensor cores deliver 1248 TOPS versus 312 TFLOPS for FP16—and then asks: *what would it take to actually use this capability for accurate LLM serving?* This inverts the standard research pipeline. Rather than developing a quantization algorithm on paper, measuring its accuracy, and then checking if it can be implemented efficiently, Atom identifies that the hardware path to 4× throughput exists but is gated by three simultaneous requirements: (a) the quantization must produce INT4 tensors that tensor cores can consume directly, (b) the outlier channels that make INT4 inaccurate must be handled without breaking the dense memory access patterns that tensor cores require, and (c) the per-group dequantization that enables fine-grained accuracy must be fused into the GEMM pipeline rather than performed as a separate step.

What makes this reframing significant beyond the performance numbers is that it **redefines the success criteria for quantization research in the serving context**. An algorithm that achieves 0.1 perplexity degradation in a standalone evaluation but cannot be implemented without 40% kernel overhead is not "better" than one with 0.3 perplexity degradation that runs at near-peak tensor core throughput. The paper's roofline analysis (Figure 4) is not just an explanatory diagram—it's a diagnostic tool that reorients the field from accuracy-only evaluation to accuracy-efficiency Pareto optimization. Prior work like SmoothQuant (Xiao et al., 2023) and OmniQuant (Shao et al., 2023) operated in an implicit "quantize first, optimize later" paradigm; Atom argues that for 4-bit precision, the quantization scheme and the kernel implementation must be co-designed because the algorithmic choices (group size, outlier ratio, symmetric vs. asymmetric) directly determine whether the resulting GEMM can be implemented efficiently on tensor cores.

This is a **fundamental shift** in perspective, not an incremental refinement. It echoes the philosophy behind FlashAttention (Dao et al., 2022)—which similarly started from GPU memory hierarchy constraints and worked backward to an algorithm—but applies it to the quantization domain where the hardware-algorithm coupling is even tighter because the bit-width of the representation determines which execution units can be used at all.

The evidence for this co-design claim is distributed throughout the paper but crystallizes in the kernel evaluation results (Section 5.3.1). The fused GEMM kernel achieves 770 TOPS with group quantization overhead—representing a 21% drop from the pure INT4 ceiling of 980 TOPS, but crucially still 18% above the INT8 ceiling of 624 TOPS. This means the algorithmic choices (group size 128, 128 outlier channels in INT8) were selected not just for their accuracy properties but because they produce a kernel that stays above the INT8 throughput threshold—if group quantization overhead had pushed throughput below 624 TOPS, using INT4 would offer no advantage over INT8 despite using half the bits. The paper does not state this as an explicit design constraint, but the numbers reveal it: the algorithmic parameters were tuned to land in the regime where INT4 throughput exceeds INT8 throughput even after accounting for all fusion overhead.

### Innovation 2: Diagnosing the Outlier Problem as the Fundamental Barrier to 4-Bit Quantization, and Solving It Through Separation Rather Than Transformation

Prior work on LLM quantization recognized that activation outliers are problematic, but the dominant approaches attempted to **transform** the problem away rather than **separate** the outliers from the normal distribution. SmoothQuant (Xiao et al., 2023) used mathematically equivalent scaling transformations to shift quantization difficulty from activations to weights, effectively smoothing the activation distribution so that per-tensor INT8 quantization could represent it. LLM.INT8() (Dettmers et al., 2022) used mixed-precision to separate outliers but did so with FP16 outliers and scattered memory access patterns, making the approach impractical for GPUs at scale. RPTQ (Yuan et al., 2023) used channel reordering but for a different purpose—reducing variance within quantization groups—not for enabling efficient mixed-precision.

Atom's distinctive conceptual contribution is the recognition that **at 4-bit precision, separation is not an optimization—it is a necessity**. The paper's ablation results (Table 3) make this argument quantitatively: simple W4A4 round-to-nearest quantization collapses to a WikiText2 perplexity of 2315.52 (compared to 5.68 for FP16), and the single intervention of keeping 128 outlier channels in higher precision recovers 2304 of those 2310 perplexity points (bringing it to 11.34). This is not a marginal improvement—it is the difference between a completely destroyed model and one that is in the ballpark of usability. The remaining 5.66 perplexity gap (from 11.34 to 5.68) is then closed by the combination of group quantization, clipping, and GPTQ, but each of those techniques contributes 5 points or less individually.

What this reveals is a **phase transition in quantization difficulty between 8-bit and 4-bit**. At 8 bits, the 256 integer levels provide enough dynamic range headroom that transformation-based approaches (SmoothQuant) can absorb outlier magnitudes into the quantizer without catastrophic error—you can shift the difficulty around enough that everything fits in the 256 levels. At 4 bits, with only 16 levels, the dynamic range is so constrained that no amount of shifting can make a 100× outlier magnitude fit alongside normal values without washing out the normal values' precision. The only viable strategy is to physically separate the outliers and quantize them at higher precision. The paper doesn't state this phase transition explicitly, but the evidence compels it: prior works achieved near-lossless INT8 quantization with transformations, but the same transformation approach (OmniQuant's learnable equivalent transformations) loses 11+ percentage points of zero-shot accuracy at INT4. The problem has changed qualitatively, not just quantitatively.

This is a **fundamental diagnostic insight** rather than a methodological contribution. It tells the field *why* 4-bit quantization is hard in a way that prior work did not articulate, and it explains why the research trajectory that worked for 8-bit (better transformations) does not extend to 4-bit. The implication is that future work on sub-4-bit quantization (INT3, INT2) will need to lean even harder into separation-based approaches, likely separating not just channel-level outliers but token-level and value-level outliers as well.

### Innovation 3: Establishing That KV-Cache Quantization Is Fundamentally Easier Than Activation Quantization, and Exploiting This Asymmetry

The paper makes a non-obvious empirical observation that has significant architectural implications: **the KV-cache is substantially easier to quantize than intermediate activations, and for fundamentally different reasons for K versus V**. This is not a claim that prior work disputed—it's a claim that prior work hadn't systematically investigated or articulated.

For the **K cache**, the paper argues that the softmax normalization in attention acts as an error dampener (Section 4.4). Quantization errors in the key vectors perturb the pre-softmax attention logits, but because softmax involves exponentiation followed by normalization, small additive errors in the logits get compressed. This is a structural property of the attention mechanism, not an empirical contingency—it holds for any transformer using softmax attention regardless of model size or training procedure.

For the **V cache**, the paper provides empirical evidence that the distribution is qualitatively different from intermediate activations. Figure 9 shows a V cache distribution with "much less dynamic range with fewer outlier channels" compared to the activation distribution in Figure 5(a). The paper attributes this to the averaging effect of attention-weighted sums: V vectors are weighted averages of value vectors across the sequence, which naturally reduces extreme magnitudes. This is an empirical finding that may or may not generalize to all models and tasks, but for the Llama models tested, it enables direct low-bit quantization of the V cache without mixed-precision.

The significance of this insight is that it **enables an asymmetric quantization strategy**: the KV-cache can be quantized more aggressively (INT4 with asymmetric quantization, per-head granularity, no mixed-precision) than intermediate activations (which require INT4 with mixed-precision, symmetric quantization, per-group granularity). This asymmetry is not an arbitrary design choice—it follows from the structural properties of the attention mechanism and the empirical properties of value vectors. The paper exploits this to reduce KV-cache memory by 4× while adding only 0.12 perplexity (Table 3), a contribution that is independent of the activation quantization scheme and could be adopted by systems using different activation quantization approaches.

This finding also has implications for **model architecture design**. If future hardware or serving systems can support even more aggressive KV-cache compression (e.g., 2-bit), the paper's analysis suggests that the K cache's robustness to quantization is architecturally guaranteed (via softmax), while the V cache's robustness is empirically observed and may benefit from architectural modifications that further regularize its distribution. This opens a design space where attention mechanisms could be explicitly designed with KV-cache quantizability as an objective, analogous to how Group Query Attention (Ainslie et al., 2023) was designed to reduce KV-cache size.

### Innovation 4: Demonstrating Through Roofline Analysis That the Optimal Quantization Strategy Depends on the Operational Regime (Batch Size), and That Weight-Only and Weight-Activation Quantization Occupy Different Efficiency Niches

The paper's roofline analysis (Figure 4) is not just a visualization—it is a **conceptual framework that explains when and why different quantization strategies are appropriate**. The key insight is that the arithmetic intensity (FLOPs per byte of memory traffic) of an operation determines whether it is memory-bound or compute-bound, and this boundary determines which quantization approach delivers benefits.

For the **dense layers** (MLP and projections), arithmetic intensity scales with batch size because the weight matrix is loaded once and reused across all batch elements, while the FLOPs scale with batch size. At small batch sizes, these operations are memory-bound, and the primary benefit of quantization is reduced memory traffic (weight-only quantization helps here by reducing weight memory). At large batch sizes—which is the target for throughput-oriented serving—these operations become compute-bound, and the primary benefit of quantization is faster arithmetic (weight-activation quantization is required here because the computation itself must use low-bit units). Weight-only quantization provides *no compute benefit* in this regime because the dequantized weights are still multiplied in FP16.

For the **self-attention layers**, the non-batchable KV-cache access means these operations are memory-bound at all practical batch sizes. Here, any quantization that reduces memory traffic helps, including weight-only quantization (which doesn't affect KV-cache but reduces weight loading in the QKV projections) and KV-cache quantization (which directly reduces attention memory traffic).

This analysis reveals that **the serving community's focus on weight-only quantization (GPTQ, AWQ, SqueezeLLM) was optimizing for the wrong bottleneck** in large-batch serving scenarios. Weight-only quantization excels at reducing the memory footprint of model weights, which is the dominant constraint for single-query, latency-bound inference or for small-batch scenarios where the dense layers are memory-bound. But for the throughput-oriented, large-batch serving that the paper targets, the dense layers shift to compute-bound, meaning the FP16 arithmetic itself becomes the bottleneck. Weight-only quantization leaves this bottleneck untouched—the roofline diagram in Figure 4(b) shows the dense layer operator *staying at the same computational throughput* regardless of weight quantization, because the operations are still FP16.

This is a **fundamental reframing** of the quantization-for-serving problem. It tells practitioners that the choice between weight-only and weight-activation quantization is not a matter of "which technique is better" but rather "which operational regime are you in?" At batch size 1, weight-only quantization may be optimal because it reduces weight-loading memory traffic and the FP16 compute units are underutilized anyway (they're waiting for data). At batch size 256, weight-activation quantization is necessary because the compute units are saturated and the only way to increase throughput is to process more operations per cycle via INT4 tensor cores. The paper's end-to-end results (Figure 10c) validate this: under a fixed memory budget, Atom's W4A4 achieves 5.5× the throughput of W4A16 (weight-only) because the larger effective batch size enabled by memory reduction combines with the higher compute throughput of INT4 tensor cores.

This insight is significant beyond the paper's specific results because it provides a **decision framework** for serving system architects. It is not generally true that lower-bit quantization is better—the benefit depends on whether the target operations are compute-bound or memory-bound, which in turn depends on batch size, model architecture, and hardware characteristics. The paper doesn't just report that Atom is faster; it provides the analytical tools to predict when and why it will be faster in different deployment scenarios.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The paper evaluates on two categories of benchmarks. For perplexity, it uses **WikiText2** (Merity et al., 2016), **PTB** (Marcus et al., 1994), and **C4** (Raffel et al., 2020) datasets—standard language modeling evaluation corpora. For zero-shot accuracy, it uses **lm-eval** (Gao et al., 2021) to evaluate on **PIQA** (Bisk et al., 2019), **ARC-easy and ARC-challenge** (Clark et al., 2018), **BoolQ** (Clark et al., 2019), **HellaSwag** (Zellers et al., 2019), and **Winogrande** (Sakaguchi et al., 2019). The calibration data for outlier identification and weight quantization uses "128 randomly sampled sentences from WikiText2" (Section 5.1), not the full dataset.

- **Base model(s).** All experiments use the open-source **Llama** model family (Touvron et al., 2023a) at four scales: **7B, 13B, 30B, and 65B** parameters. Additionally, Section 6 extends evaluation to **Llama-2** (Touvron et al., 2023b) at 7B, 13B, and 70B, and **Mixtral 8×7B** (Jiang et al., 2024), a mixture-of-experts model. The Llama family is chosen because it is widely used in the open-source LLM serving community and has been the primary evaluation target in prior quantization work (SmoothQuant, OmniQuant, QLLM), enabling direct comparison.

- **Metrics.** **Perplexity** is reported for language modeling (lower is better), computed as the exponentiated average negative log-likelihood on held-out text. **Zero-shot accuracy** is reported as the percentage of correctly answered questions across six common-sense reasoning tasks, with the average across tasks reported as a summary statistic. For efficiency, **throughput** is measured in tokens per second (generated tokens divided by total inference time), and **latency** is measured as the average decode time per token in milliseconds, excluding queuing time (Section 5.3.2). Kernel-level throughput is measured in **TOPS** (tera-operations per second) using NVBench (NVIDIA, 2024b).

- **Baselines.** The paper compares against three categories of prior work, all targeting post-training quantization:
  - **SmoothQuant** (Xiao et al., 2023): INT8 weight-activation quantization using mathematical equivalent transformations, evaluated at both W8A8 and W4A4/W3A3. The paper implements its own version since "the official code does not support Llama models" and "conducted a grid search on the alpha value defined in SmoothQuant and reported the best numbers for each benchmark" (Section 5.2).
  - **OmniQuant** (Shao et al., 2023): 4-bit weight-activation quantization using learnable weight clipping and equivalent transformations. For W4A4, the paper uses pre-quantized weights from the authors; for W3A3, it runs the official code with a hyperparameter search identifying "lr = 1e−4 and alpha = 0.75" as optimal. W3A3 OmniQuant is skipped on Llama-30B and 65B "due to the large resource requirement of its quantization process."
  - **QLLM** (Liu et al., 2023a): 4-bit weight-activation quantization using low-rank error compensation. The paper reports W4A4 numbers from the QLLM publication but does not evaluate W3A3 "as their code was unavailable when we conducted experiments."
  
  For efficiency experiments (Section 5.3), additional baselines include:
  - **FP16**: The unquantized model as the upper-bound accuracy reference and lower-bound throughput reference.
  - **W4A16**: Weight-only quantization at 4-bit with FP16 activations, following the approach of AWQ (Lin et al., 2023), implemented with a fused GEMM kernel.
  - **W8A8**: INT8 weight-activation quantization, implemented following SmoothQuant's methodology with a fused GEMM kernel.

- **Generation budget / compute accounting.** Compute efficiency is measured in two complementary ways. At the **kernel level**, throughput is reported in TOPS for dense-layer GEMM and latency in microseconds for self-attention, both profiled with NVBench at varying batch sizes from 16 to 512 for GEMM and 8 to 128 for attention. At the **end-to-end level**, the serving system processes requests from ShareGPT-derived traces under continuous batching with batch sizes from 8 to 256, and throughput is measured as total generated tokens divided by total wall-clock time including both prefill and decode phases. For memory-constrained comparisons (Figure 10c), all methods are evaluated under the same GPU memory budget (24GB RTX 4090), allowing Atom to serve larger batch sizes than FP16 or INT8 because its quantized weights and KV-cache occupy less memory. When the required memory exceeds GPU capacity, throughput is simulated "by reusing the KV-caches from a smaller batch size while preserving the data access pattern and amount of computation" (Section 5.3.2).

- **Cross-validation / statistical protocol.** The 128 outlier channels per layer are selected using calibration data (128 randomly sampled WikiText2 sentences), following prior work (Lee et al., 2023; Shao et al., 2023; Liu et al., 2023a). The clipping factors (0.9 for activations, 0.85 for weights) are determined by grid search on the same calibration data (Section 5.1). No cross-validation across multiple calibration splits is reported. Since the accuracy evaluation is on standard held-out test sets (WikiText2 test, PTB test, C4 validation, and the standard lm-eval zero-shot splits), there is no risk of test-set leakage through the calibration procedure—the calibration data comes from a different distribution (WikiText2 training sentences) than the evaluation data. The paper does not report confidence intervals, standard deviations, or statistical significance tests for any accuracy or perplexity numbers, which is standard practice in the LLM quantization literature but limits the ability to assess whether small differences (e.g., the 0.05 perplexity increase from quantizing outliers to INT8 instead of FP16) are statistically reliable.

### Main Quantitative Results

The evaluation is organized into four logical groups: (1) accuracy results comparing Atom to prior 4-bit quantization methods across model scales, (2) kernel-level efficiency results isolating the performance of the fused GEMM and attention operators, (3) end-to-end serving throughput and latency under realistic workloads, and (4) ablation studies decomposing the contribution of each quantization technique to both accuracy and efficiency.

---

#### Accuracy: Atom Crosses the Threshold to Viable INT4 Weight-Activation Quantization

**Zero-shot accuracy (Table 1).** Atom achieves substantially higher zero-shot accuracy than all prior 4-bit weight-activation quantization methods across all Llama model sizes. On Llama-7B, Atom's average accuracy across six tasks is 61.78% for W4A4, compared to 52.65% for OmniQuant, 51.84% for QLLM, and 48.23% for SmoothQuant—a 9.1 to 13.5 percentage point improvement over prior work. The FP16 baseline achieves 64.04%, meaning Atom loses only 2.26 percentage points (a 3.5% relative drop). By Llama-65B, the gap narrows further: Atom achieves 69.57% versus 70.97% for FP16, a loss of only 1.4 percentage points (2.0% relative), while OmniQuant achieves 59.22% and QLLM achieves 59.83%—both losing over 11 percentage points.

The pattern across model sizes reveals that Atom's accuracy advantage grows with model scale: the accuracy gap between Atom and the best prior method (OmniQuant) is 9.1 points at 7B, 10.0 points at 13B, 9.7 points at 30B, and 10.4 points at 65B. This suggests that larger models are not inherently easier to quantize—the prior methods do not close the gap—but Atom's specific combination of techniques (mixed-precision, group quantization, dynamic scaling) becomes increasingly effective as model size grows, possibly because the outlier phenomenon becomes more structured and separable in larger models.

For the more aggressive W3A3 setting, Atom on Llama-7B achieves 51.37%, compared to SmoothQuant's 37.28% and OmniQuant's 36.28%. On Llama-13B, Atom reaches 55.81% versus 37.36% and 36.58%. The accuracy degradation from W4A4 to W3A3 is approximately 10-11 percentage points for Atom (61.78% → 51.37% at 7B), which is substantial but still leaves the model in a usable regime—the W3A3 Atom model outperforms the W4A4 OmniQuant model on Llama-7B (51.37% vs. 52.65%), suggesting that Atom's techniques are sufficiently robust to push an additional bit lower while remaining competitive with prior work at one bit higher. W3A3 OmniQuant results on 30B and 65B are missing due to computational constraints, and W3A3 QLLM results are entirely absent due to code unavailability. The paper acknowledges these gaps by leaving the corresponding cells empty in Table 1.

Examining per-task scores reveals that the accuracy loss is not uniform across tasks. On Llama-7B W4A4, Atom loses 5.3 points on HellaSwag (72.99 → 69.81), 3.2 points on Winogrande (66.85 → 63.69), and 3.3 points on BoolQ (73.12 → 69.79), while losing only 1.1 points on PIQA (77.37 → 76.28) and 0.4 points on ARC-e (52.53 → 52.10). The larger degradation on HellaSwag and Winogrande—both of which require nuanced common-sense reasoning—suggests that 4-bit quantization disproportionately affects tasks requiring fine-grained token-level distinctions, while tasks with strong surface-level cues (PIQA) are more robust. This task-level heterogeneity is not discussed in the paper but is visible in the data.

**Perplexity (Table 2).** Atom achieves perplexity within 0.5 points of FP16 across all three datasets at the largest model scale. On Llama-65B W4A4: WikiText2 goes from 3.53 (FP16) to 3.89 (Atom, +0.36), PTB from 6.91 to 7.22 (+0.31), and C4 from 5.62 to 5.92 (+0.30). These gaps are small enough that the quantized model would likely be indistinguishable from FP16 in most downstream generation tasks, especially given that perplexity differences below 1.0 on WikiText2 are typically not human-perceptible.

The contrast with prior methods is stark. On Llama-7B W4A4 WikiText2: SmoothQuant achieves 22.62 (versus 5.68 for FP16, a 4× increase), OmniQuant achieves 11.59, QLLM achieves 9.65, and Atom achieves 6.16. The progression—22.62 → 11.59 → 9.65 → 6.16 → 5.68—illustrates how each generation of quantization research has roughly halved the perplexity gap, with Atom being the first to bring it within 0.5 of the FP16 baseline. For W3A3 on Llama-7B, SmoothQuant's WikiText2 perplexity explodes to 2.7e4 (a model that has essentially collapsed), OmniQuant reaches 3.4e3, and Atom achieves 11.77—still degraded relative to FP16 but within an order of magnitude, and dramatically better than prior work.

A notable pattern: the perplexity improvement from larger model size is preserved in Atom's quantized models. FP16 Llama-7B achieves 5.68 WikiText2 perplexity; Atom W4A4 on Llama-65B achieves 3.89, substantially better than FP16 Llama-7B. This means that a quantized 65B model still meaningfully outperforms an unquantized 7B model, suggesting that the benefits of scale are not destroyed by 4-bit quantization—a important practical finding for serving deployments where one might choose between an unquantized small model and a quantized large model.

#### Kernel-Level Efficiency: The Fused GEMM Kernel Demonstrates the INT4 Advantage

**Dense layer GEMM throughput (Figure 11a).** The paper benchmarks matrix multiplication kernels at varying batch sizes (from 16 to 512) using NVBench, configured to match the Llama-7B dimensions and a sequence length of 1024. At batch size 512—representative of the compute-bound regime targeted for large-batch serving—Atom's W4A4 fused GEMM achieves approximately 3.4× throughput improvement over the FP16 baseline and approximately 1.9× over the W8A8 implementation. The W4A16 (weight-only quantization) kernel shows modest improvement over FP16 at small batch sizes (where weight memory reduction helps in the memory-bound regime) but converges to near-FP16 throughput at batch size 512, consistent with the roofline analysis in Figure 4(b) that predicts weight-only quantization provides no compute benefit when the operation becomes compute-bound.

The paper's kernel profiling reveals an important scaling pattern: Atom's throughput advantage over INT8 grows slightly as batch size increases (from roughly 1.7× at batch size 64 to roughly 1.9× at batch size 512), while the advantage over FP16 grows more dramatically (from roughly 2.5× to 3.4×). This is because larger matrices amortize kernel launch overhead and better utilize the tensor cores' throughput, and INT4 tensor cores benefit more from this amortization than INT8 due to their higher peak throughput (2× the operations per cycle). The paper does not provide exact TOPS numbers for all methods at all batch sizes—the figure uses a normalized "Tops improvement" y-axis—but states in Section 5.4.2 that the fused GEMM kernel achieves approximately 770 TOPS with all overheads included, compared to a pure INT4 ceiling of 980 TOPS and an INT8 ceiling of 624 TOPS.

**Self-attention latency (Figure 11b).** For the self-attention layer, the paper fuses KV-cache dequantization into FlashInfer and measures latency at batch sizes from 8 to 128 (since the attention computation does not scale with batch size in the same way as dense layers—each request's attention is computed independently using its own KV-cache). At batch size 128, Atom's INT4-quantized KV-cache achieves approximately 3.5× lower latency than the FP16 baseline and approximately 1.8× lower than INT8 quantization. The improvement is nearly linear with the bit-width reduction (4-bit provides roughly 4× memory reduction over 16-bit, and 2× over 8-bit), which is exactly what the roofline model predicts for a memory-bound operation: reducing memory traffic by a factor of R should reduce latency by approximately R, assuming the computation is negligible compared to memory access time. The paper's result that INT4 is only 3.5× faster than FP16 rather than the theoretical 4× likely reflects the overhead of dequantization (fetching and applying per-head scale factors) and the fact that not all memory traffic is KV-cache (there are also Q, attention mask, and output tensors that remain in FP16).

**Kernel fusion ablation (Section 5.4.2).** The paper reports that the pure INT4 GEMM without any mixed-precision or group quantization achieves approximately 980 TOPS. Adding mixed-precision support—keeping 128 channels in INT8, which requires switching between INT4 and INT8 tensor core operations—reduces throughput to approximately 900 TOPS, an 8% overhead. Adding group quantization with fused dequantization and accumulation reduces throughput further to approximately 770 TOPS, a total 21% overhead from the pure INT4 ceiling. The paper does not report the throughput of a non-fused implementation (where dequantization and accumulation are separate kernel launches), but the claim that the fused version is necessary for practical speedup is supported by the fact that 770 TOPS remains above the INT8 ceiling of 624 TOPS—if overhead had pushed throughput below 624 TOPS, INT4 would offer no advantage over INT8.

**Channel reordering overhead (Section 5.4.2, last paragraph).** The paper compares Atom's fused reordering approach against a baseline that uses matrix decomposition for mixed-precision (following LLM.INT8()'s approach): "Results show that Atom consistently outperforms the baseline from 25% to 35%." This is measured as end-to-end inference latency of a layer-norm-plus-GEMM operation across batch sizes from 16 to 256, confirming that the irregular memory access patterns of naive mixed-precision implementations impose substantial overhead that the channel reordering technique eliminates.

#### End-to-End Serving: Throughput Gains Within Latency Constraints

**Throughput scaling with batch size (Figure 10a).** Atom achieves higher throughput than all baselines across all tested batch sizes (8 to 256). At batch size 256—the largest evaluated—Atom achieves approximately 28,000 tokens/second compared to roughly 11,000 for W8A8, 7,000 for W4A16, and under 4,000 for FP16. These are the dashed-line (simulated) numbers for cases exceeding 24GB GPU memory; the solid-line (measured) results at smaller batch sizes show the same relative ordering.

The throughput gap widens at larger batch sizes. At batch size 32 (solid line), Atom achieves roughly 3× the throughput of FP16; at batch size 128 (dashed line), the gap is roughly 5×; at batch size 256 (dashed line), roughly 7×. This super-linear scaling with batch size is expected because larger batches benefit from both the increased tensor core utilization (amortizing kernel launch overhead) and the reduced memory pressure from quantized weights and KV-cache, which allows even larger batches to fit in memory—a virtuous cycle that prior quantization methods cannot fully exploit because either their arithmetic remains in FP16 (W4A16) or their bit-width is higher (W8A8).

**Latency per token (Figure 10b).** Atom's per-token decode latency is lower than all baselines at every batch size. At batch size 64—which the paper identifies as achieving "the highest practical performance" (Section 5.3.2)—Atom's latency is approximately 30ms, compared to roughly 50ms for W8A8, 65ms for W4A16, and 110ms for FP16. The importance of this result is that Atom maintains latency below the 100ms human reading speed threshold (Trauzettel-Klosinski et al., 2012) even at batch size 256 (approximately 80ms), while the FP16 baseline exceeds 100ms around batch size 48. This means Atom can serve 5× more concurrent requests than FP16 before latency becomes human-perceptible, which directly translates to the throughput advantage shown in Figure 10a.

The latency curves reveal an interesting pattern: W4A16 (weight-only quantization) shows higher latency than W8A8 at small batch sizes (below 32) but crosses over at larger batch sizes. This is because at small batch sizes, the dense layers are memory-bound and weight-only quantization's memory reduction helps proportionally more; at larger batch sizes, the dense layers become compute-bound, and W8A8's faster tensor core arithmetic (624 TOPS vs. 312 TFLOPS for FP16) dominates. Atom's INT4 arithmetic at 770 TOPS is consistently faster than both across all regimes.

**Fixed-memory comparison (Figure 10c).** Under a fixed GPU memory budget (24GB), Atom's combined memory reduction (4-bit weights and KV-cache) and faster arithmetic enable it to serve larger batch sizes than any baseline. The bar chart shows: FP16 achieves roughly 3,600 tokens/second with a batch size limited by memory capacity, W4A16 achieves roughly 5,100 tokens/second (enabled by reduced weight memory allowing slightly larger batches), W8A8 achieves roughly 11,000 tokens/second (from both memory reduction and faster INT8 arithmetic), and Atom achieves roughly 28,000 tokens/second. The paper annotates these as 7.73× over FP16, 5.53× over W4A16, and 2.53× over W8A8. The latency bars (overlaid on the same figure) show that Atom's latency is approximately 32ms versus 65ms for FP16 and 45ms for W8A8, confirming that the throughput gains do not come at the cost of increased latency.

This comparison is the most practically relevant for production serving, where GPU memory is typically the binding constraint for how many concurrent requests can be served. The 2.53× improvement over INT8 is particularly significant because INT8 weight-activation quantization (via SmoothQuant) was the prior state of the art for practical serving—it had acceptable accuracy and used tensor cores—but was leaving a factor of 2.5× throughput on the table by not exploiting INT4 tensor cores. Atom captures that remaining throughput while maintaining comparable accuracy.

**Workload modeling and generalizability.** The paper uses ShareGPT conversation traces to model the distribution of prompt lengths and generation lengths, but details are sparse. The paper states that it "treats multi-round conversations as requests from multiple users" and "concatenates all previous prompts and responses" as the prompt for the new request (Section 5.3.2). This means the prefill lengths include the full conversation history, which can be thousands of tokens, while decode lengths are single user responses. The exact length distributions are not reported, making it difficult to assess how general the throughput results are to workloads with different prefill-to-decode ratios. In particular, if a workload has predominantly short prefill (single-turn queries) and long decode (generating lengthy responses), the relative benefit of dense-layer GEMM acceleration (which dominates prefill and projection operations) versus KV-cache quantization (which dominates the decode attention) would shift. The paper does not provide a sensitivity analysis over workload characteristics.

#### Generality Results: Extension to Llama-2 and Mixtral

**Table 4 results.** The paper demonstrates that Atom generalizes to newer model architectures by evaluating on Llama-2 (7B, 13B, 70B) and Mixtral 8×7B (a mixture-of-experts model). For Llama-2 7B W4A4, Atom achieves WikiText2 perplexity of 6.03 (versus 5.47 for FP16, +0.56), compared to SmoothQuant's 83.12 and OmniQuant's 14.61. For Llama-2 70B, Atom achieves 3.68 (versus 3.32 for FP16, +0.36). For Mixtral 8×7B, Atom achieves 4.41 (versus 3.84 for FP16, +0.57). The paper notes that "on MoE models, Atom only needs to adapt to using different reorder indices for different experts' FFN" but finds that "accuracy is similar when Atom shares reorder indices across all experts in an MoE layer," so shared indices are used for efficiency.

**FP4 compatibility.** The paper also evaluates Atom using FP4 data format (instead of INT4), since emerging hardware like NVIDIA Blackwell (NVIDIA, 2024a) supports FP4 and MX formats. On Llama-2 and Mixtral, Atom with FP4 achieves "similar accuracy to INT4 when quantizing both weights and activations into FP4" (Table 4, Atom (FP) rows). For Llama-2 7B, FP4 Atom achieves 6.14 versus 6.03 for INT4 Atom; for Mixtral, 4.50 versus 4.41. The paper concludes that "the representation capability between INT4 and FP4 is similar," which is a meaningful finding because FP4's non-uniform spacing (it allocates more representable values near zero due to the exponent) might theoretically provide better accuracy for LLM weight distributions that are concentrated near zero with heavy tails. The empirical similarity suggests that the benefits of group quantization and mixed-precision dominate over the choice of integer versus floating-point representation at 4 bits.

### Ablation Studies and Robustness Checks

**Quantization technique contribution to accuracy (Table 3):** The paper provides a step-by-step decomposition of how each technique reduces WikiText2 perplexity on Llama-7B. Starting from a W4A4 round-to-nearest (RTN) baseline with per-channel/per-token quantization, the perplexity is 2315.52. Keeping 128 outlier channels in FP16 reduces it to 11.34 (a 2304-point improvement, confirming that outliers are the dominant error source). Quantizing those same outliers to INT8 instead of FP16 yields 11.39, only a 0.05 increase—a critical finding that validates the hardware compatibility decision. Adding group quantization with group size 128 reduces perplexity to 6.22 (a 5.17-point improvement, the second-largest gain). Clipping optimization further reduces it to 6.13 (0.09 improvement). GPTQ weight quantization reduces it to 6.04 (another 0.09). Finally, quantizing the KV-cache to INT4 increases perplexity to 6.16 (0.12 increase), which the paper accepts as a tolerable trade-off for the throughput benefit. The non-obvious finding is that group quantization and outlier separation are the two dominant accuracy mechanisms, each contributing orders of magnitude more than clipping or GPTQ. This implies that future work targeting even lower bit-widths (INT3, INT2) should prioritize more sophisticated outlier handling and finer grouping rather than better rounding algorithms.

**Mixed-precision overhead (Section 5.4.2):** The GEMM kernel throughput degradation from adding mixed-precision (keeping 128 INT8 channels) is approximately 8% (980 → 900 TOPS). This relatively modest overhead—given that the outlier channels require INT8 tensor core operations which run at half the INT4 rate—suggests that the fixed cost of switching between INT4 and INT8 tensor core pipelines is well-amortized across the large matrix dimensions. The paper does not provide an ablation over the number of outlier channels (e.g., keeping 64, 128, 256 channels in INT8), which would be informative for understanding the accuracy-efficiency Pareto frontier: more outlier channels improve accuracy but reduce throughput, and the optimal point likely depends on the specific model and deployment accuracy requirements.

**Group quantization overhead (Section 5.4.2):** The addition of per-group dequantization and accumulation reduces throughput from 900 TOPS (mixed-precision only) to 770 TOPS (mixed-precision + group quantization), a 14% additional overhead. This is the largest single efficiency cost in the system, because per-group dequantization requires executing FP16 multiply-add operations on CUDA cores interleaved with INT4 tensor core operations, and the pipeline between these two execution units has limited bandwidth. The paper notes that the fused GEMM kernel still outperforms the INT8 theoretical peak by 18%, confirming that the overhead is manageable. The paper's observation that "group quantization with the MX format is supported by NVIDIA Blackwell GPUs" (Section 6) suggests that future hardware will natively support per-group scaling, potentially eliminating this overhead entirely and pushing Atom-like methods closer to the pure INT4 ceiling.

**Channel reordering vs. matrix decomposition (Section 5.4.2, last paragraph):** Atom's fused reordering approach achieves 25–35% lower latency than the LLM.INT8()-style matrix decomposition baseline across batch sizes 16 to 256. This validates the paper's central systems claim that channel reordering is not merely an accuracy optimization borrowed from RPTQ but an essential efficiency technique. The baseline's overhead comes from the need to split the activation matrix into normal and outlier submatrices, perform separate GEMMs with different precisions, and recombine the results—each step requiring separate kernel launches and memory round-trips. Atom's reordering eliminates all of this by making the outlier region a contiguous block that can be handled within a single fused kernel launch.

**KV-cache quantization accuracy impact (Table 3):** Quantizing the KV-cache to INT4 increases perplexity by 0.12 (6.04 → 6.16), which is less than the benefit of any single accuracy-preserving technique except clipping (which contributes 0.09). This confirms the paper's argument that the KV-cache is substantially easier to quantize than intermediate activations. The paper attributes this to softmax error dampening for the K cache and reduced outlier prevalence in the V cache (Section 4.4, Figure 9). However, the paper does not provide an ablation separating K-cache and V-cache quantization—both are quantized together, so it is impossible to determine whether one contributes more to the accuracy loss than the other. This is a missing experiment that would strengthen the paper's mechanistic claims about why each is robust to quantization.

**Clipping factor sensitivity (Section 5.1):** The paper reports optimal clipping factors of 0.9 for activations and 0.85 for weights, determined by grid search. The fact that weights benefit from more aggressive clipping (0.85 vs. 0.9) is consistent with weight distributions being more concentrated near zero with heavier tails—more clipping means accepting saturation of extreme weight values in exchange for finer quantization of the dense center. The paper does not report the sensitivity of perplexity to the clipping factor choice (i.e., how much worse is 0.8 or 1.0?), which would help practitioners understand how carefully this hyperparameter needs to be tuned for new models.

**Generalization to new formats (Table 4):** The FP4 results for Llama-2 and Mixtral show that Atom's techniques are not tied to INT4 specifically—the mixed-precision, group quantization, and dynamic scaling approach transfers to FP4 with similar accuracy. This is important because the paper positions Atom as a general low-bit quantization method, not an INT4-specific method. The FP4 results are less than 0.11 perplexity worse than INT4 across all models tested (Llama-2 7B: 6.03 INT vs. 6.14 FP; Mixtral: 4.41 vs. 4.50), suggesting that the choice of 4-bit format is a secondary concern compared to the algorithmic techniques that handle outliers and quantization granularity.

### Critical Assessment

The experimental evaluation establishes that Atom achieves the paper's central accuracy claim—maintaining close-to-FP16 accuracy at W4A4 across multiple model scales—and its central efficiency claim—delivering substantially higher serving throughput than FP16, W4A16, and W8A8 baselines. However, several aspects of the experimental design warrant careful examination.

**The accuracy comparison against prior work is somewhat unfair to OmniQuant and QLLM in the W3A3 setting.** The paper acknowledges that OmniQuant W3A3 on 30B and 65B is omitted "due to the large resource requirement of its quantization process" and that QLLM W3A3 is omitted because "their code was unavailable." This is understandable logistically but means the W3A3 comparison is incomplete—we cannot assess whether Atom's 10+ point accuracy advantage at W3A3 would persist at larger model scales where prior methods might also improve. Given the pattern that Atom's advantage at W4A4 roughly holds constant across scales (~10 points), it is plausible that W3A3 would similarly maintain an advantage, but this is unverified.

**The accuracy evaluation is limited to perplexity (on standard language modeling corpora) and zero-shot accuracy (on six common-sense reasoning tasks).** These are standard benchmarks in the quantization literature and sufficient for establishing that Atom's accuracy degradation is small relative to prior work. However, they do not evaluate: (a) generation quality on open-ended tasks (dialogue, summarization, instruction following), (b) factual accuracy or hallucination rates (which might be affected by quantization-induced distribution shift), (c) calibration or confidence estimation (do the quantized model's probabilities remain well-calibrated?), or (d) few-shot or in-context learning performance (does 4-bit quantization affect the model's ability to use in-context examples?). These are all relevant to serving scenarios but beyond the scope of standard quantization evaluation. The paper's claim of "negligible accuracy loss" should be understood as "negligible on the specific benchmarks evaluated."

**The efficiency evaluation has a "simulated" regime that requires careful interpretation.** The dashed lines in Figures 10(a) and 10(b) represent batch sizes that exceed 24GB GPU memory, simulated "by reusing the KV-caches from a smaller batch size while preserving the data access pattern and amount of computation." This simulation accounts for the arithmetic cost but cannot account for real-world memory system effects: at very large batch sizes, the memory controller, L2 cache pressure, and DRAM bandwidth saturation can cause nonlinear performance degradation that a linear extrapolation from smaller batches would miss. The paper's simulated results at batch size 256 should therefore be treated as optimistic upper bounds on achievable throughput. The solid-line results at batch sizes up to 32 are exact and show the same relative ordering (Atom > W8A8 > W4A16 > FP16), so the qualitative conclusion is robust, but the exact 7.73× number at batch size 256 is a simulation-based estimate, not a hardware measurement.

**The latency target of 100ms is well-justified by the cited reading-speed study (Trauzettel-Klosinski et al., 2012), but the paper evaluates only average decode latency, not tail latency.** LLM serving latency is heavily influenced by stragglers—requests with unusually long generation lengths or unlucky scheduling—and users perceive tail latency (e.g., P95 or P99) more than average latency. A quantization scheme that reduces average latency but increases variance (e.g., because per-group dequantization creates more irregular computation) could have worse perceived performance. The paper does not report latency distributions or percentiles.

**The workload is a single trace (ShareGPT) with a specific prefill-to-decode ratio, and no sensitivity analysis is provided.** Different serving scenarios have different characteristics: code completion might have short prefill (a few lines of context) and medium decode, while document summarization has long prefill (the document) and short decode (the summary). The relative benefit of Atom's dense-layer GEMM acceleration (which dominates compute-bound prefill and projection) versus its KV-cache quantization (which dominates memory-bound decode attention) would shift depending on this ratio. A workload with predominantly short prefill would benefit more from KV-cache quantization; one with long prefill would benefit more from GEMM acceleration. The paper's single-workload evaluation cannot distinguish these effects.

**The ablation study in Table 3 adds techniques cumulatively in a specific order, which can obscure interactions.** For example, group quantization is added before clipping, and both are added before GPTQ. It is possible that clipping provides more benefit when group quantization is absent (because single-scale per-channel quantization has larger errors that clipping can mitigate) or that GPTQ provides more benefit without group quantization. The cumulative ablation shows the marginal contribution of each technique in the specific order presented but cannot reveal whether the techniques are complementary or substitutable. A factorial ablation (evaluating each technique independently and in combination) would be more informative but would require 2^5 = 32 experimental configurations, which is likely why the paper uses the simpler cumulative approach.

**The paper does not evaluate Atom against quantization-aware training (QAT) methods**, only post-training quantization (PTQ) methods. QAT methods fine-tune the model to recover accuracy after quantization and typically achieve higher accuracy than PTQ at the same bit-width. The omission is reasonable—the paper targets the serving scenario where fine-tuning may not be feasible (e.g., for API-provided models where weights are frozen)—but means the accuracy comparison is limited to the PTQ regime. A QAT-trained 4-bit model might achieve FP16-comparable accuracy without needing Atom's specific techniques, potentially making the system-level contributions (kernel fusion, channel reordering, KV-cache quantization) applicable to a different accuracy solution.

**The 4-hour offline quantization time for Llama-65B is reported without comparison to prior methods.** OmniQuant requires 128 A100 GPUs for its optimization process on some configurations; SmoothQuant's offline calibration is essentially instantaneous (it only requires computing a scaling factor). Situating Atom's offline cost in the context of prior methods would help practitioners assess the total cost of adoption. The paper presents offline time as a fixed one-time cost, which is reasonable—4 hours on a single GPU for a model that will serve millions of requests is negligible—but the omission of comparison numbers leaves the reader without context.

**The generalizability results (Table 4) are for perplexity only**, not zero-shot accuracy. While perplexity on WikiText2 correlates with downstream task performance, it is an imperfect proxy. The omission of zero-shot accuracy for Llama-2 and Mixtral means we cannot verify whether Atom's accuracy advantage over prior methods transfers to these newer architectures, or whether the perplexity improvements are predictive of downstream accuracy.

Overall, the experiments robustly support the paper's central claims within their defined scope: Atom achieves higher accuracy than prior 4-bit PTQ methods on Llama models, and it achieves higher serving throughput than FP16, W4A16, and W8A8 baselines on a standard LLM serving workload. The accuracy advantage over prior methods is large enough (9-13 percentage points on zero-shot tasks) that experimental uncertainties (confidence intervals, alternative hyperparameters) are unlikely to change the qualitative conclusion. The throughput advantage is demonstrated through both kernel-level profiling (validating the fused GEMM design) and end-to-end serving measurement (validating the integration into a realistic framework), with clear roofline analysis explaining the mechanisms. The primary limitation is that the evaluation is confined to a single model family (Llama/Llama-2) and a single serving workload distribution (ShareGPT), leaving the generality of the throughput numbers to other architectures and deployment scenarios as an open question that the paper acknowledges but does not fully address.

## 6. Limitations and Trade-offs

### 6.1 Difficulty Estimation Cost Is Unaccounted for in the Offline Quantization Pipeline

**The assumption or constraint.** Atom's mixed-precision approach requires identifying which 128 activation channels per linear layer are outliers, a process that involves running 128 calibration sentences through the unquantized FP16 model, collecting activation statistics, and computing per-channel squared-sum values to select the channels with the highest magnitudes (Section 5.1). The paper also requires a grid search over clipping factors for both activations and weights to find the optimal values (0.9 and 0.85, respectively). Both of these steps are presented as one-time offline costs, but the paper does not quantify how sensitive the outlier identification is to the choice and quantity of calibration data, nor does it evaluate whether the selected outliers generalize across different input distributions at deployment time.

**The consequence.** If the calibration data (128 WikiText2 sentences) is not representative of the serving workload's activation distributions—for example, if the serving workload consists predominantly of code generation rather than natural language, or if it involves domain-specific vocabulary and reasoning patterns not present in WikiText2—then the 128 channels identified as outliers during calibration may not be the channels that exhibit outlier behavior at inference time. The paper's mixed-precision strategy hinges on isolating the *correct* outlier channels: if a channel that is an outlier at serving time was not identified during calibration, it will be quantized to INT4 along with normal channels, potentially causing large quantization errors that compound across layers. Conversely, if a channel identified as an outlier during calibration behaves normally at serving time, the system wastes INT8 tensor core throughput on channels that don't need it.

The paper provides no sensitivity analysis over the quantity of calibration data (is 128 sentences sufficient? would 64 or 256 change the outlier selection?) or the domain of calibration data (would calibration on C4 or code produce different outlier channels than WikiText2?). Prior work has shown that activation outliers in LLMs are partly input-dependent (Dettmers et al., 2022; Xiao et al., 2023), and Atom's static outlier selection—determined once offline and fixed for all future inputs—may be fragile to distribution shift in ways that the paper's single-domain evaluation cannot detect.

**What evidence exists in the paper.** The paper evaluates accuracy only on standard language modeling benchmarks (WikiText2, PTB, C4 for perplexity; PIQA, ARC, BoolQ, HellaSwag, Winogrande for zero-shot accuracy). All of these benchmarks are in the same broad domain (English natural language text) as the WikiText2 calibration data. There is no evaluation on out-of-domain text (code, mathematics, non-English languages, domain-specific technical text) that would stress-test the robustness of the static outlier selection. The calibration procedure itself is described in one sentence (Section 5.1: "To identify outlier channels, we use 128 randomly sampled sentences from WikiText2 as calibration data, following prior works"), with no ablation over calibration dataset size or domain.

**Mitigation status.** The paper does not address this limitation. It inherits the static calibration approach from prior work (Lee et al., 2023; Shao et al., 2023; Liu et al., 2023a) without evaluating its robustness. The dynamic activation quantization technique (Section 4.3) computes per-group scale factors on-the-fly at inference time, adapting to per-input distribution shifts *within* the normal and outlier channel groups, but it cannot change *which channels* are treated as outliers—that decision is baked into the reordered weight matrices during offline preprocessing. A dynamic outlier identification scheme (selecting outlier channels per-input based on runtime activation statistics) would address this limitation but would add inference-time overhead that the paper's fusion strategy does not currently handle.

### 6.2 The 4-Bit Quantization Advantage Shrinks Substantially When Moving from W4A4 to W3A3, and Hard Problems at W3A3 Collapse Entirely

**The assumption or constraint.** The paper presents Atom as a general low-bit quantization method and evaluates it at both W4A4 (4-bit weights, 4-bit activations) and W3A3 (3-bit weights, 3-bit activations) settings. The headline accuracy claims—"negligible accuracy loss," "1.4% average zero-shot accuracy drop"—apply specifically to W4A4 on Llama-65B (Table 1). The W3A3 results, while substantially better than prior work, show a qualitatively different accuracy profile that the paper's narrative of "maintaining high accuracy" does not fully acknowledge.

**The consequence.** At W3A3, the accuracy degradation is no longer negligible. On Llama-7B, Atom drops from 64.04% (FP16) to 51.37% (W3A3)—a 12.7 percentage point drop, or 19.8% relative degradation. On Llama-13B, the drop is 10.6 points (66.39% → 55.81%). On Llama-65B, even Atom's best result drops 7.8 points (70.97% → 63.20%). These accuracy losses are large enough that a production serving system would likely find them unacceptable for most applications—a model scoring 51% on common-sense reasoning tasks is qualitatively different from one scoring 64%, and the gap is large enough that users would notice incorrect or nonsensical outputs.

Moreover, the W3A3 perplexity results (Table 2) show that while Atom maintains coherence (11.77 WikiText2 perplexity on Llama-7B versus 2315.52 for the W4A4 baseline without mixed-precision), the model is substantially degraded from FP16 (5.68). Prior W3A3 methods (SmoothQuant, OmniQuant) collapse to perplexities in the thousands or tens of thousands, so Atom represents a dramatic improvement, but the absolute performance level is still far from the FP16 baseline. A serving provider choosing between deploying a W4A4 model (minimal accuracy loss, 4× memory reduction, 4× tensor core throughput) and a W3A3 model (substantial accuracy loss, 5.3× memory reduction, even faster tensor cores) would need to weigh whether the additional throughput gain justifies the accuracy cost. The paper provides no guidance on this trade-off and does not evaluate W3A3 end-to-end serving throughput to quantify the efficiency benefit that would need to offset the accuracy degradation.

The task-level breakdown for W3A3 is revealing. On Llama-7B, HellaSwag drops from 72.99 (FP16) to 53.19 (W3A3 Atom)—a 19.8 point loss. Winogrande drops from 66.85 to 55.56 (11.3 points). ARC-challenge drops from 41.38 to 30.72 (10.7 points). These are tasks that require nuanced reasoning over multiple sentences; the fact that they degrade more than pattern-matching tasks like PIQA (77.37 → 65.56, 11.8 points) suggests that W3A3 quantization disproportionately damages the model's ability to perform multi-step inference, which is precisely the capability that makes LLMs valuable.

**What evidence exists in the paper.** Table 1 reports W3A3 accuracy for Atom and baselines; Table 2 reports W3A3 perplexity. The paper does not provide an ablation decomposing W3A3 accuracy loss by quantization technique (analogous to Table 3 for W4A4), so it is unclear whether the degradation is driven by activation quantization error, weight quantization error, KV-cache quantization error, or an interaction between them. The paper also does not evaluate W3A3 end-to-end serving throughput, so the efficiency-accuracy trade-off at this precision level is unquantified.

**Mitigation status.** The paper does not address this limitation explicitly. It presents W3A3 results alongside W4A4 results without distinguishing their practical viability. The abstract and introduction emphasize the W4A4 results ("Atom improves end-to-end throughput by up to 7.73× compared to the FP16 and by 2.53× compared to INT8 quantization"), and the W3A3 results are presented as a secondary evaluation demonstrating that Atom outperforms prior methods, not as a practically deployable configuration. However, a reader could easily conclude that Atom "solves" 3-bit quantization in the same way it solves 4-bit, which the accuracy numbers do not support. The 12.7-point accuracy drop at W3A3 on Llama-7B represents a fundamentally different capability level, and the paper would be stronger if it explicitly delineated the practical boundary between "acceptable accuracy loss for deployment" (W4A4) and "substantial accuracy loss requiring application-specific justification" (W3A3).

### 6.3 The End-to-End Throughput Numbers at Large Batch Sizes Are Simulated, Not Measured, and the Simulation Methodology Cannot Capture Real Memory System Effects

**The assumption or constraint.** All end-to-end serving experiments are conducted on a single RTX 4090 GPU with 24GB of memory (Section 5.3). This hardware constraint means that at batch sizes above what fits in 24GB—which includes all the large-batch configurations where Atom's throughput advantage is largest—the paper uses simulation rather than direct measurement. The paper states: "When the memory requirement cannot be satisfied, we simulate the performance by reusing the KV-caches from a smaller batch size while preserving the data access pattern and amount of computation" (Section 5.3.2). Solid lines in Figures 10(a) and 10(b) represent exact measurements; dashed lines represent simulated results.

**The consequence.** The headline throughput improvement of 7.73× over FP16 is measured at batch size 256 (Figure 10c), which is a simulated data point—the RTX 4090's 24GB cannot hold the FP16 model weights plus KV-cache for 256 concurrent requests with realistic sequence lengths. The simulation "preserves the data access pattern and amount of computation" but cannot account for real-world memory system effects that emerge at large batch sizes: DRAM bandwidth saturation, L2 cache pressure and increased miss rates, TLB thrashing from large page tables, and memory controller queuing delays. These effects are typically nonlinear—doubling the batch size does not simply double the memory traffic; it can push the memory subsystem past a saturation point where latency increases disproportionately.

Moreover, the simulation reuses KV-caches from smaller batch sizes, meaning it models the *arithmetic* of processing a large batch (more rows in the GEMM) but not the *memory system behavior* of actually allocating and accessing the larger KV-cache in physical DRAM. For the self-attention layers—which the paper identifies as memory-bound and a key bottleneck—the actual DRAM access pattern depends on the physical layout of the KV-cache in memory, which is managed by PageAttention's virtual memory system (Kwon et al., 2023). At large batch sizes, PageAttention may need to manage many more virtual pages, increasing the translation lookaside buffer (TLB) pressure and potentially causing page table walks that add latency not captured by the simulation.

The practical implication is that the 7.73× number should be interpreted as an upper bound on achievable throughput improvement under ideal memory system conditions, not a guaranteed result on any specific GPU configuration. The solid-line results at small batch sizes (8–32 for some configurations) show throughput improvements in the 2–3× range, which are more reliable because they are directly measured. The gap between measured small-batch improvements and simulated large-batch improvements is substantial, and the paper does not provide a sensitivity analysis to bound the simulation error.

**What evidence exists in the paper.** Figure 10(a) and 10(b) use dashed lines for simulated results, and the paper is transparent about which points are measured versus simulated. The kernel-level profiling in Figure 11 is exact (measured on hardware using NVBench), and these results independently validate that the fused GEMM kernel achieves the claimed throughput advantage. However, kernel-level throughput does not directly translate to end-to-end serving throughput because the serving framework includes overhead from scheduling, memory management, and pipeline bubbles between operators that kernel benchmarks exclude.

**Mitigation status.** The paper acknowledges the simulation limitation explicitly (Section 5.3.2: "Due to GPU memory limits, we only show the exact results on small batch sizes") and distinguishes solid from dashed lines in the figures. However, it does not provide an error analysis for the simulation, does not validate the simulation against a known ground truth (e.g., simulating a batch size that *does* fit in memory and comparing to actual measurement), and does not discuss what real-world effects the simulation might miss. The paper's suggestion that deploying on GPUs with larger memory (A100 80GB, H100) would enable exact measurement of these configurations is reasonable but leaves the current claims contingent on future validation.

### 6.4 Generalization Claims Are Supported Only by Perplexity on Two Model Families, Without Zero-Shot Accuracy or Throughput Evaluation

**The assumption or constraint.** Section 6 ("Discussion") presents Atom's generality results on Llama-2 (7B, 13B, 70B) and Mixtral 8×7B, evaluating only WikiText2 perplexity (Table 4) and noting FP4 compatibility. The paper claims that "Atom's main techniques to achieve high accuracy are mixed precision for outliers and fine-grained quantization for normal values" and that "we empirically find these are generalizable to newer transformer-based LLMs." However, the evidence for this generalization claim is limited to a single metric (perplexity) on two model families, both of which are architecturally very similar to the Llama models used in the main evaluation.

**The consequence.** Perplexity is a useful indicator of language model quality, but it is an imperfect proxy for downstream task performance—models with similar perplexity can differ substantially in zero-shot accuracy, factual reliability, or instruction-following capability. The main evaluation (Section 5.2) uses both perplexity and zero-shot accuracy to establish Atom's accuracy claims on Llama models, and the fact that the discussion section omits zero-shot accuracy for Llama-2 and Mixtral weakens the claim that Atom's techniques transfer without degradation.

For Mixtral specifically, the mixture-of-experts architecture introduces additional complexity. The paper notes that "Atom only needs to adapt to using different reorder indices for different experts' FFN" but "we find that accuracy is similar when Atom shares reorder indices across all experts in an MoE layer, therefore we use shared indices for efficiency consideration" (Section 6). This is a pragmatic optimization, but the claim that shared indices produce "similar accuracy" is based on an empirical finding not reported in the paper—there is no table or figure comparing per-expert versus shared reorder indices for Mixtral. Different experts in an MoE layer specialize in different types of inputs, and their activation distributions may differ substantially. If one expert's outlier channels are not the same as another's, using shared indices means some outlier channels will be misclassified for some experts, potentially introducing quantization errors that would not occur with per-expert indices. The paper does not quantify this effect.

Moreover, the paper does not evaluate end-to-end serving throughput for Llama-2 or Mixtral. The kernel-level throughput claims (the fused GEMM achieving 770 TOPS) are architecture-agnostic—they depend only on matrix dimensions—but the end-to-end throughput depends on model-specific factors like the ratio of attention to MLP computation, the effectiveness of PageAttention for the specific KV-cache access patterns, and the overhead of the routing mechanism in MoE models. A practitioner considering Atom for Mixtral deployment cannot estimate the expected throughput improvement from the paper's Llama results alone.

**What evidence exists in the paper.** Table 4 reports WikiText2 perplexity for Llama-2 and Mixtral at W4A4, comparing Atom (INT4 and FP4 variants) against SmoothQuant and OmniQuant. No zero-shot accuracy, no perplexity on PTB or C4, no throughput numbers, and no W3A3 evaluation for these models. The Mixtral shared-index claim is presented without supporting data.

**Mitigation status.** The paper presents these results in a "Discussion" section (Section 6) rather than the main evaluation, which appropriately signals that they are preliminary. However, the text makes affirmative claims about generalizability ("we empirically find these are generalizable") that go beyond what the limited evidence supports. A more accurate characterization would be "our initial results on Llama-2 and Mixtral show promising perplexity preservation, but comprehensive evaluation including zero-shot accuracy and throughput measurement is needed to confirm generalizability."

### 6.5 The Method Provides No Mechanism for Dynamic Accuracy-Efficiency Trade-Off at Inference Time, Forcing an All-or-Nothing Quantization Decision

**The assumption or constraint.** Atom's quantization configuration—which channels are outliers, the group size (128), the clipping factors (0.9 and 0.85), and the KV-cache bit-width—is determined entirely offline during calibration and baked into the deployed model, including the reordered weight matrices and the fused kernel parameters. There is no mechanism for adjusting the quantization at inference time in response to per-request characteristics. A serving system deploying Atom must commit to a single quantization configuration for all requests, regardless of their difficulty, domain, or accuracy requirements.

**The consequence.** This all-or-nothing design forecloses an important serving optimization: trading accuracy for throughput on a per-request basis. In many production serving scenarios, not all requests have equal accuracy requirements. A user asking a factual question ("What is the capital of France?") may require high accuracy; a user asking for creative writing suggestions may tolerate occasional errors in exchange for faster generation. A system that could dynamically adjust quantization aggressiveness—for example, using W4A4 for latency-tolerant requests and W8A8 for accuracy-sensitive requests, or selectively enabling mixed-precision only for requests where the calibration-determined outliers are likely to manifest—could achieve higher average throughput while maintaining accuracy where it matters.

Atom's static configuration also means the system cannot adapt if the serving workload distribution shifts over time. If a model deployed with Atom's W4A4 quantization begins receiving substantially different types of inputs than the WikiText2 calibration data—for example, after a product update that changes the user interface and, consequently, the kinds of questions users ask—the outlier selection and clipping factors that were optimal for the calibration distribution may become suboptimal. The only remediation would be to re-run the offline calibration on new data and redeploy, an expensive process (4 hours for Llama-65B on a single GPU) that may not be feasible in continuous deployment pipelines.

This limitation is particularly acute given the paper's own finding that quantization accuracy is difficulty-dependent. In the main paper analysis (though not discussed in the prior sections here), the effectiveness of quantization varies across different types of inputs—outliers are more pronounced for some input distributions than others. Atom's static outlier selection treats all inputs uniformly, leaving potential accuracy gains on the table for inputs where a more conservative quantization would help, and potential throughput gains for inputs where more aggressive quantization would suffice.

**What evidence exists in the paper.** The offline calibration procedure is described in Section 5.1, and the deployment workflow in Figure 6 shows fixed quantization parameters throughout. No experiments evaluate dynamic adjustment of quantization parameters at inference time. The paper does not discuss the potential for per-request quantization adaptation.

**Mitigation status.** The paper does not address this limitation. It is not an oversight—the paper's goal is to demonstrate that accurate 4-bit weight-activation quantization is achievable at all, and dynamic adaptation is a natural next step that would build on this foundation. However, the omission means that practitioners adopting Atom must design their own mechanisms for multi-precision serving (e.g., deploying separate W4A4 and W8A8 model replicas and routing requests between them), which adds operational complexity that the paper does not discuss.

### 6.6 The Latency Evaluation Reports Only Average Decode Time per Token, Not Tail Latency, Making It Insufficient for Production SLO Assessment

**The assumption or constraint.** The paper's latency evaluation measures "the average decoding time of each token, without considering the queuing time" (Section 5.3.2) and compares it against a 100ms threshold derived from human reading speed studies (Trauzettel-Klosinski et al., 2012). The conclusion that "even at batch size 256, our latency is still lower than 100 ms" (Section 5.3.2) is based on this average metric.

**The consequence.** Production LLM serving systems are typically governed by Service Level Objectives (SLOs) expressed in terms of tail latency—for example, "99% of tokens must be generated within 100ms." Average latency can be misleading when the latency distribution has high variance, which is common in LLM serving due to variable generation lengths (some requests generate 10 tokens, others generate 1000), variable prompt lengths (affecting prefill time), and the continuous batching scheduler's decisions about which requests to include in each batch. A system that achieves 30ms average latency but has 5% of tokens taking 200ms would violate a typical P95 SLO, even though the average is well within the threshold.

Atom's quantization techniques introduce additional sources of latency variance that the average metric cannot capture. The fused GEMM kernel (Figure 8) interleaves INT4 tensor core operations with per-group dequantization on CUDA cores, and the balance between these two execution units depends on matrix dimensions and batch size. At certain problem sizes, the CUDA cores may become a bottleneck, causing pipeline stalls that increase latency for specific operations. The KV-cache dequantization in FlashInfer similarly adds per-token overhead that may vary depending on sequence length and memory layout. Average latency would smooth over these effects; tail latency would reveal whether they create problematic spikes.

The paper's latency target of 100ms is well-motivated by the reading speed literature, but the evaluation does not establish whether Atom can meet this target at high percentiles (P95, P99) rather than on average. For a serving provider committing to latency SLOs in a customer-facing SLA, the distinction between average and tail latency is the difference between a deployed system that mostly works and one that is contractually compliant.

**What evidence exists in the paper.** Figure 10(b) shows average decode latency per token across batch sizes for Atom and baselines. No latency distributions, percentiles, or variance metrics are reported. The kernel-level profiling in Figure 11 reports average latency for individual operators (not distributions), and NVBench typically reports mean or median execution time across multiple runs.

**Mitigation status.** The paper does not address this limitation. Measuring tail latency would require running the end-to-end serving benchmark with a larger number of requests and recording per-token latency distributions, which is standard practice in serving systems papers (e.g., vLLM reports P95 latency) but was likely constrained by the single-GPU experimental setup and the simulation-based evaluation at large batch sizes. The omission is understandable given the paper's primary focus on throughput, but it means the latency claims should be interpreted as "average latency meets the threshold" rather than "the system meets production SLOs at the threshold."

## 7. Implications and Future Directions

### How This Work Changes the Landscape

Atom does not introduce a fundamentally new quantization algorithm—mixed-precision outlier handling, group quantization, and dynamic scaling all existed in prior work—but it **redefines the success criteria for quantization research in the serving context** in a way that changes how the field should evaluate and design quantization methods.

The paper's central shift is from **accuracy-only evaluation to accuracy-efficiency co-design at the hardware level**. Prior 4-bit quantization work (OmniQuant, QLLM) operated in an implicit "quantize first, optimize later" paradigm: design an algorithm that minimizes perplexity degradation, then see if it runs fast. Atom inverts this by starting from the GPU's INT4 tensor core capability (1248 TOPS, 4× FP16 throughput) and asking: what algorithmic choices produce acceptable accuracy *while keeping the fused GEMM kernel above the INT8 throughput ceiling*? The paper's roofline analysis (Figure 4) makes this framing explicit and diagnostic—it shows that weight-only quantization's benefits evaporate in the compute-bound regime, and that weight-activation quantization's benefits only materialize if the per-group dequantization overhead stays below the gap between INT4 and INT8 peak throughput.

This reframes the research landscape in three specific ways:

**First, it resolves the apparent contradiction between weight-only and weight-activation quantization research communities.** Weight-only methods (GPTQ, AWQ, SqueezeLLM) demonstrated impressive compression ratios and acceptable accuracy for single-query inference, while weight-activation methods (SmoothQuant, LLM.INT8()) promised higher throughput via tensor core utilization but struggled to reach 4-bit precision. The contradiction dissolves when you recognize they optimize for different operational regimes: weight-only targets the memory-bound regime (small batches, latency-constrained inference), while weight-activation targets the compute-bound regime (large batches, throughput-oriented serving). Neither is universally superior—they are solutions to different problems that prior work had conflated. Atom does not replace weight-only quantization; it defines the boundary at which weight-activation becomes necessary and then provides the first practical system that crosses that boundary at 4 bits.

**Second, it establishes verifier-free, post-training 4-bit weight-activation quantization as viable for the first time**, shifting the accuracy-efficiency Pareto frontier outward. Before Atom, a serving provider choosing quantization had roughly three options: (1) INT8 weight-activation (SmoothQuant) with near-zero accuracy loss but only 2× throughput over FP16, (2) W4A16 weight-only (AWQ) with 4× memory reduction but no dense-layer compute benefit, or (3) 4-bit weight-activation (OmniQuant/QLLM) with the full 4× compute throughput potential but 10–24 percentage points of accuracy loss that made it practically unusable. Atom adds a fourth point to this frontier: 4× compute throughput with 1.4% average accuracy loss on Llama-65B (Table 1), effectively capturing the throughput that prior 4-bit methods left on the table. This is not an incremental refinement—it is a qualitatively new operating point that makes INT4 weight-activation quantization practically deployable for the first time.

**Third, it redirects research attention from better rounding algorithms to better outlier handling and kernel fusion.** The ablation study in Table 3 provides a clear decomposition: mixed-precision outlier separation contributes ~2300 perplexity points of improvement, group quantization contributes ~5 points, and clipping + GPTQ together contribute less than 0.2 points. The implication is stark: for pushing to even lower bit-widths (INT3, INT2), further improvements to rounding algorithms or learned transformations will yield diminishing returns compared to better outlier identification and isolation strategies. The paper's finding that INT3 quantization still loses 10–13 percentage points of zero-shot accuracy (Table 1) despite Atom's best techniques suggests that the next breakthrough will require fundamentally new approaches to the outlier problem—perhaps dynamic per-input outlier selection, learned outlier thresholds, or architectural modifications that reduce outlier emergence during training—rather than incremental refinements to the quantization formula.

The paper's hardware-first design philosophy—fusing quantization operators into memory-bound kernels, reordering channels to avoid irregular memory access, choosing symmetric quantization for compute-bound operations and asymmetric for memory-bound—also establishes a **methodological template** for future quantization systems work. The specific techniques (channel reordering, fused GEMM, FlashInfer integration) are implementation details; the design principle of moving complexity to where the hardware has spare capacity is transferable to new hardware architectures, new model architectures, and new precision formats.

### Follow-Up Research This Work Enables

**Dynamic outlier identification at inference time, rather than static calibration-based selection.** Atom identifies outlier channels once during offline calibration using 128 WikiText2 sentences, then fixes this selection for all future inputs. The paper acknowledges that this choice is inherited from prior work and does not evaluate its robustness to distribution shift. A natural follow-up would replace the static outlier mask with a lightweight, online mechanism that selects which channels to preserve in INT8 based on the actual activation values for each input. The challenge is that dynamic outlier selection requires reordering the activation matrix *and* the corresponding weight matrix rows on-the-fly—the weight reordering in Atom is static because it's done offline. A strong follow-up would design a "soft" mixed-precision scheme where outliers are not physically reordered but handled via a per-channel precision mask that the GEMM kernel can apply without breaking dense memory access patterns. The evaluation would stress-test this against domain shift: calibrate on WikiText2, evaluate on CodeParrot or PubMed abstracts, and measure whether dynamic selection recovers accuracy that static selection loses. The paper's FP4 results (Table 4, comparable accuracy to INT4) suggest that the per-group dynamic scaling already provides some robustness to distribution shift within the normal channels; adding dynamic outlier selection would address the between-channel distribution shift that static selection cannot handle.

**Combining Atom's weight-activation quantization with speculative decoding to push the throughput frontier further.** Speculative decoding uses a small "draft" model to generate candidate tokens that a large "target" model verifies in parallel, increasing throughput when the draft model's predictions are accurate. Atom already demonstrates that a quantized large model can serve at much higher throughput than its FP16 counterpart; a natural extension would pair a quantized target model (Atom W4A4 on Llama-65B) with an unquantized or differently-quantized draft model (e.g., a small FP16 model or an Atom W4A4 Llama-7B). The research question is whether the quantization error in the target model's verification step—where the quantized model scores candidate tokens produced by the draft model—affects the acceptance rate of draft tokens. If the quantized target model's probability distribution differs from the FP16 target's, it might reject draft tokens that the FP16 model would accept, reducing the throughput gain from speculation. The evaluation would measure end-to-end throughput (tokens/second) for the quantized speculative system versus the FP16 speculative system at the same latency target, using the ShareGPT workload from the paper. The finding would quantify whether quantization and speculative decoding are complementary (their throughput gains multiply) or partially redundant (quantization error reduces speculation's benefit).

**Quantization-aware KV-cache eviction policies that exploit Atom's finding that the V cache is easier to quantize than K.** The paper argues (Section 4.4) that the K cache's quantization errors are dampened by softmax normalization, while the V cache exhibits fewer outliers and can be quantized directly. This asymmetry suggests a possible design: when GPU memory is constrained, rather than evicting KV-cache entries uniformly (as in H2O or StreamLLM), an eviction policy could preferentially evict K vectors (keeping V vectors) or use different quantization precisions for K and V (e.g., K at INT4, V at INT2). The research question is whether the structural robustness of K to quantization error (via softmax dampening) means that K can also tolerate more aggressive *eviction* (i.e., dropping K vectors entirely for distant tokens) without degrading attention quality. A strong follow-up would implement a KV-cache manager that allocates a lower bit-width or higher eviction rate to K versus V, integrate it with Atom's fused FlashInfer kernel, and measure the accuracy-throughput Pareto frontier on long-context benchmarks (e.g., LongBench, ZeroSCROLLS) compared to uniform quantization and uniform eviction baselines. This would extend Atom's KV-cache quantization from a fixed compression scheme to an adaptive memory management policy.

**Scaling the group size with model dimension to understand the accuracy-efficiency trade-off as models grow.** Atom fixes the group size at 128 for all model sizes from 7B to 65B. But as models grow, the hidden dimension increases (from 4096 at 7B to 8192 at 65B for Llama), meaning that the ratio of groups per channel changes: at 7B with dimension 4096, there are 32 groups of 128 per channel; at 65B with dimension 8192, there are 64 groups. Larger models might tolerate larger group sizes (coarser quantization) because their increased representational capacity can absorb the additional error, which would improve throughput by reducing per-group dequantization overhead. Conversely, larger models might *require* smaller group sizes to maintain accuracy because the dynamic range within each channel grows with dimension. The research question is whether the optimal group size scales with model dimension, and if so, whether a dimension-aware group sizing policy can improve the accuracy-efficiency Pareto frontier. The experiment would sweep group sizes (32, 64, 128, 256) for Llama models at 7B, 13B, 30B, and 65B, measuring both WikiText2 perplexity and fused GEMM throughput at each configuration, then fit a scaling law relating optimal group size to hidden dimension. This would provide practical guidance for practitioners quantizing models at scales beyond those evaluated in the paper.

**End-to-end evaluation of Atom on production-scale hardware (8×A100 or 8×H100) with tensor parallelism to validate the simulated large-batch throughput claims.** The paper's headline 7.73× throughput improvement is simulated at batch size 256 on an RTX 4090, with the simulation reusing KV-caches from smaller batches. While the kernel-level profiling validates the fused GEMM speedup independently, the end-to-end serving framework includes overhead from continuous batching scheduling, PageAttention memory management, and pipeline bubbles between operators that kernel benchmarks exclude. A direct follow-up would deploy Atom on a production-grade GPU cluster (e.g., 8×A100 80GB with tensor parallelism) serving Llama-65B, measure exact end-to-end throughput and latency distributions (including P95 and P99 tail latency) under the same ShareGPT workload, and compare to the paper's simulated results. The evaluation would also measure the throughput impact of the 4-hour offline quantization cost amortized over the model's serving lifetime, providing a total-cost-of-ownership comparison against FP16 and INT8 baselines. This would either validate the paper's simulation methodology (strengthening the claims) or reveal gaps (identifying where the simulation is optimistic and bounding the real-world throughput improvement).

### Practical Applications and Downstream Use Cases

**Cost reduction for LLM API providers serving high-volume, latency-tolerant workloads.** The paper's fixed-memory comparison (Figure 10c) shows that Atom achieves 7.73× the throughput of FP16 on equivalent GPU hardware. For an LLM API provider serving millions of requests daily—where GPU rental or depreciation dominates operational costs—this directly translates to serving the same request volume with ~7.7× fewer GPUs, or serving ~7.7× more requests with the same GPU fleet. The accuracy cost (1.4% average zero-shot accuracy drop on Llama-65B) is small enough that most applications would accept it in exchange for the cost reduction. Concrete scenario: a provider currently serving Llama-65B in FP16 on 100 A100 GPUs could redeploy with Atom W4A4 on approximately 13 GPUs at the same throughput, reducing GPU costs by ~87% (ignoring the fixed costs of infrastructure and engineering). The 4-hour one-time quantization cost per model is amortized over the model's deployment lifetime and is negligible compared to ongoing serving costs.

**Enabling larger-batch, higher-throughput serving of large models on edge or private cloud deployments with limited GPU memory.** The paper shows (Figure 10c) that Atom's memory reduction from 4-bit weights and KV-cache enables larger batch sizes within the same GPU memory budget, which is critical for deployments where adding GPUs is not an option—on-premise enterprise deployments, edge inference nodes, or research labs with fixed hardware. A 24GB RTX 4090 running FP16 Llama-7B can serve perhaps 32 concurrent requests before exhausting memory; with Atom W4A4, the same GPU can serve 128+ concurrent requests while maintaining latency below 100ms (Figure 10b), effectively quadrupling the number of users a single edge node can support. This is particularly relevant for privacy-sensitive applications (healthcare, legal, finance) where data cannot leave the organization's infrastructure, and GPU capacity is a hard constraint.

**Reducing the KV-cache memory bottleneck for long-context serving applications.** As LLM context windows expand (from 4K tokens in Llama-1 to 128K+ in recent models), the KV-cache becomes the dominant memory consumer—a 128K context with Llama-65B's architecture requires approximately 128K × 2 (K+V) × 8192 (dimension) × 80 (layers) × 2 bytes (FP16) ≈ 320GB of KV-cache memory for a *single request*, far exceeding any single GPU's capacity. Atom's 4-bit KV-cache quantization reduces this to ~80GB per request, making long-context serving feasible on an 8×A100 (80GB) node with tensor parallelism. While the paper evaluates only up to Llama-65B on standard-context benchmarks, the KV-cache quantization technique (Section 4.4) is architecturally independent of the activation quantization and could be adopted by serving systems targeting long-context models (e.g., Llama-3 with 128K context, Claude with 200K context). The paper's finding that KV-cache quantization adds only 0.12 perplexity (Table 3) while providing 4× memory reduction makes this a low-risk, high-impact optimization for long-context serving.

### When to Prefer This Method

The paper does not explicitly frame Atom against a named set of alternative serving strategies with clear decision boundaries (e.g., "use Atom when X, use SmoothQuant when Y"). However, the roofline analysis in Figure 4 and the throughput results in Figure 10 implicitly establish a decision framework based on the operational regime. The key variable is whether the dense layers in the serving scenario are compute-bound (large batch sizes) or memory-bound (small batch sizes). Atom's weight-activation quantization provides throughput benefits primarily in the compute-bound regime, while weight-only quantization is competitive (and simpler to implement) in the memory-bound regime. A practitioner can determine which regime they are in by profiling their serving workload's arithmetic intensity—the ratio of FLOPs to bytes of memory traffic for the dense layer GEMMs—and comparing it to their GPU's roofline inflection point. If the measured arithmetic intensity exceeds the GPU's FP16 ridge point, the workload is compute-bound, and Atom's INT4 tensor core advantage will translate to throughput gains. If it falls below the ridge point, the workload is memory-bound, and weight-only quantization may be sufficient.
