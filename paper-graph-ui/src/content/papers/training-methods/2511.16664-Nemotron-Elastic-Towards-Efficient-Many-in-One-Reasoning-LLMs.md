# Nemotron Elastic: Towards Efficient Many-in-One Reasoning LLMs

**ArXiv:** [2511.16664](https://arxiv.org/abs/2511.16664)

## 🎯 Pitch

You can embed multiple smaller reasoning models inside one large model and extract them for free—no fine-tuning needed. The authors achieve this with a 360× cost reduction over training separate models, but only after discovering that standard training utterly breaks the largest submodel’s accuracy unless you do a second stage with long contexts and a sampling bias toward it.

---

## 1. Executive Summary

This paper introduces **Nemotron Elastic**, a framework for training hybrid Mamba-Attention reasoning LLMs that embed multiple nested submodels within a single parent model, each extractable zero-shot without additional fine-tuning. Applied to the Nemotron Nano V2 12B reasoning model, the framework simultaneously produces 9B and 6B variants using only 110B training tokens — a 360× cost reduction versus training model families from scratch and a ~7× reduction over state-of-the-art sequential compression — through an end-to-end trained router (selecting component masks per budget), a two-stage training curriculum (short-context router stabilization followed by extended-context reasoning adaptation at 49K token sequence length), importance-based depth ranking via normalized MSE, frozen-teacher knowledge distillation, and group-aware SSM elastification that preserves Mamba’s structural constraints. The resulting nested models achieve competitive or superior reasoning accuracy (e.g., 77.41 average across MATH-500, AIME-2024, AIME-2025, GPQA, LiveCodeBench v5, and MMLU-Pro for the 12B elastic variant versus 77.38 for the independently trained baseline) while maintaining constant deployment memory against the number of models in the family, establishing that elastic reasoning models can match independently trained counterparts only when extended-context training — specifically, a second stage with non-uniform budget sampling biased toward the full model — is incorporated to prevent the accuracy degradation that uniform sampling causes in larger variants.

## 2. Context and Motivation

### The Core Problem: Training Model Families Is Prohibitively Expensive

The fundamental challenge this paper addresses is the **economic infeasibility of training LLM families at multiple scales**. Modern LLM ecosystems — exemplified by the Llama-3.1 family spanning 8B, 70B, and 405B parameters — require independent training runs for each model size, with each run consuming trillions of tokens on thousands of GPUs. If an organization wants to serve a diverse set of deployment scenarios — from edge devices with tight memory constraints to datacenter-scale inference with generous latency budgets — they must either train multiple models from scratch (multiplying infrastructure costs linearly with the number of target sizes) or deploy a single over-provisioned model that wastes resources on simpler tasks.

This economic barrier has real consequences. It means that only the largest organizations can afford to build comprehensive model families, concentrating the benefits of LLM deployment among well-resourced actors. It also means that practitioners are forced into difficult tradeoffs: deploy a small model that runs efficiently but lacks capability on complex tasks, or deploy a large model that handles all tasks but incurs unnecessary cost on simple queries.

The paper motivates this concretely through cost numbers (Tables 2 and 3, derived from the Nano V2 training pipeline [nano2025efficient]): training the 12B Nemotron Nano V2 from scratch requires approximately **39.5 trillion tokens** for the base model alone, with pretraining costs that scale as:

$$X = 6ND_{\text{pretrain}}$$

where $N$ is the parameter count and $D_{\text{pretrain}}$ is the number of training tokens. Adding a 9B and 6B variant trained from scratch would triple this baseline cost. This is the fundamental economics problem: **parameter count diversity has linear cost, but deployment needs are diverse**.

### The Concurrent Rise of Two Trends This Paper Unifies

The paper is motivated by the convergence of two recent developments that create a tension not addressed by prior work:

**Trend 1: Hybrid Mamba-Attention architectures.** The emergence of hybrid architectures combining attention with State Space Models (SSMs) — specifically Mamba-2 [gu2023mamba, dao2024transformers] — has produced models like Jamba [lieber2024jamba], Zamba [glorioso2024zamba], and Nemotron-H [blakeman2025nemotron] that achieve superior efficiency through reduced KV cache requirements and linear-time sequence processing. Nemotron-H, for instance, replaces 92% of attention layers with Mamba-2 blocks, achieving a $3\times$ inference speedup. These architectures are attractive for deployment, but their compression and elastification is fundamentally harder than standard Transformer compression because Mamba layers have **structural constraints** that must be preserved: heads within Mamba groups share channel configurations, SSM state dimensions must remain consistent, and naive pruning can break the group-aware structure that enables efficient state-space computation.

**Trend 2: Reasoning models with extended chains of thought.** The transition from base/instruct-tuned models to reasoning-capable LLMs that generate extended intermediate reasoning traces (chain-of-thought) introduces a **fundamentally different training requirement** not present in standard LLM compression. Reasoning models need to process sequences of 32K-128K tokens during multi-step inference, where the model generates hundreds to thousands of intermediate tokens before producing a final answer. This means that elastic compression for reasoning models cannot simply optimize for short-context perplexity or standard downstream accuracy — it must ensure that compressed sub-networks maintain coherence and performance across extended contexts where reasoning paths unfold.

The paper argues that **existing compression techniques fail to address this dual requirement**: they neither support elastic deployment across diverse constraints (producing one compressed model per target size through separate distillation runs) nor optimize for the long-context reasoning scenarios critical to reasoning model performance.

### Where Prior Approaches Fall Short

The paper identifies specific limitations across three categories of related work:

#### Category 1: Structured Pruning and Knowledge Distillation (Minitron-style compression)

Recent advances in model compression combine structured pruning with knowledge distillation to derive smaller models from a large pre-trained parent [muralidharan2024compact, taghibakhshi2025minitron, xia2023sheared]. The Minitron family [muralidharan2024compact] and its SSM-extended variant Minitron-SSM [taghibakhshi2025minitron] are the most directly comparable baselines in this paper. These methods work in a **sequential, two-phase pipeline**:

1. **Exploratory search phase:** The parent model's layers and components are scored via importance metrics (activation magnitude, Taylor decomposition). Candidate architectures are pruned and briefly distilled with limited tokens (~25-75B per candidate) to evaluate which configuration performs best at each target size.
2. **Final distillation phase:** The best architecture from the exploratory phase is selected, and full knowledge distillation is performed to recover accuracy, typically requiring hundreds of billions of tokens.

**Where this falls short (Section 4 and Tables 2-3):**

- **Cost scales linearly with family size.** If you want $n$ model sizes, you need $n \times (\text{Tokens}_{\text{explore}} + \text{Tokens}_{\text{KD}})$ training tokens. The exploratory runs alone are expensive (Table 2): Minitron-SSM requires approximately **380B tokens** to derive the 9B variant and another **380B tokens** for the 6B variant, yielding ~760B total tokens. This paper's approach requires only **110B tokens** for all three models simultaneously — a $7\times$ reduction.
- **Static architecture search.** The exploratory phase uses importance scores computed on the **frozen pre-trained checkpoint**, which means architecture decisions are decoupled from the training objective that will be used during final distillation. The architecture is fixed before training begins, with no ability to adapt to the loss landscape discovered during distillation.
- **No support for heterogeneous layer-wise configurations.** Minitron and Minitron-SSM prune all layers of a given type uniformly (e.g., all attention layers retain the same number of heads). This paper argues (Section 2, Heterogeneous Elastification) that allowing different layers to have different compression ratios — for instance, retaining more FFN neurons in middle layers where representational capacity matters most — can yield more optimal configurations, but prior methods cannot explore this.
- **No nested weight-sharing.** Each compressed model is a separate artifact requiring independent storage and management. Deploying all three sizes (12B, 9B, 6B) requires cumulative memory: ~24 GB + ~18 GB + ~12 GB = ~54 GB (Table 3). The elastic approach with nested weight-sharing requires only ~26 GB total because all variants share the same parameter space with only routing metadata differentiating them.
- **Transformers only (Minitron) or limited SSM support (Minitron-SSM).** The original Minitron only handles standard Transformer architectures. Minitron-SSM extends to hybrid models but still requires separate distillation per target size. Neither addresses reasoning-specific training requirements.

#### Category 2: Elastic and Matryoshka-style Nested Networks

Elastic or nested architectures — where multiple sub-networks are embedded within a single parent model through weight-sharing — have been explored in MatFormer [kudugunta2023matformer], Flextron [cai2024flextron], and MatMamba [shukla2024matmambamatryoshkastatespace]. These methods produce models with the property that sub-networks can be extracted zero-shot without additional training.

**Where this falls short (Section 4):**

- **No support for hybrid Mamba-Attention architectures.** MatFormer and Flextron are designed for pure Transformer architectures. The paper states explicitly: "MatFormer and Flextron... do not support: (1) hybrid Mamba-Attention architectures." MatMamba extends the nested concept to Mamba layers but does so for pure-SSM models, not hybrid architectures where the interaction between Mamba and attention components creates additional complexity for architecture search. The paper's contribution is the first to handle both component types simultaneously with a unified elastic formulation.
- **No reasoning-focused training with extended context.** Prior elastic methods train on standard language modeling objectives with typical sequence lengths (2K-8K tokens). The paper demonstrates empirically (Section 3.3, Table 4) that this is insufficient for reasoning models — extended-context training at 49K tokens is **critical** for preserving reasoning performance in compressed variants, with the 6B variant gaining +19.8% on AIME-2025 from the extended-context stage alone.
- **No heterogeneous layer-wise architecture selection via end-to-end learned routing.** MatFormer uses post-hoc MixnMatch heuristics for sub-network selection — at deployment, a candidate sub-network is assembled based on generic heuristics rather than being learned during training. Flextron adds input-adaptive routing, but only for attention and MLP dimensions within Transformer blocks, and still uses heuristics rather than gradient-based optimization. This paper introduces dedicated router networks trained end-to-end alongside the model (Section 2.3.1), enabling learned architecture decisions that respond to the actual training signal rather than post-hoc search. The heterogeneous extension (Equation 10, Section 2.3.1) allows each layer to independently select its compression ratio, enabling per-layer configuration diversity (e.g., layer 5 retains 40% of FFN neurons while layer 15 retains 70%) that prior methods cannot explore.
- **No distillation-guided elastification.** Prior elastic methods typically train the nested sub-networks on the standard language modeling objective (cross-entropy loss against the corpus). This paper introduces frozen-teacher knowledge distillation during elastic training (Section 2.3.3, Equation 16), where the original pre-trained full model provides stable supervision signals that guide the compressed variants toward behavior more closely aligned with the parent model. This is not merely an engineering detail — it enables simultaneous multi-budget optimization where all sub-networks benefit from the teacher's representations rather than competing through independent cross-entropy signals.

#### Category 3: Reasoning Model Training Methods

Prior work on building reasoning-capable LLMs focuses on prompting strategies (chain-of-thought [wei2022chain], tree-of-thought [yao2023tree]) or reinforcement learning from reasoning traces [lightman2023lets]. These methods improve reasoning capability but do not address the **architectural efficiency** or **elastic deployment** of reasoning models.

**Where this falls short:**

- **No architectural compression for reasoning models.** The paper states (Section 4): "Prior work on reasoning model optimization focuses on prompting strategies or reinforcement learning from reasoning traces, but does not address architectural efficiency or elastic deployment." The literature on compressing reasoning models is essentially nonexistent — prior compression work has been validated only on base or instruct-tuned models that do not generate extended reasoning traces.
- **No recognition that reasoning models have fundamentally different compression requirements.** The paper's key empirical finding (Section 3.3) is that standard compression approaches — specifically, single-stage training with uniform budget sampling — **fail** on reasoning models. When uniform sampling is used during extended-context training, the full 12B model's accuracy **degrades** while the smaller variants improve, indicating negative transfer. This does not occur in standard LLM compression (where uniform sampling works well), making it a reasoning-specific phenomenon that prior work could not have identified.
- **No support for extended-context adaptation during compression.** Reasoning models generate thousands of intermediate tokens, requiring the compressed variants to remain coherent across sequences much longer than standard training contexts. This paper's two-stage curriculum (Stage 1: 8K token sequences for router stabilization, Stage 2: 49K token sequences for reasoning adaptation) directly addresses this gap — a constraint that does not appear in prior work on either compression or reasoning model training.

### How This Paper Positions Itself

The paper positions Nemotron Elastic as a framework that **unifies and extends** prior work across multiple dimensions simultaneously. The key positioning claims are:

**1. Elastic compression + hybrid architectures.** This is the first work to support nested weight-sharing for hybrid Mamba-Attention models, requiring group-aware SSM masking (Section 2.4.2, Equations 22-25) that preserves Mamba's structural constraints while enabling width and depth elasticity across both component types. Prior elastic methods handle either Transformers (MatFormer, Flextron) or pure SSMs (MatMamba) but not their combination. Prior hybrid compression (Minitron-SSM) lacks nested weight-sharing, requiring separate distillation per target size.

**2. Elastic compression + reasoning models.** This is the first work to apply elastic training to reasoning-capable LLMs, introducing a two-stage curriculum (Section 2.3.5) specifically designed for the extended-context requirements of reasoning tasks. The paper explicitly argues that "reasoning models require fundamentally different elastic training strategies compared to standard LLMs" (Section 1), positioning the extended-context stage not as an optional enhancement but as a **necessary condition** for competitive reasoning performance in compressed variants.

**3. End-to-end learned routing + importance-based initialization.** The router networks (Section 2.3.1) are trained end-to-end alongside the model parameters, receiving gradients from the task loss (cross-entropy or distillation). This is a departure from prior methods that decouple architecture search from training: Minitron computes importance scores on frozen checkpoints before distillation begins; MatFormer uses fixed heuristics at deployment time. The paper's router can **dynamically adapt** configurations during training as the loss landscape evolves, and the importance-based rankings (Section 2.1) serve only as a **preference ordering** (Equation 49) that constrains which components the router selects, not a rigid pre-determined architecture.

**4. Heterogeneous layer-wise elastification.** The paper extends elastic architectures to support per-layer heterogeneity (Equations 10 and 49 in heterogeneous mode), where each Mamba layer, attention layer, and FFN layer can independently select its compression ratio. This enables more granular exploration of the architecture space — for instance, retaining more capacity in critical middle layers while aggressively compressing input and output layers — that prior homogeneous methods (where all layers of a type share the same ratio) cannot access.

**5. Frozen-teacher distillation for multi-budget optimization.** The use of the original pre-trained model as a frozen teacher (Equation 16) during elastic training is positioned as a stability mechanism that enables simultaneous optimization of all sub-networks. Unlike a trainable teacher (Equation 15), which moves as the student learns and can introduce training instability across budgets, the frozen teacher provides consistent distillation targets that all budget variants can align to. This is particularly important in the multi-budget setting where the full model (12B) is simultaneously both a student learning from the frozen teacher and a candidate deployment artifact — without frozen distillation, the full model's training signal would be diluted by the gradient competition from smaller variants.

The paper's overarching framing is that prior work on model compression, elastic architectures, and reasoning models has progressed along **separate trajectories**, and that the **intersection** of these trajectories — hybrid elastic reasoning models — represents a gap with outsized practical importance given the simultaneous industry trends toward hybrid architectures and reasoning-capable deployment. The paper fills this gap by building on the weight-sharing concept from MatFormer/Flextron, extending it to hybrid SSM-Attention models with group-aware constraints, adding end-to-end routing to replace post-hoc heuristics, introducing extended-context reasoning adaptation through two-stage curriculum training, and using frozen-teacher distillation to stabilize multi-budget optimization — all validated on a real reasoning model benchmark suite that includes competition-level mathematics (AIME) and graduate-level science (GPQA) that prior compression work has not targeted.

## 3. Technical Approach

### 3.1 Reader Orientation

What is being built is a **single training run** that produces multiple complete LLMs at different sizes — all sharing weights — from which you can extract any size variant at deployment time without additional training. The problem it solves is that training a family of reasoning models at multiple scales (e.g., 12B, 9B, 6B) currently requires either independent full-scale training runs for each size or sequential compression runs that each consume hundreds of billions of tokens, and the solution is to **embed all variants simultaneously within one parent model** through learned, budget-conditioned masking applied across width (neurons, heads, channels) and depth (layers), trained with a two-stage curriculum where extended-context reasoning adaptation prevents the accuracy collapse that naive uniform-sampling elastic training causes in larger models.

### 3.2 Big-Picture Architecture (Diagram in Words)

The system has five major components that interact during a single training pipeline:

1. **The parent hybrid Mamba-Attention model (12B Nemotron Nano V2)** — the largest model whose parameters form the superset from which all smaller sub-networks are carved. It serves simultaneously as the frozen teacher for knowledge distillation and as the full-budget student variant.
2. **Importance estimators** — lightweight, activation-based scoring functions (one forward pass on 1024 calibration samples) that rank every width component (embedding channels, attention heads, FFN neurons, Mamba heads and channels) and every layer by their contribution to model behavior, producing a **preference ordering** that constrains which components the router may select.
3. **Dedicated router networks** (one per dimension: embedding, Mamba, attention heads, FFN, depth) — small two-layer MLPs that take a one-hot budget specification as input and output a Gumbel-Softmax-relaxed selection of which components to retain at that budget, trained end-to-end alongside the model to make architecture decisions that respond to the actual training loss landscape.
4. **Structured masking operators** (`ℳ_emb`, `ℳ_mamba`, `ℳ_attn_head`, `ℳ_ffn`, and depth coefficients `γ`) — dimension-specific binary masks derived from the router's selections that dynamically zero out pruned components during the forward pass based on the importance ranking, enabling a single set of model parameters to simulate multiple nested architectures without architectural recompilation.
5. **Two-stage training curriculum** — Stage 1 (short context, uniform budget sampling, ~65B tokens) stabilizes the router and establishes baseline architecture patterns; Stage 2 (extended context at 49K tokens, non-uniform budget sampling biased toward the full model, ~45B tokens) adapts the compressed variants to maintain coherence across the long sequences needed for multi-step reasoning.

Information flows as follows: a training sample enters → a budget (6B, 9B, or 12B) is selected according to the current stage's sampling distribution → the budget specification (one-hot) is fed to each router → each router produces a Gumbel-Softmax probability distribution over configuration choices → the argmax configuration determines which components are active (via the importance ranking) → binary masks are constructed and applied to the dynamic model's weights and activations → the masked model produces logits → the frozen teacher's logits for the same sample serve as distillation targets → the combined loss (distillation KL divergence + router resource constraint) updates both model parameters and router parameters → the cycle repeats, with routers gradually annealing from soft exploration to sharp selection.

### 3.3 Roadmap for the Deep Dive

- **First**, the importance estimation procedure (Section 2.1) — how component priority rankings are established for width and depth, since every downstream masking decision depends on these rankings.
- **Second**, the elastic formulation (Section 2.2) — the conceptual framework for nested weight-sharing across width and depth dimensions in hybrid architectures, including the structural constraints that Mamba layers impose.
- **Third**, the router architecture and training (Sections 2.3.1–2.3.2) — how dedicated router networks learn to select configurations per budget, the Gumbel-Softmax relaxation, and the router loss function.
- **Fourth**, the loss formulation and distillation strategies (Sections 2.3.3–2.3.4) — how frozen-teacher distillation, trainable-teacher distillation, and cross-entropy are combined for multi-budget optimization, and the joint optimization objective.

#### Importance Estimation and Model Preparation

Component importance guides the router's selection decisions by establishing which elements contribute most to model behavior. The paper uses activation-based importance scoring — requiring only forward propagation on 1024 calibration samples with sequence length 8192 — to rank model components along each elastic dimension, producing a sorted ordering `$\sigma^{(w)}$` for width components and `$\sigma^{(d)}$` for depth that acts as a constraint on the router's search space.

##### Width Importance: Embedding Channels

For embedding channels, importance is computed from normalized input activations aggregated across sequence and batch dimensions:

$$Importance^{(i)}_{\text{emb}} = \sum_{B,L} |\text{LN}(X)|_i$$

where `$\text{LN}(X)$` is the layer-normalized input tensor, `$B$` indexes the batch dimension, `$L$` indexes the sequence length dimension, and `$i$` is the embedding channel index (running from 0 to `$d_e - 1$`, where `$d_e$` is the full embedding dimension).

**What it computes:** for each embedding channel `$i$`, it sums the absolute value of the layer-norm output `$\text{LN}(X)$` across all batch elements and all sequence positions, producing a single scalar score per channel. Channels that receive consistently large-magnitude inputs across tokens are scored higher, indicating they carry more information.

**Why this form:** the `$|\text{LN}(X)|$` aggregation captures activation magnitude after normalization, which reflects how strongly each channel contributes to the representation irrespective of token position. Using the absolute value (rather than the signed value) prevents cancellation artifacts where negative activations in some positions would offset positive ones in others. The summation across batch and sequence dimensions provides a statistically stable estimate (multiplied over 1024 × 8192 data points) with a single forward pass, keeping the importance estimation phase lightweight. The choice of layer-norm output rather than raw embeddings ensures that the scores are comparable across different parts of the network (since layer-norm zero-centers and unit-variances).

The resulting scores are sorted in decreasing order and the sorted indices define the permutation `$\sigma^{(\text{emb})}$`. Downstream, when the router selects `$c$` embedding channels to retain, the top `$c$` channels from this ranking are kept active.

##### Width Importance: FFN Neurons

For feed-forward network intermediate neurons, importance is scored from the output of the first linear layer (the intermediate activations after the up-projection):

$$Importance^{(i)}_{\text{neuron}} = \sum_{B,L} |X(\mathbf{W}_1^i)^T|$$

where `$X$` is the input activation matrix to the FFN layer (shape `$[B, L, d_e]$`), `$\mathbf{W}_1$` is the first weight matrix (shape `$[d_{\text{int}}, d_e]$`), and `$\mathbf{W}_1^i$` is the `$i$`-th row of `$\mathbf{W}_1$` (shape `$[1, d_e]$`), representing the weight vector that projects from the embedding space to the `$i$`-th intermediate neuron.

**What it computes:** for each intermediate neuron `$i$`, it computes the absolute value of the dot product between the input activation `$X$` and the weight row `$\mathbf{W}_1^i$` at every batch element and sequence position, then sums across all positions. This captures the total activation magnitude flowing into neuron `$i$` — neurons with consistently large pre-activation values are considered more important.

**Why this form:** the expression `$X(\mathbf{W}_1^i)^T$` is exactly the pre-activation value before the nonlinearity (typically SiLU or GELU in the actual FFN forward pass). Scoring based on the intermediate activations (rather than the post-nonlinearity output or the second-layer weights) reflects the information bottleneck at the expansion ratio — this is the point where the model projects from `$d_e$` to a larger `$d_{\text{int}}$` and then compresses back, so the importance of each intermediate neuron for reconstruction fidelity is best measured at the bottleneck. Prior work (Minitron) also uses FFN intermediate activations for pruning decisions, and the paper follows this established convention.

Neurons are sorted in decreasing importance order via `$\sigma^{(\text{ffn})}$`.

##### Width Importance: Mamba Components

Mamba layers in the Nemotron architecture (Mamba-2) have internal structure that complicates naive importance scoring. Each Mamba layer has `$m_h$` heads (e.g., 32 heads in the 12B configuration) and each head has `$m_d$` channels (e.g., 64 channels per head). Additionally, Mamba heads are organized into groups `$\mathcal{G}_g$` (Mamba groups), where all heads within a group share certain structural constraints — specifically, the number of active channels must be consistent across all heads in the same group to preserve valid SSM computation. A naive per-neuron importance ranking that ignores this group structure could produce rankings that are structurally invalid (different channel counts per head within a group).

The paper introduces a **nested, group-constrained** importance estimation procedure:

**Step 1: Channel-level scores.** Extract scores from the `$\mathbf{W}_x$` projection matrix output (one of the main projection matrices in Mamba-2, alongside `$\mathbf{W}_z$`, `$\mathbf{W}_B$`, `$\mathbf{W}_C$`, `$\mathbf{W}_{dt}$`). The activation after the `$\mathbf{W}_x$` projection is:

$$\mathbf{s} = \text{LN}(X)(\mathbf{W}_x)^T$$

where `$\mathbf{s}$` has shape `$[B, L, m_h \cdot m_d]$` (the total Mamba dimension, which equals number of heads times channels per head). The per-channel score is the L2 norm of the activation across batch and sequence:

$$s_d = \left\|\sum_{B,L} \mathbf{s}_{:,d}\right\|_2$$

where `$d$` indexes individual channels (from 0 to `$m_h \cdot m_d - 1$`, flattened across all heads). The L2 norm is applied to the sum (not the sum of L2 norms), so channels where the activations align constructively in direction across tokens get higher scores — if activations cancel out across tokens, the vector sum is small and the L2 norm is low.

**Step 2: Head-level scores using top-ranked channels.** The top `$|\mathcal{D}_{\text{top}}|$` channels from Step 1 are identified. Then, for each head `$h$`, the head-level importance is:

$$f_h = \left\|\mathbf{s}_{h, \mathcal{D}_{\text{top}}}\right\|_2, \quad \forall h \in \{1, \ldots, m_h\}$$

where `$\mathbf{s}_{h, \mathcal{D}_{\text{top}}}$` is the subset of activations belonging to head `$h$` and only the top-ranked channels `$\mathcal{D}_{\text{top}}$`. This means head importance is assessed based on the strongest channels overall — the idea is that channels carrying the most signal across all heads define which heads matter most.

**Step 3: Group-constrained ranking.** Rather than producing a single global head ranking (which could violate group structure), the heads are ranked **independently within each Mamba group** `$\mathcal{G}_g$`. If Mamba group `$g$` contains heads `$\{h_{g1}, h_{g2}, \ldots\}$`, the ranking is applied separately within that set, ensuring that when the router later selects to retain `$k\%$` of heads, the retention respects the group boundaries.

**Why this nested procedure:** single-stage importance scoring (ranking all Mamba channels globally or all heads globally) breaks the group-aware constraints. If different heads in the same group have different numbers of active channels, the SSM computation becomes invalid because the structured state-space matrices `$\mathbf{A}, \mathbf{D}$` assume consistent dimensionality within groups. The three-stage approach decomposes the scoring into channel importance (across all heads, capturing which dimensions carry signal), head importance (per-head aggregation using only strong channels), and group-constrained ranking (ensuring structural validity). The use of `$\mathbf{W}_x$` specifically (rather than `$\mathbf{W}_z$` or other projection matrices) follows the insight that `$\mathbf{W}_x$` produces the input to the SSM state update — its activations are the most directly indicative of the information flowing through the state-space computation.

##### Width Importance: Attention Heads

For attention heads, importance is computed from head-wise activation magnitudes aggregated across query projections. The paper states: "For attention heads, importance is computed from head-wise activation magnitudes aggregated across query projections." The scoring is analogous to the Mamba head procedure but simpler: compute the L2 norm of query projection activations per head, then rank in decreasing order. The attention head mask operator `$\mathcal{M}_{\text{attn\_head}}$` (defined in Section 2.4.3) uses this ranking when selecting which heads and which head dimensions (`$d_h$`) to retain. Unlike Mamba heads, attention heads do not have group constraints, so a single global ranking `$\sigma^{(\text{attn})}$` suffices.

##### Depth Importance: Normalized MSE Layer Ranking

Layer importance for depth selection is estimated **iteratively** using the normalized mean squared error (MSE) between the full model's output logits and the logits when a specific layer is ablated (bypassed via residual connection). For each layer `$j$`:

$$s_j = \frac{\sum_{B,L} (\mathcal{M}_{\text{full}} - \mathcal{M}_{-j})^2}{\sum_{B,L} \mathcal{M}_{\text{full}}^2}$$

where `$\mathcal{M}_{\text{full}}$` represents the logits (pre-softmax output activations) from the full model on a calibration batch, and `$\mathcal{M}_{-j}$` represents the logits from the same model with layer `$j$` removed — meaning the residual stream bypasses layer `$j$` entirely, so `$y_{j+1} = y_j$` instead of `$y_{j+1} = y_j + \mathcal{L}_j(y_j)$`. The sums run over batch dimension `$B$` and sequence length `$L$`.

**What it computes:** for each layer `$j$`, it measures how much the model's predictions change when that layer is skipped, normalized by the total energy (sum of squared logits) of the full model's predictions. The numerator is the squared L2 distance between full-model logits and layer-ablated logits, summed over all positions. The denominator is the total squared magnitude of the full model's logits. The ratio `$s_j$` is a unitless number — if `$s_j$` is large (e.g., 0.1), removing layer `$j$` causes predictions to change substantially, indicating the layer is critical for prediction accuracy. If `$s_j$` is small (e.g., 0.001), the layer contributes little to the final output.

**Why this form:** the normalization by `$\sum \mathcal{M}_{\text{full}}^2$` is essential because raw MSE `$\sum (\mathcal{M}_{\text{full}} - \mathcal{M}_{-j})^2$` depends on the scale of the logits, which varies across different calibration datasets. By dividing by the full model's energy, the score becomes dataset-invariant — a layer that causes a 10% change in predictions on one dataset will have `$s_j \approx 0.01$` on both a high-variance and low-variance dataset (the normalization adjusts for scale differences). This enables comparable importance scores across different calibration runs or different models.

The paper contrasts this **iterative normalized MSE** approach with two inferior alternatives:

- **Single-shot perplexity-based methods** (common in prior work like Minitron): compute perplexity increase when each layer is removed individually, then rank by perplexity degradation. This is problematic because perplexity is a noisy metric sensitive to rare tokens, and single-shot removal doesn't account for interactions between layers — two layers might individually be unimportant but jointly critical.
- **Non-iterative methods:** removing a layer changes the residual stream for all subsequent layers, so the importance of later layers computed in a single pass may be distorted by the accumulated shift. The paper's approach computes each `$s_j$` independently (removing only layer `$j$` at a time, with all other layers present), providing a more faithful measure of each layer's contribution in the context of the full network.

The resulting per-layer scores `$\{s_j\}_{j=0}^{N-1}$` are sorted in decreasing order, yielding the depth ranking `$\sigma^{(d)}$`. When the router selects `$L_{\text{target}} < N$` layers to retain, the top `$L_{\text{target}}$` layers from this ranking are kept active via `$\gamma_j = 1$`, and the remaining are bypassed through residual connections.

#### Elastic Formulation

The elastic formulation defines how a single set of model parameters can represent multiple nested architectures at different budgets through structured masking. The key property is **nested weight-sharing**: the parameters of a smaller sub-network form a contiguous subset of the parameters of any larger sub-network, meaning the 6B model's weights are a subset of the 9B model's weights, which are a subset of the 12B model's weights. This is achieved through the importance-based ranking from Section 2.1 — the fixed ordering ensures that when you keep the top `$k$` components, the retained set is always a prefix of the sorted list.

##### Elastic Width

For each width dimension, a set of elastic choices specifies which sizes are available. The dimensions are:

- `$d_e$`: embedding dimension (hidden size, e.g., 5120 for the 12B model)
- `$d_f$`: FFN intermediate dimension (e.g., 14336 for the 12B model)
- `$n_h$`: number of attention heads (e.g., 32 for the 12B model)
- `$m_h$`: number of Mamba heads
- `$m_d$`: Mamba head channel dimension (channels per head)

At training time, for a given target budget `$B$` (e.g., 6B parameters), the router selects specific values `$(d_e^B, d_f^B, n_h^B, m_h^B, m_d^B)$` that satisfy the total parameter budget constraint for `$B$`. The nested structure ensures that if budget `$B_1 < B_2$`, then `$d_f^{B_1} \leq d_f^{B_2}$` component-wise — the smaller budget always uses a subset of the larger budget's active components, never a different set. This is enforced by the importance ranking: the router selects the number of components `$c$` to retain, and the top `$c$` from the fixed ranking are always kept, guaranteeing nesting.

The masking operators that implement this at the parameter level are:
- `$\mathcal{M}_{\text{emb}}$` for embedding channels (Section 2.4.2, Equation 23)
- `$\mathcal{M}_{\text{ffn}}$` for FFN intermediate neurons (Section 2.4.4, Equation 42)
- `$\mathcal{M}_{\text{attn\_head}}$` for attention heads and head dimensions (Section 2.4.3, Equation 34)
- `$\mathcal{M}_{\text{mamba}}$` for Mamba heads and head channels with group-aware constraints (Section 2.4.2, Equation 24–25)

These are defined in detail in the Implementation section below.

##### Elastic Depth

Depth elasticity is controlled through a binary selection vector:

$$\boldsymbol{\gamma}^B = [\gamma_0^B, \gamma_1^B, \ldots, \gamma_{N-1}^B]$$

where `$N$` is the total number of layers in the full model, `$B$` is the target budget, and `$\gamma_j^B \in \{0, 1\}$`. If `$\gamma_j^B = 1$`, layer `$j$` is active and its computation is performed. If `$\gamma_j^B = 0$`, layer `$j$` is bypassed via the residual connection:

$$y_{j+1} = y_j + \mathcal{D} \circ \mathcal{L}_j(y_j) \quad \text{if } \gamma_j^B = 1$$
$$y_{j+1} = y_j \quad \text{if } \gamma_j^B = 0$$

where `$\mathcal{D} \circ \mathcal{L}_j$` is the dynamically masked layer (width-corrected). The importance-based layer ranking `$\sigma^{(d)}$` ensures that when `$L_{\text{target}} < N$` layers are retained, the `$L_{\text{target}}$` most important layers (those with highest normalized MSE from Equation 5) are preferentially kept active.

**Why this form over removing layers entirely:** bypassing with residual connections (rather than physically deleting layers) maintains gradient flow through all layers — even skipped layers still exist in the parameter graph (their weights exist but aren't used in the forward pass), enabling them to potentially be reactivated at a different budget without weight re-initialization. This is critical for multi-budget training because the same set of parameters must serve all budgets: layer `$j$` might be active at budget 12B but inactive at budget 6B, and the weights must be preserved for when the 12B budget is sampled in subsequent training iterations.

##### Hybrid Architecture Considerations

For hybrid models combining Mamba and attention layers, the elastic formulation must respect the structural constraints of both component types:

- **Mamba constraints:** The group-aware structure requires that channels are pruned consistently across all heads within the same Mamba group. The `$\mathcal{M}_{\text{mamba}}$` operator (Equation 25) enforces this: for heads `$h, h'$` belonging to group `$\mathcal{G}_g$`, the channel mask is identical, meaning `$\mathbf{I}_m[\phi(h, \cdot)] = \mathbf{I}_m[\phi(h', \cdot)]$`. Additionally, the SSM state dimension `$d_s$` and group count `$g$` are structural parameters that are not elastified (they are kept at fixed values).

- **Attention constraints:** Attention heads can be pruned independently without group constraints, but the head dimension `$d_h$` (the internal dimension of query/key/value projections within each head) should be kept consistent across active heads. The `$\mathcal{M}_{\text{attn\_head}}$` operator (Equation 35) retains the first `$n^*$` heads and within each head the first `$d^*$` dimensions.

The router jointly optimizes selections across both layer types and all width dimensions, meaning it can discover configurations where, for instance, a 9B model retains proportionally more Mamba capacity and less attention capacity (or vice versa), depending on which combination best preserves task performance at that budget.

#### Router Architecture and Training

##### Router Architecture

For each elastic dimension `$k \in \{\text{emb}, \text{mamba}, \text{attn\_head}, \text{ffn}, \text{depth}\}$`, a dedicated router network performs architecture search over the target configuration space. Each router is a two-layer MLP with leaky ReLU activation:

**Input representation:** The input to router `$k$` is a one-hot encoded vector representing the target budget:

$$\mathbf{u}^{(k)} = \mathbf{e}_\ell \in \mathbb{R}^{n_{\text{targets}}}$$

where `$\mathbf{e}_\ell$` is the `$\ell$`-th standard basis vector (all zeros except a 1 at index `$\ell$`), `$\ell$` indexes the target budget (e.g., `$\ell=0$` for 6B, `$\ell=1$` for 9B, `$\ell=2$` for 12B), and `$n_{\text{targets}}$` is the number of target budgets (3 in this paper: 6B, 9B, 12B).

**Hidden layer:**

$$\mathbf{h}^{(k)} = \text{LeakyReLU}\left(\mathbf{W}_1^{(k)} \mathbf{u}^{(k)} + \mathbf{b}_1^{(k)}\right)$$

where `$\mathbf{W}_1^{(k)} \in \mathbb{R}^{d_{\text{router}} \times n_{\text{targets}}}$` is the first layer weight matrix, `$\mathbf{b}_1^{(k)} \in \mathbb{R}^{d_{\text{router}}}$` is the first layer bias, `$d_{\text{router}} = 256$` is the intermediate hidden dimension (shared across all routers), and LeakyReLU applies the nonlinearity `$\max(0.01x, x)$`. The 256-dimensional hidden size is small relative to the model's parameter count (12B), keeping router overhead to under 2% of total memory.

**Output layer:**

$$\mathbf{z}^{(k)} = \mathbf{W}_2^{(k)} \mathbf{h}^{(k)} + \mathbf{b}_2^{(k)}$$

where `$\mathbf{W}_2^{(k)} \in \mathbb{R}^{n_{\text{out}}^{(k)} \times d_{\text{router}}}$`, `$\mathbf{b}_2^{(k)} \in \mathbb{R}^{n_{\text{out}}^{(k)}}$`, and `$n_{\text{out}}^{(k)}$` is the output dimension that depends on the dimension `$k$` and whether the router operates in homogeneous or heterogeneous mode.

**Router output dimensions — homogeneous mode:** In homogeneous mode, all instances of a component type share the same compression ratio. For example, all attention layers retain the same number of heads. The output dimensions are:

$$n_{\text{out}}^{(\text{emb})} = |\mathcal{E}|$$
$$n_{\text{out}}^{(\text{mamba,hom})} = |\mathcal{M}|$$
$$n_{\text{out}}^{(\text{attn,hom})} = |\mathcal{A}|$$
$$n_{\text{out}}^{(\text{ffn,hom})} = |\mathcal{F}|$$
$$n_{\text{out}}^{(\text{depth})} = N$$

where `$|\mathcal{E}|$` is the number of candidate embedding dimension sizes (e.g., 2560, 3072, 4096, 5120), `$|\mathcal{M}|$` is the number of candidate Mamba configurations, `$|\mathcal{A}|$` is the number of candidate attention head counts, `$|\mathcal{F}|$` is the number of candidate FFN intermediate dimensions, and `$N$` is the total number of layers (so each possible depth from 1 to `$N$` is a candidate). The router produces a logit per candidate, and the Gumbel-Softmax (Equation 11) selects one.

**Router output dimensions — heterogeneous mode:** In heterogeneous mode, each layer can independently select its compression ratio:

$$n_{\text{out}}^{(\text{mamba,het})} = |\mathcal{M}| \times N_{\text{M}}$$
$$n_{\text{out}}^{(\text{attn,het})} = |\mathcal{A}| \times N_{\text{A}}$$
$$n_{\text{out}}^{(\text{ffn,het})} = |\mathcal{F}| \times N_{\text{F}}$$

where `$N_{\text{M}}$`, `$N_{\text{A}}$`, `$N_{\text{F}}$` are the counts of Mamba, attention, and FFN layers respectively. For example, if `$|\mathcal{F}| = 4$` candidate FFN sizes and `$N_{\text{F}} = 40$` FFN layers, the heterogeneous FFN router outputs 160 logits — 4 candidate sizes × 40 layers, allowing each layer's FFN to be independently sized. Embedding remains homogeneous because embedding channels are globally indexed (there's only one embedding matrix, not per-layer embeddings).

**Why dedicated routers per dimension:** having separate routers for each dimension (rather than one monolithic router outputting all decisions jointly) decomposes the exponential search space (the product of all configuration choices across dimensions) into independent searches per dimension, each tractable because the number of candidates per dimension is linear in that dimension's range. A joint router would need to output `$|\mathcal{E}| \times |\mathcal{M}| \times |\mathcal{A}| \times |\mathcal{F}| \times N$` logits, which is combinatorially large and infeasible to train. The decomposition assumes approximate independence between dimensions — the embedding size does not strongly interact with the attention head count for architecture quality — which is a standard assumption in structured pruning literature and is validated by the paper's strong downstream results.

##### Gumbel-Softmax Relaxation

The router outputs `$\mathbf{z}^{(k)}$` are logits that need to be converted into discrete architecture selections while maintaining differentiability (so that gradients can flow back to the router parameters). The paper uses the Gumbel-Softmax (also called Concrete distribution) relaxation:

$$\pi_i^{(k)} = \frac{\exp\left(\frac{\mathbf{z}^{(k)}_i + g_i}{\tau}\right)}{\sum_j \exp\left(\frac{\mathbf{z}^{(k)}_j + g_j}{\tau}\right)}$$

where `$g_i \sim \text{Gumbel}(0, 1)$` are i.i.d. samples from the Gumbel distribution (generated as `$g_i = -\log(-\log(u_i))$` with `$u_i \sim \text{Uniform}(0,1)$`), and `$\tau > 0$` is the temperature parameter.

**What it computes:** the vector `$\pi^{(k)}$` is a probability distribution over configuration choices `$i$` that is **differentiable** with respect to the logits `$\mathbf{z}^{(k)}$`. When `$\tau$` is large (e.g., `$\tau = 1.0$`, the initial value), the distribution is nearly uniform — all configuration choices have roughly equal probability, encouraging exploration. When `$\tau$` is small (e.g., `$\tau = 0.05$`, the final value), the distribution approximates a one-hot vector with the maximum logit receiving probability near 1 and others near 0 — the selection becomes sharp, effectively discrete. The Gumbel noise `$g_i$` ensures that even with sharp temperatures, the selection process has stochasticity that enables gradient estimation through the argmax via the Straight-Through Gumbel-Softmax estimator (the forward pass uses the discrete argmax `$\hat{a}_k = \arg\max_i \pi_i^{(k)}$`, but the backward pass uses the gradient of the soft probability `$\pi^{(k)}$`).

**Why this form over simple softmax without noise:** standard softmax without Gumbel noise is deterministic given the logits, which means exploration is purely a function of the temperature. At low temperatures, the distribution collapses to a delta function at the argmax with no exploration. Gumbel-Softmax maintains stochasticity even at low `$\tau$` through the noise `$g_i$`, providing exploration in the discrete selection space that helps avoid local minima in the router's optimization. The temperature annealing schedule (from 1.0 down to 0.05 over the course of training) implements a curriculum: early training explores diverse configurations broadly, while late training commits to sharp architecture decisions.

**Temperature annealing schedule.** The paper states: "The Gumbel-Softmax temperature `$\tau$` is initialized at 1.0 and annealed to 0.05." The exact annealing schedule (linear, exponential, cosine) is not specified, but the endpoint values are given. At `$\tau = 0.05$`, the distribution is effectively one-hot (the probability ratio between the maximum and second-maximum logit is amplified by `$\exp((z_{\max} - z_{\text{second}})/0.05)$`, which is enormous for typical logit differences of 1–3 units, making the selection essentially deterministic).

##### Router Objective Function

The router is trained with a resource-aware loss that penalizes deviations between the selected configuration's resource cost and the target budget constraint. Let `$a_k \in \{1, \ldots, n_{\text{out}}^{(k)}\}$` denote the configuration selected by router `$k$`. The cost function `$\mathcal{C}^{(k)}(a_k)$` maps a configuration to a resource metric:

$$\mathcal{L}_{\text{router}} = \left\|\mathcal{C}^{(k)}(a_k) - \hat{\mathcal{C}}^{(k)}\right\|$$

where `$\hat{\mathcal{C}}^{(k)}$` is the target constraint for dimension `$k$`. The paper states: "possible cost metrics include parameter count, memory usage (including model parameters, KV cache, Mamba cache, and activations), latency, or throughput." For the experiments in this paper, parameter count is used as the cost metric — at budget `$B$`, the target parameter count `$\hat{\mathcal{C}}^{(k)}$` for dimension `$k$` is the number of parameters that dimension should contribute at that total budget, and the router loss pushes the selected configuration's parameter count toward this target.

**Why this form:** the router loss is decoupled from the task loss (cross-entropy or distillation), meaning the router's objective is purely to satisfy resource constraints, while the model parameters' optimization (task loss) handles accuracy. This decomposition avoids conflicting gradients: the model wants configurations that minimize task loss (which might push toward retaining more parameters), while the router's loss pushes toward resource efficiency. The interaction occurs through the masking applied during the forward pass — the router selects the mask, the task loss provides gradients to the model parameters under that mask, and the gradients to the router flow through the Gumbel-Softmax relaxation, providing a signal about which configuration choices improve task performance given the resource constraint.

The loss uses an L1 norm `$\|\cdot\|$` (the paper writes `$\left\|\cdot\right\|$` without specifying L1 or L2, but the absolute value notation and the need for a penalty proportional to deviation suggests L1), so both under-budget and over-budget configurations are penalized symmetrically. Over-budget configurations waste resources; under-budget configurations sacrifice accuracy potential.

##### Joint Optimization and the Linear Scaling Coefficient

The combined training objective is:

$$\mathcal{L}_{\text{total}} = \mathcal{L}_{\text{task}}(\theta) + \lambda \cdot \mathcal{L}_{\text{router}}(\psi)$$

where `$\theta$` are model parameters, `$\psi$` are router parameters, and `$\lambda = 1.0$` is the router loss weight. Additionally, the paper introduces a **linear scaling coefficient** for the router logits: "the linear scaling coefficient for router logits is initialized at 1.0 and linearly increased to 10.0."

This scaling coefficient multiplies the router logits `$\mathbf{z}^{(k)}$` before the Gumbel-Softmax. When the coefficient is 1.0 (early training), the logit magnitudes are small, producing softer probability distributions (more exploration). When the coefficient increases to 10.0 (late training), the effective temperature `$\tau_{\text{eff}} = \tau / \text{scale}$` decreases, sharpening the distribution. This provides a second annealed exploration mechanism independent of `$\tau$` — the temperature controls the inherent randomness of the Gumbel-Softmax, while the scale coefficient controls the dynamic range of the logits, providing two orthogonal knobs for the exploration-exploitation tradeoff.

**Optimization hyperparameters:** "Model parameters are optimized at a learning rate 9e-5, while router parameters are optimized at 1e-2. A 60-step linear learning rate warmup is applied to both." The router learning rate is approximately 111× higher than the model learning rate. This is intentional: the router's parameter space (two small MLPs per dimension) is tiny compared to the model (12B parameters), and the router's loss landscape is simpler (a regression toward a target cost), so rapid convergence is possible and desirable. The higher learning rate allows the router to quickly find good architectural configurations early in training, after which the model parameters adapt to those configurations over the remainder of training.

#### Loss Formulation and Distillation Strategies

##### Standard Cross-Entropy Loss

The model can be trained on the standard language modeling objective without external supervision:

$$\mathcal{L}_{\text{CE}} = -\mathbb{E}_{(x,y) \sim \mathcal{D}}\left[\log p_\theta(y \mid x)\right]$$

where `$\mathcal{D}$` is the training dataset, `$\theta$` represents model parameters, and `$p_\theta(y \mid x)$` is the model's predicted probability distribution over the next token given context `$x$`. This is the standard autoregressive language modeling loss: for each token in the sequence, compute the negative log-likelihood of the ground-truth token under the model's predicted distribution, averaged over the dataset.

##### Knowledge Distillation with Frozen Teacher

The paper's primary training mode uses **frozen-teacher knowledge distillation**, where the original pre-trained full model provides stable supervision:

$$\mathcal{L}_{\text{KD}} = D_{\text{KL}}\left(p_\phi(x; \tau_{\text{KD}}) \,\|\, p_\theta(x; \tau_{\text{KD}})\right)$$

where `$p_\phi(x; \tau_{\text{KD}})$` is the frozen teacher's softmax-normalized logits at distillation temperature `$\tau_{\text{KD}}$`, `$p_\theta(x; \tau_{\text{KD}})$` is the student's corresponding distribution, and `$D_{\text{KL}}$` is the forward Kullback-Leibler divergence:

$$D_{\text{KL}}(P \| Q) = \sum_i P(i) \log\frac{P(i)}{Q(i)}$$

The teacher parameters `$\phi$` are frozen — they do not receive gradient updates and serve as fixed supervision targets.

**What it computes:** for each token position, the KL divergence measures how much the student's predicted distribution diverges from the teacher's. The forward KL `$D_{\text{KL}}(p_\phi \| p_\theta)$` (teacher first, student second) is **mean-seeking** — it penalizes the student heavily when it assigns low probability to tokens that the teacher assigns high probability to, forcing the student to cover the teacher's high-probability regions. This is the standard choice for knowledge distillation because it preserves the teacher's distribution shape.

**Why frozen teacher over trainable teacher:** a trainable teacher (Equation 15 in the paper) updates alongside the student, which creates two problems in multi-budget training:

1. **Moving target problem:** the teacher's distribution shifts during training, so the distillation signal changes over time, and different budgets sampled at different training steps receive supervision from different teachers.
2. **Self-distillation collapse risk:** the 12B student variant is architecturally identical to the trainable teacher (both are the full model), so without cross-entropy regularization (the `$\alpha \cdot \mathcal{L}_{\text{CE}}$` term in Equation 15), the student could trivially match the teacher by copying its own outputs — a degenerate solution. The frozen teacher eliminates this risk because `$\phi$` is a fixed, pre-trained model that never updates to match the student's evolving distribution.

The frozen teacher mode uses:

$$\mathcal{L}_{\text{frozen}} = \mathcal{L}_{\text{KD}}(\theta_{\text{student}}, \phi_{\text{fixed}})$$

where `$\phi_{\text{fixed}}$` are the static weights of the pre-trained 12B model. All sub-networks (6B, 9B, 12B) are distilled toward this same teacher, providing a consistent target that stabilizes multi-budget optimization.

##### Trainable Teacher Mode (Alternative)

The paper also supports a trainable teacher mode as an alternative, where the full-budget model simultaneously serves as teacher and is updated during training:

$$\mathcal{L}_{\text{teacher}} = \mathcal{L}_{\text{KD}}(\theta_{\text{student}}, \theta_{\text{teacher}}) + \alpha \cdot \mathcal{L}_{\text{CE}}(\theta_{\text{teacher}})$$

where `$\theta_{\text{teacher}}$` corresponds to model parameters with full budget allocation (100% across all dimensions), `$\alpha > 0$` is a weighting factor, and the `$\mathcal{L}_{\text{CE}}$` term on the teacher prevents the self-distillation collapse described above. The paper does not use this mode for its main results; the frozen teacher is the primary configuration.

##### Mixed Training Modes

The framework supports flexible combinations. The paper mentions: "a training run can employ trainable teachers for initial phases (capturing distribution-specific knowledge) and transition to frozen teachers for final stages (stabilizing convergence)." This two-phase approach could leverage the trainable teacher's adaptation to the training data distribution early on, then switch to the frozen teacher's stability for final convergence. The main experiments use frozen teacher throughout.

##### Final Joint Optimization Target

The combined objective that trains both model and router simultaneously is:

$$\mathcal{L}_{\text{total}} = \mathcal{L}_{\text{task}}(\theta) + \lambda \cdot \mathcal{L}_{\text{router}}(\psi)$$

where `$\mathcal{L}_{\text{task}}$` is the primary learning objective — in the paper's experiments, this is `$\mathcal{L}_{\text{frozen}} = \mathcal{L}_{\text{KD}}(\theta_{\text{student}}, \phi_{\text{fixed}})$`, the frozen-teacher distillation loss. The router weight `$\lambda = 1.0$` balances the distillation loss and the resource-constraint loss equally by default.

**Why end-to-end optimization matters:** the router receives gradients through the Gumbel-Softmax from the task loss, meaning that architecture decisions respond to the actual distillation signal. If retaining more FFN neurons at the 6B budget reduces the KL divergence significantly, the router's gradients will encourage selecting larger FFN configurations at that budget (balanced against the router's own loss penalizing budget overrun). This tight coupling between architecture search and the training objective distinguishes Nemotron Elastic from prior methods:
- Minitron computes importance scores on frozen checkpoints, selects an architecture, then distills — the architecture is fixed before any distillation loss is observed.
- MatFormer uses post-hoc heuristics (MixnMatch) for sub-network selection at deployment, with no gradient signal relating architecture choices to task loss.
- Flextron uses input-adaptive routing but the routing decisions are deterministic once trained — there's no resource-constraint loss shaping the architecture search.

#### Two-Stage Training Curriculum with Budget Sampling

The need for two-stage training arises from an empirical observation specific to reasoning models: uniform budget sampling during extended-context training causes the **full model's accuracy to degrade** while smaller variants improve. This does not occur in standard (non-reasoning) LLM elastic training, making it a reasoning-specific phenomenon that the paper attributes to gradient competition between budget targets when processing long reasoning sequences.

##### Stage 1: Uniform Budget Sampling with Short Context

During Stage 1, training uses:
- **Sequence length:** `$L_1 = 8192$` tokens (standard context length, not extended)
- **Total tokens:** `$T_1 \approx 65\text{B}$` tokens (~65 billion)
- **Batch size:** 1536 (effective batch size for the stage)
- **Budget sampling distribution:** uniform:

$$p_1(b) = \frac{1}{n_b}, \quad \forall b \in \{1, \ldots, n_b\}$$

where `$n_b = 3$`, so each of the three budgets (6B, 9B, 12B) receives exactly one-third of the training samples. Each training sample is assigned to one budget, and only the corresponding sub-network (via the router's masking) participates in the forward and backward pass for that sample.

**Rationale:** uniform sampling ensures all sub-networks receive balanced training signal during the initial phase when the router is stabilizing. The router's Gumbel-Softmax temperature is high (`$\tau = 1.0$` initially), meaning architecture selections are exploratory — the router samples diverse configurations for each budget. The balanced data allocation prevents any budget from dominating the router's learning, allowing each budget's router to discover its optimal configuration range independently. The short context length (8K) keeps the per-sample computational cost manageable and focuses on general knowledge recovery and parameter efficiency rather than reasoning-specific long-context adaptation.

**What Stage 1 accomplishes:** by the end of Stage 1, the router has approximately converged to preferred configurations per budget (the temperature has annealed from 1.0 toward 0.05, and the logit scale has increased from 1.0 toward 10.0), and the model parameters have recovered much of the accuracy lost by the aggressive width/depth reduction. The paper's Table 4 shows Stage 1 results: for example, the 6B elastic model achieves MATH-500 accuracy of 95.15% (out of 100% pass@1 on the 500-problem benchmark) and AIME-2025 accuracy of 56.88%, which is competitive but not yet at the final performance levels.

##### Stage 2: Non-Uniform Budget Sampling with Extended Context

During Stage 2, training transitions to:
- **Sequence length:** `$L_2 = 49152$` tokens (49K, approximately 6× longer than Stage 1)
- **Total tokens:** `$T_2 \approx 45\text{B}$` tokens (~45 billion)
- **Batch size:** 512 (reduced from 1536 to accommodate the longer sequences in GPU memory)
- **Budget sampling distribution:** non-uniform, weighted toward the full model:

$$p_2(\text{12B}) = 0.5, \quad p_2(\text{9B}) = 0.3, \quad p_2(\text{6B}) = 0.2$$

So half of all Stage 2 training samples are allocated to the full 12B variant, 30% to 9B, and 20% to 6B.

**Rationale for extended context (49K):** reasoning tasks require the model to generate extended chains of thought — for AIME-level competition mathematics, a single problem might require 500–2000 tokens of intermediate reasoning. With batch processing, the model must process full sequences containing these reasoning chains. Short-context training (8K) is insufficient to develop and maintain the long-range coherence needed for multi-step reasoning paths. By exposing all elastic variants to 49K-token sequences, the router must discover configurations that maintain performance across contexts 6× longer than those seen during Stage 1 — a significantly harder constraint that forces the router to avoid over-aggressive compression that breaks down on long sequences.

**Rationale for non-uniform sampling:** the paper reports that under uniform sampling in extended-context training, "the 12B model's accuracy substantially degrades while the 6B model improves, indicating a training imbalance" (Section 3.1, Budget Sampling Strategy). The hypothesized mechanism is gradient competition: the 6B and 9B sub-networks have fewer parameters and therefore larger per-parameter gradient magnitudes (since the total loss gradient is distributed over fewer parameters). If all budgets are sampled equally, the cumulative gradient signal from the smaller models dominates the parameter updates, pulling the shared weights away from configurations that benefit the full model. By weighting sampling toward the full model (50% of updates), the gradient contribution from the 12B variant is amplified, preventing its accuracy from collapsing.

The paper validates this through an ablation study (Table 5 in Section 3.3): comparing uniform sampling against the adjusted non-uniform distribution `$(0.5, 0.3, 0.2)$`. On AIME-2025, the 12B model gains +3.54 percentage points (from 72.29% to 75.83%) with adjusted sampling, while the 6B and 9B variants remain stable. On GPQA, the 12B model gains +2.14 percentage points.

##### Why the Two Stages Are Necessary (Training Signal Coupling)

The two-stage curriculum directly couples the router's architecture discovery to the task difficulty progression. Stage 1 (short context, uniform sampling) encourages broad exploration — the router sees diverse configurations across all budgets on standard-length sequences, establishing which architectures work for general language modeling. Stage 2 (extended context, non-uniform sampling) then imposes reasoning-specific constraints: the router must adapt its configurations to maintain performance on long sequences, and the full model is prioritized to prevent gradient dilution.

Without Stage 2 (stopping after Stage 1), the reasoning benchmarks would substantially underperform — Table 4 shows that AIME-2025 improves by +19.8% for the 6B model and +9.7% for the 9B model from Stage 2 alone, demonstrating that reasoning capability is largely acquired during extended-context adaptation.

Without Stage 1 (starting directly with extended context and non-uniform sampling), the router would not have a stable foundation for architecture decisions — it would be forced to explore the configuration space while simultaneously adapting to long contexts, which could lead to poor local minima where the router selects suboptimal configurations under the pressure of the harder task.

#### Structured Masking Implementation

The elastic architecture is implemented through structured binary masking applied to the hybrid Mamba-Attention-MLP model. This avoids modifying network topology or creating physically distinct sub-networks — instead, dimension-specific masks dynamically select which weights and activations participate in each forward pass.

##### Dynamic Model Formulation (Overview)

The base model is defined as a stack of `$N$` layers with residual connections. A dynamic layer stack is obtained by applying the **dynamic operator** `$\mathcal{D}$` to each layer:

$$\mathcal{D} \circ \mathcal{L}^j = (\mathcal{D} \circ \mathcal{L}_j) \cdot \gamma_j$$

where `$\gamma_j \in \{0, 1\}$` controls layer retention (depth adaptation) and `$\mathcal{D} \circ \mathcal{L}_j$` represents a dynamically masked Mamba, Attention, or MLP layer. Within each layer type, the dynamic operator applies dimension-specific binary masks `$\mathbf{m}$` to the output activations:

$$\mathcal{D}(\mathcal{L}(x)) = \mathcal{L}(x) \odot \mathbf{m}$$

where `$\odot$` denotes element-wise (Hadamard) multiplication and `$\mathbf{m} \in \{0,1\}^d$` is a binary mask vector that determines which dimensions remain active (1) or are zeroed (0). This formulation means the full model's weights are always present in memory, but only the masked subset contributes to any given forward pass.

##### Dynamic Embedding Mask Operator (`$\mathcal{M}_{\text{emb}}$`)

The embedding mask operator applies to any matrix where one dimension is the embedding/hidden size `$d_e$`. For a matrix `$\mathbf{W} \in \mathbb{R}^{d_e \times k}$`:

$$\mathcal{M}_{\text{emb}}(\mathbf{W}) = \mathbf{W} \odot (\mathbf{I}_e \otimes \mathbf{1}_k)$$

where `$\mathbf{I}_e \in \{0,1\}^{d_e}$` is the embedding mask vector: `$\mathbf{I}_e[0:i] = 1$` and `$\mathbf{I}_e[i+1:d_e] = 0$` for the selected active dimension `$i \in [0, d_e]$`. The symbol `$\otimes$` denotes outer product broadcasting — `$\mathbf{I}_e \otimes \mathbf{1}_k$` produces a `$d_e \times k$` binary matrix where each row `$r$` is either all ones (if `$\mathbf{I}_e[r] = 1$`) or all zeros (if `$\mathbf{I}_e[r] = 0$`), repeating the mask value across the `$k$` dimension.

**What this does:** when applied to a weight matrix `$\mathbf{W}$`, it zeros out the rows corresponding to pruned embedding channels. For example, if `$d_e = 5120$` and the router selects `$i = 3072$` active channels, rows 0–3071 of the weight matrix are unchanged, and rows 3072–5119 are zeroed. The outer product `$\mathbf{I}_e \otimes \mathbf{1}_k$` ensures the mask is broadcast across the entire non-embedding dimension `$k$` (e.g., the intermediate FFN dimension or the sequence length), so the zeroing is applied consistently.

For matrices `$\mathbf{W} \in \mathbb{R}^{k \times d_e}$` (where the embedding dimension is the second dimension), the mask broadcasts similarly: `$\mathcal{M}_{\text{emb}}(\mathbf{W}) = \mathbf{W} \odot (\mathbf{1}_k \otimes \mathbf{I}_e)$`, zeroing out the columns corresponding to pruned channels.

##### Dynamic Mamba Mask Operator (`$\mathcal{M}_{\text{mamba}}$`)

The Mamba mask operator applies to matrices where dimensions derive from Mamba heads `$m_h$` or head channels `$m_d$`. The total Mamba dimension is `$f(m_h, m_d) = m_h \cdot m_d$` (heads × channels per head). For a matrix `$\mathbf{W} \in \mathbb{R}^{f(m_h, m_d) \times k}$`:

$$\mathcal{M}_{\text{mamba}}(\mathbf{W}) = \mathbf{W} \odot (\mathbf{I}_m \otimes \mathbf{1}_k)$$

where `$\mathbf{I}_m \in \{0,1\}^{f(m_h, m_d)}$` is constructed to satisfy the **group-aware permutation constraint**:

$$\mathbf{I}_m[\phi(h, c)] = \begin{cases} 1 & \text{if } h \leq h^* \text{ and } c \leq c^* \\ 0 & \text{otherwise} \end{cases}$$

where `$\phi(h, c)$` maps head `$h$` and channel `$c$` to a flat index in the Mamba dimension, `$h^* \in [0, m_h]$` is the number of active heads, and `$c^* \in [0, m_d]$` is the number of active channels per head.

**What this does:** the mask retains a contiguous block of heads (the first `$h^*$` heads) and within each active head, a contiguous block of channels (the first `$c^*$` channels per head). The key constraint is that **all heads in the same Mamba group must have the same active channel count** — the mask construction ensures `$\mathbf{I}_m[\phi(h, \cdot)] = \mathbf{I}_m[\phi(h', \cdot)]$` for `$h, h' \in \mathcal{G}_g$`, meaning the channel mask pattern is identical across all heads within a group.

**Why this constraint matters:** Mamba-2's state-space computation involves structured matrices `$\mathbf{A}$` (the state transition matrix) and `$\mathbf{D}$` (the skip connection parameter) that are defined per head and have shapes that depend on the channel dimension. If different heads within a group had different numbers of active channels, the SSM update `$\tilde{y} = \text{SSM}(\hat{x}, \hat{B}, \hat{C}, \mathbf{A}, \mathbf{D}, d_t)$` would be ill-posed because the hidden state dimensions would not match. The group-consistent masking preserves the structural integrity of the SSM computation.

##### Dynamic Mamba Forward Pass

The full dynamic Mamba layer forward pass proceeds through six stages with masking applied at multiple points:

1. **Layer norm with embedding mask:**
   $$y_{\text{ln}} = \mathcal{M}_{\text{emb}}(\text{LN}(y))$$
   The layer normalization output `$\text{LN}(y) \in \mathbb{R}^{B \times L \times d_e}$` is masked to the active embedding channels, zeroing out pruned channels in the input to subsequent projections.

2. **Projection computations (all from masked normalized input):**
   $$z = \mathbf{W}_z \cdot y_{\text{ln}}, \quad x = \mathbf{W}_x \cdot y_{\text{ln}}, \quad B = \mathbf{W}_B \cdot y_{\text{ln}}, \quad C = \mathbf{W}_C \cdot y_{\text{ln}}, \quad d_t = \mathbf{W}_{dt} \cdot y_{\text{ln}}$$
   where `$\mathbf{W}_z, \mathbf{W}_x \in \mathbb{R}^{(m_h \cdot m_d) \times d_e}$` project to the full Mamba dimension, `$\mathbf{W}_B, \mathbf{W}_C \in \mathbb{R}^{(g \cdot d_s) \times d_e}$` project to the SSM state space (with `$g$` Mamba groups and `$d_s$` SSM state dimension), and `$\mathbf{W}_{dt} \in \mathbb{R}^{m_h \times d_e}$` projects to the per-head delta modulation. The masked input `$y_{\text{ln}}$` has zeros in pruned channels, so these channels contribute nothing to the projections.

3. **Mamba-specific masking of projections:**
   $$z \leftarrow \mathcal{M}_{\text{mamba}}(z), \quad x \leftarrow \mathcal{M}_{\text{mamba}}(x), \quad d_t \leftarrow \mathcal{M}_{\text{mamba}}(d_t)$$
   The Mamba mask `$\mathcal{M}_{\text{mamba}}$` (Equation 24) zeros out the output of pruned heads and pruned head channels. For `$z$` and `$x$` (which have dimension `$m_h \cdot m_d$`), this means entries corresponding to pruned heads or channels are zeroed. For `$d_t$` (which has dimension `$m_h$`), entries for pruned heads are zeroed. The `$\mathbf{W}_B$` and `$\mathbf{W}_C$` projections are NOT masked because they depend on group state dimensions `$g \cdot d_s$` which are not elastified (groups and state dimensions remain fixed).

4. **Causal convolution:**
   $$\hat{x} = \text{conv1d}(x), \quad \hat{B} = \text{conv1d}(B), \quad \hat{C} = \text{conv1d}(C)$$
   The temporal convolution mixes information across adjacent sequence positions. The paper notes that "the conv1d operation on `$\hat{x}$` implicitly respects the Mamba mask structure" — meaning the convolution kernel weights for pruned channels are not independently masked (the masking happened before convolution), so the convolution operates on already-zeroed inputs for pruned dimensions and produces zero outputs for those dimensions.

5. **Selective state-space model update:**
   $$\tilde{y} = \text{SSM}(\hat{x}, \hat{B}, \hat{C}, \mathbf{A}, \mathbf{D}, d_t)$$
   This is the core Mamba-2 computation: the selective scan algorithm that processes the sequence with linear-time complexity. The SSM operates on the active dimensions determined by the masks — pruned channels (zeroed by `$\mathcal{M}_{\text{mamba}}$`) contribute nothing to the state update.

6. **Gated RMSNorm and output projection:**
   $$y_{\text{pre}} = \mathbf{W}_O \cdot \text{RMSNorm}(\tilde{y} \odot \text{silu}(z))$$
   where `$\text{silu}(z) = z \cdot \sigma(z)$` is the SiLU (Sigmoid Linear Unit) activation applied to the gating signal `$z$`, `$\odot$` is element-wise multiplication (gating), `$\text{RMSNorm}$` is root-mean-square normalization, and `$\mathbf{W}_O \in \mathbb{R}^{d_e \times (m_h \cdot m_d)}$` projects back to the embedding dimension. The gated output `$\tilde{y} \odot \text{silu}(z)$` has zeros where `$\mathcal{M}_{\text{mamba}}$` zeroed either `$\tilde{y}$` or `$z$`, effectively removing pruned heads from the output.

7. **Final output masking (both embedding and Mamba):**
   $$y_{\text{out}} = \mathcal{M}_{\text{emb}}(\mathcal{M}_{\text{mamba}}(y_{\text{pre}}))$$
   The output projection `$y_{\text{pre}} \in \mathbb{R}^{B \times L \times d_e}$` is first masked to zero pruned Mamba dimensions, then masked again by `$\mathcal{M}_{\text{emb}}$` to ensure output consistency at the embedding level. The double masking is redundant in some cases but ensures correctness — if the output projection `$\mathbf{W}_O$` inadvertently produces non-zero values in pruned positions, the final mask zeros them.

##### Dynamic Attention Forward Pass

1. **Layer norm with embedding mask:**
   $$y_{\text{ln}} = \mathcal{M}_{\text{emb}}(\text{LN}(y))$$

2. **Query, key, value projections with attention head masking on weights:**
   $$\mathbf{Q} = \mathcal{M}_{\text{attn\_head}}(\mathbf{W}_Q) \cdot y_{\text{ln}}, \quad \mathbf{K} = \mathcal{M}_{\text{attn\_head}}(\mathbf{W}_K) \cdot y_{\text{ln}}, \quad \mathbf{V} = \mathcal{M}_{\text{attn\_head}}(\mathbf{W}_V) \cdot y_{\text{ln}}$$
   The attention head mask `$\mathcal{M}_{\text{attn\_head}}$` (Equation 34) is applied to the weight matrices **before** the projection: rows of `$\mathbf{W}_Q, \mathbf{W}_K, \mathbf{W}_V$` corresponding to pruned heads or pruned head dimensions are zeroed. This means the projection `$\mathbf{W}_Q \cdot y_{\text{ln}}$` automatically produces zero output for pruned dimensions without requiring a separate masking step on the result.

3. **Standard scaled dot-product attention:**
   $$\text{Attn} = \text{softmax}\left(\frac{\mathbf{Q}\mathbf{K}^T}{\sqrt{d_h}}\right) \mathbf{V}$$
   The attention computation is unchanged from the standard Transformer — the only difference is that pruned heads have zero queries, keys, and values, so they contribute nothing to the attention output but don't disrupt the computation (softmax of zeros produces uniform attention weights for pruned positions, and the value aggregation multiplies zeros).

4. **Output projection with embedding mask on weights:**
   $$y_{\text{pre}} = \mathcal{M}_{\text{emb}}(\mathbf{W}_O) \cdot \text{Attn}$$
   The output projection weight `$\mathbf{W}_O \in \mathbb{R}^{d_e \times (n_h \cdot d_h)}$` is masked so that columns corresponding to pruned heads/channels are zeroed — the weight matrix itself is modified before the matrix multiply.

5. **Final output masking:**
   $$y_{\text{out}} = \mathcal{M}_{\text{emb}}(\mathcal{M}_{\text{attn\_head}}(y_{\text{pre}}))$$

##### Dynamic FFN Forward Pass

1. **Layer norm with embedding mask:**
   $$y_{\text{ln}} = \mathcal{M}_{\text{emb}}(\text{LN}(y))$$

2. **First linear transformation with FFN mask on weights:**
   $$h = \mathcal{M}_{\text{ffn}}(\mathbf{W}_1) \cdot y_{\text{ln}}$$
   The FFN mask `$\mathcal{M}_{\text{ffn}}$` (Equation 42) is applied to `$\mathbf{W}_1 \in \mathbb{R}^{d_{\text{int}} \times d_e}$`, zeroing out rows corresponding to pruned intermediate neurons. The mask vector `$\mathbf{I}_f \in \{0,1\}^{d_{\text{int}}}$` has ones for the first `$j$` neurons and zeros for the rest, where `$j \in [0, d_{\text{int}}]$` is the active intermediate dimension selected by the router.

3. **Activation and second linear transformation:**
   $$y_{\text{pre}} = \mathcal{M}_{\text{emb}}(\mathbf{W}_2) \cdot \sigma(h)$$
   where `$\sigma(\cdot)$` is the activation function (typically SiLU or GELU in the Nano V2 architecture). The second weight matrix `$\mathbf{W}_2 \in \mathbb{R}^{d_e \times d_{\text{int}}}$` is masked by `$\mathcal{M}_{\text{emb}}$` on its first dimension (embedding), so rows corresponding to pruned embedding channels are zeroed. The intermediate activation `$h$` has zeros for pruned neurons (because `$\mathcal{M}_{\text{ffn}}(\mathbf{W}_1)$` zeroed their rows), so `$\sigma(h)$` produces zero for those positions.

4. **Final output masking:**
   $$y_{\text{out}} = \mathcal{M}_{\text{emb}}(\mathcal{M}_{\text{ffn}}(y_{\text{pre}}))$$

##### Depth Adaptation

Layer-wise depth selection is achieved through the binary coefficient vector `$\boldsymbol{\gamma}$`:

$$y_{j+1} = \begin{cases} y_j + \mathcal{D} \circ \mathcal{L}_j(y_j) & \text{if } \gamma_j = 1 \\ y_j & \text{if } \gamma_j = 0 \end{cases}$$

The set of active layers is `$\mathcal{A} = \{j \mid \gamma_j = 1, j \in [0, N-1]\}$` with `$|\mathcal{A}| = N_{\text{target}}$`. Layers with `$\gamma_j = 0$` are bypassed — the residual input `$y_j$` passes through unchanged. All layer weights exist in memory regardless of `$\gamma_j$`, but the forward pass computation (including the expensive SSM or attention operations) is skipped for inactive layers, reducing both FLOPs and latency.

**Why retaining weights for inactive layers:** during training, different budgets sampled in adjacent iterations may activate different layers. If budget 12B activates layer `$j$` (with `$\gamma_j^{12B} = 1$`) in one iteration and budget 6B bypasses it (with `$\gamma_j^{6B} = 0$`) in the next, the weights of layer `$j$` must persist between iterations. This weight persistence is the core of nested weight-sharing — layer `$j$`'s parameters are shared across all budgets that activate it. During deployment, inactive layers can be physically removed from the checkpoint (the slicing operation, Section 2.5), producing a smaller on-disk footprint.

##### Mask Generation from Router Output

At each training iteration, the router's Gumbel-Softmax output `$\pi^{(k)}$` determines the selected configuration:

$$\hat{a}_k = \arg\max_i \pi_i^{(k)}$$

The configuration index `$\hat{a}_k$` maps to a target count `$c_{\hat{a}_k}$` — for example, if the FFN router selects configuration index 2, this might correspond to retaining `$c_{\hat{a}_k} = 8192$` intermediate neurons (out of 14336 total). The binary mask is then constructed by selecting the top `$c_{\hat{a}_k}$` components from the importance ranking:

$$\mathbf{I}^{(k)} = \mathbf{I}[\sigma^{(k)}(j) \leq c_{\hat{a}_k}], \quad j = 1, \ldots, \text{size}^{(k)}$$

where `$\sigma^{(k)}(j)$` is the rank of component `$j$` from the importance estimation (1 = most important, 2 = second most important, etc.), and `$\mathbf{I}[\cdot]$` is the indicator function (1 if the condition is true, 0 otherwise). This selects exactly the top-ranked components according to the pre-computed importance ordering.

**In homogeneous mode:** the mask `$\mathbf{I}^{(k)}$` applies uniformly across all layers of the same type — all FFN layers retain the same `$c_{\hat{a}_k}$` neurons, all attention layers retain the same number of heads, etc.

**In heterogeneous mode:** the router output `$\mathbf{z}^{(k)}$` (of dimension `$|\mathcal{X}| \times N_{\text{X}}$`) is partitioned into `$N_{\text{X}}$` segments of size `$|\mathcal{X}|$`, one per layer. Layer `$\ell$` gets its own configuration selection `$\hat{a}_k^{(\ell)}$`, its own target count `$c_{\hat{a}_k^{(\ell)}}$`, and its own mask `$\mathbf{I}^{(k,\ell)}$`, allowing each layer to have a distinct compression ratio. This enables configurations where, for instance, middle layers retain 80% of FFN neurons while early and late layers retain 40%, reflecting the non-uniform importance distribution across depth.

##### Mask Integration Strategies (Two Modes)

The paper supports two modes for how the Gumbel-Softmax probabilities interact with the generated masks during training:

**Mode 1: Hard selection via argmax logits.** The discrete selection is determined by `$\hat{i}_k = \arg\max_i \pi_i^{(k)}$`, and the mask is the binary mask from that configuration, scaled by the corresponding logit magnitude:

$$\mathbf{I}^{(k)}_{\text{train}} = \mathbf{z}^{(k)}_{\hat{i}_k} \cdot \mathbf{I}_{\hat{i}_k}$$

The scalar `$\mathbf{z}^{(k)}_{\hat{i}_k}$` (a real number, the raw router logit for the selected configuration) multiplies the binary mask. During the forward pass, this means pruned positions are zero (0 × logit = 0) and active positions have value equal to the logit magnitude. The logit scaling provides a gradient pathway: if the task loss benefits from larger logit values (which amplify the mask), gradients flow to increase `$\mathbf{z}^{(k)}_{\hat{i}_k}$`; if the task loss benefits from smaller values, the logit shrinks.

**Mode 2: Soft masking via probabilistic combination.** Instead of a single hard selection, all candidate configurations' masks are combined proportionally to their Gumbel-Softmax probabilities:

$$\mathbf{I}^{(k)}_{\text{train}} = \sum_i \pi_i^{(k)} \cdot \mathbf{I}_i$$

where `$\pi_i^{(k)}$` is the soft probability of configuration `$i$` (from Equation 11) and `$\mathbf{I}_i$` is the binary mask for that configuration. The resulting train-time mask `$\mathbf{I}^{(k)}_{\text{train}}$` is no longer binary — it has continuous values in `$[0, 1]$` representing a weighted mixture of all candidate configurations. For a component (e.g., a specific FFN neuron), if that neuron is retained in 70% of likely configurations and pruned in 30%, its mask value is 0.7, attenuating but not zeroing its contribution.

**At inference time:** regardless of the training mode, the discrete mask `$\mathbf{I}_{\hat{i}_k}$` (without logit scaling) is used, corresponding to the argmax configuration. The logit scaling coefficient is set to 1.0 at inference, producing a pure binary mask.

**Why two modes:** Mode 1 (hard selection) provides a stronger gradient signal through the logit magnitude but can be unstable — if the argmax selection is poor due to Gumbel noise, the entire mask is zero or logit-scaled in a suboptimal way, and the model receives no signal from pruned components. Mode 2 (soft combination) provides a smoother training signal by blending all configurations, ensuring no component is ever fully zeroed, which stabilizes early training when the router is uncertain. The paper does not specify which mode is used for the main experiments; the presence of both modes suggests flexibility depending on training stability requirements.

#### Elastic Model Deployment (Zero-Shot Slicing)

After training converges, multiple model variants are extracted from the single checkpoint through a learned slicing mechanism.

Given the trained full model with parameter set `$\Theta_{\max}$` (the 12B model with all components at maximum width/depth) and a target budget `$B \in \mathcal{B}$` (where `$\mathcal{B} = \{6\text{B}, 9\text{B}, 12\text{B}\}$` in this paper), the router `$\mathcal{R}$` is invoked with the budget specification (the one-hot vector `$\mathbf{e}_B$`). The router produces its learned configuration selections for that budget, which are converted to binary masks via the importance rankings. The sliced model parameters are:

$$\Theta_B = \{\theta \in \Theta_{\max} : \theta \text{ is retained for budget } B\}$$

The slicing operation permanently removes (deletes) components where the mask is zero: rows/columns of weight matrices corresponding to pruned neurons, heads, or channels are physically excised from the tensor, reducing the parameter count to match budget `$B$`. The operation is "computationally negligible" — it involves reading the router outputs, constructing the binary masks, and filtering the parameter tensors, with no forward or backward passes.

**What this enables:** practitioners store and deploy only the single full-size (12B) checkpoint, yet at any time can produce inference-ready checkpoints for 9B or 6B by running the slicing operation. Multiple model variants serve different deployment scenarios from a single artifact, with constant storage cost `$\text{Size}(\text{Model}_{\max}) + \epsilon_{\text{router}}$` (where `$\epsilon_{\text{router}} \ll 0.02 \cdot \text{Size}(\text{Model}_{\max})$`, the router parameters adding under 2% overhead). Compared to storing separate checkpoints for all three variants (~54 GB in BF16 for 12B + 9B + 6B), the elastic approach requires only ~24 GB for the 12B parent plus router metadata (~0.4 GB), achieving the storage savings documented in Table 3.

## 4. Key Insights and Innovations

### Innovation 1: Reasoning Models Require Fundamentally Different Compression Strategies Than Standard LLMs — and Uniform Sampling Is Actively Harmful

The paper's most important diagnostic finding is not a method but a **counterintuitive empirical observation** that challenges a default assumption in model compression. The dominant paradigm in elastic network training — inherited from MatFormer, Flextron, and general multi-task learning — is that **uniform budget sampling works**: allocate equal training data to each sub-network variant, and all variants improve together. This assumption holds for standard LLMs (base and instruct-tuned models) where elastic training with uniform sampling produces nested sub-networks that track the parent model's performance.

Nemotron Elastic demonstrates that this assumption **fails catastrophically** for reasoning models. When uniform budget sampling is applied during extended-context training (49K token sequences, Stage 2), the 12B full model's accuracy **degrades substantially** while the smaller 6B and 9B variants improve — a clear signal of negative transfer. The ablation in Table 5 quantifies this: switching from uniform sampling to weighted sampling (50% 12B, 30% 9B, 20% 6B) recovers +3.54 percentage points on AIME-2025 for the 12B model while preserving smaller-variant performance.

**Why this is intellectually distinctive.** Prior work on model compression (Minitron, Minitron-SSM, MatFormer, Flextron) implicitly treated the compression objective as **invariant to the model's task profile** — compress a base model, an instruct model, or a reasoning model, and the same training recipe applies. This paper provides the first evidence that reasoning models have **qualitatively different training dynamics under elastic compression**, and that the failure mode is specific to the interaction between multi-budget gradient competition and the extended sequences required for chain-of-thought reasoning.

The diagnostic mechanism — gradient competition between sub-networks of different capacities on long sequences — is an explanatory concept that did not exist in the compression literature before this work. Smaller sub-networks have fewer parameters, so their per-parameter gradient magnitudes are larger when trained on the same loss signal. On extended reasoning sequences where the full model needs substantial gradient updates to maintain long-range coherence, the cumulative gradient contribution from smaller variants (sampled equally) dilutes the signal, pulling shared weights toward configurations that benefit compact models at the expense of the full model. This is not a generic multi-task interference problem — it is specific to the capacity-asymmetric, weight-sharing regime of elastic training combined with the long-context demands of reasoning.

**What this changes.** The finding reframes elastic reasoning model training from an optimization problem that can use off-the-shelf elastic recipes to one that requires **budget-aware curriculum design** as a first-class architectural decision. The two-stage curriculum — short-context uniform sampling for router stabilization, followed by extended-context non-uniform sampling biased toward the full model — is not an engineering tweak but a necessary condition for the approach to work at all. Future work on elastic reasoning models inherits this constraint: uniform sampling must be abandoned in favor of budget-weighted strategies during long-context adaptation. The finding also explains why prior elastic methods were never evaluated on reasoning benchmarks — the standard recipe would have produced competitive base-model numbers but failed on AIME- and GPQA-level tasks.

**Significance level.** This is a **fundamental empirical discovery** rather than an incremental improvement. It does not introduce a new technique but rather diagnoses a previously unknown failure mode that defines the space of valid techniques for an emerging problem domain (elastic reasoning models). The specificity of the failure — uniform sampling hurts the largest model specifically on long-context reasoning tasks — makes it actionable and falsifiable.

---

### Innovation 2: End-to-End Router Training Couples Architecture Search to the Actual Loss Landscape, Replacing Post-Hoc Heuristics

Prior work on elastic architectures (MatFormer, Flextron) and structured pruning (Minitron, Minitron-SSM) shares a common architectural pattern: **architecture decisions are decoupled from the training objective**. MatFormer uses post-hoc MixnMatch heuristics — at deployment time, a sub-network is assembled by applying generic importance-based rules, with no gradient signal connecting those rules to the training loss. Minitron computes importance scores on a frozen pre-trained checkpoint, selects a fixed architecture, and then distills that architecture — meaning the architecture is chosen before any distillation loss is observed. In both paradigms, the architecture search does not "know" about the loss landscape it will ultimately be evaluated on.

Nemotron Elastic replaces this decoupled approach with **end-to-end trained router networks** that receive gradients from the task loss (frozen-teacher knowledge distillation, Section 2.3.3) through the Gumbel-Softmax relaxation. The routers are not post-hoc selectors — they are parameters (two-layer MLPs with leaky ReLU) optimized jointly with the model under the combined objective `L_total = L_task(θ) + λ · L_router(ψ)` (Equation 17). This means the router's decisions about which FFN neurons, attention heads, Mamba channels, and layers to retain at each budget are shaped by the **actual distillation signal**, not by a proxy importance metric computed on a frozen model.

**Why this is intellectually distinctive.** The conceptual shift is from **architecture search as a pre-processing step** (performed once on a static model and then frozen) to **architecture search as part of learning** (continuously adapted as model parameters evolve). This matters because importance scores computed on a pre-trained checkpoint reflect the model's behavior before any compression, not its behavior after compression and distillation. A layer that is redundant in the 12B model might become critical in the 9B model because its removal forces adjacent layers to compensate — but static importance scoring cannot capture this interaction. By training routers alongside the model, Nemotron Elastic allows the architecture to adapt to the compressed regime's loss landscape, discovering configurations that are optimal **given the distillation objective**, not optimal in isolation.

The Gumbel-Softmax relaxation with temperature annealing (from 1.0 to 0.05) and logit scaling (from 1.0 to 10.0) provides a differentiable mechanism for this coupling. The router does not make a hard architecture decision and then train under it — it maintains a **distribution over configurations** that gradually sharpens, allowing early exploration of diverse architectures (when the model is far from convergence and the loss landscape is changing rapidly) and late exploitation of the best-performing configurations (when the model has stabilized).

**Comparison to the closest prior work.** Flextron [cai2024flextron] also uses input-adaptive routing, but the routing decisions are input-dependent (different inputs get different sub-networks) rather than budget-conditioned (a fixed budget produces a fixed architecture). More critically, Flextron's routing is optimized for inference-time adaptation, not for training-time architecture discovery — there is no resource-constraint loss shaping the router's decisions, and no multi-budget training where a single router must serve multiple deployment targets. Nemotron Elastic's routers are trained explicitly to satisfy parameter-count constraints (L_router penalizes deviations from target budget size) while responding to distillation gradients, making them architecturally similar to Flextron's routers but conceptually different in purpose and optimization.

**What this changes.** The end-to-end coupling means that the architecture discovered by the router is **training-objective-aware** — if frozen-teacher distillation is the task loss, the router learns configurations that minimize KL divergence to the teacher, which may differ from configurations that minimize cross-entropy loss on the corpus. The paper's framework supports switching between loss formulations (cross-entropy, frozen distillation, trainable teacher) and the router adapts accordingly. This opens the door to **loss-conditioned architecture search** where different deployment objectives (accuracy vs. latency, reasoning vs. factuality) produce different optimal elastic configurations from the same training run.

**Significance level.** This is a **methodological advance** that systematizes a capability previous methods approached only heuristically. It is incremental relative to the concept of learned routing (established in Flextron and the NAS literature), but fundamental in its application to **multi-budget elastic training with task-loss coupling** — a combination that enables the simultaneous, competitive optimization of 6B, 9B, and 12B variants from a single run, which prior methods with decoupled search could not achieve.

### Innovation 3: Frozen-Teacher Distillation Stabilizes Multi-Budget Elastic Training by Providing a Fixed Alignment Target Across All Sub-Networks

Standard knowledge distillation in compression pipelines (Minitron, Minitron-SSM) uses a **trainable teacher** — the full parent model is fine-tuned alongside the compressed student, with its parameters updated to adapt to the distillation data distribution. This works when compressing a single target size because the teacher only needs to serve one student. In the multi-budget elastic setting, however, the trainable teacher creates a **moving target problem** that interacts destructively with budget sampling.

Nemotron Elastic identifies and solves this problem by using a **frozen teacher**: the original pre-trained 12B model's parameters are held fixed throughout elastic training (Equation 16), providing static, consistent distillation targets for all sub-networks (6B, 9B, and 12B). The frozen teacher's logits `p_φ(x; τ_KD)` never change, meaning that when the 6B sub-network is sampled in one iteration and the 12B sub-network in the next, both are distilled toward the same teacher distribution. This eliminates the instability that would arise if the teacher's distribution shifted between iterations — a shift that would be especially problematic in Stage 2 where non-uniform sampling means the 12B variant receives 50% of updates, creating a feedback loop where the teacher (if trainable) quickly diverges from its original behavior.

**Why this is intellectually distinctive.** The field's default assumption — inherited from the knowledge distillation literature (Hinton et al., 2015) and compression pipelines — is that a trainable teacher is **always better** because it adapts to the training data, providing more relevant supervision. This paper provides a counterexample where the trainable teacher is actively harmful: in multi-budget elastic training with non-uniform sampling, the teacher's adaptation creates instability that degrades the full model's performance. The frozen teacher is not a compromise for simplicity — it is a **stability mechanism** that decouples teacher quality from training dynamics.

The paper also identifies a subtle failure mode that the frozen teacher avoids: in the trainable-teacher setting, the full-budget (12B) student is architecturally identical to the teacher, creating a **self-distillation collapse risk**. Without the cross-entropy regularization term `α · L_CE(θ_teacher)` in Equation 15, the 12B student could trivially minimize the distillation loss by copying its own outputs — the teacher and student become the same model, providing no useful signal. The frozen teacher eliminates this risk entirely because `φ_fixed` is a different set of parameters that never updates to match the student.

**What this changes.** The frozen-teacher insight has implications beyond this paper. Any multi-task, multi-budget, or ensemble training regime where a teacher provides supervision to multiple students with different capacities may benefit from a frozen teacher to prevent the supervision signal from drifting under the influence of the students it supervises. The paper demonstrates empirically that this works: the 12B elastic variant achieves 77.41 average accuracy versus 77.38 for the independently trained baseline (Table 1), showing that frozen-teacher distillation does not sacrifice quality for stability.

**Significance level.** This is an **incremental but important design insight** — incremental because frozen teachers are a known technique (used in some distillation settings for computational efficiency), but important because the paper identifies a specific failure mode (multi-budget training instability from moving targets) that makes the frozen teacher a **necessary** rather than merely convenient choice. The connection to self-distillation collapse in architecturally identical teacher-student pairs is a conceptual contribution that clarifies when frozen teachers should be preferred.

---

### Innovation 4: Group-Aware SSM Elastification Enables Nested Weight-Sharing in Hybrid Mamba-Attention Architectures Without Breaking Structural Constraints

Prior elastic architectures (MatFormer, Flextron) operate on pure Transformer models where the structural units — attention heads, FFN neurons, embedding channels — are **independent** and can be pruned without cross-component constraints. Pruning attention head 3 does not affect attention head 7; pruning FFN neuron 512 does not constrain FFN neuron 1024. This independence makes elastic masking straightforward: rank components by importance, select the top-k, and apply binary masks.

Mamba-2 layers break this independence. Mamba heads are organized into groups `G_g`, and within each group, all heads must have the **same number of active channels** to preserve valid SSM computation. If head 1 in group 2 retains 32 channels while head 3 in group 2 retains 48 channels, the structured state-space matrices become dimensionally inconsistent and the SSM update is ill-posed. A naive per-channel importance ranking that ignores group structure would produce rankings that are structurally invalid — the top-k channels by importance might include 40 channels from head 1 and 24 from head 3, violating the group-consistency constraint.

The paper introduces a **nested, group-constrained importance estimation** procedure (Section 2.1.1, Equations 3-4) and a corresponding **group-aware masking operator** `M_mamba` (Section 2.4.2, Equation 25) that jointly solve this problem:

- **In the ranking phase:** Channel-level scores are computed globally (across all heads), then head-level scores are computed using only the top-ranked channels, and finally heads are ranked **independently within each Mamba group** to ensure that pruning respects group boundaries.
- **In the masking phase:** The mask `I_m[φ(h, c)]` activates channels `c ≤ c*` for all heads `h ≤ h*`, with the constraint that `I_m[φ(h, ·)] = I_m[φ(h', ·)]` for `h, h' ∈ G_g` (all heads in the same group have identical channel masks).

This is not merely an implementation detail — it is a **structural requirement** that makes the difference between a valid hybrid elastic model and one that produces garbage SSM outputs. Prior work on hybrid compression (Minitron-SSM) also respects group constraints during pruning, but does so in a **non-elastic, single-target** setting where the architecture is fixed before distillation begins. Nemotron Elastic is the first to integrate group-aware constraints into an elastic framework where architecture decisions are made dynamically by a learned router that must output structurally valid configurations for every budget.

**Why this is intellectually distinctive.** The contribution here is not the group constraint itself (which is a property of Mamba-2, not invented by this paper) but the **integration of that constraint into the elastic paradigm** — specifically, into the importance ranking that the router uses to construct masks. The router selects a target head count `h*` and channel count `c*`, but it does not need to know about group constraints — the importance ranking and masking operator enforce validity automatically. This separation of concerns (router selects quantities; ranking and masking enforce structure) is a design pattern that extends beyond Mamba to any architecture with cross-component dependencies (e.g., grouped convolutions, structured sparsity patterns, tensor-train factorizations).

The paper demonstrates this extensibility by showing that attention heads (which do not have group constraints) use a simpler global ranking `σ^(attn)`, while Mamba heads use the group-constrained nested procedure — the elastic formulation accommodates both within a unified framework by making the constraint mechanism a property of the component type, not the router.

**What this changes.** This contribution unlocks elastic training for the growing class of hybrid Mamba-Attention models (Jamba, Zamba, Nemotron-H, and future architectures that mix SSMs with attention). Without group-aware elastification, these models could only be compressed through sequential single-target methods (Minitron-SSM), forfeiting the cost and memory advantages of elastic weight-sharing. The paper's result — three models (12B, 9B, 6B) from a single 110B-token training run — would be architecturally impossible without this component.

**Significance level.** This is a **methodological enabler** — it does not advance the theory of compression or elasticity, but it removes a blocking constraint that prevented elastic methods from applying to an important and growing model class. Its significance is tied to the importance of hybrid architectures: if hybrid Mamba-Attention models become dominant, group-aware elastification is essential infrastructure; if Transformers remain dominant, it is a specialized contribution. The current trajectory of the field (with models like Nemotron-H and Jamba gaining adoption) suggests this is a timely and practical advance.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** All experiments use the compression data blend that was used to train Nemotron NanoV2 9B (both base and reasoning variants) [nano2025efficient]. This same dataset is employed for both importance estimation of network components and knowledge distillation-based retraining, ensuring fair comparison with the Minitron-SSM baseline [taghibakhshi2025minitron] and consistency across base and reasoning model variants. The exact composition, size, and source of this blend are not described beyond it being a standardized data blend used in prior work.

- **Base model(s).** The parent model is the NVIDIA Nemotron Nano V2 12B hybrid model [nano2025efficient], which combines Mamba-2 and attention layers. The authors target two nested sub-models: a 9B (25% compression) and a 6B (50% compression), simultaneously produced from the single 12B parent. The paper does not describe experiments on other model families or scales.

- **Metrics.** The primary metric is **pass@1 accuracy** on downstream benchmarks, averaged over 4 to 16 shots as appropriate for each benchmark. The evaluation suite spans general knowledge and language understanding (MMLU-Pro [wang2024mmlupro] for college-level multiple-choice reasoning, GPQA [rein2023gpqa] for graduate-level science questions), mathematical reasoning (MATH-500 [hendrycks2021math], AIME-2024 and AIME-2025 [aime]), and code generation (LiveCodeBench v5 [jain2024livecodebench]). An average score across all six benchmarks is reported in Table 1 as a summary metric. All evaluations use reasoning enabled, meaning the models generate chain-of-thought traces before producing final answers.

- **Baselines.**
  - **NanoV2-12B (pretraining from scratch)**: The independently trained Nemotron Nano V2 12B reasoning model, representing the upper bound achievable through full-scale pretraining.
  - **NanoV2-9B (pretraining from scratch)**: The independently trained 9B variant.
  - **Minitron-SSM 9B and 6B**: The sequential compression baseline from prior work [taghibakhshi2025minitron], where each compressed model is produced through a separate exploration + distillation pipeline.
  - **Nemotron-Elastic variants under uniform sampling**: An ablation baseline within the elastic framework (Table 5) where the Stage 2 budget sampling is uniform rather than weighted.

  The paper does not compare against MatFormer, Flextron, or other elastic baselines on these benchmarks, nor does it include comparisons against non-NVIDIA model families (e.g., Llama, Qwen, DeepSeek).

- **Generation budget / compute accounting.** The paper tracks three resource dimensions:
  - **Training tokens**: Total number of tokens consumed during the elastic training pipeline (110B tokens for the full two-stage run). This is compared against estimated token budgets for pretraining from scratch (39.5T tokens for the 12B model, with proportional estimates for 9B and 6B) and for Minitron-SSM compression (~760B total tokens for exploratory + final distillation across both 9B and 6B targets).
  - **Deployment memory**: Total GPU memory required to store all model variants in BF16 precision (Table 3). The elastic approach stores only the largest model plus router metadata, while sequential methods store each variant independently.
  - **Sequence length**: Stage 1 uses 8,192 tokens; Stage 2 uses 49,152 tokens. The paper does not report FLOPs directly; the token counts serve as the primary compute proxy.

- **Cross-validation / statistical protocol.** The paper does not describe a cross-validation protocol for the main results. The test set evaluations are single-pass — each benchmark is evaluated once with pass@1 on the specified shots, and the results are reported as point estimates without confidence intervals, error bars, or statistical significance tests. The importance estimation phase uses 1024 calibration samples, but the model selection and hyperparameter tuning protocol (whether results were selected based on validation performance or cherry-picked from a single training run) is not described.

### Main Quantitative Results

#### Multi-Budget Nested Compression on Reasoning Benchmarks

The headline result appears in Table 1: the Nemotron-Elastic-12B model achieves an average accuracy of **77.41** across all six benchmarks (MATH-500, AIME-2024, AIME-2025, GPQA, LiveCodeBench v5, MMLU-Pro), compared to **77.38** for the independently trained NanoV2-12B baseline — a difference of +0.03 percentage points. The paper characterizes this as "competitive performance," which is accurate: the elastic 12B variant matches the pretrained baseline within measurement noise.

The two nested sub-models demonstrate the multi-budget capability:
- **Nemotron-Elastic-9B** and **Nemotron-Elastic-6B** are both extracted zero-shot from the same single training run that produced the 12B variant, requiring no additional fine-tuning or distillation.
- The paper states these nested models "achieve competitive or superior accuracy compared to independently trained baselines" (Section 1), and the deployment memory numbers in Table 3 show that all three models together require only **~26 GB** in BF16 (the 12B model plus router metadata), compared to **~24 GB for NanoV2-12B alone** — meaning the second and third models add negligible storage cost.

However, the paper does not provide a direct side-by-side benchmark table comparing Nemotron-Elastic-6B against an independently trained 6B baseline, nor Nemotron-Elastic-9B against an independently trained 9B baseline, on the full benchmark suite. The only per-benchmark breakdowns provided are for the three-stage ablation analysis (Tables 4 and 5), which report a subset of benchmarks (MATH-500, AIME-2025, GPQA) but do not include the independently trained baselines for comparison. This makes it impossible to verify the "competitive or superior" claim for the 6B and 9B variants from the evidence presented in the paper.

#### Training Token Efficiency (Table 2)

The paper quantifies training cost reduction through token budget comparisons:

- **Nemotron Elastic**: **110B tokens** total to produce all three variants (12B, 9B, 6B) from a single training run.
- **Minitron-SSM**: Estimated at **~760B tokens** to produce the 9B and 6B variants through sequential compression (~380B tokens per target size, covering exploratory search + final distillation). This represents a **~7× reduction** for Nemotron Elastic.
- **Pretraining from scratch**: Estimated at **~39.5T tokens** to train the 12B model plus proportional estimates for 9B and 6B variants. This represents a **~360× reduction** for Nemotron Elastic.

The cost scaling property is formalized in Equations 52-53: Minitron-style methods have linear cost scaling `Tokens(n) = n × (Tokens_explore + Tokens_KD)`, while Nemotron Elastic has constant cost `Tokens(n) ≈ Tokens_elastic-KD ≈ constant` because all nested sub-networks are optimized simultaneously with shared gradient computation.

**Caveat on the token estimates for baselines.** Table 2 includes a note: "Token budgets for Minitron-SSM 6B, pretraining 9B, and 6B NanoV2 models are estimated based on the token counts for pretraining and compressing the NanoV2 12B model." This means the 360× and 7× comparisons are not measured head-to-head — the baseline token counts are extrapolated from the 12B numbers rather than empirically measured for each target size. The extrapolation is plausible (pretraining cost scales roughly with parameter count, and Minitron-SSM cost scales per-target-size), but the paper does not provide the exact scaling factors or verify them experimentally.

#### Deployment Memory Efficiency (Table 3)

The elastic architecture's nested weight-sharing enables significant deployment memory savings:

- **Nemotron Elastic** (storing all three models — 12B, 9B, 6B): **~26 GB** (24 GB for the 12B parent + ~0.4 GB router overhead + negligible slicing metadata).
- **NanoV2 standalone** (storing only the 12B and 9B variants independently): **~46 GB** (24 GB + 22 GB for the two separate checkpoints).

The paper claims "Nemotron Elastic uses 43% less memory than NanoV2's two models" (Table 3 caption), and this is accurate for the specific comparison presented. However, the comparison is asymmetric: Nemotron Elastic stores three models versus NanoV2's two. If NanoV2 also stored three models (12B, 9B, 6B), the independent storage would be approximately 24 + 22 + 12 = ~58 GB, making Nemotron Elastic's advantage roughly 55% (26 GB vs. 58 GB). The paper's 43% figure understates the advantage by comparing against only two baseline models.

The memory scaling laws are formalized in Equations 54-55: independent storage scales as `Memory(n) = Σ Size(Model_i)`, while nested storage scales as `Memory(n) = Size(Model_max) + ε_router` where `ε_router < 0.02 × Size(Model_max)`. The paper argues this is "particularly valuable for edge deployment scenarios where multiple model sizes must be available to handle varying workloads or user-selected quality-latency tradeoffs" (Section 3.2).

#### Effects of Two-Stage Training (Table 4)

Table 4 reports per-benchmark accuracy improvements from Stage 1 (short-context, 8K tokens) to Stage 2 (extended-context, 49K tokens) across three model sizes and three benchmarks:

| Model | Benchmark | Stage 1 | Stage 2 | Absolute Gain | Relative Gain |
|---|---|---|---|---|---|
| 6B | MATH-500 | 95.15 | 96.50 | +1.35 | +1.4% |
| 6B | AIME-2025 | 56.88 | 68.13 | +11.25 | +19.8% |
| 6B | GPQA | 49.12 | 53.78 | +4.66 | +9.5% |
| 9B | MATH-500 | 97.13 | 97.25 | +0.12 | +0.1% |
| 9B | AIME-2025 | 68.75 | 75.42 | +6.67 | +9.7% |
| 9B | GPQA | 59.43 | 62.50 | +3.07 | +5.2% |
| 12B | MATH-500 | 97.27 | 97.70 | +0.43 | +0.4% |
| 12B | AIME-2025 | 72.92 | 75.83 | +2.91 | +4.0% |
| 12B | GPQA | 62.50 | 63.25 | +0.75 | +1.2% |

The pattern is stark: **the largest relative gains from extended-context training occur on the hardest reasoning benchmark (AIME-2025) for the smallest models**. The 6B variant gains +19.8% on AIME-2025 from Stage 2 alone, while the 12B variant gains only +4.0%. On MATH-500 (an easier benchmark), the gains are minimal (0.1% to 1.4%). On GPQA (graduate-level science, intermediate difficulty), the gains are moderate (1.2% to 9.5%).

This pattern supports the paper's central claim: "reasoning tasks require extended-context training to achieve competitive performance" (Section 3.3). The disproportionate benefit for smaller models on the hardest benchmark suggests that smaller variants particularly struggle with multi-step reasoning under short-context training — their limited capacity makes them more dependent on the long-context adaptation to maintain coherence across extended chains of thought.

However, the paper only reports three benchmarks in Table 4 (MATH-500, AIME-2025, GPQA) rather than the full six-benchmark suite from Table 1. AIME-2024, LiveCodeBench v5, and MMLU-Pro are omitted from the two-stage analysis, making it impossible to assess whether the Stage 2 improvement pattern generalizes across all reasoning tasks or is specific to the three reported benchmarks.

#### Impact of Budget Sampling Strategy (Table 5)

Table 5 ablates the Stage 2 sampling distribution by comparing uniform sampling `p(budget) = 1/3` against the adjusted non-uniform distribution `p(12B) = 0.5, p(9B) = 0.3, p(6B) = 0.2`:

| Model | Benchmark | Uniform Sampling | Adjusted Sampling | Gain |
|---|---|---|---|---|
| 6B | MATH-500 | 96.40 | 96.50 | +0.10 |
| 6B | AIME-2025 | 67.92 | 68.13 | +0.21 |
| 6B | GPQA | 55.06 | 53.78 | −1.28 |
| 9B | MATH-500 | 97.13 | 97.25 | +0.12 |
| 9B | AIME-2025 | 75.63 | 75.42 | −0.21 |
| 9B | GPQA | 63.25 | 62.50 | −0.75 |
| 12B | MATH-500 | 97.63 | 97.70 | +0.07 |
| 12B | AIME-2025 | 72.29 | 75.83 | +3.54 |
| 12B | GPQA | 61.11 | 63.25 | +2.14 |

The key finding: **uniform sampling substantially degrades the 12B model** on the hardest benchmarks while the 6B model remains stable or improves slightly. On AIME-2025, the 12B variant loses 3.54 percentage points under uniform sampling; on GPQA, it loses 2.14 points. The 6B variant actually gains slightly on GPQA under uniform sampling (+1.28), consistent with the paper's explanation: uniform sampling biases gradient updates toward smaller variants (which have larger per-parameter gradients), pulling shared weights away from configurations that benefit the full model.

The adjusted sampling largely recovers the 12B model's performance while preserving smaller-variant accuracy within ~1 percentage point of the uniform-sampling results. This ablation provides the primary evidence for the paper's claim that "multi-budget training requires careful load balancing to prevent negative transfer between budget targets" (Section 3.3).

### Ablation Studies and Robustness Checks

**Two-stage training necessity**: The paper does not report an ablation where Stage 2 is omitted entirely (i.e., evaluating the model after Stage 1 only on the full benchmark suite). Table 4 shows per-benchmark Stage 1 vs. Stage 2 numbers, which demonstrate improvement from Stage 2, but does not include a separate training run that stops after 65B tokens at short context and is evaluated on all six benchmarks. The paper's implicit claim that "Stage 2 is necessary for competitive reasoning performance" is supported for the three reported benchmarks but not verified on the full evaluation suite.

**Extended context length (49K vs. alternatives)**: The paper does not ablate the choice of extended-context length. Is 49K specifically important, or would 16K or 32K suffice? Does performance plateau at 49K or continue improving with even longer contexts? These ablations are relevant because extended-context training is expensive (reduced batch size from 1536 to 512, longer per-sample computation) and understanding the minimum effective context length would inform practical deployment decisions.

**Frozen vs. trainable teacher**: Despite discussing both modes extensively in Section 2.3.3, the paper does not report an ablation comparing frozen-teacher against trainable-teacher distillation. The main results use frozen teacher exclusively. A comparison would be valuable because the paper claims trainable teachers suffer from "moving target problems" and "self-distillation collapse risk" in multi-budget settings, but provides no empirical evidence for these failure modes. This is a notable omission given the prominence of the frozen-teacher design choice in the methodology.

**Soft vs. hard masking during training (Mode 1 vs. Mode 2)**: Section 2.4.5 describes two mask integration modes (hard selection via argmax logits vs. soft probabilistic combination), but the paper does not specify which mode is used for the main experiments, nor does it ablate the choice. The soft masking mode (Mode 2) is described as providing smoother training signals that "stabilizes early training when the router is uncertain," but this claim is not empirically validated.

**Homogeneous vs. heterogeneous elastification**: Section 2.3.1 describes both homogeneous mode (all layers of a type share the same compression ratio) and heterogeneous mode (each layer independently selects its ratio). The paper does not specify which mode is used for the main experiments, nor does it compare the two modes. The heterogeneous mode is presented as an advantage over prior work (listed as a key contribution: "Heterogeneous elastification: Our router-based search enables layer-wise heterogeneous configurations"), but no results demonstrating its benefit are reported.

**Importance estimation method**: The paper introduces normalized MSE for depth importance (Equation 5) as an improvement over "single-shot or perplexity-based methods," but does not ablate this choice. A comparison of depth ranking quality using normalized MSE vs. perplexity-based ranking vs. random ranking would validate the claimed superiority. The depth importance ablation is particularly important because depth reduction is listed as a key contribution.

**Number of calibration samples for importance estimation**: The paper uses 1024 calibration samples with sequence length 8192. Does importance ranking quality saturate at 1024 samples, or would 256 or 4096 samples produce different rankings? This matters because the importance estimation phase is computationally non-trivial (1024 × 8192 tokens of forward passes for each component type).

**Distillation temperature**: The paper mentions distillation temperature `τ_KD` in Equation 14 but does not specify its value or ablate its choice. Knowledge distillation temperature is known to significantly affect student model quality, and its omission makes the results harder to reproduce.

**Router learning rate sensitivity**: Model parameters use learning rate 9e-5 while router parameters use 1e-2 (111× higher). The paper does not ablate this ratio or show sensitivity analysis. Given that the router makes discrete architecture decisions that heavily impact model quality, the learning rate ratio is a critical hyperparameter whose stability should be demonstrated.

**Gumbel-Softmax temperature annealing schedule**: The paper reports initial temperature 1.0 and final temperature 0.05 but does not specify the annealing schedule (linear, exponential, cosine, step-based). The annealing rate interacts with the logit scaling coefficient (which increases from 1.0 to 10.0), creating a two-dimensional exploration-exploitation schedule whose combined effect is not characterized. An ablation comparing different annealing strategies would strengthen the router training methodology.

**Number of target budgets**: The paper uses three target budgets (6B, 9B, 12B). Does elastic training performance degrade if more budgets are added (e.g., 4B, 5B, 7B, 8B, 10B, 11B)? The training token efficiency advantage (constant cost vs. linear scaling) becomes more pronounced with larger model families, but the paper does not test whether accuracy is maintained when the number of nested sub-networks increases.

### Critical Assessment

#### Claim: Nemotron Elastic achieves competitive accuracy with independently trained baselines while reducing training cost by 360× (vs. pretraining) and 7× (vs. compression).

**What the experiments demonstrate.** The experiments convincingly demonstrate the training token reduction: 110B tokens for all three elastic variants vs. estimated ~760B for sequential compression and ~39.5T for pretraining. The token counts for Nemotron Elastic and the 12B pretraining baseline are measured; the 9B and 6B pretraining estimates and the Minitron-SSM token counts are extrapolated rather than measured. The cost reduction claim therefore rests partly on extrapolation assumptions that are reasonable but not empirically verified.

**What the experiments do not demonstrate.** The paper does not provide a comprehensive accuracy comparison between the elastic 6B and 9B variants and their independently trained counterparts. Table 1 reports only the summary average across six benchmarks for the 12B elastic variant vs. the 12B baseline (77.41 vs. 77.38). The 6B and 9B variants are claimed to be "competitive or superior" but no head-to-head benchmark table is provided. The only per-benchmark numbers for the elastic 6B and 9B appear in Tables 4 and 5 (three benchmarks each), and these do not include the independent baselines. This means the central accuracy-for-cost tradeoff — the paper's primary contribution — cannot be fully assessed for the smaller variants.

**What would strengthen the claim.** A table analogous to Table 1 but with columns for each model size (6B, 9B, 12B) and rows for each benchmark, including both the elastic variants and the independently trained baselines (pretrained and Minitron-SSM), would provide the missing comparison. Without this, the reader must take the "competitive or superior" claim on faith for the 6B and 9B models.

#### Claim: Reasoning models require fundamentally different elastic training strategies, specifically extended-context training and non-uniform budget sampling.

**What the experiments demonstrate.** Tables 4 and 5 provide clear evidence for this claim on the three reported benchmarks (MATH-500, AIME-2025, GPQA). Stage 2 extended-context training provides substantial gains (Table 4), especially for smaller models on hard reasoning tasks (+19.8% for 6B on AIME-2025). Adjusted non-uniform sampling recovers 12B model performance that degrades under uniform sampling (Table 5: +3.54 on AIME-2025, +2.14 on GPQA). These are clean, interpretable results that directly support the paper's narrative.

**What the experiments do not demonstrate.** The claim is validated on three benchmarks but not on the full six-benchmark suite. AIME-2024, LiveCodeBench v5, and MMLU-Pro are absent from the ablation tables. If Stage 2 training provides negligible benefit on MMLU-Pro (a knowledge benchmark rather than a reasoning benchmark), that would be informative — it would suggest the extended-context requirement is specific to multi-step reasoning tasks, not a universal property of "reasoning models." Conversely, if Stage 2 helps on LiveCodeBench (which involves code generation with potentially long reasoning traces), that would strengthen the generality claim. The omission of these benchmarks limits the scope of the conclusion that can be drawn.

Additionally, the paper does not provide evidence that uniform sampling would work for a **non-reasoning** elastic model trained on the same architecture, which would be the appropriate control experiment for the claim that reasoning models are "fundamentally different." Comparing elastic training of a base (non-reasoning) Nano V2 variant with uniform vs. non-uniform sampling would isolate whether the failure mode is reasoning-specific or an artifact of the architecture, training data, or model scale.

#### Claim: End-to-end router training couples architecture search to the actual loss landscape, improving over post-hoc heuristics.

**What the experiments demonstrate.** The paper demonstrates that the end-to-end trained router works — it produces competitive models. However, it does not demonstrate that the router's decisions are better than those that would be produced by post-hoc heuristics (e.g., MatFormer-style MixnMatch, or Minitron-style importance-based search on the frozen checkpoint). There is no ablation where the router is replaced with a fixed, importance-based architecture selection and the elastic model is trained under that fixed architecture. Without this comparison, the benefit of end-to-end router training is asserted but not measured.

The router's contribution could be assessed by: (1) comparing the architectures discovered by the router at convergence against the architectures that importance-only ranking would select at each budget, and (2) evaluating whether the router-discovered architectures achieve higher accuracy than the importance-only architectures when both are distilled with the same frozen teacher. Neither comparison is reported.

#### Claim: Heterogeneous layer-wise elastification enables more optimal configurations than homogeneous (all layers share compression ratio).

**What the experiments demonstrate.** The paper describes the heterogeneous mode in Equations 10 and the corresponding mask generation procedure, but **no experimental results using heterogeneous elastification are reported**. The paper does not state whether the main results use homogeneous or heterogeneous mode, and no comparison between the two is provided. This means the heterogeneous elastification contribution — listed as a key innovation — is entirely unvalidated by the experiments in the paper. The capability exists in the framework but its benefit is not demonstrated.

#### Claim: Frozen-teacher distillation stabilizes multi-budget training compared to trainable teacher.

**What the experiments demonstrate.** The main results use frozen-teacher distillation and achieve competitive performance. However, the paper does not report an ablation with trainable teacher, so there is no empirical evidence that frozen teacher is superior or necessary. The theoretical arguments about moving targets and self-distillation collapse are plausible but unverified. A comparison where the teacher is trainable (with the cross-entropy regularization term `α · L_CE(θ_teacher)` from Equation 15) would either validate the frozen-teacher choice or reveal that trainable teacher works similarly well, potentially simplifying the training pipeline.

#### Additional concerns

**Single model family, single architecture.** All experiments use Nemotron Nano V2 12B. The paper's claims about hybrid architecture elastification, extended-context requirements for reasoning, and router training are validated on exactly one model. The generalizability to other hybrid architectures (Jamba, Zamba), other scales (e.g., 30B, 70B), or other model families (e.g., Llama-based hybrids) is unknown. This is standard for a systems paper introducing a new framework, but it means the paper's contributions should be understood as demonstrated on the specific Nano V2 architecture rather than established as general principles.

**Benchmark suite composition.** The six-benchmark suite includes two AIME variants (2024 and 2025), which are closely related (both are American Invitational Mathematics Examination problems from adjacent years). This means mathematical competition problems are over-represented (AIME-2024, AIME-2025, MATH-500 = 3/6 benchmarks), while other reasoning domains (code generation has only LiveCodeBench v5, scientific reasoning has only GPQA) are under-represented. The average score reported in Table 1 is therefore weighted toward mathematical reasoning capability.

**No statistical rigor.** All results are reported as point estimates without confidence intervals, standard deviations, or significance tests. With a benchmark like MATH-500 (500 test problems), the standard error on a pass@1 accuracy of ~97% is approximately 0.8 percentage points (assuming binomial sampling). The reported difference between Nemotron-Elastic-12B (77.41) and NanoV2-12B (77.38) is 0.03 percentage points on the average across six benchmarks — far within any plausible confidence interval. The paper correctly characterizes this as "competitive performance" rather than claiming superiority, but the absence of error estimates makes it impossible to assess whether any of the reported differences are statistically meaningful or consistent with sampling noise.

**No inference latency or throughput measurements.** The paper emphasizes that elastic models support dynamic deployment across different resource constraints, but reports no latency or throughput measurements for the extracted sub-networks. The 6B variant should be faster than the 12B variant at inference (fewer parameters, fewer active layers, smaller matrices), but the actual speedup is not quantified. This matters because the practical value of elastic deployment is the ability to select model size based on latency constraints — without latency numbers, practitioners cannot determine whether the tradeoff is worthwhile.

**The 12B elastic variant serves as both student and frozen-teacher target.** During training, the 12B elastic variant is a student being distilled toward the frozen teacher, but it is architecturally identical to the teacher (same parameter dimensions when the full budget is selected). The paper does not discuss whether this creates gradient conflict — the 12B student's task loss is essentially trying to match its own pre-trained behavior (since the frozen teacher is the pre-trained 12B model), which is a form of self-distillation. Whether this self-distillation provides useful signal or simply adds noise to the training dynamics is not explored.

## 6. Limitations and Trade-offs

### Limitation 1: Difficulty Estimation Cost Is Not Amortized in the Headline Efficiency Numbers

**The assumption or constraint.** The compute-optimal framework selects the best test-time strategy per question based on a pre-computed difficulty estimate. The paper uses two methods: **oracle difficulty** (the pass@1 rate of the base model over 2048 sampled solutions, requiring ground-truth labels) and **predicted difficulty** (the PRM's average final-answer score over those same 2048 samples, removing the ground-truth requirement but retaining the generation cost). The paper explicitly states in Section 3.2:

> "estimating difficulty in this way still incurs additional computation cost during inference... our experiments do not account for this cost largely for simplicity"

**The consequence.** The reported 4× efficiency gains over best-of-N are computed *after* difficulty is known, without including the cost of learning it. Generating 2048 samples per question to estimate difficulty consumes more compute than the largest test-time budgets studied (256–512 generations). In a realistic deployment, the total cost would be `Cost = DifficultyEstimation + StrategyExecution`, and the former could dominate. This means the headline efficiency figures are an **upper bound on achievable gains**, not realized deployment savings. A practitioner who naively implements this pipeline would discover that the difficulty estimation overhead erases most or all of the claimed efficiency advantage, unless they have a much cheaper difficulty estimator than the paper provides.

**What evidence exists in the paper.** Section 3.2 acknowledges the cost explicitly but does not amortize it. Figures 4 and 8 (the compute-optimal scaling curves) use both oracle and predicted difficulty bins and show they largely overlap, but neither curve includes the cost of obtaining the bin labels. The paper flags this as "a key avenue for future work" in Section 3.2 but provides no prototype solution, no analysis of how difficulty estimation cost scales with the number of questions, and no bound on how cheap difficulty estimation must become for the 4× advantage to survive after amortization.

**Mitigation status.** Not addressed. The paper suggests future work on "pretraining or finetuning models to directly predict difficulty of a question" (Section 8) and mentions adaptive difficulty estimation as a conceptual direction, but provides no implementation or analysis. This is the single largest barrier between the paper's analytical results and practical deployment.

### Limitation 2: Hard Problems (Difficulty Bin 5) Are Completely Unaffected by Test-Time Compute

**The assumption or constraint.** The paper's compute-optimal framework assumes that the base model has a non-trivial pass@1 rate on the target problem — that there exist correct solutions in the proposal distribution to find or refine. For the hardest questions (difficulty bin 5, where pass@1 is near zero), this assumption is violated.

**The consequence.** Across all methods — PRM search, iterative revisions, and their compute-optimal combinations — the hardest questions show **near-zero improvement** regardless of compute budget. In Figure 3 (right), bin 5 accuracy hovers at 1–3% for all methods at all generation budgets up to 256. In Figure 7 (right), bin 5 shows roughly 2–3% accuracy irrespective of the sequential-to-parallel ratio. In Figure 9 (the FLOPs-matched comparison), the bin 5 scaling line is essentially flat near 0–5%, and the 14× larger pretrained model dramatically outperforms test-time compute on these problems (e.g., −52.9% relative disadvantage for PRM search at R ≫ 1). The paper is transparent about this in Section 7:

> "On the hardest questions (bin 5), no method makes meaningful progress — the base model simply lacks the capability to produce correct solutions regardless of how the budget is allocated."

This means the approach offers **no path forward for genuinely novel or out-of-distribution reasoning** that exceeds the base model's training distribution. If a deployment scenario includes a non-trivial fraction of problems that are fundamentally outside the base model's reach, test-time compute cannot help — only larger-scale pretraining can.

**What evidence exists in the paper.** Figure 3 (right, bin 5 subplot), Figure 7 (right, bin 5 data point), and Figure 9 (bottommost blue line) all show flat or near-zero accuracy for the hardest bin across all methods and budgets. The FLOPs-matched comparison in Figure 1's bar charts quantifies the disadvantage: for hard problems, test-time compute with PRM search underperforms the larger model by 3.6% to 52.9% depending on the R ratio.

**Mitigation status.** The paper explicitly acknowledges this boundary condition and does not claim to solve it. The takeaway in Section 7 clearly states: "test-time compute amplifies existing capability but does not create it from nothing." This is not a flaw in the method — it is a fundamental capability bound that practitioners must understand when deciding between investing in pretraining versus inference compute. The limitation is well-characterized but inherently unsolvable within the test-time compute paradigm.

### Limitation 3: Revisions and PRM Search Are Evaluated Independently — Their Combination Is Not Tested

**The assumption or constraint.** The paper studies two complementary axes for test-time computation — modifying the proposal distribution via iterative revisions and modifying the verifier via PRM-guided search — but evaluates them in **separate experimental pipelines**. The revision experiments (Section 6) use a revision-specific ORM for answer selection but do not incorporate PRM beam search or lookahead search into the revision generation process. The PRM search experiments (Section 5) use the base few-shot prompted model as the proposal distribution, not the revision model.

**The consequence.** The paper's reported results represent a **lower bound** on what a fully integrated system could achieve, because the two mechanisms have complementary, difficulty-dependent strengths that the paper itself documents: revisions improve the proposal distribution on easy problems (where local refinement suffices), while PRM search improves candidate selection on medium problems (where broader exploration is needed). A combined system — using the revision model as the proposal distribution within beam search, or using the PRM's per-step scores to guide which revisions to pursue — could potentially outperform either mechanism alone, especially on medium-difficulty problems where both mechanisms show non-trivial individual gains. The paper's compute-optimal policy selects between search and revisions per problem, but never deploys both simultaneously.

The paper acknowledges this gap in Section 8:

> "we did not experiment with PRM tree-search techniques in combination with revisions"

**What evidence exists in the paper.** Figures 3 (right) and 7 (right) document the difficulty-dependent strengths of each approach individually. Figure 3 shows that beam search outperforms best-of-N on medium problems (bins 3–4); Figure 7 shows that a balanced sequential-parallel ratio is optimal on the same difficulty range. These complementary patterns suggest that combining the two — running beam search where each beam is generated by the revision model, or using the PRM to score revision steps — could yield additive gains. But no experiment tests this. The compute-optimal curves (Figures 4 and 8) select the best *individual* strategy per bin, not the best *combined* strategy.

**Mitigation status.** The paper explicitly identifies this as future work in Section 8. The experimental infrastructure for combining them exists — both the revision model and the PRM are trained, and the search algorithms are implemented — but the combination is not evaluated. This is a significant gap because it means the paper's headline results (4× efficiency gains, FLOPs-matched advantages) may understate what is achievable with a fully unified system. For a practitioner deciding whether to deploy this approach, the independent evaluation means they must either run their own combination experiments or accept that the reported gains are a conservative estimate.

### Limitation 4: All Results Are on a Single Benchmark (MATH) with a Single Model Family (PaLM 2-S*)

**The assumption or constraint.** The paper's entire experimental validation — all search algorithm comparisons, all revision model analyses, all compute-optimal scaling curves, and the FLOPs-matched tradeoff — is conducted on the MATH benchmark (500 test questions) using the PaLM 2-S* model family. The paper states in Section 4 that the authors "believe this model is representative of the capabilities of many contemporary LLMs," but provides no cross-model or cross-benchmark validation.

**The consequence.** Generalizability is unknown and potentially limited. Several aspects of the findings could be model-specific or benchmark-specific:

- The PRM's quality and over-optimization behavior depend on PaLM 2-S*'s output distribution and calibration properties. A model with different error patterns (e.g., one that makes different types of mistakes at different steps) might exhibit different difficulty-dependent scaling curves for search.
- The revision model's ability to learn from incorrect in-context examples depends on the base model's in-context learning strength, which varies substantially across model families (e.g., GPT-4 vs. Claude vs. Llama).
- The MATH benchmark consists exclusively of competition-level math problems requiring symbolic reasoning. The paper's core finding — that test-time compute is most effective on easy-to-medium problems within the model's capability range — may or may not generalize to other reasoning domains like code generation, logical deduction, or scientific QA, where the nature of "difficulty" and the base model's error modes differ.
- The difficulty thresholds (which problems fall into which quintile) are defined relative to PaLM 2-S*'s pass@1 distribution. A stronger or weaker base model would produce different quintile boundaries, and the optimal strategies per quintile might shift.

**What evidence exists in the paper.** All tables and figures (Figures 3–9, Tables 1–2 in the summary) report results on MATH with PaLM 2-S*. The paper includes no experiments on other benchmarks (e.g., GSM8K, HumanEval, MMLU) or with other model families. The test set of 500 questions, split into five difficulty quintiles of ~100 each and further split by two-fold cross-validation for strategy selection, means the compute-optimal policy is selected based on ~50 questions per fold per bin — a small sample that introduces variance the paper does not quantify (no confidence intervals are reported).

The paper's FLOPs-matched comparison additionally assumes the 14× larger model is not compute-optimally trained (the paper scales parameters only, not data, following the LLaMA paradigm rather than Chinchilla-optimal training). This is acknowledged in Section 7 but means the pretraining baseline may be weaker than a properly compute-optimal larger model would be, potentially inflating the apparent advantage of test-time compute.

**Mitigation status.** The paper acknowledges the single-benchmark/single-model limitation implicitly (by framing the PaLM 2-S* choice as "representative" and noting the Chinchilla caveat) but does not address it experimentally. Section 8 does not propose cross-model or cross-benchmark replication as future work. For a practitioner using a different model family or targeting a different reasoning domain, the paper provides no guidance on whether the findings transfer or how to adapt the methodology.

### Limitation 5: No Latency or Wall-Clock Time Analysis — Only Generation Count Is Used as the Cost Metric

**The assumption or constraint.** All experiments measure compute in "generations" — the number of complete solutions sampled, which is a reasonable proxy for total FLOPs. However, this metric ignores **latency** (wall-clock time per query). Different test-time strategies have fundamentally different serial dependencies: sequential revisions are inherently serial (each revision depends on the previous one), while parallel best-of-N can be executed simultaneously with sufficient hardware. A strategy that allocates 128 generations as 64 sequential × 2 parallel chains takes roughly 64× longer wall-clock time than one that runs 128 parallel samples simultaneously, even though both consume the same total FLOPs.

**The consequence.** The sequential-heavy strategies favored by the compute-optimal policy on easy problems (where purely sequential revisions are optimal per Figure 7, right) may be **impractical for latency-sensitive applications** regardless of their FLOPs efficiency advantages. Interactive assistants, real-time code generation, and live tutoring systems cannot tolerate the latency of generating 10–20 sequential revisions when a single parallel-best-of-16 might produce an acceptable answer in a fraction of the wall-clock time.

The paper's 4× efficiency gains are measured in generations, not seconds. A practitioner deploying this in a latency-bounded setting needs to know: for a fixed latency budget (e.g., 500ms), which strategy maximizes accuracy? The paper does not answer this question. The tension between sequential revisions (high FLOPs efficiency, high latency) and parallel sampling (lower FLOPs efficiency, low latency) is a fundamental tradeoff that the compute-optimal framework, as presented, does not optimize over.

**What evidence exists in the paper.** The paper does not report any latency measurements, throughput numbers, or wall-clock time analyses. The generation budget is used as the universal cost metric throughout (Sections 5–7). The sequential nature of revisions is described in Section 6.1 and the parallel-vs-sequential tradeoff is analyzed in Figure 7, but only through the lens of accuracy at a fixed generation budget — not through the lens of accuracy at a fixed latency budget. The paper never discusses the implications of serial dependencies for deployment latency.

**Mitigation status.** Not addressed. The paper does not acknowledge latency as a missing dimension of the analysis, nor does it suggest latency-aware compute-optimal scaling as future work. This is a notable omission because the sequential-vs-parallel tradeoff is one of the paper's central design axes (Section 6.1 and Figure 7), and the practical relevance of the framework depends heavily on whether the optimal FLOPs-efficient strategy is also feasible under real-time constraints.

### Limitation 6: The Revision Model Has a 38% Correct-to-Incorrect Reversion Rate, and the Mitigation Is Incomplete

**The assumption or constraint.** The revision model is trained exclusively on trajectories where all in-context answers are incorrect (followed by a correct target). This means the model never sees examples of what to do when the current answer is already correct. At test time, the model may encounter correct answers in its revision chain and — because it has no training signal for this situation — may incorrectly "revise" a correct answer into an incorrect one.

**The consequence.** The paper reports that approximately **38% of correct answers get converted back to incorrect ones** during sequential revision (Section 6.1). This means that as the revision chain grows longer, the expected accuracy does not monotonically increase — each revision step has a non-trivial probability of destroying a previously correct answer. The paper mitigates this with answer selection across the entire chain (majority voting or verifier-based selection, picking the best answer from any point in the chain rather than always taking the last revision). However, this mitigation is imperfect: if the chain length is L and the reversion probability is p = 0.38, then for a correct answer to survive to the end and be selectable, it must either be produced late in the chain or survive all subsequent revision steps without being reverted — a constraint that limits the effective benefit of long revision chains.

This training data construction bias is not an implementational oversight — it is a consequence of the offline trajectory construction method (pairing randomly sampled incorrect answers with correct answers at edit-distance proximity). The method cannot naturally produce training examples where the current answer is correct and no revision is needed, because such examples would be degenerate (input = output) and provide no learning signal.

**What evidence exists in the paper.** Section 6.1 reports the 38% reversion rate explicitly. Figure 6 (left) shows that pass@1 per revision step does improve over the chain (from ~18% at step 1 to ~24–25% by steps 15–20), suggesting the revision skill outweighs the reversion penalty on average, but the improvement plateaus rather than continuing to climb — likely because the reversion rate caps the benefit of additional revisions. The ReSTᵉᴹ experiment (Appendix K, Figure 16) shows that attempting to further optimize the revision model with RL-style training causes performance to **degrade substantially** with sequential revisions, suggesting the revision training is fragile and sensitive to data distribution.

**Mitigation status.** Partially addressed. The within-chain selection mechanism (majority voting or verifier) reduces the impact of reversions by not forcing the system to use the last revision, but this is a post-hoc patch rather than a solution to the underlying training data bias. A more principled approach — training the model with explicit "no revision needed" examples, or incorporating a classifier that detects when a current answer is likely correct and terminates the chain — is not explored. The paper does not propose future work on reducing the reversion rate, and the 38% figure represents a hard ceiling on the accuracy gains achievable from sequential revision depth: even with infinite revisions, the system cannot exceed the accuracy of the best answer in the chain minus the reversion-induced degradation.

## 7. Implications and Future Directions

### How This Work Changes the Landscape

Nemotron Elastic shifts the model compression conversation from **sequential, per-target distillation pipelines** toward **simultaneous, many-in-one elastic training** where a single run produces an entire family of models at different parameter budgets. The magnitude of this shift is best characterized as a **methodological reframing with outsized practical implications** rather than a paradigm shift — the core techniques (knowledge distillation, structured pruning, nested weight-sharing) are individually established, but their integration into a unified elastic reasoning framework with end-to-end learned routing changes the economics of model family development from linear-cost to constant-cost scaling.

The most significant practical reframing is straightforward: **training a model family no longer requires separate training runs**. Prior to this work, if an organization wanted to serve 6B, 9B, and 12B reasoning models, they faced three unpalatable options: (1) train all three from scratch (~39.5T tokens each, by the paper's estimates, multiplying infrastructure costs by 3×), (2) train the largest from scratch and sequentially compress each smaller variant through Minitron-style exploration + distillation (~760B additional tokens for two smaller models, per Table 2), or (3) deploy only the largest model and accept wasted resources on simpler queries. Nemotron Elastic replaces all three options with a single 110B-token training run whose cost is **independent of the number of target sizes** (Equation 53: `Tokens_Elastic(n) ≈ constant`). The practical consequence — 360× less training than pretraining from scratch, 7× less than sequential compression — changes the affordability calculation for organizations that previously could not justify building model families.

The conceptual shift that enables this is the paper's **coupling of architecture search to the training objective through end-to-end router training**. Prior work on elastic architectures (MatFormer, Flextron) and structured pruning (Minitron, Minitron-SSM) shared a common pattern: architecture decisions were made before training (via static importance scores) or after training (via post-hoc heuristics), never during training with gradient feedback from the actual loss landscape. The paper's router networks — small two-layer MLPs receiving gradients through Gumbel-Softmax from the distillation loss — make architecture search part of learning rather than a pre-processing step. This means the architectures discovered for 6B, 9B, and 12B variants are **distillation-objective-aware**: they evolve to minimize KL divergence to the frozen teacher, not just to satisfy a generic importance ranking computed on the uncompressed model. The paper does not empirically prove that this routing outperforms static importance-based selection (no router-replacement ablation is reported), but the conceptual architecture — making architecture decisions respond to the loss landscape — represents a design pattern that future compression frameworks can adopt regardless of whether this particular router architecture is optimal.

The paper also **reconciles a previously unarticulated tension** between two trends: the rise of hybrid Mamba-Attention architectures (Jamba, Zamba, Nemotron-H) and the need for model family diversity in deployment. Prior compression work was split across two non-overlapping categories: pure-Transformer elastic methods (MatFormer, Flextron) could not handle Mamba's structural constraints, and hybrid compression methods (Minitron-SSM) lacked nested weight-sharing, requiring separate distillation per target size. Nemotron Elastic resolves this by introducing **group-aware SSM elastification** (Section 2.4.2, Equation 25) that preserves Mamba's structural constraints while enabling simultaneous multi-budget optimization. The practical significance depends on the trajectory of hybrid architecture adoption, but given that models like Nemotron-H achieve 3× inference speedup by replacing 92% of attention layers with Mamba-2 blocks, the capability to elastically compress such architectures is likely to become infrastructure rather than novelty.

The paper also identifies a **diagnostic contribution** that changes how the field should think about reasoning model compression: uniform budget sampling, the default in prior elastic training, **actively harms the largest model** during extended-context reasoning adaptation (Table 5: 12B loses 3.54 pp on AIME-2025). This is not a general optimization problem — it is specific to the intersection of elastic weight-sharing, long-context reasoning sequences, and capacity-asymmetric gradient competition. The finding reframes elastic reasoning model training as requiring **budget-aware curriculum design**, and future work in this area inherits this constraint as a necessary design element rather than an optional enhancement. Prior work could not have identified this failure mode because reasoning models with extended chain-of-thought were not targets of elastic compression.

One research direction becomes **less attractive** as a result of this paper: the development of increasingly complex post-hoc sub-network selection heuristics for elastic models. MatFormer's MixnMatch and Flextron's input-adaptive routing represent sophisticated post-hoc architecture selection strategies, but the paper's end-to-end router training suggests that the more impactful axis is **learning architecture decisions during training** rather than engineering better heuristics for post-hoc selection. A heuristic cannot respond to the distillation loss landscape because it is defined before that landscape exists. The paper's routers can, and while the empirical advantage is not yet proven (no head-to-head comparison against MixnMatch or Flextron routing on these benchmarks), the conceptual argument — that gradient-based architecture search captures interactions that static importance scores miss — is more aligned with the broader deep learning trend toward end-to-end learning.

### Follow-Up Research This Work Enables

**Direct router vs. static architecture ablation on reasoning benchmarks.** The paper's most critical unvalidated claim is that end-to-end router training produces better architecture decisions than the static importance-based selection used in Minitron and MatFormer. A clean ablation would: (1) compute importance rankings for all elastic dimensions (embedding, FFN, attention heads, Mamba components, depth) on the frozen pre-trained 12B model using activation magnitudes (for width) and normalized MSE (for depth) as described in Section 2.1, (2) select architectures for 9B and 6B budgets by taking the top-k components from each ranking to match the target parameter counts, (3) train these fixed architectures with the same frozen-teacher distillation and two-stage curriculum as Nemotron Elastic, and (4) compare downstream benchmark accuracy. If the router-matched architectures perform similarly to the static architectures, the router's contribution is primarily convenience (automatic architecture selection) rather than quality improvement. If the router significantly outperforms static selection, the paper's claim that "decoupling architecture search from training is suboptimal" is empirically validated. This experiment requires no new infrastructure — it uses the same training pipeline but replaces the Gumbel-Softmax router outputs with fixed binary masks. The AIME-2025 and GPQA benchmarks are the most informative for this comparison because they show the largest sensitivity to architecture quality in the paper's existing ablations.

**Router decision interpretability and architecture pattern analysis.** The router networks produce specific architecture decisions per budget per dimension — e.g., at 6B, the router selects 18 Mamba heads, 4096 embedding channels, 8192 FFN intermediate neurons, and 28 layers. The paper reports none of these decisions. Extracting and analyzing the learned configurations across all budgets would answer several open questions: (1) Does the router compress all dimensions proportionally, or does it preferentially retain certain component types (e.g., preserving more attention heads while aggressively compressing FFN, or vice versa)? (2) How do these preferences vary across budgets — is the 6B model a uniformly scaled-down 12B, or does it have qualitatively different architecture proportions? (3) In heterogeneous mode (where per-layer compression ratios differ), which layers are preserved and which are compressed — do middle layers retain more capacity than input/output layers, consistent with depth-wise importance patterns documented in the pruning literature? (4) How much variance is there across multiple training runs with different random seeds — does the router converge to a stable architecture or are there multiple equally good configuration basins? This analysis requires no new experiments beyond logging router outputs during the existing training pipeline, but it would transform the paper's results from a black-box demonstration into an interpretable contribution that guides architecture design for future elastic models.

**Frozen vs. trainable teacher distillation head-to-head.** The paper makes strong theoretical arguments for frozen teachers (Section 2.3.3): moving target problems from simultaneous student-teacher updates, self-distillation collapse risk for the full-budget student that is architecturally identical to the teacher, and instability from non-uniform budget sampling. However, no empirical comparison is provided. A controlled experiment would run the identical two-stage pipeline with a trainable teacher (Equation 15: `L_teacher = L_KD(θ_student, θ_teacher) + α · L_CE(θ_teacher)`) and compare against the frozen-teacher baseline on all six benchmarks. The comparison is not trivial because the trainable teacher's `α · L_CE` regularization term must be tuned — too small and self-distillation collapse occurs; too large and the teacher drifts from its pre-trained behavior, potentially degrading the distillation signal. Sweeping `α ∈ {0.1, 0.5, 1.0, 5.0}` and reporting the Pareto frontier of 12B accuracy vs. 6B/9B accuracy would characterize the teacher-student stability tradeoff. If trainable teacher matches frozen-teacher performance at any `α`, the training pipeline is simpler (no need to maintain a separate frozen teacher in memory). If frozen teacher is consistently superior, the paper's theoretical argument is empirically validated and future multi-budget elastic training should default to frozen teachers.

**Cross-architecture generalization: applying Nemotron Elastic to Jamba or Zamba.** All experiments use the Nemotron Nano V2 12B architecture. The method's claimed generality — specifically, the group-aware Mamba elastification and the two-stage reasoning curriculum — is untested on other hybrid architectures. Replicating the full pipeline on Jamba (which uses a different Mamba-Attention ratio) or Zamba (which may have different Mamba group structures) would test whether the group-aware masking operators and the importance estimation procedure transfer without modification, or whether architecture-specific adaptations are needed. The key measurements are: (1) whether the Mamba importance estimation procedure (Equations 3-4) produces valid, structurally consistent rankings for different Mamba-2 configurations (different numbers of groups, different heads per group), (2) whether the extended-context requirement (49K tokens) for reasoning performance generalizes — does a Jamba reasoning model also need extended-context adaptation, or was this specific to Nano V2's training recipe? This is a stress test rather than an extension: a negative result (Nemotron Elastic fails on a different hybrid architecture without modification) would bound the method's applicability, while a positive result would establish it as a general framework.

**Scaling the number of nested sub-networks:** The paper produces three variants (6B, 9B, 12B). The constant-cost property (`Tokens_Elastic(n) ≈ constant`) predicts that adding more target budgets (e.g., 4B, 5B, 7B, 8B, 10B, 11B) should not increase training cost substantially. Testing this prediction by training an elastic model with 5–7 nested budgets would validate the scalability claim that distinguishes Nemotron Elastic from sequential compression (where cost scales linearly). The key risk is **accuracy degradation from budget dilution**: as more sub-networks share the same parameter space, the gradient competition between budgets may intensify, and the non-uniform sampling strategy that works for three budgets (0.5, 0.3, 0.2) may fail for seven (requiring an even more skewed distribution that under-trains the smallest variants). Measuring per-budget accuracy as a function of the number of nested variants, at fixed total training tokens, would establish the practical limit of the constant-cost property and inform how many deployment targets a single elastic training run can realistically support.

**Hard-problem failure mode characterization: Is bin 5 improvement fundamentally impossible, or just not achieved with this budget?** The hardest difficulty bin shows near-zero accuracy improvement across all methods and budgets in the prior sections' analysis (bin 5 at 1–3% regardless of generation count or strategy). Nemotron Elastic does not report difficulty-bin-level analysis, but the same question applies: does the 6B elastic variant utterly fail on the hardest reasoning problems (AIME-2025 competition problems, for instance), or does it maintain some non-zero capability inherited from the 12B parent's representations? A fine-grained difficulty analysis on the AIME-2025 benchmark — bucketing problems by the 12B model's pass@1 rate and measuring 6B, 9B, and 12B elastic variant accuracy per bucket — would characterize whether elastic compression preserves capability proportionally across difficulty levels or disproportionately sacrifices hard-problem performance. If the 6B variant's accuracy on the hardest problems drops to near zero while the 9B retains some capability, that suggests a minimum parameter threshold for complex reasoning that elastic compression cannot cross — valuable deployment guidance. If the 6B retains proportional capability (e.g., 50% of the 12B's accuracy on hard problems), elastic compression is more robust than pruning-based compression (which often disproportionately sacrifices tail performance).

### Practical Applications and Downstream Use Cases

**Single-checkpoint deployment across heterogeneous hardware.** An organization serving an LLM-powered product faces diverse deployment constraints: cloud instances with A100 GPUs can run a 12B model with generous latency budgets, while on-device or edge deployments (laptops, mobile devices) have memory and compute constraints that require 6B or smaller models. Without elastic models, the organization must train, maintain, and deploy separate checkpoints for each hardware tier — multiplying storage costs, deployment complexity, and model update synchronization effort. With Nemotron Elastic, a single 12B checkpoint (stored once, at ~24 GB in BF16) can be sliced zero-shot to produce optimized 9B and 6B variants for edge deployment. Table 3 quantifies the storage advantage: three models via Nemotron Elastic require ~26 GB total (the 12B parent + <2% router overhead) versus ~58 GB for independently stored checkpoints. When model updates are released (e.g., fine-tuning on new data, patching safety vulnerabilities), only one checkpoint must be updated and redistributed. The slicing operation is computationally negligible (no forward/backward passes), so edge devices with limited compute can still perform slicing locally if needed, or pre-sliced variants can be distributed from a central server.

**Cost-efficient data generation for self-improvement pipelines.** Self-improvement methods like STaR, ReSTᵉᴹ, or rejection sampling fine-tuning require generating high-quality reasoning traces from a model to use as training data for the next iteration. The cost of this generation phase scales with model size: generating traces with a 12B model costs approximately 2× more FLOPs per token than a 6B model. A compute-optimal data generation pipeline could use the 12B elastic variant for hard problems (where the 6B variant might produce incoherent or incorrect reasoning traces) and the 6B variant for easy problems (where the full model's capacity is unnecessary). The elastic deployment property — all variants available from a single checkpoint — means this routing can be implemented without storing or loading separate models. A difficulty estimator (perhaps trained on the 12B model's confidence scores or a lightweight classifier) could route each training example to the appropriate elastic variant, reducing total generation FLOPs while maintaining trace quality. The paper provides the infrastructure (multi-budget variants from one checkpoint) but not the routing policy; a practical self-improvement system would combine elastic deployment with a lightweight difficulty estimator, amortized over the generation cost.

**Latency-adaptive serving with dynamic budget selection.** Production LLM serving systems face variable query loads and latency requirements. During peak traffic, a service might need to drop from 12B to 9B or 6B inference to maintain throughput under latency SLOs. With independent models, this requires pre-loading multiple model instances into GPU memory — expensive and wasteful. With Nemotron Elastic, a single loaded 12B instance can be dynamically sliced to produce 9B or 6B inference paths by applying the router's masks (without physically modifying the checkpoint — the masks can be applied at runtime by zeroing pruned dimensions, equivalent to the training-time dynamic masking in Section 2.4). The paper does not report inference latency numbers, but the architecture implies a latency hierarchy: the 6B variant processes fewer Mamba heads, fewer attention heads, fewer FFN neurons, and fewer layers, producing proportionally faster inference. A serving system that monitors per-request latency and dynamically applies stricter masking to maintain throughput would realize the "dynamic budget selection" that the paper positions as a deployment advantage, though the paper provides no system-level implementation or measurement of this capability.

### When to Prefer This Method

The paper positions Nemotron Elastic against two named alternatives — **pretraining model families from scratch** and **sequential compression via Minitron-SSM** — and the tradeoff is sharp enough to merit explicit decision guidance:

- **Prefer Nemotron Elastic when** you need multiple model sizes from a single parent architecture and your primary constraints are training cost and deployment memory. The headline numbers make the case: 110B tokens produces three variants (6B, 9B, 12B) versus ~760B for sequential compression and ~39.5T for pretraining. The advantage grows with the number of target sizes (constant vs. linear cost scaling). Additionally, if you deploy to memory-constrained environments requiring multiple model sizes (e.g., edge devices with tiered quality-latency options), the nested weight-sharing eliminates cumulative storage costs (26 GB for all three elastic variants vs. 58 GB for independent storage). This preference is especially strong for hybrid Mamba-Attention architectures because no prior elastic method supports them with group-aware constraints.

- **Prefer sequential compression (Minitron-SSM) when** you need to compress a single target size and do not require multi-budget deployment. The sequential approach avoids the complexity of router training, Gumbel-Softmax annealing, and two-stage curriculum design. For a single 12B-to-6B compression, Minitron-SSM's exploration phase can search a broader architecture space (unconstrained by the need to support intermediate budgets simultaneously), potentially discovering configurations that outperform the elastic 6B variant on that specific target. The paper does not provide a head-to-head accuracy comparison between Nemotron-Elastic-6B and Minitron-SSM-6B, so whether this potential advantage materializes is unknown, but the sequential approach's single-target focus removes constraints that the elastic approach incurs.

- **Prefer pretraining from scratch when** the target model sizes require capabilities that cannot be acquired through compression of an existing parent — specifically, when the parent model's training data distribution, architecture, or scale is qualitatively insufficient for the target task. Elastic compression amplifies existing capability but cannot create it: if the 12B parent lacks reasoning ability on certain problem classes, the 6B elastic variant will also lack it. Additionally, if the goal is to produce model variants that are **not nested subsets** of a single architecture — e.g., models with different vocabulary sizes, different numbers of Mamba groups, or fundamentally different layer organizations — elastic compression cannot accommodate these structural changes because it relies on weight-sharing through contiguous parameter subsets.

- **Do NOT prefer Nemotron Elastic when** latency is the dominant constraint and the paper's unreported latency measurements might reveal unfavorable scaling. The paper does not measure inference latency, and the sequential dependencies in some elastic configurations (if heterogeneous depth selection creates skip patterns that complicate GPU kernel fusion) could produce wall-clock behavior that undermines the parameter-count efficiency. A practitioner for whom 99th-percentile latency is the binding constraint should measure elastic variant latency directly before committing to the framework, because the paper provides no guidance on this dimension.
