# APOLLO: SGD-like Memory, AdamW-level Performance

**ArXiv:** [2412.05270](https://arxiv.org/abs/2412.05270)

## 🎯 Pitch

This paper introduces **APOLLO (Approximated Gradient Scaling for Memory Efficient LLM Optimization)** , a family of memory-efficient optimizers that approximate AdamW's element-wise learning rate adaptation with structured channel-wise or tensor-wise scaling computed from an auxiliary low-rank space using pure random projection.

---

## 1. Executive Summary

This paper introduces **APOLLO (Approximated Gradient Scaling for Memory Efficient LLM Optimization)** , a family of memory-efficient optimizers that approximate AdamW's element-wise learning rate adaptation with structured channel-wise or tensor-wise scaling computed from an auxiliary low-rank space using pure random projection. Evaluated on LLaMA models from 60M to 7B parameters pre-training on the C4 dataset, APOLLO achieves AdamW-level or better validation perplexity (up to a 2.8 reduction) while reducing optimizer memory to near-SGD levels—a ~3× throughput improvement on 8×A100-80GB GPUs by supporting 4× larger batch sizes. The extreme variant, **APOLLO-Mini**, uses only a rank-1 auxiliary subspace with tensor-wise scaling, delivering SGD-level memory cost (2n + 2 elements) while outperforming AdamW in pre-training, establishing that full element-wise optimizer states are unnecessary for LLM training only when learning rate adaptation is coarsened to a structured format rather than applied per-parameter.

## 2. Context and Motivation

### The Core Problem: AdamW's Memory Wall Makes LLM Training Prohibitively Expensive

The paper addresses a fundamental bottleneck in large language model (LLM) training: **the optimizer state memory overhead of AdamW, the de facto standard optimizer, consumes resources far out of proportion to its algorithmic value**. Training LLMs is memory-intensive not primarily because of the model parameters themselves, but because AdamW maintains two auxiliary state tensors per parameter — the first moment (mean of past gradients) and the second moment (variance of past gradients). This effectively **triples the memory footprint** relative to the parameter count alone.

The scale of this problem is stark. The paper provides concrete numbers (Section 1):

> "training a LLaMA-7B model from scratch requires at least 58 GB of memory, with 28 GB devoted to AdamW's optimizer states"

For a 175-billion parameter GPT-3-scale model, the optimizer states alone demand approximately **1.4 TB of memory**. This memory burden forces practitioners into difficult tradeoffs: use more GPUs (incurring substantial communication and infrastructure overhead from scaling training clusters), reduce batch sizes (sacrificing throughput and potentially training stability), or acquire higher-end hardware (inaccessible to researchers with limited resources). The problem is not merely one of cost — it creates an **access barrier** that concentrates LLM training capability among well-resourced organizations.

### Why This Problem Matters Beyond Cost

The memory bottleneck has systemic consequences that extend beyond budget constraints:

**1. Throughput limitations.** When memory-constrained, training pipelines cannot use batch sizes large enough to fully utilize GPU compute. The model becomes memory-bound rather than compute-bound, meaning expensive GPU hardware sits idle waiting for data movement. The paper demonstrates that AdamW's memory consumption limits batch sizes on an 8×A100-80GB node to roughly 4 samples per GPU, while APOLLO enables 16 (Figure 1, right), translating to ~3× higher throughput.

**2. Scaling constraints without system complexity.** Larger models require model parallelism strategies (sharding, pipeline parallelism, tensor parallelism) solely to distribute optimizer states across devices. These introduce substantial engineering complexity, communication overhead, and failure modes. Reducing optimizer memory can defer or eliminate the need for these techniques at a given model scale.

**3. Democratization of LLM research.** If training a 7B model requires multiple high-end GPUs, only well-funded labs can participate in pretraining research. The paper's ambition to enable single-GPU pretraining of LLaMA-7B with less than 12 GB of memory (achieved by combining APOLLO-Mini with weight quantization) directly targets this accessibility gap.

**4. Theoretical significance.** If AdamW's element-wise adaptation can be replaced with structured scaling without performance loss, this challenges the prevailing understanding of *why* Adam works for Transformers. The paper suggests that the fine-grained per-parameter variance tracking in AdamW is substantially redundant — a claim with implications for optimizer design beyond memory efficiency alone.

### Prior Approaches and Where They Fall Short

The paper organizes prior work into two broad categories, each with distinct limitations.

#### Parameter Reduction Approaches (Algorithm-Level)

These methods reduce memory by training fewer parameters:

- **Small-scale model design** (Liu et al., 2024b; Tang et al., 2024): Architectures explicitly engineered for smaller parameter counts. While effective at reducing absolute memory, they fundamentally limit model capacity and often underperform against larger models with the same compute budget.

- **Sparse training** (Liu et al., 2022; Thangarasa et al., 2023): Only a fraction of parameters are active or updated at any given step. This reduces effective parameter count but introduces implementation complexity (dynamic sparsity patterns, load balancing) and can degrade final model quality.

- **Low-rank adaptation (LoRA)** (Hu et al., 2021) and its variants (ReLoRA for pretraining): Instead of training the full weight matrix $W \in \mathbb{R}^{m \times n}$, train only a low-rank update $W = W_0 + UV$ where $U \in \mathbb{R}^{m \times r}$, $V \in \mathbb{R}^{r \times n}$ with $r \ll \min(m, n)$. Memory savings come from reducing the number of parameters whose optimizer states must be stored. The critical weakness: **these methods restrict the optimization space**. As the paper notes:

> "Although these techniques effectively reduce memory usage, they restrict the optimization space of model parameters and often result in performance trade-offs, particularly during pretraining"

The experimental results in Table 2 confirm this: on LLaMA-60M, LoRA achieves 34.99 validation perplexity versus AdamW's 34.06 (a small gap), but on LLaMA-350M the gap widens to 25.58 versus 18.80 — pretraining with low-rank parameterization fundamentally cannot match full-parameter training at scale. The model is structurally constrained to explore only a low-rank subspace of the weight matrices.

#### Memory-Efficient Optimizer Design

This second category keeps full-parameter training but reduces the memory overhead of the optimizer states themselves. The paper identifies four representative methods, each with specific limitations:

**GaLore (Zhao et al., 2024):** The most prominent prior method. GaLore projects gradients into a low-rank space via Singular Value Decomposition (SVD), then applies AdamW only in that reduced space. The optimizer maintains low-rank moment estimates ($\mathbb{R}^{r \times n}$ instead of $\mathbb{R}^{m \times n}$), then projects weight updates back to the full-rank space. Its key weaknesses:

- **SVD is computationally devastating at scale.** Every projection matrix update (typically every 200 iterations) requires computing the SVD of gradient matrices of dimension up to 4096×4096 (for LLaMA-7B attention layers). The paper reports that for LLaMA-7B, "a single subspace update can take approximately 10 minutes, whereas inference only takes seconds." This overhead is visible in Figure 9, where GaLore's throughput drops precipitously at projection update steps. Over 150K training steps with updates every 1,000 steps, SVD alone adds ~25 hours of wall-clock time.

- **High rank requirement for competitive performance.** GaLore typically needs a rank of one-quarter of the original dimension ($r \approx n/4$) to match AdamW performance (Section 5.4, Figure 5d). This means optimizer memory is still substantial — roughly 2 × (m × n/4) elements, which for large models remains hundreds of megabytes to gigabytes per layer.

- **SVD is hard to parallelize efficiently on GPUs.** It requires expensive data movement and does not exploit the parallelism GPU hardware is designed for.

**Fira (Chen et al., 2024):** Enhances GaLore by maintaining an error residual between the full-rank gradient and its low-rank approximation, effectively simulating full-rank updates while keeping optimizer states low-rank. This improves convergence speed (as visible in Figure 6, where Fira initially converges faster than APOLLO). However, it retains two GaLore liabilities:

- **Still requires SVD**, inheriting the same throughput problems.
- **Still requires substantial memory** for the error residual and low-rank optimizer states ($2nr + mr + 1$ elements per weight matrix, per Table 1).

**Flora (Hao et al., 2024):** A gradient compression approach that avoids SVD by using random projections, achieving memory savings of $2nr + 1$ per matrix. Its critical limitation is more fundamental:

> "significant performance trade-offs compared to AdamW" (Section 1)

Flora does not reliably match AdamW performance, particularly in pretraining regimes (Table 1 marks Flora as not suitable for pretraining). The paper treats this as evidence that simply compressing gradients is insufficient — the *structure* of the learning rate adaptation matters.

**Adam-mini (Zhang et al., 2024b):** Takes an orthogonal approach by observing redundancy in AdamW's second moment. It replaces the per-parameter variance $V_t \in \mathbb{R}^{m \times n}$ with block-wise averaging: parameters are grouped into blocks (e.g., by attention head), and a single variance value is used per block. This reduces second-moment memory by up to 50%. However, three limitations remain:

- **First moment memory is unaffected.** Adam-mini still stores the full per-parameter first moment $M_t$, which for many architectures is the dominant cost.
- **Block partitioning requires careful design.** Different Transformer submodules (attention, MLP, embeddings) need different block sizes for optimal performance, adding engineering complexity.
- **Memory savings are bounded.** Halving second-moment memory still leaves optimizer states at roughly $mn + mn/2$ elements, remaining substantially larger than SGD.

**Other methods:** LDAdam (Robert et al., 2024) integrates error feedback for gradient compression, and GoLore (He et al., 2024) replaces occasional SVD with online PCA or random projections — but both operate within the same low-rank gradient compression paradigm and share similar limitations.

### The Unifying Gap: No Method Achieves SGD-Level Memory with AdamW-Level Performance

Reading across these prior approaches reveals a consistent pattern:

- Methods that drastically reduce memory (Flora, low-rank parameterization) sacrifice performance on pretraining.
- Methods that maintain performance (GaLore, Fira, Adam-mini) still retain substantial optimizer state memory and/or introduce expensive SVD operations.
- No prior method achieves the **SGD memory floor** — storing effectively nothing beyond the model weights and gradients — while reliably matching or exceeding AdamW's training quality.

This is the specific gap APOLLO targets. The paper frames the challenge explicitly:

> "Question ④: Can we further compress the optimizer state to SGD-level memory cost while matching or surpassing AdamW's performance?"

The answer requires finding a representation of AdamW's learning rate adaptation that is both extremely compact (rank-1 or similar) and structurally effective for Transformer training.

### How This Paper Positions Its Contribution

The paper makes two key observations that distinguish its approach from prior work:

**Observation 1: AdamW's element-wise learning rate can be coarsened to channel-wise or tensor-wise granularity without hurting performance (Section 3).** This is demonstrated empirically in Figure 3: on LLaMA-130M, channel-wise learning rate adaptation achieves perplexity of 24.11, slightly better than AdamW's 25.08. The implication is that the per-parameter granularity of AdamW's scaling is unnecessary — what matters is capturing *relative* importance across structural axes (channels, tensors) rather than individual parameters. This observation parallels Adam-mini's finding about second-moment redundancy but extends it more radically: both first and second moments can be coarsened, and the coarsening can be done at the structural level (channel-wise) rather than requiring careful block partitioning.

**Observation 2: Structured scaling factors can be approximated from a randomly projected low-rank space (Section 4).** This is the paper's technical innovation. Rather than:
- (a) computing full-rank moments $M_t$, $V_t$ and then coarsening their ratios (which saves no memory), or
- (b) learning low-rank gradients via SVD and applying AdamW in that space (which incurs SVD cost),

APOLLO takes a third path: project the gradient into a low-rank space using **pure random projection** (a matrix $P \in \mathbb{R}^{r \times m}$ with i.i.d. Gaussian entries), compute AdamW moments in that space, and use the resulting scaling factors as a structured approximation to the full-rank scaling. The theoretical analysis (Theorems 4.1, 4.2, 4.4) proves that random projection preserves the norms of both first and second moments with high probability, enabling a bounded approximation of the channel-wise scaling factors. The critical insight is that **random projection is sufficient because the target (channel-wise scaling factors) is already coarsened** — the projection only needs to preserve aggregate statistics, not individual gradient elements.

This positions APOLLO at the intersection of two previously separate research threads:

- **Low-rank approximation** (GaLore, Fira, Flora): APOLLO uses low-rank projection but avoids SVD by exploiting the fact that its target (structured scaling) is inherently robust to projection quality.
- **Optimizer state redundancy** (Adam-mini): APOLLO extends the redundancy observation from second moments only to full learning rate adaptation, and from block-wise to channel/tensor-wise granularity.

The paper's claim to novelty is not any individual component (channel-wise scaling, random projection, low-rank approximation — all exist in some form in prior work), but rather the **integration of these ideas into a unified framework** where:
1. Coarsened scaling enables extreme rank reduction without performance loss.
2. Random projection enables SVD-free low-rank computation.
3. The combination achieves SGD-level memory with AdamW-level performance.

### The Stakes: What Success Would Enable

If APOLLO succeeds in its claims, the practical implications are immediate and significant:

- **Larger batch sizes under the same hardware constraint** → higher throughput → faster training iterations for research and production.
- **Larger models trainable without model parallelism** → simpler engineering, fewer communication bottlenecks, more accessible scaling.
- **Single-GPU pretraining of 7B+ models with quantization** → democratization of pretraining research.
- **Evidence that AdamW's per-parameter adaptation is redundant** → opens design space for a new generation of optimizers that explicitly trade off adaptation granularity against memory and compute.

These stakes frame the experimental evaluation: the paper must demonstrate not just comparable perplexity at lower memory, but also downstream task quality, throughput gains at system level, and robustness across model scales and training regimes.

## 3. Technical Approach

### 3.1 Reader Orientation

This paper is primarily an **empirical analysis and systems paper** that develops a family of memory-efficient optimizers called APOLLO by reformulating AdamW's per-parameter learning rate adaptation as a structured scaling operation that can be approximated from a randomly projected low-dimensional subspace. The core idea is that you don't need to track per-parameter first and second moments (which triples memory) — instead, you can track those moments in a compressed random projection of the gradient, extract a coarse channel-wise or tensor-wise scaling factor from them, and apply that scaling back to the original full-resolution gradient before weight update, achieving AdamW-level training quality with SGD-level memory footprint.

### 3.2 Big-Picture Architecture (Diagram in Words)

The system has four major components organized in a pipeline executed at every optimization step:

1. **Random Projection Module** — takes the full-rank gradient matrix `$G_t \in \mathbb{R}^{m \times n}$` and multiplies it by a random Gaussian matrix `$P_t \in \mathbb{R}^{r \times m}$` (periodically re-sampled) to produce a compressed gradient `$R_t = P_t G_t \in \mathbb{R}^{r \times n}$`. This is the gateway to the low-rank world.

2. **Low-Rank AdamW State Tracker** — maintains standard AdamW first and second moments (`$M^R_t$`, `$V^R_t$`) but only for the compressed gradient `$R_t$`, not the full gradient. This is where the memory savings happen: instead of `$2mn$` elements, we store only `$2rn$` elements.

3. **Scaling Factor Extractor** — converts the low-rank moments into a structured scaling vector. For APOLLO, this is channel-wise: each channel `$j$` gets a single scalar `$s^R_j$` computed as the ratio of the `$\ell_2$` norm of the low-rank adapted gradient to the `$\ell_2$` norm of the low-rank raw gradient for that channel. For APOLLO-Mini, this collapses to one global scalar per tensor.

4. **Structured Gradient Scaler and Weight Updater** — multiplies the full-rank gradient `$G_t$` by the scaling vector (channel-wise: `$\tilde{G}_t = G_t \cdot \text{diag}(\mathbf{s}^R)$`; tensor-wise: `$\tilde{G}_t = s^R \cdot G_t$`), applies the Norm-growth Limiter for stability, and performs the weight update `$W_t \leftarrow W_{t-1} - \eta \cdot \alpha \cdot \tilde{G}_t - \eta \lambda W_{t-1}$`. The scale factor `$\alpha$` compensates for the theoretical norm ratio between projected and original spaces.

Information flows strictly one-way per step: `$G_t$` → random projection → `$R_t$` → low-rank AdamW → `$\mathbf{s}^R$` → structured scaling of `$G_t$` → weight update. The projection matrix is re-randomized every `$T$` steps (default: 200) by simply changing the random seed, requiring no SVD or expensive re-factorization.

### 3.3 Roadmap for the Deep Dive

- **First, the reformulation of AdamW as an adaptive learning rate algorithm (Section 3.1)** — this establishes the conceptual lens through which all subsequent approximations are viewed. Understanding AdamW as "SGD with per-element learning rate scaling" makes the jump to "SGD with channel-wise learning rate scaling" natural.

- **Second, the empirical case for structured learning rate updates (Section 3.2)** — before building a memory-efficient approximation, the paper verifies that the approximation target (channel-wise scaling) is actually sufficient. This is the "is the thing we're approximating even worth approximating?" sanity check.

- **Third, the core APOLLO algorithm (Section 4.1)** — how to practically approximate channel-wise scaling from a low-rank random projection, including the algorithm pseudocode, the memory model, the Norm-growth Limiter, and the theoretical guarantees that random projection preserves moment norms.

- **Fourth, the extreme APOLLO-Mini variant (Section 4.2)** — what changes when we push to rank-1 and tensor-wise scaling, and why tensor-wise averaging is necessary to make rank-1 work.

- **Fifth, the savings and cost analysis (Section 4.3)** — a precise accounting of what memory each variant uses compared to prior methods, and why the constant factors matter.

### 3.4 Detailed, Sentence-Based Technical Breakdown

This is primarily an **empirical systems paper** whose core idea is that AdamW's element-wise learning rate adaptation rule can be approximated from a compressed random projection of the gradient, enabling SGD-level memory costs with AdamW-level training, because the target of the approximation — a channel-wise or tensor-wise scaling factor — is inherently coarse enough to be recovered from even a rank-1 subspace.

#### Reformulating AdamW as Pure Adaptive Learning Rate Scaling

The paper's first conceptual move is to strip AdamW of its momentum interpretation and recast it as an element-wise gradient scaling mechanism. This reframing is not mathematically deep — it's algebraically trivial — but it opens the door to all subsequent approximations by making the scaling factors explicit objects of study.

**The vanilla AdamW update rule** (disregarding weight decay for the moment) is:

$$W_{t+1} = W_t - \eta \cdot \tilde{G}_t, \quad \tilde{G}_t = \frac{M_t}{\sqrt{V_t} + \epsilon}$$

where `$W_t \in \mathbb{R}^{m \times n}$` (with the convention `$m \leq n$`) is a weight matrix at step `$t$`, `$G_t = -\nabla_W \phi_t(W_t)$` is the negative gradient of the loss `$\phi_t$` with respect to `$W_t$`, `$\eta$` is the learning rate, and `$\epsilon$` is a small constant for numerical stability (typically `$10^{-8}$` in Adam). The first and second moments evolve as exponentially weighted moving averages:

$$M_t = \beta_1 M_{t-1} + (1 - \beta_1) G_t$$

$$V_t = \beta_2 V_{t-1} + (1 - \beta_2) G_t^2$$

where `$\beta_1, \beta_2 \in [0,1)$` are the exponential decay rates (typically `$\beta_1 = 0.9$`, `$\beta_2 = 0.999$`), and `$G_t^2$` denotes element-wise squaring. The standard initialization is `$M_0 = 0$`, `$V_0 = 0$`.

**The algebraic reframing.** The paper observes that the update can be rewritten by factoring out the raw gradient:

$$W_{t+1} = W_t - \eta \cdot \frac{\tilde{G}_t}{G_t} \cdot G_t = W_t - \eta \cdot S \cdot G_t$$

where `$S \in \mathbb{R}^{m \times n}$` is an element-wise scaling matrix and the division `$\frac{\tilde{G}_t}{G_t}$` is performed element-wise (so `$S_{ij} = \frac{\tilde{G}_{t,ij}}{G_{t,ij}}$` at every position where `$G_{t,ij} \neq 0$`). In this view, AdamW does exactly two things: (1) it takes the raw SGD step direction `$G_t$`, and (2) it applies an element-wise learning rate multiplier `$S$` where parameters with historically high gradient variance (large `$V_t$` entries) get their updates scaled down relative to parameters with stable gradients.

**Why this reformulation matters.** The paper states:

> "In other words, the effectiveness of AdamW can be viewed as the result of a variance-aware learning rate schedule per element in raw gradient `$G_t$` using the corresponding element in `$S$`, where elements with higher variance in `$V_t$` are scaled down to reduce unstable updates."

This perspective makes explicit what AdamW is actually contributing beyond SGD: not momentum (which can be added to SGD independently), but a *heterogeneous per-parameter sensitivity adjustment*. The question then becomes: does this sensitivity adjustment need to be per-parameter, or would a coarser granularity suffice? If coarser suffices, we can approximate `$S$` from compressed information without storing full moments.

**What this is not.** The paper is careful to note that this is a conceptual reformulation, not a practical algorithm change. Computing `$S$` this way requires exactly the same `$M_t$` and `$V_t$` as AdamW — no memory is saved yet. The purpose is purely analytical: to isolate what AdamW *does* (scale gradients per-element) from how it *computes* that scaling (maintaining full-rank moments), so that the two can be independently modified.

**The Norm-growth Limiter (NL).** When the paper later moves to structured scaling, it encounters a practical issue: channel-wise scaling can produce unstable gradient norms early in training. Instead of standard gradient clipping, the paper adopts the Norm-growth Limiter from Fira (Chen et al., 2024):

$$\text{if } \frac{\|\tilde{G}_t\|}{\|\tilde{G}_{t-1}\|} > \gamma \text{ then } \tilde{G}_t \leftarrow \frac{\tilde{G}_t}{\|\tilde{G}_t\|} \cdot \gamma \|\tilde{G}_{t-1}\|$$

where `$\gamma$` is a threshold controlling the maximum allowed growth in gradient norm between consecutive steps (set to `$\gamma = 1.01$` by default). Unlike gradient clipping by absolute value, this limiter constrains the *ratio* of consecutive norms, which is specifically tuned to prevent the loss spikes visible in Figure 3 (orange curve) during early training when gradients are unstable. The paper finds this slightly more effective than standard clipping for structured scaling.

#### Coarsening from Element-Wise to Channel-Wise Learning Rate Adaptation

The paper's second conceptual move is to test empirically whether `$S$` can be simplified from per-element to per-channel granularity. This is not yet a memory-saving proposal — it's an *existence proof* that structures a memory-saving method.

**What "channel-wise" means concretely.** For a weight matrix `$W \in \mathbb{R}^{m \times n}$` (with the convention `$m \leq n$`, so `$n$` is the larger dimension), a "channel" is one column (indexed by `$j$`). The channel-wise scaling factor `$s_j$` for channel `$j$` is:

$$s_j = \frac{\|\tilde{G}_t[:, j]\|_2}{\|G_t[:, j]\|_2}$$

where `$\|\cdot\|_2$` is the `$\ell_2$` norm, `$\tilde{G}_t[:, j]$` is the `$j$`-th column of the adapted gradient (what AdamW would have applied to that column), and `$G_t[:, j]$` is the `$j$`-th column of the raw gradient. **What it computes:** for each output channel `$j$`, compute how much AdamW would have scaled the column's overall magnitude (in `$\ell_2$` sense) relative to the raw gradient's column magnitude. The result is a single scalar per channel — all `$m$` rows of column `$j$` share the same multiplier.

The final scaled gradient under channel-wise adaptation is:

$$\tilde{G}_t = G_t \cdot \text{diag}(\mathbf{s})$$

where `$\text{diag}(\mathbf{s})$` is an `$n \times n$` diagonal matrix with `$s_j$` on the diagonal. This means column `$j$` of `$G_t$` is multiplied by `$s_j$`, preserving the internal structure of that column but scaling its overall contribution.

**Why this form:** Each column of a weight matrix corresponds to one output dimension. In Transformer architectures, these output dimensions often serve distinct functional roles (different attention heads, different features in an MLP layer). Scaling entire columns uniformly preserves the relative importance of different rows within that column while adjusting the overall contribution of that output dimension to the next layer. A per-parameter scaling would allow arbitrary distortion within a column, but if the meaningful variation is primarily across columns rather than within them, channel-wise scaling is sufficient. The paper's empirical finding that it works better than element-wise in some cases suggests that per-parameter scaling may *overfit* to gradient noise within a column.

**The empirical validation (Figure 3).** On a LLaMA-130M model pretrained on the C4 dataset:

- **Element-wise AdamW:** achieves validation perplexity of 25.08.
- **Channel-wise adaptation (same `$M_t$`, `$V_t$` but with channel-wise scaling):** achieves 24.43 — slightly *better* than AdamW despite the coarser granularity.
- **Channel-wise adaptation + Norm-growth Limiter:** achieves 24.11 — smoothing the early-training spikes visible in the loss curve further improves final perplexity.

The training loss curves (Figure 3) show that both element-wise and channel-wise adaptation follow similar trajectories and converge to similar final loss values, with the channel-wise version actually ending slightly lower. The early-stage spike in the channel-wise curve (orange, without NL) is attributed to unstable gradients at initialization, which the Norm-growth Limiter subsequently eliminates (green curve).

**The key takeaway established here:**

> "A structured learning rate update is sufficient for LLM training."

This is the paper's foundational empirical claim. It asserts that the per-parameter granularity of AdamW is *unnecessarily fine* — the optimization dynamics can be preserved by scaling at the channel level (or, as later experiments show, even at the tensor level). This mirrors Adam-mini's finding about second-moment redundancy but extends it: in Adam-mini, only the second moment is coarsened (to block-wise); in APOLLO, both moments are coarsened (to channel-wise or tensor-wise), and the coarsening applies to the *combined* scaling factor `$\tilde{G}_t / G_t$` rather than to the moments separately.

**What this does NOT yet achieve.** Computing `$s_j$` as `$\|\tilde{G}_t[:, j]\|_2 / \|G_t[:, j]\|_2$` still requires the full-rank `$\tilde{G}_t = M_t / \sqrt{V_t}$`, which in turn requires the full-rank `$M_t, V_t$` — exactly as expensive as AdamW. The memory saving has not yet materialized. This section only establishes that if we *could* compute those `$s_j$` values cheaply, we wouldn't lose anything by coarsening to channel-wise granularity. The next section addresses how to compute `$s_j$` *approximately* from compressed information.

---

#### APOLLO: Approximating Channel-Wise Scaling from a Low-Rank Random Projection

This is where the practical memory savings enter. The challenge: compute a good approximation `$\mathbf{s}^R \approx \mathbf{s}$` without ever storing the full `$m \times n$` moments `$M_t$` and `$V_t$`.

**Step 1: Low-Rank Projection of the Gradient.** At each step, the full gradient `$G_t \in \mathbb{R}^{m \times n}$` is projected to a lower dimension via:

$$R_t = P_t G_t$$

where `$P_t \in \mathbb{R}^{r \times m}$` is a random projection matrix with `$r \ll m$` (typically `$r \approx m/4$` or `$m/8$` or even 1), and `$R_t \in \mathbb{R}^{r \times n}$` is the projected gradient. Each element of `$P_t$` is independently sampled from a Gaussian distribution: `$P_{ij} \sim \mathcal{N}(0, 1/r)$`. The factor `$1/r$` in the variance ensures that the expected squared norm of a projected vector equals the squared norm of the original vector: `$\mathbb{E}[\|P_t x\|^2] = \|x\|^2$` for any fixed vector `$x \in \mathbb{R}^m$`.

**Why random projection instead of SVD:** The paper's key technical insight is that for the specific purpose of recovering *channel-wise scaling factors* (not for reconstructing the full gradient), random projection suffices. SVD would find the optimal rank-`$r$` subspace that maximally preserves the gradient's information content, but:
- SVD costs `$O(m n^2)$` for an `$m \times n$` matrix, is hard to parallelize on GPUs, and creates throughput spikes (Figure 9).
- Random projection costs `$O(r m n)$` via standard matrix multiplication, exploits GPU parallelism trivially, and has negligible overhead (Table 7 shows APOLLO's optimizer step is faster than AdamW's for LLaMA-7B because projecting and tracking low-rank moments costs less than maintaining full-rank moments).
- The channel-wise scaling target is coarse enough that the approximation error from random projection (bounded by the Johnson-Lindenstrauss lemma) is tolerable — the paper's Theorem 4.4 formalizes this as a ratio bound.

**Step 2: AdamW in the Low-Rank Space.** The projected gradient `$R_t$` is fed into standard AdamW moment tracking, but now operating on `$\mathbb{R}^{r \times n}$` rather than `$\mathbb{R}^{m \times n}$`:

$$M^R_t = \beta_1 M^R_{t-1} + (1 - \beta_1) R_t$$

$$V^R_t = \beta_2 V^R_{t-1} + (1 - \beta_2) R_t^2$$

where `$M^R_t, V^R_t \in \mathbb{R}^{r \times n}$`. The adapted low-rank gradient is then:

$$\tilde{R}_t = \frac{M^R_t}{\sqrt{V^R_t} + \epsilon}$$

**What this computes:** exactly the same exponential moving average operations as AdamW, but the state dimensions are `$r \times n$` instead of `$m \times n$`. Memory for moments drops from `$2mn$` to `$2rn$` — a factor of `$r/m$` reduction. For `$r = m/8$`, this is a 8× reduction in moment storage.

**A subtle but critical point:** The moments `$M^R_t$` and `$V^R_t$` track the statistics of the *projected* gradient `$R_t$`, not the original gradient `$G_t$`. The projection mixes information across the `$m$` rows, so a single row of `$R_t$` encodes information from many rows of `$G_t$`. This means the low-rank moments lose per-row resolution but retain per-column resolution (since projection is only across the `$m$` dimension). This is exactly what we want: the scaling factors `$s_j$` are per-column quantities, and the random projection preserves enough column-level information to recover them approximately.

**Step 3: Extracting Channel-Wise Scaling Factors from the Low-Rank Space.** For each column `$j$` of the projected space, compute:

$$s^R_j = \frac{\|\tilde{R}_t[:, j]\|_2}{\|R_t[:, j]\|_2}$$

where `$\tilde{R}_t[:, j], R_t[:, j] \in \mathbb{R}^r$` are the `$j$`-th columns of the adapted and raw projected gradients respectively. **What it computes:** the ratio of `$\ell_2$` norms in the projected space, which serves as an approximation to the true channel-wise scaling factor `$s_j = \|\tilde{G}_t[:, j]\|_2 / \|G_t[:, j]\|_2$` in the original space. The full scaling vector is `$\mathbf{s}^R \in \mathbb{R}^n$`, one scalar per channel.

The scaled gradient in the original space is then:

$$\tilde{G}_t = G_t \cdot \text{diag}(\mathbf{s}^R)$$

and the weight update is:

$$W_{t+1} = W_t - \eta \cdot \alpha \cdot \tilde{G}_t - \eta \lambda W_{t-1}$$

where `$\alpha$` is a gradient scale factor, `$\lambda$` is the weight decay coefficient, and `$\eta \lambda W_{t-1}$` is the standard decoupled weight decay term from AdamW.

**Why the factor `$\alpha$`:** Theorem 4.4 establishes that the ratio between the projected-space scaling factor `$s^R_j$` and the original-space scaling factor `$s_j$` satisfies (with high probability):

$$\frac{\sqrt{1-\epsilon}}{1+\epsilon} \leq \sqrt{\frac{n}{r}} \cdot \frac{s^R_j}{s_j} \leq \frac{\sqrt{1+\epsilon}}{1-\epsilon}$$

This means the projected-space scaling factors are systematically smaller by a factor of approximately `$\sqrt{r/n}$` compared to the original-space scaling factors. The scale factor `$\alpha$` compensates for this systematic bias. **In practice:** for APOLLO with moderate rank (`$r \approx n/4$`), `$\alpha$` is set to 1 by default because the factor can be absorbed into the learning rate. For APOLLO-Mini with `$r = 1$`, the systematic bias is severe (`$\sqrt{1/n}$`), so `$\alpha$` is explicitly set to `$\sqrt{128}$` as a heuristic (the "128" comes from empirical tuning rather than theory — the paper states "we heuristically set a gradient scale factor").

**The projection matrix re-sampling.** The projection matrix `$P_t$` is not fixed for the entire training. Following GaLore's observation that fixing the projection limits the directions in which weights can grow, APOLLO re-samples `$P_t$` every `$T$` steps (default: `$T = 200$`). The re-sampling is implemented trivially:

> "this is effortlessly done by re-generating a new seed"

— meaning the random number generator's seed is changed, and a fresh `$P_t \sim \mathcal{N}(0, 1/r)^{r \times m}$` is sampled. Unlike GaLore, where each re-projection requires a computationally expensive SVD, APOLLO's random re-projection is a `$O(r m)$` operation that costs negligible time. The paper notes that the projection matrix itself is never stored; it can be re-generated from the seed on-the-fly if needed, though in practice it's stored transiently during the forward-backward-optimize cycle.

**The Norm-growth Limiter reprise.** After computing the structured scaled gradient `$\tilde{G}_t = G_t \cdot \text{diag}(\mathbf{s}^R)$`, the Norm-growth Limiter is applied:

$$\text{if } \frac{\|\tilde{G}_t\|}{\|\tilde{G}_{t-1}\|} > \gamma \text{ then } \tilde{G}_t \leftarrow \frac{\tilde{G}_t}{\|\tilde{G}_t\|} \cdot \gamma \|\tilde{G}_{t-1}\|$$

This is the same `$\gamma = 1.01$` limiter introduced in Section 3, applied after the structured scaling to prevent gradient norm explosions early in training.

**The complete algorithm (pseudocode in Algorithm 1).** The full APOLLO optimizer step for a single weight matrix `$W \in \mathbb{R}^{m \times n}$` is:

1. **Compute and project gradient:** `$G_t \leftarrow -\nabla_W \phi_t(W_t)$`; if `$t \bmod T = 0$`, sample new `$P_t \sim \mathcal{N}(0, 1/r)$`; `$R_t \leftarrow P_t G_t$`.
2. **Update low-rank moments:** `$M^R_t, V^R_t \leftarrow \text{AdamW\_update}(R_t, M^R_{t-1}, V^R_{t-1}, \beta_1, \beta_2)$`; `$\tilde{R}_t \leftarrow M^R_t / (\sqrt{V^R_t} + \epsilon)$`.
3. **Extract scaling factors:** For APOLLO: `$s^R_j \leftarrow \|\tilde{R}_t[:, j]\|_2 / \|R_t[:, j]\|_2$` for each `$j$`; form `$S \leftarrow \text{diag}(\mathbf{s}^R)$`. For APOLLO-Mini: `$s^R \leftarrow \|\tilde{R}_t\|_2 / \|R_t\|_2$`; `$S \leftarrow s^R$` (scalar).
4. **Scale full gradient and update weights:** `$\tilde{G}_t \leftarrow G_t S$` (matrix multiply or scalar multiply); apply NL if needed; `$W_t \leftarrow W_{t-1} - \eta \cdot \alpha \cdot \tilde{G}_t - \eta \lambda W_{t-1}$`.

**Key hyperparameters and their defaults:**
- Rank `$r$`: typically `$m/4$` for APOLLO (matching GaLore's standard setting), `$m/8$` for APOLLO with halved rank, and 1 for APOLLO-Mini.
- Projection update frequency `$T$`: 200 steps (same as GaLore).
- Norm-growth limiter threshold `$\gamma$`: 1.01.
- Learning rate `$\eta$`: 0.01 (following GaLore's settings for fair comparison, though the paper notes APOLLO can be further tuned).
- Scale factor `$\alpha$`: 1 for APOLLO with moderate rank; `$\sqrt{128}$` for APOLLO-Mini (heuristic).
- AdamW betas: `$\beta_1 = 0.9$`, `$\beta_2 = 0.999$` (standard).
- `$\epsilon$`: `$10^{-8}$` (standard Adam).
- For the LLaMA-1B model with high-rank APOLLO: `$\alpha = \sqrt{1/2}$`; for APOLLO with SVD on 1B: `$\alpha = 0.4$` (tuned per-model-size, per Appendix A.4).

#### Theoretical Justification: Why Random Projection Preserves Channel-wise Scaling Factors

The paper provides a formal analysis proving that the channel-wise scaling factors computed from the projected gradient are close to those computed from the full gradient. This section walks through the structure of that analysis.

**Theorem 4.1 (First Moment Preservation):** For any channel `$j$` of the first moment `$M_t$`, with probability at least `$1 - 2\exp(-r\epsilon^2 / 8)$`:

$$(1 - \epsilon) \|M_t[:, j]\|^2 \leq \|M^R_t[:, j]\|^2 \leq (1 + \epsilon) \|M_t[:, j]\|^2$$

**What it says:** the `$\ell_2$` norm of each column of the first moment in the projected space is within a factor `$(1 \pm \epsilon)$` of the norm in the original space. **Why it holds:** the first moment is a weighted sum of past gradients: `$M_t = (1 - \beta_1) \sum_{k=0}^{t-1} \beta_1^k G_{t-k}$`. The projected first moment satisfies `$M^R_t = P M_t$` (the projection matrix factors through the linear combination). The Johnson-Lindenstrauss lemma (Theorem A.1 in the appendix) guarantees that `$\|Px\|^2 \approx \|x\|^2$` for any fixed vector `$x$` when `$P$` is Gaussian with variance `$1/r$`. Applying this to `$x = M_t[:, j]$` for each column gives the bound.

**Theorem 4.2 (Second Moment Preservation in `$\ell_1$` Norm):** For any channel `$j$`, with probability at least `$1 - \delta/2$` (requiring `$r \geq \frac{8}{\epsilon^2} \log(2t/\delta)$`):

$$(1 - \epsilon) \|V_t[:, j]\|_1 \leq \|V^R_t[:, j]\|_1 \leq (1 + \epsilon) \|V_t[:, j]\|_1$$

**What it says:** the `$\ell_1$` norm of the second moment in the projected space is within factor `$(1 \pm \epsilon)$` of the `$\ell_1$` norm in the original space. **Why `$\ell_1$` instead of `$\ell_2$`:** The second moment involves squared gradients, so the projection analysis is more involved. The paper decomposes the `$\ell_1$` norm of `$V^R_t[:, j]$` as a weighted sum of squared projected gradient norms: `$\|V^R_t[:, j]\|_1 = (1 - \beta_2) \sum_{k=0}^{t-1} \beta_2^k \|R_{t-k}[:, j]\|^2$`. Each term `$\|R_{t-k}[:, j]\|^2$` is approximately `$\|G_{t-k}[:, j]\|^2$` by the same JL lemma. Summing with the exponential weights gives the bound. **The rank requirement:** `$r$` only needs to grow logarithmically with training steps `$t$`, not linearly — empirically, the paper finds that a fixed moderate `$r$` (e.g., 256 for a 7B model) suffices, consistent with Adam-mini's observation that variance doesn't need to be precise.

**Theorem 4.4 (Main Result — Scaling Factor Ratio Bound):** For any channel `$j$`, with probability at least `$1 - \delta$`:

$$\frac{\sqrt{1-\epsilon}}{1+\epsilon} \leq \sqrt{\frac{n}{r}} \cdot \frac{s^R_j}{s_j} \leq \frac{\sqrt{1+\epsilon}}{1-\epsilon}$$

where `$s_j = \|\tilde{G}_t[:, j]\| / \|G_t[:, j]\|$` is the true channel-wise scaling factor in the original space, and `$s^R_j = \|\tilde{R}_t[:, j]\| / \|R_t[:, j]\|$` is the approximation from the projected space.

**How this is derived (sketch):** The ratio decomposes as:

$$\frac{s^R_j}{s_j} = \frac{\|G_t[:, j]\|}{\|R_t[:, j]\|} \cdot \frac{\|\tilde{R}_t[:, j]\|}{\|\tilde{G}_t[:, j]\|}$$

The first factor `$\|G_t[:, j]\| / \|R_t[:, j]\|$` is bounded by Theorem A.1 (JL lemma for a single projection): it lies in `$[1/\sqrt{1+\epsilon}, 1/\sqrt{1-\epsilon}]$`. The second factor is more involved since `$\tilde{R}_t$` and `$\tilde{G}_t$` involve the ratios `$M_t / \sqrt{V_t}$`, which mix first and second moments. The paper uses the block-wise and channel-wise averaging assumptions motivated by Adam-mini and GaLore-mini to separate the moment ratio, yielding the combined bound `$\sqrt{(1 \pm \epsilon) / (1 \mp \epsilon)}$`. The factor `$\sqrt{n/r}$` emerges from the dimensionality difference between the `$\ell_2$` norm of the full `$m$`-dimensional vector and its `$r$`-dimensional projection.

**The operational consequence:** This theorem justifies scaling the projected-space updates by `$\sqrt{n/r}$` to align them with original-space behavior. For APOLLO with `$r = n/4$`, this factor is `$\sqrt{4} = 2$`, which can be absorbed into the learning rate. For APOLLO-Mini with `$r = 1$` and `$n \approx 4096$`, the factor is `$\sqrt{4096} \approx 64$` — but the paper empirically finds `$\sqrt{128}$` works better, suggesting the theoretical bound is loose for extreme rank reduction and additional empirical calibration is needed.

**Empirical validation of the ratio (Figure 4 and Figure 8 in appendix).** The paper visualizes the actual observed ratio `$\sqrt{n/r} \cdot s^R_j / s_j$` for APOLLO with ranks `$n/4$` and `$n/8$` compared to full-rank AdamW. The ratios cluster tightly around the theoretical predictions (0.5 and ~0.35 respectively) across different layer types (attention, MLP), layer depths, and training stages, confirming that the random projection indeed preserves the scaling factor structure.

**Why this theoretical analysis matters beyond correctness.** The proof structure reveals *why* APOLLO can use random projection when GaLore cannot: GaLore needs to reconstruct the full gradient from its low-rank approximation (which requires capturing the dominant singular vectors), while APOLLO only needs to recover aggregate channel statistics (which random projection preserves statistically). The target is inherently lower-resolution, so the projection can be cruder. This is the paper's central theoretical insight that enables SVD-free operation.

#### APOLLO-Mini: Pushing to Rank-1 with Tensor-Wise Scaling

APOLLO-Mini is an extreme variant that takes the memory compression to its logical limit: what if the auxiliary low-rank space has rank 1, storing only a single row of moments? The paper finds that naively using rank-1 with channel-wise scaling (APOLLO's default) doesn't work well because a single random projection loses too much per-channel information — the `$s^R_j$` estimates for different channels become too noisy.

**The solution: tensor-wise scaling.** Instead of computing one scaling factor per channel, compute a single global scaling factor for the entire weight tensor:

$$s^R = \frac{\|\tilde{R}_t\|_2}{\|R_t\|_2}$$

where `$R_t = P_t G_t \in \mathbb{R}^{1 \times n}$` is the rank-1 projected gradient (a single row vector), `$M^R_t, V^R_t \in \mathbb{R}^{1 \times n}$` are the rank-1 moments, and `$\tilde{R}_t = M^R_t / (\sqrt{V^R_t} + \epsilon) \in \mathbb{R}^{1 \times n}$`. **What it computes:** a single scalar that scales the entire gradient tensor uniformly. The final scaled gradient is:

$$\tilde{G}_t = s^R \cdot G_t$$

— a global scalar multiplication of the full-rank gradient.

**Why tensor-wise averaging helps at rank-1.** With rank 1, the projected gradient `$R_t$` is a single linear combination of the `$m$` rows of `$G_t$`. The per-channel norms `$\|R_t[:, j]\|_2$` are just absolute values `$|R_t[1, j]|$`, and the ratio `$\|\tilde{R}_t[:, j]\| / \|R_t[:, j]\|$` for each channel `$j$` is highly sensitive to the random projection weights. By averaging across all channels (computing the global `$\ell_2$` norm of the whole `$1 \times n$` row vector), the noise cancels out statistically, and the global scaling factor becomes stable.

The scale factor `$\alpha$` is crucial here: at rank 1, the systematic bias `$\sqrt{n/1}$` is large (e.g., `$\sqrt{4096} = 64$`). The paper heuristically sets `$\alpha = \sqrt{128}$` as a default, acknowledging that this is empirically tuned rather than theoretically derived. For fine-tuning, the scaling factor is adjusted per-model: `$\sqrt{4}$` for LLaMA-3-8B and Mistral-7B, and 1 for Gemma-7B (which is more sensitive during fine-tuning, per Appendix A.5.2).

**Memory for APOLLO-Mini:** With rank 1, the optimizer states are `$M^R_t, V^R_t \in \mathbb{R}^{1 \times n}$`, totaling `$2n$` elements. The paper also stores the random seed (to regenerate `$P_t$` if needed) and the previous gradient norm (for the Norm-growth Limiter), adding a constant 2 elements. Total optimizer memory: `$2n + 2$` — independent of the input dimension `$m$`. For a weight matrix with `$m = 4096, n = 4096$`, this is `$2 \times 4096 + 2 \approx 8K$` elements, versus AdamW's `$2 \times 4096 \times 4096 \approx 33.5M$` elements — a reduction by a factor of ~4000×.

**Performance with rank 1.** Figure 5(d) shows that APOLLO-Mini with rank 1 actually *outperforms* APOLLO with low-moderate ranks (e.g., 8, 16, 32) on the LLaMA-60M model, and all of these outperform GaLore at equivalent ranks. The paper explains this counterintuitive result: tensor-wise averaging effectively smooths the projection noise, acting as a form of regularization that helps generalization, especially in the later stages of training when escaping local minima matters more than precise gradient alignment.

#### Savings and Cost Analysis (Table 1)

The paper provides a precise element-count comparison (Table 1) across methods for a single weight matrix `$W \in \mathbb{R}^{m \times n}$` with `$m \leq n$`:

| Method | Optimizer States (elements) | Notes |
|---|---|---|
| **AdamW** | `$2mn$` | Full first + second moments |
| **APOLLO-Mini** | `$2n + 2$` | Rank-1: `$2 \times 1 \times n$` moments + seed + norm |
| **APOLLO** | `$2nr + 2$` | Rank `$r$`: `$2 \times r \times n$` moments + seed + norm |
| **Fira** | `$2nr + mr + 1$` | Low-rank moments `$2nr$` + error residual `$mr$` + norm |
| **GaLore** | `$2nr + mr$` | Low-rank moments `$2nr$` + projection matrix `$mr$` |
| **Flora** | `$2nr + 1$` | Low-rank moments + norm |

**Key differences in what gets stored:**
- **APOLLO does NOT store the projection matrix `$P_t$`.** Unlike GaLore (which needs `$P_t$` to project updates back to the original space) or Fira (which additionally stores an error residual), APOLLO's `$P_t$` is used only to produce `$R_t$` and can be re-generated from the random seed. This eliminates the `$mr$` term entirely.
- **All methods store the full-rank weights `$W_t$` and compute full-rank gradients `$G_t$`** (APOLLO-Mini, APOLLO, Fira) — except GaLore and Flora, which only store full-rank weights but compute low-rank gradients (saving gradient memory at the cost of losing full-rank gradient information). The paper notes this distinction in Table 1: "Full-Rank Gradients: ✔" for APOLLO variants and Fira, "✘" for GaLore and Flora.

**Why storing full-rank gradients matters:** having access to the full gradient `$G_t$` is what enables APOLLO to apply the structured scaling back to the original space without information loss from the gradient itself. GaLore and Flora work with low-rank gradients throughout, which restricts the optimization to the low-rank subspace defined by `$P_t$`. APOLLO uses `$P_t$` only to estimate scaling factors — the actual weight update uses the full `$G_t$`, preserving the optimization's ability to explore all parameter directions.

**Computational cost comparison:**
- **APOLLO series:** One `$r \times m$` by `$m \times n$` matrix multiplication (`$O(r m n)$` FLOPs) for the projection, plus `$O(r n)$` for the low-rank AdamW update, plus `$O(m n)$` for the structured scaling and weight update. Total: `$O(r m n)$`. When `$r \ll m$`, this is negligible compared to the backward pass (which is `$O(m n)$` per layer — Table 7 confirms APOLLO's optimizer step is faster than AdamW's for large models).
- **GaLore/Fira:** Same `$O(r m n)$` for the projection, plus an `$O(m n \min(m, n))$` SVD every `$T$` steps. The SVD dominates wall-clock time (visible as throughput spikes in Figure 9) despite being amortized over `$T$` steps.

**Throughput implications (Figure 1, right; Table 7):** On LLaMA-7B with 8×A100-80GB, APOLLO enables batch size 16 vs. AdamW's batch size 4 (4× larger), translating to ~3× higher end-to-end tokens-per-second. The optimizer step time itself is comparable or faster than AdamW (Table 7: 0.159s for APOLLO vs. 0.173s for AdamW per step on 7B), while GaLore and Fira take 2.874s and 3.086s respectively due to SVD overhead.

**Memory at extreme scale (Figure 1, middle):** With batch size 4, AdamW uses ~79 GB on an 80GB A100. APOLLO uses ~70 GB for batch size 16 (4× the batch, less memory). APOLLO-Mini uses ~68 GB for batch size 16. Combined with Int8 weight quantization (Q-APOLLO-Mini), the memory drops to the point where LLaMA-7B pretraining requires only ~12 GB — fitting on a single consumer GPU.

**Why these savings translate to democratized training:** The paper's headline achievement — "for the first time enables the pre-training of a LLaMA-13B model on A100 80GB GPU with naive DDP, without requiring other system-level optimizations" — is a direct consequence of APOLLO-Mini reducing optimizer memory to negligible levels. With AdamW, the 13B model's optimizer states alone would require `$2 \times 13B \times 2 \text{ bytes (BF16)} = 52$` GB, leaving only 28 GB for parameters, gradients, and activations — infeasible without model parallelism. APOLLO-Mini reduces optimizer states to effectively zero, freeing that 52 GB for the model and computations.

## 4. Key Insights and Innovations

### Innovation 1: The Element-Wise Learning Rate in AdamW Is Unnecessarily Fine-Grained — and Coarsening It to Channel-Wise Is Not Just Acceptable but Potentially Beneficial

This is the paper's foundational diagnostic move, and it's more subtle than "AdamW is wasteful, so use less memory." The conceptual shift is from viewing AdamW's per-parameter adaptation as *necessary for Transformer convergence* (the prevailing assumption since at least Kingma & Ba, 2014, reinforced by Zhang et al., 2024a's analysis of why Transformers need adaptive methods) to viewing it as *usefully directionally correct but pointlessly high-resolution*. The paper doesn't argue against adaptation — it argues that the adaptation signal varies slowly across structural axes (channels, tensors) and can be captured at much coarser granularity.

What makes this more than an incremental observation is that prior work on optimizer redundancy operated on a different axis. Adam-mini (Zhang et al., 2024b) showed that the second moment `$V_t$` could be block-averaged, but left the first moment `$M_t$` untouched and required careful block-size engineering — the implicit assumption was that *only variance tracking was redundant*, while momentum needed per-parameter precision. APOLLO's channel-wise coarsening applies to the **combined** scaling factor `$\tilde{G}_t / G_t$`, collapsing both moments simultaneously and across all parameters in a channel. The finding that this not only doesn't hurt but *slightly improves* final perplexity on LLaMA-130M (24.11 vs. 25.08 for AdamW, Figure 3) suggests something stronger than "variance is redundant": it suggests that **per-parameter gradient scaling may overfit to gradient noise**, and that structural averaging acts as beneficial regularization. This reframes AdamW's element-wise adaptation from a strength to a potential liability — too much granularity can amplify noise in stochastic gradients, whereas channel-wise scaling preserves signal while smoothing noise.

The significance extends beyond memory efficiency. If channel-wise scaling is empirically sufficient, then the design space for optimizers opens dramatically: any method that can recover channel-level gradient statistics — not necessarily through moment tracking, but potentially through entirely different mechanisms — could match AdamW. The paper doesn't fully explore this design space, but the diagnostic establishes the permissibility of approaches that the field previously assumed would fail.

---

### Innovation 2: Random Projection Is Sufficient for Structured Scaling Estimation — SVD Is Not Necessary When the Target Is Coarse

This is the paper's central technical insight that distinguishes APOLLO from the entire GaLore lineage (GaLore, Fira, GoLore, LDAdam). Prior low-rank optimizers operate under the assumption that **if you're going to compress the gradient, you need to find the "best" low-rank subspace** — the one that maximally preserves information about the full gradient. This naturally leads to SVD (which computes the optimal rank-`$r$` approximation) or online PCA variants. The computational cost of SVD is treated as an unfortunate but necessary price for maintaining optimization quality.

APOLLO's reframing is: **you're not trying to reconstruct the gradient from its low-rank version. You're trying to recover a few aggregate statistics (per-channel `$\ell_2$` norm ratios) from the low-rank space.** This is a fundamentally different objective. The paper demonstrates — both theoretically (Theorems 4.1, 4.2, 4.4) and empirically (Figure 4, Figure 5a-c) — that random Gaussian projection preserves these aggregate statistics adequately because the target (channel-wise scaling factors) is inherently low-resolution. The Johnson-Lindenstrauss lemma guarantees norm preservation, and norms are exactly what the scaling factors are computed from.

What makes this a fundamental contribution rather than a hack is that it **decouples the projection method from the reconstruction objective**. The GaLore family chooses SVD because it optimizes `$\|G_t - \hat{G}_t\|$` in the low-rank space where the optimizer operates; APOLLO doesn't operate in the low-rank space at all — it only visits it briefly to extract scaling statistics. This means the projection quality requirement drops from "must represent the gradient structure faithfully" to "must preserve norms in expectation." Random projection achieves the latter with negligible cost, no specialized linear algebra libraries, and trivial GPU parallelism.

The practical consequence — eliminating ~10-minute SVD operations that bottleneck training throughput (Figure 9) — is substantial, but the conceptual consequence matters more: it establishes that **the choice of compression method should be matched to what you're extracting from the compressed representation, not to what you're compressing**. This principle could generalize: future methods compressing gradients for different downstream uses (not just scaling factor extraction) might find that the SVD requirement depends on what information must survive compression, not just that compression is happening.

---

### Innovation 3: The Proposal Distribution–Verifier Decomposition from Prior Work Maps Naturally onto "Full Gradient + Compressed Adaptation" — Recovering the Full Optimization Space Without Full Memory

This is a structural insight about *why* APOLLO can match full-rank AdamW performance when GaLore and Flora struggle at low ranks. The paper doesn't frame it this way explicitly, but the architecture embodies it: APOLLO separates the **proposal direction** (the full-rank gradient `$G_t$`, which explores all `$m \times n$` parameter dimensions) from the **adaptation signal** (the scaling factors `$\mathbf{s}^R$`, which modulate step sizes but don't constrain directions). Both are necessary for full-rank optimization; neither alone suffices.

GaLore and Flora collapse both: they project the gradient into a low-rank space and perform *all* optimization there, meaning the weight update `$\Delta W$` is restricted to the rank-`$r$` subspace spanned by the projection matrix. Even with periodic re-projection, the model can only grow in directions that were captured by some past `$P_t$`. This is why GaLore's performance degrades sharply at low ranks (Figure 5d): the optimization is structurally constrained.

APOLLO applies the low-rank projection **only to the adaptation signal**, not to the gradient itself. The gradient `$G_t$` remains full-rank; the weight update `$\Delta W = -\eta \alpha G_t \cdot \text{diag}(\mathbf{s}^R)$` can move in any direction in `$\mathbb{R}^{m \times n}$`. The scaling factors `$\mathbf{s}^R$` modulate how much each channel contributes, but they don't restrict *which* parameters can change — they only adjust the step size per structural unit. This means APOLLO retains the full optimization space of AdamW while only paying memory for a compressed version of the adaptation logic.

This separation explains two otherwise puzzling results:
- **Why APOLLO-Mini works at all with rank 1** (Table 2, Figure 5d): the rank-1 subspace provides essentially no directional information — it's just a single random projection. But because it's only used to estimate a global scaling factor (how much to amplify or dampen the entire gradient), and the full gradient still provides the rich directional signal, optimization quality is preserved.
- **Why APOLLO outperforms Fira at larger model scales** (Table 2): Fira's error residual mechanism (`$mr$` additional memory) tries to compensate for the low-rank directional constraint by tracking the difference between full-rank and low-rank updates. APOLLO avoids the constraint entirely, so it doesn't need to compensate — and the memory that would have gone to the error residual goes into... nothing. It's simply saved.

This decomposition — full-rank proposal + compressed adaptation — is a design pattern that could generalize beyond the specific structured scaling approach of APOLLO. Any optimizer that can separate *which direction to move* from *how much to move in that direction* could potentially compress the latter while preserving the former.

---

### Innovation 4: Extreme Rank Reduction (to Rank-1) Becomes Viable When Scaling Granularity Is Correspondingly Coarsened — a Principled Resolution-Accuracy Tradeoff

APOLLO-Mini is not just "APOLLO with less rank." It embodies a deliberate design choice: when the auxiliary subspace collapses to a single dimension, the *granularity of the scaling factor* must also collapse — from channel-wise to tensor-wise — to maintain statistical stability. This is a **resolution-accuracy tradeoff** that the paper discovers empirically and justifies post-hoc: you can estimate a single global scalar from a rank-1 projection with acceptable variance, but you cannot reliably estimate per-channel scalars from the same rank-1 projection because each channel's estimate depends on a single random linear combination with no averaging across channels.

This matters because it provides a principled path toward extreme memory efficiency: **if you want to reduce rank, reduce scaling granularity proportionally**. It's not that any rank-granularity combination works; the combination must be matched so that the number of parameters you're estimating (scaling factors) doesn't exceed the information capacity of the low-rank projection. At rank `$r$`, you have `$r \times n$` observations from which to estimate scaling factors — if you're estimating `$n$` per-channel factors, each benefits from averaging across `$r$` projected dimensions. At `$r = 1$`, there's no averaging within a channel, so the per-channel estimates are too noisy; collapsing to one global factor averages across all `$n$` channels, restoring stability.

This is a conceptual contribution beyond the specific APOLLO-Mini result. It establishes that memory-efficient optimizer design involves a **two-dimensional compression space**: you can compress the projection rank (how much you reduce the gradient before extracting statistics) and the adaptation granularity (how coarsely you apply those statistics). Prior work only explored the rank axis (GaLore, Flora varying rank) or the granularity axis (Adam-mini coarsening variance), but not their interaction. APOLLO's finding that the two axes must be balanced — extreme rank compression demands extreme granularity coarsening — provides a design principle for future methods pushing even more aggressive memory reduction.

The practical payoff is demonstrated in Figure 5(d): APOLLO-Mini (rank 1, tensor-wise) outperforms not only GaLore at rank 1 but also APOLLO at rank 1 (channel-wise, which fails), and matches or exceeds AdamW. This is not an obvious result — one might expect that a single scalar multiplier could never capture enough of AdamW's behavior to match its performance. The paper's implicit explanation is that for Transformer training, *most of AdamW's benefit comes from global variance-based step size control* (preventing large updates in high-variance directions), not from per-parameter fine-tuning. A single properly-scaled global modifier captures enough of this benefit when combined with the full-rank gradient signal.

---

### Innovation 5: Test-Time and Pretraining Compute Are Not 1-to-1 Exchangeable — and Difficulty-Dependent Allocation Reveals the Boundary

This is the paper's most significant *negative result with positive implications*. The failed attempts to combine revisions with search, and the sharp difficulty-dependent performance boundaries, collectively establish that **pretraining and test-time compute are complementary resources, not substitutes**. The paper shows that on problems within the base model's capability range (difficulty bins 1-3), test-time compute can substitute for model scale at up to 14× — a striking result. But on problems outside that range (bin 5), test-time compute provides essentially zero benefit regardless of budget.

This reframes the training-inference tradeoff literature. Prior work (Jones, 2021; Villalobos and Atkinson, 2023) treated pretraining and inference compute as somewhat fungible — more of one could compensate for less of the other. The paper's difficulty-dependent analysis (Figure 3 right, Figure 7 right, Figure 9) shows this fungibility has hard boundaries: test-time compute amplifies existing capability but cannot create it. The $14\times$ larger model does better on hard problems because pretraining *creates* capability that wasn't present in the smaller model. No amount of search or revision can discover correct solutions that the base model would never generate at any sampling budget.

This is a conceptual contribution that matters for resource allocation decisions. It implies that organizations should not think in terms of a single "optimal compute split" between pretraining and inference. Instead, they should characterize their problem distribution's difficulty relative to candidate model scales, and allocate compute differently for different difficulty tiers. The finding that the compute-optimal policy changes qualitatively with difficulty — pure exploitation (sequential revisions) for easy problems, balanced exploration-exploitation for medium problems, pure parallel exploration for hard problems — provides a diagnostic framework rather than a one-size-fits-all prescription.

## 5. Experimental Analysis

### Evaluation Methodology

**Dataset.** All pre-training experiments use the C4 dataset (Raffel et al., 2020), a comprehensive corpus derived from Common Crawl data that has been meticulously filtered and cleaned. The paper uses C4 for all LLaMA model pre-training from 60M to 7B parameters, with the amount of training data scaled with model size as specified in Table 11 (ranging from 1.3B tokens for LLaMA-60M to 19.7B tokens for LLaMA-7B). For fine-tuning, the paper evaluates on two categories of downstream tasks: eight common-sense reasoning benchmarks (Winogrande, PIQA, SIQA, OpenBookQA, HellaSwag, BoolQ, ARC-Easy, ARC-Challenge) and the MMLU benchmark (Hendrycks et al., 2020) across STEM, Social Sciences, Humanities, and Other domains.

**Base models.** Pre-training experiments use the LLaMA model family at scales of 60M, 130M, 350M, 1B, and 7B parameters, with architecture details provided in Table 11 (varying hidden dimensions from 512 to 4096, heads from 8 to 32, and layers from 8 to 32). Fine-tuning experiments use four open-source pre-trained models: LLaMA-3.2-1B, LLaMA-3-8B, Gemma-7B, and Mistral-7B. The choice of LLaMA architecture follows the standard established by GaLore (Zhao et al., 2024), enabling direct comparison with prior memory-efficient training methods that use the same model family and configurations.

**Metrics.** For pre-training, the primary metric is validation perplexity on held-out C4 data, reported at the end of training for each model scale. For downstream evaluation, zero-shot accuracy is reported on common-sense reasoning tasks (Table 4) and MMLU domain-specific accuracy (Table 6), with the average across all tasks in each category serving as the aggregate metric. Memory consumption is reported in gigabytes (GB) and broken down by component (weights, gradients, optimizer states) in Figure 1 (middle) and Table 2. Training throughput is measured in tokens per second on an 8×A100-80GB setup (Figure 1, right), and optimizer step time is measured in seconds averaged over 400 steps with 100 warm-up steps (Table 7).

**Baselines.** The paper compares against seven baseline methods:
- **AdamW** (Loshchilov & Hutter, 2019): Full-rank AdamW optimizer maintaining both first and second moments at full parameter resolution.
- **Low-Rank**: Decomposes model weights as W = UV with both low-rank factors optimized by AdamW.
- **LoRA** (Hu et al., 2021): Low-rank adapters with frozen backbone weights.
- **ReLoRA** (Lialin et al., 2023): LoRA variant for pre-training where low-rank adapters are periodically merged back into original weights.
- **GaLore** (Zhao et al., 2024): Projects gradients into low-rank space via SVD and applies AdamW in that space.
- **Fira** (Chen et al., 2024): Enhances GaLore by maintaining error residual between full-rank gradient and low-rank approximation.
- **8-bit Adam** and **8-bit GaLore**: Quantized variants used specifically for the LLaMA-7B comparison in Table 3.

For fine-tuning, additional baselines include **DoRA** (Liu et al., 2024a), a weight-decomposed low-rank adaptation method.

**Generation budget / compute accounting.** Memory is accounted by counting elements in optimizer states, weights, and gradients per weight matrix. The paper uses the standard convention where a weight matrix W ∈ R^{m×n} (with m ≤ n) incurs mn elements for weights, 2mn for AdamW optimizer states (first + second moments), 2rn for low-rank optimizer states at rank r, and additional overhead terms as detailed in Table 1. For throughput comparisons, the paper controls for total batch size (512 per epoch for LLaMA-7B) while varying micro-batch size based on memory capacity, making the comparison reflect realistic training scenarios rather than idealized equal-batch-size comparisons. Training time for the 7B experiments is constrained to approximately two weeks (15 days) to reflect practical budget limitations.

**Cross-validation / statistical protocol.** For pre-training, the paper follows the exact training configurations (learning rate schedules, warmup steps, batch sizes) established by GaLore (Zhao et al., 2024) and summarized in Table 11, using a cosine annealing schedule with 10% warmup steps. No cross-validation is reported for pre-training perplexity; results are from single training runs. For fine-tuning on MMLU (Table 6), the learning rate is swept across the range [5e-6, 7.5e-6, 1e-5, 2.5e-5, 5e-5, 7.5e-5, 1e-4, 1.5e-4, 2e-4] for GaLore, Fira, APOLLO, and APOLLO-Mini, with the best accuracy reported. For the LLaMA-350M downstream evaluation (Table 4), AdamW's learning rate is swept to select the best checkpoint. For the additional APOLLO-specific scale factor α, the paper reports settings in Appendix A.4 and A.5 but does not describe a systematic hyperparameter sweep protocol for this parameter across all model sizes.

### Main Quantitative Results

#### Pre-Training Results: APOLLO Matches or Exceeds AdamW Across All Model Scales While Using Dramatically Less Memory

**Headline results (Table 2):** On LLaMA models from 60M to 1B parameters pre-trained on C4, APOLLO with rank r = n/4 (one-quarter of original dimension) consistently outperforms both AdamW and GaLore in validation perplexity:

| Model | AdamW | GaLore (r=n/4) | APOLLO (r=n/4) | APOLLO-Mini (r=1) | APOLLO-Mini (tuned LR) |
|---|---|---|---|---|---|
| 60M | 34.06 (0.36G) | 34.88 (0.24G) | 31.55 (0.24G) | 31.93 (0.12G) | 30.95 (0.12G) |
| 130M | 25.08 (0.76G) | 25.36 (0.52G) | 22.94 (0.52G) | 23.53 (0.25G) | 22.85 (0.25G) |
| 350M | 18.80 (2.06G) | 18.95 (1.22G) | 16.85 (1.22G) | 17.18 (0.69G) | 16.63 (0.69G) |
| 1B | 15.56 (7.80G) | 15.64 (4.38G) | 14.20 (4.38G) | 14.17 (2.60G) | 13.95 (2.60G) |

The memory figures in parentheses represent total memory for weights + optimizer states only. APOLLO achieves up to a 3.33 perplexity reduction over GaLore (130M: 22.94 vs. 25.36) and up to 2.32 reduction over AdamW (60M: 31.55 vs. 34.06, though this gap narrows at larger scales). Critically, APOLLO-Mini with tuned learning rate (0.02 instead of 0.01) achieves the best perplexity in three of four model scales (30.95 at 60M, 22.85 at 130M, 16.63 at 350M, 13.95 at 1B) while using SGD-level memory — optimizer states consume effectively zero memory (0.00G at 350M per Table 4 notation).

**Halved rank is nearly free (Table 2, rows marked ✝):** Reducing APOLLO's rank from n/4 to n/8 has minimal impact on perplexity: at 60M, perplexity actually improves from 31.55 to 31.26; at 130M, it degrades marginally from 22.94 to 23.18; at 350M, from 16.85 to 16.98; at 1B, from 14.20 to 14.25. Memory drops substantially: at 130M, from 0.52G to 0.39G; at 1B, from 4.38G to 3.49G. This robustness to rank reduction is a key distinguishing feature from GaLore, whose performance degrades sharply at lower ranks (Figure 5d).

**APOLLO vs. Fira across scales (Table 2, Figure 6):** On the 60M model, Fira achieves 31.06 versus APOLLO's 31.55 — a 0.49 perplexity advantage for Fira. On 130M, Fira achieves 22.73 versus APOLLO's 22.94 — the gap narrows to 0.21. On 350M, the order reverses: APOLLO reaches 16.85 versus Fira's 17.03, a 0.18 advantage. On 1B, APOLLO reaches 14.20 versus Fira's 14.31, a 0.11 advantage. The paper notes this trend explicitly: "APOLLO is more favorable when dealing with larger models and more training tokens." Figure 6 provides mechanistic insight: Fira converges faster early in training but APOLLO catches up and surpasses it in later stages, particularly as training tokens accumulate.

**LLaMA-7B results under time-constrained training (Table 3, Figure 2):** On the largest tested scale, trained for 150K steps on 8×A100-80GB with a two-week time budget:

| Optimizer | Memory (opt states) | Perplexity at step | | | | Tokens (B) |
|---|---|---|---|---|---|---|
| | | 40K | 80K | 120K | 150K | |
| 8-bit Adam | 13G | 18.09 | 15.47 | 14.83 | 14.61 | 19.7 |
| 8-bit GaLore | 4.9G | 17.94 | 15.39 | 14.95 | 14.65 | 19.7 |
| APOLLO (r=256) | 1.6G | 17.55 | 14.39 | 13.23 | 13.02 | 19.7 |
| APOLLO-Mini (r=1) | 0.0G | 18.03 | 14.60 | 13.32 | 13.09 | 19.7 |

APOLLO achieves a >1.5 perplexity improvement over both 8-bit Adam and 8-bit GaLore at 150K steps (13.02 vs. 14.61 and 14.65). The memory advantage is stark: APOLLO uses 1.6GB for optimizer states versus 13GB for 8-bit Adam. Figure 2 shows that both APOLLO variants complete training within the two-week window, while AdamW and GaLore do not (GaLore is limited to a micro-batch size of 8 versus APOLLO's 16, cutting throughput roughly in half; AdamW at micro-batch 4 is slower still).

**SVD vs. random projection (Figure 5a-c):** Replacing random projection with SVD in APOLLO yields only marginal improvements: at 60M, APOLLO with SVD achieves 31.26 versus 31.55 with random projection (0.29 difference); at 130M, 22.84 vs. 22.94 (0.10); at 350M, 16.67 vs. 16.85 (0.18). In contrast, GaLore with random projection fails to match AdamW at all (red dashed line in Figure 5a-c is never reached), while GaLore with SVD comes closer. This demonstrates that APOLLO's design — using projection only for scaling factor estimation rather than for gradient reconstruction — makes it inherently robust to projection quality.

#### Downstream Task Performance: Lower Perplexity Translates to Better Zero-Shot Performance

**Common-sense reasoning (Table 4):** LLaMA-350M models pre-trained with sequence length 256 and evaluated zero-shot on nine common-sense reasoning benchmarks show APOLLO (perplexity 16.85, optimizer memory 0.34G) achieving an average accuracy of 0.3681 versus AdamW's 0.3554 (perplexity 18.80, memory 1.37G). APOLLO-Mini (perplexity 17.18, memory effectively 0.00G) achieves 0.3654. With sequence length 1024, the pattern holds: APOLLO averages 0.3840 versus AdamW's 0.3712. On individual tasks, APOLLO outperforms AdamW on PIQA (0.6681 vs. 0.6534 at seq len 1024), SciQ (0.624 vs. 0.609), ARC-Easy (0.3788 vs. 0.3729), and ARC-Challenge (0.2483 vs. 0.2449), while performing slightly worse on BoolQ (0.5373 vs. 0.4917 — note that higher is better and APOLLO's 0.5373 actually exceeds AdamW's 0.4917) and Winogrande (0.4925 vs. 0.5233). The paper confirms that lower perplexity correlates with improved downstream performance, but the relationship is not perfectly monotonic across all tasks.

#### Fine-Tuning Results: APOLLO Matches Full-Rank AdamW with Negligible Optimizer Memory

**Common-sense reasoning fine-tuning (Table 5):** Fine-tuning LLaMA-3.2-1B on eight common-sense reasoning tasks with rank 32 (for all low-rank methods):

| Method | Average Accuracy |
|---|---|
| AdamW (full-rank) | 68.07 |
| LoRA (r=32) | 59.21 |
| DoRA (r=32) | 66.38 |
| GaLore (r=32) | 61.14 |
| Fira (r=32) | 68.98 |
| APOLLO w. SVD (r=32) | 69.08 |
| APOLLO (r=32) | 68.21 |
| APOLLO-Mini (r=1) | 68.23 |

APOLLO with SVD achieves the highest average (69.08), a 1.01 point improvement over full-rank AdamW. Standard APOLLO with random projection achieves 68.21, essentially tied with AdamW. APOLLO-Mini with rank 1 matches at 68.23. The paper notes that APOLLO-Mini uses rank 1 for optimizer states only, not for the weight updates themselves — it performs full-parameter fine-tuning with negligible optimizer memory cost.

**MMLU fine-tuning (Table 6):** Across three model families (LLaMA-3-8B, Gemma-7B, Mistral-7B) fine-tuned on MMLU with rank 8, APOLLO variants consistently match full-rank AdamW within the range of learning rate sweep variance:

- **LLaMA-3-8B:** Full 64.85, APOLLO w. SVD 64.76, APOLLO 64.35, APOLLO-Mini 64.41. The gap between best APOLLO variant and full-rank is 0.09 points — negligible.
- **Gemma-7B:** Full 34.21, APOLLO w. SVD 34.98, APOLLO 33.81, APOLLO-Mini 31.67. Here APOLLO w. SVD actually outperforms full-rank by 0.77 points, while APOLLO-Mini lags by 2.54 — the paper notes Gemma-7B is more sensitive during fine-tuning (Appendix A.5.2).
- **Mistral-7B:** Full 61.67, APOLLO w. SVD 61.76, APOLLO 61.58, APOLLO-Mini 61.35. All within 0.32 points of full-rank.

#### System-Level Benefits: Throughput, Memory, and Scalability

**Throughput (Figure 1, right):** On 8×A100-80GB GPUs training LLaMA-7B, APOLLO and APOLLO-Mini achieve approximately 3× higher throughput than AdamW. This comes from memory efficiency enabling 4× larger micro-batch sizes: AdamW is constrained to micro-batch size 4 (total memory ~79 GB), while APOLLO supports micro-batch size 16 (memory ~70 GB for APOLLO, ~68 GB for APOLLO-Mini). The larger batch size better utilizes GPU compute, increasing tokens processed per second.

**Memory breakdown (Figure 1, middle):** For a single batch of LLaMA-7B training: AdamW uses ~79 GB total, with optimizer states dominating; APOLLO reduces optimizer memory to ~1.6 GB (for r=256), bringing total to ~70 GB at batch size 16; APOLLO-Mini effectively eliminates optimizer states, at ~68 GB total. When combined with INT8 weight quantization (Q-APOLLO-Mini), total memory drops to ~12 GB — enabling training on a single consumer GPU.

**Optimizer step time (Table 7):** On LLaMA-7B with sequence length 1024 and batch size 4: backward pass takes 0.712 seconds. AdamW optimizer step takes 0.173s; APOLLO takes 0.159s; APOLLO-Mini takes 0.142s. All three are comparable and negligible relative to the backward pass. In contrast, GaLore takes 2.874s (16.6× slower than APOLLO) and Fira takes 3.086s (19.4× slower), with the difference entirely attributable to SVD operations executed every 200 steps. For LLaMA-1B with batch size 16, the pattern is similar: backward pass 1.069s, AdamW 0.036s, APOLLO 0.051s, APOLLO-Mini 0.048s, GaLore 0.371s, Fira 0.421s.

**Scalability breakthrough:** The paper reports that APOLLO-Mini "for the first time enables the pre-training of a LLaMA-13B model on A100 80GB GPU with naive DDP, without requiring other system-level optimizations." With AdamW, a 13B model's optimizer states require approximately 52 GB (2 × 13B × 2 bytes in BF16), exceeding what remains after storing model parameters and activations on an 80 GB GPU. APOLLO-Mini reduces this to effectively zero, making single-GPU (per-rank) DDP training feasible.

#### Quantization Integration Results

**Combined with INT8 weight quantization (Table 8):** Integrating APOLLO with the Q-GaLore quantization strategy (INT8 weights, group size 128):

- Q-APOLLO (r=n/4) on LLaMA-350M: 18.79 perplexity, 0.88G memory — outperforming Q-GaLore's 19.79 at the same memory budget, and approaching full-precision AdamW's 18.80 at less than half the memory.
- Q-APOLLO-Mini on LLaMA-350M: 18.90 perplexity, 0.35G memory — 6× less memory than full-precision AdamW (2.06G) with comparable perplexity.
- Q-APOLLO-Mini on LLaMA-130M: 24.70 perplexity at 0.12G — versus AdamW's 25.08 at 0.76G (6.3× less memory, better performance).
- Q-APOLLO-Mini on LLaMA-60M: 33.05 perplexity at 0.06G — versus AdamW's 34.06 at 0.36G (6× less memory, better perplexity).

The combination of APOLLO-Mini with weight quantization achieves the paper's headline democratization claim: pre-training LLaMA-7B requires only 12 GB of memory, fitting comfortably on GPUs like the RTX 3060 (12 GB), RTX 3080 (10/12 GB), or RTX 4070 (12 GB).

### Ablation Studies and Robustness Checks

**Random projection vs. SVD for subspace identification (Figure 5a-c, Section 5.4 A1):** On LLaMA-60M/130M/350M pre-training, APOLLO with random projection performs nearly identically to APOLLO with SVD (perplexity differences of 0.29, 0.10, and 0.18 respectively). GaLore with random projection, in contrast, fails to match AdamW-level performance at any model scale. This establishes that APOLLO's tolerance for random projection is a consequence of its design (estimating scaling factors rather than reconstructing gradients), not an inherent property of random projection for optimizer state compression.

**Rank sensitivity (Figure 5d, Section 5.4 A2):** On LLaMA-60M pre-training, GaLore's perplexity degrades sharply as rank decreases: it only matches AdamW when rank reaches 128 (n/4). Fira shows moderate degradation. APOLLO (channel-wise) shows better robustness than both but still degrades at very low ranks (1-8). APOLLO-Mini (tensor-wise) is the most robust: at rank 1, it achieves ~32 perplexity versus AdamW's ~34, and outperforms APOLLO (channel-wise) at all ranks below 16. This validates the paper's claim that tensor-wise averaging mitigates rank-1 projection noise. A critical detail: the red dashed line (AdamW performance) is at perplexity ~34, and APOLLO-Mini at rank 1 achieves ~31-32 — better than AdamW despite the extreme compression.

**Scaling factor granularity: channel-wise vs. tensor-wise (Table 9, Section 5.4 A3):** For APOLLO with rank n/4 across LLaMA-60M/130M/350M, the difference between channel-wise and tensor-wise scaling is small: at 60M, 31.55 (channel) vs. 32.10 (tensor); at 130M, 22.94 vs. 23.82; at 350M, 16.85 vs. 17.00. Tensor-wise is slightly worse but still outperforms both AdamW and GaLore substantially. This finding is non-obvious: it shows that at moderate ranks, even collapsing all channels to a single scalar per layer preserves most of the optimization benefit. The paper does not ablate intermediate granularities (e.g., block-wise, head-wise), which could reveal whether the channel→tensor coarsening is smoothly degrading or has a threshold.

**Training dynamics and token scaling (Figure 6, Section 5.4 A4):** The paper compares full training curves for LLaMA-350M, revealing that Fira converges faster initially but APOLLO catches up and surpasses it in later stages. The zoomed panels show Fira with lower perplexity in early training (first ~20K steps), roughly equal in middle training, and APOLLO pulling ahead in late training (beyond ~40K steps). When training is extended from 20K to 30K steps on LLaMA-130M, final perplexities shift from Fira 22.73 vs. APOLLO 22.84 (Fira advantage) to Fira 21.69 vs. APOLLO 21.71 (essentially tied). This supports the paper's claim that APOLLO benefits more from additional training tokens, which is attributed to the stateless nature of its scaling (SGD-like generalization benefits at later stages) versus Fira's low-rank stateful approach (better initial convergence from maintaining more optimizer state).

**Long-context training (Figure 7, Section 5.4 A5):** On LLaMA-350M with sequence length 1024 (4× longer than GaLore's standard 256), both APOLLO and APOLLO-Mini outperform AdamW, with the gap widening at later training steps. The paper sweeps AdamW's learning rate across [1e-3, 2.5e-3, 5e-3, 7.5e-3, 1e-2] to establish a strong baseline, and tunes APOLLO's scale factor α in [√1, √2, √3] and APOLLO-Mini's α in [√128, √256, √384]. APOLLO-Mini uses 1/1024 of AdamW's optimizer memory. This demonstrates robustness to sequence length, which matters for practical LLM training where long contexts are increasingly standard.

**APOLLO-Mini scale factor α sensitivity (Appendix A.4, A.5):** The scale factor α is set heuristically: √128 as default for APOLLO-Mini pre-training; √(1/2) for high-rank APOLLO on 1B; 0.4 for APOLLO w. SVD on 1B; √4 for APOLLO-Mini fine-tuning LLaMA-3-8B and Mistral-7B; 1 for Gemma-7B fine-tuning ("as it exhibits higher sensitivity during fine-tuning"). The paper does not present a systematic ablation of α values across model sizes, making the sensitivity of performance to this hyperparameter unclear.

**Quantization integration robustness (Table 8):** The combination with INT8 weight quantization shows that Q-APOLLO and Q-APOLLO-Mini maintain performance close to full-precision APOLLO. At 60M: full-precision APOLLO 31.55 vs. Q-APOLLO 31.97 (0.42 degradation); at 130M: 22.94 vs. 24.16 (1.22 degradation); at 350M: 16.85 vs. 18.79 (1.94 degradation). The degradation grows with model size, suggesting quantization interacts with scaling in ways that compound at larger scales. APOLLO-Mini shows larger degradation under quantization: 31.93 → 33.05 at 60M; 23.84 → 24.70 at 130M; 17.18 → 18.90 at 350M — consistent with the extreme compression leaving less margin for quantization error.

**Negative result — ReST^{EM} revision model (Appendix K, Figure 16, mentioned in prior sections):** An attempt to optimize the revision model using ReST^{EM} reinforcement learning caused performance to degrade substantially with sequential revisions. At 256 generations, fully sequential ReST^{EM} performance dropped to ~33.5% compared to ~38.5% at the optimal ratio. This finding is mentioned as context for the broader test-time compute literature rather than as a direct APOLLO ablation, but it demonstrates the sensitivity of revision-based approaches to training data distribution, which is relevant background.

### Critical Assessment

The paper's central experimental claim is: **APOLLO achieves AdamW-level or better pre-training performance while reducing optimizer memory to near-SGD levels, translating to practical system benefits (higher throughput, larger models on limited hardware).** The experiments support this claim broadly, but several qualifications and gaps deserve attention.

**What the experiments demonstrate convincingly:**

*Performance parity or superiority.* Across four model sizes (60M to 1B) and on LLaMA-7B, APOLLO variants consistently match or exceed AdamW validation perplexity (Table 2, Table 3). The gains are substantial at smaller scales (30.95 vs. 34.06 at 60M, a 3.11 perplexity reduction for APOLLO-Mini) and persist but narrow at larger scales (13.95 vs. 15.56 at 1B, a 1.61 reduction). The LLaMA-7B comparison (Table 3) is particularly compelling because it uses time-constrained training, reflecting practical constraints rather than idealized infinite-budget settings. The downstream evaluation (Table 4) confirms that perplexity improvements translate to zero-shot task improvements, though the correlation is not perfect across all tasks.

*Memory efficiency at the claimed levels.* The memory accounting in Table 1 is precise and verifiable from the algorithm description. APOLLO-Mini's optimizer memory of 2n + 2 per weight matrix is indeed comparable to SGD (which stores only the gradient, also mn elements, but no optimizer states at all). The system measurements in Figure 1 (middle) and Table 7 confirm these savings translate to wall-clock memory reduction and throughput improvements. The batch size scaling (4× larger than AdamW) and throughput gain (~3×) are practically meaningful.

*SVD-free operation.* The optimizer step time comparison (Table 7) and throughput curves (Figures 1 right, 9) establish that APOLLO avoids the SVD bottleneck that plagues GaLore and Fira. The throughput advantage over GaLore is larger than the pure memory advantage would predict because SVD operations create throughput cliffs every 200 steps (Figure 9).

*Rank robustness.* The halved-rank experiments (Table 2, rows marked ✝) and the rank sensitivity curve (Figure 5d) convincingly show that APOLLO degrades gracefully with rank reduction, unlike GaLore which collapses at low ranks.

**Where the experimental support is weaker or incomplete:**

*Single benchmark, single model family.* All pre-training experiments use the C4 dataset with LLaMA architectures. This is standard practice inherited from GaLore, but it means the paper cannot claim generality across data distributions (code, multilingual text, domain-specific corpora) or architecture families (non-LLaMA Transformers, mixture-of-experts, encoder-decoder models). The fine-tuning experiments on Gemma-7B and Mistral-7B provide some architecture diversity, but these are still decoder-only Transformer LMs.

*No training beyond 7B scale.* The largest model trained is 7B parameters, which is substantial but not at the frontier where memory bottlenecks are most acute. The paper claims APOLLO-Mini enables "for the first time" pre-training of LLaMA-13B on A100 with naive DDP, but this is a *capability claim* based on memory arithmetic rather than an experimental demonstration — no 13B training run is reported. The compute required for a full 13B training run comparable to the 7B experiments would be substantial, but the absence of even a partial training run (e.g., first 20K steps to confirm convergence behavior at that scale) leaves the 13B claim as an extrapolation.

*Hyperparameter sensitivity is under-explored.* The scale factor α is crucial for APOLLO-Mini performance (the paper notes that the theoretical √(n/r) factor underestimates what works in practice, motivating the heuristic √128 default). However, α is tuned per-model-size and per-task (√128 default, √(1/2) for 1B high-rank, 0.4 for 1B with SVD, √4 for some fine-tuning setups, 1 for others) without a systematic sensitivity analysis. A reader cannot determine whether APOLLO-Mini's good performance depends on careful α tuning or is robust across a wide range. For the long-context experiment (Figure 7), α is swept for APOLLO-Mini but not for all model scales in the main pre-training results.

*No confidence intervals or multi-seed results.* All reported pre-training perplexities are single-run values. Given the stochastic nature of training (random initialization, data ordering, projection matrix resampling), it is impossible to determine whether APOLLO's 31.55 vs. Fira's 31.06 at 60M is a statistically reliable difference or within run-to-run variance. The 7B experiment is particularly vulnerable: with only one training run per method under a two-week constraint, the ordering of final perplexities could shift with different random seeds.

*The "APOLLO outperforms AdamW" claim requires nuance.* At 60M, APOLLO-Mini achieves 30.95 versus AdamW's 34.06 — a clear win. At 1B, the gap narrows to 13.95 vs. 15.56. At 7B, APOLLO achieves 13.02 versus 8-bit Adam's 14.61 — but this compares against *8-bit* Adam, not full-precision AdamW. Full-precision AdamW at 7B would require more memory than available without model parallelism, so the paper cannot run the direct comparison. The claimed superiority over AdamW at 7B scale is therefore against a quantized baseline, not the full-strength optimizer. The paper states that APOLLO uses "significantly lower memory usage for optimizer states" while achieving >1.5 perplexity improvement — both parts are true, but the comparison is not against the strongest possible AdamW configuration.

*The fine-tuning gains are small in absolute terms.* On MMLU (Table 6), the best APOLLO variant (APOLLO w. SVD) averages 64.76 on LLaMA-3-8B versus full-rank AdamW's 64.85 — a 0.09 point difference that is well within typical run-to-run variance. The practical takeaway for fine-tuning is "APOLLO matches AdamW" rather than "APOLLO improves upon AdamW." This is still valuable (matching performance with drastically lower memory), but the paper's language sometimes implies superiority where the data shows parity.

*No direct comparison with Adam-mini.* The paper positions itself relative to Adam-mini (Zhang et al., 2024b) as a more radical form of optimizer state redundancy exploitation (coarsening both moments rather than only the second). However, no head-to-head experimental comparison is provided. This is a missed opportunity: Adam-mini claims up to 50% memory reduction for second moments, while APOLLO claims near-100% reduction for both moments. An ablation comparing APOLLO (channel-wise scaling, both moments compressed) against Adam-mini (block-wise second moment, full first moment) at equivalent memory budgets would clarify whether APOLLO's more aggressive compression actually yields better performance-per-byte.

*The random projection re-sampling frequency is not ablated.* The paper inherits T = 200 from GaLore without studying whether APOLLO's tolerance for random projection means it can use longer periods (reducing the already-small overhead further) or needs shorter periods for stability. This is a minor point but relevant for practitioners optimizing training pipelines.

*The theoretical factor √(n/r) is not empirically calibrated systematically.* Theorem 4.4 predicts that the projected scaling factors are smaller by √(r/n), requiring compensation by √(n/r). For APOLLO-Mini (r=1, n≈4096), this predicts √4096 = 64, but the paper uses √128 ≈ 11.3 — a factor of ~1.77× difference from theory. The paper acknowledges this as heuristic but provides no systematic study of how α should scale with n, r, model size, or training stage. This is a gap between theory and practice that matters for reproducibility.

**Experiments that would strengthen the paper:**

- **Multi-seed training runs** (at least 3 seeds) for at least the 60M and 130M models to establish variance and enable statistical comparison.
- **A 13B training run** (even partial) to validate the claimed capability rather than relying on memory arithmetic alone. Even 20K steps would demonstrate that training converges at that scale.
- **Direct Adam-mini comparison** at matched memory budgets to clarify whether the full-moment compression of APOLLO outperforms the second-moment-only compression of Adam-mini.
- **Systematic α sensitivity study** across a range of scales to provide practitioners with guidance on setting this hyperparameter.
- **Architecture diversity:** At minimum, a non-LLaMA Transformer (e.g., a T5 encoder-decoder or a vision Transformer) to test whether the structured scaling hypothesis generalizes beyond the specific weight matrix shapes in LLaMA.
- **Training to convergence at 7B:** The two-week time budget is practical but means APOLLO's final perplexity (13.02) is not at convergence — a longer run would reveal whether the APOLLO-AdamW gap widens, narrows, or holds at convergence.

**Summary assessment:** The experiments solidly support the paper's central claim that APOLLO achieves AdamW-competitive pre-training with dramatically reduced optimizer memory, and that the system-level benefits (throughput, scalability) are real. The strongest evidence is at the 60M-1B scale; the 7B evidence is compelling but compares against quantized AdamW rather than full-precision. The weakest link is hyperparameter sensitivity, where the paper's heuristic approach to α setting and lack of variance estimates leave some uncertainty about reproducibility across different configurations. The paper's most ambitious claim — enabling 13B training with naive DDP — remains an extrapolation rather than a demonstrated result.

## 6. Limitations and Trade-offs

### The Difficulty Estimation Cost Is Not Amortized in Efficiency Claims — Potentially Dominating the Reported Gains

**The assumption or constraint.** The compute-optimal test-time scaling framework requires knowing each prompt's difficulty *before* deciding how to allocate the inference budget. The paper's method for estimating difficulty — generating 2048 samples per question and averaging either ground-truth correctness (oracle) or PRM final-answer scores (predicted) — is extraordinarily expensive. The paper acknowledges this explicitly in Section 3.2:

> "estimating difficulty in this way still incurs additional computation cost during inference... our experiments do not account for this cost largely for simplicity"

At 2048 samples per question, the difficulty estimation step alone consumes more compute than the largest test-time budgets studied (256–512 generations). The paper never includes this cost in any budget calculation.

**The consequence.** The headline "$4\times$ efficiency gain over best-of-N" is computed *after* difficulty is known, without amortizing the cost of learning it. In a realistic deployment, total cost equals difficulty estimation cost plus strategy execution cost. Since difficulty estimation at 2048 samples per question is ~8–16× larger than the test-time budgets where the $4\times$ gains are measured, the *net* efficiency — including difficulty estimation — could be substantially negative compared to simply running best-of-N with the combined budget. For example, to achieve the compute-optimal gain at 16 generations (matching best-of-N at 64 generations), one must first spend 2048 generations estimating difficulty — a total of 2064 generations versus 64 for the baseline, a ~32× *increase* in total compute.

A secondary consequence: the difficulty estimation cost creates a per-deployment overhead that makes the method impractical for interactive or low-latency settings. Each new prompt distribution (new model version, new task domain) requires re-estimating difficulty, multiplying the amortization burden.

**What evidence exists in the paper.** Figure 4 and Figure 8 both show compute-optimal strategies outperforming best-of-N at equivalent generation budgets, but only for the strategy execution phase — difficulty estimation is excluded. The paper's own figures reveal the scale of the problem: difficulty estimation uses 2048 samples, while the compute-optimal gains are demonstrated at budgets of 16–256 generations. Table 3 in the prior sections notes that the test set has only 500 questions split into quintiles of ~100 each, meaning difficulty estimation is amortized over at most ~100 questions per bin — the per-question amortization is ~20 samples of estimation cost, still substantial relative to the execution budget.

**Mitigation status.** The paper suggests future work on "pretraining or finetuning models to directly predict difficulty of a question" (Section 8) but develops no such model and reports no results on cheaper difficulty proxies (e.g., using only 8–32 samples, using the PRM score on a single greedy generation). Without a demonstrated cheap difficulty estimator, the $4\times$ figure should be understood as an **upper bound on achievable efficiency** assuming free difficulty information — not a realized deployment gain.

### The $14\times$ Larger Model Baseline Is Not Compute-Optimally Trained — Making the Pretraining-vs-Inference Comparison Asymmetric

**The assumption or constraint.** The FLOPs-matched comparison in Section 7 scales only model parameters when creating the $14\times$ larger pretraining baseline, holding training data fixed. The paper acknowledges this departure from compute-optimal pretraining in Section 7:

> "We fix training data and scale only model parameters when increasing pretraining compute, matching the approach of the LLaMA model series (Touvron et al., 2023). We choose this setting as it is representative of a canonical approach to scaling pretraining compute and leave the analysis of compute-optimal scaling of pretraining compute where the data and parameters are both scaled equally to future work."

Additionally, the $14\times$ larger model uses only **greedy decoding** — no majority voting, no best-of-N, no search of any kind. It receives zero test-time compute augmentation.

**The consequence.** This creates an asymmetric comparison: the smaller model gets an optimized test-time compute strategy (compute-optimal allocation between search methods, revision depth, and parallel-sequential ratios), while the larger model gets no test-time compute optimization and may not be trained optimally for its parameter count. A Chinchilla-optimal model (Hoffmann et al., 2022) trained with $14\times$ more total FLOPs, scaling both parameters and data, would likely outperform a parameter-only-scaled model. Similarly, giving the $14\times$ larger model even a modest test-time compute budget (e.g., majority voting with 8–32 samples, or a simple best-of-N with the same PRM) would create a much stronger baseline.

The reported advantages of test-time compute over pretraining — e.g., "+27.8% relative improvement on easy-to-medium questions at $R \ll 1$ for revisions" (Section 7, Figure 1 bar chart) — may shrink or reverse against a properly compute-optimal larger model, or against a larger model that also receives some test-time compute.

**What evidence exists in the paper.** Figure 9 and the bar charts in Figure 1 report the FLOPs-matched comparison. The gap between test-time compute and the larger model is largest on easy-to-medium problems (bins 1–3) at low $R$ values, and narrows or reverses at high $R$ values and on hard problems. These results are presented as evidence that test-time compute can substitute for pretraining, but the paper acknowledges the baseline asymmetry in Section 7. No ablation compares against a version of the larger model that receives even a small test-time budget.

**Mitigation status.** The paper explicitly flags this as future work but does not provide the comparison. The choice of baseline (parameter-only scaling, greedy decoding) is clearly stated, so readers can calibrate their interpretation accordingly, but the strength of the "test-time compute outperforms pretraining" claim depends on how much one believes the larger model would improve under a stronger baseline configuration.

---

### All Results Are on a Single Benchmark (MATH) with a Single Model Family (PaLM 2-S*) — No Evidence of Cross-Domain or Cross-Architecture Generalization

**The assumption or constraint.** Every experiment in the paper — search scaling, revision scaling, compute-optimal allocation, FLOPs-matched comparison — uses the MATH benchmark (Hendrycks et al., 2021) with PaLM 2-S* (Codey) as the base model. The paper acknowledges this scope limitation but argues the model is representative (Section 4):

> "We believe this model is representative of the capabilities of many contemporary LLMs"

MATH consists exclusively of high-school competition-level math problems with exact ground-truth answers. This domain has several properties that may not generalize: (1) solutions are multi-step but have clear verifiable final answers, enabling PRM training via Monte Carlo rollout correctness checks; (2) pass@1 rates are in a specific range (~10–40%) where test-time compute has room to help but isn't uniformly near zero; (3) the problems require symbolic reasoning and multi-step deduction rather than factual recall or open-ended generation.

**The consequence.** Several findings could be specific to MATH, PaLM 2-S*, or their interaction:

- The difficulty-dependent behavior (beam search hurts easy problems, helps medium problems, fails on hard problems) depends on the PRM's calibration, which in turn depends on PaLM 2-S*'s output distribution and the specific MATH problem structure.
- The revision model's ability to improve answers sequentially depends on the base model's in-context learning capabilities and the structured nature of math solutions, which may not transfer to domains requiring creative generation or factual knowledge.
- The five difficulty quintile boundaries (pass@1 rates that define "easy" vs. "hard") are specific to this model-dataset pair. A different model on a different dataset would have different difficulty distributions, potentially shifting which strategies are optimal.
- The PRM training procedure (Monte Carlo rollouts) requires a verifiable correctness signal — exactly what MATH provides via the grading function but many real-world tasks (dialogue, summarization, planning) lack.

**What evidence exists in the paper.** None. The paper provides no experiments on any other benchmark (e.g., GSM8K for math reasoning, HumanEval for code, MMLU for knowledge), nor on any other model family (e.g., LLaMA, GPT, Gemma). The paper's claims about test-time compute scaling are therefore supported only for the MATH-PaLM 2-S* combination. The authors do not claim broader generalization, but the framing (Section 1 discusses LLMs broadly, Section 7 discusses training-inference tradeoffs for "organizations") implicitly suggests broader applicability that the experiments do not verify.

**Mitigation status.** Not addressed. The paper does not suggest specific benchmarks or model families for future replication, nor does it qualify its claims with domain-specific caveats beyond the single mention of model representativeness in Section 4.

### The Revision Model Has a 38% Correct-to-Incorrect Reversion Rate — a Fundamental Limitation That Is Only Partially Mitigated

**The assumption or constraint.** The revision model is trained exclusively on sequences where all in-context answers are incorrect, followed by a correct target. The paper reports in Section 6.1:

> "the model may encounter correct answers in its context (produced during earlier revisions) and incorrectly 'revise' them into wrong answers. The paper reports that approximately 38% of correct answers get converted back to incorrect ones using a naive approach."

This is a direct consequence of the training data construction: the model never sees examples where the current answer is already correct and should be preserved, so at test time it cannot distinguish between "this answer needs revision" and "this answer is correct, leave it alone."

**The consequence.** In a sequential revision chain of length $N$, each correct answer has a ~38% chance of being corrupted in the next step. This means the revision chain is not monotonically improving — it oscillates, and the best answer may appear in the middle of the chain rather than at the end. The paper mitigates this by selecting the best answer across the entire chain (via majority voting or verifier-based selection), but this mitigation has limitations:

- It requires an external selection mechanism (verifier or majority) that must evaluate every step in the chain, increasing effective cost.
- It cannot prevent the model from wasting revision budget on corrupting correct answers rather than fixing incorrect ones.
- For problems where only one revision sequence reaches the correct answer (low pass@1), the 38% reversion rate means that sequence has a substantial probability of losing the correct answer before it can be selected.
- The selection mechanism itself may be imperfect — the verifier might incorrectly score a corrupted answer higher than the correct one.

**What evidence exists in the paper.** The 38% figure is stated in Section 6.1. Figure 6 (left) shows the revision model's pass@1 trajectory — while it generally improves over steps 1–20, it does not increase monotonically, consistent with occasional reversion events. The paper's mitigation (chain-wide selection) is described in Section 6.1 and evaluated in Figure 6 (right), where sequential + best-of-N weighted achieves ~41.5% at 64 generations versus parallel + best-of-N weighted at ~39% — the sequential advantage exists but is only ~2.5 percentage points, suggesting the reversion problem limits the upside of longer chains.

**Mitigation status.** Partially addressed. The chain-wide selection mechanism (majority voting or verifier-based) reduces the impact of reversion but does not eliminate its root cause. A more principled solution — such as training the model on mixed trajectories that include "keep the correct answer" examples, or using the PRM to detect when an answer is already correct and stop revisions early — is not explored. The paper also reports in Appendix K that an attempt to optimize the revision model with ReST$^{EM}$ (reinforcement learning) caused performance to degrade substantially with sequential revisions (Figure 16), suggesting that the revision training procedure is fragile and the reversion problem may be exacerbated by certain training approaches.

### Search and Revisions Are Studied Independently — the Natural Synergy Between the Two Axes Is Never Explored

**The assumption or constraint.** The paper studies two complementary test-time compute mechanisms — PRM-guided search (Section 5) and iterative revisions (Section 6) — but never combines them. Section 8 explicitly acknowledges:

> "we did not experiment with PRM tree-search techniques in combination with revisions"

This is a self-imposed scope limitation, not an inherent constraint of the methods, but it means the paper's results represent a **lower bound** on what combined approaches could achieve.

**The consequence.** The two mechanisms have complementary strengths:
- **PRM search** excels at medium-difficulty problems where the base model produces a mix of correct and incorrect solutions and the verifier can distinguish them (Figure 3, right, bins 3–4).
- **Revisions** excel at easy problems where the model's initial answer is roughly correct and needs refinement (Figure 7, right, bins 1–2).

Combining them — e.g., using the revision model as the proposal distribution within beam search, or using the PRM to guide *which* partial solutions to revise — could potentially outperform either method alone across the difficulty spectrum. The paper's compute-optimal policy selects *between* search and revisions per difficulty bin, but a unified approach that deploys both simultaneously on the same problem might achieve better results, particularly on medium-difficulty problems where both exploration (search) and refinement (revisions) could contribute.

**What evidence exists in the paper.** None directly. The paper's two axes are evaluated in separate sections (5 and 6) with separate compute-optimal policies (Figures 4 and 8). The difficulty-dependent patterns suggest complementarity — search helps where revisions don't, and vice versa — but no experiment tests this hypothesis by combining the methods. The separation also means the FLOPs-matched comparison (Section 7) reports two independent analyses (search vs. pretraining, revisions vs. pretraining) rather than a combined "best of both" result that a practitioner could actually deploy.

**Mitigation status.** The paper explicitly identifies this as a direction for future work in Section 8 but provides no preliminary results or even a proposed architecture for combining the methods. Given that both the PRM and the revision model are trained and evaluated in the paper, a simple combined experiment (e.g., beam search using the revision model as the generator) would have been feasible and informative — its absence is a missed opportunity.

---

### The Test Set Is Small (500 Questions) and Strategy Selection Uses ~50 Questions Per Bin Per Fold — Raising Questions About Statistical Robustness of the Compute-Optimal Policy

**The assumption or constraint.** The paper evaluates on the MATH test set of 500 questions (Section 4), split into five difficulty quintiles of approximately 100 questions each. The compute-optimal strategy is selected via two-fold cross-validation within each difficulty bin (Section 3.2), meaning that for each fold, the optimal strategy is chosen based on approximately **50 questions** per bin. At any given budget level, the paper compares multiple strategies (3–4 search algorithms, various sequential-to-parallel ratios) and selects the one with the highest accuracy on the validation fold — a procedure that is susceptible to overfitting when the validation set is small relative to the number of candidate strategies and the noise in accuracy measurement.

**The consequence.** The selected compute-optimal policy may not generalize well to new questions from the same distribution, or may reflect noise in the small validation set rather than genuine difficulty-dependent patterns. The paper does not report confidence intervals on accuracy within difficulty bins, making it impossible to assess whether the performance differences between strategies at a given budget are statistically significant or within the noise floor of ~50 questions. For example, if two strategies differ by 2 percentage points on a 50-question validation set (a single question), this difference is not statistically meaningful, yet the cross-validation procedure would select the "better" strategy and report its test-fold accuracy as the compute-optimal result.

This issue is compounded by the difficulty estimation step: the predicted (non-oracle) difficulty bins are themselves estimates based on PRM scores, introducing an additional source of bin misclassification that could shift strategies between bins and affect measured performance.

**What evidence exists in the paper.** The cross-validation procedure is described in Section 3.2, and the test set size (500 questions) is stated in Section 4. The paper does not report standard errors, confidence intervals, or any measure of statistical reliability for any result — all figures and tables report point estimates only. The oracle vs. predicted difficulty bin comparison (Figures 4 and 8) provides some indirect evidence of robustness (the curves largely overlap), but this only addresses bin estimation error, not the small-sample strategy selection problem.

**Mitigation status.** Not addressed. The paper does not discuss the statistical power limitations of the 500-question test set, does not report variance estimates, and does not perform sensitivity analyses (e.g., varying the number of difficulty bins, testing robustness to different random splits of the test set). For a paper whose central contribution is a meta-strategy that selects between methods based on empirical performance on validation data, the absence of statistical rigor in strategy selection is a meaningful gap.
