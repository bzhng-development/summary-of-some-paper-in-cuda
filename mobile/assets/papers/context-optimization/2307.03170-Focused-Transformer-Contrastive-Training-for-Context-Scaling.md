# Focused Transformer: Contrastive Training for Context Scaling

**ArXiv:** [2307.03170](https://arxiv.org/abs/2307.03170)

## 🎯 Pitch

This paper introduces the **Focused Transformer (FOT)**, a technique that addresses what the authors identify as the **distraction issue** — the phenomenon where, as the number of documents in context increases, attention becomes evenly spread across relevant and irrelevant keys, degrading the model's ability to focus on pertinent information.

---

## 1. Executive Summary

This paper introduces the **Focused Transformer (FOT)**, a technique that addresses what the authors identify as the **distraction issue** — the phenomenon where, as the number of documents in context increases, attention becomes evenly spread across relevant and irrelevant keys, degrading the model's ability to focus on pertinent information. The method applies contrastive-learning-inspired training to a subset of attention layers, exposing them to both positive (same-document) and negative (other-document) key–value pairs during training, and augments inference with a k-nearest-neighbors memory lookup (enabling context lengths up to 256k tokens on passkey retrieval). Fine-tuning 3B and 7B OpenLLaMA checkpoints into **LONGLLAMA** models yields a 4× context length extrapolation (73% accuracy at 256k tokens despite training on only 8k tokens) and significant gains on few-shot tasks like TREC — establishing that test-time context can be extended far beyond the training horizon only when the key–value space has been structured via contrastive exposure to distractions during training.

## 2. Context and Motivation

### The Core Problem: Attention Gets Distracted When Context Grows

The fundamental problem this paper tackles is deceptively specific yet practically crippling: **when you feed a Transformer many documents in its context window, its attention mechanism cannot distinguish which information belongs to which document, and performance degrades as a result**. The authors give this phenomenon a precise name — the **distraction issue** — and frame it as "one of the primary obstacles in augmenting the context length" (Section 1).

Here's what "distraction" means concretely. In a standard Transformer, the attention layer computes a weighted sum over all preceding keys, where the weights come from a softmax over query–key inner products. When you concatenate multiple unrelated documents into the context (e.g., several books, or multiple source code repositories), the keys from *irrelevant* documents can have inner products with the query that are comparable to those from the *relevant* document. Because the softmax normalizes across ALL keys, the attention mass gets spread thinly across everything — both useful and useless information. The authors quantify this in Section 3.3, introducing a metric called **positive attention mass** ($r_d$): the fraction of attention weight that falls on keys from the *same* document as the query. Their finding is stark:

> "we observe that $r_d \approx 1/d$, which can be interpreted as the fact that the attention is equally distracted by the positive (coming from the current document at $i = 1$) and negative keys."

In plain language: if there are $d$ documents in the context, the model gives roughly $1/d$ of its attention to the right document, and the remaining $(d-1)/d$ to irrelevant ones. As $d$ grows, the signal-to-noise ratio approaches zero. This is not merely a curiosity — it means that simply expanding the context window (e.g., giving the model access to an entire codebase or a library of research papers) can *hurt* performance unless the model has been taught to focus.

### Why This Problem Matters

The motivation is intensely practical and arises from a tension in how we currently use large language models (LLMs).

**The knowledge integration bottleneck.** LLMs have two primary mechanisms for incorporating new information: fine-tuning and in-context learning. Fine-tuning is resource-intensive, requires managing training pipelines and data versions, and — crucially — does not actually teach the model *facts* in the way users might expect. The authors illustrate this with a pointed example (Section 1):

> "fine-tuning on a text such as 'Alice in Wonderland' does not equip the model to answer questions about the story itself, but rather it trains the model to predict the next token or complete masked sentences."

Fine-tuning changes the model's behavior on the distribution it was trained on, but does not give it explicit, queryable memory of the content. In-context learning — dropping the relevant text directly into the prompt — does provide explicit access, but is "considerably restricted by the model's effective context length" (Section 1). If you want an LLM to answer questions about a 500-page legal document, debug across a million-line codebase, or synthesize information from dozens of research papers, the context window must be large enough to hold all of that material *and* the model must be able to attend to the right parts of it.

**The scaling imperative.** The authors explicitly connect this to frontier applications: "For this method to work with large knowledge databases (like large code repositories), the model needs to manage a context length extending to millions of tokens." This is not speculative — repository-level code generation, long-document question answering, and multi-document summarization are active areas of research and commercial interest where the context-length bottleneck is the primary limitation.

**The multi-document setting is underexplored.** Most prior work on long-context Transformers evaluates in a **single-document setting**, where the entire context comes from one coherent source (one book, one paper, one code file). The model sees a long, contiguous sequence from a single distribution. The authors argue this is an incomplete test: real-world use cases involve *multiple* documents mixed together, where the model must actively ignore most of its context to focus on what matters. The distraction issue is specifically a *multi-document* phenomenon that single-document benchmarks fail to capture.

### Prior Approaches and Where They Fall Short

The paper positions itself against a landscape of long-context methods, identifying specific gaps that FOT fills.

#### 1. Sparse and Efficient Attention Mechanisms

A large body of work reduces the quadratic cost of self-attention to enable longer sequences: **Transformer-XL** (Dai et al., 2019) caches previous context segments and attends across segment boundaries; **Longformer** (Beltagy et al., 2020) uses a combination of sliding window, dilated, and global attention patterns; **BigBird** (Zaheer et al., 2020) adds random sparse attention to the mix; **LongT5** (Guo et al., 2021) applies sparse attention in an encoder-decoder framework; **FlashAttention** (Dao et al., 2022) makes dense attention faster and more memory-efficient at the hardware level. These methods successfully reduce computational complexity, but the authors note a critical limitation (Section 2, citing Kaddour et al., 2023): efficiency-focused designs show **"limited gains"** in actual long-range modeling capability. Making attention cheaper to compute does not, by itself, make it *better* at focusing on the right information when irrelevant content is present. Sparse attention patterns can even exacerbate the distraction issue if the sparsity pattern accidentally excludes relevant keys while including irrelevant ones.

#### 2. Hierarchical and Conditional Computation

**Hierarchical Transformers** (Nawrot et al., 2021, 2023) downsample activations in intermediate layers, reducing sequence length for deeper layers. **COLT5** (Ainslie et al., 2023) uses conditional computation — selectively applying heavy attention only to important tokens while using lightweight attention for the rest. These methods save memory and enable longer contexts, but they address the *efficiency* of attending over many tokens, not the *discrimination* of relevant from irrelevant tokens. A hierarchical model might efficiently process a million tokens but, without training explicitly for the multi-document distraction scenario, still distribute its attention mass uniformly across all documents.

#### 3. Retrieval-Augmented and Memory-Based Methods

The approach most directly related to FOT is the **Memorizing Transformer** (MT; Wu et al., 2022), which augments a subset of attention layers with a k-nearest-neighbors (kNN) lookup into a growing memory of past (key, value) pairs. At inference time, each query in a memory-augmented layer retrieves the top-$k$ most similar keys from memory and attends to them alongside the local context. This effectively extends the context to include tokens that would otherwise have fallen out of the window. The FOT paper adopts this architecture almost wholesale (same kNN retrieval, same concept of designated memory layers) and acknowledges the debt in Section 2 and Appendix B.5.

However, the authors identify two critical shortcomings of MT that FOT is designed to address:

- **Non-differentiable memory during training.** MT populates its memory with (key, value) pairs from earlier training steps, but the retrieval step is not backpropagated through — the keys and values in memory are treated as fixed constants during training. This means the model never receives a gradient signal telling it *how* to structure its key space to make retrieval work well; it only learns to use whatever keys happen to be produced by the base language modeling objective. The authors argue this is "key for joint training of well-structured key, value, and query embeddings" (Appendix C.3).

- **No exposure to distracting documents during training.** MT was designed and evaluated primarily in the single-document setting, where the memory contains only tokens from the *same* document. At training time, the model never encounters a scenario where its memory is polluted with irrelevant documents. As a result, when deployed in a multi-document setting, MT has no learned ability to distinguish relevant from irrelevant keys — it was never trained to do so. The authors' experiments confirm this (Section 5.3, Figure 6): MT's perplexity degrades significantly when evaluated with multi-document memory, while FOT handles it gracefully.

More broadly, **RETRO** (Borgeaud et al., 2022) retrieves chunks from a large external database, embeds them with a frozen encoder, and feeds them into the model via cross-attention. This is a two-stage pipeline (retrieve, then embed) rather than FOT's single-stage integration of retrieval directly into self-attention layers. RETRO's retrieval is based on a frozen encoder whose representations are not fine-tuned end-to-end for the language modeling task.

**KNN-LM** (Khandelwal et al., 2019) interpolates between the model's output distribution and a distribution derived from nearest-neighbor lookups in a datastore, but this operates at the *output* level only — no attention-level integration, and no ability for the model to reason over the retrieved information in intermediate layers.

#### 4. Positional Encoding Extrapolation Methods

A recent line of work extends context length by modifying or fine-tuning positional encodings: **Position Interpolation** (Chen et al., 2023; kaiokendev, 2023) rescales rotary positional encodings (RoPE) to fit longer sequences within the range the model was trained on, then fine-tunes on the extended length. **Landmark Attention** (Mohtashami and Jaggi, 2023) compresses context into landmark tokens and uses positional encodings to retrieve relevant landmarks. These methods successfully stretch context windows — Landmark Attention reaches 32K on LLaMA-7B — but they have a fundamental dependency: they rely on **positional encodings** to structure attention across the extended context.

FOT takes a different philosophical stance. The authors cite Haviv et al. (2022), which showed that Transformers without positional encodings can still learn positional information, and argue that for *additional* context beyond the local window, positional encodings are unnecessary and potentially limiting. By removing positional encodings from memory layers (Section 3.1), FOT's additional context is "theoretically unbounded" — tokens retrieved from memory are attended to purely based on semantic similarity, not position. This is why FOT extrapolates from 8K training context to 256K inference context (Figure 1), while positional-encoding-based methods tend to hit a ceiling tied to their training length.

#### 5. Contrastive Learning in Language Models

The paper also connects to work applying contrastive learning to text representations. **TRIME** (Zhong et al., 2022) trains language models with memory augmentation using negative samples, but interpolates at the *output* layer rather than within attention. **ContraCLM** (Jain et al., 2023) applies contrastive losses at token and sequence levels to promote isotropic, uniformly distributed representations, improving performance on semantic similarity benchmarks. The authors acknowledge these connections but emphasize a key distinction: ContraCLM targets *general expressiveness* of representations, while FOT's contrastive-inspired approach is "designed specifically for training the attention mechanism to handle longer context lengths" (Section 2). The negative samples in FOT serve a very specific purpose — teaching the model's keys to be document-discriminative so that kNN retrieval naturally separates relevant from irrelevant tokens.

### How This Paper Positions Itself

The paper's positioning can be understood as filling three intersecting gaps:

**Gap 1: Multi-document context scaling.** Prior work on long contexts almost exclusively evaluates single-document scenarios. FOT is motivated by, designed for, and evaluated on the multi-document setting where the distraction issue manifests. The authors introduce both a problem definition (the distraction issue, Section 3.3) and a quantitative metric (positive attention mass) that were absent from prior work.

**Gap 2: End-to-end differentiable key–value structuring.** Memorizing Transformer showed that kNN-augmented attention works, but trained the model *around* retrieval rather than *for* retrieval. FOT makes the key–value pairs differentiable with respect to the language modeling loss during training via the crossbatch procedure, so the model learns to produce keys that make retrieval naturally effective.

**Gap 3: Contrastive exposure to distractions during training.** The crossbatch procedure deliberately exposes the model to (key, value) pairs from *other documents* during training — what the paper calls "negatives." This is conceptually simple but was absent from all prior memory-augmented Transformer training recipes. The authors show that this exposure is what enables the model to maintain focus when the inference-time memory grows large (Figure 8: perplexity increases only 0.18 points when scaling from memory of the current document to 500k+ tokens of multi-document memory).

The paper also explicitly positions FOT as a **fine-tuning method for existing models**, not a from-scratch training recipe. This is a practical stance: "Our method is simple to implement, and it provides the benefit of extending model context without modifying the architecture, facilitated by cost-effective fine-tuning" (Section 1, contribution 3). The LONGLLAMA results (Section 4) demonstrate this by taking publicly available OpenLLaMA checkpoints and extending their effective context length by two orders of magnitude using only 10B tokens of fine-tuning for the 3B model and 3B tokens for the 7B model — a tiny fraction of the original 1T-token pretraining budget. This positions FOT not as a competitor to pretraining-scale efforts but as a lightweight augmentation that can be applied post-hoc to any Transformer model.

## 3. Technical Approach

### 3.1 Reader Orientation

This is primarily a **methods paper** with extensive empirical validation, proposing a training procedure and architectural augmentation that together enable Transformer language models to effectively attend to relevant information within a vastly expanded context containing multiple documents. The core problem is the **distraction issue**: when multiple documents are present in context, standard attention distributes its mass evenly across all of them, making the model unable to focus on the document that actually matters for the current prediction. The solution has two components — a **crossbatch training procedure** that teaches the model's key representations to be document-discriminative by exposing attention layers to both same-document and other-document keys in a fully differentiable way during training, and **memory attention layers** that use k-nearest-neighbors retrieval at inference time to extend the effective context far beyond the local window using the structured keys the model has learned to produce.

### 3.2 Big-Picture Architecture (Diagram in Words)

The Focused Transformer (FOT) system has three major components that interact during training and inference:

1. **Base Transformer Model** — a standard decoder-only Transformer (e.g., OpenLLaMA) with most layers operating conventionally. A designated subset of attention layers is converted into memory attention layers.

2. **Memory Attention Layers** — a subset of the Transformer's layers (e.g., layers 6, 12, and 18 in the 3B model) that have access to additional (key, value) pairs beyond the local context window. During inference, these layers populate a growing memory store with past (key, value) pairs they have processed and use exact kNN search to retrieve the top-$k$ most relevant entries for each query. During training, they instead attend to a mixture of keys from the *previous* local context of the same document and from contexts of *other* documents in the batch — the crossbatch procedure.

3. **Crossbatch Training Procedure** — a data pipeline and attention modification that, for each document in a batch, constructs a differentiable attention context containing (key, value) pairs from (a) the current local context, (b) the *previous* local context of the same document (positives), and (c) the previous local contexts of $d-1$ *other* documents in the batch (negatives). The loss is the standard next-token prediction objective; the only change is what the memory layers attend to.

**Information flow during training:** A batch is constructed where each batch index corresponds to a different document → the previous local context ($C_{\text{prev}}$) and current local context ($C_{\text{curr}}$) are embedded for each document → in each memory attention layer, every query from $C_{\text{curr}}$ attends to its own local context, the previous context of its document, and $d-1$ previous contexts from other documents → the standard language modeling loss is computed → gradients flow through ALL attended (key, value) pairs, including those from other documents, shaping the key space to be document-discriminative.

**Information flow during inference:** Documents are processed sequentially → as each memory attention layer processes tokens, it stores their (key, value) pairs in a FAISS index → for each new query, the layer retrieves the $k$ most similar keys from memory → the query attends to both its local context and these retrieved entries → attention is computed using the same softmax mechanism as standard attention, treating retrieved entries identically to local entries (no gating) → the memory persists across document boundaries in multi-document settings, or is cleared between documents in single-document settings.

### 3.3 Roadmap for the Deep Dive

- **First**, the memory attention layer mechanism — how it stores and retrieves (key, value) pairs, how it computes attention over the combined local-plus-memory context, and why it removes positional encodings from memory entries — because this is the architectural foundation that everything else builds on.
- **Second**, the crossbatch training procedure in full detail — how the batch is constructed, which keys each query attends to, the role of the positive-to-negative ratio parameter $d$, and why full differentiability through all attended keys is the critical property that distinguishes FOT from prior memory-augmented approaches.
- **Third**, the distraction issue formalization — the `positive attention mass` metric, why standard training produces $r_d \approx 1/d$, and how crossbatch training with increasing $d$ reshapes attention to focus on relevant keys — because this is the paper's core diagnostic and the empirical justification for the entire method.
- **Fourth**, the specific details of how FOT is applied to pre-trained models (the LONGLLAMA recipe) — which layers are converted, how positional encodings are handled for backward compatibility, the fine-tuning dataset mixture, and the crossbatch configuration — because this demonstrates the practical portability of the method.
- **Fifth**, the design choices and ablation justifications — why FOT uses direct concatenation rather than gating for memory integration, why differentiable keys outperform non-differentiable memory during training, and how the schedule of $d$ is managed to prevent the model from ignoring the local context early in training.

### 3.4 Detailed, Sentence-Based Technical Breakdown

The Focused Transformer is a **training method plus inference augmentation** — not a new model architecture. It takes an existing Transformer, designates a subset of its attention layers for special treatment, trains them with a contrastive-inspired objective that forces the key space to encode document identity, and then at inference time augments those layers with kNN-based memory lookup to extend the effective context length by orders of magnitude. The key insight is that *the quality of kNN retrieval depends entirely on the structure of the key space*, and standard language model training does not produce keys that are discriminative across document boundaries — but a simple, differentiable modification to the attention context during training can teach this discrimination without any auxiliary loss or additional parameters.

#### Memory Attention Layers: The Inference-Time Architecture

A memory attention layer is a standard Transformer attention layer with one modification: in addition to attending to keys from the local context (the tokens that precede the current query within the same sequence window), it also attends to a set of (key, value) pairs retrieved from an external memory store. The memory is populated incrementally at inference time: as the layer processes tokens, it stores their (key, value) pairs. When a new query arrives, the system uses exact k-nearest-neighbors search (implemented via FAISS, Johnson et al., 2017) to find the $k$ keys in memory whose inner product with the query is largest. These $k$ retrieved pairs, denoted $M_{\text{top}}$, are then concatenated with the local context keys $C_{<q}$ (the keys from tokens preceding $q$ in the current window), and attention is computed over the combined set.

The attention computation treats retrieved memory entries identically to local context entries — there is no separate gating mechanism, no weighted interpolation, no distinction between "local" and "memory" sources. Formally, for each query $q$ in a memory attention layer, the attention output value $v$ is computed as:

$$v = \sum_{(key, val) \in M_{\text{top}} \cup C_{<q}} s(key) \cdot val$$

where $M_{\text{top}}$ is the set of top-$k$ (key, value) pairs retrieved from memory via kNN, $C_{<q}$ is the set of (key, value) pairs from tokens preceding $q$ in the local context, and $s(key)$ is the softmax weight assigned to that key.

**What it computes:** a standard attention-weighted sum of value vectors, where the attention weights come from a softmax over the inner products between the query and all keys in the combined set (local context plus retrieved memory). The softmax is computed with a learnable temperature parameter $\tau$:

$$\text{softmax}\left(\left\{\frac{\langle q, key\rangle}{\tau}\right\}_{key \in M_{\text{top}} \cup C_{<q}}\right)$$

where $\tau$ is a per-head learnable scalar that scales the logits before the softmax.

**Why this form:** the key design decision is the *unified* softmax over local and memory keys together — a single attention distribution, not two separate ones that are later combined. Prior work (Memorizing Transformer, Wu et al., 2022) used a gating mechanism: compute separate attention values $v_M$ for memory and $v_C$ for local context, then combine them as $v = v_M \cdot g + v_C \cdot (1-g)$ where $g = \sigma(b_g)$ with a learned bias $b_g$. The authors tested both approaches and found them "equally effective" (Appendix B.2, Figure 4), but chose the unified softmax because it is simpler and requires no additional parameters. They speculate that gating was needed in the Memorizing Transformer because its training did not backpropagate through memory keys — the model had to learn, via the gate, how much to trust potentially low-quality retrieved keys. FOT's differentiable training produces high-quality keys directly, making the gate unnecessary.

The number of retrieved entries $k$ is a hyperparameter. For the 184M-parameter analysis models, the authors use $k = 128$. For the dictionary lookup task with 37M-parameter models, they use $k = 32$. For LONGLLAMA models, they replace kNN entirely with dense attention over the full memory — they found "only marginal performance differences" (Appendix A.2) and dense attention is simpler to implement.

**Positional encodings in memory layers.** A critical design choice: the memory attention layers **do not use positional encodings** for the retrieved memory entries. In the base architecture (non-LLaMA models), positional encodings are removed entirely from memory attention layers during both training and inference — the attention is purely content-based, driven by semantic similarity of keys rather than position. The authors cite Haviv et al. (2022), which showed that Transformers can learn positional information even without explicit positional encodings, and argue that removing them is essential for the "theoretically unbounded" context length: if positional encodings were used for memory entries, the model would need to assign meaningful positions to tokens retrieved from arbitrary points in the past, which becomes ill-defined when the memory spans millions of tokens.

For LONGLLAMA models specifically (Section 4.1, Appendix A.2), the authors make a pragmatic compromise: they **retain** standard LLaMA rotary positional encodings (RoPE) for the local context (up to 2K tokens) to maintain full backward compatibility with existing LLaMA inference code, but encode all memory keys "as if they had position 0 in the local context window." This means the model can see that a memory token is "not in the local window" (it has position 0) but cannot distinguish the relative positions of different memory tokens. This compromise enables LONGLLAMA checkpoints to be drop-in replacements for standard LLaMA checkpoints — they work with any existing inference code, just without the long-context memory capabilities unless the memory attention code is also used.

**Memory population.** The memory is populated incrementally: as each memory attention layer processes tokens during the forward pass, the (key, value) pairs it computes are appended to that layer's memory store. In the single-document evaluation setting, the memory is cleared between documents — each document gets a fresh memory. In the multi-document setting, the memory persists across documents without reset, testing whether the model can ignore accumulated irrelevant information.

#### Crossbatch Training Procedure: Learning Document-Discriminative Keys

The crossbatch training procedure is the intellectual core of FOT. It is not a new loss function or a new architecture — it is a **modification of what each memory attention layer attends to during training**, implemented entirely through changes to the data pipeline and a minor adjustment to the attention computation. The standard language modeling objective (next-token prediction cross-entropy) remains unchanged; the only difference is that the memory layers see a broader, document-mixed attention context.

The procedure operates at the batch level. Each batch element corresponds to a different document, and this assignment is fixed: a given batch index $i$ always processes tokens from the same document across consecutive steps. For each forward pass, the system embeds two segments of each document: the **current local context** ($C_{\text{curr}}$), which contains the tokens for which predictions are being made, and the **previous local context** ($C_{\text{prev}}$), which contains the immediately preceding segment of the same document. 

For each document $\delta$ in the batch (occupying batch index $i$), and for each query $q$ in a memory attention layer, the system constructs a set $p^\delta$ of additional (key, value) pairs that the query will attend to beyond its own local context. This set contains:

- **Positives:** all tokens from the *previous* local context of document $\delta$ (i.e., from $C_{\text{prev}}$ at batch index $i$).
- **Negatives:** all tokens from the previous local contexts of $d-1$ *other* documents in the batch, specifically those at batch indices $(i+1) \bmod bs, (i+2) \bmod bs, \ldots, (i+d-1) \bmod bs$, where $bs$ is the total batch size.

The attention value for query $q$ is then computed as:

$$v = \sum_{(key, val) \in p^\delta \cup C_{\text{curr}}^{<q}} s(key) \cdot val$$

where $C_{\text{curr}}^{<q}$ is the set of (key, value) pairs from tokens that preceded $q$ within its own current local context, $p^\delta$ is the crossbatch context containing positives and negatives, and $s(key)$ is the softmax weight (using the learnable temperature $\tau$).

**What it computes:** an attention-weighted sum over a mixed context that spans three categories — the query's own local past, the previous segment of the same document, and the previous segments of $d-1$ unrelated documents. The softmax normalizes across all of these uniformly, so a query must learn to allocate its limited attention mass discriminatingly: giving high weight to keys from its own document (both current and previous segments) and low weight to keys from other documents. The language modeling loss provides the training signal — if the model extracts useful information from the right keys, it predicts the next token better.

**Why this form:** the crossbatch procedure is a minimal change that achieves three crucial properties simultaneously:

1. **Full differentiability through all attended keys.** Unlike the Memorizing Transformer, where memory keys are treated as constants during training (no gradient flows through them), crossbatch includes the additional keys in the forward pass of the *current* step. All keys — from the current context, the previous same-document context, and the other-document contexts — are produced by the current forward pass. Gradients flow back through all of them, jointly optimizing query, key, and value projections so that relevant keys have high inner products with queries and irrelevant keys have low inner products. This is what the authors call "joint training of well-structured key, value, and query embeddings" (Appendix C.3).

2. **Explicit exposure to distractions during training.** Standard language model training only exposes the model to tokens from one document at a time. In such a regime, there is no pressure to make keys document-discriminative — any key structure that helps within-document prediction is sufficient. Crossbatch forces the model to encounter a scenario where most of the keys it sees are from *irrelevant* documents, and the only way to minimize the loss is to learn key representations that cluster by document identity so that the softmax naturally concentrates mass on the right keys. This is the direct analog of contrastive learning: the model learns a representation space where "positive" pairs (queries and keys from the same document) have high similarity and "negative" pairs (queries and keys from different documents) have low similarity.

3. **No dependence on long training documents.** Because the training context is constructed by concatenating fixed-length segments from multiple documents (rather than requiring a single document to be long enough to fill a large memory), FOT can be trained on datasets with relatively short individual documents. The total differentiable context length during training equals $(d+1) \times \text{local\_context\_length}$ (the current segment plus $d$ previous segments), but these segments come from different documents. This is a significant practical advantage — many popular training corpora consist of short documents that would be insufficient for training a Memorizing Transformer with large memory.

**The crossbatch dimension $d$.** The hyperparameter $d$ controls the ratio of positive to negative documents in the crossbatch attention context. When $d=1$, the model sees its own previous context and zero other-document contexts — this is essentially standard training with an extended differentiable context. When $d=2$, the model sees one positive and one negative. When $d=8$, it sees one positive and seven negatives. The authors find that higher $d$ values produce better key structure and lower perplexity in multi-document settings (Section 5.3, Figure 8), but too-high $d$ early in training can cause the model to ignore the previous context entirely — there are too many negative keys, and the model's softmax simply learns to give zero weight to everything outside the local context. The solution is a **schedule**: start training with a small $d$ (e.g., $d \leq 8$) to establish the use of additional context, then increase to larger values (e.g., $d \geq 64$) once the model is reliably attending to positive keys. The precise schedule varies by experiment: for the PG-19 multi-document experiments in Section 5.3, models labeled "d=2→64" trained with $d=2$ for 450k steps and switched to $d=64$ for the final 50k steps. For the 184M model in Section 5.2, $d$ was randomly sampled from $\{2, 128\}$ at each training step.

**Implementation note.** Listing 1 in the paper provides pseudocode for the crossbatch attention computation. The key implementation detail is that keys from the previous contexts are encoded with a modified positional encoding — they are treated as if they were at the *beginning* of the local context (position 0), rather than at their actual positions. This removes position-based shortcuts that would allow the model to distinguish relevant from irrelevant keys by position rather than by content, forcing the model to rely on key semantics. The crossbatch attention is computed by concatenating the local context keys with the crossbatch keys along the sequence dimension and running a single, unified softmax.

#### The Distraction Issue: Formalization and Measurement

The distraction issue is the paper's core diagnostic and the primary motivation for FOT. It is not a hypothesis about why models fail — it is an empirically measured phenomenon with a precise quantitative definition.

**Definition.** For a given document $\delta$ in a multi-document setting, the model's attention layer is exposed to a set $p^\delta$ of (key, value) pairs constructed as in the crossbatch procedure: it contains keys from the previous context of document $\delta$ (at position $i=1$ in the batch dimension) and keys from $d-1$ other documents (at positions $i=2, \ldots, d$). Let $w_{ij}$ be the softmax attention weight assigned to the $j$-th key from the $i$-th document in $p^\delta$. The **positive attention mass** $r_d$ is defined as:

$$r_d := \frac{\sum_j w_{1j}}{\sum_{i=1}^d \sum_j w_{ij}}$$

where $w_{1j}$ is the attention weight on keys from the *same* document (the positive, at batch index $i=1$), and the denominator sums over all attention weights on all $d$ documents in the crossbatch context.

**What it computes:** the fraction of the total attention mass allocated to keys from the *current* document's previous context, as opposed to keys from other documents. If the model perfectly focuses on relevant keys, $r_d \approx 1$. If the model is completely distracted, $r_d \approx 1/d$ (uniform distribution across all $d$ documents).

**The empirical finding.** The authors measure $r_d$ for both a standard Transformer and FOT variants trained with different $d$ values, evaluated in a setting where they see varying numbers of documents. The results (Figure 3) show that:

- For a standard Transformer, $r_d \approx 1/d$ across all values of $d$ — the attention is essentially uniform across documents. This is what the authors call the distraction issue: the model has no learned bias to prefer keys from its own document over keys from unrelated documents, so its attention mass is "equally distracted" by all of them.
- For FOT trained with $d=1$, $r_d$ behaves similarly to the standard Transformer — without exposure to negatives during training, the model does not learn document-discriminative keys.
- For FOT trained with $d=8$, $r_d$ is significantly higher than $1/d$ — the model has learned to concentrate attention on same-document keys.
- For FOT trained with $d=2$ then increased to $d=64$ ("FoT d=2→64"), $r_d$ approaches 1.0 even when the evaluation-time number of documents is large — the model has learned strongly document-discriminative keys.

This measurement is the direct empirical link between the crossbatch training procedure and the model's ability to focus. It explains *why* higher $d$ during training leads to better perplexity in multi-document settings (Section 5.3, Figure 8): because the model learns to ignore distractions, its attention concentrates on the keys that actually carry predictive information, and the effective context quality improves even as the total memory size grows.

**Why the standard Transformer fails.** During standard training, each batch element processes tokens from one document at a time. The attention mechanism never encounters a situation where it must distinguish keys from different documents. As a result, the key space evolves purely to support within-document next-token prediction — keys from different documents can occupy overlapping regions of the key space without penalty because they are never simultaneously present in the same softmax. When multiple documents are later concatenated at inference time, this overlapping key space means the softmax distributes weight roughly uniformly across all keys with similar inner products, regardless of document provenance. The distraction issue is thus a *training data distribution* problem: the model was never taught to be document-discriminative because it was never exposed to multi-document contexts.

#### The LONGLLAMA Recipe: Applying FOT to Pre-Trained Models

The LONGLLAMA results (Section 4) demonstrate that FOT can be applied as a fine-tuning procedure to already-trained large language models, extending their effective context length without modifying the base architecture. The recipe has several important components that differ from training a FOT model from scratch.

**Model selection and layer conversion.** The authors use OpenLLaMA-3B and OpenLLaMA-7B (Geng and Liu, 2023), which are open-source reproductions of LLaMA (Touvron et al., 2023) trained for 1 trillion tokens. For the 3B model, they convert layers $\mathcal{L} = \{6, 12, 18\}$ into memory attention layers — these are specific layer indices, chosen following the Memorizing Transformer's precedent of converting a subset of middle-to-late layers. For the 7B model, they use layers $\mathcal{L} = \{8, 16, 24\}$. The choice of which layers to convert is inherited from prior work; the authors note this in Section 5.5: "due to the limited resources we have followed the Memorizing Transformer in the choice of memory layers."

**Positional encoding handling for backward compatibility.** A critical practical decision: LONGLLAMA retains the standard LLaMA rotary positional encodings (RoPE) for the local context (up to 2K tokens). For memory keys, which can come from arbitrary positions in the past, all keys are encoded as if they were at position 0 in the local context window. More precisely: "queries and keys from the local context (up to 2K tokens) receive the standard LLaMA rotary positional encoding, whereas memory keys are encoded as if they had position 0 in the local context window" (Section 4.1). This means the positional encoding conveys exactly one bit of information for memory keys: "this key is not in the local window." The model cannot distinguish the relative positions of different memory keys — it must rely entirely on semantic content.

This design decision makes LONGLLAMA checkpoints fully backward-compatible with any existing LLaMA inference code. A LONGLLAMA model loaded into standard LLaMA inference code will run correctly (using only local context, ignoring the memory augmentation) and produce exactly the same outputs as if the memory layers were standard layers — the checkpoint is a valid LLaMA-architecture checkpoint. The memory augmentation is an *optional* extension that requires the additional memory attention code to activate.

**Dense attention instead of kNN.** For LONGLLAMA, the authors replace the kNN retrieval with dense attention over the full memory: "we resign from using kNN lookup and perform attention over the whole memory" (Appendix A.2). They report only marginal performance differences between kNN and dense attention in this setting. This simplifies implementation and eliminates the external FAISS dependency for LONGLLAMA inference. The trade-off is computational — dense attention over a 256K-token memory would be prohibitively expensive — but in practice the memory attention is applied only in a subset of layers, and the passkey retrieval experiments (Figure 1) show that the approach works at scale.

**Fine-tuning dataset.** The fine-tuning corpus is a mixture based on RedPajama (TogetherComputer, 2023) with additional Python code from The Stack (Kocetkov et al., 2022). The mixture proportions are specified in Table 4 (Appendix A.3): arxiv 25%, python 25%, book 10%, common_crawl 29%, c4 5%, github 2%, stackexchange 2%, wikipedia 2%. Documents shorter than a minimum length (specified per subset, e.g., 4096 tokens for python, 1024 for c4) are filtered out. When a document is too short to span multiple contexts for crossbatch training, it is concatenated with the next document from the dataset.

**Fine-tuning hyperparameters.** The 3B model is fine-tuned on 10 billion tokens with a context length of 8K; the 7B model on 3 billion tokens with the same context length. The batch size is 256K tokens. The learning rate is constant at $2 \times 10^{-5}$, which is lower than the learning rate at the end of OpenLLaMA's original training ($3 \times 10^{-5}$). Weight decay is 0.01. The optimizer follows OpenLLaMA's choices.

**Crossbatch configuration for LONGLLAMA.** The crossbatch setup for LONGLLAMA is more sophisticated than the simple $d$-document configuration used in the analysis experiments. The authors divide the batch into four equal-sized segments and apply different crossbatch configurations to each segment. For the 3B model, the configuration is:

- Segment 1 (25% of batch): $d=0$ — only local context, no crossbatch. Notated as $\frac{1}{4}(0, 0)$.
- Segment 2 (25% of batch): $d=2$, with 1 positive (same document) and 1 negative (different document). Notated as $\frac{1}{4}(1, 1)$.
- Segment 3 (25% of batch): $d=3$, with 2 positives and 1 negative. Notated as $\frac{1}{4}(2, 1)$.
- Segment 4 (25% of batch): $d=3$, with 3 positives and 0 negatives. Notated as $\frac{1}{4}(3, 0)$.

This heterogeneous configuration serves multiple purposes. The $d=0$ segment ensures the model continues to perform well on standard local-context prediction (no memory). The mixed positive-negative segments teach document discrimination. The all-positive segment teaches the model to use extended same-document context (which is valuable for the single-document long-context setting).

For the 7B model, the configuration is $\frac{1}{4}(0, 0), \frac{1}{4}(1, 2), \frac{1}{4}(2, 5), \frac{1}{4}(3, 4)$ — still four equal segments but with larger negative counts in the later segments. The notation $(p, n)$ means $p$ positive contexts (from the same document) and $n$ negative contexts (from different documents), with total crossbatch dimension $d = p + n + 1$ (the +1 accounting for the current context).

**Training context vs. inference context.** LONGLLAMA models are trained with an 8K local context length. At inference time, the local context remains 2K tokens (matching the original LLaMA training length), while the memory extends the total effective context. This means the model must extrapolate: it was trained with an 8K differentiable context via crossbatch, but at inference the local window is 2K and the rest comes from memory. The passkey retrieval results (Figure 1) show successful extrapolation to 100K tokens (94.5% accuracy) and 256K tokens (73% accuracy), which is 32× the training context length.

#### Contrastive Learning Connection and Why Standard Training Fails

The crossbatch training procedure is explicitly "inspired by contrastive learning" (Section 1), and understanding this connection clarifies why the method works.

In standard contrastive learning (e.g., SimCLR, Chen et al., 2020), the goal is to learn representations where semantically similar pairs (positives) have high similarity and semantically dissimilar pairs (negatives) have low similarity. The loss function explicitly pushes these similarities apart. FOT does **not** use an explicit contrastive loss — it uses the standard next-token prediction cross-entropy — but the *structure of the attention context* creates an implicit contrastive pressure. The query must predict the next token using a weighted sum of values, where the weights come from a softmax over all keys in the context. If negative keys (from other documents) have high similarity to the query, they will receive significant softmax mass, diluting the contribution from the positive keys that actually carry useful information. The only way for the model to minimize the language modeling loss is to make the query–key similarities for negatives systematically lower than for positives — which is exactly the objective that an explicit contrastive loss would enforce, but achieved implicitly through the gradient signal from next-token prediction.

This implicit approach has a crucial advantage over explicit contrastive losses: it does not require defining what constitutes a "positive pair" or "negative pair" in advance, and it does not introduce a new loss term that needs to be balanced against the primary language modeling objective. The model discovers which keys are useful for prediction through the standard gradient flow, and the crossbatch context simply ensures that *irrelevant* keys are present in the softmax so that the model must learn to ignore them.

The connection to the "representation degeneration problem" (Gao et al., 2019) is also relevant. Prior work observed that language model embeddings tend to occupy a narrow cone in representation space, making it difficult to distinguish between different tokens or contexts by similarity alone. The crossbatch training procedure, by forcing the model to discriminate between keys from different documents in the same softmax, pushes the key space toward a more isotropic, uniformly distributed structure — keys from different documents spread out, while keys from the same document cluster. This is exactly what makes the kNN retrieval effective at inference time: the memory contains keys from many documents, and the retrieval mechanism depends on the inner product between queries and keys to rank relevance. If all keys were in a narrow cone, kNN retrieval would be essentially random; with FOT's structured key space, the top-$k$ keys tend to come from the same document as the query.

#### Design Choices, Ablations, and Why Alternatives Were Rejected

Several specific design choices in FOT are supported by ablation experiments in the paper. Each represents a deliberate departure from prior approaches or a resolution of a trade-off.

**Differentiability through memory keys (vs. Memorizing Transformer).** The Memorizing Transformer (Wu et al., 2022) populates its memory during training with (key, value) pairs computed in previous training steps. These stored pairs are treated as constants — no gradient flows through them when they are retrieved and used in the current step's attention. The authors argue this is a critical limitation: the model cannot learn to adjust its key representations to make retrieval work better because the retrieval targets are frozen.

FOT's crossbatch procedure makes all keys in the additional context fully differentiable — they are produced by the current forward pass and gradients flow back through them. The ablation in Figure 5 (Appendix C.1) directly compares FOT with $d=8$ against a "Multi-doc MT" trained with non-differentiable memory of size 4096 shared across 8 documents, both with a local context of 512. FOT achieves significantly lower perplexity as the inference-time context grows to 500K tokens. Table 8 further shows that even in the single-document setting (no distractions), FOT with $d=1$ (differentiable previous context) slightly outperforms MT (non-differentiable memory) across multiple training context lengths (512, 1024, 2048). This confirms that differentiability through additional context keys is beneficial even without the distraction aspect.

**Inclusion of negatives (vs. training with only positives, $d=1$).** When FOT is trained with $d=1$ (only the previous same-document context, no negatives), it behaves similarly to a standard Transformer in the distraction metric — $r_d \approx 1/d$ — and its multi-document perplexity degrades significantly as memory size grows (Section 5.3, Figure 6). In contrast, FOT trained with $d=2 \rightarrow 64$ maintains near-constant perplexity across memory sizes from the current document up to 500K+ tokens. This ablation isolates the effect of negatives specifically: without exposure to other-document keys during training, the model never learns document-discriminative keys, regardless of whether the previous context was differentiable. The negatives are the essential ingredient that teaches the model to *focus*.

**Unified softmax vs. gating for memory integration.** The Memorizing Transformer uses a gating mechanism to combine memory and local attention: $v = v_M \cdot \sigma(b_g) + v_C \cdot (1 - \sigma(b_g))$, where $b_g$ is a learned bias. The gating gives the model explicit control over how much to trust the memory vs. the local context. FOT uses a simpler approach: memory keys and local keys are concatenated, and a single softmax is applied over the combined set. The authors tested both approaches (Appendix B.2, Figure 4) and found no difference in performance, so they chose the simpler method because it requires no additional parameters and makes fine-tuning existing models straightforward (no architectural changes to the attention layer itself).

The authors speculate that gating is unnecessary in FOT because the differentiable training produces memory keys that are already high-quality — the model can trust them by default. In contrast, MT's non-differentiable memory may contain stale or poorly-structured keys, requiring the gate to learn when to ignore the memory. This is an example of how a training-procedure improvement (differentiability) simplifies the architectural requirements.

**Removing positional encodings from memory layers (non-LLaMA models).** For the analysis models (non-LLaMA), memory attention layers do not use positional encodings at all. The justification is twofold: (1) Haviv et al. (2022) showed that Transformers can learn positional information without explicit encodings, so the local context still has implicit position awareness through the causal mask; (2) for memory keys retrieved from arbitrary positions, assigning meaningful positional encodings is impossible — the positions are relative to a context window that may have been processed millions of tokens ago. By removing positional encodings entirely from the memory layers, the model is forced to attend based on content similarity, which is exactly the inductive bias needed for effective kNN retrieval.

For LONGLLAMA, the decision is different (retain RoPE for local context, position-0 for memory) due to backward compatibility requirements rather than performance considerations. This is a pragmatic engineering choice, not a claim that positional encodings are beneficial.

**Schedule of $d$ (crossbatch dimension).** Training with large $d$ from the start can cause the model to ignore the additional context entirely — the softmax over many negative keys produces near-zero weights for all of them, including the positive keys. The solution is a curriculum: start with small $d$ (2–8), let the model learn to attend to the previous context, then increase $d$ (to 64 or 128) to force finer document discrimination. The specific schedule varies across experiments and is described in Appendix E.1: for the PG-19 experiments with $d=2 \rightarrow 64$, the model trains with $d=2$ for 450K steps and $d=64$ for the final 50K steps. For the 184M model fine-tuning experiments (Section 5.2), $d$ is randomly sampled from $\{2, 128\}$ at each step. The random sampling approach is interesting — it prevents the model from overfitting to a specific crossbatch configuration and ensures it remains capable of operating with both small and large additional contexts.

**Choice of memory layers $\mathcal{L}$.** The paper follows the Memorizing Transformer's convention of converting a subset of middle-to-late layers into memory attention layers (e.g., layer 8 out of 12 for the 184M model, layers $\{6, 12, 18\}$ out of 26 for the 3B LONGLLAMA). The authors note (Section 5.5) that "due to the limited resources we have followed the Memorizing Transformer in the choice of memory layers," acknowledging that the optimal layer selection may differ and that this is an unexplored hyperparameter. The rationale for converting only a subset of layers rather than all layers is practical: it limits the computational overhead of kNN retrieval (which is only performed in those layers) and preserves the standard behavior in other layers, preventing the model from becoming entirely dependent on the memory mechanism.

**Temperature parameter $\tau$.** The learnable per-head temperature $\tau$ in the softmax (used only in non-LLaMA models, not in LONGLLAMA) provides the model with a learned way to control the sharpness of the attention distribution over the combined local-plus-memory context. A smaller $\tau$ produces a sharper distribution (more focused attention), while a larger $\tau$ produces a flatter distribution. This is important because the local context and memory context may require different attention sharpness — for example, the model might want sharp attention over the local context (where most tokens are relevant) but wider attention over memory (to avoid missing a key piece of information among many candidates). By making $\tau$ learnable and shared across the unified softmax, the model can find the right balance. For LONGLLAMA, $\tau$ is not used because the LLaMA architecture does not normalize keys and queries, making the temperature unnecessary.

## 4. Key Insights and Innovations

### Innovation 1: Naming and Diagnosing the "Distraction Issue" as the Primary Bottleneck in Multi-Document Context Scaling

The most conceptually important contribution of this paper is not a method — it is the **identification and precise quantification of a failure mode** that prior work on long-context Transformers had overlooked entirely. The authors give this failure mode a name — the **distraction issue** — and provide a clean, measurable metric (**positive attention mass**, $r_d$) that diagnoses it. This transforms what was previously a vague intuition ("models get worse with too much context") into a sharply defined problem with a quantitative signature: when $d$ documents are present, a standard Transformer allocates $r_d \approx 1/d$ of its attention to the relevant document, meaning it is almost perfectly distracted.

Why is this a genuine intellectual contribution rather than an obvious observation? Because the dominant framing in long-context research has been about **computational efficiency** — how to make attention cheaper so you can fit more tokens. The implicit assumption was that if you could afford to attend over more tokens, the model would naturally use them well. The distraction issue challenges this assumption directly: even with infinite compute and perfect efficiency, attention over a multi-document context would still fail because the model has never learned to distinguish relevant from irrelevant keys. The problem is not capacity — it is discrimination.

This insight is backed by a strikingly simple experiment (Figure 3). The authors construct a controlled setting where the model sees exactly $d$ documents in its attention context, measures where the attention mass goes, and finds the $r_d \approx 1/d$ relationship. This is not a scaling law fitted to hundreds of data points — it is a clean, almost embarrassingly straightforward measurement that should have been done years ago but wasn't, because the field was focused on single-document evaluations where the question never arises. The paper's contribution here is diagnostic: it identifies that prior benchmarks (PG-19, arXiv, etc. in single-document mode) systematically fail to measure the capability that matters most for practical long-context use cases.

The distinction from prior work is sharp. Sparse attention methods (Longformer, BigBird, LongT5) address computational cost. Hierarchical methods (Nawrot et al., COLT5) address memory efficiency. Positional interpolation methods (Chen et al., Mohtashami and Jaggi) address positional encoding extrapolation. None of these address the **semantic discrimination** of relevant from irrelevant keys across document boundaries. The Memorizing Transformer (Wu et al., 2022) comes closest — its kNN retrieval should, in principle, help — but its single-document training regime means the model never learns to structure its keys for the multi-document setting. FOT's key insight is that this structuring must be taught, and it can be taught through a training procedure that is almost embarrassingly simple once you've diagnosed the problem correctly.

The significance of this contribution extends beyond the paper's own results. By providing a clear problem definition and a metric, the authors enable an entire research program: any future long-context method can and should be evaluated on multi-document distraction, not just single-document perplexity. The $r_d \approx 1/d$ baseline establishes a null hypothesis — if your method doesn't beat it, you haven't solved the real problem. This reframes long-context scaling from an efficiency challenge to a representation-learning challenge, which is a fundamental shift in perspective.

---

### Innovation 2: Implicit Contrastive Learning Through Attention Context Manipulation (Not Loss Modification)

The second conceptual contribution is the **crossbatch training procedure** itself — not its mechanics (which Section 3 covers in detail), but the design philosophy it represents. FOT achieves contrastive learning of key representations **without a contrastive loss, without defining positive/negative pairs explicitly, and without introducing any new training objective**. The model learns document-discriminative keys purely through the gradient signal from standard next-token prediction, because the crossbatch attention context makes discrimination necessary for good prediction.

This is a genuinely novel approach to representation learning in Transformers that sits in an underexplored middle ground. Prior work on contrastive learning for language models falls into two camps. On one side, explicit contrastive losses: ContraCLM (Jain et al., 2023) adds token-level and sequence-level contrastive objectives alongside the language modeling loss. TRIME (Zhong et al., 2022) interpolates a memory-based distribution at the output layer using negative samples. These approaches require designing a contrastive loss, choosing a temperature, balancing multiple loss terms, and deciding what counts as a positive or negative pair — all non-trivial design decisions. On the other side, retrieval-augmented methods (RETRO, Memorizing Transformer) use external retrieval during training but do not backpropagate through the retrieval mechanism, meaning the key representations are not optimized for retrieval quality.

FOT carves out a third path: **change what the attention layer sees, not how it's trained**. By concatenating keys from other documents into the attention context during training, the standard language modeling loss *becomes* a contrastive loss — the model cannot minimize next-token perplexity unless it learns to give higher softmax weights to same-document keys than to other-document keys. The gradient for this discrimination comes purely from the language modeling objective; no auxiliary loss term is needed. The hyperparameter $d$ (number of documents in crossbatch context) plays the role that batch size plays in standard contrastive learning — more negatives produce better representations — but it is tuned through the attention context rather than the loss function.

This design philosophy has a profound practical consequence that distinguishes FOT from most contrastive learning work: **no new loss hyperparameters to tune**. There is no contrastive loss weight, no temperature for a separate loss term, no decision about which layers get the contrastive signal. The only new hyperparameter is $d$, and the paper demonstrates that a simple schedule (start small, increase later) works robustly (Appendices E.1, C.2). This makes the method unusually portable — applying it to OpenLLaMA required changing the attention computation in a handful of layers, with the exact same training objective and optimizer as the original model.

The "implicit contrastive" approach also provides a clean explanation for why standard training fails at multi-document attention: the objective is the same (next-token prediction), the architecture is the same (Transformer attention), but the *distribution of attention contexts* during training determines what the key space learns to represent. Standard training on one document at a time produces keys that are useful for within-document prediction but undifferentiated across documents. Crossbatch training on mixed-document contexts produces keys that are both useful for prediction and document-discriminative. The same loss function, applied to different input distributions, produces qualitatively different representations — this is a insight about the relationship between data distribution and learned structure that extends beyond the specific application to long contexts.

The evidence supporting this innovation is the triplet of measurements in Figures 3, 5, and 6. Figure 3 shows that positive attention mass $r_d$ transitions from $1/d$ (for standard Transformer and FOT $d=1$) to near 1.0 (for FOT $d=2\rightarrow 64$) — directly measuring the key space structure that the implicit contrastive training produces. Figure 5 (Appendix C.1) shows that this structure translates to better perplexity: FOT with differentiable crossbatch significantly outperforms Memorizing Transformer with non-differentiable memory, even when both see the same multi-document context at inference. Figure 6 (Appendix C.2) isolates the role of negatives specifically: FOT with $d=1$ (no negatives, but still differentiable) performs dramatically worse than FOT with $d=2\rightarrow 64$ in multi-document settings, proving that the contrastive exposure to other documents is the active ingredient.

---

### Innovation 3: Context Length as a Property of Key Space Structure, Not Positional Encoding

The third conceptual contribution is a reframing of **what limits context length in Transformers**. The dominant approach to extending context — as seen in Position Interpolation (Chen et al., 2023), Landmark Attention (Mohtashami and Jaggi, 2023), and related work — treats the bottleneck as positional: the model was trained on positions up to $L$, so it cannot attend to tokens at positions beyond $L$ because the positional encodings are out-of-distribution. The solution is to modify or interpolate the positional encodings to cover the extended range.

FOT proposes and validates a radically different view: **for memory-based attention over long contexts, the limiting factor is not position but semantics — specifically, the structure of the key space.** If the model's keys are document-discriminative (similar keys for similar content, dissimilar keys for dissimilar content), then kNN retrieval will naturally surface the relevant tokens regardless of their position. The bottleneck is the quality of the key representations, not the range of the positional encodings.

This reframing is supported by a striking empirical result: FOT models trained with a total differentiable context of 2K–8K tokens extrapolate to 256K tokens at inference time on passkey retrieval (Figure 1), and 37M-parameter models trained on 512-token documents extrapolate to 16M tokens on dictionary lookup (Figure 10). These are not marginal extrapolations — they are 32× to 32,000× beyond the training context length, achieved without any positional encoding modification. The extrapolation works because the model learns to attend based on *what* the tokens are (their semantic content, encoded in the key vectors), not *where* they are (their position).

The contrast with positional-encoding-based methods is instructive. Position Interpolation rescales RoPE frequencies so that positions beyond the training range map into the range the model has seen — enabling extension to roughly 2–4× the training length (e.g., 2K → 8K), after which performance degrades because the positional resolution becomes too coarse. Landmark Attention compresses context into landmark tokens, enabling extension to 32K from a 2K training length (16×). FOT achieves 32× (8K → 256K) with no positional encoding on memory tokens at all, and the authors argue the context length is "theoretically unbounded" because there is no positional encoding barrier to extrapolate past — only the engineering limits of the kNN index size.

This is not merely a performance claim. It is a **conceptual claim about what attention mechanisms need to scale**: if you have a content-addressable memory (the kNN index) and content-discriminative keys (from crossbatch training), position becomes irrelevant for retrieval. The attention mechanism's job is to find relevant information by *similarity*, not by recency or location. This connects FOT to a broader set of ideas — content-addressable memory in neural networks, retrieval-augmented generation, and the separation of "working memory" (local context) from "long-term memory" (the kNN index) — and suggests that the future of long-context Transformers lies in better key representations, not better positional encodings.

The evidence for this reframing is the extrapolation results themselves (Figures 1 and 10), but also the ablation that positional encodings are *removed entirely* from memory attention layers in the analysis models (Section 3.1, Appendix B.2) without hurting performance. The model doesn't need them because the key space structure provides a stronger signal than position ever could for the task of distinguishing relevant from irrelevant tokens across long distances.

---

### Innovation 4: Verifying That Test-Time Performance Can Be Decoupled From Training-Time Sequence Length

The fourth contribution is an **empirical finding with significant practical implications**: a model can be trained on relatively short sequences (2K–8K tokens) and, with the right key space structure, perform effectively at test time on sequences orders of magnitude longer. This decouples the cost of training from the benefit of long-context inference.

Prior work largely assumed — implicitly or explicitly — that to handle context length $L$ at inference, you need to train on sequences of length at least $L$, or at least within a small factor of $L$. Memorizing Transformer trained with memory sizes matching its evaluation memory sizes. Position Interpolation needed fine-tuning at the extended length. Standard Transformer-XL and Longformer models were trained on the same sequence lengths they were evaluated on. The underlying assumption was that attention mechanisms need to *experience* long-range dependencies during training to learn to use them.

FOT challenges this assumption directly. The 3B LONGLLAMA model is fine-tuned with an 8K context length and achieves 94.5% accuracy at 100K and 73% at 256K on passkey retrieval (Figure 1). The 37M model is trained on 512-token documents and achieves >92% accuracy at 16M tokens on dictionary lookup (Figure 10, Appendix F). In both cases, the training context length is a tiny fraction of the inference context length, yet performance remains high.

What makes this finding non-trivial is that it is **not simply a consequence of the kNN architecture**. The Memorizing Transformer also used kNN memory at inference time, but when trained with 2K additional context, it "struggles to utilize additional context beyond 32K tokens effectively" (Appendix K, Table 10). FOT with the same architecture but crossbatch training reaches 128K tokens with monotonically improving perplexity (Appendix K, Table 11). The difference is the key space structure: MT's keys, trained without document-discriminative pressure, produce kNN retrievals that degrade in quality as the memory grows and the fraction of relevant keys shrinks. FOT's keys, trained with crossbatch, maintain retrieval quality at scale because they are semantically structured from the start.

This finding has a direct practical upshot: **you don't need to train on long sequences to get long-context performance.** The 10B tokens used to fine-tune LONGLLAMA-3B is a tiny fraction (1%) of the 1T tokens used to pretrain OpenLLaMA, and it was done at 8K context — not 256K. The computational savings are enormous. More importantly, it means that long-context capability can be added to *existing* models post-hoc, without the data engineering challenge of assembling massive corpora of long documents for training. Many widely-used pretraining datasets (C4, The Pile, RedPajama) consist primarily of documents shorter than a few thousand tokens. FOT's ability to train on these datasets while enabling inference at vastly longer contexts dramatically expands the set of models and domains where long-context inference is feasible.

The evidence for this decoupling is strongest in the controlled dictionary lookup experiment (Figure 10), where the task is pure association (memorize key-value pairs, retrieve by key) and there are no confounding factors like language modeling difficulty or document coherence. The baseline Transformer fails completely beyond 16K tokens — its attention mechanism, even with perfect computational capacity, cannot locate the right key among the distractors because it was never trained to do so. FOT maintains >92% accuracy out to 16M tokens, with the only limitation being the size of the FAISS index. This clean experiment isolates the effect: it's not about training length, it's about key space structure.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The paper uses a diverse set of benchmarks spanning synthetic tasks, language modeling, and downstream few-shot evaluation. The primary long-context language modeling datasets are: **PG-19** (Rae et al., 2019), a corpus of English-language books published before 1919, used as a well-established long-context benchmark; **arXiv**, comprising LaTeX source of papers labeled "Mathematics" downloaded via arXiv Bulk Data Access; **GitHub**, permissively licensed repositories filtered for C, C++, Java, Python, Go, and TypeScript, with files concatenated within each repository while preserving subdirectory structure; and **Isabelle**, formal mathematical proofs from the Archive of Formal Proofs and Isabelle standard library, with files concatenated based on import dependencies. For downstream evaluation, the paper uses **TREC** (Li and Roth, 2002; Hovy et al., 2001) for question classification (50 classes), **WebQS** (Berant et al., 2013) for question answering, **Qasper** (Dasigi et al., 2021) from the SCROLLS benchmark (Shaham et al., 2022) for question answering over research papers, and the **passkey retrieval** synthetic task (Mohtashami and Jaggi, 2023) for measuring effective context length. Models are evaluated in two distinct settings: **single-document (single-doc)**, where memory is cleared between documents, and **multi-document (multi-doc)**, where memory persists across documents without resets, testing the model's ability to ignore accumulated irrelevant information. The dictionary lookup task (Appendix F) is a custom synthetic benchmark where models memorize key-value mappings and answer queries, with training on 512-token documents and evaluation up to 16M tokens. Language modeling evaluations use 1M tokens for computing test perplexities (Appendix J).

- **Base model(s).** Three tiers of models are used. For the LONGLLAMA experiments (Section 4), the base models are **OpenLLaMA-3B** and **OpenLLaMA-7B** (Geng and Liu, 2023), open-source reproductions of LLaMA (Touvron et al., 2023) trained for 1 trillion tokens, chosen because they are "representative of the capabilities of many contemporary LLMs" (Section 4) and, critically, their public availability enables the paper's stated goal of demonstrating that FOT can extend context length of *existing* models through cost-effective fine-tuning. For the analysis experiments (Section 5), the authors use decoder-only Transformers with 12 layers: primarily **184M-parameter** models (embedding dim 1024, head dim 128, 8 heads, feedforward dim 4096) and **37M-parameter** models (embedding dim 512, head dim 64, 8 heads, feedforward dim 2048), both trained from scratch or fine-tuned on C4 (Raffel et al., 2019a). For the FLOPs-matched-type comparison against Memorizing Transformer (Appendix K), the same 184M architecture is used with varying training memory lengths (2K, 8K, 16K, 32K) to study scaling behavior.

- **Metrics.** The primary metrics are: **perplexity** on language modeling datasets (PG-19, arXiv, GitHub, Isabelle), measuring next-token prediction quality — lower is better, computed on 1M held-out tokens per dataset; **accuracy** on downstream tasks — for TREC (50-class classification), WebQS (question answering), Qasper (question answering with yes/no and open questions evaluated separately), and passkey retrieval (binary: correct retrieval of hidden passkey); **positive attention mass** ($r_d$, Section 3.3), a diagnostic metric defined as the fraction of attention weight allocated to keys from the same document as the query when $d$ documents are present in the crossbatch attention context — this measures the degree of distraction, with $r_d \approx 1/d$ indicating uniform distraction and $r_d \approx 1$ indicating perfect focus; and **dictionary lookup accuracy** (Appendix F), measuring whether the model correctly predicts the value tokens associated with a queried key. For the short-context performance retention check (Section 4.6), the paper uses the **LM Evaluation Harness** (Gao et al., 2021a) with its standard suite of metrics (accuracy, accuracy normalized, exact match, F1) across tasks including ANLI, ARC, BoolQ, HellaSwag, OpenBookQA, PIQA, ReCoRD, RTE, TruthfulQA, WiC, and WinoGrande.

- **Baselines.** The paper compares against several baselines. **Standard Transformer** (Vaswani et al., 2017): the same architecture without memory attention layers, trained on the standard next-token prediction objective — this establishes the lower bound for what happens without any memory augmentation. **Memorizing Transformer (MT)** (Wu et al., 2022): the most directly comparable prior work, using kNN-augmented attention layers with non-differentiable memory during training and gating-based memory integration; evaluated in both single-doc (memory from same document only) and multi-doc (memory shared across documents) configurations with training memory lengths of 2K, 8K, 16K, and 32K tokens (Appendix K). **Transformer-XL** (Dai et al., 2019): a sparse-attention architecture that caches previous context segments and attends across segment boundaries in all layers, trained with both local context and memory length of 1K tokens. **Standard long-context fine-tuning** (Section 4.5): a 3B OpenLLaMA model fine-tuned on 4K context for 1B tokens using standard next-token prediction (no FOT, no memory layers), following the approach of MosaicML (2023) and Nijkamp et al. (2023) — this tests whether FOT outperforms simply training on longer sequences. **LongChat-7B** (Ma and Zhang, 2023): an external 7B model fine-tuned for long-context performance, used as a reference point for Qasper evaluation. **OpenLLaMA (original)**: the unmodified checkpoints evaluated at 2K context length, serving as the short-context baseline for both the passkey retrieval and the LM Evaluation Harness benchmarks.

- **Generation budget / compute accounting.** Compute is measured in several ways depending on the experiment. For training: **training steps** (e.g., 100K steps pretraining + 10K steps fine-tuning for the 184M model analysis in Section 5.2; 500K steps total for the PG-19 experiments in Section 5.3; 5K steps for the dictionary lookup task in Appendix F) and **total tokens processed** (10B tokens for LONGLLAMA-3B fine-tuning, 3B tokens for LONGLLAMA-7B, 1B tokens for the standard long-context fine-tuning baseline in Section 4.5, 128K tokens per step for the 184M models in Sections 5.2 and 5.4). For inference: **context length** measured in tokens — the local context window (typically 512, 1K, or 2K tokens) plus the size of the memory/kNN index (ranging from 4K to 16M tokens depending on the experiment). For the kNN retrieval: **$k$**, the number of nearest neighbors retrieved (usually $k = 128$ for 184M models and $k = 32$ for 37M models). The crossbatch training dimension **$d$** controls the ratio of positive to negative documents during training (ranging from $d=1$ to $d=128$). **Batch size** is reported in tokens: 32K tokens for most analysis experiments, 128K tokens for the larger-scale fine-tuning in Sections 5.2 and 5.4, and 256K tokens for LONGLLAMA fine-tuning. All FOT-specific overhead is localized to the memory attention layers (a subset of total layers), and the paper notes in Appendix I that the maximum $d$ is constrained by TPU memory — $d=64$ or $d=128$ is "the maximum value that fits into the memory of a single TPUv3/TPUv2 machine."

- **Cross-validation / statistical protocol.** For the TREC and WebQS few-shot experiments (Section 4.4), the paper averages over 20 trials with different random samples of in-context demonstrations from the training set and reports confidence intervals: "the resulting confidence intervals for TREC and WebQS are smaller than 1% and 0.1%, respectively" (Table 1). For the dictionary lookup task (Figure 10, Appendix F), error bars represent the minimum and maximum over 10 different random seeds, allowing assessment of variance. For the arXiv baseline experiment in Appendix K, the authors performed three runs with different random seeds and report a standard deviation of 0.002 perplexity. However, the authors explicitly note a limitation: "due to resource constraints, we were unable to conduct multiple runs for all experiments. Our preliminary findings indicate that the observed variance was minimal compared to the impact observed from other factors under investigation" (Appendix J). No formal cross-validation or statistical testing (e.g., bootstrap confidence intervals, paired tests) is reported for the main perplexity results or the LONGLLAMA evaluations. For hyperparameter selection (Appendix E), sweeps were performed over learning rates and batch sizes, with the best values selected based on validation performance, but the selection procedure (held-out validation set? within-training monitoring?) is not specified in detail for all experiments.

### Main Quantitative Results

#### Passkey Retrieval: Context Length Extrapolation

The headline result for LONGLLAMA's effective context length comes from the passkey retrieval task (Figure 1). **LONGLLAMA-3B achieves 94.5% accuracy at 100K tokens and 73% accuracy at 256K tokens**, despite being fine-tuned with only an 8K context length. The original OpenLLaMA-3B, trained with a 2K context, cannot handle any context beyond its training length — its accuracy drops to near zero for prompts longer than 2K tokens. This represents a **32× extrapolation** beyond the training context length (8K → 256K) while maintaining well-above-chance performance (73% vs. the ~0% of the baseline at that length).

The accuracy curve (Figure 1) shows a gradual decline: near 100% at 2K and 8K, approximately 94.5% at 100K, and 73% at 256K. There is no sudden cliff — performance degrades gracefully as context lengthens, suggesting that the limitation at 256K may be due to the model's retrieval precision rather than a fundamental breakdown. The paper does not report results beyond 256K, so it is unclear where accuracy would approach chance levels. The 7B model results are not shown in Figure 1; the paper focuses on the 3B model for this plot.

#### Few-Shot In-Context Learning: TREC and WebQS

Table 1 reports accuracy on TREC (question classification, 50 classes) and WebQS (question answering) as the context length increases from 2K to 8K, using LONGLLAMA-3B and LONGLLAMA-7B. **On TREC, LONGLLAMA-3B improves from 67.0% at 2K to 73.3% at 8K (+6.3 percentage points); LONGLLAMA-7B improves from 63.2% at 2K to 75.9% at 8K (+12.7 points).** The gains are monotonic with context length for both models: 4K yields intermediate improvements (71.6% for 3B, 72.7% for 7B), and 6K yields further gains (72.9% for 3B, 74.9% for 7B). The 7B model shows a particularly large jump from 2K (63.2%) to 4K (72.7%), suggesting that the additional demonstrations available at 4K provide critical coverage of the 50-class label space that is largely absent at 2K (where only ~100 examples fit, meaning many classes have zero or one demonstration).

**On WebQS, gains are more modest.** LONGLLAMA-3B improves from 21.2% at 2K to 22.4% at 8K (+1.2 points); LONGLLAMA-7B improves from 25.5% at 2K to 27.7% at 8K (+2.2 points). The improvements are also monotonic, though smaller in absolute terms. The paper notes that TREC benefits more from extended context because "only 100 examples fit the standard context length (2K); it is not unusual that no class example is present for a given question, making the task impossible" (Section 4.4) — the extended context directly addresses the label coverage problem. WebQS, as a question-answering task, may benefit less from additional *unrelated* demonstrations and more from the specific knowledge contained in relevant passages, though the paper does not analyze this difference in depth.

**Comparison to standard long-context fine-tuning** (Table 2, Section 4.5) isolates FOT's contribution. Both models (FOT and baseline) are 3B models fine-tuned on 1B tokens with 4K context. At 4K context (the training length for both), FOT achieves 60.9% on TREC vs. 57.2% for the baseline (+3.7 points), and 21.0% on WebQS vs. 18.7% for the baseline (+2.3 points). The crucial difference is **extrapolation beyond the training length**: at 6K context, FOT reaches 61.7% on TREC (vs. baseline cannot process 6K) and at 8K reaches 62.5%. The baseline, restricted to its 4K training window, cannot be evaluated beyond 4K. On WebQS, FOT at 6K achieves 21.2% while the baseline is capped at its 4K performance of 18.7%. This demonstrates that FOT's extrapolation capability is not simply a function of the longer training context (both were trained at 4K) but rather a property of the learned key space structure.

#### Qasper: Question Answering Over Research Papers

Table 6 (Appendix A.5) reports zero-shot performance on the Qasper validation set from SCROLLS. **LONGLLAMA-3B improves monotonically from 18.7% at 2K to 26.6% at 8K (+7.9 percentage points)**. OpenLLaMA-3B is capped at 2K (18.7%, same as LONGLLAMA at that length). For reference, LongChat-7B (a 7B model specifically designed for long context) achieves 19.4% at 2K, 21.2% at 4K, 25.0% at 6K, and 28.8% at 8K. LONGLLAMA-3B at 8K (26.6%) approaches LongChat-7B at 8K (28.8%) despite being less than half the size, and outperforms LongChat-7B at 4K (20.7% vs. 21.2% at 4K, essentially tied with the larger model). The key comparison is that LONGLLAMA-3B's performance *increases* with context length, while OpenLLaMA-3B cannot access the additional context at all. The evaluation uses the LM Evaluation Harness implementation where "yes/no questions are evaluated separately from open questions" (Table 6 note); the table reports aggregate performance.

#### Language Modeling Perplexity: FOT Fine-Tuning and Extrapolation

Table 3 (Section 5.2) presents perplexity on four long-context datasets (GitHub, Isabelle, arXiv, PG-19) after fine-tuning a standard 184M-parameter Transformer with FOT on C4 (10K steps, crossbatch dimension $d$ randomly sampled from $\{2, 128\}$). **FOT achieves monotonically decreasing perplexity as context length scales from 2K to 64K on all four datasets.** For example, on PG-19: 23.74 at 2K, 23.25 at 4K, 22.85 at 16K, and 22.65 at 64K — a 1.09 perplexity improvement from 2K to 64K. On arXiv: 8.17 at 2K down to 6.81 at 64K (1.36 improvement). On GitHub: 6.72 at 2K down to 5.32 at 64K (1.40 improvement). On Isabelle: 5.63 at 2K down to 4.44 at 64K (1.19 improvement). The improvements are largest in the transition from 2K to 4K or 16K, with diminishing returns at 64K, but crucially there is no degradation — the model continues to benefit from additional context beyond anything it saw during fine-tuning (which used 2K total differentiable context when $d=1$ and 2K local with $d=128$ additional contexts).

**Comparison to Memorizing Transformer (MT) fine-tuned from the same base checkpoint** shows FOT's decisive advantage at scale. At 2K context, MT achieves higher perplexity than FOT on all datasets (e.g., PG-19: 24.03 vs. 23.74; arXiv: 9.39 vs. 8.17; GitHub: 8.10 vs. 6.72). At 64K, MT's perplexity is substantially worse: PG-19 23.24 vs. 22.65 for FOT; arXiv 8.60 vs. 6.81; GitHub 7.26 vs. 5.32; Isabelle 6.64 vs. 4.44. Moreover, MT's perplexity improvements with context length are much smaller — on PG-19, MT goes from 24.03 at 2K to 23.24 at 64K (0.79 improvement) vs. FOT's 23.74 to 22.65 (1.09 improvement). The MT model was fine-tuned with "local context of 1K and memory size of 16K" (Section 5.2), meaning it was actually trained on *longer* sequences than FOT's 2K total differentiable context, yet performs worse at all evaluation lengths. This directly supports the paper's claim that differentiable key-value training (FOT) produces qualitatively better key representations than non-differentiable memory training (MT), even when MT has access to longer contexts during training.

**Comparison to Transformer-XL** (also fine-tuned from the same base with local context and memory length of 1K): at 2K context, Transformer-XL performs comparably to FOT (PG-19: 23.57 vs. 23.74; arXiv: 8.21 vs. 8.17; GitHub: 6.85 vs. 6.72; Isabelle: 5.76 vs. 5.63). Transformer-XL has access to the previous context in *all* layers, unlike FOT (which has memory attention in only one layer, layer 8), so its competitive performance at 2K is expected. However, Transformer-XL cannot be evaluated at longer contexts (it is not designed to extend beyond its training window), so the comparison is only at 2K. The fact that FOT matches Transformer-XL's performance at 2K while using memory in only one layer, and then significantly improves at longer contexts, demonstrates the advantage of the memory attention mechanism beyond the training length.

**Appendix K (Tables 10 and 11)** provides a more detailed comparison on arXiv between FOT and MT with varying training memory lengths, in a setting where both are trained and evaluated on arXiv (rather than C4 → arXiv zero-shot as in Table 3). The key finding: **FOT with $(w=2, d=2)$ — meaning 4K total differentiable context during training — achieves 2.148 perplexity at 128K evaluation context, which is better than MT with 16K training memory length (2.164 at 128K)**. This is the paper's strongest apples-to-apples evidence that differentiable crossbatch training is more effective than simply training with larger non-differentiable memory. The breakdown: MT with 2K training memory plateaus at 64K–128K evaluation context (2.195 → 2.195), showing no further improvement beyond 64K. MT with 8K training memory improves to 2.168 at 128K. MT with 16K training memory reaches 2.164 at 128K — essentially the same as 8K, suggesting diminishing returns from larger non-differentiable memory. FOT with $w=1, d=2$ (2K differentiable context) achieves 2.171 at 128K, already outperforming MT with 2K memory and competitive with MT with 8K memory. FOT with $w=2, d=2$ (4K differentiable context) reaches 2.148 at 128K, the best result in the table. Additionally, FOT with $d=2$ consistently outperforms FOT with $d=1$: at $w=1$, $d=2$ achieves 2.171 at 128K vs. $d=1$ at 2.187; at $w=2$, $d=2$ achieves 2.148 vs. $d=1$ at 2.152. This confirms that including negatives ($d>1$) in the crossbatch training is beneficial even in single-document evaluation.

#### Multi-Document Language Modeling: Handling Distractions

Section 5.3 and Figure 8 examine how FOT handles the multi-document setting on PG-19, where the memory contains books unrelated to the current document. The metric is perplexity as a function of total tokens in context (memory size), ranging from a few thousand to over 500K tokens. The key findings:

**FOT with higher crossbatch dimension $d$ achieves lower perplexity.** At 500K+ tokens: FOT $d=8$ achieves approximately 14.5 perplexity, FOT $d=4$ approximately 14.7, FOT $d=2$ approximately 14.9, and FOT $d=1$ approximately 15.3. The standard Transformer (no memory) achieves approximately 16.1 — worse than all FOT variants. The ranking $d=8 > d=4 > d=2 > d=1 >$ no memory is monotonic, confirming that exposure to more negatives during training produces better discrimination at inference.

**FOT $d=2 \rightarrow 64$ (the curriculum schedule) is the best performer**, achieving roughly 14.3 perplexity at 500K+ tokens — essentially tying with "Single-doc MT (Single-doc eval)," which serves as a soft lower bound since it has no distractions (memory contains only the current book). The gap between FOT $d=2 \rightarrow 64$ and this lower bound is only about 0.2 perplexity points, meaning that FOT with strong crossbatch training is nearly as good at handling 500K tokens of multi-document memory as a model that sees only single-document memory — it has almost entirely overcome the distraction issue.

**Memorizing Transformer (single-doc training) degrades significantly in multi-document evaluation.** The "Single-doc MT" curve (trained with single-document memory of 16K) starts at approximately 14.0 perplexity when evaluated in the *single-doc* setting (the lower bound line) but jumps to approximately 14.9 when evaluated in the *multi-doc* setting at 500K tokens — a gap of ~0.9 perplexity, significantly larger than FOT $d=2 \rightarrow 64$'s gap of ~0.2. This directly measures the cost of lacking crossbatch training: MT's keys are not document-discriminative, so when other books enter the memory, the kNN retrieval quality degrades, and perplexity suffers.

**All FOT variants gracefully handle increasing memory sizes.** The perplexity curves in Figure 8 are nearly flat from 100K to 500K tokens — FOT $d=2 \rightarrow 64$ increases from roughly 14.1 to 14.3 across this range, a change of only 0.2 perplexity. This is the "graceful" scaling that the paper emphasizes: "perplexity increases with memory size, but we stress that this happens gracefully" (Section 5.3). In contrast, the non-FOT baselines (standard Transformer, MT) show steeper degradation.

#### Single-Document Context Extrapolation with Varying Crossbatch Configuration

Figure 9 (Section 5.4) examines perplexity on PG-19 in the single-doc setting when varying both $d$ and $w$ (the number of previous contexts used in crossbatch, where $w=1$ means total differentiable context of $2 \times 1024$ and $w=2$ means $3 \times 1024$). Four configurations are compared: $(d=2, w=2)$, $(d=2, w=1)$, $(d=1, w=2)$, and $(d=1, w=1)$.

**Perplexity improves as evaluation context grows from 2K to 64K for all configurations**, confirming that FOT extrapolates beyond its training context length even in single-doc settings. The baseline model (before FOT fine-tuning) achieves approximately 23.8 at 2K context; all FOT configurations improve on this. At 64K evaluation context: $(d=2, w=2)$ achieves approximately 22.4 perplexity (best), $(d=1, w=2)$ approximately 22.55, $(d=2, w=1)$ approximately 22.65, and $(d=1, w=1)$ approximately 22.85 (worst among FOT variants, but still much better than the pre-fine-tuning baseline).

**Increasing $d$ helps: $(d=2, w=1)$ outperforms $(d=1, w=1)$** at all evaluation lengths beyond 2K. At 64K, the gap is roughly 0.2 perplexity (22.65 vs. 22.85). Similarly, increasing $w$ (longer training context) also helps: $(d=1, w=2)$ outperforms $(d=1, w=1)$ at most lengths. An interesting comparison: $(d=1, w=2)$ slightly outperforms $(d=2, w=1)$ at 64K (22.55 vs. 22.65), suggesting that given a fixed computational budget, extending the training context length ($w=2$, meaning 3K tokens) may be slightly more beneficial than increasing the crossbatch dimension ($d=2$ with $w=1$, meaning 2K tokens). However, $(d=2, w=2)$ achieves the best of both, confirming that both dimensions are beneficial and complementary.

#### Dictionary Lookup: Extreme Extrapolation

Figure 10 (Appendix F) reports accuracy on a synthetic dictionary lookup task where models memorize key-value mappings and must answer queries. **A 37M-parameter FOT model, trained on 512-token documents, achieves >92% accuracy with 16 million tokens of dictionary memory.** The standard Transformer baseline, trained on the same 512-token documents, achieves near-perfect accuracy up to 1K tokens but drops to approximately 0% accuracy beyond 16K tokens — it completely fails when the dictionary exceeds a modest size. FOT maintains >98% accuracy up to 256K tokens, approximately 96% at 4M tokens, and approximately 92% at 16M tokens. The decline is gradual, suggesting that even 16M tokens is not a hard limit — the accuracy curve is still well above chance, and the primary bottleneck appears to be the capacity of the FAISS index rather than a fundamental limitation of the key space structure.

This task is designed to isolate the pure retrieval capability: the model must associate arbitrary token sequences (keys, 4 tokens each) with arbitrary value sequences (values, 4 tokens each) and retrieve the correct value when queried. There is no language modeling nuance, no semantic similarity to exploit — it is a stress test of whether the kNN mechanism can locate the right key among millions of distractors. The fact that FOT succeeds at 16M tokens (a 31,250× increase over the 512-token training length) while the baseline fails at 16K (only 31×) directly demonstrates that crossbatch training produces key representations that remain discriminative at extreme scales. Error bars (min/max over 10 random seeds) are visible in Figure 10, with the spread increasing at larger memory sizes but remaining well above the baseline.

#### Short-Context Performance Retention

Table 5 (Appendix A.4) evaluates LONGLLAMA-3B and LONGLLAMA-7B on the LM Evaluation Harness benchmark, compared to the original OpenLLaMA checkpoints. **The average score across all tasks is identical: 0.53 for both OpenLLaMA-3B and LONGLLAMA-3B; 0.55 for both OpenLLaMA-7B and LONGLLAMA-7B.** Individual task scores differ by at most 2–3 percentage points in either direction, with no systematic degradation. For example, LONGLLAMA-3B scores 0.48 on HellaSwag vs. 0.49 for OpenLLaMA-3B; 0.73 on PIQA vs. 0.75; 0.50 on WiC vs. 0.48. LONGLLAMA-7B scores 0.52 on HellaSwag vs. 0.53; 0.75 on PIQA vs. 0.76; 0.50 on WiC vs. 0.51. These differences are within the range of sampling variation and confirm that fine-tuning with FOT does not catastrophically forget short-context capabilities. The evaluation was performed without context extension, treating LONGLLAMA as a standard OpenLLaMA model (i.e., using only local context, no memory augmentation), confirming backward compatibility.

### Ablation Studies and Robustness Checks

**Differentiability of keys and values (FOT vs. Memorizing Transformer):** Figure 5 (Appendix C.1) compares FOT with $d=8$ to a "Multi-doc MT" trained with non-differentiable memory of size 4096 shared across 8 documents, both with local context of 512 tokens. At 100K tokens in context, FOT achieves approximately 14.5 perplexity vs. MT's 14.8; at 500K tokens, FOT reaches approximately 15.0 vs. MT's 15.4. The gap widens as memory grows, confirming that differentiable keys and values are increasingly important at scale. Table 8 further shows that even in single-doc (no distractions), FOT with $d=1$ (differentiable previous context) achieves slightly lower perplexity than MT (non-differentiable memory) at all training context lengths tested (512: 14.18 vs. 14.68; 1024: 14.17 vs. 14.46; 2048: 14.11 vs. 14.43), showing that differentiability helps even without negatives.

**Importance of negatives (crossbatch dimension $d$):** Figure 6 (Appendix C.2) compares FOT trained with $d=1$ (no negatives) to FOT trained with $d=2 \rightarrow 64$ (curriculum to many negatives), evaluated in the multi-doc setting. At 500K tokens, FOT $d=1$ achieves approximately 15.3 perplexity, which is only slightly better than the "Transformer (no mem)" baseline at approximately 16.1, and dramatically worse than FOT $d=2 \rightarrow 64$ at approximately 14.3. The "Single-doc MT (Single-doc eval)" lower bound is approximately 14.1. FOT $d=1$'s curve rises steeply with memory size (from ~14.3 at 10K to ~15.3 at 500K), while FOT $d=2 \rightarrow 64$'s curve is nearly flat. This ablation establishes that **negatives are the active ingredient** — differentiable context alone ($d=1$) is insufficient; the model must be exposed to other-document keys during training to learn document-discriminative representations.

**Impact of $d$ schedule:** Figure 8 compares constant $d \in \{1, 2, 4, 8\}$ against a curriculum schedule ($d=2 \rightarrow 64$). The curriculum schedule produces the best perplexity across all memory sizes. Among constant schedules, larger $d$ is consistently better ($d=8 > d=4 > d=2 > d=1$), but the curriculum ($d=2 \rightarrow 64$) outperforms constant $d=8$, demonstrating that starting with a small $d$ to establish use of additional context, then increasing to a much larger $d$, is more effective than using a moderate $d$ throughout training.

**Gating vs. unified softmax for memory integration:** Appendix B.2 and Figure 4 compare the original Memorizing Transformer gating mechanism ($v = v_M \cdot \sigma(b_g) + v_C \cdot (1-\sigma(b_g))$) against FOT's simpler approach (concatenate local and memory keys, apply single softmax). The two methods produce "no difference in performance" (the training curves in Figure 4 overlap almost perfectly through 500K steps on PG-19 single-doc with 16K memory). The authors choose the simpler unified softmax because it requires no additional parameters and makes fine-tuning existing models straightforward.

**Impact of training memory length for Memorizing Transformer:** Table 10 (Appendix K) shows that scaling MT's training memory length from 2K to 8K provides meaningful perplexity improvements on arXiv evaluated at long contexts (e.g., at 64K evaluation: 2.195 for 2K training memory vs. 2.169 for 8K). However, further scaling to 16K and 32K yields minimal additional gains (2.166 and 2.168 respectively at 64K; 2.164 and 2.166 at 128K). This suggests that non-differentiable memory training hits diminishing returns — the model cannot effectively structure its keys to utilize very large memories because it receives no gradient signal through the retrieved entries.

**FOT with $w$ and $d$ variations on arXiv:** Table 11 (Appendix K) shows that both $w$ (number of previous contexts, effectively training context length) and $d$ (crossbatch dimension) independently improve performance. At 128K evaluation: $(w=1, d=1)$ achieves 2.187; increasing $d$ to 2 yields 2.171; increasing $w$ to 2 with $d=1$ yields 2.152; increasing both yields 2.148. The best FOT configuration $(w=2, d=2)$ with 4K total differentiable context outperforms MT with 16K training memory (2.148 vs. 2.164), despite using 4× less training context.

**Combined FOT + MT training (proof-of-concept):** Appendix C.3 and Figure 7 report an experiment where a model trained with crossbatch for 499K steps is fine-tuned with the MT objective (non-differentiable memory) for 1K steps. The resulting model achieves better perplexity than pure MT trained for the full 500K steps (e.g., at 65K evaluation context: FOT→MT achieves approximately 14.1 vs. pure MT at approximately 14.35). This suggests that crossbatch training provides a strong initialization that can be further refined with MT-style training that exposes the model to the full memory. The authors frame this as a promising direction for combining the strengths of both approaches but do not pursue it further.

**ReST$^{EM}$ on revisions:** Not applicable — this paper does not use ReST$^{EM}$ or revision models. The paper's only mention of iterative refinement is in a different context (the broader impact statement) and does not involve experimental results.

**Attention mass diagnostic (Figure 3):** This is a diagnostic measurement, not strictly an ablation. The "FOT d=2→64" curve shows near-perfect focus ($r_d \approx 1.0$ even when many documents are present), while the baseline Transformer and FOT $d=1$ show $r_d \approx 1/d$. The intermediate "FOT d=8" curve shows partial improvement — attention mass is above $1/d$ but below 1.0, confirming that the effect is graded with $d$.

### Critical Assessment

#### Claim 1: "FOT addresses the distraction issue, enabling context length extension."

**What the experiments demonstrate:** The paper convincingly shows that FOT with crossbatch training ($d > 1$) produces keys that are document-discriminative (Figure 3: $r_d$ approaches 1.0), and that this translates to better perplexity in multi-document settings (Figures 6, 8) and better retrieval at extreme scales (Figure 10: 16M tokens on dictionary lookup). The causal chain — crossbatch training → structured key space → reduced distraction → better long-context performance — is well-supported by the combination of the diagnostic metric ($r_d$) and the downstream perplexity/accuracy results.

**Qualifications and gaps:** The paper does not directly measure whether FOT's improvements on perplexity translate to proportionally better performance on *generative* tasks in the multi-document setting. The downstream evaluations (TREC, WebQS, Qasper) are all single-document — the context contains demonstrations or a research paper, but not multiple unrelated documents mixed together. The one exception is the dictionary lookup task, which is purely retrieval-based with no language understanding component. The passkey retrieval task is also a pure retrieval test. The real-world use case the paper motivates — "large code repositories" (Section 1) where the model must retrieve relevant code across files while ignoring irrelevant ones — is not directly tested. Multi-document *generation* quality (e.g., summarization of one document among many, or code completion in a repository context) would be a stronger test of the distraction issue's practical impact.

#### Claim 2: "LONGLLAMA models adeptly manage a 256k context length for passkey retrieval."

**What the experiments demonstrate:** Figure 1 shows LONGLLAMA-3B achieving 73% accuracy at 256K on passkey retrieval, which is a striking result given 8K training context. This is a clean demonstration of extrapolation.

**Qualifications and gaps:** (1) This is a *single* synthetic task measuring a *single* capability — retrieving a token from long context. It does not measure the model's ability to *reason over* long context, integrate information across the context, or handle complex dependencies. A model could achieve high passkey retrieval while being useless for practical long-context tasks. (2) The paper does not report passkey results for the 7B model — Figure 1 shows only the 3B model. (3) The accuracy drops from near-100% at 8K to 73% at 256K — this is a 27 percentage point decline, and the trend is downward. Whether accuracy would drop further at 512K or 1M is untested. (4) There is no comparison to other long-context methods on this task — how does LONGLLAMA compare to Position Interpolation or Landmark Attention at 256K? The paper does not say.

#### Claim 3: "FOT can be applied to existing models via cost-effective fine-tuning."

**What the experiments demonstrate:** LONGLLAMA-3B fine-tuned on 10B tokens (1% of the original 1T pretraining budget) and LONGLLAMA-7B on 3B tokens (0.3% of pretraining) achieve demonstrated gains. The LM Evaluation Harness results (Table 5) confirm that short-context performance is preserved. The backward compatibility (using LONGLLAMA as a standard LLaMA checkpoint) is a genuine practical advantage.

**Qualifications and gaps:** (1) "Cost-effective" is asserted but not directly compared — what does 10B tokens of fine-tuning cost vs. pretraining from scratch with FOT? The paper doesn't provide FLOP counts or dollar amounts. (2) The fine-tuning dataset is a carefully constructed mixture with specific length filtering and concatenation strategies (Appendix A.3) — how sensitive are the results to the dataset composition? (3) The fine-tuning uses the original OpenLLaMA optimizer and hyperparameters with only a learning rate reduction — the paper does not ablate whether these choices are optimal or whether further tuning would yield additional gains. (4) The claim that FOT "does not require long context during training" (abstract) is true for the inference-time context (256K), but the training context is 8K, which is already 4× longer than the original 2K context — so some extension during training *is* required, even if it's modest compared to the inference-time extension.

#### Claim 4: "FOT enables extrapolation to 16 million tokens on dictionary lookup."

**What the experiments demonstrate:** Figure 10 shows >92% accuracy at 16M tokens for a 37M-parameter FOT model trained on 512-token sequences. This is an impressive 31,250× extrapolation.

**Qualifications and gaps:** (1) This is a *synthetic* task with random key-value pairs — there is no semantic content, no language structure, and no ambiguity. Success on this task demonstrates that the kNN retrieval mechanism works at scale, but it does not demonstrate that the model can perform useful language tasks with 16M tokens of context. (2) The 37M model is tiny compared to the LONGLLAMA models (3B, 7B) — it is unclear whether the 16M-token extrapolation would hold at larger model scales or with real text rather than random tokens. (3) The task uses a vocabulary of only 64 tokens — dramatically smaller than the 32K vocabulary of real language models — which simplifies the key space structure. (4) The paper uses this task as a proof of concept for the key space structure, not as a practical benchmark; the strong result is suggestive but does not directly imply practical long-context capability.

#### Claim 5: "FOT significantly improves few-shot learning by enabling more demonstrations."

**What the experiments demonstrate:** Table 1 shows monotonic accuracy improvements on TREC (+6.3 points for 3B, +12.7 points for 7B from 2K to 8K) and smaller improvements on WebQS (+1.2 for 3B, +2.2 for 7B). Table 2 shows that FOT outperforms standard long-context fine-tuning and extrapolates beyond the training length.

**Qualifications and gaps:** (1) The absolute numbers on TREC are not compared to a simple alternative — what if you used the extended context to include *better* demonstrations (e.g., retrieved by similarity) rather than *more* demonstrations? FOT enables more demonstrations, but the paper does not show that more random demonstrations are the best use of the extended context. (2) The WebQS improvements are small — 1–2 percentage points — and it's unclear whether they are statistically significant (the confidence intervals are reported as <0.1%, but this appears to be across sampling of demonstrations, not across model training runs). (3) The paper does not compare to other context-extension methods on these tasks — how does LONGLLAMA at 8K compare to Position Interpolation at 8K, or to a model natively trained on 8K context? Table 2 provides a baseline (standard fine-tuning at 4K), but no 8K-trained baseline. (4) The 7B model's improvement from 2K to 4K on TREC is enormous (+9.5 points, from 63.2 to 72.7), which may indicate that the 2K context is simply insufficient for this 50-class task (as the paper notes) — the gains from 4K to 8K are more modest (+3.2 points for 7B), suggesting the extension from 2K to 4K is the critical range, and FOT's contribution is primarily in enabling that extension.

#### Missing Experiments and Weaknesses

**No multi-document downstream evaluation.** The paper's central motivation is the multi-document distraction issue, but all downstream evaluations (TREC, WebQS, Qasper) are single-document tasks. There is no evaluation where the model must answer questions about one document while other documents are present in memory — the exact scenario that the crossbatch training is designed for. A multi-document QA or retrieval task (e.g., "answer questions about paper A, with papers B–E also in memory") would directly test the paper's core claim.

**No comparison to Position Interpolation or Landmark Attention.** These are the most directly comparable recent methods for context extension in LLaMA models. The paper cites them (Section 2) but never compares LONGLLAMA against them quantitatively. A head-to-head comparison on passkey retrieval or few-shot tasks would strengthen the claim that FOT's extrapolation is superior.

**Single model family for large-scale experiments.** The LONGLLAMA results use only OpenLLaMA (3B, 7B). There is no demonstration on other model families (e.g., GPT, PaLM, Falcon) or larger scales (13B, 65B). The analysis experiments use custom 184M and 37M Transformers, but the bridge between these small-scale ablations and the 3B/7B LONGLLAMA results relies on the assumption that the findings transfer — reasonable, but unverified.

**No ablation of which layers to convert to memory attention.** The paper follows the Memorizing Transformer's layer choices (layer 8 of 12 for 184M models; layers $\{6, 12, 18\}$ for 3B; $\{8, 16, 24\}$ for 7B) and acknowledges this was not explored (Section 5.5). Converting different layers, or more/fewer layers, could substantially change performance, but no experiments test this.

**Sensitivity to $k$ (number of retrieved neighbors) not thoroughly explored.** The paper uses $k=128$ for 184M models and $k=32$ for 37M models, but there is no sweep or ablation showing how performance varies with $k$. This matters because $k$ controls the tradeoff between retrieval coverage and distraction — too small and useful keys are missed; too large and the softmax is diluted.

**No latency or throughput measurements.** The paper uses exact kNN search via FAISS, which has computational cost that scales with the memory size. Dense attention over 256K tokens (as used in LONGLLAMA) has quadratic cost in the memory size. Neither latency nor throughput is reported for any configuration, making it impossible to assess the practical deployment cost of the method. The authors acknowledge that "storing more than 16M (key, value) pairs will require a distributed multi-node system" (Section 6), suggesting that practical scaling beyond the reported experiments faces significant engineering hurdles.

**Positive attention mass $r_d$ is measured at the layer level, not per-head.** The paper reports $r_d$ as an aggregate metric, but attention patterns can vary significantly across heads. Some heads might be highly document-discriminative while others remain distracted — the aggregate metric could mask this heterogeneity. A per-head breakdown would provide a richer picture of the learned key space structure.

**The dictionary lookup task uses random keys and values.** While this isolates retrieval capability, it removes any semantic signal that might help or hinder retrieval in real text. Real documents have topical coherence, semantic overlap, and polysemy — a key from one document might be legitimately similar to a query from another document because they discuss the same topic. The dictionary lookup task does not test whether FOT can distinguish *semantically* similar but *documentally* distinct keys, which is the harder and more realistic version of the distraction problem.

## 6. Limitations and Trade-offs

### The Difficulty Estimation Cost Is Not Accounted for in Practical Deployments

**The assumption or constraint.** The crossbatch training procedure requires that each batch index corresponds to a different document, and that document identity is preserved across consecutive training steps so that the previous context can be associated with the current context of the same document. For fine-tuning pre-trained models (LONGLLAMA), this requires assembling a training corpus where documents are long enough to span multiple context windows, or artificially concatenating short documents. The paper addresses this constraint directly in Appendix A.3: "In case one document is too short to span across several contexts for crossbatch, then we concatenate it with the next document from the dataset." This concatenation means the model's "positive" crossbatch keys may actually come from a *different* document — semantically, a false positive. The paper does not measure how often this occurs or what effect it has on the learned key space structure.

**The consequence.** When training documents are concatenated, the crossbatch procedure loses the guarantee that "positive" keys (those from the same batch index in the previous context) are semantically related to the current query. The model may learn to associate keys that are actually from unrelated documents as if they were from the same document, which could weaken the document-discriminative structure that crossbatch is designed to create. This is particularly concerning for datasets like C4, where documents are often short (the paper explicitly filters out documents shorter than 1K–4K tokens for some subsets of the LONGLLAMA fine-tuning mixture, Table 4). Practitioners fine-tuning on their own corpora — which may consist primarily of short documents — may get weaker results than the paper reports if their data cannot be made to satisfy the crossbatch assumptions.

**What evidence exists in the paper.** The paper does not quantitatively measure the impact of document concatenation on key space structure or downstream performance. The filtering thresholds in Table 4 indicate the authors are aware of the issue (documents shorter than 1K–4K tokens are excluded from some subsets), but no ablation compares concatenated vs. naturally long documents. The dictionary lookup task (Appendix F, Figure 10) uses synthetic documents of exactly 512 tokens where the document structure is perfectly controlled — this tells us nothing about what happens with concatenated real documents. The multi-document PG-19 experiments (Section 5.3, Figure 8) use books, which are naturally long documents — again, a best-case scenario that may not generalize.

**Mitigation status.** Partially addressed through document length filtering (Table 4), but the filtering thresholds vary by subset and the concatenation fallback is described without any analysis of its frequency or impact. The authors do not frame this as a limitation or suggest alternatives (e.g., using document boundary tokens to signal concatenation points to the model). A practitioner would need to independently verify that their corpus satisfies the crossbatch assumptions.

---

### No Multi-Document Downstream Evaluation Exists for the Core Distraction Claim

**The assumption or constraint.** The entire motivation for FOT — the distraction issue, the contrastive-inspired crossbatch training, the multi-document memory setting — is built on the premise that real-world applications involve *multiple documents* mixed in context, and that standard models fail in this setting because they cannot distinguish relevant from irrelevant keys. Yet **every downstream task used to evaluate LONGLLAMA's practical capabilities uses single-document contexts.** TREC (Section 4.4) provides demonstrations from a single training set; WebQS (Section 4.4) provides question-answer pairs; Qasper (Section 4.6, Appendix A.5) provides a single research paper; passkey retrieval (Section 4.2) embeds a single passkey in a long string of filler text. None of these tasks require the model to focus on one document while ignoring others in the same context.

**The consequence.** The paper's strongest practical claim — that FOT "addresses the distraction issue" and enables effective use of long contexts in multi-document scenarios — is supported only by perplexity measurements on language modeling datasets (PG-19, Figure 8) and synthetic retrieval tasks (dictionary lookup, Figure 10; passkey retrieval, Figure 1). Perplexity improvements do not necessarily translate to better performance on generative or discriminative tasks in multi-document settings. A model could have lower perplexity (better next-token prediction on the current document) while still failing to answer questions about the current document when other documents are present, or generating responses that blend content from multiple documents. The dictionary lookup and passkey tasks test pure retrieval — finding a specific token or sequence among distractors — not the kind of multi-document reasoning (synthesis, comparison, question-answering with selective focus) that motivates the work.

**What evidence exists in the paper.** The multi-document perplexity experiments (Figure 8, Section 5.3) show that FOT with high $d$ maintains near-constant perplexity as memory grows to 500K+ tokens of mixed documents, while baselines degrade. This is evidence that the key space structure works for language modeling. The dictionary lookup task (Figure 10) shows near-perfect retrieval at 16M tokens. But the gap between these controlled measurements and real multi-document tasks is acknowledged only implicitly — the paper does not discuss what additional capabilities would be needed to demonstrate multi-document *task* performance, nor does it propose a benchmark for this purpose.

**Mitigation status.** Not addressed. The paper does not include a multi-document downstream task evaluation, does not frame this absence as a limitation, and does not propose such an evaluation as future work. Section 6 ("Limitations and Future Work") focuses on scaling engineering challenges (distributed kNN, larger $d$) and combining with other methods, not on the evaluation gap. A practitioner considering FOT for repository-level code generation or multi-document QA would need to run their own multi-document task evaluations, as the paper provides no evidence that the perplexity gains translate to those settings.

---

### The Method Has Not Been Demonstrated Beyond the LLaMA Model Family

**The assumption or constraint.** The LONGLLAMA results — which are the paper's primary evidence of practical impact — use OpenLLaMA-3B and OpenLLaMA-7B as base models (Section 4.1). OpenLLaMA is a specific architecture with rotary positional embeddings (RoPE), pre-normalization with RMSNorm, SiLU activations, and a SentencePiece tokenizer (Appendix A.1). The analysis experiments (Sections 5.2–5.5) use custom 184M and 37M Transformer models that differ from OpenLLaMA in several ways: they normalize keys and queries, use learnable attention temperature parameters, and — critically for the core mechanism — completely remove positional encodings from memory attention layers (Appendix B.1). LONGLLAMA, in contrast, retains RoPE for local context and encodes memory keys at position 0 (Appendix A.2). These architectural differences mean the analysis experiments and the LONGLLAMA results were conducted on models that handle positional information differently in their memory layers. The paper states in Section 3.1: "We remove positional encodings in memory layers in all our models except LONGLLAMAs," acknowledging the difference but not exploring its implications.

**The consequence.** It is unclear whether FOT's extrapolation capabilities depend on the specific absence of positional encodings in memory layers (as in the analysis models) or are compatible with RoPE-style encodings (as in LONGLLAMA). If the key space structure learned through crossbatch interacts with positional encodings — for example, if RoPE embeddings in the local context create position-based shortcuts that interfere with content-based retrieval — then applying FOT to non-LLaMA architectures (GPT, PaLM, Falcon) might yield different results. The paper's claim that FOT is a "plug-and-play extension of transformer models" (Section 3) is supported by evidence from only one model family (LLaMA) at practical scale, and from custom models that differ architecturally from that family. A practitioner using a different base model would need to determine whether to follow the analysis-model approach (remove positional encodings from memory layers) or the LONGLLAMA approach (retain them), without guidance from the paper on which choice is better or why.

**What evidence exists in the paper.** The analysis models (no positional encodings in memory layers) achieve strong extrapolation: 64K context on language modeling (Table 3), 16M tokens on dictionary lookup (Figure 10). The LONGLLAMA models (RoPE in local context, position-0 for memory keys) achieve 256K on passkey retrieval (Figure 1) and 8K on downstream tasks (Tables 1, 2). Both configurations work, but there is no head-to-head comparison — no experiment tests the same model with and without positional encodings in memory layers to determine whether the choice matters. The paper's only comment on this tradeoff is pragmatic: "we retain the positional encodings in the local context of the memory layers... this makes our checkpoints fully compatible with any existing LLaMA inference codebase" (Section 4.1). Backward compatibility, not performance, drove the choice.

**Mitigation status.** The paper acknowledges the architectural difference (Section 3.1, Appendix A.2) but does not treat it as a limitation or propose systematic investigation. Section 6 suggests combining FOT with other methods but does not mention testing across model families. A practitioner would need to treat the LLaMA-specific findings as potentially non-transferable without independent verification.

---

### Inference-Time Computational Overhead Is Neither Measured nor Characterized

**The assumption or constraint.** FOT adds inference-time computation that the paper does not quantify. For the analysis models (Sections 5.2–5.5), each memory attention layer performs kNN search over a FAISS index at every query, plus additional attention computation over the $k$ retrieved entries. For LONGLLAMA (Section 4.1), kNN is replaced with "dense attention over the whole memory" — meaning that at inference time with 256K tokens of memory, each memory attention layer computes attention over a 256K × query_length attention matrix. The computational cost of this operation is not reported anywhere in the paper. Memory storage costs are also unquantified: storing (key, value) pairs for 256K tokens across multiple layers requires substantial GPU memory, but no memory footprint numbers are provided.

**The consequence.** The paper's headline results — 256K context on passkey retrieval, 16M tokens on dictionary lookup — are presented as accuracy numbers without any corresponding latency, throughput, or memory cost. A practitioner deciding whether to deploy FOT cannot answer basic questions: How much slower is inference with 256K memory vs. 2K memory? What is the GPU memory requirement for storing 16M (key, value) pairs? How does the cost scale with the number of memory attention layers? The paper itself acknowledges that scaling up faces engineering challenges: "storing more than 16M (key, value) pairs will require a distributed multi-node system" and "Using approximate kNN search will require a lot of engineering effort" (Section 6). These acknowledgments confirm that the reported results represent a best-case scenario (exact kNN on a single machine) that cannot scale further without significant infrastructure investment, but the concrete costs of even the reported results remain unknown.

**What evidence exists in the paper.** None. The paper reports no latency, throughput, FLOP counts, or memory usage for any inference configuration. Appendix I describes the hardware used (TPUv2/TPUv3 with 64GB/128GB device memory) but does not specify memory utilization. The dictionary lookup experiment (Figure 10) uses a FAISS index with 16M entries, but the time to build, query, or store this index is not given. The authors do note that using approximate kNN would be necessary for scaling beyond their experiments (Section 6: "In our experiments, we use the exact kNN search, which is not scalable to large memory"), so they are aware of the scaling challenge, but the cost at the reported scales is left unspecified.

**Mitigation status.** The paper explicitly identifies this as a limitation for future scaling (Section 6: "Scaling up context — The challenges start from purely engineering, storing more than 16M (key, value) pairs will require a distributed multi-node system... Using approximate kNN search will require a lot of engineering effort, as well as careful evaluation of the impact of the approximation on the model performance.") However, it does not report the computational cost at the scales it *has* tested, leaving practitioners without even a baseline to extrapolate from. The use of dense attention in LONGLLAMA (rather than kNN) compounds this opacity — dense attention over 256K tokens is expensive, and whether it was used for the 256K passkey evaluation or only for shorter contexts is not clarified.

---

### The Positive Attention Mass Metric ($r_d$) Is Reported Only at Aggregate Level and for a Single Layer Configuration

**The assumption or constraint.** The paper's core diagnostic for the distraction issue — the positive attention mass $r_d$ (Section 3.3, Figure 3) — measures the fraction of attention weight allocated to same-document keys when $d$ documents are present in the crossbatch context. This metric is reported for FOT trained with different $d$ values and for a standard Transformer baseline. However, the paper presents this metric only at the **aggregate level** (averaged across all attention heads in the memory layer, and across all queries and documents in the evaluation set) and only for a **single layer configuration** (layer 8 of a 12-layer model). The experiments that follow (Sections 5.2–5.5, Tables 1–3, Figures 8–10) use different model configurations — different numbers of memory layers, different layer indices, different model sizes — but $r_d$ is never re-measured for these configurations.

**The consequence.** The $r_d$ metric is the paper's primary evidence that FOT's key space structure is document-discriminative and that increasing $d$ during training reduces distraction. If this effect varies across attention heads (some heads become highly discriminative while others remain undifferentiated), the aggregate metric could mask that the model achieves focus through a small subset of specialized heads while others remain distracted — which might limit how well the structured key space generalizes to novel document types or tasks. More importantly, $r_d$ is never measured for the LONGLLAMA models (which use three memory layers, not one, and retain positional encodings, unlike the analysis model used in Figure 3). The paper assumes — but does not demonstrate — that the same contrastive key-space structuring occurs in LONGLLAMA as in the smaller analysis models, despite the architectural differences.

**What evidence exists in the paper.** Figure 3 provides $r_d$ for four configurations: "FoT d=2→64", "FoT d=8", "FoT d=1", and "Transformer" — all using a 12-layer model with a single memory attention layer at index 8. No per-head breakdown is provided. No $r_d$ measurement is reported for LONGLLAMA (3B or 7B), which use three memory layers each (layers {6, 12, 18} for 3B; {8, 16, 24} for 7B) and retain positional encodings. The paper does not discuss whether $r_d$ varies across layers or how the presence of multiple memory layers affects the aggregate attention mass.

**Mitigation status.** Not addressed. The paper treats $r_d$ as a diagnostic that validates the approach in a controlled setting, then moves to downstream metrics (perplexity, accuracy) for the larger-scale experiments. The chain of evidence — crossbatch training → structured keys (as measured by $r_d$) → better retrieval (as measured by perplexity and accuracy) — is established only for the small-scale analysis model. For LONGLLAMA, the paper demonstrates the final link (better accuracy) but omits the intermediate diagnostic (key space structure). A practitioner trying to debug poor performance when applying FOT to a new model would lack the diagnostic tools to determine whether the crossbatch training is producing the intended key-space effect.

## 7. Implications and Future Directions

### How This Work Changes the Landscape

This paper shifts the framing of long-context scaling from a **positional encoding problem** to a **key space structure problem**. Before FOT, the dominant approach to extending Transformer context length treated the bottleneck as positional: the model cannot attend beyond its training length because positional encodings for those positions are out-of-distribution. Position Interpolation (Chen et al., 2023; kaiokendev, 2023) and Landmark Attention (Mohtashami and Jaggi, 2023) both operate within this paradigm, modifying or compressing positional information to stretch the context window. FOT demonstrates a radically different path: if the model produces content-discriminative keys, position becomes irrelevant for long-range attention — the model attends based on *what* tokens mean, not *where* they are. The 32× extrapolation (8K training → 256K inference on passkey retrieval, Figure 1) and 31,250× extrapolation (512 → 16M on dictionary lookup, Figure 10) would be impossible under the positional bottleneck view.

The magnitude of this shift is significant but incomplete. It is not yet a paradigm shift — the LONGLLAMA results are on one model family (LLaMA), one synthetic long-context task (passkey retrieval), and a handful of single-document downstream evaluations. But it is more than an incremental refinement because it provides both a **diagnostic** (the distraction issue, quantified by positive attention mass $r_d$) and a **mechanism** (crossbatch training) that were absent from prior work. The diagnostic alone is a contribution: Figure 3's demonstration that $r_d \approx 1/d$ for standard Transformers gives the field a concrete metric for a failure mode that was previously only vaguely intuited. Any future long-context method can be evaluated on whether it beats the $1/d$ baseline, and methods that don't address key space structure will necessarily fail at multi-document settings regardless of their positional encoding sophistication.

The paper also reconciles a tension in the Memorizing Transformer results. Wu et al. (2022) showed that kNN-augmented attention works well for single-document long contexts, but their method's performance in multi-document settings was never tested. The FOT analysis (Figures 5, 6; Appendix K, Tables 10, 11) reveals why: MT's non-differentiable memory training produces keys that are adequate for single-document retrieval (where all memory entries are relevant) but degrade sharply when irrelevant documents enter the memory. FOT resolves this by making the key space document-discriminative during training, and the experiments show that this single change — differentiability plus negatives — produces better perplexity than MT with 4× larger training memory (Table 11: FOT with 4K differentiable context outperforms MT with 16K non-differentiable memory). This explains why prior memory-augmented methods plateau: they were solving the *architecture* problem (how to attend over a large memory) without solving the *representation* problem (how to make the memory contents distinguishable).

Several research directions become more attractive in light of this work. **Content-based attention mechanisms** — not just kNN retrieval, but any form of learned sparsity or retrieval that depends on key similarity — now have a clear training recipe for making the key space suitable for that mechanism. **Fine-tuning existing models for long context** becomes a practical path rather than an architectural redesign: the LONGLLAMA results show that 1% of the original pretraining budget (10B tokens for a 3B model trained on 1T tokens) can add 256K context capability. This dramatically lowers the barrier to entry for long-context applications compared to training long-context models from scratch. **Multi-document evaluation** as a first-class benchmark requirement, rather than an afterthought, follows directly from the distraction issue diagnosis — the paper makes it clear that single-document evaluations are insufficient and provides the metric ($r_d$) to measure what single-document benchmarks miss.

Conversely, some directions become less attractive. **Pure positional encoding extrapolation**, without any mechanism for content-based discrimination, now faces a clear limitation: it can extend the context window but cannot solve the distraction issue, because attention will still spread uniformly across documents regardless of how positions are encoded. **Scaling training sequence length as the primary approach to long contexts** is also called into question — FOT achieves 256K inference context from 8K training context, suggesting that training on ever-longer sequences yields diminishing returns compared to training for better key discrimination on modest-length sequences. The MT scaling results in Appendix K (Table 10) reinforce this: going from 8K to 32K training memory yields only 0.002 perplexity improvement at 128K evaluation, while FOT's differentiable training with 4K context achieves better results than MT with 16K.

### Follow-Up Research This Work Enables

**Multi-document question answering with controlled distractors.** The paper's central claim — that FOT addresses the distraction issue — is validated only through perplexity and synthetic retrieval. A direct test would construct a QA dataset where the model must answer questions about Document A while Documents B–E (on unrelated topics) are also in memory. The key metric is whether answer accuracy degrades as the number of distractor documents increases, and whether FOT with high $d$ maintains accuracy while baselines (standard fine-tuning, MT) degrade. This experiment would close the gap between the perplexity results (Figure 8) and the practical multi-document scenarios that motivate the work. A strong follow-up would use a dataset like Qasper or NarrativeQA, partition the test documents into groups, and measure accuracy as a function of the number of off-topic documents simultaneously present in memory. The paper's own results predict that FOT's accuracy should remain flat while baselines approach chance, but this prediction is untested.

**Per-head analysis of key space structure in FOT models.** Figure 3 reports positive attention mass $r_d$ as an aggregate metric, masking potential heterogeneity across attention heads. A follow-up study would measure $r_d$ per head in each memory attention layer, asking: Do all heads become document-discriminative, or does the model achieve focus through a small subset of specialized heads? Are there heads that remain distracted ($r_d \approx 1/d$) even as the aggregate $r_d$ approaches 1.0? This matters because if discrimination is achieved by a minority of heads, the model's ability to handle novel document types or tasks may be brittle — removing or damaging those specific heads would collapse performance. The experiment requires instrumenting the attention computation to log per-head attention weights to documents, then computing $r_d$ per head during evaluation on the PG-19 multi-document setting from Section 5.3. A negative result (all heads contribute equally to discrimination) would strengthen confidence in the method's robustness; a positive result (discrimination is concentrated in a few heads) would suggest targeted regularization or pruning strategies.

**FOT applied to non-LLaMA architectures with systematic positional encoding comparison.** The analysis models (Sections 5.2–5.5) remove positional encodings entirely from memory layers; LONGLLAMA retains RoPE for local context and assigns position-0 to memory keys. The paper never compares these two approaches on the same model. A controlled experiment would take a single base model (e.g., a 184M Transformer), fine-tune it with FOT under three conditions — (a) no positional encodings in memory layers (analysis-model style), (b) RoPE with position-0 for memory keys (LONGLLAMA style), and (c) standard RoPE for all tokens — and measure perplexity and $r_d$ on both single-doc and multi-doc settings. This would determine whether the positional encoding choice matters for FOT's effectiveness and whether LONGLLAMA's approach of retaining RoPE for backward compatibility incurs a performance cost. A strong follow-up would also apply FOT to GPT-style architectures (learned positional embeddings) and report whether the method transfers or whether architectural assumptions limit its generality.

**Combining FOT with Position Interpolation or Landmark Attention.** The paper positions FOT as an alternative to positional-encoding-based context extension, but these approaches may be complementary. Position Interpolation extends the local context window (e.g., from 2K to 8K) while FOT extends the memory context (potentially to 256K+). A combined system would use a position-interpolated local context of 8K–32K tokens plus a FOT memory of 256K+ tokens. The key question is whether the local context extension (via positional encoding) and the memory extension (via key space structure) provide additive benefits, or whether they interfere — for example, if the position-interpolated local context causes the model to prefer local keys over memory keys even when the memory contains more relevant information. The experiment would fine-tune LONGLLAMA with Position Interpolation on the local context, then evaluate on tasks requiring both recent context (within the extended local window) and distant context (in memory), measuring whether accuracy improves over FOT alone.

**Approximate kNN impact on FOT retrieval quality.** The paper uses exact kNN search via FAISS and acknowledges that "approximate kNN search will require a lot of engineering effort, as well as careful evaluation of the impact of the approximation on the model performance" (Section 6). A systematic study would replace exact kNN with approximate nearest neighbor methods (e.g., HNSW, IVFPQ, SCANN) at various recall levels (90%, 95%, 99%, 99.9%) and measure the impact on perplexity and task accuracy for LONGLLAMA on passkey retrieval and TREC. The practical question is: what recall level is sufficient such that the approximate search does not degrade model performance? This is essential for scaling FOT to billion-scale memories, where exact kNN becomes infeasible. The paper's dictionary lookup results (Figure 10, 92% accuracy at 16M tokens with exact kNN) provide the baseline; a follow-up would show how that curve shifts under approximation. A negative result — even 99.9% recall degrades performance — would indicate that FOT's key space is structured such that the exact ranking matters, requiring more sophisticated approximate retrieval.

**Training a difficulty predictor for adaptive crossbatch dimension $d$.** The paper uses a fixed schedule for $d$ (start small, increase later) and notes that too-large $d$ early in training causes the model to ignore the additional context. A more adaptive approach would predict, per batch element, whether the model is successfully attending to positive keys and adjust $d$ dynamically — increasing $d$ when $r_d$ is high (model is focused) and decreasing it when $r_d$ drops (model is getting distracted). This is analogous to adaptive batch sizing in contrastive learning. The experiment would instrument the training loop to compute $r_d$ on a small validation set of multi-document contexts at regular intervals and use it to control $d$ via a simple PID controller or threshold-based rule. The metric would be whether adaptive $d$ achieves the same final perplexity as the best fixed schedule in fewer training steps, or achieves better final perplexity by avoiding periods where $d$ is too large or too small for the model's current key space quality.

### Practical Applications and Downstream Use Cases

**Repository-level code generation with FOT-augmented models.** A software development assistant needs to generate code in the context of an entire repository — thousands of files, millions of lines — where the relevant code for a given query (e.g., "add error handling to this function") is spread across a handful of files while the vast majority of the codebase is irrelevant. FOT's memory attention layers can store the entire repository as (key, value) pairs, and the document-discriminative key space ensures that kNN retrieval surfaces keys from the relevant files rather than random code. The dictionary lookup result (92% accuracy with 16M key-value pairs, Figure 10) provides an existence proof that the retrieval mechanism works at repository scale. The benefit over standard approaches (e.g., chunking the repository and feeding chunks into context) is that FOT does not require pre-segmenting the codebase or deciding in advance which chunks are relevant — the model retrieves based on semantic similarity of keys, which can span file boundaries and surface cross-file dependencies that fixed chunking would miss. A deployment would use approximate kNN (since exact search over millions of code tokens is impractical) and would need to balance retrieval latency against accuracy, informed by the approximate kNN study proposed above.

**Long-document question answering with multi-document memory persistence.** In legal, medical, or academic research settings, a user may query across dozens or hundreds of documents — contracts, clinical trial reports, journal articles — asking questions that require synthesizing information from one document while the others remain in memory. FOT's multi-document mode (where memory persists across documents without clearing) directly supports this scenario. The Qasper results (Table 6: LONGLLAMA-3B improves from 18.7% at 2K to 26.6% at 8K) show that the model benefits from additional single-document context. The multi-document perplexity results (Figure 8: FOT $d=2\rightarrow 64$ maintains near-constant perplexity from single-document to 500K+ tokens of mixed documents) suggest that this benefit would extend to the multi-document case, though as noted in Section 6, this has not been directly tested with a QA task. A production system would load all relevant documents into memory once, then answer multiple user queries without re-indexing, amortizing the memory population cost across queries. The 73% passkey retrieval at 256K (Figure 1) indicates that the memory can hold approximately 6–8 full-length research papers (at ~30K–40K tokens each) with reliable retrieval of specific facts.

**Fine-tuning existing domain-specific models for long-context capability.** Organizations that have fine-tuned LLaMA (or LLaMA-derived models) on proprietary data — legal documents, medical records, internal codebases — can apply the LONGLLAMA fine-tuning recipe to extend context length without retraining from scratch or losing domain adaptation. The LM Evaluation Harness results (Table 5: identical average scores between OpenLLaMA and LONGLLAMA on short-context tasks) provide evidence that FOT fine-tuning preserves existing capabilities. The 10B-token fine-tuning budget for the 3B model (1% of pretraining) is within reach of organizations with modest GPU resources — it represents roughly 10–20 hours on 8× A100 GPUs, based on the training throughput implied by the 256K batch size. The backward compatibility (LONGLLAMA checkpoints work with any LLaMA inference code) means the long-context capability can be deployed incrementally — existing pipelines continue to work with the original context length, while new pipelines can activate the memory attention code for long-context queries. A practical deployment would fine-tune on the domain-specific corpus using the RedPajama mixture proportions in Table 4 as a starting point, substituting domain data for the general subsets while keeping the long-context subsets (arxiv, books) for crossbatch document diversity.

**Retrieval-augmented generation with learned retrieval structure.** In standard RAG pipelines, documents are retrieved by a separate embedding model (e.g., a fine-tuned BERT or a generic text embedding API), and the LLM processes the retrieved chunks without any control over how retrieval is performed. FOT's end-to-end differentiable key space means the LLM *itself* determines which documents are retrievable — the key representations are optimized jointly with the language modeling objective through the crossbatch procedure. This could enable RAG systems where the retrieval index is built from the LLM's own keys, making retrieval naturally aligned with what the model finds useful for generation. The FOT architecture already implements this: the FAISS index stores the model's own (key, value) pairs, not external embeddings. A practical system would fine-tune the LLM with FOT on the target document collection, build the FAISS index from the fine-tuned model's memory layers, and use the model for both retrieval (via kNN) and generation — eliminating the external retriever component entirely. The benefit over standard RAG is that retrieval and generation share the same representation space, avoiding the mismatch that occurs when a separately-trained retriever surfaces documents that the generator cannot effectively use.
