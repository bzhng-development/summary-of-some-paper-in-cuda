# Reducing Transformer Key-Value Cache Size with Cross-Layer Attention

**ArXiv:** [2405.12981](https://arxiv.org/abs/2405.12981)

## 🎯 Pitch

This paper introduces **Cross-Layer Attention (CLA)**, a modification to the transformer architecture that reduces the size of the key-value (KV) cache by sharing key and value activations across adjacent layers (e.g., a CLA2 configuration where every pair of consecutive layers reuses the same KV projections).

---

## 1. Executive Summary

This paper introduces **Cross-Layer Attention (CLA)**, a modification to the transformer architecture that reduces the size of the key-value (KV) cache by sharing key and value activations across adjacent layers (e.g., a CLA2 configuration where every pair of consecutive layers reuses the same KV projections). Through extensive pretraining experiments on 1B- and 3B-parameter models trained on the SlimPajama dataset, the authors demonstrate that combining CLA with Multi-Query Attention (MQA) achieves a 2× reduction in KV cache size while incurring only a minimal perplexity degradation of less than 1% relative to an unmodified MQA baseline (e.g., a 3B-parameter CLA2 model with `dhead = 64` achieves 12.99 Wikitext perplexity versus 12.94 for the baseline at half the cache footprint). The CLA family advances the accuracy/memory Pareto frontier over traditional MQA and GQA architectures, establishing that cross-layer KV sharing provides robust benefits specifically when applied with a sharing factor of 2 and combined with MQA rather than GQA.

## 2. Context and Motivation

### The Core Problem: The KV Cache Is a Memory Bottleneck at Scale

The fundamental problem this paper addresses is a systems-level constraint in deploying transformer-based large language models: **the key-value (KV) cache consumes memory proportional to both the number of layers and the sequence length**, and this overhead has become one of the dominant bottlenecks in serving LLMs at long contexts or large batch sizes.

To understand why this matters, we need to recall how autoregressive decoding works in transformers. During inference, the model generates tokens one at a time. At each step, it computes attention between the current token's query vectors and the key/value vectors of all previous tokens. Naively, this would require recomputing the keys and values for all previous tokens at every step — an $O(n^2)$ operation. The standard optimization — introduced in the original transformer paper (Vaswani et al., 2017) — is to **cache** the key and value activations from each layer once they are first computed, so that future decoding steps only need to compute the new token's K/V and then attend over the cached history. This KV cache avoids redundant computation but introduces a memory cost that grows linearly with sequence length and with the number of transformer layers.

For a transformer with $L$ layers, $H$ distinct key/value heads per layer, and embedding dimension $d_{\text{head}}$ per head, the KV cache stores $2 \cdot L \cdot H \cdot d_{\text{head}}$ elements **per token** (a factor of 2 for keys and values). At 16-bit precision, this means a 20-layer model with 16 heads and $d_{\text{head}} = 128$ stores 163,840 bytes per token — roughly 164 KB. For a 2,048-token sequence, that is approximately 336 MB for a single sequence. At batch size 64, this balloons to over 21 GB, competing directly with model weights and activations for scarce GPU memory.

The authors highlight three concrete pain points that make KV cache memory a first-order concern (Section 1):

- **Batch size limitations at long sequence lengths.** As Chowdhery et al. (2022) observed in training PaLM, the KV cache can limit batch sizes when operating on long sequences, directly reducing throughput in serving systems. Every generation in every layer adds to the cache, and memory pressure forces operators to reduce parallelism.

- **Expensive offloading for memory-constrained deployments.** Sheng et al. (2023) demonstrated that on-device or single-GPU inference with large models at long contexts often requires offloading KV cache entries to CPU or disk, incurring significant latency penalties. The cost of storage directly determines the cost of retrieval in such systems.

- **Persistent KV caches for multi-turn applications.** Emerging use cases described by Gao et al. (2024) and Google's Context Caching feature (2024) involve persisting KV caches over long periods — across multi-turn conversations, document editing sessions, and retrieval-augmented generation workloads — to avoid recomputing the same prefixes. In these settings, the KV cache transitions from a transient inference cost to a **persistent storage cost**, and its size directly determines the infrastructure cost of maintaining state for millions of concurrent users.

A critical subtlety that the paper makes explicit: as new applications demand increasingly long sequence lengths (document-level understanding, long-form code generation, multi-hour conversational agents), the KV cache bottleneck becomes **super-linear** in practical impact. Memory pressure forces smaller batch sizes, which reduces GPU utilization; it forces offloading, which increases latency; it forces cache eviction, which discards useful context. The KV cache size is therefore not just a minor inefficiency — it is a hard constraint on the design space of deployable language models.

### Where Existing Approaches Fall Short

Prior to this work, the research community had explored three broad categories of interventions for KV cache reduction, each with distinct limitations:

**1. Post-hoc compression (quantization and sparsification).** Works like KVQuant (Hooper et al., 2024) and Coupled Quantization (Zhang et al., 2024) apply precision reduction and non-uniform encoding to compress existing KV caches to as low as 1-2 bits per element. Sparsification methods like $H_2O$ (Zhang et al., 2023), Scissorhands (Liu et al., 2023), and FastGen (Ge et al., 2024) selectively evict tokens deemed unimportant based on heuristics like attention score magnitude or recency. While these methods can be applied to already-trained models without retraining, they share a fundamental limitation: **they are lossy at the representation level**. Quantization introduces accumulated numerical error that can degrade output quality at extreme compression ratios, and eviction heuristics are imperfect — important tokens can be incorrectly discarded, particularly in tasks requiring long-range reasoning or precise factual recall across many tokens. Moreover, these methods apply compression *after* the full KV cache has been materialized, meaning that peak memory usage during computation is not necessarily reduced unless the compression is applied eagerly.

**2. Architectural changes that reduce effective sequence length.** Methods like sliding window attention (Child et al., 2019; Dai et al., 2019) limit attention to a fixed window of recent tokens, reducing the KV cache to only that window's size. Infini-attention (Munkhdalai et al., 2024) compresses older tokens into a fixed-size representation using linear attention. Retrieval-based approaches like Memorizing Transformers (Wu et al., 2022) and Landmark Attention (Mohtashami and Jaggi, 2023) perform attention over a smaller retrieved subset of tokens rather than the full history. The limitation of these approaches is that they **reduce the model's ability to condition on distant context**. While successful for many tasks, they fundamentally limit the model's effective context window — a property that many applications (document summarization, long-form instruction following, in-context learning with many examples) critically depend on.

**3. Replacing softmax attention entirely.** State-space models (Gu and Dao, 2023), linear attention variants (Katharopoulos et al., 2020), and architectures like RWKV (Peng et al., 2024) replace the quadratic softmax attention mechanism with alternatives that have constant memory complexity w.r.t. sequence length. These approaches eliminate the KV cache entirely but require **entirely different model architectures** not directly compatible with the dominant transformer-based LLM ecosystem (Llama, GPT, PaLM families). For practitioners invested in the transformer architecture and its pre-trained model zoo, these alternatives represent a multi-year migration path rather than an incremental optimization.

**4. Query-side KV sharing (MQA and GQA).** The most directly relevant prior work, and the foundation on which this paper builds, is Multi-Query Attention (Shazeer, 2019) and its generalization, Grouped-Query Attention (Ainslie et al., 2023b). In standard Multi-Head Attention (MHA), each query head attends over its own distinct key/value head. This means the KV cache stores $H_{\text{query}}$ distinct key/value head tensors per layer. MQA makes the radical simplification: **all query heads share a single key/value head**, reducing the number of distinct KV heads per layer from $H_{\text{query}}$ to 1 — a factor equal to the number of query heads. GQA interpolates between MHA and MQA by grouping query heads into $G$ groups, each sharing one KV head, reducing heads by a factor of $H_{\text{query}} / G$.

MQA and GQA represent the most successful architectural interventions for KV cache reduction to date. They are **lossless in sequence length** (the full context is preserved in the shared KV heads), are **fully compatible** with dense transformer architectures, and incur only modest accuracy degradation. Many production LLMs — including the Llama 2 series (Touvron et al., 2023) and PaLM (Chowdhery et al., 2022) — have adopted GQA for precisely this reason.

However, MQA and GQA operate **within each layer independently**. They share KV heads across query heads within a single attention block, but every layer still computes and stores its own distinct KV activations. The size of the KV cache still scales linearly with the number of transformer layers:

$$\text{KV cache size} \propto L \times G \times d_{\text{head}}$$

where $L$ is the number of layers and $G$ is the number of GQA groups ($G = 1$ for MQA). MQA and GQA reduce the per-layer factor $G \times d_{\text{head}}$, but the $L$ factor — the number of distinct layer-level KV caches — remains untouched.

### The Unexplored Dimension: Cross-Layer Sharing

The paper's core insight is that **the number of distinct layer-level KV caches, $L$, is itself an optimizable dimension**. Just as MQA demonstrated that multiple query heads can share a single KV head within a layer without catastrophic accuracy loss, the authors hypothesize that adjacent layers can share KV activations *across* layers without catastrophic accuracy loss. This is not an obvious hypothesis. Different transformer layers are known to serve different functional roles: lower layers tend to encode local syntactic patterns, middle layers encode higher-level semantic structure, and upper layers specialize in task-specific representations. Sharing KV activations across layers means forcing, say, layer 7 to attend using the same key/value representations computed by layer 6 — representations that were produced from layer 6's hidden states, not layer 7's. The open question is whether the attention mechanism is sufficiently robust to this cross-layer constraint.

This unexplored dimension is orthogonal to MQA/GQA. MQA reduces the per-layer factor $G$ (from $H_{\text{query}}$ down to 1); CLA reduces the per-model factor $L$ (from the total number of layers down to $L / S$ where $S$ is the sharing factor). The two are **composable**: a model can simultaneously use MQA (one KV head per layer) and CLA2 (one KV cache shared between every pair of layers), reducing the total KV cache size to:

$$\text{KV cache size} \propto \frac{L}{S} \times 1 \times d_{\text{head}}$$

where both reductions multiply. For a model with $L = 20$, $H_{\text{query}} = 16$, and $d_{\text{head}} = 128$, traditional MHA requires $20 \times 16 \times 128 = 40,960$ elements per token. MQA alone reduces this to $20 \times 1 \times 128 = 2,560$. CLA2 further reduces it to $10 \times 1 \times 128 = 1,280$ — a total factor of 32× from MHA or 2× from MQA alone.

### How This Paper Positions Itself

The paper explicitly frames CLA as filling a gap in the design space of efficient attention architectures. The introduction (Section 1) positions the contribution as extending the MQA/GQA lineage **along a new axis**:

> "In this paper, we introduce a method for reducing the size of the KV cache along a dimension different than those explored in prior work: namely, reducing the number of unique layers in the KV cache."

This is more than a rhetorical framing device. The paper's experimental design reflects a specific hypothesis: that CLA combined with MQA (rather than CLA combined with GQA or MHA) will yield the best accuracy/memory tradeoffs, because MQA already demonstrates that aggressive KV sharing within a layer is viable, and cross-layer sharing extends the same principle between layers. This is why the paper's central results (Figure 3, the Pareto frontier) focus on MQA-CLA2 models and why CLA2 with GQA does not provide the same consistent advantage (Table 1: GQA4-CLA2 at `dhead = 256` matches baseline GQA4 perplexity but does not improve on it, and GQA2-CLA2 at `dhead = 128` achieves a perplexity of 13.59 vs. MQA-CLA2's 13.60 at the same 10,240 bytes/token — essentially identical, suggesting GQA adds no benefit beyond MQA when combined with CLA).

The paper also positions itself relative to the broader landscape of KV cache optimization (Section 5). Unlike post-hoc compression methods, CLA is an **architectural change applied at training time** — it produces models that natively require less KV cache memory without any runtime compression overhead or lossiness. Unlike sequence-length-reducing methods, CLA preserves the full context window. And unlike SSM-style alternatives, CLA operates within the standard dense transformer framework, making it a drop-in modification for existing codebases and training pipelines. The cost is modest: a slight reduction in total parameters (because fewer key/value projection matrices exist), a slight reduction in training FLOPs (for the same reason), and — crucially — **no direct effect on the core attention latency** during decoding, since even shared KV caches must be separately re-read from memory in each attention layer.

A subtle but important design choice that reflects the paper's positioning: the authors deliberately limit themselves to sharing patterns where layers reuse KV activations from **previous** layers in the forward pass (not future layers, and not learnable combinations of multiple layers). This causal constraint ensures that CLA is compatible with autoregressive generation and with standard tensor parallelism approaches. The authors note that pipeline parallelism requires either keeping shared-KV layers in the same pipeline stage or communicating KV activations between stages — a manageable constraint that does not fundamentally break existing parallelism strategies.

## 3. Technical Approach

### 3.1 Reader Orientation

This paper proposes a modification to the transformer architecture — not a post-hoc compression technique or a new training algorithm — that reduces the memory footprint of the key-value cache during autoregressive decoding. The system being built is a transformer language model whose attention blocks are wired so that **adjacent layers reuse the same key and value activations** rather than each layer computing its own; this shared wiring pattern is introduced at architecture design time and the model is trained from scratch with it, producing a model that natively requires less KV cache memory because fewer layers contribute distinct entries to the cache. The problem it solves is the linear scaling of KV cache size with the number of transformer layers, and the shape of the solution is a hyperparameter called the **sharing factor** `$S$` that controls how many consecutive layers form a sharing group, with the default recommendation being `$S = 2$` (pairs of layers share one KV cache).

### 3.2 Big-Picture Architecture

A transformer with Cross-Layer Attention has the same high-level structure as a standard decoder-only transformer — a stack of `$L$` layers, each containing an attention block followed by a feed-forward network with residual connections and layer normalization — but with a critical internal rewiring:

- **KV Projection Layers (a subset):** Only a subset of layers contain key/value projection matrices (`$W_K$`, `$W_V$`). These layers compute fresh keys and values from their hidden states and contribute their KV activations to the KV cache. In a CLA2 configuration, this is every other layer (layers 0, 2, 4, ...).

- **KV Reusing Layers (the remainder):** The remaining layers contain no key/value projection matrices at all — they contain only query projection (`$W_Q$`) and output projection (`$W_O$`) in their attention blocks. At each forward pass, these layers fetch the KV activations from the most recent KV projection layer below them in the stack and perform attention using those *reused* keys and values against their own freshly-computed queries.

- **KV Cache (reduced):** The KV cache stores entries only for the KV projection layers, not for every layer. For a 20-layer model with CLA2, only 10 layers contribute to the cache, halving the total memory footprint relative to a standard architecture where all 20 layers store separate KV entries.

- **Learnable Per-Layer Normalization:** Even layers sharing the same KV activations maintain separately-learnable affine parameters in their layer normalization before the query projections and after the attention block, allowing each layer to learn different scaling and centering of the shared representations.

This architecture is orthogonal to MQA/GQA: the per-layer KV head count (1 for MQA, `$G$` for GQA) multiplies with the per-model layer count `$L/S$` to determine total cache size.

- **First, the connection to MQA and GQA:** I will explain precisely how MQA and GQA reduce KV cache size within a single layer, because CLA is a direct extension of the same principle — sharing KV heads — applied across layers rather than across query heads. Understanding MQA's mechanism makes CLA's mechanism immediately transparent.

This is primarily an **architectural innovation paper** whose core idea is that KV activations can be shared across adjacent transformer layers during both training and inference with minimal accuracy degradation, and that this sharing — when combined with MQA, which already shares KV heads across query heads within a layer — yields a new family of attention designs that Pareto-dominate existing MQA/GQA architectures on the accuracy-versus-KV-cache-memory frontier.

#### How MQA and GQA Reduce KV Cache Size Per Layer

To understand why CLA is a natural extension of MQA/GQA, we need to be precise about what MQA and GQA do inside a single attention layer. In standard Multi-Head Attention (MHA) as described by Vaswani et al. (2017), each layer computes:

For each of `$H$` attention heads:
- Query: `$Q_h = X W_Q^h$`
- Key: `$K_h = X W_K^h$`
- Value: `$V_h = X W_V^h$`

where `$X \in \mathbb{R}^{n \times d_{\text{model}}}$` is the input hidden state sequence (n tokens, each of dimension `$d_{\text{model}}$`), and `$W_Q^h, W_K^h, W_V^h \in \mathbb{R}^{d_{\text{model}} \times d_{\text{head}}}$` are head-specific projection matrices. The output for each head is `$\text{softmax}(Q_h K_h^T / \sqrt{d_{\text{head}}}) V_h$`, and the head outputs are concatenated and projected back to `$d_{\text{model}}$` through an output projection `$W_O$`.

In MHA, the KV cache at each layer stores, for every generated token `$t$`, `$H$` key vectors and `$H$` value vectors — one per head — each of dimension `$d_{\text{head}}$`. The total storage per token per layer is therefore:

$$2 \cdot H \cdot d_{\text{head}} \text{ elements}$$

where the factor of 2 accounts for both keys and values, `$H$` is the number of heads (which equals the number of query heads), and `$d_{\text{head}}$` is the per-head embedding dimension.

**Multi-Query Attention (Shazeer, 2019)** makes a single change to this design: instead of having `$H$` distinct key projection matrices `$W_K^h$` and value projection matrices `$W_V^h$` (one per head), MQA uses a **single shared** key projection `$W_K$` and a single shared value projection `$W_V$` for all heads. Formally, for all `$h \in \{1, \ldots, H\}$`:

- `$K = X W_K$` (shared across all heads)
- `$V = X W_V$` (shared across all heads)
- `$Q_h = X W_Q^h$` (still head-specific)

Each query head still computes its own query, but all heads attend over the same keys and values. The KV cache at each layer now stores, per token, only **one** key vector and **one** value vector (each still of dimension `$d_{\text{head}}$`), reducing the per-layer storage to:

$$2 \cdot 1 \cdot d_{\text{head}} \text{ elements}$$

a reduction by a factor of `$H$` (the number of query heads) compared to MHA. Shazeer found that this aggressive sharing incurs only a small degradation in model quality on machine translation and language modeling benchmarks, because the query projections retain enough head-specific flexibility to extract different information from the shared keys and values.

**Grouped-Query Attention (Ainslie et al., 2023b)** generalizes MQA by organizing the `$H$` query heads into `$G$` groups, where `$1 \leq G \leq H$`, and sharing one key/value head per group. The heads within each group `$g$` all share the same `$K_g = X W_K^g$` and `$V_g = X W_V^g$`. The KV cache size per layer becomes:

$$2 \cdot G \cdot d_{\text{head}} \text{ elements}$$

MHA is the special case where `$G = H$` (one KV head per query head); MQA is the special case where `$G = 1$` (one KV head for all query heads). GQA provides a continuous knob for trading off KV cache memory against attention expressivity: smaller `$G$` reduces memory and bandwidth but may reduce model quality.

**The critical observation for CLA:** MQA and GQA achieve their memory savings by **reducing the number of distinct KV heads within each layer**, but they leave the **number of layers that contribute to the KV cache** unchanged. Every layer still stores its own KV activations, even if those activations are now just one or a few heads. The total KV cache size for an `$L$`-layer model is:

$$\text{Total KV cache} = \sum_{l=1}^{L} 2 \cdot G_l \cdot d_{\text{head}} = 2 \cdot L \cdot G \cdot d_{\text{head}} \quad \text{(if G is constant across layers)}$$

The factor `$L$` — the number of distinct layer-level KV caches — is what CLA targets.

#### The Cross-Layer Attention Mechanism

CLA extends the sharing principle from the query-head dimension to the layer dimension. Instead of having every layer compute its own key and value activations, CLA designates only a **subset of layers** to compute KV projections; the remaining layers reuse the KV activations from the nearest KV-computing layer below them in the forward pass.

**Sharing factor and grouping.** The hyperparameter that controls CLA is the **sharing factor** `$S$`, which specifies how many consecutive layers form a sharing group. Layers within a group share a single set of KV activations. The paper defines three named configurations:

- **CLA2** (`$S = 2$`): Every group of 2 consecutive layers shares one KV cache. For a 20-layer model, layers are grouped as (0,1), (2,3), (4,5), ..., (18,19), with the first layer in each pair computing KV projections and the second layer reusing them. This yields `$L/S = 20/2 = 10$` distinct KV caches.

- **CLA3** (`$S = 3$`): Every group of 3 consecutive layers shares one KV cache. For a 20-layer model, this yields `$\lceil 20/3 \rceil = 7$` KV caches, though the last group contains only 2 layers since 3 does not evenly divide 20.

- **CLA4** (`$S = 4$`): Every group of 4 consecutive layers shares one KV cache, yielding 5 KV caches for a 20-layer model.

The sharing factor can be any integer from 1 (no sharing — traditional attention) up to `$L$` (all layers share a single KV cache). The paper explores `$S \in \{2, 3, 4\}$`.

**Which layers compute KV projections.** Within each sharing group, only the **first layer** (the lowest-indexed layer in the group) contains key/value projection matrices and computes fresh KV activations. The subsequent layers in the group (`$S-1$` of them) contain only query projection and output projection matrices. This design choice — having earlier layers produce KV activations consumed by later layers — respects the causal forward-pass dependencies: when layer `$l$` needs KV activations, they are already available from the layer `$l - (l \bmod S)$` that computed them earlier in the forward pass.

For example, in a CLA2 model with layers indexed 0 through 19:
- Layer 0 computes `$K_0, V_0$` from its hidden state and stores them in the KV cache; layer 1 fetches `$K_0, V_0$` from the cache (or from memory during training) and attends using its own queries.
- Layer 2 computes `$K_2, V_2$` and stores them; layer 3 uses `$K_2, V_2$`.
- And so on through layer 19, where layer 18 computes KV and layer 19 reuses it.

**What happens inside a KV-reusing layer.** Consider layer `$l$` in a sharing group whose KV projections live in layer `$l_{\text{kv}} < l$`. During the forward pass:
1. Layer `$l$` receives its hidden state input `$X_l$` (the output of the previous layer's feed-forward block plus residual).
2. It applies layer normalization with its own learnable affine parameters `$\gamma_l, \beta_l$` to produce `$\tilde{X}_l$`.
3. It computes its query projections: `$Q_l^h = \tilde{X}_l W_Q^{l,h}$` for each head `$h$` (or for each GQA group).
4. It fetches the key and value activations from layer `$l_{\text{kv}}$`: `$K_{l_{\text{kv}}}, V_{l_{\text{kv}}}$`. During training, these are the KV activations computed in the same forward pass by layer `$l_{\text{kv}}$`. During inference, they are read from the KV cache which was populated when layer `$l_{\text{kv}}$` processed the token.
5. It performs standard scaled dot-product attention: `$\text{Attention}(Q_l, K_{l_{\text{kv}}}, V_{l_{\text{kv}}}) = \text{softmax}(Q_l K_{l_{\text{kv}}}^T / \sqrt{d_{\text{head}}}) V_{l_{\text{kv}}}$`.
6. The head outputs are concatenated and projected through `$W_O^l$`, added to the residual stream, and passed through the feed-forward network as usual.

The crucial point: layer `$l$` has **no `$W_K^l$` or `$W_V^l$` matrices at all**. It cannot transform or adapt the KV activations it receives — it must use them exactly as they were computed by layer `$l_{\text{kv}}$`. The only per-layer flexibility comes from: (a) the layer normalization applied to `$X_l$` before the query projection, which can scale and shift the queries to better align with the shared keys, and (b) the query projections `$W_Q^{l,h}$` themselves, which can learn to extract different information from the same keys than layer `$l_{\text{kv}}$`'s query heads do. This is directly analogous to how MQA's multiple query heads learn to attend differently over a single shared set of keys.

**Learnable per-layer normalization.** The paper explicitly notes (Section 3.1) that CLA models use "separately-learnable affine layer-norm parameters for the KV projection blocks and Q projection blocks in attention." This means:
- Each KV-computing layer has its own learnable scale `$\gamma_{\text{kv}}$` and shift `$\beta_{\text{kv}}$` before its key/value projections.
- Each layer (whether KV-computing or KV-reusing) has its own learnable scale `$\gamma_q$` and shift `$\beta_q$` before its query projections.
- Each layer has its own learnable `$\gamma_{\text{out}}$` and `$\beta_{\text{out}}$` after the attention output projection but before the residual addition.

These per-layer normalization parameters allow KV-reusing layers to adjust the distribution of their queries to be compatible with shared keys computed from potentially different hidden state distributions.

**Positional embeddings.** The paper uses rotary position embeddings (RoPE; Su et al., 2023), which are applied directly to the query and key vectors. RoPE encodes position `$t$` by rotating pairs of dimensions in the query/key vector by angle `$\theta_t = t \cdot \omega$`, where `$\omega$` is a frequency determined by the dimension index. In a CLA model, when layer `$l$` reuses KV activations from layer `$l_{\text{kv}}$`, the keys in those activations were rotated with RoPE using the token positions at the time layer `$l_{\text{kv}}$` computed them — which is the correct positional encoding for the same tokens being attended to by layer `$l$`. No special handling of RoPE is required for CLA, because position is a property of the tokens, not of which layer is attending. This is a non-trivial compatibility point: CLA works with RoPE without modification because positional information is encoded in the keys themselves, not in which projection matrix produced them.

**How this differs from weight tying.** A natural question is whether CLA is equivalent to simply tying the `$W_K$` and `$W_V$` weight matrices across adjacent layers. It is not. Weight tying would mean layers 0 and 1 both have `$W_K$` and `$W_V$` matrices that are constrained to be equal, but they would each independently multiply those matrices by their own hidden states to produce keys and values — and since layers 0 and 1 have different hidden states (layer 1's input is layer 0's output), they would produce different KV activations despite sharing weights. CLA instead shares the **activations** themselves: layer 1 receives layer 0's post-projection keys and values, not the projection matrices. This is a stronger form of sharing because it constrains the representations, not just the parameters.

**How training works with CLA.** During training, the model processes the entire sequence in parallel (teacher forcing). The forward pass proceeds layer by layer:
1. Layer 0 receives the embedded input tokens `$X_0$`.
2. Layer 0 computes its queries, keys, and values, performs self-attention, applies the output projection and residual, then passes through the feed-forward network to produce `$X_1$` (the hidden state input to layer 1).
3. Layer 1 receives `$X_1$`, computes its layer normalization, computes its queries `$Q_1$`, but does **not** compute keys or values — it uses `$K_0, V_0$` which are still in memory from layer 0's computation. It performs attention, applies output projection and residual, then feed-forward to produce `$X_2$`.
4. Layer 2 receives `$X_2$`, computes its own `$Q_2, K_2, V_2$`, performs attention, and so on.

During the backward pass, gradients flow through the shared KV activations back to the layer that computed them. Layer `$l_{\text{kv}}$` receives gradient contributions from both its own attention computation (its queries attending over its own keys) and from all layers that reuse its KV activations. This means the KV projection matrices in a CLA model are trained to produce representations that are useful not only for the layer that computed them but also for potentially multiple downstream layers — a more demanding optimization problem that the paper's results show is nevertheless learnable.

#### KV Cache Structure Under CLA

The structure of the KV cache under CLA is simpler than under traditional attention: it is a dictionary mapping **layer indices that compute KV projections** to their key/value tensors, rather than having an entry for every layer.

**Cache population during autoregressive decoding.** Consider generating token `$t$` in a CLA2 model. The forward pass proceeds layer by layer:
- Layer 0 receives the embedding of token `$t$` and the hidden states from all previous tokens in its residual stream. It computes `$K_0[t], V_0[t]$` — the key and value for the new token — and appends them to its KV cache entry (which already contains keys and values for tokens `$0$` through `$t-1$`).
- Layer 1 receives `$X_1$`, computes its queries, and retrieves layer 0's full KV cache (now including token `$t$`) to perform attention. It produces its hidden state output without adding anything to the KV cache.
- Layer 2 computes `$K_2[t], V_2[t]$` and appends to its KV cache.
- Layer 3 uses layer 2's KV cache.
- And so on through all `$L$` layers.

Notice that after processing token `$t$`, the KV cache has grown by `$(L/S) \cdot 2 \cdot G \cdot d_{\text{head}}$` elements — one key and one value per GQA group per KV-producing layer — rather than `$L \cdot 2 \cdot G \cdot d_{\text{head}}$` which a traditional model would store.

**Cache sizing formula.** For a model with `$L$` layers, sharing factor `$S$`, `$G$` KV heads per KV-producing layer (1 for MQA, `$H/S$` for GQA, `$H$` for MHA), and per-head dimension `$d_{\text{head}}$`, the per-token KV cache size in elements is:

$$2 \cdot L_{\text{kv}} \cdot G \cdot d_{\text{head}}$$

where `$L_{\text{kv}} = \lceil L / S \rceil$` is the number of layers that compute KV projections, `$G$` is the number of distinct key/value heads per KV-producing layer, and `$d_{\text{head}}$` is the embedding dimension per head. The factor of 2 accounts for storing both keys and values. When `$S$` evenly divides `$L$`, this simplifies to `$2 \cdot (L/S) \cdot G \cdot d_{\text{head}}$`.

In 16-bit precision (2 bytes per element), the cache size in bytes per token is:

$$\text{Bytes per token} = 2 \cdot L_{\text{kv}} \cdot G \cdot d_{\text{head}} \cdot 2 \text{ bytes/element}$$

The paper reports this quantity in the "KV Bytes Per Token (16-Bit)" column of Tables 1, 3, 5, and 7. For example, the H128-MQA baseline (20 layers, MQA so `$G = 1$`, `$d_{\text{head}} = 128$`) computes: `$2 \cdot 20 \cdot 1 \cdot 128 \cdot 2 = 10{,}240$` bytes per token. The H128-MQA-CLA2 model (20 layers, CLA2 so `$L_{\text{kv}} = 10$`, MQA, `$d_{\text{head}} = 128$`) computes: `$2 \cdot 10 \cdot 1 \cdot 128 \cdot 2 = 5{,}120$` bytes per token — exactly half.

**Non-uniform sharing patterns.** The paper also explores three non-uniform CLA2 configurations (Table 1, bottom rows), where the sharing pattern is not a regular partition of consecutive pairs:

- **H128-MQA-CLA2-KeepEnds:** Layer 0 is unshared (it gets its own KV cache). Layers 1 and 2 share, 3 and 4 share, ..., 17 and 18 share, and layer 19 is unshared. This yields `$L_{\text{kv}} = 1 + 9 + 1 = 11$` KV caches. The motivation (not explicitly stated but implied) is that the first and last layers may learn unique representations that benefit from dedicated KV projections.

- **H128-MQA-CLA2-DenseFront:** The first 10 layers (0–9) each have their own KV cache (like traditional attention). Then layers 10 through 19 all share the KV activations of layer 9, except layer 19 which has its own KV cache. This yields `$L_{\text{kv}} = 10 + 1 = 11$` KV caches. The idea is to test whether clustering all shared layers at the end of the model is beneficial.

- **H128-MQA-CLA2-DenseBack:** Layers 0 and 1 each have their own KV cache. Then layers 2 through 11 all share the KV activations of layer 1. Finally, layers 12 through 19 each have their own KV cache. This yields `$L_{\text{kv}} = 2 + 1 + 8 = 11$` KV caches, testing the opposite clustering (shared layers concentrated earlier).

All three non-uniform patterns achieve worse perplexity than the uniform CLA2 pattern at the same KV cache footprint (Table 1: 13.62, 13.75, and 14.03 vs. 13.60 for uniform CLA2 at `$d_{\text{head}} = 128$`), suggesting that regular alternating sharing is the most effective pattern. The DenseBack configuration performs particularly poorly (14.03), indicating that concentrating shared KV projections in early layers and having many unshared later layers is detrimental — potentially because later layers need their own KV representations to perform task-specific attention patterns.

#### System-Level Implications of CLA

The paper is careful to enumerate what CLA does and does not affect from a systems engineering perspective (Section 2.3). This section is important because it clarifies that CLA is a targeted intervention — it primarily reduces KV cache memory and has only minor or zero effect on other resource dimensions.

**KV cache memory: primary benefit.** The KV cache memory footprint shrinks by a factor approximately equal to the sharing factor `$S$`. For CLA2, this is a 2× reduction; for CLA3, a 3× reduction (with slight loss due to uneven division); for CLA `$S$`, approximately `$S$`×. This is the headline benefit and the motivation for the entire approach.

**Training memory footprint: minor benefit.** During training, intermediate KV activation tensors are materialized for every layer, but for KV-reusing layers these are just references to the KV tensors of the layer that computed them, not separate allocations. However, the paper notes that "for GQA and MQA models such KV tensors are typically small compared to the model's hidden states and MLP activations," so the training memory reduction is modest — the dominant memory consumers during training are the hidden states (`$L \times d_{\text{model}}$` per token) and the feed-forward network activations (`$L \times 4 \cdot d_{\text{model}}$` with SwiGLU). CLA does not reduce these at all.

**Parameters and FLOPs: minor reduction.** Because CLA removes the key/value projection matrices (`$W_K$` and `$W_V$`) from `$L - L_{\text{kv}}$` layers, the total parameter count decreases slightly. The number of removed parameters per KV-absent layer is `$2 \cdot d_{\text{model}} \cdot (G \cdot d_{\text{head}})$` — the weights of the key and value projection matrices. For the 1B-scale models with `$d_{\text{model}} = 2048$`, MQA (`$G = 1$`), `$d_{\text{head}} = 128$`, and CLA2 (10 layers without KV projections), the parameters saved are approximately `$10 \cdot 2 \cdot 2048 \cdot 128 = 5.24$` million parameters out of 1 billion — about 0.5% of the total. The corresponding FLOP reduction during a forward pass is similarly small, as the key/value projections are cheap compared to the `$Q \cdot K^T$` computation in attention and the feed-forward network's `$d_{\text{model}} \to 4 \cdot d_{\text{model}}$` and `$4 \cdot d_{\text{model}} \to d_{\text{model}}$` projections. The paper does not explicitly compute these numbers but notes that the effect is "slight."

**Decoding latency: indirect benefit via larger batches.** CLA does not directly reduce the per-token decoding latency of the attention computation. The paper states:

> "Unlike MQA and GQA, CLA has no direct effect on the memory bandwidth consumed by the attention mechanism in each decoding step, because even shared KV cache layers must be separately re-read from main memory in each attention layer."

To understand why: in a standard transformer decoding step, each layer must read its entire KV cache from GPU memory to compute attention scores against the new query. In a CLA model, each layer still reads a KV cache from memory — it is just that for shared layers, the KV cache being read is the same physical tensor rather than a different one. But the memory bandwidth for reading that tensor is still consumed once per layer that uses it. So layer 1 reading layer 0's KV cache costs the same memory bandwidth as it would if it were reading its own (smaller) KV cache — the cache being read is the same size in either case (it stores keys for all previous tokens), but in CLA it is shared rather than duplicated. The bandwidth savings come from not having to *write* duplicate KV caches, not from reduced reading.

Where CLA *can* improve latency is indirectly: by reducing per-sequence memory footprint, it allows larger batch sizes before hitting GPU memory limits, which can increase throughput and reduce average latency under load. Similarly, it enables longer KV cache persistence without offloading, which reduces the frequency of expensive cache reloads.

**Model parallelism compatibility.** CLA is "fully compatible with standard tensor parallelism techniques (Shoeybi et al., 2020) for sharding model weights across multiple accelerators." Tensor parallelism splits the weight matrices within each layer across devices, and CLA does not introduce any cross-device dependencies that tensor parallelism cannot handle — the KV activations are communicated between devices within the same layer during attention (as in standard models), and the fact that some layers reuse others' KV activations does not affect the sharding pattern.

For pipeline parallelism (Huang et al., 2019), the paper notes a constraint: "either different layers which share a KV cache must be kept in the same pipeline stage, or else KV activations must be communicated between pipeline stages." This constraint arises because if layer 0 is in pipeline stage A and layer 1 is in pipeline stage B, then `$K_0, V_0$` must be transmitted from stage A to stage B, adding a cross-stage communication cost that pipeline parallelism is designed to minimize. The natural solution is to ensure that layers within a CLA sharing group always belong to the same pipeline stage — a mild scheduling constraint that is easy to satisfy when setting up the pipeline partition.

**Core attention latency: no direct effect.** As noted above, the raw attention computation — `$\text{softmax}(QK^T / \sqrt{d_{\text{head}}})V$` — is unchanged in cost. The `$Q$`, `$K$`, and `$V$` tensors have the same shapes as they would in an equivalent non-CLA model (same number of heads, same head dimension); the only difference is that `$K$` and `$V$` are computed by a different layer than the one using them. The arithmetic intensity and memory access pattern of the attention kernel itself is identical.

#### Training Infrastructure and Hyperparameters

The paper's experimental findings depend on a specific training setup, and these details matter for reproducibility and for understanding the scope of the results.

**Base architecture.** All models follow a Llama-like (Touvron et al., 2023) decoder-only transformer design with:
- **Pre-normalization:** Layer normalization is applied *before* the attention and feed-forward sublayers, not after (the original transformer applied it after). This is standard in modern LLM architectures and improves training stability.
- **SwiGLU activations (Shazeer, 2020; Ramachandran et al., 2017):** The feed-forward network uses a gated linear unit with Swish activation: `$\text{FFN}(x) = (W_2 \cdot \text{Swish}(W_1 x)) \odot (W_3 x)$`, where `$W_1, W_2, W_3$` are projection matrices and `$\odot$` is element-wise multiplication. This expands the hidden dimension to `$d_{\text{ff}} = 4 \cdot d_{\text{model}} / (2/3) \approx 5.33 \cdot d_{\text{model}}$`? No — the paper reports specific FFN sizes in Table 2: for 1B models, `$d_{\text{ff}} = 5472$` with `$d_{\text{model}} = 2048$` (ratio 2.67×); for 3B models, `$d_{\text{ff}} = 8192$` with `$d_{\text{model}} = 3072$` (also ratio 2.67×). This is smaller than the typical 4× expansion in many transformer implementations, which is standard for SwiGLU (which typically uses `$2/3 \times 4 = 8/3 \approx 2.67$` expansion to keep total parameters comparable to a 4×-expansion ReLU FFN, because SwiGLU has three weight matrices instead of two).
- **Rotary position embeddings (RoPE; Su et al., 2023):** Positional information is encoded by rotating query and key vectors in pairs of dimensions by angle proportional to the token position, rather than being added as learned or sinusoidal embeddings at the input. RoPE is applied within each attention head at every layer.
- **No dropout:** All models are trained with dropout probability 0.0. This is consistent with modern LLM pretraining practice, where dropout is often omitted because the massive scale of data provides sufficient regularization.
- **Learnable elementwise affine parameters for layer norm:** Each layer normalization module has learnable scale `$\gamma$` and shift `$\beta$` parameters. CLA models additionally have separate layer normalizations before KV projections and before Q projections.

**Architectural hyperparameters by scale (Table 2).**

| Hyperparameter | 1B Models | 3B Models |
|---|---|---|
| Hidden size `$d_{\text{model}}$` | 2048 | 3072 |
| Feed-forward size `$d_{\text{ff}}$` | 5472 | 8192 |
| Number of layers `$L$` | 20 | 32 |
| Sequence length | 2048 | 2048 |
| Training tokens | `$30 \times 10^9$` (30B) | `$100 \times 10^9$` (100B) |

The number of query heads `$H$` is set so that `$H \cdot d_{\text{head}} = d_{\text{model}}$`, meaning the concatenated head outputs exactly span the hidden dimension. For a model with `$d_{\text{head}} = 128$`, this gives `$H = 2048 / 128 = 16$` heads for 1B models and `$H = 3072 / 128 = 24$` heads (approximately — the paper would use 24 but Table 5's 3B model with `$d_{\text{head}} = 128$` implicitly has `$H = 24$` since `$24 \times 128 = 3072$`).

**Dataset.** All models are trained on SlimPajama (Soboleva et al., 2023), a cleaned and deduplicated 627-billion-token subset of the RedPajama corpus. Tokenization uses the GPT-NeoX tokenizer (Black et al., 2022) with Byte-Pair Encoding (BPE; Wang et al., 2019). Validation perplexity is measured on a held-out subset of approximately 4 million tokens from the same corpus. This is a standard open-source pretraining dataset, chosen to allow reproducible experiments without proprietary data.

**Optimizer configuration.** The paper uses AdamW (Loshchilov and Hutter, 2019) with:
- `$\beta_1 = 0.9$`, `$\beta_2 = 0.95$` (standard values)
- Weight decay factor of `$0.1$` (applied in the decoupled AdamW style, not as L2 regularization)
- Gradient clipping norm of `$1.0$` (gradients are scaled down if their L2 norm exceeds 1.0)
- Linear learning rate warmup for the first 5% of training examples
- Cosine learning rate schedule (Loshchilov and Hutter, 2017) decaying to 10% of the peak learning rate over the remaining 95% of training

The batch size is 2048 sequences, each of length 2048 tokens, giving approximately `$2048 \times 2048 = 4,194,304 \approx 4$` million tokens per training step. For 1B models trained on 30B tokens, this is `$30 \times 10^9 / 4.194 \times 10^6 \approx 7,150$` training steps.

**Weight initialization.** All linear layer weights are initialized from a normal distribution with mean zero and standard deviation `$0.01275$`. This is a small standard deviation appropriate for deep networks, chosen to keep initial activations well-scaled.

**Mixed precision.** Training uses mixed precision (Micikevicius et al., 2018) in BF16 (brain floating point 16-bit; Kalamkar et al., 2019) for forward and backward passes, with gradient all-reduce and gradient accumulation performed in FP32 for numerical stability. BF16 has the same exponent range as FP32 but only 7 bits of mantissa precision, making it less prone to overflow/underflow than FP16 while still reducing memory and bandwidth.

**Learning rate sweeps (Section 3.2.2 and Appendix A).** For selected models, the paper conducts learning rate optimization to verify that CLA's benefits persist when baselines are well-tuned. The protocol: starting from an initial learning rate of `$3 \times 10^{-4}$`, the learning rate is swept upward in multiplicative increments of 1.5× until validation perplexity stops improving. The learning rate that achieves the lowest validation perplexity is treated as the approximate optimum for that model architecture. This is important because CLA models might have different optimal learning rates than non-CLA models due to the reduced number of trainable parameters and the different gradient flow patterns through shared KV activations.

The paper finds:
- At 1B scale: H128-MQA optimal LR = `$1.5 \times 10^{-3}$`; H64-MQA optimal LR = `$2.25 \times 10^{-3}$`; H128-MQA-CLA2 optimal LR = `$2.25 \times 10^{-3}$`. The CLA2 model and the smaller-head baseline share the same optimal LR, while the larger-head baseline has a lower optimal LR. This suggests CLA models can tolerate (and benefit from) higher learning rates, possibly because the reduced parameter count provides implicit regularization or because the shared KV gradients are larger (receiving contributions from multiple layers).
- At 3B scale (first set): H128-MQA optimal LR = `$6.75 \times 10^{-4}$`; H64-MQA optimal LR = `$1.0 \times 10^{-3}$`; H128-MQA-CLA2 optimal LR = `$2.25 \times 10^{-3}$`. The CLA2 model's optimal LR is substantially higher (2–3×) than the baselines, reinforcing the pattern that CLA benefits from more aggressive optimization.
- At 3B scale (second set): all models converged best at LR = `$1.0 \times 10^{-3}$`.

**Design space exploration: the sweep configurations (Table 1).** The 1B-scale sweep covers 18 distinct model configurations spanning:

- **7 non-CLA baselines**: H128-MHA, H128-GQA4, H128-GQA2, H128-MQA, H64-MQA, H46-MQA, H32-MQA. This sweeps both the MHA→GQA→MQA axis (varying the number of KV heads per layer from 16 down to 1) and the head dimension axis (varying `$d_{\text{head}}$` from 128 down to 32). Reducing `$d_{\text{head}}$` reduces KV cache size proportionally but also reduces attention expressivity; reducing the GQA factor reduces KV cache size by reducing the number of distinct KV heads while keeping `$d_{\text{head}}$` large.

- **5 MQA-CLA2 models**: H512-MQA-CLA2, H256-MQA-CLA2, H128-MQA-CLA2, H90-MQA-CLA2, H64-MQA-CLA2. These combine CLA2 with MQA and sweep `$d_{\text{head}}$` from 512 down to 64. Note that when `$d_{\text{head}}$` is large (512), the number of query heads is small (`$H = 2048/512 = 4$`), which is an unusual configuration but one that the paper includes to fill out the memory axis of the Pareto frontier.

- **2 GQA-CLA2 models**: H256-GQA4-CLA2 and H128-GQA4-CLA2 test whether CLA provides benefits beyond MQA when the per-layer KV head count is larger. H128-GQA2-CLA2 tests GQA2 (intermediate between MQA and GQA4).

- **2 higher-sharing-factor models**: H128-MQA-CLA3 and H128-MQA-CLA4 test whether sharing across more than 2 layers is beneficial.

- **3 non-uniform CLA2 models**: H128-MQA-CLA2-KeepEnds, H128-MQA-CLA2-DenseFront, H128-MQA-CLA2-DenseBack test alternative layer grouping patterns.

All non-CLA baselines have 20 layers, each with its own KV cache. CLA2 models have 10 KV-producing layers; CLA3 has 7; CLA4 has 5. The non-uniform patterns have 11 KV-producing layers.

**Why the paper focuses on MQA-CLA2.** The rationale — implicit in the experimental design and explicit in the results — is that MQA already establishes that aggressive KV sharing within a layer is viable (1 KV head for all query heads), and extending this principle across layers with a modest sharing factor of 2 provides the best accuracy-per-byte tradeoff. Higher sharing factors (3, 4) reduce cache size further but the accuracy degradation accelerates, making CLA2 the "sweet spot." GQA + CLA2 provides little benefit over MQA + CLA2 because the per-layer head reduction from GQA and the layer-count reduction from CLA are partially redundant: if CLA already halves the number of KV caches, further reducing per-cache head count from 1 (MQA) to 0 (impossible) is not an option, and per-cache head counts of 2 or 4 (GQA2, GQA4) increase memory without commensurate accuracy gains.

**Two-fold cross-validation... is not used.** Unlike the example paper that used cross-validation for strategy selection, this paper does not use cross-validation. The results are simply perplexities on a fixed held-out validation set, with no adaptive strategy selection that would require separate tuning and evaluation folds. The paper does use two different training environments for the second set of 3B experiments (due to logistical constraints — "a different training cluster using a different training software stack and data order"), and retrains the H64-MQA-CLA2 baseline in the new environment to control for this, which is a form of robustness check.

**Compute infrastructure.** All experiments run on NVIDIA H100 GPUs using PyTorch (Paszke et al., 2019; Ansel et al., 2024). The paper does not report wall-clock training times or GPU counts.

#### Design Choices and Their Justifications

**Choice: Share KV activations across layers rather than tying KV weights.** Weight tying (making layers `$l$` and `$l+1$` use the same `$W_K$` and `$W_V$` matrices) would still produce different KV activations at each layer because the hidden states differ. Activation sharing forces a stronger constraint — the representations themselves must be shared — which is what yields the memory reduction. If the weights were tied but each layer still computed its own KV activations and cached them separately, there would be zero memory savings.

**Choice: CLA2 over higher sharing factors.** The empirical results (Table 1) show that CLA3 (perplexity 13.77) and CLA4 (13.95) achieve worse perplexity than CLA2 (13.60) at the same head dimension. Even when comparing at similar cache footprints, CLA2 with a tuned head dimension outperforms higher sharing factors. For example, H128-MQA-CLA3 at 3584 bytes/token and perplexity 13.77 is worse than H90-MQA-CLA2 at 3600 bytes/token and perplexity 13.73 — essentially identical memory but worse accuracy. This suggests that the accuracy cost of forcing layers 0, 1, and 2 to all share one KV representation is higher than the cost of forcing only layers 0 and 1 to share, and the additional memory savings of CLA3 do not justify the accuracy hit.

**Choice: MQA over GQA as the base attention mechanism for CLA.** The GQA-CLA2 results show that GQA4-CLA2 at `$d_{\text{head}} = 128$` achieves perplexity 13.48 at 20,480 bytes/token, versus MQA-CLA2 at `$d_{\text{head}} = 512$` achieving 13.49 at the same 20,480 bytes/token — identical perplexity with a much larger head dimension. GQA2-CLA2 at `$d_{\text{head}} = 128$` achieves 13.59 at 10,240 bytes/token, versus MQA-CLA2 at `$d_{\text{head}} = 256$` achieving 13.51 at the same memory — the MQA-CLA2 version is better. This suggests that when CLA already reduces the KV cache through layer sharing, the additional flexibility of having multiple KV heads per layer (GQA) provides diminishing returns: the model benefits more from having a single large-headed KV representation (which can capture rich key/value information) than from having multiple smaller-headed KV representations that consume the same total memory. MQA-CLA2 with a larger `$d_{\text{head}}$` is a better use of a fixed memory budget than GQA-CLA2 with a smaller `$d_{\text{head}}$`.

**Choice: Uniform pairing over non-uniform patterns.** The non-uniform patterns (KeepEnds, DenseFront, DenseBack) all perform worse than uniform CLA2, with DenseBack being particularly poor (14.03 perplexity). The paper does not deeply analyze why, but the results suggest that distributing KV-sharing pairs uniformly throughout the model depth provides the best accuracy/memory tradeoff — likely because it gives each layer access to KV representations computed from a nearby hidden state (the immediately preceding layer), minimizing the representational mismatch between the layer producing the keys and the layer consuming them. DenseBack forces many later layers to use KV representations from an early layer, creating a large representational gap.

**Choice: Training from scratch rather than converting pre-trained models.** Unlike Ainslie et al. (2023b), who showed that GQA models can be obtained by uptraining from MHA checkpoints, this paper trains all CLA models from scratch. This is a cleaner experimental methodology for isolating the effect of the architecture — uptraining introduces confounding factors like the learning rate schedule during conversion and the potential for the model to partially "recover" from the architectural change without fully adapting. Training from scratch ensures that the model learns to work with the CLA constraint from the beginning, giving the most accurate assessment of CLA's impact on model quality. The downside is that the paper does not provide a migration path for existing pretrained models to adopt CLA without retraining — this is left as future work (implicitly).

## 4. Key Insights and Innovations

### Innovation 1: Expanding the KV Cache Optimization Axis from Per-Layer Head Count to Cross-Layer Sharing

The field's approach to reducing KV cache memory through architectural design has been dominated by a single conceptual axis since Shazeer's MQA proposal in 2019: **reduce the number of distinct key/value heads within each attention layer**. MQA collapses all query heads onto one shared KV head. GQA provides a tunable knob along this axis, interpolating between full MHA (one KV head per query head) and full MQA (one KV head total). This axis has proven productive — it gave us production architectures like Llama 2 and PaLM — but it treats the per-layer head count as the only architectural lever for KV cache compression. Every layer still gets its own KV cache entry, and the total cache size scales as `L × G × d_head`.

This paper's foundational conceptual move is to identify that **the number of distinct layer-level KV caches, `L`, is an independent and previously unexploited optimization dimension**. The observation is almost obvious in retrospect: if query heads can share KV heads within a layer without catastrophic accuracy loss, perhaps adjacent layers can share KV activations across layers without catastrophic accuracy loss. But this is not a trivial extension. Intra-layer sharing (MQA/GQA) means multiple query projections attend over the same keys and values *computed from the same hidden state*. Cross-layer sharing means a layer's query projections attend over keys and values **computed from a different layer's hidden state** — hidden states that have been transformed by one or more feed-forward networks and residual connections in between. The central risk is that the keys from layer `l` encode information in a representational format that is simply incompatible with the queries from layer `l+1`, because the two layers operate on different residual-stream distributions.

What makes this an intellectual contribution rather than merely a parameter sweep is that the paper **demonstrates this axis is real and productive**, not just theoretically plausible. By sweeping CLA sharing factors, head dimensions, and base attention mechanisms (MQA, GQA) simultaneously, the paper maps a two-dimensional design space — per-layer head count on one axis, cross-layer sharing on the other — and shows that the Pareto frontier achieved by jointly optimizing both dimensions lies strictly above the frontier achievable by optimizing either alone (Figure 3). The non-CLA models define a Pareto curve in the `(KV bytes per token, perplexity)` plane; the CLA models define a new curve shifted leftward/downward. This is the architectural analog of showing that a new hyperparameter opens a previously inaccessible region of the design space.

The significance goes beyond the specific CLA2 recommendation. It establishes that **KV cache architecture design is fundamentally a two-axis problem**, and future work on efficient attention should consider both the head-count dimension and the layer-count dimension as jointly optimizable. Just as GQA made MHA/MQA a continuous choice along one axis, CLA (or future generalizations like learned cross-layer mixtures) could make the layer-sharing pattern a rich design space rather than a binary "share or don't share" decision.

### Innovation 2: The Synergistic Interaction Between CLA and MQA — Why the Combination Is More Than the Sum of Its Parts

A naive reading of the paper might conclude that CLA and MQA are independent optimizations that compose multiplicatively: MQA reduces per-layer KV heads by a factor of `H`, CLA reduces the number of KV-producing layers by a factor of `S`, and together they reduce total cache size by `H × S`. Under this additive view, the choice of base attention (MHA, GQA, or MQA) should be orthogonal to the choice of CLA sharing factor — you pick your per-layer head count to hit a target memory/accuracy tradeoff, and independently pick your CLA factor to reduce layers.

The experimental results (Table 1, Figure 3) reveal something more interesting: **CLA works substantially better with MQA than with GQA, even when controlling for total KV cache size**. The GQA4-CLA2 model at `d_head = 128` achieves a perplexity of 13.48 at 20,480 bytes/token; the MQA-CLA2 model at `d_head = 512` achieves a perplexity of 13.49 at the same 20,480 bytes/token — identical accuracy with a head dimension 4× larger. But the GQA4-CLA2 model uses 4 KV heads per layer (consuming 4× the per-layer cache of MQA), while MQA-CLA2 uses 1 KV head per layer with a larger head dimension (4× the dimension). The memory budgets are identical (same `KV bytes per token`), yet MQA-CLA2 achieves the same accuracy with a single large-headed KV representation rather than four smaller-headed ones. This is not what multiplicative independence would predict — it suggests that when layers already share KV caches, the **marginal benefit of having multiple distinct KV heads per layer diminishes**, and the representational quality of the shared head (driven by its dimension) matters more than the quantity of heads.

The paper's implicit explanation (Section 2.2: "CLA is orthogonal to MQA/GQA/MHA, and can be combined with any of them") undersells this finding. The GQA2-CLA2 result reinforces the pattern: at 10,240 bytes/token, GQA2-CLA2 with `d_head = 128` (perplexity 13.59) is slightly worse than MQA-CLA2 with `d_head = 256` (perplexity 13.51) at the same cache budget. The `d_head = 256` MQA-CLA2 model can afford the larger head dimension precisely because MQA uses only 1 KV head per layer, freeing the memory budget for richer representations.

This is a **diagnostic finding with practical implications**: if you are designing a CLA model, the right strategy is to push the per-layer head count as low as possible (ideally to MQA, `G = 1`) and use the saved memory to increase `d_head`. The interaction between the two optimizations is not purely multiplicative — it is **synergistic** in the sense that CLA's reduction in the number of KV caches makes the per-cache memory budget larger, which is better spent on a single high-dimensional head than on multiple low-dimensional ones. The paper does not theorize why, but a plausible mechanism is that CLA already constrains attention through cross-layer representation sharing; adding representational flexibility through a larger `d_head` — allowing richer keys and values — partially compensates for this constraint, while adding more KV heads per layer does not compensate effectively because the constraint is at the representation level, not the capacity level.

### Innovation 3: The Empirical Demonstration That Higher Sharing Factors Have Diminishing Returns — CLA2 Is the Sweet Spot

The paper's ablation across CLA2, CLA3, and CLA4 (all MQA, all `d_head = 128`) provides a clean result that shapes the practical guidance: **accuracy degrades faster than memory improves as the sharing factor increases beyond 2**. CLA2 reaches perplexity 13.60 at 5,120 bytes/token. CLA3 at 3,584 bytes/token (30% less memory than CLA2) reaches 13.77 — a 0.17-point perplexity increase. CLA4 at 2,560 bytes/token (50% less memory than CLA2) reaches 13.95 — a 0.35-point increase.

But the more revealing comparison is at equivalent memory footprints. When the paper sweeps `d_head` down for CLA2 models, it finds that H90-MQA-CLA2 achieves perplexity 13.73 at 3,600 bytes/token — slightly better accuracy than CLA3 at essentially the same memory (3,584 vs. 3,600, within 0.4%). And H64-MQA-CLA2 achieves perplexity 13.89 at 2,560 bytes/token — better than CLA4 at the identical 2,560 bytes/token (13.89 vs. 13.95). **This means CLA3 and CLA4 are Pareto-dominated by CLA2 with a tuned head dimension**: for any memory target achievable with CLA3 or CLA4, a CLA2 configuration with a smaller `d_head` achieves equal or better accuracy.

This is a non-obvious finding because the natural intuition is that more sharing = more memory savings = a different point on the Pareto frontier worth exploring. The results instead suggest that the **accuracy cost of forcing layers `l` and `l+2` to share KV representations (skipping a layer in between) is fundamentally higher than the cost of forcing adjacent layers `l` and `l+1` to share**. The representational gap between layers grows with depth distance. Layer `l+2`'s hidden state has been transformed by two feed-forward blocks and two residual additions relative to layer `l`'s hidden state, and the keys computed by layer `l` from its hidden state are simply less useful for layer `l+2`'s queries than they are for layer `l+1`'s queries. The paper does not analyze this representational mismatch directly (e.g., via attention pattern similarity or key-value subspace analysis), but the empirical result is clear enough to establish CLA2 as the recommended configuration.

This has a practical consequence for practitioners: **the CLA design space is effectively one-dimensional** (choose `d_head` with CLA2) rather than two-dimensional (choose sharing factor AND `d_head`), because CLA2 uniformly Pareto-dominates other sharing factors. This simplifies architectural search considerably, even though it was not obvious ex ante that sharing factors >2 would be dominated.

### Innovation 4: The Learning Rate Interaction — CLA Models Benefit from Higher Optimization Rates

The learning rate tuning experiments (Section 3.2.2, Appendix A) reveal a pattern that is not the paper's headline contribution but represents a substantive methodological finding: **CLA models consistently achieve their best perplexity at higher learning rates than comparable non-CLA baselines**. At 1B scale: H128-MQA baseline optimal LR = `1.5 × 10⁻³`; H128-MQA-CLA2 optimal LR = `2.25 × 10⁻³` (1.5× higher). At 3B scale: H128-MQA baseline optimal LR = `6.75 × 10⁻⁴`; H128-MQA-CLA2 optimal LR = `2.25 × 10⁻³` (3.3× higher).

This is not merely an implementation detail. It has implications for how CLA models should be evaluated and compared. If a researcher compares a CLA model to a non-CLA baseline at the same learning rate (as the paper's initial design space exploration does, using a conservative `LR = 3 × 10⁻⁴` for all models), the CLA model may appear artificially disadvantaged if its optimal learning rate is higher. The fact that CLA's Pareto improvement **persists and in some cases strengthens** after learning rate tuning (Table 3: the CLA2 model's perplexity gap to the `d_head = 128` baseline shrinks from 0.06 to 0.04 points, and the CLA2 model's advantage over the `d_head = 64` baseline at the same cache size widens from 0.21 to 0.31 points) validates that the core finding is robust, but the tuning is essential to demonstrate this.

The mechanistic reason for the higher optimal learning rate is not established, but the paper offers a plausible structural explanation: CLA models have fewer trainable parameters (the key/value projection matrices are removed from approximately half the layers for CLA2), and the gradient flow through shared KV activations is different — the KV-producing layers receive gradient contributions from both their own attention and from the attention of all layers that reuse their keys/values. This means the gradient signal for the KV projection weights is effectively "amplified" by being summed across multiple downstream layers, potentially supporting larger parameter updates without instability. This is a hypothesis, not a verified mechanism, but it points toward a general principle: **architectural changes that reduce parameter count or concentrate gradient flow may shift the optimal learning rate regime**, and fair comparisons between architectures require learning rate sweeps.

The finding also has practical transfer value: if you adopt CLA for your own models, you should expect to retune the learning rate, and you should expect the optimum to be somewhat higher than what your non-CLA baselines use. The paper does not provide a predictive formula (e.g., "increase LR by 1.5–3×"), but the directional guidance is clear from the consistent pattern across model scales.

### Innovation 5: The Non-Uniform Sharing Pattern Negative Result — Why Regular Alternation Is Optimal

In addition to the main CLA2, CLA3, and CLA4 configurations, the paper tests three non-uniform CLA2 patterns (Table 1, bottom rows): KeepEnds (unshared first and last layers, pairs in between), DenseFront (first 10 layers unshared, then 9 layers all sharing layer 9's KV, then one unshared final layer), and DenseBack (layers 2–11 all sharing layer 1's KV, with unshared layers at both extremes). All three perform worse than uniform CLA2 at the same or slightly higher memory (all require 11 KV-producing layers vs. uniform CLA2's 10). The DenseBack configuration is particularly poor at 14.03 perplexity — worse than many baselines with much smaller KV caches.

This is a **negative result that provides diagnostic insight** despite not advancing the Pareto frontier. It tells us that **the benefit of CLA is not simply about reducing the number of distinct KV caches — the spatial arrangement of which layers share with which matters greatly**. Uniform pairing (layer 0 with 1, 2 with 3, ...) ensures that each KV-reusing layer is only one transformation step away from the layer that produced its keys. The DenseBack pattern forces layers 3 through 11 — spanning much of the model's depth — to all attend using KV representations computed from layer 1's hidden state, with up to 10 feed-forward transformations separating the key producer from the key consumer. The severe degradation of DenseBack (14.03 vs. 13.60 for uniform CLA2, a 0.43-point gap) isolates the cost of **representational staleness**: keys computed from an early hidden state are simply poor proxies for the keys that later layers would compute if they had their own KV projections, and no amount of learnable query-side adaptation (layer norm, query projections) can fully compensate.

This finding constrains the design space in a theoretically informative way. It rules out a whole class of CLA variants one might naively consider — clustering all shared layers together, or sharing across non-adjacent layers — and establishes that **locality of sharing** (adjacent layers only) is a necessary condition for CLA to work well. This aligns with what we know about transformer representations: the residual stream evolves gradually across layers, so the hidden states of adjacent layers are more similar than those of distant layers. Keys computed from similar hidden states are more likely to be useful for each other's queries. The paper thus provides empirical grounding for an architectural principle that might have been guessed from first principles but needed verification: cross-layer KV sharing should be **local** along the depth dimension, not global.

## 5. Experimental Analysis

### Evaluation Methodology

**Dataset.** All pretraining experiments use the Slimpajama dataset (Soboleva et al., 2023), a cleaned and deduplicated 627-billion-token subset of the RedPajama corpus. The data is tokenized using the GPT-NeoX tokenizer (Black et al., 2022) with Byte-Pair Encoding. For validation, the authors hold out approximately 4 million tokens from the same corpus to measure perplexity. For downstream evaluation, they use EleutherAI's LM Eval Harness (Gao et al., 2023) to measure Wikitext (Merity et al., 2016) perplexity and accuracy on seven standard benchmarks: Hellaswag, PIQA, WinoGrande, SciQ, OpenBookQA, BoolQ, and ARC-Easy.

**Base model(s).** All models are Llama-like (Touvron et al., 2023) decoder-only transformers with pre-normalization, SwiGLU activations (Shazeer, 2020; Ramachandran et al., 2017), and rotary position embeddings (Su et al., 2023). The paper trains two scales: 1B-parameter models (20 layers, `d_model = 2048`, FFN size 5472, 30B training tokens) and 3B-parameter models (32 layers, `d_model = 3072`, FFN size 8192, 100B training tokens). These scales are chosen to be large enough to exhibit realistic scaling trends but small enough to enable extensive hyperparameter sweeps. The Llama-like architecture is selected because it represents the dominant modern LLM design family, making the results directly transferable to practitioners working with models like Llama 2, Mistral, or similar architectures. All models are trained from scratch — no pretrained checkpoints are used or converted — to isolate the architectural effect from confounding factors introduced by uptraining or conversion.

**Metrics.** The primary metric throughout is **validation perplexity** on a held-out subset of approximately 4 million tokens from Slimpajama. For learning-rate-tuned models, the paper additionally reports **Wikitext perplexity** and accuracy on seven downstream benchmarks via the LM Eval Harness. KV cache memory footprint is reported as **KV bytes per token at 16-bit precision**, computed as `2 × L_kv × G × d_head × 2 bytes/element`, where `L_kv` is the number of layers that compute KV projections, `G` is the number of KV heads per layer (1 for MQA, variable for GQA), and `d_head` is the per-head embedding dimension. This metric directly captures the deployment-time memory cost that motivates the work.

**Baselines.** The paper trains seven non-CLA baseline models at the 1B scale, spanning the MHA → GQA → MQA spectrum at various head dimensions (Table 1): H128-MHA (`d_head = 128`, 16 KV heads per layer, 163,840 bytes/token), H128-GQA4 (4 KV heads, 40,960 bytes/token), H128-GQA2 (2 KV heads, 20,480 bytes/token), H128-MQA (1 KV head, 10,240 bytes/token), H64-MQA (5,120 bytes/token), H46-MQA (3,680 bytes/token), and H32-MQA (2,560 bytes/token). These baselines are all drawn from the existing MQA (Shazeer, 2019) and GQA (Ainslie et al., 2023b) literature, establishing the accuracy/memory tradeoff frontier achievable with prior art. At the 3B scale, baselines shift based on empirical findings: after discovering that `d_head = 64` MQA outperforms `d_head = 128` MQA at 3B parameters, the second set of experiments uses H64-MQA and H32-MQA as the primary non-CLA reference points (Tables 5, 7).

**Generation budget / compute accounting.** Because this is a pretraining study rather than an inference-time scaling study, "compute" is measured in training FLOPs. All models within a given scale are trained on the same number of tokens (30B for 1B, 100B for 3B) with the same sequence length (2048) and batch size (2048 sequences ≈ 4M tokens per step), ensuring that total training FLOPs are approximately matched. CLA models require slightly fewer FLOPs due to the reduced number of key/value projection matrices, but this difference is minor relative to the total training budget. The paper does not measure or compare inference-time latency or throughput, focusing solely on the memory/accuracy tradeoff as the design objective.

**Cross-validation / statistical protocol.** The paper does not use cross-validation in the traditional machine learning sense. Validation perplexity is measured on a single fixed held-out set of approximately 4M tokens. For learning rate tuning, the protocol is: sweep learning rates upward from `3 × 10⁻⁴` in multiplicative increments of `1.5×` until validation perplexity stops improving, then select the learning rate that achieved the lowest validation perplexity as each model's approximate optimum. For the second set of 3B-scale experiments, models were retrained in a different training environment (different cluster, different software stack, different data order) to control for infrastructure-induced variability — a form of robustness check rather than cross-validation. The learning rate tuning results are reported as single-point estimates without confidence intervals, which is standard for pretraining experiments at this scale where multiple training runs per configuration are prohibitively expensive.

### Main Quantitative Results

#### The Pareto Frontier: CLA2 + MQA Advances Accuracy/Memory Tradeoffs (1B Scale)

The central result of the paper is the accuracy/memory Pareto frontier plotted in Figure 3 and tabulated in Table 1. At the 1B-parameter scale, the authors train 7 non-CLA baselines and 11 CLA variants, measuring validation perplexity and KV cache bytes per token for each.

**Headline finding:** MQA-CLA2 models achieve **strictly better perplexities** than non-CLA baselines at equivalent KV cache memory budgets, shifting the Pareto frontier leftward (Figure 3, red curve vs. blue curve). Concretely, comparing CLA2 models to baselines at approximately matched cache footprints:

- **At ~20,480 bytes/token:** H512-MQA-CLA2 achieves perplexity 13.49 and H256-MQA-CLA2 achieves 13.51, compared to H128-GQA2 at 13.52 and H128-MQA at 13.54 for the same footprint. This is a small improvement (0.01–0.05 points), but it comes with a critical architectural difference: the CLA2 models achieve this with **half as many KV-producing layers** (10 instead of 20) and a **larger head dimension** (256 or 512 instead of 128).

- **At ~10,240 bytes/token:** H256-MQA-CLA2 achieves perplexity 13.51, which is identical to one of the 20,480-byte/token baselines — but at half the memory. Compared to the baseline with the same 10,240 bytes/token footprint (H128-MQA at 13.54), the CLA2 model is 0.03 points better. More interesting is the comparison to the next-smaller baseline: H64-MQA at 5,120 bytes/token with perplexity 13.81. The CLA2 model achieves **0.30 points better perplexity** than this baseline while using **2× more memory** — a direct demonstration of moving the Pareto frontier, since no non-CLA configuration can achieve perplexity 13.51 at 10,240 bytes/token (H128-MQA is closest at 13.54, which is worse).

- **At ~5,120 bytes/token:** H128-MQA-CLA2 achieves perplexity 13.60, compared to H64-MQA baseline at 13.81. This is a **0.21-point improvement** at identical memory. Stated differently: CLA2 allows a model to maintain nearly the same accuracy as a 10,240-byte/token baseline (H128-MQA at 13.54) while using half the KV cache memory (5,120 bytes/token, H128-MQA-CLA2 at 13.60 — a degradation of only 0.06 points for a 2× memory reduction).

- **At ~3,600 bytes/token:** H90-MQA-CLA2 achieves perplexity 13.73, compared to H46-MQA baseline at 13.96 — a **0.23-point improvement** at matched memory.

- **At ~2,560 bytes/token:** H64-MQA-CLA2 achieves perplexity 13.89, compared to H32-MQA baseline at 14.37 — a substantial **0.48-point improvement** at matched memory. This is the largest absolute gap in the Pareto frontier, suggesting CLA2's relative advantage grows at tighter memory budgets.

**The pattern across the frontier:** The CLA2 advantage is not uniform — it is largest at low memory budgets (0.48 points at 2,560 bytes/token) and smallest at moderate budgets (0.01–0.05 points at 20,480 bytes/token), before potentially disappearing at very high budgets (the curve would asymptote to non-CLA performance as memory becomes unconstrained). This shape makes intuitive sense: when KV cache memory is abundant, the constraint CLA imposes (forcing layers to share representations) is a pure cost with little benefit; when memory is scarce, CLA's memory savings free up budget for a larger `d_head`, which improves representational quality more than the sharing constraint degrades it.

Table 1 provides the complete numerical results. The Pareto frontier plot in Figure 3 visualizes these as a scatter plot with linked frontier lines, clearly showing the red CLA2 frontier lying to the left of and below the blue non-CLA frontier. The authors explicitly note that "our MQA-CLA2 models are able to achieve better perplexities than baseline models requiring the same amount of KV cache memory, advancing the accuracy/memory Pareto frontier."

#### GQA + CLA2 Does Not Provide Consistent Advantages Over MQA + CLA2

The paper trains three GQA-CLA2 models (Table 1) to test whether the additional per-layer head flexibility of GQA is beneficial when combined with cross-layer sharing. The results are essentially negative for GQA as a complement to CLA:

- **H256-GQA4-CLA2** (4 KV heads per layer, `d_head = 256`, 40,960 bytes/token): perplexity 13.38. This is better than H128-MHA (13.15 at 163,840 bytes/token — 4× the memory) in an absolute sense, but the relevant comparison is to models using the same CLA2 technique with MQA. The H512-MQA-CLA2 model at half the memory (20,480 bytes/token) achieves perplexity 13.49 — only 0.11 points worse while using **half** the KV cache. If the GQA4-CLA2 model's per-layer head count were reduced (making it MQA-CLA2) and the freed memory reinvested in `d_head`, the perplexity would likely improve.

- **H128-GQA4-CLA2** (4 KV heads, `d_head = 128`, 20,480 bytes/token): perplexity 13.48, compared to H256-MQA-CLA2 at 13.51 for the same memory — the MQA-CLA2 variant is slightly (0.03 points) worse. This is essentially a tie.

- **H128-GQA2-CLA2** (2 KV heads, `d_head = 128`, 10,240 bytes/token): perplexity 13.59, compared to H256-MQA-CLA2 at 13.51 at the same memory — the MQA-CLA2 variant is **0.08 points better**. At this memory budget, MQA with `d_head = 256` unambiguously beats GQA2 with `d_head = 128`.

The takeaway: GQA + CLA2 does not Pareto-dominate MQA + CLA2. In the two cases where they can be compared at equal memory (20,480 and 10,240 bytes/token), MQA-CLA2 with a larger head dimension either ties or beats GQA-CLA2 with a smaller head dimension. This implies that **when layers already share KV caches (CLA), the marginal value of having multiple distinct KV heads per layer diminishes relative to the value of having a single higher-dimensional head**. The authors do not state this mechanistic interpretation explicitly, but it follows directly from the numbers.

#### Higher Sharing Factors (CLA3, CLA4) Are Pareto-Dominated by CLA2 with Tuned Head Dimension

The ablation of CLA sharing factors (Table 1, "MQA + CLA > 2 Models") tests H128-MQA-CLA3 and H128-MQA-CLA4, both at `d_head = 128`. The raw numbers:

- H128-MQA-CLA3: 3,584 bytes/token, perplexity 13.77
- H128-MQA-CLA4: 2,560 bytes/token, perplexity 13.95

These achieve better perplexity than non-CLA baselines at similar memory (H46-MQA at 3,680 bytes/token, 13.96; H32-MQA at 2,560 bytes/token, 14.37), so they do provide improvements over prior art. **However**, they are Pareto-dominated by CLA2 configurations with tuned head dimensions:

- H90-MQA-CLA2 achieves perplexity 13.73 at 3,600 bytes/token — **better accuracy than CLA3** (13.73 vs. 13.77) and essentially the same memory budget (3,600 vs. 3,584, within 0.4%).
- H64-MQA-CLA2 achieves perplexity 13.89 at 2,560 bytes/token — **better accuracy than CLA4** (13.89 vs. 13.95) at the **exact same** memory budget (2,560 bytes/token).

This means CLA3 and CLA4 are **not on the Pareto frontier**: for any memory target they can achieve, a CLA2 variant with a smaller head dimension achieves equal or better accuracy. The paper interprets this as evidence that **the accuracy cost of skipping layers in the sharing pattern (forcing non-adjacent layers to share KV representations) exceeds the accuracy cost of reducing `d_head`**, making CLA2 the universally optimal sharing factor in this experimental regime. The practical recommendation follows directly: practitioners should use CLA2 and tune `d_head` to hit their memory target, rather than using higher sharing factors.

#### Non-Uniform Sharing Patterns Degrade Performance

The three non-uniform CLA2 configurations (Table 1, bottom rows) all require 11 KV-producing layers (one more than uniform CLA2's 10) and all achieve worse perplexity than uniform CLA2 at similar memory:

- H128-MQA-CLA2-KeepEnds: 5,632 bytes/token, perplexity 13.62 — 0.02 points worse than H128-MQA-CLA2 (13.60) and **requires 10% more memory** (5,632 vs. 5,120)
- H128-MQA-CLA2-DenseFront: 5,632 bytes/token, perplexity 13.75 — 0.15 points worse
- H128-MQA-CLA2-DenseBack: 5,632 bytes/token, perplexity 14.03 — 0.43 points worse, and worse than H64-MQA (13.81) which uses only 5,120 bytes/token

The DenseBack result is the most informative negative finding. By forcing layers 2–11 to all share the KV activations computed by layer 1, this configuration creates a worst-case representational mismatch: layer 11's queries must attend over keys computed from a hidden state transformed by 10 intervening feed-forward blocks. The 0.43-point perplexity gap to uniform CLA2 isolates the cost of **non-local sharing** — when the layer producing keys and the layer consuming them are separated by many transformations, the shared KV representations become poor proxies for what the consuming layer would compute if it had its own KV projections.

This ablation establishes that the effectiveness of CLA depends on **locality**: shared KV activations should be computed from a hidden state as close as possible to the layer consuming them. Uniform pairing (layer 0→1, 2→3, etc.) minimizes this distance (one transformation step), which is why it outperforms all alternatives. The KeepEnds configuration, which only deviates from uniform pairing at the first and last layers, incurs a smaller penalty (0.02 points), suggesting that the interior layers are more sensitive to sharing disruption than the boundaries, or that the boundary layers' special roles (input embedding processing, final output preparation) make dedicated KV caches marginally useful at the ends.

#### Learning Rate Tuning: CLA2 Benefits Persist Against Well-Tuned Baselines

The design space exploration results above were all obtained at a single learning rate of `3 × 10⁻⁴`. To verify that CLA's advantages are not an artifact of suboptimal baseline tuning, the paper conducts learning rate sweeps on three key 1B-scale models (Section 3.2.2, Appendix A, Figure 5): H128-MQA baseline, H64-MQA baseline, and H128-MQA-CLA2. After tuning each to its optimal learning rate (Table 3):

- H128-MQA (best LR = `1.5 × 10⁻³`): validation perplexity 12.39, Wikitext perplexity 19.30, KV cache 10,240 bytes/token
- H128-MQA-CLA2 (best LR = `2.25 × 10⁻³`): validation perplexity 12.43, Wikitext perplexity 19.29, KV cache **5,120 bytes/token**
- H64-MQA (best LR = `2.25 × 10⁻³`): validation perplexity 12.74, Wikitext perplexity 20.00, KV cache 5,120 bytes/token

**The key comparisons after tuning:**

1. **CLA2 vs. same-head-dimension baseline (2× memory reduction):** H128-MQA-CLA2 (12.43) vs. H128-MQA (12.39) — a degradation of only **0.04 validation perplexity points** (0.3%) while halving the KV cache. On Wikitext, the CLA2 model is actually **0.01 points better** (19.29 vs. 19.30), within noise. This validates that the minimal accuracy cost observed in the initial sweep (0.06 points at LR = `3 × 10⁻⁴`) is real and not a learning rate artifact.

2. **CLA2 vs. same-memory baseline:** H128-MQA-CLA2 (12.43) vs. H64-MQA (12.74) — an improvement of **0.31 validation perplexity points** at the identical 5,120 bytes/token. On Wikitext, the improvement is **0.71 points** (19.29 vs. 20.00). This is a substantial gain: CLA2 allows a model to use `d_head = 128` at half the KV cache cost of a non-CLA model with the same head dimension, and the larger head improves accuracy enough to significantly outperform a non-CLA model constrained to the same memory budget with `d_head = 64`.

**Downstream benchmarks (Table 4)** tell a more nuanced story. Across the seven tasks, no model consistently wins:

- H128-MQA scores highest on Hellaswag (36.24), WinoGrande (52.96), BoolQ (57.40), and ARC-E (55.43)
- H128-MQA-CLA2 scores highest on PIQA (69.15, tied with H128-MQA) and OpenBookQA (21.4)
- H64-MQA scores highest on PIQA (69.21) and performs worst on SciQ (78.5) and ARC-E (51.68)

All three models are within 1–5 percentage points across benchmarks, with no clear trend favoring any architecture. This is actually a positive result for CLA: it demonstrates that the perplexity improvements translate to **at least no systematic degradation** on standard downstream evaluations. The paper does not claim downstream superiority, only that CLA "minimally degrades accuracy," and the benchmark scatter supports this claim.

#### 3B-Scale: CLA2 Outperforms Baselines, But Baseline Ordering Shifts

The initial 3B-scale experiments (Table 5) compare H128-MQA, H128-MQA-CLA2, and H64-MQA after learning rate tuning. The unexpected finding is that **H64-MQA outperforms H128-MQA** at 3B scale (validation perplexity 9.48 vs. 9.52; Wikitext 13.49 vs. 13.63), despite having half the KV cache memory. This is the opposite of the 1B-scale pattern, where larger head dimensions always improve accuracy. The paper does not explain this reversal, but it may reflect a ceiling effect: at 3B parameters and `d_model = 3072`, the `d_head = 128` configuration forces `H = 3072/128 = 24` query heads, while `d_head = 64` forces 48 heads. More query heads with smaller dimension may be beneficial at this scale and depth, or the `d_head = 128` models at 3B scale may require more training tokens to converge optimally (100B tokens is Chinchilla-suboptimal for 3B parameters — the Chinchilla-optimal token count for a 3B model is approximately 60B, so 100B is adequate but not excessive).

Because H64-MQA emerges as the stronger baseline, the authors run a second set of 3B experiments (Table 7) comparing H64-MQA, H64-MQA-CLA2, and H32-MQA. After controlling for training environment (all models retrained on the same cluster with the same data order at LR = `10⁻³`):

- H64-MQA: Wikitext perplexity 12.94, KV cache 8,192 bytes/token
- H64-MQA-CLA2: Wikitext perplexity 12.99, KV cache **4,096 bytes/token**
- H32-MQA: Wikitext perplexity 13.34, KV cache 4,096 bytes/token

**The pattern from 1B scale replicates:**

- CLA2 vs. same-head-dimension baseline (2× memory reduction): H64-MQA-CLA2 (12.99) vs. H64-MQA (12.94) — a degradation of **0.05 Wikitext perplexity points** (0.4%). This matches the 1B-scale finding of minimal accuracy cost.

- CLA2 vs. same-memory baseline: H64-MQA-CLA2 (12.99) vs. H32-MQA (13.34) — an improvement of **0.35 Wikitext perplexity points** at identical 4,096 bytes/token. This is comparable to the 0.31-point validation perplexity improvement seen at 1B scale.

Downstream benchmarks (Tables 6 and 8) again show no consistent winner, with all three model pairs within typical few-shot variance across tasks. The first set of 3B downstream results (Table 6) actually shows H128-MQA-CLA2 achieving the highest scores on Hellaswag (47.12), PIQA (74.32), WinoGrande (60.69), and SciQ (89.2) — arguably the best overall downstream performance despite using half the KV cache of H128-MQA. The second set (Table 8) is more mixed, with H64-MQA winning on ARC-E (66.92) and H32-MQA winning on BoolQ (61.87). Again, no architecture systematically dominates downstream, which is consistent with CLA preserving task performance.

**Cross-scale consistency:** At both 1B and 3B parameters, MQA-CLA2 with the standard head dimension (128 at 1B, 64 at 3B due to the baseline shift) achieves perplexity within 0.5% of a non-CLA MQA model with the same head dimension while using half the KV cache, and substantially outperforms (0.31–0.35 perplexity points) a non-CLA MQA model constrained to the same memory budget. This consistency across scales strengthens the claim that CLA2 provides a reliable 2× KV cache reduction with minimal accuracy cost, at least for models in the 1B–3B parameter range.

### Ablation Studies and Robustness Checks

**Sharing factor (2 vs. 3 vs. 4):** CLA2 dominates CLA3 and CLA4 at equivalent memory budgets (Table 1). H90-MQA-CLA2 achieves 13.73 at 3,600 bytes/token versus H128-MQA-CLA3 at 13.77 and 3,584 bytes/token — CLA2 is better and the memory is essentially equal. H64-MQA-CLA2 achieves 13.89 at 2,560 bytes/token versus H128-MQA-CLA4 at 13.95 and the same 2,560 bytes/token — a clear win for CLA2. Higher sharing factors reduce memory further but reduce accuracy more than proportionally, making CLA2 the optimal sharing factor universally in these experiments.

**Base attention mechanism (MQA vs. GQA with CLA2):** GQA + CLA2 does not improve over MQA + CLA2 at equal memory (Table 1). H256-MQA-CLA2 achieves perplexity 13.51 at 10,240 bytes/token versus H128-GQA2-CLA2 at 13.59 for the same memory — MQA-CLA2 wins. H512-MQA-CLA2 at 20,480 bytes/token (13.49) is essentially tied with H128-GQA4-CLA2 (13.48) at the same memory. The additional per-layer KV heads of GQA provide no clear benefit when layers already share KV caches.

**Sharing pattern uniformity:** Three non-uniform CLA2 patterns are tested against uniform CLA2 (Table 1, bottom). H128-MQA-CLA2-KeepEnds (13.62), DenseFront (13.75), and DenseBack (14.03) all underperform uniform CLA2 (13.60) despite requiring 10% more memory (5,632 vs. 5,120 bytes/token). DenseBack, which forces a large block of non-adjacent layers to share a single KV cache, is particularly degraded — 0.43 perplexity points worse than uniform at higher memory cost. This isolates the importance of local (adjacent) sharing and rules out architectures that cluster KV-producing layers together.

**Head dimension sweep for CLA2:** The five MQA-CLA2 configurations with `d_head ∈ {64, 90, 128, 256, 512}` (Table 1) show that CLA2 provides a smooth accuracy/memory tradeoff curve parameterized by head dimension, analogous to how GQA provides a tradeoff curve parameterized by group count. This sweep establishes that CLA2 is not a single architecture but a **family** spanning the memory/accuracy spectrum, allowing practitioners to choose any point along the frontier.

**Learning rate robustness (1B scale):** The learning rate sweep (Section 3.2.2, Appendix A, Figure 5) tests H128-MQA, H64-MQA, and H128-MQA-CLA2 across learning rates from `3 × 10⁻⁴` upward. The qualitative ordering is preserved across all learning rates: CLA2 at its optimum (12.43) beats H64-MQA at its optimum (12.74) and is competitive with H128-MQA at its optimum (12.39). Notably, H128-MQA-CLA2 and H64-MQA share the same optimal learning rate (`2.25 × 10⁻³`), while H128-MQA converges best at a lower rate (`1.5 × 10⁻³`). This means that a naive comparison at `1.5 × 10⁻³` would disadvantage CLA2 (it would appear at ~12.50 based on the curve shape in Figure 5, still better than H64-MQA but further from H128-MQA), reinforcing the importance of per-architecture tuning.

**Learning rate robustness (3B scale, first set):** Appendix A, Figure 4 shows the 3B-scale LR sweeps for H128-MQA, H64-MQA, and H128-MQA-CLA2. H128-MQA-CLA2 achieves its best perplexity at LR = `2.25 × 10⁻³`, substantially higher than H128-MQA (`6.75 × 10⁻⁴`) and H64-MQA (`1.0 × 10⁻³`). The CLA2 model's validation perplexity at its optimum (9.34) beats both baselines at their optima (9.52 and 9.48). This is a stronger result than at 1B scale — CLA2 not only matches the same-head-dimension baseline but surpasses it, and the optimal learning rate is 2–3.3× higher, suggesting distinct optimization dynamics.

**Training environment robustness (3B scale, second set):** Due to logistical constraints, the second set of 3B experiments (Table 7) was run on a different training cluster with a different software stack and data order. The authors retrain H64-MQA-CLA2 in the new environment to control for this, and the core finding replicates: CLA2 achieves Wikitext perplexity within 0.4% of the H64-MQA baseline (12.99 vs. 12.94) while using half the KV cache. The absolute perplexities differ from the first set (12.94 vs. 13.49 for H64-MQA), reflecting the different training environment, but the relative comparisons are preserved. This is a useful robustness check confirming that CLA's benefits are not an artifact of a particular training infrastructure.

**Downstream task diversity:** Across 14 downstream evaluations (7 tasks × 2 scales in Tables 4 and 6, plus 7 tasks in Table 8), CLA2 models never show a systematic accuracy degradation relative to non-CLA baselines at the same head dimension. The results are mixed — sometimes CLA wins, sometimes it loses, always within a few percentage points — which is the expected outcome for a architectural modification that preserves perplexity. This is an important validation that the perplexity improvements (or lack of degradation) are not achieved by overfitting to the language modeling objective at the expense of transfer performance.

**What was NOT ablated** (and constitutes a limitation of the experimental design):

- **Sequence length:** All experiments use a fixed sequence length of 2048 tokens. The paper does not test whether CLA's effectiveness changes at longer contexts (4096, 8192, or beyond). Since KV cache memory pressure grows linearly with sequence length, the absolute memory savings of CLA grow proportionally, but the accuracy cost might also change if longer sequences require more layer-specific attention patterns.

- **Training data scale:** All 1B models are trained on 30B tokens and all 3B models on 100B tokens. The paper does not investigate whether CLA's relative performance changes with training data volume (e.g., would CLA2 models catch up to baselines given more tokens, or would the gap widen?).

- **MHA + CLA:** The paper does not test CLA with standard Multi-Head Attention (16 KV heads per layer). The design space exploration moves directly from MHA to GQA4 to GQA2 to MQA in the baselines, and from GQA4 + CLA2 to GQA2 + CLA2 to MQA + CLA2 in the CLA models, but never tests MHA + CLA2. This is a reasonable omission given the paper's finding that MQA + CLA2 outperforms GQA + CLA2 at equivalent memory, but it leaves open the possibility that a very large head dimension MHA + CLA2 configuration could achieve better accuracy than the MQA + CLA2 frontier at very high memory budgets.

- **Batch size during inference:** The paper measures memory in "bytes per token," which is a static architectural property. It does not evaluate end-to-end inference throughput or latency at scale, which would depend on batch size, GPU memory capacity, and the interaction between KV cache size and available memory. The authors explicitly acknowledge this as future work (Section 4): "We leave end-to-end inference efficiency evaluations of large, long-context models employing CLA as an interesting problem for future work."

- **Very large models (7B+):** The experiments stop at 3B parameters. While the consistency between 1B and 3B is encouraging, extrapolating CLA's benefits to 7B, 13B, 70B, or larger models is speculative. The learning rate trend (higher optimal LR for CLA) might interact with scaling in unknown ways, and the relative importance of the KV cache vs. model weights changes at larger scales.

### Critical Assessment

This paper makes one central empirical claim: that combining CLA with MQA advances the accuracy/memory Pareto frontier for transformer language models, enabling approximately 2× KV cache reduction with minimal (less than 1%) perplexity degradation. The experimental design tests this claim along multiple dimensions — model scale (1B, 3B), sharing factor (2, 3, 4), base attention mechanism (MQA, GQA2, GQA4), sharing pattern (uniform, KeepEnds, DenseFront, DenseBack), head dimension (32 through 512), and learning rate (swept to approximate optimal for key comparisons).

**Do the experiments demonstrate this claim?** For the specific regime tested — 1B and 3B Llama-like models with MQA, trained on 30B–100B tokens of Slimpajama at 2048 sequence length, evaluated by perplexity — the evidence is consistent and compelling. The CLA2 Pareto frontier in Figure 3 unambiguously dominates the non-CLA frontier, with gaps ranging from 0.21 to 0.48 perplexity points at matched low-to-medium memory budgets. The learning rate tuning (Tables 3, 5, 7) confirms that the advantage is not an artifact of suboptimal baseline tuning. The 3B-scale replication (Tables 5, 7) shows the pattern holds at a larger model size, though with the unexpected complication that `d_head = 64` outperforms `d_head = 128` at 3B parameters — a finding that led the authors to adjust their baseline comparisons for the second set of experiments. This adjustment is methodologically sound (it strengthens the baseline rather than cherry-picking a weak one), but it does mean the 3B results do not perfectly mirror the 1B results in absolute terms.

**Where the evidence is strongest:** The Pareto frontier advancement at low memory budgets is the most robust finding. At 2,560 bytes/token, H64-MQA-CLA2 achieves 13.89 vs. H32-MQA at 14.37 — a 0.48-point gap that is large relative to the typical perplexity differences between architectures. At 5,120 bytes/token, the 0.21-point improvement (13.60 vs. 13.81) is also substantial. These comparisons are at matched memory and matched training data, isolating the architectural effect.

The claim that CLA2 "incurs only a small (0.06 point) degradation in perplexity" relative to a same-head-dimension MQA baseline (H128-MQA-CLA2 at 13.60 vs. H128-MQA at 13.54) is supported, but this number comes from the initial sweep at LR = `3 × 10⁻⁴`. After learning rate tuning (Table 3), the gap shrinks to 0.04 validation perplexity points (12.43 vs. 12.39), and on Wikitext the CLA2 model is actually 0.01 points better. So the "minimal degradation" characterization is fair, and in some conditions CLA2 may even match or slightly exceed the baseline.

**Where the evidence has meaningful gaps:**

1. **The experimental scale is modest relative to production LLMs.** The largest model tested (3B parameters) is an order of magnitude smaller than Llama 2 7B, two orders of magnitude smaller than Llama 2 70B, and three orders of magnitude smaller than frontier models like GPT-4. While the consistency between 1B and 3B is encouraging, the extrapolation to larger scales is entirely speculative. Scaling laws are notoriously non-linear, and architectural modifications that work at 1B parameters sometimes fail at 100B. The paper acknowledges this implicitly by not making claims beyond the tested scales, but readers should be cautious about assuming CLA's benefits persist to production scales without evidence.

2. **Perplexity is an imperfect proxy for downstream capability.** The paper uses cross-entropy loss (perplexity) as the primary accuracy metric. While perplexity improvements typically correlate with downstream improvements, this correlation is not perfect, especially when comparing across different architectures where the loss may be achieved through different internal mechanisms. The downstream benchmark results (Tables 4, 6, 8) are reassuring — no systematic degradation — but they are noisy and cover only a handful of tasks. A more comprehensive evaluation on tasks that stress long-range attention (e.g., Needle-in-a-Haystack, multi-document QA) would be particularly relevant because CLA constrains cross-layer attention patterns, and the impact might only manifest on tasks requiring specific layer-dependent attention behaviors.

3. **End-to-end inference performance is not measured.** The paper's value proposition is entirely about reducing KV cache memory, with the implicit promise that this translates to better inference throughput, larger batch sizes, or longer context lengths. But none of these downstream benefits are actually demonstrated. A model with CLA2 uses half the KV cache memory, but if the model is deployed in a regime where KV cache is not the memory bottleneck (e.g., the model weights dominate), the practical benefit may be zero. The paper acknowledges this limitation in Section 4 ("We leave end-to-end inference efficiency evaluations... as an interesting problem for future work"), which is honest but means the paper's central claim is about an intermediate metric (KV cache size) rather than a user-facing metric (latency, throughput, or maximum context length).

4. **The CLA3 and CLA4 ablation could be more complete.** The paper tests CLA3 and CLA4 only at `d_head = 128`. Since the key finding is that CLA3 and CLA4 are Pareto-dominated by CLA2 with tuned `d_head`, it would strengthen the argument to show that **no** head dimension can rescue CLA3 or CLA4 — i.e., that H90-MQA-CLA3 and H64-MQA-CLA2 at ~3,600 bytes/token still favor CLA2. The current evidence is suggestive but incomplete: CLA3 at `d_head = 128` (3,584 bytes) is compared to CLA2 at `d_head = 90` (3,600 bytes), and CLA2 wins slightly. But what about CLA3 at a slightly smaller `d_head`? The conclusion that CLA2 dominates higher sharing factors is probably correct, but the ablation sweep could be denser to fully establish this.

5. **The training token budget may be insufficient for full convergence.** The 1B models are trained on 30B tokens and the 3B models on 100B tokens. The Chinchilla-optimal token-to-parameter ratio is approximately 20:1, meaning a 1B model would optimally be trained on ~20B tokens and a 3B model on ~60B tokens. The 1B models thus have a comfortable surplus (30B vs. 20B), but the 3B models have a healthy but not excessive budget (100B vs. 60B). The concern is not that the models are radically undertrained, but that architectural differences sometimes interact with training duration — a CLA model might converge slower initially but catch up with extended training, or vice versa. The paper does not explore this by training for multiple token budgets.

6. **The non-uniform sharing pattern experiments are all at CLA2 granularity with extra unshared layers.** The KeepEnds, DenseFront, and DenseBack configurations all use 11 KV-producing layers (more than CLA2's 10). A more controlled comparison would be: what if we take a fixed budget of 10 KV-producing layers and arrange them non-uniformly (e.g., unshared layers at both ends, then pairs in the middle, but total count still 10)? The current design confounds "non-uniform pattern" with "more KV-producing layers," making it harder to isolate the effect of the pattern itself. However, the result that all three patterns underperform uniform CLA2 despite having **more** memory supports the conclusion strongly — these patterns lose even with an advantage.

7. **No investigation of attention pattern similarity across layers.** The paper demonstrates empirically that CLA2 works, but provides no mechanistic analysis of **why** it works. Do layers that share KV activations learn similar attention patterns? Are the shared keys in layer `l` sufficiently expressive for layer `l+1`'s queries because layer `l+1` learns to attend to the same token positions as layer `l`, or because it learns to extract different information from the same keys? Without attention map visualization or representational similarity analysis, the mechanism remains a black box. This is not a flaw in the empirical claims themselves, but it limits the paper's ability to predict when CLA will or will not work in new settings.

**Missing experiments that would strengthen the paper:**

- A 7B or 13B scale run to test scaling trends. Even one larger model at a fixed configuration would help establish whether the Pareto frontier advantage grows, shrinks, or stays constant with scale.
- Long-context evaluation (4096+ tokens) where KV cache pressure is more acute and where CLA's memory savings would have the largest practical impact.
- A comparison against post-hoc KV cache compression methods (e.g., KVQuant at 2-bit precision applied to a non-CLA model) to establish whether architectural CLA is competitive with or complementary to runtime compression.
- Training curve comparisons (perplexity vs. tokens seen) for CLA vs. non-CLA to test for convergence speed differences.
- An experiment combining CLA with a pretraining-then-finetuning pipeline (e.g., pretrain with CLA, then finetune on a downstream task) to test whether CLA's architectural constraint affects transfer learning differently than pretraining perplexity.

**Overall assessment:** The paper's core claim is well-supported within the tested regime. The evidence for a 2× KV cache reduction with minimal accuracy cost is consistent across two model scales, multiple memory budgets, and after learning rate tuning. The Pareto frontier advancement is genuine and the ablation results point to clear design guidance (use CLA2, use MQA, use uniform pairing). The primary limitation is one of scope, not methodology: the experiments do not extend to the model scales, context lengths, or end-to-end inference metrics that would make the results directly actionable for production LLM deployments. The paper is best understood as establishing a new architectural design axis and providing initial characterization, with the full practical validation deferred to future work at larger scale.

## 6. Limitations and Trade-offs

### KV Cache Memory Reduction Does Not Directly Translate to End-to-End Inference Gains

**The assumption or constraint.** The paper's entire value proposition is that reducing KV cache size enables better inference performance — larger batch sizes, longer sequence lengths, or reduced offloading costs. However, the paper explicitly stops short of measuring any end-to-end inference metric. Section 4 states:

> "We leave end-to-end inference efficiency evaluations of large, long-context models employing CLA as an interesting problem for future work."

The only metric reported is a static architectural quantity: KV bytes per token at 16-bit precision. This is an *intermediate* metric, not a user-facing one.

**The consequence.** The practical benefit of a 2× KV cache reduction is entirely context-dependent and may be zero in many deployment regimes. If the KV cache is not the memory bottleneck — for example, in deployments where model weights dominate GPU memory, or where sequence lengths are short enough that the KV cache is a small fraction of total memory — CLA provides no throughput or latency improvement. Worse, even when the KV cache *is* the bottleneck, CLA has no direct effect on the memory bandwidth consumed during attention: "even shared KV cache layers must be separately re-read from main memory in each attention layer" (Section 2.3). This means the per-token decoding latency of the attention computation is unchanged. The only latency benefit CLA can provide is indirect — by enabling larger batch sizes when KV cache memory, specifically, is the binding constraint — but this is never demonstrated. A practitioner considering CLA cannot determine from this paper whether their specific workload will benefit.

Additionally, sequential dependencies in CLA (a KV-reusing layer cannot compute attention until the KV-producing layer has finished) could interact with pipeline parallelism scheduling in ways that reduce throughput, but these effects are not measured. The paper notes the pipeline parallelism constraint (Section 2.3) but does not evaluate its practical impact.

**What evidence exists in the paper.** None. The paper reports no inference throughput, latency, maximum batch size, or maximum sequence length numbers for any model. Every result is a perplexity-at-training-time measurement paired with a static KV cache size calculation. The paper acknowledges this gap in Section 4, framing it as future work.

**Mitigation status.** Not addressed. The paper does not provide even a back-of-the-envelope analysis of when KV cache memory is likely to be the binding constraint (e.g., at what ratio of model parameters to sequence length × batch size). Practitioners must determine applicability independently.

---

### Experiments Do Not Extend to Production Model Scales

**The assumption or constraint.** All experiments are conducted at the 1B and 3B parameter scales, trained on 30B and 100B tokens respectively. These are two to three orders of magnitude smaller than frontier production models (e.g., Llama 2 70B, GPT-4). The paper does not claim its findings extrapolate to larger scales, but the practical value of CLA depends almost entirely on whether the Pareto frontier advancement persists at scales where KV cache memory is a genuine production bottleneck. At 3B parameters, the absolute KV cache sizes are modest — the largest baseline tested (H128-MHA) stores only 163,840 bytes per token, and a 2048-token sequence at batch size 64 requires roughly 21 GB of KV cache memory. At 70B parameters, a comparable model might store megabytes per token, and the KV cache can easily exceed GPU memory at modest batch sizes.

**The consequence.** There are several reasons why CLA's benefits might not scale linearly or might reverse at larger model sizes:

- Larger models have more layers (70B-class models typically have 80–100 layers vs. 20–32 in this paper). The representational gap between adjacent layers might shrink as layers become thinner functional slices of the model, potentially making CLA *more* effective at scale. Alternatively, larger models might develop more specialized per-layer attention patterns, making cross-layer sharing *more* costly.
- The learning rate interaction (CLA models consistently require higher optimal learning rates, by 1.5–3.3× at the tested scales) might have different dynamics at larger scales where learning rate tuning is more constrained by stability.
- The paper's finding that `d_head = 64` MQA outperforms `d_head = 128` MQA at 3B parameters but not at 1B parameters (compare Table 3 to Table 5) demonstrates that the optimal head dimension is scale-dependent. The optimal CLA configuration might similarly shift.

Without larger-scale evidence, a practitioner at a major AI lab cannot confidently adopt CLA for a production model — the cost of a failed architectural bet (retraining from scratch) is too high.

**What evidence exists in the paper.** The 1B and 3B results show a consistent pattern (CLA2 provides ~2× KV cache reduction with <1% perplexity degradation), but this is only two data points on the scaling curve, both in the small-model regime. The paper does not provide any theoretical argument or scaling law-style extrapolation for why the pattern should persist.

**Mitigation status.** Not addressed. The paper does not discuss scaling trends or acknowledge the gap between the tested scales and production deployment scales.

---

### No Evidence That CLA Preserves Attention Quality on Long-Range or Retrieval-Heavy Tasks

**The assumption or constraint.** All experiments use a fixed sequence length of 2048 tokens and evaluate using perplexity on a standard language modeling corpus (Slimpajama), plus a handful of short-context downstream benchmarks (Hellaswag, PIQA, WinoGrande, SciQ, OpenBookQA, BoolQ, ARC-Easy). None of these evaluations specifically stress long-range attention, multi-document reasoning, factual recall across distant context, or in-context learning with many examples — precisely the types of tasks where KV cache memory pressure is highest and where CLA's architectural constraint (forcing later layers to attend over keys computed by earlier hidden states) might be most consequential.

**The consequence.** CLA fundamentally constrains the attention mechanism: layer `l+1` must attend over keys produced from layer `l`'s hidden state, not from its own hidden state. In a standard transformer, each layer learns to extract keys that are specifically tuned to its own queries' needs — layer `l+1` might learn to attend to semantic or syntactic patterns that are only accessible from its own (more processed) hidden state. Forcing layer `l+1` to use layer `l`'s keys strips away this layer-specific key extraction capability. This constraint might be especially damaging for tasks that require:

- **Fine-grained retrieval** across long contexts (e.g., Needle-in-a-Haystack), where later layers need to precisely attend to specific tokens based on semantic content that only emerges in the upper layers' representations.
- **Multi-hop reasoning** where attention patterns in different layers serve different functional roles (e.g., lower layers attend to local syntax, upper layers attend to semantically related entities).
- **In-context learning with many examples**, where later layers need to attend to task-relevant patterns in the context, and those patterns may be represented differently in the hidden states of different layers.

Perplexity on randomly sampled text — which is dominated by local, high-frequency patterns — is a weak signal for these capabilities. The downstream benchmarks evaluated are all short-context (typically a sentence or paragraph with a single question) and do not stress long-range attention.

**What evidence exists in the paper.** Almost none. The paper reports no long-context evaluations, no retrieval task performance, and no in-context learning benchmarks. The downstream tasks shown in Tables 4, 6, and 8 are all standard short-context evaluations where CLA2 models perform within a few percentage points of baselines. But these tasks are precisely the ones where long-range attention quality is least tested. Section 4 speculates that CLA models "will stand to gain the most" in "extremely long sequence" settings, but this is an assertion about memory savings, not about whether the accuracy degradation at long contexts remains minimal.

**Mitigation status.** Not addressed. The paper does not acknowledge the gap between standard perplexity/short-benchmark evaluation and the long-context scenarios where CLA's memory savings would be most impactful, nor does it suggest specific long-context evaluations for future work.

---

### CLA's Effectiveness Depends Critically on a Specific Recipe — MQA + CLA2 + Uniform Pairing — With No Evidence That Alternative Recipes Can Be Rescued

**The assumption or constraint.** The paper's design space exploration validates one specific recipe as optimal: Multi-Query Attention (one KV head per layer) with a sharing factor of 2 and uniform adjacent pairing of layers. Several plausible variants either underperform or are not meaningfully tested:

- **GQA + CLA** produces no consistent benefit over MQA + CLA at equivalent memory budgets (Section 3.2.1, Table 1): H256-MQA-CLA2 matches H128-GQA4-CLA2 at 20,480 bytes/token (13.51 vs. 13.48, essentially tied), and H256-MQA-CLA2 beats H128-GQA2-CLA2 at 10,240 bytes/token (13.51 vs. 13.59). This means the additional per-layer KV head flexibility of GQA provides no value when CLA is already present.

- **Higher sharing factors (CLA3, CLA4)** are Pareto-dominated by CLA2 with a tuned head dimension. H90-MQA-CLA2 (13.73) beats H128-MQA-CLA3 (13.77) at essentially the same memory. H64-MQA-CLA2 (13.89) beats H128-MQA-CLA4 (13.95) at identical memory. This means higher sharing does not simply provide more memory savings at a linear accuracy cost — it becomes strictly inferior to keeping the sharing factor at 2 and reducing `d_head`.

- **Non-uniform sharing patterns** (KeepEnds, DenseFront, DenseBack) all perform worse than uniform CLA2 despite using *more* memory (11 vs. 10 KV-producing layers for the 20-layer models). DenseBack in particular is severely degraded (14.03 vs. 13.60 for uniform CLA2, a 0.43-point gap at higher memory cost).

- **MHA + CLA** is never tested at all.

**The consequence.** The design space for CLA is effectively one-dimensional: choose CLA2, use MQA, and tune `d_head`. This is not inherently a weakness — simple design guidance is valuable — but it raises questions about robustness:

1. If MQA is not available (e.g., existing models trained with GQA, or architectures where MQA is found to degrade accuracy unacceptably for a particular domain), CLA may provide little additional benefit. The GQA4-CLA2 result (13.48 at 20,480 bytes/token) is only 0.01 points better than the non-CLA GQA4 baseline (13.36 at 40,960 bytes/token) while using half the memory — a genuine benefit — but the GQA2-CLA2 result (13.59 at 10,240 bytes/token) is *worse* than the non-CLA MQA baseline (13.54 at 10,240 bytes/token). So CLA's benefits interact non-trivially with the base attention mechanism and are not guaranteed across all configurations.

2. The paper never explores *why* higher sharing factors and non-uniform patterns fail. Without understanding the mechanism (representational mismatch? gradient flow issues? optimization dynamics?), it is impossible to predict whether modified training recipes — different learning rate schedules, auxiliary losses, or architectural tweaks to bridge the representational gap — could rescue these configurations. The negative results are empirically useful but theoretically opaque.

3. A practitioner who needs KV cache reduction beyond 2× (e.g., for extreme long-context deployment) has no guidance from this paper: CLA3 and CLA4 are inferior to CLA2 with smaller `d_head`, but there is a floor on how far `d_head` can be reduced before attention quality collapses. The paper does not establish this floor, so the maximum KV cache reduction achievable with CLA2 is unknown.

**What evidence exists in the paper.** The full design space exploration in Table 1 provides clear evidence for the dominance of MQA-CLA2 with uniform pairing. The gaps are small enough for some comparisons (0.01–0.05 points in the 20,480 bytes/token regime) that a practitioner might reasonably wonder whether they are statistically significant — the paper reports no confidence intervals, and with a validation set of only ~4M tokens, the standard error on perplexity differences at these magnitudes is not negligible.

**Mitigation status.** The paper presents the MQA-CLA2 recipe as a recommendation (Section 4): "We recommend this recipe to practitioners as a conservative change to existing MQA architectures which delivers substantial memory overhead reductions with relatively little risk." The recommendation is empirically grounded, but the paper does not investigate whether the failed variants could be rescued, nor does it establish the lower bound on `d_head` for CLA2 viability.

### Difficulty Estimation and Strategy Selection Are Not Applicable — This Is an Architectural Contribution Without Adaptive Allocation

*Note: This limitation is fundamentally different in nature from the others — it identifies a missing capability that would make CLA more powerful, rather than a weakness in what the paper does demonstrate. It is included because practitioners familiar with the compute-optimal test-time scaling literature (the companion paper analyzed in this series) would naturally ask whether CLA's benefits could be amplified by adaptive per-layer or per-example sharing decisions.*

**The assumption or constraint.** CLA applies a static, uniform sharing pattern to all layers and all inputs. Every forward pass uses the same wiring: layers 0 and 1 share, layers 2 and 3 share, etc. There is no mechanism for the model to decide at runtime which layers should share KV activations or to adjust the sharing pattern based on the input. This is the simplest possible cross-layer sharing scheme, and its simplicity is part of its appeal — it requires no additional parameters, no gating mechanisms, and no dynamic routing.

**The consequence.** The paper's own results demonstrate that the value of KV cache memory varies across the model. The non-uniform sharing patterns (KeepEnds, DenseFront, DenseBack) show that *some* layers benefit more from dedicated KV caches than others. KeepEnds (13.62) is closest to uniform CLA2 (13.60), suggesting that interior layers are less sensitive to sharing than boundary layers, or equivalently that the first and last layers benefit slightly from dedicated KV projections. A static uniform pattern cannot exploit this heterogeneity — it must either give all layers dedicated caches (wasteful for interior layers) or share uniformly (slightly suboptimal for boundary layers). A learned or adaptive sharing pattern — for example, allowing the model to have more KV-producing layers in early and late stages and fewer in the middle — could improve the accuracy/memory tradeoff beyond what CLA2 achieves.

More ambitiously, sharing decisions could be made per-input or per-token. Easy inputs might tolerate more aggressive sharing (CLA3 or CLA4), while complex inputs requiring fine-grained multi-hop reasoning might need CLA2 or even dedicated KV caches in certain layers. This would be analogous to how the compute-optimal test-time scaling paper dynamically allocates inference compute based on estimated problem difficulty. CLA provides no such adaptivity.

**What evidence exists in the paper.** The non-uniform sharing pattern ablations (Table 1) provide indirect evidence for heterogeneity: KeepEnds degrades less than DenseFront or DenseBack, indicating that the first and last layers are the most "valuable" to keep unshared. But these are static patterns trained from scratch — there is no experiment testing whether a model can *learn* which layers to share (e.g., via learned gating or architecture search), or whether per-input sharing adaptivity would provide additional gains.

**Mitigation status.** Not addressed. The paper does not discuss adaptive or learned sharing patterns, nor does it frame CLA as a stepping stone toward more sophisticated dynamic sharing schemes. This is not a flaw in what the paper does demonstrate — it is a limitation of scope that constrains the maximum achievable memory/accuracy tradeoff.
