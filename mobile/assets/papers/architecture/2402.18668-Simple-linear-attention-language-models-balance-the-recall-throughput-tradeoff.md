# Simple linear attention language models balance the recall-throughput tradeoff

**ArXiv:** [2402.18668](https://arxiv.org/abs/2402.18668)

## 🎯 Pitch

Attention layers ace recall but crush throughput with a ballooning KV-cache, while efficient fixed-state models like Mamba run fast but can't retrieve facts from context—losing over 32 accuracy points on recall-heavy tasks. The paper proposes BASED, a dead-simple hybrid that stitches linear attention (Taylor-softmax) with a tiny sliding window, hitting a sweet spot where it matches Mamba's speed while doubling its recall accuracy and delivering up to 24× the generation throughput of FlashAttention-2.

---

## 1. Executive Summary

This paper introduces **BASED**, a simple hybrid architecture combining global linear attention via a Taylor approximation of softmax with local exact attention in small sliding windows, to navigate the fundamental **memory-recall tradeoff** that the authors demonstrate holds across a broad class of sequence mixers (e.g., Mamba, H3, Hyena, sliding window attention). Training language models up to 1.3B parameters on the Pile, the paper shows BASED matches the strongest sub-quadratic models in overall perplexity while outperforming Mamba by 10.36 accuracy points on recall-intensive downstream tasks and, with custom IO-aware CUDA kernels, delivers up to 24× higher generation throughput than FlashAttention-2 when generating 1024 tokens at batch size 128. The work establishes that combining simple linear attention with tiny sliding windows expands the Pareto frontier of the throughput-recall tradeoff space beyond prior architectures, though without ground-truth labels for estimating difficulty — unlike the adaptive compute-optimal framework in prior test-time scaling work — and without solving the hardest problems where the base model's pass@1 is near zero.

## 2. Context and Motivation

### The Core Problem: You Can Have Fast Generation or Good Recall, But Not Both

The fundamental question this paper tackles is: **can we build language models that achieve both the high-quality recall of attention-based architectures and the efficient inference of recurrent models?** This matters because the current architectural landscape forces a painful choice between two competing objectives.

On one side, **softmax attention** (Vaswani et al., 2017) excels at *recall* — the ability to ground generations in tokens previously seen in context. Prior work has established that attention is particularly effective at *associative recall* (AR): the capacity to retrieve specific pieces of information from earlier in a sequence when prompted by a query token (Olsson et al., 2022; Arora et al., 2023a). This skill is correlated with in-context learning and is critical for tasks like information extraction, reading comprehension, summarization, and code generation — real-world scenarios where a model must reference previously seen details during generation. Attention accomplishes this, as the authors demonstrate, with **perfect accuracy** on synthetic associative recall tasks.

But attention pays for this capability with a **growing memory footprint**. The KV-cache — the recurrent state that stores all previous key-value pairs for attention computation — scales linearly with sequence length. During generation, every new token requires accessing this expanding cache, resulting in memory consumption that grows unboundedly and throughput that degrades for longer sequences. For deployment scenarios requiring high-throughput generation (e.g., serving many users simultaneously), this becomes a severe bottleneck.

On the other side, a wave of **efficient alternatives** has emerged that maintain a **fixed-size recurrent state** during generation, enabling substantially higher throughput: Mamba (Gu and Dao, 2023), H3 (Fu et al., 2023a), Hyena (Poli et al., 2023), RWKV (Peng et al., 2023), and various linear attention architectures (Katharopoulos et al., 2020a). These models achieve sub-quadratic training complexity and constant memory per inference step, often competing with attention on coarse metrics like **overall perplexity**. However, as the paper demonstrates, this parity on aggregate metrics is misleading: when evaluated on the specific skill of associative recall, these architectures **struggle significantly**. For instance, the authors show that Mamba — a leading attention-alternative — falls behind attention by **32.2 accuracy points** on real-world recall-intensive tasks (Table 1).

The gap exists because these architectures lack the precise mechanism for local token comparisons and shifts that attention provides. Gated convolutions like Hyena and H3, despite having sub-quadratic complexity, are shown to be **asymptotically less efficient than attention at performing recall** (Arora et al., 2023a). Linear attention removes the softmax non-linearity that gives standard attention its sharp selectivity for matching queries to keys, resulting in a "blurrier" attention pattern that struggles with precise retrieval.

The practical tension is this: **deploying AI systems in the real world requires both recall quality and generation throughput**, but existing architectures force practitioners to sacrifice one for the other. A reading comprehension assistant needs to accurately retrieve facts from a long context, but also needs to respond quickly. A code generation tool must reference earlier function definitions while maintaining responsive generation speeds. The architectural choice currently determines which of these requirements can be satisfied.

### Conflicting Design Philosophies in the Field

The paper is motivated by a genuine fragmentation in the field's approach to efficient sequence modeling. Two broad strategies have emerged, each with distinct strengths and weaknesses, and the paper argues that neither alone is sufficient.

**Strategy 1: Sparse Attention (Locality Only).** Sliding window attention (SWA) caps the recurrent state size at a fixed window width `w`, so each token only attends to the last `w` tokens (Parmar et al., 2018; Child et al., 2019; Beltagy et al., 2020). This provides **constant memory during generation** and reduces training complexity to `O(Nw)`, which is linear in sequence length `N`. Recent large language models, like Mistral-7B (Jiang et al., 2023), have adopted this approach with large windows (`w = 4096`). However, the authors identify two critical shortcomings:

- **Limited recall range**: Associative recall range is bounded by the window width. If a key-value pair appears more than `w` tokens before the query, the model cannot access it. As Figure 2 shows, sliding window attention with small windows achieves poor synthetic recall, and while larger windows help, they do so at the expense of the very memory efficiency that motivated the approach — the recurrent state grows linearly with `w`.

- **Hardware-inefficient window sizes**: The authors observe that common window sizes (256–4096) are chosen without consideration of GPU hardware properties. As they show in Figure 1 (left), the latency of matrix multiplications on tensor cores is non-linear with respect to dimensions: small matrices (e.g., 64×64) execute approximately as fast as even smaller ones (16×16), but larger matrices become compute-bound. Using unnecessarily large windows wastes computational resources without proportional recall benefit.

**Strategy 2: Linear Attention (Global but Imprecise).** By replacing the softmax in attention with a kernel function `ϕ(q)⊤ϕ(k)`, linear attention achieves `O(Nd²)` time and space complexity during training and `O(1)` memory per step during generation via a recurrent formulation (Katharopoulos et al., 2020b). This provides **global token interactions** — every token can depend on every previous token — with a **fixed-size recurrent state**. However, the paper shows this comes with a significant quality cost:

- **Loss of precision for local operations**: The softmax function in standard attention provides sharp, exponential selectivity — a query attends strongly to a small number of highly matching keys and weakly to everything else. Linear attention's kernel approximations lack this sharpness. Prior work (Fu et al., 2023b; Arora et al., 2023a) has shown that precise *local token shifts and comparisons* — the ability to attend very specifically to a small set of tokens based on exact or near-exact matches — are critical for associative recall. Linear attention's "blurrier" attention pattern makes such precise operations difficult.

- **Hardware-inefficiency in practice**: Despite theoretical `O(Nd²)` complexity, linear attention implementations are **often slower than well-optimized softmax attention** in wall-clock time (Dao et al., 2022). This is because the large hidden state dimension `d̃` required for good approximations (e.g., `d̃ = d²` for the Taylor series feature map) leads to substantial data movement between GPU memory hierarchy levels. The baseline implementation of Taylor linear attention, as the authors show in Figure 4, is significantly slower than both FlashAttention-2 and Mamba despite its theoretical efficiency.

### Where Existing Architecture Comparisons Fall Short

The paper identifies that prior work comparing architectures suffers from **evaluation methodology blindspots**. The field has largely relied on **aggregate perplexity** as the primary quality metric when comparing attention-based models to their efficient alternatives. The authors argue this is inadequate for several reasons:

- **Perplexity masks recall ability**: Overall perplexity on a corpus like the Pile is dominated by frequent, simple token predictions that do not require recall. The model can achieve competitive perplexity by being good at common patterns while being poor at the rarer associative recall operations that are critical for downstream tasks. As Table 1 shows, Mamba and BASED achieve nearly identical overall Pile perplexity (6.28 vs. 6.30 at 1.3B/50B), but when the authors slice the test set to isolate tokens requiring associative recall, a clearer picture emerges: BASED achieves 1.71 versus Mamba's 1.74 AR perplexity, while Transformer++ achieves 1.65. These differences, while numerically small in absolute terms, correspond to **large downstream accuracy gaps**.

- **Synthetic benchmarks underused**: Prior work on efficient architectures rarely tests on controlled synthetic tasks like Multi-Query Associative Recall (MQAR) that isolate specific cognitive capabilities. Without such targeted evaluation, architectural deficiencies in recall remain hidden until deployment in real-world recall-intensive tasks — at which point the cost of fixing them is much higher.

- **No systematic comparison framework**: The field lacks a framework for comparing architectures along the joint axes of **quality (recall) and efficiency (state size)**. Individual papers propose new architectures (Mamba, H3, Hyena, etc.) and compare them to attention on either quality or efficiency, but not both simultaneously. There is no established methodology for understanding *where* on the Pareto frontier a new architecture sits, or how to navigate the tradeoff by varying architectural hyperparameters.

### Prior Work's Unresolved Tensions

The paper situates itself at the intersection of several active research threads, each with unresolved challenges:

**Gated convolutions and SSMs are efficient but recall-limited.** Architectures built from gating and long-convolution primitives (H3, Hyena, RWKV) or state-space models (Mamba, S4 variants) have demonstrated competitive perplexity while achieving sub-quadratic training and efficient inference (Gu et al., 2021; Poli et al., 2023; Fu et al., 2023a; Peng et al., 2023; Gu and Dao, 2023). However, Arora et al. (2023a) showed both empirically and theoretically that this class of architectures — termed *gated convolutions* — struggles to learn associative recall as efficiently as attention. Specifically, they proved that while attention can solve associative recall in a constant number of layers with model dimension independent of sequence length, any gated convolution architecture requires parameters or depth that scale with sequence length. The paper builds on this analysis by:

- **Extending the theoretical results**: In Section 3.2 and Appendix F, the authors prove new lower bounds showing that gated convolution architectures (formalized as BaseConv) require `Ω(log log N)` layers to solve MQAR, establishing a fundamental limitation that explains why architectures like H3 and Hyena fall below the Pareto frontier in Figure 2.

- **Expanding the empirical scope**: Beyond gated convolutions, the paper evaluates the recently popular Mamba architecture, which introduces input-dependent recurrences to address the limitations of purely data-independent models. The synthetic and real-world results show that while Mamba expands the Pareto frontier beyond its predecessors, it still falls short of attention's recall capacity.

**Linear attention implementations lag in practice.** The theoretical benefits of linear attention have been known since Katharopoulos et al. (2020a) — `O(Nd²)` training and `O(1)` generation steps — but practical implementations have been disappointingly slow. The Fast Transformers CUDA kernel (Vyas et al., 2020) for computing the causal dot product is the standard implementation used in prior work, but it does not exploit the GPU memory hierarchy effectively. This means that linear attention models have theoretical advantages that go unrealized in real-world wall-clock measurements. The paper explicitly acknowledges this gap and sets out to close it:

- The baseline implementation they benchmark (Section 5.2, Figure 4) uses the standard Fast Transformers kernel and achieves speeds **slower than** well-optimized softmax attention.
- Their IO-aware algorithms (Algorithm 1 and Algorithm 2) are designed specifically to reduce data movement between HBM, SRAM, and registers, enabling throughput competitive with or exceeding both FlashAttention-2 and Mamba.

**Combining sparse and linear attention has been tried, but not with hardware-aware design.** The idea of combining sparse (local) and low-rank (linear) attention mechanisms is not new. Scatterbrain (Chen et al., 2021a) showed that a sparse-plus-low-rank approximation can achieve lower error than either alone, inspired by robust PCA principles. BigBird (Zaheer et al., 2020) and Longformer (Beltagy et al., 2020) combined local windows with global tokens or random patterns. However, the paper argues that prior combination approaches did not systematically study **how the choice of hyperparameters** (feature dimension, window size, layer ratio) affects the joint quality-efficiency tradeoff, and did not design implementations with **GPU hardware efficiency** as a primary constraint. For instance:

- Scatterbrain uses a fixed low-rank approximation with `d̃ << d`, which limits recall capacity. The paper shows in Figure 3 that higher feature dimensions (and thus larger recurrent states) are necessary for competitive recall performance.
- Prior sliding window attention implementations use large windows (256–4096) that do not fully exploit tensor core properties. The paper's "Tensor Core-aware Window" (TCWINDOW) of size 64–128 is explicitly chosen to maximize hardware utilization while minimizing the per-step compute cost.

### How This Paper Positions Itself

The paper's central claim is that **no single primitive — sliding window attention, linear attention, gated convolutions, or input-dependent SSMs — solves the recall-throughput tradeoff alone**. Each provides part of the solution but has a complementary weakness. The paper frames its contribution as:

- **Systematically characterizing the tradeoff**: Through a combination of synthetic experiments (Section 3.1, Figure 2) and theoretical lower bounds (Section 3.2, Theorem 3.1 through Theorem 3.4), the paper demonstrates that the memory-recall tradeoff is *fundamental* — it is not an implementation artifact but a consequence of information-theoretic constraints. Any recurrent model requires `Ω(N)` bits of state to solve MQAR, and gated convolution architectures require logarithmically many layers. This provides a principled foundation for understanding *why* previous architectures fall where they do on the Pareto frontier.

- **Proposing a simple hybrid that expands the frontier**: BASED combines linear attention (for global, long-range interactions with a fixed-size state) with tiny sliding window attention (for precise local operations) and short convolutions (for additional local precision). The key insight is that these components are **complementary**: linear attention provides large memory for long-range recall, sliding window attention handles the precise local token shifts and comparisons needed for associative recall, and the whole combination is orchestrated with hardware-aware design to achieve practical speedups.

- **Prioritizing hardware efficiency throughout the design**: Unlike prior work that optimized for theoretical complexity and treated hardware efficiency as an afterthought, the paper makes IO-awareness a first-class design constraint. The feature map choice (2nd-order Taylor series), the window size selection (64–128 based on tensor core properties), and the custom CUDA kernels (Algorithms 1–3) are all driven by the goal of **real-world throughput**, not just asymptotic complexity. This is what allows BASED to achieve 24× higher generation throughput than FlashAttention-2 despite being, in theory, a simpler model.

- **Evaluating beyond aggregate metrics**: The paper distinguishes itself by evaluating on **recall-specific slices** of the Pile test set (Arora et al., 2023a) and on a suite of **downstream recall-intensive tasks** (SWDE information extraction, FDA extraction, SQUAD question answering) rather than relying solely on overall perplexity. This reveals quality differences that aggregate metrics obscure and provides a more actionable picture of model capabilities.

The paper explicitly connects to the growing body of work on efficient architectures while distinguishing its contribution: rather than proposing a completely new sequence mixer, it demonstrates that **thoughtful combination of known primitives, guided by hardware constraints and a clear understanding of the underlying tradeoff, can achieve results that surpass more complex and theoretically sophisticated alternatives**. This positions BASED not as a competitor to specific architectures like Mamba, but as a framework for navigating the entire Pareto frontier of the recall-throughput tradeoff.

## 3. Technical Approach

### 3.1 Reader Orientation

This is primarily an **empirical analysis and architecture design paper** whose core idea is that the memory-recall tradeoff in language models is fundamental and can be navigated by combining two simple architectural primitives—global linear attention and local sliding-window softmax attention—into a single hybrid architecture called **BASED**, which expands the Pareto frontier beyond more complex alternatives like Mamba.

### 3.2 Big-Picture Architecture (Diagram in Words)

The BASED architecture is a sequence-to-sequence language model composed of three types of layers stacked together in a specific ratio:

1. **Linear Attention Layers** (approximately 20% of layers): Use a 2nd-order Taylor approximation of the softmax exponential function to compute global attention over the entire sequence. These layers provide a large, fixed-size recurrent state that captures long-range token interactions without the KV-cache growing with sequence length. During generation, they operate in `O(1)` time per token through a recurrent formulation.

2. **Sliding Window Attention Layers** (approximately 20% of layers): Use exact causal softmax attention within small windows of 64–128 tokens, designed to match GPU tensor core tile sizes. These layers handle the precise local token shifts and comparisons needed for associative recall. Their recurrent state size is capped at the window width.

3. **Gated Convolution Layers** (approximately 60% of layers): Use short convolution filters (width 3) with element-wise gating and a SiLU non-linearity. These complement the sliding window attention by performing additional local operations over the full sequence.

When processing an input sequence, each layer transforms the hidden state and passes it to the next layer. During training, linear attention uses the parallel formulation with matrix multiplications for efficiency. During generation, linear attention switches to a recurrent formulation that updates a fixed-size hidden state, enabling constant-time per-token inference. The sliding window and convolution layers maintain their own small recurrent states.

By varying two hyperparameters—the **linear attention feature dimension** `$d'$` and the **sliding window width** `$w$`—the model can smoothly trade off between memory consumption and recall capacity, moving along the Pareto frontier from the efficient regime (small `$d'$`, small `$w$`) to the high-recall regime (large `$d'$`, large `$w$`).

### 3.3 Roadmap for the Deep Dive

- **First**, the formal memory-recall tradeoff and its empirical characterization via synthetic MQAR experiments (Section 3.1 of the paper), establishing *why* no single primitive suffices and motivating the hybrid architecture.
- **Second**, the Taylor linear attention mechanism—how the feature map is constructed, how it enables a recurrent formulation, why the 2nd-order Taylor series is chosen over alternatives, and how the feature dimension `$d'$` controls state size.
- **Third**, the sliding window attention component—why small windows (64–128 tokens) are chosen based on GPU tensor core properties, how this relates to prior work using much larger windows (256–4096), and what the TCWINDOW design principle is.
- **Fourth**, the combined BASED architecture—how the three layer types are hybridized, including the gated convolution layers that provide additional local precision, and the input-dependent decay mechanism used in some configurations.
- **Fifth**, the IO-aware implementation—the GPU memory hierarchy constraints, the baseline inefficiency, and the specific optimizations in Algorithms 1–3 that make BASED competitive in wall-clock time, including how data movement between HBM, SRAM, and registers is reduced.

This is primarily an **empirical analysis and architecture design paper** whose core finding is that the memory-recall tradeoff is fundamental, and that combining global linear attention with local exact attention in a hardware-aware manner expands the Pareto frontier of achievable throughput-recall combinations.

#### The Memory-Recall Tradeoff: Empirical Characterization

The paper establishes a fundamental tension through controlled experiments on the **Multi-Query Associative Recall (MQAR)** synthetic task (Arora et al., 2023a). This task is the paper's primary diagnostic tool for measuring recall capacity in isolation from other language modeling capabilities.

**Task definition.** In MQAR, input sequences consist of a series of key-value pairs followed by queries. Each input has the structure:

> `A 4  B 3  C 6  F 1  E 2  →  A ?  C ?  F ?  E ?  B ?`

where tokens before the arrow are key-value pairs (e.g., "A" maps to "4", "B" maps to "3"), and tokens after the arrow are queries for the model to complete. For a query like "A ?", the model must recall that key "A" was associated with value "4" earlier in the sequence and predict "4". The paper trains on sequences of 256 tokens with 4–64 key-value pairs and evaluates on sequences of 1,024 tokens with 4–256 key-value pairs, testing both in-distribution and length-generalization capacity.

**What is measured.** The paper trains architectural variants with different hyperparameters that control their recurrent state size during inference and measures accuracy on MQAR. The recurrent state size is the memory footprint maintained per token during generation—for attention, this is the KV-cache; for linear attention, it is the fixed-size hidden state from the recurrent formulation; for sliding window attention, it is the window-sized KV-cache.

**The key empirical finding (Figure 2).** The paper demonstrates a clear **tradeoff holds within and across architecture classes**:

- **Within each architecture class**, increasing the recurrent state size almost always leads to improved MQAR accuracy. For sliding window attention, as the window width `$w$` increases from 8 to 1,024 tokens, accuracy improves monotonically because more past context is available for recall.
- **Across architecture classes**, qualitatively different tradeoff curves emerge. Attention achieves **perfect recall accuracy** but its recurrent state size grows linearly with sequence length—unbounded and memory-intensive. Other architectures (Mamba, H3, Hyena) admit models with much smaller recurrent states but limited recall capacity.
- **Not all architectures make equal use of a fixed memory budget.** Mamba makes the "best use of a limited memory budget" among prior architectures, expanding the Pareto frontier beyond H3 and Hyena. Architectures with a convolutional view (Hyena, H3) **fall well below the Pareto frontier**, meaning they require larger states to achieve the same recall as Mamba or attention. BASED, when varying its controllable hyperparameters (feature dimension `$d'$` and model dimension), can "smoothly navigate the tradeoff between efficient models and memory-hungry models with high recall capacity."

**How state size is calculated for each architecture.** The paper provides exact formulas (Appendix E.2):

- **Attention**: `$\text{sizeof}(s_i) = 2 \times d \times N$`, where `$d$` is the model dimension and `$N$` is sequence length. The factor 2 accounts for separate key and value storage.
- **Sliding window attention**: `$\text{sizeof}(s_i) = 2 \times d \times \min(N, k_{\text{sliding}})$`, capped at the window width.
- **Mamba**: `$\text{sizeof}(s_i) = 2 \times d \times d_{\text{state}}$`, where `$d_{\text{state}}$` is the Mamba state expansion factor (typically 16).
- **H3**: `$\text{sizeof}(s_i) = d \times d_{\text{state}}$`, where typically `$d_{\text{state}} = d/4$`.
- **Hyena**: `$\text{sizeof}(s_i) = d \times N$`, since Hyena's implicit state depends on the full sequence.
- **BASED**: `$\text{sizeof}(s_i) = (d + 1) \times (1 + \frac{3d'}{2} + \frac{d'^2}{2})$`, where `$d'$` is the projected feature dimension before applying the Taylor map, and `$d$` is the model dimension. The +1 in the first factor accounts for the K-state used in computing the denominator (normalization term) in the linear attention recurrence.

**Controlling BASED's state size.** By changing `$d'$`—the projected query/key dimension before applying the 2nd-order Taylor feature map—the paper can "modulate the size of the recurrent state." In experiments (Figure 2), BASED is run with `$d \in \{48, 64, 128\}$` and `$d' \in \{8, 16, 24\}$`, producing a family of points along the Pareto frontier. This controllability is what enables BASED to "dial the state size" and traverse the tradeoff curve.

#### Theoretical Justification for the Tradeoff

The paper provides formal lower bounds that explain *why* the observed tradeoff is fundamental, not merely an artifact of specific hyperparameter choices. These results appear in Section 3.2 and are proven in detail in Appendix F.

**Theorem 1 (State size lower bound for recurrent models).** Any recurrent model (defined as a model whose state at position `$i$` depends only on inputs up to `$i$`, Equation 24 in Appendix F.10) that solves the associative recall problem requires `$\Omega(N)$` bits in its state size, where `$N$` is the sequence length. The proof proceeds via communication complexity: the associative recall problem can simulate the Index problem (Alice has an `$N$`-bit string, Bob has an index, Bob must output the bit at that index). Since the Index problem has one-way randomized communication complexity `$\Omega(N)$`, any recurrent model solving AR must pass at least `$\Omega(N)$` bits of state, and this lower bound applies directly to Mamba as a special case (Corollary F.13).

**Theorem 2 (Layer lower bound for gated convolutions).** A data-independent BaseConv model—the canonical formalization of gated convolution architectures (H3, Hyena, RWKV)—needs **at least `$\log(2d)$` layers** to solve MQAR when the vocabulary size `$c = 2^d$` and tokens are encoded as binary vectors (Theorem F.19). The proof constructs a multilinear polynomial of degree `$2d+1$` that exactly represents the MQAR function and shows that `$L$` layers of BaseConv produce a multilinear polynomial of degree at most `$2^L$`. Therefore, to achieve degree `$2d+1$`, at least `$\log(2d)$` layers are required.

**Theorem 3 (Complementary lower bound).** When the token embedding dimension `$d$` satisfies `$\log c \leq d \leq 2(\log N)^{1-\epsilon}$` for `$\epsilon > 0$`, a data-independent BaseConv model with parameters taking `$O(\log N)$` bits requires `$\Omega(\epsilon \log \log N)$` layers to solve associative recall (Theorem F.14). This result explains why architectures like H3 and Hyena lie below the Pareto frontier in Figure 2: their depth must grow logarithmically with sequence length to maintain recall capacity, while attention solves AR in a constant number of layers (Proposition F.16).

**Theorem 4 (Upper bound shows tightness).** The paper also shows that these lower bounds are tight: there exist settings where `$O(\max(\log \log c, \log \log N))$` BaseConv layers suffice to solve MQAR (Theorem F.30), establishing that the logarithmic depth requirement is both *necessary* and *sufficient* for this architecture class.

**Simulation of linear attention by BaseConv.** As a point of comparison, Proposition F.8 shows that linear attention can be simulated by BaseConv with only a **poly-logarithmic blowup** in the number of layers (`$O(\log^2(Nd))$` layers), suggesting that linear attention is *more efficient* than gated convolutions for recall—a claim consistent with the empirical results showing BASED (which includes linear attention) outperforming H3 and Hyena on recall tasks.

#### Taylor Linear Attention: Global Interactions with Fixed State

This is the component that gives BASED its global modeling capacity. The key challenge is to approximate softmax attention—which is expensive for generation—using a formulation that admits a recurrent view with fixed state size.

**The softmax attention bottleneck.** Standard causal softmax attention computes output `$y_i \in \mathbb{R}^d$` for position `$i$` as:

$$y_i = \frac{\sum_{j=1}^{i} \exp(q_i^T k_j / \sqrt{d})\, v_j}{\sum_{j=1}^{i} \exp(q_i^T k_j / \sqrt{d})}$$

where `$q_i = x_i W_q$`, `$k_j = x_j W_k$`, `$v_j = x_j W_v$` are the query, key, and value projections of the input `$x \in \mathbb{R}^{N \times d}$`, and `$W_q, W_k, W_v \in \mathbb{R}^{d \times d}$` are learnable matrices. The denominator is the softmax normalization sum over all keys up to position `$i$`.

**What this computes:** For each query at position `$i$`, it computes a weighted average of all past values `$v_j$` (for `$j \leq i$`), where the weight for value `$v_j$` is proportional to `$\exp(q_i^T k_j / \sqrt{d})$`—an exponential function of the dot-product similarity between the query and key. Queries attend strongly to keys with high dot-product similarity (large positive values inside the exponential) and weakly to keys with low or negative similarity (small or near-zero exponential). The result `$y_i$` is a context-dependent representation that selectively aggregates information from the history.

**Why this form is problematic for generation:** To compute `$y_N$`, the model needs all previous keys `$\{k_j\}_{j=1}^{N-1}$` and values `$\{v_j\}_{j=1}^{N-1}$` stored in memory. The KV-cache grows linearly with `$N$` and requires `$O(N)$` operations per new token, making it expensive for long sequences.

**Linear attention via kernel feature maps.** The key insight (Katharopoulos et al., 2020a) is to replace the softmax with a kernel function. If we can find a feature map `$\phi: \mathbb{R}^d \rightarrow \mathbb{R}^{\tilde{d}}$` such that `$\phi(q_i)^T \phi(k_j) \approx \exp(q_i^T k_j / \sqrt{d})$`, then we can rewrite the attention formula using matrix product associativity:

$$y_i = \frac{\sum_{j=1}^{i} \phi(q_i)^T \phi(k_j) \, v_j}{\sum_{j=1}^{i} \phi(q_i)^T \phi(k_j)} = \frac{\phi(q_i)^T \sum_{j=1}^{i} \left(\phi(k_j) v_j^T\right)}{\phi(q_i)^T \sum_{j=1}^{i} \phi(k_j)}$$

where the key-value outer product `$\phi(k_j) v_j^T$` produces a `$\tilde{d} \times d$` matrix, and the key sum `$\phi(k_j)$` produces a `$\tilde{d}$`-dimensional vector. Critically, the sums over `$j$` can be **computed incrementally**.

**What this computes (operational view):** Instead of computing `$N$` separate exponential similarities for each query (which is `$O(N)$` per query), the linear attention formulation first accumulates two running sums over the entire history: a "KV-state" `$S_i = \sum_{j=1}^{i} \phi(k_j) v_j^T \in \mathbb{R}^{\tilde{d} \times d}$` and a "K-state" `$z_i = \sum_{j=1}^{i} \phi(k_j) \in \mathbb{R}^{\tilde{d}}$`. Then, for each new query `$q_i$`, the attention output is computed as `$y_i = (\phi(q_i)^T S_i) / (\phi(q_i)^T z_i)$`—two vector-matrix products requiring `$O(\tilde{d}d)$` time, independent of sequence position `$i$`. The KV-state `$S_i$` and K-state `$z_i$` have fixed sizes `$\tilde{d} \times d$` and `$\tilde{d}$` respectively, independent of `$N$`.

**Recurrent formulation.** The recurrence that enables `$O(1)$` per-token generation is:

$$S_i = S_{i-1} + \phi(k_i) v_i^T$$

$$z_i = z_{i-1} + \phi(k_i)$$

$$y_i = \frac{\phi(q_i)^T S_i}{\phi(q_i)^T z_i}$$

where `$S_i \in \mathbb{R}^{\tilde{d} \times d}$` and `$z_i \in \mathbb{R}^{\tilde{d}}$`. The recurrent state consists of `$S_i$` and `$z_i$`, and each generation step only requires evaluating `$\phi(k_i)$`, `$\phi(q_i)$`, performing two outer-product additions to update `$S_i$` and `$z_i$`, and two dot products to produce `$y_i$`. This is `$O(1)$` in `$N$`, contrasting with attention's `$O(N)$` per step.

**Why this form enables the memory-recall tradeoff:** The size of the recurrent state `$S_i$` is determined by `$\tilde{d} \times d$`—the feature dimension `$\tilde{d}$` times the head dimension `$d$`. By changing `$\tilde{d}$` (through the choice of feature map and projection dimension), the model can explicitly trade off memory consumption against approximation quality. A larger `$\tilde{d}$` means a larger state that can better approximate the softmax's exponential selectivity; a smaller `$\tilde{d}$` means a more compact state with coarser approximation.

**The 2nd-order Taylor series feature map.** The paper chooses `$\phi: \mathbb{R}^{d'} \rightarrow \mathbb{R}^{1 + d' + d'^2}$` as:

$$\phi(q_i)^T \phi(k_j) = 1 + q_i^T k_j + \frac{(q_i^T k_j)^2}{2}$$

where queries and keys are first projected from the model dimension `$d$` down to a smaller dimension `$d'$` (e.g., `$d' = 16$` for a model with `$d = 1024$`) using learned projection matrices `$W_q, W_k \in \mathbb{R}^{d \times d'}$`. The feature map constructs a vector whose dot product with another such vector yields the first three terms of the Taylor expansion of `$\exp(q_i^T k_j)$`.

**What this computes (operational view):** Given projected query `$q \in \mathbb{R}^{d'}$` and key `$k \in \mathbb{R}^{d'}$`, the feature map produces: (1) a constant 1 term (allows uniform background attention), (2) the `$d'$` first-order terms `$q_1, q_2, \ldots, q_{d'}$` (captures linear similarity), and (3) the `$d'^2$` second-order terms `$q_1^2/\sqrt{2}, q_1q_2, q_1q_3, \ldots, q_{d'}q_{d'-1}, q_{d'}^2/\sqrt{2}$` (captures quadratic interactions and squared similarities). The total feature dimension after applying `$\phi$` is `$\tilde{d} = 1 + d' + d'^2$`. For `$d' = 16$`, this is `$1 + 16 + 256 = 273$`, which is then padded to 320 for hardware alignment (multiples of 64).

**Why this feature map over alternatives.** The paper empirically evaluates a broad set of feature maps on the MQAR task (Figure 3): `$\phi_{\text{ReLU}}(x) = \max(x, 0)$`, `$\phi_{\text{PosELU}}(x) = \text{ELU}(x) + 1$`, `$\phi_{\text{Square}}(x) = x^2$`, `$\phi_{\text{Identity}}(x) = x$`, `$\phi_{\text{CosFormer}}$` (Qin et al., 2022a), and `$\phi_{\text{Performer}}$` (Choromanski et al., 2020). The Taylor series feature map, along with `$\phi_{\text{PosELU}}$` and `$\phi_{\text{ReLU}}$`, sits at the **Pareto frontier** of the memory-recall tradeoff. The advantage of the Taylor map over these simpler alternatives is that "it expands the recurrent state size (improving recall capacity) without changing the number of parameters"—because the `$d'^2$` second-order terms come from the outer product structure inherent in the feature map, not from learned projections. In Figure 3 (bottom), the Taylor map requires fewer parameters than alternatives to achieve high recall capacity.

**How the feature dimension controls state size.** The projected dimension `$d'$` is the key knob. The paper ablates `$d' \in \{8, 16, 24, 32\}$` (Table 6). The effective feature dimension after the Taylor map is `$1 + d' + d'^2$`: for `$d'=8$`, this is 45; for `$d'=16$`, it is 273; for `$d'=24$`, it is 325; for `$d'=32$`, it is 561. The recurrent KV-state size is `$(d+1) \times \tilde{d}$` where `$d$` is the model's head dimension. For `$d=64$` and `$d'=16$`, this is `$65 \times 273 \approx 17,745$` elements per head. By varying `$d'$`, the model can sweep across the Pareto frontier: at `$d'=8$`, it uses a small state with limited recall capacity; at `$d'=32$`, it uses a large state approaching attention-like recall quality.

**Ablation results on real language data (Table 6).** Holding the architecture fixed at 362M parameters on the Pile at 10B tokens:
- Increasing `$d'$` from 8 to 16 improves associative recall perplexity from 2.18 to 2.07, 24 from 16 gives 2.02 (diminishing returns). Diminishing returns continue: 32 gives 2.00.
- Overall perplexity improves from 8.77 (`$d'=8$`) to 8.65 (`$d'=16$`) to 8.58 (`$d'=24$`) to 8.56 (`$d'=32$`).
- Comparing feature maps at fixed state size: CosFormer with `$d'=64$` (effective state dimension 128) achieves 8.82 overall and 2.18 AR perplexity, competitive with Taylor at `$d'=24$` but requiring more parameters (the larger `$d'$` increases the learned projection matrices).

#### Sliding Window Attention: Local Precision with TCWINDOW

The second key component of BASED handles the precise local token comparisons needed for associative recall. Standard linear attention lacks the "sharp selectivity" of the exponential softmax for discriminating between highly similar versus somewhat similar key-query pairs.

**Standard sliding window attention.** For window width `$w$`, each query `$q_i$` only attends to keys `$\{k_{i-w+1}, \ldots, k_i\}$`, computing exact softmax attention within this local neighborhood:

$$y_i = \frac{\sum_{j=\max(1, i-w+1)}^{i} \exp(q_i^T k_j / \sqrt{d})\, v_j}{\sum_{j=\max(1, i-w+1)}^{i} \exp(q_i^T k_j / \sqrt{d})}$$

**What this computes:** Exact softmax attention, but restricted to a local window. Within the window, the model has the full precision of the exponential non-linearity for discriminating between keys. Outside the window, the query cannot attend at all—tokens beyond `$w$` positions in the past are invisible. This creates a direct tradeoff: larger `$w$` increases recall range but also increases the memory footprint and computational cost.

**Why small windows (64–128) are chosen over large windows (256–4096).** The paper introduces the concept of **TCWINDOW** ("Tensor Core-aware Window"), selecting window sizes based on GPU hardware properties rather than modeling considerations. GPU tensor cores—specialized units for matrix multiplication that achieve 312 TFLOP/s versus 19 TFLOP/s for non-tensor-core operations—operate on `$16 \times 16$` tiles. Large GEMMs (e.g., `$4096 \times 4096$` matrix multiplication) are compute-bound, but small GEMMs benefit from sufficient occupancy to hide tensor core latency. Figure 1 (left) shows that the latency (execution time) for Cutlass GEMMs increases non-linearly with matrix dimension: `$64 \times 64$` matrix multiplications have approximately the same latency as `$16 \times 16$`, but latency grows substantially for larger dimensions. BASED sets `$w$` to use `$64 \times 64$` tiles (window sizes of 64 or 128 tokens, multiples of 16) to balance tensor core utilization against computational cost.

**Comparison to prior sliding window implementations.** Mistral-7B (Jiang et al., 2023) uses `$w = 4096$`, which the authors note results in approximately "1e-5× the latency" of the `$w=64$` windows used in BASED. For every layer of `$w=4096$` Mistral sliding window attention, achieving the same receptive field with `$w=64$` would require 64 layers—highlighting why sliding window attention alone cannot provide long-range modeling without either large windows (costly) or deep stacks (parameter-intensive). BASED's global linear attention overcomes this by providing long-range interactions through a separate mechanism, allowing the sliding window component to focus on local precision.

**TCWINDOW during training vs. generation.** During training (prefill), the paper uses FlashAttention's existing sliding window implementation (Dao, 2023), which already provides efficient batched computation. During generation (next-token prediction), the paper introduces a custom IO-aware kernel (Algorithm 3, Appendix B.2.2) that fuses the attention computation for the single new query into thread registers, avoiding repeated SRAM reads and writes.

**Ablation results (Table 6).** At 362M parameters and 10B tokens:
- Removing sliding window attention entirely (keeping linear attention + convolutions) degrades AR perplexity from 2.07 to 2.11 and overall perplexity from 8.65 to 8.74.
- Increasing window size from 64 to 128 tokens improves AR perplexity from 2.07 to 2.06 and overall from 8.65 to 8.61—marginal gains, suggesting the global linear attention already handles most long-range interactions.
- Using neither sliding window nor convolutions (pure linear attention with Taylor map and `$d'=24$`) degrades AR perplexity to 2.29 and overall to 9.49, showing both local components are important for quality.

#### Gated Convolution Layers: Additional Local Precision

BASED includes BaseConv layers (Arora et al., 2023a) with short convolution filters and SiLU activation. These operate over the full sequence but with very small filters (width 3), making their recurrent state negligible.

**The BaseConv formulation.** For input `$u \in \mathbb{R}^{N \times d}$`, a BaseConv layer computes:

$$y = \left((u \cdot W_1 + b_1) \odot \sigma(h * u \cdot W_2 + b_2)\right) \cdot W_3 + b_3$$

where `$W_1, W_2 \in \mathbb{R}^{d \times cd}$` are learned projection matrices that expand the dimension by a factor `$c=4$`, `$W_3 \in \mathbb{R}^{cd \times d}$` is a projection that contracts back to the model dimension, `$h \in \mathbb{R}^{N \times cd}$` is a learned convolution filter, `$\odot$` is the Hadamard (element-wise) product, `$\sigma$` is the SiLU non-linearity `$\sigma(x) = x \cdot \text{sigmoid}(x)$`, and `$*$` denotes linear causal convolution.

**What this computes:** The first branch `$(u W_1 + b_1)$` is a standard linear projection. The second branch applies a short convolution `$h * u$` (mixing information from nearby tokens via learned filters of width 3), projects through `$W_2$`, and applies a non-linear gating through the SiLU function. The gating mechanism—element-wise multiplication of the two branches—provides input-dependent modulation: the convolution branch determines *where* to apply the projection, acting as a dynamic filter. The final projection `$W_3$` compresses back to the model dimension.

**Why short convolutions complement sliding window attention.** While sliding window attention with small `$w=64$` handles token interactions within a 64-token radius, the short convolutions operate over the *full sequence* (through the cascade of convolution layers) but with a very local filter (width 3). Short convolutions "can help perform local, precise shifts for token comparisons since they operate over the full sequence, while TCWINDOW does not." The gating mechanism adds input-dependence, enabling the model to selectively emphasize or suppress information based on context.

**Ablation confirming necessity (Table 6).** Removing convolutions (keeping linear attention + sliding window) degrades AR perplexity from 2.07 to 2.09 and overall from 8.65 to 8.74. The impact on downstream recall tasks is more pronounced: SWDE accuracy drops from 29.16 to 24.66, and FDA accuracy drops from 11.71 to 2.36. This suggests convolutions contribute significantly to the precise local operations needed for information extraction.

#### The Combined BASED Architecture: Hybridization and Configurations

**Layer ratios in the hybrid architecture.** The paper trains BASED as a hybrid with specific layer ratios (Table 7):

- **360M parameter model (27 layers):** 5 linear attention layers, 5 sliding window attention layers, 17 BaseConv layers (approximately 18.5% linear attention, 18.5% sliding window, 63% convolutions).
- **1.4B parameter model (36 layers):** 7 linear attention layers, 7 sliding window attention layers, 22 BaseConv layers (approximately 19.4% linear attention, 19.4% sliding window, 61% convolutions).

Both use exactly the same ratio of approximately 20% linear attention, 20% sliding window, and 60% convolutions. The model dimension `$d$` scales from 1024 (360M) to 1792 (1.4B), and the number of heads for both linear and sliding window attention is fixed at 16.

**Feature dimension and window size.** Across the main experiments (Table 1), the Taylor feature dimension `$d'$` is fixed at 16, producing an effective feature size of 273 (padded to 320 for hardware alignment). The sliding window size is 64 for the 360M model and 16 for the 1.4B model (curiously smaller, not explained in the paper but presumably to control total memory given the larger model dimension).

**Why this ratio of layer types.** The paper does not provide an explicit ablation of the layer ratio, but the reasoning can be inferred: linear attention and sliding window attention are the sequence mixers that provide the core recall capability, while the gated convolutions provide additional local processing capacity at low recurrent-state cost. The 60% allocation to convolutions suggests that most of the model's capacity goes to general language modeling operations (which convolutions handle well), while the attention layers are targeted specifically at the recall-critical operations.

**Input-dependent decay (optional).** As described in Appendix C, the paper experiments with a coarse input-dependent decay technique for the linear attention layer. Rather than using per-token decay rates (as in Mamba or GLA, which require a parallel scan), BASED uses a **per-head fixed decay rate** combined with an input-dependent scaling: a linear projection takes the input `$\in \mathbb{R}^{N \times d}$` and projects to `$\mathbb{R}^{N \times H}$` (where `$H$` is the number of heads), and the result scales the attention combination across heads. However, in the main results (Table 1), the models trained to 30B and 50B tokens use **no input-dependent decay whatsoever**. Decay provides small quality improvements at 10B tokens (Table 6) but "removing the decay does not affect the overall trends for BASED relative to other architectures."

**Comparison to prior hybrid approaches.** The paper emphasizes that, unlike Scatterbrain (Chen et al., 2021a) which uses a fixed low-rank approximation with `$\tilde{d} \ll d$`, BASED deliberately chooses `$\tilde{d} > d$` (e.g., 273 vs. 64 for the feature dimension vs. head dimension) because the memory-recall tradeoff analysis shows that "we actually need `$d_{\text{query}} > d_{\text{model}}$` to match attention's recall capacity." This is a direct consequence of the empirical finding that larger feature dimensions (and thus larger recurrent states) are necessary for competitive recall performance.

#### IO-Aware Implementation: Making Linear Attention Fast in Practice

Despite theoretical `$O(Nd^2)$` complexity, standard linear attention implementations are **slower than well-optimized softmax attention** (FlashAttention-2) in wall-clock time. The paper identifies the root cause and provides custom CUDA kernels to fix it.

**The GPU memory hierarchy (Section 5.1).** Modern NVIDIA GPUs (e.g., H100) have a tiered memory system:

- **HBM (High Bandwidth Memory):** 80 GB, 2 TB/s bandwidth—the slowest but largest memory. All input tensors and final outputs reside here.
- **L2 Cache:** 80 MB, intermediate speed—a shared cache across all streaming multiprocessors (SMs).
- **L1 Cache / Shared Memory (SRAM):** 192 KB per SM, 19 TB/s bandwidth—fast memory shared among threads within a thread block.
- **Register File:** 256 KB per SM—the fastest memory, private to individual threads.

The key IO principle: **fuse multiple operations on the same data while it resides in fast memory (SRAM or registers) before writing results back to slow memory (HBM)**. Each unnecessary round-trip between HBM and SRAM, or between SRAM and registers, adds latency.

**The baseline implementation's inefficiency (Section 5.2).** The prior approach (used in Zhang et al., 2024 and listed in Appendix B.1) computes the Taylor feature maps `$\phi(q)$` and `$\phi(k)$` in Python/PyTorch, writing the full `$N \times \tilde{d}$` featurized matrices to HBM. The causal dot-product computation (from Katharopoulos et al., 2020b, using the Fast Transformers kernel from Vyas et al., 2020) then reads these matrices back from HBM. The IO cost analysis:

- Writing featurized `$q, k$` to HBM: `$2BHN\tilde{d}$` bytes (for batch size `$B$`, heads `$H$`, sequence `$N$`, feature dim `$\tilde{d}$`).
- Reading `$q, k, v$` tiles during causal dot product: `$2BHN\tilde{d} + BHN d$` bytes.
- Reading/writing the running KV-state `$\sum_{j} (k_j v_j^T) \in \mathbb{R}^{\tilde{d} \times d}$` from SRAM to registers: `$O(BHN\tilde{d}d)$` bytes at 19 TB/s bandwidth.

The total data movement is dominated by `$O(BHN\tilde{d}d)$` bytes between SRAM and registers for the KV-state, which becomes the bottleneck.

**Algorithm 1: IO-aware forward pass (prefill/training).** The custom kernel for the Taylor linear attention forward pass (Algorithm 1, described in Section 5.2 and Appendix B.1) reduces data movement through several techniques:

1. **Fusing feature map computation and causal dot product.** Instead of computing feature maps in Python and writing to HBM as intermediate tensors, the kernel computes the Taylor expansion terms (constant, 1st-order, 2nd-order) on-the-fly in registers as data streams through SRAM. This eliminates `$2BHN\tilde{d}$` bytes of HBM writes and reads for the intermediate featurized tensors.

2. **Partitioning the large KV-state across warps.** The KV-state for the 2nd-order Taylor terms has dimension `$d'^2 \times d$` (e.g., `$256 \times 64$` for `$d'=16, d=64$`), which is too large to fit in the registers of a single warp (a warp has 32 threads with a shared register budget). The kernel partitions this state across 8 warps, each responsible for `$32 \times 64$` of the state (stored in two register fragments `A_{20}$` and `A_{21}$` per warp). Warp `$i$` maintains slices `$2i$` and `$2i+1$` of the KV-state. This avoids the `$O(BHN\tilde{d}d)$` bytes of SRAM-to-register data movement present in the baseline, since the state stays in registers across iterations.

3. **Splitting computation into diagonal and off-diagonal terms.** For each tile of 16 tokens (chosen because tensor cores operate on `$16 \times 16$` tiles), the kernel computes:
   
   - **On-diagonal:** `$\text{Causal}(q_i^T k_i) v_i$` using the quadratic attention view with causal masking. This is a standard attention computation within the 16-token tile.
   - **Off-diagonal:** `$q_i \sum_{j=0}^{i-1} (k_j v_j^T)$` using the linear attention view, where the cumulative sum up to tile `$i-1$` is already maintained in the partitioned KV-state across warps.

   The diagonal term handles local interactions within the tile; the off-diagonal term handles all previous history. Their sum produces the correct linear attention output.

4. **Maintaining running KV-state in SRAM for 0th and 1st order terms.** For the constant term (0th order in the Taylor series), the KV-state reduces to a cumulative sum of `$v$`. For the 1st order term, the state is `$\sum_j k_j v_j^T \in \mathbb{R}^{d' \times d}$`. These are small enough to store in SRAM (shared memory) and accumulate across tiles.

**IO cost analysis of Algorithm 1 (Section 5.2).** The optimized kernel requires:
- `$2BHNd'$` bytes for reading `$q, k$` from HBM to SRAM (reduced from `$\tilde{d}$` to `$d'$` since only projected queries/keys are read, not the expanded feature vectors).
- `$2BHNd$` bytes for reading `$v$` and writing output `$y$` between HBM and SRAM.
- **No HBM writes** for intermediate feature map tensors (versus `$2BHN\tilde{d}$` bytes in baseline).
- **Register-resident KV-state** for the 2nd-order term, avoiding `$O(BHN\tilde{d}d)$` bytes of SRAM-to-register data movement.

The net effect is that the kernel becomes **compute-bound rather than memory-bound**, allowing it to effectively utilize tensor cores.

**Algorithm 2: IO-aware recurrent update (next-token prediction).** During generation, the expensive operation is updating the KV-state:

$$S_t = S_{t-1} + \phi(k_t) v_t^T$$

This outer product `$\phi(k_t) v_t^T \in \mathbb{R}^{\tilde{d} \times d}$` requires `$O(BH\tilde{d}d)$` computation and space. Algorithm 2 (Appendix B.2.1) provides an IO-aware version that:
- Loads the current `$q, k, v$` projections (for the single new token, shapes `$B \times H \times 1 \times d$`) from HBM to SRAM.
- Loads the running KV-state `$S_{t-1}$` in chunks of size `$n_{\text{warps}} \times 8 \times d$` (e.g., `$8 \times 8 \times 64$` for 8 warps, 8 rows per warp, 64 head dim).
- For each chunk (batch of rows), multiplies the broadcasted `$k$` value with `$v$` to update the KV-state, and multiplies `$q$` with the updated KV-state to accumulate the output.
- Writes the updated KV-state chunks back to HBM asynchronously.

**Why this matters for practical throughput.** The recurrent update is the critical path during generation—every token requires this state update. Reducing its data movement from `$O(BH\tilde{d}d)$` HBM-SRAM transfers to `$O(BH d' + BH d)$` (only the projected queries, keys, and values are loaded) enables the `$\approx 24\times$` generation throughput improvement over FlashAttention-2 reported in Figure 4.

**Algorithm 3: IO-aware sliding window attention generation.** For the sliding window attention layers during next-token prediction, the kernel (Appendix B.2.2) fuses the entire attention computation for a single query into thread registers:
1. Loads the window-sized key and value cache (`$w \times d$` elements) into SRAM as `$4T \times 4T$` tiles (where `$T=16$`).
2. Loads the single query into a register fragment.
3. Computes `$q^T k$` (a GEMV operation) and the softmax (max subtraction, exponentiation, sum normalization) entirely in registers.
4. Computes the attention-weighted value `$\text{softmax}(q^T k) \cdot v$` as another GEMV in registers.
5. Writes the output to HBM.

The key optimization is avoiding SRAM-to-register data movement for the intermediate attention weights `$w_{\text{reg}}$` (size `$1 \times w$`), which remain in registers throughout the computation.

**Micro-benchmarks (Appendix B).** The paper provides micro-benchmarks for each kernel against baseline implementations:
- **Forward pass (Figure 5):** The BASED kernel achieves 40–175ms versus the PyTorch baseline (which runs out of memory at larger batch sizes and sequence lengths) and 20–40% faster than the Fast Transformers kernel.
- **Recurrent update (Figure 6):** At batch size 256, the BASED kernel achieves approximately 0.15ms versus approximately 0.45ms for PyTorch—a 3× speedup.
- **Sliding window generation (Figure 7):** The BASED kernel achieves approximately 0.04–0.16ms across batch sizes 50–250, roughly 2× faster than FlashAttention's sliding window function at the same window size.

**End-to-end benchmarks (Figure 4).** At 1.3B parameters on a single H100 GPU:
- **Prefill at 4K sequence length:** BASED achieves 161.71 tokens/ms, 56% faster than FlashAttention-2 (103.50 tokens/ms) and 44% faster than Mamba (112.22 tokens/ms).
- **Generation at 1024 tokens, batch size 128:** BASED achieves 24.28 tokens/ms, **24× higher throughput** than FlashAttention-2 (0.99 tokens/ms) and 95% of Mamba's throughput (25.69 tokens/ms). The recurrent formulation eliminates the growing KV-cache, while FlashAttention-2's throughput degrades as the cache accumulates.
- **At 360M parameters:** BASED's generation throughput is 47.23 tokens/ms, 98% higher than FlashAttention-2 (23.82 tokens/ms) and 18% higher than Mamba (39.95 tokens/ms).

The paper notes that the custom kernel "unlocks the efficiency of BASED"—without it, the baseline Fast Transformers implementation is actually slower than FlashAttention-2, negating the theoretical efficiency advantages.

#### Summary of Design Choices and Their Justifications

- **2nd-order Taylor feature map over Performer/CosFormer:** Empirically on the Pareto frontier of the memory-recall tradeoff (Figure 3); expands state size without increasing parameter count (the `$d'^2$` terms come from the outer product structure, not learned projections); prior work (Zhang et al., 2024) demonstrated strong performance on associative recall with Taylor maps.
- **Feature dimension `$d'=16$` over larger or smaller values:** Larger values (24, 32) provide diminishing returns on both perplexity and AR (Table 6: 2.00 vs. 2.02 vs. 2.07); smaller values (8) degrade recall capacity (2.18 AR perplexity); `$d'=16$` balances state size (273 effective features) with quality.
- **Small sliding windows (64–128) over large windows (4096):** Guided by tensor core properties—`$64 \times 64$` matrices have similar latency to `$16 \times 16$` (Figure 1, left), and larger matrices become compute-bound; the global linear attention handles long-range modeling, so the sliding window only needs to provide local precision.
- **Three layer types in approximately 20/20/60 ratio:** Linear attention for global interactions, sliding window attention for local precision, convolutions for additional local operations; the 60% convolution allocation leverages their low recurrent state cost (filter width 3) while providing most of the model's capacity for general language modeling.
- **No input-dependent decay in main results:** Removing decay does not affect relative architectural trends (Appendix C); decay provides small perplexity gains at 10B tokens (Table 6) but introduces additional complexity (parallel scan or per-head projection) that is not necessary for competitive performance.
- **IO-aware CUDA kernels over Fast Transformers baseline:** The baseline uses non-IO-aware feature map computation in Python and a separate causal dot-product kernel, resulting in excessive HBM-SRAM and SRAM-register data movement; the fusion in Algorithms 1–3 reduces data movement by `$O(2BHN\tilde{d})$` bytes (HBM) and `$O(BHN\tilde{d}d)$` bytes (SRAM-to-register), making the implementation compute-bound and enabling practical speedups.
- **Partitioning KV-state across warps (8 warps for 2nd-order term):** The `$d'^2 \times d$` state is too large for a single warp's register budget; partitioning across 8 warps (each handling 2 slices of the 16-slice decomposition) keeps the state in registers across iterations, avoiding the SRAM bottleneck; this is feasible because the 2nd-order Taylor expansion's outer product computation can be parallelized across dimensions.
- **16-token tile size:** Matches tensor core tile dimensions (`$16 \times 16$`), enabling efficient use of matrix multiplication hardware.

## 4. Key Insights and Innovations

### Innovation 1: The Memory-Recall Tradeoff as a Fundamental, Measurable Architectural Axis

The paper's most significant conceptual contribution is not any specific model, but the **systematic characterization and formalization of the memory-recall tradeoff as a first-class architectural design axis**. Prior to this work, the field evaluated efficient architectures primarily on aggregate perplexity — a metric that, as the paper convincingly demonstrates, masks critical differences in recall capability. Individual architectures (Mamba, H3, Hyena, RWKV) were proposed as point solutions, each claiming to "match attention" on language modeling quality while offering efficiency gains. The paper shows this framing is inadequate: "matching attention on perplexity" obscures the fact that these architectures sit at **different points on a fundamental Pareto frontier**, and that moving along this frontier involves trading off memory consumption against recall capacity in ways that prior work did not systematically measure.

What makes this contribution intellectually distinctive is the **diagnostic methodology**, not just the observation that there's a tradeoff. The paper constructs a controlled experimental framework — the MQAR synthetic task with varied hyperparameters mapped to exact state size calculations — that isolates recall capacity from other language modeling capabilities. By plotting recall accuracy against recurrent state size (in bytes) for six different architecture classes on the same axes (Figure 2), the paper reveals something that aggregate perplexity comparisons could never show: **not all architectures make equal use of a fixed memory budget**. Mamba expands the Pareto frontier beyond H3 and Hyena, meaning it achieves higher recall for the same state size. BASED expands it further. Attention sits at the extreme upper-right corner — perfect recall, unbounded memory. The convolutional architectures (H3, Hyena) fall below the frontier entirely.

This reframes the architecture design problem from "how do we match attention's perplexity with lower cost?" to **"where on the recall-memory Pareto frontier should we operate, and how do we move along it?"** The answer is not a single architecture but a family of configurations, controlled by hyperparameters (feature dimension `d'`, window size `w`) that smoothly interpolate between efficient low-recall models and expensive high-recall models. This is conceptually analogous to how the Chinchilla scaling laws (Hoffmann et al., 2022) reframed pretraining from "train the biggest model possible" to "trade off model size and data optimally for a given compute budget" — but applied to the architecture-memory-recall axis rather than the pretraining compute allocation axis.

The theoretical results in Section 3.2 and Appendix F strengthen this contribution from "empirical observation" to **"fundamental architectural constraint."** Theorem 3.1 (any recurrent model needs Ω(N) bits of state for MQAR) establishes that the tradeoff is information-theoretic, not an artifact of specific design choices. Theorem 3.4 (gated convolutions need Ω(log log N) layers for AR, while attention solves it in O(1) layers) provides a mechanistic explanation for *why* H3 and Hyena fall below the Pareto frontier — their recall capacity is fundamentally constrained by depth requirements that grow with sequence length, while attention's is not. This combination of empirical characterization + theoretical lower bounds + constructive upper bounds (showing tightness) makes the tradeoff both **credible** and **actionable**: it's a real constraint, but architectures can be designed to push the frontier outward.

### Innovation 2: Hybridization as Pareto Frontier Expansion, Not Just Model Combination

Combining sparse and linear attention is not new — Scatterbrain (Chen et al., 2021a), BigBird (Zaheer et al., 2020), and Longformer (Beltagy et al., 2020) all did it before. What distinguishes BASED is **why** the combination works and **how** the specific hybridization hyperparameters are chosen.

The paper's insight is that linear attention and sliding window attention have **complementary failure modes** on the recall task. Linear attention provides global, long-range token interactions with a fixed-size recurrent state — but lacks the "sharp selectivity" of the exponential softmax for precise local token comparisons. Sliding window attention provides exact, sharp local attention — but its recall range is bounded by the window width. Neither primitive alone can navigate the Pareto frontier: linear attention (Figure 1, center, dark blue) plateaus at sub-perfect recall regardless of state size because it can't do the precise local shifts; sliding window attention (light blue) improves with window size but requires impractically large windows (and thus large states) to achieve long-range recall. Their combination (orange) achieves near-perfect recall at much smaller state sizes than either alone.

This is **not** the standard machine learning story of "ensembling improves performance." It's a specific claim about the **functional decomposition of associative recall** into two sub-operations that map onto different architectural primitives: (1) **long-range retrieval** (finding which past position contains the relevant key-value pair), which linear attention handles through its global recurrent state, and (2) **local token comparison** (precisely matching the query against candidate keys in the retrieved neighborhood), which exact softmax attention within small windows handles through its sharp exponential selectivity. The theoretical results in Appendix F support this decomposition: Proposition F.8 shows linear attention can be simulated by BaseConv with poly-log layers, meaning it's more efficient than pure gated convolutions for long-range interactions, while Proposition F.16 shows attention (with exact softmax) solves MQAR in constant layers by exploiting the sharp XNOR-then-AND operations that require precise local comparisons.

The **TCWINDOW design principle** — selecting window sizes based on GPU tensor core properties (64–128 tokens, multiples of 16) rather than modeling considerations — is a second-order insight that makes the hybridization **practical**. Prior sliding window attention implementations (Mistral-7B uses `w=4096`) chose window sizes to maximize recall range, implicitly accepting the latency penalty. By offloading long-range interactions to linear attention, BASED can use windows so small (64 tokens) that they occupy at most `64 × 64` matrix multiplication tiles — the sweet spot where tensor core latency is minimized (Figure 1, left) — while still achieving high recall through the complementary linear attention component. This is a **hardware-architecture co-design** insight: the functional decomposition (long-range vs. local) aligns with a hardware efficiency decomposition (cheap large-state linear attention vs. expensive small-state exact attention), and the hyperparameter choices that maximize quality also maximize throughput.

The ablation results in Table 6 confirm that the combination is more than the sum of its parts: removing either sliding window attention or convolutions degrades both AR perplexity and downstream recall accuracy, with the combined model (all three layer types) achieving the best results across all metrics.

### Innovation 3: A Negative Result That Redirects Research Effort — Gated Convolutions Are Fundamentally Recall-Limited

The paper provides a significant **negative result** that changes how the field should think about a broad class of architectures. Arora et al. (2023a) previously showed that gated convolution architectures (H3, Hyena) struggle with associative recall empirically and provided upper bounds on their efficiency (showing they *can* solve AR with sufficient layers/parameters). The current paper extends this to **lower bounds**: Theorem 3.2 and Theorem 3.4 prove that data-independent BaseConv — the canonical formalization of any architecture built from gating and convolution primitives — **requires** Ω(log log N) layers to solve associative recall, while attention solves it in O(1) layers. Theorem 3.2 further shows that when the vocabulary size `c = 2^d` (natural binary encoding), at least log(2d) layers are needed.

This is not just "H3 and Hyena are worse than attention at recall" — that's an empirical observation that could be fixed with better training or hyperparameters. This is a **structural limitation**: any architecture in this class, regardless of training procedure, parameter count, or specific gating mechanism, will have its recall capacity fundamentally bounded by depth requirements that grow with sequence length or vocabulary size. The theoretical result explains **why** the convolutional architectures fall below the Pareto frontier in Figure 2: they are not just undertrained or poorly configured — they are architecturally incapable of making efficient use of a fixed memory budget for recall in the way that attention or input-dependent recurrences (Mamba, BASED) can.

The significance of this negative result extends beyond the specific architectures studied. It provides a **formal diagnostic for evaluating future architectures**: if a proposed model can be simulated by BaseConv with constant-factor overhead in depth, then it inherits the same recall limitations. Conversely, if a model achieves strong recall with constant depth (like attention), it must be doing something that BaseConv cannot — providing a constructive research direction. Proposition F.8 shows that linear attention can be simulated by BaseConv with only poly-logarithmic overhead, while the lower bounds show BaseConv needs logarithmic depth itself — suggesting linear attention sits at a "sweet spot" of efficiency for recall without requiring the full attention mechanism.

The tightness result (Theorem F.30, showing O(max(log log c, log log N)) BaseConv layers suffice) prevents this from being an overly pessimistic finding: the lower bounds are achievable, meaning the analysis correctly captures the fundamental limitation rather than just providing a weak bound. The practical implication is clear: **the field should shift research effort away from pure gated convolutions as a path to attention-quality recall and toward input-dependent sequence mixers (like selective SSMs or linear attention) that can achieve attention-like recall efficiency.**

### Innovation 4: IO-Awareness as a First-Class Design Constraint That Determines Architectural Viability

The paper makes a meta-contribution about **how efficient architectures should be designed and evaluated**. Linear attention has been theoretically appealing since Katharopoulos et al. (2020a) — O(Nd²) training, O(1) generation — but practically disappointing: implementations were slower than FlashAttention-2 despite the theoretical advantages (Dao et al., 2022). The paper identifies that this gap between theory and practice is not incidental but **determines whether an architecture is viable at all**. Without IO-aware kernels, BASED's baseline implementation (using the Fast Transformers causal dot-product kernel, Vyas et al., 2020) is actually slower than FlashAttention-2 (Figure 4), negating the entire motivation for using linear attention in the first place.

The innovation is not in any single optimization technique — tiling, kernel fusion, and register-level state management are well-established in GPU programming. It's in the **design philosophy**: treat IO-awareness as a constraint that shapes architectural choices from the beginning, not as an implementation detail to optimize post-hoc. Three architectural decisions are directly driven by this philosophy:

1. **The choice of the 2nd-order Taylor series feature map** over alternatives like Performer or CosFormer is not just about quality — it's about what can be efficiently computed in CUDA. The Taylor map's structure (constant term + linear term + outer-product quadratic term) admits a natural decomposition into diagonal (causal attention within a 16-token tile) and off-diagonal (cumulative KV-state) computations that map cleanly onto the GPU's warp-level parallelism. The outer product for the 2nd-order term can be partitioned across 8 warps, each handling 2 of 16 slices of the KV-state, keeping the large state in registers rather than repeatedly moving it through SRAM.

2. **The TCWINDOW size (64–128)** is chosen by measuring Cutlass GEMM latency as a function of matrix dimension (Figure 1, left), identifying the point where latency stops decreasing with smaller dimension sizes, and setting the window to match that sweet spot. This is a hardware-first design decision, not a modeling-first one.

3. **The 16-token tile size** throughout the kernel design is dictated by tensor core dimensions (16×16), enabling efficient use of matrix multiplication hardware.

This design philosophy has implications beyond BASED. As the paper shows, architectures like Mamba, which use input-dependent recurrences requiring parallel scans, achieve strong throughput without custom CUDA kernels because their operations map naturally onto existing optimized primitives. The paper's approach suggests that **the "efficiency" of an architecture should be measured by its wall-clock throughput after hardware-aware optimization, not by its asymptotic complexity**, and that architectural innovations should be evaluated on whether they admit efficient implementations on real hardware. This is a methodological contribution to how the field compares and develops efficient architectures, not just a technical contribution to one specific model.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The primary dataset is the Pile (Gao et al., 2020), an 800GB corpus of diverse English text used for pretraining. For downstream evaluation, the paper uses SWDE (semi-structured HTML information extraction, Lockard et al., 2019), FDA (unstructured PDF information extraction, Arora et al., 2023b), SQUAD (reading comprehension), and the LM Eval Harness suite (SuperGLUE, ARC, PIQA, WinoGrande, HellaSwag, LAMBADA; Gao et al., 2023). For DNA modeling, the HG38 human genome dataset (Nguyen et al., 2023) and GenomicBenchmarks classification tasks (Gresova et al., 2022) are used. Synthetic recall experiments use the Multi-Query Associative Recall (MQAR) task from Arora et al. (2023a).

- **Base model(s).** All language modeling experiments train models from scratch at two scales: approximately 360M parameters and 1.3B parameters, with training budgets of 10B, 30B, and 50B tokens from the Pile. The architectures compared include Transformer++ (Llama-style with Rotary encodings, RMSNorm, SwiGLU; Touvron et al., 2023), Mamba (Gu and Dao, 2023), H3 (Fu et al., 2023a), Hyena (Poli et al., 2023), RWKV v5 (Peng et al., 2023), and Gated Linear Attention (Yang et al., 2023). BASED is the proposed architecture. For synthetic MQAR experiments, models are trained from scratch with varying hyperparameters to sweep the recurrent state size.

- **Metrics.** For language modeling, the primary metric is **perplexity** on the Pile test set, computed using the GPT-2 BPE tokenizer (Radford et al., 2019). The paper additionally reports perplexity on two slices of the test set following Arora et al. (2023a): **associative recall (AR) tokens** (final positions of bigrams that previously occurred in context but ≤1250 times in training data) and **other tokens** (all remaining tokens). For information extraction (SWDE, FDA), the metric is **accuracy** — whether the generated text contains the ground-truth value (case-insensitive substring match). For SQUAD, the metric is **F1 score**. For LM Eval Harness tasks, standard metrics are used (LAMBADA perplexity and accuracy, HellaSwag normalized accuracy, PIQA accuracy, ARC-challenge normalized accuracy, ARC-easy accuracy, WinoGrande accuracy). For synthetic MQAR, the metric is **accuracy** — the fraction of queries for which the model correctly predicts the associated value. For efficiency, **throughput** is measured in tokens per millisecond (tok/ms) for both prefill (processing the prompt) and generation (next-token prediction) on a single NVIDIA H100 GPU.

- **Baselines.** The paper compares against **Transformer++** (standard softmax attention with modern improvements: Rotary position encodings, RMSNorm, SwiGLU activations; Touvron et al., 2023), **Mamba** (selective state-space model with input-dependent recurrences; Gu and Dao, 2023), **H3** (gated state-space model with multiplicative interactions; Fu et al., 2023a), **Hyena** (gated convolution with implicit long convolutions; Poli et al., 2023), **RWKV v5** (attention-free RNN with token mixing and channel mixing; Peng et al., 2023), and **Gated Linear Attention (GLA)** (linear attention with gating and chunk-wise recurrence; Yang et al., 2023). For efficiency benchmarks, **FlashAttention-2** (Dao, 2023) serves as the optimized softmax attention baseline. For the BASED variant without custom IO-aware kernels, the **Fast Transformers CUDA kernel** (Vyas et al., 2020; Katharopoulos et al., 2020b) is used as the linear attention implementation baseline.

- **Generation budget / compute accounting.** For synthetic MQAR experiments, recurrent state size (in bytes) is the primary independent variable, computed using exact formulas for each architecture class (Appendix E.2). For language model pretraining, all models process exactly the same tokens of training data in the same order, eliminating data-order confounds. For throughput benchmarks, generation budget is measured in tokens processed per millisecond, with separate measurements for prefill throughput (processing a prompt of 4,096 tokens at batch size 2) and generation throughput (producing 1,024 tokens at varying batch sizes). All efficiency measurements exclude the time to update the KV-cache for attention-based models and Rotary encoding processing for sliding window attention.

- **Cross-validation / statistical protocol.** For synthetic MQAR experiments, the paper trains on sequences of 256 tokens and evaluates on sequences of 1,024 tokens, testing generalization to longer contexts. For language modeling, all models see the same training data in identical order, ensuring fair comparison. For downstream recall-intensive tasks (SWDE, FDA, SQUAD), models are evaluated zero-shot without fine-tuning. For SQUAD, the questions are reformatted by GPT-4 to convert question-answer pairs into declarative sentences ending with the answer, and 40% of reformatted sentences that do not end with the answer are discarded, yielding a final dataset of 2,984 questions from the validation set. For throughput benchmarks, measurements are averaged over 20 repetitions on an H100 GPU using CUDA graph capture during next-token prediction (NVIDIA, 2019). The paper does not report confidence intervals or standard deviations for any result.

### Main Quantitative Results

#### 5.1 Synthetic Recall: Characterizing the Memory-Recall Tradeoff (Figure 2, Figure 3)

**Headline finding: There is a fundamental tradeoff between recurrent state size and associative recall accuracy that holds within and across six architecture classes, with Mamba and BASED expanding the Pareto frontier beyond convolutional architectures (H3, Hyena).**

Figure 2 plots MQAR accuracy against recurrent state size (in bytes) for attention, sliding window attention, Mamba, H3, Hyena, and BASED, with each architecture represented by multiple points corresponding to different hyperparameter configurations (e.g., varying model dimension, feature dimension, window width). The key patterns:

- **Attention** achieves perfect recall accuracy (~1.0) but its recurrent state size grows linearly with sequence length (determined by the task's N=1024 evaluation length, not a model hyperparameter). It sits in the upper-right quadrant — best recall, largest memory.

- **Sliding window attention** shows a clear monotonic relationship: as window width increases from 8 to 1,024 tokens, accuracy improves from near-zero to near-perfect, while state size grows proportionally. This curve traces a smooth tradeoff from the lower-left (efficient, low-recall) to upper-right (expensive, high-recall).

- **Mamba** expands the Pareto frontier beyond sliding window attention: for a given state size, Mamba achieves higher recall accuracy than sliding window attention, meaning it makes more efficient use of limited memory. However, Mamba cannot reach perfect recall even at its largest state size (accuracy plateaus around ~0.85–0.90), falling short of attention.

- **BASED** further expands the frontier beyond Mamba: by varying the feature dimension `d'` and model dimension `d`, BASED achieves higher recall at equivalent or smaller state sizes. At the high-recall end, BASED approaches attention's performance with substantially smaller state size.

- **H3 and Hyena** fall well below the Pareto frontier, requiring much larger states to achieve the same recall as Mamba or BASED, and plateauing at substantially lower maximum accuracy (~0.4–0.6). This empirically confirms the theoretical limitations proven in Theorem 3.2 and Theorem 3.4.

**Extended comparison across feature maps (Figure 3).** Figure 3 isolates the behavior of linear attention with different feature maps, using a harder MQAR setting (256 key-value pairs). The key findings:

- **Top panel (state size vs. accuracy):** The Taylor series feature map and simple alternatives (`ϕ_PosELU`, `ϕ_ReLU`) sit at the Pareto frontier of the memory-recall tradeoff. More sophisticated feature maps (`ϕ_CosFormer`, `ϕ_Performer`) fall below the frontier — they require larger states for equivalent recall or achieve lower maximum recall.

- **Bottom panel (parameter count vs. accuracy):** The Taylor feature map achieves high recall with significantly fewer parameters than alternatives, because the `d'^2` second-order terms come from the outer product structure of the feature map itself rather than from learned projection matrices. For example, to achieve ~0.8–0.9 accuracy, the Taylor map uses approximately 10^5 parameters while `ϕ_CosFormer` requires approximately 10^6 parameters.

**Additional architectures (Figure 8).** An extended version of Figure 2 in Appendix D.1 includes NystromFormer (Xiong et al., 2021), BigBird (Zaheer et al., 2020), and ScatterBrain (Chen et al., 2021a), all of which fall below the Pareto frontier established by Mamba and BASED.

All three architectures converge to nearly identical overall perplexity (6.28–6.30). Mamba achieves the best "other" perplexity at 6.78 — confirming that Mamba's core language modeling (non-recall) capability is actually superior — but its AR perplexity of 1.74 is the worst of the three, offsetting this advantage. This is the most striking illustration of the paper's central argument: **aggregate perplexity parity masks a systematic tradeoff where architectures differ in their recall vs. non-recall capability profiles**.

**Headline finding: BASED systematically outperforms Mamba on recall-intensive downstream tasks, with the gap widening as training budget increases. At 1.3B/50B, BASED beats Mamba by an average of 10.36 accuracy points across three recall-intensive benchmarks.**

**Information Extraction on SWDE (Table 1).** This task requires extracting structured attributes from raw HTML websites (e.g., extracting the movie runtime from an IMDB page). At 1.3B/50B:

- Transformer++: 76.50% accuracy.

The gap to Transformer++ narrows from 23.86 points at 10B to 12.05 points at 50B, showing that extended training helps BASED close the recall quality gap to attention. At 360M/30B, the BASED-Mamba gap is 17.38 points (45.01 vs. 27.63), compared to 5.49 points at 10B — the gap widens with more training, suggesting Mamba's recall limitations are not merely a data-efficiency issue.

**Information Extraction on FDA (Table 1).** This task requires extracting key-value pairs from FDA PDF documents. At 1.3B/50B:

- Transformer++: 80.47% accuracy.
- BASED: 30.40% — trails Transformer++ by 50.07 points (a dramatic gap).
- Mamba: 18.51% — trails BASED by 11.89 points.

FDA is much harder than SWDE for both sub-quadratic architectures, with Transformer++ showing a dominant advantage. At 360M/30B, the absolute numbers are lower: Transformer++ 63.79%, BASED 16.45%, Mamba 8.71%. The BASED-Mamba gap of 7.74 points at 360M scales to 11.89 points at 1.3B, again showing that Mamba's recall deficit is not eliminated by scale.

**Question Answering on SQUAD (Table 1).** At 1.3B/50B:

- Transformer++: 43.47 F1.
- BASED: 41.62 F1 — trails Transformer++ by 1.85 points.
- Mamba: 35.92 F1 — trails BASED by 5.70 points.

SQUAD shows the smallest gaps among the three recall tasks, with BASED achieving 95.7% of Transformer++'s F1 score. At 360M/30B, BASED (32.67) actually outperforms Transformer++ (25.07) by 7.60 F1 points — the only recall-intensive task where a sub-quadratic architecture beats attention, though this result at the smaller scale warrants cautious interpretation.

**Average recall-intensive performance (computed from Table 1).** At 1.3B/50B, averaging the three recall tasks (SWDE, FDA, SQUAD):
- Transformer++: (76.50 + 80.47 + 43.47) / 3 = 66.81 average.
- BASED: (64.45 + 30.40 + 41.62) / 3 = 45.49 average.

This is counterintuitive: one might expect that more training would allow all architectures to converge, but instead the recall gap widens. This suggests Mamba has a **structural limitation** in recall that cannot be overcome by additional data or optimization steps — consistent with the theoretical results that attention-free architectures have fundamental constraints on recall efficiency (though Mamba, with its input-dependent recurrences, is not directly covered by the gated-convolution lower bounds).

#### 5.4 Efficiency Benchmarks (Figure 4, Figure 1)

**Headline finding: With IO-aware kernels, BASED achieves 24× higher generation throughput than FlashAttention-2 at 1.3B parameters (batch size 128, generating 1024 tokens). During prefill, BASED is 56% faster than FlashAttention-2 at 4K sequence length.**

**Prefill throughput (Figure 4, left).** On a single H100 GPU at 1.3B parameters and batch size 2, processing a prompt of growing sequence length:

- At 4K tokens: BASED achieves 161.71 tok/ms (Table 1), Transformer++ (FlashAttention-2) achieves 103.50 tok/ms, Mamba achieves 112.22 tok/ms. BASED is 56% faster than FlashAttention-2 and 44% faster than Mamba.
- At 360M parameters (batch size 2): BASED achieves 514.57 tok/ms, Transformer++ 207.77 tok/ms, Mamba 267.09 tok/ms. BASED is 148% faster than FlashAttention-2 and 93% faster than Mamba.
- At 8K sequence length (1.3B): BASED's advantage grows as FlashAttention-2's quadratic memory scaling causes it to run out of memory earlier (the line is cut off in Figure 4).
- The **baseline BASED implementation** (using the Fast Transformers CUDA kernel without IO-aware optimizations) performs significantly worse — its throughput line in Figure 4 is labeled separately and falls far below both FlashAttention-2 and Mamba, demonstrating that "the custom kernel introduced in our work unlocks the efficiency of BASED."

**Generation throughput (Figure 4, right).** At 1.3B parameters, generating 1024 tokens at varying batch sizes:

- At batch size 128: BASED achieves 24.28 tok/ms, FlashAttention-2 achieves 0.99 tok/ms, Mamba achieves 25.69 tok/ms. BASED provides **24.5× higher throughput** than FlashAttention-2 and reaches **95% of Mamba's throughput**.
- At batch size 1: BASED achieves approximately 19 tok/ms, FlashAttention-2 approximately 16 tok/ms, Mamba approximately 20 tok/ms. The gap between architectures narrows at small batch sizes because per-token overhead dominates.
- At batch size 256: FlashAttention-2's throughput drops further (to approximately 0.8 tok/ms) as the growing KV-cache becomes the bottleneck, while BASED and Mamba maintain near-constant throughput independent of generation length (their recurrent states do not grow with sequence length).
- At 360M parameters (generating 1024 tokens): BASED achieves 47.23 tok/ms, FlashAttention-2 23.82 tok/ms (98% improvement), Mamba 39.95 tok/ms (18% improvement). BASED **exceeds Mamba's throughput** at this scale, unlike at 1.3B where Mamba maintains a slight edge.

**Why the generational throughput advantage is so large over FlashAttention-2.** During generation, attention-based models must compute `q^T K` for all previous keys and values stored in the expanding KV-cache. At token position 1024, this means computing dot products with 1023 stored key-value pairs — an `O(N)` operation per token that grows linearly with generation length. Linear attention's recurrent formulation (Equation 3 in the paper) replaces this with an `O(1)` update: `S_t = S_{t-1} + φ(k_t)v_t^T` and `y_t = φ(q_t)^T S_t / (φ(q_t)^T z_t)`, where the KV-state `S_t` is a fixed-size matrix. The cost per generated token is constant regardless of how many tokens have already been generated. This asymptotic advantage translates directly to wall-clock throughput at long generation lengths.

**The TCWINDOW latency justification (Figure 1, left).** The paper benchmarks Cutlass GEMM execution time as a function of matrix dimension, showing that `64 × 64` matrix multiplications have approximately the same latency as `16 × 16` (tensor core native tile size), while larger dimensions incur growing latency. This hardware measurement directly motivates the choice of small sliding windows (64–128 tokens): the computational cost of the sliding window attention is minimized at these sizes, and increasing the window would increase latency without proportional recall benefit (since the linear attention component already provides global interactions).

### Ablation Studies and Robustness Checks

All ablations use the 362M parameter BASED configuration trained to 10B tokens on the Pile (Table 6). Each row modifies one aspect while holding the rest of the architecture at the default configuration (Taylor 2nd-order feature map, `d'=16`, sliding window 64, convolutions enabled, input-dependent decay enabled).

**Feature map choice (Taylor vs. Performer vs. CosFormer):** Replacing the Taylor 2nd-order feature map with Performer (random Fourier features with `d'=16`, effective feature size 16) dramatically degrades quality: overall perplexity 9.08 (vs. 8.65 for Taylor), AR perplexity **8.53** (vs. 2.07), and downstream recall collapses: SWDE accuracy drops from 29.16 to 8.10, FDA from 11.71 to 0.36, SQUAD from 25.07 to 7.47. Performer's poor AR perplexity of 8.53 indicates near-random performance on recall tokens — effectively no recall capability. CosFormer at `d'=16` (effective feature size 32) performs better than Performer but substantially worse than Taylor: 9.03 overall, 2.42 AR, 19.35 SWDE, 7.71 FDA, 24.63 SQUAD. **Expanding CosFormer's state size** to match Taylor's by increasing `d'` to 64 (effective feature size 128, via learned projections that increase parameter count) closes much of the gap: 8.82 overall, 2.18 AR, 25.47 SWDE, 9.07 FDA, 27.85 SQUAD. This confirms that state size, not just feature map expressiveness, is the critical variable — but the Taylor map achieves this larger state without extra learned parameters.

**Feature dimension `d'`:** Sweeping `d'` ∈ {8, 16, 24, 32}:
- `d'=8` (effective feature dim 45): 8.77 overall, 2.18 AR, 23.40 SWDE, 12.79 FDA, 22.35 SQUAD.
- `d'=16` (effective 273): 8.65 overall, 2.07 AR, 29.16 SWDE, 11.71 FDA, 25.07 SQUAD.
- `d'=24` (effective 325): 8.58 overall, 2.02 AR, 34.38 SWDE, 20.87 FDA, 24.77 SQUAD.
- `d'=32` (effective 561): 8.56 overall, 2.00 AR, 37.62 SWDE, 12.89 FDA, 26.74 SQUAD.

Overall and AR perplexity improve monotonically with `d'` but with diminishing returns: the jump from 8 to 16 reduces AR perplexity by 0.11 (2.18 → 2.07), from 16 to 24 reduces it by 0.05 (2.07 → 2.02), from 24 to 32 reduces it by 0.02 (2.02 → 2.00). The paper notes that "feature dimension √1024 = 32, where 1024 is the attention model dimension at the 360 parameter scale in our experiments," suggesting `d'=32` may saturate the information capacity of the model dimension, but the diminishing returns appear before this point. The default `d'=16` represents a practical sweet spot balancing state size (273 effective features, 17,745 recurrent state elements per head) against quality.

**Sliding window attention presence and size:** Removing sliding window attention entirely (keeping linear attention + convolutions): 8.91 overall (vs. 8.65), 2.11 AR (vs. 2.07), SWDE accuracy 28.62 (vs. 29.16), FDA 10.16 (vs. 11.71), SQUAD 24.50 (vs. 25.07). The degradation is modest — suggesting linear attention and convolutions compensate for most of the lost local precision. Increasing window size from 64 to 128: 8.61 overall, 2.06 AR, 32.13 SWDE, 14.39 FDA, 31.84 SQUAD — small improvements consistent with diminishing returns beyond the TCWINDOW-optimal size.

**Convolution presence:** Removing convolutions (keeping linear attention + sliding window): 8.74 overall (vs. 8.65), 2.09 AR (vs. 2.07). The overall and AR perplexity impact is small, but **downstream recall tasks show larger degradation**: SWDE drops from 29.16 to 24.66, FDA drops from 11.71 to **2.36** (a 5× reduction), SQUAD drops from 25.07 to 18.87. This asymmetric impact — small perplexity change, large downstream recall impact — suggests convolutions contribute to the specific local operations needed for structured information extraction rather than to general language modeling.

**Both local components removed:** Removing both sliding window attention and convolutions (keeping only linear attention with `d'=24`): 9.49 overall, 2.29 AR, 19.62 SWDE, 8.71 FDA, 11.33 SQUAD. This configuration, which is "pure linear attention," performs substantially worse than the full hybrid, confirming that both local components are necessary for competitive quality.

**Input-dependent decay:** Removing decay from the default configuration: 8.65 overall (identical), 2.04 AR (vs. 2.07 — marginally better), 22.95 SWDE (vs. 29.16 — worse), 12.34 FDA (vs. 11.71 — similar), 27.45 SQUAD (vs. 25.07 — better). The mixed results indicate decay has inconsistent effects, and the paper's decision to omit it from the main 30B and 50B training runs is supported by these findings — "removing the decay does not affect the overall trends for BASED relative to other architectures."

**Pure linear attention with CosFormer at increased state size:** Comparing the Taylor map at `d'=16` (effective 273) against CosFormer at `d'=64` (effective 128, with additional learned projections increasing parameter count), the Taylor map achieves slightly better overall perplexity (8.65 vs. 8.82) and AR perplexity (2.07 vs. 2.18) with lower parameter count. This confirms the Taylor map's advantage in memory-recall efficiency: it expands state size through its outer-product structure without requiring additional learned parameters.

### Critical Assessment

#### Does the paper demonstrate that BASED "expands the Pareto frontier of the throughput-recall tradeoff space beyond prior architectures"?

The evidence for this claim is strong at the architectural comparison level (Figures 2, 3) but has important boundary conditions that are not always clarified.

**What is well-supported:** Figure 2 directly shows that, for a given recurrent state size, BASED achieves higher MQAR accuracy than Mamba, H3, Hyena, and sliding window attention. The theoretical results (Section 3.2, Appendix F) provide a mechanistic explanation for *why* prior architectures (especially gated convolutions) fall below the frontier: they require depth that grows with sequence length for recall (Theorem 3.4), while attention solves it in constant depth (Proposition F.16). BASED's linear attention component has a poly-log simulation overhead (Proposition F.8) relative to BaseConv, suggesting it is structurally more efficient than gated convolutions for recall. The Pareto frontier expansion is demonstrated by varying BASED's controllable hyperparameters (`d'`, `d`, `w`) and showing that the resulting curve lies above and to the left of Mamba's curve.

**What is less clear:** The Pareto frontier characterization in Figure 2 is on a **single synthetic task** (MQAR) with **specific configurations**. The mapping from synthetic recall to real-world recall-intensive tasks (SWDE, FDA, SQUAD) is only partially validated. While BASED does outperform Mamba on these tasks (Table 1), the performance is nowhere near the ~100% MQAR accuracy that Figure 2 suggests for larger state sizes. At 1.3B/50B on SWDE, BASED achieves 64.45% — far below the near-perfect recall suggested by the synthetic experiments. This gap between synthetic and real-world performance is not explained: it could be due to the complexity of real-world recall (multi-hop, noisy contexts, ambiguous references), the limited model scale (1.3B parameters is small by modern standards), or the pretraining data distribution. The paper implicitly treats the MQAR results as a lower bound on what's architecturally possible, with real-world results representing a combination of architecture and training limitations, but this distinction is not made explicit.

A more thorough validation would include: (1) scaling MQAR to larger sequence lengths and key-value pair counts to see if the BASED-Mamba gap grows or shrinks; (2) adding real-world recall tasks with controlled difficulty levels to map synthetic performance onto practical capability; (3) measuring the memory-recall tradeoff on the real-world tasks themselves (e.g., by varying `d'` and measuring SWDE accuracy vs. generation memory).

---

#### Does the paper demonstrate that BASED "matches the strongest sub-quadratic models (e.g., Mamba) in perplexity and outperforms them on real-world recall-intensive tasks by 10.36 accuracy points"?

**The perplexity claim is solid but nuanced.** At both 360M and 1.3B scales, BASED and Mamba achieve nearly identical overall Pile perplexity (differences of 0.01–0.05 points at 30B and 50B tokens). Both trail Transformer++ by small margins that narrow with scale. This supports the claim that BASED is competitive on aggregate language modeling quality.

However, the paper's own finer-grained analysis reveals that this parity is achieved through **different capability profiles**: at 1.3B/50B, BASED has better AR perplexity (1.71 vs. 1.74) but worse "other" perplexity (6.82 vs. 6.78). Mamba is actually better at the non-recall, general language modeling portion of the task. The architectures are not "matching" in the sense of being interchangeable; they have complementary strengths that happen to average out to similar overall perplexity. This is an important nuance that the headline "matches in perplexity" obscures.

**The recall claim is strongly supported against Mamba but weakly against attention.** At 1.3B/50B, BASED out-scores Mamba on all three recall-intensive tasks: SWDE (+11.70), FDA (+11.89), SQUAD (+5.70). The average gap of ~9.8 points is close to the claimed 10.36. At 360M/30B, the gap is 10.36 exactly (SWDE +17.38, FDA +7.74, SQUAD +5.96). The gap grows with training scale (3.9 → 9.0 → 10.4 from 10B to 30B to 50B at 360M), which is a strong signal that the difference is architectural, not due to undertraining.

However, BASED still **substantially trails Transformer++** on recall-intensive tasks: at 1.3B/50B, BASED is behind by 12.05 points on SWDE, **50.07 points on FDA**, and 1.85 points on SQUAD. The FDA gap is enormous — Transformer++ achieves 80.47% while BASED achieves 30.40%. This suggests that even with expanded Pareto frontier, BASED has not "closed the gap to attention" on recall in any practical sense for real-world tasks, despite the synthetic MQAR results showing near-perfect recall at large state sizes. Either the effective recall range needed for tasks like FDA exceeds what BASED's state size provides, or the training procedure does not adequately teach the model to use its recall capacity for these specific tasks.

**Missing baseline: Mamba with increased state size.** The paper shows BASED can expand its state size by increasing `d'` and moving along the Pareto frontier. Mamba's state size can also be increased (by increasing `d_state`, its expansion factor). The paper uses the default Mamba configurations from Gu and Dao (2023) but does not explore whether scaling Mamba's state size to match BASED's would close or maintain the gap. If Mamba's recall scales similarly with state size, the claimed advantage might be about hyperparameter choices rather than architectural superiority.

---

#### Does the paper demonstrate that BASED provides "24× higher throughput on language generation than FlashAttention-2"?

**This claim is the best-supported in the paper, with important caveats about the measurement conditions.** The 24× figure comes from generation at batch size 128, 1024 tokens, 1.3B parameters on an H100 GPU (Figure 4, right; Table 1). The mechanisms are well-understood and not surprising: attention's generation throughput degrades as the KV-cache grows (FlashAttention-2: 0.99 tok/ms at batch 128), while linear attention's recurrent formulation maintains constant per-token cost (BASED: 24.28 tok/ms). The IO-aware kernels (Algorithms 1-3) are necessary for this advantage — without them, the baseline BASED implementation is slower than FlashAttention-2 (Figure 4).

**Caveats that qualify the claim:**
1. **The 24× figure is at a specific operating point** (batch size 128, 1024 generated tokens, 1.3B parameters). At smaller batch sizes (1-4), the advantage is much smaller (~1.2-3×). At 360M parameters, the advantage is ~2× over FlashAttention-2. The 24× figure represents the most favorable comparison point, not the typical advantage.
2. **FlashAttention-2 is an attention implementation, not an architecture optimized for generation.** It is designed for efficient training and prefill, not for maximizing generation throughput. The more relevant comparison is to Mamba, which achieves 25.69 tok/ms — 6% faster than BASED at 1.3B. The paper acknowledges this: BASED achieves "95% the throughput of the recurrent Mamba architecture." At 360M, BASED (47.23 tok/ms) is 18% faster than Mamba (39.95 tok/ms).
3. **The comparison excludes the cost of the sliding window and convolution layers.** BASED is a hybrid architecture where only ~20% of layers benefit from the recurrent linear attention formulation. The other ~80% of layers (sliding window attention and convolutions) have their own inference costs. The end-to-end benchmarks include these costs, but it means the 24× figure over FlashAttention-2 is for the full model, not for the linear attention component alone. The fact that the hybrid model still achieves such high throughput suggests the non-linear-attention layers are relatively efficient, but their individual contributions to the total latency are not measured.
4. **CUDA graph capture is used during generation** (NVIDIA, 2019), which reduces kernel launch overhead. The paper does not report whether the same optimization is applied to FlashAttention-2 and Mamba. If not, part of the throughput advantage may come from systems-level optimization rather than fundamental algorithmic efficiency.

---

#### Does the theoretical analysis strengthen the empirical findings?

**The theory is rigorous but disconnected from the architectural claims about BASED specifically.** The lower bounds (Theorem 3.1, 3.2, 3.4) establish fundamental limitations of recurrent models and gated convolutions for associative recall. These results explain why H3 and Hyena fall below the Pareto frontier — they are in the gated convolution class and thus depth-constrained. However:

- **The theoretical results do not cover Mamba.** Mamba uses input-dependent recurrences that are not captured by the data-independent BaseConv model used in the lower bounds. The paper acknowledges this (Corollary F.13 only covers the state-size lower bound for causal Mamba, not the layer lower bound). Mamba's position on the Pareto frontier (above H3/Hyena) is consistent with it avoiding the gated convolution limitations, but there is no theorem proving Mamba *cannot* be further improved to match attention.
- **The theoretical results do not directly characterize BASED's capabilities.** Proposition F.8 shows linear attention can be simulated by BaseConv with poly-log overhead, but this is a simulation result — it shows linear attention is *at most* poly-log worse than BaseConv, not that it achieves any specific lower bound. There is no theorem proving that BASED requires smaller state or fewer layers than Mamba for equivalent recall. The theoretical contribution is primarily **negative** (showing limitations of gated convolutions) and **comparative** (showing linear attention's simulation complexity), not **constructive** for BASED.
- **The upper bound (Theorem F.30)** shows O(max(log log c, log log N)) BaseConv layers suffice, establishing tightness of the lower bounds. But this result uses 1-hot encodings and at most one key match per query — a restricted setting that does not directly characterize real-world recall complexity.

The theory section is valuable for establishing the *existence* and *fundamental nature* of the memory-recall tradeoff, but its connection to the specific architectural claims about BASED (e.g., "expands the Pareto frontier") is correlational rather than causal. The experiments demonstrating BASED's superiority over Mamba on recall tasks are empirical, not theoretically guaranteed.

---

#### What experiments would have strengthened the paper?

1. **Scaling BASED to larger models (7B+ parameters) and longer training (100B+ tokens).** All experiments max out at 1.3B parameters and 50B tokens, which is small by modern standards (Mistral-7B, Llama-2-7B). It is unknown whether BASED's recall advantages over Mamba would persist, grow, or shrink at scales where both architectures have had sufficient training to approach their asymptotic capabilities. The trend of growing gap with training (Section 6.1) suggests it would persist, but this is extrapolation from three data points (10B, 30B, 50B at 360M).

2. **Direct comparison of BASED and Mamba at matched state sizes.** The paper controls state size for synthetic MQAR (Figure 2) by sweeping hyperparameters for each architecture, but for real-world language modeling, only default configurations are compared. An experiment scaling Mamba's `d_state` to match BASED's recurrent state size and measuring the resulting AR perplexity and downstream recall would clarify whether BASED's advantage is about state size or about how that state is structured.

3. **Ablation of the layer ratio (20/20/60 vs. other ratios).** The paper fixes the ratio of linear attention to sliding window to convolution layers at approximately 20/20/60 based on presumably preliminary experiments, but no ablation of this ratio is reported. Would 40/40/20 perform better on recall? Would 10/10/80 be more efficient without significant quality loss? The quantitative contribution of each component to the overall Pareto frontier expansion is not measured.

4. **A continuous difficulty-controlled real-world recall benchmark.** The paper uses SWDE, FDA, and SQUAD as recall-intensive tasks but does not control for problem difficulty within these benchmarks. A benchmark with controlled recall distance (how far back in the context the relevant information appears), number of distractors, and key-value pair count would allow mapping the synthetic MQAR findings onto real-world task performance and characterizing *where* on the difficulty spectrum BASED's advantages over Mamba are most pronounced.

5. **Memory consumption measurements, not just throughput.** The paper frames the tradeoff as "memory-recall" but the efficiency benchmarks measure only throughput (tokens/ms), not actual GPU memory usage. For deployment, peak memory consumption is often the binding constraint. Reporting the HBM footprint of the recurrent state for each architecture at different sequence lengths would complete the characterization of the Pareto frontier.

6. **Confidence intervals for all key results.** The paper does not report any measure of statistical uncertainty (standard deviations, confidence intervals, or standard errors) for pretraining perplexity, downstream accuracy, or throughput measurements. With a test set of 500 questions for MQAR and a single pretraining run per configuration, the stability of the reported differences (e.g., 0.03 AR perplexity difference between BASED and Mamba at 1.3B/50B) is unknown. The throughput measurements are averaged over 20 repetitions but no variance is reported.

---

#### Summary: What the experiments genuinely demonstrate vs. what they claim

**Solidly demonstrated:**
- There is a real, measurable tradeoff between recurrent state size and associative recall capacity that holds across diverse architectures (Figure 2).
- BASED, as a specific combination of linear attention, small sliding windows, and short convolutions, achieves competitive overall perplexity with Mamba and Transformer++ at scales up to 1.3B/50B (Table 1).
- BASED outperforms Mamba on synthetic and real-world recall-intensive tasks, with the gap widening with training scale (Table 1, MQAR).
- With custom IO-aware kernels, BASED's recurrent linear attention layers achieve generation throughput competitive with Mamba and far exceeding FlashAttention-2, whose throughput degrades with generation length (Figure 4).
- Gated convolution architectures (H3, Hyena) have fundamental depth requirements for recall that limit their position on the Pareto frontier (Theorem 3.4, Figure 2).

**Demonstrated with important qualifications:**
- "24× higher throughput than FlashAttention-2" is true at a specific operating point (batch 128, 1024 tokens, 1.3B) but the advantage is much smaller at lower batch sizes and the comparison to Mamba shows near-parity, not a 24× advantage.
- "Matches sub-quadratic models in perplexity" is true in aggregate but masks complementary capability profiles — BASED is better at recall, Mamba is better at non-recall prediction (Table 1, 1.3B/50B).
- "Expands the Pareto frontier" is demonstrated on synthetic MQAR but the mapping to real-world recall task performance is incomplete (large gap to attention on FDA, Section 6.1).
- The theoretical lower bounds explain gated convolution limitations but do not directly characterize BASED's architectural advantages over Mamba, which is not in the gated convolution class.

**Not demonstrated / open questions:**
- Whether BASED's advantages over Mamba persist at larger scales (7B+ parameters, 100B+ tokens).
- Whether the recall advantage is due to architectural structure or simply to larger effective state size at matched parameter count.
- Whether the IO-aware implementation is necessary for practical deployment or whether similar optimizations applied to Mamba would close or reverse the throughput gap.
- The optimal ratio of layer types in the hybrid architecture and the individual contribution of each component to the overall quality-efficiency tradeoff.

## 6. Limitations and Trade-offs

### Small Model Scale and Single Training Budget Ceiling

**The assumption or constraint.** All language modeling experiments train models at two modest scales — approximately 360M and 1.3B parameters — with a maximum budget of 50B tokens from the Pile. The paper does not train models in the regime where modern production LLMs operate (7B-70B parameters, 1T+ tokens). It acknowledges that all experiments use "models up to the 1.3Bn parameters" (Section 1), and that the PaLM 2-S* model in related work is "representative of the capabilities of many contemporary LLMs" — a claim inherited from that work's framing, not empirically validated here.

**The consequence.** It is unknown whether the central claims — that BASED expands the Pareto frontier beyond Mamba, that it outperforms Mamba by 10.36 accuracy points on recall tasks, that the gap widens with training scale — persist at production scales. Three mechanisms could undermine these claims at larger scales:

- **Diminishing returns on recall from linear attention state size**: If recall quality saturates at a given feature dimension `d'` regardless of model size, then simply scaling model width (more heads, larger `d`) without proportionally scaling `d'` means the recall advantage as a fraction of total model capacity shrinks.
- **Mamba's recall scaling**: Mamba's input-dependent recurrences may learn to compensate for recall limitations given sufficient training data and model capacity — the structural limitation suggested by the synthetic experiments may be surmountable at scale.
- **Training budget sufficiency**: 50B tokens is a small fraction of the Pile's 800GB (roughly 200B+ tokens after tokenization). It is plausible that Mamba is simply less data-efficient at learning recall than BASED, and that the gap would close with enough training — the paper's own observation that the gap "grows" from 10B to 50B could reflect relative training progress rather than asymptotic differences.

**What evidence exists in the paper.** The gap between BASED and Mamba on recall-intensive tasks does widen with training (Section 6.1, Table 1): at 360M, the average gap goes from 3.9 points (10B) to 9.0 (30B); at 1.3B, from 9.0 (10B) to 10.4 (50B). This is the strongest signal in the paper that the recall advantage is not purely a data-efficiency artifact. However, three data points per scale (10B, 30B, 50B for 360M; 10B, 50B for 1.3B) is insufficient to establish an asymptotic trend. The curve could still flatten or reverse.

**Mitigation status.** The paper does not address this limitation beyond acknowledging the scale of experiments in Section 1. No extrapolation analysis, no scaling law curve, and no training beyond 50B tokens is presented. The claim that BASED "expands the Pareto frontier" is therefore validated only within the 360M-1.3B range. Section 8 of the original paper (Conclusions) does not mention scaling to larger models as future work, focusing instead on combining search and revisions. This is a notable omission given that the architectural claims would need to hold at larger scales to be practically relevant.

---

### Single Benchmark, Single Modality, Single Model Family

**The assumption or constraint.** All quality evaluations — perplexity, downstream recall tasks, LM Eval Harness — use the Pile corpus for pretraining (English text, GPT-2 BPE tokenizer) and a specific set of English-language benchmarks (SWDE, FDA, SQUAD, SuperGLUE, ARC, PIQA, WinoGrande, HellaSwag, LAMBADA). The architecture was designed based on synthetic recall experiments (MQAR) using a specific token structure (key-value pairs followed by queries). The only non-language experiment is DNA modeling (HG38 pretraining, GenomicBenchmarks classification; Table 4, Table 5). The paper states it evaluates on "standard natural language understanding benchmarks" and "a suite of recall-intensive tasks" (Section 6) without claiming broader generality.

**The consequence.** Two distinct generalisation risks arise:

- **Domain specificity of the recall advantage**: The MQAR synthetic task models a specific type of recall — exact string matching between keys and queries in a structured sequence. Real-world recall in language tasks includes fuzzy matching, multi-hop reasoning, negation handling, and temporal ordering. BASED's advantage over Mamba on SWDE (structured HTML extraction) is 11.70 points at 1.3B/50B, but on FDA (unstructured PDF extraction) the absolute performance of both architectures is poor (30.40% vs. 18.51%) while Transformer++ achieves 80.47%. This enormous gap to attention on FDA suggests that the type of recall required for unstructured document extraction may not map well onto the MQAR-style associative recall that the architecture was designed to optimize. If the advantage disappears or reverses on certain recall subtypes, the architecture's utility depends on the recall characteristics of the target task — which the paper does not characterize.

- **Architectural generalizability**: The paper trains PaLM 2-style models (Transformer++) as the baseline, but does not test whether BASED's advantages persist if, for instance, the model architecture uses different normalisation schemes, activation functions, or position encoding strategies. The "Transformer++ improvements" (Rotary encodings, RMSNorm, SwiGLU) are applied to all architectures, but the interaction between these training recipes and the sequence mixer architecture is unexplored. It is conceivable that Mamba's default hyperparameters were chosen for a different training configuration and are suboptimal under the "Transformer++ recipe," making the comparison biased in favor of BASED.

**What evidence exists in the paper.** The DNA modeling results (Table 4, Table 5) provide the only cross-domain validation. On HG38 pretraining, BASED, Mamba, and Transformer++ achieve nearly identical perplexity (within 0.01-0.03 points), and on GenomicBenchmarks classification, the architectures cluster within a few percentage points. These results suggest that the *overall quality* generalises across modalities, but the DNA tasks have fixed, short contexts (1K-8K tokens, byte-level tokenization) and the paper does not report AR-slice perplexity for DNA — so the recall-specific claims are not validated in this domain.

**Mitigation status.** No mitigation is attempted beyond the DNA experiments. The paper does not evaluate on code generation (HumanEval, MBPP), multi-lingual text, or long-document QA (NarrativeQA, Qasper) — all of which would test recall under different conditions. The synthetic MQAR experiments are a strength of the paper's methodology but also a limitation: architectures optimised to perform well on a specific synthetic task may overfit to its structure in ways that do not transfer to real-world recall diversity.

---

### Difficulty Estimation Cost Is Not Accounted for in the Tradeoff Framework

**The assumption or constraint.** The paper's central empirical framework (Figure 2, Section 3.1) characterises the memory-recall tradeoff by training multiple architecture variants with different hyperparameter configurations and measuring their MQAR accuracy and state size. This requires **knowing the ground-truth recall accuracy post-hoc** — i.e., evaluating on the test set to determine where each configuration sits on the tradeoff curve. In a deployment setting, the practitioner does not have access to this oracle curve. The paper does not provide a method for selecting the optimal operating point on the tradeoff for a given task *before* training or evaluation.

This is analogous to, but distinct from, the difficulty estimation cost in the compute-optimal test-time scaling framework (referenced as prior work in the reader's context). In this paper, the unsolved problem is: given a target task with unknown recall demands, how does one choose the feature dimension `d'`, window size `w`, and layer ratio for BASED without exhaustively training and evaluating multiple configurations?

**The consequence.** A practitioner deploying BASED faces a chicken-and-egg problem. The paper demonstrates that varying `d'` from 8 to 16 to 24 to 32 moves the model along the Pareto frontier (Table 6, Figure 3), trading off state size against AR perplexity. But without a reliable *a priori* estimate of how much recall capacity a target task or deployment context requires, the practitioner must either:

- **Guess a configuration** (e.g., default to `d'=16` as in the paper's main results), potentially leaving recall capacity unused (if `d'=24` would have been better for a recall-intensive task) or wasting memory (if `d'=8` would have sufficed for a non-recall-intensive task).
- **Train multiple variants and evaluate**, which multiplies training cost by the number of configurations tested. This undermines the practical benefit of having a "navigable" Pareto frontier: if finding the right point on the frontier requires training the entire frontier, the navigation cost can exceed the deployment savings.

This is the exact same structural problem that the compute-optimal test-time scaling work (Arora et al., reference paper in reader's context) faces with its difficulty estimation — the framework shows what is *possible* but does not provide a cheap mechanism for achieving it in a new setting.

**What evidence exists in the paper.** The paper does not measure or acknowledge this cost. The MQAR experiments in Figure 2 require training dozens of model variants across six architecture classes and evaluating them on the synthetic test set. The language modeling ablations in Table 6 require training 16 model variants at 362M parameters to 10B tokens each — a substantial computational investment to characterise the tradeoff. The paper provides no method for reducing this cost, no transfer learning results showing that the optimal `d'` for one task predicts the optimal `d'` for another, and no characterisation of how sensitive task performance is to being "off" the Pareto frontier.

**Mitigation status.** Not addressed. The paper frames the controllability of BASED's state size as a feature — "by varying BASED window size and linear attention feature dimension, we can dial the state size and traverse the Pareto frontier" (Abstract) — but does not discuss how a practitioner should choose the dial setting in practice. The sentence "we can smoothly navigate the tradeoff between efficient models and memory-hungry models with high recall capacity" (Section 3.1) describes a capability of the architecture class, not a deployable method. This is a significant gap between the conceptual framework and its practical utility.

---

### The 14× Larger Model Baseline for Recall Comparison Is a Weak Counterfactual

**The assumption or constraint.** The paper compares BASED against attention in recall quality primarily through synthetic MQAR experiments (Figures 2, 3) and real-world downstream tasks (Table 1). In both cases, the attention baseline uses a standard Transformer++ configuration at the same parameter count and training budget as BASED. The paper does not compare against a **larger attention-based model** that uses additional parameters to compensate for its inference inefficiency — a comparison that would mirror the FLOPs-matched analysis in the compute-optimal test-time scaling work.

Table 1 shows that at 1.3B/50B, Transformer++ achieves AR perplexity of 1.65 versus BASED's 1.71 — a small but persistent gap of 0.06. On downstream recall tasks, Transformer++ leads BASED by 12.05 points on SWDE, 50.07 points on FDA, and 1.85 F1 on SQUAD. These gaps suggest that at matched parameter count and training budget, attention still dominates on recall quality.

**The consequence.** The paper frames the tradeoff as recall vs. throughput (memory), but the practical question for deployment is: **given a fixed total budget (hardware, latency, throughput requirements), should I deploy a small attention-based model, a large attention-based model, or a medium-sized BASED model?** The paper does not answer this because:

- It compares against attention at matched parameter count, where attention has better recall but worse throughput. This makes the tradeoff seem inevitable: you must sacrifice one for the other.
- But a **larger attention model with reduced batch size or shorter sequences** might achieve equivalent throughput to a smaller BASED model while retaining superior recall — the extra parameters might compensate for the inference overhead, especially in latency-tolerant settings.
- Alternatively, a **smaller attention model with aggressive KV-cache compression** (e.g., quantization, token dropping, grouped-query attention) might close the throughput gap while retaining much of the recall advantage.

The absence of a Pareto frontier that includes *model size* as a third axis means the two-dimensional recall-throughput tradeoff may be misleading. What appears as a BASED advantage over attention at fixed parameter count might disappear when total deployment cost is normalised.

**What evidence exists in the paper.** The MQAR experiments (Figure 2) do not include a larger attention model. The language modeling experiments (Table 1) do not include a 7B or 13B attention baseline trained on the same data. The throughput benchmarks (Figure 4) do not include an attention model with a larger batch size (compensating for lower per-token throughput through parallelism). These are standard comparisons in the efficient architectures literature but represent an incomplete characterisation of the deployment tradeoff space.

**Mitigation status.** The paper does not acknowledge this as a limitation. It frames the comparison as "i can either deploy attention (good recall, expensive) or BASED (good recall, cheap)," which implicitly assumes that model size is fixed and that attention's recall advantage cannot be converted into efficiency gains through other means. This framing is common in the efficient architectures literature but is a genuine limitation of the work's claims about practical deployment.

---

### IO-Aware Implementation Is Tied to a Specific GPU Architecture and May Not Generalise

**The assumption or constraint.** The IO-aware CUDA kernels (Algorithms 1, 2, and 3) are designed for and benchmarked on NVIDIA H100 GPUs. The optimisations exploit specific hardware properties: 16×16 tensor core tiles, the HBM-SRAM-register memory hierarchy with specific bandwidth ratios (2 TB/s HBM, 19 TB/s SRAM), 8 warps per thread block with 32 threads per warp, and CUDA graph capture (NVIDIA, 2019) for kernel launch overhead reduction. The paper states that benchmarks were "run using an H100 NVIDIA GPU and averaged over 20 repetitions" (Section 6.2).

**The consequence.** The 24× generation throughput advantage over FlashAttention-2 is contingent on these hardware-specific optimisations. On different hardware, the advantage may shrink, disappear, or reverse:

- **Older GPUs (A100, V100):** Smaller SRAM (192KB vs. 256KB on H100 per SM), lower bandwidth (1.5 TB/s HBM on A100 vs. 2 TB/s on H100), and fewer tensor cores mean the register-resident KV-state partitioning strategy may not be feasible or beneficial. If the KV-state spills from registers to SRAM (or SRAM to HBM), the latency advantage of the recurrent formulation over attention's growing KV-cache may be eroded.
- **Inference-specialised hardware (TPUs, Inferentia, custom ASICs):** These have entirely different memory hierarchies and computation models. The tiling strategy (16-token tiles), warp-level state partitioning, and kernel fusion logic are CUDA-specific and would need to be re-engineered — potentially from scratch — for each platform.
- **Future GPU architectures:** The H100 introduces the Transformer Engine with FP8 support and improved tensor cores. The paper uses BFloat16 throughout, so it does not benefit from FP8 acceleration. If future architectures change tensor core tile sizes or memory bandwidth ratios, the TCWINDOW size (64-128, optimised for current tensor core latency profiles) would need re-calibration.

This means that the "expanded Pareto frontier" in Figure 2 — which plots state size against recall accuracy — is incomplete as a throughput-recall tradeoff characterisation. The actual throughput for a given state size depends on hardware-specific implementation quality, which is not captured by the abstract state size metric. Mamba's parallel scan implementation may map more naturally onto emerging hardware architectures than BASED's custom linear attention kernels, potentially reversing the throughput ordering at matched state sizes on different hardware.

**What evidence exists in the paper.** The paper provides micro-benchmarks for individual kernels (Appendix B, Figures 5, 6, 7) on the H100 and compares against baseline implementations (PyTorch, Fast Transformers kernel, FlashAttention-2). It does not benchmark on A100 or any non-NVIDIA hardware. The TCWINDOW design principle is validated only through the Cutlass GEMM latency measurements in Figure 1 (left), which are hardware-specific.

**Mitigation status.** The paper partially acknowledges this through its strategy of using established libraries (FlashAttention for training prefill) and providing the kernels as open-source code (https://github.com/HazyResearch/ThunderKittens). However, it does not discuss hardware portability as a limitation or provide any guidance for adapting the kernels to other platforms. The efficiency claims are presented as intrinsic properties of the architecture ("BASED enables up to 24× higher throughput"), when in fact they depend on a specific implementation targeting a specific generation of NVIDIA GPUs. The distinction between algorithmic efficiency (asymptotic complexity) and implementation efficiency (wall-clock time on specific hardware) — which the paper itself makes in Section 5 — is blurred in the headline claims.

---

### The Hybrid Architecture's Layer Configuration Is Not Ablated or Justified

**The assumption or constraint.** BASED combines three layer types — Taylor linear attention, sliding window attention, and gated convolutions — in a fixed ratio of approximately 20/20/60 (5/5/17 layers at 360M, 7/7/22 at 1.4B; Table 7). This ratio is used in all main experiments (Table 1) and is not varied. The paper states that BASED "combines familiar local and global sequence mixers to achieve high quality" and that it trains "as a hybrid of ≈20% linear attention, ≈20% sliding window attention, and ≈60% gated convolution layers as discussed in Appendix E.1" (Section 6), but Appendix E.1 provides the hyperparameter tables without justifying the ratio.

**The consequence.** The paper demonstrates that the *existence* of all three components improves quality (Table 6 ablations: removing sliding window or convolutions degrades performance), but does not demonstrate that the 20/20/60 ratio is optimal or even near-optimal. Several concerns:

- **Over-allocation to convolutions**: 60% of layers are gated convolutions with short filters (width 3). These have small recurrent states but also limited modeling capacity per layer. If recall quality is the primary goal, the paper provides no evidence that allocating more layers to linear or sliding window attention (e.g., 40/40/20) would not improve recall further at an acceptable throughput cost.
- **Under-allocation to sliding window attention**: The sliding window attention is responsible for precise local token comparisons (Section 4.2), but it occupies only 20% of layers. Given that real-world recall tasks involve multi-step retrieval and reasoning (not just single-hop key-value lookup as in MQAR), more layers of local exact attention might be necessary to compose multiple recall operations. The 20% allocation may be sufficient for the Pile's AR slice but insufficient for complex recall tasks like FDA (where BASED achieves only 30.40% vs. Transformer++'s 80.47%).
- **Interaction effects**: The layer ordering (which positions in the stack contain which layer types) is fixed but not documented or ablated. In Transformers, early layers tend to capture local syntax while later layers capture semantics. The optimal placement of linear attention layers (which provide global context) versus sliding window layers (which provide local precision) may depend on their depth in the network.

**What evidence exists in the paper.** The only direct evidence about the necessity of each component comes from the Table 6 ablations, which are binary presence/absence tests, not ratio sweeps. Removing sliding window attention entirely degrades AR perplexity by 0.04 (2.07 → 2.11); removing convolutions degrades it by 0.02 (2.07 → 2.09); removing both degrades it by 0.22 (2.07 → 2.29). These results confirm that all three components contribute positively, but give no information about whether the contribution saturates at 20% allocation or continues to increase. A ratio sweep (e.g., 10/10/80 vs. 20/20/60 vs. 30/30/30 vs. 40/40/20) would be necessary to characterise the optimal configuration — and this optimal may itself vary with model scale, training budget, and target task.

**Mitigation status.** Not addressed. The paper treats the 20/20/60 ratio as a fixed architectural constant, similar to how a standard Transformer fixes the attention-to-FFN ratio. But in a paper whose central argument is that navigating a tradeoff through hyperparameter choices (feature dimension, window size) is the key insight, the omission of the **layer ratio** as a navigation axis is notable. The layer ratio directly affects both quality and throughput: more linear attention layers improve global modeling but increase the number of large recurrent states; more sliding window layers improve local precision but increase the number of window-sized KV-caches; more convolution layers are cheapest but provide the least recall-specific capability. The optimal ratio is likely task-dependent, and the paper's failure to characterise this dependency means a practitioner cannot adapt BASED to their specific throughput-recall requirements beyond the two knobs (`d'` and `w`) that the paper does sweep, when the layer ratio may be the more impactful hyperparameter.

## 7. Implications and Future Directions

### How This Work Changes the Landscape

This paper shifts the conversation around efficient language model architectures from **point-solution comparisons** to **systematic characterization of a fundamental tradeoff surface**. Before this work, the field evaluated architectures like Mamba, H3, Hyena, and RWKV primarily by asking: "Does it match attention's perplexity?" If the answer was approximately yes, the architecture was deemed successful, and nuanced quality differences were attributed to training details or hyperparameter choices. The paper demolishes this framing by showing that **aggregate perplexity parity masks systematic differences in recall capability** — differences that emerge cleanly when the evaluation isolates associative recall tokens (Table 1: Mamba and BASED achieve identical overall Pile perplexity at 1.3B/50B but differ by 0.03 AR perplexity, which translates to 10.36 accuracy points on downstream recall tasks). This is not a marginal refinement; it's a methodological correction that changes what it means for an efficient architecture to "match" attention.

The practical implication is that the field now has a **diagnostic toolkit** rather than a leaderboard. The MQAR synthetic task (Arora et al., 2023a), combined with exact state size calculations (Appendix E.2) and AR-slice perplexity on real corpora, provides a systematic procedure for placing any new architecture on the recall-memory Pareto frontier and understanding why it falls where it does. This changes the architecture design problem from "beat the state-of-the-art on perplexity" to **"understand what capabilities your architecture trades off, and position it explicitly on the frontier."** A new architecture that matches Mamba on overall perplexity but sits below it on the MQAR curve (as H3 and Hyena do) is immediately identifiable as structurally deficient for recall, regardless of its aggregate metrics.

The paper also reconciles an apparent contradiction in the prior literature. On one side, linear attention has been theoretically appealing since Katharopoulos et al. (2020a) — `O(Nd^2)` training and `O(1)` generation steps — but benchmarks showed implementations were slower than FlashAttention-2 (Dao et al., 2022). On the other side, architectures like Mamba achieved strong throughput without custom kernels but struggled on recall. The resolution, demonstrated empirically in Figure 4, is that **theoretical efficiency is necessary but insufficient**: the Fast Transformers baseline implementation of BASED is slower than FlashAttention-2 despite its asymptotic advantages, and only with IO-aware kernels (Algorithms 1-3) does the theoretical benefit translate to wall-clock speedups. This resolves the tension by showing that both sides were partially right — linear attention is algorithmically efficient, but realizing that efficiency requires hardware-specific implementation engineering that the original linear attention papers did not provide.

The work also redirects research effort away from **pure gated convolutions** as a path to attention-quality recall. The theoretical lower bounds (Theorems 3.2, 3.4) prove that any architecture built from gating and convolution primitives requires depth that grows logarithmically with sequence length or vocabulary size to solve associative recall, while attention solves it in constant depth (Proposition F.16). This is not an empirical observation that could be fixed with better training — it's a structural limitation. For researchers developing new efficient architectures, this provides a clear negative result: **if your proposed model can be simulated by BaseConv with constant-factor overhead, it inherits the same recall limitations.** The positive corollary is that architectures should incorporate input-dependent operations (selective SSMs, linear attention with sufficiently expressive feature maps) that break out of the BaseConv simulation regime. This makes Mamba-like input-dependence and linear attention more attractive as research directions, and pure long-convolution approaches (like H3 and Hyena) less attractive for tasks requiring strong recall.

Finally, the paper elevates **IO-awareness from an implementation detail to a first-class architectural design constraint.** The TCWINDOW principle — choosing window sizes based on GPU tensor core latency measurements rather than modeling considerations — and the register-resident KV-state partitioning strategy demonstrate that architectural decisions (which feature map to use, what window size to set) should be made with hardware efficiency as a primary criterion. This challenges the prevailing separation of concerns where architects design models and systems engineers optimize them post-hoc. In BASED, the choice of the 2nd-order Taylor series feature map is driven partly by its decomposability into diagonal (causal, on-chip) and off-diagonal (cumulative, in-register) computations that map efficiently onto the GPU memory hierarchy. This design philosophy — what might be called **hardware-architecture co-design** — is likely to become more important as the gap between theoretical FLOPs and realized throughput widens with specialized AI hardware.

### Follow-Up Research This Work Enables

**A scaling law study mapping the recall-memory Pareto frontier as a function of model size and training tokens.** The paper demonstrates the tradeoff at 360M and 1.3B parameters with up to 50B training tokens. The natural follow-up asks: **does the Pareto frontier shift with scale, and can we predict the optimal feature dimension `d'` and window size `w` for a given model size and training budget without exhaustive sweeps?** A strong experiment would train BASED at 4-5 scales (e.g., 300M, 700M, 1.5B, 3B, 7B) with the same training data and systematically vary `d'` (and optionally `w`) at each scale, measuring both MQAR accuracy and AR-slice perplexity. The output would be a family of Pareto curves parameterized by model size, from which one could read off: "to achieve AR perplexity X at model size Y, you need feature dimension at least Z." This would convert the architectural tradeoff from an empirical finding into a predictive design tool, analogous to how Chinchilla scaling laws predict optimal model size given a compute budget. The paper's observation that `d' = 32` saturates at `d_model = 1024` (since 32 = √1024, Section 6.2) hints at a scaling relationship — the optimal `d'` may grow as `√d_model` — but this is speculation based on a single data point.

**Direct measurement of the recall-throughput tradeoff on real-world tasks by varying BASED's state size.** The paper characterizes the memory-recall tradeoff on synthetic MQAR (Figure 2) and compares fixed-configuration BASED against Mamba on downstream tasks (Table 1), but never connects the two: **does varying `d'` and `w` produce the same tradeoff curve on SWDE, FDA, or SQUAD that it does on MQAR?** A strong experiment would take the pretrained 1.3B BASED models with different `d'` values (8, 16, 24, 32) from the Table 6 ablations, measure their throughput and recall accuracy on SWDE/FDA/SQUAD, and plot the resulting real-world Pareto frontier. This would answer: (1) whether the synthetic tradeoff predicts real-world recall behavior, (2) whether there exists a `d'` that closes the enormous gap to Transformer++ on FDA (currently 30.40% vs. 80.47%), and (3) whether the optimal `d'` is task-dependent (e.g., higher for FDA's unstructured extraction than for SQUAD's passage-based QA). If the real-world tradeoff curve saturates at a much lower accuracy than MQAR's near-perfect recall, it would indicate that factors beyond associative recall (e.g., multi-hop reasoning, negation, ambiguity resolution) dominate real-world recall difficulty — a finding that would refine the scope of claims about BASED's recall capabilities.

**Combining BASED with the compute-optimal test-time compute framework and evaluating the joint tradeoff.** The paper's memory-recall tradeoff is orthogonal to the compute-optimal test-time compute framework (Arora et al. — the reference paper in this analysis, which demonstrates difficulty-conditioned allocation of inference compute). A natural integration would use BASED as the base architecture in a compute-optimal test-time scaling pipeline, where the difficulty estimator determines not only how much test-time compute to allocate (beam search vs. best-of-N, revision depth) but also **which point on BASED's Pareto frontier to deploy for each prompt.** Easy prompts (difficulty bin 1-2) might use a small `d'=8` configuration with minimal state size for maximum throughput; hard prompts (bin 3-4) might dynamically switch to `d'=32` with a larger recurrent state for maximum recall. This is conceptually clean because the difficulty estimation cost (generating a few samples and scoring with a verifier) is already incurred in the compute-optimal framework, and the verifier's score distribution could simultaneously inform the difficulty bin and the optimal `d'` setting — amortizing the state-size selection cost. A concrete experiment would: (1) train BASED variants with `d' ∈ {8, 16, 24, 32}` on a shared pretraining corpus, (2) implement the compute-optimal test-time scaling pipeline from the reference paper (PRM training, difficulty estimation, compute-optimal strategy selection) using BASED as the base model, (3) add `d'` as an additional hyperparameter in the strategy space, and (4) measure whether the combined adaptive allocation achieves better efficiency than either BASED with fixed `d'` or the original compute-optimal framework with an attention-based model. The hypothesis is that easy problems would benefit from BASED's throughput advantage (small `d'`, high throughput) while hard problems would benefit from its recall capacity (large `d'`, high recall) — and that the difficulty estimator could route prompts appropriately.

**Stress-testing BASED on long-context recall beyond the MQAR training distribution.** The MQAR experiments train on sequences of 256 tokens and evaluate on 1,024 tokens, testing a 4× length generalization. Real-world long-context applications (document QA, repository-level code understanding, multi-turn dialogue) require recall over 10K-100K tokens. **Does BASED's linear attention recurrent state maintain recall fidelity at these lengths, or does the Taylor approximation accumulate errors that degrade retrieval accuracy?** A strong experiment would evaluate pretrained BASED models zero-shot on a benchmark like SCROLLS or Long Range Arena, measuring whether recall accuracy for key-value pairs degrades as the distance between key and query grows. This would stress-test a specific mechanistic hypothesis: the Taylor series approximation `1 + qᵀk + (qᵀk)²/2` is a local approximation to the exponential function — for large dot products `qᵀk` (which can occur with long sequences and high-dimensional embeddings), the approximation error grows, potentially causing the linear attention to "forget" or mis-weight keys that are far in the past. If this hypothesis holds, it would motivate higher-order Taylor approximations or alternative feature maps (such as those based on random Fourier features with more frequencies) specifically for long-context settings — a finding that would refine the paper's feature map recommendations (currently based on short-context MQAR).

**A direct theoretical comparison of recall efficiency: attention vs. Mamba vs. linear attention.** The paper provides lower bounds for gated convolutions (Theorems 3.2, 3.4) but does not theoretically characterize Mamba's recall capabilities relative to attention or linear attention. Mamba's input-dependent recurrences place it outside the BaseConv class, so the lower bounds do not apply. **Can Mamba solve MQAR in constant depth, like attention (Proposition F.16), or does it require depth that grows with the problem parameters?** A theoretical analysis answering this would involve: (1) expressing Mamba's state update as a polynomial over the input (following the approach in Appendix F), (2) determining the degree of the polynomial required to represent the MQAR function, and (3) deriving a lower bound on the number of Mamba layers from degree growth. If Mamba requires `Ω(log N)` layers (like BaseConv) rather than `O(1)` (like attention), it would explain the empirical gap on recall tasks and establish that input-dependence via selective state updates is not sufficient for attention-like recall efficiency — motivating the hybrid linear+exact attention approach of BASED. Conversely, if Mamba can solve MQAR in `O(1)` layers, the empirical gap would be attributed to training or capacity limitations that might close at larger scales. This theoretical result would be a significant contribution in its own right, resolving whether Mamba's empirical recall deficit is a fundamental limitation or a scaling artifact.

**Extending BASED to decoder-only pretraining at the 7B scale with a public replication package.** The paper's experiments top out at 1.3B parameters and 50B tokens — too small to determine whether the architectural advantages persist in the regime where most practitioners deploy models. A strong follow-up would train BASED at 7B parameters on 1T+ tokens (e.g., on the SlimPajama or RefinedWeb datasets), release the training code, model weights, and evaluation harness, and compare against publicly available 7B checkpoints (Mistral-7B, Mamba-7B if available, Llama-2-7B). This would answer: (1) does the recall gap between BASED and attention narrow, persist, or widen at scale? (2) does the 24× throughput advantage over FlashAttention-2 (measured at 1.3B) translate to production-scale serving scenarios with 7B models and batch sizes of 64-256? and (3) does the 10.36 accuracy point advantage over Mamba on recall tasks survive when both models are trained to compute-optimality at the 7B scale? Beyond the specific results, the primary contribution would be establishing BASED as a viable open-source alternative to attention-based models, with documented training recipes and serving benchmarks — lowering the barrier for practitioners to adopt the architecture.

### Practical Applications and Downstream Use Cases

**High-throughput serving of recall-intensive applications with bounded memory.** Consider a production information extraction system that processes millions of semi-structured HTML pages daily (e.g., monitoring product listings across e-commerce sites). Each page requires extracting structured attributes (price, availability, specifications) from raw HTML — a task structurally similar to the SWDE benchmark where BASED achieves 64.45% accuracy at 1.3B/50B (vs. Mamba's 52.75%). At this scale, serving cost is dominated by GPU memory and throughput: the KV-cache of an attention-based model grows linearly with the HTML page length (which can be 2K-8K tokens for complex product pages), limiting the batch size that fits in GPU memory. Deploying BASED with a small feature dimension `d'=16` (recurrent state size ~17.7K elements per head) would allow batch sizes 4-8× larger than an equivalent attention model, reducing the number of GPU-hours required by a similar factor. If the 24× generation throughput advantage (batch size 128, 1024 tokens) scales to the 8K context lengths typical of HTML pages, the cost per extracted page could drop by an order of magnitude while maintaining recall quality well above Mamba's. The concrete decision criterion: if the recall quality of BASED (64.45% on SWDE) meets the application's accuracy requirement, the throughput advantage makes it the cheaper deployment choice; if the application requires attention-level accuracy (76.50%), investing in a larger attention model or using compute-optimal test-time scaling (from the reference paper) may be necessary.

**On-device or edge deployment of small language models with strong retrieval capabilities.** Consider a privacy-sensitive medical coding assistant that runs locally on a clinician's device, extracting diagnosis codes from patient notes without sending data to the cloud. The model must fit within the memory constraints of a laptop or tablet GPU (typically 4-8GB of unified memory), maintain sub-second latency for interactivity, and accurately retrieve facts from notes that can span 1K-4K tokens. At the 360M parameter scale, BASED achieves 514.57 tok/ms prefill throughput (Table 1) — 148% faster than FlashAttention-2 — and its recurrent generation state has a fixed size independent of context length. This means the memory footprint is predictable and small: for `d_model=1024`, `d'=16`, 16 heads, the recurrent state per head is ~17.7K elements × 2 bytes (BFloat16) ≈ 35KB, totaling ~560KB for the linear attention layers. The sliding window layers (window size 64) add ~2MB for their KV-caches. The total inference memory is dominated by model weights (~720MB for 360M parameters in BFloat16), not by the attention state — enabling deployment on devices where attention-based models would exhaust memory on longer contexts. The key advantage is not raw speed but **predictable, bounded memory** that enables deployment on hardware where attention's growing KV-cache would be a non-starter.

**Cost-efficient data generation for self-improvement pipelines on recall-intensive tasks.** The paper's comparison with the compute-optimal test-time scaling framework (the reference paper) highlights a use case where architectures that are strong at recall and efficient at generation are particularly valuable: generating high-quality training data through rejection sampling or self-consistency methods. Suppose a team wants to generate 100M QA pairs from a corpus of documents by having a model read each document and produce question-answer pairs, then filtering for correctness. This requires: (1) strong recall to extract specific facts from the source document, (2) high generation throughput to process millions of documents within budget. At 1.3B/50B, BASED achieves 24.28 tok/ms generation throughput — 24× faster than FlashAttention-2 at batch size 128 — while matching Mamba on non-recall perplexity (6.82 vs. 6.78 "other" perplexity) and outperforming it on recall (1.71 vs. 1.74 AR perplexity). For a data generation pipeline where correctness depends on accurate retrieval from the source document, BASED would produce higher-quality QA pairs than Mamba at similar throughput, or equivalent-quality pairs at lower cost than attention. The concrete deployment scenario: run BASED with `d'=24` (improved recall over the default `d'=16`, Table 6: AR perplexity 2.02 vs. 2.07) on a cluster of H100 GPUs, generate answers with simple greedy decoding (avoiding the complexity of best-of-N or beam search), and filter for correctness using a separately trained verifier. The combination of recall quality and throughput would reduce the total GPU-hours for data generation by an estimated 4-8× compared to using an attention-based model at matched parameter count.

### When to Prefer This Method

The paper explicitly positions BASED as a **navigable point on the throughput-recall Pareto frontier**, not as a universal replacement for attention or Mamba. The decision to use BASED depends on where the target application sits in the tradeoff space:

**Prefer BASED over Transformer++ (standard attention) when:**
- Generation throughput is a binding constraint and the application involves generating many tokens per prompt (1024+), where the 24× throughput advantage over FlashAttention-2 at batch size 128 (Figure 4, Table 1) translates to reduced serving cost or latency.
- GPU memory during inference is the bottleneck, and the fixed-size recurrent state of BASED's linear attention layers (independent of sequence length) enables larger batch sizes or longer contexts than attention's growing KV-cache.
- The application's recall requirements fall within BASED's demonstrated capability — e.g., information extraction from structured HTML (SWDE at 64.45% accuracy) or passage-based QA (SQUAD at 41.62 F1) — and the ~12-point gap to Transformer++ on SWDE or ~2-point gap on SQUAD (Table 1, 1.3B/50B) is acceptable given the throughput gains.
- The hardware lacks specialized attention accelerators (e.g., non-NVIDIA GPUs, edge devices) where FlashAttention-2 optimizations are unavailable, making attention's generation cost even higher than the already-substantial gap shown in Figure 4.

**Prefer BASED over Mamba when:**
- The target task requires strong recall, as demonstrated by the 10.36 average accuracy point advantage over Mamba across SWDE, FDA, and SQUAD at 1.3B/50B (Table 1). This is the clearest differentiator: if the downstream evaluation suite includes recall-intensive benchmarks, BASED should outperform Mamba at matched scale.
- Training budget is fixed and the model must be deployed without extensive task-specific fine-tuning, since the recall advantage appears in zero-shot evaluation of pretrained models (Section 6.1) and grows with training scale (3.9 → 10.4 points from 10B to 50B at 360M).
- The deployment hardware supports custom CUDA kernels (NVIDIA H100/A100), where BASED's throughput at 360M (47.23 tok/ms) exceeds Mamba's (39.95 tok/ms) by 18%. On hardware without custom kernel support, this advantage may not materialize.

**Prefer Mamba over BASED when:**
- Generation throughput is the absolute priority and the deployment hardware does not support BASED's custom IO-aware kernels. At 1.3B parameters on H100, Mamba achieves 25.69 tok/ms versus BASED's 24.28 tok/ms (Table 1) — a 6% advantage. At smaller scales or on older hardware, this gap may widen.
- The target task does not require strong recall (e.g., short-context classification, common sense reasoning on LM Eval Harness tasks), where Mamba matches or slightly exceeds BASED's performance (Table 2: Mamba 46.84% vs. BASED 46.68% at 1.3B/10B).
- Simplicity and maintainability of the deployment stack matter more than fine-grained quality differences. Mamba uses a single sequence mixer (selective SSM) rather than a hybrid of three layer types. For teams that want a single architecture to deploy across diverse tasks without per-task hyperparameter tuning (feature dimension, window size, layer ratio), Mamba's homogeneity is a practical advantage.

**Prefer attention (Transformer++) over both when:**
- The recall requirements are stringent and the application demands near-perfect retrieval accuracy. On FDA (unstructured document extraction), Transformer++ achieves 80.47% accuracy versus BASED's 30.40% at 1.3B/50B (Table 1) — a 50-point gap that renders BASED unsuitable for this specific task at this scale.
- The deployment can tolerate the growing KV-cache (e.g., batch size 1, short generation lengths, or sufficient GPU memory). At batch size 1 and 1024 generated tokens, FlashAttention-2 achieves ~16 tok/ms versus BASED's ~19 tok/ms (Figure 4, right) — the throughput advantage is only ~1.2×, and the recall quality advantage may justify the small cost.
- The training pipeline already includes strong optimizations for attention (FlashAttention-2 for training, PagedAttention for serving, GQA/MQA for KV-cache compression), and retooling for a new architecture would incur engineering overhead that exceeds the throughput benefits.
- The model scale is large enough (70B+ parameters) that attention's recall advantage over BASED is fully realized, and the throughput bottleneck shifts from the attention mechanism to the feedforward layers (which dominate FLOPs at large scales) — a regime where the sequence mixer's contribution to total latency diminishes, reducing BASED's relative advantage.
