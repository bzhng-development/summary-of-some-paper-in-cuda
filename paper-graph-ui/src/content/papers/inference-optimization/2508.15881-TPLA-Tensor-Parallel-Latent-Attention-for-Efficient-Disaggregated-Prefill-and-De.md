## 1. Executive Summary

This paper introduces **Tensor Parallel Latent Attention (TPLA)**, a scheme that partitions the low-rank latent KV representation introduced by Multi-Head Latent Attention (MLA) across tensor-parallel devices, enabling each device to hold only a fraction of the compressed KV cache while preserving full representational capacity per attention head (every head still accesses the complete latent via an all-reduce over independently computed attention outputs, in contrast to Grouped Latent Attention which restricts heads to local latent shards). Evaluated on DeepSeek-V3 (685B) and Kimi-K2 (1T) with FlashAttention-3, TPLA achieves 1.79× and 1.93× decoding throughput speedups respectively at a 32K-token context length, while orthogonal reparameterization via PCA or Hadamard transforms—combined with a prefill–decode separation that uses standard MLA during compute-bound prefill and TPLA only during memory-bound decoding—limits accuracy degradation on commonsense and LongBench benchmarks to a modest drop, establishing that TPLA recovers tensor-parallel KV-cache savings without retraining only when the latent is sliced under an orthogonal transform satisfying approximate norm and attention-score partitioning conditions.

## 2. Context and Motivation

### The Core Problem: MLA's KV-Cache Compression Benefits Evaporate Under Tensor Parallelism

This paper addresses a specific, previously underappreciated tension between two dominant inference-efficiency techniques for large language models: **KV cache compression** (specifically, Multi-Head Latent Attention as introduced in DeepSeek-V2) and **tensor parallelism** (the standard method for distributing large models across multiple GPUs). The problem is that MLA's primary advantage—reducing per-token KV cache memory by compressing multi-head key–value states into a single low-rank latent vector `cKV`—is **almost entirely negated** when tensor parallelism is applied, because under TP, every device must load the full `cKV` regardless of the parallelism degree.

To understand why this matters concretely, consider the numbers the paper provides in Section 1. In LLaMA-3-70B, which uses GQA, the per-token KV cache dimension is $2 \times 8 \times 128 = 2048$. Under tensor parallelism with TP = 4, this is sharded across devices, so each GPU holds only $2048 / 4 = 512$ dimensions per token. In contrast, DeepSeek-V3 uses MLA with a fixed KV cache dimension of $64 + 512 = 576$ per token. Under tensor parallelism, **every device must replicate the full 576-dimensional latent**, regardless of whether TP = 2, 4, or 8. The per-device KV cache for DeepSeek-V3 under TP = 4 is therefore **576**, which is larger than LLaMA-3-70B's per-device cache of **512**—despite MLA's design goal of reducing memory. The compression advantage over GQA disappears precisely when tensor parallelism is most needed (for large models that cannot fit on a single GPU).

This is not a theoretical curiosity. It has direct implications for the throughput and latency of deployed models. During auto-regressive decoding, the model is memory-bandwidth-bound: each token generation requires reading the entire KV cache from high-bandwidth memory (HBM) to on-chip SRAM. The per-device KV cache size directly determines how much data must be moved per step, which in turn determines the maximum achievable throughput. If MLA's compression doesn't reduce per-device memory traffic under TP, then the primary motivation for adopting MLA—reducing the memory-bandwidth bottleneck—is undermined for large-scale deployments.

### Why This Problem Is Important: The Memory-Bandwidth Wall

The practical significance of this gap becomes clear when we consider the inference economics of large models in production. The paper frames the issue in terms of the **compute-bound vs. memory-bound** distinction (Section 4.5):

- **Prefill phase**: Processing the entire prompt in a single parallel pass is compute-bound—the bottleneck is FLOPs, not memory bandwidth. Here, MLA's reduced computation (via matrix absorption, where up-projection matrices are folded into query and output projections) is beneficial.
- **Decode phase**: Auto-regressively generating one token at a time requires reading the entire, growing KV cache from HBM for each step. As context length increases, this data movement becomes the dominant bottleneck—the decode phase is memory-bandwidth-bound. Here, the size of the KV cache on each device directly determines throughput.

At long context lengths (e.g., 32K tokens, which the paper benchmarks), the KV cache can consume gigabytes of memory per device. For DeepSeek-V3 with its 576-dimensional latent per token over 32K tokens and 61 layers, the KV cache is substantial. If each device must hold the full cache, memory bandwidth becomes the hard ceiling on generation speed. TPLA addresses this by reducing the per-device latent dimension from $4d_h$ to $2d_h$ (when TP = 2), effectively halving the per-device KV cache memory traffic. The measured speedups—1.79× for DeepSeek-V3 and 1.93× for Kimi-K2 at 32K context—directly translate to reduced serving costs and improved user-facing latency.

Beyond the immediate throughput gains, this problem matters because it represents a **system-level mismatch** between two techniques that were developed with different assumptions. MLA was designed with single-device inference in mind, where the full `cKV` is loaded once. Tensor parallelism was designed for models like standard MHA or GQA, where head dimensions naturally partition across devices. The failure of these techniques to compose effectively means that practitioners deploying large MLA-based models (DeepSeek-V3, Kimi-K2, and potentially future models adopting MLA) face an unpalatable choice: either accept the full per-device KV cache overhead, or abandon tensor parallelism entirely (which is infeasible for 685B+ parameter models). TPLA provides a third option.

### Where Prior Approaches Fall Short

The paper identifies three categories of prior work and explains where each is insufficient for this specific tension:

**1. General KV cache compression methods are destructive.**

A large body of work attempts to reduce KV cache memory by discarding or altering information: token pruning/eviction (Ge et al., 2023; Zhang et al., 2024; Li et al., 2024), token merging (Wang et al., 2024; Liu et al., 2025), cross-layer KV sharing (Yang et al., 2024; Brandon et al., 2024), low-rank factorization (Zhang et al., 2024; Lin et al., 2024), and quantization (Hooper et al., 2024; Wang et al., 2025). The paper acknowledges these approaches but draws a sharp distinction (Section 2): "Although effective, these approaches inevitably discard or alter information in the KV cache and can degrade model performance. In contrast, TPLA leaves the KV contents intact: it reduces the amount of cache each device must hold so the model retains full information while alleviating memory pressure." TPLA's compression is **distributed, not destructive**—the full latent still exists across the ensemble of devices, just not replicated on each one.

**2. Grouped Latent Attention (GLA) addresses the TP problem but sacrifices representational capacity and requires retraining.**

GLA (Zadouri et al., 2025) was proposed specifically to address MLA's tensor parallelism limitation. It partitions the latent KV cache into $g$ groups and assigns each group to a subset of attention heads, so that each head only accesses its local latent shard. For TP = 2, this means splitting the $4d_h$-dimensional latent into two $2d_h$ shards and pairing each shard with $h_q/2$ heads. This solves the per-device KV cache replication problem: each GPU only loads its assigned $2d_h$ latent.

However, the paper identifies two critical limitations of GLA (Section 1 and validated experimentally in Table 1):

- **Loss of representational capacity**: Each attention head loses access to half of the latent representation. Figure 2 and Table 1 quantify this: directly converting DeepSeek-V2-Lite from MLA to GLA causes WikiText-2 perplexity to explode from 6.31 to **2212**, and average commonsense accuracy to drop from 61.75% to 33.77%. This is not a minor degradation—it represents catastrophic information loss. The intuitive reason is that MLA's latent is a compressed bottleneck that encodes information about all key–value heads; restricting each head to only half of this latent means each head sees a fundamentally incomplete representation of the context.

- **Training from scratch is required**: GLA changes the attention head grouping structure fundamentally. A model pre-trained with MLA cannot be converted to GLA without retraining—the collapsed accuracy in Table 1 confirms this. Training a large model from scratch (e.g., DeepSeek-V3 at 685B parameters) to validate GLA's effectiveness is prohibitively expensive. The paper estimates this cost as "significant computational resources" (Section 1), which limits GLA's practical adoption—practitioners with existing MLA checkpoints cannot benefit without a full retraining cycle.

**3. Standard tensor parallelism for MHA/GQA does not apply to MLA's compressed latent.**

Tensor parallelism (Shoeybi et al., 2019; Xu et al., 2021) splits weight matrices and input activations across devices along row or column dimensions, performing distributed matrix multiplications with collective communication (all-reduce or all-gather). For standard multi-head attention, this is straightforward: the head dimension is split so each device computes a subset of attention heads independently, and the outputs are concatenated via all-reduce. For GQA, heads are grouped to share key–value representations, and these groups can be distributed across devices while preserving per-group KV sharing.

MLA breaks this pattern because it collapses all heads' key–value states into a **single latent vector** `cKV`. There is no head dimension to split for the KV cache—the compression eliminates the independence of per-head keys and values. The only dimension available for tensor parallelism is the latent dimension itself ($4d_h$), but splitting it naively breaks the attention computation. As the paper explains in Section 4.2, if we simply assign half of the latent to each device:

$$\text{softmax}(Q (\hat{c}_{KV})^\top) \neq \text{softmax}(Q_0 (\hat{c}_{KV}^0)^\top) \;\; \text{[Device 0]}$$

The softmax normalization requires the global attention scores across the full latent dimension, which means each device would need the other device's partial scores. Without a method to decompose the softmax computation, naive latent splitting is mathematically invalid.

### How This Paper Positions Itself Relative to Existing Work

The paper positions TPLA as a **practical, drop-in inference optimization** that bridges the gap between MLA's compression efficiency and tensor parallelism's scalability, without requiring retraining. This positioning has several distinct aspects:

**TPLA vs. GLA: Same goal (TP-compatible MLA), fundamentally different approach to preserving capacity.**

Both TPLA and GLA aim to distribute MLA's latent KV cache across tensor-parallel devices. However, they differ in what they sacrifice to achieve this:

- **GLA** restricts each attention head's access: heads in group $i$ see only latent shard $i$. The per-device KV cache is halved, but each head loses half its latent capacity.
- **TPLA** preserves full head access: every head computes attention against the full latent, but the computation is split across devices so that each GPU contributes a partial attention output, which is then summed via all-reduce. The per-device KV cache is halved, and all heads see the full latent (just computed distributively).

The paper explicitly frames TPLA as having "stronger representational capacity" (Section 1, Section 4) than GLA because no head is information-restricted. Table 1 empirically validates this: TPLA conversion of DeepSeek-V2-Lite yields WikiText-2 perplexity of 7.24 (vs. 2212 for GLA), demonstrating that preserving full latent access per head avoids catastrophic degradation.

**TPLA benefits from MLA pre-training; GLA requires training from scratch.**

A key practical advantage the paper emphasizes is that TPLA can directly load pre-trained MLA checkpoints. The conversion process involves:
1. Applying an orthogonal transformation $U$ to reparameterize weight matrices (absorbing $U$ into $W^{DKV}$ and $U^\top$ into $W^{UKV}$)
2. Slicing the transformed latent across devices
3. Adjusting RMSNorm and softmax computations to work with partial latents

This conversion introduces approximation error (the orthogonal transform must satisfy specific conditions for RMSNorm and softmax slicing to be accurate), but as Tables 1 and 2 show, the error is small and largely recoverable with lightweight alignment (100M tokens) or eliminated via prefill–decode separation. The ability to inherit MLA checkpoints means practitioners can immediately apply TPLA to existing DeepSeek-V3 or Kimi-K2 deployments without the enormous cost of pre-training from scratch.

**TPLA as a re-sharding strategy, not a new attention mechanism.**

Section 4.4 presents a revealing perspective: TPLA can be viewed as a special case of GLA with **double the number of attention heads**. By duplicating the query tensor along the head dimension and sharding appropriately, TPLA's computation becomes algebraically equivalent to GLA with $2h_q$ heads, where each device processes $h_q$ heads and a $2d_h$ latent. This framing has two practical consequences:
- TPLA is **compatible with FlashAttention-3** (and similar optimized attention kernels) because it inherits GLA's sharding pattern—only the head count differs.
- The additional computational cost from head duplication is analyzed in Section 4.5 and shown to be manageable: during decoding, the attention computation dominates, and TPLA's attention complexity ($O(L_q \times S_{KV} \times h_q \times 2d_h \times 2)$) is arithmetically equivalent to MLA's under TP = 2 ($O(L_q \times S_{KV} \times h_q/2 \times 4d_h \times 2)$). The extra cost comes from computing $Q$ with more heads, but this is negligible relative to attention at long context lengths (Figure 4 confirms that TTFT with prefill–decode separation is actually lower than TPLA without separation).

**The prefill–decode separation as a phase-aware optimization.**

The paper recognizes that TPLA's full latent slicing, while beneficial for memory-bandwidth-bound decoding, adds computational overhead during the compute-bound prefill phase. Rather than accepting this overhead or abandoning TPLA for prefill, they introduce a **hybrid strategy** (Section 4.5): use standard MLA (with the same orthogonal reparameterization but without RMSNorm/softmax slicing) during prefill, and switch to TPLA during decoding. This is motivated by the different bottlenecks in each phase:
- Prefill is compute-bound → minimize computation → MLA is optimal (heads can be split across devices without changing latent dimension, reducing per-device compute)
- Decode is memory-bandwidth-bound → minimize KV cache size per device → TPLA is optimal (halving latent dimension reduces memory traffic)

This phase-aware design is what enables the "free lunch" TTFT improvement shown in Figure 4: TPLA with PD separation achieves 1.4× faster time-to-first-token than TPLA without separation at 1K prompt length, while preserving the decoding throughput gains.

**The orthogonal reparameterization as the key enabler.**

The paper's technical core is the insight that an orthogonal transformation $U$ applied to the latent space can make latent slicing approximately valid for both RMSNorm and softmax, without changing the model's mathematical output (when exact conditions are met). This is what makes the training-free conversion possible. Without reparameterization, simply slicing the latent naively would produce the kind of catastrophic degradation seen in GLA (Table 1). The reparameterization serves two purposes:
- For RMSNorm: it balances the norm across partitions so that local RMS computations approximate the global RMS (Condition 1, Equation 18)
- For softmax: it concentrates or balances information so that local attention scores approximate the global scores up to a scaling factor (Condition 2, Equation 22)

The paper explores two families of orthogonal transforms—Hadamard matrices (which balance values uniformly) and PCA (which concentrates variance in leading dimensions)—and finds that PCA works better for softmax slicing while Hadamard suffices for RMSNorm slicing (Figure 2, Section 5.3.2). This differentiation is itself a contribution: it shows that different components of the attention computation have different sensitivity to how the latent is partitioned.

### Summary of the Gap and the Positioning

To distill: the paper addresses a **system-level composition failure**—two well-motivated techniques (MLA for KV cache compression, tensor parallelism for model scaling) do not compose effectively because MLA's compressed latent eliminates the head dimension that TP normally splits. GLA proposed to fix this but introduced a representational capacity bottleneck and requires retraining. TPLA fixes the composition failure by distributing the latent computation (not restricting head access) under an orthogonal reparameterization that makes distributed RMSNorm and softmax approximately valid, all while inheriting pre-trained MLA weights. The result is a practical, training-free path to efficient tensor-parallel inference for MLA-based models.

## 3. Technical Approach

### 3.1 Reader Orientation

TPLA is a **re-sharding strategy for attention computation during inference**, not a new attention mechanism or a model architecture change. It takes a pre-trained MLA model (e.g., DeepSeek-V3) and rewires how the compressed KV latent `cKV` is distributed across tensor-parallel GPUs during decoding, so that each device holds only half the latent yet every attention head still effectively sees the full latent—achieved by computing partial attention on each device and summing the results with an all-reduce, all while preserving the model's mathematical equivalence through an orthogonal reparameterization trick.

The problem TPLA solves is the **composition failure between MLA and tensor parallelism**: MLA compresses all heads' key–value states into a single latent vector `cKV` of dimension `$4d_h$` (e.g., 512 for DeepSeek-V3), but tensor parallelism requires each device to load the full `cKV` because there is no head dimension left to shard—so MLA's memory savings vanish under TP. The shape of TPLA's solution is to **distribute the computation, not restrict access**: split the latent across devices, let each device compute attention between all its heads and its local latent shard, and then combine partial outputs via all-reduce, thereby halving per-device KV cache memory while preserving full representational capacity per head (unlike GLA which restricts heads to local shards, causing catastrophic degradation).

### 3.2 Big-Picture Architecture (Diagram in Words)

The TPLA system has five major components working together across two inference phases:

1. **Orthogonal Reparameterization Module** — Applies an orthogonal matrix `$U$` (Hadamard or PCA-derived) to the pre-trained MLA weight matrices before inference. This transforms the latent space so that slicing `cKV` across devices approximately preserves RMSNorm and softmax properties. `$U$` is absorbed into `$W^{DKV}$` (down-projection) and `$U^\top$` is absorbed into `$W^{UKV}$` (up-projection) so no additional computation is needed at runtime.

2. **Latent Slicing Function** — During decoding, partitions the reparameterized latent `$c_{KV}$` into two shards `$c_{KV}^0$` and `$c_{KV}^1$` each of dimension `$2d_h$` (half the original `$4d_h$`). Each shard goes to a different GPU. This is the core mechanism that halves per-device KV cache memory.

3. **Distributed Attention Engine** — Each GPU computes attention independently using its local latent shard `$c_{KV}^i$` and its full set of query heads `$Q^i$`. The attention scores are computed locally, scaled by coefficients derived from the orthogonal transform, and the attention output `$O^i$` is projected through `$W^{VO,i}$`. This runs on standard attention kernels (FlashAttention-3) since TPLA is algebraically equivalent to GLA with doubled heads.

4. **All-Reduce Aggregator** — Sums the partial outputs `$\tilde{O}^0$` and `$\tilde{O}^1$` from the two devices to produce the final attention output `$O$`. This is standard tensor-parallel communication and is the only cross-device synchronization needed.

5. **Phase-Aware Scheduler** — During prefill (compute-bound), uses standard MLA without latent slicing—heads are split across devices normally, the full `$4d_h$` latent is replicated, and RMSNorm/softmax use the full dimension. During decode (memory-bound), switches to TPLA with latent slicing. The prefill KV cache is partially reused by TPLA during decode. This separation eliminates conversion-induced accuracy loss during prefill while capturing throughput gains during decode.

Information flow during decoding: token embedding enters → reparameterized `$W^{DKV}$` projects to latent → latent is split by device → each GPU applies RMSNorm on its shard (using scaling factors `$\alpha$`, `$\beta$` to approximate global norm) → each GPU computes local attention scores (with softmax scaling factors `$\mu$`, `$\nu$`) → each GPU projects through local `$W^{VO,i}$` → all-reduce sums partial outputs → final token representation.

### 3.3 Roadmap for the Deep Dive

- **First**, the mathematical foundation: how MLA's computation is structured in its "absorbed" form (Equation 4 and Equation 5), since this absorbed form—where up-projection matrices are folded into query and output projections—is what TPLA operates on and what makes the reparameterization possible. Without understanding matrix absorption, the orthogonal transform trick appears magical rather than mechanical.

- **Second**, the orthogonal reparameterization: why any orthogonal `$U$` preserves MLA's output equivalence (Proposition 1), how `$U$` gets absorbed into weight matrices (Equation 17), and what conditions `$U$` must satisfy for sliced RMSNorm and softmax to approximate their global counterparts (Condition 1 and Condition 2). This is the conceptual core that enables training-free conversion.

- **Third**, the RMSNorm slicing mechanism: why naively computing RMS on half the dimension gives the wrong normalization, how balancing the norms of the two partitions (via Condition 1) enables local RMSNorm to approximate global RMSNorm using scaling coefficients `$\alpha$` and `$\beta$`, and how these coefficients are derived from the orthogonal transform's properties.

- **Fourth**, the softmax slicing mechanism: the more challenging problem of decomposing `$\text{softmax}(Q\hat{c}_{KV}^\top)$` across devices, why the global softmax cannot be trivially split (the normalization sums over all dimensions), and how conditioning the orthogonal transform (Condition 2) allows local softmax computations to approximate the global softmax up to multiplicative factors `$\mu$` and `$\nu$`.

- **Fifth**, the two reparameterization strategies (Hadamard and PCA): their mathematical definitions, how each satisfies or fails to satisfy the two conditions, the empirical findings from Figure 2 that PCA dominates for softmax while Hadamard suffices for RMSNorm, and why PCA's variance concentration makes it brittle for more than two partitions.

- **Sixth**, the GLA-equivalence framing: how TPLA can be recast as GLA with doubled attention heads, why this makes TPLA compatible with FlashAttention-3 without kernel modifications, and the complexity analysis showing TPLA's attention computation is arithmetically equivalent to MLA under TP=2 despite having more heads.

- **Seventh**, the prefill–decode separation: the phase-aware motivation (prefill is compute-bound, decode is memory-bound), how TPLA without separation adds overhead during prefill, and how the hybrid strategy eliminates prefill overhead while preserving decode gains.

The paper does not propose new attention mathematics; it proposes a specific reparameterization and sharding strategy that composes MLA with tensor parallelism without retraining.

#### Foundation: MLA's Absorbed Computation Form

TPLA operates on MLA in its **absorbed computation form**, not the standard form with explicit key and value up-projections. Understanding this absorption is prerequisite to everything that follows, because it is what makes the orthogonal reparameterization mechanically possible and what defines the weight matrices that TPLA modifies.

Standard MLA (Equation 4 in the paper) works as follows during training and standard inference. An input sequence `$X \in \mathbb{R}^{B \times L \times D}$` (batch size `$B$`, sequence length `$L$`, model dimension `$D$`) is first projected down to a low-rank latent:

$$c_{KV} = X W^{DKV}$$

where `$W^{DKV} \in \mathbb{R}^{D \times 4d_h}$` is the down-projection matrix that compresses from the model dimension `$D$` to the latent dimension `$4d_h$`. This latent `$c_{KV}$` is what gets cached—instead of storing full per-head keys and values, only this single compressed vector per token is stored. The latent is then normalized:

$$\hat{c}_{KV} = \text{RMSNorm}(c_{KV})$$

From this normalized latent, multi-head keys and values are reconstructed:

$$k = \hat{c}_{KV} W^{UK}, \quad v = W^{UV} \hat{c}_{KV}$$

where `$W^{UK} \in \mathbb{R}^{4d_h \times (h_q \cdot d_h)}$` up-projects to full-head keys and `$W^{UV} \in \mathbb{R}^{4d_h \times (h_q \cdot d_h)}$` up-projects to full-head values. Here `$h_q$` is the number of query heads and `$d_h$` is the per-head dimension. Separately, queries are produced by a similar low-rank decomposition (`$W^{DQ}$`, `$W^{UQ}$`), and rotary position embeddings are handled via decoupled RoPE using `$q^{PE}$` and `$k^{PE}$` produced by `$W^{QR}$` and `$W^{KR}$`.

The full attention output including positional components is:

$$O = \text{softmax}\left(\frac{q k^\top + q^{PE} (k^{PE})^\top}{\sqrt{d_h + d_r}}\right) v$$

$$\tilde{O} = O W^O$$

where `$W^O \in \mathbb{R}^{(h_q \cdot d_h) \times D}$` projects back to model dimension.

**The absorption trick** (Equation 5) exploits associativity of matrix multiplication to eliminate the explicit reconstruction of keys and values. Omitting RoPE components and scaling for clarity:

$$O W^O = \text{softmax}(q k^\top) \, v \, W^O$$
$$= \text{softmax}(q (\hat{c}_{KV} W^{UK})^\top) \, \hat{c}_{KV} W^{UV} W^O$$
$$= \text{softmax}((q (W^{UK})^\top) \, \hat{c}_{KV}^\top) \, \hat{c}_{KV} \, (W^{UV} W^O)$$
$$= \text{softmax}(Q \, \hat{c}_{KV}^\top) \, \hat{c}_{KV} \, W^{VO}$$

where:
- `$Q = q (W^{UK})^\top \in \mathbb{R}^{B \times 1 \times h_q \times 4d_h}$` is the **absorbed query**—the query matrix `$q$` post-multiplied by the transpose of the key up-projection, so that the attention score `$Q \hat{c}_{KV}^\top$` directly computes `$q k^\top$` without materializing `$k$`
- `$W^{VO} = W^{UV} W^O \in \mathbb{R}^{(h_q \cdot 4d_h) \times D}$` is the **absorbed value-output projection**—the value up-projection composed with the output projection, so that multiplying attention-weighted latents by `$W^{VO}$` directly produces the output without materializing `$v$`

**What this achieves operationally:** During decoding, instead of (1) computing `$k = \hat{c}_{KV} W^{UK}$`, (2) computing attention scores `$q k^\top$`, (3) computing `$v = \hat{c}_{KV} W^{UV}$`, (4) computing attention output `$O v$`, and (5) projecting `$O W^O$`, the absorbed form computes: (1) attention scores directly as `$Q \hat{c}_{KV}^\top$`, (2) attention output as `$\text{softmax}(Q \hat{c}_{KV}^\top) \hat{c}_{KV}$`, and (3) final output as the attention output times `$W^{VO}$`. The intermediate key and value tensors are never materialized, saving memory bandwidth.

**Why this form enables TPLA:** The key observation is that `$Q$` and `$W^{VO}$` are now the matrices that directly interact with `$\hat{c}_{KV}$`. If we apply an orthogonal transformation `$U$` to `$\hat{c}_{KV}$`, we can **absorb `$U$` into `$Q$` and `$W^{VO}$`** without changing the mathematical result:

$$Q \hat{c}_{KV}^\top = (Q U) (\hat{c}_{KV} U)^\top = Q' (\hat{c}_{KV} U)^\top$$

where `$Q' = Q U$`. Similarly, `$\hat{c}_{KV} W^{VO} = (\hat{c}_{KV} U) (U^\top W^{VO}) = (\hat{c}_{KV} U) W^{VO,\text{new}}$`. This means the orthogonal transformation `$U$` applied to the latent can be exactly compensated by updating the weight matrices, leaving the overall computation unchanged. This is the mathematical foundation for why reparameterization works: any orthogonal `$U$` preserves the model's output exactly (before slicing), and we can choose `$U$` to make the sliced computation approximately correct.

**In practice, `$W^{UV}$` is typically not absorbed into `$W^O$`**, as noted in the paper, "to avoid generating an impractically large matrix." The absorption of `$W^{UK}$` into `$Q$` is the critical one for TPLA, since it's the key–query interaction that must be distributed.

#### Orthogonal Reparameterization: Why It Enables Slicing

The central mathematical insight of TPLA is that an orthogonal transformation `$U \in \mathbb{R}^{4d_h \times 4d_h}$` (satisfying `$U U^\top = I$`) applied to the latent vector `$c_{KV}$` can be **absorbed into the model's weight matrices** without changing the model's output, while simultaneously **conditioning the latent** so that slicing it across devices produces approximately correct local computations.

**Proposition 1 (Section 4.1) establishes the RMSNorm equivalence:**

$$\text{RMSNorm}(1, c) = \text{RMSNorm}(1, c U) U^\top$$

where `$c \in \mathbb{R}^{L \times d}$` is the input latent (omitting batch for simplicity) and `$\text{RMSNorm}(1, \cdot)$` denotes RMSNorm without the learned scaling parameter `$\gamma$` (i.e., `$\gamma = 1$`).

**Proof sketch (paraphrased from the paper):** RMSNorm can be written as matrix multiplication:

$$\text{RMSNorm}(\gamma, c) = D_c \, c \, W_\gamma$$

where:
- `$D_c = \text{diag}(1/\text{RMS}(c_1), \ldots, 1/\text{RMS}(c_L)) \in \mathbb{R}^{L \times L}$` is a diagonal matrix whose diagonal entries are the reciprocal RMS values for each token in the sequence
- `$W_\gamma = \text{diag}(\gamma_1, \ldots, \gamma_d) \in \mathbb{R}^{d \times d}$` is a diagonal matrix of learned scaling parameters.

Since orthogonal transformations preserve the `$L_2$` norm (`$\|c U\|_2^2 = \|c\|_2^2$`), we have `$\text{RMS}(c) = \text{RMS}(c U)$`, and therefore `$D_{cU} = D_c$`. Substituting:

$$\text{RMSNorm}(\gamma, c U) U^\top = D_c \, c U \, W_\gamma \, U^\top$$

When `$\gamma = 1$` (i.e., `$W_\gamma = I$`), the `$U$` and `$U^\top$` cancel: `$D_c \, c \, U \, I \, U^\top = D_c \, c = \text{RMSNorm}(1, c)$`. This proves that for `$\gamma = 1$`, any orthogonal `$U$` leaves RMSNorm unchanged.

**How `$\gamma = 1$` is achieved:** The learned scaling `$W_\gamma$` can be absorbed into the subsequent up-projection matrix. Specifically, if we define `$W^{UKV} = (W^{UK}, W^{UV})$` as the combined key–value up-projection, we can absorb `$W_\gamma$`:

$$W^{UKV}_{\text{new}} = U^\top W_\gamma W^{UKV}$$

The `$U^\top$` comes from the reparameterization (since we apply `$U$` to the latent, we need `$U^\top$` in the up-projection to cancel), and `$W_\gamma$` is the original learned scaling. After this absorption, the effective RMSNorm has `$\gamma = 1$`, satisfying the condition for Proposition 1.

**Weight matrix absorption (Equation 17):** The orthogonal transformation is applied to both directions of the latent path:

$$W^{UKV}_{\text{new}} = U^\top W_\gamma W^{UKV}$$
$$W^{DKV}_{\text{new}} = W^{DKV} U$$

where `$W^{DKV}_{\text{new}}$` is the reparameterized down-projection (projecting input to transformed latent) and `$W^{UKV}_{\text{new}}$` is the reparameterized up-projection (projecting transformed latent to keys and values). This is a one-time conversion done after loading the pre-trained checkpoint and before inference—no additional computation at runtime.

**What this means operationally:** The reparameterized model computes `$c_{KV}^{\text{new}} = X W^{DKV} U = (X W^{DKV}) U$`, which is the original latent rotated by `$U$`. All subsequent computations (RMSNorm, attention, output projection) work on this rotated latent, with the weight matrices adjusted so that the final output is identical to the original model. The orthogonal property (`$U U^\top = I$`) guarantees that no information is lost—the transformation is a rotation/reflection in latent space.

**Why orthogonality matters specifically:** Orthogonal transformations preserve inner products (`$(cU)(cU)^\top = c c^\top$`) and norms (`$\|cU\| = \|c\|$`). Without orthogonality, the RMSNorm equivalence (Proposition 1) would fail because `$\text{RMS}(cU) \neq \text{RMS}(c)$`, and the softmax attention scores would change because `$Q (cU)^\top \neq Q c^\top$` in general. Orthogonality is the precise property that makes the reparameterization output-equivalent to the original model before slicing. Non-orthogonal transforms would introduce irreversible distortion.

#### RMSNorm Slicing: How Local Norms Approximate Global Norms

When the latent `$c_{KV}$` is split across two devices, each device has only half the dimensions. For device 0 holding `$c_{KV}^0 \in \mathbb{R}^{B \times L \times 2d_h}$`, computing RMSNorm on this half gives:

$$\text{RMS}(c_{KV}^0) = \sqrt{\frac{1}{2d_h} \sum_{i=1}^{2d_h} (c_{KV,i}^0)^2 + \epsilon}$$

which differs from the true RMSNorm over the full `$4d_h$` dimensions:

$$\text{RMS}(c_{KV}) = \sqrt{\frac{1}{4d_h} \sum_{i=1}^{4d_h} c_{KV,i}^2 + \epsilon}$$

Naively using the local RMS would produce incorrect normalization—the local norm sees only half the variance and would over-normalize or under-normalize depending on how the variance is distributed across dimensions.

**Condition 1 (RMSNorm Slicing Condition, Equation 18):**

$$\alpha \|(c U)_0\|_2^2 \approx \beta \|(c U)_1\|_2^2 \approx \|c U\|_2^2 = \|c\|_2^2$$

where `$(c U)_0$` and `$(c U)_1$` are the first and second halves of the orthogonal-transformed latent, and `$\alpha$` and `$\beta$` are constants that do not depend on the specific input (they are properties of the transform, not the data).

**What this condition demands:** After applying the orthogonal transform `$U$`, the squared norm of the entire latent should be approximately recoverable from either half independently, up to a fixed scaling factor. If the first half captures fraction `$1/\alpha$` of the total variance, then scaling the first half's squared norm by `$\alpha$` recovers the full norm. Similarly for the second half with `$\beta$`. The constants `$\alpha$` and `$\beta$` depend on how `$U$` distributes variance across dimensions.

**How this enables local RMSNorm (Equation 19):**

$$\text{RMS}(c) = \sqrt{\frac{1}{4d_h} \|c\|_2^2 + \epsilon} \approx \sqrt{\frac{\alpha}{4d_h} \|(c U)_0\|_2^2 + \epsilon} = \sqrt{\frac{\alpha}{2}} \, \text{RMS}((c U)_0)$$

Similarly for device 1 with `$\beta$`. Each device can compute its local RMS on `$2d_h$` dimensions, multiply by `$\sqrt{\alpha/2}$` (a pre-computed constant), and obtain a value that approximates the global RMS. The normalized vectors are then:

$$\hat{c}_{KV}^0 = \frac{c_{KV}^0}{\text{RMS}((c U)_0)} \cdot \sqrt{\frac{2}{\alpha}} \approx \frac{c_{KV}^0}{\text{RMS}(c)}$$

**In practice** (as described in Section 4.3.2 for PCA), `$\alpha$` and `$\beta$` are computed once from the eigenvalue spectrum of the latent covariance matrix. If `$\lambda_1 \geq \lambda_2 \geq \cdots \geq \lambda_{4d_h}$` are the eigenvalues, then:

$$\alpha = \frac{\sum_{i=1}^{2d_h} \lambda_i}{\sum_{i=1}^{4d_h} \lambda_i}, \quad \beta = \frac{\sum_{i=2d_h+1}^{4d_h} \lambda_i}{\sum_{i=1}^{4d_h} \lambda_i}$$

These are simply the fractions of total variance captured by the first and second halves of the PCA-ordered dimensions. For Hadamard transforms (Section 4.3.1), the balancing property means `$\alpha \approx \beta \approx 2$`—each half captures approximately half the variance, so local RMS values are approximately equal to the global RMS.

**The failure mode without proper conditioning:** If `$U$` is the identity matrix (no transformation) and the original latent has highly non-uniform variance across dimensions, one device's half might capture 95% of the variance while the other captures only 5%. The first device would under-normalize (its local RMS would be larger than the global RMS, so it divides by too large a number) and the second would over-normalize. This asymmetry would propagate through attention scores and cause the kind of degradation seen in the "TPLA-Vanilla" bar in Figure 2. The orthogonal transform's role is to **balance or concentrate** the variance so that each partition's norm is predictably related to the global norm.

#### Softmax Slicing: The More Challenging Decomposition

Softmax slicing is fundamentally harder than RMSNorm slicing because the softmax involves an **exponential of sums across all dimensions**—it is not linearly decomposable. The attention score between query and latent is:

$$S = \text{softmax}\left(\frac{Q \hat{c}_{KV}^\top + q^{PE} (k^{PE})^\top}{\sqrt{d_h + d_r}}\right)$$

where the term `$Q \hat{c}_{KV}^\top$` expands to `$Q_0 (\hat{c}_{KV}^0)^\top + Q_1 (\hat{c}_{KV}^1)^\top$` when the query and latent are split across devices. The softmax is:

$$\text{softmax}(S_0 + S_1 + S_{PE}) = \frac{\exp(S_0 + S_1 + S_{PE})}{\sum \exp(S_0 + S_1 + S_{PE})}$$

where `$S_0 = Q_0 (\hat{c}_{KV}^0)^\top / \sqrt{d_h}$`, `$S_1 = Q_1 (\hat{c}_{KV}^1)^\top / \sqrt{d_h}$`, and `$S_{PE}$` is the positional score component (which is replicated across devices unchanged). Each device has only its local score `$S_i$`, but the exponential of a sum is the product of exponentials: `$\exp(S_0 + S_1) = \exp(S_0) \cdot \exp(S_1)$`. The denominator sums the product, which couples the two devices' computations.

**Condition 2 (Softmax Slicing Condition, Equation 22):**

$$Q' (\hat{c}_{KV} U)^\top \approx \mu \, Q'_0 (\hat{c}_{KV} U)_0^\top \approx \nu \, Q'_1 (\hat{c}_{KV} U)_1^\top$$

where `$Q' = Q U$` is the absorbed query after reparameterization, `$Q'_0$` and `$Q'_1$` are its first and second halves along the feature dimension, and `$\mu$` and `$\nu$` are scaling constants (note: the paper writes `$Q'_0$` meaning the first half of columns of `$Q'$`, paired with the first half of the latent; this is the row-parallelism described in Equation 20).

**What this condition demands:** The full attention score `$Q' \hat{c}_{KV}'^\top$` (where `$\hat{c}_{KV}' = \hat{c}_{KV} U$`) should be approximately proportional to the local attention score computed on either half. If device 0 computes `$S^{\text{local}}_0 = Q'_0 (\hat{c}_{KV} U)_0^\top$`, then multiplying by `$\mu$` should recover the global score. This is a much stronger requirement than Condition 1—it's not just about norms but about the **directional alignment** of the query and latent partitions.

**How the global softmax is approximated in practice:** The positional component `$S_{PE}$` is replicated across devices (not split), so each device has access to it. The local attention score on device 0 is:

$$S_0^{\text{total}} = \mu \cdot \frac{Q'_0 (\hat{c}_{KV} U)_0^\top}{\sqrt{d_h}} + \frac{q^{PE} (k^{PE})^\top}{\sqrt{d_h + d_r}}$$

and similarly for device 1 with `$\nu$`. Each device computes its local softmax independently:

$$A_0 = \text{softmax}(S_0^{\text{total}}), \quad A_1 = \text{softmax}(S_1^{\text{total}})$$

The attention output is then:

$$O_0 = A_0 \, \hat{c}_{KV}^0 \in \mathbb{R}^{B \times 1 \times h_q \times 2d_h}$$

where each device computes attention between its full set of `$h_q$` query heads and its `$2d_h$`-dimensional latent shard. The final output sums these partial outputs after value-output projection:

$$O = \text{AllReduce}(\tilde{O}_0 + \tilde{O}_1) = \text{AllReduce}(O_0 W^{VO}_0 + O_1 W^{VO}_1)$$

**Why the softmax slicing is inherently approximate:** Even with Condition 2 satisfied, each device's softmax uses a different normalization constant. Device 0 computes `$\text{softmax}(S_0^{\text{total}})$` where the denominator sums `$\exp(S_0^{\text{total}})$` over the sequence, while the global softmax has denominator summing `$\exp(S_0 + S_1 + S_{PE})$`. If the two halves' scores are not perfectly proportional, the local softmax distribution differs from the global one. The approximation quality depends on how well the orthogonal transform makes `$S_0 \propto S_1 \propto S$`.

**The paper's empirical finding (Figure 2):** Hadamard transforms fail at Condition 2 despite succeeding at Condition 1. The example in Section 4.3.1 illustrates why: with `$Q = (100, 0, 0, 0)$` and `$c = (0, 0, 80, 0)$`, the Hadamard transform produces `$Q' = (50, 50, 50, 50)$` and `$c' = (40, 40, -40, -40)$`. The element-wise product `$Q' \odot c'$` is `$(200, 200, -200, -200)$`; splitting into halves gives `$400$` vs. `$-400$`, which are not proportional. The signs cause cancellation across halves that the scaling factor cannot fix. PCA, by contrast, concentrates information into leading dimensions, making the first half's contribution dominate (high `$\mu$`, low `$\nu$`), which reduces interference between halves.

#### Reparameterization Strategy 1: Hadamard Matrix Transformation

The Hadamard transform (Section 4.3.1) uses a deterministic, recursively constructed orthogonal matrix `$H_d \in \mathbb{R}^{d \times d}$` with entries `$\pm 1/\sqrt{d}$` (the `$1/\sqrt{d}$` scaling makes it orthonormal). The construction is:

$$H_{2n} = \frac{1}{\sqrt{2}} \begin{pmatrix} H_n & H_n \\ H_n & -H_n \end{pmatrix}, \quad H_1 = (1)$$

This is the Sylvester/Walsh-Hadamard construction. For a `$4d_h$`-dimensional latent (e.g., 512 for DeepSeek-V3), the Hadamard matrix is `$512 \times 512$`, which is efficiently computable. To increase robustness, the paper multiplies by a random diagonal matrix `$D$` with entries `$\pm 1$`—this breaks deterministic structure (preventing pathological input alignments) while preserving orthogonality since `$(H_d D)(H_d D)^\top = H_d D^2 H_d^\top = H_d H_d^\top = I$` (because `$D^2 = I$` for `$\pm 1$` entries).

**Why Hadamard works for RMSNorm (Condition 1):** The Hadamard transform balances the magnitudes of vector elements. The example in Equation 24 demonstrates: a sparse vector `$c = (100, 0, 0, 0)$` becomes `$c' = (50, 50, 50, 50)$` after the transform. More generally, the Hadamard transform spreads each input dimension's value roughly equally across all output dimensions, so each half of the output captures approximately half the total norm. Formally:

$$\frac{\|(c H_d)_0\|_2^2}{d/2} \approx \frac{\|(c H_d)_1\|_2^2}{d/2} \approx \frac{\|c H_d\|_2^2}{d} = \frac{\|c\|_2^2}{d}$$

This satisfies Condition 1 with `$\alpha \approx \beta \approx 2$`. Each device can compute local RMS and the result approximates the global RMS without scaling adjustment (since `$\sqrt{\alpha/2} \approx 1$`).

**Why Hadamard fails for softmax (Condition 2):** The balancing that helps RMSNorm hurts softmax. Hadamard entries are `$\pm 1$`, which means the transformed vectors have both positive and negative components. When computing `$Q'_0 (\hat{c}_{KV} U)_0^\top$`, the positive and negative contributions can cancel, making the local score a poor predictor of the global score. The example with `$Q = (100, 0, 0, 0)$` and `$c = (0, 0, 80, 0)$` shows the two halves giving `$400$` and `$-400$`—equal magnitude, opposite sign, complete cancellation in the sum but strong signal in each half. A scaling factor cannot fix sign flips. The paper hypothesizes that "the exponential nature of softmax makes it more sensitive to imbalance"—small per-sample perturbations in the Hadamard-transformed space produce significant asymmetries in softmax outputs that accumulate across tokens.

The paper acknowledges this limitation and states: "A potential direction to address this issue is to search for an optimized Hadamard matrix via dimension permutations that minimizes the discrepancy between partitions. We leave the investigation of such optimized transformations for future work."

#### Reparameterization Strategy 2: Principal Component Analysis (PCA)

PCA-based reparameterization (Section 4.3.2) takes a data-driven approach. Instead of using a fixed orthogonal matrix, it computes the principal components of the latent distribution and uses the eigenbasis as the orthogonal transform `$U$`.

**Procedure:**

1. **Collect calibration data:** Run the pre-trained MLA model on a calibration dataset (the paper uses WikiText-2) and collect the KV latent cache `$c_{KV}$` from all layers. This produces a matrix `$F \in \mathbb{R}^{(B \cdot L) \times 4d_h}$` where each row is a latent vector from some token in the calibration set.

2. **Compute the covariance matrix:** Form `$\Sigma_F = F^\top F / (B \cdot L)$` (assuming mean-centered data; the paper states "for mean-centered features, the variance is equivalent to mean of the squared values, closely related to squared RMS value").

3. **Eigendecomposition:** Compute `$\Sigma_F = U \Lambda U^\top$` where `$U \in \mathbb{R}^{4d_h \times 4d_h}$` is orthogonal (columns are eigenvectors) and `$\Lambda = \text{diag}(\lambda_1, \ldots, \lambda_{4d_h})$` contains eigenvalues in descending order (`$\lambda_1 \geq \lambda_2 \geq \cdots \geq \lambda_{4d_h}$`).

4. **Use `$U$` as the orthogonal transform.** The eigenvalues `$\lambda_i$` represent the variance of the latent data along each principal direction.

**Why PCA works for RMSNorm (Condition 1):** PCA orders dimensions by variance. The first `$2d_h$` principal components capture fraction `$\alpha$` of the total variance, and the remaining `$2d_h$` components capture fraction `$\beta$`, where:

$$\alpha = \frac{\sum_{i=1}^{2d_h} \lambda_i}{\sum_{i=1}^{4d_h} \lambda_i}, \quad \beta = \frac{\sum_{i=2d_h+1}^{4d_h} \lambda_i}{\sum_{i=1}^{4d_h} \lambda_i}$$

For typical neural network activations, variance is concentrated in the leading PCA dimensions, so `$\alpha$` is significantly larger than `$\beta$`. For instance, if the first half captures 80% of variance (`$\alpha = 1/0.8 = 1.25$`) and the second half captures 20% (`$\beta = 1/0.2 = 5$`), device 0 would scale its local RMS by `$\sqrt{1.25/2} \approx 0.79$` to approximate the global RMS, while device 1 would scale by `$\sqrt{5/2} \approx 1.58$`. This is less balanced than Hadamard but still accurately predictable because the eigenvalues are fixed (computed once from calibration data).

**Why PCA works better for softmax (Condition 2):** Because PCA concentrates information (variance) in the leading dimensions, the first half of the transformed latent dominates the attention score computation. This means:

$$Q' (\hat{c}_{KV} U)^\top = Q'_0 (\hat{c}_{KV} U)_0^\top + Q'_1 (\hat{c}_{KV} U)_1^\top \approx Q'_0 (\hat{c}_{KV} U)_0^\top$$

The second half contributes little to the score, so device 0's local computation closely approximates the global score. This satisfies Condition 2 with `$\mu \approx 1$` (for device 0) and `$\nu$` large but essentially irrelevant because device 1's contribution is small. The paper defines `$\mu$` and `$\nu$` in "the same manner, making them equivalent to `$\alpha$` and `$\beta$`, respectively" (Section 4.3.2), meaning `$\mu = \alpha$` and `$\nu = \beta$`.

**The concentration-vs-balancing trade-off:** PCA's variance concentration is a double-edged sword. It makes `$g = 2$` partitioning work well (one half dominates, the other is negligible), but it implies that for `$g > 2$` partitions, the middle partitions would have ill-defined scaling behavior. The paper explicitly identifies this limitation (Section 6): "TPLA with group-partitions `$g = 2$` can achieve good performance, but when `$g > 2$`, it probably fails to maintain effectiveness." Hadamard's balancing, by contrast, would scale better to more partitions but fails at softmax slicing. This tension is left as future work.

**Practical note on PCA computation:** The calibration requires running the model on representative text (WikiText-2) once to collect latents. This is a one-time offline cost—the eigenvalues and eigenvectors are computed once and baked into the weight matrices via Equation 17. The quality of the PCA approximation depends on how representative the calibration data is of the deployment distribution. The paper does not explore sensitivity to calibration data mismatch.

#### TPLA as a Special Case of GLA: Compatibility with FlashAttention-3

Section 4.4 provides a crucial implementation insight: TPLA can be reformulated as Grouped Latent Attention (GLA) with doubled attention heads, which means standard optimized attention kernels (FlashAttention-3) can be used without modification.

**GLA's sharding scheme** (from Section 3.2): For TP = 2, GLA partitions the query tensor `$Q \in \mathbb{R}^{B \times L \times h_q \times 4d_h}$` along both the head dimension and the feature dimension, yielding four sub-tensors:

$$Q = \begin{pmatrix} Q_{0,0} & Q_{0,1} \\ Q_{1,0} & Q_{1,1} \end{pmatrix}$$

where `$Q_{i,j} \in \mathbb{R}^{B \times L \times h_q/2 \times 2d_h}$`. In standard GLA, only the diagonal blocks are used—device 0 gets `$Q_{0,0}$` and device 1 gets `$Q_{1,1}$`. Each device's `$h_q/2$` heads attend only to its `$2d_h$`-dimensional latent shard. The off-diagonal blocks `$Q_{0,1}$` and `$Q_{1,0}$` are discarded, which is why GLA loses representational capacity.

**TPLA's reformulation as GLA with `$2h_q$` heads:** Define a conceptual query tensor `$Q'$` that duplicates the original query along the head dimension:

$$Q' = \begin{pmatrix} Q_{0,0} & Q_{0,1} \\ Q_{1,0} & Q_{1,1} \\ Q_{0,0} & Q_{0,1} \\ Q_{1,0} & Q_{1,1} \end{pmatrix} \in \mathbb{R}^{B \times L \times (2h_q) \times 4d_h}$$

This `$Q'$` has `$2h_q$` heads, where the first `$h_q$` heads are the original query and the second `$h_q$` heads are a duplicate. When sharded across two devices using GLA's pattern, device 0 gets the top two row-blocks:

$$\text{Device 0: } \begin{pmatrix} Q_{0,0} & Q_{0,1} \end{pmatrix} \in \mathbb{R}^{B \times L \times h_q \times 4d_h}$$

This is the **full** `$Q$`—all `$h_q$` heads with the full `$4d_h$` feature dimension, but since the feature dimension is split into two `$2d_h$` halves on the same device, we are back to TPLA's configuration. Device 0 processes all heads against latent shard 0 (`$Q_{0,0}$` part) and also against latent shard 1 (`$Q_{0,1}$` part, which is zeroed out or ignored). Similarly, device 1 gets `$(Q_{1,0}, Q_{1,1})$` which is also the full query.

**Algebraic equivalence:** TPLA's computation (Equation 6) computes on device 0:

$$O_0 = \text{softmax}\left(\frac{Q_0 (\hat{c}_{KV}^0)^\top}{\sqrt{d_h}}\right) \hat{c}_{KV}^0$$

where `$Q_0 \in \mathbb{R}^{B \times 1 \times h_q \times 2d_h}$`. In the GLA reformulation, device 0's `$h_q$` heads process `$Q_{0,0}$` against `$\hat{c}_{KV}^0$` and `$Q_{0,1}$` against `$\hat{c}_{KV}^1$` (but `$\hat{c}_{KV}^1$` is on device 1, so effectively only `$Q_{0,0}$` is active). The key insight is that **the sharding pattern is identical**—only the number of heads differs. GLA with `$h_q$` heads splits each device's heads by 2; TPLA keeps all `$h_q$` heads per device by conceptually duplicating to `$2h_q$` heads before sharding.

**Why this matters for implementation:** FlashAttention-3 (and similar kernels) are optimized for the GLA sharding pattern. Since TPLA uses the same pattern, it can literally use FlashAttention-3 as-is—just with `$2h_q$` heads passed to the kernel, where the kernel's internal sharding across devices naturally produces TPLA's configuration. No custom CUDA kernels are needed. This is a significant practical advantage: TPLA leverages years of kernel optimization work without requiring new low-level code.

**Generalization to `$k$` devices (Section 4.4):** For `$k$` devices, TPLA divides them into `$g$` groups of size `$k/g$`. Each group holds a disjoint slice of the latent (width `$4d_h/g$`) and replicates the complete set of head parameters. Within each group, the head axis is sharded across the `$k/g$` devices. Each device processes `$h_q / (k/g)$` heads and `$4d_h / g$` latent features. For `$g = 2$`, `$k = 2$`, this recovers the two-device case: each device gets `$h_q$` heads and `$2d_h$` latent width. The replication factor `$g$` trades off per-device memory (smaller with larger `$g$`) against computational cost (more replication means more total attention computation).

#### Complexity Analysis: Why TPLA's Overhead Is Acceptable

Section 4.5 provides a complexity analysis comparing TPLA and MLA under tensor parallelism with TP = 2. The dominant cost in both is the attention computation itself.

**For MLA with TP = 2:** The `$h_q$` heads are split across two devices, so each device handles `$h_q/2$` heads. The latent dimension is `$4d_h$` and is replicated on each device. The attention complexity per device is:

$$O(L_q \times S_{KV} \times (h_q/2) \times 4d_h \times 2)$$

where `$L_q$` is the query length (1 for decode, prompt length for prefill), `$S_{KV}$` is the KV cache length, and the factor of 2 accounts for the two devices. Simplified: `$O(L_q \times S_{KV} \times 4 h_q d_h)$`.

**For TPLA with TP = 2:** Each device handles all `$h_q$` heads (since TPLA doesn't split heads). The latent dimension is `$2d_h$` (half the original). The attention complexity per device is:

$$O(L_q \times S_{KV} \times h_q \times 2d_h \times 2)$$

Simplified: `$O(L_q \times S_{KV} \times 4 h_q d_h)$`—**arithmetically identical** to MLA under TP = 2.

**Where TPLA adds overhead:** Outside the attention computation, TPLA modifies two operations:
- **Computing `$c_{KV}$`:** In MLA, `$c_{KV} = X W^{DKV}$` is computed on a single device (or replicated). In TPLA, `$W^{DKV}$` is split across devices, so each device computes `$c_{KV}^i = X W^{DKV,i}$` where `$W^{DKV,i} \in \mathbb{R}^{D \times 2d_h}$`. This **reduces** computation by a factor of 2 per device.
- **Computing `$Q$`:** In MLA with TP = 2, `$Q$` is split across devices along heads, so each device computes `$Q$` for `$h_q/2$` heads. In TPLA, each device computes `$Q$` for all `$h_q$` heads. This **increases** computation by a factor of 2 per device.

The paper notes these as `$O(L_q \times D \times 2d_h \times 2)$` reduction for `$c_{KV}$` and `$O(L_q \times D \times 2h_q \times d_h)$` increase for `$Q$`. At short context lengths, these non-attention computations matter. At long context lengths (the regime where TPLA is designed to help), the attention computation—which scales with `$S_{KV}$`—dominates, and the `$c_{KV}$` and `$Q$` computations (which scale with `$L_q = 1$` during decode) are negligible.

**Positional encoding overhead:** The paper acknowledges that "positional components introduce additional overhead, since TPLA doubles the number of heads without reducing the RoPE dimension." In MLA, RoPE uses decoupled queries `$q^{PE}$` and keys `$k^{PE}$`. Under TP = 2, these are split across devices normally. In TPLA, each device handles all heads for RoPE as well, doubling the RoPE computation. The paper characterizes this effect as "relatively minor."

**The decode-phase dominance argument (Figure 3 and 4):** The empirical speedup results (Figure 3) show TPLA achieving 1.33× to 1.93× throughput improvement over MLA during decode, with the gap widening as context length increases. This confirms that the reduced memory traffic (halving the per-device KV cache dimension) outweighs any additional computation from having more heads per device. During decode, each token generation reads the entire KV cache from HBM, and this memory bandwidth cost scales linearly with `$S_{KV} \times d_{\text{latent}}$`. Halving `$d_{\text{latent}}$` nearly doubles throughput at long contexts because the computation is memory-bandwidth-bound, not FLOPs-bound.

#### Prefill–Decode Separation: Phase-Aware Strategy Selection

The prefill–decode separation (Section 4.5) is motivated by the different computational characteristics of the two inference phases:

- **Prefill** processes the entire prompt `$L_q = L_{\text{prompt}}$` tokens in parallel. The attention computation is `$O(L_{\text{prompt}}^2 \times h_q \times d_{\text{latent}})$`—quadratic in prompt length—making it heavily compute-bound. Here, reducing per-device KV cache size doesn't help (the KV cache is being written, not repeatedly read), and TPLA's additional head computation would be pure overhead.
- **Decode** processes one token at a time (`$L_q = 1$`) but reads the entire KV cache (length `$S_{KV}$`). The computation is `$O(S_{KV} \times h_q \times d_{\text{latent}})$`—linear in cache length—and memory-bandwidth-bound because each step requires loading `$S_{KV} \times d_{\text{latent}}$` elements from HBM. Here, halving `$d_{\text{latent}}$` directly halves the memory traffic, yielding the speedups in Figure 3.

**How the separation works (TPLA with PD-sep.):**

During prefill, the model uses **reparameterized MLA**: the orthogonal transform `$U$` is applied to the weight matrices (Equation 17), ensuring the latent space is conditioned for later TPLA use during decode. However, RMSNorm and softmax are **not sliced**—they operate on the full `$4d_h$`-dimensional latent, exactly as in the original MLA. Heads can be split across devices for tensor parallelism (reducing per-device prefill computation), and the full `$4d_h$` latent is replicated. The resulting KV cache is stored in the transformed latent space (i.e., `$c_{KV}^{\text{new}} = c_{KV} U$`).

During decode, the model switches to TPLA: the prefill KV cache (already in the transformed space) is sliced across devices, RMSNorm and softmax are sliced using the scaling coefficients (`$\alpha, \beta, \mu, \nu$`), and attention proceeds in the distributed fashion described in Equation 6 and 7.

**Key insight from Table 1 and 2 (the PD-sep. rows):** TPLA with prefill–decode separation achieves **near-original-model accuracy without any training**:
- DeepSeek-V2-Lite: WikiText-2 perplexity 6.31 (identical to original MLA), commonsense average 61.44 (vs. 61.75 for MLA)
- DeepSeek-V3 on LongBench: average 56.04 (vs. 58.19 for MLA), a drop of only 2.15 points

This is because the prefill phase—which processes the vast majority of tokens (the entire prompt)—uses exact MLA computation with no slicing approximation. The approximation error only affects the decode phase, where single tokens are processed sequentially and the sliced RMSNorm/softmax approximations accumulate gradually. The paper argues this approach "reduces first-token latency and accuracy loss" and that "these small losses, compared with training from scratch, are likely recoverable with a small amount of additional training."

**TTFT improvement (Figure 4):** During prefill, TPLA with PD separation uses MLA's head-splitting for tensor parallelism, which means each device processes `$h_q/2$` heads during prefill (for TP = 2), reducing per-device computation compared to TPLA without separation (which would process all `$h_q$` heads per device). At 1K prompt length, TPLA (PD-sep.) achieves 1.45× faster time-to-first-token than TPLA without separation for DeepSeek-V3 (Figure 4a). This is the "free lunch" the paper claims: the separation eliminates TPLA's prefill overhead while preserving its decode throughput gains.

#### Training-Free Conversion and Lightweight Alignment

The paper demonstrates two pathways to convert MLA to TPLA, trading off between zero training cost and higher accuracy:

**Pathway 1: Training-free conversion (TPLA and TPLA PD-sep. rows in Table 1):**

1. Load the pre-trained MLA checkpoint.
2. Run calibration on WikiText-2 to collect KV latents and compute PCA eigenvectors `$U$` (or use Hadamard matrix directly).
3. Absorb the orthogonal transform into weights via Equation 17.
4. For TPLA (no PD separation): slice RMSNorm and softmax in both prefill and decode.
5. For TPLA (PD separation): use full MLA computation during prefill, TPLA slicing during decode.

This requires no gradient updates. The residual error comes entirely from the slicing approximations. For DeepSeek-V2-Lite, TPLA (PD-sep.) achieves 6.31 WikiText-2 perplexity (matching MLA's 6.31) and 61.44 commonsense average (vs. MLA's 61.75). For DeepSeek-V3, TPLA (PD-sep.) achieves 56.04 LongBench average (vs. MLA's 58.19).

**Pathway 2: Lightweight alignment (TPLA align rows in Table 1 and 2):**

After the training-free conversion, apply supervised fine-tuning with two stages:

1. **Layer-wise feature matching:** Match the input/output features of each TPLA layer to the original MLA layer using 256 random samples of length 2,048 for 10 epochs, minimizing mean squared error with the Muon optimizer (initial learning rate `$1 \times 10^{-6}$`).

2. **End-to-end output alignment:** Align the full model's outputs using 100M tokens from SmolLM-Corpus, following the TransMLA setting: batch size 32, learning rate `$2 \times 10^{-5}$`, warmup ratio 0.03, cosine learning rate scheduler, maximum sequence length 4096. Experiments use 8 GPUs with 96 GB each.

This 100M-token alignment is tiny compared to pre-training (trillions of tokens). It recovers most of the remaining accuracy gap: DeepSeek-V2-Lite TPLA (align) achieves 6.51 perplexity and 61.52 commonsense average, very close to MLA's 6.31 and 61.75. For DeepSeek-V2-Lite on LongBench (Table 2), alignment improves from 10.98 to 22.60 (though still below MLA's 28.90), while PD separation alone reaches 24.44.

**Observation on LongBench alignment effectiveness:** The paper notes that "its effectiveness is limited because the alignment corpus is formed by concatenating short texts." The 4096-token sequences used for alignment are shorter than LongBench's evaluation context (up to 31,500 for V2-Lite, 127,500 for V3). The slicing errors in softmax and RMSNorm "accumulate with sequence length," so alignment on short contexts doesn't fully transfer to long-context performance. This is why PD separation (which eliminates prefill slicing entirely) outperforms alignment on LongBench for V2-Lite (24.44 vs. 22.60).

#### Training TPLA from Scratch: An Open Problem

The paper acknowledges (Section 4.5, "Discussion") that training TPLA from scratch would be costly because TPLA doubles the number of attention heads (conceptually `$2h_q$`) without reducing per-head dimension `$d_h$`. This increases the total attention FLOPs. The paper characterizes this as "an open problem" and suggests the practical pathway of pre-training with MLA (which is efficient) and post-hoc conversion to TPLA (which is nearly free). This is consistent with the paper's framing as an inference optimization rather than a training method.

The ReST$^{EM}$ negative result mentioned in the example paper (not present in TPLA) is not relevant here, but an analogous concern might apply: fine-tuning a TPLA-converted model for many steps on long sequences might be unstable due to accumulation of slicing approximation errors. The paper does not explore this.

## 4. Key Insights and Innovations

### Innovation 1: Diagnosing and Resolving a Previously Invisible Composition Failure Between Two Dominant Inference Techniques

The paper's most fundamental intellectual contribution is not proposing a new attention mechanism, but rather **identifying a specific, previously undocumented system-level composition failure** between two techniques that were each well-motivated in isolation: Multi-Head Latent Attention (MLA) for KV cache compression, and tensor parallelism for distributing large models across GPUs. The failure is this: MLA compresses all heads' key–value states into a single low-rank latent vector `cKV`, eliminating the head dimension that tensor parallelism normally splits across devices. Under TP, every device must therefore load the full `cKV`, negating MLA's primary memory advantage.

This is not obvious a priori. One could reasonably assume that MLA's compression reduces the total KV cache volume, and that tensor parallelism would divide whatever cache exists. The paper shows this assumption is wrong: because MLA collapses the multi-head structure into a monolithic latent, there is no per-head sharding dimension for TP to exploit. The concrete numbers in Section 1 make this vivid: DeepSeek-V3's per-device KV cache under TP=4 is 576 dimensions per token, which is larger than LLaMA-3-70B's 512 dimensions per device under the same TP configuration—despite MLA being explicitly designed to reduce memory.

Prior work on KV cache compression (token pruning, merging, quantization; cited in Section 2) treated compression as a single-device problem. Prior work on tensor parallelism (Shoeybi et al., 2019; Xu et al., 2021) assumed standard MHA or GQA architectures where the head dimension provides a natural sharding axis. The interaction between these two design families—what happens when you try to tensor-parallelize a model whose KV cache has already been compressed across heads—was simply not analyzed. GLA (Zadouri et al., 2025) recognized the problem but addressed it by restricting head access to local latent shards, trading representational capacity for TP compatibility and requiring retraining from scratch.

TPLA's diagnostic move is to recognize that the composition failure is fundamentally about **how the latent is distributed, not how heads are grouped**. Instead of restricting which heads see which latent portions (GLA's approach), TPLA preserves full head-to-latent connectivity but distributes the computation itself, using an all-reduce to combine partial attention outputs. This reframes the problem from "how do we partition heads to match latent shards?" to "how do we make the latent shardable while keeping heads whole?"—and the orthogonal reparameterization provides the mathematical machinery to answer that question.

The significance of this reframing extends beyond the specific solution. It establishes that **compression and parallelism are not composable by default** in attention mechanisms that collapse the head dimension. Any future attention variant that compresses across heads (not just MLA) will face the same tension, and TPLA's framework—distributing computation rather than restricting access, conditioned on an orthogonal reparameterization—provides a template for resolving it. This is a conceptual contribution to the design space of distributed attention, not merely an engineering optimization for DeepSeek models.

### Innovation 2: Orthogonal Reparameterization as a General Tool for Making Norm-Dependent and Exponential Operations Shardable

The paper's core technical insight is that **an orthogonal transformation applied to a compressed latent space can condition it so that operations normally requiring global information—RMSNorm and softmax—become approximately decomposable across tensor-parallel devices**. This is not obvious because both RMSNorm and softmax are non-linear functions of the full latent vector: RMSNorm depends on the global L2 norm, and softmax normalizes across all attention scores with a sum in the denominator. There is no general algebraic identity that splits either operation across an arbitrary partition.

The key conceptual move is to separate two questions that are typically conflated: (1) does the orthogonal transform preserve the model's mathematical output *before slicing*? (answered by Proposition 1: yes, for any orthogonal `U` applied consistently), and (2) does the orthogonal transform make the *sliced* computation approximate the global one? (answered by Conditions 1 and 2: only for specific `U` that balance or concentrate variance across partitions). The first question guarantees that reparameterization is lossless in principle—you can rotate the latent space arbitrarily without changing what the model computes. The second question constrains *which* rotation you should choose so that slicing introduces minimal error.

This two-step logic—guarantee exact equivalence under transformation, then optimize the transformation for approximate equivalence under partitioning—is a general pattern that extends beyond TPLA. Any scenario where a compressed representation must be split across devices for operations involving normalization or softmax-like non-linearities could potentially use the same approach: find an orthogonal transform that makes the partitioned statistics predictable.

The paper's empirical finding that **different orthogonal families are optimal for different operations** (Figure 2) adds an important nuance. Hadamard transforms balance variance uniformly and work well for RMSNorm (where balanced partitioning means local RMS ≈ global RMS) but fail for softmax (where sign cancellations between balanced partitions destroy proportionality). PCA concentrates variance and works well for softmax (where one partition dominates the attention score, making the local computation close to the global) but may generalize poorly to more than two partitions. This operational specificity—that the choice of transform depends on which operation you're decomposing—is a non-trivial characterization of what makes each operation difficult to shard.

Prior work on tensor parallelism (Megatron-LM, Shoeybi et al., 2019) assumed matrices could be split along naturally independent dimensions (rows, columns, heads). Prior work on low-rank compression (Palu, LoRC, cited in Section 2) focused on reducing dimensionality but did not address distributed computation. TPLA bridges these literatures by showing that **the choice of basis in which compression is represented matters for shardability**, and that orthogonal transforms provide a principled way to re-basis the compressed space for distributed execution. This is a genuinely new idea at the intersection of linear algebra, attention computation, and distributed systems.

### Innovation 3: Prefill–Decode Phase Separation as a Principle for Inference-Time Architecture Switching

The paper introduces a practical design principle that, to our knowledge, has not been articulated in prior inference optimization work: **use different attention computation strategies during prefill and decode, because the two phases have fundamentally different computational bottlenecks, and switching between them requires no retraining if the underlying latent representation is shared.** This goes beyond simple disaggregation (which runs prefill and decode on different machines, as in DistServe or Dynamo) to actually changing the mathematical structure of the attention computation itself—MLA during prefill, TPLA during decode—within the same model weights.

The key insight is that the orthogonal reparameterization makes this switching possible without weight duplication. Because `U` is absorbed into `W_DKV` and `W_UKV` once (Equation 17), the transformed latent space is shared between both phases. During prefill, the model operates in this transformed space using full MLA (no slicing of RMSNorm/softmax), which is compute-optimal. During decode, it switches to TPLA in the same transformed space, but now slices for memory-bandwidth optimality. There is no need for two sets of weights or on-the-fly conversion—the latent representation is the same, only how it's consumed differs.

This phase-aware switching is what enables the "free lunch" in Figure 4: TPLA with PD separation achieves 1.4× faster time-to-first-token than TPLA without separation at 1K prompt length, because it avoids TPLA's per-device head duplication during the compute-bound prefill. Meanwhile, it preserves the 1.79× decode throughput gain (Figure 3) because it uses full TPLA during the memory-bound decode. Neither phase suffers the overhead of the other's optimal strategy.

The broader principle this establishes is that **inference-time architecture adaptation based on workload characteristics is viable when the adaptation can be expressed as a change in computational pattern rather than a change in model parameters**. This is distinct from dynamic batching, speculative decoding, or quantization-level switching—it's a change in how attention is computed (which dimensions are local vs. global) based on whether the current phase is compute-bound or memory-bound. As models become larger and context lengths grow, this principle could extend to other architectural choices: perhaps different sparse attention patterns for prefill vs. decode, different activation checkpointing strategies, or different degrees of quantization per phase.

The empirical validation that this phase switching works *without any training* (Tables 1 and 2, TPLA PD-sep. rows) is crucial: DeepSeek-V2-Lite achieves 6.31 WikiText-2 perplexity (identical to original MLA) and DeepSeek-V3 drops only 2.15 points on LongBench average. This demonstrates that the orthogonal reparameterization's approximation error accumulates almost entirely during decode (where it's applied to one token at a time), not prefill (where it processes all prompt tokens with exact MLA). The separation effectively quarantines the approximation error to the phase where memory-bandwidth savings dominate any accuracy cost.

### Innovation 4: Empirical Characterization of Why Naive Latent Partitioning Fails—The Asymmetric Sensitivity of RMSNorm vs. Softmax to Variance Distribution

While the orthogonal reparameterization framework is the paper's constructive contribution, an equally important diagnostic finding emerges from the ablation in Figure 2: **slicing RMSNorm and softmax have qualitatively different failure modes and are sensitive to different properties of the latent partition, and the optimal reparameterization strategy must account for both.** This is not merely a hyperparameter tuning observation—it reveals fundamental differences in how these two operations interact with variance distribution across dimensions.

The empirical evidence (Figure 2, "norm only" vs. "softmax only" bars) shows:
- When only RMSNorm is sliced (softmax uses full dimension via all-gather), Hadamard-based reparameterization performs comparably to PCA and near the original MLA. This means RMSNorm slicing is **forgiving**—it only requires that each partition's local norm be predictably related to the global norm, which both balanced (Hadamard) and concentrated (PCA) partitions satisfy.
- When only softmax is sliced (RMSNorm uses full dimension), the PCA-based method dramatically outperforms Hadamard and vanilla. This means softmax slicing is **brittle**—it requires that the local attention scores be proportional to the global scores, which balanced partitions (Hadamard) fail due to sign cancellations, and concentrated partitions (PCA) succeed because one partition dominates.
- When both are sliced (the full TPLA setting), PCA consistently dominates, confirming that softmax is the binding constraint.

This differential sensitivity is not predicted by any prior theory of tensor parallelism or attention computation. It tells us something specific about the mathematical structure of these operations: RMSNorm is a **smooth, norm-based statistic** that is robust to how variance is distributed as long as the distribution is predictable; softmax is a **ratio of exponentials** that is acutely sensitive to the alignment (not just magnitude) of partitioned components, because the exponential amplifies differences and the denominator couples all partitions through the sum.

This finding matters beyond TPLA because it suggests a general principle for distributed attention: **operations that involve normalization across a sum of exponentials (softmax, sigmoid, etc.) are the primary bottleneck for tensor-parallel decomposition, not operations that involve simple norm computations.** Any future attempt to tensor-parallelize a compressed attention variant should expect RMSNorm-like operations to be relatively easy to shard and softmax-like operations to be the hard case requiring careful conditioning of the latent basis. The paper's characterization of why Hadamard fails—"small per-sample perturbations may result in significant asymmetries" in softmax—points toward a more general sensitivity analysis of how basis choice affects exponential-family decomposability.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** Commonsense reasoning is evaluated on six benchmarks using the LightEval framework: MMLU (Hendrycks et al., 2021), ARC Easy and Challenge (Clark et al., 2018), PIQA (Bisk et al., 2020), HellaSwag (Zellers et al., 2019), OpenBookQA (Mihaylov et al., 2018), and WinoGrande (Sakaguchi et al., 2021). Long-context understanding is evaluated on LongBench (Bai et al., 2023), a bilingual multi-task benchmark comprising 21 tasks across six categories (question answering, summarization, few-shot learning, code, and synthetic tasks). Perplexity is measured on WikiText-2 (Merity et al., 2016). The calibration set for PCA-based reparameterization is also WikiText-2. For lightweight alignment, the paper uses SmolLM-Corpus (Ben Allal et al., 2024) with 100M tokens.

- **Base model(s).** The paper evaluates on four MLA-based model families: DeepSeek-V2-Lite (a smaller model, roughly 16B total parameters based on the DeepSeek-V2 paper), DeepSeek-V2 (~236B total parameters), DeepSeek-V3-0324 (685B parameters), and Kimi-K2-Base (1T parameters). Additionally, LLaMA-2-7B is converted from GQA to MLA via TransMLA and then to TPLA, demonstrating the method's applicability to non-MLA architectures through the TransMLA bridge. The paper also evaluates a TransMLA-converted checkpoint released by the TransMLA authors. These models span varying scales and include both dense (LLaMA-2-7B, DeepSeek-V2-Lite, DeepSeek-V2) and Mixture-of-Experts architectures (DeepSeek-V3, Kimi-K2). For throughput and latency measurements, MoE is removed from DeepSeek-V3 and Kimi-K2 to isolate attention speed effects.

- **Metrics.** Commonsense performance is reported as per-task accuracy (%) and an average across all six benchmarks (Avg.↑). WikiText-2 performance is reported as perplexity (PPL↓). LongBench is reported as average score across all 21 tasks, with per-category breakdowns (MultiQA, SingleQA, Summarize, Few-Shot, Code, Synthetic). Throughput is measured in tokens per second during decoding at varying prefill context lengths (1K to 32K tokens). Time-to-first-token (TTFT) is measured in milliseconds during the prefill phase at varying prompt lengths (1K to 16K tokens). Speedups are reported as multiplicative factors (e.g., 1.79×) comparing TPLA to MLA at the same configuration.

- **Baselines.** Four baselines appear throughout the experiments. **(1) Original MLA:** the unmodified pre-trained model using MLA computation, serving as the accuracy upper bound. **(2) GLA (Zadouri et al., 2025):** direct conversion of MLA to Grouped Latent Attention by partitioning attention heads into two groups and assigning each group half the latent dimension (Section 3.2). **(3) TPLA-Vanilla:** TPLA conversion without any orthogonal reparameterization—parameters are split evenly across devices with no conditioning of the latent. This isolates the contribution of reparameterization. **(4) TransMLA (Meng et al., 2025):** for LLaMA-2-7B, the GQA-to-MLA conversion method, which serves as the starting point for TPLA conversion, allowing comparison against the original GQA model.

- **Generation budget / compute accounting.** TPLA is an inference-time architecture modification, not a sampling strategy—there is no generation budget in the sense of number of samples. The relevant compute accounting is: **(1) KV cache memory per device** (dimensions per token), which directly determines memory-bandwidth-bound decode throughput. TPLA reduces this from 4d_h to 2d_h per device for TP=2 (e.g., DeepSeek-V3 goes from 576 to 320 dimensions per token). **(2) Computational complexity** of attention, analyzed in Section 4.5 as arithmetically equivalent between TPLA and MLA under TP=2 for the attention computation itself, with modest overhead in Q computation and RoPE. **(3) Training FLOPs:** lightweight alignment uses 100M tokens at batch size 32, sequence length 4096, on 8×GPUs—a negligible fraction of pre-training cost. The training-free conversion uses zero gradient steps (only PCA computation on WikiText-2 latents). **(4) Inference throughput and latency** are measured directly in tokens/sec and ms on hardware described below, not estimated from FLOP counts.

- **Hardware and implementation.** Commonsense and LongBench evaluations use a node with 8× GPUs (96 GB per GPU, ~148 FP16 TFLOPS each). Throughput and latency measurements in Figures 3 and 4 use two GPUs (TP=2) with FlashAttention-3, with MoE removed from DeepSeek-V3-0324 and Kimi-K2-Base to isolate attention effects. Both models are converted to BF16. Maximum batch size at each context length is configured as shown in Figure 3. The maximum input context length for LongBench is 31,500 tokens for DeepSeek-V2-Lite and 127,500 tokens for DeepSeek-V3 due to GPU memory constraints; output lengths match the original LongBench paper. Alignment experiments follow the TransMLA setting: batch size 32, learning rate 2e-5, warmup ratio 0.03, cosine scheduler, max sequence length 4096. Layer-wise feature matching uses 256 random samples of length 2048 for 10 epochs with the Muon optimizer at learning rate 1e-6.

- **Cross-validation / statistical protocol.** No cross-validation is performed—results are reported on standard benchmark test sets. For commonsense reasoning, standard evaluation protocols from LightEval are used. For LongBench, the standard test split is used. The paper does not report confidence intervals, standard deviations, or multiple runs with different random seeds for the throughput/latency measurements in Figures 3 and 4. The PCA reparameterization depends on WikiText-2 calibration data; no sensitivity analysis to calibration dataset choice or size is reported. The two-fold cross-validation protocol described in the reference example paper is not used here—TPLA has no hyperparameter selection over strategies per difficulty bin, as it is a deterministic conversion rather than an adaptive inference policy.

### Main Quantitative Results

#### TPLA Preserves MLA Performance with Minimal Degradation on Commonsense Tasks

Table 1 reports the core accuracy comparison between original MLA models and their TPLA-converted counterparts across six commonsense benchmarks plus WikiText-2 perplexity. The headline finding is that TPLA with prefill–decode separation achieves near-identical performance to the original MLA models **without any training**, while TPLA with lightweight alignment (100M tokens) recovers essentially all remaining degradation.

For **DeepSeek-V2-Lite**, the numbers are:
- **Original MLA:** WikiText-2 perplexity 6.31, commonsense average 61.75.
- **Direct GLA conversion:** perplexity 2212, average 33.77—catastrophic degradation confirming that restricting heads to local latent shards destroys representational capacity.
- **TPLA (training-free, no PD separation):** perplexity 7.24, average 54.33. This is substantially better than GLA but shows non-trivial degradation (7.42 points below MLA on average), indicating the approximation error from slicing both RMSNorm and softmax in both phases.
- **TPLA (align):** perplexity 6.51, average 61.52—only 0.23 points below MLA on average, with individual benchmarks showing similarly tight gaps (MMLU: 42.72 vs. 43.19, HellaSwag: 73.32 vs. 74.46). This demonstrates that 100M tokens of alignment is sufficient to recover nearly all conversion-induced loss.
- **TPLA (PD-sep.):** perplexity 6.31, average 61.44—essentially identical to MLA on perplexity and only 0.31 points below on average, achieved with **zero training**. The per-benchmark breakdown shows no systematic pattern of degradation: MMLU (43.19 vs. 43.19, identical), ARC Easy+Challenge (60.14 vs. 60.39, slightly lower), PIQA (80.09 vs. 80.20), HellaSwag (74.41 vs. 74.46), WinoGrande (65.59 vs. 65.43, actually slightly higher), OBQA (45.20 vs. 45.80).

For **DeepSeek-V2** (the 236B model), Table 1 reports:
- **Original MLA:** perplexity 3.89, average 68.32.
- **TPLA (training-free, no PD separation):** perplexity 4.72, average 63.40—a 4.92-point drop, larger than DeepSeek-V2-Lite's drop, suggesting the approximation error may scale with model capacity or that the PCA basis computed on WikiText-2 is less representative for larger models.
- PD-separation results are not reported for DeepSeek-V2, which is a gap—it would be informative to see whether PD separation alone closes the gap for the larger dense model as effectively as it does for V2-Lite.

For **DeepSeek-V3** (the 685B MoE model):
- **Original MLA:** perplexity 3.24, average 72.10.
- **TPLA (training-free, no PD separation):** perplexity 4.02, average 68.00—a 4.10-point drop. The degradation is proportionally similar to DeepSeek-V2, suggesting a consistent conversion cost across model scales when no phase separation or alignment is used.

For **Kimi-K2-Base** (the 1T MoE model):
- **Original MLA:** perplexity 1.91, average 73.52.
- **TPLA (training-free, no PD separation):** perplexity 2.44, average 70.49—a 3.03-point drop. Kimi-K2 shows the smallest relative degradation among the large models, possibly due to differences in how its MLA latent is structured or trained.

For **LLaMA-2-7B** via TransMLA bridge:
- **Original LLaMA-2-7B:** perplexity 5.47, average 59.85.
- **TransMLA (GQA→MLA conversion):** perplexity 5.88, average 58.95.
- **TPLA (from TransMLA checkpoint):** perplexity 6.74, average 54.68—a degradation of 4.27 points from the TransMLA baseline. This is notable because it demonstrates the full pipeline: GQA→MLA→TPLA, with cumulative conversion loss at each step. The paper does not report PD-separation or alignment results for the LLaMA-2-7B TPLA variant, which would clarify how much of this loss is recoverable.

**What these numbers collectively demonstrate:** TPLA conversion without training introduces a consistent but modest perplexity increase (roughly 20–25% relative increase for the DeepSeek models, e.g., 6.31→7.24 for V2-Lite, 3.89→4.72 for V2, 3.24→4.02 for V3) and a 7–10% relative drop in commonsense average accuracy. However, **the prefill–decode separation eliminates essentially all of this degradation** for DeepSeek-V2-Lite (perplexity returns to 6.31, exactly matching MLA), demonstrating that the error is concentrated in the prefill phase where slicing approximations process many tokens simultaneously. For DeepSeek-V3, PD-separation results are not reported for commonsense (only LongBench in Table 2), which is a missing data point—it would be the most practically important model for practitioners.

#### TPLA on Long-Context Tasks: PD Separation Maintains Strong Performance Without Training

Table 2 reports LongBench results for DeepSeek-V2-Lite and DeepSeek-V3. Long-context evaluation is critical because approximation errors from softmax and RMSNorm slicing accumulate with sequence length—the longer the context, the more tokens each attention operation processes, and the more slicing errors compound.

For **DeepSeek-V2-Lite** on LongBench (maximum context 31,500 tokens):
- **Original MLA:** average 28.90, with strong performance on Few-Shot (62.59) and Code (57.86), moderate on SingleQA (20.04) and Summarize (16.74), weak on MultiQA (12.43) and Synthetic (3.77).
- **TPLA (training-free, no PD separation):** average 10.98—a catastrophic 17.92-point drop. This is dramatically worse than the commonsense degradation (61.75→54.33 for TPLA without PD separation), confirming that **slicing errors accumulate with sequence length** and make training-free TPLA without phase separation unusable for long contexts. Every category degrades: MultiQA (12.43→6.96), SingleQA (20.04→9.20), Summarize (16.74→6.91), Few-Shot (62.59→25.29), Code (57.86→14.41), Synthetic (3.77→3.11).
- **TPLA (align):** average 22.60—a substantial recovery but still 6.30 points below MLA. The alignment helps most on Few-Shot (25.29→58.03, recovering most of the 62.59 baseline) and Summarize (6.91→16.59, nearly matching 16.74). However, it helps little on MultiQA (6.96→10.97 vs. 12.43), Code (14.41→31.59 vs. 57.86), and Synthetic (3.11→3.77 vs. 3.77, unchanged). The paper attributes this limited effectiveness to the alignment corpus being "formed by concatenating short texts" (Section 5.2)—4096-token sequences—so the model never learns to compensate for slicing errors at the 31,500-token scale during alignment.
- **TPLA (PD-sep.):** average 24.44—**better than the aligned variant** (24.44 vs. 22.60) and achieved with zero training. The per-category breakdown reveals an interesting pattern: PD separation dramatically helps Few-Shot (14.41→46.67, though still below MLA's 62.59) and Code (14.41→46.67), but actually **worsens** Summarize (16.59→8.62 vs. the aligned variant's 16.59 and MLA's 16.74) and SingleQA (14.67→15.07, well below MLA's 20.04). This suggests PD separation quarantines slicing errors to the decode phase, which differentially affects tasks—some tasks (Few-Shot, Code) benefit from exact prefill computation because their prompts contain most of the task structure, while others (Summarize) may be more sensitive to the quality of auto-regressive generation where decode-phase errors accumulate.

For **DeepSeek-V3** on LongBench (maximum context 127,500 tokens):
- **Original MLA:** average 58.19, with excellent performance on Few-Shot (69.42), Code (80.09), Synthetic (68.63), and strong on MultiQA (55.37) and SingleQA (51.65).
- **TPLA (training-free, no PD separation):** average 44.52—a 13.67-point drop. This is proportionally less severe than V2-Lite's collapse (roughly 24% relative drop vs. 62% for V2-Lite), but still substantial. The degradation pattern differs: Summarize drops most severely (23.97→12.55), followed by Few-Shot (69.42→53.01), Code (80.09→61.20), MultiQA (55.37→35.02), and SingleQA (51.65→38.53). Synthetic is surprisingly robust (68.63→66.83). This varying sensitivity across categories mirrors V2-Lite and suggests systematic differences in how task types interact with latent slicing.
- **TPLA (PD-sep.):** average 56.04—a drop of only 2.15 points from MLA's 58.19, achieved with **zero training**. This is the paper's strongest result for practical deployment: a 685B model preserving 96% of its LongBench performance while gaining 1.79× decode throughput (Figure 3a). The per-category breakdown shows near-perfect preservation on MultiQA (55.37→53.01), SingleQA (51.65→50.17), Synthetic (68.63→68.47), and good preservation on Few-Shot (69.42→67.22), Code (80.09→75.97), and Summarize (23.97→21.39). The largest absolute drop is in Code (4.12 points), which may reflect sensitivity to decode-phase approximation errors during long code generation.

**What these LongBench results collectively demonstrate:** The prefill–decode separation is not merely a nice-to-have optimization—it is **essential** for long-context tasks. Without it, training-free TPLA degrades catastrophically on V2-Lite (28.90→10.98) and substantially on V3 (58.19→44.52). With PD separation, V3 retains 96.3% of its LongBench performance (56.04/58.19). The finding that PD separation outperforms 100M-token alignment on V2-Lite (24.44 vs. 22.60) is notable and counterintuitive—it suggests that alignment on short sequences can actually interfere with long-context generalization in the TPLA setting, perhaps by overfitting to patterns that don't transfer to the sliced attention regime at scale.

#### Inference Throughput: TPLA Achieves 1.79×–1.93× Decode Speedup at 32K Context

Figure 3 reports decoding throughput (tokens/sec) for DeepSeek-V3-0324 (Figure 3a) and Kimi-K2-Base (Figure 3b) comparing MLA and TPLA, both using FlashAttention-3 with TP=2 and MoE removed. The key pattern is that TPLA's speedup over MLA **increases with context length**, consistent with the analysis that longer contexts amplify the memory-bandwidth bottleneck that TPLA addresses.

For **DeepSeek-V3-0324** (Figure 3a), the speedups at each prefill length are:
- 1K: 1.33× (MLA throughput at some base level, TPLA 33% higher)
- 2K: 1.38×
- 4K: 1.45×
- 8K: 1.57×
- 16K: 1.65×
- 32K: 1.79×

The monotonic increase with context length confirms the mechanistic story: at short contexts, non-attention overhead (Q computation, RoPE doubling) partially offsets the memory-bandwidth savings from halving the latent dimension. As context length grows, the attention's memory traffic—which scales as O(S_KV × d_latent)—increasingly dominates, and the 2× reduction in d_latent translates more directly to throughput gains. The speedup is sub-linear in the dimension reduction (1.79× vs. the theoretical 2×) because: (a) non-attention operations don't benefit from latent halving, (b) Q computation and RoPE overhead are higher in TPLA, and (c) the all-reduce communication adds latency.

For **Kimi-K2-Base** (Figure 3b), the speedups are:
- 1K: 1.28×
- 2K: 1.35×
- 4K: 1.51×
- 8K: 1.55×
- 16K: 1.76×
- 32K: 1.93×

Kimi-K2 shows slightly larger speedups than DeepSeek-V3 at longer contexts (1.93× vs. 1.79× at 32K). The paper does not analyze why, but plausible factors include different ratios of attention to non-attention computation, different head counts affecting RoPE overhead, or different memory access patterns. The near-2× speedup at 32K suggests that for Kimi-K2 at this context length, the overhead factors are nearly negligible relative to the memory-bandwidth savings.

**What these throughput results do and do not demonstrate:** They demonstrate that halving the per-device KV cache dimension yields substantial decode throughput improvements at realistic context lengths (4K–32K), validating the core motivation for TPLA. However, several caveats apply: (1) MoE is removed for timing, so these are purely attention speed measurements—in a production MoE model, expert routing and communication would add overhead that might dilute the relative speedup; (2) only TP=2 is tested, so scaling behavior at higher TP degrees is unknown; (3) only two models are tested, both using MLA, so generalizability to other MLA variants is assumed; (4) absolute throughput numbers are not reported, only multiplicative speedups, so practitioners cannot estimate tokens/sec for their specific hardware.

#### Prefill Latency: PD Separation Provides 1.4× TTFT Improvement

Figure 4 reports time-to-first-token (TTFT) in milliseconds for DeepSeek-V3-0324 (a) and Kimi-K2-Base (b), comparing TPLA without PD separation to TPLA with PD separation, both with MoE removed and TP=2. TTFT measures the latency to process the entire prompt and generate the first output token—this is the user-facing delay before generation begins.

For **DeepSeek-V3-0324** (Figure 4a), the speedups of PD separation over standard TPLA are:
- 1K: 1.45×
- 2K: 1.40×
- 4K: 1.32×
- 8K: 1.22×
- 16K: 1.12×

The speedup **decreases** with prompt length. This is the inverse of the decode throughput pattern and confirms the phase characterization: prefill is compute-bound. At short prompts (1K), the compute savings from head-splitting (MLA's approach) give a large relative advantage. At longer prompts (16K), the O(L²) attention computation dominates, and the head-splitting advantage is diluted by the quadratic scaling of attention FLOPs, which are the same regardless of how heads are split.

For **Kimi-K2-Base** (Figure 4b), the pattern is similar but with slightly smaller speedups:
- 1K: 1.41×
- 2K: 1.35×
- 4K: 1.29×
- 8K: 1.21×
- 16K: 1.13×

The paper describes this as "essentially a 'free lunch'" (Section 5.4.2) because PD separation adds no accuracy cost—the prefill computation in TPLA (PD-sep.) is mathematically identical to MLA (the same reparameterized weights, no RMSNorm/softmax slicing). The speedup comes purely from avoiding TPLA's head duplication during prefill.

**Absolute TTFT numbers are plotted on a log scale** (10² to 10³ ms), with TPLA (PD-sep.) consistently on the lower curve and TPLA without separation on the upper curve. The paper does not report exact TTFT values in text, only the multiplicative factors in Figure 4.

#### Qualitative Summary of Results Across All Three Axes

Across commonsense (short-text, Table 1), LongBench (long-context, Table 2), and throughput/latency (Figures 3 and 4), the results paint a coherent picture:
- **TPLA without PD separation or alignment** introduces non-trivial but manageable accuracy loss on short texts (perplexity +15–25%, average accuracy −7–10%) but fails on long contexts (V2-Lite LongBench collapses from 28.90 to 10.98).
- **TPLA with PD separation** eliminates essentially all accuracy loss on short texts (V2-Lite perplexity returns to MLA's 6.31 exactly) and preserves 96% of LongBench performance on V3 (56.04 vs. 58.19), all without training.
- **TPLA with 100M-token alignment** recovers commonsense accuracy to near-MLA levels but is less effective for long contexts than PD separation (V2-Lite LongBench: 22.60 aligned vs. 24.44 PD-sep.).
- **Decode throughput** improves by 1.28–1.93× depending on model and context length, with larger gains at longer contexts, validating the memory-bandwidth reduction hypothesis.
- **Prefill latency** with PD separation is 1.12–1.45× faster than TPLA without separation, with larger gains at shorter prompts, confirming that avoiding head duplication during compute-bound prefill is beneficial.

### Ablation Studies and Robustness Checks

The paper conducts ablation studies primarily through the controlled comparisons in Table 1 and Figure 2. These are not traditional hyperparameter ablations but rather **structural ablations** that isolate the contribution of each reparameterization choice and each component of TPLA.

**MLA → GLA conversion vs. MLA → TPLA conversion:** Table 1, comparing the GLA row to the TPLA row for DeepSeek-V2-Lite. GLA produces perplexity 2212 and average accuracy 33.77; TPLA without any reparameterization or PD separation produces perplexity 7.24 and average 54.33. The massive gap (2212 vs. 7.24 perplexity) directly quantifies the cost of restricting heads to local latent shards (GLA) vs. preserving full head-to-latent connectivity (TPLA). This is the paper's central motivation for preferring TPLA over GLA.

**Reparameterization method: Hadamard vs. PCA vs. Vanilla for individual components:** Figure 2 is the key ablation, analyzing DeepSeek-V2-Lite across six commonsense benchmarks. The figure tests three parallelization configurations (norm only, softmax only, both) crossed with three reparameterization strategies (vanilla/equal split, Hadamard, PCA), plus the original MLA baseline. Findings:

**(1) Error ordering:** Across all strategies, the degradation order is consistent: slicing only RMSNorm < slicing only softmax < slicing both. For example, with PCA, TPLA (norm only)-PCA shows near-MLA performance on most benchmarks, while TPLA (softmax only)-PCA shows larger gaps, and TPLA (both)-PCA shows the largest gaps. This empirically validates the paper's theoretical claim that softmax slicing is the harder problem.

**(2) TP on RMSNorm only:** Hadamard-based reparameterization achieves "performance comparable to the original MLA model on multiple tasks" (Section 5.3.2). PCA also performs well. Vanilla equal splitting performs worse, confirming that some conditioning is needed even for RMSNorm—the orthogonal transform's norm-balancing or variance-concentrating properties matter.

**(3) TP on softmax only:** PCA dominates dramatically. The paper states: "PCA-based method concentrates information into the dimensions assigned to device 1, effectively preserving performance. In contrast, the Hadamard-based method fails to improve softmax accuracy." The hypothesis is that "the exponential nature of softmax makes it more sensitive to imbalance" and that Hadamard's balancing, while statistically even, produces sign cancellations that make local softmax poor approximators of the global softmax.

**(4) TP over both RMSNorm and softmax:** PCA consistently achieves the best performance across all benchmarks. This is why PCA is adopted as the default reparameterization for all experiments in Tables 1 and 2 (unless stated otherwise).

The specific accuracy values in Figure 2 are reported as bars and not exact numbers in the text, but the visual shows clear separation between methods. MMLA (the purple horizontal line) represents the original DeepSeek-V2-Lite accuracy. TPLA-Vanilla (both sliced, vanilla split) shows the largest drops. TPLA-PCA (both sliced) consistently approaches MLA performance on PIQA, HellaSwag, and Winogrande while showing larger gaps on MMLU and ARC. TPLA-Hadamard (both sliced) performs intermediately.

**Training-free vs. aligned vs. PD-separation TPLA:** Table 1 rows for TPLA, TPLA (align), and TPLA (PD-sep.) on DeepSeek-V2-Lite quantify the tradeoffs:
- **TPLA (no PD, no alignment):** perplexity 7.24, average 54.33—baseline training-free conversion cost.
- **TPLA (align):** perplexity 6.51, average 61.52—alignment adds 0.73 perplexity improvement and 7.19 accuracy points, at the cost of 100M tokens of training.
- **TPLA (PD-sep.):** perplexity 6.31, average 61.44—PD separation alone achieves better perplexity than alignment (6.31 vs. 6.51) and comparable accuracy (61.44 vs. 61.52), at zero training cost.

The near-identical accuracy between alignment and PD separation for commonsense suggests that for short-text tasks, PD separation is strictly preferable—same accuracy, zero training. However, the LongBench results in Table 2 complicate this: for V2-Lite, PD separation outperforms alignment (24.44 vs. 22.60), but it's unclear whether alignment + PD separation combined would outperform either alone. The paper does not test this combination.

**TransMLA bridge for non-MLA models:** Table 1, LLaMA-2-7B rows. The progression is: original LLaMA-2-7B (5.47 perplexity, 59.85 average) → TransMLA conversion to MLA (5.88, 58.95) → TPLA conversion (6.74, 54.68). The TPLA step introduces an additional 0.86 perplexity increase and 4.27 accuracy drop beyond the TransMLA conversion loss. This establishes that TPLA can be applied to models not originally trained with MLA, but the cumulative conversion cost is larger than for natively MLA-trained models. The paper does not report PD-separation or alignment results for LLaMA-2-7B-TPLA, which would indicate how much of this loss is recoverable—a notable missing ablation.

**LongBench failure of TPLA without PD separation:** Table 2, comparing TPLA vs. TPLA (PD-sep.) for DeepSeek-V2-Lite (average 10.98 vs. 24.44) and DeepSeek-V3 (44.52 vs. 56.04). This is not presented as a formal ablation but serves as one: the presence vs. absence of PD separation has a much larger effect on LongBench than on commonsense (V2-Lite: +13.46 LongBench points from PD separation vs. +7.11 commonsense points). This quantifies how slicing errors compound with sequence length and validates the phase-separation design.

**Training data quantity for alignment:** The paper uses 100M tokens for the end-to-end alignment stage (following TransMLA). It does not ablate over alignment data quantity—no results are reported for 10M, 50M, or 500M tokens. Given that 100M tokens recovers most but not all commonsense accuracy (61.52 vs. 61.75 for V2-Lite) and is insufficient for LongBench (22.60 vs. 28.90), the scaling behavior of alignment data is an important open question. Would 1B tokens close the LongBench gap? Would fine-tuning on long-context data specifically help? These are not tested.

**Calibration dataset for PCA:** The paper uses WikiText-2 for PCA computation. No ablation over calibration dataset (e.g., SmolLM-Corpus, C4, or in-domain data for the target task) or calibration data quantity is reported. The sensitivity of the PCA basis to calibration data choice could be significant—if the latent distribution in the target task differs substantially from WikiText-2, the variance concentration ratios (α, β) would be miscalibrated, potentially increasing slicing error. This is a robustness concern for deployment on out-of-distribution tasks.

**Hadamard transform variants:** The paper tests only the standard Walsh-Hadamard construction with a random ±1 diagonal. It does not test dimension-permuted Hadamard matrices (mentioned as future work in Section 6) or other orthogonal families (e.g., discrete cosine transform, random orthogonal matrices). The paper hypothesizes that "an optimized Hadamard matrix via dimension permutations that minimizes the discrepancy between partitions" could improve softmax slicing, but this is left untested.

**Layer-wise vs. full-model feature matching:** The alignment procedure has two stages—layer-wise feature matching (MSE on input/output features) followed by end-to-end output alignment. The paper does not ablate the layer-wise stage (e.g., whether end-to-end alignment alone would suffice) or the hyperparameters of either stage (number of samples, epochs, optimizer choice). Given that 256 random samples for 10 epochs is a small amount of data, this stage's contribution to the final accuracy is unclear.

**Reparameterization for individual layers vs. globally:** The PCA computation is described as collecting KV latents "from all layers" (Section 4.3.2). It is not specified whether a single PCA basis is computed globally and applied to all layers, or whether per-layer PCA bases are computed. Given that latent distributions likely differ across layers (earlier layers encode lower-level features, later layers encode higher-level semantics), a global PCA basis may be suboptimal for individual layers. This design choice and its impact are not ablated.

### Critical Assessment

**Do the experiments support the paper's central claims?** The paper makes several claims, which we examine in turn against the experimental evidence.

**Claim 1: "TPLA preserves the benefits of a compressed KV cache while unlocking TP efficiency."** The evidence supports this claim with important qualifiers. The benefit of a compressed KV cache is reduced memory per device—TPLA achieves this by halving the latent dimension per device (from 4d_h to 2d_h for TP=2). Figures 3a and 3b demonstrate that this translates to 1.28–1.93× decode throughput improvements depending on model and context length, with larger gains at longer contexts. This is genuine and practically significant. However, "unlocking TP efficiency" is demonstrated only for TP=2 on two GPUs. The paper does not evaluate TP=4 or TP=8, which are common configurations for 685B+ models. At TP=4 with TPLA configured as described in Section 4.4 (g=2 groups, k/g=2 devices per group), each device would hold a 2d_h latent and h_q/2 heads—the per-device memory would be further reduced, but the all-reduce communication pattern becomes more complex (within-group all-reduce plus potentially cross-group synchronization). The throughput scaling at higher TP degrees is an open question. Furthermore, MoE is removed for all timing experiments, so the claim of "TP efficiency" applies strictly to the attention component, not end-to-end model inference where expert routing and communication may dominate.

**Claim 2: "Every head in TPLA still leverages the full latent representation, maintaining stronger representational capacity [than GLA]."** The evidence strongly supports this. Table 1 shows GLA causing catastrophic degradation (perplexity 2212 for V2-Lite) while TPLA preserves reasonable performance (perplexity 7.24 without training, 6.31 with PD separation). The mechanism is clear: TPLA's all-reduce combines partial attention outputs, so each head's effective attention sees the full latent, while GLA restricts each head to a local shard. However, the claim of "full latent representation" is approximate, not exact—the slicing of RMSNorm and softmax means the representation on each device is an approximation of what the full latent would produce. PD separation reduces this approximation to zero during prefill but not during decode. So TPLA heads see a slightly distorted version of the full latent during decode, and the claim of "full" should be understood as "functionally equivalent up to a small approximation error" rather than "mathematically identical."

**Claim 3: "TPLA is drop-in compatible with models pre-trained using MLA... without retraining."** Partially supported. TPLA can indeed load MLA checkpoints directly and convert them via orthogonal reparameterization without gradient updates. The training-free TPLA (PD-sep.) on DeepSeek-V2-Lite achieves identical WikiText-2 perplexity to MLA (6.31 vs. 6.31) and near-identical commonsense average (61.44 vs. 61.75). However, for LongBench, training-free TPLA (PD-sep.) on DeepSeek-V3 drops 2.15 points on average (56.04 vs. 58.19), which is modest but non-zero. And on DeepSeek-V2-Lite LongBench, even PD-separation leaves a 4.46-point gap (24.44 vs. 28.90). So "without retraining" is not universally lossless—it works with negligible degradation for short texts and moderate degradation for long texts. The "drop-in" characterization is reasonable for many use cases but practitioners should expect some long-context accuracy cost without fine-tuning. Additionally, the PCA reparameterization requires a calibration pass over WikiText-2, which is not strictly "drop-in"—it requires representative data and offline computation, though no weight updates.

**Claim 4: "Applying simple orthogonal transforms... before TP slicing further mitigates cross-shard interference, yielding minimal accuracy degradation."** Strongly supported by Figure 2. The comparison between TPLA-Vanilla (no orthogonal reparameterization) and TPLA-PCA or TPLA-Hadamard shows clear improvements across all benchmarks. PCA-based reparameterization consistently achieves the best performance when both RMSNorm and softmax are sliced. The "minimal accuracy degradation" characterization is fair for PCA with PD separation on short texts, but for long texts without PD separation, the degradation is substantial (Table 2: V2-Lite drops from 28.90 to 10.98, which is not "minimal"). The claim should be qualified: minimal degradation when combined with PD separation, or when evaluated on short contexts.

**Claim 5: "By reducing the per-device KV cache... we achieve 1.79× and 1.93× speedups, respectively, at a 32K-token context length while maintaining performance."** The speedup numbers are well-supported by Figure 3. The "while maintaining performance" part is supported by Table 1 (commonsense) and Table 2 (LongBench with PD separation on V3 showing only 2.15-point drop) but with the qualifier that LongBench evaluation is at context lengths up to 127,500 tokens, while the speedup is measured from 1K to 32K prefill length—not at the full 127.5K context used for accuracy evaluation. There is a mismatch between the context length at which speedups are measured (up to 32K) and the context length at which accuracy is evaluated (up to 127.5K). The speedup at 127.5K is not reported and would likely be even larger (extrapolating the trend in Figure 3), but this is not directly measured. Additionally, "maintaining performance" on LongBench for V3 means 56.04 vs. 58.19—a 3.7% relative drop, which some practitioners would consider meaningful. Whether 1.79× throughput compensates for a 3.7% accuracy drop is a deployment-specific tradeoff the paper does not quantify.

**Genuine weaknesses in the experimental design:**

**(1) No end-to-end system benchmarks with MoE enabled.** All throughput and latency numbers (Figures 3 and 4) remove MoE layers. For DeepSeek-V3 and Kimi-K2, which are MoE models, the attention component is one part of a larger system. In production, expert routing, all-to-all communication for expert parallelism, and load balancing would affect end-to-end throughput. The 1.79× attention speedup does not directly translate to 1.79× end-to-end speedup—it would be diluted by the non-attention components of the model. The paper does not provide end-to-end throughput numbers, which are what practitioners ultimately care about.

**(2) Single TP configuration (TP=2) for all speed measurements.** The paper's analysis in Section 4.4 describes how TPLA generalizes to higher TP degrees, but Figure 3 only measures TP=2 on two GPUs. DeepSeek-V3 at 685B parameters would typically be deployed with TP=4 or TP=8. At TP=4 with g=2 (the recommended configuration), each GPU would hold 2d_h latent and h_q/2 heads—different from the TP=2 configuration where each GPU holds 2d_h latent and h_q heads. The throughput scaling to higher TP degrees (does the speedup over MLA increase, decrease, or stay constant?) is not characterized.

**(3) No confidence intervals or variance estimates.** All accuracy, perplexity, throughput, and latency numbers are reported as point estimates without error bars, standard deviations, or multiple runs. Throughput measurements can vary across runs due to GPU clock fluctuations, memory controller contention, and thermal throttling. For the commonsense benchmarks, the standard evaluation protocol typically involves deterministic greedy decoding, so variance would come from benchmark sampling rather than model stochasticity, but this is still not reported.

**(4) Missing PD-separation results for DeepSeek-V3 and Kimi-K2 on commonsense.** Table 1 reports TPLA (PD-sep.) only for DeepSeek-V2-Lite. For DeepSeek-V3 and Kimi-K2, only TPLA without PD separation is reported. This is a significant gap—DeepSeek-V3 is the most practically important model (685B, widely deployed), and practitioners need to know whether PD separation on V3 achieves near-MLA commonsense accuracy as it does for V2-Lite. The LongBench results in Table 2 (V3 PD-sep.: 56.04 vs. 58.19) are encouraging but don't substitute for commonsense evaluation.

**(5) PD separation helps some LongBench categories but hurts others—no investigation of why.** For DeepSeek-V2-Lite LongBench, PD separation improves Few-Shot and Code dramatically over the aligned variant (14.41→46.67 for Code) but worsens Summarize (16.59→8.62) compared to alignment. The paper notes this but offers no analysis. Understanding which task characteristics make them sensitive to decode-phase slicing errors would help practitioners anticipate deployment performance on their specific tasks.

**(6) No sensitivity analysis to PCA calibration data.** The PCA basis is computed once on WikiText-2. If a practitioner deploys TPLA on a domain far from WikiText-2 (e.g., code, medical text, non-English languages), the PCA variance distribution may be miscalibrated, potentially increasing approximation error. The paper neither tests domain shift robustness nor provides guidance on calibration data selection.

**(7) The GLA baseline is a strawman in one important sense.** The paper compares against GLA by directly converting an MLA-pretrained model to GLA without retraining, which causes catastrophic degradation (perplexity 2212). But GLA's authors (Zadouri et al., 2025) presumably intended GLA to be pre-trained from scratch, not converted. A fairer comparison would include GLA models trained from scratch at the same scale—but this is computationally prohibitive, which is exactly the paper's point about TPLA's practical advantage. The paper is transparent about this: GLA is shown as a conversion baseline to demonstrate that restricting head access is fundamentally harmful, not as a claim that GLA is an inferior architecture when trained from scratch. The distinction matters for interpreting the representational capacity claim.

**(8) The TransMLA bridge for LLaMA-2-7B is promising but incomplete.** TPLA is applied to LLaMA-2-7B via the TransMLA conversion, showing the pipeline works. But the TPLA accuracy (54.68 average vs. 61.44 for native V2-Lite TPLA with PD separation) is much lower, the PD-separation variant is not tested, and alignment is not tested. The full potential of TPLA for non-MLA models remains unclear. Given that most deployed models use GQA (not MLA), the TransMLA→TPLA pathway is practically important but under-explored.

**Missing experiments that would strengthen the paper:**

- **End-to-end throughput with MoE enabled**, ideally at realistic serving batch sizes. This would show the actual production speedup, not just the attention-component speedup.
- **TP=4 and TP=8 scaling curves** for decode throughput, to characterize how the speedup over MLA changes with parallelism degree.
- **PD-separation results for DeepSeek-V3 and Kimi-K2 on commonsense benchmarks**—these are the models practitioners care about most.
- **Alignment on long-context data** (e.g., concatenated sequences at 32K+ length) to see if the LongBench gap can be closed without PD separation, or if PD separation + long-context alignment combines the benefits of both.
- **Ablation over calibration data for PCA**—testing WikiText-2 vs. SmolLM-Corpus vs. code data vs. in-domain data, to characterize robustness.
- **Comparison with alternative approaches to the same problem**, such as applying token-wise KV cache pruning on top of MLA under TP, or combining MLA with sequence parallelism instead of tensor parallelism for the KV cache.
- **Memory footprint measurements**—the paper argues that reducing per-device KV cache memory is the mechanism for throughput improvement, but actual GPU memory usage (GB) before and after TPLA conversion is not reported. A memory reduction from, say, 40 GB to 20 GB per device for the KV cache at 32K context would directly validate the mechanism.
- **Scaling behavior with number of attention heads**—the paper's analysis in Section 4.5 notes that TPLA doubles the effective number of heads for RoPE. Testing how this overhead scales with native head count (e.g., DeepSeek-V2-Lite with fewer heads vs. V3 with more) would characterize a potential scaling limitation.

**Where claims hold conditionally:**

- **"Drop-in compatible without retraining"**: holds for short-text tasks (perplexity and commonsense are essentially unchanged with PD separation), holds partially for long-context tasks (PD separation preserves 96% of V3 LongBench performance with a 2.15-point absolute drop). The drop, while modest, is non-zero and task-dependent.
- **"Minimal accuracy degradation"**: holds for commonsense with PD separation (≤0.31 points average drop), holds for LongBench on V3 with PD separation (2.15 points drop—modest in absolute terms, 3.7% relative), does NOT hold for LongBench without PD separation (V2-Lite drops 17.92 points, V3 drops 13.67 points).
- **"Stronger representational capacity than GLA"**: holds strongly for converted models (2212 vs. 7.24 perplexity). For models trained from scratch with each architecture, the comparison is not tested and the paper does not claim superiority—only that TPLA preserves more capacity when converting from MLA.
- **"1.79×–1.93× speedup"**: holds at 32K context with TP=2 and MoE removed. At shorter contexts the speedup is smaller (1.28–1.33× at 1K). At higher TP degrees, speedup is unknown. With MoE enabled, speedup is unknown.

## 6. Limitations and Trade-offs

### 6.1 PCA-Based Reparameterization Does Not Extend Beyond Two Latent Partitions

**The assumption or constraint.** TPLA's default reparameterization strategy—Principal Component Analysis—succeeds by concentrating variance in the leading principal components so that the first partition dominates the attention score computation (Condition 2, Section 4.3.2). This concentration property is precisely what makes PCA fail when the latent must be split into more than two partitions. The paper explicitly acknowledges this in Section 6:

> "PCA concentrates most of the data's informative content in the first few dimensions, which provide a representative summary of the global structure. In contrast, the later dimensions primarily capture negligible noise and minor variations that contribute minimally to the overall representation. Consequently, TPLA with group-partitions g = 2 can achieve good performance, but when g > 2, it probably fails to maintain effectiveness."

In other words, PCA makes the first partition information-rich and the second partition information-poor, which works for g = 2. For g = 3 or g = 4, the middle partitions would have no well-defined relationship to the global latent—they capture neither the dominant signal (which is in the first partition) nor negligible noise (which is in the last partition)—and there is no principled way to assign meaningful scaling coefficients μ, ν, τ, … for the softmax slicing approximation.

**The consequence.** This is a hard scalability ceiling. Tensor parallelism is most commonly used at TP = 4 or TP = 8 for large models (DeepSeek-V3 at 685B would typically require at least 4 GPUs for the model weights alone, before any KV cache). The paper demonstrates TP = 2 with g = 2 (two devices, two latent groups), which halves the per-device KV cache. To halve it again (TP = 4 with g = 4), each device would hold only 4d_h/4 = d_h latent dimensions—but this is the regime where PCA-based reparameterization "probably fails." The paper cannot deliver further memory reductions at higher tensor-parallel degrees without switching to a fundamentally different reparameterization strategy. A practitioner with 8 GPUs cannot run TPLA at TP = 8 with g = 8 to get 8× per-device KV cache reduction; they are capped at g = 2, which means the per-device KV cache reduction is at most 2× regardless of how many GPUs are available.

Additionally, the concentration property makes TPLA's accuracy sensitive to the latent dimension's inherent rank structure. If a model's MLA latent has near-uniform variance across dimensions (unlike the DeepSeek models, where PCA works well), the α and β coefficients would be close to 0.5 and 0.5, meaning both partitions contribute substantially to the attention score—exactly the regime where softmax slicing error is largest (as shown in Figure 2, where vanilla equal-split performs worst). The paper provides no diagnostic or mitigation for this case.

**What evidence exists in the paper.** The limitation is stated explicitly in Section 6 and supported indirectly by Figure 2. Figure 2 shows that PCA dominates Hadamard and vanilla for g = 2 when both RMSNorm and softmax are sliced. But the paper never tests g > 2—no experiment with g = 4, no experiment with TP = 4 using TPLA's described multi-group scheme (Section 4.4). The generalization to k devices with g groups is described mathematically (Section 4.4: "TPLA divides k devices into r group size of size k/g") but never evaluated. Even the throughput measurements (Figures 3 and 4) use only TP = 2 on two GPUs, so the practical speedup at higher parallelism degrees—which is where TPLA's memory savings would be most needed—is unknown.

**Mitigation status.** The paper identifies Hadamard-based transforms as a potential alternative: "By contrast, numerical-value balancing via orthogonal transforms, particularly the Hadamard transform, tends to be more effective when partitioning into multiple groups." However, the same sentence acknowledges that Hadamard currently fails for softmax slicing (Figure 2, "TPLA-Hadamard" underperforms PCA). The paper suggests "design[ing] and evaluat[ing] optimized Hadamard-like orthogonal matrices to balance softmax slicing, thereby improving both robustness and scalability" as future work. No solution exists in the current paper. A practitioner who needs TP = 4 or TP = 8 cannot use TPLA with g > 2 and expect maintained accuracy.

### 6.2 All Throughput Measurements Exclude Mixture-of-Experts Layers, Overstating End-to-End Gains for DeepSeek-V3 and Kimi-K2

**The assumption or constraint.** The paper's headline speedup claims—1.79× for DeepSeek-V3 and 1.93× for Kimi-K2 at 32K context—are measured exclusively on the attention component of these models. Section 5.4.1 states:

> "Because these models are extremely large and Mixture-of-Experts (MoE) routing can confound attention-speed effects, we remove MoE for timing."

This is a reasonable experimental control for isolating attention throughput, but it means the reported numbers measure the speedup of one component (attention) in a system where other components (expert routing, all-to-all communication, shared expert computation) contribute substantially to end-to-end latency and are unaffected by TPLA. DeepSeek-V3 uses 256 routed experts with top-8 gating plus 1 shared expert per MoE layer; the attention layers are interleaved with MoE FFN layers throughout the model. Halving the attention KV cache memory traffic improves attention throughput, but the non-attention computation and communication—which may dominate at certain batch sizes and sequence lengths—are unchanged.

**The consequence.** The 1.79× attention speedup does not translate to a 1.79× end-to-end decoding speedup. The actual end-to-end gain is diluted by the fraction of total inference time spent in attention vs. MoE computation. At short contexts, attention is a smaller fraction of total compute, so the dilution is larger—exactly the regime where Figure 3 already shows smaller speedups (1.33× at 1K). At long contexts, attention dominates more, so the dilution is smaller—but even at 32K, some fraction of each forward pass is spent in MoE routing and FFN computation that TPLA does not accelerate. The paper provides no end-to-end throughput numbers, so practitioners cannot estimate their actual speedup.

For Kimi-K2 (1T parameters, also MoE), the same dilution applies, potentially more severely given the larger model scale and potentially different attention-to-MoE compute ratios.

Additionally, the MoE removal means that expert parallelism communication patterns—all-to-all communication for dispatching tokens to experts and combining expert outputs—are absent from the timing. In a real deployment, expert parallelism may use separate communication channels (NVLink, InfiniBand) that contend with the all-reduce communication TPLA adds for combining partial attention outputs. The interaction between TPLA's all-reduce and MoE's all-to-all communication on shared interconnects is not characterized and could reduce the net speedup below what Figure 3 suggests.

**What evidence exists in the paper.** The MoE removal is stated explicitly in Section 5.4.1 but not flagged as a limitation—it's presented as a methodological choice for clean measurements. No end-to-end throughput numbers with MoE enabled are reported anywhere in the paper. Section 5.4.2 similarly measures prefill latency (TTFT) with MoE removed (Figure 4). The paper provides no decomposition of end-to-end latency into attention vs. non-attention components for DeepSeek-V3 or Kimi-K2, so the dilution factor cannot be estimated from the paper's data alone.

**Mitigation status.** Not addressed. The paper does not discuss the end-to-end throughput implication of MoE removal, does not report the fraction of inference time spent in attention for these models, and does not provide even an analytical estimate of expected end-to-end speedup. A practitioner deploying DeepSeek-V3 with TPLA would need to run their own benchmarks to determine the actual throughput gain.

### 6.3 PCA Calibration Data Dependency Is Not Tested, Threatening Robustness Under Domain Shift

**The assumption or constraint.** The PCA-based reparameterization computes eigenvectors and eigenvalues from the KV latent distribution of the pre-trained MLA model on WikiText-2 (Section 4.3.2: "we process a calibration dataset (e.g., Wikitext-2) to collect the KV latent cache"). The resulting orthogonal transform U and the scaling coefficients α, β, μ, ν are functions of this calibration data. The implicit assumption is that WikiText-2 latents are representative of the latent distribution the model will encounter at deployment time. If the deployment distribution differs—e.g., code generation (latents from programming language syntax), medical text (domain-specific terminology), non-English languages, or long-form structured documents—the PCA basis computed on WikiText-2 may not align with the actual variance structure of the deployment latents.

**The consequence.** Two failure modes arise. First, the α and β coefficients could be miscalibrated: if the deployment data has a different variance concentration ratio than WikiText-2, the local RMSNorm approximations (Equation 19) would systematically over- or under-normalize each partition, introducing additional approximation error that compounds with sequence length. Second, the PCA directions themselves (the eigenvectors in U) might not capture the dominant variance directions of the target domain, meaning the rotation does not achieve the intended concentration of information in the first partition. In the worst case, the target domain's latents could have near-uniform variance in the PCA-rotated space, effectively degenerating to the vanilla equal-split case that Figure 2 shows performs worst.

The paper provides no sensitivity analysis—no experiment where TPLA is calibrated on WikiText-2 and evaluated on a substantially different domain, or calibrated on one corpus and compared against calibration on another. Without this characterization, a practitioner deploying TPLA on, say, a code completion task faces unknown accuracy risk. The LongBench results in Table 2 provide partial evidence: LongBench includes code tasks (where TPLA PD-sep. on V3 achieves 75.97 vs. 80.09 for MLA, a 4.12-point drop, larger than the average drop of 2.15) and synthetic tasks. But these are still evaluated with WikiText-2-calibrated PCA, so the accuracy gap conflates domain-shift-induced calibration error with inherent slicing approximation error.

**What evidence exists in the paper.** The calibration dataset choice is mentioned once in Section 4.3.2 and once in Section 5.1 ("we first use WikiText-2 as a calibration set"). No ablation over calibration datasets is reported—no comparison with SmolLM-Corpus, C4, code data, or in-domain data. The paper does not report the variance concentration ratios (α values) for the tested models, which would help practitioners assess whether PCA is strongly concentrating (high α, well-conditioned for TPLA) or weakly concentrating (low α, closer to the risky uniform-variance regime). The robustness to domain shift is not discussed as a limitation.

**Mitigation status.** Not addressed. The paper does not suggest re-calibrating PCA on in-domain data as a deployment practice, does not provide guidance on calibration data selection, and does not characterize the sensitivity of TPLA accuracy to the calibration distribution. The Hadamard transform—which is data-independent and therefore robust to domain shift—is acknowledged as preferable for scalability (Section 6) but its current failure on softmax slicing prevents it from serving as a domain-robust alternative.

### 6.4 Generalization Is Tested Only on MLA-Native Models; the TransMLA Bridge for Non-MLA Architectures Shows Substantial Degradation

**The assumption or constraint.** TPLA is presented as a method for converting MLA-based models to a tensor-parallel-efficient form. The paper demonstrates this on DeepSeek-V2-Lite, DeepSeek-V2, DeepSeek-V3, and Kimi-K2—all models natively trained with MLA. However, the paper also claims broader applicability via the TransMLA bridge (Meng et al., 2025), which can convert standard MHA or GQA models to MLA, and then to TPLA. The LLaMA-2-7B experiment in Table 1 tests this pipeline. The implicit claim is that TPLA can benefit models beyond the DeepSeek/Moonshot ecosystem.

**The consequence.** The LLaMA-2-7B results in Table 1 show that the GQA → TransMLA → TPLA pipeline introduces cumulative conversion loss. Specifically: original LLaMA-2-7B achieves 5.47 perplexity and 59.85 average commonsense accuracy. TransMLA conversion to MLA achieves 5.88 perplexity and 58.95 average accuracy—a 0.41 perplexity increase and 0.90 accuracy drop, attributable to the GQA-to-MLA conversion. Further TPLA conversion (without PD separation or alignment) achieves 6.74 perplexity and 54.68 average accuracy—an additional 0.86 perplexity increase and 4.27 accuracy drop. The total degradation from the original GQA model is 1.27 perplexity (23% relative increase) and 5.17 accuracy points (8.6% relative drop). This is substantially worse than TPLA conversion for natively MLA-trained models: DeepSeek-V2-Lite TPLA (no PD, no alignment) loses 0.93 perplexity (15% increase) and 7.42 accuracy points (12% drop) compared to its MLA baseline, but crucially, the MLA baseline is the native architecture—there is no GQA-to-MLA conversion loss to compound with TPLA loss.

Moreover, the paper does not test PD separation or alignment for the LLaMA-2-7B TPLA variant, so it's unknown whether these mitigations would recover the loss as effectively as they do for native MLA models. The current evidence says: if you start with a GQA model, convert it to MLA via TransMLA (which has its own conversion cost), then convert to TPLA, you incur both conversion costs additively. The final accuracy (54.68 average) is substantially below the original GQA model (59.85), making the pipeline unattractive unless the throughput gains (not measured for LLaMA-2-7B) are exceptionally large.

For most deployed models in early 2025—LLaMA-3/4, Mistral, Qwen, Gemma—which use GQA, not MLA, the practical path to TPLA is through TransMLA with cumulative accuracy cost that is not well-characterized beyond a single 7B-scale experiment.

**What evidence exists in the paper.** Table 1, LLaMA-2-7B rows. The paper acknowledges the TransMLA conversion loss implicitly (by reporting the TransMLA row separately) but does not flag the cumulative conversion cost as a limitation. No PD-separation or alignment results are reported for LLaMA-2-7B-TPLA, and no results exist for any other non-MLA model. The throughput improvement for LLaMA-2-7B-TPLA is not measured (Figures 3 and 4 are DeepSeek-V3 and Kimi-K2 only), so we cannot assess whether the speedup justifies the accuracy loss.

**Mitigation status.** The paper suggests future work on training TPLA-based models from scratch (Section 6: "we will post-pretrain DeepSeek-V3, or train a TPLA-based model from scratch, to further demonstrate TPLA's excellent expressiveness"), which would bypass the cumulative conversion problem. But for existing non-MLA models, no mitigation is offered beyond the untested suggestion that PD separation and alignment might help. The TransMLA bridge is presented as a feature ("With TransMLA as a bridge, TPLA can be applied to pretrained models that originally use MLA, GQA, or MHA"—Section 5.1) without the caveat that the cumulative accuracy cost is substantially larger than for native MLA models.

### 6.5 Prefill–Decode KV Cache Reuse Relies on the Reparameterized Latent Space Being Shared Between Phases, but the Accuracy–Throughput Tradeoff at the Phase Boundary Is Not Characterized

**The assumption or constraint.** The prefill–decode separation (Section 4.5) works by using reparameterized MLA during prefill (no RMSNorm/softmax slicing, full 4d_h latent, heads split across devices) and TPLA during decode (RMSNorm/softmax sliced, 2d_h latent per device, all heads per device). The prefill KV cache is stored in the reparameterized latent space (c_KV after transformation by U) and must be re-interpreted by the TPLA decode phase: the cache is sliced across devices, and each device's RMSNorm and attention computation operate on a 2d_h slice rather than the full 4d_h. The paper states this reuse is possible because "the MLA reparameterization enables the prefill KV cache to be used directly by TPLA at decode time" (Section 5.3.1). This assumes that the orthogonally transformed latent produced during prefill is compatible with the sliced computation during decode without additional conversion.

**The consequence.** This reuse introduces a subtle but potentially consequential discrepancy: during prefill, the KV cache entries are normalized by the full RMSNorm over 4d_h dimensions (exact). During decode, each device sees only 2d_h dimensions of each cached entry and normalizes by a local RMS scaled by √(α/2). The prefill-produced normalized latents ĉ_KV (used as the attention keys and values during decode) were computed with global RMS, but the decode phase's attention expects latents normalized by the local RMS approximation. The paper does not discuss whether the KV cache needs to be re-normalized at the prefill–decode boundary, or whether the prefill-computed normalized latents are stored and used as-is during decode despite the normalization mismatch. This could introduce a systematic error in early decode steps, which gradually diminishes as new tokens (normalized under the sliced scheme) accumulate in the cache.

Furthermore, the accuracy–throughput Pareto frontier is not mapped. PD separation eliminates prefill slicing error (since prefill uses exact MLA), but introduces a structural mismatch between the prefill-produced KV cache and the decode-phase attention that consumes it. Without PD separation, the prefill KV cache is produced under the same sliced normalization as decode, so the representations are consistent, but the prefill accuracy is lower (due to slicing). The paper reports PD separation as strictly better for accuracy on commonsense (Table 1: TPLA PD-sep. 61.44 vs. TPLA 54.33 on V2-Lite), but does not report whether a mixed strategy—e.g., using PD separation for short contexts where prefill accuracy matters more, and full TPLA (no separation) for long contexts where decode consistency matters more—would be optimal. The LongBench results in Table 2 show PD separation beating alignment for V2-Lite (24.44 vs. 22.60) but not recovering full MLA performance (28.90), leaving a 4.46-point gap whose source (prefill–decode mismatch vs. inherent decode slicing error) is not diagnosed.

**What evidence exists in the paper.** Table 1 (TPLA vs. TPLA PD-sep. on V2-Lite) shows PD separation substantially improves commonsense accuracy. Table 2 (TPLA vs. TPLA PD-sep. on V2-Lite and V3 LongBench) shows large improvements for PD separation but with residual gaps to MLA. Figure 4 shows PD separation improves TTFT by 1.12–1.45×. However, no experiment directly measures whether the prefill–decode KV cache mismatch contributes to the residual LongBench gap. No ablation tests whether re-normalizing the prefill cache at the decode boundary (to match local RMS) improves or worsens accuracy. No experiment compares full TPLA vs. PD-separation across a range of context lengths to map the accuracy–throughput Pareto curve.

**Mitigation status.** The paper does not acknowledge this as a potential issue. The discussion in Section 5.3.1 characterizes PD separation as unambiguously beneficial: "avoiding RMSNorm/softmax partitioning in prefill reduces approximation error for the vast majority of tokens." The possibility of a consistency cost at the phase boundary is not mentioned. The residual LongBench gap after PD separation (V2-Lite: 24.44 vs. MLA 28.90; V3: 56.04 vs. MLA 58.19) is attributed generically to slicing errors, without decomposing how much comes from the decode phase itself vs. the phase-boundary mismatch.

### 6.6 The Training-Free Conversion Still Requires a Calibration Pass That May Not Be Practical for All Deployment Scenarios

**The assumption or constraint.** The paper presents TPLA's training-free conversion—using PCA reparameterization computed from WikiText-2 latents—as a key advantage over GLA's requirement to train from scratch. This is accurate: no gradient updates are needed for the conversion. However, the calibration pass itself has non-trivial practical requirements that the paper does not discuss. Computing the PCA basis requires:

1. **Access to the full pre-trained model** and the ability to run forward passes on a calibration dataset to collect KV latents from all layers. For DeepSeek-V3 (685B parameters), running WikiText-2 through the model to collect latents across all tokens and all layers requires substantial GPU memory and compute—not at the scale of training, but non-trivial. The paper does not report the computational cost of this calibration pass (GPU-hours, memory requirements).

2. **Eigendecomposition of a (4d_h × 4d_h) covariance matrix.** For DeepSeek-V3, 4d_h = 512, so this is a 512 × 512 eigendecomposition—computationally trivial. However, for models with larger latent dimensions (if future MLA variants increase 4d_h), this scales as O((4d_h)^3).

3. **Absorption of the orthogonal transform into weight matrices** (Equation 17: W^{UKV}_{new} = U^T W_γ W^{UKV} and W^{DKV}_{new} = W^{DKV} U). This involves matrix multiplications between U (4d_h × 4d_h) and the weight matrices. For W^{DKV} ∈ R^{D × 4d_h} (e.g., D = 7168 for DeepSeek-V3, 4d_h = 512), this is a (7168 × 512) × (512 × 512) multiplication—modest. For W^{UKV}, the up-projection matrices have larger output dimensions (h_q · d_h), making the absorption more expensive, though still a one-time cost.

**The consequence.** The "training-free" characterization is technically correct (no gradient updates) but may create a misleading impression of zero cost. A practitioner deploying TPLA must: (1) allocate GPU resources for the calibration pass, (2) collect and store latents from all layers (potentially large intermediate activations for long calibration sequences), (3) compute PCA per layer or globally, (4) absorb U into weight matrices through matrix multiplications, and (5) validate that the converted model's accuracy is acceptable on their target tasks. This is a non-trivial engineering pipeline, especially for the largest models.

More importantly, the calibration pass assumes the practitioner has access to a representative calibration dataset. For models deployed in proprietary or sensitive domains (e.g., internal corporate data, medical records, classified information), the practitioner may not have a publicly available calibration corpus that matches their deployment distribution. Running the calibration on a mismatched corpus (e.g., WikiText-2 for a code-generation deployment) risks the domain-shift calibration error discussed in Limitation 6.3. The paper offers no guidance on minimum calibration data requirements, how to assess calibration quality, or how to adapt the calibration to the target domain.

For models behind an API (where weights are not downloadable), the calibration pass is impossible—the user cannot access intermediate latents or modify weight matrices. TPLA is therefore applicable only to openly available models or models deployed in-house, not to API-accessed models (e.g., the DeepSeek API, Kimi API).

**What evidence exists in the paper.** The calibration procedure is described in Section 4.3.2 but its computational cost is not quantified. The paper does not report GPU-hours, memory footprint, or wall-clock time for the PCA calibration on any model. The weight absorption step is described mathematically (Equation 17) but its implementation cost—in terms of peak memory for the matrix multiplications—is not discussed. The paper does not report the time required for the full training-free conversion pipeline end-to-end.

**Mitigation status.** The paper does not address the practical cost or domain requirements of the calibration pass. The Hadamard transform alternative (Section 4.3.1) is data-independent and would eliminate the need for calibration data and PCA computation, but it currently fails for softmax slicing (Section 6, Figure 2). The paper's future work on "optimized Hadamard-like orthogonal matrices" would address this limitation if successful, but no solution exists currently. The paper does not discuss the API-accessibility limitation at all.
