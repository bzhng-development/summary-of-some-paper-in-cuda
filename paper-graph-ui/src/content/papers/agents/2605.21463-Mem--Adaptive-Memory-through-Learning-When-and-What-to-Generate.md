# Mem-π: Adaptive Memory through Learning When and What to Generate

**ArXiv:** [2605.21463](https://arxiv.org/abs/2605.21463)

## 🎯 Pitch

Retrieving static hints from a memory bank actually *hurts* an AI agent more than 30% of the time, yet Mem-π turns memory into a generative policy that learns to stay silent on those tasks, boosting overall success by over 20% and nearly doubling web navigation scores.

---

## 1. Executive Summary

This paper introduces **Mem-π**, a framework that reformulates agent memory as a **generative policy**—a dedicated language or vision-language model fine-tuned to produce context-specific guidance on demand rather than retrieving static entries from memory banks. The policy jointly learns **when to generate** and **what to generate** (adaptive abstention vs. task-specific hints) through a **decision-content decoupled RL objective**, which separates the routing decision from content optimization using structured counterfactual rollouts with paired abstain and generate branches. Evaluated across four diverse agentic benchmarks—WebArena, WorkArena, ALFWorld, and LifelongAgentBench—using Qwen-2.5-7B-Instruct as the memory backbone and gpt-5.4-mini as the downstream agent, Mem-π achieves over 20% relative improvement on average over retrieval-based baselines, with gains approaching 50% on WebArena (43.1% vs. 27.1% base agent), while using 31% fewer memory tokens than always-on generation, establishing that adaptive generative memory substantially outperforms retrieval-centric systems only when the policy learns to abstain on tasks where memory would be unhelpful or counterproductive.

## 2. Context and Motivation

### The Core Problem: Agent Memory Is Stuck in a Retrieval Paradigm

The fundamental problem this paper addresses is deceptively simple: **how can an LLM agent remember and reuse useful guidance from prior experience without being constrained by static, pre-stored memory entries?** Current LLM agents—systems that use language models to take actions in environments like websites, terminals, or simulated worlds—face a critical limitation: they are stateless. Each new interaction starts from scratch. An agent that has solved a Magento admin task 100 times in training has no built-in mechanism to distill that experience into a compact, reusable form when facing the 101st task.

To address this, the field has converged on **external memory banks** (Section 1, Figure 1): during training or prior interaction, the agent stores "memory fragments"—hints, trajectories, skill descriptions—in a database, and at inference time retrieves the most similar entries via similarity search (e.g., BM25 or embedding-based retrieval). This is the paradigm underlying RAG (retrieval-augmented generation), Mem0, and a host of workflow-based memory systems (Packer et al., 2023; Fu et al., 2024; Ouyang et al., 2025).

The paper argues that this retrieval-centric approach has a **fundamental structural limitation**: retrieved memories are **inherently static and context-agnostic**. A hint retrieved from the memory bank was written for a specific source task and encodes that task's specifics verbatim—a count, a product name, a navigation path. When the new query differs in even a small way (e.g., the source task asked for "top 2 search terms" but the current query asks for "top 3"), the retrieved hint copies the source's "2" directly and misleads the agent. More subtly, even when the retrieved hint is generally relevant, it may encode assumptions (a specific product family, an outdated workflow) that no longer apply. The paper provides concrete evidence of this in the case studies (Figure 6, Case 1): RAG retrieves a hint that says "read the first two rows" because the most similar source task was a top-2 query, while the current task asks for top-3. The hint is "close" in embedding space but contains a **verbatim error** that generation can fix.

This is not merely an engineering annoyance—it reflects a deep misalignment between how retrieval-based memory operates and what is actually needed. The cognitive science framing (Section 1, paragraph 3) is instructive: human memory is not literal replay but **constructive reconstruction**, where recollection is dynamically synthesized from prior knowledge and current context (Bartlett, 1932; Schacter et al., 1998). Retrieval-based memory, by contrast, is closer to a photocopy—it can only reproduce what was stored, with no ability to adapt the stored content to the present situation.

### Why This Problem Matters: Real-World Stakes

The paper operates at the intersection of three practical trends that make the retrieval-limitation problem increasingly acute:

**1. The shift from single-task to lifelong agent deployment.** Early agent evaluations (e.g., WebArena, ALFWorld) tested agents on individual tasks in isolation. But as agents move toward continuous deployment—embodied assistants, enterprise automation, research copilots—they accumulate experience across thousands of interactions. A retrieval-based memory bank grows linearly with the number of experiences, creating a **scaling problem**: the bank becomes larger, retrieval becomes slower and less precise, and the agent must manage merging, forgetting, and staleness of entries (Yin et al., 2024; Hu et al., 2024; Zhong et al., 2024). A generative memory policy, by contrast, has a **fixed memory footprint** bounded by model size, not the number of accumulated experiences. This is a practical advantage for deployment on resource-constrained devices or in systems where memory management overhead would become prohibitive.

**2. The unreliability of generated memory as an intervention.** Recent work such as ParaMem (Yao et al., 2026) and SEAM (Li et al., 2026) has begun exploring **generative memory**—using a model to produce guidance on the fly rather than retrieving it. This is a step in the right direction, but the paper identifies a critical weakness in how these methods operate: they either generate memory unconditionally (as an always-on auxiliary step) or treat generation as a retrieval imitation task, optimizing the generator to reproduce the same content a retriever would have returned. This creates a **reliability concern** that is especially acute when memory is an *intervention on a downstream agent* rather than the final output. If the generator produces guidance that is irrelevant, misleading, or hallucinated, it can actively harm the agent's performance—causing the agent to follow a plausible-sounding but incorrect procedure, or distracting it with unnecessary detail. The paper quantifies this indirectly through the performance drop when Stage 1 (always-on generation) is compared to the full Mem-π with abstention (Table 1: Stage 1 achieves 35.0% on WebArena while Mem-π achieves 43.1%, a gap of +8.1 pp driven largely by the ability to abstain on easy tasks). The implication is clear: **unconditional generation is not just inefficient—it can be counterproductive.**

**3. The gap between memory content optimization and memory routing optimization.** Learning-based memory systems such as Memory-R1 (Yan et al., 2025) and MemRL (Zhang et al., 2026b) have advanced beyond fixed retrieval pipelines by training controllers with reinforcement learning to optimize memory operations—when to store, what to retrieve, how to update. However, these methods still operate within the retrieval paradigm: they learn **better retrieval policies** but the memory content itself remains fixed at write time. This creates a ceiling: even with perfect retrieval, the retrieved content is bounded by what was originally stored, and cannot be adapted to the query's specific requirements. The paper's central claim is that **generation can break through this ceiling** by synthesizing guidance that fuses signals from many past experiences into a single context-specific hint—something retrieval fundamentally cannot do, since it must return discrete entries.

### Where Prior Approaches Fall Short

The paper organizes prior work along two axes and identifies specific failure modes for each (Section 1, Figure 1; Section 4):

**Workflow-based memory (RAG, Mem0, JEF-Hinter).** These systems use predefined rules for memory construction, retrieval, and update. The agent writes experiences to a bank (often by distilling raw traces into structured hints using tools like JEF-Hinter), and at inference retrieves the top-k most similar entries via BM25 or dense retrieval.

The specific shortcomings are:
- **Static content**: Retrieved entries are fixed at write time. If the query differs in even a small detail (e.g., "top 3" vs. "top 2"), the retrieved hint copies the source verbatim and introduces an error (Figure 6, Case 1).
- **No abstention mechanism**: Retrieval always returns *something*—the top-k entries, even if k=1 and the similarity score is low. The paper shows (Figure 6, Case 2) that injecting an irrelevant or narrowly-scoped hint can actively mislead the agent, whereas abstaining would restore the base agent's correct behavior.
- **Memory bank scaling**: The bank grows with experience, requiring merging, deduplication, and staleness management (Zhong et al., 2024; Yin et al., 2024). This is a practical overhead that parametric memory avoids entirely.

**Learning-based memory (Memory-R1, MemRL, Mem-α).** These systems train a controller (often an LLM itself) to optimize memory operations—what to store, when to retrieve, how to update—using downstream task outcomes as reward signals via RL.

The specific shortcomings are:
- **Still retrieval-centric**: The controller learns to retrieve *better*, but the content is still pulled from a static bank. The paper acknowledges these methods "improve when and how to access stored entries, but the memory content itself is fixed at write time" (Section 4, paragraph 2).
- **No content adaptation**: Even with optimized retrieval policies, the retrieved entry cannot be rewritten to match the query's specific numbers, identifiers, or format requirements. The case studies show that this verbatim copying is a persistent source of errors.
- **Separate controller overhead**: These methods require an additional trainable component (a memory manager or Q-value estimator) on top of the agent and memory bank, increasing system complexity.

**Early generative memory (ParaMem, SEAM, MemGen).** These methods train models to produce memory guidance on demand rather than retrieving it, representing the closest prior work to Mem-π.

The paper identifies three specific gaps in this line of work:
- **Always-on generation**: These methods invoke generation as an unconditional auxiliary step—memory is always produced, even for tasks where the base agent already knows what to do. This wastes tokens and, critically, can introduce noise that degrades performance on easy tasks (quantified in Mem-π's 31% token reduction vs. Stage 1 in Figure 5).
- **Retrieval imitation objective**: Many generative memory methods are trained to imitate the output of a retriever—the training signal comes from matching generated memory to reference hints in the bank. This bounds the generator's output to the quality and specificity of the retrieval baseline it imitates, defeating the purpose of moving beyond retrieval.
- **No reliability mechanism**: There is no built-in mechanism for the generator to determine when generation would be unhelpful and abstain. This is the paper's key architectural innovation—adding an explicit [ABSTAIN] option and training the policy to use it via structured RL.

### How Mem-π Positions Itself

The paper frames its contribution not as a single new memory method but as a **paradigm shift** from retrieval-centric to generative memory, with two distinguishing properties (Section 1, paragraph 4):

**1. Memory as a parametric policy, not a database lookup.** Rather than storing experiences in an external bank, Mem-π **distills** experiences into the parameters of a dedicated model (πmem) via supervised learning (Stage 1: Experience Distillation). This model can then **synthesize** guidance for novel tasks by combining signals from many past experiences, producing hints that are conditioned on the specific query rather than copying from the most similar stored entry. This is directly contrasted with retrieval: "since πmem synthesizes guidance on demand rather than copying stored entries, it can fuse signals from many past experiences into a single context-specific hint, unlike top-k retrieval, which may split them across fragments or omit them beyond the cutoff" (Section 1, paragraph 5).

**2. Adaptive abstention as a first-class decision.** The paper argues that the key reliability challenge for generative memory is not generating good guidance (Stage 1 already does that reasonably well) but knowing **when not to generate**. Mem-π introduces an explicit decision token space {[GENERATE], [ABSTAIN]} and trains the policy via RL to abstain when generation would not improve downstream task outcomes. This is formalized through the **decision-content decoupled RL objective** (Section 2.2), which uses structured counterfactual rollouts to compare abstain and generate branches directly, decomposing the learning signal into separate decision-level and content-level advantages.

**3. Separation of specialization from execution.** A practical design choice with significant deployment implications: Mem-π uses a **separate model** for memory generation (Qwen-2.5-7B-Instruct) from the downstream agent (which can be a different, potentially larger model like gpt-5.4-mini). This means a smaller, privately fine-tuned model can serve as the memory policy and be plugged into a frontier agent to leverage its broader reasoning capabilities—a separation that retrieval-based systems (where the bank is model-agnostic) and monolithic RL-trained controllers (where the manager and agent are often coupled) do not support as cleanly.

The paper explicitly connects this to the cognitive science literature on constructive memory (Bartlett, 1932; Schacter et al., 1998; Schacter & Addis, 2007) to motivate why generation is a more appropriate model for agent memory than retrieval: "human remembering is not a literal replay mechanism... but a constructive process, where recollection is dynamically reconstructed from prior knowledge and the current context" (Section 1, paragraph 3). This is not just rhetorical—it motivates the architecture: if memory is reconstruction, then the model needs both the ability to synthesize (Stage 1) and the ability to recognize when reconstruction would be unreliable (Stage 2's abstention).

### The Unresolved Challenge That Motivates the Technical Contribution

The paper's technical centerpiece—the **decision-content decoupled RL objective**—is motivated by a specific optimization challenge that prior approaches do not address. When training a generative memory policy with RL, the output consists of two qualitatively different components: a short decision prefix (d ∈ {[GENERATE], [ABSTAIN]}, 1 token) and, if generating, a potentially long guidance sequence (m, up to 256 tokens). Under a standard per-token policy gradient (like vanilla GRPO), the gradient signal is averaged across all tokens. This creates two problems:

- **Decision-token gradient dilution**: The content tokens (which are numerous) dominate the gradient, suppressing the signal to the decision token. The policy may learn to generate good content but fail to learn when to abstain, because the abstain-vs-generate comparison contributes negligibly to the average token-level loss.
- **No guarantee of abstain-generate comparisons in sampling**: Standard GRPO samples groups i.i.d., which means a group might contain only generate rollouts (no abstain branch), eliminating the possibility of learning from the comparison.

The decision-content decoupled objective solves both simultaneously through structured counterfactual rollouts (forcing one abstain and G−1 generate branches per group) and per-token credit assignment (routing the decision advantage to the decision prefix and the content advantage to the content tokens, with ∆-gating to suppress content updates when generation is detrimental). This is the mechanism that makes adaptive memory *learnable* in practice, and it represents the paper's primary algorithmic contribution beyond the architectural shift from retrieval to generation.

## 3. Technical Approach

### 3.1 Reader Orientation

This paper proposes a **two-stage training framework** that converts a static collection of agent interaction hints into a **learned policy model** that can produce useful, context-adaptive guidance on demand. The system solves the problem of **when and what to generate** by first cloning expert-like hinting behavior from an offline bank, then refining that behavior through reinforcement learning that explicitly teaches the policy to abstain when generation would be unhelpful—using a novel optimization objective that prevents the long guidance sequence from drowning out the short routing decision during training.

### 3.2 Big-Picture Architecture (Diagram in Words)

The system has four major components connected in a training pipeline, with two models operating at inference time:

1. **Offline Experience Bank (E)** — A dataset of context-guidance pairs `(x, m)` where `x = (q, o)` is a task specification and environment observation, and `m` is a concise procedural hint extracted from agent interaction traces using JEF-Hinter. This is the raw material for Stage 1 training.

2. **Memory Policy Model (πmem)** — A dedicated language or vision-language model (Qwen-2.5-7B-Instruct) with its own parameters, separate from the downstream agent. It maps from task context `x` to either a guidance string `m` (when generating) or the special token `[ABSTAIN]` (when skipping). This model is the output of training and what gets deployed.

3. **Downstream Agent (πagent)** — The LLM that actually performs tasks in the environment (Qwen-2.5-7B-Instruct fine-tuned, or gpt-5.4-mini). It is **frozen during all memory training** and only used to evaluate the quality of generated guidance by measuring whether the augmented context leads to task success.

4. **RL Training Loop (Stage 2 only)** — A structured rollout mechanism that, for each training task, samples one abstain branch and three generate branches from πmem, executes the agent under each branch to obtain binary success rewards, decomposes the reward signal into decision-level and content-level advantages, and updates πmem parameters through GRPO with per-token credit assignment.

**Information flow at inference time:** A new task context `x` arrives → πmem processes it and outputs either `[ABSTAIN]` (agent operates on `x` alone) or `[GENERATE] ⊕ m` (guidance `m` is prepended to the agent's input, forming augmented context `x ⊕ m`) → the agent acts in the environment under the selected context → task succeeds or fails based on the agent's actions.

### 3.3 Roadmap for the Deep Dive

- **First**, the formal definition of πmem's input/output spaces and the two-stage training structure—this establishes the mathematical framing that everything else builds on.
- **Second**, Stage 1: Experience Distillation—the supervised learning objective, what data is used, what the model learns, and why this initialization is essential before RL.
- **Third**, the reward design for Stage 2—what signal drives adaptation distillation, including the task reward, the length regularizer, and how the structured rollout produces distinct rewards for abstain vs. generate branches.

- **Fifth**, implementation and training configuration details—model initialization, token embedding strategy, hyperparameters, and deployment considerations.

### 3.4 Detailed, Sentence-Based Technical Breakdown

This is primarily a **systems and methods paper** whose core idea is that agent memory should be modeled as a generative policy with explicit abstention capability, trained through a two-stage process that separates behavioral cloning from outcome-driven refinement using a decision-content decoupled RL objective.

---

#### Formal Definition of the Memory Policy and Two-Stage Training

The memory policy `πmem` is a neural language model parameterized by `θ`, realized as a dedicated model instance separate from the downstream agent. Its purpose is to consume a task context and produce either memory guidance or an abstention signal. The formal specification evolves across the two training stages.

**Stage 1 output space.** After experience distillation, the policy implements the mapping:

$$\pi^1_{\text{mem}}: (q, o) \mapsto m$$

where `q` is the task specification (a natural language instruction describing what the agent must accomplish), `o ∈ O` is the environment observation (which may include structured textual representations of the current state and, in visual settings, screenshots with grounding descriptions), and `m ∈ M` is a textual guidance string that will be inserted into the downstream agent's context. There is no abstention option in Stage 1—the policy always generates guidance.

**Stage 2 output space.** After extending the vocabulary with decision tokens, the policy implements:

$$\pi^2_{\text{mem}}: (q, o) \mapsto y = d \oplus m$$

where `d ∈ {[GENERATE], [ABSTAIN]}` is a discrete routing decision encoded by a single special token, `m ∈ M ∪ {∅}` is guidance content (empty when `d = [ABSTAIN]`), and `⊕` denotes string concatenation. The key structural change is that the policy now makes an explicit decision about whether to intervene before deciding what to say.

**Agent interaction.** The downstream agent `πagent` operates on context `x = (q, o)`. When `d = [GENERATE]` and `m ≠ ∅`, the guidance is prepended to form the augmented input `x ⊕ m`. When `d = [ABSTAIN]`, the agent operates on the original context `x` with no modification. The agent's parameters are frozen throughout all memory training—only πmem is updated.

**Why separate models:** This separation allows the memory policy to be a smaller, privately fine-tuned model (Qwen-2.5-7B-Instruct) while the agent can be a larger or proprietary frontier model (gpt-5.4-mini). The memory model learns to produce guidance that is useful to the agent, not to take actions itself—it is a meta-cognitive intervention layer rather than a replacement for the agent's decision-making.

---

#### Stage 1: Experience Distillation (Supervised Learning)

**Purpose.** Stage 1 converts an offline collection of task-hint pairs into the initial parameters of πmem. The goal is not to produce a deployable memory system (since the resulting policy always generates and cannot abstain) but to provide a strong initialization for Stage 2 RL—one where the model already knows how to produce plausible, task-relevant guidance. Without this initialization, the RL stage would need to discover both the content of useful guidance and the routing policy simultaneously, which the ablation in Section 3.2 shows fails badly (−5.2 pp on WebArena when Stage 1 initialization is removed).

**Training data.** The offline experience bank `E` consists of pairs `(x, m)` where each `m` is a concise procedural hint generated by JEF-Hinter (Nekoei et al., 2025) from agent interaction traces on training tasks. JEF-Hinter analyzes the agent's successful trajectory and identifies the decisive steps—the actions that were critical for task completion—and distills them into a compact textual summary. Figure 8 shows examples: for a WebArena CMS task, the hint describes navigating to a specific report, setting date filters, and extracting the top product; for an ALFWorld cleaning task, the hint provides a numbered procedure with a common-pitfall warning. The bank contains only hints derived from training-split tasks to prevent test-set leakage.

Each context `x = (q, o)` pairs the original task instruction with the environment observation at the start of the task. Crucially, the hint `m` is not a complete trajectory transcript but a compressed strategic summary—it tells the agent *what* approach to take and *what pitfalls to avoid* without specifying every low-level action. This compression is what makes the hints reusable across tasks with similar structure but different specific parameters.

**Training objective.** Stage 1 uses standard autoregressive supervised learning—the model is trained to predict each token of the target hint `m` given the context `x` and all preceding tokens of `m`:

$$J^{(1)}_{\text{mem}}(\theta) = \mathbb{E}_{(x, m) \sim \mathcal{E}}\left[\sum_{t=1}^{|m|} \log \pi^1_{\text{mem}}(m_t \mid x, m_{<t}; \theta)\right]$$

where `m_t` is the `t`-th token of the target memory `m`, `m_{<t}` denotes all tokens before position `t`, and the expectation is taken over the experience bank `E` (pairs of context `x` and target hint `m`).

**What it computes:** For each training example, the model processes the context `x` (task instruction + observation) and receives the ground-truth hint `m` token by token. At each position `t`, the model's predicted probability for the correct next token `m_t` is logged. These log-probabilities are summed across all token positions and averaged across the training batch. The result is maximized when the model assigns high probability to the exact wording of the reference hint at every position.

**Why this form:** Autoregressive maximum-likelihood training is the standard objective for sequence generation because it directly optimizes the model to reproduce the target distribution one token at a time, which is exactly how the model will be used at inference time. Alternative objectives like masked language modeling or denoising would create a mismatch between training and inference behavior. The form is specifically teacher-forcing: at training time, the model always sees the ground-truth previous tokens `m_{<t}` rather than its own predictions, which stabilizes learning but creates a train-test distribution gap (the model sees its own predictions at inference time, not ground-truth) that Stage 2 RL partially addresses.

**What Stage 1 produces.** After training, `π^1_mem` can generate plausible hints for new task contexts. However, it has two critical limitations: (1) it always generates—there is no mechanism to decide that a task doesn't need guidance—and (2) its outputs are shaped entirely by imitation of the reference hints, which may be suboptimal for the specific downstream agent or may not align with what actually improves task success. These are the gaps that Stage 2 addresses.

**Training configuration.** The paper specifies training with AdamW optimizer, learning rate `$2 \times 10^{-5}$`, cosine schedule with 5% warmup, batch size 32, weight decay 0.01, gradient clipping at 1.0, maximum sequence length 2,048 tokens, and 3 epochs. Implementation uses PyTorch FSDP across `$8 \times$` NVIDIA H100-80GB GPUs. These hyperparameters are standard for Qwen-2.5-7B fine-tuning and were not the subject of extensive ablation.

#### Reward Design for Stage 2: Adaptation Distillation

**Purpose.** Stage 2 refines the Stage 1 policy using reinforcement learning, where the reward signal comes from whether the downstream agent succeeds at the task when using the memory policy's output. This aligns memory generation with actual task utility rather than imitation quality—a hint that looks different from the reference but leads to task success is rewarded; a hint that perfectly matches the reference but causes the agent to fail is penalized.

**The base RL algorithm: GRPO.** The paper builds on Group Relative Policy Optimization (GRPO; Shao et al., 2024), which removes the need for a separate value model by estimating advantages from groups of samples. For each input `x`, GRPO samples a group of `G` outputs `{y_1, ..., y_G}` from the current policy, executes the agent under each to obtain rewards `r = (r_1, ..., r_G)`, and computes group-relative advantages:

$$\hat{A}_j = \frac{r_j - \text{mean}(r)}{\text{std}(r) + \epsilon_{\text{std}}}$$

where `r_j` is the reward for the `j`-th output in the group, `mean(r)` and `std(r)` are the sample mean and standard deviation of all rewards in the group, and `$\epsilon_{\text{std}}$` (set to `$10^{-6}$`) prevents division by zero. This normalizes advantages within each group so that the policy learns to prefer outputs that are better relative to what the current policy can produce, not against an absolute reward scale.

**The task reward.** The primary reward signal is binary task success:

$$\text{TaskReward}(\pi_{\text{agent}}(\cdot \mid \cdot)) \in \{0, 1\}$$

This is 1 if the agent's interaction trajectory under the given context (memory-augmented or original) achieves the task's success criterion, and 0 otherwise. The success criterion is benchmark-specific: for WebArena and WorkArena, the official BrowserGym verifiers; for LifelongAgentBench, SQL execution results (DB) or OS state checks (OS); for ALFWorld, the environment's terminal condition checker.

**The length regularizer.** To prevent the policy from generating unnecessarily verbose or overly specific guidance, a length penalty is applied to generate branches:

$$R_m(m) = -\lambda_{\text{len}} \frac{|m|}{L_{\text{max}}}$$

where `|m|` is the number of tokens in the generated guidance (after stripping chat-template scaffolding and instruction echoes), `L_max = 256` is the maximum generation budget, and `$\lambda_{\text{len}} = 0.1$` controls the penalty magnitude.

**What it computes:** For a guidance string of length `|m|`, the penalty is `$-0.1 \times |m| / 256$`. At maximum length (256 tokens), the penalty saturates at `$-0.1$`. At typical lengths (~138 tokens average for Mem-π, from Figure 5), the penalty is approximately `$-0.054$`. This is an order of magnitude smaller than the binary task reward (0 vs. 1), ensuring that downstream success dominates the optimization signal.

**Why this form:** The penalty is proportional to length (not a fixed cost) to encourage conciseness, and it is normalized by `L_max` so that the maximum penalty is bounded by `$\lambda_{\text{len}}$`. This prevents the length penalty from ever outweighing the task reward: even the longest possible guidance (256 tokens) incurs only a 0.1 penalty, which cannot flip a success signal from 1.0 to below 0.9 (failure being 0.0). The authors cite prior work on length-aware reward shaping (Aggarwal & Welleck, 2025; Yu et al., 2025b; Liu et al., 2025c) as motivation for this design.

**Combined reward for generate branches.** For a generate branch `y_j = [GENERATE] ⊕ m_j` (where `j ≥ 1`), the total reward is:

$$R(x, y_j) = \text{TaskReward}(\pi_{\text{agent}}(\cdot \mid x \oplus m_j)) + R_m(m_j)$$

**Reward for abstain branches.** For the abstain branch `y_0 = [ABSTAIN] ⊕ ∅`, there is no guidance to penalize, so:

$$R(x, y_0) = \text{TaskReward}(\pi_{\text{agent}}(\cdot \mid x))$$

This is simply whether the base agent succeeds on the original context `x`.

**Why separate rewards matter.** The distinction between these two reward calculations is what enables the policy to learn when to generate vs. abstain. If the base agent already succeeds (TaskReward = 1 for the abstain branch), then any generate branch that also succeeds must overcome the length penalty to match the abstain reward of 1.0—encouraging the policy to abstain on easy tasks where generation provides no marginal benefit. If the base agent fails (TaskReward = 0 for abstain), then any generate branch that succeeds provides a reward of `1.0 + R_m(m) ≈ 0.95+`, which strongly dominates the abstain reward of 0.

#### Decision-Content Decoupled Policy Optimization

This is the paper's core algorithmic contribution. It addresses a specific optimization pathology that arises when applying standard GRPO to the structured output `y = d ⊕ m`, where `d` is a single-token decision and `m` is a potentially long sequence of content tokens.

**The problem with vanilla GRPO.** Under standard GRPO (Equation 2), the policy is updated by maximizing:

$$J_{\text{GRPO}}(\theta) = \mathbb{E}_x \left[\frac{1}{G} \sum_{j=1}^{G} \frac{1}{|y_j|} \sum_{t=1}^{|y_j|} \left[\min\left(\rho^j_t \hat{A}_j, \text{clip}(\rho^j_t, 1-\epsilon_{\text{clip}}, 1+\epsilon_{\text{clip}}) \hat{A}_j\right) - \beta D^{(t)}_{\text{KL}}\right]\right]$$

where `$\rho^j_t$` is the importance ratio between current and old policy, `$\hat{A}_j$` is the scalar group-relative advantage from Equation 2, and the average is taken over all tokens `t` and all group members `j`.

The pathology arises because the single scalar `$\hat{A}_j$` is broadcast identically to every token position. For a generate branch `y_j` where `|y_j| ≈ 1 + |m_j|` (one decision token plus a long guidance), the content tokens outnumber the decision token by roughly two orders of magnitude (e.g., 1 decision token vs. ~138 content tokens on average). The gradient contribution from the decision token is therefore diluted by a factor of `$1/|y_j|$`, meaning the policy receives very weak signal about whether the *decision to generate* was correct—the signal is dominated by whether the *content* was good, which is a separate learning problem entirely.

Additionally, standard i.i.d. sampling of groups offers no guarantee that an abstain branch will appear in any given group. If all `G` samples are generate branches, there is no comparison against abstention, and the policy cannot learn the relative value of generating vs. not generating.

**The solution: structured counterfactual rollouts.** Rather than sampling `G` outputs i.i.d., Mem-π constructs each rollout group deterministically:

$$y_0 = \texttt{[ABSTAIN]} \oplus \emptyset$$

$$y_j = \texttt{[GENERATE]} \oplus m_j, \quad j = 1, \ldots, G-1$$

where `G = 4` (one abstain branch and three generate branches, each producing a distinct guidance string `m_j` sampled at temperature 1.0 with `top_p = 0.95`). This construction guarantees that every group contains both decisions, making the relative value of generating vs. abstaining directly observable through reward comparison.

**Advantage decomposition.** Given the structured group, the paper decomposes the learning signal into two components that capture different aspects of policy quality.

**Decision-level advantage.** First, compute the average value of each decision:

$$V_{\text{abs}} = R(x, y_0)$$

$$V_{\text{gen}} = \frac{1}{G-1} \sum_{j=1}^{G-1} R(x, y_j)$$

where `$V_{\text{abs}}$` is the reward of the single abstain branch and `$V_{\text{gen}}$` is the mean reward across the `G-1 = 3` generate branches. Then define the cross-branch differential:

$$\Delta = V_{\text{abs}} - V_{\text{gen}}$$

**What Δ represents:** `Δ` captures the relative benefit of abstaining over generating for the current task context `x`. When `Δ > 0`, abstention outperforms generation on average—the base agent succeeds at a higher rate or the generated guidance is actively harmful. When `Δ < 0`, generation provides net benefit over abstention. When `Δ ≈ 0`, the two decisions are roughly equivalent and the policy has no strong signal either way.

**Decision advantage assignment.** The decision advantage `$A^j_d$` uses `Δ` as a signed signal routed to the decision-token position in each branch:

$$A^j_d = \begin{cases} +\Delta, & j = 0 \text{ (abstain)} \\ -\Delta, & j \geq 1 \text{ (generate)} \end{cases}$$

**Why this assignment works:** If abstention is better (`Δ > 0`), the abstain branch receives a positive advantage `$+\Delta$` (reinforcing the decision to abstain) while generate branches receive a negative advantage `$-\Delta$` (discouraging the decision to generate). If generation is better (`Δ < 0`), the signs flip: abstention is penalized and generation is reinforced. The magnitude is proportional to how much better one decision is than the other, not to the absolute reward level—this is the same group-relative principle as GRPO but applied to the decision comparison rather than within-branch ranking.

**Content advantage assignment.** The content advantage `$A^j_c$` ranks the quality of generated guidance within the generate branch:

$$A^j_c = \begin{cases} 0, & j = 0 \\ \displaystyle \frac{R(x, y_j) - V_{\text{gen}}}{\text{std}(\mathbf{r}_{\text{gen}}) + \epsilon_{\text{std}}}, & j \geq 1 \end{cases}$$

where `$\mathbf{r}_{\text{gen}} = \{R(x, y_j)\}_{j=1}^{G-1}$` is the set of rewards for the three generate branches, and `$V_{\text{gen}}$` and `$\text{std}(\mathbf{r}_{\text{gen}})$` are their mean and standard deviation respectively.

**What it computes:** For each generate branch `j ≥ 1`, the content advantage is the standardized deviation of that branch's reward from the mean generate-branch reward. A guidance string that leads to task success when the average generate branch fails receives a positive content advantage; one that leads to failure when the average succeeds receives a negative content advantage. The abstain branch receives zero content advantage because it has no content to optimize.

**Why this form:** This reduces to the standard GRPO advantage formulation but computed only within the generate subset. The group-relative normalization ensures that the policy learns to prefer better guidance among the generate branches, while the separation from the decision advantage ensures that the content tokens don't receive signal about whether generating at all was a good idea—they only learn relative content quality.

**Per-token credit assignment (the gating mechanism).** The decomposed advantages must be routed to the correct token positions. Let `T_d` denote the length of the decision prefix (1 token in practice: either `[ABSTAIN]` or `[GENERATE]`). The per-token advantage `$A^j_t$` for token position `t` in branch `j` is:

$$A^j_t = \begin{cases} A^j_d, & t \leq T_d \\ \mathbf{1}[\Delta < 0] \cdot A^j_c, & t > T_d \end{cases}$$

**What this means operationally:**
- **Decision tokens (t ≤ T_d, i.e., the first token):** Receive only the decision-level signal `$A^j_d$`. They learn whether to generate or abstain based on the cross-branch comparison, entirely independently of what content was produced.
- **Content tokens (t > T_d, i.e., the guidance sequence):** Receive the content-level signal `$A^j_c$`, but only when `Δ < 0`—that is, only when generation outperforms abstention. When `Δ ≥ 0` (abstention is better), the content advantage is multiplied by zero, completely suppressing content-level gradient updates.

**The critical role of Δ-gating.** The indicator `$\mathbf{1}[\Delta < 0]$` is the "Δ-gating" mechanism that prevents a specific failure mode. Consider a task where the base agent succeeds (so abstention reward = 1) and all generate branches fail (generate rewards ≈ 0, so `V_gen ≈ 0`). Then `Δ = 1 - 0 = 1 > 0`: abstention is strongly preferred. Without gating, the content tokens on generate branches would still receive negative content advantages (`$A^j_c \approx -1$`), causing the policy to update its content-generation parameters to produce *different* guidance next time. But the correct behavior is not to generate better guidance—it's to recognize that generation is harmful on this task and abstain. The Δ-gate suppresses content updates entirely when `Δ ≥ 0`, ensuring that the policy doesn't waste capacity learning to improve guidance quality on tasks where guidance is counterproductive. Instead, only the decision token learns (from `$A^j_d = -\Delta$`) that generating was a mistake.

**Putting it together: the Stage 2 objective.** Substituting the per-token advantage `$A^j_t$` into the GRPO objective yields:

$$J^{(2)}_{\text{mem}}(\theta) = \mathbb{E}_x \left[\frac{1}{G} \sum_{j=0}^{G-1} \frac{1}{|y_j|} \sum_{t=1}^{|y_j|} \left[\min\left(\rho^j_t A^j_t, \text{clip}(\rho^j_t, 1-\epsilon_{\text{clip}}, 1+\epsilon_{\text{clip}}) A^j_t\right) - \beta D^{(t)}_{\text{KL}}\right]\right]$$

The only change from standard GRPO (Equation 2) is replacing the scalar group-relative advantage `$\hat{A}_j$` with the per-token advantage `$A^j_t$`. This preserves the GRPO framework (clipped importance ratios, KL penalty) while routing different learning signals to different parts of the output.

**Why this decomposition is necessary, not just helpful.** The paper's ablation (Section 3.2, RQ2) shows that removing structured rollouts costs 4.8 pp on WebArena and removing Δ-gating costs 1.8 pp. Structured rollouts are necessary because without them, i.i.d. sampling may produce groups with no abstain branch, eliminating the cross-branch comparison entirely. Δ-gating is necessary because without it, content updates on tasks where generation is harmful dilute the decision signal and waste optimization steps on improving guidance for situations where guidance should not be produced at all. The two mechanisms work together: structured rollouts create the comparison, and Δ-gating ensures the comparison drives the right kind of learning at each token position.

**KL regularization.** The term `$- \beta D^{(t)}_{\text{KL}}$` penalizes per-token divergence from a reference policy `$\pi_{\text{ref}}$`, which is set to the Stage 1 policy `$\pi^1_{\text{mem}}$`. This prevents the RL stage from drifting too far from the behavior learned during experience distillation, which would risk catastrophic forgetting of the ability to produce coherent guidance. The KL coefficient is `$\beta = 0.01$`, a relatively small value that allows meaningful policy improvement while maintaining proximity to the Stage 1 initialization.

---

#### Training Configuration and Implementation

**Model initialization.** The memory policy πmem is initialized from Qwen-2.5-7B-Instruct for the text-only setting, and Qwen-2.5-VL-7B-Instruct for the visual-input ablation. The downstream agent is a separately fine-tuned Qwen-2.5-7B-Instruct (frozen during memory training) for the RL stage, with gpt-5.4-mini used for test-time evaluation with the unseen agent.

**Decision token embedding.** Two special tokens, `[GENERATE]` and `[ABSTAIN]`, are added to the model vocabulary. Their embeddings are initialized symmetrically: each token's embedding is set to the mean embedding of semantically related existing tokens (`skip`/`bypass` for `[ABSTAIN]`; `recall`/`retrieve` for `[GENERATE]`), then averaged together to produce a shared initial embedding. This symmetric initialization ensures both decision tokens start with approximately equal logit values, producing roughly 50% abstention probability at the start of Stage 2. The paper shows this is critical for cold-start exploration: without symmetric initialization, the `[ABSTAIN]` token starts with near-zero probability and recovers only slowly, never reaching the converged abstention rate of the symmetric variant (Figure 7b).

**Stage 2 hyperparameters.** The RL training uses AdamW with learning rate `$1 \times 10^{-6}$`, `$\beta_1 = 0.9$`, `$\beta_2 = 0.999$`, weight decay 0, batch size 8 tasks per step, and 200 optimization steps. The clip ratio is `$\epsilon_{\text{clip}} = 0.2$`, the KL coefficient is `$\beta = 0.01$`, and the advantage normalization constant is `$\epsilon_{\text{std}} = 10^{-6}$`. The structured rollout uses `$G = 4$` branches (1 abstain + 3 generate), with each generate branch producing up to `$L_{\text{max}} = 256$` tokens at sampling temperature 1.0 and `$\text{top_p} = 0.95$`.

**Memory usage and generation budget.** The length regularizer uses `$\lambda_{\text{len}} = 0.1$` with generation budget `$L_{\text{max}} = 256$`. Generation is capped by vLLM's `max_new_tokens`, so `$|m| \in [1, L_{\text{max}}]$` for every generate branch. Prompt-leakage tokens (chat-template scaffolding and instruction echoes) are stripped before counting `|m|`, so the penalty reflects only substantive memory content.

**Infrastructure.** Stage 1 uses PyTorch FSDP across `$8 \times$` NVIDIA H100-80GB GPUs. Stage 2 uses DeepSpeed ZeRO-2 with vLLM colocated for inference on the same GPU configuration; the policy model and the rollout vLLM instance share GPU memory via vLLM's sleep mode. The implementation is built on PyTorch, Hugging Face Transformers, TRL, and vLLM.

**Design choice: length penalty magnitude.** The paper sets `$\lambda_{\text{len}} = 0.1$` so that the maximum length penalty (0.1) is an order of magnitude smaller than the binary task reward (1.0). This ensures that downstream task success dominates the optimization—the policy should never prefer abstention over successful generation just to save a few tokens. The penalty only tilts the decision when generate and abstain branches have comparable task success rates, encouraging the policy to prefer the more efficient option (abstention) when quality is equivalent.

## 4. Key Insights and Innovations

### Innovation 1: Memory as a Generative Policy Rather Than Storage and Retrieval

The paper's most fundamental intellectual move is not incremental—it reframes **what memory means** in the context of LLM agents. The dominant paradigm across workflow-based (RAG, Mem0, JEF-Hinter) and learning-based systems (Memory-R1, MemRL) treats memory as an **external storage problem**: experiences are collected in a bank, indexed, and retrieved by similarity. Even sophisticated RL-trained controllers in prior work optimize *when and how* to access stored entries, but the entries themselves remain static snapshots written at experience time. This creates an inherent ceiling: no matter how good the retrieval policy becomes, the retrieved content is bounded by what was originally stored and cannot adapt to the query's specific parameters.

Mem-π shifts the locus of memory from an external database to a **parametric policy model** `πmem` with its own weights, separate from the downstream agent. The model does not look up stored hints—it *synthesizes* them on demand from knowledge internalized through training. This is a fundamental conceptual shift, not merely a different training recipe for the same underlying architecture. The difference is analogous to the transition from retrieval-based QA (where answers are looked up in a corpus) to generative QA (where answers are produced from parametric knowledge): latency, flexibility, and failure modes all change qualitatively.

**Why this matters beyond retrieval's limitations.** The paper provides concrete evidence for three advantages of the generative framing that retrieval structurally cannot match:

- **Query adaptation (Figure 6, Case 1).** When a retrieval system faces a query that differs from the most similar stored entry in a specific numeric or identifier detail (e.g., "top 3" vs. the source's "top 2"), it copies the source verbatim and injects the wrong number into the agent's context. A generative policy conditions on the current query and rewrites the count, format, or identifier to match. This is not a matter of retrieval quality—even perfect retrieval would return the "top 2" entry because it *is* the most similar. The error is structural to the retrieval paradigm.
- **Signal fusion.** A generative policy can combine patterns from many training tasks into a single context-specific hint. Retrieval must return discrete entries, potentially splitting related guidance across fragments or omitting relevant details that fall below the top-k cutoff. The paper does not provide a quantitative decomposition of this effect, but it logically follows from the parametric nature of the policy: the model's hidden state at inference time reflects a distributed combination of all training experiences, not a discrete selection.
- **Fixed memory footprint.** A retrieval bank grows linearly with accumulated experience, requiring merging, deduplication, and staleness management. A parametric policy has a fixed size (determined by model architecture), which is a practical advantage for long-term deployment. The paper notes this in Section 1 but does not empirically evaluate scaling—it is presented as a structural property of the generative paradigm rather than a demonstrated gain.

**Prior work comparison.** Early generative memory systems (ParaMem, SEAM, MemGen) have begun exploring this direction, but the paper argues they either treat generation as retrieval imitation (optimizing the generator to reproduce what a retriever would have returned) or as an always-on auxiliary step. Mem-π's contribution is not the idea of generating memory—it is modeling memory as a *policy* with an explicit output decision (generate vs. abstain), trained end-to-end from downstream utility rather than retrieval fidelity.

**Significance.** This is a **paradigm-level reframing**, not a small algorithmic improvement. It establishes generative memory as a distinct category from retrieval-based memory, with its own design considerations (when to intervene, how to balance content quality against intervention cost) that prior work had not articulated. The paper is careful not to claim generative memory is universally superior—the case studies show regions where retrieval wins (Figure 6, regions 010 and 100)—but it establishes generation as a fundamentally different mechanism with complementary strengths.

---

### Innovation 2: Adaptive Abstention as a First-Class Memory Operation

The second conceptual contribution is recognizing that **when not to produce memory** is as important a decision as what memory to produce. This is a non-obvious design choice because the default in both retrieval and prior generative memory systems is to always return something: retrieval always returns top-k entries (even if relevance is low), and prior generative systems treat memory production as unconditional. The paper argues this creates a reliability problem: injecting any memory—even plausible memory—into the agent's context can be actively harmful if it encodes assumptions that don't transfer to the current task.

**The failure mode.** The paper provides a concrete diagnostic through case analysis (Figure 6, Case 2): a retrieved hint narrows the agent's search to a specific product family ("game card case") based on the most similar stored experience, but the query asks for "the best storage option" broadly. The narrowed hint misleads the agent into a suboptimal search path. Mem-π emits `[ABSTAIN]`, restoring the base agent's open-ended search, which finds a better solution. This is not a failure of retrieval quality—the retrieved hint is genuinely the most relevant in the bank—but a failure of the always-return-something assumption. The hint would have been useful for a query specifically about game card cases; for a query about the *best* storage option, it introduces harmful bias.

**Quantifying the value of abstention.** The paper shows this effect is systematic, not anecdotal. On the easiest WebArena tasks (base agent success rate 80–100%), Mem-π abstains ~71% of the time (Figure 4), and the success-rate improvement over the base agent is only +1.3 pp—abstention correctly recognizes that memory is unnecessary. On the hardest tasks (base agent success rate 0–20%), Mem-π abstains only ~13% of the time and provides +9.7 pp improvement. This correlation between task difficulty and abstention rate shows the policy has learned **calibrated abstention**: it avoids unnecessary intervention on tasks the agent already handles well while generating on tasks where guidance provides genuine value.

The token-efficiency analysis (Figure 5, RQ6) further demonstrates the value: Mem-π uses 138 memory tokens per task on average, 31% fewer than the always-on Stage 1 variant (200 tokens) and 38% fewer than Memory-R1 (225 tokens), while simultaneously achieving the highest success rate (43.1%). This establishes a performance-efficiency Pareto improvement: Mem-π is both better and cheaper than always-on generation.

**Why this is novel, not obvious.** It is tempting to view abstention as a natural consequence of RL training—the policy simply learns not to generate when generation doesn't improve reward. But the paper shows this fails without specific architectural support. The ablation removing structured rollouts (−4.8 pp on WebArena) shows that standard i.i.d. GRPO sampling rarely produces groups with both abstain and generate branches, so the policy never observes the comparison needed to learn when to abstain. The ablation removing Δ-gating (−1.8 pp) shows that even when the comparison exists, naive fusion of decision and content signals allows content gradients on harmful generate branches to dilute the abstention signal. Adaptive abstention is not an emergent property of RL—it requires specific optimization design to be learnable.

**Prior work comparison.** No prior memory system—retrieval-based or generative—treats abstention as a first-class operation. Retrieval systems return top-k unconditionally. Prior generative systems are always-on. Learning-based controllers (Memory-R1, MemRL) learn *what to retrieve* but not *whether to retrieve*. The paper introduces abstention as a core memory primitive, with its own optimization signal separate from content quality, making it a fundamental architectural extension rather than a training trick.

**Significance.** This is a **diagnostic reframing** with practical consequences. It establishes that the reliability challenge for agent memory is not just producing good guidance (Stage 1 does that reasonably well) but knowing when guidance would be harmful. The implication for future work is clear: memory systems should be evaluated not just on whether their guidance is accurate but on whether they correctly recognize when no guidance is needed. This creates a new evaluation axis that prior benchmarks do not capture.

### Innovation 3: Decision-Content Decomposition as a Solution to the Structural Credit Assignment Problem in Structured Policy Optimization

The paper's primary algorithmic contribution is the **decision-content decoupled RL objective** (Section 2.2), which separates the optimization of *when to generate* from *what to generate* through structured counterfactual rollouts and per-token credit assignment with Δ-gating. This is not an incremental improvement to GRPO—it addresses a **structural credit assignment pathology** that arises whenever a policy's output contains a short binary decision prefix followed by a long content sequence, under a flat per-token policy gradient.

**The pathology.** Under standard GRPO (or PPO), the same scalar advantage signal is broadcast to every token in the output sequence. When the output is `[GENERATE] ⊕ m` with `|m| ≈ 138` (Mem-π's average guidance length), the single decision token receives only `1/139` of the total gradient contribution, while content tokens collectively receive `138/139`. This means the policy gradient is dominated by whether the *content* was good, and receives vanishing signal about whether *generating at all* was the correct decision. The problem is structural: it follows from the length asymmetry between decision and content, not from any particular dataset or hyperparameter setting.

**Why this matters beyond Mem-π.** This pathology generalizes to any setting where an LLM's output contains a routing or classification decision followed by a long generation: tool-use decisions (should I call a calculator or answer directly?), retrieval decisions (should I search or reason from memory?), modality selection in multimodal systems. Standard per-token policy gradients will consistently under-optimize the routing decision relative to the content generation. The paper's decomposition approach—creating separate advantage signals for the decision prefix and the content body, with a gating mechanism that suppresses content updates when the decision is incorrect—is a **general design pattern** for structured policy optimization, not a domain-specific trick.

**The two mechanisms and their roles (reference to Section 3.4).** The decomposition has two components, each addressing a distinct sub-problem:

- **Structured counterfactual rollouts** guarantee that every training batch contains both an abstain and multiple generate branches. This solves the *exploration* problem: without this structure, i.i.d. sampling may produce groups with no abstain branch, making the cross-branch comparison unobservable. The ablation showing a 4.8 pp drop on WebArena when this is removed confirms it is the most critical component of the objective design.

- **Δ-gating** routes the decision advantage to the decision token and the content advantage to content tokens, with the gate `1[Δ < 0]` suppressing content updates when generation is worse than abstention. This solves the *credit assignment* problem: when generation is harmful, the policy should learn to stop generating on that task, not learn to generate different content. The 1.8 pp drop from removing Δ-gating shows this matters even when structured rollouts are present.

**Prior work comparison.** GRPO and PPO variants with token-level credit assignment exist (e.g., per-token advantage estimation in RLHF), but these typically decompose advantages based on *temporal* credit assignment (which tokens caused future reward), not based on *structural* credit assignment (separating a routing decision from its content). The paper's decomposition is orthogonal—it does not attempt to assign token-level causal responsibility within the guidance sequence, but rather creates a top-level separation between the decision and content optimization problems.

**Significance.** This is a **methodological contribution** with applicability beyond agent memory. The decision-content decomposition represents a principled approach to a class of structured generation problems that are becoming increasingly common as LLMs are deployed as routing-and-generation components in larger systems. The paper does not claim this as a theoretical advance (there is no convergence proof or regret bound), but it provides strong empirical evidence that the decomposition is necessary for learnability—the structured optimization problem is not solvable via standard methods.

---

### Innovation 4: Two-Stage Distillation as a Practical Recipe for Generative Memory from Offline Data

The paper's training pipeline—supervised experience distillation followed by outcome-driven RL refinement—is not individually novel (both stages are well-established techniques), but their **combination as a recipe for converting offline memory banks into generative policies** is distinctive and practically significant.

**The Stage 1 insight.** Experience distillation (Stage 1) is conceptually simple: train the memory policy to imitate reference hints via next-token prediction. What makes this distinctive is *what it enables* rather than *how it works*. The paper shows (Table 1, "Mem-π (Stage 1)" row) that this supervised policy alone achieves results comparable to or better than RL-trained retrieval controllers: 35.0% on WebArena vs. 33.2% for Memory-R1 and 34.0% for MemRL. This means that simply compressing an offline experience bank into model parameters via supervised learning is competitive with sophisticated RL-based retrieval optimization—using no RL at all. This is a strong empirical validation of the parametric memory hypothesis: the model parameters are an effective storage medium for reusable agent experience, and imitation is a surprisingly good teacher for this task.

**Why Stage 1 alone is insufficient.** Despite its strong performance, the Stage 1 policy has two structural weaknesses that Stage 2 addresses. First, it always generates—there is no mechanism to recognize when guidance is unnecessary or harmful. The token-efficiency analysis (Figure 5) quantifies this cost: Stage 1 uses 200 tokens per task on average vs. Mem-π's 138, while achieving lower success rate (35.0% vs. 43.1%). Second, Stage 1's output is shaped by imitation of reference hints, which may not be optimal for the specific downstream agent. Stage 2 realigns the policy from "match the reference" to "help the agent succeed," which is a different objective.

**The Stage 2 insight.** The RL stage uses the frozen downstream agent as a reward function: good guidance is whatever causes the agent to succeed at the task. This elegantly solves the distribution-mismatch problem that would arise if the policy were evaluated by similarity to reference hints—a generated hint that looks different from the reference but works better for the agent is rewarded, not penalized. The 8.1 pp gain from Stage 1 to Mem-π on WebArena (35.0% → 43.1%) comes from this realignment plus the addition of adaptive abstention.

**Why this recipe matters practically.** The two-stage design has a crucial property: it works with *offline* experience data. The experience bank can be constructed from any source—human demonstrations, agent interaction traces, or curated documentation—using tools like JEF-Hinter to extract compact hints. Stage 1 can then be run as a standard supervised fine-tuning job with no environment interaction. Stage 2 requires online environment interaction to obtain task rewards, but only for a relatively small number of RL steps (200 optimization steps × 8 tasks per step = 1,600 task interactions per benchmark). This makes the approach practical for domains where environment interaction is expensive or where the experience bank already exists from prior agent runs.

**Prior work comparison.** SEAM (Li et al., 2026) also uses GRPO to train a generative memory component, but treats it as a single-stage RL problem from a frozen base model—no supervised initialization. The paper's ablation ("w/o Stage 1 init," −5.2 pp on WebArena) shows this approach underperforms dramatically, confirming that the experience distillation initialization is essential for stable RL. ParaMem (Yao et al., 2026) encodes reflection patterns into model parameters but does not use downstream task outcomes for refinement.

**Significance.** This is a **practical engineering contribution** rather than a fundamental algorithmic advance. The paper provides a complete, replicable training recipe that anyone with an offline agent experience bank can follow: (1) extract hints from successful trajectories using a tool like JEF-Hinter, (2) supervised-fine-tune a model to produce those hints from task contexts, (3) add decision tokens and run decision-content decoupled RL with the frozen agent as reward function. The strong Stage 1 results suggest that even without RL, parametric memory via supervised distillation is a viable alternative to retrieval-based memory—a finding with immediate practical implications for teams that cannot afford online RL.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The paper evaluates on four agentic benchmarks: **WebArena** (812 multi-step browser tasks across five domains—Shopping, CMS, GitLab, Reddit, Maps—with a 647/165 train/test split following WebAgent-R1), **WorkArena** (33 enterprise task templates on the ServiceNow platform across four categories, with 20 seeds per template for training and 10 disjoint seeds for evaluation), **LifelongAgentBench / LAB** (terminal tool-use tasks, using the Database subset with 22 SQL skills and the OS subset with 29 Bash skills, each with 500 tasks and a 7:3 split following MemRL), and **ALFWorld** (text-based embodied household tasks across six manipulation types, using the official split of 3,553 training and 134 unseen test tasks). The diversity of these benchmarks—spanning web navigation, enterprise software, terminal command execution, and physical manipulation—is deliberate: it tests whether generative memory provides gains across fundamentally different interaction modalities, observation types (visual vs. text-only), and task structures.

- **Base model(s).** The memory policy `πmem` is initialized from **Qwen-2.5-7B-Instruct** for the text-only setting, matching the backbone used by the strongest learning-based baseline (Memory-R1) for fair comparison. The visual-input ablation uses **Qwen-2.5-VL-7B-Instruct**. The downstream agent during RL training is a separately fine-tuned **Qwen-2.5-7B-Instruct** kept frozen; for test-time evaluation, the paper also assesses transfer to the proprietary **gpt-5.4-mini** without retraining the memory model. This choice of base models serves two purposes: (1) using an open 7B-scale model for the memory policy demonstrates that generative memory does not require frontier-scale models, and (2) the frozen-agent design with cross-agent transfer evaluation tests whether learned memory generalizes beyond the training-time agent.

- **Metrics.** The primary metric across all benchmarks is **task success rate (SR %)**, a binary per-task signal indicating whether the agent's trajectory achieved the benchmark's success criterion. For WebArena and WorkArena, the official BrowserGym verifiers determine success; for LAB, correctness is verified by SQL execution output (DB) or OS state checks (OS); for ALFWorld, the environment's terminal condition checker provides the signal. All reported numbers are **means over three independent seeds**. The paper also uses **average memory tokens per task** (Figure 5) as an efficiency metric, counting only substantive memory content after stripping chat-template scaffolding and instruction echoes.

- **Baselines.** The paper compares against five baselines spanning two memory paradigms. **Workflow-based**: (1) **RAG** (Lewis et al., 2020)—retrieves the top-k most similar hints from the JEF-Hinter memory bank via BM25, with k=1, effectively matching the approach used in JEF-Hinter; (2) **Mem0** (Chhikara et al., 2025)—combines RAG with rule-based memory management. **Learning-based**: (3) **Memory-R1** (Yan et al., 2025)—trains a memory manager with outcome-driven RL for structured memory operations; (4) **MemRL** (Zhang et al., 2026b)—learns Q-values over episodic memory for utility-aware retrieval. The **Base Agent** (no memory) serves as the zero-memory baseline. All training-based methods use only training-split tasks and their corresponding JEF-Hinter hints, with the same split isolation applied to RAG and Mem0 banks, ensuring no test-set leakage.

- **Generation budget / compute accounting.** The paper measures computation in terms of **generated memory tokens** (for efficiency analysis) and **number of RL optimization steps** (for training cost). Memory generation is capped at `L_max = 256` tokens per generate branch. For the RL stage, training uses 200 optimization steps with batch size 8 tasks per step, totaling approximately 1,600 task interactions per benchmark (each interaction involves executing the agent under one memory branch to obtain a reward). The paper does not report total FLOPs or wall-clock time for training, making cross-method efficiency comparisons (beyond memory token counts) difficult.

- **Cross-validation / statistical protocol.** The paper uses three independent random seeds and reports means, but does not report standard deviations, confidence intervals, or statistical significance tests. For the task-difficulty analysis (Figure 4), tasks are grouped into five equal-width bins based on the base agent's success rate—this is a post-hoc analysis on the test set, not cross-validated difficulty estimation. The absence of variance reporting is a notable gap: with test sets as small as 134 tasks (ALFWorld unseen), some of the reported gains may fall within seed variance, but the paper provides no means to assess this.

### Main Quantitative Results

#### Overall Performance Across Benchmarks (Table 1)

The headline result is that **Mem-π achieves state-of-the-art performance on all four benchmarks**, with an average success rate of 55.4% across benchmarks compared to 45.3% for the base agent—a **22.3% relative improvement**. The gains are not uniform across benchmarks, which is informative about where generative memory adds the most value.

**WebArena (overall SR):** Mem-π achieves 43.1%, substantially outperforming all retrieval-based and RL-optimized baselines. The nearest competitor is MemRL at 34.0%, followed by Memory-R1 at 33.2%, Mem0 at 31.9%, RAG at 31.4%, and the base agent at 27.1%. The gap between Mem-π and the base agent is **+16.0 pp (59% relative improvement)**. This is the benchmark where generative memory shows the largest absolute and relative gains, consistent with WebArena's diverse domain structure and long-horizon tasks that benefit most from adaptive, context-specific guidance.

**WorkArena (overall SR):** Mem-π achieves 50.3%, compared to 46.1% for MemRL, 44.3% for Memory-R1, 44.1% for Mem0, 42.6% for RAG, and 42.0% for the base agent. The +8.3 pp gain is smaller in absolute terms than WebArena, reflecting WorkArena's more constrained enterprise workflows where the base agent already achieves relatively high performance and the room for memory-driven improvement is narrower.

**ALFWorld (overall SR):** Mem-π achieves 91.6%, with the base agent at 85.3%. The strongest baselines are RAG at 87.1%, Memory-R1 at 87.9%, and MemRL at 88.0%. The +6.3 pp gain over the base agent is notable given the already-high ceiling—the base gpt-5.4-mini agent is strong on these embodied tasks—but the gap between Mem-π and the best retrieval baseline (MemRL at 88.0%) is a more modest +3.6 pp. This consistent improvement across all six ALFWorld task types (Pick&Place, Examine, Clean, Heat, Cool, Pick-Two) suggests the memory policy is providing generally applicable procedural guidance rather than task-specific memorization.

**LifelongAgentBench (DB and OS):** Mem-π achieves 38.4% on DB and 35.0% on OS, averaging 36.7%, compared to the base agent's 28.5% and 25.0% (average 26.8%). The nearest baselines are MemRL at 33.0%/30.7% (avg. 31.9%) and Memory-R1 at 32.6%/29.8% (avg. 31.2%). The +9.9 pp average gain over the base agent is substantial, and Mem-π leads in both DB (+5.4 pp over MemRL) and OS (+4.3 pp over MemRL). This suggests that terminal tool use—where correct command syntax and procedural ordering are critical—benefits particularly from generative memory that can adapt procedural hints to specific query parameters.

#### Per-Domain Analysis on WebArena (Table 1)

The WebArena sub-domain breakdown reveals substantial heterogeneity in where Mem-π's gains come from:

- **CMS:** Mem-π achieves 42.8%, compared to the base agent's 14.6%. This is the largest relative gain of any domain (+28.2 pp), and Mem-π more than doubles the performance of the best baseline (MemRL at 26.4%). CMS tasks require navigating Magento admin interfaces—structured, form-based interactions where knowing the correct report path and filter configuration is essential. The paper attributes this gain to Mem-π's ability to condition on specific query parameters (e.g., rewriting date ranges, product counts) that retrieval copies verbatim from the most similar source.

- **Reddit:** Mem-π achieves 52.6%, compared to the base agent's 28.8% (+23.8 pp). Reddit tasks involve forum navigation where the correct sequence of actions (finding a subreddit, sorting, identifying the right post) depends heavily on the specific query parameters. The large gain suggests that retrieval-based memory often returns hints for similar-but-not-identical Reddit tasks with misleading specifics, while generation adapts the procedure.

- **Shopping:** Mem-π achieves 34.6%, compared to the base agent's 28.4% (+6.2 pp). The gap over baselines is more modest (MemRL: 31.2%, Memory-R1: 30.6%). Shopping tasks require product search and filtering where the base agent's general web-navigation capability is already relatively strong, and the marginal value of memory is lower.

- **GitLab:** Mem-π achieves 50.2%, compared to the base agent's 31.2% (+19.0 pp). GitLab tasks involve repository management, issue tracking, and code review—procedures that benefit from knowing the correct UI paths and API endpoints, which the memory policy internalizes.

- **Maps:** Mem-π achieves 35.4%, compared to the base agent's 32.4% (+3.0 pp). This is the smallest gain across any domain. Maps tasks involve geographic search and direction computation where the base agent is relatively proficient, and the task structure may be less amenable to procedural hinting (search queries are highly location-specific, making experience transfer difficult).

#### Stage 1 (Experience Distillation Only) Performance (Table 1)

A striking finding is that **Stage 1 alone—pure supervised imitation of JEF-Hinter hints, with no RL training—already matches or surpasses all RL-trained retrieval baselines**. Mem-π (Stage 1) achieves 35.0% on WebArena, compared to 34.0% for MemRL and 33.2% for Memory-R1. On WorkArena, Stage 1 achieves 41.6%, compared to 46.1% for MemRL (the only baseline ahead). On ALFWorld, Stage 1 achieves 90.0%, ahead of all baselines including MemRL at 88.0%. On LAB, Stage 1 achieves 35.3% (DB) and 32.9% (OS), averaging 34.1%, ahead of MemRL at 31.9%.

This has significant practical implications: if online RL is infeasible (due to environment interaction costs, safety constraints, or infrastructure limitations), **supervised parametric memory distillation alone is a viable alternative to state-of-the-art retrieval-based memory**. The paper does not overstate this—it acknowledges that Stage 1 still has the limitations of always-on generation and imitation-bounded quality—but the empirical finding itself is important and somewhat surprising given that Stage 1 never receives any signal about whether its hints actually help the agent succeed.

#### Stage 2 Gains and Where They Concentrate (Table 1)

The transition from Stage 1 to the full Mem-π yields an aggregate gain, but the gains are unevenly distributed:

- **WebArena:** +8.1 pp overall (35.0% → 43.1%). The largest sub-domain jumps are **CMS (+25.4 pp!)**, Reddit (+4.8 pp), and Maps (+3.0 pp). The CMS jump is remarkable—from 17.4% (Stage 1) to 42.8% (Mem-π)—suggesting that Stage 1 produced plausible but often incorrect guidance for CMS tasks (e.g., wrong menu paths or filter configurations) that RL realigned toward agent success. Interestingly, Shopping actually **declines** from 30.6% to 34.6%, a +4.0 pp gain, while GitLab goes from 46.8% to 50.2% (+3.4 pp).

- **WorkArena:** +8.7 pp (41.6% → 50.3%). The largest sub-domain gain is Form (+6.8 pp: 9.0% → 13.6%), followed by Menu & Dashboard (+4.3 pp: 65.8% → 70.6%). Form tasks require filling structured fields where small errors in field identification or value formatting cause failure—RL likely refines the guidance to be more precise about field names and expected formats.

- **ALFWorld:** +1.6 pp (90.0% → 91.6%). The small absolute gain reflects the high ceiling—the base agent is already at 85.3% and Stage 1 reaches 90.0%. RL squeezes out an additional fraction by refining edge cases.

- **LAB:** +2.6 pp average (34.1% → 36.7%). Both DB (+3.1 pp) and OS (+2.1 pp) improve modestly. Terminal command tasks may benefit less from RL refinement because the procedural hints from JEF-Hinter are already quite precise—there is less room for RL to discover better guidance than the human-written reference procedures.

#### Cross-Agent Transfer (Table 3)

The paper evaluates whether a memory policy trained with a Qwen-2.5-7B-Instruct agent transfers to the unseen gpt-5.4-mini agent **without retraining**. This tests whether the learned guidance encodes task knowledge at a sufficiently abstract level to benefit a different, stronger agent.

**On WebArena:** Mem-π transfers from +18.2 pp gain over the base Qwen agent (46.1% vs. 27.9%) to +16.0 pp gain over the gpt-5.4-mini agent (43.1% vs. 27.1%). The gain shrinks by 2.2 pp but remains very large. For comparison, RAG transfers from +4.2 pp (Qwen) to +4.3 pp (GPT-5.4-mini)—essentially constant, as expected for retrieval which doesn't depend on the training agent. Mem-π's 3–5× larger gains than RAG persist across agents.

**On ALFWorld:** Mem-π transfers from +11.8 pp (84.7% vs. 72.9%) to +6.3 pp (91.6% vs. 85.3%). The gain shrinks more significantly here (nearly halved), consistent with the higher ceiling: gpt-5.4-mini already achieves 85.3% on ALFWorld without memory, leaving less room for any memory system to add value. This pattern—gains shrink as the base agent becomes stronger—is expected for any memory intervention, since memory augments agent capability rather than replacing it, and stronger agents benefit less from external guidance.

**Key insight.** The paper interprets the cross-agent transfer result as evidence that "memory learned from a weaker agent can encode task guidance at a sufficiently explicit level to remain useful for stronger unseen agents" (Section 3.3). This has practical implications for deployment: organizations can train the memory policy using a cheaper, open-source agent during development, then deploy it with a proprietary frontier agent in production.

#### Adaptive Abstention Analysis (Figure 4)

The paper analyzes the relationship between Mem-π's abstention behavior and task difficulty on WebArena by binning tasks into five equal-width bins based on the base agent's success rate and plotting abstention rate and success-rate improvement per bin.

**The abstention-difficulty relationship is strongly monotonic:** on the easiest tasks (base agent SR 80-100%), Mem-π abstains ~71% of the time; on the hardest tasks (base agent SR 0-20%), abstention drops to ~13%. This is the key behavioral evidence that the policy has learned **calibrated abstention**—it recognizes when tasks are within the base agent's capability and avoids unnecessary intervention.

**The success-rate improvement shows the complementary pattern:** improvement is largest on the hardest bin (+9.7 pp) and smallest on the easiest bin (+1.3 pp). This means Mem-π is not just abstaining conservatively (avoiding generation everywhere) but strategically: it generates precisely on the tasks where memory provides the most benefit relative to the base agent.

**The paper does not show independent data on whether the base agent actually succeeds on the tasks where Mem-π abstains.** The abstention analysis shows that Mem-π abstains ~71% of the time on easy tasks and that the improvement on these tasks is only +1.3 pp, but it does not directly report the base agent's success rate on the subset where Mem-π abstained vs. generated. This means we cannot verify that abstention preserves base-agent performance—the +1.3 pp aggregate improvement could mask cases where abstention caused failures on tasks the base agent would otherwise have solved, offset by cases where generation helped. The case study (Figure 6, Case 2) provides anecdotal evidence of successful abstention, but systematic verification is missing.

#### Memory-Token Efficiency (Figure 5)

The paper compares task success rate against average memory tokens per task for all methods on WebArena. Mem-π achieves the best of both worlds: highest success rate (43.1%) at 138 memory tokens per task. Stage 1 uses 200 tokens at 35.0% SR—Mem-π improves both metrics simultaneously. Memory-R1 uses the most tokens (225 at 33.2% SR), while RAG uses the fewest (~120 at 31.4% SR).

The 31% token reduction from Stage 1 to Mem-π quantifies the value of adaptive abstention: by not generating on tasks where memory is unnecessary, the average token cost drops while success rate increases. The paper frames this as a Pareto improvement over always-on generation.

**An important nuance:** the token counts for Mem-π include abstention tasks (zero tokens), which pulls down the average. The paper does not report the **conditional** token count when Mem-π generates (i.e., average length of guidance when d = [GENERATE]), which would tell us whether the guidance that *is* produced is shorter/better/more efficient than Stage 1's always-on guidance, or whether the token savings come entirely from the abstention rate. With a ~34% overall abstention rate on WebArena (Figure 7a) and 31% fewer tokens than Stage 1, we can infer that the per-generation token count is similar (since the token savings roughly match the abstention fraction), but this is not directly reported.

#### Visual Observations Ablation (Figure 3)

On WebArena, adding visual information (initial screenshot + grounding text extracted by gemini-2.5-flash, processed by Qwen-2.5-VL-7B-Instruct as the memory backbone) provides consistent gains over the text-only variant (Qwen-2.5-7B-Instruct). The overall improvement is +2.7 pp (45.8% vs. 43.1%, approximately—the paper shows bars but does not tabulate the exact numbers; these are estimates from Figure 3's bar chart).

The gains are domain-dependent, which is informative about where visual information matters for memory:
- **CMS** shows the largest gain (+3.8 pp)—consistent with the Magento admin interface having visual layout cues (sidebar menus, report configuration panels, data grids) that textual state representations may not fully capture.
- **Shopping** shows +3.3 pp—product images and page layouts provide grounding signals for e-commerce navigation that text alone misses.
- **Reddit** (+2.4 pp) and **Maps** (+1.7 pp) show moderate gains.
- **GitLab** shows the smallest gain (+0.9 pp)—consistent with GitLab's code-centric content where visual rendering provides limited additional signal beyond what structured text captures (repository names, file paths, merge request metadata).

**The paper does not ablate the visual backbone choice or the grounding extraction method.** It uses gemini-2.5-flash for grounding extraction and Qwen-2.5-VL-7B-Instruct as the VL backbone, but does not test whether a different VL model or a different grounding extraction approach would yield different results, nor does it compare against a version that receives raw screenshots without grounding text. This limits conclusions about *why* vision helps—is it the raw pixel information, the structured grounding, or the combination?

### Ablation Studies and Robustness Checks

**Training stage necessity (Table 2):** Removing Stage 1 initialization and applying online RL directly to Qwen2.5-7B-Instruct causes a **-5.2 pp** drop on WebArena (43.1% → 37.9%) and a **-4.7 pp** drop on ALFWorld (91.6% → 86.9%). The unified single-stage variant—which collapses both stages into one RL phase with a combined reward including a BERTScore similarity term to reference hints—performs even worse: **-6.8 pp** on WebArena (43.1% → 36.3%) and **-5.9 pp** on ALFWorld (91.6% → 85.7%). The paper attributes this to conflicting reward signals: `R_sim` encourages imitation of reference memories, while `R_task` rewards task success, and useful memories for new tasks may differ from the references. The Stage 2-to-unified gap is larger than the Stage 1 removal gap, suggesting the sequential training design matters both for initialization quality and for avoiding optimization conflicts.

**Structured rollout necessity (Table 2):** Removing structured counterfactual rollouts and reverting to vanilla GRPO (i.i.d. sampling of branches) causes the largest single-component drop: **-4.8 pp** on WebArena (43.1% → 38.3%) and **-4.5 pp** on ALFWorld (91.6% → 87.1%). This confirms that without guaranteed abstain-generate comparisons, the policy rarely observes the cross-branch signal needed to learn adaptive abstention. The paper does not report whether vanilla GRPO ever samples groups with mixed abstain/generate branches—it would be informative to know how often the comparison naturally occurs under i.i.d. sampling.

**Δ-gating necessity (Table 2):** Removing Δ-gating and replacing it with a naive sum of decision and content advantages causes a **-1.8 pp** drop on WebArena (43.1% → 41.3%) and **-2.0 pp** on ALFWorld (91.6% → 89.6%). This smaller but consistent drop supports the paper's claim that the gating mechanism is necessary to prevent content-level updates from diluting the decision signal, particularly on tasks where generation is harmful.

**Length regularizer effect (Table 2):** Removing the length penalty `R_m` causes a **-1.2 pp** drop on WebArena (43.1% → 41.9%) and **-1.1 pp** on ALFWorld (91.6% → 90.5%). This mild degradation suggests the length regularizer provides a small but helpful signal toward conciseness. The paper frames this as evidence that "the length regularizer encourages concise memory and helps reduce noise in generated guidance," but the effect is small enough that it could potentially fall within seed variance (not reported).

**Visual observations (Figure 3):** Already discussed in Main Results above. Consistent gains across all WebArena sub-domains, largest in visually grounded domains (CMS, Shopping), smallest in code-centric domains (GitLab).

**Symmetric vs. standard decision-token initialization (Figure 7b):** The paper shows training curves for abstention rate with and without symmetric initialization of the `[ABSTAIN]` and `[GENERATE]` token embeddings. With symmetric initialization, the abstention rate starts at ~50% and converges to a stable task-appropriate level within ~100 steps. Without symmetric initialization, the `[ABSTAIN]` token starts with near-zero probability, recovers slowly to ~21%, and never reaches the converged rate of the symmetric variant. This is a small but practically important finding: the success of RL-based abstention learning depends on a trivial-seeming initialization trick that ensures both decisions are adequately explored from the start. Without it, the policy is stuck in a generate-always local optimum.

**Case analysis Venn diagram (Figure 6, left):** Across the WebArena test set, the paper reports task-count overlaps between the base agent, RAG, and Mem-π success sets. The raw counts are: 10 tasks solved by Base + Mem-π but not RAG (Pattern 2: abstention recovers from RAG noise), 19 tasks solved only by Mem-π (Pattern 1: generation reaches where retrieval fails), 28 tasks solved by all three, 12 tasks solved by RAG + Mem-π but not Base, and smaller counts for other regions. The detailed case breakdown in Appendix A.4 provides concrete examples for each region, showing both Mem-π's wins (regions 001, 101; 25 tasks total) and losses (regions 010, 110, 100; 13 tasks total) with plausible explanations for each failure mode.

### Critical Assessment

#### Do the experiments support the claim that Mem-π achieves state-of-the-art performance across benchmarks?

**Yes, with qualifications.** The results in Table 1 show Mem-π outperforming all listed baselines on all four benchmarks using gpt-5.4-mini as the downstream agent. The gains are largest on WebArena (+16.0 pp over base, +9.1 pp over the best baseline MemRL) and most modest on ALFWorld (+6.3 pp over base, +3.6 pp over MemRL). However, several factors limit the strength of the SOTA claim:

- **The baseline set is not exhaustive.** The paper compares against four memory baselines (RAG, Mem0, Memory-R1, MemRL) but does not include comparisons against other recent generative memory systems that it cites as related work—ParaMem, SEAM, or MemGen. This is understandable given that these are concurrent or near-concurrent works, but it means the claim of "state-of-the-art" is relative to the selected baselines, not the full literature. Given that SEAM (Li et al., 2026) also uses GRPO to train a generative memory component, a direct comparison would be particularly informative.

- **Single memory backbone (Qwen-2.5-7B-Instruct).** All methods use the same backbone for fair comparison, but the paper's conclusions about the superiority of generative memory over retrieval may be specific to this model scale. Would a larger memory model (e.g., Qwen-2.5-32B) produce even better generative memory, or would the retrieval gap narrow? The paper provides no scaling analysis.

- **Single base agent per result column.** Table 1 reports results with gpt-5.4-mini as the agent, while Table 3 adds Qwen-2.5-7B as an additional agent for WebArena and ALFWorld only. We don't know whether the WorkArena and LAB gains transfer to other agents.

- **No variance reporting.** Without standard deviations or confidence intervals, we cannot assess whether differences of 1-2 pp between Mem-π and the best baselines are statistically reliable, particularly on ALFWorld where the gap to MemRL is only +3.6 pp with a test set of 134 tasks.

#### Does the decision-content decoupled RL objective actually cause the reported gains, or is the two-stage training itself sufficient?

**The evidence is strong that both stages matter, but the incremental contribution of the decoupled objective specifically (beyond generic RL) is harder to isolate.** The ablation comparing full Mem-π against "w/o structured rollout" shows a large drop (4.8 pp on WebArena), but this ablation removes *both* structured rollouts and the associated advantage decomposition—it's a bundled removal. The Δ-gating ablation removes a smaller piece and shows a 1.8 pp drop. The combination suggests that the decoupled objective components are important, but we cannot attribute the full Stage 2 gain (8.1 pp on WebArena) specifically to the decoupling—some of that gain comes from the RL training itself (reward alignment, abstention learning) and some from the specific objective design. A more diagnostic ablation would be: Mem-π with structured rollouts but with a flat scalar advantage (no per-token decomposition), which would isolate the effect of the structured sampling from the effect of the per-token credit assignment. This ablation is not reported.

#### Do the experiments support the claim that adaptive abstention provides calibrated, difficulty-aware behavior?

**Partially.** Figure 4 shows a clear monotonic relationship between task difficulty (base agent SR) and abstention rate, with improvement concentrated on harder tasks. This is consistent with calibrated abstention. However, the paper does not report the base agent's success rate *conditional on Mem-π's decision*—what is the base agent's SR on tasks where Mem-π abstains vs. where it generates? Without this, we cannot verify that abstention correctly preserves base agent success on easy tasks (rather than, say, abstaining randomly and happening to coincide with easy tasks in aggregate). The case study provides one example of successful abstention (Figure 6, Case 2) and the region analysis counts 10 tasks where Base+Mem-π succeed but RAG fails (consistent with abstention recovering from RAG noise), but there are also 3 tasks where Base succeeds alone but Mem-π fails. These 3 tasks—plus the 4 tasks where Base+RAG succeed but Mem-π fails—are potential cases of harmful generation or incorrect abstention. The paper does not analyze these failure cases in enough detail to determine whether they represent incorrect abstention decisions or poor-quality generated guidance.

#### Does the cross-agent transfer result actually demonstrate generalization?

**Yes, but the transfer agents are from different model families, not different capabilities.** The training agent is Qwen-2.5-7B-Instruct and the transfer agent is gpt-5.4-mini. The gains shrink as expected (from +18.2 to +16.0 pp on WebArena; from +11.8 to +6.3 pp on ALFWorld). The paper interprets this as evidence that memory encodes task knowledge at an abstract level, but an alternative interpretation is that the Qwen and gpt families share similar web-navigation capabilities (both are strong instruction-tuned models) and the guidance is simply procedurally useful regardless of the agent. A stronger test of generalization would be transfer to an agent with substantially different capabilities (e.g., a much smaller model, or a model from a different architecture family with different failure modes). The paper does not test this.

#### Do the visual-input results demonstrate that multimodal information improves memory generation?

**Yes, but with narrow scope.** Figure 3 shows consistent gains from adding visual information on WebArena, with domain-appropriate variation (larger gains in visually grounded domains). However, the experiment uses a specific visual pipeline (screenshots + gemini-2.5-flash grounding text + Qwen-2.5-VL-7B-Instruct) and compares against a text-only Qwen-2.5-7B-Instruct. This confounds the visual modality with the model architecture (VL vs. text-only backbones), making it unclear whether the gains come from visual information or from using a VL model. A proper ablation would include a vision-language model variant that receives only text, to isolate the information channel from the model capacity.

#### What experiments would strengthen the paper but were not run?

- **Direct comparison with SEAM and other generative memory methods**—to support the claim that the decision-content decoupling specifically matters beyond generic generative memory.
- **Scaling analysis of the memory model**—how do the gains change if πmem is Qwen-2.5-0.5B, 1.5B, 7B, 32B? Does the retrieval gap narrow or widen with model scale?
- **Agent-aware difficulty analysis**—does the difficulty binning (based on gpt-5.4-mini's SR) change if we use the training-time Qwen agent instead? Are the same tasks "easy" for both agents?
- **Variance reporting**—confidence intervals or standard deviations for all main-table results, particularly important given small test sets (134–165 tasks per benchmark).
- **Ablation of the visual pipeline**—text-only VL model vs. VL model with vision, to separate modality from architecture effects.
- **Conditional memory token analysis**—how long is Mem-π's generated guidance when it *does* generate, versus Stage 1's always-on guidance? Are the RL-trained generations more concise, or are the token savings entirely from abstention?

## 6. Limitations and Trade-offs

### The Difficulty Estimation and Difficulty-Conditioned Allocation Cost Is Not Accounted For

**The assumption or constraint.** The paper's central innovation—adaptive abstention that varies with task difficulty—is evaluated *after* the policy has been trained, with no accounting for the cost of learning *whether* to generate or abstain. The difficulty-binned analysis (Figure 4, Section 3.3) uses a post-hoc binning of test tasks by the base agent's success rate into five equal-width bins. This is not a difficulty *prediction* that Mem-π performs at inference time—it is a retrospective categorization of test tasks used to analyze the policy's *emergent* behavior. The policy itself receives only the task context `(q, o)` and produces `d ⊕ m` without any explicit difficulty estimate. The paper acknowledges the cost of difficulty estimation in the context of its compute-optimal test-time scaling framework (Section 3.2), but Mem-π's adaptive abstention does not rely on explicit difficulty estimation—it learns when to generate directly from the structured RL objective.

However, a related cost *is* unaccounted for: the paper does not amortize the cost of Stage 2 RL training into any efficiency metric. Stage 2 requires approximately 1,600 task interactions per benchmark (200 optimization steps × 8 tasks per step × 1 interaction per task to obtain the task reward for the structured rollout group—though each step involves 4 branches, the reward signal comes from executing the agent under each branch, so this is roughly 200 × 8 × 4 = 6,400 agent executions). The paper reports memory token savings at inference time (138 tokens per task for Mem-π vs. 200 for Stage 1, Figure 5) but does not include the RL training cost in any amortized efficiency calculation.

**The consequence.** The headline efficiency gain—31% fewer memory tokens than Stage 1 with higher success rate (Figure 5)—is an *inference-time* gain that does not reflect the total cost of achieving that policy. If a practitioner needs to run Stage 2 RL for each new benchmark or domain, the fixed cost of online environment interaction may dominate the per-task inference savings unless the policy is deployed at massive scale. This is particularly relevant for the paper's practical framing: the two-stage recipe (Section 4, Innovation 4) is presented as a general approach for converting offline experience banks into generative memory policies, but Stage 2 requires online agent execution to obtain task rewards. In domains where environment interaction is expensive, slow, or unsafe (e.g., real-world robotics, production database manipulation, enterprise systems with rate limits), the RL stage may be impractical regardless of the inference-time benefits.

**What evidence exists in the paper.** The paper reports the number of RL optimization steps (200) and batch size (8 tasks per step) in Appendix A.2 but does not report the total number of agent-environment interactions needed for Stage 2, wall-clock training time, or the cost relative to the number of inference queries needed to amortize the training. Figure 5 shows inference-time token efficiency but is purely a test-time metric. The ablation showing "w/o Stage 1 init" requires RL from scratch, which the paper shows underperforms (−5.2 pp on WebArena, Table 2), confirming that Stage 2 *needs* Stage 1 initialization—but neither experiment quantifies the cost of Stage 2 itself relative to the gains it provides.

**Mitigation status.** The paper does not discuss amortization of training cost or propose methods to reduce Stage 2's environment interaction budget. It does not report whether fewer RL steps would yield similar performance (no learning curve is provided). The authors do not frame this as a limitation—the training cost is simply not discussed in the context of efficiency claims. The paper also does not explore whether Stage 1 alone (which requires no online interaction) might be sufficient if combined with a simpler abstention heuristic (e.g., thresholding the PRM score, or using a lightweight classifier), which would eliminate the need for online RL entirely while preserving some of the abstention benefit.

### The $14\times$ Larger Pretraining Baseline Is Empirically Meaningful but Contextually Mismatched

**Note: This limitation is specific to the FLOPs-matched comparison in Section 7 of the cited paper, which uses a much larger model than the 7B memory backbone used throughout Mem-π. However, the cross-agent transfer experiment in Mem-π (Section 3.3, Table 3) provides a structurally analogous comparison: a memory policy trained with a weaker agent (Qwen-2.5-7B-Instruct) is evaluated with a stronger agent (gpt-5.4-mini). I structure this limitation around the cross-agent scaling implications of Mem-π's design.**

**The assumption or constraint.** Mem-π's memory policy πmem is trained with the same downstream agent that provides the reward signal during Stage 2 RL (Qwen-2.5-7B-Instruct, fine-tuned under the WebAgent-R1 setting). The paper evaluates cross-agent transfer by deploying this same memory policy with gpt-5.4-mini without retraining (Table 3). The implicit assumption is that guidance useful for a 7B agent remains useful—perhaps equally useful—for a frontier agent with substantially greater capability.

**The consequence.** The cross-agent transfer results (Table 3) show a consistent but shrinking gain: +18.2 pp over the base Qwen agent on WebArena vs. +16.0 pp over the base gpt-5.4-mini agent (a 2.2 pp reduction), and +11.8 pp on ALFWorld vs. +6.3 pp (a 5.5 pp reduction, nearly halved). This pattern suggests that as the agent becomes stronger, the marginal value of memory decreases. The paper interprets this as evidence that memory encodes task knowledge at an abstract level, but an equally valid interpretation is that the memory policy produces guidance optimized for the *weaknesses* of the training agent—guidance that helps a Qwen agent overcome navigation errors or procedural mistakes that a gpt-5.4-mini agent doesn't make in the first place.

This creates a deployment trade-off that the paper does not address: should one train the memory policy with the strongest available agent (to produce guidance relevant to that agent's actual failure modes), or with a weaker agent (to obtain sparser but more interpretable guidance that generalizes broadly)? Training with a strong agent may produce more targeted guidance but the RL reward signal becomes sparser (the agent already succeeds on many tasks, leaving fewer opportunities to observe when guidance helps vs. when it's unnecessary). Training with a weak agent provides denser reward signal but risks producing guidance that addresses weaknesses the deployment agent doesn't have, wasting tokens and potentially introducing distracting or misleading cues. The paper provides no analysis of this trade-off because it only tests one training agent and one transfer agent.

**What evidence exists in the paper.** Table 3 provides the primary evidence of the shrinking-gain pattern. The ALFWorld results are particularly telling: Mem-π provides only +6.3 pp gain for gpt-5.4-mini (from 85.3% to 91.6%) versus +11.8 pp for Qwen (from 72.9% to 84.7%). Since gpt-5.4-mini is already at 85.3%, the ceiling effect is real, but the pattern is consistent with agent-specificity of the learned guidance. The paper does not analyze *which* ALFWorld tasks Mem-π helps Qwen with but not gpt-5.4-mini (or vice versa), nor does it analyze the content of generated guidance to determine whether it addresses agent-specific failure modes or general procedural knowledge. The case studies (Figure 6 and Appendix A.4) are all from the gpt-5.4-mini evaluation and do not provide Qwen-specific qualitative analysis.

**Mitigation status.** The paper acknowledges that "training with even weaker agents may further improve interpretability, but could also make Stage 2 RL rewards sparser, introducing a trade-off for future exploration" (Section 3.3). This is a brief mention without empirical exploration. The paper does not test memory policies trained with different agents (e.g., Qwen-2.5-0.5B, Qwen-2.5-1.5B, Qwen-2.5-32B) to characterize the agent-specificity curve, nor does it test whether fine-tuning the memory policy on the deployment agent's trajectories (even without full RL) recovers the lost gains. This limitation is consequential for practitioners because it affects a key stated benefit of Mem-π's design: "a smaller private local model can be fine-tuned as πmem and plugged into a larger or frontier agent model" (Section 1). The paper demonstrates this works, but does not characterize how much performance is left on the table relative to training directly with the frontier agent.

### Evaluated on a Single Model Family with a Single Memory Backbone; No Scaling Analysis

**The assumption or constraint.** All experiments use Qwen-2.5-7B-Instruct as the memory policy backbone (with Qwen-2.5-VL-7B-Instruct for the visual ablation). The paper justifies this choice by matching the Memory-R1 baseline's backbone "for fair comparison" (Appendix A.2), but the implication throughout the paper—particularly in the parametric memory motivation—is that the generative-memory paradigm is broadly applicable across model scales. The paper states that "its memory footprint is bounded by model size rather than the number of accumulated experiences" (Section 1) as a key advantage of parametric memory, but this property is architectural and would hold at any scale. The question is whether the *performance* advantage over retrieval-based memory holds at other scales.

**The consequence.** Without scaling analysis, we cannot determine whether the generative-memory advantage is a property of the 7B scale specifically or a more general phenomenon. Several scaling-dependent effects are plausible:

- **At smaller scales** (e.g., 0.5B, 1.5B): The memory model may lack the capacity to internalize the experience bank effectively during Stage 1. The supervised distillation of thousands of task-hint pairs into 7B parameters may work well, but 0.5B parameters may not have sufficient capacity to encode the diversity of guidance patterns, causing the model to produce lower-quality hints or to over-generalize (producing the same generic guidance for many different tasks). This would shrink or reverse the gap relative to retrieval, which has no capacity bottleneck (the bank scales with experience).

- **At larger scales** (e.g., 32B, 70B): The memory model may produce substantially better guidance, widening the gap over retrieval. Alternatively, larger models may overfit the Stage 1 imitation signal and become harder to optimize with Stage 2 RL (larger models typically require more careful KL regularization to prevent reward hacking). The paper provides no evidence either way.

- **Cross-backbone generalization**: The paper uses Qwen-2.5 models exclusively. Would Mem-π trained with a Llama-3 backbone perform similarly? Would the decision-content decoupled objective work equally well with different model architectures or tokenizers? The special-token initialization trick (symmetric embedding for `[ABSTAIN]` and `[GENERATE]` based on semantically related existing tokens) relies on properties of the Qwen tokenizer and embedding space that may not transfer.

**What evidence exists in the paper.** None. There is no scaling analysis—no experiments varying the memory model size, no experiments with alternative backbones, and no discussion of how the results might change at different scales. This is a notable gap given that the parametric-memory argument (fixed footprint regardless of experience) is one of the three advertised advantages of the generative paradigm (Section 1, paragraph 5). The footprint advantage exists at any scale, but the performance advantage may not.

**Mitigation status.** Not addressed. The paper does not acknowledge the single-scale, single-family limitation, nor does it suggest scaling analysis as future work. Given that the memory model is separate from the agent and relatively small (7B parameters), the scaling properties of generative memory are a first-order practical question for anyone considering deployment: should I use the smallest model that can still internalize my experience bank, or does performance improve substantially with scale? The paper provides no guidance.

### The Case Analysis Reveals Systematic Failure Modes That the Paper Does Not Quantify or Address

**The assumption or constraint.** The paper's case analysis (Figure 6 and Appendix A.4) partitions the WebArena test set into eight Venn regions based on which methods succeed. Two regions represent Mem-π's wins over RAG (25 tasks total, regions 001 and 101), but three regions represent Mem-π's losses to RAG or to the base agent: region 010 (6 tasks where RAG succeeds but Mem-π fails), region 110 (4 tasks where Base + RAG succeed but Mem-π fails), and region 100 (3 tasks where only the base agent succeeds, both memory methods fail).

**The consequence.** The failure cases in Appendix A.4 reveal specific, recurring failure modes in Mem-π's generated guidance:

- **Region 110 (Case A5): Generation produces plausible but inverted instructions.** The query asks to preview a theme, which requires clicking "View" in the Action column. Mem-π's guidance says "avoid clicking the Action column"—exactly opposite to the correct action—while RAG's retrieved hint preserves the correct "Action → View" click from the source task. This suggests that the generative policy sometimes produces *confident but incorrect* procedural advice—a failure mode that retrieval, limited to reproducing verified hints, largely avoids. The paper notes this as a "plausible but inverted instruction" but does not analyze how often generation produces actively misleading vs. merely suboptimal guidance.

- **Region 010 (Case A6): Generation re-orders procedural steps incorrectly.** The generated hint moves a "Reset Filter" step earlier in the procedure than the retrieved hint, which causes the page to clear a server-side default needed for the page to populate. The content of both hints is nearly identical—only the *ordering* differs—but the ordering is critical. This suggests the generative policy has imperfect procedural world knowledge: it knows *what* actions to take but not always *in what sequence*, a failure mode that retrieval (which preserves the source trajectory's ordering) avoids.

- **Region 100 (Case A7): Both memory methods prescribe plans exceeding the agent's effective context window.** The generated hint (like the retrieved hint) recommends multi-page enumeration and arithmetic that overloads the agent's context. The unassisted base agent succeeds by using a simpler shortcut. This suggests that both generative and retrieval-based memory can produce guidance that is *correct but impractical* for the agent's capabilities—a failure mode the paper's length regularizer is designed to address, but which evidently persists in edge cases.

**What evidence exists in the paper.** The Venn diagram (Figure 6, left) provides aggregate counts: 25 tasks where Mem-π wins over RAG, 13 tasks where Mem-π loses to RAG or Base. The paper presents the win cases prominently (Cases 1 and 2 in Figure 6) and provides full region analysis in Appendix A.4, but the main text does not quantitatively characterize the failure modes. There is no analysis of how often generated guidance contains factual errors (like Case A5), procedural ordering errors (like Case A6), or impractical complexity (like Case A7), nor whether these failure modes correlate with task difficulty, domain, or generation length. The paper does not report whether the Δ-gating mechanism or the length regularizer specifically reduces any of these failure modes (the ablations in Table 2 remove these components entirely, but do not decompose their effect by failure type).

**Mitigation status.** The paper acknowledges the existence of failure cases through the Venn diagram and case studies but treats them as qualitative illustrations rather than systematic limitations to be addressed. There is no discussion of how these failure modes might be mitigated—for example, using the PRM from the compute-optimal scaling framework (Section 5.1 of the companion paper) to verify generated guidance before injecting it, or training with negative examples (incorrect hints that cause agent failure) to teach the policy to recognize and avoid common mistake patterns. The paper frames the case analysis as support for Mem-π's advantages (highlighting the 25-task win) rather than as a diagnostic of its remaining weaknesses (the 13-task loss), which is a missed opportunity for understanding where generative memory still falls short relative to simpler retrieval approaches.

### Single-Turn Memory Intervention; No Analysis of Multi-Turn Memory Dynamics or Accumulation Over Time

**The assumption or constraint.** Mem-π produces a single guidance string at the start of a task and injects it into the agent's context once. The agent then operates on the augmented context for the entire trajectory, with no further memory intervention. The paper evaluates Mem-π on benchmarks where tasks are independent episodes—each test task is solved once, and there is no notion of accumulating memory across tasks within a session. This is a single-turn memory intervention model: the memory policy observes the initial task context `(q, o)`, produces guidance (or abstains), and its job is done.

**The consequence.** Real-world agent deployment often involves sequential task-solving within a session, where earlier tasks provide context for later ones, and memory should accumulate and update dynamically. A customer support agent handling multiple tickets in a session might benefit from remembering the resolution pattern from ticket 1 when handling a similar ticket 3 later. A research assistant conducting a multi-step literature review should carry forward insights from earlier papers to later ones. Mem-π's single-turn design does not address these scenarios:

- **No memory update mechanism.** The policy πmem is frozen after training. There is no mechanism to incorporate new experiences encountered during deployment into the policy's parameters without full retraining (or at least additional RL fine-tuning). This contrasts with retrieval-based memory, where new experiences can simply be added to the bank, and contrasts with online-learning memory systems that update continuously from agent interactions.

- **No cross-task context.** Each task is processed independently. The policy cannot condition on what the agent did in previous tasks within the same session, what guidance was previously provided, or whether that guidance was successful. This limits the policy's ability to adapt its guidance based on observed agent performance—if the agent consistently fails on a particular type of task, a multi-turn memory system could escalate from abstention to generation, or from brief hints to detailed procedures.

- **Potential for stale guidance.** Since πmem is trained on a static offline experience bank, the guidance it produces reflects the environment, agent capabilities, and task distribution at training time. If the environment changes (e.g., a website redesign, a new software version, new task types), the policy may produce outdated guidance that references deprecated UI elements or obsolete procedures. Retrieval-based memory can mitigate this by updating the bank; parametric memory requires retraining.

**What evidence exists in the paper.** None directly, because the benchmarks are explicitly single-episode. The paper acknowledges this implicitly by evaluating on standard agent benchmarks (WebArena, WorkArena, ALFWorld, LAB) that all define tasks as independent evaluation episodes. The LifelongAgentBench (LAB) benchmark's *name* suggests lifelong learning, but the paper uses it in the standard single-episode evaluation mode with a fixed train/test split, not in a continual-learning setup where the agent encounters tasks sequentially and must accumulate and transfer knowledge across the sequence. The paper does not discuss multi-turn memory dynamics, online memory updating, or concept drift as limitations or future directions.

**Mitigation status.** The paper does not address this limitation directly, but Section 5 (Conclusion) gestures toward future work on "closed-loop memory learning, where agents continuously collect new experiences and update their parametric memory." This acknowledges the gap but provides no empirical exploration or proposed mechanism for doing so. Continuous parametric memory updating is a hard problem—naively fine-tuning πmem on the agent's own trajectories could lead to catastrophic forgetting of previously learned guidance, reward hacking (the policy learns to produce guidance that succeeds on specific tasks but fails to generalize), or distribution collapse (the policy's outputs become increasingly narrow as it overfits to recent experience). The paper's two-stage training recipe does not address any of these challenges, and the single-turn evaluation does not measure resistance to these failure modes. For practitioners considering long-term deployment where the task distribution or environment evolves, this is a significant open question.

### No Statistical Significance Reporting; Test Sets Are Small for the Claimed Gains

**The assumption or constraint.** The paper reports all main results as point estimates (means over three independent seeds) without standard deviations, confidence intervals, or statistical significance tests. The test sets are small: WebArena has 165 test tasks, ALFWorld has 134 unseen test tasks, WorkArena has 10 seeds × 33 templates = 330 evaluation instances, and LAB has 150 test tasks per subset (DB and OS). The reported gains on some benchmarks are modest in absolute terms: on ALFWorld, Mem-π (91.6%) beats MemRL (88.0%) by only +3.6 pp, which is a difference of approximately 5 tasks out of 134 on the ALFWorld unseen split. On WorkArena's sub-domains, several gains are in the 1-3 pp range over the best baselines.

**The consequence.** Without variance estimates, we cannot determine whether the reported differences between Mem-π and the strongest baselines are statistically reliable or could be explained by seed variation. This is particularly acute in two regimes:

- **Small absolute gains on small test sets.** On ALFWorld, a 3.6 pp gap over MemRL corresponds to approximately 4.8 tasks (3.6% of 134). If the per-seed standard deviation is even 2-3%, the difference may not be statistically significant. Similarly, some of the ablation effects in Table 2—the length regularizer removal (−1.2 pp on WebArena, −1.1 pp on ALFWorld)—could easily fall within seed variance. The paper's claim that "the length regularizer encourages concise memory and helps reduce noise in generated guidance" is plausible but not statistically supported.

- **Cross-benchmark ranking instability.** The paper frames results as a consistent ranking (Mem-π > MemRL > Memory-R1 > Mem0 > RAG > Base Agent), but with small test sets and unreported variance, this ranking could be fragile. On WorkArena, for example, the ordering between Stage 1 (41.6%), Mem0 (44.1%), and Memory-R1 (44.3%) is within a 2.7 pp range—potentially overlapping within one standard deviation. If the ranking is not statistically reliable, the paper's narrative of consistent improvement across benchmarks is weaker than it appears.

**What evidence exists in the paper.** The paper reports "means over three independent seeds" (Appendix A.2) but provides no variance information. Figures 4 (abstention analysis) and 5 (token efficiency) show no error bars. The Venn diagram (Figure 6) reports exact task counts but does not indicate whether the region boundaries are stable across seeds—would the same tasks fall into region 001 (Mem-π only) across all three seeds, or is there seed-dependent variation in which tasks each method solves? The case studies (Figure 6 and Appendix A.4) analyze specific tasks qualitatively, but do not indicate whether the failure patterns are consistent across seeds.

**Mitigation status.** Not addressed. The paper does not acknowledge the absence of variance reporting as a limitation, nor does it provide any justification for why three seeds were chosen (vs. five or ten). The small test sets are an inherent constraint of the benchmarks (MATH, WebArena, and ALFWorld all have established test splits that the paper follows), but this makes variance reporting *more* important, not less—when sample sizes are small, readers need confidence intervals to interpret small differences. The paper's strongest claims—"Mem-π consistently outperforms retrieval-based and RL-optimized memory baselines" (Section 5, Conclusion)—are qualitative summaries that are not fully supported by the quantitative evidence provided.

## 7. Implications and Future Directions

### How This Work Changes the Landscape

This paper shifts the conversation about agent memory from **retrieval engineering to policy learning**. The dominant paradigm in the field—whether workflow-based (RAG, Mem0, JEF-Hinter) or learning-based (Memory-R1, MemRL)—has treated memory as a storage-and-lookup problem: collect experiences, index them, retrieve the most similar ones. Mem-π argues that this framing has a structural ceiling. Even perfect retrieval returns static content that cannot adapt its specifics (numbers, identifiers, procedural ordering) to a new query. The paper provides concrete evidence of this ceiling through the case studies (Figure 6, Case 1): the most similar retrieved hint says "read the first two rows" because the source task was top-2, but the current query asks for top-3. The hint is close in embedding space but contains a verbatim error that generation can fix by conditioning on the explicit "3" in the query.

This is not an incremental improvement to retrieval—it is a **paradigm shift** from treating memory as a database to treating memory as a generative policy with its own parameters, its own training pipeline, and crucially, its own decision about whether to intervene at all. The shift is analogous to the transition from retrieval-based QA (where answers are looked up in a corpus) to generative QA (where answers are produced from parametric knowledge), but with an additional dimension: the policy must also learn *when to be silent*. The paper shows that this silence decision is not optional—the always-on Stage 1 variant uses 31% more tokens while achieving lower success rate (Figure 5), and the case studies show that injected memory can actively mislead the agent (Figure 6, Case 2; region 010 cases in Appendix A.4).

The paper also provides a **reconciliation mechanism** for a tension in the literature. Prior generative memory systems (ParaMem, SEAM, MemGen) took a step toward parametric memory but either treated generation as always-on or trained by imitating a retriever. This created inconsistent expectations: sometimes generation helped, sometimes it added noise, and it was unclear why. Mem-π's abstention mechanism and difficulty-binned analysis (Figure 4) provide a framework for understanding this variation: on easy tasks where the base agent already knows what to do, memory—whether retrieved or generated—is mostly unnecessary and can be harmful; on hard tasks, generative memory that adapts to the query provides genuine value that retrieval cannot match. The abstention rate varies monotonically with task difficulty (~71% on easy tasks, ~13% on hard tasks), showing that the policy has learned calibrated intervention. This suggests that prior work's mixed results may reflect differences in benchmark difficulty distributions rather than fundamental limitations of generative memory.

Perhaps the most significant methodological contribution is the identification of a **structural credit assignment pathology** in standard per-token policy gradients when the output contains a short routing decision followed by a long generation. The paper shows (Table 2) that vanilla GRPO cannot learn adaptive abstention effectively—removing structured rollouts costs 4.8 pp on WebArena, and removing Δ-gating costs another 1.8 pp. This pathology generalizes beyond agent memory to any setting where an LLM must make a binary routing decision before generating content: tool-use selection, retrieval-vs-reasoning decisions, modality routing in multimodal systems. The decision-content decoupled objective—structured counterfactual rollouts + per-token credit assignment with gating—is a **general design pattern** for this class of problems, not a domain-specific trick.

The paper also reframes what "memory efficiency" means in agent systems. Prior work measured efficiency by retrieval latency, bank size, or memory write cost. Mem-π introduces a new axis: **intervention efficiency**—how many tokens of guidance are injected per task, and whether those interventions actually improve outcomes. Figure 5 shows that Mem-π achieves the best of both worlds (highest success rate at lowest token cost), while always-on generation and verbose retrieval baselines occupy worse points on the efficiency frontier. This creates a new evaluation criterion for memory systems: not just "does memory improve performance?" but "does memory improve performance per token of intervention?" If a memory system produces verbose guidance that sometimes helps but sometimes distracts, it may be worse than no memory at all—a point the base-agent-only success cases (Figure 6, region 100) directly demonstrate.

Where does this leave retrieval-based memory? The paper is careful not to claim retrieval is obsolete. The case analysis (Appendix A.4) shows six tasks (region 010) where RAG succeeds and Mem-π fails—typically because retrieval preserves a verified procedural ordering that generation re-orders incorrectly. The paper's contribution is not "generation beats retrieval" but **"generation and retrieval have complementary failure modes, and an adaptive generative policy can match retrieval's strengths (by producing similar guidance when appropriate) while adding capabilities retrieval structurally cannot match (query adaptation, abstention)."** This suggests a future where memory systems are evaluated on their decision quality (when to intervene, which type of intervention to use) rather than on retrieval accuracy alone.

### Follow-Up Research This Work Enables

**1. Direct comparison between Mem-π and SEAM on the same benchmarks with the same agent and experience bank.** The paper cites SEAM (Li et al., 2026) as the closest prior work—it also uses GRPO to train a generative memory component—but provides no direct comparison. SEAM trains an "experience adapter" to generate utility-optimized experience entries for a frozen executor, which is architecturally similar to Mem-π's design but lacks the decision-content decoupled objective and the supervised Stage-1 initialization. A direct comparison would isolate the value of these two components: how much does Mem-π's two-stage training improve over SEAM's single-stage RL? Does SEAM also learn implicit abstention (by generating empty or very short guidance on easy tasks), or does it always produce non-empty output? This experiment could be run by replacing Mem-π's training pipeline with SEAM's while holding the agent, experience bank, and benchmarks identical—a clean ablation of the training methodology.

**2. Scaling analysis of the memory policy: how do gains change with model size from 0.5B to 32B parameters?** The paper uses a single memory model size (Qwen-2.5-7B-Instruct) and argues that parametric memory has a fixed footprint advantage over retrieval banks. But does the *performance* advantage hold across scales? A scaling study using Qwen-2.5 variants at 0.5B, 1.5B, 3B, 7B, 14B, and 32B parameters would characterize the capacity-performance curve for generative memory. The key questions: (a) Is there a minimum capacity threshold below which Stage 1 distillation fails to internalize the experience bank, causing the generative policy to underperform retrieval? (b) Does the RL stage become more or less stable with model scale (larger models may be more prone to reward hacking but may also produce higher-quality initial guidance)? (c) At what scale does the Stage-1-only policy match the best retrieval baseline, making the RL stage unnecessary? The paper already shows Stage 1 alone is competitive (35.0% on WebArena vs. 34.0% for MemRL), suggesting the capacity threshold may be surprisingly low, but this needs systematic study.

**3. Multi-turn memory: train πmem to condition on the agent's trajectory within a session, not just the initial observation.** Mem-π produces a single guidance string at task start and never intervenes again. This ignores the most natural setting for persistent agent deployment: over a session of multiple tasks, the policy could observe the agent's successes and failures and adapt its guidance strategy. A multi-turn extension would allow πmem to be called at multiple points during an episode (e.g., after each action or after each sub-goal), conditioning its output on the trajectory history—what the agent tried, whether it succeeded, what errors it made. This transforms memory from a single-shot hint into a **coaching policy** that provides guidance when the agent appears stuck and stays silent when it's on track. The training would require multi-turn RL with per-step rewards (or temporal credit assignment), which is significantly harder than the single-turn setting, but the decision-content decoupled objective could be extended naturally: the decision token now governs whether to intervene *at this step*, with the same structural advantage decomposition. The key experiment would be an ablation comparing single-turn Mem-π (guidance at t=0 only) against multi-turn Mem-π (guidance at t=0, t=5, t=10, or on-demand) on long-horizon tasks where the agent's needs evolve during the episode.

**4. Stress-test abstention calibration: evaluate Mem-π on systematically perturbed tasks to measure whether abstention decisions generalize or are brittle.** The paper shows that Mem-π abstains more on easy tasks and generates more on hard tasks, with a smooth monotone relationship (Figure 4). But this analysis is on the natural task distribution. A stress-test would construct controlled perturbations: (a) **easy tasks with injected distractors**—add misleading details to the task query (irrelevant numbers, distractor conditions) to see if Mem-π still correctly abstains or gets confused and generates unnecessary guidance; (b) **hard tasks stripped of difficulty**—remove the challenging sub-conditions from hard tasks to see if Mem-π recognizes they've become easy and switches from generation to abstention; (c) **out-of-distribution tasks**—tasks from a different benchmark or environment (e.g., evaluate the WebArena-trained Mem-π on WorkArena tasks without retraining) to see whether abstention is a general behavior or overfits to the training distribution's difficulty cues. The paper's cross-agent transfer (Table 3) is a first step in this direction but tests agent generalization, not task generalization. The key risk is that Mem-π's abstention decisions rely on superficial features of the task query (e.g., presence of specific keywords or query length) rather than genuine difficulty assessment—systematic perturbations would reveal this.

**5. Combine generative memory with retrieval for tasks where retrieved hints are provably correct and generation introduces errors.** The case analysis (Appendix A.4) identifies six tasks (region 010) where RAG succeeds and Mem-π fails because retrieval preserves a verified procedural ordering that generation re-orders incorrectly. This suggests a hybrid architecture: apply the decision-content decoupled objective to learn a three-way routing decision: `[GENERATE]`, `[RETRIEVE]`, or `[ABSTAIN]`. When generation on a task type is unreliable (the policy has learned via RL that its generated guidance often re-orders procedures incorrectly), the policy could fall back to retrieving the top-1 hint from the bank. The training would require structured rollouts with three branches (abstain, generate, retrieve), and the advantage decomposition would extend to include a retrieval-vs-generation comparison analogous to the abstain-vs-generate comparison. The key experiment: does the hybrid policy match Mem-π's performance on Mem-π's win regions while recovering RAG's performance on RAG's win regions, achieving the union of their strengths? This would directly test whether generation and retrieval have genuinely complementary failure modes, or whether Mem-π's failures are fixable by better generation training (rendering the hybrid unnecessary).

**6. Investigate whether the Δ-gating mechanism prevents or merely suppresses a specific failure mode: content updates on abstain-preferable tasks that degrade previously correct guidance.** The paper shows that removing Δ-gating causes a 1.8 pp drop on WebArena (Table 2), but does not characterize *what goes wrong* without gating. Does the policy learn to produce different guidance on tasks where abstention is preferable, degrading from Stage 1's already-reasonable generation quality? Or does it fail to learn abstention entirely, continuing to generate always? A diagnostic experiment would track per-task generation quality (measured by the agent's success rate with that guidance) for the "w/o Δ-gating" variant on the subset of tasks where Mem-π learns to abstain. If quality degrades—the guidance becomes actively worse than Stage 1's baseline—this confirms the paper's hypothesis that content updates on abstain-preferable tasks are harmful, not just wasteful. If quality stays constant but the decision token never learns to abstain, the problem is purely a decision-level credit assignment failure, and a simpler fix (e.g., upweighting the decision-token gradient) might suffice without full advantage decomposition. The paper's claim that Δ-gating prevents "suboptimal generate decisions" being reinforced is plausible but not directly verified.

### Practical Applications and Downstream Use Cases

**1. Enterprise workflow automation with evolving software platforms.** In the WorkArena setting—automating tasks on the ServiceNow platform—enterprise environments face a continuous deployment challenge: the platform's UI, form fields, and menu structures are updated regularly (new releases, customizations), and agent interaction traces from the previous version become partially stale. A retrieval-based memory bank would need constant curation to remove or update deprecated hints—a manual process that doesn't scale. A parametric memory policy can be retrained periodically on fresh traces (Stage 1 alone is sufficient, requiring no environment interaction) and will naturally produce guidance that conditions on the current query rather than copying verbatim from a possibly-stale source. The paper shows that Stage 1 alone achieves 41.6% on WorkArena vs. 42.0% for the base agent (Table 1), and the full Mem-π reaches 50.3%, a +8.3 pp gain. For a deployment handling thousands of tasks daily, this gain translates directly to reduced human escalation. The 31% token reduction vs. always-on generation (Figure 5) further reduces per-task inference cost, which matters at enterprise scale where every token of context increases latency and API expense.

**2. On-device assistance for consumer applications with privacy constraints.** A key architectural feature of Mem-π is that the memory policy πmem is a separate model from the downstream agent. This enables a deployment pattern where a relatively small memory model (7B parameters, quantizable to 4-bit) runs on-device with a user's personal interaction history, while the actual task execution is handled by a cloud-based frontier agent. The memory model processes the user's query and local context, produces a concise hint (or abstains), and the hint—not the raw interaction data—is sent to the cloud agent. This provides a form of privacy-preserving context augmentation: the cloud agent never sees the user's full history, only the task-adaptive guidance extracted by the on-device memory policy. The paper's cross-agent transfer result (Table 3) supports this pattern: a memory policy trained with a Qwen agent provides substantial gains when deployed with gpt-5.4-mini (+16.0 pp on WebArena), so the on-device model can be trained with a cheap open agent and deployed with a proprietary cloud agent. The 138 average tokens per task (Figure 5) means the privacy-critical information sent to the cloud is extremely compact—roughly a sentence or two of strategic guidance—rather than kilobytes of interaction transcripts.

**3. Bootstrapping agent capabilities for new domains without expensive RL.** The paper's Stage-1-only result is surprisingly strong: supervised parametric distillation of an offline experience bank achieves 35.0% on WebArena, matching RL-trained retrieval controllers (Memory-R1 at 33.2%, MemRL at 34.0%) with **no online environment interaction**. This has immediate practical implications for teams deploying agents in new domains where online RL is infeasible due to cost, safety, or infrastructure constraints. The recipe is straightforward: (1) run the base agent on training tasks to collect trajectories, (2) extract concise hints from successful trajectories using JEF-Hinter or a similar tool, (3) supervised-fine-tune a small model to produce those hints from task contexts. The resulting generative memory policy can be deployed immediately, providing retrieval-competitive performance without the infrastructure for RL (no value model, no environment simulator, no reward signal beyond binary task success). If online RL becomes feasible later, the Stage 1 checkpoint serves as initialization for Stage 2, providing a clean upgrade path. The key caveat is that Stage 1 always generates—it lacks abstention—so practitioners accepting this tradeoff should monitor whether guidance is actively harmful on easy tasks (the paper shows region 100 cases where both RAG and Mem-π fail while the base agent succeeds, but doesn't decompose this by Stage 1 vs. full Mem-π). A lightweight abstention heuristic (e.g., thresholding on the base agent's confidence or on similarity to retrieved hints) could be layered on Stage 1 without requiring full RL.

**4. Experience compression for lifelong learning agents deployed over months or years.** One of the paper's advertised advantages of parametric memory is bounded footprint: the model size is fixed regardless of how many experiences are accumulated, unlike retrieval banks that grow linearly. For agents deployed continuously—a coding assistant that observes thousands of repository-specific interactions, a research assistant that reads hundreds of papers, a customer-support agent handling millions of tickets—this is not just a convenience but a necessity. Retrieval banks at that scale require approximate nearest-neighbor indices, staleness detection, deduplication, and sharding across machines. A parametric memory policy of fixed size (7B parameters ≈ 14GB in FP16, or ~4GB quantized) can be periodically retrained on a sliding window of recent experiences or fine-tuned incrementally. The paper doesn't demonstrate this continual-learning scenario—all training is offline on a fixed bank—but the architectural separation of πmem from the agent makes it feasible: the memory model can be updated independently without touching the (much larger) agent model. The key open question is whether catastrophic forgetting in the memory model limits how much experience can be accumulated before performance plateaus or degrades. The paper doesn't study this, but the finding that Stage 1 alone is competitive with RL-trained retrieval suggests that supervised distillation of recent experience might be sufficient for updating, avoiding the complexity of continual RL.
