# Resonance RoPE: Improving Context Length Generalization of Large Language Models

**ArXiv:** [2403.00071](https://arxiv.org/abs/2403.00071)

## 🎯 Pitch

Standard RoPE extrapolation methods fail because nearly half of a model’s positional features are *interpolated* rather than extrapolated when handling unseen long contexts. Resonance RoPE eliminates this gap by snapping each feature’s wavelength to an integer, instantly correcting faulty position recognition without any runtime overhead or retraining.

---

## 1. Executive Summary

This paper introduces **Resonance RoPE**, a modification to Rotary Position Embedding that improves length generalization in train-short-test-long (TSTL) scenarios by rounding each RoPE feature's wavelength to the nearest integer, eliminating the interpolation gap between in-distribution and out-of-distribution token positions on pre-critical dimensions. The authors also present **POSGEN**, a synthetic benchmark with three subtasks—Recursive, Chain-of-Thought, and Semi-recursive—that isolates position recognition failures from the confounding effect of increasing token generation difficulty on longer sequences. Across both small-scale Transformer experiments on POSGEN and LLM-scale evaluations with LLaMA2-Chat 7B and 13B fine-tuned on PG19, applying Resonance RoPE on top of the state-of-the-art YaRN scaling method consistently improves out-of-distribution position accuracy (e.g., raising OOD accuracy from 33.70% to 48.46% on the Semi-Recursive subtask) and reduces perplexity on GovReport and Proofpile corpora, while on real-world long-text tasks from L-Eval, **Resonance YaRN** achieves higher average closed-ended task performance than standard YaRN under equivalent fine-tuning budgets—establishing that minimizing feature interpolation on pre-critical RoPE dimensions yields complementary gains to existing extrapolation-focused scaling methods, with the strongest benefits emerging when both mechanisms are combined.

## 2. Context and Motivation

### The Core Problem: Train-Short-Test-Long (TSTL) Generalization

The fundamental problem this paper addresses is deceptively simple: **a language model trained on sequences of length L often fails catastrophically when asked to process sequences longer than L**, even when the underlying task (e.g., token prediction rules, reasoning patterns) is identical. This is the train-short-test-long (TSTL) scenario, formalized by Press et al. (2022), and it represents a critical gap between how LLMs are trained and how they are used.

Why does this matter in practice? Consider the standard LLM deployment pipeline: models like LLaMA (Touvron et al., 2023a) and LLaMA2 (Touvron et al., 2023b) are pre-trained on corpora with a fixed context window (typically 2K or 4K tokens) because training on extremely long sequences is computationally prohibitive—the quadratic cost of self-attention makes long-context pre-training exponentially more expensive. Yet real-world applications routinely demand much longer contexts: summarizing book chapters, analyzing legal documents, maintaining coherence across multi-turn conversations spanning tens of thousands of words, or reasoning over large codebases. When a model trained on 4K tokens encounters a 32K-token prompt, its performance degrades not because the underlying language is harder but because **the model has never seen token positions beyond position 4095**, and the position embedding mechanism that encodes where each token sits in the sequence produces values the model cannot interpret.

This is not merely an inconvenience. As Section 1 of the paper notes:

> "LLMs, pre-trained on shorter sequences, struggle with out-of-distribution (OOD) token positions in longer sequences, impacting their performance in real-world applications"

The economic consequences are direct: without effective length extrapolation, deploying models on long-context tasks requires either (a) retraining from scratch with a larger context window, costing millions of dollars in compute, or (b) applying inference-time hacks like sliding windows that fundamentally limit the model's ability to attend across the full document. Both are unsatisfactory. An effective, lightweight TSTL solution would allow existing pretrained models to be deployed on much longer contexts with minimal additional training, unlocking long-context applications without the prohibitive cost of retraining.

### The Positional Encoding Bottleneck

To understand *why* TSTL failures occur, we must briefly examine how Transformers represent position information. Unlike recurrent networks that process tokens sequentially and implicitly encode order, Transformers are permutation-invariant by default: without explicit position encoding, the sentence "dog bites man" and "man bites dog" produce identical representations. Position embeddings inject order information into the otherwise position-agnostic attention mechanism.

Early Transformers (Vaswani et al., 2017) used **absolute position embeddings**—a learned or sinusoidal vector added to each token's representation—which generalize poorly to unseen positions because the model has never seen the embedding vectors for positions beyond L. Relative position encoding schemes avoid this by encoding the *distance* between tokens rather than their absolute positions. Among these, **Rotary Position Embedding (RoPE)** (Su et al., 2024) has become dominant, adopted by LLaMA, LLaMA2, Mistral, and most recent open-weight LLMs, because it elegantly encodes relative position directly into the attention computation through rotation matrices (detailed in Section 3.1 of the paper).

However, RoPE introduces a subtle failure mode in TSTL. The rotary angles `mθⱼ` applied at position `m` for feature `j` depend on a **wavelength** `λⱼ = 2π / θⱼ` that determines how many tokens must pass before the feature's rotation completes a full cycle (returns to the same angle). The rotary base `b` (typically 10,000) controls these wavelengths: in LLaMA, they range from approximately 6.28 tokens (the fastest-rotating feature) to over 54,000 tokens (the slowest-rotating feature). The key insight, building on Liu et al. (2024), is that there exists a **critical dimension** `c` such that `λ_c ≥ L` and `λ_{c-1} < L`. Dimensions above `c` (longer wavelengths) have **never completed a full rotation** during training—their rotary angles `mθⱼ` for test positions `m > L` are **extrapolated** to unseen values. Dimensions below `c` (shorter wavelengths) have cycled through all possible angles during training, so their value ranges are fully covered.

Existing work, which the paper builds on and critiques, focuses almost exclusively on this **extrapolation** problem for post-critical dimensions while leaving the **interpolation** problem for pre-critical dimensions unexamined. This paper argues that both matter.

### Prior Approaches and Their Limitations

#### Where Existing RoPE Scaling Methods Succeed

Recent methods for extending RoPE-based models to longer contexts have converged on a common principle: **scale the position embedding so that OOD positions map to rotary angles within the range seen during training**. The paper identifies three main strategies in Section 2.1:

**Positional Interpolation (Chen et al., 2023):** Compresses all position indices by a scaling factor `s`, so position `n` in the extended context maps to position `n/s` in the original RoPE computation. For example, extending from 4K to 32K (`s=8`), position 32,000 becomes position 4,000—within the training range. This requires fine-tuning (typically ~1,000 steps) and works but uniformly compresses *all* RoPE features, including pre-critical dimensions whose wavelengths were already fully covered during training. Unnecessary compression of fast-rotating features reduces the model's ability to distinguish nearby positions—compressing a feature with wavelength 100 tokens to wavelength 12.5 tokens fundamentally changes its temporal semantics.

**NTK-Aware (Adjusted Base Frequency) Scaling (bloc97, 2023; Xiong et al., 2023; Liu et al., 2024):** Rather than compressing position indices, this approach scales the rotary base `b` to `s·b`, which stretches all wavelengths by a factor of `s`. The key insight is that stretching wavelengths proportionally to their original values preserves the *relative* spacing between features—analogous to how the Neural Tangent Kernel perspective suggests neural networks are sensitive to the spectral properties of their input features. NTK-aware scaling applies uniformly to all dimensions, which means pre-critical dimensions with short wavelengths get stretched unnecessarily, potentially distorting their ability to capture fine-grained positional distinctions.

**YaRN (Peng et al., 2024):** The current state-of-the-art, which the paper positions Resonance RoPE as a complement to. YaRN introduces **NTK-by-parts**: it partitions RoPE features into three regimes using two thresholds `α` and `β`. Features with very short wavelengths (`λⱼ < L/β`, typically `β=32`) are left **unchanged**—they already fully covered all rotary angles during training and are kept as-is to preserve fine-grained position discrimination. Features with very long wavelengths (`λⱼ > L/α`, typically `α=1`) are **fully scaled** by `s` to eliminate extrapolation. Features in between are **partially scaled** with a linear interpolation ramp:

```
ˆλⱼ = (1 − γⱼ)sλⱼ + γⱼλⱼ
```

where `γⱼ` transitions smoothly from 1 (no scaling) for short wavelengths to 0 (full scaling) for long wavelengths. YaRN also includes an attention entropy adjustment to prevent the softmax from becoming too peaked at longer sequence lengths. Empirically, YaRN achieves remarkable results: extending LLaMA2 to 64K context with only 400 fine-tuning steps (Peng et al., 2024).

#### Where They Fall Short: The Interpolation Gap

The paper's central critique—and the gap it fills—is that **all existing methods treat the pre-critical dimensions as a solved problem** while focusing engineering effort on the post-critical dimensions where extrapolation is obvious and measurable. Section 4 articulates this directly:

> "Existing RoPE scaling methods mainly focus on the post-critical dimensions of RoPE... In this section, we argue that reducing RoPE's feature interpolation on the pre-critical dimensions is also beneficial for better length extrapolation."

The issue, which the paper is the first to identify and address, is subtle. Consider a pre-critical feature with wavelength `λⱼ = 125.66` tokens. During training on sequences of length `L=64`, the model sees positions 0 through 63. The rotary angle at position 64 (which would be seen during TSTL testing) is `mθⱼ = 64 · (2π/125.66) ≈ 3.20` radians. The rotary angle at position 0 is `0 · (2π/125.66) = 0` radians. The difference is `3.20 - 0 = 3.20` radians—not a multiple of `2π`—so the feature vector at position 64 is *different* from any vector seen during training. This creates what the paper calls an **interpolation gap**: the model must generalize to feature values that lie *between* the discrete set of values seen during training, even though all possible *ranges* of those values were covered.

The term "interpolation" here is precise. Because the wavelength is not an integer, each complete cycle of `2π` in the rotary angle does not correspond to an integer number of tokens. After `⌊λⱼ⌋ = 125` tokens, the angle is `125 · (2π/125.66) ≈ 2π - 0.033`—almost back where it started, but not quite. This small phase shift accumulates, meaning that position 64 might produce a rotary angle that falls in a "gap" between the discrete positions 0-63 the model was trained on. Over the full OOD range (positions 64-255 in the paper's POSGEN experiments), these gaps compound.

Why would this matter? The model's attention mechanism computes dot products between query and key vectors that have been rotated by RoPE. If the rotation angle at an OOD position does not exactly match any rotation angle seen during training, the resulting query vector lies slightly outside the model's learned manifold of expected query representations. The model must **generalize** from its training distribution of rotation angles to these interpolated values. For a single feature and a single position, the gap is small. But for *all* pre-critical features (17 out of 32 RoPE features in the paper's 2-layer Transformer experiments) across *all* OOD positions, the accumulated interpolation error becomes significant—exactly what the paper's experiments demonstrate.

To make this concrete: in LLaMA2, the pre-critical dimensions for a 4K context window include features with wavelengths from approximately 6.28 tokens up to just under 4,096 tokens. After training, the model has effectively memorized the behavior of RoPE features at integer position indices within `[0, 4095]`. When asked to process position 5000, the model must extrapolate for post-critical features (long wavelengths) but must *interpolate* for pre-critical features—producing rotary angles the model has never exactly seen, even though their overall range has been covered.

### How the Paper Positions Itself

The paper positions Resonance RoPE as a **universal, zero-cost enhancement** to RoPE and any RoPE-based scaling method. The key differentiators from prior work:

**1. It targets a different aspect of the TSTL problem** (Section 4). Prior methods (including YaRN) focus on value *extrapolation*—ensuring OOD positions produce rotary angles within the range `[min_train_angle, max_train_angle]`. Resonance RoPE targets feature *interpolation*—ensuring OOD positions produce rotary angles that *exactly equal* some angle seen during training. These are complementary rather than competing goals.

The paper uses a formal framework to make this distinction: the **feature gap** metric `h_i` (Equation 8) measures the maximum discrepancy between RoPE features at in-distribution and OOD positions. For post-critical dimensions, this gap is large because the OOD positions produce completely new angle magnitudes (extrapolation). For pre-critical dimensions, the gap exists because of non-integer wavelengths causing phase misalignment (interpolation). YaRN reduces the first; Resonance RoPE eliminates the second.

**2. It exploits a structural property of RoPE that prior work overlooked.** RoPE features use a rotary base `b` (default 10,000) that produces **non-integer wavelengths** for all features. The paper's key observation is that rounding these wavelengths to the nearest integer (`˜λ_j = round(λ_j)`) forces each feature's rotation to be **periodic with a period equal to an integer number of tokens**. This means that for pre-critical features (where `˜λ_j < L`), the feature values at *any* OOD position `n` are guaranteed to exactly match the feature values at some training position `m ∈ {0, ..., L-1}`—the interpolation gap drops to **zero** (Theorem 1 in Section 4 and Appendix A).

The proof is straightforward but powerful: for a pre-critical feature with integer wavelength `˜λ_j < L`, for any test position `n`, we can find `k = ⌊n / ˜λ_j⌋` such that `m = n - k·˜λ_j` falls in `{0, ..., L-1}`, and the rotary angle at `n` equals the rotary angle at `m` modulo `2π`. The model has seen this exact feature value during training—no generalization required.

**3. It is architecture-agnostic and requires zero runtime overhead** (Section 4). Resonance RoPE is a one-time adjustment to `Θ` (the set of angular frequencies) that happens *before* training or fine-tuning. The adjusted `˜Θ` precomputes the modified rotation matrices once; during inference, the computational cost is identical to standard RoPE. This stands in contrast to dynamic scaling methods (e.g., Dynamic NTK-Aware) that recompute RoPE features based on current sequence length, incurring ongoing computational cost (which the paper notes as a limitation in its experiments—these methods were evaluated without fine-tuning "due to the high cost of frequently recomputing RoPE features").

**4. It is explicitly designed to complement, not replace, existing methods** (Section 4, Limitations). The paper is clear that Resonance RoPE does nothing for post-critical dimensions—those with wavelengths `λ_j > L` that require extrapolation. For these, YaRN or other scaling methods remain essential. The paper's experiments consistently show the *combination* of Resonance RoPE with YaRN (Resonance YaRN) outperforming either technique alone, establishing a "bag-of-tricks" framing where Resonance RoPE handles interpolation and YaRN handles extrapolation.

### Reconciling Conflicting Evidence in Position Embedding Research

The paper is also motivated by a methodological gap in how position embeddings are evaluated, which leads to **confounded experimental results** across prior work. When a model fails on a long-sequence task, is it because (a) it cannot recognize the new token positions, or (b) the underlying token prediction problem is genuinely harder at longer lengths? The paper argues that most existing benchmarks cannot distinguish these two factors (Section 5):

- **Perplexity-based evaluations** (PG19, GovReport, Proofpile): Longer texts are not merely position-extended versions of short texts—they have more complex discourse structures, longer-range dependencies, and more varied vocabulary that make next-token prediction *inherently harder*. A perplexity increase at position 10,000 could reflect either harder prediction or position embedding failure.

- **Existing synthetic tasks** (Kazemnejad et al., 2023; Liu et al., 2023): These typically define generation rules where token `x_l` depends on all previous tokens `x_0, ..., x_{l-1}`. The algorithmic complexity of computing `x_l` grows with `l` (more context to aggregate), so performance degradation on long sequences confounds position recognition with algorithmic difficulty.

This confound has practical consequences for the research community. If a newly proposed position embedding scheme shows improved perplexity on long documents, is the gain genuine (better position recognition) or an artifact of the evaluation (the model happens to be better at the harder predictive task)? Without disentangling these factors, progress on position embeddings is difficult to measure reliably.

The paper's **POSGEN** benchmark directly addresses this by constructing three synthetic tasks (Recursive, Chain-of-Thought, Semi-recursive) where the **difficulty of generating token `x_l` is identical regardless of `l`** (Section 5). This is achieved by making each new token depend on a fixed window of previous tokens (parameterized by `j` and `k`), ensuring the computational complexity of the generation rule is constant across all positions. Any failure beyond the training length `L` can then be attributed to position embedding issues rather than increasing task difficulty. This design choice makes POSGEN complementary to real-world benchmarks—it isolates the position embedding contribution to TSTL failure, enabling cleaner scientific comparisons between methods.

### The Broader Research Trajectory

This paper sits at the intersection of two active research threads: (1) the empirical effort to extend the useful context window of pretrained LLMs without retraining from scratch, and (2) the theoretical question of how Transformer position encodings behave under distribution shift. The first thread is driven by immediate practical needs (deploying LLaMA on 32K+ contexts); the second by a desire to understand the inductive biases that govern length generalization.

The paper's contribution to the first thread is clear: a simple, compatible enhancement that improves state-of-the-art RoPE scaling with no additional cost. Its contribution to the second thread is more subtle but equally important: it identifies interpolation (not just extrapolation) as a failure mode in RoPE-based position embeddings, providing a formal framework (Theorem 1) for understanding when and why this failure occurs, and a constructive solution (integer wavelength alignment) that eliminates it for a broad class of features. The POSGEN benchmark provides the controlled experimental apparatus needed to verify these theoretical claims empirically, separating the position encoding signal from the task difficulty noise that confounded prior evaluations.

The paper thus advances both the practical state of the art (better long-context performance for LLaMA-family models with YaRN) and the conceptual foundations (a more complete taxonomy of TSTL failure modes: extrapolation + interpolation, rather than extrapolation alone). The experiments in Sections 6.2 and 6.3 operationalize this dual contribution: showing that Resonance YaRN beats YaRN on real long-text benchmarks (practical advance) while the POSGEN results in Section 6.1 demonstrate that the gains come specifically from better OOD position recognition rather than other confounding factors (conceptual validation).

## 3. Technical Approach

### 3.1 Reader Orientation

This is primarily a **methods paper** that proposes a novel, zero-cost modification to Rotary Position Embedding (RoPE) designed to improve how Transformer language models handle token positions they never saw during training. The core idea is deceptively simple: **round each RoPE feature's wavelength to the nearest integer** so that, for features whose cycle length is shorter than the training context, every out-of-distribution (OOD) position produces a rotation angle that *exactly matches* some angle the model encountered during training—eliminating a previously unrecognized "interpolation gap" that forced the model to generalize to unseen feature values. Resonance RoPE is not a standalone solution but a **universal enhancement** that can be applied on top of any RoPE-based scaling method (such as YaRN) to handle the *interpolation* problem for short-wavelength features, complementing existing methods that address the *extrapolation* problem for long-wavelength features.

### 3.2 Big-Picture Architecture (Diagram in Words)

The Resonance RoPE system has four conceptual components that interact in a pipeline:

1. **Base RoPE Definition** (`Θ`): The set of angular frequencies `θⱼ` (one per pair of dimensions in the attention head) that control how quickly each feature rotates as position increases. These are derived from the standard RoPE formula `θⱼ = b^{-2j/d}` where `b` is the rotary base (default 10,000) and `d` is the head dimension. Each `θⱼ` defines a wavelength `λⱼ = 2π/θⱼ`—the number of tokens required for the feature to complete one full rotation.

2. **Resonance Transformation** (`Θ → ˜Θ`): An offline, one-time computation that rounds each wavelength `λⱼ` to the nearest integer `˜λⱼ = round(λⱼ)`, then converts back to the corresponding angular frequency `˜θⱼ = 2π/˜λⱼ`. This produces a modified set of frequencies `˜Θ` whose wavelengths are all integers. This transformation requires no training, no gradients, and no runtime computation beyond the initial precomputation of the new rotation matrices.

3. **RoPE Scaling Method** (e.g., YaRN, NTK-Aware, Positional Interpolation): An optional but recommended component that handles the *extrapolation* problem for features with wavelengths longer than the training context. This method takes `˜Θ` (not the original `Θ`) as input and applies its scaling logic (e.g., NTK-by-parts wavelength stretching) to produce a final set of frequencies `˜Θ_scaled` suitable for the target extended context length. Resonance RoPE operates *before* the scaling method in the pipeline.

4. **Attention Computation with Modified RoPE**: During both training (or fine-tuning) and inference, the standard RoPE mechanism uses `˜Θ_scaled` instead of the original `Θ` to compute query and key rotations. The computational graph—matrix multiplications, rotation operations, attention softmax—is *identical* to standard RoPE. There are zero additional FLOPs, zero extra memory accesses, and zero changes to the model architecture. The only difference is the numerical values inside the precomputed rotation matrices.

**Information flow**: Pretrained model checkpoint → Extract `Θ` from RoPE parameters → Apply Resonance transformation (`Θ → ˜Θ`) → (Optionally) Apply RoPE scaling method (`˜Θ → ˜Θ_scaled`) → Fine-tune model with modified RoPE → Deploy for inference with `˜Θ_scaled` active → Model processes arbitrarily long sequences where pre-critical OOD positions produce *exactly* seen rotation angles, eliminating interpolation gaps.

### 3.4 Detailed, Sentence-Based Technical Breakdown

#### RoPE's Mathematical Structure and the Critical Dimension Concept

RoPE (Rotary Position Embedding) is a relative position encoding scheme that injects position information into the self-attention computation by rotating the query and key vectors in a position-dependent way. Unlike absolute position embeddings that add a learned vector to each token representation, RoPE encodes the *relative* distance between tokens directly into the attention logits, which is why it has been adopted by LLaMA, LLaMA2, Mistral, and most modern open-weight LLMs.

The mechanism operates in 2-dimensional subspaces. For an attention head with dimension `d`, RoPE partitions the query and key vectors into `d/2` pairs of dimensions. Each pair `[2j : 2j+1]` is treated as a complex number or, equivalently, a 2D vector in Euclidean space. The operations are:

**Per-feature angular frequency:** For feature index `j ∈ {0, 1, ..., d/2 - 1}`, the angular frequency is:

$$\theta_j = b^{-2j/d}$$

where `b` is the rotary base (a constant, default 10,000 in the original RoPE paper and in LLaMA) and `d` is the head dimension. This specific functional form—exponential decay with frequency index `j`—creates a geometric progression of wavelengths: the 0th feature has the shortest wavelength (fastest rotation), and the `(d/2 - 1)`th feature has the longest wavelength (slowest rotation).

**What this computes:** For each feature index `j`, the angular frequency `θ_j` determines how many radians the 2D vector at that feature pair rotates per token. A larger `θ_j` means faster rotation; a smaller `θ_j` means slower rotation. As `j` increases, `2j/d` grows, so `θ_j` shrinks exponentially—the feature wavelengths grow exponentially with `j`.

**Why this form:** The exponential spacing of frequencies mimics the Fourier basis, where low frequencies capture long-range dependencies and high frequencies capture short-range positional patterns. A uniform spacing would either (a) undersample long-range relationships or (b) waste capacity on redundant high-frequency components that discriminate positions more finely than the model can usefully exploit.

**Rotation matrix for a single feature:** For position `m` and feature `j`, RoPE applies a 2×2 rotation:

$$R_{\theta_j, m} = \begin{pmatrix} \cos m\theta_j & -\sin m\theta_j \\ \sin m\theta_j & \cos m\theta_j \end{pmatrix}$$

**What this computes:** This matrix rotates a 2D vector (a pair of dimensions from the query or key) by an angle of `mθ_j` radians counterclockwise. At position `m=0`, the rotation angle is zero (identity). As `m` increases, the vector rotates continuously.

**Why this form:** The 2D rotation matrix is the only norm-preserving linear transformation that encodes angle as a function of position. Because `cos` and `sin` are periodic with period `2π`, the rotation wraps around: positions `m` and `m + 2π/θ_j` produce identical rotation matrices. This periodicity is the key property that Resonance RoPE exploits.

**Full RoPE computation:** RoPE assembles the per-feature rotation matrices into a `d × d` block-diagonal matrix:

$$R^d_{\Theta, m} = \begin{pmatrix} R_{\theta_0, m} & 0 & \cdots & 0 \\ 0 & R_{\theta_1, m} & \cdots & 0 \\ \vdots & \vdots & \ddots & \vdots \\ 0 & 0 & \cdots & R_{\theta_{d/2-1}, m} \end{pmatrix}$$

where `Θ = {θ_0, θ_1, ..., θ_{d/2-1}}` is the set of all angular frequencies. The query and key vectors are then computed as:

$$q_m = R^d_{\Theta, m} W_q x_m$$

$$k_n = R^d_{\Theta, n} W_k x_n$$

where `x_m` is the `d`-dimensional input token representation at position `m`, `W_q` and `W_k` are learned projection matrices, and `q_m`, `k_n` are the position-encoded query and key vectors.

**What this computes:** For each token at position `m`, its query vector is (1) projected by the learned weight matrix to the attention space, then (2) rotated by the block-diagonal rotation matrix `R^d_{\Theta, m}`. The rotation is position-specific: token at position `m` gets rotated differently from token at position `n`. However—and this is the critical property—when we compute the attention logit `q_m^T k_n`, the position dependence collapses to the *relative* distance:

$$q_m^T k_n = x_m^T W_q R^d_{\Theta, n-m} W_k x_n$$

The rotation depends only on `n-m`, not on `m` and `n` individually. This means the model learns functions of relative position, generalizing across absolute positions.

**Wavelength definition:** For each feature `j`, the wavelength is:

$$\lambda_j = \frac{2\pi}{\theta_j} = 2\pi b^{2j/d}$$

where `b` is the rotary base and `d` is the head dimension. The wavelength `λ_j` is the number of tokens required for the rotation matrix `R_{\theta_j, m}` to return to its starting orientation—that is, for `mθ_j` to increase by exactly `2π`.

**What this computes:** For LLaMA/LLaMA2 with `b=10000` and `d=128` (per head), the wavelengths range from `λ_0 = 2π · 10000^{0/128} = 2π ≈ 6.28` tokens (the fastest feature completes a full rotation every ~6 tokens) to `λ_{63} = 2π · 10000^{126/128} ≈ 54,410.14` tokens (the slowest feature takes over 54K tokens to complete a full rotation).

**The critical dimension:** Given a model trained on sequences of maximum length `L`, Liu et al. (2024) identified that there exists a **critical dimension index** `c` such that:

- `λ_c ≥ L` (this feature's wavelength is longer than or equal to the training length, so it has *never* completed a full rotation during training)
- `λ_{c-1} < L` (the immediately lower-indexed feature has completed at least one full rotation)

Features with `j ≥ c` are **post-critical**: their wavelengths exceed the training length, so the model has never seen what these features do after a full rotation. On OOD test positions `m > L`, the rotary angles `mθ_j` for post-critical features **extrapolate** to values the model never encountered—the angular magnitudes simply grow beyond the training range.

Features with `j < c` are **pre-critical**: their wavelengths are shorter than the training length, so the model has seen these features complete multiple full rotations. The rotary angles at any test position fall within the same `[0, 2π)` range seen during training. However—and this is the paper's central observation—**the exact angle values at OOD positions do not necessarily match any angle seen at an integer training position** because of the non-integer wavelength.

**Why non-integer wavelengths matter:** Consider a pre-critical feature with `λ_j = 125.66` tokens (a typical value for a mid-range feature in LLaMA2 with 4K context). During training up to position `L=4095`, the model sees rotation angles at positions 0, 1, 2, ..., 4095. Each position advances the angle by `θ_j = 2π/125.66 ≈ 0.050` radians. After 125 tokens, the angle is `125 × 0.050 = 6.25` radians ≈ 356 degrees—almost back to 0, but offset by ~4 degrees. After 126 tokens, the angle is ~6.30 radians ≈ 361 degrees (or 1 degree past 0). The model sees a discrete set of 4096 different angles (positions 0-4095), none of which necessarily match the angle at position 5000, which is `5000 × 0.050 = 250.0` radians = some specific angle on the unit circle. Even though the value *range* [0, 2π) is fully covered, the *specific discretization* differs.

This is the **interpolation gap**: the model must generalize from the 4096 discrete rotation angles seen during training to the slightly different discrete angles at test positions. The model has learned to process tokens whose queries/keys have been rotated by exactly the angles at training positions; at test time, it encounters queries/keys rotated by different angles and must interpolate its learned functions to these new values.

#### The Feature Gap Formalization

To make the interpolation problem precise, the paper defines a **feature gap** metric `h_i` that quantifies the maximum discrepancy between RoPE features at in-distribution (training) positions and out-of-distribution (test) positions. This metric is applied per feature dimension `i` (where `i = 0, 1, ..., d-1` indexes individual scalar dimensions, not feature pairs).

**Definition (Equation 8):**

$$h_i(\tilde{f}) = \max_{x \in \mathcal{X}} \min_{\substack{m \in \{0,\cdots,L-1\} \\ n \in \{L,\cdots,L'-1\}}} |\tilde{f}(x, m)_i - \tilde{f}(x, n)_i|$$

where:

- `\tilde{f}(x, m) = R^d_{\tilde{\Theta}, m} W x` is the position embedding function that maps an input vector `x` at position `m` to its rotated representation, using a (possibly scaled) frequency set `\tilde{\Theta}`.
- `\tilde{f}(x, m)_i` is the `i`-th scalar component of the output vector.
- `\mathcal{X} \subset \mathbb{R}^d` is the set of input feature vectors to which position embedding is applied (i.e., the query/key projections before rotation).
- `L` is the maximum training position, and `L'` is the maximum test position (with `L' > L`).
- The `\min_{m \in \{0,...,L-1\}}` picks the training position that comes *closest* to matching the OOD position's feature value.
- The `\max_{x \in \mathcal{X}}` considers the worst-case input vector (since the feature gap depends on which input is being rotated).

**What this computes:** For a single feature dimension `i`, take an OOD test position `n > L`. Compute the rotated feature value `\tilde{f}(x, n)_i`. Now search over all training positions `m \in \{0, ..., L-1\}` to find the one whose rotated feature value comes closest to the OOD value. The absolute difference between these values is the "gap" for position `n`. The minimum over `m` ensures we measure the best-case interpolation scenario—if even the closest training position produces a large gap, the feature is hard to generalize. Then take the maximum over all OOD test positions `n` (worst test position) and all input vectors `x` (worst input), giving a single number `h_i` that represents the largest feature gap the model must overcome.

**Why this specific form:** The `\min_m` captures the notion that the model can potentially "recognize" an OOD position if its feature matches *some* training position's feature, even if not the one at the same absolute offset. The `\max_x` over input vectors matters because different input vectors produce different output feature values; there might exist some input for which the interpolation gap is particularly severe. The absolute difference `|\tilde{f}(x,m)_i - \tilde{f}(x,n)_i|` is the natural metric in Euclidean space where the attention operations live.

**Relationship to existing metrics:** The paper explicitly distinguishes `h_i` from the "embedded vector distance" proposed by Xiong et al. (2023). That metric (Appendix B) compares the *original* RoPE `f(x, k)` to a *scaled* RoPE `\hat{f}(x, j)` *at the same training positions*, measuring how much the scaling operation changes the position embeddings themselves. In contrast, `h_i` compares the *same* scaled RoPE `\tilde{f}` *across different position ranges* (training positions vs. OOD test positions), measuring the generalization gap the model faces during inference. This distinction is critical: Xiong et al.'s metric evaluates offline whether a scaling method preserves the learned RoPE structure; `h_i` evaluates online whether the scaled RoPE will be recognizable to the model at new positions.

**Operational meaning:** A feature with `h_i = 0` means that for every OOD test position `n` and every possible input `x`, there exists some training position `m` whose rotated feature value exactly matches the OOD value. This feature requires zero generalization—the model has already seen, during training, every feature value it will encounter at test time. A feature with `h_i > 0` means there exist OOD positions where the model must process previously unseen feature values.

Resonance RoPE is designed to drive `h_i` to exactly zero for all pre-critical dimensions.

#### The Resonance Transformation: Algorithm and Theorem 1

The Resonance RoPE transformation is a deterministic, computation-free modification to the set of angular frequencies `Θ`. The algorithm operates independently on each RoPE feature `j`:

**Algorithm (Section 4, Algorithm 1):**

For each feature index `j ∈ {0, 1, ..., d/2 - 1}`:

1. Compute the current wavelength: `λ_j = 2π / θ_j`
2. Round to the nearest integer: `˜λ_j = round(λ_j)`
3. Convert back to angular frequency: `˜θ_j = 2π / ˜λ_j`

Then use `˜Θ = {˜θ_0, ˜θ_1, ..., ˜θ_{d/2-1}}` instead of `Θ` in all subsequent RoPE computations (Equations 2-6 in the paper).

**Concrete LLaMA2 example (illustrative):** For a feature with `θ_j = 0.05` (so `λ_j = 2π/0.05 ≈ 125.66` tokens), Resonance RoPE sets `˜λ_j = 126` (the nearest integer) and `˜θ_j = 2π/126 ≈ 0.04988`. The rotation now completes exactly one full cycle every 126 tokens—no fractional leftover. At position `m=0`, the angle is 0 radians. At position `m=126`, the angle is `126 × 0.04988 = 2π` radians—exactly back to the same orientation as `m=0`. At any position `n`, the rotation angle equals the angle at `n mod 126`.

**What this operation physically does:** It adjusts each feature's rotation speed by a tiny fractional amount so that the rotation period becomes an exact integer number of tokens. The adjustment is minimal because `round(λ_j)` is at most 0.5 tokens away from `λ_j`; for features with large wavelengths (hundreds or thousands of tokens), the relative change `|˜λ_j - λ_j| / λ_j` is well under 1%. This means the feature's temporal semantics—how it discriminates between nearby positions—is nearly unchanged. The only thing that changes is that the feature now has a **perfect periodic alignment** with integer token positions.

**Theorem 1 (Formal guarantee):** For a RoPE-equipped model with context window `L`, Resonance RoPE `\tilde{f}(x,m) = R^d_{\tilde{\Theta}, m} W x` reduces the feature gap on all pre-critical dimensions to zero. Specifically, for any input vector `x ∈ \mathcal{X}`, any OOD test position `n ∈ ℕ \ {0, ..., L-1}`, and any pre-critical dimension `i ∈ {0, ..., 2c-1}` (where `c` is the critical dimension index), there exists a training position `m ∈ {0, ..., L-1}` such that:

$$|\tilde{f}(x, m)_i - \tilde{f}(x, n)_i| = 0$$

**What this computes:** The theorem guarantees that `h_i = 0` for all pre-critical dimensions. For any OOD position, the model processes the exact same feature values it already encountered during training—no interpolation, no generalization required.

**Why this holds (proof sketch from Appendix A):** The proof relies on two properties: (1) the wavelength is now an integer `˜λ_j`, and (2) for pre-critical dimensions, `˜λ_j ≤ λ_j < L` (the integer rounding preserves, for pre-critical features, the property that the wavelength is less than or equal to the training length).

For any test position `n` and pre-critical feature `j`, we can find an integer `k = ⌊n / ˜λ_j⌋` such that the training position `m = n - k·˜λ_j` satisfies `0 ≤ m ≤ ˜λ_j - 1 < L`. Since `˜λ_j` is an integer, `n - k·˜λ_j` is an integer in the valid training range. The rotation angle at position `n` is `n˜θ_j = n(2π/˜λ_j) = (m + k˜λ_j)(2π/˜λ_j) = m(2π/˜λ_j) + k(2π) = m˜θ_j + 2πk`. Since adding `2πk` preserves trigonometric function values (cosine and sine are `2π`-periodic), the rotation matrix at position `n` is identical to the rotation matrix at position `m`: `R_{\tilde{θ_j}, n} = R_{\tilde{θ_j}, m}`.

**Why rounding to the nearest integer rather than floor or ceiling:** Rounding minimizes the absolute change in wavelength `|˜λ_j - λ_j| ≤ 0.5` for all features, which keeps the modified rotation speed as close as possible to the original. Floor or ceiling would systematically bias the adjustment: ceiling would always slow down the rotation (increase wavelength), floor would always speed it up (decrease wavelength). Rounding distributes adjustments symmetrically, preserving the overall distribution of wavelengths.

**Why not simply use integer wavelengths from the start:** The original RoPE design with base `b=10000` produces non-integer wavelengths because `b^{2j/d}` is generally not a rational number. The exponential spacing is crucial for covering the full spectrum from local to global positions efficiently; simply using consecutive integers as wavelengths would produce near-identical rotation speeds for nearby features, wasting capacity. Resonance RoPE preserves the exponential spacing structure while enforcing exact periodicity.

**Key property: the LCM argument:** The paper notes that although each individual pre-critical feature `j` repeats with period `˜λ_j`, the *combination* of all pre-critical features (the full `2c`-dimensional vector) only repeats after the least common multiple (LCM) of all `˜λ_j` values. For LLaMA2, this LCM is greater than `7 × 10^51` tokens—effectively infinite, meaning that each token position still gets a unique combination of feature values. The individual feature periods are small (allowing the theorem's guarantee), but their collective period is astronomically large (preserving the position-encoding capacity of the full embedding).

**Interaction with post-critical dimensions:** Resonance RoPE does not modify the `h_i` for post-critical dimensions (`i ≥ 2c`). For these features, `˜λ_j ≥ L`, meaning there may be no training position `m` whose rotation angle matches the OOD position `n`. The theorem's proof depends on `˜λ_j ≤ L` to guarantee `m = n - k·˜λ_j` falls in the training range. For post-critical dimensions, Resonance RoPE provides no benefit and no harm—it relies entirely on a separate RoPE scaling method (like YaRN) to handle the extrapolation.

**Computational cost:** The algorithm operates entirely offline, once, before any training or inference. It loops over `d/2` feature indices (e.g., 64 iterations for LLaMA2's 128-dimensional heads), performing three floating-point operations per iteration (`2π/θ_j`, `round`, `2π/˜λ_j`). The total cost is negligible—effectively zero compared to the billions of FLOPs in a single forward pass. During training and inference, the modified `˜Θ` is used identically to the original `Θ`: the rotation matrices `R^d_{\tilde{\Theta}, m}` are precomputed or computed on-the-fly with exactly the same cost as before. There is no additional memory, no additional parameters, and no change to the computation graph.

#### Combining Resonance RoPE with RoPE Scaling Methods

Resonance RoPE is not designed to be used alone in TSTL scenarios because it does nothing for the post-critical dimensions that suffer from extrapolation. The paper's framework positions it as a **preprocessing step** applied to `Θ` before any RoPE scaling method:

$$\Theta \xrightarrow{\text{Resonance}} \tilde{\Theta} \xrightarrow{\text{Scaling (e.g., YaRN)}} \tilde{\Theta}_{\text{scaled}}$$

**Order of operations:** Resonance RoPE must be applied *first*, rounding wavelengths to integers, because the scaling method needs to know which features are pre-critical and which are post-critical *after* the integer rounding. If scaling were applied first, the stretched wavelengths might not be integers, and Resonance RoPE applied afterward would reintroduce non-integer wavelengths from the scaled values, defeating the purpose.

**Interaction with YaRN's NTK-by-parts:** YaRN partitions features into three categories based on their wavelengths relative to the training length `L` and two hyperparameters `α=1` and `β=32`:

- **Short wavelengths** (`λ_j < L/32`): Left unchanged (`γ_j = 1`). These are features whose wavelengths are *much* shorter than the training length—they've completed many full rotations during training. YaRN's logic is that these features capture fine-grained local position information and should not be distorted by scaling.

- **Long wavelengths** (`λ_j > L/1`): Fully scaled by factor `s` (`γ_j = 0`). These are post-critical features that would extrapolate; scaling their wavelengths to `s·λ_j` ensures they remain within or near the training range after extension.

- **Intermediate wavelengths** (`L/32 ≤ λ_j ≤ L/1`): Partially scaled with a linear ramp `γ_j = (L/λ_j - α) / (β - α)`. This provides a smooth transition between the unchanged short-wavelength regime and the fully-scaled long-wavelength regime.

When combined with Resonance RoPE, the classification uses the **rounded wavelengths** `˜λ_j` instead of the original `λ_j`. This is a subtle but important point: a feature whose original wavelength was `λ_j = 128.3` (just barely above the threshold `L/32` for `L=4096`) might become `˜λ_j = 128` (now below the threshold) after rounding. This changes which YaRN regime it falls into. The paper does not analyze this interaction in depth, but the experimental results suggest that Resonance RoPE's zeroing of the interpolation gap for pre-critical features outweighs any minor misclassification of borderline features by YaRN's partitioning logic.

**Why Resonance RoPE cannot replace scaling methods:** Post-critical features have `˜λ_j ≈ λ_j ≥ L`. Rounding to an integer does not change the fact that their wavelength exceeds the training length—they still have never completed a full rotation during training. On OOD positions, the rotation angles for these features will reach values that did not occur during training. YaRN's wavelength stretching `s·˜λ_j` is essential to bring these angles back into the training range. Resonance RoPE eliminates the interpolation problem; YaRN eliminates the extrapolation problem. They are orthogonal and complementary.

**Assumption of fixed critical dimension:** The resonance transformation assumes that the critical dimension boundary `c` (features with `λ_j < L`) is stable under the `λ_j → round(λ_j)` transformation. For features with `λ_j ≈ L` (within 0.5 tokens), rounding could change their pre/post-critical classification. The paper does not analyze this edge case—it likely affects at most one feature (the one whose wavelength straddles `L`) and has negligible empirical impact.

#### The POSGEN Benchmark Design

POSGEN (POSition GENeralization) is a synthetic benchmark designed to isolate position recognition failures from task difficulty confounds in TSTL evaluation. The core insight is that on most existing long-context benchmarks, generating token `x_l` becomes inherently harder as `l` increases (more context to aggregate, more complex dependencies), making it impossible to determine whether a model's failure at long lengths is due to position embedding issues or increasing task difficulty.

POSGEN consists of three subtasks that share a common structure but differ in their **token dependency patterns**, simulating different types of reasoning. Each subtask is defined by:

- A **fixed function** `h : V^{j+k} → V` that computes the next token from `j+k` previous tokens, where `V` is the model's vocabulary and `j`, `k` are difficulty-controlling constants.
- A **generation rule** that specifies *which* `j+k` previous tokens are used as input to `h` at each position.
- A **seed sequence** of the first `j+k` tokens, from which all subsequent tokens are deterministically generated.

The paper instantiates all three subtasks with a **modular addition** function: `h(x_0, x_1, x_2, x_3) = (Σ_{i=0}^{3} x_i) mod 17` with vocabulary `V = {0, 1, ..., 16}`, and difficulty parameters `j=1, k=3`. This specific choice is motivated by Nanda et al. (2023), who proved that a one-layer Transformer can learn modular addition, ensuring the task is solvable by small models.

**Why modular addition:** It's a well-studied algorithmic task with known mechanistic solutions in Transformers, making it a clean testbed. The `mod 17` choice gives 17 output classes—small enough to learn reliably with 10,000 training examples, large enough that random guessing (1/17 ≈ 5.9% accuracy) does not dominate the signal.

The three subtasks are:

**1. Recursive:** Tokens depend only on the immediately preceding `j+k = 4` tokens:

$$x_l = h(x_{l-4}, x_{l-3}, x_{l-2}, x_{l-1}) \quad \text{for } l \geq 4$$

This simulates the dependency pattern of generating a Fibonacci-style sequence, where each new element is a fixed function of a sliding window of recent elements. The token generation difficulty is **constant** across all positions because the function `h` always sees exactly 4 inputs, and those inputs are always the 4 most recent tokens—no context grows, no aggregation becomes more complex.

**2. Chain-of-Thought (CoT):** Tokens depend on `k=3` neighboring tokens (simulating the most recent reasoning step) and `j=1` token from the very beginning (simulating the original question):

$$x_l = h(x_0, x_{l-3}, x_{l-2}, x_{l-1}) \quad \text{for } l \geq 4$$

This simulates CoT reasoning where each reasoning step builds on the immediately preceding steps but must also attend back to the original problem statement. The dependency pattern is **non-local** (position 0 is far from position `l` for large `l`), but the *complexity* of the function `h` is identical across all positions—it always takes 4 inputs, even if one of those inputs is far away.

**3. Semi-Recursive:** Tokens depend on `k=3` neighboring tokens and `j=1` token at a **variable distance** that depends on the current position:

$$x_l = h(x_{\lfloor l/2 \rfloor - 1}, x_{l-3}, x_{l-2}, x_{l-1}) \quad \text{for } l \geq 4$$

The `\lfloor (l - (j+k)) / 2 \rfloor` expression (simplified in the paper to `\lfloor l/2 \rfloor - 1` for `j=1, k=3`) means that as `l` grows, the non-local input comes from progressively further back in the sequence—position `l/2` rather than a fixed offset. This simulates the last-letter concatenation task (Zhou et al., 2023) where the model must retrieve information from words at varying distances. The dependency pattern changes with position (the non-local offset grows), but the *computational complexity* of evaluating `h` remains constant.

**Why three subtasks:** Each exercises a different attention pattern: Recursive requires purely local attention (easy for any position embedding), CoT requires one long-range attention to a fixed position, and Semi-Recursive requires long-range attention to positions at varying distances. If a position embedding scheme fails on CoT but not Recursive, the failure is specifically in attending to distant but fixed positions—a find-grained diagnosis not possible with perplexity benchmarks.

**Training and evaluation protocol:**

- **Training set:** 10,000 sequences of length `L = 64`. Each sequence is generated by sampling the first `j+k=4` seed tokens (with non-overlapping seeds across all sequences in the dataset) and then deterministically applying the generation rule for 60 more steps.
- **Validation set:** 1,000 sequences of length `L' = 256`, using seed tokens that do not overlap with training seeds.
- **Test set:** 1,000 sequences of length `L' = 256`, using seed tokens that do not overlap with training or validation seeds.
- **Training objective:** Standard language modeling cross-entropy loss on all positions (the model predicts each `x_l` given `{x_0, ..., x_{l-1}}`).
- **Evaluation metric:** OOD Accuracy (OOD Acc) computed on positions `l ∈ {64, 65, ..., 255}`—positions the model was never trained on. Only these positions contribute to the metric. The model must correctly predict `x_l` given the true prefix; it does not auto-regressively generate the entire sequence (teacher forcing evaluation).
- **Model:** 2-layer Transformer with T5-Small configuration per layer (Raffel et al., 2020): 6 attention heads, 64 dimensions per head (`d=64`), feed-forward dimension 2048. This means each head has `d/2 = 32` RoPE features.
- **Training hyperparameters:** AdamW optimizer (Loshchilov and Hutter, 2019), learning rate `2 × 10^{-4}`, weight decay `1 × 10^{-2}`, batch size 128, 150 training epochs. All hyperparameters were tuned to maximize YaRN's validation performance on the Semi-Recursive subtask.
- **Hardware:** Single NVIDIA V100 32GB GPU per experiment.
- **Seeds:** Results averaged over 5 random seeds with different training/validation/test splits.

**Critical design choice—non-overlapping seeds:** The first 4 tokens of each sequence are unique and do not overlap across any sequences in the dataset. This ensures the model cannot memorize specific seed patterns and must learn the actual generation rule `h`. If seeds overlapped, the model could potentially succeed by recognizing the seed and looking up the subsequent tokens from memory, rather than learning the algorithmic rule.

**Why constant difficulty enables clean TSTL diagnosis:** Since the function `h` is the same at all positions and always takes exactly `j+k` inputs, the algorithmic complexity of predicting `x_l` is identical regardless of `l`. If the model achieves, say, 95% accuracy on position 63 (the last training position) but 60% on position 64 (the first OOD position), the drop cannot be explained by increasing task difficulty—something about position 64 itself causes the failure. This isolates the position embedding as the culprit, enabling clean comparisons between RoPE variants.

**The critical dimension in POSGEN's Transformer:** With `L=64` training length, the 32 RoPE features (per head, `d=64`) have wavelengths ranging from `λ_0 = 2π ≈ 6.28` to `λ_31 = 2π · 10000^{62/64} ≈ 18,205`. The critical dimension is where `λ_c ≥ 64`. With `b=10000`, we can estimate: `λ_j = 2π · 10000^{2j/64} = 2π · 10000^{j/32}`. Setting `λ_j = 64` gives `j/32 = log_{10000}(64/(2π)) ≈ log_{10000}(10.19) ≈ 0.252`, so `j ≈ 8`. Features `j=0` through `j=7` are pre-critical (wavelengths ~6-55 tokens, all < 64); features `j=8` through `j=31` are post-critical (wavelengths ~72-18,205 tokens). The paper states that the first 17 features are pre-critical (Section 6.1.1: "each head has 32 RoPE features, out of which the first 17 are pre-critical dimensions with a wavelength less than the maximum training length"). The discrepancy from our estimate arises because they define the critical dimension at exactly `λ_c ≥ L` with `λ_{c-1} < L`; with `L=64`, `λ_16` might be just under 64 and `λ_17` just over, giving 17 pre-critical features (`j=0` through `j=16`). Regardless, Resonance RoPE affects roughly half the RoPE features—a substantial fraction.

**Scaled version for YaRN evaluation:** When evaluating YaRN or Resonance YaRN, the models are trained with the scaling already applied (scaling factor `s=4` for the POSGEN experiments, matching the TSTL factor `L'/L = 256/64 = 4`). This means the model sees YaRN-scaled or Resonance-YaRN-scaled position embeddings during training on short sequences, and the same scaling naturally handles the extension to 256 positions during testing. This contrasts with the LLM experiments where scaling is applied *after* pretraining and the model is fine-tuned to adapt.

#### LLM-Scale Fine-Tuning Setup

The LLM experiments apply Resonance RoPE in combination with YaRN to LLaMA2-Chat 7B and 13B (Touvron et al., 2023b), then fine-tune on long-text data and evaluate on perplexity and downstream tasks.

**Base models:** LLaMA2-Chat 7B (32 attention heads, 128 dimensions per head, `d=128`) and LLaMA2-Chat 13B (40 attention heads, 128 dimensions per head). Both were originally pretrained with RoPE using rotary base `b=10000` on sequences of length `L=4096` (4K tokens).

**Target context lengths:** 32K tokens for the 7B model (scaling factor `s=8`) and 16K tokens for the 13B model (scaling factor `s=4`). These are chosen to be substantial extensions (4× and 8× the pretraining context) while remaining within the range where YaRN has been shown effective.

**Position embedding configurations tested (Section 6.2.1):**

1. **NTK-Aware Scaling (no fine-tuning):** The rotary base is scaled from `b=10000` to `b' = s·b` (80,000 for 7B, 40,000 for 13B). This stretches all wavelengths by factor `s`. Evaluated without fine-tuning following bloc97 (2023). The paper notes this method was applied by replacing the original RoPE parameters and testing directly.

2. **Dynamic NTK-Aware Scaling (no fine-tuning):** The scaling factor is computed dynamically as `s = L_c / L` where `L_c` is the current sequence length and `L` is the original context window (4096). This means shorter sequences within the test set receive less aggressive scaling. Evaluated without fine-tuning; the paper explicitly notes "due to the high cost of frequently recomputing RoPE features, we evaluated its performance without fine-tuning."

3. **YaRN (with fine-tuning):** Full YaRN with `α=1` and `β=32` (the recommended values for LLaMA family), applied with scaling factor `s=8` (7B) or `s=4` (13B). The model is fine-tuned after replacing the original RoPE with the YaRN-scaled version.

4. **Resonance YaRN (with fine-tuning):** Resonance RoPE applied first (`Θ → ˜Θ`), then YaRN applied to `˜Θ` with the same `α=1`, `β=32`, and scaling factor as standard YaRN. The model is fine-tuned identically to the YaRN condition.

**Fine-tuning data:** The training split of PG19 (Rae et al., 2020), a dataset of full-length books published before 1919. PG19 is chosen because it contains naturally long documents (many exceeding 100K tokens), providing contiguous long-context training data without artificial concatenation of short texts.

**Fine-tuning details:**

- **Total training tokens:** Approximately 100M tokens across all settings. The paper controls for total tokens rather than number of steps to ensure fair comparison.
- **Optimizer:** AdamW (Loshchilov and Hutter, 2019) with learning rate `2 × 10^{-5}` and weight decay `1 × 10^{-2}`.
- **Batch size:** 1 per GPU (with gradient accumulation to maintain effective batch size).
- **Learning rate schedule:** Warmup for the first 5% of total training steps, followed by linear decay.
- **Precision:** BF16 (bfloat16) mixed precision.
- **Infrastructure:** FlashAttention 2 (Dao, 2023) for efficient attention computation, DeepSpeed ZeRO-3 Offload (Ren et al., 2021) for memory-efficient distributed training.
- **Hardware:** 4 NVIDIA A100 40GB GPUs per experiment.

**Two fine-tuning strategies (Section 6.2.3):**

1. **Long-sequence fine-tuning:** The model is fine-tuned directly on the target sequence length (32,768 for 7B, 16,384 for 13B) for fewer steps:
   - 7B: 50 optimization steps on 32K-length sequences
   - 13B: 100 optimization steps on 16K-length sequences
   
   This exposes the model to the full target length immediately, but each step is expensive (quadratic in sequence length).

2. **Short-sequence fine-tuning:** The model is fine-tuned on the original pretraining sequence length (4,096) for more steps:
   - Both 7B and 13B: 400 optimization steps on 4K-length sequences
   
   This is computationally cheaper per step and exposes the model to more diverse training examples (many 4K chunks vs. fewer 32K documents), but the model never sees long sequences during fine-tuning. The RoPE scaling ensures that even though the model only processes 4K tokens during fine-tuning, the position embeddings are already configured for 32K/16K—the fine-tuning just adapts the model weights to work with the scaled embeddings.

**Total token count control:** In all fine-tuning settings, the total number of tokens processed is approximately 100M. For long-sequence fine-tuning (50 steps of 32K length with effective batch size derived from gradient accumulation), 50 × 32,768 × batch_size_tokens = 100M. For short-sequence fine-tuning (400 steps of 4K length), 400 × 4,096 × batch_size_tokens = 100M. This controls for the total training signal, isolating the effect of the position embedding scaling from the effect of seeing more or fewer tokens.

**Why two fine-tuning strategies:** They test different hypotheses about what's needed for length extrapolation. If the model needs to *see* long sequences to learn how to use the scaled position embeddings, long-sequence fine-tuning should outperform. If the scaled position embeddings are sufficient and the model just needs to adapt its attention patterns, short-sequence fine-tuning should be competitive or better (more training diversity). The experiments in Table 2 test both, and the short-sequence strategy generally performs better, suggesting that adaptation to the scaled embeddings matters more than exposure to long sequences per se.

**Evaluation datasets:**

- **Perplexity:** GovReport (Huang et al., 2021) and Proofpile (Azerbayev, 2022), 50 randomly selected samples each. Perplexity is measured on text fragments of gradually increasing length to produce the curves in Figure 4.

- **Downstream tasks:** L-Eval (An et al., 2023)'s closed-ended task suite, covering Coursera (lecture transcripts), GSM (math word problems), QuALITY (multiple-choice QA on long documents), TOEFL (English proficiency essays), CodeU (code understanding), and SFiction (science fiction stories). The paper reports per-task accuracy and aggregate average.

**Resonance RoPE's effect on the critical dimension in LLaMA2:** For LLaMA2-7B with `d=128` per head and `L=4096`, the critical dimension `c` satisfies `λ_c ≥ 4096` and `λ_{c-1} < 4096`. Using `λ_j = 2π · 10000^{2j/128}`: solving `λ_j = 4096` gives `j = (128/2) · log_{10000}(4096/(2π)) ≈ 64 · log_{10000}(652.5) ≈ 64 · 0.687 ≈ 44.0`. So the critical dimension is around `c ≈ 44-45`. Features `j=0` through `j≈43` are pre-critical (wavelengths ~6 to ~3600 tokens), and features `j≈44` through `j=63` are post-critical (wavelengths ~4200 to ~54,000 tokens). Resonance RoPE modifies all 64 RoPE features but provides its zero-gap guarantee (Theorem 1) for the 44 pre-critical features; the 20 post-critical features still require YaRN's extrapolation handling.

This is a substantial fraction—nearly 70% of RoPE features are pre-critical and benefit directly from Resonance RoPE's interpolation elimination. The paper's results suggest that this translates to meaningful empirical gains in both synthetic and real-world evaluations.

## 4. Key Insights and Innovations

### Innovation 1: Identifying Feature Interpolation as a Previously Overlooked Failure Mode in RoPE-Based Length Generalization

The field's understanding of why RoPE-based models fail in train-short-test-long (TSTL) scenarios has been dominated by a single concept: **value extrapolation** on post-critical dimensions. The intellectual framework, crystallized by Liu et al. (2024)'s critical dimension analysis, partitioned RoPE features into two categories—those whose wavelengths exceed the training length (post-critical, suffering from extrapolation to unseen rotary angle magnitudes) and those whose wavelengths are shorter (pre-critical, assumed safe because the full angular range [0, 2π) has been covered during training). Every major RoPE scaling method—Positional Interpolation (Chen et al., 2023), NTK-Aware scaling (bloc97, 2023; Xiong et al., 2023), and YaRN (Peng et al., 2024)—operates under this assumption: solve the extrapolation problem for long-wavelength features, and leave the short-wavelength features alone (or minimally perturb them).

This paper's most fundamental conceptual contribution is to **identify a second, orthogonal failure mode that the extrapolation framework misses entirely**: feature interpolation on pre-critical dimensions. The distinction hinges on a subtle but crucial geometric fact: covering the *range* of possible rotary angles is not the same as the model having seen the *exact discrete set* of angles that will appear at OOD positions. Because RoPE's standard wavelength formula `λ_j = 2π·b^{2j/d}` produces non-integer wavelengths for all features, a pre-critical feature with, say, `λ_j = 125.66` tokens completes a full rotation at position 125 (angle ≈ 2π - 0.033 radians, *almost* but not quite back to where it started) and position 126 (angle ≈ 2π + 0.017 radians, slightly past the starting angle). The discrete set of rotation angles at training positions {0, 1, ..., L-1} is therefore a specific, non-periodic sampling of the unit circle. An OOD test position `n > L` will generally produce an angle that falls *between* two training angles—the model must interpolate its learned query-key rotation functions to this unseen value.

This is not merely a rephrasing of the extrapolation problem in different terms. Extrapolation involves processing angles of *unprecedented magnitude* (e.g., `mθ_j > 2π` when training only covered `m ≤ L` with `λ_j > L`). Interpolation involves processing angles within the *familiar magnitude range* but at *unprecedented discrete values*. Both require generalization, but they are mathematically and mechanistically distinct failure modes. The paper formalizes this distinction through the **feature gap** metric `h_i` (Equation 8), which measures the minimum distance between the RoPE feature value at any OOD position and the set of feature values at all training positions. A non-zero `h_i` on a pre-critical dimension quantifies the interpolation burden the model faces—a burden that all prior methods implicitly accepted as unavoidable or irrelevant.

The significance of this identification goes beyond the specific solution (Resonance RoPE). It **completes the taxonomy of TSTL failure modes in RoPE**: there is not one problem (extrapolation) but two (extrapolation + interpolation), and they require different solutions. This explains subtle patterns in prior results—why YaRN, which handles extrapolation exceptionally well, still shows performance degradation on long sequences that cannot be attributed to post-critical features alone. The POSGEN experiments in Table 1 make this concrete: on the Semi-Recursive subtask, standard RoPE achieves only 17.96% OOD accuracy, while YaRN (which addresses extrapolation) reaches 33.70%. But Resonance RoPE *alone* (without any YaRN scaling) reaches 29.78% OOD accuracy on the same task—nearly matching YaRN's performance by addressing *only* the interpolation problem. The combination (Resonance YaRN) reaches 48.46%, demonstrating that the two failure modes are additive and both must be addressed for optimal performance.

This insight is fundamental rather than incremental: it changes what researchers should look for when diagnosing TSTL failures, and it opens a new axis for position embedding design that was previously invisible under the extrapolation-only framework.

### Innovation 2: The Resonance Principle — Exact Periodicity as a Zero-Cost Solution to the Interpolation Gap

If Innovation 1 diagnoses the problem, Innovation 2 provides a solution whose elegance lies in exploiting a structural property of RoPE that was always present but never leveraged: **by forcing each RoPE feature's wavelength to be an integer, the feature becomes exactly periodic with a period equal to that integer, guaranteeing that every OOD position produces a rotation angle identical to some training position**. The paper calls this the "resonance" principle—each feature "resonates" with a specific token span length, completing an exact integer number of full rotations over that span and thus returning to precisely the same orientation.

What makes this conceptually distinctive is not the mathematical operation (rounding wavelengths is trivial to implement, as Algorithm 1 shows) but the **recognition that exact periodicity is both sufficient and essentially cost-free** for eliminating the interpolation gap. Prior work either (a) ignored pre-critical dimensions entirely, assuming the range coverage was sufficient, or (b) actively avoided modifying pre-critical dimensions out of concern that any perturbation would degrade their fine-grained position discrimination. YaRN's NTK-by-parts strategy, for instance, explicitly leaves short-wavelength features unchanged (`γ_j = 1` for `λ_j < L/β`) to preserve local positional resolution. The implicit assumption is that modifying these features—even slightly—would be harmful.

Resonance RoPE challenges this assumption with a **constructive counterexample**: modifying pre-critical features by rounding their wavelengths to integers (a fractional change of at most 0.5/λ_j, well under 1% for most features) not only doesn't harm performance but **substantially improves it**, precisely because the benefit of eliminating the interpolation gap outweighs any minor distortion of the original wavelength distribution. The validation loss curves in Figure 3 provide direct evidence: across all three POSGEN subtasks, Resonance RoPE achieves lower validation loss than standard RoPE throughout training, and its loss trajectory remains systematically lower. This is not a tradeoff—it's a Pareto improvement: better OOD generalization without sacrificing in-distribution performance.

The formal guarantee provided by Theorem 1 (proved in Appendix A) elevates this from an empirical trick to a **principled design choice**. The theorem establishes that for all pre-critical dimensions (where `˜λ_j < L` after rounding), the feature gap `h_i` drops to exactly zero—not approximately, not asymptotically, but identically zero for every OOD position and every input vector. This is a stronger guarantee than any existing RoPE scaling method provides. YaRN reduces extrapolation but does not eliminate it (post-critical features still see some new angle values after scaling, just within a bounded range). Positional Interpolation compresses all positions into the training range but still produces new fractional position indices that the model must interpolate between. Resonance RoPE, on the pre-critical dimensions it affects, achieves **perfect alignment** between training and testing feature distributions.

The paper's handling of the collective periodicity concern demonstrates intellectual rigor: while each individual feature now has a small integer period (e.g., 126 tokens), the **combination** of all pre-critical features has an astronomically large least common multiple (exceeding 7×10^51 for LLaMA2), meaning that the full position embedding vector remains unique for every position within any practical context length. The resonance principle improves local alignment without sacrificing global discriminability—a non-obvious property that the paper explicitly verifies.

This innovation is **fundamental in its framing** (exact periodicity as a design principle for position embeddings) but **incremental in its implementation** (a one-line rounding operation). The implementation being simple does not diminish the insight—in fact, the best conceptual innovations often make obvious-in-retrospect observations that the field systematically overlooked. The fact that no prior work considered integer wavelength alignment, despite the wavelength formula being a direct consequence of RoPE's definition, suggests that the field's extrapolation-focused framework created a blind spot around pre-critical dimension behavior.

### Innovation 3: POSGEN — A Diagnostic Benchmark That Disentangles Position Recognition from Task Difficulty

The paper's third major contribution is methodological rather than algorithmic: **POSGEN (POSition GENeralization), a synthetic benchmark that isolates whether TSTL failures are caused by position embedding issues or by the increasing difficulty of token prediction on longer sequences**. This is not merely another evaluation dataset—it is a **diagnostic instrument** designed to answer a specific scientific question that existing benchmarks cannot address.

The problem with existing evaluations is fundamental and pervasive. Perplexity-based benchmarks (PG19, GovReport, Proofpile) measure language modeling quality on long documents, but longer documents are not just position-extended versions of short ones—they have more complex discourse structures, longer-range syntactic dependencies, and greater lexical diversity. When perplexity degrades at position 10,000, it is impossible to determine whether the model (a) cannot recognize position 10,000 due to OOD position embeddings, or (b) finds predicting token 10,000 genuinely harder than predicting token 1,000 because the linguistic context is more complex. Similarly, existing synthetic TSTL tasks (Kazemnejad et al., 2023; Liu et al., 2023) typically define generation rules where each new token depends on all previous tokens, making the computational complexity of prediction grow with sequence length—again confounding position recognition with task difficulty.

POSGEN's design solves this by enforcing a **constant-difficulty invariant**: on all three subtasks (Recursive, Chain-of-Thought, Semi-Recursive), each token `x_l` is computed by applying the *same* function `h` to a *fixed-size* window of `j+k` previous tokens, regardless of `l`. The function `h` (instantiated as modular addition modulo 17 in the paper's experiments) has identical computational complexity at position 64 and position 255. The dependency patterns differ across subtasks (local-only for Recursive, one long-range fixed dependency for CoT, variable-distance long-range dependency for Semi-Recursive), but within each subtask, the algorithmic difficulty is position-invariant. This means any drop in accuracy between the last training position (63) and the first OOD position (64) can be **unambiguously attributed to position embedding failure** rather than increasing task difficulty.

What elevates POSGEN beyond a typical benchmark contribution is its **decompositional power**. By varying the dependency pattern (local vs. long-range-fixed vs. long-range-variable) while holding difficulty constant, POSGEN enables fine-grained diagnosis of *which types of attention patterns* are most vulnerable to position embedding failures. The results in Table 1 demonstrate this diagnostic value: on the Recursive subtask (purely local attention), Resonance RoPE actually *underperforms* standard RoPE (62.64% vs. 65.29% OOD accuracy), but on the Semi-Recursive subtask (which requires long-range attention to varying positions), Resonance RoPE dramatically *outperforms* standard RoPE (29.78% vs. 17.96%). This asymmetry reveals that the interpolation gap on pre-critical dimensions predominantly affects tasks requiring long-range attention—the local attention patterns in the Recursive task can tolerate interpolation better because nearby positions have similar rotation angles regardless of exact periodicity, while distant-position attention is more sensitive to whether the query and key vectors at those positions land on familiar or unfamiliar rotations.

The contrast with prior synthetic benchmarks is instructive. Liu et al. (2023) used automaton-based sequence generation tasks for TSTL evaluation, but their automata define state transitions that depend on cumulative sequence history—the state space grows with sequence length. Kazemnejad et al. (2023) used algorithmic tasks with similar scaling complexity. Both are valuable for testing length generalization broadly, but neither can isolate the position embedding's contribution from the model's ability to handle increasingly complex state. POSGEN is the first benchmark explicitly designed to factor out task complexity, and as such it fills a methodological gap that has made position embedding research difficult to evaluate rigorously.

This innovation is **fundamental methodologically**: it provides a tool that the field previously lacked, enabling cleaner experiments and sharper conclusions about position embedding quality. The paper's own experiments demonstrate its utility—the POSGEN results (Table 1 and Figure 3) provide the cleanest evidence that Resonance RoPE specifically improves OOD position recognition, because POSGEN eliminates alternative explanations for the performance gains.

### Innovation 4: Establishing That Interpolation and Extrapolation Are Complementary, Additive Failure Modes — And That Addressing Both Is Necessary for Optimal Performance

While Innovations 1 and 2 respectively diagnose and solve the interpolation problem, and Innovation 3 provides the evaluation apparatus to measure it cleanly, the paper's fourth contribution is the **empirical demonstration that interpolation and extrapolation are independent, additive bottlenecks** whose combined resolution yields performance unattainable by addressing either alone. This is not a foregone conclusion—it was entirely possible that fixing the interpolation gap would provide negligible additional benefit once extrapolation was handled (i.e., that extrapolation was the dominant bottleneck and interpolation a minor curiosity). The experiments decisively reject this hypothesis.

The key evidence comes from the POSGEN results in Table 1, which can be read as a **2×2 factorial experiment**: with/without Resonance RoPE (addresses interpolation) × with/without YaRN (addresses extrapolation):

- **Neither** (standard RoPE): 17.96% OOD accuracy on Semi-Recursive
- **Interpolation only** (Resonance RoPE): 29.78% (+11.82 percentage points)
- **Extrapolation only** (YaRN, s=4): 33.70% (+15.74 pp)
- **Both** (Resonance YaRN): 48.46% (+30.50 pp)

The gain from combining both (30.50 pp over baseline) substantially exceeds the sum of the individual gains (11.82 + 15.74 = 27.56 pp), suggesting a **super-additive interaction**: fixing interpolation makes extrapolation handling more effective, and vice versa. On the CoT subtask, the pattern is even clearer: standard RoPE achieves 69.56%, Resonance RoPE 75.25%, YaRN 98.71%, and Resonance YaRN 99.58%—nearly perfect OOD accuracy.

This additivity result carries significant implications for how the field should approach position embedding design. It establishes that **there is no single "right" solution to TSTL**—instead, there are multiple independent failure modes, each requiring a targeted intervention, and the best systems will combine complementary techniques. This "bag-of-tricks" framing is familiar from other areas of deep learning (e.g., the combination of BatchNorm, residual connections, and data augmentation each addressing distinct training difficulties), but it had not been articulated for position embeddings because the failure modes themselves had not been cleanly separated.

The LLM-scale experiments in Section 6.2 confirm that the additivity transfers to realistic settings. Across both LLaMA2-Chat 7B and 13B, under both fine-tuning strategies (long-sequence and short-sequence), and across both upstream perplexity (Figure 4) and downstream task performance (Table 2), **Resonance YaRN consistently outperforms standard YaRN** with identical hyperparameters and training budgets. The average performance on L-Eval closed-ended tasks illustrates the pattern: for LLaMA2-Chat 7B with short-sequence fine-tuning (FT@4K, 400 epochs), standard YaRN achieves 36.61% average accuracy, while Resonance YaRN achieves 37.58%—a modest but consistent gain of nearly one percentage point that cannot be attributed to additional training compute, architectural changes, or hyperparameter tuning, since all these are held constant. The per-task breakdowns show that Resonance YaRN's improvements are distributed across diverse domains (Coursera, GSM, QuALITY, SFiction), suggesting the benefit is not task-specific but stems from genuinely better position generalization.

The perplexity curves in Figure 4 provide complementary evidence: Resonance YaRN achieves lower perplexity than standard YaRN at every context length from 4K to 32K on both GovReport and Proofpile. The gap is stable rather than widening with context length, suggesting that Resonance RoPE provides a uniform improvement in position embedding quality rather than a benefit that only manifests at extreme lengths.

What makes this innovation **fundamental** rather than merely empirical reporting is that it establishes a **design principle**: future position embedding research should analyze and address extrapolation and interpolation as separate sub-problems, and methods that target only one should be understood as partial solutions. This principle has predictive power—it suggests that any future improvement to extrapolation handling (a better post-critical scaling method than YaRN) could be combined with Resonance RoPE for additive gains, and any future improvement to interpolation handling could be combined with YaRN. The paper's framework thus provides a **roadmap for incremental progress** rather than a one-off solution, which is the hallmark of a genuinely useful conceptual advance.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The paper uses three distinct evaluation settings. For synthetic experiments: POSGEN, a custom benchmark with 10,000 training sequences of length 64, 1,000 validation sequences of length 256, and 1,000 test sequences of length 256, instantiated as modular addition modulo 17 with non-overlapping seed tokens across all splits. For LLM perplexity: 50 randomly selected samples each from GovReport (Huang et al., 2021) and Proofpile (Azerbayev, 2022). For downstream tasks: L-Eval (An et al., 2023)'s closed-ended task suite, spanning Coursera, GSM, QuALITY, TOEFL, CodeU, and SFiction.

- **Base model(s).** For synthetic experiments: a 2-layer Transformer with T5-Small configuration per layer (Raffel et al., 2020)—6 attention heads, 64 dimensions per head, feed-forward dimension 2048. For LLM experiments: LLaMA2-Chat 7B (32 attention heads, 128 dimensions per head) and LLaMA2-Chat 13B (40 attention heads, 128 dimensions per head), both originally pretrained with RoPE (rotary base 10,000) on 4,096-token sequences. The 2-layer Transformer is chosen because modular addition is provably learnable by a one-layer Transformer (Nanda et al., 2023) and small models enable rapid iteration; the LLaMA2 models are chosen as representative state-of-the-art open-weight LLMs.

- **Metrics.** Three primary metrics are used: **(1) OOD Accuracy (OOD Acc)** on POSGEN—the fraction of tokens at positions 64–255 (unseen during training) correctly predicted via teacher forcing, measuring position recognition in isolation. **(2) Perplexity (PPL)** on GovReport and Proofpile—standard language modeling perplexity computed on text fragments of gradually increasing length, with lower values indicating better length generalization. **(3) Downstream task accuracy** on L-Eval's closed-ended tasks—the fraction of questions answered correctly per task, with an aggregate average across all tasks.

- **Baselines.** For synthetic experiments: **(1) Standard RoPE** (Su et al., 2024) with rotary base 10,000 and no scaling. **(2) YaRN** (Peng et al., 2024) with scaling factor s=4, α=1, β=32. For LLM experiments: **(1) NTK-Aware Scaling** (bloc97, 2023; Xiong et al., 2023; Liu et al., 2024)—scaling the rotary base to s·b without fine-tuning. **(2) Dynamic NTK-Aware Scaling** (Peng et al., 2024; Rozière et al., 2023)—computing the scaling factor dynamically as L_c/L without fine-tuning. **(3) YaRN** (Peng et al., 2024) with α=1, β=32, full attention entropy adjustment, fine-tuned on PG19. All Resonance RoPE variants (Resonance RoPE, Resonance YaRN) are compared against their non-Resonance counterparts at identical hyperparameter settings.

- **Generation budget / compute accounting.** For synthetic experiments: all models are trained for 150 epochs with identical architecture, batch size (128), and optimizer settings; compute is implicitly identical since the only difference is the precomputed Θ vs. ˜Θ rotation matrices. For LLM experiments: the paper controls total training tokens to approximately 100M across all fine-tuning settings (Section 6.2.1). Fine-tuning for long-sequence configurations uses 50 steps at 32K length (7B) or 100 steps at 16K length (13B); short-sequence configurations use 400 steps at 4K length for both model sizes. All other hyperparameters (learning rate 2×10⁻⁵, weight decay 1×10⁻², AdamW optimizer, BF16 precision, FlashAttention 2, DeepSpeed ZeRO-3) are held constant. Resonance RoPE itself introduces zero additional FLOPs—the ˜Θ rotation matrices are precomputed once offline.

- **Cross-validation / statistical protocol.** For POSGEN experiments: results are averaged over 5 random seeds with different training/validation/test splits. The seed tokens (first 4 tokens of each sequence) are non-overlapping across all sequences in the dataset to ensure the model learns the generation rule rather than memorizing specific patterns. For LLM experiments: no cross-validation is reported; fine-tuning is performed once per configuration, and evaluations are on fixed test sets. All YaRN hyperparameters (α=1, β=32) are taken directly from Peng et al. (2024) without further tuning, meaning Resonance YaRN uses the identical configuration as standard YaRN—the only difference is the Resonance preprocessing step.

### Main Quantitative Results

#### Synthetic Task Evaluation on POSGEN (Section 6.1)

The central synthetic result appears in **Table 1** (OOD Accuracy on POSGEN's test set, positions 64–255). Across the three subtasks, the combination of Resonance RoPE with YaRN (Resonance YaRN) achieves the highest performance in all cases, demonstrating that eliminating the interpolation gap on pre-critical dimensions yields additive gains beyond extrapolation handling alone.

**Recursive subtask (local attention only):**

- Standard RoPE achieves 65.29% OOD accuracy.
- Resonance RoPE alone: 62.64%—a **decrease** of 2.65 percentage points. This is the only configuration where Resonance RoPE underperforms its non-Resonance counterpart. The paper attributes this to "the dominance of extrapolated post-critical dimensions in OOD positions" (Section 6.1.2). Since the Recursive task requires only local attention (each token depends on the 4 previous tokens), post-critical features with long wavelengths—which Resonance RoPE does not help—play a larger role in attending to the relevant context.
- YaRN alone (s=4): 95.93%—nearly perfect, suggesting that extrapolation handling alone suffices for tasks requiring only local attention patterns.
- Resonance YaRN: 98.30%—approaching ceiling performance, with variance reduced to effectively zero (±0.00% standard deviation across 5 seeds).

The gap between Resonance RoPE (62.64%) and YaRN (95.93%) on Recursive is the largest in the table, supporting the paper's claim that Resonance RoPE must be combined with a scaling method for post-critical dimensions to achieve full potential on tasks where long-wavelength features matter.

**Chain-of-Thought subtask (one fixed long-range dependency):**

- Standard RoPE: 69.56%.
- Resonance RoPE alone: 75.25%—a gain of 5.69 percentage points over standard RoPE, showing that fixing interpolation alone helps when the task requires attending to a fixed distant position (position 0).
- YaRN alone: 98.71%—near-perfect, showing that extrapolation handling is highly effective for fixed long-range attention.
- Resonance YaRN: 99.58%—approaching 100%, with variance reduced to essentially zero.

The key observation: on CoT, Resonance RoPE alone already provides a substantial improvement over standard RoPE, unlike on Recursive. The paper does not explicitly analyze why, but the implication is clear from the task structure: CoT requires attending to position 0 from positions up to 255, meaning the query and key vectors at widely separated positions must interact correctly. The interpolation gap on pre-critical features degrades the model's ability to match query rotations at OOD positions with key rotations at training positions; Resonance RoPE's elimination of this gap directly improves long-range attention fidelity.

**Semi-Recursive subtask (variable-distance long-range dependency):**

This is the most diagnostically informative subtask because it requires long-range attention to positions at varying distances, making it the hardest task and the one where both interpolation and extrapolation matter most.

- Standard RoPE: 17.96%—substantially above random baseline (1/17 ≈ 5.9%) but severely degraded from in-distribution performance.
- Resonance RoPE alone: 29.78%—a gain of 11.82 percentage points, representing a **65.8% relative improvement** over standard RoPE. This is the strongest single-method gain in the table (excluding combinations), demonstrating that the interpolation gap on pre-critical dimensions is a major bottleneck specifically for tasks requiring variable-distance long-range attention.
- YaRN alone: 33.70%—a gain of 15.74 percentage points over standard RoPE (87.6% relative improvement), showing extrapolation handling is also critical.
- Resonance YaRN: 48.46%—a gain of 30.50 percentage points over standard RoPE (169.8% relative improvement). Critically, the combined gain (30.50 pp) **exceeds the sum of the individual gains** (11.82 + 15.74 = 27.56 pp), indicating a super-additive interaction where fixing interpolation makes extrapolation handling more effective and vice versa.

**Variance analysis (Table 1):** The paper reports standard deviations across 5 random seeds. Resonance YaRN consistently achieves not only the highest mean accuracy but also the **lowest variance**—effectively zero (±0.00%) on Recursive and CoT, and ±0.03% on Semi-Recursive. Standard RoPE shows substantially higher variance (±0.43% on Recursive, ±0.33% on CoT, ±0.03% on Semi-Recursive). This suggests that Resonance RoPE provides more robust training dynamics—the model's performance is less sensitive to random initialization and data order when the interpolation gap is eliminated.

**Validation loss trajectories (Figure 3):** The paper plots validation loss against training epochs for all four configurations on each subtask. Three patterns emerge:

1. **Resonance RoPE achieves lower validation loss than standard RoPE** across all epochs on all three subtasks, even on Recursive where its final OOD accuracy is slightly lower. The loss curves for Resonance RoPE are systematically below those for RoPE, indicating better generalization during training.

2. **Resonance YaRN achieves lower validation loss than standard YaRN** across all epochs on all subtasks. The gap is particularly pronounced on the Semi-Recursive subtask, where Resonance YaRN's loss curve is substantially lower throughout training.

3. **On the Semi-Recursive subtask, Resonance RoPE alone achieves lower validation loss than standard YaRN**—a striking result given that Resonance RoPE does nothing for post-critical dimensions while YaRN is specifically designed for extrapolation. The paper notes this in Section 6.1.2: "Resonance RoPE achieving even lower validation losses than YaRN in the Semi-Recursive subtask." This suggests that for variable-distance long-range attention tasks, the interpolation gap on pre-critical dimensions may be an **even larger bottleneck** than the extrapolation gap on post-critical dimensions—a non-obvious finding that the extrapolation-focused literature would not predict.

#### LLM Perplexity Evaluation on Long Sequences (Section 6.2.2)

**Figure 4** shows perplexity curves for LLaMA2-Chat 7B with four position embedding configurations on GovReport and Proofpile corpora, measured at context lengths from approximately 2,000 to 32,000 tokens. The key headline: **Resonance YaRN (s=8) achieves the lowest perplexity at every context length on both datasets**, and its advantage over standard YaRN (s=8) is stable rather than growing with context length.

**GovReport (left panel of Figure 4):**

- Dynamic NTK (no fine-tuning): The worst performer, with perplexity rising sharply from ~4.6 at 10K tokens to ~6.5 at 30K tokens.
- NTK-Aware Scaling (s=8, no fine-tuning): Better than Dynamic NTK, with perplexity rising from ~4.4 at 10K to ~5.5 at 30K.
- YaRN (s=8, fine-tuned): Substantially better, with perplexity rising from ~4.2 at 10K to ~4.9 at 30K.
- Resonance YaRN (s=8, fine-tuned): The best performer, with perplexity rising from ~4.1 at 10K to ~4.6 at 30K—a consistent advantage of roughly 0.1–0.3 PPL across all context lengths.

The YaRN and Resonance YaRN curves are nearly parallel, indicating that the Resonance modification provides a **uniform improvement** rather than one that only manifests at extreme lengths. This is consistent with the POSGEN finding that the interpolation gap affects OOD positions at all distances, not just the furthest ones.

**Proofpile (right panel of Figure 4):**

- Dynamic NTK: Perplexity rises from ~2.5 at 10K to ~5.5 at 30K—the steepest degradation.
- NTK-Aware Scaling: Better, rising from ~2.3 at 10K to ~4.2 at 30K.
- YaRN: Substantially better, rising from ~2.1 at 10K to ~3.5 at 30K.
- Resonance YaRN: Best, rising from ~2.0 at 10K to ~3.2 at 30K—a consistent advantage of ~0.1–0.3 PPL.

The gap between Resonance YaRN and YaRN on Proofpile is slightly larger at longer context lengths (approximately 0.3 PPL at 30K vs. 0.1–0.2 PPL at shorter lengths), though the paper does not quantify this trend. The overall pattern across both datasets: Resonance RoPE provides a modest but consistent perplexity improvement when combined with YaRN, and this improvement does not require any additional fine-tuning tokens, architectural changes, or hyperparameter tuning beyond the standard YaRN configuration.

**Important caveat on Figure 4:** The paper only reports perplexity for LLaMA2-Chat 7B. Results for the 13B model are not shown in perplexity curves, though downstream task results in Table 2 cover both model sizes. The paper also does not report perplexity for the "short-sequence fine-tuning" (FT@4K) configurations that appear in Table 2—Figure 4 presumably uses the long-sequence fine-tuned models (FT@32K, 50 epochs), though this is not explicitly stated. The 50 random samples per dataset provide a limited evaluation set for perplexity; confidence intervals are not reported, making it difficult to assess whether the 0.1–0.3 PPL differences are statistically significant.

#### Real-World Downstream Task Evaluation (Section 6.2.3)

**Table 2** presents closed-ended task accuracy on L-Eval for LLaMA2-Chat 7B and 13B under various position embedding and fine-tuning configurations. The central finding: **Resonance YaRN achieves higher average performance than standard YaRN across both model sizes and both fine-tuning strategies**, though no single configuration dominates all subtasks.

**LLaMA2-Chat 7B results (target context: 32K, s=8):**

Five fine-tuned configurations plus two no-fine-tuning baselines are compared:

*Long-sequence fine-tuning (FT@32K, 50 epochs):*

- YaRN: 33.24% average across 6 tasks.
- Resonance YaRN: 34.24% average—a gain of 1.00 percentage points.

*Short-sequence fine-tuning (FT@4K, 400 epochs):*

- YaRN: 36.61% average.
- Resonance YaRN: 37.58% average—a gain of 0.97 percentage points.

Several patterns stand out. First, **short-sequence fine-tuning (4K, 400 epochs) consistently outperforms long-sequence fine-tuning (32K, 50 epochs)** for both YaRN and Resonance YaRN, despite the model never seeing long sequences during the short-sequence fine-tune. This suggests that adaptation to the scaled position embeddings matters more than exposure to long contexts per se, and that the 400-epoch schedule provides more diverse training examples (many 4K chunks from different documents vs. fewer 32K documents) within the 100M token budget.

Second, the **per-task breakdown reveals heterogeneous gains**. On GSM (math word problems), Resonance YaRN achieves 27.00% vs. YaRN's 24.00% under short-sequence fine-tuning—a 3.00 percentage point gain. On QuALITY (multiple-choice QA on long documents), Resonance YaRN achieves 40.59% vs. 37.62%—a 2.97 percentage point gain. On SFiction (science fiction), Resonance YaRN achieves 61.72% vs. 60.94%—a modest 0.78 pp gain. However, on CodeU (code understanding), Resonance YaRN underperforms: 3.33% vs. 4.44% for YaRN under short-sequence fine-tuning. The paper does not analyze per-task variance, but the CodeU degradation suggests that the interpolation gap elimination may not benefit—or may slightly harm—tasks with specific attention patterns (code understanding involves highly structured, syntax-driven attention that may be less sensitive to position embedding interpolation).

**LLaMA2-Chat 13B results (target context: 16K, s=4):**

*Long-sequence fine-tuning (FT@16K, 100 epochs):*

- YaRN: 41.48% average.
- Resonance YaRN: 41.65% average—a marginal gain of 0.17 percentage points, which is smaller than the 7B gains. The per-task breakdown shows Resonance YaRN leads on Coursera (38.66% vs. 38.08%), QuALITY (43.56% vs. 43.07%), and marginally on TOEFL (65.06% vs. 65.43%), but trails on SFiction (62.50% vs. 63.28%). The small average difference suggests that at larger model scales (13B vs. 7B), the interpolation gap may be partially mitigated by the model's greater capacity to learn interpolation during fine-tuning.

*Short-sequence fine-tuning (FT@4K, 400 epochs):*

- YaRN: 39.06% average.
- Resonance YaRN: 39.87% average—a gain of 0.81 percentage points.

In the 13B short-sequence setting, the average gain is comparable to the 7B gains (~0.8–1.0 pp). However, the 13B short-sequence results are lower overall than the 13B long-sequence results (39.06% vs. 41.48% for YaRN), which is the opposite pattern from 7B (where short-sequence fine-tuning was better). This reversal is not discussed in the paper. It may reflect the 13B model's greater capacity to benefit from seeing long sequences during fine-tuning, or it may be an artifact of the specific 100M token budget being insufficient for the 13B model to fully adapt to the scaled embeddings on short sequences.

**No-fine-tuning baselines (Table 2, top rows for each model size):**

- Dynamic NTK-Aware (7B, 32K): 32.59% average—competitive with fine-tuned YaRN (33.24%), which is remarkable given zero fine-tuning cost. However, per-task performance is highly variable: 59.11% on TOEFL but only 1.11% on CodeU.
- NTK-Aware (7B, s=8): 25.43% average—substantially worse than Dynamic NTK, primarily due to catastrophic performance on GSM (3.00% vs. 32.00% for Dynamic NTK). This illustrates the brittleness of fixed-scale NTK-Aware without fine-tuning.

- Dynamic NTK-Aware (13B, 16K): 35.62% average—the best no-fine-tuning result, competitive with fine-tuned configurations.
- NTK-Aware (13B, s=4): 35.47% average—nearly identical to Dynamic NTK, unlike the 7B case where NTK-Aware was substantially worse.

The fact that Dynamic NTK-Aware without fine-tuning can match or approach fine-tuned YaRN on some configurations (particularly 13B) suggests that a substantial portion of the TSTL performance gap can be closed without any training at all, simply by dynamically adjusting the scaling factor. However, the paper explicitly notes the computational cost of Dynamic NTK-Aware ("due to the high cost of frequently recomputing RoPE features") as a practical limitation, making Resonance YaRN with short-sequence fine-tuning a more deployment-friendly alternative.

**The FT@4K vs. FT@32K/16K comparison across models:**

For LLaMA2-Chat 7B, FT@4K (400 epochs) outperforms FT@32K (50 epochs) by 3.37 pp for YaRN (36.61% vs. 33.24%) and 3.34 pp for Resonance YaRN (37.58% vs. 34.24%). For LLaMA2-Chat 13B, FT@16K (100 epochs) outperforms FT@4K (400 epochs) by 2.42 pp for YaRN (41.48% vs. 39.06%) and 1.78 pp for Resonance YaRN (41.65% vs. 39.87%). The paper does not explore this model-size-dependent reversal, which could indicate that the optimal fine-tuning strategy (long sequences for fewer steps vs. short sequences for more steps) depends on model scale. A plausible hypothesis: larger models have more capacity to absorb the position embedding scaling and benefit from actually seeing long-range dependencies during fine-tuning, while smaller models benefit more from the greater data diversity of short-sequence training.

### Ablation Studies and Robustness Checks

**Resonance RoPE alone vs. with YaRN across subtask difficulty (Table 1):** On the Recursive subtask (purely local attention), Resonance RoPE alone **degrades** performance relative to standard RoPE (62.64% vs. 65.29%), while on the Semi-Recursive subtask (variable-distance long-range attention), it **substantially improves** performance (29.78% vs. 17.96%). This ablation demonstrates that the interpolation gap on pre-critical dimensions primarily affects tasks requiring non-local attention—when attention is purely local, the extrapolation problem on post-critical dimensions dominates, and modifying pre-critical features without addressing post-critical features can be net harmful. The paper does not explicitly ablate *which* pre-critical features are responsible for this effect, but the task structure (Recursive depends on positions `l-4` through `l-1`, all neighboring) vs. Semi-Recursive (depends on position `⌊l/2⌋-1`, potentially 128 tokens away) provides a natural explanation: nearby positions have similar rotation angles regardless of exact periodicity, so the interpolation gap matters less; distant positions require precise alignment of query and key rotations, which Resonance RoPE provides.

**Validation loss trajectories across training (Figure 3):** For all three subtasks, the validation loss curves show that Resonance RoPE and Resonance YaRN achieve lower losses than their non-Resonance counterparts throughout training—not just at convergence. This indicates that the benefit is not merely a final-performance improvement from better OOD generalization but a **training-dynamics improvement**: the model learns more effectively at all stages when the interpolation gap is eliminated, even on in-distribution positions. The paper does not ablate whether this effect is due to (a) the model spending less capacity learning to interpolate, freeing resources for learning the actual task, or (b) the gradient signal being cleaner when RoPE features are exactly periodic.

**Dynamic NTK-Aware vs. static NTK-Aware without fine-tuning (Table 2):** For LLaMA2-Chat 7B, Dynamic NTK-Aware (32.59% average) dramatically outperforms static NTK-Aware scaling with s=8 (25.43% average). The per-task breakdown reveals that static NTK-Aware suffers catastrophic failure on GSM (3.00% vs. 32.00%) and significantly worse performance on QuALITY (26.73% vs. 34.65%) and TOEFL (34.20% vs. 59.11%). For LLaMA2-Chat 13B, the gap narrows substantially: Dynamic NTK-Aware (35.62%) vs. static NTK-Aware (35.47%)—nearly identical. This interaction with model scale suggests that larger models are more robust to suboptimal fixed scaling factors, possibly because they can better handle the residual interpolation/extrapolation through learned attention patterns. The Dynamic NTK method's high computational cost (recomputing RoPE features at every sequence length) makes it impractical for deployment despite its strong no-fine-tuning performance, which the paper acknowledges but does not quantify in terms of latency or FLOP overhead.

**Fine-tuning strategy ablation: long sequences (32K/16K) vs. short sequences (4K) (Table 2):** For LLaMA2-Chat 7B, short-sequence fine-tuning (FT@4K, 400 epochs) outperforms long-sequence fine-tuning (FT@32K, 50 epochs) for both YaRN and Resonance YaRN, by margins of 3.37 pp and 3.34 pp respectively. The paper controls total tokens to ~100M in both settings, meaning the short-sequence strategy exposes the model to roughly 8× more distinct training documents (many 4K chunks vs. fewer 32K documents). The performance advantage of short-sequence fine-tuning supports the hypothesis that **the model primarily needs to adapt its weights to the scaled position embeddings, not to learn new long-range dependencies**—otherwise long-sequence fine-tuning, which actually demonstrates long-range patterns, should outperform. However, this pattern reverses for LLaMA2-Chat 13B (long-sequence FT@16K outperforms short-sequence FT@4K by 2.42 pp for YaRN), complicating the interpretation. The paper does not ablate the interaction between fine-tuning sequence length and model scale, leaving open the question of whether the 100M token budget is sufficient for both model sizes.

**Model scale ablation (7B vs. 13B in Table 2):** The relative gain from Resonance YaRN over standard YaRN is larger for 7B than 13B under short-sequence fine-tuning (0.97 pp vs. 0.81 pp) and much larger under long-sequence fine-tuning (1.00 pp vs. 0.17 pp). This suggests that the interpolation gap is more consequential for smaller models—larger models may have sufficient capacity to learn to interpolate RoPE features during fine-tuning, partially compensating for the non-integer wavelengths. The paper does not test models beyond 13B, so whether this trend continues (Resonance RoPE providing diminishing returns at larger scales) or plateaus is unknown.

**Task type ablation (per-task results in Table 2):** The L-Eval benchmark covers diverse domains, implicitly ablating whether Resonance RoPE's benefits are task-specific. Gains are observed on lecture comprehension (Coursera), mathematical reasoning (GSM), long-document QA (QuALITY), and fiction understanding (SFiction), suggesting broad applicability. However, the CodeU task shows inconsistent results—Resonance YaRN underperforms YaRN on CodeU for 7B short-sequence (3.33% vs. 4.44%) but outperforms on 13B long-sequence (1.11% vs. 0.00%). The small absolute magnitudes on CodeU (most scores are 0–5%) make these comparisons noisy; the paper does not discuss whether CodeU performance is above random baseline.

**Wavelength rounding ablation (implicit in Theorem 1 vs. empirical results):** The paper does not ablate the rounding strategy (nearest integer vs. floor vs. ceiling). Theory (Appendix A) requires exact integer wavelengths for the zero-gap guarantee, but the paper does not test whether "close to integer" (e.g., rounding to nearest 0.5) would provide partial benefits. This is a missing ablation that would help establish how sensitive the gains are to exact periodicity vs. approximate periodicity.

**Negative result: Resonance RoPE degrades Recursive subtask performance (Table 1):** The 2.65 pp drop from standard RoPE (65.29%) to Resonance RoPE (62.64%) on the Recursive subtask is a genuine negative result that the paper acknowledges. It demonstrates that Resonance RoPE is not universally beneficial—on tasks where post-critical dimension extrapolation dominates and pre-critical interpolation is less relevant (purely local attention), modifying pre-critical features can be net harmful. The paper correctly identifies this as a motivation for combining Resonance RoPE with a scaling method like YaRN, but does not analyze *why* the degradation occurs. A plausible mechanism: by rounding wavelengths to integers, Resonance RoPE slightly alters which discrete angles appear at training positions, potentially making the model's task of learning local attention patterns slightly harder (the original non-integer wavelengths provide a denser sampling of the unit circle at nearby positions, which could help discriminate between adjacent tokens). This hypothesis is untested.

**Negative result: Static NTK-Aware scaling catastrophic on GSM (Table 2):** For LLaMA2-Chat 7B with NTK-Aware scaling (s=8, no fine-tuning), GSM accuracy drops to 3.00%—far below Dynamic NTK-Aware (32.00%) and fine-tuned methods (19.00–27.00%). This illustrates that the fixed scaling factor s=8 with no adaptation is insufficient for mathematical reasoning, even though it achieves reasonable performance on other tasks (36.77% on Coursera, 50.78% on SFiction). The paper does not explore whether an intermediate scaling factor or partial fine-tuning could recover GSM performance without full YaRN.

### Critical Assessment

#### Does Resonance RoPE improve OOD position recognition specifically, or does it provide a more general performance benefit?

The POSGEN experiments (Table 1, Figure 3) provide strong evidence for the specific claim. By design, POSGEN eliminates the confound of increasing task difficulty with sequence length, so any OOD accuracy improvement must stem from better position recognition. The fact that gains are task-pattern-dependent (large on Semi-Recursive, small/negative on Recursive) further supports a position-embedding-specific mechanism rather than a general optimization benefit. A general benefit (e.g., better conditioning, easier optimization landscape) would presumably improve all subtasks roughly equally. The asymmetric gains align with the theoretical prediction: Resonance RoPE eliminates the interpolation gap for pre-critical features, which matters more when the task requires precise long-range attention alignment.

**Limitation:** The paper tests only one instantiation of POSGEN (modular addition modulo 17 with j=1, k=3). The claim that POSGEN "isolates position recognition" is supported for this specific task, but the generalizability to other synthetic tasks (e.g., different functions h, different vocabulary sizes, different j/k ratios) is untested. The choice of modular addition is well-motivated (Nanda et al., 2023), but the paper does not demonstrate that the constant-difficulty invariant holds empirically—i.e., that a model with perfect position embeddings would achieve uniform accuracy across all positions. If the model's in-distribution accuracy (positions 0–63) is not uniform, then some position-independent difficulty variation remains, partially confounding the OOD accuracy metric.

#### Does Resonance RoPE provide gains beyond what YaRN already achieves?

The LLM experiments (Figure 4, Table 2) show that Resonance YaRN consistently outperforms standard YaRN with identical hyperparameters and training budgets. The gains are modest but consistent: ~1% average accuracy on L-Eval closed-ended tasks, ~0.1–0.3 PPL improvement on GovReport and Proofpile. The fact that these gains appear across both model sizes (7B, 13B), both fine-tuning strategies (short-sequence and long-sequence), and diverse downstream tasks (lectures, math, QA, fiction) strengthens the claim that the benefit is genuine rather than noise.

**Limitation:** The paper does not establish statistical significance for the LLM-scale results. No confidence intervals, standard deviations, or significance tests are reported for Table 2 or Figure 4. The L-Eval benchmark likely has a limited number of questions per task (not specified in the paper, but typical L-Eval closed-ended tasks have 50–200 questions each), and the aggregate average across 6 tasks with varying sample sizes may obscure per-task variance. The 0.1–0.3 PPL differences in Figure 4 are small enough that with only 50 samples per dataset, they could fall within measurement noise. A more rigorous evaluation would report confidence intervals via bootstrapping or multiple fine-tuning runs with different random seeds.

**Missing baseline: Resonance RoPE alone at LLM scale.** The paper never tests Resonance RoPE without YaRN on LLaMA2-Chat 7B or 13B. This is a significant omission because it would answer whether the interpolation gap matters at LLM scale independently of extrapolation handling. Based on the POSGEN results, one would predict that Resonance RoPE alone on LLaMA2-Chat 7B without fine-tuning would improve performance on long-range attention tasks but potentially degrade short-range tasks (as on Recursive). This prediction is untested. The paper's framing of Resonance RoPE as a "universal enhancement" to RoPE scaling methods is therefore validated only in combination with YaRN, not as a standalone modification.

#### Are the gains from Resonance RoPE additive with YaRN, or does Resonance RoPE simply change the effective hyperparameters?

A skeptical interpretation of the results: rounding wavelengths to integers changes the effective wavelengths that YaRN's NTK-by-parts partitioning operates on, potentially moving some features from one scaling regime to another. The observed improvements might be achievable with standard YaRN by simply tuning α and β differently, rather than from eliminating the interpolation gap per se.

The POSGEN results partially address this concern. The super-additive gains on Semi-Recursive (Resonance YaRN: +30.50 pp vs. sum of individual gains: +27.56 pp) suggest a genuine interaction beyond hyperparameter tuning—if Resonance RoPE merely improved YaRN's effective hyperparameters, the combined gain would be at most the maximum of the individual gains, not exceeding their sum. However, the paper does not perform a systematic hyperparameter sweep for YaRN to establish a performance ceiling that Resonance YaRN exceeds. The fixed α=1, β=32 from Peng et al. (2024) are used for both YaRN and Resonance YaRN; it is possible that Retuning α and β for standard YaRN could close or eliminate the gap.

**Missing ablation:** A sweep of α and β for standard YaRN vs. fixed α=1, β=32 for Resonance YaRN would test whether the gains are robust to hyperparameter optimization. If standard YaRN with optimally tuned α, β can match Resonance YaRN, then Resonance RoPE's contribution is effectively a hyperparameter simplification (making YaRN less sensitive to α, β choices) rather than a fundamentally new mechanism.

#### Does Resonance RoPE's benefit scale with model size?

The paper tests two model sizes: 7B and 13B. The relative gain from Resonance YaRN over YaRN is smaller at 13B than 7B for long-sequence fine-tuning (0.17 pp vs. 1.00 pp) but comparable for short-sequence fine-tuning (0.81 pp vs. 0.97 pp). This is insufficient data to establish a scaling trend. If larger models can learn to interpolate RoPE features during fine-tuning, the benefit of explicit integer-wavelength alignment would diminish with scale, eventually becoming negligible. Testing on a 70B model (e.g., LLaMA2-70B) would provide evidence for or against diminishing returns—an important practical consideration since the largest models are the ones where long-context deployment is most expensive and where position embedding improvements would be most valuable.

**Missing experiment:** Apply Resonance YaRN to LLaMA2-70B with the same 100M token fine-tuning budget and compare against standard YaRN. If gains shrink to near zero, Resonance RoPE would be primarily valuable for smaller models; if gains persist, it would be a robust enhancement across scales.

#### Does POSGEN measure what it claims to measure?

The paper claims POSGEN "controls the difficulty in generating tokens throughout the sequence to be identical." For the modular addition instantiation, this is true by construction: `h(x_0, x_1, x_2, x_3) = (Σ x_i) mod 17` has identical computational complexity regardless of which 4 inputs it receives. However, the **learning difficulty** may not be identical across positions. During training, the model sees position 0 through 63. At position 63, the model has been trained on 63 preceding positions with their specific prediction errors and gradient signals. The optimization trajectory may lead to better representations for later training positions simply because they are closer to the loss computed at the end of the sequence (backpropagation through time effects). If so, the "in-distribution accuracy" curve across positions 0–63 may not be flat, indicating that some position-dependent difficulty remains even with constant algorithmic complexity. The paper does not report per-position accuracy within the training range (0–63) to validate the constant-difficulty assumption.

Furthermore, the paper tests only `j=1, k=3` and modular addition mod 17. Different functions `h` (e.g., multiplication, XOR, lookup tables), different vocabulary sizes, and different `j, k` ratios could produce different position-embedding sensitivity profiles. The paper's claim that POSGEN is a "benchmark" implies broader applicability, but the single instantiation makes it more of a case study. A true benchmark would include multiple task instances with varying difficulty and structure.

#### Are the LLM fine-tuning results confounded by data distribution?

The paper fine-tunes on PG19 (books published before 1919). The language in PG19 differs substantially from modern text in vocabulary, syntax, and discourse structure—potentially creating a distribution shift between fine-tuning and evaluation (which includes modern lectures, math problems, code, and science fiction). If Resonance RoPE provides a regularization effect that improves out-of-distribution robustness (beyond position embeddings), the observed gains might overestimate the position-specific benefit. The paper does not ablate the fine-tuning dataset (e.g., fine-tuning on a modern corpus like C4 or The Pile) to test whether the gains are PG19-specific.

#### Generalizability beyond LLaMA-family models

All LLM experiments use LLaMA2-Chat 7B and 13B. The paper claims Resonance RoPE is a universal enhancement to RoPE-based models, but Mistral (Jiang et al., 2023), Code LLaMA (Rozière et al., 2023), and other RoPE-equipped models may have different rotary base values, head dimensions, and pretraining context lengths that affect the critical dimension boundary and the number of pre-critical features. The paper does not test on any non-LLaMA model.

**Missing experiment:** Apply Resonance RoPE to Mistral 7B (which uses a sliding window attention mechanism in addition to RoPE) to test whether the interpolation-gap benefit interacts with sparse attention patterns. Apply to a vision Transformer with RoPE to test whether the benefit extends beyond language. The paper's claims of universality are speculative without such cross-architecture validation.

#### Computational cost accounting

The paper emphasizes that Resonance RoPE introduces "no additional online computational costs" (Abstract) and "zero runtime overhead" (Section 4). This is strictly true: the `Θ → ˜Θ` transformation is a one-time precomputation of d/2 floating-point values, and the inference graph is identical. However, the paper does not account for the **cost of fine-tuning** in its efficiency claims. Resonance YaRN still requires fine-tuning on ~100M tokens (4 A100 GPUs for the experiments reported)—the same as standard YaRN. If the claim is that Resonance RoPE "improves performance without additional online computational costs," this is accurate. But compared to no-fine-tuning methods like Dynamic NTK-Aware, Resonance YaRN requires substantial offline compute that is not factored into any cost-benefit analysis.

**Missing comparison:** The paper does not compare Resonance RoPE at a smaller fine-tuning budget (e.g., 10M tokens) against standard YaRN at 100M tokens. If Resonance YaRN with 10M tokens can match or exceed standard YaRN with 100M tokens, that would demonstrate a practical efficiency gain from faster adaptation to scaled embeddings. Alternatively, if the gains require the full fine-tuning budget, the practical benefit is limited to the ~1% accuracy improvement at equal cost.

#### Overall assessment

The experiments provide **strong support for the existence and importance of the interpolation gap in controlled settings** (POSGEN) and **moderate but consistent support for practical benefits at LLM scale** (perplexity and downstream tasks). The paper's central claim—that Resonance RoPE narrows the generalization gap in TSTL scenarios by refining RoPE feature interpolation for OOD positions—is well-supported by the synthetic experiments, which isolate the mechanism and demonstrate substantial gains. The claim that Resonance RoPE "significantly improves model performance without additional online computational costs" is supported only in the sense that the gains are positive and the inference cost is zero; the statistical significance of the LLM-scale gains is uncertain given the lack of confidence intervals, and the offline fine-tuning cost is omitted from the cost accounting.

The strongest evidence comes from the POSGEN Semi-Recursive results (Table 1), where the super-additive interaction between Resonance RoPE and YaRN provides clear evidence of complementary mechanisms. The weakest evidence comes from the LLM downstream task evaluation (Table 2), where the per-task gains are heterogeneous (some tasks show degradation), the average gains are modest (~1%), and the statistical reliability is unestablished. The paper would be strengthened by (1) statistical significance testing for LLM results, (2) testing on 70B-scale models to assess scaling trends, (3) a hyperparameter sweep for YaRN to rule out the "better hyperparameters in disguise" interpretation, (4) testing Resonance RoPE alone at LLM scale to isolate the interpolation-gap contribution from YaRN's extrapolation handling, and (5) validation on non-LLaMA RoPE-based models to support the universality claim.

## 6. Limitations and Trade-offs

### The Difficulty Estimation Cost Is Not Accounted For — And It Dominates the Inference Budget

The compute-optimal framework's headline efficiency claim — that adaptive allocation recovers more than a `4×` improvement over best-of-N — is computed *after* the prompt's difficulty is known. The method for estimating difficulty is extraordinarily expensive: it requires generating 2,048 complete solutions per prompt and scoring them with the PRM (or checking against ground truth for the oracle variant). This cost is not amortized into any of the reported efficiency numbers. The paper acknowledges this explicitly in Section 3.2:

> "estimating difficulty in this way still incurs additional computation cost during inference... our experiments do not account for this cost largely for simplicity"

**The consequence:** In a realistic deployment, the total compute spent per prompt equals `(difficulty estimation cost) + (strategy execution cost)`. Since the difficulty estimation cost (2,048 generations) is equal to or larger than the largest test-time budgets studied (256–512 generations), the true cost could be **5–10× higher** than what the headline numbers suggest. The `4×` efficiency gain over best-of-N is therefore an **upper bound** that applies only in regimes where difficulty estimation is free — such as when difficulty labels are precomputed offline for a static set of prompts, or when the cost is amortized over many repeated queries to the same prompt. For one-shot queries (the most common deployment scenario), the total cost including difficulty estimation may make the compute-optimal approach *less* efficient than simply running best-of-N with the full budget.

**What evidence exists in the paper:** The paper reports results using both oracle difficulty (ground-truth pass@1) and predicted difficulty (PRM-based scoring of 2,048 samples). The predicted-difficulty curves largely overlap with oracle curves in Figure 4 and Figure 8, demonstrating that the method works without ground-truth labels. However, **at no point** does the paper report total cost inclusive of difficulty estimation. The generation budgets on the x-axes of Figure 3, Figure 4, Figure 6, and Figure 8 represent only the strategy execution cost, not the 2,048-sample precomputation. This makes direct cost comparisons against baselines (which do not incur a precomputation overhead) misleading.

**Mitigation status:** The paper flags this as a key area for future work in Section 8, suggesting "pretraining or finetuning models to directly predict difficulty of a question" and noting that the current approach represents an exploration-exploitation tradeoff. The paper also proposes — but does not implement — adaptive difficulty estimation where difficulty is inferred from a small number of initial samples and the remaining budget is allocated accordingly. No experiments test whether, for example, difficulty estimated from 32 samples (rather than 2,048) retains enough signal for the compute-optimal policy to work. This is a significant gap between the conceptual framework and a practical deployment.

### Hard Problems Remain Essentially Unsolved — Test-Time Compute Cannot Compensate for Fundamental Capability Gaps

Across all methods studied — PRM search, iterative revisions, and their compute-optimal combinations — the hardest questions (difficulty bin 5) show **near-zero improvement** regardless of compute budget. The paper is transparent about this in Section 7, stating that test-time compute provides "essentially zero benefit regardless of budget" on these problems.

**The consequence:** This establishes a hard boundary condition on the approach: test-time compute can amplify existing capability but cannot create it. If the base model's pass@1 is near zero on a problem class, no amount of search, revision, or adaptive allocation will help — there are no correct solutions in the proposal distribution to find or refine. For any deployment where the prompt distribution includes a non-trivial fraction of genuinely hard problems (those outside the base model's capability range), the compute-optimal framework offers no path forward. Practitioners must either (a) accept that those problems will not be solved, (b) deploy a larger model (scaling pretraining instead), or (c) develop fundamentally different capabilities (e.g., tool use, retrieval) that the base model lacks.

**What evidence exists in the paper:** Figure 3 (right) shows bin 5 accuracy hovering at 1–3% for all search methods and all budgets. Figure 7 (right) shows bin 5 at ~2–3% regardless of the sequential-to-parallel ratio. In the FLOPs-matched comparison (Figure 9, Section 7), the bin 5 scaling line is essentially flat near 0–5%, with test-time compute showing a −52.9% relative disadvantage compared to the `~14×` larger model on hard problems at `R ≫ 1`. The paper's own text in the Section 7 takeaway box acknowledges this candidly: "On the hardest questions (bin 5), test-time compute provides essentially zero benefit."

**Mitigation status:** The paper does not attempt to solve this limitation — it treats it as an inherent boundary of the test-time compute paradigm. Future work combining test-time compute with retrieval-augmented generation, tool use, or other capability-expanding mechanisms could push the boundary, but the paper does not explore these directions. The practical implication is clear: if your use case includes problems where the base model's pass@1 is effectively zero, you need a better base model, not better test-time strategies.

### The `~14×` Larger Model Baseline In the FLOPs-Matched Comparison Is Not Compute-Optimally Trained

The paper's FLOPs-matched comparison (Section 7) asks: given a fixed total FLOPs budget, is it better to train a larger model or keep the smaller model and spend the extra FLOPs on inference-time computation? The comparison scales model parameters by `~14×` while holding training data fixed, following the LLaMA paradigm (Touvron et al., 2023a) where models are overtrained relative to the Chinchilla-optimal data-to-parameters ratio. The paper acknowledges this:

> "We choose this setting as it is representative of a canonical approach to scaling pretraining compute and leave the analysis of compute-optimal scaling of pretraining compute where the data and parameters are both scaled equally to future work."

**The consequence:** A Chinchilla-optimal model trained with `~14×` more total FLOPs — scaling both parameters and data according to Hoffmann et al. (2022) — would likely outperform a parameter-only-scaled model at the same FLOPs budget. This makes the pretraining baseline **weaker than it needs to be**, potentially overstating the advantage of test-time compute. The reported advantages (e.g., +27.8% on easy questions at `R ≪ 1` for revisions, Figure 1) may shrink or reverse against a properly compute-optimal larger model.

Additionally, the `~14×` larger model uses only **greedy decoding** with no test-time augmentation of its own. A fairer comparison would give the larger model a modest test-time compute budget — say, best-of-8 or best-of-16 — since the FLOPs-matched framework could, in principle, allocate a portion of the larger model's total budget to inference rather than using all of it for pretraining. The paper's comparison implicitly assumes the larger model uses all its FLOPs for pretraining and none for inference augmentation, which biases the comparison in favor of test-time compute with the smaller model.

**What evidence exists in the paper:** The FLOPs accounting in Section 7 uses standard formulas (`X = 6 N D_pretrain` for pretraining, `Y = 2 N D_inference` for inference) and correctly derives the inference budget available to the smaller model. However, the paper does not test alternative pretraining baselines (Chinchilla-optimal scaling, mixture of parameter and data scaling) or alternative larger-model inference strategies (best-of-N, majority voting). The paper's results are therefore specific to the particular pretraining recipe of the model family used (PaLM 2), and the magnitude of the test-time compute advantage may not generalize to models trained with different scaling philosophies.

**Mitigation status:** The paper explicitly acknowledges the limitation and frames it as future work. The claim that "test-time compute can substitute for pretraining" should be understood as conditional on the specific pretraining recipe used — it is not a universal law. Practitioners using Chinchilla-optimal training or other scaling strategies should not expect the same `4×` advantage magnitudes without additional validation.

### The OOD Accuracy Metric in POSGEN Does Not Verify That In-Distribution Difficulty Is Constant

POSGEN — the paper's proposed synthetic benchmark for isolating position recognition from task difficulty — is designed around a **constant-difficulty invariant**: because each token `x_l` is computed by applying the same function `h` to a fixed-size window of `j+k` previous tokens, the computational complexity of prediction is identical at all positions. This invariant is the foundation for the claim that any drop in accuracy beyond the training length can be unambiguously attributed to position embedding failure.

However, the paper **does not empirically validate that this invariant holds in practice**. The model's in-distribution accuracy (positions 0–63) is never reported per-position. If accuracy is not uniform across training positions — for instance, if the model performs worse on position 63 than position 10 due to optimization effects like backpropagation-through-time or accumulated error — then some position-dependent difficulty variation remains even within the training range, partially confounding the OOD accuracy metric.

**The consequence:** The OOD accuracy drop between position 63 (last training position) and position 64 (first OOD position) might overstate the position embedding's contribution to failure if the model's in-distribution accuracy was already declining toward the end of the training range. More subtly, the paper's claim that POSGEN "isolates" position recognition failures depends on the constant-difficulty assumption; without validation, the benchmark provides a **cleaner** signal than existing evaluations but not necessarily a **perfectly clean** one.

**What evidence exists in the paper:** Table 1 reports aggregate OOD accuracy across all positions 64–255, and Figure 3 shows validation loss aggregated across all positions. Neither provides per-position accuracy breakdowns that would validate the constant-difficulty invariant. The paper does not report in-distribution accuracy (positions 0–63) at all, making it impossible to determine the baseline from which OOD accuracy drops. If in-distribution accuracy is, say, 95%, then an OOD accuracy of 48.46% (the best Resonance YaRN result on Semi-Recursive) represents a large drop attributable to position embeddings. If in-distribution accuracy is only 60%, the drop is smaller and partially attributable to the model not having learned the task perfectly even on training positions.

**Mitigation status:** The paper does not acknowledge this as a limitation. The modular addition task with `j=1, k=3` is simple enough that a well-tuned Transformer should achieve near-perfect in-distribution accuracy (Nanda et al., 2023 showed that one-layer Transformers can learn modular addition), suggesting the confound is likely small. But without explicit validation, POSGEN's status as a diagnostic instrument rests on an unverified assumption. A simple fix would be to report per-position accuracy curves for both in-distribution and OOD positions, showing a sharp drop at position 64 with a flat profile elsewhere.

---

### The Paper Never Combines PRM Search with the Revision Model — Leaving the Strongest Potential Gains Unexplored

The paper studies two complementary test-time compute mechanisms — PRM-guided search (Section 5) and iterative revision of the model's own outputs (Section 6) — as independent scaling axes. But it **never combines them** into a unified system where, for example, beam search is applied on top of revision model outputs, or the PRM guides which revisions to pursue. The authors explicitly acknowledge this gap in Section 8:

> "we did not experiment with PRM tree-search techniques in combination with revisions"

**The consequence:** The current results represent a **lower bound** on what a fully integrated system could achieve. The two mechanisms have complementary, difficulty-dependent strengths: revisions improve the proposal distribution (better candidate generation through iterative refinement), while PRM search improves candidate selection (finding the best among generated candidates via verifier-guided exploration). The paper's own difficulty-bin analysis shows that revisions excel on easy problems (where local refinement suffices) while beam search excels on medium-hard problems (where global exploration is needed). A combined system could theoretically deploy revisions to generate high-quality candidates and then apply PRM-guided search to select among them — or use the PRM's per-step scores to decide *when* to revise versus *when* to restart from scratch — achieving gains beyond either method alone.

The failure to explore this combination is particularly significant because the paper's framing positions the two mechanisms as independent, complementary axes (Section 2), implying that their combination is the natural next step. The paper establishes the conceptual framework for this combination but stops short of implementing it.

**What evidence exists in the paper:** All experiments treat search and revisions independently. Section 5 reports search results with the base LLM as the proposal distribution (no revision model). Section 6 reports revision results with best-of-N weighted or majority voting as the selection mechanism (no PRM-guided search). There is no experiment where the revision model serves as the proposal distribution for beam search, or where the PRM scores guide revision decisions. The paper's Section 8 explicitly identifies this as future work.

**Mitigation status:** This is an acknowledged gap that the paper explicitly earmarks for future investigation. The absence of combined experiments is understandable given the already-broad scope of the paper (two mechanisms × multiple algorithms × difficulty bins × FLOPs-matched comparisons). However, it means the paper's primary practical recommendation — use compute-optimal allocation to choose between search and revisions per difficulty bin — may be suboptimal compared to a system that uses both mechanisms simultaneously. The performance ceiling for test-time compute is likely higher than what the paper demonstrates.

### The Revision Model Has a 38% Correct-to-Incorrect Reversion Rate With Only an Imperfect Patch

The revision model is trained on sequences where all in-context answers are incorrect, followed by a correct target. This training data construction creates a systematic problem at inference time: when the model produces a correct answer during the revision chain, it has never been trained to recognize that the current answer is correct and should be preserved. Instead, it conditions on the correct answer and "revises" it — often changing it to an incorrect one. The paper reports that approximately **38% of correct answers get converted back to incorrect ones** during revision (Section 6.1).

**The consequence:** Even when the revision model succeeds in producing a correct answer at some step in the chain, that answer is fragile — there is a substantial probability that the next revision step will overwrite it with a wrong answer. This means the model cannot be trusted to converge toward correctness; longer revision chains do not monotonically improve. The paper's mitigation — using majority voting or verifier-based selection across the entire chain to pick the best answer rather than always taking the last revision — is a patch, not a solution. It adds overhead (storing and scoring all intermediate revisions) and reduces the effective forward progress of the chain: the model may find the correct answer at step 3, lose it at step 4, and never recover, making steps 5+ wasted computation.

The reversion problem fundamentally limits how much benefit additional sequential revisions can provide. The paper's Figure 6 (left) shows that pass@1 at each step gradually improves through about step 15–20, then plateaus. This plateau is at least partially attributable to correct answers being revised back to incorrect ones, capping the chain's effective length regardless of budget.

**What evidence exists in the paper:** The paper explicitly reports the 38% reversion rate in Section 6.1. The selection mechanism (majority or verifier across the chain) is described as a mitigation. Figure 6 (left) shows the plateau in per-step pass@1. However, the paper does not report *what fraction of chains* experience reversion, how often the correct answer is recovered after being lost, or how the reversion rate changes across difficulty bins. A deeper analysis of reversion dynamics — e.g., whether revisions that lose the correct answer tend to produce answers that are further from correct than the original wrong answer — is absent.

**Mitigation status:** The paper partially mitigates this via chain-level selection (majority voting or verifier scoring across all revisions), but this is an inference-time workaround, not a fix for the underlying training data issue. A more principled solution — such as training the model with examples where the correct answer appears in context and the target is to output it unchanged (teaching a "no revision needed" behavior) — is not explored. The ReST^EM experiment in Appendix K (Figure 16) suggests that naïve attempts to optimize the revision model further can backfire, indicating the training procedure is fragile. The 38% reversion rate represents a significant unsolved problem that caps the achievable gains from increasing sequential revision depth.

## 7. Implications and Future Directions

### How This Work Changes the Landscape

Resonance RoPE introduces a conceptual shift in how the field understands Rotary Position Embedding failures under length generalization. Prior to this work, the dominant framework — crystallized by Liu et al. (2024)'s critical dimension analysis and operationalized by methods like YaRN (Peng et al., 2024) — partitioned RoPE features into two categories: post-critical dimensions suffering from value *extrapolation* (rotary angles reaching magnitudes never seen during training) and pre-critical dimensions assumed to be safe because their angular range [0, 2π) is fully covered. Every major RoPE scaling method, from Positional Interpolation (Chen et al., 2023) through NTK-Aware scaling (bloc97, 2023; Xiong et al., 2023) to YaRN, operates within this extrapolation-centric framework: solve the long-wavelength problem, and leave short-wavelength features alone or minimally perturbed.

This paper **completes the taxonomy of TSTL failure modes** by identifying a second, orthogonal problem that the extrapolation framework missed entirely: feature *interpolation* on pre-critical dimensions. The distinction hinges on a geometric subtlety — covering the *range* of possible rotary angles is not the same as the model having encountered the *exact discrete set* of angles that appear at OOD test positions. Because RoPE's standard wavelength formula `λ_j = 2π·b^{2j/d}` produces non-integer wavelengths for all features, a pre-critical feature with, say, `λ_j = 125.66` tokens produces rotation angles at training positions {0, 1, ..., L-1} that form a specific, non-periodic sampling of the unit circle. An OOD test position `n > L` will generally produce an angle falling *between* two training angles — the model must interpolate to function values it has never exactly seen, even though the overall magnitude range is familiar.

The significance of this identification goes beyond the specific solution (rounding wavelengths to integers). It **reframes what constitutes a complete solution to TSTL**: addressing extrapolation is necessary but not sufficient; the interpolation gap on pre-critical dimensions is an independent bottleneck that requires its own targeted intervention. The POSGEN experiments in Table 1 make this reframing concrete. On the Semi-Recursive subtask (variable-distance long-range attention), standard RoPE achieves only 17.96% OOD accuracy. YaRN alone (addressing extrapolation) reaches 33.70%. Resonance RoPE alone (addressing interpolation, with no extrapolation handling) reaches 29.78% — nearly matching YaRN's performance by targeting an entirely different failure mode. Critically, the combination (Resonance YaRN) reaches 48.46%, a super-additive gain of 30.50 percentage points that exceeds the sum of the individual improvements (11.82 + 15.74 = 27.56 pp). This additivity pattern — replicated on all three POSGEN subtasks — establishes that interpolation and extrapolation are **complementary, independent bottlenecks** rather than competing explanations for the same degradation.

This reframing has immediate consequences for research prioritization. The extrapolation-dominated view implicitly suggested that pre-critical dimensions were a solved problem and that further progress on TSTL would come from better post-critical scaling strategies. The Resonance RoPE results show that this was premature: roughly half the RoPE features in LLaMA2 (44 out of 64 per head for a 4K context, per the wavelength analysis in Section 6.1.1) are pre-critical, and eliminating their interpolation gap provides gains comparable to or exceeding state-of-the-art extrapolation handling in certain regimes (Resonance RoPE alone outperforms YaRN on the Semi-Recursive subtask's validation loss, Figure 3). The implication is that **future position embedding research should analyze interpolation and extrapolation as separate sub-problems** and should evaluate methods on both axes rather than assuming pre-critical dimensions are benign.

The paper also resolves a latent tension in prior work. YaRN's NTK-by-parts strategy (Peng et al., 2024) explicitly avoids modifying short-wavelength features (`γ_j = 1` for `λ_j < L/β`) to preserve fine-grained local position discrimination. The implicit assumption — that any perturbation to pre-critical wavelengths would be harmful — was reasonable under the extrapolation-only framework, where these features were considered already optimal. Resonance RoPE provides a **constructive counterexample**: a specific, minimal perturbation (rounding wavelengths to the nearest integer, a fractional change well under 1% for most features) that *improves* rather than degrades performance by eliminating the previously unrecognized interpolation burden. The validation loss curves in Figure 3 show that Resonance RoPE achieves lower loss than standard RoPE throughout training on all three POSGEN subtasks — this is a Pareto improvement, not a tradeoff. The field's prior caution about modifying pre-critical features was based on an incomplete understanding of their failure mode; Resonance RoPE demonstrates that a carefully designed modification targeting the interpolation gap is beneficial where a naïve modification would indeed be harmful.

On the methodological side, POSGEN introduces a **diagnostic capability that the field previously lacked**. Existing long-context evaluations — perplexity on PG19/GovReport, synthetic automaton tasks (Liu et al., 2023; Kazemnejad et al., 2023) — cannot distinguish whether TSTL failures stem from position embedding issues or from the genuinely increasing difficulty of token prediction on longer sequences. POSGEN's constant-difficulty design (each token depends on a fixed-size window of `j+k` previous tokens via the same function `h`) isolates the position embedding contribution, enabling cleaner scientific comparisons. The three-subtask structure (Recursive, CoT, Semi-Recursive) further enables fine-grained diagnosis of *which attention patterns* are most vulnerable to specific position embedding failure modes. The paper's own results demonstrate this diagnostic power: the fact that Resonance RoPE degrades Recursive performance (62.64% vs. 65.29% for standard RoPE) but dramatically improves Semi-Recursive performance (29.78% vs. 17.96%) reveals that the interpolation gap predominantly affects tasks requiring long-range attention, while local-only attention is more sensitive to extrapolation on post-critical dimensions. Without POSGEN's task-pattern decomposition, this asymmetry would be invisible in aggregate metrics.

The paper's contribution is best characterized as a **conceptual reframing with an immediately practical implementation**. It is not a paradigm shift on the scale of RoPE itself (which replaced absolute position embeddings with a fundamentally different mechanism), nor is it a mere hyperparameter tuning trick. It occupies a middle ground — analogous to how the Chinchilla scaling laws (Hoffmann et al., 2022) reframed pretraining compute allocation by showing that model size and data quantity should be scaled simultaneously, changing how the field budgets training compute without introducing new architectures. Similarly, Resonance RoPE reframes TSTL as requiring solutions to two distinct sub-problems (extrapolation + interpolation) and provides a zero-cost, universally compatible technique for the interpolation sub-problem. The fact that the implementation is a one-line operation (rounding wavelengths to integers) does not diminish the conceptual contribution — the best reframings often make obvious-in-retrospect observations that a field's dominant framework systematically overlooked.

### Follow-Up Research This Work Enables

**Stress-testing the constant-difficulty invariant in POSGEN to establish it as a reliable diagnostic instrument.** POSGEN's value as a position embedding benchmark depends entirely on the claim that token generation difficulty is identical across all positions. The paper asserts this by construction (the function `h` takes a fixed-size window of `j+k` inputs at every position) but never validates it empirically. A critical follow-up experiment would: (1) Train a Transformer with a "perfect" position embedding (e.g., learned absolute position embeddings trained on the full test length, or a no-position-embedding variant where the model sees position as an explicit input feature) to establish an upper bound on in-distribution accuracy. (2) Report per-position accuracy for positions 0–63 (training range) and 64–255 (OOD range) with standard RoPE, YaRN, and Resonance YaRN. If the in-distribution accuracy curve is flat (all positions 0–63 show similar accuracy), the constant-difficulty invariant holds, and POSGEN's diagnostic claims are validated. If accuracy degrades toward the end of the training range (e.g., position 63 is harder than position 10 due to optimization effects like backpropagation-through-time), then some of the OOD accuracy drop is confounded by position-dependent difficulty that POSGEN's design does not eliminate. This validation experiment requires minimal additional compute (the per-position accuracy breakdown is a logging change, not a new training run) and would substantially strengthen the paper's methodological contribution. If the invariant fails, POSGEN's design would need refinement — perhaps through auxiliary losses that equalize optimization pressure across positions, or through alternative task formulations where the dependency window slides rather than accumulates.

**Combining Resonance RoPE with alternative RoPE scaling methods beyond YaRN to test the universality of the additivity claim.** The paper demonstrates super-additive gains when Resonance RoPE is combined with YaRN, but the theoretical framework (Theorem 1) predicts that Resonance RoPE should complement *any* method that handles extrapolation on post-critical dimensions — regardless of the specific extrapolation strategy. A natural follow-up would test Resonance RoPE in combination with: (a) Positional Interpolation (Chen et al., 2023) — does rounding wavelengths before compressing position indices provide the same additivity? (b) NTK-Aware scaling with fine-tuning (the paper only tests no-fine-tuning NTK-Aware) — does Resonance RoPE improve fine-tuned NTK-Aware as it improves fine-tuned YaRN? (c) Randomized position encodings (Ruoss et al., 2023) — do the interpolation and randomization benefits compound? A negative result (e.g., Resonance RoPE + Positional Interpolation showing no improvement over Positional Interpolation alone) would reveal that the additivity depends on YaRN's specific NTK-by-parts partitioning, which would narrow the scope of Resonance RoPE's applicability. A positive result across multiple scaling methods would establish Resonance RoPE as a universal preprocessing step for *any* RoPE-based length extension, which is the paper's stated ambition.

**Quantifying the scaling behavior of Resonance RoPE's benefit with model size to determine whether it is primarily valuable for smaller models.** The paper tests LLaMA2-Chat 7B and 13B. The relative gain from Resonance YaRN over standard YaRN is smaller at 13B than 7B for long-sequence fine-tuning (0.17 pp vs. 1.00 pp in Table 2) but comparable for short-sequence fine-tuning (0.81 pp vs. 0.97 pp). This is insufficient data to establish a trend, but the hypothesis that larger models can learn to interpolate RoPE features during fine-tuning — partially compensating for non-integer wavelengths through greater capacity — is plausible and testable. A follow-up experiment would apply Resonance YaRN to LLaMA2-70B (or LLaMA3-70B, which also uses RoPE) with the same ~100M token PG19 fine-tuning budget and compare against standard YaRN. If the gain shrinks to near zero at 70B, Resonance RoPE would be primarily a technique for smaller or medium-scale models, and practitioners deploying very large models could safely ignore it (the interpolation gap is handled implicitly by model capacity). If the gain persists at 0.5–1.0 pp at 70B scale, it would indicate that the interpolation gap is a fundamental geometric limitation that even large models cannot fully overcome through learning — making Resonance RoPE valuable at all scales. A parallel experiment would test whether the gain depends on the *relative* fine-tuning budget (tokens per parameter): with a fixed 100M token budget, the 7B model receives ~14 tokens per parameter while the 70B model receives only ~1.4 tokens per parameter, potentially under-training the larger model. Testing with a parameter-matched token budget (e.g., 100M tokens for 7B, 1B tokens for 70B) would disambiguate model scale effects from training budget effects.

**Developing a learned wavelength perturbation that goes beyond simple integer rounding to optimize for downstream task performance rather than geometric alignment.** Resonance RoPE's wavelength rounding minimizes the interpolation gap (drives `h_i` to zero for pre-critical features, per Theorem 1), but the paper does not claim that zero interpolation gap is *optimal* — only that it is better than the status quo. It is possible that a small, non-zero interpolation gap is actually beneficial, acting as a form of regularization that encourages the model to learn smoother functions of position. Alternatively, different downstream tasks might benefit from different wavelength perturbations: tasks requiring fine-grained local position discrimination (like the Recursive subtask, where Resonance RoPE underperforms standard RoPE) might prefer wavelengths that are *not* integers, to provide denser angular sampling at nearby positions. A follow-up would parameterize the wavelength perturbation as a learned function `˜λ_j = f(λ_j)` trained end-to-end with the model on the target task distribution. This could be implemented as a lightweight network that takes the original wavelength `λ_j` and outputs a perturbed wavelength `˜λ_j`, trained via bilevel optimization (the inner loop trains the Transformer with the perturbed RoPE; the outer loop updates the perturbation network based on validation performance). The learned perturbation could recover integer wavelengths where they help (Semi-Recursive-style long-range attention tasks) and non-integer wavelengths where they hurt (Recursive-style local attention tasks), potentially outperforming both standard RoPE and Resonance RoPE across all task types. The paper's finding that Resonance RoPE degrades Recursive subtask performance (Table 1) provides a concrete motivation: the optimal perturbation is likely task-dependent, and a learned approach could discover this automatically. This direction is computationally intensive but would transform Resonance RoPE from a fixed geometric correction into an adaptive, data-driven position embedding optimization framework.

**Testing Resonance RoPE on vision Transformers and other non-language modalities that use RoPE to assess domain generality.** The paper's claims are restricted to language (all experiments use text data and LLaMA-family architectures), but RoPE is increasingly used in vision (e.g., Vision Transformers with rotary embeddings for 2D position encoding) and multimodal models. The interpolation gap diagnosis depends on two properties: (1) the existence of pre-critical dimensions with non-integer wavelengths shorter than the training sequence length, and (2) the model's sensitivity to the exact discrete set of rotation angles at OOD positions. In vision, the "sequence length" is typically the number of image patches (e.g., 256 for a 16×16 grid), and the critical dimension boundary would fall at a different point in the frequency spectrum. A follow-up would train a ViT with RoPE on, say, 16×16 patches (256 positions) and test on 32×32 patches (1024 positions) with and without Resonance RoPE, measuring classification accuracy and per-position attention pattern consistency. If Resonance RoPE improves vision length generalization, the interpolation gap is a cross-modal phenomenon and the technique has broader applicability than the paper claims. A null result would suggest that the interpolation gap is specific to the sequential structure of language or to the particular wavelength-to-context-length ratios in LLM architectures, narrowing Resonance RoPE's domain of relevance.

**Investigating whether Resonance RoPE's benefit persists under continued pretraining on long sequences, or whether it is primarily valuable in the low-data fine-tuning regime.** The paper fine-tunes LLaMA2-Chat on ~100M tokens of PG19 — a modest budget relative to the trillions of tokens seen during pretraining. This low-data regime is practically important (deploying existing pretrained models on longer contexts without expensive retraining), but it leaves open the question of whether the interpolation gap would be learned away given sufficient long-context training data. A follow-up would pretrain a LLaMA-scale model *from scratch* (or from a mid-training checkpoint) on sequences of mixed lengths — some at the original 4K, some at the target 32K — with either standard RoPE or Resonance RoPE, using a training budget of hundreds of billions of tokens. If the performance gap between standard RoPE and Resonance RoPE shrinks with more long-context training, the interpolation gap is primarily a sample-efficiency problem (Resonance RoPE accelerates adaptation to long contexts but is not strictly necessary given enough data). If the gap persists even after massive long-context training, the non-integer wavelength issue represents a fundamental representational limitation that training cannot overcome — making Resonance RoPE an architectural improvement rather than a training shortcut. This experiment would also clarify whether the paper's FT@4K vs. FT@32K comparison (short-sequence fine-tuning outperforms long-sequence fine-tuning for 7B) reflects a genuine benefit of data diversity or is an artifact of the small fine-tuning budget. With sufficient training data, long-sequence fine-tuning should eventually outperform short-sequence fine-tuning (the model actually sees the relevant position range); if this cross-over occurs later for standard YaRN than for Resonance YaRN, it would indicate that Resonance RoPE improves sample efficiency specifically for long-context adaptation.

### Practical Applications and Downstream Use Cases

**Cost-efficient context window extension for deployed LLaMA-family models.** Organizations running LLaMA2 or LLaMA3 in production with a 4K context window can extend to 32K or 64K using Resonance YaRN with the same fine-tuning recipe (PG19, ~100M tokens, ~400 steps at 4K sequence length) that the paper demonstrates effective for standard YaRN, while obtaining an additional ~1% average accuracy on downstream long-text tasks (Table 2: Resonance YaRN FT@4K achieves 37.58% vs. YaRN's 36.61% for 7B; 39.87% vs. 39.06% for 13B) and 0.1–0.3 lower perplexity on long-document corpora (Figure 4). The Resonance RoPE modification itself is a one-time offline precomputation of 64 floating-point values per attention head — effectively zero engineering cost — and the fine-tuning cost is identical to standard YaRN because Resonance RoPE introduces no additional parameters, no architectural changes, and no runtime overhead. For a deployment serving long-document summarization, multi-turn conversation, or codebase analysis, the ~1% accuracy gain translates to fewer hallucinations and more reliable long-range reasoning at zero marginal inference cost. The FT@4K fine-tuning strategy (training on original-length sequences for more steps) is particularly attractive for organizations with limited GPU memory that cannot fit 32K-length sequences in a single batch even with gradient accumulation, as it requires only 4K-length training while still enabling 32K-length inference.

**Improved data generation for self-improvement pipelines on reasoning tasks requiring long contexts.** When using LLMs to generate training data for themselves — as in STaR (Zelikman et al., 2022), ReST^EM (Singh et al., 2024), or rejection sampling fine-tuning — the model must process long reasoning chains, multi-step proofs, or document-grounded answers that span thousands of tokens. Position embedding failures at OOD positions can cause the model to lose track of earlier steps in the chain, producing incoherent or contradictory training data that degrades rather than improves the model. Replacing standard RoPE with Resonance YaRN before generating self-improvement data would reduce position-related errors in the generated outputs, particularly on tasks requiring variable-distance long-range attention (analogous to the Semi-Recursive POSGEN subtask, where Resonance YaRN achieves 48.46% vs. 33.70% for standard YaRN — a 44% relative improvement). The zero runtime overhead of Resonance RoPE means this improvement comes at no additional generation cost. This application is particularly synergistic with the paper's own limitation analysis: while Resonance RoPE cannot help on tasks where the base model's capability is near zero (difficulty bin 5 in the POSGEN-style continuum), it directly addresses the position-recognition bottleneck that degrades performance on tasks within the model's capability range, which are precisely the tasks where self-improvement data generation is most productive.

**Fine-grained diagnosis of position embedding failures in new model architectures.** Teams developing novel position encoding schemes — whether for long-context LLMs, vision Transformers, or multimodal models — can use POSGEN (or its methodology of constant-difficulty subtasks with varying dependency patterns) as a lightweight diagnostic before scaling to expensive LLM evaluations. The POSGEN experiments in the paper use a 2-layer Transformer trained for 150 epochs on a single V100 GPU — a total cost of a few GPU-hours. By contrast, the LLM experiments require 4 A100 GPUs for fine-tuning and evaluation. A team developing a new position embedding can rapidly test it on POSGEN's three subtasks (Recursive, CoT, Semi-Recursive) to characterize: (a) whether the embedding handles purely local attention (Recursive), (b) whether it supports fixed long-range attention (CoT), and (c) whether it supports variable-distance long-range attention (Semi-Recursive). The per-subtask performance profile — combined with validation loss curves as in Figure 3 — would reveal which failure modes (extrapolation, interpolation, or both) the new embedding addresses and which remain, enabling targeted refinement before investing in expensive LLM-scale experiments. The paper's finding that Resonance RoPE degrades Recursive but improves Semi-Recursive (Table 1) provides a concrete example of the kind of signature that POSGEN can detect: a method that asymmetrically affects long-range attention tasks likely targets the interpolation gap specifically.

### When to Prefer This Method

The paper does not position Resonance RoPE as an alternative to existing RoPE scaling methods but rather as a universal preprocessing step that should be applied before any such method. There is no tradeoff described between using Resonance RoPE and not using it — the computational cost is zero, the implementation is trivial, and the paper demonstrates that Resonance RoPE improves or maintains performance in all tested configurations that combine it with a post-critical scaling method (Resonance YaRN matches or exceeds YaRN on all LLM-scale evaluations). The one exception — where Resonance RoPE alone without any scaling method degrades performance — occurs on a task (Recursive, purely local attention) that is not representative of real-world long-context applications, and the paper's recommendation is explicitly to combine Resonance RoPE with a scaling method like YaRN.

The decision rule is therefore not "when to prefer Resonance RoPE over alternative A" but rather **"when can Resonance RoPE be applied, and when must it be combined with another method?"**:

- **Always apply Resonance RoPE when using any RoPE-based scaling method (YaRN, NTK-Aware, Positional Interpolation) for context window extension.** The paper's experiments show consistent, additive gains across two model sizes (7B, 13B), two fine-tuning strategies (short-sequence, long-sequence), and multiple downstream tasks. The one-line implementation (Algorithm 1) has zero runtime cost and cannot degrade performance when combined with a method that handles post-critical dimensions, because Resonance RoPE only modifies pre-critical features and leaves the scaling method to handle the rest.

- **Resonance RoPE alone (without a scaling method) should only be used if the target extension is small enough that no features have wavelengths exceeding the training length.** In the paper's POSGEN experiments, Resonance RoPE alone degrades Recursive subtask performance because the model's 4× context extension (64 → 256) creates post-critical dimensions with extrapolation that Resonance RoPE does not address. The paper explicitly states that "this method does not solve the extrapolation issue on RoPE's post-critical dimensions" (Limitations section) and recommends combination with a scaling method. For very small extensions (e.g., 4K → 5K where few or no features cross the critical dimension threshold), Resonance RoPE alone might suffice, but this regime is not tested in the paper.

- **For deployments where fine-tuning is infeasible (zero-shot context extension), prefer Dynamic NTK-Aware scaling over Resonance RoPE-based methods.** The paper shows that Dynamic NTK-Aware without fine-tuning achieves competitive performance (32.59% average on L-Eval for 7B, 35.62% for 13B) and does not require Resonance RoPE's pre-critical dimension modification, which itself requires a scaling method to handle post-critical features — and all scaling methods tested in the paper that work well without fine-tuning (Dynamic NTK-Aware) recompute RoPE features dynamically rather than using a fixed scaled `˜Θ` that Resonance RoPE precomputes. The paper does not test Resonance RoPE with Dynamic NTK-Aware, and the interaction between integer wavelength alignment and dynamic scaling factor computation is unexplored, making this combination speculative. For zero-shot settings, Dynamic NTK-Aware without Resonance RoPE is the safer choice based on current evidence.
