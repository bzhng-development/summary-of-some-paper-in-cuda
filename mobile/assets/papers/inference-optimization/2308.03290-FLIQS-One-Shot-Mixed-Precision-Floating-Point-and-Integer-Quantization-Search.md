# FLIQS: One-Shot Mixed-Precision Floating-Point and Integer Quantization Search

**ArXiv:** [2308.03290](https://arxiv.org/abs/2308.03290)

## 🎯 Pitch

For identical per-layer bitwidths, floating-point formats consistently beat integer formats—a finding made practical by FLIQS, the first one-shot mixed-precision search that needs no retraining. By pairing a reinforcement learning controller with a novel cosine entropy schedule, it jointly discovers optimal floating-point and integer assignments alongside neural architecture dimensions, discovering that adding channels or larger kernels can be cheaper than more bits under fixed compute budgets.

---

## 1. Executive Summary

This paper introduces **FLIQS (Floating-Point and Integer Quantization Search)**, the first one-shot mixed-precision quantization search framework that eliminates the need for post-search retraining by employing a cosine entropy regularization schedule that gradually reduces policy exploration during training. Evaluated on convolutional networks (ResNet-18/50, MobileNetV2, EfficientNet, InceptionV3) and vision transformers (DeiT-B16) using ImageNet, FLIQS uses a reinforcement learning controller to assign per-layer numerical formats — spanning integer (INT4 through INT8) and low-precision floating-point (E2M1 through E6M1, including FP8 variants like E4M3) — while simultaneously optimizing channel widths and kernel sizes in its FLIQNAS extension, with model cost measured in billions of bit-operations (GBOPs) using a quadratic cost model that reflects hardware area and power scaling. The framework achieves substantial accuracy improvements over prior work at equivalent cost: integer FLIQS-L improves ResNet-18 by 1.31 percentage points and ResNet-50 by 0.90 points over previous mixed-precision methods, floating-point FLIQS-L improves MobileNetV2 by up to 0.98 points over state-of-the-art FP8 models, and the joint quantization-neural architecture variant (FLIQNAS) improves MobileNetV2 by an additional 2.69 points at similar cost, establishing that floating-point formats consistently outperform integer formats at identical total bitwidths and that for fixed compute budgets, allocating resources to architectural dimensions (channel width, kernel size) becomes preferable to increasing bitwidth as model cost targets grow.

## 2. Context and Motivation

### The Core Problem: Hardware Diversity Has Outpaced Our Ability to Assign Numerical Formats

The fundamental challenge this paper addresses is a **mismatch between hardware capability and software methodology**. Modern AI accelerators — Google TPUv3, NVIDIA Hopper/Ampere GPUs, AMD Xilinx FPGAs — now support multiple numerical formats within the same device, including various integer precisions (INT4, INT8) and low-precision floating-point formats (FP8 variants like E4M3 and E5M2, as well as non-standard FP4/FP5/FP6 types on reprogrammable fabrics). This hardware diversity creates an opportunity: different layers of a deep neural network exhibit different sensitivity to quantization error, so assigning them different formats can yield better accuracy-to-cost ratios than uniform precision across the entire model.

However, this opportunity comes with an **assignment problem**: given a model with tens to hundreds of layers and a candidate set of, say, 16 floating-point formats plus several integer precisions, the space of possible per-layer format assignments is enormous (the paper cites **approximately 10²⁵ configurations** for a pure quantization search on ResNet-18 with 53 tunable layers, and over **10¹⁰⁰** when neural architecture parameters are included). Manual assignment is clearly infeasible at this scale, and even heuristics-based approaches (e.g., "give more bits to the first and last layers") cannot reliably find Pareto-optimal configurations across the full accuracy-cost frontier.

This gap is practically significant for several reasons the paper establishes throughout Section 1 and the related work discussion:

- **Legacy model adaptation**: Organizations with deployed models need to port them to new hardware generations that support different format combinations. Without an automated search, this porting requires either costly manual tuning or accepting suboptimal uniform-precision defaults that either waste hardware capability (by using more bits than necessary on insensitive layers) or sacrifice accuracy (by using too few bits on sensitive layers).

- **Hardware-software co-design**: For custom accelerator development, understanding which formats a future chip should support requires knowing how different layers use precision. An automated search over candidate format sets provides empirical evidence for hardware design decisions — for instance, the paper's finding that floating-point consistently outperforms integer at identical bitwidths has direct implications for which compute units should populate the silicon.

- **Deployment diversity from edge to cloud**: A model trained once may be deployed across devices with radically different format support (BF16 on TPUv3, INT8 on some edge NPUs, FP8 on next-generation GPUs, arbitrary precision on FPGAs). Manually tuning layer formats for each deployment target is economically unviable. An automated search that can accept different format candidate sets as input makes this workflow tractable.

### Conflicting Design Philosophies in Prior Work

The paper is motivated by a tension between two broad categories of prior quantization search methods, each with fundamental tradeoffs that prevent either from being a complete solution:

**Post-training quantization (PTQ) searches** — including HAQ, ReLeQ, and the HAWQ series (v1, v2, v3) — perform the format assignment search *after* the model is already trained. Their advantage is simplicity: no training interference, no modification to the training pipeline, and relatively fast search over format configurations using proxy metrics (Hessian spectrum, layer sensitivity estimates, integer linear programming formulations). But this separation creates a fundamental limitation: the search cannot benefit from **quantization-aware training (QAT)**, where the model's weights adapt to the quantization error during training. As the paper states in Section 2:

> "being PTQ-based, these methods cannot take advantage of the higher accuracy and more accurate feedback provided by quantization-aware training (QAT) during the search."

This feedback gap matters because quantization error is not merely an inference-time penalty — it changes the loss landscape, and a model trained with quantization from the start converges to a different (and generally better) optimum than a model quantized post-hoc. A PTQ search receives quality signals from a model that was *never optimized for quantization*, so the accuracy estimates it uses to make format decisions are systematically pessimistic, especially for very low bitwidths where the gap between QAT and PTQ is largest. The paper's results in Table 1 bear this out: FLIQS, which conducts the search during QAT, consistently outperforms PTQ-based methods like HAWQ-V3 at comparable or lower model cost (GBOPs).

**Quantization-aware training (QAT) searches** embed the format search within the training process itself. These typically follow one of two sub-approaches:

- **Multi-trial RL methods**: train separate models for each candidate configuration sequentially. This provides accurate quality feedback (since each configuration gets a full training run) but is computationally prohibitive for large search spaces — training dozens of separate ResNet-50 variants from scratch is impractical at scale.

- **Differentiable NAS / super-network methods**: replicate weights and activations for each candidate format as parallel branches, form a continuous relaxation (e.g., a softmax-weighted combination of branch outputs), and optimize both the layer weights and the branch importance weights jointly via gradient descent. Representative works include EDMIPS, MPQ, and DNAS. The paper identifies a critical problem with this approach in Section 2:

> "because they replicate the weights and activations, they incur higher memory and computational costs compared to RL-based methods."

Table 6 in the appendix quantifies this: for a ResNet-18 with batch size 32, a representative differentiable ("branched") search requires **92.6 MiB** for gradients, **70.2 MiB** for weights, and **220.8 MiB** for activations — roughly double FLIQS's requirements across all memory categories. This memory explosion limits differentiable searches to smaller models or smaller search spaces, which is precisely the opposite direction from where the field is heading as models grow larger.

More subtly, differentiable searches suffer from a **coupling problem**: the relaxation that enables gradient-based optimization (maintaining all branches simultaneously) creates unrealistic interactions between format choices at different layers. A branch for INT4 on layer 3 is trained alongside a branch for INT8 on layer 3, but at deployment time only one will be used. This train-time co-adaptation across branches can lead to configuration rankings that don't transfer to the discrete final model.

Both PTQ and QAT prior works share another limitation: after the search identifies a format configuration, the model undergoes **an additional retraining or fine-tuning step** from scratch or from a checkpoint, using only the selected format. This retraining is necessary because the search process (whether PTQ with calibration data or QAT with multiple branches) disturbs the weights. But retraining adds cost, and for QAT approaches, it raises a question: if you're going to retrain anyway, was the expensive in-training search worthwhile? FLIQS's key contribution — enabling deployment *without retraining* — directly addresses this inefficiency.

### The Unexplored Territory: Floating-Point Quantization Search

Prior to this work, essentially all mixed-precision quantization search methods operated exclusively on **integer formats** (INT4, INT8, etc.). This reflected the historical reality that hardware supported integers for inference, but the hardware landscape has shifted — FP8 is now standardized across major vendors (AMD, Intel, NVIDIA, Qualcomm) and programmable fabrics like FPGAs support arbitrary floating-point formats. The paper states in Section 2:

> "Low-precision floating point is being discussed as the next generation format for DNN training and inference."

Yet despite this shift, no prior work had conducted a systematic search over mixed-precision floating-point formats. The existing FP8 literature (HFP8, MPFP, FPQuant) focused on *uniform* precision: every layer uses the same FP8 variant (typically E4M3 for inference, E5M2 for training gradients). This uniform approach leaves significant accuracy on the table because, as the paper demonstrates, different layers exhibit different quantization characteristics under floating-point. For example, the paper's per-layer analysis in Figures 3 and 8–9 shows that depthwise convolutions and attention blocks are systematically assigned higher-precision floating-point formats than pointwise convolutions in MobileNetV2 and DeiT — a pattern that uniform FP8 cannot capture.

The paper therefore positions itself as filling a **dual gap**: providing the first search framework that (1) operates across both integer and floating-point format spaces, and (2) produces mixed-precision floating-point configurations that outperform uniform FP8 baselines. The floating-point FLIQS-L results in Table 1 (e.g., +1.93% ImageNet accuracy on ResNet-18 versus MPFP [8] at one-third the GBOPs) validate that this gap was consequential.

### The One-Shot Challenge: Why No Retraining Is Hard

The paper's central technical ambition — a **one-shot search without retraining** — addresses a challenge acknowledged implicitly by prior QAT search work: the search process itself disturbs model training. The paper formalizes this disturbance through its concept of **switching error** (Section 4, Equations 4–7), which quantifies the noise introduced when a layer's quantizer changes from one bitwidth to another between training steps.

The challenge can be understood intuitively: if layer 3 is INT4 at step 10,000 and switches to INT8 at step 10,001, the weight gradients computed at step 10,001 are based on the quantized weights from the *previous* format configuration. This creates a lag in the optimizer's gradient estimates — SGD or Adam sees gradients that correspond to a stale quantization state. As the search continues to switch formats, this lag accumulates as effective noise in the optimization, pushing the converged solution away from the true optimum. The paper demonstrates (Equation 6) that this switching error is proportional to the **policy entropy** — how uncertain the controller is about which format to assign. High entropy (early training, when the controller is exploring) means frequent, large-magnitude format switches and therefore high optimization noise.

Prior one-shot QAT methods attempted to manage this noise through heuristics: MPQ gradually freezes the bitwidths of specific layers during training, and EDMIPS alternates between training layer weights and branch weights. But neither provided a principled mechanism to drive the noise to zero by the end of training — models emerged from the search process with residual optimization noise, requiring the retraining step to recover accuracy. The paper's entropy regularization schedule (Equation 9) is the proposed solution: by explicitly driving policy entropy toward zero via a cosine schedule, the expected switching error converges to zero by the end of training, making the model deployable directly from the search process. Figure 4(b) visually demonstrates this property: the entropy curve falls smoothly, and the policy probabilities converge to near-deterministic assignments. Appendix Table 8 confirms empirically that retraining after FLIQS provides no accuracy benefit when sufficient entropy regularization is applied.

### Systematic Comparison Across Formats and Architectures

A final motivation is the absence in prior literature of a **large-scale, controlled comparison** between mixed-precision integer and floating-point models. The paper notes this explicitly as its third listed contribution:

> "Perform the largest comparison of integer and floating-point mixed-precision networks."

Establishing whether floating-point formats actually *improve* accuracy over integers at equivalent bitwidth — rather than merely providing a different tradeoff curve — has implications beyond search methodology. If floating-point consistently outperforms integer (as Figure 5 and Appendix Figure 12 demonstrate), then hardware designers should prioritize floating-point compute units, and software deployments should prefer floating-point quantization when hardware support exists. The paper's finding that floating-point dominates integer at identical total bitwidths (Section 5, "Joint integer and floating-point searches were attempted; however, since floating-point dominates integer formats at the same total bitwidths, the outputs of these searches were the same as the pure floating-point searches") provides a clean empirical answer to this open question.

Additionally, the joint quantization-neural architecture search (FLIQNAS, Section 6) addresses a subtler question: for a fixed compute budget, should we spend it on **higher bitwidth** (more precise arithmetic per operation) or on **larger architectural dimensions** (more channels, larger kernels, more operations total)? This tradeoff has not been studied for floating-point formats. The paper's finding — that at high cost targets, architectural scaling dominates bitwidth scaling — provides actionable guidance for model designers allocating compute across these dimensions.

## 3. Technical Approach

### 3.1 Reader orientation (approachable technical breakdown)

FLIQS is a reinforcement learning controller embedded inside a standard neural network training loop that simultaneously trains the model *and* searches for the best per-layer numerical format (e.g., INT4, INT8, E4M3 floating-point) and optionally architectural dimensions (channel widths, kernel sizes), delivering a fully-trained quantized model at the end without any separate retraining step. It solves the assignments problem — given dozens of layers and up to 16 candidate formats, which layer gets which precision? — by treating format selection as a sequential decision process where the controller gradually settles on a deterministic configuration as training progresses, guided by a reward function that balances classification accuracy against a quadratic hardware cost model.

### 3.2 Big-picture architecture (diagram in words)

The system has four major components that interact in a loop during training:

**Component 1: The Base Model with Quantization** — a standard neural network (ResNet, MobileNet, DeiT, etc.) where each layer's weights and activations pass through a simulated quantization function before being used in the forward pass. The quantization is "fake" quantization — values are rounded to the nearest representable number in the current format but stored in full precision to enable gradient computation through a straight-through estimator. Every layer has a *current format* assigned to it, which changes during the search.

**Component 2: The RL Controller** — a lightweight policy module that outputs a probability distribution over candidate formats (and optionally architectural choices like channel widths) for each layer. At each training step, the controller samples a configuration, applies it to the base model, and later receives a reward signal to update its policy. The policy is parameterized by per-layer logits `$\theta_{l,\alpha}$` that are converted to probabilities via softmax.

**Component 3: The Cost Model** — a quadratic bit-operations (BOPs) estimator that computes the hardware cost of the current configuration based on each layer's total bitwidth squared multiplied by its MAC count. This cost is combined with the validation accuracy to form the reward.

**Component 4: The Entropy Regularization Schedule** — a cosine-scheduled loss term added to the RL policy loss that gradually forces the controller to stop exploring and commit to a single format per layer by the end of training, driving the switching noise to zero and eliminating the need for retraining.

Information flows as follows: training data enters → the RL controller samples per-layer formats (and optionally architecture parameters) → the base model's layers are quantized according to the sampled formats → a forward pass computes the training loss and updates model weights via SGD/Adam → a separate forward pass on validation data produces a quality signal (accuracy) → the quality signal is combined with the BOPs cost to produce a reward → the reward advantage (difference from running average) updates the controller's policy via REINFORCE → entropy regularization is applied to the policy loss → repeat for the entire training duration → at the end, the controller has converged to near-deterministic format assignments, and the model is used directly for inference.

### 3.3 Roadmap for the deep dive

- **First**, the quantization mechanism itself — how fake quantization works, the two-phase weight/activation quantization strategy, and the switchable clipping thresholds — because all format decisions operate on quantized values.
- **Second**, the quadratic cost model and the absolute reward function, since these define what the controller is *optimizing for* and how accuracy and cost are traded off.
- **Third**, the RL controller architecture and the REINFORCE update, since this is the decision-making core that searches the format space during training.
- **Fourth**, the switching error analysis and entropy regularization schedule, which is the key technical innovation that makes one-shot search without retraining possible.
- **Fifth**, the format search spaces (FLIQS-S vs. FLIQS-L) for both integer and floating-point, to ground what the controller is choosing from.
- **Sixth**, the FLIQNAS extension that jointly searches quantization formats and neural architecture dimensions (channel widths, kernel sizes), building on the base FLIQS mechanisms.

### 3.4 Detailed, sentence-based technical breakdown

This is primarily a **systems and optimization paper** whose core idea is that per-layer numerical format assignment can be formulated as a reinforcement learning problem embedded within the training loop, and that driving the policy entropy to zero via a scheduled regularizer eliminates the switching noise that previously prevented one-shot quantization search from working without retraining.

#### Quantization Mechanism and Two-Phase Training

The base model undergoes fake quantization, where values are rounded to the nearest representable number in the target format but stored in full floating-point precision. The quantizer operates by first clipping the input to a threshold `$\sigma_t$`, then scaling it to the representable range of the target format, rounding to the nearest valid value, and rescaling back. Formally (from Appendix A.2):

$$x_q = \lfloor s \cdot \sigma(x_f; \sigma_t) \rceil$$

> where `$x_f$` is the original full-precision value, `$\sigma(x_f; \sigma_t) = \max(-\sigma_t, \min(x_f, \sigma_t))$` is the clipping function that bounds values to `$[-\sigma_t, \sigma_t]$`, `$s$` is the scale factor that normalizes the clipped value to the format's maximum representable number, and `$\lfloor\cdot\rceil$` represents rounding to the nearest representable value in the target format (integer grid for integer formats, non-uniform grid for floating-point formats due to the exponent).

**What it computes:** the full-precision input is first truncated to the clipping range, then multiplied by the scale factor to map it into the format's representable range, rounded to the nearest valid value in that format, and the result is the quantized output `$x_q$`. The scale factor `$s$` is determined at runtime from the profiled statistics of the weights and activations — specifically, for activations the clipping threshold `$\sigma_t$` is set as a multiple (typically 3–4×) of the profiled standard deviation of the activation tensor, and `$s = (2^{k-1} - 1) / \sigma_t$` for a symmetric integer quantizer with bitwidth `$k$`.

**Why this form:** separate clipping and scaling is necessary because different bitwidths require different dynamic range tradeoffs. Lower bitwidths have fewer quantization levels, so they benefit from more aggressive clipping (smaller `$\sigma_t$`) to reduce rounding error on the central mass of the distribution, even though this increases clipping error on outliers. Higher bitwidths can afford less clipping because they have enough levels to span the full dynamic range. Using a single global clipping threshold would force a compromise that is suboptimal for both low and high bitwidth layers. The paper uses pre-computed clipping thresholds per layer rather than learned thresholds, finding empirically (Appendix A.2, Table 10b) that 3–4× the standard deviation works well across models and avoids the complexity and instability of learning per-layer thresholds during the search.

The quantization process is applied in **two phases** (Section 3, main text; Appendix A.2):

- **Phase 1 (weight-only quantization):** from training step 0 until a specified activation quantization start step, only the model weights are quantized during the forward pass. Activation values remain in full precision. This allows the model to adapt its weight distribution to the quantization constraint before adding the more disruptive activation quantization.

- **Phase 2 (weight and activation quantization):** after the activation start step, both weights and activations are quantized. The paper sweeps this start step empirically (Appendix A.2, Table 10a) and finds the optimum at approximately 15–20% of total training time. For ResNets and InceptionV3 (trained to 30,200 steps), activation quantization begins at step 7,500. For MobileNetV2, EfficientNet, and DeiT (trained for 112,000 steps or longer), it begins at step 15,000–20,000.

**Why two phases:** starting activation quantization at the very beginning of training (single-phase QAT) leads to severe optimization difficulty because the model must simultaneously learn the task and adapt to activation quantization noise while the weight distributions are still rapidly changing. Starting activation quantization too late (hybrid QAT-PTQ) means the model has already converged its internal representations without activation quantization, so applying it post-hoc gives no chance for the weights to compensate. The 15–20% sweet spot provides a warmup period for weight quantization followed by enough joint training for activation adaptation.

**Switchable clipping thresholds** (Section 3, main text) extend this concept to the search setting. Since the controller assigns different formats to a given layer at different training steps, the clipping threshold must change when the format changes. The paper implements this by pre-computing per-format per-layer clipping thresholds, typically using synthetic data or profiled statistics from the first training phase. When the controller switches a layer from, say, INT4 to INT8, the layer's clipping threshold correspondingly switches from the pre-computed INT4 threshold to the pre-computed INT8 threshold. This is motivated by Figure 4(a), which shows that the optimal clipping threshold (the percentile value that minimizes quantization MSE on synthetic data) shifts substantially as bitwidth changes — lower bitwidths require more aggressive clipping (lower percentile) to manage the coarser quantization grid.

**Why pre-computed rather than learned thresholds:** learning per-layer clipping thresholds during the search would add additional parameters that must adapt to the changing format assignments, creating a circular dependency where clipping thresholds are optimized for one format but then applied under a different format after the controller switches. Pre-computing stabilizes the training by decoupling threshold selection from format search.

#### Cost Model and Reward Function

The controller's decisions are guided by a reward function that combines model quality and hardware cost. The cost model uses bit-operations (BOPs), defined per layer `$l$` for an architecture `$\alpha$` as:

$$C_l(\alpha) = b(\alpha)^2 \cdot \text{MAC}_l(\alpha)$$

> where `$b(\alpha)$` is the **total bitwidth** of the arithmetic (the sum of weight bitwidth and activation bitwidth) for the format assigned to layer `$l$` under architecture `$\alpha$`, and `$\text{MAC}_l(\alpha)$` is the number of multiply-accumulate operations in layer `$l$` under that architecture (which depends on channel widths and kernel sizes if architecture search is enabled). In the appendix table notation, "GBOPS" represents this quantity summed across all layers, divided by `$10^9$`.

**What it computes:** for each layer, square the total arithmetic bitwidth (combined weight + activation precision), multiply by the layer's MAC count, sum across all layers. This produces a scalar cost that approximates hardware area and power consumption. The squaring is critical: it captures the fact that multiplier area and power scale quadratically with bitwidth in digital logic. A layer with 8-bit arithmetic costs approximately 4× as much as the same layer with 4-bit arithmetic, all else equal.

**Why this form:** the quadratic relationship is justified by hardware design principles (Section 3, citing PokeBNN [28]): "multipliers dominate resources and scale quadratically in power and area." Table 2 validates this empirically on a Xilinx UltraScale+ FPGA, showing that look-up table (LUT) counts — which serve as an area proxy — scale quadratically with bitwidth. A pure linear cost model (`$b(\alpha) \cdot \text{MAC}_l$`) would under-penalize higher bitwidths and lead the controller to overallocate precision, since the accuracy benefit of an extra bit does not scale quadratically. The quadratic model correctly makes high-bitwidth layers expensive relative to their marginal accuracy contribution.

The total model cost `$C(\alpha) = \sum_l C_l(\alpha)$` is combined with the quality signal in the **absolute reward function** (Equation 1 in the main text, adapted from Tunas [29]):

$$r(\boldsymbol{\alpha}) = Q(\boldsymbol{\alpha}) + \gamma \left| \frac{\sum_l C_l(\alpha)}{C_T} - 1 \right|$$

> where `$Q(\boldsymbol{\alpha})$` is the quality signal — typically the validation accuracy (ImageNet Top-1) on a held-out batch — measured after applying the architecture `$\boldsymbol{\alpha}$` to the model, `$C_T$` is a user-specified **cost target** that controls where on the accuracy-efficiency Pareto frontier the search should operate, and `$\gamma$` is a scalar weight that balances the importance of the cost constraint versus the quality signal.

**What it computes:** the reward is the validation accuracy *plus* a penalty term proportional to how far the current model's cost deviates from the target `$C_T$`. If the model's BOPs exactly match `$C_T$`, the penalty term is zero and the reward equals the accuracy. If the model costs more than `$C_T$`, the absolute deviation becomes positive but is multiplied by `$\gamma$` and added to the accuracy (since the reward is being *maximized*, this is a penalty — a larger deviation reduces the reward relative to what the accuracy alone would give). If the model costs less than `$C_T$`, the deviation term is again positive, penalizing models that are too cheap as well as too expensive — this prevents the controller from collapsing to minimum bitwidth for everything, since the accuracy would then suffer.

**Why this form:** the absolute-value penalty around a target (rather than, say, a linear reward `$Q - \lambda C$`) gives the user direct, interpretable control over the operating point. By sweeping `$C_T$` across multiple values and running separate searches, the paper generates entire Pareto curves (Figure 5) showing the best achievable accuracy at each cost level. The absolute value form also means the controller is not incentivized to reduce cost far below the target at the expense of accuracy — hitting the target exactly is optimal, so the search allocates precision where it maximally improves accuracy until the budget is exhausted. Alternative formulations like `$Q - \lambda C$` would require careful tuning of `$\lambda$` for each target and could produce solutions far from the frontier if `$\lambda$` is poorly chosen.

The cost target `$C_T$` and scalar `$\gamma$` are the primary knobs the user controls. The paper does not specify exact values of `$\gamma$` used but the cost target is swept to produce the Pareto curves (different points in Figure 5 correspond to different `$C_T$` values). The absolute reward function is taken from prior work on weight-sharing NAS (Tunas, Bender et al. [29]), adapted here to the quantization domain.

#### Reinforcement Learning Controller Architecture and Update

The controller is responsible for proposing per-layer format (and optionally architecture) configurations at each training step. It learns a policy `$\pi_l(\alpha)$` for each layer `$l$` that is a probability distribution over the candidate architectures `$\alpha$` for that layer (e.g., {INT4, INT8, BF16} for FLIQS-S integer search, or 16 floating-point formats plus BF16 for FLIQS-L floating-point search). The policy is parameterized by per-layer, per-candidate logits `$\theta_{l,\alpha}$`:

$$\pi_l(\alpha) = \frac{\exp(\theta_{l,\alpha})}{\sum_j \exp(\theta_{l,j})}$$

> where `$\theta_{l,\alpha}$` is a learned scalar weight for candidate `$\alpha$` in layer `$l$`, and the denominator sums over all candidates `$j$` in the search space for layer `$l$`. This is a standard softmax over the logits.

**What it computes:** the probability that the controller will select format `$\alpha$` for layer `$l$`. Higher logits `$\theta_{l,\alpha}$` correspond to higher selection probability. The softmax ensures probabilities are non-negative and sum to 1 across all candidates for each layer.

**Why this form:** the softmax parameterization is simple, differentiable (enabling gradient-based policy updates), and naturally handles the requirement that each layer gets exactly one architecture at each step (the controller samples from the categorical distribution defined by the softmax, so exactly one candidate is selected per layer per step). More complex policy models (e.g., multi-layer perceptrons that condition on layer position or neighboring layer decisions) were explored but "offered no quality improvements while being more costly" (Section 3, RL Controller paragraph), so the paper uses this factorized per-layer parameterization.

**Channel width selection** (for FLIQNAS, the joint quantization-architecture search) is handled separately and efficiently through **channel masks** — rather than actually changing the convolutional layer's weight tensor size, the full-precision weights are stored at the maximum width, and a binary mask zeroes out the channels not included in the current architecture. This avoids the overhead of repeatedly reshaping tensors and reallocating memory during the search.

At each training step, the controller samples a full model architecture `$\boldsymbol{\alpha} = \{\alpha_l\}_{l=1}^L$` by independently sampling each layer's format from its policy distribution. The sampled architecture is applied to the base model (formats and channel masks updated), and a forward-backward pass on training data updates the model weights. Separately, a forward pass on validation data produces the quality signal `$Q(\boldsymbol{\alpha})$`. The reward `$r(\boldsymbol{\alpha})$` is computed using Equation 1.

Because the validation accuracy naturally increases throughout training (the model is learning), the raw reward `$r(\boldsymbol{\alpha})$` would drift upward even if the architecture were fixed. To isolate the architecture's *relative* quality from this training drift, the paper uses a **reward advantage** `$r_\Delta(\boldsymbol{\alpha})$`:

$$r_\Delta(\boldsymbol{\alpha}) = \bar{r}(\boldsymbol{\alpha}) - r(\boldsymbol{\alpha})$$

> where `$\bar{r}(\boldsymbol{\alpha})$` is the **running average** of rewards received for architecture `$\boldsymbol{\alpha}$` over previous steps, and `$r(\boldsymbol{\alpha})$` is the current step's reward.

**What it computes:** the difference between how well the current architecture performed *in the past* (when the model was less trained) and *now* (when the model is more capable). If the current reward is *higher* than the running average (the architecture is performing unusually well given the training progress), `$r_\Delta$` is negative, and since the REINFORCE update (Equation 3) multiplies the gradient by `$-r_\Delta$`, this increases the probability of the sampled architecture. If the current reward is *lower* than the running average, `$r_\Delta$` is positive, decreasing the probability.

**Why this form:** without the advantage baseline, the controller would simply learn to prefer architectures sampled later in training (when accuracy is naturally higher), regardless of their intrinsic quality. The running average subtracts out the training progress effect, leaving only the architecture-specific quality signal. This is analogous to the advantage function in actor-critic RL, but implemented simply via a running average rather than a learned value function, which the paper notes is chosen "due to its low complexity."

The policy is updated using the **REINFORCE** algorithm (Equation 3). The policy loss is:

$$\mathcal{L}_\theta = -r_\Delta(\boldsymbol{\alpha}) \sum_l \log(\alpha_l \sim \pi_l(\alpha))$$

> where `$\log(\alpha_l \sim \pi_l(\alpha))$` is the log-probability of the action that was actually sampled (i.e., `$\log \pi_l(\alpha_l)$` for the chosen `$\alpha_l$`), and the sum is over all layers.

**What it computes:** the REINFORCE policy gradient loss. The gradient of this loss with respect to `$\theta$` increases the log-probability of actions that produced a positive reward advantage (`$r_\Delta < 0$`, meaning the reward exceeded the running average) and decreases the log-probability of actions that produced a negative reward advantage (`$r_\Delta > 0$`, reward below the running average). The parameter update is then a standard gradient descent step: `$\theta \leftarrow \theta + \eta \nabla_\theta \mathcal{L}_\theta$` where `$\eta$` is the RL learning rate (set to `$4.6 \times 10^{-3}$` with Adam optimizer momentum of 0.95, per Appendix A.4).

**Why REINFORCE over alternatives:** REINFORCE is chosen for its simplicity and low overhead. The paper states that "other reinforcement learning methods, such as PPO, and more sophisticated policy models, such as multi-layer perceptron models, offered no quality improvements while being more costly" (Section 3, RL Controller paragraph). Since the controller must run inside the training loop, overhead matters — a slower controller would increase total training time multiplicatively across hundreds of thousands of steps. REINFORCE with the simple running-average baseline is the minimal viable policy gradient method that provides unbiased gradient estimates with variance reduction from the baseline.

The RL controller operates during the final 75% of training — there is a warmup period lasting the first 25% of training steps where the controller's policy is not updated, and architectures are sampled uniformly at random (Appendix A.4). This warmup allows the base model's weights to stabilize before the controller begins influencing format assignments, and allows the running reward averages `$\bar{r}(\boldsymbol{\alpha})$` to accumulate enough statistics to be meaningful baselines.

**Search Parameters** (Appendix A.4, Table 6): The controller adds one parameter per searched layer per searched candidate. For a ResNet-18 on FLIQS-S (3 candidates per layer) with all layers searched, this adds approximately 51 MiB of additional parameters beyond the model weights — negligible compared to the model itself. The controller uses a standard softmax cross-entropy loss formulation (the REINFORCE loss is cross-entropy between the policy and the sampled actions, weighted by the advantage) with label smoothing coefficient 0.1.

#### Switching Error Analysis and Entropy Regularization

The core technical challenge for one-shot quantization search is that changing a layer's format during training introduces **switching error** — noise in the optimizer's gradient estimates caused by the mismatch between the current quantizer and the quantizer used for the previous gradient step. The paper formalizes this concept in Section 4.

Consider a symmetric integer quantizer `$Q(x; s)$` with scale factor `$s = (2^{k-1} - 1) / \sigma_T$`, where `$\sigma_T$` is the clipping threshold. The absolute quantization error for a single format is:

$$\Delta(x; s) = |Q(x; s) - x|$$

When the format changes from bitwidth `$k_1$` to bitwidth `$k_2$` (with corresponding scale factors `$s_1, s_2$` determined by `$k_1, k_2$` and fixed `$\sigma_T$`), the **switching error** is defined as:

$$\Delta_S(x; k_1, k_2) = |Q(x; k_2) - Q(x; k_1)|$$

> where `$x$` is the input value (a weight or activation), `$k_1$` is the previous bitwidth, `$k_2$` is the new bitwidth, `$Q(x; k_1)$` is the quantized value under the old format, and `$Q(x; k_2)$` is the quantized value under the new format.

**What it computes:** the absolute difference between what the quantized value *was* under the previous format configuration and what it *is* under the new format configuration. This represents a discontinuity in the loss surface from the optimizer's perspective: the weights adapted to gradients computed with `$Q(x; k_1)$`, but now the forward pass uses `$Q(x; k_2)$`, so the stored weight values are slightly wrong for the new quantizer.

**Why this form matters:** Figure 4(a) shows that this switching error is substantial, especially when one of the bitwidths is small. When going from INT4 to INT8 (or vice versa), the difference between the two quantized representations can be several percent of the value range. This error manifests as additional noise in the stochastic gradient estimates — SGD or Adam sees gradients that are partially based on stale quantization, pushing the weights away from what would be optimal for the current format. Over many format switches during training, this noise accumulates and prevents convergence to a sharp optimum.

The paper connects switching error to policy entropy through a probabilistic argument. At any point in the search, the expected switching error over random format switches is proportional to the entropy of the controller's policy. The total policy entropy `$H_M$` of the model `$M$` is:

$$H_M = -\sum_{l \in M} \sum_k \pi_l(k) \log \pi_l(k)$$

> where the outer sum is over all layers `$l$` in the model, the inner sum is over all candidate bitwidths `$k$` (or more generally, all format candidates), and `$\pi_l(k)$` is the controller's current probability of selecting bitwidth `$k$` for layer `$l$`.

**What it computes:** the total uncertainty of the controller across all layers. High entropy means the controller is exploring — probabilities are spread across many candidates, so format switches are frequent and large in magnitude (since the candidate set includes widely separated bitwidths like INT4 and INT8). Low entropy means the controller is exploiting — probabilities are concentrated on one or a few candidates, so format switches are rare and, when they occur, tend to be between adjacent bitwidths with smaller switching error.

**Why this connection matters:** if `$H_M$` is high at the end of training, the expected switching error is also high, and the model converges to a noise-ball around the optimum rather than the optimum itself. This is why prior one-shot QAT searches required retraining: they lacked a mechanism to drive the entropy to zero, so the final model weights were optimized for an *average* of format configurations rather than the specific one to be deployed. Retraining with a fixed configuration could then sharpen the solution.

To solve this, FLIQS introduces **entropy regularization** with a cosine schedule. This adds a regularization term to the policy loss `$\mathcal{L}_\theta$` (Equation 8):

$$\mathcal{L} = \mathcal{L}_\theta - \beta_H H_M$$

> where `$\beta_H$` is a scalar coefficient that controls the strength of entropy regularization. A positive `$\beta_H$` *rewards* high entropy (encourages exploration). A negative `$\beta_H$` *penalizes* high entropy (encourages exploitation).

Since FLIQS needs high exploration early (to evaluate many format configurations and learn which are good) and deterministic assignment late (to eliminate switching error before training ends), the paper introduces a **cosine entropy regularization schedule** (Equation 9):

$$\beta_H^{\text{cos}} = -0.5 \beta_H^{\text{end}} (1 + \cos(\pi s)) + \beta_H^{\text{end}}$$

> where `$s \in [0, 1]$` represents the current training progress (0 at the start of the search phase, 1 at the end of training), and `$\beta_H^{\text{end}} = 0.5$` is the final entropy regularization strength.

**What it computes:** the effective entropy coefficient as a function of training progress. At `$s = 0$` (beginning of search), `$\cos(0) = 1$`, so `$\beta_H^{\text{cos}} = -0.5 \cdot 0.5 \cdot 2 + 0.5 = -0.5 + 0.5 = 0$` — no entropy regularization, maximum exploration. At `$s = 1$` (end of training), `$\cos(\pi) = -1$`, so `$\beta_H^{\text{cos}} = -0.5 \cdot 0.5 \cdot 0 + 0.5 = 0.5$` — the full `$\beta_H^{\text{end}}$` is applied. The cosine shape provides a smooth transition between these extremes.

The key insight is that `$\beta_H^{\text{cos}}$` is *subtracted* from the policy loss, but the cosine schedule makes `$\beta_H^{\text{cos}}$` effectively *negative* when interpreted as an entropy penalty. Let's trace the sign carefully: the full policy loss is `$\mathcal{L}_\theta - \beta_H^{\text{cos}} H_M$`. When `$\beta_H^{\text{cos}} = 0.5$` at the end, the term is `$-0.5 H_M$`. Since `$H_M$` is non-negative, adding `$-0.5 H_M$` to the loss *increases* the loss when entropy is high. Minimizing the loss therefore *minimizes* entropy — it pushes the policy toward determinism. At the start, `$\beta_H^{\text{cos}} = 0$`, so entropy has no effect on the loss and the controller explores freely. The transition between exploration and exploitation is smooth, following a cosine curve that is flat near the endpoints and steepest in the middle.

**Why a cosine schedule rather than linear decay:** a cosine schedule spends more time near the extremes (close to full exploration early, close to full exploitation late) and transitions more sharply in the middle, which matches the natural dynamics of policy learning — the controller needs sustained exploration to discover good configurations, then a decisive shift toward exploitation to settle the weights. A linear schedule would force the controller to begin exploiting too early, before it has accumulated enough reward signal to distinguish good from bad formats, or would leave residual entropy at the end.

Figure 4(b) demonstrates the effect of this schedule empirically. The left panel shows that higher entropy regularization (larger `$\beta_H^{\text{end}}$`) leads to higher final accuracy — the controller converges more completely, and the weights undergo fewer disruptive format switches near the end of training. The center panel shows how the entropy itself evolves: it starts high (broad distributions over candidates), remains elevated through the exploration phase, then smoothly decays toward zero as the cosine schedule ramps up the regularization. The right panel shows the corresponding policy convergence — the probability of a specific format (e.g., `$\pi_6(\text{INT8})$`) starts near uniform, then converges to near 1.0 by the end of training.

The **no-retraining** property is validated in Appendix A.11, Table 8. For a ResNet-18 across model widths from 0.5× to 2.0×, FLIQS-S without retraining achieves, e.g., 69.92% Top-1 at 1.0× width, while FLIQS-S with retraining (taking the best configuration and training from scratch) achieves 69.53% — actually slightly worse. Across all widths and both FLIQS-S and FLIQS-L, there is "no noticeable advantage to retraining." This confirms that the entropy schedule successfully drives the switching noise to zero, making direct deployment equivalent to or better than training from scratch with the fixed configuration.

**Why prior methods couldn't do this:** without entropy regularization, one-shot QAT searches maintain high policy entropy throughout training (since there's no incentive to commit). The model at the end has weights adapted to a distribution of formats, and freezing to any single format leaves a gap. PTQ searches avoid the training interference but cannot benefit from QAT, so their accuracy ceiling is lower. Differentiable searches (EDMIPS, MPQ) maintain all branches simultaneously, but the soft weighting creates interactions across branches that don't transfer to discrete selection after the search. Entropy regularization resolves this by ensuring the training process *converges to* a single, specific quantization scheme, with the weights optimized for exactly that scheme.

#### Format Search Spaces: FLIQS-S and FLIQS-L

The controller operates over one of two search spaces that determine which numerical formats are available as candidates per layer. These are categorized by size and hardware target:

**FLIQS-S (Small search space)** — designed for existing hardware with fixed format support:

- **Integer variant:** {INT4, INT8, BF16}. These correspond to the standard formats supported on TPUv3 (INT8, BF16) and modern GPUs like NVIDIA Ampere (INT4, INT8, BF16). FP16 is excluded because "this format typically performs worse than BF16 in most common use cases" (Appendix A.5).
- **Floating-point variant:** {E2M1, E4M3, BF16}. E4M3 is the standard FP8 inference format, E2M1 is a custom FP4 format, and BF16 is the half-precision fallback. This mirrors the integer FLIQS-S in having three candidates spanning low, medium, and high precision.

**FLIQS-L (Large search space)** — designed for customizable hardware like FPGAs and for hardware-software co-design:

- **Integer variant:** {INT4, INT5, INT6, INT7, INT8, BF16} — every integer bitwidth from 4 to 8 inclusive, plus the BF16 fallback. This provides fine-grained control valuable for bit-serial deep learning engines (mentioned in Appendix A.5) that can efficiently implement arbitrary bitwidths.
- **Floating-point variant:** All floating-point formats with total bitwidth between 4 and 8 bits. With 16 such formats — E2M1, E2M2, E2M3, E2M4, E2M5, E3M1, E3M2, E3M3, E3M4, E4M1, E4M2, E4M3, E5M1, E5M2, E6M1, plus BF16 — this is "the largest quantization search performed" (Section 3, Format Search Space) to the authors' knowledge. Each format is specified by `$E$` (exponent bits) and `$M$` (mantissa bits), with total bitwidth = `$E + M + 1$` (the additional bit is for the sign). For example, E4M3 has total bitwidth 4 + 3 + 1 = 8 bits (standard FP8), while E2M1 has total bitwidth 2 + 1 + 1 = 4 bits (custom FP4).

**Floating-point format properties (Appendix A.5):** All custom formats support subnormals (denormalized numbers that provide gradual underflow near zero) and do not support infinity (values that exceed the maximum exponent are saturated to the maximum representable value rather than producing an infinity). The exponent bias is chosen to make the exponent range symmetric about zero, but the paper notes this bias is irrelevant during search because FLIQS uses a profiled per-layer scale factor that absorbs any constant bias — effectively, the scale factor rather than the format's intrinsic dynamic range determines the numerical range.

The key distinction between integer and floating-point for the quantizer: integer formats produce a *uniform* grid of representable values (evenly spaced), while floating-point formats produce a *non-uniform* grid (dense near zero, sparse at large magnitudes). The floating-point quantizer rounds to the nearest value on this non-uniform grid. This is why floating-point can outperform integer at the same total bitwidth: it allocates precision where most weight and activation values live (near zero for normalized distributions), leaving coarser representation for outlier magnitudes that are rare.

**Search space sizes:** For FLIQS-S integer search on ResNet-18 with 53 tunable layers and 3 candidates per layer, the search space has `$3^{53} \approx 10^{25}$` possible configurations. For FLIQNAS-S, which adds tunable channel widths (on inverted bottleneck projection layers) and kernel sizes (on depthwise layers) to a MobileNetV2 search space, there are "230 tunable values leading to a search space of over `$10^{100}$` configurations" (Section 6). These astronomically large spaces are navigated via the RL policy gradient, which learns to allocate probability mass to promising regions without explicit enumeration.

#### FLIQNAS: Joint Quantization and Neural Architecture Search

Section 6 extends FLIQS to **FLIQNAS**, which simultaneously searches quantization formats *and* neural architecture parameters. The search space is built on a MobileNetV2 backbone with two additional degrees of freedom per layer:

1. **Channel widths** (filter widths on inverted bottleneck projection layers): tunable via channel masks that dynamically zero out unused channels, keeping the full weight tensor at maximum width.
2. **Kernel sizes** (on central depthwise convolution layers): the kernel size can be, for example, 3×3 or 5×5.

The controller's sampled architecture now includes, for each tunable layer, a triple: (quantization format, channel width multiplier, kernel size). During the search, channel masks zero out the appropriate fraction of channels, and the convolution operation uses the selected kernel size (implemented via separate branches for each kernel size option). The paper specifies a branch sampling schedule for QNAS: during the RL controller warmup period (first 25% of training), branches for different kernel sizes are sampled jointly with a probability schedule that begins at 1 (all branches active simultaneously) and decreases linearly to 0 (only the selected branch active) by the end of warmup. After warmup, only a single branch (kernel size) is active at a time.

**Why joint search:** expanding the search space from pure quantization to include architecture dimensions raises the question: for a fixed compute budget, is it better to increase bitwidth (finer quantization) or increase architectural capacity (more channels, larger kernels)? Separately optimizing quantization and architecture would miss interactions. For example, a layer with many channels might tolerate lower bitwidth because the increased representational capacity compensates for coarser quantization, while a layer with few channels might need higher bitwidth to preserve information.

The results in Figure 6 validate this hypothesis: at low model costs (below ~15 GBOPs), FLIQS-S and FLIQS-L (pure quantization search) perform on par with FLIQNAS, because at these tight budgets, format optimization matters most. At higher costs (above ~15 GBOPs), FLIQNAS pulls ahead substantially, suggesting that expanding architectural dimensions becomes the more efficient way to spend additional compute budget once quantization is already well-optimized. The paper frames this as a design recommendation: "for a fixed compute budget, larger models benefit from increasing architectural dimensions over bitwidth" (Section 7).

The comparison against APQ ([25], which performs joint architecture, pruning, and quantization search using a once-for-all network) shows FLIQNAS achieving higher accuracy at similar GBOPs: 74.79% vs. 72.10% at ~13 GBOPs, 75.65% vs. 74.10% at ~17 GBOPs, and 75.95% vs. 75.10% at ~22 GBOPs. These improvements come despite APQ including an additional pruning dimension (which FLIQNAS does not), suggesting FLIQNAS's in-training search and entropy-regularized convergence produce more effective joint assignments.

#### Deployment: From Search Output to Inference Model

At the end of FLIQS training, the controller's policy has converged to near-deterministic assignments for each layer (policy entropy near zero). The final model architecture is obtained by taking the **argmax** of each layer's policy — the format (and architecture parameters) with the highest probability. Since the weights were trained throughout the search under these format assignments (with progressive reduction of switching error), the model can be deployed directly for inference using the selected per-layer formats.

**Why argmax rather than sampling:** the entropy regularization drives policy probabilities to near-zero or near-one by the end of training, so sampling and argmax would give the same result. The argmax simply makes the selection deterministic and reproducible.

**Inference infrastructure:** for GPU latency measurements (Table 3), the paper uses "an infrastructure developed by the authors of HAWQV3 that extends the TVM compiler to support INT4 inference." On an NVIDIA 2080 Ti, the FLIQS-S ResNet-50 achieves 1.303× speedup over the INT8 baseline and 1.213× speedup on an A6000, while delivering 77.40% Top-1 accuracy — 2.49 percentage points higher than uniform INT4 at only marginally lower speed. This demonstrates that the per-layer format heterogeneity (some layers at INT4, some at INT8, some at BF16) does not introduce overhead that erodes the theoretical FLOP reduction from lower bitwidths.

**FPGA validation** (Table 2) confirms the quadratic relationship between bitwidth and area: for a ResNet-18 downsampling block implemented on a Xilinx UltraScale+ FPGA, INT4 (bitwidth 4-4-4 for the three convolutions) uses 42.8K LUTs, while INT8 (8-8-8) uses 67.6K LUTs — a 1.58× increase, close to the theoretical `$(8+8)^2 / (4+4)^2 = 256/64 = 4\times$` if both weight and activation bitwidths double, though here the comparison is on total arithmetic bitwidth. The FLIQS-L configuration (5-6-6) uses 47.1K LUTs — only 1.10× the INT4 area — while achieving 71.51% Top-1 accuracy, substantially higher than INT4's 67.31%. This demonstrates that FLIQS's per-layer precision allocation concentrates hardware cost on the layers where it most improves accuracy.

**Why first and last layers stay high-precision:** a consistent pattern across all searched models (Figure 3, Figures 7–9 in Appendix A.1) is that the first convolutional layer and the final classification layer are assigned higher precision (BF16 or INT8/FP8) even when interior layers are aggressively quantized. The first layer processes raw input pixels with potentially large dynamic range and few channels, making it sensitive to clipping error. The last layer directly produces class logits, where small quantization errors in the final representation propagate directly to classification decisions. FLIQS discovers this pattern automatically through the reward signal rather than hard-coding it as a constraint — the cost model makes these layers expensive at high bitwidth, but the accuracy penalty of quantizing them is severe enough that the controller learns to preserve them.

## 4. Key Insights and Innovations

### Innovation 1: Entropy Regularization as the Enabling Mechanism for One-Shot Quantization Search Without Retraining

The paper's most fundamental contribution is not the use of reinforcement learning for quantization search — that existed in prior work (HAQ, ReLeQ) — but rather the **diagnosis of switching error as the root cause of one-shot search instability**, and the corresponding solution of **entropy regularization with a cosine schedule** to eliminate the need for retraining. This pairs a conceptual insight (why prior one-shot methods failed) with an elegantly simple mechanism (a scheduled penalty on policy entropy) that resolves it.

Before FLIQS, the field treated the need for post-search retraining as an inherent cost of embedding search within training. Prior QAT search methods accepted that after the search identified a configuration, the model would need additional fine-tuning or full retraining from scratch to recover accuracy lost during the search process. Whether through multi-branch soft-weighting (EDMIPS), alternating weight and branch optimization, or gradual bitwidth freezing (MPQ), these methods all carried the implicit assumption that the search *disturbs* training in a way that only a separate retraining phase could repair. The retraining step was treated as inevitable, not as a problem to be solved.

The paper's switching error analysis (Section 4, Equations 4–7) reframes this disturbance as a specific, quantifiable phenomenon: the noise introduced when a layer's quantizer changes between training steps propagates as stale gradients, preventing convergence to a sharp optimum. The key diagnostic insight is connecting this noise to **policy entropy** — the controller's uncertainty about format assignments. When entropy is high (broad distribution over candidates), format switches are frequent and large-magnitude, producing substantial switching error. When entropy is low (concentrated distribution), switches are rare and small-magnitude, producing negligible error. The implication is immediate: if you can drive entropy to zero by the end of training, the switching error vanishes and the model converges cleanly, eliminating the retraining step entirely.

This is a **fundamental reframing** rather than an incremental improvement. Prior work viewed the search-training interaction as a generic interference problem to be managed through heuristics (freeze layers early, alternate updates). The paper provides a precise mechanism (policy entropy → expected switching error → optimization noise) and a principled solution (schedule the entropy to zero). The cosine schedule itself is not novel as a mathematical form, but its *deployment as the mechanism that makes one-shot search work* is the contribution — it converts an intractable problem (simultaneously search and converge) into a tractable one by explicitly controlling the exploration-exploitation tradeoff through a single scalar schedule.

The empirical validation of the no-retraining claim is remarkably clean: Appendix Table 8 shows that across all model widths for ResNet-18, FLIQS-S with retraining achieves essentially identical (and in some cases slightly worse) accuracy than without retraining. There is "no noticeable advantage to retraining." This table is the paper's single most important ablation: it demonstrates that the entropy schedule does exactly what the switching error analysis predicts — it makes the search process converge to a deployable model directly. If this table had shown significant gains from retraining, the entire one-shot claim would collapse.

This contribution elevates FLIQS from "another RL-based quantization search" to a method that changes what's possible: by removing retraining from the pipeline, it enables searches on larger models and larger search spaces where retraining would be prohibitively expensive. The DeiT-B16 results — a model with 10× the cost of BF16 MobileNetV2 — are a direct consequence, as the paper notes explicitly. Without the entropy regularization innovation, scaling to transformer architectures with this search methodology would have been impractical.

### Innovation 2: The First Empirical Demonstration That Floating-Point Systematically Outperforms Integer at Identical Bitwidths in Mixed-Precision Deployment

Prior to FLIQS, the question of whether low-precision floating-point formats offer accuracy advantages over integer formats at the *same total bitwidth* was unresolved. The FP8 literature (HFP8, MPFP, FPQuant) had demonstrated that FP8 uniform precision can match or approach full-precision accuracy, but these works compared FP8 to BF16/FP32 — they did not systematically compare mixed-precision floating-point models against mixed-precision integer models at matched bitwidth and matched cost. The intuition that floating-point's non-uniform quantization grid should be better suited to the bell-shaped distributions of neural network weights and activations existed, but it had not been empirically tested at scale across diverse architectures with automated format search.

The paper resolves this question definitively through a controlled experiment: running FLIQS separately on integer search spaces and floating-point search spaces across ResNet-18, ResNet-50, MobileNetV2, InceptionV3, EfficientNet, and DeiT-B16, then plotting the Pareto curves together (Figure 5, right panel "Float vs. Integer" and Appendix Figure 12). The result is unambiguous: "floating-point models outperform their integer counterparts for the same total bitwidth" (Section 5). The curves show floating-point Pareto frontiers lying above and to the left of integer frontiers — higher accuracy at the same cost, or lower cost at the same accuracy.

This is a **significant empirical finding**, not merely an incremental improvement. It changes the hardware design conversation: if floating-point consistently dominates integer at equivalent bitwidth, then accelerator designers should prioritize floating-point compute units over integer units for inference workloads where mixed-precision is deployed. The paper provides concrete evidence by attempting joint integer-floating-point searches, which "were attempted; however, since floating-point dominates integer formats at the same total bitwidths, the outputs of these searches were the same as the pure floating-point searches" (Section 5). The controller, given the freedom to mix integer and floating-point within the same model, never chooses integer — it converges to all-floating-point configurations.

The mechanism behind this advantage is understood qualitatively (floating-point allocates quantization levels non-uniformly, with higher density near zero where most weight and activation values concentrate), but the paper's contribution is providing the **first large-scale, multi-architecture evidence** that this advantage is robust and universal enough to dominate an automated search across format types. The quantitative magnitude matters: at the same GBOPs, the floating-point advantage can be substantial — for instance, the FLIQS-L MobileNetV2 floating-point model reaches 72.94% Top-1 at ~17 GBOPs, while the integer counterpart reaches 72.96% at ~17 GBOPs (Table 1), showing comparable peak accuracy but with the floating-point Pareto curve generally above the integer curve across the full cost range in Figure 5.

This finding also implicitly critiques the field's historical focus on integer quantization: nearly all prior mixed-precision quantization search work (HAQ, HAWQ, ReLeQ, EDMIPS, Bayesian Bits, DQ, PACT) operated exclusively in the integer domain, reflecting the hardware landscape of 2019–2021. By demonstrating that this focus was suboptimal given modern and emerging floating-point-capable hardware, the paper redirects research attention toward floating-point quantization methods.

### Innovation 3: The Quadratic Cost Model as a Hardware-Validated Abstraction That Correctly Biases Search Toward Efficient Configurations

The paper's use of a quadratic bit-operations (BOPs) cost model — specifically, `C_l = b(α)² × MAC_l` where `b(α)` is the total arithmetic bitwidth — is not in itself novel as a cost metric. Prior quantization search work (HAQ, ReLeQ) used similar BOPs estimates. What distinguishes FLIQS's treatment is the **hardware validation loop**: the paper closes the gap between cost model and silicon reality by measuring actual area on an FPGA across multiple bitwidth configurations (Table 2), confirming that LUT counts scale quadratically with bitwidth, and then using this validated model as the optimization target during search.

This matters because the choice of cost model fundamentally shapes what the controller learns. A linear cost model (`b(α) × MAC_l`) would systematically under-penalize high-bitwidth layers, leading the controller to overallocate precision since the marginal accuracy benefit of an extra bit (which is diminishing) would outweigh the marginal cost (which is linear). The quadratic model, by making higher bitwidths quadratically more expensive, correctly captures the diminishing returns to precision — each additional bit costs quadratically more in area and power but provides a sub-quadratic improvement in signal-to-quantization-noise ratio. This shapes the controller's allocation decisions toward configurations that concentrate precision on the most sensitive layers rather than spreading it uniformly.

The FPGA validation (Table 2) is worth examining carefully because it provides the empirical foundation for the entire cost model. For a ResNet-18 downsampling block, uniform INT4 (4-4-4 bits) uses 42.8K LUTs while uniform INT8 (8-8-8) uses 67.6K LUTs — a 1.58× increase. If the cost model were purely linear in total bitwidth (12 → 24 bits), we would expect 2×. The observed 1.58× reflects the fact that area scales with bitwidth squared for the multipliers but includes fixed overhead (control logic, routing) that doesn't scale. The quadratic model approximates this better than a linear one, and more importantly, the relative cost ordering it produces matches hardware reality: a FLIQS-L configuration (5-6-6 bits, 47.1K LUTs) costs only 1.10× the INT4 baseline while delivering substantially higher accuracy (71.51% vs. 67.31%). This validates that the controller's cost-driven decisions — allocating a few extra bits to the pointwise convolutions in the skip branch while keeping most layers at low precision — correspond to real hardware efficiency gains.

This contribution is **incremental in method but significant in epistemology**: it demonstrates that an abstract cost model, when properly validated against silicon, can serve as a reliable proxy for hardware cost during search, enabling Pareto-optimal model discovery without per-configuration hardware synthesis. This closes a loop that prior quantization search papers often left open — they proposed cost models and reported theoretical BOPs reductions, but whether those reductions translated to real area, power, or latency improvements on actual hardware remained an open question. FLIQS's FPGA validation and GPU latency measurements (Table 3) provide the missing confirmation.

### Innovation 4: The Joint Quantization-Architecture Search Reveals a Fundamental Resource Allocation Principle — Architectural Scaling Dominates Bitwidth Scaling at Higher Budgets

FLIQNAS (Section 6) extends the search space to include architectural dimensions — channel widths and kernel sizes — alongside quantization formats. While joint quantization-architecture search existed in prior work (APQ, Auto-NBA), the paper's contribution is extracting a **general design principle** from the search results: "for a fixed compute budget, larger models benefit from increasing architectural dimensions over bitwidth" (Section 7).

This principle emerges from Figure 6, which shows FLIQS (pure quantization search) dominating at low model costs (below ~15 GBOPs), but FLIQNAS (joint search) pulling ahead at higher costs. At ~13 GBOPs, FLIQS-L achieves ~73% while FLIQNAS-L achieves ~74.8% — roughly a 1.8 percentage point gap. At ~22 GBOPs, the gap widens: FLIQNAS-L reaches ~75.95% while pure quantization search would need substantially higher bitwidths to match that accuracy, moving rightward on the cost axis. The Pareto frontier at higher costs is defined entirely by FLIQNAS configurations.

The conceptual significance is that it reframes the "how to spend a compute budget" question from a single-axis optimization (assign bits to layers) to a multi-axis allocation problem (assign compute across precision, channel count, and kernel size dimensions). The search discovers that once quantization is well-optimized (the easy gains from giving more bits to sensitive layers are captured), further improvements come more efficiently from expanding architectural capacity — more channels, larger kernels — rather than from further increasing bitwidth. This is not an obvious result: one could imagine that at higher budgets, further precision increases (e.g., moving from INT4 to INT6 across more layers) would provide better returns than adding channels at low precision, since more channels at low precision might simply accumulate more quantization noise. The search empirically rejects this hypothesis and favors architectural expansion.

This finding has **direct implications for hardware-software co-design**: if you are building a fixed-function accelerator and deciding how many MAC units to include and at what precision, this result suggests that supporting a moderate number of precision levels (say, INT4 through INT8 or FP4 through FP8) and using the remaining silicon budget for more compute units (wider SIMD, more parallel MACs) yields better accuracy than supporting finer-grained precision control with fewer total units. It also implies that research on ultra-low-bitwidth quantization (binary, ternary, 2-bit) may be hitting diminishing returns relative to simply building wider networks at moderate bitwidths, at least for the ImageNet-scale models studied.

The comparison to APQ in Figure 6 strengthens this finding by showing that FLIQNAS outperforms APQ across three design points despite APQ including an additional search dimension (pruning). Pruning can be viewed as another form of architectural scaling (sparsity rather than channel count), and FLIQNAS's comparable-or-better results suggest that explicit channel width search — guided by the same entropy-regularized RL controller — is a particularly effective way to allocate the architectural compute budget.

This is a **moderate but conceptually important contribution**: it doesn't propose a new algorithm for joint search, but rather uses the search infrastructure to produce a recommendation with broad design implications. The recommendation is supported by the Pareto curves but would benefit from more controlled follow-up experiments (e.g., isolating the bitwidth-vs-channels tradeoff at fixed total BOPs across multiple architectures) to establish it as a law rather than an observation. The paper acknowledges this implicitly by presenting it as a finding rather than as a proven universal principle.

### Innovation 5: Framework Portability Across Model Architectures, Formats, and Tasks Without Architecture-Specific Tuning

While not presented as a single headline result, a cross-cutting contribution of the paper is demonstrating that the same FLIQS framework — RL controller, REINFORCE update, entropy regularization, cost model — works **without modification** across convolutional networks (ResNet-18, ResNet-50, MobileNetV2, EfficientNet, InceptionV3), vision transformers (DeiT-B16), and a recommendation model (DCN-V2 on Criteo), and across integer and floating-point format spaces. This portability is non-trivial because these architectures have fundamentally different computational structures: residual connections in ResNets, depthwise-separable convolutions in MobileNetV2, multi-branch Inception modules, self-attention in DeiT, and embedding layers plus MLPs in the recommender.

The significance is that FLIQS **abstracts the search problem away from the model architecture**. The controller does not need to understand that a depthwise convolution behaves differently from a pointwise convolution under quantization, or that attention's softmax operation has different numerical sensitivity than a ReLU activation. It learns these sensitivities implicitly through the reward signal — if quantizing attention layers to low precision hurts accuracy, the controller receives lower rewards for those configurations and shifts probability mass toward higher-precision formats for attention. The per-layer policy parameterization is factorized, meaning each layer's format decisions are learned independently based on that layer's observed contribution to the reward. There is no architecture-specific feature engineering or sensitivity analysis required — the same code, the same hyperparameters (Appendix A.3–A.4), and the same entropy schedule work across all models.

This is a **practical rather than theoretical contribution**, but it has significant implications for adoption. In industrial settings where multiple model architectures need to be quantized for deployment across different hardware targets, a single search methodology that adapts automatically to each model's characteristics eliminates per-model engineering effort. The paper's demonstration on DeiT-B16 — a transformer with 10× the BF16 cost of MobileNetV2 — is particularly important because transformers were not part of the quantization search literature prior to this work (all prior methods in Table 1 focus on CNNs), and their attention mechanisms have qualitatively different quantization behavior than convolutions. FLIQS handles them without modification, discovering that attention blocks should receive higher precision than MLP blocks within the transformer (Figure 3, Figure 8, Appendix A.1).

The recommender model extension (Appendix A.13, Figure 13) further strengthens this portability claim by demonstrating effectiveness on a completely different task (click-through rate prediction with the AUC metric) and data modality (tabular sparse features with embeddings), where the optimization landscape and sensitivity to quantization are different from image classification. The FLIQNAS Pareto curves on Criteo show the same pattern as ImageNet — FLIQNAS outperforming FLIQS at higher model costs, floating-point dominating integer — suggesting the learned allocation principles transfer across domains.

This contribution is **incremental in concept** (generic RL methods are designed to be domain-agnostic) but **significant in empirical demonstration**: it shows that the specific combination of choices — REINFORCE with running-average baseline, quadratic BOPs cost, cosine entropy schedule, per-layer softmax policies — forms a robust recipe that works out-of-the-box across the modern DNN architecture zoo without per-model tuning, a property that none of the prior quantization search methods in Figure 1(b) can claim across such architectural diversity.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** All image classification experiments use the ImageNet dataset (ILSVRC 2012), consisting of approximately 1.28 million training images and 50,000 validation images across 1,000 classes. For the recommendation model extension (Appendix A.13), the Criteo dataset is used — 45 million user log examples over 7 days, each with 13 continuous features and 26 categorical features, with a binary click-through-rate prediction label.

- **Base model(s).** The paper evaluates FLIQS on five convolutional architectures (ResNet-18, ResNet-50, MobileNetV2, InceptionV3, EfficientNet-B0 through B4) and one vision transformer (DeiT-B16). These span diverse computational patterns: standard residual blocks with 3×3 convolutions (ResNets), inverted bottleneck structures with depthwise-separable convolutions (MobileNetV2, EfficientNet), multi-branch Inception modules, and self-attention mechanisms (DeiT). The authors train all models from scratch from random initialization; no pretrained weights are used. The recommender experiment uses a multi-layer perceptron with four hidden layers and factorization similar to DCN-V2 (Wang et al., 2021).

- **Metrics.** The primary quality metric is **ImageNet Top-1 validation accuracy** (%). Model cost is measured in **billions of bit-operations (GBOPs)**, computed as `$\sum_l b(\alpha)^2 \cdot \text{MAC}_l$` where `$b(\alpha)$` is the total arithmetic bitwidth (weight bitwidth + activation bitwidth) for layer `$l$` under architecture `$\alpha$`, and `$\text{MAC}_l$` is the layer's multiply-accumulate count. The recommendation model uses **AUC (Area Under the ROC Curve)**. GPU latency speedup (Table 3) is measured on NVIDIA 2080 Ti and A6000 GPUs using a TVM-based inference infrastructure extended to support INT4. FPGA area (Table 2) is measured in look-up table (LUT) count on a Xilinx UltraScale+ platform using Vivado HLS, with the first ResNet-18 residual block serving as proxy for full-model area.

- **Baselines.** The paper compares against two categories of prior work:
  - **Uniform precision baselines:** BF16 (full half-precision), INT8, INT4 for integer; BF16, E4M3 (FP8), E2M1 (FP4) for floating-point. These are trained with the same two-phase QAT procedure but with a fixed format for all layers.
  - **Prior mixed-precision methods:** HAWQ-V3 (Yao et al., 2021) for integer PTQ search; ZeroQ (Cai et al., 2020) for hybrid INT2/INT8 PTQ; EDMIPS (Cai and Vasconcelos, 2020) for differentiable integer QAT search; LQNets (Zhang et al., 2018) for learned integer quantization; Bayesian Bits (van Baalen et al., 2020) for integer; DQ (Uhlich et al., 2020) for differentiable integer quantization; PACT (Choi et al., 2018) for integer with learned clipping; HFP8 (Sun et al., 2019), FPQuant (Kuzmin et al., 2022), and MPFP (Mellempudi et al., 2019) for uniform FP8. For the FLIQNAS comparison: APQ (Wang et al., 2020) at three published design points (APQ-A, APQ-B, APQ-C).

- **Generation budget / compute accounting.** The search budget is measured implicitly in training steps: all models undergo a single training run which simultaneously serves as the search process. There is no separate search phase with its own compute budget — the RL controller operates during the final 75% of standard training, with the first 25% serving as warmup where architectures are sampled uniformly. Training hyperparameters are listed in Appendix Table 4: ResNets use SGD with cosine learning rate schedule (base LR 2.64), 350 epochs, activation quantization starting at step 7,500 (of ~30,200 total steps); MobileNetV2, EfficientNet, and DeiT use RMSProp or AdamW, 360-400 epochs, activation quantization starting at step 15,000-18,000 (of 112,000+ total steps). All models use batch size 2,048. The paper does not report wall-clock search time relative to standard training, but states the controller overhead is minimal due to the simplicity of the REINFORCE update with per-layer softmax policies. Memory comparisons in Appendix Table 6 show FLIQS using roughly half the activation memory of differentiable "branched" methods (73.6 MiB vs. 220.8 MiB) for ResNet-18 at batch size 32.

- **Cross-validation / statistical protocol.** The paper reports FLIQS results using mean and standard deviation aggregated over three independent trials for the table comparisons (Table 1). For the Pareto curves (Figure 5, Appendix Figures 14–26), individual data points are generated by sweeping the cost target `$C_T$` to produce models at different accuracy-efficiency operating points, with each point representing a single trained model. Error bars are not shown on the Pareto curves. Some uniform-precision baselines (BF16, INT8, INT4, E4M3) are evaluated only once (no standard deviation reported), while FLIQS entries include standard deviations from three trials. The paper does not employ k-fold cross-validation; generalization is assessed across six different model architectures rather than through dataset resampling.

### Main Quantitative Results

#### Integer Quantization Search (Table 1, Figure 5)

The headline result for integer FLIQS is that it achieves higher accuracy at lower model cost compared to all prior mixed-precision integer quantization methods evaluated. Specific comparisons from Table 1:

**ResNet-18:** Integer FLIQS-L achieves 70.61 ± 0.04% Top-1 at 32.17 GBOPs, compared to HAWQ-V3's 68.45% at 34 GBOPs with identical 4-bit lower precision — an improvement of **2.16 percentage points** while using 5.4% fewer GBOPs. Against EDMIPS [22], which searches over [1,4]-bit formats and achieves 67.20% at 22 GBOPs, FLIQS-L achieves 70.61% at 32 GBOPs — the cost is higher but the accuracy gap (3.41 percentage points) is substantial, suggesting EDMIPS's differentiable branch-based approach loses accuracy relative to FLIQS's RL-based search even at the same bitwidth range. Compared to uniform INT8 (70.60% at 116.9 GBOPs for 1.0× width, from Appendix Figure 15), FLIQS-L achieves essentially identical accuracy (70.61%) at approximately 3.6× lower cost (32.17 vs. 116.9 GBOPs). This is the most direct evidence that mixed-precision allocation recovers the accuracy of uniform high-precision models at a fraction of the hardware cost.

**ResNet-50:** Integer FLIQS-S achieves 77.40 ± 0.12% at 73.1 GBOPs, comparing favorably to HAWQ-V3's 74.24% at 71 GBOPs — a **1.09 percentage point** improvement at only 3% higher GBOPs. When first and last layers are kept at 8-bit (HAWQ-V3 4/8* at 154 GBOPs, 76.73%), FLIQS-S at 81 GBOPs achieves 77.32% — 0.59 percentage points higher at 47% lower cost. The key insight is that FLIQS achieves better accuracy than HAWQ-V3's best configuration while using substantially less hardware budget, because HAWQ-V3's Hessian-based sensitivity estimates (used for bitwidth allocation) are less reliable for low-bit quantization than FLIQS's in-training reward signals — the Hessian is computed on the pretrained full-precision model, which does not reflect how sensitivities change after quantization-aware training adapts the weights.

**MobileNetV2:** Integer FLIQS-L achieves 71.87 ± 0.24% at 7.03 GBOPs, versus Bayesian Bits [34] at 72.00% and 17 GBOPs — essentially matching accuracy at **59% lower cost**. Against DQ [35] (69.74% at 37 GBOPs), FLIQS-L achieves 2.13 percentage points higher accuracy at 81% lower cost. MobileNetV2 is known to be challenging for low-bit quantization due to its depthwise-separable convolutions having fewer parameters per layer, making each layer's representational capacity more sensitive to precision loss. The fact that FLIQS substantially outperforms prior methods on this architecture validates the benefit of search during training — PTQ methods lack the feedback to discover which MobileNetV2 layers can tolerate aggressive quantization.

**Figure 5 Pareto curves** provide the broader picture: the FLIQS-L integer curve for ResNet-18 spans from ~59% at 8 GBOPs (0.5× width) to ~76% at 453 GBOPs (2.0× width), consistently above the uniform INT8 and INT4 curves. The INT4 curve shows a characteristic saturation: at low widths (0.5×), INT4 achieves 57.03% vs. FLIQS-L's 60.11%, but at 2.0× width, INT4 reaches 73.57% vs. BF16's 75.56% — the gap narrows because architectural scaling (more channels) partially compensates for precision loss. FLIQS-L stays closer to the BF16 upper envelope across all widths, demonstrating that per-layer precision allocation captures most of the BF16 accuracy at substantially lower cost.

**The advantage of FLIQS-L over FLIQS-S** is visible in the Pareto curves: FLIQS-L consistently sits above FLIQS-S, especially at intermediate cost targets. For ResNet-18 at ~36 GBOPs (1.0× width, Appendix Figures 15), FLIQS-S achieves 69.92% while FLIQS-L achieves 69.56% — a marginal difference showing that the additional format options (INT5, INT6, INT7) do not always improve accuracy when the search space is already well-covered by {INT4, INT8, BF16}. But at lower widths (0.5×, ~8 GBOPs), FLIQS-S achieves 59.08% vs. FLIQS-L's 60.11% — a more meaningful 1.03 percentage point gain, suggesting the finer-grained format control is most valuable when the cost budget is tight and every bit of precision must be carefully allocated.

**Layer-wise allocation patterns** (Appendix Figures 7–8) reveal consistent behavior across models: FLIQS systematically assigns higher bitwidths to the first convolution (which processes raw input pixels with large dynamic range), the last classification layer (where quantization error directly affects logit computation), and the 1×1 pointwise convolutions in ResNet skip branches (which project between channel dimensions and are information bottlenecks). For MobileNetV2, the depthwise 3×3 convolutions — which operate on individual channels with fewer parameters — receive higher bitwidths than the surrounding pointwise convolutions, contrary to the pattern in ResNets. This inversion makes sense: in MobileNetV2's inverted bottleneck structure, the depthwise convolution has the fewest parameters per channel and is therefore the most precision-sensitive, while the 1×1 projections have more parameters and can tolerate coarser quantization. FLIQS discovers this architecture-specific sensitivity pattern purely through the reward signal, without architecture-specific heuristics.

#### Floating-Point Quantization Search (Table 1, Figure 5)

The floating-point results establish that mixed-precision FP allocation outperforms uniform FP8, and that floating-point dominates integer at equivalent cost. From Table 1:

**ResNet-18:** FP FLIQS-L achieves **71.64 ± 0.37%** at 46 GBOPs. Against HFP8 [7] uniform E4M3 (69.39% at 137 GBOPs), this is a 2.25 percentage point improvement at **66% lower cost**. Against MPFP [8] (69.71% at 137 GBOPs), the improvement is 1.93 percentage points. FPQuant [9] achieves 70.28% at 116 GBOPs — FLIQS-L is 1.36 percentage points higher at 60% lower cost. These gaps are substantially larger than the integer improvements over prior work (typically 0.6–2 percentage points), indicating that the opportunity for mixed-precision floating-point — which prior work entirely missed by using uniform formats — is larger than the opportunity for mixed-precision integer.

**ResNet-50:** FP FLIQS-L achieves 77.34 ± 0.14% at 74 GBOPs, compared to HFP8 uniform at 76.22% and 284 GBOPs — 1.12 percentage points higher accuracy at **74% lower cost**.

**MobileNetV2:** FP FLIQS-L achieves 72.94 ± 0.09% at 17 GBOPs, versus FPQuant at 71.60% and 19 GBOPs — a 1.34 percentage point improvement. This is notable because MobileNetV2 is the most quantization-sensitive architecture in the study (uniform E4M3 achieves only 72.63% at 19.25 GBOPs from Appendix Figure 23, compared to BF16's 73.13% at 77 GBOPs), yet FLIQS-L recovers nearly all of the BF16 accuracy with aggressive floating-point mixed-precision at 78% lower cost.

**The floating-point vs. integer comparison** appears most clearly in Figure 5 (right panel) and Appendix Figure 12. Across all models and cost targets, the floating-point Pareto curves lie above and to the left of the integer curves. For MobileNetV2 at ~7 GBOPs (Appendix Figures 17, 23): integer FLIQS-L reaches 71.87% at 7.06 GBOPs, while floating-point FLIQS-L reaches 71.97% at 6.77 GBOPs — the floating-point model achieves slightly higher accuracy at 4% lower cost. At ~17 GBOPs: integer FLIQS-L reaches 72.96% at 17 GBOPs, floating-point reaches 72.94% at 17 GBOPs — essentially tied at this operating point. The floating-point advantage is most pronounced at low-to-moderate bitwidths where the non-uniform quantization grid provides the greatest benefit over uniform integer spacing; at higher bitwidths (where both formats have sufficient precision), the gap narrows.

**The importance of format granularity** is demonstrated by comparing FLIQS-S and FLIQS-L for floating-point. FP FLIQS-S (only {E2M1, E4M3, BF16}) for ResNet-18 (Appendix Figure 21) achieves 68.89% at 1.0× width (~31 GBOPs), while FP FLIQS-L (16 formats) achieves 70.01% at similar cost — the additional format options provide a 1.12 percentage point gain by enabling finer-grained allocation. This gain is larger than the corresponding integer FLIQS-S vs. FLIQS-L gap (69.92% vs. 69.56% at 1.0× width), suggesting that the floating-point format space benefits more from fine-grained search because different layers have different optimal exponent-mantissa tradeoffs (some layers benefit from more exponent bits for dynamic range, others from more mantissa bits for precision), a dimension that doesn't exist in integer formats.

**Joint integer-floating-point searches** were attempted but the controller never selected integer formats when floating-point was available: "since floating-point dominates integer formats at the same total bitwidths, the outputs of these searches were the same as the pure floating-point searches" (Section 5). This is a strong result: across multiple models and cost targets, the controller's learned reward signal consistently ranks floating-point formats above integer formats at equivalent bitwidth, providing the first large-scale empirical evidence that the non-uniform quantization grid of floating-point is universally preferable to uniform integer quantization for DNN inference when hardware supports both.

#### GPU Latency and FPGA Area Validation (Tables 2, 3)

These experiments validate that the theoretical GBOPs reductions translate to real hardware efficiency.

**GPU latency (Table 3):** On a ResNet-50, uniform INT8 achieves 77.47% Top-1 and serves as the 1.000× speedup baseline. Uniform INT4 achieves 74.91% with 1.338× speedup on RTX 2080 Ti and 1.234× on A6000 — a substantial speedup but with 2.56 percentage point accuracy loss. FLIQS-S (mixed INT4/INT8/BF16) achieves 77.40% — only 0.07 points below INT8 accuracy — with 1.303× speedup on 2080 Ti and 1.213× on A6000, only 2.6% and 1.7% slower than pure INT4 respectively. The critical insight: FLIQS recovers nearly all of INT8's accuracy while capturing most of INT4's speedup, because the layers kept at higher precision (first/last layers, skip-branch pointwise convolutions) constitute a small fraction of total compute. Keeping a few critical layers at INT8 or BF16 adds minimal latency overhead while preventing the accuracy collapse that uniform INT4 suffers.

**FPGA area (Table 2):** For a ResNet-18 downsampling block on Xilinx UltraScale+, uniform INT4 (4-4-4 bits for the three convolutions) uses 42.8K LUTs and achieves 67.31% full-model accuracy. Uniform INT8 (8-8-8) uses 67.6K LUTs (1.58×) and achieves 70.78%. A FLIQS-L configuration (5-6-6 bits) uses 45.9K LUTs — only 1.07× the INT4 area — while achieving 70.12% accuracy, within 0.66 percentage points of INT8 at nearly half the area cost. Another FLIQS-L configuration (5-6-6 bits, different model) achieves 71.51% — actually exceeding INT8 accuracy by 0.73 points — at only 1.10× the INT4 area. This is the paper's strongest hardware validation: mixed-precision allocation can simultaneously improve accuracy and reduce area relative to uniform high-precision, because the few extra bits allocated to sensitive layers cost little in total area but provide disproportionate accuracy gains.

The LUT counts scale approximately quadratically with bitwidth as predicted by the BOPs model: going from 4-4-4 (bitwidth 12 total) to 8-8-8 (bitwidth 24 total) increases LUTs by 1.58×. A pure quadratic model would predict `$(24/12)^2 = 4\times$` for the MAC units alone, but the observed 1.58× reflects that LUTs include fixed overhead (control logic, routing, accumulation) that doesn't scale with bitwidth. The quadratic BOPs model is therefore a conservative cost estimate (it penalizes high bitwidth more than actual LUT scaling), which biases the controller toward lower bitwidths — a safe direction for hardware efficiency.

**Mantissa sweep (Appendix Table 7):** For uniform FP8, varying the exponent-mantissa allocation from E1M6 to E5M2 shows a monotonic accuracy improvement with more mantissa bits: E1M6 achieves the highest accuracy (71.72% on ResNet-18) while E5M2 achieves the lowest (71.59%). The gap is small for ResNets (~0.13 points) but larger for MobileNetV2 (73.20% for E1M6 vs. 72.07% for E5M2 — a 1.13 point gap), confirming that MobileNetV2's depthwise convolutions are more sensitive to mantissa precision than ResNet's standard convolutions. FLIQS's floating-point search space includes all these FP8 variants and can assign, for example, E4M3 to depthwise layers and E2M5 to pointwise layers within the same MobileNetV2, capturing the best of both formats.

#### Quantization + Neural Architecture Search (FLIQNAS, Figure 6, Table in Section 6)

FLIQNAS extends the search to include channel widths and kernel sizes alongside quantization formats on a MobileNetV2 backbone, with 230 tunable parameters producing a search space exceeding 10^100 configurations.

**Headline results from Figure 6 table:** FLIQNAS-L achieves 74.79 ± 0.08% at ~13 GBOPs and 75.65 ± 0.20% at ~17 GBOPs. Compared to the APQ baselines (which additionally include pruning): FLIQNAS-L outperforms APQ-A (72.10% at ~13 GBOPs) by 2.69 percentage points, APQ-B (74.10% at ~16 GBOPs) by 1.55 points, and APQ-C (75.10% at ~23 GBOPs) by 0.85 points, all at equal or lower GBOPs. Against pure quantization search (FLIQS-L): at ~13 GBOPs, FLIQNAS-L achieves 74.79% vs. FLIQS-L's ~73% — a ~1.8 point gain — while at ~17 GBOPs, FLIQNAS-L achieves 75.65% vs. 72.96% — a 2.69 point gain.

**The Pareto frontier in Figure 6** shows a clear transition: below approximately 15 GBOPs, FLIQS-S and FLIQS-L (pure quantization search) define the Pareto frontier, with FLIQNAS overlapping rather than exceeding them. Above 15 GBOPs, FLIQNAS pulls ahead decisively, with quantized NAS (fixed format, architecture search only) forming an intermediate curve. At the highest costs (~22 GBOPs), the gap between FLIQNAS-L and FLIQS-L widens to ~3 percentage points (75.95% vs. ~73%). This pattern indicates that when the compute budget is very tight, optimizing quantization is the highest-leverage strategy — every bit of precision matters because there's minimal architectural capacity to compensate for quantization error. As the budget increases, expanding channel widths and kernel sizes becomes more efficient than further increasing bitwidth, because more channels at moderate precision provide greater representational capacity than fewer channels at high precision.

**MobileNetV2 uniform INT8** achieves 72.83% at 19.25 GBOPs (Appendix Figure 17). FLIQNAS-L at 17 GBOPs achieves 75.65% — 2.82 percentage points higher at 12% lower cost — demonstrating that joint architecture-quantization optimization can substantially exceed the accuracy of standard uniform high-precision models even at lower hardware cost.

**Resource allocation trends** (Appendix A.7): FLIQNAS tends to allocate more channels to layers that receive lower bitwidths, "recuperating losses in representational ability from the lower bitwidth" with additional capacity. There is a weaker trend toward larger kernel sizes in lower-bitwidth layers. When the cost target increases, the controller expands architectural dimensions (primarily channel count, secondarily kernel size) before increasing bitwidth — consistent with the Pareto curve showing FLIQNAS dominating only at higher costs.

#### Recommendation Model Extension (Appendix A.13, Figure 13)

The recommender experiment on Criteo extends FLIQS to tabular data with sparse categorical features. Using a DCN-V2-style MLP with four hidden layers and low-rank factorization, FLIQNAS-L and FLIQS-L are compared against uniform INT8 and E4M3 baselines. The Pareto curves (AUC vs. MBOPs) show:

- FLIQNAS-L outperforms FLIQS-L at higher model costs (above ~15 MBOPs), replicating the ImageNet pattern where architectural dimensions become the better investment at larger budgets.
- Both FLIQNAS-L and FLIQS-L dominate the uniform INT8 and E4M3 baselines across all cost levels, consistent with the ImageNet findings.
- The floating-point FLIQNAS curve sits above the integer curve (visible in the separate integer and floating-point panels of Figure 13), consistent with the ImageNet finding that floating-point outperforms integer at equivalent bitwidth.

This is a small-scale experiment (single model architecture, appendix placement) but important for generalizability: it demonstrates that the FLIQS framework transfers to a fundamentally different data modality (sparse categorical + continuous features), optimization objective (binary cross-entropy for CTR prediction, evaluated by AUC), and model architecture (MLP with embeddings and factorization) without modification.

### Ablation Studies and Robustness Checks

The paper conducts several ablation studies and sensitivity analyses, primarily documented in Appendix A.2, A.9, A.11, and the main-text analysis (Section 4).

- **Retraining vs. no retraining (Appendix A.11, Table 8):** For ResNet-18 evaluated across six model widths (0.5× to 2.0×), FLIQS-S with retraining (taking the best configuration and training from scratch) and without retraining (direct deployment from search) produce essentially identical accuracy. At 1.0× width: FLIQS-S achieves 69.92% without retraining vs. 69.53% with retraining — the no-retraining variant is actually slightly better. For FLIQS-L: 69.56% vs. 69.56% — exactly tied. Across all widths and both search spaces, "there is no noticeable advantage to retraining." This is the single most important ablation: it validates the central claim that entropy regularization enables one-shot search that produces directly deployable models. The fact that retraining sometimes yields *worse* accuracy (FLIQS-S at 1.0×: 69.92% vs. 69.53%) suggests that the weights co-adapted with the search process are actually better optimized for the final format configuration than weights trained from scratch with that fixed configuration — the search process may find better optimization trajectories.

- **Activation quantization start step (Appendix A.2, Table 10a):** Sweeping the start of activation quantization from step 1,000 to 30,000 on a ResNet-50 trained for 30,200 steps shows the optimal start is at 4,000–6,000 steps (approximately 13–20% of total training). At step 1,000 (single-phase QAT), accuracy is 75.59%; at step 6,000 (two-phase with warmup), accuracy peaks at 76.05%. Starting too late (step 30,000, i.e., post-training quantization of activations) drops accuracy to 74.19%. The sweet spot provides enough warmup for weight-only quantization to stabilize before introducing the additional noise of activation quantization, but not so late that activations are quantized as a post-hoc step without weight adaptation. This ablation justifies the two-phase design choice, though it is conducted without the search (fixed precision) and may interact with the switching error dynamics during search.

- **Clipping threshold standard deviation multiple (Appendix A.2, Table 10b):** On ResNet-18, sweeping the clipping threshold as multiples of profiled activation standard deviation from 1× to 8× shows an optimum at 3–4×. At 1× (aggressive clipping), accuracy is only 63.39% — severe clipping error on outliers dominates. At 8× (minimal clipping), accuracy is 64.91% — rounding error on the central mass dominates. The peak at 3× (68.02%) reflects the classic quantization tradeoff: balance clipping error and rounding error for the specific distribution shape. The paper uses 3–4× for all models, noting that this choice is not highly sensitive (accuracy varies by less than 1 percentage point between 3× and 5×). This ablation is conducted with fixed-precision models; during FLIQS search, the switchable clipping mechanism adapts this threshold per-format to account for the different optimal clipping ranges at different bitwidths (Figure 4a).

- **Number of profiling batches for clipping threshold (Appendix A.2, Table 10c):** The number of batches used to profile activation standard deviations has minimal impact on final accuracy: sweeping from 1 to 100 profiling batches yields accuracy between 67.75% and 68.09% with no clear trend. This is attributed to the large batch size (2,048) used with shuffled data, providing a stable estimate of activation statistics even with a single batch.

- **Mantissa vs. exponent bits in FP8 (Appendix A.9, Table 7):** Sweeping uniform FP8 formats from E1M6 to E5M2 across ResNet-18, ResNet-50, MobileNetV2, and InceptionV3 shows that more mantissa bits consistently improve accuracy, but the effect size varies by architecture. On ResNet-18: E1M6 (71.72%) vs. E5M2 (71.59%) — a 0.13 point gap. On MobileNetV2: E1M6 (73.20%) vs. E5M2 (72.07%) — a 1.13 point gap. InceptionV3 shows intermediate sensitivity. This architecture-dependent sensitivity explains why mixed-precision floating-point search is valuable: a uniform FP8 format forces a single exponent-mantissa tradeoff across all layers, while FLIQS can assign E4M3 (balanced) to most layers, E2M5 (more mantissa for precision) to depthwise convolutions in MobileNetV2, and E5M2 (more exponent for dynamic range) to layers with outlier-heavy activation distributions, though the paper doesn't provide per-layer format traces for floating-point to confirm this specific pattern.

- **Entropy regularization strength (Figure 4b):** The left panel of Figure 4(b) shows that ImageNet Top-1 accuracy improves monotonically as the final entropy regularization strength `$\beta_H^{\text{end}}$` increases (the x-axis is labeled "Entropy (HM)" showing higher entropy leads to better accuracy, but this refers to the effect of the regularization schedule — stronger regularization ultimately produces lower final entropy and higher accuracy). The middle panel shows the entropy trajectory under the cosine schedule: it starts high, remains elevated during exploration, then smoothly decays toward zero. The right panel shows a specific policy probability `$\pi_6(\text{INT8})$` converging from roughly uniform to near 1.0. This figure validates the core mechanism: the schedule successfully controls the exploration-exploitation transition, and stronger regularization (more decisive convergence) improves final accuracy.

- **RL controller vs. alternatives (Section 3, RL Controller paragraph):** The paper states that "other reinforcement learning methods, such as PPO, and more sophisticated policy models, such as multi-layer perceptron models, offered no quality improvements while being more costly." No quantitative results are shown for this comparison, but the claim is consistent with the paper's design philosophy of minimizing search overhead: the factorized per-layer softmax policy with REINFORCE is the minimal viable policy gradient method, and more complex models would add parameters and computation without improving the quality of format assignments.

- **Search memory comparison (Appendix Table 6):** For ResNet-18 at batch size 32, FLIQS uses 46.8 MiB for gradients, 23.4 MiB for weights, 73.6 MiB for activations, and 51 MiB for search parameters (the controller's per-layer logits). A representative differentiable "branched" method uses 92.6 MiB for gradients, 70.2 MiB for weights, and 220.8 MiB for activations — roughly double FLIQS across all categories. The activation memory gap is most significant (3×) because branched methods must store activations for all candidate bitwidths simultaneously to compute branch importance weights, while FLIQS only stores activations for the single sampled configuration at each step. This validates the claim that RL-based search is more memory-efficient than differentiable search, enabling quantization search on larger models (like DeiT-B16).

- **Cosine entropy schedule (Equation 9) vs. no schedule:** The paper does not present an ablation comparing cosine-scheduled entropy regularization against, for example, linear decay or no regularization. Appendix Table 8 shows FLIQS with the cosine schedule (labeled `+ (β^cos_H)`) compared to FLIQS without the cosine schedule explicitly noted, but the standard FLIQS-S and FLIQS-L results already use the cosine schedule, so there is no no-schedule baseline in the table. The closest comparison is the retraining sweep, which shows that with the cosine schedule, retraining provides no benefit — implying the schedule is sufficient to eliminate switching error. A direct ablation (cosine vs. linear vs. constant vs. no schedule) would strengthen the claim that the specific schedule form matters.

### Critical Assessment

#### Claim: FLIQS achieves state-of-the-art accuracy for integer and floating-point mixed-precision quantization search.

**Supported with important nuance.** Table 1 provides a comprehensive set of comparisons showing FLIQS outperforming prior integer methods (HAWQ-V3, EDMIPS, Bayesian Bits, DQ, PACT, LQNets) and prior FP8 methods (HFP8, MPFP, FPQuant) at comparable or lower GBOPs. The improvements are consistent across ResNet-18, ResNet-50, and MobileNetV2 — the three architectures most commonly benchmarked in prior work.

**However, the comparison is not fully controlled.** Prior methods use different training recipes (epochs, learning rate schedules, optimizers, data augmentation), making it impossible to isolate how much of FLIQS's improvement comes from the search mechanism versus from the more modern two-phase QAT training procedure, the specific quantization library (AQT), or model width scaling (many FLIQS results are at non-standard widths like 0.5×, 0.75×, 1.25×, while prior work typically reports at standard widths). The paper would be stronger if it included a "FLIQS with uniform precision" baseline that uses the identical training recipe but with a fixed format — this would isolate the search contribution from the training recipe contribution. The BF16, INT8, INT4, and E4M3 baselines serve this purpose partially, but they are trained with two-phase QAT and the AQT library, while prior work like HAWQ-V3 uses different PTQ calibration procedures. A fair head-to-head would require reimplementing HAWQ-V3 within the same training framework and comparing search methods directly, which the paper does not do.

**The standard deviations** on FLIQS results (e.g., ±0.04% for integer FLIQS-L on ResNet-18) are very small, indicating that FLIQS is stable across random seeds. However, the standard deviations on floating-point results are larger (±0.37% for FP FLIQS-L on ResNet-18), suggesting floating-point search is somewhat less stable — possibly because the search space is larger (16 formats vs. 6 for integer FLIQS-L) and the controller has more difficulty converging consistently. The paper does not discuss this stability difference.

#### Claim: The cosine entropy regularization schedule enables one-shot search without retraining.

**Supported, but the evidence is narrow.** Table 8 is the key ablation: it shows that retraining provides no benefit for ResNet-18 across six model widths. This is clean and convincing for ResNet-18. However, the paper does not show the same ablation for any other architecture — no retraining comparison for ResNet-50, MobileNetV2, EfficientNet, or DeiT. Given that MobileNetV2 is known to be much more sensitive to quantization (its uniform INT4 accuracy drops heavily relative to BF16), it's plausible that the entropy schedule's effectiveness is architecture-dependent and that MobileNetV2 might benefit from retraining even with the schedule. The paper's strongest results on MobileNetV2 (FLIQNAS, ~75%) are at larger model widths where the architectural capacity provides robustness, potentially masking residual switching error.

**The switching error analysis (Section 4)** is a theoretical justification, not an empirical validation. Figure 4(a) shows switching error curves from synthetic data (Gaussian/Laplacian distributions with injected outliers), not from actual FLIQS training runs. The paper does not measure switching error during search, does not correlate measured switching error with policy entropy, and does not show that higher entropy during search corresponds to higher final-accuracy variance. The connection between the theoretical analysis and the empirical success of the cosine schedule is persuasive but indirect — alternative mechanisms could explain why the cosine schedule works (e.g., it prevents the controller from making large format changes late in training when the learning rate is small and recovery is slow), and the switching error formalism may be post-hoc rationalization.

**The claim that no *prior* method achieves one-shot search without retraining** requires examining prior work more carefully. MPQ [21], published contemporaneously (arXiv 2024), also claims "retraining-free model quantization via one-shot weight-coupling learning." FLIQS does not cite or compare to MPQ in the context of retraining-free operation (MPQ is cited in Section 2 but only as a differentiable NAS approach), so the "first one-shot" claim may be contested. This is a timestamp issue rather than a technical flaw, but readers should verify publication dates.

#### Claim: Floating-point formats systematically outperform integer formats at equivalent bitwidth.

**Strongly supported by the Pareto curves but with a format-specific caveat.** Figure 5 (right panel) and Appendix Figure 12 show floating-point Pareto curves above integer curves across all models. The joint integer-floating-point search never selects integer. However, the paper uses a **quadratic** cost model where cost scales with `$(b_w + b_a)^2$`, and floating-point and integer formats with the same total bitwidth `$b_w + b_a$` are assigned identical cost. Is this correct? For a given bitwidth, a floating-point multiplier is generally *more expensive* in area and energy than an integer multiplier because the FP multiplier must handle exponent addition, mantissa multiplication, normalization, and rounding. The quadratic BOPs model treats them identically, which is favorable to floating-point — it assumes FP8 costs the same as INT8, when in reality FP8 multipliers are larger. This means the floating-point advantage in accuracy at identical BOPs may not translate to identical silicon area or power — the comparison understates floating-point cost relative to integer. The FPGA validation (Table 2) uses only integer formats, so this potential bias in the cost model is not corrected by hardware measurements for floating-point.

**Additionally, the floating-point advantage is largest at low cost targets** (low bitwidths). Figure 5 shows the floating-point and integer curves nearly overlapping at high GBOPs (where more layers use BF16/INT8, making the format distinction moot) but substantially separated at low GBOPs. This means the floating-point advantage is most relevant for aggressive quantization (4–6 bit range) but diminishes for moderate quantization (7–8 bits). The practical implication is that floating-point is specifically beneficial for ultra-low-precision deployment, not a universal superiority across all precision regimes.

#### Claim: Joint quantization-architecture search (FLIQNAS) reveals that architectural scaling dominates bitwidth scaling at higher compute budgets.

**Supported by the MobileNetV2 Pareto curves but not established as a general principle.** Figure 6 shows FLIQNAS outperforming FLIQS at costs above ~15 GBOPs, but this is only demonstrated for one architecture (MobileNetV2). The paper does not report FLIQNAS results for ResNet-18, ResNet-50, EfficientNet, or DeiT, so it's unknown whether the transition point (the cost at which architectural scaling becomes preferable to bitwidth scaling) is architecture-specific. Intuitively, architectures that are already heavily optimized for efficiency (MobileNetV2, EfficientNet) might have less room for architectural improvement through channel width changes than architectures with simpler designs (ResNets), potentially shifting the transition point or eliminating the advantage of joint search entirely.

**The claim "larger models benefit from increasing architectural dimensions over bitwidth"** is demonstrated for scaling *within* a MobileNetV2 search space (varying channel widths and kernel sizes from a baseline), not for scaling *across* model families. It doesn't address whether training a larger ResNet at low precision is preferable to a smaller ResNet at high precision — a different question entirely, and one that the FLOPs-matched comparisons in the executive summary do not address.

**A missing ablation** would be a controlled experiment at fixed total BOPs comparing: (a) increasing bitwidth on all layers vs. (b) widening channels on all layers vs. (c) FLIQNAS's joint allocation. This would isolate the marginal benefit of architectural scaling from the joint optimization benefit, and establish whether the principle is "architectural dimensions are better than bitwidth" or "joint optimization is better than optimizing either dimension alone."

#### Claim: FLIQS works across diverse architectures (CNNs, vision transformers, recommenders) without modification.

**Supported but with an asymmetry in the evidence.** The ImageNet experiments cover six architectures comprehensively, and the recommendation model extension (Appendix A.13) shows transfer to a different domain. However, the recommendation experiment is limited to one model architecture with one search space, reported only in the appendix with fewer details than the ImageNet experiments. The paper does not report retraining ablations, layer-wise format allocations, or multi-trial standard deviations for Criteo, making it harder to assess whether the no-retraining property and search stability transfer. Additionally, DeiT-B16 results are reported only at the standard width (no width sweep in Table 1 or Appendix Figure 20/26), making the transformer evidence less thorough than the CNN evidence.

**The hyperparameter portability claim** (same cosine schedule, same RL learning rate, same two-phase QAT timing across all ImageNet models) is implicit rather than explicit. Appendix Table 4 shows different learning rate schedules, optimizers, and activation quantization start steps for different model families, so the hyperparameters are *not* fully uniform. This is a minor point — some architecture-specific tuning of training hyperparameters is expected — but the paper's framing of "works without modification" should be understood as "the search framework adapts automatically, not that every training hyperparameter is identical."

#### Missing analyses and experiments

Several experiments that would significantly strengthen the paper are absent or underdeveloped:

1. **No difficulty-dependent analysis.** Unlike the computation-allocation theme in the executive summary's reference example, FLIQS does not analyze whether the optimal format allocation varies with input difficulty or data distribution. This is somewhat outside the scope (quantization search is architecture-focused, not data-dependent), but understanding whether certain layers need higher precision for certain input types would be valuable for dynamic-precision systems.

2. **No ablation on the cost model form.** The quadratic BOPs model is justified by FPGA measurements and cited prior work, but the paper doesn't show how sensitive the search results are to the choice of cost model. Would a linear BOPs model produce qualitatively different format allocations? Would an energy model (which scales differently from area) change the Pareto frontier? This is particularly relevant given the point above about floating-point vs. integer cost modeling.

3. **Limited scale analysis.** All models are trained from scratch on ImageNet — a substantial compute investment but not at the frontier of model scale (largest model is DeiT-B16 at ~87M parameters). It's unknown whether the entropy schedule's effectiveness scales to larger models (ViT-L, ResNet-152) where training is more expensive and getting one-shot search right matters more because retraining would be proportionally more costly.

4. **No direct comparison to per-layer sensitivity analysis.** HAQ and HAWQ use Hessian-based sensitivity measures to guide bitwidth allocation. FLIQS never compares its learned allocations to those produced by Hessian-based methods on the same models — it only compares final accuracy. Showing that the RL controller discovers fundamentally different (and better) allocation patterns than sensitivity-based heuristics would strengthen the case for training-integrated search.

5. **No latency breakdown by layer for the GPU results.** Table 3 reports overall speedup but doesn't show whether layers kept at INT8/BF16 by FLIQS become latency bottlenecks, potentially limiting further speedup even if other layers use INT4. This information would help practitioners understand the deployment tradeoffs.

6. **No ablation on the REINFORCE advantage baseline.** The paper uses a running-average baseline for variance reduction but doesn't compare against no baseline or a learned value function baseline. The claim that PPO "offered no quality improvements" is stated without quantitative evidence.

In summary, the paper provides substantial empirical evidence for its main claims, with the strongest support for (a) FLIQS outperforming prior mixed-precision methods on ResNet and MobileNetV2 architectures, (b) the no-retraining property via entropy regularization for ResNet-18, and (c) floating-point's advantage over integer at equivalent bitwidth. The claims around FLIQNAS and architectural vs. bitwidth scaling are supported but less thoroughly validated across architectures. The primary limitations are the single-benchmark (ImageNet) evaluation, the lack of a fair controlled comparison that isolates the search mechanism from the training recipe, and the absence of ablation studies on the cost model form and entropy schedule design space beyond the binary "with schedule vs. retraining" comparison.

## 6. Limitations and Trade-offs

### Floating-Point Cost Model Treats FP and Integer Multipliers as Equally Expensive

The paper uses a quadratic cost model where `$C_l(\alpha) = b(\alpha)^2 \cdot \text{MAC}_l$`, with `$b(\alpha)$` representing total arithmetic bitwidth (weight + activation bits). This model assigns **identical cost** to integer and floating-point formats at the same total bitwidth — an INT8 layer (8-bit integer arithmetic) and an E4M3 layer (also 8 bits total: 4 exponent + 3 mantissa + 1 sign) are treated as having equal hardware cost. This is an optimistic assumption for floating-point.

In digital logic, a floating-point multiplier is more expensive than an integer multiplier at the same bitwidth because it must handle exponent addition, mantissa multiplication, normalization, and rounding logic. The quadratic BOPs model captures multiplier area scaling with bitwidth but ignores the constant-factor overhead of floating-point operations — the control logic, exponent handling, and denormal support that add area and energy beyond what bitwidth alone predicts. The consequence is that the paper's headline finding — "floating-point dominates integer at equivalent bitwidth" — may **overstate the practical advantage** of floating-point when translated to real hardware area or power. A deployment engineer choosing between an INT8 accelerator and an FP8 accelerator at the same silicon budget would need to factor in the per-MAC area penalty of floating-point, which the GBOPs metric washes out.

The paper provides **no hardware validation for floating-point formats**. The FPGA area measurements in Table 2 use only integer formats (INT4 through INT8). Table 3's GPU latency measurements use INT8, INT4, and the mixed integer FLIQS-S, again with no floating-point benchmarks. The mantissa sweep in Appendix Table 7 shows that E1M6 and E5M2 have different accuracies at the same total bitwidth, but provides no corresponding hardware cost measurements to validate whether the quadratic model's assumption of equal cost holds. This is a significant gap because the entire floating-point-vs-integer conclusion rests on the cost model being fair to both format families. If FP8 multipliers require, say, 1.3× more area than INT8 multipliers at the same bitwidth, the floating-point Pareto curves in Figure 5 would shift rightward, potentially crossing or falling below the integer curves at some cost targets.

The authors do not acknowledge this limitation in the text. Section 3 justifies the quadratic model only for integer multipliers, citing that "multipliers dominate resources and scale quadratically in power and area [28]," but the PokeBNN citation [28] concerns binary and integer networks, not floating-point. The paper would benefit from synthetic hardware synthesis of floating-point MAC units across the E2M1 through E6M1 range to calibrate the floating-point cost model, similar to the integer LUT validation in Table 2.

---

### Difficulty Estimation Cost Is Not a Factor in the Search Overhead

FLIQS's search process is embedded within a single training run, so the **cost of exploring suboptimal configurations is paid in training time and compute** rather than in a separate search phase. The RL controller explores the search space for the final 75% of training, during which many evaluated architectures produce lower rewards than the final configuration — those training steps with poor architectures contribute to model training but under suboptimal quantization conditions, potentially wasting compute.

The paper does not report how much total training compute is spent evaluating configurations that are ultimately discarded, nor how the convergence speed of the base model under switching formats compares to training with a fixed format from the start. The relevant metric is: if you knew the optimal format configuration in advance (say, from an oracle), how much less training compute would you need to reach the same accuracy? The paper provides no such comparison. Table 8 shows that retraining *after* search provides no benefit — but that's a different question than whether the search *itself* could be shortened if the format were fixed earlier. If the controller converges to the near-final configuration after 50% of training but continues to run the REINFORCE updates for the remaining 25%, those extra steps are search overhead that doesn't improve the final model.

This matters for practitioners deciding whether FLIQS is worth the implementation complexity over a simpler approach: train a model with uniform INT8 or FP8, profile layer sensitivities post-training (using Hessian metrics like HAWQ-V3), and manually assign a few precision tiers. The paper never compares FLIQS's total training cost to this simpler pipeline. The closest comparison is the accuracy-vs-GBOPs tables, which show inference cost but not training cost. For organizations with limited training budgets who need to quantize many models, the search overhead may outweigh the inference-time gains — especially if the model will be deployed at low inference volume where per-query savings don't amortize the search cost.

The authors flag the computational cost of the search only in terms of memory (Appendix Table 6, comparing to branched differentiable methods) and in terms of controller simplicity ("the controller and policy model must be efficient enough to be embedded within the training graph to not significantly increase the training time," Section 3), but provide no wall-clock time measurements, no FLOP counts for the search process, and no comparison of total training time against training a fixed-format model to convergence. The claim that RL-based search is more efficient than differentiable search is supported only by memory comparisons, not by time-to-convergence or total compute.

---

### Generalization Is Demonstrated on a Single Task Family and Data Modality

All primary experiments use **ImageNet classification** — a single task (1,000-way object categorization) with a single data modality (natural images at 224×224 resolution). While the authors evaluate six different model architectures, the underlying optimization problem is identical in each case: minimize cross-entropy loss on the same ImageNet training distribution. This leaves open the question of whether FLIQS's per-layer format allocations, and specifically the entropy regularization schedule that enables no-retraining, transfer to tasks with fundamentally different loss landscapes.

The recommendation model extension (Appendix A.13, Criteo dataset) is the only non-ImageNet experiment, and it is limited to a single model architecture with results reported only in an appendix figure without per-layer allocation analysis, standard deviations, or retraining ablations. The Criteo task differs from ImageNet in important ways — binary classification with extreme class imbalance, sparse categorical features with embedding layers, and a different optimization landscape (AUC is not directly optimized; binary cross-entropy serves as a surrogate) — but the appendix reports only a small Pareto curve with minimal detail. The paper does not show whether the no-retraining property holds for Criteo, whether the entropy schedule needs different `$\beta_H^{\text{end}}$` values, or whether floating-point maintains its advantage over integer in this domain.

This matters because quantization sensitivity is known to be **task-dependent**. Tasks requiring fine-grained numerical precision (e.g., depth estimation, super-resolution, audio generation) may exhibit different layer-wise sensitivity patterns than classification, and the optimal format allocation discovered by FLIQS on ImageNet may not transfer. More importantly, tasks where the model must produce **calibrated probabilities** (like medical diagnosis or financial forecasting) may be more sensitive to quantization than classification tasks where only the argmax matters — a model quantized with FLIQS to match Top-1 accuracy might produce substantially worse log-likelihoods, which the ImageNet Top-1 metric does not capture.

The paper implicitly claims generality by evaluating across model architectures, but architecture diversity within a single task is weak evidence for task-level generality. A more convincing demonstration would evaluate on at least one additional task family — semantic segmentation (pixel-level classification with different loss structure), object detection (regression + classification), or language modeling (autoregressive next-token prediction) — with the same FLIQS framework and hyperparameters.

---

### The Entropy Schedule Design and Its Robustness Are Underexplored

The cosine entropy regularization schedule (Equation 9) is the mechanism that enables one-shot search without retraining, yet the paper provides **minimal ablation of the schedule's design space**. The schedule has two degrees of freedom: the functional form (cosine vs. linear, step, exponential) and the final regularization strength `$\beta_H^{\text{end}}$` (set to 0.5). The paper shows in Figure 4(b) that higher entropy regularization (larger `$\beta_H^{\text{end}}$`) leads to better accuracy, but does not sweep the schedule form itself. A linear decay from 0 to `$\beta_H^{\text{end}}$` might work equally well or better. An exponential schedule might converge faster. The cosine choice appears motivated by convention (cosine schedules are common for learning rate decay) rather than by empirical comparison.

More critically, the paper does not investigate what happens if `$\beta_H^{\text{end}}$` is set incorrectly. If `$\beta_H^{\text{end}}$` is too small, the policy retains residual entropy at the end of training, leaving switching noise that degrades the final model — this would require retraining to fix, defeating the purpose of the schedule. If `$\beta_H^{\text{end}}$` is too large, the controller converges to deterministic assignments too early, before it has accumulated enough reward signal to distinguish good from bad configurations, locking in suboptimal format choices. The single value `$\beta_H^{\text{end}} = 0.5$` is used for all models and all search spaces (FLIQS-S, FLIQS-L, FLIQNAS), but the paper provides no evidence that this value is near-optimal for any architecture, let alone universally appropriate. The statement in Appendix A.4 that "a cosine entropy regularization schedule is applied to all runs beginning with no regularization and ending with `$\beta_H = 0.5$`" suggests this value was chosen once and never revisited.

This is a practical deployment risk. A practitioner applying FLIQS to a new model architecture or dataset has no guidance for tuning `$\beta_H^{\text{end}}$`, and the cost of getting it wrong is either degraded accuracy (if too large) or the need for retraining (if too small), which is exactly the cost FLIQS promises to eliminate. A sweep of `$\beta_H^{\text{end}}$` across, say, {0.1, 0.25, 0.5, 0.75, 1.0} on at least one model, with corresponding measurements of final policy entropy, final accuracy, and retraining benefit, would provide the calibration needed for practitioners to set this parameter with confidence. The current paper leaves it as an opaque hyperparameter.

---

### The Hardest Quantization Regime Shows Diminishing Returns, and Some Baselines Are Weak

The paper demonstrates FLIQS's advantages primarily against **aggressive low-bit baselines** (INT4, E2M1) and **prior mixed-precision methods** that use older training recipes. Against these, FLIQS shows substantial accuracy improvements. However, the paper does not evaluate against a simple, strong baseline that a practitioner might actually use in 2024: **uniform INT8 or FP8 with modern quantization-aware training and architectural scaling**.

Consider the uniform INT8 and E4M3 baselines in the Pareto curves (Figure 5). At moderate-to-high bitwidths, the gap between uniform precision and FLIQS narrows substantially. For ResNet-18 at 1.0× width, uniform INT8 achieves 70.60% at 116.9 GBOPs (Appendix Figure 15), while integer FLIQS-L achieves 70.61% at 32.2 GBOPs — the accuracy is essentially identical, and the entire advantage is in the cost reduction from per-layer precision allocation. But how does this compare to simply training a **wider INT8 model**? If uniform INT8 at 0.75× width achieves 67.80% at 67.2 GBOPs, a hypothetical 0.85× width INT8 model might achieve ~69.5% at ~85 GBOPs — still more expensive than FLIQS-L's 70.61% at 32.2 GBOPs, but a fairer comparison would match total MACs rather than GBOPs, since GBOPs penalize uniform high-precision via the quadratic term while uniform precision avoids the implementation complexity of per-layer format heterogeneity.

The paper does not compare FLIQS against **architecturally scaled uniform-precision models** with matched MAC count (not matched GBOPs). If the end goal is the best accuracy for a given silicon budget, expanding a uniform INT8 or FP8 model to use all available MAC units might be simpler to deploy than a mixed-precision model where different layers require different hardware datapaths. The FLIQNAS results partially address this — they show that joint quantization-architecture search outperforms quantization-only search — but the comparison is to FLIQS itself, not to a simple baseline of "train a wider model at uniform INT8 until it matches the mixed-precision model's accuracy."

Additionally, the prior work baselines (HAWQ-V3, EDMIPS, Bayesian Bits, DQ) were published between 2018 and 2021 and use training recipes (optimizers, data augmentation, epoch counts) that are likely suboptimal by 2024 standards. The paper retrains FLIQS models from scratch with modern two-phase QAT and the AQT library, which may account for some fraction of the accuracy gap independent of the search method. The uniform INT8, INT4, and E4M3 baselines trained with the same recipe partially control for this, but the comparison to prior mixed-precision methods is confounded by recipe differences. A controlled experiment where HAWQ-V3's bitwidth allocations are retrained with the same two-phase QAT recipe as FLIQS would isolate the search contribution, but this is not performed.

---

### No Dynamic or Input-Adaptive Quantization Capability

FLIQS assigns a **static per-layer format** that is fixed at the end of training and used identically for all inputs at inference time. This is standard for quantization search, but it leaves on the table the possibility of **input-adaptive quantization** — where a layer's bitwidth or format varies depending on the difficulty or characteristics of the current input. For example, an "easy" image (high-contrast, canonical pose, unambiguous class) might be correctly classified with all layers at INT4, while a "hard" image (low contrast, occluded, atypical viewpoint) might require higher precision in early layers to preserve fine-grained spatial information.

The paper demonstrates that different *layers* within a model have different quantization sensitivity, but does not investigate whether this sensitivity is **input-dependent**. Prior work on conditional computation and dynamic networks has shown that layer sensitivity can vary substantially across inputs, and a static per-layer format leaves performance on the table for inputs where certain layers could be reduced in precision without accuracy loss. In production deployments where latency and energy budgets are per-query rather than amortized, the ability to spend less compute on easy inputs and more on hard inputs — analogous to the compute-optimal test-time scaling in the reference paper — would be valuable.

This is not a flaw in FLIQS per se (no prior quantization search method handles input-adaptive formats), but it is a fundamental limitation of the static per-layer approach for deployment scenarios where input difficulty varies and per-query cost matters. The paper's framework could potentially be extended to learn input-conditioned format policies (e.g., a small gating network that predicts per-layer bitwidths based on input features), but the current formulation does not support this, and the paper does not discuss the possibility.

## 7. Implications and Future Directions

### How This Work Changes the Landscape

FLIQS shifts the conversation around DNN quantization from **manual or heuristic-driven precision assignment** to **automated, training-integrated search** that produces directly deployable models without retraining. Before this work, the field faced a structural tradeoff captured in Figure 1(b): you could either perform a fast post-training quantization (PTQ) search that sacrificed accuracy, or an expensive quantization-aware training (QAT) search that required post-search retraining or incurred severe memory overhead from branching. FLIQS breaks this tradeoff by providing the first method that simultaneously achieves QAT-level accuracy, RL-level memory efficiency, and PTQ-level deployment simplicity (no retraining). This is not a paradigm shift — the core idea of using RL for quantization search existed in HAQ and ReLeQ — but it is a **methodological resolution of a previously inescapable tension**.

The most consequential reframing is the paper's diagnosis of **switching error as the mechanism linking policy entropy to model accuracy**. Prior one-shot quantization search methods treated the search-training interference as an opaque optimization problem to be managed through heuristics (gradual bitwidth freezing in MPQ, alternating optimization in EDMIPS). The paper shows that this interference has a specific, quantifiable form: the expected switching error is proportional to policy entropy (Equation 6), and therefore driving entropy to zero via a scheduled regularizer (Equation 9) eliminates the interference at its source. This reframes the one-shot search problem from "how do we manage the search's disruption to training?" to "how do we schedule the controller's exploration so that it converges before training ends?" The former question admits many incomplete solutions; the latter has a clean, parametric answer.

The practical consequence is that **quantization search becomes feasible for larger models and larger search spaces**. The memory comparison in Appendix Table 6 makes this concrete: FLIQS uses roughly half the memory of differentiable branched methods across all categories (gradients, weights, activations), with the activation memory gap being most dramatic (73.6 MiB vs. 220.8 MiB — a 3× reduction). This memory efficiency, combined with the no-retraining property, is why the paper can report results on DeiT-B16 (a vision transformer with 10× the BF16 cost of MobileNetV2) — a scale that would be prohibitively expensive for differentiable search methods that must maintain parallel branches for each candidate format.

The paper also **resolves an open empirical question about floating-point vs. integer quantization**. Prior to FLIQS, the intuition that floating-point's non-uniform quantization grid should better match DNN weight and activation distributions existed, but systematic evidence was lacking. The paper provides that evidence at scale: across six architectures, mixed-precision floating-point Pareto curves consistently lie above integer curves (Figure 5, right panel), and joint integer-floating-point searches never select integer formats. This shifts the burden of proof: future quantization hardware and software should default to floating-point unless there is a specific reason to prefer integer (e.g., legacy hardware support, simpler multiplier design for ultra-low-area applications). The paper does not fully close this question — the cost model treats FP and integer multipliers as equally expensive, which understates floating-point hardware cost — but it provides the strongest evidence to date that the accuracy advantage is substantial enough to motivate further investigation of floating-point hardware.

Finally, the FLIQNAS results (Section 6) provide an **actionable design principle for hardware-software co-design**: when scaling up a model's compute budget, expanding architectural dimensions (channels, kernel sizes) becomes more efficient than further increasing bitwidth beyond a moderate precision level. The Pareto curves in Figure 6 show this transition clearly: below ~15 GBOPs, FLIQS (pure quantization search) defines the frontier; above ~15 GBOPs, FLIQNAS (joint search) pulls ahead. This has direct implications for accelerator design — it suggests that supporting a moderate number of precision levels (e.g., INT4 through INT8, or FP4 through FP8) and investing the remaining silicon budget in more compute units yields better accuracy than supporting finer-grained precision control with fewer total MACs.

### Follow-Up Research This Work Enables

**Validating the floating-point cost model with hardware synthesis.** The paper's central finding — floating-point outperforms integer at equivalent bitwidth — rests on a quadratic BOPs cost model that treats INT8 and E4M3 as equally expensive. This assumption is almost certainly optimistic for floating-point, since FP multipliers require exponent handling, normalization, and rounding logic beyond what integer multipliers need. A direct follow-up would synthesize a range of floating-point and integer MAC units (E2M1 through E6M1 floating-point; INT4 through INT8 integer) in a standard cell library or on an FPGA, measuring actual area and energy per operation. This would produce a calibrated cost model where FP8 might cost, for example, 1.2–1.5× more than INT8 in area at the same total bitwidth. Re-running FLIQS with this calibrated cost model and re-plotting the integer vs. floating-point Pareto curves would reveal whether the floating-point advantage survives the correction, and if so, at which bitwidth ranges. The FPGA infrastructure from Table 2 provides a starting point — extending it to synthesize and measure floating-point DSP configurations would close the hardware validation loop that the current paper leaves open.

**Stress-testing the entropy schedule across architectures and search spaces.** The cosine entropy schedule with `$\beta_H^{\text{end}} = 0.5$` is used for all models and all search spaces in the paper, but the only retraining ablation is on ResNet-18 (Appendix Table 8). MobileNetV2 is known to be more quantization-sensitive than ResNet-18 — its uniform INT4 accuracy drops more sharply relative to BF16 — and it is plausible that the optimal `$\beta_H^{\text{end}}$` is architecture-dependent. A systematic study would sweep `$\beta_H^{\text{end}} \in \{0.1, 0.25, 0.5, 0.75, 1.0\}$` on ResNet-18, ResNet-50, MobileNetV2, and DeiT-B16, measuring (a) final accuracy without retraining, (b) final accuracy with retraining, and (c) the gap between them as a function of `$\beta_H^{\text{end}}$`. If the gap is zero for ResNet-50 and DeiT across all values (similar to ResNet-18 in Table 8), the schedule's robustness is confirmed. If MobileNetV2 shows a non-zero gap at `$\beta_H^{\text{end}} = 0.5$` that closes at a higher value, then the recommended default needs architecture-specific tuning. The schedule's functional form (cosine vs. linear vs. exponential decay) should also be ablated — the paper chose cosine without comparison to alternatives, and a linear schedule might work equally well with simpler implementation.

**Combining FLIQS with input-adaptive quantization.** FLIQS assigns static per-layer formats used identically for all inputs. However, prior work on dynamic networks has shown that layer sensitivity can be input-dependent — an "easy" image might be correctly classified with all layers at low precision, while a "hard" image requires higher precision in early layers. A natural extension would add a lightweight gating network that takes intermediate features as input and predicts per-layer bitwidths (or a binary "low precision vs. high precision" decision per layer) for the current input, trained jointly with the base model using an augmented reward function that includes both average accuracy and average cost across inputs. The FLIQS framework provides the search infrastructure — the RL controller already learns to predict format quality, and this could be extended to condition on input features rather than operating unconditionally. The key experiment would compare the accuracy-cost Pareto frontier of input-adaptive quantization against FLIQS's static per-layer allocation on ImageNet, measuring whether the additional degree of freedom (input-dependent precision) shifts the frontier meaningfully leftward (lower average cost at the same accuracy).

**Scaling FLIQS to language models and autoregressive generation.** All FLIQS experiments are on vision models (convolutional and transformer) trained for classification with cross-entropy loss. Language model quantization presents different challenges: autoregressive generation where quantization errors compound across time steps, attention mechanisms with different numerical sensitivity profiles than vision transformers, and metrics beyond Top-1 accuracy (perplexity, downstream task performance) that may respond differently to mixed-precision allocation. A concrete experiment would apply FLIQS to a BERT-base or GPT-2-scale model on language modeling or GLUE benchmarks, using the same RL controller, entropy schedule, and quadratic BOPs cost model, but replacing the classification head with a language modeling head and the accuracy reward with perplexity or a composite of downstream task scores. The key question is whether the per-layer format allocation patterns learned for vision — more bits to first/last layers, more bits to attention than MLP within transformers — transfer to language, or whether the different loss landscape and token-level prediction produce fundamentally different sensitivity patterns. The paper's DeiT-B16 results (uniform width only, no width sweep) suggest the framework works for transformer architectures, but extending to autoregressive decoding would stress-test the approach.

**Investigating whether the "architectural scaling dominates bitwidth scaling" principle generalizes.** The FLIQNAS finding — that at higher compute budgets, expanding channels and kernel sizes is more efficient than further increasing bitwidth — is demonstrated only on a MobileNetV2 search space. To assess whether this is a general principle or architecture-specific, a follow-up would implement FLIQNAS on at least two additional architecture families with different computational structures: ResNet-50 (residual connections, no depthwise convolutions) and EfficientNet (compound scaling of width, depth, and resolution). For each, generate Pareto curves comparing (a) pure quantization search (FLIQS), (b) pure architecture search (fixed moderate precision, varying channel widths and kernel sizes), and (c) joint search (FLIQNAS). If the transition point — the GBOPs value where joint search overtakes pure quantization search — is approximately constant across architectures when normalized by some measure of baseline model capacity, the principle is validated. If the transition point varies wildly (e.g., ResNet-50 never benefits from joint search over pure quantization because its simple structure has less room for architectural optimization), then the principle is architecture-specific and the paper's recommendation needs qualification.

**Negative result: does FLIQS fail when the base model is trained with a different recipe?** The paper trains all models from scratch with its own two-phase QAT procedure. A valuable stress test would apply FLIQS to a pretrained model checkpoint (e.g., a torchvision ResNet-50 pretrained on ImageNet) and fine-tune with quantization search, rather than training from scratch. This is the more common industrial workflow — organizations have existing pretrained models and want to quantize them for deployment — and it introduces complexities that from-scratch training avoids: the pretrained weight distribution is optimized for full precision and may need to shift substantially under quantization, potentially amplifying switching error because the optimizer is simultaneously adapting weights to quantization and responding to format changes. If FLIQS's entropy schedule and no-retraining property hold under fine-tuning, the framework's practical value increases substantially. If they fail — if fine-tuned models require retraining or show degraded accuracy relative to from-scratch training — then the current contribution is limited to cases where models are trained from the ground up with quantization search in mind.

### Practical Applications and Downstream Use Cases

**Deployment of a single trained model across heterogeneous hardware targets.** An organization that deploys the same DNN architecture on cloud GPUs (supporting INT8, BF16, FP8), edge TPUs (INT8 only), and FPGA-based accelerators (arbitrary precision) currently faces a choice: maintain separate quantized versions of the model for each target, or use a uniform low-precision format that works everywhere but sacrifices accuracy on capable hardware. With FLIQS, the organization can run one search per hardware target's format support list — using FLIQS-S for the GPU (candidates: INT4, INT8, BF16), a different FLIQS-S for the TPU (candidates: INT4, INT8), and FLIQS-L for the FPGA (candidates: all integer and floating-point formats from 4–8 bits) — producing per-platform models that maximize accuracy within each hardware constraint. The no-retraining property means each search produces a deployable model directly, without per-platform fine-tuning. The ResNet-50 results quantify the benefit: on a GPU-like target, FLIQS-S achieves 77.40% at 73 GBOPs (Table 1), while on a more flexible FPGA-like target, FLIQS-L achieves 77.34% at 72 GBOPs — similar accuracy but using different per-layer format assignments optimized for each platform's capabilities.

**Hardware-software co-design for next-generation AI accelerators.** When designing a new accelerator, architects must decide which numerical formats to support in hardware, and at what precision levels, often with limited empirical guidance on which formats actually improve DNN accuracy. FLIQS provides this guidance by searching over candidate format sets and reporting the accuracy-cost tradeoffs that result. For example, the paper's finding that floating-point consistently outperforms integer at equivalent bitwidth across six architectures suggests that new accelerator designs should prioritize floating-point compute units. More granularly, the mantissa sweep in Appendix Table 7 shows that for MobileNetV2 (the most quantization-sensitive architecture tested), E1M6 and E2M5 have a 1.13 percentage point accuracy gap — suggesting that supporting multiple FP8 variants (with different exponent-mantissa splits) and allowing per-layer format selection provides meaningful accuracy benefits for sensitive architectures. The FPGA area validation in Table 2 provides a template for this workflow: propose a candidate set of formats, run FLIQS to find the Pareto-optimal per-layer allocations, synthesize representative blocks to measure actual hardware cost, and iterate on the format support list based on which formats are consistently selected by the controller.

**Cost-efficient batch inference pipelines with mixed-precision models.** For organizations running large-scale batch inference (e.g., processing millions of images per day for content moderation or product categorization), the FLIQS Pareto curves in Figure 5 provide directly actionable operating points. A team currently using uniform INT8 ResNet-50 at 1.0× width (77.47% accuracy, 262 GBOPs per inference per Table 3 related data) could switch to FLIQS-S at approximately 73 GBOPs while maintaining 77.40% accuracy — a 3.6× reduction in theoretical compute cost with only a 0.07 percentage point accuracy drop. On the GPU latency measurements in Table 3, this translates to a 1.30× speedup on RTX 2080 Ti and 1.21× on A6000 while keeping accuracy essentially unchanged. For a pipeline processing 100 million images daily, a 1.21× speedup on A6000 GPUs translates to approximately 17% fewer GPU-hours, directly reducing cloud compute costs. The key practical insight is that FLIQS's per-layer format heterogeneity (keeping first/last layers and skip-branch pointwise convolutions at INT8/BF16 while reducing interior layers to INT4) concentrates the hardware cost savings on the bulk of the compute while preserving accuracy on the most sensitive operations.
