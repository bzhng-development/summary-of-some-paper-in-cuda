## 1. Executive Summary

This work introduces **HySparse (Hybrid Sparse Attention)**, a new architecture that interleaves each full attention layer with multiple sparse attention layers, where the sparse layers derive both their token selection indices and KV caches directly from the preceding full attention layer — eliminating the proxy-based selection bottleneck and enabling cross-layer KV cache sharing simultaneously. The authors evaluate HySparse on both a 7B dense model (1:3 full-to-sparse ratio) and an 80B MoE model (1:11 full-to-sparse ratio) against full attention and hybrid sliding window attention baselines across general benchmarks, long-context RULER, and ablation conditions. HySparse consistently outperforms both baselines — in the 80B MoE setting with only 5 full attention layers out of 49 total — achieving a nearly 10× KV cache reduction while delivering substantial performance gains, establishing that oracle-guided sparse token selection from full attention layers can push hybrid ratios to their limit without compromising long-context modeling, provided that each sparse layer retains an independent sliding window KV cache rather than sharing the full attention cache for local computation.

## 2. Context and Motivation

### The Core Problem: Sparse Attention Improves Computation but Not Memory, and Token Selection Relies on Unreliable Proxies

The fundamental problem this paper addresses is a **decoupling of benefits** in modern sparse attention methods for large language models. Sparse attention — the technique of computing attention over a subset of tokens rather than the full sequence — is the primary architectural solution to the $O(n^2)$ quadratic scaling of self-attention with sequence length. However, the paper identifies that existing sparse attention approaches succeed at reducing *computation* but largely fail at reducing *memory*, while simultaneously depending on low-fidelity mechanisms to decide *which* tokens to attend to. These two limitations are not independent failures — they interact in ways that constrain the practical deployment of sparse attention in long-context settings.

To understand why this matters, we need to be precise about what happens during autoregressive generation with long contexts. When a transformer generates token $t$, the self-attention mechanism computes:

$$o_t = \sum_{i=1}^{t} \frac{\exp(q_t^\top k_i / \sqrt{d})}{\sum_{j=1}^{t} \exp(q_t^\top k_j / \sqrt{d})} v_i$$

This is computed for every layer, every head, and every generated token. The FLOPs cost grows as $O(t^2)$ across the full generation, since each new token re-attends to all previous positions. Simultaneously, the KV cache — the stored key and value tensors $\{k_i, v_i\}_{i=1}^{t}$ — grows linearly with sequence length and is stored for every layer independently. For a model with $L$ layers, $H$ KV heads, and head dimension $d$, the KV cache size at sequence length $n$ is approximately $2 \times L \times H \times d \times n$ elements (in half-precision). At long context lengths (32k, 128k, or 1M tokens), this becomes the dominant memory bottleneck, limiting batch size during inference and constraining throughput even before computation becomes the primary concern.

Sparse attention methods attempt to solve both problems by attending to only $k \ll n$ selected tokens. However, the paper argues that **most methods only actually solve one problem**. Let's trace through why.

### Limitation 1: Proxy-Based Token Selection Is Inherently Unreliable

Sparse attention requires a mechanism to select which $k$ tokens are important *before* computing the full attention matrix. Since the full attention scores are not known a priori, methods must rely on some **proxy** — an approximate, cheaper-to-compute signal that estimates token importance. The paper categorizes these proxies into two broad families and explains why both are inadequate.

**Training-free proxies** use fixed patterns or heuristics that require no model modification. Examples include:

- **Sliding window attention**: attending only to the $w$ most recent tokens (Xiao et al., 2023, 2024; Zhang et al., 2023). This assumes that local context dominates importance — a reasonable heuristic for some tasks but demonstrably wrong for tasks requiring retrieval from distant positions (e.g., finding a fact mentioned 10,000 tokens ago).
- **Query-aware sparsity**: using the current query to estimate which keys will have high dot-product scores without computing the full matrix, typically through approximate nearest-neighbor search or low-rank projections (Jiang et al., 2024; Tang et al., 2024).
- **Heuristic importance scoring**: selecting tokens based on accumulated attention statistics from prior layers or prior steps (Zhang et al., 2023; Xiao et al., 2024).

The paper identifies a critical limitation that goes beyond simple inaccuracy: training-free methods create a **training-inference mismatch**. The model was trained with full attention — every token had access to every other token. At inference time, sparsity is suddenly imposed, meaning tokens can only attend to a subset. This mismatch is not merely a theoretical concern. As the paper notes (Section 2.1), it can lead to "error accumulation in long decoding or multi-step reasoning" (He and Lab, 2025; Hu et al., 2026; Liu et al., 2025b). The intuition is that in a multi-step reasoning chain, each step conditions on the previous context through attention. If attention is truncated at inference time, information that the model was trained to rely on may be silently dropped, and these errors compound across decoding steps.

**Trainable proxies** attempt to close the training-inference gap by learning the token selection mechanism during training. The paper discusses several approaches:

- **Self-distillation methods** (Gao et al., 2024, 2025; Liu et al., 2025a) train a lightweight gating or indexing module to predict which tokens the full attention would have attended to, using the full attention's own scores as distillation targets. The selection module is trained to approximate the full attention's behavior.
- **End-to-end sparse pretraining** (Yuan et al., 2025; Lu et al., 2025) integrates sparsity directly into the architecture during pretraining, typically by having a compressed attention pathway whose output feeds into the main attention computation.

The paper's critique of trainable proxies is nuanced and important. The fundamental issue is not that these methods are inaccurate — they can be quite effective — but rather that they **add complexity without eliminating the proxy bottleneck**. Self-distillation methods require training an auxiliary module with additional loss terms, increasing the training recipe's complexity. The gating or indexing modules are themselves approximations, and their quality bounds the quality of the sparse attention. End-to-end methods like NSA (Yuan et al., 2025) allow the selection module to receive gradients only indirectly through the final attention output, without "direct supervision on its token selection decisions" (Section 2.1). This means the selection module never receives explicit feedback about which tokens it *should* have selected — only about whether the final output was good. Learning to select tokens from this weak signal is inherently challenging.

A concrete example helps illustrate the difference: suppose a question requires retrieving a specific numerical value mentioned in paragraph 3 of a long document. A training-free heuristic might select tokens from the beginning and end of the document (common heuristics), missing paragraph 3 entirely. A self-distilled proxy might learn that paragraph 3 is important for this *type* of question, but will be limited by the fidelity of its learned approximation. **HySparse's key insight** is that there is a source of ground-truth token importance available for free: the *preceding full attention layer*. Since full attention computes the exact attention scores for all tokens, it provides an oracle signal — not an approximation — about which tokens are important, at least for that layer's representation.

The paper explicitly frames this as eliminating the proxy: "this eliminates the need for auxiliary proxy modules and ensures stable end-to-end training" (Section 1). The word "oracle" in the title is crucial — it signifies that the token selection signal comes from exact attention computation (the oracle), not from a learned or heuristic approximation (the proxy).

### Limitation 2: Computation Reduction Without Memory Relief

The second limitation is about KV cache memory, and understanding it requires carefully distinguishing between **static** and **dynamic** sparsity patterns.

**Static sparsity** uses fixed patterns — for example, every layer attends to tokens $t-w$ through $t$ (sliding window) plus every $s$-th token (strided). Because the pattern is fixed and known in advance, the KV cache can be **evicted** — tokens that will never be attended to by any future generation step can be deleted. This provides genuine memory savings. However, the paper notes that static patterns "often incur noticeable performance degradation" (Section 1). The fixed selection cannot adapt to the content — a token that happens to fall outside the window but is crucial for answering a question will be lost permanently.

**Dynamic sparsity** selects tokens adaptively based on the current query and context. A token that is unimportant for one generation step might become important for the next. Because token importance can shift as generation progresses, dynamic methods typically **retain the full KV cache** — evicting a token from cache is irreversible and could be catastrophic if that token later becomes important. This means that while dynamic sparse attention reduces FLOPs (fewer attention dot-products are computed), it provides "no relief for memory consumption" (Section 1). The full KV cache must still be stored.

This is a profound practical limitation because, as the paper points out, **memory is often the dominant bottleneck** for long-context inference. KV cache memory constrains the maximum batch size — you can only serve as many sequences simultaneously as can fit in GPU memory alongside the model weights and intermediate activations. For a service provider running inference at scale, doubling the context length without reducing per-sequence memory means halving the batch size, which roughly halves throughput and revenue. Reducing computation without reducing memory addresses only half the problem.

Some methods attempt a middle ground. For example, models that use a small constant-size sliding window plus a "global" selection of $k$ tokens can evict tokens outside both sets. But the selection of global tokens still depends on a proxy or heuristic, and the eviction is still irreversible if the proxy makes a mistake.

### Why This Problem Matters Now

The paper connects these limitations to three contemporary trends that make the problem urgent (Section 1):

1. **Test-time scaling** (Guo et al., 2025; Jaech et al., 2024): Modern LLMs are increasingly used in settings where they generate long chains of reasoning — thousands of tokens of intermediate computation — before producing a final answer. These long generations produce enormous KV caches that grow linearly with the reasoning chain length. Without memory-efficient attention, the cost of serving such models becomes prohibitive.

2. **Agentic workflows** (Anthropic, 2024; Kimi Team et al., 2025a): AI agents that interact with tools, maintain state across multiple turns, and process long conversation histories require models to attend to very long contexts. The KV cache for a multi-turn agent conversation can easily span tens of thousands of tokens.

3. **Longer context demands generally**: Users increasingly expect models to process entire codebases, long documents, or multi-hour transcripts. Model providers have responded by training models with 128k, 1M, or even 10M token context windows — but serving these models economically requires solving the KV cache memory problem.

### How Prior Work Approaches the Problem — and Where It Falls Short

The paper provides a structured overview of the relevant prior work, which we can organize by how they address the twin challenges of computation and memory.

**Training-free sparse attention** (Jiang et al., 2024; Tang et al., 2024; Xiao et al., 2023, 2024; Yang et al., 2025b; Zhang et al., 2023) applies sparsity patterns at inference time without retraining. The advantage is simplicity — drop-in deployment without additional training cost. The disadvantages are threefold: (1) the proxy selection quality is bounded by the heuristics, (2) the training-inference mismatch can cause error accumulation, and (3) dynamic variants still retain the full KV cache, providing no memory savings. The paper cites recent work (He and Lab, 2025; Hu et al., 2026) showing these methods can be "defeated" by the nondeterminism introduced through mismatch.

**Trainable sparse attention** (Gao et al., 2024, 2025; Liu et al., 2025a; Lu et al., 2025; Yuan et al., 2025; Zhao et al., 2025) integrates sparsity into training. This improves the quality of token selection — the model learns what to attend to — but introduces new problems: additional modules, training complexity, auxiliary loss tuning, and still no memory savings for dynamic variants. The paper specifically notes that even state-of-the-art methods like SeerAttention (Gao et al., 2024) and DSA (Liu et al., 2025a) "typically rely on gating or indexing mechanisms that still operate in $O(n^2)$, albeit in a compressed form" (Section 5). These methods reduce but do not eliminate the quadratic cost.

**Hybrid attention architectures** combine different attention mechanisms within a single model. This is the closest architectural lineage to HySparse, and the paper carefully positions its contribution relative to this family. The key observation is that prior hybrid architectures have **not** combined dynamic sparse attention with full attention interleaving:

- **Hybrid linear+softmax attention** (Li et al., 2025a; Qwen Team, 2025; Kimi Team et al., 2025b) replaces some softmax attention layers with linear attention or state-space model variants. This reduces both computation and memory (linear attention has constant-size state rather than growing KV cache), but comes at the cost of representational capacity — linear attention cannot express certain attention patterns that softmax attention can.
- **Hybrid Mamba+Transformer** (Basant et al., 2025; Blakeman et al., 2025; Lieber et al., 2024) interleaves Mamba/SSM blocks with standard attention blocks. Similar tradeoff: Mamba provides efficient sequence modeling but is not a drop-in replacement for attention on all tasks.
- **Hybrid sliding window + global attention** (Agarwal et al., 2025; Gemma Team et al., 2025; Xiaomi Team et al., 2026) interleaves full attention layers with sliding window attention layers. The full attention layers provide periodic global context, while SWA layers handle local computation with minimal KV cache. This is the **direct baseline** for HySparse. The paper's Hybrid SWA baseline directly follows this pattern, using a 1:3 or 1:11 full-to-SWA layer ratio.

The critical gap the paper identifies is that hybrid SWA models still rely on a crude proxy for token selection in the non-full layers: the sliding window. Sliding window is a fixed heuristic — it attends to the last $w$ tokens regardless of content. When the full-to-SWA ratio becomes aggressive (1:11, meaning only 5 full attention layers out of 49), the model goes many consecutive layers without any global context, relying entirely on local windows. The paper's 80B MoE results (Table 2 and Table 3) demonstrate this empirically: Hybrid SWA degrades substantially at the 1:11 ratio on benchmarks like DROP (56.7 → 47.8 from Full-Attn to Hybrid SWA in 80B MoE) and RULER (93.6 → 72.7 overall at 16k in 80B MoE), while HySparse recovers or exceeds full attention performance.

**Cross-layer KV cache sharing** provides a separate but complementary line of work. YOCO (Sun et al., 2024), CLA (Brandon et al., 2024), and others show that sharing KV caches between layers — having layer $l+1$ reuse the keys and values computed at layer $l$ — reduces memory with minimal accuracy loss. The paper builds on this observation but adds a crucial refinement: sharing is beneficial for *global* retrieval (the sparse attention branch) but harmful for *local* computation (the sliding window branch). This finding, demonstrated in the ablation study (Table 4), is one of the paper's key empirical contributions and will be discussed in detail later.

**Cross-layer salient token stability** is the second empirical observation HySparse leverages. Several concurrent works (Deshmukh et al., 2025; Hao et al., 2025; Yang et al., 2024a, 2025a; Zarch et al., 2025) observe that the set of tokens receiving high attention scores remains relatively stable across consecutive transformer layers. This observation has been exploited for inference acceleration: after computing full attention at layer $l$, use the same important token indices for layers $l+1$, $l+2$, etc., avoiding the cost of recomputing or re-estimating importance. The paper explicitly states (Section 2.3): "Inspired by these works, we elevate this empirical observation to a hybrid attention architecture for pretraining." In other words, prior work used cross-layer stability as a post-hoc inference optimization; HySparse embeds it directly into the training architecture, making it a first-class design principle rather than an approximate shortcut.

### How HySparse Positions Itself

The paper's positioning is clearest when we understand what HySparse is and is not trying to do. It is not proposing a new sparse attention algorithm, a new token selection mechanism, or a new type of linear attention. Instead, it proposes an **architectural pattern** that combines existing components — full attention, sparse attention, sliding window attention, and cross-layer KV sharing — in a way that addresses the two fundamental limitations simultaneously.

The architectural pattern can be summarized as a design rule: **Every sparse attention layer should derive both its token selection and its KV cache for global retrieval from the nearest preceding full attention layer.** This rule embodies three key design decisions:

1. **Oracle token selection**: By reusing the preceding full attention layer's attention scores to identify important tokens, sparse layers get exact, high-quality token selection without any proxy, auxiliary module, or additional loss. The full attention layer serves as the oracle.

2. **Cross-layer KV cache sharing for sparse attention**: Since the full attention layer already computed and stored KV tensors for all tokens, sparse layers can reuse those tensors rather than computing and storing their own. This means sparse layers contribute zero additional KV cache for their global retrieval branch.

3. **Independent KV cache for local computation**: Each sparse layer maintains its own small sliding window KV cache (window size 128 tokens). The ablation study (Table 4) shows this is essential — forcing the SWA branch to share the full attention's KV cache degrades performance substantially (e.g., MMLU drops from 58.4 to 52.8 when sharing for both SA and SWA).

The paper positions this architecture relative to existing work along two axes. **Relative to sparse attention methods**, HySparse eliminates the proxy bottleneck entirely by using exact full attention scores. It is not a better proxy — it is a fundamentally different approach that avoids the proxy problem. **Relative to hybrid attention architectures**, HySparse shows that you can push the full-to-sparse ratio much further than Hybrid SWA allows. The 1:11 ratio in the 80B MoE model — only 5 full attention layers out of 49 — would cause severe degradation in a Hybrid SWA model, but HySparse not only recovers the degradation but surpasses Full-Attn. This is the paper's central empirical claim: that oracle-guided sparse selection enables more aggressive hybrid ratios than previously possible.

A subtle but important positioning point: HySparse does **not** aim to eliminate full attention entirely. Section 5 explicitly discusses this: "it remains challenging to completely eliminate $O(n^2)$-style full attention components in practice." The goal is not removal but *reduction* — minimizing the number of full attention layers while preserving model quality. The paper argues that what matters is "the ratio of expensive global computation to cheaper local or sparse computation, as well as GPU memory usage" (Section 5). HySparse improves this ratio dramatically: in the 80B MoE model, 5 out of 49 layers do the expensive $O(n^2)$ computation, while 44 layers do the cheaper $O(k)$ sparse attention ($k = 1024$) plus $O(w)$ sliding window ($w = 128$). The KV cache is reduced by nearly 10× because only 5 layers (plus the small SWA caches in 44 layers) need storage, compared to 49 layers in a standard full attention model.

In summary, the paper addresses a concrete, well-motivated gap: existing sparse attention methods improve computation but not memory, and their token selection quality is bottlenecked by proxy fidelity. HySparse proposes to resolve both limitations through an architectural pattern that treats full attention layers as oracles for subsequent sparse layers, enabling aggressive hybrid ratios without sacrificing performance. The approach builds on two empirically observed phenomena — cross-layer salient token stability and cross-layer KV cache sharing — and elevates them from post-hoc inference optimizations to architectural design principles for pretraining.

## 3. Technical Approach

### 3.1 Reader Orientation

HySparse is a **model architecture** — not a post-processing trick or inference optimization — that replaces the standard transformer layer stack with a repeated pattern of one full attention layer followed by multiple sparse attention layers, where the sparse layers inherit their global-view capabilities from the full layer rather than building their own. The system solves the twin problems of (1) requiring unreliable proxies to select important tokens in sparse attention, and (2) sparse attention reducing computation without reducing KV cache memory, by treating each full attention layer as an **oracle** whose exact attention scores identify important tokens and whose already-computed KV cache can be reused by subsequent sparse layers. The "shape" of the solution is a block-structured interleaving pattern: `[Full-Attn → Sparse-Attn₁ → Sparse-Attn₂ → ... → Sparse-Attn_N]`, repeated across the depth of the model, with the final layer always using full attention for final global aggregation.

### 3.2 Big-Picture Architecture (Diagram in Words)

The HySparse architecture replaces the standard transformer backbone with repeated **hybrid blocks**. Each hybrid block contains:

- **One full attention layer** that computes standard softmax self-attention over all tokens. This layer serves three purposes simultaneously: (a) it processes the current hidden states through full global attention, (b) it outputs **block-level attention scores** that identify which token blocks are most important (the "oracle" selection signal), and (c) it produces a full KV cache that represents every token's key and value for this layer's perspective.

- **N subsequent sparse attention layers** (where N=3 for the 7B model, N=11 for the 80B MoE model) that each contain two parallel attention branches computed from the same query: a **block sparse attention branch** that attends only to the top-k token blocks identified by the preceding full attention layer (using the full attention layer's KV cache, not its own), and a **sliding window attention branch** that attends to the most recent 128 tokens (maintaining its own small, independent KV cache). The outputs of these two branches are fused via learned sigmoid gates.

Information flows through a hybrid block as follows:

1. Hidden states enter the full attention layer, which computes standard global attention and produces updated hidden states, block-level attention importance scores `S`, and a full KV cache `(K_full, V_full)`.

2. The block attention scores `S` are processed by a TopK operator to produce a set of block indices `I` identifying the most-attended token blocks.

3. The hidden states pass through the standard feed-forward or MoE layer after the full attention.

4. These hidden states then enter the first sparse attention layer. The sparse layer computes queries `Q'` from the current hidden states. The block sparse attention branch attends to the token blocks indexed by `I`, using `K_full` and `V_full` as its key-value source. In parallel, the sliding window branch attends to the `w=128` most recent tokens using its own independently maintained KV cache. The two branch outputs are gated and summed.

5. Steps 2-4 repeat for each subsequent sparse layer in the block, with all sparse layers sharing the same block indices `I` and the same full attention KV cache `(K_full, V_full)`, though each maintains its own sliding window KV cache.

6. After N sparse layers, the next hybrid block begins with a new full attention layer, which computes fresh global attention, fresh block indices, and a fresh shared KV cache for its subsequent sparse layers.

The final layer of the entire model is always a full attention layer, regardless of the block structure, to ensure the model has one last global aggregation step before the language modeling head.

### 3.3 Roadmap for the Deep Dive

This is an **architectural design paper** whose core idea is that full attention layers can serve as oracles for subsequent sparse layers, eliminating both proxy-based token selection and per-layer KV cache overhead for global retrieval. I will explain:

- **First, the full attention layer's modified computation**, which must output block-level attention scores in addition to the standard attention output. This requires understanding how FlashAttention works internally (its tiled online softmax procedure) and how a small modification exposes tile-level attention maxima that serve as the oracle signal. This is the foundation — without this modification, HySparse cannot extract token importance from full attention layers without materializing the prohibitively expensive full attention matrix.

- **Second, how the block-level scores are converted into sparse indices**, including the TopK selection mechanism, the block size and top-k values, and how Grouped-Query Attention (GQA) is handled to ensure index sharing within query groups for kernel efficiency.

- **Third, the sparse attention layer's dual-branch structure**, covering (a) the block sparse attention branch that reuses both indices and KV cache from the full layer, (b) the sliding window attention branch that maintains independent local KV cache, and (c) the sigmoid-gated fusion mechanism that dynamically mixes global and local information. This section also explains the critical ablation finding of *why* the SWA branch needs its own KV cache rather than sharing the full layer's.

- **Fourth, the overall architectural configuration and training setup**, including the hybrid ratios (1:3 for 7B, 1:11 for 80B), the block size, number of selected tokens, sliding window size, and where full attention layers are positioned in the stack, plus training hyperparameters like sequence lengths, learning rates, and the WSD schedule.

I follow this order because the full attention layer modification is the enabling mechanism — you can't understand how sparse layers get their oracle indices without first understanding what the full layer outputs and why. The sparse layer structure then builds naturally on this output. The architectural configuration ties everything together into a concrete instantiation.

### 3.4 Detailed, Sentence-Based Technical Breakdown

#### Full Attention Layers as Oracles: Extracting Block-Level Attention Scores

The full attention layers in HySparse serve a dual role not found in standard transformers. In addition to computing the standard self-attention output, they must **expose attention importance scores** that can be used to select which token blocks subsequent sparse layers will attend to. This is the "oracle" function — the full attention layer tells the sparse layers exactly which tokens it found most important.

The challenge is that modern transformers use **FlashAttention** (Dao et al., 2022; Dao, 2023; Shah et al., 2024) to compute attention without materializing the full attention matrix. Standard FlashAttention computes attention in tiles, using an online softmax algorithm that processes the attention scores in chunks and never stores the complete `$n \times n$` attention matrix in high-bandwidth memory. The attention scores exist only transiently in SRAM during each tile computation and are discarded after the softmax normalization is applied to accumulate the output. This is what makes FlashAttention memory-efficient and fast — but it means the raw attention scores are not available for token importance selection.

The paper's key technical contribution at this layer is a **modification to FlashAttention that exposes block-level (tile-level) maximum attention scores** with negligible overhead, by leveraging intermediate values that FlashAttention already computes during its online softmax procedure. To understand how this works, we need to understand what FlashAttention computes internally.

**Standard FlashAttention background.** FlashAttention processes attention in tiles. The queries are divided into row-blocks of size `$B_M$` and the keys/values into column-blocks of size `$B_N$`. For each query block `$Q_i \in \mathbb{R}^{B_M \times d}$`, FlashAttention iterates over all key-value blocks `$(K_j, V_j) \in \mathbb{R}^{B_N \times d}$`, computing the attention logits `$A_{ij} = Q_i K_j^\top \cdot \tau$` (where `$\tau = 1/\sqrt{d}$` is the softmax scale) for that tile. The online softmax algorithm maintains two running statistics: a row-wise maximum `$\boldsymbol{m}_i$` (used to stabilize the softmax computation by subtracting the maximum before exponentiation) and a row-wise sum `$\ell_i$` (the unnormalized softmax denominator, used for final normalization). As each key-value tile is processed, the algorithm updates:

- `$\tilde{\boldsymbol{m}}_{ij} \leftarrow \text{rowmax}(A_{ij})$`: the maximum logit within the current tile `$(i,j)$`
- `$\boldsymbol{m}_i \leftarrow \max(\boldsymbol{m}_i, \tilde{\boldsymbol{m}}_{ij})$`: update the global row-wise maximum
- Rescale the accumulated output and denominator using the ratio `$\exp(\boldsymbol{m}_i^{\text{old}} - \boldsymbol{m}_i^{\text{new}})$` to adjust for the new maximum
- Accumulate the softmax-weighted values and the new denominator

After all key-value tiles have been processed for query block `$i$`, the output is normalized by dividing by the final denominator `$\ell_i$`.

**The modification for block-level score output.** The crucial observation is that during this iteration, FlashAttention already computes `$\tilde{\boldsymbol{m}}_{ij} = \text{rowmax}(A_{ij})$` — the maximum attention logit within each tile. The paper's modification is to **store this intermediate value** and then, after the final row-wise maximum `$\boldsymbol{m}_i$` and denominator `$\ell_i$` have been computed, **rescale and output these tile-level maxima as block-level attention scores**.

Specifically, Algorithm 1 in the paper describes the procedure. For each tile `$(i, j)$`:

1. During the forward pass, after computing the tile-level logits `$A_{ij}$`, the algorithm computes `$\tilde{\boldsymbol{m}}_{ij} = \text{rowmax}(A_{ij})$` and stores it in an auxiliary tensor `$S_{ij}$` (line 8 of Algorithm 1).

2. After all key-value tiles for query block `$i$` have been processed, the algorithm has the final row-wise maximum `$\boldsymbol{m}_i$` and the final denominator `$\ell_i$` (the sum of exponentiated, max-subtracted scores).

3. The stored tile-level maxima are then **rescaled** to convert them from raw logit-space maxima to proper attention score maxima (lines 13-15 of Algorithm 1). For each tile `$j$`, the block-level attention score is computed as:

$$S_{ij} \leftarrow (S_{ij} - \boldsymbol{m}_i) / \ell_i$$

Let's walk through what this rescaling does and why it produces a meaningful attention score.

**What the rescaling computes conceptually.** During online softmax, the raw logits are stabilized by subtracting the row-wise maximum before exponentiation:

$$\text{softmax}(A)_t = \frac{\exp(A_t - m)}{\sum_{t'} \exp(A_{t'} - m)}$$

The stored value `$S_{ij}$` was originally `$\tilde{\boldsymbol{m}}_{ij} = \max_{t \in \text{tile } j} A_t$`, the maximum raw logit within tile `$j$`. After rescaling, `$S_{ij} - m_i$` gives `$\max_{t \in \text{tile } j} (A_t - m_i)$`, the maximum stabilized logit within the tile. Dividing by `$\ell_i = \sum_{t'} \exp(A_{t'} - m_i)$` gives:

$$S_{ij} = \frac{\exp(\max_{t \in \text{tile } j} (A_t - m_i))}{\ell_i} = \max_{t \in \text{tile } j} \frac{\exp(A_t - m_i)}{\ell_i} = \max_{t \in \text{tile } j} \text{softmax}(A)_t$$

In words: **the output `$S_{ij}$` is the maximum attention probability assigned to any token within block `$j$` by any query position in query block `$i$`**. This is exactly what the paper's Equation 3 defines:

$$S_t^i = \max_{i' \in \mathcal{B}_i} \left( \frac{\exp(q_t^\top k_{i'} / \sqrt{d})}{\sum_{j=1}^{t} \exp(q_t^\top k_j / \sqrt{d})} \right)$$

where `$\mathcal{B}_i$` is the set of token indices in block `$i$`, `$t$` indexes the query position, and `$d$` is the head dimension.

**Why block-level maximum instead of other aggregations.** The paper uses the block-level maximum attention score rather than other possible aggregations (such as the sum or mean of attention scores within a block) for a practical reason embedded in how FlashAttention works. The online softmax algorithm already computes the row-wise maximum for numerical stability (to prevent overflow when exponentiating large logits). This maximum is computed at the tile level as an intermediate step. By using the maximum, the algorithm can extract the block-level importance signal from information that FlashAttention already computes and stores transiently — the modification is essentially "don't discard this value, save it and rescale it." Computing the sum or mean of attention scores within a tile would require materializing and storing the full attention matrix for that tile, defeating the purpose of using FlashAttention's memory-efficient tiled computation.

The block size `$B$` is set to **64 tokens** by default (matching the FlashAttention block size `$B_N$`). This means the full attention layer outputs a score matrix `$S \in \mathbb{R}^{t \times \lceil t/B \rceil}$` where `$t$` is the current sequence length. Each entry `$S_{ij}$` is the maximum attention probability that query position `$i$` assigned to any token in block `$j$`.

**Computational cost of the modification.** The paper states this modification introduces "negligible overhead" because (a) the tile-level maxima are already computed during the standard FlashAttention forward pass for numerical stability, (b) storing them requires only `$O(t \cdot \lceil t/B \rceil)$` memory rather than the `$O(t^2)$` memory that would be needed for the full attention matrix, and (c) the rescaling step is a simple element-wise subtraction and division that runs after the main attention computation is complete. For a sequence of length 32,768 with block size 64, the score matrix `$S$` has dimensions `$32768 \times 512$`, which is `$512$` times smaller than the full attention matrix.

#### From Block Scores to Sparse Indices: TopK Selection and GQA Handling

The block-level attention score matrix `$S$` contains, for each query position, the maximum attention probability assigned to each token block. The next step is to convert this into a set of block indices `$I$` that specify which blocks the subsequent sparse attention layers should attend to. The paper applies a **TopK operator** to select the `$k/B$` blocks with the highest scores, where `$k$` is the target number of tokens for sparse attention and `$B$` is the block size.

**The TopK selection procedure.** The default values established in the paper are:

- **Sparse attention token budget `$k = 1024$`**: each sparse attention layer attends to exactly 1024 tokens from the full context for its block sparse attention branch. This is a constant that does not scale with sequence length — at 32k context, sparse attention uses only `$1024/32768 \approx 3.1\%$` of the tokens.

- **Block size `$B = 64$`**: tokens are selected in contiguous blocks of 64. This means the TopK operator selects `$1024/64 = 16$` blocks out of the `$\lceil t/64 \rceil$` total blocks (512 blocks at 32k context).

The block size of 64 is not arbitrary — it is chosen to match the FlashAttention tile size `$B_N$`, which ensures that the selected token blocks align with the memory access granularity of the sparse attention kernel. This is a hardware-alignment consideration: when the sparse attention kernel loads a selected block, it loads exactly one FlashAttention tile's worth of keys and values, maximizing memory bandwidth utilization.

**How TopK is applied across query positions.** The attention score matrix `$S$` has shape `$(t, \lceil t/B \rceil)$` — one row per query position. However, for kernel efficiency, sparse attention typically requires that all query positions within a **query group** (under Grouped-Query Attention) share the same set of selected key-value blocks. The paper addresses this explicitly: "Under Grouped-Query Attention (GQA), we further aggregate `$S$` within each query group (via a group-wise maximum) so that all heads in the same group share identical sparse indices, improving sparse attention kernel efficiency and reducing indexing overhead."

The aggregation works as follows:

1. For each query group (a set of query heads that share the same KV head), take the element-wise maximum of the block scores `$S$` across all query heads in that group. This produces a single score per block per query group.

2. Apply TopK selection independently for each query group based on these aggregated scores. This means different query groups can select different blocks — which is desirable because different attention heads typically specialize in different types of information retrieval.

3. All query heads within a group use the same set of block indices `$I$` for their sparse attention computation.

This design choice trades some per-head selection granularity for substantial kernel efficiency gains. If each query head selected its own blocks independently, the sparse attention kernel would need to gather a different set of KV tiles for each head, leading to irregular memory access patterns and poor hardware utilization. By sharing indices within query groups (which already share KV heads by GQA design), the kernel can load one set of KV tiles and use them for all heads in the group.

**The oracle nature of the selection.** The paper emphasizes that this selection is "oracle" because it is derived from exact full attention scores — not from a learned gating module, a heuristic like positional distance, or an approximate low-rank projection. The full attention layer literally computes the true attention probabilities for every token, and the TopK blocks are simply those that received the highest attention. This is what distinguishes HySparse from all proxy-based methods: the selection signal has perfect fidelity (for the representation space of that particular full attention layer) because it is the actual attention computation, not an approximation of it.

**Why does this work across multiple subsequent layers?** The paper does not attempt to prove theoretically that token importance is stable across layers — it cites empirical evidence from concurrent work (Section 2.3: Deshmukh et al., 2025; Hao et al., 2025; Yang et al., 2024a, 2025a; Zarch et al., 2025) showing that salient tokens remain relatively stable across consecutive transformer layers. The key empirical validation is **whether the model performs well when trained with this architectural constraint**. The results in Tables 2 and 3 demonstrate that it does — HySparse not only matches but often exceeds full attention performance despite sparse layers using stale indices from the preceding full layer. This validates that the cross-layer stability hypothesis holds sufficiently well for this architectural pattern to work.

However, the paper implicitly acknowledges that stability is not perfect by including the sliding window branch. If the oracle-selected blocks perfectly captured all important tokens for all subsequent layers, the SWA branch would be redundant. The ablation study (Table 4, discussed in detail below) shows that removing the SWA branch causes significant accuracy drops, confirming that the oracle selection is good but not perfect, and that a local attention pathway provides complementary coverage.

#### Sparse Attention Layer Structure: Dual-Branch Architecture with Gated Fusion

Each sparse attention layer in HySparse contains two attention branches operating in parallel on the same query, followed by a learned gated fusion. This dual-branch design is the mechanism by which sparse layers achieve both global retrieval (through the block sparse branch using oracle indices) and local coherence (through the sliding window branch).

**Query, Key, and Value projections.** The sparse attention layer applies a single set of linear projections to the input hidden states `$\boldsymbol{x}_t$` to produce queries, keys, and values:

$$\boldsymbol{q}'_t, \boldsymbol{k}'_t, \boldsymbol{v}'_t = \mathbf{W}_{q'/k'/v'} \boldsymbol{x}_t$$

where `$\mathbf{W}_{q'}, \mathbf{W}_{k'}, \mathbf{W}_{v'} \in \mathbb{R}^{d \times d}$` are the standard attention projection matrices (with appropriate reshaping for multi-head or grouped-query attention). Critically, the **same query `$\boldsymbol{q}'_t$` is used for both the sparse attention branch and the sliding window branch**. This means the model computes one set of queries and uses them to interrogate two different key-value sources, rather than computing separate queries for each branch.

**Branch 1: Block Sparse Attention.** The block sparse attention branch attends to the key-value blocks indexed by `$I$`, where both `$I$` and the key-value tensors are derived from the preceding full attention layer:

$$\tilde{\mathbf{K}}, \tilde{\mathbf{V}} = \text{concat}\left( \{\mathbf{K}_{\text{full}}[(j-1)B+1 : jB], \mathbf{V}_{\text{full}}[(j-1)B+1 : jB]\}_{j \in I} \right)$$

This concatenation operation gathers the selected blocks from the full attention layer's KV cache and concatenates them into a contiguous tensor. If the TopK selection chose 16 blocks of size 64, then `$\tilde{\mathbf{K}}, \tilde{\mathbf{V}} \in \mathbb{R}^{1024 \times d}$` (for the KV head dimension).

The sparse attention output is then computed as standard softmax attention over these selected tokens:

$$\tilde{\boldsymbol{o}}_t = \sum_{i=1}^{k} \frac{\exp(\boldsymbol{q}_t'^\top \tilde{\boldsymbol{k}}_i / \sqrt{d})}{\sum_{j=1}^{k} \exp(\boldsymbol{q}_t'^\top \tilde{\boldsymbol{k}}_j / \sqrt{d})} \tilde{\boldsymbol{v}}_i$$

where `$k = 1024$` is the number of selected tokens. This computation costs `$O(k)$` per query position rather than `$O(t)$` for full attention. At sequence length 32,768, this is approximately a 32× reduction in attention FLOPs for this branch.

**Why reuse the full attention layer's KV cache rather than computing new keys and values.** This is one of the two key memory innovations of HySparse. The sparse attention layer does **not** compute its own keys and values for the global retrieval branch. Instead, it uses the keys and values that the preceding full attention layer already computed and stored. This means:

- The sparse layer contributes **zero additional KV cache entries** for its global retrieval pathway. The full attention layer already stored its KV cache; the sparse layer simply reads from it.
- The sparse layer's `$\mathbf{W}_{k'}$` and `$\mathbf{W}_{v'}$` projections are used **only for the sliding window branch** (see below), not for the sparse attention branch. This is a design choice that the ablation study validates: sharing the full attention KV cache for the sparse branch works well, but sharing it for both branches degrades performance.

This design relies on the assumption that the full attention layer's keys and values are sufficiently informative for the sparse layers' retrieval needs — that the representation space of the full layer's KV cache is compatible with the sparse layers' queries. The cross-layer KV cache sharing literature (Section 2.4) provides empirical precedent for this assumption, but the paper adds the refinement that compatibility holds for *global* retrieval but not for *local* processing.

**Branch 2: Sliding Window Attention.** In parallel with the block sparse attention, each sparse layer computes sliding window attention over the most recent `$w = 128$` tokens:

$$\boldsymbol{o}'_t = \sum_{i=t-w+1}^{t} \frac{\exp(\boldsymbol{q}_t'^\top \boldsymbol{k}'_i / \sqrt{d})}{\sum_{j=t-w+1}^{t} \exp(\boldsymbol{q}_t'^\top \boldsymbol{k}'_j / \sqrt{d})} \boldsymbol{v}'_i$$

This branch uses its **own independently maintained KV cache** — the keys and values `$\boldsymbol{k}'_i, \boldsymbol{v}'_i$` are computed using `$\mathbf{W}_{k'}$` and `$\mathbf{W}_{v'}$` and stored separately for each sparse layer. Since the window size is only 128 tokens, this KV cache overhead is negligible: 128 entries per sparse layer per head, compared to 32,768 entries per full attention layer. For the 80B MoE model with 44 sparse layers, the total SWA KV cache is `$44 \times 128 \times (\text{number of KV heads}) \times (\text{head dimension})$` — a small fraction of what full attention KV caches would require.

**Why 128 tokens for the sliding window.** The paper does not provide an extensive ablation on window size, but 128 is consistent with prior work on hybrid SWA architectures (Agarwal et al., 2025; Gemma Team et al., 2025; Xiaomi Team et al., 2026). The window size represents a tradeoff: larger windows capture more local context at higher memory cost, smaller windows reduce memory but may miss important local dependencies. The choice of 128 suggests that for the tasks evaluated (general reasoning, long-context retrieval, math, code), the most critical local information is within approximately 128 tokens of the current position.

**Gated fusion of the two branches.** The outputs of the two branches are combined using learned sigmoid gates, following the approach of Qiu et al. (2025):

$$\tilde{g}_t, g'_t = \sigma(\mathbf{W}_{\tilde{g}/g'} \boldsymbol{x}_t)$$

$$\boldsymbol{o}_t = \tilde{g}_t \odot \tilde{\boldsymbol{o}}_t + g'_t \odot \boldsymbol{o}'_t$$

where `$\sigma$` is the sigmoid function, `$\mathbf{W}_{\tilde{g}/g'} \in \mathbb{R}^{2 \times d}$` is a learned linear projection that outputs two scalar gate values (one per branch), and `$\odot$` denotes element-wise multiplication. The gate values `$\tilde{g}_t \in (0, 1)$` and `$g'_t \in (0, 1)$` control how much each branch contributes to the final output at each position.

The sigmoid gating (as opposed to softmax gating where the two gates sum to 1) allows both branches to contribute strongly or weakly simultaneously — the model can attend heavily through both pathways, heavily through one, or lightly through both. This provides more flexibility than softmax gating, where increasing one branch's contribution necessarily decreases the other's.

The gating projection takes the **input hidden states** `$\boldsymbol{x}_t$` as its input, not the attention outputs. This means the gate values are computed before the attention computation, but applied after. The gating is computed per-position, not globally — each token position independently decides its mix of global and local information.

**Sink biases in sparse and sliding window attention.** The paper mentions (Section 4.1) that "for sparse attention and sliding window attention, we incorporate per-head learnable sink biases, following the approach in gpt-oss (Agarwal et al., 2025)." Attention sinks are a recent finding (Xiao et al., 2023) that certain tokens (often the initial tokens) act as "sinks" that absorb excess attention probability during softmax computation, helping stabilize the attention distribution. A learnable sink bias adds a learned scalar offset to the attention logits of a specific token position (or set of positions) before softmax, encouraging the model to route excess probability mass to these sink tokens rather than distributing it arbitrarily across the sequence.

In HySparse, sink biases are applied per-head in the sparse attention and SWA branches. This is a standard stabilization technique in modern transformer training and not a core contribution of the paper, but it is important for reproducibility.

#### Why the SWA Branch Needs Its Own KV Cache: The Ablation Finding

One of the most informative parts of the technical approach is not the design that was ultimately chosen, but the alternative that was tested and rejected. The ablation study (Section 4.4, Table 4) directly addresses the question: **Can the sliding window branch also share the full attention layer's KV cache, maximizing memory savings?**

The answer is a clear **no**, and understanding why reveals important properties of the architecture.

**The experiment.** Three configurations were compared for the 7B dense model (all with the intra-layer SWA branch present):

- **HySparse (w/o intra-layer SWA)**: The sparse attention layer has no SWA branch at all — only the block sparse branch using oracle indices and full-layer KV cache. This tests whether the SWA branch is necessary at all.

- **HySparse (sharing for SA & SWA)**: Both the sparse attention branch and the SWA branch reuse the full attention layer's KV cache. The SWA branch attends to the most recent 128 tokens, but using the full attention layer's keys and values for those tokens rather than its own.

- **HySparse (sharing only for SA)**: The configuration used in the main HySparse model. The sparse attention branch reuses the full layer's KV cache; the SWA branch maintains its own independent KV cache (computed via `$\mathbf{W}_{k'}$` and `$\mathbf{W}_{v'}$`).

**Results from Table 4.** Sharing KV caches for both branches (SA & SWA) substantially degrades performance compared to sharing only for SA:

| Configuration | DROP | GSM8K | MMLU | MMLU-Pro | BBH |
|---|---|---|---|---|---|
| Sharing for SA & SWA | 47.9 | 30.2 | 52.8 | 23.2 | 47.2 |
| Sharing only for SA | 51.9 | 36.7 | 58.4 | 29.0 | 53.9 |

The performance gap is large and consistent: DROP drops by 4.0 points, GSM8K by 6.5 points, MMLU by 5.6 points, MMLU-Pro by 5.8 points, and BBH by 6.7 points.

**Why this happens: representation mismatch between global and local pathways.** The paper's explanation (Section 4.4, Study 2) is that the two attention branches serve fundamentally different roles and require different key-value representations:

- **The sparse attention branch** is optimized for **global retrieval** — it needs keys and values that are effective for long-range content-based lookup. The full attention layer's KV cache is optimized for this purpose, since the full attention layer was trained to do global attention. The representations in the full layer's KV cache encode information in a way that supports distinguishing relevant from irrelevant content across large distances.

- **The sliding window branch** is optimized for **local coherence** — it needs keys and values that are effective for modeling short-range syntactic and semantic dependencies within a narrow window of neighboring tokens. This requires representations that capture fine-grained local structure, which may be quite different from the representations optimized for global retrieval.

Forcing the SWA branch to use the full attention layer's KV cache means the sliding window must perform local modeling using representations that were optimized for a different task (global retrieval). The paper argues that this "deprives it of the short-range, local features it requires and entangles it with globally optimized representations, thereby weakening the local pathway and reducing overall accuracy."

This finding has important implications: **cross-layer KV cache sharing is not uniformly beneficial — it is beneficial specifically for global retrieval but harmful for local computation.** The successful application of KV sharing in prior work (YOCO, CLA, SwiftKV) may have worked because those methods applied sharing to the entire attention mechanism or to global-context layers, not to local-window branches. HySparse's contribution here is identifying this granularity: share KV caches for the global branch, maintain independent KV caches for the local branch.

**The necessity of the SWA branch itself.** Comparing "w/o intra-layer SWA" against "sharing only for SA" (with both using oracle token selection but no KV sharing), removing the SWA branch altogether also hurts performance substantially:

| Configuration | DROP | GSM8K | MMLU | MMLU-Pro | BBH |
|---|---|---|---|---|---|
| w/o intra-layer SWA | 46.4 | 29.7 | 57.1 | 25.0 | 48.2 |
| w/ intra-layer SWA | 52.2 | 37.7 | 56.1 | 26.5 | 52.4 |

The drops are particularly large on DROP (-5.8) and GSM8K (-8.0). This demonstrates that even with high-quality oracle token selection, the sparse attention branch alone is insufficient — there are important dependencies (likely local ones) that the oracle indices do not reliably capture. The SWA branch provides coverage for these cases, and the gated fusion allows the model to learn dynamically when to rely on global versus local information.

Another possible explanation the paper offers is that "the SWA branch may help stabilize optimization by providing a consistent local pathway, particularly during early training stages." During early training, the full attention layers' representations are not yet well-formed, so the oracle token selection may be noisy. The SWA branch provides a reliable fallback that ensures the model always has access to recent context, preventing the sparse layers from collapsing early in training before the oracle signal becomes meaningful.

#### Architectural Configuration and Training Setup

**Hybrid block structure.** The HySparse architecture divides the model's layers into blocks, where each block consists of one full attention layer followed by `$N$` sparse attention layers. The specific configurations are:

- **7B Dense Model**: 36 total layers, using a full-to-sparse ratio of **1:3**. This means each hybrid block contains 1 full attention + 3 sparse attention = 4 layers. With 36 layers and the final layer reserved for full attention, the 36 layers are organized as: 8 full attention layers (including the final) and 28 sparse attention layers, arranged in 7 hybrid blocks (with the final full attention layer serving as both the end of the last block and the final global aggregation). More precisely, the structure is: `[F, S, S, S] × 8 blocks + [F]` where F is full attention and S is sparse attention, giving 9 full attention layers and 27 sparse attention layers for 36 total. However, the paper says the final layer uses full attention, so a likely layout is `[F, S, S, S] × 8 = 32 layers, then 4 more sparse layers plus a final full = 37 layers total`. The exact layer breakdown is not fully specified, but the ratio of 1:3 is the defining constraint.

- **80B MoE Model**: 49 total layers, using a full-to-sparse ratio of **1:11**. This means each hybrid block contains 1 full attention + 11 sparse attention = 12 layers. With 49 layers and the final layer reserved for full attention, there are **only 5 full attention layers total** and 44 sparse attention layers. The arrangement is approximately `[F, S×11] × 4 blocks + [F]` = 4 × 12 + 1 = 49 layers, giving 5 full attention layers.

The aggressive 1:11 ratio in the 80B MoE model is a key demonstration of the paper's claim: HySparse can push the hybrid ratio far beyond what Hybrid SWA can achieve. At 1:11, a Hybrid SWA model would go 11 consecutive layers with only local window attention (no global context at all), which the paper shows causes severe degradation (Table 3: Hybrid SWA at 32k context on 80B MoE drops to 69.5 overall RULER score vs. 82.1 for Full-Attn). HySparse's sparse attention provides global context in those 11 layers through the oracle-selected blocks, avoiding this degradation.

**Final layer design.** In all configurations, the final layer uses full attention. The paper states this explicitly: "the final layer employs full attention to preserve global aggregation" (Section 1). This is important because the final layer's output feeds directly into the language modeling head. Having a final full attention layer ensures that the last transformation before prediction has access to the entire context, which may be crucial for tasks requiring global reasoning over the full sequence.

**Sparse attention parameters across all configurations:**

| Parameter | Value |
|---|---|
| Sparse attention token budget `$k$` | 1024 |
| Block size `$B$` | 64 |
| Number of selected blocks `$k/B$` | 16 |
| Sliding window size `$w$` | 128 |
| KV cache sharing scope | SA branch only (not SWA) |

**Training hyperparameters for 7B dense model.** The 7B models are trained in two stages:

- **Stage 1 (short-context pretraining):** 1 trillion tokens with sequence length 8,192. Optimizer: AdamW with `$\beta_1 = 0.9$`, `$\beta_2 = 0.95$`, `$\epsilon = 10^{-10}$`. Weight decay: 0.1. Gradient clipping: maximum norm 1.0. Precision: BF16. Learning rate schedule: WSD (warmup-stable-decay) with maximum learning rate `$8.3 \times 10^{-4}$`.

- **Stage 2 (long-context adaptation):** 200 billion tokens with sequence length 32,768 and learning rate `$3.0 \times 10^{-5}$`. The RoPE base frequency is adjusted to 640,000 at this stage (increased from the standard value to better support the longer context length; larger RoPE base frequencies allow the positional encoding to distinguish positions at longer ranges by stretching the rotary frequencies).

**Training hyperparameters for 80B MoE model.** The 80B MoE model is trained in a single stage:

- 500 billion tokens with sequence length 32,768. WSD schedule with maximum learning rate `$1 \times 10^{-3}$`. RoPE base frequency: 640,000.

The MoE model uses 8 activated experts out of 512 total experts, following a standard Mixture-of-Experts configuration. For the Full-Attn baseline in the MoE setting (but not the Hybrid SWA or HySparse models), gated attention (Qiu et al., 2025) is additionally employed "to stabilize training." This is an important detail — the Full-Attn MoE baseline uses a training stabilization technique that the sparse models do not require, suggesting that the sparse architecture may be inherently more stable to train, or that the gated attention in the sparse branches already provides sufficient stabilization.

**GQA configuration.** Both model sizes use Grouped-Query Attention:

- **7B Dense:** 32 query heads, 8 KV heads. This gives 4 query heads per KV group.
- **80B MoE:** 64 query heads, 4 KV heads. This gives 16 query heads per KV group.

Head dimension is 128 for both models. Hidden size is 4096 for the 7B model and 2048 for the 80B MoE model (the smaller hidden size in the MoE model is compensated by the MoE FFN capacity).

**How the architecture is implemented at the kernel level.** The paper describes the modified FlashAttention kernel (Algorithm 1) that outputs block-level scores. For the sparse attention layers, the paper implies the use of an efficient sparse attention kernel that gathers only the selected KV blocks rather than loading the full KV cache. The specifics of this kernel implementation are not detailed, but the block-aligned selection (block size matching FlashAttention tile size) suggests that the kernel can use the same tiled loading strategy as FlashAttention, simply skipping tiles that are not in the selected index set `$I$`.

**What happens during autoregressive generation.** During generation, the architecture operates incrementally:

1. When a new token is generated, its hidden state passes through the model layer by layer.
2. At each full attention layer, the new token's query attends to the full KV cache (which now includes the new token's own key and value, plus all previous tokens). The full attention layer computes new block-level attention scores `$S$` for the current query position (a single row, since only one new token is being processed).
3. The TopK operator selects blocks based on this single-row score, identifying which blocks are important for the current generation step from this layer's perspective.
4. The sparse attention layers that follow reuse these indices and the full attention layer's KV cache (which is continuously updated as new tokens are generated and their KV entries are appended). The SWA branch simply attends to the last 128 tokens, which now include the newly generated token.

This incremental operation means that the oracle indices are refreshed every time a full attention layer is encountered during generation. Since the full attention layers are spaced every N+1 layers (every 4 layers for 7B, every 12 layers for 80B MoE), the indices are updated at that frequency. Between full attention layers, the sparse layers use potentially slightly stale indices — but the frequency of refresh (every 4 or 12 layers) is high enough that cross-layer stability holds.

**Design choice: why interleave rather than use one full attention at the beginning.** An alternative design would be to compute full attention only at the first layer and use those indices for all subsequent sparse layers. The paper's interleaved design — repeating full attention layers throughout the depth — is motivated by the cross-layer stability observation: token importance is stable across *consecutive* layers, but not necessarily across the entire depth of the model. As representations transform through the layers, what constitutes an "important" token may shift. By interleaving full attention layers, HySparse periodically recomputes true attention scores, adapting the oracle indices as the representation space evolves through the network depth. The spacing of 4 or 12 layers between full attention layers represents an empirical judgment about how far the stability assumption can be stretched before the oracle indices become too stale.

**Summary of what makes the approach novel.** HySparse's technical approach is distinguished from prior work by three design choices working in concert:

1. **Full attention layers serve as oracles**, exposing exact block-level attention maxima through a modified FlashAttention kernel. This eliminates proxy-based token selection entirely — no auxiliary modules, no distillation losses, no heuristics.

2. **Cross-layer KV cache sharing is selective**: the full attention KV cache is shared only for global retrieval (the sparse attention branch), while local computation (the sliding window branch) maintains its own KV cache. This is validated by the ablation showing that sharing for both branches hurts performance.

3. **The hybrid ratio can be pushed aggressively** (1:11 in the 80B MoE model, meaning only 5 full attention layers out of 49) while maintaining or exceeding full attention performance, because the sparse layers receive oracle-quality global context rather than relying on crude heuristics like sliding windows alone.

## 4. Key Insights and Innovations

### Innovation 1: Reframing Full Attention from Cost Center to Oracle — Eliminating the Proxy Bottleneck Entirely

The field's default approach to sparse attention has been to treat full attention as the expensive thing to be replaced, and to design increasingly sophisticated *approximations* — proxies — that estimate token importance without computing it exactly. Whether training-free heuristics (Jiang et al., 2024; Xiao et al., 2023; Zhang et al., 2023) or learned gating modules trained via self-distillation (Gao et al., 2024; Liu et al., 2025a), the implicit assumption has been: full attention is too expensive, so we must find a cheaper substitute for its importance signal.

HySparse makes a genuinely different conceptual move. Instead of trying to *replace* the full attention signal with a cheaper approximation, it asks: **what if we keep a small number of full attention layers and treat them as oracles for the rest?** The full attention layer is not the problem to be eliminated — it is the *solution* to the proxy quality problem. Since full attention computes exact attention scores, it provides a perfect (for its representation space) token importance signal. The architectural challenge shifts from "how do we approximate attention scores cheaply?" to "how far can we stretch one layer's oracle signal across subsequent layers before it goes stale?"

This reframing has a subtle but profound implication: it converts the token selection problem from a **learning problem** (training a proxy to approximate full attention) into an **architectural design problem** (deciding spacing and interleaving of oracle layers). Trainable sparse attention methods like SeerAttention (Gao et al., 2024) and DSA (Liu et al., 2025a) must train auxiliary modules with additional loss terms, tune distillation weights, and accept that their selection quality is bounded by proxy fidelity. NSA (Yuan et al., 2025) integrates sparsity into pretraining but provides only indirect gradient signals to its selection module. HySparse sidesteps all of this: the selection signal is simply the actual attention scores from the nearest preceding full layer, extracted through a minimally modified FlashAttention kernel. There is nothing to train, distill, or tune for token selection — it comes for free with the full attention computation already being performed.

The significance of this reframing extends beyond performance gains. It suggests that the research effort invested in better selection proxies — better gating modules, better heuristics, better distillation procedures — may have been addressing the wrong bottleneck. If a small number of full attention layers can serve as adequate oracles for the rest of the model (as the 1:11 ratio in the 80B MoE model demonstrates), then the proxy quality problem is solved architecturally, not algorithmically. The limiting factor becomes cross-layer stability of token importance, not proxy fidelity. This redirects research attention toward understanding *how* and *why* attention patterns propagate across layers, rather than toward better approximation techniques.

The evidence for this reframing being more than just semantics comes from the Hybrid SWA comparison in Table 2 and Table 3. Hybrid SWA uses the same interleaving pattern (1:3 or 1:11 full-to-SWA ratio) but relies purely on sliding windows — the crudest possible proxy — in its non-full layers. At the 1:11 ratio in the 80B MoE model, Hybrid SWA degrades substantially (RULER 32k overall drops from 82.1 to 69.5), while HySparse with oracle-guided sparse attention not only recovers the degradation but surpasses Full-Attn (87.4 vs. 82.1). This demonstrates that oracle-quality token selection is what enables the aggressive hybrid ratio — not just the presence of full attention layers at intervals, but the *reuse* of their exact attention signal by subsequent layers.

This is a **fundamental reframing**, not an incremental improvement. The conceptual relationship between full attention and sparse attention is inverted: full attention is not the adversary to be minimized but the enabler to be strategically placed.

---

### Innovation 2: Selective KV Cache Sharing — Global Retrieval and Local Computation Require Different Representations

Cross-layer KV cache sharing as a memory optimization is not new. YOCO (Sun et al., 2024), CLA (Brandon et al., 2024), SwiftKV (Qiao et al., 2025), and others have demonstrated that sharing KV caches between layers can substantially reduce memory with minimal accuracy loss. The dominant assumption — implicit in how these methods are applied — has been that if KV sharing works for one type of attention, it should work for all attention in a layer. Share the KV cache, reduce memory uniformly.

The ablation study in Table 4 reveals something more subtle and intellectually significant: **KV cache sharing is beneficial specifically for global retrieval and harmful specifically for local computation.** When the SWA branch shares the full attention layer's KV cache (the "sharing for SA & SWA" condition), performance drops substantially across all benchmarks — MMLU falls from 58.4 to 52.8, GSM8K from 36.7 to 30.2, BBH from 53.9 to 47.2. Yet when the SWA branch maintains its own independent KV cache while the sparse attention branch shares (the final HySparse configuration), performance is strong. This is not a small difference — these are 5-6 point drops across major benchmarks, comparable to the gap between entirely different model architectures.

What this finding reveals is that **global and local attention operate on fundamentally different representational spaces.** The keys and values optimized for long-range content-based retrieval — distinguishing relevant information from 32,768 tokens of context — encode different features than the keys and values optimized for modeling short-range syntactic and semantic dependencies within a 128-token window. The full attention layer's KV cache, trained to do global attention, produces representations that are excellent for answering "which of these 512 blocks contains information relevant to my current query?" but poor for answering "what is the local discourse structure in the immediately preceding sentences?"

This finding has implications beyond HySparse. It suggests that prior work on cross-layer KV sharing may have succeeded because it applied sharing to models or layers where the attention computation was predominantly global in nature, or because the accuracy measurements were too coarse to detect the local coherence degradation. It also implies that future architectures wanting to maximize memory savings through KV sharing should apply it discriminatively based on the *function* of each attention pathway, not uniformly across all attention in a layer. A layer that does purely global retrieval (like a dedicated retrieval head or a full-attention-only layer) can share its KV cache aggressively; a layer or branch that handles local computation needs its own representation.

This is a **diagnostic insight** — a finding about *why* something works or fails that changes how we think about the underlying mechanism. It is not a method improvement (the method is simply "don't share for SWA") but a conceptual clarification of when and why a previously proposed technique (KV sharing) is applicable. The field previously knew that KV sharing *can* work; HySparse shows that it works along a specific functional axis (global vs. local) and fails when that axis is ignored. This is a more precise understanding than what existed before.

---

### Innovation 3: Pushing the Hybrid Ratio to Its Limit — Demonstrating That Sparse Oracles Enable Far More Aggressive Sparsity Than Heuristic Proxies

The practical goal of hybrid attention architectures — interleaving expensive full attention with cheaper alternatives — is to minimize the number of full attention layers while preserving model quality. The Hybrid SWA family (Agarwal et al., 2025; Gemma Team et al., 2025; Xiaomi Team et al., 2026) demonstrated that moderate ratios work: with enough full attention layers interspersed, performance can be maintained. But the question of **how far the ratio can be pushed** — what is the minimum viable number of full attention layers — was unexplored. The implicit assumption was that at some point, removing more full attention layers would cause catastrophic degradation because the non-full layers would go too long without global context.

HySparse's 80B MoE configuration with a **1:11 ratio** — only 5 full attention layers in a 49-layer model — pushes far beyond what existing hybrid architectures have attempted. And critically, HySparse does not merely *match* Full-Attn at this ratio; it **exceeds** it. Table 2 shows HySparse outperforming Full-Attn on MMLU (62.2 vs. 61.8), MMLU-Redux (66.2 vs. 65.6), DROP (56.5 vs. 56.7, essentially tied), GSM8K (54.1 vs. 53.8), MATH (30.8 vs. 28.6), HumanEval (38.4 vs. 35.4), MBPP (59.3 vs. 55.3), and Chinese benchmarks (65.0 vs. 64.6 on C-Eval, 67.0 vs. 66.7 on CMMLU). On long-context RULER at 32k (Table 3), HySparse achieves 87.4 overall vs. 82.1 for Full-Attn — a substantial 5.3 point improvement — while using nearly 10× less KV cache.

The significance of this finding is not "sparse attention can match full attention" — that has been shown before. The significance is **the specific mechanism by which it works at such extreme ratios.** Hybrid SWA with the same 1:11 ratio degrades substantially (RULER 32k: 69.5, DROP: 47.8, ARC-C: 63.9). This proves that the oracle-guided sparse attention is not merely a nice-to-have improvement over sliding windows — it is **essential** for making aggressive hybrid ratios viable. Sliding windows alone cannot sustain model quality when full attention layers are spaced 12 layers apart; oracle-guided sparse attention can, because each sparse layer receives high-quality global context rather than being restricted to a local window.

This finding also suggests an answer to a question the paper raises in Section 5: "Can We Ultimately Avoid Full Attention?" The answer from the experimental evidence appears to be **no, but we can reduce it dramatically.** Five full attention layers out of 49 is a 9.8× reduction. Could it be reduced further — to 3 layers, or 1? The paper does not test these extremes, but the fact that the 1:11 ratio *improves* over Full-Attn while 1:3 (in the 7B model) shows more modest gains suggests there may be a sweet spot where the ratio is aggressive enough to provide regularization benefits (preventing overfitting or encouraging more robust representations) without being so aggressive that global information is lost. Finding this sweet spot is now a well-posed empirical question, enabled by HySparse's demonstration that the ratio can be pushed much further than previously assumed.

This is an **empirical boundary-pushing finding** — it establishes a new Pareto frontier for the tradeoff between full attention layers and model quality. Prior to this work, the frontier was defined by Hybrid SWA, which could not sustain quality below some moderate ratio. HySparse shifts the frontier substantially inward, demonstrating that oracle-guided token selection changes the fundamental tradeoff rather than merely improving it incrementally.

### Innovation 4: A Unified Architecture That Solves Both the Computation and Memory Problems Simultaneously — Not Through a New Mechanism, but Through Architectural Integration of Known Techniques

The paper's title emphasizes "Oracle Token Selection *and* KV Cache Sharing" — two techniques that, individually, are not novel. Oracle token selection via cross-layer attention stability has been used in training-free inference optimizations (Deshmukh et al., 2025; Hao et al., 2025). Cross-layer KV cache sharing has been used as a standalone memory optimization (Sun et al., 2024; Brandon et al., 2024). What HySparse contributes is not either technique in isolation, but the **architectural integration** that makes them work together synergistically — and the insight that they *can* work together at all.

Prior sparse attention methods faced a structural tension: dynamic sparsity reduces computation but cannot reduce memory because the full KV cache must be retained. Cross-layer KV sharing reduces memory but does not reduce computation. These have been treated as separate problems with separate solutions. HySparse's insight is that **the same architectural feature — the preceding full attention layer — can serve both purposes simultaneously.** The full attention layer provides the oracle token selection (solving the computation problem by identifying which tokens sparse layers should attend to) *and* the shared KV cache (solving the memory problem by eliminating per-layer KV storage for the global retrieval pathway). The two benefits are not independent add-ons; they flow from a single design decision: having sparse layers reuse the full layer's outputs rather than computing their own.

This integration matters because it addresses the full practical bottleneck of long-context inference. Reducing computation without reducing memory means you can process tokens faster but cannot increase batch size — you're still limited by the KV cache footprint. Reducing memory without reducing computation means you can serve more sequences simultaneously but each sequence still costs the same per-token FLOPs. HySparse achieves both simultaneously because the sparse layers both do less computation (attending to 1024 tokens rather than 32,768) and store less KV cache (reusing the full layer's cache rather than storing their own for global retrieval). The nearly 10× KV cache reduction in the 80B MoE model is not a separate result from the performance gains — it is a direct consequence of the same architectural pattern that enables the oracle-guided selection.

The ablation study (Table 4, Figure 2) provides the evidence that this integration is non-trivial: simply combining oracle selection with uniform KV sharing (the "sharing for SA & SWA" condition) fails. Getting the integration right requires understanding that the SWA branch needs its own representation. This is the kind of detail that distinguishes "we combined two existing ideas" from "we discovered the conditions under which combining two existing ideas actually works."

This is a **systems-level integration insight** rather than a novel mechanism. The contribution is not a new algorithm but a demonstration that two previously-separate techniques can be unified in a single architecture to achieve something neither achieves alone: simultaneous computation and memory reduction with quality preservation. The significance is practical — it provides a blueprint for building transformers that are efficient in both FLOPs and memory, which is what production deployments actually need — but the intellectual contribution is in showing that the architectural integration is both possible and non-obvious (given the failed naive integration in the ablation).

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The paper evaluates on a broad suite covering general language understanding and reasoning (BBH, MMLU, MMLU-Redux, MMLU-Pro, DROP, ARC-Challenge, HellaSwag, WinoGrande, TriviaQA), mathematics reasoning (GSM8K, MATH), coding (HumanEval, MBPP), Chinese understanding (C-Eval, CMMLU), and long-context capabilities (RULER). All benchmarks use standard published evaluation protocols with the specified few-shot settings shown in Table 2. The training data for pretraining is not from these benchmarks — the 7B models train on 1T tokens (general corpus, not specified) plus 200B tokens of long-context adaptation, and the 80B MoE models train on 500B tokens, all with standard language modeling objectives.

- **Base model(s).** The paper trains two model scales from scratch: a 7B dense transformer (36 layers, 32 query heads, 8 KV heads, hidden size 4096) and an 80B-A3B Mixture-of-Experts model (49 layers, 64 query heads, 4 KV heads, hidden size 2048, 8 activated experts out of 512 total). Both use Grouped-Query Attention and are trained under three attention variants: Full-Attn (all layers standard full attention), Hybrid SWA (interleaved full and sliding window attention), and HySparse (the proposed architecture). The model scales are chosen to test the architecture at moderate (7B) and large (80B MoE) sizes, with the MoE setting additionally probing whether the approach works under sparsity-structured feed-forward computation.

- **Metrics.** For all standard benchmarks (MMLU, GSM8K, HumanEval, etc.), the metric is **accuracy** — the fraction of test instances where the model's generated answer matches the ground truth, computed under the standard evaluation protocol for each benchmark (exact match or equivalent). For long-context evaluation, the RULER benchmark reports per-subtask scores and an overall average across all subtasks. For the training curves in Figure 2, the paper additionally reports **validation perplexity** on the Pile dataset and per-benchmark accuracy at intermediate training checkpoints (measured every 200B tokens for the 7B model up to 1T tokens).

- **Baselines.** Two baselines are compared against HySparse across all settings. **Full-Attn**: all layers use standard full softmax attention with full KV cache — this represents the upper bound on model quality against which efficiency gains are measured. **Hybrid SWA**: a hybrid sliding window attention architecture that uses the same full-to-SWA layer ratio as HySparse (1:3 for 7B, 1:11 for 80B MoE), where non-full layers attend only to a local window of 128 tokens with their own per-layer KV cache. This is the direct architectural baseline that follows the pattern of gpt-oss (Agarwal et al., 2025), Gemma3 (Gemma Team et al., 2025), and MiMo-V2-Flash (Xiaomi Team et al., 2026). No comparison is made against other trainable sparse attention methods like SeerAttention (Gao et al., 2024) or NSA (Yuan et al., 2025), since HySparse is a full pretraining architecture rather than an inference optimization or module that could be dropped in.

- **Generation budget / compute accounting.** The paper does not use a FLOPs-matched or latency-matched comparison framework for its main results. Instead, models are compared under identical training budgets (same number of training tokens) and identical architectural parameters (same hidden size, number of layers, etc.), with the efficiency claims based on **structural properties** of the architecture rather than runtime measurements. Specifically: HySparse is claimed to reduce computation because sparse attention layers attend to 1024 tokens rather than the full sequence (a ~32× reduction in attention FLOPs at 32k context), and to reduce memory because only full attention layers (5 out of 49 in the 80B MoE model) plus the small SWA caches (128 tokens per sparse layer) contribute to the KV cache. No wall-clock timing, GPU memory profiling, or throughput measurements are reported. The "nearly 10× KV cache reduction" claim is a structural count: 49 layers of full KV cache vs. 5 layers of full KV cache plus 44 layers of 128-token SWA caches.

- **Cross-validation / statistical protocol.** The paper does not report confidence intervals, standard deviations, or statistical significance tests for any benchmark results. All reported numbers are point estimates from single evaluation runs on the standard test sets. For the long-context adaptation experiments, the same base model checkpoints are extended via continued training on 200B tokens (7B) or directly trained with 32k context (80B MoE), with no cross-validation over random seeds or data orders. The ablation experiments in Section 4.4 are conducted on the 7B dense model and report accuracy at the final training checkpoint (1T tokens for Table 4) and at intermediate checkpoints (Figure 2), but without error bars. The training curves in Figure 2 provide some evidence of training stability and convergence, showing that the relative ordering of methods is consistent across most of training, but they do not constitute a formal statistical protocol.

### Main Quantitative Results

#### Standard Benchmark Performance: 7B Dense and 80B MoE Models

The central quantitative result appears in **Table 2**, which compares HySparse against Full-Attn and Hybrid SWA across 15 benchmarks for both the 7B dense (1:3 hybrid ratio) and 80B MoE (1:11 hybrid ratio) settings. The headline finding is that HySparse achieves **best or near-best performance across nearly all benchmarks at both scales**, despite using substantially fewer full attention layers and less KV cache memory.

For the **7B dense model** (trained on 1T tokens), HySparse surpasses Full-Attn on a broad set of knowledge and reasoning benchmarks. On MMLU, HySparse achieves 58.8 vs. 56.9 for Full-Attn and 57.5 for Hybrid SWA. On MMLU-Redux, the pattern holds: 61.6 (HySparse) vs. 59.6 (Full-Attn) vs. 60.8 (Hybrid SWA). On MMLU-Pro, HySparse reaches 29.0 vs. 26.8 (Full-Attn) and 26.5 (Hybrid SWA). On the reading comprehension benchmark DROP, HySparse achieves 52.4, approaching Full-Attn's 53.1 but substantially outperforming Hybrid SWA's 43.8 — a 8.6-point gap that illustrates how sliding windows alone lose critical long-range dependencies for multi-step reasoning over paragraphs. On commonsense reasoning, HySparse equals or edges ahead: ARC-Challenge 75.0 vs. 74.9 (Hybrid SWA) and 70.2 (Full-Attn); HellaSwag 78.1 vs. 77.8 and 77.5; WinoGrande 74.3 vs. 74.9 and 73.7. On TriviaQA, HySparse reaches 51.1 vs. 50.1 and 50.0.

On mathematical reasoning benchmarks (GSM8K, MATH), HySparse shows consistent improvement. GSM8K: 37.9 (HySparse) vs. 35.6 (Hybrid SWA) and 33.3 (Full-Attn). MATH: 10.1 vs. 9.2 for both baselines. These are modest absolute numbers (MATH at 10.1% reflects the difficulty of the MATH dataset for a 7B model), but the direction is consistent.

On code benchmarks, the picture is more mixed. HumanEval: 23.5 (HySparse) vs. 25.0 (Full-Attn) and 22.0 (Hybrid SWA) — HySparse slightly underperforms Full-Attn here. MBPP: 51.6 vs. 51.0 and 52.8 — all three methods are close. On Chinese benchmarks, HySparse shows clear gains on both C-Eval (52.2 vs. 50.6 for Full-Attn) and CMMLU (54.5 vs. 52.5).

A notable pattern: **Hybrid SWA often outperforms Full-Attn** in the 7B setting (e.g., BBH 54.0 vs. 52.2, MMLU 57.5 vs. 56.9, GSM8K 35.6 vs. 33.3). This suggests that at a moderate 1:3 hybrid ratio, even the simple sliding window approach can provide a form of beneficial regularization — limiting attention to a local window may prevent overfitting to spurious long-range correlations during training. HySparse builds on this effect while adding oracle-guided global retrieval, yielding further gains.

For the **80B MoE model** (trained on 500B tokens with a 1:11 hybrid ratio), the pattern is more dramatic. HySparse outperforms Full-Attn on MMLU (62.2 vs. 61.8), MMLU-Redux (66.2 vs. 65.6), and approaches it closely on MMLU-Pro (32.6 vs. 33.8). On DROP, HySparse essentially matches Full-Attn (56.5 vs. 56.7). On GSM8K, HySparse reaches 54.1 vs. 53.8 (Full-Attn) and 45.3 (Hybrid SWA) — the gap between HySparse and Hybrid SWA is 8.8 points, showing that at the aggressive 1:11 ratio, sliding windows alone are insufficient. On MATH, HySparse achieves 30.8 vs. 28.6 (Full-Attn) and 25.8 (Hybrid SWA) — a 5.0-point gap over Hybrid SWA. On HumanEval, HySparse reaches 38.4 vs. 35.4 (Full-Attn), and on MBPP, 59.3 vs. 55.3 (Full-Attn) — the largest code benchmark improvements.

Crucially, **Hybrid SWA degrades substantially at the 1:11 ratio** on several benchmarks where it previously performed well at 1:3. BBH drops from 56.1 (Full-Attn) to 48.2 (Hybrid SWA) — a 7.9-point gap. MMLU drops from 61.8 to 54.9. DROP drops from 56.7 to 47.8. ARC-Challenge drops from 78.4 to 63.9. These degradations confirm that when full attention layers become too sparse (only 5 out of 49), relying solely on 128-token sliding windows between them is insufficient — the model loses access to critical long-range information. HySparse recovers these losses and exceeds Full-Attn in most cases, demonstrating that oracle-guided sparse attention provides the missing global context.

A quantitative nuance: HySparse does not universally outperform Full-Attn in the 80B MoE setting. On MMLU-Pro, HySparse scores 32.6 vs. 33.8 for Full-Attn (a 1.2-point gap). On DROP, 56.5 vs. 56.7 (essentially tied). On WinoGrande, 72.1 vs. 71.2 (HySparse slightly ahead). The pattern is that HySparse is generally on par or better than Full-Attn, with a few benchmarks where it slightly trails.

#### Long-Context Evaluation: RULER Benchmark

**Table 3** reports RULER performance for both the 7B dense model (at 16k and 32k context lengths) and the 80B MoE model (at 16k and 32k). RULER consists of 13 subtasks spanning different long-context capabilities: single-keys (S1-S3), multi-keys (MK1-MK3), multi-query (MQ), multi-value (MV), variable tracking (VT), common word extraction (CWE), and frequent word extraction (FWE). The "Total" column is the average across all subtasks.

For the **7B dense model at 16k context**, HySparse achieves the highest total score of 94.1, compared to 93.0 for Full-Attn and 91.6 for Hybrid SWA. The gains are concentrated on the harder subtasks. On CWE (common word extraction, requiring retrieval of words meeting frequency criteria across the full context), HySparse scores 60.8 vs. 37.1 (Full-Attn) and 23.7 (Hybrid SWA) — a massive 23.7-point improvement over Full-Attn and 37.1 points over Hybrid SWA. This is the single largest performance gap in the table and suggests that HySparse's oracle-guided sparse attention is particularly effective at tasks requiring targeted retrieval of content from arbitrary positions, rather than tasks solvable by local patterns. On the simpler single-key retrieval tasks (S1-S3), all methods achieve near-perfect scores (99.8-100.0), indicating that even Hybrid SWA can handle tasks where the relevant information is just a single key somewhere in the context. But as the retrieval demands become more complex (multiple keys, values, tracking variables over long spans), the gaps widen.

For the **7B dense model at 32k context**, HySparse achieves 89.3 total vs. 88.2 (Full-Attn) and 84.2 (Hybrid SWA). The CWE advantage remains large: 38.8 (HySparse) vs. 16.6 (Full-Attn) and 10.4 (Hybrid SWA) — an 22.2-point improvement over Full-Attn. On multi-key retrieval MK2, HySparse scores 99.6 vs. 99.4 (Full-Attn, near tie). On MK3, HySparse scores 76.2 vs. 75.8 (Full-Attn, near tie) while Hybrid SWA drops to 53.4. These results show that at 32k, the increasing context length begins to stress even Full-Attn (MK3 drops from 96.4 at 16k to 75.8 at 32k), but HySparse tracks Full-Attn closely while Hybrid SWA degrades severely.

For the **80B MoE model**, the differences between architectures are stark. At **16k context**, Full-Attn achieves 93.6 total. Hybrid SWA drops dramatically to 72.7 — a 20.9-point degradation that confirms the 1:11 hybrid ratio is too aggressive for sliding windows alone. HySparse achieves 90.6, within 3 points of Full-Attn and 17.9 points above Hybrid SWA. On the challenging subtasks: MK3 (HySparse 99.6 vs. Full-Attn 93.0 vs. Hybrid SWA 69.4), MV (HySparse 91.3 vs. Full-Attn 94.9 vs. Hybrid SWA 57.8), and CWE (HySparse 40.2 vs. Full-Attn 74.5 vs. Hybrid SWA 13.3). Interestingly, on CWE at 16k, Full-Attn substantially outperforms HySparse (74.5 vs. 40.2) — this is one of the few subtasks where the oracle selection may miss content that full attention captures.

At **32k context** for the 80B MoE model, the pattern shifts: HySparse achieves 87.4 total vs. 82.1 for Full-Attn and 69.5 for Hybrid SWA — HySparse **outperforms Full-Attn by 5.3 points** while Hybrid SWA trails by 12.6 points behind Full-Attn. This crossover — HySparse being behind Full-Attn at 16k (90.6 vs. 93.6) but ahead at 32k (87.4 vs. 82.1) — is one of the paper's most striking results. It suggests that as context length increases, the sparse attention pattern in HySparse may actually help the model focus on relevant information rather than being distracted by the full context. On MK3, HySparse achieves 98.4 vs. 77.0 for Full-Attn — a 21.4-point gap. On VT, 89.6 vs. 74.5. On FWE, 82.1 vs. 66.7. The only subtask where Full-Attn maintains a clear advantage is CWE (20.8 for HySparse vs. 40.7 for Full-Attn), though both degrade from their 16k scores.

A critical observation from Table 3: the **Hybrid SWA 80B MoE model at 32k** achieves only 69.5 overall, with particularly low scores on CWE (8.4), FWE (54.3), VT (73.1), and the multi-key tasks (MK2: 90.2, MK3: 61.0). These near-random scores on tasks requiring global retrieval confirm that with only 5 full attention layers out of 49, a model relying solely on 128-token windows between them cannot reliably find information more than a few hundred tokens away. HySparse's sparse attention branch — selecting 1024 tokens guided by oracle indices — bridges this gap.

#### Training Dynamics: Accuracy vs. Training Tokens

**Figure 2** shows validation perplexity on the Pile dataset and per-benchmark accuracy (DROP, GSM8K, MMLU, MMLU-Pro, BBH) as a function of training tokens from 0 to 1T for the 7B dense model, comparing all six configurations from the ablation study plus Full-Attn and Hybrid SWA baselines.

The perplexity curves (top-left) show the expected ranking: Full-Attn achieves the lowest perplexity throughout training, followed closely by the HySparse variants. The "HySparse w/o SWA w/o sharing" configuration (no intra-layer SWA, no KV cache sharing) consistently shows the highest perplexity, consistent with its poor downstream performance in Table 4. The ordering between the other HySparse variants is stable across training, suggesting that the architectural differences manifest early and do not require special training recipes or schedules to materialize.

On the downstream task curves (DROP, GSM8K, MMLU, MMLU-Pro, BBH), the patterns are consistent with Table 4 but shown dynamically. For GSM8K, the "HySparse w/ SWA only sharing SA" configuration tracks closest to or above Full-Attn throughout the latter half of training, while the variants with suboptimal sharing (sharing for both SA & SWA) or no SWA branch consistently underperform. For MMLU, the performance ordering stabilizes after approximately 400B tokens, with the final HySparse configuration overtaking both baselines. On BBH, all HySparse variants start similarly but diverge after ~600B tokens, with "sharing only for SA" pulling ahead.

An interesting negative result visible in the training curves: the "HySparse w/ SWA sharing SA & SWA" configuration (sharing KV for both branches) shows decent early performance that degrades relative to other configurations as training progresses, particularly on GSM8K and BBH. This suggests that the representational conflict from forcing the SWA branch to use full-attention KV caches becomes more detrimental as the model's representations become more specialized later in training.

### Ablation Studies and Robustness Checks

All ablation studies are conducted on the 7B dense model and reported in **Table 4** and **Figure 2**.

**Intra-layer SWA branch (necessity of the sliding window pathway):** Removing the SWA branch entirely while using oracle token selection and no KV cache sharing ("HySparse w/o intra-layer-SWA") causes substantial accuracy drops: DROP falls from 52.2 to 46.4 (-5.8), GSM8K from 37.7 to 29.7 (-8.0), MMLU-Pro from 26.5 to 25.0 (-1.5), and BBH from 52.4 to 48.2 (-4.2). MMLU is essentially flat (56.1 vs. 57.1). These results demonstrate that even with high-quality oracle token selection from full attention, the sparse global retrieval pathway alone is insufficient — local coherence modeling through the SWA branch provides complementary capabilities that the global sparse attention cannot replicate. The paper hypothesizes that the SWA branch helps stabilize early training and captures short-range dependencies that are not reliably covered by oracle-selected blocks.

**KV cache sharing configuration (global vs. local representation conflict):** Comparing three sharing strategies — all with the intra-layer SWA branch present and oracle token selection enabled — reveals a striking sensitivity:

- **Sharing for both SA & SWA**: Both branches reuse the full attention layer's KV cache. Results: DROP 47.9, GSM8K 30.2, MMLU 52.8, MMLU-Pro 23.2, BBH 47.2.

- **Sharing only for SA**: Only the sparse attention branch shares; SWA maintains independent KV. Results: DROP 51.9 (+4.0), GSM8K 36.7 (+6.5), MMLU 58.4 (+5.6), MMLU-Pro 29.0 (+5.8), BBH 53.9 (+6.7).

The performance gap between these two configurations is large and consistent — 4 to 6.7 points across all five benchmarks — confirming that forcing the sliding window branch to use representations optimized for global retrieval is harmful. This is the paper's key ablative finding: **cross-layer KV sharing is beneficial for global sparse attention but detrimental for local sliding window attention.** The SWA branch requires its own KV cache with representations specialized for short-range coherence.

**Oracle token selection vs. no sparse attention (comparison with Hybrid SWA):** While not a separate ablation row, comparing "HySparse (w/ intra-layer SWA)" against Hybrid SWA in Table 4 isolates the effect of adding oracle-guided sparse attention to a hybrid architecture. HySparse improves over Hybrid SWA on DROP (52.2 vs. 43.9, +8.3), GSM8K (37.7 vs. 35.7, +2.0), MMLU-Pro (26.5 vs. 26.6, essentially tied), and BBH (52.4 vs. 54.3, -1.9 — Hybrid SWA slightly ahead). On MMLU, Hybrid SWA slightly leads (57.6 vs. 56.1 for this HySparse variant without KV sharing). This suggests that the benefit of oracle-guided sparse attention interacts with KV sharing — the full HySparse configuration with selective KV sharing (which achieves MMLU 58.4) outperforms both.

**Training trajectory robustness (Figure 2):** The training curves provide a form of robustness check by showing that the relative ordering of configurations is stable throughout training, not just at the final checkpoint. The "HySparse w/ SWA only sharing SA" configuration consistently tracks among the top methods from ~400B tokens onward across all five downstream benchmarks. There is no crossing of curves late in training that would suggest the chosen configuration only looks good at the final checkpoint due to noise. The convergence behavior appears smooth, with no sudden divergence or instability in any configuration.

**Negative result on no-SWA configuration:** The "HySparse w/o SWA w/o sharing" row in Table 4 and its trajectory in Figure 2 represent a negative result: simply using oracle token selection without any local attention pathway and without KV sharing performs poorly. On BBH, this configuration achieves only 48.2 (vs. 53.9 for the full HySparse and 54.3 for Hybrid SWA). On GSM8K, it scores 29.7 (vs. 37.7 for full HySparse and 35.7 for Hybrid SWA). This demonstrates that oracle tokens alone are not a sufficient replacement for local context — the model needs both global retrieval and local coherence.

### Critical Assessment

**Claim 1: HySparse consistently outperforms both Full-Attn and Hybrid SWA baselines across tasks and model scales.** The evidence in Table 2 and Table 3 largely supports this claim, but with important qualifications about *consistency*. In the 7B dense model, HySparse outperforms Full-Attn on 11 of 15 benchmarks in Table 2 (all except DROP, WinoGrande, HumanEval, and MBPP where it is close). In the 80B MoE model, HySparse outperforms Full-Attn on 10 of 15 benchmarks (with MMLU-Pro, DROP, and ARC-Challenge slightly below). The claim of "consistently outperforms" thus holds for the majority of benchmarks but not universally. On long-context RULER, HySparse outperforms Full-Attn at 32k for both model sizes (7B: 89.3 vs. 88.2; 80B: 87.4 vs. 82.1) but at 16k for the 80B MoE, Full-Attn still leads (93.6 vs. 90.6). So the "consistent" outperformance is context-length-dependent: at shorter contexts, Full-Attn can still be better; at longer contexts, HySparse's advantage grows.

**Claim 2: HySparse achieves nearly 10× KV cache reduction while delivering substantial performance gains.** The KV cache reduction claim is based on a structural count: 5 full attention layers vs. 49 total layers in the 80B MoE model, giving approximately 9.8× reduction in the number of layers storing full KV caches. This is a fair architectural comparison. However, the claim needs two qualifications. First, the 44 sparse layers each maintain a 128-token SWA KV cache, so the total KV cache is not exactly 1/10th of full attention — it is `(5 × n + 44 × 128)` vs. `(49 × n)` where `n` is the sequence length. At 32k context, this is `(5 × 32768 + 44 × 128) = 163840 + 5632 = 169472` entries per KV head vs. `49 × 32768 = 1605632` entries — approximately 9.5× reduction, consistent with "nearly 10×." Second, the paper does not report actual GPU memory measurements or throughput numbers, so the practical memory savings — which depend on memory allocator overhead, padding, and whether the sparse KV caches can be stored compactly — are not empirically validated.

**Claim 3: Oracle token selection from full attention eliminates the proxy-based selection bottleneck.** This is a conceptual claim that the experiments support indirectly but do not directly test. There is no head-to-head comparison against a proxy-based method (like training a SeerAttention-style gating module in the same architecture). The evidence that oracle selection matters comes from comparing HySparse against Hybrid SWA — where the proxy is "attending to local window tokens only" — and showing substantial improvements (Table 2, Table 3). But this comparison conflates two changes: HySparse adds global sparse attention *and* uses oracle indices. Whether a non-oracle global sparse attention (e.g., using a learned gating module) would perform similarly is not tested. The paper's claim that oracle selection "eliminates" the proxy bottleneck is logically sound given the architecture, but the empirical demonstration is limited to showing that the architecture works, not that proxy-based alternatives would fail in the same setting.

**Claim 4: The SWA branch needs its own KV cache — sharing the full attention KV cache is harmful.** This is the strongest and cleanest empirical result, directly supported by the ablation in Table 4. The 4-6.7 point gaps across five benchmarks, with consistent direction, make a convincing case. However, the finding is demonstrated only for the 7B model with a 1:3 ratio. Whether the same holds at the 1:11 ratio in the 80B MoE model is not tested via ablation — though the strong performance of the final 80B HySparse configuration (which uses selective sharing) is consistent with the finding.

**Genuine weaknesses in the experimental design:**

- **No runtime or memory measurements.** All efficiency claims are structural (counting layers and KV cache entries) rather than empirical. The paper does not report inference latency, throughput, peak GPU memory usage, or batch size scaling. For an architecture motivated by efficiency, this is a significant omission. The modified FlashAttention kernel for block score extraction may have overhead that is "negligible" in theory but non-trivial in practice, especially for shorter sequences where the `O(t^2/B)` score storage cost competes with the compute cost. Similarly, the sparse attention kernel that gathers only selected KV blocks may have irregular memory access patterns that reduce hardware utilization compared to dense FlashAttention, potentially making the theoretical FLOP reduction less impactful in wall-clock time.

- **Single training run per configuration.** The paper reports point estimates from single training runs with no error bars, confidence intervals, or multiple seeds. Given the known variability in LLM training (different random seeds can produce models with accuracy differing by 1-3 percentage points on some benchmarks), the reported differences — especially the smaller ones like MMLU 62.2 vs. 61.8 — should be interpreted cautiously. The training curves in Figure 2 partially mitigate this concern by showing consistent relative ordering throughout training, but they do not address seed-to-seed variability.

- **No comparison against other trainable sparse attention methods.** HySparse is compared only against full attention and Hybrid SWA. Comparisons against methods like SeerAttention (Gao et al., 2024), DSA (Liu et al., 2025a), or NSA (Yuan et al., 2025) — which also integrate sparsity into training — are absent. While these methods target somewhat different settings (some are inference optimizations rather than pretraining architectures), a controlled comparison at equivalent model size and training budget would clarify whether HySparse's specific mechanism (oracle selection + KV sharing) outperforms learned proxy approaches.

- **Training data not specified.** The paper states that models are trained on "1T tokens" or "500B tokens" but does not describe the training data composition, quality, or domain mix. If the training data differs between the Full-Attn, Hybrid SWA, and HySparse runs, the benchmark comparisons could reflect data differences rather than architectural ones. The paper implies identical training data is used for all variants, but this is not explicitly stated.

- **No ablation on key hyperparameters.** Several architectural choices lack ablations: the sparse attention block size (64), the number of selected tokens (1024), the sliding window size (128), the full-to-sparse layer ratio (only two values tested: 1:3 and 1:11), and the number of query groups sharing sparse indices. Sensitivity to these choices is unknown. For example, would 2048 selected tokens improve CWE performance (where HySparse trails Full-Attn) at the cost of higher compute? Would a window size of 256 affect the SWA sharing ablation? Without such ablations, the reported configuration may be locally optimal but not robustly justified.

- **The hybrid ratio confound in model comparisons.** The 7B model uses a 1:3 ratio and the 80B MoE model uses 1:11. This means that when comparing across model scales, both the model architecture (dense vs. MoE, hidden size, number of layers) and the hybrid ratio change simultaneously. Whether a 7B model at 1:11 would perform well, or an 80B MoE at 1:3 would show even larger gains, is not tested. This makes it difficult to disentangle the effect of model scale from the effect of hybrid ratio.

- **RULER evaluation sensitivity.** The RULER benchmark is sensitive to evaluation protocol details (prompt format, exact string matching criteria, model temperature). The paper does not describe these details, making reproduction difficult.

**Missing experiments that would strengthen the paper:**

- **Comparison with a learned proxy baseline.** Training a variant of HySparse where the sparse layers use a learned gating module (e.g., via self-distillation from the full attention layer) instead of oracle indices would directly test the claim that oracle selection is superior to proxies. If oracle selection performs similarly to a well-trained proxy, the "elimination of proxy bottleneck" claim would be weakened.

- **Ablation on number of selected tokens and block size.** Sweeping `k` (sparse attention token budget) over a range (e.g., 512, 1024, 2048, 4096) and measuring both accuracy and inference speed would characterize the computation-quality Pareto frontier that HySparse enables.

- **Ablation on full-to-sparse ratio.** Testing ratios between 1:3 and 1:11 (e.g., 1:5, 1:7, 1:9) would reveal whether the gains at 1:11 are near the limit or whether even more aggressive ratios (1:15, 1:23) remain viable. This would more precisely characterize "how far the ratio can be pushed."

- **Inference benchmarking.** Measuring prefill latency, decode latency per token, peak memory usage, and maximum batch size compared to Full-Attn and Hybrid SWA baselines would ground the structural efficiency claims in practical metrics.

- **Multi-seed training runs.** Training 2-3 seeds for at least one model configuration would provide the variance estimates needed to assess whether the reported differences are statistically reliable.

## 6. Limitations and Trade-offs

### Limitation 1: Efficiency Claims Are Structural, Not Empirically Measured

The paper's headline efficiency claims — "nearly 10× KV cache reduction" and reduced attention computation — are based on architectural counting rather than measured runtime or memory performance. The KV cache reduction is computed as a structural ratio: 5 full-attention layers storing full KV caches versus 49, with 44 sparse layers adding only 128-token SWA caches. The computation reduction is based on sparse layers attending to 1024 tokens rather than the full sequence, giving a theoretical ~32× reduction in attention FLOPs at 32k context. At no point does the paper report actual GPU memory consumption, inference latency (prefill or decode), throughput (tokens per second), or maximum batch size under a fixed memory budget, for any of the three architectures compared.

**The consequence** is that the paper's central value proposition — that HySparse is "efficient" — relies on idealized arithmetic that may not translate to wall-clock gains. Several factors could erode the theoretical advantages: (1) the modified FlashAttention kernel that extracts block-level attention scores introduces additional memory traffic and computation for the score matrix `S`, which has dimensions `t × ⌈t/B⌉` — at 32k context with block size 64, this is a `32768 × 512` float16 tensor (~33 MB per full attention layer per head group, non-trivial bandwidth), (2) the sparse attention kernel that gathers only selected KV blocks likely has irregular memory access patterns (gathering 16 non-contiguous blocks of 64 tokens each from the full KV cache rather than streaming through contiguous tiles), potentially reducing hardware utilization compared to standard FlashAttention's regular tiled access pattern, and (3) the cross-layer KV cache sharing means sparse layers must read from the preceding full layer's KV cache, which may reside in different GPU memory regions, adding pointer-chasing overhead. Prior work on sparse attention has frequently found that theoretical FLOP reductions of 10-100× translate to much more modest wall-clock speedups (2-5×) due to memory access and kernel launch overheads. Without profiling data, a practitioner cannot assess whether HySparse's structural efficiency translates into meaningful deployment benefits.

**Evidence in the paper:** The paper reports no wall-clock timing, no GPU memory profiling, and no throughput measurements for any configuration. The efficiency claims are stated in architectural terms throughout: "reducing KV cache storage by nearly 10×" (Section 1), "sparse attention layers reuse the KV cache... thereby reducing both computation and memory" (Abstract). The ablation study (Table 4) measures only accuracy, not efficiency. Figure 2 reports perplexity and accuracy over training tokens, not training time or memory.

**Mitigation status:** The paper does not acknowledge this gap as a limitation. Section 4.1 describes the architectural configurations, and the efficiency claims are presented as direct consequences of the structural design rather than hypotheses requiring empirical validation. Section 5 mentions future work on "efficient KV cache offloading" but does not address the absence of runtime measurements for the current architecture.

---

### Limitation 2: The Oracle Assumption Depends on Cross-Layer Token Importance Stability That Is Empirically Observed but Not Characterized

HySparse's core mechanism — sparse layers reusing token importance indices from a preceding full attention layer — rests on the assumption that token saliency is stable across consecutive transformer layers. The paper cites concurrent work observing this phenomenon (Section 2.3: Deshmukh et al., 2025; Hao et al., 2025; Yang et al., 2024a, 2025a) but does not itself measure or characterize the degree of stability for its specific models and training setup. The stability is presented as a given — "token saliency is stable across consecutive layers" — without quantifying how stable, under what conditions it degrades, or how far apart two layers can be before the oracle indices become unreliable.

**The consequence** is that the paper provides no guidance on the critical architectural hyperparameter: the full-to-sparse layer ratio. The paper tests only two ratios (1:3 for 7B, 1:11 for 80B MoE) and finds both work, but does not characterize the maximum viable spacing. At a 1:11 ratio, the 11th sparse layer after a full attention layer is using indices that are 11 layers stale. Could a 1:23 ratio work? 1:47? The answer depends entirely on the rate at which token importance patterns evolve across layers, which the paper does not measure. A practitioner wanting to deploy HySparse at a different model scale or on a different task distribution has no empirical basis for choosing the hybrid ratio — they would need to replicate the full training pipeline at multiple ratios to find the sweet spot. Furthermore, the stability property may depend on model architecture (dense vs. MoE, pre-norm vs. post-norm, training data distribution), meaning the 1:11 ratio found viable for an 80B MoE model may not transfer to other architectures.

Additionally, the paper's difficulty estimator analogy from the oracle-vs-predicted comparison (Section 3.2) actually reveals a subtle circularity: the full attention layer provides "oracle" indices, but these indices reflect that layer's representational priorities, which may differ from what the 11th subsequent sparse layer needs. The sparse layers use the full layer's KV cache (whose representations are also from that earlier layer), which partially mitigates this — keys and queries are in the same representational space — but the query representations in the sparse layer have been transformed by 11 layers of processing, and what constitutes a "relevant" token may have shifted.

**Evidence in the paper:** The paper does not measure cross-layer token importance stability for its models. The evidence is indirect: the architecture works (Tables 2, 3), which validates that stability is sufficient at the tested ratios, but provides no characterization of the stability function. The Hybrid SWA degradation at 1:11 versus HySparse's success at the same ratio (Table 3: 80B MoE at 32k, HySparse 87.4 vs. Hybrid SWA 69.5) demonstrates that oracle indices remain informative 11 layers later, but does not tell us whether they would remain informative 15 or 20 layers later. The ablation removing the SWA branch (Table 4) shows that oracle indices alone are insufficient — some important tokens are missed — but this measures the *limitation* of oracle selection, not its degradation rate with layer distance.

**Mitigation status:** The paper does not acknowledge this as a limitation or characterize the stability property. Section 2.3 cites prior work observing stability but does not measure it in the HySparse models. Section 5 asks "Can We Ultimately Avoid Full Attention?" but frames the question around the ratio of expensive to cheap computation rather than the underlying stability assumption. The paper does not suggest measuring or predicting the stability decay rate as future work.

---

### Limitation 3: No Comparison Against Learned Proxy Sparse Attention Methods — The "Oracle" Claim Is Untested Against the Alternative It Purports to Improve Upon

The paper's central conceptual claim is that oracle token selection from full attention layers eliminates the "proxy-based bottleneck" that limits other trainable sparse attention methods. Section 1 argues that prior methods "typically rely on additional proxies to predict token importance, introducing extra complexity and potentially suboptimal performance," and that "HySparse uses the full attention layer as a precise oracle to identify important tokens." This framing positions oracle selection as superior to learned proxies like self-distilled gating modules (SeerAttention; Gao et al., 2024) or end-to-end trained selection mechanisms (NSA; Yuan et al., 2025). However, the paper never empirically compares HySparse against any learned proxy method. The only comparison is against Hybrid SWA, where the "proxy" is attending to the last 128 tokens — the crudest possible heuristic. Beating this baseline does not demonstrate that oracle selection outperforms a well-trained learned proxy; it demonstrates that *any* global sparse attention is better than no global attention at all in non-full layers.

**The consequence** is that the paper's core narrative — oracle > proxy — is asserted rather than demonstrated. A learned proxy approach (e.g., training a lightweight gating module per sparse layer that predicts token importance using self-distillation from the nearest full attention layer) might achieve comparable or even better performance than reusing stale full-attention indices. A learned proxy could: (1) adapt per-layer rather than using identical indices across all sparse layers in a block, (2) learn to compensate for the representational drift between the full attention layer and later sparse layers, and (3) potentially select more tokens from the full KV cache by learning which patterns the oracle indices tend to miss (the tokens the SWA branch ends up covering). Without this comparison, a practitioner choosing between HySparse's oracle approach and a learned proxy approach has no evidence on which to base their decision. The HySparse design may be simpler (no auxiliary loss, no additional module), but whether that simplicity comes at a quality cost relative to learned proxies is unknown.

**Evidence in the paper:** There is no experiment comparing HySparse against a configuration where sparse layers use a learned gating module instead of oracle indices. The baselines are Full-Attn (all layers full attention) and Hybrid SWA (sparse layers have sliding window only, no global sparse attention at all). The paper discusses trainable sparse attention methods in Section 2.1 (SeerAttention, DSA, NSA, MoBA) and Section 5 (acknowledging these methods exist) but does not implement or compare against any of them.

**Mitigation status:** The paper does not acknowledge this as a missing comparison. Section 5 mentions that "sparse attention methods such as SeerAttention and DSA typically rely on gating or indexing mechanisms that still operate in `O(n^2)`, albeit in a compressed form," but this is a discussion of prior work, not a comparative experiment. The paper's positioning implies that oracle selection is inherently superior, but this claim is not tested empirically.

---

### Limitation 4: Single Training Run per Configuration with No Variance Estimates — Small Reported Differences May Be Noise

All results in Tables 2, 3, and 4, and all curves in Figure 2, are point estimates from single training runs. The paper reports no standard deviations, confidence intervals, or multi-seed replication for any benchmark or model configuration. This matters because LLM training is known to exhibit non-trivial variance across random seeds, data orders, and hardware nondeterminism — differences of 1-3 percentage points on standard benchmarks are not uncommon between identically-configured training runs with different random seeds. Many of the paper's reported improvements over Full-Attn fall within this range.

**The consequence** is that the paper's claims of "consistent" outperformance over Full-Attn are not statistically grounded. Examining Table 2 for the 7B dense model: HySparse outperforms Full-Attn on MMLU by 1.9 points (58.8 vs. 56.9), on MMLU-Redux by 2.0 points (61.6 vs. 59.6), on GSM8K by 4.6 points (37.9 vs. 33.3), on MATH by 0.9 points (10.1 vs. 9.2), and on C-Eval by 1.6 points (52.2 vs. 50.6). Several of these gaps (MATH +0.9, MMLU +1.9, C-Eval +1.6) are within the range where seed-to-seed variance could plausibly reverse the ranking. Even the larger gaps (GSM8K +4.6) would benefit from variance estimates to assess reliability, especially given the small test set sizes for some benchmarks (HumanEval has 164 problems, GSM8K has 1,319 test examples). For the 80B MoE model, HySparse outperforms Full-Attn on MMLU by only 0.4 points (62.2 vs. 61.8) and ties on DROP (56.5 vs. 56.7). Without replication, a practitioner cannot determine whether the choice of architecture meaningfully improves over the baseline on these specific benchmarks, or whether the observed ordering reflects training noise.

The training curves in Figure 2 partially address this by showing consistent relative ordering throughout training for the ablation configurations, but they do not provide seed-to-seed replication — they show that *within a single training run*, the ordering is stable, not that it would replicate across runs.

**Evidence in the paper:** The paper reports no error bars, no confidence intervals, no p-values, and no mention of multiple seeds or training runs. All tables contain single numbers per benchmark per configuration. The training curves in Figure 2 show a single trajectory per configuration with no shaded regions indicating variance.

**Mitigation status:** The paper does not acknowledge this limitation or discuss measurement uncertainty. The use of single-point estimates is standard in many LLM architecture papers, but given the small absolute gaps on several benchmarks and the absence of statistical testing, the strength of the "consistently outperforms" claim exceeds the robustness of the evidence.

---

### Limitation 5: No Runtime or Memory Profiling; the Modified FlashAttention Kernel's Overhead Is Unquantified

The paper's key technical modification — extending FlashAttention to output block-level attention scores — is described as introducing "negligible overhead" (Section 3.2). This claim is based on the observation that FlashAttention already computes tile-level row maxima during its online softmax procedure, so the additional work consists of storing these intermediate values and rescaling them after the main computation. However, this overhead has two components that are not analyzed: (1) **memory bandwidth**: the block score matrix `S` with dimensions `t × ⌈t/B⌉` must be written to HBM (high-bandwidth memory, i.e., GPU DRAM) rather than discarded. For a full attention layer at 32k context with block size 64, this is a `32768 × 512 × sizeof(float16) ≈ 33.5 MB` write per full attention layer, per query group. In the 7B model with 8 KV heads (8 query groups), this is ~268 MB of additional HBM writes per full attention layer per forward pass, which may be non-trivial relative to the attention computation itself, and (2) **kernel complexity**: the modified kernel requires conditional logic to store and rescale the tile maxima, which may affect compiler optimizations, register allocation, and occupancy compared to the highly-optimized standard FlashAttention kernel. Additionally, the sparse attention kernel that gathers only selected blocks from the full attention KV cache faces an irregular memory access pattern — it must load 16 non-contiguous blocks of 64 tokens each from the full KV cache — which may have substantially lower effective memory bandwidth utilization than the contiguous tiled access pattern of standard FlashAttention.

**The consequence** is that the paper's efficiency claims cannot be verified without profiling data. A practitioner implementing HySparse might find that the modified full attention layers run slower than standard FlashAttention (due to the additional score matrix writes) and that the sparse attention layers, despite attending to only 1024 tokens, do not run 32× faster than full attention due to gather-scatter memory patterns and kernel launch overhead. The net speedup over a standard full attention model might be much less than the structural FLOP reduction suggests — perhaps 2-3× rather than the ~32× per-layer reduction for sparse layers. For the 80B MoE model where 44 of 49 layers use sparse attention, the gap between theoretical and actual speedup would compound across layers. Without profiling, the paper's practical value proposition for latency-sensitive or throughput-critical deployments is unquantified.

**Evidence in the paper:** The paper includes Algorithm 1 showing the modified FlashAttention kernel but does not benchmark it against standard FlashAttention. There are no latency measurements, no roofline analyses, no memory bandwidth utilization numbers, and no kernel-level timing breakdowns. The "negligible overhead" claim is stated without quantitative support.

**Mitigation status:** The paper does not acknowledge the absence of profiling data as a limitation. The overhead claim is presented as self-evident from the algorithmic description. Section 5 discusses future work on KV cache offloading for systems-level efficiency but does not address kernel-level overhead of the current implementation.

---

### Limitation 6: Generalization Is Demonstrated on Only Two Model Configurations, One Dataset Family, and One Base Architecture

The paper evaluates HySparse exclusively on decoder-only transformer models using the PaLM-style architecture (Grouped-Query Attention, RoPE positional encoding, SwiGLU feed-forward layers) trained on undisclosed training data. The two model configurations tested — a 7B dense model and an 80B MoE model — both use the same architectural template (GQA, RoPE, pre-normalization) and are trained with similar recipes (WSD learning rate schedule, BF16 precision, AdamW optimizer). The evaluation benchmarks span general reasoning, math, code, Chinese understanding, and long-context RULER, but all fall within the broad category of text-based QA and reasoning tasks. There is no evaluation on generation quality (e.g., summarization, translation, dialogue), instruction-following, or multimodal tasks. The long-context evaluation (RULER) uses synthetic retrieval tasks whose relationship to real-world long-context use cases (document QA, repository-level code understanding, multi-turn conversation) is unclear.

**The consequence** is that the paper's findings may be specific to the tested combination of model architecture, training recipe, and evaluation distribution. Several architectural features of HySparse could interact differently with other design choices: (1) **Positional encoding**: HySparse's sliding window branch with 128-token window may behave differently with ALiBi or NoPE than with RoPE, since these encodings affect how attention scores decay with distance; (2) **Attention type**: models using Multi-Head Attention (MHA) rather than GQA would have per-head sparse indices rather than per-group indices, potentially changing the index sharing dynamics; (3) **Training data**: the cross-layer token importance stability that HySparse relies on may depend on the training data distribution — data with high topical coherence (e.g., books, long documents) may exhibit different stability patterns than data with rapid topic shifts (e.g., web crawl, social media); (4) **Model depth**: the appropriate full-to-sparse ratio likely depends on total model depth — a 12-layer model might need a different ratio than a 49-layer model, even for the same task distribution, because the representational drift per layer may be larger in shallower models. A practitioner using a different model architecture or targeting a different task domain cannot assume the paper's findings will transfer; they would need to replicate the full training pipeline (including the ablation on hybrid ratio and sharing configuration) for their specific setup.

**Evidence in the paper:** All experiments use the same base architecture family (decoder-only transformer with GQA and RoPE). The paper does not evaluate on encoder-decoder models, models with MHA, or models with alternative positional encodings. The evaluation benchmarks cover reasoning and QA but not generation quality, factuality, safety, or instruction-following. The RULER benchmark uses synthetic "needle-in-a-haystack" style retrieval tasks.

**Mitigation status:** The paper does not discuss generalization to other architectures, training recipes, or task domains. Section 5 mentions future work to "scale HySparse to even larger model sizes and train on more tokens" but does not address evaluation on different task types or architectures. The paper positions HySparse as a general-purpose architecture, stating it "provides a simple and effective architectural solution to the core limitations of sparse attention" (Section 1), but the evidence base for this generality claim is narrow — two model configurations within a single architecture family, evaluated on benchmarks that all fall within text-based QA/reasoning.

## 7. Implications and Future Directions

### How This Work Changes the Landscape

This paper introduces a conceptual reframing rather than a paradigm shift, but the reframing is sharp enough to redirect research investment within the sparse attention subfield. The core reorientation is this: **full attention layers are not the enemy to be minimized — they are the enabler that makes aggressive sparsity viable.** Prior work treated full attention as pure cost, to be replaced by increasingly clever approximations (learned gating modules, heuristic patterns, low-rank projections). HySparse inverts the relationship: keep a *small number* of full attention layers strategically placed throughout the model, and treat their exact attention scores as an oracle signal that subsequent sparse layers can exploit. The intellectual move is from "how do we approximate the full attention signal without computing it?" to "how far can we stretch the exact signal we already have?"

This reframing matters because it changes the optimization target for sparse attention research. Rather than developing better token importance *predictors* (improving proxy fidelity), the high-leverage research direction becomes understanding and extending cross-layer token importance *stability* (how far oracle indices remain valid). The paper's 1:11 ratio in the 80B MoE model — sparse layers reusing indices from 11 layers prior while still outperforming full attention — demonstrates that stability extends further than many practitioners would have assumed. But the paper does not characterize *how much* further, or under what conditions the assumption breaks. This gap defines the new frontier.

The work also resolves a latent tension between two lines of evidence that appeared contradictory. On one hand, dynamic sparse attention methods (Jiang et al., 2024; Tang et al., 2024) showed that selecting tokens based on approximate importance scores could maintain model quality while reducing computation — but they couldn't reduce memory because the full KV cache had to be retained. On the other hand, cross-layer KV cache sharing methods (Sun et al., 2024; Brandon et al., 2024) showed that memory could be reduced by reusing KV caches across layers — but they didn't reduce computation and risked representational mismatch. HySparse shows these are not independent problems requiring independent solutions. **The same architectural feature — the preceding full attention layer — can serve as both the oracle for token selection (solving computation) and the shared KV cache source (solving memory).** The tension dissolves when you recognize that the KV cache being shared is exactly the one from which oracle indices are derived. This is a unification insight: it reveals that two previously-separate optimizations are naturally complementary when integrated architecturally rather than layered post-hoc.

A specific diagnostic contribution is the finding that **cross-layer KV cache sharing is beneficial for global retrieval but harmful for local computation** (Table 4: sharing the full attention KV cache for both the sparse attention and sliding window branches drops MMLU by 5.6 points, GSM8K by 6.5 points, and BBH by 6.7 points compared to sharing only for sparse attention). Prior work on KV sharing applied it uniformly and reported that it worked with minimal degradation. HySparse reveals a more precise condition: sharing works when the attention function is global retrieval, but fails when the attention function is local coherence modeling. This is a *boundary condition* on a previously accepted technique — it tells researchers not "does KV sharing work?" but "*when* does KV sharing work?" The answer — "for global, not for local" — is a finer-grained understanding that should inform future architectures beyond HySparse. Any hybrid architecture with both global and local attention pathways should consider this distinction when designing its KV cache management.

The landscape shift also makes certain research directions less attractive. **Better proxy-based token selection** — developing more sophisticated gating modules, improved distillation losses, or fancier heuristic patterns — becomes less urgent because HySparse demonstrates that oracle-guided selection from strategically placed full attention layers can eliminate the proxy problem entirely, at least up to fairly aggressive hybrid ratios. The bottleneck is no longer "how good is our importance predictor?" but "how many full attention layers do we need, and where should they go?" Research effort previously directed at proxy improvement might be better redirected toward understanding the stability properties that determine optimal full-layer placement. Similarly, **sparse attention methods that reduce computation but not memory** — the dominant paradigm in dynamic sparse attention — are revealed as solving only half the problem. HySparse demonstrates that computation and memory reduction can be achieved simultaneously through architectural integration, setting a higher bar for what "efficient attention" should deliver.

### Follow-Up Research This Work Enables

**Characterizing the cross-layer token importance stability decay rate as a function of layer distance, model depth, and task type.** The paper demonstrates that oracle indices from a full attention layer remain informative 11 layers later in an 80B MoE model — but provides no measurement of *how* informative, or how quickly informativeness decays. A strong follow-up would instrument a trained HySparse model to measure, at each sparse layer, the overlap between the oracle-selected blocks (from the nearest preceding full attention layer) and the blocks that *would* be selected if full attention were computed at that layer. This overlap could be plotted as a function of layer distance from the last full attention layer, for different model depths, different task types (retrieval vs. reasoning vs. generation), and different positions in the model (early vs. late layers). The resulting stability decay curves would provide the missing empirical basis for choosing the optimal full-to-sparse ratio — you could read off the maximum viable spacing for a target overlap threshold. This experiment would also test whether stability is uniform across the model depth (the paper implicitly assumes it is, since the hybrid ratio is constant across blocks) or whether different depths require different spacing of full attention layers.

**Comparing oracle token selection against a learned proxy head-to-head in the HySparse architecture.** The paper claims oracle selection eliminates the proxy bottleneck but never compares against a learned proxy in the same architecture. A clean experiment would take the HySparse 7B model and replace the oracle index mechanism with a learned gating module per sparse layer, trained via self-distillation from the nearest full attention layer's exact attention scores (following the SeerAttention recipe; Gao et al., 2024). Both variants would use the same KV cache sharing scheme (SA branch shares full-layer KV, SWA branch independent). The comparison would answer: does the oracle approach outperform a well-trained proxy of comparable computational cost? If the learned proxy matches or exceeds oracle performance, the "oracle" framing is less compelling — the advantage would be simplicity (no auxiliary loss, no additional module training) rather than quality. If oracle outperforms, it validates the central claim. Either outcome is informative. A stronger version would also test whether a per-layer learned proxy (each sparse layer learns its own selection, potentially adapting to representational drift) outperforms both the shared oracle approach and a shared learned proxy, quantifying the benefit of per-layer adaptation.

**Determining the minimum viable number of full attention layers through a systematic sweep of hybrid ratios.** The paper tests exactly two ratios — 1:3 (7B) and 1:11 (80B MoE) — and both work, but these are confounded with model scale and architecture type (dense vs. MoE). A focused follow-up would fix the model configuration (say, the 7B architecture) and sweep hybrid ratios: 1:3, 1:5, 1:7, 1:9, 1:11, 1:15, 1:23, and an extreme like 1:35 (one full attention layer at the beginning, one in the middle, one at the end). The key measurement is where performance diverges from Full-Attn — the "cliff" beyond which oracle indices become too stale. This would establish an empirical upper bound on the hybrid ratio for this model class and provide practical guidance for architecture design. An even more informative variant would plot the *tradeoff curve*: KV cache memory against accuracy, with each ratio as a point on the curve, so practitioners can choose their operating point based on deployment memory constraints. The paper's implication that 1:11 is near the limit is speculative without data points beyond 1:11.

**Testing HySparse on generation-heavy and instruction-following tasks beyond QA and reasoning benchmarks.** All evaluations in the paper are on benchmarks with clear correct answers (multiple choice, exact match, or synthetic retrieval). The architecture's behavior on open-ended generation — summarization, dialogue, creative writing, multi-turn instruction following — is unexplored. These tasks differ in their attention patterns: they may require more fine-grained local coherence over longer spans, or more dynamic shifts in what constitutes an "important" token. A concrete experiment would fine-tune (or evaluate zero-shot) the existing HySparse 7B checkpoint on benchmarks like AlpacaEval, MT-Bench, or a long-document summarization task (GovReport, SummScreen), measuring both generation quality and attention pattern characteristics. The key question is whether the 1024-token global sparse budget, plus 128-token local window, is sufficient for tasks where relevance is more diffuse or where maintaining discourse coherence across many sentences is critical. A negative result (substantial degradation on generation quality compared to Full-Attn, even though reasoning benchmarks improve) would refine the applicability domain of the architecture.

**Combining HySparse with KV cache offloading for extreme context lengths.** Section 5 mentions that HySparse "points to a straightforward systems-level strategy" of offloading full attention KV caches to external memory (CPU or SSD) and keeping only the selected sparse KV on GPU. This is mentioned as future work but not implemented. A concrete systems project would implement this for the 80B MoE HySparse model and benchmark it: measure prefill latency, decode throughput, and maximum batch size with offloaded full-attention KV caches, compared to an in-memory Full-Attn baseline with equivalent hardware. The hypothesis is that since only 5 out of 49 layers need their full KV caches loaded from external memory (and only at those layers during generation), the offloading overhead is amortized across the 44 sparse layers that operate on small in-memory caches. The key metric is whether end-to-end throughput at extreme context lengths (128k, 256k) improves enough to make deployment economically viable. Prior work like OmniKV (Hao et al., 2025) explored similar ideas post-hoc; HySparse's architectural integration (the full attention layers are already identified and isolated) may make the offloading strategy more natural and lower-overhead than retrofitting it onto a standard dense model.

**Training a difficulty predictor or "layer importance" predictor that dynamically determines where full attention layers should be placed.** The paper places full attention layers at fixed intervals (every 4 or 12 layers) based on a uniform spacing assumption. But token importance stability may vary with layer depth (early layers might need more frequent full attention, or vice versa) and with input characteristics (some sequences may benefit from more frequent global context). A learnable approach could treat full attention layer placement as an architectural decision to be optimized: train a lightweight predictor (possibly a small MLP or attention-based module) that, given the current hidden state and generation context, decides whether the next layer should use full attention or sparse attention. This is similar in spirit to dynamic layer skipping or early-exit work, but applied to attention type rather than layer execution. The training signal could come from the downstream task loss, with a regularization penalty that encourages sparser full attention usage. This would transform HySparse from a fixed architectural pattern into an adaptive computation mechanism — pushing toward the "compute-optimal" philosophy where the architecture adjusts its cost based on input difficulty.

### Practical Applications and Downstream Use Cases

**Long-context serving with constrained GPU memory.** The most direct deployment scenario for HySparse is serving LLMs with context lengths exceeding what fits comfortably in GPU memory at reasonable batch sizes. Consider a deployment where a 49-layer dense model with full attention at 32k context requires approximately 40 GB of KV cache per sequence (rough estimate for 80B-scale model). With the HySparse 80B MoE configuration, only 5 full attention layers store full KV caches (plus 44 layers with 128-token SWA caches), reducing the per-sequence KV cache by approximately 9.5× — from ~40 GB to ~4.2 GB. This doesn't make the model faster per-token (sparse layers still compute attention, just over fewer tokens), but it directly increases the maximum batch size by roughly 9.5× under the same memory budget. For a serving provider, this means 9.5× more simultaneous users can be served on the same GPU cluster, directly translating to throughput and revenue. The caveat — and why this paper alone doesn't close the case — is that empirical memory measurements and throughput benchmarking are needed to confirm the structural estimates translate into real deployment gains.

**Pretraining cost reduction through architectural sparsity.** HySparse is a pretraining architecture, not an inference-time optimization. This means the efficiency benefits extend to training as well: sparse attention layers compute attention over 1024 tokens rather than the full sequence during pretraining, reducing attention FLOPs during training by approximately the same factor as at inference (~32× at 32k context). The paper does not report training time comparisons, but a practitioner training a large model from scratch could adopt the HySparse pattern to reduce total training FLOPs while maintaining or improving downstream quality. The 80B MoE results suggest this might come with *improved* quality — the HySparse model outperformed Full-Attn on most benchmarks despite using substantially less attention compute during training. This inverts the usual cost-quality tradeoff: HySparse may be cheaper to train *and* better, at least for long-context models. The practical adoption path is for organizations pretraining large models to experiment with the HySparse pattern as a drop-in architectural change, starting with the 1:3 ratio (conservative) and testing more aggressive ratios based on their quality targets.

**On-device or edge deployment of long-context models.** Edge devices (phones, laptops) have severe memory constraints — a 7B model with full 32k KV cache may exceed the available RAM on many devices. HySparse's KV cache reduction makes long-context capability feasible on memory-constrained hardware without model quantization or other lossy compression. The 7B HySparse model with 1:3 ratio reduces the number of full-KV-cache layers from 36 to approximately 9 (exact count depends on the final layer arrangement, but roughly 4× fewer full-cache layers), while maintaining or improving accuracy on general benchmarks and substantially improving long-context RULER scores (94.1 vs. 93.0 overall at 16k, 89.3 vs. 88.2 at 32k). This is a concrete benefit: better long-context performance in a smaller memory footprint. Application developers building document Q&A, local code assistants, or personal knowledge management tools that need to process long documents entirely on-device could adopt the HySparse architecture to fit within device memory budgets that would otherwise force context truncation.

**Efficient data generation pipelines for self-improvement or distillation.** When using LLMs to generate training data — for instance, generating reasoning chains for math problems, summarizing documents, or producing synthetic instruction-tuning data — the inference cost can dominate the total pipeline cost. HySparse's computational efficiency (attention over 1024 tokens rather than the full sequence in most layers) directly reduces the per-token cost of generation, while the long-context improvements (Table 3) mean that quality on retrieval-heavy generation tasks is preserved or improved. A team running large-scale data generation (billions of tokens) could switch from a Full-Attn model to a HySparse model with the same parameter count and training recipe and expect lower inference cost per generated token with no quality degradation — and potentially quality improvements on tasks requiring long-context reasoning. The memory reduction also enables larger batch sizes during generation, further improving throughput. This is a straightforward drop-in optimization for any pipeline that uses LLM inference at scale with long contexts.

### When to Prefer This Method

The paper positions HySparse against two alternatives — Full-Attn (all layers standard full attention) and Hybrid SWA (interleaved full attention and sliding window attention only) — and the choice between them depends on context length, available memory, and task characteristics:

- **Prefer HySparse over Full-Attn when** deploying models at context lengths where KV cache memory is the binding constraint on batch size (roughly 16k+ tokens for large models), AND when the hybrid ratio can be tuned to at least 1:3 or more aggressive based on architectural budget. The 7B results show performance parity or improvement at 1:3; the 80B MoE results show substantial gains at 1:11. The crossover point where HySparse's memory savings outweigh any quality differences will depend on deployment hardware, but the structural 9.5× KV cache reduction at 1:11 is large enough to dominate practical serving economics in most long-context settings.

- **Prefer HySparse over Hybrid SWA when** the full-to-sparse ratio is aggressive (roughly 1:5 or higher) OR when tasks require global retrieval over long distances. At moderate ratios (1:3), Hybrid SWA and HySparse are competitive (Table 2, 7B model: BBH 54.0 vs. 53.5, MMLU 57.5 vs. 58.8, DROP 43.9 vs. 52.4 — HySparse's advantage is benchmark-dependent). At aggressive ratios (1:11, 80B MoE), Hybrid SWA degrades substantially on tasks requiring global context (DROP drops 8.9 points, RULER overall drops 20.9 points at 16k), while HySparse recovers or exceeds Full-Attn performance. The rule of thumb: if you're interleaving full attention layers more than ~5 layers apart, use HySparse rather than Hybrid SWA, because sliding windows alone cannot bridge 5+ layers of missing global context.

- **Prefer Full-Attn when** context lengths are short (4k or less) such that KV cache memory is not the primary constraint, OR when inference latency is the dominant concern and the additional overhead of the modified FlashAttention kernel (block score extraction and storage) plus the irregular memory access patterns of sparse attention gathering would erode or eliminate the theoretical FLOP advantage. The paper provides no latency data to guide this tradeoff, so a conservative practitioner would run their own benchmarks before deploying HySparse in a latency-critical setting.

- **Do not prefer any existing learned proxy approach over HySparse based on the current evidence**, because the paper provides no comparison against learned proxies. A practitioner choosing between HySparse and, say, SeerAttention-style gating would need to run their own comparison — the paper's "oracle > proxy" claim is architecturally motivated but empirically untested against well-trained learned proxies.
