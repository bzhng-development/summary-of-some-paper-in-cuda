# Taming Actor-Observer Asymmetry in Agents via Dialectical Alignment

**ArXiv:** [2604.19548](https://arxiv.org/abs/2604.19548)

## 🎯 Pitch

LLM agents mirror a classic human cognitive bias: merely swapping from 'executor' to 'reviewer' causes over 20% of the same failures to be blamed on external circumstances instead of internal faults. This paper shows that simply telling agents to 'be objective' backfires, but training them to synthesize a thesis with its antithesis via dialectical reasoning slashes this bias threefold and lets a 4B model match 32B rivals.

---

## 1. Executive Summary

This paper identifies, quantifies, and mitigates a systematic cognitive bias in role-playing LLM agents — **Actor-Observer Asymmetry (AOA)** — the tendency for an agent acting as an executor (actor) to attribute failures to external circumstances while the same agent acting as a reviewer (observer) attributes identical failures to internal faults. The authors introduce the Ambiguous Failure Benchmark (AFB), a diagnostic dataset of 200 inherently ambiguous failure scenarios across 10 domains, which reveals that simply swapping the agent's perspective triggers AOA in over 20% of cases for most tested models (e.g., Qwen3-4B reaches 29% V-AOA on Human-Agent traces and DeepSeek-V3.2 hits 31% on Agent-Agent traces). To tame this bias, they propose **ReTAS** (Reasoning via Thesis-Antithesis-Synthesis), a model trained through dialectical alignment — a structured three-stage reasoning process (role-congruent thesis, opposing antithesis, evidence-grounded synthesis) enforced via Group Relative Policy Optimization (GRPO) with an attribution-consistency reward — that guides agents to synthesize conflicting viewpoints into an objective consensus. On the FinQA-TAS and Spider-TAS failure attribution benchmarks, ReTAS (4B parameters) reduces V-AOA by roughly threefold compared to dual-view reflection baselines while improving attribution accuracy to 71.2% on FinQA-TAS and matching or exceeding much larger models (e.g., QwQ-32B), establishing that dialectical alignment can substitute for model scale in resolving perspective-dependent cognitive bias — but only when the underlying training enforces structured synthesis rather than merely prompting for multiple viewpoints.

## 2. Context and Motivation

### The Core Problem: Role-Playing Introduces a Systematic Cognitive Bias

The fundamental problem this paper tackles is that **role-playing — the dominant paradigm for building multi-agent LLM systems — systematically distorts how agents attribute failures**. When an LLM is assigned a functional role (e.g., "executor" or "reviewer") to enable specialized task decomposition, that role does more than specify *what* the agent should do; it functions as a **cognitive prior** that shapes *how* the agent reasons about causes, particularly when things go wrong.

This is not an occasional glitch. The paper demonstrates (Table 2) that across six models ranging from 4B to closed-source frontier systems, simply swapping the perspective prompt — all other context held identical — causes a shift in failure attribution in over 20% of cases for most models. A Qwen3-4B model, when assigned the actor (executor) role, externalizes blame in 29% of Human-Agent scenarios. The same model, given identical failure information but cast as an observer (reviewer), instead attributes those failures to internal faults. This is **Actor-Observer Asymmetry (AOA)**: a well-documented human cognitive bias (Heider, 1958; Jones and Nisbett, 1972; Malle, 2006) that the paper demonstrates has permeated LLMs through their training on human discourse.

The paper's central insight is not merely that agents make inconsistent attributions. Rather, it identifies a **specific, predictable structure** to this inconsistency that mirrors a deeply studied phenomenon in social psychology. An actor's self-serving bias — "the external circumstances made me fail" — and an observer's fundamental attribution error — "their internal flaws caused the failure" — emerge in LLM agents when, and only when, role assignments create a self/other distinction. This is significant because it means that the very mechanism used to improve agent reliability (role specialization for mutual auditing) simultaneously undermines that reliability by introducing a systematic, role-dependent skew in causal reasoning.

### Why This Matters: Epistemic and Practical Consequences

**Epistemic consequence: roles corrupt causal reasoning.** In a multi-agent framework where one agent executes tasks and another reviews outputs, the system's ability to correctly diagnose the root cause of failures is paramount. If the executor consistently blames missing context (external) while the reviewer consistently blames reasoning errors (internal), the system arrives at contradictory diagnoses for the same evidence. These conflicting perspectives, the paper argues, "hinder consensus, resulting in inter-agent misalignment" (Section 1). The consequence is not merely inefficiency — it is *epistemic*. The system cannot converge on a shared understanding of what went wrong, which in turn makes it impossible to take the correct corrective action. The paper provides a concrete example in Figure 1: a timeout exception that could plausibly stem from either a server issue (external) or a logic error in the code (internal). If the executor and reviewer disagree on the cause, the system either fixes the wrong thing or deadlocks.

**Practical consequence: scaling model size doesn't fix this.** One might assume that larger, more capable models would naturally overcome such biases. The paper's AFB results (Table 2) directly contradict this assumption. While GPT-5.1 — the most capable model tested — reduces V-AOA to 5% in Human-Agent scenarios, it still exhibits a massive **attribution imbalance**: 94% of failures are attributed internally regardless of perspective. In other words, the most advanced model simply flips from actor-favoring bias to a systemic anti-agent bias, consistently blaming the agent even when external factors are genuinely responsible. This has dire practical implications for agent systems in production: a reviewer that always finds the executor at fault will generate false corrections, while an executor that never accepts responsibility will ignore genuine reasoning errors. Neither extreme supports reliable collaboration.

Furthermore, the paper demonstrates (Section 5.1, Figure 7-8) that this bias generalizes across domains. The ReTAS model, trained on financial reasoning (FinQA-TAS) and text-to-SQL (Spider-TAS), transfers its debiasing effect to the completely unseen AFB domains (coding, customer service, safety alignment, creative writing, etc.). This suggests that AOA is not task-specific but is a **fundamental property of role-conditioned reasoning** that manifests whenever an agent's perspective is specified.

**Theoretical significance: bridging cognitive science and agent architecture.** The paper makes a novel connection between attribution theory in social psychology and the architecture of LLM agent systems. This connection is more than metaphorical. The paper argues, drawing on prior work (Tjuatja et al., 2024; Acerbi and Stubbersfield, 2023; Leng, 2024), that because LLMs are trained on human-generated text, they "inherit such attributional biases." By framing the problem through the lens of AOA rather than generic inconsistency, the paper provides a **mechanistic hypothesis** for *why* agents disagree: the role prompt activates a cognitive schema (self-serving vs. other-blaming) that LLMs learned from millions of human-authored texts where actors and observers described the same events differently.

This is a sharper diagnosis than prior work, which typically attributed multi-agent failures to general "misalignment" or "communication breakdown." By naming the specific bias and its psychological origins, the paper enables targeted interventions — dialectical synthesis, in this case — rather than broad (and often ineffective) injunctions to "be objective" or "consider other perspectives."

### Where Prior Approaches Fall Short

The paper identifies three categories of prior work and explains why each falls short of resolving AOA.

**1. Role-playing as a framework introduces the bias it should prevent.** The evolution from single-agent reasoning (Wei et al., 2022; Yao et al., 2023a) to multi-agent role-playing systems (Liu et al., 2024; Zhang et al., 2024a) was motivated by the need for specialization, self-reflection, and mutual auditing. Frameworks like ChatDev (Qian et al., 2024) and ProAgent (Zhang et al., 2024a) assign roles such as "programmer," "reviewer," and "tester" to decompose complex software engineering tasks. While this decomposition demonstrably improves efficiency and solution quality (Yang et al., 2024a), the paper argues it introduces an "under-explored epistemic risk: roles act not only as functional specifications but also as cognitive priors that shape reasoning" (Section 2). Prior work on role-playing (Shao et al., 2023) focused almost exclusively on eliciting domain expertise — making agents more knowledgeable or more skilled in their assigned domain. It did not consider that role assignment also induces predictable, systematic distortions in causal reasoning. The paper positions its contribution as addressing this blind spot: while role-playing is effective for task decomposition, it simultaneously creates an attribution problem that, left unchecked, undermines the very reliability that role specialization was meant to achieve.

**2. Self-reflection and cross-critique treat symptoms, not causes.** A substantial body of work has attempted to improve agent reliability through self-reflection (Shinn et al., 2023; Ji et al., 2023; Dou et al., 2024; Bo et al., 2024) and cross-critique mechanisms (Yu et al., 2024; Wang et al., 2024; Lan et al., 2025). Self-reflection — where an agent reviews its own outputs and identifies errors — is precisely the scenario that AOA distorts: an agent in an "actor" role tends to externalize blame, producing defensive justifications rather than genuine error analysis. Cross-critique — where one agent reviews another's outputs — is the complementary scenario: an "observer" agent tends to internalize blame, finding faults even where external constraints were the true cause.

The paper's experimental results validate this critique directly. In Table 3, the Dual View reflection baselines (which prompt the same model to adopt both executor and reviewer perspectives) achieve **worse** attribution consistency than Single View reflection for some models. For GLM-4.6, Dual View reflection produces a Flip rate of 52.7% on FinQA-TAS — meaning that over half of the time, the model's attribution changes solely because of the perspective swap. The paper explains this counterintuitive result: "mere role diversification can exacerbate conflict when agents remain entrenched in role-based priors" (Section 5.3). Simply adding an opposing viewpoint, without a mechanism to *synthesize* the conflict into an evidence-grounded conclusion, amplifies rather than resolves the bias.

A more subtle limitation of prior reflection approaches is that they operate at the **output level** — asking the model to "check your work" or "critique this solution" — without intervening in the **reasoning process**. The paper's key insight is that AOA is a failure of *reasoning*, not merely of output correctness. An agent can produce a plausible-sounding self-critique that is nonetheless systematically skewed by its role. Naïve interventions like "be objective" are ineffective because "role inertia" (Section 1) causes the agent to defend its position rather than genuinely re-evaluate evidence. Similarly, enforcing opposing perspectives without synthesis invites "over-correction and groundless self-blame" — the agent simply swaps one bias for another rather than converging on the truth.

**3. Attribution theory in LLMs has been studied, but not in the context of agent collaboration.** Prior work had established that LLMs inherit attributional biases (Tjuatja et al., 2024; Acerbi and Stubbersfield, 2023) and exhibit social stereotypes (Hu et al., 2025; Shrawgi et al., 2024) and evaluator biases (Wang et al., 2024). However, this work examined biases in isolation — e.g., an LLM filling out a survey exhibits a particular response pattern — rather than studying how biases *interact* across multiple perspectives in a collaborative setting. The paper's contribution is to show that in a multi-agent system, these biases are not just additive; they are **antagonistic**. The actor's self-serving bias and the observer's fundamental attribution error pull in opposite directions, creating a conflict that neither perspective can resolve individually because each is epistemically closed by its role.

The connection to attribution theory also explains why **increasing model scale is insufficient**. The paper's AFB results (Table 2) show that while larger models exhibit lower V-AOA, they develop a different pathology: unconditional internal attribution (94% for GPT-5.1). This is consistent with prior findings that larger models, trained on more curated data, may over-learn norms of self-criticism or humility from their training distribution. But from the perspective of agent collaboration, it is equally damaging — a reviewer that always blames the executor is no more reliable than one that exhibits role-dependent bias.

**4. Existing debiasing methods don't address the perspective-dependent nature of the bias.** General-purpose debiasing techniques — calibration training, instruction tuning for fairness, reinforcement learning from human feedback (RLHF) — operate at the level of individual model outputs. They aim to produce less biased responses overall. But AOA is not a bias in any *single* output; it is a bias in the *relationship* between outputs generated from different perspectives. An agent can be perfectly calibrated in each role individually yet still exhibit AOA if its attributions systematically diverge under role swaps. The paper's framing of the problem as perspective-invariance — the requirement that the same evidence should lead to the same attribution regardless of the agent's assigned role — is a novel desideratum that prior debiasing work did not target.

### How This Paper Positions Itself

The paper positions itself at the intersection of three research threads: **multi-agent role-playing** (the application domain), **cognitive bias in LLMs** (the phenomenon being studied), and **structured reasoning alignment** (the proposed solution). Its primary contribution is not a new role-playing architecture or a general debiasing technique, but rather a **diagnosis-then-treatment approach** that first identifies the specific psychological mechanism driving multi-agent misalignment (AOA), then develops a targeted intervention (dialectical alignment) that addresses that mechanism.

The diagnosis component — the AFB benchmark and the empirical demonstration of AOA across models — establishes that the problem is real, systematic, and not addressed by scale alone. The paper explicitly constructs AFB to "maximize attribution ambiguity, where the absence of a deterministic ground truth exposes agents' inherent attribution biases" (Section 3). This is a deliberate design choice: by eliminating scenarios where there is a single obviously correct attribution, AFB creates the epistemic conditions under which AOA is most likely to manifest — conditions that also happen to be common in real-world agent deployments where failures are genuinely ambiguous.

The treatment component — ReTAS — draws on Fichtean dialectics (Fichte, 1982) to propose that "robust attribution requires a structured reasoning process: articulating a position, confronting its negation, and integrating both into a unified truth" (Section 1). This is not merely a prompting technique. The paper distinguishes its approach from "surface-level prompt engineering" (Section 6) by embedding the dialectical structure into the model's learned behavior through GRPO-based reinforcement learning. The key claim is that **the reasoning process itself must be aligned**, not just the prompt template. The ablation study in Table 5 supports this: adding the TAS template as a zero-shot prompt (the "+ TAS" row in the Qwen3-4B variant experiments) improves V-AOA from 22.7% to 14.1% on FinQA-TAS, but the fully trained ReTAS model drives it down to 5.4%. The paper argues this gap — from 14.1% to 5.4% — represents the difference between prompting a model to think dialectically and training it to internalize dialectical reasoning as a behavioral habit.

The paper also positions itself as contributing to a broader shift in agent design philosophy. Rather than treating agents as black-box reasoners whose outputs we can only accept or critique, the paper advocates for "principled cognitive alignment and auditing" (Section 6) — building systems that can explicitly track how their perspective influences their conclusions and correct for it. This is presented as complementary to (not a replacement for) scaling model size, with the FLOPs-matched results (Table 3) showing that a 4B model with dialectical alignment matches or exceeds 32B models without it on attribution accuracy.

Finally, the paper positions its work as **validating a causal mechanism**, not just reporting a correlation. By demonstrating that ReTAS-trained models transfer their debiased reasoning to unseen domains (AFB) and to dynamic negotiation tasks (SALES ARENA), the paper argues that dialectical alignment teaches a generalizable reasoning strategy — "decoupl[ing] the agent's reasoning from its role-induced stance" (Section 5.1) — rather than overfitting to the training distributions. This generalization evidence strengthens the theoretical claim that AOA is a fundamental property of role-conditioned reasoning and that dialectical synthesis is a fundamental solution, not a task-specific hack.

## 3. Technical Approach

### 3.1 Reader Orientation

The paper builds **ReTAS**, a fine-tuned language model that, when deployed as an agent in a multi-agent system, can diagnose the root cause of a task failure — is the problem missing evidence (external) or flawed reasoning (internal)? — **without its conclusion being swayed by whether it's currently playing the role of the executor who made the mistake or the reviewer judging someone else's work**. The solution takes the shape of a three-stage reasoning ritual (Thesis → Antithesis → Synthesis) that the model is first taught via supervised fine-tuning on expert-written examples, then *internalized as a behavioral habit* through reinforcement learning that rewards the model for arriving at the same evidence-grounded attribution regardless of which role it's simulating.

### 3.2 Big-Picture Architecture (Diagram in Words)

The ReTAS system is constructed in three sequential stages, each feeding into the next:

1. **Attribution Data Generator (Section 4.2)** — A standard retrieval-augmented pipeline (Qwen-2.5-7B backbone) processes existing QA datasets (FinQA, Spider) to produce questions paired with retrieved evidence and model-generated answers. Each example is automatically labeled as `FalseExt` (missing evidence makes the answer impossible), `FalseInt` (sufficient evidence, but the answer is wrong), or `True` (correct) by comparing retrieved evidence and the predicted answer against the gold-standard evidence and answer.

2. **Dialectical Synthesis Engine (Section 4.3)** — A strong teacher model (GPT-5.1) takes each labeled failure case and generates *two* complete reasoning trajectories — one from a defensive "Actor" perspective, one from a critical "Reviewer" perspective — both following the Thesis-Antithesis-Synthesis (TAS) format. Critically, both trajectories are required to converge to the *same* attribution label (the ground-truth label from Stage 1), forcing the model to demonstrate that the final conclusion is derived from evidence, not from the initial role-induced reaction.

3. **Dialectical Alignment Trainer (Section 4.4)** — The backbone model (Qwen3-4B-Instruct-2507) is first supervised-fine-tuned on the synthesized TAS trajectories to learn the format, then further optimized via Group Relative Policy Optimization (GRPO) with a composite reward that jointly incentivizes correct formatting, correct attribution, and correct final answers. This second phase is what transforms the TAS template from a prompted pattern into a learned reasoning policy.

At inference time, the trained ReTAS model receives a case record (question, evidence, answer, code) and a system prompt that can specify *either* an Actor or Reviewer perspective. The model generates a TAS-structured response — an initial role-congruent reaction (Thesis), an evidence-checking counterfactual (Antithesis), and an evidence-grounded attribution plus corrective action (Synthesis) — that should be consistent regardless of which perspective the system prompt requested.

### 3.4 Detailed, Sentence-Based Technical Breakdown

This is an **empirical methods paper** whose core idea is that role-induced attribution bias (AOA) can be mitigated by training a language model to follow a structured dialectical reasoning process — Thesis, Antithesis, Synthesis — where the initial role-congruent reaction is explicitly recorded, challenged against objective evidence, and then overridden by an evidence-grounded conclusion, with reinforcement learning used to make this process robust to perspective swaps.

---

#### Task Formalization and the Need for Verifiable Attribution Labels

To train a model that produces perspective-invariant failure attributions, the paper needs training data where the *true* cause of failure is known with certainty. This is the fundamental requirement driving the data generation pipeline: if the ground-truth attribution is ambiguous, the model cannot be trained to converge to it.

The paper selects **retrieval-augmented reasoning tasks** as the substrate because they decompose cleanly into two stages with distinct responsibility boundaries:

1. **Context Retrieval** — an upstream retriever fetches evidence items `$E$` from a document corpus given the question.
2. **Program Synthesis** — a downstream agent takes the question plus the retrieved evidence `$E$` and produces an answer `$\hat{a}$` (by generating executable code for FinQA, or SQL for Spider).

From the perspective of the second-stage agent (the one ReTAS will simulate), failures can be objectively localized. If the necessary evidence is missing from `$E$`, the agent *cannot possibly* produce the correct answer regardless of its reasoning quality — the failure is **external** (situational constraint). If the evidence is present but the agent produces the wrong answer, the failure is **internal** (reasoning flaw within the agent's control). This clean decomposition provides the verifiable attribution labels that AOA measurement and ReTAS training both require.

---

#### Attribution Data Generation (Section 4.2)

The data generation pipeline is implemented using **Qwen-2.5-7B** (Yang et al., 2024b) as the backbone model that performs both retrieval and answer generation. The pipeline operates on two existing datasets:

- **FinQA** (Chen et al., 2021) — a financial reasoning dataset requiring hybrid numerical and textual reasoning over financial reports.
- **Spider** (Yu et al., 2018) — a text-to-SQL dataset spanning multiple domains with complex database schemas.

For each question in these datasets, the pipeline executes three sequential operations:

**Operation 1: Context Retrieval.** The retriever extracts the top-k evidence items `$E$` from the document corpus (text chunks for FinQA, table schemas for Spider). The paper does not specify the exact value of `$k$` or the retrieval mechanism, but the downstream labeling logic does not depend on these specifics — it only requires that the set of retrieved evidence items `$E$` can be compared against the gold evidence set `$E_{\text{gold}}$` (the evidence items that a perfect retriever would have returned).

**Operation 2: Program Synthesis.** Using the retrieved evidence `$E$`, the agent generates executable logic (Python code for FinQA, SQL queries for Spider) and executes it to produce a predicted answer `$\hat{a}$`.

**Operation 3: Fact-Check Labeling.** Each example is compared against two ground-truth references — the gold evidence `$E_{\text{gold}}$` (the set of evidence items that are actually necessary to answer the question correctly) and the gold answer `$a^*$` (the correct final answer). The labeling rule is a three-way classification:

- **`FalseExt` (External Fault):** The retrieved evidence is missing at least one necessary item. Formally, `$E_{\text{gold}} \not\subseteq E$`. This means the agent's answer `$\hat{a}$` — whatever it is — cannot be correct because critical information was never provided to it. The failure is attributed to the retrieval stage (external to the agent).

- **`FalseInt` (Internal Fault):** The retrieved evidence is sufficient — `$E_{\text{gold}} \subseteq E$` — but the predicted answer is wrong: `$\hat{a} \neq a^*$`. This means the agent had all the information it needed but still produced an incorrect answer, indicating a reasoning flaw within the agent itself.

- **`True` (Correct):** The evidence is sufficient (`$E_{\text{gold}} \subseteq E$`) and the answer is correct (`$\hat{a} = a^*$`).

**Why this labeling scheme works.** The key property is that the `FalseExt` / `FalseInt` distinction depends *only* on the sufficiency of the evidence, not on the correctness of the answer per se. A case where evidence is missing `$E_{\text{gold}} \not\subseteq E$` is labeled `FalseExt` regardless of whether the agent's answer happened to be right by chance. This ensures that the attribution label captures the *structural* cause of failure (or success) — the epistemic conditions under which the agent was operating — rather than merely the outcome.

**Training dataset statistics (Table 8).** The paper reports:
- **FinQA-TAS:** 6,251 training samples, 883 dev samples, 1,147 test samples. The training set contains 984 `External`, 2,952 `Internal`, and 2,315 `Correct` examples.
- **Spider-TAS:** 7,000 training samples, 1,034 dev samples. The training set contains 301 `External`, 1,391 `Internal`, and 5,308 `Correct` examples.

The class imbalance — particularly in Spider-TAS where `Correct` examples dominate — is notable and the paper does not discuss rebalancing strategies. The strong performance on both `FalseExt` and `FalseInt` attribution (as reflected in low V-AOA scores in Table 3) suggests that the dialectical training procedure is robust to this imbalance, possibly because the TAS format provides a uniform reasoning structure that applies to all three classes.

**Why the FinQA/Spider choice over alternatives.** The paper does not explicitly argue for FinQA and Spider over other retrieval-augmented datasets, but the implicit logic is clear: both datasets have (a) clean gold evidence annotations that enable reliable comparison with retrieved evidence, (b) gold answers that enable correctness checking, (c) multi-step reasoning requirements that make internal failures plausible (the agent can go wrong in non-trivial ways even with all evidence present), and (d) real-world complexity that makes external failures plausible (retrieval quality varies). Simpler QA datasets where retrieval is trivial or reasoning is single-step would not produce the diagnostic failure distribution needed for AOA training.

#### Dialectical Synthesis: Generating TAS Trajectories (Section 4.3)

Given a labeled failure case from Stage 1 (question, retrieved evidence, predicted answer, generated code, ground-truth attribution label), the next stage produces training trajectories that demonstrate *how* to reason from role-congruent bias to evidence-grounded conclusion. This is the core intellectual mechanism that distinguishes ReTAS from prior reflection approaches.

**The Thesis-Antithesis-Synthesis (TAS) format.** Each trajectory is a structured reasoning trace with three explicitly tagged segments, enclosed in `<thinking>` tags, followed by two output fields:

```
<thinking>
<thesis> [Role-Dependent Bias/Instinct] </thesis>
<antithesis> [Evidence Verification] </antithesis>
<synthesis> [Objective Convergence] </synthesis>
</thinking>
[Attribution] FalseExt | FalseInt | True
[Action] Search(new_query) | Revise(code) | Confirm()
```

The three internal stages serve distinct cognitive functions:

- **Thesis:** The agent's *initial, role-congruent reaction*. For an Actor (executor), this is a defensive response that externalizes blame — e.g., claiming the context is missing, the instructions were vague, or the retrieval system failed. For a Reviewer (observer), this is a critical response that internalizes blame — e.g., claiming the executor made a logic error, hallucinated, or failed to check available evidence. The key property of this stage is that it records the *bias* — the instinctive, evidence-unchecked reaction that the role prompts — without suppressing it. This is deliberate: by making the bias *explicit and tagged*, the model learns to recognize it as a distinct cognitive step rather than conflating it with the final conclusion.

- **Antithesis:** The model *pauses and checks the evidence*. The paper specifies that this stage must begin with a pivot marker — "Wait...", "Hold on...", or "But let me check context..." — to signal a shift from role-driven reaction to evidence-driven verification. The agent re-examines the retrieved evidence `$E$` in light of the question, testing whether the initial Thesis is actually supported. For an Actor: "Wait, let me scan the text again — is the data actually missing, or did I overlook it?" For a Reviewer: "Wait, checking the context — does the evidence actually support the executor's reasoning, or is the critical information absent?" This stage embodies the Fichtean dialectical principle that a thesis must be confronted by its negation — not to produce an intermediate compromise, but to reveal the blind spots that neither the thesis nor the antithesis alone could see.

- **Synthesis:** The agent resolves the conflict between Thesis and Antithesis by grounding its conclusion in *objective evidence*. The Synthesis output is twofold: an **attribution label** (`FalseExt`, `FalseInt`, or `True`) that must match the ground-truth label from Stage 1, and a **corrective action** chosen from three options:
  - `Search(new_query)`: for `FalseExt` cases — specify what missing information needs to be retrieved.
  - `Revise(code)`: for `FalseInt` cases — indicate that the reasoning logic needs to be corrected.
  - `Confirm()`: for `True` cases — the answer is already correct, no action needed.

**Dual-trajectory generation with convergence constraint.** For *every* question, the synthesis engine (GPT-5.1) generates **two complete trajectories**, each starting from a different role:

- **Defensive Actor trajectory:** The Thesis expresses an executor's self-serving bias (blaming external factors). The Antithesis checks whether the evidence actually supports that claim. The Synthesis converges to the ground-truth attribution.

- **Critical Reviewer trajectory:** The Thesis expresses an observer's fundamental attribution error (blaming internal factors). The Antithesis checks whether the evidence actually supports *that* claim. The Synthesis converges to the *same* ground-truth attribution as the Actor trajectory.

This dual-trajectory design is crucial and non-obvious. The paper could have generated trajectories from only one perspective and trained the model to always produce the correct attribution regardless of role. But that would not teach the model *why* the role-congruent reaction is wrong — it would merely teach the model to suppress its initial instinct. By generating symmetric trajectories that start from opposite biases but converge to the same conclusion, the training data demonstrates that the evidence, not the role, determines the correct attribution. The model sees that both "the context is missing" (Actor thesis) and "the executor made an error" (Reviewer thesis) can be *equally wrong* when they contradict the evidence, and that the correct conclusion is reached not by choosing one perspective over the other, but by *checking both against the facts*.

**Why the teacher model is GPT-5.1.** The paper uses a strong closed-source model as the trajectory generator rather than the Qwen3-4B backbone that will later be trained. This is a standard distillation-like approach: the teacher's superior reasoning capability produces higher-quality TAS traces (more faithful to the evidence, better at identifying blind spots) than the backbone could produce on its own. The paper does not ablate the choice of teacher model, so it is unknown whether a weaker teacher would produce trajectories that still yield effective training.

**Design choice: pre-synthesis recording of bias vs. direct correction.** A simpler alternative would be to train the model to produce the correct attribution directly, without the intermediate Thesis and Antithesis stages. The paper argues (implicitly, through the experimental results) that this would not work because the model would not learn to distinguish its role-induced reflex from its evidence-grounded conclusion. The Thesis and Antithesis stages serve as *explicit disagreement markers* — they create a training signal that says "your first thought may be wrong; here is how to check it." The GRPO training then reinforces the *Synthesis* as the component that should drive the final attribution and action, while the Thesis and Antithesis remain as documentation of the reasoning path. This is analogous to how chain-of-thought prompting (Wei et al., 2022) includes intermediate steps — but unlike standard CoT where the intermediate steps are the *correct* reasoning path, TAS includes the *potentially incorrect* initial reaction as a distinct, tagged stage.

#### Supervised Fine-Tuning Phase (Section 4.4)

The first training phase takes the Qwen3-4B-Instruct-2507 backbone and fine-tunes it on the full set of synthesized TAS trajectories using standard language modeling.

**Objective.** Standard next-token prediction with cross-entropy loss on the TAS-formatted outputs. The model is trained to produce the entire structured response — `<thinking>`, `<thesis>`, `<antithesis>`, `<synthesis>`, `[Attribution]`, `[Action]` — given the case record as input.

**Training configuration.** The paper reports: "3 epochs with a learning rate of 5e-6." No additional hyperparameters (batch size, optimizer, sequence length for this phase) are specified. Training takes "approximately 15 minutes per epoch" on dual NVIDIA H200 GPUs.

**What SFT teaches.** This phase teaches the model *format adherence* and *action vocabulary*. After SFT, the model can produce syntactically correct TAS responses with the proper XML-like tags and the three output classes (`FalseExt`, `FalseInt`, `True`) and three action types (`Search`, `Revise`, `Confirm`). The model has seen examples of role-congruent bias being recorded and then corrected through evidence verification.

**What SFT does NOT teach.** The ablation in Table 4 shows that SFT alone (the "w/o GRPO" row) achieves an attribution accuracy of 67.7% on FinQA-TAS with a V-AOA of 12.4% — an improvement over the 22.7% V-AOA of the backbone with dual-view prompting (Table 5), but substantially worse than the full ReTAS model (71.2% accuracy, 5.4% V-AOA). The paper's interpretation is that SFT teaches the model *what* the TAS format looks like, but not *why* to follow it — the model can still default to role-congruent attributions when the evidence is genuinely ambiguous because it has not been reinforced for prioritizing evidence over role. This is the gap that the GRPO phase closes.

---

#### Reinforcement Alignment Phase: GRPO Training (Section 4.4)

The second training phase uses Group Relative Policy Optimization (GRPO) to transform the TAS format from a prompted template into a learned reasoning policy — a behavioral habit that the model follows even when role cues would otherwise pull it toward biased attributions.

**What GRPO is.** GRPO (Guo et al., 2025) is a reinforcement learning algorithm for language models that operates on *groups* of rollouts. For each input, the current model policy generates `$G$` different output sequences (a "group"), each of which is scored by a reward function. The model is then updated to increase the probability of the sequences that scored higher than the group average, and decrease the probability of sequences that scored lower. This group-relative comparison eliminates the need for a separately trained critic model (as in PPO), because the baseline for each rollout is derived from its peers rather than from a learned value function.

The paper configures GRPO with:

- **Group size `$G = 8$`:** Eight trajectories are rolled out for each input.
- **750 optimization steps** run independently on FinQA-TAS and Spider-TAS datasets. Given the training set sizes (6,251 for FinQA-TAS, 7,000 for Spider-TAS) and a batch size of 1 with gradient accumulation steps of 16, this corresponds to "about 1.9 epochs on FinQA-TAS and 1.7 epochs on Spider-TAS."
- **Maximum sequence length:** 2,048 tokens.
- **Hardware:** Dual NVIDIA H200 GPUs, requiring 9 hours for the GRPO stage.

**The composite reward function.** Each rollout is scored by a weighted sum of three reward components:

$$R(\cdot) = \alpha R_1(\cdot) + \beta R_2(\cdot) + \gamma R_3(\cdot)$$

where `$\alpha = 1$`, `$\beta = 2$`, and `$\gamma = 4$` are the reward coefficients, and `$R_1$`, `$R_2$`, and `$R_3$` are the three reward functions applied to the rollout.

**What it computes:** The total reward `$R(\cdot)$` is a scalar that evaluates a single generated rollout (a complete TAS-formatted response) along three dimensions. Each component reward `$R_i$` contributes a score that reflects how well the rollout satisfies a specific desideratum; the coefficients determine their relative importance. The model is trained to maximize this scalar across rollouts using GRPO's group-relative optimization.

**Why this form:** The composite reward decomposes the training objective into three independently verifiable signals rather than relying on a single holistic quality metric. This allows the training to balance competing objectives — a rollout could have perfect format (`$R_1$`) but wrong attribution (`$R_2$`), and the reward function penalizes the attribution error more heavily (via `$\beta = 2$`) while still giving partial credit for format adherence. The relative weights `$\alpha:\beta:\gamma = 1:2:4$` encode a priority ordering: answer correctness is most important, attribution correctness is second, and format adherence is third. The paper reports (Table 7) that varying the weight ratio among non-zero values has "a modest impact on performance," but removing any single component causes "a notable degradation," confirming that all three are indispensable.

**Reward component `$R_1$`: Format correctness.**

This is a binary or near-binary reward for producing the syntactically correct TAS format. The paper describes it as "reward[ing] producing the correct TAS format." Concretely, this likely checks that the output contains properly structured `<thesis>`, `<antithesis>`, and `<synthesis>` tags within `<thinking>` tags, followed by valid `[Attribution]` and `[Action]` fields with legal values. The reward ensures the model does not drift from the structured reasoning template during RL optimization — without it, the model might learn to produce correct attributions in free-form text that would not generalize to the structured multi-agent setting.

**Reward component `$R_2$`: Attribution correctness.**

This rewards the model when the `[Attribution]` label in its output matches the ground-truth label (`FalseExt`, `FalseInt`, or `True`) from the data generation pipeline. This is the core debiasing signal: it directly penalizes the model for producing a role-congruent but factually incorrect attribution. If the ground truth is `FalseExt` (missing evidence) and the model, simulating an Actor, correctly attributes to external factors despite its Thesis being defensive, `$R_2$` is high. If the model instead produces `FalseInt` (blaming its own reasoning), `$R_2$` is low.

**Why `$R_2$` is critical.** The ablation in Table 4 demonstrates that removing `$R_2$` (the "w/o R2" row) causes V-AOA to triple from 5.4% to 16.8% on FinQA-TAS, while attribution accuracy drops from 71.2% to 65.5%. This confirms that "correctness-based rewards alone fail to disentangle reasoning from role identity" (Section 5.2). Without `$R_2$`, the model optimizes for answer correctness (`$R_3$`) and format (`$R_1$``) but can achieve those by generating correct answers *and* role-congruent (but incorrect) attributions — the attribution becomes a decorative element that tracks the role rather than the evidence.

**Reward component `$R_3$`: Answer correctness.**

This rewards the model for producing the correct final answer. In the case of `True` examples, the correct answer is the one from the data generation pipeline. For `FalseExt` and `FalseInt` examples, the model is not expected to produce the correct answer (since the evidence is missing or its reasoning was flawed), but `$R_3$` still provides a signal: if the model *does* produce the correct answer on a `FalseExt` case (perhaps by guessing or by retrieving implicit knowledge), that is undesirable because it masks the external failure. Conversely, if the model produces the correct answer on a `FalseInt` case, that means it has diagnosed and corrected its own reasoning error — exactly the desired behavior.

Why `$R_3$` is needed. The ablation shows that removing `$R_3$` (the "w/o R3" row) causes F1 on FinQA-TAS to drop from 72.1% to 68.3%. The paper explains that without `$R_3$`, the model optimizes for correct attribution but may lose its ability to actually solve the downstream task. This is a concrete demonstration of a common alignment challenge: optimizing for the auxiliary objective (attribution accuracy) can come at the expense of the primary objective (task performance) if they are not jointly optimized.

**Why GRPO rather than PPO or DPO.** The paper does not provide an explicit comparison with alternative RL algorithms, but the choice of GRPO is consistent with the design philosophy. PPO requires training a separate critic model (a value function estimator), which adds computational overhead and introduces the risk that the critic's errors propagate into the policy update. DPO (Direct Preference Optimization) operates on pairwise preference data and would require generating preference pairs — but in this setting, the "preferred" response is always the one with correct attribution and correct answer, which is already the training target. GRPO's group-relative mechanism is well-suited to multi-objective optimization because the group of 8 rollouts naturally produces variation along all three reward dimensions, and the relative comparison encourages the model to shift probability mass toward rollouts that score well on all three simultaneously.

**Training procedure detail.** The paper reports "a batch size of 1, gradient accumulation steps of 16, and a group generation size of 8 trajectories." This means for each optimization step, the model processes one input, generates 8 rollouts, computes rewards for each, and accumulates gradients over 16 such inputs before updating. The effective batch size is 16 inputs × 8 rollouts = 128 trajectories per update. This is a relatively small effective batch size, which may contribute to training instability — though the paper does not report instability issues.

**Relationship between SFT and GRPO.** The two phases are sequential and complementary. SFT provides a stable starting policy that already produces syntactically correct TAS outputs (so GRPO does not need to learn the format from scratch) and has a non-trivial attribution accuracy (67.7% on FinQA-TAS per the ablation). GRPO then refines this policy by rewarding the specific behaviors that SFT cannot enforce: perspective-invariant attribution (`$R_2$`) and correct downstream answers (`$R_3$`). The paper's central claim — that "GRPO is critical for learning the dialectical policy" — is validated by the gap between the SFT-only baseline (67.7% accuracy, 12.4% V-AOA) and the full ReTAS model (71.2% accuracy, 5.4% V-AOA) in Table 4.

---

#### Summary of Design Choices and Their Justifications

- **Retrieval-augmented tasks as the training substrate** over open-ended generation: the clean decomposition into retrieval vs. reasoning stages provides verifiable ground-truth attribution labels (`FalseExt` / `FalseInt` / `True`) that are impossible to obtain in domains where failure causes are genuinely ambiguous.

- **GPT-5.1 as the trajectory synthesis teacher** over using the backbone model itself: the teacher's superior reasoning produces higher-quality TAS traces that better demonstrate evidence-grounded convergence; this is a standard distillation approach trading off teacher inference cost against training data quality.

- **Dual-trajectory generation with convergence constraint** over single-perspective trajectories: by requiring both Actor and Reviewer trajectories to arrive at the same attribution, the training data teaches that the evidence, not the role, determines the correct conclusion. Single-perspective data would only teach the model to produce correct attributions from one role, without demonstrating that the same reasoning process works equally from the opposite role.

- **Explicit Thesis and Antithesis stages** over direct correct attribution: recording the role-congruent bias as a distinct, tagged stage teaches the model to recognize its instinctive reaction as potentially incorrect, rather than conflating it with the final conclusion. This is what enables the model to override role-induced bias — it learns that "my first thought (Thesis) may be wrong, and checking against evidence (Antithesis) will tell me whether it is."

- **GRPO with composite reward** over SFT-only or PPO: SFT teaches format but not perspective invariance; PPO requires a separately trained critic that adds complexity. GRPO's group-relative optimization provides a natural mechanism for multi-objective optimization because the within-group comparison automatically calibrates the baseline for each reward component.

- **Reward coefficient ratio `$\alpha:\beta:\gamma = 1:2:4$`:** Attribution correctness is weighted higher than format because it is the primary debiasing objective; answer correctness is weighted highest because the ultimate goal is task performance, not merely correct attribution. The paper acknowledges that this ratio was adopted "without extensive tuning" (Appendix A), suggesting that the system is robust to moderate weight variations (confirmed by the sensitivity analysis in Table 7 where ratios of 1:1:1, 1:8:1, and 1:1:8 all achieve within ~1-2 F1 points of the chosen 1:2:4).

- **Qwen3-4B as the backbone** over larger models: the paper deliberately chooses a small, open-weights model to demonstrate that dialectical alignment can compensate for model scale — "it enables full fine-tuning at low cost while remaining highly deployable." The results showing ReTAS (4B) matching or exceeding QwQ-32B on attribution metrics (Table 3) validate this choice as a proof-of-concept that the method, not the model size, drives the debiasing effect.

## 4. Key Insights and Innovations

### Innovation 1: Actor-Observer Asymmetry as a Diagnosable, Systematic Failure Mode of Role-Playing Agents

This is not merely the observation that agents disagree. It is the identification of a **specific, named, and psychologically grounded cognitive bias** that explains *how* and *why* role-based multi-agent systems produce inconsistent failure attributions. The paper does not invent AOA — it imports the concept from social psychology (Heider, 1958; Jones and Nisbett, 1972) — but the intellectual move is to argue that this bias has been silently inherited by LLMs through their training on human discourse and that it manifests in precisely the structured, predictable way that attribution theory would predict: actors externalize, observers internalize.

What makes this a genuine innovation rather than an obvious analogy is the **rigor of the diagnostic setup**. Prior work had noted that LLMs exhibit biases (Tjuatja et al., 2024; Gallegos et al., 2024) and that multi-agent systems sometimes fail to converge (Cemri et al., 2025). But these observations treated bias as generic noise — an undifferentiated "misalignment" to be reduced. The paper's contribution is to show that the bias has a **specific directional structure** that depends on the agent's assigned role, and that this structure can be **quantitatively measured** by swapping perspectives while holding all other context constant. The AFB benchmark (Section 3, Table 2) is not just a dataset — it is a **counterfactual probe** that isolates the perspective variable. The metric "Flip" — the percentage of cases where attribution changes solely due to role swap — operationalizes AOA as a measurable quantity, distinct from overall accuracy or calibration.

This is a **fundamental shift** in how the field should think about agent reliability. The dominant paradigm has been that role specialization improves reliability by enabling self-reflection and mutual auditing (Shinn et al., 2023; Qian et al., 2024). The paper demonstrates that this paradigm contains an internal contradiction: the very mechanism that enables auditing (assigning distinct perspectives) also introduces systematic, perspective-dependent distortions in causal reasoning. This reframes the problem from "how do we make agents better at self-critique?" to "how do we design reasoning processes that are invariant to the agent's perspective?" — a harder and more fundamental question.

The evidence anchoring this claim is Table 2. GPT-5.1, the strongest model tested, exhibits only 5% V-AOA on Human-Agent traces — but simultaneously shows a 94% internal attribution rate, regardless of perspective. This is not AOA in the classic sense; it is a different failure mode where the model has over-learned self-criticism. The paper's framing reveals that **perspective-dependence and unconditional attribution bias are two manifestations of the same underlying problem**: the model lacks a mechanism to ground causal reasoning in evidence rather than in role identity. This is a more precise diagnosis than prior claims that "LLMs are biased."

### Innovation 2: The Thesis-Antithesis-Synthesis (TAS) Process as a General Mechanism for Perspective-Invariant Reasoning

The core conceptual contribution of the paper is the claim that **structured dialectical reasoning — recording the role-congruent bias, confronting it with evidence, and synthesizing an evidence-grounded conclusion — is the correct algorithmic response to perspective-dependent cognitive bias**. This is not a prompting trick. It is a specific reasoning architecture that the paper argues generalizes across tasks, roles, and model scales because it addresses the **structural cause** of AOA rather than its symptoms.

To appreciate why this is novel, consider what the field was doing before. The dominant approaches to debiasing reasoning were:
- **Instruction-level interventions:** prompting models to "be objective," "consider both sides," or "avoid bias." The paper explicitly argues these fail due to "role inertia" — agents defensively justify their position rather than genuinely re-evaluate evidence (Section 1).
- **Multi-perspective aggregation:** simply collecting outputs from multiple roles and aggregating them (e.g., majority voting, debate). The Dual View baselines in Table 3 show this can *worsen* attribution consistency (GLM-4.6: 52.7% Flip on FinQA-TAS) because adding opposing views without a synthesis mechanism amplifies conflict rather than resolving it.
- **Calibration and fairness training:** general-purpose debiasing (e.g., RLHF for harmlessness) that operates on individual outputs without addressing the *relationship* between outputs from different perspectives.

TAS differs from all of these in a fundamental way: it does not suppress bias. It **surfaces bias as an explicit, tagged cognitive stage**, then subjects it to verification. The Thesis stage exists precisely so that the model can record its role-congruent instinct — "I cannot answer this because the context is incomplete" (Actor) or "The executor's answer is completely wrong" (Reviewer) — rather than having that instinct silently shape the final conclusion. The Antithesis stage then *checks* whether the instinct matches the evidence. The Synthesis stage *overrides* the instinct if it does not.

This matters because it addresses the root cause of AOA: the model's role activates a learned cognitive schema (self-serving vs. other-blaming) that pre-empts evidence evaluation. By making the schema explicit, TAS enables the model to treat it as a hypothesis to be tested rather than as a conclusion to be defended. The analogy is to cognitive behavioral therapy, where patients learn to recognize automatic thoughts ("I failed because I'm incompetent") as mental events that can be examined and corrected, rather than as objective truths.

The claim that TAS is a **general mechanism** rather than a task-specific hack is supported by the cross-domain generalization results. The ReTAS model trained on FinQA-TAS (financial reasoning) transfers to the completely unseen AFB domains (coding, customer service, safety alignment, creative writing) — reducing V-AOA on Agent-Agent traces from the Qwen3-4B baseline of 29 to 11 (Figure 7), and significantly reducing human-favoring bias on Human-Agent traces (Figure 8). This generalization would be unlikely if TAS were simply learning patterns specific to financial data. Instead, the model appears to learn a domain-agnostic reasoning strategy: "record my first reaction, check it against the evidence, and synthesize a conclusion that the evidence supports."

The comparison to Chain-of-Thought (Wei et al., 2022) is instructive. Standard CoT records the *correct* reasoning path — it shows the model how to arrive at the right answer. TAS additionally records the *potentially incorrect* initial reaction and the verification step that corrects it. This means TAS teaches not just *what* to think, but *how to think about one's own thinking* — a metacognitive skill that CoT does not explicitly train. The paper does not make this comparison directly, but it's a natural reading of the architectural difference.

### Innovation 3: Reinforcement Learning as the Mechanism for Internalizing Dialectical Reasoning, Not Just Prompting It

The paper makes a strong empirical claim that is also a conceptual one: **prompting a model to think dialectically is not the same as training it to internalize dialectical reasoning as a policy**. The gap between the zero-shot TAS prompted baseline (+TAS in Table 5: 14.1% V-AOA on FinQA-TAS) and the fully trained ReTAS model (5.4% V-AOA) is not merely a performance improvement — it represents a **qualitative difference in the kind of capability** the model possesses.

Before this paper, the standard approach to improving LLM reasoning was prompt engineering — design a better template, and the model follows it. The TAS format could have been presented as just another prompt template: "here's a structured way to think about failure attribution." But the paper demonstrates that this is insufficient. The SFT-only ablation (67.7% accuracy, 12.4% V-AOA; Table 4) shows that even after seeing thousands of TAS examples and learning to produce the format correctly, the model still exhibits significant perspective-dependent bias. The model knows *what* the TAS format looks like; it does not know *why* to follow it when role cues pull toward a different conclusion.

GRPO-based reinforcement learning bridges this gap. The innovation is not the RL algorithm itself (GRPO is from Guo et al., 2025), but the **training objective design**: the composite reward that jointly optimizes format adherence, attribution correctness, and answer correctness. This multi-objective design forces the model to internalize the TAS process as the *means* to achieving correct attributions and correct answers, not as an arbitrary formatting requirement. The model learns that producing an evidence-grounded Synthesis is instrumentally valuable — it increases expected reward — while producing a role-congruent but evidence-incorrect Thesis (and then failing to correct it in Synthesis) is penalized.

The conceptual significance of this goes beyond ReTAS. It suggests a general principle for debiasing LLMs: **prompting addresses surface-level behavior; RL on structured reasoning traces addresses the underlying policy**. If this principle generalizes, it has implications for a wide range of cognitive biases beyond AOA — confirmation bias, anchoring, framing effects — all of which could potentially be addressed by training models to record their instinctive (biased) reaction, check it against evidence, and synthesize a corrected conclusion, with RL reinforcing the synthesis step.

The reward component ablation (Table 4) is the key evidence for this claim. Removing R2 (attribution reward) causes V-AOA to triple (5.4% → 16.8%), demonstrating that correctness rewards alone do not disentangle reasoning from role identity. The model can achieve high answer scores while still producing role-congruent attributions — it learns to "look correct on the surface while thinking incorrectly underneath," in effect. The composite reward is necessary because the three objectives (format, attribution, task performance) must be optimized jointly; optimizing any subset creates perverse incentives.

### Innovation 4: The Ambiguous Failure Benchmark as a New Type of Diagnostic Instrument for Cognitive Bias in LLMs

The AFB is more than a dataset — it is a **counterfactual experimental design** that isolates the effect of perspective on causal reasoning. This represents a methodological innovation in how the field evaluates cognitive biases in language models.

Prior bias evaluation datasets (e.g., BBQ, Winogender, StereoSet) typically measure whether a model's outputs reflect social stereotypes or unfair associations. These are **static bias measurements**: given an input, does the model produce a biased output? AFB measures something different: **perspective-dependent bias**. The same input is presented twice, varying only the system prompt that specifies the agent's role (Actor vs. Observer). Any difference in attribution is, by construction, due to the perspective variable — because all other context is held identical.

This is a fundamentally different type of measurement because it captures a **relational** property of the model's reasoning rather than an **absolute** property. A model could score perfectly on traditional bias benchmarks (producing unbiased outputs in each role individually) and still exhibit high AOA if its attributions systematically shift under role swaps. In fact, the paper's results with GPT-5.1 suggest something close to this: the model is consistent (only 5% V-AOA) but consistently biased in a different way (94% internal attribution). Both patterns are invisible to standard bias benchmarks that evaluate single outputs.

The construction of AFB is itself an intellectual contribution. The paper deliberately creates scenarios with "inherently ambiguous" failures where "a single failure signature plausibly supports contradictory root causes" (Section 3). This is not a bug — it is the feature that makes AOA measurable. If failures had obvious, deterministic causes, any competent model would make the same attribution regardless of role, and AOA would be unobservable. The epistemic uncertainty in AFB creates the conditions under which cognitive biases *do their work* — when the evidence underdetermines the conclusion, agents fall back on learned heuristics (self-serving bias, fundamental attribution error) to resolve the ambiguity. This mirrors real-world agent deployments, where genuinely ambiguous failures are common and role-induced bias has the most room to cause damage.

The 10-domain coverage of AFB (Table 1) — spanning coding, customer service, RAG systems, safety alignment, planning, creative writing, data analysis, translation, math logic, and professional communication — demonstrates that AOA is not domain-specific. This breadth strengthens the paper's central claim that role-induced attribution bias is a **fundamental property of role-conditioned reasoning**, not a quirk of particular task formulations. The fact that ReTAS transfers from FinQA/Spider training to AFB evaluation (Figures 7-8) further validates AFB as a diagnostic instrument: it measures a generalizable capability (perspective-invariant attribution) rather than domain-specific knowledge.

The methodological precedent this sets is significant. Future work on cognitive biases in LLMs could adopt the same counterfactual design — varying perspective, identity, or framing while holding evidence constant — to isolate specific bias mechanisms. The paper demonstrates that this approach can reveal structured, predictable bias patterns that would be invisible to single-output evaluation, opening a new dimension of LLM auditing.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The paper constructs two failure attribution datasets: **FinQA-TAS** (based on FinQA, Chen et al., 2021 — a financial numerical reasoning benchmark) with 6,251 training, 883 dev, and 1,147 test samples; and **Spider-TAS** (based on Spider, Yu et al., 2018 — a cross-domain text-to-SQL benchmark) with 7,000 training and 1,034 dev samples. Both are generated via the attribution data pipeline described in Section 4.2, where each example is labeled as `FalseExt`, `FalseInt`, or `True`. For cross-domain generalization evaluation, the paper uses the **Ambiguous Failure Benchmark (AFB)**, a diagnostic dataset of 200 interaction traces (100 Human-Agent, 100 Agent-Agent) spanning 10 domains (Table 1), where attribution ambiguity is deliberately maximized to expose perspective-dependent bias. For multi-turn dynamic evaluation, the paper uses **SALES ARENA**, a custom negotiation environment pairing a Qwen3-4B Seller against a QwQ-32B Buyer with four items, budget constraints, and a maximum of 8 turns per item.

- **Base model(s).** The ReTAS model is built on **Qwen3-4B-Instruct-2507** (Yang et al., 2025), a 4B-parameter open-weights instruction-tuned model. The paper explicitly chooses a small backbone to demonstrate that dialectical alignment can compensate for model scale — "it enables full fine-tuning at low cost while remaining highly deployable" (Section 5.3). For baselines, the paper evaluates a range of larger models including **GPT-5.1** (OpenAI, 2025; closed-source), **DeepSeek-V3.2** (DeepSeek-AI, 2025; 671B), **QwQ-32B** (Qwen, 2024; 32B), **Qwen3-30B-A3B** (Yang et al., 2025; 30B with 3B activated), and **GLM-4.6** (Zhipu, 2025; 9B). The data generation pipeline in Section 4.2 uses **Qwen-2.5-7B** (Yang et al., 2024b) as the backbone for retrieval and program synthesis. The dialectical synthesis teacher model is **GPT-5.1** (Section 4.3).

- **Metrics.** Four primary metrics are reported. **Attribution Accuracy (Acc.%)** measures the percentage of cases where the model's predicted attribution label (`FalseExt`, `FalseInt`, or `True`) matches the ground-truth label from the data generation pipeline. **Flip (%)** measures the percentage of cases where the model's attribution changes solely due to a role swap (Actor vs. Observer) — computed by presenting the same case twice with different system prompts and counting disagreements. **V-AOA (Vanilla Actor-Observer Asymmetry, %)** specifically quantifies the classic bias pattern where the Actor attributes to external factors while the Observer attributes to internal factors (`y_act = Ext, y_obs = Int`). **F1 Score** measures downstream task performance — the quality of the final answer produced by the agent after attribution and corrective action, using standard precision/recall balancing appropriate to the task. For the SALES ARENA experiments, metrics include **Total Profit ($)**, **Average Profit per Product ($)**, **Average Number of Turns**, and **Success Rate**.

- **Baselines.** The paper evaluates against three tiers of baselines (Table 3). **(1) Standard Prompting**: five state-of-the-art models (GPT-5.1, DeepSeek-V3.2, QwQ-32B, Qwen3-30B-A3B, GLM-4.6) generate answers directly from documents in a zero-shot setting — no reflection or attribution is performed, so only F1 is reported. **(2) Single View Reflection**: the model diagnoses the failure and proposes a correction given the case record, without explicit role assignment. Three models are evaluated: QwQ-32B, Qwen3-30B-A3B, and GLM-4.6. **(3) Dual View Reflection**: the model is explicitly prompted as either a defensive Executor or a critical Observer to probe role-induced bias. The same three models are evaluated. Additionally, in ablation studies (Table 5), two more baselines appear: **Qwen3-4B + Dual View** (adding dual-perspective reflection to the backbone) and **Qwen3-4B + TAS** (applying the TAS inference template in a zero-shot manner without fine-tuning).

- **Generation budget / compute accounting.** The paper does not measure compute in FLOPs or generation budgets in a standardized way for the main experiments, unlike scaling-law style papers. Instead, the comparison is controlled by model size: ReTAS (4B) is compared against models ranging from 9B to 671B parameters, with the implicit claim that ReTAS's performance is achieved with substantially less compute per inference. Training compute is reported qualitatively: SFT takes "approximately 15 minutes per epoch" on dual NVIDIA H200 GPUs, and GRPO requires "9 hours" for 750 optimization steps with a maximum sequence length of 2,048 tokens (Appendix A). The paper does not provide FLOP counts or attempt FLOPs-matched comparisons between ReTAS and larger baselines.

- **Cross-validation / statistical protocol.** The paper does not report k-fold cross-validation for the main FinQA-TAS and Spider-TAS evaluations. The FinQA-TAS evaluation uses a standard train/dev/test split: training on the FinQA training set (6,251 samples), validation on the dev set (883 samples) for checkpoint selection, and testing on the held-out test set (1,147 samples). Spider-TAS uses the training set (7,000 samples) for training and the dev set (1,034 samples) for evaluation, "following standard practice among prior text-to-SQL work" since Spider does not publicly release a separate test split (Appendix A). The paper does not report confidence intervals, standard deviations, or statistical significance tests for any of the reported metrics. For the AFB generalization evaluation (Figures 7-8), the ReTAS model fine-tuned on FinQA-TAS is evaluated on the full 200-trace AFB dataset, but no cross-validation is applied.

### Main Quantitative Results

#### Attribution Consistency and Bias Mitigation on FinQA-TAS and Spider-TAS (Table 3)

The headline result is that **ReTAS (4B) achieves 71.2% attribution accuracy on FinQA-TAS with only 5.4% V-AOA, outperforming all open-weights baselines regardless of scale, including QwQ-32B (32B, which has 8× more parameters but reaches only 54.9% accuracy with 14.7% V-AOA under Dual View reflection).**

On **FinQA-TAS**, ReTAS's 71.2% attribution accuracy compares against the best Dual View baseline (QwQ-32B at 54.9%) — a relative improvement of approximately 30%. The Flip rate (12.4%) is less than one-quarter the rate of GLM-4.6 under Dual View (52.7%), and the V-AOA rate (5.4%) is roughly one-third the best Dual View baseline (QwQ-32B at 14.7%). In downstream task performance, ReTAS achieves an F1 of 72.1%, which is within 4.8 percentage points of GPT-5.1's prompting-only F1 (76.9%) and within 3.9 points of DeepSeek-V3.2 (76.0%) — despite ReTAS having 4B parameters compared to these models' orders-of-magnitude larger scales.

On **Spider-TAS**, ReTAS achieves 61.4% attribution accuracy with 21.9% Flip and 10.2% V-AOA. The comparison with Dual View baselines is even starker: Qwen3-30B-A3B achieves higher attribution accuracy than QwQ-32B (55.6% vs. 34.8%), but its V-AOA is competitive (10.4% vs. 24.2%). GLM-4.6 under Dual View collapses to 34.2% accuracy with 32.3% Flip and 18.3% V-AOA — performing worse than its Single View variant (35.1% accuracy). ReTAS's F1 of 63.5% on Spider-TAS exceeds the best prompting baseline (DeepSeek-V3.2 at 64.0% F1) by a statistically negligible margin, but notably surpasses all other prompting baselines including GPT-5.1 (61.5%) and the much larger QwQ-32B (58.2%).

A critical pattern across both datasets: **Dual View reflection degrades performance relative to Single View for some models**. On FinQA-TAS, GLM-4.6 drops from 43.7% accuracy (Single View) to 43.1% (Dual View), while its Flip explodes to 52.7%. On Spider-TAS, QwQ-32B's accuracy rises marginally from 33.8% (Single View) to 34.8% (Dual View), but at the cost of a 26.9% Flip rate. This validates the paper's claim that "structural role assignment alone is insufficient to overcome cognitive bias" and that "mere role diversification can exacerbate conflict when agents remain entrenched in role-based priors" (Section 5.1).

The comparison between ReTAS and proprietary models is nuanced. GPT-5.1 and DeepSeek-V3.2 achieve higher F1 scores (76.9% and 76.0% on FinQA-TAS, 61.5% and 64.0% on Spider-TAS), but these are prompting-only baselines — they do not attempt attribution and thus have no Acc, Flip, or V-AOA measurements. The paper treats these as upper bounds on task performance rather than direct competitors on attribution quality. The claimed achievement is that "ReTAS significantly narrows the gap, demonstrating that calibrating the underlying cognitive stance is a potent lever for enhancing agent reliability independent of model size."

#### Reward Component Ablation (Table 4)

The ablation study isolates the contribution of each reward component and the GRPO mechanism itself.

**Full ReTAS baseline:** 71.2% Acc, 5.4% V-AOA, 72.1% F1 on FinQA-TAS; 61.4% Acc, 10.2% V-AOA, 63.5% F1 on Spider-TAS.

**Removing R2 (attribution-matching reward):** Attribution accuracy drops from 71.2% to 65.5% on FinQA-TAS and from 61.4% to 56.3% on Spider-TAS. More dramatically, V-AOA triples from 5.4% to 16.8% on FinQA-TAS and more than doubles from 10.2% to 27.2% on Spider-TAS. F1 drops modestly (72.1% → 69.5% on FinQA-TAS, 63.5% → 59.2% on Spider-TAS). The paper interprets this as evidence that "correctness-based rewards alone fail to disentangle reasoning from role identity" (Section 5.2): without explicit pressure toward correct attribution, the model optimizes for answer quality while producing role-congruent but wrong attributions.

**Removing R3 (answer correctness reward):** Attribution accuracy also drops, but less severely than removing R2: 71.2% → 68.2% on FinQA-TAS, 61.4% → 58.3% on Spider-TAS. V-AOA rises substantially (5.4% → 15.9% on FinQA-TAS, 10.2% → 22.8% on Spider-TAS), suggesting that answer correctness provides a complementary signal that helps the model stay grounded in task reality. However, F1 drops sharply: 72.1% → 68.3% on FinQA-TAS and 63.5% → 55.6% on Spider-TAS — a 7–8 point decline that the paper attributes to the model losing its ability to actually solve the downstream task when the corrective action signal is absent.

**Removing GRPO entirely (w/o GRPO, SFT only):** The SFT-only model achieves 67.7% accuracy and 12.4% V-AOA on FinQA-TAS — better than the backbone with Dual View prompting (50.0% Acc, 22.7% V-AOA from Table 5), but substantially worse than full ReTAS. On Spider-TAS, the SFT-only degradation is less dramatic (61.2% Acc vs. 61.4% for full ReTAS, 10.6% V-AOA vs. 10.2%), but F1 drops from 63.5% to 60.3%. The asymmetric degradation pattern — GRPO matters more for FinQA-TAS than Spider-TAS — is not discussed, but may reflect the greater complexity of financial reasoning versus the more schema-constrained text-to-SQL task.

**Reward weight sensitivity (Table 7):** The paper reports that varying the weight ratio among R1:R2:R3 (from the default 1:2:4 to 1:1:1, 1:8:1, or 1:1:8) produces F1 scores on FinQA-TAS within a narrow band: 72.1% (1:2:4), 71.7% (1:1:1), 70.9% (1:8:1), 71.3% (1:1:8). This modest variation supports the claim that the system is "robust to moderate weight variations" (Appendix A). However, removing any single component causes larger degradation (69.5%, 68.3%, 69.4% for removing R2, R3, R1 respectively), confirming that all three components are necessary.

#### Impact of Dialectical Alignment: Decomposing Gains from TAS Prompting vs. GRPO Training (Table 5, Figures 4–5)

Table 5 decomposes the improvement over the Qwen3-4B backbone into three stages: the raw backbone, adding Dual View reflection, adding TAS prompting, and full ReTAS training.

**Raw Qwen3-4B (prompting only, no reflection):** 51.2% accuracy, 62.0% F1 on FinQA-TAS; 33.0% accuracy, 54.7% F1 on Spider-TAS. (V-AOA and Flip are not computable for prompting-only baselines since no dual-perspective evaluation is performed.)

**+ Dual View (dual-perspective reflection prompt, no TAS):** Attribution accuracy actually *drops* from 51.2% to 50.0% on FinQA-TAS (though F1 increases slightly to 62.5%), while V-AOA is 22.7%. On Spider-TAS, accuracy improves marginally (33.0% → 35.4%) but V-AOA is 22.2%. The paper interprets the accuracy decline on FinQA-TAS as evidence that "mere role diversification can exacerbate conflict when agents remain entrenched in role-based priors" (Section 5.3).

**+ TAS (zero-shot TAS inference template, no fine-tuning):** This is the critical comparison. Applying the TAS format as a zero-shot prompt improves attribution accuracy from 51.2% to 57.6% on FinQA-TAS (+6.4 points) and from 33.0% to 45.8% on Spider-TAS (+12.8 points). V-AOA drops substantially: 22.7% → 14.1% on FinQA-TAS, 22.2% → 15.6% on Spider-TAS. F1 improves to 67.3% and 59.2%, respectively. This demonstrates that the TAS structure itself provides benefit even without training — but the V-AOA of 14.1% / 15.6% remains substantial.

**Full ReTAS (TAS + SFT + GRPO):** The decisive leap: 71.2% accuracy (+13.6 over TAS-only), 5.4% V-AOA (−8.7 from TAS-only), 72.1% F1 (+4.8) on FinQA-TAS. On Spider-TAS: 61.4% accuracy (+15.6), 10.2% V-AOA (−5.4), 63.5% F1 (+4.3). The paper frames the gap between TAS prompting and ReTAS as representing "the difference between prompting a model to think dialectically and training it to internalize dialectical reasoning as a behavioral habit" (Section 4.4 context).

**Figures 4 and 5** extend this analysis across multiple model scales (4B–32B). Figure 4 shows that applying TAS consistently improves attribution accuracy over Dual View reflection for all tested models. QwQ-32B, the strongest reasoner in the set, benefits from TAS (accuracy increases from the Dual View baseline), suggesting that "AOA is an inherent flaw of role-playing that requires structural intervention regardless of model size" (Section 5.3). Figure 5 shows the complementary result for bias mitigation: TAS reduces V-AOA across all models, but ReTAS (4B) achieves the lowest bias — lower than QwQ-32B with TAS prompting — establishing that "reinforcement learning enables the model to navigate complex evidence chains effectively."

#### Analysis of Evidence Complexity (Figure 6)

Figure 6 stratifies attribution accuracy by the number of evidence pieces required for reasoning (1, 2, 3, 4+). Three patterns emerge:

**TAS-based methods dominate in low-evidence settings (1–2 pieces).** ReTAS (4B) and QwQ+TAS both significantly outperform the standard Dual View models when context is concise. The paper attributes this to "structured dialectical reasoning effectively reduc[ing] misjudgment when the context is concise" (Section 5.4).

**Zero-shot QwQ-32B degrades sharply as complexity increases (3 and 4+ pieces).** The Dual View QwQ-32B performance drops substantially at higher evidence counts, which the paper attributes to "information overload" overwhelming the model's ability to maintain consistent attributions across perspectives.

**ReTAS maintains robustness even at high complexity.** At 3 and 4+ evidence pieces, ReTAS (4B) maintains strong performance and "even outperforms the 32B model." The ReTAS (SFT) variant — SFT only, no GRPO — serves as an internal ablation within this figure: it consistently underperforms full ReTAS at all complexity levels, with the gap widening at 3 and 4+ pieces. This supports the claim that "reinforcement learning enables the model to navigate complex evidence chains effectively" (Section 5.4).

#### Cross-Domain Generalization to AFB (Figures 7–8)

The ReTAS model fine-tuned only on FinQA-TAS is evaluated on the completely unseen AFB benchmark, split into Agent-Agent (Figure 7) and Human-Agent (Figure 8) settings.

**Agent-Agent setting (Figure 7):** The raw Qwen3-4B backbone exhibits high V-AOA (29, visible as the baseline bar). Incorporating TAS as a prompt reduces this, but the fully trained ReTAS model achieves the strongest reduction — "reducing bias to 11." The figure also shows that ReTAS achieves more unified conclusions across different perspectives, with the Actor and Observer attributions converging closer together than for any baseline.

**Human-Agent setting (Figure 8):** This reveals a different bias pattern. Baseline models "tend to side with the user, as reflected in high internal attribution rates that disproportionately assign blame to the agent." The Qwen3-4B backbone (and Qwen3-4B + TAS prompting) exhibits high internal attribution — the model consistently blames the agent regardless of perspective, mirroring the GPT-5.1 behavior observed in the AFB preliminary study (Table 2, where GPT-5.1 showed 94% internal attribution). ReTAS "achieves the lowest internal attribution, distributing responsibility based on evidence rather than favoring the user." The paper frames this as "effectively matching the zero-shot consistency of top-tier models" in terms of reducing perspective-dependent bias, even though ReTAS is only 4B parameters.

Notably, the generalization is imperfect: adding TAS as a zero-shot prompt to Qwen3-4B yields initial improvements, but the fully trained ReTAS delivers "further gains," confirming that the SFT+GRPO training transfers beyond the training distribution.

#### Generalization to Dynamic Negotiation (Table 6, Figure 9)

The SALES ARENA experiments test whether dialectical alignment improves performance in a multi-turn strategic setting where the agent must negotiate prices against a stronger opponent (QwQ-32B Buyer).

**Overall performance (Table 6):** The Reflection_TAS configuration achieves the highest total profit ($168) and highest average profit per product ($2.10), while reducing the average number of turns to 4.81 (compared to 5.08 for Reflection_SOLO and 5.16 for Reflection_Dual). This suggests that TAS enables "a transition from hesitant stalling to decisive, strategic execution" (Section 5.6).

**Counter-intuitive Dual View failure:** Reflection_Dual (adding a Reviewer agent in a debate-style discussion with the Actor) produces the *worst* total profit ($135) — substantially below even the NONE baseline ($157). The paper interprets this as evidence that "in the absence of a synthesis mechanism, tension between the Actor and Observer leads to indecision rather than corrective behavior" (Section 5.6). This is the negotiation-domain analog of the FinQA-TAS finding where Dual View reflection worsened attribution accuracy for GLM-4.6: adding an opposing viewpoint without structured synthesis amplifies conflict.

**Turn-by-turn dynamics (Figure 9):** Reflection_SOLO (self-reflection without dialectical structure) shows a pattern of "gradual capitulation, with the agent increasingly conceding under pressure from the stronger buyer." The offer price curve trends downward across turns. In contrast, TAS exhibits a different pattern: "following an initial probing phase, the agent recalibrates its strategy by synthesizing external resistance with internal profit objectives, thereby maintaining stronger negotiation outcomes." The TAS curve shows a dip followed by recovery, suggesting that the dialectical process enables the agent to learn from the buyer's resistance and adjust its strategy upward rather than simply conceding.

The paper does not report statistical significance for the profit differences, nor does it provide variance estimates across negotiation runs. The results are presented as a single simulation per configuration, which limits the strength of conclusions that can be drawn.

### Ablation Studies and Robustness Checks

- **Attribution-matching reward R2 (Table 4):** Ablating R2 causes V-AOA to triple from 5.4% to 16.8% on FinQA-TAS, and more than double from 10.2% to 27.2% on Spider-TAS. Attribution accuracy drops by 5.7 and 5.1 points, respectively. This is the largest single-component ablation effect on attribution metrics, confirming that explicit reinforcement for correct attribution is necessary — correctness rewards alone (R3) do not disentangle reasoning from role identity. F1 drops modestly (2.6 and 4.3 points), suggesting that attribution and task performance are partially separable but that incorrect attribution indirectly degrades downstream performance by causing wrong corrective actions.

- **Answer-correctness reward R3 (Table 4):** Ablating R3 causes a sharp F1 decline (72.1% → 68.3% on FinQA-TAS, 63.5% → 55.6% on Spider-TAS), while attribution accuracy drops modestly (71.2% → 68.2% and 61.4% → 58.3%). V-AOA rises to 15.9% and 22.8%, indicating that answer correctness provides a grounding signal that prevents the model from drifting into correct attributions that are disconnected from actual task performance. The asymmetric F1 impact across datasets (3.8 vs. 7.9 point drops) is not discussed, but may reflect Spider-TAS's greater sensitivity to the quality of corrective actions.

- **Format reward R1 (Table 7):** Ablating R1 is only reported in the weight sensitivity table (Table 7), not in the main ablation (Table 4). The 0:2:4 configuration (w/o R1) achieves 69.4% F1 on FinQA-TAS, compared to 72.1% for full ReTAS — a 2.7-point drop, smaller than the drops from removing R2 (69.5%) or R3 (68.3%). This suggests format adherence is the least critical of the three components, but still contributes meaningfully.

- **GRPO vs. SFT-only (Table 4):** Removing GRPO (keeping only SFT) causes a 3.5-point accuracy decline and V-AOA increase from 5.4% to 12.4% on FinQA-TAS. On Spider-TAS, the degradation is minimal for attribution metrics (61.2% vs. 61.4% accuracy, 10.6% vs. 10.2% V-AOA) but F1 drops from 63.5% to 60.3%. This asymmetric pattern suggests that GRPO's primary contribution differs by dataset: on FinQA-TAS it primarily improves attribution consistency, while on Spider-TAS it primarily improves task execution.

- **Diabactical structure (TAS vs. Dual View) (Table 5):** The comparison between Qwen3-4B + Dual View and Qwen3-4B + TAS isolates the effect of the TAS format from the effect of multi-perspective input. Adding TAS as a zero-shot prompt improves attribution accuracy by 7.6 points on FinQA-TAS (50.0% → 57.6%) and 10.4 points on Spider-TAS (35.4% → 45.8%), while reducing V-AOA by roughly 8 and 7 points respectively. This is a large effect from a prompt-level intervention alone, supporting the claim that the dialectical structure itself — not just having multiple perspectives — is what drives improvement.

- **Model scale vs. dialectical alignment (Figures 4–5):** TAS prompting improves attribution accuracy and reduces V-AOA across all tested model scales (Qwen3-4B, GLM-4.6, Qwen3-30B-A3B, QwQ-32B). The improvement is not limited to small models — even QwQ-32B, a strong reasoner, benefits from the dialectical structure. This is an important robustness check: if TAS only helped small models, it would suggest it compensates for lack of reasoning capacity. That it helps across scales supports the claim that AOA is a "fundamental property of role-conditioned reasoning" that requires structural intervention regardless of raw model capability.

- **Teacher model choice (not ablated):** The paper does not ablate the choice of GPT-5.1 as the dialectical synthesis teacher. It is unknown whether a weaker teacher (e.g., Qwen3-30B or QwQ-32B) would produce TAS trajectories of sufficient quality to train ReTAS effectively. This is a significant open question, since reliance on a closed-source frontier model as the teacher limits reproducibility and raises the cost of extending the method to new domains.

- **Difficulty estimation / data balance (not ablated):** The paper does not analyze whether ReTAS's performance varies across the three attribution classes (`FalseExt`, `FalseInt`, `True`). Given the class imbalance in Spider-TAS (Table 8: 301 External, 1,391 Internal, 5,308 Correct), it is possible that the model's attribution performance is driven primarily by the dominant `True` class — where attribution is trivially "no failure" — and that performance on the rarer but more diagnostic `FalseExt` and `FalseInt` classes is substantially lower. The paper does not report per-class breakdowns.

- **Single backbone architecture (not ablated):** All ReTAS results use Qwen3-4B-Instruct-2507. The paper does not demonstrate ReTAS training on any other model family (e.g., Llama, Mistral, DeepSeek). The strong TAS prompting results across model scales (Figures 4–5) are suggestive that the method transfers, but whether the full SFT+GRPO pipeline would work equally well on a non-Qwen backbone is untested.

- **Negative result: ReST$^{\text{EM}}$ degradation (not included in this paper):** Unlike some RLHF-oriented papers that report when optimization fails, ReTAS does not include a negative result for an alternative training approach. The paper notes in Appendix A that they "prioritize algorithmic robustness over parameter engineering, adopting the reward weight ratio without extensive tuning," but no alternative training paradigms are compared against GRPO.

### Critical Assessment

The paper makes four central empirical claims: (1) AOA is a systematic, quantifiable bias in role-playing LLM agents, (2) the TAS dialectical structure reduces AOA compared to single-view and dual-view reflection baselines, (3) GRPO-based reinforcement learning is necessary for fully internalizing dialectical reasoning — prompting alone is insufficient, and (4) ReTAS generalizes across domains and tasks, including to dynamic multi-turn settings. Each claim receives varying degrees of empirical support.

**Claim 1 (AOA is systematic and quantifiable): Strongly supported for the tested models, but qualified by the synthetic nature of the evidence.** The AFB results in Table 2 demonstrate a clear, structured bias pattern across six models: the Flip metric (aggregating V-AOA and R-AOA) ranges from 6% (GPT-5.1 on Human-Agent) to 39% (DeepSeek-V3.2 on Agent-Agent). The 10-domain coverage in Table 1 shows AOA is not an artifact of a single task type. However, this evidence has important limitations. AFB is synthetically generated by GPT-5.1 — the same model family that shows the lowest V-AOA. This creates a potential self-assessment confound: the generator may produce ambiguous failures that are ambiguous *for GPT-5.1's reasoning style*, and different models may genuinely perceive different causal structures. The paper's framing that "the absence of a deterministic ground truth exposes agents' inherent attribution biases" (Section 3) is a reasonable methodological choice for a *diagnostic* benchmark, but it means AFB cannot distinguish between "the model exhibits AOA" and "the model's reasoning, which happens to correlate with its perspective, leads to a different attribution that could also be justified by the ambiguous evidence." A stronger validation would include human judgments on AFB traces to establish that the ambiguity is genuinely symmetric — that neither attribution is objectively more correct — rather than relying on the generator's assertion of ambiguity. The 94% internal attribution rate for GPT-5.1 also complicates the AOA narrative: it suggests the model has a *different* systematic bias (over-internalization) rather than the classic actor-observer pattern. The paper frames this as a different manifestation of "the same underlying problem" (Section 4 in the prior sections), but this is an interpretive claim that the experiments do not directly test.

**Claim 2 (TAS reduces AOA compared to baselines): Well-supported for the tested datasets, with an important nuance about Dual View baselines.** The FinQA-TAS and Spider-TAS results (Table 3) show that Dual View reflection — explicitly prompting as Actor vs. Observer — produces worse attribution consistency than Single View reflection for some models (GLM-4.6: 43.7% Single View vs. 43.1% Dual View on FinQA-TAS; 52.7% Flip rate). This is a non-obvious, important result that validates the paper's central critique of simple multi-perspective approaches. TAS (both zero-shot and trained) consistently outperforms Dual View across all models and datasets (Figures 4–5). However, there is a confound: the Dual View baselines use a different prompt structure than TAS, so the improvement could be partially attributable to the specific prompt wording rather than the dialectical structure per se. A stronger comparison would control for prompt length and specificity — e.g., a baseline that asks the model to "consider both internal and external causes and then decide" without the explicit Thesis/Antithesis/Synthesis tagging. The paper's claim that TAS is necessary *specifically because* it records and then overrides the role-congruent bias (rather than simply aggregating multiple views) is plausible but not rigorously isolated from the effect of having any structured reasoning template at all.

**Claim 3 (GRPO is necessary; prompting alone is insufficient): Supported with the important caveat that the gap between TAS prompting and full ReTAS varies substantially by dataset.** On FinQA-TAS, the gap between zero-shot TAS prompting (57.6% Acc, 14.1% V-AOA) and full ReTAS (71.2% Acc, 5.4% V-AOA) is large — 13.6 points of accuracy and 8.7 points of V-AOA. This is the paper's strongest evidence for the necessity of GRPO. On Spider-TAS, however, the SFT-only model (w/o GRPO in Table 4) achieves 61.2% Acc and 10.6% V-AOA — nearly identical to full ReTAS (61.4% Acc, 10.2% V-AOA). The attribution improvement from GRPO on Spider-TAS is essentially zero. This asymmetry is not discussed in the paper, but it raises an important question: is GRPO necessary in general, or only for certain task types? The paper's narrative that GRPO is "critical for learning the dialectical policy" (Section 5.2) is true for FinQA-TAS but overstated as a universal claim given the Spider-TAS results. The F1 improvement from GRPO on Spider-TAS (60.3% → 63.5%) does show that GRPO helps with downstream task performance even when attribution accuracy is unchanged, but this is a different claim — GRPO as a task-performance optimizer rather than as a debiasing mechanism. The reward weight sensitivity analysis (Table 7) is a genuine robustness check that strengthens the claim, but it only examines F1 on FinQA-TAS, not attribution metrics, and the range tested (1:1:1 to 1:8:1) is relatively narrow.

**Claim 4 (Generalization across domains and tasks): Supported qualitatively but quantitatively thin.** The AFB generalization results (Figures 7–8) show that ReTAS-FinQA reduces V-AOA from 29 to 11 on Agent-Agent traces and significantly reduces internal attribution bias on Human-Agent traces. These are directionally strong results. However, the paper reports these as bar chart comparisons without tables of exact numbers. The ReTAS bar is compared against "Baseline" (presumably the raw Qwen3-4B) and "Baseline + TAS" — but other baselines from Table 3 (QwQ-32B, GPT-5.1) are not shown on these figures, making it impossible to assess whether ReTAS's cross-domain performance is competitive with larger models' in-domain performance. The SALES ARENA results (Table 6, Figure 9) are the paper's only multi-turn evaluation, and they are based on a single simulation run — no variance estimates, no multiple random seeds, no statistical tests. The profit difference between Reflection_TAS ($168) and NONE ($157) is $11, or about 7%, across 4 items. Without knowing the variance across runs, this could easily be noise. The turn-by-turn dynamics (Figure 9) show a visually distinct pattern for TAS, but again with unknown variance. The paper presents these as proof-of-concept results, but they do not meet the evidentiary standard of the main FinQA-TAS / Spider-TAS experiments. A genuine strength, however, is the *negative* SALES ARENA result: Reflection_Dual's $135 profit (worse than NONE's $157) is a concrete, counter-intuitive finding that reinforces the paper's critique of aggregation-without-synthesis approaches. Even with the variance caveat, a 14% *decrease* from adding a reviewer is a striking result that warrants further investigation.

**Missing experiments that would strengthen the paper:**

- **Per-class attribution breakdown.** The paper reports aggregate attribution accuracy but never breaks it down by `FalseExt` vs. `FalseInt` vs. `True`. Given the class imbalance in Spider-TAS (5,308 True vs. 301 External), the 61.4% accuracy could be achieved by almost always predicting `True`, with poor performance on the rarer but more important failure classes. This is a critical omission for a paper about failure attribution.

- **Human evaluation of attribution correctness.** The ground-truth labels in FinQA-TAS and Spider-TAS come from the automated fact-check pipeline (Section 4.2): compare `E` against `E_gold` and `â` against `a*`. This is reliable for the `True` class and for clear-cut `FalseExt` / `FalseInt` cases, but there may be edge cases where the gold evidence annotation is incomplete or the answer grading is imperfect. Human validation of a sample of labels would strengthen confidence that the attribution accuracy metric measures genuine attribution quality rather than agreement with an imperfect automatic labeling process.

- **Direct comparison with an attribution-trained but non-diabactical baseline.** The paper compares against prompting baselines (Single View, Dual View) and against SFT-only, but never against a model trained with the same composite reward (R1+R2+R3) on standard CoT reasoning traces (without the TAS format). This would isolate whether the benefit comes from the TAS structure or from the multi-objective RL training itself.

- **Computational cost breakdown.** The paper reports training times (15 min/epoch SFT, 9 hours GRPO) but does not compare total training FLOPs against the larger baselines. For a paper that claims to show "parameter efficiency," a FLOPs-matched comparison — how much does it cost to train ReTAS vs. how much does it cost to inference QwQ-32B? — would be informative.

- **Ablation of dual-trajectory synthesis.** Section 4.3 describes generating both Actor and Reviewer trajectories that converge to the same attribution. A natural ablation would be to train on single-perspective trajectories only (e.g., only Actor trajectories, or only Reviewer trajectories) and measure whether the dual-trajectory design actually improves perspective invariance at test time. This is not performed.

**When the paper's claims hold and when they may not:** The claim that ReTAS reduces AOA holds clearly for FinQA-TAS — a 5.4% V-AOA with 71.2% accuracy is a strong result. It holds more weakly for Spider-TAS, where V-AOA is 10.2% and the GRPO contribution to attribution is negligible. The cross-domain generalization holds directionally but with thin statistical support. The SALES ARENA results are suggestive but preliminary. The broader claim that dialective alignment can substitute for model scale is supported only in the specific sense that ReTAS (4B) matches or exceeds larger models *on attribution metrics* — but larger models (GPT-5.1, DeepSeek-V3.2) still outperform ReTAS on raw task F1 (76.9% vs. 72.1%), so the substitution is for debiasing quality, not for overall capability. Readers should understand ReTAS as a specialized debiasing module that can be integrated into a larger agent system, not as a general-purpose replacement for model scale.

## 6. Limitations and Trade-offs

### The Difficulty Estimation Cost Is Not Accounted For

The ReTAS training pipeline depends critically on ground-truth attribution labels (`FalseExt`, `FalseInt`, `True`) for every training example, produced by the Stage 1 data generation pipeline (Section 4.2). This pipeline requires access to two forms of **oracle information** that are unavailable in most real-world deployments: (1) the gold evidence set `E_gold` — the complete set of evidence items that a perfect retriever would return — which must be annotated for every question, and (2) the gold answer `a*`, against which the agent's predicted answer `â` is compared. The fact-check labeling rule (`E_gold ⊆ E` and `â = a*`) is only executable because FinQA and Spider provide these annotations.

**The consequence** is that the method cannot be directly applied to new domains without either (a) selecting datasets that already have gold evidence and answer annotations, or (b) incurring the cost of manual annotation at scale. FinQA contains 8,281 labeled questions; Spider contains 8,034. For a practitioner building an agent on a proprietary dataset — say, an internal code review system or a customer-support triage pipeline — the labeling cost to create `E_gold` annotations (identifying exactly which documents, tables, or schema elements a perfect retriever should return for each query) is a substantial barrier. The paper is silent on whether approximate labels (e.g., using a strong retriever's top results as a proxy for `E_gold`) would suffice, or whether the TAS training degrades under label noise.

**The paper does not measure** the sensitivity of ReTAS to labeling errors in the ground-truth attributions. The class imbalance in Spider-TAS (5,308 `True` vs. 301 `FalseExt`; Table 8) raises the possibility that label noise on the rarer failure classes could disproportionately degrade attribution performance. No ablation introduces systematic label noise to test robustness.

**Mitigation status:** The paper does not acknowledge this as a limitation. The data generation pipeline is presented as a standard step (Section 4.2) without discussion of what happens when gold annotations are unavailable. The cross-domain generalization experiments (Figures 7-8) demonstrate that ReTAS trained on FinQA-TAS transfers to AFB without AFB-specific labels, but this only removes the labeling requirement for *evaluation* — the training still required FinQA's gold annotations. A fully self-supervised extension (e.g., using the model's own confidence or a consistency check across multiple retrieval runs as a pseudo-label) is not explored.

---

### The Dual-Trajectory Synthesis Relies on a Closed-Source Frontier Teacher Model

The dialectical synthesis stage (Section 4.3) uses GPT-5.1 — a closed-source, frontier-scale proprietary model — to generate the TAS reasoning trajectories on which Qwen3-4B is subsequently trained. This is a **distillation dependency**: the 4B model learns to produce dialectical reasoning by imitating traces generated by a model that is orders of magnitude larger, trained on undisclosed data, and accessible only through a paid API. The paper does not ablate the choice of teacher model. It is unknown whether a weaker open-weights model (e.g., Qwen3-30B or QwQ-32B) could generate trajectories of sufficient quality for the SFT+GRPO pipeline to converge to similar performance.

**The consequence** is that ReTAS's reported performance is not fully attributable to the TAS architecture and GRPO training alone — it is confounded with the quality of the teacher's reasoning. If GPT-5.1 systematically produces higher-quality Antithesis verifications or more nuanced Synthesis resolutions than a smaller teacher could, the trained ReTAS model inherits these advantages. A practitioner wanting to replicate ReTAS on a new domain must either (a) pay for GPT-5.1 API access at scale (generating two trajectories per training example — approximately 13,000 trajectories for FinQA-TAS + Spider-TAS combined), or (b) gamble that a weaker teacher will produce trajectories that still yield effective training. The paper reports that SFT takes 15 minutes per epoch and GRPO takes 9 hours, but this does not include the teacher inference cost — which, for GPT-5.1 generating thousands of long-form TAS traces with three-stage reasoning, likely dominates the total pipeline cost.

**The paper provides no evidence** on teacher quality sensitivity. The trajectory generation prompt templates (Figures 12-13 in Appendix B) show that the teacher receives detailed instructions including role definition, simulation rules, and structured thinking paradigms — but the paper does not report how often the teacher's generated trajectories correctly converge to the ground-truth attribution label, nor whether the SFT+GRPO pipeline filters out trajectories where the teacher's Synthesis does not match the label from Stage 1.

**Mitigation status:** Not acknowledged. The paper treats GPT-5.1 as a black-box trajectory generator without discussing alternatives, costs, or quality verification. A teacher-free approach — e.g., generating TAS trajectories via self-play between the backbone model acting as both Actor and Reviewer, with correct convergence verified against ground-truth labels — is not explored.

### No Per-Class Attribution Breakdown Conceals Potential Failure-Mode Blindness

The paper reports aggregate attribution accuracy (Acc.%) across all three classes (`FalseExt`, `FalseInt`, `True`) combined, but **never reports per-class performance**. Given the extreme class imbalance in both training datasets — Spider-TAS contains 5,308 `True` examples versus only 301 `FalseExt` and 1,391 `FalseInt` (Table 8) — the aggregate metric could be dominated by the trivial `True` class, where the model simply needs to recognize that the evidence was sufficient and the answer was correct. A model that achieves 61.4% aggregate accuracy on Spider-TAS could, in principle, achieve near-perfect accuracy on `True` examples while performing at chance on the rarest and most diagnostic class (`FalseExt`), where correctly identifying an external (retrieval) failure is critical for triggering the `Search` corrective action.

**The consequence** is that practitioners cannot assess whether ReTAS improves the specific attribution skills that matter most in deployment. In a production agent system, `FalseExt` and `FalseInt` require *different* corrective actions — re-retrieving missing evidence versus revising the reasoning logic. A model that correctly identifies `True` cases but systematically misclassifies `FalseExt` as `FalseInt` would trigger `Revise(code)` when it should trigger `Search(new_query)`, leading the system to waste compute trying to fix reasoning that was never the problem. The paper's strong claim that "ReTAS effectively decouples the agent's reasoning from its role-induced stance" (Section 5.1) is undercut if this decoupling is achieved primarily by correctly recognizing non-failure cases while still exhibiting role-dependent bias on actual failures.

**The paper provides no evidence** on this point. The AFB generalization results (Figures 7-8) are the only evaluation where `True` cases are absent by design — AFB consists entirely of ambiguous failure scenarios — and ReTAS does show bias reduction there, which is encouraging. But on the main FinQA-TAS and Spider-TAS benchmarks, the per-class breakdown could reveal important asymmetries. For instance, if V-AOA is concentrated in the `FalseInt` class (where an Actor might externalize a reasoning error while an Observer correctly internalizes it) but near-zero for `FalseExt`, that would imply a qualitatively different bias pattern than if V-AOA is uniform across failure types.

**Mitigation status:** Not discussed. The paper reports aggregate V-AOA and Flip metrics, which measure perspective-dependence across the full dataset, but these do not reveal whether perspective-dependence is stronger in specific attribution classes. Future work should report confusion matrices or per-class F1/Bias scores, which is standard practice in diagnostic classification tasks and would substantially strengthen the paper's claims about debiasing failure attribution.

### Generalization Evidence Is Qualitatively Strong but Statistically Thin

The paper's claim that ReTAS learns a "generalized reasoning strategy rather than overfitting the training distribution" (Section 5.5) rests on three sets of generalization experiments: (1) cross-domain transfer from FinQA-TAS to AFB (Figures 7-8), (2) cross-task transfer to SALES ARENA (Table 6, Figure 9), and (3) TAS prompting improvements across multiple model scales (Figures 4-5). While these results are directionally positive, each carries significant evidentiary limitations.

**AFB generalization (Figures 7-8):** The AFB benchmark contains 200 interaction traces (100 Human-Agent, 100 Agent-Agent), which are further split by agent type within each figure. The bars in Figure 7 (Agent-Agent) appear to show V-AOA counts (not percentages) with a maximum y-axis value of 30 — meaning the reported "reducing bias to 11" (Section 5.5) reflects roughly 11 out of 100 traces, with unknown variance. No confidence intervals, statistical tests, or exact numerical values in a table accompany these bar charts. The comparison set is limited: Qwen3-4B (the untrained backbone), Qwen3-4B + TAS (zero-shot prompting), and ReTAS. Larger baselines from Table 3 (QwQ-32B, Qwen3-30B-A3B) are not evaluated on AFB, so it is unknown whether ReTAS's cross-domain performance merely matches what a larger model could achieve without domain-specific training.

**SALES ARENA (Table 6, Figure 9):** The paper explicitly states in its Limitations section (at the end of the paper) that "our Sales Arena study offers an initial probe of multi-turn negotiation, but broader real-world negotiation settings remain future work." The results in Table 6 report a single set of scalar metrics — total profit, average profit per product, average turns — without variance estimates, confidence intervals, or information about the number of negotiation runs. The profit difference between the best configuration (Reflection_TAS: $168) and the baseline (NONE: $157) is $11 across 4 items (approximately $2.75 per item), which, in the absence of variance data, could easily fall within run-to-run noise. The paper's own Limitations section acknowledges that the Sales Arena study is preliminary.

**TAS prompting across model scales (Figures 4-5):** These figures show that TAS prompting improves attribution accuracy and reduces V-AOA across Qwen3-4B, GLM-4.6, Qwen3-30B-A3B, and QwQ-32B. The results support the claim that the TAS structure provides benefits beyond the Qwen3-4B backbone, but they do not demonstrate that the SFT+GRPO training generalizes across model families. All ReTAS results use Qwen3-4B-Instruct-2507 as the backbone; no ReTAS model is trained on Llama, Mistral, or DeepSeek architectures. The generalization claim for the full training pipeline is therefore limited to: "within the Qwen family, and for zero-shot TAS prompting only, the dialectical structure provides cross-model benefit."

**Mitigation status:** The paper partially acknowledges the SALES ARENA limitation in its Limitations section. The AFB and cross-model generalization limitations are not acknowledged. The authors present the AFB results as strong generalization evidence without caveating the small sample size, absence of variance estimates, or the absence of larger-scale baseline comparisons on AFB.

### The Method Evaluates Attribution Accuracy Without Measuring Whether Corrective Actions Actually Work

The paper's evaluation framework measures whether ReTAS produces the correct attribution label (`FalseExt`, `FalseInt`, or `True`) and the correct F1 score on the downstream task after taking corrective action. But **it does not directly measure whether the corrective action the model selects — `Search(new_query)`, `Revise(code)`, or `Confirm()` — actually fixes the failure when applied.** The F1 metric in Table 3 measures the quality of the *final* answer after the full pipeline (attribution → action → re-execution), but it does not isolate whether correct attributions produce effective actions or whether incorrect attributions produce ineffective ones.

**The consequence** is that the paper's central narrative — "by correctly attributing ambiguous failures, ReTAS is able to take corrective actions, leading to substantial improvements for the downstream tasks" (Section 5.1) — conflates correlation with causation. A model could achieve high attribution accuracy while selecting actions that are syntactically valid but semantically inappropriate (e.g., `Search` with an irrelevant query that retrieves equally useless evidence), and as long as the downstream model is robust to irrelevant retrievals, the F1 score might not degrade significantly. Conversely, a model could achieve low attribution accuracy but high F1 if the downstream task is easy enough that corrective actions are rarely needed (which is plausible given the class imbalance toward `True` in Spider-TAS). The paper does not provide a causal mediation analysis that would establish, for example, that conditioning on correct attribution (`Acc = True`) leads to higher F1 than conditioning on incorrect attribution (`Acc = False`).

**The paper provides indirect evidence** through the reward ablation (Table 4). Removing R2 (attribution reward) causes V-AOA to triple and F1 to drop modestly (72.1% → 69.5% on FinQA-TAS), suggesting that correct attribution does contribute to downstream performance. Removing R3 (answer correctness reward) causes F1 to drop sharply (72.1% → 68.3% on FinQA-TAS; 63.5% → 55.6% on Spider-TAS), suggesting that answer correctness provides a complementary signal. However, neither ablation directly measures the *action effectiveness* pathway — for instance, by re-running the pipeline with the model's selected action and measuring whether the failure is actually resolved.

**Mitigation status:** Not discussed. The paper's evaluation framework is attribution-centric: it assumes (reasonably) that correct attribution enables correct corrective action, but it does not close the loop by verifying that actions are effective. A simple extension — for `FalseExt` cases, re-execute retrieval with the model's `Search` query and measure whether the newly retrieved evidence now contains `E_gold`; for `FalseInt` cases, measure whether `Revise(code)` produces a correct answer on the existing evidence — would provide the missing causal link and substantially strengthen the practical value proposition of ReTAS.

---

### The Framework Is Validated on a Single Task Family with Clean Gold Annotations

All ReTAS experiments — training on FinQA-TAS and Spider-TAS, evaluation on AFB — operate within the **retrieval-augmented reasoning paradigm**, where failures decompose cleanly into retrieval failures (external) and reasoning failures (internal), and where ground-truth evidence and answers can be objectively verified. The paper's own Limitations section (at the end of the paper) acknowledges this explicitly:

> "To rigorously quantify Actor-Observer Asymmetry, we restricted our analysis to FinQA-TAS and Spider-TAS datasets. While this structural isolation is necessary for establishing internal validity, it simplifies the open-ended decision spaces characteristic of fully autonomous agents deployed in complex environments. Consequently, the efficacy of the ReTAS framework in scenarios involving long-horizon planning or creative generation where objective fault attribution is inherently subjective remains an area for future exploration."

**The consequence** is that the paper's method is validated only for tasks where (1) the agent's responsibility boundary is well-defined (retrieval vs. reasoning), (2) ground-truth correctness is objectively verifiable (numerical answers, SQL execution results), and (3) failure can be localized to a single, discrete stage. These properties do not hold for many real-world agent applications: an autonomous coding agent debugging a multi-file repository, a customer-service agent handling a multi-turn dialogue with a frustrated user, or a planning agent navigating a partially observed environment. In these settings, failures are often multi-causal (a bug was introduced in file A but triggered by code in file B; a customer escalated because of tone, not factual error), and "correct" attribution is genuinely ambiguous rather than just epistemically uncertain.

The paper's AFB benchmark partly addresses this by including ambiguous scenarios across 10 domains (Table 1), but AFB is a diagnostic probe, not a task benchmark — it measures whether attribution changes under role swaps, not whether the agent can actually *resolve* the failure across multiple corrective attempts. The SALES ARENA experiment is the only multi-turn evaluation, and as discussed above, it is preliminary.

**The paper provides some generalization evidence** through the AFB cross-domain transfer (Figures 7-8), but this evidence shows bias reduction in attribution judgments, not successful failure resolution in open-ended tasks. The SALES ARENA results show profit improvements in a structured negotiation task, which is a step toward multi-turn validation, but negotiation is still a relatively constrained domain with objective outcomes (profit).

**Mitigation status:** Partially acknowledged in the Limitations section but understated in the main narrative. The paper's abstract claims ReTAS "establishes a robust paradigm for agent collaboration" without qualifying this to retrieval-augmented reasoning tasks. The broader claim that "dialectical alignment can substitute for model scale in resolving perspective-dependent cognitive bias" (Section 1 of the prior sections) is supported only within the retrieval-augmented reasoning family. Extending ReTAS to open-ended generation, multi-turn dialogue, or embodied agent tasks would require either (a) developing attribution labeling procedures for domains without clean gold standards, or (b) demonstrating that the method transfers without domain-specific labels — neither of which the paper attempts.

## 7. Implications and Future Directions

### How This Work Changes the Landscape

This paper introduces a **new diagnostic dimension for LLM reliability** — perspective-invariant reasoning — and demonstrates that it is a distinct capability not addressed by model scale, general debiasing, or standard multi-agent architectures. The conceptual shift is from treating cognitive bias as a property of *individual model outputs* (does this response reflect a stereotype? is this evaluation unfair?) to treating it as a property of *relationships between outputs conditioned on different roles* (does the same evidence lead to the same causal attribution regardless of whether the agent is the executor or the reviewer?). This is not merely additive — it reveals a failure mode that is invisible to standard bias benchmarks but structurally unavoidable in any multi-agent system that assigns functional roles.

The magnitude of the shift is best characterized as a **reframing with diagnostic novelty, not a paradigm change**. The paper does not overturn the role-playing paradigm for multi-agent systems — it explicitly endorses role specialization as effective for task decomposition. Rather, it identifies a previously unnamed cost of that paradigm (perspective-dependent distortion of causal reasoning) and provides the first targeted intervention. The paradigm itself remains intact; what changes is that future multi-agent systems must now contend with AOA as a first-class design constraint, much as single-agent systems had to contend with hallucination after it was named and measured.

The work resolves a specific puzzle in the literature: **why do self-reflection and cross-critique sometimes help and sometimes hurt?** Prior work contained genuinely contradictory findings. Reflexion (Shinn et al., 2023) and related approaches showed that self-reflection improves agent performance on reasoning benchmarks. Yet other work found that "LLMs cannot self-correct reasoning" (Huang et al., 2023, cited in the reference example) and that self-critique often introduces new errors. The paper's Dual View baselines (Table 3) demonstrate the mechanism behind this contradiction: adding an opposing perspective without a synthesis mechanism *amplifies* attribution inconsistency. GLM-4.6's Flip rate of 52.7% under Dual View means the model changes its attribution on more than half of examples simply because the role prompt changed. The paper's framework explains when cross-critique helps (when the agent has a mechanism to check its role-congruent instinct against evidence — the Antithesis stage) and when it hurts (when perspectives are simply juxtaposed without reconciliation, creating role-inertia deadlock). This converts a confusing empirical pattern into a testable hypothesis about *which component* of the reasoning process is missing.

The paper also redirects attention in the multi-agent reliability literature. Prior to this work, the dominant approaches for improving agent collaboration were **(a) better role engineering** (more specific prompts, better role definitions), **(b) more sophisticated aggregation** (voting, debate, hierarchical review), and **(c) scaling model size** (assuming larger models are less biased). The paper demonstrates that none of these approaches address the mechanism driving AOA. Role engineering without structured verification (the Dual View baselines) can worsen bias. Aggregation without synthesis (Reflection_Dual in SALES ARENA producing $135 vs. $157 for no reflection) creates indecision. Scaling model size (GPT-5.1's 94% internal attribution rate) trades one bias for another. The paper thus shifts the research agenda from "how do we design better roles?" to "how do we train models to reason about their own role-conditioned biases?" — a metacognitive framing that did not exist in the multi-agent literature before this work.

One consequence is that **verifier robustness becomes central to multi-agent systems**, not just to single-agent RLHF. The paper's key mechanism — Antithesis checking the Thesis against evidence — depends on the model's ability to accurately evaluate whether the initial role-congruent reaction is supported by the available information. If the model's evidence-verification capability is itself biased (e.g., a Reviewer's Antithesis selectively attends to evidence that confirms internal blame), the dialectical process degrades to role-congruent reasoning with extra steps. This suggests that future work on multi-agent reliability should invest as heavily in training agents to *evaluate evidence* independent of their role identity as in training them to perform their role-specific functions — a design principle that the paper demonstrates but does not name explicitly.

### Follow-Up Research This Work Enables

**Closing the loop: measuring whether TAS-driven corrective actions actually resolve failures.** The paper demonstrates that ReTAS produces correct attributions and achieves high downstream F1, but never measures the causal pathway: for a `FalseExt` case where ReTAS selects `Search(new_query)`, does re-executing retrieval with that query actually recover the missing evidence? For a `FalseInt` case where ReTAS selects `Revise(code)`, does the revised code produce the correct answer? A direct follow-up would instrument the FinQA-TAS and Spider-TAS pipelines to execute the model's chosen action and measure a **repair success rate**: the fraction of `FalseExt` cases where post-search evidence now satisfies `E_gold ⊆ E_new`, and the fraction of `FalseInt` cases where the revised answer `â_revised = a*`. This would distinguish between "ReTAS makes correct attributions" and "ReTAS's attributions enable effective recovery" — two claims the paper currently conflates. A negative result (correct attribution but ineffective action selection) would reveal that the `[Action]` field is learned as a surface-level tag rather than a semantically grounded operation, which would motivate training on action outcomes rather than merely on attribution labels.

**Per-class diagnostic: where does AOA actually live?** The paper reports aggregate attribution accuracy and V-AOA across all three classes (`FalseExt`, `FalseInt`, `True`), but the class imbalance (Spider-TAS: 5,308 `True` vs. 301 `FalseExt`; Table 8) means aggregate metrics may be dominated by the trivial `True` class. A targeted follow-up would report **per-class confusion matrices** for attribution under both Actor and Observer perspectives. The diagnostic question: is V-AOA concentrated in the `FalseInt` class (where an Actor externalizes a reasoning error while an Observer correctly internalizes it), or in `FalseExt` (where an Observer blames the executor for a retrieval failure), or uniformly distributed? If V-AOA is primarily a "self-serving bias on reasoning errors" phenomenon, then the intervention can be narrowed — perhaps only the `FalseInt` pathway needs the full TAS structure, and `FalseExt` can use a simpler verification check. Conversely, if V-AOA is symmetric across failure types, the dialectical approach is validated as a general solution. The paper provides no evidence on this question, and answering it would substantially sharpen both the psychological interpretation (is this genuinely Actor-Observer Asymmetry in the social-psychological sense, or a narrower phenomenon?) and the engineering prescription.

**Teacher model sensitivity: how strong does the trajectory generator need to be?** The paper uses GPT-5.1 as a black-box dialectical synthesis teacher, but never ablates teacher quality. A systematic follow-up would train ReTAS variants using TAS trajectories generated by a range of teachers — GPT-5.1 (frontier closed-source), QwQ-32B (strong open-weights reasoner), Qwen3-30B (mid-scale), Qwen3-4B (self-distillation, where the backbone generates its own training trajectories) — and measure how attribution accuracy and V-AOA scale with teacher capability. If self-distillation (4B generating trajectories for 4B) achieves non-trivial attribution improvement, the method becomes substantially more accessible — no API dependency, no teacher inference cost, fully reproducible. If only GPT-5.1-generated trajectories work, the method is effectively a distillation from frontier models and its claimed "parameter efficiency" must be weighed against the unmeasured cost of the teacher. A secondary analysis within this experiment: measure the **teacher's own attribution accuracy** on FinQA-TAS under Dual View prompting. If GPT-5.1 exhibits high AOA despite generating the trajectories that train ReTAS, it would be a striking dissociation — the model *generates* correct dialectical reasoning for others but does not *apply* it itself — which would suggest that TAS training teaches a reasoning *format* rather than a genuine metacognitive skill. This would be a crucial stress-test of the paper's strongest claim.

**TAS as a general debiasing protocol for cognitive biases beyond AOA.** The paper demonstrates that recording an initial biased reaction (Thesis), checking it against evidence (Antithesis), and synthesizing a corrected conclusion (Synthesis) reduces *perspective-dependent* attribution bias. Does the same structure work for other cognitive biases that have different mechanisms? Concrete candidates: **confirmation bias** (Thesis: the model's initial answer to a question; Antithesis: explicitly search for evidence *against* that answer; Synthesis: revise the answer based on the full evidence set), **anchoring bias** (Thesis: the model's estimate given an initial anchor value; Antithesis: recompute the estimate ignoring the anchor; Synthesis: reconcile), and **framing effects** (Thesis: answer under positive frame; Antithesis: answer under negative frame; Synthesis: identify the frame-invariant conclusion). Each of these would require constructing a benchmark analogous to AFB — a set of scenarios where the bias is measurable under counterfactual framing swaps — and then testing whether zero-shot TAS prompting and TAS+GRPO training reduce the bias. If TAS generalizes across bias types, it suggests a unified metacognitive architecture for LLM debiasing: surface the automatic (biased) response as a tagged hypothesis, verify it, and override it when evidence contradicts it. If TAS only works for AOA — because AOA's structure (self vs. other) maps cleanly onto the Actor/Observer role distinction — then the method is narrower and new structures would be needed for other biases.

**Dynamic, runtime TAS: replacing pre-computed difficulty with online perspective arbitration.** The current ReTAS model runs TAS once at inference time when presented with a candidate failure. But in a real multi-agent system, attribution happens iteratively — the executor and reviewer disagree, new evidence is gathered, perspectives shift. A dynamic extension would embed TAS into a multi-turn dialogue: Agent A (Actor) produces a Thesis, Agent B (Observer) produces an Antithesis, and a third module (or the same model in a Synthesis role) integrates them — with the option to request additional evidence or iterate if the Synthesis is inconclusive. This turns TAS from a static reasoning template into an interactive negotiation protocol. The minimal viable experiment: take the AFB Agent-Agent scenarios from Section 3, and instead of evaluating a single model under role-swapped prompts, have two instances of ReTAS (one as Actor, one as Observer) engage in a 2–3 turn exchange, with each turn requesting evidence or proposing attributions, until they converge or a turn limit is reached. Measure: (a) convergence rate — do they agree on attribution more often than the single-model Dual View baselines? (b) evidence efficiency — do they request fewer pieces of evidence than a non-dialectical debate baseline to reach consensus? The SALES ARENA experiment (Table 6) is a first step in this direction, but it uses a static reflection step between rounds rather than interactive perspective arbitration. A true multi-agent dialectical protocol would test whether TAS scales from individual reasoning to collaborative reasoning.

**Adversarial role assignment: can a sufficiently strong role prompt break ReTAS?** The paper demonstrates that ReTAS is robust to the specific Actor/Observer prompts used in evaluation. But the method's claimed mechanism — "decoupling the agent's reasoning from its role-induced stance" — implies that it should be robust to *any* role prompt, including adversarial ones designed to induce extreme bias. A stress-test would construct deliberately extreme role prompts: "You are a defensive executor who believes the retrieval system is always at fault" vs. "You are a hostile auditor who believes the executor is incompetent and never checks the evidence." If ReTAS maintains low V-AOA under these extreme prompts, the claim that it has internalized evidence-grounded reasoning is strongly validated. If V-AOA re-emerges under extreme prompts, it reveals that ReTAS has learned to be robust to the *specific* role distributions in its training data but not to arbitrary role manipulations — a more limited form of debiasing. A secondary manipulation within this experiment: vary the *order* of the Thesis and Antithesis (start with evidence verification, then produce the role-congruent reaction) to test whether the sequence matters, or whether any structured two-step check produces debiasing regardless of which step comes first.

### Practical Applications and Downstream Use Cases

**Automated root-cause analysis in production multi-agent pipelines.** Consider a deployed software engineering agent system like ChatDev (Qian et al., 2024), where a Programmer agent writes code and a Reviewer agent evaluates it. When a test fails, the system must determine whether the failure stems from a misunderstood requirement (external, the Product Manager's specification was ambiguous) or a logic error in the code (internal, the Programmer made a mistake). The current default — having the Reviewer diagnose the failure unilaterally — is vulnerable to the fundamental attribution error (the Reviewer over-attributes to internal causes). ReTAS can be integrated as a **failure triage module**: given the test failure, the requirement specification, and the generated code, ReTAS produces a structured attribution that is invariant to whether the Programmer or Reviewer perspective is used to invoke it. The paper's FinQA-TAS results (5.4% V-AOA, 71.2% attribution accuracy) suggest that in roughly 95% of cases, the attribution would not flip based on who asks the question. This directly reduces the misallocation of debugging effort — preventing the system from "fixing" code when the specification needs clarification, and vice versa. The 30% relative improvement in attribution accuracy over QwQ-32B Dual View (Table 3: 71.2% vs. 54.9%) translates to roughly one in every three failure investigations reaching the correct root cause that would otherwise have been misdiagnosed by a state-of-the-art reasoning model.

**Self-improvement data filtering for agent fine-tuning.** When using agent execution traces to generate fine-tuning data (as in ReST-style self-improvement loops; Singh et al., 2024, cited in the paper), the quality of the training signal depends on correctly identifying *which* component of the pipeline failed. If an execution trace is labeled as "reasoning failure" when the actual cause was missing retrieval, the model learns to correct something that wasn't broken. ReTAS can serve as an **automatic trace labeler**: for each execution trace in a self-improvement corpus, ReTAS produces a `FalseExt`/`FalseInt`/`True` label and a corrective action. Traces labeled `FalseInt` enter the reasoning-correction training set; traces labeled `FalseExt` are either discarded (since they don't reflect reasoning quality) or routed to a retrieval-improvement pipeline. The paper's Spider-TAS training set statistics (Table 8: 301 External, 1,391 Internal) suggest that in a typical retrieval-augmented deployment, roughly 18% of failure traces are external and would otherwise contaminate a reasoning-focused fine-tuning dataset. ReTAS's 61.4% attribution accuracy on Spider-TAS means it can identify roughly three out of five external failures correctly — a substantial improvement over using a generic "failure = bad reasoning" heuristic, which would mislabel all 301 external failures as internal.

**Role-based model routing in cost-sensitive deployments.** Many production LLM systems route queries to different models based on estimated difficulty or domain. ReTAS enables a new routing dimension: **role sensitivity**. A query that is likely to trigger AOA (e.g., debugging a complex multi-stage failure where internal and external causes are genuinely ambiguous) can be routed to a dialectically aligned model (ReTAS or a ReTAS-augmented agent), while straightforward queries (single-step reasoning, clear attribution) can be routed to a cheaper, non-TAS model. The paper's cross-domain generalization results (Figures 7-8) suggest that a ReTAS model trained on one domain (FinQA) transfers its debiasing capability to entirely different domains (AFB's 10 categories including coding, customer service, safety alignment). This means a single ReTAS instance could serve as the attribution specialist for a heterogeneous agent system, invoked only when the system detects (via confidence scores or inter-agent disagreement) that attribution is contested. The compute savings come from avoiding the overhead of dialectical reasoning on every query — TAS adds generation length (three reasoning stages plus action output) — while still having access to debiased attribution when it matters.

### When to Prefer This Method

The paper articulates a specific tradeoff between **role-based multi-agent architectures with dialectical alignment** (TAS+GRPO training) and **scaling model size without structured debiasing**. The results in Table 3 make this tradeoff explicit: ReTAS (4B) with dialectical alignment achieves 71.2% attribution accuracy and 5.4% V-AOA on FinQA-TAS, while QwQ-32B (8× larger) with Dual View reflection achieves 54.9% accuracy and 14.7% V-AOA — worse on both metrics despite having 8× the parameters. However, GPT-5.1 and DeepSeek-V3.2 (prompting only, no attribution mechanism) achieve higher downstream F1 (76.9% and 76.0% vs. ReTAS's 72.1%), indicating that dialectical alignment compensates for scale on the *debiasing* objective but not fully on the *task performance* objective.

The paper also identifies a clear boundary condition: **when attribution ambiguity is inherent** (as in AFB's deliberately constructed scenarios), standard role-based approaches fail. The Dual View baselines in Table 3 show that simply prompting a model to consider both perspectives can *increase* inconsistency (GLM-4.6: 52.7% Flip). The SALES ARENA results extend this to dynamic settings: Reflection_Dual (aggregating Actor and Observer without synthesis) produces *worse* profit than no reflection at all ($135 vs. $157). This suggests that in any deployment where agents must resolve genuinely ambiguous failures through multi-perspective deliberation, dialectical synthesis is not merely beneficial — aggregation without synthesis is actively harmful.

- **Prefer dialectical alignment (TAS+GRPO) over scaling model size when:** (1) the deployment requires reliable, perspective-invariant failure attribution (the system must act on the attribution, not just achieve high task F1); (2) model size is constrained (on-device, edge deployment, cost-sensitive API usage) and the 4× to 8× smaller dialectically trained model matches or exceeds larger models on attribution metrics; (3) the task domain has a clean decomposition into stages with separable responsibility boundaries (retrieval vs. reasoning, planning vs. execution), enabling the `FalseExt`/`FalseInt` distinction to be objectively grounded.

- **Prefer scaling model size over dialectical alignment when:** (1) raw task performance (F1, accuracy) is the primary objective and failure attribution is not required for downstream action; (2) the task domain lacks clean ground-truth attribution labels for training the TAS pipeline — the method requires gold evidence annotations (`E_gold`) and gold answers (`a*`) to generate the `FalseExt`/`FalseInt`/`True` labels, and the paper provides no evidence that it works with noisy or approximate labels; (3) the deployment has access to frontier-scale models (GPT-5.1 class) and the attribution task is genuinely subjective — in creative writing or open-ended dialogue, where "correct" attribution is a matter of judgment, dialectical synthesis may produce well-structured but still subjective conclusions.

- **Avoid dual-view aggregation without synthesis in any attribution-sensitive setting.** The paper's most actionable negative result is that adding an opposing perspective without a structured reconciliation mechanism (Synthesis) degrades performance across multiple settings: GLM-4.6's 52.7% Flip rate (Table 3), Reflection_Dual's $135 total profit in SALES ARENA (Table 6, below the $157 no-reflection baseline), and the Qwen3-4B attribution accuracy decline from 51.2% (Single View) to 50.0% (Dual View) in Table 5. If a system must include multiple perspectives, include a synthesis mechanism — whether TAS or an alternative — that forces convergence to a single evidence-grounded conclusion.
