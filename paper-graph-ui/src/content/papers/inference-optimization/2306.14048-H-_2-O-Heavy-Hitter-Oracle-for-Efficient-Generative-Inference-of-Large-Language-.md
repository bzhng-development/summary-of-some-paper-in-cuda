# H$_2$O: Heavy-Hitter Oracle for Efficient Generative Inference of Large Language Models

**ArXiv:** [2306.14048](https://arxiv.org/abs/2306.14048)

## 🎯 Pitch

This paper proposes **Heavy Hitter Oracle (H2O)**, a KV cache eviction policy that dramatically reduces the memory footprint of large language model inference by exploiting the observation that attention matrices are over 95% sparse and that a small subset of tokens—termed **Heavy Hitters (H2)**—contribute most of the value when computing attention scores.

---

## 1. Executive Summary

This paper proposes **Heavy Hitter Oracle (H2O)**, a KV cache eviction policy that dramatically reduces the memory footprint of large language model inference by exploiting the observation that attention matrices are over 95% sparse and that a small subset of tokens—termed **Heavy Hitters (H2)**—contribute most of the value when computing attention scores. Evaluated across OPT, LLaMA, and GPT-NeoX models on tasks from HELM and lm-eval-harness, H2O dynamically balances retention of these high-impact tokens alongside recent tokens, formulating KV cache eviction as a dynamic submodular maximization problem with theoretical guarantees. The approach achieves up to 29× higher throughput over DeepSpeed Zero-Inference, 29× over Hugging Face Accelerate, and 3× over FlexGen on OPT-6.7B and OPT-30B, while maintaining full-cache accuracy with only 20% of the KV cache budget—enabling the model to process inputs of up to four million tokens, establishing that aggressive KV cache reduction preserves generation quality only when eviction policies account for both recency and the persistent influence of a small core of attention-dominating tokens.

## 2. Context and Motivation

### The Core Problem: The KV Cache Is an Overlooked Inference Bottleneck

When deploying large language models for generative tasks, the computational cost is typically characterized by two well-recognized bottlenecks: the massive parameter count of the models themselves and the quadratic complexity of attention layers with respect to sequence length. However, this paper addresses a third bottleneck that is becoming increasingly prominent as models are deployed for long-content generation: **the KV cache**.

The KV cache is a standard optimization in autoregressive generation. During the token-by-token decoding process, each new token must attend to all previously generated tokens. Without caching, this would require recomputing the key and value projections for every previous token at every decoding step — a quadratic cost in the sequence length that would make generation prohibitively slow. The KV cache stores these intermediate attention key and value embeddings in GPU memory after they are first computed, so that during subsequent decoding steps they can be read from memory rather than recomputed.

The problem is that the KV cache grows linearly with both sequence length and batch size. As the authors note in Section 1:

> "a 30 billion-parameter model with an input batch size of 128 and a sequence length of 1024 results in 180GB of KV cache."

This is enormous. To put it in perspective: the model parameters themselves for a 30B model occupy roughly 60GB in half-precision, so the KV cache can be three times larger than the model. For applications involving long conversations, story generation, or document summarization — all of which require generating hundreds or thousands of tokens — the KV cache rapidly becomes the dominant memory consumer, limiting both the maximum batch size (and therefore throughput) and the maximum sequence length the system can handle.

### Why This Problem Matters Now

The KV cache bottleneck is not just a theoretical concern — it has immediate, practical consequences for LLM deployment that the paper makes explicit:

**Throughput limitations.** Because GPU memory is finite, the KV cache competes directly with model parameters for space. When the KV cache grows large, the system must either reduce the batch size (hurting throughput) or resort to offloading — moving data between GPU and CPU memory, which introduces substantial latency. The paper's experiments in Section 5.2 demonstrate this concretely: on a T4 GPU with 16GB of memory, standard inference engines can only support batch sizes of 1–2 for OPT-6.7B with moderate sequence lengths before hitting out-of-memory errors or requiring CPU offloading.

**Long-content generation.** Many of the most compelling applications of LLMs — dialogue systems, story writing, document summarization, multi-turn reasoning — require generating long sequences. The linear growth of the KV cache means that doubling the output length doubles the memory requirement, creating a hard ceiling on how much content can be generated in a single session. This is particularly acute for applications where the model needs to maintain coherence over very long contexts (the paper demonstrates handling up to four million tokens with H2O, which would be infeasible with a full KV cache).

**Batch inference economics.** When serving LLMs at scale (e.g., for API providers or enterprise deployments), throughput directly determines cost. If the KV cache limits batch sizes, the cost per query increases, making LLM deployment less economically viable. The paper's demonstrated 29× throughput improvement over baseline systems translates directly to reduced infrastructure costs and lower latency for end users.

The problem has theoretical significance as well. The KV cache represents a fundamental tension in transformer architectures: the attention mechanism's strength — that every token can attend to every previous token — is precisely what makes its memory requirements scale linearly during generation. Understanding whether and how this cache can be compressed without degrading model quality is a question about the nature of attention itself: does the model genuinely need access to *all* previous tokens, or is the information content of the attention history highly redundant?

### Prior Approaches and Where They Fall Short

The paper situates its contribution against several categories of prior work, each of which addresses related problems but fails to fully satisfy the requirements of an ideal KV cache solution.

#### Sparse Attention Approximation (for Training)

A substantial body of work exists on making attention more efficient during *training*, including Reformer (Kitaev et al., 2020), Flash Attention (Dao et al., 2022), Performer (Choromanski et al., 2020), and Linear Transformers (Katharopoulos et al., 2020). However, the paper identifies a critical mismatch: these methods were designed to overcome the quadratic memory cost of attention when modeling long sequences during training, but they **still require a large cache size** during inference. Specifically, Flash Attention computes exact attention in a memory-efficient way but does not reduce the number of KV entries that must be stored — it only reorganizes computation to avoid materializing the full attention matrix. Reformer uses locality-sensitive hashing to reduce the set of keys each query attends to, but this reduces compute more than it reduces storage. These methods solve a different problem than the KV cache bottleneck.

As the authors note in Section 1:

> "most existing methods, e.g., Reformer and Flash Attention, are designed to overcome the quadratic memory required by attention mechanisms when modeling long sequences but still require a large cache size."

#### Architectural Modifications to Reduce Cache Size

Several transformer variants explicitly reduce the number of keys and values that need to be cached:

- **Multi-Query Attention** (Shazeer, 2019) and **Grouped-Query Attention** (used in PaLM, Chowdhery et al., 2022) share key and value heads across query heads, directly reducing the cache size by a factor equal to the number of heads. While effective, this requires training models with these architectures from scratch — it cannot be applied to existing pre-trained LLMs.

- **Sparse Transformer** (Child et al., 2019) introduces fixed sparse attention patterns (strided or local windows) that naturally limit which keys need to be cached. However, the paper demonstrates in Section 5.1 (Table 2) that directly applying these fixed sparsity patterns to pre-trained models during inference results in severe accuracy degradation — up to 35% accuracy drop compared to full cache under a 20% budget. This is because the fixed patterns were baked into training; a model trained with dense attention has learned to rely on arbitrary long-range dependencies that a fixed sparse pattern may sever.

#### Learned Cache Compression

**Gisting tokens** (Mu et al., 2023) learn to compress the KV cache for documents by training a model to produce compact "gist" representations. However, the paper points out that their "expensive eviction policies are difficult to deploy during generation" because the compression itself requires additional computation at inference time, undermining the efficiency goal.

Another closely related work is **Dynamic Context Pruning** (Anagnostidis et al., 2023), which uses a learnable mechanism to determine which tokens are necessary during inference. However, the paper notes this "requires an extra fine-tuning process, which makes it less practical" — it cannot work out-of-the-box on arbitrary pre-trained models.

#### Existing Inference Systems

The paper benchmarks against three state-of-the-art inference systems:

- **DeepSpeed Zero-Inference** (Aminabadi et al., 2022) partitions model weights across GPUs but does not specifically optimize the KV cache, leading to limited batch sizes when the cache grows large.
- **Hugging Face Accelerate** provides a simple offloading mechanism but suffers from severe throughput degradation when the KV cache forces CPU offloading.
- **FlexGen** (Sheng et al., 2023) introduces sophisticated offloading and scheduling strategies for high-throughput inference on a single GPU, but still uses a full KV cache, limiting its maximum batch size and throughput.

As shown in Section 5.2 (Tables 3 and 4), all three systems hit throughput walls due to KV cache memory pressure. FlexGen achieves 8.1 tokens/s on OPT-30B with a batch size of 144 (requiring CPU offloading), while H2O with 20% cache achieves 12.7 tokens/s with a batch size of 728 — simultaneously faster and handling 5× the batch size.

### How This Paper Positions Itself

The paper frames its contribution not as yet another attention approximation or architectural modification, but as an **eviction policy** for the KV cache — analogous to cache replacement policies (LRU, LFU) in classical computer systems. This framing is deliberate and has important implications:

**1. It is a deployment-time solution, not a training-time one.** H2O requires no retraining, no fine-tuning, and no architectural changes. It operates purely at inference time on any pre-trained transformer model. This makes it immediately applicable to the vast ecosystem of existing LLMs (OPT, LLaMA, GPT-NeoX, and by extension any decoder-only transformer).

**2. It treats the KV cache as a resource allocation problem.** Rather than modifying *how* attention is computed (like sparse attention) or *how much* cache each head uses (like multi-query attention), H2O asks: given a fixed cache budget, *which* tokens should be retained? This is the cache eviction problem: at each decoding step, when the cache is full, which entry should be evicted to make room for the new token?

**3. It is grounded in empirical observations about attention.** The paper does not posit an arbitrary heuristic. Instead, it begins with two empirical observations that motivate the design (Section 3):

- **Attention sparsity:** Pre-trained LLMs, despite being trained densely, produce attention matrices that are over 95% sparse at inference time (Figure 2a). This means that for any given query, only a small fraction of keys receive non-trivial attention scores — suggesting that most of the KV cache is unused at each step.

- **Heavy-hitters follow a power law:** The accumulated attention scores across all tokens follow a power-law distribution (Figure 2b), meaning a small number of tokens account for a disproportionate share of total attention mass. These "heavy hitters" are strongly correlated with frequently co-occurring words in the training data, and removing them causes catastrophic performance degradation (Figure 2c).

**4. It provides theoretical grounding.** The paper does not stop at heuristics. In Section 4 and Appendix D, it formulates KV cache eviction as a **dynamic submodular maximization problem** and proves (under mild assumptions) that the greedy H2-based eviction policy has a theoretical guarantee (Theorem 4.4): the set of tokens it retains achieves at least $(1-1/e)(1-\alpha)$ times the optimal value minus a small error term. This theoretical framework, while necessarily relying on assumptions about the submodularity of attention, distinguishes H2O from purely empirical approaches and provides a foundation for future work on KV cache policies.

**5. It addresses all three requirements of an ideal KV cache.** The paper explicitly states in Section 1 that an ideal KV cache should have:
- A **small cache size** to reduce memory footprint → H2O achieves 5–10× reduction.
- A **low miss rate** to maintain generation quality → H2O matches full-cache accuracy on most tasks.
- A **low-cost eviction policy** to reduce wall-clock time → H2O uses a simple greedy algorithm based on accumulated attention scores, with minimal computational overhead.

The paper's position, then, is that the KV cache bottleneck can be substantially mitigated *without* retraining models, *without* architectural changes, and *without* expensive learned compression — simply by making smarter decisions about which tokens to keep and which to evict, guided by the empirical fact that attention is highly concentrated on a small set of tokens. The contribution is both practical (immediately deployable) and principled (grounded in theory and empirical observation), and it opens a new research direction: the design and analysis of eviction policies as a first-class problem in efficient LLM inference.

## 3. Technical Approach

### 3.1 Reader Orientation (Approachable Technical Breakdown)

The system is a memory-saving replacement for the standard KV cache in autoregressive language model generation that decides, at each decoding step, which past token embeddings to keep in GPU memory and which to permanently discard. It solves the problem that the KV cache grows linearly with sequence length and batch size, preventing large-batch or long-sequence generation, and the shape of the solution is an eviction policy — analogous to a CPU cache replacement algorithm — that preferentially retains a small core of "heavy hitter" tokens that dominate attention scores while also keeping the most recent tokens for local coherence.

### 3.2 Big-Picture Architecture (Diagram in Words)

The H2O system operates inside the attention computation of a standard decoder-only transformer during autoregressive generation. It has three major components that interact at every decoding step:

1. **Attention Score Accumulator** — At each decoding step, when the model computes attention scores between the current query and all cached keys, these scores are added to a running accumulation for each token. This accumulator is the data structure that identifies which tokens are "heavy hitters" — the persistent memory of which tokens have historically received large attention weights.

2. **KV Cache with Fixed Capacity** — Instead of storing key and value embeddings for all previous tokens, H2O maintains a fixed-size cache split into two logical regions: one for heavy hitters (identified by the accumulator) and one for recent tokens (a sliding window of the most recently generated tokens). The total cache size is a user-specified budget, typically 20% of the full sequence length.

3. **Eviction Policy (Greedy Algorithm)** — When the cache is full and a new token is generated, the eviction policy must decide which existing entry to remove. The policy uses the accumulated attention scores as a value function: it evicts the token with the lowest accumulated score from the heavy-hitter region (if a heavy hitter needs to be displaced) or the oldest token from the recent-token region. The new token's KV embeddings are then inserted into the appropriate region.

Information flows as follows: at each decoding step, the query vector for the new token attends only to the keys present in the reduced KV cache → attention scores are computed for those cached keys → these scores are added to the running accumulator for the corresponding tokens → the eviction policy uses the updated accumulator to decide which (if any) entry to evict → the new key and value are stored in the vacated slot. The cache size remains constant throughout generation, and the accumulator grows incrementally with each step's attention scores.

### 3.3 Roadmap for the Deep Dive

- **First**, the formal problem definition (Section 2.1 of the paper): what exactly are we optimizing when we limit the KV cache? This establishes the mathematical framework and notation for eviction policies and the generative process with a constrained cache.
- **Second**, the empirical observations that motivate H2O (Section 3): the discovery that attention matrices are over 95% sparse and that accumulated attention scores follow a power-law distribution. These observations justify why aggressive cache reduction is possible and why heavy hitters are the right thing to retain.
- **Third**, the dynamic submodular formulation (Section 4 and Appendix D): how the eviction problem maps to maximizing a sequence of submodular functions under cardinality constraints, and why the greedy algorithm has theoretical guarantees. This is the intellectual backbone that distinguishes H2O from arbitrary heuristics.
- **Fourth**, the H2O eviction policy itself (Algorithm 1 and Algorithm 2): the concrete procedure — how accumulated scores are computed, how the eviction decision is made at each step, and how the cache is maintained. This includes the practical variant using only local (past-token) statistics rather than requiring future knowledge.
- **Fifth**, the system implementation details (Section 4.2 and Appendix A): how H2O is integrated into FlexGen to achieve I/O efficiency, the memory layout (circular queue for recent tokens, preallocated cache), and why these engineering choices matter for wall-clock performance.
- **Sixth**, the theoretical analysis (Appendix D): the proofs that under submodularity assumptions, the greedy H2 policy achieves near-optimal value — both the full-knowledge version (Lemma 3.1) and the limited-cache version (Theorem 4.4).

### 3.4 Detailed, Sentence-Based Technical Breakdown

This is primarily an **eviction policy design paper** whose core idea is that the KV cache can be dramatically compressed without accuracy loss by preferentially retaining tokens that have historically received high cumulative attention, formulated as a dynamic submodular maximization problem with greedy selection.

---

#### Formal Problem Definition: Generative Inference with a Constrained KV Cache

The paper begins by formally defining the generative process of an LLM operating with a limited-size KV cache, because the entire approach depends on making this constrained process mimic the unconstrained one. The formalization (Section 2.1) defines the attention query matrix as $Q \in \mathbb{R}^{n \times d}$ and the key matrix as $K \in \mathbb{R}^{n \times d}$, where $n$ is the total number of tokens processed so far (prompt + generated) and $d$ is the head dimension.

**Definition 2.1 (Eviction Policy, informal).** Let $S_{i-1}$ denote the set of token indices currently in the KV cache before processing token $i$. Let $S_i$ denote the updated set after processing token $i$. An eviction policy is a function $g: S_{i-1} \rightarrow S_i$ satisfying two constraints:

- $|S_i| = k$, meaning the cache size stays constant after it fills up (for the first $k$ tokens it grows naturally).
- $|S_i \setminus S_{i-1}| \leq 1$ or equivalently $|S_i \cap S_{i-1}| \geq k-1$, meaning at most one entry is evicted per step (the policy changes the cache incrementally).

**Definition 2.2 (The generative process with eviction policy, informal).** For each token $i \in [n]$, when predicting the $i$-th token:

- Let $S_i \subset [n]$ be the set of token indices currently stored in the KV cache.
- The normalized attention vector for token $i$ is computed as:

$$o_i := D_i^{-1} \cdot \exp(Q_{i,*}(K_{S_i,*})^\top)$$

where $Q_{i,*} \in \mathbb{R}^{1 \times d}$ is the query for token $i$ (a row vector), $K_{S_i,*} \in \mathbb{R}^{|S_i| \times d}$ is the key matrix restricted to rows indexed by $S_i$, and $\exp$ is applied element-wise.

- The normalization scalar $D_i$ is:

$$D_i := (\exp(Q_{i,*}(K_{S_i,*})^\top) - \mathbf{1}_{[i] \setminus S_i}) \cdot \mathbf{1}_i$$

where $\mathbf{1}_{[i] \setminus S_i}$ is a row vector with ones at positions corresponding to tokens that are NOT in the cache (these are zeroed out in the attention computation, and must be subtracted from the normalization sum to maintain a proper probability distribution), and $\mathbf{1}_i$ is a length-$i$ vector of all ones.

**What this computes:** For each generated token, the model computes attention only over the keys that are currently in the cache, producing a probability distribution over the cached positions. The evicted tokens' attention scores are treated as zero, and the normalization constant is adjusted accordingly so that the remaining scores still sum to one. The output $o_i$ tells the model how much to attend to each cached token when producing the next token.

**Why this form:** The definition makes explicit that eviction is irreversible — once a token's KV embeddings are removed, they are permanently unavailable for all future decoding steps (they cannot be recovered because recomputing them would require re-running the entire prefix, defeating the purpose of caching). This is fundamentally different from classical CPU caches where evicted entries can be reloaded from main memory, and it means that eviction errors compound: if an important token is evicted early, the model loses access to it for the entire remainder of generation. The whole H2O design is motivated by making this irreversible decision as accurately as possible.

**Remark 2.3** states the core objective: find a KV cache eviction policy such that the output distribution over tokens in the constrained process is "similar or comparable" to the original unconstrained process. This is intentionally vague — the paper measures similarity through downstream task accuracy rather than attempting to match attention distributions exactly.

#### Empirical Observations That Motivate H2O

The H2O design is not an arbitrary heuristic; it is directly motivated by two empirical findings about how attention works in pre-trained LLMs at inference time.

**Observation 1: Attention sparsity for small cache size (Section 3.1).** The authors conduct zero-shot inference with a pre-trained OPT model on the validation set of Wiki-Text-103. For each attention head, they compute the normalized attention score matrix $\text{Softmax}(QK^\top)$, set a threshold at 1% of the maximum value in each row, and calculate what fraction of entries fall below this threshold (i.e., are negligible). The result, visualized in Figure 2(a), shows that **the attention matrices are over 95% sparse in almost all layers**. This means that for any given query, the model genuinely only needs to attend to about 5% of the available keys — the vast majority of attention weights are near zero.

The critical insight is that this sparsity emerges despite dense training: the model was trained with full attention, but at inference time it spontaneously concentrates its attention on a small subset of tokens. This directly implies that **most of the KV cache is wasted memory** — the embeddings that receive near-zero attention scores could theoretically be evicted without affecting the computation.

**Observation 2: Heavy-hitters for low miss rate (Section 3.2).** Going beyond per-step sparsity, the authors examine the distribution of **accumulated attention scores** — for each token (word) in the vocabulary, they sum the attention scores it receives across all queries in all layers. The result, shown in Figure 2(b), reveals that these accumulated scores follow a **power-law distribution**: a very small number of tokens receive orders of magnitude more total attention than the rest. They call these tokens **heavy-hitters (H2)**.

To verify that these heavy hitters are genuinely important, the authors perform an ablation: they remove (mask out) the heavy hitter tokens from the attention computation and measure the resulting accuracy drop. Figure 2(c) shows that **removing heavy hitters completely destroys model functionality** — accuracy drops drastically across all tasks, confirming that these tokens are not statistical artifacts but are functionally essential.

Additionally, the red scatter points in Figure 2(b) show that the accumulated attention score of each word has a **high correlation with its co-occurrence frequency in the training data** (gray curve). This suggests a plausible mechanistic explanation: words that co-occur frequently with many other words (function words, common nouns, key structural tokens) become attention sinks because the model learns that attending to them is useful across many different contexts.

**Why these two observations together suggest H2O.** Observation 1 tells us we *can* reduce the cache size dramatically (95%+ reduction is theoretically possible). Observation 2 tells us *what to keep*: the heavy hitters, because they are disproportionately valuable. The combination suggests a retention policy: keep the heavy hitters (identified by accumulated attention scores) and some recent tokens for local coherence, and evict everything else. The paper validates this intuition with an empirical study in Figure 2(d): an eviction policy that retains only H2 and recent tokens achieves comparable performance to the full KV cache, while "Local" (recent-only) performs catastrophically worse. The "H2O with local statistic" curve overlaps with the "Full KV" curve, while "H2O with global statistic" (which requires knowledge of future tokens) performs only marginally better — this justifies using only past-token statistics for the greedy algorithm, since future tokens are unavailable at inference time.

#### The Dynamic Submodular Formulation

The paper's key theoretical contribution is framing KV cache eviction as a **dynamic submodular maximization problem**. This formulation provides both an explanation for why the greedy H2-based policy works well and a theoretical guarantee on its performance. The full formal treatment is in Appendix D; here we walk through the core concepts.

**What is submodularity and why does it apply here?** A set function $f: 2^{[n]} \rightarrow \mathbb{R}$ is submodular if it exhibits **diminishing returns**: adding an element to a smaller set provides at least as much marginal gain as adding it to a larger superset. Formally, for all $X \subseteq Y \subset [n]$ and $x \in [n] \setminus Y$:

$$f(X \cup \{x\}) - f(X) \geq f(Y \cup \{x\}) - f(Y)$$

The authors argue (Section D.7) that attention has this property: when a token "w" is added to a small set of previously attended tokens $S'$, it provides a large information gain because its contribution is novel. When the same token is added to a larger superset $S$, the gain is smaller because $S$ may already contain tokens that encode similar information. The diminishing returns property is what makes greedy selection provably effective — if each addition provides less value than the previous, then greedily picking the highest-marginal-gain element at each step cannot be too far from optimal.

**The dynamic extension (Definition 4.1, formal version Definition D.4).** Standard submodular optimization has a single fixed function. But in LLM generation, the "value" of keeping a token in the cache changes as new tokens are generated — a token that was unimportant 10 steps ago might become relevant again. Therefore, the paper defines a **dynamic submodular framework**:

$$F: 2^{[n]} \times [n] \times 2^{[n]} \rightarrow \mathbb{R}$$

where the three arguments are:
- $Z \subset [n]$: the current cache contents (the set of retained tokens so far)
- $i \in [n]$: the index of the current token being predicted
- $X \subset [n]$: a candidate set of tokens whose value we want to evaluate

For each fixed $Z$ and $i$, the function $f_{Z,i}(X) = F(Z, i, X)$ is a submodular function of $X$. This means that at each decoding step, given the current cache contents, the value of any candidate set of tokens satisfies the diminishing returns property — but the function itself evolves as the cache changes and as generation progresses.

**The score function in H2O.** In the concrete instantiation (Algorithm 1, Line 10), the score function for a set of tokens $T$ is defined as:

$$F_{\text{score}}(T) := \sum_{s \in T} o_{i,s}$$

where $o_{i,s}$ is the normalized attention weight that the current query (token $i$) assigns to cached token $s$. In the formal version (Algorithm 2, Line 10), this is generalized to:

$$F_{\text{score}}(T) := h\left(\sum_{s \in T} \widetilde{o}_{i,s}\right)$$

where $\widetilde{o}_{i,s}$ is the **accumulated** attention score for token $s$ across all previous decoding steps, and $h$ is a non-decreasing concave function (such as $h(z) = \sqrt{z+1}$ or $h(z) = \log(z+1)$) chosen to ensure the submodularity property holds. The concave transformation $h$ is crucial: summing raw attention scores would be linear (modular), which is trivially submodular but doesn't capture the diminishing returns intuition. The concave function introduces diminishing returns — the 100th unit of accumulated attention contributes less marginal value than the 1st unit.

**Why the greedy algorithm works (Theorem 4.4, informal).** Under the assumption that the attention-based score function is submodular, the classic result of Nemhauser et al. (1978) guarantees that greedy selection achieves at least $(1 - 1/e)$ of the optimal value. The paper extends this to the dynamic setting:

> "Under the mild assumption, let $k$ denote the budget of space limitation. If for each token, we greedily compute the attention score based on top-$k$ choice, then we can show the set $\widetilde{S}_i$ we generate each for token $i$ satisfy that $f(\widetilde{S}_i) \geq (1-\alpha)(1-1/e) \max_{|S|=k} f(S) - \beta$, where $\alpha, \beta > 0$ are parameters."

In plain language: the greedy H2-based eviction policy achieves near-optimal cache composition, up to a small constant-factor degradation from the dynamic nature of the problem ($\alpha$) and a small additive error ($\beta$) from using approximate accumulated scores. The formal proof (Theorem D.32) sets $\alpha = \theta = \gamma$ where $\theta$ and $\gamma$ capture how much the optimal value degrades between consecutive steps of the dynamic process, and $\beta = n \cdot \epsilon_0$ where $\epsilon_0$ is the per-step approximation error of the accumulated score function relative to the true (future-aware) submodular function.

**Practical significance of the theory.** The theoretical guarantee does not mean H2O is optimal in practice — the submodularity assumption is approximate, and the constants are not tight. Rather, it provides a **principled justification** for why a simple greedy selection based on accumulated attention scores should work: if attention is roughly submodular, then greedy is provably near-optimal, and the dynamic extension handles the evolving nature of generation. This distinguishes H2O from purely heuristic cache policies (LRU, LFU) that have no theoretical relationship to the attention mechanism.

#### The H2O Eviction Policy: Algorithm and Mechanics

Here we describe the exact procedure that H2O executes at each decoding step. The informal version is Algorithm 1 in the main paper; the formal and complete version is Algorithm 2 in Appendix D (which we follow for precision).

**Input and parameters.** The algorithm takes as input:
- $Q \in \mathbb{R}^{n \times d}$: the query matrix (all queries computed so far)
- $K \in \mathbb{R}^{n \times d}$: the key matrix (all keys computed so far)
- $k \in \mathbb{N}$: the budget size of the KV cache (typically set to 20% of the prompt length)

The algorithm also maintains state:
- $S_{i-1}$: the set of token indices currently in the cache (initialized to $\emptyset$)
- $\widetilde{o}_{i-1}$: a vector of accumulated attention scores for all tokens seen so far

**Step-by-step procedure (for each token $i = 1 \ldots n$):**

**Case 1: Cache not full ($i \leq k$).** The cache has not yet reached its capacity. The algorithm simply adds the new token:

$$S_i \leftarrow S_{i-1} \cup \{i\}$$

No eviction occurs. The cache grows linearly until it reaches size $k$.

**Case 2: Cache full ($i > k$).** This is the steady-state regime where the algorithm must decide what to evict.

*Step 1: Compute attention with current cache.* The query for token $i$ attends to the keys currently in the cache:

$$D_i \leftarrow (\exp(Q_{i,*}(K_{S_{i-1},*})^\top) - \mathbf{1}_{[i] \setminus S_{i-1}}) \cdot \mathbf{1}_i$$

This computes the normalization constant, subtracting the contributions of tokens not in the cache (since their attention weights are zero but the exponential of zero is 1, these must be removed from the sum to maintain a proper softmax denominator).

$$o_i \leftarrow D_i^{-1} \cdot \exp(Q_{i,*}(K_{S_{i-1},*})^\top)$$

This produces the normalized attention weights $o_i$ for the tokens in $S_{i-1}$.

*Step 2: Update accumulated scores.*

$$\widetilde{o}_i \leftarrow \widetilde{o}_{i-1} + o_i$$

Each token's accumulated score is incremented by the attention weight it received at the current step. Tokens not in the cache (and therefore not in $o_i$) receive no increment — their accumulated score stays frozen until they are evicted.

*Step 3: Compute the score of the candidate set.* The set $G_i = S_{i-1} \cup \{i\}$ represents the candidate cache if we added the new token without evicting anything (size $k+1$). For each element $v \in G_i$, compute:

$$F_{\text{score}}(G_i \setminus \{v\})$$

where $F_{\text{score}}(T) := h(\sum_{s \in T} \widetilde{o}_{i,s})$. In the simplest case (Algorithm 1), $h(z) = z$ (the identity function), so this is just the sum of accumulated scores for the $k$ tokens that would remain after removing $v$.

*Step 4: Select victim for eviction.*

$$u \leftarrow \arg\max_{v \in G_i} F_{\text{score}}(S_{i-1} \cup \{i\} \setminus \{v\})$$

This chooses the token $u$ whose removal maximizes the score of the remaining set — equivalently, the token whose removal causes the smallest decrease in total accumulated attention score. In the identity-$h$ case, this simplifies to removing the token with the smallest accumulated score among the $k+1$ candidates.

*Step 5: Update cache.*

$$S_i \leftarrow (S_{i-1} \cup \{i\}) \setminus \{u\}$$

The new token is added, and the least valuable token (by accumulated attention) is evicted. The cache size remains exactly $k$.

**What makes this a "heavy hitter" policy?** The accumulated score $\widetilde{o}_{i,s}$ acts as a persistent value estimate: tokens that have received large attention weights across many decoding steps will have large accumulated scores and will therefore be retained. Tokens that received attention early on but have been ignored recently will see their relative accumulated score decline as new tokens accumulate more attention, potentially leading to their eventual eviction. The policy is "greedy" because at each step it makes the locally optimal decision based on current accumulated scores, without planning for future attention patterns.

**The role of the concave function $h$ (Remark D.14).** In Algorithm 1 (the simplified presentation), $h(z) = z$ is used for clarity. However, Appendix D explains that choosing a concave function like $h(z) = \sqrt{z+1}$ or $h(z) = \log(z+1)$ is important for the theoretical guarantee, because it makes the score function submodular. With $h(z) = z$, the score function is linear (modular), which is technically submodular but does not capture the diminishing returns property that makes greedy selection provably near-optimal. The concave transformation means that adding the same amount of accumulated attention to a token that already has high accumulated attention provides less marginal value than adding it to a token with low accumulated attention — this is precisely the diminishing returns property.

**Local vs. global statistics (Figure 2d).** The paper empirically compares two variants:
- **Global statistic:** uses accumulated attention scores computed from the *entire* generation sequence, including future tokens. This is infeasible in practice (you can't know future attention patterns) but serves as an oracle upper bound.
- **Local statistic:** uses accumulated attention scores computed only from tokens generated *so far* — the actual deployable version.

Figure 2(d) shows that the local statistic performs nearly identically to the global statistic, both closely tracking the "Full KV" baseline. This is a critical empirical finding: it means the heavy hitters that are important for future generation are **predictable from past attention patterns** alone. The tokens that will be important in the future are largely the same tokens that have been important in the past — attention importance is persistent, not transient. This persistence is what makes the greedy local policy work.

**Why not just keep the top-k by accumulated attention?** A natural alternative would be to simply keep the $k$ tokens with the highest accumulated attention scores, ignoring recency entirely. The paper addresses this implicitly through the dual-region design (Section 4.1 states that H2O combines heavy hitters and recent tokens). The ablation in Table 9 and Section 5.3 (Q4) shows that keeping *only* heavy hitters or *only* recent tokens is inferior to keeping both: the "w. Local" (recent-only) column shows performance drops of 2.85% to 22.75%, and "w. H2" (heavy-hitter-only) is better but still worse than the combined policy. The recent tokens capture local syntactic and semantic coherence that heavy hitters alone may miss (e.g., the beginning of a new clause that hasn't had time to accumulate much attention yet but is structurally important for the next few tokens).

#### System Implementation Details

The theoretical algorithm is straightforward, but making it fast in practice requires careful engineering to avoid memory overhead and I/O bottlenecks. The paper implements H2O on top of FlexGen (Sheng et al., 2023), a state-of-the-art inference engine for single-GPU LLM deployment, and describes key implementation choices in Section 4.2 and Appendix A.

**Memory layout for the dual-region cache.** The KV cache is preallocated as a contiguous block of GPU memory to avoid dynamic allocation overhead. It is logically split into two regions:
- **Heavy-hitter region (first $K$ slots):** stores the KV embeddings for the top-$K$ tokens by accumulated attention score. These entries are not ordered — when a new heavy hitter displaces an existing one, it fills the evicted token's slot directly.
- **Recent-token region (last $K$ slots):** managed as a **circular queue**. The oldest recent token is always the one evicted when a new token needs to enter this region, regardless of its attention score. This ensures that the most recent $K$ tokens are always available.

The total cache size is $2K$ (heavy hitters + recent tokens). When the paper reports "20% budget," this typically means $K$ is 10% of the full sequence length for heavy hitters and 10% for recent tokens, totaling 20%.

**I/O efficiency: no data movement on eviction.** A naïve implementation would shift all subsequent entries when a middle slot is freed, or would maintain indirection. The H2O implementation does neither: when a heavy hitter is evicted from slot $j$, the new token's KV embeddings are written directly into slot $j$, overwriting the old data. This means **eviction is a single memory write** — no data movement, no compaction, no pointer updates. The attention computation iterates over the cache linearly; empty slots would cause problems, but the cache is always full (it grows to capacity and stays there), so every slot always contains valid data.

**Preallocation.** All memory for the KV cache is allocated once at the start of inference. This eliminates per-step allocation overhead and ensures that the GPU memory footprint is constant and predictable throughout generation — an important property for production systems where memory fragmentation can cause out-of-memory errors at unpredictable times.

**Integration into FlexGen.** FlexGen is a white-box implementation of OPT models that orchestrates I/O between GPU and CPU memory with overlapped computation. H2O modifies the attention forward pass in FlexGen's `compute_layer()` function:
- During **prefill** (processing the input prompt), the function `compute_attention()` selects the top-$K$ heavy hitters and $K$ most recent tokens from the prompt's KV cache if the prompt length exceeds $2K$, otherwise returns all KV embeddings.
- During **decoding** (generating new tokens), the same function computes new KV embeddings for the current token and returns eviction indices that identify which cache slots will be overwritten.

The `store_cache()` function implements the circular queue for recent tokens: it computes `oldest = ((i-1) % K) - K` (where indexing from the end of the cache represents the recent-token region) and uses this as the eviction target for the oldest recent token. The heavy-hitter eviction indices are computed by the attention function itself based on accumulated scores.

**Computational overhead.** The H2O eviction policy adds minimal computation to each decoding step: maintaining the accumulated attention scores (one addition per cached token per step), finding the minimum among $2K+1$ numbers (for eviction), and the small overhead of managing the circular queue index. Compared to the cost of computing attention itself ($O(K \cdot d)$ for the cached tokens), this overhead is negligible. The paper's throughput results (Tables 3-5) include this overhead in the end-to-end measurements.

**Compatibility with quantization (Section 5.3, Q3).** H2O operates on the KV cache entries themselves, not on the computation that produces them. This means it is orthogonal to weight quantization (e.g., 4-bit weights). The paper demonstrates in Table 6 that combining H2O with 4-bit quantization preserves accuracy, and in Table 7 that it further improves throughput by allowing larger batch sizes (since quantized weights free GPU memory that can be used for the KV cache of additional batch elements).

#### Theoretical Analysis and Guarantees

The paper provides a substantial theoretical analysis in Appendix D, building on the dynamic submodular formulation. Here we walk through the key theoretical results and the assumptions they require.

**Assumption: Submodularity of the attention-based score function (Section D.7).** The theoretical guarantee depends on the assumption that the score function $F_{\text{score}}$ (which aggregates accumulated attention scores over a set of tokens) is submodular. The paper provides an intuitive justification: attention exhibits diminishing returns because adding a token to a small set of already-attended tokens provides more novel information than adding it to a large set that may already contain semantically similar tokens. The concave transformation $h$ (e.g., $h(z) = \sqrt{z+1}$) is specifically chosen to induce submodularity even if the raw accumulated scores are linear.

**Definition D.25: Universal Dynamic Condition 1 (for exact function).** This assumption states that the value of the cache does not degrade too rapidly when the cache composition changes by one token between steps. Formally, for all $i \in [n]$, for all $S_i \subseteq [i-1]$, $S_{i-1} \subseteq [i-2]$, with $|S_i \setminus S_{i-1}| \leq 1$:

$$f_{S_i,i}(S_i) \geq (1-\theta) \cdot f_{S_{i-1},i-1}(S_i)$$

where $\theta \in (0,1)$ is a small constant. This says: when we move from step $i-1$ to step $i$ and the cache changes by at most one element, the value of the cache (as evaluated by the new step's submodular function) does not drop by more than a factor $(1-\theta)$. Without this condition, the dynamic nature of the problem could cause the optimal value to change arbitrarily between steps, making any policy with a static budget impossible to bound.

**Definition D.28: Universal Dynamic Condition 2.** The optimal achievable value $\text{opt}_i$ (defined in Definition D.27 as the maximum possible score using any size-$k$ cache at step $i$) does not degrade too rapidly between steps:

$$\text{opt}_i \geq (1-\gamma) \cdot \text{opt}_{i-1}$$

This is a weaker condition: it only says the best possible cache at step $i$ is almost as good as the best possible cache was at step $i-1$, which is reasonable since the set of available tokens only grows (more tokens have been seen).

**Lemma D.29: Induction lemma for exact function.** This is the core technical lemma that builds the guarantee by induction over decoding steps. It assumes the three conditions above (submodularity, Dynamic Condition 1, Dynamic Condition 2) and a base case that at step $i$, the current cache $S_i$ has value at least $(1-1/e)(1-\theta)^i(1-\gamma)^i \text{opt}_i$. It then proves that after one step of greedy eviction (Definition D.20), the updated cache $S_{i+1}$ achieves value at least $(1-1/e)(1-\theta)^{i+1}(1-\gamma)^{i+1} \text{opt}_{i+1}$.

**What the lemma computes:** It shows that greedy selection preserves a near-optimality invariant, where the approximation factor degrades geometrically by $(1-\theta)(1-\gamma)$ per step. Over $n$ steps, the total degradation is $(1-\theta)^n(1-\gamma)^n$, which can be bounded by choosing $\theta$ and $\gamma$ sufficiently small (e.g., $\theta = \gamma = \alpha/(10n)$ for desired final approximation $\alpha$).

**Lemma 3.1 (formal version Lemma D.31): Full-knowledge guarantee.** If we have access to the exact attention scores for all future tokens (the "full knowledge" or "global statistic" setting), then greedily constructing the cache achieves:

$$f(S_i) \geq (1-1/e) \cdot (1-\alpha) \cdot \text{opt}_i$$

This is essentially the classic submodular maximization guarantee, with an additional $(1-\alpha)$ factor from the dynamic degradation over $n$ steps.

**Theorem 4.4 (formal version Theorem D.32): Limited-cache, approximate-function guarantee.** This is the practical guarantee for the deployable H2O algorithm (using only past-token statistics and approximate accumulated scores). Under the same assumptions plus a per-step approximation error $\epsilon_0$ for the accumulated score function, the greedy H2 policy achieves:

$$f(\widetilde{S}_i) \geq (1-1/e) \cdot (1-\alpha) \cdot \text{opt}_i - \beta$$

where $\beta = n \cdot \epsilon_0$ accounts for the accumulated approximation error over all $n$ steps. This is proved in Lemma D.30 (the induction lemma for approximate functions), which is identical to Lemma D.29 but carries an additive error term $-i \cdot \epsilon_0$ that grows linearly with the step count.

**What these guarantees mean in practice.** The theoretical analysis does not provide tight numerical bounds (the constants $\alpha, \beta, \theta, \gamma$ are not quantified empirically). Rather, it provides a **structural explanation** for why H2O works:
1. If attention scores are roughly submodular (diminishing returns), then greedy selection is provably near-optimal.
2. The dynamic nature of generation introduces geometric degradation per step, but this can be controlled if the optimal cache value doesn't change too rapidly between steps.
3. Using approximate (past-only) scores introduces linear error accumulation, but this is bounded if the per-step approximation is small.
4. The total approximation factor $(1-1/e)(1-\alpha)$ minus a small additive error is the best one can hope for in a dynamic, budget-constrained setting.

The theory also explains *why* H2O outperforms heuristics like LRU: LRU makes decisions based purely on recency, which has no necessary relationship to submodular value in the attention score function. By contrast, H2O's decisions are based on the accumulated attention scores, which are precisely the marginal gains in the submodular formulation — greedy selection with respect to the right value function is provably better than arbitrary heuristics.

#### Loss Function Design for Sparse Attention Training (Appendix D.17–D.22)

The paper includes a theoretical section (Sections D.17–D.22) that proposes a loss function designed to induce heavy-hitter-like sparsity patterns during training, and proves that a greedy-type Newton method can optimize it efficiently. This is not part of the H2O inference algorithm itself — it is a proposal for future work on training models that are inherently more amenable to KV cache sparsification. However, it provides deeper insight into why heavy hitters emerge and how they might be encouraged.

**Definition D.41: Sparsity penalty.** The proposed loss function adds an $\ell_1$-type sparsity penalty to the standard softmax regression loss:

$$L_{\text{sparse}}(x) := \|\exp(Ax)\|_1$$

where $A \in \mathbb{R}^{n \times d}$ is the input matrix and $x \in \mathbb{R}^d$ is the parameter vector.

**What this computes:** This is the sum of all exponentiated logits, which is exactly the normalization constant of the softmax function (Claim D.42: $L_{\text{sparse}}(x) = \alpha(x)$). By penalizing this sum, the loss encourages the softmax distribution to be more concentrated (sparser) — if the sum of exponentiated values is small, then the softmax must concentrate its probability mass on fewer positions.

**Why this form:** Standard $\ell_1$ regularization penalizes $\|Ax\|_1$, which encourages the *pre-softmax* logits to be sparse. But sparsity in logit space does not directly translate to sparsity in probability space (a small logit can still contribute non-trivial probability after softmax, and vice versa). The $\|\exp(Ax)\|_1$ penalty directly penalizes the *denominator* of the softmax, which means it explicitly encourages the probability distribution to have fewer large entries — exactly the heavy-hitter property.

**Total loss (Definition D.43):**

$$L(x) := L_{\text{exp}}(x) + L_{\text{sparse}}(x) + L_{\text{reg}}(x)$$

where $L_{\text{exp}}(x)$ is the standard softmax regression loss (fitting attention outputs to targets), $L_{\text{sparse}}(x)$ is the sparsity penalty, and $L_{\text{reg}}(x) = 0.5 \cdot \|\text{diag}(w)Ax\|_2^2$ is a weighted $\ell_2$ regularization term that ensures the Hessian is positive definite (Lemma D.47).

**Theoretical properties proved:**
- **Lemma D.47:** The Hessian $H(x) = A^\top(B(x) + W^2)A$ is positive definite when the regularization weights $w_i^2$ are sufficiently large (specifically, $w_i^2 \geq 200 \cdot \exp(R^2) + l/\sigma_{\min}(A)^2$, where $R$ bounds $\|x\|_2$ and $l > 0$ is the desired convexity lower bound). Positive definiteness guarantees that the optimization problem has a unique global minimum and that Newton's method converges quadratically.
- **Lemma D.48:** The Hessian is Lipschitz continuous with constant $n^2 \exp(40R^2)$, which is another standard condition for Newton's method convergence.
- **Theorem D.49:** A randomized approximate Newton method (Algorithm 4) can find an $\epsilon$-approximate optimal solution in $\log(\|x_0 - x^*\|_2 / \epsilon)$ iterations, each taking $O((\text{nnz}(A) + d^\omega) \cdot \text{poly}(\log(n/\delta)))$ time, where $\omega$ is the matrix multiplication exponent (currently ~2.373).

**Relevance to H2O.** This theoretical section shows that the heavy-hitter property is not just an empirical curiosity — it can be *designed into* the training objective. A model trained with this sparsity-inducing loss would presumably have even more concentrated attention patterns, making H2O even more effective. The paper does not actually train such a model (H2O is applied to existing densely-trained models), but this analysis provides a theoretical foundation for future work on co-designing training objectives and inference-time cache policies.

#### Summary of Design Choices and Their Justifications

- **Dual-region cache (heavy hitters + recent tokens)** over pure-heavy-hitter or pure-recent: Ablation (Table 9) shows both components are necessary — heavy hitters provide long-range coherence, recent tokens provide local syntactic structure.

- **Accumulated attention scores as the value function** over per-step attention scores: Accumulation captures persistent importance across many decoding steps. A token that receives moderate attention at every step will outrank a token that received high attention once and then was ignored — which is the desired behavior for a cache that must serve many future queries.

- **Concave transformation $h$ of accumulated scores** over raw linear summation: Introduces diminishing returns, making the score function submodular and enabling the theoretical guarantee (Theorem D.32). Without this, the score function would be modular (linear), which is trivially submodular but does not capture the diminishing returns intuition; the concave transformation makes the submodularity non-trivial and the greedy guarantee meaningful.

- **Greedy eviction (remove minimum-score token)** over more sophisticated combinatorial optimization: The greedy algorithm is simple enough to run at every decoding step with negligible overhead, and the submodularity guarantee ensures it is near-optimal under the stated assumptions. Exact optimization would be NP-hard and impractical for real-time inference.

- **Local (past-only) accumulated statistics** over global (future-aware) statistics: Future tokens are unavailable at inference time by definition. The empirical finding that local and global statistics produce nearly identical results (Figure 2d) justifies this choice — attention importance is persistent, so past attention patterns predict future ones.

- **In-place eviction (overwrite, no compaction)** over indirection or garbage collection: Minimizes memory bandwidth and avoids fragmentation. The preallocated, fixed-layout cache is critical for predictable GPU memory usage and consistent performance.

- **Integration with FlexGen** over a standalone implementation: FlexGen provides sophisticated I/O scheduling and offloading infrastructure. H2O's KV cache reduction complements these optimizations — FlexGen improves the efficiency of moving data between GPU and CPU, while H2O reduces the amount of data that needs to be moved in the first place.

## 4. Key Insights and Innovations

### Innovation 1: Reframing KV Cache Reduction as a Cache Eviction Problem Rather Than an Architectural or Training Problem

The dominant approaches to reducing transformer memory footprints prior to this work fell into two categories: architectural modifications (multi-query attention, sparse attention patterns baked into training) and attention approximation (low-rank, locality-sensitive hashing, kernel methods). Both categories require changing the model — either its architecture or its training procedure. H2O introduces a fundamentally different framing: **the KV cache is a classic cache, and the right way to shrink it is to design a better eviction policy**, not to change what is being cached.

This reframing is intellectually significant for several reasons:

**It decouples the memory problem from the model design problem.** Architectural approaches (Shazeer, 2019; Child et al., 2019) embed assumptions about attention sparsity into the model structure itself. If those assumptions are wrong for a particular task or input, the model is stuck with them. An eviction policy, by contrast, operates at deployment time and can adapt per-input, per-head, and even per-decoding-step. This means the same pre-trained model can use different cache policies for different deployment scenarios (latency-sensitive vs. throughput-sensitive, short-context vs. long-context) without retraining.

**It introduces the concept of "cache miss" to the LLM inference literature.** In classical caching, a miss occurs when requested data is not in the cache and must be fetched from slower storage. For KV caches, a miss is fundamentally more severe: evicted KV embeddings cannot be "fetched" from anywhere — they are permanently lost for the remainder of generation. The paper's problem formulation (Definition 2.2) makes this explicit by setting evicted tokens' attention weights to zero and adjusting the normalization constant. This irreversibility means that KV cache eviction is not a performance optimization with a quality trade-off — it is a **quality constraint** where each eviction decision has compounding consequences for all future tokens. The field had largely treated KV cache reduction as an approximation problem; recasting it as a caching problem with irreversible eviction surfaces the true stakes.

**It creates a new design space.** By treating the KV cache as a cache, a rich set of questions becomes relevant that were previously invisible: What is the access pattern (which tokens get "reused")? What is the optimal replacement policy under this access pattern? Can we prove guarantees analogous to Belady's optimal algorithm for standard caches? The paper answers these questions by identifying heavy hitters as the high-reuse tokens and proving near-optimality of greedy eviction under submodularity assumptions. This design space did not exist before because no one had asked the question in these terms.

This innovation is a **fundamental reframing**, not an incremental improvement. It does not propose a better way to do something the field was already doing — it proposes doing something the field was not doing at all (designing eviction policies for autoregressive generation), and shows that this new activity produces substantial gains.

---

### Innovation 2: The Discovery and Characterization of Heavy Hitters as a Persistent, Functionally Essential Attention Phenomenon

The paper does not merely observe that attention is sparse — that much was known from prior work (Likhosherstov et al., 2021; Edelman et al., 2022). The distinctive contribution is the identification of **heavy hitters (H2)** as a specific, measurable, and functionally critical category of tokens, along with the empirical characterization of their properties.

**What distinguishes H2 from generic attention sparsity:** Prior observations of attention sparsity showed that at any given step, most attention weights are near zero. But this per-step sparsity does not, by itself, tell you which tokens to keep in a cache — a token that is unimportant at step $t$ might become critical at step $t+100$. H2 are defined by **accumulated attention scores across all tokens and all layers**, which captures persistent importance rather than transient relevance. The paper shows that this accumulated distribution follows a power law (Figure 2b), meaning a very small number of tokens absorb a disproportionate share of total attention mass. These are not just "currently attended" tokens — they are tokens that the model returns to repeatedly throughout generation.

**The functional essentiality result (Figure 2c) is the key diagnostic move.** Rather than merely noting the correlation between accumulated attention and co-occurrence frequency, the paper asks a causal question: are heavy hitters actually necessary for the model to function? The ablation — removing H2 tokens and measuring the accuracy drop — answers this definitively: yes, removing them destroys performance. This converts the observation from a curiosity to a constraint. Any successful cache reduction method *must* retain H2 tokens, or it will break the model. This is a diagnostic insight that the field did not have before: the attention mass is not just concentrated, it is *functionally concentrated*, meaning the concentration reflects real computational necessity rather than slack that can be compressed away.

**The persistence property (Figure 2d, local vs. global comparison).** The finding that local (past-only) accumulated statistics nearly match global (all-step) statistics is not obvious a priori. One could imagine that which tokens become heavy hitters depends on the full generation context, including future tokens. The paper shows this is not the case: the tokens that will dominate attention in the future are largely predictable from their past attention patterns. This persistence is what makes H2O deployable — if heavy hitters shifted unpredictably, no past-data-based eviction policy could work. The fact that they are stable is an empirical discovery about how LLMs use attention during generation, not a design choice.

**Connecting H2 to co-occurrence frequency (Figure 2b, red scatter vs. gray curve).** The correlation between accumulated attention and training-data co-occurrence frequency provides a mechanistic hypothesis for *why* heavy hitters exist: they are tokens that co-occur with many other tokens, making them useful "anchor points" for attention. This is not proved causally (the paper does not manipulate co-occurrence statistics and measure H2 emergence), but it provides a satisfying explanatory bridge between training data statistics and inference-time attention patterns. It also suggests that H2 are not an artifact of a particular model or task — they should emerge in any model trained on natural language, because natural language has Zipfian word frequency distributions.

This innovation is a **discovery**, not an invention. The paper found something true about how LLMs work — that a small core of tokens dominate attention persistently and are functionally irreplaceable — and built a system around that discovery. The discovery is what makes the system simple: once you know that H2 exist and are both identifiable from past statistics and necessary to retain, the eviction policy writes itself.

---

### Innovation 3: Formulating KV Cache Eviction as Dynamic Submodular Maximization with Theoretical Guarantees

Prior work on efficient attention (sparse transformers, linear attention, hashing-based methods) provided either no theoretical guarantees or guarantees about approximation error relative to full attention, not about the optimality of token retention under a budget. The paper introduces a fundamentally new theoretical framework: **modeling the KV cache retention decision at each decoding step as maximizing a submodular set function under a cardinality constraint, where the function itself evolves dynamically as generation proceeds**.

**Why submodularity is the right structure, not just a convenient one.** The paper's argument (Section D.7) is that adding a token to a set of retained tokens exhibits diminishing returns: a token provides more marginal value when added to a small set than when added to a large set that already contains semantically similar tokens. This is an intuitive property of attention — if you've already kept several tokens that encode a particular concept, keeping another token encoding the same concept adds little. Submodular functions are precisely the class of functions with this diminishing returns property. The connection is not arbitrary; it follows from the nature of attention as an information-aggregation mechanism.

**What the theoretical guarantee actually provides (Theorem 4.4 / Theorem D.32).** Under assumptions of submodularity and controlled dynamic degradation, the greedy H2 eviction policy achieves at least $(1-1/e)(1-\alpha)$ times the optimal cache value minus a small additive error. The $(1-1/e) \approx 0.63$ factor is the classic Nemhauser et al. (1978) guarantee for monotone submodular maximization with a cardinality constraint. The $(1-\alpha)$ factor captures the fact that the problem is dynamic — the optimal cache at step $i$ may differ from the optimal cache at step $i-1$, and the greedy policy can only react to past data. The additive error $\beta$ captures approximation error from using accumulated rather than future-aware scores.

**This is a structural guarantee, not a numerical one.** The theorem does not claim that H2O achieves 63% of full-cache accuracy (it achieves ~100% on most tasks). Rather, it claims that among all possible size-$k$ caches, the one H2O selects is within a constant factor of the best possible one in terms of the submodular value function. The significance is not the specific constant but the **proof that greedy selection is a principled strategy** under assumptions that are plausible for attention. This distinguishes H2O from heuristic cache policies (LRU, LFU, random) that have no theoretical relationship to the attention mechanism and whose failure modes are unpredictable.

**The dynamic submodular framework as a reusable abstraction.** The paper defines (Definitions 4.1 / D.4 / D.3) a general framework for problems where a submodular function evolves as the set changes, and proves properties of greedy selection in this framework. This is not tied to KV caches — any problem where an agent must maintain a fixed-size subset of items under a dynamically changing submodular value function could use this analysis. The paper does not explore such generalizations, but the framework is laid out in sufficient generality (Appendix D) that future work could apply it to other streaming subset selection problems.

**The relationship between theory and practice.** The theoretical analysis explains *why* the simple greedy policy works so well (Section 5.1 shows it matches full-cache accuracy at 20% budget). In the absence of theory, one might dismiss the good empirical results as luck or dataset-specific. The theory provides a mechanistic explanation: if attention scores induce a submodular value function, greedy retention is near-optimal, so the empirical success is expected rather than surprising. This transforms H2O from "a heuristic that happens to work" to "an approximately optimal solution to a well-characterized problem."

This innovation is a **theoretical advance** that provides intellectual foundation for a new research direction. It is incremental in the sense that submodular maximization and greedy algorithms are well-studied, but fundamental in applying them to a new domain (KV cache eviction in autoregressive generation) and extending them to a dynamic setting with provable guarantees. The combination of theory and empirics — proving that greedy works, then showing it works — is stronger than either alone.

---

### Innovation 4: The Empirical Finding That Test-Time KV Cache Aggressiveness Can Match Full-Cache Performance, With Precise Characterization of When It Fails

The paper's central empirical result — that H2O with 20% KV cache budget matches full-cache accuracy across a wide range of models, tasks, and sequence lengths (Figure 4, Tables 1-2, Section 5.1) — is not just a benchmark score. It is a **discovery about the information content of the KV cache** that challenges a default assumption in LLM deployment.

**The default assumption prior to this work** was that reducing the KV cache size would necessarily degrade generation quality, because autoregressive generation requires attending to all previous tokens to maintain coherence. This assumption was reasonable: attention was designed to let each token access all previous tokens, and the fact that models were trained with full attention suggested they learned to rely on this full access. Prior methods that reduced attention coverage (sparse transformers applied post-hoc, fixed window attention) did indeed show substantial accuracy degradation (Table 2 shows drops of up to 35 percentage points for these methods at 20% budget). The natural inference was that the full cache was necessary.

**What H2O demonstrates is that the full cache is not necessary — but that *which* tokens you keep matters enormously.** The "Local" baseline (keeping only the most recent tokens) collapses at 20% budget, often performing near random chance on some tasks (e.g., Winogrande drops from 70.24% to 49.17% with OPT-30B in Table 2). H2O, keeping the same total number of tokens but selecting them based on accumulated attention, matches full-cache performance. The implication is that **the information in the KV cache is highly redundant: most tokens provide negligible marginal value beyond what is already captured by the heavy hitters and a small window of recent context.**

**The difficulty-dependent and task-dependent variation is an important nuance.** Figure 4 shows that H2O's effectiveness varies across tasks and model sizes. For some combinations (e.g., LLaMA-13B on XSUM, LLaMA-7B on CNN/Daily Mail), the "Local" baseline collapses even at 60% budgets while H2O matches full-cache at 20%. For others, H2O actually *exceeds* full-cache performance (OPT-66B on RTE: +0.73%; OPT-30B on MathQA: +0.64%; GPT-NeoX-20B on XSUM: +0.18). The authors interpret these "improvements" as a regularization effect — evicting low-value tokens may reduce noise or spurious correlations — but regardless of interpretation, they demonstrate that full-cache is not a strict upper bound on performance.

**The infinite-length extension (Section 5.3, Q1; Figure 5).** The finding that H2O can process sequences of up to four million tokens (when combined with StreamingLLM's position-rolling technique) while maintaining lower perplexity than StreamingLLM alone is a striking demonstration of the heavy-hitter concept's power. StreamingLLM (Xiao et al., 2023) keeps only the first few tokens (attention sinks) and a recent window. H2O adds heavy hitters to this mix. The perplexity improvement (Figure 5, bottom) shows that attention sinks are not the only persistent tokens — there exists a broader set of H2 tokens that carry information across very long contexts. This is a finding about the nature of long-context attention, not just a system optimization.

**The diversity bonus (Section 5.3, Q5; Appendix C.1; Figures 6-7).** The observation that H2O increases the diversity of generated text (lower Self-BLEU scores, fewer repeated phrases) is noted as a "bonus" but may be more significant than the authors claim. The full-cache model sometimes gets stuck in repetition loops (e.g., the LLaMA-7B example in Figure 7 repeating "so moving that," "so moved that," "began to cry"). H2O breaks these loops. A speculative explanation: the full cache gives the model access to its own recent repetitions, creating a positive feedback loop. Evicting some of those recent tokens forces the model to rely on the more diverse information in the heavy hitters, breaking the repetition. If this effect is robust, it suggests that KV cache reduction is not just a memory optimization but can also improve generation quality — a finding that inverts the usual quality-efficiency trade-off.

This innovation is **primarily empirical**, but its significance is conceptual: it establishes that the apparent information in the full KV cache is mostly redundant, and that a small, well-chosen subset recovers essentially all of it. This changes the default assumption from "we need the full cache unless proven otherwise" to "we can aggressively reduce the cache as long as we keep the heavy hitters and a recent window." The implication for future work is that efforts should focus on *identifying* the high-value tokens rather than on *approximating* the full attention computation.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The paper uses a combination of standard NLP benchmarks to evaluate H2O's impact on generation quality. From the HELM framework (Liang et al., 2022), the authors select **XSUM** (Narayan et al., 2018) and **CNN/Daily Mail** (Nallapati et al., 2016), both summarization datasets, evaluating on 1,000 test samples each. From the lm-eval-harness framework (Gao et al., 2021), they select six tasks: **COPA** (Roemmele et al., 2011), **MathQA** (Amini et al., 2019), **OpenBookQA** (Mihaylov et al., 2018), **PiQA** (Bisk et al., 2020), **RTE** (Wang et al., 2018), and **Winogrande** (Sakaguchi et al., 2021). Additionally, the paper evaluates on **AlpacaEval** (Li et al., 2023) and **MT-bench** (Zheng et al., 2023) for generation quality, and uses **PG-19** (Rae et al., 2020) for the infinite-length perplexity experiments. For attention sparsity analysis, the validation set of **Wiki-Text-103** is used.

- **Base model(s).** The experiments span three model families across a wide range of scales: **OPT** (Zhang et al., 2022) at 6.7B, 13B, 30B, and 66B parameters; **LLaMA** (Touvron et al., 2023) at 7B, 13B, and 30B parameters; and **GPT-NeoX-20B** (Black et al., 2022). This diversity is deliberate — the authors need to show that H2O's effectiveness is not specific to a particular architecture or training recipe, and the range of scales demonstrates that the heavy-hitter phenomenon persists from moderate (6.7B) to large (66B) models. OPT and LLaMA represent the two dominant open-source LLM families, and GPT-NeoX provides an additional architectural variant.

- **Metrics.** For downstream task evaluation, the primary metric is **accuracy (%)** — the fraction of test examples where the model's selected answer matches the ground truth. For summarization tasks (XSUM, CNN/Daily Mail), the paper reports performance scores from the respective evaluation frameworks (HELM). For the infinite-length streaming experiments, the metric is **perplexity** on the PG-19 test set. For generation diversity, the paper uses **Self-BLEU** (Zhu et al., 2018), where lower scores indicate more diverse outputs. For throughput experiments, the metric is **generation throughput (tokens/second)** , computed as the number of generated tokens divided by the total wall-clock time (prompt processing + decoding).

- **Baselines.** The paper compares against several baselines:
  - **Full KV cache**: The unmodified model with all KV embeddings retained, representing the accuracy upper bound.
  - **"Local" strategy**: Keeping only the most recent KV embeddings, filling the entire cache budget with the latest tokens. This tests whether recency alone is sufficient.
  - **Sparse Transformer (strided)**: The fixed strided attention pattern from Child et al. (2019), applied post-hoc to a densely trained model. This tests whether training-agnostic sparse patterns can recover full-cache accuracy.
  - **Sparse Transformer (fixed)**: A fixed local window attention pattern, also from Child et al. (2019), applied post-hoc.
  - **Top-K**: Keeping the K tokens with the highest per-step attention scores (without accumulation across steps). This tests whether instantaneous attention scores are sufficient for cache retention decisions.
  - **SpAtten** (Wang et al., 2021): A prior method that accumulates attention scores across attention heads and layers to select important tokens, included as a direct comparison in Appendix C.9.
  - For throughput experiments, the baselines are **DeepSpeed ZeRO-Inference** (Aminabadi et al., 2022), **Hugging Face Accelerate**, and **FlexGen** (Sheng et al., 2023) — three state-of-the-art inference systems with different offloading and scheduling strategies.
  - **StreamingLLM** (Xiao et al., 2023): For the infinite-length experiments, compared as the prior state-of-the-art for handling sequences beyond training length.

- **Generation budget / compute accounting.** The KV cache budget is expressed as a **percentage of the prompt's length**. For example, "20% budget" means the total cache stores KV embeddings for 20% as many tokens as the full sequence would require. The cache is split evenly between heavy hitters and recent tokens (10% each), unless otherwise specified. For throughput experiments, the budget is measured implicitly — H2O with 20% budget can support larger batch sizes and longer sequences than the full-cache baselines, and throughput comparisons are at the maximum batch size each system can support without out-of-memory errors (or with equivalent offloading configurations). All throughput numbers include both prompt processing and decoding time, and include the computational overhead of H2O's eviction policy.

- **Cross-validation / statistical protocol.** The paper does not employ formal cross-validation or statistical significance testing for the main accuracy results. Results are reported as point estimates (accuracy percentages) on the standard test sets. For the throughput experiments, numbers are measured on a single GPU (NVIDIA T4 16GB or NVIDIA A100 80GB). The infinite-length perplexity comparison (Figure 5) uses the first text sample from PG-19 as a case study rather than a statistical aggregate.

### Main Quantitative Results

#### Accuracy Preservation Under Aggressive KV Cache Reduction

The headline result is that H2O with **20% KV cache budget matches or exceeds full-cache accuracy** across a wide range of models and tasks, while the "Local" (recent-only) baseline collapses to near-random performance on many tasks at the same budget.

**Figure 4** presents the core accuracy comparisons across six tasks (COPA, MathQA, RTE, OpenBookQA, XSUM, CNN/Daily Mail) and multiple model scales (OPT-30B, OPT-66B, LLaMA-7B, LLaMA-13B, LLaMA-30B, GPT-NeoX-20B). The pattern is consistent: H2O (blue bars) tracks the "Full" baseline (gray bars) closely at budgets of 20%, 60%, and even 4-10% in many cases, while "Local" (orange bars) degrades sharply as budget decreases. Specific examples from the figure:

- **OPT-30B on COPA**: Full cache achieves 85.00%. H2O at 20% achieves 84.00%. Local at 20% drops to 48.00%.
- **OPT-30B on OpenBookQA**: Full cache achieves 43.20%. H2O at 20% achieves 43.00%. Local at 20% drops to 25.20%.
- **OPT-66B on RTE**: Full cache achieves approximately 67.3%. H2O at 20% achieves approximately 68.0% (a +0.73% improvement over full cache). Local at 20% drops to approximately 56%.
- **LLaMA-13B on XSUM**: Here the pattern is particularly stark — the "Local" strategy *collapses* even at 60% budget (performing far below full cache), while H2O at 20% matches full cache. This is one of the cases the authors highlight as evidence that H2 is critical for some model-task combinations.
- **GPT-NeoX-20B on XSUM**: H2O at 20% achieves +0.18 improvement over full cache.

**Table 1** provides a quantitative comparison between H2O with 20% budget and full-cache baselines with different numbers of shots. For OPT-30B on 5-shot tasks, H2O with 20% cache achieves 79.22% on PiQA (vs. 80.09% full), 85.00% on COPA (vs. 81.00% full — an improvement), 43.80% on OpenBookQA (vs. 44.80% full), and 71.67% on Winogrande (vs. 71.51% full — essentially tied). Critically, H2O with 20% cache (which uses approximately 1.2 samples per input on average due to the smaller cache enabling longer effective sequences) outperforms both 0-shot full (78.89%, 76.00%, 41.40%, 70.00%) and 1-shot full (79.11%, 76.00%, 43.60%, 70.24%) on COPA, OpenBookQA, and Winogrande, demonstrating that the few-shot information retained via heavy hitters is more valuable than simply having more examples but losing key tokens.

**Table 2** shows H2O's ability to *enhance* existing sparsification baselines. On OPT-30B with 20% budget, Sparse Transformer (strided) without H2 achieves only 50.00% on COPA (vs. 85.00% full) — a catastrophic 35-point drop. Adding H2 (keeping heavy hitters in addition to the strided pattern) recovers to 83.00%. Similarly, Sparse Transformer (fixed) drops to 61.00% on COPA without H2, but recovers to 76.00% with H2. This pattern holds across all four tasks tested (COPA, OpenBookQA, PiQA, Winogrande). The implication is that H2 tokens are not just an alternative to sparse attention patterns — they capture information that fixed sparse patterns fundamentally miss, and combining both approaches yields near-full-cache performance.

#### Throughput and Latency Improvements

The paper demonstrates that H2O's memory savings translate directly into substantially higher throughput and lower latency, with the magnitude of improvement depending on the baseline system and the memory pressure of the workload.

**Table 3** reports generation throughput (tokens/second) on an NVIDIA T4 GPU (16GB) with synthetic datasets at varying sequence lengths. Key comparisons:

- **OPT-6.7B, 512 prompt + 1024 generation**: Accelerate achieves 5.6 tokens/s (batch size 16, requiring CPU offloading). DeepSpeed achieves 10.1 tokens/s (batch size 16, CPU). FlexGen achieves 16.9 tokens/s (batch size 1, GPU only). H2O at 20% achieves **52.1 tokens/s (batch size 4, GPU only)** — a 3.1× improvement over FlexGen, 5.2× over DeepSpeed, and 9.3× over Accelerate, while running purely on GPU without offloading.
- **OPT-30B, 512 prompt + 32 generation**: Accelerate achieves 0.6 tokens/s (batch size 8, CPU). DeepSpeed achieves 0.6 tokens/s (batch size 4, CPU). FlexGen achieves 8.1 tokens/s (batch size 144, CPU). H2O at 20% achieves **12.7 tokens/s (batch size 728, CPU)** — a 1.6× improvement over FlexGen in throughput, but with a **5× larger batch size** (728 vs. 144). The larger batch size is the direct result of KV cache memory savings.
- **OPT-6.7B, 512 prompt + 32 generation**: H2O achieves 35.1 tokens/s (batch size 4, GPU) vs. FlexGen's 20.2 (batch size 2, GPU), Accelerate's 20.4 (batch size 2, GPU), and DeepSpeed's 10.2 (batch size 16, CPU — notably, DeepSpeed requires CPU offloading for 16 batches while H2O fits 4 batches on GPU).

The throughput improvements are most dramatic when H2O eliminates the need for CPU offloading entirely. For OPT-6.7B with long generation (512+1024), both Accelerate and DeepSpeed require CPU offloading (batch sizes of 16), FlexGen can only support batch size 1 on GPU, while H2O supports batch size 4 purely on GPU — the combination of avoiding offloading overhead and supporting larger batches yields the 3-9× improvements.

**Table 4** replicates the throughput comparison on a real-world dataset (XSUM) rather than synthetic padded sequences. The pattern holds: on OPT-6.7B, H2O achieves 30.40 tokens/s vs. FlexGen's 10.80 (2.8×), Accelerate's 11.98 (2.5×), and DeepSpeed's 3.52 (8.6×). On OPT-30B, H2O achieves 6.70 tokens/s vs. FlexGen's 3.29 (2.0×). The real-world results confirm that the throughput gains are not an artifact of synthetic uniform-length sequences.

**Table 5** extends the evaluation to an NVIDIA A100 GPU (80GB) with sequence lengths up to 10K tokens, testing H2O's potential for future models trained on longer contexts (OPT itself was trained on 2K context). At 2048 prompt + 2048 generation tokens with OPT-6.7B:
- With batch size 24, H2O reduces latency from FlexGen's 99.5 seconds to **53.5 seconds (1.9× reduction)** .
- With the same batch size 24, H2O achieves 918.9 tokens/s throughput vs. FlexGen's 494.1 (1.9× improvement).
- With batch size 64, H2O achieves 1161.0 tokens/s — a batch size and throughput **unattainable by FlexGen** (out of memory).

At extreme sequence lengths (7000 prompt + 1024 generation with OPT-30B, batch size 1), H2O reduces latency from 57.0s to 50.4s (1.1×). The smaller improvement here reflects that at batch size 1 with extreme lengths, the KV cache is a smaller fraction of total memory (model parameters dominate), so the memory savings have less impact.

#### Infinite-Length Streaming

**Figure 5** demonstrates H2O's ability to handle sequences vastly longer than the training context. The experiment uses the StreamingLLM framework (Xiao et al., 2023), which enables infinite-length generation by retaining initial "attention sink" tokens and using position rolling. The authors augment this with H2O's heavy-hitter retention.

The upper panel shows that H2O successfully processes inputs with sequence lengths of **four million tokens** — approximately 2,000× longer than OPT's training context of 2,048 tokens. The lower panel provides a perplexity comparison on the first text sample of PG-19 between StreamingLLM and H2O-enhanced StreamingLLM, across various cache sizes (measured as number of retained tokens, from 256 to 2048). At every cache size, H2O achieves **lower perplexity** than the original StreamingLLM. For example, at a cache size of 512 tokens, the H2O perplexity is visibly lower (the exact numerical values are not explicitly stated in the text, but the figure shows a consistent gap). The interpretation is that StreamingLLM's fixed retention policy (first few tokens + recent window) loses important mid-sequence information that H2O's dynamic heavy-hitter retention preserves.

This result is significant because it addresses a known limitation of StreamingLLM: the initial-token retention policy is task-agnostic and can drop critical information that happens to fall in the middle of long documents. The multi-document QA experiment (Appendix C.4, Figure 9) demonstrates this concretely — when key information is in a middle document that StreamingLLM evicts, accuracy drops, while H2O retains it because the relevant tokens accumulate high attention scores.

### Ablation Studies and Robustness Checks

**Heavy hitters vs. recent tokens — separate contributions (Table 9, Appendix C.6):** The paper ablates the two components of H2O's retention policy by evaluating OPT-13B and OPT-30B on PiQA, OpenBookQA, MathQA, and Winogrande with three cache configurations: only heavy hitters, only recent tokens (local), and both (full H2O). Keeping only heavy hitters outperforms keeping only recent tokens across all eight model-task combinations (e.g., OPT-30B on PiQA: H2-only = 67.25% vs. Local-only = 55.82%; on OpenBookQA: H2-only = 26.60% vs. Local-only = 25.20%). However, neither alone matches full-cache performance. The combined H2O (both H2 and local) matches or nearly matches full cache: 78.45% vs. 78.51% on PiQA, 43.00% vs. 43.20% on OpenBookQA, 26.87% vs. 26.23% on MathQA, 69.06% vs. 70.24% on Winogrande. This confirms that the two components are complementary — heavy hitters provide long-range coherence, recent tokens provide local structure.

**Compatibility with quantization (Table 6, Section 5.3 Q3):** H2O is tested in combination with 4-bit weight quantization on OPT-30B across COPA, OpenBookQA, and PiQA. The full-cache baselines: 85.00% (COPA), 43.20% (OpenBookQA), 78.51% (PiQA). H2O alone: 84.00%, 43.00%, 78.45%. Quantization alone: 84.00%, 43.28%, 78.67%. H2O + Quantization: 84.00%, 43.20%, 78.80%. The combination **consistently achieves accuracy equal to or better than either technique alone**. On PiQA, H2O + Quant (78.80%) slightly exceeds full-cache accuracy (78.51%). This is a non-obvious finding — sparsity and quantization are often seen as competing sources of error that compound when combined (Han et al., 2015), but here they appear to be complementary or even synergistic. Table 7 further shows that the combined approach enables dramatic batch size increases: with 4-bit quantization, H2O supports batch size 70 (vs. 4 without quantization) on OPT-6.7B with 512+32 sequences, yielding 50.5 tokens/s throughput (vs. 35.1 without quantization).

**Enhancing the "Top-K" baseline (Table 8, Appendix C.5):** The paper tests whether the H2 accumulation approach outperforms a simpler "Top-K" baseline that selects tokens based on instantaneous (single-step) attention scores rather than accumulated scores. On OPT-30B with 20% budget: TopK without H2 achieves 80.00% on COPA, 41.40% on OpenBookQA, 76.96% on PiQA, 65.35% on Winogrande. TopK with H2 achieves 82.00%, 42.80%, 77.96%, 66.48% — consistent improvements of 1-2 percentage points. While the paper frames this as "H2 enhances TopK," the more direct interpretation is that accumulated scores (H2) outperform instantaneous scores (TopK) for cache retention decisions, which is expected since accumulated scores capture persistent importance rather than transient relevance.

**Effectiveness across different numbers of shots (Table 10, Section 5.3 Q2):** H2O is tested with both 5-shot and 10-shot prompts on OPT-30B and OPT-66B across OpenBookQA, COPA, and MathQA. Across all configurations, H2O with 20% budget achieves accuracy within 1 percentage point of full cache (e.g., OPT-66B 10-shot OpenBookQA: H2O = 44.80% vs. Full = 44.80%; OPT-30B 10-shot COPA: H2O = 85.00% vs. Full = 86.00%). The "Local" baseline degrades substantially in all cases (e.g., OPT-66B 10-shot COPA: Local = 76.00% vs. Full = 85.00%). This confirms that H2O's effectiveness is not an artifact of a particular prompt length or number of examples.

**Zero-shot and one-shot inference (Figure 8, Appendix C.3):** On LLaMA-7B with zero-shot and one-shot prompts, H2O successfully maintains full-cache accuracy at 20% budget for most tasks, though some tasks (the paper notes without specifying which) require 30-40% budget. The authors attribute this to shorter sequence lengths in 0/1-shot settings (100-300 tokens), meaning the budget percentage translates to a very small absolute number of retained tokens.

**Comparison with SpAtten (Table 11, Appendix C.9):** On OPT-30B with COPA, OpenBookQA, and PiQA, H2O outperforms SpAtten (Wang et al., 2021), a prior method that accumulates attention scores across heads and layers: 84.00% vs. 82.00% on COPA, 43.00% vs. 41.90% on OpenBookQA, 78.45% vs. 77.06% on PiQA. The paper attributes H2O's advantage to its per-head, per-layer independent retention decisions (SpAtten aggregates scores across heads and layers, losing granularity).

**Comparison with StreamingLLM on long-document tasks (Figure 9, Appendix C.4):** On multi-document QA (where key information is placed at varying positions) and text summarization (XSUM, CNN/Daily Mail), StreamingLLM's fixed retention of initial tokens causes consistent performance degradation, while H2O maintains accuracy closer to the full-cache baseline. The figure shows multiple H2O configurations (e.g., H2O-256-256 meaning 256 heavy hitters + 256 local tokens) consistently outperforming StreamingLLM equivalents.

**Generation diversity (Figures 6-7, Appendix C.1):** The paper provides qualitative examples showing that H2O generates more diverse text than the full-cache model. With OPT-6.7B, the full model generates text with redundant phrases ("a few years after the events of the first game"), while H2O produces more varied content ("the game is a first-person exploration game"). The "Local" baseline at 20% budget collapses into repetitive punctuation and whitespace. With LLaMA-7B, the full model repeats "so moving that," "so moved that," "began to cry" in a loop, while H2O produces coherent, non-repetitive text. Quantitatively, Self-BLEU scores on 100 XSUM samples: Full = 0.0057, H2O = 0.0051, Local = 0.0436. Lower Self-BLEU for H2O indicates slightly more diverse outputs than the full model.

**Heavy hitters in MLP blocks (Figures 11-13, Appendix C.10):** The paper extends the H2 analysis to MLP blocks, finding that neuron activation frequencies also follow a power-law distribution (Figure 11), with a small number of neurons activated by nearly all input tokens. Removing these neurons degrades perplexity from 19.32 to 31.78, but fine-tuning on as little as 1% of training data recovers to 19.86 (Table 12). The H2 neurons show high overlap across different input datasets (Wiki-Text-103, Penn Treebank, Amazon Review; Figure 12) and emerge early in training (within 4% of the training budget; Figure 13). These findings are not directly part of the H2O KV cache method but suggest the heavy-hitter phenomenon is a general property of transformer representations, potentially exploitable for broader model compression.

### Critical Assessment

The experiments collectively provide strong support for the paper's central practical claim — that H2O with 20% KV cache budget matches full-cache accuracy across many tasks while enabling substantial throughput improvements — but several important limitations and open questions remain.

**Claim: H2O matches full-cache accuracy at 20% budget.** The evidence for this claim is extensive across model families, scales, and task types (Figures 4, Tables 1, 2, 8, 10). However, the claim should be qualified in two ways. First, the per-task variation is non-trivial: while most tasks show near-identical accuracy between H2O-20% and Full, some require higher budgets (the paper mentions 30-40% for certain zero-shot tasks in Appendix C.3, though without specifying which tasks). Second, the experimental design uses a fixed 50-50 split between heavy hitters and recent tokens for the cache budget. The paper does not systematically sweep this ratio to determine whether 50-50 is generally optimal or task-dependent. Table 9 shows that both components contribute, but does not explore whether, for example, summarization tasks benefit from more recent tokens while reasoning tasks benefit from more heavy hitters.

**Claim: H2O achieves up to 29× throughput improvement over baseline systems.** The 29× figure comes from comparing H2O (OPT-6.7B, 512+1024, batch size 4, GPU-only, 52.1 tokens/s) against Accelerate (batch size 16, CPU offloading, 5.6 tokens/s) in Table 3 — a 9.3× improvement, not 29×. The 29× figure appears to come from the comparison against Accelerate on a different configuration (512+32, OPT-30B, where Accelerate achieves 0.6 tokens/s with CPU offloading and H2O achieves 12.7 tokens/s with CPU offloading — a 21× improvement, still not 29×). The paper also cites 29× against DeepSpeed for OPT-30B. It's likely the 29× number comes from a specific configuration not fully reported in the tables (perhaps including both throughput and batch size scaling). This inconsistency weakens the headline claim: the actual throughput improvements, while substantial (1.6-3.1× against FlexGen, 1.1-5.2× against DeepSpeed, 1.1-9.3× against Accelerate), are lower than 29× in most configurations.

**Claim: H2O enables processing of four million tokens.** Figure 5 (upper panel) shows H2O combined with StreamingLLM handling 4M tokens, and the lower panel shows perplexity improvements over StreamingLLM. However, the evaluation is on a single text sample from PG-19, not a systematic benchmark. The paper does not report downstream task accuracy at these extreme lengths — only perplexity. Perplexity improvements do not necessarily translate to task performance improvements, especially at lengths far beyond training context where models may produce fluent but factually incorrect text. The multi-document QA experiment (Figure 9) is more informative, but it uses much shorter sequences. The 4M-token claim is more of a proof-of-concept than a rigorously evaluated capability.

**Missing experiments and baselines:**

- **No direct comparison with oracle eviction policies.** The paper's theoretical framework (dynamic submodular maximization) proves near-optimality under assumptions, but there is no empirical comparison against the true optimal eviction policy computed offline (e.g., via brute force on a small scale). Such a comparison would validate whether the submodularity assumption holds in practice and whether the $(1-1/e)$ bound is tight.

- **No ablation on the concave transformation $h$.** The theoretical analysis (Appendix D) emphasizes that the concave transformation of accumulated scores (e.g., $h(z) = \sqrt{z+1}$) is important for submodularity, but the experiments use $h(z) = z$ (identity) in Algorithm 1. The paper does not report whether using a concave $h$ improves or degrades empirical performance, or whether the identity function already works well enough that the theoretical distinction is practically irrelevant.

- **Single GPU evaluation for throughput.** All throughput experiments use a single GPU (T4 or A100). Multi-GPU inference, where KV cache memory pressure is distributed differently (e.g., tensor parallelism reduces per-GPU cache size but introduces communication overhead), is not evaluated. The paper's claims about throughput improvements may not directly translate to multi-GPU deployments.

- **No comparison with grouped-query attention (GQA) or multi-query attention (MQA).** These architectural modifications (Shazeer, 2019; Ainslie et al., 2023) directly reduce KV cache size by sharing key-value heads. While the paper notes they require retraining, a comparison showing that H2O applied to a standard model matches or exceeds a GQA model of similar size would strengthen the case for eviction policies as an alternative to architectural changes.

- **Limited evaluation on generation quality beyond accuracy.** The diversity analysis (Self-BLEU, Figures 6-7) is brief and qualitative. There is no systematic evaluation of generation quality metrics like coherence, factual consistency, or relevance for summarization tasks — only aggregate scores from HELM. This matters because KV cache eviction could introduce subtle degradation (e.g., losing a key fact mentioned early in a document) that aggregate metrics might miss.

**The "regularization" claim is under-evidenced.** The paper notes that H2O sometimes *outperforms* full cache (+0.73% on RTE, +0.64% on MathQA, +0.18% on XSUM) and attributes this to a "regularization effect" where evicting low-value tokens reduces noise. This is an intriguing hypothesis, but the paper provides no analysis to support it — no error analysis showing that full-cache errors correlate with attention to specific evicted tokens, no controlled experiment where only specific token types are evicted. The improvements are small enough (fractions of a percentage point) that they could be noise; without error bars or statistical testing, the regularization claim is speculative.

**The the theoretical experiments do not evaluate the training loss.** Sections D.17-D.22 propose a sparsity-inducing training loss and prove convergence of a Newton-type optimizer, but no model is trained with this loss. The theoretical contribution is clean, but the paper provides no empirical evidence that training with $L_{\text{sparse}}$ actually produces models with more concentrated attention or makes H2O more effective. This is acknowledged implicitly (the loss is presented as theoretical groundwork, not as an evaluated method), but it means the theory-practice gap remains unbridged.

**The heavy-hitter definition is operational, not analytical.** H2 tokens are defined by their accumulated attention scores — i.e., the policy identifies H2 by the same metric it uses to retain them. This is circular: "we retain high-attention tokens because they have high attention." The paper partially breaks this circularity with the co-occurrence correlation (Figure 2b) and the functional essentiality ablation (Figure 2c), which show that H2 tokens are both statistically predictable from training data and causally necessary. But a deeper analysis of *what linguistic properties* make a token a heavy hitter — beyond co-occurrence frequency — is absent. Are they function words, punctuation, named entities, topic words? Do different heads and layers have different types of heavy hitters? Understanding this could lead to even more targeted retention policies (e.g., retaining different token types for different attention heads).

Overall, the experiments strongly support the practical viability of H2O and convincingly demonstrate the existence and importance of heavy hitters, but the paper's more ambitious claims (29× throughput, 4M-token generation, regularization effects, theoretical optimality in practice) are less thoroughly substantiated. The core finding — that a simple accumulated-attention-based eviction policy can match full-cache accuracy at 20% budget — is robust and well-supported. The extensions and implications, while promising, would benefit from more rigorous empirical grounding.

## 6. Limitations and Trade-offs

### The Cost of Difficulty Estimation Is Not Accounted for in the Headline Efficiency Numbers

**The assumption or constraint.** H2O's eviction policy has negligible per-step computational overhead — the paper is clear and convincing on this point (Section 4.2, Appendix A). However, the policy depends on a specific initialization: before any eviction decisions can be made, the system must identify which tokens are heavy hitters. This requires processing the entire prompt with full attention to accumulate initial attention scores. The paper acknowledges this implicitly when describing the two-phase generation process (Section 2: prompt phase produces the full KV cache, token generation phase uses the eviction policy), but the memory and compute costs of this prompt phase are not isolated or compared against the savings from the reduced cache during decoding.

**The consequence.** For workloads where the prompt is short relative to the generation length (e.g., a one-sentence instruction followed by a multi-paragraph story), the prompt-phase overhead is amortized over many decoding steps and is negligible. But for workloads where the prompt is long and the generation is short (e.g., document summarization, multi-document QA, or few-shot prompting with many examples), the system must compute and store the full KV cache for the entire prompt before it can begin evicting. This means the peak memory usage during the prompt phase is **unchanged from a full-cache baseline** — H2O's memory savings only materialize during decoding. For a 30B model with a 2048-token prompt, the prompt-phase KV cache still occupies the same ~30GB it would without H2O. If GPU memory is the binding constraint (which it typically is), the peak memory requirement, not the steady-state decoding memory, determines whether a workload can run at all. H2O does not reduce peak memory — it reduces the memory growth rate during decoding, enabling longer generation but not enabling larger prompts or larger batch sizes during the prompt phase.

**What evidence exists in the paper.** The paper does not report peak memory usage or prompt-phase memory separately. Table 3 shows that for OPT-6.7B with 512-token prompts, H2O can run with batch size 4 purely on GPU while FlexGen with full cache is limited to batch size 1 (512+1024 configuration) — this suggests that even including the prompt phase, H2O reduces peak memory enough to increase batch size. But the mechanism is not analyzed: is the memory savings during decoding so large that it compensates for the full-cache prompt phase, or is the prompt short enough (512 tokens) that the peak memory is dominated by model weights anyway? The paper states (Section 5.2) that "all the speedup results are tested in an end-to-end setting, including both the pre-filling and generation phases. And it includes the time for constructing the H2O KV cache." This is good practice, but the memory dimension (not just time) is equally important and is not broken down.

**Mitigation status.** The paper does not address this directly. A natural mitigation — applying H2O during the prompt phase itself, evicting tokens as the prompt is processed rather than waiting until generation begins — is not explored. This would be a straightforward extension of the algorithm (the eviction logic in Algorithm 2 does not depend on whether the current token is from the prompt or from generation), but it would require re-defining the "recent token" region during prompt processing and would change the heavy-hitter identification (since prompt tokens would be evicted before their full importance is known). The paper's silence on this point leaves a practical gap: a practitioner with a memory-constrained deployment cannot use H2O to fit longer prompts into GPU memory; they can only use it to generate longer outputs from prompts that already fit.

### Heavy Hitters Are Defined Circularly — by the Same Attention Scores That Determine Retention — With No Independent Characterization

**The assumption or constraint.** The paper defines heavy hitters operationally: they are the tokens with the highest accumulated attention scores (Section 3.2, Algorithm 1). The eviction policy then retains tokens with the highest accumulated attention scores. This is a tight loop: the policy keeps what it measures, and it measures what it keeps. The paper partially breaks this circularity with two findings: (1) H2 tokens correlate with co-occurrence frequency in the training data (Figure 2b), and (2) removing H2 tokens causes catastrophic accuracy drops (Figure 2c). These findings confirm that H2 tokens are real and important, but they do not provide an independent, ex-ante characterization of what makes a token an H2 — e.g., are they function words? punctuation? named entities? topic words from the prompt? This matters because without an independent characterization, there is no way to predict H2 behavior on new domains, new model architectures, or new tasks. If a practitioner deploys H2O on a model fine-tuned for code generation, will the same co-occurrence pattern hold? The paper provides no framework for answering this question without running the full attention accumulation and checking empirically.

**The consequence.** The operational definition creates a risk of domain shift. H2 tokens are identified by the attention patterns of a particular model on a particular data distribution. If the model is deployed on text from a different distribution — e.g., a model trained on English news articles deployed on multilingual code — the attention patterns may shift, and the set of H2 tokens may change. The current method has no mechanism to detect or adapt to such a shift; it will continue to accumulate attention scores and retain whatever tokens score highly, even if those tokens are no longer the functionally critical ones. Since the attention accumulation is purely reactive (it only updates based on tokens the model already chose to attend to), the policy could lock into a suboptimal set of retained tokens if the initial prompt induces attention patterns that are not representative of the generation to follow.

The paper's observation that H2 tokens correlate with co-occurrence frequency suggests that the phenomenon is rooted in general statistical properties of language, not in any specific task. But the correlation is shown for a single model (OPT) on a single corpus (Wiki-Text-103). Figure 12 (Appendix C.10) shows that MLP heavy hitters overlap across Wiki-Text-103, Penn Treebank, and Amazon Review — but this is for the MLP blocks, not for attention heavy hitters, and the three datasets are all English text corpora with broadly similar statistical properties. The claim that H2 are universal would need evidence from more diverse domains (code, mathematics, multilingual text, structured data).

**What evidence exists in the paper.** The functional essentiality experiment (Figure 2c) is the strongest evidence that the circular definition is not vacuous — the tokens identified as H2 are genuinely necessary, not just artifacts of the measurement. The across-task and across-model consistency of the results (H2O works on OPT, LLaMA, GPT-NeoX across 8+ tasks) provides circumstantial evidence that H2 are robust. But the paper provides no analysis of what H2 tokens actually are linguistically, no breakdown by part-of-speech or token type, and no evaluation on out-of-distribution inputs where the H2 set might shift.

**Mitigation status.** The paper does not attempt to characterize H2 tokens beyond the co-occurrence correlation. The MLP heavy-hitter analysis (Appendix C.10, which is an aside rather than part of the main H2O evaluation) provides richer characterization — overlap across datasets, early-bird emergence during training, recoverability via fine-tuning — that implies a structural rather than accidental origin. But this analysis is not connected back to the attention heavy hitters. Future work might train a lightweight classifier to predict which tokens will be H2 based on surface features (position, frequency, part-of-speech), which would both break the circularity and potentially enable even faster initialization.

### Single-Benchmark Validation on Natural Language Tasks Only, With No Code, Multilingual, or Structured-Data Evaluation

**The assumption or constraint.** The paper evaluates H2O exclusively on natural language understanding and generation benchmarks (Section 5.1): six tasks from lm-eval-harness (COPA, MathQA, OpenBookQA, PiQA, RTE, Winogrande), two summarization tasks from HELM (XSUM, CNN/Daily Mail), and two generation benchmarks (AlpacaEval, MT-bench). All are English-language tasks. No evaluation is performed on code generation, mathematical reasoning beyond MathQA (which is multiple-choice), multilingual text, structured data tasks (table-to-text, data-to-text), or tasks requiring precise factual recall over long contexts (e.g., needle-in-a-haystack).

**The consequence.** The paper's central claim — that a small set of heavy-hitter tokens captures almost all the information needed for attention — may be true for natural language tasks where semantic redundancy is high (many words carry overlapping meaning) but could fail for domains where individual tokens carry high, non-redundant information density. Consider a code generation task where a single token (e.g., a variable name defined 100 tokens ago) must be precisely recalled to generate correct code. If that variable name does not happen to be an H2 token (because it appeared once, received moderate attention, and was subsequently evicted in favor of higher-frequency tokens like indentation or keywords), the model would lose access to it and produce incorrect code. Natural language has high lexical redundancy — you can often infer meaning even if you drop many words — but code does not. Similarly, for multilingual tasks, the co-occurrence statistics that produce H2 tokens in English may differ in morphologically rich languages where function words are less frequent or where word order is freer.

The paper's infinite-length experiments (Figure 5) use PG-19, a collection of English-language books — again, natural language with high redundancy. The StreamingLLM comparison (Figure 9) uses multi-document QA and summarization, both natural language tasks. The paper does not test whether H2O preserves the model's ability to recall specific facts, numbers, or entity names from earlier in the context — the kind of precise recall that is critical for many practical applications (legal document analysis, scientific literature review, customer support with knowledge base retrieval).

**What evidence exists in the paper.** The only evidence that bears on this question is the functional essentiality experiment (Figure 2c), which shows that removing H2 tokens destroys performance on the tested benchmarks. This confirms that H2 tokens are necessary but does not address whether H2 tokens (plus recent tokens) are *sufficient* for tasks requiring precise token-level recall. The paper does not include any probe or benchmark that specifically tests long-range factual recall or exact-match information retrieval under KV cache eviction.

**Mitigation status.** The paper does not acknowledge this domain limitation explicitly. The evaluation scope (English NLU + summarization + generation quality) is standard for LLM efficiency papers and covers a reasonable range, but the absence of code, math, or structured-data tasks limits the generalizability claims. A practitioner considering H2O for code completion or multilingual deployment would need to run their own evaluation — the paper provides no guidance on whether H2O is expected to work in those settings or what failure modes to watch for.

### The 50-50 Cache Split and the Identity Scoring Function Are Not Systematically Ablated

**The assumption or constraint.** H2O as implemented and evaluated splits the KV cache budget evenly: 50% of the budget goes to heavy hitters (tokens with highest accumulated attention scores) and 50% goes to the most recent tokens (Section 4.2, Appendix A: "we always maintain a list of KV cache with the first K entries as heavy hitters, and the last K entries as most recent tokens"). The total cache size is 2K. This split is not justified by any sweep, ablation, or theoretical argument — it is simply the design choice the authors made. Similarly, the scoring function used in the experiments (Algorithm 1) is the identity function $h(z) = z$ — raw accumulated attention scores, without the concave transformation ($\sqrt{z+1}$, $\log(z+1)$) that the theoretical analysis identifies as important for submodularity (Remark D.14, Appendix D.7).

**The consequence for the cache split.** The optimal ratio of heavy hitters to recent tokens is almost certainly task-dependent and length-dependent. A summarization task where the key information appears early in the document might benefit from a larger heavy-hitter allocation (to retain those early tokens). A dialogue task where the last few utterances are most relevant might benefit from a larger recent-token allocation. A very long generation task might start with an even split but need to gradually shift toward heavy hitters as the generation length grows and the recent-token window becomes a smaller fraction of the total context.

The paper's ablation in Table 9 shows that both components individually underperform the combination, but does not sweep the ratio. For example, at 20% total budget, does an 80-20 heavy-hitter-to-recent split outperform 50-50 for summarization? Does the optimal ratio change with total budget (e.g., at 4% budget, is it better to allocate almost everything to heavy hitters since the recent window would be trivially small anyway)? Without this sweep, H2O's reported accuracy numbers are specific to the 50-50 split and may not represent the best achievable performance at a given budget.

**The consequence for the scoring function.** The theoretical analysis (Sections D.7-D.14) emphasizes that submodularity — and therefore the near-optimality guarantee — depends on the score function exhibiting diminishing returns. The identity function $h(z) = z$ is linear (modular), meaning the marginal value of adding attention to a token does NOT diminish with the token's existing accumulated score. This makes the score function trivially submodular (linear functions are a degenerate case of submodular functions) but does not provide the diminishing-returns structure that makes the greedy guarantee meaningful — with a linear function, the greedy algorithm is just "keep the top-k by raw score," which is trivially optimal for a linear objective. The paper's theoretical framework is built for non-linear $h$ (concave, to induce diminishing returns), but the experiments use a linear $h$.

This gap matters because a linear score function may behave differently from a concave one in the dynamic setting. With a linear function, a token that receives massive attention in the first few steps will dominate the accumulated scores indefinitely, potentially preventing the cache from ever admitting new heavy hitters that become important later in generation. A concave function would saturate, making it easier for newly important tokens to displace old ones whose marginal value has diminished. The paper does not report whether this saturation effect matters empirically — whether the identity function causes the cache to "freeze" on early heavy hitters and miss later-emerging important tokens.

**What evidence exists in the paper.** Table 9 and the ablation in Section 5.3 (Q4) show that both components are important, but do not sweep the ratio. The theoretical sections (D.7-D.14) discuss the concave transformation but do not test it empirically. The paper acknowledges in Remark D.14 that the choice of $h$ matters for submodularity but states that Algorithm 1 uses $h(z) = z$ "for the purpose of providing readers with an intuitive understanding and due to space limitation." This is a reasonable simplification for exposition, but it means the empirical validation uses a different (and theoretically weaker) score function than the theoretical analysis.

**Mitigation status.** The paper does not claim that 50-50 is optimal or that the identity function is theoretically preferred. But it also does not provide guidance on how to choose the split or the scoring function for a new task or model. A practitioner deploying H2O would need to either accept the 50-50 default or run their own sweeps — the paper provides no transfer learning results or heuristics that would allow selecting the split without expensive per-task evaluation.

### Evaluation Is on a Fixed Set of 8 Tasks With No Statistical Significance Testing or Confidence Intervals

**The assumption or constraint.** All accuracy results in the paper are reported as point estimates — single percentage values — without confidence intervals, error bars, or statistical significance testing (Section 5.1, Figures 4, Tables 1-2, 8-11). The test sets range from 100 to 1,000 examples depending on the benchmark (XSUM and CNN/Daily Mail use 1,000 test samples; the lm-eval-harness tasks vary; the exact sizes are not specified for all tasks). The paper uses two-fold cross-validation only for the compute-optimal allocation policy in the reference example's model (Section 3.2 of that paper), but H2O itself uses no cross-validation or statistical protocol.

**The consequence.** The reported improvements — particularly the cases where H2O slightly *outperforms* full cache (OPT-66B on RTE: +0.73%; OPT-30B on MathQA: +0.64%; GPT-NeoX-20B on XSUM: +0.18%) — cannot be distinguished from noise without confidence intervals. A +0.18% improvement on XSUM (1,000 samples) represents 1-2 additional correct answers out of 1,000. This could easily be sampling noise from the particular test set split. The paper interprets these as "regularization effects" (Section 5.1), but this interpretation requires the improvements to be statistically reliable. Without error bars, the reader cannot assess whether H2O genuinely improves over full cache on some tasks or merely matches it within noise.

More broadly, the paper's central claim — that H2O at 20% budget matches full-cache accuracy — depends on the definition of "matches." For most tasks, the difference between H2O-20% and Full is less than 1-2 percentage points. At typical test set sizes of 500-1,000 examples, a 1-2 percentage point difference may or may not be statistically significant depending on the baseline accuracy and variance. The paper provides no way to assess this.

**What evidence exists in the paper.** The tables report raw accuracy values. The figures (Figure 4) show bar charts with no error bars. The paper states the number of test samples for XSUM and CNN/Daily Mail (1,000) in Appendix A, and for PG-19 (first text sample) in Section 5.3, but does not consistently report sample sizes for the lm-eval-harness tasks. The diversity experiment uses 100 samples from XSUM for the Self-BLEU calculation (Appendix C.1). The infinite-length perplexity experiment uses a single text sample (Section 5.3 Q1: "results are collected on the first text sample of PG-19").

**Mitigation status.** This is a standard practice in the LLM efficiency literature — many papers report point estimates without statistical testing, particularly when the number of experimental configurations (model sizes × tasks × budget levels × baselines) makes comprehensive statistical analysis computationally expensive. The paper's consistency across many model-task pairs (H2O-20% is close to Full in essentially all configurations) provides informal robustness — it is unlikely that this pattern would emerge by chance across dozens of independent configurations. But the lack of formal testing means the "regularization" claims and the precise numerical comparisons should be treated as suggestive rather than definitive. A practitioner deploying H2O should not expect a +0.73% improvement on their specific task; they should expect roughly full-cache-equivalent performance, with small task-dependent variations in either direction.

### The Infinite-Length Claim Rests on a Single Text Sample and Perplexity, Not Downstream Task Performance

**The assumption or constraint.** The paper's most visually striking result — that H2O enables processing of sequences up to four million tokens (Section 5.3 Q1, Figure 5) — is evaluated on perplexity using a single text sample from PG-19, a dataset of English-language books (Rae et al., 2020). The comparison is against StreamingLLM (Xiao et al., 2023), a concurrent method that also claims infinite-length capability. The evaluation metric is perplexity, not downstream task accuracy, factuality, or coherence.

**The consequence.** Perplexity is a measure of how well the model predicts the next token given the preceding context — it captures local fluency and statistical regularity. It does not capture whether the model can actually *use* the long context to perform tasks that require integrating information across large distances. For example, a model could achieve low perplexity on a 4M-token book by learning that "the" is usually followed by a noun and that chapter transitions have predictable patterns, without ever tracking the identity of the protagonist across chapters. Downstream tasks like multi-document QA (where the answer requires synthesizing facts from different parts of the context) or long-form summarization (where the summary must cover all key points) are much harder tests of whether the model genuinely retains and uses long-range information.

The multi-document QA experiment (Figure 9) provides some task-based evaluation for long contexts, but at much shorter lengths (the figure does not specify exact lengths, but the experimental description mentions "ten documents" — likely hundreds to low thousands of tokens, not millions). The gap between "perplexity on 4M tokens" and "task performance on 4M tokens" is large and unbridged.

Furthermore, perplexity on a single sample provides no information about variance. Different types of texts (narrative fiction vs. technical manuals vs. dialogue) may have different H2 patterns, and a single book sample cannot capture this diversity. If the particular PG-19 sample happens to be a book with a small core cast of recurring characters (whose names become heavy hitters), H2O may work well; a book with a constantly shifting cast might show different behavior.

**What evidence exists in the paper.** Figure 5 (upper panel) shows the perplexity curve over 4M tokens for the H2O-enhanced StreamingLLM, and the lower panel shows perplexity comparisons at several cache sizes (256-2048 tokens) between StreamingLLM and H2O on the first PG-19 sample. Figure 9 compares StreamingLLM and H2O on multi-document QA and summarization tasks, but at context lengths far shorter than 4M tokens. The paper does not report task accuracy at extreme lengths.

**Mitigation status.** The paper's framing of the infinite-length result is appropriately cautious: "H2O can empower LLMs to tackle input with length up to four million tokens, achieving a better performance (lower perplexity) than the original StreamLLM method" (Section 5.3 Q1). It does not claim that the model can perform useful tasks at this length, only that it can process the tokens without perplexity collapse. The multi-document QA experiment (Figure 9) partially addresses the gap by showing task benefits at moderate lengths. However, a practitioner evaluating H2O for genuinely long-context applications (e.g., analyzing entire codebases, processing full legal documents, multi-hour dialogue transcripts) should treat the 4M-token result as a proof of concept for length generalization, not as evidence of usable task performance. The combination of H2O with StreamingLLM is promising, but the evaluation at extreme lengths is preliminary.

## 7. Implications and Future Directions

### How This Work Changes the Landscape

This paper introduces a **new category of inference optimization** — the KV cache eviction policy — that is distinct from the two dominant paradigms for making LLM inference efficient: architectural modifications (multi-query attention, sparse transformers) and attention computation approximations (hashing, low-rank, kernel methods). Prior to H2O, the standard assumption was that reducing KV cache memory required either changing the model architecture (which requires retraining) or approximating the attention computation (which degrades accuracy). H2O demonstrates a third path: keep the model and the attention computation unchanged, but make smarter decisions about which computed embeddings to retain in memory and which to discard.

The significance of this reframing is that it **decouples the memory problem from the model design problem.** An organization with a deployed LLM can now reduce inference costs without retraining, without changing model architecture, and without accepting the accuracy degradation that comes with fixed sparse attention patterns. This is not a speculative future benefit — the paper demonstrates it immediately on three model families (OPT, LLaMA, GPT-NeoX) at scales from 6.7B to 66B parameters. The practical corollary is that the large installed base of pre-trained dense transformer models can benefit from H2O today, without waiting for next-generation architectures.

More deeply, the paper shifts the field's understanding of what information the KV cache contains. The default assumption — that autoregressive generation requires access to all previous tokens because the model was trained with full attention — implied that KV cache capacity was a hard constraint on generation length and batch size. H2O's central empirical finding challenges this: **the information in the full KV cache is highly redundant, and a small fraction of tokens (the heavy hitters plus a recent window) captures essentially all of it for natural language tasks.** This is a discovery about attention, not just an engineering optimization. It implies that attention, despite being architecturally capable of attending to every previous token, functionally concentrates on a stable core of high-value tokens throughout generation.

The paper also resolves a latent tension in the literature. Prior work had documented attention sparsity (Likhosherstov et al., 2021) and the existence of "attention sinks" (Xiao et al., 2023) — tokens that absorb disproportionate attention mass. But it was unclear whether this sparsity was exploitable for memory reduction, because a token that is unimportant at one step could become critical later. H2O resolves this by showing that heavy hitters are **persistent**: the tokens that dominate accumulated attention in the past are the same tokens that will dominate in the future (Figure 2d, local vs. global comparison). This persistence is what makes a reactive, past-data-based eviction policy viable — if attention importance were transient, no caching strategy short of clairvoyance could work.

The theoretical contribution — formulating KV cache eviction as dynamic submodular maximization — introduces a new analytical framework to the LLM inference literature. Prior work on attention efficiency provided either no guarantees (heuristic sparse patterns) or guarantees about approximation error relative to full attention (kernel methods, hashing). H2O provides a different kind of guarantee: near-optimality of the retained set relative to a submodular value function, under assumptions that are plausible for attention. Section D and Theorem 4.4 supply the formal statement: greedy H2 eviction achieves at least $(1-1/e)(1-\alpha)$ times the optimal cache value minus a small error term. This theoretical scaffolding, while dependent on assumptions not directly verified in the paper, provides a principled foundation that heuristic cache policies lack and that other KV cache reduction methods (StreamingLLM, gisting tokens) do not attempt to provide.

The paper also redirects research attention toward a previously under-explored design dimension. The KV cache has traditionally been treated as an implementation detail — a straightforward memory-speed tradeoff with no interesting algorithmic content. H2O demonstrates that eviction policy design is a rich problem with measurable performance consequences. It opens the door to a new subfield: the design, analysis, and benchmarking of KV cache replacement algorithms, analogous to the decades of work on CPU cache replacement policies (LRU, LFU, ARC, CAR, etc.) but with the crucial difference that KV cache eviction is irreversible (evicted embeddings cannot be recomputed without re-running the prefix) and the access pattern is determined by the attention mechanism rather than by program behavior.

### Follow-Up Research This Work Enables

**Systematic characterization of heavy hitters across domains, languages, and model architectures.** The paper identifies heavy hitters operationally (tokens with high accumulated attention) and shows they correlate with co-occurrence frequency in English text (Figure 2b). But what *are* heavy hitters linguistically? A strong follow-up would annotate H2 tokens by part-of-speech, syntactic role, and semantic category across multiple languages and domains (code, mathematics, legal text, dialogue). The hypothesis to test: in English, H2 tokens are predominantly function words and punctuation because these co-occur with everything; in code, they might be keywords and common variable names; in mathematics, they might be operators and equality symbols. If this hypothesis holds, the heavy-hitter phenomenon is a consequence of Zipfian token frequency distributions, not a learned property of attention, and should generalize universally. If it fails — if H2 tokens in code are not simply the most frequent tokens — then attention is learning something domain-specific about information salience, and H2O's effectiveness would need to be validated per-domain. The experiment would involve: (1) loading a pre-trained multilingual or code model, (2) running attention accumulation on domain-specific corpora, (3) classifying H2 tokens by linguistic category, and (4) measuring whether domain shift changes the H2 set.

**Adaptive cache split ratios: when to prefer heavy hitters vs. recent tokens.** The paper fixes the heavy-hitter-to-recent ratio at 50-50 and does not sweep it (Section 4.2, Appendix A). Yet Table 9 shows that the two components are complementary, and the optimal ratio almost certainly depends on the task, generation length, and cache budget. A natural follow-up would systematically sweep the ratio from 0-100 (all recent to all heavy hitters) across the eight tasks in the paper's evaluation suite, at multiple budget levels (4%, 10%, 20%, 60%), and report the accuracy surface. The concrete question: is there a universal optimal ratio (suggesting a fixed property of attention), or is the optimal ratio strongly task-dependent (suggesting meta-learning or per-task tuning is needed)? A second-order question: can the optimal ratio be predicted from simple features of the prompt — its length, lexical diversity, genre — enabling automatic ratio selection without per-task evaluation? The experiment would be straightforward to run within the paper's existing evaluation framework.

**Combining H2O with grouped-query attention (GQA) and multi-query attention (MQA).** H2O reduces the number of cached tokens per head. GQA and MQA reduce the number of key-value heads relative to query heads. These are orthogonal and potentially multiplicative: H2O applied to an MQA model would retain the same number of tokens but each token's KV cache would be smaller (shared across heads). The critical test: does H2O + MQA on a standard pre-trained model achieve the same accuracy as a full-cache model with a fraction of the memory, and does this combination approach the efficiency of a purpose-built MQA model trained from scratch? Specifically, one could take a standard dense LLaMA model, simulate MQA by replicating key-value heads (as is sometimes done for inference optimization), apply H2O at 20% budget, and measure both accuracy and total KV cache memory. If the combined approach matches full-cache accuracy with ~5% of the original KV cache memory (20% token retention × 75% head reduction for 4-query-groups), this would make long-context LLM deployment dramatically more accessible without requiring retraining. The paper's current results (Table 2) showing that H2O enhances existing sparsification baselines provide a template for this kind of combination experiment.

**Empirical validation of the submodularity assumption and the greedy guarantee.** The paper's theoretical analysis proves near-optimality of greedy eviction under the assumption that the accumulated-attention-based score function is submodular (Section 4.2, Appendix D). But is this assumption true in practice? A rigorous empirical test would: (1) compute the true optimal eviction policy for a small-scale model (e.g., OPT-125M) on short sequences (e.g., 32 tokens, cache budget 8) by brute-force enumeration of all possible eviction sequences, (2) compare the submodular value of the greedy H2O policy against the true optimum, and (3) measure whether the $(1-1/e)$ bound is tight or loose in practice. If the bound is loose (H2O achieves >95% of optimal rather than 63%), the theoretical framework is conservative but confirms the approach. If the bound is tight or violated, the submodularity assumption does not hold, and the theoretical justification needs revision. This experiment would also reveal whether the identity scoring function $h(z)=z$ used in the paper's implementation (Algorithm 1) or the concave functions suggested by theory ($h(z)=\sqrt{z+1}$, $h(z)=\log(z+1)$) better approximate the true optimal policy.

**Training models with the sparsity-inducing loss from Appendix D and measuring H2O effectiveness.** Sections D.17-D.22 propose a training objective $L(x) = L_{\text{exp}}(x) + L_{\text{sparse}}(x) + L_{\text{reg}}(x)$ where $L_{\text{sparse}}(x) = \|\exp(Ax)\|_1$ explicitly penalizes the softmax denominator to encourage concentrated attention. The paper proves that a Newton-type optimizer can minimize this loss efficiently, but does not train any model with it. A strong follow-up would: (1) pre-train a small transformer (e.g., GPT-2 scale) from scratch with this sparsity-inducing loss, (2) measure whether attention sparsity increases compared to a standard-training baseline (using the 95% sparsity metric from Figure 2a), (3) measure whether H2O at a given budget achieves higher accuracy on the sparsity-trained model than on the standard-trained model, and (4) test whether the sparsity-trained model can tolerate even more aggressive budgets (e.g., 10% or 5%). This experiment would bridge the theory-practice gap that the paper leaves open and would demonstrate whether H2O-like cache reduction can be co-designed with training rather than applied post-hoc. The concern to watch for: the sparsity penalty might harm pre-training perplexity or downstream accuracy in ways that outweigh the inference efficiency gains — the experiment should measure both.

**KV cache eviction as a learned policy via reinforcement learning or imitation learning.** H2O uses a hand-designed greedy policy based on accumulated attention. But the theoretical framework (dynamic submodular maximization) and the empirical observation that future attention patterns are predictable from past ones (Figure 2d) suggest that a learned eviction policy could outperform the heuristic. The proposal: train a lightweight policy network (e.g., a small MLP) that takes as input the current cache contents, the accumulated attention scores, and features of the new token, and outputs an eviction decision. The policy could be trained via: (a) imitation learning, using the oracle optimal eviction decisions computed via brute force on small sequences, or (b) reinforcement learning, where the reward is the negative of the attention loss (or downstream task accuracy) after a sequence of eviction decisions. The trained policy could then be deployed as a drop-in replacement for the greedy algorithm in Algorithm 2. The paper's existing infrastructure (FlexGen integration, attention score accumulation) provides the environment for this RL formulation. The key question: can a learned policy generalize across model scales (trained on 125M, deployed on 6.7B) and tasks (trained on WikiText, deployed on summarization)? If so, this would substantially reduce the deployment cost of H2O-like methods by eliminating the need to hand-tune the eviction heuristic.

**Stress-testing H2O on tasks requiring precise long-range token-level recall.** The paper's evaluation focuses on natural language understanding and summarization, where semantic redundancy is high. A critical stress test would evaluate H2O on tasks where individual tokens carry non-redundant, precise information that must be recalled many steps later. Concrete candidates: (1) the "needle-in-a-haystack" benchmark (inserting a specific fact at a controlled position in a long document and testing whether the model can recall it), (2) code completion tasks where a variable defined at the beginning of a function must be used at the end, (3) multi-hop question answering where the answer depends on correctly combining two facts separated by distractor text, and (4) the "Lost in the Middle" benchmark (Liu et al., 2023) which specifically tests whether models can use information in the middle of long contexts. For each benchmark, the experiment would sweep H2O budgets (from 10% to 100%) and measure whether accuracy drops when key information falls outside the heavy-hitter-plus-recent set. If H2O fails catastrophically on these tasks at low budgets, it would establish a clear boundary condition: H2O is safe for tasks with high semantic redundancy but unsafe for tasks requiring precise token-level recall. This would be a practically important finding, guiding which production workloads can safely use aggressive KV cache reduction and which cannot.

### Practical Applications and Downstream Use Cases

**High-throughput batch inference for content generation at scale.** Organizations running large-scale LLM inference for content generation — dialogue systems, story writing assistants, marketing copy generation — face a direct tradeoff between throughput and cost. The paper demonstrates (Tables 3-4) that H2O with 20% cache budget enables 2-3× higher throughput on a T4 GPU compared to FlexGen (the prior state-of-the-art single-GPU inference engine) by allowing larger batch sizes and eliminating CPU offloading. For OPT-6.7B generating 1024 tokens, H2O achieves 52.1 tokens/s vs. FlexGen's 16.9 — a 3.1× improvement on hardware costing approximately $0.30/hour (on-demand T4 pricing). For a content generation service handling millions of requests, this throughput improvement directly reduces the number of GPU-hours required and therefore the infrastructure cost. The key practical insight: the benefits are largest when generation length is long (the KV cache dominates memory), meaning H2O is particularly well-suited to the very use cases — story generation, long-form dialogue — where KV cache pressure is most acute.

**Enabling long-context applications on memory-constrained hardware.** The paper shows that H2O enables OPT-6.7B to run with batch size 4 on a T4 GPU (16GB) with 512 prompt + 1024 generation tokens, while FlexGen with full cache is limited to batch size 1 on the same hardware (Table 3, 512+1024 configuration). Extrapolating: on edge devices, consumer GPUs, or shared cloud instances with limited memory, H2O could make the difference between a model fitting in GPU memory at all vs. requiring costly offloading or falling back to a smaller model. For a developer deploying a 7B-parameter LLM on a laptop GPU or a smartphone-class accelerator for an interactive application (e.g., a writing assistant that generates suggestions as the user types), the KV cache is often the binding memory constraint for response length. H2O at 20% budget quintuples the maximum generation length before out-of-memory, or equivalently, allows generation of the same length with a model that would otherwise not fit. The practical benefit is not just faster inference, but inference at all in memory-constrained deployment scenarios.

**Streaming processing of very long documents and transcripts.** The infinite-length results (Section 5.3 Q1, Figure 5) combined with the multi-document QA experiments (Figure 9) suggest that H2O-enhanced StreamingLLM can maintain task-relevant information across contexts far longer than the model's training length. A concrete use case: processing multi-hour meeting transcripts (easily 10,000-50,000 tokens) to answer questions about decisions made early in the meeting. Current approaches either truncate the transcript (losing early information), use retrieval-augmented generation (requiring a separate retrieval pipeline), or pay the quadratic cost of full attention (prohibitively slow). H2O with StreamingLLM offers a middle path: the model processes the entire transcript autoregressively with bounded memory, retaining early-meeting heavy hitters that turn out to be important for later questions while discarding the vast majority of low-value tokens. The paper demonstrates (Figure 9) that H2O preserves accuracy on multi-document QA when key information is in middle documents that StreamingLLM would evict. A meeting-summarization or legal-document-analysis product could deploy this today, using H2O to process entire documents without truncation and without the infrastructure complexity of retrieval.

**KV cache reduction as a complementary optimization in multi-GPU inference.** The paper evaluates H2O on single-GPU setups, but the memory savings are equally valuable in multi-GPU deployments. In tensor-parallel inference (where model weights are split across GPUs), the KV cache is typically replicated or partitioned, and its per-GPU memory footprint remains a constraint on batch size. Applying H2O in this setting would reduce the per-GPU KV cache memory, enabling larger micro-batch sizes and therefore higher throughput — the paper's demonstrated 2-3× throughput improvements on single GPU would compound with the existing parallelism benefits. In pipeline-parallel inference, where different GPUs process different layers, the KV cache memory pressure is concentrated on the GPUs handling later layers (which must store the cache for all previous layers' tokens). H2O would reduce this pressure, potentially enabling more balanced memory distribution. For LLM serving platforms (e.g., vLLM, TensorRT-LLM, TGI) that already implement sophisticated memory management, H2O-style eviction could be integrated as an additional memory-saving technique that kicks in when the KV cache approaches capacity limits, reducing the frequency of preemption or the need to reserve excessive memory headroom. The paper's clean integration with FlexGen (Appendix A) provides a template for how to add H2O to an existing inference engine without restructuring the memory management system.
