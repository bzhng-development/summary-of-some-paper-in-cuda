# SageAttention2++: A More Efficient Implementation of SageAttention2

**ArXiv:** [2505.21136](https://arxiv.org/abs/2505.21136)

## 🎯 Pitch

SageAttention2++ proposes a more efficient implementation of the SageAttention2 attention quantization method by leveraging a faster GPU instruction—`mma.f16.f8.f8.f16`, which performs FP8 matrix multiplication with an FP16 accumulator and is 4× faster than FP16—for the PV matrix multiplication in attention, replacing the slower `mma.f32.f8.f8.f32` instruction used in SageAttention2.

---

## 1. Executive Summary

SageAttention2++ proposes a more efficient implementation of the SageAttention2 attention quantization method by leveraging a faster GPU instruction—`mma.f16.f8.f8.f16`, which performs FP8 matrix multiplication with an FP16 accumulator and is 4× faster than FP16—for the PV matrix multiplication in attention, replacing the slower `mma.f32.f8.f8.f32` instruction used in SageAttention2. The paper addresses the resulting FP16 representable-range overflow by narrowing the quantization ranges of P and V (specifically, constraining Pr × Vr ≤ 2047 and selecting Pr = 224, Vr = 4.5), coupled with a delayed FP32 buffering technique that accumulates two consecutive MMA results in FP16 before conversion to halve the transformation overhead. Evaluated across Llama3.1 (8B), CogvideoX, HunyuanVideo, Wan, Flux, and Stable-Diffusion3.5 on RTX4090 and RTX5090 GPUs, SageAttention2++ achieves a 3.9× speedup over FlashAttention2 while matching SageAttention2's attention accuracy and incurring negligible end-to-end metrics loss, establishing that further acceleration of quantized attention is achievable through accumulator-aware instruction selection only when quantization ranges are explicitly constrained to stay within the narrower dynamic range of FP16 accumulation.

## 2. Context and Motivation

### The Core Problem: Attention's Quadratic Time Complexity Is a Practical Bottleneck

The central challenge this paper addresses is the **runtime cost of exact attention in Transformer models**. The standard scaled dot-product attention mechanism computes:

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

The $QK^T$ multiplication produces an $N \times N$ matrix, where $N$ is the sequence length, and both this operation and the subsequent multiplication by $V$ have $O(N^2 d)$ complexity. For long sequences — which are increasingly common in modern applications such as high-resolution video generation, long-context language modeling, and high-quality image synthesis — this quadratic scaling means that attention computation can dominate end-to-end model runtime.

This is not merely a theoretical concern. The paper implicitly focuses on **deployment and inference scenarios** where speed directly translates to user experience, throughput capacity, and energy cost. For video generation models like CogvideoX or HunyuanVideo, where each generated frame requires computing attention over spatial and temporal dimensions simultaneously, shaving even 2–3× off the attention kernel can cut generation latency from minutes to seconds. For large language models serving long contexts (e.g., 32K tokens), attention can account for the majority of total inference FLOPs.

### Why This Specific Gap Matters: The Memory Wall Meets Instruction Throughput

To understand the gap this paper addresses, we need to be precise about what SageAttention2 already achieved and where it left room for improvement.

**What SageAttention2 does.** SageAttention2 (Zhang et al., 2025a) accelerates attention by quantizing all three matrix multiplications involved:
- $QK^T$: Q and K are quantized to INT4 or INT8 using per-block scaling factors ($\delta_Q = \max(|Q|)/127$, $\delta_K = \max(|K|)/127$).
- $PV$: $\tilde{P}$ (the post-softmax attention weights) and V are quantized to FP8 in the E4M3 format (range -448 to 448), with per-block scaling for $\tilde{P}$ ($\delta_P = \max(|\tilde{P}|)/448$) and per-channel scaling for V ($\delta_V = \text{colmax}(|V|)/448$).

By quantizing these matrices to low-precision formats, SageAttention2 uses Tensor Core operations that process more elements per clock cycle than FP16. Specifically, for the $PV$ multiplication, SageAttention2 uses the `mma.f32.f8.f8.f32` instruction — an FP8 multiply-accumulate instruction that stores partial sums in an FP32 accumulator.

**Why SageAttention2's PV instruction choice is suboptimal.** Table 1 in the paper provides the critical data point: on RTX4090 and RTX5090 GPUs (both Ada Lovelace and Blackwell architectures), the speedup of different matrix multiply instructions relative to FP16 is:

| MMA Input | MMA Accumulator | Speedup vs. FP16 |
|-----------|----------------|-------------------|
| FP16 | FP32 | 1× (baseline) |
| FP8 | FP32 | 2× |
| FP8 | FP16 | **4×** |

This means SageAttention2 is leaving **a factor of 2× on the table** for the PV multiplication alone. Why? Because its choice of `mma.f32.f8.f8.f32` — the FP32-accumulator variant — runs at only half the throughput of the FP16-accumulator variant `mma.f16.f8.f8.f16`. In GPU hardware, the accumulator data type affects register pressure and the number of operations that can be in flight simultaneously: FP16 accumulators require fewer bits per partial result, allowing more parallel threads of execution within the same Tensor Core unit.

The gap is specifically about the **PV multiplication**, not the $QK^T$ multiplication. The paper does not modify the $QK^T$ quantization or instruction choice from SageAttention2 — that part already uses INT4/INT8 Tensor Core operations which have their own throughput characteristics. The theoretical maximum speedup is therefore bounded by Amdahl's law: even if the PV instruction doubles in speed, the overall attention kernel speedup depends on what fraction of total time PV accounts for.

### Prior Approaches and Their Limitations

The paper situates itself within three broad categories of attention acceleration (Section 1):

**1. Linear attention methods.** These replace the $O(N^2)$ softmax attention with $O(N)$ approximations, typically by factorizing the attention matrix using kernel functions (e.g., Performer, Linear Transformer, Lightning Attention-2). While these methods can achieve asymptotic complexity improvements, they come with a fundamental tradeoff: the approximation introduces error that can degrade model quality, particularly on tasks requiring precise long-range token interactions. More critically, linear attention methods are **not plug-and-play** — they require architectural changes to the model, retraining or fine-tuning, and may not generalize across different model families. A linear attention variant that works for a language model may not transfer to a video diffusion transformer.

**2. Sparse attention techniques.** These reduce the number of token-token interactions processed by selecting only a subset of keys/values for each query — for example, via sliding windows (StreamingLLM), dynamic token pruning (MInference), or learned sparsity patterns (SeerAttention, MoA). Like linear attention, these methods introduce approximation error. The paper explicitly notes that these methods "often exhibit limited generality across models and tasks" — a sparse pattern that is effective for a text-to-image model's spatial attention may not work for a language model's causal attention, and vice versa. Each new model or use case may require retuning the sparsity strategy.

**3. Hardware-optimized exact attention.** This category — which includes FlashAttention, FlashAttention2, FlashAttention3, xFormers, and the SageAttention family — computes exact (not approximate) attention but uses hardware-aware tiling, recomputation strategies, and low-precision arithmetic to maximize throughput. The fundamental advantage of this category is **generality with guaranteed accuracy**: the mathematical operation being computed is identical to full-precision attention (or nearly so, in the case of quantization-based methods like SageAttention), meaning models require no retraining and no architectural modification. You swap the attention kernel and the model runs faster with (ideally) identical outputs.

This third category is where the paper positions itself. Within this category, the state of the art at the time of writing was:

- **FlashAttention2**: The fastest exact-FP16 attention kernel, achieving speedups over naive attention through careful tiling that minimizes HBM (high-bandwidth memory) reads/writes, fused kernel operations that avoid materializing the full $N \times N$ attention matrix, and parallelization over the batch and head dimensions. On RTX4090 at headdim=128 and sequence length 32K, FlashAttention2 achieves approximately 164 TOPS (Figure 1).

- **SageAttention2**: Uses quantization to push throughput beyond FlashAttention2. Its (4+8) variant (INT4 for Q/K, FP8 for $\tilde{P}$/V) achieves approximately 489 TOPS on the same configuration — about 3.0× faster than FlashAttention2. Its (8+8) variant achieves approximately 422 TOPS — about 2.6× faster.

The gap this paper identifies is **within the SageAttention2 design space itself**: SageAttention2 already committed to FP8 quantization for PV, but did not use the fastest available FP8 instruction variant because doing so would cause numerical overflow in the FP16 accumulator. The paper's contribution is solving that overflow problem while retaining the throughput benefit.

### Conflicting Design Tensions: Speed vs. Numerical Range

The core tension that motivates this work is between **instruction throughput** and **representable numerical range**. Here's the conflict in concrete terms:

The `mma.m16n8k32` instruction used for the PV multiplication (Section 3.1) computes the product of an $m \times k$ tile of $\tilde{P}$ and a $k \times n$ tile of $V$, accumulating $k=32$ products into each output element. With SageAttention2's original quantization ranges — $\tilde{P}$ values up to ±448, V values up to ±448 (both in FP8 E4M3 format) — the maximum possible accumulated value is:

$$|32 \times 448 \times 448| = 32 \times 200,704 = 6,422,528$$

This exceeds FP16's maximum representable value of 65,504. The accumulator would overflow, producing infinities or severely incorrect results. This is not a theoretical edge case — multiplication near the extremes of FP8's range would routinely trigger overflow during the accumulation steps.

SageAttention2 avoided this by using the FP32 accumulator (`mma.f32.f8.f8.f32`), where the representable range is ~3.4 × 10³⁸ — effectively unlimited for these purposes. But that safety came at the cost of halving the instruction throughput.

The paper's motivation is thus a concrete engineering challenge: **How can we use the faster FP16-accumulator instruction while guaranteeing that no overflow occurs?** The answer must preserve the accuracy of SageAttention2 — otherwise we've recreated the tradeoff that makes approximate attention methods less appealing than exact ones.

### How This Paper Positions Itself

The paper presents itself as a **direct incremental improvement** to SageAttention2, not as a new attention quantization method. This is explicit in the title ("A More Efficient Implementation of SageAttention2") and in the approach: the workflow of SageAttention2++ is "based on SageAttention2, also using the smoothing of Q and K, INT4/INT8 quantization for $QK^T$ Matmul and FP8 quantization for $PV$ Matmul" (Section 3). The only change is in the PV computation.

This positioning matters for several reasons:

**Trust and adoption.** By building on SageAttention2's established approach — which has already been validated in prior publications as achieving near-lossless accuracy across diverse models — the paper avoids having to re-prove the fundamental viability of quantized attention. The accuracy claims focus specifically on showing that the new instruction choice doesn't introduce degradation relative to SageAttention2, which is a much lighter burden than proving accuracy against full-precision attention from scratch.

**Practical deployment path.** SageAttention2 already has production users. SageAttention2++ can be described as "SageAttention2, but faster for free" — swap the kernel, get 1.3× additional speedup on top of SageAttention2's existing 3× over FlashAttention2, with verified negligible metrics change. This is exactly the kind of improvement that gets adopted quickly because the risk-reward ratio is extremely favorable.

**Conceptual contribution.** The paper is not just an engineering tweak. It makes a conceptual point: **accumulator-aware quantization range selection is a first-class design dimension in low-precision attention kernels**. The choice of $P_r$ and $V_r$ is not arbitrary — it must satisfy the constraint $P_r \times V_r \leq 2047$ (derived from $65504 / 32$) to prevent overflow, and with the delayed FP32 buffering optimization (Section 3.2), the constraint tightens to $P_r \times V_r \leq 2047/2 \approx 1023$. This constraint couples the quantization design space (how aggressively we quantize) to the hardware instruction space (which Tensor Core instruction we can use). Prior work in quantized attention treated these as independent choices; this paper shows they are linked through accumulator dynamics.

### What the Paper Does NOT Attempt

It's worth being explicit about what this paper leaves unchanged, because this clarifies the scope of its contribution:

- **It does not change the $QK^T$ quantization.** The INT4/INT8 quantization of Q and K, the per-block smoothing, and the instruction choice for that multiplication remain identical to SageAttention2.

- **It does not propose new quantization formats or granularities.** $\tilde{P}$ and V are still quantized to FP8 E4M3, with per-block (for $\tilde{P}$) or per-channel (for V) scaling. The only change is in the scaling factor denominators — $P_r$ and $V_r$ are reduced from 448 to 224 and 4.5 respectively (or other feasible pairs satisfying the product constraint).

- **It does not modify the attention algorithm itself.** There is no change to the softmax computation, the tiling strategy inherited from FlashAttention, or the online normalization. The paper is purely about how the PV matrix multiply is executed once $\tilde{P}$ and V are quantized.

- **It does not claim superiority over FlashAttention3.** The paper explicitly notes that "FlashAttention3 can only run on Hopper GPUs, so FlashAttention2 is already the fastest version for RTX5090 and RTX4090" (Section 4.1). The Ada Lovelace and Blackwell consumer GPU architectures (RTX 40 and 50 series) lack the hardware features (FP8 Tensor Core support with specific accumulator modes, asynchronous data movement) that FlashAttention3 exploits on Hopper (H100). For the GPU class being targeted — consumer GPUs widely used for local inference, image/video generation, and development — FlashAttention2 remains the relevant baseline.

### The Practical Significance: Real-World Deployment Context

The paper's motivation is grounded in concrete deployment scenarios that are worth making explicit:

- **Consumer GPU inference.** RTX 4090 and RTX 5090 are the most powerful consumer GPUs available. For researchers, hobbyists, and small organizations running image generation (Stable Diffusion, Flux), video generation (CogvideoX, HunyuanVideo, Wan), or local LLM inference, these GPUs represent the practical ceiling of available hardware. A 3.9× kernel speedup directly translates to ~4× higher throughput — generating 4 images in the time it previously took to generate 1, or reducing video generation from 10 minutes to 2.5 minutes.

- **No retraining required.** The plug-and-play nature of SageAttention2++ (inherited from SageAttention2) means these speedups can be applied immediately to existing pretrained model weights. There is no fine-tuning step, no calibration data requirement, and no model-specific hyperparameter tuning — the quantization ranges ($P_r=224$, $V_r=4.5$) are universal across all models tested. This contrasts sharply with quantization-aware training or post-training quantization methods that require per-model calibration.

- **The "free lunch" argument.** If SageAttention2++ matches SageAttention2's accuracy (which it demonstrably does — see Table 2 showing CosSim of 99.97% and identical L1 error) while being faster, then any existing SageAttention2 user can upgrade with literally no downside. This is the strongest possible motivation for an engineering improvement: strictly dominated alternatives should be driven out of use.

## 3. Technical Approach

### 3.1 Reader Orientation

SageAttention2++ is a GPU kernel — a low-level CUDA implementation of the attention mechanism — that accelerates Transformer models during inference by quantizing the matrices involved in attention to low-precision formats and executing their multiplications using the fastest available Tensor Core instructions. The paper solves the problem that the fastest FP8 matrix multiply instruction on consumer GPUs uses an FP16 accumulator whose limited numerical range would overflow with the quantization ranges SageAttention2 originally chose, by deliberately narrowing those ranges and adding a buffering technique that together preserve accuracy while achieving a 3.9× speedup over FlashAttention2.

### 3.2 Big-Picture Architecture (Diagram in Words)

The SageAttention2++ system modifies exactly one component of the SageAttention2 attention pipeline — the $PV$ matrix multiplication — while leaving all other components unchanged. The architecture has three parts:

1. **The inherited SageAttention2 pipeline** — which handles tiling Q, K, V into blocks; smoothing Q and K; quantizing Q and K to INT4/INT8 for the $QK^T$ multiplication; computing softmax online to produce $\tilde{P}$; and quantizing $\tilde{P}$ and V to FP8 for the $PV$ multiplication. All of this remains identical to SageAttention2.

2. **The modified PV multiplication** — which replaces the `mma.f32.f8.f8.f32` instruction (FP8 multiply with FP32 accumulate) with `mma.f16.f8.f8.f16` (FP8 multiply with FP16 accumulate), a 2× faster instruction on Ada Lovelace and Blackwell GPUs. To prevent FP16 accumulator overflow, the quantization ranges of $\tilde{P}$ and V are deliberately narrowed from `[-448, 448]` to `[-224, 224]` and `[-4.5, 4.5]` respectively, chosen so that the product of their ranges stays below the safe threshold of 2047 (or 1023 with the buffering optimization).

3. **The delayed FP32 buffering mechanism** — which accumulates two consecutive `mma.m16n8k32` instruction results in FP16 before converting to FP32, halving the overhead of the data-type conversion PTX instructions while requiring a further halving of the quantization range product to stay within FP16's representable limits.

Information flows through the system as: input Q, K, V → SageAttention2 tiling and $QK^T$ quantization (unchanged) → online softmax producing $\tilde{P}$ (unchanged) → quantization of $\tilde{P}$ with narrowed scale factor $\delta_P = \max(|\tilde{P}|)/224$ and V with narrowed per-channel scale factors $\delta_V = \text{colmax}(|V|)/4.5$ (modified) → FP8 matrix multiply with FP16 accumulation using pairs of MMA instructions buffered before FP32 conversion (modified) → FP32 output O.

### 3.3 Roadmap for the Deep Dive

- **First**, the SageAttention2 baseline in detail — its tiling, quantization scheme, and instruction choices — because SageAttention2++ is a surgical modification of this pipeline and understanding what stays the same is essential for understanding what changes.

- **Second**, the accumulator data type speed hierarchy on consumer GPUs (Table 1), because this empirical fact — that FP16 accumulation provides 4× throughput over FP16 but FP32 provides only 2× — is the entire motivation for the paper.

- **Third**, the core numerical constraint: why using the FP16 accumulator forces a reduction in quantization ranges, how the constraint $P_r \times V_r \leq 2047$ is derived from the FP16 maximum representable value, and what the feasible $(P_r, V_r)$ pairs look like in practice.

- **Fourth**, the delayed FP32 buffering optimization, why it matters for throughput despite further constraining the quantization ranges, and how the final constraint $P_r \times V_r \leq 1023$ is obtained.

- **Fifth**, the selection of the specific $(P_r = 224, V_r = 4.5)$ configuration, including the ablation evidence from Table 2 showing that other feasible pairs produce equivalent accuracy, meaning the choice is driven by performance considerations rather than accuracy tradeoffs.

### 3.4 Detailed, Sentence-Based Technical Breakdown

This is a **systems and kernel optimization paper** whose core idea is that the choice of accumulator data type in a tensor core matrix multiply instruction couples the quantization range design space to the hardware instruction design space, and that by explicitly constraining quantization ranges to satisfy the accumulator's representable limits, one can unlock a faster instruction class with zero accuracy cost.

#### The SageAttention2 Baseline: What Stays the Same

SageAttention2 (Zhang et al., 2025a) is a quantization method built on top of FlashAttention's tiling framework. FlashAttention (Dao et al., 2022) introduced the key insight that exact attention can be computed in a memory-efficient way by tiling Q, K, V into blocks that fit in SRAM (on-chip memory), computing partial softmax results block-by-block using online normalization (Milakov & Gimelshein, 2018), and never materializing the full $N \times N$ attention matrix in HBM (high-bandwidth memory, i.e., GPU DRAM). This tiling eliminates the $O(N^2)$ memory footprint that plagued earlier attention implementations.

SageAttention2 layers quantization on top of this tiling framework. The computation is broken into blocks $\{Q_i\}$, $\{K_i\}$, $\{\tilde{P}_i\}$, $\{V_i\}$, where each block is small enough to be processed in fast on-chip memory. For simplicity, the paper refers to individual blocks as $Q$, $K$, $\tilde{P}$, $V$ without subscripts, with the understanding that these operations apply identically to every block.

**$QK^T$ quantization (unchanged in SageAttention2++).** Each block of Q and K is quantized to either INT8 or INT4 format using per-block scaling factors:

$$\delta_Q = \frac{\max(|Q|)}{127}, \quad \delta_K = \frac{\max(|K|)}{127}$$

where $\max(|Q|)$ is the maximum absolute value of all elements in the current block of Q, and 127 is the maximum representable value in INT8 (signed 8-bit integer, range $[-127, 127]$). For INT4, the denominator is 7 (range $[-7, 7]$). The quantized values are computed as:

$$\hat{Q} = \left\lceil \frac{Q}{\delta_Q} \right\rfloor, \quad \hat{K} = \left\lceil \frac{K}{\delta_K} \right\rfloor$$

where $\lceil \cdot \rfloor$ denotes rounding to the nearest integer. The matrix multiplication then computes $\hat{Q}\hat{K}^T$ using INT8/INT4 Tensor Core operations, and the result is rescaled by $\delta_Q \delta_K$ to recover the correct magnitude.

SageAttention2 also applies a **smoothing** step to Q and K before quantization. Smoothing redistributes magnitude between Q and K to reduce quantization error — if Q has elements with very large magnitude while K has small magnitude, quantizing both symmetrically would preserve Q's precision at the expense of K. Smoothing applies a per-channel scaling factor to both matrices that balances their dynamic ranges without changing the mathematical result (since scaling Q up and scaling K down by the same factor leaves $QK^T$ unchanged). This smoothing step is critical for achieving INT4 accuracy but is not modified by SageAttention2++.

**$PV$ quantization in SageAttention2.** After the softmax, the attention weights $\tilde{P}$ are quantized to FP8 in the E4M3 format. E4M3 is an 8-bit floating-point format with 1 sign bit, 4 exponent bits, and 3 mantissa bits, providing a representable range of approximately $[-448, 448]$ (the maximum normal value is $448 = 2^{8-1} \times (1 + 1/2 + 1/4 + 1/8)$ for exponent bias 7 and max mantissa). The per-block scaling factor is:

$$\delta_P = \frac{\max(|\tilde{P}|)}{448}$$

The value matrix V is similarly quantized to FP8 E4M3, but with **per-channel** granularity — each column (channel) of V gets its own scale factor:

$$\delta_V = \frac{\text{colmax}(|V|)}{448}$$

where $\text{colmax}(|V|)$ is the maximum absolute value in each column of V, producing a vector of per-channel scale factors. Per-channel granularity is important because different feature dimensions in V can have very different dynamic ranges — a channel encoding positional information might have values near zero while a channel encoding semantic content might have values in the hundreds. Per-block granularity for $\tilde{P}$ is sufficient because the attention weights within a block tend to be in similar ranges (they are probabilities bounded between 0 and 1, and are explicitly normalized by the softmax within the block).

The quantized matrices are:

$$\hat{P} = \left\lceil \frac{\tilde{P}}{\delta_P} \right\rfloor_{\text{FP8}}, \quad \hat{V} = \left\lceil \frac{V}{\delta_V} \right\rfloor_{\text{FP8}}$$

where the rounding operation now rounds to the nearest representable FP8 value rather than an integer. The product is then computed as:

$$PV = \hat{P}\hat{V} \times \delta_P \times \delta_V$$

with the quantization scale factors multiplied back after the matrix multiplication.

**SageAttention2's instruction choice for PV.** The matrix multiplication $\hat{P}\hat{V}$ is executed using the Tensor Core instruction `mma.f32.f8.f8.f32`. Breaking down this instruction name: `mma` stands for matrix multiply-accumulate; the first type (`f32`) is the accumulator data type; the second and third types (`f8`, `f8`) are the input operand types. So this instruction multiplies FP8 values but accumulates partial sums in FP32 (32-bit floating point).

The specific variant used is `mma.m16n8k32`, which processes a tile of size $16 \times 8$ from the output matrix, accumulating over $k=32$ elements of the inner dimension. This means each output element is the sum of 32 products of FP8 values.

SageAttention2 chose the FP32 accumulator because it guarantees that the accumulated sum never overflows — FP32 can represent values up to approximately $3.4 \times 10^{38}$, far larger than any possible accumulation of 32 FP8 products (maximum $32 \times 448 \times 448 = 6,422,528$). But this safety comes at a throughput cost, as Table 1 quantifies.

#### The Accumulator Speed Hierarchy (Table 1): Why the FP16 Accumulator Matters

Table 1 presents the speedup of different matrix multiply instructions relative to FP16 with FP32 accumulation (the baseline for standard floating-point attention). This is the empirical fact that motivates the entire paper:

| MMA Input | MMA Accumulator | Speedup vs. FP16 |
|-----------|----------------|-------------------|
| FP16 | FP32 | 1× (baseline) |
| FP8 | FP32 | 2× |
| FP8 | FP16 | **4×** |

On RTX 4090 and RTX 5090 GPUs, switching from FP16 inputs to FP8 inputs (while keeping an FP32 accumulator) provides a 2× speedup. This is what SageAttention2 already exploits — by quantizing $\tilde{P}$ and V to FP8, the Tensor Core processes 2× more elements per clock compared to FP16 inputs for the same accumulator width.

But switching **additionally** from an FP32 accumulator to an FP16 accumulator provides **another 2×** — jumping from 2× to 4× total speedup over the FP16 baseline. Why does the accumulator type affect throughput so dramatically? The reason is register pressure and data path width: FP32 values consume 32 bits per partial result, while FP16 values consume only 16 bits. Within the same Tensor Core unit, narrower accumulators mean more partial results can be held in registers, more parallel multiply-accumulate pipelines can operate simultaneously, and less bandwidth is consumed moving partial sums between pipeline stages. On Ada Lovelace (RTX 40 series) and Blackwell (RTX 50 series) architectures, the FP16 accumulator path in the Tensor Core is explicitly designed for higher throughput.

The implication for SageAttention2 is immediate: its PV multiplication is leaving a 2× speedup on the table by using `mma.f32.f8.f8.f32` instead of `mma.f16.f8.f8.f16`. But the FP16 accumulator can only represent values in the range $[-65504, 65504]$ (FP16's maximum normal value), and SageAttention2's quantization ranges would routinely cause accumulations to exceed this limit.

#### The Core Constraint: Deriving the Safe Quantization Range Product

The paper's central technical insight is that the overflow problem can be eliminated by **deliberately constraining the quantization ranges**, and that there exists a family of $(P_r, V_r)$ pairs that simultaneously satisfy the FP16 range constraint while introducing negligible accuracy loss.

**The accumulator overflow condition.** The `mma.m16n8k32` instruction accumulates $k=32$ products into each output element of the $16 \times 8$ tile. Each product is of the form $p \times v$, where $p$ comes from the quantized $\hat{P}$ matrix (values in the range $[-P_r, P_r]$) and $v$ comes from the quantized $\hat{V}$ matrix (values in the range $[-V_r, V_r]$). The maximum possible absolute accumulated value is:

$$|\text{accumulated}|_{\max} = 32 \times P_r \times V_r$$

For the accumulator to remain within FP16's representable range, we require:

$$32 \times P_r \times V_r \leq 65504$$

Rearranging:

$$P_r \times V_r \leq \frac{65504}{32} = 2047$$

This is the fundamental constraint derived in Section 3.1 of the paper. Any pair of quantization ranges $(P_r, V_r)$ whose product is $\leq 2047$ is mathematically guaranteed to never overflow the FP16 accumulator during the `mma.m16n8k32` instruction, regardless of the actual data values.

**Why SageAttention2's values violate the constraint.** In SageAttention2, both $\tilde{P}$ and V are quantized with $P_r = V_r = 448$ (the E4M3 maximum). The product is $448 \times 448 = 200,704$, which exceeds 2047 by nearly two orders of magnitude. The maximum possible accumulation is $32 \times 448 \times 448 = 6,422,528$, which far exceeds FP16's limit of 65,504. This is why SageAttention2 required the FP32 accumulator.

**The design space of feasible pairs.** With the constraint $P_r \times V_r \leq 2047$, the quantization ranges of $\tilde{P}$ and V become coupled design variables. If we reduce $P_r$, we can keep $V_r$ larger, and vice versa. The paper explores three specific feasible pairs (Table 2):

| $P_r$ | $V_r$ | Product ($P_r \times V_r$) | Attention Cosine Similarity | Attention L1 Error |
|-------|-------|---------------------------|----------------------------|---------------------|
| 448 | 448 | 200,704 (infeasible) | 99.97% (SageAttn2 baseline) | 0.01862 |
| 448 | 2.25 | 1,008 (feasible) | 99.97% | 0.01863 |
| 224 | 4.5 | 1,008 (feasible) | 99.97% | 0.01862 |
| 112 | 9 | 1,008 (feasible) | 99.97% | 0.01863 |

The key empirical finding is that **all feasible pairs produce effectively identical attention accuracy**. The cosine similarity between the quantized attention output and full-precision attention output is 99.97% in all cases, and the relative L1 error varies only in the fifth decimal place (0.01862–0.01863). This is the critical result that makes the approach viable: narrowing the quantization ranges does not hurt accuracy because the FP8 E4M3 format has enough precision (3 mantissa bits, providing about 7–8% relative precision) to represent the quantized values accurately even when the representable range is reduced from $\pm 448$ to as low as $\pm 112$ for $\tilde{P}$ or $\pm 2.25$ for V.

**Understanding the quantization scale factor transformation.** With SageAttention2's original quantization, the scale factors were:

$$\delta_P^{\text{old}} = \frac{\max(|\tilde{P}|)}{448}, \quad \delta_V^{\text{old}} = \frac{\text{colmax}(|V|)}{448}$$

With the new quantization ranges, the scale factors become:

$$\delta_P^{\text{new}} = \frac{\max(|\tilde{P}|)}{P_r}, \quad \delta_V^{\text{new}} = \frac{\text{colmax}(|V|)}{V_r}$$

The effect of reducing the denominator from 448 to a smaller value (e.g., 224 for $\tilde{P}$, 4.5 for V) is that the scale factor becomes **larger**. A larger scale factor means the FP8 quantized value $\hat{P} = \tilde{P} / \delta_P$ becomes **smaller** in magnitude for a given $\tilde{P}$ value. The reconstruction $PV = \hat{P}\hat{V} \times \delta_P \times \delta_V$ remains mathematically correct because the larger scale factors are multiplied back, but the quantized representation operates in a narrower numeric range that stays within the FP16 accumulator's limits.

This is analogous to changing the unit of measurement: if you measure a length in meters versus centimeters, the numerical value changes by a factor of 100, but the actual length is the same when you multiply by the appropriate conversion factor. Narrowing the quantization range is like choosing a coarser unit — the stored integers are smaller, the scale factor is larger, and the reconstructed product is unchanged (up to the precision of the FP8 quantization itself).

---

#### The Delayed FP32 Buffering Optimization (Section 3.2)

With the basic constraint $P_r \times V_r \leq 2047$, SageAttention2++ can already use the `mma.f16.f8.f8.f16` instruction without overflow. But there is an additional hardware overhead that further constrains the design: the transformation of accumulated values from FP16 to FP32.

**The problem: data type conversion overhead.** After the `mma.m16n8k32` instruction completes, its accumulated results are stored in FP16 registers. But the subsequent steps of the attention computation — adding the bias, applying the residual connection, integrating with other layers — operate in FP32. Converting each FP16 accumulator output to FP32 requires explicit PTX (Parallel Thread Execution) conversion instructions, which consume instruction issue slots and register bandwidth. If every `mma` instruction result is immediately converted to FP32, this conversion overhead is incurred on every tile.

**The solution: accumulate two tiles, convert once.** The paper proposes to accumulate the results of **two consecutive** `mma.m16n8k32` instructions in FP16 before converting the combined result to FP32. This halves the number of conversion instructions — from one per MMA to one per two MMAs — reducing the conversion overhead by 50%.

**The cost: tighter range constraint.** Accumulating two tiles in FP16 means the FP16 accumulator must hold values up to the sum of two independent $k=32$ product accumulations. The maximum absolute value in the buffered accumulator is:

$$|\text{buffered}_{\max}| = 2 \times 32 \times P_r \times V_r = 64 \times P_r \times V_r$$

To stay within FP16's range:

$$64 \times P_r \times V_r \leq 65504$$

$$P_r \times V_r \leq \frac{65504}{64} \approx 1023$$

which the paper approximates as $2047/2 \approx 1023$ (Equation 3). This is a factor of 2 reduction from the basic constraint, making the feasible $(P_r, V_r)$ pairs more restricted.

The paper explicitly acknowledges this tradeoff: the delayed buffering improves throughput by reducing conversion overhead, but at the cost of halving the allowable quantization range product. Whether this tradeoff is beneficial depends on whether the quantized attention accuracy remains acceptable under the tighter constraint — and Table 2 shows that it does, because all the tested feasible pairs ($448 \times 2.25 = 1008$, $224 \times 4.5 = 1008$, $112 \times 9 = 1008$) have products well below both 2047 and 1023, and all achieve identical attention accuracy.

---

#### Selecting the Final Configuration: Pr = 224, Vr = 4.5

With both constraints established ($P_r \times V_r \leq 2047$ without buffering, $\leq 1023$ with buffering) and empirical evidence that attention accuracy is insensitive to the specific $(P_r, V_r)$ pair within these bounds, the choice of $P_r = 224$ and $V_r = 4.5$ is driven by performance considerations rather than accuracy.

Looking at the tested pairs in Table 2:

- $(P_r = 448, V_r = 2.25)$ keeps $\tilde{P}$ at full FP8 range ($\pm 448$) but heavily constrains V to $\pm 2.25$. This might seem attractive because $\tilde{P}$ values are naturally in $[0, 1]$ (attention probabilities) and are quantized to FP8 only because integer quantization would be inappropriate for probabilities — keeping $P_r$ large means $\delta_P$ stays small, which might better preserve the distribution of attention weights. However, V values can have much larger dynamic range (the value vectors are unnormalized layer outputs), and constraining them to $\pm 2.25$ requires $\delta_V$ to be large, potentially losing precision in channels where values are much smaller than the channel maximum.

- $(P_r = 224, V_r = 4.5)$ represents a balanced tradeoff: both $\tilde{P}$ and V are constrained to about half the FP8 maximum (224 vs. 448, and 4.5 vs. 9 if we were to double to keep the product constant). This balanced constraint means neither matrix's quantization is disproportionately aggressive, which is likely beneficial for numerical stability and cache behavior.

- $(P_r = 112, V_r = 9)$ pushes $\tilde{P}$ to a very narrow range while giving V more headroom. The paper selects against this presumably because $\tilde{P}$ encodes the softmax-normalized attention distribution, and overly aggressive quantization of softmax probabilities can introduce artifacts in the attention pattern that affect downstream layer computations, even if the immediate attention output cosine similarity remains high.

The paper states that they "select $P_r = 224$ and $V_r = 4.5$ for optimal performance" (end of Section 3.2), though they do not provide a detailed ablation comparing the throughput of different $(P_r, V_r)$ pairs. The throughput difference between these pairs would be negligible since they all use the same instruction sequence (same number of MMA operations, same conversion overhead from the buffering optimization). The "optimal performance" likely refers to the balanced quantization strategy being most robust to per-model variations in $\tilde{P}$ and V distributions across the diverse set of models tested (Llama, CogvideoX, HunyuanVideo, Wan, Flux, Stable-Diffusion3.5).

---

#### How the Scale Factors Are Applied in Practice

The modification to SageAttention2's code is surgical: only the computation of the scale factors $\delta_P$ and $\delta_V$ changes. The rest of the kernel — the tiling, the $QK^T$ computation, the softmax, the online normalization, the memory access patterns — is inherited verbatim from SageAttention2.

Concretely, for each block during the attention computation:

1. **$\tilde{P}$ quantization (modified).** After the softmax produces $\tilde{P}$ for the current block, compute $\delta_P = \max(|\tilde{P}|) / 224$ (instead of dividing by 448). Quantize each element to $\hat{P} = \text{FP8-round}(\tilde{P} / \delta_P)$. The quantized values are now in the range $[-224, 224]$ instead of $[-448, 448]$.

2. **V quantization (modified).** For each channel of V, compute $\delta_V = \text{colmax}(|V|) / 4.5$ (instead of dividing by 448). Quantize each element to $\hat{V} = \text{FP8-round}(V / \delta_V)$. The quantized values are now in the range $[-4.5, 4.5]$ instead of $[-448, 448]$.

3. **Matrix multiply with buffering.** Execute pairs of `mma.m16n8k32` instructions on the quantized tiles using `mma.f16.f8.f8.f16`. After each pair, convert the buffered FP16 accumulation to FP32 using a single PTX conversion instruction. The product of the quantized values and the accumulation of 32 (or 64 with buffering) products per output element is guaranteed to stay within FP16 range because $224 \times 4.5 = 1008 \leq 1023$.

4. **Rescaling.** Multiply the resulting FP32 matrix by $\delta_P \times \delta_V$ to recover the correct magnitude. This rescaling is identical to SageAttention2's procedure, just with different $\delta_P$ and $\delta_V$ values.

The mathematical identity being exploited is:

$$PV = \hat{P}\hat{V} \times \delta_P \times \delta_V = \left(\text{FP8-round}\left(\frac{\tilde{P}}{\delta_P}\right) \times \text{FP8-round}\left(\frac{V}{\delta_V}\right)\right) \times \delta_P \times \delta_V$$

which holds (approximately, up to FP8 rounding error) regardless of the specific values of $\delta_P$ and $\delta_V$, as long as they correctly normalize the input data to within the FP8 representable range. Changing $\delta_P$ from $\max(|\tilde{P}|)/448$ to $\max(|\tilde{P}|)/224$ and $\delta_V$ from $\text{colmax}(|V|)/448$ to $\text{colmax}(|V|)/4.5$ changes only the quantization granularity — the reconstruction formula automatically compensates through the larger scale factors.

---

#### Why This Approach Was Not Obvious Ex Ante

The paper's approach might seem straightforward in hindsight — "just reduce the quantization range to prevent overflow" — but there were non-obvious risks that the experiments had to validate:

**Risk 1: Accuracy degradation from reduced quantization range.** Narrowing $P_r$ from 448 to 224 means each quantized $\hat{P}$ value represents a larger slice of the original $\tilde{P}$ range — the quantization step size increases by a factor of 2. This could have introduced visible degradation in attention accuracy, especially for attention heads with very peaked distributions where small differences in attention weights matter. Table 2 shows this risk does not materialize — cosine similarity remains at 99.97% across all pairs — but this is an empirical finding, not a theoretical guarantee.

**Risk 2: Per-channel V quantization with very small range.** Constraining V to $[-4.5, 4.5]$ is significantly more aggressive than the original $[-448, 448]$. For channels of V with very large values, the scale factor $\delta_V$ must be very large to bring those values into range, which means channels with small values get quantized to zero (since their values divided by a large $\delta_V$ fall below the FP8 minimum representable value). This could theoretically lose important fine-grained information in low-magnitude channels. The attention accuracy metrics in Table 2 suggest this loss is negligible, but it is a genuine concern that had to be empirically validated.

**Risk 3: Accumulator overflow from distribution outliers.** The constraint $P_r \times V_r \leq 1023$ is derived assuming worst-case values — if any single element of $\hat{P}$ is at the maximum $P_r$ and any corresponding element of $\hat{V}$ is at the maximum $V_r$, the product hits the bound. In practice, quantized values are not all at the maximum simultaneously, so the actual accumulations are typically far below the theoretical maximum. The constraint is a sufficient condition for safety, not a necessary one — a looser constraint might also be safe in practice. However, the paper chooses the conservative approach of guaranteeing no overflow under any input distribution, which is the correct engineering choice for a plug-and-play kernel that must work across diverse models and input distributions without per-model tuning.

**Risk 4: The buffering optimization's actual throughput benefit.** The delayed FP32 buffering reduces conversion instruction count by 2×, but the conversion instructions are only a fraction of the total instruction mix. The actual throughput improvement from buffering might be small if the kernel is bound by memory bandwidth or Tensor Core throughput rather than instruction issue rate. The paper does not provide an ablation comparing buffered vs. unbuffered configurations at the same $(P_r, V_r)$, so the marginal benefit of buffering is not quantified — but the fact that they include it in the final configuration suggests it measurably improves performance on their target GPUs.

## 4. Key Insights and Innovations

### Innovation 1: Accumulator-Aware Quantization Range Selection as a First-Class Design Dimension

**What makes this distinctive at the idea level.** The paper introduces the concept that in low-precision GPU kernel design, the choice of quantization range for input matrices is not an independent decision — it is coupled to the accumulator data type of the Tensor Core instruction through a hard numerical constraint. Prior to this work, quantization range selection (e.g., choosing FP8's E4M3 range of ±448 for all activations) and instruction selection (e.g., picking `mma.f32.f8.f8.f32` vs. `mma.f16.f8.f8.f16`) were treated as orthogonal design choices: you picked your quantization format based on accuracy considerations, then picked the fastest instruction that supported that format. SageAttention2 followed this pattern: it quantized to FP8 E4M3 (±448) and selected the instruction that could handle the resulting products (the FP32-accumulator variant), accepting the throughput penalty as the cost of using FP8 at all.

This paper demonstrates that the causal arrow can be reversed — and that doing so unlocks performance. Specifically, the paper identifies that the FP16 accumulator's representable range imposes a constraint on the product of the quantization ranges of the two input matrices: $P_r \times V_r \leq 2047$ (or $\leq 1023$ with buffering). Once this constraint is recognized as the binding design rule, the quantization ranges become **tunable parameters** that can be deliberately narrowed to satisfy the constraint, enabling the use of the faster FP16-accumulator instruction. This is not an optimization of an existing design point; it is the discovery of a new design point that was previously invisible because the coupling between accumulator range and quantization range was not explicitly modeled.

**Comparison to prior work.** In SageAttention2, the quantization ranges were chosen to maximize the representable range of FP8 — the E4M3 maximum of 448 was used for both $\tilde{P}$ and V. This is the natural default: if you're going to use an 8-bit format, you might as well use its full dynamic range. The field's dominant assumption was that aggressive quantization (smaller range, coarser quantization step) degrades accuracy, and that accuracy preservation requires giving each quantized tensor as much representational headroom as the format allows. This assumption is embedded in standard post-training quantization pipelines (e.g., in the quantization literature surveyed in Appendix F of SageAttention2), where per-channel or per-tensor ranges are calibrated to minimize reconstruction error, not to satisfy a downstream accumulator constraint.

**Significance beyond raw performance.** The conceptual contribution is a **design methodology** rather than a specific technique. The paper shows that accumulator-aware range selection generalizes: the same logic that produced $P_r=224, V_r=4.5$ for FP16 accumulation on Ada Lovelace could be applied to other accumulator types (FP32, INT32, BF16), other input formats (INT8, FP4), and other GPU architectures with different accumulator throughput characteristics. The constraint equation $P_r \times V_r \leq \text{accumulator\_max} / k$ (where $k$ is the inner dimension tile size) is a portable design rule that any kernel developer can apply. This reframes quantization not as "find the ranges that minimize per-element error" but as "find the ranges that maximize instruction throughput while satisfying the accumulator safety constraint and the accuracy budget" — a constrained optimization problem rather than a simple error minimization.

**Is this incremental or fundamental?** This is a **fundamental reframing within the subdomain of quantized attention kernels**, though it is incremental in the broader context of GPU programming (where accumulator-aware design is well-known in other domains, e.g., mixed-precision linear algebra libraries). The paper's contribution is not discovering that FP16 accumulators have limited range — that's documented in NVIDIA's architecture whitepapers — but rather demonstrating that this constraint can be **surgically satisfied at the quantization stage** with zero accuracy cost for attention specifically, and that doing so unlocks a previously unavailable performance tier. This transforms the FP16 accumulator from a "don't use this, it's unsafe" warning in the GPU programming guide into a "use this, here's how to make it safe" optimization opportunity.

**Evidence anchor.** Table 2 shows that all feasible $(P_r, V_r)$ pairs within the constraint produce identical attention accuracy (99.97% cosine similarity, ~0.0186 L1 error), confirming that the constraint can be satisfied without accuracy loss. The speedup figures (Figure 1: 3.9× over FlashAttention2 for the (4+8) variant vs. SageAttention2's ~3.0×) demonstrate that the unlocked instruction provides a real throughput gain — the FP16 accumulator variant genuinely adds ~30% speedup on top of SageAttention2's already-optimized kernel.

---

### Innovation 2: Delayed FP32 Buffering as a Throughput Optimization that Compounds the Accumulator Constraint

**What makes this distinctive at the idea level.** The delayed FP32 buffering optimization (Section 3.2) is more than just an implementation trick — it is an example of **coupling instruction-level optimization to the quantization design space**. The insight is that the overhead of FP16-to-FP32 conversion instructions (which is a pure instruction-issue bottleneck, not an arithmetic throughput bottleneck) can be halved by accumulating two MMA results before conversion, but this doubles the effective accumulation depth from $k=32$ to $k=64$ products, which in turn halves the allowable quantization range product from $2047$ to $\approx 1023$. The optimization and the constraint are two sides of the same coin: you get the throughput benefit of reduced conversion overhead only if your quantization ranges are tight enough to tolerate the deeper buffered accumulation.

This is distinctive because it reveals an **instruction-level performance pathology** (PTX conversion instruction overhead) that would be invisible at the level of FLOP-counting or roofline analysis, and shows that the fix for this pathology has direct consequences for the numerical design of the kernel. Most kernel optimization papers treat instruction scheduling and numerical accuracy as separate concerns — the scheduling people optimize instruction mix and the quantization people optimize ranges, with a clear interface between them. This paper shows that for the specific case of accumulator type conversion in Tensor Core pipelines, the two concerns are inseparable: the buffering depth determines the effective accumulation length, which determines the safe quantization range, which determines the accuracy.

**Comparison to prior work.** In FlashAttention and FlashAttention2, the primary throughput optimizations are memory-level (tiling to reduce HBM accesses, recomputation to avoid materializing attention matrices) and parallelism-level (splitting work across thread blocks and warps). Instruction-level optimizations like this buffering technique are characteristic of the SageAttention family's focus on quantization — once you've committed to low-precision arithmetic, the instruction mix becomes a first-order performance concern because you're now issuing specialized Tensor Core instructions with non-trivial setup and teardown costs. Prior quantized attention work (SageAttention, SageAttention2) did not identify conversion instruction overhead as a bottleneck worth optimizing, likely because the FP32 accumulator variant doesn't have this problem — the accumulator is already in the target format.

**Significance beyond raw performance.** The buffering optimization demonstrates a general principle for mixed-precision kernel design: **when a computation pipeline has a mandatory precision conversion step, amortizing that conversion over a larger block of same-precision work shifts the pipeline balance toward arithmetic throughput rather than instruction overhead.** This principle applies beyond FP16→FP32 conversion — it is relevant to any kernel that must convert between narrow accumulator formats and wide downstream formats (e.g., INT32→FP32 in integer-quantized kernels, or BF16→FP32 in mixed-precision training kernels). The specific technique of buffering two MMA results is architecture-specific (it depends on the PTX conversion instruction cost and register file capacity on Ada/Blackwell), but the design pattern — identify conversion overhead, amortize through buffered accumulation, and verify that the buffering doesn't break numerical constraints — is reusable.

**Is this incremental or fundamental?** This is a **clever incremental optimization** whose significance is amplified by its interaction with Innovation 1. On its own, delayed FP32 buffering is a standard technique (instruction fusion, batching conversion operations) applied to a specific instruction sequence. What elevates it is that it **tightens the accumulator constraint** and the paper explicitly models this interaction — the constraint tightens from $P_r \times V_r \leq 2047$ to $P_r \times V_r \leq 1023$, and the paper verifies that the chosen $(224, 4.5)$ pair ($1008 \leq 1023$) still satisfies the tighter bound. This interaction between an instruction-level throughput hack and a numerical constraint is the kind of cross-layer reasoning that distinguishes excellent systems work from "we tried all the instruction flags and picked the fastest one."

**Evidence anchor.** The paper does not provide an explicit ablation comparing buffered vs. unbuffered configurations, which is a weakness — we cannot quantify the marginal throughput benefit of buffering alone. However, the fact that the final selected configuration satisfies the tighter constraint ($1008 \leq 1023$) and that the throughput numbers in Figures 1–4 represent the buffered implementation suggests that the optimization was deployed in the final kernel and contributed to the measured speedups. The accuracy results in Table 2 confirm that the tighter constraint does not degrade attention quality.

---

### Innovation 3: Empirical Demonstration that Quantization Range Reduction Has Zero Accuracy Cost for Attention

**What makes this distinctive at the idea level.** The paper provides a crisp empirical result that challenges a natural intuition: that reducing the FP8 quantization range of $\tilde{P}$ from ±448 to ±224 (a 2× reduction) and V from ±448 to ±4.5 (a ~100× reduction) should visibly degrade attention accuracy. The data in Table 2 shows it does not — cosine similarity stays at 99.97%, L1 error stays at ~0.0186 across all tested pairs. This is not a theoretical result about FP8's representational capacity; it is an empirical finding about the **tolerance of the attention mechanism to quantization scale**, specifically, about the fact that the reconstruction formula $PV = \hat{P}\hat{V} \times \delta_P \times \delta_V$ is self-correcting — the larger scale factors compensate for the narrower quantized ranges, and the FP8 format has sufficient precision (3 mantissa bits) to preserve the relevant information about attention weight distributions and value vector magnitudes.

What makes this a genuine contribution rather than an obvious observation is the **asymmetric severity** of the range reduction. Halving $\tilde{P}$'s range from 448 to 224 is a modest change; the softmax probabilities are bounded in [0, 1] anyway, so even the original ±448 range was mostly unused. But reducing V's range from ±448 to ±4.5 is a ~100× reduction — it means a channel of V whose maximum value is, say, 200 will have a scale factor of 200/4.5 ≈ 44.4, and any element of that channel with value less than about 0.1 (44.4 × minimum-FP8-value) will quantize to zero. Intuition suggests this should lose information, and the fact that it does not — that the per-channel scaling is sufficient to preserve the information that matters for the downstream attention output — is a non-trivial empirical discovery about the structure of value matrices in Transformer attention.

**Comparison to prior work.** In the broader quantization literature, range reduction is typically associated with accuracy degradation — quantization-aware training and post-training quantization research focuses on finding the optimal clipping thresholds per tensor or per channel precisely because clipping too aggressively (reducing the representable range) throws away outlier information and hurts model quality. The standard approach to maintaining accuracy under aggressive quantization is to compensate through finer granularity (per-channel, per-group, per-token scaling) or through training (quantization-aware training, learned step sizes). SageAttention2 already uses per-channel scaling for V, but the finding here is that even with per-channel scaling, the range can be reduced by 100× with no measurable accuracy cost — the per-channel granularity is sufficient to absorb the range reduction.

**Significance beyond raw performance.** This finding has methodological implications for future work in quantized attention. It suggests that the FP8 quantization design space has a large "flat" region where accuracy is insensitive to the specific $(P_r, V_r)$ pair, and that the binding constraint on range selection is the accumulator safety constraint rather than the accuracy constraint. This inverts the typical quantization design flow: rather than asking "what is the most aggressive range I can use while maintaining accuracy?", one asks "what range satisfies the accumulator constraint, and is that range within the accuracy flat region?" If the answer is yes (as it is here), accuracy is not a limiting factor at all — the quantization ranges are determined entirely by hardware constraints. This could generalize: for any matrix multiply where the accumulator type creates a range constraint, the first step should be to check whether the constraint-violating ranges are in the flat region, and if so, just satisfy the constraint rather than searching for an accuracy-optimal range.

**Is this incremental or fundamental?** This is a **valuable empirical finding** that adds confidence to the accumulator-aware design methodology (Innovation 1). Without Table 2, the constraint $P_r \times V_r \leq 1023$ would be an abstract requirement, and a practitioner might worry that satisfying it requires sacrificing accuracy. Table 2 eliminates that worry for attention specifically — it shows the flat region exists and is wide. Whether this flat region exists for other operations (feed-forward layers, convolution, normalization) is an open question that this finding motivates but does not answer.

**Evidence anchor.** Table 2 presents the three tested $(P_r, V_r)$ pairs and the attention accuracy metrics, all of which are essentially identical. The metrics are computed on CogvideoX (averaged across all attention layers), which is a representative video diffusion transformer — the finding should generalize to other Transformer architectures since attention mechanism structure is consistent, but the paper only provides this ablation for one model.

---

### Innovation 4: The "Plug-and-Play with Zero Downside" Standard as a Desirable Property for Kernel Optimizations

**What makes this distinctive at the idea level.** The paper implicitly establishes a standard for what constitutes a successful kernel optimization in the attention acceleration space: the optimization should match the accuracy of its predecessor exactly (not within some tolerance — literally matching, as Table 3 shows with metrics fluctuating within noise), while providing a speedup that requires no model-specific tuning, no calibration, no retraining, and no change to model architecture. This standard is higher than what is typically accepted in the quantization literature, where "minor degradation" (e.g., 0.1–0.5 perplexity increase, 1–2% accuracy drop) is considered acceptable for the sake of efficiency. SageAttention2++ claims to **strictly dominate** SageAttention2 on the speed-accuracy Pareto frontier — same accuracy, higher speed — which means any existing SageAttention2 user should switch unconditionally.

This standard matters because it reduces adoption friction to near zero. A practitioner who has already validated that SageAttention2 produces acceptable outputs for their application can upgrade to SageAttention2++ by changing a library import, with zero additional validation burden — the paper's claim that accuracy is unchanged means the outputs are bitwise-nearly-identical (not just "similar enough for the end task"), and the comprehensive end-to-end metrics in Table 3 across six models and multiple metrics per model demonstrate that this holds across diverse use cases. Compare this to, say, adopting a sparsity-based attention method, where the practitioner must re-evaluate whether the sparsity pattern works for their specific model and sequence lengths.

**Comparison to prior work.** FlashAttention2 over FlashAttention represents a similar "strictly dominates" improvement — it provides identical mathematical results (same exact attention, no quantization) with higher throughput through better parallelism and work partitioning. SageAttention over full-precision attention, by contrast, is **not** strictly dominant — it introduces quantization error, which users must validate for their specific models. The progression from SageAttention (quantized, some accuracy loss) to SageAttention2 (improved quantization, less loss) to SageAttention2++ (further optimized, same loss as SageAttention2) represents a trajectory toward the FlashAttention2 ideal: each step reduces the accuracy gap or improves the throughput, converging toward the "same math, faster" property.

**Significance beyond raw performance.** The "strictly dominates" standard, if adopted by the field, changes the nature of kernel optimization research. Rather than trading accuracy for speed (which requires per-model Pereto analysis), researchers would aim to find optimizations that are purely additive — they improve some dimension (speed, memory, latency) while leaving others unchanged. This is a more demanding standard but yields results with much higher practical impact, because adoption requires zero risk assessment. SageAttention2++ demonstrates that this standard is achievable for quantized attention — there exist quantization techniques that are as fast as aggressive quantization and as accurate as conservative quantization, by choosing the right instruction-level design point.

**Is this incremental or fundamental?** This is more a **philosophical contribution to the evaluation methodology** than a technical innovation. The paper does not explicitly argue for the "strictly dominates" standard — it simply reports results that happen to meet it. However, the fact that the paper's evaluation is structured to demonstrate exact accuracy matching (Table 2's attention-level metrics, Table 3's end-to-end metrics, and Figures 5–7's visible examples all converging on "identical") suggests the authors view this as the relevant bar. If future kernel optimization papers adopt this framing — explicitly aiming for Pareto-dominant improvements rather than Pareto-tradeoff improvements — this paper's evaluation methodology will have been influential.

**Evidence anchor.** Table 3 is the key exhibit: for Llama3.1, perplexity is 6.013 (full-precision), 6.019 (SageAttn2), 6.020 (SageAttn2++) — differences in the third decimal place that are statistically indistinguishable. For Flux, FID is 165.117 (full-precision), 163.185 (SageAttn2), 163.555 (SageAttn2++) — SageAttn2++ actually shows slightly better FID than SageAttn2, which is noise rather than a real improvement, but confirms the "no degradation" claim. The visible examples in Figures 5–7 further reinforce that generated outputs are visually indistinguishable.

## 5. Experimental Analysis

### Evaluation Methodology

- **Dataset.** The paper evaluates on three generation domains using standard benchmarks: text-to-text on WikiText (Merity et al., 2022) for perplexity, LAMBADA (Paperno et al., 2016) for contextual understanding accuracy, and a Needle-in-A-Haystack (NIAH) task (Kamradt, 2023); text-to-video on the Open-Sora prompt set (Zheng et al., 2024); and text-to-image on COCO annotations (Lin et al., 2014). Detailed dataset specifications appear in Appendix A.2.

- **Base model(s).** Six models spanning three modalities are evaluated: Llama3.1 (8B) (Dubey et al., 2024) for text-to-text; CogvideoX (2B), HunyuanVideo (Kong et al., 2024), and Wan (Wan et al., 2025) for text-to-video; and Flux (schnell) (Black Forest Labs, 2023) and Stable-Diffusion3.5 (turbo) (Stability AI, 2023) for text-to-image. This diverse selection covers state-of-the-art models across language, image, and video generation at scales ranging from 2B to 8B parameters.

- **Metrics.** Perplexity (Ppl.) (Jelinek et al., 1977) and accuracy (Acc.) for text models; CLIPSIM, CLIP-Temp (CLIP-T), VQA-a, VQA-t, and Flow-score (FScore) for video models (Liu et al., 2024; Wu et al., 2023); and FID (Heusel et al., 2017), sFID (Salimans et al., 2016), CLIP score (Hessel et al., 2021), and ImageReward (IR) (Xu et al., 2023) for image models. For kernel-level accuracy, the paper measures cosine similarity and relative L1 distance between quantized attention output O' and full-precision attention output O, defined as CosSim = ∑OO' / √(∑O²∑O'²) and L1 = ∑|O - O'| / ∑|O| (Appendix A.2).

- **Baselines.** FlashAttention2 (Dao, 2024), SageAttention (Zhang et al., 2025c), and SageAttention2 (Zhang et al., 2025a) serve as the primary baselines. The paper explicitly notes that FlashAttention3 (Shah et al., 2024) cannot run on RTX4090 and RTX5090 (it requires Hopper GPUs), making FlashAttention2 the relevant speed baseline for the consumer GPU class being targeted. Full-precision (unquantized) attention serves as the accuracy reference for end-to-end metrics.

- **Generation budget / compute accounting.** Kernel throughput is measured in TOPS (Tera Operations Per Second) across sequence lengths from 1K to 32K, with separate configurations for head dimensions of 64 and 128 and for both causal and non-causal attention masks. This captures throughput scaling behavior across the range of sequence lengths encountered in practice. Speedups are reported as multiplicative factors relative to FlashAttention2 at the same sequence length and configuration.

- **Cross-validation / statistical protocol.** The paper does not employ cross-validation or report confidence intervals. End-to-end metrics are reported as single numerical values per model per method (Table 3), which means the variability of these metrics (e.g., FID computed on different subsets of COCO, or perplexity on different WikiText splits) is not characterized. For the attention-level accuracy ablation (Table 2), metrics are averaged across all attention layers of CogvideoX and reported to 4–5 significant figures.

### Main Quantitative Results

#### Kernel-Level Throughput

**Headline result.** On RTX4090 at headdim=128 with no causal mask, SageAttention2++(4+8) achieves 489 TOPS at sequence length 32K compared to FlashAttention2's 164 TOPS — a 3.0× speedup for the (8+8) variant and a 3.9× speedup for the (4+8) variant (Figure 1, top row). On RTX5090 at the same configuration, SageAttention2++(8+8) achieves approximately 643 TOPS at sequence length 32K vs. FlashAttention2's ~214 TOPS (Figure 3, top row).

**Comparison to SageAttention2.** The key comparison is SageAttention2++ vs. SageAttention2, since the paper's claim is about improving on SageAttention2's throughput. At headdim=128, causal=False, sequence length 32K on RTX4090 (Figure 1, top row):

- FlashAttention2: 164 TOPS
- SageAttention2(4+8): 489 TOPS (2.98× over FlashAttn2)
- SageAttention2++(4+8): **493 TOPS (3.01× over FlashAttn2)**
- SageAttention2(8+8): 422 TOPS (2.57× over FlashAttn2)
- SageAttention2++(8+8): **440 TOPS (2.68× over FlashAttn2)**

The improvement of SageAttention2++ over SageAttention2 is approximately 1.04× for the (4+8) variant and 1.04× at this sequence length. The absolute TOPS gain appears modest at 32K, but the pattern varies by sequence length. At shorter sequence lengths (1K–4K), the gap is larger: at 1K, SageAttention2(8+8) achieves approximately 346 TOPS while SageAttention2++(8+8) achieves approximately 411 TOPS — a 1.19× improvement. This suggests the FP16 accumulator benefit is more pronounced when the PV multiplication constitutes a larger fraction of total kernel time (at shorter sequences where the tiling overhead and softmax computation are proportionally smaller relative to the matrix multiply arithmetic).

**The 3.9× claim.** The paper's headline "3.9× speedup over FlashAttention" refers specifically to the SageAttention2++(4+8) configuration at the most favorable sequence length in their benchmarks. Reading Figure 1 carefully: at headdim=128, causal=False, the FlashAttention2 baseline ranges from 145 TOPS (at 1K) to 164 TOPS (at 32K), while SageAttention2++(4+8) ranges from 574 TOPS (at 1K) to 493 TOPS (at 32K). The ratio 574/145 = 3.96× at 1K is likely the source of the "3.9×" figure. This is an accurate but selective reporting — the speedup at 32K (the longest sequence length tested, which is the regime where attention dominates) is approximately 3.0× for (4+8) and 2.7× for (8+8). The paper does not explicitly state which sequence length the headline 3.9× comes from, which is a minor reporting ambiguity.

**Causal vs. non-causal attention.** With causal masking (Figure 1, bottom row), throughput is lower across all methods because only the lower triangular portion of the attention matrix is computed, but the speedup ratios remain similar. At 32K, FlashAttention2 achieves 161 TOPS, SageAttention2(4+8) achieves 478 TOPS, and SageAttention2++(4+8) achieves 489 TOPS — essentially identical to the non-causal case.

**Headdim=64 results (Figure 2).** At the smaller head dimension, absolute TOPS are lower across all methods because the smaller inner dimension provides less parallelism for Tensor Cores. At 32K, causal=False: FlashAttention2 achieves 167 TOPS, SageAttention2(4+8) achieves 443 TOPS, and SageAttention2++(4+8) achieves 451 TOPS — a 2.7× speedup over FlashAttention2 and a negligible improvement over SageAttention2. The (8+8) variant shows SageAttention2 at 385 TOPS vs. SageAttention2++ at 413 TOPS, a 1.07× improvement at 32K and larger differences at shorter sequence lengths (1K: 252 TOPS vs. 287 TOPS, a 1.14× improvement).

**RTX5090 results (Figures 3 and 4).** On the newer RTX5090 (Blackwell architecture), the speedups are qualitatively similar but with higher absolute TOPS across all methods. At headdim=128, causal=False, 32K (Figure 3): FlashAttention2 achieves ~214 TOPS, SageAttention2(8+8) achieves ~583 TOPS, and SageAttention2++(8+8) achieves ~643 TOPS. The paper does not benchmark the (4+8) variant of SageAttention2 on RTX5090 — only the (8+8) configuration is shown for both SageAttention2 and SageAttention2++. The speedup of SageAttention2++ over SageAttention2 at 32K is approximately 643/583 = 1.10×, consistent with the RTX4090 pattern of modest but real gains at long sequences and larger gains at shorter sequences.

**Important observation about the "3.9×" figure.** The paper's abstract claims "SageAttention2++ achieves a 3.9× speedup over FlashAttention," which corresponds to the most favorable (4+8) variant at short sequence lengths. The comparison that matters most for the paper's contribution — SageAttention2++ vs. SageAttention2 — shows more modest improvements. At the longest sequence lengths (32K) where attention computation is most critical, SageAttention2++(8+8) is approximately 1.04–1.07× faster than SageAttention2(8+8) at headdim=128 and 1.07–1.14× at shorter lengths. This is a real improvement, but it's a refinement rather than a breakthrough relative to the prior version. The paper's framing emphasizes the speedup over FlashAttention2 (which includes both the quantization benefit from SageAttention2's design and the incremental FP16 accumulator benefit), which is a fair but broader claim.

#### End-to-End Model Performance

**Headline result.** Table 3 shows that SageAttention2++(8+8) incurs "almost no metrics loss" across all six models, while SageAttention2++(4+8) "brings a little metrics loss" relative to full-precision attention, with both variants matching SageAttention2's accuracy at the corresponding quantization level.

**Llama3.1 (8B) text generation.** The perplexity on WikiText is 6.013 (full-precision), 6.019 (SageAttn2(8+8)), and 6.020 (SageAttn2++(8+8)) — a difference of +0.007 for SageAttn2 and +0.007 for SageAttn2++ relative to full-precision, both within expected noise. LAMBADA accuracy is 0.815 (full-precision), 0.811 (SageAttn2(8+8)), and 0.813 (SageAttn2++(8+8)) — a slight degradation of 0.004 and 0.002 respectively. NIAH accuracy is 0.906, 0.903, and 0.901 — a degradation of 0.003 and 0.005. These metrics confirm that SageAttention2++ preserves the same level of accuracy as SageAttention2 on language tasks, with all differences well below what would be considered practically meaningful.

**CogvideoX (2B) video generation.** The metrics tell a nuanced story. CLIPSIM and CLIP-T are essentially identical across all methods at ~0.179 and ~0.997 respectively, confirming that text-video alignment is preserved. However, the technical quality metrics show more variation: VQA-a for SageAttn2++(8+8) is 76.309, which is higher than full-precision's 74.499 — this is noise, not a real improvement, and illustrates the variance in these metrics. The VQA-t metric shows SageAttn2++(8+8) at 73.165 vs. full-precision's 74.642 and SageAttn2(8+8)'s 74.447 — a slight degradation of ~1.5 points. Flow-score shows 4.386 for SageAttn2++(8+8) vs. 4.974 for full-precision and 4.899 for SageAttn2(8+8) — a degradation of ~0.5 points. These video quality metrics are known to be noisy (Appendix A.2 notes they are evaluated on the Open-Sora prompt set, which is not a standardized benchmark with established variance characteristics), so the fluctuations may not be statistically significant, but the paper does not provide error bars or multiple evaluation runs to establish variance.

For the (4+8) variants, the pattern is more pronounced: VQA-t drops from 74.642 (full-precision) to 66.396 (SageAttn2(4+8)) and 66.568 (SageAttn2++(4+8)), a degradation of ~8 points. This is expected — the (4+8) variant uses INT4 for Q/K, which is more aggressive quantization than the (8+8) INT8 variant. The key point is that SageAttention2++(4+8) matches SageAttention2(4+8) in this degradation, confirming no additional loss from the FP16 accumulator change.

**HunyuanVideo.** The pattern is similar: metrics are largely consistent between SageAttention2 and SageAttention2++ at the same quantization level. For (8+8): CLIPSIM 0.175 for both; VQA-t 54.878 (SageAttn2) vs. 51.080 (SageAttn2++) — a larger fluctuation that, given the absence of error bars, should be interpreted as noise rather than systematic degradation. Flow-score is 1.176 vs. 1.192 — essentially identical.

**Wan.** Again, metrics track closely. For (8+8): CLIPSIM is 0.172 for both; CLIP-T is 0.999 for both; VQA-a is 49.794 (SageAttn2) vs. 50.876 (SageAttn2++) — slightly better for SageAttn2++, but this is noise; Flow-score is 1.870 vs. 1.902 — essentially identical.

**Flux and Stable-Diffusion3.5 image generation.** For Flux: FID is 163.185 (SageAttn2(8+8)) vs. 163.555 (SageAttn2++(8+8)), both slightly better than full-precision's 165.117; sFID is 146.101 vs. 146.036, both slightly better than full-precision's 147.831; CLIP score is 31.453 vs. 31.445, both close to full-precision's 31.401; ImageReward is 0.905 vs. 0.902, both slightly below full-precision's 0.912. The (4+8) variants show identical metrics between SageAttn2 and SageAttn2++ — FID 164.170 for both, sFID 147.185 for both, etc. — confirming that the FP16 accumulator change introduces zero additional degradation.

For Stable-Diffusion3.5: FID is 164.971 (SageAttn2(8+8)) vs. 165.842 (SageAttn2++(8+8)), both slightly better than full-precision's 166.369. The (4+8) variants are again identical between SageAttn2 and SageAttn2++ across all metrics.

**Visible examples (Figures 5, 6, 7).** The paper includes qualitative comparisons showing generated images and video frames from Flux, Stable-Diffusion3.5, CogvideoX, HunyuanVideo, and Wan. The images appear visually indistinguishable between full-precision, SageAttention2++(8+8), and SageAttention2++(4+8) — colors, composition, detail level, and artifacts are subjectively identical. This is consistent with the quantitative metrics but does not constitute formal evidence; it serves primarily as a sanity check that the quantization is not introducing visually obvious artifacts.

**Key takeaway from end-to-end results.** The data in Table 3 overwhelmingly supports the claim that SageAttention2++ preserves SageAttention2's accuracy. In every model, every metric, and every quantization variant, the SageAttention2++ numbers are within the noise range of the corresponding SageAttention2 numbers. There is no systematic trend of SageAttention2++ performing worse (or better) than SageAttention2. The claim of "negligible end-to-end metrics loss" is well-supported, with the (8+8) variant showing essentially zero loss and the (4+8) variant showing the same small loss as SageAttention2(4+8).

### Ablation Studies and Robustness Checks

**Quantization range pair feasibility (Table 2).** The paper tests three feasible (Pr, Vr) pairs that satisfy the FP16 accumulator constraint: (448, 2.25), (224, 4.5), and (112, 9), all with product 1008 (≤ 1023). The results show attention-level accuracy is invariant to the specific pair: cosine similarity is 99.97% and relative L1 error ranges from 0.01862 to 0.01863 across all pairs, including the original SageAttention2 baseline (Pr=448, Vr=448, product=200704, which is infeasible for FP16 accumulation). This demonstrates that the accuracy "flat region" in quantization range space is wide enough that the accumulator constraint can be satisfied without any accuracy cost. The fact that even the most aggressive pair (Pr=112, Vr=9) achieves identical metrics to the least aggressive pair (Pr=448, Vr=2.25) suggests that the FP8 E4M3 format's precision is sufficient to absorb large range asymmetries in the quantization — a finding that is specific to attention's numerical properties and may not generalize to other operations.

**The (4+8) vs. (8+8) quantization level comparison (Table 3, all models).** This is not presented as a formal ablation but serves as one: across all models, the (4+8) variant (INT4 for Q/K) shows slightly larger metrics degradation than the (8+8) variant (INT8 for Q/K), which is expected since INT4 is coarser quantization. The critical robustness check is that SageAttention2++ matches SageAttention2 at **both** quantization levels — the FP16 accumulator change does not interact adversely with the more aggressive INT4 Q/K quantization.

**Cross-model robustness.** The paper evaluates on six models spanning three modalities, which serves as an implicit robustness check on the (Pr=224, Vr=4.5) configuration. Since these models have different attention patterns — causal language models (Llama3.1) have very different attention distributions than diffusion transformers (Flux, Stable-Diffusion3.5) or video models with spatial-temporal attention (CogvideoX, HunyuanVideo, Wan) — the fact that a single (Pr, Vr) pair works across all of them without per-model tuning confirms the generality of the approach. However, all models use Transformer attention, so this does not test generalization to non-Transformer architectures.

**Missing ablations.** Several ablations that would strengthen the paper are absent:

- **Buffered vs. unbuffered comparison.** The paper does not provide throughput numbers comparing the delayed FP32 buffering configuration against an otherwise-identical kernel without buffering (using the same Pr=224, Vr=4.5 but converting after every MMA instruction). This means the marginal benefit of the buffering optimization — which is a distinct technical contribution (Section 3.2) — is not quantified. The paper claims buffering "halv[es] the transformation overhead" but does not show what fraction of total kernel time this overhead represents.

- **Sensitivity to (Pr, Vr) choice on throughput.** The paper states that Pr=224 and Vr=4.5 are selected "for optimal performance" (Section 3.2) but does not provide throughput data for the alternative pairs (448, 2.25) or (112, 9). Since all pairs use the same instruction sequence, the throughput difference would be negligible for the PV multiplication itself, but there could be second-order effects from the different scale factors affecting memory access patterns or cache behavior. Without this data, the claim of optimality is asserted rather than demonstrated.

- **Ablation on per-channel vs. per-block granularity for V.** SageAttention2 uses per-channel quantization for V, which is critical for handling the diverse dynamic ranges across feature dimensions. The paper inherits this but does not test whether per-channel granularity remains adequate when the quantization range is reduced to ±4.5 — it is possible that for some channels with very small values, the combination of a large per-channel scale factor (to accommodate the channel's maximum) and the narrow representable range causes the smallest values to quantize to zero. The attention accuracy metrics suggest this is not a problem, but a direct analysis of the fraction of V values that quantize to zero (or below FP8's minimum subnormal) under the ±4.5 range would strengthen confidence.

- **Longer sequence lengths.** The kernel benchmarks stop at 32K, which is the longest sequence length shown. For language models that support 128K+ context windows, attention at longer sequences would be the most compute-intensive regime. The paper does not provide data on whether the speedup ratios hold or degrade at very long sequences.

### Critical Assessment

**Claim: "SageAttention2++ achieves a 3.9× speedup over FlashAttention."** This claim is supported only for the most favorable configuration — (4+8) variant, short sequence length (1K), non-causal attention, RTX4090. At the longest sequence length benchmarked (32K), the speedup is approximately 3.0× for the (4+8) variant and 2.7× for the (8+8) variant. At headdim=64, the speedups are lower (2.7× at 32K). The "3.9×" figure is an accurate maximum but not representative of the typical speedup a practitioner would observe in long-sequence inference scenarios where attention matters most. The abstract and introduction would benefit from qualifying this as a peak speedup and reporting the long-sequence speedup separately, since long sequences are the regime where attention acceleration is most urgently needed.

**Claim: "SageAttention2++ matches SageAttention2's attention accuracy."** Strongly supported. Table 2 shows identical cosine similarity (99.97%) and L1 error (~0.0186) between the methods at the attention output level. Table 3 shows end-to-end metrics that fluctuate within noise across all six models and all metrics. There is no evidence of any systematic accuracy difference between SageAttention2 and SageAttention2++. The claim of parity is convincingly demonstrated.

**Claim: "[SageAttention2++] maintains the same attention accuracy as SageAttention2."** The evidence supports this, but with a nuance: what is actually demonstrated is that SageAttention2++ matches SageAttention2 at the attention-output level (cosine similarity, L1) and at the end-to-end metric level. However, attention-output cosine similarity of 99.97% means the attention outputs are not bitwise identical — there is a 0.03% cosine dissimilarity. This is extremely small, but the paper's phrasing "maintaining the same attention accuracy" could be read as claiming exact mathematical equivalence. A more precise formulation would be "SageAttention2++ achieves attention accuracy indistinguishable from SageAttention2 by both cosine similarity and downstream task metrics."

**Claim: Plug-and-play acceleration with negligible end-to-end metrics loss across diverse models.** Supported with strong evidence. The paper's model diversity (language, image, video; 2B to 8B parameters; causal and bidirectional attention) is comprehensive for a kernel optimization paper. Every model shows the same pattern: SageAttention2++ metrics track SageAttention2 metrics within expected noise. The paper would be strengthened by reporting the variability of metrics (e.g., standard deviation of FID across multiple COCO subsets, or multiple evaluations of video metrics) to quantify what "negligible" means statistically, but the face-value pattern in Table 3 is clear and consistent.

**Weakness: No reporting of metric variance or statistical significance.** All end-to-end metrics in Table 3 are reported as scalar values without confidence intervals, standard deviations, or information about the number of evaluation samples. For metrics like FID (which is known to be sensitive to the number of generated images and the specific reference set), CLIPSIM (which depends on the specific CLIP model checkpoint and prompt set), and the video metrics (which are computed on unspecified numbers of generated videos), the differences between methods are likely within the noise floor of the evaluation procedure. The paper acknowledges this implicitly by not claiming improvements — only "negligible loss" — but explicit variance reporting would allow readers to assess whether differences of 1–2 FID points or 0.5 Flow-score points represent noise or signal.

**Weakness: The improvement over SageAttention2 is modest at long sequence lengths.** The headline speedup over FlashAttention2 obscures the more relevant comparison for existing SageAttention2 users: the improvement of SageAttention2++ over SageAttention2. At 32K sequence length, this improvement is 4–7% for the (8+8) variant and 1–4% for the (4+8) variant on RTX4090. At 1K, it is 19% for (8+8) and 18% for (4+8). These are genuine gains — a 19% speedup at no accuracy cost is valuable — but they represent refinement rather than breakthrough relative to the prior version. The paper's framing as "3.9× over FlashAttention2" correctly positions the work in the broader attention acceleration landscape, but a reader evaluating whether to upgrade from SageAttention2 to SageAttention2++ would care about the 4–19% incremental gain, not the 3.9× gain that was already mostly achieved by SageAttention2.

**Missing experiment: comparison against other quantized attention methods at matched throughput.** The paper compares against FlashAttention2 (FP16, exact) and the SageAttention family (quantized), but does not compare against other quantized attention approaches such as those that might use different quantization formats (INT8 for PV, for instance) or different instruction choices on the same hardware. This is understandable given the paper's narrow scope — it is specifically improving SageAttention2, not surveying all possible quantized attention implementations — but it means the claim that the (Pr=224, Vr=4.5) configuration is "optimal" is only demonstrated within the SageAttention2 design space, not across all possible quantized attention kernels.

**Missing analysis: What fraction of attention time is PV?** The paper's approach accelerates only the PV matrix multiplication, leaving QK^T unchanged. The speedup from using the FP16 accumulator instruction for PV is bounded by the fraction of total attention time spent in PV. At very long sequences, the QK^T multiplication (which produces the N×N attention matrix) can dominate runtime, especially in causal attention where the softmax must be computed for triangular matrices. The paper does not profile the time breakdown between QK^T and PV across sequence lengths, which would help explain why the SageAttention2++ improvement over SageAttention2 is smaller at 32K than at 1K — at longer sequences, the QK^T multiply may dominate, reducing the impact of PV acceleration. This profiling data would also help practitioners understand when SageAttention2++ provides the largest benefit.

**The visible examples are insufficient as evidence.** Figures 5, 6, and 7 show example outputs that appear visually identical between methods, but this is a weak form of evidence. Visual inspection cannot detect subtle quality differences that metrics might capture, and the selected examples may not be representative. The paper would benefit from a more rigorous quality assessment, such as a human preference study (even a small-scale one with 10–20 raters) or quantitative analysis of specific image properties (color distribution divergence, high-frequency detail preservation, artifact detection). That said, the primary evidence for accuracy preservation is the quantitative metrics in Table 3, and the visible examples serve as a qualitative sanity check that the metrics are not masking obvious visible degradation.

**Summary of experimental strength.** The paper provides comprehensive throughput benchmarks across two GPU architectures, two head dimensions, two masking modes, six sequence lengths, and two quantization levels — this is thorough kernel benchmarking. The end-to-end evaluation covers six models across three modalities with appropriate metrics for each — this is strong evidence for the plug-and-play claim. The attention-level accuracy ablation (Table 2) confirms that the quantization range reduction does not degrade the attention operation itself. The main weaknesses are the absence of variance reporting for end-to-end metrics, the absence of profiling data that would contextualize the PV acceleration's impact, and the somewhat modest incremental improvement over SageAttention2 at the longest sequence lengths where attention acceleration matters most. The experiments convincingly demonstrate that the approach works as described, but leave open questions about how much the improvement matters in the most compute-intensive long-sequence regime.

## 6. Limitations and Trade-offs

### The Headline 3.9× Speedup Is a Peak Figure, Not Representative of the Long-Sequence Regime Where Attention Acceleration Matters Most

**The assumption or constraint.** The paper's abstract and introduction prominently claim "a 3.9× speedup over FlashAttention" without qualification. This figure is achieved only at the shortest sequence length benchmarked (1K tokens) with the most aggressive quantization variant (4+8, using INT4 for Q/K) in the non-causal attention configuration on RTX4090 (Figure 1, top row: SageAttn2++(4+8) reaches ~574 TOPS at 1K vs. FlashAttn2's ~145 TOPS). The paper does not explicitly state which sequence length or configuration the 3.9× corresponds to, leaving the reader to extract it from the dense bar charts.

**The consequence.** A practitioner deploying this kernel for long-context language modeling, video generation, or any application with sequences of 8K–32K tokens — precisely the regime where attention's quadratic cost is most painful and acceleration is most urgently needed — would observe more modest speedups. At 32K, headdim=128, causal=False:

- SageAttn2++(4+8): ~493 TOPS vs. FlashAttn2's ~164 TOPS = **3.0× speedup**
- SageAttn2++(8+8): ~440 TOPS vs. FlashAttn2's ~164 TOPS = **2.7× speedup**

At headdim=64 (common in many Transformer architectures), the speedup at 32K drops further to 2.7× for (4+8) and 2.5× for (8+8) (Figure 2). The incremental gain over SageAttention2 is even narrower at long sequences: at 32K, SageAttn2++(8+8) is only 1.04× faster than SageAttn2(8+8) on RTX4090 (440 vs. 422 TOPS). This pattern — larger speedups at short sequences, smaller at long sequences — is consistent across all configurations (Figures 1–4) and suggests that the PV multiplication, which the paper accelerates, constitutes a decreasing fraction of total attention time as sequence length grows (the QK^T multiplication, which is unchanged, scales quadratically and increasingly dominates).

**What evidence exists in the paper.** The speedup ratio at 32K can be computed directly from the TOPS values in Figures 1–4. The paper reports absolute TOPS for every configuration at every sequence length, so the data is available to readers, but the paper does not itself discuss the variation of speedup with sequence length or acknowledge that the headline figure is a peak. The paper also does not provide a profiling breakdown of attention kernel time (what fraction is QK^T vs. PV vs. softmax) that would explain why the speedups shrink at long sequences.

**Mitigation status.** Not addressed. The paper neither qualifies the headline figure as a peak nor provides speedup numbers aggregated or averaged over sequence lengths. The abstract and introduction present 3.9× as the representative figure, which overstates the practical benefit for long-sequence workloads. Future work could address this by reporting harmonic-mean speedups weighted by typical sequence length distributions, or by separately optimizing the QK^T multiplication (which would become the bottleneck at long sequences after PV is accelerated).

### The Incremental Improvement Over SageAttention2 Is Modest, and the Paper Does Not Quantify the Contribution of Each Optimization

**The assumption or constraint.** SageAttention2++ is presented as a direct improvement over SageAttention2, with the key change being the use of `mma.f16.f8.f8.f16` instead of `mma.f32.f8.f8.f32` for the PV multiplication, plus the delayed FP32 buffering optimization (Section 3.2). The paper claims that the FP16-accumulator instruction is "4× faster than FP16" while the FP32-accumulator instruction is "2× faster than FP16" (Table 1), implying a 2× throughput improvement for the PV multiplication in isolation. However, translating this instruction-level speedup into end-to-end kernel speedup is subject to Amdahl's law: the PV multiplication is only one component of the attention kernel, alongside QK^T, softmax, tiling overhead, and memory operations.

**The consequence.** The actual speedup of SageAttention2++ over SageAttention2 — the comparison that matters for existing SageAttention2 users deciding whether to upgrade — is substantially smaller than the instruction-level speedup ratio suggests:

| Sequence Length | SageAttn2(8+8) | SageAttn2++(8+8) | Improvement |
|----------------|----------------|-------------------|-------------|
| 1K | 346 TOPS | 411 TOPS | **1.19×** |
| 2K | 382 TOPS | 461 TOPS | **1.21×** |
| 4K | 421 TOPS | 489 TOPS | **1.16×** |
| 8K | 423 TOPS | 490 TOPS | **1.16×** |
| 16K | 423 TOPS | 493 TOPS | **1.17×** |
| 32K | 422 TOPS | 440 TOPS | **1.04×** |

(RTX4090, headdim=128, causal=False, Figure 1 top row.)

For the (4+8) variant, the improvement is even smaller: 1.18× at 1K dropping to 1.01× at 32K. These are genuine gains — a 16–21% speedup for the (8+8) variant at short-to-medium sequences — but they represent refinement rather than breakthrough. A practitioner evaluating whether the engineering effort of switching kernels is worthwhile would weigh this ~15% improvement against the validation cost of confirming that the new kernel produces identical outputs for their specific model and use case.

Furthermore, the paper does not isolate the contribution of the two innovations (FP16 accumulator instruction + delayed FP32 buffering). The buffering optimization is presented as a distinct technique (Section 3.2) with its own constraint ($P_r \times V_r \leq 1023$ instead of 2047), but no ablation compares a kernel using the FP16-accumulator instruction *without* buffering (satisfying the looser constraint $P_r \times V_r \leq 2047$ but paying full conversion overhead) against the final buffered kernel. Without this ablation, it is impossible to determine whether the buffering optimization provides a meaningful throughput gain or whether the FP16 accumulator instruction alone accounts for essentially all of the improvement. The paper claims buffering "halv[es] the transformation overhead" but does not show what fraction of kernel time this overhead represents — if conversion instructions account for 2% of total time, halving them saves 1%, which is negligible and would not justify the additional quantization range constraint.

**What evidence exists in the paper.** Figures 1–4 provide SageAttention2 and SageAttention2++ TOPS at matching configurations, from which the incremental speedups can be computed. Table 2 confirms that the buffered configuration (using the tighter constraint) achieves identical accuracy. No profiling data or ablation on conversion instruction overhead is provided.

**Mitigation status.** Not addressed. The paper does not discuss Amdahl's law effects, does not isolate the marginal contribution of each optimization, and does not provide instruction-level profiling data (e.g., fraction of kernel time spent in MMA instructions vs. conversion instructions vs. memory operations). Future work could strengthen the contribution by demonstrating the value of the buffering optimization specifically, and by identifying which remaining kernel components limit further speedup (likely the QK^T multiplication at long sequences).

### The Method Is Coupled to Specific GPU Architectures and Instruction Availability

**The assumption or constraint.** SageAttention2++'s core innovation — using `mma.f16.f8.f8.f16` for the PV multiplication — depends on the availability and throughput characteristics of this specific Tensor Core instruction. The speedup hierarchy in Table 1 (FP8/FP16 accumulator = 4×, FP8/FP32 accumulator = 2×) is measured on RTX4090 (Ada Lovelace) and RTX5090 (Blackwell). The paper explicitly notes that FlashAttention3 cannot run on these GPUs, confirming that instruction set and microarchitectural differences across GPU generations create hard compatibility boundaries.

**The consequence.** The approach may not transfer to other hardware platforms:

- **Older GPUs (pre-Ada Lovelace, e.g., RTX 30 series, Ampere).** These architectures do not support FP8 Tensor Core operations at all — the `mma.f16.f8.f8.f16` and `mma.f32.f8.f8.f32` instructions simply do not exist. SageAttention2++ cannot run on these GPUs; Fallback to full SageAttention2 FP16 computation would be needed, losing all quantization speedups.

- **Datacenter GPUs (Hopper H100, H200).** These GPUs do support FP8 Tensor Core operations, but their instruction throughput characteristics differ from consumer GPUs. The relative speedup of FP16-accumulator vs. FP32-accumulator FP8 instructions may not be 2× on Hopper — FlashAttention3's optimizations for Hopper exploit asynchronous data movement and different Tensor Core scheduling that could change the cost-benefit calculation. Moreover, FlashAttention3 is available on Hopper and is likely faster than both FlashAttention2 and the SageAttention family on that architecture, making the comparison landscape different.

- **Non-NVIDIA hardware (AMD, Intel, Apple Silicon, cloud TPUs).** These platforms have entirely different matrix multiply instruction sets with different accumulator types, precision support, and throughput characteristics. The accumulator-aware range selection methodology (Innovation 1 in Section 4) could theoretically be applied, but would require re-deriving the safe quantization constraints for each platform's specific instruction parameters.

- **Future GPU architectures.** If NVIDIA releases an FP8 Tensor Core instruction with an FP32 accumulator that runs at the same throughput as the FP16 accumulator variant (eliminating the accumulator-dependent speedup gap), SageAttention2++'s advantage over SageAttention2 would disappear. Similarly, if future architectures introduce FP4 or MX-format Tensor Core instructions that are faster than FP8, both SageAttention2 and SageAttention2++ would be superseded by methods targeting those formats.

The practical implication is that SageAttention2++'s benefit is narrow in hardware scope: it provides a meaningful speedup (15–20% over SageAttention2) only on RTX 40 and 50 series consumer GPUs running FP8-capable Tensor Core code. For deployment environments targeting datacenter GPUs, mobile GPUs, or inference on heterogeneous hardware, the approach either does not apply or would need revalidation.

**What evidence exists in the paper.** The paper benchmarks exclusively on RTX4090 and RTX5090 (Section 4.2, Figures 1–4). Table 1 specifies that the speedup ratios apply to these GPUs. Section 4.1 explicitly notes that FlashAttention3 is incompatible with these GPUs, implicitly acknowledging the hardware specificity. No experiments or discussion address other GPU architectures.

**Mitigation status.** Not addressed. The paper does not discuss hardware portability, does not benchmark on Hopper or Ampere GPUs, and does not provide guidance on when SageAttention2++ should be preferred over SageAttention2 or FlashAttention2 on different hardware. The accumulator-aware methodology is conceptually portable, but the specific implementation and the claimed speedups are tied to Ada Lovelace and Blackwell consumer GPUs.

### The Difficulty of Extending the FP16 Accumulator Approach Beyond the PV Multiplication Is Not Discussed, Limiting the Generality of the Contribution

**The assumption or constraint.** The paper's technical contribution is scoped to accelerating the PV matrix multiplication within attention by using the FP16-accumulator FP8 Tensor Core instruction. The QK^T multiplication remains unchanged from SageAttention2, using INT4/INT8 quantization with whatever accumulator type SageAttention2 originally employed. The paper does not discuss whether the FP16 accumulator approach could be applied to QK^T, to feed-forward layers, to normalization operations, or to other matrix multiplications in Transformer inference.

**The consequence.** The impact of the contribution is bounded by the fraction of total inference time spent in the PV multiplication specifically. In a full Transformer layer, computation is divided among QK^T attention, PV attention, feed-forward network (two large matrix multiplications), layer normalization, and residual additions. Accelerating only PV — one of perhaps four major matrix multiplications per layer — means the end-to-end model speedup will be diluted by Amdahl's law.

For short sequences (where QK^T is cheap relative to PV), the PV acceleration matters more, which is consistent with the observation that SageAttention2++'s speedup over SageAttention2 is larger at 1K (19%) than at 32K (4%). For very long sequences (where QK^T dominates), accelerating PV provides diminishing returns. For FFN layers, which account for a large fraction of inference FLOPs in many Transformer architectures (especially encoder-decoder models and large language models), the paper provides no acceleration.

**What evidence exists in the paper.** None explicitly. The paper does not profile the fraction of end-to-end inference time spent in PV vs. QK^T vs. FFN layers, does not report end-to-end model throughput (only kernel TOPS), and does not discuss whether the accumulator-aware quantization methodology could be applied to other matrix multiplications. The speedup curves in Figures 1–4 implicitly reveal the diminishing-returns pattern at long sequences, but the paper does not analyze this.

**Mitigation status.** Not addressed. The paper frames the contribution as an improvement to SageAttention2's attention kernel and does not attempt to accelerate non-attention operations. Extending the FP16-accumulator approach to other matrix multiplications would require analysing the numerical properties of those operations (e.g., FFN weight matrices have different dynamic range characteristics than attention value matrices) and validating that quantization range reduction does not degrade model quality — a separate set of experiments that the paper does not undertake. The authors do not suggest this as future work.

### The Delayed FP32 Buffering Constraint ($P_r \times V_r \leq 1023$) Is Conservatively Derived from Worst-Case Analysis, Leaving Potential Throughput on the Table

**The assumption or constraint.** The constraint $P_r \times V_r \leq 1023$ (Equation 3) is derived assuming that all 32 products of quantized $\hat{P}$ and $\hat{V}$ values within each `mma.m16n8k32` tile are at their maximum representable magnitudes simultaneously, and that two consecutive such tiles are accumulated in FP16 before conversion. Specifically: $|\text{buffered}_{\max}| = 2 \times 32 \times P_r \times V_r \leq 65504$, yielding $P_r \times V_r \leq 1023$.

This is a **sufficient** condition for safety, not a necessary one. In practice, the quantized values $\hat{P}$ and $\hat{V}$ are not all at the maximum simultaneously — $\hat{P}$ values are derived from softmax-normalized attention weights that sum to 1 within each query's attention distribution, so most values are much smaller than the maximum. $\hat{V}$ values are similarly distributed with most elements far below the per-channel maximum. The actual accumulated sums are typically far below the theoretical worst-case bound.

**The consequence.** The conservative constraint may unnecessarily restrict the quantization ranges, forcing $P_r = 224$ and $V_r = 4.5$ (product = 1008, just below 1023). With a probabilistic or empirical analysis of actual accumulation magnitudes — for instance, by profiling the distribution of accumulated products across all attention heads in representative models — a looser constraint might be justified, allowing larger $P_r$ or $V_r$ values. Larger quantization ranges would mean smaller scale factors, which could improve quantization fidelity for channels with small values (reducing the fraction of V elements that quantize to zero) or improve the precision of $\hat{P}$ for attention distributions with very peaked structure. While Table 2 shows that the current ranges already achieve excellent accuracy, there may be corner cases (models with unusual activation distributions, tasks requiring extreme precision in attention patterns) where the conservative constraint causes measurable degradation that a less conservative constraint would avoid.

Conversely, the conservative constraint might be **too aggressive** relative to actual hardware behavior. The FP16 format can represent values slightly above 65504 in certain rounding modes, and the Tensor Core's internal accumulation might use guard bits that extend the effective range before saturation. The paper's analysis assumes strict saturation at 65504, which may be pessimistic.

**What evidence exists in the paper.** Table 2 shows that all tested $(P_r, V_r)$ pairs achieve identical accuracy, which implies the current constraint is not causing accuracy loss. However, this does not test whether *looser* constraints (e.g., $P_r=448, V_r=4.5$, product = 2016, violating the constraint) would also be safe in practice while providing better quantization fidelity. No profiling data on actual accumulation magnitudes is provided.

**Mitigation status.** Not addressed. The paper takes the conservative worst-case approach without discussing whether it is unnecessarily restrictive, and does not test whether the constraint can be relaxed without overflow in practice. For a systems paper aiming to maximize throughput at guaranteed accuracy, conservatism is a reasonable engineering choice, but the tradeoff between conservatism and potential accuracy headroom is not acknowledged. An empirical study of accumulation distributions across model architectures could tighten the constraint (allowing larger ranges) without sacrificing safety, potentially extending the approach to operations where the current ranges would be too restrictive.

### The Paper Does Not Report End-to-End Throughput or Latency, Only Kernel TOPS

**The assumption or constraint.** All speed measurements in the paper are reported in TOPS (Tera Operations Per Second) for the attention kernel alone, measured across varying sequence lengths and configurations in isolation (Figures 1–4). The paper does not measure end-to-end model inference throughput (tokens per second for language models, images per second for image generation, frames per second for video generation) or per-query latency. The claim that SageAttention2++ "effectively accelerates various models" (abstract) is supported by kernel-level benchmarks, not by measurements of complete model inference pipelines.

**The consequence.** Kernel TOPS measures the arithmetic throughput of the attention computation when the GPU is fully dedicated to that operation. In a real inference pipeline, attention is interleaved with feed-forward layers, normalization, activation functions, residual connections, embedding lookups, and output projections — all of which consume GPU time and memory bandwidth. The end-to-end speedup from a faster attention kernel is diluted by these non-attention components. For instance, if attention accounts for 40% of total inference time in a particular model at a particular sequence length, a 3× attention speedup translates to only a 1.5× end-to-end speedup (by Amdahl's law: $1 / (0.6 + 0.4/3) = 1.36\times$, actually less due to memory bandwidth sharing).

Additionally, latency matters for interactive applications (chat, real-time image generation). The paper's buffering optimization accumulates pairs of MMA results in FP16 before FP32 conversion, which introduces a small amount of additional latency per tile. While this latency is negligible for throughput-oriented batch processing, it could matter for single-query latency where every microsecond of kernel execution is on the critical path.

Without end-to-end measurements, a practitioner cannot estimate the actual wall-clock speedup they would observe when deploying SageAttention2++ in their inference pipeline. The kernel speedup figures (3.9× peak, ~3.0× at 32K) are upper bounds on the achievable end-to-end speedup, and the gap between kernel speedup and end-to-end speedup depends on model architecture, sequence length, batch size, and hardware configuration in ways the paper does not characterize.

**What evidence exists in the paper.** The paper reports only kernel TOPS (Figures 1–4) and end-to-end model quality metrics (Table 3). There are no measurements of end-to-end inference throughput or latency for any of the six models tested. The abstract's claim of effective model acceleration is an inference from kernel characteristics, not a demonstrated measurement.

**Mitigation status.** Not addressed. The paper does not discuss the relationship between kernel TOPS and end-to-end throughput, does not report the fraction of inference time spent in attention for any model, and does not provide guidance for practitioners to estimate end-to-end speedups. This is a significant gap for a paper whose stated contribution is accelerating model inference. Kernel-level benchmarks are standard in the attention acceleration literature (FlashAttention, FlashAttention2, SageAttention all report primarily kernel speed), but the stronger claim of "plug-and-play acceleration" across models would be substantiated by showing that the accelerated kernel actually translates to faster model inference in practice.
