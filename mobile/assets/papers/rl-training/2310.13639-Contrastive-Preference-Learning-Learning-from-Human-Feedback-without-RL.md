# Contrastive Preference Learning: Learning from Human Feedback without RL

**ArXiv:** [2310.13639](https://arxiv.org/abs/2310.13639)

## 🎯 Pitch

Human preferences reflect judgments of optimality, not cumulative reward—so the entire RL phase of RLHF is unnecessary. CPL exploits this by directly extracting the optimal policy from preferences via a simple contrastive loss, matching or beating RL-based methods on pixel-based robotics tasks while running 1.6× faster.

---

## 1. Executive Summary

This paper introduces **Contrastive Preference Learning (CPL)**, a new family of algorithms for aligning models with human feedback that eliminates the need for reinforcement learning entirely. Operating on the regret-based model of human preferences — where users compare behaviors based on optimality rather than cumulative reward — CPL leverages the maximum entropy framework's bijection between optimal advantage functions and policies (substituting the policy's log-probability directly for the advantage) to derive a purely supervised contrastive objective whose optimum is the optimal policy under the expert's reward. On six MetaWorld robotics manipulation tasks with both state and pixel observations, CPL matches or exceeds prior RL-based methods like Preference IQL while running 1.6× faster and using less than a quarter of the parameters, and on dense preference data surpasses RL baselines on 5 of 6 tasks, establishing that the RL phase of RLHF can be circumvented entirely under the regret preference model — but only when the base data provides sufficient state-action coverage to prevent degenerate out-of-distribution policies.

## 2. Context and Motivation

### The Core Problem: RLHF Is Built on a Flawed Foundation, and RL Makes It Unnecessarily Hard

This paper addresses a fundamental tension in how we align machine learning models with human intent. The dominant paradigm — Reinforcement Learning from Human Feedback (RLHF) — operates in two phases: first, learn a reward function from human preferences, then optimize that reward function using reinforcement learning. This two-phase approach has driven breakthroughs in finetuning large language models (Ouyang et al., 2022), improving image generation (Lee et al., 2023), and adapting robot policies (Christiano et al., 2017). But the paper identifies two distinct problems with this paradigm, one conceptual and one practical, and argues that both are unnecessary.

**The conceptual problem: human preferences don't follow reward.** Virtually all RLHF algorithms assume that when a human says "I prefer behavior A over behavior B," they are comparing the cumulative discounted reward of each behavior. Under this *partial return model*, the probability that a human prefers segment $\sigma^+$ to $\sigma^-$ is:

$$P[\sigma^+ \succ \sigma^-] = \frac{\exp \sum_{\sigma^+} \gamma^t r_E(s_t, a_t)}{\exp \sum_{\sigma^+} \gamma^t r_E(s_t, a_t) + \exp \sum_{\sigma^-} \gamma^t r_E(s_t, a_t)}$$

This seems intuitively reasonable, but Knox et al. (2022) identified a critical flaw. Consider a sparse reward environment where $r_E(s,a) = \mathbf{1}\{s = g\}$ — the agent only gets a positive reward when it reaches a goal. Two behavior segments that both fail to reach the goal have identical partial returns (zero), even if one segment makes progress toward the goal while the other moves away from it. Under the partial return model, a human would be indifferent between these two behaviors. But real humans are not indifferent — they reliably prefer behaviors that make progress, because they judge behaviors by how close they come to optimality, not by their accumulated reward.

The alternative, proposed by Knox et al. (2022) and adopted by this paper, is the **regret preference model**. Rather than comparing cumulative reward, humans compare *negated regret* — how much worse each action is compared to what the optimal policy would have done. Formally, regret at state $s$ for taking action $a$ is $V^*(s) - Q^*(s,a)$, the difference between the optimal value and the value of that specific action. The preference model becomes:

$$P_{A^*}[\sigma^+ \succ \sigma^-] = \frac{\exp \sum_{\sigma^+} \gamma^t A^*(s_t^+, a_t^+)}{\exp \sum_{\sigma^+} \gamma^t A^*(s_t^+, a_t^+) + \exp \sum_{\sigma^-} \gamma^t A^*(s_t^-, a_t^-)}$$

where $A^*(s,a) = Q^*(s,a) - V^*(s)$ is the optimal advantage function. In the sparse reward example, the advantage function does distinguish between progress toward the goal and movement away from it — because $Q^*(s,a)$ correctly estimates the expected future reward of reaching the goal from state $s$ after action $a$. The regret model thus captures what humans actually seem to care about: optimality, not reward accumulation.

The paper's first key motivation is that **existing RLHF methods are learning the wrong quantity**. They learn a reward function when they should be learning an advantage function (or equivalently, negated regret). This is not a minor technicality — it means the entire first phase of standard RLHF is targeting the wrong signal.

**The practical problem: RL introduces severe optimization challenges.** Even setting aside the conceptual mismatch, the second phase of standard RLHF — optimizing the learned reward with reinforcement learning — imposes substantial practical burdens:

- **Temporal credit assignment**: In sequential decision problems, RL algorithms must propagate reward signals backward through time, a process that introduces high variance in policy gradient estimates (Marbach & Tsitsiklis, 2003) and instability in approximate dynamic programming (Van Hasselt et al., 2018).

- **Restrictive workarounds**: These challenges are so severe that practitioners systematically restrict the scope of problems they tackle. RLHF for large language models (Ouyang et al., 2022; Ziegler et al., 2019) assumes a *contextual bandit* formulation — a single query produces a single response, which receives a single reward. This strips away the temporal dimension entirely, even though real human-LLM interactions are multi-turn and sequential. In robotics, RLHF has been confined to low-dimensional state-based control problems (Christiano et al., 2017; Sikchi et al., 2023a) — settings where approximate dynamic programming methods are known to be stable — and has not scaled to high-dimensional image-based continuous control where value function estimation is substantially harder.

- **Computational overhead**: Standard RLHF requires learning and maintaining multiple neural networks: a reward model, a value function, a Q-function, and a policy. Each introduces its own training instabilities, hyperparameters, and computational cost. In the image-based experiments in this paper, the Preference IQL baseline requires 9.6 million parameters across all its components, compared to CPL's 2.1 million parameters for the policy alone.

The paper's second key motivation is therefore that **RL is an unnecessarily expensive and restrictive mechanism for learning from preferences**. If one could derive what the RL phase accomplishes — optimizing behavior to match human judgments of optimality — through a simpler mechanism, the entire chain of complications could be bypassed.

### Why This Problem Matters

The paper's motivation extends beyond intellectual dissatisfaction with the status quo. Addressing both the conceptual and practical problems has concrete implications across multiple deployment scenarios:

**Enabling genuinely sequential RLHF.** Current LLM alignment treats each user query as an isolated event — the model produces a response, receives a preference label, and learns. But real dialogue is sequential: users build context over multiple turns, and the quality of an interaction depends on how responses chain together. The contextual bandit simplification discards this structure. CPL's ability to handle general Markov Decision Processes (MDPs) with preferences over multi-step segments means it could, in principle, optimize for the quality of entire conversations rather than individual responses. The paper explicitly notes (Section 6) that no multi-step preference dataset currently exists for LLMs — but the algorithmic machinery to handle one would already exist with CPL.

**Scaling RLHF to high-dimensional control.** Robotics and other embodied AI domains operate in high-dimensional continuous state and action spaces where RL's optimization challenges are most acute. The standard RLHF recipe — learn a reward, then run PPO or IQL — has largely not been demonstrated on image-based manipulation tasks with complex dynamics. By replacing RL with supervised learning, CPL makes RLHF scale as well as supervised learning scales, which is to say: to very large networks and very high-dimensional inputs, as demonstrated by the success of contrastive representation learning at scale (Chen et al., 2020; He et al., 2020; Radford et al., 2021).

**Computational efficiency at deployment.** As models grow larger, the cost of maintaining separate reward, value, and Q-function networks alongside the policy becomes substantial. For a large language model, adding a separate reward model of comparable size doubles the parameter count. CPL's elimination of all auxiliary networks means that in a production RLHF pipeline, only the policy network needs to be trained and deployed — a direct reduction in both training cost and inference memory.

**Theoretical clarity.** Beyond practical benefits, the paper addresses a conceptual gap: if human preferences follow regret rather than reward, what is the correct algorithm for learning from those preferences? Prior work (Knox et al., 2022; 2023) recognized the mismatch but proposed algorithms that still required learning intermediate representations (successor features with assumed linear reward structure) that were brittle and restricted to tabular or simple grid-world settings. CPL provides the first algorithm that is both faithful to the regret preference model and scalable to complex domains.

### Where Prior Approaches Fall Short

The paper positions itself against several categories of prior work, each with distinct limitations:

**1. Standard two-phase RLHF (reward learning + RL).** The dominant approach — learning a reward model under the partial return preference model, then optimizing it with RL (Christiano et al., 2017; Ouyang et al., 2022; Stiennon et al., 2020) — suffers from both the conceptual mismatch (wrong preference model) and the practical RL challenges described above. The paper's Preference IQL baseline (Section 4) is a concrete instantiation of this: it learns a reward function from preferences, then uses Implicit Q-Learning (Kostrikov et al., 2022), a state-of-the-art offline RL algorithm, to optimize that reward. While effective, it requires learning a reward function, Q-function, value function, and policy — four separate neural networks — and inherits all the hyperparameter sensitivity and training instability of offline RL.

Note that the paper's P-IQL baseline uses an interesting variant: since the preferences are regret-based (generated using the optimal advantage function as ground truth), the reward model is effectively learning to approximate $A^*_{r_E}$, which Corollary 1 in Appendix A proves has the same optimal policy as $r_E$. This means P-IQL gets the "right" reward function to optimize — it's actually learning an advantage function dressed up as a reward. Yet it still requires the full RL machinery to extract a policy from that function.

**2. Regret-preference methods that still require RL.** Knox et al. (2022) first proposed the regret preference model, and Knox et al. (2023) developed algorithms for learning from it. However, these approaches learn an advantage function directly (by maximizing the likelihood of the preference data under Eq. 2), then distill it into a policy. The limitation is that *learning a Bellman-consistent advantage function is itself a form of RL* — it requires enforcing the Bellman equation $A(s,a) = r(s,a) + \gamma \mathbb{E}_{s'}[V(s')] - V(s)$, which bootstrap training and introduces the same stability challenges as value-based RL. These methods have only been demonstrated on simple grid-world environments and rely on successor features with assumed linear reward representations, making them unsuitable for complex continuous control.

**3. Contextual bandit RLHF methods.** Approaches like PPO with KL-constrained rewards (Ziegler et al., 2019; Ouyang et al., 2022) and Direct Preference Optimization (DPO; Rafailov et al., 2023) operate in the contextual bandit setting — single-step decisions with no temporal structure. DPO is particularly relevant because it also eliminates the RL phase: it derives a supervised objective by substituting the optimal policy's relationship to the reward function directly into the preference model. However, DPO's derivation **depends on the contextual bandit assumption**. In a general MDP, the relationship between policy and reward is mediated by the value function ($\pi^*(a|s) \propto e^{Q^*(s,a)}$, not $e^{r(s,a)}$), and the simple substitution that DPO performs no longer holds. The paper shows in Appendix A.6 that DPO is a special case of CPL when segments have length 1 and start from the same state — essentially, CPL generalizes DPO's insight to sequential decision problems.

**4. Preference-based RL (PbRL) without RL.** Recent work has attempted to remove RL from PbRL pipelines. Hejna et al. (2023) and Eysenbach et al. (2022) developed contrastive objectives for goal-conditioned RL from images, showing that supervised learning can replace RL in that setting. An et al. (2023) proposed direct policy optimization from preferences without reward modeling, but their approach does not use the regret preference model and is demonstrated on simpler settings. CPL can be seen as the extension of these "no-RL" ideas to the regret-based preference framework for general MDPs.

### How This Paper Positions Itself

The paper's positioning is best understood through the diagram in Figure 1. Standard two-phase RLHF sits on one side: preferences → reward learning → RL → policy. CPL sits on the other: preferences → contrastive learning → policy. The key enabler of this shortcut is the **regret preference model combined with the maximum entropy RL framework**.

The maximum entropy framework (Ziebart, 2010; Haarnoja et al., 2017) provides a critical theoretical relationship that the paper exploits: under maximum entropy RL with temperature $\alpha$, the optimal policy and optimal advantage function are in direct bijection:

$$\pi^*(a|s) = e^{A^*(s,a)/\alpha}$$

or equivalently, $A^*(s,a) = \alpha \log \pi^*(a|s)$. This means that instead of learning an advantage function from preference data and then extracting a policy from it (the naïve approach in Section 3.1), one can **substitute the policy directly into the preference model**:

$$P[\sigma^+ \succ \sigma^-] = \frac{\exp \sum_{\sigma^+} \gamma^t \alpha \log \pi_\theta(a_t^+ | s_t^+)}{\exp \sum_{\sigma^+} \gamma^t \alpha \log \pi_\theta(a_t^+ | s_t^+) + \exp \sum_{\sigma^-} \gamma^t \alpha \log \pi_\theta(a_t^- | s_t^-)}$$

This is Eq. (4) in the paper. The preference model is now expressed purely in terms of the policy's log-probabilities — no advantage function, no reward function, no value function, no Q-function. Maximizing the likelihood of preference data under this model yields the CPL objective (Eq. 5), a contrastive loss where the score of a behavior segment is its discounted sum of policy log-probabilities.

The paper draws a deliberate analogy to **contrastive representation learning**, specifically Noise Contrastive Estimation (Gutmann & Hyvärinen, 2010) and InfoNCE (Oord et al., 2018). In standard contrastive learning, positive and negative examples are embedded by a neural network, and the loss encourages the embedding of positives to be closer to a query than the embedding of negatives. In CPL, "positive" and "negative" behavior segments are scored by summing the log-probabilities the policy assigns to their actions, and the loss encourages the policy to assign higher probability to actions in preferred segments than to actions in dispreferred segments. The paper explicitly notes this connection by using "+" and "-" notation for preferred and dispreferred segments. This framing is strategic: it positions CPL not as an RL algorithm that happens to use supervised learning, but as a supervised, representation-learning algorithm that happens to converge to the optimal policy — inheriting the well-established scalability properties of contrastive methods.

Crucially, the paper does not claim to have invented the regret preference model (that is Knox et al., 2022), nor the maximum entropy framework (Ziebart, 2010), nor the idea of eliminating RL from preference-based learning (Rafailov et al., 2023; An et al., 2023). Its contribution is the **combination**: recognize that the regret model + maximum entropy framework creates a shortcut from preferences directly to policies, bypassing both reward learning and RL. This combination had not been previously identified or exploited.

The paper also carefully distinguishes itself from the na¨ıve two-step approach within the regret framework. Section 3.1 addresses why one cannot simply learn an advantage function via maximum likelihood on Eq. (2) and then extract a policy: the advantage function must satisfy the normalization constraint $\int_A e^{A(s,a)/\alpha} da = 1$ for all states to be a valid optimal advantage. Enforcing this constraint during neural network training is intractable, particularly in continuous action spaces. By learning the policy directly — which naturally satisfies the distributional constraint $\int_A \pi_\theta(a|s) da = 1$ — CPL avoids this normalization problem entirely. Proposition 1 formalizes this: CPL's implicit advantage function $A_\theta(s,a) = \alpha \log \pi_\theta(a|s)$ is guaranteed to be a *consistent* advantage function (one that is optimal for some reward function), regardless of how much preference data is available.

This consistency property addresses a subtle but important point. In standard RLHF reward learning, the Boltzmann rational preference model is invariant to additive shifts: adding a constant to all rewards (or to the exponent in the numerator and denominator) does not change $P[\sigma^+ \succ \sigma^-]$. This means reward models trained via maximum likelihood on preferences are only identified up to an additive constant — a known source of instability (Christiano et al., 2017; Hejna & Sadigh, 2023). CPL's policy constraint eliminates this invariance: adding a constant to $\alpha \log \pi_\theta(a|s)$ would violate the normalization $\int_A \pi_\theta(a|s) da = 1$, so the optimization is forced to settle on a specific, well-defined solution. As the paper puts it, CPL "will always learn the optimal policy for some reward function, and adding additional preference data only improves the implicit estimate of $r_E$" (Section 3.1).

The paper's position in the landscape of RLHF research can be summarized by three claimed properties that no prior method simultaneously achieves: (1) scalable as well as supervised learning (no policy gradients, no dynamic programming), (2) fully off-policy (can use any offline suboptimal data), and (3) applicable to arbitrary MDPs (handles sequential, multi-step preferences). DPO achieves (1) and (2) but only in contextual bandits, not MDPs (failing 3). Standard RLHF with PPO achieves (3) in principle but suffers in (1) due to on-policy data requirements and high-variance gradients, and requires careful handling for (2). Offline RL-based methods like P-IQL achieve (2) and (3) but still require dynamic programming and multiple learned components (failing 1). CPL claims all three, and the experimental section tests whether this theoretical positioning translates into practical performance gains.

## 3. Technical Approach

### 3.1 Reader orientation (approachable technical breakdown)

The system is a training procedure that turns a dataset of pairwise human preferences over behavior segments directly into an optimized policy — a function mapping environment states to actions — using nothing but a contrastive supervised learning loss. It solves the problem of aligning models with human feedback without reinforcement learning by recognizing that, under the regret-based model of human preferences and the maximum entropy framework, the optimal advantage function (which drives those preferences) is simply proportional to the log-probability of the optimal policy, allowing us to substitute the policy directly into the preference model and optimize it via maximum likelihood.

### 3.2 Big-picture architecture (diagram in words)

CPL has essentially one major component — the policy network `$\pi_\theta(a|s)$` — and one learning signal — the contrastive preference loss `$\mathcal{L}_{\text{CPL}}$`. There is no reward model, no value function, no Q-function, and no separate policy improvement step. Information flows in a single loop:

1. **Behavior segments are sampled** from a dataset of offline suboptimal trajectory data (e.g., 2500 episodes of a robot attempting a task with ~50% success rate). Each segment `$\sigma$` is a sequence of state-action pairs `$(s_1, a_1, s_2, a_2, ..., s_k, a_k)$` of length `$k$` (set to 64 in all MetaWorld experiments).

2. **Preference labels are assigned** (synthetically from an oracle advantage function or from real human raters) comparing pairs of segments `$\sigma^+ \succ \sigma^-$`, indicating the preferred segment has lower regret under the expert's optimal policy. The paper uses both "sparse" comparisons (one labeled pair per two segments, e.g., 10K comparisons for 20K segments) and "dense" comparisons (all possible pairwise rankings among all segments, e.g., for 2.5K segments, every segment is ranked relative to every other, producing a complete ordering).

3. **The policy scores each segment** by computing the discounted sum of log-probabilities it assigns to the actions in that segment: `$\sum_{\sigma} \gamma^t \alpha \log \pi_\theta(a_t | s_t)$`, where `$\alpha$` is a temperature parameter (set to 0.1 in all experiments). This score measures how "optimal" the policy considers the behavior — higher log-probability on taken actions means higher score.

4. **The contrastive loss compares scores**: a preferred segment `$\sigma^+$` is treated as a positive example, a dispreferred segment `$\sigma^-$` as a negative example, and the loss is the negative log-likelihood that the preferred segment has a higher score under a Boltzmann (logistic) model. The loss encourages the policy to increase the log-probability of actions in preferred segments and decrease it for actions in dispreferred segments.

5. **Parameters are updated** via standard gradient descent on this loss (Adam optimizer, learning rate 0.0001). Over training, the policy's implicit advantage function `$A_\theta(s,a) = \alpha \log \pi_\theta(a|s)$` converges to match the expert's optimal advantage function `$A^*(s,a)$`, and consequently the policy converges to the optimal policy `$\pi^*$`.

A regularizer (the "bias" regularizer with parameter `$\lambda$`, set to 0.5) prevents the policy from placing high probability on out-of-distribution actions by down-weighting the negative segment's score contribution in the Boltzmann denominator. An optional pretraining phase (200K steps for state, 80K for image-sparse, 40K for image-dense) initializes the policy via behavior cloning on all segments before the CPL loss takes over.

#### Formal Setup: The Sequential RLHF Problem

CPL operates in a reward-free Markov Decision Process (MDP) defined as `$\mathcal{M} \setminus r = (\mathcal{S}, \mathcal{A}, p, \gamma)$`, where `$\mathcal{S}$` is the state space, `$\mathcal{A}$` is the action space, `$p(s_{t+1}|s_t, a_t)$` is the transition dynamics, and `$\gamma$` is the discount factor. The expert user has a hidden reward function `$r_E(s,a)$` that we never observe. Instead, we observe a dataset of preferences `$\mathcal{D}_{\text{pref}} = \{(\sigma^+_i, \sigma^-_i)\}_{i=1}^n$`, where each `$\sigma$` is a length-`$k$` behavior segment `$(s_1, a_1, s_2, a_2, ..., s_k, a_k)$` and `$\sigma^+ \succ \sigma^-$` means the expert prefers `$\sigma^+$` to `$\sigma^-$`.

The goal is to learn a policy `$\pi(a|s)$` that maximizes the expert's reward function `$r_E$` under the maximum entropy objective:

$$\max_\pi \mathbb{E}_\pi \left[ \sum_{t=0}^\infty \gamma^t (r_E(s_t, a_t) - \alpha \log \pi(a_t|s_t)) \right]$$

where `$\alpha$` is the temperature parameter that controls the trade-off between reward maximization and entropy maximization. The solution to this objective is denoted `$\pi^*$`, with corresponding optimal state-value function `$V^*(s)$`, state-action value function `$Q^*(s,a)$`, and advantage function `$A^*(s,a) = Q^*(s,a) - V^*(s)$`.

**Why maximum entropy:** the maximum entropy framework provides the bijection `$\pi^*(a|s) = e^{A^*(s,a)/\alpha}$` (Ziebart, 2010), which is the key relationship that enables CPL's substitution. Without this bijection — in standard RL without entropy regularization — there is no direct algebraic relationship between the optimal advantage and the optimal policy, and one cannot substitute one for the other. The paper notes that the KL-constrained variant used in many LLM finetuning settings (where a reference distribution `$\mu(a|s)$` is added to the objective) follows similarly by replacing `$\pi^*(a|s)$` with `$\pi^*(a|s)/\mu(a|s)$` in the bijection (Appendix A.6).

---

#### The Naïve Approach: Why Not Just Learn the Advantage Function?

Before deriving CPL, the paper carefully explains a two-step alternative that seems natural but fails: learn an advantage function `$A_\theta$` by maximizing the likelihood of the preference data under Eq. (2), then extract a policy from it. The failure modes of this approach motivate why CPL's direct policy learning is necessary.

**Step 1 would be:** optimize `$A_\theta$` to maximize:

$$\max_{A_\theta} \mathbb{E}_{(\sigma^+, \sigma^-) \sim \mathcal{D}_{\text{pref}}} \left[ \log \frac{\exp \sum_{\sigma^+} \gamma^t A_\theta(s_t^+, a_t^+)}{\exp \sum_{\sigma^+} \gamma^t A_\theta(s_t^+, a_t^+) + \exp \sum_{\sigma^-} \gamma^t A_\theta(s_t^-, a_t^-)} \right]$$

This is a standard logistic regression — learn an advantage function that makes the preferred segment have a higher score under the Boltzmann model.

**Step 2 would be:** given the learned `$A_\theta$`, extract a policy via `$\pi(a|s) = e^{A_\theta(s,a)/\alpha}$`.

**Why this fails — the normalization problem.** For the extracted policy to be valid, it must satisfy `$\int_A e^{A_\theta(s,a)/\alpha} da = 1$` for every state `$s$`. During neural network training with maximum likelihood, there is zero pressure to enforce this constraint. The logistic loss only cares about the *difference* between the scores of positive and negative segments — any constant added to `$A_\theta$` leaves the loss unchanged. In a continuous action space with a deep neural network, the network can output unnormalized advantages that violate the sum-to-one constraint, and the induced policy `$\pi(a|s) \propto e^{A_\theta(s,a)/\alpha}$` would require an intractable normalization constant to sample from or evaluate.

Additionally, the invariance to additive shifts means that the learned `$A_\theta$` is not unique — infinitely many advantage functions achieve the same preference likelihood, and only one of them (the one satisfying normalization) corresponds to a valid optimal advantage. Prior work attempting this (Knox et al., 2023) had to assume linear or tabular representations where normalization could be explicitly enforced, making the approach inapplicable to neural network function approximation.

**What CPL does differently.** By learning `$\pi$` directly, CPL automatically satisfies normalization: every valid policy `$\pi_\theta$` (parameterized as, say, a Gaussian with mean and variance output by a neural network) has `$\int_A \pi_\theta(a|s) da = 1$` by construction. The implicit advantage function `$A_\theta(s,a) = \alpha \log \pi_\theta(a|s)$` then automatically satisfies `$\int_A e^{A_\theta(s,a)/\alpha} da = 1$`. This is not an additional optimization constraint — it falls out of the policy parameterization for free. Proposition 1 formalizes this: CPL always learns a consistent advantage function (one that is optimal for *some* reward function), regardless of how much preference data is provided or how well the model fits the preferences.

#### Deriving the CPL Objective: Substituting Policy for Advantage

The derivation proceeds in three equations, each building on the previous one.

**Equation 1: The regret preference model in terms of optimal advantage.**

$$P_{A^*}[\sigma^+ \succ \sigma^-] = \frac{\exp \sum_{\sigma^+} \gamma^t A^*(s_t^+, a_t^+)}{\exp \sum_{\sigma^+} \gamma^t A^*(s_t^+, a_t^+) + \exp \sum_{\sigma^-} \gamma^t A^*(s_t^-, a_t^-)}$$

where `$A^*(s,a)$` is the optimal advantage function for the expert's reward `$r_E$`, and `$\sum_{\sigma}$` is shorthand for summing over the `$k$` timesteps in segment `$\sigma$` with discount `$\gamma^t$`.

**What this equation establishes:** the probability that an expert prefers `$\sigma^+$` to `$\sigma^-$` is a Boltzmann (softmax) distribution over the segments' total discounted optimal advantages. A segment with higher cumulative advantage — meaning its actions are closer to what the optimal policy would do — has a higher probability of being preferred. This is the "regret" model because advantage is negated regret: `$A^*(s,a) = -(V^*(s) - Q^*(s,a))$`, so higher advantage means lower regret. This form is a standard Bradley-Terry model (Bradley & Terry, 1952) applied to segment-level scores.

**Equation 2: The maximum entropy bijection.**

$$A^*(s,a) = \alpha \log \pi^*(a|s)$$

where `$\alpha$` is the temperature from the MaxEnt objective and `$\pi^*$` is the optimal policy for `$r_E$`.

**What this equation establishes:** under maximum entropy RL, there is an exact equivalence between the optimal advantage function and the log-probability of the optimal policy, scaled by the temperature. This is a direct consequence of Ziebart's (2010) result that `$\pi^*(a|s) = e^{\frac{1}{\alpha}(Q^*(s,a) - V^*(s))} = e^{A^*(s,a)/\alpha}$`. Rearranging gives the bijection. This relationship is what makes the substitution possible.

**Equation 3: Substituting policy for advantage in the preference model.**

$$P[\sigma^+ \succ \sigma^-] = \frac{\exp \sum_{\sigma^+} \gamma^t \alpha \log \pi_\theta(a_t^+ | s_t^+)}{\exp \sum_{\sigma^+} \gamma^t \alpha \log \pi_\theta(a_t^+ | s_t^+) + \exp \sum_{\sigma^-} \gamma^t \alpha \log \pi_\theta(a_t^- | s_t^-)}$$

where `$\pi_\theta$` is the learned policy with parameters `$\theta$`.

**What this equation computes:** it replaces `$A^*(s,a)$` in the numerator and denominator of Eq. (1) with `$\alpha \log \pi_\theta(a|s)$`, producing a preference model parameterized entirely by the policy's log-probabilities. The score of a segment `$\sigma$` is now `$\sum_{\sigma} \gamma^t \alpha \log \pi_\theta(a_t | s_t)$` — the discounted sum of how "likely" the policy considers each action in the segment.

**Why this form:** it eliminates the advantage function entirely. Rather than learning `$A_\theta$` to approximate `$A^*$` and then extracting a policy, we directly optimize `$\pi_\theta$` to maximize the likelihood of the observed preferences. If the preference data is generated by the regret model with true advantage `$A^*$`, then at optimum `$\pi_\theta$` will assign log-probabilities such that `$\alpha \log \pi_\theta(a|s) = A^*(s,a)$`, meaning `$\pi_\theta = \pi^*$`.

---

#### The CPL Loss Function

The CPL loss is simply the negative log-likelihood of the preference data under the substituted preference model:

$$\mathcal{L}_{\text{CPL}}(\pi_\theta, \mathcal{D}_{\text{pref}}) = \mathbb{E}_{(\sigma^+, \sigma^-) \sim \mathcal{D}_{\text{pref}}} \left[ -\log \frac{\exp \sum_{\sigma^+} \gamma^t \alpha \log \pi_\theta(a_t^+ | s_t^+)}{\exp \sum_{\sigma^+} \gamma^t \alpha \log \pi_\theta(a_t^+ | s_t^+) + \exp \sum_{\sigma^-} \gamma^t \alpha \log \pi_\theta(a_t^- | s_t^-)} \right]$$

where the expectation is over the empirical preference dataset.

**Operationally, what happens when this loss is computed for a single preference pair:**

1. **Compute positive score:** for each timestep `$t$` in the preferred segment `$\sigma^+$`, evaluate `$\log \pi_\theta(a_t^+ | s_t^+)$` — the log-probability the current policy assigns to the action that was actually taken in that state. Multiply by `$\gamma^t \alpha$` and sum over the segment. This produces a scalar `$S^+$`.

2. **Compute negative score:** do the same for the dispreferred segment `$\sigma^-$`, producing scalar `$S^-$`.

3. **Compute the logistic probability:** `$p = \frac{e^{S^+}}{e^{S^+} + e^{S^-}}$`. This is the model's predicted probability that `$\sigma^+$` should be preferred to `$\sigma^-$`.

4. **Compute loss:** `$-\log p$`. If the model assigns high probability to the preferred segment being preferred (p close to 1), loss is low. If it assigns near-equal probability (p close to 0.5), loss is higher. If it assigns the wrong preference (p close to 0), loss is very high.

5. **Gradient flow:** the gradient of `$-\log p$` with respect to `$\log \pi_\theta$` pushes the policy to increase `$\log \pi_\theta$` on actions in `$\sigma^+$` (making the preferred behavior more likely) and decrease `$\log \pi_\theta$` on actions in `$\sigma^-$` (making the dispreferred behavior less likely). The `$\alpha$` temperature scales the magnitude of the update — higher `$\alpha$` means stronger preference signal per unit of log-probability difference.

**Why this loss is a contrastive objective.** The loss is exactly a Noise Contrastive Estimation (NCE) loss (Gutmann & Hyvärinen, 2010) where the positive example is `$\sigma^+$`, the negative example is `$\sigma^-$`, and the scoring function is the discounted log-probability under the policy. This connection is deliberate: contrastive objectives have been shown to scale well to large datasets and deep networks in representation learning (Chen et al., 2020; Radford et al., 2021), and CPL inherits those scaling properties by design.

#### CPL as Logistic Regression: Understanding Non-Strict Convexity

The paper provides a reformulation of the CPL loss that reveals its mathematical structure and motivates the need for regularization. Let the policy be represented as a vector `$\log \pi \in \mathbb{R}^{|\mathcal{S}| \times |\mathcal{A}|}$` (for clarity of analysis; in practice it is a neural network). For each preference comparison `$i$`, define a "comparison vector" `$x_i \in \mathbb{R}^{|\mathcal{S}| \times |\mathcal{A}|}$` where:

$$x_i[s,a] = \begin{cases} \gamma^t & \text{if } (s,a) \text{ is the } t\text{-th step of the preferred segment } \sigma^+_i \\ -\gamma^t & \text{if } (s,a) \text{ is the } t\text{-th step of the dispreferred segment } \sigma^-_i \\ 0 & \text{otherwise} \end{cases}$$

With this encoding, the difference between scores of the two segments is a dot product:

$$\sum_{\sigma^+_i} \gamma^t \log \pi(a_t|s_t) - \sum_{\sigma^-_i} \gamma^t \log \pi(a_t|s_t) = x_i^\top \log \pi$$

**The CPL loss can then be written as standard logistic regression:**

$$\mathcal{L}_{\text{CPL}}(\pi, \mathcal{D}_{\text{pref}}) = -\sum_{i=1}^n \log \text{logistic}(\alpha x_i^\top \log \pi(a|s))$$

where `$\text{logistic}(z) = \frac{1}{1 + e^{-z}}$` is the sigmoid function, and `$\alpha$` is absorbed into the dot product.

**Operationally, what this computes:** for each comparison `$i$`, compute the dot product between the comparison vector `$x_i$` (encoding which state-action pairs appear in the positive and negative segments, with appropriate discounting) and the log-policy vector. Pass this through the logistic function and take the negative log. Sum over all comparisons. This is identical in form to binary logistic regression where `$x_i$` is the feature vector and `$\log \pi$` is the weight vector being learned.

**Convexity analysis.** The Hessian of this objective with respect to `$\log \pi$` is `$X^\top D X$`, where `$X$` is the `$n \times (|\mathcal{S}| \times |\mathcal{A}|)$` matrix whose rows are `$x_i$`, and `$D$` is a diagonal matrix with entries `$D_{ii} = \text{logistic}(x_i^\top \log \pi)(1 - \text{logistic}(x_i^\top \log \pi)) > 0$`. The matrix `$X^\top D X$` is symmetric and positive semi-definite, making the objective convex in `$\log \pi$`.

**But the objective is NOT strictly convex.** `$X^\top D X$` is only positive *definite* (guaranteeing a unique minimum) if `$X$` has full column rank. In practice, `$|\mathcal{S}| \times |\mathcal{A}| \gg n$` — the number of possible state-action pairs vastly exceeds the number of preference comparisons — so `$X$` is highly rank-deficient. Any vector in the null space of `$X$` can be added to `$\log \pi$` without changing the loss. This means:

- **There are infinitely many policies that achieve the exact same CPL loss.** Some of these policies may place high probability on actions never seen in the preference data (out-of-distribution actions), as long as the differences between segment scores are preserved.
- **The paper provides an explicit construction in Appendix A.3.** In a single-state MDP with three actions where only comparisons between `$a_1$` and `$a_2$` appear in the data, any policy where `$\log \pi(a_1) - \log \pi(a_2) = \text{constant}$` achieves the same loss, regardless of the probability assigned to the unseen action `$a_3$`.

**Why this matters for offline learning.** When learning from a fixed offline dataset, we do not want the policy to extrapolate to actions it has never seen — those actions might lead to states not in the data, causing the policy to fail catastrophically when deployed. The principle of pessimism in offline RL (Levine et al., 2020; Jin et al., 2021) dictates that we should prefer policies that stay within the support of the dataset. But the vanilla CPL loss provides no pressure to do so. The next section addresses this.

#### The Bias Regularizer: Enforcing In-Distribution Policies

To resolve the non-uniqueness problem and prefer policies that assign high probability to actions that actually appear in the data, the paper introduces a bias regularizer `$\lambda \in (0, 1)$` that asymmetrically down-weights the negative segment's score:

$$\mathcal{L}_{\text{CPL}(\lambda)}(\pi_\theta, \mathcal{D}_{\text{pref}}) = \mathbb{E}_{(\sigma^+, \sigma^-) \sim \mathcal{D}_{\text{pref}}} \left[ -\log \frac{\exp \sum_{\sigma^+} \gamma^t \alpha \log \pi_\theta(a_t^+ | s_t^+)}{\exp \sum_{\sigma^+} \gamma^t \alpha \log \pi_\theta(a_t^+ | s_t^+) + \exp \left( \lambda \sum_{\sigma^-} \gamma^t \alpha \log \pi_\theta(a_t^- | s_t^-) \right)} \right]$$

The only change from the vanilla loss is the `$\lambda$` factor multiplying the negative segment's score in the denominator.

**Operationally, what `$\lambda$` does:**

- In the vanilla loss (`$\lambda = 1$`), if you increase the log-probability of all actions in both `$\sigma^+$` and `$\sigma^-$` by the same constant amount, the numerator and denominator both increase by the same factor, and the logistic probability `$p$` is unchanged. The loss is invariant to overall shifts in log-probability.

- With `$\lambda < 1$`, the negative segment's score is scaled down. If you now increase log-probabilities uniformly across the board, the numerator increases by `$\exp(\Delta)$`, but the denominator increases by only `$\exp(\lambda \Delta) < \exp(\Delta)$` (for the negative term). The logistic probability `$p$` *increases*, and the loss *decreases*. The loss now actively rewards higher overall log-probability on in-dataset actions.

- Conversely, if the policy assigns low probability to all actions in the dataset, the loss is higher with `$\lambda < 1$` than with `$\lambda = 1$`, because the negative term's penalty is attenuated.

**Proposition 2 formalizes this tie-breaking behavior:**

> Consider two comparisons `$\sigma^+ \succ \sigma^-$` and `$\sigma'^+ \succ \sigma'^-$` such that `$\mathcal{L}_{\text{CPL}}(\pi, \sigma^+ \succ \sigma^-) = \mathcal{L}_{\text{CPL}}(\pi, \sigma'^+ \succ \sigma'^-)$` for a fixed policy `$\pi$`. If `$\sum_{\sigma^+} \gamma^t \log \pi(a_t^+ | s_t^+) > \sum_{\sigma'^+} \gamma^t \log \pi(a_t^+ | s_t^+)$`, then `$\mathcal{L}_{\text{CPL}(\lambda)}(\pi, \sigma^+ \succ \sigma^-) < \mathcal{L}_{\text{CPL}(\lambda)}(\pi, \sigma'^+ \succ \sigma'^-)$`.

**What this means:** if two comparisons are "equally informative" about relative preferences (same vanilla loss), the regularized loss prefers the one where the policy assigns higher absolute probability to the actions in the dataset. The regularizer transforms the objective from caring only about *relative* log-probability differences to also caring about *absolute* log-probability levels.

**The proof sketch (Appendix A.4):** Let `$\delta = \sum_{\sigma^+} \gamma^t \log \pi(a_t|s_t) - \sum_{\sigma'^+} \gamma^t \log \pi(a_t|s_t) > 0$` be the amount by which the first comparison has higher log-probability. Since both comparisons have the same vanilla loss, the negative segments must also differ by the same `$\delta$`. Substituting into the regularized loss, the second comparison's loss includes an extra factor of `$\exp(\delta(1-\lambda)) > 1$` in the denominator's logit, making the logistic probability smaller and the loss higher. Since `$\delta > 0$` and `$0 < \lambda < 1$`, the inequality is strict.

**Practical effect:** `$\lambda$` acts as a knob controlling how strongly the policy is pushed toward the data distribution. At `$\lambda = 1$`, no bias — the policy can assign zero probability to some dataset actions as long as relative scores are correct. At `$\lambda \to 0$`, the negative segment receives almost no weight, and the loss essentially becomes "just maximize log-probability of the preferred segment," which degenerates toward behavior cloning on preferred data. The paper uses `$\lambda = 0.5$` as a balanced setting — enough regularization to prevent OOD extrapolation but not so much that the contrastive signal is lost.

**The temperature `$\alpha$`** (set to 0.1 in all experiments) controls the sharpness of the preference distribution. Small `$\alpha$` means the logistic function is less sensitive to differences in log-probability — preferences are "noisy" — requiring more data to distinguish good from bad behaviors. Large `$\alpha$` makes preferences more deterministic but risks overfitting to label noise. The paper found `$\alpha = 0.1$` worked well across tasks, though Figure 2 (right panel) shows some sensitivity: `$\alpha = 0.02$` underperforms in Drawer Open (too little signal per comparison), while `$\alpha = 0.5$` is comparable to 0.1 but slightly worse.

#### Alternative Regularizers: BC-Regularized CPL and KL-Constrained CPL

The paper explores two additional variants in Appendix B, though they are not the primary method used in experiments.

**BC-Regularized CPL.** This adds an explicit behavior cloning (BC) term to the loss:

$$\min_\pi \mathcal{L}_{\text{CPL}}(\pi_\theta, \mathcal{D}_{\text{pref}}) - \beta \mathbb{E}_{(s,a) \sim \rho_\mu}[\log \pi(a|s)]$$

where `$\beta$` is a Lagrange multiplier (set to 1 in experiments) and `$\rho_\mu$` is the state-action distribution of the dataset. This is derived from the constrained optimization problem:

$$\min_\pi \mathcal{L}_{\text{CPL}}(\pi_\theta, \mathcal{D}_{\text{pref}}) \quad \text{s.t.} \quad \mathbb{E}_{s \sim \rho_\mu}[D_{KL}(\mu(\cdot|s) || \pi(\cdot|s))] < \epsilon$$

**Operational difference from the bias regularizer:** while the bias regularizer indirectly encourages higher log-probability on all dataset actions (by making the loss lower when log-probabilities are higher), the BC regularizer directly adds a term that explicitly maximizes log-probability of dataset actions. The bias regularizer is more subtle — it only breaks ties, while BC explicit penalizes low-probability regardless of relative scores. The paper reports that CPL with BC regularization sometimes performed comparably or worse than the bias variant (learning curves in Figures 3-6, Appendix C), suggesting the softer bias approach is more effective.

**KL-Constrained CPL.** This variant changes the preference model itself to incorporate a reference distribution `$\mu(a|s)$`, following the KL-constrained objective used in DPO and LLM RLHF:

$$\mathcal{L}_{\text{CPL-KL}(\lambda)}(\pi_\theta, \mathcal{D}_{\text{pref}}) = \mathbb{E}_{(\sigma^+, \sigma^-) \sim \mathcal{D}_{\text{pref}}} \left[ -\log \frac{\exp \sum_{\sigma^+} \gamma^t \alpha \log \frac{\pi_\theta(a_t^+ | s_t^+)}{\mu(a_t^+ | s_t^+)}}{\exp \sum_{\sigma^+} \gamma^t \alpha \log \frac{\pi_\theta(a_t^+ | s_t^+)}{\mu(a_t^+ | s_t^+)} + \exp \left( \lambda \sum_{\sigma^-} \gamma^t \alpha \log \frac{\pi_\theta(a_t^- | s_t^-)}{\mu(a_t^- | s_t^-)} \right)} \right]$$

where `$\mu$` is the reference distribution (learned via behavior cloning on the dataset).

**What this computes:** instead of scoring segments by the raw policy log-probability, it scores them by the log-ratio `$\log(\pi / \mu)$` — effectively measuring how much the policy deviates from the reference distribution. A segment where the policy assigns higher probability relative to the reference gets a higher score. The KL-constrained optimal policy satisfies `$\pi^*(a|s) = \mu(a|s) e^{A^*(s,a)/\alpha}$`, so substituting `$A^*(s,a) = \alpha \log(\pi^*(a|s)/\mu(a|s))$` into the preference model yields this objective.

**Why this variant exists:** it directly generalizes DPO to sequential settings (Appendix A.6 shows DPO is the special case when segments have length 1 and start at the same state). The paper explored this but found the simpler maximum entropy version (without `$\mu$`) performed better in most experiments (Figure 4 shows CPL-KL underperforms CPL and CPL-BC on the 20K Sparse dataset for most tasks). This is likely because the reference distribution `$\mu$` is itself learned from suboptimal data and may not accurately capture the support of optimal behavior.

#### The Complete Training Recipe

The paper's implementation of CPL follows a specific pipeline with hyperparameters tuned for the MetaWorld benchmark.

**Pretraining phase.** Before the CPL loss is applied, the policy is pretrained via behavior cloning (BC) on the same segments used for preference data: `$\min_\theta \mathbb{E}_{(s,a) \sim \mathcal{D}} [-\log \pi_\theta(a|s)]$`. This initialization serves two purposes:

1. It starts the policy close to the data distribution, so the CPL loss begins from a point where actions in the dataset already have reasonable probability. Without this, early training might push the policy toward random out-of-distribution modes before the contrastive signal has time to shape it.

2. It follows the common RLHF recipe (Ouyang et al., 2022) of supervised finetuning before preference optimization, making CPL's training protocol directly comparable to existing approaches.

The pretraining steps are 200K for state-based experiments, 80K for image-based sparse experiments, and 40K for image-based dense experiments. These steps count toward the total training budget, as visible in all learning curves (Figures 3-6 in Appendix C) where a dotted vertical line marks when CPL pretraining ends and the CPL loss takes over.

**Interestingly, pretraining is not always beneficial.** Figure 10 in Appendix C shows that CPL without pretraining can outperform CPL with pretraining on some tasks (Bin Picking, Button Press, Door Open) in the 2.5K Dense state setting. The paper speculates that "pre-training helps when a policy closer to the data distribution is desirable, particularly when out-of-distribution actions are detrimental" but can also constrain the policy too much, preventing it from improving beyond the dataset's average quality.

**Training loop.** After pretraining, each training step follows:

1. **Sample a batch of preference comparisons** from `$\mathcal{D}_{\text{pref}}$`. The batch size (number of comparisons) is 96 for state-based experiments, 48 for image-based sparse, and 32 for image-based dense. Each comparison contains two segments of length 64, so a single batch sees `$2 \times \text{batch\_size} \times 64$` total state-action pairs.

2. **For image-based experiments with dense preferences**, the paper augments the batch by computing all pairwise comparisons within the batch (see Appendix B, "CPL with Dense Preferences"): for a batch of `$b$` segments, compute all `$b(b-1)/2$` pairwise comparisons where `$\sigma_i$` is preferred to `$\sigma_j$`. This provides as much contrastive signal per batch as possible. The dense variant is described as:

$$\mathcal{L}_{\text{CPL}(\lambda)\text{-D}} = -\sum_{i=0}^{b-1} \sum_{j=0}^{b-1} \mathbf{1}\{\sigma_i \succ \sigma_j\} \log \frac{\exp \sum_{\sigma_i} \gamma^t \alpha \log \pi_\theta(a_t^i | s_t^i)}{\exp \sum_{\sigma_i} \gamma^t \alpha \log \pi_\theta(a_t^i | s_t^i) + \exp \left( \lambda \sum_{\sigma_j} \gamma^t \alpha \log \pi_\theta(a_t^j | s_t^j) \right)}$$

This provides `$b^2$` comparisons (minus the diagonal) per batch instead of just `$b/2$` paired comparisons, dramatically increasing the contrastive signal density.

3. **Compute the CPL loss** with regularization. For state-based experiments, the main CPL uses `$\alpha = 0.1$` and `$\lambda = 0.5$`. The BC-regularized variant uses `$\beta = 1.0$`. The KL-constrained variant uses `$\lambda = 0.75$`.

4. **Update policy parameters** using the Adam optimizer with learning rate 0.0001. For the BC-regularized variant, the learning rate is reduced to 10% of its original value after the pretraining phase (a learning rate schedule).

5. **For the KL-constrained variant**, the reference distribution `$\mu$` is trained separately via BC on the dataset first, before CPL training begins. Its parameters are frozen during CPL training.

**Policy architecture.** The paper uses:
- For state-based experiments: a [512, 512] MLP with dropout 0.25 on the actor.
- For image-based experiments: the DrQv2 architecture (Yarats et al., 2022), a convolutional encoder followed by an MLP, with dropout 0.5 on the actor and random shift data augmentations (Laskin et al., 2020).
- All policies are Gaussian: the network outputs a mean, and the variance is fixed (for MetaWorld) or learned per-dimension (for D4RL). The log-probability is computed as `$\log \pi(a|s) \propto -||\pi(s) - a||^2_2$` for the fixed-variance case.

**Total training steps:** 500K for state, 200K for image sparse, 120K for image dense — all including pretraining steps. The image experiments use fewer steps because the dense datasets have only 2.5K segments versus 20K for sparse, leading to fewer unique state-action pairs to learn from.

**Discount factor `$\gamma$`:** set to 1.0 in all CPL experiments. The paper notes this as a limitation — CPL assumes knowledge of the human rater's temporal discounting, which in practice would be difficult to elicit or communicate. Setting `$\gamma = 1.0$` means all steps in a 64-length segment are equally weighted, which may not match how humans actually discount future steps.

#### Preference Data Generation for MetaWorld

Since CPL requires preference-labeled segments, the paper generates synthetic preferences using an oracle SAC (Soft Actor-Critic; Haarnoja et al., 2018) agent trained to 100% success on each MetaWorld task. The procedure is:

**Step 1: Train suboptimal behavior policies.** Train baseline SAC policies until they reach approximately a 50% success rate (exact rates vary by task: 55.6% for Bin Picking, 15.56% for Button Press, 53.96% for Door Open, 60.12% for Drawer Open, 34.4% for Plate Slide, 42.25% for Sweep Into). Add Gaussian noise with standard deviation 0.3 when collecting rollouts to increase coverage.

**Step 2: Generate rollout data.** For each suboptimal policy, rollout 2500 episodes of stochastic behavior. This produces a dataset of diverse suboptimal trajectories with varying quality.

**Step 3: Train oracle SAC to convergence.** Using the suboptimal rollout data (added to the replay buffer to prevent it from being overwritten) combined with online data collection, train an SAC agent to 100% success on each task. This yields oracle Q-function `$Q^*(s,a)$`, policy `$\pi^*$`, and value function `$V^*(s)$`.

**Step 4: Estimate segment-level advantage.** For each segment `$\sigma = (s_1, a_1, ..., s_k, a_k)$` of length 64, compute the discounted sum of optimal advantages. Rather than directly computing `$A^*(s_t, a_t) = Q^*(s_t, a_t) - V^*(s_t)$` at each step (which would require Monte Carlo estimation of `$V^*(s) = \mathbb{E}_{a \sim \pi^*}[Q^*(s,a)]$` and suffer from neural network approximation error), the paper uses a mathematical identity that reduces variance. Under deterministic dynamics, the sum of discounted advantages telescopes:

$$-\text{regret}(\sigma) = \sum_{t=1}^k \gamma^t A^*(s_t, a_t) = \gamma^k V^*(s_k) - V^*(s_1) + \sum_{t=1}^{k-1} \gamma^t r_E(s_t, a_t)$$

This identity combines the value at the terminal state, the value at the initial state, and the accumulated reward along the segment — quantities that are each directly available from the oracle SAC. The paper calls this the "sum" method and found it produced the highest agreement with other theoretically equivalent estimation approaches (Figure 12, Appendix D): across tasks, the "sum" method had average agreement rates of 71-74% with other methods, versus 59-73% for direct "$Q-V$" computation, 61-74% for Monte Carlo policy rollouts, and 62-71% for using the log-probability bijection directly (`$\alpha \log \pi^*(a|s)$`).

**Step 5: Construct preference datasets.** Two types are generated:

- **Dense (2.5K segments):** For each of the 2500 segments, compute its advantage score. Then construct a *total ordering* of all segments by their scores — `$\sigma_{\tau(1)} \succ \sigma_{\tau(2)} \succ ... \succ \sigma_{\tau(2500)}$`. This dataset has a single ground-truth ranking over all segments, providing the maximum possible contrastive signal per segment. In practice, during training, the CPL Dense objective (see above) generates all pairwise comparisons within each batch using this total ordering.

- **Sparse (20K segments):** For each pair of segments in the dataset, a single random comparison is labeled. This produces a dataset of 20K segments with 10K pairwise comparisons (one label per two segments on average). This is sparser than dense but has *more state-action coverage* because more unique segments are included (20K vs. 2.5K).

**The "regret" labels in P-IQL.** An important detail for the baseline: since P-IQL learns a reward function assuming the partial return model, but the labels are regret-based, what reward is P-IQL actually learning? Corollary 1 in Appendix A shows that the reward function `$r'(s,a) = A^*_{r_E}(s,a)$` has the same optimal MaxEnt policy as `$r_E$`. Therefore, if P-IQL perfectly recovers the advantage function as its "reward," it will optimize a function that leads to the correct optimal policy. This is a best-case scenario for P-IQL — it's effectively getting a shaped reward (Ng et al., 1999) that makes the optimization easier. In fact, Knox et al. (2023) showed that using `$A^*_{r_E}$` as the reward function results in such strong shaping that "a horizon of one transition is sufficient to determine the optimal action in each state." This makes P-IQL a strong baseline against which CPL must compete.

#### Theoretical Guarantees

The paper provides three formal results, all proved in Appendix A.

**Theorem 1 (Convergence).** Assume an unbounded number of preferences generated from a noisy rational regret-preference model with expert advantage function `$A^*$`. CPL recovers the optimal policy `$\pi^*$` corresponding to reward `$r_E$`.

**What this theorem establishes:** with infinite data, the CPL objective has a unique global optimum, and that optimum is exactly the optimal policy. The proof proceeds by:

1. Rewriting the CPL loss as the KL divergence between the true preference distribution `$P$` (generated by `$A^*$`) and the model's distribution `$Q$` (generated by the implicit advantage `$\hat{A} = \alpha \log \pi_\theta$`).
2. Noting that KL divergence is zero only when the two distributions are identical for all possible segment pairs.
3. Using the identifiability of the regret preference model (proved in Knox et al., 2022) to show that `$P = Q$` for all pairs implies `$A^* = \hat{A}$` pointwise.
4. Leveraging the consistency property (Proposition 1) — that `$\int_A e^{\hat{A}(s,a)/\alpha} da = 1$` at all states — to perform an inductive argument stripping away the last timestep of segments, showing that equality of segment-level scores implies equality of per-state-action advantages.

The key step in the induction: for segments of length `$k$`, if `$\hat{A}(\sigma_k) = A^*(\sigma_k)$` for all `$\sigma_k$`, then summing out the last action using normalization gives equality for all segments of length `$k-1$`. Repeating this gives equality at the level of individual state-action pairs.

**Why infinite data is assumed:** the proof requires that the KL divergence can be driven to zero pointwise for every possible segment pair. With finite data, there exist segment pairs not in the dataset for which no preference label is available, and the loss no longer uniquely determines `$\hat{A}$`.

**Proposition 1 (Consistency).** CPL learns a consistent advantage function.

Definition 1 in the paper: an advantage function `$A(s,a)$` is *consistent* if there exists some reward function `$r(s,a)$` for which `$A$` is the optimal advantage, meaning `$A(s,a) = A^*_r(s,a)$`.

**Proof sketch:** CPL optimizes a valid policy `$\pi_\theta$` satisfying `$\int_A \pi_\theta(a|s) da = 1$` for all `$s$`. The implicit advantage `$\hat{A}(s,a) = \alpha \log \pi_\theta(a|s)$` therefore satisfies `$\int_A e^{\hat{A}(s,a)/\alpha} da = \int_A \pi_\theta(a|s) da = 1$`. Lemma 1 (proved in Appendix A.1) shows that any function satisfying this normalization is a consistent advantage function — specifically, it is the optimal advantage for the reward function `$r'(s,a) = \hat{A}(s,a) = \alpha \log \pi_\theta(a|s)$`. To verify: under reward `$r'$`, the MaxEnt objective is `$\max_\pi \mathbb{E}_\pi[\alpha \log \pi_\theta(a|s) - \alpha \log \pi(a|s)] = \max_\pi -\alpha \mathbb{E}_\pi[D_{KL}(\pi || \pi_\theta)]$`, which is minimized when `$\pi = \pi_\theta$` pointwise. Since `$\pi^*_{r'} = \pi_\theta$`, the advantage of `$\pi_\theta$` under `$r'$` is `$A^*_{r'} = \alpha \log \pi_\theta = \hat{A}$`, making `$\hat{A}$` consistent.

**What this means in practice:** regardless of how much preference data CPL sees or how well it fits, the implicit advantage function it learns is always the *optimal* advantage for *some* reward function. Adding more data simply improves the estimate of which reward function that is (moving it closer to the true `$r_E$`). This is in contrast to standard reward learning, where a partially-trained reward model may not correspond to any optimal advantage function — it could violate Bellman consistency or normalization constraints.

**Corollary 1.** The reward function `$r$` and the reward function defined as the optimal advantage function for `$r$`, `$A^*_r$`, have the same optimal MaxEnt policy.

**Proof sketch:** Lemma 1 shows that for reward `$r$`, the optimal policy is `$\pi^*_r$`, and its advantage function is `$A^*_r = \alpha \log \pi^*_r$`. If we define a new reward `$r' = A^*_r = \alpha \log \pi^*_r$`, then the MaxEnt objective for `$r'$` is `$\max_\pi \mathbb{E}_\pi[\alpha \log \pi^*_r(a|s) - \alpha \log \pi(a|s)] = \max_\pi -\alpha \mathbb{E}_\pi[D_{KL}(\pi || \pi^*_r)]$`, which is minimized at `$\pi = \pi^*_r$`. Therefore `$\pi^*_{r'} = \pi^*_r$`.

**Why this matters for the P-IQL baseline:** P-IQL learns a reward function from regret-based preferences. The preferences are generated by `$A^*_{r_E}$`, not `$r_E$`. Corollary 1 guarantees that if P-IQL perfectly recovers `$A^*_{r_E}$` as its reward function, optimizing that learned reward will still produce the correct optimal policy `$\pi^*_{r_E}$`. This makes P-IQL a valid and well-motivated baseline — it is not optimizing the wrong function, even though it uses a reward-learning architecture on advantage-based data.

---

#### Connection to Direct Preference Optimization (DPO)

The paper explicitly shows in Appendix A.6 that DPO (Rafailov et al., 2023) is a special case of CPL. The reduction requires two assumptions:

1. **Contextual bandit setting:** the MDP terminates after a single step, meaning there is no next state `$s'$` and the value function is zero at termination. In this case, the advantage function simplifies: `$A^*(s,a) = Q^*(s,a) - V^*(s) = r_E(s,a) + \gamma \mathbb{E}_{s'}[V^*(s')] - V^*(s) = r_E(s,a) - V^*(s)$` (since there is no `$s'$`). The advantage is the reward shifted by a state-dependent baseline.

2. **Same starting state:** all preference comparisons start from the same state `$s$` (in LLM RLHF, this corresponds to all responses being generated from the same prompt). The `$V^*(s)$` term cancels in the preference model:

$$P[\sigma^+ \succ \sigma^-] = \frac{\exp(r_E(s,a^+) - V^*(s))}{\exp(r_E(s,a^+) - V^*(s)) + \exp(r_E(s,a^-) - V^*(s))} = \frac{\exp(r_E(s,a^+))}{\exp(r_E(s,a^+)) + \exp(r_E(s,a^-))}$$

This is exactly the Bradley-Terry model over rewards that DPO uses. In the KL-constrained setting (where the objective augments the reward with a KL penalty against a reference distribution `$\mu$`), DPO substitutes `$r_E(s,a) = \alpha \log \frac{\pi^*(a|s)}{\mu(a|s)} + V^*(s)$` into this preference model, and the `$V^*(s)$` terms cancel, yielding the DPO loss directly.

**What CPL adds beyond DPO:** in a general MDP, preferences are over multi-step segments `$\sigma$`, and the bias term `$V^*(s)$` does not cancel because each step in the segment has a different state. The generalization from single-step to multi-step requires the telescoping identity or the direct advantage substitution — neither of which is available in the bandit setting because there is no multi-step structure to exploit. CPL's use of the maximum entropy bijection `$A^*(s,a) = \alpha \log \pi^*(a|s)$` handles this by working at the level of per-step advantages, which naturally incorporate the multi-step value structure through the Bellman equation encoded in `$A^*$`.

---

#### Connection to InfoNCE and Ranking Data

When preference data comes as rankings rather than pairwise comparisons — that is, a human orders `$K$` segments from best to worst — CPL generalizes to the InfoNCE objective (Oord et al., 2018).

**Plackett-Luce ranking model.** Under the regret preference model, the probability of a particular ranking `$\tau$` (a permutation mapping position to segment) is:

$$P(\tau | \sigma_1, ..., \sigma_K) = \prod_{k=1}^K \frac{\exp \sum_{\sigma_{\tau(k)}} \gamma^t A^*(s_t^{\tau(k)}, a_t^{\tau(k)})}{\sum_{j=k}^K \exp \sum_{\sigma_{\tau(j)}} \gamma^t A^*(s_t^{\tau(j)}, a_t^{\tau(j)})}$$

**What this computes:** at each position `$k$` in the ranking, the probability that segment `$\sigma_{\tau(k)}$` (the one placed at position `$k$`) is the "best" among the remaining segments `$\{\sigma_{\tau(k)}, ..., \sigma_{\tau(K)}\}$`. The denominator sums over all remaining segments, creating a sequence of softmax operations that together define the probability of the full ranking. This generalizes the Bradley-Terry model (which handles `$K=2$` with a single softmax) to arbitrary `$K$`.

**Substituting the policy** gives the CPL ranking loss:

$$\mathcal{L}_{\text{CPL}}(\pi_\theta, \mathcal{D}_{\text{rank}}) = \mathbb{E}_{(\sigma_1, ..., \sigma_K) \sim \mathcal{D}_{\text{rank}}} \left[ -\sum_{k=1}^K \log \frac{\exp \sum_{\sigma_{\tau(k)}} \gamma^t \alpha \log \pi_\theta(a_t^{\tau(k)} | s_t^{\tau(k)})}{\sum_{j=k}^K \exp \sum_{\sigma_{\tau(j)}} \gamma^t \alpha \log \pi_\theta(a_t^{\tau(j)} | s_t^{\tau(j)})} \right]$$

**Operationally, this is the InfoNCE loss:** the segment at position `$k$` is treated as the "positive" query, and all segments at positions `$k$` through `$K$` are the "negative" candidates. The loss encourages the policy to assign higher score (discounted log-probability) to higher-ranked segments. This is how CPL handles the "dense" preference data: by constructing a total ordering of all segments (from the oracle advantage scores) and treating it as a single ranking, the dense CPL objective becomes a version of InfoNCE where the policy's scoring function is its own log-probability.

## 4. Key Insights and Innovations

### Innovation 1: The Conceptual Cleanup — Recognizing That the Regret Preference Model Enables Direct Policy Learning via Maximum Entropy

The most intellectually distinctive move in this paper is not a new algorithm per se — it's the recognition that two previously disconnected ideas, when combined, eliminate the entire RL stack from RLHF. The key insight is that **the regret preference model (Knox et al., 2022) and the maximum entropy RL framework (Ziebart, 2010) are naturally complementary in a way that no one had previously exploited.** The regret model says human preferences follow the optimal advantage function `A*(s,a)`. Maximum entropy RL says the optimal advantage function is exactly proportional to the optimal policy's log-probability: `A*(s,a) = α log π*(a|s)`. Therefore, under the correct model of human preference, the preference distribution can be rewritten purely in terms of the policy — no advantage function, reward function, value function, or Q-function required.

This is a **fundamental conceptual reframing**, not an incremental improvement. Prior work treated the regret model and the maximum entropy framework as unrelated tools. Knox et al. (2022, 2023) used the regret model to justify learning advantage functions directly, but then had to grapple with Bellman consistency constraints — essentially reinventing RL in the process of fitting those advantages, which limited them to tabular or linear settings. Rafailov et al. (2023) exploited the maximum entropy bijection to eliminate RL from preference learning in DPO, but only in contextual bandits where the bijection simplifies to a relationship between reward and policy. The crucial observation CPL makes — and that no prior work had made — is that the maximum entropy bijection operates at the level of *advantages*, not rewards, and that the regret model's demand for advantages is perfectly met by the bijection's supply of log-probabilities. The paper is essentially saying: "If you accept the regret model (and the evidence in Knox et al. suggests you should), then you don't need to learn advantages — you can learn policies directly, and maximum entropy RL provides the translator."

What makes this more than a clever algebraic manipulation is that it solves a previously-identified practical problem that had no scalable solution. The na¨ıve approach — learn an advantage function via maximum likelihood on preferences, then extract a policy — was known to be intractable for neural networks because the learned advantage must satisfy `∫_A e^{A(s,a)/α} da = 1` for every state, a normalization constraint that is impossible to enforce during training. CPL sidesteps this entirely because any valid policy parameterization (Gaussian, softmax, etc.) automatically satisfies the corresponding constraint `∫_A π(a|s) da = 1` by construction. The normalization burden shifts from something the optimizer must enforce to something the architecture guarantees. This is a genuine architectural insight — it's the difference between "optimize with constraints" and "choose a parameterization where constraints are vacuous."

Evidence for this contribution being fundamental rather than incremental: it opens an entirely new class of algorithms (supervised contrastive losses for sequential RLHF) that didn't exist before. The paper doesn't just propose one method — it proposes a family, with variants for rankings (InfoNCE), KL-constrained preferences (multi-step DPO), and different regularizers (bias, BC, KL). The derivation framework is general and the paper explicitly maps out these connections in Appendix A. The fact that DPO — published contemporaneously by overlapping authors — falls out as a special case when segment length is 1 and states are identical (Appendix A.6) confirms that CPL isn't a parallel discovery but a strictly more general framework.

### Innovation 2: Identifying and Operationalizing the Non-Strict Convexity Problem — And the Bias Regularizer as a Solution

The paper's second major intellectual contribution is the diagnosis of a subtle but practically critical failure mode of contrastive preference objectives, and the introduction of a simple regularizer that addresses it. When the CPL loss is reformulated as logistic regression over comparison vectors (Section 3.1), a structural property emerges: the objective is convex in log π but **not strictly convex** because the comparison matrix X is rank-deficient — there are far more state-action pairs than preference comparisons. This means infinitely many policies achieve the same minimum loss, including policies that place arbitrarily high probability on out-of-distribution actions never seen in the training data.

This is not an abstract concern. The paper provides an explicit constructive proof in Appendix A.3 showing how, given any policy that minimizes the CPL loss, one can shift probability mass to unseen actions while preserving the loss — as long as the relative log-probability differences between compared segments are maintained. In offline settings where the deployment environment may differ from the training distribution, such extrapolation is catastrophic. The paper reframes this as a **pessimism problem**: in offline RL, the standard remedy is to stay within the support of the data, but the vanilla CPL objective provides zero pressure to do so.

The innovation here is not that offline learning has this problem — it is well-known in offline RL (Levine et al., 2020; Jin et al., 2021). The innovation is recognizing that the problem manifests in CPL in a specific, identifiable form (the null space of X) and can be addressed with a specific, lightweight mechanism (the bias regularizer λ). The bias regularizer — multiplying the negative segment's score by λ < 1 in the Boltzmann denominator — breaks the invariance to uniform log-probability shifts. Proposition 2 proves that for any two comparisons achieving the same vanilla CPL loss, the regularized loss favors the comparison where the policy assigns higher absolute log-probability to the actions in the dataset. This is a **tie-breaking mechanism**, not a hard constraint, and the paper shows it works in practice while being simpler than explicit BC regularization or KL constraints.

What distinguishes this from generic regularization is the **precision of the diagnosis**. The logistic regression formulation reveals exactly what structure causes the degeneracy (rank deficiency of X) and exactly what geometric property the regularizer must have (it must break invariance to shifts in the null space of X). The choice of an asymmetric bias rather than a symmetric penalty is deliberate: adding the same penalty to both positive and negative segments would preserve the invariance (both terms shift equally). The bias regularizer attacks the invariance directly by making the positive and negative contributions asymmetric. This is a more elegant solution than explicit BC regularization (which adds a separate term and requires tuning a Lagrange multiplier for a constraint that is only approximate) because it operates within the contrastive objective itself, modifying the relative weighting of the signal rather than supplementing it.

The empirical evidence supports that this matters. The gap between CPL and P-IQL is larger on dense preference datasets than sparse ones (Table 1), which is consistent with the contrastive objective benefiting from more informative negatives — dense comparisons provide richer signal about relative preferences, but without the regularizer, that signal could be satisfied by many degenerate policies. The fact that CPL without pretraining sometimes outperforms CPL with pretraining (Appendix C, Figure 10) suggests the regularizer is genuinely doing work beyond simply anchoring the policy to the BC initialization.

### Innovation 3: Providing the First Scalable Algorithm for Regret-Based Preferences Beyond Grid Worlds

Prior to CPL, the regret preference model had a significant practical problem: it was theoretically appealing but computationally intractable for any non-trivial domain. Knox et al. (2022) introduced the model and proved its identifiability, but the algorithms they proposed for learning from regret-based preferences required either successor features with an assumed linear reward representation or explicit Bellman consistency enforcement on the learned advantage function. These approaches were demonstrated only on simple grid-world environments. Knox et al. (2023) advanced the theory further but their methods remained fundamentally limited by the need to learn a valid advantage function — which, as discussed, requires RL-like bootstrapping or tabular representations.

CPL's contribution here is **practical scalability enabled by theoretical correctness**. By eliminating the need to learn advantage functions entirely and replacing them with policy log-probabilities that are naturally normalized, CPL becomes the first algorithm for regret-based preference learning that can be implemented with standard deep learning toolchains — a policy network, a contrastive loss, and gradient descent. There is no dynamic programming, no Bellman backup, no target networks, no value function approximation error, no policy gradient variance. The computational savings are substantial: on image-based MetaWorld tasks, CPL runs 1.6× faster and uses 2.1 million parameters versus P-IQL's 9.6 million (Table 2). But the real significance is that the regret model — which is arguably the correct model of human preference based on the evidence in Knox et al. — is now deployable at the scale of modern deep RL problems.

This is a **fundamental shift in the accessibility** of the regret preference framework. Before CPL, a practitioner wanting to use regret-based preferences had to essentially build a custom RL algorithm on top of a learned advantage function, requiring expertise in both preference modeling and value-based RL. After CPL, they can use the exact same training infrastructure they would use for behavior cloning or supervised learning — just with a different loss function. The contrastive objective maps directly onto widely-used frameworks for representation learning (SimCLR, MoCo, CLIP), meaning the extensive engineering and scaling knowledge from that literature transfers directly.

The MetaWorld results (Table 1) demonstrate this scalability concretely. On state-based dense preferences, CPL matches or exceeds P-IQL on 5 of 6 tasks, often by substantial margins (70.4% vs. 60.6% on Sweep Into, 61.1% vs. 49.6% on Plate Slide). On image-based dense preferences, CPL outperforms P-IQL on 4 of 6 tasks and ties on the fifth. On sparse state preferences, CPL outperforms P-IQL on 5 of 6 tasks. These gains are achieved with a fraction of the parameters and training time, and without any of the algorithmic complexity of offline RL methods. The fact that CPL can handle both state and pixel observations without modifying the algorithm — it just changes the encoder architecture — is further evidence of the framework's generality relative to prior regret-preference methods, which had no demonstrated ability to handle high-dimensional inputs.

The D4RL human preference experiments (Table 3) provide an additional dimension of evidence. With only 100 or 500 real human preference queries, CPL matches or exceeds Preference Transformer on 3 of 4 tasks, reaching 109.1 normalized score on Hopper-Medium-Expert versus 86.7 for the next best method. This is particularly notable because these human preferences were collected by a single user with pre-planned rules (Kim et al., 2023) — they may not perfectly follow the regret model, yet CPL still performs competitively. This suggests that the CPL objective is reasonably robust to mismatch between the assumed and actual preference model, an important practical property that the paper does not emphasize but the results demonstrate.

### Innovation 4: Unifying Contrastive Representation Learning and Preference-Based RL Under a Single Objective Family

The paper's final distinctive contribution is the explicit mapping of preference-based policy learning onto contrastive representation learning objectives, creating a **unified conceptual vocabulary** that didn't previously exist. The connection is more than cosmetic. The paper shows that:

1. **Pairwise CPL is Noise Contrastive Estimation (NCE)** (Gutmann & Hyvärinen, 2010) where positive and negative segments are scored by discounted log-probability under the policy.

2. **Ranking CPL is InfoNCE** (Oord et al., 2018) where higher-ranked segments serve as positives relative to lower-ranked negatives within the same query, with the same scoring function.

3. **The dense preference variant** augments batches with all pairwise comparisons within the batch, creating a contrastive learning setup nearly identical to SimCLR-style training where the model learns to pull preferred behaviors closer (in log-probability space) and push dispreferred behaviors apart.

This unification is intellectually significant because it reframes RLHF — usually understood through the lens of reinforcement learning or inverse reinforcement learning — as an instance of **self-supervised representation learning** applied to behavioral data. The paper uses the deliberate notation `σ^+` and `σ^-` (instead of `σ_1` and `σ_2` or `σ_A` and `σ_B`) to make this connection visually explicit. The "score" of a segment in CPL is exactly analogous to the embedding similarity in standard contrastive learning — except the "embedding" is the policy's log-probability, and the "similarity" is measured by how likely the policy considers the observed actions.

What makes this more than a relabeling exercise is that it changes the **design principles** for preference-based learning algorithms. If preference learning is contrastive learning, then the entire engineering playbook from contrastive representation learning applies: hard negative mining (Robinson et al., 2021) could improve sample efficiency, data augmentation (already shown to help in the image-based experiments) is a natural fit, momentum encoders could stabilize training, and large batch sizes (which matter enormously in contrastive learning) should improve performance by providing more negatives per positive. The paper's observation that CPL benefits more from dense comparisons than P-IQL (Section 4.2, Figure 2 left, Appendix C.3) is exactly what one would expect from a contrastive method — more negatives per positive improves the quality of the representation — and is harder to explain under the RL-as-optimization framing.

This unification also resolves a tension in the literature. Prior work had observed that contrastive objectives work well for goal-conditioned RL (Eysenbach et al., 2022; Hejna et al., 2023) and that preference data could be used for representation learning (Kang et al., 2023; Xu et al., 2023), but these were seen as separate lines of work — contrastive learning for representations, RL for behavior. CPL shows they are instances of the same underlying mathematics when the scoring function is the policy log-probability and the preference model is regret-based. The distinction between "learning a representation" and "learning a policy" collapses — in CPL, the policy is the representation, and the contrastive loss directly shapes it to match human judgments of optimality.

This is a **framing-level innovation** with downstream practical implications. It suggests that the extensive literature on contrastive learning — including techniques for selecting informative negatives, curriculum design, and scaling to massive datasets — can be directly ported to sequential RLHF. The paper's own dense-batch augmentation (computing all pairwise comparisons within a training batch) is a first step in this direction, and the experiments on increasing comparisons-per-segment (Figure 2, left) provide preliminary evidence that more contrastive signal improves performance. Future work following this framing could incorporate techniques like temperature scaling of the contrastive distribution, momentum-encoded target policies to provide stable negatives, or multi-view augmentations (different crops or perturbations of the same behavior segment treated as positives).

## 5. Experimental Analysis

### Evaluation Methodology

**Dataset.** The primary benchmark is **MetaWorld** (Yu et al., 2020), a suite of simulated robotics manipulation tasks. The paper uses six tasks: Bin Picking, Button Press, Door Open, Drawer Open, Plate Slide, and Sweep Into. All tasks use a modified version of MetaWorld where the goal is observable (removing reward stochasticity) and initial arm position is randomized (increasing data coverage). Proprioceptive history is removed to make the environment more Markovian. For human preference experiments, the paper uses the **D4RL benchmark** (Fu et al., 2020) with real human preference labels from Kim et al. (2023), specifically Walker2D Medium Expert, Walker2D Medium Replay, Hopper Medium Expert, and Hopper Medium Replay — these datasets contain either 100 (expert) or 500 (replay) human preference queries.

**Base model(s).** For MetaWorld, the paper trains policies from scratch — there is no pretrained base model. Suboptimal policies are first trained using Soft Actor-Critic (SAC; Haarnoja et al., 2018) to approximately 50% success rates (actual rates: Bin Picking 55.6%, Button Press 15.56%, Door Open 53.96%, Drawer Open 60.12%, Plate Slide 34.4%, Sweep Into 42.25%, per Table 4). These suboptimal policies generate the offline trajectory data from which preferences are derived. An oracle SAC agent is separately trained to 100% success (incorporating the suboptimal rollout data into its replay buffer) to generate ground-truth optimal advantages for preference labeling. For D4RL, the policies are also trained from scratch, initialized from the offline datasets with real human preference labels.

**Metrics.** The primary metric is **success rate (%)**, measured as the fraction of evaluation episodes in which the agent successfully completes the task. For MetaWorld, evaluation is performed every 5000 training steps (state-based) or 2500 steps (image-based), with 25 episodes per evaluation. The reported numbers in Table 1 are computed as follows: for each seed, a running average over eight neighboring checkpoints (totaling 200 evaluation episodes) is computed; this is then averaged across seeds (4 seeds for state, 3 seeds for images); the maximum of this average is reported. For D4RL, the metric is **normalized score** (scale 0–100+ where 100 represents expert-level performance), evaluated every 5000 steps with 10 episodes following Kim et al. (2023).

**Baselines.** The paper compares against four methods:

- **SFT (Supervised Fine-Tuning):** Trains a policy via behavior cloning on all segments in the preference dataset, then fine-tunes only on the preferred segments (`σ^+`). This represents the simplest possible use of preference data — just imitate what humans prefer.

- **P-IQL (Preference IQL):** An offline RL method that first learns a reward function from preferences (assuming the partial return model, though the labels are regret-based), then optimizes it using Implicit Q-Learning (IQL; Kostrikov et al., 2022). Uses Hejna & Sadigh (2023)'s implementation, which includes a reward model, Q-function, value function, and policy — four separate neural networks. This baseline is equivalent to TREX (Brown et al., 2019) on pairwise preferences.

- **PPO (Proximal Policy Optimization):** A KL-constrained PPO implementation as commonly used for RLHF with LLMs (Ziegler et al., 2019). This is explicitly noted as *not a fair comparison* because PPO requires 3.84 million additional online state-action pairs (25× the data of CPL 2.5K Dense, 4× the data of CPL 20K Sparse) and full trajectory rollouts rather than segment-level data. PPO is run only for state-based experiments.

- **%BC (Top-X% Behavior Cloning):** Trains a policy via behavior cloning on only the top X% of rollouts according to ground-truth reward `r_E` (using 10% and 5%). This represents an oracle baseline showing what performance is achievable by simply filtering the dataset for quality without any preference learning.

Additionally, for D4RL experiments, the paper compares against **Preference Transformer** (PT; Kim et al., 2023), which learns a transformer-based reward model from preferences and then uses IQL for policy optimization.

**Generation budget / compute accounting.** The paper does not use "generations" as its compute unit since CPL does no generation during training (it is an offline method). Instead, compute is measured by **total training steps** and **wall-clock runtime**. All methods are trained for the same number of steps: 500K for state-based, 200K for image-sparse, 120K for image-dense. Pretraining steps count toward this budget. Wall-clock comparison is reported in Table 2: CPL trains in 10.2 hours on a single TitanRTX GPU for 200K image-based training steps, versus 16.5 hours for P-IQL — a 1.62× speedup. Parameter count is 2.1M for CPL (policy only) versus 9.6M for P-IQL (reward + Q + V + policy networks).

**Cross-validation / statistical protocol.** The paper does not use cross-validation. Instead, it reports **mean success rates across seeds** (4 seeds for state experiments, 3 seeds for image experiments) with standard deviations. The evaluation procedure — averaging over eight checkpoints and 200 total episodes per seed, then taking the maximum of the seed-averaged curve — is designed to balance the risk of overfitting (which supervised methods like CPL are more susceptible to than RL methods like P-IQL) against the risk of under-reporting peak performance. The paper explicitly notes this tension: "Supervised learning methods, like CPL can easily overfit the training data. On the other hand, off-policy RL methods like P-IQL converge to a fixed point and thus often take much longer to train before overfitting" (Appendix D.3). For D4RL experiments, results follow the protocol from Kim et al. (2023) with 10 evaluation episodes every 5000 steps.

### Main Quantitative Results

#### How Does CPL Perform on State-Based MetaWorld Tasks?

**The headline result appears in Table 1, rows 1 and 3.** On state-based observations:

**With 2.5K dense segments** (where all pairwise comparisons are labeled, creating a total ordering of segments):
- CPL outperforms all baselines on 5 of 6 tasks by statistically meaningful margins. On Sweep Into, CPL achieves 70.4 ± 3.0% versus P-IQL at 60.6 ± 3.6% and SFT at 51.9 ± 2.1%. On Drawer Open, CPL reaches 83.6 ± 1.6% versus P-IQL at 71.1 ± 2.3%. On Plate Slide, CPL achieves 61.1 ± 3.0% versus P-IQL at 49.6 ± 3.4%. On Door Open, CPL matches P-IQL (80.0 ± 6.8% vs. 79.0 ± 6.6%, both bolded as within 1%). On Bin Picking, CPL achieves 80.0 ± 2.5% versus P-IQL at 70.6 ± 4.1%.
- The only task where P-IQL outperforms CPL is Button Press, where P-IQL scores 16.2 ± 5.4% versus CPL's 24.5 ± 2.1% — but both substantially exceed SFT's 21.6 ± 1.6%, and the standard deviation on P-IQL is large (5.4).
- PPO achieves 22.7 ± 1.9% on Button Press (comparable to CPL's 24.5%) and 83.7 ± 3.7% on Bin Picking (vs. CPL's 80.0%), but underperforms CPL on Drawer Open (79.3 ± 1.2 vs. 80.0 ± 6.8), Plate Slide (51.5 ± 3.9 vs. 61.1 ± 3.0), and Sweep Into (55.3 ± 6.0 vs. 70.4 ± 3.0). Critically, PPO achieves these numbers using 3.84 million additional online state-action pairs — a 25× data multiplier over the 2.5K dense dataset.
- %BC baselines achieve 62.6% (top 10%) and 64.6% (top 5%) on Bin Picking — well below CPL's 80.0% — confirming that CPL is extrapolating beyond the best behaviors in the dataset, not simply mimicking high-quality segments.

**With 20K sparse segments** (one pairwise comparison per two segments, 10K total comparisons):
- CPL outperforms baselines on 5 of 6 tasks: Sweep Into (81.2 ± 1.6% vs. P-IQL 73.4 ± 4.2%), Bin Picking (83.2 ± 3.5% vs. P-IQL 75.0 ± 3.3%), Button Press (29.8 ± 1.8% vs. P-IQL 19.5 ± 1.8%), Drawer Open (79.1 ± 5.0% vs. P-IQL 76.2 ± 2.8%), and Plate Slide (56.4 ± 3.9% vs. P-IQL 55.5 ± 4.2% — close but CPL edges ahead).
- On Door Open, P-IQL slightly edges out CPL (79.0 ± 6.6% vs. 77.9 ± 9.3%), though both are bolded (within 1%).
- PPO underperforms CPL on all tasks except Door Open (82.8 ± 1.6% vs. 77.9 ± 9.3%) and performs comparably on Button Press (24.5 ± 0.8% vs. 29.8 ± 1.8%) — but again, with 3.84M extra online samples.

**A critical pattern emerges across both datasets:** the gap between CPL and P-IQL is consistently larger on the dense dataset than on the sparse dataset. For example, on Sweep Into, CPL leads by 9.8 percentage points (70.4 vs. 60.6) on dense but only 7.8 points (81.2 vs. 73.4) on sparse. On Plate Slide, the gap is 11.5 points on dense versus 0.9 points on sparse. This is consistent with CPL's contrastive nature — denser comparisons provide more informative positive-negative pairs that help shape the policy.

#### How Does CPL Scale to High-Dimensional Image Observations?

**Table 1, rows 2 and 4, and Table 2.** With 64 × 64 pixel image observations using the DrQv2 architecture (Yarats et al., 2022) with random shift augmentations:

**With 2.5K dense image segments:**
- CPL outperforms P-IQL on 4 of 6 tasks and ties on 1: Button Press (27.5 ± 4.2% vs. 22.1 ± 0.8%), Door Open (73.6 ± 6.9% vs. 68.0 ± 4.6%), Drawer Open (80.3 ± 1.4% vs. 76.0 ± 4.6%), Plate Slide (57.3 ± 5.9% vs. 51.2 ± 2.4%), and Sweep Into (68.3 ± 4.8% vs. 67.7 ± 4.4%) — the last being a virtual tie.
- On Bin Picking, P-IQL outperforms (83.7 ± 0.4% vs. 80.0 ± 4.9%), though both are high-performing. Interestingly, P-IQL's performance *increases* substantially when moving from state to images (from 70.6% to 83.7% on Bin Picking), while CPL's stays nearly identical (80.0% vs. 80.0%). The paper attributes this to data augmentation benefiting value function learning for P-IQL. SFT also sees a moderate improvement (66.9% → 74.7% on Bin Picking).

**With 20K sparse image segments:**
- CPL and P-IQL perform comparably on most tasks. CPL wins on Button Press (31.3 ± 1.6% vs. 27.2 ± 4.1%), Plate Slide (61.0 ± 4.2% vs. 54.8 ± 5.8%), and Sweep Into (72.0 ± 1.8% vs. 72.5 ± 2.0% — tie). P-IQL wins on Bin Picking (80.0 ± 2.3% vs. 78.5 ± 3.1%), Door Open (74.8 ± 5.8% vs. 70.2 ± 2.1%), and Drawer Open (80.3 ± 1.2% vs. 79.5 ± 1.4%).
- The sparser comparison data reduces CPL's advantage relative to P-IQL on images, consistent with the pattern observed in the state-based experiments.

**The computational efficiency advantage is stark** (Table 2). On image-based training, CPL uses 2.1M parameters (just the policy network) compared to 9.6M for P-IQL (reward model + Q-function + value function + policy + separate encoders for each). Runtime is 10.2 hours for CPL versus 16.5 hours for P-IQL — a 1.62× speedup. The paper notes this gap would only grow with larger models: "As networks get larger and larger, the performance gain from using CPL would only increase" (Section 4.1). This is because CPL's parameter count scales linearly with model size (only the policy grows), while P-IQL's scales roughly 4× (reward, Q, V, and policy all grow).

#### How Does CPL Perform on Real Human Preferences (D4RL)?

**Table 3 and Figure 11 (Appendix C.5).** On the D4RL human preference benchmark from Kim et al. (2023), using only 100 (expert datasets) or 500 (replay datasets) human preference queries:

- **Hopper Medium Expert:** CPL achieves a normalized score of 109.1 ± 0.7, dramatically outperforming P-IQL (88.6 ± 3.6) and Preference Transformer (86.7 ± 6.8). This is a 22.7% improvement over the next best method.
- **Walker2D Medium Expert:** CPL approximately ties Preference Transformer (109.2 ± 0.2 vs. 110.2 ± 0.8), both significantly above P-IQL (99.9 ± 6.2).
- **Hopper Medium Replay:** CPL achieves 72.4 ± 3.1, outperforming P-IQL (60.2 ± 20.6) and approaching Preference Transformer (78.9 ± 10.3).
- **Walker2D Medium Replay:** CPL underperforms at 48.3 ± 3.7, significantly below P-IQL (71.6 ± 5.9) and Preference Transformer (76.6 ± 3.2).

For these experiments, CPL was modified to handle the extremely limited number of queries: it first learns a logistic regression model (not a reward or advantage function — it operates on entire segments) to predict human preferences `P[σ^+ ≻ σ^-]`, following An et al. (2023), then uses this model to relabel the offline D4RL data with dense preferences for CPL. The paper does not use BC pretraining in this setting.

The Walker2D Medium Replay failure is noteworthy. The paper speculates: "We posit that this is because the preferences for this dataset may not closely follow the regret-based model as per discussions with the authors of Kim et al. (2023) they were collected by a single user with a pre-planned rules-based approach." This is an honest admission that CPL's performance depends on the regret model being a reasonable approximation of the actual preference-generation process.

### Ablation Studies and Robustness Checks

**Dense vs. sparse comparison density (Figure 7, Figure 8, and Table 1):** The paper systematically varies the number of comparisons per segment. Figure 7 (Appendix C.3) shows scaling with different-sized dense comparison datasets (1K, 2.5K, 5K, 7.5K segments) on state-based MetaWorld. CPL's performance generally increases with dataset size on most tasks, while P-IQL's is more variable — on Door Open, P-IQL's performance *drops* when scaling from 2.5K to 7.5K segments (from ~0.85 to ~0.75 success rate), which the paper attributes to reward model underfitting ("Inspecting our training logs reveals that this is likely due to the reward function underfitting... the reward modeling loss is near zero with only 2 comparisons per segment... With 16 comparisons per segment, the loss ends near 0.16. This highlights an additional limitation of P-IQL: it requires tuning an addition[al] reward model, which can be very sensitive to its training parameters").

Figure 8 (Appendix C.3) controls total segments at 5K and varies comparisons-per-segment from 2 to 16. CPL benefits substantially from more comparisons on most tasks: Bin Picking increases from ~0.80 (2 comparisons/segment) to ~0.88 (16 comparisons/segment), Sweep Into from ~0.68 to ~0.80. The exceptions are Button Press (relatively flat) and Plate Slide (slight decrease at higher densities). P-IQL is less affected by comparison density and sometimes performs worse with more comparisons — on Sweep Into, P-IQL drops from ~0.78 (2 comp/seg) to ~0.73 (16 comp/seg). This is a critical finding: **CPL exhibits the expected behavior of a contrastive method — more negatives per positive helps — while P-IQL does not**, suggesting CPL is better suited to leveraging rich preference data.

**Segment length (Figure 9, Appendix C.4):** On Drawer Open with 20K sparse segments, the paper varies segment size from 8 to 64 steps. Both CPL and P-IQL perform best with longer segments (64 steps), with CPL achieving ~0.85 success rate at segment size 64 versus ~0.78 at size 8. This confirms that longer segments provide more informative temporal context for learning sequential behaviors.

**Hyperparameter sensitivity — temperature α and bias λ (Figure 2, right panel, and Section 4.2):** On Drawer Open from state with 2.5K dense segments:
- **Temperature α:** Swept at 0.02, 0.1, and 0.5. α = 0.1 reaches ~0.88 success rate, α = 0.5 reaches ~0.85, and α = 0.02 plateaus around ~0.80. Higher α amplifies the contrastive signal (larger difference in scores per unit of log-probability difference), but too high (0.5) may overfit to label noise. Lower α (0.02) provides insufficient signal per comparison.
- **Bias λ:** Swept at 0.25, 0.5, and 0.75. λ = 0.5 performs best (~0.88), λ = 0.25 plateaus lower (~0.82), and λ = 0.75 plateaus even lower (~0.80). This confirms the bias regularizer is doing meaningful work — too little bias (0.25) doesn't sufficiently push the policy toward the data distribution; too much bias (0.75) dampens the contrastive signal from negatives.

**Pretraining ablation (Figure 10, Appendix C.4):** On MetaWorld state with 2.5K dense segments, CPL without BC pretraining is compared to CPL with pretraining. On Bin Picking, CPL without pretraining achieves ~0.82 versus ~0.78 with pretraining. On Door Open, no-pretraining reaches ~0.82 versus ~0.80 with pretraining. On Button Press, no-pretraining is slightly worse (~0.22 vs. ~0.24). The paper concludes that "pretraining helps when a policy closer to the data distribution is desirable" but can also constrain the policy too much, preventing it from moving far enough from the average behavior in the dataset.

**Alternative CPL variants (Figures 3-6, Appendix C.1-C.2, and Appendix B):** Two additional regularizer variants are compared in learning curves:
- **CPL (BC):** BC-regularized CPL with β = 1. On state 2.5K dense (Figure 3), CPL-BC generally underperforms the bias-regularized CPL — substantially on Bin Picking (~0.72 vs. ~0.80 CPL), Button Press (~0.20 vs. ~0.25), and Door Open (~0.72 vs. ~0.80). On image 2.5K dense (Figure 5), CPL-BC trails CPL on most tasks.
- **CPL (KL):** KL-constrained CPL with λ = 0.75, shown only for state 20K sparse (Figure 4). Underperforms both CPL and CPL-BC on Bin Picking (~0.70 vs. ~0.83 CPL), door Open (~0.68 vs. ~0.78), and Drawer Open (~0.72 vs. ~0.79), while being comparable on Plate Slide and Sweep Into. The reference distribution µ may be poorly estimated from suboptimal data, limiting its effectiveness.

**Dense batch augmentation (Appendix B and image experiments):** For image-based experiments with dense preferences, CPL augments each training batch by computing all pairwise comparisons within the batch — for `b` segments, this yields `b(b-1)` directed comparisons (minus self-comparisons). The paper notes this "lead to a slight increase in performance for some tasks" (Appendix B), though no direct ablation is provided comparing with-and-without batch augmentation.

**PPO sensitivity (Section 4.1 and Appendix D.4):** While not a CPL ablation, the paper reports substantial difficulty tuning PPO: "We found PPO to be very sensitive to the KL-constraint coefficient on reward, which makes it difficult to tune as observed in prior work (Touvron et al., 2023)." Additionally, "we spent a lot of time tuning PPO to try and get better results. We found that limited the standard deviation of the policy to be at least 0.5 was crucial, as well as bounding the reward values of the pretrained reward model to stay between 0 and 1." Despite this tuning effort, PPO still underperforms CPL on most tasks while requiring orders of magnitude more data.

### Critical Assessment

#### Claim: "CPL matches or exceeds prior RL-based methods while being 1.6× faster and using 1/4 the parameters"

**Where the evidence is strong.** The side-by-side comparison with P-IQL across 6 MetaWorld tasks, two observation modalities (state and image), and two data regimes (dense and sparse) is comprehensive. CPL either exceeds or matches P-IQL on 18 of 24 task-dataset-modality combinations (6 tasks × 2 datasets × 2 modalities). The computational efficiency claims (Table 2) are straightforward and well-supported: 1.62× faster training, 4.6× fewer parameters. The parameter count advantage is an architectural certainty — CPL has one network, P-IQL has four — and would generalize to any domain.

**Where the evidence is weaker.** The claim that CPL "matches or exceeds" prior methods is sensitive to the choice of baseline P-IQL configuration. P-IQL's hyperparameters were tuned for 10K comparisons (the sparse setting), then held fixed for dense experiments. The paper acknowledges that P-IQL sometimes underperforms with more comparisons because its reward model underfits — but this raises the question of whether a *differently tuned* P-IQL could have performed better on dense data. A fairness-minded reader might ask: was P-IQL given equal hyperparameter optimization effort relative to CPL? The paper states both methods were tuned, but P-IQL has more components (reward model learning rate, reward net steps, IQL expectile, IQL temperature) than CPL (α and λ), making it harder to tune comprehensively within a fixed budget. The comparison may inadvertently favor CPL by virtue of its simplicity.

**Missing experiments.** A direct comparison with DPO on the *contextual bandit* version of these tasks (single-step decisions) would have isolated whether CPL's gains come from the regret model or from the contrastive objective itself. The paper shows theoretically that DPO is a special case of CPL (Appendix A.6), but no empirical comparison is provided. Additionally, CPL is never compared to a version of P-IQL that *directly learns the advantage function* as its reward (rather than learning a reward and then doing IQL) — since the preferences are regret-based, this would be a more natural baseline for testing whether CPL's shortcut (skipping advantage learning) is actually beneficial or just different.

#### Claim: "CPL can effectively use the same RLHF fine-tuning procedure as dialog models to learn temporally extended manipulation policies"

**Where the evidence is strong.** The MetaWorld tasks genuinely require sequential decision-making — they are multi-step manipulation problems with complex dynamics, not contextual bandits. The fact that CPL learns effective policies from offline segment-level preferences on these tasks, and does so with a training protocol (pretraining + fine-tuning with preferences) that mirrors the LLM RLHF recipe, demonstrates the claimed capability. The experiments with segment lengths of 64 steps (versus varying lengths down to 8 in the ablation, Figure 9 Appendix C.4) confirm that CPL uses the temporal structure, not just the first or last step.

**Where the evidence is weaker.** The paper claims CPL is suitable for "the same RLHF fine tuning procedure as dialog models," but there is a critical procedural mismatch. In LLM RLHF, preferences are typically collected on *model-generated* responses — the policy generates text, humans rate it, and then the policy is updated. In CPL's MetaWorld experiments, preferences are generated *offline* from a fixed dataset of suboptimal rollouts — there is no online interaction, no deployment of the current policy to collect new preferences, and no iterative refinement cycle. The training protocol is purely offline, while LLM RLHF is typically iterative (collect data → train → collect more data → train again). The paper acknowledges this gap (Section 6: "Our work only considers offline data generated by suboptimal policies. An online version of CPL could be developed that works with online human feedback"), but the claim "can effectively use the same... procedure" overstates the current evidence. An online CPL experiment — where preferences are collected on the current policy's outputs and used for the next training round — would be needed to substantiate this claim.

#### Claim: "CPL is able to match the performance of prior RL based methods"

**Where the evidence is strong.** On the MetaWorld benchmark, CPL is competitive with or superior to P-IQL across almost all settings. On D4RL human preferences, CPL matches or exceeds Preference Transformer on 3 of 4 tasks. The evidence for "matching" is robust.

**Where the evidence is weaker.** The D4RL Walker2D Medium Replay result (48.3 for CPL vs. 71.6 for P-IQL and 76.6 for Preference Transformer) is a significant failure. The paper's explanation — that the preferences may not follow the regret model — is plausible but unverified. A more rigorous approach would have tested whether P-IQL (which assumes the partial return model) systematically outperforms CPL when the true preference model is *not* regret-based, and vice versa. Without such a controlled experiment, the claim that CPL "matches" prior methods carries an unstated condition: *when preferences approximately follow the regret model*. This condition is satisfied by construction in the synthetic MetaWorld experiments but may not hold for real human data.

**Missing experiment.** A controlled study varying the preference model used to generate labels — comparing CPL and P-IQL under both partial-return-generated preferences and regret-generated preferences — would cleanly separate the benefit of the regret model from the benefit of the contrastive objective. Without this, we cannot know whether CPL's strong performance comes from the regret model (which captures human preferences better) or from the contrastive loss (which may simply be a more effective optimization mechanism than IQL, even if the underlying model is wrong). The paper's synthetic data uses only regret-based labels, so the algorithms are never tested under model mismatch where CPL's assumed preference model is wrong.

#### Claim: "Without dynamic programming or policy gradients, CPL is able to match the performance of prior RL based methods"

**This claim is solidly supported.** The CPL loss function (Eq. 5) contains no value function, no Q-function, no Bellman backup, no advantage estimation, no policy gradient — it is a pure supervised loss computed by evaluating the policy's log-probability on fixed data and comparing preferred to dispreferred segments. Yet the results in Table 1 show CPL matching or exceeding P-IQL (which does value iteration via IQL) and PPO (which does Monte Carlo policy gradient estimation). This is the paper's most consequential empirical finding: it proves, by demonstration, that the RL phase of RLHF is dispensable for the class of problems tested.

**Caveat.** The claim holds for problems where the base data provides sufficient coverage — the paper goes to substantial lengths to discuss the off-distribution issue and the need for regularization. On problems with very narrow data coverage or where out-of-distribution generalization is required, the lack of dynamic programming (which, in methods like IQL, provides a mechanism for stitching together suboptimal trajectories into optimal ones) might become a liability. The paper does not test CPL in data-scarce regimes where this stitching is critical — the offline datasets, while suboptimal, contain partial successes (~50% average success rate across tasks) that provide reasonable coverage of the state space. On datasets with lower coverage or more severe distribution shift, P-IQL's value-based stitching might provide an advantage that CPL's purely policy-based objective cannot match.

#### Overall Assessment of the Experimental Design

**Strengths:**
- **Comprehensive coverage:** 6 tasks × 2 observation modalities × 2 data densities × 4 baselines = a thorough empirical study. Learning curves are provided for all combinations in the appendix, allowing readers to assess training dynamics beyond the summary statistics in Table 1.
- **Honest reporting of weaknesses:** The paper is transparent about PPO's unfair data advantage, CPL's failure on Walker2D Medium Replay, and the sensitivity of P-IQL to comparison density. Negative results are reported rather than buried.
- **Ablation quality:** The hyperparameter sweeps (α, λ, segment length, comparisons per segment, pretraining on/off, regularizer variants) systematically probe CPL's design space and demonstrate that the key components (bias regularizer, sufficient comparison density) are doing genuine work.
- **Real human preference validation:** The D4RL experiments, while limited (4 tasks, small preference datasets), provide an existence proof that CPL works with actual human data, not just synthetic labels.

**Weaknesses:**
- **Single benchmark domain (MetaWorld) for the main results:** MetaWorld is a specific robotics manipulation benchmark. Whether CPL's performance transfers to other sequential decision domains (navigation, game playing, dialogue management) is unknown. The algorithmic principles should generalize, but the empirical demonstration is narrow.
- **Small evaluation sets:** The evaluation protocol — 200 total episodes per seed, formed by averaging over 8 checkpoints — means that a single unlucky batch of 25 evaluation episodes can meaningfully shift an 8-checkpoint average. With only 3-4 seeds, standard deviations in Table 1 are sometimes large (e.g., CPL on Door Open state 2.5K Dense: 80.0 ± 6.8%, P-IQL on Hopper Medium Replay: 60.2 ± 20.6%), suggesting substantial run-to-run variability that the modest seed count may not fully capture.
- **Oracle preferences in MetaWorld are only regret-based:** The synthetic labels are generated from the oracle SAC advantage function. This means the experiments test CPL under *perfect model specification* — the preference model used to generate labels is exactly the one CPL assumes. Real human preferences may deviate from the regret model in unknown ways. The D4RL results partially address this (real humans provided the preferences), but the small scale and mixed results (one failure out of four tasks) leave uncertainty.
- **No evaluation of the learned implicit advantage:** CPL produces an implicit advantage function `A(s,a) = α log π(a|s)`. The paper never evaluates whether this advantage function actually matches the true `A*(s,a)` — it evaluates only the downstream policy's success rate. This leaves open the question of whether CPL's policy improvement comes from accurately recovering the advantage function (as the theory claims) or from some other mechanism that happens to produce good policies without matching the underlying advantage. A pointwise comparison of learned vs. true advantages at sampled states would have strengthened the theoretical narrative.
- **The difficulty estimation problem is unaddressed:** Unlike RLHF for LLMs, where a reward model is explicitly trained to score outputs, CPL has no mechanism for estimating how "good" a segment is beyond the policy's own log-probability. This means CPL cannot be easily used for *ranking* new behaviors at deployment time — it can produce a policy, but it cannot evaluate someone else's policy. For applications requiring a standalone reward or verifier model, CPL provides no solution. This is not a flaw in the experiments per se, but a limitation of the approach that the experimental design does not acknowledge.

## 6. Limitations and Trade-offs

### The Difficulty Estimation Problem Is Not Addressed, Making the Framework Incomplete for Deployment

**The assumption or constraint.** CPL assumes that a dataset of human preference comparisons over behavior segments already exists — preferences are given as input, not as something the system must actively elicit or estimate. This is a reasonable assumption for an offline algorithm, but it carries a hidden implication: CPL provides no mechanism for *evaluating* the quality of novel behaviors at deployment time. Unlike standard two-phase RLHF methods, which produce an explicit reward model or verifier that can score arbitrary new trajectories, CPL learns only a policy. The policy can generate actions, but it cannot answer the question "which of these two candidate behaviors is better?" — a capability that is often critical in practice for filtering generated outputs, selecting among alternatives, or providing interpretable quality scores.

The paper acknowledges this implicitly by positioning CPL purely as a *policy learning* algorithm, not a *verifier learning* algorithm. The contrastive objective trains a policy to maximize the likelihood of observed preferences, but the policy's implicit advantage function `$A(s,a) = \alpha \log \pi(a|s)$` — which the theory says should converge to `$A^*(s,a)$` — is never validated as an accurate verifier. There is no experiment where CPL's implicit advantage is used to rank held-out segments and the ranking is compared to ground-truth preference labels. The entire experimental evaluation measures only the *policy's* success rate, not the *verifier's* accuracy.

**The consequence.** For applications that require a standalone reward or verifier model — which includes most current RLHF pipelines for LLMs, where the reward model is used to score model-generated responses during the RL phase, to filter bad outputs at inference time, or to serve as a training signal for iterative refinement — CPL cannot serve as a drop-in replacement. It solves the policy-optimization problem but leaves the verifier problem unsolved. A practitioner who needs to reject low-quality generations at deployment time would need to train a separate verifier model (bringing back exactly the complexity CPL was designed to avoid) or trust that the policy never produces bad outputs (which is unrealistic).

Furthermore, for *iterative* RLHF pipelines — where the policy is deployed, new preferences are collected on its outputs, and the model is updated — CPL's offline nature means it would need to be retrained from scratch on the accumulated preference dataset each iteration, rather than incrementally updated. The verifier-based approach decouples preference modeling from policy optimization, allowing the reward model to be continuously refined and the policy to be periodically retrained. CPL tightly couples these steps into a single loss, which is elegant for one-shot training but creates friction for iterative deployment loops.

**What evidence exists in the paper.** This limitation is entirely unmeasured. The paper never reports the correlation between CPL's implicit advantage function and the ground-truth optimal advantage, never uses `$\alpha \log \pi(a|s)$` to rank or evaluate behavior segments, and never compares the *verification accuracy* of CPL versus a learned reward model on held-out preference data. Table 1 reports only task success rates. The D4RL experiments (Section 4.3, Table 3) use a separately trained logistic regression model to predict preferences, which is then used to relabel data for CPL — this external preference predictor is essentially a reward model in all but name, and its existence undermines the claim that CPL eliminates the need for reward-like components in the full pipeline.

**Mitigation status.** The paper does not acknowledge this limitation or propose mitigations. It is a consequence of the architecture — learning a policy directly means there is no explicit scoring function that can be applied independently of the policy. Future work might address this by jointly training a verifier alongside the policy using the same contrastive objective, or by showing that the implicit advantage is practically useful as a verifier, but the current paper provides no evidence for either approach.

---

### Hard Problems Where the Base Data Has Insufficient Coverage Remain Unsolved — CPL Can Only Amplify, Not Create

**The assumption or constraint.** CPL is an *offline* algorithm that learns entirely from a fixed dataset of suboptimal trajectories. The regret preference model provides information about which behaviors are better than others, but it cannot provide information about behaviors that are absent from the dataset entirely. If the dataset contains no examples of a particular skill — for instance, a robot never successfully picks up an object in the Bin Picking task — then CPL has no mechanism for *discovering* that skill. The contrastive loss can push the policy toward the better segments in the data, but the policy's probability mass is fundamentally constrained by where the data provides coverage.

The paper addresses this issue through the non-strict convexity analysis (Section 3.2, Appendix A.3) and the bias regularizer. The analysis shows that the vanilla CPL loss has infinitely many minimizers, some of which place high probability on out-of-distribution (OOD) actions — and the bias regularizer is designed to *prevent* this by favoring solutions that stay within the data distribution. This means CPL is explicitly designed to be *conservative* with respect to data coverage: it actively avoids extrapolating beyond the support of the dataset. While this is the correct strategy in offline RL (where OOD actions lead to distributional shift and catastrophic failure), it also means that CPL cannot learn behaviors that are not at least partially demonstrated in the data.

This stands in contrast to standard offline RL methods like IQL, which perform *dynamic programming* — they use the Bellman equation to propagate value estimates from successful states backward through the transition dynamics, potentially stitching together suboptimal trajectory fragments into novel optimal paths. CPL has no such mechanism: it only compares complete segments, never *composing* partial segments into new sequences.

**The consequence.** On tasks where the base dataset contains *some* successful trajectories (even if rare), CPL can amplify those successes by upweighting the policy probability on states and actions that lead to success. This is what the strong results on MetaWorld (Table 1) demonstrate — the suboptimal datasets have ~50% success rates on average, meaning roughly half the segments contain at least partial success. But on tasks where the base dataset has *zero* successful trajectories — or where success requires a sequence of actions never seen together in the data — CPL would fail to learn. The contrastive loss would have no positive signal to amplify.

The paper's own data supports this concern indirectly. On the hardest task in the benchmark — Button Press — the suboptimal policies achieve only a 15.56% success rate (Table 4), far lower than any other task. The performance of *all* methods on Button Press is substantially lower than on other tasks: CPL achieves 24.5% on state dense, 29.8% on state sparse, 27.5% on image dense, 31.3% on image sparse. These are the lowest success rates across all tasks, roughly a third of what CPL achieves on easier tasks like Bin Picking or Drawer Open. While CPL does outperform the baselines on Button Press, the absolute performance remains poor — the policy cannot succeed more than ~30% of the time despite having preferences that distinguish good from bad behavior. This suggests that the dataset lacks sufficient coverage of successful Button Press behavior for any method to reliably learn from.

The D4RL Walker2D Medium Replay result (48.3 normalized score for CPL vs. 71.6 for P-IQL, Table 3) provides additional evidence. The Medium Replay dataset consists of data from a replay buffer of a partially-trained agent — it contains a mix of exploratory and successful behaviors, but the coverage of successful trajectories is sparser and less consistent than the Expert datasets. P-IQL's value-based dynamic programming may allow it to stitch together fragments of good behavior that CPL's segment-based contrastive loss cannot compose. The paper's speculation that the preferences may not follow the regret model is only one possible explanation — the alternative is that CPL's purely policy-based objective lacks the compositional generalization capability that value-based methods provide.

**What evidence exists in the paper.** The limitation is partially visible in the difficulty-dependent performance patterns (Button Press being universally hard, Walker2D Medium Replay being the only D4RL failure), but the paper never runs an explicit experiment testing data coverage as a variable. There is no ablation where the percentage of successful trajectories in the dataset is systematically varied and CPL's performance compared to P-IQL's — such an experiment would directly reveal whether CPL's lack of dynamic programming creates a coverage-dependent performance gap. The non-strict convexity analysis (Appendix A.3) effectively proves that CPL *could* extrapolate to OOD actions in principle (since the loss does not uniquely determine the policy on unseen state-action pairs), but the bias regularizer is designed to prevent exactly this. The tension between "the loss could extrapolate" and "the regularizer prevents it" is never resolved experimentally.

**Mitigation status.** The paper addresses the OOD extrapolation problem by introducing the bias regularizer (Section 3.2, Proposition 2), which pushes the policy toward the data distribution. This is a conscious design choice — the paper is choosing conservatism over potential unsafe extrapolation — but it does not provide an alternative mechanism for composing novel behaviors from partial data. The paper acknowledges in Section 6 that an online version of CPL could be developed to address this ("An online version of CPL could be developed that works with online human feedback, allowing policies to continually improve") — online interaction would allow the policy to explore and collect data on behaviors it is uncertain about, potentially filling coverage gaps. But the offline version presented here has no such capability.

### The Discount Factor γ Must Be Known and Matches the Human's Temporal Discounting — A Strong and Unvalidated Assumption

**The assumption or constraint.** CPL's loss function (Eq. 5) weights each step in a behavior segment by `$\gamma^t$`, where `$\gamma$` is the discount factor from the MDP. The derivation of CPL from the regret preference model (Eq. 2) assumes that human preferences follow the *discounted* sum of optimal advantages: `$\sum_{\sigma} \gamma^t A^*(s_t, a_t)$`. The discount factor `$\gamma$` appears in three places simultaneously: (1) it defines how the expert's optimal advantage function `$A^*$` is computed (via the Bellman equation), (2) it defines how humans weight different timesteps when comparing segments, and (3) it appears explicitly in the CPL loss as the weight applied to each step's log-probability.

For the CPL objective to converge to the correct optimal policy, the `$\gamma$` used in the loss must match the `$\gamma$` that generated the expert's optimal advantage function, which in turn must match the `$\gamma$` implicit in the human's preference judgments. This is a strong assumption. In practice, it is extremely difficult to know a human's temporal discounting — do they care equally about all steps in a 64-step behavior segment? Do they discount future steps? At what rate? The paper sets `$\gamma = 1.0$` in all MetaWorld experiments, meaning every step from 1 to 64 is weighted equally. The paper also sets `$\gamma = 0.99$` for the P-IQL baseline (Table 7), creating a subtle mismatch: CPL uses `$\gamma = 1.0$` while the method it is compared against uses `$\gamma = 0.99$`. The oracle SAC used to generate preference labels also uses its own `$\gamma$` (not explicitly stated, but presumably 0.99 as is standard for SAC). This means the `$\gamma$` in the preference labels, the `$\gamma$` in CPL's loss, and the `$\gamma$` in P-IQL's optimization are different — and the paper does not discuss the implications of this mismatch.

**The consequence.** If the human's temporal discounting differs from the `$\gamma$` used in CPL's loss, the learned policy will not converge to the true optimal policy for the human's intended reward function. The mismatch introduces a systematic bias: if the human cares less about later timesteps than CPL assumes (i.e., the true `$\gamma$` is smaller), CPL overweights later steps and may learn policies that prioritize long-term outcomes at the expense of immediate correctness. Conversely, if the human cares more about later timesteps (true `$\gamma$` is larger, approaching 1.0), CPL underweights them and may learn myopic policies that ignore future consequences.

Furthermore, different humans may have different discount factors, and the same human may apply different discounting to different types of tasks. A human evaluating a robot performing a manipulation task might care strongly about the final outcome (reaching the goal) and less about intermediate motions — but CPL with `$\gamma = 1.0$` weights all steps equally, potentially penalizing efficient but jerky motions that would be acceptable to a human. The paper provides no mechanism for learning `$\gamma$` from the preference data itself — it is treated as a fixed hyperparameter that must be specified in advance.

**What evidence exists in the paper.** The paper explicitly acknowledges this limitation in Section 6: "CPL, like other RLHF approaches, assumes knowledge of the human rater's temporal discounting (i.e., of the discount factor γ), which in practice would be difficult to communicate." However, there is no ablation study varying `$\gamma$` in CPL to test sensitivity. The fixed `$\gamma = 1.0$` in all experiments means we have no evidence about how much performance degrades if `$\gamma$` is misspecified — for instance, if a practitioner guessed `$\gamma = 0.9$` when the human actually used `$\gamma = 0.99$`. The mismatch between CPL's `$\gamma = 1.0$` and P-IQL's `$\gamma = 0.99$` is noted in Tables 6 and 7 but not discussed.

The appendix D results on varying segment length (Figure 9, Appendix C.4) are tangentially relevant: performance improves with longer segments (64 steps outperforms 8 steps), which suggests that more temporal context is helpful. But this does not isolate the effect of `$\gamma$` — it only shows that having more steps in the segment (weighted equally with `$\gamma = 1.0$`) is beneficial. The interaction between segment length and discount factor is unexplored.

**Mitigation status.** The paper suggests one mitigation in the Future Directions section: "to relax the assumption that γ is known, one might instead include it in the expressivity of CPL or other RLHF approaches." This is vague — it is not clear what "include it in the expressivity" means (learn γ as a parameter? Infer it from annotation times? Use inverse RL techniques?). No concrete approach is proposed or tested. The limitation remains essentially unaddressed in the current work.

---

### Single Benchmark Domain and Single Model Architecture — The Generality of the Approach Is Not Empirically Validated

**The assumption or constraint.** All main experimental results (Table 1, Figures 2-10) are on the MetaWorld robotics manipulation benchmark (Yu et al., 2020) using relatively small MLP or DrQv2 convolutional policies (2.1M parameters maximum). The D4RL experiments (Table 3) extend to locomotion tasks but use a different CPL variant (with a separately trained preference predictor) and still involve only standard MuJoCo environments with moderate-dimensional state spaces. There are no experiments on domains where RLHF is most prominently deployed — language generation, code synthesis, image generation — nor on domains with fundamentally different structure, such as discrete action spaces, partially observable environments, or multi-agent settings.

The paper claims (Section 1) that CPL is applicable to "arbitrary MDPs" and can "elegantly scale to high-dimensional and sequential RLHF problems," but the highest-dimensional input tested is 64 × 64 pixel images — a far cry from the scale of modern LLMs (vocabularies of tens of thousands of tokens, sequence lengths of thousands of steps) or high-resolution image generation (256 × 256 or larger outputs with complex spatial structure). The policy architectures used (Gaussian MLPs and DrQv2 encoders) are not representative of the transformer-based architectures that dominate LLM and vision applications.

**The consequence.** The empirical evidence does not support the claim of general applicability across "arbitrary MDPs." Several aspects of CPL's performance could be specific to the continuous-control robotics domain:

- **Continuous action spaces:** CPL's policies are Gaussian, and the contrastive loss operates on log-probabilities computed from Gaussian likelihoods. In discrete action spaces (e.g., language token generation), the log-probability is computed from a categorical distribution, and the normalization properties (which CPL relies on for consistency, Proposition 1) are different — categorical distributions are naturally normalized, but the geometry of the optimization landscape differs substantially from continuous Gaussians.

- **Relatively short segments:** MetaWorld segments are 64 steps. For language tasks, a single response can be hundreds or thousands of tokens. The contrastive loss sums log-probabilities over the entire segment — for very long segments, this sum could become numerically unstable (the scores grow with segment length), and the relative weighting of early vs. late tokens (controlled by `$\gamma$`) becomes increasingly important. The paper's `$\gamma = 1.0$` setting means that a 1000-token segment has each token weighted equally, making the score a sum of 1000 log-probabilities that could dominate the Boltzmann comparison.

- **Dense reward structure shaped by advantage:** The MetaWorld tasks, when labeled with regret-based preferences, effectively provide dense, shaped feedback — the advantage function `$A^*(s,a)$` is non-zero at almost every step, distinguishing good from bad actions continuously. In sparse-reward environments where the advantage is zero for most steps and only becomes informative near the goal, CPL's contrastive signal would be much weaker per segment, potentially requiring orders of magnitude more preference data to achieve the same performance.

- **No experiments with stochastic or human preferences at scale:** The main MetaWorld results use *synthetic* preferences derived from an oracle advantage function. The D4RL experiments use real human preferences but with only 100-500 queries — and CPL requires a separately trained logistic regression model to densify the preferences before they can be used. The paper has not demonstrated that CPL works directly on raw, sparse human preference data at scale without this auxiliary densification step.

**What evidence exists in the paper.** The paper acknowledges the domain limitation implicitly — Section 6 states "First is scaling CPL to larger datasets and architectures where we believe its benefits will be more pronounced. One potentially exciting application is LLMs, where CPL enables fine-tuning on multiple steps of turn-based dialogue." This explicitly frames LLM application as future work, not current capability. However, the paper does not discuss the technical challenges that would arise in moving from continuous control to discrete language domains (e.g., the change in policy parameterization, the numerical stability of summing over long sequences, the handling of variable-length segments, or the interaction with the reference-distribution constraints commonly used in LLM finetuning).

The D4RL experiments provide some cross-domain evidence (locomotion vs. manipulation), but still within the same broad category of continuous control with proprioceptive state observations. The D4RL CPL variant uses a separate preference prediction model (a logistic regression on segment embeddings), which is a significant departure from the main CPL algorithm — it is no longer "pure" CPL where the policy is the only learned component.

**Mitigation status.** The paper does not attempt to mitigate this limitation experimentally. The theoretical framework is domain-agnostic (the derivation assumes arbitrary MDPs with any state and action spaces), but the gap between theoretical generality and empirical validation is substantial. A reader interested in applying CPL to language or other discrete domains would need to resolve several open questions — how to handle the policy parameterization, how to set `$\gamma$` and `$\alpha$` for long sequences, whether the bias regularizer transfers — without guidance from the paper.

### The GPU Memory Requirement for Long Segments Restricts Practical Segment Length

**The assumption or constraint.** CPL's loss function is computed over entire behavior segments of length `$k$`, where `$k = 64$` in the MetaWorld experiments. To compute the score of a segment, the policy network must be evaluated on all `$k$` state-action pairs, and the log-probabilities must be summed. For a batch of `$B$` comparisons, this requires processing `$2 \times B \times k$` state-action pairs through the policy network *simultaneously* (since the Boltzmann denominator couples the positive and negative segment scores, preventing sequential processing). The gradient computation must backpropagate through all `$2Bk$` evaluations.

The paper acknowledges this limitation explicitly in Section 6: "As CPL's loss function is computed over segments, it requires a substantial amount of GPU memory for large segment sizes." The experiments use segment sizes of 64 steps — which is manageable for the relatively small MetaWorld state spaces (proprioceptive observations of dimension <50) and image observations (64 × 64 pixels, processed through a convolutional encoder before the segment-level scoring). But for applications with larger state representations — high-resolution images, long text sequences, or video segments — the memory requirement scales linearly with segment length.

**The consequence.** The practical segment length is bounded by GPU memory. For a batch of 96 comparisons (the MetaWorld state batch size), a segment length of 64, and a policy network with modest memory footprint, the total memory for a single forward-backward pass includes storing activations for `$96 \times 2 \times 64 = 12,288$` state-action pairs through the entire policy network. For image-based experiments, the paper had to *reduce* the batch size from 96 (state) to 48 (image sparse) to 32 (image dense) — and for the image dense experiments, the effective comparisons-per-batch are much higher due to the dense batch augmentation (computing all pairwise comparisons within the `$b$` segments in the batch, yielding `$b(b-1)$` comparisons). Even with these reductions, image training still required 16.5 hours for P-IQL and 10.2 hours for CPL on a TitanRTX GPU (Table 2).

For language applications where a segment might be a multi-turn dialogue with hundreds or thousands of tokens, the memory requirement could become prohibitive. The paper provides no mechanism for *truncating* segments (using only the most recent `$k$` steps) or for *summarizing* early timesteps in a way that preserves the contrastive signal. The fixed `$\gamma = 1.0$` setting means that all steps in the segment are weighted equally in the sum — there is no natural decay that would justify truncating later steps.

Additionally, the memory constraint interacts poorly with the need for large batch sizes in contrastive learning. Contrastive objectives typically benefit from large batches (more negatives per positive), but each batch element in CPL is a full segment of length `$k$`, multiplying the memory footprint. This creates a tension between "long enough segments to capture temporal structure" and "large enough batches to provide informative contrasts" — a tension that the paper never quantifies or resolves.

**What evidence exists in the paper.** The only direct evidence is the batch size adjustments in the hyperparameters (Table 5): state experiments use batch size 96 with segment length 64 (12,288 pairs/batch), image sparse uses 48 (6,144 pairs/batch), image dense uses 32 (4,096 pairs/batch for dense, but with dense augmentation the effective comparisons are much higher). The paper does not report GPU memory usage, peak activation memory, or any ablation varying segment length while holding batch size/memory constant. The segment-length ablation in Figure 9 (Appendix C.4) shows performance increases with segment length from 8 to 64, suggesting that longer segments are helpful — but it does not measure the memory cost or explore the tradeoff between segment length and batch size at a fixed memory budget.

**Mitigation status.** The paper does not attempt to mitigate this limitation. The acknowledgement in Section 6 is a brief sentence with no proposed solution. Potential mitigations — gradient checkpointing (trading compute for memory by recomputing activations during backpropagation), segment-level subsampling (randomly dropping timesteps), or architecture modifications (shared feature extraction across timesteps before segment-level scoring) — are not discussed. The limitation is left as an open challenge for practitioners attempting to scale CPL to longer segments or larger models.

## 7. Implications and Future Directions

### How This Work Changes the Landscape

CPL represents a **methodological reframing with practical consequences**, not a paradigm shift. The core insight — that the regret preference model and the maximum entropy framework combine to enable direct policy learning from preferences without RL — is intellectually elegant and opens a genuinely new class of algorithms, but it does not overturn the dominant RLHF paradigm. Rather, it provides a **simpler alternative for a specific, growing subset of RLHF problems**: those where the regret model is a reasonable approximation of human preference, where offline data with sufficient coverage exists, and where the primary goal is policy optimization rather than reward model training.

The magnitude of the contribution lies in **removing unnecessary machinery**. Standard RLHF requires reward learning (a model misspecification under the regret model) followed by RL (a suite of optimization challenges that restrict problem scope). CPL collapses both phases into a single supervised contrastive loss. The practical impact — 1.6× faster training, 4.6× fewer parameters (Table 2), matching or exceeding P-IQL on 18 of 24 task-dataset-modality combinations (Table 1) — demonstrates that the removed machinery was genuinely unnecessary for the tested problems. This is a **diagnostic contribution**: CPL proves, by counterexample, that the RL phase of RLHF is not fundamental to learning from preferences under the regret model.

The paper also **resolves a tension** between two bodies of evidence. Knox et al. (2022, 2023) established that the regret model better captures human preferences, but their algorithms were unscalable beyond grid worlds — suggesting the correct model was computationally impractical. Meanwhile, DPO (Rafailov et al., 2023) showed that RL could be eliminated from preference learning, but only in contextual bandits — suggesting the no-RL approach was limited to single-step problems. CPL shows that both limitations were artifacts of specific design choices (learning advantage functions in the first case, using reward-based rather than advantage-based substitution in the second), not fundamental barriers. The regret model *is* scalable, and the no-RL approach *does* extend to sequential problems — but only when the maximum entropy bijection is applied to advantages rather than rewards.

Several research directions become **more attractive** as a result of this work:

- **Regret-based preference elicitation.** If the regret model is correct, then the way we collect preferences should change — asking humans "which behavior is better?" should be framed as asking "which behavior is closer to optimal?" rather than "which behavior accumulated more reward?" CPL provides the algorithmic back-end that makes acting on such preferences feasible, which should motivate better front-end elicitation protocols designed specifically for regret judgments.

- **Contrastive learning engineering for sequential decisions.** The explicit mapping of CPL onto NCE and InfoNCE (Section 3.1, Appendix A.5) means that the extensive contrastive learning literature — hard negative mining, momentum encoding, multi-view augmentation, large-batch training — can be directly ported to preference-based policy learning. This is a lower-risk research direction than developing new RL algorithms because the engineering principles are already well-understood.

- **Multi-step preference datasets for LLMs.** CPL's ability to handle sequential preferences over general MDPs creates a need that currently has no supply: datasets of human preferences over multi-turn dialogues or multi-step reasoning chains. The paper explicitly notes (Section 6) that "no multi-step preferences dataset currently exists for LLMs" — this is now a concrete, actionable gap that dataset creators can fill.

Conversely, some directions become **less attractive**:

- **Developing ever-more-sophisticated RL algorithms for offline RLHF.** If a supervised contrastive loss can match or exceed IQL (a state-of-the-art offline RL algorithm) on complex manipulation tasks, then further improvements to offline RL for preference-based learning may yield diminishing returns — the bottleneck may shift to preference data quality and coverage rather than optimization capability.

- **Reward model architectures that assume the partial return model.** If the regret model is correct, then reward models are learning a misspecified quantity, and no amount of architectural improvement can fix the fundamental mismatch. CPL's strong performance under the regret model suggests that investment should shift toward advantage-based or policy-based approaches rather than better reward models.

### Follow-Up Research This Work Enables

**Directly measure whether the regret model or the contrastive objective drives CPL's gains.** The paper's experiments use only regret-generated preferences (synthetic MetaWorld labels from oracle advantages), so we cannot disentangle the benefit of the regret model from the benefit of the contrastive loss. A controlled experiment would generate two preference datasets from the same underlying trajectories: one labeled by the partial return model (segment scores = sum of rewards) and one labeled by the regret model (segment scores = sum of advantages). Then train CPL (which assumes regret) and P-IQL (which can use either labeling) on both datasets. If CPL outperforms P-IQL on *regret-labeled* data but underperforms on *return-labeled* data, the gain comes from model-algorithm match. If CPL outperforms on *both*, the contrastive objective is simply a better optimizer. This experiment would clarify whether practitioners should switch to regret-based labeling (an elicitation change) or can keep their existing return-based labels and just use a contrastive loss (an algorithmic change).

**Train a lightweight difficulty estimator or segment scorer from CPL's implicit advantage and test it as a verifier.** CPL learns an implicit advantage function `A(s,a) = α log π(a|s)` that the theory claims converges to the optimal advantage (Theorem 1, Proposition 1), but the paper never evaluates it as a standalone verifier. A direct experiment: take a trained CPL policy, use its implicit advantage to score held-out test segments, and measure the correlation with ground-truth optimal advantage (available from the oracle SAC in MetaWorld) and with human preference labels (available in the D4RL real-human setting). Additionally, test whether the implicit advantage can be used for best-of-N selection — generate N trajectories from a suboptimal policy, score them with CPL's `A(s,a)`, pick the highest-scoring one, and measure success rate. If this works, CPL becomes a drop-in replacement for reward-model-based verification without any additional training; if it fails, practitioners know they need a separate verifier model, and CPL should be positioned purely as a policy optimizer.

**Test CPL on a dataset where successful trajectories are systematically removed, measuring the coverage threshold at which value-based stitching becomes necessary.** The paper hypothesizes that CPL cannot compose novel behaviors from partial data the way dynamic programming can (Section 6 implicitly acknowledges this by noting CPL is purely offline). A clean experiment: take the MetaWorld datasets and progressively filter out all trajectories above a success threshold (e.g., remove all trajectories that reach the goal within 50, 100, 150 steps), creating datasets with increasingly sparse coverage of successful behavior. Train CPL and P-IQL on each filtered dataset and plot the performance gap as a function of coverage. The prediction: at high coverage (many successful trajectories, even if suboptimal), CPL and P-IQL perform similarly; at medium coverage (some fragments of good behavior but few complete successes), P-IQL pulls ahead due to stitching; at very low coverage (almost no success signal), both fail. This experiment would produce a coverage-difficulty curve that tells practitioners exactly when CPL's simplicity is worth the tradeoff against value-based methods.

**Develop an online version of CPL with iterative preference collection and measure whether it breaks through the offline performance ceiling.** The paper's offline results show CPL matching but not dramatically exceeding P-IQL, and both methods saturate well below 100% on most tasks. An online CPL would operate in rounds: deploy the current policy, collect new trajectories, elicit preferences (from a human or an oracle) on those trajectories, add them to the preference dataset, retrain CPL, repeat. The key question is whether iterative data collection allows CPL to continually improve, and whether the improvement rate matches or exceeds online RL-based approaches. The MetaWorld setup makes this tractable: use the same environment, use the oracle SAC to provide automated regret-based labels at each round (simulating a human in the loop), and measure the sample efficiency of improvement — how many new trajectories per round are needed to see gains, and how many rounds until convergence. This would address the paper's stated limitation that "our work only considers offline data" (Section 6).

**Scale CPL to language domains with multi-turn dialogue preferences, resolving the numerical and architectural challenges.** The paper explicitly calls for applying CPL to LLMs on multi-step turn-based dialogue (Section 6), but several technical challenges must be solved first. A concrete first experiment: take a small open-source LLM (e.g., a 1B-parameter model), create synthetic multi-turn dialogues where an oracle model provides "correct" follow-up responses, generate preference data by comparing model-generated dialogues to oracle dialogues using the regret model (advantages can be estimated from the oracle's log-probabilities via the bijection), and train CPL to optimize the policy over 3-5 turn segments. Measure whether CPL-trained policies produce more coherent multi-turn dialogues than SFT or standard DPO (which treats each turn independently). Key engineering questions to resolve: how to handle variable-length sequences (padding? truncation?), what temperature α works for token-level log-probabilities summed over hundreds of tokens, and whether the bias regularizer λ needs adjustment for the categorical action space. This experiment would either validate CPL's claimed applicability to language or identify fundamental obstacles.

**Run the preference model mismatch experiment: train CPL and P-IQL on data generated by both the regret model and the partial return model, and also test both on real human preferences where the ground-truth model is unknown.** The paper's theory assumes regret-based preferences, and its synthetic experiments use only regret-based labels. The D4RL results (Table 3) hint at sensitivity — CPL fails on Walker2D Medium Replay, possibly because the real human rater used a rules-based approach inconsistent with the regret model. A systematic study would: (1) generate MetaWorld preference data under *both* models (regret and partial return) from the same trajectories, (2) train CPL and P-IQL on each, (3) measure performance. The prediction: CPL should strongly outperform P-IQL on regret-labeled data (matched assumption), P-IQL should outperform CPL on return-labeled data (CPL's assumption is wrong), and the gap should quantify the cost of model mismatch. Then, test both on the D4RL human preference data — if CPL's performance correlates with how "regret-like" the human preferences are (measurable by how well the regret model fits the human's actual preference probabilities), this provides a diagnostic for when to use CPL vs. return-based methods. If the correlation is weak, the benefit of CPL may come from the contrastive objective rather than the regret model.

### Practical Applications and Downstream Use Cases

**Offline fine-tuning of robot policies from human preference videos.** In industrial robotics, collecting demonstrations is expensive but collecting preference judgments is cheaper — a human operator can watch two videos of a robot attempting a task and click which one looks better. CPL's ability to learn from offline segment-level preferences without any online interaction makes it directly applicable: record a dataset of the robot performing a task with varying quality (from random exploration, scripted policies, or previous model versions), have a human watch pairs of video clips and indicate preferences, and train CPL to produce a policy. The MetaWorld image-based results (Table 1, rows 2 and 4) demonstrate that CPL handles pixel observations and substantively improves over the average behavior in the dataset — for example, on Drawer Open from pixels with dense preferences, CPL achieves 80.3% versus SFT's 64.5%, a 24.5% relative improvement, using only the fixed offline data. The 1.6× training speedup and 4.6× parameter savings over P-IQL (Table 2) matter here: industrial deployments often run on edge hardware with limited GPU memory and compute budgets, making the elimination of auxiliary networks (reward, Q, value) directly valuable.

**Aligning multi-turn dialogue agents on conversation quality, not just single-response quality.** Current LLM RLHF treats each user-assistant exchange independently — a user query, an assistant response, a preference label. But real conversational quality is inherently sequential: a response that is individually reasonable might derail the conversation two turns later, and a response that seems suboptimal in isolation might set up a better interaction later. CPL's ability to learn from preferences over multi-step segments (64 steps in MetaWorld, potentially 5-10 turn dialogues in a language setting) means it could optimize for the quality of entire conversations, not isolated responses. A deployment scenario: for a customer service chatbot, collect preference judgments on full dialogues (the customer's problem was resolved vs. wasn't), then train CPL on those dialogue-level preferences. The current limiting factor — that no multi-step preference dataset exists for LLMs (Section 6) — is addressable: companies with deployed chatbots already collect conversation-level satisfaction ratings that could be converted to pairwise preferences. CPL would be the first algorithm capable of directly optimizing a language policy from those sequential judgments without assuming a contextual bandit.

**Efficient reward-free adaptation of pretrained behavioral priors in simulation-to-reality transfer.** A common robotics pipeline pretrains a policy in simulation (where reward functions are easy to define), then deploys it on a physical robot where the sim reward no longer applies. With CPL, the transfer step could use human preferences on the robot's real-world behavior: collect a batch of real-robot rollouts of varying quality (some from the pretrained policy, some with added exploration noise), have a human compare them, and train CPL on those preferences to adapt the policy to the real environment — all without defining a new reward function. The advantage is that preferences are easier to provide than demonstrations (no need to teleoperate the robot to produce expert trajectories) and more reliable than sparse success/failure labels (preferences provide graded feedback on partial progress). The MetaWorld results with varying data densities (2.5K dense vs. 20K sparse segments, Table 1) suggest that even a few hundred real-robot trajectories with dense pairwise preference labels (every pair compared) could provide sufficient signal for adaptation — CPL achieves 80%+ success on several tasks from only 2.5K offline segments, which could correspond to 2-3 hours of real-robot data collection at typical control frequencies.

### When to Prefer This Method

The paper positions CPL against two named alternatives — standard two-phase RLHF (reward learning + RL) and DPO (the contextual bandit no-RL approach) — with explicit tradeoffs derived from the theoretical framework and empirical results. The decision rule is:

- **Prefer CPL when:**
  - You have or can collect preference data over multi-step behavior segments (not just single-step responses) and want to optimize a policy for sequential decision-making. CPL is the only no-RL method that handles this case — DPO cannot because it requires the contextual bandit assumption.
  - The preferences are or can be framed as judgments of optimality (regret-based) rather than cumulative reward — for example, when a human is comparing which behavior is "closer to what they wanted" rather than "which one accumulated more points." The MetaWorld results show CPL matching or exceeding P-IQL on 5 of 6 tasks under regret-based labels (Table 1, state sparse).
  - Computational efficiency at training time matters — you are willing to trade the ability to stitch together novel behaviors from partial data (which value-based methods provide) for a 1.6× training speedup and 4.6× parameter reduction (Table 2). This tradeoff favors deployment scenarios with limited hardware, rapid iteration cycles, or very large policy networks where training auxiliary value functions is prohibitive.
  - You have relatively dense preference data per behavior segment — CPL benefits more from many comparisons per segment than P-IQL (Figure 2 left, Appendix C.3 Figure 8), so in settings where you can obtain full rankings of behaviors rather than isolated pairwise judgments, CPL's contrastive objective extracts more signal.

- **Prefer standard RLHF (reward learning + RL) when:**
  - Human preferences are known or believed to follow the partial return model rather than the regret model — for instance, when humans are explicitly told to rate behaviors by "total reward accumulated" or when the task has a natural cumulative scoring metric that humans internalize.
  - You need an explicit verifier or reward model at deployment time for scoring, filtering, or ranking novel behaviors — CPL produces only a policy, not a standalone scoring function that can evaluate arbitrary candidate trajectories.
  - The offline dataset has very sparse coverage of successful behavior and you need value-based stitching — CPL's lack of dynamic programming means it cannot compose optimal trajectories from fragments the way IQL can. The Walker2D Medium Replay D4RL result (48.3 vs. 71.6 for P-IQL, Table 3) is a cautionary example of where this matters.
  - The problem is genuinely a contextual bandit (single-step decisions with no temporal structure) — in this case DPO is simpler and better-validated. CPL reduces to DPO as a special case (Appendix A.6), so there is no reason to use the more general framework when the simpler one suffices.

- **Prefer DPO when:**
  - The problem is a contextual bandit (single-step, same starting state for all comparisons) and you want the simplest possible no-RL method. DPO has been extensively validated on LLM alignment at scale, while CPL's language-domain performance is untested.
  - You are working with KL-constrained objectives (reference distribution µ) and want a loss function that has been battle-tested in production LLM training pipelines. CPL's KL-constrained variant exists in theory (Appendix B) but was empirically tested only on a subset of MetaWorld tasks where it underperformed the max-entropy variant (Figure 4).
